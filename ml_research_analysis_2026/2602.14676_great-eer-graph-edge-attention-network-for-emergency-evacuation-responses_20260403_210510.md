# GREAT-EER: Graph Edge Attention Network for Emergency Evacuation Responses

## Quick Facts
*   **arXiv ID:** 2602.14676
*   **Source URL:** https://arxiv.org/abs/2602.14676
*   **Reference count:** 9
*   **Primary result:** A deep RL framework (GREAT-EER) solves the NP-hard Bus Evacuation Orienteering Problem near-optimally in seconds on real-world data, significantly outperforming a greedy heuristic and approaching a 30-minute MILP solver's quality.

## Executive Summary
The paper introduces GREAT-EER, a deep reinforcement learning framework for the Bus Evacuation Orienteering Problem (BEOP), which aims to maximize the number of people evacuated by bus within a fixed time during emergencies. The core innovation is a Graph Edge Attention Network (GREAT) encoder that processes edge-level features to handle asymmetric travel times common in real road networks. Coupled with a pointer decoder using state-dependent masking to enforce hard constraints, the model is trained offline via policy gradients with the POMO framework. Evaluated on San Francisco data, GREAT-EER achieves solution quality within 1-2% of a 30-minute Gurobi MILP solve but with inference times of fractions of a second. It generalizes to larger instances and adapts to stochastic travel times and demands in real-time without constraint violations, where deterministic plans fail.

## Method Summary
GREAT-EER frames BEOP as a Markov Decision Process where actions are sequential node selections for multiple bus tours. The framework uses a Graph Edge Attention Network (GREAT) encoder to process a complete graph of evacuation nodes, where edge features encode travel times (normalized), and the target node's demand/time window. The encoder iteratively updates edge embeddings via attention over edge neighborhoods. These are aggregated into node embeddings, which are used by a state encoder to build a query vector from the current MDP state (bus location, load, remaining time/vehicles). A pointer decoder then computes visit probabilities, applying a mask to zero out probabilities for nodes that would violate capacity, time window, or total tour time constraints. The model is trained offline using REINFORCE with the POMO technique, generating multiple rollouts per instance with random first steps to create a robust baseline. Instance augmentation via random distance scaling (0.5–1.5) further improves generalization.

## Key Results
*   On 100-node instances with 1.5 hours and 3 buses, GREAT-EER achieved a 94.41% evacuation quota in 1 second, compared to 88.16% for Gurobi after 24 hours.
*   The model maintains near-optimal performance on out-of-distribution instance sizes (e.g., 200 nodes) and adapts to stochastic travel times and surprise demand reductions without generating infeasible plans.
*   It significantly outperforms a greedy heuristic across all tested scenarios, with inference speeds orders of magnitude faster than exact MILP solvers.

## Why This Works (Mechanism)
### Mechanism 1: Edge-Centric Processing for Asymmetric Networks
*   **Claim:** The Graph Edge Attention Network (GREAT) encoder captures asymmetric travel time structures critical for non-Euclidean evacuation routing.
*   **Mechanism:** GREAT processes edge features (travel times relative to minima/averages, node demands as edge-target features) through iterative message passing over edge neighborhoods, comparing incoming/outgoing edge pairs via attention. This learns a latent representation where edge embeddings encode viable routing connections under asymmetric conditions.
*   **Core assumption:** Asymmetric travel times (e.g., one-way streets) make Euclidean distance-based models insufficient; edge-centric representation is necessary.
*   **Evidence anchors:** Paper explicitly states the network is "highly asymmetric due to one way streets" and details the edge feature engineering and update equation (Section 3.1).

### Mechanism 2: Hard Constraint Enforcement via Masking
*   **Claim:** The pointer decoder with state-dependent masking enforces hard constraints (capacity, time windows) during incremental tour construction.
*   **Mechanism:** At each decoding step, the policy network computes visit probabilities from node embeddings. A masking operation zeroes probabilities for nodes that would violate constraints (capacity overflow, time window miss, total time overrun) relative to the current MDP state (load, elapsed time, visited set).
*   **Core assumption:** Combinatorial constraints must be respected at every construction step; posterior filtering is inefficient for valid solution generation.
*   **Evidence anchors:** Paper states masking is applied "to ensure that our generated solutions are valid" and defines the MDP action space with explicit constraint checks (Section 3.1, 2.2).

### Mechanism 3: Robust Training via POMO and Augmentation
*   **Claim:** POMO (Policy Optimization with Multiple Optima) and instance augmentation via distance scaling provide a robust training signal that generalizes across BEOP instance distributions.
*   **Mechanism:** POMO starts each rollout with a random first node choice, generating diverse solution trajectories from the same instance. The reward baseline is the average over rollouts, encouraging the model to outperform random starts. Instance augmentation multiplies travel times by random factors (0.5–1.5) during training, exposing the model to varied distance scales and preventing overfitting.
*   **Core assumption:** BEOP solutions have multiple near-optimal structures; diversifying rollouts and augmenting instances improves policy robustness.
*   **Evidence anchors:** Paper explicitly uses POMO and distance scaling for training (Section 3.2) and shows consistent validation improvement (Section 4.2).

## Foundational Learning
*   **Concept:** Combinatorial Optimization (Orienteering Variants)
    *   **Why needed:** BEOP is a modification of the capacitated team orienteering problem (CTOP) with multi-tour vehicles and time windows. Understanding prize collection under time/capacity constraints is essential.
    *   **Quick check:** How does allowing intermediate depot returns (subtours) change BEOP compared to classical CTOP?
*   **Concept:** Graph Neural Networks (Edge-Based Message Passing)
    *   **Why needed:** GREAT processes edge features exclusively, unusual compared to node-focused GNNs, to address asymmetric travel times by comparing neighboring edges.
    *   **Quick check:** Why transform node demands and time windows into edge features directed into the node?
*   **Concept:** Reinforcement Learning with Policy Gradients and Masking
    *   **Why needed:** No supervised labels exist for BEOP; RL learns from reward (evacuated prize). Masking integrates hard constraints into the stochastic policy, making rollout samples always feasible.
    *   **Quick check:** What would happen if masking were removed during training? (Constraint violations → zero reward)

## Architecture Onboarding
*   **Component map:** Input Processor -> GREAT Encoder (5 layers) -> Edge-to-Node Aggregator -> State Encoder -> Pointer Decoder (iterative) -> Rollouts. Training: Sample Instance -> Augment Distances -> POMO Rollouts -> Compute Rewards -> REINFORCE Update.
*   **Critical path:** Transform BEOP instance into complete graph with edge features -> Encode graph with GREAT -> Aggregate to node embeddings -> For each bus tour: build state query from current node/load/time -> decode next node via pointer network with masking -> update state -> repeat until time/capacity exhausted.
*   **Design tradeoffs:**
    *   Edge vs. node GNN: Edge-based GREAT handles asymmetry but has O(n²) memory; node-based would be faster but lose directional nuance.
    *   Masking vs. reward penalty: Masking guarantees feasible rollouts but may restrict exploration; reward penalty allows infeasible paths but wastes compute.
    *   POMO vs. single rollout: POMO improves solution quality but increases training compute by factor of rollout count.
*   **Failure signatures:**
    *   Invalid routes in stochastic inference: Model ignores realized travel time deviations → exceeds T.
    *   Poor generalization on hazard zones: If training never had blocked roads, model may not reroute effectively.
    *   Low evacuation quota on dense time windows: If >30% nodes have early deadlines, model may miss feasible picks due to myopic decisions.
*   **First 3 experiments:**
    1.  **Reproduce deterministic benchmark:** Implement GREAT-EER, run on 20-node San Francisco instances, compare evacuation quota and runtime against Gurobi (30min) and greedy heuristic.
    2.  **Test out-of-distribution size:** Feed 200-node instance (trained on 100) to GREAT-EER. Check if evacuation quota degrades gracefully vs. greedy.
    3.  **Stochastic online validation:** Simulate 20% zero-demand realizations during rollout. Compare deterministic plan (violations?) vs. stochastic model (zero invalid, comparable quota).

## Open Questions the Paper Calls Out
*   **Question 1:** How can the GREAT-EER framework be extended to handle stochastic travel times and demands with multiple cooperating buses in real-time?
    *   **Basis:** Authors aim to generalize to "several vehicles that cooperate in the stochastic setting which, in our MDP so far, is only possible in deterministic settings."
*   **Question 2:** What is the effect of incorporating loading times and heterogeneous bus capacities on evacuation quotas and solution feasibility?
    *   **Basis:** Authors note future work can extend BEOP with "loading times" and "heterogeneous bus characteristics such as different passenger capacities."
*   **Question 3:** Can GREAT-EER scale to BEOP instances with thousands of evacuation nodes while maintaining near-optimal solution quality and fast inference times?
    *   **Basis:** Authors state "scaling to even larger instances is an open challenge and requires more advanced learning pipelines," noting experiments only went up to 200 nodes.

## Limitations
*   No public code; implementation details must be reverse-engineered from paper equations, risking inaccuracies.
*   Training procedure for stochastic setting unclear regarding how expected travel times are used for masking during inference.
*   Weak external corroboration (low citation count, no identified strong neighboring results), limiting confidence in novelty/performance claims.

## Confidence
*   **Performance superiority** (near-optimal quality, speed): Medium. Based on internal experiments, but no independent verification.
*   **Edge attention necessity**: Medium. Theoretical rationale given, but lacking ablation isolating GREAT’s contribution.
*   **Constraint handling via masking**: Medium. Described in text, but no analysis of failure cases when masking disabled.
*   **Generalization via POMO/augmentation**: Medium. Techniques are common, but no demonstration of their specific impact on BEOP.
