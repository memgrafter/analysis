# Looking Through Glass Box

## Quick Facts
- **arXiv ID:** 2603.06272
- **Source URL:** https://arxiv.org/abs/2603.06272
- **Reference count:** 15
- **Primary result:** A glass-box neural fuzzy cognitive map architecture with Langevin dynamics achieves direct edge accuracy 73.88%–99.29% and transitive chain accuracy 63.50%–99.38% on causal recovery, and provides an inverse solution for service/product modification.

## Executive Summary
This paper tackles fuzzy optimization in service design by introducing a neural implementation of fuzzy cognitive maps (FCMs). The proposed "glass-box" architecture enforces adjacency constraints during state propagation, ensuring transparent learning of causality patterns. Langevin-like stochastic dynamics are employed in the inverse solving phase to avoid overfitting and escape local minima. The model is evaluated on synthetic urban policy, Sachs protein, Auto MPG, and IEEE power grid datasets, demonstrating high accuracy in recovering direct and transitive causal links. An inverse solution yields a modification criterion for discretion-based selection of better services, illustrated with real MPG data.

## Method Summary
The model consists of an encoder that maps input data to initial node embeddings. A "mini-FCM" fusion function produces a propagation weight matrix that respects a given binary adjacency mask. State updates follow an iterative propagation operator Φ that combines the current state, the mini-FCM output, and a scaled copy of the initial embeddings. At the initial and final steps, a sign()-based operation enforces a binary-like membership aligned with the adjacency mask. A metrics head predicts a scalar target, and training minimizes the prediction loss. For the inverse problem, the learned weight matrix is used to optimize input parameters via SGD with scheduled Gaussian noise, adding stochasticity during the first half of steps to explore the parameter space. This yields input modifications that drive the system toward desired outputs while respecting forbidden edges.

## Key Results
- Direct edge accuracy ranges from 73.88% to 99.29% across datasets.
- Transitive chain accuracy ranges from 63.50% to 99.38%.
- The inverse solution provides a concrete criterion to modify vehicle features (MPG dataset) for better service selection.

## Why This Works (Mechanism)
### Mechanism 1: Adjacency-Constrained Propagation
The architecture enforces causal directionality and adjacency constraints via a specialized propagation operator Φ(H_t). State updates combine a fused weight matrix (mini-FCM output) with the current state using tanh and a scaled term. Crucially, an adjacency constraint is applied at the initial and final steps (H_0^t = H_curr + sign(H_curr), H_final = H_T + sign(H_T)), which projects values to enforce a binary-like [0,1] pattern aligned with the known adjacency mask A. This transforms a black-box into a glass-box by ensuring that learning respects the known causal graph topology. Evidence: Section 3.2 defines Φ and enforcement; abstract states glass-box architecture. Break condition: if learned H_curr cannot be forced into a valid adjacency pattern, transparency is lost.

### Mechanism 2: Langevin Dynamics for Inverse Solving
Langevin-like stochastic dynamics (noise injection) mitigate overfitting and help escape local minima when solving the inverse FCM problem. During inverse optimization, Gaussian noise (ϵ ~ N(0, 0.01²)) is added to activations in the first half of steps (t < T/2), simulating simulated annealing. This broadens exploration of the parameter space before convergence, addressing the non-convexity of the inverse problem. Evidence: Abstract mentions Langevin differential Dynamics; Section 4 describes stochastic activation with noise. Break condition: improper noise tuning (magnitude or schedule) may cause failure to escape minima or divergence.

### Mechanism 3: Mini-FCM as Latent Regularizer
The "mini-FCM" fusion function acts as a learned normalizer and latent space regularizer, aligning the encoder's internal representation with plausible FCM weight dynamics. The encoder produces H_0, which is passed through MiniFCM to yield H_prop; this combined pipeline is trained to minimize loss on a metrics projection head, forcing the embeddings to be compatible with FCM propagation semantics. Evidence: Section 3.1 defines MiniFCM; Section 3.2 states that encoder+fcm are forced to learn weights and causality. Break condition: if MiniFCM imposes an incorrect inductive bias, learned causality may not reflect true system behavior.

## Architecture Onboarding
Component map: Inputs (X, A) → Encoder → H_curr → Mini-FCM → H_prop → Propagation Loop (Φ) → H_T → sign() → H_final → Metrics Head → Y_m → Loss → Inverse Solver

Critical path: The encoder maps input data to initial node embeddings. The mini-FCM generates a propagation weight respecting the adjacency mask. The propagation operator iteratively updates the state while injecting a scaled copy of the initial embeddings. After T steps the state is sign‑clamped, then passed to the metrics head to predict a scalar. Training minimizes the prediction loss. For inversion, the learned weight matrix is used to optimize input parameters with scheduled Gaussian noise, yielding modifications that achieve a target output.

Design tradeoffs:
- Transparency vs. Scalability: Hard adjacency constraints improve interpretability but may limit capacity on larger, denser graphs.
- Noise Tuning: Inverse solve relies on carefully scheduled Gaussian noise; poor tuning leads to failure.
- Mask Fidelity: The glass-box property assumes the provided adjacency mask A is correct; an incorrect A forces an invalid causal structure.

Failure signatures:
- Propagation divergence: state values explode or saturate before sign step.
- Stuck inverse: inverse returns high forbidden weights despite penalty, indicating ineffective noise.
- Poor generalization: high variance in edge accuracy across data splits (e.g., Sachs 25‑node).

First 3 experiments:
1. **Synthetic Urban Policy (9 nodes):** Baseline with known structure; expected >99% accuracy to validate core mechanism.
2. **Sachs Protein Network (11 nodes):** Real biological network with known reference graph; expected ~76% accuracy with higher variance, testing robustness to real‑world noise.
3. **Auto MPG (6 nodes):** Real regression problem; inverse solution should identify feature deltas that improve MPG, demonstrating applied discretion‑based selection.

## Open Questions the Paper Calls Out
1. **How can neural networks explicitly model fuzzy implications (e.g., logical operators) in cognitive maps to ensure accurate causality learning for optimization tasks?** The paper notes this as a pending question but does not address it in the proposed architecture, leaving implication modeling unresolved.

2. **How does the glass-box FCM neural network's causal accuracy scale with increasing network size and density, and what are the computational trade-offs?** Table 1 shows declining accuracy as nodes increase (e.g., 24‑node case), hinting at scalability limits not explored.

3. **What specific data characteristics (e.g., noise, missing values, dimensionality) most degrade the inverse solution's performance on real‑world datasets?** The MPG discussion notes unresolved real‑data challenges but lacks detailed analysis of robustness factors.

4. **How robust is the model's causal learning to inaccuracies in the provided adjacency matrix, and can it adapt if the adjacency prior is flawed?** The methodology uses adjacency masks assuming valid/invalid paths, but no experiments test sensitivity to erroneous adjacency inputs.

## Limitations
- The Mini‑FCM operator is underspecified, hindering faithful reproduction and theoretical analysis.
- The best‑state selection criterion (based on St) is mathematically ambiguous and not experimentally justified.
- The sign() enforcement step is mathematically incorrect (e.g., 1.2 + sign(1.2) = 2.2), undermining the transparency claim.

## Next Checks
1. **Ablate the Mini‑FCM component:** Replace Mini‑FCM with an identity mapping or standard normalization; measure change in Direct/Transitive Chain Accuracy on all datasets. A significant drop would confirm its regularizing role.
2. **Stress‑test inverse solver with known infeasible targets:** For a synthetic dataset, set target v outside the reachable range under adjacency constraints. Quantify failure rates under different noise schedules (λ_t, magnitude) to validate the claimed escape‑from‑minima property.
3. **Clarify the sign() operation’s role:** Implement two variants: (a) as described (post‑update + sign()), (b) applying a hard clamp (H = max(0, min(1, H))) at the same points. Compare training stability, final adjacency accuracy, and output distributions to determine if the operation is for constraint enforcement or stabilization.
