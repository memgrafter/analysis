# Look Twice: Training-Free Evidence Highlighting in Multimodal Large Language Models

## Quick Facts
- **ArXiv ID**: 2604.01280
- **Source URL**: https://arxiv.org/abs/2604.01280
- **Reference count**: 40
- **Primary result**: A training-free inference-time framework that highlights relevant visual regions and textual evidence via internal attention patterns, achieving up to +5.3% average accuracy gains on knowledge-based VQA benchmarks.

## Executive Summary
Multimodal Large Language Models (MLLMs) often struggle to select the most relevant visual and textual evidence when answering knowledge-intensive queries, leading to suboptimal performance on tasks like knowledge-based VQA. This paper introduces Look Twice (LoT), a training-free framework that operates at inference time to improve evidence selection. LoT exploits the model’s own attention patterns: in a lightweight first pass (generating a single token), it extracts attention signals to identify query-relevant image regions (via object-conditioned attention and sink filtering) and informative sentences in retrieved text. These cues are then highlighted with special markers in the prompt, guiding the model to re-attend to them during the second pass where the final answer is generated. Experiments across multiple MLLMs and KB-VQA benchmarks (E-VQA, InfoSeek, OVEN, ViQuAE) show consistent improvements over zero-shot baselines, with average gains up to +5.3%. Additional evaluations demonstrate that visual evidence highlighting alone benefits vision-centric and hallucination benchmarks. LoT requires no additional training or architectural modifications and introduces negligible computational overhead (one extra token).

## Method Summary
LoT employs a two-pass inference scheme. In the first pass, the MLLM processes the multimodal input (image, question, and optionally retrieved text) and generates exactly one token while its full attention matrices from all decoder layers are recorded. Two key attention submatrices are extracted: (1) *object-to-visual* attention, computed between tokens representing the target object in the question (identified via a lightweight NLP parser) and all visual tokens; and (2) *last-to-context* attention, from the final generated token to tokens of the retrieved text context. The object-to-visual scores are aggregated across layers and heads, then filtered to suppress spurious high-attention “sink” activations. The filtered attention map is reshaped to image space, and a single bounding box is derived via a weighted centroid and spread (with scaling factor β=2). For the text, attention scores are aggregated per sentence, and the sentence with the maximum score is selected. In the second pass, the model is given a prompt in which the cropped image is wrapped in `<START_IMPORTANT_IMG>`/`<END_IMPORTANT_IMG>` tags and the chosen sentence in `<START_IMPORTANT_TXT>`/`<END_IMPORTANT_TXT>` tags. The model then generates the final answer, now guided to focus on the highlighted evidence. The entire pipeline is training-free, relies solely on the model’s existing attention weights, and adds only one extra forward pass for the single token.

## Key Results
- **Consistent gains on KB-VQA**: Across four benchmarks and various MLLMs (Qwen2-VL, Qwen2.5-VL, Qwen3-VL, InternVL3.5), LoT improves zero-shot accuracy by up to +5.3% on average.
- **Visual evidence helps broadly**: Even when only visual highlighting is applied (no textual selection), performance improves on vision-centric and hallucination benchmarks (RealWorldQA, TextVQA, etc.).
- **Minimal overhead**: The method incurs negligible computational cost beyond a single additional token generation during the first pass.

## Why This Works (Mechanism)
### Mechanism 1: Object-conditioned visual grounding
- **Claim**: Attention between tokens referring to the target object (e.g., “female butterfly”) and visual tokens serves as an implicit relevance signal for localizing the queried entity in the image.
- **Mechanism**: From the first-pass attention matrices, the submatrix `obj→vis` (rows: object tokens, cols: visual tokens) is extracted for intermediate layers `Lvis` and all heads. The scores are aggregated across object tokens, layers, and heads to produce a per-visual-token relevance map `a_vis`. The assumption is that stronger attention from the linguistic representation of the entity to visual features correlates with the spatial location of that entity.
- **Break condition**: If the target object extraction fails or the model’s attention to the object tokens is weak/noisy, `a_vis` becomes unreliable.

### Mechanism 2: Attention sink filtering
- **Claim**: Filtering activations associated with attention sinks removes spurious high-attention values on visually salient but semantically irrelevant patches, refining the visual relevance map.
- **Mechanism**: For a set of intermediate layers `Lsink`, a “sink score” `s_sink` is computed per visual token based on maximum activation across a predefined subset of hidden dimensions `D_sink` (known to act as sinks). Tokens where `s_sink` exceeds a percentile threshold `τ` (e.g., 25th) are deemed sinks; their scores in `a_vis` are zeroed out before reshaping to the 2D map `M_vis`.
- **Break condition**: If the sink dimensions are not generalizable or if relevant visual tokens coincidentally activate sink dimensions, filtering may discard valid signals.

### Mechanism 3: Textual evidence selection
- **Claim**: The attention pattern from the last generated token to the retrieved context tokens identifies the most informative sentences for answering the query.
- **Mechanism**: In the first pass, the `last→ctx` submatrix (row: the final generated token index, cols: context tokens) is extracted from deeper layers `Ltxt` and aggregated across heads to yield a score `a_txt` per context token. Sentences with the highest aggregated scores are selected and highlighted in the second-pass prompt.
- **Break condition**: If the first token is a generic filler, its attention may not reflect answer-relevant text.

## Foundational Learning
- **Transformer Self-Attention Dynamics in MLLMs**: Understanding how self-attention weights flow between modalities is essential because LoT directly manipulates specific attention submatrices. Attention weight `A[i,j]` in a decoder-only Transformer represents the importance of token `j` to the representation of token `i` at a given layer, conditioned on the causal mask. *Quick check*: In a decoder-only Transformer, how does causal self-attention differ from encoder cross-attention, and what does `A[i,j]` represent in a multimodal sequence?  
- **Attention Sink Phenomenon**: Attention sinks are hidden dimensions that disproportionately attract attention regardless of input content, a phenomenon observed in LLMs and extended here to visual tokens. LoT’s sink filtering mitigates artifacts caused by such dimensions. *Quick check*: What is an “attention sink” in LLMs, and why might a similar phenomenon occur for specific *visual tokens* in a Multimodal LLM?  
- **Evidence Highlighting via Prompt Engineering**: Using special marker tokens to steer the model’s focus without training draws on the ability of LLMs to parse structural cues in prompts. *Quick check*: How can inserting special delimiter tokens into a prompt influence an autoregressive model’s focus on specific text spans during generation, and what are the risks of the model simply copying these tokens?

## Architecture Onboarding
**Component map**  
Target Object Parser → First-Pass Attention Extractor → (Visual Evidence Pipeline & Textual Evidence Pipeline) → Prompt Constructor → Second-Pass Generator

**Critical path**  
The input (image, question, retrieved text) flows through the parser to obtain the target object. The attention extractor runs a one-token forward pass and records all attention matrices. The visual pipeline computes `a_vis`, filters sinks, and derives a bounding box; the textual pipeline computes `a_txt` and selects sentences. The prompt constructor crops the image to the box, inserts markers, and assembles the final prompt. The second-pass generator then produces the answer.

**Design tradeoffs**  
- *Layer ranges*: Using intermediate layers for visual grounding (`Lvis`) balances semantic richness and spatial precision; final layers for text (`Ltxt`) capture high-level context.  
- *Highlighting granularity*: Sentence-level selection is more precise than passage-level for E-VQA but may miss multi-sentence evidence.  
- *Bounding box scale (`β`)*: `β=2` enlarges the Gaussian-based box to include context; larger `β` risks including noise, smaller `β` risks cropping out relevant regions.  
- *Sink threshold (`τ`)*: A fixed percentile (25th) is simple but may not generalize across models or inputs.

**Failure signatures**  
- *Visual*: Bounding box misses the object (check attention map `M_vis`); box too large/noisy (sink filter too weak); object parser extracts wrong span.  
- *Textual*: Selected sentence is irrelevant (inspect `a_txt` distribution); no sentence selected (`α` too high).  
- *System*: Second-pass answer identical to baseline (highlighting ineffective); performance degradation (highlighting misleads).

**First 3 experiments**  
1. **Visual highlighting ablation**: Run LoT with only visual highlighting on a vision-centric benchmark (e.g., RealWorldQA). Expected: improvement over baseline, confirming visual evidence helps.  
2. **Sink filtering ablation**: Disable sink filtering (set `s_sink` to zero) on a dataset requiring fine-grained grounding (e.g., ViQuAE). Expected: significant drop, validating the filtering step.  
3. **Bounding box extraction comparison**: Compare weighted centroid against min‑max and morphological methods on a held‑out set (using a detector like GroundingDINO as proxy ground truth). Expected: weighted centroid yields better IoU/coverage trade‑off.

## Open Questions the Paper Calls Out
- **Token influence**: How does the specific token generated in the first pass affect the stability and reliability of the extracted attention signals? The paper assumes the first token’s attention is a consistent proxy without empirical validation.
- **Non-object queries**: How does LoT perform on questions without a clear target object (e.g., relational, abstract, or multi‑entity queries) given its reliance on extracting a single noun phrase as `Tobj`?
- **Multi‑region visual grounding**: Could allowing multiple bounding boxes or an adaptive box scale improve coverage for queries with spatially distributed evidence?
- **Multi‑sentence textual evidence**: Does selecting only the single top‑attended sentence suffice, or would a set of top‑ranked sentences enhance performance for multi‑fact questions?

## Limitations
- **Heuristic hyperparameters**: Layer ranges (`Lvis`, `Ltxt`, `Lsink`) and sink dimensions (`Dsink`) are chosen heuristically and not systematically validated per model.
- **Retrieval details omitted**: The pipeline for generating concise Wikipedia summaries and constructing the retrieval index is incompletely described, hindering exact replication.
- **Object extraction fragility**: The spaCy‑based parser may fail on complex question syntax, leading to incorrect visual grounding.
- **Fixed sink threshold**: The 25th‑percentile threshold `τ` may not generalize across diverse inputs and models.

## Confidence
- **Visual grounding**: Medium
- **Sink filtering**: Medium

- **Overall reported gains**: High

## Next Checks
1. Conduct a layer-sensitivity study for each MLLM by varying `Lvis` and `Ltxt` on a validation set to determine robust default ranges.
2. Calibrate sink dimensions `Dsink` per model on a diverse sample (e.g., 1k inputs) and test whether a fixed set generalizes across datasets; if not, implement an adaptive selection method.
3. Quantify object extraction accuracy on a held‑out question set; if accuracy is below ~80%, replace the spaCy extractor with an LLM‑based approach and measure impact on visual grounding.
