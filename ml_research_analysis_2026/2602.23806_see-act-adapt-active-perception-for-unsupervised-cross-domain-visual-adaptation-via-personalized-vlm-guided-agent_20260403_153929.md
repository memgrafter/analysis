# See, Act, Adapt: Active Perception for Unsupervised Cross-Domain Visual Adaptation via Personalized VLM-Guided Agent

## Quick Facts
- arXiv ID: 2602.23806  
- Source URL: https://arxiv.org/abs/2602.23806  
- Reference count: 19  
- Primary result: Sea² adapts viewpoint selection via a VLM-guided agent to improve frozen perception modules on novel indoor scenes, achieving gains up to +27.68% (3D box IoU).

## Executive Summary
Pre-trained vision models suffer performance drops when deployed in novel indoor scenes due to shifts in viewpoint distribution, occlusion patterns, and spatial semantics. Standard fine-tuning risks catastrophic forgetting and requires labeled data. Sea² introduces an alternative paradigm: instead of retraining the perception modules, it learns a viewpoint-selection policy that actively seeks informative observations. This policy is implemented by a VLM that is first fine-tuned on heuristic exploration trajectories and then refined via unsupervised reinforcement learning (GRPO) using scalar rewards derived from the perception modules' confidence and geometric consistency. Across ReplicaCAD and HM3D datasets, Sea² significantly outperforms passive baselines in visual grounding, segmentation, and 3D box estimation, demonstrating annotation-free, modular domain adaptation.

## Method Summary
Sea² comprises two core components: a set of frozen perception modules (for visual grounding, segmentation, and 3D box estimation) and a VLM-based policy that controls the agent's viewpoint. The policy takes a natural language instruction and current observation, outputs a structured action (including thoughts, task type, and low-level pose command). The perception modules process the observation with the task prompt and return predictions along with scalar confidence scores. The system is trained in two stages: first, supervised fine-tuning (SFT) on trajectories generated by a deterministic heuristic (search → center → approach) to align the VLM with spatial reasoning and output format; second, reinforcement learning (GRPO) where the policy is optimized using a reward that combines format compliance, confidence improvement, and geometric consistency (area and center alignment of predictions). All perception modules remain frozen; only the VLM policy is updated, enabling adaptation without labels or model fine-tuning.

## Key Results
- Visual grounding mAP improves by +13.54% (ReplicaCAD) and +22.16% (HM3D) over frozen baselines.  
- Segmentation IoU increases by +15.92% (ReplicaCAD) and +12.49% (HM3D); Dice +13.59%.  
- 3D box estimation IoU gains +27.68% (ReplicaCAD) and +9.31% (HM3D); center score +25.35%.  
- Approach works across multiple perception backbones without modifying them.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The primary cause of performance drop in novel indoor scenes is suboptimal viewpoint selection, not inherent model capacity limitations.  
- **Mechanism:** By learning a policy that navigates to viewpoints where frozen perception modules produce higher confidence and geometrically consistent outputs, the system compensates for domain gaps without modifying the modules.  
- **Core assumption:** Perceptual quality (e.g., detection confidence, mask area) is a differentiable, view-dependent signal that can be optimized via motion.  
- **Evidence anchors:** [abstract], [section 1] argue that perception depends on viewpoint informativeness; neighbor papers support active perception. No direct controlled ablation isolating viewpoint as primary cause; assumption: domain gap effects are separable.  
- **Break condition:** If systematic viewpoint variation does not correlate with perception module output metrics (confidence, IoU) across scenes, the causal link fails.

### Mechanism 2
- **Claim:** A VLM can be transformed into an effective low-level pose controller via a two-stage training pipeline (SFT on heuristic trajectories + RL with unsupervised rewards).  
- **Mechanism:** SFT provides spatial reasoning priors and output format alignment, reducing RL exploration variance. RL then refines the policy using scalar rewards derived from frozen module outputs, enabling task- and model-agnostic adaptation.  
- **Core assumption:** The VLM's pretrained spatial reasoning is malleable to control tasks via fine-tuning, and RL can optimize long-horizon viewpoint selection using only sparse scalar feedback.  
- **Evidence anchors:** [section 3.3] describes the pipeline; [section 4.3] ablation shows SFT+RL outperforms RL-only and SFT-only.  
- **Break condition:** If the VLM cannot effectively output structured control actions after SFT, or if RL fails to improve upon SFT using the proposed reward signals, the pipeline is ineffective.

### Mechanism 3
- **Claim:** Combining confidence-based and geometrically-shaped rewards is necessary for stable and effective policy learning, as each alone is insufficient (confidence is noisy, geometry is task-agnostic).  
- **Mechanism:** Confidence reward (`r_c`) provides task-specific feedback on perceptual improvement. Geometric reward (`r_g`) provides smooth, model-agnostic spatial guidance (area/center alignment). Their combination yields a robust learning signal.  
- **Core assumption:** Confidence from frozen modules is a noisy but directionally correct proxy for perception quality; geometric constraints are stable but insufficiently specific.  
- **Evidence anchors:** [section 3.3.2] defines reward components; [section 4.3] ablation (Table 4) shows full combination outperforms single-component variants.  
- **Break condition:** If confidence signals are systematically misleading or if geometric shaping leads to degenerate behaviors (e.g., centering at cost of occlusion), the combined reward fails to converge to informative viewpoints.

## Foundational Learning
- **Concept: Active Perception**  
  *Why needed:* The entire premise is that perception is an active, embodied process where viewpoint choice determines outcome quality. Engineers must understand the difference between passive recognition and active information gathering.  
  *Quick check:* If moving the camera changes a frozen detector's confidence for the same object, what does that imply about the original "performance drop"?

- **Concept: Reinforcement Learning from Environment Feedback (No External Reward Model)**  
  *Why needed:* The policy learns from scalar signals derived from module outputs, not human preferences or ground-truth labels. Engineers must design stable reward functions from black-box outputs.  
  *Quick check:* Why is a confidence delta (`c_t - c_{t-1}`) a plausible reward, and what are its failure modes?

- **Concept: Modular System Design (Frozen Components)**  
  *Why needed:* The system separates control (VLM policy) from perception (frozen modules). Engineers must implement clean interfaces (prediction + confidence) and ensure modules are truly unchanged.  
  *Quick check:* If you replaced the segmentation module with a different architecture, what parts of the system would need retraining?

## Architecture Onboarding
- **Component map:**  
  Task Instruction -> VLM Policy (outputs thoughts, task type, task prompt, action) -> Perception Module Selector (routes to correct frozen module) -> Frozen Perception Modules (output predictions and confidence) -> Reward Computer (computes r_f, r_c, r_g) -> RL Optimizer (GRPO updates VLM policy)

- **Critical path:** The agent receives instruction I and observation o_t; VLM parses I to get task type h and generates task prompt p; module selector picks frozen module m based on h; m processes (o_t, p) to produce (ŷ_t, c_t); reward computer aggregates these across steps to produce r_t; GRPO updates VLM policy using r_t while keeping modules frozen.

- **Design tradeoffs:**  
  - VLM scale vs. control granularity: Larger VLMs have better reasoning but may output verbose, non-actionable thoughts; smaller VLMs may be more controllable but less accurate. The paper uses 2B variants.  
  - Reward simplicity vs. specificity: Geometric rewards are general but task-agnostic; confidence is task-specific but noisy; tradeoff managed by weighting.  
  - SFT data heuristic vs. diversity: Rule-based trajectories provide clean data but lack exploration diversity; RL is needed to overcome heuristic bias.

- **Failure signatures:**  
  - Task misrouting (wrong module selected) → metrics zeroed.  
  - Confidence collapse (monotonic decrease or near-zero) → reward signal vanishes.  
  - Geometric fixation (agent centers and never stops) → may cause occlusion.  
  - Format evasion (VLM omits required fields) → format penalty dominates.

- **First 3 experiments:**  
  1. **SFT Data Validation:** Run heuristic policy on training scenes; verify logged trajectories contain valid (thought, task_type, task_prompt, action) and correct task type from instruction.  
  2. **Reward Signal Sanity Check:** For fixed action sequence (e.g., from heuristic), compute r_t components; confirm r_c and r_g change sign appropriately when moving toward/away from target.  
  3. **RL Warm-start Test:** Train for 1 GRPO iteration from SFT checkpoint; check average episode reward increases and task routing accuracy improves over RL-only baseline.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: Can Sea²'s active perception policy generalize to outdoor or real-world environments?  
- Basis: Evaluation restricted to synthetic indoor scenes (ReplicaCAD, HM3D) in Habitat; no outdoor or physical deployment.  
- Why unresolved: Outdoor scenes have different geometry, lighting, and occlusions, which may alter viewpoint-perception correlation.  
- What evidence would resolve: Run on outdoor embodied datasets (e.g., Gibson, KITTI) or real robots; measure relative gains.

### Open Question 2
- Question: How robust is the approach to noisy or miscalibrated confidence scores from perception modules?  
- Basis: The reward uses confidence change; authors note confidence can be noisy and degrade grounding/segmentation.  
- Why unresolved: Confidence is critical; if unreliable, policy may learn misleading correlations, limiting applicability.  
- What evidence would resolve: Inject controlled noise into confidence values or test with multiple detectors having different calibration; assess performance drop.

### Open Question 3
- Question: Does the claimed plug-and-play compatibility hold for perception models that lack explicit confidence outputs?  
- Basis: The method requires a scalar confidence from each module. Only models with such outputs (or constructed ones) were tested.  
- Why unresolved: Many vision models do not produce a natural confidence score. Need for task-specific confidence extraction undermines universality claim.  
- What evidence would resolve: Apply Sea² to diverse models (e.g., CLIP for classification, DETR for detection) using simple proxy confidences (e.g., max probability) and report performance gains or failures.

## Limitations
- Implementation details missing: heuristic thresholds, SFT dataset size, GRPO hyperparameters (batch, KL coefficient), reward weights; impedes exact replication.  
- Simulator-only evaluation: Results on synthetic indoor datasets; no real-world tests, so physical deployment uncertain.  
- Backbone specificity: Only GroundingDINO, SAM, and a custom 3D estimator used; modularity claim needs validation with other models.  
- Confidence calibration: No evidence that module confidence correlates with perceptual quality; noisy signals could destabilize learning.  
- Causal attribution: Viewpoint selection identified as primary cause without isolating from other factors like feature shift.

## Confidence
- Mechanism 1 (viewpoint primary cause): Medium  
- Mechanism 2 (VLM two-stage pipeline): High  
- Mechanism 3 (combined reward): High  

## Next Checks
1. **Correlation study:** Sample diverse viewpoints in multiple scenes, compute confidence vs. ground-truth informativeness (object visibility, mask completeness). Expect strong positive correlation; weak correlation would undermine reward design.  
2. **Backbone swap:** Substitute each perception module with two alternative architectures (e.g., MDETR for VG, SAM‑2 for segmentation). Retain same policy; measure performance drop. Minimal degradation would confirm backbone-agnosticism.  
3. **Real-world pilot:** Deploy on a mobile robot in unseen indoor environments. Compare perception metrics against random/forward baselines. Success would validate sim-to-real transfer.
