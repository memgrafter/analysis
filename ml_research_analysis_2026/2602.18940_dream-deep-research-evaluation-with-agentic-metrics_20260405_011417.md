# DREAM: Deep Research Evaluation with Agentic Metrics

## Quick Facts
- arXiv ID: 2602.18940
- Source URL: https://arxiv.org/abs/2602.18940
- Reference count: 40
- Primary result: DREAM introduces an agentic evaluation framework that overcomes the Mirage of Synthesis, achieving high sensitivity to factual, temporal, and reasoning flaws while maintaining strong correlation with human judgments.

## Executive Summary
Deep research agents produce analyst-grade reports, but evaluating them is challenging because multiple valid outcomes and multidimensional quality dimensions exist. Existing benchmarks suffer from the "Mirage of Synthesis," where surface fluency and citation alignment hide serious flaws because static evaluators lack tool-use capabilities. The DREAM framework addresses this by employing a two-phase agentic evaluation: first constructing a query-specific protocol that combines static metrics with adaptive metrics generated by a tool-calling agent; then executing each metric with specialized evaluators (LLM, agent, or workflow). Controlled experiments show DREAM's heightened sensitivity: near-linear degradation with injected factual errors whereas citation-alignment metrics stay invariant; Key-Information Coverage scores drop dramatically from 79.35 to 22.34 on temporally outdated reports; and Reasoning Quality consistently penalizes flawed reasoning. Human evaluations confirm the relevance, clarity, and verifiability of agent-generated protocols (average scores ~0.92 with retrieval support). DREAM thus provides a scalable, reference-free evaluation that bridges the capability gap between researchers and evaluators.

## Method Summary
DREAM comprises two phases: Protocol Creation and Protocol Execution. In Phase 1, a tool-equipped agent (with web search, arXiv, GitHub) generates query-specific adaptive metrics: a Key-Information Coverage (KIC) checklist that enumerates essential time-sensitive facts, and a set of Reasoning Quality (RQ) validation plans that define structured cross-referencing steps. These are combined with predefined static metrics (Writing Quality, Factuality, Citation Integrity, Domain Authoritativeness) to form an evaluation protocol. In Phase 2, each metric is assigned an appropriate evaluator: an LLM evaluates Writing Quality and KIC yes/no items; an agent evaluator executes RQ validation plans with tool calls; a workflow evaluator handles Factuality (via neutral search and evidence extraction), Citation Integrity (claim attribution and faithfulness), and Domain Authoritativeness (domain credibility scoring). The outputs are aggregated into final scores. The framework is designed to match evaluator capabilities to the complexity of each metric, ensuring capability parity and enabling detection of temporal, factual, and reasoning flaws that static methods miss.

## Key Results
- DREAM exhibits near-linear degradation in Factuality with injected errors, while citation-alignment metrics remain invariant, proving sensitivity to hidden falsehoods.
- Key-Information Coverage scores drop dramatically for outdated reports (79.35 → 44.80 → 22.34), demonstrating temporal awareness.
- Reasoning Quality scores consistently degrade (~40% penalty) on reports with reasoning flaws, confirming ability to detect analytical gaps beyond surface coherence.

## Why This Works (Mechanism)
### Mechanism 1: Capability Parity through Agentic Evaluation
Static evaluators fail to detect factual, temporal, and reasoning flaws because they lack the tool-use and reasoning capabilities of the research agents they assess. DREAM enforces capability parity by making the evaluation process itself agentic: the evaluator is equipped with retrieval tools, temporal awareness, and reasoning abilities to independently verify claims. This directly addresses the "Mirage of Synthesis," where surface-level fluency and citation alignment mask deeper issues. Evidence shows that without tool access, evaluation loses sensitivity to temporal and factual errors.

### Mechanism 2: Two-Phase Protocol Construction and Execution
Deep research queries are open-ended with multiple valid outcomes, so a one-size-fits-all rubric cannot capture necessary information and reasoning probes. DREAM first constructs an evaluation protocol in Phase 1 (Protocol Creation) that combines static metrics with adaptive metrics generated by an agent that researches the query. In Phase 2 (Protocol Execution), each metric is assessed by an evaluator whose capabilities match the metric’s requirements (LLM, agent, or workflow). This query-specific, dynamically constructed protocol allows the evaluation to cover the diverse dimensions of quality that matter for a given research task.

### Mechanism 3: Adaptive Metrics for Temporal and Reasoning Sensitivity
Static metrics are insensitive to temporal decay and reasoning flaws. DREAM’s adaptive metrics—Key-Information Coverage and Reasoning Quality—are grounded in up-to-date evidence and structured reasoning plans. For temporally volatile queries, the Protocol Creation Agent generates KIC checklist items based on current sources; thus, scores drop for outdated reports. For reasoning quality, the agent creates validation plans that require cross-referencing evidence, exposing logical gaps even in fluent text. These adaptive mechanisms provide the sensitivity needed to evaluate deep research outputs beyond superficial correctness.

## Architecture Onboarding
**Component map:**  
Protocol Creation Agent -> Evaluation Protocol (Static Metrics + Adaptive Metrics) -> Evaluators (LLM Evaluator, Agent Evaluator, Workflow Evaluator)

**Critical path:**  
1. Input query -> Protocol Creation Agent generates KIC checklist and RQ validation plans.  
2. Combine with built-in static metrics to form full protocol.  
3. For each metric in protocol, route to appropriate evaluator (LLM, agent, workflow).  
4. Execute evaluations, collect scores, aggregate final result.

**Design tradeoffs:**  
- Static vs adaptive: Static metrics are cheap and consistent but lack query-specificity; adaptive metrics are expensive and tool-dependent but provide temporal/reasoning sensitivity.  
- Evaluator selection: Using the simplest capable evaluator reduces cost (e.g., LLM for Writing Quality) but may limit nuance; complex evaluators (agent) increase accuracy but latency.  
- Tool reliance: External tools introduce latency, availability dependencies, and potential bias, but are necessary for temporally aware fact-checking.

**Failure signatures:**  
- Protocol Creation Agent fails: missing key information items, ambiguous validation plans, or non-verifiable questions.  
- Tool outage: retrieval failures cause incomplete evidence, leading to “Unverifiable” labels or default low scores.  
- Evaluator inconsistency: different LLM backbones produce divergent scores; need calibration.  
- Over-penalization: adaptive metrics may be too strict if generated criteria are too narrow or based on noisy sources.

**First 3 experiments:**  
1. Temporal Sensitivity Test: Run KIC on reports with simulated knowledge cutoffs; expect degradation in scores for older cutoffs.  
2. Reasoning Flaws Detection: Compare scores of well-reasoned vs malformed reports using RQ; expect significant drop for malformed.  
3. Factual Corruption Study: Inject known false claims with aligned citations; measure Factuality score degradation while Alignment metrics remain invariant.

## Open Questions the Paper Calls Out
1. How can DREAM's reliance on external tools (e.g., web search) be made robust against retrieval bias, service outages, or manipulation to ensure fair and stable evaluation?  
2. What optimization techniques (e.g., caching, selective verification) can make DREAM's multi-step agentic evaluation computationally feasible for large-scale or real-time assessment without sacrificing its sensitivity to factual and temporal errors?  
3. Can DREAM's evaluation principles be extended beyond output assessment to directly measure the quality of a DRA's intermediate research process (e.g., search trajectory coherence, source diversity, iterative refinement)?  
4. Under what conditions does DREAM's agentic evaluation provide a statistically significant advantage over the best non-agentic (static LLM-judge or citation-workflow) benchmarks when evaluating the *synthesis quality* (analytical depth) of reports that are factually correct and up-to-date?  
5. Does DREAM's evaluation protocol generalize effectively to domains requiring deep specialized knowledge (e.g., advanced mathematics, experimental physics) where the agent's "tool-use" (e.g., ArXiv search) must be supplemented by domain-specific validation (e.g., symbolic computation, lab data simulation)?

## Limitations
- Exact prompts, tool specifications, and heuristics for metric generation are not disclosed, hindering precise replication.
- Generated criteria may be overly narrow, risking over-penalization of valid reports.
- Scalability depends on external tool availability and cost; domain generalizability remains untested beyond presented benchmarks.
