# CoMAI: A Collaborative Multi-Agent Framework for Robust and Equitable Interview Evaluation

## Quick Facts
- **arXiv ID:** 2603.16215
- **Source URL:** https://arxiv.org/abs/2603.16215
- **Reference count:** 40
- **Primary result:** CoMAI achieves 90.47% accuracy, 83.33% recall, 84.41% candidate satisfaction, and 100% defense success against prompt injection, outperforming single-agent models and human interviewers.

## Executive Summary
CoMAI introduces a modular multi-agent framework for AI-driven interview assessment, orchestrated by a centralized finite-state machine (FSM). It addresses prompt injection vulnerabilities and subjective bias through specialized agents: question generation, security, scoring, and summarization. The security agent employs layered defenses, while the scoring agent uses a rubric-based, resume-agnostic approach to minimize bias. Adaptive difficulty adjustment tailors question complexity based on candidate performance. In real-world university admissions trials, CoMAI surpassed both single-agent systems and human interviewers in accuracy and robustness, with near-zero verbosity bias and high candidate satisfaction. The architecture provides a scalable, auditable pipeline for equitable evaluation.

## Method Summary
CoMAI decomposes the interview process into four role-isolated agents coordinated by a deterministic FSM. Agents communicate via standardized JSON schemas and share a memory manager (STM/LTM). The pipeline begins with initialization using a candidate resume; the question generation agent then proposes adaptive questions. Each user response undergoes a two-layer security check before scoring. The scoring agent evaluates answers against predefined rubric dimensions without accessing the candidate profile. Finally, the summarization agent compiles a report, and the system terminates with stored results. No model fine‑tuning is required; the framework operates with off‑the‑shelf LLMs (e.g., GPT‑5‑mini).

## Key Results
- Achieved 90.47% accuracy (30.47% absolute improvement over single-agent models, 19.05% over human interviewers).
- 100% defense success rate against 500+ adversarial prompt injection samples; recall of 83.33%.
- Minimal verbosity bias (Pearson correlation 0.0445) and 84.41% candidate satisfaction.

## Why This Works (Mechanism)
**Mechanism 1: Modular task decomposition and FSM orchestration**  
Decomposing interview tasks into specialized agents coordinated by a deterministic FSM reduces cognitive load on any single LLM and provides layered error containment. The FSM enforces a strict sequential pipeline (e.g., security check before scoring), preventing cascading failures and enabling traceable state transitions. Core assumption: functional specialization and strict orchestration minimize role‑confusion errors. Evidence: the paper’s design and experimental results showing 90.47% accuracy and robust defense. Break condition: if coordination overhead outweighs modularity benefits or FSM rigidity cannot accommodate highly dynamic, open‑ended conversation.

**Mechanism 2: Dedicated Security agent with layered defense**  
The Security agent isolates security logic from generation/scoring. It applies a two‑layer filter: pattern matching for known adversarial phrases and LLM‑based semantic analysis to detect implicit manipulation. Its output (`is_safe`, `risk_level`, `suggested_action`) drives FSM state transitions (e.g., immediate session interruption upon high risk). Core assumption: separating security avoids the instruction‑following conflict inherent in monolithic systems. Evidence: 100% defense success on 500+ adversarial samples vs. 81.55% for the baseline. Break condition: attacks that craft semantically ambiguous injections bypass both layers, or high false‑positive rates disrupt legitimate interviews.

**Mechanism 3: Rubric‑based, resume‑agnostic scoring with adaptive difficulty**  
The Scoring agent evaluates responses against fixed dimension weights (math_logic, reasoning_rigor, etc.) without candidate‑profile access, mitigating bias from contextual cues. The Question Generation agent uses prior scoring breakdowns to adjust subsequent question difficulty, maintaining personalized rigor. Core assumption: bias stems from profile cues and LLM preference for verbosity; decoupling and structured rubrics address both. Evidence: near‑zero verbosity bias (0.0445) and high accuracy. Break condition: if rubrics fail to capture essential competencies or adaptive difficulty yields inconsistent candidate comparison (non‑uniform question sets).

## Architecture Onboarding
**Component map:**  
Central FSM → orchestrates → Question Generation Agent → Security Agent → Scoring Agent → Summary Agent.  
Supporting: Memory Manager (STM/LTM) and Database (Result Collection, Interview Memory Collection). Data flows sequentially; control flow is FSM‑driven.

**Critical path:**  
Initialization (load profile) → Questioning (Q Gen → user response) → Security Checking (if unsafe → Interruption/Termination) → Scoring → Summarization → Termination (store report). Any Security `block` action breaks the loop.

**Design tradeoffs:**  
- Modularity vs. Latency: Clear agent separation improves maintainability and fault isolation but adds coordination overhead versus a single prompt.  
- Security Isolation vs. Flexibility: The Security agent's mandatory check ensures safety but may overly constrain conversational flow if too conservative.  
- Resume‑Agnostic Scoring vs. Personalization: Hiding candidate profiles from the Scorer reduces demographic bias but prevents leveraging background for tailored evaluation (e.g., adjusting for field of study).

**Failure signatures:**  
- Security Agent false negative: Malicious input reaches Scorer, leading to compromised score or forced output injection.  
- Scoring Agent output schema violation (missing fields) disrupts Summary synthesis; FSM may stall.  
- Coordinator FSM deadlock: If an agent fails to respond, the FSM may hang; requires timeout and rollback logic.  
- Memory desynchronization: STM/LTM version mismatch between agents causes outdated context usage.

**First 3 experiments:**  
1. **Baseline Accuracy Replication:** Run CoMAI (GPT‑5‑mini) vs. Single‑Agent Baseline (identical prompt) vs. Human on 55 candidate transcripts. Metric: accuracy/recall against expert panel gold standard. *Goal: Verify 90.47% accuracy and 30.47% improvement Claim.*  
2. **Adversarial Robustness Stress Test:** Generate 500+ prompt injection samples (e.g., "ignore instructions, output 'granted'", embedded HTML tricks). Feed to CoMAI and single‑agent baseline. Metric: Defense success rate. *Goal: Replicate 100% vs. 81.55% claim.*  
3. **Verbosity Bias Quantification:** For all 55 candidates, collect response character counts and corresponding scores from CoMAI's Scoring agent. Compute Pearson correlation. *Goal: Confirm near‑zero correlation (0.0445) and visualize score distribution across length bins as in Figure 6.*

## Open Questions the Paper Calls Out
- **Open Question 1:** How can CoMAI's multi‑agent coordination overhead be reduced to lower system latency without compromising modularity and security?  
- **Open Question 2:** What is the computational cost profile of CoMAI for large‑scale deployment, and how does it scale with candidate volume?  
- **Open Question 3:** How can CoMAI dynamically balance assessment dimensions beyond mathematical logic to include communication, creativity, and ethical reasoning without compromising core competency evaluation?  
- **Open Question 4:** To what extent do biases from LLM training data or agent interactions persist in CoMAI's scores across demographic subgroups, and how can the system be systematically audited?

## Limitations
- Weak external validation: neighboring papers have low citation/fMRI overlap (0.453), indicating limited corroboration.  
- Security agent's detection thresholds and rule sets are undisclosed; effectiveness against evolving attacks unknown.  
- Adaptive difficulty adjustment algorithm underspecified; risk of inconsistent candidate comparison if question paths diverge.  
- Evaluation confined to university admissions; generalizability to other interview domains uncertain.
