# Natural Language Processing Models for Robust Document Categorization
## Quick Facts
- **arXiv ID:** 2602.20336
- **Source URL:** https://arxiv.org/abs/2602.20336
- **Reference count:** 18
- **Primary result:** BiLSTM provides the most balanced solution for resource-constrained IT ticket categorization, achieving 98.56% accuracy with moderate computational cost.

## Executive Summary
This study compares Naive Bayes, BiLSTM, and fine-tuned BERT models for automating the categorization of imbalanced IT support tickets into Problem, Request, and Change classes. BERT achieved the highest mean accuracy (>99%) but required substantial training time (~20 minutes per cycle) and resources. BiLSTM offered a strong compromise at 98.56% accuracy with moderate computational demands and good contextual understanding. Naive Bayes was the fastest (milliseconds) but least accurate (~94.5%). All models were impacted by class imbalance, particularly for the minority "Change" category. A functional demonstrative system was implemented, enabling automated routing with throughput unattainable manually. The authors conclude BiLSTM is the most balanced choice for resource-constrained scenarios.

## Method Summary
The task was automated categorization of imbalanced IT support tickets (3 classes: Problem, Request, Change) using the "Customer IT Support - Ticket Dataset" from Kaggle. Inputs consisted of concatenated subject and body text fields. Preprocessing included lowercasing, removal of special characters and English stop words, and whitespace normalization; empty entries were dropped. Models evaluated were: 1) Naive Bayes (likely MultinomialNB with TF-IDF vectorization), 2) BiLSTM with various architectures (best: 128 batch size, 7 epochs), and 3) fine-tuned BERT (`bert-base-uncased`) with class weighting. Performance metrics included accuracy, precision, recall, and F1-score per class and mean, assessed via repeated k-fold cross-validation. The study balanced classification accuracy against computational cost (training/inference time).

## Key Results
- BERT achieved >99% mean accuracy but required ~20 minutes per training cycle and greater computational resources.
- BiLSTM achieved 98.56% accuracy with moderate training times (e.g., ~95 seconds per run) and good contextual understanding.
- Naive Bayes was the fastest (milliseconds) but had the lowest accuracy (~94.5%).
- All models exhibited reduced recall for the minority "Change" class, indicating persistent impact of class imbalance.

## Why This Works (Mechanism)
- **BERT:** Self-attention layers capture long-range dependencies and deep contextual relationships, yielding high accuracy. However, the transformer architecture is computationally intensive due to large parameter counts and quadratic attention complexity.
- **BiLSTM:** Bidirectional processing allows the model to learn representations from both past and future tokens, efficiently capturing sequential context with fewer parameters than BERT. This provides a favorable trade-off between accuracy and computational cost.
- **Naive Bayes:** Assumes feature independence and uses a probabilistic bag-of-words model, making training and inference extremely fast. Its simplicity limits its ability to capture word order and context, resulting in lower accuracy.
- **Class Imbalance:** Class weighting during training helps mitigate bias toward majority classes but cannot fully compensate for insufficient minority examples, leading to degraded "Change" recall across all models.

## Architecture Onboarding
Component map: Raw Text -> Preprocessing -> Feature Extraction (TF-IDF for Naive Bayes / Tokenization+Padding for BiLSTM / BERT Tokenizer) -> Model (Naive Bayes / BiLSTM / BERT) -> Predictions

Critical path: Data acquisition -> Preprocessing -> Train/test split (or CV folds) -> Feature extraction -> Model training with hyperparameters -> Evaluation -> Comparative analysis.

Design tradeoffs: 
- Accuracy vs. computational cost: BERT maximizes accuracy but at high resource cost; BiLSTM balances both; Naive Bayes minimizes cost at accuracy expense.
- Model complexity vs. interpretability: Naive Bayes is highly interpretable; BiLSTM moderately so; BERT is a black box.
- Imbalance handling: Class weighting is simple but may be insufficient; resampling or advanced losses could improve minority recall but increase complexity.

Failure signatures: 
1) "Change" class recall below 0.85 suggests inadequate imbalance handling or preprocessing removing key terms.
2) BERT training time significantly deviating from ~20 minutes indicates incorrect batch size, learning rate, or hardware mismatch.
3) BiLSTM shows high training accuracy but low validation accuracy, signaling overfitting or poor architecture choices.

First experiments:
1) Train Naive Bayes with TF-IDF (max_features=5000), report metrics and wall-clock training/inference time.
2) Train BiLSTM with 128 embedding dimension, 64 LSTM units per layer, dropout 0.2, batch size 128, 7 epochs; apply class weights computed from training set.
3) Fine-tune BERT-base-uncased with max sequence length 128, batch size 16, learning rate 2e-5 for 3 epochs; incorporate class weights; measure single training cycle time.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can computational efficiency be improved for transformer-based models like BERT in resource-constrained document categorization without significantly sacrificing accuracy?
- **Open Question 2:** To what extent do class imbalance mitigation techniques beyond simple weighting (e.g., resampling, focal loss) improve minority class recall across different model architectures?
- **Open Question 3:** Are the performance trade-offs observed (accuracy vs. computational cost) consistent across diverse text classification domains, or are they specific to IT support tickets?
- **Open Question 4:** What architectural modifications or hybrid approaches (e.g., combining BiLSTM with attention) can close the accuracy gap with BERT while maintaining BiLSTM's computational efficiency?
- **Open Question 5:** How does the choice of text representation (e.g., word embeddings vs. subword tokenization) interact with model architecture to affect performance on imbalanced, short-text documents like support tickets?

## Limitations
- Model hyperparameters for BiLSTM (embedding dimension, LSTM units, dropout) and BERT (epochs, learning rate, sequence length) are incompletely specified, hindering exact replication.
- The study only applies class weighting for imbalance mitigation; it does not explore advanced techniques like resampling or focal loss, limiting claims of robustness for minority classes.
- Hardware details for computational cost measurements are absent, preventing accurate scalability assessment and fair comparison across resource-constrained environments.

## Confidence
- "BERT achieves >99% mean accuracy": Medium (plausible for fine-tuned BERT but dependent on unreported training setup).
- "BiLSTM offers the most balanced solution": Medium (contingent on the specific unreported architecture and the authors' resource constraints).
- "Naive Bayes was the fastest (milliseconds)": High (aligns with algorithmic complexity and empirical evidence).
