# Self-Auditing Parameter-Efficient Fine-Tuning for Few-Shot 3D Medical Image Segmentation
## Quick Facts
- **arXiv ID**: 2603.05822
- **Source URL**: https://arxiv.org/abs/2603.05822
- **Reference count**: 30
- **Primary result**: SEA-PEFT automates adapter selection for few-shot 3D medical segmentation, improving mean Dice by 2.4–2.8 points over strongest PEFT baselines while training <1% parameters, with end-to-end runtime 2.5–6.5 hours.

## Executive Summary
SEA-PEFT addresses the challenge of configuring parameter-efficient fine-tuning (PEFT) for few-shot 3D medical segmentation. It frames adapter selection as an online allocation problem: iteratively training a subset of adapters, auditing their individual contributions via temporary deactivation on a validation set, and greedily allocating a new subset under a tight parameter budget. Stabilization techniques—exponential moving average, interquartile range smoothing, and a finite-state machine—prevent erratic changes. Evaluated on TotalSegmentator and FLARE’22 with 1/5/10-shot settings, SEA-PEFT yields mean Dice gains of 2.4–2.8 points over the best fixed-topology PEFT baselines, uses less than 1% trainable parameters, and runs in 2.5–6.5 hours on a single V100 GPU.

## Method Summary
SEA-PEFT begins with a pre-trained Swin-UNETR backbone and a library of candidate adapter modules (LoRA, AdaptFormer, AFFine-LN) placed across transformer layers. Each adapter has an associated parameter cost. The algorithm runs a search-audit-allocate loop for a predetermined number of training steps. In each cycle, it trains the currently active adapters for K steps, then audits a random sample of M adapters: for each, it temporarily deactivates it, computes validation Dice, and measures the drop ΔDice; the utility is defined as ΔDice divided by the adapter’s cost. Utilities are smoothed via exponential moving average and interquartile range over a history window. Allocation then solves a greedy knapsack problem on the smoothed utility densities under a budget P_max (≤1% of backbone parameters). A finite-state machine (FSM) with vote counters τ_act stabilizes changes: an adapter’s status flips only if its counter exceeds the threshold. After the loop, a final knapsack without exploration yields the selected adapter set. These adapters are reinitialized and the model is fine-tuned from scratch for 200 epochs (early stopping on validation). The final model is evaluated on the test set.

## Key Results
- **Dice improvement**: Mean Dice increases by 2.4–2.8 points over the strongest fixed-topology PEFT baselines across 1-shot, 5-shot, and 10-shot settings.
- **Parameter efficiency**: Less than 1% of the backbone parameters are trained.
- **Runtime**: End-to-end execution takes 2.5–6.5 hours on a V100 GPU.

## Why This Works (Mechanism)
SEA-PEFT treats adapter selection as a dynamic resource allocation problem. By directly measuring each adapter’s marginal contribution (ΔDice) on a validation set and normalizing by its parameter cost, the algorithm estimates a utility density that reflects efficiency. The iterative loop allows utilities to be refined as training progresses, while smoothing (EMA/IQR) mitigates noise inherent in few-shot validation. The greedy knapsack efficiently selects a near-optimal subset within the budget. The FSM acts as a low-pass filter, requiring persistent evidence before flipping an adapter’s state, which prevents oscillations and encourages convergence to a stable configuration. This closed-loop search-audit-allocate process effectively automates what would otherwise be a manual, trial-and-error design of PEFT topology.

## Architecture Onboarding
**Component map**: 
   Pre-trained Swin-UNETR Backbone + Adapter Library -> Active Adapter Subset -> Model -> Train (K steps) -> Validation Dice -> Audit (sample M adapters, toggle off each, compute ΔDice) -> Utility Estimation -> Smoothing (EMA + IQR) -> Greedy Knapsack -> Proposed Active Set -> FSM (vote counters) -> Update Active Subset -> repeat -> after total_steps: Final Knapsack -> Selected Adapters -> Reinitialize -> Fine-tune (200 epochs) -> Test Evaluation.

**Critical path**: 
1. Preprocess 3D medical volumes into 96³ patches; split shots into training and validation sets.
2. Load pre-trained backbone; instantiate all candidate adapters with parameter costs.
3. Initialize active adapter set (typically empty or random).
4. Loop for total_steps / K cycles:
   a. Train model with active adapters for K steps (AdamW, lr=1e-3, batch=1).
   b. Audit: sample M adapters; for each, deactivate, run validation inference, compute Dice; restore.
   c. Compute utility = (Dice_without - Dice_with) / cost; update EMA and IQR for smoothed utility.
   d. Allocate: sort adapters by smoothed_utility/cost, greedily select until budget P_max reached.
   e. FSM: for each adapter, if proposed status differs from current, increment vote counter; else reset. If counter ≥ τ_act, flip status.
5. After loop, run final knapsack on the latest smoothed utilities without ε exploration; optionally perform single-swap refinements.
6. Reinitialize selected adapters (random weights); freeze backbone; train from scratch for up to 200 epochs with early stopping on validation.
7. Evaluate final model on test set.

**Design tradeoffs**:
- **Greedy vs. exact knapsack**: Greedy is O(n log n) and nearly optimal for independent items, but ignores combinatorial interactions (e.g., synergy between adapters). Exact dynamic programming is exponential.
- **Smoothing aggressiveness**: EMA (β=0.9) heavily weights recent estimates but may lag; IQR over history H trims outliers but can smooth out real shifts. λ_S balances the two. Too much smoothing delays adaptation; too little yields chatter.
- **FSM threshold τ_act**: Low τ_act (e.g., 2) allows fast adaptation but risks instability; high τ_act (e.g., 4) stabilizes but slows convergence. The paper uses τ_act≈2–3.
- **Exploration fraction ε**: Upweighting low-utility adapters ensures they get audited; ε=0.1 balances exploration/exploitation. Too high ε injects noise; too low may miss good adapters.
- **Budget P_max**: Tight budget (<1% params) forces extreme sparsity; might discard useful but slightly more expensive adapters. Looser budget increases parameters.

**Failure signatures**:
- **Chatter**: Frequent active set changes (>30 per 100 cycles) → utilities too noisy or τ_act too low. Remedy: increase τ_act, increase IQR history H, or increase λ_S.
- **Under-utilization**: Total selected cost ≪ P_max → Exploration too high, utilities systematically low, or FSM preventing additions. Check ε, inspect utility distribution; maybe decrease ε or λ_S.
- **Degraded final Dice**: Search-selected adapters perform poorly after fine-tuning → utilities poorly correlated with true benefit. Evaluate correlation between search-phase smoothed utilities and final test Dice; increase total_steps or fine-tuning epochs.
- **Validation overfitting**: Dval is extremely small (e.g., 1 volume for 1-shot), causing high variance in Dice estimates → utilities noisy. Use more validation patches if possible, increase IQR history, or aggregate Dice over multiple patch samples.

**Exactly 3 first experiments**:
1. **Convergence sanity check**: Run SEA-PEFT on a single organ (e.g., liver) with 5 shots using default hyperparameters. Log active set size and stability over cycles; expect convergence to a stable set within total_steps.
2. **Utility sanity check**: After the first audit cycle, print top-5 and bottom-5 adapter utilities (smoothed). Verify that adapters with higher ranks or more relevant layers (e.g., early self-attention) have higher utilities; test that deactivating a random adapter reduces Dice.
3. **Budget adherence**: After the final knapsack, sum parameter costs of selected adapters. It should be ≤ P_max (0.01 × backbone params) and typically close to it. If significantly under, adjust ε downward or λ_S.
