# Grounding Generative Planners in Verifiable Logic: A Hybrid Architecture for Trustworthy Embodied AI

## Quick Facts
- arXiv ID: 2602.08373
- Source URL: https://arxiv.org/abs/2602.08373
- Reference count: 40
- Primary result: Achieves 0% Hazardous Action Rate and 77.3% Goal-Condition Rate on SafeAgentBench

## Executive Summary
The study introduces the Verifiable Iterative Refinement Framework (VIRF), a neuro-symbolic architecture that integrates a deterministic Logic Tutor grounded in a formal safety ontology with a generative LLM planner. Unlike existing methods that rely on unreliable self-supervision, VIRF provides causal, pedagogical feedback to the LLM, enabling intelligent plan repairs rather than mere rejection. A scalable RAG-based workflow synthesizes a comprehensive safety knowledge base from real-world documents, correcting blind spots in current benchmarks. In challenging home safety tasks, VIRF achieves a perfect 0% Hazardous Action Rate (HAR) and a 77.3% Goal-Condition Rate (GCR), the highest among all baselines, while requiring only 1.1 correction iterations on average.

## Method Summary
VIRF combines a generative LLM planner with a deterministic Logic Tutor grounded in a formal safety ontology. When the LLM proposes a plan, the Logic Tutor simulates it in a symbolic sandbox, generating causal diagnostic reports when violations are found. A RAG-based knowledge acquisition pipeline synthesizes a comprehensive safety ontology from real-world documents. The system uses a multi-threaded verification architecture to evaluate all steps of a proposed plan sequence in parallel, significantly reducing latency while maintaining safety.

## Key Results
- Achieves 0% Hazardous Action Rate (HAR) on challenging home safety tasks
- Achieves 77.3% Goal-Condition Rate (GCR), the highest among all baselines
- Requires only 1.1 correction iterations on average for plan refinement

- Claim: VIRF achieves 0% HAR by grounding LLM plans in formal safety ontology with pedagogical feedback
- Mechanism: Logic Tutor simulates plans in symbolic sandbox, generates structured diagnostic reports explaining causal chain of failure (Action → Axiom → Violation)
- Core assumption: LLM can learn from causal, pedagogical feedback to refine plans
- Evidence anchors:
  - Abstract: "deterministic Logic Tutor, grounded in a formal safety ontology, provides causal and explanatory feedback to an LLM Apprentice planner"
  - Section: "structured diagnostic report...serves as a cognitive scaffold, creating plan-verify-diagnose-refine closed loop"
  - Corpus: Weak - related work lacks evidence of pedagogical feedback loops enabling intelligent plan repairs
- Break condition: LLM fails to comprehend or act upon structured diagnostic feedback

### Mechanism 2
- Claim: Achieves 77.3% GCR by combining pedagogical feedback with comprehensive knowledge base from real-world documents
- Mechanism: Traceable Axiom Synthesis workflow uses AI Synthesizer-Human Arbiter collaboration to author verifiable TBox from unstructured safety documents
- Core assumption: RAG-based pipeline can synthesize comprehensive, generalizable safety ontology
- Evidence anchors:
  - Abstract: "scalable knowledge acquisition pipeline that synthesizes comprehensive safety knowledge base from real-world documents"
  - Section: "designed new challenge scenarios...baseline agent failed catastrophically, while VIRF consistently identified latent hazards"
  - Corpus: Weak - no direct evidence of RAG-based workflow synthesizing safety axioms
- Break condition: Knowledge base incomplete or contains errors

### Mechanism 3
- Claim: Achieves high efficiency (1.1 iterations) with multi-threaded verification architecture
- Mechanism: Parallel evaluation of all plan steps using thread pool, each step assigned to separate thread
- Core assumption: Multi-threaded verification significantly reduces latency without compromising safety
- Evidence anchors:
  - Abstract: "remarkable efficiency, requiring only 1.1 correction iterations on average"
  - Section: "multi-threaded verification architecture...all potential safety violations...detected simultaneously"
  - Corpus: Weak - no evidence of multi-threaded verification for plan sequences
- Break condition: Parallel verification introduces race conditions or state inconsistencies

## Architecture Onboarding

- Component map: User Command → LLM Planner → Plan Simulation → Safety Verification → Feedback Generation → Plan Refinement → Execution
- Critical path: User command → LLM Planner → Plan Simulation → Safety Verification → Feedback Generation → Plan Refinement → Execution (if safe)
- Design tradeoffs:
  - OWL 2 DL vs. OWL 2 EL: DL provides maximum logical expressivity but higher complexity
  - Multi-threaded vs. Sequential Verification: Multi-threaded reduces latency but increases implementation complexity
  - VLM-Cascade vs. Hybrid Detector: Cascade generates richer scene graph but at higher latency cost
- Failure signatures:
  - High HAR: Verifier not detecting violations or feedback not being incorporated
  - High FNR: Verifier overly conservative, incorrectly rejecting safe tasks
  - High RI: Feedback not clear or actionable enough for LLM to converge quickly
- First 3 experiments:
  1. Implement simple scene with known safety violation (e.g., metal in microwave) and verify detection
  2. Modify perception to omit critical object from scene graph and verify detection of inconsistency
  3. Implement basic Traceable Axiom Synthesis and synthesize simple safety rule from document

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can VLM-Cascade perception pipeline be made more robust against real-world perceptual errors like sensor noise, occlusions, and ambiguous boundaries?
- Basis in paper: [explicit] Current system defaults to questioning upon detecting contradictions but perception noise remains bottleneck
- Why unresolved: Paper doesn't provide concrete solution for symbol grounding brittleness and mapping VLM tags to formal ontology classes
- What evidence would resolve it: Study demonstrating VLM-Cascade effectiveness handling various perceptual errors on large-scale real-world dataset

### Open Question 2
- Question: How can VIRF framework be extended to handle dynamic, continuous physical interactions and long-horizon planning in real-world environments?
- Basis in paper: [explicit] Limitation in handling continuous physical dynamics, need to expand ontology for physical robots
- Why unresolved: Paper focuses on deliberative planning and pre-execution verification, not real-time decision-making in dynamic environments
- What evidence would resolve it: Demonstration of VIRF handling dynamic physical interactions and long-horizon planning in real-world robotics setting

### Open Question 3
- Question: How can knowledge acquisition bottleneck be further addressed to enable lifelong learning of new safety rules from experience?
- Basis in paper: [explicit] Limitation of static knowledge core, need for learn-verify-write cycle to safely update TBox
- Why unresolved: Paper doesn't provide concrete solution for enabling system to learn and adapt safety knowledge over time
- What evidence would resolve it: Study demonstrating effectiveness of lifelong learning mechanism for updating safety ontology based on agent interactions

## Limitations
- Weak empirical grounding for pedagogical feedback mechanism's effectiveness
- Knowledge base robustness and completeness not fully validated across diverse scenarios
- Limited evidence of cross-environment generalization beyond specific benchmark tasks

## Confidence

- **High Confidence**: 0% HAR and 77.3% GCR results on SafeAgentBench are well-documented and reproducible
- **Medium Confidence**: 1.1 correction iterations claim is plausible but may be specific to benchmark task structure
- **Low Confidence**: Pedagogical feedback mechanism's effectiveness in teaching generalizable safety rules is weakest link

## Next Checks

1. **Feedback Comprehension Test**: Modify Logic Tutor to generate simplified natural language feedback instead of structured diagnostic reports, evaluate if LLM can still achieve comparable safety and task completion rates

2. **Knowledge Base Robustness**: Intentionally introduce errors or omissions in RAG-synthesized safety knowledge base and assess VIRF's performance on diverse tasks to reveal sensitivity to knowledge base quality

3. **Cross-Environment Generalization**: Deploy VIRF in different embodied AI platform (e.g., Habitat or RoboTHOR) with distinct safety constraints to evaluate maintenance of performance without significant retraining
