# DLLM Agent: See Farther, Run Faster
## Quick Facts
- arXiv ID: 2602.07451
- Source URL: https://arxiv.org/abs/2602.07451
- Reference count: 40
- Primary result: Diffusion LLM agents match autoregressive accuracy on BrowseComp-zh (15.5%) while reducing end-to-end inference time by over 30% and requiring fewer interaction turns and tool calls.

## Executive Summary
This work compares diffusion-based and autoregressive large language models within a unified tool-use agent framework. Under identical fine-tuning trajectories and evaluation budgets, diffusion agents achieve equivalent final accuracy on a web-browsing benchmark but are significantly more efficient, using fewer turns and tool calls, showing higher planning coverage, and experiencing fewer conflict corrections. However, they produce a higher rate of invalid tool calls and exhibit worse calibration. Task-type analysis reveals complementary strengths: diffusion excels at constrained, multi-constraint and evidence-reconciliation problems, while autoregressive models perform better on linear multi-hop chains. The results suggest that diffusion's iterative refinement supports earlier global convergence at the cost of structured reliability, highlighting the need for better tool-call-specific training and alignment.

## Method Summary
The study uses the DeepDiver-v2 agent architecture with two 7B parameter backbones: openPangu-Embedded-7B (autoregressive) and openPangu-R-7B-Diffusion (diffusion). Both models are fine-tuned on an identical dataset of agent trajectories, each consisting of a history context H<sub>t-1</sub> and the next action segment x<sub>t</sub>. For the diffusion model, training employs a conditional denoising loss (L<sub>MDM</sub>) augmented with an auxiliary autoregressive loss (L<sub>AR</sub>, weight λ=0.5). During training, only the action spans are corrupted (context-clean corruption), and span-aware attention masking prevents information leakage across the corrupted region. Action segments are serialized with BEGIN_ACTION/END_ACTION delimiters. Both models are trained for 5 epochs with a learning rate decay from 5e-6. Evaluation runs on a 110-question subset of the BrowseComp-zh benchmark under fixed resource budgets: 32K context length, maximum 15 interaction turns, and a cap on tool calls.

## Key Results
- Diffusion agents achieve equal final accuracy (15.5% on BrowseComp-zh) to AR baselines while reducing end-to-end inference time by >30%, interaction turns (13.0 vs. 14.8), and tool calls (6.7 vs. 7.5), and show higher planning coverage (62% vs. 38%) with fewer conflict corrections.
- However, diffusion agents have a higher invalid action rate (6.4% vs. 1.9%) and worse calibration (higher ECE).
- Task analysis reveals diffusion excels on constraint-intersection and evidence-reconciliation problems, while AR performs better on linear multi-hop chains.

## Why This Works (Mechanism)
Diffusion-based agents iteratively refine the action segment via conditional denoising over multiple steps, allowing the model to incorporate information from the entire context at each refinement step. This global perspective supports earlier identification of consistent multi-step plans, reducing avoidable conflicts and unnecessary tool calls, which explains the lower turn count and faster end-to-end time. The context-clean corruption strategy ensures that the learning signal focuses on the action generation while preserving the integrity of the historical context, and the span-aware attention mask enforces proper separation between context and action during denoising. The auxiliary AR loss stabilizes training by retaining a token-level prediction objective. In contrast, autoregressive generation proceeds left-to-right without global refinement, leading to myopic decisions that cause more backtracking and tool interactions. However, diffusion's iterative process, if not tightly constrained, can yield malformed action outputs due to accumulated formatting errors, accounting for the higher invalid action rate and poorer calibration.

## Foundational Learning
- **Diffusion Models**: probabilistic generative models that iteratively denoise from a random starting point. *Why needed*: Provides a mechanism for multi-step refinement, enabling global planning in action generation. *Quick check*: Can explain forward diffusion and reverse denoising process.
- **Autoregressive Language Modeling**: predicts next token conditioned on previous tokens. *Why needed*: Baseline generative paradigm for sequential action generation. *Quick check*: Understands left-to-right token prediction and its limitations for planning.
- **Agent Tool-Use**: LLMs interacting with external tools via structured calls. *Why needed*: The application domain where these models are evaluated. *Quick check*: Knows how tool calls are parsed and executed within an agent loop.
- **Conditional Denoising Loss (L<sub>MDM</sub>)**: loss used in masked diffusion models to denoise only the target span. *Why needed*: Enables diffusion to focus on generating clean action tokens while keeping context fixed. *Quick check*: Identifies that only action tokens are corrupted and predicted.
- **Span-Aware Attention Masking**: attention mechanism that prevents communication between context and action spans during diffusion. *Why needed*: Maintains separation so context is not corrupted and action generation is conditioned properly. *Quick check*: Recognizes that attention is restricted within spans during denoising steps.
- **Auxiliary Autoregressive Loss**: additional cross-entropy loss on clean action tokens to stabilize training. *Why needed*: Mitigates instability in diffusion fine-tuning by preserving AR objective. *Quick check*: Understands that λ balances between diffusion and AR losses.

## Architecture Onboarding
**Component Map**:  
User query → Agent state (history) → Action Generation Module (DLLM: iterative denoising with context-clean corruption and span attention; AR: single forward pass) → Action parser → Tool executor → Observation → Updated history → termination check.

**Critical Path** (core execution loop):
1. Receive user question, initialize history.
2. Generate next action segment using the backbone model.
   - DLLM: Initialize action span with noise, perform K denoising steps (each: predict noise for action tokens, update, apply span attention & context unchanged).
   - AR: Autoregressive sampling until END_ACTION token.
3. Parse action into structured tool call; if invalid, either retry or record error.
4. Execute tool, obtain observation.
5. Append action and observation to history.
6. Repeat from step 2 up to turn limit or call cap.
7. Return final answer after last turn.

**Design Tradeoffs**:
- DLLM: Offers global refinement per turn, leading to better planning and efficiency, but introduces computational overhead (multiple denoising steps) and higher risk of malformed outputs. Requires careful training (L<sub>MDM</sub> + L<sub>AR</sub>) and inference hyperparameters (confidence threshold τ).
- AR: Simpler, lower latency per token, more reliable action formatting, but prone to myopic decisions resulting in more turns, more tool calls, and later convergence.
- Both require strict adherence to tool schemas; diffusion models suffer more without explicit constraints, pointing to a need for schema-aware objectives.

**Failure Signatures**:
- DLLM: Invalid action rate spikes: missing BEGIN_ACTION/END_ACTION, wrong field types, empty arguments; calibration plots show overconfidence; often corrected by a single retry but may exceed turn budget.
- AR: High conflict corrections: repeated tool calls with contradictory parameters, backtracking, low PlanRate; manifests as many rounds with similar actions but different parameters.
- Shared: Parsing errors due to delimiter issues; can be diagnosed by regex validation.

**First Three Experiments**:
1. **Parser Validation**: Run both models on a small set of prompts, collect raw outputs, and apply the deterministic parser. Measure exact match, structural validity (well-formed JSON or required fields), and identify common syntax errors (missing delimiters, extra tokens).
2. **Invalid Action Rate vs. Confidence Threshold**: For DLLM, vary the adaptive decoding confidence threshold τ and record invalid action rate and average denoising steps. Determine the τ that minimizes invalid actions while maintaining planning coverage.
3. **Planning Coverage Probe**: On a subset of BrowseComp-zh with known constraint-intersection and linear multi-hop questions, compute PlanRate (fraction of turns where a valid plan covering remaining constraints is produced) and conflict correction count for both models. Verify that DLLM shows higher PlanRate on constraint tasks and AR on linear tasks.

## Open Questions the Paper Calls Out
- Do the efficiency and planning advantages of diffusion LLM agents generalize to longer-horizon workflows, richer tool ecosystems, and embodied environments?
- How can the higher invalid action rate in diffusion-based agents be mitigated when tool calls require strict schema compliance?
- Do diffusion-based agents under-explore in tasks requiring hypothesis branching and multi-path verification, and how can calibrated exploration be introduced without sacrificing efficiency?
- How can reinforcement learning be effectively applied to diffusion-based tool agents given the two-timescale optimization and sparse validity rewards?

## Limitations
- Trajectory dataset details (source, size, collection) are missing, preventing exact replication of the training distribution.
- Critical diffusion hyperparameters (number of steps K, block size, corruption ratio, adaptive decoding threshold τ) are unspecified, hindering precise reconstruction of the DLLM agent.
- Evaluation details such as exact action segmentation rules and turn counting are unclear, which could affect reported metrics for invalid actions and interaction counts.

## Confidence
- Efficiency gains (time, turns, calls): Medium
- Planning coverage and conflict reduction: Medium
- Accuracy parity (15.5% on BrowseComp-zh): High
- Invalid action rate & calibration: Medium
- Task-specific performance differences: Low

## Next Checks
