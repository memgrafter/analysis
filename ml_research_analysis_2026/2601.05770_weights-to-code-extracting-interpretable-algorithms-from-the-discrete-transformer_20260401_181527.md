# Weights to Code: Extracting Interpretable Algorithms from the Discrete Transformer

## Quick Facts
- **arXiv ID:** 2601.05770  
- **Source URL:** https://arxiv.org/abs/2601.05770  
- **Reference count:** 40  
- **Primary result:** Extracts human-readable programs from trained Discrete Transformers that match or exceed RNN-based program induction in accuracy (1.00) and achieve very low RMSE (1e-5–1e-3), while scaling to continuous-variable tasks where prior methods fail.

## Executive Summary
The paper introduces the Discrete Transformer, an architecture designed to overcome the entanglement (superposition) that hinders algorithm extraction from standard Transformers. It enforces functional disentanglement by using scalar residual streams, separating information routing (Numerical Attention) from element-wise arithmetic (Numerical MLP), and training with temperature-annealed differentiable sampling to induce a discrete computational graph. A post-hoc extraction pipeline combines hypothesis testing for attention patterns and symbolic regression for MLP modules, compiling an interpretable program. On algorithmic tasks—including continuous dynamics—the method achieves high fidelity, demonstrating that architectural constraints coupled with discrete optimization enable reliable program synthesis.

## Method Summary
The approach constructs a Discrete Transformer with a scalar-based residual stream. Each layer reads from the stream via a differentiable pointer (`S(W_read, τ)`), then processes selected values through two parallel module types: Numerical Attention (which retrieves a past scalar using a hard-attention router) and Numerical MLP (which applies a shallow, low-dimensional arithmetic network to its inputs). Training uses geometric temperature annealing (`τ`: 10.0 → 0.1) to transition from soft continuous optimization to a hard discrete graph. Extraction first classifies each Attention head’s pattern (e.g., Fixed Offset, Windowed Extrema) via hypothesis tests on its attention matrix, then uses PySR symbolic regression on input-output pairs from each MLP sub-module to derive closed-form expressions. Finally, backward traversal from the sparse linear output head assembles these pieces into an executable Python program.

## Key Results
- Extracted programs match ground-truth algorithms on discrete tasks (e.g., `sum_last2`, `parity_last2`) with perfect accuracy and near-zero RMSE, comparable to RNN-based MIPS.
- Extends successfully to continuous-variable tasks (exponential moving average, free fall height) that MIPS cannot handle, demonstrating broader applicability.
- Analysis reveals a clear phase transition during annealing: functional loss drops before structural discretization completes, enabling fine-grained control over the emergent algorithm.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Strict functional separation between Numerical Attention (routing) and Numerical MLP (arithmetic) reduces superposition, enabling interpretable extraction.
- **Mechanism:** The scalar residual stream and discrete pointer operations prevent mixing of feature directions. Attention only copies past scalars; narrow MLPs perform isolated element-wise operations.
- **Evidence:** Architecture aligns with RASP; ablations show narrow MLPs (`k=2`, small `d_hid`) are recoverable via symbolic regression.
- **Break condition:** Wide or high-dimensional MLPs may learn entangled functions that symbolic regression cannot simplify.

### Mechanism 2
- **Claim:** Temperature-annealed differentiable sampling creates a continuous-to-discrete homotopy, guiding the model to a stable, interpretable graph.
- **Mechanism:** High `τ` allows gradient flow through soft selections; annealing sharpens distributions toward one-hot pointers, first optimizing function then freezing structure.
- **Evidence:** Metrics show `L_soft` decreasing before `Δ(e)` (discretization discrepancy) drops and `A(e)` (structural agreement) rises.
- **Break condition:** Too-fast annealing locks in suboptimal discrete choices; too-slow may yield redundant modules.

### Mechanism 3
- **Claim:** Modular extraction—hypothesis testing for Attention patterns and symbolic regression (PySR) for MLP arithmetic—faithfully recovers executable programs.
- **Mechanism:** Statistical tests classify Attention heads into templates; PySR fits simple expressions to MLP I/O. Sparse output head prunes unused variables, and backward traversal compiles code.
- **Evidence:** Extracted programs replicate known algorithms (e.g., `y_t = x_t + x_{t-1}`) with low RMSE across tasks.
- **Break condition:** Unrecognized Attention patterns or complex MLP functions lead to “unmatched” components or inaccurate expressions.

## Foundational Learning
- **Concept: Superposition & Polysemanticity**  
  *Why needed:* Standard Transformers entangle features across directions, making it hard to map neurons to single variables. Understanding this explains why the Discrete Transformer’s scalar disentanglement is necessary.  
  *Quick check:* If a neuron activates for multiple unrelated features, symbolic regression would struggle to assign it a single interpretable role.

- **Concept: Differentiable Discrete Optimization (Gumbel-Softmax / Sparsemax Annealing)**  
  *Why needed:* The core training mechanism relies on making discrete pointer selections differentiable. The annealing trade-off between gradient flow and true discreteness is key to the phase transition.  
  *Quick check:* Using purely softmax sampling (no annealing) would likely fail to crystallize a discrete structure, leaving the model in a continuous, uninterpretable state.

- **Concept: Symbolic Regression (Genetic Algorithm Search)**  
  *Why needed:* Extraction of MLP logic depends on finding simple closed-form expressions from black-box I/O. PySR’s search balances complexity and error, which works only if the underlying function is simple.  
  *Quick check:* A wider MLP (`d_hid=32`) would expand the expression search space, likely yielding more complex or incorrect formulas.

## Architecture Onboarding
- **Component map:**  
  Input → Numerical Residual Stream (scalar list) → Discretized Reading (`u = S(W_read, τ) * h_l`) → split into Numerical Attention (router) and Numerical MLP (operator) → concatenate outputs back to Residual Stream → repeat per layer → Linear Output Head (`ŷ = w_out^⊤ h_final`).

- **Critical path:** For each layer: read relevant scalars from current residual stream; Attention copies a past scalar; MLP computes a new scalar; both are appended. The final head aggregates a sparse subset of final scalars.

- **Design tradeoffs:**  
  Expressivity vs. Interpretability: More layers/heads increase capacity but cause redundancy (multiple modules learning same function), complicating extraction.  
  Annealing schedule: Faster annealing risks poor discrete optima; slower improves resolution but extends training.  
  Inductive bias strength: Narrow MLPs (`k=2`, small `d_hid`) ensure recoverable functions but may require deeper stacks for complex tasks.

- **Failure signatures:**  
  Training: High, non-decreasing MSE; `A(e)` remains low and `Δ(e)` high after annealing → no stable discrete graph formed.  
  Extraction: Many Attention heads labeled “unmatched”; PySR returns overly complex or non-converged expressions; assembled program yields high RMSE on validation.  
  Compiled code: Orphan variables, contradictory logic, inability to simplify to known algorithms.

- **First 3 experiments:**  
  1. Train a minimal 1-layer, 2-head, 2-sub-MLP model on `sum_last2`; extract and verify recovery of `y_t = x_t + x_{t-1}`.  
  2. On `parity_last2`, log `L_soft`, `L_hard`, `A(e)`, `Δ(e)` during annealing; expect `L_soft` drop followed by sharp `Δ(e)` decline and `A(e)`→1.0.  
  3. Train `maximum_prev2` with/without sub-MLPs; expect MLP-based ReLU max in standard case, but `Windowed Extrema` Attention pattern when sub-MLPs are disabled.

## Open Questions the Paper Calls Out
1. Can algorithm extraction be adapted to standard Transformer architectures that lack functional disentanglement? The Discrete Transformer’s scalar, separated design is not directly applicable to dense vector models.
2. What drives the phase transition during temperature annealing, and can it be predicted or scheduled adaptively? The current geometric schedule is heuristic.
3. Does symbolic regression scale to sub-modules with more-than-two inputs or larger hidden layers? The paper restricts `k=2` and small `d_hid` for tractability.

## Limitations
- The method requires careful hyperparameter selection (layers, heads, sub-MLPs) per task; optimal configurations are not fully generalized.
- Extraction relies on Attention patterns conforming to one of two hypothesized templates; deviations lead to loss of critical steps.
- Dataset generation details (input distributions, sequence lengths) are underspecified, blocking exact replication.

## Confidence
- **Functional disentanglement (High).** Strong ablations and alignment with RASP support the claim, though narrow-MLP break condition lacks full validation.
- **Annealing dynamics (Medium).** Phase transition is empirically clear, but hybrid sampling function `S(·,τ)` is underspecified, hindering exact replication.
- **Modular extraction (Medium).** Works on benchmark tasks, but robustness to non-template Attention or complex MLP functions is uncertain.
