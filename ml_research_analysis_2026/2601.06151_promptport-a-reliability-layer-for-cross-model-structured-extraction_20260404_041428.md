# PromptPort: A Reliability Layer for Cross-Model Structured Extraction

## Quick Facts
- arXiv ID: 2601.06151
- Source URL: https://arxiv.org/abs/2601.06151
- Reference count: 0
- Primary result: PromptPort achieves 0.890 F1 (99.3% of per-field oracle) by combining deterministic canonicalization and a DistilBERT verifier, recovering format failures and enabling cross-model semantic selection without modifying base LLMs.

## Executive Summary
Structured extraction with LLMs fails in production due to "format collapse"—models output varied, unparsable formats (fenced JSON, prose wrappers). This paper introduces PromptPort, a model-agnostic reliability layer that uses a deterministic canonicalizer to fix format issues and a DistilBERT verifier to select semantically correct field values across model outputs. On a 37k-example camera metadata benchmark, it recovers format failures (+6–8 F1) and adds verifier-driven semantic gains (+14–16 F1), reaching 0.890 F1 (99.3% of per-field oracle). The approach generalizes to held-out model families and provides explicit abstention, offering a practical solution for reliable structured extraction without retraining base models.

## Method Summary
PromptPort consists of three components: a deterministic canonicalizer that standardizes raw LLM outputs into valid JSON (stripping fences, repairing syntax, normalizing keys); a DistilBERT verifier trained to score per-field correctness given the query and candidate JSON; and a conservative safe-override policy that aggregates multiple model outputs using verifier confidence thresholds. The system operates as a post-processing layer, requiring only cached model outputs and a validation set for threshold tuning. It separates format reliability (ROS) from semantic capability (CSS), allowing targeted improvements.

## Key Results
- Format collapse is severe: Gemma-2B shows ROS 0.116 vs CSS 0.246, a 0.130 gap indicating many outputs fail strict parsing.
- Cross-model portability gaps are large: ROS gap between best and worst models is 0.569, highlighting model-specific brittleness.
- PromptPort achieves 0.890 F1, 99.3% of the per-field oracle (0.896), with override precision 87.2% and abstain precision 91.3%.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Deterministic canonicalization recovers a substantial portion of failures attributable to format variability (e.g., fenced JSON, prose wrappers).
- **Mechanism:** A rule-based pipeline strips delimiters, extracts the most plausible JSON substring via bracket matching, repairs common syntax issues (trailing commas, single quotes), and normalizes keys/values (case-insensitive matching, unit standardization). Missing schema keys are filled with `null`.
- **Core assumption:** Format deviations follow predictable patterns that can be addressed without model-specific tuning.
- **Evidence anchors:** Abstract: "combining deterministic canonicalization... recovers format failures (+6–8 F1)"; Section 4: Details the five-step canonicalization process and quantifies the ROS→CSS gap (e.g., Gemma-2B ROS 0.116 vs CSS 0.246).
- **Break condition:** Outputs with severe, non-standard syntax errors or completely non-JSON structures (e.g., pure prose lists) beyond the repair heuristics' scope will fail canonicalization.

### Mechanism 2
- **Claim:** A lightweight verifier (DistilBERT) learns to judge per-field semantic correctness from the query and candidate output, enabling cross-model selection.
- **Mechanism:** The verifier is a binary classifier trained on (query, candidate JSON) pairs to predict if each field's value matches the gold label. It outputs confidence scores used by the safe-override policy.
- **Core assumption:** Semantic errors (incorrect or hallucinated values) produce detectable signals in the query-output interaction that generalize across model families.
- **Evidence anchors:** Abstract: "adds verifier-driven semantic selection (+14–16 F1 beyond canonicalization)"; Section 5: "verifier is a DistilBERT classifier that takes (query, candidate JSON) as input and outputs six probabilities—one per field"; Section 6.2 (Ablations): Output-only verifier yields minimal gain (0.695 F1 vs baseline 0.685), while query+output yields 0.890 F1, confirming both inputs are essential.
- **Break condition:** A significant domain shift (e.g., new schema types, languages, or query styles) not represented in the training distribution may degrade the verifier's calibration.

### Mechanism 3
- **Claim:** A conservative safe-override policy, using verifier confidence thresholds, approaches per-field oracle performance while providing explicit abstention.
- **Mechanism:** For each field, keep the base model's value if its verifier confidence exceeds `τ_keep`. Override with an alternative only if its confidence exceeds `τ_take` and is substantially higher. Abstain (return `null`) if no candidate meets `τ_keep`.
- **Core assumption:** Verifier confidence scores are well-calibrated predictors of correctness, and a conservative policy (few overrides) prevents catastrophic degradation from incorrect overrides.
- **Evidence anchors:** Abstract: "achieving 0.890 F1 (99.3% of per-field oracle 0.896)... provides explicit abstention"; Section 6.1: Diagnostics show override precision 87.2% and abstain precision 91.3%, and the policy achieves near-oracle F1; Section 5: Policy described as "conservative: it starts from the best single model and only overrides when highly confident."
- **Break condition:** Poorly tuned thresholds (e.g., `τ_keep` too low/high) could lead to excessive overrides (degrading accuracy) or excessive abstentions (reducing coverage).

## Foundational Learning
### Concept: Dual-Metric Evaluation (ROS/CSS)
- **Why needed here:** Separates format brittleness (ROS) from semantic capability (CSS), which is critical for diagnosing whether a model's failure is due to production pipeline constraints or actual lack of understanding.
- **Quick check question:** What does a large gap between a model's ROS and CSS scores tell you about its suitability for a strict production parser?

### Concept: Deterministic Output Canonicalization
- **Why needed here:** Provides a universal pre-processing layer that neutralizes model-specific formatting quirks, enabling fair comparison and reliable parsing without modifying base LLMs.
- **Quick check question:** Can a canonicalizer reliably fix a valid JSON object that has an extra trailing comma after the last element? If so, how?

### Concept: Verification-Driven Field-Level Selection
- **Why needed here:** When multiple model outputs are available (even from a single model with sampling), a verifier can select the most trustworthy value per field, improving over naive aggregation (e.g., majority vote) by considering query semantics.
- **Quick check question:** Why is it insufficient for the verifier to see only the candidate JSON output without the original query?

## Architecture Onboarding
### Component map
1. Canonicalizer -> 2. Verifier (DistilBERT) -> 3. Safe-Override Policy

### Critical path
Raw LLM output(s) -> Canonicalizer (per output) -> Verifier (scoring each canonicalized output) -> Safe-Override (aggregate per-field decision) -> Validated JSON.

### Design tradeoffs
- Black-box compatibility vs. overhead: Works with any LLM API but adds ~2ms per field (DistilBERT inference) and storage for cached outputs. Canonicalizer is near-zero cost.
- Conservative vs. aggressive overrides: Conservative policy (high `τ_keep`) maintains precision but increases abstain rate; aggressive policy increases coverage but risks errors. Thresholds are domain/dev-set dependent.
- Single-model vs. ensemble: The system can operate on a single model's output (for cost) or ensemble (for quality). Verifier training benefits from diverse model outputs but generalizes to held-out families.

### Failure signatures
- High abstain rate (>20%): May indicate out-of-domain queries, canonicalizer failures, or verifier miscalibration.
- Low override precision (<80%): Suggests verifier is overconfident on incorrect outputs or thresholds are too permissive.
- Significant ROS→CSS gap after canonicalization: Indicates semantic errors dominate; verifier should be primary improvement lever.
- Performance drop on held-out model families: Signals verifier overfitting to training model idiosyncrasies.

### First 3 experiments
1. **Baseline format collapse quantification:** Run cached outputs from target models through strict JSON parser to compute ROS. Then apply only the Canonicalizer and compute CSS. The difference isolates format-induced failures.
2. **Verifier input ablation:** Train three verifier variants: (a) output-only, (b) query-only, (c) query+output. Compare F1 on dev set to confirm both inputs are necessary for semantic selection.
3. **Held-out model generalization:** Train verifier on outputs from a subset of models (e.g., 4/6). Evaluate on all models, including the held-out families. Degradation should be minimal (<2% F1 drop) to confirm transferable signals.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How well does PromptPort generalize to diverse structured extraction domains beyond camera metadata?
- **Basis in paper:** [explicit] The authors state that their quantitative evaluation is limited to a single domain (camera metadata) and that "comprehensive multi-domain evaluation remains future work."
- **Why unresolved:** The paper only provides qualitative examples for other domains (product attributes, medical dosing, citations) without systematic metrics; it is unknown whether the observed performance gains and generalization to held-out models extend to other schemas and data distributions.
- **What evidence would resolve it:** Evaluate PromptPort on multiple standardized structured extraction benchmarks covering varied domains (e.g., e-commerce product specs, clinical information, bibliographic data) using the same ROS/CSS framework, comparing cross-model gaps and verifier effectiveness.

### Open Question 2
- **Question:** To what extent can the deterministic Canonicalizer be made robust against adversarial or highly unusual output formats?
- **Basis in paper:** [explicit] The authors acknowledge that "the deterministic Canonicalizer handles common format variations but cannot guarantee robustness to adversarial or highly unusual outputs."
- **Why unresolved:** The Canonicalizer relies on handcrafted heuristics (fence stripping, bracket matching, common repairs); its failure modes on edge-case or maliciously formatted outputs are not characterized, limiting trust in production settings with unpredictable LLM behavior.
- **What evidence would resolve it:** Conduct adversarial stress testing by generating outputs with extreme formatting (e.g., deeply nested fences, obfuscated JSON, mixed encodings, or syntax far from JSON) and measure canonicalization success rates; inform whether a learned canonicalizer or expanded rule set could maintain high ROS recovery.

### Open Question 3
- **Question:** How can we provide formal statistical guarantees for the verifier's abstention behavior to ensure reliability in safety-critical applications?
- **Basis in paper:** [explicit] The authors suggest that "integrating conformal prediction could provide formal coverage guarantees for abstention rates" and note current thresholds are tuned for F1 without such guarantees.
- **Why unresolved:** The safe-override policy uses fixed confidence thresholds optimized on a dev set; in high-stakes deployments, the probability that abstentions correctly avoid errors is not formally controlled, risking either over- or under-abstention.
- **What evidence would resolve it:** Replace the threshold-based abstention with a conformal prediction approach that outputs prediction sets with user-specified confidence (e.g., 95% coverage) and empirically verify coverage on held-out test data across domains and models.

### Open Question 4
- **Question:** Does PromptPort's reliability layer generalize to multilingual structured extraction scenarios?
- **Basis in paper:** [explicit] The authors state that "current evaluation is English-only. Extending to multilingual structured extraction is important future work."
- **Why unresolved:** All training and test data are English; multilingual extraction introduces challenges like script variations, language-specific formatting conventions, and multilingual model outputs, which could affect canonicalization rules and verifier performance.
- **What evidence would resolve it:** Build multilingual versions of the camera metadata benchmark (or other schemas) in languages with diverse scripts (e.g., Arabic, Chinese, Hindi) and evaluate ROS/CSS gaps and PromptPort’s effectiveness; test with both English-trained and multilingual LLMs.

## Limitations
- Dataset access: The 37k camera benchmark is announced but not publicly released, forcing potential recreations that may not match the original distribution.
- Implementation specifics: Exact canonicalizer rules and safe-override thresholds are omitted, requiring non-trivial reverse-engineering.
- Generalization boundary: The verifier’s robustness to truly out-of-domain schemas (e.g., non-metadata, multilingual) is unvalidated beyond held-out model families.

## Confidence
- **Canonicalization recovers format failures (+6–8 F1):** Medium. Evidence is strong within the paper but lacks independent replication.
- **Verifier enables cross-model semantic selection (+14–16 F1):** High. Supported by rigorous input ablations showing query+output necessity, though calibration on truly held-out families remains partially unproven.
- **Safe-override approaches oracle with abstention:** Medium. Diagnostic metrics (87.2% override precision) are promising, but threshold sensitivity and abstain-rate tradeoffs are not fully stress-tested.

## Next Checks
1. **Canonicalizer Edge-Case Stress Test**: Apply the implemented canonicalizer to 100 random ROS failure cases (e.g., nested prose, malformed arrays). Measure residual unparsable rate; target <2% to match reported ROS→CSS gap recovery.
2. **Verifier Hyperparameter Sensitivity**: Perform a controlled sweep over learning rates ({1e-5, 2e-5, 5e-5}) and epochs ({3, 5, 10}) on the dev split. Identify configurations that achieve ≥0.880 F1; report variance to assess specification criticality.
3. **Held-Out Family Generalization Replication**: Train the verifier on outputs from only 4 of the 6 families (e.g., exclude Gemma and Phi-3). Evaluate on all 6 families; expect <0.02 F1 drop on held-out families per paper claims. Significant degradation would indicate overfitting to training-model quirks.
