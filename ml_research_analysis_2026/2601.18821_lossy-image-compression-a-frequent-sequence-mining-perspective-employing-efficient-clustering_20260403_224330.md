# Lossy Image Compression -- A Frequent Sequence Mining perspective employing efficient Clustering
## Quick Facts
- arXiv ID: 2601.18821
- Source URL: https://arxiv.org/abs/2601.18821
- Reference count: 18
- Primary result: Achieves compression ratios up to 2.555, PSNR up to 50.26 dB, with average compression time of 2 seconds; quality comparable to JPEG at similar bitrates and superior to GIF.

## Executive Summary
This paper proposes a lossy image compression method that replaces the discrete cosine transform (DCT) in JPEG with a pipeline based on parallel k-means clustering and closed frequent sequence mining. The image is divided into blocks, each locally clustered to assign pixel symbols; these symbolic matrices are then mined for maximal repetitive sequences using a modified GSP algorithm, and the sequences are entropy-coded via Huffman. Results on standard 512×512 images show competitive quality versus JPEG at comparable compressed sizes and consistent gains over GIF, though performance degrades on highly textured images like Baboon. The authors highlight efficiency via parallelism and suggest future work on alternative clustering and neighbourhood-aware mining.

## Method Summary
The compression pipeline processes each RGB component separately. First, the component is split into non-overlapping blocks; k-means clustering runs in parallel on every block, replacing each pixel with its cluster identifier (0 to k–1). The block-wise identifier maps are concatenated into a full symbolic matrix I'. This matrix is treated as a sequence database: a refined GSP algorithm mines closed frequent sequences (CFS) with a minimum support ψ, followed by a "support modification" step that reallocates overlapping occurrences to the longest matching patterns, producing a reduced modified support set S'. Huffman coding builds a prefix code from S', and the final compressed stream consists of the encoded sequences, block centroid tables, and the Huffman code table. Decompression reverses these steps.

## Key Results
- Compression ratios up to 2.555, PSNR up to 50.26 dB.
- On Lena at ~224 kB: PSNR 39.49 dB vs JPEG 41.82 dB, SSIM 0.978 vs 0.992.
- Outperforms GIF in both compression ratio and quality metrics (PSNR/SSIM).

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Parallel k-means clustering on local image blocks replaces raw pixel values with cluster identifiers, reducing data entropy and enabling efficient pattern mining.
- **Mechanism:** The image is split into b×b blocks. For each color component, k-means runs in parallel on all blocks, assigning each pixel a cluster ID based on nearest centroid. The block-wise means (centroids) are stored in identifier tables. This transforms local pixel variations into discrete symbols, creating a symbolic matrix (I') where spatial redundancy is condensed into repeated identifiers.
- **Core assumption:** Within small blocks, pixel intensities form tight clusters such that representing all members by a centroid ID yields acceptable perceptual loss. The parallelism amortizes clustering cost across blocks.
- **Evidence anchors:** [abstract] "clustering pixels and using the cluster identifiers in the compression... applying k-means clustering in parallel to all blocks"; [section III.A.2] details parallel clustering, replacement with IDs, and merging blocks into I'.
- **Break condition:** If k is too low, distinct pixel intensities are over-merged, causing blocking artifacts. If k is too high, identifier diversity increases, reducing pattern frequency and hurting compression.

### Mechanism 2
**Claim:** Closed frequent sequence mining (CFSM) on the symbolic matrix extracts maximal, non-redundant sequential patterns, minimizing codebook size while preserving representational coverage.
- **Mechanism:** The symbolic matrix (I') is treated as a sequence database where each row is a sequence. A modified GSP algorithm mines closed frequent sequences (CFS)—patterns whose no super-pattern has equal support. An additional "support modification" step sorts patterns by length descending and subtracts overlapping occurrences, prioritizing longer patterns. This yields a reduced, modified support set (S') for Huffman coding.
- **Core assumption:** Closed sequences capture all maximal repetitive patterns without inclusion of sub-patterns that would bloat the code table. Support modification correctly allocates occurrence counts to the longest matching patterns, preventing codebook inflation from overlapping subsequences.
- **Evidence anchors:** [abstract] "refined GSP algorithm with pruning for closed frequent sequence mining... achieving a good reduction in the code table size"; [section III.A.3] explains closed sequence definition, GSP modification with pruning, and the support modification procedure with example in Table III.
- **Break condition:** If minimum support ψ is too low, CFS set grows large, increasing code table overhead. If ψ is too high, few patterns survive, forcing many pixels to be encoded as raw IDs.

### Mechanism 3
**Claim:** Huffman coding on the modified support set (S') produces a near-optimal prefix code for the frequent sequences, achieving entropy-limited compression of the symbolic matrix.
- **Mechanism:** Sequences in S' (with modified supports) are sorted by length. Huffman builds a binary code tree where more frequent sequences get shorter codes. Each occurrence of a sequence in I' is replaced by its Huffman code, producing the compressed bitstream CI.
- **Core assumption:** The statistical distribution of modified supports accurately reflects the optimal bit allocation for the patterns. The code table overhead is amortized by the length of encoded sequences.
- **Evidence anchors:** [abstract] "followed by Huffman coding"; [section III.A.4] describes Huffman coding on S' and replacement of sequences in I'.
- **Break condition:** If code table size exceeds savings from encoding frequent sequences, compression ratio degrades. This is mitigated by the CFSM reduction.

## Foundational Learning
- **k-means clustering**  
  **Why needed:** The entire pipeline starts by converting pixel intensities into discrete symbols. Understanding k-means' iterative assignment and centroid update is key to predicting how k and block size b affect both compression speed (via parallelism) and quality (via quantization error).  
  **Quick check:** If you double k while keeping block size constant, what happens to (a) the number of unique cluster IDs per block, (b) the average intra-block variance, and (c) the expected size of the block identifier tables?
- **Closed Frequent Sequence Mining (CFSM)**  
  **Why needed:** This is the core novelty versus JPEG. You must distinguish between all frequent sequences and closed ones, and understand why closedness reduces codebook size. Also, grasp the "support modification" step, critical to the authors' claimed code table reduction.  
  **Quick check:** Given a sequence database where pattern A appears 5 times, AB appears 5 times, and ABC appears 3 times with ψ=3, list the initial CFS set. After applying the described support modification (processing longest first), what is the modified support of A?
- **Huffman Coding**  
  **Why needed:** The final entropy coding stage. You need to know that Huffman is optimal for symbol-by-symbol coding given known probabilities, and that codebook storage overhead must be factored into net compression.  
  **Quick check:** If Huffman coding yields a codebook where the most frequent sequence gets a 2-bit code and the least frequent gets a 6-bit code, what can you infer about the ratio of their probabilities?

## Architecture Onboarding
- **Component map:** Input Parser -> Parallel Block Clustering -> Symbolic Matrix Merger -> CFSM Engine -> Huffman Encoder -> Packager.
- **Critical path:** The sequential dependency is: Clustering → Merger → CFSM → Huffman. Parallelism is only within the per-block clustering step. CFSM on each component can also be parallelized across components.
- **Design tradeoffs:**
  - Block size b: Larger b means fewer blocks, less overhead from centroid tables, but worse local clustering (more mixed pixels) → lower PSNR. Smaller b increases table overhead but may improve local symbol homogeneity.
  - Cluster count k: Higher k yields finer quantization (better PSNR) but more unique IDs → fewer long frequent sequences → lower compression ratio. Also increases clustering time.
  - Support ψ: Controls CFS set size. Higher ψ yields smaller code table but less frequent patterns go uncoded (worse compression). The sweet spot (ψ ∈ [40%,70%] per paper) balances table size vs. pattern coverage.
- **Failure signatures:**
  - Quality collapse: PSNR drops sharply when k is too small (e.g., <8) for complex images like Baboon.
  - Poor compression ratio: If ψ is too low, code table swells; if b is too small, centroid table overhead dominates. Check final compressed size components.
  - Slow runtime: Lack of parallelism in clustering or having too many blocks (b small) with high k will increase time. Monitor CPU usage; should utilize all cores during clustering.
- **First 3 experiments:**
  1. Parameter sweep on Lena: Fix b=128, vary k from 4 to 32, plot PSNR and compression ratio. Expected: PSNR increases with k, but ratio peaks then falls.
  2. Support threshold impact: Fix b=256, k=12, sweep ψ from 30% to 90%. Expected: Ratio peaks in 40-70% range as per Figure 1.
  3. Comparison baseline: Compress Lena at ~224 kB with both proposed (use b=256,k=12,ψ=70) and JPEG (quality factor ~50). Compare PSNR/SSIM and visual inspection for blocking vs. smoothing artifacts.

## Open Questions the Paper Calls Out
1. Which alternative clustering algorithms (e.g., DBSCAN, hierarchical, Gaussian Mixture Models) can improve visual quality (PSNR/SSIM) in the proposed compression framework while maintaining comparable compression ratio and time?  
   *Basis:* Conclusion states: "As a part of future work, other efficient clustering algorithms can be tried in place of k-means to improve the visual quality of the image."  
   *Why unresolved:* Only k-means is evaluated; no other algorithms tested.  
   *Resolving evidence:* Comparative experiments using different clustering algorithms on standard images, measuring quality, compression ratio, and time.
2. How can spatial neighbourhood properties be incorporated into the closed frequent sequence mining step to boost compression ratio without significant quality loss?  
   *Basis:* Conclusion notes: "Neighbourhood properties of the image can be exploited to improve the compression ratio."  
   *Why unresolved:* Current mining treats blocks independently, ignoring spatial continuity; not explored.  
   *Resolving evidence:* Design of a neighbourhood-aware sequence mining extension and validation showing improved compression ratios at similar quality.
3. How does the algorithm scale in performance (ratio, quality, time) on high-resolution and diverse images, and what are optimal parameter settings (b, k, ψ) for large images?  
   *Basis:* Conclusion says: "We aim to conduct extensive simulations on standard datasets with large size to investigate several other parameters including the compression time."  
   *Why unresolved:* Results only on 512×512 images; scaling behavior not studied.  
   *Resolving evidence:* Extensive tests on various large images, analyzing parameter effects and providing scaling guidelines.
4. What is the impact of the modified support calculation on code table size and compression ratio, and could alternative pruning strategies perform better?  
   *Basis:* Inferred: Paper introduces modified support to reduce sequence cardinality but does not compare with original support or other pruning methods.  
   *Why unresolved:* Trade-offs of modified vs. original support are not quantified; optimality unclear.  
   *Resolving evidence:* Ablation study comparing original and modified support under identical Huffman coding, measuring code table size and final compressed size.
5. How does the proposed method compare in rate-distortion performance with modern codecs like JPEG2000 and WebP?  
   *Basis:* Inferred: Paper compares only with JPEG and GIF, omitting newer standards.  
   *Why unresolved:* Practical competitiveness against state-of-the-art unknown.  
   *Resolving evidence:* Implement proposed method and standard codecs (e.g., OpenJPEG, libwebp) on common test images; compare rate-distortion curves and visual quality.

## Limitations
- **Implementation details ambiguous:** Exact k-means parameters (initialization, iterations, tolerance) and precise mapping of ψ from percentage to absolute count are unspecified.
- **Generalizability narrow:** Performance degrades on high-texture images (e.g., Baboon); evaluation limited to a few standard 512×512 images.
- **Comparisons outdated:** Only JPEG and GIF are benchmarked; modern codecs (WebP, HEIC) are absent, limiting assessment of practical competitiveness.
- **Scalability unverified:** Runtime claim of ~2 seconds depends on unstated hardware and parallelism; behavior on large images not studied.

## Confidence
- **Cluster 1 (Parallel k-means reduces entropy):** Medium – supported by methodology and parallel computing principles, but lacks quantitative ablation on block size vs. speed/quality.
- **Cluster 2 (Closed frequent sequence mining with support modification yields compact codebook):** Medium – algorithm description is clear, yet no external validation; neighbor papers do not confirm the specific "support modification".
- **Cluster 3 (Overall performance comparable to JPEG, superior to GIF):** Low‑Medium – results for one image are reported, but unknown parameter sensitivity and small test set prevent strong confidence.
- **Cluster 4 (Efficiency – 2 s average compression time):** Low – depends on unstated hardware, parallel implementation quality, and image size.
