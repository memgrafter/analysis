# Fed-GAME: Personalized Federated Learning with Graph Attention Mixture-of-Experts For Time-Series Forecasting

## Quick Facts
- **arXiv ID:** 2603.01363
- **Source URL:** https://arxiv.org/abs/2603.01363
- **Reference count:** 0
- **Primary result:** On the Shenzhen EV charging dataset (200 stations), Fed-GAME improves Quantile Score by 54.23% and Interval Coverage Percentage by 43.87% over non-federated local training for 6-step forecasts, with negligible (~0.1-0.2%) communication overhead.

## Executive Summary
Fed-GAME is a personalized federated learning framework for time-series forecasting that addresses client heterogeneity by decoupling model updates into a globally averaged component and a client-specific selective component. The selective updates are aggregated via a novel Graph Attention Mixture-of-Experts (GAME) module, which constructs a dynamic, client-specific implicit graph using shared scoring experts and personalized gating. This enables fine-grained personalization without relying on static client topologies. Evaluated on two real-world electric vehicle charging datasets (Palo Alto, Shenzhen), Fed-GAME achieves state-of-the-art performance, significantly outperforming existing personalized federated learning and federated graph learning baselines in quantile forecasting metrics while maintaining minimal communication costs.

## Method Summary
Clients maintain a private model \( M_A \) and a shared global model \( M_B \). After local fine-tuning (with a proximal term), each client uploads the parameter difference \( \Delta = M_A - M_B \) to the server. The server splits \( \Delta \): (1) the average of all \( \Delta \) updates \( M_B \) for global consensus, and (2) the selective difference \( \Delta_u \) (only the final MLP layers) is processed by the GAME aggregator. GAME embeds \( \Delta_u \), then for each client, a personalized noisy Top-k gate weights outputs from \( M \) shared scoring experts to compute attention weights \( w_{ij} \) over other clients. The server computes a personalized update \( \Delta_{\text{pers}, i} = w_{\text{self}} \cdot \Delta_{u,i} + (1-w_{\text{self}}) \sum_{j \neq i} w_{ij} \Delta_{u,j} \), which is sent back to client \( i \). The GAME module (encoder and gates) is trained server-side via a meta-loss \( \mathcal{L}_{\text{meta}} \) that aligns \( \Delta_{\text{pers}} \) with the client's raw \( \Delta_u \). Clients then apply \( \Delta_{\text{pers}} \) and perform another local fine-tuning step.

## Key Results
- On the Shenzhen dataset (200 stations), Fed-GAME reduces Quantile Score (QS) by 54.23% and improves Interval Coverage Percentage (ICP) by 43.87% compared to non-federated local training for 6-step forecasts.
- It consistently outperforms PFL (FedProx, pFedMe) and FGL (PAG-FedAvg, GCRN-FedAvg) baselines in QS and ICP.
- Communication overhead is extremely low (~0.1-0.2% of full model size) because only small, selective parameter differences are transmitted.

## Why This Works (Mechanism)
### Mechanism 1: Decoupled Updates for Consensus and Personalization
- **Claim:** Splitting parameter updates into a globally averaged component and a client-specific selective component enables robust consensus while allowing fine-grained personalization.
- **Mechanism:** Clients upload \( \Delta = M_A - M_B \). The server: (1) averages all \( \Delta \) to update \( M_B \) for global consensus, (2) uses only the selective \( \Delta_u \) (final MLP layers) in the GAME aggregator to compute a personalized update \( \Delta_{\text{pers}} \) for each client.
- **Core assumption:** Final layers capture higher-level, task-specific representations suitable for selective sharing, while earlier layers contain more general or client-specific features.
- **Evidence anchors:** [abstract] "decomposed into two streams: (1) averaged difference... (2) the selective difference fed into a novel Graph Attention Mixture-of-Experts (GAME) aggregator"; [section 2.2] "we restrict to select the final MLP layers, as they are widely recognized to capture high-level transferable features".

### Mechanism 2: GAME as a Dynamic Implicit Graph Learner
- **Claim:** The GAME aggregator learns a dynamic, client-specific implicit graph via a Mixture-of-Experts (MoE) paradigm, replacing static topologies with data-driven, personalized attention weights.
- **Mechanism:** Selective updates are embedded and processed by \( M \) shared scoring experts. Each client has a personalized noisy Top-k gate that combines expert scores into a single relevance value per neighbor. A temperature-scaled softmax converts these into personalized attention weights \( w_{ij} \) for message passing.
- **Core assumption:** Inter-client relationships for personalization are multi-faceted and client-dependent; a single attention function is insufficient, but a shared set of experts evaluated by personalized routers can capture this diversity.
- **Evidence anchors:** [abstract] "models personalized aggregation as message passing over a learnable dynamic implicit graph"; [section 2.3] "shared scoring experts... personalized gates adaptively weight expert outputs for each client... Fed-GAME eliminates reliance on static topology"; [section 3.2] GAME outperforms GAT and GraphSAGE ablations.

### Mechanism 3: Meta-Loss for Update Fidelity
- **Claim:** A server-side, similarity-based meta-loss \( \mathcal{L}_{\text{meta}} \) trains the GAME aggregator without direct client data access, aligning personalized updates with each client's own raw parameter difference to preserve local intent.
- **Mechanism:** \( \mathcal{L}_{\text{meta}} \) combines L2 distance and cosine dissimilarity between the server-generated \( \Delta_{\text{pers}} \) and the client's selective raw difference \( \Delta_u \). This encourages the aggregator to produce client-specific updates that remain semantically close to the client's own model adjustment.
- **Core assumption:** A client's raw \( \Delta_u \) is a valid proxy for its "true" desired update direction, and minimizing divergence from it improves personalization fidelity.
- **Evidence anchors:** [section 2.4] "meta-loss... encourages the MoE to generate personalized updates that align with clients’ own raw parameter difference"; [section 3.1] Fed-GAME achieves best QS/ICP, implying effective personalization, though not a direct ablation of \( \mathcal{L}_{\text{meta}} \).

## Architecture Onboarding
- **Component map:** Client private model (MA) -> Local fine-tuning (FedProx) -> Parameter difference (Δ) upload -> Server: Δ split -> (1) Global model (MB) update via mean(Δ); (2) Selective Δ_u extraction -> Encoder -> GAME aggregator (M shared experts + N personalized gates) -> Personalized Δ_pers -> Client update (MA ← MA + Δ_pers) -> Second local fine-tuning.
- **Critical path:** 1. Client uploads Δ_i = MA_i - MB. 2. Server updates MB ← MB + η·mean(Δ). 3. Server extracts Δ_u,i (final layer), encodes to e_i. 4. GAME: personalized gate G_i uses e_i to weight M expert scores s_ijk from all j≠i, producing w_ij. 5. Server computes Δ_pers,i = w_self·Δ_u,i + (1-w_self)∑_{j≠i} w_ij Δ_u,j. 6. Server sends Δ_pers,i to client i. 7. Client updates MA ← MA + lr·Δ_pers,i; performs second FedProx fine-tuning.
- **Design tradeoffs:** Selective layer choice (final MLP only minimizes communication but assumes personalization is encoded there); GAME sparsity (Top-k=k balances efficiency vs. relationship complexity); w_self balance (high w_self relies on local data, low w_self crowdsources more).
- **Failure signatures:** Diverging local models (MA far from MB); uniform attention (w_ij → 1/(N-1), indicating aggregator failure); meta-loss stagnation (L_meta not decreasing); communication bottleneck (r too small, selective Δ_u lacks information).
- **First 3 experiments:** 1. Ablate GAME: replace with FedAvg, FedProx, GraphSAGE, GAT on same selective updates; measure QS/ICP degradation. 2. Layer selection analysis: vary included layers (last1, last2, all); expect performance peak at shallow depth with lowest communication. 3. Attention weight analysis: visualize w_ij matrices; expect evolution from uniform to structured patterns; correlate with client metadata (e.g., location) to test semantic alignment.

## Open Questions the Paper Calls Out
1. **Adaptive parameter selection:** How to develop adaptive strategies for selecting which parameters to include in the selective update, beyond fixing the final MLP layers? The current static choice may limit personalization or efficiency.
2. **Interpretability of learned graphs:** What do the learned attention weights reveal about client relationships? Can they be aligned with exogenous factors (geographic proximity, temporal similarity) to improve interpretability and guide design?
3. **Scalability to large client populations:** How does Fed-GAME scale computationally and in communication when the number of clients becomes very large (e.g., thousands)? The server-side attention is O(N²), which may be prohibitive.
4. **Sensitivity and auto-tuning of MoE components:** How sensitive is performance to MoE configuration (number of experts, Top-k) and meta-loss weighting (α, β)? Can these be automatically tuned for robustness across contexts?

## Limitations
- Unreported hyperparameters (η, meta-optimizer details, temperature T, embedding dimension, noise variance) block exact reproduction.
- The assumption that only final MLP layers carry personalization is untested; earlier layers may contain complementary signals.
- Evaluation is limited to two EV charging datasets, so generalizability to other time-series domains is unknown.
- No direct ablation of the meta-loss \( \mathcal{L}_{\text{meta}} \), leaving its contribution uncertain.
