# STRUCTUREDAGENT: Planning with AND/OR Trees for Long-Horizon Web Tasks

## Quick Facts
*   **arXiv ID:** 2603.05294
*   **Source URL:** https://arxiv.org/abs/2603.05294
*   **Reference count:** 40
*   **Primary result:** A hierarchical planning framework using dynamic AND/OR trees and structured memory significantly improves success rates on long-horizon web tasks, achieving 83.3% on Amazon Easy and 46.7% on Amazon Hard with Claude 3.7 Sonnet.

## Executive Summary
Existing LLM-based web agents struggle with long-horizon tasks due to limited planning and memory. STRUCTUREDAGENT introduces a hierarchical planning framework that dynamically constructs and traverses AND/OR trees, interleaving planning with execution. This approach enables robust error recovery, alternative strategy exploration, and prevents redundant work. A structured memory module tracks candidate entities and satisfied constraints for information-seeking tasks. Evaluated on WebVoyager, WebArena, and custom Amazon shopping benchmarks, STRUCTUREDAGENT consistently outperforms strong baselines like AgentOccam and produces interpretable plans.

## Method Summary
STRUCTUREDAGENT addresses complex web tasks by decomposing them into a dynamic AND/OR tree. AND nodes represent conjunctive subgoals (all children must succeed), OR nodes represent alternative strategies (any child can succeed), and ACTION nodes are executable browser actions. Traversal uses a modified depth-first search with three states (ENTERING, EXITING, FAILED) per node, allowing failure recovery, local repair, and plan revision without restarting. For tasks with multiple candidate items, a structured memory module maintains a table of candidates and their satisfied constraints to guide decision-making. The LLM is invoked only for specific, localized operations: node expansion, repair, completion checks, summarization, and global tree updates.

## Key Results
*   With Claude 3.5 Sonnet, achieves 83.3% (Amazon Easy) and 35.6% (Amazon Hard); with Claude 3.7 Sonnet, reaches 46.7% on Amazon Hard.
*   On WebArena, achieves a 52.6% overall success rate, with peaks in Shopping (72.6%) and Reddit (45.8%).
*   Structured memory improves performance on hard information-seeking tasks (+5% on Amazon Hard) but introduces overhead on simpler tasks.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** Hierarchical AND/OR trees decompose complex tasks while preserving alternative strategies.
*   **Mechanism:** The framework builds a dynamic tree where AND nodes require all subgoals, OR nodes offer alternatives, and atomic nodes are actions. The LLM handles only localized operations (expansion, repair). Traversal interleaves planning and execution via a modified DFS.
*   **Core assumption:** Complex web tasks have compositional structure and multiple viable strategies for subproblems.
*   **Evidence anchors:**
    *   [abstract] "online hierarchical planner that uses dynamic AND/OR trees"
    *   [section 3.1] Definitions of AND, OR, and ACTION node types.
*   **Break condition:** Poor initial decomposition leads to repeated repairs and eventual failure if the revision budget is exhausted.

### Mechanism 2
*   **Claim:** Structured memory reduces redundant exploration by tracking candidate entities and constraints.
*   **Mechanism:** A dynamic table stores candidate items (rows) with attribute columns. Constraints are extracted from the task description and updated during browsing. The planner retrieves top-K candidates satisfying most constraints to guide navigation.
*   **Core assumption:** Long-horizon information-seeking tasks require evaluating multiple candidates against several constraints; agents without structured tracking forget earlier discoveries.
*   **Evidence anchors:**
    *   [section 3.4] Description of the Structured Memory module for tracking candidates and constraints.
    *   [section 4.1] StructuredAgentMem improves Amazon Hard performance by 5%.
*   **Break condition:** Overhead hurts performance on simpler tasks where constraint tracking is unnecessary.

### Mechanism 3
*   **Claim:** Modified DFS with ENTERING/EXITING/FAILED states enables robust error recovery and dynamic plan revision.
*   **Mechanism:** Nodes can be revisited. On failure, the agent attempts node repair (add/modify children) within a revision limit; if repair fails, the node is pruned and failure propagates upward, triggering re-evaluation of ancestors. This isolates failures and explores alternatives without restarting.
*   **Core assumption:** Web environments are stochastic; failures must be locally contained and recovered from.
*   **Evidence anchors:**
    *   [section 3.2] Introduction of three execution states for DFS stack nodes.
    *   [section 3.3] Recovery process upon encountering a FAILED state, including repair and pruning.
*   **Break condition:** Excessive repair attempts on unsolvable subgoals waste time and may exceed the revision budget.

## Foundational Learning
*   **Concept:** Partially Observable Markov Decision Processes (POMDPs)
    *   **Why needed:** Models web-agent interaction where observations (HTML, history) are partial and actions lead to stochastic state transitions. Clarifies the need for robust planning under uncertainty.
    *   **Quick check:** Which aspects of web browsing make the environment partially observable, and how does the agent's lack of full browser state influence its design?
*   **Concept:** Hierarchical Task Network (HTN) Planning
    *   **Why needed:** AND/OR trees are a form of HTN. Decomposing tasks, ordering subgoals, and reasoning about alternatives are core HTN concepts.
    *   **Quick check:** What is the semantic difference between an AND node and an OR node, and how do they map to classical HTN planning?
*   **Concept:** Depth-First Search (DFS) with Stack-Based Backtracking
    *   **Why needed:** The planning algorithm is a modified greedy DFS. Understanding standard DFS (stack, visit states) is prerequisite to grasp the three-state modification and node reprocessing.
    *   **Quick check:** How does the introduction of a FAILED state and multiple revisits change computational complexity compared to standard DFS on a fixed tree?

## Architecture Onboarding
*   **Component map:** Task & Constraints -> ObservationSummarizer -> AND/OR Tree Planner <-> Node Operations (Expansion, Repair, Completion, Global Update) <-> Environment Wrapper -> Browser. Structured Memory interacts with Planner and Node Operations. LLM serves as controller for all operators.
*   **Critical path:** Root node (ENTERING) -> NodeExpansion (LLM) -> push children (AND/OR logic) -> process child nodes recursively -> reach ACTION node -> execute in browser -> ObservationSummarizer updates context -> GlobalTreeUpdate (LLM) may prune -> parent node EXITING -> NodeCompletionCheck (LLM) -> if failure, NodeRepair (LLM) or prune -> propagate status upward; loop until root SUCCESS/FAIL.
*   **Design tradeoffs:**
    1.  Tree depth vs. breadth: Greedy DFS limits exploration but risks missing viable paths.
    2.  Revision budget: More repairs increase robustness but also computational cost.
    3.  Structured memory overhead: beneficial for multi-candidate tasks but adds noise for simple ones.
    4.  Atomic action granularity: finer actions increase flexibility but raise planning complexity.
*   **Failure signatures:**
    1.  Node status repeatedly toggling between FAILED and ENTERING indicates struggling decomposition.
    2.  High counts of prune/repair operations in logs.
    3.  Trajectory lengths much longer than baselines on hard tasks.
    4.  Disagreement between automated judges and humans on complex constraints.
*   **First 3 experiments:**
    1.  Amazon shopping benchmarks: Compare success rates against AgentOccam, BasicClaudeAction, SteP on Easy/Hard tasks with Claude 3.5/3.7; evaluate StructuredMemory impact.
    2.  WebArena evaluation: Test across Map, Shopping, Reddit, GitLab categories; compare overall success rate and action distribution.
    3.  Model generalization: Use Kimi-K2 as backbone on WebArena subset to show framework benefits extend beyond Claude.

## Open Questions the Paper Calls Out
*   **Question 1:** How can we design effective admissible heuristics to guide hierarchical AND/OR tree planning for web agents?
    *   **Basis:** "designing effective admissible heuristics for these domains remains an open challenge."
*   **Question 2:** Can fine-tuning LLM-based web agents with dense reward signals improve generalization and sample efficiency?
    *   **Basis:** "fine-tuning capable and generalizable web agents using high-quality trajectories paired with dense reward signals remains a largely underexplored direction."
*   **Question 3:** Under what task and model conditions does the Structured Memory module yield performance gains versus overhead?
    *   **Basis:** Inferred from contradictory results (improves on Amazon Hard, degrades on Amazon Easy, no gain with Claude 3.7).
*   **Question 4:** Can we automate the detection and repair of erroneous subgoal decompositions in AND/OR trees without human intervention?
    *   **Basis:** Inferred from reliance on manual intervention for decomposition correction (Figure 13).

## Limitations
*   Key hyperparameters (MAX_REVISION_COUNT, MAX_RETRY_COUNT, BUDGET, OR scoring range) are undisclosed, hindering exact replication.
*   Baseline implementation details are missing, weakening comparative claims; evaluation judge choices are unspecified.
*   Structured Memory degrades performance on simpler tasks, indicating limited generality of the memory mechanism.

## Confidence
*   **Hierarchical AND/OR planning and dynamic DFS recovery:** Medium. Mechanism is clearly described, but evidence for core assumptions (e.g., prevalence of alternative strategies) is indirect.
*   **Structured memory for constraint tracking:** Medium. Benefits on hard tasks are offset by overhead on easy ones; scalability and precise impact thresholds are unclear.
*   **Overall superiority over baselines:** Medium-High. Results across multiple benchmarks are strong, but reproducibility concerns persist due to missing hyperparameters and baseline specifications.
