# Mirage2Matter: A Physically Grounded Gaussian World Model from Video

## Quick Facts
- **arXiv ID:** 2602.00096  
- **Source:** https://arxiv.org/abs/2602.00096  
- **Reference count:** 15  
- **Primary result:** VLA models trained on simulated data achieve zero-shot real-robot grasping success of 80.0% (banana) and 86.7% (croissant), surpassing prior methods.

## Executive Summary
Mirage2Matter tackles data scarcity for embodied AI by generating high-fidelity simulation environments directly from handheld multi-view videos, without requiring expensive sensors. The pipeline combines 3D Gaussian Splatting for photorealistic scene and object reconstruction, generative models for creating collision-ready meshes, and a calibration procedure that aligns the reconstruction to real-world scale. This unified simulation supports training Vision-Language-Action (VLA) models that transfer zero-shot to real robots, demonstrating strong performance on grasping, button pressing, and push/pull tasks. The approach narrows the sim-to-real gap and outperforms existing simulation-based baselines.

## Method Summary
Given handheld videos of a workspace containing a calibration board of known size and target objects, the pipeline first runs COLMAP to obtain sparse structure and camera poses. Separate 3D Gaussian Splatting models are trained for the background scene and each object (segmented via SAM2 with text prompts). Watertight meshes for objects are produced using Tripo3D from single-view images. A scaled ICP alignment between the SfM points of the calibration board and a point cloud from the Genesis simulator computes a similarity transform (scale, rotation, translation) that maps the entire reconstruction into the simulator’s metric space. Object 3DGS are then aligned to their meshes via a similarity transform. The robot’s head camera is calibrated to the manipulator base using a ChArUco board. The aligned 3DGS background and object gaussians are placed in the simulator, collision meshes are attached, and motion planning (IK+RRT) generates trajectories. Hybrid training videos are created by compositing Genesis-rendered robot foreground onto 3DGS background renders. Finally, a VLA model (PoSA-VLA) is trained on these videos and deployed zero-shot to the real robot.

## Key Results
- **Grasping:** 80.0% (banana) and 86.7% (croissant) success, outperforming DISCOVERSE (60.0%, 66.7%) and RoboSimGS (76.7%, 76.7%).
- **Press & Push/Pull:** Press button 93.3% vs real 96.7%; push/pull 73.3% vs real 83.3%.
- **Ablation:** Using 3DGS objects improves average grasp success to 83.4% from 78.4%, and performance scales with more demonstrations.

## Why This Works (Mechanism)
The method succeeds because it jointly addresses visual fidelity, geometric accuracy, and physical grounding. 3D Gaussian Splatting captures fine details and supports differentiable rendering, minimizing the visual domain gap. The calibration board provides a real-world scale anchor, and scaled ICP ensures the reconstructed scene aligns with simulator metrics. Separate generative meshes yield collision-ready geometry while preserving the high-quality appearance of gaussians. The hybrid video composition blends the reconstructed scene with synthetic robot motion, creating training data that closely matches real conditions. This integrated design enables zero-shot transfer with only a modest sim-to-real performance drop.

## Architecture Onboarding
**Component Map:**  
Input Video -> COLMAP -> Camera poses & SfM points  
Video + SAM2 masks -> 3DGS Scene/Objects -> Gaussian parameters  
Single-view images -> Tripo3D -> Object meshes  
Calibration board (SfM) + Genesis base point cloud -> Scaled ICP -> Similarity transform (scale, R, t)  
Apply transform -> SfM points & 3DGS parameters aligned to simulator  
Robot camera + ChArUco -> Camera extrinsics calibration  
Aligned 3DGS + Object meshes + Robot model -> Genesis simulation -> Motion planning (IK+RRT) -> Trajectories  
Genesis robot render + 3DGS background render -> Composite video -> PoSA-VLA training -> Trained policy -> Real robot deployment

**Critical Path:**  
1. Capture video with calibration board → 2. Run COLMAP → 3. Train 3DGS → 4. Segment objects and generate meshes → 5. Perform scaled ICP alignment → 6. Calibrate robot camera → 7. Assemble simulation → 8. Generate demonstration videos → 9. Train VLA → 10. Deploy zero-shot.

**Design Tradeoffs:**  
- Visual fidelity vs physics: 3DGS gives realism but no collision; separate mesh provides physics at cost of slight visual mismatch.  
- Alignment simplicity vs robustness: Using a planar board is straightforward but assumes correct placement and clear visibility; errors propagate to scale.  
- Generative mesh accuracy: Tripo3D yields watertight meshes but may deviate from true object geometry; ICP alignment between gaussians and mesh is an approximation.

**Failure Signatures:**  
- High novel view reconstruction error or photometric loss in 3DGS indicates poor scene capture (e.g., insufficient parallax).  
- Large ICP RMSE after alignment suggests board detection failure or sparse SfM points in the board region.  
- Visible offset between object gaussians and their meshes in simulation leads to unrealistic interactions.  
- SAM2 segmentation errors produce incorrect object gaussians and faulty meshes.

**First Three Experiments:**  
1. **Calibration robustness:** Vary board size (e.g., A4 vs A3) and placement (center vs corner) to measure scale error and subsequent task success.  
2. **Visual representation ablation:** Replace 3DGS objects with mesh-only rendering in hybrid videos and compare success rates across tasks.  
3. **Demonstration scaling:** Train policies on increasing numbers of simulated demonstrations (e.g., 10, 50, 100) and evaluate real-robot performance to confirm scaling trends.

## Limitations
- **Calibration details:** Board dimensions, pattern, and detection method are unspecified, limiting reproducibility of scale alignment.  
- **Training hyperparameters:** Exact settings for 3DGS and VLA training (e.g., learning rates, iterations) are omitted, making full replication difficult.  
- **Segmentation reliability:** Dependence on SAM2 prompts may fail for objects with ambiguous appearance, causing mesh generation errors.
