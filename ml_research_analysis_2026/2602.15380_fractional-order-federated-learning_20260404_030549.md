# Fractional-Order Federated Learning
## Quick Facts
- **arXiv ID**: 2602.15380
- **Source URL**: https://arxiv.org/abs/2602.15380
- **Reference count**: 40
- **Primary result**: FOFedAvg matches or outperforms ten baselines in test accuracy and convergence speed, reducing communication by up to 10% and reaching target accuracy in fewer rounds under non‑IID data.

## Executive Summary
Federated learning (FL) struggles with slow convergence and instability when client data is non‑IID, due to client drift. This paper introduces Fractional‑Order Federated Averaging (FOFedAvg), which integrates Fractional‑Order SGD (FOSGD) based on Caputo derivatives into the FedAvg framework. The fractional‑order update creates a memory‑aware mechanism that weights historical gradients, smoothing the optimization trajectory and mitigating drift. Evaluated on nine datasets with varying non‑IID partitions, FOFedAvg matches or exceeds ten baseline methods (including FedAvg, SCAFFOLD, MOON) in test accuracy and convergence speed. On MNIST with severe non‑IID data, it reaches 60% accuracy in 4–60 communication rounds versus 9–215 for baselines, and reduces total communication cost by up to 10% compared to FedAvg. Theoretical analysis confirms convergence to a stationary point under standard smoothness assumptions.

## Method Summary
FOFedAvg modifies the client‑side update in FedAvg by replacing local SGD with Fractional‑Order SGD (FOSGD). For a client’s local step index *t*≥1, the update is:
`Θ ← Θ − (µ_t / Γ(2−α)) * (‖Θ_t − Θ_{t−1}‖ + δ)^{1−α} * ∇ℓ(Θ; batch)`,
where `µ_t = µ_0/√(t+1)`, α∈(0,1] is the fractional order, δ>0 is a small constant, and Γ is the gamma function. For *t*=0 (the first local step after receiving the global model), standard SGD is used. Each client retains its own previous local model (Θ_{t−1}) across rounds. After *E* local epochs, the server aggregates client updates via weighted averaging based on client dataset sizes. This memory effect stabilizes optimization under non‑IID data.

## Key Results
- On MNIST with severe non‑IID (Dirichlet α=0.1), FOFedAvg reaches 60% accuracy in 4–60 communication rounds, while baselines require 9–215 rounds.
- Total communication cost (in MB) is reduced by up to 10% compared to FedAvg.
- Across nine datasets (including CIFAR‑10, Sent140, Edge‑IIoTset), FOFedAvg consistently matches or outperforms ten baseline FL algorithms in final test accuracy and convergence speed.

## Why This Works (Mechanism)
The fractional‑order update effectively computes a Caputo fractional derivative, integrating historical gradients with a power‑law decay. This smoothing dampens oscillations caused by client drift in heterogeneous settings. The parameter α controls memory length: smaller α gives longer memory, better averaging conflicting gradients but potentially slowing adaptation. The δ term avoids numerical instability when parameter differences vanish, and the adaptive learning rate µ_t = µ_0/√(t+1) regulates step size across local iterations. Together, these elements yield more stable and faster convergence under non‑IID conditions.

## Foundational Learning
1. **Fractional Calculus**  
   *Why needed*: Provides derivatives/integrals of non‑integer order, enabling updates that depend on the full history of gradients rather than just the immediate past.  
   *Quick check*: Caputo derivative of *f(t)=t* for α=0.5 is D^{0.5}_C t = Γ(2)/Γ(1.5)·t^{0.5} ≈ 1.128·t^{0.5}.

2. **Caputo Derivative**  
   *Why needed*: A fractional derivative suited for initial‑value problems; yields zero for constant functions, avoiding spurious shifts in optimization.  
   *Quick check*: For any constant *c*, D^{α}_C c = 0.

3. **FedAvg (Federated Averaging)**  
   *Why needed*: Standard FL algorithm that reduces communication via local SGD; FOFedAvg extends it with fractional updates.  
   *Quick check*: Implement FedAvg with *E* local epochs and client fraction *C*; verify convergence on IID data.

4. **Non‑IID Data in FL**  
   *Why needed*: Real‑world FL data is heterogeneous across clients, causing client drift and slowing convergence.  
   *Quick check*: Partition MNIST so each client gets only two digits; FedAvg will converge slower and to lower accuracy than IID partition.

5. **Client Drift**  
   *Why needed*: Divergent local gradients due to data heterogeneity produce a noisy global update, hindering model quality.  
   *Quick check*: In a two‑client setting with disjoint label sets, local gradients point in opposite directions, illustrating drift.

## Architecture Onboarding
**Component map**:  
Global Model (Server) -> (broadcast: Θ_t, Θ_{t−1}) -> Client (local data, FOSGD) -> (upload update) -> Server (weighted average) -> New Global Model

**Critical path** (per communication round *t*):
1. Server initializes Θ_0.
2. For each round:
   - Server selects subset *S_t* (fraction *C*) and sends each client Θ_t and Θ_{t−1} (for *t*=0, send Θ_0 twice).
   - Each client *k* sets local parameters Θ^{(k)} = Θ_t.
   - Local training:
     * For local step index *t_local* = 0: use standard SGD.
     * For *t_local* ≥ 1: use FOSGD with the client’s own previous local parameters (Θ_{t_local−1} and Θ_{t_local−2}? Actually formula uses Θ_t and Θ_{t−1}; client must store two consecutive local models).
   - After *E* epochs, client sends final Θ^{(k)} to server.
3. Server aggregates: Θ_{t+1} = ∑_{k∈S_t} (n_k / ∑ n_k) Θ^{(k)}_{t+1}.
4. Shift: Θ_{t−1} ← Θ_t, Θ_t ← Θ_{t+1}.

**Design tradeoffs**:
- **α**: Smaller values (e.g., 0.6) increase memory and smoothing but may slow adaptation; larger values (close to 1) reduce memory, approaching FedAvg.
- **δ**: Must be positive; too small risks numerical instability near zero ‖Δ‖, too large diminishes memory effect.
- **µ_0**: Base learning rate; larger values speed convergence but may cause divergence with fractional scaling; requires per‑dataset tuning.
- **Local epochs *E* & batch size *B***: More local steps amplify memory but also increase client drift; trade‑off between communication frequency and accuracy.

**Failure signatures**:
- Using server’s Θ_{t−1} instead of the client’s own previous local model: memory term becomes incorrect, likely causing divergence.
- Applying fractional scaling at *t*=0: first update mis‑scaled, harming early convergence.
- Gamma function errors: inaccurate Γ(2−α) distorts step size, especially for small α.
- Sporadic client participation: a returning client may have a large ‖Δ‖, producing a huge step; needs careful handling.

**First experiments**:
1. **Unit test FOSGD** on a synthetic linear regression model; verify fractional scaling by comparing update magnitude for α=0.5 vs α=1, and check that α=1 reduces to standard SGD.
2. **Replicate MNIST** using CNNMnist, Dirichlet α=0.1 partition, *E*=20, *B*=50, *C*=0.2, µ_0=0.05, α=0.6. Report rounds to reach 60% accuracy; expect 4–60.
3. **Ablation study**: run FOFedAvg with α=1 (FedAvg) and α=0.6 under identical settings; plot convergence curves to isolate memory effect. Optionally test α=0.3 to see longer memory impact.

## Open Questions the Paper Calls Out
- **Hyperparameter tuning**: How to automatically select α and δ for different heterogeneity levels? Current approach relies on grid search.
- **Robustness to poisoning/outliers**: Fractional memory weights all historical gradients, potentially amplifying malicious or minority patterns; a robust aggregation scheme is needed.
- **Differential privacy**: How to incorporate DP without losing convergence advantages? Clipping and noise may interfere with fractional scaling; trade‑off analysis is required.

## Limitations
- Exact partitioning seeds and class‑shard distributions for the nine datasets are not provided, hindering exact reproducibility.
- Per‑dataset hyperparameters (α, µ_0, *E*, *B*) used for the main curves are reported only as ranges; specific values are unspecified.
- Model architectures for non‑image tasks (Sent140, Edge‑IIoTset, Cleveland) lack details such as layer sizes and embedding dimensions.

## Confidence
- **Empirical superiority over baselines**: Medium (improvements are consistent, but hyperparameter variations could affect magnitude).
- **Communication cost reduction**: Low‑Medium (claims depend on local epoch/batch choices not fully documented).
- **Theoretical convergence to stationary point**: High (proof aligns with standard assumptions and is provided in the appendix).
