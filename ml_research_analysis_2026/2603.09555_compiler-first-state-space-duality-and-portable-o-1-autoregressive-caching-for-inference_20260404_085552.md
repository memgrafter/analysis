# Compiler-First State Space Duality and Portable $O(1)$ Autoregressive Caching for Inference

## Quick Facts
- arXiv ID: 2603.09555
- Source URL: https://arxiv.org/abs/2603.09555
- Reference count: 1
- Primary result: Kernel‑free Mamba‑2 inference on CPU/GPU/TPU with O(1) caching and performance up to 140 TFLOPS (15% MFU) on TPU v6e.

## Executive Summary
State‑space models like Mamba‑2 typically rely on custom CUDA/Triton kernels, limiting them to NVIDIA hardware. This work demonstrates that Mamba‑2’s state‑space duality—characterized by a diagonal state structure, chunkable recurrence, and einsum‑dominated compute with static control flow—aligns with XLA’s optimization passes. Consequently, a fully kernel‑free implementation becomes possible using only standard JAX primitives. The approach achieves portable O(1) autoregressive caching via compiled on‑device control flow, eliminating host‑device round‑trips during generation. Across five model scales (130M–2.7B) on TPU v6e, prefill reaches ~140 TFLOPS (15% MFU) and decode attains up to 64% HBM bandwidth utilization. Greedy decoding matches the PyTorch/CUDA reference token‑for‑token, with hidden‑state agreement within float32 rounding error. Ablations confirm that static masking prevents an 82.8% throughput drop and that float32 decay exponentiation is required for numerical correctness.

## Method Summary
The authors map the SSD algorithm to standard JAX primitives: prefill splits the full sequence into fixed‑size chunks (L=256); within each chunk, the sequential recurrence unrolls into parallel batched einsum contractions that XLA tiles onto matrix units. Inter‑chunk sequential states are merged via a lightweight scan. For autoregressive generation, the state cache (SSM state and convolution state) is carried in a JAX PyTree inside a compiled `jax.lax.fori_loop`, avoiding host‑device round‑trips and yielding O(1) step latency. Critical design choices include: using a static lower‑triangular mask (precomputed from the decay matrix) to preserve fusion, and performing decay exponentiation in float32 to prevent numerical drift. The same codebase runs unmodified on CPU, GPU, and TPU.

## Key Results
- Kernel‑free Mamba‑2 implementation using only shaped JAX primitives achieves portability (CPU/GPU/TPU) and O(1) autoregressive caching.
- Prefill performance up to ~140 TFLOPS (15% MFU) on TPU v6e; decode HBM bandwidth utilization up to 64%.
- Token‑level parity with PyTorch/CUDA reference; static masking prevents 82.8% throughput drop; float32 decay exponentiation ensures numerical correctness.

## Why This Works (Mechanism)
The success rests on three interconnected mechanisms:

1. **Alignment of SSD structure with XLA’s optimization passes**  
   Mamba‑2’s diagonal state matrix and chunkable recurrence allow the intra‑chunk computation to be expressed as batched einsum contractions over contiguous tensor axes. These regular, dense operands enable XLA’s tiler to generate efficient GEMM calls. The recurrence is analytically unrolled over fixed‑size chunks (L=256), converting sequential dependence into parallel matrix operations. Evidence: [abstract]; [section 3.1]; [section 3.2].

2. **Static masking preserves fusion**  
   The causal decay mask `L` is precomputed as `tril(exp(segsum(log A)))`. This static tensor is fused into surrounding element‑wise operations. Dynamic per‑position masking (e.g., via `fori_loop` and `dynamic_slice`) would break fusion graphs, forcing intermediate materialization and causing an 82.8% throughput drop. Evidence: [section 3.3]; ablation in [section 5.7.1].

3. **Compiled on‑device loop for O(1) caching**  
   The cache (a JAX PyTree) is carried through a `jax.lax.fori_loop` that traces the entire generation step onto the device. This eliminates host‑device round‑trips per token, which otherwise incur a ~2.4× slowdown for small models. Evidence: [section 3.4]; [section 4.3]; [appendix B.6].

## Foundational Learning
- **XLA’s fusion and tiling passes**  
  XLA fuses operations into megakernels and tiles batched matmuls. This is needed because SSD compute is einsum‑dominated; understanding fusion explains why a single `einsum` can be more efficient than decomposed `matmul` and `multiply`.  
  *Quick check:* If you decompose the einsum into separate primitives, you may lose tiling opportunities and increase memory traffic.

- **State‑Space Model (SSM) recurrence and duality**  
  The recurrence `h_t = Â h_{t‑1} + B̂ x_t` has a fixed state size (e.g., 128) independent of sequence length, enabling O(1) caching.  
  *Quick check:* Doubling the state dimension multiplies cache size by that factor; doubling the number of heads multiplies it as well; sequence length never appears in cache size.

- **JAX transformation semantics (`jit`, `fori_loop`, PyTree)**  
  The cache must be a JAX PyTree to be carried inside a `jax.lax.fori_loop` that is jit‑compiled, ensuring the entire loop is one XLA program.  
  *Quick check:* If the cache is a Python list, `jax.jit` cannot trace it, causing fallback to host iteration or recompilation per step.

## Architecture Onboarding
Component map:  
`Input -> SSD Prefill (chunked einsums + inter‑chunk scan) -> Final chunk states & logits -> Mamba2Cache (ssm_state, conv_state) -> fori_loop decode_step (projections, conv update, SSM decay & state update) -> logits`

Critical path: Prefill produces initial cache; then compiled `fori_loop` repeatedly calls `decode_step` carrying cache, avoiding host interaction.

Design tradeoffs:
- Chunk size L: Larger L improves intra‑chunk tiling (MFU) but increases inter‑chunk overhead; paper uses fixed L=256.
- Precision: BF16 for matmuls for throughput, but float32 for decay exponentiation mandatory for correctness.
- Loop placement: Device loop (`fori_loop`) essential for small models (2.4× speedup); host loop only acceptable for large models where per‑step FLOPs dominate launch overhead.

Failure signatures:
- Numerical drift: mismatch with PyTorch tokens → check decay dtype (float32) and matmul precision.
- Throughput collapse (~82.8% drop) → check for dynamic masking; ensure static `jnp.tril`.
- Memory scaling linearly with sequence length → verify chunking and that cache is carried, not recomputed.
- Portability issues (e.g., CUDA‑only ops) → avoid custom calls; stick to standard JAX.

First 3 experiments:
1. Portability smoke test: Run identical JAX script on CPU, GPU (A100), TPU (v6e) with 130M checkpoint, 128‑token prompt, 32 decode steps. Verify token sequences match PyTorch reference exactly.
2. Cache scaling validation: Measure decode throughput and peak memory for sequence lengths 128, 1024, 4096. Confirm throughput constant and memory constant for cached path; quadratic slowdown for non‑cached.
3. Masking ablation: Replace static `jnp.tril(L)` with dynamic row‑wise mask inside loop. Expect ~80% throughput drop; confirm outputs bitwise identical.

## Open Questions the Paper Calls Out
1. What is the optimal chunk size L for Mamba‑2 across model scales and hardware, and how does it trade off between prefill MFU and decode HBU?
2. How do XLA’s fusion and tiling strategies vary across different hardware backends (e.g., TPU v4/v5e, NVIDIA GPUs of different architectures), and what is the corresponding impact on MFU and HBU?
3. Can the compiler‑first pattern extend to SSM variants involving irregular operations (e.g., data‑dependent control flow, gather/scatter), and what compiler or algorithmic modifications would be needed to preserve fusion?
4. Does the numerical drift from using compiler‑generated code with float32 decay exponentiation affect downstream task accuracy (e.g., perplexity, zero‑shot accuracy) on standard benchmarks?

## Limitations
- Exact XLA compilation flags used for benchmarks are not disclosed, risking that reported MFU/HBU numbers may depend on non‑default optimizations.
- Portability is validated only on CPU, NVIDIA A100, and TPU v6e; behavior on other accelerators (AMD/Intel GPUs, other TPU generations) remains unknown.
- Design choices (fixed L=256, static masking) lack systematic ablation across model scales and hardware; their optimality is not established.

## Confidence
- Kernel‑free Mamba‑2 via XLA: Medium
- Static masking prevents 82.8% throughput drop: High
- O(1) caching via compiled `fori_loop`: High
- Single codebase portability (CPU/GPU/TPU): High (for tested platforms)
