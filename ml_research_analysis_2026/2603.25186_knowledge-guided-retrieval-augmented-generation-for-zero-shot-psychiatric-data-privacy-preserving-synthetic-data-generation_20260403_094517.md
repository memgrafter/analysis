# Knowledge-Guided Retrieval-Augmented Generation for Zero-Shot Psychiatric Data: Privacy Preserving Synthetic Data Generation

## Quick Facts
- **arXiv ID:** 2603.25186
- **Source URL:** https://arxiv.org/abs/2603.25186
- **Reference count:** 40
- **Primary result:** A zero‑shot LLM+RAG approach generates synthetic psychiatric tabular data with fidelity comparable to CTGAN/TVAE and privacy metrics on par with CTGAN, without exposure to real patient records.

## Executive Summary
Access to real psychiatric data is severely limited by privacy regulations, hampering AI research in mental health. Existing synthetic data generators that rely on real patient records face a trade‑off between fidelity and privacy. This paper introduces a zero‑shot framework that uses a Large Language Model (Mistral 7B) guided by Retrieval‑Augmented Generation (RAG) with clinical manuals (DSM‑5, ICD‑10) to generate synthetic tabular patient assessment data without any exposure to real records. Evaluated on six anxiety disorders, the proposed method attains fidelity metrics (Jensen‑Shannon divergence, Mean Absolute Cramér’s V error, Energy Distance) competitive with state‑of‑the‑art synthetic data generators (CTGAN, TVAE), while privacy metrics (exact overlap, linkage risk) are comparable to CTGAN and superior to TVAE. The results demonstrate that knowledge‑guided LLM generation can produce high‑quality synthetic psychiatric data without the privacy risks associated with using real patient data.

## Method Summary
The system constructs a Faiss vector store from chunks (~256 tokens) of DSM‑5 and ICD‑10 manuals. For each synthetic patient, it first samples demographics (sex, age) and a latent profile (severity prior, response style, symptom awareness, communication style, consistency level). Then, for each questionnaire item (5‑point Likert scale 0–4), it retrieves the top‑k relevant manual excerpts, combines them with the profile, the item text, and memory of prior answers into a structured prompt for Mistral 7B. The LLM is instructed to output a JSON object containing a score; the response is parsed and stored. The process repeats for all items, forming a complete synthetic row. The authors test four knowledge conditions: no knowledge base (NO‑KB), DSM‑5 only, ICD‑10 only, and dual‑KB. Baselines include CTGAN and TVAE trained via the Synthetic Data Vault (SDV). To select privacy‑aware models, each baseline is trained on a 70% train split and tuned on a 30% hold‑out with grid search over epochs and seeds. Candidate models are filtered by privacy gates (Exact Overlap ≤0.01, Near‑match share ≤0.10, 5th‑percentile normalized nearest‑neighbour distance ≥1). If none pass, a fallback hierarchy (min EO, then min Share, then max distance, then min JSD) picks a model. The selected models are retrained on the full real dataset and evaluated on fidelity (JSD, MAEV, Energy Distance²) and privacy (Exact Overlap, linkage risk) against the complete real data.

## Key Results
- The knowledge‑augmented LLM achieves fidelity scores (JSD, MAEV, ED²) that are competitive with CTGAN and TVAE across the six anxiety disorders.
- Privacy analysis shows the zero‑shot LLM yields modest exact overlaps and low linkage risk comparable to CTGAN, while TVAE exhibits extensive duplication.
- An ablation study demonstrates that retrieval from clinical manuals improves fidelity over a no‑retrieval LLM baseline.

## Why This Works (Mechanism)
The RAG component grounds the LLM’s generation in authoritative clinical knowledge by retrieving relevant excerpts from DSM‑5 and ICD‑10. This ensures that each synthetic response respects disorder‑specific symptom criteria and their typical severity ranges. The latent profile introduces individual variability (e.g., overall severity, response style) so that generated rows differ across simulated patients. Structured JSON extraction forces the model to produce discrete scores consistent with the questionnaire format. Because the LLM never sees real patient data, the approach sidesteps the privacy‑fidelity trade‑off that plagues conventional generative models trained on actual records.

## Architecture Onboarding
**Component map**  
Random seed → Demographic sampler → Latent profile generator → For each item: Retriever (Faiss) → Prompt builder → Mistral 7B → JSON parser → Memory update → Collected scores → Row assembler → Synthetic dataset

**Critical path**  
1. Sample patient demographics and latent variables.  
2. For each questionnaire item:  
   a. Retrieve top‑k manual excerpts.  
   b. Build prompt with demographics, profile, excerpts, item text, and prior answers.  
   c. Invoke Mistral 7B.  
   d. Parse JSON to obtain a score (0–4).  
   e. Store score and update memory.  
3. Combine all scores with demographics to form one synthetic row.  
4. Repeat to reach target dataset size.

**Design tradeoffs**
- *LLM size:* 7B‑parameter Mistral balances quality and computational cost; larger models might capture finer clinical nuances but are more expensive.
- *Retrieval k:* Larger k provides richer context but increases prompt length and may introduce irrelevant snippets.
- *Structured extraction:* Using JSON ensures tabular output but demands careful prompting; free‑form text would be more flexible but harder to parse.
- *Privacy‑utility tradeoff:* The stringent privacy gates (EO≤0.01, etc.) protect patient privacy but can exclude otherwise high‑fidelity models, forcing fallback selections that might sacrifice utility.

**Failure signatures**
- High LLM output parsing failure rate (malformed JSON or missing score).
- Retrieved snippets that are off‑topic or pertain to the wrong disorder.
- Synthetic dataset contains many exact duplicates (EO spikes) or has very low linkage risk yet poor fidelity (over‑regularization).
- Generates score distributions that differ drastically from real data (e.g., extreme JSD values).

**First experiments**
1. **Baseline replication:** Implement the pipeline with default parameters (k=5, no latent profile) and generate one disorder’s dataset; compute fidelity metrics to ensure they are in the same ballpark as reported values.
2. **Retrieval quality assessment:** Manually evaluate the top‑5 excerpts for a random set of items to verify clinical relevance; compute an average relevance score (e.g., 1‑5 scale) and identify failure modes.
3. **Latent profile impact:** Run an ablation where all latent variables are fixed (e.g., severity=moderate, uniform response style) and compare score diversity (e.g., standard deviation of item scores) to the full model; the full model should show greater variability.

## Limitations
- Key hyperparameters (retrieval *k*, prompt template, LLM temperature, latent profile distributions) are not fully specified, leaving replication uncertain.
- Definitions of privacy metrics (e.g., normalized vs. unnormalized Hamming distance) are ambiguous, potentially affecting reported privacy outcomes.
- The magnitude of the observed retrieval benefit depends on the quality of the knowledge base chunking and embedding model, which are not thoroughly characterized.

## Confidence
- **Fidelity claims:** Medium (metrics are well‑defined but implementation gaps could shift results).
- **Privacy claims:** Low (ambiguous metric definitions and privacy‑gate thresholds introduce high variance).
- **Ablation conclusion:** Medium (retrieval likely helps, but effect size is uncertain without full specs).
