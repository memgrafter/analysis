# Where Matters More Than What: Decoding-aligned KV Cache Compression via Position-aware Pseudo Queries

## Quick Facts
- **arXiv ID**: 2603.11564
- **Source URL**: https://arxiv.org/abs/2603.11564
- **Reference count**: 40
- **Primary result**: DapQ achieves near-lossless long-context performance (99.5% on Needle-in-a-Haystack) with only 3% KV cache budget.

## Executive Summary
KV cache compression is essential for serving long-context large language models efficiently. Existing methods assess token importance during the prefill stage using input-side attention patterns, which fails to preserve tokens critical for future generation because those patterns misalign with actual decoding queries. This paper introduces DapQ, which constructs lightweight pseudo queries by appending synthetic tokens to the input during prefill and assigning them the precise positional encodings of the first N decoding steps. These position-aware pseudo queries simulate the output tokens' contextual positioning, creating an observation window that accurately reflects the attention patterns of the generation process. DapQ significantly outperforms strong baselines under strict memory constraints across multiple long-context benchmarks while introducing negligible overhead.

## Method Summary
DapQ operates during the prefill stage without additional training. Given a prompt of length Lₚ, the method appends N synthetic tokens immediately after the prompt and assigns them positional IDs [Lₚ, Lₚ+N−1], corresponding to the first N decoding positions. The model processes this extended sequence, generating query vectors for the synthetic tokens (Qₚₛₑᵤ𝑑ₒ) that inherit the correct positional information. Importance scores for each original prompt token are computed by summing its attention weights from all Qₚₛₑᵤ𝑑ₒ. The top-K tokens by these scores are retained; all others and the synthetic tokens are evicted from the KV cache. Decoding then proceeds from position Lₚ with the compressed cache.

## Key Results
- Achieves 99.5% accuracy on Needle-in-a-Haystack with just 3% KV cache budget.
- Consistently ranks top across LongBench, LongBenchV2, Ruler, and HELMET at low budgets (64–256 tokens).
- Introduces negligible Time-to-First-Token overhead compared to SnapKV and maintains comparable throughput.

## Why This Works (Mechanism)
**Mechanism 1: Positional information dominates query representation.** In RoPE-based models, the positional encoding component shapes the query vector far more than token embedding. Queries with matching positional IDs but different content maintain high similarity to true decoding queries, while mismatched positions drastically reduce similarity even if content matches. This insight makes the semantic content of pseudo queries secondary; correct positions suffice.

**Mechanism 2: Position-aware pseudo queries mimic decoding queries.** By appending synthetic tokens with positional IDs [Lₚ, Lₚ+N−1], DapQ ensures that during prefill, the computed Qₚₛₑᵤ𝑑ₒ have the same positional context as the first N actual decoding queries. This creates an observation window whose attention distribution closely mirrors that of the generation process, without requiring actual token generation.

**Mechanism 3: High recall of critical tokens.** Because Qₚₛₑᵤ𝑑ₒ approximates the true decoding query distribution, the tokens selected via summed attention scores have high overlap with the ideal set (selected using all future queries). This high recall preserves the right context for accurate generation, especially under tight cache budgets.

## Architecture Onboarding
**Component map**:  
Input Processor -> Pseudo Token Extension Module -> Prefill Engine -> Importance Scorer -> Eviction Controller -> Autoregressive Decoder

**Critical path**:  
1. Receive prompt; compute Lₚ (prompt length).  
2. Generate N pseudo tokens; assign positional IDs [Lₚ, Lₚ+N−1]; concatenate to prompt.  
3. Run prefill on extended sequence; extract last-layer attention weights and full KV cache.  
4. Sum attention from pseudo query positions to original keys to compute token scores.  
5. Select top-K tokens; prune KV cache to these indices.  
6. Discard pseudo tokens and their KV entries.  
7. Begin decoding at position Lₚ with compressed KV cache.

**Design tradeoffs**:  
- **Window size N**: Larger N improves robustness but beyond ~64 introduces noise; default N=32 recommended.  
- **Pseudo token content**: Content is secondary; a mix of prefix and suffix tokens (e.g., first 4 + last 28) yields stable performance.  
- **Positional assignment**: Must be exactly [Lₚ, Lₚ+N−1]; any offset degrades similarity.  
- **Memory overhead**: Temporary KV for N pseudo tokens adds prefill memory; ensure N is small for target hardware.

**Failure signatures**:  
1. Sharp drop in Needle-in-a-Haystack accuracy at moderate budgets (e.g., <50% at 3%) indicates poor recall, likely due to positional misalignment or insufficient N.  
2. High variance across random seeds for pseudo token content suggests model-specific sensitivity.  
3. Latency increase in prefill exceeding O(N) expectations could signal inefficient attention computation.  
4. Performance collapse on content-heavy tasks (e.g., factual QA) may arise if the model relies more on semantic content than position.

**First 3 experiments**:  
1. **Attention similarity validation**: Compute cosine similarity between Qₚₛₑᵤ𝑑𝑜 attention distribution and actual first N decoding queries (when available). Target >0.95 as in Table 8.  
2. **Recall metric test**: Replicate Section 3.3 on a dataset like GovReport; verify recall >0.5 at window=32.  
3. **End-to-end budgeted accuracy**: Run Needle-in-a-Haystack with KV budget (e.g., 256 for LLaMA-3-8B). Aim for reported accuracy within ±1% (e.g., 99%). If not met, check positional assignment and N.

## Open Questions the Paper Calls Out
**Open Question 1**  
How can we construct semantically more meaningful pseudo queries (Qₚₛₑᵤ𝑑𝑜) without introducing significant computational overhead, to further improve performance under extreme compression?  
*Basis*: Limitations state future work may explore intelligent Qₚₛₑᵤ𝑑𝑜 content construction. Current method uses simple concatenation; semantically optimized variants could boost accuracy but may increase prefill cost.

**Open Question 2**  
How can we design layer-wise or adaptively-aware Qₚₛₑᵤ𝑑𝑜 approximation mechanisms to better align with the attention distribution of each layer, given varying sensitivity to positional and semantic information?  
*Basis*: Limitations note that DapQ applies the same pseudo queries uniformly across layers, while different layers may have distinct attention patterns. Layer-specific adjustments could improve compression.

**Open Question 3**  
Does the finding that positional information dominates over semantic content in query representations generalize to all Transformer-based LLMs, including those with different positional encoding schemes (e.g., ALiBi) or extreme model scales?  
*Basis*: Core insight is based on RoPE-based models (LLaMA, Qwen). It is untested on architectures with absolute embeddings or ALiBi, or on very large models (>70B).

**Open Question 4**  
What is the optimal window size (N) for a given model and context length, and can it be predicted or adapted automatically rather than chosen via manual grid search?  
*Basis*: Section 6.2 shows non-monotonic N-performance relationship with an optimal peak (e.g., 32–64). No automatic method is proposed; manual tuning is inconvenient and may not generalize.

## Limitations
- **Generalizability**: Positional dominance demonstrated only on RoPE-based models; unknown for absolute embeddings or newer architectures.
- **Layer-specific behavior**: Analysis focuses on late layers; early/middle layers may exhibit different positional sensitivity.
- **Hyperparameter stability**: Optimal N and pseudo-token content mix are dataset/model-dependent; no universal rule provided.
- **Benchmark coverage**: Comparisons exclude recent concurrent methods (e.g., TreeKV, LazyEviction), leaving relative ranking incomplete.

## Confidence
- **Positional dominance mechanism**: High – Strong empirical evidence (cosine similarity, ablations) on multiple models.
- **Pseudo-query construction efficacy**: Medium – Well-specified procedure, but optimal N and token selection lack theoretical justification.
- **End-task performance under budget**: Medium – Consistent gains on long-context benchmarks, but evaluation limited to older models (LLaMA-2/3) and may not generalize to newer architectures or harder tasks.

## Next Checks
1. **Architecture stress test**: Replicate on a non-RoPE model (e.g., GPT-2 with absolute embeddings) to verify if positional dominance breaks, causing DapQ performance to collapse.
2. **Layer-aggregation ablation**: Compare last-layer vs. multi-layer (e.g., last 4 layers) importance scoring to quantify sensitivity to depth and identify optimal aggregation.
3. **Competitive benchmarking**: Run DapQ against TreeKV and LazyEviction on the same budget (64–256 tokens) across LongBench and Ruler to establish current state-of-the-art ranking.
