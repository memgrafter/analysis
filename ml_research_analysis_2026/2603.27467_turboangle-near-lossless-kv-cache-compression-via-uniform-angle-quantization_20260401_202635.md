# TurboAngle: Near-Lossless KV Cache Compression via Uniform Angle Quantization

## Quick Facts
- **arXiv ID:** 2603.27467
- **Source URL:** https://arxiv.org/abs/2603.27467
- **Reference count:** 16
- **Primary result:** Achieves lossless compression (∆PPL≤0) on four of seven models (1B–7B) and near‑lossless (∆PPL≤0.002) on six, with total bits as low as 6.56 per element on Mistral‑7B and zero calibration; represents a 14.8× reduction in perplexity degradation versus TurboQuant at similar bit rates.

## Executive Summary
TurboAngle tackles the memory scalability issue of KV caches in large language models by introducing a calibration‑free uniform angle quantization scheme. The core idea is to transform KV vectors using a random diagonal rotation followed by a Fast Walsh‑Hadamard Transform (FWHT), which produces uniformly distributed angles on pairs of coordinates, enabling optimal uniform quantization without per‑channel calibration. The approach extends with per‑layer early‑boost to allocate more bits to critical layers and asymmetric norm quantization (8‑bit linear for keys, 4‑bit log‑space for values) to minimize total bit rate while preserving accuracy. Evaluated on seven models (1B–7B), TurboAngle attains lossless compression on four models and near‑lossless on six, with total bits as low as 6.56 per element on Mistral‑7B, a 14.8× improvement over prior scalar quantization methods.

## Method Summary
TurboAngle compresses KV cache vectors through a three‑stage pipeline: a fixed random ±1 diagonal rotation applied to each vector, followed by a normalized Fast Walsh‑Hadamard Transform (FWHT) that produces coordinate pairs with approximately uniform angular distribution. The resulting polar coordinates are quantized separately: the angle is uniformly mapped to a configurable number of bins (codebook size) per layer, while the norm undergoes per‑vector scalar quantization—linear for keys (8 bits) and log‑space for values (4 bits). The angle codebook size can be independently set for each transformer layer’s K and V caches, enabling a per‑layer early‑boost strategy where a subset of critical layers receives higher precision while others use a baseline. The random diagonal rotation is globally shared and fixed, eliminating the need for calibration data. Reconstruction exactly inverts these steps using the shared rotation matrix and the normalized inverse FWHT. The method’s bit rate combines angle bits (3.28–3.67 per element in the basic configuration) with norm bits (totaling ~6.56 bits per element on Mistral‑7B in the full configuration).

## Key Results
- Lossless (∆PPL≤0) on 4/7 models; near‑lossless (∆PPL≤0.002) on 6/7 models at 3.28–3.67 angle bits/element.
- Full configuration on Mistral‑7B: 6.56 total bits/element with ∆PPL=+0.0014 and zero calibration overhead.
- Compared to TurboQuant scalar quantization, TurboAngle reduces perplexity degradation by 14.8× at comparable bit rates.

## Why This Works (Mechanism)
TurboAngle’s near‑lossless performance arises from three synergistic mechanisms:

1. **Uniform Angle Distribution via Randomized FWHT**: A fixed random ±1 diagonal rotation followed by a normalized Fast Walsh‑Hadamard Transform yields consecutive output pairs that are approximately uniformly distributed on the unit circle for head dimensions d ≥ 64, a consequence of the Central Limit Theorem driving the joint distribution toward a spherically symmetric 2‑D Gaussian. Under this distribution, the angle is exactly uniform and independent of the radius, making uniform quantization information‑theoretically optimal for a given bit rate and obviating per‑channel calibration. The asymptotic uniformity assumption may fail for very small d (< 32), where non‑uniform codebooks could become necessary.

2. **Per‑Layer MixedKV Early‑Boost**: Transformer layers exhibit heterogeneous sensitivity to KV cache quantization. TurboAngle allows independent configuration of K and V angle codebook sizes per layer. The early‑boost heuristic assigns larger codebooks (e.g., 256 bins) to a contiguous set of initial layers while keeping later layers at a baseline (e.g., 128 bins), effectively allocating bits to the most impactful layers. This works well for most models but some (e.g., phi‑1.5) exhibit “negative‑transfer” layers where extra precision harms quality, requiring selective non‑contiguous boost configurations.

3. **Asymmetric Norm Quantization**: Attention scores are highly sensitive to the scaling provided by K‑cache norms (10–20× more than V‑norms). Consequently, TurboAngle uses 8‑bit linear quantization for K‑norms, while V‑norms tolerate aggressive 4‑bit log‑space quantization due to their right‑skewed distribution and additive contribution to value aggregation. This asymmetry shrinks the total bit budget without meaningful degradation.

## Architecture Onboarding
### Component Map
Encode pipeline: Input KV vector `x` → Random Diagonal Rotation `D` (fixed ±1 matrix) → Normalized FWHT `H·D·x` → Polar Decomposer (computes per‑pair angle θ and norm r) → Angular Quantizer (uniform binning of θ, codebook size `n` per layer) + Norm Quantizer (scalar quantization of r, asymmetric bits for K/V) → Store encoded indices and norm codes.  
Decode pipeline: Retrieve indices/norm codes → Reconstructor (dequantize angles/norms, map to Cartesian) → Inverse FWHT `H⁻¹` → Multiply by `D` → Reconstructed `x̂`.  
Configuration Manager: Holds per‑layer `(n_K, n_V)` and norm bit settings; supplies them to quantizers.

### Critical Path
For each KV vector `x`: apply `y = H·D·x` via FWHT; for each consecutive pair `(y_{2i}, y_{2i+1})` compute angle `θ_i = atan2(y_{2i+1}, y_{2i})` and norm `r_i = sqrt(y_{2i}^2 + y_{2i+1}^2)`; quantize angle into `k_i = floor(n * θ_i/(2π) + 0.5) mod n`. Norm quantization uses per‑vector min‑max scaling, optionally in log‑space for V. Reconstruction: from `k_i, r_i` compute `(r_i cos(θ̂), r_i sin(θ̂))` with `θ̂ = (k_i + 0.5) * (2π/n)`, then inverse transform `x̂ = D·H⁻¹·[reconstructed pairs]`.

### Design Tradeoffs
- **Angle bits vs. Norm bits:** Increasing angle codebook size improves directional fidelity; increasing norm bits improves radius fidelity. The paper shows K‑angles and K‑norms are both highly sensitive, while V‑norms are less so.
- **Per‑layer boost granularity vs. Search cost:** Finer per‑layer granularity can capture nuanced sensitivities but requires more evaluation runs. The early‑boost heuristic works for most models, but selective configurations may be needed for some.
- **Log‑space vs. linear norm quantization:** Log‑space better for low bit rates (4‑bit) on right‑skewed V‑norm distribution; linear is safer for K‑norms at higher bits (8).
- **Calibration‑free vs. bit rate:** TurboAngle avoids calibration at the cost of 1–2 extra total bits/element compared to calibration‑based methods at very low bit rates.

### Failure Signatures
- **Non‑monotonic ∆PPL with increasing angle codebook size `n`** (e.g., TinyLlama `n=64` worse than `n=56` or `128`) due to alignment with FWHT butterfly structure.
- **Non‑monotonic ∆PPL with increasing number of boosted layers** (e.g., OLMo E8 worse than E4) indicating layers where extra precision is harmful.
- **Negative transfer:** Some layers (e.g., phi‑1.5 layers 8‑15) degrade accuracy when boosted above baseline.
- **Catastrophic degradation with 4‑bit K‑norms** across most models; K‑norms require ≥8 bits.

### First 3 Experiments
1. **Uniform baseline:** Apply TurboAngle with fixed `(n_K=128, n_V=64)` across all layers and store norms in fp32. Measure ∆PPL to establish the basic angular transform’s impact.
2. **Per‑layer early‑boost sweep:** Test contiguous early‑boost configurations (early layers set to `(256,128)` vs. `(128,256)`; varying `n_early ∈ {4,8,16}`). Measure ∆PPL vs. average angle bits to identify the best orientation and boost depth. For phi‑1.5, also test selective non‑contiguous configurations.
3. **Norm quantization sensitivity:** Take the best angular configuration from (2). Replace fp32 norms with 8‑bit linear for both K and V, then with asymmetric K8V4‑log. Compute ∆PPL and total bits (Eq. 3) to quantify norm quantization cost and validate asymmetry.

## Open Questions the Paper Calls Out
1. Does TurboAngle’s near‑lossless perplexity on WikiText‑2 generalize to diverse downstream tasks (e.g., reasoning, code generation) and long‑context benchmarks? The paper only evaluates WikiText‑2.
2. What is the actual inference latency and memory bandwidth overhead of the FWHT operations under realistic serving conditions (e.g., high batch sizes, long sequences)? This is claimed negligible but unmeasured.
3. How does the method perform for transformer architectures with head dimension d < 32? All evaluated models have d ≥ 64; the asymptotic angle uniformity argument may break down for smaller dimensions.
4. What causes negative‑transfer layers where increasing angular precision harms performance, and can these be predicted without exhaustive layer‑group sweeps? The paper observes this but does not explain the underlying mechanism.

## Limitations
- **Implementation vagueness:** Exact FWHT butterfly order, numerical precision (float16 vs. float32 intermediates), and handling of odd head dimensions are unspecified, which could affect angle quantization boundaries.
- **Controlled baselines missing:** Comparisons to calibration‑based methods (e.g., KIVI, KVQuant) use mismatched models, datasets, or sequence lengths, preventing isolated attribution of gains.
- **Generalizability bounds:** Paper tests only d ≥ 64 (1B–7B models). Performance for small‑d heads (<32) or extremely long contexts (>32k tokens) is unknown.

## Confidence
- **Angular uniformity via FWHT+rotation:** High (theoretical CLT justification and empirical validation for d≥64).
- **Per‑layer early‑boost efficacy:** Medium (strong results on 6/7 models, but phi‑1.5 requires selective configuration).
- **Asymmetric K/V norm sensitivity:** High (consistent ablations across models show 10–20× sensitivity ratio).
