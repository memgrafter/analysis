# Counting on Consensus: Selecting the Right Inter-annotator Agreement Metric for NLP Annotation and Evaluation

## Quick Facts
- arXiv ID: 2603.06865
- Source URL: https://arxiv.org/abs/2603.06865
- Reference count: 0
- Primary result: Provides a task-type-driven guide to IAA metric selection, emphasizing that agreement is context-dependent and must be reported with confidence intervals and disagreement analysis.

## Executive Summary
This paper addresses a critical methodological challenge in NLP: selecting appropriate inter-annotator agreement (IAA) metrics for diverse annotation tasks. It argues that raw agreement overestimates reliability, and that the choice of chance-corrected metric must align with the task's data structure (categorical, segmentation, continuous). The authors synthesize a comprehensive framework, summarised in a decision table, and advocate for best practices such as reporting confidence intervals, analysing disagreement patterns, and transparently documenting annotation design. The core message is that IAA is not a single number but a context-sensitive measure that must be interpreted alongside validity and the informative value of disagreement to ensure reproducible annotation.

## Method Summary
The paper employs a narrative review methodology, organising IAA measures by the underlying annotation task type: categorical (e.g., text classification), structured/segmentation (e.g., named entity recognition), and continuous (e.g., rating scales). For each type, it analyses the mathematical assumptions, limitations (e.g., sensitivity to label imbalance, handling of missing data), and appropriate metrics (e.g., Cohen’s κ for two annotators, Fleiss’ κ for multiple, Krippendorff’s α for flexible designs, Pk/WindowDiff for segmentation, ICC for continuous). It does not present new empirical data but instead provides a practical guide (Table 1) for metric selection based on task properties, number of annotators, and data completeness. The recommended procedure includes computing point estimates, confidence intervals, and detailed disagreement diagnostics.

## Key Results
- A comprehensive mapping of IAA metrics to task types and annotation designs is provided, demonstrating that using a mismatched metric yields uninterpretable scores.
- Agreement metrics behave differently under factors like label imbalance, number of annotators, and missing data; e.g., κ can paradoxically decrease with high agreement on imbalanced data.
- Best practices for IAA reporting include: calculating confidence intervals, analysing per-label or boundary-specific disagreement, and documenting all annotation choices to ensure transparency and reproducibility.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Chance-corrected metrics provide a more accurate reliability estimate than raw agreement by accounting for expected coincidental matches.
- **Mechanism:** Raw percentage agreement (`Po`) inflates reliability when annotators systematically favor prevalent categories or when categories are imbalanced. Chance-corrected coefficients (e.g., Cohen’s κ, Fleiss’ κ, Krippendorff’s α) subtract an estimate of expected agreement (`Pe`) derived from the annotators' marginal distributions or uniform assumptions, thus isolating agreement beyond random chance.
- **Core assumption:** Annotator decisions are partially stochastic, and a baseline model of random or biased labeling exists to compute `Pe`.
- **Evidence anchors:**
  - [abstract] “relying on raw agreement alone can overestimate reliability, motivating the use of chance-corrected and task-appropriate statistics”
  - [section 2] Detailed derivation of `Pe` for Cohen’s κ and Bennett’s S, showing how `Pe` is computed from individual annotator label frequencies.
  - [corpus] Neighbor papers (e.g., *ReasonScaffold*, *BiasLab*) implicitly validate the need for correction by designing protocols to reduce ambiguity, acknowledging that raw agreement is insufficient.
- **Break condition:** If the annotation task is trivial with no label variation (all items have the same label), `Pe` becomes trivial and correction may subtract noise; also, if annotator biases are perfectly correlated, `Pe` estimates may be inaccurate.

### Mechanism 2
- **Claim:** Metric selection must align with the underlying data structure (categorical, segmentation, continuous) because each metric’s distance function and handling of missing data are tailored to specific annotation designs.
- **Mechanism:** Different tasks produce different agreements: categorical tasks need label-matching with optional weighting (κ, α); segmentation tasks need boundary alignment (Pk, WindowDiff, γ); continuous tasks need variance partitioning (ICC, CCC). Using a mismatched metric (e.g., Pk for categorical labels) yields uninterpretable scores because the disagreement definition (boundary vs. label) does not match the task’s unit of analysis.
- **Core assumption:** The annotation design defines the “unit” of agreement (item label, span, boundary, score) and the appropriate distance metric (e.g., 0/1 mismatch vs. squared difference).
- **Evidence anchors:**
  - [abstract] “organises agreement measures by task type… discussing how factors… influence reliability estimates”
  - [section 3 & 4] Explicit separation of metrics: span-based F1 for NER, Pk/WindowDiff for segmentation, ICC for continuous ratings.
  - [corpus] Neighbors like *From Variance to Invariance* (narrative graphs) and *LongEval* (faithfulness) involve structured/continuous judgments, requiring specialized metrics beyond κ.
- **Break condition:** If a task combines multiple units (e.g., segmenting *and* labeling each segment), a single unified metric like γ is needed; using separate categorical and segmentation metrics fragments the agreement signal.

### Mechanism 3
- **Claim:** Interpreting agreement scores requires contextual factors (label imbalance, number of annotators, missing data) because metric behaviour is sensitive to these design choices, affecting comparability and thresholds.
- **Mechanism:** Metrics react differently to prevalence: κ can paradoxically decrease when agreement is high but categories are imbalanced (“κ-paradox”), while Gwet’s AC1 is more stable. Missing data handling varies: α can accommodate sparse annotations, while Fleiss’ κ requires equal ratings per item. Thus, the same numerical score (e.g., κ=0.6) can mean different reliability depending on these factors.
- **Core assumption:** Agreement statistics are not absolute measures but estimators whose variance and bias depend on sample characteristics (prevalence, rater count, missingness).
- **Evidence anchors:**
  - [section 5.1] “agreement scores are not always comparable across metrics… affected by factors such as class imbalance, the number of annotators, and annotation granularity.”
  - [section 2.7] Gwet’s AC1 introduced specifically to address κ’s instability under imbalance.
  - [corpus] Neighbor *Tracing How Annotators Think* and *Leveraging Annotator Disagreement* highlight that label distribution and annotator traits condition agreement values.
- **Break condition:** If the annotation scheme has near-uniform category distribution and complete data, many metrics converge, reducing contextual sensitivity; but this is rare in complex NLP tasks.

## Foundational Learning
- **Concept: Chance-corrected agreement**
  - Why needed here: To avoid overestimating reliability when categories are imbalanced or annotators have biases; foundational for interpreting κ, α, AC1.
  - Quick check question: Why might two annotators achieve 90% raw agreement on a sentiment task with 95% positive instances, yet κ be near 0?
- **Concept: Reliability vs. Validity**
  - Why needed here: High IAA only confirms consistency, not that labels match the intended construct; Section 5.2 stresses this distinction for responsible reporting.
  - Quick check question: Can an annotation scheme have high κ but low validity? Provide an example.
- **Concept: Task-type metric mapping**
  - Why needed here: Using a categorical metric (κ) on span-based data (NER) would ignore boundary alignment; Table 1 is a decision guide based on data type.
  - Quick check question: Which metric(s) would you choose for a dialogue segmentation task where annotators place turn boundaries? Why?

## Architecture Onboarding
- **Component map:** Annotation Schema Definition -> Metric Selection Engine -> Reporting Module -> Disagreement Analyzer
- **Critical path:** Schema → Metric Selection → Pilot annotation → Compute full IAA + confidence intervals → Disagreement analysis → Iterate schema/training.
- **Design tradeoffs:**
  - *Precision vs. Interpretability:* Weighted κ captures ordinal nuance but requires defining weights; simpler unweighted κ is more interpretable but discards magnitude information.
  - *Missing data handling:* α’s flexibility vs. Fleiss’ κ’s requirement for complete designs—choose α if annotations are sparse, but acknowledge computational complexity.
  - *Aggregation strategy:* Single-rater reliability (ICC(2,1)) vs. average-rater reliability (ICC(2,k))—impacts whether you treat annotators as random samples or fixed.
- **Failure signatures:**
  - High `Po` (e.g., >0.85) but very low κ (<0.2) → severe class imbalance or asymmetric annotator biases.
  - κ highly sensitive to small changes in label distribution → consider Gwet’s AC1 as a robustness check.
  - Boundary-based metrics (Pk) giving counterintuitive scores (e.g., low agreement for nearly aligned boundaries) → switch to WindowDiff or γ for near-miss tolerance.
- **First 3 experiments:**
  1. **Schema validation run:** Annotate 50 items with 3 annotators; compute all applicable metrics (κ, α, ICC if continuous); check for paradoxical results (high Po/low κ) to detect imbalance issues.
  2. **Missing data stress test:** Randomly drop 20% of annotations; recompute α vs. Fleiss’ κ (which would require complete data); observe stability/feasibility.
  3. **Disagreement drilling:** For the main task, compute per-label recall/precision between annotators; identify “problematic” labels causing low α; revise guidelines or add distinguishing examples.

## Open Questions the Paper Calls Out
- **Question:** What IAA metrics are appropriate for multimodal and highly subjective annotation tasks (e.g., humor, creativity) not covered in this survey?
  - *Basis in paper:* [explicit] The Limitations section explicitly states that "multi-modal annotation, interactive evaluation, and subjective phenomena like humour or creativity may require approaches beyond those discussed."
  - *Why unresolved:* The paper's scope deliberately excludes these domains, leaving a gap in methodological guidance for metric selection in such complex, multidimensional tasks.
  - *What evidence would resolve it:* Development and empirical validation of new or adapted IAA metrics specifically for multimodal/creative contexts, including case studies that compare existing metrics' applicability and demonstrate reliability.
- **Question:** How should human evaluation benchmarks for LLMs be designed to account for legitimate diversity in human perspectives rather than collapsing disagreement into a single "gold standard"?
  - *Basis in paper:* [inferred] Section 5.5 challenges the assumption that human agreement is an upper bound and suggests benchmarking LLM evaluators against "diverse human perspectives" rather than a single reference.
  - *Why unresolved:* Current LLM evaluation practices often correlate model outputs with aggregated human judgments, ignoring that human disagreement may reflect valid variation rather than noise.
  - *What evidence would resolve it:* Empirical studies that collect multi-perspective human annotations across diverse domains, then benchmark multiple LLM evaluators against these varied reference sets to assess alignment, bias, and generalizability.
- **Question:** What practical, scalable frameworks exist for integrating annotator disagreement into NLP model training or evaluation pipelines instead of discarding it through majority voting?
  - *Basis in paper:* [inferred] Section 5.3 treats disagreement as informative and mentions rater-aware models and soft labels, but provides no concrete implementation strategies or comparative evaluation.
  - *Why unresolved:* While the paper advocates preserving disagreement, it does not resolve how to operationalize this in standard NLP workflows or measure its impact on downstream performance.
  - *What evidence would resolve it:* Benchmarks comparing disagreement-aware methods (e.g., annotator embeddings, label distribution learning) against aggregation baselines on tasks like text classification or NER, with analysis of robustness and fairness outcomes.

## Limitations
- No empirical validation of Table 1’s recommendations; the guide is a narrative synthesis without systematic benchmarking across diverse annotation tasks.
- Missing practical details: optimal parameters for boundary metrics (e.g., Pk window size), ordinal weighting schemes, and handling of sparse/non‑ignorable missing data.
- Unclear decision rules when multiple metrics apply (e.g., γ vs. separate boundary/label metrics for unitising tasks), risking inconsistent usage.

## Confidence
- *Chance-corrected metrics outperform raw agreement:* **High** (well-established statistical theory and derivation in Section 2).
- *Metric selection must match task data type:* **High** (clear theoretical distinction and practical examples in Sections 3–4).
- *Interpretation of agreement is context-dependent:* **High** (factors like imbalance and missing data are documented in Section 5.1).

## Next Checks
1. **Benchmark across tasks:** Assemble a meta-dataset of NLP annotations (categorical, segmentation, continuous). Compute all applicable IAA metrics and correlate them with downstream performance or expert consensus to identify the most predictive metrics.
2. **Sensitivity simulations:** Systematically vary label prevalence, annotator count, and missingness in synthetic data. Quantify metric stability (e.g., κ‑paradox) to provide actionable thresholds for when to prefer alternatives like AC1 or γ.
3. **Parameter optimization:** For metrics with tunable parameters (Pk/WindowDiff window, ordinal weights, boundary tolerance), run grid searches on real annotation data to find values that maximize alignment with gold standards or minimize disagreement entropy.
