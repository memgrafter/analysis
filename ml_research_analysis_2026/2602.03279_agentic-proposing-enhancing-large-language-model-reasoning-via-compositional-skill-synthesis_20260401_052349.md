# Agentic Proposing: Enhancing Large Language Model Reasoning via Compositional Skill Synthesis

## Quick Facts
- **arXiv ID**: 2602.03279
- **Source URL**: https://arxiv.org/abs/2602.03279
- **Reference count**: 40
- **Primary result**: A 30B solver trained on only 11,000 synthetic trajectories achieves 91.6% on AIME25, rivaling GPT-5 and outperforming models with 20× more parameters.

## Executive Summary
Large language models require vast amounts of high-quality reasoning data, yet human annotation is costly and existing synthesis approaches trade off validity for difficulty. Agentic Proposing addresses this by framing synthetic trajectory generation as a goal-driven decision process. An agent dynamically composes modular reasoning skills through iterative internal reflection and tool-use, while Multi-Granularity Policy Optimization ensures precise, verifiable outputs.

Training a 30B solver on just 11,000 such trajectories yields 91.6% on AIME25, matching GPT-5 and outperforming models with twenty-fold more parameters. A 4B solver improves by +4.1 points on math benchmarks and +5.3 on cross-domain reasoning tasks, proving that minimal high-quality synthetic data can substitute for large human-curated datasets.

## Method Summary
Agentic Proposing treats reasoning data synthesis as a sequential decision problem. An agent equipped with a library of modular reasoning skills iteratively constructs solution trajectories. The agent decomposes a given problem into subgoals, selects relevant skills, and generates reasoning steps, optionally invoking external tools (e.g., calculators, code executors). An internal reflection phase critiques and revises the trajectory after each step, while an automated verifier checks for logical correctness. Invalid traces are filtered out, ensuring dataset quality.

The proposer model (Agentic-Proposer-4B) is trained via Multi-Granularity Policy Optimization (MGPO), which optimizes policies at multiple abstraction levels – from individual steps to full trajectories – to improve both correctness and coherence. This yields a generator that produces diverse, valid reasoning paths with very few seed examples.

## Key Results
- A 30B solver trained on 11,000 synthetic trajectories achieves 91.6% on AIME25, rivaling GPT-5 and outperforming models with 20× more parameters.
- A 4B solver gains +4.1 points on math benchmarks (MATH, GSM8K) and +5.3 points on cross-domain reasoning tasks.
- The approach demonstrates that small volumes of high-quality synthetic data can replace massive human-curated datasets.

## Why This Works (Mechanism)
Agentic Proposing works by converting trajectory synthesis into a goal-oriented decision process. The agent dynamically assembles modular reasoning skills – akin to building blocks – to address subproblems. Iterative internal reflection allows the agent to detect and correct errors mid-generation, while tool-use (e.g., calculators, code executors) provides reliable external computation. Together, these elements produce reasoning traces that are both diverse and verifiable. Multi-Granularity Policy Optimization further refines the agent by aligning short-term step generation with long-term trajectory success, leading to high-quality synthetic data even from minimal seed sets.

## Foundational Learning
- **Goal-driven decomposition**: Why needed: breaks complex problems into manageable subgoals, enabling focused skill application. Quick check: can the agent set intermediate objectives without external prompting?
- **Modular skill library**: Why needed: allows recombination of verified reasoning primitives across problems, increasing coverage and efficiency. Quick check: can each skill be independently validated and reused in different contexts?
- **Iterative reflection**: Why needed: provides a self‑correction mechanism to identify and fix logical errors during generation. Quick check: does the agent revise its output when an intermediate step is flagged as incorrect?
- **Tool integration**: Why needed: offloads deterministic computations (e.g., arithmetic, code) to reliable external modules, reducing internal hallucination. Quick check: are tool calls correctly invoked and their results seamlessly integrated?
- **Multi‑granularity policy optimization**: Why needed: optimizes at both step‑level and trajectory‑level, ensuring immediate correctness and global coherence. Quick check: does the policy improve both individual step accuracy and full‑trajectory success rates?

## Architecture Onboarding
**Component Map**: Agent -> SkillComposer -> TrajectoryGenerator -> Verifier -> MGPOLearner -> SyntheticDataset

**Critical Path**: (1) Agent receives a problem; (2) decomposes it into subgoals; (3) SkillComposer selects and sequences modular skills; (4) TrajectoryGenerator emits step‑by‑step reasoning, invoking tools as needed; (5) Verifier checks each step for correctness; (6) Valid trajectories are stored; (7) MGPOLearner updates the agent policy across granularities using the collected data.

**Design Tradeoffs**:
- Skill library size vs. selection efficiency: larger libraries increase coverage but raise retrieval cost and risk of irrelevant composition.
- Reflection depth vs. compute budget: more iterations improve correctness but increase generation latency.
- Verification strictness vs. dataset diversity: stricter checks ensure quality but may discard potentially useful, imperfect traces.

**Failure Signatures**:
- Invalid intermediate steps that pass automated verification (e.g., subtle logical gaps).
- Agent oscillation: repeated generation of similar invalid steps without progress.
- Overfitting to benchmark‑specific heuristics, leading to poor cross‑domain transfer.
- Excessive tool reliance causing brittle behavior when tools are unavailable.

**First Experiments**:
1. **Skill coverage test**: Feed the agent elementary math problems and measure the proportion of successfully completed trajectories after verification.
2. **Baseline comparison**: Train a 4B model on Agentic‑Proposing data vs. an equal‑sized self‑instruct dataset; evaluate on MATH and GSM8K.
3. **Reflection ablation**: Disable iterative reflection (single‑pass generation) and compare trajectory validity and downstream solver performance.

## Limitations
- The internal mechanism for modular skill representation and composition is underspecified, limiting reproducibility.
- Verification relies on automated checks that may accept flawed reasoning traces, risking noisy training data.
- Evaluation is confined to math benchmarks; generalizability to other reasoning domains remains uncertain.

## Confidence
- High: Small, high‑quality synthetic datasets substantially improve small models' reasoning performance (supported by consistent gains on multiple math benchmarks).
- Medium: The 30B solver’s 91.6% on AIME25 rivals GPT‑5 (confidence moderated by lack of direct GPT‑5 comparison and potential overfitting).
- Low: The approach can broadly replace human‑curated datasets across diverse tasks (evidence limited to mathematics).

## Next Checks
1. Independent Replication: Reproduce the 4B solver results using the published pipeline on MATH, GSM8K, and cross‑domain benchmarks, and compare with baselines.
2. Ablation Study: Isolate the impact of compositional skill synthesis by replacing it with standard data generation methods (e.g., self‑instruct) while keeping data size constant.
3. Cross‑Domain Generalization: Apply the full Agentic Proposing framework to a non‑math reasoning domain (e.g., logical deduction or scientific QA) and measure performance relative to existing synthetic data recipes.
