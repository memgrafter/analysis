# Build, Judge, Optimize: A Blueprint for Continuous Improvement of Multi-Agent Consumer Assistants

## Quick Facts
- **arXiv ID:** 2603.03565  
- **Source URL:** https://arxiv.org/abs/2603.03565  
- **Reference count:** 13  
- **Primary result:** MAMuT GEPA improved overall rubric pass rate from 77.1% to 84.7%, with gains of +12.0% in Safety & Compliance and +8.0% in Conversational Quality.

## Executive Summary
This paper tackles the challenges of evaluating and optimizing multi-turn interactions in multi-agent conversational shopping assistants. It introduces a four-domain evaluation rubric (Shopping Execution, Personalization, Conversation Quality, Safety) and a calibrated LLM-as-judge pipeline that achieves 91.4% human agreement. The authors compare two optimization strategies—Sub-agent GEPA (optimizing individual agent prompts) and MAMuT GEPA (jointly optimizing all agent prompts via multi-turn simulation)—on a held-out test set of 238 trajectories from a production grocery assistant. MAMuT GEPA substantially outperformed Sub-agent GEPA, raising the overall rubric pass rate from 77.1% to 84.7% and yielding particularly large gains in Safety & Compliance (+12.0%) and Conversational Quality (+8.0%).

## Method Summary
The method involves building a modular multi-agent grocery assistant with an orchestrator and specialized sub-agents (e.g., cart, search) that log full interaction traces. The core components are: (1) a four-domain binary evaluation rubric with weighted aggregation (Shopping Execution 50%, Personalization & Context 20%, Conversational Quality 10%, Safety & Compliance 20%); (2) an LLM-as-judge pipeline calibrated via GEPA to achieve 91.4% agreement with human annotators; (3) two optimization strategies: Sub-agent GEPA optimizes each agent’s prompt independently using micro-rubrics on held-out per-agent data, while MAMuT GEPA jointly optimizes all agent prompts by simulating full trajectories with a hybrid simulator (replaying logged user responses when actions match, else generating synthetic responses via a User Persona Agent) and scoring with the calibrated judge. Updates are accepted only if the held-out set improves and safety does not regress.

## Key Results
- Overall rubric pass rate: Sub-agent GEPA 77.1% → MAMuT GEPA 84.7%.
- Safety & Compliance domain improved by +12.0%.
- Conversational Quality improved by +8.0%.
- Calibrated LLM judge achieved 91.4% human agreement.

## Why This Works (Mechanism)

### Mechanism 1: Decomposing quality into orthogonal binary domains
**Claim:** Decomposing end-to-end shopping quality into four orthogonal, binary-check domains produces a stable, interpretable reward signal for optimization.  
**Mechanism:** The rubric converts subjective, multi-turn quality into deterministic pass/fail scores over observable trace artifacts (e.g., `selected_item_id` for cart completeness). This grounds evaluation in concrete system behavior. The domain weights (e.g., Shopping Execution 50%) aggregate these checks into a single scalar with clear business priority.  
**Core assumption:** The four domains sufficiently capture production failure modes for grocery CSAs, and binary checks are reliably distinguishable from the trace.  
**Break condition:** A new critical failure mode emerges that does not map to any existing binary check (e.g., novel safety risk), requiring rubric revision and destabilizing the reward signal.

### Mechanism 2: Calibrating the LLM judge via GEPA
**Claim:** Calibrating the LLM-as-judge prompt with GEPA against human annotations yields a high-agreement, automated evaluation pipeline that can replace human review for trajectory scoring.  
**Mechanism:** GEPA performs reflective prompt evolution to optimize the judge’s decision boundaries. The optimized prompt adds explicit grounding rules, edge-case heuristics, and stricter evidence requirements, reducing ambiguity.  
**Core assumption:** Human baseline represents the "true" quality signal; disagreements are due to judge ambiguity rather than task subjectivity.  
**Break condition:** Judge reliability degrades on out-of-distribution trajectories (e.g., new product categories, user slang), requiring re-calibration.

### Mechanism 3: Joint optimization via MAMuT simulation
**Claim:** Joint, system-level prompt optimization (MAMuT GEPA) over multi-agent bundles using trajectory-level simulation outperforms optimizing sub-agents in isolation because it discovers coordination incentives invisible to local rubrics.  
**Mechanism:** MAMuT optimizes a prompt bundle by simulating full trajectories and scoring with the calibrated judge. The "Replay-when-consistent" hybrid simulator maintains user intent fidelity while handling divergence via a User Persona Agent. This allows trading off performance across agents to maximize the global rubric, repairing interactional defects like context withholding.  
**Core assumption:** The simulator generates sufficiently realistic user responses to divergence, making the optimization gradient a valid proxy for production performance.  
**Break condition:** The simulator’s user responses become systematically misaligned with real user behavior for novel divergence patterns, causing overfitting to simulator quirks.

## Foundational Learning

### Multi-Agent System Coupling
**Why needed here:** Understanding why optimizing individual agents fails is central. The paper’s insight is that in tightly coupled systems (Orchestrator → Sub-agents), local improvements can be undermined by upstream coordination failures.  
**Quick check:** If the Search Agent returns perfect results but the Orchestrator fails to present them clearly to the user, does Sub-agent GEPA on the Search Agent fix the failure? Why?  
*Answer: No—the failure occurs in the Orchestrator; Sub-agent GEPA cannot address coordination deficits.*

### LLM-as-Judge Calibration
**Why needed here:** The optimization pipeline depends on a reliable, automated reward. This concept covers turning an LLM’s subjective judgment into a stable, binary scoring function aligned with human annotators through prompt engineering (GEPA) and grounding rules.  
**Quick check:** What is the risk of using a non-calibrated, "vanilla" LLM judge for prompt optimization, and how does the paper’s approach (binary checks, trace grounding) mitigate it?  
*Answer: A vanilla judge is ambiguous and inconsistent, leading to noisy gradients; binary checks and trace grounding reduce ambiguity, yielding a stable reward.*

### Trajectory-Level vs. Turn-Level Optimization
**Why needed here:** The contrast between Sub-agent GEPA (effectively single-turn, per-node) and MAMuT GEPA (multi-turn, full trajectory) defines the paper’s methodological contribution.  
**Quick check:** Why can’t you simply sum the scores of individually optimized sub-agents to predict end-to-end system performance?  
*Answer: Because inter-agent coordination effects can create emergent failures or improvements that are not captured by summing independent node scores.*

## Architecture Onboarding

### Component Map
System components: Orchestrator, Sub-agents (Cart, Search, Quantity-Adjust, etc.), Tool Layer (APIs, inventory, pricing, preference models), Evaluation Judge, Optimizer (GEPA/MAMuT), User Persona Agent. Interaction flow: User → Orchestrator → Sub-agents → Tool Layer → Orchestrator → response → User. For optimization: Optimizer modifies prompts; MAMuT simulator replays or generates user turns; full trajectories scored by Judge; updates accepted based on held-out metrics.

### Critical Path
1. User sends initial message.  
2. Orchestrator interprets intent and retrieves context.  
3. Orchestrator calls Sub-agent(s) sequentially.  
4. Sub-agents execute tools and return actions.  
5. Orchestrator validates actions, updates shared cart state, formulates response.  
6. User replies; loop back to step 2.  
7. At session end, full trace sent to Judge for scoring.

### Design Tradeoffs
- **Modularity vs. Coupling:** Modular sub-agents improve maintainability but create tight coupling via shared context window; Orchestrator prompt becomes critical.
- **Local vs. Global Optimization:** Sub-agent GEPA is cheaper and easier to debug but misses coordination effects; MAMuT captures emergent effects but is more expensive.
- **Simulator Fidelity vs. Scalability:** Replay-when-consistent balances realism (real user turns) with handling divergence (synthetic turns); over-reliance on synthetic turns risks simulator bias.

### Failure Signatures
- **Coordination Cascades:** One sub-agent’s verbose output floods context, causing another to miss critical data.
- **Context Contamination:** Orchestrator fails to prune outdated context, leading sub-agents to act on stale preferences.
- **Local Optima Trap:** Sub-agent GEPA improves a micro-rubric but harms another domain because the micro-rubric doesn’t penalize cross-agent harm.
- **Simulator Divergence:** User Persona Agent generates implausible responses to novel system actions, causing optimizer to overfit to simulator quirks.

### First 3 Experiments
1. **Judge Validation:** Run calibrated and baseline judges on 100 human-labeled traces; measure Cohen’s kappa per domain; expect calibrated ≥90% agreement.
2. **Optimization Strategy A/B Test:** On held-out 238 trajectories, run Sub-agent GEPA and MAMuT GEPA; compare overall rubric pass rate and per-domain gains; expect MAMuT > Sub-agent overall, with large Safety (+12%) and Conversational Quality (+8%) margins.
3. **Simulator Sanity Check:** For 50 synthetic user turns from divergence cases, have humans rate intent consistency (1–5) and Turing Test pass rate; expect >4.0 intent consistency and >70% Turing pass.

## Limitations
- Exact agent architectures, prompts, and context management are not disclosed, hindering direct replication.
- Simulator implementation details (NLI model, User Persona Agent design, GEPA hyperparameters) are unspecified.
- The four-domain evaluation rubric may not generalize beyond the grocery domain (e.g., lacks return/refund handling).

## Confidence
- Rubric stability & interpretability: Medium  
- Judge calibration (91.4% agreement): Medium-High  
- MAMuT superiority over Sub-agent GEPA: Medium

## Next Checks
1. **Judge OOD Stress Test:** Run calibrated judge on 100 out-of-distribution trajectories (new categories, slang) and measure agreement drop.
2. **Simulator Fidelity Audit:** Collect human ratings on 50 synthetic user turns for intent consistency (1–5) and Turing test pass rate; compare to paper’s thresholds.
3. **Cross-Domain Transfer:** Apply MAMuT GEPA to a different multi-agent shopping domain (e.g., travel booking) and compare to Sub-agent GEPA; expect similar gains if coupling mechanism generalizes.
