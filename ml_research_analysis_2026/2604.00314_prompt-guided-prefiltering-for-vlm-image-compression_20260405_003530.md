# Prompt-Guided Prefiltering for VLM Image Compression

## Quick Facts
- arXiv ID: 2604.00314
- Source URL: https://arxiv.org/abs/2604.00314
- Reference count: 37
- Primary result: Achieves 25-50% BD-rate reduction on standard codecs while maintaining identical VQA accuracy on VLM tasks.

## Executive Summary
This paper introduces a codec-agnostic prefiltering technique to optimize image compression for vision-language models (VLMs). Traditional codecs preserve all image details, many of which are irrelevant to a VLM’s textual query. The proposed module uses a lightweight TinyCLIP model to analyze the prompt and generate a spatial relevance map, which then guides a locally adaptive Gaussian filter: details in prompt-relevant areas are preserved, while irrelevant regions are aggressively smoothed. The prefiltered image is compressed with any standard or learned codec (JPEG, HEVC, VVC, Cheng’s) and sent to a cloud VLM for tasks such as visual question answering. Experiments on MME, MMBench, and SEEDBench using InternVL and LLaVA show average BD-rate reductions of 25–50% while maintaining identical VQA accuracy. Ablations confirm that the TinyCLIP-guided relevance map is essential; without it, bitrate increases by ~71% at the same accuracy.

## Method Summary
The method inserts a lightweight, trainable-free preprocessing module before any image encoder. First, the image is resized to a multiple of 224 pixels and divided into 224×224 tiles; the number of tiles is set to approximately 24 by selecting a stride from {224, 112, 56}. The text prompt undergoes preprocessing: instructional phrases are removed, common stop words are filtered out using NLTK, words are lemmatized, and if needed, lower-priority parts of speech (verbs, then others) are pruned to fit TinyCLIP’s context window. TinyCLIP (a distilled CLIP variant) then computes the similarity between the processed prompt and each tile; these raw scores are scaled by a learned logit scale and normalized so that their average equals 1. Overlapping tile scores are averaged within each stride×stride block, resulting in a low-resolution grid that is upsampled to a full-image relevance map. This map is transformed into a spatially varying Gaussian kernel standard deviation σ via an exponential function: σ = σ₁ * (σ_max/σ₁)^(1-score), with σ₁=0.2 and σ_max=3.0. An 11×11 Gaussian blur with the per-pixel σ (computed efficiently via separability and reflection padding) is applied to the original image, producing the prefiltered version.

The prefiltered image is then encoded with any off‑the‑shelf codec—JPEG, HEVC, VVC, or a learned model from CompressAI—without any modification to the codec itself. At the decoder, the reconstructed image is fed to the target VLM (e.g., InternVL3-9B or LLaVA-OV-7B) together with the original prompt. The VLM’s task accuracy (measured on VQA benchmarks) is unchanged compared to using an unfiltered compressed image, but the bitrate is significantly lower because the smoothing reduces high-frequency content in regions that do not affect the VLM’s decision. The entire pipeline is codec-agnostic, requiring no retraining of TinyCLIP or the codec.

## Key Results
- Average BD-rate reductions of 25–50% across JPEG, HEVC, VVC, and a learned codec when compared to baseline compression without prefiltering, while maintaining identical Visual Question Answering accuracy.
- Ablation study: Removing TinyCLIP guidance (using uniform scores) leads to ~71% higher bitrate at the same accuracy, proving the importance of prompt-driven relevance mapping.
- Prompt preprocessing contributes ~7.65% average BD-rate improvement for InternVL, as shown by the “w/o PP” ablation.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Prompt-driven spatial relevance maps from TinyCLIP guide locally adaptive smoothing, preserving task-critical details while allowing aggressive compression in irrelevant regions.
- **Mechanism:** The prefiltering module divides the image into tiles, uses a lightweight TinyCLIP model to compute text-image similarity scores for each tile based on the preprocessed prompt, aggregates these into a pixel-level score map, and maps scores to Gaussian filter sigma values (higher sigma for low scores). This creates a smoothed version of the image where irrelevant areas are low-pass filtered.
- **Core assumption:** The semantic alignment between TinyCLIP (a distilled CLIP variant) and the downstream VLM (e.g., InternVL, LLaVA) is sufficient for the relevance scores to correlate with regions important for the specific VQA task defined by the prompt.
- **Evidence anchors:** The abstract states that the module uses TinyCLIP to analyze the text prompt and generate a spatial relevance map that guides a locally adaptive Gaussian filter. Section III.C & III.E details the tile scoring, softmax normalization, and exponential sigma mapping: "σ=σ₁ (σₘₐₓ/σ₁)^(1−score)". The paper's own ablation (w/o TinyCLIP) is primary evidence for necessity.
- **Break condition:** If the TinyCLIP model's notion of relevance diverges significantly from the main VLM's, the prefiltering may remove details the VLM needs. Ablation shows removing TinyCLIP increases bitrate ~71% at same accuracy, suggesting the VLM is robust to mild uniform smoothing but loses efficiency without prompt guidance.

### Mechanism 2
- **Claim:** Because the prefiltering is a lossy preprocessing step applied before any standard or learned codec, it is codec-agnostic and enables bitrate reduction without modifying the encoder or decoder.
- **Mechanism:** The filtered image is fed to an off-the-shelf codec (JPEG, HEVC, VVC, Cheng learned codec). The smoothing reduces high-frequency content in irrelevant regions, which these codecs can represent more efficiently (fewer bits for flat/smooth areas). The VLM receives the reconstructed image, and the paper shows identical accuracy at lower bitrates.
- **Core assumption:** The VLM's task accuracy is robust to the low-pass filtering artifacts introduced in irrelevant regions, and the codec can capitalize on the reduced entropy in those regions.
- **Evidence anchors:** The abstract states it is codec-agnostic and can be applied before conventional and learned encoders. Section I says the prefiltering module operates as a plug-and-play preprocessor requiring no modifications. Section IV.A reports BD-rate reductions of 25-50% across all four codecs while maintaining VQA accuracy.
- **Break condition:** If the VLM is highly sensitive to smoothing in regions that appear irrelevant to TinyCLIP but are actually needed for fine-grained reasoning (e.g., subtle textures, background text), accuracy could drop. The paper maintains identical accuracy, suggesting this sensitivity is low for the tested VQA benchmarks.

### Mechanism 3
- **Claim:** Prompt preprocessing (stop-word removal, lemmatization, POS-based pruning) compresses the textual input to fit TinyCLIP's limited context window while preserving the essential query semantics for tile scoring.
- **Mechanism:** Instructional and common stop words are stripped. If still too long, words are prioritized (nouns > adjectives > verbs > others) and lowest-priority tokens are removed until the sequence fits TinyCLIP's context. This ensures the text embedding focuses on key concepts.
- **Core assumption:** The core task semantics (key nouns, adjectives, verbs) are sufficient for TinyCLIP to generate a relevance map aligned with the full, original prompt's intent.
- **Evidence anchors:** Section III.B describes the steps: non-essential instructional phrases are removed, NLTK is used for stop-word removal and lemmatization, and priority is assigned based on word type with iterative pruning. Section IV.B Ablation "w/o PP" (without prompt preprocessing) variant yields worse BD-rate (+7.65% for InternVL on average), indicating preprocessing contributes to efficiency, implying it helps TinyCLIP focus.
- **Break condition:** If the pruned tokens contain critical, low-frequency task specifications (e.g., negation, spatial prepositions, specific attributes), the relevance map could misalign. The paper does not test adversarial prompts where key terms are function words.

## Foundational Learning
- **Concept: Vision-Language Model (VLM) Inference Pipeline**
  - *Why needed here:* The entire system exists to optimize image transmission to a cloud VLM. Understanding that the VLM takes an image and a text prompt, processes the image with a visual encoder (e.g., ViT) into tokens, and then an LLM reasons over both modalities is essential. The prefiltering targets the input to the visual encoder.
  - *Quick check question:* If the VLM's visual encoder is a ViT that partitions the image into patches, how does our tile-based prefiltering (with stride) align or misalign with that patch grid?

- **Concept: Rate-Distortion Tradeoff in Image Compression**
  - *Why needed here:* The core evaluation is BD-rate reduction at constant task accuracy. This requires understanding that "distortion" is not pixel-wise MSE/PSNR but task accuracy (VQA score). The prefiltering intentionally introduces distortion (smoothing) in some regions, betting the VLM's distortion metric is insensitive to it.
  - *Quick check question:* Why might a codec like VVC achieve larger BD-rate savings (>47%) than JPEG (~28%) with the same prefiltering? (Answer: VVC's intra-prediction and transform coding can more efficiently represent the smoothed regions' reduced high-frequency content.)

- **Concept: Gaussian Scale-Space Filtering**
  - *Why needed here:* The adaptive Gaussian filter is the physical smoothing operation. Understanding that sigma (σ) controls the cutoff frequency (larger σ = more smoothing, lower spatial frequency preserved) is key. The exponential mapping from relevance score to σ is a design choice.
  - *Quick check question:* Why is a Gaussian kernel specifically chosen over, say, a bilateral filter? (Answer: Paper cites circular symmetry and guarantee of no spurious artifacts; also separable for fast implementation.)

## Architecture Onboarding
- **Component map:** Inputs (image, prompt) → Resize & Tile Extraction → Prompt Preprocessing → TinyCLIP (per-tile scoring) → Score Aggregation (stride grid) → Sigma Mapping (exponential) → Locally Adaptive Gaussian Filter → Codec Encode/Decode → VLM (output)
- **Critical path:** The image flows through tile extraction, scoring, aggregation, sigma mapping, filtering, then codec; the prompt flows parallel to tiles and is preprocessed before TinyCLIP. The VLM receives the final decoded image and original prompt.
- **Design tradeoffs:**
  - `tile_num` ↑ → finer-grained relevance map but higher TinyCLIP latency/memory; must match device capability.
  - `logit_scale` ↑ → sharper score distribution; affects concentration of preserved regions.
  - σ₁ vs σₘₐₓ: σ₁ (min sigma) should preserve details; σₘₐₓ (max sigma) must smooth irrelevant regions without destroying potentially useful structures.
  - TinyCLIP model size (23M/57M/120M): Larger may improve relevance accuracy but increases edge latency; 57M found optimal.
- **Failure signatures:**
  - Task accuracy drop at all bitrates: over-smoothing. Check σₘₐₓ too high or TinyCLIP misalignment.
  - No bitrate savings (BD-rate ≈ 0): prefiltering not smoothing. Check if scores uniformly near 1 (all regions marked relevant) – maybe prompt preprocessing failed or `logit_scale` too low.
  - High edge latency: `tile_num` too large; reduce or use smaller TinyCLIP.
  - Artifacts in reconstructed image: Gaussian kernel size fixed 11×11; if stride large, block boundaries may show. Increase overlap (reduce stride).
- **First 3 experiments:**
  1. Baseline replication: Run full VQA pipeline (e.g., InternVL + HEVC) without prefiltering. Establish rate-accuracy curve. Then add proposed prefiltering (with paper’s hyperparameters: `tile_num=24`, `logit_scale=20`, `σ₁=0.2`, `σₘₐₓ=3.0`, TinyCLIP-57M). Expect leftward shift; compute BD-rate.
  2. Ablation - TinyCLIP core: Replace TinyCLIP scoring with uniform scores (all 1) → fixed σ=σ₁ (mimics "w/o TinyCLIP"). Expect significant BD-rate penalty (~+70%). Confirms relevance map necessity.
  3. Codec generality test: Repeat experiment 1 with JPEG and VVC. Expect positive BD-rate savings for all, but magnitude may differ (larger for VVC). Validates codec-agnostic claim. If one codec shows no gain/loss, investigate rate-control interaction.

## Open Questions the Paper Calls Out
- **Open Question 1:** What is the optimal tile_num for different edge devices and VLMs, and how does it affect the bitrate-accuracy trade-off?
  - Basis in paper: Section III-A states tile_num should be selected according to application and device capabilities, but only tile_num=24 is experimented.
  - Why unresolved: No analysis of varying tile_num on computational cost and compression gains; optimal may vary with device and VLM.
  - What evidence would resolve: Evaluate rate-accuracy curves and runtime for tile_num values (12, 24, 48, 96) on representative hardware and multiple codec-VLM combinations.

- **Open Question 2:** Does the Gaussian kernel size affect prefiltering performance, and can a non‑fixed size improve compression efficiency?
  - Basis in paper: Section III‑E says Gaussian filter fixed to 11×11.
  - Why unresolved: Kernel size determines spatial support; a larger kernel might smooth more effectively without harming details, but unexplored.
  - What evidence would resolve: Compare rate-accuracy for kernel sizes (5×5, 11×11, 21×21) while keeping σ mapping identical, report BD-rate changes.

- **Open Question 3:** Can the prompt‑guided prefiltering transfer to other VLM tasks like image captioning or visual grounding, not just VQA?
  - Basis in paper: Exclusively evaluates VQA on MME, MMBench, SEEDBench; method described as general but not tested on other tasks.
  - Why unresolved: Different tasks emphasize different regions; prefiltering tuned for VQA might not preserve necessary details for captioning or detection.
  - What evidence would resolve: Run identical experiments on captioning (e.g., COCO) and grounding (e.g., RefCOCO) benchmarks, measuring accuracy and bitrate with and without prefiltering.

## Limitations
- Tile aggregation stride auto‑tuning and prompt preprocessing rules are underspecified, hindering exact replication.
- Cheng learned codec evaluation lacks configuration details (architecture, entropy model, rate points).
- The method’s effectiveness is only demonstrated on VQA datasets with two VLMs; extension to other tasks and VLM architectures remains open.
