# Pre-training LLM without Learning Rate Decay Enhances Supervised Fine-Tuning

## Quick Facts
- **arXiv ID**: 2603.16127
- **Source URL**: https://arxiv.org/abs/2603.16127
- **Reference count**: 40
- **Primary result**: Warmup-Stable-Only (WSO) pre-training without learning rate decay yields superior supervised fine-tuning (SFT) performance, improving averaged task scores by up to +1.1 points over decay-based schedulers for 8B models.

## Executive Summary
This paper challenges the conventional use of learning rate decay during large language model pre-training. Through extensive experiments with 1B and 8B parameter models across various pre-training regimes, the authors show that maintaining a constant learning rate after warmup (WSO) leads to better downstream performance after supervised fine-tuning (SFT), even though pre-training loss is higher. Analysis reveals that WSO results in flatter loss landscapes, which enhance adaptability. The findings suggest that standard LR decay, while minimizing pre-training loss, may hinder model portability to downstream tasks, advocating for WSO in practical deployments.

## Method Summary
The study compares several learning rate schedulers during pre-training: Warmup-Stable-Only (WSO) with no decay, and decay-based schedulers (Linear, Cosine, Warmup-Stable-Decay) with varying decay aggressiveness (α). Pre-training is conducted on 1B and 8B Llama 3 models using datasets like FineWeb-Edu, olmo-mix-1124, and dolmino-mix-1124 for up to 80k steps. After pre-training, models are fine-tuned for one epoch on the Tulu-3 SFT mixture, with a learning rate sweep per checkpoint to select the best model based on AlpacaEval. Key metrics include pre-training validation loss, zero-shot task accuracy, post-SFT average scores on AlpacaEval, TruthfulQA, and MMLU. Additionally, loss landscape sharpness is measured using Hutchinson’s trace estimator (Hessian trace) on pre-training and SFT validation sets.

## Key Results
- WSO pre-training consistently outperforms decay-based schedulers in post-SFT evaluation: for 8B models, WSO improves averaged task scores by up to +1.1 points over the best decay scheduler.
- Despite higher pre-training loss, WSO-trained models achieve better SFT performance across standard, mid-training, and over-training regimes.
- Loss landscape analysis shows WSO preserves flatter minima (lower Hessian trace) compared to sharper minima under decay, explaining enhanced adaptability.

## Why This Works (Mechanism)
Learning rate decay during pre-training minimizes pre-training loss by converging to sharp minima, which are less adaptable to new tasks. In contrast, WSO’s constant learning rate after warmup encourages exploration and lands in flatter regions of the loss landscape. Flatter minima generalize better to downstream tasks because they are less sensitive to parameter perturbations, making the model more robust when fine-tuned on new data. Thus, while decay optimizes for pre-training metrics, WSO optimizes for downstream portability by preserving model plasticity.

## Foundational Learning
- **Learning rate scheduling**: Governs step size during optimization; decay reduces LR over time to refine weights but may lead to sharp minima. *Why needed*: Controls convergence and generalization. *Quick check*: Does constant LR after warmup yield higher pre-training loss but better fine-tuning?
- **Supervised fine-tuning (SFT)**: Adapts pre-trained models to specific tasks via labeled data. *Why needed*: Bridges pre-training to downstream applications. *Quick check*: Does SFT performance correlate with pre-training LR scheduler choice?
- **Loss landscape flatness**: Measures sensitivity of loss to weight perturbations; flatter minima generalize better. *Why needed*: Explains model robustness. *Quick check*: Can Hessian trace distinguish WSO vs. decay minima?
- **Hessian trace estimation**: Computes sharpness via Hutchinson’s estimator; cheap approximation of eigenvalue sum. *Why needed*: Quantifies flatness efficiently. *Quick check*: Does trace align with generalization gaps?
- **AdamW optimizer**: Default for LLM training; decouples weight decay. *Why needed*: Stable training for large models. *Quick check*: Are AdamW hyperparameters identical across schedulers?
- **Pre-training vs. fine-tuning dynamics**: Pre-training learns general representations; fine-tuning adapts to tasks. *Why needed*: Highlights differing optimization goals. *Quick check*: Does pre-training LR affect fine-tuning convergence speed?

## Architecture Onboarding
Component map: Data → Pre-training (LR scheduler) → Checkpoint → SFT → Eval (AlpacaEval/TruthfulQA/MMLU) → Analysis (Sharpness)
Critical path: Pre-training with WSO/decay → SFT LR sweep → select best per pre-trained model → evaluate.
Design tradeoffs: WSO trades higher pre-training loss for better SFT; decay minimizes pre-training loss but harms adaptability. SFT LR sweep ensures fair comparison by selecting optimal LR per checkpoint.
Failure signatures: (1) Decay pre-training yields lower pre-training loss but worse SFT scores; (2) Sharpness measurements show higher Hessian trace for decay models; (3) SFT LR sweep fails to improve WSO models if reference model mismatched.

## Limitations
- Dataset versions and train/validation splits for FineWeb-Edu, olmo-mix-1124, and dolmino-mix-1124 are unspecified, risking evaluation variance.
- Pre-training token totals (350B/500B) conflict with computed totals from steps and batch sizes (~335B/1T); unclear which governs convergence.
- Sharpness measurement depends on Hutchinson’s estimator implementation; without open-sourced code, replication may yield divergent trends.

## Confidence
- WSO improves post-SFT performance vs. decay schedulers: **High**
- Flatter minima under WSO explains adaptability: **Medium**
- Recommendation to avoid LR decay for portable models: **Medium**
