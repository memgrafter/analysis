# SteerEval: A Framework for Evaluating Steerability with Natural Language Profiles for Recommendation

## Quick Facts
- **ArXiv ID:** 2601.21105
- **Source URL:** https://arxiv.org/abs/2601.21105
- **Reference count:** 29
- **Primary result:** All tested recommender pipelines achieve statistically significant steering (average ΔAUCt: +0.0476 increase, -0.0266 decrease); genres are steered more effectively than trigger warnings; embedding similarity rankers fail for decrease tasks; LLM scoring and full profile rewrites yield the strongest steering; adding oracle tag information drastically improves steering, highlighting LLM knowledge gaps, with minimal harm to accuracy for non-tagged items.

## Executive Summary
SteerEval introduces a benchmark and framework for evaluating the steerability of natural language profile-based recommenders, addressing a gap in assessing diverse, nuanced user control beyond simple attributes like genres. The framework uses movie tags (genres, trigger warnings) to test steering interventions—template append, LLM append, and rewrite—across different recommender configurations. Experiments show that all pipelines achieve significant directional shifts in item rankings toward or away from target tags, with LLM-based scoring and full rewrites being most effective. Notably, embedding-based rankers fail for decrease tasks, and augmenting item metadata with explicit oracle tag information substantially boosts steering, especially for niche tags, revealing LLM knowledge limitations. The study also finds that steering minimally impacts recommendation accuracy for items unrelated to the steered tags.

## Method Summary
The evaluation uses the MovieLens 25M dataset, filtering users with ≥100 ratings. For each user, the first 50 rated movies form the history, from which natural language profiles (paragraph and sentence lengths) are generated using Llama-3.1-8B-Instruct. Steering interventions modify these profiles to increase or decrease relevance for specific tags (19 genres, 75 trigger warnings after filtering). Candidate items (100 per user-tag pair) are ranked using either LLM scoring (predicting 0–5 ratings) or embedding similarity (with mxbai-embed-large-v1). Steering effectiveness is measured by ΔAUCt, the change in tag-specific AUC between original and steered rankings, with positive values indicating successful increase and negative values successful decrease. Statistical significance is tested via one-tailed paired t-tests across 940 tag-task combinations.

## Key Results
- All recommender pipelines achieve statistically significant steering, with average ΔAUCt of +0.0476 for increase tasks and -0.0266 for decrease tasks.
- Genres are steered more effectively than trigger warnings; embedding similarity rankers fail for decrease tasks (yielding positive ΔAUCt instead of negative), while LLM scoring and full profile rewrites produce the strongest steering effects.
- Adding oracle tag information to item metadata drastically improves steering, particularly for trigger warnings, indicating LLM knowledge gaps; steering minimally harms accuracy for non-tagged items.

## Why This Works (Mechanism)
**Mechanism 1:** Steering interventions (append/rewrite) modify the natural language profile to shift item rankings by altering the textual signal consumed by the ranking method. The profile text is a direct input; injecting language referencing a target tag changes semantic alignment between profile and item metadata, causing the ranker to prioritize relevant items. The ranking method must interpret edits as meaningful preference shifts rather than noise. Evidence: The paper shows all pipelines achieve significant steering and defines interventions in Section 3.2.

**Mechanism 2:** Embedding-based rankers fail for decrease steering because they conflate positive and negative sentiment toward a tag. Text embeddings map semantically similar phrases to nearby vectors, so profiles stating "avoid horror" and "love horror" both become closer to horror-related item vectors than a neutral profile. The similarity ranker cannot isolate negative sentiment, causing relevant items to ascend despite a decrease intent. Evidence: Abstract notes embedding ranker failure; Section 4.2 hypothesizes the mechanism.

**Mechanism 3:** Augmenting item metadata with explicit oracle tag information drastically improves steering for niche topics (trigger warnings) by compensating for LLM world knowledge gaps. The LLM scorer relies on item metadata to infer tag relevance; for obscure tags, the LLM may not know a movie contains a specific trigger. Adding explicit annotations provides a direct signal. Evidence: Abstract highlights LLM knowledge gaps; Section 4.4.2 shows oracle ranker performs significantly better.

## Foundational Learning
- **Concept: Natural Language Profiles as Steerable Representations**
  - Why needed here: Unlike latent vectors, natural language profiles are human-readable and editable, enabling direct user control. This shifts design goals from optimizing vector similarity to maintaining textual semantics under edits.
  - Quick check question: If a user edits their profile text, what properties must the ranking method preserve to ensure the edit meaningfully changes recommendations rather than adding noise?

- **Concept: Steering Interventions as Profile Edit Strategies**
  - Why needed here: Different interventions (append template, LLM append, rewrite) vary in user effort and effectiveness. Recognizing their trade-offs informs interface design—e.g., low-effort appends may suffice for well-known tags.
  - Quick check question: Why might a full profile rewrite yield stronger steering than appending a single sentence, and what risk does that introduce?

- **Concept: Tag-based AUC (AUCt) and ΔAUCt as Steering Metrics**
  - Why needed here: These metrics isolate steering impact from general recommendation accuracy by measuring rank changes specifically for items relevant/irrelevant to the steered tag. ΔAUCt quantifies directional shift.
  - Quick check question: How does ΔAUCt differ from traditional ranking metrics like NDCG, and why is it necessary for evaluating steerability?

## Architecture Onboarding
- **Component map:** Profile Creation -> Steering Intervention -> Item Ranking -> Evaluation
- **Critical path:** User history → Profile Creation → Original Profile → Steering Intervention → Steered Profile → Item Ranking (for both profiles) → Evaluation (ΔAUCt).
- **Design tradeoffs:**
  - *Ranking method:* Embedding similarity is fast but fails for decrease tasks; LLM scoring is flexible but slower and costlier.
  - *Intervention effort:* Appending a template is low-effort but less effective; full rewrite is most effective but requires more user effort.
  - *Profile length:* Shorter profiles may be less robust to modifications; longer profiles provide more context but risk conflicting information.
- **Failure signatures:**
  - Embedding ranker: ΔAUCt positive for decrease tasks (items ascend when they should descend).
  - LLM refusal: Steering for certain trigger tags rejected by safety guardrails.
  - Low ΔAUCt for niche tags: Without oracle metadata, trigger warning steering shows smaller effects.
- **First 3 experiments:**
  1. Baseline steering test: Use default pipeline (paragraph profile, LLM ranking, template append) on 5 genre tags (increase/decrease). Verify ΔAUCt >0 (increase) or <0 (decrease) with statistical significance.
  2. Embedding ranker failure demonstration: Run same as Experiment 1 but with embedding ranking. Observe ΔAUCt >0 for decrease tasks, confirming failure.
  3. Oracle augmentation validation: Add oracle tag info to item metadata for trigger warnings. Re-run Experiment 1 on 5 trigger tags. Expect substantively larger |ΔAUCt| compared to non-oracle condition.

## Open Questions the Paper Calls Out
1. How does steerability quantitatively differ between well-known topics (genres) and nuanced topics (trigger warnings), and what specific properties (e.g., semantic specificity, training data prevalence) drive this difference?
2. What is the practical trade-off between user effort and steering effectiveness for different intervention methods, and is the increased effectiveness of full rewrites worth the higher user cost?
3. Why do embedding-based rankers catastrophically fail on decrease steering tasks, and can alternative embedding architectures achieve competitive decrease steering without LLM scoring?
4. How can we practically augment item metadata to mitigate LLM knowledge gaps for niche topics, and which augmentation strategies (e.g., automatic tag extraction, knowledge graph linking) yield the best balance of improved steerability and scalability?
5. How does sequential steering—where a user applies multiple, potentially conflicting edits over time—impact long-term recommendation accuracy, profile coherence, and steerability durability?

## Limitations
- The exact list of retained trigger tags (75 out of 128) is unreported, requiring reconstruction via the paper’s filtering criterion.
- Precise wording of "stronger" vs. "weaker" emphasis templates in Table 4 is unspecified.
- Evaluation is restricted to one dataset (MovieLens) and one LLM (Llama-3.1-8B), limiting generalizability; LLM safety refusals may bias the tag set; the oracle augmentation is artificially unrealistic.

## Confidence
- All pipelines achieve significant steering: **High**
- Embedding rankers fail for decrease tasks: **Medium-High**
- Oracle metadata drastically improves steering: **High**
- Generalizability beyond movies/Llama: **Low**

## Next Checks
1. **Tag-filtering replication:** Re-derive the 75 trigger tags by applying the >25% refusal/misinterpretation filter to the initial 128-tag set using the exact intervention prompts.
2. **Cross-domain test:** Apply SteerEval to a non-movie domain (e.g., books or news) with domain-specific tags to test robustness of steering patterns.
3. **Multi-LLM comparison:** Repeat key experiments with at least two additional LLMs (e.g., GPT-4, Claude) to assess whether embedding failure and oracle gains generalize beyond Llama.
