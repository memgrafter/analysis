# Reward Prediction with Factorized World States

## Quick Facts
- arXiv ID: 2603.09400
- Source URL: https://arxiv.org/abs/2603.09400
- Reference count: 40
- Primary result: StateFactory achieves zero‑shot EPIC distance 60% lower than VLWM‑critic and 8% lower than LLM‑as‑a‑Judge, and improves planning success rates by +21.64% on AlfWorld and +12.40% on ScienceWorld.

## Executive Summary
Agents need accurate reward signals for planning, but supervised reward models overfit to training domains, limiting generalization. This paper proposes StateFactory, which transforms unstructured text observations into hierarchical object‑attribute world state representations using language models. Rewards are computed as semantic similarity between factorized current and goal states. Evaluated on RewardPrediction, a new benchmark with 2,454 trajectories across five domains, StateFactory achieves zero‑shot EPIC distance 60% lower than VLWM‑critic and 8% lower than LLM‑as‑a‑Judge, while supervised models show 138% increased error on novel domains. The superior reward quality yields planning improvements of +21.64% on AlfWorld and +12.40% on ScienceWorld.

## Method Summary
StateFactory is a zero‑shot reward predictor for text‑based environments. It processes raw textual observations through three modules: (1) State Extraction, which parses the observation into a set of objects and their attributes using an LLM; (2) Goal Interpretation, which dynamically updates the goal state by grounding the language instruction in the observed objects; and (3) Hierarchical Routing, which computes a dense reward by aligning current and goal states via object‑level matching and attribute similarity using a text embedding model. The system runs recurrently, updating state and goal at each timestep without any training. Ablations highlight the importance of fine‑grained object‑attribute factorization and a reasoning‑capable LLM for strong generalization.

## Key Results
- Zero‑shot EPIC distance reduced by 60% compared to VLWM‑critic and by 8% compared to LLM‑as‑a‑Judge.
- Supervised reward models exhibit a 138% increase in error on novel domains, underscoring overfitting.
- Integration with planning agents yields +21.64% improvement on AlfWorld and +12.40% on ScienceWorld success rates.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Factorizing world states into hierarchical object‑attribute structures reduces task‑irrelevant noise and disentangles attributes, enabling more precise reward estimation across domains.  
- **Mechanism**: The state extraction module (_f_state_) recursively refines raw observations into a set of object instances, each with an identity and a set of attribute key‑value pairs. This filters out irrelevant details and isolates the semantic factors that directly influence progress toward the goal.  
- **Core assumption**: Task progress is determined by a small set of object‑level attribute changes; unstructured text contains abundant distractors that obscure these changes.  
- **Evidence anchors**:  
  - [abstract]: The abstract states that StateFactory “transforms unstructured observations into a hierarchical object‑attribute structure” and that the “compact representation structure… enables strong reward generalization capabilities” (lines 1‑3).  
  - [section]: Section 3.2.1 defines the recurrent state extraction process; Section 4.3 (Figure 5a) reports EPIC distance reductions when moving from raw observations (0.57) to object‑attribute states (0.30).  
  - [corpus]: “Flow Factorized Representation Learning” (ID 236641) supports the principle that factorized representations capture ground‑truth factors of variation, providing a theoretical foundation for disentanglement. Direct empirical evidence for reward prediction is from this paper.  
- **Break condition**: If task progress depends on holistic scene configurations (e.g., spatial layout) that cannot be decomposed into independent object attributes, the factorization loses necessary contextual information, causing reward misestimation.

### Mechanism 2
- **Claim**: Dynamic goal interpretation—iteratively refining the goal state using current observations—prevents the “illusion of progress” that arises from static, pre‑defined goal representations.  
- **Mechanism**: The goal interpretation module (_f_goal_) updates the goal state at each timestep by combining the initial goal description, the previous goal state, and the current world state. This grounds abstract instructions in concrete objects as they appear and incorporates intermediate milestones from multi‑step tasks.  
- **Core assumption**: Goal descriptions are often ambiguous (e.g., “put the thing on the table”) and must be anchored to observed entities; a fixed initial interpretation may become misaligned as the environment evolves.  
- **Evidence anchors**:  
  - [abstract]: The abstract describes “dynamic goal state” and “iterative, state‑aware process” (Section 3.2.2).  
  - [section]: Section 3.2.2 details the dynamic update; Section 4.3 (Figure 5b) shows that the online dynamic goal (EPIC 0.30) remains close to the offline oracle (0.28), confirming robustness.  
  - [corpus]: “Learning telic‑controllable state representations” (ID 152230) distinguishes descriptive (what is) from prescriptive (what should be) state aspects, aligning with the need to ground prescriptive goals dynamically.  
- **Break condition**: If goals are truly static and fully specified upfront, dynamic updates may introduce drift or spurious modifications, especially when observations are noisy or incomplete.

### Mechanism 3
- **Claim**: Hierarchical routing—computing reward by matching objects and attributes under a joint consistency constraint—yields a robust progress signal that avoids false positives from superficial text similarity.  
- **Mechanism**: For each goal object, the system searches the current state for the best matching object, scoring both identity (object type similarity) and attribute satisfaction (value similarity). A multiplicative joint score ensures that correct object identity is necessary for attribute matches to contribute; the final reward averages scores across all goal objects.  
- **Core assumption**: Reward should reflect both the presence of correct entities and their desired states; coincidental attribute matches on wrong objects should not count as progress.  
- **Evidence anchors**:  
  - [abstract]: The abstract describes rewards as “estimated naturally as the semantic similarity between the current state and the goal state under hierarchical constraint.”  
  - [section]: Section 3.2.3 presents the full hierarchical routing (Eqs. 7‑9). Ablation in Figure 5a shows that object‑attribute factorization (with hierarchical routing) outperforms object‑centric (which entangles attributes), confirming the benefit of disentangled matching.  
  - [corpus]: Related work on compositional RL (e.g., “A Unified Theory of Compositionality, Modularity, and Interpretability in MDPs”, ID 38574) explores structured value functions, but direct empirical evidence for hierarchical routing in reward prediction is primarily from this paper.  
- **Break condition**: If objects are not consistently identifiable (e.g., due to aliases, missing references, or segmentation errors), identity matching fails to align goal and current objects, causing the reward to ignore critical attribute changes.

## Foundational Learning
### Concept: Goal‑Augmented Markov Decision Process (GA‑MDP)
- **Why needed here**: The paper formulates reward prediction within a GA‑MDP, where the reward depends on both the state and a language goal. This framework justifies conditioning reward models on goals and interpreting states relative to them.  
- **Quick check question**: In a GA‑MDP, how does the reward function differ from a standard MDP, and what implications does this have for representation learning (e.g., _φ_ mapping goals to states?)  

### Concept: Semantic Similarity via Embeddings
- **Why needed here**: StateFactory computes reward as semantic similarity between factorized states and goals using text embeddings. Understanding embedding properties (e.g., cosine similarity, paraphrase robustness) is essential to interpret why this works and its limitations.  
- **Quick check question**: Why might direct text similarity (e.g., BLEU) between raw observations and goals be insufficient for dense reward prediction, and how does embedding‑based similarity address these issues?  

### Concept: Object‑Centric Representations
- **Why needed here**: The method builds an object‑level decomposition; knowing the trade‑offs between object‑centric and holistic representations clarifies why factorization aids generalization (e.g., mitigating noise, enabling systematic recombination).  
- **Quick check question**: What are the advantages and potential pitfalls of using object‑centric representations compared to end‑to‑end learned features for cross‑domain reward prediction?

## Architecture Onboarding
### Component map:
- **Inputs**: Textual goal description, action‑observation trajectory (history), optional previous state/goal summaries.  
- **Core modules**:  
  - *State Extraction* (f_state): Recurrent LLM‑based parser that converts raw observations into a set of {object: {attribute: value}} structures.  
  - *Goal Interpretation* (f_goal): Recurrent LLM that updates the goal state representation based on the goal description and current context.  
  - *Hierarchical Routing*: Aligns objects between current state and goal state, computes attribute‑wise semantic similarity, and aggregates to produce a scalar reward using an embedding model (e.g., all‑MiniLM‑L6‑v2).  
- **Supporting tools**: Large language model (e.g., gpt‑oss‑20b) for extraction/interpretation; a lightweight text‑embedding model for similarity computation.  
- **Output**: Dense reward estimate _r̂_t_ at each timestep.

### Critical path:
1. **Per‑timestep processing**: Raw observation _o_t_ and previous state/goal are fed into _f_state_ to produce factorized current state _ŝ_t_.  
2. **Goal update**: _f_goal_ ingests the goal description, previous goal state _ĝ_{t‑1}_, and current state _ŝ_t_ to produce updated goal state _ĝ_t_.  
3. **Reward computation**: Hierarchical routing aligns objects between _ŝ_t_ and _ĝ_t_, computes attribute‑wise semantic similarity, and averages to yield _r̂_t = sim(ŝ_t, ĝ_t)_.  
4. **Downstream use**: The reward guides planning (e.g., ranking actions in ReAct or as heuristic in MCTS with a world model).

### Design tradeoffs:
- **LLM vs. specialized extractors**: LLMs offer flexibility in parsing diverse text but are slow and costly; smaller fine‑tuned models could be more efficient but might sacrifice generalization across domains.  
- **Factorization granularity**: Finer (object‑attribute) granularity captures subtle state changes and reduces attribute interference, but increases parsing complexity and may miss holistic context.  
- **Dynamic vs. static goals**: Dynamic goals adapt to observed entities and intermediate milestones, improving robustness; however, they risk over‑fitting to noise or drifting from the true goal if the LLM makes erroneous updates.  
- **Embedding choice**: Discriminative embeddings (trained on NLI) yield higher alignment precision but may be domain‑specific; generic embeddings are broader but less sensitive to fine‑grained state differences.

### Failure signatures:
- High EPIC distance on RewardPrediction benchmark (e.g., >0.5 average) indicates poor alignment with ground‑truth progress.  
- Ablation degradation: Removing factorization (using raw text) leads to a significant jump in EPIC distance (Fig. 5a: 0.57 vs 0.30).  
- Planning utility drop: When integrated into ReAct, success rate improvement falls below 5% (e.g., on AlfWorld), suggesting reward quality is insufficient to guide decisions.  
- Goal divergence: In dynamic interpretation, the evolving goal state compares poorly to an oracle final state (increased gap beyond the 0.02 reported in Fig. 5b), indicating mis‑grounding.

### First 3 experiments:
1. **Main evaluation on RewardPrediction**: Compare zero‑shot StateFactory against supervised reward models and LLM‑as‑a‑Judge, reporting EPIC distance across five domains (Table 1).  
2. **Ablation on representation granularity**: Systematically vary state structure (raw, textual, object‑centric, object‑attribute) to quantify the impact of factorization (Figure 5a).  
3. **Utility for agent planning**: Integrate StateFactory‑derived rewards into ReAct and MCTS with a world model, showing success rate gains on AlfWorld (+21.64%) and ScienceWorld (+12.40%) (Table 2, Section 4.4).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can the factorization‑based state representation in StateFactory be extended to continuous control and visual domains to enable accurate reward prediction for low‑level planning?
- **Basis in paper**: [explicit] The authors state that extending from low‑level continuous planning to high‑level language‑based planning "remains an open challenge."
- **Why unresolved**: StateFactory was evaluated only on text‑based environments; its applicability to continuous or visual state spaces is unknown.  
- **What evidence would resolve it**: Implement StateFactory on continuous control benchmarks (e.g., robotic manipulation) and demonstrate reward accuracy and planning improvements.

### Open Question 2
- **Question**: Can state factorization be performed efficiently without relying on large, computationally expensive language models?
- **Basis in paper**: [inferred] The ablation shows performance scales with model size and reasoning capability; the method uses gpt‑oss‑20b, indicating a dependency on scale.
- **Why unresolved**: The paper does not explore more efficient alternatives, leaving open whether smaller or specialized models can achieve comparable factorization quality.  
- **What evidence would resolve it**: Develop and evaluate a distilled or lightweight factorizer that maintains accuracy on RewardPrediction, or analyze trade‑offs between model size and performance.

### Open Question 3
- **Question**: Why do supervised reward models overfit to training domains, and how can we design architectures that generalize to novel tasks?
- **Basis in paper**: [inferred] Supervised models exhibit a 138% increase in error on unseen domains, indicating poor generalization.  
- **Why unresolved**: The paper does not analyze the underlying causes nor propose remedies beyond moving to zero‑shot methods.  
- **What evidence would resolve it**: Conduct diagnostic studies probing supervised models' representations across domains and test architectural modifications (e.g., contrastive pretraining, domain invariance) on RewardPrediction.

### Open Question 4
- **Question**: Is the simple averaging of object‑level alignment scores in StateFactory optimal for aggregating task progress, or could learned weighting improve performance?
- **Basis in paper**: [inferred] The reward is computed as the mean of maximum matching scores without learning to weight different objects or attributes.  
- **Why unresolved**: The design choice is not justified beyond intuition and no learned aggregation is compared.  
- **What evidence would resolve it**: Implement a parametric aggregation (e.g., attention over object contributions) and evaluate whether it reduces EPIC distance on the benchmark.

## Limitations
- Reliance on LLM‑based parsers: brittle to observation noise or domain shifts.  
- Evaluation limited to five text‑based environments; generalization to other domains (continuous control, vision) is unproven.  
- Dynamic goal interpretation may drift if the LLM misinterprets subgoals.  
- Dependence on the specific embedding model (all‑MiniLM‑L6‑v2); sensitivity not fully explored.

## Confidence
