# The Optimal Token Baseline: Variance Reduction for Long-Horizon LLM-RL

## Quick Facts
- **arXiv ID:** 2602.07078
- **Source URL:** https://arxiv.org/abs/2602.07078
- **Reference count:** 40
- **Primary result:** The Optimal Token Baseline (OTB) enables stable, token-efficient RL for long-horizon LLMs, matching large group baselines (N=32) with only N=4 and achieving SOTA on AIME25, AIME24, AMC23, and MATH500.

## Executive Summary
Long-horizon reinforcement learning (RL) for large language models (LLMs) suffers from training collapse due to exploding gradient variance. Existing baselines, such as value models or group means, fail to account for per-token heterogeneity or are computationally expensive and acausal. This paper introduces the Optimal Token Baseline (OTB), a causally derived, token-level variance reduction method. OTB weights each token by its realized energy—the cumulative gradient norm up to that point—and uses a Logit-Gradient Proxy to compute this efficiently via forward passes only. This yields stable training, drastic token savings (66-68%), and state-of-the-art performance on mathematical reasoning benchmarks, scaling reliably to 16k contexts and 14B models.

## Method Summary
OTB operates within the on-policy RL framework. For each token position *t* in a group of *N* sampled responses, it computes a baseline *B_t* as a weighted average of reward-to-go *G_t*, where weights are cumulative sums of per-token proxy energies ˆ*W_t*. The proxy energy ˆ*w_t* for a token is derived from its output probability: ˆ*w_t* = 1 − 2π(*y_t*) + ‖π_t‖², intended to approximate the squared gradient norm of the logit. This design is causal (using only past tokens), dynamic (a distinct baseline per position), and efficient (no extra backward passes). The advantage *A_t = G_t − B_t* then drives the policy gradient update.

## Key Results
- OTB prevents training collapse and matches the performance of large group-mean baselines (N=32) while using only N=4 group size, reducing token consumption by 66-68%.
- Sets new SOTA on AIME25 (30.31), AIME24 (37.29), AMC23 (85.08), and MATH500 (93.43).
- Scales effectively to 16k token contexts and 14B parameter models, demonstrating robustness to long horizons and large scales.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Weighting each token by its accumulated gradient norm (realized energy) reduces variance by accounting for token heterogeneity in a causal manner.
- **Mechanism:** The gradient variance for a token depends on accumulated stochasticity from prior tokens. OTB computes a baseline *B_t* that weights *G_t* by the cumulative sum of squared gradient norms up to *t*, *W_t*. This downweights contributions from high-uncertainty (high-energy) token sequences, stabilizing updates. The core assumption is that *W_t* is a stable proxy for a sequence's accumulated instability at step *t*.
- **Evidence anchors:** Abstract defines realized energy *W_t*; Section 3 defines it and Figure 4 shows energy profiles. Neighboring works like "Trust Region Masking..." and "Shrinking the Variance..." address instability but lack token-level mechanisms.
- **Break condition:** If the relationship between *W_t* and variance contribution is non-monotonic or if future gradient norms (approximated by *W_t*) do not correlate with the eventual variance impact of current tokens.

### Mechanism 2
- **Claim:** The Logit-Gradient Proxy (‖δ_t‖²) enables efficient OTB computation by approximating parameter gradient norms using only forward-pass outputs.
- **Mechanism:** For Transformers, ‖∇_W *J*‖_F ∝ ‖δ_t‖ · ‖h_t‖. RMSNorm keeps ‖h_t‖ constant, so ‖δ_t‖² (computable from token probabilities π_t) proxies the gradient norm. The proxy formula is: ‖δ_t‖² = 1 − 2π(*y_t*) + ‖π_t‖².
- **Evidence anchors:** Abstract introduces the proxy; Section 5.3 derives the proportionality and argues for constant ‖h_t‖; Section 4.1 Proposition 4.2 shows the closed-form.
- **Break condition:** If the architecture deviates from RMSNorm (e.g., LayerNorm) or gradient propagation is anisotropic, the proportionality may break.

### Mechanism 3
- **Claim:** OTB's dynamic, token-specific baselines capture temporal variations in gradient variance better than static or group-level baselines, as the optimal baseline evolves over generation steps.
- **Mechanism:** Unlike a single global baseline (OGB) or group-mean baselines that assign the same value to all tokens, OTB computes *B_t* for each *t*. This adapts to the changing risk profile of the sequence—e.g., weighting low-energy early steps differently than high-energy late steps—using only past information (causal).
- **Evidence anchors:** Abstract notes dynamic assignment; Section 4 Theorem 4.1 gives the formula; Figure 7 compares advantage distributions; Section 5.2 shows a strictly positive variance gap when comparing objectives.
- **Break condition:** If token-level variance contributions were homogeneous across time (i.e., *W_t* did not correlate with variance impact at *t*), dynamic baselines offer no advantage over static ones.

## Architecture Onboarding
- **Component map:**
  LLM Policy Network (θ) -> Rollout Engine -> Reward Calculator -> Energy Calculator (ˆw_t) -> Cumulative Energy Aggregator (ˆW_t) -> OTB Baseline Module (B_t) -> Advantage Calculator (A_t) -> Policy Gradient Update.

- **Critical path:**
  1. Sample N rollouts from current policy.
  2. For each token, compute forward pass to get π_θ(*y_t*|prefix) and proxy energy ˆw_t.
  3. Accumulate ˆW_t per sequence.
  4. For each token position *t*, aggregate ˆW_t^{(i)} and G_t^{(i)} across the group to compute B_t.
  5. Compute advantage A_t = G_t − B_t.
  6. Backward pass on ∇_θ log π_θ to get gradient weighted by A_t.
  7. Update θ via Adam.

- **Design tradeoffs:**
  - Group size (N): Larger N improves baseline accuracy but increases rollout cost. OTB aims for high performance with small N=4 vs. standard N=32.
  - Proxy vs. true energy: Logit-Gradient Proxy (no extra cost) vs. true ‖s_t‖² (requires per-token backward pass). Proxy trades some accuracy for massive efficiency.
  - Causal vs. acausal: Using cumulative *W_t* (causal) vs. total *W_T* (acausal). The paper shows *W_t* is sufficient under gradient consistency.
  - Static vs. dynamic: Per-token *B_t* versus a single *B* per sequence. Dynamic is more expressive but requires storing *W_t* for each position.

- **Failure signatures:**
  - Gradient norm spikes despite OTB: indicates realized energy *W_t* is not tracking variance; likely miscalibrated proxy ˆw_t.
  - High KL divergence between rollout and train policies: suggests OTB isn't preventing policy drift; check stability of ˆw_t distribution.
  - Response length explosion/collapse: OTB should stabilize length; large swings indicate poor baseline adaptation.
  - Performance degrades with increasing horizon: may break gradient consistency assumption.
  - Sharp performance drop when reducing group size below N=4: group statistics become too noisy.

- **First 3 experiments:**
  1. **Comparison against baselines on AIME25:** Run full on-policy RL on Qwen3-8B with GRPO, RLOO, OPO, OGB, OTB (N=16). Track gradient norm and AIME25 score. Expected: OTB shows smooth gradient norm and highest final score; others collapse.
  2. **Group size ablation:** Fix OTB, vary N in {4, 8, 16, 32}. Measure final AIME25 score and total tokens consumed. Expected: OTB with N=4 matches N=32 performance, confirming token efficiency.
  3. **Logit-Gradient Proxy validation:** Replace OTB's ˆw_t with sequence length (Length Proxy) within same OTB framework. Train on AIME24. Expected: Length Proxy variant collapses early; true Logit-Gradient Proxy sustains stability, proving proxy efficacy.

## Open Questions the Paper Calls Out
- **Open Question 1:** Does OTB generalize to tasks beyond mathematical reasoning, such as search engines or open-domain dialogue?
  - **Basis:** Conclusion states future work will explore stability on more tasks.
  - **Why unresolved:** Only evaluated on math benchmarks with rule-based rewards.
  - **Resolution evidence:** Experiments on diverse tasks with varying reward sparsity, measuring training stability and final performance.

- **Open Question 2:** How robust is the Logit-Gradient Proxy to architectural variations (e.g., models without RMSNorm)?
  - **Basis:** Proxy justification assumes RMSNorm and isotropic gradient propagation.
  - **Why unresolved:** Theoretical derivation relies on specific Transformer properties; validity for other architectures unverified.
  - **Resolution evidence:** Test OTB across models with LayerNorm/no norm; correlate logit gradient norms with true parameter gradient norms via backward passes.

- **Open Question 3:** Is the Gradient Consistency approximation (positive cross-temporal gradient correlations) valid under dense or shaped rewards?
  - **Basis:** Central to OTB derivation in Appendix C.3; based on empirical observation.
  - **Why unresolved:** Might fail when token advantages are less correlated (e.g., dense rewards).
  - **Resolution evidence:** Compute actual gradient correlations in trajectories from sparse vs. dense reward tasks and quantify approximation error.

- **Open Question 4:** Can OTB maintain variance reduction at extreme scales (100k tokens, 100B parameters)?
  - **Basis:** Paper tests up to 16k tokens and 14B models.
  - **Why unresolved:** Variance dynamics at extreme scales unexplored; weighting mechanism may behave differently.
  - **Resolution evidence:** Extend experiments to larger contexts/models, monitoring gradient norms, collapse rates, sample efficiency.

## Limitations
- OTB assumes constant hidden state norm due to RMSNorm; this may not hold for other normalizations (e.g., LayerNorm).
- Logit-Gradient Proxy accuracy depends on isotropic gradient propagation; anisotropic behavior could degrade correlation with true gradient norms.
- Reward design for tool-integrated reasoning (TIR) is underspecified, hindering full reproduction.
- Evaluation details (training steps, checkpoint selection) are not fully disclosed, potentially affecting reported SOTA numbers.
- Memory usage scales with context length as per-token cumulative energies must be stored, limiting practicality beyond 16k tokens.

## Confidence
- **OTB reduces variance and stabilizes long-horizon RL:** High (theoretical derivation and strong empirical collapse of baselines).
- **Logit-Gradient Proxy accurately estimates gradient norm:** Medium (validated on RMSNorm models but not alternatives; proxy may falter if hidden state norm varies).
- **Token efficiency (N=4 matching N=32):** High (consistent across benchmarks and ablations).
- **Scalability to 16k contexts and 14B models:** Medium (limited experiments; no stress tests at extreme scales).

## Next Checks
1. **Proxy vs. true gradient correlation:** On Qwen3-8B and a non-RMSNorm model (e.g., Llama), compute correlation between ˆw_t and actual per-token gradient norm (via backward pass) across 100 random sequences. Expect *r* ≥ 0.9 for RMSNorm; lower correlation indicates proxy breakdown.
2. **Causal weighting necessity:** Ablate OTB's cumulative energy *W_t* by replacing it with total sequence energy *W_T* (acausal) on AIME24 with 12k-token responses. Compare gradient norm trajectories and final accuracy; OTB should show strictly lower variance, confirming causality.
3. **Group size robustness on new long-horizon task:** Test OTB with N=2,4,8 on an algorithmic reasoning task with horizon >4000 tokens. Verify N=4 attains within 0.5% of N=32's final performance while consuming ~67% fewer tokens, extending the efficiency claim.
