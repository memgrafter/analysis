# Overview of PAN 2026: Voight-Kampff Generative AI Detection, Text Watermarking, Multi-Author Writing Style Analysis, Generative Plagiarism Detection, and Reasoning Trajectory Detection

## Quick Facts
*   **arXiv ID:** 2602.09147
*   **Source URL:** https://arxiv.org/abs/2602.09147
*   **Reference count:** 0
*   **Primary result:** PAN 2026 organizes five shared tasks to advance text forensics, built on the reproducible TIRA Docker platform which has facilitated over 1,100 submissions since 2012.

## Executive Summary
PAN 2026 continues a tradition of competitive evaluation in computational text forensics through five shared tasks. These tasks target emerging challenges: detecting AI-generated text mixed with human writing and under obfuscation (Voight-Kampff), evaluating the robustness of text watermarks against destruction, analyzing multi-author writing style changes in fanfiction, detecting generative plagiarism via source retrieval and alignment, and classifying the source and safety of AI/human reasoning trajectories. All tasks rely on the TIRA platform, which uses Docker containers to ensure reproducible, fair evaluation in a stateless sandbox.

## Method Summary
The workshop defines five concrete problems with specific datasets and evaluation protocols. Participants develop software systems and submit them as Docker containers via the TIRA platform for most tasks, which are then run automatically on hidden test data. The Reasoning Trajectory Detection task allows output-only submissions without container execution. Datasets are constructed from authentic sources: fanfiction corpora for style analysis, PubMed/JSTOR for plagiarism, and math/coding/financial queries with scraped or model-generated reasoning traces. A core evaluation theme across tasks is robustness—against unknown obfuscations, watermark destruction, or adversarial paraphrasing.

## Key Results
*   PAN establishes a benchmark suite for modern text forensics, addressing generative AI detection, watermarking, multi-author analysis, generative plagiarism, and reasoning trajectory inspection.
*   The TIRA Docker platform has a proven track record, enabling over 1,100 submissions since 2012, including 112 software submissions and 70 notebook papers in 2025 alone.
*   The shared tasks collectively push research toward robustness against realistic adversarial modifications and authentic, domain-specific evaluation scenarios.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** The PAN workshop’s reliance on Docker containers via the TIRA platform guarantees reproducible, fair evaluation across submissions.
*   **Mechanism:** Participants package their systems as Docker images. TIRA executes these in a controlled, stateless sandbox on hidden test data, ensuring identical environments and preventing cross-run contamination.
*   **Core assumption:** The containerized environment fully isolates runs and uniformly enforces resource limits.
*   **Evidence anchors:** Abstract: "Built on the reproducible TIRA Docker platform" and "more than 1,100 submissions have been made this way via the TIRA experimentation platform." Section: "submitted software systems are executed in a stateless sandbox... prevents knowledge leaks."
*   **Break condition:** Sandbox isolation failure or uneven resource enforcement; use of disallowed external APIs.

### Mechanism 2
*   **Claim:** By introducing unknown obfuscation transformations, PAN tasks evaluate robustness against realistic adversarial attacks.
*   **Mechanism:** Voight-Kampff uses a builder-breaker setup where one group obfuscates AI text (e.g., paraphrasing) and another’s detector must identify the origin. Text Watermarking passes watermarked text through unknown automated obfuscations (e.g., synonym replacement) before verification.
*   **Core assumption:** The obfuscations represent real adversarial modifications users might employ.
*   **Evidence anchors:** Abstract mentions "mixed and obfuscated authorship scenarios" and text goes through "unknown automated text obfuscation processes." Section references 2025 focus on "robustness analysis... against unknown text modifications."
*   **Break condition:** Obfuscations too narrow (overfitting) or too destructive (unsolvable floor).

### Mechanism 3
*   **Claim:** PAN’s use of authentic, domain-specific datasets creates ecologically valid benchmarks that mirror real-world forensic scenarios.
*   **Mechanism:** Multi-author uses fanfiction collections with natural multi-author texts; Generative Plagiarism uses real PubMed/JSTOR sources; Reasoning Trajectory uses real math/coding/financial queries with human/AI traces.
*   **Core assumption:** These authentic sources capture true diversity and complexity, and performance correlates with practical effectiveness.
*   **Evidence anchors:** Abstract lists task-specific datasets. Sections detail construction for fanfiction, PubMed/JSTOR, and reasoning sourcing.
*   **Break condition:** Datasets contain hidden biases or licensing restrictions limit distribution; benchmarks become stale as LLM tactics evolve.

## Architecture Onboarding
*   **Component map:**
    TIRA Server -> Docker Registry -> Execution Sandbox (Isolated Docker Runtime) -> Evaluation Engine -> Leaderboard
    Participant Container (uploaded to Docker Registry) feeds into Execution Sandbox; Task Packages define specifications.
*   **Critical path:**
    1. Study task specs and download training data.
    2. Develop and validate algorithm locally.
    3. Package code into Docker image with TIRA-compliant entrypoint.
    4. Upload image via TIRA web UI and trigger test run.
    5. Review outputs and metrics on leaderboard.
    6. Iterate: refine, rebuild, resubmit.
*   **Design tradeoffs:**
    *   Reproducibility vs. Flexibility: Docker ensures identical environments but may restrict large models/GPUs; Reasoning task relaxes this with output-only submissions.
    *   Adversarial Difficulty vs. Solvability: Obfuscations must be realistic yet not impossible.
    *   Dataset Authenticity vs. Scalability: Real sources provide validity but are large; preprocessing may lose context.
*   **Failure signatures:**
    *   Container crashes/timeouts: resource exhaustion, missing deps, entrypoint bugs.
    *   Near-random scores: data format mismatch, task misunderstanding.
    *   High variance across reruns: non-determinism (missing seeds, external API reliance).
    *   Sudden performance drops: data leakage, broken preprocessing.
*   **First 3 experiments:**
    1. Submit a trivial majority-class system to verify end-to-end pipeline and establish a lower bound.
    2. Replicate a simple prior approach (e.g., sliding window with character n-grams) to confirm solvability and benchmark expected performance.
    3. Locally stress-test the Docker container with resource limits (`--memory`, `--cpus`) on a small sample to ensure TIRA compliance and correct output formatting.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** How can generative AI detection systems be made robust across diverse text domains and against sophisticated, unseen obfuscation techniques?
*   **Basis in paper:** [explicit] "However, LLM detection remains a challenge, especially across text domains, but also in the face of potential LLM style obfuscations."
*   **Why unresolved:** Current detectors likely overfit to specific domains and known obfuscations, limiting real-world applicability.
*   **What evidence would resolve it:** A benchmark dataset with standardized, diverse-domain texts and a wide array of adversarial obfuscations (from builder–breaker), where top systems show consistently high detection accuracy.

### Open Question 2
*   **Question:** What are the optimal formal trade-offs and evaluation metrics for balancing watermark inconspicuousness against robustness against a wide range of automated text modifications?
*   **Basis in paper:** [inferred] Task aims to evaluate based on "inconspicuousness... and its robustness" but does not define the trade-off metric.
*   **Why unresolved:** Without a clear, agreed-upon metric jointly measuring detectability, perceptual quality, and survival rate, progress is fragmented.
*   **What evidence would resolve it:** A principled metric or Pareto frontier analysis from human studies and standardized robustness tests, adopted as a benchmark standard.

### Open Question 3
*   **Question:** Can we reliably detect unsafe or deceptive reasoning trajectories in LLM outputs, even when those trajectories culminate in a safe or correct final answer?
*   **Basis in paper:** [explicit] "reasoning models may sometimes arrive at safe conclusions via deceptive or misaligned reasoning paths... This subtask targets step-level and outcome-level safety."
*   **Why unresolved:** Existing safety classifiers often miss hazardous intermediate logic hidden behind correct conclusions.
*   **What evidence would resolve it:** A dataset of reasoning traces with fine-grained, step-by-step safety annotations and evaluation showing systems identify harmful reasoning with high precision.

### Open Question 4
*   **Question:** For generative plagiarism involving merging or expanding, what retrieval and alignment strategies are most effective, and how should they be evaluated?
*   **Basis in paper:** [inferred] Task reinstates "the crucial retrieval aspect" and incorporates "merging" and "expanding" but does not specify optimal approaches or evaluation metrics.
*   **Why unresolved:** These forms test semantic retrieval and granular alignment under significant paraphrasing and transformation, where current techniques may fail.
*   **What evidence would resolve it:** A shared evaluation framework with new metrics for retrieval recall and alignment precision for merging/expansion, supported by winning systems that demonstrably outperform baselines.

## Limitations
*   Exact 2026 test data formats, sampling methods (especially fanfiction mixing), and precise evaluation metrics (e.g., tolerance for style change detection) are unknown.
*   Task-specific obfuscation pipelines (Watermarking) and query/AI trace provenance (Reasoning) are unspecified, creating uncertainty about the true adversarial challenge.
*   Potential hidden biases in fanfiction/scientific corpora and licensing constraints may limit generalizability and dataset distribution.

## Confidence
*   **Claim 1 (TIRA reproducibility):** High confidence. Supported by long-term use and explicit platform design.
*   **Claim 2 (Adversarial obfuscations):** Medium confidence. Builder-breaker paradigm described, but obfuscation specifics unknown; risk of over/under-fitting.
*   **Claim 3 (Authentic datasets):** Medium confidence. Domain sources are credible, but dataset construction details and biases remain to be verified.
