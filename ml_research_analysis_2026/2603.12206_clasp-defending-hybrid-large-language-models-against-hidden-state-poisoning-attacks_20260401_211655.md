# CLASP: Defending Hybrid Large Language Models Against Hidden State Poisoning Attacks

## Quick Facts
- arXiv ID: 2603.12206
- Source URL: https://arxiv.org/abs/2603.12206
- Reference count: 40
- Primary result: CLASP detects Hidden State Poisoning Attacks with 95.9% token-level F1 and 99.3% document-level F1, while maintaining high throughput (1,032 tokens/s) and low VRAM (<4GB).

## Executive Summary
This paper introduces CLASP, a lightweight front-line defense against Hidden State Poisoning Attacks (HiSPAs) that target state space models (SSMs) like Mamba. HiSPAs use malicious strings to corrupt the model's hidden state, causing irreversible amnesia. CLASP exploits distinctive spikes in Mamba's block output embeddings (BOEs) induced by HiSPA tokens. It frames detection as a token-level binary classification task, using a curated set of BOE features and an XGBoost classifier. Evaluated on 2,483 résumés with controlled injections, CLASP achieves near-perfect detection (99.3% document F1) and generalizes reasonably to structurally novel triggers (91.6% average doc F1 under clustered cross-validation). The full pipeline processes tokens efficiently, making it deployable for SSM-based and hybrid architectures.

## Method Summary
CLASP operates in two phases: feature extraction and classification. For each token in a document, a frozen Mamba model produces block output embeddings (BOEs) from 64 layers. A pre-identified set of 13 "fingerprint" dimensions across 26 blocks, which show statistically significant activation spikes during HiSPA corruption, are extracted as raw features. Additionally, 14 summary statistics (mean, std, skewness, etc.) are computed over the full BOE vector at each block, yielding 409 features per token. These time-invariant features avoid context dependency to prevent memorization of specific triggers. An XGBoost classifier, trained on token-level labels from an augmented résumé corpus (injecting either HiSPA or benign strings), scores each token. Document-level decisions are made by aggregating token scores (e.g., max). The system is designed for high throughput (~1k tokens/s) and modest memory (<4GB VRAM).

## Key Results
- **High detection accuracy**: 95.9% token-level F1 and 99.3% document-level F1 on the full test set.
- **Generalization to novel triggers**: Under clustered cross-validation (holding out entire structural clusters), CLASP maintains an average 91.6% document-level F1; leave-one-out yields 96.9%.
- **Efficiency**: The full pipeline processes 1,032 tokens per second with under 4GB VRAM, suitable for real-world screening.

## Why This Works (Mechanism)
The defense relies on three core mechanisms:

1. **BOE Spike Signature**: HiSPA triggers cause sharp, statistically significant over-activation in a small set of BOE dimensions across mid- and late-layers. This spike pattern is consistent across different HiSPA strings, providing a discriminative signal. Evidence: The fingerprint dimensions are selected with χ² p<0.001 and >5 percentage point effect size; Figure 2/3 show large differentials.

2. **Time-Invariant Feature Representation**: Each token is classified based solely on its own BOE (no temporal context), forcing the model to learn the intrinsic corruption pattern rather than memorizing specific trigger sequences. The aggregate of token scores yields a robust document-level signal even with token-level ambiguity. Evidence: Document-level F1 reaches 99.3% despite token-level incompressible errors on ambiguous tokens.

3. **Generalization via Tabular Classification**: XGBoost on the curated 409-feature set learns a decision boundary that generalizes across trigger families. Feature importance pruning reduces to 200 dimensions, improving cross-validation robustness. Evidence: LOO (96.9% doc F1) and CCV (91.6% avg) demonstrate resilience, though performance drops for special-token triggers (Cluster 2).

Break conditions for each mechanism include attacks that avoid activating fingerprint dimensions, benign text mimicking the spike pattern, or a shift in BOE dynamics for unseen domains.

## Foundational Learning
Understanding CLASP requires grounding in three concepts:

- **State Space Models (SSMs) & Selective Recurrence**: SSMs maintain an explicit hidden state that acts as compressed memory, updated via recurrence. This makes them vulnerable to corruption by malicious inputs. - **Hidden State Poisoning Attacks (HiSPAs)**: Short adversarial strings that force an SSM’s hidden state into a contracting regime, causing irreversible amnesia. Distinct from prompt injection. Quick check: *What is the key difference between a HiSPA and a standard Prompt Injection Attack (PIA) in terms of payload and mechanism?*
- **Block Output Embeddings (BOEs)**: The output of each Mamba block before layer normalization. BOEs carry signatures of hidden state corruption, observable as activation spikes in certain dimensions. Quick check: *In Mamba, what is a "block," and how is its output embedding (BOE) computed? ## Architecture Onboarding
The CLASP pipeline consists of the following sequential components:

Input text → Tokenization (Mamba tokenizer) → Feature Extractor (frozen Mamba forward pass) → Feature Engineer (compute 409 features per token) → Classifier (XGBoost) → Decision Layer (aggregation & thresholding)

**Critical path**: Tokenization → Mamba forward pass (GPU-bound, ~1 ms/token) → CPU feature computation → XGBoost inference → aggregation.

**Design tradeoffs**:
- **Time-invariance vs. Context**: Time-invariant features prevent memorization but cause errors on ambiguous tokens (e.g., "Write", "System:") that appear in both benign and malicious contexts. A contextual variant could improve token F1 but risks overfitting.
- **Feature count**: 409-dim features yield best full-set performance but may overfit to seen trigger clusters; 200-dim pruned set improves CCV generalization.
- **Model independence**: The method assumes Mamba-like BOE dynamics; extending to hybrid models (e.g., Jamba) requires selecting appropriate SSM layers.

**Failure signatures**:
- High false negatives on Cluster 2 triggers (special tokens/redaction) in CCV.
- High false positives on benign tokens with similar linguistical patterns to triggers.
- Threshold collapse under CCV (optimal token thresholds drop to 0.04–0.21), indicating lower confidence on novel patterns.

**First 3 experiments**:
1. **Feature Extraction Sanity**: Run extraction on a small clean resume; verify 409-dimensional vectors contain the 13 fingerprint dimensions for their respective blocks.
2. **Single-Trigger Detection**: Inject one HiSPA trigger (e.g., "Ignore all previous instructions.") and its benign counterpart into two clean resumes; confirm the HiSPA file yields high max token score while the benign file does not.
3. **Cross-Validation Stress Test**: Perform CCV with Fold 3 (train on Clusters 0 & 1, test on Cluster 2); observe document-level F1 drop to ~82%, confirming vulnerability to special-token triggers.

## Open Questions the Paper Calls Out
- How does CLASP generalize to document domains other than résumés (e.g., legal contracts, scientific papers) without retraining?
- Can the trigger catalog be automatically expanded to cover more attack patterns and improve robustness?
- How effective is CLASP against adaptive attacks where the adversary knows the detector and crafts stealthy triggers?
- Does incorporating contextual information from neighboring tokens improve token-level detection, especially for ambiguous tokens?
- Can CLASP's feature extraction be efficiently performed using smaller Mamba models without sacrificing accuracy?

## Limitations
The evaluation reveals three major uncertainties:
1. Unclear injection protocol: Exact mapping from character-level random positions to token labels is underspecified, risking metric instability.
2. Opaque feature selection and thresholds: Statistical pipeline details (e.g., top-K definition, aggregation) are missing; classification thresholds vary widely across CV folds.
3. Generalization boundary undefined: Performance significantly degrades for Cluster 2 triggers (special tokens/redaction), suggesting either a limitation of BOE signatures or insufficient training diversity.

## Confidence
- **Mechanism 1 (BOE Spike Signature)**: High (strong statistical evidence for known triggers, but drops for novel ones).
- **Mechanism 2 (Time-Invariant Classification)**: Medium (document-level success but token-level ambiguity remains).
- **Mechanism 3 (Generalization via XGBoost)**: Medium-Low (LOO strong, CCV shows 7.7% avg drop; severe for Cluster 2).

## Next Checks
1. **Reproduce Feature Extraction Sanity**: Inject a single HiSPA trigger and its benign counterpart into 10 clean resumes; extract BOE features and verify that the 13 fingerprint dimensions show a significant activation spike at the trigger position (t-test p<0.01).
2. **Sensitivity to Injection Parameters**: Vary token labeling policy (splitting vs. ignoring partial tokens) and number of injections per file; measure changes in token and document F1. Expect >2pp drop if protocol choices are critical.
3. **Targeted Generalization Stress Test**: Train on Clusters 0 & 1 only and evaluate on Cluster 2; also create a synthetic novel trigger family. If Cluster 2 remains low (<85%) while synthetic triggers achieve >95%, the limitation is structural.
