# LLM-Driven Multi-Turn Task-Oriented Dialogue Synthesis for Realistic Reasoning

## Quick Facts
- **arXiv ID**: 2602.23610  
- **Source URL**: https://arxiv.org/abs/2602.23610  
- **Reference count**: 40  
- **Primary result**: Proposed trilevel optimization framework for realistic multi-turn dialogue synthesis; resulting RealReasoning dataset reveals current LLMs still struggle, with top model achieving 87.8% overall but 85.3% on common-sense reasoning.

## Executive Summary
The paper tackles the scarcity of realistic benchmarks for evaluating LLM reasoning in task-oriented dialogues. It introduces an LLM-driven framework that uses trilevel optimization to iteratively refine prompts and evaluation metrics, generating multi-turn dialogues grounded in real-world scenarios. This process produces the RealReasoning dataset—500 dialogues with manually annotated reasoning questions. Experiments show that even state-of-the-art models face challenges, particularly on common-sense tasks, and the iterative curation reduces easy problems from 26.6% to 0.6%, effectively raising the benchmark’s difficulty.

## Method Summary
The synthesis pipeline starts with a scenario description. A user generator creates candidate user profiles, and a selected user agent interacts with external tools (e.g., search) to produce an action sequence, updating its memory. This memory and action sequence provide a coherent narrative backbone for multi-turn dialogue between user and assistant agents. A trilevel optimizer then iteratively refines the dialogue prompts (multi-turn and single-turn) and composite evaluation metrics using zeroth-order gradient approximations and an evolutionary metric search, guided by quality scores from an expert LLM. Reasoning questions are extracted and manually labeled. Finally, an iterative refinement loop uses a set of reasoning models to identify and replace easy instances (high accuracy) by generating new questions conditioned on similar difficult problems from a knowledge base, progressively increasing dataset difficulty.

## Key Results
- **Dataset**: RealReasoning contains 500 multi-turn task-oriented dialogues with reasoning questions.
- **Model performance**: DeepSeek-R1 achieves 87.8% overall accuracy but only 85.3% on common-sense reasoning, indicating persistent challenges.
- **Difficulty curation**: Iterative replacement reduces easy problems from 26.6% to 0.6%, significantly raising benchmark difficulty.

## Why This Works (Mechanism)
The paper’s effectiveness rests on three integrated mechanisms:

**1. Trilevel Optimization for Dialogue Quality**  
The framework defines three optimization levels: top-level metric parameters (ω), mid-level multi-turn prompt (θ), and bottom-level single-turn prompt (ϕ). It uses zeroth-order gradient estimation for θ and ϕ (due to black-box LLMs) and an evolutionary algorithm to search over composite metrics governed by ω. Iterations maximize a quality score h(θ,ϕ) from an expert LLM, assuming this score reliably reflects human preferences (coherence, fluency, diversity). Evidence includes the detailed formulation in Section 3.6 and corpus analysis showing novelty (FMR scores 0.53–0.68). However, if the expert LLM’s scoring is inconsistent or the evolutionary search fails to discover metrics aligned with human judgment, optimization may stagnate or degrade.

**2. Pre-generating User Action Sequences**  
To ensure contextual coherence and topic diversity, the system first generates a user profile (intent, problem) and then a sequence of actions A = {a₁,…,aₙ} via interaction with an external environment (e.g., search tools). The user agent updates its memory after each action, creating a narrative backbone. During dialogue, the user agent references this memory, maintaining continuity and reducing repetition. The core assumption is that a semi-deterministic action planner guided by scenario keywords and external knowledge can approximate realistic user behavior. Evidence: The paper highlights this in the abstract and Section 3.4, and corpus comparison shows this explicit action modeling is a differentiator. If action generation becomes too deterministic or fails to capture diverse behaviors, dialogue diversity collapses (high cosine similarity).

**3. Iterative Replacement of Easy Problems**  
The dataset curation iteratively replaces instances that are easily solved by current reasoning models. For each dialogue-question pair, multiple models compute an average accuracy. If accuracy is perfect (accᵢ = 1), the instance is labeled “easy” and replaced by generating a new question ˆP conditioned on the easy dialogue Yⱼ and a difficult problem Pₖ from a knowledge base Kp (acc < ϕ = 0.5). The new question is verified and added, while the easy instance is removed. This reduces the proportion of easy problems from 26.6% to 0.6%. The assumption is that model accuracy indicates difficulty and that conditioning on both dialogue and hard problem yields a harder variant. Evidence: Section 4.3 details the algorithm and the dramatic reduction. Risks include generating unsound questions or biased difficulty assessment due to model overfitting.

## Architecture Onboarding
**Component map**:  
Scenario Input (x) → User Generator (p₁) → Candidate Users (U) → Action Sequencer (p₂) → Action Sequence (A) & Memory (M) → Dialogue Interaction (p₃, p₄) → Dialogue (Y) → Reasoning Question Generator → (P, l) → Dataset Manager (D).  
Trilevel Optimizer iteratively updates p₃, p₄ (θ, ϕ) and metric parameters (ω) using expert LLM scores (h).  
Iterative Refinement Loop: D → evaluate with reasoning models {Mᵢ} → compute accᵢ → identify easy instances → Knowledge Base (Kp) → problem generator I → new question ˆP → replace easy → updated D.

**Critical path**:
1. Input scenario x.
2. User Generator produces candidate users U.
3. Select a user; generate action sequence A and memory M via Action Sequencer.
4. Initialize or load prompt parameters (θ, ϕ).
5. Execute Dialogue Interaction to produce Y.
6. Trilevel Optimizer: score Y with expert LLM → h(θ,ϕ); update θ, ϕ via zeroth-order; evolve ω; repeat until convergence.
7. Extract reasoning question P and label l; add (Y, P, l) to D.
8. Periodically run Iterative Refinement: evaluate D with models → accᵢ; maintain Kp of difficult problems (acc < ϕ); replace easy instances (acc=1) by generating ˆP from similar Pₖ in Kp; verify/annotate; update D.

**Design tradeoffs**:
- **Zeroth-order vs. first-order**: Zeroth-order avoids gradient extraction but is sample-inefficient and noisy.
- **Evolutionary metric search**: Flexible but computationally heavy; tree depth d trades expressivity for stability.
- **Manual vs. automated labeling**: Manual ensures quality but limits scale; automated difficulty assessment may bias if models are over/under-confident.
- **External tools**: Enrich realism but add latency and API dependencies.

**Failure signatures**:
- **Low diversity**: average cosine similarity > 0.9 across dialogues; indicates overfitting or insufficient action variation.
- **Trilevel stagnation**: quality score h(θ,ϕ) fluctuates or degrades; check metric evolution and update stability.
- **Ineffective refinement**: easy-problem ratio remains high; verify Kp updates and problem generation relevance.
- **Memory drift**: user memory becomes inconsistent (contradicts earlier intents); inspect memory traces.
- **Knowledge base saturation**: Kp contains near-duplicate hard problems; monitor similarity distribution.

**First 3 experiments**:
1. **Ablation study**: Generate dialogues under three conditions (direct interaction, +user identity, +action sequence). Compute cosine similarity and unique topic counts; validate diversity gains.
2. **Trilevel impact**: Compare dialogues with trilevel optimizer disabled (fixed metrics) vs. full method using expert LLM scores for coherence, fluency, diversity.
3. **Iterative refinement dynamics**: Seed dataset of 20 dialogues; run replacement for 5 iterations. Plot easy-problem ratio over time; sample new problems for human evaluation to assess difficulty increase and label validity.

## Limitations
- Missing exact prompts (p1–p4) and hyperparameters for trilevel evolution/perturbation.
- Expert LLM quality scores lack human evaluation correlation; proxy reliability unknown.
- Difficulty curation relies on model accuracy as difficulty signal and problem generator soundness—both unvalidated.

## Confidence
- **Trilevel optimization improves quality**: Medium
- **Action sequences boost coherence/diversity**: High
- **Iterative replacement raises difficulty**: Medium
- **LLMs struggle on the dataset**: Medium
