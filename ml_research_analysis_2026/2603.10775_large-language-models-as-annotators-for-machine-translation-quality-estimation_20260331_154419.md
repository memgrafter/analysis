# Large Language Models as Annotators for Machine Translation Quality Estimation

## Quick Facts
- arXiv ID: 2603.10775
- Source URL: https://arxiv.org/abs/2603.10775
- Reference count: 15
- Primary result: Synthetic MQM annotations from GPT‑4o can train reference‑free COMET models that achieve competitive MTQE performance, with a notable edge on lower‑quality translation segments.

## Executive Summary
The paper tackles the high inference cost of using Large Language Models directly for Machine Translation Quality Estimation (MTQE). It proposes using a systematically engineered GPT‑4o prompt (PPbMQM) to generate simplified MQM‑style annotations for source‑target segments. These synthetic annotations are then used to train a reference‑free COMET model instead of relying on expensive LLM calls at test time. Evaluations on Chinese‑English and English‑German WMT EbHE datasets show that the PPbMQM annotations correlate well with human judgments. More importantly, COMET models trained on the synthetic data match or exceed the performance of models trained on human MQM annotations, particularly for segments with quality scores below 0.8. This approach offers a cost‑effective and consistent alternative for high‑quality MTQE.

## Method Summary
The method consists of three main steps:

1. **Prompt Development**: The authors design a few‑shot prompt (PPbMQM) that restricts LLM output to the top‑level MQM categories (Accuracy, Fluency, Style, Terminology, Locale Convention) plus the Omission subcategory. A severity scale of 1–5 is mapped to Major (4–5) and Minor (1–3); severity 1–2 is discarded during training. Two few‑shot examples illustrate the expected output.

2. **LLM Annotation**: Using GPT‑4o, the final prompt is applied to each source‑target segment from the WMT EbHE training sets (20703 Chinese–English and 10121 English–German segments). The model returns JSON containing error type, severity, and span indices. Span indices are aligned to NLTK tokens, picking the closest token if ambiguous.

3. **COMET Training**: Two reference‑free COMET models are trained per language pair—one on the synthetic PPbMQM scores and one on human MQM scores—using the default COMET training configuration (hyperparameters not detailed). Models are evaluated on a held‑out test set, and segment‑level Pearson correlation with human judgments is reported, including bucketed analysis for segments with quality scores below 0.8.

## Key Results
- PPbMQM annotations exhibit strong correlation with human MQM judgments (no exact numbers provided, but described as “well”).
- COMET models trained on synthetic data achieve comparable overall segment‑level Pearson ρ to human‑trained models on both Chinese–English and English–German.
- For lower‑quality segments (score <0.8), synthetic‑trained models significantly outperform human‑trained models: e.g., zh‑en ρ=0.523 vs 0.434; en‑de ρ=0.708 vs 0.692.

## Why This Works (Mechanism)
The PPbMQM prompt imposes a structured and simplified annotation schema that reduces variability and focuses on error types most predictive of overall quality. GPT‑4o’s strong language understanding yields consistent error identification and severity assignment, partly because the prompt disambiguates categories and provides clear examples. Training COMET on these synthetic annotations effectively distills the LLM’s judgment into a lightweight model that can be deployed at low cost. The observed advantage on low‑quality segments suggests that human annotators may have lower inter‑annotator agreement on heavily flawed translations, whereas the LLM provides more stable labels in that regime.

## Foundational Learning
Key concepts underlying the approach:

- **Machine Translation Quality Estimation (MTQE)** – Predicts translation quality without access to a reference. *Why needed:* Core task the paper addresses. *Quick check:* Can define MTQE as a source‑target pair → quality score mapping.
- **Multidimensional Quality Metrics (MQM)** – A fine‑grained annotation framework categorizing translation errors (Accuracy, Fluency, etc.) with severity levels. *Why needed:* Provides the annotation schema that PPbMQM simplifies. *Quick check:* Understand top‑level MQM categories and severity scales.
- **COMET** – A neural metric trained on human judgments (often using MQM) that serves as a state‑of‑the‑art reference‑free QE model. *Why needed:* The downstream model that consumes synthetic annotations. *Quick check:* Know COMET’s architecture (e.g., encoder‑based) and training objective (e.g., regression on quality scores).
- **Large Language Models as Annotators** – Using LLMs like GPT‑4o to produce annotations via prompting. *Why needed:* Enables cheap, scalable generation of training data. *Quick check:* Be able to design a prompt that elicits structured JSON output from an LLM.
- **Few‑Shot Prompting** – Including input‑output examples in the prompt to steer LLM behavior. *Why needed:* Critical for the PPbMQM prompt’s effectiveness. *Quick check:* Can construct a few‑shot prompt with two examples for a classification task.
- **Reference‑Free Evaluation** – Quality estimation without a gold reference translation. *Why needed:* COMET is trained reference‑free here, making the approach applicable where references are unavailable. *Quick check:* Distinguish reference‑free vs. reference‑based metrics.

## Architecture Onboarding
The system pipeline comprises the following components:

- **Data Source**: WMT EbHE datasets (source‑target segment pairs) for zh‑en and en‑de.
- **LLM Annotator**: GPT‑4o with the PPbMQM prompt → structured JSON annotations (error type, severity, spans).
- **Span Resolver**: NLTK tokenizer to align LLM‑provided character spans to tokens; disambiguates by nearest token.
- **Score Aggregator**: Converts error annotations into a segment score (weighted sum: Major=5, Minor=1; severity 1‑2 discarded).
- **COMET Trainer**: Trains a reference‑free COMET model on (source, target, score) triples; two variants: synthetic vs. human MQM.
- **Evaluator**: Computes Pearson/Spearman correlation on held‑out test set; also buckets by segment quality.

**Component map:** Data Source -> LLM Annotator -> Span Resolver -> Score Aggregator -> COMET Trainer -> Evaluator.

**Critical Path:** The most resource‑intensive steps are (1) generating LLM annotations for all training segments and (2) training the COMET models. Any failure in annotation consistency directly impacts model performance.

**Design Tradeoffs:**
- Simplicity vs. Granularity: PPbMQM uses only top‑level MQM categories, sacrificing fine‑grained error types for higher LLM consistency.
- Severity Filtering: Discarding severity 1‑2 removes noisy low‑impact errors but may lose signal for high‑quality segments.
- LLM vs. Human Cost: LLM annotation is cheaper and scalable but may introduce subtle biases not present in human data.

**Failure Signatures:**
- Low JSON parsable rate (<90%) indicates prompt instability or model drift.
- Discrepancy between synthetic and human scores on high‑quality segments may stem from severity mapping choices.
- Overfitting in COMET training if synthetic scores are too uniform or have low variance.

**First Three Experiments:**
1. **Annotation Consistency Check**: Run GPT‑4o on a fixed set of segments multiple times (or with different seeds) and compute agreement (e.g., Cohen’s κ) on error type and severity; also compare correlation with human MQM.
2. **Baseline Replication**: Train both synthetic‑data and human‑data COMET models using the described pipeline, evaluate overall Pearson ρ on the test set, and confirm that results align with the paper’s reported numbers for each language pair.
3. **Bucket Analysis**: Re‑implement the quality‑bucketing (<0.8 vs. ≥0.8) and verify the performance gap on lower‑quality segments; also test alternative severity mappings (e.g., include all severities) to assess robustness.

## Open Questions the Paper Calls Out
The authors highlight four unresolved directions:

1. **Generalization to Lower‑Resource Pairs** – How does PPbMQM perform on language pairs beyond the two high‑resource ones studied? The conclusion explicitly wonders about lower‑resource settings. Evidence needed: systematic evaluation across diverse language pairs with varying resources and linguistic features.
2. **Reason for Low‑Quality Segment Advantage** – Why do synthetic‑trained models outperform human‑trained ones on segments with scores <0.8? The authors speculate that LLM annotations may be more consistent than human ones in this regime, but direct evidence linking consistency to performance is lacking. Evidence needed: measure inter‑annotator agreement for both annotation sources and correlate with COMET performance across quality buckets.
3. **Impact of Category Simplification** – Does reducing MQM to top‑level categories omit critical error information? Error‑type F1 scores were low, especially for Style and Fluency, but the trade‑off between simplicity and granularity is not analyzed. Evidence needed: an ablation comparing full MQM hierarchy vs. simplified categories on downstream QE performance, per error type and language.
4. **Reliability Across LLM Backends** – The authors chose GPT‑4o due to API stability issues with LLaMA 3, yet observed some variation across system_fingerprint values. However, broader reliability across LLM versions, prompt tweaks, and domains remains unknown. Evidence needed: large‑scale stability tests across multiple LLMs, prompt variants, and input domains, measuring both annotation consistency and downstream performance variance.

## Limitations
- Exact COMET training hyperparameters (model version, learning rate, batch size, epochs, random seed) are not disclosed (“default settings”), hindering precise replication.
- Train/test splits for the WMT EbHE datasets are unspecified; potential overlap or differing distributions could invalidate performance comparisons.
- The reported advantage on lower‑quality segments depends on the chosen severity threshold (discarding 1–2) and score aggregation; robustness to alternative mappings is unverified.

## Confidence
- Prompt design and LLM annotation generation: High
- Correlation between PPbMQM and human judgments: Medium
- Competitive segment‑level performance of synthetic‑data COMET models, especially the low‑quality segment claim: Low
