# EntropyCache: Decoded Token Entropy Guided KV Caching for Diffusion Language Models
## Quick Facts
- arXiv ID: 2603.18489
- Source URL: https://arxiv.org/abs/2603.18489
- Reference count: 40
- Primary result: EntropyCache achieves up to 26.4× speedup with negligible overhead and competitive accuracy on diffusion LLMs.

## Executive Summary
Diffusion language models (dLLMs) suffer from high inference costs because their bidirectional attention prevents lossless KV caching, requiring a full forward pass at every denoising step. Existing approximate caching methods either scale poorly with context length or model depth. EntropyCache introduces a constant-cost mechanism that uses the maximum entropy of newly decoded token distributions as a cheap signal to decide whether to skip KV recomputation, and it recomputes the k most recently decoded tokens to capture feature volatility that persists across steps. Evaluated on LLaDA-8B-Instruct and Dream-7B-Instruct, EntropyCache achieves speedups of 15.2×–26.4× with decision overhead under 0.5% of total inference time and accuracy comparable to or better than prior methods.

## Method Summary
EntropyCache modifies the inference pipeline of diffusion LLMs by inserting lightweight decision points between denoising steps. After each decoding step, it computes the maximum entropy of the newly decoded token probability distributions. If this entropy exceeds a threshold τ, a full forward pass is performed to refresh all KV states; otherwise, a partial forward pass is executed that recomputes KV only for mask tokens and the k most recently decoded positions (selected via a decode history buffer). The entropy threshold and recent token budget k are fixed constants, making the decision overhead O(V) and independent of context length. The method leverages two empirical observations: (1) token entropy correlates with KV cache drift, and (2) feature volatility extends beyond a single step, justifying recomputation of a recent window.

## Key Results
- Achieves 15.2×–26.4× speedup on standard benchmarks and 22.4×–24.1× on chain-of-thought benchmarks.
- Decision overhead is only ~0.5% of total inference time, constant across context lengths and model scales.
- Accuracy is competitive with or exceeds prior dynamic KV caching methods on most tasks, though some code-generation tasks show sensitivity to threshold settings.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: Maximum decoded token entropy correlates with KV cache drift, enabling a cheap skip trigger.
- Mechanism: After decoding new tokens, compute max entropy over their probability distributions. If > τ, the next step performs a full forward pass; otherwise, a partial forward pass.
- Core assumption: Tokens decoded from high-uncertainty distributions induce larger representation shifts, causing more cache staleness.
- Evidence anchors:
  - [abstract]: "uses the maximum entropy of the newly decoded token distributions as a constant-cost signal for deciding when to recompute."
  - [section 3.1]: "decoded token entropy correlates with KV cache drift, providing a cheap proxy for cache staleness."
  - [corpus]: Neighbor methods (e.g., d2Cache, Elastic-Cache) rely on attention rollout or layer-wise drift, which scale with context length or model depth; entropy is simpler and constant.
- Break condition: If entropy–drift correlation fails on new models/data (e.g., HumanEval showed weaker Spearman ρ), skip decisions become unreliable, potentially degrading accuracy.

### Mechanism 2
- Claim: Feature volatility persists beyond one decoding step; recomputing the k most recently decoded tokens captures multi-step instability.
- Mechanism: Maintain a decode history H where each position records its decoding step. Select k positions with largest H values (most recent) and recompute their KV along with mask tokens during partial steps.
- Core assumption: Recently decoded tokens are more likely to contribute to cache staleness in subsequent steps.
- Evidence anchors:
  - [section 3.2]: PCA trajectories show some tokens drift for many steps after decoding.
  - [section 4.2]: "motivating recomputation of the k most recently decoded tokens."
  - [corpus]: Prior dynamic methods (d2Cache, Elastic-Cache) only recompute tokens from the immediate previous step, not a window.
- Break condition: If all tokens stabilize immediately after decoding, the k-recent budget causes unnecessary recomputation, reducing throughput without accuracy benefit.

### Mechanism 3
- Claim: The combination yields constant decision overhead independent of context length and model scale.
- Mechanism: Entropy computation costs O(V); history selection costs O(k). Both are fixed constants.
- Core assumption: Vocabulary size V and recent token budget k are invariant to context length L or model depth ℓ.
- Evidence anchors:
  - [abstract]: "The skip-or-recompute decision requires only O(V) computation per step, independent of context length and model scale."
  - [section 4.1]: "This decision requires a single O(V) computation per step, where V is the vocabulary size. This overhead is entirely independent of context length, model depth, and hidden dimension."
  - [section 5.4]: Table 3 shows EntropyCache overhead O(V) vs. O(ℓ·L·H) and O(ℓ·L·d) for competitors.
- Break condition: If models adopt extremely large vocabularies (V >> typical) or k is set very large, overhead may become non-negligible relative to computation.

## Architecture Onboarding
Component map:
Token_Decoding -> Update_H -> Entropy_Calculator -> Skip_Decider -> (Recent_Selector -> Partial_Forward) OR (Full_Forward) -> Forward_Pass_Controller -> Update_KV_Cache -> Update_Mask -> (repeat)

Critical path per step:
1. Decode new tokens from current logits.
2. Update decode history for newly decoded positions.
3. Compute max entropy of decoded token distributions.
4. Set skip_flag = (entropy ≤ τ).
5. If skip_flag, select k most recent tokens from history (plus mask tokens) for partial recomputation; else, plan full recomputation.
6. Execute next forward pass (full or partial), updating KV cache.
7. Update mask positions and repeat.

Design tradeoffs:
- Fixed token budget k vs. fixed step window: k gives stable per-step cost even with variable parallel decoding; a step window would vary with decoding confidence.
- Entropy threshold τ: Lower τ increases accuracy but reduces speedup; higher τ opposite.
- Entropy metric: Max entropy outperforms sum entropy or max confidence (ablation Fig 4).
- Sliding window size w: Larger windows may degrade quality on some models (Table 4); w=32 balances efficiency and accuracy.

Failure signatures:
- Accuracy drop on certain tasks (e.g., MBPP on LLaDA) at default τ=1.5, k=64, recoverable by lowering τ.
- Throughput lower than expected if k is too large or τ too low (frequent full recomputation).
- Overhead remains constant; if not, likely implementation bug (e.g., computing entropy over all tokens).
- On code tasks, entropy–drift correlation weaker but accuracy may still hold; unexpected behavior may indicate mis-calibration.

First 3 experiments:

## Limitations
- Generalizability: Evaluated only on LLaDA-8B and Dream-7B; may not hold for other dLLM architectures or extremely large models.
- Entropy–drift correlation: Weaker on code-generation tasks (e.g., HumanEval), risking inaccurate skip decisions.
- Overhead scaling: For models with very large vocabularies (V >> typical) or large k, O(V) or O(k) may become non-negligible.
