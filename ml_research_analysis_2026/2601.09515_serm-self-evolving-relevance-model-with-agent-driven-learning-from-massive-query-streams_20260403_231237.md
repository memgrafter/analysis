# SERM: Self-Evolving Relevance Model with Agent-Driven Learning from Massive Query Streams

## Quick Facts
- **arXiv ID**: 2601.09515  
- **Source URL**: https://arxiv.org/abs/2601.09515  
- **Reference count**: 37  
- **Primary result**: SERM achieved a +2.99 point gain in NDCG@1 and a +0.0359% increase in 14‑day user retention after three self‑evolution iterations in large‑scale industrial A/B testing.

## Executive Summary
Relevance models for search must continuously adapt to evolving query streams, but face two key challenges: sparse informative samples and unreliable pseudo‑labels when self‑training. The Self‑Evolving Relevance Model (SERM) introduces a two‑component solution: a Multi‑Agent Sample Miner (MSM) that detects distributional shifts and selects challenging query‑document pairs, and a Multi‑Agent Relevance Annotator (MRA) that generates high‑quality labels via a two‑level agreement framework across multiple LLMs. In industrial tests across multilingual streams, SERM consistently improved offline metrics (e.g., +2.99 NDCG@1) and online user retention, while avoiding the degradation seen with standard self‑training. The work validates a multi‑agent pipeline for continuous, robust model evolution.

## Method Summary
SERM begins with two training stages on static labeled data: continual pre‑training on 100 B in‑domain document tokens, followed by supervised fine‑tuning (SFT) on 3.6 M relevance‑scored pairs. For iterative self‑evolution, the deployed model processes a live query stream. The Multi‑Agent Sample Miner (MSM) selects up to four candidate documents per query via four agents: (1) User Feedback (clicks/dwell > 5 s with model confidence < 0.4), (2) Click Model Feedback (pre‑trained click model score > 0.1), (3) Intrinsic disagreement (max difference across three temperature samples), and (4) Entropy of label distribution. The union of selected pairs forms a training set. The Multi‑Agent Relevance Annotator (MRA) then assigns labels: each LLM (e.g., GPT‑4o, Gemini) generates multiple reasoning paths; majority vote per LLM yields a stable label, and only samples where all LLMs agree are kept with aggregated rationales. Finally, the newly annotated data is mixed with all previous self‑evolution data and the original SFT data, and the model is retrained (learning rate 3e‑6, one epoch) before redeployment. This loop runs for multiple iterations (e.g., three).

## Key Results
- **Offline gains**: +2.99 NDCG@1 and consistent improvements in NDCG@4 and accuracy across Germanic, Romance, and Minor Language families.
- **Online improvement**: +0.0359% 14‑day user retention and –1.2081% negative feedback in A/B testing.
- **Stability**: Outperforms self‑training, which showed degradation on some language families; SERM’s gains remained stable across iterations.

## Why This Works (Mechanism)

### Multi‑Agent Sample Miner (MSM)
**Claim**: SERM’s MSM identifies informative, challenging query‑document pairs by combining environmental and intrinsic signals, addressing the sparsity of high‑learning‑value samples.  
**Mechanism**: Four agents operate in parallel: (a) User Feedback Agent selects pairs with strong engagement (click + dwell > 5 s) but low model confidence (f(q,d) < τc=0.4); (b) Click Model Feedback Agent uses a pre‑trained click model Rcm and selects pairs where predicted click probability > τcm=0.1; (c) Intrinsic Feedback Agent computes model disagreement (max score difference among K = 3 temperature samples) and uncertainty (entropy of label distribution). For each query, each agent samples up to n = 4 documents; duplicates are removed and the union forms the training set.  
**Core assumption**: Samples where the model’s prediction conflicts with user behavior or exhibits high uncertainty are more likely to contain novel patterns or knowledge gaps, thus offering higher learning value.  
**Evidence**: [abstract]; [section 3.1].

### Two‑Level Agreement Annotator (MRA)
**Claim**: SERM’s MRA produces reliable pseudo‑labels via a two‑level agreement framework (inner‑ and inter‑agreement) across multiple LLMs, mitigating the unreliability of self‑generated labels.  
**Mechanism**: Inner‑agreement: For each sample, multiple LLMs generate several reasoning paths (via temperature sampling) and produce candidate labels; majority vote yields a stable label per LLM. Inter‑agreement: The system retains only samples where all LLMs agree on the label; their rationales are aggregated into a coherent explanation.  
**Core assumption**: Consensus among diverse LLMs correlates with ground‑truth relevance; disagreement indicates ambiguity or noise, so discarding such samples prevents error propagation.  
**Evidence**: [abstract]; [section 3.2].

### Iterative Self‑Evolution with Mixed Data
**Claim**: Iterative retraining on a mixture of newly annotated, previously collected self‑evolution, and original SFT data enables continuous adaptation to evolving query streams without catastrophic forgetting.  
**Mechanism**: After each Self‑Evolution iteration, the newly created dataset (from MSM+MRA) is combined with all prior self‑evolution data and the original SFT set. The relevance model is then retrained (e.g., LR = 3e‑6, warm‑up 10%, 1 epoch). This mixture preserves knowledge from earlier distributions while incorporating new patterns.  
**Core assumption**: Retraining on a blend of old and new data prevents overwriting previously learned relevance patterns, which is essential in non‑stationary environments.  
**Evidence**: [section 4.2] describes the mixing strategy; Tables 1, 6, 7 show monotonic gains across iterations, while self‑training baselines degrade, confirming the benefit.

## Architecture Onboarding
**Component map**  
Input Stream (live user queries) → Multi‑Agent Sample Miner (four agents) → Multi‑Agent Relevance Annotator (inner‑ and inter‑agreement) → Training Data Aggregator (mix new + old + original SFT data) → Model Retrainer (SFT with LR=3e‑6) → Deployed Model → (back to Input Stream)

**Critical path**  
1. A new query triggers retrieval of top‑k candidate documents.  
2. MSM agents score each (query, document) pair; up to n = 4 docs per agent are selected per query; duplicates are removed to form a candidate set.  
3. For each candidate, MRA inner‑agreement: each LLM generates K = 3 reasoning paths, yields a candidate label, and majority vote assigns a stable label per LLM.  
4. MRA inter‑agreement: only pairs where all LLMs agree on the label are retained; rationales are aggregated.  
5. The retained pairs constitute the iteration’s newly annotated data.  
6. After a fixed interval (e.g., 2 weeks), merge new data with all previous self‑evolution data and the original SFT data.  
7. Retrain the relevance model from the previous checkpoint on the mixed dataset.  
8. Evaluate on a validation set; if performance improves, replace the production model and repeat.

**Design tradeoffs**  
- **Cost vs. Quality**: More LLMs and reasoning paths improve label reliability but increase API cost and latency. The paper uses two LLMs and three paths as a practical balance.  
- **Sample selection thresholds (τc, τcm)**: Lower thresholds increase recall of informative samples but risk including noise; higher thresholds improve precision but may miss subtle shifts. Optimal values depend on data distribution (τc=0.4, τcm=0.1 in the paper).  
- **Mixing ratio**: The proportion of new vs. old data controls adaptation speed vs. forgetting; the paper does not specify exact ratios.  
- **Iteration frequency**: Too frequent iterations may not accumulate enough shift; too infrequent may miss emerging trends. The authors use 2‑week intervals.

**Failure signatures**  
- Degradation on specific language families (e.g., Minor Languages) indicating possible LLM bias or insufficient sample coverage.  
- Ablation of any MSM agent causing a performance drop (as shown in Table 3).  
- Online metrics worsening after deployment (e.g., increased negative feedback) suggesting noisy annotations or forgetting.  
- Self‑training‑like degradation across iterations (NDCG decreasing) if the agreement mechanism fails to filter errors.  
- Inter‑agreement rate dropping (< 90%) signals potential label quality issues.

**First three experiments**  
1. **Baseline Reproduction**: Implement CT+SFT and self‑training baselines with identical data/hyperparameters; verify SERM outperforms them on validation metrics (e.g., NDCG@4).  
2. **Ablation Study**: Remove one component at a time (e.g., disable User Feedback Agent, drop inter‑agreement) and measure performance drop to quantify each part’s contribution.  
3. **Hyperparameter Sensitivity**: Sweep τc (model confidence threshold) and τcm (click model threshold) on a held‑out validation set to maximize NDCG@4; confirm optimal values on test set (as in Figure 3).

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: What are the long‑term operational costs and scalability limits of using multiple proprietary LLMs (e.g., GPT‑4o, Gemini) in the MRA module for large‑scale, real‑time annotation?  
- **Basis in paper**: [inferred] The MRA relies on multi‑LLM agreement for label reliability, but the paper focuses on performance gains without discussing economic or infrastructural constraints of continuous, high‑volume API calls to external models.  
- **Why unresolved**: The industrial deployment context (billions of requests) makes cost and latency critical, yet the analysis lacks any cost‑benefit trade‑off or stress‑testing under peak loads. The sustainability of this approach for smaller organizations or with future pricing changes is unknown.  
- **What evidence would resolve it**: A detailed economic analysis reporting API costs per annotated sample, latency distributions under production‑scale load, and comparisons against cheaper alternatives (e.g., open‑source model ensembles) while maintaining performance.

### Open Question 2
- **Question**: Can the thresholds for sample selection (τc, τcm) be dynamically adapted to different query stream characteristics (e.g., seasonality, topic emergence) to optimize the informativeness/volume trade‑off?  
- **Basis in paper**: [explicit] The paper selects fixed thresholds (τc=0.4, τcm=0.1) via validation on a static test set and states these are defaults for "subsequent self‑evolution experiments."  
- **Why unresolved**: Query streams are inherently dynamic; a static threshold may over‑ or under‑sample in different phases (e.g., during a viral event vs. stable periods). The paper does not investigate threshold sensitivity across time or propose an adaptive mechanism.  
- **What evidence would resolve it**: Experiments with adaptive threshold algorithms (e.g., based on recent distribution shift detection or feedback‑loop metrics) showing consistent performance gains across diverse, temporally segmented query streams compared to static thresholds.

### Open Question 3
- **Question**: What specific signals or metrics can reliably indicate that a self‑evolving model has reached a local optimum or begun degrading, enabling timely termination or intervention of the self‑evolution loop?  
- **Basis in paper**: [inferred] The paper shows performance saturation on a static test set after Iteration 3–5 for self‑training and diminishing returns for SERM, yet continues iterations. It mentions a newly collected test set ("testing‑v2") to assess ongoing evolution but provides no formal stopping criterion.  
- **Why unresolved**: Without a clear convergence or degradation signal, indefinite self‑evolution risks wasted computation, catastrophic forgetting, or drift. The paper demonstrates gains but does not analyze when the loop becomes counterproductive.  
- **What evidence would resolve it**: Defining and validating a set of monitoring metrics (e.g., rate of change in validation NDCG, disagreement between new and old model on a holdout set, annotation confidence decay) that correlate with eventual performance plateaus or drops on a truly held‑out, future‑dated test set.

### Open Question 4
- **Question**: How does the performance of the multi‑agent sample miner (MSM) compare to simpler, more efficient shift‑detection methods (e.g., embedding‑based clustering, novelty detection) in identifying truly informative samples for relevance evolution?  
- **Basis in paper**: [inferred] The MSM uses a composite of user feedback, click‑model, and intrinsic signals (disagreement/uncertainty) as a heuristic for "informative and challenging" samples. The contribution of each signal and their combinatorial necessity vs. more streamlined approaches is not isolated.  
- **Why unresolved**: The ablation study shows each agent contributes, but it doesn’t compare against potential simpler baselines that might achieve similar informativeness with lower computational overhead. The marginal benefit of the multi‑agent complexity is unclear.  
- **What evidence would resolve it**: A direct comparative evaluation where samples selected by the full MSM are replaced with those selected by:  
  1. A single strongest signal (e.g., model uncertainty alone).  
  2. A learned classifier for "growth potential" using features like prediction error, query novelty, etc.  
  Performance of models trained on these alternative sample sets would quantify the MSM’s unique value.

### Open Question 5
- **Question**: To what extent do the gains from SERM generalize beyond the specific LLM architectures (Qwen2.5) and multilingual families (Germanic, Romance, Minor) tested, particularly to low‑resource languages with drastically different scripts or morphologies?  
- **Basis in paper**: [explicit] The evaluation is explicitly on "Germanic, Romance, and Minor Language families" using Qwen2.5 models. The "Minor Language" group includes languages like Indonesian, Arabic, Japanese, Russian, but the paper does not break down results per language or discuss linguistic diversity limits.  
- **Why unresolved**: The paper asserts multilingual effectiveness but does not analyze variance within the "Minor" group or test on languages with minimal training data or non‑Latin scripts beyond the listed examples. The robustness of the multi‑agent agreement framework for languages where LLMs have known weaknesses is unexamined.  
- **What evidence would resolve it**: Fine‑grained per‑language performance reports for the "Minor" group, plus dedicated experiments on truly low‑resource languages (e.g., with <10 k training queries) comparing SERM’s annotation reliability and model improvement against baselines. Analysis of whether agreement rates between LLMs degrade for certain language families.

## Limitations
- **Proprietary data**: Exact sources of the 100 B token corpus and 3.6 M SFT pairs are undisclosed, preventing exact replication or public benchmarking.  
- **Cost and scalability**: Reliance on commercial LLMs (GPT‑4o, Gemini) for large‑scale annotation incurs high API costs and may introduce systematic biases; open‑source alternatives might behave differently.  
- **Tiny online KPI effects**: Reported improvements in user retention (+0.0359%) are extremely small, raising questions about practical significance versus implementation overhead.

## Confidence
- **MSM identifies informative samples**: Medium  
- **MRA provides reliable pseudo‑labels**: Medium  
- **Iterative self‑evolution avoids catastrophic forgetting**: High  
- **Overall NDCG@1 gain (+2.99)**: Medium
