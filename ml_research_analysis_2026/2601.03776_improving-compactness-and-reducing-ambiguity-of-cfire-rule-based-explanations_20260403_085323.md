# Improving Compactness and Reducing Ambiguity of CFIRE Rule-Based Explanations

## Quick Facts
- **arXiv ID:** 2601.03776
- **Source URL:** https://arxiv.org/abs/2601.03776
- **Reference count:** 6
- **Primary result:** ThresholdPruning reduces CFIRE rule set size by 31–45% and inter-class ambiguity by 32–47% (θ=0.05) with under 0.1% average F1 degradation, while safe pruning (θ=0) yields 4–15% size and 5–20% ambiguity reductions with zero F1 change.

## Executive Summary
CFIRE rule-based explanations often suffer from inter-class ambiguity, where multiple class rules apply to the same sample, reducing clarity. This paper introduces ThresholdPruning, a post-hoc method that removes rules with low win-counts (selection frequency in CFIRE's tie-breaking) under a performance tolerance threshold θ. Evaluated on 2,100 models across 14 tabular datasets using three local explainers, safe pruning (θ=0) reduces model size by 4–15% and ambiguity by 5–20% with zero F1 change on reference data. Moderate pruning (θ=0.05) achieves size reductions of 31–45% and ambiguity reductions of 32–47%, while limiting average F1 degradation to under 0.1%. These results demonstrate improved compactness and clarity with minimal fidelity loss.

## Method Summary
ThresholdPruning is applied after CFIRE generates its rule set. It calculates a win-count for each rule, representing how frequently that rule is selected during CFIRE's tie-breaking process across explained samples. Rules with win-counts below a threshold θ are removed. The threshold θ acts as a performance tolerance: higher θ removes more rules but risks fidelity loss. The method is post-hoc and does not modify CFIRE's core generation process, making it easily integrable.

## Key Results
- Safe pruning (θ=0) reduces rule set size by 4–15% and inter-class ambiguity by 5–20% with no change in F1 on reference data.
- Moderate pruning (θ=0.05) cuts size by 31–45% and ambiguity by 32–47%, with average F1 degradation under 0.1%.
- Across 2,100 models and 14 datasets, ThresholdPruning consistently improves compactness and clarity while maintaining high fidelity.

## Why This Works (Mechanism)
ThresholdPruning reduces ambiguity by eliminating rules that are rarely selected in tie-breaking (low win-count), which are likely redundant or conflicting with more dominant rules. By removing these, each sample is less likely to be covered by multiple class rules, thus clarifying explanations. Compactness improves because fewer rules remain, simplifying the rule set without sacrificing predictive performance when θ is chosen appropriately, as low win-count rules contribute little to CFIRE's decision-making.

## Foundational Learning
- **Rule-based explanations**: Models represented as IF-THEN rules; needed for interpretable, human-readable insights.
- **Inter-class ambiguity**: When rules from different classes apply to the same instance, confusing explanations; mitigated by pruning conflicting low-impact rules.
- **Win-count**: Frequency a rule wins tie-breaks in CFIRE; proxy for rule importance; used to filter non-essential rules.
- **Fidelity**: How well surrogate explanations mimic original model; measured via F1 on reference data; critical to ensure pruning doesn't distort model behavior.
- **Post-hoc pruning**: Modifying explanations after generation; allows flexibility without retraining explainer.
- **Performance tolerance (θ)**: Hyperparameter controlling trade-off between compactness and fidelity; higher values increase pruning aggressiveness.

Quick checks: Verify win-count distribution before pruning; test θ=0 as baseline; monitor fidelity metrics on held-out data.

## Architecture Onboarding
Component map:
CFIRE Rule Generator -> Win-Count Calculator -> Threshold Filter -> Pruned Rule Set

Critical path: CFIRE generates full rule set -> for each rule, compute win-count across explained samples -> apply θ threshold to discard rules with win-count ≤ θ -> output pruned rule set.

Design tradeoffs: Smaller θ preserves fidelity but less compactness; larger θ increases compactness but risks fidelity loss. Threshold chosen heuristically; no adaptive method provided.

Failure signatures: Sharp drop in F1 when θ too high; residual ambiguity if threshold too low; inconsistent across datasets due to varying rule distributions.

## Limitations
- Evaluations limited to 14 tabular datasets and three local explainers; generalizability to image/text data or other explainers (e.g., SHAP, LIME) is unknown.
- Fidelity measured only via F1 on reference data; robustness to other metrics (e.g., AUROC, faithfulness) or out-of-distribution samples not validated.
- Threshold θ chosen heuristically without theoretical bounds or adaptive strategies for different model complexities.

## Confidence
- **High**: Safe pruning (θ=0) consistently reduces size and ambiguity with zero F1 change across 2,100 models.
- **Medium**: Moderate pruning (θ=0.05) yields favorable average trade-offs, but worst-case variability across datasets/models not detailed.
- **Low**: Claims about broader applicability beyond tabular data or CFIRE's tie-breaking; theoretical justification for win-count thresholds absent.

## Next Checks
1. Test ThresholdPruning on non-tabular modalities (e.g., vision/text transformers) and alternative rule-based explainers to evaluate cross-domain generalizability.
