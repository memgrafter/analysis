# Lookahead identification in adversarial bandits: accuracy and memory bounds

## Quick Facts

- **arXiv ID:** 2603.00803
- **Source URL:** https://arxiv.org/abs/2603.00803
- **Reference count:** 40
- **Primary result:** Proposes lookahead best-arm identification in adversarial bandits; random window selection yields error ε = O(1/√log T) over Ω(√T) windows, CountSketch reduces memory to poly‑log under local sparsity, and regret minimization with poly‑log memory achieves Õ(T^{2/3} K^{1/3}), separating identification from regret.

## Executive Summary

The paper tackles the problem of lookahead best‑arm identification (BAI) in adversarial multi‑armed bandits, where the learner must commit to an arm that will be near‑optimal over a future prediction window. It introduces a simple yet effective algorithm that randomly selects a window and uniformly samples arms, achieving an identification error of ε = O(1/√log T) over Ω(√T) windows under an oblivious adversary and K = O(T^{1/4}). To address memory constraints, the authors exploit a natural local sparsity property: when the instance is locally ϕ‑sparse, they replace brute‑force accumulators with CountSketch, preserving the same accuracy while reducing memory to poly‑logarithmic size. For the complementary objective of regret minimization, they present a reduction to bounded‑memory expert learning that attains Õ(T^{2/3} K^{1/3}) regret with poly‑log memory, thereby establishing a sharp separation between the memory requirements of identification and regret. The analysis builds on density‑prediction techniques and recent advances in memory‑bounded online learning.

## Method Summary

The core methods are threefold. (1) For general lookahead BAI (Algorithm 1), the learner randomly picks a window length w = 2^{m/2} (with m in a logarithmic range) and a start time t₀; within a fixed window preceding t₀, arms are sampled uniformly and their rewards recorded. The arm with the highest empirical average over that window is returned. (2) To reduce memory, Algorithm 2 handles locally sparse instances (binary rewards) by streaming arm indices with reward = 1 into a CountSketch data structure; after the window, it queries the sketch for an arm whose estimated count is near‑maximal. (3) For regret minimization (Algorithm 3), time is divided into Q = Θ(T^{2/3} K^{1/3}/σ) blocks. A bounded‑memory expert learner supplies a distribution over arms with small support at the start of each block. Within the block, the algorithm randomly explores a few arms according to that support to estimate losses, constructs a sparse loss vector, and feeds it to the expert for the next distribution. This reduction yields Õ(T^{2/3} K^{1/3}) regret with poly‑log memory, contrasting with the linear memory needed for identification in general.

## Key Results

- **Lookahead BAI accuracy:** Random window selection with uniform arm sampling achieves identification error ε = O(1/√log T) over Ω(√T) windows, assuming K = O(T^{1/4}) and an oblivious adversary.
- **Memory reduction under sparsity:** Under a local sparsity condition, the same ε = O(1/√log T) accuracy is achievable using only poly‑logarithmic memory (via CountSketch); general instances require Ω(K) bits.
- **Regret with limited memory:** An algorithm with poly‑log memory achieves Õ(T^{2/3} K^{1/3}) regret, demonstrating a sharp separation between identification and regret objectives.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Random window selection with uniform arm sampling achieves identification error ε = O(1/√log T) over Ω(√T) windows in adversarial bandits.
- **Mechanism:** Sample m ∈ [⌈log T/2⌉, ⌈log T⌉] and b ∈ [⌊T/2ᵐ⌋]; set window w = 2ᵐ/² and start time t₀ = (b−1)·2ᵐ + w + 1. For each t in [t₀−w, …, t₀], pick an arm uniformly at random and record its reward. Output the arm with the highest empirical average over these w samples.
- **Core assumption:** Rewards are bounded in [0, 1]; the adversary is oblivious (fixed ahead of time); the number of arms K = O(T^{1/4}) for the bound to hold.
- **Evidence anchors:**
  • [Abstract] explicitly states the ε = O(1/√log T) guarantee over Ω(√T) windows.
  • [Section 2, Lemma 3] proves that for any sequence, the expected squared difference between averages over two nested windows is O(1/w), giving the estimation error.
  • [Corpus] indicates density‑prediction techniques (Drucker 2013) that inspired the analysis, though this work extends to multi‑arm bandits.
- **Break condition:** The bound relies on K = O(T^{1/4}); if many more arms are present, the Hoeffding concentration used in the proof fails. If the adversary is adaptive (non‑oblivious), the randomisation of t₀ and w may not suffice to protect against future manipulation.

### Mechanism 2
- **Claim:** Under a natural local sparsity condition, lookahead BAI attains the same O(1/√log T) accuracy using only poly‑logarithmic memory.
- **Mechanism:** Replace the brute‑force accumulators with CountSketch. In the chosen window, for each round if the observed reward equals 1, update the sketch with the arm index. At the end, query CountSketch for an arm whose estimated count is (1−ε′)-close to the maximum.
- **Core assumption:** Rewards are binary {0, 1} (the analysis can be extended to real‑valued rewards via weighted updates). The instance is locally ϕ‑sparse for the window size w ≥ √T: for every contiguous window of length w, the vector of arm sums satisfies ∥n∥₂² / n₁² ≤ ϕ.
- **Evidence anchors:**
  • [Abstract] highlights the memory improvement under local sparsity.
  • [Section 3, Definition 10] formalises local sparsity; [Theorem 14] gives the algorithm and its guarantee with memory Õ(ϕ).
  • [Corpus] references CountSketch (Charikar et al. 2004) as the underlying ApproxTop primitive.
- **Break condition:** If the instance is not locally sparse, CountSketch’s approximation error may exceed ε. The memory scales with ϕ, so a large ϕ (many arms with comparable sums) increases memory usage and may violate the poly‑log budget.

### Mechanism 3
- **Claim:** Regret minimisation in adversarial bandits can achieve sublinear regret Õ(T^{2/3} K^{1/3}) with poly‑logarithmic memory, separating it from identification which requires Ω(K) bits.
- **Mechanism:** Reduce bandit feedback to a bounded‑memory expert learner A (Peng & Rubinstein 2023). Partition T into Q = Θ(T^{2/3} K^{1/3}/σ) blocks. At the start of each block τ, obtain distribution pₖ (with small support) from A. Within block B_τ, pick a random set E_τ of exploration times uniformly from the support of pₖ; on these times play the corresponding arm to observe losses, otherwise sample from pₖ. Construct a loss vector ˆc_τ that is non‑zero only on the support (using losses from E_τ) and feed it to A to get p_{τ+1}.
- **Core assumption:** There exists a (σ, s)‑bounded expert learner achieving Õ(√(Q K/σ)) regret on Q rounds (the construction from Peng & Rubinstein 2023). The random exploration within each block provides unbiased loss estimates.
- **Evidence anchors:**
  • [Abstract] presents the regret bound and memory separation.
  • [Section 4, Theorem 17] details the algorithm and analysis.
  • [Corpus] cites prior lower bounds for memory‑bounded experts (Srinivas et al. 2022; Peng & Rubinstein 2023) that inform the construction.
- **Break condition:** If the expert learner A does not achieve its target regret, or if the block size Q is not chosen as Θ(T^{2/3} K^{1/3}/σ), the overall regret may be larger. The analysis also relies on uniform random sampling of exploration times; a biased schedule can inflate variance.

## Foundational Learning

### Density Prediction (Drucker 2013)
- **Why needed:** Provides the core probabilistic tool (binary‑tree averaging) to bound the error between averages over randomly shifted windows (Lemma 3). This underpins the accuracy of the random‑window identification scheme.
- **Quick check:** In the tree construction, what does the random variable Z(M−m) represent, and why does it equal the average of a contiguous block of size 2ᵐ?

### CountSketch (Charikar et al. 2004)
- **Why needed:** A succinct streaming algorithm for ApproxTop (heavy‑hitter identification). It reduces memory from O(K) to O(ϕ polylog) under the local sparsity condition, enabling the sparse‑bandit variant of lookahead BAI.
- **Quick check:** How does CountSketch use pairwise independent hash functions and random signs to turn collisions into cancellations, and what does the parameter ϕ = ∥n∥₂² / n₁² capture about the data stream?

### Bounded‑Memory Online Learner (Srinivas et al. 2022; Peng & Rubinstein 2023)
- **Why needed:** Serves as a black‑box in the regret algorithm (Algorithm 3). The learner maintains a distribution over arms with small support and limited memory while achieving sublinear regret in the full‑information expert setting.
- **Quick check:** What is the trade‑off between support size s, memory σ, and regret R(T) for such learners? Cite a concrete bound from Peng & Rubinstein (2023).

## Architecture Onboarding

### Component map
- *WindowSampler* → *ArmSampler* → (*Accumulator* | *CountSketchModule*) → *Selector*
- For regret: *BlockPartitioner* → *ExpertLearnerWrapper* → *ExplorationPlanner* → *LossEstimator* → *FeedbackLoop*

### Critical path
1. Initialise parameters (T, K, ε, etc.).
2. For identification: call WindowSampler → loop over window rounds with ArmSampler → update Accumulator/CountSketch → call Selector.
3. For regret: compute Q → for each block τ: get pₖ from A → sample E_τ → play arms (explore/exploit) → construct ˆc_τ → feed to A → repeat.

### Design tradeoffs
- **Window size vs. accuracy:** Larger w reduces variance (∝ 1/√w) but reduces number of usable windows (∝ √T). Algorithm picks w = Θ(√T) to balance.
- **Memory vs. sparsity:** CountSketch trades approximation error (ε′) for memory O(ϕ/ε′² polylog). Without sparsity, Ω(K) bits are unavoidable.
- **Block size in regret:** Q balances regret Õ(T^{2/3} K^{1/3}) and expert‑learner overhead; too small Q hurts regret, too large Q increases constants.
- **Exploration frequency:** At least s exploration steps per block are needed to estimate losses for the support of pₖ; insufficient exploration increases variance.

### Failure signatures
- **Identification:** Empirical error significantly > 20/√log T indicates violation of K ≤ O(T^{1/4}) or an adaptive adversary.
- **Sparse identification:** CountSketch returns a low‑count arm or memory overflow → ϕ larger than expected or instance not locally sparse.
- **Regret:** Observed regret ≫ Õ(T^{2/3} K^{1/3}) suggests the expert learner underperformed or exploration schedule was biased.
- **Memory overflow:** In sparse algorithm, a spike in ϕ (many arms with moderate sums) may exceed CountSketch’s space budget.

### First 3 experiments
1. **Uniform adversarial test for identification:** Generate random bounded sequences (oblivious adversary). Run Algorithm 1 across seeds; verify average error ≤ 20/√log T. Sweep K to observe degradation when K > T^{1/4}.
2. **Sparse instance test for memory reduction:** Construct instance with r ≪ K heavy arms (sum ≈ T) and others light (sum ≈ √T). Run Algorithm 2 with CountSketch; confirm heavy‑arm identification with high probability while using only Õ(r) memory. Test non‑sparse instance to see failure.
3. **Regret comparison and memory scaling:** Implement Algorithm 3 using the Peng‑Rubinstein expert learner. Benchmark against full‑memory exponential‑weights on a hard adversarial sequence. Verify Õ(T^{2/3} K^{1/3}) regret and poly‑log memory; measure memory scaling with K and T to confirm polylogarithmic growth.

## Open Questions the Paper Calls Out

1. **Tightness of sparse BAI memory bound?** Is the $\tilde{O}(\phi)$ memory upper bound for sparse lookahead BAI tight? The paper leaves open whether any algorithm needs $\Omega(\phi)$ memory. Evidence: an algorithm exists with poly‑log memory, but no lower bound beyond $\Omega(K)$. Resolving would require proving an $\Omega(\phi)$ (or at least $\Omega(\text{polylog}(KT))$) lower bound, or discovering an $o(\phi)$‑memory algorithm.

2. **Optimal regret with poly‑log memory?** For adversarial bandits with $O(\text{polylog}(KT))$ memory, is $\tilde{O}(T^{2/3} K^{1/3})$ regret optimal, or can the classic $O(\sqrt{KT})$ rate be maintained? The paper provides an algorithm achieving the former but does not know if it's best possible. Resolution would need a matching lower bound or a new algorithm with $\sqrt{KT}$ regret and poly‑log memory.

3. **Optimal identification error?** The gap between the lower bound $\Omega(1/\log T)$ and upper bound $O(1/\sqrt{\log T})$ for lookahead BAI error remains. Why it persists: both bounds are unchanged since the paper. Closing the gap would require improving either bound, e.g., showing $\Omega(1/\sqrt{\log T})$ or $O(1/\log T)$.

## Limitations

- The exact constants and hidden poly‑log factors in the bounds (e.g., dependence on $K$ in Theorem 2, conversion between $\phi$ and memory in Theorem 14, and the memory–support trade‑off in Theorem 17) are not provided, making precise parameterisation difficult.
- The extension of CountSketch to non‑binary rewards is asserted as "well‑known" without a formal proof; it is unclear how the local sparsity parameter $\phi$ applies to general bounded rewards.
- The regret reduction relies on an unspecified bounded‑memory expert learner (Peng & Rubinstein 2023); without concrete parameters, the claimed $\tilde{O}(T^{2/3} K^{1/3})$ bound cannot be independently verified.

## Confidence

- **Lookahead BAI accuracy (ε = O(1/√log T)):** High confidence (solid analysis, clear assumptions).
- **Memory reduction under local sparsity:** Medium confidence (depends on CountSketch extension for real‑valued rewards, which lacks full justification).
- **Regret bound with poly‑log memory:** Low confidence (critical dependence on an opaque bounded‑memory expert learner; trade‑off parameters not stated).
