# Kyrtos: A methodology for automatic deep analysis of graphic charts with curves in technical documents

## Quick Facts
- **arXiv ID:** 2602.09337  
- **Source URL:** https://arxiv.org/abs/2602.09337  
- **Reference count:** 40  
- **Primary result:** Achieves high SSIM (0.95–0.97 single-curve, 0.79–0.92 multi-curve) via clustering-based curve extraction and formal language analysis, invariant to curve width, color, and direction.

## Executive Summary
Kyrtos tackles the automatic deep analysis of curve-based charts in technical documents, a task limited by prior heuristic-based methods that struggle with varying curve properties. It introduces a two-module approach: first, a recognition pipeline that extracts curve line-segments from detected "unevenness points" using clustering; second, an analysis engine that interprets segment relations via a formal language to generate attributed graphs and Stochastic Petri Nets (SPNs). These representations encode both structural and behavioral features, enabling curve reconstruction. Evaluated on synthetic datasets, Kyrtos demonstrates robust accuracy across single- and multi-curve charts, showing promise for general application despite dependencies on heuristic thresholds.

## Method Summary
The method comprises recognition and analysis modules. Recognition preprocesses chart images with an HSV homogeneity filter to group similar colors, then traces each curve’s pixels and flags "unevenness points"—pixels where slope changes exceed a threshold *e*. Clustering (hierarchical followed by K-Means with elbow selection) groups these points, and cluster middle-points define line segments. Analysis applies heuristic merging rules (based on endpoint proximity and slope similarity) to combine segments, detects intersections between curves, and converts segments and their relations into attributed graphs. These graphs are linked to chart axes for growth-rate labeling, translated into natural-language sentences (A-V-P kernels), and mapped to SPNs where segments are places and relations are transitions. Curves are reconstructed from SPNs and compared to originals via SSIM.

## Key Results
- SSIM scores of 0.95–0.97 on single-curve charts and 0.79–0.92 on multi-curve charts (2–4 curves), with performance decreasing as curve count and complexity increase.
- Invariance to curve width, color, and direction, attributed to the middle-point approximation and formal relation analysis.
- Generates interpretable outputs: attributed graphs for structure and SPNs for behavior, enabling qualitative insights beyond pixel matching.

## Why This Works (Mechanism)
Kyrtos succeeds by decoupling curve extraction from relational analysis. Clustering middle-points from unevenness points provides a noise-resistant segment approximation, avoiding direct pixel-width heuristics. The formal language framework (Kyrtos) systematically encodes segment connections, parallels, and intersections, which are then materialized as graphs and SPNs. This abstraction allows robust reconstruction even when curves overlap or vary visually, as the SPN tokens (2D coordinates) preserve geometric fidelity. However, performance hinges on precise unevenness detection and merging, which currently rely on empirical thresholds and can be disrupted by axis interference or scanning direction biases.

## Foundational Learning
- **Unevenness point detection**: Identifies pixels where curve direction changes significantly; needed to approximate curves with piecewise linear segments. *Quick check*: Visualize flagged points—should align with inflection points and avoid axis lines.
- **Hierarchical clustering + elbow-based K-Means**: Groups unevenness points into curve-like clusters; needed to handle variable curve densities and lengths. *Quick check*: Plot distortion vs. *k*—elbow should correspond to visually distinct clusters along curves.
- **Attributed graphs**: Encode segments as nodes and relations (connections, parallels, intersections) as labeled edges; needed for structural analysis of chart topology. *Quick check*: Verify edges correctly represent segment adjacency and geometric properties.
- **Stochastic Petri Nets (SPNs)**: Model behavioral dynamics with places (segments), transitions (relations), and tokens (coordinates); needed to reconstruct curves from relational data. *Quick check*: Fire transitions to ensure token movement traces curve continuity.
- **HSV homogeneity filtering**: Preprocesses to separate chart elements by color dominance; needed to isolate curves from axes and backgrounds. *Quick check*: Confirm axes are suppressed while curve pixels retain coherence.
- **Slope-based merging heuristics**: Combine colinear or proximate segments; needed to reduce over-segmentation. *Quick check*: Merged segments should align smoothly with original curves without kinks.

## Architecture Onboarding
**Component map**: Input Image -> HSV Homogeneity Filter -> Unevenness Point Detection -> Clustering (Hierarchical + K-Means) -> Line Segments -> Merging Rules -> Intersection Detection -> Attributed Graph -> Axis Association -> NL Generation -> SPN Construction -> Curve Reconstruction -> SSIM Computation

**Critical path**: Recognition pipeline (HSV filter → unevenness points → clustering → segments) feeds into analysis (merging → intersections → graph/SPN → reconstruction). Errors in early clustering propagate to SPN fidelity.

**Design tradeoffs**: 
- Heuristic thresholds (e.g., clustering distance, merge criteria) trade adaptability for simplicity; may require per-dataset tuning.
- Color-based segmentation assumes clear hue separation; fails on grayscale or similar-colored curves.
- Middle-point approximation reduces noise but may smooth sharp corners.

**Failure signatures**: 
- Spurious unevenness points near axes (causing extra segments).
- Missing top-peak keypoints due to unidirectional tracing.
- Over-merging of distinct curves when parallel segments are incorrectly linked.

**First experiments**:
1. Sweep clustering distance thresholds (2–6 px) and merge slope tolerances on the synthetic dataset, measuring SSIM sensitivity.
2. Apply Kyrtos to a real-world chart dataset (e.g., ChartOCR) with ground-truth curves, comparing reconstruction SSIM against a baseline tracer (e.g., Potrace).
3. Ablate the HSV filter: replace with k-means color quantization, evaluate segment extraction accuracy and SSIM change.

## Limitations
- Parameter thresholds (clustering bounds, merge criteria, unevenness *e*) lack adaptive selection or theoretical derivation; curve width estimation is not described.
- HSV homogeneity filter implementation is underspecified—details on color dominance computation, axis-curve separation, and noise filtering are missing.
- Evaluation is limited to 150 synthetic multi-curve and 125 single-curve charts; no testing on noisy real technical documents with text or complex backgrounds.

## Confidence
- **Clustering-based segment extraction**: *Medium* (plausible but parameter guidance absent; axis interference noted).
- **Formal language analysis and SPN generation**: *Medium* (high-level description; conversion specifics vague).
- **Reported SSIM and invariance claims**: *Medium* (strong synthetic results but generalizability to real charts unverified; threshold sensitivity not reported).
