# Starting Off on the Wrong Foot: Pitfalls in Data Preparation

## Quick Facts
- **arXiv ID:** 2603.18190  
- **Source URL:** https://arxiv.org/abs/2603.18190  
- **Reference count:** 40  
- **Primary result:** InformedAutoML reduces estimation error and improves performance on imbalanced insurance data via distributionally consistent splitting and robust feature screening.

## Executive Summary
The paper tackles critical data preparation challenges in insurance analytics, where random train-test splits and standard feature selection fail under class imbalance and missing data. It introduces a unified framework, InformedAutoML, that replaces random splitting with support points to maintain distributional stability, uses the non‑parametric Chatterjee correlation coefficient for reliable feature screening, and integrates MissForest imputation for missing values. Empirical evaluations on simulated Tweedie loss data demonstrate dramatic reductions in coefficient estimation error, while real‑world tests show superior predictive accuracy and up to fivefold runtime improvements over conventional AutoML. The work underscores that statistically rigorous preprocessing is not merely a preliminary step but a core contributor to model reliability and efficiency.

## Method Summary
InformedAutoML, also referred to as the IDPP (Informed Data Preparation Pipeline), comprises two parallel preprocessing branches. The complete‑case branch (IDPP_comp) discards rows with missing values, applies Chatterjee correlation feature screening, and splits the data using support points. The missing‑data branch (IDPP_miss) first eliminates features with excessive missingness, imputes remaining missing entries via MissForest, screens features with the Chatterjee coefficient, and also splits using support points. Both branches then feed the processed data into a model‑only AutoML optimizer. For prediction, a simple aggregation rule selects the model from the missing‑pipeline if the new input contains any missing values; otherwise it averages the predictions from both pipelines.

## Key Results
- On simulated Tweedie data, IDPP_miss lowered coefficient MAE substantially (e.g., from 0.0973 to 0.0356 under MAR).
- The pipeline retained more informative features even when missingness exceeded 70%.
- Across two real insurance datasets, InformedAutoML achieved lower test MSE/RMSE and speedups of up to 5× compared to standard AutoML.

## Why This Works (Mechanism)

### Support Points for Distributionally Consistent Splitting
- **Claim:** Support points produce a train‑test split that preserves the full data distribution, yielding more stable performance estimates than random splits, especially for imbalanced insurance data.
- **Mechanism:** By minimizing the energy distance between a candidate test set and the full dataset, the chosen test points are both close to the original distribution (low divergence) and well‑spread among themselves (high dispersion). This quasi‑Monte Carlo selection reduces variance in error estimation.
- **Core assumption:** The full dataset is an IID sample from the underlying distribution F, and energy distance is an appropriate discrepancy measure for the modeling task.

### Chatterjee Correlation Coefficient for Robust Feature Screening
- **Claim:** The Chatterjee correlation coefficient (CCC) and its multivariate extension (ACCC) provide a non‑parametric, distribution‑free measure of feature‑response dependence, capturing both linear and nonlinear relationships without strict distributional assumptions, which is crucial for zero‑inflated insurance losses.
- **Mechanism:** CCC ranks the response y and examines the concordance of consecutive ranks after ordering the feature X. ACCC extends this by incorporating nearest‑neighbor ranks in the full feature space. The resulting statistic ranges from –1 to 1 and is zero under independence.
- **Core assumption:** The underlying dependence structure is reflected in the rank ordering of y relative to X (or k‑nearest neighbors), and ties can be adequately handled (e.g., by averaging over random tie‑breaks).

### MissForest Imputation for Missing Values
- **Claim:** MissForest imputation, embedded within the informed pipeline, recovers missing values non‑parametrically, preserving complex feature interactions and reducing bias relative to simple imputation, particularly under MAR and even some MNAR scenarios.
- **Mechanism:** Iterative random‑forest imputation: initial guesses (e.g., mean) are used to train a random forest for each feature with missing values; predicted values replace missing entries; process repeats until convergence, capturing non‑linearities and interactions.
- **Core assumption:** The missingness mechanism is at least MAR (conditionally on observed data, missingness independent of unobserved values) and the imputation model is flexible enough to approximate the true conditional distribution.

## Architecture Onboarding

**Component map**  
The system consists of two data preparation pipelines –  
IDPP_comp (complete‑case selection, CCC feature screening, SPlit) and  
IDPP_miss (missing‑rate feature selection, MissForest imputation, CCC screening, SPlit) –  
and a model‑only AutoML optimizer. Input data with missing values are routed through both pipelines; the trained models are combined via a prediction aggregation rule that selects the missing‑pipeline model for incomplete inputs and averages both models otherwise.

**Critical path**  
For a new dataset:  
compute missing rates to select features → apply imputation if needed → compute CCC scores → threshold to select features → compute support points for the selected data → split into train/validation → run model optimization → repeat for both pipelines (if missing values present) → define final predictor using aggregation rule.

**Design tradeoffs**  
- Extra hyperparameters (missing threshold, CCC threshold, MissForest parameters) increase joint tuning cost but improve performance.  
- Preprocessing flexibility is reduced (fixed encoding, scaling) to gain efficiency and robustness.  
- Complete‑case branch discards data under high missingness; imputation preserves data but may introduce noise if the imputation model is misspecified.

**Failure signatures**  
1. Unstable CCC estimates: large variation across random seeds, especially with many ties.  
2. Support points failing to converge: indicates numerical issues or extremely large N.  
3. Discrepancy between complete‑case and missing‑pipeline performance on overlapping complete observations suggests imputation bias.  
4. Aggregated predictions having higher error than either individual model indicates poor complementarity or over‑averaging.

**First 3 experiments**  
1. **Simulation recovery:** Generate Tweedie data with known coefficients under MCAR/MAR/MNAR. Apply IDPP_comp and IDPP_miss. Confirm IDPP_miss yields lower coefficient MAE under high missingness (≥70% row‑missing).  
2. **Complete‑data benchmark:** On ausprivauto (no missingness), run InformedAutoML vs. InsurAutoML. Expect comparable or lower test MSE and ~4× speedup from removing random preprocessing search.  
3. **Missing‑data aggregation:** On the Pell Grant dataset, compare InformedAutoML’s test RMSE on the complete subset, the missing subset, and the aggregated overall prediction. Expect InformedAutoML to outperform InsurAutoML on both subsets and on the combined test set.

## Open Questions the Paper Calls Out
1. **Can IDPP components (support points, CCC, MissForest) be scaled efficiently to very large insurance datasets?**  
   - *Basis in paper:* Explicitly identified as a key limitation.  
   - *Why unresolved:* No scalable solutions proposed; experiments only on datasets up to tens of thousands of records.  
   - *What evidence would resolve it:* Scalable approximations or parallel implementations that preserve statistical properties, validated on big data (e.g., >1M rows) with speedup and memory usage measurements.

2. **How can model optimization in InformedAutoML incorporate statistical knowledge (e.g., Tweedie, heavy tails) to improve efficiency and interpretability?**  
   - *Basis in paper:* Authors note the model optimization stage remains data‑driven and could benefit from statistically informed mechanisms.  
   - *Why unresolved:* Current AutoML treats model selection as black‑box; no domain priors or custom loss functions for insurance.  
   - *What evidence would resolve it:* Design of prior‑embedded search spaces or insurance‑specific objectives, showing fewer trials needed and better alignment with domain expectations.

3. **How can downstream modeling explicitly handle the outcome imbalance (excess zeros, heavy tails) that persists after IDPP?**  
   - *Basis in paper:* Authors state that downstream modeling does not explicitly account for imbalance and that targeted strategies may enhance performance.  
   - *Why unresolved:* Standard regression minimizes MSE, which may not focus on rare high‑severity claims; no imbalance‑aware methods integrated into model‑only AutoML.  
   - *What evidence would resolve it:* Integration of imbalance‑sensitive losses (e.g., quantile, focal) or sampling within AutoML, evaluated with tail risk metrics and calibration improvements.

## Limitations
- **Scalability:** Support points require O(N²) energy‑distance minimization; performance and variance‑reduction benefits for very large N are untested.
- **CCC stability:** Many tied values (e.g., zero‑inflated outcomes) can destabilize Chatterjee correlation estimates; averaging over random tie‑breaks may not fully mitigate variance.
- **Generality:** Validation is limited to two real datasets; robustness across diverse insurance domains, high‑dimensional feature spaces, and varied missingness mechanisms remains unknown.

## Next Checks
1. **Scalability test for support points:** Apply IDPP to a ≥100k‑row insurance dataset. Record computation time and performance stability across multiple random seeds; compare against random splits.
2. **CCC robustness under extreme sparsity:** Simulate responses with >90% zeros and high‑cardinality features. Compute CCC repeatedly with different tie‑breaking seeds; measure variance and correlation with known dependencies; benchmark against Hoeffding’s D and mutual information.
3. **Ablation against alternatives:** On 3+ public insurance datasets with missingness, replace one component at a time (e.g., MICE for MissForest, Boruta for CCC, random split for support points) while keeping AutoML constant. Compare test error, runtime, and feature retention to quantify each component’s contribution.
