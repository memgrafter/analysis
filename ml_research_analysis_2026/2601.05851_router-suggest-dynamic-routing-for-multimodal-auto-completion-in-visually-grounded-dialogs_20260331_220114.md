# Router-Suggest: Dynamic Routing for Multimodal Auto-Completion in Visually-Grounded Dialogs

## Quick Facts
- **arXiv ID**: 2601.05851
- **Source URL**: https://arxiv.org/abs/2601.05851
- **Reference count**: 30
- **Primary result**: Router-Suggest achieves 2.3–10× speedup over the best VLM while matching performance via dynamic routing between textual and multimodal models.

## Executive Summary
This paper introduces Multimodal Auto-Completion (MAC), a task that predicts a user’s next utterance in a visually-grounded dialog given a partial text prefix and the multimodal dialog history (text and images). The authors build MAC benchmarks from MMDialog and ImageChat by filtering for visual relevance using GPT-4V. Evaluations show that fine-tuned vision-language models (VLMs) far exceed traditional textual baselines (MPC, QB) on metrics like Partial-F1 and Typing Effort Saved. To address VLM latency, they propose Router-Suggest, a framework that dynamically chooses between a lightweight textual model and a VLM per input prefix using a cost-sensitive neural router. This yields up to 10× speedup with minimal accuracy loss. A user study confirms that VLMs improve both objective efficiency (TES) and subjective satisfaction, validating the practical value of multimodal grounding.

## Method Summary
The authors construct MAC datasets by applying GPT-4V to MMDialog (MMDD) and ImageChat, retaining only samples where the image is relevant to the dialog turn (score ≥4). Data are formatted as a multimodal history (interleaved image and text tokens), a partial prefix, and the gold completion (obtained by splitting the last utterance). Baselines include a trie-based Question Bot (QB) and a neural MPC model. VLMs (MiniCPM-V, PaliGemma, Qwen2-VL) are fine-tuned for 5 epochs with LoRA (rank 8, dropout 0.05), batch size 8, and learning rate 1e-4. Evaluation uses Partial-F1 (primary), Trigger Rate, Syntactic Match, and Typing Effort Saved (TES). Router-Suggest employs a lightweight neural classifier that consumes 768D embeddings from EmbeddingGemma-300m of the prefix. It is trained with a cost-sensitive loss `L = (1−λ)L_CE + λL_cost`, where `L_cost` scales with the candidate model’s average latency. The router selects among QB and the VLMs. A user study measures TES and satisfaction in an interactive setup.

## Key Results
- VLMs (MiniCPM-V) achieve the highest Partial-F1 (0.247 on MMDD) and significantly outperform textual baselines.
- Router-Suggest variants attain large speedups: Router-4-L matches MiniCPM-V’s Partial-F1 (0.240) at 5× lower latency; Router-2-L (4GB GPU) provides a 10× speedup with minimal performance drop.
- The user study shows VLMs yield higher TES and user satisfaction than textual models, confirming the benefit of multimodal context.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Multimodal context (image + dialog history) disambiguates partial text prefixes, leading to more accurate and relevant completions than text-only models.
- **Mechanism**: The MAC task conditions completion generation on both the typed prefix and the multimodal history. A vision-language model processes interleaved image and text tokens, allowing visual grounding to influence token prediction for the continuation. Textual models see only the prefix and must rely solely on dialog text.
- **Core assumption**: The visual content in the dialog history is *causally relevant* to the user's intended next utterance, providing information not inferable from text alone.
- **Evidence anchors**: Abstract states MAC grounds predictions in multimodal context; Section 3.1 defines input/output; neighboring papers on affective visual dialog support the research consensus on visual grounding.
- **Break condition**: When the image is irrelevant or contradictory (as filtered by GPT-4V) or too ambiguous to offer a disambiguating signal.

### Mechanism 2
- **Claim**: A lightweight neural router can dynamically select between a fast textual model and a slower but more accurate VLM per input prefix, achieving a favorable latency-accuracy trade-off for real‑time deployment.
- **Mechanism**: The router uses a small classifier (e.g., MLP) that takes a 768D embedding of the prefix and predicts which candidate model (QB, Qwen2-VL, PaliGemma, MiniCPM-V) will achieve the highest partial‑F1. Training optimizes a combined loss: `L = (1−λ)L_CE + λL_cost`, where `L_cost` is proportional to the model’s average inference latency and λ controls the cost‑accuracy trade‑off.
- **Core assumption**: Prefix embedding features predict the *relative performance* of candidate models for that prefix. The cost‑weighted objective reliably translates into real‑world latency savings without catastrophic accuracy drops.
- **Evidence anchors**: Abstract reports 2.3×–10× speedup; Section 3.4 describes router training; Table 3 shows Router-4-L matches MiniCPM-V’s PR‑F1 at 5× lower latency.
- **Break condition**: If the prefix distribution at deployment shifts (new domains, typing patterns), the router may consistently mis‑rank models, causing either wasted latency or severe accuracy drops.

### Mechanism 3
- **Claim**: User satisfaction and self‑reported typing effort saved (TES) in interactive MAC systems are significantly higher when using VLMs compared to textual‑only models, validating the utility of multimodal grounding.
- **Mechanism**: A user study compares models (MPC, QB, MiniCPM-V, Router-2-L) in an interactive platform where users type continuations for shown prefixes and rate the alignment of suggestions. TES is calculated relative to the final user‑approved text. Positive correlation between TES and user ratings across models suggests TES is a valid proxy for perceived utility.
- **Core assumption**: The controlled study elicits genuine preferences and TES reliably captures typing efficiency gains that correlate with satisfaction.
- **Evidence anchors**: Abstract cites higher TES and satisfaction; Section 5 reports MiniCPM‑V achieves highest TES and stable experience; neighboring work on user‑centric dialog metrics provides context.
- **Break condition**: If the user pool is unrepresentative or if inline completion interaction fundamentally changes, the observed TES‑satisfaction correlation may not generalize. Also, user adaptation to suggestions may inflate TES circularly.

## Foundational Learning
### Concept: Multimodal Dialog Understanding
- **Why needed**: To grasp how visual information integrated into a conversational history influences linguistic intent and disambiguates partial user input.
- **Quick check**: Given an image of a dog in a park and the prefix “I love bringing my __”, why might a text‑only model fail while a VLM succeeds?

### Concept: Sequence‑to‑Sequence Generation for Inline Completion
- **Why needed**: MAC is mid‑utterance continuation, not next‑utterance prediction. The model must generate a coherent suffix for a partial string conditioned on a long context without restarting from the dialog beginning.
- **Quick check**: How does the training “unrolling” and “splitting” procedure (Section 4.2) create valid (prefix, completion) pairs from a full dialog turn?

### Concept: Latency‑Accuracy Trade‑offs in Model Serving
- **Why needed**: VLMs are computationally expensive. The core engineering problem is deciding *when* to invoke a VLM vs. a cheap textual model to meet real‑time interaction constraints.
- **Quick check**: If a VLM gives 5% higher PR‑F1 but is 20× slower than a textual model, what factors determine if it’s “worth” using for a given prefix?

## Architecture Onboarding
- **Component map**: Input Processor -> Candidate Models -> Feature Extractor -> Router Classifier -> Orchestrator
- **Critical path**:  
  1. User types characters; system buffers current prefix `p`.  
  2. Once `p` meets length/confidence threshold, Feature Extractor computes `emb(p)`.  
  3. Router Classifier predicts `argmax_m p_m`.  
  4. Orchestrator invokes chosen model `M_i` with full context (prefix `p`, dialog history `H_mm`, associated images).  
  5. Model `M_i` generates completion `c` auto‑regressively until stop token or max length.  
  6. Completion `c` is displayed to user. Steps 2–5 must complete within ~100–200 ms for real‑time feel.
- **Design tradeoffs**:  
  - Router capacity vs. overhead: Deeper router may make better decisions but adds its own latency; keep it tiny (~1–2 layers) to target near‑zero overhead.  
  - Number of candidates (`n`): More models (e.g., Router‑4) offer finer latency‑quality granularity but increase router complexity and memory footprint (25 GB vs. 4 GB for Router‑2).  
  - Loss weight `λ`: Higher `λ` forces the router to favor low‑latency models more aggressively, risking accuracy drops on complex prefixes. Tuning per deployment latency budget is critical.  
  - Feature representation: Choice of embedding model (EmbeddingGemma‑300m) is fixed in the paper; using a different extractor alters the trade‑off.
- **Failure signatures**:  
  - High latency, low accuracy: Router frequently selects a VLM for prefixes that textual models could handle (poor cost‑sensitive training or `λ` too low).  
  - Low latency, very low accuracy: Router over‑selects textual models (QB), especially on visually complex prefixes (insufficient hard examples in training).  
  - Inconsistent `p_m` distributions: For similar prefix embeddings, router outputs wildly different choices (router under‑capacity or poor feature extraction).  
  - User study discrepancy: Offline PR‑F1 gains from routing do not translate to TES/satisfaction gains (offline metric may not capture when suggestions appear or subtle quality nuances).
- **First 3 experiments**:  
  1. **Baseline Individual Evaluation**: Run all candidate models (textual and VLM) on the unseen‑prefix test set of MMDD/ImageChat. Compute PR‑F1, SM, TES, and average latency per model. Establish the Pareto frontier of (latency, accuracy) for the model pool.  
  2. **Router Training Validation**: Train router with `λ=0` (accuracy‑only). On a validation set, check if router’s top‑1 prediction matches the model with highest actual PR‑F1 for that prefix (the “oracle” choice). Accuracy should be high (>80%?). Then sweep `λ` and measure the expected cost `E[cost]` on validation to confirm cost‑awareness.  
  3. **End‑to‑End Routing Simulation**: For a sample of prefixes, simulate the Router‑Suggest system: use router’s prediction to select model, add its latency to total, accumulate its PR‑F1. Plot the overall (latency, PR‑F1) point for different `λ` configurations (as in Figure 3). Verify that desired configurations (e.g., Router‑4‑L) hit target latency with minimal PR‑F1 drop from the best individual VLM.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can we reduce selection bias and increase linguistic diversity in MAC benchmarks derived from GPT‑4V filtering?
- **Basis**: Limitations section states benchmarks “may introduce selection bias toward visually explicit cases and lack linguistic diversity” due to GPT‑4V filtering.
- **Why unresolved**: Automated filtering likely favors certain visual contexts, and diversity metrics are unaddressed, risking unrepresentative evaluations.
- **What evidence would resolve it**: Curate a benchmark with manual annotations or stratified sampling across diverse images and linguistic styles, then compare model performance dispersion.

### Open Question 2
- **Question**: How can MAC be extended to handle multi‑image or video‑based dialogs, moving beyond single‑image contexts?
- **Basis**: Limitations note “current datasets only cover single‑image contexts, limiting generalization to real‑world multimodal settings with evolving or multiple visuals.”
- **Why unresolved**: Real conversations often involve sequential or multiple visuals; the task definition and models are not designed for this.
- **What evidence would resolve it**: Develop a multi‑image MAC dataset, adapt models to process image sequences (e.g., via temporal attention), and evaluate on unseen multi‑image dialogs.

### Open Question 3
- **Question**: How can Router‑Suggest’s routing decisions be made interpretable without compromising latency efficiency?
- **Basis**: Limitations state the router “lacks interpretability in its routing choices” and may degrade under domain shift.
- **Why unresolved**: Opaque routing hinders debugging, user trust, and fairness audits in deployment.
- **What evidence would resolve it**: Integrate post‑hoc explainers (e.g., SHAP) or design intrinsically interpretable routers, then measure latency impact and human understanding via user testing.

### Open Question 4
- **Question**: Beyond Typing Effort Saved (TES), what multi‑dimensional metrics better capture user satisfaction and safety in MAC systems?
- **Basis**: Ethical Considerations note TES “can fail to capture subtle misinformation, cultural or demographic mismatches,” and the user study uses a small, potentially biased pool.
- **Why unresolved**: TES focuses on keystroke reduction but ignores output quality, bias, and holistic user experience.
- **What evidence would resolve it**: Conduct large‑scale, diverse user studies correlating TES with metrics like accuracy, toxicity, fairness, and subjective satisfaction, then identify robust predictors.

## Limitations
- Exact train/test splits and GPT‑4V filtering prompt reproducibility are unknown, risking dataset mismatch.
- Router neural classifier architecture (layers, activations) and precise λ values are underspecified, hindering exact replication.
- User study generalizability is uncertain due to unreported participant demographics and potential circularity in TES calculation.
