# What Users Leave Unsaid: Under-Specified Queries Limit Vision-Language Models

## Quick Facts
*   **arXiv ID:** 2601.06165
*   **Source URL:** https://arxiv.org/abs/2601.06165
*   **Reference Count:** 31
*   **Primary Result:** Real-world underspecified queries cause major VLM failures; explicit rewrites improve scores by 8-22 points, and web search cannot compensate for missing context.

## Executive Summary
Vision-language models (VLMs) struggle with real-user queries that are often underspecified, relying on implicit image context. Existing benchmarks use clear, explicit prompts, creating a performance gap. This study introduces HAERAE-Vision, a benchmark of 653 authentic Korean questions from online communities, each with an explicit rewrite. Evaluating 45 VLMs with and without web search reveals that even top models score under 50% on original queries. Explicitating queries yields substantial gains (8-22 points), with the largest improvements for smaller models. Critically, providing web search does not close the gap; original+search still underperforms explicit-only, proving retrieval cannot resolve missing textual context. After explicitation, the remaining errors primarily stem from culturally specific knowledge gaps embedded in the Korean context.

## Method Summary
The authors constructed HAERAE-Vision by collecting 653 authentic Korean image+query pairs from online communities. Each original underspecified query was rewritten by GPT-5.1 into an explicit, self-contained version, yielding 1,306 total data points. Model responses are evaluated against a GPT-4-generated checklist of required answer criteria via an LLM judge (GPT-5-Mini). Evaluation is run across 45 VLMs in two settings: with and without web search augmentation. The analysis isolates the impact of query ambiguity, the efficacy of search, and the nature of residual errors (e.g., cultural knowledge) through controlled comparisons between original and explicit query splits.

## Key Results
*   Top models (GPT-5, Gemini 2.5 Pro) achieve <50% on original underspecified queries; explicit rewrites boost performance by 8-22 points.
*   Smaller models benefit most from explicitation (e.g., GPT-5-Nano +21.7 points).
*   Original queries with web search still underperform explicit-only queries, demonstrating that text-based retrieval cannot compensate for missing query context.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** Explicitating under-specified queries substantially improves VLM performance by grounding ambiguous references in explicit textual context.
*   **Mechanism:** The task shifts from inferring missing context (requiring complex multimodal reasoning) to directly extracting information from a clear prompt, reducing cognitive load.
*   **Evidence:** Gains of 8-22 points across 45 models (abstract, Fig 5, Table 3); largest gains for smaller models support the inference burden hypothesis.
*   **Break condition:** Query is fully self-contained, removing reliance on image-based context inference.

### Mechanism 2
*   **Claim:** Web search augmentation cannot compensate for query under-specification because the model cannot formulate effective, grounded search queries without explicit textual context.
*   **Mechanism:** Vague queries lack concrete nouns/searchable terms, yielding irrelevant results. Search efficacy is gated by the model's ability to first understand *what* to search for, which requires explicit context.
*   **Evidence:** Original+Search consistently underperforms Explicit-NoSearch for both GPT-5 and GPT-5-Mini (Table 3, Section 6.2).
*   **Break condition:** Query includes explicit, searchable terms accurately reflecting visual context and intent.

### Mechanism 3
*   **Claim:** After resolving surface-level ambiguity, the remaining dominant failure mode is a lack of culturally specific knowledge embedded in the image or context.
*   **Mechanism:** HAERAE-Vision contains items requiring familiarity with Korean local services, UI conventions, or region-specific objects. Global VLMs lack this grounded, locale-specific knowledge.
*   **Evidence:** After explicitation, cultural knowledge attribution as a root cause increases (+6.4pp) with examples like Korean winter road sandbags or the SKY IM-100 phone (Section 6.3).
*   **Break condition:** Model possesses sufficient training on culturally specific, image-grounded data relevant to the query's locale.

## Foundational Learning
*   **Concept: Multimodal Grounding**
    *   **Why needed:** The core problem is aligning vague textual references ("this," "that") with specific visual regions and concepts. Engineers must understand how VLMs associate language with visual entities.
    *   **Quick check:** Given an image of a unique Korean street food and the query "How much is this?", what architectural components allow a VLM to resolve "this" to the correct food item?
*   **Concept: Query Ambiguity Taxonomy**
    *   **Why needed:** Not all underspecification is equal. The paper distinguishes vagueness, missing domain context, and cultural opacity. Classifying types helps design targeted interventions.
    *   **Quick check:** Classify "How do I do this?" vs. "How do I remove the margin border...?" into ambiguity types. What system change best resolves each?
*   **Concept: Culture as a Multimodal Signal**
    *   **Why needed:** Cultural knowledge is encoded in visual styles, UI layouts, and local products. Engineers must consider how to embed this non-universal knowledge without overfitting.
    *   **Quick check:** Why might a globally trained VLM fail on a photo of a Seoul Metro signage map even with the explicit query? What data source could help?

## Architecture Onboarding
*   **Component map:** Input Encoder (image & text) -> Query Analyzer (ambiguity detection) -> Context Resolver / Rewriter -> Multimodal Reasoning Core -> (Optional) Retrieval Augmentation -> Response Generator.
*   **Critical path:** Text prompt -> Query Analyzer flags ambiguity -> triggers internal resolution OR query rewrites -> resolved query + image features -> Reasoning Core -> Answer against checklist criteria -> Output.
*   **Design tradeoffs:**
    *   Explicitation-in-training vs. inference-time clarification: Pre-training may improve robustness but loses naturalness; inference rewriting adds latency.
    *   Static knowledge vs. retrieval: Fine-tuning on cultural data vs. search. Paper shows search fails without explicitation, suggesting knowledge must be *grounded* in parameters.
    *   Universal vs. specialized models: Single global model vs. region-specific adapters. Poor performance of Korean-specialized models (VARCO, HyperCLOVA) suggests specialization without scale may backfire.
*   **Failure signatures:**
    *   Over-reliance on prompt keywords without visual grounding.
    *   Search invoked but based on poor query formulation, returning generic results.
    *   Checklist failures on criteria requiring specific cultural terms (e.g., naming "ᄉ ᅥ ᆨᄀ ᅩ테 ᆨᄉ ᅳ"/gypsum board).
*   **First 3 experiments:**
    1.  **Replication of Explicitation Gain:** Run original vs. explicit HAERAE-Vision splits. Expect ~10-22 point gain, largest for smaller models (<10B).
    2.  **Search Under-specification Test:** For a subset, run with/without search. Validate: `Original+Search < Explicit-NoSearch`. If false, search integration is superficial.
    3.  **Cultural Knowledge Isolation:** Filter for "culturally grounded" items (23.7%). Evaluate on explicitated versions only. Expect low scores (~20-30%), isolating the cultural gap.

## Open Questions the Paper Calls Out
*   **OQ1:** How does the performance gap between original and explicitated queries vary across languages with different cultural specificity or writing conventions? The paper only evaluates Korean.
*   **OQ2:** What specific categories of Korean cultural knowledge are most frequently missing after explicitation, and can targeted data augmentation reduce these errors? The paper identifies the trend but not the breakdown.
*   **OQ3:** Why do text-based web search integrations fail to close the gap, and would truly multimodal retrieval (e.g., querying an indexed image corpus) better compensate? The study only tests OpenAI’s text-based search API.
*   **OQ4:** Do LLM-generated checklists introduce systematic evaluation biases compared to human-written rubrics for underspecified VQA? The paper acknowledges potential LLM-judge bias.
*   **OQ5:** Why do smaller VLMs exhibit larger relative gains from query explicitation? Is it a fundamental limit in inferring implicit context or a data distribution mismatch? The paper suggests capacity but doesn't disentangle factors.

## Limitations
*   **Dataset Scope:** Korean-only (HAERAE-Vision). Generalizability to other languages/cultures is uncertain.
*   **Rewrite Process:** GPT-5.1 generated explicit variants; inherent model biases may shape the "explicitation" and gap magnitude.
*   **Scoring Reliance:** Checklist-based evaluation may miss nuanced failures not captured by criteria, despite high inter-judge agreement (α=0.867).

## Confidence
*   **Explicitation Improves Performance:** **High** (robust across 45 models, consistent gains).
*   **Search Cannot Compensate for Underspecification:** **High** (direct comparison shown repeatedly).
*   **Remaining Errors are Cultural:** **Medium** (supported by item analysis, but "cultural" attribution may conflate other gaps).

## Next Checks
1.  **Cross-Lingual Replication:** Run original/explicit splits on a non-Korean underspecified benchmark (e.g., RealFin). Validate if explicitation gain magnitude holds.
2.  **Search Query Analysis:** Log exact search queries generated for original vs. explicit prompts. Quantify keyword specificity and result relevance to confirm the "ungrounded query" hypothesis.
3.  **Cultural Diagnostic Subset:** Manually curate a high-purity "culturally specific" subset from HAERAE-Vision. Re-evaluate top models to isolate the minimum expected cultural knowledge failure rate.
