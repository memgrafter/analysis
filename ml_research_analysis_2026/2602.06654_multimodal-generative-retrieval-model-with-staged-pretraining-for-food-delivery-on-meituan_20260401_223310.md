# Multimodal Generative Retrieval Model with Staged Pretraining for Food Delivery on Meituan

## Quick Facts
- **arXiv ID**: 2602.06654
- **Source URL**: https://arxiv.org/abs/2602.06654
- **Reference count**: 40
- **Primary result**: Staged pretraining with semantic IDs yields +3.80% R@5 and +1.12% online revenue over state-of-the-art baselines.

## Executive Summary
This paper presents SMGR, a multimodal generative retrieval system for food delivery that addresses two key challenges: modality neglect and the one-epoch problem in joint optimization. The authors propose a staged pretraining strategy that sequentially trains unimodal and cross-modal tasks before end-to-end fine-tuning, and introduce semantic IDs (SIDs) generated via RQ-VAEs to associate discrete tokens with item semantics. Evaluated on Meituan’s massive real-world dataset, SMGR achieves significant offline improvements in retrieval metrics and online gains in revenue and click-through rate.

## Method Summary
SMGR employs a dual-tower architecture with separate text and image encoders (Qwen3-0.6B and ViT respectively), each projecting to a 128-dimensional space. Pretraining consists of four sequential stages: query-to-text, image-to-text, query-to-image, and finally query-to-item contrastive learning using InfoNCE loss. This staged approach prevents any single modality from dominating and aligns training speeds across modalities. For efficient retrieval, semantic IDs are generated by training residual-quantized VAEs (3 layers, 32 codes each) on high-dimensional embeddings of text, image, and their fusion. The SIDs are concatenated and incorporated as side information during fine-tuning, which combines discriminative objectives (doc2docid, query2item contrastive) and generative ones (causal prediction of query tokens with and without SIDs). The final model retrieves items by computing similarity between query and item vectors, optionally using SIDs to augment the item representation.

## Key Results
- Offline: R@5 +3.80%, R@10 +2.64%, R@20 +2.17%; N@5 +5.10%, N@10 +4.22%, N@20 +2.09% compared to strong baselines.
- Online A/B test (1 week): Revenue +1.12%, CTR +1.02%.

## Why This Works (Mechanism)
Staged pretraining isolates each modality’s learning dynamics, ensuring that weaker modalities (like image) receive adequate training before being combined, thus mitigating modality neglect. It also alleviates the one-epoch problem where joint optimization would prematurely converge on easier tasks. The generative use of SIDs creates a bridge between continuous embeddings and discrete token prediction, enabling efficient large-scale retrieval via an inverted index while preserving semantic associations from both text and image modalities.

## Foundational Learning
- **Contrastive Learning (InfoNCE)**  
  *Why needed*: Pulls query and relevant item embeddings together while pushing apart irrelevant ones, fundamental for retrieval.  
  *Quick check*: Training loss decreases steadily; cosine similarity of positive pairs remains high.

- **RQ-VAE (Residual Quantized VAE)**  
  *Why needed*: Produces compact, discrete semantic IDs that capture multimodal semantics and support generative decoding.  
  *Quick check*: Reconstruction error (MSE between original and quantized embedding) is low and stable across validation set.

- **Generative Retrieval**  
  *Why needed*: Replaces brute-force similarity search with token-level prediction, drastically reducing index size and latency.  
  *Quick check*: Model can generate valid SIDs for unseen items, and retrieval via SID decoding matches or exceeds dense vector search.

- **Multimodal Fusion**  
  *Why needed*: Combines textual and visual signals to represent items holistically, crucial for food delivery where appearance and description matter.  
  *Quick check*: Cross-modal retrieval (query text → image, image → text) performs significantly above random.

- **Staged Pretraining**  
  *Why needed*: Coordinates heterogeneous training speeds and prevents dominant modalities from overshadowing others.  
  *Quick check*: Monitor per-stage losses; each stage converges before proceeding, and later stages do not degrade earlier modalities.

## Architecture Onboarding
**Component Map**  
Query Text → Text Encoder (Qwen3-0.6B) → Projection MLP → L2 Normalization → Query Vector  
Item Text → Text Encoder → Projection MLP → L2 Norm → Item Text Vector  
Item Image → Image Encoder (ViT) → Projection MLP → L2 Norm → Item Image Vector  
Fused Item Vector = Concatenate(Text, Image) → L2 Norm  
RQ-VAE on Text, Image, and Fused embeddings → SID indices (g_text, g_image, g_item) → Concatenated SID → Side token  

**Critical Path**  
Input (query text, item text+image) → Encoder(s) → Projection → Normalization → Vector representation → Similarity computation (cosine) → Retrieval score.

**Design Tradeoffs**  
- *Staged vs Joint*: Staged adds training time but avoids modality neglect; joint is faster but risks losing image signal.  
- *SIDs vs Dense*: SIDs enable compact indexing and generative decoding but incur quantization error; dense vectors offer higher fidelity at larger storage cost.  
- *Generative+Discriminative Fine-tuning*: Combines strengths of both paradigms but increases objective complexity and hyperparameter tuning.

**Failure Signatures**  
- If `query2image` loss plateaus while `query2text` diminishes → modality neglect likely due to skipping staged pretraining.  
- Ablating any SID component (text, image, item) leads to measurable drop in N@5.  
- Using only one causal loss (`L_causal` or `L_causal_SIDs`) results in lower retrieval performance compared to full combination.  
- High RQ-VAE reconstruction loss indicates insufficient codebook capacity or poor training.

**First Three Experiments to Onboard**  
1. Replicate the four-stage pretraining exactly in order, verifying each stage reaches a stable loss before proceeding. Compare against a joint multi-task baseline; expect joint to show degraded image-related metrics.  
2. Train RQ-VAEs on embeddings from stage 4 and compute reconstruction error; then ablate SID combinations during fine-tuning to confirm all three SID types contribute.  
3. Implement hard negative mining using a separate relevance model (oracle) and an in-batch negative strategy; evaluate R@5 differences to validate the need for sophisticated negatives.

## Open Questions the Paper Calls Out
1. **User history incorporation**: How to integrate user historical behavior into the query tower to better model preferences?  
2. **SIDs for sequential data**: How to generate and utilize SIDs for session sequences to extend generative retrieval to dynamic scenarios?  
3. **Optimal staging for >2 modalities**: What is the best pretraining order when incorporating more than two modalities (e.g., audio, video) with varying complexities?  
4. **Long-term robustness**: How does staged pretraining perform under chronic distribution shifts (e.g., seasonal trends) without full retraining?

## Limitations
- Proprietary Meituan data schema and preprocessing (tokenization, geo_hash usage, hard negative mining) are underspecified, hindering exact replication.
- Key training hyperparameters (epochs per stage, learning rates, optimizer) are not reported, requiring empirical search.
- The mechanism for injecting SID tokens into the LLM vocabulary and fine-tuning interactions lacks implementation details.

## Next Checks
1. **Staged vs. Joint Pretraining Ablation**: On a public multimodal dataset (e.g., XM2Cafe), train both staged (query→text→image→item) and joint (all losses simultaneously) models. Compare per-modality loss curves and final R@5 to confirm modality neglect in joint training.  
2. **SID Composition Ablation**: During fine-tuning, systematically remove one SID type at a time (e.g., only [g_text,g_image], only [g_image,g_item], etc.). Measure N@5 on validation; expect the all-three concatenation to outperform all subsets.  
3. **Hard Negative Mining Impact**: Contrast two strategies: (a) relevance-model based hard negatives; (b) simple in-batch negatives. Keep all other settings fixed and compare R@5 and N@5. A significant drop with (b) would confirm the importance of the paper’s hard negative source.
