# LegoNet: Memory Footprint Reduction Through Block Weight Clustering

## Quick Facts
- **arXiv ID:** 2603.06606
- **Source URL:** https://arxiv.org/abs/2603.06606
- **Reference count:** 23
- **Primary result:** Post-training weight clustering achieves up to 128× compression with minimal accuracy loss on ImageNet models.

## Executive Summary
LegoNet tackles the problem of deploying large neural networks on memory-limited embedded devices. It introduces a simple post‑training compression technique: weights are divided into small blocks (e.g., 4×4), all blocks across the model are clustered with K‑means, and each block is replaced by its cluster index. The method requires no retraining, fine‑tuning, or architectural changes. On ResNet‑50 (ImageNet) it achieves a 64× reduction in memory footprint with no loss in top‑1 accuracy, and up to 128× compression with less than 3% accuracy drop.

## Method Summary
Given a pre‑trained model, LegoNet processes all learnable parameters. The user selects a block size \( b \) such that every layer’s parameter count is divisible by \( b^2 \). Each tensor is flattened and split into non‑overlapping blocks of \( b^2 \) elements. All blocks from all layers are stacked into a single matrix and clustered via K‑means (Euclidean distance) into \( K \) clusters. The centroids form a codebook; each block is assigned the index of its nearest centroid. The compressed model stores the codebook (K × b² floats) and, for each layer, the integer indices (each stored in \( \lceil \log_2 K \rceil \) bits). During inference, the weights are reconstructed by lookup of the centroids using the indices and reshaping to the original tensor shapes. No model weights are updated; the process is entirely post‑training.

## Key Results
- 64× memory reduction on ResNet‑50 with zero top‑1 accuracy loss (ImageNet).
- Up to 128× compression with less than 3% accuracy loss.
- Compression achieved without retraining, fine‑tuning, or any change to the network architecture.

## Why This Works (Mechanism)
The approach leverages two insights: (1) Neural network weights exhibit redundancy; many blocks of weights have similar values across layers. (2) Representing a weight block by a shared centroid (codebook index) drastically reduces the number of bits needed, because the index requires only \( \log_2 K \) bits versus 32 bits for a float. By clustering globally, LegoNet finds a compact representation that captures common patterns across the entire model. The block size is chosen to preserve spatial or channel‑local structure (e.g., within a convolution kernel), which helps maintain reconstruction fidelity. Because the centroids are derived from the original weights, the reconstructed weights closely approximate the originals, preserving accuracy when the codebook is sufficiently large (e.g., K=50 gives near‑perfect reconstruction). The reduction in memory comes from both storing indices instead of floats and from the fact that a single codebook serves the whole model, avoiding per‑layer overhead.

## Foundational Learning
1. **Post‑training compression** – *Why needed:* Enables deployment on devices without expensive retraining or access to training data. *Quick check:* Verify that no gradient updates or data are used during compression.
2. **K‑means clustering** – *Why needed:* Provides an efficient way to learn a small set of representative prototypes for a large set of weight blocks. *Quick check:* Confirm Euclidean distance metric and that all blocks are clustered globally.
3. **Block‑based weight sharing** – *Why needed:* Captures local correlations in weight tensors better than vector‑wise quantization. *Quick check:* Ensure block size \( b \) is chosen so that \( b^2 \) divides the number of elements in each layer.
4. **Codebook representation** – *Why needed:* Allows each block to be stored as a short integer index instead of a full‑precision float. *Quick check:* Compute theoretical compression ratio \( \text{CR} = (b^2 \cdot 32) / \lceil \log_2 K \rceil \).
5. **Memory‑constrained inference** – *Why needed:* Embedded systems often have strict storage and bandwidth limits. *Quick check:* Compare original and compressed model sizes on disk.

## Architecture Onboarding
**Component map:**  
Pretrained model → Block splitting → Global K‑means clustering → Codebook + Indices → Weight reconstruction → Compressed model

**Critical path:** The compression pipeline proceeds linearly: extract weights, split into blocks, run K‑means, store centroids and per‑layer index arrays, and finally re‑assemble the model state dict. During inference, the model loads the codebook and indices, reconstructs weights on‑the‑fly (or offline), then runs standard forward passes.

**Design tradeoffs:**  
- *Block size \( b \):* Larger \( b \) (more elements per block) can capture more structure, potentially improving accuracy at a given \( K \), but increases centroid memory and may reduce divisibility.  
- *Number of clusters \( K \):* Larger \( K \) gives finer representation and higher accuracy but lower compression ratio; smaller \( K \) yields higher compression but risks accuracy loss.  
- *Single vs. per‑layer codebook:* LegoNet uses a single global codebook for simplicity and maximal sharing; per‑layer codebooks could adapt to layer‑specific distributions but increase overhead.  
- *Full‑batch vs. mini‑batch K‑means:* Full‑batch gives exact clusters but may be memory‑intensive; mini‑batch is scalable but may affect quality.

**Failure signatures:**  
- Accuracy drop far exceeding expected bounds (e.g., >3% at 128×) – might indicate incorrect block splitting, poor K‑means convergence, or missing parameters.  
- Parameter count mismatch – check divisibility condition; if a layer’s size is not a multiple of \( b^2 \), the implementation may need padding/truncation.  
- Compression ratio lower than theoretical – ensure indices are packed at the bit level, not byte‑aligned.  
- Out‑of‑memory during clustering – use MiniBatchKMeans or subsample blocks.

**First three experiments:**  
1. Validate block splitting: For every layer in ResNet‑50, confirm `num_elements % (b*b) == 0` (with b=4). If not, decide on a padding/truncation strategy.  
2. Evaluate accuracy: Compile ResNet‑50 with \( K=50 \) and \( K=16 \), measure top‑1 ImageNet validation accuracy (single‑crop). Compare to baseline (76.1%?) and verify claims.  
3. Measure actual compression: Compute file size of saved compressed model (including bit‑packed indices) and compare to the original float32 checkpoint to confirm CR ≥ 64 and 128 respectively.

## Limitations
- Exact K‑means hyperparameters (max_iter, tol, n_init, batch size) are not disclosed; different settings may alter clustering quality and thus accuracy.  
- Layers whose parameter count is not divisible by \( b^2 \) require a handling strategy (padding/truncation) that is not specified; this could bias results.  
- It is unclear whether all learnable parameters (including biases and BatchNorm statistics) were clustered; inclusion/exclusion affects the compression ratio and accuracy.

## Confidence
- **64× memory reduction with zero accuracy loss on ResNet‑50:** Medium confidence (divisibility likely holds, but unknown clustering details introduce variability).  
- **Up to 128× compression with less than 3% accuracy loss:** Low confidence (higher compression amplifies sensitivity to K‑means initialization and any layer‑handling choices).
