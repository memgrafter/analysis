# Causality Elicitation from Large Language Models

## Quick Facts
- **arXiv ID:** 2603.04276  
- **Source URL:** https://arxiv.org/abs/2603.04276  
- **Reference count:** 40  
- **Primary result:** A five‑step pipeline (generate → extract → canonicalize → matrix → causal discovery) turns LLM‑produced narratives into inspectable causal hypothesis maps, though without real‑world validation.

## Executive Summary
The paper tackles the challenge of extracting interpretable causal hypotheses from large language model (LLM) generated narratives, which suffer from surface‑form variation leading to variable fragmentation. The authors propose a five‑step pipeline: generate topic‑conditioned analytical documents, extract events, canonicalize event mentions via embedding clustering and LLM naming, build a binary document‑event incidence matrix, and apply causal discovery algorithms (PC, GES, LiNGAM).  

Two case studies (Trump‑Japan policy, AI‑gold) demonstrate that the pipeline yields structured, inspectable graphs that serve as hypothesis maps for expert review, though without real‑world validation. The approach transforms unstructured narrative into a structured representation amenable to causal inference, but its reliability depends on canonicalization choices and the suitability of causal discovery methods for binary data.

## Method Summary
The method is explicitly defined: Given a topic T, sample N documents (e.g., N=100) from an LLM using a fixed analyst‑style prompt. Extract event phrases from each document with an LLM via robust JSON/Python/newline parsing. Canonicalize raw events: compute embeddings (e.g., text‑embedding‑3‑large), L2‑normalize, cluster with MiniBatchKMeans (K = min(Kmax, M)), and name each cluster with an LLM prompt. Map each raw event to a canonical label. Build a binary document‑canonical event matrix Z by aggregating raw event occurrences per canonical event (logical OR). Remove constant columns. Finally, apply causal discovery (PC with α=0.1, GES, LiNGAM) to Z and output graphs in DOT format. The output is intended as a hypothesis map, not a verified causal model.

## Key Results
- **Trump‑Japan case (N=100, C=30):** PC revealed three interpretable mechanisms linking U.S. trade/tech pressures to Japanese foreign direct investment and monitoring sinks.
- **AI‑gold case (C=20):** PC separated macro‑financial and geopolitical channels converging on gold demand.
- **General:** The pipeline produces inspectable causal graphs for expert review, but these are not validated real‑world causal relationships.

## Why This Works (Mechanism)
The pipeline works by reducing lexical variability of event mentions through semantic clustering and LLM‑assisted naming, producing stable canonical variables. Each document becomes a binary vector over these events, capturing co‑occurrence. Causal discovery algorithms then infer conditional dependence relationships; edges represent statistical dependencies that survive conditional independence tests, suggesting potential causal links under assumptions like faithfulness. By aggregating across many documents, the method leverages the LLM’s implicit causal knowledge to propose a consensus hypothesis map. However, the binary co‑occurrence matrix discards temporal order, relies on LLM narrative correctness, and applying continuous‑data causal methods to discrete data may introduce bias.

## Foundational Learning
### Causal Discovery Algorithms (PC, GES, LiNGAM)
- **Why needed:** These algorithms infer causal graph structure from observational data by testing conditional independences (PC), optimizing scores (GES), or exploiting non‑Gaussianity (LiNGAM). They form the core inference engine.
- **Quick check:** What assumption does LiNGAM make about the data distribution that PC does not?

### Event Canonicalization via Embedding Clustering
- **Why needed:** LLM narratives use varied phrasing for the same underlying event (e.g., "trade war" vs "trade conflict"). Canonicalization merges synonyms to define consistent variables for reliable analysis.
- **Quick check:** If two event mentions have high cosine similarity in embedding space, should they always be merged? What would be a counterexample?

### Document‑Event Incidence Matrix
- **Why needed:** This binary matrix provides a structured representation of which events appear in which documents, serving as the input data matrix for causal discovery.
- **Quick check:** What does a '1' entry represent? How does logical OR aggregation affect the data?

### LLM‑Based Information Extraction
- **Why needed:** The pipeline starts by extracting event mentions from unstructured text. LLMs are used for their ability to parse analytical documents and output structured event lists.
- **Quick check:** Why might the LLM extraction step produce noisy or inconsistent event phrases even with robust parsing?

### Binary Data in Causal Inference
- **Why needed:** The incidence matrix is binary, yet standard continuous‑variable causal discovery algorithms are applied, possibly violating assumptions like linearity or Gaussianity.

## Architecture Onboarding
### Component Map
Document Generation -> Event Extraction -> Canonicalization -> Matrix Construction -> Causal Discovery

### Critical Path
The critical path runs from generating documents to extracting events, then clustering events into canonical concepts, building the binary matrix, and finally running causal discovery. Each step depends on the previous: canonicalization requires raw events from extraction; matrix construction requires the canonical mapping; causal discovery requires the matrix.

### Design Tradeoffs
- **Kmax selection in clustering:** Too low yields under‑merging (too many variables, sparsity), too high yields over‑merging (biased variables). The choice influences graph interpretability and stability.
- **Algorithm choice for causal discovery:** PC (constraint‑based), GES (score‑based), LiNGAM (non‑Gaussian) have different sensitivities to sample size and data distribution. Using multiple provides robustness but also disagreement.
- **Binary vs continuous representation:** Binary incidence simplifies extraction but discards frequency information and may violate assumptions; alternatives like TF‑IDF or counts could be considered.

### Failure Signatures
- **Over‑merging events:** Clusters that mix semantically distinct events (e.g., "interest rate hike" and "quantitative easing") lead to conflated variables and misleading edges.
- **Sparse or unstable graphs:** If the matrix is too sparse or canonicalization is noisy, causal discovery may produce wildly different graphs across runs.
- **Violation of causal assumptions:** Applying continuous methods to binary data may yield high false positive rates or failed conditional independence tests due to limited variation.

### First Three Experiments
1. **Canonicalization sensitivity:** Vary Kmax (e.g., 20, 30, 40, 50) on the same document set. Compare cluster cohesion (average intra‑cluster cosine similarity) and separation. Observe graph changes.
2. **Algorithmic agreement:** For a fixed matrix Z, compute graphs from PC (α=0.1), GES, and LiNGAM. Calculate edge overlap (Jaccard index) pairwise. Disagreement suggests algorithm‑specific biases.
3. **Stability across generations:** Generate documents multiple times with different random seeds (fixed prompts). Canonicalize and run PC each time. Measure edge stability (proportion of edges present in all graphs). Low stability indicates pipeline sensitivity.

## Open Questions the Paper Calls Out
1. **Granularity policy for canonicalization:** How to systematically choose the appropriate level of event merging to balance false merges and missed merges? The paper notes it is context‑dependent and left to the analyst.
2. **Adapting causal discovery for binary data:** How can causal discovery algorithms be tailored to the binary, discrete nature of document‑event matrices while respecting their generative assumptions? The paper suggests discrete tests/SEMs and methods robust to latent confounding as directions.
3. **Mitigating prompt‑dependent biases:** How to measure and reduce biases and omissions in LLM‑generated documents so elicited causal hypotheses are stable and representative? The paper calls for repeated‑run stability checks and external validity assessments.
4. **Incorporating temporal ordering:** How to integrate temporal information from narratives to move beyond conditional co‑occurrence toward causal sequences with temporal precedence? The pipeline currently discards ordering.
5. **External validation beyond expert review:** What methodologies can test whether elicited graphs correspond to real‑world causality? The paper admits no verification of causal truth and calls for validation against empirical data.

## Limitations
- **Unreported implementation details:** Exact LLM models, generation parameters (temperature, top‑p), and clustering seeds are unspecified, hindering exact replication.
- **Algorithm‑assumption mismatch:** Causal discovery algorithms (PC, GES, LiNGAM) are designed for continuous data; their application to binary incidence matrices may violate conditional independence test assumptions and produce spurious edges.
- **Lack of real‑world validation:** The output graphs are treated as hypothesis maps for expert review, with no systematic external validation against empirical causal data.

## Confidence
- **Pipeline description clarity:** High confidence – steps are explicitly defined.
- **Canonicalization robustness:** Medium confidence – stability depends on unreported seeds and Kmax; over/under‑merging risks are noted.
- **Causal validity of output graphs:** Low confidence – no real‑world validation and potential discrete‑data assumption violations.

## Next Checks
1. **Replication with fixed seeds and specified models:** Implement the full pipeline using a specific LLM (e.g., GPT‑4) at low temperature (0.1) and fixed KMeans seeds; compare edge stability across three independent runs.
2. **Stress‑test canonicalization granularity:** Vary Kmax (e.g., 20–50) and quantify cluster cohesion/separation; inspect ambiguous clusters; observe impact on graph stability and interpretability.
3. **Validate discrete‑data causal assumptions:** Apply Bayesian network methods for discrete data (e.g., BDeu score in bnlearn) to the same matrix Z; compare resulting graph structures with those from PC/GES to assess sensitivity and potential false positives.
