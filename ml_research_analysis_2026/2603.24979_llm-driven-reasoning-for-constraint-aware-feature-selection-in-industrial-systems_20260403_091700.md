# LLM-Driven Reasoning for Constraint-Aware Feature Selection in Industrial Systems

## Quick Facts
- **arXiv ID:** 2603.24979
- **Source URL:** https://arxiv.org/abs/2603.24979
- **Reference count:** 15
- **Primary result:** MoFA uses LLM-driven constraint-aware feature selection to improve model metrics (e.g., +0.63% AUC) while significantly reducing feature group counts (54% reduction) on multiple industrial tasks.

## Executive Summary
Feature selection in industrial ML systems is often hampered by limited labeled data and stringent operational constraints (e.g., consolidating features into fewer groups). MoFA addresses this by employing an LLM-based agent that sequentially selects features through natural language reasoning, integrating semantic descriptions and quantitative metadata (importance scores, correlations, group IDs) within structured prompts that encode explicit constraints. To scale to large feature spaces, a Divide-and-Conquer strategy partitions features into buckets, performs parallel local selections, and then a global refinement to reach the target size.

Results on three industrial tasks confirm MoFA's practical value: on True Interest/Time-Worthiness, it achieves up to +0.63% AUC improvement while reducing feature groups by 54% (K=500); on the Value Model, it discovers high-order interactions driving session lifts up to +0.055% in online A/B tests; and on Notification Prediction, selecting 4,000 features from 8,169 improves normalized entropy loss over production (+0.065% pclick, +0.198% pdismiss). The approach demonstrates that LLM reasoning can effectively navigate trade-offs between predictive utility and operational feasibility.

## Method Summary
MoFA is a constraint-aware feature selection framework that uses an LLM agent to sequentially choose features from a candidate set. For each selection step, the LLM receives a structured prompt containing the task objective, currently selected features with metadata, remaining candidates with their metadata (feature definition, importance scores, correlations, group identifiers), and explicit constraints (e.g., limit on total feature groups). The LLM outputs the next feature and a reasoning, which is added to the selected set. To handle very large feature spaces, MoFA employs a Divide-and-Conquer strategy: features are partitioned into disjoint buckets; Phase 1 runs independent sequential selections within each bucket to obtain local top candidates (size K' > K/B); Phase 2 merges all candidates and runs a final global sequential selection to reach the target K. The backbone LLM used in the paper is Llama4-Maverick, but the approach is model-agnostic. The method’s key innovation is the integration of heterogeneous metadata and constraints into natural language prompts, enabling the LLM’s world knowledge to compensate for limited labeled data and to reason about operational requirements.

## Key Results
- True Interest/Time-Worthiness: Up to +0.63% AUC gain while cutting feature groups by 54% (K=500).
- Value Model: Identified high-order interactions driving session lifts up to +0.055% in online A/B tests.
- Notification Prediction: Selected 4,000 from 8,169 features, improving NE loss over production (+0.065% pclick, +0.198% pdismiss) and random baselines.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** MoFA enables constraint-aware feature selection by integrating heterogeneous metadata (semantics, importance, correlations, group membership) into structured LLM prompts.
- **Mechanism:** The LLM agent receives a prompt at each step containing the task objective, current selected features, remaining candidates with their metadata, and explicit constraints (e.g., limit feature groups). It reasons in natural language to select the next feature that best balances predictive utility with operational requirements, outputting both the choice and an explanation.
- **Core assumption:** An LLM with sufficient domain knowledge and reasoning capability can synthesize numerical metadata and semantic descriptions to make selections superior to purely statistical heuristics when constraints are present.
- **Evidence anchors:**
  - [abstract] "MoFA incorporates feature definitions, importance scores, correlations, and metadata (e.g., feature groups or types) into structured prompts and selects features through interpretable, constraint-aware reasoning."
  - [section 3.3] Details prompt construction including "auxiliary requirements C(S)" and metadata like group identifiers, with output format "Selected Feature: f* t, Reason: ρ t".
  - [corpus] *Weak anchor:* Neighbors like "LLM-FS: Zero-Shot Feature Selection" and "Knowledge-Aware Iterative Retrieval" show general LLM-feature selection interest but do not directly evidence MoFA's constraint integration mechanism.
- **Break condition:** If the LLM consistently ignores explicit constraint instructions in prompts, or if metadata (e.g., group IDs) is omitted or misunderstood, the constraint satisfaction property fails.

### Mechanism 2
- **Claim:** The Divide-and-Conquer strategy addresses the quadratic context window limitation of LLMs when selecting from thousands of industrial features.
- **Mechanism:** The feature space is partitioned into disjoint buckets. Phase 1 runs parallel, independent sequential selection within each bucket to get local top candidates (|S_b| = K' > K/B). Phase 2 merges these candidates into a refined pool and performs a final global sequential selection on this smaller set to reach target K. This ensures all features are evaluated while keeping per-step context manageable.
- **Core assumption:** Local selections within buckets preserve the most promising features from each partition, and a final global pass on the union can resolve cross-bucket redundancies and dependencies that independent selections might miss.
- **Evidence anchors:**
  - [abstract] "with a Divide-and-Conquer strategy for scalability."
  - [section 3.2] Full description: "partition the total feature set F into B disjoint buckets... Phase 1: Bucketed Parallel Selection... Phase 2: Global Synthesis and Refinement."
  - [section 4.2 & 4.4] Concrete application: "partitioning the 1,030 features into B = 5 disjoint buckets" and "partition the 8,169 features into B = 10 disjoint buckets."
- **Break condition:** If highly synergistic features are inadvertently placed in separate buckets and one gets eliminated in Phase 1, the global Phase 2 cannot recover the optimal combination, leading to suboptimal final sets.

### Mechanism 3
- **Claim:** Sequential greedy selection via LLM reasoning can identify high-value feature subsets in data-scarce or constraint-rich production environments where traditional statistical methods falter.
- **Mechanism:** Instead of relying on labeled data for correlation or model-based importance scores, MoFA uses the LLM's world knowledge to evaluate a feature's semantic relevance to the task and its quantitative metadata (provided) in a step-by-step selection process. It implicitly reasons about feature semantics, interactions, and constraints without requiring retraining a model at each step.
- **Core assumption:** The LLM's parametric knowledge, combined with provided quantitative metadata, encodes a sufficient proxy for downstream model utility and feature synergy to outperform random selection and compete with Lasso on small budgets, especially when operational constraints (like group consolidation) are valued.
- **Evidence anchors:**
  - [abstract] "Traditional feature selection methods rely on labeled data and statistical heuristics... To address this, we propose MoFA... using both semantic and quantitative feature information."
  - [section 4.2] For True Interest (K=20), MoFA AUC +0.63% over Lasso; for Time-Worthiness, group reductions of 54% (K=500) vs. Lasso.
  - [section 4.4] MoFA (4K features) beats random (4K) and production (7.5K) on NE loss for pclick (+0.065% vs prod, +0.19% vs random) and pdismiss (+0.198% vs prod, +0.332% vs random).
- **Break condition:** If the LLM's internal knowledge is misaligned with the specific domain or task semantics (e.g., misunderstanding user intent signals), or if provided metadata is noisy/irrelevant, the sequential selections will be suboptimal. Performance may degrade to random or worse for very large K if early greedy choices create irreversible local optima.

## Foundational Learning
- **Concept: LLM Prompt Engineering for Structured Reasoning**
  - **Why needed here:** MoFA's core is transforming feature selection into a sequential natural language reasoning task. Engineers must design prompts that clearly encode task objectives, feature semantics, quantitative metadata, and constraints in a way that elicits consistent, correct reasoning from the LLM.
  - **Quick check question:** How would you format the prompt to include a constraint like "select no more than 5 features from team X's group" without confusing the LLM? What prompt elements risk the LLM ignoring a constraint?
- **Concept: Greedy Algorithm Pitfalls in Feature Selection**
  - **Why needed here:** MoFA's sequential selection is a greedy algorithm. Understanding its limitations (e.g., inability to recover from poor early picks, ignoring synergistic feature groups) is crucial for interpreting results, setting expectations (e.g., why performance might plateau at larger K), and designing mitigations like the Divide-and-Conquer global refinement.
  - **Quick check question:** If features A and B together are highly predictive but individually are weak, what is the risk that a greedy sequential selector like MoFA will miss including both? How does the Phase 2 global refinement help?
- **Concept: Industrial Feature Engineering & Operational Constraints**
  - **Why needed here:** MoFA's value proposition hinges on satisfying real-world constraints (feature group consolidation, capacity) that traditional methods ignore. Engineers must identify, formalize, and weight these constraints as metadata for the LLM.
  - **Quick check question:** Beyond predictive accuracy, list three operational constraints in a large-scale recommender system that would influence feature selection. How would you represent each as metadata in MoFA's prompt?

## Architecture Onboarding
- **Component map:**
  1.  **Metadata Pre-processor:** Extracts/calculates importance scores, correlations, group IDs, categories from existing models/logs for all candidate features.
  2.  **Bucket Partitioning Module:** Splits the full feature list F into B disjoint buckets (heuristic: by feature group, team, or random).
  3.  **Prompt Constructor:** For a given step (t), current set S_t, and candidate set A_t (from a bucket or refined pool), builds the structured prompt string containing: task description, O(S), S_t with metadata, A_t with metadata, and constraints C(S).
  4.  **LLM Agent Wrapper:** Manages API calls to the backbone LLM (e.g., Llama4-Maverick), enforces output format ("Selected Feature: ..., Reason: ..."), parses responses, and handles errors/retries.
  5.  **Sequential Selection Controller:** Orchestrates the loop: initialize S_0 = ∅, for t=1..K' (Phase 1) or K (Phase 2): call Prompt Constructor -> LLM Agent -> update S_t, A_t.
  6.  **Pool Merger & Refinement:** Aggregates Phase 1 outputs S_b into F_refine, then reinitializes the Sequential Selection Controller for Phase 2 with target K.
  7.  **Validation Pipeline:** Offline evaluator (train/test AUC, NE loss) and/or online A/B test setup to measure selected subset's impact.
- **Critical path:** Metadata availability → Bucketing → (Phase 1: Parallel bucket selections) → Merge → Phase 2: Global selection → Validate.
  *Key dependency:* The entire pipeline fails without accurate, comprehensive metadata for all features.
- **Design tradeoffs:**
  - **Bucket size vs. context limit:** Smaller buckets reduce per-prompt size but increase Phase 1 local minima risk. Larger buckets risk context overflow. B and K' are hyperparameters tuned per feature space size.
  - **LLM choice vs. cost/quality:** Larger, more capable models (e.g., Maverick) likely provide better reasoning but are costlier/slower. Tradeoff must be evaluated per use case.
  - **Constraint specificity:** Over-specified constraints may confuse the LLM. Under-specified constraints lead to undesirable operational outcomes. Requires prompt tuning.
- **Failure signatures:**
  - **Constraint violation:** Selected subsets consistently exceed group limits or other C(S). *Diagnosis:* Prompt instruction unclear; LLM ignoring constraint; metadata missing/incorrect.
  - **Poor accuracy vs. baselines:** MoFA underperforms Lasso (data-rich) or random (data-scarce) on offline metrics. *Diagnosis:* LLM reasoning misaligned; metadata irrelevant/noisy; greedy path too suboptimal.
  - **High group count despite constraint:** Group consolidation fails. *Diagnosis:* Group metadata not included in prompt; instruction to "concentrate groups" absent/ineffective.
  - **Inconsistent output parsing:** LLM doesn't follow "Selected Feature: X, Reason: Y" format. *Diagnosis:* Need output formatting constraints (e.g., JSON mode) or more explicit instructions.
- **First 3 experiments:**
  1.  **Sanity Check on Small Synthetic Set:** Use a toy feature set (e.g., 50 features) with known optimal solutions (e.g., "pick only group G1 features with high 'importance' metadata"). Verify MoFA can follow a simple constraint and prioritize high-value features. Measure success rate over 10 runs.
  2.  **Replication of Section 4.2 (TI/WT) Setup:** If possible, replicate the exact 1,030-feature, K=20/100/200/500 experiment. Compare group counts and AUC to Table 1. This tests full pipeline (bucketing, metadata use, global refinement) against a published benchmark.
  3.  **Constraint Ablation Study:** Run the same selection (e.g., K=500 in TI task) but remove group metadata from prompts. Measure degradation in group count reduction. This isolates the contribution of explicit constraint integration.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can MoFA's sequential, greedy selection procedure be improved to avoid suboptimal feature subsets caused by myopic decisions, without prohibitive computational cost?
- **Basis in paper:** [explicit] "MoFA’s sequential approach is inherently a greedy search, which might overlook optimal feature combinations that only show synergy when selected together."
- **Why unresolved:** The paper acknowledges this fundamental limitation but does not explore alternative search strategies (e.g., beam search, look-ahead, or stochastic sampling) due to the offline nature of feature selection and the cost of LLM queries. The trade-off between selection quality and reasoning steps remains unquantified.
- **What evidence would resolve it:** A comparative study measuring the performance gap between MoFA's greedy selection and a (computationally feasible) non-greedy oracle or heuristic (e.g., limited backtracking) on the same tasks, analyzing the prevalence of synergistic feature pairs missed by the greedy path.

### Open Question 2
- **Question:** What is the optimal strategy for partitioning the feature space in the Divide-and-Conquer phase, and how sensitive is final performance to the partitioning scheme (e.g., by feature group, correlation, or random)?
- **Basis in paper:** [inferred] The paper uses a simple disjoint bucketing strategy (e.g., random or by group) to manage context limits but provides no analysis or ablation on the choice of partitioning logic. The global refinement phase is designed to mitigate errors from independent bucket selections, but its efficacy as a function of initial partition quality is unknown.
- **Why unresolved:** The authors implement a practical solution but do not investigate whether certain partitioning principles (e.g., maximizing intra-bucket feature correlation diversity or respecting semantic hierarchies) lead to better final subsets after global refinement. This is a key design choice with no stated rationale.
- **What evidence would resolve it:** An ablation experiment holding total feature budget and LLM constant, varying only the partitioning criterion (random, by feature group, by correlation clustering, by feature type), and measuring the final model performance and group concentration. This would reveal if the current approach is near-optimal or if significant gains are possible from smarter partitioning.

### Open Question 3
- **Question:** To what extent do MoFA's gains depend on the specific semantic and metadata prompt structure, and how transferable are the selected features across different LLM backbones or prompt designs?
- **Basis in paper:** [explicit] "MoFA incorporates feature definitions, importance scores, correlations, and metadata... into structured prompts." However, the exact prompt template and the weighting of semantic vs. quantitative cues are not analyzed. The paper uses a single LLM (Llama4-Maverick).
- **Why unresolved:** The framework's effectiveness is attributed to integrated reasoning, but the critical prompt components and their interactions are not disentangled. It is unclear if results generalize to other LLMs with different reasoning capacities or if minor prompt tweaks could drastically change selections. This limits reproducibility and understanding of the core mechanism.
- **What evidence would resolve it:** A systematic prompt ablation study, removing or altering metadata fields (e.g., no correlations, no group info) and measuring changes in selection outcomes and downstream performance. Additionally, replicating key experiments with a different LLM family (e.g., GPT, Claude) to assess robustness of the selection pattern and final utility.

### Open Question 4
- **Question:** Can the computational overhead of MoFA's sequential reasoning be reduced (e.g., via parallelization, distillation, or alternative architectures) while preserving its constraint-aware selection quality for very large feature spaces (N >> 10,000)?
- **Basis in paper:** [explicit] "the computational time scales linearly with the number of features K to be selected... providing a comprehensive list of all features... can challenge the input token limits." The Divide-and-Conquer strategy mitigates but does not eliminate the sequential bottleneck per bucket.
- **Why unresolved:** The paper treats reasoning time as an acceptable offline cost but does not explore engineering optimizations. As feature spaces grow, even bucketed sequential selection may become impractical. The potential for parallelizing selections across buckets is noted, but the global refinement step remains sequential and could become a new bottleneck.
- **What evidence would resolve it:** Benchmarking the wall-clock time of MoFA as a function of total features (N) and target budget (K) on larger-scale synthetic or real datasets, testing modifications like parallel candidate generation per bucket followed by a single global step, or training a smaller model to imitate the LLM's sequential decisions (distillation).

## Limitations
- **Prompt engineering opacity:** The exact LLM prompt template (wording, ordering, in-context examples) is not disclosed, making it difficult to replicate constraint adherence and reasoning quality.
- **Metadata specifications missing:** Details on how quantitative metadata (e.g., feature importance scores, correlations) are computed and sourced are lacking, impeding faithful reproduction.
- **LLM backbone dependency:** All experiments use Llama4-Maverick; it is unknown whether conclusions hold for other LLMs with different reasoning or instruction-following capabilities.
