# Adversarial Attacks on Locally Private Graph Neural Networks
## Quick Facts
- **ArXiv ID:** 2603.20746
- **Source URL:** https://arxiv.org/abs/2603.20746
- **Reference Count:** 40
- **Primary Result:** A data poisoning attack exploiting LPGNN's deterministic bias removal achieves near-perfect (97–100%) inference of private binary node features, effectively breaking LDP guarantees.

## Executive Summary
This paper explores the security of Locally Differentially Private Graph Neural Networks (LPGNNs) under adversarial threats. It identifies a critical vulnerability: the deterministic bias removal step in LPGNN's multi-bit LDP encoder creates a predictable mapping that a carefully crafted data poisoning attack can exploit. By injecting a precise perturbation into node features before LDP encoding, an attacker can induce a deterministic output (e.g., always encoding as 1) for certain feature dimensions, enabling near-perfect inference of the original binary feature values. While standard label-flipping attacks degrade model utility in a linear fashion and a basic neighborhood inference attack fails due to excessive noise, the proposed poisoning attack fundamentally compromises the LDP privacy guarantee on datasets with binary features. The work highlights a fundamental tension between utility-optimizing LDP mechanisms and adversarial robustness.

## Method Summary
The study evaluates attacks on the LPGNN framework, which protects node features and labels using Local Differential Privacy. The core pipeline involves: (1) clients perturbing raw data locally via a *Multi-Bit Encoder* before transmission, (2) a server applying a *Multi-Bit Rectifier* to remove encoding bias, followed by *KProp* denoising and standard GNN layers (GCN, GAT, SAGE). Labels are protected via Randomized Response and denoised with a *DROP* module. The novel **data poisoning attack** calculates a perturbation `p` based on LDP parameters (`ε`, `m`, bounds `α`, `β`) and adds it to targeted nodes' features prior to encoding. This forces the Bernoulli trial in the encoder to output a non-zero value (e.g., 1) with certainty when the original feature equals `α`. Observing this output on the server allows the attacker to conclusively infer the original binary feature was the opposite value (e.g., 1 if `α=0`). The attack's success hinges on discrete (binary) features and full knowledge of the LDP encoding scheme.

## Key Results
*   Label-flipping attacks cause a consistent, linear degradation in node classification accuracy as the proportion of flipped labels increases.
*   A basic inference attack that aggregates denoised neighborhood features fails because the multi-bit LDP mechanism expands the output domain, making the aggregated noise too large to estimate original values.
*   The proposed poisoning attack achieves near-perfect inference success rates (97–100%) on datasets with binary features, effectively violating LDP guarantees across varying privacy budgets (`ε`).

## Why This Works (Mechanism)
### Mechanism 1: Breaking LDP via Poisoning
*   **Claim:** A calculated data poisoning attack breaks LPGNN's multi-bit LDP guarantee, enabling near-perfect inference of original binary node features.
*   **Mechanism:** The attacker adds a perturbation `p = (α - β) / (e^(ε/m) - 1)` to the raw feature values of targeted nodes before the Multi-Bit Encoder. This perturbation ensures that when the original feature `x_i = α`, the Bernoulli trial probability in the encoder becomes exactly 0. Consequently, the encoder outputs a non-zero value (e.g., 1) with certainty. The server's deterministic Multi-Bit Rectifier preserves this output. Observing `x*_i = 1` allows the attacker to infer `x_i ≠ α` (and for binary `[0,1]` features, `x_i = 1`).
*   **Core Assumptions:** Features are discrete (binary is optimal); attacker knows encoding parameters (`α`, `β`, `ε`, `m`) and binary representation.
*   **Evidence Anchors:** Abstract and Section 3.3 detail the attack algorithm, derivation of `p`, and proof under binary features. Experimental results in Section 4.3 (Figure 9) show 97–100% success on binary datasets.
*   **Break Condition:** Attack fails on continuous features or with miscalculated `p`.

### Mechanism 2: Linear Utility Degradation via Label-Flipping
*   **Claim:** Flipping labels of compromised nodes degrades LPGNN's classification accuracy linearly with the proportion of flipped labels.
*   **Mechanism:** Attacker modifies labels before the LDP process. The poisoned labels are perturbed by Randomized Response and propagated via message passing during training. The DROP denoising layer cannot fully correct this adversarial noise, leading the GNN to learn from corrupted supervision and misclassify nodes.
*   **Core Assumptions:** Attacker has white-box label access and targets high-degree nodes to maximize propagation.
*   **Evidence Anchors:** Abstract states the linear degradation; Section 3.1.2 describes the threat model; Section 4.1.2 (Figure 7) shows experimental linear trends.
*   **Break Condition:** Effectiveness diminishes if attacker cannot access labels or if graph homophily is very low.

### Mechanism 3: Failed Basic Inference Due to Domain Expansion
*   **Claim:** A standard inference attack aggregating denoised neighborhood features fails because LDP noise expands the feature domain.
*   **Mechanism:** The attack assumes that averaging unbiased, noisy features from homophilic neighbors will estimate a target node's original feature. However, the multi-bit mechanism drastically expands the output domain (e.g., from `[0,1]` to `[-178.5, 179.5]`). The residual noise after bias removal is large relative to any neighborhood similarity, making the aggregate an ineffective estimator.
*   **Core Assumptions:** Neighboring node features are highly similar.
*   **Evidence Anchors:** Abstract notes failure due to domain expansion; Section 3.2 explains the attack's design and failure; Section 4.3 reports poor metrics (cosine similarity ~0, mean difference >> feature range).
*   **Break Condition:** Could succeed if the rectifier introduced systematic bias (it does not) or if neighborhood feature variance were extremely low compared to LDP noise.

## Architecture Onboarding
*   **Component Map:** Raw Features/Labels → Multi-Bit Encoder (LDP noise) → Noisy Binary Vector `x*` → Multi-Bit Rectifier (unbiasing) → Denoised Features `x'` → KProp Layer (hop-wise denoising) → GNN Layers (GCN/GAT/SAGE). Labels: Raw Labels → Randomized Response (LDP) → Noisy Labels → DROP Module → Robust Training.
*   **Critical Path:** The feature pipeline (Encoder → Rectifier → KProp → GNN) is the primary attack surface. The poisoning attack targets the boundary between raw features and the Encoder.
*   **Design Tradeoffs:** The Multi-Bit Rectifier's deterministic unbiasedness maximizes utility under LDP but creates a predictable mapping the poisoning attack exploits. KProp adds denoising assuming smoothness, which may break under poisoning.
*   **Failure Signatures:** (1) Poisoning attack success: ~97–100% inference accuracy on binary datasets (Fig 9a). (2) Basic inference failure: Mean feature difference >> feature range (Table 6). (3) Node injection ineffectiveness: Minimal accuracy drop even at high injection rates (Fig 5).
*   **First 3 Experiments:** 1) **Baseline utility:** Train/evaluate LPGNN (GCN/GAT/SAGE) on all datasets without attack (Table 1). 2) **Utility attacks:** Apply Node Injection and Label Flipping attacks at varying scales (Figs 5 & 7); validate linear degradation for label-flipping. 3) **Privacy attacks:** Run Basic Inference (Sec 3.2) and Poisoning Attacks (Sec 3.3); measure success via cosine similarity/mean difference (basic) and binary inference accuracy (poisoning) (Table 6, Fig 9).

## Open Questions the Paper Calls Out
1.  Does the data poisoning attack generalize to a wider variety of graph datasets and GNN architectures beyond the four datasets and three architectures tested?
2.  How effective is the poisoning attack on node features with non-binary or continuous values, and what adaptations are necessary?
3.  Can adversarial attacks and defenses in LPGNN be formally modeled as a game-theoretic problem to identify optimal strategies?
4.  Are there robust defense mechanisms against the data poisoning attack that preserve LPGNN utility and LDP guarantees, beyond the simple domain validation suggested in the appendix?

## Limitations
*   **Parameter ambiguity:** Missing exact LDP hyperparameters (`m`, `α`, `β`, step sizes) prevents precise replication of the poisoning calculation.
*   **Binary-feature dependency:** Attack's near-perfect success is shown only on binary features; effectiveness on continuous features is unclear and theoretically reduces to a weaker membership-exclusion attack.
*   **Threat model realism:** Requires compromising client nodes to inject poison pre-encoding, which may be difficult in practice.
*   **Defense evaluation:** Proposed client-side validation (reject out-of-bound features) lacks implementation details and empirical testing.

## Confidence
*   **High:** The poisoning attack breaks LDP (mechanism 1) – strong theoretical proof and consistently high empirical success on binary features.
*   **High:** The basic inference attack fails (mechanism 3) – clear explanation of domain expansion and robust empirical validation.
*   **Medium:** Label-flipping causes linear degradation (mechanism 2) – observed trend is consistent, but cross-dataset robustness and deeper causal analysis are less developed.
