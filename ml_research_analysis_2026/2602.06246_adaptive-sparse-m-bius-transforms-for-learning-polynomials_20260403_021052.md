# Adaptive Sparse Möbius Transforms for Learning Polynomials
## Quick Facts
- **arXiv ID**: 2602.06246  
- **Source URL**: https://arxiv.org/abs/2602.06246  
- **Reference count**: 33  
- **Primary result**: Introduces adaptive group testing algorithms for exact learning of s‑sparse degree‑d Boolean polynomials, achieving near‑optimal query complexities O(sd log(n/d)) (FASMT) and O(sd² log n) (PASMT), with PASMT reducing adaptive rounds to O(d² log n).

## Executive Summary
The paper tackles the exact recovery of an s‑sparse degree‑d Boolean polynomial in its AND‑basis (Möbius) representation, given query access to the polynomial. Standard compressed sensing fails because AND‑basis vectors are highly coherent. The authors overcome this by recognizing that adaptive group testing provides a query‑efficient implementation of the Möbius transform. Two algorithms emerge: FASMT (fully adaptive) uses generalized binary splitting to achieve O(sd log(n/d)) queries and O((sd+n)·sd log(n/d)) time, nearly matching an information‑theoretic lower bound of Ω(sd log(n/d)/log s). PASMT (partially adaptive) trades a factor d in queries for O(d² log(n/d)) adaptive rounds independent of s, using O(sd² log(n/d)) queries and O((s²+sn)d² log n) time. Both avoid the exponential dependence on d that plagued prior hypergraph reconstruction methods. Experiments on real‑world hypergraphs (circuits, metabolic networks) show FASMT attains optimality ratios within 2–4× the information‑theoretic limit.

## Method Summary
The learning problem is to recover the Möbius coefficients F(k) of an unknown f: {0,1}ⁿ → ℝ, assuming exactly s non‑zero coefficients each of degree at most d, and that no non‑empty subset of these coefficients sums to zero (subset‑sum independence). The core idea is to treat the unknown supports as “defectives” in a group testing framework. Queries of the form f(¬h) yield sums of coefficients whose supports are disjoint from h, thereby splitting a current “bin” (a subset of the hypercube) into two children. The algorithms maintain a collection of active bins that partition the search space; each bin’s value is the sum of coefficients inside it. By adaptively splitting bins until each non‑zero coefficient is isolated, exact recovery is achieved.

FASMT processes bins in lexicographic order using a priority queue. It employs Generalized Binary Splitting (GBSA) to pick a test vector h that bisects the candidate index set for the current bin. A key innovation is the residual function f_T(x), which subtracts contributions of already discovered coefficients; because all smaller bins have been resolved, the residual of a specially constructed x equals the left child’s sum, so one query suffices per split. This yields O(sd log(n/d)) queries. PASMT precomputes a d‑disjunct matrix H with O(d² log n) columns. In each of b = O(d² log n) rounds, all active bins at a given depth split simultaneously using the same column h_t. The left child sums are recovered by solving a lower‑triangular linear system; right sums follow by subtraction. After b rounds, each leaf label ℓ is decoded to the unique support k of weight ≤ d using H. PASMT uses O(sd² log n) queries but only O(d² log n) adaptive rounds, independent of s.

## Key Results
- **Query complexities**: FASMT O(sd log(n/d)), PASMT O(sd² log(n/d)).
- **Adaptive rounds**: PASMT reduces to O(d² log(n/d)), independent of sparsity s.
- **Empirical performance**: FASMT attains optimality ratios within 2–4× the information‑theoretic limit on real hypergraphs (ISCAS‑85 circuits, metabolic networks).

## Why This Works (Mechanism)
The success of the algorithms rests on three interconnected mechanisms.

1. **Group Testing for Bin Splitting**. The algorithms view unknown non‑zero coefficients as defectives. Queries f(¬h) aggregate coefficients whose supports avoid h, splitting a bin into children based on inclusion of h. FASMT uses generalized binary splitting (GBSA) to adaptively choose h that roughly halves the candidate index set; PASMT uses a precomputed d‑disjunct matrix H that guarantees any ≤d defectives can be uniquely identified from test outcomes. This navigates the subset lattice efficiently despite AND‑basis coherence. Core assumptions: subset‑sum independence (no cancellations within a bin) and known degree bound d. Evidence: Lemma 1 formalizes bin‑sum correspondence; Section 3 details algorithms; group testing for sparse transforms is established in prior work. Break condition: Cancellation causes a bin sum to be zero even when coefficients are present, leading to incorrect pruning; degree > d prevents full isolation.

2. **Residual Subtraction in FASMT**. FASMT processes bins in increasing lexicographic order. When splitting bin B(ℓ), it queries f_T(x) with x built from the current test matrix H and new test h. Because all lexicographically smaller bins have already been processed and their coefficients stored in T, the residual equals the left child’s sum (ℓ∥0). The right child’s sum is the difference. Thus one query per split suffices. This relies on the invariant that all smaller bins are fully resolved before the current bin. Evidence: Lemma 4 (Bin Refinement) formalizes the residual property; the abstract states the O(sd log(n/d)) query bound. Break condition: Out‑of‑order processing contaminates residuals with undiscovered coefficients, corrupting bin sums.

3. **Fixed Disjunct Matrix for Partial Adaptivity (PASMT)**. PASMT uses a fixed d‑disjunct matrix H with b = O(d² log n) columns. In each round t, all active bins at depth t split using the same column h_t. Because H is d‑disjunct, the pattern of left/right splits uniquely identifies each support of weight ≤ d. After b rounds, each leaf label ℓ is decoded via a linear‑time decoder. All bins at a given depth are processed in parallel, so the number of adaptive rounds equals b, independent of s. Assumptions: H is d‑disjunct and all coefficients have degree ≤ d. Evidence: Algorithm 1 and Lemma 2 describe bin refinement and the linear system; disjunct matrices are standard in group testing (e.g., Kautz & Singleton, 1964). Break condition: If H is insufficiently disjunct (b too small), decoding fails due to collisions; degree > d leads to incomplete isolation.

## Foundational Learning
- **Möbius Transform (Inclusion–Exclusion)**  
  Represents a Boolean polynomial as a sum of AND monomials over subsets of variables. This basis is local and often sparse for conjunctions. *Why needed*: The learning task is exactly to recover the Möbius coefficients. *Quick check*: For f(x₁,x₂,x₃) = x₁x₂ + 2x₁x₃, what are F({1,2}) and F({1,3})? (Answer: F({1,2}) = 1, F({1,3}) = 2.)

- **Group Testing (Disjunct Matrices & Adaptive Splitting)**  
  A combinatorial search paradigm where tests reveal whether a pooled set contains any defective item. A d‑disjunct matrix guarantees that any set of up to d defectives can be uniquely identified from the test outcomes. *Why needed*: The algorithms use group testing to isolate supports; each query corresponds to a test that checks whether a coefficient’s support intersects a given set. *Quick check*: What property must a binary matrix have to ensure that any d columns have distinct syndromes? (Answer: d‑disjunctness: for any set of ≤ d columns and any other column, there exists a row where the other column has 1 and all columns in the set have 0.)

- **Basis Coherence and Compressed Sensing Limits**  
  Coherence measures the maximum inner product between distinct basis vectors. AND‑basis vectors are nested, leading to high coherence and violation of the Restricted Isometry Property required by compressed sensing. *Why needed*: Understanding this limitation motivates the shift from standard compressive techniques to adaptive group testing. *Quick check*: Give an example of two nested AND basis vectors and compute their inner product over {0,1}ⁿ. (Example: χ_{ {1} } and χ_{ {1,2} }; inner product = 2^{n‑2}.)

## Architecture Onboarding
The system comprises five logical components:
- **Query Scheduler**: Issues oracle calls f(x) and computes residual f_T(x) by subtracting contributions from the Coefficient Cache.
- **Bin Store**: Maintains a priority queue (FASMT) or level‑based lists (PASMT) of active bins, each storing its label ℓ, current value, and the test matrix H used so far.
- **Test Selector**: For FASMT, wraps Generalized Binary Splitting (GBSA); for PASMT, reads the next column from a precomputed d‑disjunct matrix.
- **Decoder** (PASMT only): After all rounds, decodes each leaf label ℓ to the unique support k of weight ≤ d using H.
- **Coefficient Cache**: Stores discovered (k, F(k)) pairs for residual computation and final output.

The main control flow (FASMT) is:
1. Initialize root bin (ε, f(1), empty matrix).
2. Pop smallest bin (ℓ, v, H) from the priority queue.
3. If v = 0, prune and loop.
4. Call GBSA(ℓ). If it returns (RESULT, z), set T(z) ← v.
5. Otherwise it returns (TEST, h). Construct query x = ¬((H∥h)·¬(ℓ∥0)).
6. Query residual m = f_T(x).
7. Push left child (ℓ∥0, m, H∥h) and right child (ℓ∥1, v−m, H∥h).

PASMT follows a similar high‑level loop but processes all bins in parallel per round using a fixed matrix; see Algorithm 1 for details.

**Design Tradeoffs**
- **FASMT vs PASMT**: FASMT achieves lower query complexity O(sd log(n/d)) but requires Θ(queries) adaptive rounds (essentially sequential). PASMT reduces adaptive rounds to O(d² log n), independent of s, at the cost of a factor d in queries.
- **Memory**: FASMT’s priority queue may hold up to O(sd log(n/d)) bins; PASMT stores O(s) bins per level, with O(d² log n) levels → O(sd² log n) total bin entries.
- **Matrix construction**: PASMT needs a d‑disjunct matrix of size O(d² log n) columns; constructing it takes O(d n log n) time using known methods (e.g., Kautz–Singleton). This is a one‑time cost.
- **GBSA overhead**: FASMT’s test selection is lightweight but sequential; its per‑split cost is O(d) for partitioning and binary splitting. PASMT’s matrix lookups are constant‑time per bin per round.

**Failure Signatures**
- **Unexpected zero bin sums**: May indicate violation of subset‑sum independence (cancellation) or premature pruning.
- **Decoding errors in PASMT**: Syndrome ℓ fails to decode → matrix too small or degree > d.
- **Residual mismatch in FASMT**: Off‑by‑one bin processing order causes cross‑bin contamination.
- **Query count blowup**: Poor group testing design (e.g., non‑disjunct matrix) or higher effective sparsity/degree.

**First 3 Experiments**
1. **Synthetic unit test**: Small instance (n=10, d=3, s=5) with random positive coefficients. Verify exact recovery and query count matches O(sd log(n/d)).
2. **Real hypergraph (ISCAS‑85)**: Apply FASMT to a circuit netlist (e.g., c499). Compare learned hyperedges against ground truth via random input evaluation.
3. **Scalability stress test**: Vary n up to 10,000 with s=100, d=10. Measure query and time scaling; confirm logarithmic dependence on n and linear on s,d.

## Open Questions the Paper Calls Out
1. **Question**: Can the proposed algorithms (FASMT and PASMT) be extended to handle noisy additive queries while maintaining exact learning guarantees?  
   **Basis in paper**: "Noise robustness: Our current framework uses an exact additive oracle. A natural extension is to adapt these algorithms to a noisy oracle. Given the direct application of group testing designs in our framework, the application of robust group testing results (Scarlett, 2019), particularly to PASMT, could yield robust extensions."  
   **Why unresolved**: The algorithms rely on precise bin sums to prune zero‑sum bins and isolate coefficients; noise corrupts these sums and may violate the subset‑sum independence assumption.  
   **What evidence would resolve it**: Development of robust versions using techniques like repeated queries for estimation or noise‑aware bin refinement, with theoretical guarantees under specific noise models; experimental validation on noisy synthetic/real hypergraphs.

2. **Question**: Can we achieve polynomial query complexity in s and d (ideally near‑optimal) while reducing adaptive rounds further, ideally independent of s?  
   **Basis in paper**: "Adaptivity: PASMT trades off a query complexity factor of d to remove the dependency on s. It is unclear if we can maintain polynomial query complexity in s and d while reducing the number of adaptive rounds further. In particular, fully adaptive algorithms that don't suffer from some of the restrictions of Kang et al. (2024) would be interesting."  
   **Why unresolved**: FASMT uses O(s) rounds (sequential bin processing) while PASMT uses O(d² log n) rounds but higher queries; the hybrid still has an sd term. A fundamental trade‑off may exist, but it is unknown if better parallelism is possible.  
   **What evidence would resolve it**: New algorithms combining non‑adaptive designs with limited adaptivity to achieve near‑optimal queries and sublinear in s rounds; lower bounds on the round‑query trade‑off; simulations demonstrating improved parallelization.

3. **Question**: Is the affine‑slice non‑cancellation assumption (Assumption 2) necessary for polynomial‑query exact learning, or can algorithms succeed without it?  
   **Basis in paper**: "Necessity of non‑cancellation: Our algorithms require the affine‑slice non‑cancellation assumption (Assumption 2). It remains open whether this assumption is necessary for efficient learning, or whether there exist polynomial‑query algorithms that succeed without it."  
   **Why unresolved**: The assumption ensures that bin sums are non‑zero iff a coefficient is present, enabling pruning. Without it, cancellations could mask coefficients, but it is not known if this can be overcome with more queries or smarter strategies.  
   **What evidence would resolve it**: A lower bound proving that without non‑cancellation, any exact learner requires super‑polynomial queries; or an algorithm that tolerates cancellations (e.g., by using additional tests to disentangle sums) while keeping query complexity polynomial in n,s,d.

## Limitations
- The algorithms assume known degree d and sparsity s, and require subset‑sum independence (no coefficient cancellations). Real‑world polynomials often have signed coefficients, which can cause bins to sum to zero and be pruned incorrectly.
- Practical construction of d‑disjunct matrices and details of GBSA are not fully specified; an explicit, efficient implementation for large n remains an open engineering challenge.
- Empirical validation is limited to a few hypergraphs with presumably positive coefficients; performance in noisy or signed settings is uncertain.

## Confidence
- **High**: The group‑testing framework and residual subtraction mechanism are theoretically sound (supported by Lemmas 1 and 4).
- **Medium**: Asymptotic query and time complexity claims are plausible but depend on optimistic assumptions about GBSA efficiency and d‑disjunct matrix construction; these have not been fully instantiated.
- **Low**: The reported near‑optimality ratios (2–4×) and robustness to real‑world complications have limited empirical evidence; the algorithms may degrade with cancellations or degree misspecification.
