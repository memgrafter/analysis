# Data-driven Clustering and Merging of Adapters for On-device Large Language Models

## Quick Facts
- **arXiv ID**: 2601.17441
- **Source URL**: https://arxiv.org/abs/2601.17441
- **Reference count**: 0
- **Primary result**: D2C clusters and merges LoRA adapters to achieve near-single-task performance with far fewer adapters (e.g., 26.0% avg on Llama 3.2 3B vs. 32.9% upper bound using only 5 merged adapters instead of 40).

## Executive Summary
On-device LLMs face severe storage constraints when storing many task-specific LoRA adapters. This paper introduces D2C, a method that uses only a few task examples (e.g., 10) to iteratively cluster adapters and then merge them within clusters. Evaluated on 40 tasks across three models with a 12.5% storage budget (5 merged adapters vs. 40 single-task), D2C significantly outperforms random and K-Means clustering (by ~2.1–4.5%) and approaches the single-task upper bound (32.9%). The approach is robust to varying cluster counts and numbers of examples.

## Method Summary
D2C operates on a set of pre-trained single-task LoRA adapters. Starting from a random partition of the adapters into K clusters, it performs T iterative refinement steps. In each step, it samples a cluster and an adapter from that cluster, tentatively moves the adapter to another cluster, and computes the loss of the merged adapter (via TIES) of the original cluster on the adapter’s task examples. The move is retained only if the loss does not increase. After iterations, adapters within each final cluster are merged using TIES to produce K multi-task adapters. The method uses minimal task data (10 examples) for clustering decisions and aims to maximize average task performance under a fixed storage budget.

## Key Results
- With K=5 clusters (12.5% storage), D2C achieves average scores: **26.0%** (Llama 3.2 3B), **24.6%** (Qwen 2.5 1.5B), **17.3%** (StableLM 2 1.6B).
- Outperforms random clustering and K-Means by **2.1–4.5%** absolute.
- Approaches the single-task upper bound of **32.9%** on Llama, with a gap of ~6.9%.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Iterative, loss-driven reassignment of adapters between clusters improves cluster quality beyond random or static initialization.
- **Mechanism**: Starting from a random partition, the algorithm repeatedly samples a cluster, moves one adapter out, evaluates the performance (via cross-entropy loss) of the *remaining* cluster’s merged adapter on that adapter’s original task data, and only retains the move if it does not increase loss. This greedy, local search explores the combinatorial space of partitionings, seeking clusters where the merged adapter performs well on all constituent tasks.
- **Core assumption**: The performance of a merged adapter (via TIES) evaluated on a task’s few examples is a reliable proxy for that task’s final performance when the merged adapter is deployed, and minimizing this loss leads to better multi-task adapters.
- **Evidence anchors**:
  - [abstract] "...employs an iterative optimization process to refine cluster assignments."
  - [section 3, Algorithm 1] Explicitly describes the loss evaluation and move acceptance criterion.
  - [corpus] Neighbors (e.g., "K-Merge") explore online variants, supporting the premise that iterative refinement is a viable direction for on-device adapter management.
- **Break condition**: If the loss evaluation on the few task examples becomes uncorrelated with true task performance (e.g., due to severe data mismatch or distribution shift), the iterative signal becomes misleading, and the clustering may degrade.

### Mechanism 2
- **Claim**: Clustering adapters primarily by task semantics (homogeneity) yields superior merged adapters compared to clustering by other characteristics like language family.
- **Mechanism**: The iterative loss minimization implicitly drives adapters with similar *functional objectives* (i.e., solving the same type of problem like summarization) into the same cluster. A merged adapter within a semantically homogeneous cluster is more likely to find parameter configurations that serve the shared objective well, avoiding the interference that occurs when merging fundamentally different tasks.
- **Core assumption**: Task type (e.g., grammar correction vs. QA) is a primary determinant of compatible LoRA parameter directions. Merging adapters for unrelated tasks causes destructive interference in the delta parameters.
- **Evidence anchors**:
  - [section 4.3, "Identified Clusters"] "The identified clustering is done predominantly by task."
  - [section 4.3, Figure 3] Dirichlet sampling experiments show that enforcing task-homogeneous clusters (small α) improves performance, while language-homogeneous clusters do not.
  - [corpus] Weak direct evidence; neighbors focus on merging/selection mechanics, not the *basis* for grouping. Assumption: This aligns with general multi-task learning literature which posits task-relatedness.
- **Break condition**: If tasks within a cluster have conflicting optimal parameter directions despite similar high-level goals (e.g., summarization vs. tone adjustment both being "generation" but requiring opposite stylistic changes), homogeneity may not guarantee mergeability.

### Mechanism 3
- **Claim**: The choice of merging technique (e.g., TIES) is a critical enabler that transforms a good cluster into a high-performing multi-task adapter, and D2C’s clustering is complementary to advanced merging.
- **Mechanism**: Clustering groups compatible adapters. The subsequent merging algorithm (TIES in the paper) resolves conflicts in the individual LoRA parameters (A, B matrices) by filtering low-magnitude changes and resolving sign conflicts. A cluster found by D2C provides a set of adapters with sufficient common signal for the merging algorithm to extract a coherent set of parameters.
- **Core assumption**: Merging techniques like TIES are effective at extracting a "consensus" parameter update from a set of compatible fine-tunes. D2C’s role is to assemble sets where such a consensus exists and is beneficial.
- **Evidence anchors**:
  - [abstract] "...the adapters within each cluster are merged."
  - [section 3] "...merge the LoRAs within each cluster to obtain multi-tasking LoRAs."
  - [section 4.3, "Alternative Merging Strategy"] Shows D2C maintains advantage over random clustering even with a different merging method (linear), indicating its clustering is the primary driver of improvement, but merging quality modulates final score.
  - [corpus] {"paper_id": 48959} "Tensorized Clustered LoRA Merging..." directly studies the interaction of clustering and tensorized merging, providing contextual evidence that these are coupled problems.
- **Break condition**: If the merging technique is fundamentally incapable of combining the adapters in a cluster (e.g., extreme sign conflicts, disjoint learned features), even a perfectly chosen cluster by D2C will yield a poor merged adapter.

## Foundational Learning
- **Concept**: **LoRA (Low-Rank Adaptation)**
  - **Why needed**: The entire system operates on LoRA adapters ((A, B) matrices). Understanding that these are low-rank approximations of full fine-tuning updates is crucial to grasp why they are storable, mergeable, and why interference during merging is a key challenge.
  - **Quick check**: If a LoRA adapter has rank *r*, how does the number of trainable parameters compare to a full fine-tuning of a *d*-dimensional activation layer?

- **Concept**: **Model/Adapter Merging (e.g., Task Arithmetic, TIES)**
  - **Why needed**: The end goal is to fuse multiple (A, B) pairs into one ((A_merge, B_merge)). Principles like sign agreement (TIES) or weighted average (Task Arithmetic) are the operations that realize the merger. The effectiveness of D2C is predicated on these operations working well on the grouped adapters.
  - **Quick check**: What problem does the "sign election" step in TIES aim to solve when merging multiple fine-tuned models?

- **Concept**: **Clustering as Partition Optimization**
  - **Why needed**: D2C formulates the adapter grouping as finding a partitioning (θ) that minimizes a loss-based objective. This is a combinatorial optimization problem, related to but distinct from classic clustering (like K-Means) because its objective function is defined by a downstream merging+evaluation operation, not a static distance metric.
  - **Quick check**: Why might clustering adapters based on Euclidean distance between flattened (A, B) matrices (a naive K-Means approach) be a poor proxy for finding clusters that merge well?

## Architecture Onboarding
Component map: Adapter Repository -> Task Example Bank -> Clustering Engine (D2C) -> Merging Module (TIES) -> Deployment Package

Critical path:
Random initial partition -> [Iteration T times: Sample (c, t) -> Compute loss of merge(cluster c) on D_t -> Tentatively move adapter t to c' -> Compute loss of merge(c') on D_t -> Accept move if ℓ ≤ ℓ'] -> Final partition θ -> Merge LoRAs per cluster in θ -> Output K merged adapters.

Design tradeoffs:
- Storage budget vs. average performance: More clusters (K) means less merging interference per cluster, improving performance but increasing storage. D2C aims to maximize performance for a given K.
- Example cost vs. clustering quality: More examples (*n*) likely give a more reliable loss signal for each move evaluation, improving clustering but requiring more access to task data.
- Offline compute time vs. deployment gain: The T iterations (e.g., 200) require GPU time (~1.3 hrs for 40 tasks). This is a one-time cost for a given set of adapters.

Failure signatures:
- No loss improvement after many iterations: The initialization or task data may be uninformative; clusters might already be near-local optima, or tasks are fundamentally incompatible.
- Extreme cluster imbalance: Some clusters become very large (>N/K) while others tiny, indicating the loss heuristic may be getting stuck or that task compatibility is highly uneven.
- Performance approaches random clustering: D2C’s iterative signal is not guiding better than noise; likely the few-shot loss evaluation is not predictive of true multi-task utility.

First 3 experiments:
1. Baseline Replication: Implement random clustering and K-Means (on flattened params and on SVD features) merging pipelines to establish the performance baseline (~20-22% in the paper’s metric) and confirm TIES implementation correctness.
2. D2C Sanity Check: Run D2C with a single cluster (K=1). This should perform similarly to merging all 40 adapters into one (paper reports ~18.7% for Llama), verifying the merging pipeline itself works and that the iterative process doesn’t break with K=1.
3. Loss Correlation Spot-Check: For a small subset of tasks (e.g., 5), after running D2C, manually compute the loss of a final merged adapter on the *full* validation set of each constituent task. Check if the loss on the 10 examples used during clustering correlates (rank) with the full-set loss. This tests the core proxy assumption.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: What specific properties of LoRA adapters (e.g., feature alignment, interference patterns) make task-based clustering substantially more effective than language-based clustering for multi-task merging, as suggested by the Dirichlet sampling experiments?
- **Basis in paper**: [inferred] The paper’s analysis in Figure 3 shows that clusters homogeneous in task (“Dirichlet (task)”) yield higher performance than clusters homogeneous in language (“Dirichlet (lang.)”), but it does not analyze the internal characteristics of the adapters or the tasks that explain this disparity.
- **Why unresolved**: The empirical result is presented without mechanistic insight. Understanding *why* task affinity dominates could inform better clustering objectives or merging criteria beyond the current loss-based proxy.
- **What evidence would resolve it**: An analysis correlating adapter merging performance with measurable metrics of task similarity (e.g., gradient similarity, output representation overlap) versus language similarity. Ablation studies isolating the effect of task vs. language in synthetic cluster assignments would also clarify the dominant factor.

### Open Question 2
- **Question**: What is the theoretical performance bound for clustering-based adapter merging under a fixed storage budget, and how close does D2C operate to this bound across diverse task distributions?
- **Basis in paper**: [explicit] The paper states D2C’s performance (e.g., 26.0% on Llama) approaches but remains below the single-task upper bound (32.9%), leaving an unexplained performance gap. The authors note this gap but do not characterize its source or limit.
- **Why unresolved**: The gap could stem from inherent interference between tasks, suboptimal merging (TIES), or clustering limitations. Without a theoretical framework, it is unclear whether the gap is fundamental (due to task conflicts) or practical (due to the algorithm).
- **What evidence would resolve it**: A formal analysis of merging error as a function of task similarity and cluster size. Empirical studies varying task similarity (e.g., within-cluster task diversity) could isolate whether the gap is due to negative interference between dissimilar tasks forced into one cluster.

### Open Question 3
- **Question**: How does the computational cost of D2C’s iterative optimization scale with the number of adapters (N) and how can its efficiency be improved for large-scale deployment scenarios (e.g., hundreds of tasks)?
- **Basis in paper**: [inferred] The paper reports a 1.3-hour clustering time for 40 adapters on a single GPU but does not analyze algorithmic complexity or scalability to larger N, which is critical for real-world on-device ecosystems with many tasks.
- **Why unresolved**: The iterative process (T iterations, each evaluating merge changes) may become prohibitively slow as N grows. The paper does not provide a complexity analysis or explore approximations (e.g., mini-batch swaps, early stopping) to reduce cost.
- **What evidence would resolve it**: Empirical scaling experiments measuring runtime vs. N (e.g., 100, 500 adapters). Analysis of convergence behavior to determine if fewer iterations suffice for larger N. Development and testing of heuristic initializations (e.g., using K-Means as a warm start) to reduce total iterations needed.

## Limitations
- Missing adapter weights, dataset splits, and TIES implementation details hinder exact reproduction.
- Clustering decisions based on only 10 examples per task may not reliably predict full task performance.
- Greedy iterative search lacks optimality guarantees; scalability to hundreds of tasks is unclear.
