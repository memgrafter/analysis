# Online Learning with Limited Information in the Sliding Window Model

## Quick Facts
- **arXiv ID**: 2601.03533
- **Source URL**: https://arxiv.org/abs/2601.03533
- **Reference count**: 24
- **Primary result**: With two queries per day and polylogarithmic memory, they achieve near-optimal interval regret O(√(n|I|) polylog(nT)) and sliding window regret O(√(nW) polylog(nT)); in the single-query streaming bandit setting, they obtain O(n T^{2/3}) polylog(T) with polylog memory, the first sublinear regret in that model; under the assumption that the best expert’s losses are in random order, they further improve to optimal O(√(nT)) regret.

## Executive Summary
The paper tackles the online learning experts problem in the sliding window model, where recent data is more valuable, while limiting the number of queries per round and the memory footprint. For the two-query setting (one free query), the authors design a pool-based algorithm that maintains a small set of experts via hierarchical merging and a covering condition, achieving near-optimal interval and sliding-window regret with only polylogarithmic memory. In the single-query streaming model (no free queries), they combine uniform exploration with recursive boosting to obtain the first sublinear regret O(n T^{2/3}) using polylog memory. Under the additional assumption that the losses of the best expert appear in random order, a binary search–style algorithm attains optimal O(√(nT)) regret with a single query and polylog memory. The core innovations include careful low-variance loss estimation, breaking dependencies in recursive compositions, and adaptive pruning.

## Method Summary
The algorithm operates by maintaining a dynamic pool of experts. At each epoch, experts are sampled into the pool with probability 1/n, and an EXP3-style bandit algorithm (Multiplicative Weights Update) is run on the pool. To keep memory low, a covering condition prunes experts whose cumulative loss is significantly worse than a benchmark derived from a filtered set of promising experts; this is combined with hierarchical merging across epochs, ensuring the pool size stays polylogarithmic. In the two-query variant, the free query provides low-variance loss estimates by uniformly sampling an expert from the pool, enabling accurate testing of the covering condition and unbiased MWU updates. To improve the T^{2/3} regret of the single-query case, the authors recursively compose baseline algorithms (Baseline_k) in a boosting hierarchy, where an outer EXP3 selects among subroutines. By using the free query to separate exploration (estimating losses for both experts and meta-algorithms) from exploitation, they break circular dependencies and shrink the bad-epoch cost from B to √B per level, ultimately reaching √T after O(log n) levels. For sliding-window regret, multiple instances of the two-query baseline are run for dyadic interval lengths and combined via the SQUINT meta-algorithm. When the best expert’s losses are in random order, a simpler binary search approach evicts suboptimal experts by checking their empirical loss on dynamically sized intervals, achieving optimal regret.

## Key Results
- With two queries per day and polylogarithmic memory: interval regret O(√(n|I|) polylog(nT)) for any interval I, and sliding-window regret O(√(nW) polylog(nT)).
- In single-query streaming (one costly query per round): regret O(n T^{2/3}) polylog(T) with polylog memory; this is the first sublinear guarantee in this model with limited memory.
- Under the assumption that the best expert’s losses are in random order: optimal O(√(nT)) regret using a single query and polylog memory.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Achieving polylogarithmic memory while maintaining near‑optimal regret by maintaining a small pool of experts and aggressively pruning those with loss sequences not competitive against a benchmark.
- **Mechanism**: At the start of each epoch, sample each expert into a pool with probability 1/n. Within the pool, run an EXP3‑style algorithm (with two query signals) to select actions. Periodically merge subpools and evict any expert i whose estimated loss over its duration D satisfies ˜L(D)(i) ≥ ˜L(D)(BM) − C·nlog(nT)|D|^ρ, where ˜L(D)(BM) is the minimum estimated loss among a small filter set. This covering condition ensures only experts with exponentially decreasing losses remain, bounding pool size by O(polylog(nT)). The hierarchical merging (using a procedure like Merge) maintains this bound over time.
- **Core assumption**: The best expert eventually enters the pool; if it is not evicted quickly, it remains competitive, and the covering condition is strong enough to remove non‑optimal experts while preserving the best one.
- **Evidence anchors**:
  - [abstract] states: "with two queries per day and polylogarithmic memory, they achieve near‑optimal interval regret O(√(n|I|) polylog(nT))".
  - [section 2.1] discusses why histogram‑based and coreset approaches fail and introduces the pool idea.
  - [section 4] formally defines the pool, eviction rule (Definition 1), and Lemma 4.1 proves the merge step keeps pool size polylog.
- **Break condition**: If the best expert is never sampled (probability drops exponentially in n) or if the covering threshold is too loose (causing many experts to survive), pool size could grow linearly, increasing memory and regret.

### Mechanism 2
- **Claim**: Overcoming dependency between the inner and outer updates in a recursive boosting scheme for partial‑information settings, thereby reducing regret from T^{2/3} to the optimal √T while using only two queries per round.
- **Mechanism**: Construct a hierarchy of “baseline” algorithms A_1, A_2, … ; an outer EXP3 plays one of these each day. The key is to estimate losses for both arms and baseline algorithms using the second query via uniformly random sampling, and to separate these “exploration” updates from the “exploitation” plays. By fixing the randomness of the second query, the loss estimates become deterministic functions of the past, breaking the circular dependency. This allows applying the same covering argument recursively, shrinking the bad‑epoch regret from B to B^{2/3} per recursion level, ultimately reaching O(√T) after O(log n) levels.
- **Core assumption**: With two queries we can obtain unbiased loss estimates with variance O(√D) for any duration D; with high probability these estimates remain close to true losses over all relevant intervals. The outer EXP3 can then be analyzed as if it received full feedback on the meta‑experts.
- **Evidence anchors**:
  - [abstract] mentions “boost[ing] with additional queries… removing dependencies” and Algorithm 10 (Baseline_k) in Section 5.
  - [section 2.2] explains the dependency issue and how separating learning/exploitation days resolves it; Lemmas 5.2 and 5.3 bound estimation errors.
  - [corpus] shows prior work [PR23] achieved polylog memor for full‑information; this work extends to partial‑information by using the second query for low‑variance estimates.
- **Break condition**: If the second query’s random sampling fails to provide sufficiently accurate loss estimates (e.g., too few samples for long durations), the covering condition may not fire at the right times, causing bad epochs to dominate and regret to degrade.

### Mechanism 3
- **Claim**: Under a random‑order assumption for the best expert’s loss sequence, a simple binary‑search style algorithm attains optimal O(√T) regret with only a single query and polylog memory.
- **Mechanism**: Start with a target error rate C/√T (C=1) and cycle through experts, measuring their empirical loss over intervals of length B_C = O(√T / (C+1)). If an expert’s loss over such an interval exceeds C/√T by a margin, evict it; otherwise keep it and continue checking. If no expert survives, increase C and restart. Because the best expert’s losses are in random order, with high probability its empirical loss will stay within the target once C ≈ true error rate, and it will never be evicted. For sub‑optimal experts that temporarily appear good, the “reverse regret” (the algorithm benefiting from their temporary excellence) amortizes the cost of checking them.
- **Core assumption**: The loss sequence of the best expert is a uniformly random permutation (or at least exchangeable). This ensures that short intervals where its loss is unusually low occur with predictable probability, preventing premature eviction.
- **Evidence anchors**:
  - [abstract] states: “under the assumption that the best expert’s losses are in random order, they further improve to optimal O(√(nT)) regret”.
  - [section 2.3] outlines the binary search approach and dynamic checking; Algorithm 16 and Lemma 8.4 prove √T regret.
  - [corpus] Although the corpus does not include random‑order bandit papers, it shows related work on bandit optimality (e.g., [LZC+24] for two‑query). The random‑order model is standard in streaming; see [SWXZ22] cited in the paper.
- **Break condition**: If the best expert’s losses are adversarially ordered, the algorithm may evict it and suffer linear regret; the guarantee is conditional on the random‑order assumption.

## Foundational Learning
- **Concept: EXP3 algorithm**
  - **Why needed here**: The core of the approach is an adversarial multi‑armed bandit algorithm that balances exploration and exploitation with bandit feedback. All baselines and outer EXP3 instances are variants of EXP3 or “learning with exploration” (warm‑start weights).
  - **Quick check**: How does the exploration rate γ affect the bias‑variance trade‑off in EXP3 with underestimated losses?
- **Concept: Sliding window model**
  - **Why needed here**: The goal is to achieve regret measured over recent windows (or any interval) rather than the whole horizon, reflecting time‑sensitive applications.
  - **Quick check**: Why can’t standard streaming histogram techniques (e.g., DGIM) be directly applied to the sliding window in the partial‑information setting?
- **Concept: Recursive boosting in memory‑bounded learning**
  - **Why needed here**: To reduce the exponent on T from 2/3 to 1/2 while keeping polylog memory, the paper recursively composes algorithms, requiring a mechanism to break dependencies caused by limited feedback.
  - **Quick check**: In the boosting hierarchy, why is it necessary to fix the randomness of the second query before analyzing the outer EXP3?

## Architecture Onboarding
- **Component map**: Pool Manager → Exploration Controller → Meta‑Expert Hierarchy → (Interval Orchestra for sliding‑window or Random‑Order Searcher for random‑order case).
- **Critical path**: Input loss sequence → (Day) → Pool updates (if new epoch) → Exploration/Exploitation decision (use second query to estimate) → Arm selection (draw from distribution) → Observed loss → Update estimated losses → Possibly evict arm or restart baseline → Outer weight updates. For interval version, the path branches to run all interval algorithms in parallel and weight their distributions.
- **Design tradeoffs**:
  - Memory vs. Regret: More hierarchical levels (boosting depth) reduces regret but increases polynomial factors; pooling depth controls memory.
  - Query usage: One query (bandit) forces exploration costs → T^{2/3} regret; two queries enable low‑variance estimation → √T regret.
  - Window sensitivity: Sliding‑window regret requires handling all intervals, which is achieved by simulating interval‑regret algorithms; this costs only O(log T) extra memory.
- **Failure signatures**:
  - Pool size explosion: If covering condition fails (e.g., estimation error too large), Lemma 4.1 fails → linear memory.
  - Dependency leakage: If exploration/exploitation separation not precise, outer EXP3 analysis fails → bad epoch cost becomes B instead of √B.
  - Random‑order violation: Binary search evicts best expert → linear regret.
- **First 3 experiments**:
  1. **Baseline single‑query scaling**: Run Algorithm 6 on synthetic adversarial losses with varying T and n; measure memory (should be polylog) and regret (should scale like n T^{3/4}). Verify pool size stays bounded.
  2. **Two‑query boosting depth**: Implement Algorithm 10 with k=1,2,3; test regret vs T on fixed n. Expect improvement from T^{2/3} to T^{1/2} as k increases, but watch polynomial blow‑up in constants.
  3. **Sliding‑window interval regret**: Run Algorithm 11 for all intervals I; compute max interval regret over windows of various sizes. Should scale as √(n|I|) polylog. Check memory stays polylog as W varies.

## Limitations
- All results assume an oblivious adversary and a fixed query budget.
- Polylog‑memory guarantees require the covering condition to successfully prune experts; otherwise the pool size may grow linearly.
- The construction of the interval algorithm (ALG_κ) for arbitrary intervals is ambiguous, potentially affecting the claimed sliding‑window guarantees.
