# CreativeBench: Benchmarking and Enhancing Machine Creativity via Self-Evolving Challenges

## Quick Facts
- arXiv ID: 2603.11863  
- Source URL: https://arxiv.org/abs/2603.11863  
- Reference count: 40  
- Primary result: CreativeBench introduces a rigorous, executable benchmark for machine creativity with two tracks (Combo and Explore) and a unified Creativity metric; EvoRePE steering consistently enhances creativity across models.

## Executive Summary
The paper addresses the lack of standardized evaluation for machine creativity, particularly in self-evolving code generation systems. It introduces CreativeBench, a benchmark grounded in Boden’s cognitive framework, featuring two subsets: CreativeBench-Combo (combinatorial creativity via domain fusion) and CreativeBench-Explore (exploratory creativity via constrained self-play). The benchmark uses executable Python code and defines Creativity as the product of solution Quality (Pass@1) and Novelty (embedding and n-gram distance from baselines). Evaluating state-of-the-art models reveals scaling improves combinatorial creativity but yields diminishing returns for exploration, larger models become more correct but less divergent, and reasoning primarily benefits constrained exploration. The paper also proposes EvoRePE, an inference-time steering method that extracts a creativity vector from evolutionary trajectories and boosts creativity across models.

## Method Summary
CreativeBench construction:  
- **Combo track**: Take two Python solutions from different domains (e.g., mathematics, games), fuse them into a new specification, generate tests for that specification, and reverse-engineer a natural language problem description.  
- **Explore track**: Start from seed tasks and iteratively stack constraints between a Generator (produces code) and a Solver (attempts to satisfy constraints); a new level is created only when the Solver succeeds, progressively tightening challenges.  
Both tracks apply three filtering stages: (i) difficulty (Pass@1 < 100% on five sampled solutions), (ii) quality audit (LLM judge checks signature and test consistency), and (iii) diversity (semantic deduplication via embedding cosine similarity < 0.85).  

Creativity metric:  
Quality = Pass@1 (sandbox execution). Novelty = 1 − cos(embedding) + Jaccard(4‑grams). For Explore, novelty measures deviation from an unconstrained baseline; for Combo, novelty averages deviation from the two source solutions.  

EvoRePE: Collect pairs of (standard, evolved) prompts from an evolutionary search (e.g., AlphaEvolve). Extract hidden activations at a chosen layer (e.g., layer 26 for Qwen2.5‑7B), compute activation deltas, and run PCA to obtain a creativity vector \(v\). During inference, steer by adding \(\alpha v\) to the hidden states.

## Key Results
- Scaling significantly improves combinatorial creativity but yields diminishing returns for exploration.  
- Larger models exhibit “convergence-by-scaling,” becoming more correct but less divergent.  
- Reasoning capabilities primarily benefit constrained exploration rather than combination.  
- EvoRePE, a plug-and-play inference-time steering strategy, consistently enhances creativity across models and is orthogonal to the underlying evolutionary algorithm.

## Why This Works (Mechanism)
The benchmark operationalizes Boden’s dual facets of creativity by deliberately engineering challenges that require either domain fusion (combinatorial) or search under constraints (exploratory). Executable code provides an objective quality signal, while dual novelty metrics (semantic distances plus n-gram overlap) ensure meaningful divergence without rewarding trivial changes. EvoRePE hypothesizes that evolutionary trajectories toward successful solutions induce systematic shifts in model activations; the principal component of these shifts (the creativity vector) captures a direction that, when applied, nudges the model toward more creative outputs without sacrificing correctness. The method’s orthogonal gains suggest it taps into a generalizable latent factor for creativity.

## Foundational Learning
**1. Boden’s Creativity Framework**  
*Why needed*: Distinguishes combinatorial (mixing existing concepts) and exploratory (searching within a conceptual space) creativity, directly motivating the two benchmark tracks.  
*Quick check*: Explain how domain fusion maps to combinatorial creativity and constraint-based self-play to exploratory creativity.

**2. Executable Code Evaluation (Pass@1)**  
*Why needed*: Provides automated, objective quality assessment by running generated code in a sandbox.  
*Quick check*: Set up a Python sandbox and verify that given a solution and unit tests, Pass@1 correctly counts passing generations.

**3. Dual Novelty Metrics (Semantic + Syntactic)**  
*Why needed*: Captures both meaning-level and surface-level divergence, avoiding degenerate novelty (e.g., only renaming variables).  
*Quick check*: Compute cosine similarity and Jaccard 4‑gram distance between two semantically equivalent code snippets with different formatting; verify novelty increases.

**4. Evolutionary Code Search (AlphaEvolve/GEPA)**  
*Why needed*: Generates a curriculum of challenging problems (for Explore) and produces trajectories for EvoRePE vector extraction.  
*Quick check*: Implement a simple mutate‑and‑evaluate loop that improves a solution over generations on a fixed coding task.

**5. Activation Steering via PCA**  
*Why needed*: Enables inference-time control without retraining; PCA summarizes common activation shifts correlated with creative solutions.  
*Quick check*: Given a set of activation pairs, compute PCA and ensure the first component explains >50% variance.

## Architecture Onboarding
**Component map**  
Seed Pool → Combo/Explore Constructor → Filtering → CreativeBench Dataset → Evaluation Engine → Creativity Scores  
Evolutionary Search → EvoRePE Extractor → Steering Module → Creative+ Generation  

**Critical path**  
1. Select seed tasks from AutoCodeBench Python subset.  
2. Run Combo and Explore construction pipelines.  
3. Apply three-stage filtering (difficulty, quality audit, diversity).  
4. Assemble final benchmark splits.  
5. For evaluation: sample model solutions, compute Pass@1 and Novelty, aggregate Creativity.  
6. For EvoRePE: collect evolutionary prompt pairs, extract activations, compute PCA vector, steer inference.

**Design tradeoffs**  
- *Combo*: Domain fusion yields diverse challenges but risks generating ill-specified tasks; balancing domain similarity is key.  
- *Explore*: Constraint stacking may produce unsatisfiable constraints early; careful constraint design and solver refinement loops are needed.  
- *Filtering*: Strict criteria ensure quality but reduce dataset size and may introduce bias; a tradeoff exists between rigor and coverage.  
- *Novelty metric*: Embedding distance is model‑dependent and costly; n‑gram distance is cheap but only surface-level; weighting them influences score stability.  
- *EvoRePE*: Layer and token selection (e.g., layer 26, last token) may not generalize across models; steering strength \(\alpha\) requires tuning to avoid quality degradation.

**Failure signatures**  
- Combo tasks have Pass@1 near 0% or 100% after difficulty filtering.  
- Explore construction stalls at low constraint levels (no advancement).  
- Filtering removes >90% of generated instances, indicating overly strict criteria.  
- Novelty scores cluster near zero for all solutions, suggesting metric collapse.  
- Steering with EvoRePE drastically lowers Pass@1 without novelty improvement.

**First experiments**  
1. **Mini‑Combo prototype**: Implement Combo construction for one domain pair (e.g., math + games) on 5 seed solutions each. Generate and filter 10 tasks; verify novelty distribution relative to source solutions.  
2. **EvoRePE vector extraction**: Run a simple evolutionary search (mutation + selection) on a single task for 20 generations. Extract activations, compute PCA, and apply steering to a held‑out prompt; measure changes in novelty and Pass@1.  
3. **Metric sanity check**: On 20 human‑written and model‑generated solutions, compute Creativity components and confirm that intentionally creative modifications increase novelty while preserving quality.

## Open Questions the Paper Calls Out
1. **Generalizing to non‑executable domains**: How can the framework be adapted for creative domains like storytelling or music, where quality is not execution‑grounded? What automated quality and novelty metrics would correlate with human judgment?  
2. **Process‑based creativity signals**: Can interaction traces (intermediate solutions, revisions) provide a process metric that complements outcome scores? How to automatically extract and validate such traces from LLMs?  
3. **Language generalizability**: Does the exclusive use of Python affect the observed scaling and reasoning trends? Would findings hold for other programming paradigms (e.g., functional, systems languages)?  
4. **Transferability of EvoRePE vectors**: Is the creativity vector general across models and tasks, or is it tied to the specific evolutionary trajectories and base model used for extraction?

## Limitations
- Prompt templates and detailed generation procedures (fusion, constraint stacking, LLM audit) are omitted, hindering faithful reconstruction of the full benchmark.  
- Activation extraction specifics (token position, representation layer, aggregation method) are under‑specified, limiting reproducibility of EvoRePE.  
- Evolutionary hyperparameters for baselines (AlphaEvolve, GEPA) are not fully documented, making accurate replication difficult.  

## Confidence
- **Benchmark Construction Process**: Medium  
- **Creativity Metric (Quality × Novelty)**: Medium  
- **EvoRePE Steering Effectiveness**: Low‑to‑Medium  
- **Scaling & Convergence Findings**: High  

## Next Checks
1. **Prompt Reconstruction Audit**: Implement the Combo/Explore pipelines for a seed subset (e.g., 10 tasks each) using the paper’s high‑level descriptions. Compare output diversity and difficulty against the paper’s reported statistics to infer missing prompt constraints.  
2. **EvoRePE Ablation**: On a fixed evolutionary trajectory set, systematically vary token aggregation (last vs. mean), representation (residual vs. MLP output), and layer choice. Measure novelty gain stability to identify robust extraction settings.  
3. **Evolutionary Baseline Reproduction**: For a small domain, re‑run AlphaEvolve/GEPA with best‑effort hyperparameters (mutation rate, population size). Compare solution novelty distributions against any available trajectory snippets from the paper to calibrate search dynamics.
