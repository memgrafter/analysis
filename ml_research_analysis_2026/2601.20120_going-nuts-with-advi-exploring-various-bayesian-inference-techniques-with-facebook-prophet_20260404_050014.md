# Going NUTS with ADVI: Exploring various Bayesian Inference techniques with Facebook Prophet

## Quick Facts
- **ArXiv ID:** 2601.20120
- **Source URL:** https://arxiv.org/abs/2601.20120
- **Reference count:** 17
- **Primary result:** Reimplementation of Prophet in PyMC enables comparison of Bayesian inference methods; NUTS converges best, ADVI/FullRank ADVI converge fast but mis-calibrate uncertainty, and DMZ yields the lowest forecast MSE despite non-convergence.

## Executive Summary
Facebook Prophet's limited inference options and inflexible API hinder comprehensive evaluation of Bayesian methods for time-series forecasting. This paper addresses these limitations by fully reimplementing Prophet in PyMC, leveraging its modular, operator-based API and unified inference interface. The authors compare six Bayesian approaches—NUTS, Metropolis-Hastings (MH), Discrete Metric Zero (DMZ) MCMC, MAP, ADVI, and FullRank ADVI—on the classic Peyton Manning Wikipedia daily page-view dataset. Key findings: NUTS is the only MCMC method that converges (R-hat <1.01, ESS >400) and provides a high effective sampling rate (170 samples/sec); ADVI and FullRank ADVI converge quickly (~15-19 seconds) but suffer from mis-calibrated uncertainty (overconfidence vs. underconfidence); MAP is fastest but yields no uncertainty; and DMZ, despite non-convergence, achieves the best forecast MSE (0.579). The work demonstrates the value of flexible Bayesian tooling for rigorous model comparison and highlights trade-offs between convergence reliability, computational efficiency, and uncertainty representation.

## Method Summary
The authors reconstructed the Prophet model in PyMC using a modular API where each component (trend, seasonality) is defined as a separate PyMC random variable or deterministic and combined via arithmetic operators to reflect additive/multiplicative decompositions. The model includes a piecewise linear trend with 25 change points, additive yearly seasonality (Fourier order 10), and weekly seasonality (Fourier order 3). Priors are set as in the original Prophet: slope and intercept ~ Normal(0,5), changepoint deltas ~ Laplace(0,0.05), seasonality coefficients ~ Normal(0,10). The dataset comprises daily log page views for Peyton Manning, split into two years for training and one year for testing. Six Bayesian inference methods are evaluated: NUTS (4 chains, 2000 draws, 1000 warm-up), MH and DMZ (1,000,000 draws, 10,000 warm-up), ADVI and FullRank ADVI (100,000 iterations), and MAP. Performance is measured via forecast error metrics (MSE, RMSE, MAE, MAPE) on the hold-out period, MCMC convergence diagnostics (R-hat, ESS), and variational ELBO. Timing and effective sampling rates are also recorded.

## Key Results
- NUTS is the only MCMC method to converge (R-hat <1.01, ESS >400) and achieves the highest effective sampling rate (170 samples/sec).
- ADVI and FullRank ADVI converge rapidly (~15-19 sec) but misrepresent uncertainty: ADVI is overconfident, FullRank ADVI underconfident relative to NUTS reference.
- MAP estimation is fastest but provides only a point estimate; DMZ yields the best forecast MSE (0.579) despite failing to converge.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The modular, operator-based API in PyMC enables faithful reimplementation of Prophet’s decomposable structure and flexible composition of model components.
- **Mechanism:** By defining each component (e.g., trend, seasonality) as a separate PyMC random variable or deterministic, and overloading arithmetic operators (+, *), the model’s mathematical form (additive or multiplicative) is translated into a computational graph that PyMC’s inference engines compile.
- **Core assumption:** Prophet’s additive/multiplicative decompositions map cleanly onto arithmetic operations within PyMC’s declarative modeling context.
- **Evidence anchors:** Abstract and Section II.B describe the modular API and operator overloading; the paper demonstrates successful model construction and inference.
- **Break condition:** If model components involve non-linear interactions or hierarchical dependencies not expressible via simple arithmetic, the operator composition could become cumbersome or ambiguous.

### Mechanism 2
- **Claim:** PyMC’s unified inference interface allows the same Prophet model to be evaluated with multiple Bayesian algorithms (MCMC, VI, MAP) without rewriting model code.
- **Mechanism:** After defining the model within a PyMC `Model` context, different inference functions (`pm.sample()`, `pm.fit()`, `pm.find_MAP()`) are called on the same model object; PyMC handles compilation, gradient computation, and adaptation internally.
- **Core assumption:** PyMC’s inference implementations are correctly configured for the Prophet model’s continuous parameter space and lack of discrete latent variables.
- **Evidence anchors:** Abstract and Sections II.C–II.E describe applying NUTS, MH, DMZ, ADVI, FullRank ADVI, and MAP to the same PyMC model; results show all methods run successfully (except convergence issues).
- **Break condition:** If the model contains parameters or structures incompatible with a specific algorithm (e.g., discrete variables for NUTS), that method would fail or require workarounds.

### Mechanism 3
- **Claim:** The reimplementation provides built-in diagnostics and timing infrastructure, enabling empirical assessment of convergence and efficiency across methods.
- **Mechanism:** PyMC’s sampling traces are analyzed (e.g., via ArviZ) to compute R-hat and ESS; variational inference tracks negative ELBO; execution time is measured via Python timing. These metrics are compared to identify convergence and performance.
- **Core assumption:** The chosen thresholds (R-hat <1.01, ESS >400) are sufficient to judge convergence for this model and dataset.
- **Evidence anchors:** Section III.C describes convergence diagnostics; Section IV.A presents R-hat and ESS tables showing only NUTS converges; Section IV.B shows ELBO convergence for VI.
- **Break condition:** If diagnostics are misleading (e.g., R-hat converges while chains are trapped in separate modes for multimodal posteriors), the assessment of convergence quality may be incorrect.

## Architecture Onboarding
**Component map:**  
Model specification layer (component classes: LinearTrend, FourierSeasonality) -> Composition layer (arithmetic operator overloading: +, *) -> PyMC Model -> Inference layer (PyMC functions: NUTS, MH, DMZ, ADVI, FullRank ADVI, MAP) -> Diagnostics layer (ArviZ: R-hat, ESS, ELBO; timing; forecast MSE)

**Critical path:**
1. Define model components (e.g., `LinearTrend()`, `FourierSeasonality(p=365.25, order=10)`).
2. Combine components with `+` or `*` inside a `with pm.Model() as model:` block.
3. Choose inference method: call `pm.sample()` for MCMC, `pm.fit()` for VI, or `pm.find_MAP()` for MAP.
4. Extract posterior samples/approximation, compute diagnostics and forecasting metrics.
5. Compare results across methods.

**Design tradeoffs:**
- Flexibility vs. performance: PyMC offers many inference options but may be slower than Prophet’s optimized Stan backend for simple MAP/NUTS.
- Modularity vs. simplicity: The component-based API is more extensible but adds abstraction; users must understand PyMC’s random variable semantics.
- Diagnostic richness: Full MCMC provides reliable diagnostics (ESS, R-hat) but at high computational cost; VI is fast but offers less direct convergence assurance (ELBO plateau ≠ accurate posterior).

**Failure signatures:**
- MCMC: R-hat > 1.01, ESS < 400 for key parameters, high autocorrelation in trace plots.
- VI: ELBO not decreasing steadily, poor calibration (e.g., ADVI variance too small/large compared to NUTS), or high reconstruction error on holdout forecasts.
- MAP: Only a single point estimate; no uncertainty quantification; potential for getting stuck in local mode if optimization fails.
- General: Memory errors for large datasets, or gradient failures (e.g., NaN log-probability) indicating model mis-specification.

**First 3 experiments:**
1. Replicate the paper’s NUTS results on the Peyton Manning dataset to validate the reimplementation (compare R-hat, ESS, effective sampling rate, and forecast MSE).
2. Test a different time series (e.g., from the M4 competition) to check generalizability of conclusions about ADVI overconfidence.
3. Stress-test the modular API by adding a custom regressor (e.g., temperature) and verify that all inference methods still run without modification.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can GPU acceleration significantly speed up MCMC (NUTS, MH, DMZ) for Prophet models, despite their sequential nature?
- **Basis in paper:** Future Work (Sec VI): "we will be looking into GPU acceleration to speed up the full MCMC sampling... every MCMC algorithm is inherently sequential... GPU acceleration can only speed up the computation of the likelihood."
- **Why unresolved:** No empirical data exist to quantify trade-offs (e.g., GPU overhead, model size, likelihood complexity); unclear when acceleration yields net benefit.
- **What evidence would resolve it:** Systematic benchmarks comparing CPU and GPU MCMC implementations across varying parameter counts and dataset sizes, reporting effective samples per second and time to convergence.

### Open Question 2
- **Question:** Why does ADVI underestimate and FullRank ADVI overestimate posterior uncertainty in the Prophet model?
- **Basis in paper:** Conclusion (Sec V): "However the FullRank ADVI overestimated and ADVI underestimated posterior uncertainty. This could be due to algorithmic limitations and should be further addressed."
- **Why unresolved:** The precise algorithmic reasons (e.g., factorization assumption, model nonlinearities) are undiagnosed, undermining confidence in VI uncertainty estimates.
- **What evidence would resolve it:** Direct comparison of marginal posterior densities from NUTS (ground truth) with those from ADVI/FullRank ADVI on both the real dataset and synthetic models with known posteriors.

### Open Question 3
- **Question:** How can Bayesian inference automatically determine appropriate regularization strengths (prior scales) for parameters in Prophet-like models?
- **Basis in paper:** Conclusion/Future Work: "We want to further investigate the usage of Bayesian inference to determine the regularization strength of various parameters."
- **Why unresolved:** Although MAP estimation with certain priors corresponds to L1/L2 regularization, fully Bayesian estimation of prior variance (the regularization strength) is not demonstrated, leaving manual tuning necessary.
- **What evidence would resolve it:** Implementing hierarchical priors where regularization hyperparameters have their own weakly informative priors (e.g., Half‑Normal) and performing inference via NUTS or VI; comparing predictive performance to manual prior choices.

## Limitations
- **Implementation uncertainty:** Model specifics (changepoint placement, Fourier series, error term) are reconstructed from the paper’s description, not from released code, risking subtle deviations.
- **Single-dataset evaluation:** Experiments use only the Peyton Manning series; conclusions about ADVI/FullRank ADVI calibration and DMZ performance may not generalize to other time series.
- **No public replication package:** Absence of released code hinders independent verification and extension.

## Confidence
- **Modular API feasibility:** Medium
- **Unified inference interface:** High
- **Diagnostic sufficiency (R-hat/ESS thresholds):** Medium
- **Performance hierarchy (NUTS vs ADVI vs DMZ vs MAP):** High for the specific dataset (internal consistency), Low for broad generalization (single data evaluation)
