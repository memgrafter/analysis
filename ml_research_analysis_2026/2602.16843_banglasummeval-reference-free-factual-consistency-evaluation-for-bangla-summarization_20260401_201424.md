# BanglaSummEval: Reference-Free Factual Consistency Evaluation for Bangla Summarization

## Quick Facts
- **arXiv ID:** 2602.16843  
- **Source URL:** https://arxiv.org/abs/2602.16843  
- **Reference count:** 20  
- **Primary result:** A QA-based reference-free metric using a single model achieves Pearson 0.694 and Spearman 0.763 correlation with expert human judgments on Bangla summarization.

## Executive Summary
BanglaSummEval introduces a reference-free factual consistency evaluation framework for Bangla summarization, addressing the lack of robust metrics for low-resource languages. The system leverages a single multilingual instruction-tuned model (Qwen3-14B-bnb-4bit) to perform question generation, answering, answer extraction, and importance weighting. Semantic similarity is assessed via BERTScore-Recall, which outperforms lexical overlap metrics. Validated on 300 human-written educational and medical summaries, the metric correlates highly with human evaluations and runs efficiently on free-tier GPUs. The framework also provides step-wise diagnostics to identify specific error types.

## Method Summary
The pipeline takes a Bangla source document and a candidate summary. It first extracts named entities and nouns from both using a prompted Qwen3 model. For each extracted answer candidate in a context (source or summary), the model generates a question and validates that the context can answer it by checking BERTScore-Recall between the generated answer and the candidate (τ=0.6). The validated QA pairs form a set P(context). Precision is computed by answering the summary’s questions using the source as context and measuring semantic similarity of the answers to the summary’s original candidates. Recall combines answerability scores (comparing the summary’s answers to an “unanswerable” baseline) weighted by a learned importance score for each question. The final metric is the harmonic mean of precision and recall. The entire system uses a single quantized 4-bit model for all LLM tasks and XLM-RoBERTa-base for semantic similarity, enabling execution on a 16GB GPU in approximately 25 minutes per summary.

## Key Results
- Pearson correlation r = 0.694 and Spearman ρ = 0.763 with expert human judgments on 300 Bangla summaries.  
- The system completes evaluation in ~25 minutes per summary on a free-tier GPU, demonstrating practical accessibility.  
- BERTScore-Recall significantly outperforms lexical metrics (chrF, Token-F1) for detecting factual consistency in Bangla.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Using a single multilingual instruction-tuned model for all core components reduces system complexity and computational cost while maintaining sufficient task performance for Bangla.  
- **Mechanism:** The same model instance (Qwen3-14B-bnb-4bit) is prompted differently to perform each sub-task (NER, QG, QA, weighting), avoiding multiple specialized models.  
- **Core assumption:** A sufficiently capable multilingual model can follow Bangla instructions for distinct NLP tasks with comparable proficiency to specialized models; performance loss is offset by efficiency.  
- **Evidence anchors:**  
  - Abstract: “A single multilingual instruction-tuned language model handles question generation, question answering, candidate answer extraction, and question importance weighting. This unified design reduces system complexity and computational cost.”  
  - Section 3.1: Benchmarking selected Qwen3-14B-bnb-4bit as best for QA/QG on BanglaRQA, outperforming BanglaT5 and mT5-Base.  
  - Neighbor papers (e.g., PlainQAFact, FactKB) use separate or ensemble models; no direct counter-evidence.  
- **Break condition:** If the model’s performance on any sub-task degrades significantly below a threshold (e.g., F1 < 0.6 on a Bangla NER probe), error propagation would outweigh efficiency gains.

### Mechanism 2
- **Claim:** Replacing token-level F1 with BERTScore-Recall for answer comparison captures semantic equivalence in Bangla more robustly, leading to higher correlation with human factual judgments.  
- **Mechanism:** BERTScore uses contextual embeddings (XLM-RoBERTa-base) to measure similarity between a reference answer (from source) and a candidate answer (from summary), handling morphological variation and paraphrasing.  
- **Core assumption:** Factual consistency at the atomic answer level is a semantic equivalence problem; higher BERTScore-Recall indicates correct fact preservation.  
- **Evidence anchors:**  
  - Section 3.4 (Table 2): BERTScore-Recall achieves Pearson r=0.673, the highest among tested metrics, outperforming chrF (r=0.666) and Token-F1 (r=0.496).  
  - Abstract: “To capture semantic consistency beyond surface-level overlap, we use BERTScore-Recall for answer comparison.”  
  - Neighbor papers (e.g., Evaluating Factual Consistency with SRL, FactKB) also use semantic metrics but not specifically BERTScore-Recall for Bangla.  
- **Break condition:** If BERTScore-Recall fails to distinguish semantically equivalent but factually different answers (e.g., “Prime Minister” vs. “President” in context), false positives occur.

### Mechanism 3
- **Claim:** Weighting generated questions by predicted importance (using the same model) produces a recall score that better reflects coverage of salient source information, improving alignment with human prioritization.  
- **Mechanism:** After generating QA pairs from the source, a query weighter scores each question’s importance (0.0–1.0) based on the source context. Weighted recall aggregates answerability scores proportionally to these weights.  
- **Core assumption:** Not all extracted facts are equally important; a factuality metric should prioritize central entities/events over peripheral details to match human evaluation.  
- **Evidence anchors:**  
  - Section 3.7: “To account for the relative importance of different facts, we employ a query weighting function W(q,D)… The final recall computation therefore becomes a weighted aggregation where each question contributes proportionally to its estimated informativeness.”  
  - Section 4.2 reports overall correlation (Spearman ρ=0.763), implying the weighting contributes to strong performance, though ablation is not shown.  
  - No neighbor paper uses learned importance weight for QA pairs; QuestEval treats all questions equally. This is a novel but unevaluated component.  
- **Break condition:** If human evaluations show no correlation between predicted weights and human importance judgments (τ < 0.3), the weighting introduces noise.

## Foundational Learning
- **QA-based Factual Consistency Evaluation**  
  *Why needed:* Decomposes evaluation into atomic question-answer verification, avoiding brittle holistic document similarity.  
  *Quick check:* “Why is answering automatically generated questions from a summary more reliable for detecting hallucinations than comparing the summary text directly to the source?”

- **Semantic Similarity vs. Lexical Overlap**  
  *Why needed:* Bangla’s morphological richness and paraphrasing make exact token match (ROUGE, BLEU) ineffective; semantic similarity (BERTScore) matches different surface forms of the same fact.  
  *Quick check:* “What is a concrete example where a correct Bangla summary would score low on ROUGE but high on BERTScore-Recall?”

- **Importance-weighted Aggregation**  
  *Why needed:* Raw recall treats all extracted entities equally, misaligning with human focus on key information.  
  *Quick check:* “How might an unweighted recall score be gamed by a summary that correctly states many minor details but misses the main event?”

## Architecture Onboarding
- **Component map:**  
  Input (D, S) -> NER/Extraction (G(D), G(S)) -> QG & QA Loop (per context: for each r in G, generate q; validate (q,r) via sim>=τ to form P) -> Precision (for (q,r) in P(S), QA on D -> a'; average sim(a',r)) -> Query Weighting (W(q,D) for each (q,r) in P(D)) -> Recall (Ans(S,q) weighted by W) -> Final Score (harmonic mean of Prec and Rec).

- **Critical path:** NER → (QG+QA validation) for source → Query weighting → QA on summary for recall → (QG+QA validation) for summary → QA on source for precision → Score aggregation. Bottleneck: QG+QA validation loop for each entity; runtime scales with |G(context)|.

- **Design tradeoffs:**  
  - *Single model vs modular:* Single model (Qwen3) minimizes dependencies and VRAM (~13GB 4-bit) but risks circular error propagation (NER → QG → QA).  
  - *BERTScore-Recall vs lexical:* Chosen for semantic robustness but uses fixed τ=0.60 without Bangla-specific tuning; may reject valid paraphrases.  
  - *Free-tier GPU compatibility:* Quantification and unified model enable 16GB VRAM execution but limit context length (2048 tokens) and may degrade performance on long documents.

- **Failure signatures:**  
  - *Low precision (<0.3):* Summary contains facts not in source; check P(S) generation (QG may produce unanswerable questions, or QA on D fails).  
  - *Low recall (<0.3):* Important source facts missing; check P(D) coverage (NER missed key entities, or weighting gave low scores to central questions).  
  - *High variance across summaries:* Outlier entities in NER output or inconsistent weighting scores; may indicate model instability on certain Bangla constructs.  
  - *Discrepancy between BERTScore and human score:* If BERTScore high but human low, semantic matching may be incorrect (e.g., confusing similar names); inspect specific QA pairs.

- **First 3 experiments:**  
  1. *Sanity check on short documents:* Process a 5-sentence source/summary pair with known facts. Verify NER extraction, QG question answerability, and QA on source/summary return exact answers. Expected score ~1.0.  
  2. *Metric comparison replication:* Re-run Table 2’s benchmark on a small Bangla factuality probe (50 sentence pairs with known paraphrases). Confirm BERTScore-Recall > chrF > Token-F1 in detecting factual equivalence.  
  3. *Threshold sensitivity test:* Vary τ (0.5, 0.6, 0.7) on 20 samples. Track number of QA pairs retained and score stability. A sharp drop at τ=0.7 suggests over-filtering; τ=0.6 likely optimal.

## Open Questions the Paper Calls Out
1. **Bias mitigation:** How can biases inherited from high-resource training data in multilingual instruction-tuned models like Qwen3 be mitigated for fair Bangla factual consistency evaluation?  
2. **Domain generalization:** How effective is BanglaSummEval in domains beyond education and medicine (e.g., legal, scientific), and what specific adaptations are required?  
3. **Semantic encoder improvement:** Can larger or Bangla-specific semantic encoders (beyond XLM-RoBERTa-base) improve BERTScore-Recall's accuracy for capturing subtle Bangla nuances?  
4. **Cross-lingual generalization:** To what extent can the framework be generalized to other low-resource languages with different linguistic characteristics, and what minimal modifications are essential?  
5. **Relational error detection:** How can BanglaSummEval be enhanced to detect complex relational errors (e.g., causal chains, multi-hop dependencies) that atomic QA-based evaluation might miss?

## Limitations
- **Dataset access:** The 300 human summaries from NCTB and BanglaCHQ-Summ are not publicly released, hindering replication.  
- **Threshold τ=0.60:** Chosen empirically without reported sensitivity analysis or validation set details, affecting QA pair filtering.  
- **Query weighter evaluation:** No reported correlation between predicted importance scores and human judgments, leaving its contribution unverified.

## Confidence
- **Overall correlation (r=0.694, ρ=0.763):** High (solid n=300 human validation).  
- **Single-model efficiency/sufficiency for Bangla QA:** Medium (runs on free GPU, but weak corpus anchors; no modular baseline).  
- **BERTScore-Recall superiority over lexical metrics:** High (Table 2 directly shows best Pearson).  
- **Learned importance weighting improves recall:** Low (novel, unevaluated; no ablation or human weight correlation).
