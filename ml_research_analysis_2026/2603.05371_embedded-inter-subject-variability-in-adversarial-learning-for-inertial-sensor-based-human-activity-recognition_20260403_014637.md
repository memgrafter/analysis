# Embedded Inter-Subject Variability in Adversarial Learning for Inertial Sensor-Based Human Activity Recognition

## Quick Facts
- arXiv ID: 2603.05371
- Source URL: https://arxiv.org/abs/2603.05371
- Reference count: 0
- Primary result: A deep adversarial framework with a binary subject discrimination task achieves state-of-the-art accuracy and F1-Score Macro on three HAR datasets (PAMAP2, REALDISP, MHEALTH) under leave-one-subject-out cross-validation.

## Executive Summary
The paper addresses inter-subject variability in wearable sensor-based Human Activity Recognition (HAR), which hampers generalization to new users. It proposes a deep adversarial learning framework that introduces a novel binary discrimination task: given two feature vectors (extracted from the same activity), the model predicts whether they originate from the same subject or different subjects. This adversarial setup encourages the feature extractor to learn subject-invariant representations while preserving discriminative activity information. Evaluated via leave-one-subject-out cross-validation on three benchmark datasets (PAMAP2, REALDISP, MHEALTH), the method outperforms prior approaches (MCCNN, DCLSTM, METIER, UIDFE, DDLearn) in both accuracy and F1-Score Macro. Analysis using Wasserstein distance confirms that the adversarial step reduces the distribution shift between training and test subjects for the same activity.

## Method Summary
The proposed method employs a deep neural network architecture comprising a feature extractor (likely a CNN or LSTM) that processes inertial sensor data into fixed-length feature vectors. An auxiliary activity classifier is attached to the feature extractor to maintain discriminative power for activity recognition. The key innovation is a binary discriminator that takes a pair of feature vectors (sampled from the same activity class) and predicts whether they belong to the same subject. During training, the discriminator is optimized to correctly classify same-subject pairs vs. different-subject pairs, while the feature extractor is optimized both for activity classification and to fool the discriminator (i.e., to make subject pairs indistinguishable). This adversarial learning loop drives the features to be invariant to subject-specific variations. Pair construction and sampling strategies are used, though details are sparse. The whole system is trained end-to-end.

## Key Results
- The adversarial framework achieves state-of-the-art accuracy and F1-Score Macro on PAMAP2 (accuracy 0.8703±0.1219), REALDISP (0.9710±0.0423), and MHEALTH (0.9225±0.0606) under leave-one-subject-out evaluation.
- It consistently outperforms prior HAR methods (MCCNN, DCLSTM, METIER, UIDFE, DDLearn) across all three datasets.
- The Wasserstein distance between training and test feature distributions for the same activity is significantly reduced after adversarial training, indicating mitigation of inter-subject variability.

## Why This Works (Mechanism)
The adversarial binary discrimination task forces the feature extractor to produce representations that hide subject identity. By requiring the discriminator to predict whether two features come from the same subject, the feature space becomes aligned across subjects within each activity. The feature extractor must maintain enough information to classify activities accurately while removing subject-specific cues, leading to features that generalize to unseen subjects. The adversarial loss acts as a regularizer that minimizes the domain shift (subject shift) in a feature-level distribution matching manner. This approach directly targets inter-subject variability, which is a major obstacle for wearable HAR.

## Foundational Learning
- **Adversarial Training**: Uses a min-max game between a generator (feature extractor) and discriminator to learn domain-invariant features. *Why needed*: To reduce the discrepancy between source (training) and target (test) subject distributions. *Quick check*: Does the discriminator's accuracy plateau near chance, indicating domain confusion?
- **Domain Adaptation**: Techniques to adapt models to new domains without labeled data. *Why needed*: Handles subject variability without requiring labeled data from new users. *Quick check*: Are feature distributions for the same activity across subjects becoming more similar?
- **Human Activity Recognition (HAR)**: Recognizing physical activities from sensor data. *Why needed*: Core application; subject variability degrades performance in real deployments. *Quick check*: Does the model maintain high accuracy on unseen subjects?
- **Wasserstein Distance**: A metric for comparing probability distributions. *Why needed*: Quantifies distribution shift between training and test features; used as evidence of reduced variability. *Quick check*: Is the distance after adaptation lower than before?
- **Binary Discrimination Task**: The proposed task of predicting same/different subject from a feature pair. *Why needed*: Encourages subject-invariant features without requiring subject labels during inference. *Quick check*: Does the discriminator's loss decrease over training?

## Architecture Onboarding
**Component Map**  
Sensor Data -> Feature Extractor -> Feature Vector  
Feature Vector -> Activity Classifier -> Activity Prediction  
Pair of Feature Vectors -> Discriminator -> Same/Different Subject Prediction  

**Critical Path**  
1. Input sensor window passes through Feature Extractor (backbone CNN/LSTM) to produce a feature vector.  
2. In parallel, the feature vector is fed to Activity Classifier to compute classification loss.  
3. For a batch, pairs of features are sampled; the discriminator takes the pair (concatenated or differenced) and outputs a same-subject probability.  
4. The discriminator loss (binary cross-entropy) is computed.  
5. The Feature Extractor is updated via a combined loss: activity loss + λ * (discriminator loss with reversed gradients or adversarial loss). Typically, gradients from discriminator are reversed (Gradient Reversal Layer) or the feature extractor is trained to maximize discriminator loss (i.e., fool the discriminator).  

**Design Tradeoffs**  
- Pair sampling strategy (e.g., positive/negative ratio) can bias learning and affect convergence.  
- Adversarial loss weighting (λ) balances activity accuracy vs. subject invariance; too high may hurt activity performance.  
- Discriminator capacity: A too strong discriminator may be impossible to fool, leading to collapsed features; a too weak one may not enforce invariance properly.  
- Computational overhead: Pairwise training doubles or more the data processing compared to standard single-sample training.  

**Failure Signatures**  
- Discriminator accuracy near 100% indicates subject information still present in features.  
- Activity classifier accuracy drops significantly, suggesting overemphasis on adversarial loss.  
- Training instability: oscillations in losses indicate poor regularization or sampling imbalance.  
- No reduction in Wasserstein distance or performance drop on new subjects suggests ineffective alignment.

3. **Sweep adversarial loss weight λ** to find optimal trade-off between activity accuracy and subject invariance; monitor discriminator accuracy and Wasserstein distance.

## Limitations
- Evaluation uses only leave-one-subject-out cross-validation, which may not reflect real-world distribution shifts such as new sensor placements or activities.
- The binary discrimination task requires constructing pairs of feature vectors; the paper lacks details on the pair sampling strategy (e.g., balance of same/different subjects), which can influence training stability and performance.
- The claim of reduced inter-subject variability relies solely on a single metric (Wasserstein distance), without broader validation (e.g., feature visualization, calibration analysis).
