# Streaming Real-Time Trajectory Prediction Using Endpoint-Aware Modeling

## Quick Facts
- **ArXiv ID**: 2603.01864  
- **Source URL**: https://arxiv.org/abs/2603.01864  
- **Reference count**: 40  
- **Primary result**: SEAM achieves streaming SOTA on Argoverse 2 with brier‑minFDE6 of 1.84 (single‑agent) and 1.85 (multi‑agent), reducing online latency to 28 ms (vs. 39 ms for DeMo).

## Executive Summary
Snapshot‑based trajectory prediction ignores temporal continuity, causing high latency and inconsistent streaming outputs. SEAM introduces a streaming framework that leverages endpoints from previous predictions as anchors to extract target‑centric context features. These are fused with agent‑centric features via a dual‑context decoder, producing accurate future trajectories in a single pass without refinement iterations. On Argoverse 2, SEAM sets new streaming benchmarks while maintaining low computational cost.

## Method Summary
SEAM processes driving scenes in a streaming manner, preserving scene context and past predictions across time steps. For each frame, it encodes current agents and lanes into a scene token set *C*<sub>t</sub>. Previous scene context *S*<sub>t‑1</sub> is motion‑aware normalized and reintegrated via cross‑attention. The endpoints of the previous multimodal trajectory set *F*<sub>t‑1</sub> define *K* target regions; scene tokens within a fixed radius are gathered and encoded by a shallow target encoder into *T*<sub>t</sub>. A dual‑context decoder with *K* learnable mode queries runs for *d*=3 stages; in each stage, queries attend to both the agent‑centric scene *S*<sub>t</sub> and their corresponding target‑centric features *T*<sub>t</sub>. The decoded trajectories and confidences are refined through a trajectory relay module that attends to *F*<sub>t‑1</sub>. For multi‑agent scenarios, a global consistency module enforces joint coherence. The design yields high accuracy with only 4.6 M parameters and ~28 ms online latency.

## Key Results
- **Single‑agent**: brier‑minFDE6 = 1.84, matching DeMo but with lower latency (28 ms vs. 39 ms).  
- **Multi‑agent**: avgBrierMinFDE6 = 1.85, outperforming prior streaming method RealMotion.  
- **Ablations**: Endpoint‑aware modeling (EAM) yields a clear gain over other streaming mechanisms; streaming (CS+TR+EAM) achieves brier‑minFDE6 = 1.85 vs. snapshot = 2.00 on Argoverse 2 validation.

## Why This Works (Mechanism)

### Mechanism 1: Endpoint‑aware context extraction
- **Claim**: Using previous prediction endpoints as anchors to extract target‑centric context features improves accuracy by focusing on relevant future regions without iterative refinement.  
- **Mechanism**: For each mode of *F*<sub>t‑1</sub>, its endpoint defines a target region. Scene tokens (agents and lanes) within a fixed radius *r* around each endpoint are gathered from the current scene context *C*<sub>t</sub> and encoded by a shallow target encoder *f*<sub>T</sub> into target‑centric features *T*<sub>t</sub>. During decoding, each mode query attends to its corresponding *T*<sub>t</sub>, incorporating long‑range contextual information about the predicted future area.  
- **Core assumption**: The endpoint of a trajectory predicted at *t‑1* reliably indicates the region where the agent will be at future times, assuming previous predictions are sufficiently accurate.  
- **Evidence anchors**:  
  - Abstract: “Our temporal context propagation uses the trajectory endpoints of the previous forecasts as anchors to extract targeted scenario context encodings.”  
  - Section 3.3: “We use the endpoints of these trajectories as anchors to define *K* target regions. Next, we gather tokens from our scene context *C*<sub>t</sub> within a region‑of‑interest radius *r* around each target anchor…”  
  - Corpus: No prior work uses endpoint‑aware modeling; RealMotion uses trajectory relay only.  
- **Break condition**: Performance degrades if previous predictions are noisy or erroneous (Table 8: added endpoint noise increases errors). Failures occur for abrupt maneuvers or inadequately mapped areas (Figure 10).

### Mechanism 2: Dual‑context decoder fusion
- **Claim**: Dual‑context attention in the decoder fuses agent‑centric and target‑centric information in a single pass, achieving high accuracy with low latency by avoiding refinement iterations.  
- **Mechanism**: The decoder uses *K* learnable mode queries. For *d* stages (e.g., *d* = 3), each query performs cross‑attention to the agent‑centric context *S*<sub>t</sub> (local surroundings) and its mode‑specific target‑centric context *T*<sub>t</sub> (future region). The updated queries are projected to trajectories *F*<sub>t</sub> and confidence scores *P*<sub>t</sub>.  
- **Core assumption**: Agent‑centric and target‑centric contexts are complementary; the decoder can effectively integrate both via cross‑attention.  
- **Evidence anchors**:  
  - Section 3.4: “We iteratively execute cross‑attention *d*-times to our scene context *S* and the target‑specific tokens *T*. Thus, information from both feature sets is available in each decoder stage.”  
  - Table 4: Combining EAM with context stream and trajectory relay yields the best results (brier‑minFDE6 = 1.85 vs. 1.93 with CS+TR alone).  
  - Corpus: RealMotion lacks target‑centric context; refinement‑based methods (e.g., SmartRefine) use multiple decoding passes, incurring higher latency.  
- **Break condition**: If target context is irrelevant (due to poor previous predictions), it may introduce noise; however, agent‑centric context remains as a fallback.

### Mechanism 3: Streaming information propagation
- **Claim**: Streaming propagation via context referencing and trajectory relay maintains temporal consistency and leverages past information for more accurate predictions.  
- **Mechanism**:  
  - *Context referencing*: Previous scene context *S*<sub>t‑1</sub> is motion‑aware normalized (MLN) to align with the current frame and integrated into the current token set *C*<sub>t</sub> via cross‑attention (agent‑to‑scene and map‑to‑map).  
  - *Trajectory relay*: Current predictions *F*<sub>t</sub> are refined by attending to previous predictions *F*<sub>t‑1</sub> via a cross‑attention module.  
- **Core assumption**: The scene evolves continuously; past information is relevant if properly aligned. MLN compensates for ego and agent motion between frames.  
- **Evidence anchors**:  
  - Section 3.5: “We apply motion‑aware layer normalization (MLN) to the scene context *S*<sub>t‑1</sub> before integrating it into the current encoding *C*<sub>t</sub> via agent‑to‑scene and map‑to‑map cross‑attention.”  
  - Table 4: Streaming methods (CS+TR, EAM, or both) outperform snapshot‑based prediction (e.g., on AV2 val: brier‑minFDE6 = 1.85 vs. 2.00 for snapshot).  
  - Corpus: RealMotion introduced these mechanisms; SEAM integrates them with endpoint‑aware modeling.  
- **Break condition**: Large inter‑frame motion or abrupt behavior changes can cause misalignment (MLN failure) or inconsistent relay, degrading performance.

## Architecture Onboarding

**Component Map**  
A<sub>t</sub>, L<sub>t</sub> → [f<sub>A</sub>, f<sub>L</sub>] → C<sub>t</sub> → [context referencing (MLN + cross‑attention with S<sub>t‑1</sub>)] → C′<sub>t</sub> → [f<sub>S</sub>] → S<sub>t</sub>  
F<sub>t‑1</sub> → endpoints → gather tokens from C<sub>t</sub> → [f<sub>T</sub>] → T<sub>t</sub>  
Mode queries → [d × (cross‑attention to S<sub>t</sub>, cross‑attention to T<sub>t</sub>)] → [projection MLPs] → F<sub>t</sub>, P<sub>t</sub> → [cross‑attention with F<sub>t‑1</sub>] → final F<sub>t</sub>  
Multi‑agent extension adds global consistency module after marginal predictions.

**Critical Path (single‑agent)**  
1. Encode current agents and lanes → C<sub>t</sub>.  
2. Integrate S<sub>t‑1</sub> via context referencing.  
3. Encode scene → S<sub>t</sub>.  
4. Extract target context from F<sub>t‑1</sub> → T<sub>t</sub>.  
5. Dual‑context decoding → initial F<sub>t</sub>, P<sub>t</sub>.  
6. Apply trajectory relay → final F<sub>t</sub>.

**Design Tradeoffs**  
- *Target radius r*: Larger *r* includes more context but increases compute and noise; optimal ~30 m (Table 5).  
- *Decoder stages d*: More stages could improve accuracy but increase latency; *d*=3 balances both.  
- *Target encoder depth*: Shallower (2 blocks) than scene encoder (4 blocks) due to fewer tokens, saving compute.  
- *Streaming vs. snapshot*: Streaming uses past information but requires state management and alignment (MLN).

**Failure Signatures**  
- Endpoint noise sensitivity: Performance degrades with increasing noise on previous endpoints (Table 8).  
- Scenario failures: Unexpected stops or inadequately mapped driveways cause large errors (Figure 10), indicating limited anticipation of abrupt maneuvers and dependency on map completeness.  
- Latency ceiling: Online latency of 28 ms (single‑agent, V100) is low but may be a bottleneck for high‑frequency planning (>30 Hz).

**First 3 Experiments**

## Open Questions the Paper Calls Out

- **Generalization to other datasets**: Does SEAM’s endpoint‑aware streaming generalize to nuScenes, WOMD, etc., with different sampling rates and map representations?  
- **Error propagation robustness**: How does performance degrade over longer streams with noisy initial predictions? Systematic tests with controlled perturbations are needed.  
- **Primary improvement factor**: Is the gain from endpoint‑aware modeling due to long‑range dependencies, multimodal intent disambiguation, or temporal consistency? Diagnostic ablations are required.  
- **Consistency benefit for planning**: Does SEAM reduce trajectory fluctuation compared to a snapshot baseline, and does this improve downstream planning robustness? Controlled comparisons and simulation studies are needed.

## Limitations
- Loss scaling and exact learning‑rate schedule are not specified, risking convergence issues during reproduction.  
- Multi‑agent finetuning details (e.g., whether decoder weights are frozen, batch composition) are ambiguous.  
- Endpoint‑aware modeling is sensitive to prior prediction noise and may fail on abrupt maneuvers or poorly mapped areas.

## Confidence
- Endpoint‑aware modeling: **Medium** (supported by ablations but relies on prior accuracy).  
- Dual‑context decoder: **Medium‑High** (architecture clearly described; implementation nuances may affect efficiency).  
- Streaming propagation (CS+TR): **Medium** (prior work validates; Table 4 shows benefit).  
- SOTA results: **Low** (lack independent replication; missing reproducibility details).
