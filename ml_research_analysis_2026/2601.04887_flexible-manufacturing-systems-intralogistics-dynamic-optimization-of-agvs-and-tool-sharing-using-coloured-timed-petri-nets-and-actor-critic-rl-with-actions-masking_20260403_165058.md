# Flexible Manufacturing Systems Intralogistics: Dynamic Optimization of AGVs and Tool Sharing Using Coloured-Timed Petri Nets and Actor-Critic RL with Actions Masking

## Quick Facts
- **arXiv ID:** 2601.04887
- **Source URL:** https://arxiv.org/abs/2601.04887
- **Reference count:** 40
- **Primary result:** A framework combining Colored-Timed Petri Nets and Maskable PPO reduces makespan by 18–40% and computation time tenfold compared to a metaheuristic on large-scale Job Shop Scheduling instances with AGVs and tool sharing.

## Executive Summary
This paper tackles the extended Job Shop Scheduling Problem in Flexible Manufacturing Systems, where the simultaneous coordination of Automated Guided Vehicles (AGVs) and shared tools creates a highly complex, interdependent decision space. The proposed solution integrates a Colored-Timed Petri Net (CTPN) as a formal, constraint-enforcing environment model with a Maskable Proximal Policy Optimization (PPO) reinforcement learning agent. The CTPN dynamically masks infeasible actions, dramatically shrinking the search space. An additional lookahead strategy predicts future job assignments to preposition AGVs, eliminating deadheading travel. Evaluated on new large-scale benchmarks, the approach matches traditional solvers on small instances and significantly outperforms a state-of-the-art Symbiotic Organisms Search metaheuristic on large instances, while being orders of magnitude faster. The framework also generalizes across instance sizes and adapts to dynamic job arrivals without retraining.

## Method Summary
The method constructs a gym-compatible simulation environment where the system state is defined by the marking of a CTPN. The CTPN models places (buffers, idle resources), colored tokens (jobs, operations), and transitions (controllable job/AGV selection, autonomous transport/processing). Guard functions on controllable transitions enforce all physical constraints (machine/tool/AGV availability, precedence) by outputting a binary action mask. A Maskable PPO agent observes the CTPN-derived state vector and the mask, then selects a feasible action (assigning a job operation to an AGV). A shaped reward penalizes idle machines each timestep. For AGVs with empty buffers, a "twin" CTPN environment simulates future steps using the current deterministic policy to predict the next token destination, enabling proactive AGV positioning. The agent is trained on multiple instances of a given size using PPO updates.

## Key Results
- Matches traditional optimization methods on small public benchmarks (e.g., EX11).
- Outperforms the Symbiotic Organisms Search (SOS) metaheuristic on large Taillard-inspired instances (up to 100 jobs), reducing makespan by 18–25% (AGVs only) and 35–40% (with tool sharing).
- Achieves ~10× reduction in computation/solve time (e.g., 0.24s vs. 217s).
- Demonstrates strong generalization: a single agent trained on 50x20 instances solves sizes from 15x15 to 100x20 with ≤4% performance drop.
- Ablation study confirms the contributions of reward shaping, lookahead, and action masking.
- Adapts to dynamic new job arrivals without retraining.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Colored-Timed Petri Nets (CTPNs) dynamically constrain the RL agent's action space via guard-function-based masking, making the large, interdependent action space tractable.
- **Mechanism:** The CTPN model encodes all system constraints (machine/AGV/tool availability, job precedence) as guard functions on controllable transitions. At each decision step, these guard functions output a Boolean mask indicating which of the agent's potential actions are currently feasible. The Maskable PPO agent uses this mask to set the logits of invalid actions to negative infinity, so they are never selected. This reduces the effective branching factor dramatically.
- **Core assumption:** The CTPN model is a correct and complete formal representation of all physical constraints in the FMS. An incorrect or incomplete model would generate an invalid mask, blocking feasible actions or permitting infeasible ones.
- **Evidence anchors:**
  - [abstract] "CTPNs provide a formal modeling structure and dynamic action masking, significantly reducing the action search space."
  - [section 5.2] "The dynamic masking is driven by the Petri Net’s guard function, which generates a Boolean vector indicating enabled transitions based on token distribution."
  - [corpus] The related work corpus confirms the use of Petri nets for constraint enforcement in scheduling but does not directly validate this specific masking integration.
- **Break condition:** If the CTPN model fails to accurately represent a real-world constraint (e.g., a machine breakdown rule), the mask will be incorrect. The RL agent will be forced to operate in a mis-specified state space, leading to systematically infeasible or suboptimal schedules.

### Mechanism 2
- **Claim:** An actor-critic model-based RL agent (Maskable PPO) learns a policy that maps the current CTPN state (token distribution) to optimal job/AGV assignment actions, retaining knowledge for adaptation.
- **Mechanism:** The environment state is derived from the CTPN marking and token attributes (color, remaining time). The agent's policy network (actor) selects a masked action, while the value network (critic) estimates the expected cumulative reward (negative makespan) from that state. The proximal policy optimization update ensures stable learning by constraining policy updates. Knowledge is retained in the network weights, allowing the policy to be applied to new problem instances without re-searching from scratch.
- **Core assumption:** The FMS problem, though complex, exhibits sufficient Markovian structure when represented by the CTPN state. The reward function (penalizing idle machines) provides a dense enough signal for effective credit assignment over long horizons.
- **Evidence anchors:**
  - [section 3.1] Details the MDP framework and PPO algorithm, stating it "ensures adaptability to changing environments through the learned policy."
  - [section 5.2] "We penalize idle machines... providing immediate feedback... The reward function is given by Reward = - (idle machines / total machines)."
  - [section 6.5] Demonstrates generalization: a single agent trained on one instance size (50x20) can solve others (15x15 to 100x20) with only a 4% performance drop.
- **Break condition:** If the reward shaping is insufficiently informative for a highly complex instance (e.g., extreme tool contention), the credit assignment problem may prevent the policy from learning the long-term dependencies needed for optimal sequencing, causing convergence to poor local optima.

### Mechanism 3
- **Claim:** A model-based lookahead strategy simulates future policy steps in a "twin" CTPN environment to predict which token will fill an empty AGV buffer, enabling proactive AGV positioning and eliminating deadheading.
- **Mechanism:** When an AGV's buffer is empty, the current deterministic policy is rolled out in a copy of the CTPN state until a token is assigned to that AGV. The predicted future token location determines the AGV's next destination. The AGV is then instructed to relocate (deadhead) to that machine *in advance*, so it arrives exactly when needed. This converts reactive deadheading into proactive, zero-wait positioning.
- **Core assumption:** The learned policy is sufficiently deterministic and accurate to make reliable short-horizon predictions about future token assignments. The cost of simulating multiple steps is outweighed by the makespan reduction from eliminated deadheading.
- **Evidence anchors:**
  - [section 5.3] "If the buffer is empty, the algorithm creates a twin of the environment and simulates future steps using the learned current policy until the buffer is filled... By ensuring the AGV is optimally positioned... deadheading is effectively eliminated."
  - [section 6.7] Ablation study shows lookahead improves makespan on small instances (e.g., EX12: 82 vs. 100 steps).
- **Break condition:** In highly stochastic or adversarial dynamic scenarios (e.g., frequent random new job arrivals that drastically change optimal policy), the policy used for lookahead may be quickly outdated, leading the AGV to preposition for a token that is no longer the next best assignment, causing mispositioning and wasted travel.

## Foundational Learning
- **Concept: Petri Nets (Colored, Timed)**
  - *Why needed here:* The entire environment model and constraint enforcement (action masking) are built upon a CTPN. A learner must understand places, transitions, tokens, colors, guard functions, and timed transitions to interpret the state representation and debugging/modeling.
  - *Quick check question:* How does a guard function on a "job select" transition use token color to enforce that an operation can only be started if its required machine is idle and its tool is available?
- **Concept: Reinforcement Learning (Policy Gradient, Actor-Critic, PPO)**
  - *Why needed here:* The core decision-making engine is a Maskable PPO agent. Understanding policies, value functions, the advantage estimator, and the clipping mechanism is essential to interpret training curves, loss functions, and to troubleshoot learning stability.
  - *Quick check question:* Explain the purpose of the "clipping" parameter (ε) in PPO and how it contributes to training stability compared to a basic policy gradient update.
- **Concept: Job Shop Scheduling Problem (JSSP) & Extensions (FMS with AGVs/Tools)**
  - *Why needed here:* This defines the optimization objective (minimize makespan) and the specific constraints (machine eligibility, precedence, limited AGVs/tools, deadheading). Without this domain knowledge, one cannot design a valid reward function or interpret solution quality.
  - *Quick check question:* What is the fundamental difference in scheduling complexity between a classic JSSP and the JSSP with AGVs and tool sharing (JSSPT-T) as described in this paper?

## Architecture Onboarding
- **Component map:**
  1.  **CTPN Environment Core:** The formal model. Contains places for job buffers, machine buffers, AGV buffers, tool buffers, and idle states. Transitions encode operations: job selection (controllable), AGV selection (controllable), loading/unloading (autonomous/timed), machine allocation (autonomous), processing (timed).
  2.  **RL Agent (Maskable PPO):** Actor network (policy) and critic network (value). Takes the CTPN state vector (token features, counts) as input. Outputs a probability distribution over all controllable transitions (job ops, AGVs).
  3.  **Mask Generator:** Queries the CTPN's guard functions for all controllable transitions at the current marking. Outputs a binary mask vector synced with the agent's action space.
  4.  **Lookahead Module:** Uses a copy of the CTPN and the current policy to simulate N future steps when an AGV buffer is empty, predicting the next token destination.
  5.  **Reward Calculator:** Computes the step reward based on the current fraction of idle machines (Equation 8).
- **Critical path:**
  1.  CTPN marking updated by transition firings.
  2.  Mask generator reads guard functions -> mask vector.
  3.  Agent observes state + mask, selects action.
  4.  Action triggers firing of a controllable transition in CTPN.
  5.  CTPN evolves autonomously (timed delays, resource updates) until next controllable decision point.
  6.  Reward computed from new state.
  7.  Transition tuple (s, a, r, s', mask) stored for PPO update.
- **Design tradeoffs:**
  - *Modularity vs. Performance:* The CTPN's locality provides plug-and-play modularity (easy to add/remove AGVs/tools). However, the centralized state vector may not scale as efficiently to thousands of resources as a graph neural network might.
  - *Interpretability vs. Automation:* The CTPN offers visual, traceable state (token flow), aiding debugging. This comes at the cost of manually designing the net structure, which is error-prone for very large, irregular layouts.
  - *Lookahead Depth vs. Compute:* Deeper lookahead yields more accurate AGV positioning predictions but increases simulation overhead per step. The paper uses a short, deterministic rollout.
- **Failure signatures:**
  - *Training:* Episode reward plateaus at a high (bad) value; entropy loss drops to zero early (policy collapsed); KL divergence spikes (update too large); deadlocks in the CTPN (no enabled transitions, simulation hangs).
  - *Deployment:* Makespan significantly worse than training average; AGVs exhibit constant deadheading; tool contention bottlenecks (machines idle waiting for tools); the mask vector has all zeros (system deadlock).
- **First 3 experiments:**
  1.  **CTPN Sanity Check:** With a tiny instance (e.g., 2 jobs, 2 machines, 1 AGV), manually step through the CTPN. Verify that guard functions correctly enable/disable actions based on token presence and color. Ensure timed transitions fire after correct delays. Confirm the state vector accurately reflects the marking.
  2.  **Masking Validation:** Run the agent in "random action" mode (ignoring its policy) but respecting the provided mask. The episode *must* complete without hitting a deadlock (no enabled actions). If it fails, the CTPN model or mask generation is flawed.
  3.  **Benchmark Baseline Replication:** Train a Maskable PPO agent on the smallest public benchmark (e.g., EX11). Compare the resulting makespan and compute time against the heuristics in Table 3 and the SOS results in Figure 7. This validates the entire pipeline from training to solution quality against published claims.

## Open Questions the Paper Calls Out
- How can the PetriRL framework be extended to handle internal disruptions such as machine breakdowns and scheduled maintenance without requiring full retraining?
- To what extent does the assumption of a single tool instance per type constrain performance in scenarios with multiple identical tools or shared tool pools?
- How robust is the lookahead mechanism when faced with highly stochastic job arrivals (e.g., Poisson processes) that break the deterministic prediction assumption?
- What are the practical computational limits (in terms of jobs, machines, AGVs) for training a generalizable PetriRL agent before training time or solution quality deteriorates unacceptably?

## Limitations
- Exact CTPN guard function logic, particularly for tool-sharing constraints, is unspecified.
- Hyperparameters and architecture of the Maskable PPO agent are omitted.
- Observation vector design and padding mechanism for cross-size generalization are unclear.
- Lookahead simulation details (depth, deterministic policy use) are missing.
- Replication parameters for the Symbiotic Organisms Search baseline are absent.
