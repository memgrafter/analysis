# RAP: KV-Cache Compression via RoPE-Aligned Pruning
## Quick Facts
- arXiv ID: 2602.02599
- Source URL: https://arxiv.org/abs/2602.02599
- Reference count: 40
- One-line primary result: RAP reduces KV-Cache size, attention parameters, and FLOPs by 20–30% at 30% compression while maintaining accuracy and lowering attention latency, uniquely achieving joint reduction without overhead.

## Executive Summary
RAP introduces a KV-Cache compression technique specifically designed for models using Rotary Positional Embeddings (RoPE). Standard low-rank compression methods (e.g., SVD) cannot absorb the reconstruction matrix into downstream weights due to RoPE’s rotation structure, leading to runtime overhead. RAP circumvents this by pruning entire RoPE-aligned column pairs, which preserves the 2×2 rotation invariance and allows the compression matrix to be absorbed into subsequent linear layers. Evaluated on LLaMA-3-8B and Mistral-7B, RAP achieves 20–30% reductions in KV-Cache memory, attention parameters, and FLOPs at a 30% compression ratio, with negligible accuracy loss on perplexity, zero-shot tasks, and LongBench. Moreover, it reduces attention latency to 83% for prefill and 77% for decode, demonstrating genuine speedup without extra computational cost.

## Method Summary
RAP targets the incompatibility between RoPE and weight decomposition methods. It operates on the key and value projection matrices of each attention head. First, it identifies pairs of columns that are rotated versions of each other under RoPE; these pairs share the same rotational basis. Then, it prunes entire such pairs based on a saliency metric (e.g., magnitude or reconstruction error), rather than individual columns. Because the pruned structure aligns with the 2×2 rotation blocks, the resulting compression matrix commutes with the RoPE operator. Consequently, the compression can be folded into the subsequent projection weights (e.g., the output projection) during a one-time restructuring, eliminating the need for on-the-fly reconstruction. The method thus yields a compressed KV-Cache and a set of modified attention weights that together reduce memory, parameters, and FLOPs without altering the model’s functional behavior.

## Key Results
- Simultaneous reduction of KV-Cache size, attention parameters, and attention FLOPs by 20–30% at a 30% compression ratio, matching the linear reduction ratio.
- Maintains strong accuracy: negligible perplexity increase, competitive zero-shot task performance, and LongBench gains, outperforming SVD and PaLU.
- Lowers attention latency to 83% (prefill) and 77% (decode) of the baseline, providing genuine speedup; RAP is the only method achieving joint parameter, memory, and compute reduction without overhead.

## Why This Works (Mechanism)
RoPE applies a rotation matrix to each column of the query and key projections, creating a block structure where columns come in 2×2 rotationally linked pairs. Low-rank compression (e.g., SVD) produces a dense reconstruction matrix that does not commute with these rotations, so it cannot be merged into downstream linear layers. Instead, it must be applied explicitly during attention, incurring extra compute and memory. RAP solves this by removing entire RoPE-aligned column pairs instead of individual columns. Pruning a pair preserves the rotational symmetry: the remaining columns still form complete 2×2 blocks, and the compression matrix becomes block-diagonal with 2×2 orthogonal blocks. Such a matrix commutes with the RoPE operator, allowing it to be absorbed into the subsequent weight matrices (e.g., the output projection) via a simple matrix multiplication during a one-off restructuring. After absorption, the attention computation proceeds with the original formulation but with smaller dimensions, yielding reductions in memory (KV-Cache), parameters (attention projections), and FLOPs (matrix multiplies) without any reconstruction overhead at runtime.

## Architecture Onboarding
**Component map:**
KV-Cache (K, V projections) -> RoPE alignment analysis -> Column pair pruning -> Compressed KV-Cache -> Absorption into downstream projections (e.g., O) -> Modified attention computation

**Critical path:**
1. For each attention head, compute the RoPE rotation angles and identify column pairs that share the same rotational basis.
2. Evaluate saliency of each pair (e.g., via magnitude or reconstruction error) and select the least important pairs to prune according to a global budget.
3. Apply pruning mask to the key and value weight matrices, effectively discarding the selected pairs.
4. Multiply the pruning mask into the subsequent projection matrices (e.g., the output projection) to absorb the compression.
5. Load the compressed KV-Cache during inference; the attention computation proceeds with reduced dimensionality.

**Design tradeoffs:**
- Compression ratio vs. accuracy: Higher pruning rates yield larger savings but risk losing important information; the method shows small accuracy drops up to 30% compression.
- RoPE dependency: RAP only works with RoPE because it relies on the 2×2 rotation structure; models with absolute or learned positional encodings are not supported.
- One-time restructuring cost: Absorption requires modifying downstream weights, which incurs a minor upfront computation but no ongoing overhead.
- Need for potential fine-tuning: Although the paper reports no fine-tuning, in practice the weight shift from absorption might require a small amount of calibration to recover accuracy.

**Failure signatures:**
- Sudden increase in perplexity or drop in zero-shot accuracy beyond acceptable thresholds, indicating over-pruning.
- Latency not improving or even worsening, possibly because absorption introduced irregular memory access patterns or the implementation did not fully utilize the reduced dimensions.
- Incompatibility with hardware kernels that assume fixed projection dimensions; may require custom attention kernels.
- Model divergence if pruning is applied without proper initialization or if the absorption is incorrectly implemented.

**First three experiments to run:**
1. **Accuracy validation**: Run RAP on LLaMA-3-8B and Mistral-7B with compression ratios from 10% to 30%; measure perplexity on WikiText2, zero-shot accuracy on common sense reasoning tasks, and LongBench scores.
2. **Latency measurement**: Profile attention latency (prefill and decode phases) on a GPU (e.g., A100) using standard kernels; compare against baseline and SVD/PaLU baselines.
3. **Generalizability test**: Apply RAP to a larger RoPE-based model (e.g., LLaMA-3-70B) and to a non-RoPE model (e.g., GPT-2 with learned positional embeddings) to confirm that compression benefits transfer or fail gracefully.

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions, but its limitations and future work imply the following areas remain unresolved:
- What are the trade-offs at compression ratios beyond 30%? The experiments stop at 30%, leaving higher compression unexplored.
- How does RAP generalize to architectures without RoPE or to much larger models (e.g., >20B parameters)? The evaluation is limited to LLaMA-3-8B and Mistral-7B.
- Is fine-tuning necessary after applying RAP to recover any accuracy loss from weight absorption? The paper reports no fine-tuning, but this may not hold for all tasks or models.

## Limitations
- Model coverage limited to LLaMA-3-8B and Mistral-7B; scalability to larger architectures remains unproven.
- Compression extent capped at 30% in experiments; trade-offs at higher ratios (e.g., 50%) are unquantified.
- End-to-end system evaluation lacking; latency measured only on attention kernels, not on full inference pipelines or memory footprints under realistic workloads.
