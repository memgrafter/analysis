# CausalAgent: A Conversational Multi-Agent System for End-to-End Causal Inference

## Quick Facts
- arXiv: 2602.11527
- URL: https://arxiv.org/abs/2602.11527
- References: 20
- Primary result: CausalAgent automates end-to-end causal inference—from data cleaning to report generation—through natural language interaction, lowering technical barriers while ensuring rigor and interpretability.

## Executive Summary
CausalAgent is a conversational multi-agent system that automates the entire causal inference pipeline. It decomposes the workflow into three specialized agents—Data Processing, Causal Structure Learning, and Reporting—orchestrated by a LangGraph state machine. Leveraging retrieval-augmented generation (RAG) from a knowledge base of causal textbooks and the Model Context Protocol (MCP) to invoke external discovery tools, the system produces rigorous causal graphs and interactive reports from raw data and natural language queries. Demonstrated on the Sachs protein signaling dataset, it identified Akt and Pka as master regulators and supported follow-up intervention questions, making causal analysis accessible to non-experts. Nevertheless, challenges remain regarding latent confounders, data type diversity, and the reliability of LLM-driven decisions.

## Method Summary
The system employs a modular multi-agent architecture orchestrated by a LangGraph state machine. The Data Processing Agent handles data validation, statistical profiling, and visualization; the Causal Structure Learning Agent selects an appropriate discovery algorithm (e.g., PC, OLC) via the Model Context Protocol (MCP) and invokes the `causal-learn` library; the Reporting Agent synthesizes results using a retrieval-augmented generation (RAG) knowledge base of causal textbooks and a fine‑tuned LLM (GLM‑4.6, SFT) to produce explanations and interactive visualizations. Agents exchange a shared structured state, enabling full automation from raw data upload to an interactive causal analysis report. Follow‑up queries reuse the persisted state, allowing users to ask intervention questions without re‑running discovery.

## Key Results
- Conducted autonomous data profiling on the Sachs dataset and selected the PC algorithm for DAG discovery.
- Produced a causal graph highlighting Akt and Pka as key master regulator targets.
- Supported natural language follow‑up queries, such as assessing intervention effects on Mek, without additional user effort.

## Why This Works (Mechanism)
### Mechanism 1: Modular Multi-Agent Decomposition
- **Claim**: Modular decomposition automates the end-to-end causal workflow.
- **Mechanism**: The pipeline is split into three agents with well-defined inputs/outputs; shared state confines failures and simplifies orchestration.
- **Core assumption**: The causal analysis workflow can be cleanly segmented into sequential, stateful stages.
- **Evidence**: Abstract states "integrates Multi-Agent Systems (MAS)... to achieve automation from data cleaning and causal structure learning to bias correction and report generation"; Section 2.1 details "The architecture is composed of three primary components: Data Processing Agent, Causal Structure Learning Agent, and Reporting Agent." Related MAS (e.g., EDM-ARS, KIMAs) exist but offer no direct validation of this segmentation for causal inference.
- **Break condition**: If a sub‑task (e.g., latent confounder handling) cannot be encapsulated, agent handoffs may introduce errors or require human intervention.

### Mechanism 2: RAG and SFT Grounding
- **Claim**: Retrieval‑augmented generation and supervised fine‑tuning reduce LLM hallucination in causal outputs.
- **Mechanism**: A vector knowledge base from causal textbooks provides retrieved context for the Reporting Agent; SFT of GLM‑4.6 improves instruction following and translation of statistical results to natural language.
- **Core assumption**: Retrieved textual knowledge and fine‑tuned instruction following can adequately constrain the LLM to produce technically accurate explanations.
- **Evidence**: Section 3 describes "(1) Retrieval‑Augmented Generation (RAG). We constructed a vectorized knowledge base from causal textbooks... (2) Supervised Fine‑Tuning (SFT). The base model was fine‑tuned to enhance instruction‑following and accuracy..." Abstract claims "ensuring rigorous, interpretable analysis without requiring users to manually interpret complex algorithmic outputs." Corpus includes works on LLM hallucination and RAG, supporting the general strategy but not specific efficacy.
- **Break condition**: If the knowledge base is incomplete or SFT data lacks coverage for novel outputs, the system may produce plausible but incorrect interpretations.

### Mechanism 3: MCP‑Enabled Safe Algorithm Selection
- **Claim**: The Model Context Protocol standardizes tool invocation and enables dynamic, safe algorithm selection.
- **Mechanism**: The Causal Structure Learning Agent uses natural language prompts and data characteristics to select and invoke appropriate tools (PC, OLC) through MCP, decoupling reasoning from execution and preventing invalid operations.
- **Core assumption**: Algorithm selection can be reliably triggered by an LLM based on NL instructions and simple data meta‑features.
- **Evidence**: Section 2.3 notes "This agent acts as an algorithm scheduler... utilizing the Model Context Protocol (MCP)... The agent selects the most appropriate algorithm based on natural language instructions and data characteristics." Section 4.1 shows "By analyzing data distribution characteristics... it autonomously selects the PC algorithm for pathway reconstruction." MCP is a new standard (Anthropic, 2024) with limited public validation.
- **Break condition**: Ambiguous queries or data characteristics outside heuristics may lead to inappropriate algorithm choice (e.g., using PC with latent confounders).

## Foundational Learning
### Causal DAG Assumptions and Structure Learning
- **Why needed**: The system outputs a DAG; users must understand assumptions (causal sufficiency, faithfulness) to interpret results and judge their validity.
- **Quick check**: What does the "acyclic" constraint imply about causal loops, and what real‑world phenomenon might violate this assumption?

### Multi‑Agent System (MAS) Orchestration
- **Why needed**: To extend or debug the system, engineers must comprehend agent communication, state management, and where failures propagate.
- **Quick check**: If the Data Processing Agent outputs a dataset with an unhandled missing value pattern, where in the shared state would this issue be recorded, and which agent is responsible for remediation?

### Retrieval‑Augmented Generation (RAG)
- **Why needed**: Report quality depends on the knowledge base and fine‑tuning; engineers must curate the corpus and assess retrieval relevance for domain‑specific causality terminology.
- **Quick check**: How would a poorly curated RAG knowledge base (e.g., mixing frequentist and Pearlian causality texts) manifest in the final report's language?

## Architecture Onboarding
### Component Map
Frontend/Interface -> Orchestrator (LangGraph) -> Data Processing Agent -> Causal Structure Learning Agent (via MCP to causal-learn) -> Reporting Agent (uses RAG from Knowledge Base) -> Frontend (interactive report). Supporting components: LLM Backend (GLM-4.6), Knowledge Base (vector store of textbooks), Tools (`causal-learn` under MCP).

### Critical Path
Data Upload → Data Processing Agent (profiling, quality checks) → State update → Causal Structure Learning Agent (algorithm selection via MCP, graph generation) → State update → Reporting Agent (RAG retrieval, synthesis, visualization) → Interactive report. Follow‑up queries re‑enter at Reporting with persisted state.

### Design Tradeoffs
- **Modularity vs Latency**: Agent handoffs and tool calls add overhead but improve debuggability and isolation.
- **Flexibility vs Safety**: LLM‑driven algorithm selection offers flexibility but risks mismatch; constrained by a limited library (PC, OLC) to mitigate.
- **Automation vs Transparency**: Full automation lowers barriers but may obscure methodological choices from advanced users.

### Failure Signatures
1. **Invalid graph**: Reporting Agent describes relationships absent from the adjacency matrix (state inconsistency).
2. **Stalled pipeline**: Data Processing Agent detects cycles but cannot propose a resolution, leaving the system awaiting user input.
3. **Hallucinated methodology**: Report cites causal principles not present in the RAG knowledge base.

### First 3 Experiments
1. **Data validation edge case**: Upload a dataset with a known non‑linear confounder structure. Check whether Data Processing flags it, whether Causal defaults to PC or tries OLC, and whether the report includes appropriate caveats.
2. **Algorithm selection probe**: Upload a linear DAG dataset (e.g., Alarm). Query "find all direct causes". Verify PC selection and graph accuracy. Then query "account for hidden factors" to test switch to OLC‑based if available.
3. **State persistence & follow‑up**: After initial analysis, ask "What is the effect of intervening on X on Y?". Confirm that the system reuses the persisted graph rather than rerunning discovery, and whether the intervention effect is computed quantitatively or described qualitatively.

## Open Questions the Paper Calls Out
- **Latent confounders & quantitative effect estimation**: The paper proposes integrating structure learning methods that handle latent confounders (e.g., FCI) and counterfactual modules to enable quantitative causal effect estimation, which is currently unsupported.
- **Expert feedback for high‑stakes domains**: Incorporating expert feedback loops for domains like healthcare and finance is suggested to enhance safety and reliability, but no implementation details are provided.
- **Robustness to mixed data types and time series**: The system's behavior on datasets with mixed data types (continuous, categorical) or non‑stationary time series is unexplored; the demo uses only continuous static flow cytometry data.
- **Impact of LLM‑driven decisions on rigor**: The LLM's role in routing, conflict resolution, and algorithm selection may introduce biases or hallucinations; the paper lacks ablation studies to quantify this risk.
- **Accommodating users with varying expertise**: The natural language interface targets non‑experts, but common query formulation pitfalls are not studied; adaptive guidance may be needed.

## Limitations
- Modular segmentation lacks external validation; no prior work confirms that this specific agent handoff design yields robust causal inference.
- MCP, a new standard, has unproven safety and expressivity for dynamic algorithm selection in causal discovery.
- The composition of the RAG knowledge base and the SFT data are undisclosed, raising concerns about grounding completeness and generalizability.

## Confidence
- Modular decomposition: Medium
- RAG/SFT grounding: Low
- MCP‑enabled algorithm selection: Medium

## Next Checks
- **Algorithm selection probe**: Test with datasets containing known latent confounders (e.g., from benchmarks) to verify whether the system inappropriately defaults to PC or attempts OLC‑based methods.
- **State persistence audit**: After an initial analysis, issue follow‑up intervention queries (e.g., "Effect of intervening on X on Y") and confirm that the system reuses the persisted causal graph rather than re‑running discovery.
- **RAG fidelity check**: Audit the final report's citations against the knowledge base chunks to detect whether explanations cite principles absent from retrieved contexts (i.e., hallucinations).
