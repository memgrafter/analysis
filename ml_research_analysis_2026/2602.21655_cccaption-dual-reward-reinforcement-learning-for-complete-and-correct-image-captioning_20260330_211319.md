# CCCaption: Dual-Reward Reinforcement Learning for Complete and Correct Image Captioning

## Quick Facts
- **arXiv ID**: 2602.21655
- **Source URL**: https://arxiv.org/abs/2602.21655
- **Reference count**: 40
- **Primary result**: CCCaption-2B outperforms state-of-the-art models including Qwen3-VL-32B with significant improvements in completeness and correctness metrics.

## Executive Summary
This paper addresses the fundamental limitation of image captioning models that rely on subjective human-annotated references, which often leads to incomplete or incorrect captions. The authors propose CCCaption, a dual-reward reinforcement learning framework that explicitly optimizes two objective aspects of caption quality: completeness and correctness. Completeness is achieved by rewarding captions that answer diverse visual queries generated by multiple MLLMs, while correctness is ensured by penalizing hallucinations through sub-caption query validation. A dynamic query sampling strategy is introduced to improve training efficiency. The framework is trained on a comprehensive CCaption-44k dataset and evaluated across multiple benchmarks, demonstrating state-of-the-art performance with substantial improvements over existing models.

## Method Summary
The paper proposes a dual-reward reinforcement learning framework that optimizes completeness and correctness in image captioning. The framework uses MLLM-generated queries to assess whether captions fully describe visual content (completeness) and whether they avoid hallucinations (correctness). A dynamic query sampling strategy improves training efficiency by focusing on high-contribution queries. The method employs GRPO algorithm for RL training, fine-tuning a Qwen3-VL-2B base model on 44k training samples. The framework generates diverse visual queries using multiple MLLMs, filters them for quality, and uses these queries to compute completeness and correctness rewards during training. Evaluation uses Prism, Hallucinations, and CapArena frameworks with Qwen3-VL-32B as judge.

## Key Results
- CCCaption-2B achieves new state-of-the-art performance, outperforming Qwen3-VL-32B by significant margins
- Substantial improvements in completeness metrics across ChartQA, CharXiv, InfoVQA, Verse, MMBench, and MMMUPro benchmarks
- Marked reductions in hallucination rates compared to baseline models and CapRL
- Strong performance on specialized benchmarks including OCRBench, RefCOCO, and WeMath2.0-Pro

## Why This Works (Mechanism)
The framework works by explicitly optimizing two complementary objectives that traditional captioning models overlook. Completeness reward ensures captions cover all salient visual information by requiring them to answer diverse MLLM-generated queries about the image. Correctness reward prevents hallucinations by validating that each sub-caption can answer specific queries about itself. The dynamic query sampling strategy makes training efficient by prioritizing queries that contribute most to learning. This dual-objective approach addresses the fundamental weakness of reference-based training, where models optimize for similarity to subjective human annotations rather than objective image understanding.

## Architecture Onboarding
**Component Map**: Image → MLLM Query Generator → Query Filter → Caption Generator → Completeness Judge + Correctness Judge → Rewards → GRPO Optimizer → Updated Model

**Critical Path**: Query generation → Caption generation → Reward computation → Model update → Training iteration

**Design Tradeoffs**: 
- Multiple MLLMs vs. single MLLM for query generation (better diversity vs. computational cost)
- Static vs. dynamic query sampling (simplicity vs. efficiency)
- MLLM judges vs. human evaluation (scalability vs. potential bias)
- Separate vs. joint reward optimization (stability vs. interaction effects)

**Failure Signatures**:
- Training instability when reward scaling is incorrect
- Hallucination increase when correctness reward is insufficient
- Poor coverage when query generation lacks diversity
- Slow convergence when dynamic sampling is ineffective

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How do different diversity thresholds affect the trade-off between completeness and correctness in CCCaption?
- **Basis in paper**: [explicit] The paper mentions using a threshold τ=0.1 for query diversity in Algorithm 1 but doesn't explore how varying this threshold impacts performance.
- **Why unresolved**: The authors fixed the threshold at 0.1 without investigating how different values might affect the balance between completeness and correctness rewards.
- **What evidence would resolve it**: Experiments testing different diversity thresholds (e.g., 0.05, 0.1, 0.2) and their effects on completeness/correctness metrics across multiple benchmarks.

### Open Question 2
- **Question**: What is the optimal query sampling strategy for the correctness reward computation?
- **Basis in paper**: [inferred] The paper uses a static sampling of 5 sub-caption queries for correctness reward but doesn't explore whether dynamic sampling would improve performance.
- **Why unresolved**: The authors applied dynamic sampling only to completeness reward, leaving open whether similar benefits could be achieved for correctness reward computation.
- **What evidence would resolve it**: Comparative experiments testing static vs. dynamic query sampling for correctness reward across various datasets and evaluation metrics.

### Open Question 3
- **Question**: How does CCCaption perform on out-of-distribution or cross-domain image captioning tasks?
- **Basis in paper**: [inferred] The paper evaluates on standard benchmarks but doesn't test performance on images from domains significantly different from the training data.
- **Why unresolved**: The evaluation focuses on existing benchmarks without exploring the model's robustness to domain shifts or novel image types.
- **What evidence would resolve it**: Testing CCCaption on diverse image domains (medical imaging, satellite imagery, historical photographs) and comparing performance degradation rates to baseline models.

## Limitations
- Performance constrained by quality of MLLM-generated queries used for training
- Evaluation framework relies heavily on MLLM judges, introducing potential bias
- Significant computational overhead from using large MLLM judges for reward computation
- Unknown implementation details for diversity metric V(Qx) affect reproducibility

## Confidence
- **High Confidence**: Dual-reward RL framework architecture and basic implementation
- **Medium Confidence**: Dynamic query sampling effectiveness and MLLM prompt templates
- **Low Confidence**: Absolute performance claims due to potential evaluation bias
