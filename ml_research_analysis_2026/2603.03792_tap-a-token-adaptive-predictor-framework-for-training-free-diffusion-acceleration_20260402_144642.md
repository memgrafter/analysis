# TAP: A Token-Adaptive Predictor Framework for Training-Free Diffusion Acceleration
## Quick Facts
- **arXiv ID:** 2603.03792
- **Source URL:** https://arxiv.org/abs/2603.03792
- **Reference count:** 40
- **Primary result:** TAP achieves a 6.24× speedup on FLUX.1-dev with no perceptual quality loss (ImageReward 0.99 vs. baseline 0.95) and only +0.1 GB memory overhead; on HunyuanVideo, it attains 4.98× acceleration with a minimal 1.7% drop in VBench score (65.46 vs. 66.61).

## Executive Summary
TAP is a training-free framework for accelerating diffusion model inference by adaptively predicting per-token features instead of performing full model evaluations. It employs a single first-layer probe to select the optimal predictor from a Taylor expansion family for each token at every step, exploiting heterogeneous temporal dynamics. On FLUX.1-dev, TAP achieves a 6.24× speedup with no perceptual quality loss, and on HunyuanVideo, it attains 4.98× acceleration with only a 1.7% drop in VBench score. The method consistently improves the accuracy-efficiency frontier over fixed global predictors and caching baselines across multiple architectures, with minimal memory overhead.

## Method Summary
TAP introduces a training-free, token-adaptive predictor framework for diffusion models. It operates in an N-step cycle: every Nth step, a full model evaluation caches the modulated first-layer input (h_t) and the residual (r_t). For the subsequent N-1 steps, for each token, TAP computes a lightweight proxy loss (cosine distance) between each candidate predictor's prediction of h_t and the cached actual h_t. The predictor with the smallest proxy loss is selected per token, and its prediction of the residual is used to form the output as x_t + predicted residual. The predictor family consists of Taylor expansions with varying orders (0,1,2) and prediction horizons, providing diversity to match heterogeneous token dynamics. This approach avoids hand-tuned thresholds and achieves significant speedups with minimal quality degradation, adding only constant memory overhead.

## Key Results
- **FLUX.1-dev:** 6.24× speedup, ImageReward 0.99 (baseline 0.95), memory overhead +0.1 GB.
- **HunyuanVideo:** 4.98× acceleration, VBench score 65.46 vs. baseline 66.61 (1.7% drop).
- **Consistency:** Outperforms fixed global predictors and caching baselines (e.g., TeaCache) across architectures at matched acceleration ratios.

## Why This Works (Mechanism)
TAP's effectiveness relies on three synergistic mechanisms:

1. **First-layer probe as a proxy for predictor quality:** A single full evaluation of the model's first layer provides an effective low-cost proxy for predicting which candidate predictor will yield the lowest downstream error for each token. The modulated first-layer input (h_t) is cached, and for subsequent steps, the distance between each predictor's predicted h_t and the cached value is computed. The core assumption is that error in predicting h_t is highly correlated with final output error, which is empirically validated (e.g., Figure 7 shows strong positive correlation). This allows cheap, early validation without running the full model.

2. **Diverse Taylor predictor family to capture heterogeneous token dynamics:** Tokens evolve at different rates and smoothness along the sampling trajectory. TAP constructs a predictor family by varying the Taylor expansion order (0,1,2) and prediction horizon range, yielding a compact set of candidates. Different tokens achieve their best approximation at different points in this predictor space. Ablations (Figure 2) show that jointly varying order and distance range yields the largest improvement, and zero-order predictors are particularly valuable for abrupt dynamics.

3. **Threshold-free per-token selection based on relative proxy errors:** Instead of applying a single global predictor or using fixed thresholds (e.g., TeaCache's), TAP selects per token based on argmin of proxy errors across the predictor pool. This relative decision is inherently adaptive to the current local state and avoids error accumulation. TAP outperforms threshold-based methods at matched acceleration ratios (e.g., 6.24× on FLUX.1-dev: TAP IR 0.99 vs. TeaCache 0.66), demonstrating the advantage of adaptive selection without hand-tuning.

## Architecture Onboarding
**Component map (data flow):**  
Probe Module -> (caches h_t, r_t) -> Selector (with Predictor Pool) -> p* -> Executor -> b_r_t -> Output.  
Window Manager controls the N-step cycle (1 full compute, N-1 predicted steps).

**Critical path:**
1. Every N steps (t mod N == 0): Run full forward pass f_θ(x_t, t), cache h_t and r_t, output = f_θ(...).
2. For other steps: For each predictor p in parallel, compute b_h_t,p = Predict(p, C_h) using finite differences from cached features.
3. Per token: p* = argmin_p d(b_h_t,p, C_h) (cosine distance).
4. Per token: b_r_t = Predict(p*, C_r).
5. Assemble b_r_t across tokens, output = x_t + b_r_t.

**Design tradeoffs:**
- **Predictor Pool Size vs. Overhead:** More predictors increase chance of a good fit but add linear prediction cost. Empirically, a small pool (e.g., 15) saturates gains.
- **Probe Fidelity vs. Cost:** Using only first-layer h_t minimizes cost but may be less informative for deeper dynamics. Modulated input works better than raw input.
- **Granularity (δ) vs. Diminishing Returns:** Finer discretization of prediction horizon (δ=0.1) gives minimal gain (~0.005 IR) vs. δ=1, so coarse is preferred.
- **Memory:** TAP's constant O(1) cache (only h_t, r_t) vs. O(L) for layer-wise caches (e.g., TaylorSeer) is a major advantage.

**Failure signatures:**
- **Quality Drop at High N:** If the predictor pool cannot cover a token's dynamics within the larger prediction horizon, selected predictors will have high error → visible artifacts (blur, distortion).
- **Batch Divergence:** If per-token p* choices cause unstable, non-smooth transitions in the predicted residual field across the batch, it may lead to coherent artifacts or flickering in videos.
- **Probe Misleading:** If for certain prompts/timesteps, the first-layer probe is a poor proxy for final error (low correlation), selections will be misinformed. This might manifest as prompt-specific quality collapse.
- **Memory Overrun:** While O(1), the cached tensors scale with batch size and token count. Very large batches/resolutions could still pressure HBM.

**First 3 experiments:**
1. **Reproduce Probe Correlation:** On a small subset (e.g., 10 prompts), run full-step trajectories, cache h_t and final output features. Compute, for a held-out set of predictor types, the correlation between d(bh_p, h_t) and the true future feature error at step t+k. Validate the core assumption (target Spearman >0.7).
2. **Ablate Predictor Pool:** Fix N (e.g., 5). Systematically remove predictor categories (e.g., only order 0, only order 2, only short horizon). Measure delta in ImageReward/LPIPS. Confirms that diversity (especially inclusion of order 0) is necessary.
3. **Validate Threshold-Free Claim:** Implement a naive thresholded version of TAP: only accept a predictor if min_p L_p < τ, else do full compute. Sweep τ and compare Pareto frontier to base TAP (argmin). Empirical evidence should show TAP's relative selection outperforms any fixed τ, confirming the design choice.

## Open Questions the Paper Calls Out
**Open Question 1:** What is the optimal configuration for the Taylor predictor family in TAP, including order range, prediction horizon, and granularity, for different diffusion models?  
*Basis:* The paper uses fixed hyperparameters (M=3, λ=4, δ=1) based on ablation but does not provide a method to determine these for arbitrary models.  
*Why unresolved:* The heuristic choices may not be globally optimal; model-specific tuning could improve the accuracy-efficiency trade-off.  
*What evidence would resolve it:* Systematic evaluation of predictor pool configurations across multiple benchmarks, with analysis correlating optimal pools with model statistics (e.g., feature variance, token dynamics).

**Open Question 2:** Is the first-layer modulated input probe the best choice for estimating predictor error, or can probes from other layers or feature aggregates improve TAP's selection accuracy?  
*Basis:* The paper compares modulated input to raw input but does not test probes from deeper layers or combined features.  
*Why unresolved:* The probe's correlation with downstream error might vary by model depth; a more informative probe could reduce misselection and enhance quality.  
*What evidence would resolve it:* Experiments using probes from various transformer layers, measuring proxy error correlation with actual prediction error, and assessing impact on generation metrics.

**Open Question 3:** Can TAP's token-adaptive prediction framework be successfully extended to non-transformer diffusion architectures, such as U-Net-based models?  
*Basis:* All evaluations are on diffusion transformers (FLUX, Qwen-Image, HunyuanVideo); U-Net models like Stable Diffusion are not tested.  
*Why unresolved:* U-Nets have different feature hierarchies and spatial dependencies; TAP's assumption of per-token dynamics might not hold, and probe design may need adaptation.  
*What evidence would resolve it:* Implement TAP on a standard U-Net diffusion model, compare acceleration and quality against baselines, and analyze token heterogeneity in such architectures.

**Open Question 4:** What is the theoretical bound on error accumulation in TAP's per-token adaptive prediction, and how does it scale with acceleration ratio and predictor pool size?  
*Basis:* The paper demonstrates empirical error reduction but provides no theoretical analysis of error propagation with adaptive selection.  
*Why unresolved:* Without formal guarantees, it's difficult to predict TAP's behavior on unseen models or under extreme acceleration; theory could guide safe operating regimes.  
*What evidence would resolve it:* Develop a mathematical model for error bounds in adaptive predictor selection, validate with empirical error measurements at various acceleration factors.

## Limitations
- **Ambiguous probe definition:** The exact formulation of the modulated first-layer input h_t (layer placement, adaLN injection) is unspecified, risking implementation errors.
- **Unclear video handling:** Details on tokenizing video frames and mapping prediction horizon k_p to temporal steps are lacking.
- **Limited probe validation:** The correlation between probe error and downstream error is only validated on one model; it may degrade on diverse data, undermining predictor selection.
