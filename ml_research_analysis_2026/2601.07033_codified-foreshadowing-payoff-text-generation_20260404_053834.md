# Codified Foreshadowing-Payoff Text Generation

## Quick Facts
- arXiv ID: 2601.07033
- Source URL: https://arxiv.org/abs/2601.07033
- Reference count: 14
- Primary result: CFPG achieves >0.96 Should-Payoff Rate and 0.911 Avg. Score (vs 0.569) on BookSum, reducing premature triggers by 29.3%.

## Executive Summary
The paper addresses a critical weakness in large language models: their inability to maintain long-range narrative coherence, specifically failing to resolve foreshadowed elements (Chekhov's guns). To remedy this, the authors introduce Codified Foreshadowing-Payoff Generation (CFPG), a framework that explicitly models foreshadowing commitments as executable Foreshadow-Trigger-Payoff triples and maintains a dynamic "foreshadow pool" state during incremental generation. At each step, CFPG selects active payoffs based on trigger conditions, conditions the model on these payoffs, and updates the pool with new triples extracted from the generated text.

Evaluated on the BookSum dataset, CFPG dramatically outperforms strong prompting baselines. Under oracle timing, it achieves near-perfect payoff activation (>0.96 Should-Payoff Rate) and substantially higher narrative alignment (GPT-4.1-mini Avg. Score 0.911 vs. 0.569). Even under non-oracle tracking, CFPG reduces premature triggers by 29.3% and improves continuation fidelity, demonstrating that codifying narrative mechanics is a viable path to genuine long-range coherence.

## Method Summary
CFPG builds on a pre-extracted set of (Foreshadow, Trigger, Payoff) triples derived from BookSum hierarchical summaries. The core generation loop runs iteratively: (1) **Select** - From the current Foreshadow Pool Ct, identify triples whose Trigger condition T is satisfied by the accumulated context; these become active payoffs St. (2) **Generate** - Condition the language model on the active payoffs St and produce the next continuation y. (3) **Update** - Form the next pool Ct+1 by removing any triples whose Payoff P appears in y (i.e., resolved), and by codifying new (F, T, P) triples from y itself to propagate the narrative state forward. This ensures that foreshadowing commitments are persistently tracked and selectively activated.

The method is model-agnostic and operates at the token level, integrating seamlessly with existing autoregressive decoders. By externalizing the narrative “to-do list” into a dynamic pool, CFPG compensates for the limited context window and short-range biases of LLMs, compelling the generator to honor earlier setups when appropriate.

## Key Results
- Under oracle trigger detection, CFPG achieves >0.96 Should-Payoff Rate, nearly resolving all eligible foreshadows.
- On GPT-4.1-mini, CFPG’s narrative alignment Avg. Score is 0.911 vs. 0.569 for the foreshadow-aware prompting baseline.
- CFPG reduces premature triggers by 29.3% and improves continuation fidelity across multiple model families (Qwen2.5, Llama-3.1), demonstrating robustness.

## Why This Works (Mechanism)
CFPG succeeds by making narrative commitments explicit and computationally enforceable. The triple structure isolates the foreshadow, its necessary trigger condition, and the required payoff, turning vague literary devices into actionable items. The dynamic pool serves as a persistent working memory that survives beyond the model’s context window, ensuring no foreshadow is forgotten. Trigger evaluation gates payoff activation, preventing the model from firing payoffs too early or too late. Conditioning the generator on active payoffs biases its output toward needed resolutions, overriding the LLM’s default myopic distribution. This systematic combination of stateful tracking and goal-directed generation directly targets the root cause of long-range incoherence: the lack of internal checks that setups are eventually honored.

## Architecture Onboarding
**Component map**: Foreshadow Pool -> Select -> Generate -> Update -> Foreshadow Pool

**Critical path**: The generation loop iterates: (1) Select active triples by scanning pool for satisfied triggers; (2) Generate next segment conditioned on these active payoffs; (3) Update pool: remove resolved triples, extract new triples from the generated text. This cycle maintains a consistent narrative state.

**Design tradeoffs**: 
- Triple extraction quality: Errors in initial (F,T,P) mining propagate; requires clean source (e.g., summaries) and possibly manual verification.
- Trigger detection: Must balance precision (avoid false activations) and recall (capture true triggers); implementation may rely on heuristics or a classifier.
- Computational overhead: Maintaining and updating the pool each step adds latency and memory cost compared to vanilla generation.

**Failure signatures**:
- Premature triggers: High “Early Triggers” count indicates triggers firing before true narrative conditions are met.
- State desynchronization: Missing expected payoffs or duplicate removals manifest as “Deferred NYO” or “State Failure” errors.
- Low continuation fidelity: Generated text diverges significantly from source despite payoff conditioning, suggesting pool misalignment.

**First experiments**:
1. Oracle timing test: Provide the entire target story for perfect trigger detection; establish upper bound on Should-Payoff Rate.
2. Non-oracle timing with simple trigger matching (e.g., keyword overlap); quantify performance drop due to imperfect detection.
3. Baseline replication: Run the “foreshadow-aware prompting” without CFPG to confirm the reported gap on BookSum.

## Limitations
- Implementation specifics (exact prompt templates, trigger codification heuristics) are omitted, hindering exact replication.
- Evaluation confined to BookSum summaries; generalization to raw narrative text or diverse genres remains untested.
- The dynamic pool is prone to state failures (e.g., deferred NYO errors), revealing brittleness in trigger management and update logic.
