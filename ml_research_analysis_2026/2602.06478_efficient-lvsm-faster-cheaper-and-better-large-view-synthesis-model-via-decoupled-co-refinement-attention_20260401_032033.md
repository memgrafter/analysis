# Efficient-LVSM: Faster, Cheaper, and Better Large View Synthesis Model via Decoupled Co-Refinement Attention

## Quick Facts
- **arXiv ID:** 2602.06478  
- **Source URL:** https://arxiv.org/abs/2602.06478  
- **Reference count:** 21  
- **Primary result:** Achieves 29.86 dB PSNR on RealEstate10K with 2 input views, beating LVSM by 0.2 dB while using half the training time and 4.4× faster inference.

## Executive Summary
Efficient-LVSM tackles the inefficiency of large view synthesis models (e.g., LVSM) caused by full self-attention, which scales quadratically with input views and forces shared parameters for heterogeneous tokens (scene content vs. pose queries). It introduces a decoupled dual-stream architecture: an input encoder processes each view separately via intra-view self-attention, and a target decoder alternates self-attention (among targets) and cross-attention to cached encoder outputs from corresponding layers. This reduces complexity from O(N²) to O(N), enables KV-cache reuse for incremental inference, and allows specialized processing of distinct token streams. On RealEstate10K with 2 inputs, it achieves state-of-the-art PSNR (29.86 dB) with significantly lower training cost and faster inference, and generalizes zero-shot to any number of input views.

## Method Summary
The core method is a dual-stream transformer. Input views (images + camera poses as Plücker rays) are tokenized and encoded by an **Input Encoder** that applies intra-view self-attention separately per view, producing cached key/value pairs. Target views (pose-only tokens) are processed by a **Target Decoder** with L layers; each layer first performs self-attention among all targets, then cross-attends to the encoder’s output from the corresponding layer (co-refinement), followed by an FFN. This decoupling separates parameters for content-rich inputs and pose-only queries, eliminating unnecessary cross-view attention. An optional **REPA** (RenderEverything-Phase-Aligned) distillation uses a frozen DINOv3 teacher to align intermediate student features via a learned MLP and Smooth L1 loss, improving semantics without inference overhead. The render head converts final target tokens to images. Complexity is linear in the number of input views, and cached encoder KV pairs are reused across multiple target queries.

## Key Results
- PSNR 29.86 dB on RealEstate10K (2 input views), +0.2 dB over LVSM.
- 2× faster training, 4.4× faster inference compared to LVSM.
- State-of-the-art on multiple benchmarks; zero-shot generalization to arbitrary input view counts; up to 18.7× speedup with KV-caching for 16 inputs.

## Why This Works (Mechanism)

**Mechanism 1: Decoupled Dual-Stream Architecture**  
Separating input encoding from target decoding eliminates quadratic complexity and enables specialized processing of heterogeneous tokens. The Input Encoder uses intra-view self-attention, processing each input view independently, while the Target Decoder alternates self-attention (among targets) and cross-attention to cached encoder outputs. This avoids attention among input views and separates parameters for content-rich inputs vs. pose-only queries. Evidence: [Abstract] decoupled dual-stream architecture eliminates unnecessary computation; [Section 2.3] complexity reduced from O(N²) to O(N). Break condition: If input views require strong inter-view reasoning (e.g., precise stereo matching), intra-view-only encoder may lose critical correspondences, harming quality.

**Mechanism 2: Co-Refinement via Layer-Wise Bridging**  
Connecting each encoder layer to the corresponding decoder layer leverages multi-level features, improving reconstruction details. At decoder layer l, cross-attention queries the encoder’s output from the same layer, fusing fine-grained early-layer details with high-level late-layer semantics. Evidence: [Section 2.5] decoder synthesizes using both fine-grained details and rich semantic context; [Table 6a] co-refinement yields 1.28 dB PSNR gain over cross-attention-only decoder. Break condition: Encoder intermediate features may be noisy or misaligned with decoder’s evolving representation, especially early in training, introducing artifacts.

**Mechanism 3: REPA Distillation with DINOv3**  
Distilling middle-layer features from a pretrained vision model (DINOv3) injects semantic supervision without inference overhead. During training, projected intermediate tokens are aligned with DINOv3 features using Smooth L1 loss; the teacher is discarded after training. Evidence: [Abstract] REPA distills visual features without sacrificing inference speed; [Section 2.6] REPA helps extract semantics; [Table 6b] REPA adds +0.8 dB for Efficient-LVSM vs. +0.16 dB for LVSM, showing synergy. Break condition: If DINOv3 features are out-of-distribution (e.g., synthetic vs. real scenes), alignment loss may misguide training.

## Foundational Learning
- **Attention Complexity and KV-Caching**  
  Why needed: The efficiency gains rely on linearizing attention and reusing key-value caches. Without understanding O(N²) scaling and KV-cache mechanics, the speedups are unintuitive.  
  Quick check: How many times does LVSM recompute attention for N input tokens when synthesizing M target views? How does caching per-view KV pairs avoid this?
  
- **Dual-Stream vs. Monolithic Transformer**  
  Why needed: The core innovation decouples the transformer into separate encoder and decoder streams with different attention constraints. Recognizing the roles of intra-view SA vs. cross-attention is essential.  
  Quick check: Why can't we simply use a single transformer with masked attention to simulate the dual-stream design? What computational inefficiency would remain?
  
- **Feature Distillation with Alignment**  
  Why needed: REPA is a key quality booster but introduces training complexity. Understanding the choice of teacher layer, loss, and projector avoids misconfiguration.  
  Quick check: What is the trade-off between distilling from early vs. middle vs. late layers of DINOv3? Why might Smooth L1 work better than L2 or cosine loss?

## Architecture Onboarding

**Component map**  
Patchifier -> Plücker embedder -> Input Encoder (N independent intra-view SA streams) & Target Decoder inputs -> Target Decoder (L layers: self-attn -> cross-attn to encoder's same-layer output -> FFN) -> Render head -> Output. REPA train-only branch: DINOv3 teacher + MLP projector aligns student tokens.

**Critical path**  
1. For each input view, patchify RGB + Plücker rays → tokens S_i.  
2. Encode: each S_i → L encoder layers (intra-view SA+FFN). Cache all K_i, V_i.  
3. For each target view, initialize Plücker-only token T_j.  
4. Decode per layer: T_j self-attn → cross-attn to all K_i^l, V_i^l → FFN.  
5. Render: final T_j → LayerNorm → Linear → Sigmoid → unpatchify → image.  
6. Loss: L1/L2 image loss + λ · REPA loss (if used).

**Design tradeoffs**  
- Dual-stream: +~12% parameters vs LVSM but gains linear complexity and KV-reuse.  
- Intra-view encoder: faster, but loses inter-view cues; compensated by decoder cross-attention. Fails with <2 inputs.  
- REPA: ~20% longer training, zero inference cost. Depends on pretrained teacher domain match.  
- Co-refinement: better quality but increases memory (caching all layer KVs). Still cheaper than full attention.

**Failure signatures**  
- Blurry outputs (low PSNR): missing REPA, incorrect co-refinement (e.g., only last encoder layer), or insufficient training.  
- No speedup: defective intra-view attention mask or missing KV-cache reuse; verify near-linear memory growth.  
- REPA degrades performance: dimension mismatch, poor MLP init, or wrong DINOv3 layer (should be middle, e.g., layer 8).  
- Training divergence: too high learning rate, unstable masked attention; use gradient clipping and longer warmup.

**First 3 experiments**  
1. Ablate architecture: (a) cross-attn-only decoder, (b) self-then-cross, (c) +co-refinement. Expect (c) best (Table 6a).  
2. REPA sweep: with/without REPA; vary DINOv3 layer (8/10/12) and loss (Smooth L1/L2/cosine). Expect middle-layer Smooth L1 best (Table 5).  
3. Scaling test: measure latency/memory vs #input views (2,4,8,16). Expect Efficient-LVSM linear; LVSM Dec-Only quadratic (Fig 6).

## Limitations
- Plücker embedding details (dimension, normalization) and image preprocessing are unspecified, requiring assumptions for reproduction.
- Full training schedule (iterations for 12+12 layer model) is not provided; scaling from smaller models needs ad-hoc adjustments.
- REPA configuration (student layer to align, loss weight, token streams) is only partially described.
- Potential domain gap: DINOv3 features may not align well with NVS scenes; intra-view encoder loses inter-view cues for single-view inputs.
