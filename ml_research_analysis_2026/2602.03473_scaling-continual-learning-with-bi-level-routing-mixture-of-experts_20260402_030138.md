# Scaling Continual Learning with Bi-Level Routing Mixture-of-Experts
## Quick Facts
*   **arXiv ID:** 2602.03473
*   **Source URL:** https://arxiv.org/abs/2602.03473
*   **Reference Count:** 24
*   **Primary Result:** Proposed CaRE method with BR-MoE achieves state-of-the-art performance on long-sequence class-incremental learning (e.g., +4.67% over prior best on 100 tasks) and maintains strong results on standard benchmarks.

## Executive Summary
This paper introduces CaRE, a method designed to scale class-incremental learning (CIL) to extremely long task sequences (100-300+ tasks). The core innovation is a Bi-Level Routing Mixture-of-Experts (BR-MoE) mechanism integrated into each network layer, which dynamically routes inputs to task-specific and shared experts. To evaluate this scaling, the authors establish a new long-sequence protocol using a 1000-class subset of OmniBenchmark-V2. CaRE significantly outperforms all prior methods across sequences of 100, 151, 200, and 301 tasks on this protocol, while also remaining competitive on conventional shorter-sequence CIL benchmarks.

## Method Summary
CaRE incorporates a BR-MoE block into every layer of a neural network. This block employs a two-stage routing process. First, an entropy-based router selection mechanism identifies the most relevant subset of task-specific routers from a large pool. Second, an expert routing mechanism activates and aggregates the top-k most relevant experts from those selected routers, complemented by a always-active shared expert. This design aims to balance task-specific specialization (via the routers and their associated experts) with general knowledge retention (via the shared expert), enabling the model to learn discriminative and comprehensive features across a vast number of incremental tasks without prohibitive parameter growth.

## Key Results
*   On the proposed 100/151/200/301-task OmniBenchmark-V2 protocol, CaRE achieves state-of-the-art performance, exceeding the previous best method (MIN) by 4.67% in last accuracy on the 100-task sequence and by a large margin on the 301-task sequence.
*   CaRE maintains leading performance on standard short-sequence CIL benchmarks like CIFAR-100 and ImageNet-R/A.
*   The method demonstrates consistent improvement as sequence length increases, highlighting its effectiveness for scaling.

## Why This Works (Mechanism)
The BR-MoE mechanism likely succeeds because it explicitly addresses two core challenges of long-sequence CIL: catastrophic forgetting and the need for fine-grained feature discrimination across many classes. The bi-level routing (router selection then expert aggregation) provides a computationally efficient way to specialize model capacity for each task without linearly scaling parameters. The shared expert acts as a stabilizing force, preserving general features and mitigating forgetting. The entropy-based router selection ensures that only the most contextually relevant routers (and thus their expert subsets) are activated for a given input, preventing interference from irrelevant task-specific parameters and promoting clean, discriminative representations.

## Foundational Learning
*   **Class-Incremental Learning (CIL):** A paradigm where a model learns a sequence of classification tasks with disjoint class sets. *Why needed:* The fundamental problem the paper solves. *Quick check:* Can the model classify all seen classes at the end without task IDs?
*   **Mixture-of-Experts (MoE):** A neural network architecture where multiple "expert" sub-networks are conditionally activated by a gating/router mechanism. *Why needed:* The core architectural component (BR-MoE) enabling scalable, conditional computation. *Quick check:* Does only a subset of parameters process each input?
*   **Catastrophic Forgetting:** The tendency of neural networks to lose previously learned knowledge upon learning new information. *Why needed:* The primary challenge in continual learning that CaRE aims to mitigate. *Quick check:* Does model performance on old tasks drop sharply after learning new tasks?
*   **Dynamic Routing:** The process of determining which experts or pathways in a network should be activated for a given input. *Why needed:* Implements the conditional computation in BR-MoE. *Quick check:* Is the path through the network input-dependent?
*   **Task-Specific vs. Shared Representations:** A trade-off between specializing parameters for individual tasks versus maintaining generalist parameters. *Why needed:* BR-MoE explicitly balances these via its router/expert design. *Quick check:* Are there parameters that are always active (shared) and some that are only active for specific tasks?
*   **Entropy-Based Selection:** Using the entropy of a router's output distribution as a signal for its relevance. *Why needed:* Proposed criterion for the first stage of bi-level routing to select routers. *Quick check:* Is router selection based on the uncertainty/peakedness of its expert weighting?

## Architecture Onboarding
**Component Map:** Input -> BR-MoE Block (Entropy Router Selection -> Expert Routing [Top-k Aggregation + Shared Expert]) -> ... (multiple such layers) -> Classifier

**Critical Path:** The forward pass for an input traverses each layer's BR-MoE block. Within a block: (1) Compute router outputs for all task-specific routers; (2) Select top routers based on low entropy of router output; (3) For selected routers, compute and combine top-k expert outputs, summing with the shared expert's output; (4) Pass aggregated result to next layer.

**Design Tradeoffs:** The bi-level design trades increased architectural complexity and potential computational overhead for superior long-sequence performance. The number of routers and experts per router controls capacity and sparsity. The shared expert provides stability but may limit pure task-specific specialization. The entropy threshold for router selection is a key hyperparameter balancing specificity and robustness.

**Failure Signatures:** 1) Performance collapse on very long sequences (>200 tasks) if router selection becomes noisy or fails to identify relevant routers. 2) High computational cost if router selection or expert aggregation is inefficient. 3) Degraded performance on short sequences if the shared expert's contribution is insufficient or if router selection introduces instability.

**First 3 Experiments:**
1.  Replicate main results on the 100-task OmniBenchmark-V2 sequence and confirm the performance gap vs. MIN.
2.  Ablate the BR-MoE design by removing the entropy-based router selection stage (using all routers always) to measure its contribution.
3.  Measure and report the average activation ratio of experts (sparsity) and compare training/inference FLOPs against a dense ResNet of similar total parameter count.

## Limitations
*   Evaluation is confined to a single curated 1000-class subset of OmniBenchmark-V2, limiting claims about generalizability to other long-sequence data distributions.
*   The computational overhead (memory, FLOPs, latency) of the BR-MoE mechanism is not quantified, which is essential for validating "scaling" claims.
*   The complex bi-level architecture makes it difficult to isolate the individual contribution of its components (entropy router, top-k routing, shared expert) without targeted ablations.

## Confidence
*   **High:** Performance improvement on the *proposed* 100/151/200/301-task OmniBenchmark-V2 protocol (internal validation).
*   **Medium:** Claim of SOTA superiority over prior methods on long sequences; depends on baseline implementation fairness and protocol design.
*   **Low:** Generalizability of these gains to other long-sequence benchmarks or fundamentally different task structures; not tested.
