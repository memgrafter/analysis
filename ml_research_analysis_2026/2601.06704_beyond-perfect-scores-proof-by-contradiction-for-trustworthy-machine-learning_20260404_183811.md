# Beyond Perfect Scores: Proof-by-Contradiction for Trustworthy Machine Learning

## Quick Facts
*   **arXiv ID:** 2601.06704
*   **Source URL:** https://arxiv.org/abs/2601.06704
*   **Reference Count:** 40
*   **Primary Result:** A bucket-level label permutation test, using Fisher-style p-values, can detect when high model accuracy is driven by untrustworthy spurious correlations in hierarchical biomedical data.

## Executive Summary
Machine learning models in biomedicine frequently achieve near-perfect test accuracy by exploiting spurious correlations within hierarchical datasets (many data units from few groups/buckets), such as using hospital-specific artifacts instead of true disease signals. This undermines clinical trust. The authors propose a trustworthiness test based on proof-by-contradiction: if a model genuinely learns predictive signal, randomly permuting labels *within* predefined buckets (e.g., patient IDs) should cause a significant drop in accuracy. Performance comparable to the null distribution indicates overfitting or data leakage. This method is grounded in the Rubin causal model and uses interpretable Fisher p-values for quantification. Evaluations on bacterial diagnostics and benchmarks reveal that perfect scores can coexist with high p-values, exposing unreliability. The approach also shows computational efficiency, with stable p-values achievable using only ~15% of all possible permutations.

## Method Summary
The core method is a non-parametric, bucket-level permutation test. First, the data's hierarchical structure is leveraged to define buckets (e.g., unique patient identifiers). The test statistic is the model's accuracy on a held-out set. To build a null distribution, labels are repeatedly shuffled *within* each bucket (preserving the bucket structure), and accuracy is recomputed for each shuffle. A Fisher-combined p-value aggregates evidence across these permutations. The null hypothesis is that the model's performance does not depend on the true input-output mapping within buckets. A small p-value (significant drop in accuracy under permutation) suggests the model relies on valid signal; a large p-value suggests its performance may be driven by spuriously correlated features that remain valid under within-bucket shuffling.

## Key Results
*   Models can achieve >99% test accuracy yet have non-significant p-values (>0.05), indicating their performance is likely untrustworthy due to spurious correlations.
*   The Fisher p-value test successfully discriminates between models that overfit to bucket-level artifacts and those that learn generalizable features on bacterial diagnosis tasks.
*   Using approximately 15% of all possible within-bucket permutations yields p-values that are stable and highly correlated with those from the full permutation set, offering >80% computational savings.

## Why This Works (Mechanism)
The method operates on a proof-by-contradiction principle anchored in causal inference. If a model's predictions are based on true causal features of the outcome, then destroying the relationship between those features and the label (via permutation) must degrade performance. Conversely, if a model's high accuracy stems from leveraging spurious correlations—features that are constant or predictable within a bucket but unrelated to the true label—shuffling labels within buckets will not break these correlations. The model's accuracy will remain high under permutation, leading to a non-significant p-value. This logic explicitly tests for dependency on the true label mechanism within the exchangeability blocks defined by the buckets, making the trustworthiness assessment causal rather than correlational.

## Foundational Learning
*   **Hierarchical / Grouped Data:** Data where units (e.g., samples, patients) are nested within buckets (e.g., hospitals, collection batches). *Why needed: The method's validity depends on correctly identifying these buckets to define exchangeability blocks for permutation.* Quick check: Verify that units within the same bucket share a common source of potential spurious correlation (e.g., same scanner, same clinician).
*   **Spurious Correlation:** A statistical association between a feature and the label that does not reflect a causal or generalizable relationship, often arising from confounding or data collection artifacts. *Why needed: The paper's central thesis is that high accuracy can be driven by such correlations, which the test aims to detect.* Quick check: Check if a feature's importance vanishes or reverses when controlling for bucket identity or in new environments.
*   **Rubin Causal Model (RCM):** A framework for causal inference based on potential outcomes. *Why needed: The permutation test's justification is grounded in the RCM's definition of causal effects and the assumption of exchangeability within strata.* Quick check: Ensure the bucket definition aligns with a coarse version of the assignment mechanism for the "treatment" (the true label).
*   **Permutation Test / Randomization Test:** A statistical test where the null distribution is generated by artificially shuffling data. *Why needed: Provides a model-free, exact way to compute p-values without distributional assumptions.* Quick check: Confirm that the permutation scheme (within-bucket) correctly implements the null hypothesis of no true signal.
*   **Fisher's Combined Probability Test:** A method to combine p-values from multiple independent tests into one overall p-value. *Why needed: The test yields one accuracy value per permutation; Fisher's method aggregates these to produce a single, interpretable p-value for the model's overall performance.* Quick check: Apply Fisher's method to a set of uniform[0,1] p-values and confirm the resulting distribution is also uniform under the global null.
*   **Exchangeability:** The statistical assumption that the joint distribution of data is invariant to permutation. *Why needed: The within-bucket permutation test's validity rests on the assumption that labels are exchangeable within buckets under the null hypothesis of no true signal.* Quick check: Visually inspect or test for residual temporal or spatial patterns within buckets that might violate exchangeability.

## Architecture Onboarding
*   **Component Map:**
    Bucket Definition -> Label Permutation (within buckets) -> Model Inference on Permuted Data -> Accuracy Calculation -> Fisher p-value Aggregation -> Trustworthiness Decision
*   **Critical Path:** The computational bottleneck is model inference on the permuted validation sets. The number of permutations directly determines runtime. The path to a decision is: define buckets -> choose number of permutations (k) -> generate k permuted label sets -> run model on each -> compute k accuracies -> combine into Fisher p-value -> compare p-value to threshold (e.g., α=0.05).
*   **Design Tradeoffs:** The primary tradeoff is between computational cost (number of permutations) and p-value stability. More permutations yield a more precise null distribution but increase runtime. The paper suggests ~15% is sufficient. A second tradeoff is in bucket definition: overly granular buckets reduce permutation power; overly coarse buckets may fail to capture key spurious correlations.
*   **Failure Signatures:**
    1.  High accuracy + High p-value (non-significant): Model likely untrustworthy, relying on spurious correlations.
    2.  Low accuracy + Low p-value (significant): Model is consistently poor and its poor performance is not due to bucket artifacts; it fails generally.
    3.  Sensitivity to bucket definition: Drastic changes in p-value when bucket granularity is altered indicate the test's dependence on correct bucket specification.
*   **First 3 Experiments:**
    1.  **Sanity Check with Synthetic Leakage:** Train a model on a synthetic dataset where the label is artificially leaked via a bucket-level constant feature. Verify the test yields a high p-value, while a model trained on true signal yields a low p-value.
    2.  **Permutation Fraction Ablation:** For a fixed model and dataset, compute p-values using 1%, 5%, 10%, 15%, 20%, 50%, and 100% of possible permutations. Plot p-value stability (e.g., correlation with full p-value) vs. fraction to empirically validate the ~15% claim.
    3.  **Comparison to Calibration Metrics:** Train a well-calibrated model and an overconfident model on a biomedical dataset. Compare their bucket permutation p-values against metrics like Expected Calibration Error (ECE) and Brier score to assess whether the p-value captures distinct information about trustworthiness related to overfitting/leakage.

## Limitations
*   The test's validity critically depends on correct bucket specification; unknown or misspecified buckets can lead to invalid p-values and incorrect conclusions about trustworthiness.
*   The Fisher p-value framework and the within-bucket permutation rely on the assumption of label exchangeability within buckets, which may be violated by unmodeled temporal, spatial, or other dependencies, potentially inflating Type I error.
*   Evaluations are limited to bacterial diagnostic tasks and controlled synthetic benchmarks, so the method's generalizability and performance across the full spectrum of biomedical machine learning problems remain to be fully established.

## Confidence
*   **Problem Claim (Spurious correlations in hierarchical biomedical data undermine trust):** Medium Confidence. The existence of this issue is well-documented in ML fairness and dataset literature, but its specific prevalence and impact in the evaluated biomedical contexts require broader empirical validation.
*   **Method Claim (Bucket permutation with Fisher p-values detects untrustworthy models):** Medium Confidence. The causal reasoning is sound and empirical results on provided datasets are compelling, but the method's sensitivity/specificity on unseen, diverse biomedical data and under bucket misspecification is not fully characterized.
*   **Efficiency Claim (~15% permutations suffice for stable p-values):** Medium Confidence. The presented empirical analysis supports this for the specific datasets used, but this threshold may be dataset-dependent and the stability metric could benefit from more rigorous definition (e.g., confidence interval width).
