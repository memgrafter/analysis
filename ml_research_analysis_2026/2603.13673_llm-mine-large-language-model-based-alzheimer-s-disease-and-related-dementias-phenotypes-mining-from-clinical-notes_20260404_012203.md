# LLM-MINE: Large Language Model based Alzheimer's Disease and Related Dementias Phenotypes Mining from Clinical Notes

## Quick Facts
- **arXiv ID:** 2603.13673  
- **Source URL:** https://arxiv.org/abs/2603.13673  
- **Reference count:** 31  
- **Primary result:** A customizable LLM prompting framework extracts clinically meaningful ADRD phenotypes from clinical notes; few-shot prompting with combined phenotype lists achieves the best unsupervised patient clustering (ARI=0.290, NMI=0.232), substantially outperforming biomedical NER and dictionary-based baselines.

## Executive Summary
This paper introduces LLM-MINE, a framework for mining Alzheimer’s disease and related dementias (ADRD) phenotypes from unstructured clinical notes using large language models. The approach constrains the LLM’s output to a predefined phenotype vocabulary, enabling reliable, structured extraction that can be aggregated into binary feature vectors per patient. Evaluated on MIMIC-IV discharge notes across cognitively normal, mild cognitive impairment (MCI), and ADRD cohorts, the extracted phenotypes show statistically significant prevalence differences (e.g., memory impairment) and support unsupervised patient stratification. Few-shot prompting and combining multiple phenotype lists yield the strongest clustering performance, surpassing traditional biomedical NLP baselines.

## Method Summary
LLM-MINE processes discharge notes by first splitting them into sentence-level chunks to handle length constraints. For each chunk, a prompt is constructed containing a task instruction, a candidate phenotype list (from one or two expert-curated sources), and optionally three few-shot examples. The instruction-tuned model (`gemma-3-12b-it`) is queried to select applicable phenotypes from the list (or output “none”). Results from all chunks are union-aggregated per note and then per patient, producing a binary feature vector indicating presence/absence of each phenotype. These vectors are used for chi-square tests of prevalence across cohorts and for k-means clustering (K=2, K=3), evaluated against true cohort labels via ARI, NMI, and FMI. The method is fully prompt-based, with no model fine‑tuning.

## Key Results
- Phenotype prevalence differs significantly across CN, MCI, and ADRD cohorts (chi‑square p<0.001 for key phenotypes like memory impairment).
- Few-shot prompting with combined phenotype lists achieves best clustering: ARI=0.290 (K=2) and NMI=0.232 (K=3), far exceeding QuickUMLS and biomedical NER baselines.
- Memory impairment emerges as the strongest discriminator between CN and ADRD, while distinguishing MCI from ADRD remains challenging.

## Why This Works (Mechanism)
**Mechanism 1: Constrained output space improves reliability.**  
Framing extraction as a multi‑label classification from a fixed candidate list suppresses open‑ended generation, reduces hallucination, and yields parseable results that map directly to binary feature vectors. This consistency enables downstream aggregation without complex post‑processing. If phenotypes fall outside the predefined list, recall will suffer.

**Mechanism 2: Few‑shot prompting enhances accuracy.**  
Providing three demonstration examples teaches the model the task format, expected output style, and mapping from clinical language to phenotypes. This in‑context learning bridges the gap between the model’s general medical knowledge and the precise extraction task. Poorly chosen or non‑representative examples could cause overfitting.

**Mechanism 3: Chunking at sentence boundaries preserves local context.**  
Long notes are split into self‑contained sentence chunks; the LLM processes each independently and extractions are unioned. This avoids truncating mid‑span and handles documents exceeding the context window. The approach assumes phenotype mentions are locally contained; cross‑sentence dependencies may be missed.

## Architecture Onboarding
**Component map:**  
Raw clinical notes → Sentence chunking → LLM prompting per chunk (with phenotype list and few‑shot examples) → Union aggregation across chunks → Binary feature vector per patient → Statistical tests & k‑means clustering

**Critical path:**  
1. Load note.  
2. Split into sentence chunks.  
3. For each chunk: build prompt, call LLM, parse output.  
4. Combine phenotypes across all chunks for the note.  
5. Combine across all notes for the patient to create a binary vector.  
6. Run chi‑square tests and k‑means clustering (K=2,3) on the patient matrix.

**Design tradeoffs:**  
- Constrained output vs. expressivity: fixed list ensures consistency but may miss unspecified phenotypes.  
- Chunking vs. context loss: chunking handles long notes but risks missing cross‑sentence phenotype cues.  
- Few‑shot vs. zero‑shot: few‑shot improves accuracy but requires curated, representative examples.

**Failure signatures:**  
- Chi‑square tests show no significant differences for key phenotypes (p>0.05).  
- Clustering metrics (ARI/NMI) near zero or negative, indicating poor separation.  
- Prevalence of a known ADRD phenotype (e.g., memory impairment) is low or non‑monotonic across cohorts.

**First 3 experiments:**  
1. Replicate cohort differentiation using the combined phenotype list with few‑shot prompting; confirm monotonic prevalence increases for memory and neuroimaging findings (p<0.001).  
2. Reimplement patient feature pipeline and k‑means clustering; verify that “Combination + Few‑shot” achieves ARI≈0.290 (K=2) and outperforms QuickUMLS/BioNER.  
3. Perform prompt sensitivity analysis: compare zero‑shot, few‑shot (3 examples), and an open‑ended prompt; validate the reported performance gain from few‑shot.

## Open Questions the Paper Calls Out
- What alternative gold‑standard assessments (e.g., neuropsychological tests, biomarkers) can validate LLM‑extracted phenotypes beyond ICD codes?  
- Which specific phenotypic features or combinations can effectively distinguish MCI from ADRD, given the weak statistical discrimination observed?  
- Why do LLM‑extracted features yield low unsupervised clustering performance, and how can feature representation be improved (e.g., continuous embeddings, alternative clustering algorithms)?  
- How does LLM‑MINE generalize to diverse clinical settings with varying documentation styles, and what factors influence its robustness?

## Limitations
- Few‑shot demonstration examples are unreported, risking reproducibility and performance variance.  
- Note‑chunking strategy (e.g., sentence grouping, max chunk size) is underspecified, potentially affecting extraction completeness.  
- External validity is limited: evaluation uses only MIMIC‑IV discharge summaries; performance on other note types or institutions is unknown.

## Confidence
- **High:** Constrained output improves reliability and enables direct aggregation.  
- **Medium:** Few‑shot prompting significantly boosts accuracy (supported by clustering gains but lacks example specification).  
- **Low:** Chunking at sentence boundaries effectively handles long notes without loss (plausible but untested for cross‑sentence phenotypes).
