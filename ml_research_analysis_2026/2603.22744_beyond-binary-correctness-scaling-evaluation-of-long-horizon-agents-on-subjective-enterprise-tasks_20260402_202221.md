# Beyond Binary Correctness: Scaling Evaluation of Long-Horizon Agents on Subjective Enterprise Tasks

## Quick Facts
- arXiv ID: 2603.22744  
- Source URL: https://arxiv.org/abs/2603.22744  
- Reference count: 40  
- Primary result: Introduces LH-Bench, a three-pillar evaluation framework for long-horizon subjective enterprise tasks, showing expert-authored rubrics achieve κ=0.60 inter-judge reliability and agents self-correct 70% of errors via structured verification feedback.

## Executive Summary
The paper addresses the inadequacy of binary correctness metrics for evaluating autonomous agents on long-horizon, subjective enterprise tasks where success depends on organizational context and intermediate artifact quality. It introduces LH-Bench, a comprehensive evaluation framework built on three pillars: (i) expert-grounded rubrics providing domain context to LLM judges, (ii) curated ground-truth artifacts enabling stepwise reward signals, and (iii) pairwise human preferences for convergent validation. The framework is applied to two enterprise environments: Figma-to-code (33 tasks) and programmatic content generation (183 chapters). Key outcomes show that expert-authored rubrics yield substantially higher inter-judge reliability (Cohen’s κ=0.60) compared to LLM-authored rubrics (κ=0.46). Human preference evaluations confirm that the same primary ranking separation is observed (p<0.05). Moreover, the system demonstrates that structured test-time verification feedback enables agents to self-correct from 70% of errors, with recovery strongly tied to error-message quality.

## Method Summary
LH-Bench evaluates agents through a three-pillar design. First, domain experts author process rubrics with binary-observable boundaries aligned to sequential workflow phases (e.g., “token file created before components”); three LLM judges score agent transcripts against these rubrics. Second, curated ground-truth artifacts (e.g., per-frame PNG exports for Figma designs, line-addressable source spans for content) enable automated checkpoint verifiers to produce dense, diagnostic reward signals at intermediate stages. Third, pairwise human preference judgments provide convergent validation of LLM-as-judge rankings. The evaluation harness runs agents (Claude Code, Codex CLI, Gemini CLI) in sandboxed environments with MCP tool servers, integrating runtime verification hooks that return structured error feedback. Agent outputs are compared against ground truth via vision-language models for artifact fidelity, and process rubrics are scored by LLM judges from transcripts. Leaderboards aggregate tier scores with bootstrap confidence intervals.

## Key Results
- Expert-authored rubrics achieve Cohen’s κ=0.60 inter-judge reliability, a substantial improvement over LLM-authored rubrics (κ=0.46).
- Human pairwise preferences confirm the same primary agent ranking as LLM-as-judge scores (p<0.05), validating the use of LLM judges.
- Structured verification feedback allows agents to self-correct 70% of encountered errors, with recovery rates varying by error type (e.g., >85% for syntax/type errors vs. ~17% for configuration errors).

## Why This Works (Mechanism)

1. **Expert-authored rubrics with binary-observable boundaries**: Domain experts define sequential workflow phases (e.g., “token file created before components”) with concrete, transcript-verifiable thresholds. This eliminates subjective interpretation of generic criteria, forcing judges to anchor scores to specific, observable actions. Evidence: Inter-judge Cohen’s κ improves from 0.46 (LLM-authored) to 0.60 (expert-authored). Break condition: if the task workflow cannot be decomposed into phases with transcript-verifiable boundaries (e.g., purely aesthetic judgments), expert-authored rubrics may not improve agreement.

2. **Curated ground-truth artifacts enabling stepwise reward signals**: Experts provide deterministic reference artifacts (e.g., per-frame PNGs, line-addressable citations). Automated verifiers compare intermediate agent outputs at defined checkpoints, producing dense, diagnostic scores rather than a single binary outcome. Evidence: The framework includes `manifest.json` and ground-truth assets for both Figma-to-code and programmatic content tasks, enabling fine-grained analysis of failure modes. Break condition: if the task produces no stable intermediate artifacts (e.g., monolithic output), stepwise verification is not feasible.

3. **Runtime verification hooks for self-correction**: The harness integrates post-tool-use hooks (e.g., after `create_app_preview`) that run automated checks and return structured error payloads with diagnoses and suggested repairs, allowing agents to iterate within the same episode. Evidence: Agents recover from 70% of errors; structured feedback (syntax/build) yields >85% recovery vs. 17% for configuration errors. Break condition: if the environment lacks deterministic verification mechanisms (e.g., purely creative tasks), runtime hooks cannot provide actionable feedback.

  Why needed here: LH‑Bench targets tasks requiring dozens of interdependent steps across multiple tools and artifact edits, collapsing under binary, final-state-only metrics.

  Why needed here: Expert rubrics must be scored consistently by different LLM judges; using transcript-verifiable thresholds (e.g., “token file created before components”) reduces subjective interpretation.

## Architecture Onboarding

**Component map**: Task/Rubric Datastore (HuggingFace datasets) → Agent Harness (sandboxed runner with MCP servers) → Verification Layer (post-tool hooks, ground-truth comparisons) → Judging Pipeline (three LLM judges, VLM) → Leaderboard (aggregated scores).

**Critical path**: 1. Load task config and expert `SKILL.md`. 2. Agent executes in sandbox, invoking tools; verification hooks run after key calls. 3. Final artifacts uploaded; screenshots/citations captured. 4. Judges score in parallel; results aggregated to tier scores. 5. Leaderboard ranks harnesses by weighted aggregates.

**Design tradeoffs**:
- Expert authorship cost vs. scalability: Expert rubrics/annotations are expensive initially but enable LLM-as-judge scaling without per-task human eval.
- Rubric granularity: Finer scales (5-point) reduce VLM ties and improve discrimination but require more precise anchor definitions.
- Harness coupling: Current evaluations are model-family-specific; an open-source harness would decouple orchestration from model.

**Failure signatures**:
- Low token extraction score: Agent “prompts-to-pixels” without systematic design inspection.
- High error count but high recovery: Reactive agent encountering many failures but effectively using feedback.
- Low inter-judge κ (<0.5): Rubrics lack binary-observable boundaries or are too generic.

**First 3 experiments**:
1. Reproduce primary results: Run the released Figma-to-code tasks (n=33) with `SKILL.md` across three harnesses; verify Table 3–5 rankings and κ=0.60 agreement.
2. Rubric ablation: Execute the `SKILL.md` ablation (with/without expert workflow) on 3 tasks per harness (as in Table 7) to measure impact on skill scores and deployment success.
3. Recovery analysis: Extract error→recovery pairs from agent transcripts (as in Section 8.7); verify that structured feedback types (syntax/build) have >85% recovery vs. configuration errors (~17%).

## Open Questions the Paper Calls Out

1. What is the effect size and statistical significance of expert-authored SKILL.md workflow guidance on agent performance across a large, diverse task set? The authors note the ablation study (n=7) is underpowered and that “scaling to more tasks per condition is needed for definitive conclusions” (Section 8.5).

2. Does the LH‑Bench three-pillar evaluation reliably distinguish agent capabilities in other enterprise domains (e.g., data analysis, customer support) as it does for the two studied? The framework’s validity might be domain-specific; subjective criteria and verification hooks may not transfer.

3. Can an open-source, model‑agnostic harness replicate the LH‑Bench evaluation results while decoupling orchestration from model family? Current harnesses are tightly coupled to Claude Code, Codex CLI, Gemini CLI, preventing isolation of model effects.

4. Why is design token and style extraction a universal bottleneck, and what specific techniques can significantly improve agents’ ability to extract and centralize design tokens? The paper identifies the symptom but not the underlying causes; no analysis of failure modes or proposed remedies.

## Limitations

- Implementation fidelity: Exact MCP server behavior and verification hook integration are undocumented; reimplementations may deviate.
- Judge model dependence: Results are tied to specific, inaccessible model versions (Gemini 3.1 Pro, Claude Sonnet 4.6, GPT‑5.2); substituting models likely changes scores and agreement.
- Task scope: Framework’s efficacy is validated only on two specific enterprise domains (Figma‑to‑code, programmatic content); generalizability to other subjective long‑horizon tasks is unknown.

## Confidence

- **Mechanism 1 (Expert rubrics improve reliability):** Medium.
- **Mechanism 2 (Ground‑truth artifacts for stepwise signals):** Medium.
- **Mechanism 3 (Structured feedback enables self‑correction):** Medium‑High.
