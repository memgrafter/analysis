# BaseCal: Unsupervised Confidence Calibration via Base Model Signals

## Quick Facts
- **arXiv ID:** 2601.03042
- **Source URL:** https://arxiv.org/abs/2601.03042
- **Reference count:** 27
- **Primary result:** BaseCal reduces Expected Calibration Error (ECE) by an average of 42.90% (ReEval) and 35.32% (Proj) versus best unsupervised baselines across 5 QA datasets and 3 LLM families, achieving top-two unsupervised performance in 29/30 metric settings.

## Executive Summary
Post-trained large language models (PoLLMs) often exhibit severe overconfidence, undermining trust in their outputs. This work identifies that their corresponding base pre-trained LLMs frequently remain well-calibrated. Motivated by this, the authors propose BaseCal, an unsupervised, plug-and-play framework for calibrating PoLLMs by leveraging their base counterparts. BaseCal offers two variants: **BaseCal-ReEval**, which re-evaluates PoLLM responses through the base LLM to compute confidence from averaged token probabilities, and **BaseCal-Proj**, which learns a lightweight linear projection to map the PoLLM’s final hidden states into the base LLM’s representation space, then uses the base output layer for confidence estimation without extra inference cost. Both methods consistently and substantially improve calibration across diverse models and datasets.

## Method Summary
BaseCal operates in two modes. **BaseCal-ReEval** treats the base LLM as an external verifier: for a given prompt and a PoLLM-generated response, it runs the concatenated sequence through the base model, averages the predicted probabilities of the PoLLM’s own tokens, and uses this as the calibrated confidence. **BaseCal-Proj** is more efficient. It first trains a single linear projection layer in an unsupervised manner using only unlabeled questions. Using paired responses from the base and post-trained models, it extracts final-layer hidden states for each prefix and learns to map the post-trained model’s states to the base model’s states via mean squared error loss. At inference, the trained projection transforms the PoLLM’s hidden states, which are then fed through the frozen base output layer (softmax over logits) to produce token probabilities; the average over the response tokens yields the final confidence. Both variants require no ground-truth labels and leave the PoLLM’s generation process untouched.

## Key Results
- Across 5 QA datasets (TriviaQA, Natural Questions, SQuAD, WebQuestions, MMLU) and 3 model families (Qwen2.5, Llama3.1, Olmo2), BaseCal-ReEval reduced ECE by an average of 42.90% and BaseCal-Proj by 35.32% compared to the best existing unsupervised calibration methods.
- Both variants achieved the top two unsupervised performances in 29 out of 30 metric settings (5 datasets × 3 model families × 2 metrics).
- BaseCal-Proj demonstrated strong out-of-domain generalization, with an average near-zero performance drop (ΔECE ~ +0.0005) between in-domain and out-of-domain test sets, contrasting with supervised temperature scaling which degraded significantly (average ΔECE -0.0886).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Base LLMs intrinsically preserve better confidence calibration than their post-trained counterparts for free-form QA.
- **Mechanism:** Post-training processes (SFT, DPO, RLVR) distort the model’s internal representations, decoupling token probability confidence from actual correctness, while the base pre-trained model’s next-token prediction objective maintains a tighter coupling.
- **Core assumption:** Calibration properties are encoded in final-layer hidden states and output layers; post-training disrupts this encoding more severely than it disrupts base model representations.
- **Evidence anchors:** Abstract observation that base LLMs remain well-calibrated; Figure 2 showing progressively worse overconfidence across Olmo2 checkpoints after SFT/DPO/Instruct tuning.
- **Break condition:** If a base LLM itself is severely miscalibrated on the target distribution, the premise fails.

### Mechanism 2
- **Claim:** A lightweight linear projection can effectively map a PoLLM’s final hidden states into the base LLM’s representation space, allowing the base output layer to compute well-calibrated probabilities.
- **Mechanism:** The projection ϕθ(hp) ≈ hb learns a linear transformation aligning post-trained model states with base model states for identical input contexts. Feeding this aligned state into the base output layer recovers the base model’s token probability distribution.
- **Core assumption:** The mapping from base to post-trained hidden states is approximately linear and learnable with minimal data; the critical calibration information resides in the geometry of the base model’s representation space.
- **Evidence anchors:** Abstract description of BaseCal-Proj; Section 4.3 defining projection training objective; Section 5.4 showing linear projection performs on par with non-linear variants; Section 5.3 OOD generalization success.
- **Break condition:** If the transformation between spaces is highly non-linear or dataset-dependent, a single linear projection will fail to generalize.

### Mechanism 3
- **Claim:** Training the projection in an unsupervised manner on unlabeled questions avoids overfitting to a specific dataset’s correctness distribution, enabling strong out-of-domain generalization.
- **Mechanism:** The loss function optimizes for representational alignment (hp → hb) without requiring ground-truth answers or correctness labels. This decouples the learned transformation from any single dataset’s binary correctness signal.
- **Core assumption:** Model calibration is a property of the representation space and output layer itself, separable from the specific difficulty or answer distribution of a held-out test set.
- **Evidence anchors:** Abstract stating the method is unsupervised; Section A.1.2 noting reliance solely on input questions; Figure 5 & 7 showing near-zero average ΔECE for BaseCal-Proj vs. significant degradation for supervised Temperature Scaling.
- **Break condition:** If calibration depends on dataset-specific decision boundaries rather than representation geometry, unsupervised alignment would not transfer.

## Foundational Learning
- **Confidence Calibration & ECE**  
  - **Why needed:** The entire work measures success by reducing Expected Calibration Error (ECE). Understanding ECE’s definition (bin-wise accuracy-confidence gap) and limitations (binning sensitivity) is essential to interpret results.  
  - **Quick check:** If a model is perfectly calibrated, what is the relationship between the confidence score `q` and the empirical accuracy of all predictions assigned confidence `q`?
- **Transformer Hidden States & Output Layer**  
  - **Why needed:** BaseCal-Proj manipulates final-layer hidden states and feeds them into the base LLM’s output layer. Understanding that the output layer maps a hidden state to a token probability distribution via `softmax` is critical.  
  - **Quick check:** In a standard transformer decoder, what does the final hidden state of the last token represent, and how is it used to generate the next token’s probability?
- **Unsupervised Representation Alignment**  
  - **Why needed:** BaseCal-Proj trains a projection by minimizing the distance between projected PoLLM states and base states without labels. This is akin to instance-level alignment in domain adaptation.  
  - **Quick check:** Why can the projection be trained without knowing whether the PoLLM’s response was *correct*? What specific signal provides the training target?

## Architecture Onboarding
- **Component map:**
  PoLLM (Frozen) -> Projection Module ϕθ (Trainable) -> Base LLM Output Layer (Frozen) -> Confidence Score
  (Note: Base LLM itself is frozen and only its output layer weights are used; no full forward pass at inference for Proj variant.)
- **Critical path:**
  1. **Data Extraction:** For each training question, generate PoLLM response y_p. For every token position t in y_p, run both PoLLM and base LLM on the prefix (x, y_{<t}^p) to extract paired final-layer hidden states (h_p^{t-1}, h_b^{t-1}).
  2. **Projection Training:** Train linear ϕθ to minimize MSE between ϕθ(h_p^{t-1}) and h_b^{t-1} over all pairs. Validate on held-out questions; early stop.
  3. **Inference:** For new prompt x, generate y_p with PoLLM. Extract h_p^{t-1} for each token, compute ϕθ(h_p^{t-1}), apply base output layer (softmax(W_b^o * ...)), average probabilities of tokens in y_p to get confidence c(x, y_p).
- **Design tradeoffs:**
  - **BaseCal-ReEval vs. BaseCal-Proj:** ReEval (full base forward pass) guarantees exact base probability estimation but doubles latency. Proj (projection + output layer) adds ~1% overhead but approximates base probabilities. Tradeoff: approximation error vs. computational savings.
  - **Projection Complexity:** A simple linear layer suffices (Table 2); deeper MLPs give marginal gains but risk overfitting.
  - **Training Data Source:** Uses unlabeled questions. More diverse prompts improve alignment stability; correctness labels are unnecessary.
- **Failure signatures:**
  - **High training loss:** Projection fails to align states. Check: Are both models’ forward passes extracting states correctly? Is the base model the correct counterpart?
  - **No ECE improvement:** Projection misaligned. Check: Visualize PCA of h_p, h_b, and ϕθ(h_p) (Figure 4). Poor overlap indicates failure.
  - **Poor OOD generalization (large negative ΔECE):** Projection overfitted to training prompt distribution. Remedy: Increase training data diversity or use simpler (linear) projection.
  - **Degraded generation quality:** Should not happen; BaseCal-Proj only affects confidence calculation, not token generation.
- **First 3 experiments:**
  1. **Alignment Verification:** On a validation set, compute average MSE between ϕθ(h_p) and h_b. It should be low. Visualize 2D PCA of h_p, h_b, projected states; projected cluster should overlap base cluster.
  2. **Calibration Sanity Check:** Apply BaseCal-Proj to the base LLM itself (base as both PoLLM and base). Resulting ECE should be nearly identical to vanilla base ECE, confirming the pipeline doesn’t break a well-calibrated model.
  3. **Component Ablation:** Compare against (a) using a random projection, (b) training projection but using the **PoLLM’s** output layer instead of base’s. Both should show significantly worse ECE, isolating importance of base output layer and learned alignment.

## Open Questions the Paper Calls Out
1. **What underlying mechanistic or representational changes during post-training cause base LLMs to remain well-calibrated while PoLLMs become systematically overconfident?** The paper provides empirical evidence but no theoretical explanation for this core observation.
2. **Does the BaseCal approach and the observed calibration disparity generalize to specialized architectures beyond decoder-only transformers, such as Mixture-of-Experts (MoE) or reasoning LLMs?** Experiments are limited to standard dense decoder-only models.
3. **How can BaseCal-Proj be adapted for closed-source LLMs (e.g., GPT-4, Claude) where neither the base model nor its output layer parameters are accessible?** BaseCal-Proj requires access to the base LLM’s output layer, limiting applicability to open-weight models.
4. **Why does a simple linear projection suffice to recover base-calibrated confidence?** The success implies the calibration discrepancy might be largely linear in the final-layer hidden space, but the paper does not explore why linearity works.
5. **Does the superior calibration of base LLMs generalize beyond free-form QA to tasks like code generation, mathematical reasoning, or dialogue?** The paper evaluates only QA datasets; calibration properties may be task-dependent.

## Limitations
- Exact projection training hyperparameters (learning rate, batch size, early stopping patience) are not specified, requiring empirical tuning that may affect reproducibility.
- BaseCal assumes the base LLM remains well-calibrated on the target distribution; if the base model is miscalibrated, the method’s advantage diminishes.
- The linear projection’s sufficiency lacks theoretical grounding and may break for certain architecture pairs or training regimes.
- Correctness labels for ECE computation rely on an LLM-as-a-judge, introducing potential noise and bias.

## Confidence
- **High:** Empirical results (average ECE reduction 42.90% for ReEval, 35.32% for Proj; top-two performance in 29/30 settings) demonstrate strong, consistent effectiveness.
- **Medium:** Observation that base LLMs remain better calibrated than post-trained variants is supported by Figure 2 but may not hold universally across all domains or post-training strategies.
- **Low:** The assumption that a lightweight linear projection can universally align hidden spaces lacks theoretical grounding and may fail for some model pairs.

## Next Checks
1. **Hyperparameter Robustness Sweep:** Train BaseCal-Proj with a range of learning rates (e.g., 1e-5, 1e-4, 1e-3) and batch sizes (16, 32, 64) on multiple model families; report mean ECE and standard deviation.
2. **Base Calibration Degradation Test:** Apply temperature scaling to degrade base model calibration by known factors (e.g., scaling factor 0.5, 2.0) and evaluate BaseCal-Proj’s resulting ECE to quantify dependence on base quality.
3. **Projection Capacity Ablation:** Compare linear projection against shallow MLPs (1–3 hidden layers) on alignment task; measure ECE and OOD generalization to test linearity hypothesis and overfitting risk.
