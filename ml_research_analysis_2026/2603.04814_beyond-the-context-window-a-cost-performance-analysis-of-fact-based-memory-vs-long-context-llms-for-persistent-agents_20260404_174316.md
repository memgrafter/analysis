# Beyond the Context Window: A Cost-Performance Analysis of Fact-Based Memory vs. Long-Context LLMs for Persistent Agents

## Quick Facts
- **ArXiv ID:** 2603.04814
- **Source URL:** https://arxiv.org/abs/2603.04814
- **Reference count:** 18
- **Primary result:** Long-context LLMs achieve higher factual recall on complex benchmarks (+33.4 pp on LongMemEval, +35.2 pp on LoCoMo) but at higher cumulative cost; fact-based memory systems become cost-effective after ~10 turns at 100k tokens, saving ~26% by 20 turns.

## Executive Summary
This paper addresses a core architectural choice for persistent conversational AI agents: whether to feed the full conversation history to a long-context large language model (LLM) or to use a fact-based memory system that compresses and retrieves relevant facts. The authors compare Mem0, a fact-based memory pipeline, against long-context inference using GPT-5-mini (and GPT-OSS-120B) across three memory benchmarks: LongMemEval, LoCoMo, and PersonaMem v2. Both accuracy (via LLM-as-a-judge) and cumulative API cost under prompt caching are evaluated.

Results show that long-context models substantially outperform the memory system on complex multi-session reasoning tasks (LongMemEval: +33.4 percentage points; LoCoMo: +35.2 pp), while the memory system remains competitive on persona consistency (PersonaMem v2: 62.48% vs. 69.75%). Cost modeling reveals that the memory system’s per-turn read cost is fixed after an initial one-time write, whereas long-context cost grows linearly with context length even with caching. At a 100k-token context, the memory system becomes cheaper after approximately ten interaction turns, saving about 26% by twenty turns, and the break-even point decreases as context length increases.

## Method Summary
The study implements two architectural approaches: (1) a fact-based memory system (Mem0) that processes the entire conversation history through segmentation, extracts atomic facts using GPT-5-nano, embeds them with text-embedding-3-small, and stores them in a vector database (pgvector) for top-k retrieval per query; (2) a long-context baseline that provides the full conversation history (including timestamps) directly to GPT-5-mini or GPT-OSS-120B at each turn. For each benchmark, both pipelines generate answers that are evaluated for accuracy via a three-vote majority judgment using GPT-5-mini as the judge. Cumulative cost is modeled using OpenAI API prices as of 2025-08-07, accounting for a 90% prompt caching discount on repeated prefix tokens from turn 2 onward. The cost equations are: *C_mem(N) = C_write + N*C_read* for the memory system, and *C_lc(N) = C_first_turn + (N-1)*C_cached_turn* for long-context, where *N* is the number of turns.

## Key Results
- Factual recall: Long-context models outperform Mem0 by large margins on LongMemEval (+33.4 pp) and LoCoMo (+35.2 pp); Mem0 is competitive on PersonaMem v2 (62.48% vs. 69.75%).
- Cost crossover: For a 100k-token context, the memory system becomes cheaper after ~10 turns and saves ~26% by 20 turns.
- Break-even: The turn count at which memory becomes cheaper decreases as context length grows, due to linear scaling of cached long-context cost per turn.

## Why This Works (Mechanism)
The performance gap stems from information loss during the memory system’s fact extraction. The pipeline condenses long dialogues (≈101k tokens) into a compact set of atomic facts (≈2.9k tokens), discarding temporal markers, implicit coreferences, and ephemeral updates. This loss is catastrophic for multi-hop or time-sensitive questions, explaining the large accuracy deficits on LongMemEval and LoCoMo. The long-context approach preserves all original details, enabling complex reasoning.

Economically, the memory system’s cost structure diverges from long-context due to caching dynamics. Even with a 90% discount on cached tokens, each turn of long-context inference incurs a charge proportional to the full context length. The memory system’s read cost, however, depends only on the retrieved facts (≈1k tokens) and is fixed after the initial write phase. Thus, as the number of turns increases, the memory system’s total cost grows slowly, eventually undercutting the long-context approach, especially for longer contexts.

Task type determines which architecture is preferable. Persona consistency relies on stable, discrete facts (e.g., preferences, habits) that flat extraction captures well, hence the smaller accuracy gap on PersonaMem v2. Complex multi-session reasoning over temporal sequences or implicit references benefits from the full-context preservation of long-context models. Therefore, the accuracy-cost trade-off should be guided by the expected query distribution.

## Foundational Learning
- **Prompt caching economics**: Understanding that caching reduces but does not eliminate per-turn cost growth with context length is crucial. Quick check: If a 100k-token history is cached at 90% discount, the per-turn cost still increases linearly with context length because cached tokens are still charged at the discounted rate.
- **Flat fact extraction trade-off**: Converting raw dialogue into atomic facts inevitably discards some information (temporal, implicit, ephemeral), which hurts recall on complex benchmarks. Quick check: Why might a fact like "user started yoga three times a week after their last session" be lost if earlier extraction captured "yoga twice a week"? Because the update and temporal relationship are not captured as atomic facts.
- **Break-even analysis for cumulative cost**: The crossover point where memory becomes cheaper depends on context length and number of turns. Quick check: If context length doubles from 100k to 200k tokens, the break-even point decreases because cached long-context cost per turn increases, while memory read cost remains stable.

## Architecture Onboarding
**Component map:**  
Memory system: Segmentation -> Fact Extraction (GPT-5-nano) -> Embedding (text-embedding-3-small) -> Vector storage (pgvector) -> Top-k retrieval -> Answer (GPT-5-mini).  
Long-context: Raw conversation history (with timestamps) -> Answer (GPT-5-mini/OSS-120B).

**Critical path:**  
1. Memory: Write phase (one-time) processes full history via segmentation and extraction; subsequent read phase retrieves ~top-20 facts per query and generates answer.  
2. Long-context: Every turn re-sends full history (cached from turn 2 onward) to the model.

**Design tradeoffs:**  
- Memory: High upfront write cost, low per-turn read cost; accuracy loss on complex recall tasks.  
- Long-context: Lower initial cost, higher cumulative cost; higher accuracy on complex benchmarks but potential lost-in-the-middle degradation.

**Failure signatures:**  
- Memory: Incorrect answers on questions requiring temporal ordering, coreference resolution, or updates to earlier facts.  
- Long-context: Cost overruns on long-running threads; accuracy degradation if relevant facts fall outside effective context window.

**First 3 experiments:**  
1. Replicate accuracy on LongMemEval using provided prompts/models to verify the ~33 pp gap.  
2. Measure write vs. read cost breakdown on a sample conversation to confirm fixed read cost after extraction.  
3. Vary context length (30k, 100k, 200k tokens) and plot cumulative cost vs. turns to reproduce break-even curve.

## Open Questions the Paper Calls Out
1. How do richer memory architectures (e.g., temporal semantic memory, hierarchical engram-based systems) compare to flat-typed fact extraction in factual recall accuracy and cumulative cost?
2. What is the impact of incremental memory updates during active sessions on the accuracy-cost trade-off?
3. How do memory-based systems and long-context LLMs perform on tasks requiring real-time knowledge, structured-data reasoning, or compositional multi-document inference?
4. Does the LLM-as-a-judge evaluation framework introduce biases that skew accuracy comparisons?
5. How does variation in prompt caching hit rates affect the break-even point in real deployments?

## Limitations
- API pricing and cache hit dynamics may diverge from the assumed 90% discount and stable prefix.
- LLM-as-a-judge may systematically favor GPT-5-mini outputs, inflating relative accuracy.
- Fact extraction loss generalizability beyond provided benchmarks is untested.

## Confidence
- Accuracy deficit (memory vs. long-context): Medium (strong on benchmarks but depends on judge model).
- Cost crossover point: Medium (equations sound but rely on idealized caching and pricing).
- Task alignment (persona vs. complex): Medium (benchmark patterns support it, but real query distributions may differ).

## Next Checks
1. Measure actual cache hit rates during long-context inference with controlled inter-turn delays to validate the 90% assumption.
2. Re-evaluate a subset of answers using a different judge model (e.g., Claude) or human annotators to quantify judge bias.
3. Perform retrieval failure analysis by inspecting top-20 facts for failed LongMemEval queries to confirm loss of temporal/coreferential information.
