# Cross-Domain Offline Policy Adaptation via Selective Transition Correction

## Quick Facts
- arXiv ID: 2602.05776  
- Source URL: https://arxiv.org/abs/2602.05776  
- Reference count: 40  
- Primary result: With only 5000 target transitions, STC achieves a total normalized score of 1045.2 across 24 MuJoCo tasks, beating OTDF (818.1) by 27% and IQL (677.6) by 54%.

## Executive Summary
Cross-domain offline reinforcement learning (RL) seeks to reuse a large source dataset to improve policy learning in a target domain whose dynamics differ. Naively merging source and target data often degrades performance due to distribution shift. This paper introduces Selective Transition Correction (STC), which adapts source transitions to align with target dynamics using target-domain models: an inverse policy predicts target-consistent actions, a reward model adjusts rewards via Taylor expansion, and a forward dynamics model selectively retains only those corrections that better match the target dynamics. Evaluated on MuJoCo benchmarks with gravity, friction, and morphology shifts, STC attains a total normalized score of 1045.2 across 24 tasks using only 5000 target transitions, substantially outperforming strong baselines. The method also shows robustness to the quality and size of the target dataset.

## Method Summary
STC consists of two phases. First, three models are trained exclusively on the limited target dataset: an inverse policy `f_inv(s,s') → â` (predicting the action from a state transition), a forward dynamics model `f_fwd(s,a) → Δs` (predicting the next-state change), and a reward model `r(s,a) → r̂` (estimating the reward). In the second phase, each source transition `(s,a,r,s')` is processed: the inverse policy generates a corrected action `â`; the reward is adjusted as `ŕ = r + α * (∇_a r(s,a) · (â - a))` with a normalized gradient. The forward model computes prediction errors for the original action (`ε_orig = ||f_fwd(s,a) - (s'-s)||`) and the corrected action (`ε_corr = ||f_fwd(s,â) - (s'-s)||`). The corrected transition is kept only if `ε_corr < λ * ε_orig`; otherwise the original is retained. The selectively corrected source data is merged with the target data, and a policy is trained using Implicit Q-Learning (IQL) with Q‑weighted behavioral regularization, which mitigates overfitting to out‑of‑distribution actions. This pipeline effectively reuses large source datasets while ensuring compatibility with the target dynamics.

## Key Results
- STC obtains a total normalized score of **1045.2** across 24 MuJoCo tasks, beating OTDF (818.1) by 27% and IQL (677.6) by 54%.
- The method requires only **5000 target transitions**, demonstrating high sample efficiency.
- STC exhibits **robustness** to variations in target data quality and size.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Correcting source domain actions and rewards using target‑domain models reduces dynamics mismatch without discarding data.  
- **Mechanism:** An inverse policy model `f_inv(s,s')` predicts target‑consistent actions for source state transitions `(s_src, s'_src)`. The reward is adjusted via first‑order Taylor expansion using a reward model `r(s,a)` and the action change.  
- **Core assumption:** The inverse policy trained on limited target data can generalize to source state pairs despite potential out‑of‑distribution inputs.  
- **Evidence anchors:**  
  - [abstract] “modifies source transitions to align with target dynamics: an inverse policy model predicts target‑consistent actions, a reward model adjusts rewards”  
  - [section 4.1] “We utilize the inverse policy model to replace the original source actions with ones that are more consistent with target dynamics.”  
  - [corpus] Weak/absent direct evidence; neighboring papers (e.g., IGDF, OTDF) also use target models for filtering, not correction.  
- **Break condition:** When the inverse policy’s action predictions are inaccurate for source transitions, corrections may worsen dynamics alignment (Section 4.3).

### Mechanism 2
- **Claim:** Selective retention of corrected transitions via forward dynamics validation prevents error amplification from inaccurate model corrections.  
- **Mechanism:** A forward dynamics model `f_fwd(s,a)` computes the prediction error (dynamics discrepancy) for both original and corrected source transitions. Only corrections that reduce this error below a threshold `λ * ε_orig` are kept.  
- **Core assumption:** The forward model’s error serves as a reliable proxy for alignment with target dynamics, even when trained on limited target data.  
- **Evidence anchors:**  
  - [abstract] “a forward dynamics model selectively retains corrections that better match target dynamics”  
  - [section 4.3] “Quantify the dynamic discrepancy… use it as a metric to decide whether the inverse policy model can be reliable… The corrected transition is adopted only if its dynamics discrepancy is substantially smaller.”  
  - [section 5.4] Figure 2 shows corrected action distributions align better with target.  
- **Break condition:** If both forward and inverse models are biased (e.g., due to limited target data), their mutual error‑checking may reject valid corrections or accept invalid ones (Section 4.3).

### Mechanism 3
- **Claim:** Q‑weighted behavioral regularization enables safe policy learning from the merged, corrected dataset by prioritizing high‑value transitions while avoiding out‑of‑distribution actions.  
- **Mechanism:** The policy `π_φ(s)` is optimized with a loss combining Q‑value maximization and a behavior cloning term weighted by `ηQ_θ(s,A)` from the target domain dataset.  
- **Core assumption:** The Q‑function implicitly learned on the mixed dataset accurately reflects values in the target domain, and the behavioral prior prevents exploitation of spurious correlations from corrected source data.  
- **Evidence anchors:**  
  - [section 4.4] “regularize the policy learning with the Q‑value‑weighted behavior cloning… akin to IQL”  
  - [section 5.1] STC outperforms IQL (which uses the same loss but on naively merged data), demonstrating the benefit of corrected data.  
  - [corpus] IQL (Kostrikov et al., 2022) establishes this regularization as effective for offline RL.  
- **Break condition:** When the Q‑function is poorly estimated due to distribution shift, the weighted cloning may overfit to low‑quality or misaligned source samples.

## Foundational Learning

### Inverse Reinforcement Learning (IRL) / Inverse Dynamics Modeling
- **Why needed:** The inverse policy model `f_inv(s,s')` is the core mechanism for generating target‑consistent actions from source state transitions without explicit reward or dynamics access.  
- **Quick check:** Given a target dataset `D_tar = {(s, a, s')}`, what objective would you use to train `f_inv(s,s')` to approximate the inverse of the target dynamics? (Answer: Mean squared error between predicted action `f_inv(s,s')` and observed action `a` from `D_tar`, as in Equation 1.)

### Dynamics‑Aware Data Selection / Filtering
- **Why needed:** STC’s selective correction is a form of dynamics‑aware filtering that accepts/rejects corrected transitions based on forward model consistency (`ε_corr` vs. `ε_orig`). This builds on the principle of using learned dynamics to estimate distribution shift.  
- **Quick check:** In STC, a corrected source transition `(s, â, s', ŕ)` is kept only if `ε_corr < λ * ε_orig`. What risk does each error term represent if the forward model is imperfect? (Answer: `ε_orig` estimates incompatibility of original source action with target dynamics; `ε_corr` estimates incompatibility of corrected action.)

### Conservative Offline RL via Implicit Regularization
- **Why needed:** The final policy learning uses IQL’s Q‑weighted behavioral regularization to avoid exploiting OOD actions from the merged/corrected dataset. This is critical because source data correction may still produce imperfect state‑action pairs.  
- **Quick check:** In IQL’s loss `L_π = -E[ηQ(s,π(s)) - β exp(ηQ(s,a))||π(s)-a||²]`, what is the role of the second term? (Answer: It is a form of behavior cloning weighted by the exponential of Q‑values, acting as a “soft” constraint to keep the policy close to the data, especially in low‑uncertainty regions.)

## Architecture Onboarding

### Component map
Source transitions → [Inverse Policy (`f_inv`) → corrected action] + [Reward Model (`r`) + gradient → adjusted reward] → Candidate corrected transitions → [Forward Dynamics (`f_fwd`) → `ε_orig`, `ε_corr`] → Selection (`ε_corr < λ ε_orig`) → Filtered corrected source data → Merge with target data → IQL training (`Q_θ`, `π_φ`).

### Critical path
1. Train `f_inv`, `f_fwd`, `r` on `D_tar` (offline, no source data).  
2. For each batch from `D_src`:  
   a. Compute corrected action `â = f_inv(s,s')`.  
   b. Compute corrected reward `ŕ = r + α * (∇_a r(s,a) · (â - a))` with normalized gradient.  
   c. Compute discrepancies: `ε_orig = ||f_fwd(s,a) - (s'-s)||`, `ε_corr = ||f_fwd(s,â) - (s'-s)||`.  
   d. Keep corrected transition only if `ε_corr < λ * ε_orig`; else keep original.  
   e. Construct corrected batch `e b_src` and merge with batch from `D_tar`.  
3. Update critic `Q_θ` (TD loss) and actor `π_φ` (Q‑weighted BC + regularization).

### Design tradeoffs
- **Model accuracy vs. conservatism:** Tighter `λ` (e.g., 1.0) enforces higher alignment but reduces data coverage; looser `λ` (e.g., 5.0) uses more data but risks bad corrections.  
- **Reward adjustment magnitude:** `α` scales Taylor‑based reward change. Larger `α` amplifies sensitivity to action change but risks instability; `α=0.5` found robust.  
- **Computational cost:** Three additional models (`f_inv`, `f_fwd`, `r`) add pre‑training and per‑iteration inference overhead, but enable more effective source data usage than filtering‑only methods.

### Failure signatures
- **Inverse model failure:** Corrected actions have drastically different distributions from target (e.g., KDE of action norms diverges).  
- **Forward model failure:** `ε_orig` and `ε_corr` are similarly high for many samples → selection becomes noisy or arbitrary.  
- **Policy collapse:** If the IQL behavioral coefficient `β` is too low, policy overfits to erroneous corrected transitions; if too high, it underfits (ignores corrected data).

### First 3 experiments
1. **Train inverse & forward dynamics:** Verify `f_inv` and `f_fwd` achieve low MSE on a held‑out set from `D_tar`.  
2. **Visualize correction impact:** For sampled source transitions, plot original vs. corrected actions against the target action distribution (as in Figure 2) to check if the correction moves actions toward the target.  
3. **Ablation over `λ`:** Run STC with `λ` in `{0 (no selection), 1.0, 5.0, 10.0}`. If `λ=0` hurts performance, selection is necessary; if a sweet spot exists, it validates the selective criterion.

## Open Questions the Paper Calls Out
- Can the theoretical analysis be extended by relaxing strong assumptions (e.g., bounded dynamics discrepancy, accurate inverse policy) to provide more realistic performance guarantees?  
- How can the selective correction threshold `λ` be determined automatically across tasks without manual tuning, while balancing correction reliability and data retention?  
- Can STC be extended to handle cross‑domain scenarios where the reward function differs between source and target domains, beyond the current assumption of identical rewards?

## Limitations
- STC depends on accurate inverse, forward, and reward models trained on limited target data; model errors may propagate.  
- Core assumptions (e.g., inverse policy generalizes to source states, bounded dynamics gap) are strong and not directly validated empirically.  
- Evaluation is restricted to MuJoCo environments; generalizability to other domains (e.g., image‑based, robotic) remains unknown.

## Confidence
- Performance claim (STC outperforms baselines): **High**  
- Mechanism claim (selective correction aligns dynamics): **Medium**  
- Robustness claim (to target data quality/size): **Medium**  
- Generalizability claim: **Low**

## Next Checks
