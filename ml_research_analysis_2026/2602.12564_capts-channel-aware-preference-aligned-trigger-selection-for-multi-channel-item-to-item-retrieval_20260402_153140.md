# CAPTS: Channel-Aware, Preference-Aligned Trigger Selection for Multi-Channel Item-to-Item Retrieval

## Quick Facts
- **arXiv ID:** 2602.12564
- **Source URL:** https://arxiv.org/abs/2602.12564
- **Reference Count:** 30
- **Primary Result:** Improves multi-channel recall by 10.7% at R@2000 over the strongest baseline and delivers significant lifts in online engagement metrics, including +0.351% average time spent per device and +0.098% DAU.

## Executive Summary
CAPTS is a system designed to improve the selection of "trigger" user interactions (e.g., video watches) that seed multiple downstream Item-to-Item (I2I) retrieval channels. It addresses two key problems: biased value attribution, where triggers are judged by their own immediate feedback rather than the utility of items they retrieve, and uncoordinated routing, where channels independently select triggers causing redundant candidate pools. The solution combines a Value Attribution Module (V AM) that provides look-ahead supervision by crediting triggers with downstream engagement, and a Channel-Adaptive Trigger Routing (CATR) module that coordinates assignments across channels while optimizing for both per-channel value and cross-channel diversity. Evaluated on Kwai's short-video platform, CAPTS shows substantial offline recall gains and confirms effectiveness in large-scale online A/B tests.

## Method Summary
CAPTS operates in two offline-trained stages. First, the Value Attribution Module (V AM) constructs training labels by replaying historical I2I retrievals. For a given request time τ0, it simulates retrieval for each candidate trigger `t` on each channel `c`, then aggregates watch time on items from that retrieval set that a user consumes within a defined future window `w_s`. This produces a channel-specific, intensity-aware value signal `ℓ_c(t, τ0)` and a binary utility label `y_c(t, τ0)`. Second, the Channel-Adaptive Trigger Routing (CATR) model scores each trigger-channel pair. It uses a shared encoder to produce a trigger-aware representation, then per-channel heads predict a base value `ṽ_c(t)`, a uniqueness ratio `ρ̂_c(t)`, and a channel-specific calibration term. The final routing score `s^r_c(t) = v̂_c(t) + η ρ̂_c(t)` balances calibrated value with a diversity bonus. CATR is trained on V AM labels with a combined loss: binary cross-entropy for value, a calibration loss for intensity, and a diversity loss that encourages triggers to produce unique retrieved sets across channels. At inference, the top-`B_c` triggers per channel are selected by routing score.

## Key Results
- Offline multi-channel Recall@2000 improved by 10.7% over the strongest baseline.
- Online A/B test showed a +0.351% lift in average time spent per device and +0.098% increase in daily active users.
- Consistent gains were observed in channel exposure share and user engagement rates (e.g., effective-view, long-view) across all four I2I channels.

## Why This Works (Mechanism)

### Mechanism 1: Look-Ahead Value Attribution
CAPTS mitigates biased value attribution by aligning a trigger's supervised value with the downstream engagement it generates, rather than its own immediate feedback (e.g., likes). The Value Attribution Module (V AM) performs an offline replay of the I2I retrieval system for each candidate trigger at a historical request time. It then matches the retrieved items to a future consumption window and aggregates engagement (watch time) on those matched items. This creates channel-specific labels (`y_c(t, τ0)`) and intensity signals (`ℓ_c(t, τ0)`) that credit a trigger based on its ability to seed engaging content. The core assumption is that a trigger's true value is best estimated by the engagement it induces on subsequently retrieved items. A break condition occurs if the future window `w_s` is poorly chosen or if the retrieval state at replay time significantly drifts from the snapshot, making the supervision signal noisy.

### Mechanism 2: Coordinated Routing with Uniqueness
The Channel-Adaptive Trigger Routing (CATR) module reduces uncoordinated multi-channel routing and cross-channel redundancy. It learns channel-adaptive value predictions via a shared encoder with channel-specific heads. Crucially, it also predicts a uniqueness ratio `ρ̂_c(t)` for each trigger-channel pair, which estimates the fraction of items retrieved from that trigger that are unique compared to other channels. The final routing score `s^r_c(t) = v̂_c(t) + η ρ̂_c(t)` combines calibrated per-channel utility with a diversity bonus. The uniqueness head is supervised by the historical uniqueness ratio `ρ_c(t, τ0)` computed from the replay, and a diversity loss (`ℒdiv`) encourages this uniqueness during training. The core assumption is that channels sharing a trigger quota benefit from coordinated assignment that minimizes overlap in the final merged candidate pool, increasing overall coverage. A break condition is an improperly tuned uniqueness threshold `θ` or trade-off `η`, which could over-prioritize diversity at the expense of high-value triggers.

### Mechanism 3: Channel-Specific Value Calibration
CATR includes a small channel-specific calibrator network that makes bounded corrections to the base value prediction. This stabilizes learning from the heavy-tailed, channel-specific intensity signals (`ℓ_c(t, τ0)`) produced by V AM. The calibrator adds a `β tanh(...)` term to the sigmoid output of the base value head, then clips the result. It is trained with a calibration loss (`ℒcal`) that uses the normalized intensity as a target, reweighted to focus on high-intensity samples. The core assumption is that directly training the main value head with continuous intensity can destabilize the primary binary utility objective; the calibrator provides a separate, stable pathway for this signal. A break condition is a significant shift in intensity distribution or over-regularization via the loss weight `λ`, which could lead to poor calibration or under-fitting.

## Foundational Learning
- **Concept: Look-ahead Supervision**
  - **Why needed:** Traditional trigger selection uses immediate feedback on the trigger (e.g., clicks), which is a biased proxy for downstream utility. Look-ahead supervision via replay and future-window engagement aligns training with the true goal: retrieving items that lead to future consumption.
  - **Quick check:** If you only had clicks on the trigger item for training, what specific failure mode might occur when triggers are used for I2I retrieval?
- **Concept: Trigger-to-Channel Routing as a Combinatorial Assignment**
  - **Why needed:** Each request has a shared pool of candidate triggers and per-channel budgets. The system must decide which triggers go to which channels, considering both per-channel value and cross-channel redundancy. This is a constrained assignment problem, not independent per-channel scoring.
  - **Quick check:** Why would optimizing each channel's trigger selection independently (without coordination) likely increase overlap in the final candidate set?
- **Concept: Diversity Regularization via Uniqueness Supervision**
  - **Why needed:** To prevent channels from converging on similar triggers, CATR explicitly measures and rewards triggers that produce unique retrieved items per channel. This is operationalized by comparing replayed retrieval sets.
  - **Quick check:** How is "uniqueness" defined for a trigger in a specific channel in CAPTS? What data is needed to compute it?

## Architecture Onboarding
- **Component map:**
  1. Log Ingestion & Storage -> 2. V AM Labeling Service (offline batch) -> 3. Feature Join & Dataset Construction -> 4. CATR Model Training -> 5. Model Sync to Online Service -> 6. Online Serving (per-request scoring & routing) -> 7. I2I Retrieval Channels.
  A parallel Nearline Cache (extended history scoring) feeds into Online Serving.
- **Critical path:** Raw interaction logs and retrieval snapshots are ingested. The V AM labeling service replays retrievals to generate utility and uniqueness labels. These are joined with request features to train CATR. The trained model is synced online, where per-request it scores candidate triggers (from recent history and nearline cache), applies routing scores to select per-channel trigger sets, and feeds them to the I2I retrievers.
- **Design tradeoffs:**
  - **Replay fidelity vs. cost:** V AM requires timestamp-aligned I2I replay, which is computationally heavy. The system uses a conservative rollback (~20 minutes) and limits replay depth (top-50 per trigger) to manage cost.
  - **Latency vs. coverage:** Trigger supply is split into an online small set (recent interactions, low latency) and a nearline large set (longer history, pre-scored and cached) to balance real-time constraints with long-term interest coverage.
  - **Calibrator complexity:** Adding a per-channel calibrator network increases model size and training complexity but stabilizes learning from continuous intensity signals.
- **Failure signatures:**
  - High cross-channel overlap in final retrieved sets (check `Uniq@K` metrics), indicating routing diversity failure.
  - Per-channel recall drops in isolation (especially on channels like MMU that benefited most), suggesting V AM supervision degradation or routing value misestimation.
  - Online engagement metrics (e.g., time spent per device) not improving or declining despite offline recall gains, pointing to an offline-online metric gap or negative downstream ranking effects.
- **First 3 experiments:**
  1. **Ablation: Remove V AM, use trigger's direct watch time instead.** Verify offline multi-channel recall drop, confirming the need for look-ahead attribution.
  2. **Ablation: Remove CATR diversity objective (`μ=0`).** Measure change in cross-channel `Uniq@K` and overall merged Recall@2000 to isolate coordination impact.
  3. **Sensitivity: Vary future window `w_s`.** Evaluate Recall@K on each channel (Swing, Marm, MMU) to find the window that balances supervision stability and temporal relevance.

## Open Questions the Paper Calls Out
- **Question 1:** Does CAPTS outperform strong industrial trigger selection baselines in overall multi-channel recall?
  - **Basis:** Section 4.1 explicitly lists RQ1 and presents offline experiments on Kwai's platform.
  - **Why unresolved:** Effectiveness across other domains (e.g., e-commerce, news) or with heterogeneous channel sets remains unproven.
  - **Resolving evidence:** Evaluations on multiple datasets from diverse recommendation domains using consistent channel configurations.
- **Question 2:** How much does VAM improve per-channel recall, and how sensitive is it to the future window size?
  - **Basis:** Section 4.2 addresses RQ2 via per-channel evaluations and sensitivity analysis of the future window size.
  - **Why unresolved:** The optimal window size varies across channels (e.g., MMU benefits from larger windows), and a fixed window may not adapt to user-, item-, or channel-specific dynamics.
  - **Resolving evidence:** Investigating adaptive window sizing strategies (e.g., per-channel or per-user) and their impact on recall stability and training efficiency.
- **Question 3:** Can CATR increase cross-channel diversity and complementarity without degrading overall recall?
  - **Basis:** Section 4.3 examines RQ3 by measuring uniqueness and performing routing ablations.
  - **Why unresolved:** The diversity objective uses a fixed threshold θ and trade-off parameter η; the paper does not explore automated tuning or alternative diversity metrics (e.g., topic coverage), leaving the robustness of the diversity-recall trade-off open.
  - **Resolving evidence:** Systematic sensitivity analysis of η and θ, and evaluations with multiple diversity metrics to understand the Pareto frontier.
- **Question 4:** Do the offline gains of CAPTS translate into lifts on key business metrics in large-scale online A/B tests?
  - **Basis:** Section 4.4 reports RQ4 results from online A/B tests on Kwai.
  - **Why unresolved:** The A/B test duration and scope are not detailed; long-term effects (e.g., user retention, ecosystem health) and potential negative impacts are unexplored.
  - **Resolving evidence:** Long-term A/B tests with extended durations, monitoring a broader set of metrics (e.g., churn rate, content diversity), and user satisfaction surveys.

## Limitations
- Exact V AM hyperparameters (scaling `s_c`, clip `M_c`, threshold `γ_c`), uniqueness threshold `θ`, and channel budgets `B_c` are undisclosed, requiring empirical tuning for reproduction.
- Precise architecture details (encoder size, feature engineering) and I2I channel definitions/snapshot policies (rollback `δ`) are proprietary, hindering exact replay.
- The paper's evaluation is confined to a single short-video platform; generalizability to other domains and channel configurations is unverified.

## Confidence
- **Look-ahead value attribution:** Medium. Mechanism is plausible and supported by ablations, but highly sensitive to replay fidelity and future window choice.
- **Channel-adaptive routing with uniqueness:** Medium-High. Strong offline evidence (Uniq@K gains) and online lift; uniqueness signal depends on replay stability.
- **Calibrator stabilization:** Medium. Removing calibrator hurts recall, but architectural details are sparse, and sensitivity to hyperparameters `λ` and `β` is unclear.

## Next Checks
1. **Replay fidelity audit:** For a random sample of requests, compare I2I retrieval sets `R_c(t, τ0)` from replay against actual online retrievals at `τ0` (from logs). Measure mismatch rate; >1% suggests labeling leakage.
2. **Diversity ablation replication:** Train CATR without `L_div` (`μ=0`) on the same data. Expect: (a) multi-channel Recall@2000 drop ≥10% relative, (b) `Uniq@K` decrease >5% points, (c) per-channel recall may increase at small K but overall declines at larger K.
3. **Parameter robustness sweep:** Vary future window `w_s` (50, 100, 200 effective views) and uniqueness threshold `θ` (0.5–0.9). Plot overall Recall@2000 and per-channel engagement. Identify stable region; if best `w_s` differs markedly from paper (~100), results may be dataset-specific.
