# KP-Agent: Keyword Pruning in Sponsored Search Advertising via LLM-Powered Contextual Bandits
## Quick Facts
*   **arXiv ID:** 2601.05257
*   **Source URL:** https://arxiv.org/abs/2601.05257
*   **Reference Count:** 26
*   **Primary Result:** An LLM-powered contextual bandit system improves cumulative profit by up to 49.28% compared to heuristic baselines on a real-world dataset.

## Executive Summary
This paper tackles the under-explored problem of keyword pruning in sponsored search advertising, where low-value keywords consume fixed budgets and displace high-value ones. The authors propose KP-Agent, an agentic system that frames pruning as a contextual bandit decision. It employs a domain-specific toolset to accurately retrieve and process tabular KPI data, preventing LLM hallucination, and incorporates a memory module for few-shot learning with reflective feedback. Evaluated on a 0.5 million-record dataset from Meituan, KP-Agent demonstrates significant profit gains over common heuristic pruning strategies.

## Method Summary
KP-Agent models the keyword pruning decision as a contextual bandit problem. For each candidate keyword, the system's LLM-based agent observes a context (features like historical KPIs) and selects an action (prune or retain). To ground its decisions in accurate numerical data, the agent uses a predefined toolset to query and compute from the underlying KPI tables. A memory module stores past state-action-reward tuples and retrieves similar historical cases for few-shot prompting, enabling the agent to learn from reflective feedback over time.

## Key Results
*   Addresses a critical industry gap: optimizing keyword portfolios under fixed budgets by removing low-value keywords.
*   Proposes a novel LLM-agent architecture with tool augmentation and memory to solve a sequential decision-making problem.
*   Achieves up to a 49.28% improvement in cumulative profit versus baseline heuristics (impression-rank, CTR-rank) on a large-scale, real-world advertising dataset.

## Why This Works (Mechanism)
The system succeeds by combining the high-level reasoning of an LLM with mechanisms that enforce accuracy and learning. The **domain-specific toolset** is critical; it offloads all numerical retrieval and calculation from the LLM to deterministic functions, eliminating hallucination risks with tabular KPI data. The **memory module** enables few-shot learning by retrieving analogous past pruning decisions and their outcomes, providing the agent with concrete examples of successful strategies and allowing for reflective adjustment. Together, these components allow the LLM to focus on strategic pattern recognition within the contextual bandit framework, balancing the exploration of new pruning actions with the exploitation of known profitable ones.

*   **Contextual Bandits:** Why needed? Formalizes the prune/retain decision as a sequential trade-off between immediate reward and long-term profit under budget constraints. *Quick check:* Can you define the exploration-exploitation dilemma in this setting?
*   **LLM Agents & Tool Use:** Why needed? Leverages the LLM's reasoning for complex state interpretation while using tools as "oracles" to guarantee factual accuracy for numeric KPIs. *Quick check:* How would you design a tool to safely return a keyword's 7-day average CTR?
*   **Memory-Augmented Learning:** Why needed? Overcomes the limitations of a single prompt by providing a dynamic, experience-based knowledge base for few-shot learning. *Quick check:* What information would you store in a memory tuple for a pruning decision (state, action, reward)?
*   **Sponsored Search Auctions:** Why needed? The problem exists within a second-price auction ecosystem where budget allocation directly impacts overall profit. *Quick check:* How does pruning a low-CTR keyword affect the auction dynamics for remaining keywords?
*   **Reflective Feedback Loops:** Why needed? Allows the system to analyze past decisions (e.g., "Did pruning this keyword lead to budget reallocation?") and improve future strategy. *Quick check:* What metric would trigger a "reflection" on a past pruning decision?

## Architecture Onboarding
*   **Component Map:** User Query (Keyword Context) -> LLM Agent -> [Toolset: KPI_Data_Retriever, Profit_Calculator] -> [Memory: Reflection_Buffer] -> Pruning Decision (Action)
*   **Critical Path:** The agent receives a new keyword's context. It first uses the `KPI_Data_Retriever` tool to fetch precise historical performance metrics. It then queries the `Memory` module for similar past cases. With this grounded data and exemplars, the agent reasons and outputs a prune/retain decision. The outcome (resulting profit change) is later stored in memory with a reflective summary.
*   **Design Tradeoffs:** Using an LLM provides flexibility and reasoning but introduces latency and cost; the toolset sacrifices some end-to-end learning for guaranteed accuracy. The memory module improves adaptivity but requires storage and a robust retrieval mechanism. The design prioritizes correctness (via tools) and continual improvement (via memory) over pure model simplicity.
*   **Failure Signatures:** 1) Agent consistently ignores tool outputs and hallucinates KPIs. 2) Memory retrieval returns irrelevant cases, leading to stale or poor decisions. 3) The system fails to adapt to a sudden market shift (e.g., a new competitor) because memory contains only pre-shift patterns.
*   **First 3 Experiments:**
    1.  **Tool Validation:** Measure the accuracy of the `KPI_Data_Retriever` tool against ground-truth SQL queries on a held-out data slice.
    2.  **Memory Ablation:** Run KP-Agent with the memory module disabled to quantify the performance delta from few-shot reflective learning.
    3.  **Baseline Stress Test:** Implement a simple rule-based heuristic (e.g., "prune if CTR < 2%") and compare its profit and robustness against KP-Agent on a dataset subset with introduced noise.

## Limitations
*   Evaluation is confined to a single commercial dataset from Meituan, raising concerns about generalizability to other platforms or market dynamics.
*   Baselines are limited to simple heuristic rankers (impression, CTR); the work does not compare against state-of-the-art non-LLM contextual bandit algorithms (e.g., LinUCB, Thompson Sampling).
*   The reported "up to 49.28%" gain is a peak result; average or median improvements and statistical significance tests are not provided.

## Next Checks
1.  **Cross-Dataset Replication:** Re-run KP-Agent on at least two additional sponsored search datasets from different platforms/e-commerce sectors (e.g., a public ad dataset or a partner's log) to test generalizability of the 49% gain claim.
2.  **Baseline Expansion:** Compare KP-Agent against state-of-the-art non-LLM contextual bandit algorithms (e.g., Bootstrapped UCB, Neural Thompson Sampling) using the same feature set. This isolates the value-add of the LLM agent versus the bandit framework itself.
3.  **Ablation Study:** Perform a systematic ablation on the Meituan dataset, removing the memory module, the reflective feedback loop, and the domain-specific toolset in isolation. Quantify the individual contribution of each component to the cumulative profit gain.
