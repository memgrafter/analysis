# Methods for Knowledge Graph Construction from Text Collections: Development and Applications
## Quick Facts
- **arXiv ID:** 2603.25862
- **Source URL:** https://arxiv.org/abs/2603.25862
- **Reference count:** 0
- **Primary result:** Scalable, flexible knowledge graph construction from unstructured text is achieved via domain-tailored pipelines combining NLP/ML (open IE, LLMs, topic modeling) with Semantic Web practices, yielding high-precision graphs and publicly released resources across three application domains.

## Executive Summary
This thesis presents a framework for constructing knowledge graphs (KGs) from large, unstructured text collections, addressing challenges of scalability, domain adaptation, and semantic structuring. The approach is demonstrated across three distinct domains: monitoring Digital Transformation discourse via social media and news, mapping research trends in Architecture, Engineering, Construction, and Operations (AECO), and extracting biomedical causal relations from clinical and user-generated text. Each use case employs a tailored pipeline that integrates classical NLP (dependency parsing, topic modeling), machine learning (clustering), generative AI (instruction-tuned LLMs), and Semantic Web technologies (entity linking, graph construction). The outcomes include publicly released KGs, interactive dashboards, and fine-tuned models, validating the effectiveness of hybrid extractive-semantic pipelines for domain-specific knowledge extraction and analysis.

## Method Summary
The methodology revolves around three pipeline variants, each balancing schema flexibility and domain specificity. For noisy, schema-free text (social media), an unsupervised Open Information Extraction (Open IE) approach uses dependency parsing and relation clustering to generate high-precision triples without predefined ontologies. For structured scientific literature, an enhanced pipeline combines upstream neural topic modeling (BERTopic) with a fine-tuned, instruction-tuned LLM to extract task-method triples from topically coherent paper clusters. For biomedical causality, a causal relation classification model (CLiMA) is created via instruction fine-tuning of a medically pre-trained LLM on a small specialized dataset, enabling zero-shot extraction across clinical notes and patient reviews. All pipelines incorporate semantic enrichment via entity linking (DBpedia/Wikidata) and graph reification.

## Key Results
- Digital Transformation monitoring pipeline achieved **0.96 precision** on triple extraction and produced linked KGs (DTSMM_KG, DHNEWS_KG) from social media and news.
- AECO research pipeline generated **AECO-KG** with **over 255,000 triples**, connecting 15,037 Tasks and 22,240 Methods, enabling fine-grained trend analysis.
- Instruction-tuned biomedical model **CLiMA** (MedLlama fine-tuned on MIMICause) achieved **0.829 macro F1**, and its application to drug reviews built **CausalDrugsKG** with **0.73 precision**.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Unsupervised Open IE with dependency parsing and relation clustering generates high-precision triples from noisy social media without requiring a predefined ontology.
- **Mechanism:** Text is preprocessed to normalize platform-specific tokens. Candidate entities and predicate verbs are extracted via dependency parse tree patterns. Relations are generalized by clustering lemma embeddings with UMAP-HDBSCAN, using the cluster exemplar as the relation label. Entities are linked to DBpedia via lexical matching.
- **Core assumption:** Syntactic dependency paths reliably indicate semantic relations, and vectors of relation lemmas capture semantic equivalence across surface forms.
- **Evidence anchors:**
  - [abstract] "an unsupervised open information extraction pipeline from social media and news achieved high precision (0.96) and generated linked KGs"
  - [section] "Relation Extraction...only the subset of paths with a prevalence of correct triples...were considered reliable"
  - [corpus] Triple evaluation on tweets: Precision=0.82 (vs. baseline 0.31–0.77), with 8% of entities linked to DBpedia.
- **Break condition:** If dependency parsing accuracy drops on informal text, or if lemma embeddings fail to cluster synonymous relations (e.g., low silhouette score).

### Mechanism 2
- **Claim:** Upstream neural topic modeling coupled with a domain-adapted LLM-based SKG pipeline enables large-scale, domain-specific scientific KG construction from heterogeneous corpora.
- **Mechanism:** A BERTopic model with optimized UMAP-HDBSCAN clusters papers into macro-topics. For each cluster, an instruction-tuned LLM (fine-tuned on a small SciERC-style dataset) extracts (Task, Used-for, Method) triples. Entities are merged via Wikidata/DBpedia linking and cosine similarity.
- **Core assumption:** Topic clusters provide topical coherence that enhances recall of specific research entities, and few-shot instruction tuning can adapt generalist LLMs to out-of-domain entity/relation schemas.
- **Evidence anchors:**
  - [abstract] "enhanced information extraction pipeline using instruction-tuned LLMs and optimized topic modeling produced a large-scale graph (AECO-KG) with over 255,000 triples"
  - [section] "fine-tuning...using 816 training instances...average F1 0.73" on SciERC AECO; "AECO-KG connects 15,037 Tasks and 22,240 Methods"
  - [corpus] Linkage: 1.7% to Wikidata, 0.34% to DBpedia; Precision=0.695 on a random 300-triple sample.
- **Break condition:** If topic coherence degrades (avg. coherence <0.6), or if LLM fine-tuning fails on a small training set, leading to low recall and erroneous triples.

### Mechanism 3
- **Claim:** Instruction fine-tuning on a small, specialized causal relation dataset yields a high-performance, portable model for causal KG construction across biomedical text genres.
- **Mechanism:** A causal relation classification model (CLiMA) is created by instruction fine-tuning a medically pre-trained LLM (MedLlama) on the MIMICause dataset (1,953 instances) using LoRA (rank=8). The model is then applied zero-shot to ADE corpus and drug reviews to build CausalDrugsKG.
- **Core assumption:** Causal relation semantics can be distilled into a small, high-quality instruction-tuning set and that base LLMs can learn this abstract reasoning without large-scale biomedical causal annotation.
- **Evidence anchors:**
  - [abstract] "fine-tuned MedLlama model (CLiMA) achieving up to 0.829 macro F1 on MIMICause"
  - [section] "fine-tuned models...macro F1 score that is over 0.25 higher than the best-performing in-context learning configuration"
  - [corpus] "CLiMA achieves overall precision of 0.73" on drug reviews; "all fine-tuned models reach >0.95 F1 on ADE positive examples."
- **Break condition:** If the fine-tuning dataset is not representative of the target domain (e.g., lacks slang from patient forums), or if LoRA rank is too low to capture relation-specific tuning.

## Foundational Learning
- **Concept: Dependency Parsing & Path Patterns**
  - Why needed here: Forms the core of the open IE mechanism for DT monitoring; erroneous parse trees directly degrade triple precision.
  - Quick check question: "Which dependency path pattern would extract a relation from 'The system uses solar panels'? What if the verb is in passive voice?"
- **Concept: UMAP-HDBSCAN for Relation Clustering**
  - Why needed here: Generalizes surface-form relation verbs into canonical labels; clustering hyperparameters control the trade-off between precision and relation vocabulary size.
  - Quick check question: "What metric typically indicates good cluster separation and coverage for HDBSCAN? How would increasing `min_cluster_size` affect the number of relation types?"
- **Concept: Instruction Fine-Tuning with LoRA**
  - Why needed here: Enables domain adaptation of large LLMs with limited compute and training data (e.g., <2k samples) for schema-bound extraction tasks like SciERC and causal RE.
  - Quick check question: "What are the two matrices in the LoRA update ΔW = BA? How does a low `r` rank affect model capacity and overfitting?"

## Architecture Onboarding
- **Component map:**
  1. **Pre-processing:** Text normalization (hashtags, URLs, anaphora) → dependency parse trees.
  2. **Triple Extraction:** Pattern-based entity/relation span detection from trees.
  3. **Refining:** Entity normalization/lemmatization → DBpedia/Wikidata linking; Relation lemma embedding → UMAP-HDBSCAN clustering → exemplar mapping.
  4. **KG Finalization:** Reification with source support, ontology property mapping.
  5. **LLM Module (AECO/Biomed):** Instruction-tuned model for joint NER-RE.
  LLM path: Text + entities → JSON instruction prompt → Model output → Parse → Validate → Graph.
- **Critical path:** Raw text → Dependency parse → (Entities, Predicates) → Clean/normalize → Link/Cluster → Graph triples.
- **Design tradeoffs:**
  - Schema-free vs. schema-bound: Open IE (DT) generalizes relations but lacks typed predicates; LLM-based (AECO/Biomed) uses fixed schemas but needs tuning data.
  - Recall vs. Precision: Lower cosine similarity threshold (0.75) increases entity merging recall but introduces false merges; higher thresholds preserve precision but fragment entities.
  - Cost vs. scalability: Fine-tuning (biomed) gives best performance but requires labeled data; zero-shot in-context learning (AECO variant) scales but underperforms.
- **Failure signatures:**
  - DT: Low silhouette score in relation clustering; >50% of entities not linked to DBpedia; many singleton relation clusters.
  - AECO: Topic coherence <0.5; >30% outlier articles; LLM output format errors (>5%) or low consistency score.
  - Biomed: Fine-tuned model F1 <0.6 on MIMICause dev set; high variance across relation classes; poor generalization on ADE drug-review text.
- **First 3 experiments:**
  1. Run the DT pipeline on a 500-tweet sample. Manually inspect 50 generated triples. Compute entity linking rate and relation cluster count. Goal: >80% precision, 100–300 relation clusters.
  2. For AECO: Run BERTopic on 10k paper abstracts with default settings. Compute avg. coherence and % outliers. Then apply the optimized UMAP-HDBSCAN settings from Table 1. Goal: coherence >0.6, <40% outliers.
  3. For Biomed: Fine-tune base Llama-2-7b on 100 MIMICause train instances (small subset). Evaluate on 50 MIMICause test instances. Goal: >0.5 macro F1 to confirm learning signal before full training.

## Limitations
- Scalability claims lack stress-testing on truly massive corpora (e.g., >1M documents); reported graphs are modest in size.
- Domain portability of fine-tuned models (e.g., CLiMA) is asserted but only validated on two biomedical subdomains; cross-genre robustness remains unclear.
- Ontology alignment is superficial (lexical DBpedia matching); deeper semantic integration (e.g., ontology class inference) is absent.

## Confidence
- **Mechanism 1 (Unsupervised Open IE):** Medium. High precision (0.96) demonstrated, but recall not evaluated; relies on dependency parsing accuracy and relation clustering quality, with break conditions indicating sensitivity to these factors.
- **Mechanism 2 (LLM + Topic Modeling for Science):** Medium-Low. Performance constrained by topic coherence and small fine-tuning dataset (816 instances), yielding moderate precision (0.695); break conditions include topic degradation and LLM output errors.
- **Mechanism 3 (Instruction-Tuned Causality):** Medium. Strong in-domain performance (macro F1 0.829) but cross-genre robustness uncertain; limited validation on only two biomedical subdomains suggests potential gaps.
