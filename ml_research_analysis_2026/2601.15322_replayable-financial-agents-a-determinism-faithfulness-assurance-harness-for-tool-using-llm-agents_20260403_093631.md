# Replayable Financial Agents: A Determinism-Faithfulness Assurance Harness for Tool-Using LLM Agents
## Quick Facts
- arXiv ID: 2601.15322
- Source URL: https://arxiv.org/abs/2601.15322
- Reference count: 17
- Primary result: LLM agents fail regulatory audit replay due to inconsistent outputs; DFAH reveals orthogonal determinism-accuracy trade-off and tier-specific validation scaling.

## Executive Summary
Financial regulators require LLM agents to produce reproducible decisions for audit replay, but current agents exhibit inconsistent outputs. This paper introduces the Determinism-Faithfulness Assurance Harness (DFAH) to measure two independent dimensions: trajectory determinism (reproducibility) and evidence-conditioned faithfulness (grounding in retrieved data). Across 4,700+ runs on three financial benchmarks, DFAH reveals no correlation between determinism and accuracy, overturning the assumption that reproducibility implies correctness. Small (7–20B) models with schema-first architectures achieve near-perfect determinism (>95%) yet low accuracy (20–42%) via pattern matching, while frontier models show moderate determinism (50–96%) with higher, variable accuracy. No model excels at both. The analysis further shows that high-drift models (Tier 3, 120B+) need 3.7× larger validation samples to reach equivalent statistical confidence, posing economic barriers for compliance. DFAH provides a practical framework for deploying auditable financial agents, emphasizing architectural constraints over scale.

## Method Summary
The DFAH evaluates tool-using LLM agents by executing multiple trials per test case under controlled randomness (temperature T=0.0, fixed seeds). It records full trajectories (tool calls, arguments, results) in a structured store. A grader suite computes case-level metrics: decision determinism (agreement on final output), signature determinism (identical tool sequences), task accuracy (majority-vote vs. ground truth), and evidence-conditioned faithfulness (lexical alignment between claims and retrieved context, using high-precision heuristics to avoid recursive non-determinism). Stress-test scenarios (Redeploy, Data Quality Fault, Market Shock) perturb tool outputs to measure determinism degradation. From the drift variance across runs, the framework derives a validation scaling factor ϕ(m) that inflates required sample sizes for unstable models, extending prior work on validation design.

## Key Results
- Decision determinism and task accuracy show no detectable correlation (Pearson r = -0.11, 95% CI [-0.49, 0.31], p=0.63) across 21 model-benchmark configurations.
- Tier 1 (7–20B) schema-first models achieve 94–100% determinism but only 20–42% accuracy; frontier models (50–96% determinism) attain higher, variable accuracy (up to 89%). No model simultaneously exceeds 95% determinism and 80% accuracy.
- Tier 3 (120B+) models exhibit drift variance σ²_drift = 0.27, requiring a validation scaling factor ϕ = 3.7× (bootstrap CI [2.9×, 4.8×]) relative to Tier 1, making compliance validation economically infeasible at scale.

## Why This Works (Mechanism)
**Mechanism 1: Orthogonality of Determinism and Accuracy**  
The DFAH demonstrates that reproducibility and correctness are independent failure modes. By running multiple trials per case and computing decision determinism (fraction of identical final outputs) alongside majority-vote accuracy, the framework reveals no significant correlation (r = -0.11). A model can be deterministic but inaccurate (e.g., rigid pattern matching) or accurate but non-deterministic (exploring diverse tool paths). Evidence includes bootstrap confidence intervals from 4,705 runs (Section 6.2) and neighbor literature that treats non-determinism in isolation. If future studies with >100 configurations find |r| > 0.5, the orthogonality claim would need revision.

**Mechanism 2: Schema-First Architectures Enable Audit Replay for Small Models**  
Constraining agent decisions and tool arguments via predefined JSON schemas suppresses variations in tool calls, allowing Tier 1 (7–20B) models to achieve >95% decision determinism even under tool-using execution. This architectural constraint—not model size—engineers determinism. Evidence: schema-first + qwen2.5:7b maintained 100% determinism across stress pilots (Figure 5). If frontier models adopt schema-first and reach >95% determinism without accuracy loss, the tier-based trade-off may converge.

**Mechanism 3: Validation Scaling Inflation for High-Drift Models**  
Output instability adds measurement error; more validation samples are needed to average out drift. The required sample size scales with drift variance via ϕ(m) = 1 + σ²_drift(m)/σ²_ref. Tier 3 models (σ²_drift = 0.27) need 3.7× more samples than Tier 1 (σ²_ref ≈ 0.1), per empirical derivation in Section 4.4 and Appendix F. If architectural improvements reduce σ²_drift of large models to near zero, ϕ would approach 1.0, making validation feasible.

## Foundational Learning
- **Determinism Metrics**: Regulatory audit requires consistent decisions (pass k), not just one success (pass@k). Signature determinism (exact tool paths) is stricter than decision determinism.  
  *Quick check*: For compliance replay, which must be near 100%—decision determinism or signature determinism? Why does pass k matter?  
  *Answer*: Decision determinism, because regulators care about final outcomes, not internal paths. Pass k demands all sampled decisions reproduce, not just one.

- **Evidence-Conditioned Faithfulness**: Agents must ground decisions in retrieved evidence, not hallucinate. DFAH uses a high-precision lexical alignment heuristic (Jaccard ≥0.6 + entity match) to keep evaluation interpretable and deterministic, accepting lower recall to avoid false positives that regulators would reject.  
  *Quick check*: Why favor a conservative heuristic over an NLI-based LLM judge?  
  *Answer*: To prevent recursive non-determinism and ensure human reviewers can trace claims to specific evidence snippets.

- **Validation Scaling Factor ϕ**: Determines how many validation cases are needed to offset drift-induced measurement error. Institutions allocate resources accordingly.  
  *Quick check*: Compute ϕ for σ²_drift = 0.08, σ²_ref = 0.1. How does a planned 1,000-case sample change?  
  *Answer*: ϕ = 1 + 0.08/0.1 = 1.8×, so effective required sample is 1,800 cases; a 1,000-case sample yields wider confidence intervals.

## Architecture Onboarding
- **Component map**: Task Runner -> Trajectory Store -> Grader Suite (code-based determinism checkers, heuristic faithfulness grader, human calibration grader) -> Aggregator. Stress-Test Scenarios integrate with Runner/Store to perturb tool outputs.

- **Critical path**:  
  1. Load benchmark case (input + real tools).  
  2. Task Runner instantiates agent (T=0.0, seed=42) and runs until decision.  
  3. Trajectory Store records transcript and decision.  
  4. Repeat steps 1–3 for N runs per case (3–8 typical).  
  5. Aggregator compares transcripts via code graders to compute decision/signature determinism.  
  6. Aggregator computes evidence-conditioned faithfulness via lexical alignment.  
  7. Apply stress perturbations (modify tool outputs before step 2); recompute determinism degradation.  
  8. Derive drift variance and scaling factor ϕ for the configuration.

- **Design tradeoffs**:  
  - Determinism graders: Exact match (audit-safe) vs. semantic equivalence (flexible).  
  - Faithfulness: High-precision heuristic (deterministic, conservative) vs. LLM-as-a-judge (flexible but non-deterministic).  
  - Cost vs. confidence: More runs detect rare drift but increase runtime; 8 runs balances >5% drift detection with feasibility.  
  - Architecture: Schema-first boosts determinism but may limit agent flexibility; unconstrained agents need human oversight.

- **Failure signatures**:  
  - Decision determinism <95% on high-risk cases fails audit replay.  
  - Decision–signature gap >20% indicates trajectory variance that may fail transcript audits.  
  - Faithfulness <80% suggests insufficient evidence grounding.  
  - Stress-test degradations >10% reveal perturbation vulnerability.  
  - Extreme decision concentration (>75% one action) with low accuracy signals pattern-matching without understanding.

- **First 3 experiments**:  
  1. Baseline determinism scan: Run qwen2.5:7b (schema-first) across all benchmarks to establish Tier 1 determinism baseline.  
  2. Determinism-accuracy correlation study: Execute 21 model-benchmark configurations, compute Pearson r, and bootstrap confidence intervals.  
  3. Stress-test perturbation analysis: Apply Redeploy, DQ Fault, Market Shock to each tier, measure determinism degradation, and project scaling factors.

## Limitations
- Exact system prompts and evidence-retrieval framing for benchmarks are undisclosed, risking replication of agent behavior.
- Evidence-alignment heuristic details (noun-phrase extraction, numerical tolerance) are summarized but not fully specified, affecting faithfulness scores.
- Stress-test degradation projections (Δ_tier,p) lack transparent derivation beyond median values in Table 9.

## Confidence
- Orthogonality of determinism and accuracy: Medium (strong evidence but wide confidence interval [-0.49, 0.31] leaves uncertainty about true correlation).
- Schema-first efficacy for Tier 1: Medium (pilot data limited to one model; generalizability unproven).
- Validation scaling factor ϕ: Medium (formula clear but extrapolation assumes stable drift characteristics across models and contexts).

## Next Checks
1. Prompt & Heuristic Audit: Reproduce DFAH using exact prompts and heuristic code (once released) to verify reported determinism/faithfulness distributions.
2. Heuristic Sensitivity Probe: Systematically vary lexical alignment threshold (e.g., Jaccard ∈ [0.5, 0.7]) on a human-annotated slice to quantify robustness of faithfulness scores and their correlation with determinism.
3. Stress-Test Seed Stability: For frontier models (Claude, Gemini), run stress perturbations with multiple seeds beyond T=0.0 to distinguish API-level non-determinism from intrinsic architectural drift.
