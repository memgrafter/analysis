# Still Fresh? Evaluating Temporal Drift in Retrieval Benchmarks

## Quick Facts
- arXiv ID: 2603.04532
- Source URL: https://arxiv.org/abs/2603.04532
- Reference count: 40
- Primary result: Benchmarks remain robust despite temporal corpus drift; model rankings strongly correlated (Kendall τ up to 0.978) due to content migration within the ecosystem.

## Executive Summary
This paper investigates whether static retrieval benchmarks stay reliable when technical documentation evolves over time. Using FreshStack (a LangChain-focused benchmark), the authors compare two corpus snapshots from October 2024 and October 2025. They automatically generate relevance judgments via LLM-assessed nugget support. Results show that almost all queries (202 of 203) remain answerable in the 2025 corpus because relevant documents migrate to repositories like LlamaIndex. Model rankings across snapshots are strongly correlated, with Kendall τ reaching 0.978 at Recall@50, indicating that benchmarks can maintain robustness despite temporal drift.

## Method Summary
The study constructs two corpus snapshots from ten GitHub repositories (e.g., `langchain`, `llama_index`, `chroma`) at specified dates (Oct 2024 and Oct 2025). Documents are chunked into ≤2048 tokens. Queries and their atomic nuggets are sourced from Stack Overflow via FreshStack. An oracle retrieval pipeline pools results from BM25 and multiple embedding models (BGE, E5, Qwen3) using various query representations (original answers, nuggets, sub-questions). To assess relevance, Cohere Command A judges whether a document chunk supports any nugget for a query, generating qrels. The analysis then measures query support (fraction of nuggets grounded in the corpus), the distribution of relevant documents across repositories, and ranking correlation (Kendall τ) between snapshots.

## Key Results
- 202 of 203 queries retained full nugget support in the 2025 corpus; relevant content migrated from LangChain to competitor repos like LlamaIndex.
- Model rankings across time are highly stable: Kendall τ = 0.978 for Recall@50, indicating strong correlation.
- Coverage@20 shows lower correlation (τ = 0.692), suggesting diversity of retrieved passages is more sensitive to temporal drift.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Queries remain answerable across temporal snapshots because relevant content migrates within the ecosystem rather than disappearing.
- **Mechanism:** When a primary repository (e.g., LangChain) deprecates or reorganizes content, the functionality often persists in related repositories (e.g., LlamaIndex). This migration preserves the semantic substance needed to answer existing factual queries.
- **Core assumption:** The domain ecosystem (e.g., RAG frameworks) is sufficiently interlinked that core functionalities are replicated or integrated across competing projects.
- **Evidence anchors:**
  - [abstract] "all but one query posed in 2024 remain fully supported by the 2025 corpus, as relevant documents 'migrate' from LangChain to competitor repositories, such as LlamaIndex."
  - [section 4.1] Experimental results showing 202 of 203 queries retained full nugget support in the 2025 corpus.
  - [corpus] Weak—neighboring papers discuss dynamic corpora (LongEval) and FreshStack but do not directly evidence this migration mechanism.
- **Break condition:** If migrated content is incomplete or semantically altered such that nuggets are no longer supported.

### Mechanism 2
- **Claim:** Model rankings remain stable (high Kendall τ) despite document migration because retrieval models target semantic content, not specific file locations.
- **Mechanism:** Dense and hybrid retrievers encode semantic meaning. When relevant content moves to a different repository but retains similar terminology and context, the embeddings remain comparable, preserving relative model performance.
- **Core assumption:** The linguistic and technical semantics of the domain are stable enough that embedding spaces for the same concepts in 2024 (LangChain) and 2025 (LlamaIndex) are proximally aligned.
- **Evidence anchors:**
  - [abstract] "model rankings across snapshots were strongly correlated, with Kendall τ reaching 0.978 at Recall@50."
  - [section 4.3] Table 3 and analysis showing very strong correlation (τ = 0.978 for Recall@50) across diverse embedding models.
  - [corpus] Weak—neighbors like "Query Drift Compensation" discuss embedding stability but are not evidence for this specific result.
- **Break condition:** If semantic shift (e.g., API redesign with new terminology) causes embedding distributions to diverge, reducing correlation.

### Mechanism 3
- **Claim:** Nugget-level LLM assessment enables reliable drift evaluation by decoupling query relevance from specific document versions.
- **Mechanism:** Queries are decomposed into atomic nuggets (key facts). A document is judged relevant if it supports any nugget. This allows the same nuggets to be matched against documents from different repositories or versions, making the judgment process robust to where the information resides.
- **Core assumption:** LLM judges (Command A) can accurately assess nugget support across diverse document sources and versions.
- **Evidence anchors:**
  - [abstract] "automatically generated relevance judgments via LLM-assessed nugget support."
  - [section 3.4] Describes using Command A to judge documents against nuggets, defining relevance as supporting at least one nugget.
  - [corpus] Weak—neighbors describe LLM judges (e.g., "LLMJudge") but do not validate this specific implementation.
- **Break condition:** If LLM judgment consistency degrades across repository styles (e.g., code vs. cookbook) or if nuggets become obsolete.

## Architecture Onboarding
### Component Map
1. **Corpus Preparation:** Snapshots of multiple GitHub repos at timed intervals → chunked documents.
2. **Nugget Generation:** Stack Overflow Q&A → atomic facts (via GPT-4o).
3. **Oracle Retrieval:** Hybrid fusion (BM25 + multiple embedding models) using diverse query forms (answers, nuggets, sub-questions) → top-50 candidate documents per query.
4. **Nugget-level Assessment:** LLM judge (Command A) assigns relevance per document per nugget → final qrels.

### Critical Path
Nugget Generation → Oracle Retrieval → Nugget Assessment. The nuggets tie the query to candidate documents across time.

### Design Tradeoffs
- Automatic vs. human judgments: LLM judges are scalable but may have systematic biases not captured in the paper's analysis.
- Multi-repo vs. single-repo corpus: Captures migration but adds noise from unrelated content; requires careful filtering.
- Fixed queries vs. temporal queries: Using 2024 queries for 2025 evaluation assumes query intent is stable, which may not hold for all domains (acknowledged in conclusion).

### Failure Signatures
- Low nugget support in RQ1 (many facts unsupported) → domain too volatile or ecosystem insufficiently linked.
- Massive source distribution shift (RQ2) with *decrease* in total relevant docs → content loss, not just migration.
- Low Kendall τ (RQ3) → retrieval models are brittle to semantic shifts or embedding spaces misalign.

### First 3 Experiments
1. Reproduce corpus snapshots: Use provided GitHub commit hashes for October 2024/2025 to generate identical chunked corpora. Validate document counts and repositories.
2. Replicate nugget assessment pipeline: For 5 sample queries, run Command A with the same prompt. Compare relevance labels against the released qrels to verify the judgment process.
3. Compute ranking stability: Use the provided model runs and qrels for both snapshots. Calculate Kendall τ for Recall@50 and α-nDCG@10 to confirm the reported correlations. If values diverge, inspect which models' rankings changed most.

## Open Questions the Paper Calls Out
1. **Question:** To what extent do the findings on document migration and benchmark robustness generalize to non-modular or non-code domains, such as Wikipedia or news archives?
   *Basis in paper:* [explicit] The authors explicitly state in the Conclusion & Future Work that their focus on LangChain's modular ecosystem may not apply to other domains like Wikipedia, where information and answers may evolve rather than simply migrate between repositories.
   *Why unresolved:* The study is confined to a single, highly dynamic technical domain with specific migration patterns. Generalizability remains an open empirical question.
   *What evidence would resolve it:* Conducting similar temporal drift analyses on benchmarks from diverse domains (e.g., historical Wikipedia articles, evolving scientific literature, legal documents) and comparing the stability of queries, nuggets, and model rankings.

2. **Question:** In domains where factual answers themselves change over time (e.g., evolving Wikipedia content), is it necessary to regenerate nuggets at each temporal snapshot to maintain a valid test collection?
   *Basis in paper:* [explicit] The authors directly pose this question for Wikipedia in the Conclusion & Future Work, contrasting it with their LangChain setup where answers are task-oriented and nuggets remain supported via migration.
   *Why unresolved:* The paper's methodology reuses nuggets from the 2024 snapshot for the 2025 corpus. This approach's validity hinges on the assumption that the core facts needed to answer queries remain constant, which may not hold in all domains.
   *What evidence would resolve it:* A controlled study comparing test collections built with static vs. dynamically regenerated nuggets across multiple temporal snapshots in a domain with evolving factual answers, measuring the impact on system ranking consistency.

3. **Question:** Why does the correlation between model rankings across time snapshots weaken notably for the Coverage@20 metric (Kendall τ = 0.692) compared to Recall@50 (τ = 0.978), and what does this reveal about retrieval systems' temporal robustness?
   *Basis in paper:* [explicit] The results in Section 4.3 explicitly report the Kendall τ correlations for all metrics, highlighting the relatively lower correlation for Coverage@20 and concluding that models struggle to retrieve diverse relevant passages over time.
   *Why unresolved:* The analysis identifies the phenomenon but does not investigate the underlying causes, such as whether specific model architectures or training data are more susceptible to diversity loss under corpus drift.
   *What evidence would resolve it:* An error analysis correlating Coverage@20 score changes with specific query types, document source shifts, or model properties (e.g., embedding dimensionality, training corpus age) to identify drivers of diversity degradation.

4. **Question:** How sensitive are the conclusions about temporal robustness to the choice of LLM judge for nugget-level relevance assessment?
   *Basis in paper:* [inferred] The entire judgment pipeline relies on a single LLM (Cohere Command A) to assess nugget support. The paper does not explore the robustness of this critical step to variations in judge model, prompt, or version.
   *Why unresolved:* LLM-as-judge reliability is an active research area with known variability across models. A biased or unstable judge could artifactually inflate or deflate perceived temporal stability by inconsistently labeling document relevance across snapshots.
   *What evidence would resolve it:* Re-running the nugget-level assessment for a subset of queries using multiple LLM judges (e.g., GPT-4o, Claude, open-source models) and measuring inter-judge agreement across time snapshots and its impact on the reported Kendall τ correlations.

## Limitations
- Exact snapshots undocumented: Commit hashes for Oct 2024/2025 are not provided; only "main branch as of" dates. This requires reconstruction, risking drift in replication.
- LLM judge opacity: Command A’s prompt, temperature, and version are unspecified, introducing potential variability in nugget support labels.
- Ecosystem dependency: The migration mechanism heavily relies on inter-project linking (LangChain ↔ LlamaIndex). Generalizability to less-connected domains is uncertain.

## Confidence
- Query answerability persists: High
- Model ranking stability: Medium
- Nugget-based robustness: Medium-Low
