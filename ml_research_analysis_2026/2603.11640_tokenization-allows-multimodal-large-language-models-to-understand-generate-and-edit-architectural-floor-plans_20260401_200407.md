# Tokenization Allows Multimodal Large Language Models to Understand, Generate and Edit Architectural Floor Plans
## Quick Facts
- arXiv ID: 2603.11640
- Source URL: https://arxiv.org/abs/2603.11640
- Reference count: 40
- Primary result: HouseMind: multimodal LLM unifying floor plan understanding, generation, and editing using VQ-VAE tokenization; achieves near-perfect understanding (Success 1.000) and strong generation/editing (Macro IoU 0.653, ΔIoU 0.608) in ~3 seconds on RTX 3090.

## Executive Summary
Architectural floor plan design demands coherent spatial reasoning across geometry, semantics, and hierarchy, a challenge for prior AI systems. This paper introduces HouseMind, a multimodal large language model capable of understanding, generating, and editing floor plans within a single framework. HouseMind discretizes continuous layouts into hierarchical room-instance tokens via a conditional VQ-VAE, creating a shared vocabulary that links geometric and symbolic representations. Through a three-stage multimodal alignment and instruction tuning pipeline, the model learns to reason directly in token space. It achieves near-perfect understanding, superior generation quality, and precise editing, all while running efficiently (~3 seconds on a single RTX 3090), demonstrating geometric validity, controllability, and local deployability.

## Method Summary
HouseMind employs a tokenization-based approach: a VQ-VAE encodes building outlines and individual rooms (conditioned on the outline) into discrete tokens, forming an interleaved sequence that an LLM can process autoregressively. The model undergoes three training stages: embedding initialization, pre-training on mixed text and spatial token sequences to align modalities, and supervised fine-tuning (SFT) on task-specific instructions. This unified sequence modeling eliminates the need for task-specific heads, allowing the same architecture to handle understanding, generation, and editing through prompt formatting. A lightweight Qwen3-0.6B backbone serves as the LLM, and a post-processing pipeline ensures topological correctness of outputs.

## Key Results
- Understanding: Success 1.000, Room Match Rate 0.998
- Generation: Macro IoU 0.653, FID 1.89, Node F1 0.994
- Editing: ΔIoU 0.608 with ~3 seconds inference on a single RTX 3090

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Hierarchical room-instance tokenization enables coherent spatial reasoning by converting continuous layouts into discrete, structured sequences.
- **Mechanism:** A VQ-VAE encodes the building outline and each room (conditioned on the outline) into separate codebook tokens. These tokens form an interleaved sequence `[outline, room_label, room_tokens, ...]` that an LLM can process autoregressively.
- **Core assumption:** Discrete tokens preserve sufficient geometric and relational information for downstream tasks while being compatible with LLM sequence modeling.
- **Evidence anchors:**
  - [abstract]: "discretizing layouts into hierarchical room-instance tokens via VQ-VAE, creating a shared vocabulary linking geometry and symbolic reasoning."
  - [section 4.1]: Details conditional VQ-VAE for outline and rooms, with `Eq. (2)-(7)` defining tokenization.
  - [corpus]: Neighbors like ChatHouseDiffusion [176981] use diffusion, not tokenization; evidence is weak—HouseMind's specific token-based approach isn't directly cited.
- **Break condition:** If token reconstruction fidelity (PSNR/SSIM in Tables A.1-A.2) drops significantly, the latent space loses spatial structure needed for reasoning.

### Mechanism 2
- **Claim:** Progressive multimodal alignment (embedding init → pre-training → SFT) grounds spatial tokens within the LLM's semantic space.
- **Mechanism:** Stage 1 initializes token embeddings; Stage 2 trains the LLM on mixed text/spatial token sequences to learn correspondence; Stage 3 fine-tunes on task-specific instructions.
- **Core assumption:** The LLM backbone can act as a universal sequence modeler for both language and discrete geometric symbols after alignment.
- **Evidence anchors:**
  - [section 4.2]: "three-stage multimodal alignment and instruction tuning pipeline" with Fig. 3 illustrating stages.
  - [section 5.5 (Ablations)]: Table 4 shows removing either Stage 1 or 2 increases eval loss, proving their necessity for alignment.
- **Break condition:** If validation loss rises without stability in early stages (e.g., Stage 1 embedding init), cross-modal grounding fails, harming all downstream tasks.

### Mechanism 3
- **Claim:** Unified sequence modeling allows one architecture to handle understanding, generation, and editing via prompt formatting, avoiding task-specific modules.
- **Mechanism:** All tasks are framed as autoregressive prediction over the same interleaved token sequence, with prompts differentiating objectives (e.g., "Generate" vs. "Edit").
- **Core assumption:** Spatial reasoning capabilities learned in one task transfer to others because they share the same token-level representations.
- **Evidence anchors:**
  - [section 3]: "Unified task formulation... jointly addresses three core tasks as... sequence-modeling problem."
  - [section 5.3]: HouseMind-O (jointly trained) performs comparably to task-specific variants, supporting transfer.
- **Break condition:** If editing or understanding degrades when jointly trained vs. separately (see Table 3: HouseMind-E vs. HouseMind-O's ΔIoU 0.598 vs. 0.608), negative transfer occurs.

  - *Quick check question:* How does conditioning the room VQ-VAE on the outline mask (Sec. 4.1) improve adjacency preservation?

  - *Why needed here:* Teaches the LLM to follow text prompts that manipulate spatial tokens, enabling controllable generation/editing.
  - *Quick check question:* Why is SFT (Stage 3) necessary after pre-training (Stage 2) for precise editing (Table 3)?

  - *Why needed here:* Evaluates topological correctness beyond pixel metrics; floor plans require valid room connectivity.

## Architecture Onboarding
- **Component map:** VQ-VAE tokenizers (outline and conditional room) → Embedding layer (spatial token embeddings) → LLM backbone (Qwen3-0.6B) → Post-processing pipeline.
- **Critical path:** Pre-train VQ-VAEs → Initialize embeddings (Stage 1) → Pre-train LLM on mixed sequences (Stage 2) → SFT on task instructions (Stage 3) → Generate token sequences → Decode via VQ-VAE decoders → Apply post-processing.
- **Design tradeoffs:** Token granularity (patch size) balances geometric fidelity vs. sequence length; unified model offers versatility but may sacrifice task-specific peak performance; larger codebooks marginally improve fidelity but increase memory.
- **Failure signatures:** Geometric incoherence (high GED, low Edge Overlap) indicates invalid topology; token misalignment (high eval loss in ablation) shows poor cross-modal grounding; task leakage (e.g., generation model misinterprets edit prompts) suggests SFT data mixing issues.
- **First 3 experiments:**
  1. **Tokenization sanity check:** Encode/decode sample floor plans; verify PSNR > 40 dB to ensure no severe bottleneck.
  2. **Alignment probe:** After Stage 1 & 2, measure next spatial token prediction given text description; expect low eval loss.
  3. **Task validation:** Run inference on a small subset for each task; check Success ~1.000 (understanding), Macro IoU >0.65 (generation), ΔIoU >0.5 (editing).

## Limitations
- Token discretization may oversimplify geometry, losing fine details.
- Evaluation limited to the provided synthetic dataset; real-world generalizability uncertain.
- Automatic metrics (Macro IoU, GED) do not fully capture functional spatial quality; lacking human studies.
