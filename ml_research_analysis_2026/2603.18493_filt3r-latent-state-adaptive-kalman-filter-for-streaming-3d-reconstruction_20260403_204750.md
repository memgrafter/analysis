# FILT3R: Latent State Adaptive Kalman Filter for Streaming 3D Reconstruction

## Quick Facts
- **ArXiv ID:** 2603.18493  
- **Source URL:** https://arxiv.org/abs/2603.18493  
- **Reference count:** 40  
- **Primary result:** Reduces origin-aligned ATE on TUM-800 by 50% (0.107 vs. 0.214) vs. TTT3R.

## Executive Summary
Streaming 3D reconstruction suffers from long-horizon instability due to poorly balanced state update rules—aggressive overwrites cause forgetting, while conservative updates fail to adapt, both degrading beyond the training horizon. FILT3R addresses this by introducing a training-free latent filtering layer that recasts recurrent updates as adaptive Kalman filtering in token space. It maintains per-token variance, computes a Kalman gain to balance memory and new observations, and estimates process noise online from temporal drift while fixing measurement noise. This unifies prior overwrite and gating policies, leading to substantial improvements on long sequences. For example, on TUM-800 pose, origin-aligned ATE drops 50% compared to TTT3R.

## Method Summary
FILT3R is a plug-in replacement for the state update in streaming 3D reconstruction architectures like CUT3R. It treats persistent latent tokens as a stochastic state-space model: the true scene state evolves as a random walk with process noise, and each frame provides a noisy measurement (the decoder’s candidate state). The filter maintains a per-token variance estimate for the state. For each new frame, it computes the temporal drift of tokens between consecutive candidate states. This drift, normalized by an exponential moving average of stream-level drift, is mapped via a sigmoid to a per-token process noise estimate. Measurement noise is fixed as a scalar hyperparameter. Using these, it performs a standard Kalman predict‑update: predict variance by adding process noise, compute gain as predicted variance over total variance, update state as a weighted combination of prior state and new candidate, and update variance in a numerically stable Joseph form. This adaptive gain automatically interpolates between overwriting (high gain) and preserving (low gain) based on estimated change.

## Key Results
- TUM-800 pose (origin-aligned ATE): 0.107 (FILT3R) vs. 0.214 (TTT3R) – 50% reduction.
- Bonn-500 metric depth (Abs Rel): 0.089 (FILT3R) vs. 0.100 (TTT3R).
- 7-Scenes 3D reconstruction at length 1000: accuracy improves 2.7× (0.054 vs. 0.145).

## Why This Works (Mechanism)

### Adaptive Kalman Gain in Token Space
FILT3R computes a per-token Kalman gain that smoothly interpolates between prior state and new candidate, providing adaptive memory retention. The state update follows `s_t = s_{t-1} + k_t ⊙ (˜s_t - s_{t-1})`, with gain `k_t = p̅_t / (p̅_t + r)`. Larger `k_t` emphasizes new evidence; smaller `k_t` preserves history. This rests on the assumption that the decoder output `˜s_t` is a noisy measurement of the true latent scene state and that the latent evolves as a random walk with process noise `q_t`. Evidence: abstract and Section 3.1 define the stochastic state‑space model and Kalman‑style update equations. Break condition: if `r` is underestimated relative to `q_t`, gains become too large and the filter behaves like overwrite; overestimated `r` yields overly conservative updates.

### Online Process Noise Estimation from Temporal Drift
FILT3R estimates per-token process noise `q_t` from normalized temporal drift, enabling gains to rise during genuine scene changes. For each token, drift `Δ_t,i = ||˜s_t,i - ˜s_{t-1},i||^2` is computed. An EMA of stream‑level mean drift (`ˆΔ_t`) normalizes drift to score `g_t,i = Δ_t,i / (ˆΔ_t+ε)`. A sigmoid maps `g_t,i` to `q_t,i` within `[q_min, q_max]`. The core assumption is that large inter‑frame token displacement corresponds to actual motion or scene change. Evidence: abstract and Section 3.2 describe this mechanism (Eqs. 7–10). Break condition: if the drift signal is corrupted (e.g., by decoder hallucinations), `q_t` estimates may be inaccurate, causing inappropriate gain spikes or lulls.

### Fixed Measurement Noise Anchor and Recursive Uncertainty Propagation
A fixed scalar measurement noise `r` and variance recursion enable confidence to accumulate over time, naturally shrinking gains in stable periods without hand‑tuned gates. The variance prediction `p̅_t = p_{t-1} + q_t`; gain `k_t = p̅_t/(p̅_t+r)`; posterior `p_t = (1-k_t)^2 p̅_t + k_t^2 r` (Joseph form). With constant `q_t`, the recursion converges to a steady state where `p_t` contracts as evidence accumulates, making `k_t` decay ~`1/t` in static scenes. The fixed `r` anchors the gain and avoids correlated noise spikes. Evidence: abstract mentions fixing measurement noise and propagating uncertainty; Section 3.2 presents equations and rationale; Section 4.8 ablations show adaptive measurement noise degrades stability. Break condition: if the decoder’s uncertainty varies significantly across tokens/time, fixed `r` leads to mis‑calibrated gains; diagonal covariance may miss correlations.

## Foundational Learning
- **Kalman Filtering**: Understanding the predict‑update cycle, gain derivation, and noise covariances is foundational because FILT3R directly implements a Kalman filter in latent space. Quick check: In a scalar Kalman filter with zero process noise, how does the posterior variance evolve as more consistent measurements arrive? (Answer: It decreases monotonically, approaching the measurement noise variance.)
- **Streaming 3D Reconstruction with Persistent Latents**: Needed to know the baseline recurrent state update. Quick check: What problem arises from using a uniform overwrite (β_t ≡ 1) in long‑horizon streaming? (Answer: Catastrophic forgetting of earlier information.)
- **Uncertainty Propagation in Neural Systems**: Distinguishes FILT3R’s explicit variance recursion from heuristic gating that recomputes gates from scratch. Quick check: Why does the Joseph form (Eq. 14) preserve numerical stability compared to naive `p_t = (1-k_t) p̅_t`? (Answer: It avoids loss of precision when `k_t` is small by using a more stable computation.)

## Architecture Onboarding
- **Component map**: Pretrained encoder & decoder (frozen backbone) extracts image tokens and produces candidate state `˜s_t` from previous state. FILT3R layer consumes `s_{t-1}`, `p_{t-1}`, `˜s_{t-1}`, `˜s_t`; computes drift, updates EMA, estimates `q_t`, predicts `p̅_t`, computes `k_t`, updates `s_t` and `p_t`. Includes buffers for previous candidate and EMA value. 3D heads consume the updated state for depth/pose/reconstruction.
- **Critical path**: Numeric stability of gain computation (`k_t = p̅_t/(p̅_t+r)`) and correct normalization of drift (with ε and clamping) to prevent NaN explosions. State update uses element‑wise ops; no cross‑token dependencies.
- **Design tradeoffs**:
  - Fixed `r` vs adaptive `r`: fixed simplifies and stabilizes; adaptive (e.g., from attention) introduces correlated spikes and hurts performance.
  - `q_min > 0`: ensures filter never freezes; too large a floor reduces long‑term stability (tuned to 0.02).
  - Gain clamping `[k_min, k_max]` prevents extremes; `k_min=0.01` ensures minimal updating, `k_max=0.99` avoids full overwriting.
  - EMA rate `λ_Δ`: balances responsiveness vs jitter; set to 0.05.
- **Failure signatures**:
  - Drift spikes across tokens (sudden motion): `q_t` ↑ → gains ↑ → state rapidly changes. If gains remain high, `q_max` may be too high or `r` too low.
  - Near‑zero drift but gains do not decay: variance may have grown due to `q_min` too high or omitted `q_t` addition.
  - NaNs in `k_t`: from denominator near zero or negative `p̅_t`; check ε and clamping on `p̅_t`.
- **First 3 experiments**:
  1. Short‑horizon sanity check: Run FILT3R on Sintel (or Bonn 110‑frame) to verify depth/pose error matches baseline; ensures no regression.
  2. Long‑horizon pose: Evaluate on TUM‑RGBD truncated to 800 frames; check origin‑aligned ATE reduced by >50% vs CUT3R/TTT3R.
  3. Length generalization: Test 3D reconstruction on 7‑Scenes at 1000 frames; expect completeness/accuracy metrics to degrade less than baselines.

## Open Questions the Paper Calls Out
1. *Can a more sophisticated model disentangle correlated process and measurement noise estimates to enable stable adaptive measurement noise?* The paper fixed measurement noise after finding adaptive versions caused correlated spikes and instability. Resolved by an extension that safely introduces token‑wise adaptive `r_t` without correlated spikes.
2. *Do alternative Bayesian filtering frameworks (e.g., particle filters, extended/unscented Kalman filters for non‑linear token dynamics) yield further stability gains?* FILT3R uses a linear random‑walk with diagonal covariances; non‑linear or non‑Gaussian alternatives might better capture complex latent dynamics.
3. *Does incorporating structural or relational priors among tokens (beyond independent diagonal variances) improve long‑horizon coherence?* Independent token filtering may underutilize scene‑level constraints; a variant coupling variance updates or gain computation via token affinity could improve fragmented surfaces.
4. *Why does FILT3R’s advantage diminish on KITTI under metric‑scale evaluation?* On forward‑driving motion, TTT3R’s heuristic gate may already be well‑calibrated; the exact reason (motion pattern, depth distribution) is unclear.
5. *Is there an optimal schedule or learned mapping from token features to the sigmoid parameters (α_q, τ_q) in the process noise gate?* The current gate uses fixed hyperparameters; learning them from token features could adapt to diverse scene types.

## Limitations
- **Code release status**: The repository may not be public yet, hindering exact implementation.
- **Decoder noise homogeneity**: Fixed measurement noise `r` assumes homogeneous uncertainty; in reality, decoder uncertainty varies across tokens and time.
- **Drift signal corruption**: Process noise estimation relies on token displacement; hallucinations or sensor noise can cause inaccurate `q_t`.
- **Diagonal covariance limitation**: Ignores correlations between tokens, potentially missing structured scene changes.
