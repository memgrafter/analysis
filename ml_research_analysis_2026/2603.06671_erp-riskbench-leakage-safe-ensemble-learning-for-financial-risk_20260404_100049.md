# ERP-RiskBench: Leakage-Safe Ensemble Learning for Financial Risk
## Quick Facts
- **arXiv ID:** 2603.06671
- **Source URL:** https://arxiv.org/abs/2603.06671
- **Reference Count:** 39
- **Primary Result:** A leakage-safe stacking ensemble achieves MCC 0.651±0.017 and AUPRC 0.629±0.016 on BPI P2P, with leakage-safe protocols reducing inflated accuracy estimates by 0.08–0.12 MCC compared to flawed random splitting.

## Executive Summary
This paper tackles critical flaws in experimental practices for financial risk detection in ERP systems, primarily data leakage and inflated performance metrics. It introduces a rigorous leakage-safe nested cross-validation framework incorporating time-aware and group-aware splitting to prevent unrealistic performance estimates. The core method is a stacking ensemble of gradient boosting models evaluated on a new composite benchmark, ERP-RiskBench. The ensemble demonstrates superior detection performance under realistic evaluation protocols. Crucially, the study quantifies the substantial inflation caused by common leakage errors, showing that naive random splitting overestimates model effectiveness by up to 0.12 MCC, rendering prior comparisons potentially invalid.

## Method Summary
The proposed methodology centers on a leakage-safe evaluation protocol and a stacking ensemble. The evaluation uses nested cross-validation with an outer loop (K=5) for performance estimation and an inner loop (K=3) for hyperparameter tuning. Critically, all preprocessing—including imputation, encoding, feature selection, and resampling (SMOTE/CTGAN)—is confined strictly within training folds to prevent any data leakage across temporal or group boundaries. Splits are constructed chronologically and enforce that all records from the same vendor or purchase order remain within a single fold. The predictive model is a stacking ensemble where base learners (XGBoost, LightGBM, CatBoost, Random Forest) generate out-of-fold predictions, which are then used by a logistic regression meta-learner. Final probability outputs are calibrated via Platt scaling, and a cost-sensitive threshold—derived from a misclassification cost matrix—is applied to minimize expected operational cost, prioritizing high recall for rare fraud cases.

## Key Results
- The stacking ensemble consistently achieves the highest detection performance across datasets, e.g., MCC 0.651±0.017, AUPRC 0.629±0.016 on the BPI P2P dataset.
- Leakage-safe time- and group-aware splitting reduces performance inflation dramatically; random stratified splitting inflates MCC by 0.08–0.12 compared to the realistic protocol.
- Probability calibration and cost-sensitive thresholding (with C_FN/C_FP=10) yield operationally optimal decisions, explicitly minimizing expected investigation cost rather than default 0.5 thresholds.

## Why This Works (Mechanism)
### Mechanism 1: Leakage-Safe Evaluation Protocol
A nested cross-validation framework with strict time-aware and group-aware splitting prevents data leakage and yields realistic, deployment-grade performance estimates. Chronological ordering stops future information from contaminating past training folds. Group constraints (by vendor/PO) prevent entity leakage, ensuring no transactional patterns from the same business entity appear in both training and validation. All preprocessing, feature selection, and resampling are fit exclusively on the current training partition and transformed independently on validation/test data. The core assumption is that ERP transactional data exhibits strong temporal dependencies and repeated entity interactions; random IID splitting violates these, creating artificial performance gains. The break condition is ignoring temporal order or group constraints during splitting, which causes leakage and invalid estimates.

### Mechanism 2: Stacking Ensemble Diversity
A stacking ensemble of heterogeneous gradient boosting models (XGBoost, LightGBM, CatBoost, Random Forest) exploits complementary strengths across different feature subspaces and learning biases. Base learners are trained on the same training folds; their out-of-fold predictions form meta-features for a logistic regression meta-learner, which learns an optimal combination. The core assumption is that no single model family dominates across all transaction patterns, and that base learners are sufficiently diverse. The break condition is high correlation among base learners (e.g., using only similar boosting implementations), which eliminates the meta-learner's advantage.

### Mechanism 3: Calibrated Cost-Sensitive Thresholding
Platt scaling calibrates model probabilities, enabling correct application of a cost-sensitive threshold derived from a misclassification cost matrix (C_FN >> C_FP). The optimal threshold τ* = C_FP / (C_FP + C_FN) shifts the decision boundary toward higher recall, minimizing total expected cost. The core assumption is that the cost of a missed fraud (false negative) far exceeds a wasted audit (false positive). The break condition is applying the cost-optimal formula to uncalibrated probabilities, which leads to suboptimal resource allocation.

- **Concept: Data Leakage in Resampling**  
  Applying oversampling (SMOTE/CTGAN) before data splitting incorporates information from the entire dataset into synthetic samples, contaminating validation/test sets and causing severe performance inflation.

  Nested CV separates hyperparameter optimization (inner loop) from final performance estimation (outer loop), preventing optimistic bias from tuning on the test set, which is critical when comparing many model configurations.

## Architecture Onboarding
- **Component map:**  
  Data Ingestion → Canonical Schema Mapping → Time+Group Split → Outer CV Loop (K=5) → Inner CV Loop (K=3) with Leakage-Safe Pipeline → Outer Test Scoring → Metric Aggregation → Calibration & Cost Analysis → Augmented Test Suites (PHTS/SATS)
- **Critical path:** Raw data → canonical schema → chronological split with group constraints → for each outer fold: run inner CV with all preprocessing inside training bounds → select best inner config → refit on full outer train → score outer test → aggregate metrics. Resampling and feature selection must never leave the training boundary.
- **Design tradeoffs:**  
  1. Computation vs. Unbiasedness: Nested CV multiplies compute (K_outer × K_inner) but is non-negotiable for trustworthy estimates.  
  2. Stacking Complexity vs. Gain: Stacking adds meta-learning overhead; gain over single best booster (LightGBM) is statistically significant but often small (~0.02 MCC), may not justify complexity for simple deployments.  
  3. Augmentation Complexity: CTGAN provides marginal recall boost over SMOTE but requires separate generator training per fold, adding significant engineering burden for strict leak-proofing.
- **Failure signatures:**  
  - Data Leakage: Resampling or feature selection applied before outer split.  
  - Metric Inflation: Using random stratified splits instead of time+group; reporting accuracy over MCC/AUPRC.  
  - Uncalibrated Thresholds: Using default 0.5 threshold or cost formula with uncalibrated probabilities.  
  - Explanation Instability: SHAP top-20 feature rank correlation <0.7 across outer folds, indicating unreliable audit justifications.
- **First 3 experiments:**  
  1. **Splitting Protocol Comparison (A5 vs A6):** Train stacking under time+group (A5) vs random stratified (A6). Expect ~0.1 MCC inflation with random split, validating the leakage mechanism.  
  2. **Resampling Ablation (A2 vs A3):** Within time+group, compare SMOTE (A2) vs CTGAN (A3) vs no resampling (A0). Measure minority recall gain to test incremental value of learned augmentation.  
  3. **Statistical Significance of Stacking:** Using outer fold scores, run Wilcoxon signed-rank test (Holm-corrected) comparing stacking vs LightGBM and vs FT-Transformer. Confirms if stacking's edge is robust beyond noise.

## Open Questions the Paper Calls Out
- **Open Question 1:** How do the leakage-safe protocols and the reported performance rankings (e.g., stacking ensemble superiority) generalize to proprietary ERP datasets from live enterprise deployments? The study relies on public logs and synthetic data; real ERP systems may have different structures and fraud patterns.
- **Open Question 2:** How do empirically derived, organization-specific cost ratios (C_FN/C_FP) affect the cost-sensitive thresholding and comparative operational utility of different models? The used ratio (10) is a reasonable assumption but not empirically grounded.
- **Open Question 3:** Do graph-based features constructed from vendor networks and transactional relationships provide a significant performance boost over the current feature set in ERP risk detection? The current set focuses on transactional aggregates; graph features could capture relational fraud patterns.
- **Open Question 4:** How does the framework's performance and leakage-safety guarantees hold when adapted from batch scoring to a streaming or near-real-time scoring architecture? Streaming introduces temporal ordering, drift, and online learning challenges not addressed.

## Limitations
- **ERP-Synth validity:** Synthetic data generation parameters (rule thresholds, CTGAN configs) are underspecified, limiting independent verification of the benchmark's realism and typology distribution.
- **Pipeline ambiguity:** The "Best" configuration (A5) does not clarify whether SMOTE, CTGAN, or both were used, nor the exact feature selection method, blocking exact replication of the reported 0.651 MCC.

## Confidence
- **Leakage-safe protocol efficacy:** High. Strong experimental contrast (0.08–0.12 MCC gap) directly supports the mechanism; break condition is clearly defined.
- **Stacking ensemble advantage:** Medium. Statistical tests show significance, but the diversity assumption relies on heterogeneous base learners; high correlation among them would diminish the gain.
- **Calibration & cost-sensitive thresholding:** Medium-High. Reliability diagrams indicate good calibration, but operational cost reduction depends on accurate, stable cost ratios across folds.

## Next Checks
1. **Replicate leakage inflation magnitude:** Implement both random stratified and time+group splits on BPI P2P. Train a simple model (LightGBM) under each; expect an MCC gap of ~0.1 if leakage is present, confirming the core experimental flaw.
2. **Stress base-learner diversity:** In the stacking ensemble, replace one base model with another highly similar algorithm (e.g., CatBoost → another GBM). Measure drop in MCC/AUPRC; a significant loss (>0.02) supports the diversity-exploitation mechanism.
3. **Audit calibration stability:** For each outer fold, compute Brier score and reliability diagram for Platt-scaled vs. raw probabilities. Check for consistent calibration improvement; inconsistent scaling would invalidate the cost-optimal threshold calculation.
