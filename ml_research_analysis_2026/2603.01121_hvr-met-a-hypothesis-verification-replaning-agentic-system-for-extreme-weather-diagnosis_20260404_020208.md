# HVR-Met: A Hypothesis-Verification-Replaning Agentic System for Extreme Weather Diagnosis

## Quick Facts
- **arXiv ID:** 2603.01121
- **Source URL:** https://arxiv.org/abs/2603.01121
- **Reference count:** 40
- **Primary result:** Achieves 85% pass rate for end-to-end diagnostic reports, 71.86% accuracy for index computation, and 79.52% success for figure generation.

## Executive Summary
Extreme weather diagnosis demands multi-step reasoning, dynamic tool use, and expert judgment, capabilities that current AI systems lack due to poor integration of domain knowledge and absence of iterative validation. HVR-Met addresses this with a multi-agent framework featuring a closed-loop Hypothesis-Verification-Replanning (HVR) mechanism. It leverages a Guideline Library semi-automatically extracted from 584 expert-validated papers to guide diagnostic pathways across seven specialized agents.

In evaluations, HVR-Met achieves an 85% pass rate for complete diagnostic reports, 71.86% accuracy on index computation tasks, and 79.52% success on figure generation. Ablation studies confirm the critical roles of the Guideline Library and core agents (Decomposer, Image Checker, Diagnostician), with their removal causing drastic performance drops. This demonstrates the effectiveness of integrating structured domain knowledge with iterative hypothesis testing in a modular agentic system.

## Method Summary
The system tackles extreme weather diagnosis using WeatherBench2 (ERA5) data, a semi-automatically constructed Guideline Library from 584 papers, and tool knowledge bases (MetPy, Cartopy, Matplotlib). The objective is to produce end-to-end diagnostic reports with high quality, measured by pass rate (LLM score >4/5), index accuracy (relative error <0.05), and figure generation success (VLM QA alignment).

HVR-Met orchestrates seven agents without training: Decomposer plans using guideline templates; Data Specialist retrieves data and computes indices via RAG on MetPy; Code Executor runs code; Plotter generates visualizations via RAG on Cartopy; Image Checker validates figures; Diagnostician integrates evidence and verifies hypotheses; Reporter synthesizes reports. The core innovation is the closed-loop HVR mechanism: after initial hypothesis generation, the system computes indices and plots, then the Diagnostician checks visual-physical alignment. If evidence is insufficient, the system rejects the hypothesis, records the result, and replans by querying the guideline library, iterating until convergence.

## Key Results
- **End-to-end report pass rate:** 85% (LLM score >4/5).
- **Index computation accuracy:** 71.86% of tasks achieve relative error <0.05.
- **Figure generation success:** 79.52% of figures pass VLM-based quality assessment.
- **Ablation insights:** Removing the Guideline Library drops final report score to 0.40/5; eliminating Decomposer, Image Checker, or Diagnostician leads to severe degradation across hypothesis, data, figure, and report scores.

## Why This Works (Mechanism)
HVR-Met's effectiveness stems from three synergistic mechanisms. First, the closed-loop Hypothesis-Verification-Replanning (HVR) mechanism enables iterative refinement: the system generates an initial hypothesis from the Guideline Library, computes indices and figures, and the Diagnostician evaluates evidence alignment. Discrepancies trigger hypothesis rejection and replanning, mimicking expert forecaster intuition. Second, the semi-automatically constructed, expert-validated Guideline Library provides domain-specific prior knowledge, ensuring strategic selection of relevant indices and visualizations rather than relying on generic LLM knowledge. Third, role specialization across seven agents modularizes the complex workflow, enforcing domain constraints (e.g., unit safety via MetPy) and quality gates (e.g., plot validation), which together maintain rigorous execution of each subtask. Ablation studies confirm that removing any of these components—especially the library or core agents—causes severe performance degradation, underscoring their necessity.

- **Concept: Closed-Loop Reasoning with Hypothesis Testing**  
  *Why needed:* The HVR mechanism is a form of abductive reasoning; the system actively tries to falsify its hypothesis and must have a fallback (replanning) from the guideline library.  
  *Quick check:* "What specific evidence would cause the Diagnostician to reject an initial 'low-level moisture convergence' hypothesis for a rainstorm, and what would trigger the next cycle?"

## Architecture Onboarding
**Component map:**  
The system comprises seven agents with specialized roles:
- Decomposer: Strategic planner; outputs numbered task list referencing guideline templates.
- Data Specialist: Fetches data and computes indices using RAG from MetPy docs; ensures rigorous preprocessing and numerical precision.
- Code Executor: Sandbox; executes all Python code; returns stdout/stderr.
- Plotter: Generates visualization code using RAG on Cartopy/Matplotlib docs; outputs .png.
- Image Checker: QA for plots; inspects saved figures; suggests refinements (smoothing, contour intervals, etc.).
- Diagnostician: Reasoning engine; integrates indices + figures + guideline knowledge; outputs hypothesis validation status.
- Reporter: Final synthesis; compiles reasoning trace and evidence into report.

**Critical path:**  
Query → Decomposer (plan) → Data Specialist (fetch/calc) → Code Executor (run) → (if indices ready) → Plotter (code) → Code Executor (run) → (if figure saved) → Image Checker (validate, may iterate) → Diagnostician (integrate & verify hypothesis) → (if hypothesis rejected, return to Decomposer with updated context) → Reporter (final report).

**Design tradeoffs:**
- *Specialization vs. flexibility:* Strict agent roles ensure quality (e.g., unit safety) but reduce adaptability; a failed agent requires explicit replanning.
- *Knowledge base dependency:* Performance tightly coupled to guideline library completeness and tool documentation accuracy; gaps cause cascading failures.
- *Verification overhead:* The HVR loop adds computational cost by potentially re-running data/plot cycles, trading speed for reliability.

**Failure signatures:**
- Hypothesis score << 4: Decomposer retrieving incorrect/incomplete guideline templates.
- Data score < 5 but > 0: Data Specialist fetching wrong variables or spatiotemporal extent.
- Figure score drop (e.g., 4.13 → 2.98): Image Checker absent or plot code violating meteorological standards.
- Final Report << 4 while sub-tasks moderate: Diagnostician failing at multimodal integration or HVR loop stuck.

**First 3 experiments:**
1. **Guideline Library Retrieval Test:** Provide a 'heat wave' event. Verify Decomposer's plan includes indices/figures from the *Heat Wave* category template covering all three physical dimensions (moisture, thermal, dynamics) per scoring criteria.
2. **Index Calculation Execution Test:** Run a 'medium difficulty' index (e.g., Warm Advection Center Intensity). Check Data Specialist's code uses `.metpy.assign_units()`, correct MetPy function call, saves to `./nc/`. Validate output relative error < 0.05.
3. **HVR Loop Termination Test:** Provide an event where initial hypothesis is correct. Inject an anomalous signal that should validate it; Diagnostician must output "hypothesis validated" and proceed to Reporter without replanning. Then invert the signal to test rejection and replanning.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can the semi-automatic construction of the Guideline Library be scaled to cover a broader range of extreme weather types and updated automatically with new research?
- **Open Question 2:** What happens when the HVR replanning mechanism encounters an anomalous signal that has no corresponding alternative hypothesis in the Guideline Library?
- **Open Question 3:** Does the evaluation benchmark adequately represent the global diversity of extreme weather events in terms of geography, climate zones, and event frequency?
- **Open Question 4:** Can the seven-agent architecture be simplified (e.g., by merging roles or using fewer agents) without significant loss in diagnostic performance?

## Limitations
- The 584-paper guideline library and the full benchmark dataset are unreleased, blocking exact replication and external validation.
- Ablation results demonstrate internal necessity but cannot confirm generalizability to new event types or data sources beyond WeatherBench2.
- Identified break conditions (e.g., HVR loop stalling if all hypotheses fail) are theoretical; the paper does not report their frequency or mitigation strategies.
