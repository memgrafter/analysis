# Expected Reward Prediction, with Applications to Model Routing
## Quick Facts
- arXiv ID: 2603.20217
- Source URL: https://arxiv.org/abs/2603.20217
- Reference count: 9
- Primary result: Demonstrates that expected reward for a model on a prompt can be predicted from prompt embeddings, enabling cost-aware routing that matches oracle performance and scales linearly to new models.

## Executive Summary
Model routing dynamically selects the most suitable large language model for a given prompt, balancing quality and cost. This paper investigates whether we can predict a model’s expected reward on a prompt before generating any response, using only a cheap prompt embedding. The authors train linear predictors on off-the-shelf text embeddings to estimate each model’s expected reward, then route by maximizing predicted reward minus a cost penalty. Extensive experiments across multiple models, reward models, and prompt categories show that expected rewards are highly predictable (test R² up to 0.59). The resulting Expected Reward Prediction (ERP) policy attains a Pareto frontier that dominates common baselines (random, per-category best) and matches an oracle—all without requiring prompt category labels. ERP also matches the performance of more complex pairwise routers while being trivially extensible to new models.

## Method Summary
ERP operates in two phases. Training: For each candidate LLM, sample K responses per training prompt, score them with a reward model, and compute the empirical mean reward (cER). Simultaneously, embed each prompt with a frozen embedding model (e.g., gte-large). Then fit a ridge-regularized linear model to predict cER from the embedding, separately for each LLM. Inference: Given a new prompt, compute its embedding, then for each LLM compute the predicted cER minus λ·cost(i) (where λ controls the cost-quality tradeoff). Route to the model with the highest score. This approach requires no prompt category labels, trains independently per model, and scales linearly with the number of models.

## Key Results
- High predictability: Expected reward can be predicted from prompt embeddings with test R² up to 0.59 within categories, across all studied LLM/reward model pairs.
- Effective routing: ERP establishes a Pareto frontier that strictly dominates random and per-category best baselines, and matches the oracle’s performance without using category information.
- Simplicity and scalability: ERP matches the performance of more complex pairwise routers (e.g., Zooter) while being trivially extensible to new models.

## Why This Works (Mechanism)
The success of ERP rests on three interconnected mechanisms.

**Implicit absolute reward scale**: Despite the Bradley-Terry objective only guaranteeing meaningful differences between responses to the same prompt, reward models fine-tuned from pretrained LMs end up using a consistent absolute scale across prompts. Training data covers many prompts with few responses per prompt, which biases the model to learn a global scale rather than arbitrary prompt-specific offsets. Consequently, the expected reward (mean of scores for a prompt) becomes a learnable quantity.

**Linear predictability from embeddings**: Off-the-shelf text embeddings (e.g., gte-large) encode semantic features that correlate strongly with model performance as measured by the reward model. A linear probe on these embeddings suffices to predict expected reward accurately because the signal-to-noise ratio is high enough for linear separability. The observed R² values confirm this.

**Routing by expected reward**: Assuming per-prompt reward distributions are subgaussian (light-tailed), the difference in expected rewards between models bounds the probability that one model will produce a higher-reward response than another (Proposition 1). Thus, selecting the model with highest predicted expected reward (adjusted for cost) effectively maximizes expected reward under a cost constraint. Empirical results validate that ERP approximates the oracle and outperforms simpler strategies.

## Foundational Learning
- **Bradley-Terry Reward Modeling**: The standard method for training reward models on pairwise preferences; it only identifies relative differences, not absolute values, making ERP’s success non‑obvious. *Quick check*: Does the Bradley‑Terry objective trained on pairwise preferences identify an absolute reward scale across prompts? Why or why not?
- **Subgaussian Random Variables**: Distributions with tails no heavier than Gaussian; Proposition 1 assumes reward outcomes are subgaussian to relate expected reward gaps to win probabilities. *Quick check*: If reward outcomes are subgaussian with variance σ², what does a larger gap in expected rewards imply about the probability that one model beats another?
- **Linear Probing on Frozen Embeddings**: A common technique where a linear classifier is trained on fixed pretrained representations. The paper uses this to predict expected reward from prompt embeddings. *Quick check*: Why might a linear model on a frozen embedding suffice for predicting expected reward, even though reward modeling is complex and nonlinear?

## Architecture Onboarding
**Component map**: Prompt text → embedding model (gte-large) → embedding vector → per‑model linear predictor (θ_i) → predicted expected reward cER_i. Routing: for each model i compute (cER_i - λ·cost(i)), select argmax.

**Critical path**:
- Training: For each LLM π_i, generate K responses per prompt, score with reward model, compute empirical cER_i. Train ridge regression θ_i on (embedding, cER_i) for training prompts.
- Inference: Given prompt x, compute embedding v(x). For each i, score s_i = θ_i^T v(x) - λ·cost(i). Route to model with maximum s_i.

**Design tradeoffs**:
- Linear vs. nonlinear predictor: Linear is simple, interpretable, and requires less data; nonlinear (e.g., MLP) could capture more complex patterns but risks overfitting.
- Per‑model vs. pairwise predictors: Per‑model scales linearly with the number of models; pairwise (e.g., Zooter) scales quadratically but directly models preferences between model pairs.
- Cost proxy: Parameter count is used; alternative cost metrics (latency, memory) may change routing decisions.

**Failure signatures**:
- Negative or very low test R² for certain model/reward/category combinations, indicating poor generalizability.
- Large discrepancies between predicted and actual win rates, or ERP Pareto frontier dominated by baselines.
- Out‑of‑memory errors during response generation for large models.
- High variance in empirical cER when using small K (number of sampled responses).

**First 3 experiments**:
1. Predictability within categories: Train per‑model linear predictors and evaluate test R², both overall and per prompt category.
2. Pairwise win prediction: Use predicted cER differences to predict which model’s response will be preferred; compare AUROC against a logistic regression trained on pairwise preference data.
3. Full routing evaluation: Run ERP and baselines on test prompts for a range of λ values; plot regret vs. total cost to assess the Pareto frontier.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Why is expected reward prediction effective despite the theoretical non‑identifiability of absolute reward scales under standard Bradley‑Terry models?
- **Basis in paper:** The introduction notes that reward models only guarantee relative ordering, so expected reward “need not be learnable even in principle.” The discussion explicitly calls for understanding the classes of reward models for which ERP is effective.
- **Why unresolved:** The paper shows empirical success but does not explain how the arbitrary prompt‑dependent offset in reward models becomes predictable from prompt embeddings.
- **What evidence would resolve it:** Probing internal representations of reward models for implicit normalization across prompts, or controlled experiments with modified reward models that alter the offset structure.

### Open Question 2
- **Question:** What specific properties of reward models (e.g., training data, architecture, objectives) determine the variability in predictability across models and prompt categories?
- **Basis in paper:** The discussion urges investigation into the classes of reward models affecting predictability. Results show large differences: e.g., GRM‑2B‑RM has negative R² in math for Llama3.1‑8B.
- **Why unresolved:** The paper tests three reward models but does not analyze the underlying reasons for these disparities, particularly in specific categories like math.
- **What evidence would resolve it:** Systematic ablation studies varying reward model training regimes, dataset diversity, and model sizes, correlated with prediction R² scores.

### Open Question 3
- **Question:** Does the simplicity of linear predictors limit expected reward prediction accuracy, and would more complex models (e.g., neural networks) significantly improve performance, especially for underperforming reward models?
- **Basis in paper:** The method uses ridge‑regularized linear models exclusively, justified by simplicity and strong results. However, some R² values drop below zero.
- **Why unresolved:** No comparison to non‑linear baselines is provided; the linear assumption is not validated as optimal.
- **What evidence would resolve it:** Repeat experiments with neural network predictors (e.g., MLPs) on the same embeddings and report changes in R², particularly for low‑performing combinations.

### Open Question 4
- **Question:** How does the scalability of ERP‑based routing hold as the number of models in the pool grows, in terms of data efficiency and regret‑cost tradeoffs compared to pairwise routing methods?
- **Basis in paper:** The paper claims ERP is “trivially extensible” and scales linearly, whereas pairwise methods scale quadratically. Experiments involve only 5 models.
- **Why unresolved:** The scalability claim is not empirically tested beyond a small pool; data requirements and performance degradation with more models are unknown.
- **What evidence would resolve it:** Run routing experiments with increasingly large model pools (e.g., 10, 20 models), measuring regret versus cost and amount of per‑model data needed to train predictors.

## Limitations
- Generalizability: Results are limited to the specific set of models, reward models, and the open‑perfectblend prompt distribution; performance may degrade on other datasets or model types.
- Embedding dependence: The method relies on the gte‑large embedding; alternative embeddings (e.g., BGE, OpenAI) might yield lower predictability.
- Cost approximation: Using parameter count as a proxy for cost may not reflect actual deployment constraints (e.g., latency, memory), potentially leading to suboptimal routing decisions.

## Confidence
- Implicit absolute reward scale (Mechanism 1): Medium
- Linear predictability of expected reward (Mechanism 2): Medium
- ERP routing effectiveness (Mechanism 3): High

## Next Checks
1. Cross‑dataset robustness: Evaluate ERP on prompts from a held‑out distribution (e.g., MT‑Bench or AlpacaEval) to test generalizability beyond open‑perfectblend.
2. Nonlinear probe ablation: Replace ridge regression with a small MLP (1–2 hidden layers) on the same embeddings; compare test R² and routing regret to quantify benefit.
3. Subgaussianity diagnostics: For each model/reward pair, compute kurtosis and perform normality tests on per‑prompt reward distributions to verify the subgaussian assumption underlying Proposition 1.
