# TourPlanner: A Competitive Consensus Framework with Constraint-Gated Reinforcement Learning for Travel Planning

## Quick Facts
- **arXiv ID:** 2601.04698
- **Source URL:** https://arxiv.org/abs/2601.04698
- **Reference count:** 40
- **Primary result:** Achieves 100% Feasibility Pass Rate and 56.1% Final Pass Rate on the TripTailor benchmark through spatially-aware candidate selection, competitive consensus planning, and constraint-gated reinforcement learning.

## Executive Summary
TourPlanner addresses three core challenges in automated travel planning: pruning points of interest (POIs) without losing relevant options, escaping the limitations of single-path reasoning, and jointly optimizing hard feasibility constraints with soft user-preference constraints. It introduces a three-part framework: Personalized Recall and Spatial Optimization (PReSO) constructs a spatially coherent candidate set; Competitive consensus Chain-of-Thought (CCoT) uses multiple specialized agents to generate and arbitrate parallel proposals; and a constraint-gated reinforcement learning mechanism dynamically balances hard and soft constraint optimization. On the TripTailor benchmark, the system achieves state-of-the-art performance, including perfect feasibility and significant improvements in preference alignment and route efficiency.

## Method Summary
The framework begins with PReSO, which extracts user demands and retrieves POIs via three branches (semantic similarity, high-rated attractions, LLM supplement). Retrieved POIs are clustered spatially using DBSCAN to integrate nearby accommodations and restaurants, producing a geographically compact candidate set. For each travel day, CCoT instantiates 4–6 specialized agents with distinct objectives (e.g., budget, diversity). Each agent refines a base skeleton plan in parallel. Proposals are weighted by diversity (inverse average similarity), peer-reviewed, and fused by an LLM arbiter to produce a consensus itinerary. Finally, constraint-gated reinforcement learning (using GSPO) refines consensus plans. The reward combines hard-constraint (`R_hard`) and soft-constraint (`R_soft`) scores, modulated by a sigmoid gate `α(η) = 1/(1+e^{-k(η-τ)})` that suppresses `R_soft` until the hard-constraint score `η` exceeds a threshold `τ`.

## Key Results
- PReSO achieves a 42.3% POI recall rate, a 14.4% absolute improvement over the TripTailor baseline.
- CCoT raises Macro Rationality Pass Rate to over 88% from below 30% in baseline methods.
- The full system attains 100% Feasibility Pass Rate, 56.1% Final Pass Rate, 30.2% Final Surpassing Rate, and reduces Average Route Distance Ratio to 2.15.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** PReSO’s spatially-aware candidate construction increases relevant POI recall while controlling context length.
- **Mechanism:** A three-branch recall (semantic similarity, high-rated attractions, LLM supplement) followed by DBSCAN spatial clustering integrates POIs with nearby accommodations/restaurants. Cluster labels are added as contextual attributes.
- **Core assumption:** Geographically compact candidate sets improve route efficiency and reduce irrelevant options without sacrificing recall of ground-truth POIs.
- **Evidence anchors:** [abstract] “constructs a spatially-aware candidate POI set using a three-branch recall and clustering, achieving a 42.3% recall rate—a 14.4% absolute improvement”; [section 3.2] details the three recall branches and DBSCAN anchoring; corpus shows spatial clustering is used but not coupled with multi-dimensional recall.
- **Break condition:** If spatial clustering over-constrains the candidate set (e.g., too few clusters for a dispersed destination), recall of relevant ground-truth POIs would drop, harming downstream plan quality.

### Mechanism 2
- **Claim:** CCoT’s competitive consensus resolves multi-objective conflicts and expands feasible solution space exploration beyond single-path reasoning.
- **Mechanism:** Instantiate specialized agents (Identity, Objective, Priorities). Each modifies a base skeleton in parallel. Proposals are weighted by diversity (inverse average similarity), peer-reviewed (score + critique), and top-k are fused by an LLM arbiter.
- **Core assumption:** Multiple, deliberately conflicting reasoning trajectories, when arbitrated via diversity-weighted peer review, yield a balanced plan satisfying hard constraints and diverse preferences better than a monolithic reasoning path.
- **Evidence anchors:** [abstract] “increasing Macro Rationality Pass Rate to over 88% from below 30% in baseline methods”; [section 3.3] describes the three-phase arbitration; corpus shows multi-agent coordination is active but CCoT’s specific protocol is novel.
- **Break condition:** If agent objectives are poorly calibrated or diversity weighting collapses, consensus degrades to a lowest-common-denominator plan, reducing rationality.

### Mechanism 3
- **Claim:** The sigmoid-based gating in RL decouples hard and soft constraint optimization, preventing soft-constraint rewards from destabilizing feasibility learning.
- **Mechanism:** Total reward `R = R_hard + α(η)·R_soft`, where `α(η) = 1/(1+e^{-k(η-τ)})`. `η` is hard-constraint score. When `η < τ`, `α ≈ 0`, forcing focus on `R_hard`. Once `η ≥ τ`, `α` rises rapidly to include `R_soft`.
- **Core assumption:** A curriculum-like gating signal prevents the policy from being prematurely pulled toward dense soft rewards before mastering sparse hard constraints, which are prerequisites for a feasible plan.
- **Evidence anchors:** [abstract] “dynamically prioritizes soft-constraint optimization only after hard constraints are met, raising the Final Surpassing Rate to 30.2%”; [section 3.4] contrasts with Vanilla RL’s failure; corpus does not validate this exact approach.
- **Break condition:** If threshold `τ` is set too high, soft constraints are never optimized; if too low, the gate fails to shield early learning from soft-reward noise, leading to feasibility collapse.

## Foundational Learning
- **Concept: Retrieval-Augmented Generation (RAG) & Spatial Indexing**  
  Why needed: PReSO’s recall stage is a form of constrained RAG. Understanding embedding-based similarity, keyword expansion, and density-based clustering (DBSCAN) is prerequisite to grasp candidate pruning.  
  Quick check: How does DBSCAN’s `eps` parameter affect the granularity of spatial clusters, and what is the trade-off with the number of candidate POIs retained?

- **Concept: Multi-Agent Systems & Consensus Mechanisms**  
  Why needed: CCoT models a committee of specialized agents. Prerequisites include understanding how to define agent personas/objectives, parallel proposal generation, and arbitration protocols (voting, weighted sum, peer review).  
  Quick check: In CCoT’s diversity weighting, why is the weight set inversely proportional to average peer similarity? What would happen if it were directly proportional?

- **Concept: Reinforcement Learning with Reward Shaping & Gating**  
  Why needed: The RL refinement stage uses a curriculum-style gated reward. Prerequisites include understanding sparse vs. dense rewards, policy gradient methods (GSPO), and how to design a gating function that modulates reward components based on a binary feasibility signal.  
  Quick check: If the hard-constraint score `η` is a continuous [0,1] value, what are the implications of using a sigmoid vs. a step function for `α(η)` in terms of training stability?

## Architecture Onboarding
- **Component map:** User Query → PReSO Pipeline (Demand Extraction → Multi-dimension Recall → DBSCAN Clustering) → Spatially-tagged Candidate Set → CCoT Loop (per day: Agent Instantiation → Base Skeleton → Parallel Refinement → Diversity Weighting → Peer Review → Consensus Fusion) → Consensus Plan → Constraint-Gated RL (GSPO Rollouts → Reward Calculation → Sigmoid Gating → Policy Update) → Refined Plan.
- **Critical path:** User query must flow through PReSO first to constrain context. CCoT then day-by-day builds the plan, with each day’s consensus depending on prior days’ selections (non-repetition constraint). RL operates after CCoT produces a complete draft plan, refining it via multiple rollouts.
- **Design tradeoffs:**  
  - **Agent count (CCoT):** More agents increase diversity but raise computational cost and risk of consensus dilution. Paper finds 4–6 agents optimal; 10 agents yields diminishing returns.  
  - **Gating sharpness (k):** Higher `k` makes the transition from hard to soft focus sharper (more curriculum-like), but may cause abrupt policy shifts. Lower `k` provides smoother annealing but risks premature soft-reward interference.  
  - **Recall breadth vs. context:** PReSO’s recall dimensions (3×duration, 9×duration) must balance candidate richness against LLM context window limits.
- **Failure signatures:**  
  - **PReSO failure:** Recall rate < baseline (~27–28%). Symptom: Generated plans miss many ground-truth POIs. Check: Are clusters too sparse? Is LLM supplement underperforming?  
  - **CCoT failure:** Macro Rationality Pass Rate near baseline (<30%). Symptom: Consensus plan has hard constraint violations or fails diversity objectives. Check: Are agent objectives too overlapping? Is diversity weighting ineffective?  
  - **RL failure:** Final Pass Rate drops after RL (vs. TourPlanner w/o RL). Symptom: Soft constraint optimization harms feasibility. Check: Is `τ` misconfigured? Is `R_soft` improperly normalized?  
  - **Output violations:** Itineraries violate hard constraints (hallucinations, time conflicts). Diagnostic: Run automatic feasibility checks; identify violation patterns.  
  - **Poor spatial coherence:** High route distance ratio. Diagnostic: Analyze POI cluster assignments and transfer distances; check if clustering aligns with geography.
- **First 3 experiments:**  
  1. **Ablate PReSO:** Replace with TripTailor’s recall. Expect significant drop in recall rate and downstream Final Pass Rate, confirming candidate set quality is foundational.  
  2. **Vary CCoT agents:** Systematically change number of agents (3, 4–6, 10). Expect a peak in Macro Rationality and Final Pass Rate at 4–6, validating the “sweet spot” and the cost of over-diversification.  
  3. **Test gating functions:** Compare Constraint-Gated RL against Vanilla RL and ablated gating (e.g., linear `α(η)`). Expect gated version to uniquely maintain high Feasibility Pass rate (100%) while improving Final Surpassing Rate, proving the gating’s role in balancing objectives.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can end-to-end reinforcement learning be effectively integrated with the multi-day, iterative CCoT planning process, given the difficulty of defining a suitable process reward function?  
  Basis: Limitations state that due to CCoT’s iterative nature, defining an effective process reward is challenging, as travel planning rewards depend on overall trip quality.
- **Open Question 2:** How can reward models be more closely aligned with user preferences to increase the Final Surpassing Rate, given the limited exploration of reward mechanisms in this study?  
  Basis: Limitations state that reward model exploration is limited, primarily adopting previous work’s methodology; future research should align rewards more closely with user preferences.
- **Open Question 3:** Does the optimal number of specialized agents in CCoT depend on query complexity, and how can the system dynamically determine the appropriate ensemble size?  
  Basis: Paper ablates agent counts (3, 4–6, 10) and finds a sweet spot at 4–6, but queries vary in conflicting objectives; an adaptive mechanism could improve performance and efficiency.
- **Open Question 4:** Are there more effective gating mechanisms than the fixed sigmoid function to balance hard and soft constraint optimization during RL refinement?  
  Basis: The gating mechanism is a design choice not thoroughly explored; alternative strategies (e.g., step functions, adaptive thresholds, learned gates) might provide a better trade-off.

## Limitations
- **Reproducibility gaps:** Critical hyperparameters and implementation details are unspecified (e.g., exact embedding model for semantic recall, base skeleton prompt in CCoT, RL training data collection protocol, full hardware specs).
- **Benchmark specificity:** Claims are validated solely on the Chinese-city TripTailor benchmark; generalization to other geographies, languages, or POI distributions is unknown.
- **Component isolation:** The reported SOTA performance is for the full system; the independent and interactive contribution of each module to final metrics is asserted but not fully disentangled via comprehensive ablations across all downstream metrics.

2. **Stress-test CCoT diversity:** Deliberately set agent objectives to be highly overlapping (e.g., all prioritize “budget”) and measure the change in Macro Rationality Pass Rate and plan diversity metrics.
3. **Compare gating functions:** Replace the sigmoid gate with a linear or step function (same `τ`) in the RL stage. Compare Final Surpassing Rate and Feasibility Pass Rate stability across training epochs.
