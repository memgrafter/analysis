# SpecForge: A Flexible and Efficient Open-Source Training Framework for Speculative Decoding

## Quick Facts
- **ArXiv ID:** 2603.18567
- **Source URL:** https://arxiv.org/abs/2603.18567
- **Reference Count:** 29
- **Primary Result:** SpecForge accelerates EAGLE-3 training by up to 9.99×, while SpecBundle draft models achieve up to 4.48× end-to-end inference speedup on SGLang.

## Executive Summary
SpecForge is an open-source framework designed to overcome key barriers in speculative decoding adoption: the scarcity of high-quality draft models, subpar performance of existing open-source drafts, and the absence of scalable training infrastructure. It introduces a production-oriented training framework featuring target-draft decoupling with hybrid parallelism—leveraging SGLang for the frozen large target model and FSDP for the lightweight draft model—alongside optimized kernels for the Training-Time Test procedure. The framework integrates seamlessly with inference engines for deployment. Coupled with SpecBundle, a suite of EAGLE-3 draft models trained on diverse corpora, SpecForge delivers substantial training acceleration and inference speedups across major LLM families, while optimized attention kernels drastically reduce execution time and memory footprint.

## Method Summary
The core method decouples training of the target and draft models to optimize resource utilization. It employs hybrid parallelism: the large frozen target model is handled by SGLang, which manages memory-efficient inference, while the smaller draft model is trained using FSDP for scalability. A specialized Training-Time Test procedure with optimized kernels ensures draft quality during training. The framework is designed for direct integration with inference engines like SGLang, enabling immediate deployment. The authors also release SpecBundle, a collection of EAGLE-3 draft models pretrained on extensive, diverse corpora to cover major LLM families, addressing the draft model scarcity problem.

## Key Results
- **Training Acceleration:** Up to 9.99× faster EAGLE-3 training for Qwen3-235B-A22B compared to FSDP-only baselines.
- **Inference Speedup:** SpecBundle drafts achieve up to 4.48× end-to-end speedup on SGLang versus autoregressive decoding and a 1.3× improvement over prior open-source draft checkpoints.
- **Kernel Efficiency:** Optimized attention kernels reduce execution time by 62.1% and peak memory by 93.5% at a sequence length of 4096.

## Why This Works (Mechanism)
Based on the description, the framework’s effectiveness stems from two key innovations: decoupled training and hybrid parallelism. The target model remains frozen and its inference is offloaded to SGLang, which provides memory-efficient serving. The draft model is trained using Fully Sharded Data Parallel (FSDP), enabling scalable distribution across multiple GPUs. During training, a Training-Time Test procedure evaluates the draft model’s generation quality on-the-fly, using optimized attention kernels that reduce overhead. This setup allows rapid iteration while maintaining draft quality. The hybrid parallelism minimizes memory contention between the large target and the draft, and the kernel optimizations cut computation time and memory usage, directly contributing to the reported speedups.

## Foundational Learning
SpecForge builds on the speculative decoding paradigm (notably EAGLE-3) and leverages existing systems: SGLang for efficient target inference and FSDP for distributed training. It addresses a critical gap—the scarcity of high-quality open-source draft models—by releasing SpecBundle, a suite of EAGLE-3 drafts pretrained on diverse corpora covering major LLM families. The work demonstrates how to integrate training and inference pipelines in an open-source framework, providing a template for future speculative decoding research.

## Architecture Onboarding
**Component map:** The system comprises a frozen large target model, a smaller draft model, the SGLang engine (for target inference), an FSDP-based training loop (for the draft), a Training-Time Test module with custom attention kernels, and an integration layer for deployment in inference engines like SGLang.  
**Critical path:** During each training step, data is loaded → target model generates hidden states via SGLang → draft model computes loss → Training-Time Test runs a forward pass with optimized kernels to assess draft quality → update draft parameters via FSDP.  
**Design tradeoffs:** Decoupling target and draft adds integration complexity but allows each subsystem to use the most suitable parallelization (SGLang for memory-bound inference, FSDP for compute-bound training). The custom kernels are tuned for specific sequence lengths (e.g., 4096) and may require adaptation for other lengths or attention patterns.  
**Failure signatures:** Degraded draft quality manifests as low acceptance rates in the Training-Time Test; kernel performance may regress outside the validated configuration; integration issues can arise if the inference engine APIs evolve.  
**First experiments:** The authors measured training speedup on Qwen3-235B-A22B (up to 9.99×), inference throughput with SpecBundle on SGLang (up to 4.48×), and kernel benchmarks showing 62.1% time and 93.5% memory reductions at sequence length 4096.

## Open Questions the Paper Calls Out
While the paper does not explicitly enumerate open questions, its discussion of limitations and future work hints at several: the generalizability of optimized kernels beyond 4096 tokens, broader coverage of LLM families in SpecBundle, and the overhead of integrating with diverse inference engines. These points suggest avenues for further research and system refinement.

## Limitations
- Claimed speedups ("up to") lack detailed experimental setup (hardware, batch sizes, datasets), hindering reproducibility.
- Optimized attention kernel benefits are validated only at 4096 sequence length; generalizability to other lengths and attention types (e.g., sliding window) is uncertain.
- SpecBundle's coverage of LLM families and diversity of its training corpora remain unspecified, limiting assessment of its broad applicability.
- Integration overhead and compatibility challenges with inference engines (e.g., SGLang) are not evaluated.
