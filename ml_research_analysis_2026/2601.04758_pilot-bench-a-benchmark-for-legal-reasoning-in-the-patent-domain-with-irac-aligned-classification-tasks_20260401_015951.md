# PILOT-Bench: A Benchmark for Legal Reasoning in the Patent Domain with IRAC-Aligned Classification Tasks

## Quick Facts
- **arXiv ID:** 2601.04758
- **Source URL:** https://arxiv.org/abs/2601.04758
- **Reference Count:** 40
- **Primary Result:** Closed-source LLMs (e.g., GPT-o3, Claude) achieved >0.75 Micro-F1 on Issue Type; best open-source (Qwen-8B) lagged ~0.56.

## Executive Summary
PILOT-Bench introduces a benchmark for evaluating legal reasoning in patent appeals by aligning 18K PTAB ex parte decisions with USPTO patent data. It defines three IRAC-aligned classification tasks (Issue Type, Board Authorities, Subdecision) and uses an opinion split to isolate arguments from the Board's reasoning. Zero-shot evaluations show closed-source models significantly outperform open-source ones, with role-separated inputs yielding the best results.

## Method Summary
The dataset construction involved collecting PTAB decisions via the USPTO API and linking them to USPTO patent data. Each decision was segmented into four roles (appellant arguments, examiner findings, etc.) using an LLM-based pipeline, with the Board opinion excluded to force reasoning on raw inputs. The three tasks are multi-label (Issue Type: 5 labels; Board Authorities: 9 labels) and multi-class (Subdecision: 23 fine/6 coarse labels). Input variants: Split (separate arguments/findings), Merge (combined), Split+Claim (with claims added). Models were evaluated zero-shot via instruction prompts, with JSON outputs normalized and compared to gold labels.

## Key Results
- Closed-source models (GPT-o3, Claude) consistently exceeded 0.75 Micro-F1 on Issue Type; the strongest open-source model (Qwen-8B) achieved ~0.56, revealing a substantial reasoning gap.
- All models exhibited low Macro-F1, indicating difficulty with rare labels.
- Role-separated inputs (Split) performed best; augmenting with claim text generally degraded performance, particularly for Board Authorities.

## Why This Works (Mechanism)
The opinion split removes the Board's own reasoning from the input, preventing the model from simply copying the final decision. This forces the model to perform independent legal reasoning based on the appellant's arguments and examiner's findings. The tasks align with the IRAC framework (Issue, Rule, Application, Conclusion), ensuring the benchmark measures structured legal reasoning rather than superficial pattern matching.

## Foundational Learning
- **IRAC Method**: A cornerstone of legal analysis that structures reasoning into Issue, Rule, Application, and Conclusion; essential for understanding how the benchmark frames tasks. *Quick check*: What does IRAC stand for?
- **PTAB Ex Parte Appeals**: The specific patent adjudication context where the Patent Trial and Appeal Board hears ex parte appeals; required to interpret decision contents. The dataset comprises 18K PTAB ex parte decisions. *Quick check*: What is the role of the PTAB?
- **Multi-Label Classification**: The tasks Issue Type and Board Authorities require predicting multiple applicable labels; essential for evaluating a model's ability to handle overlapping legal concepts. Issue Type has 5 labels and Board Authorities has 9 labels. *Quick check*: How does multi-label differ from multi-class classification?
- **Zero-Shot Evaluation**: Tests model reasoning without fine-tuning; crucial for assessing inherent capabilities. Models are evaluated via instruction prompts without any task-specific training. *Quick check*: What is the difference between zero-shot and few-shot prompting?
- **Opinion Splitting**: The segmentation of decisions into functional roles (appellant arguments, examiner findings, etc.) with the Board opinion excluded; key to creating unbiased inputs. This forces models to reason from raw materials rather than copying the Board's decision. *Quick check*: Why exclude the Board's opinion from the input?

## Architecture Onboarding
**Component Map**  
Raw PTAB Decisions -> Opinion Split -> Input Prompt Construction -> LLM Inference -> JSON Output -> Normalization -> Evaluation Metrics

**Critical Path**  
Data collection (USPTO API) → Opinion splitting (LLM-based) → Task-specific prompt generation → Model query → Parse JSON → Compare with gold labels → Compute metrics.

**Design Tradeoffs**
- *Split vs Merge*: Separate roles preserve discourse structure but require longer context; merging simplifies but may dilute role-specific cues.
- *Adding Claims*: Claims provide patent scope information but increase input length and often harms performance, indicating models struggle with extraneous legal text.
- *Open vs Closed Models*: Closed-source models offer better instruction following and formatting reliability; open-source models require robust post-processing.

**Failure Signatures**
- Invalid/non-JSON responses (common in open-source models)
- Low Macro-F1 despite decent Micro-F1, indicating poor performance on rare labels.
- Context overflow when using Split+Claim for models with small context windows.

**First Three Experiments**
1. Replicate the paper’s zero-shot evaluation on GPT-o3 and Qwen-8B using the provided prompts and splits to confirm the reported gap.
2. Test constrained decoding (e.g., with `outlines`) on Qwen-8B to quantify reduction in invalid outputs and Macro-F1 improvement.
3. Perform error analysis stratified by label frequency to isolate whether low Macro-F1 stems from underrepresentation or inherent confusion.

## Limitations
- Exact opinion-split generation prompts and LLM settings are undocumented, hindering full replication.
- Post-processing heuristics for open-source model outputs are described only conceptually.
- The dataset is limited to PTAB ex parte appeals, which may not generalize to other patent proceedings or jurisdictions.

## Confidence
- Closed-source > open-source performance gap: High
- Input variation effects (Split best, Claim often harmful): Medium-High
- Low Macro-F1 due to rare labels: Medium
- PILOT-Bench as reusable foundation: Medium
