# Search-Augmented Masked Diffusion Models for Constrained Generation

## Quick Facts
- **arXiv ID**: 2602.02727
- **Source URL**: https://arxiv.org/abs/2602.02727
- **Reference count**: 40
- **Primary result**: SearchDiff yields large, consistent gains in constrained generation; e.g., 497.6 admissible molecules vs 142.0 best AR baseline, 76% SAT accuracy vs 9.6%, 100% peptide constraint satisfaction, and 27× more feasible tRNA than prior methods.

## Executive Summary
This paper introduces SearchDiff, a training-free inference framework for constrained discrete sequence generation. SearchDiff enhances masked diffusion models by integrating informed search into each reverse denoising step. It comprises two key components: Candidate Search Sampling (CSS), which draws multiple candidates from the denoiser's predicted distribution and selects the least-violating one; and Local Refinement (LS), which greedily improves this candidate via single-token edits to minimize constraint violations. The refined candidate then guides a modified reverse kernel that fixes unmasked tokens and biases stochastic unmasking toward the refined values. This approach steers samples toward feasible regions without any additional training. The authors demonstrate substantial improvements across diverse tasks: molecular design, peptide generation, tRNA secondary structure prediction, and symbolic reasoning (Sudoku, SAT), often outperforming autoregressive baselines by large margins.

## Method Summary
SearchDiff operates on a pre‑trained masked diffusion model (MDLM). At each reverse step \(t\), the denoiser predicts a clean‑state distribution \(\hat{x}_0^{(t)}\). For the currently masked positions, Candidate Search Sampling (CSS) draws \(M\) samples from this distribution (keeping already‑unmasked tokens fixed) and selects the sample with the lowest constraint violation \(V(x)\). Starting from this seed, Local Refinement (LS) iteratively examines all Hamming‑1 neighbors (any single token change) and accepts moves that strictly reduce \(V\). The resulting refined sequence \(\bar{x}_t\) is then used to compute the next state \(x^{t-1}\): any token already unmasked is set to the refined value, while each masked token is unmasked with probability \(\eta_t\) to the refined token else remains masked. This integration of search into the diffusion trajectory is training‑free and can be applied to any masked diffusion denoiser.

## Key Results
- Molecular generation: 497.6 admissible samples (vs 142.0 best AR baseline) and mean QED 0.77 (vs 0.62).
- Boolean SAT (7 variables): 76.0% solved (vs 9.6% vanilla diffusion), surpassing larger GPT‑2 autoregressive models.
- Peptides: 1024/1024 satisfy all constraints (0% violation); tRNA: 719 feasible sequences (27× over best baseline).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Candidate Search Sampling (CSS) initializes the search with model‑plausible candidates that are more likely to be near feasible regions than random draws, preserving generative fidelity while enabling constraint‑aware exploration.
- **Mechanism**: At each reverse denoising step, the denoiser predicts a clean‑state distribution \(\hat{x}_0^{(t)}\). CSS draws \(M\) samples from this distribution (clamped to currently masked positions) and selects the least‑violating one as the seed for local refinement. This anchors the subsequent search in the model’s learned proposal space, avoiding blind exploration.
- **Core assumption**: The denoiser’s raw predictions, though not optimized for constraints, contain a subset of candidates that are closer to satisfaction than uniform or random baselines; best‑of‑\(M\) selection can identify these without additional training.
- **Evidence anchors**:
  - [abstract]: “the model predictions define a proposal set that is optimized under a user‑specified property satisfaction”
  - [section 5.1]: “We leverage this distribution to construct a strong initial candidate via Candidate Search Sampling (CSS).”
  - [corpus]: Neighbors (e.g., Planner Aware Path Learning) explore inference‑time scaling via search, but do not directly address CSS; evidence for CSS’s role is primarily internal.
- **Break condition**: If the denoiser’s proposal distribution is entirely misaligned with the feasible manifold (e.g., constraints are heavily out‑of‑distribution), CSS may consistently fail to provide a viable seed, leading to no improvement over random search.

### Mechanism 2
- **Claim**: Local refinement through greedy single‑token edits efficiently navigates the discrete space toward lower violation by exploiting local smoothness of the constraint landscape, enabling fine‑grained repairs that global sampling misses.
- **Mechanism**: Starting from the CSS seed, the search iteratively examines the Hamming‑1 neighborhood (all sequences differing by one token) and accepts moves that strictly reduce the violation score \(V(x)\). This greedy descent makes incremental adjustments that preserve overall structure while fixing local errors.
- **Core assumption**: The feasible region is (at least partially) connected via single‑token edits, and the violation function exhibits sufficient local smoothness such that a greedy hill‑climber can escape shallow local minima and find improved candidates.
- **Evidence anchors**:
  - [section 5.2]: “Local search refinement… iterative improvements… greedy improvement”
  - [section 6.1.1]: “Local refinement is crucial for exploring chemical regions not observed during training.”
  - [section 6.1.1, Figure 3]: LS alone generates 212.6 OOD molecules vs. 0 for baselines, demonstrating its role in discovering high‑value regions.
- **Break condition**: If the constraint satisfaction requires coordinated multi‑token changes (e.g., flipping two bits to satisfy a clause) or the violation landscape is highly rugged with many sharp cliffs, greedy local search may become trapped in poor local minima and fail to reach feasible or high‑quality candidates.

### Mechanism 3
- **Claim**: The search‑guided reverse kernel integrates the refined candidate into the diffusion trajectory by deterministically fixing unmasked tokens and biasing stochastic unmasking toward refined values, thereby propagating constraint improvements forward and preventing reversion to infeasible states.
- **Mechanism**: After obtaining \(\bar{x}_t\), the modified reverse transition sets any already‑unmasked positions \(x_i^t \neq M\) to \(\bar{x}_i^t\) deterministically. For masked positions, it samples from a categorical distribution that combines the original mask token \(M\) and a one‑hot for \(\bar{x}_i^t\), weighted by \(\gamma_t\) and \(\eta_t\). This commits to the refinements while maintaining diffusion‑style randomness.
- **Core assumption**: The refined candidate \(\bar{x}_t\) represents a better intermediate state that, if carried forward, increases the likelihood of reaching a fully feasible final sample; the stochastic component allows occasional exploration of alternatives.
- **Evidence anchors**:
  - [section 5.3]: “the modified reverse kernel used \(\bar{x}_t\) to deterministically update unmasked tokens and stochastically unmask a subset of masked tokens”
  - [section 6.2, Table 10]: Applying search only at the last step (“Last_Step”) underperforms full‑trajectory SearchDiff on both Sudoku and SAT, showing that distributing search throughout the steps is critical.
  - [section 6.1.1, Table 3]: Running LS throughout all steps yields higher SA/QED satisfaction than applying it only at convergence, confirming the benefit of iterative integration.
- **Break condition**: If the search refinement at a step is erroneous (e.g., overfits to a local violation and harms global quality), the deterministic fixation of unmasked tokens may lock in a poor decision, making later recovery difficult. The stochastic component mitigates but does not eliminate this risk.

## Foundational Learning
- **Concept**: Masked Diffusion Reverse Process  
  **Why needed**: SearchDiff directly modifies the reverse denoising steps of a pre‑trained masked diffusion model; understanding the standard reverse kernel (Eq. 2) is essential to grasp how the search‑guided kernel deviates.  
  **Quick check**: In masked diffusion, what happens to a token that is still \([MASK]\) at step \(t\) during the reverse transition to \(t-1\)?
- **Concept**: Constraint Violation Functions  
  **Why needed**: The entire search mechanism optimizes a user‑defined violation score \(V(x)\); knowing that constraints are encoded as black‑box, possibly non‑differentiable functions is key to understanding the neurosymbolic setup.  
  **Quick check**: How is the aggregate violation \(V(x)\) constructed from individual constraints in SearchDiff?
- **Concept**: Discrete Local Search (Greedy Hill‑Climbing)  
  **Why needed**: The refinement stage is a greedy local search over single‑token edits; this algorithm’s properties (completeness, termination) determine when SearchDiff can succeed or fail.  
  **Quick check**: What constitutes a neighbor in the Hamming‑1 neighborhood \(\mathcal{N}_t(x)\) and how is the next candidate selected?

## Architecture Onboarding
**Component map**: Pre‑trained masked diffusion denoiser → Candidate Search Sampling (CSS) → Local Refinement → Modified reverse kernel. The Constraint Violation Evaluator is queried by CSS and Local Refinement.

**Critical path** (per denoising step \(t = T,\dots,1\)):
1. Denoiser predicts \(\hat{x}_0^{(t)}\) from current state \(x_t\).
2. CSS draws \(M\) candidates, selects \(x_{t}^{css}\) (lowest \(V\)).
3. Local search iteratively improves \(x_{t}^{css}\) to \(\bar{x}_t\).
4. For each position \(i\):
   - If \(x_i^t \neq [MASK]\), set \(x_i^{t-1} = \bar{x}_i^t\).
   - Else sample \(x_i^{t-1} \sim \text{Cat}(\gamma_t [MASK] + \eta_t \delta_{\bar{x}_i^t})\).
5. Update \(x_{t-1}\) and repeat.

**Design tradeoffs**:
- **CSS budget \(M\)**: Larger \(M\) improves seed quality but increases inference time; performance scales sublinearly (Figure 5, Table 6).
- **Search frequency**: Running LS every step (“all steps”) outperforms applying only at final convergence or last step (Table 3, Table 10).
- **Local search rounds \(R\)**: More rounds allow deeper refinement but add overhead; greedy descent may terminate early if no improving neighbor exists.
- **Violation function design**: Weights \(\lambda_k\) prioritize constraints; mis‑specification can skew search away from desired trade‑offs.

**Failure signatures**:
- **Zero feasible candidates found**: CSS fails to produce any seed with \(V < \infty\) or local search cannot improve; check violation function calibration and denoiser alignment.
- **Degradation in generative fidelity**: Over‑aggressive search drives samples to low‑probability regions under \(p_\theta\); monitor validity/novelty metrics (e.g., Table 8 where baselines fail).
- **Stuck in local minima**: Repeated failure to satisfy constraints across many runs; may require larger \(M\), more LS rounds, or alternative neighborhood definitions.
- **Excessive runtime**: High \(M\) and \(R\) on long sequences (e.g., tRNA) can become costly; consider early termination heuristics or approximate search.

**First 3 experiments**:
1. **Small molecule generation** (Section 6.1.1): Optimize QED while enforcing Synthetic Accessibility (SA) threshold; uses RDKit black‑box evaluators. SearchDiff achieves 497.6 admissible molecules vs. 142.0 best AR baseline.
2. **Peptide generation** (Section 6.1.2): Enforce length, positive charge, and hydrophobic fraction constraints via Biopython; yields 1024/1024 peptides satisfying all constraints, where baselines leave violations.
3. **tRNA generation** (Section 6.1.3): Design sequences folding into correct secondary structure (acceptor stem, D/anticodon/variable loops, TΨC) using ViennaRNA; SearchDiff attains 719 feasible (27× over best baseline) while others struggle with coupled long‑range constraints.

## Limitations
- **Missing pretrained checkpoints and hyperparameters**: No released MDLM weights or full training details (noise schedule \(\alpha_t\), diffusion steps \(T\), tokenization) hinder exact reproduction.
- **Incomplete constraint evaluator specifications**: Exact versions and parameters for RDKit SA, QED thresholds, ViennaRNA settings, and SAT solvers are not provided, risking implementation drift.
- **Scalability concerns**: Computational overhead of CSS and LS (especially on long sequences like ∼100‑token tRNA) is not reported; runtime may become prohibitive without approximations.

## Confidence

- CSS initialization: Medium
- LS as primary driver: High
- Trajectory‑wide integration: High

## Next Checks
1. **Independent MDLM reproduction**: Train a masked diffusion model on QM9 from scratch or use a public checkpoint; re‑run SearchDiff to verify gains are not checkpoint‑specific.
2. **Constraint robustness stress test**: For molecules, systematically vary QED thresholds (e.g., >0.8, >0.9) and SA limits; measure success rate decay to expose break conditions.
3. **Scalability benchmark**: Measure wall‑clock time and memory on synthetic sequences of lengths 50, 100, 200 tokens (matching tRNA scale); identify efficient approximations (e.g., fewer LS rounds, early termination).
