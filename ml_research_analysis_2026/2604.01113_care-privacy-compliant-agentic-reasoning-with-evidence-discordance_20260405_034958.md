# CARE: Privacy-Compliant Agentic Reasoning with Evidence Discordance

## Quick Facts
- arXiv ID: 2604.01113
- Source URL: https://arxiv.org/abs/2604.01113
- Reference count: 34
- Primary result: On the MIMIC-DOS benchmark, CARE (local GPT-OSS + remote GPT-5) attains Balanced Accuracy 0.5460, G-mean 0.5455, MCC 0.0921, with TPR 0.5220 and TNR 0.5700—both exceeding 0.5—while all non‑CARE baselines collapse toward a single class.

## Executive Summary
Clinical decision support using large language models (LLMs) faces a dual challenge: patient symptoms often conflict with objective signs, and privacy regulations restrict sending sensitive data to powerful proprietary models. This paper presents CARE, a privacy‑preserving multi‑stage framework that divides labor between a remote LLM (providing high‑level guidance) and a local LLM (processing private information). Evaluated on a newly introduced benchmark, MIMIC‑DOS, which isolates sign‑symptom discordance in ICU cases, CARE achieves a balanced accuracy of 0.5460 and, critically, simultaneously surpasses the 0.5 threshold for both true positive and true negative rates—a result no baseline can match, as they all exhibit one‑class collapse. The work demonstrates that agentic, state‑based reasoning can robustly manage conflicting evidence under strict privacy constraints.

## Method Summary
CARE orchestrates four stages. A remote proprietary LLM (e.g., GPT‑5) first generates a rubric schema that defines clinical states and severity levels, and later produces transition guidance based on the current state and the set of available feature *types* (e.g., hemodynamic, perfusion). These remote interactions occur without exposure to raw patient values. A local open‑source LLM (e.g., GPT‑OSS) executes the remaining stages on private data: (1) initial state assignment using the rubric; (2) category‑aware evidence acquisition—deciding which additional feature keys to retrieve; (3) local state update by re‑applying the rubric to the augmented data and merging with remote transition candidates via a constrained merge; (4) final decision mapping states to actions (OBSERVE, TREAT_S, INVESTIGATE_O). The system is evaluated on MIMIC‑DOS with 22 ICU features, where only a limited snapshot (7 objective features) is initially available and up to 15 additional facts may be fetched upon request; subjective features are always accessible. This staged design balances privacy, token efficiency, and reasoning depth.

## Key Results
- Balanced Accuracy: 0.5460, G‑mean: 0.5455, Matthews Correlation Coefficient: 0.0921.
- True Positive Rate: 0.5220, True Negative Rate: 0.5700 (both > 0.5).
- All baseline workflows (single‑pass, majority voting, RSMAD, ConfMAD) collapse toward one class (TPR or TNR near 0 or 1).
- Using GPT‑OSS as local and GPT‑5 as remote uniquely maintains balanced performance across both classes.

## Why This Works (Mechanism)

### Mechanism 1: Asymmetric Responsibility Split
CARE enforces privacy by separating raw data handling (local LLM) from abstract reasoning (remote LLM). The remote model creates a value‑independent rubric schema and transition policies based purely on feature semantics, while the local model applies these to the patient’s private values through the staged pipeline. Evidence: [abstract] describes the split; [section 4.2] details stage responsibilities. The approach assumes the remote structure generalizes to specific cases; if the rubric fails to capture clinically relevant distinctions, the mechanism breaks.

### Mechanism 2: State‑Transition‑Based Evidence Integration
The multi‑stage design explicitly manages evidence discordance. After an initial state is assigned, Stage 2 acquires additional evidence conditioned on that state. Stage 3 then obtains remote transition guidance based on the *types* of newly available evidence, and the local model updates its state via a constrained merge. This allows the system to revise an early reassuring impression if objective data suggests deterioration. Evidence: [section 1] frames the need for revision; [section 4.2, Stage 3] describes transition reasoning; [table 2] shows removing Stage 3 harms TPR/TNR balance. Failure may occur if remote advice is misaligned or the merge is too conservative.

### Mechanism 3: Category‑Aware Evidence Acquisition
Rather than exposing all 22 features at once, CARE requests only those feature *types* relevant to confirming or challenging the current state. This conditional acquisition reduces noise and focuses computation on resolving the specific uncertainty implied by the state. Evidence: [section 4.2, Stage 2] defines the process; [appendix A.4.2] illustrates a request for hemodynamic and perfusion data from a seemingly stable patient; [section 6] ablation shows backbone‑only (no conditional acquisition) underperforms full CARE. The mechanism fails if the local model’s mapping from state to required evidence is poor, leading to irrelevant or insufficient data retrieval.

## Foundational Learning

- **Privacy‑Preserving ML & Asymmetric Architectures**  
  Why needed: CARE’s core innovation operates under a strict threat model where patient data cannot be sent to the most capable model. Engineers must design pipelines that keep sensitive operations local while outsourcing high‑level guidance.  
  Quick check: If remote guidance is purely text‑based (schema, transitions), what information must the local model always retain sole custody of to maintain privacy?  
  → Raw patient values (e.g., MAP, lactate) must never leave the local environment.

- **State‑Based Agentic Workflows (vs. Single‑Pass)**  
  Why needed: CARE’s power derives from multi‑stage reasoning with explicit state updates; a durable state representation (the rubric category) persists across LLM calls and modulates subsequent actions.  
  Quick check: In a state‑based system, what is the functional difference between Stage 2 (acquisition) and Stage 3 (transition reasoning)? What would break if these were combined?  
  → Stage 2 selects *what* data to fetch based on the current state; Stage 3 interprets the fetched data and suggests state changes. Combining them would lose the conditional relevance of data acquisition and could overwhelm the model with irrelevant evidence.

- **Handling Evidence Discordance & Model Brittleness**  
  Why needed: Standard LLM prompts fail when symptoms and signs point in opposite directions; structured disagreement resolution via state transitions is required.  
  Quick check: Why do single‑pass and debate baselines in Table 1 exhibit strong directional bias (e.g., high TNR, low TPR)? What specific aspect of MIMIC‑DOS construction makes this hard for them?  
  → Because they lack a mechanism to revise an initial impression when new conflicting evidence appears; MIMIC‑DOS explicitly creates cases where early subjective symptoms conflict with later objective physiology, causing flat models to default to the majority signal of the initial snapshot.

## Architecture Onboarding

### Component Map
Remote LLM (GPT-5) -> Rubric Schema, Transition Guidance -> Local LLM (GPT-OSS) -> Stage1 (Initial State) -> Stage2 (Evidence Acquisition) -> Feature Store (data retrieval) -> Stage3 (Remote Transition Advice, Constrained Merge) -> Stage4 (Final Decision). State Manager maintains current_category, severity, reason across stages.

### Critical Path
1. Input: task description + minimal snapshot (7 objective features).  
2. Stage1: Local LLM assigns initial category via programmatic rubric mapping.  
3. Stage2: Local LLM, given current state, outputs a list of required fact_keys; Feature Store retrieves corresponding values.  
4. Stage3: Remote LLM receives current state and list of available feature types; returns transition candidates and textual guidance. Local LLM re‑applies rubric to all now‑available data, then performs constrained merge with remote candidates to produce an updated category.  
5. Stage4: Local LLM synthesizes initial snapshot, retrieved facts, initial and updated categories, and outputs final action.

### Design Tradeoffs
- Token efficiency vs. Reasoning depth: CARE uses ~7k tokens/sample, far more than single‑pass (~1k), but gains balanced performance and avoids collapse.  
- Privacy vs. Performance upper bound: The split prevents raw data exposure but caps effectiveness at the local model’s ability to apply remote guidance.  
- Rigidity vs. Adaptability: A fixed rubric provides stability but may not cover all discordance patterns; dynamic generation is possible but adds complexity.

### Failure Signatures
- One‑class collapse: TPR or TNR near 0 or 1, indicating the model consistently ignores one class.  
- Invalid outputs: JSON parse failures, especially with weaker local models.  
- State stasis: Initial category rarely changes after Stage 3, rendering the transition loop ineffective.  
- Irrelevant acquisition: Stage 2 requests features unrelated to the current state’s diagnostic needs, wasting tokens and not resolving conflict.

### First 3 Experiments
1. **Stage Isolation Test**: Disable Stages 2 and 3, run only Stage 1 + Stage 4. Expect performance similar to the “backbone‑only” ablation (BA ~0.541), confirming added value of middle stages.  
2. **Remote Guidance Ablation**: Replace GPT‑5’s transition advice with a deterministic rule (e.g., always escalate severity). Compare to full remote guidance to isolate the benefit of nuanced remote reasoning.  
3. **Local Model Capability Sweep**: Vary the local LLM (e.g., GPT‑OSS 20B, 120B; Qwen 32B) while keeping remote fixed. Hypothesis: performance improves with local capability, but the gap between local‑only and CARE narrows as locals get stronger.

## Open Questions the Paper Calls Out
1. What additional clinical scenarios of sign‑symptom discordance should be incorporated into MIMIC‑DOS to improve coverage of real‑world ICU decision‑making challenges?  
2. How can CARE be modified to prevent leakage of sensitive information through feature metadata (e.g., feature names, rubric definitions) under stricter privacy models?  
3. Can the rubric schema used in Stage 1 be automatically generated from task descriptions without human specification, and does such automation maintain or degrade CARE’s performance across diverse clinical tasks?  
4. What specific aspects of Stage 3’s transition reasoning (remote guidance + local merge) are most critical for resolving evidence discordance, beyond simply acquiring more evidence in Stage 2?

## Limitations
- **Reproducibility gaps**: Exact prompt templates, programmatic threshold rules for initial state, and full feature extraction pipeline from raw MIMIC‑IV are not provided, hindering exact replication.  
- **Limited evaluation**: Experiments are confined to MIMIC‑DOS; generalizability to other discordance types, tasks, or privacy‑sensitive domains remains unknown.  
- **Dependence on proprietary components**: Performance hinges on GPT‑5 and specific large local models; the asymmetric premise may not hold with alternative models or tighter privacy constraints.
