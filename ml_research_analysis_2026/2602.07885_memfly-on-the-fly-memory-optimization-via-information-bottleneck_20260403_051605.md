# MemFly: On-the-Fly Memory Optimization via Information Bottleneck

## Quick Facts
- **arXiv ID**: 2602.07885  
- **Source URL**: https://arxiv.org/abs/2602.07885  
- **Reference count**: 25  
- **Primary result**: MemFly achieves 38.62% F1 and 34.51 BLEU-1 on Qwen3-8B, exceeding the best baseline by 5.86 F1 points; on GPT-4o-mini it reaches 43.76% F1 (+1.79%).

## Executive Summary
Long-term memory for LLM agents faces a fundamental trade-off: compressing redundant information to reduce noise while retaining precise details for accurate retrieval and reasoning. MemFly resolves this by framing memory optimization as an Information Bottleneck (IB) problem. It employs an LLM-driven, gradient-free optimizer to greedily merge redundant memory units, preserving relevance through a stratified Note-Keyword-Topic hierarchy grounded in double clustering. Retrieval combines three pathways—Topic navigation, Keyword anchoring, and topological expansion—with Reciprocal Rank Fusion and an Iterative Evidence Refinement (IER) loop. On the LoCoMo benchmark, MemFly consistently outperforms six state-of-the-art baselines across multiple models, with ablations confirming the critical roles of its gated structural updates and iterative refinement.

## Method Summary
MemFly operates in two phases: memory construction and retrieval. During construction, each new interaction turn is parsed by an LLM into a structured Note (denoised context, embedding, extracted keywords). A gated update then retrieves a candidate neighborhood via dual sparse-dense indices and uses the LLM to score redundancy (`s_red`) and complementarity (`s_comp`) against each candidate. Based on thresholds (`τ_m=0.7`, `τ_l=0.5`), it merges duplicate notes, adds logical links, or appends the new note. Periodically, Keywords are clustered into Topics using the Leiden algorithm on their co-occurrence graph. For retrieval, a query is intent-parsed to obtain a topic description and keywords. Three pathways run in parallel: (1) Topic navigation to retrieve linked notes, (2) Keyword matching, and (3) one-hop expansion from the anchor set. Results are fused via Reciprocal Rank Fusion and passed through an IER loop where an LLM sufficiency evaluator may generate sub-queries to iteratively enrich the evidence pool until a termination condition is met.

## Key Results
- On Qwen3-8B, MemFly achieves 38.62% F1 and 34.51 BLEU-1, exceeding the best baseline by 5.86 F1 points; on GPT-4o-mini it reaches 43.76% F1 (+1.79%).
- Removing the gated update (w/o Update) drops F1 by over 10 points, confirming the necessity of IB-guided consolidation.
- Ablations show IER is critical for adversarial/open-domain queries, while the Keyword layer most impacts single-hop performance; removing any layer degrades overall results.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: MemFly optimally balances compression and relevance by minimizing the Information Bottleneck Lagrangian during online memory updates.
- **Mechanism**: At each step, it greedily minimizes ΔL = ΔI(X;M) − β ΔI(M;Y), where I(X;M) is reduced by merging redundant memory units (lowering |V_t|) and I(M;Y) is preserved by maintaining evidence structure via keywords and links. Redundancy is assessed via an LLM approximating Jensen-Shannon divergence between candidate units’ task-relevance distributions.
- **Core assumption**: Future task relevance *Y* can be approximated by (1) local keyword co-occurrence (semantic coherence) and (2) global topic navigability (evidence accessibility).
- **Evidence anchors**: [abstract] “formulating memory as an Information Bottleneck problem… minimizes compression entropy while maximizing relevance entropy”; [section 3.1] Eq. (1) defines the IB objective; discussion of I(X;M) vs. I(M;Y) and proxy signals for *Y*.
- **Break condition**: If β is poorly tuned or the chosen proxies (keyword co-occurrence, topic structure) fail to correlate with actual downstream task performance.

### Mechanism 2
- **Claim**: An LLM‑driven gradient‑free policy replaces intractable JS‑divergence computation, enabling scalable online merge decisions.
- **Mechanism**: For a new note *n_t* and candidate *n_i*, the LLM outputs a redundancy score *s_red(n_t, n_i)* ∈ [0,1]. If *s_red > τ_m* (e.g., 0.7), the notes are merged; if a complementarity score *s_comp > τ_l*, a link is added; otherwise, the note is appended. *s_red* is hypothesized to inversely correlate with JS divergence between *p(Y|n_t)* and *p(Y|n_i)*.
- **Core assumption**: The LLM’s pretrained knowledge implicitly captures task‑relevant distributional properties, so its semantic similarity assessment approximates JS divergence without requiring explicit probability estimation.
- **Evidence anchors**: [section 3.3.2] “LLM as JS‑Divergence Approximator” and Eq. (4) linking *s_red* to JS divergence; prompt templates in Appendix A.1.2.
- **Break condition**: If LLM scoring becomes inconsistent across prompts or models, or if *s_red* does not reliably indicate distributional similarity for certain domains.

### Mechanism 3
- **Claim**: A stratified Note‑Keyword‑Topic hierarchy, grounded in the double clustering principle, stabilizes the semantic space and preserves evidence structure for precise retrieval.
- **Mechanism**: Notes (raw fidelity) are anchored by Keywords (symbolic intermediates), which are clustered into Topics (navigable regions). Keywords mitigate vector dilution by providing dense symbolic anchors; Topics enable O(1) macro‑navigation. This two‑stage abstraction (clustering features → documents) follows Slonim & Tishby’s double clustering.
- **Core assumption**: High‑dimensional embedding spaces suffer from sparsity; a lower‑dimensional symbolic layer (Keywords) yields more robust similarity estimates, and clustering Keywords into Topics creates well‑connected semantic regions.
- **Evidence anchors**: [abstract] “stratified Note‑Keyword‑Topic hierarchy based on double clustering”; [section 3.2] detailed layer definitions and mapping to double clustering.
- **Break condition**: If keyword extraction systematically omits key entities, or if the keyword co‑occurrence graph is too sparse for meaningful topic partitioning (e.g., low modularity).

## Foundational Learning
- **Concept**: Information Bottleneck (IB)  
  **Why needed**: Provides the theoretical foundation for the compression‑relevance trade‑off; explains *why* merging and linking decisions are made.  
  **Quick check**: What does minimizing *I(X;M) − β I(M;Y)* encourage? (Answer: Reducing redundancy in memory while retaining information predictive of future tasks.)

- **Concept**: Double Clustering (Slonim & Tishby, 2000)  
  **Why needed**: Justifies the hierarchical design; explains why an intermediate symbolic layer (Keywords) improves robustness compared to direct clustering of high‑dimensional embeddings.  
  **Quick check**: In double clustering, what is clustered first: data points or features? (Answer: Features/word clusters first, then documents.)

- **Concept**: Reciprocal Rank Fusion (RRF)  
  **Why needed**: Enables score‑agnostic fusion of the three retrieval pathways (topic, keyword, neighbor), critical for combining heterogeneous evidence without normalization.  
  **Quick check**: How does RRF combine ranked lists? (Answer: Sum reciprocal ranks of each candidate across lists.)

## Architecture Onboarding
- **Component map**: Ingestion -> Gated Update -> Topic Evolution -> Retrieval -> IER.  
  Ingestion: raw input -> LLM parser -> Note (r, c, h, K).  
  Gated Update: candidate retrieval (dual index) -> LLM scorer -> Merge/Link/Append -> update graph.  
  Topic Evolution: Leiden algorithm on keyword co-occurrence graph -> recluster Topics periodically.  
  Retrieval: query -> LLM parser -> (htopic, Hkeys) -> three pathways (Topic nav, Keyword match, neighbor expansion) -> RRF -> iterative refinement (IER).  
  Storage: Neo4j graph: Notes ↔ Keywords ↔ Topics, with E_rel edges.

- **Critical path**: Construction: stream → ingestion → neighbor lookup → LLM scoring → structural op → topic update. Retrieval: query → intent parse → parallel pathway search → RRF → sufficiency check → sub‑query (if needed) → repeat.

- **Design tradeoffs**: 
  - Construction quality vs. latency (LLM calls per step).
  - Hierarchy depth (3 layers) vs. granularity (too many Keywords/Topics fragment memory).
  - Retrieval coverage (K_topic, K_key, K_final) vs. noise (larger pools increase distractor risk).

- **Failure signatures**:
  - **Memory coherence drop**: Many near‑duplicate Notes → τ_m too low or s_red scoring too lenient.
  - **Topic fragmentation**: Many tiny Topics → Leiden resolution too high or keyword sparsity.
  - **Poor single‑hop**: Low recall on entity queries → keyword extraction failing or K_key too small.
  - **IER stalling**: No improvement after iterations → sufficiency evaluator too strict or missing evidence not linked.

- **First 3 experiments**:
  1. **Main results (Tables 1,2)**: Compare F1/BLEU on LoCoMo across 4 backbone models vs. 6 baselines; shows consistent gains, especially on open‑source models.
  2. **Construction ablation (Table 3, Fig 2a)**: Removing gated update (w/o Update) devastates performance (F1 −10.65), confirming IB‑guided consolidation is critical.
  3. **Retrieval ablation (Table 3, Fig 2b)**: Removing IER hurts adversarial/open‑domain most; removing Keywords hurts single‑hop; removing Topic hurts overall navigation, validating tri‑pathway synergy.

## Open Questions the Paper Calls Out
- **Open Question 1**: How does MemFly's performance and memory structure scale to multimodal inputs and specialized domain scenarios beyond text-based dialogues?
- **Open Question 2**: What is the theoretical and empirical justification for using an LLM as a gradient-free proxy for Jensen-Shannon divergence in the online IB optimization?
- **Open Question 3**: How does the substitution of distributional word clustering (from the original Double Clustering principle) with LLM-based keyword extraction affect the information-theoretic guarantees and robustness of the Note-Keyword-Topic hierarchy?
- **Open Question 4**: What are the precise failure modes and complementary strengths of the three retrieval pathways (Topic, Keyword, Topological) across different reasoning query types?
- **Open Question 5**: How reliable and calibrated is the LLM-based sufficiency evaluator in the Iterative Evidence Refinement (IER) protocol, and what are its common failure modes?

## Limitations
- LLM redundancy scoring (`s_red`) is not validated; it may not correlate with true JS divergence between relevance distributions.
- Candidate neighborhood retrieval parameters (k, sparse-dense weighting) are unspecified, affecting update quality and efficiency.
- Topic centroid computation and update frequency are unclear, potentially causing hierarchy instability.

## Confidence
- **IB-guided optimization (Mechanism 1)**: Medium. The IB principle is solid, but proxies for future relevance Y are unverified.
- **LLM as JS-divergence approximator (Mechanism 2)**: Low. No evidence that LLM scores reflect actual distributional similarity.
- **Stratified Note‑Keyword‑Topic hierarchy (Mechanism 3)**: High. Ablations show large drops when any layer is removed, and double clustering provides theoretical grounding.

## Next Checks
1. **LLM score validation**: Compute JS divergence between note pairs' task-relevance distributions (using a fixed classifier). Correlate with `s_red`; expected Pearson *r* > 0.7.
2. **Candidate retrieval sweep**: Vary k-NN size (k = 5,10,20) and sparse-dense weight; measure F1 and latency. Identify if reported config is Pareto-optimal.
3. **Topic stability over time**: During memory construction, compute Leiden modularity and NPMI coherence of the Keyword‑Topic graph at regular intervals. Stability (no significant decay) supports the hierarchy design.
