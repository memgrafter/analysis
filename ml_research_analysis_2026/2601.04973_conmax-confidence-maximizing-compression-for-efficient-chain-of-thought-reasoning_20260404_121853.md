# ConMax: Confidence-Maximizing Compression for Efficient Chain-of-Thought Reasoning
## Quick Facts
- **arXiv ID**: 2601.04973
- **Source URL**: https://arxiv.org/abs/2601.04973
- **Reference count**: 6
- **Primary result**: ConMax reduces generated token length by 43% on the 7B variant while incurring only a 0.7% drop in accuracy.

## Executive Summary
Large Reasoning Models often produce verbose chain-of-thought traces that increase computational costs without proportional accuracy gains—a phenomenon termed "overthinking." ConMax addresses this by formulating reasoning trace compression as a reinforcement learning problem. It trains a policy to maximize a dual-confidence reward derived from a frozen auxiliary Large Reasoning Model (LRM), which evaluates both answer correctness (Answer Confidence) and reasoning coherence (Thinking Confidence). Experiments across five mathematical and scientific datasets with Qwen2.5 models show that ConMax achieves a 43% reduction in token length with only a 0.7% accuracy loss, offering a superior efficiency-performance trade-off for generating high-quality, compact training data.

## Method Summary
ConMax operates in two stages. First, a compression policy πθ (initialized from a teacher model like DeepSeek-R1-Distill-Qwen-7B) is trained using Group Relative Policy Optimization (GRPO) to generate shortened reasoning traces. The reward function Rc = Sans + β·Sthink combines answer confidence (the normalized log-probability of the ground-truth answer under a frozen auxiliary LRM πϕ) and thinking confidence (the average log-probability of the compressed trace itself). The system prompt instructs the policy to produce concise yet coherent traces. No explicit length penalty is used. In the second stage, the trained policy compresses the original SFT dataset Dsft to produce a compressed dataset bDsft. Finally, a target model (e.g., Qwen2.5-7B-Instruct) is fine-tuned on bDsft. This approach yields compact traces that retain reasoning validity and answer accuracy.

## Key Results
- 43% reduction in average token length on Qwen2.5-7B, with only a 0.7% drop in accuracy compared to using full traces.
- Consistent improvements in efficiency across five benchmarks (AIME2025, MATH500, AMC23, MINERVA, GPQA).
- Demonstrates that implicit length constraints via reward design can achieve diverse compression rates without sacrificing correctness.

## Why This Works (Mechanism)
ConMax’s success rests on three interconnected mechanisms:

**1. Dual-Confidence Reward Optimization**  
Claim: The policy can compress traces while preserving accuracy by optimizing a reward that combines answer and thinking confidence.  
Mechanism: The reward Rc(ˆz)=Sans(ˆz)+β·Sthink(ˆz) encourages the policy to generate compressed traces that are both predictive (high Sans) and coherent (high Sthink). Sans is the length-normalized log-probability of the ground-truth answer under πϕ, while Sthink is the average log-probability of the trace tokens themselves.  
Core assumption: The frozen auxiliary LRM πϕ is capable enough to assign meaningful confidence scores.  
Evidence anchors: Abstract and Section 3.2 define these components; neighboring work like ConCISE also uses confidence signals.  
Break condition: If πϕ is miscalibrated or suffers distribution shift, the reward may misguide the policy, causing over-compression or incoherence.

**2. Frozen Auxiliary LRM Supervision**  
Claim: Using a frozen LRM provides stable, high-quality supervision without training a separate verifier.  
Mechanism: πϕ remains unchanged and evaluates both answer condition and trace content, leveraging its existing reasoning abilities.  
Core assumption: πϕ’s internal probability distribution reliably correlates with reasoning quality.  
Evidence anchors: Abstract mentions "frozen auxiliary LRM"; Section 3.2 describes its use; VeriThinker also uses a static verifier.  
Break condition: If πϕ is significantly larger or more capable than πθ, it may set an unattainable standard, leading to premature convergence or bias propagation.

**3. Implicit Length Constraint via System Prompt**  
Claim: Avoiding explicit length penalties allows the policy to discover diverse, optimal compression lengths for different reasoning patterns.  
Mechanism: The system prompt instructs conciseness while the reward focuses on fidelity and coherence; this separation prevents premature bias toward shorter outputs.  
Core assumption: The policy can internalize the compression objective from prompt guidance and confidence rewards.  
Evidence anchors: Abstract notes "rely on a compression‑oriented system prompt"; Section 4.5.3 shows adding an explicit compression rate reward does not improve results.  
Break condition: If the prompt is ambiguous, the policy may not learn to compress; for tasks requiring minimum depth, it might over-compress critical steps.

## Architecture Onboarding
Component map: Drl (x,z,y) -> πθ (system prompt) -> G candidates ˆz -> (πϕ with (x,y) for Sans, πϕ with (x) for Sthink) -> Reward Calculator -> group normalization -> GRPO Trainer -> update πθ. Dsft (x,z) -> πθ -> compressed ˆz -> bDsft -> SFT target model.

Critical path:
1. Prepare Drl: For each (x,z,y) in D, feed x and z to πθ; sample G compressed candidates per instance.
2. Compute reward Rc(ˆz) for each candidate via reward calculator using πϕ, y, x.
3. Compute advantage A_i,t = (Rc(ˆz_i) – mean_group) / std_group for each token.
4. Apply GRPO objective: maximize clipped advantage minus KL penalty against reference policy.
5. Update πθ via Adam; repeat for many steps.
6. After training, run πθ on Dsft to produce compressed dataset bDsft.
7. Fine‑tune a target model on bDsft and evaluate.

Design tradeoffs:
- β weighting: Higher β emphasizes thinking coherence; too high reduces answer accuracy.
- Group size G: Larger groups stabilize advantage estimates but increase memory.
- RL hyperparameters: Learning rate, KL penalty β_KL; too strong KL hinders learning.
- System prompt specificity: Must balance compression instruction with reasoning preservation.
- Choice of auxiliary model: Must be sufficiently strong; otherwise rewards are noisy.

Failure signatures:
- Accuracy collapse: overall accuracy drops significantly (>3 points) vs. original.
- No compression: average token length remains similar to original.
- Degenerate outputs: traces become gibberish, reflected by low Sthink or high repetition.
- Training instability: advantage variance explodes; may be due to small group size or high learning rate.
- Reward saturation: both Sans and Sthink approach zero early; may need reward scaling.

First 3 experiments:
1. **Reward pipeline sanity check**: For a small set (e.g., 100 samples), manually compute Sans and Sthink for hand‑crafted compressed traces and verify scores are sensible (correct answer > Sans; coherent > Sthink).
2. **Smoke test RL**: Train πθ for 10–20 steps on 1k samples; verify mean Rc increases and token length decreases. If not, adjust prompt or β.
3. **Hyperparameter sensitivity**: Short sweeps for β ∈ {0.5, 1.0, 1.2} and possibly Rlen; validate chosen β (1.2) yields best trade‑off on held‑out set.

## Open Questions the Paper Calls Out
- **Generalization to non‑math domains**: Does ConMax work for creative writing or code generation? Current evaluation is limited to math/science tasks.
- **Scalability to larger models**: How does it perform on 70B+ models or other architectures (e.g., Llama, GPT)? Experiments are restricted to Qwen2.5 up to 14B.
- **Self‑supervised alternative**: Can the auxiliary LRM be replaced by a self‑supervised mechanism to avoid external dependencies?

## Limitations
- **Model accessibility**: Primary DeepSeek-R1-7B may be restricted; substitutions could degrade reward quality.
- **Dataset reproducibility**: Exact NuminaMath subset and random seed are unspecified, hindering exact replication.
- **Benchmark availability**: AIME2025 and AMC23 might not be public, forcing substitutes.
