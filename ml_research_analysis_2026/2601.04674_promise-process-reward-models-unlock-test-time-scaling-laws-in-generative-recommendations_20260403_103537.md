# PROMISE: Process Reward Models Unlock Test-Time Scaling Laws in Generative Recommendations
## Quick Facts
*   **arXiv ID:** 2601.04674
*   **Source URL:** https://arxiv.org/abs/2601.04674
*   **Reference Count:** 40
*   **Primary Result:** Introduces a Process Reward Model (PRM) that mitigates semantic drift in hierarchical generative recommendations, yielding large offline gains (e.g., +42.41% Recall@5 on Sports) and a +0.121% lift in total app usage time in online A/B tests on Kuaishou.

## Executive Summary
Generative recommendation models using hierarchical Semantic IDs (SIDs) suffer from **semantic drift**: an early error in generating a high-level SID token irrevocably leads the model down an irrelevant item subspace. This paper proposes PROMISE, which introduces a lightweight, path-level Process Reward Model (PRM) trained jointly with the generative backbone. The PRM scores intermediate SID path prefixes, enabling a guided beam search that prunes low-quality branches during inference. On public and industrial datasets, PROMISE significantly outperforms baselines. Crucially, it unlocks **test-time scaling laws**: increasing the initial candidate pool size (𝐾+) during inference improves metrics without increasing decoder compute, allowing smaller models to surpass larger ones.

## Method Summary
PROMISE addresses semantic drift by adding a two-stage inference process. First, a standard decoder generates a large pool (𝐾+) of candidate SID path extensions at each step. Second, a lightweight PRM—trained via an InfoNCE loss to score the relevance of a user context against a given path prefix—re-ranks all these candidates. The top 𝐾′ paths are selected to continue decoding. This allows the model to use increased inference compute (via the larger 𝑲+) to explore more of the valid item space, while the PRM acts as a cheap verifier to filter out paths that have already drifted off-course, preventing error accumulation.

## Key Results
*   **Offline Gains:** On the Sports dataset, PROMISE achieves a +42.41% improvement in Recall@5 over the previous state-of-the-art (ActionPiece). On industrial data with 𝐾+=4000, it yields a +47.92% Recall@100 improvement.
*   **Online Impact:** An A/B test on the Kuaishou video platform reports a statistically significant +0.121% increase in total user app usage time.
*   **Test-Time Scaling:** Increasing the initial candidate size 𝑲+ from 1,000 to 6,000 (while keeping the active beam size 𝐾 fixed at 1,000) leads to a monotonic increase in hierarchical recall (e.g., HRecall@3@1000 improves from 22.96% to 36.37%), demonstrating a scalable inference-time compute trade-off.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** A lightweight path-level Process Reward Model (PRM), trained jointly with the generative backbone, provides dense, step-by-step supervision that can detect and penalize erroneous intermediate Semantic ID (SID) paths.
*   **Mechanism:** The PRM (function `F`) takes a user context `(𝑢, 𝑐)` and a candidate SID path prefix `[𝑠₁, ..., 𝑠𝑏]` and outputs a relevance score. It is trained via an InfoNCE loss (Eq. 7) to maximize the score for the ground-truth path prefix against uniformly sampled negative paths from the valid path space `V𝑏` (Eq. 5). This explicit discrimination on intermediate states, unlike the Next-Token Prediction (NTP) loss trained with teacher forcing, allows the model to learn what a *correct* reasoning step looks like, not just the final outcome.
*   **Core assumption:** Errors in early, high-level SID tokens cause irreversible deviation into irrelevant semantic subspaces (Semantic Drift). Identifying and pruning these errors at intermediate steps prevents cascading failures.
*   **Evidence anchors:**
    *   [abstract] "Introduces a lightweight path-level Process Reward Model (PRM) trained jointly... to score intermediate SID paths, enabling PRM-guided beam search that prunes low-quality branches."
    *   [section 3.2] Details the negative sampling strategy from valid paths `V𝑏` and the InfoNCE optimization objective (Eq. 7-9) for the PRM.
    *   [corpus] Neighbor papers like "Exploring Training and Inference Scaling Laws in Generative Retrieval" and "MCTS-Judge: Test-Time Scaling in LLM-as-a-Judge" investigate related scaling and verification paradigms, providing contextual support for the approach but not direct evidence for this specific PRM design.
*   **Break condition:** If the set of valid negative paths `V𝑏` is not sufficiently representative of common error modes (e.g., due to data sparsity in certain semantic regions), the PRM may fail to generalize and recognize out-of-distribution erroneous paths during inference.

### Mechanism 2
*   **Claim:** PRM-guided beam search dynamically prunes low-quality candidate branches during generation by re-ranking a large initial candidate set (`𝐾 +`) down to a smaller, high-quality set (`𝐾 ′`), mitigating semantic drift.
*   **Mechanism:** At each decoding step `𝑏`, the standard decoder generates `𝐾 +` candidate path extensions based on token probabilities. Instead of naively keeping the top `𝐾 +` by decoder score, the lightweight PRM scores all `𝐾 +` complete prefixes in parallel (using cross-attention over encoder features). The top `𝐾 ′` paths by PRM score (where `𝐾 ′` equals the original beam size `𝐾`) are carried forward. This uses the PRM's dense feedback to select semantically coherent paths, not just locally probable ones.
*   **Core assumption:** The PRM's path score is a more reliable indicator of eventual retrieval success than the decoder's next-token probability, especially for distinguishing semantically valid prefixes from drift-induced OOD paths.
*   **Evidence anchors:**
    *   [abstract] "PRM-guided Beam Search strategy that leverages dense feedback to dynamically prune erroneous branches."
    *   [section 3.3] Algorithm 1 explicitly shows the process: generate `𝐾 +` candidates, score with PRM (Eq. 10-12), select top `𝐾 ′`.
    *   [section 4.4.2] Ablation in Table 4 shows that applying PRM at more steps (`𝑏=1,2,3`) consistently improves HRecall@𝑏@1000, confirming the pruning effect reduces error accumulation at each stage.
*   **Break condition:** If the PRM is poorly calibrated or overfits to the specific negative sampling distribution used in training, it may incorrectly rank genuinely promising but less common paths as low-quality, harming recall and causing premature pruning of valid subspaces.

### Mechanism 3
*   **Claim:** This setup unlocks test-time scaling laws: increasing inference compute (via larger `𝐾 +`) improves recommendation metrics (e.g., HRecall@3@1000) without increasing decoder FLOPs, allowing smaller models to surpass larger ones.
*   **Mechanism:** The computational bottleneck in beam search is the decoder's self/cross-attention. By keeping the decoder's active beam size `𝐾` (and thus its compute) fixed and only increasing the initial candidate pool `𝐾 +` evaluated by the lightweight PRM, total inference FLOPs grow sub-linearly (primarily from PRM's cross-attention and a larger Top-K). The PRM acts as a cheap "verifier" that filters the `𝐾 +` candidates to a high-quality `𝐾 ′`, effectively using more "test-time thoughts" to find better paths.
*   **Core assumption:** The marginal cost of scoring `𝐾 +` paths with the PRM is significantly lower than the cost of decoding `𝐾 +` paths for `𝑑` steps. Therefore, scaling `𝐾 +` offers a better compute-quality trade-off than simply scaling model parameters (which increases decoder FLOPs per step).
*   **Evidence anchors:**
    *   [abstract] "Unlocks Test-Time Scaling Laws... by increasing inference compute, smaller models can match or surpass larger models."
    *   [section 4.5] Figure 4 shows HRecall@𝑏@1000 monotonically increases as `𝐾 +` grows (from 1000 to 6000) while `𝐾` remains 1000. The red triangles (brute-force `𝐾` scaling) show steep FLOP increase with minor gains.
    *   [section 4.6] Figure 5 compares test-time scaling (PRM+increasing `𝐾 +`) against parameter scaling, showing better HRecall@3@1000 at equal or lower FLOPs.
*   **Break condition:** Diminishing returns: beyond a certain `𝐾 +`, the PRM may not find proportionally more high-quality paths, and the overhead of Top-K selection and PRM scoring could become significant if `𝐾 +` is extremely large, potentially violating the "negligible increase" claim for very high `𝐾 +` (e.g., >10,000).

## Foundational Learning
*   **Concept: Semantic IDs (SIDs)**
    *   **Why needed here:** SIDs are the discrete token sequences (e.g., `[𝑠₁, 𝑠₂, 𝑠₃]`) that represent items. They are the fundamental "language" the generative model speaks. Understanding their hierarchical nature (coarse-to-fine) is essential to grasp why an error in `𝑠₁` (e.g., wrong category) causes irrecoverable drift.
    *   **Quick check question:** If an item's SID is `[45, 67, 13]` and the model first generates token `45` incorrectly as `99`, what is the fundamental reason subsequent predictions for `𝑠₂` and `𝑠₃` are likely to be meaningless?
*   **Concept: Exposure Bias & Teacher Forcing**
    *   **Why needed here:** This is the root cause of semantic drift. The model is trained to predict the next token given *perfect* history (teacher forcing) but must generate with its own *imperfect* history at inference. It never learns to recover from its own mistakes.
    *   **Quick check question:** During training, if the model incorrectly predicts `𝑠₁ = 99` for a ground-truth `𝑠₁ = 45`, what does the training signal (NTP loss) actually do at that step? What crucial experience is it missing?
*   **Concept: Hierarchical Quantization (RQ-VAE/Residual K-means)**
    *   **Why needed here:** This is the process that creates the SID structure. Residual quantization means `𝑠₂` refines the subspace defined by `𝑠₁`. This hierarchy creates the "drift" vulnerability: a bad `𝑠₁` puts you in the wrong top-level subspace where all subsequent `𝑠₂` codes are irrelevant.
    *   **Quick check question:** In residual quantization for a 3-level SID, what does the second codebook `𝐶₂` (for `𝑠₂`) represent? Is it defined over the entire item embedding space or only a subset?

## Architecture Onboarding
*   **Component map:** Encoder -> Decoder -> Path-level PRM -> Inference Controller
*   **Critical path:** `User History -> Encoder (E⁽ᴸ⁾) -> [for each step 𝑏: Decoder predicts next token for all current beam paths -> extend to get 𝐾 + candidates -> PRM scores all 𝐾 + prefixes -> select top 𝐾 ′ for next step] -> Final 𝐾 ′ complete SID paths`.
*   **Design tradeoffs:**
    *   **𝐾 + vs. Latency:** Larger `𝐾 +` improves quality (Fig 4) but increases PRM scoring and Top-K selection cost. Deployment uses `𝐾+=4000`, `𝐾=𝐾′=1000`.
    *   **PRM Depth `𝐹` vs. Efficiency:** Paper uses `𝐹=1` for deployment. More layers might improve accuracy but add latency. The design reuses `E⁽ᴸ⁾` to minimize parameters (only ~15% increase).
    *   **Negative Sample Count `𝑁`:** More negatives per step (in InfoNCE) may improve PRM discrimination but increases training memory/computation. Paper does not specify `𝑁` in main text.
*   **Failure signatures:**
    *   **Semantic Drift persists:** HRecall@𝑏@𝑘 drops sharply between `𝑏=1` and `𝑏=2` in ablated runs without PRM at step 2 (Table 4, (2) vs (1)).
    *   **PRM Misguidance:** Overall Recall@𝑘 decreases when applying PRM, especially if `𝐾 ′` is too small or `𝐾 +` is insufficient to contain good paths.
    *   **Online Degradation:** A/B test shows *negative* or negligible lift in app usage time, indicating PRM scores do not correlate with offline metrics or user satisfaction in production.
*   **First 3 experiments:**
    1.  **Ablation on PRM Application Steps:** Fix `𝐾=1000`, vary `𝐾 +𝑏` (4000 or "-") at each of the 3 SID levels. Measure HRecall@1/2/3@1000. Expected: Applying PRM at all steps (8) > two steps > one step > none (1).
    2.  **Test-Time Scaling Curve:** Vary `𝐾 +` (1000, 2000, ..., 6000) with `𝐾=𝐾′=1000`. Plot HRecall@3@1000. Expected: Monotonic increase, validating scaling law. Compare against brute-force `𝐾` scaling (same `𝐾` values) showing steeper FLOP increase for smaller gains.
    3.  **Online A/B Test:** Deploy `𝐾+=4000` version vs. baseline (`𝐾=1000`, no PRM). Primary metric: total app usage time % change. Expected: Statistically significant positive lift (as in Table 3: +0.121% on Kuaishou).

## Limitations
*   PRM training relies on uniformly sampled negatives from valid paths `V_b`; representativeness of real error modes is unverified, risking poor generalization to novel drift patterns.
*   Online A/B test restricted to Kuaishou; scalability across platforms/content domains remains unproven.
*   PRM calibration (score reliability) not assessed; potential misranking of viable paths could offset gains.

## Confidence
*   **PRM mechanism**: Medium. Evidence from InfoNCE training and ablations supports the design, but break condition highlights dependency on negative sampling coverage.
*   **Beam search pruning**: Medium. Algorithm 1 and Table 4 show efficacy, yet miscalibration or overfitting risks (per break condition) could undermine reliability.
*   **Test-time scaling laws**: Medium. Figures 4–5 demonstrate monotonic gains vs. `K+`, but single-platform online lift (+0.121%) and potential diminishing returns at very large `K+` limit certainty.

## Next Checks
1.  **PRM calibration audit**: Compute precision/recall of PRM scores on a held-out set of erroneous prefixes (annotated by human judges); expect high true-positive rate for top-ranked paths.
2.  **Cross-dataset scaling replication**: Apply PROMISE to at least two additional public benchmarks (e.g., Amazon Reviews, MovieLens) with hierarchical SIDs; verify monotonic HRecall@k improvement as `K+` increases from 1000→6000.
3.  **End-to-end latency vs. FLOP trade-off**: Profile total inference time (p99) for `K+`∈{1000, 2000, 4000, 6000} against a baseline `K` scaling; confirm sub-linear growth and that `K+=4000` meets SLA constraints.
