# FinReflectKG -- HalluBench: GraphRAG Hallucination Benchmark for Financial Question Answering Systems

## Quick Facts
- arXiv ID: 2603.20252
- Source URL: https://arxiv.org/abs/2603.20252
- Reference count: 27
- Primary result: Embedding-based hallucination detectors maintain robust performance under KG noise while other methods degrade significantly.

## Executive Summary
This paper introduces FinBench-QA-Hallucination, a benchmark comprising 755 SEC 10-K question-answer pairs annotated with strict evidence linkage to knowledge graph triplets. It evaluates six hallucination detectors in both clean and noisy KG conditions, revealing that large language model judges and embedding-based methods achieve the highest clean performance (F1 0.82–0.86). However, most methods suffer severe degradation when triplets are corrupted (MCC drops of 44–84%), while embedding approaches remain relatively robust (9% drop). Statistical tests confirm these differences are significant (p<0.001), underscoring critical vulnerabilities in KG-augmented financial QA systems.

## Method Summary
The authors construct FinBench-QA-Hallucination by extracting Q&A pairs from SEC 10-K filings and annotating each answer with specific supporting KG triplets, enforcing "strict evidence linkage." Six hallucination detectors—including LLM judges, embedding similarity models, and rule-based methods—are evaluated on the benchmark under two conditions: a clean KG and a noisy KG where triplets are corrupted via an unspecified injection process. Performance is measured using F1-score and Matthews Correlation Coefficient (MCC) to assess detection accuracy.

## Key Results
* LLM judges and embedding methods achieve highest clean performance (F1 0.82–0.86).
* Most detectors degrade severely with triplet noise (MCC drop 44–84%).
* Embedding-based approaches remain robust (only 9% drop).
* Statistical tests confirm significant differences (p<0.001).

## Why This Works (Mechanism)
Strict evidence linkage transforms hallucination detection into a binary verification problem: an answer is either supported by an explicit KG triplet or not. This creates an objective ground truth. Noise injection then exposes whether detectors rely on exact string/triple matches (brittle to noise) or semantic similarity (more robust). Embedding-based methods succeed under noise because they operate in continuous vector space, tolerating paraphrased or slightly corrupted evidence via proximity in embedding distribution.

2. **Hallucination detection**: Identifying when generated text is unsupported by sources. *Why needed*: Ensures reliability in high-stakes financial domains. *Quick check*: What distinguishes a hallucination from a legitimate inference in financial QA?
3. **SEC 10-K filings**: Annual reports filed with the SEC containing audited financial statements. *Why needed*: Authoritative, standardized source for corporate financial data. *Quick check*: Which 10-K section details risk factors?
4. **Knowledge Graph triplets**: (subject, predicate, object) tuples representing facts. *Why needed*: Enable precise, queryable evidence for grounding answers. *Quick check*: Convert "Revenue increased by 5%" into a triplet.
5. **Strict evidence linkage**: Mapping each answer to specific supporting triplets. *Why needed*: Provides objective, reproducible hallucination labels. *Quick check*: How is linkage verified during annotation?
6. **Embedding-based similarity**: Using neural embeddings to compute semantic match between answer and triplet. *Why needed*: Tolerates paraphrasing and minor noise. *Quick check*: Why might cosine similarity handle noisy triplets better than string match?

## Architecture Onboarding
- **Component map**: SEC 10-K Filings -> Knowledge Graph Extraction -> FinBench-QA-Hallucination Dataset (Q&A + Evidence Triplets) -> Hallucination Detectors (LLM Judges, Embedding Models, etc.) -> Performance Metrics (F1, MCC)
- **Critical path**: Question -> QA System generates answer -> Detector compares answer to evidence triplets -> Output hallucination decision (supported/unsupported).
- **Design tradeoffs**: LLM judges offer high accuracy but are slow and costly; embedding methods are fast and robust but may miss nuanced support; exact-match detectors are precise but brittle to noise.
- **Failure signatures**: Detector returns "supported" for answers with no linked triplet (false negative); returns "unsupported" for answers with correct but paraphrased evidence (false positive due to strict matching).

## Limitations
* Benchmark limited to SEC 10-K filings, reducing generalizability to other financial domains (e.g., private firms, global markets).
* Annotation process lacks reported inter-annotator agreement and evidence coverage metrics.
* Noise injection method is unspecified, limiting ecological validity of robustness claims.

## Confidence
- High: Benchmark construction (755 Q&A pairs) and clean-performance leaderboard (F1 0.82–0.86) are concrete if dataset is released.
- Medium: Relative ranking of detectors depends on unreported implementation specifics.
- Low: Broad claims about "critical vulnerabilities" overreach single-benchmark findings; generalizability uncertain.
