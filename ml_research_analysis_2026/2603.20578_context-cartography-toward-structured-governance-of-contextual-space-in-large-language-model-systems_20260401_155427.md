# Context Cartography: Toward Structured Governance of Contextual Space in Large Language Model Systems

**Quick Facts**
- arXiv ID: 2603.20578
- Source URL: https://arxiv.org/abs/2603.20578
- Reference count: 21
- Primary result: The paper formalizes a tripartite zonal model for contextual governance in LLMs, defines seven cartographic operators, and reports independent convergence across four agent systems.

**Executive Summary**
Context Cartography introduces a formal framework for governing contextual space in large language model (LLM) systems, addressing critical failure modes such as the "lost in the middle" effect and relational degradation in long contexts. The proposal partitions context into three epistemic zones—black fog (unobserved), gray fog (stored memory), and visible field (active reasoning)—and defines seven operators that intentionally transition information between zones. Cross-system analysis of four modern agent architectures reveals independent convergence on these operators, suggesting their necessity. The framework is mechanically verified in Lean 4 and includes falsifiable predictions and a diagnostic benchmark (CCD) for operator necessity.

**Method Summary**
The paper combines theoretical formalism with empirical cross-system analysis. It adapts concepts from cartographic generalization to define a tripartite zonal model and seven operators (reconnaissance, selection, simplification, aggregation, projection, displacement, layering) that govern information transitions between zones. The author then evaluates implementations of these operators in four contemporary agent systems (Claude Code, Letta, MemOS, OpenViking) using a structured rubric. Key properties and operator invariants are mechanically verified in Lean 4. The work further proposes operator-ablation predictions and a diagnostic benchmark (CCD) to test necessity.

**Key Results**
- Tripartite zonal model clarifies epistemic states and prevents zone-level failures (hallucination, drift/bloat, overload) via controlled transitions (sense, recall, evict, expire).
- Seven cartographic operators are identified; cross-system analysis shows universal adoption of layering (λ, score 5.00) and near-universal projection (π, 4.25), while displacement (δ) is widely neglected (1.25).
- Framework includes testable operator-ablation predictions and a diagnostic benchmark (CCD) for each operator class, with key structural properties formally verified in Lean 4.

**Why This Works (Mechanism)**
The tripartite zonal model (black fog, gray fog, visible field) creates a governance layer that controls information transitions, preventing direct contamination from unobserved space and managing active capacity. Explicit functions (sense, recall, evict, expire) ensure that new information is archived and simplified before entering the visible field, mitigating hallucination and overload. This addresses transformer entropy accumulation and non-uniform salience gradients.

The seven operators target specific failure modes arising from causal attention's U-shaped salience and append-only memory. Displacement (δ) repositions items to salience peaks; simplification (ϕ) reduces token count to curb entropy; projection (π) changes representation while preserving structure; layering (λ) isolates namespaces. Composing these into inbound/outbound pipelines actively reshapes context to maintain signal fidelity.

Independent convergence on these operators across four diverse agent systems (Claude Code, Letta, MemOS, OpenViking) suggests they capture fundamental constraints. The cross-system analysis, using a 5-criterion rubric, found layering universally implemented, projection nearly so, and displacement widely neglected—consistent with the framework's prioritization and indicating that some operators (like displacement) are still emerging solutions.

**Architecture Onboarding**
Component map: Zonal State Manager ↔ (Boundary Operators ρ, σ, π±) ↔ (Within-Zone Operators ϕ, α, δ, λ) ↔ Pipeline Assembler; Maintenance Scheduler asynchronously applies {ϕ, α, λ} to gray fog. Inbound pipeline: σ → π+ → ϕ → δ → λ → visible field. Outbound pipeline: visible field → σ → π- → gray fog.

Critical path: When an agent encounters a knowledge gap, ρ (reconnaissance) decides to invoke a tool (sense). The tool output is simplified (ϕ) and projected (π+) into gray fog (or possibly directly into visible field with guard). At each reasoning turn, the context builder selects relevant items from gray fog (σ), projects them (π+), simplifies further (ϕ), repositions for salience (δ), and layers (λ) into the visible field. After generating a response, if the visible field exceeds capacity, σ selects items to evict, and π- compacts them into gray fog for archival, possibly applying additional ϕ, α, or λ during background maintenance.

Design tradeoffs:
- ϕ: Aggressive token reduction risks losing task-critical details; must balance with preservation.
- π resolution: Coarse projection saves tokens but may omit structural details needed for fine-grained reasoning.
- δ: Repositioning for salience may break chronological dependencies required by some tasks.
- λ: More namespaces improve isolation but increase orchestration complexity.
- Automation vs. configurability: Auto operators ease deployment but reduce fine control.

Failure signatures:
- Hallucination from black fog content appearing in visible field unmediated → missing ϕ on sense output.
- Context collapse (accuracy degrades over iterations) → destructive π- without archival.
- Constraint violations → missing δ (critical info not in salience peaks).
- Namespace collisions → missing λ (conflicting layers mixed in visible field).
- Overload/dilution → weak σ or ϕ (too many/low-quality items in visible field).

First 3 experiments:
1. Operator ablation: Remove each operator from the inbound pipeline, evaluate on CCD tasks. Predict specific degradations per operator.
2. Displacement–length interaction: Test constraint adherence across context lengths (4K vs. 32K tokens) with/without δ. Expect δ effect negligible at short lengths, substantial at long.
3. Compaction mode comparison: Implement archival vs. destructive π- over iterative compaction cycles on a multi-session debugging benchmark. Predict archival maintains accuracy, destructive collapses.

**Open Questions the Paper Calls Out**
1. Is the prescribed inbound pipeline order (λ ◦ δ ◦ ϕ ◦ π+ ◦ σ) universally optimal, or are there task-dependent operator sequences that yield better performance? The paper asks about reorderings (e.g., δ before ϕ when simplification is position-sensitive).
2. How do cartographic operators interact when combined (e.g., can strong layering λ compensate for weak displacement δ), and what are the synergistic or antagonistic effects across operator pairs? The paper notes that interactions require factorial experimental designs.
3. Do the seven cartographic operators remain necessary and sufficient for non-transformer architectures (e.g., SSMs, diffusion LMs), or does the operator basis change with different salience geometries? The paper suggests SSMs may internalize δ while diffusion models emphasize ϕ/α.
4. Can a learned meta-controller dynamically select and parameterize cartographic operators based on real-time context state and task characteristics, rather than relying on static hand-crafted pipelines? The paper asks about learning which operators to apply and with what parameters.

**Limitations**
- CCD benchmark lacks concrete tasks/datasets and evaluation scripts; operator parameterizations are ambiguous; scoring rubric evidence thresholds are ambiguous.
- Confidence levels: Tripartite model and operator definitions high; cross-system operator convergence medium; CCD benchmark and ablation predictions low.
- External validation is weak (average neighbor citations 0.0).

**Confidence**
- Tripartite zonal model and operator definitions: High
- Cross-system operator convergence evidence: Medium
- CCD benchmark and ablation predictions: Low

**Next Checks**
1. Operationalize the CCD benchmark by designing concrete task instances and automated metrics for each operator class (reconnaissance, selection, projection, displacement, etc.), then validate the predicted failure signatures.
2. Specify concrete parameterizations for key operators (e.g., projection schemas f, m, r, d) derived from system documentation or first principles; implement a minimal pipeline and test composition invariants (e.g., that selected items are always projections of gray-fog items).
3. Refine the 5-criterion rubric with explicit evidence thresholds; conduct blind scoring on the four systems by multiple raters and compute inter-rater reliability to verify original scores.
