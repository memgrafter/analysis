# Picking the Right Specialist: Attentive Neural Process-based Selection of Task-Specialized Models as Tools for Agentic Healthcare Systems

## Quick Facts
- arXiv ID: 2602.14901
- Source URL: https://arxiv.org/abs/2602.14901
- Reference count: 29
- Primary result: ToolSelect outperforms 10 SOTA routers on a new benchmark of 1448 chest X-ray queries, achieving up to 59.88% F1 in disease detection (+35.44 points over best baseline).

## Executive Summary
Agentic healthcare systems require dynamic selection of the most suitable specialist model for each query, as no single model performs best on all inputs. ToolSelect introduces an Attentive Neural Process (ANP)-based selector that conditions on the query and compact behavioral reference sets summarizing each model’s performance. Trained via a comp-sum surrogate loss while keeping specialists frozen, ToolSelect achieves state-of-the-art performance on the new ToolSelectBench spanning diagnosis, report generation, visual grounding, and VQA tasks. It substantially improves over baselines and narrows the gap to the oracle across all tasks.

## Method Summary
ToolSelect addresses query-conditioned specialist selection by encoding multimodal queries (image + instruction) with shared backbones (ViT-B/16 for images, CheXbert for text) into a unified representation. For each candidate tool, a small reference set (16–64 examples) of its past predictions is processed: embeddings undergo self-attention and then cross-attention with the query to produce a query-dependent tool descriptor. This descriptor, concatenated with the tool’s real-time prediction and optional metadata, is scored by a lightweight MLP. Selection probabilities are obtained via masked softmax, excluding tools that do not support the current query. The selector is trained end-to-end using a differentiable comp-sum surrogate loss, with regularization (panel entropy, L2, dropout), while all specialist models remain frozen.

## Key Results
- Outperforms 10 SOTA routers on ToolSelectBench; disease detection F1: 43.80% (Open-I) and 59.88% (VinDr), improving over best baseline by 31.82 and 35.44 points respectively.
- Report generation F1-RadGraph: 24.17% (+1.77); grounding mean IoU: 50.08% (+~9); VQA accuracy: 72.01% (+~8.8).
- Consistently reduces the oracle gap across all tasks.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** ToolSelect uses an Attentive Neural Process (ANP) to condition tool selection on the specific query by attending over compact behavioral reference sets summarizing each tool’s performance.
- **Mechanism:** The multimodal query (image + question) is encoded into a unified representation *u(p)* via shared backbones. For each candidate tool *E*, a small reference set *Dt_E* (tens of examples with inputs, ground truths, and the tool’s aligned predictions) is embedded. Self-attention over reference embeddings refines them, and cross-attention with *u(p)* produces a query-dependent tool descriptor *ψt_E(p)*. This descriptor, concatenated with the tool’s real-time prediction *˜mt_E(x)* and optional metadata *η_E*, is scored by a lightweight MLP to yield *rθ(p, E; St)*. The scores are normalized via masked softmax (masking tools with partial support) to produce selection probabilities.
- **Core assumption:** Assumption: The reference set sufficiently captures the tool’s behavior on queries similar to the current input, such that attention can identify relevant behavioral patterns.
- **Evidence anchors:**
  - [abstract]: “propose an Attentive Neural Process–based selector conditioned on the query and per-model behavioral summaries”
  - [section 2.3]: Detailed ANP architecture, reference set construction, and attention computations.
  - [corpus]: Weak evidence; corpus neighbors include LLM routers (e.g., GraphRouter) but not ANP-based tool selection. No direct support.
- **Break condition:** If the reference set is too small, unrepresentative, or mismatched to the test distribution, attention may fail to retrieve relevant examples, leading to inconsistent or poor routing decisions.

### Mechanism 2
- **Claim:** Compact behavioral reference sets serve as efficient, fixed descriptors of tool competence, eliminating the need for test-time gradient computation or model fine-tuning.
- **Mechanism:** Instead of evaluating tools via costly inference on many examples or computing gradients, each tool provides a pre-computed reference set of *Bt* examples (16–64) covering its typical outputs. These sets are static during routing and are processed once by the ANP to generate *ψt_E(p)*. This decouples tool evaluation from the selector’s training and keeps all underlying specialists frozen.
- **Core assumption:** Assumption: A small, fixed reference set can reliably indicate a tool’s relative strengths and weaknesses across the task distribution.
- **Evidence anchors:**
  - [section 2.3]: “Task-specific reference set (few-shot behavioural descriptors)… Bt ∈[16,64]”
  - [section 3.3]: Implementation uses these reference set sizes; training batch size 16.
  - [corpus]: No direct evidence; corpus neighbors focus on routing algorithms, not reference set design.
- **Break condition:** If the reference set is biased (e.g., over-representing certain subpopulations) or fails to include edge cases, the descriptor may misrepresent the tool’s true capabilities, causing systematic misrouting.

### Mechanism 3
- **Claim:** The comp-sum surrogate loss enables differentiable training of the selector while providing a consistent upper bound on the true task-conditional selection risk.
- **Mechanism:** The true selection loss is the cost of the chosen tool, which is non-differentiable due to the argmax. The comp-sum surrogate replaces the indicator of selection with a weighted sum over all tools, where each weight *wj* is the pairwise cost difference relative to others, multiplied by a decreasing function *Ψ* (logistic) of the selection probability. This yields a smooth, differentiable objective that correlates with the true risk.
- **Core assumption:** Assumption: Minimizing the comp-sum surrogate decreases the expected true selection loss; the surrogate is a consistent upper bound.
- **Evidence anchors:**
  - [section 2.2]: Formal definition of *Lt_Ψ* and logistic *Ψ(u) = -log u*; reduction to binary margin form for *m=2*.
  - [section 3.3]: Training optimizes this surrogate with AdamW.
  - [corpus]: Theoretical justification cited from Mao et al. (2023b;a), but these works are not in the provided corpus neighbors.
- **Break condition:** If many tools have nearly identical costs, the pairwise weights become uninformative and gradients may vanish, slowing or preventing convergence to a good selector.

## Foundational Learning
- **Concept: Attentive Neural Process (ANP)**
  - **Why needed here:** ANP allows the selector to adapt to each query by dynamically weighting reference examples, enabling query-specific tool assessment without test-time optimization.
  - **Quick check question:** How does the cross-attention between the query and reference set produce a query-dependent tool descriptor?
- **Concept: Comp-sum surrogate loss**
  - **Why needed here:** The selection decision is discrete; comp-sum provides a differentiable surrogate that is theoretically aligned with the true risk, enabling gradient-based training.
  - **Quick check question:** For a panel of two tools with costs *c1* and *c2*, what is the form of the logistic comp-sum loss?
- **Concept: Partial label support and abstention**
  - **Why needed here:** Tools may not support all output components (e.g., certain diseases or phrases); masking ensures invalid tools do not contribute to loss or selection probabilities.
  - **Quick check question:** How is the validity indicator *1[(x, t) ∈ σ_E]* used in the masked softmax?

## Architecture Onboarding
- **Component map:** Query encoder (image: ViT-B/16, text: CheXbert) → fused representation *u(p)* → for each tool: Reference encoder (self-attention on reference embeddings, then cross-attention with *u(p)*) → query-dependent descriptor *ψt_E(p)* → concatenate with tool prediction *˜mt_E(x)* and metadata *η_E* → MLP scorer *gθ* → scores → masked softmax (mask invalid tools) → selection probabilities → argmax. Loss: comp-sum surrogate + panel entropy + L2.
- **Critical path:** Input (x, q) → *u(p)* → for each tool: compute *ψt_E(p)* via ANP → concatenate → *gθ* → scores → masked softmax → argmax selection.
- **Design tradeoffs:**
  - **Reference set size (Bt):** Larger sets improve descriptor quality but increase memory/computation. Paper uses 16–64.
  - **Backbone choice:** Shared encoders reduce parameters but may not capture task-specific nuances.
  - **Panel size (m):** Fixed during training; larger *m* better approximates population risk but slows training.
- **Failure signatures:**
  - **Uniform probabilities:** Selector cannot distinguish tools (e.g., early training or poor reference sets).
  - **Singleton selection:** Selector always picks one tool, ignoring query (overfitting).
  - **Degraded performance on shifted domains:** If reference sets come from a different distribution than test queries.
  - **High variance across similar queries:** Indicates instability in attention or scoring.
- **First 3 experiments:**
  1. **Disease detection:** Evaluate on Open-I and VinDr test splits; compare macro F1, accuracy, AUC.
  2. **Report generation:** Evaluate F1-RadGraph and RateScore on Open-I reports.
  3. **Visual grounding:** Evaluate mean IoU and mAP@0.5 on VinDr phrase-level grounding queries.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** What is the optimal size and composition of the behavioral reference sets for tool selection, given the trade-off between computational cost and accuracy?
- **Basis in paper:** [inferred] The paper uses reference sets of size Bt ∈ [16,64] and states they should be as large as feasible, but does not investigate the optimal size or diversity.
- **Why unresolved:** The reference set directly impacts the ANP's ability to capture tool behavior; choosing a suboptimal size could lead to poor generalization or unnecessary overhead.
- **What evidence would resolve it:** Systematic experiments varying reference set size and diversity across tasks, measuring selection accuracy and computational cost, to derive guidelines or a principled method for setting Bt.

### Open Question 2
- **Question:** Can ToolSelect generalize to other medical imaging modalities (e.g., CT, MRI) and non-image clinical tasks beyond chest X-rays?
- **Basis in paper:** [inferred] The paper evaluates ToolSelect exclusively on chest X-ray tasks and does not test on other modalities or tasks.
- **Why unresolved:** The method's reliance on modality-specific encoders and task-specific label alignment may not transfer directly; generalization is crucial for broader adoption.
- **What evidence would resolve it:** Extensive experiments on additional medical imaging datasets and tasks, measuring performance relative to chest X-ray results.

### Open Question 3
- **Question:** Would alternative meta-learning architectures (e.g., prototypical networks, simple metric learners) achieve comparable tool selection performance with lower complexity compared to the Attentive Neural Process?
- **Basis in paper:** [inferred] The paper adopts ANP but does not compare against other few-shot learning frameworks.
- **Why unresolved:** ANP introduces architectural complexity; simpler alternatives might be more efficient and easier to train, which matters for practical deployment.
- **What evidence would resolve it:** Controlled ablation studies replacing ANP with other meta-learning modules while keeping other components constant, evaluating selection accuracy, training stability, and inference speed.

## Limitations
- Specialist model access & alignment: The 55 frozen tool weights and exact `ρ_E` mappings for output space alignment are not publicly released, blocking independent replication.
- Reference set construction: The sampling strategy for `D_t^E` (16–64 examples) is unspecified; representativeness relative to test queries is unclear.
- Training panel distribution: The prior `P_t(E)` used to sample tool panels during training is not detailed (e.g., uniform, weighted, with/without replacement).

## Confidence
- Performance claims: *Medium* – strong on-provided benchmark but no external dataset validation.
- Mechanism design: *Medium* – paper details architecture; theoretical justification cited but not in corpus neighbors.
- Reproducibility: *Low* – critical implementation details (specialist models, reference set creation) are missing.
