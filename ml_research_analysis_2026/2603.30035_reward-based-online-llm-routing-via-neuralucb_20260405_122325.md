# Reward-Based Online LLM Routing via NeuralUCB

## Quick Facts
- arXiv ID: 2603.30035
- Source URL: https://arxiv.org/abs/2603.30035
- Reference count: 2
- Primary result: NeuralUCB significantly outperforms random, min-cost, and RouteLLM-BERT on RouterBench, achieving higher average reward (~0.60) while reducing inference cost to ~33% of a max-quality reference.

## Executive Summary
The paper addresses cost-aware LLM routing, where a system dynamically selects a model per query to balance quality and inference cost under partial feedback (only the chosen model's outcome is observed). It proposes NeuralUCB, a contextual bandit algorithm that uses a neural network (UtilityNet) to predict a utility reward defined as quality multiplied by an exponential cost penalty. The network's last hidden layer provides features for an Upper Confidence Bound (UCB) exploration bonus, and a gating branch controls when to apply this bonus. Evaluations on the RouterBench benchmark with a 20-slice simulated online protocol show NeuralUCB achieves an average reward of ~0.60, substantially higher than random (~0.32), min-cost (~0.52), and RouteLLM-BERT (~0.36). The method reduces inference cost to about 33% of a max-quality reference, though a quality gap remains.

## Method Summary
NeuralUCB formulates routing as a contextual bandit problem. For each query, it uses a neural network (UtilityNet) to predict a utility for each candidate model, combining predicted quality and normalized cost via a fixed parameter λ. The last hidden layer of UtilityNet yields feature representations used to compute an UCB exploration bonus that depends on the model's historical selection frequency and feature covariance. A gating branch determines whether to add this bonus, balancing exploration and exploitation. After each decision, the network is updated with the observed reward (quality) and cost of the chosen model, while unseen models' rewards remain unknown. This approach handles partial feedback and adapts online to optimize the utility objective.

## Key Results
- NeuralUCB achieves average reward ~0.60 on RouterBench, significantly outperforming random (~0.32), min-cost (~0.52), and RouteLLM-BERT (~0.36).
- It reduces inference cost to approximately 33% of a max-quality reference while maintaining competitive overall reward.
- Despite cost reduction, a quality gap persists compared to always using the highest-quality model.

## Why This Works (Mechanism)
NeuralUCB effectively balances exploration and exploitation in cost-aware routing. The UtilityNet predicts a utility that directly encodes the cost-quality trade-off via λ. The UCB exploration bonus, derived from the network's feature representations, encourages trying under-sampled models, which is crucial under partial feedback to avoid suboptimal convergence. The gating branch adapts exploration intensity based on learned uncertainty, preventing unnecessary cost escalation. This mechanism allows the system to gradually identify cost-efficient models without sacrificing too much quality, leading to superior cumulative reward in online settings.

## Foundational Learning
- **Contextual bandits**: Framework for sequential decision-making with context and partial feedback; needed to model routing where each query has features and only chosen model's reward is observed. Quick check: Does the algorithm balance exploration and exploitation? Yes, via UCB.
- **Neural UCB**: Extension of UCB to deep networks, using hidden layer features to model uncertainty; needed to handle high-dimensional query representations. Quick check: Are features from the last hidden layer used to compute the bonus? Yes.
- **Utility function**: Combines quality and cost into a single reward (quality * exp(-λ * normalized_cost)); needed to encode user preferences for cost savings. Quick check: Is λ a tunable hyperparameter that controls cost sensitivity? Yes.
- **Partial feedback**: Only the selected model's outcome is observed; necessitates exploration to learn about other models. Quick check: Does the method avoid needing rewards for unchosen models? Yes, it uses UCB to estimate potential rewards.

## Architecture Onboarding
**Component map**: Query -> UtilityNet -> (Predicted Utility, Hidden Features); Hidden Features -> UCB Bonus; Predicted Utility + UCB Bonus -> Model Selection.

**Critical path**: For a given query and candidate models, UtilityNet predicts utility and extracts hidden features; UCB bonus is computed from these features and historical data; the gating branch decides whether to add the bonus; the model with the highest adjusted utility is selected and invoked; after observing quality and cost, the network updates.

**Design tradeoffs**:
- Neural network provides expressive utility estimation but introduces inference latency and requires training data.
- UCB exploration improves long-term reward but may temporarily increase cost by selecting expensive models.
- Fixed λ simplifies the utility but cannot adapt to changing cost-quality preferences over time.
- Gating branch adds complexity but helps modulate exploration based on uncertainty.

**Failure signatures**:
- Excessive exploration leading to high cost spikes.
- UtilityNet mispredicting quality or cost due to poor calibration.
- Gating failure causing either no exploration (stuck in local optimum) or constant exploration (high variance).
- Network update instability if learning rate is too high.

## Limitations
- Evaluation is confined to RouterBench simulation (20 slices); real-world query distributions, latency, and model failures may differ.
- The utility function uses a fixed λ; its sensitivity and generalization to other preferences are unclear.
- Baselines are limited to older methods; recent routers (e.g., xRouter, CARROT) are not included.
