# In-Context Planning with Latent Temporal Abstractions

## Quick Facts
- **arXiv ID:** 2602.18694
- **Source URL:** https://arxiv.org/abs/2602.18694
- **Reference count:** 40
- **Primary result:** I-TAP achieves state-of-the-art normalized returns on Stochastic MuJoCo (mean 98.50, 71.33, 76.45 across datasets) and Adroit (133.81, 128.37, 105.98, 109.85 expert; POMDP: 81.68, 72.36, 95.05, 52.16), addressing primitive-scale branching and partial observability.

## Executive Summary
I-TAP introduces a unified framework for offline reinforcement learning that combines in-context adaptation with online planning in a learned discrete temporal-abstraction space. The method compresses observation-macro-action segments into coarse-to-fine token stacks using an observation-conditioned residual-quantization VAE, enabling efficient search via Monte Carlo Tree Search (MCTS) in a discrete latent space. A causal Transformer models a prior over tokens from recent context, serving as both a task-adaptation mechanism and a latent dynamics simulator. Test-time MCTS leverages this prior to guide planning without gradient updates. Empirical evaluations on Stochastic MuJoCo and Adroit benchmarks, including partial observability settings, show substantial improvements over prior approaches. Ablations confirm the critical roles of macro-actions, context conditioning, planning, and residual depth.

## Method Summary
I-TAP consists of training and inference phases. During training, it processes offline trajectories by extracting macro-scale segments (length L=3), each containing return-to-go, macro-return, observation, and a primitive-action sequence. An observation-conditioned residual-quantization VAE (RQ-VAE) encodes each segment into a depth-D stack of discrete tokens via a shared codebook, trained with reconstruction and commitment losses. Simultaneously, a causal Transformer is trained to predict the next token stack given a context of C recent token stacks and the current observation; this becomes the prior p_φ. At inference, the agent maintains a sliding context window of the last C token stacks. For each decision step, it pre-samples candidate macro-actions using the prior, simulates outcomes via the prior and the decoder to construct a latent search tree, and runs MCTS (P-UCT) over the discrete token space to select the optimal macro. The first primitive action of the chosen macro is executed.

## Key Results
- **Stochastic MuJoCo:** Mean normalized returns 98.50 (Medium-Expert), 71.33 (Medium), 76.45 (Medium-Replay) across perturbation levels 0, 2.5, 5.
- **Adroit expert:** State-of-the-art returns: 133.81 (Pen), 128.37 (Hammer), 105.98 (Door), 109.85 (Relocate).
- **Adroit POMDP:** 81.68 (Pen), 72.36 (Hammer), 95.05 (Door), 52.16 (Relocate), outperforming baselines.

## Why This Works (Mechanism)
The approach is explained through three core mechanisms:

### Mechanism 1: Discretization via Residual Quantization
The RQ-VAE compresses continuous observation-macro-action data into a discrete latent space, reducing planning complexity while preserving reconstruction fidelity. The coarse-to-fine token stack balances expressiveness and compactness. Ablations show that increasing residual depth improves performance up to a plateau, confirming the importance of capacity.

### Mechanism 2: In‑Context Adaptation via Temporal Transformer
The Transformer prior p_φ(kt,1:D | k<t,1:D, o_t) autoregressively models token stacks conditioned on recent context. This allows the agent to infer latent task parameters (e.g., perturbation severity) from history and adapt online without gradient updates. Longer contexts yield better adaptation, especially under high stochasticity.

### Mechanism 3: Planning via Monte Carlo Tree Search in Latent Space
MCTS operates directly in the discrete token space, guided by the context‑conditioned prior. It simulates future trajectories via the prior and backs up values, efficiently balancing exploration and exploitation. The approach handles partial observability and stochastic dynamics, with ablations demonstrating benefits of deeper search horizons.

## Foundational Learning

### Macro‑Actions as Temporal Abstractions
- **Why needed:** Macro-actions of fixed length L reduce the effective planning horizon and branching factor, making MCTS tractable in high-dimensional continuous control.
- **Quick check:** How does macro length L interact with context size C to determine the effective history length for adaptation?

### Residual Quantization (RQ‑VAE)
- **Why needed:** RQ‑VAE scales discretization by recursively quantizing residuals, maintaining high reconstruction fidelity for high‑dimensional data without exploding codebook size.
- **Quick check:** What is the key difference between RQ‑VAE and standard VQ‑VAE, and how does it increase effective capacity?

### Monte Carlo Tree Search (MCTS)
- **Why needed:** MCTS performs online optimization in the latent token space, handling uncertainty and long horizons by sampling futures and backing up values, surpassing static policies.
- **Quick check:** How does I‑TAP’s MCTS incorporate the context‑conditioned prior to guide exploration?

## Architecture Onboarding

### Component map
RQ-VAE encoder -> Temporal Transformer -> Decoder -> Latent search tree constructor -> MCTS engine -> Policy head

### Critical path
- **Training:** Extract macro-step tokens from offline data. Train RQ-VAE on reconstruction and commitment losses. Train Transformer prior via negative log-likelihood.
- **Inference:** Encode recent history into context tokens. Pre-construct a latent search tree by sampling top-K macro candidates via the prior and simulating outcomes. Run MCTS on the cached tree using P‑UCT. Execute the first primitive action from the selected macro.

### Design tradeoffs
- **Macro length L:** Longer macros shorten planning horizon but increase steps per macro; too short balloons branching factor.
- **Context size C:** Larger context enhances latent disambiguation but increases latency; too small impairs adaptation.
- **Residual depth D:** Higher depth improves reconstruction fidelity but adds computational overhead; performance typically plateaus.
- **Planning depth H:** Deeper search better compensates for limited context but raises decision time.
- **Number of simulations:** More simulations improve value estimates but linearly increase compute cost.

### Failure signatures
- **High reconstruction error:** Indicates RQ-VAE is underfitting; inspect codebook size, depth, loss weights.
- **Poor adaptation to new regimes:** Context window too short or prior fails to capture latent dynamics; increase C or adjust context masking.
- **MCTS degeneracy:** Over‑confident prior or mis‑tuned P‑UCT constants; adjust exploration parameters or temperature.
- **Latency spikes:** Caused by large context or deep planning; optimize parallelization and caching.

### First 3 experiments
1. **Ablation on residual depth D:** Train with D ∈ {1,2,3,5}, measure reconstruction loss and normalized returns; expect improvement up to a saturation point.
2. **Held‑out regime generalization:** Train only on perturbation levels 0 and 2.5, test on 5.0; compare against baselines without context to quantify adaptation gains.
3. **Context‑length latency benchmark:** Measure average decision time for C ∈ {1,3,6,12} with fixed planning depth; identify the point where longer context ceases to justify additional latency.

## Open Questions the Paper Calls Out
- **Optimal context length:** What context size best balances adaptation and latency in partially observable settings? The paper tests only three lengths.
- **Macro-action length interaction:** How does L interact with C and stochasticity to affect effective planning horizon and branching? Only L=1,3,6 were compared.
- **Residual depth scaling:** What is the principled relationship between D and task complexity (e.g., observation/action dimensionality)? The choice appears ad‑hoc.
- **Intra‑episode non‑stationarity:** Can I‑TAP adapt to latent regime shifts within an episode? The paper assumes per‑episode stationarity.

## Limitations
- **Implementation gaps:** Critical details (macro-action sampling, decoder architecture, codebook updates, context padding) are unspecified, hindering exact replication.
- **Reconstruction‑planning trade‑off:** Higher residual depth may not translate to better control and increases computational cost; optimal capacity depends on the task.
- **Prior accuracy under shift:** The context‑conditioned prior may become unreliable when facing distribution shifts (e.g., unseen perturbations), misleading MCTS.

## Confidence
- Discretization via Residual Quantization: Medium
- In‑Context Adaptation via Temporal Transformer: Medium
- Planning via Monte Carlo Tree Search: High
