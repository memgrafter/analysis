# Beyond Static Summarization: Proactive Memory Extraction for LLM Agents

## Quick Facts
- **arXiv ID:** 2601.04463
- **Source URL:** https://arxiv.org/abs/2601.04463
- **Reference count:** 7
- **Primary result:** ProMem achieves 73.80% memory integrity and 62.26% QA accuracy on HaluMem, significantly outperforming ~42% integrity baselines.

## Executive Summary
ProMem addresses a fundamental flaw in current LLM agent memory systems: static, one-off summarization fails to capture future-relevant details and accumulates errors. Instead, it frames memory extraction as an iterative cognitive process, inspired by recurrent processing theory. The framework introduces two key modules: (1) memory completion via semantic matching to identify and re-extract overlooked dialogue turns, and (2) memory verification via self-questioning to probe the dialogue history, validate facts, and discard hallucinations. Evaluated on the HaluMem benchmark, ProMem substantially improves memory integrity (73.80% vs. ~42%) and downstream QA accuracy (62.26%), while demonstrating robustness under token compression and when using smaller language models.

## Method Summary
ProMem operates on raw dialogue histories to produce a structured memory bank. The process begins with an initial extraction pass using a prompt (`Pextract`) to generate candidate memory entries. A completion module then employs semantic matching—comparing embeddings of entries and dialogue turns—to flag uncovered turns and perform targeted supplementary extraction only on those turns. A verification module conducts self-questioning: for each candidate entry, the agent generates a probing question, searches the original dialogue for supporting evidence, and either replaces the entry with a dialogue-grounded version or discards it as a hallucination. Finally, a deduplication step merges consistent entries. The system uses GPT-4o-mini for generation, GPT-4o for judging, and Qwen3-Embedding-8B for semantic similarity. Key hyperparameters include a matching threshold τ_match=0.6 and deduplication threshold τ_sim=0.8.

## Key Results
- **Memory integrity** reaches 73.80% on HaluMem, compared to ~42% for static summarization baselines.
- **QA accuracy** improves to 62.26% by leveraging the higher-fidelity memory.
- **Robustness** is maintained under token compression (via LLMLingua-2) and when using smaller models (Llama3-8B).

## Why This Works (Mechanism)

### Mechanism 1: Iterative Recurrent Processing
**Claim:** Treating extraction as an iterative cognitive process, rather than a static one-off summarization, mitigates the "ahead-of-time" problem where future task relevance is unknown.  
**Mechanism:** Inspired by recurrent processing theory (RPT), ProMem introduces a recurrent feedback loop. The initial "feed-forward" extraction produces a baseline memory. This is followed by active probing (self-questioning) and verification against raw dialogue, allowing recovery of missed details and correction of hallucinations.  
**Evidence:** The abstract and section 3.1 explicitly link the two-phase process to RPT. Neighbor papers (e.g., RGMem, A-MEM) explore related memory management but do not directly evaluate this specific iterative extraction loop.  
**Break condition:** If future user queries are entirely predictable from the initial dialogue context, the feedback loop’s recovery effort becomes redundant.

### Mechanism 2: Semantic Completion via Targeted Re-extraction
**Claim:** Semantic matching between extracted memory entries and source dialogue turns identifies overlooked information, enabling efficient gap-filling.  
**Mechanism:** After initial extraction, embeddings for each entry and dialogue turn are compared via cosine similarity. Turns with low maximum similarity to any entry are flagged as "uncovered." A supplementary extraction is performed *only* on these specific turns.  
**Evidence:** Section 3.3 details the mapping and conditional re-extraction. Section 4.4/Fig 4 shows robustness under token compression, suggesting the targeted approach salvages memory from degraded inputs. Related work does not replicate this two-stage completion design.  
**Break condition:** If dialogues contain heavy paraphrasing or abstraction where a fact’s semantic meaning diverges from its source turn’s surface form, similarity matching may fail to flag a miss.

### Mechanism 3: Self-Questioning for Hallucination Filtering
**Claim:** Agent-generated verification queries act as an effective feedback signal to detect hallucinations and refine memory fidelity.  
**Mechanism:** For each candidate entry, the agent generates a probing question seeking supporting evidence. It re-scans the original dialogue to answer this question. If evidence exists, a new, dialogue-grounded entry is created; if not, the original entry is discarded. Deduplication merges consistent results.  
**Evidence:** Section 3.4 describes the evidence-seeking logic. Table 2 (Ablation) shows a large QA accuracy drop when removing verification (+10.74% gain with MV). Table 4 (Case Study) contrasts vague baseline answers with ProMem’s precise outputs. No direct corpus validation exists.  
**Break condition:** If the backbone LLM cannot formulate precise, distinguishing questions for ambiguous facts, the loop may introduce noise or fail to catch errors.

## Architecture Onboarding
- **Component map:** Raw Dialogue -> Initial Extraction (LLM) -> Candidate Memory -> [Semantic Matching & Supplementary Extraction] -> Candidate Memory -> [Self-Questioning -> Evidence Search -> Deduplication] -> Final Memory.
- **Critical path:** The recurrent verification loop (self-questioning cycle) is the quality engine that prunes hallucinations and refines entries. Failure here directly undermines integrity and QA gains.
- **Design tradeoffs:**
  1. Token Cost vs. Memory Fidelity: The iterative loop increases write-time tokens but amortizes cost over many reads and prevents error propagation.
  2. Model Capability vs. Loop Efficacy: Verification success depends on the LLM’s ability to generate insightful questions; smaller models reduce cost but risk a weaker feedback signal.
  3. Completeness vs. Precision: The system favors recall (recovering missing details). The deduplication threshold (τsim) is a key knob: lower values increase recall but risk redundancy; higher values increase precision but may discard corrected entries.
- **Failure signatures:**
  1. **Memory Integrity Stagnation:** After the loop, integrity remains near the "w/o MC & MV" baseline (~54%), suggesting both modules failed (e.g., poor similarity threshold).
  2. **High Hallucination Rate in QA:** Final memory contains many unsupported facts, indicating a failed verification loop (e.g., ineffective self-questioning).
  3. **Extreme Sensitivity to Token Compression:** Performance collapses rapidly as compression increases, indicating the completion module cannot identify uncovered turns from degraded context.
- **First 3 experiments:**
  1. **Ablation Study (Table 2):** Isolate contributions of Memory Completion (MC) and Memory Verification (MV) by removal. Verify MC boosts integrity and MV boosts QA accuracy.
  2. **Token Compression Robustness (Figure 4):** Systematically compress dialogue tokens and measure degradation. Confirms ProMem’s resilience compared to a sensitive baseline (Mem0).
  3. **Small Language Model Deployment (Table 3):** Run full pipeline with Llama3-8B. A significant gap over Mem0 in integrity/QA confirms robustness to model capability.

## Open Questions the Paper Calls Out
1. **Lifelong Memory Management:** How can ProMem’s iterative extraction be extended with updating and forgetting mechanisms to handle storage limits over indefinite time horizons? (Basis: Future Work section)
2. **Threshold Sensitivity:** What are the optimal thresholds for semantic matching (τ_match) and deduplication (τ_sim), and how do they trade off completeness against hallucination risk across domains? (Basis: Empirically set defaults without systematic study)
3. **Prompt Engineering Impact:** To what extent does the self-questioning prompt design influence verification efficacy, and can automated prompt optimization further enhance fidelity? (Basis: Fixed prompt without variation analysis)
4. **Precision-Recall Trade-off:** Does ProMem’s pursuit of higher completeness introduce a precision-recall trade-off where recovered details become inaccurate, and at what point does increased integrity cease to improve downstream QA? (Basis: Overall accuracy masks quality differences in newly added entries)

## Limitations
- **Prompt templates** (`Pextract`, `Psupp`, `Pquestion`) are unreported; reproduction requires approximation, risking prompt-sensitive performance.
- **Dataset access** to HaluMem and LongMemEval is unclear; without official releases, proxy datasets or author contact may be needed.
- **Evaluation granularity** (ground-truth fact matching criteria, judging protocols) is unspecified, potentially affecting reported integrity/accuracy scores.

## Confidence
- **Mechanism 1 (Iterative RPT Loop):** Medium. Theoretical grounding is clear, but corpus evidence for this specific design in dialogue extraction is weak.
- **Mechanism 2 (Semantic Completion):** Medium. Algorithm description is precise, but no neighboring work validates the two-stage completion via similarity matching; break condition risk is noted.
- **Mechanism 3 (Self-Questioning Verification):** High. Strongest support via ablation (Table 2) and case study (Table 4); empirical evidence upholds LLM-generated question efficacy.

## Next Checks
1. **Prompt Sensitivity Sweep:** Systematically vary key prompt phrases for extraction/verification on a held-out subset to quantify performance volatility vs. reported results.
2. **Threshold Optimization:** Perform a grid search over τ_match (0.5–0.9) and τ_sim (0.6–1.0) to validate the chosen defaults (0.6, 0.8) and identify robustness boundaries.
3. **Manual Hallucination Audit:** Sample 100 discarded memory entries from the verification step; human-label whether each was a true hallucination or a valid fact, assessing false-positive/negative rates of the self-questioning filter.
