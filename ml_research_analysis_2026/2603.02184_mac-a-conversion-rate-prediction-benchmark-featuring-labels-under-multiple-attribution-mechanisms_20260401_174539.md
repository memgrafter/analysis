# MAC: A Conversion Rate Prediction Benchmark Featuring Labels Under Multiple Attribution Mechanisms
## Quick Facts
*   **arXiv ID:** 2603.02184
*   **Source URL:** https://arxiv.org/abs/2603.02184
*   **Reference Count:** 40
*   **Primary Result:** Introduces MAC, the first public CVR benchmark with multi-attribution labels, and shows its proposed MoAE model surpasses prior SOTA (NATAL) by up to +0.92 percentage points GAUC.

## Executive Summary
This paper addresses a critical gap in conversion rate (CVR) prediction research: the lack of public datasets with labels derived from multiple attribution mechanisms. It introduces the MAC benchmark, which provides conversion labels from last-click, first-click, linear, and DDA attribution for 79 million clicks. Alongside the dataset, the authors release PyMAL, an open-source library of multi-attribution learning (MAL) baselines. Systematic evaluation on MAC demonstrates that MAL consistently improves performance across all target attribution settings, with the most significant gains for users with long conversion paths. The proposed Mixture of Asymmetric Experts (MoAE) model, combining mixture-of-experts for comprehensive knowledge learning with asymmetric knowledge transfer for main-task prioritization, establishes a new state-of-the-art.

## Method Summary
The work formalizes Multi-Attribution Learning (MAL) for CVR as a multi-task learning problem where one attribution mechanism (e.g., last-click) is the primary task and the others are auxiliary tasks. The MAC dataset provides user features (20 categorical), behavior sequences (item/shop/category IDs + visual similarity), and continuous attribution weights for all four mechanisms. Models are trained with binary cross-entropy loss, using the continuous attribution weights as sample importance weights. The paper evaluates several MTL architectures (Shared-Bottom, MMoE, PLE, HoME, NATAL) and proposes MoAE, which uses a Mixture-of-Experts backbone with shared and private experts per attribution, coupled with an asymmetric transfer module to funnel auxiliary knowledge into the main task predictor. Optimal auxiliary task combinations are found via greedy forward selection for each primary target.

## Key Results
*   MAL consistently improves primary task GAUC compared to single-attribution training across all four target attribution mechanisms.
*   The proposed MoAE model substantially outperforms the prior MAL SOTA (NATAL), achieving GAUC gains of up to +0.92 percentage points.
*   Performance gains are most pronounced for users with longer conversion paths, and the choice of auxiliary objectives is critical (e.g., first-click primary only benefits from last-click auxiliary).

## Why This Works (Mechanism)
### Mechanism 1: Multi-Faceted Supervision from Complementary Attribution Views
*   **Claim:** MAL improves CVR prediction by integrating conversion labels from multiple attribution mechanisms, each encoding distinct perspectives on touchpoint value.
*   **Mechanism:** Joint training on labels from last-click, first-click, linear, and DDA forces the model to learn a more holistic representation of user conversion intent than any single view, as each mechanism assigns credit differently based on touchpoint position or causal inference.
*   **Core Assumption:** The diverse attribution labels capture complementary, non-redundant signals about conversion causality.
*   **Evidence Anchors:** [abstract] states MAL enables "a more comprehensive and holistic understanding of touchpoint contributions." [section 3.1] formalizes MAL with a set of attribution mechanisms. Corpus context from related MAL papers supports the paradigm.

### Mechanism 2: Knowledge Transfer via Multi-Task Learning Architecture
*   **Claim:** MAL leverages MTL architectures to share representations across attribution tasks, capturing common conversion patterns while retaining task-specific nuances.
*   **Mechanism:** Models like PLE and MoAE use mixture-of-experts (MoE) structures with shared experts for common patterns and private experts for attribution-specific patterns. Gradients from all tasks update shared parameters, enabling cross-task knowledge transfer.
*   **Core Assumption:** Conversion patterns underlying different attribution mechanisms overlap sufficiently for shared learning, yet each mechanism has unique aspects requiring specialized modeling.
*   **Evidence Anchors:** [section 4] describes MTL baselines. [section 5.1] shows MTL with MoE (PLE, HoME) improves metrics vs. Shared-Bottom. Corpus: other MTL-for-CVR works support this.

### Mechanism 3: Asymmetric Knowledge Prioritization for Main-Task Optimization
*   **Claim:** Effective MAL must both learn multi-attribution knowledge and leverage it in a main-task-prioritized manner to avoid auxiliary tasks degrading primary performance.
*   **Mechanism:** NATAL and MoAE incorporate asymmetric transfer: auxiliary knowledge is integrated into the main task predictor while auxiliary task gradients do not directly dominate shared updates. This ensures auxiliary signals boost the target attribution.
*   **Core Assumption:** The target attribution is the business-critical objective; auxiliary tasks are means to improve it. Unconstrained MTL may sacrifice primary performance.
*   **Evidence Anchors:** [section 5.1] contrasts NATAL (asymmetric KT) vs. PLE (MoE only): NATAL has better primary GAUC but worse auxiliary metrics. [section 5.2] shows MoAE (MoE + asymmetric) outperforms NATAL. [section 6.2.4] validates the two principles.

## Foundational Learning
*   **Concept: Conversion Attribution Mechanisms**
    *   *Why needed:* MAL's core is using multiple attribution labels. Understanding how last-click, first-click, linear, and DDA differ is essential.
    *   *Quick check:* How does DDA attribution differ from rule-based (last/first/linear) in weight assignment rationale, and why might DDA labels be less noisy?
*   **Concept: Multi-Task Learning (MTL) Paradigms**
    *   *Why needed:* MAL is framed as MTL; baselines (Shared-Bottom, MMoE, PLE, HoME) and MoAE are MTL architectures.
    *   *Quick check:* What is the difference between MMoE's task-specific gating and PLE's explicit separation of shared/task-specific experts, and why does PLE reduce negative transfer?
*   **Concept: Sample Definition in CVR Prediction with Attribution**
    *   *Why needed:* MAC defines positive samples as those with non-zero attribution weight. This differs from traditional binary CVR and affects loss weighting.
    *   *Quick check:* Why are attribution weights used as sample importance weights in the loss (Eq. 3), and how does this interact with multi-attribution labels?

## Architecture Onboarding
*   **Component map:** Input Features -> Embedding Layers + Sequence Encoder -> MoE Backbone (Shared Experts + Private Experts per Attribution) -> Asymmetric Transfer Module (for main task) -> Task-Specific MLP Predictors (one per attribution) -> Weighted Binary Cross-Entropy Losses.
*   **Critical path:** Load MAC data (temporal split) -> Embed categorical features -> Encode behavior sequence with target attention -> Route through MoE experts based on gating -> For main task, apply asymmetric transfer from auxiliary features -> Compute predictions per task -> Calculate loss using attribution-weighted samples -> Update shared and task-specific parameters.
*   **Design tradeoffs:**
    *   Parameter efficiency vs. expressiveness: More experts/private parameters improve knowledge capture but risk overfitting; MAC's size (~79M clicks) supports moderate complexity.
    *   Auxiliary task selection: Adding more auxiliaries generally helps except for first-click target (only last-click aux helps); requires per-target search.
    *   Loss weighting: Fixed λ (searched over {0.1,0.4}) suffices; dynamic gradient surgery methods (GCS, PCGrad) give marginal gains and can hurt strong models.
*   **Failure signatures:**
    *   Poor primary GAUC despite strong auxiliary metrics: Insufficient main-task prioritization (e.g., using plain MTL without asymmetric transfer).
    *   Degraded performance when adding certain auxiliaries: Especially for first-click target; suggests incompatible auxiliary objectives.
    *   Overfitting on small user groups: MAL benefits are concentrated on long-path users; ensure validation reflects user diversity.
*   **First 3 experiments:**
    1.  **Baseline replication:** Train BASE (single-attribution) and Shared-Bottom on MAC with last-click as target. Verify MAL gains (≥1.5pt GAUC) and that gains aren't from parameter growth.
    2.  **Auxiliary objective ablation:** For each target attribution, perform greedy forward-selection of auxiliaries (per Appendix A). Confirm first-click target only benefits from last-click auxiliary; others benefit from all.
    3.  **Architecture comparison:** Implement MoAE, NATAL, PLE on MAC. Verify MoAE achieves best primary GAUC and strong auxiliary metrics. Test with/without asymmetric transfer to isolate its impact.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can we systematically select the optimal set of auxiliary attribution mechanisms for a given target in MAL? Current approach requires costly greedy search; no predictive heuristic exists.
*   **Open Question 2:** How can foundation models (e.g., large language/vision models) be effectively integrated into MAL to improve CVR prediction? Architectural challenges in adapting them to the multi-attribution, multi-task setting remain.
*   **Open Question 3:** What are "more comprehensive conversion objectives" beyond binary labels, and how can they be incorporated into MAL? Incorporating continuous attribution weights or revenue targets is untested.
*   **Open Question 4:** Why do standard auxiliary-task learning methods (e.g., gradient surgery) fail to improve strong MAL models, and how can ATL be tailored to MAL? It is unclear if ATL techniques are mismatched with MAL's asymmetric transfer or need MAL-specific modifications.

## Limitations
*   **Implementation unknowns:** Exact model hyperparameters (expert counts, layer sizes), precise "target attention"/SimTier implementations, final loss weight λ values, and preprocessing details are not fully specified, blocking faithful performance replication.
*   **Benchmark scope:** MAC's four attribution mechanisms may not capture all real-world attribution logics; DDA's causality assumptions are dataset-specific. Generalization of findings to other attribution schemes is uncertain.
*   **Corpus signals:** Low average citations (0.04) and moderate FMR (0.475) indicate the work is recent/nascent with limited external validation; the benchmark's long-term impact is not yet established.

## Confidence
*   **MAL improves CVR prediction:** Medium-High. Supported by systematic MAC evaluation and MTL literature, but gains are dataset-dependent.
*   **MoAE surpasses prior SOTA (NATAL):** Medium. Evident in MAC experiments, but confidence lowered by unreported implementation details and potential overfitting to MAC's distribution.
*   **Asymmetric knowledge transfer is necessary:** Medium. Strongly supported by ablations (NATAL vs. PLE), but the theoretical condition where it's unnecessary (perfectly aligned tasks) remains untested.
