# Characterizing Linear Alignment Across Language Models

## Quick Facts
- **arXiv ID:** 2603.18908
- **Source URL:** https://arxiv.org/abs/2603.18908
- **Reference count:** 40
- **Primary result:** Independently trained LLMs share linear representational structure, enabling cross-model alignment via affine transformations with minimal accuracy loss and efficient privacy-preserving inference.

## Executive Summary
This paper explores whether independently trained language models can be aligned using simple affine transformations of their final hidden states, allowing one model to perform tasks using another’s representations without retraining. The authors learn linear maps between source and target models on public data and evaluate on classification and text generation. They find that classification accuracy is largely preserved across model pairs, while text generation works for large models (≥4B parameters) with compatible tokenizers. Additionally, they introduce HELIX, a privacy-preserving framework that homomorphically encrypts only the linear operations, achieving sub-second latency and MB-scale communication for cross-silo inference.

## Method Summary
The core method involves learning an affine transformation (W, b) from a source model’s hidden states to a target model’s hidden states using ridge regression on a public dataset. For classification, a frozen target linear head processes the mapped embeddings. For generation, the source model’s penultimate hidden states are transformed and fed into the target model’s language modeling head for token-by-token decoding. The HELIX extension uses CKKS homomorphic encryption to secure the alignment and classification steps, keeping client data and queries private while the provider computes the linear head. The approach relies on public data only, avoiding private data leakage, and is evaluated across multiple model families and tasks.

## Key Results
- Linear CKA similarities between models range from 0.595 to 0.881, indicating substantial shared representational structure.
- Cross-model linear alignment preserves classification accuracy with minimal degradation (e.g., 94.5% → 93.1% for Gemini→OpenAI on SST-2) across diverse datasets.
- Text generation is feasible for models ≥4B parameters with compatible tokenizers, achieving LLM-judge scores of 3.9–4.7/10 (retaining 60–70% of single-model quality); small or incompatible models score <2.0.
- The HELIX framework performs encrypted inference in sub-second (<1s) with MB-scale communication, demonstrating practical privacy-preserving cross-silo deployment.

## Why This Works (Mechanism)
- **Shared linear structure:** Independently trained LLMs develop geometrically similar representation spaces (Platonic Representation Hypothesis), as evidenced by CKA scores 0.595–0.881. An affine transformation maps source hidden states into the target’s feature space, allowing a frozen target linear head to process them effectively. Failure occurs if CKA drops below ~0.5 or if architectures/tokenizers diverge significantly.
- **Scale and tokenizer compatibility for generation:** Text generation is sensitive to representational noise; larger models (≥4B) provide robust representations that tolerate linear distortion. Tokenizer compatibility ensures token-level alignment during training, enabling consistent mapping across positions. Exact match rate <0.67 or Jaccard index <0.32 leads to incoherent output (score <2.0).
- **Efficient privacy via linear encryption:** HELIX exploits that only the alignment map and linear head are linear operations; encrypting these with CKKS avoids the high cost of full-model homomorphic evaluation. This yields sub-second latency. Adding nonlinearities (e.g., softmax with argmax) would increase encryption depth and time.

## Architecture Onboarding
**Component map:** Mapper trainer -> Downstream evaluator -> Encryption module

**Critical path:**
1. Prepare shared public dataset Dpub.
2. Extract embeddings ZA = gA(Dpub), ZB = gB(Dpub).
3. Learn (W,b) via ridge regression on ZA, ZB.
4. Evaluate on downstream tasks using frozen target head.
5. Integrate CKKS: encrypt mapped embeddings, evaluate fA homomorphically.

**Design tradeoffs:**
- Accuracy vs. privacy: Public data preserves privacy but may cause misalignment; adding few-shot private samples improves accuracy but risks membership leakage.
- Tokenizer compatibility vs. model family: Same-family models have perfect token match; cross-family requires high Jaccard (>0.64) for generation quality.
- HE depth vs. functionality: Encrypting only linear ops gives sub-second latency; adding nonlinearities increases depth and time.

**Failure signatures:**
- Low CKA (<0.5) between models → alignment unlikely to work.
- High perplexity (>30% increase) on mapped generation → representational mismatch.
- HELIX latency >5s → HE parameters or communication volume too high.

**First 3 experiments:**
1. Compute linear CKA between all model pairs on Alpaca/TriviaQA to assess representational similarity.
2. Train linear classifier on target embeddings; evaluate on source embeddings via learned affine map on AG News/SST-2.
3. Pilot cross-model generation with Llama-3-8B → Qwen2.5-14B and Gemma-270M → Llama-3-8B to validate tokenizer/scale effects.

## Open Questions the Paper Calls Out
- How can linear alignment be extended to multi-modal models and tokenizer-incompatible LLMs? The paper only evaluates text-only LLMs with compatible tokenizers; multi-modal and cross-vocabulary scenarios remain unaddressed.
- Can HELIX be enhanced to protect the provider’s classifier parameters from client access? Currently, the client learns the alignment map and may infer provider information; securing the linear head parameters is an open challenge.
- Do non-linear alignment methods improve cross-model generation quality while maintaining computational efficiency? Linear alignment yields sub-native quality (60–70%); non-linear methods might close this gap but are unexplored.

## Limitations
- Tokenizer alignment details are not released, hindering precise replication across tokenizers.
- HELIX’s CKKS parameters and hardware configuration are unspecified; sub-second latency claims may be context-specific.
- Evaluation is restricted to a small set of model families (OpenAI, Llama, Qwen, Gemma); extension to other architectures (e.g., encoder-decoder, MoE) is unknown.

## Confidence
- **Linear alignment preserves classification:** High (consistent CKA 0.595‑0.881, <2% accuracy drop across 6 tasks).
- **Cross‑model generation requires ≥4B + tokenizer compatibility:** Medium (evidence limited to tested pairs; thresholds may not generalize).
- **HELIX provides efficient privacy:** Medium (results plausible but lack reproducible implementation details).

## Next Checks
1. Replicate token alignment: Implement the character‑offset mapping, compute exact match rate and Jaccard index on a held‑out corpus for multiple tokenizer pairs, and verify the reported thresholds (exact match >0.67, Jaccard >0.32).
2. Cross‑family generation test: Using two ≥4B models with divergent tokenizers (e.g., Llama‑3‑8B vs. Gemma‑2‑9B), learn an affine map on Wikipedia, generate text, and evaluate with an LLM‑as‑a‑Judge to confirm the tokenizer compatibility requirement.
3. HELIX benchmark replication: Reimplement the protocol with TenSEAL (depth‑1 CKKS) on standardized hardware (e.g., AWS c5.xlarge), measure end‑to‑end latency and communication for batch sizes 1–64, and compare against the <1s claim.
