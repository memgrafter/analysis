# Can Heterogeneous Language Models Be Fused?

## Quick Facts
- **arXiv ID:** 2604.01674
- **Source URL:** https://arxiv.org/abs/2604.01674
- **Reference count:** 40
- **Primary result:** HeteroFusion achieves average F1 scores of 71.38 (single-source) and 71.31 (multi-source) on InstructUIE, significantly outperforming FuseLLM (~63 and ~60) and demonstrating strong robustness to noisy sources (~70.55% vs ~20%).

## Executive Summary
HeteroFusion introduces a method for fusing LoRA adapters from heterogeneous large language model backbones (e.g., Llama, Qwen, Mistral) without requiring weight alignment. The core idea is to transfer knowledge at the level of functional module topology rather than raw parameters. It uses a topology-based alignment to match analogous modules across architectures and a conflict-aware denoising module to filter incompatible signals. By preserving the target adapter's basis (A matrix) and only predicting structured updates for its B matrices via a cross-attention HyperNet, the method enables stable, effective cross-family knowledge transfer. Results on instruction-following (InstructUIE) and general language understanding (GLUE) benchmarks show substantial gains over prior fusion techniques, particularly in multi-source and noisy-source scenarios.

## Method Summary
HeteroFusion performs post-training fusion of task-specific LoRA adapters from multiple source models into a single target model of a different architecture. The process involves: 1) **Topology-based alignment**, which maps functionally corresponding modules (e.g., query projections) across source and target models using structural properties, grouping them by role and LoRA rank. 2) **Conflict-aware denoising**, which for each module group constructs feature contexts from the source and target adapters' A⊤ and B matrices, applies SVD to derive spectral descriptors, and uses a learned sparse gate to suppress noisy channels while a rectified distribution matching (RDM) loss regularizes latent space fragmentation. 3) **Structured transfer**, where a HyperNet (using target features as query and concatenated source features as key/value) predicts ∆B updates. Only the target's B matrices are updated (A is frozen), with group-wise scaling α. Training uses a small mixed replay dataset; loss combines the language modeling objective on replay data with the RDM regularization term.

## Key Results
* HeteroFusion achieves an average InstructUIE F1 of **71.38** (single-source transfer) and **71.31** (multi-source fusion), beating FuseLLM by ~8-11 points.
* On noisy-source robustness (with irrelevant source experts), it maintains **~70.55% F1** while prior methods collapse to **~20%**.
* On GLUE, it reaches an average score of **82.58**, confirming effective cross-family generalization to diverse NLP tasks.

## Why This Works (Mechanism)
### Mechanism 1: Topology-Based Alignment
The method matches functional modules (e.g., attention projections) across different Transformer families by analyzing their structural roles and positions (e.g., depth, module type suffixes), not raw weight values. This allows knowledge transfer even when tensor shapes differ. The core assumption is that analogous computational functions exist across architectures and can be identified via topology. Evidence is provided by the paper's ablation studies showing that naive parameter-level alignment fails, while their functional matching succeeds. The break condition is a failure to find valid matches for certain module types (e.g., unique rotary embedding layers).

### Mechanism 2: Conflict-Aware Denoising
Architecture-specific biases and task-irrelevant signals are filtered using an SVD-guided sparse gate. Singular value descriptors identify spectral outliers associated with noise; a learned gate then suppresses these channels. A rectified distribution matching (RDM) loss further aligns the latent distributions of source and target features to reduce fragmentation. The assumption is that noise has a distinct spectral signature. Evidence includes robustness experiments where denoising preserves performance despite noisy sources, while ablating it causes severe degradation. Failure can occur if noise lacks spectral outliers or if the RDM regularization weight is mis-scaled.

### Mechanism 3: Basis Preservation via Frozen A Matrices
By freezing the target adapter's A matrix (the down-projection in LoRA's ΔW = BA) and only updating B, the transfer is constrained to the target's existing latent subspace. This bounds perturbation, maintains stability, and exploits the target's pre-adapted basis. The assumption is that the target task's core representation is already well-captured by Aₜ, and source knowledge can be incorporated as linear combinations. Evidence includes ablations showing that updating both A and B leads to instability or performance drops. The limitation is if source tasks require a fundamentally different basis, expressiveness may be capped.

## Architecture Onboarding
### Component map
Input Adapters (A_t, B_t; A_s, B_s) -> Layer Mapper (π_k(ℓ)) -> Block Context Builder (C_t, C_s) -> Feature Extractor (f_row, f_col, s) -> Denoising Module (SVD Gate + RDM) -> HyperNet (Cross-Attention + Decoder) -> ΔB Predictor -> Dynamic Patcher (temporary B_t update) -> Loss (LM + λ_reg·RDM)

### Critical path (post-training fusion)
For each aligned module group g: 1) Build C_t and C_s from (A⊤, B) of target and sources. 2) Extract row/column features and compute SVD descriptors s. 3) Apply gate g = clip(ReLU(MLP(s)+µ_gate),0,1); denoise z = LN((f_row+f_col)⊙g). 4) Compute cross-attention H_g = MHA(z_t+E_pos, z_s+E_pos, z_s+E_pos). 5) Predict ΔB_g = SliceB(Dec(H_g)). 6) Update B_t ← B_t + α_g·ΔB_g (A_t fixed).

### Design tradeoffs
*Adapter-space vs. full fusion:* Adapter-only limits capacity but ensures efficiency and stability; full-model fusion risks destabilization.
*Topology vs. permutation alignment:* Functional matching is robust to shape differences but coarse; permutation-based methods require identical architectures.
*Denoising aggressiveness:* µ_gate trades noise suppression vs. signal retention; too high admits noise, too low filters useful features.
*Basis preservation:* Freezing A_t stabilizes but may limit expressiveness if source tasks need a new basis.

### Failure signatures
*Adding sources hurts performance:* Conflicts overwhelm denoising or mapping is incorrect.
*Extreme gate sparsity (>80% zeros):* Signal loss; inspect gate activations and tune µ_gate.
*RDM loss dominates or collapses:* Latent distributions irreconcilable; adjust λ_reg.
*High α sensitivity:* Poor conditioning; retune scaling factors per group.

### First 3 experiments
1. **Single-source transfer** (e.g., Qwen→Llama): Expect ~71.38 F1, beating FuseLLM (~63.15). Validates basic cross-architecture transfer.
2. **Multi-source fusion** (Qwen+Mistral→Llama): Expect ~71.31 F1, showing scalable knowledge integration. Checks conflict handling.
3. **Noisy-source robustness:** Add irrelevant Llama experts; expect HeteroFusion ~70.55 F1 while baselines drop to ~20%. Validates denoising.

## Open Questions the Paper Calls Out
### Open Question 1
Can HeteroFusion's adapter-space fusion principle be generalized beyond LoRA to other parameter-efficient fine-tuning methods (e.g., prefix-tuning, adapter layers) or extended to full-model fusion? The method is designed for LoRA's low-rank structure; other PEFT methods have different parameterizations, and full-model fusion involves far more parameters, potentially destabilizing the alignment and denoising.

### Open Question 2
Can heterogeneous fusion be performed without any replay data, achieving fully data-free operation while maintaining robustness? The current method relies on a small replay set to learn interactions; without data, optimization may lack supervision, especially in conflict-heavy scenarios.

### Open Question 3
How can topology-based alignment be made adaptive for highly heterogeneous architectures beyond standard Transformers, such as multimodal models (e.g., vision-language) or architectures with fundamentally different layer designs (e.g., state space models)? The current alignment relies on matching functional module types in Transformer families; multimodal or non-Transformer models may have incompatible module concepts.

## Limitations
* Exact algorithmic details for layer mapping π_k(ℓ) and HyperNet architecture are underspecified, hindering exact replication.
* Evidence relies solely on the paper's internal results and ablations; no independent validation from other groups is cited in the corpus.
* The core assumption that functional roles align across Transformer families via topology requires stronger empirical justification beyond the presented scores, especially for highly divergent architectures.

## Confidence
*Mechanism 1 (Topology Alignment):* Medium – Supported by paper's description and ablations, but implementation gap reduces certitude.
*Mechanism 2 (Conflict-Aware Denoising):* Medium – Robustness evidence is strong, but spectral signature assumption lacks external validation.
*Mechanism 3 (Basis Preservation):* Medium-High – LoRA theory and ablations provide solid grounding.
*Overall Results:* Medium – Scores beat baselines, but reproducibility concerns and single-source validation limit broader confidence.
