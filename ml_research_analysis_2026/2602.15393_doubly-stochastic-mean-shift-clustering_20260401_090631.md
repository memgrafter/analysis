# Doubly Stochastic Mean-Shift Clustering

## Quick Facts
- **arXiv ID:** 2602.15393
- **Source URL:** https://arxiv.org/abs/2602.15393
- **Reference count:** 29
- **Primary result:** DSMS mitigates mean-shift's bandwidth sensitivity in sparse data via randomized point and bandwidth selection, achieving accurate cluster counts and matching or outperforming SMS across metrics without degradation when bandwidth range is optimal.

## Executive Summary
Mean-shift clustering suffers from bandwidth sensitivity, particularly over-segmentation in sparse data regimes. Doubly Stochastic Mean-Shift (DSMS) addresses this by introducing randomness in two dimensions per iteration: the data point selected for update and the kernel bandwidth used. This multi-scale exploration acts as an implicit regularizer, allowing the algorithm to traverse low-density gaps with larger scales while refining modes with smaller ones. Theoretical analysis establishes that the resulting stochastic process forms a positive submartingale, guaranteeing almost-sure convergence to a stable clustering. Empirical evaluations on synthetic 3-cluster Gaussian Mixture Models (GMMs) demonstrate that DSMS maintains cluster counts near the true value (3) even with as few as 10–50 points per cluster, significantly reducing over-segmentation compared to deterministic MS, bounded MS (BMS), and stochastic MS (SMS). Performance metrics—Average Cluster Purity (ACP), Average Label Purity (ALP), and their geometric mean K—show DSMS matches or surpasses SMS across varying class imbalances and cluster numbers, with optimal results dependent on the chosen bandwidth range.

## Method Summary
DSMS modifies the classic mean-shift update by randomly selecting a single data point per iteration and drawing the kernel bandwidth from a controlled uniform distribution around the current bandwidth. Given a dataset \(\{x_i\}_{i=1}^n\) and initial bandwidth \(h_1\) (often set to the fixed optimal value \(h_\infty\) for SMS), each iteration \(k\) proceeds as: (1) sample an index \(i_k \sim \text{Uniform}[n]\); (2) compute \(\delta_k = \min\left( \nu_k, (h_k/h_{\min})^2 -1, 1 - (h_k/h_{\max})^2 \right)\) where \(\nu_k\) is a decay term (e.g., \(\nu_k = 1/\log_{10}(10+\log_{10}k)\)) and \([h_{\min}, h_{\max}]\) defines the allowed bandwidth range; (3) draw \(\alpha_k \sim \text{Uniform}(1-\delta_k, 1+\delta_k)\); (4) set \(h_{k+1} = h_k / \sqrt{\alpha_k}\); (5) update the selected point via the mean-shift operator \(x_{i_k}^{(k+1)} = S_{h_{k+1}}(x_{i_k}^{(k)}; X^{(k)})\); (6) check convergence (\(\|x_{i_k}^{(k+1)} - x_{i_k}^{(k)}\| < \epsilon\) or max iterations). The theoretical guarantee hinges on proving that the objective \(L_h(X)\) behaves as a submartingale under this update scheme, ensuring convergence. Key hyperparameters include the initial bandwidth \(h_1\), the bounds \([h_{\min}, h_{\max}]\), and the decay schedule for \(\nu_k\).

## Key Results
- DSMS maintains accurate cluster counts (near true value \(K=3\)) for 10–50 points per cluster, severely reducing over-segmentation versus MS, BMS, and SMS.
- Metrics like ACP, ALP, and geometric mean \(K\) show DSMS matches or outperforms SMS across class imbalances and cluster numbers, with no performance degradation when bandwidth range is optimally chosen.
- The randomized bandwidth policy acts as implicit regularization, balancing large-scale exploration (merging spurious modes) and small-scale refinement without harming other clustering metrics.

## Why This Works (Mechanism)
### Mechanism 1
*Claim:* Randomly sampling both the data point index and the kernel bandwidth per iteration reduces over-segmentation in sparse regimes by enabling multi-scale density exploration.
*Mechanism:* At each step, an index \(i_k\) is uniformly sampled from \([n]\), and a bandwidth \(h_{k+1}\) is drawn from \(\mathcal{U}(1-\delta_k, 1+\delta_k)\) scaled from \(h_k\), ensuring \(h_{k+1} \in [h_{\min}, h_{\max}]\). The selected point is then shifted using the mean-shift operator with \(h_{k+1}\). This avoids the fragmentation caused by fixed-bandwidth KDE, where a single scale cannot both bridge low-density gaps (need larger \(h\)) and resolve fine modes (need smaller \(h\)).
*Evidence anchors:* Abstract statement on multi-scale exploration; Section 2.2 Algorithm 1b; SMS literature confirming random point selection alone insufficient; adaptive mean-shift works motivating local scale variation.
*Break condition:* If \(h_{\max}\) is excessively large relative to inter-cluster distances, distinct clusters may merge (over-smoothing), as seen in performance degradation in Figure 4.

### Mechanism 2
*Claim:* The specific bandwidth update rule \(h_{k+1} = h_k / \sqrt{\alpha_k}\) with \(\alpha_k \sim \mathcal{U}(1-\delta_k, 1+\delta_k)\) ensures the objective function \(L_h(X)\) forms a submartingale, guaranteeing almost-sure convergence to a stable clustering.
*Mechanism:* The expected value of \(L_{h_{k+1}}(X^{(k+1)})\) conditioned on current state and \(h_k\) is at least \(L_{h_k}(X^{(k)})\). This relies on Jensen's inequality applied to the convex profile function \(\kappa\) and symmetric uniform sampling of \(\alpha_k\) around 1.
*Evidence anchors:* Section 3.1 Proposition 2 proving submartingale property; Appendix B details Jensen step; blurring mean-shift convergence proofs provide foundation.
*Break condition:* If kernel profile \(\kappa\) is non-convex or \(h_k\) jumps outside \([h_{\min}, h_{\max}]\) without control, the submartingale property may fail.

### Mechanism 3
*Claim:* The randomized bandwidth policy acts as implicit regularization, preventing fragmentation without degrading ACP/ALP by balancing exploration (large \(h\)) and refinement (small \(h\)).
*Mechanism:* Large bandwidth samples allow points to traverse low-density barriers between spurious micro-modes, merging them into true clusters. Small bandwidth samples then refine mode locations. The uniform range \([h_{\min}, h_{\max}]\) ensures both scales are visited.
*Evidence anchors:* Abstract statement on implicit regularization; Section 4.3 Figures 4 and 5 showing trade-offs; adaptive and hyperbolic mean-shift literature highlighting fixed bandwidth limitations.
*Break condition:* If data density is unimodal or clusters are well-separated at a single scale, DSMS may introduce unnecessary variance or over-merge compared to an optimal fixed \(h\).

## Foundational Learning
- **Kernel Density Estimation (KDE)**: The DSMS updates are gradients of a KDE-based objective \(L_h(X) = \sum_{i \leq j} K\left(\frac{\|x_i - x_j\|^2}{h^2}\right)\). Bandwidth \(h\) controls smoothing and support, directly impacting mode count.
  *Quick check:* How does the kernel's compact support and bandwidth affect the number of modes in a KDE for a Gaussian mixture with 10 points per component?
- **Stochastic Partial Gradient Ascent**: DSMS updates only one randomly selected point per iteration, corresponding to a partial gradient step on \(L_h\). This asynchronous update alters convergence dynamics versus deterministic batch updates.
  *Quick check:* Why does updating a single point at a time (SMS) still converge despite the non-convex objective?
- **Martingale Convergence Theorems**: The proof that \(L_{h_k}(X^{(k)})\) is a positive submartingale and its almost-sure convergence rely on Doob's theorem and boundedness arguments.
  *Quick check:* What properties of a submartingale guarantee it converges almost surely if it is bounded in \(L^1\)?

## Architecture Onboarding
- **Component map:** Initial State → Random Index Sampler → Bandwidth Sampler → Shift Operator → Convergence Check (loop)
- **Critical path:** Initialize \(X^{(0)}, h_1\). Loop: sample \((i_k, h_{k+1})\) → update \(x_{i_k}\) → check convergence. Dependency: \(h_{k+1}\) depends on \(h_k\); shift depends on \(h_{k+1}\) and \(X^{(k)}\).
- **Design tradeoffs:**
  - Bandwidth range \([h_{\min}, h_{\max}]\): Too narrow reduces to SMS; too wide causes over-merging. Optimal range is data-dependent.
  - Decay rate \(\nu_k\): Must tend to 0 to ensure eventual stabilization; too slow prolongs exploration, too fast limits multi-scale benefit.
  - Computational cost: Per-iteration \(O(n)\) (like SMS), but total iterations often higher than deterministic MS/BMS.
- **Failure signatures:**
  - Symptom: Final cluster count >> true \(K\) even for moderate sample sizes.
    Likely cause: \(h_{\min}\) too small or \(\nu_k\) decay too slow → persistent over-segmentation.
  - Symptom: Final cluster count << true \(K\) or ACP drops sharply.
    Likely cause: \(h_{\max}\) too large → over-merging distinct clusters.
  - Symptom: No convergence within max iterations.
    Likely cause: \(\nu_k\) not decaying or \(h_{\min}/h_{\max}\) bounds violate assumptions.
- **First 3 experiments:**
  1. Sparse 3-GMM test (Figure 1): Run DSMS with \(h_{\min}=0.2, h_{\max}=1.6\) on 2D GMM (3 clusters, 10–200 points/cluster). Compare average cluster count vs. true \(K=3\). Expect DSMS to maintain count near 3 for \(N \leq 50\), while MS/SMS/BMS over-segment.
  2. Imbalance robustness (Figure 2): Use multi-cluster GMMs with varying cardinality ratios (e.g., 1:4). Compute \(K = \sqrt{\text{ACP} \times \text{ALP}}\). DSMS should match SMS when range is optimal.
  3. Bandwidth range sweep (Figure 4): Fix data (3 clusters, 100 points each). Vary \(h_{\max} - h_{\min}\) while keeping \(h_{\infty}\) constant. Plot \(K\) vs. range width; expect peak at intermediate widths.

## Open Questions the Paper Calls Out
1. **Optimal bandwidth range selection:** How can \([h_{\min}, h_{\max}]\) be characterized and selected based on data distribution and cluster structure? The paper states this data-dependency remains an open challenge.
2. **Adaptive bandwidth sampling:** How can the bandwidth strategy be made adaptive to local data density during clustering? The paper notes data-dependent sampling is out of scope and should be investigated.
3. **Finite-time convergence bounds:** What are the iteration bounds for DSMS to achieve stable clustering with high probability? The paper admits no theoretical results provide a higher bound on \(k\) under specified probability.
4. **Real-world performance:** How does DSMS perform on real-world tasks (e.g., image segmentation, speaker diarization) with noisy, high-dimensional, or anisotropic data? The paper exclusively uses synthetic 2D GMMs, leaving real-data validation unaddressed.

## Limitations
- Kernel profile (e.g., Epanechnikov, tri-weight) for key experiments unspecified, hindering exact replication.
- Bandwidth hyperparameters for Figures 2–3 not provided; only Table 3 parameters for the 3-cluster case are available.
- Theoretical guarantees rely on assumptions (kernel convexity, \(h_k \in [h_{\min}, h_{\max}]\)) that may not hold for all data choices.
- Evaluation limited to 2D synthetic Gaussian mixtures; real-world performance and high-dimensional scalability unproven.
