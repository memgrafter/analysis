# Transport, Don't Generate: Deterministic Geometric Flows for Combinatorial Optimization
## Quick Facts
- **arXiv ID:** 2602.10794
- **Source URL:** https://arxiv.org/abs/2602.10794
- **Reference count:** 10
- **Primary result:** Deterministic point transport via CycFlow achieves 2-3 orders of magnitude speedup over diffusion baselines while maintaining competitive optimality gaps on TSP benchmarks.

## Executive Summary
This paper addresses the slow inference problem in neural Traveling Salesman Problem (TSP) solvers that use diffusion models. Instead of the standard approach of stochastic edge denoising on a quadratic-sized heatmap, CycFlow reformulates TSP as deterministic point transport: it learns a continuous velocity field that maps an input point cloud directly to a canonical circular arrangement derived from the optimal tour. The final tour is recovered by angular sorting, shifting computational complexity from \(O(N^2)\) edge scoring to linear-coordinate dynamics. Results show dramatic speedups—sub-second latency even for TSP-1000—with optimality gaps that remain competitive (e.g., 0.08% on TSP-50 in 0.004s) compared to diffusion baselines that require minutes.

## Method Summary
CycFlow constructs a target circular manifold \(x_1\) from the optimal tour, with arc lengths proportional to edge distances and radius scaling with the input’s Frobenius norm. It couples \(x_0\) and \(x_1\) via Procrustes alignment (Kabsch rotation) to minimize global displacement, defining a linear interpolant \(x_t = (1-t)x_0 + t x_{1,\text{rot}}\) for Flow Matching training. The input point cloud is canonicalized using spectral ordering (Fiedler vector) and rigid alignment to a standardized frame, enabling a Transformer with Rotary Positional Embeddings and Adaptive Layer Norm to predict a velocity field \(v_\theta\). During inference, Euler integration in the canonical frame transports points to the circular manifold; the tour is then obtained by angular sorting and optionally refined with greedy 2-OPT.

## Key Results
- **TSP-50:** 0.08% optimality gap in 0.004 seconds.
- **TSP-1000:** 9.89% gap in 0.22 seconds (vs. Fast-T2T: 0.58% gap in 516 seconds).
- Achieves **2-3 orders of magnitude speedup** over diffusion-based baselines while maintaining comparable gaps for moderate instance sizes (N ≤ 200).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Reformulating TSP as deterministic point transport (moving N coordinates) instead of stochastic edge denoising (classifying an N×N heatmap) eliminates the quadratic computational bottleneck.
- **Mechanism:** The input point cloud \(x_0 \in \mathbb{R}^{N \times 2}\) is deterministically coupled to a target circular arrangement \(x_1 \in \mathbb{R}^{N \times 2}\) derived from the optimal tour. The solver learns a velocity field \(v_\theta\) via Flow Matching to directly transport points from \(x_0\) to \(x_1\) along a linear interpolant \(x_t = (1-t)x_0 + t x_1\). The final tour is recovered by angular sorting.
- **Core assumption:** The optimal tour can be represented as a canonical circular manifold where permutation reduces to angular sorting, and a linear path between the coupled \((x_0, x_1)\) pairs is a sufficient approximation of the optimal transport map.
- **Evidence anchors:** Abstract: "reformulating TSP as deterministic point transport... shifts computational burden... to linear coordinate dynamics." Section 3.1: "We construct the target \(x_1\) by embedding the optimal TSP tour onto a circle... This defines a deterministic relationship."
- **Break condition:** If the problem instance lacks a smooth Euclidean inductive bias (e.g., purely graph-based TSP with arbitrary distances), the circular manifold assumption fails. Also, the linear interpolant assumes the optimal transport path is straight, which may not hold for highly non-convex point distributions.

### Mechanism 2
- **Claim:** Data-dependent coupling via Procrustes alignment creates a sharp conditional distribution \(p(x_1|x_0)\), which simplifies the flow learning task by ensuring low-displacement trajectories.
- **Mechanism:** For each training pair \((x_0, \pi^*)\), the target \(x_1\) is constructed on a circle with arc lengths proportional to tour edges. The rotation \(R^*\) minimizing \(\|x_1 R - x_0\|_F\) is applied, yielding an aligned pair \((x_0, x_1 R^*)\). This minimizes global displacement, reducing the complexity of the flow field the network must learn.
- **Core assumption:** Minimizing initial misalignment via optimal rotation yields straighter, easier-to-learn flow trajectories compared to an independent coupling (e.g., from Gaussian noise).
- **Evidence anchors:** Section 3.1: "By explicitly minimizing global displacement, this alignment acts as a structural 'head start,' simplifying the regression task." Section 3.2: "This defines a direct bridge between the problem and its solution."
- **Break condition:** If the optimal tour's geometry is highly irregular (e.g., many near-equal edge lengths), the circular embedding may introduce artificial distortions. The Kabsch alignment also assumes a 2D rotation group; scaling or more complex Euclidean transforms could break this.

### Mechanism 3
- **Claim:** Canonicalization (spectral ordering + rigid alignment) enforces permutation/rotation/translation equivariance, allowing a standard Transformer to operate on a standardized frame without sacrificing geometric precision.
- **Mechanism:** The input point cloud is transformed into a canonical sequence: nodes are sorted by the Fiedler vector (with sign fixed by skewness), then translated to origin and rotated to align a weighted orientation vector with the vertical axis. A Transformer with RoPE processes this canonical sequence; predictions are inverse-transformed back to the original geometry.
- **Core assumption:** The Fiedler vector provides a consistent, structure-preserving ordering for arbitrary Euclidean point clouds, and the canonical frame removes all global symmetries, making the prediction task invariant to input pose.
- **Evidence anchors:** Section 3.3: "This strategy decouples symmetry constraints from the network architecture... allowing the model to remain 'geometrically aware'." Section 4.3 ablation: Canonicalization (CycFlow) outperforms equivariant GNNs (0.09% vs 0.34% gap), suggesting explicit canonicalization better preserves fine geometry.
- **Break condition:** For point clouds with degenerate Laplacian spectra (e.g., disconnected components), the Fiedler vector is not unique or meaningful. The weighting scheme for orientation may fail on highly asymmetric distributions, causing unstable canonicalization.

## Foundational Learning
- **Concept: Flow Matching (FM)**  
  *Why needed here:* CycFlow uses FM as a simulation-free objective to learn a deterministic ODE directly, avoiding costly iterative reverse diffusion. Understanding FM's regression-of-velocity-field formulation is key to grasping why inference is a simple ODE solve.  
  *Quick check question:* How does the FM objective (Eq. 4) differ from a standard denoising score matching loss in diffusion, and why does this lead to faster inference?
- **Concept: Data-Dependent Coupling in Generative Models**  
  *Why needed here:* The paper's core innovation is coupling \(x_0\) and \(x_1\) based on the optimal tour, rather than using a fixed prior (Gaussian). This is non-standard and critical for straight flows.  
  *Quick check question:* Why would coupling the source and target via Procrustes alignment potentially yield simpler ODE trajectories than an independent coupling?
- **Concept: Geometric Equivariance via Canonicalization**  
  *Why needed here:* TSP solutions must be equivariant to rigid transforms. The paper achieves this by explicitly canonicalizing the input, rather than building equivariance into the network layers.  
  *Quick check question:* What are the trade-offs of using a pre-processing canonicalization step versus an equivariant architecture (like an EGNN) for handling rotation symmetry?

## Architecture Onboarding
**Component map:**  
Input coordinates → Canonicalization module (Fiedler sort + rigid alignment) → Velocity network (Transformer with RoPE + AdaLN) → Restoration module (inverse transform) → ODE integrator (Euler steps) → Angular sort + greedy 2-opt

**Critical path:**  
Canonicalization → (for each step \(t\): network forward pass with canonicalized \(x_t\) and \(t\)) → restoration → Euler update → repeat \(K\) times → angular sort.

**Design tradeoffs:**  
- *Canonicalization robustness vs. computational cost:* Spectral sort is \(O(N^3)\) but likely done once per instance; needs profiling for large \(N\) (e.g., 1000).  
- *Linear interpolant assumption:* Simpler but may not capture highly nonlinear optimal transports; empirical success on Euclidean TSP suggests sufficiency.  
- *Transformer size:* Larger models might improve accuracy but increase per-step latency; paper implies a small backbone given sub-ms timings.

**Failure signatures:**  
- Poor spectral ordering on symmetric/regular point sets (e.g., grid) → wrong permutation → large gap.  
- Inaccurate rotation alignment → points transported to wrong circle sector → angular sort yields crossing edges.  
- ODE instability with too few steps (\(K\)) → under-transported points; too many steps → unnecessary compute.  
- Network fails to condition on \(t\) (AdaLN broken) → flow field inconsistent across time → ODE diverges.

**First 3 experiments (onboarding validation):**  
1. **Canonicalization sanity check:** Feed a synthetic point set shaped like a circle (ordered) and a noisy circle (unordered). Verify that canonicalized output is identical (same spectral order, aligned frame). Check that inverse transform reconstructs original ordering.  
2. **Flow matching sanity check:** On a held-out TSP-50 instance, compute target \(x_1\) via optimal tour. Compare predicted velocity at \(t=0.5\) against ground truth \(x_1 - x_0\). Expected: direction roughly points toward circular manifold, magnitude correlates with distance to target.  
3. **End-to-end timing breakdown:** Measure time per component: canonicalization, \(K\) network forwards (batch size 1), restoration, angular sort, 2-opt. Confirm that network inference dominates, not canonicalization, and that \(K\) is small (e.g., 10–100 steps as suggested by sub-ms timings).

## Open Questions the Paper Calls Out
1. **Can CycFlow learn without optimal tour supervision?** The paper notes that developing unsupervised or reinforcement learning variants to eliminate dependency on optimal tour labels (e.g., from Concorde) remains an open frontier.
2. **Why does accuracy degrade significantly for N≥500 and can this be mitigated?** Results show gaps rising from 0.35% (N=100) to 6.84% (N=500) and 9.89% (N=1000), but no analysis is provided. This may relate to model capacity or breakdown of geometric assumptions at scale.
3. **What is the marginal contribution of neural flow matching beyond 2-OPT post-processing?** All reported results include 2-OPT refinement, but the paper does not isolate the neural component’s effect. An ablation comparing 2-OPT on raw angular-sorted input vs. flow output is needed.
4. **Can CycFlow generalize to non-Euclidean or graph-based routing problems?** The current method exploits Euclidean geometry by transporting 2D coordinates to a circular manifold; extending to arbitrary graph distances requires architectural adaptations.

## Limitations
- Assumes Euclidean geometry; non-Euclidean TSP or graph-based routing may fail due to circular manifold construction.
- Canonicalization (Fiedler vector + Kabsch) can break on degenerate/symmetric point sets (e.g., grids, regular clusters).
- Optimality gap grows with problem size (9.89% on TSP-1000), limiting practical applicability for large instances.
- Missing hyperparameters and architecture details (model size, \(K\), learning rate, training data规模) hinder faithful reproduction.

## Confidence
- **High:** Quadratic bottleneck removal (empirically proven by speedup); Sub-second inference with competitive gaps (for N ≤ 200).
- **Medium:** Procrustes alignment yields straight flows (plausible but not validated against alternative couplings); Canonicalization > equivariant GNNs (ablation vs. one EGNN but may not generalize).
- **Low:** Linear interpolant assumption for optimal transport (theoretical justification weak; empirical success may not hold for all distributions).

## Next Checks
1. **Test canonicalization on degenerate inputs:** Evaluate on grids, symmetric clusters, or disconnected components to expose failure modes in spectral ordering and alignment.
2. **Ablate the linear interpolant:** Compare learned constant velocity against a nonlinear trajectory model (e.g., neural ODE with flexible path) and measure impact on optimality gaps.
3. **Perform a step-size study:** Vary Euler integration steps \(K\) and record gap/latency trade-offs to identify the minimal \(K\) for stable convergence across problem sizes.
