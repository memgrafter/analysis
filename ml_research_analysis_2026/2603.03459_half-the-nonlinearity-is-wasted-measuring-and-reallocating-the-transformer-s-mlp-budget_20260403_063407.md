# Half the Nonlinearity Is Wasted: Measuring and Reallocating the Transformer's MLP Budget

## Quick Facts
- **arXiv ID:** 2603.03459
- **Source URL:** https://arxiv.org/abs/2603.03459
- **Reference count:** 2
- **Primary result:** A minimal (d+1)-parameter gate can route 25–56% of MLP computations to a linear surrogate with negligible perplexity cost (<1% in GPT-2); fine-tuning reallocation yields 10.2–17.3% perplexity improvement.

## Executive Summary
This paper reveals that the nonlinearity in Transformer MLP layers is largely wasted. By replacing MLPs with learned linear surrogates and using a tiny router, a substantial fraction of computations can be made linear with almost no increase in perplexity. The need for nonlinearity is entirely context-dependent; token identity alone does not predict it. Architectural differences matter: GPT-2 models have many highly linearizable layers, while Pythia models are less so. Surprisingly, linearizing certain MLP layers can even *improve* perplexity, suggesting some nonlinearities are actively harmful. The authors argue that nonlinear capacity should be concentrated at network boundaries.

## Method Summary
The method involves replacing each MLP with a linear surrogate fit via ridge regression on pre-MLP activations. A separate logistic regression gate, trained on the same activations, decides per-position whether to use the full MLP or the linear surrogate. The gate uses a minimal (d+1)-parameter model. Evaluations on GPT-2 and Pythia models across WikiText-103 and LAMBADA measure perplexity change, routing percentage, and gate AUC. To study token versus context effects, the pre-MLP activation is decomposed into a token component (embedding+position) and a context component; separate gates are trained on each. Cross-corpus generalizability is tested via a “No‑Fly list” of tokens with high linearization cost, computing Pearson correlation of per-token cost across corpora.

## Key Results
- A gated linear surrogate routes 25–56% of computations to a linear path with <1% perplexity penalty in GPT-2 Medium.
- Five of 24 GPT-2 Medium layers can be fully linearized at zero cost; with fine-tuning, linearizing four middle layers improves perplexity by 10.2%, and a two-phase gated approach yields 17.3% improvement (19.00 PPL).
- In GPT-2 Large, 11/36 layers beat baseline with all-linear replacement; Pythia models incur higher costs, though Pythia-2.8B layer 3 nearly matches baseline (−0.13% Δ).
- Token identity predicts nonlinearity need poorly: cross-corpus Pearson r < 0.05, per-token R² < 1.3%; the context component drives gate performance.

## Why This Works (Mechanism)
The Transformer’s MLP nonlinearity is often redundant because pre-MLP activations already contain sufficient linear structure to approximate the MLP’s output. The context (i.e., attention-processed information) determines where nonlinearity is truly needed; token identity alone is uninformative. This allows a simple linear surrogate to handle many positions, with a tiny gate (trained on the same activations) accurately routing only the cases that genuinely require the full nonlinearity. Architectural choices like sequential attention-MLP ordering (in GPT-2) appear to make nonlinearity more concentrated, enabling higher linearizability.

## Foundational Learning
- **Transformer MLP**: A position-wise feed-forward network (usually two linear layers with a non-linearity like GELU). *Why needed:* It is the computational unit being replaced. *Quick check:* Can you identify the MLP in a transformer block diagram?
- **Linear surrogate**: A single linear layer fitted to replicate an MLP’s output. *Why needed:* Provides a cheaper computational path. *Quick check:* Why might a linear map approximate a nonlinear MLP well on some inputs?
- **Ridge regression**: Regularized least squares used to fit the linear surrogate. *Why needed:* Prevents overfitting on activation samples. *Quick check:* What does the regularization parameter λ control?
- **Logistic regression gate**: A linear classifier that routes positions to either full MLP or linear surrogate. *Why needed:* Minimal parameters avoid defeating the efficiency gains. *Quick check:* Why not use a more complex router?
- **Layer normalization**: Applied before MLP. *Why needed:* Normalizes activations, affecting the distribution the linear surrogate must fit. *Quick check:* How would removing layer norm change the surrogate’s task?
- **Token vs. context decomposition**: Splits pre-MLP activation into embedding+position (token) and the remainder (context). *Why needed:* Isolates the source of routing signal. *Quick check:* Is the token component directly present in deeper layer activations?

## Architecture Onboarding
**Component map:** Input -> Token Embedding + Position Encoding -> LayerNorm -> Attention -> LayerNorm -> MLP -> Output (per layer)

**Critical path:** Pre-MLP activation (after second LayerNorm) is the key representation. It is used to (1) fit the linear surrogate, (2) train the gate, and (3) evaluate replacement effects.

**Design tradeoffs:** The paper trades nonlinear capacity for FLOP reduction. The minimal gate introduces negligible overhead but relies on accurate routing labels derived from the full model’s outputs. LayerNorm placement and attention-MLP ordering (sequential vs. parallel) strongly influence linearizability.

**Failure signatures:** 
- All-linear perplexity increases >10% for a layer → that layer’s MLP is highly nonlinear or mis-fitted.
- Token-only gate AUC >0.6 → decomposition contaminated by context, invalidating token irrelevance claim.
- Gate routing percentage near 0% → threshold mis-set or gate under-capacitated.

**First three experiments:**
1. **All-linear baseline:** For each layer, fit a linear surrogate on 10K activation samples, replace the MLP, and evaluate perplexity on 50K held-out tokens. Expect middle layers to show lowest cost.
2. **Gated replacement (single layer):** On a middle layer (e.g., L12), train a logistic gate on 25K samples, predict routing on 12K eval tokens, and measure combined perplexity and % routed linearly. Expect <1% cost and ~40% routing.
3. **Token vs. context ablation:** Decompose activations; train separate gates on token-only and context-only components. Compare AUCs; context gate should match full gate, token gate near random.

## Open Questions the Paper Calls Out
- Does the pattern of high MLP linearizability generalize to modern transformer families beyond GPT-2 and Pythia, such as Llama or Mistral?
- Can post-hoc gated linearization be engineered to achieve real-world wall-clock speedups on contemporary hardware without sacrificing perplexity?
- To what extent does the sequential (GPT-2) versus parallel (Pythia) attention-MLP computation order causally explain the stark difference in linearizability between architectures?
- Is the "negative regularization" effect—where linearizing certain MLP layers *improves* perplexity—a widespread phenomenon or a peculiarity of specific GPT-2 middle layers?

## Limitations
- The 80K token split source (test vs. train) is unspecified, risking distribution shift.
- Token+context decomposition method is ambiguous; subtraction may not cleanly isolate token effects in deeper layers.
- Cross-corpus analysis sensitive to No‑Fly list thresholds; token frequency biases may affect Pearson r.
- Scope limited to GPT-2/Pythia and English corpora; generalizability unproven.

## Confidence
- **Waste & routing:** Medium – reproducible but sensitive to ridge λ and activation sampling.
- **Token irrelevance:** Low – heavily dependent on correct decomposition; AUC could be inflated by contamination.
- **Architectural differences:** Medium – consistent pattern across few models but confounded by multiple design choices.
- **MLP harmfulness:** Medium – fine-tuning gains may overfit or depend on data; not tested on many models.

## Next Checks
1. **Decomposition fix:** Use the raw embedding+position vector (no subtraction from later activations) as the token component. If token gate AUC exceeds 0.6, the token irrelevance claim is weakened.
2. **Cross-corpus robustness:** Build No‑Fly list on WikiText-103 train; evaluate per-token cost on LAMBADA *and* a held-out genre (e.g., GitHub code). Compute pairwise correlations; high variance undermines generalizability.
3. **Gate capacity ablation:** Replace the logistic gate with a small MLP (e.g., 2 layers, 32 hidden units). If routing percentage rises or perplexity drops further, the minimal gate is suboptimal.
