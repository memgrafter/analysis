# CoBA-RL: Capability-Oriented Budget Allocation for Reinforcement Learning in LLMs

## Quick Facts
- **arXiv ID**: 2602.03048
- **Source URL**: https://arxiv.org/abs/2602.03048
- **Reference count**: 40
- **Primary result**: CoBA-RL improves average accuracy over GRPO by +4.54% (to 46.78%) on Qwen2.5-7B-Instruct and by +5.62% on AIME25; it also outperforms Knapsack-RL and speeds up allocation 928× versus dynamic programming.

## Executive Summary
Reinforcement learning with human feedback (RLHF) often uses group-relative policy optimization (GRPO), which allocates a uniform number of rollouts to each prompt, leading to wasted computation on low-value samples. Existing adaptive allocation methods rely on static instance-level metrics that do not reflect the model’s evolving capabilities. CoBA-RL introduces a Capability-Oriented Value function that models the expected training gain from allocating additional rollouts to a prompt as the product of a Budget Saturation Factor (capturing diminishing returns) and a Beta-distributed density over the prompt’s pass rate. The Beta parameters are dynamically adjusted according to a transformed global failure rate, allowing the system to shift its preference between exploitation (favoring high pass-rate prompts) and exploration (favoring low pass-rate prompts) as training progresses. The total rollout budget is then distributed via a heap‑based greedy algorithm that, under the strictly diminishing marginal returns property, provably achieves the optimal integer allocation while being orders of magnitude faster than dynamic programming. Empirically, CoBA-RL consistently surpasses both GRPO and the adaptive Knapsack‑RL baseline across a suite of mathematical reasoning benchmarks. For the Qwen2.5‑7B‑Instruct model, average accuracy rises to 46.78% versus GRPO’s 42.24% (+4.54) and Knapsack‑RL’s 45.39% (+1.39); on AIME25 it reaches 18.33% compared to 12.71% (+5.62) for GRPO. Gains are robust across model scales, and the allocation algorithm is 928× faster than dynamic programming, offering a superior exploration‑exploitation trade‑off and data efficiency.

## Method Summary
CoBA-RL augments the standard GRPO training loop with an adaptive rollout allocator. Given a batch of M prompts at step t, it first collects G rollouts per prompt to estimate individual pass rates p_i. It then computes the batch’s global failure rate F_t = 1 − mean(p_i). To stabilize this signal, a moving average ¯F_t over k recent steps is maintained and transformed by a piecewise function Ψ: if ¯F_t > 0.5, ˜F_t = ¯F_t; otherwise ˜F_t = σ(γ·(¯F_t − 0.5)) with γ=10. From ˜F_t, the α_t parameter of a Beta distribution is derived via α_t = clip(α_min + λ·˜F_t, α_min, α_max), while β_t = κ − α_t (κ is a fixed sum, e.g., 11). The value of allocating B_i rollouts to prompt i is  
V(B_i, p_i) = (1 − exp(−B_i / (τ p_i(1−p_i)))) · Beta(p_i; α_t, β_t).  
Here the exponential term models diminishing returns with temperature τ. The allocation must satisfy B_low ≤ B_i ≤ B_up and ∑_{i=1}^M B_i = B_total.

To maximize ∑ V(B_i, p_i) under these constraints, CoBA-RL uses a greedy heap algorithm:
1. Initialize B_i = B_low for all i.
2. Compute the marginal gain ΔV_i = V(B_i+1, p_i) − V(B_i, p_i) for each prompt.
3. Insert all (ΔV_i, i) into a max‑heap.
4. While total allocated < B_total:
   a. Pop the prompt i with highest ΔV.
   b. Increment B_i ← B_i + 1.
   c. Recompute ΔV_i ← V(B_i+1, p_i) − V(B_i, p_i).
   d. Insert the updated (ΔV_i, i) back into the heap.
The marginal gain is strictly decreasing in B_i for any fixed p_i (Proposition 2.2), a property that mathematically guarantees the greedy procedure yields the optimal integer allocation. After determining the B_i counts, the batch is resampled accordingly, and GRPO proceeds with the expanded set of rollouts.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The Capability-Oriented Value function dynamically prioritizes samples with the highest *potential* training gain by aligning its probability density with the model's current global success/failure rate.
- **Mechanism:** The value `V(Bi, pi)` multiplies a Budget Saturation Factor (capturing diminishing returns per sample) by a Beta-distributed Density(pi; αt, βt). The Beta parameters (αt, βt) are linear functions of a transformed global failure rate `˜Ft = Ψ(¯Ft)`. A high global failure rate (low capability) shifts the Beta distribution to favor lower pass-rate `pi` (exploration of hard samples). A low failure rate (high capability) shifts it to favor higher `pi` (exploitation of easy/moderate samples where value is consolidated).
- **Core assumption:** The model's evolving global capability (captured by batch-wide failure rate) is a reliable, real-time proxy for which samples currently offer the highest marginal training value. The relationship between `pi` and training value is non-linear and capability-dependent.
- **Evidence anchors:**
  - [abstract]: "shifts allocation preferences based on the global failure rate to prioritize either exploration or exploitation."
  - [section 2.3.1]: Details the Capability-Induced Preference Density as a Beta distribution with parameters set via `αt = clip(αmin+λ·˜Ft, ...)` and `βt = κ−αt`.
  - [corpus]: The neighbor "Adaptive Rollout Allocation..." uses a similar global metric but differs in value function design; the corpus does not provide direct evidence for the Beta shape's efficacy, making this design choice a novel assumption.
- **Break condition:** The mechanism fails if the global failure rate `Ft` becomes a misleading signal—for example, if the batch distribution is highly skewed by a few outlier tasks, if capability progression is non-monotonic (e.g., catastrophic forgetting on specific skills), or if the `Ψ` transformation (sigmoid scaling) fails to sensitively calibrate `˜Ft` in the low-failure regime.

### Mechanism 2
- **Claim:** A heap-based greedy allocation strategy efficiently maximizes the total batch value under the diminishing-returns property of `V`, achieving optimal resource distribution with near-constant-time per allocation.
- **Mechanism:** Starting from a minimum budget `Blow` for all tasks, the algorithm repeatedly selects the task with the highest marginal gain `∆Vi = V(Bi+1, pi) - V(Bi, pi)` from a max-heap, increments its budget, and updates its new marginal gain in the heap until the total budget `Btotal` is exhausted. Proposition 2.2 proves `∆V` is strictly decreasing in `Bi` (geometric decay), which mathematically guarantees this greedy approach yields the optimal integer solution to the constrained maximization problem.
- **Core assumption:** The discrete budget allocation problem exhibits the greedy-choice property due to strictly diminishing marginal returns. The value function's structure (exponential decay term multiplied by Beta density) ensures this property holds universally for all `pi` and `Bi`.
- **Evidence anchors:**
  - [section 2.4]: "Proposition 2.2. The marginal gain... is strictly monotonically decreasing... This diminishing marginal utility property guarantees that a greedy allocation strategy yields an optimal solution."
  - [section 2.4]: Algorithm 1 details the heap implementation, showing complexity `O(Btotal log M)` vs DP's `O(M·Btotal·(Bup−Blow))`.
  - [section 3.6]: Table 4 empirically shows a 928× speedup over dynamic programming with identical allocation results.
- **Break condition:** The greedy optimality proof collapses if the value function's marginal gain is not strictly decreasing for some `pi` or `Bi` (e.g., if the Budget Saturation Factor model is incorrect or the Beta density term interacts non-monotonically). Numerical instability in heap updates or edge cases where `Blow = Bup` would also break the mechanism.

### Mechanism 3
- **Claim:** The system self-calibrates the exploration-exploitation trade-off over training by letting `αt` (and thus the Beta distribution's mode) evolve as a function of the *trend* in global failure rate, not just its instantaneous value.
- **Mechanism:** A moving average of the global failure rate `¯Ft` is computed over `k` steps to smooth noise. This `¯Ft` is transformed by `Ψ` to produce `˜Ft`. When `¯Ft > 0.5` (high failure), `˜Ft = ¯Ft` directly. When `¯Ft ≤ 0.5`, `˜Ft = σ(γ·(¯Ft−0.5))` applies a sigmoid with scaling factor `γ=10`, compressing small improvements in low failure rates into more sensitive changes in `˜Ft`. This causes `αt` (which increases with `˜Ft`) to decrease smoothly as capability improves, shifting allocation from exploiting high-`pi` samples to exploring lower-`pi` samples as the model masters the easier material.
- **Core assumption:** A smoothed, non-linearly transformed global failure rate is a robust indicator of the *phase* of learning (early/late) and should drive a continuous, smooth shift in allocation preference from exploitation to exploration. The sigmoid transformation is necessary to maintain sensitivity when `¯Ft` is already low.
- **Evidence anchors:**
  - [section 2.3.1]: Equation 6 defining `˜Ft` with the conditional sigmoid transformation.
  - [section 3.3]: Table 2 and Figure 5 show that "Exploit → Explore" (decreasing `αt`, matching CoBA-RL's behavior) significantly outperforms the reverse schedule, validating the preferred direction of shift.
  - [corpus]: The "Adaptive Rollout Allocation..." neighbor uses a static value function per prompt; CoBA-RL's innovation is the *dynamic* capability-driven shift, which is not corroborated by neighbors but is central to the claimed mechanism.
- **Break condition:** The `Ψ` transformation could mis-calibrate if the learning curve is not smooth (e.g., sudden leaps in capability on a subset of skills) or if the moving average window `k` is poorly chosen (too short = noisy; too long = sluggish response). If the optimal exploration/exploitation schedule is task-batch-specific rather than globally uniform, a single scalar `˜Ft` might be insufficient.

## Foundational Learning
- **Concept: Beta Distribution Parameterization**  
  **Why needed here:** The core value function uses a Beta(α, β) as a flexible, differentiable density over pass rates p_i. Understanding how α and β control the mode (peak preference) and variance (sharpness of preference) is essential to grasp how capability shifts allocation.  
  **Quick check question:** If α increases while β decreases (with constant sum κ), how does the mode of the Beta distribution change, and what does that imply for which samples get more budget?

- **Concept: Diminishing Marginal Returns in Resource Allocation**  
  **Why needed here:** Proposition 2.2 and the greedy algorithm rely on the strict mathematical property that each additional rollout on a sample yields less incremental value than the previous one. This underpins the optimality of the heap-based approach.  
  **Quick check question:** For the function V(B) = C * (1 - exp(-k*B)), derive ΔV(B) and prove it is decreasing in B. What economic intuition does this represent?

- **Concept: Exploration vs. Exploitation in Online RL**  
  **Why needed here:** The entire adaptive mechanism aims to balance allocating rollouts to samples where the model already succeeds (exploitation, to solidify gains) versus samples it fails on (exploration, to find new solutions). The paper argues the ideal balance shifts over time.  
  **Quick check question:** In early training, would you expect a higher global failure rate F to correlate with a need for more exploration or exploitation? How should the value function's Beta parameters behave in that phase?

## Architecture Onboarding
**Component map:**
1. Capability Estimator: Computes ¯F_t (moving avg of batch pass rates), applies Ψ to get ˜F_t, and calculates α_t, β_t.
2. Value Function Calculator: Given pi for each prompt and current (α_t, β_t), computes V(B_i, pi) and its marginal gain ΔV(B_i, pi) for any B_i.
3. Budget Allocator (Heap-Based Greedy): Maintains a max‑heap of (ΔV_i, i) tuples. Implements Algorithm 1: initialize B_i = B_low, push all tasks, then iteratively pop max, increment B_i, recalc ΔV_i, and push back until B_total spent.
4. Batch Resampler: Expands the original batch of M prompts into a larger list of B_total items according to the final B_i counts before rollout generation.

**Critical path:**
1. At training step t, process a batch of M prompts, compute their current pass rates p_i (from a quick small‑G generation).
2. Capability Estimator runs on the batch to get α_t, β_t.
3. Budget Allocator takes {p_i}, α_t, β_t, B_low, B_up, B_total and outputs allocation {B_i}.
4. Batch Resampler creates the expanded rollout set.
5. Generate B_i rollouts per prompt x_i and proceed with GRPO loss calculation and policy update.
6. Repeat.

**Design tradeoffs:**
- **Computational Cost vs. Precision:** The heap‑based allocator (O(B_total log M)) is vastly faster than DP (O(M·B_total·range)) but assumes diminishing returns (Proven). If the value model were misspecified, DP would find the true optimum but be unusably slow; the tradeoff favors speed under a sound model.
- **Global vs. Local Signal:** Using a single global F_t is cheap and provides a clear learning‑phase signal, but may miss batch‑specific nuances (e.g., a batch with a mix of old and radically new skills). A more complex per‑task capability estimate would increase cost and complexity.
- **Parameter Robustness:** The choice of κ (Beta sum), γ (sigmoid scale), and moving average window k control sensitivity. The paper shows robustness to κ (Appendix D.2), but poor k could cause oscillations or lag.

**Failure signatures:**
- **Allocation collapse:** If ˜F_t hits a boundary (e.g., α_t clipped to α_max or α_min for many steps), allocation becomes static (like a baseline). Monitor α_t trajectory.
- **Heap corruption/inefficiency:** If marginal gains are not strictly recomputed after every B_i increment (e.g., due to caching), greedy suboptimality emerges. Validate with small‑scale DP comparison.
- **Batch distribution shift:** If a training batch is highly anomalous (e.g., all extremely hard or all extremely easy), F_t may not represent the model's *general* capability, leading to mis‑calibrated α_t. Monitor batch‑level p_i variance.
- **Value function miscalibration:** If the Budget Saturation Factor's temperature τ is wrong, the perceived marginal gains will be distorted. The heap will incorrectly prioritize tasks. Effectiveness should be validated via the ablation in Appendix D.2 (varying κ).

**First 3 experiments:**
1. **Unit Test - Value Function & Marginal Gain:** For a fixed p_i, manually compute V(B_i) for B_i from B_low to B_up with known α, β, τ. Verify ΔV(B_i) is strictly decreasing (plot the sequence). Test edge p_i→0 or p_i→1.
2. **Component Test - Heap vs. Exhaustive:** For a tiny batch (M=3, B_total=10), run the heap allocator and a brute‑force DP enumerating all B_i combinations satisfying constraints. Assert identical total ∑V is achieved. This validates the greedy optimality claim empirically on small instances.
3. **Integration Test - Allocation Behavior:** Train for 2‑3 steps on a tiny synthetic dataset (e.g., 10 prompts with known p_i). Log α_t and the *distribution* of allocated B_i across the p_i spectrum at each step. Expect to see: (a) early steps with high F_t → α_t high → B_i allocated more to high‑p prompts; (b) later steps with lower F_t → α_t low → B_i shifts toward low‑p prompts. Visualize as in Figure 4.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does CoBA-RL's performance generalize to non‑mathematical reasoning domains such as code generation or agentic tasks?
- **Basis in paper:** [inferred] The paper's experiments are exclusively conducted on mathematical benchmarks (AIME24, AIME25, AMC23, MATH500, OLYMPIAD), despite RLVR being applied broadly in coding and agentic domains (as noted in the Introduction).
- **Why unresolved:** The Capability‑Oriented Value function and exploration‑exploitation dynamics may behave differently in settings with partial rewards, longer horizons, or diverse task structures; without evaluation, it is unclear if the observed gains are domain‑specific.
- **What evidence would resolve it:** Evaluate CoBA-RL on standard code benchmarks (e.g., HumanEval, MBPP) and agentic benchmarks (e.g., WebShop, AlfWorld), comparing against GRPO and Knapsack‑RL to measure relative improvements and analyze allocation patterns.

### Open Question 2
- **Question:** Is the exponential Budget Saturation Factor (η = 1 − exp(−B_i / (τ p_i(1−p_i)))) the most effective functional form for modeling diminishing returns, or would alternative forms yield better allocation and accuracy?
- **Basis in paper:** [inferred] The paper adopts this specific exponential form in Section 2.3.2 without empirical or theoretical justification beyond intuition, and no alternative functions are tested.
- **Why unresolved:** The choice directly shapes the marginal gain property that enables greedy optimality; other diminishing‑return functions (e.g., polynomial, logarithmic) might better reflect true learning dynamics for certain tasks or models.
- **What evidence would resolve it:** Conduct an ablation replacing the exponential with a family of functions (e.g., η = 1 − (1 + B_i/τ)^{−γ} for various γ) across multiple benchmarks, measuring final accuracy and allocation distribution to identify optimal forms.

### Open Question 3
- **Question:** Can a dynamic, instance‑level capability metric (tracking per‑task success rates over time) improve upon the global failure rate used in CoBA‑RL, especially for heterogeneous task batches?
- **Basis in paper:** [inferred] The paper uses a global batch‑averaged failure rate (F_t) to calibrate the Beta distribution (Section 2.3), while criticizing prior work for relying on static instance‑level metrics; however, it does not explore whether instance‑level dynamics could offer finer‑grained control.
- **Why unresolved:** The global metric may conflate tasks with disparate learning trajectories, leading to suboptimal allocations for batches with high variance in difficulty; instance‑level tracking could adapt more sensitively but is untested.
- **What evidence would resolve it:** Implement a variant of CoBA‑RL that maintains a moving average of pass rates per task instance and uses these to derive task‑specific α_t, β_t; compare allocation efficiency (e.g., marginal gain per rollout) and final model performance against the global version on datasets with diverse initial pass rates.

## Limitations
- **Hyperparameter ambiguity**: Critical values (α_min, α_max, λ, τ, B_low, B_up, moving average window k) are unreported, hindering faithful reproduction.
- **Global metric fragility**: The reliance on a single global failure rate may misrepresent model capability on heterogeneous batches and is sensitive to window size and transformation parameters.
- **Assumption sensitivity**: Performance hinges on the diminishing‑returns property; violations due to misspecification or numerical errors could break greedy optimality.
