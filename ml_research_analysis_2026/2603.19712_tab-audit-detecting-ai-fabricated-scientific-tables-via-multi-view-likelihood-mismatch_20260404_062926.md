# TAB-AUDIT: Detecting AI-Fabricated Scientific Tables via Multi-View Likelihood Mismatch
## Quick Facts
- **arXiv ID:** 2603.19712  
- **Source URL:** https://arxiv.org/abs/2603.19712  
- **Reference count:** 40  
- **Primary result:** TAB-AUDIT detects AI-fabricated tables with AUROC 0.987 in-domain and 0.883 out-of-domain, using within-table likelihood mismatch as the key forensic signal.

## Executive Summary
The paper presents TAB-AUDIT, a novel detector for AI-generated fabricated scientific tables, addressing a critical threat to academic integrity. Unlike prior text-based detectors, TAB-AUDIT exploits a forensic signal derived from the mismatch in language-model perplexity between a table’s textual skeleton (headers, row labels) and its numeric content. This multi-view likelihood contrast, augmented with handcrafted numeric and structural features, achieves strong detection performance on the new FabTab benchmark. Under a low false‑positive screening regime (5% FPR), TAB-AUDIT attains high true positive rates and significantly outperforms existing methods, demonstrating the forensic utility of likelihood mismatch for structured evidence.

## Method Summary
TAB-AUDIT processes each experimental table by serializing it into three deterministic text views: the full table string (`sfull`), a skeleton view with all numeric substrings replaced by a placeholder (`stext`), and a digit‑level view containing only numeric characters spaced out (`sdig`). The core feature, **f∆**, captures the within‑table mismatch:  

`f∆ = sign(diff) · log(1+|diff|)`  

where `diff = PPL(sdig) – PPL(stext)` computed using a frozen observer language model (e.g., GPT‑2 base). The observer scores each view via a sliding‑window approach to handle long sequences; perplexity is derived from token‑level negative log‑likelihood.  

Complementary, language‑model‑free numeric statistics (e.g., row Δ‑consistency, monotonicity, sortedness, decimal precision) and structural attributes (row/column counts, numeric density) are extracted. For a paper containing multiple tables, each feature is aggregated across tables using the median to produce a fixed‑length paper‑level vector. A Random Forest classifier (or alternatives like logistic regression or MLP) is trained on these vectors; the decision threshold is calibrated on a validation set of human papers to achieve approximately 5% false positive rate.  

The method is evaluated on the FabTab benchmark, which comprises human‑authored tables from arXiv NLP papers and AI‑fabricated tables generated via GPT‑4o using a literature‑grounded pipeline.

## Key Results
- **In‑domain (GPT‑4o) detection:** AUROC 0.987, with TPR@5%FPR far exceeding prior text detectors.  
- **Out‑of‑domain (GPT‑5.2 holdout):** AUROC 0.883, demonstrating robust generalization across model generations.  
- **Ablation:** Removing the within‑table mismatch feature `f∆` degrades performance markedly, confirming it as the strongest individual cue.

## Why This Works (Mechanism)
The forensic signal arises because language models treat numeric and textual tokens differently. Human‑written tables exhibit coherent statistical patterns: numeric values follow domain‑specific distributions, often display monotonic trends or rounded numbers, and produce a relatively low perplexity when viewed in isolation (`sdig`). The relationship between numeric and textual perplexities is consistent. In contrast, AI‑generated tables, even when conditioned on real references, yield numeric content that is less aligned with the textual context and shows irregularities at the digit level. A frozen observer LM (preferably a base model, not instruction‑tuned) assigns higher perplexity to the numeric view of AI tables relative to the skeleton, leading to a larger mismatch `f∆`. This systematic within‑table discrepancy acts as a telltale artifact of fabrication, largely independent of superficial textual quality.

## Foundational Learning
- **Perplexity**  
  *Why needed:* Quantifies how well a language model predicts text; the basis of the mismatch feature `f∆`.  
  *Quick check:* Compute the perplexity of a known fluent sentence under a LM; it should be low.  

- **Tokenization**  
  *Why needed:* Determines how numbers are split into tokens, directly affecting perplexity calculations and alignment between `stext` and `sdig`.  
  *Quick check:* Tokenize the string `"123.45"` using the LM’s tokenizer and observe token boundaries.  

- **Table serialization**  
  *Why needed:* Converts structured table data into linear strings for LM scoring; formatting choices influence the forensic signal.  
  *Quick check:* Serialize a sample table into `sfull`, `stext`, `sdig` and verify that replacing numeric substrings in `sfull` with the placeholder yields `stext`.  

- **Paper‑level aggregation**  
  *Why needed:* Combines multiple table features per paper into a single decision vector; median aggregation reduces noise.  
  *Quick check:* Given a set of feature values across tables, compute the median and compare to the individual values.  

- **Random Forest classifier**  
  *Why needed:* Provides a non‑linear, robust decision boundary used in the presented system.  
  *Quick check:* Train a Random Forest on a small synthetic dataset and inspect feature importances to see which features contribute most.

## Architecture Onboarding
**Component Map:**  
Raw Table → Serialization (`sfull`, `stext`, `sdig`) → Observer LM (perplexity computation) → Feature Extraction (`f∆`, numeric stats, structural stats) → Paper‑level Aggregation (median) → Classifier (Random Forest) → Threshold Calibration → Detection Decision.

**Critical Path:**  
1. Correct table extraction and deterministic serialization.  
2. Accurate perplexity computation for the three views using a sliding window.  
3. Computation of `f∆` and supplementary numeric/structural features.  
4. Median aggregation across tables per paper.  
5. Application of trained classifier and calibrated threshold for binary decision.

**Design Tradeoffs:**  
- **Observer LM choice:** Base models preserve numeric anomalies (stronger signal) but may be less stable; instruct‑tuned models smooth anomalies (weaker signal) but might improve out‑of‑domain robustness.  
- **Sliding window:** Larger windows capture more context but increase computational cost; stride determines coverage completeness.  
- **Aggregation method:** Median is robust to outliers but may discard useful variance; mean is more sensitive to atypical tables.  
- **Classifier complexity:** Random Forest offers good performance with minimal tuning; logistic regression is more interpretable; MLP may overfit on limited data.

**Failure Signatures:**  
- Overlap between `f∆` distributions of human and AI tables → poor separation and low AUROC.  
- Extremely high perplexity values due to extraction errors (e.g., merged cells) → outlier features that distort classifier training.  
- Classifier overfitting to in‑domain data → sharp drop in out‑of‑domain performance.  
- Threshold calibrated on validation humans yielding unexpectedly high FPR on test due to distribution shift.

**First Experiments (3):**  
1. **Validate `f∆` signal:** Compute `f∆` on a small balanced subset of human and AI tables; visualize histograms to confirm separation.  
2. **Compare observer LMs:** Run mismatch computation with GPT‑2, Qwen3‑8B base, and Llama3‑8B base; measure effect size between classes to select the most discriminative model.  
3. **Baseline with single feature:** Train a logistic regression using only `f∆`; report AUROC to establish the core signal strength independent of supplementary features.

## Limitations
- Exact serialization format and some numeric feature formulas require the appendix; without them, faithful replication is hindered.  
- Performance is sensitive to observer LM selection (base vs. instruct) and scoring parameters (window size, stride), which are not fully specified.  
- The FabTab benchmark covers only NLP papers and a single GPT‑4o generation pipeline; broader domain and model diversity remain untested.
