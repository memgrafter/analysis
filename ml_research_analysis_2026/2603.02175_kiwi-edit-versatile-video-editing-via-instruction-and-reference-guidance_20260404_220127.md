# Kiwi-Edit: Versatile Video Editing via Instruction and Reference Guidance

## Quick Facts
- **arXiv ID:** 2603.02175
- **Source URL:** https://arxiv.org/abs/2603.02175
- **Reference count:** 40
- **Primary result:** Achieves new SOTA on OpenVE-Bench (3.02 vs. prior 2.50) and RefVIE-Bench (3.31 overall, 3.98 identity consistency, 3.72 reference similarity).

## Executive Summary
Kiwi-Edit tackles reference-guided video editing, where a source video is modified according to both a textual instruction and a reference image. The core challenge is training data scarcity for such quadruplets. The authors address this by constructing RefVIE, a 477K-scale dataset synthesized automatically from existing video editing pairs using a scalable pipeline. The proposed model unifies a frozen Multimodal Large Language Model (MLLM) and a Diffusion Transformer (DiT) via dual connectors and a hybrid latent injection strategy, trained through a progressive curriculum. This design balances instruction semantics, reference fidelity, and source structure preservation. On established and new benchmarks, Kiwi-Edit sets a new state-of-the-art among open-source methods, particularly excelling in identity and reference consistency metrics.

## Method Summary
Kiwi-Edit processes three inputs: a source video, an instruction text, and a reference image. A frozen Qwen2.5-VL MLLM, lightly adapted with LoRA, interprets the interleaved sequence of source frames, instruction, and reference. Its outputs are bifurcated: a Query Connector (MLP) distills sparse editing intent via learnable query tokens, while a Latent Connector (MLP) projects dense visual features from the reference region. These signals, along with a hybrid injection mechanism, condition a Wan-TI2V DiT backbone. Specifically, source video latents are added element-wise to the noisy latent at each timestep, scaled by a learnable scalar γ(t), preserving structure. Reference image latents are concatenated to the input sequence for fine-grained transfer. Training proceeds in three stages: (1) MLLM–DiT alignment on image editing data with frozen backbones, (2) instructional tuning on video data with the DiT unfrozen, and (3) reference-guided fine-tuning on the RefVIE quadruplets. The model is trained with a Flow Matching objective.

## Key Results
- **OpenVE-Bench:** Overall score 3.02, beating prior best 2.50.
- **RefVIE-Bench:** Overall score 3.31, with identity consistency 3.98 and reference similarity 3.72.
- **SOTA status:** Highest reported scores for open-source methods on both benchmarks.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** A scalable data pipeline can synthesize high-fidelity reference images from existing video editing pairs, mitigating training data scarcity.  
**Mechanism:** The pipeline uses a VL model (Qwen3-VL) to ground the edited region in the target video frame, then segments with SAM3 and extracts/generates the reference via a specialized image editor (Qwen-Image-Edit). This automates creation of the missing reference component from a (source video, instruction, target video) triplet.  
**Evidence:** Detailed 4-stage pipeline (Source Aggregation, Grounding/Segmentation, Reference Synthesis, Quality Control) in Section 3.1; ablation shows dataset quality is critical.  
**Break condition:** Fails if grounding mislocalizes the edit region or the image editor introduces artifacts/identity drift.

### Mechanism 2
**Claim:** Unified conditioning of a DiT via a frozen MLLM with dual connectors (Query & Latent) and hybrid latent injection effectively balances instruction semantics, reference fidelity, and source preservation.  
**Mechanism:** The MLLM processes interleaved inputs to produce two signals: distilled intent via learnable queries (Query Connector) and dense reference features (Latent Connector). Source latents are added element-wise (modulated by learnable γ(t)) to the noisy latent; reference latents are concatenated to the input sequence.  
**Evidence:** Equations in Section 4.1; Table 4 ablations show channel concatenation performs poorly and both connectors are necessary.  
**Break condition:** Query Connector fails to capture salient intent, or Latent Connector misaligns reference features; γ(t) learned incorrectly leads to overwriting or ignoring source structure.

### Mechanism 3
**Claim:** A progressive multi-stage training curriculum is necessary for stable convergence and effective transfer of multimodal understanding to video generation.  
**Mechanism:** Stage 1 trains only lightweight bridges (LoRA, connectors, queries) on image editing data to establish coarse MLLM→DiT mapping without destabilizing frozen backbones. Stage 2 unfreezes the DiT and trains on video instruction triplets to learn motion/editing primitives. Stage 3 introduces RefVIE quadruplets for fine-tuning reference adherence.  
**Evidence:** Section 4.2 defines stages; Table 4 ablation shows catastrophic drop when skipping Stage 1.  
**Break condition:** Skipping stages causes collapse; insufficient Stage 1 prevents semantic alignment, weak Stage 2 harms temporal consistency, biased Stage 3 data degrades background edits.

## Foundational Learning
- **Concept: Diffusion Models / Flow Matching**  
  *Why needed here:* Kiwi-Edit’s DiT backbone generates video latents via a diffusion/flow matching process. Understanding the training objective (predicting velocity field) and noise scheduling is fundamental to how conditioning signals influence generation.  
  *Quick check question:* How does adding the source video feature (γ(t)·src_latent) to the noisy latent z_t at timestep t affect the denoising trajectory, and why is a learnable γ(t) used instead of a fixed weight?
- **Concept: Multimodal Large Language Models (MLLMs) as Semantic Encoders**  
  *Why needed here:* The MLLM is the core module for understanding the interleaved input sequence (video frames, text, reference image). Its role as a frozen feature extractor with lightweight LoRA adaptation, and how its output tokens are processed by separate connectors, is central to the architecture.  
  *Quick check question:* Why is the MLLM’s base weights frozen, and what is the purpose of the separate Query Connector vs. Latent Connector if both take MLLM output?
- **Concept: Video Editing Data Scarcity & Synthetic Data Construction**  
  *Why needed here:* The paper’s primary motivation and contribution (RefVIE) is a solution to data scarcity. Understanding why manual quadruplet curation is infeasible and how existing triplets can be automated into quadruplets is key to the paper’s data-centric narrative.  
  *Quick check question:* What is the core insight that allows the pipeline to synthesize a valid reference image from a (V_src, T_inst, V_tgt) pair, and what are the two main failure modes filtered out in Stage 4?

## Architecture Onboarding
**Component map:**  
Input Encoder (VAE) → Semantic Encoder (frozen Qwen2.5-VL + LoRA) → Connector Suite (Query MLP & Latent MLP) → Conditioning Injection (Hybrid: source added with γ(t), reference concatenated) → Generator (Wan-TI2V DiT)

**Critical path:**  
1. Encode source video and reference image via VAE into latents.  
2. Create interleaved sequence (source frames, instruction, reference) and process through MLLM+LoRA.  
3. Extract tokens corresponding to the reference region and apply cross-attention with learnable queries.  
4. Project MLLM outputs via Query Connector (intent) and Latent Connector (reference features).  
5. Form context tokens from projections and prepare DiT input with hybrid injection: noisy latent + γ(t)*source latent, plus concatenated reference latent.  
6. Feed sequence and context into DiT, predict velocity, compute Flow Matching loss against target video latent.

**Design tradeoffs:**  
- Element-wise add vs. concat for source: add preserves exact structure without increasing sequence length but relies on perfectly learned γ(t); concat is more expressive but causes instability and longer sequences.  
- Dual connectors vs. single MLLM output: splitting into sparse intent and dense visual allows specialized handling but adds complexity; a single projection might conflate signals.  
- Frozen MLLM + LoRA vs. full fine-tuning: preserves pre-trained knowledge and reduces forgetting/compute, but limits adaptation capacity to video editing domain.  
- Curriculum cost vs. performance: three stages require more compute and data management but prevent collapse and yield SOTA; joint training would be faster but likely fails to converge well.

**Failure signatures:**  
- Temporal incoherence: object flickers/deforms across frames → weak Stage 2 video tuning or γ(t) ≈ 0.  
- Poor reference adherence: generated object has wrong identity/texture → failed grounding in dataset, weak Latent Connector, or insufficient Stage 3 data.  
- Instruction ignoring: edits applied to wrong regions → Query Connector failure or misaligned MLLM-LoRA.  
- Source structure destroyed: background/untouched areas change → γ(t) too high or source injection broken.  
- Artifacts at boundaries: halos/seams → poor spatial attention from concatenation or bad segmentation masks in training data.

**First 3 experiments:**  
1. Ablate γ(t): train with γ(t) fixed to 1.0, set to 0, and learnable; expect learnable γ(t) to best balance source preservation and edit flexibility.  
2. Connector isolate test: train with only Query Connector (disable Latent) and only Latent Connector (disable Query); combined should be best, each alone degrading complementary metrics.  
3. Curriculum necessity: skip Stage 1 (Alignment) and train only Stages 2+3; expect catastrophic drop across all metrics, confirming Stage 1’s prerequisite role.

## Open Questions the Paper Calls Out
- Why does stage-3 fine-tuning hurt background editing performance? The paper cites dataset bias toward local changes but provides no solution.  
- Does fine-tuning the entire MLLM improve reference-guided editing over the frozen MLLM with LoRA?  
- How reliable are MLLM-based metrics (Gemini) for video editing evaluation versus human judgment?  
- Can Kiwi-Edit handle arbitrary user-provided references not derived from the target video? Training references are synthesized from the target video, so distribution shift may cause failure.

## Limitations
- Dataset bias: RefVIE is heavily biased toward local object changes, degrading background replacement performance.
- Evaluation reliability: Automated scoring with Gemini-2.5-Pro lacks human validation; correlation with human perception is unknown.
- Architecture constraints: Frozen MLLM may limit adaptation to video editing nuances; full fine-tuning impact unexplored.
- Generalization: Model may fail with external/misaligned reference images due to training distribution alignment.

## Confidence
- Data pipeline (RefVIE synthesis) solves scarcity: **Medium** – supported by ablations but quality control details undisclosed.
- Architecture (dual connectors + hybrid injection): **Medium** – ablations validate design, yet γ(t) sensitivity and alignment issues could affect robustness.
- Progressive curriculum essential: **High** – skipping Stage 1 causes catastrophic drop, strongly indicating necessity.

## Next Checks
1. **γ(t) behavior validation:** Train models with γ(t) fixed at 0, 0.5, 1.0; compare against learnable γ(t) to confirm optimal balance between source preservation and edit flexibility.
2. **Connector role isolation:** Remove Query or Latent connector individually on RefVIE-Bench; measure impact on instruction adherence versus reference similarity to verify dual-path necessity.
3. **Curriculum robustness test:** Ablate Stage 1 (e.g., reduce steps or data) or skip it entirely; expect performance collapse if Stage 1 is indeed prerequisite for stable MLLM-DiT alignment.
