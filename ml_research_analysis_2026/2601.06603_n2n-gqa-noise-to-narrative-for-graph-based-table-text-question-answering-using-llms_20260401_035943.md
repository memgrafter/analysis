# N2N-GQA: Noise-to-Narrative for Graph-Based Table-Text Question Answering Using LLMs

## Quick Facts
- **ArXiv ID:** 2601.06603
- **Source URL:** https://arxiv.org/abs/2601.06603
- **Reference count:** 10
- **Primary result:** 19.9-point Exact Match improvement via graph-based evidence curation; overall 48.80 EM without task-specific training.

## Executive Summary
N2N-GQA is a zero-shot framework for multi-hop question answering over hybrid table-text data that tackles retrieval noise—a key weakness of standard RAG pipelines, where flat document lists obscure reasoning chains. It constructs dynamic evidence graphs from retrieved documents, using nodes for documents and TF-IDF term overlap for weighted edges to surface critical "bridge" documents. On the OTT-QA benchmark, this graph-based curation alone yields a 19.9-point Exact Match (EM) gain over strong RAG baselines. The full system achieves 48.80 EM without any fine-tuning, matching fine-tuned retrieval models (CORE: 49.0 EM) and approaching heavily optimized systems (COS: 56.9 EM). The work demonstrates that organizing retrieval results as structured graphs is essential for effective multi-hop reasoning and can rival sophisticated fine-tuned approaches in a zero-shot setting.

## Method Summary
N2N-GQA is a multi-stage, zero-shot pipeline. First, an LLM decomposes the question into a structured plan of hops with conditional templates. For each hop, a dense retriever (ColBERTv2) fetches top-k documents (text passages or serialized table rows). From this retrieved set, a hop-specific evidence graph is built: documents are nodes, edges weighted by TF-IDF term overlap. Graph centrality (weighted degree) identifies likely "bridge" documents. GraphRank re-ranks nodes via a multiplicative score combining normalized semantic similarity and normalized centrality, with a hyperparameter α enforcing semantic dominance. The graph is pruned to a focused set, and an LLM extracts intermediate entities. After all hops, a Bridge-Aware Hybrid Selector boosts scores of top-ranked passages and tables that share entities. A final global graph is built from all evidence, re-ranked via GraphRank, pruned, and an LLM synthesizes the answer. No task-specific training is used.

## Key Results
- Graph-based evidence curation provides a 19.9-point Exact Match improvement on OTT-QA over strong RAG baselines.
- Full N2N-GQA achieves 48.80 EM without fine-tuning, matching the fine-tuned retriever CORE (49.0 EM) and approaching the optimized COS system (56.9 EM).
- The framework demonstrates zero-shot competitiveness, closing most of the performance gap with state-of-the-art fine-tuned methods.

## Why This Works (Mechanism)
**Mechanism 1: Evidence graph exposes relational structure.** Retrieved documents become graph nodes; edges weighted by TF-IDF term overlap represent semantic connections. Graph centrality identifies "bridge" documents that link reasoning steps. Pruning based on connectivity filters noise and surfaces coherent evidence chains. Core assumption: multi-hop reasoning requires understanding relationships between evidence pieces, not just individual relevance scores. Break condition: if initial retrieval fails to include any gold-chain documents in top-k, graph construction cannot recover missing links.

**Mechanism 2: GraphRank scoring amplifies structurally important documents.** Score_GR(v) = S_sem_norm(v) × (1 + (1–α) × S_struct_norm(v)) with α=0.85. This enforces semantic dominance while using structural centrality as a confidence amplifier, not an independent ranking factor. It boosts bridge documents without overriding semantic relevance. Break condition: α too low risks noise from central but irrelevant nodes; too high loses structural benefits.

**Mechanism 3: Bridge-Aware Hybrid Selector bridges table-text modalities.** For top-ranked passage (p_top) and table (t_top), compute ϕ(p,t)=1 if passage contains any table key entity. Apply boost β to their scores, then re-rank. This prioritizes documents that connect table and text evidence, critical for hybrid QA. Break condition: entity linking failures due to ambiguity or serialization loss can miss true bridges or boost false positives.

Needed because the graph's purpose is to denoise by exposing relationships. ## Architecture Onboarding
**Component map:** Query Planner -> Retriever -> Graph Constructor -> GraphRank -> Entity Extractor -> Bridge-Aware Selector -> Final Graph & Answer Generator.

**Critical path:** Question → Structured Plan → Iterative per-hop: Hop Query → Retrieve → Build Graph → GraphRank/Prune → Extract Entity → Aggregate All Evidence → Bridge-Aware Selector → Final Graph → GraphRank/Prune → Answer Synthesis.

**Design tradeoffs:** TF-IDF edges chosen for efficiency and zero-shot consistency over dense embeddings; α=0.85 in GraphRank balances semantic dominance vs. structural boost; retrieval k-size (100 final, 20 per hop) trades recall vs. noise.

**Failure signatures:** Retrieval failure (gold docs not in top-k); sparse graph edges (TF-IDF too strict); entity extraction ambiguity; Bridge-Aware misprioritization.

**First 3 experiments:**
1. Vanilla RAG baseline (top-k to LLM) establishes severe noise problem (~8 EM).
2. RAG + Query Decomposition isolates value of breaking into hops (~28-37 EM).
3. N2N-GQA w/o GraphRank isolates impact of graph-based curation (+~20 EM over experiment 2).

## Open Questions the Paper Calls Out
1. **Can computational cost be reduced via distillation or LLM call optimization while preserving performance?** Basis: Limitations note high cost from large LLMs; future work suggests distillation.
2. **To what extent do richer edge representations (dense embeddings, entity links) improve over TF-IDF, and generalize?** Basis: Methodology defends TF-IDF but leaves exploration of richer structures as future work.
3. **Is the Bridge-Aware Selector's heuristic broadly effective or dataset-specific?** Basis: Selector introduced as useful but not isolated; generalizability assumed but untested.
4. **Can GraphRank α be dynamically set per query/hop instead of fixed 0.85?** Basis: Methodology sets α based on preliminary runs; limitations suggest dynamic weighting.
5. **Does the "noise-to-narrative" paradigm fundamentally improve reasoning, or is it just better context format?** Basis: Core claim is graph structure helps, but paper doesn't disentangle from document selection; ablation confounds graph with iterative retrieval.

## Limitations
- Graph curation cannot recover if initial retrieval misses all gold-chain documents (retrieval dependency).
- Effectiveness of Bridge-Aware Selector heuristic is unproven (β value undisclosed; no independent ablation).
- High computational cost due to reliance on large LLMs; zero-shot generalizability beyond OTT-QA/HybridQA uncertain.

## Confidence
- **Graph curation denoising:** High (ablation shows ~20 EM gain).
- **Zero-shot competitiveness:** Medium (matches fine-tuned retrievers on OTT-QA but may not generalize).
- **Bridge-Aware selector:** Low (heuristic described; β unspecified; no isolation test).
