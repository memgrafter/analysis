# Cold-Start Personalization via Training-Free Priors from Structured World Models

## Quick Facts
- arXiv ID: 2602.15012
- Source URL: https://arxiv.org/abs/2602.15012
- Reference count: 40
- Primary result: Pep achieves 80.8% preference alignment vs. 68.5% for RL (GRPO), using 3–5x fewer interactions.

## Executive Summary
Cold-start personalization requires inferring user preferences with limited interactions when no historical data exists. The core challenge is efficiently identifying the few relevant preference dimensions from a large set. Reinforcement learning (RL) approaches fail because sparse terminal rewards prevent exploiting factored preference structure, leading to static questioning. Pep addresses this by decomposing the problem: offline learning of a structured world model from complete preference profiles captures preference correlations via latent variables. Online, it performs training-free Bayesian inference, updating beliefs over user embeddings after each response to select maximally informative questions and predict full profiles. On four reasoning benchmarks, Pep achieves 80.8% preference alignment vs. 68.5% for RL (GRPO), using 3–5x fewer interactions. When users differ on the same question, Pep adapts its follow-up 39–62% of the time vs. 0–28% for RL. It uses ~10K parameters versus RL’s 8B, demonstrating the bottleneck is structural exploitation, not capacity.

## Method Summary
Pep employs a two-stage approach to cold-start personalization. In the offline phase, it learns a structured world model from a dataset of complete user preference profiles. The model captures correlations between preferences across criteria and users via a latent user embedding z. Implementations include Bayesian linear regression (BLR) or a Gaussian mixture model (GMM). The model factorizes the joint preference distribution as P(v|c, z, x), where each criterion's value depends on the latent embedding, enabling dense supervision from the full profiles.

During online interaction with a new user, Pep maintains a Bayesian posterior over the user's latent embedding. After each response to a queried criterion, it updates the posterior using Bayes' rule. Question selection is driven by an acquisition function—typically information gain—that scores each unqueried criterion by the expected reduction in uncertainty about the latent state or the predictive distribution over other criteria. After a fixed budget T (e.g., 5) of queries, Pep predicts the full preference profile by marginalizing the posterior over z and passes this profile to a fixed LLM solver (e.g., GPT-4.1) to generate a personalized response. The entire online process is training-free, relying solely on the offline-learned parameters and efficient Bayesian updates.

## Key Results
- Pep achieves 80.8% preference alignment vs. 68.5% for RL (GRPO) on four reasoning benchmarks.
- It uses 3–5× fewer interaction turns to reach comparable alignment, demonstrating superior query efficiency.
- Pep adapts its follow-up question 39–62% of the time when users differ on a given question, compared to 0–28% for RL, showing higher adaptivity.

## Why This Works (Mechanism)
#### Mechanism 1: Structured world model captures preference correlations
- **Claim:** Learning a structured world model offline from complete preference profiles captures cross-criterion and cross-user preference correlations, enabling inference of unobserved preferences from partial interactions.
- **Mechanism:** Offline, the model learns a task-conditioned latent variable distribution P(v|c,z,x) where z is a user embedding. This structure factorizes the joint preference distribution, allowing each criterion's value to depend on z. Dense supervision from full profiles directly estimates these conditional distributions, avoiding credit assignment.
- **Core assumption:** User preferences exhibit predictable correlations across criteria (e.g., a user who values detail also values examples) that are stable enough to be captured by a low-dimensional latent z and can be transferred across tasks.
- **Evidence anchors:** [abstract] "learns a structured world model of preference correlations offline from complete profiles"; [section 3.1] "modeling preference correlations: without the latent structure... elicitation yields very slow improvement".
- **Break condition:** If preference correlations are extremely task-specific or non-existent, the world model provides no benefit and random querying would be equally effective. Performance would plateau near population average regardless of adaptive selection.

#### Mechanism 2: Bayesian posterior updates drive adaptive questioning
- **Claim:** Maintaining a Bayesian posterior over the user embedding z and updating it after each response allows the system to select questions that maximally reduce uncertainty about the full preference profile, including unqueried criteria.
- **Mechanism:** After observing (a_t, v_t), Bayes' rule updates P(z|H_t,x) ∝ P(v_t|a_t,z,x) P(z|H_{t-1},x). The selection strategy (e.g., information gain) scores candidate criteria by expected reduction in entropy of z or predictive uncertainty over other criteria. This uses the offline-learned P(v|c,z,x) to propagate information from queried to unqueried criteria via z.
- **Core assumption:** The latent variable z is a sufficient statistic for user preferences; knowing z makes criteria conditionally independent. The posterior update accurately reflects the user's type given observed responses.
- **Evidence anchors:** [abstract] "performs training-free Bayesian inference online to select informative questions and predict complete preference profiles"; [section 3.2] "Information gain... measures how much observing... reduces uncertainty about the latent structure connecting all preferences"; [section 4.3.2] "Pep adapts 2× more often than baselines" showing adaptive questioning driven by posterior updates.
- **Break condition:** If the latent dimension K is too small, the model cannot capture true user heterogeneity; if K is too large, posterior updates become inefficient and overfit. Also, if the likelihood model P(v|c,z,x) is mis-specified, Bayesian updates become inaccurate.

#### Mechanism 3: Reinforcement learning fails due to sparse terminal reward
- **Claim:** Reinforcement learning fails at cold-start elicitation because terminal reward supervision is entangled and does not exploit the factored per-criterion structure of preference profiles, causing credit assignment problems that lead to static, non-adaptive policies.
- **Mechanism:** RL optimizes a policy π using only a terminal PrefAlign score after T turns. This scalar provides no per-turn feedback, making it difficult to assign credit across the sequence of questions. The agent must explore O(C^T) question sequences to learn which are effective. In practice, it converges to fixed sequences that ignore user responses because deviating from common patterns carries high variance.
- **Core assumption:** The factored supervision (complete profiles with per-criterion labels) exists but is inaccessible to RL during training; RL only sees the aggregated terminal reward. The combinatorial explosion in question sequences is insurmountable with realistic sample budgets.
- **Evidence anchors:** [abstract] "RL's feedback structure is mismatched... sparse and terminal... provides no indication of which questions were informative"; [section 2] "Proposition 1... sample complexity scales exponentially in the budget T"; [section 4.3.2] "GRPO tends to exploit majority patterns and converge to static generic questioning" with 0% adaptivity on AIME.
- **Break condition:** If the interaction budget T were large enough to allow exhaustive exploration or if reward were shaped (e.g., intermediate rewards for eliciting correct preferences), RL might learn adaptive policies. However, in cold-start with tight T, the exponential complexity makes this infeasible.

## Foundational Learning
#### Bayesian inference for latent variable models
- **Why needed:** Pep's online adaptation relies on updating posterior beliefs over user embedding z after each response. Without Bayesian updating, the system cannot coherently incorporate new evidence to refine its belief about the user's full preference profile.
- **Quick check:** Given prior P(z) and likelihood P(v|a_t,z,x), how do you compute the posterior P(z|a_t,v_t) and use it to predict P(v'|c',z) for an unqueried criterion c'?

#### Collaborative filtering / matrix factorization intuition
- **Why needed:** The world model exploits correlations between users and criteria, analogous to collaborative filtering where user similarities help infer missing ratings. Here, "missing" are unobserved preferences, and the latent z plays the role of user factors.
- **Quick check:** How does a latent variable model like P(m|z,x) = ∏_c P(v_c|c,z,x) enable predicting a user's preference for an unobserved criterion based on their observed preferences?

#### Active learning with information-theoretic acquisition
- **Why needed:** Question selection aims to maximally reduce uncertainty about the full profile. Information gain (mutual information between response and latent z) formalizes this as an optimal experiment design problem.
- **Quick check:** Why is information gain I(v_c; z | H_t) a better criterion for elicitation than simply selecting the most uncertain criterion H[v_c|H_t]?

#### POMDPs and belief-state planning
- **Why needed:** Preference elicitation is a POMDP with hidden state m*. The belief over z is a sufficient statistic for acting optimally. Pep's approach is a specific POMDP solution where the belief update is Bayesian and the policy is myopic acquisition.
- **Quick check:** In a POMDP, what is the belief state, and why is maintaining the posterior over z sufficient for optimal action selection in this setting?

## Architecture Onboarding
#### Component map
Offline world model trainer → Online elicitation engine (comprising prior initializer, belief updater, selection strategy, profile predictor, solver interface). Data flow: Offline training produces a compact model (~10K parameters). Online loop: Initialize prior over z for task x; for each turn t=1..T: compute acquisition scores for all unqueried criteria using current posterior, select the argmax criterion a_t, query the user for response v_t, update posterior P(z|H_t) via Bayes, repeat; after T turns, predict full preference profile by marginalizing posterior, then call the fixed solver LLM with the predicted profile to generate personalized response y.

#### Critical path
1. Offline: Aggregate complete profiles per task type. Train BLR or GMM to model P(v|c,z,x). Save parameters.
2. Online per user: For given task x, initialize P(z|x) (uniform or task prior). For each turn: compute information gain for all unqueried criteria using current posterior, pick argmax, get user response, update posterior via Bayes.
3. After T turns: use posterior to predict all criterion values (marginalizing over z). Format into profile string. Call solver LLM with (x, profile).
4. Return solver output.

#### Design tradeoffs
- **Modularity vs. expressiveness:** Using a simple belief model (BLR) keeps inference tractable and sample-efficient but may underfit complex preference structures. More expressive models (neural) risk intractable posteriors without approximations.
- **Fixed budget T:** The system assumes a strict turn limit (e.g., 5). Strategies must be myopic (greedy) since planning beyond one step is intractable. This may be suboptimal but is necessary for scalability.
- **Solver decoupling:** Treating solver as black box simplifies the elicitation module but means the world model cannot influence the solver's internal reasoning—only the input profile. This limits end-to-end optimization but ensures compatibility with any model.

#### Failure signatures
- **Low adaptivity (<20%):** Posterior updates are uninformative—likely because world model correlations are weak or posterior collapses (e.g., all z have equal likelihood after observations). Check: Are P(v|c,z) sufficiently distinct across z? Is T too small for meaningful update?
- **Plateauing performance beyond T=3:** The world model may be too simple (e.g., linear BLR) to capture nonlinear interactions, causing each additional question to yield diminishing returns. Check: Ablate with more complex belief model.
- **Predicted profile inconsistent with responses:** The posterior predictive b_t(v|c) might assign high probability to values contradictory to observed criteria correlations. Check: Calibration of P(v|c,z,x); insufficient training data for some criteria.
- **High variance across runs:** Stochastic selection (Soft strategies) may cause instability if information gain estimates are noisy. Ensure enough posterior samples or deterministic scoring.

#### First 3 experiments
1. **Ablation: World model vs. no correlations.** Compare Pep (with latent) against a baseline that uses only independent priors b0(v|c) without z (i.e., no correlation learning). Expected: With adaptive selection, the correlated model should show steep improvement over turns, while the independent model plateaus near population average.
2. **Adaptive vs. random selection.** Fix the belief model (same world model) and compare information gain strategy against random criterion selection. Expected: Adaptive selection should achieve similar or better alignment with fewer queries, demonstrating the value of informed question choice.
3. **Pep vs. RL (GRPO) on query efficiency.** Measure how many queries GRPO needs to match Pep's alignment at T=5. Also measure adaptivity (Eq 13). Expected: Pep achieves target alignment with far fewer queries and higher adaptivity, confirming that the bottleneck is structural exploitation, not capacity.

## Open Questions the Paper Calls Out
1. **Extension to natural language elicitation**  
   - Basis: Conclusion states "Future work should extend to natural language elicitation, where questions and responses are free-form rather than structured over predefined criteria."  
   - Why unresolved: The current framework assumes structured preference dimensions with fixed sets of values; free-form questions and ambiguous responses are not addressed.  
   - Resolving evidence: Integrate an NLP module (e.g., LLM) to map free-form user responses to the latent space, evaluate on datasets with open-ended interactions, and compare alignment/efficiency.

2. **Automatic discovery of preference dimensions**  
   - Basis: Conclusion mentions "and to automatic discovery of preference dimensions from data."  
   - Why unresolved: Pep relies on manually defined criterion sets C(x), which may omit relevant dimensions or include irrelevant ones; automatically discovering dimensions would increase adaptability but is unexplored.  
   - Resolving evidence: Develop unsupervised or LLM-based methods to induce preference criteria from interaction logs, integrate with the world model, and test on tasks where the true criterion set is unknown or evolving.

3. **Longitudinal settings with evolving preferences**  
   - Basis: Limitations state: "We do not address longitudinal learning across sessions or helping users form preferences they have not yet considered."  
   - Why unresolved: Each task is treated as an independent cold-start problem, resetting the user embedding; real users have persistent but changing preferences across sessions.  
   - Resolving evidence: Extend belief model with a persistent user embedding that slowly adapts across sessions (hierarchical Bayesian modeling), conduct multi-session user studies tracking preference evolution, and measure adaptation speed, stability, and long-term alignment.

4. **Social bias in learned preference correlations**  
   - Basis: Limitations note: "it is crucial to ensure that the learned correlations do not encode or propagate social biases."  
   - Why unresolved: The offline model captures population-level correlations that may reflect societal biases (e.g., gender, cultural), potentially leading to unfair personalization for underrepresented groups; no analysis or mitigation is provided.  
   - Resolving evidence: Audit learned correlations for bias (e.g., between demographic proxies and criteria), apply bias mitigation techniques (adversarial debiasing, fairness constraints) during training, and evaluate fairness metrics across demographic groups.

5. **Robustness to non-passive user behaviors**  
   - Basis: [inferred] The paper uses passive user simulation and notes "real-world deployment would introduce additional challenges such as noisy, inconsistent, or evolving preferences." It also mentions "higher risks of reward hacking with collaborative users."  
   - Why unresolved: Evaluation assumes minimal, truthful answers; real users may be verbose, inconsistent, or strategic, which could degrade Pep's Bayesian updates and selection.  
   - Resolving evidence: Design experiments with varied user models (noisy responses, inconsistencies, strategic manipulation), measure performance degradation, and develop robustness techniques like response validation, inconsistency detection, or robust Bayesian updates.

## Limitations
- **Dataset reconstruction uncertainties:** Exact PrefDisco filtering thresholds (e.g., criteria prevalence cutoffs) and resulting user/criterion counts are unspecified, risking mismatched reconstruction.
- **LLM configuration ambiguity:** Solver and judge use GPT-4.1 but exact API version, temperature, and judge rubric are not documented, making exact score reproduction difficult.
- **Assumption sensitivity:** Pep assumes that a low-dimensional latent z suffices to capture preference correlations and that these correlations are stable across tasks; if preferences are highly task-specific or independent, gains may diminish.

## Confidence
- Mechanism 1 (structured world model captures correlations): Medium
- Mechanism 2 (Bayesian posterior updates drive adaptive questioning): Medium
- Mechanism 3 (RL fails due to sparse terminal reward): High

## Next Checks
1. Replicate world-model ablation: train offline model with and without latent correlations, compare alignment over interaction turns to confirm that factored structure yields faster improvement.
2. Isolate adaptive selection: fix belief model, replace information-gain with random criterion selection, measure query efficiency to demonstrate the value of informed question choice.
3. RL budget sweep: run GRPO with budgets from 1 to 8 turns, compute adaptivity and final alignment; verify that Pep reaches ≥95% of RL's best alignment using ≤1/3 of the queries.
