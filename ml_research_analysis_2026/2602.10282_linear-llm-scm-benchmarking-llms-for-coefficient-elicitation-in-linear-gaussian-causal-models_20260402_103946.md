# Linear-LLM-SCM: Benchmarking LLMs for Coefficient Elicitation in Linear-Gaussian Causal Models

## Quick Facts
- **ArXiv ID**: 2602.10282  
- **Source URL**: https://arxiv.org/abs/2602.10282  
- **Reference count**: 27  
- **Primary result**: The Linear-LLM-SCM benchmark finds that Gemini 2.5 Flash most accurately elicits linear-Gaussian causal coefficients, but larger models suffer from high stochasticity and sensitivity to structural misspecifications.

## Executive Summary
The paper presents Linear-LLM-SCM, a novel framework for evaluating large language models on quantitative causal reasoning in continuous domains. Given a pre-specified directed acyclic graph (DAG), the framework decomposes it into local parent-child sets, prompts an LLM to produce linear regression coefficients for each node, and aggregates the results to compare with known ground-truth parameters. This approach isolates the LLM’s ability to translate semantic descriptions into numeric causal effects.

In experiments across seven real-world causal graphs, the authors assess models including Gemini 2.5 Flash and Llama 3 variants using scale-invariant metrics such as normalized L2 distance (M3) and effect size ordering match (M4). Gemini 2.5 Flash achieves the best performance, yet larger models display significant stochasticity even at zero temperature. Additional robustness tests reveal that spurious edges and unit changes cause severe degradation, as LLMs fail to suppress coefficients on irrelevant connections. The study highlights both the potential and current limitations of LLMs for precise causal parameterization.

## Method Summary
Although no reproduction notes were provided, the Linear-LLM-SCM framework can be summarized as follows. For a given DAG and variable definitions, the system iterates over each node, identifies its parent nodes, and constructs a natural language prompt that describes the node and its parents, asking the LLM to output a linear equation with coefficients. The LLM’s response is parsed into numeric values. After processing all nodes, the set of elicited coefficients is compared against the true parameters from the underlying linear-Gaussian SCM using several metrics, including absolute error (M2), normalized multi-parent L2 error (M3), and ordering agreement of effect sizes (M4). This modular prompt-based design enables evaluation of off-the-shelf LLMs without fine‑tuning.

## Key Results
- Gemini 2.5 Flash attains the lowest normalized errors (M3) and highest effect size ordering accuracy (M4), outperforming Llama 70B and Llama 8B across most DAGs.  
- Larger LLMs (Gemini, Llama 70B) exhibit high stochasticity in coefficient estimates even when temperature is set to zero, while the smaller Llama 8B yields consistent but less accurate results.  
- Introducing spurious edges into the DAG or changing measurement units leads to substantial performance drops; LLMs often assign non‑zero coefficients to irrelevant edges, indicating poor robustness to structural noise and lack of unit invariance.

## Why This Works (Mechanism)
The decomposition of the global regression task into local conditional regressions aligns with the conditional independence structure encoded in the DAG. Each prompt focuses the LLM on a single equation, reducing the complexity of having to infer the full joint model. The LLM’s pre‑training on vast text and code corpora likely includes exposure to scientific formulas and domain knowledge, enabling it to map textual descriptions of variables to approximate numeric relationships. By asking for explicit coefficients, the framework directly probes this mapping. The aggregation step then reconstructs the full SCM, allowing a comparison to ground truth. This design effectively isolates the LLM’s semantic‑to‑numerical reasoning within a well‑defined statistical scaffold.

## Foundational Learning
- **Linear‑Gaussian SCM**  
  *Why needed*: Provides a mathematically tractable setting where ground‑truth coefficients are defined and enable closed‑form evaluation.  
  *Quick check*: Given a DAG and linear equations, derive the covariance matrix using d‑separation and linear algebra.  

- **Directed Acyclic Graph (DAG)**  
  *Why needed*: Encodes the causal structure; decomposition relies on identifying parent sets for each node.  
  *Quick check*: Confirm that the graph A → B ← C is acyclic and identify colliders.  

- **Prompt Engineering for Numeric Output**  
  *Why needed*: The LLM must produce parseable numbers; prompt phrasing strongly influences whether the model responds with a clean equation.  
  *Quick check*: Prompt “Write a linear equation: y = a*x + b” and verify the response contains numeric placeholders.  

- **Scale‑Invariant Evaluation Metrics (M3, M4)**  
  *Why needed*: Raw coefficient errors depend on arbitrary units; normalization allows fair comparison across domains and models.  
  *Quick check*: For true coefficients (1, 2) and predictions (0.5, 1), compute normalized L2 error: true norm = √(1²+2²)=√5, error = √(0.5²+1²)=√1.25, M3 = √1.25/√5 ≈ 0.5.

## Architecture Onboarding
**Component map**: DAG Input -> Parent Set Extractor -> Prompt Generator -> LLM Interface -> Response Parser -> Coefficient Aggregator -> Evaluation Module  

**Critical path**: The pipeline processes each node sequentially: extract parents → generate prompt → query LLM → parse coefficients → store. After all nodes, aggregator assembles the full parameter set and evaluation computes metrics. The LLM query is the longest latency step; failures in parsing or repeated LLM retries can cause blockage.  

**Design tradeoffs**: Local prompts reduce cognitive load on the LLM but prevent it from correcting inconsistencies across equations (e.g., ensuring a parent’s effect is consistent across its children). Using a black‑box LLM provides flexibility but introduces stochasticity and cost; a fine‑tuned deterministic model could improve consistency but reduces portability. The framework emphasizes broad applicability over optimization for any single domain.  

**Failure signatures**:  
- LLM returns verbose text without a clear equation.  
- Coefficients are non‑numeric or missing.  
- High variance across repeated queries indicates API nondeterminism or model instability.  
- When spurious edges are present, the LLM often assigns non‑zero coefficients instead of near‑zero, signaling structural overfitting.  

**First three experiments**:  
1. **Baseline sanity check**: Use a toy DAG (e.g., X → Y → Z) with known coefficients (1, 2) to validate that the pipeline correctly elicits them from the LLM.  
2. **Spurious edge test**: Add an extra edge X → Z and verify whether the LLM assigns a coefficient close to zero; if not, quantify the bias.  
3. **Stability measurement**: Query the same parent‑child relationship 25 times at zero temperature and compute the sample variance of the elicited coefficient to assess determinism across models.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can LLMs be made robust to structural misspecifications (e.g., spurious edges) in causal graphs?  
- **Basis in paper**: [explicit] "we do not address how to mitigate this LLMs' susceptibility to perturbations, which we leave as future work" and "Models struggle to assign zero or near-zero coefficients to these edges, indicating a lack of robustness to DAG structural uncertainty."  
- **Why unresolved**: The study only benchmarks the issue; no mitigation strategies are investigated.  
- **What evidence would resolve it**: Demonstration of prompt engineering, fine-tuning, or architectural modifications that maintain coefficient accuracy when extra edges are introduced.

### Open Question 2
- **Question**: Can LLMs accurately parameterize non-linear continuous SCMs given only the DAG structure and variable semantics?  
- **Basis in paper**: [explicit] "Our framework currently assesses linear-Gaussian models and is limited by its linear assumption. Future research should extend these benchmarks to non-linear functional forms."  
- **Why unresolved**: Linear models allow ground-truth parameterization from literature; non-linear ground truths for real domains are not easily available or verifiable.  
- **What evidence would resolve it**: A benchmark with non-linear SCMs (e.g., polynomial, sigmoid) where ground-truth functions are derived from domain equations or validated simulations, showing LLMs can elicit correct functional forms.

### Open Question 3
- **Question**: Why do state-of-the-art LLMs exhibit high stochasticity in coefficient estimation even at zero temperature?  
- **Basis in paper**: [explicit] "larger models (Gemini 2.5 Flash, Llama 3.3 70B) exhibit high stochasticity across metrics, with non-Gaussian distributions at n=25 samples, possibly due to hardware and software factors beyond our control via external APIs."  
- **Why unresolved**: The paper observes the phenomenon but cannot isolate its source due to reliance on external APIs; the root cause (e.g., MoE routing, parallelism) remains unknown.  
- **What evidence would resolve it**: Controlled experiments on open-weight models with deterministic inference settings, systematically varying architecture (MoE vs dense) and implementation details to identify causes.

### Open Question 4
- **Question**: What architectural modifications are necessary for LLMs to perform reliable quantitative causal reasoning?  
- **Basis in paper**: [explicit] "...what kind of architectural changes are required toward robust intelligence capable of quantitative causal reasoning" and "Low deterministic model (Llama 8B) is consistent but less accurate."  
- **Why unresolved**: The study only evaluates off-the-shelf models; no model architectures are modified or compared.  
- **What evidence would resolve it**: Ablation studies comparing base LLMs with specialized heads for numerical consistency, or training objectives that enforce causal constraint compliance, measuring improvements in both accuracy and determinism.

### Open Question 5
- **Question**: Are LLMs' coefficient estimates invariant under realistic unit transformations (e.g., micromolar to nanomolar) across diverse domains?  
- **Basis in paper**: [explicit] "We also admit the empirical coverage for the unit tweaking is limited and will plan to scale into different unit specifications in different DAGs" and the experiment on only one DAG showed mixed results.  
- **Why unresolved**: Only one DAG (Cachexia1) was tested with a single unit conversion; patterns may not generalize.  
- **What evidence would resolve it**: Systematic evaluation on multiple DAGs with various unit conversions (e.g., length, mass, time), measuring whether normalized metrics (M2-M4) remain stable.

## Limitations
- Evaluation on only seven real‑world DAGs limits statistical power and the generalizability of model comparisons.  
- The model set is narrow, omitting other leading LLMs (e.g., GPT‑4, Claude), which may affect performance rankings.  
- Scale‑invariant metrics (M3, M4) ignore absolute coefficient error, possibly obscuring practical utility for precise estimation.

## Confidence
- **Linear‑LLM‑SCM as a valid benchmark**: Medium  
- **Gemini 2.5 Flash outperforms others**: Medium  
- **Larger models show greater stochasticity**: Medium  
- **Sensitivity to DAG misspecification**: High  

## Next Checks
1. Expand evaluation to at least 30 diverse DAGs (synthetic and real) to test the generalizability of model rankings and increase statistical robustness.  
2. Perform a systematic prompt ablation study: vary instructions, few‑shot examples, and phrasing to quantify prompt sensitivity and derive a robust elicitation template.  
3. Conduct a controlled edge‑noise experiment: inject spurious edges at increasing probabilities (0–50%) and measure both normalized (M3, M4) and absolute error metrics, focusing on the ability to assign near‑zero coefficients to irrelevant edges.
