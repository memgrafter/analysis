# TensorLens: End-to-End Transformer Analysis via High-Order Attention Tensors

## Quick Facts
- arXiv ID: 2601.17958
- Source URL: https://arxiv.org/abs/2601.17958
- Reference count: 40
- Primary result: TensorLens unifies the Transformer as a high-order tensor, outperforming prior aggregation methods in perturbation tests (e.g., AUC 0.084 for DeiT-Base, 0.158 for BERT) and matching/exceeding LRE on relation decoding.

## Executive Summary
TensorLens addresses the lack of a unified representation for the entire Transformer model. Prior work aggregated only individual attention matrices or partial components. The key insight is to express each sub-component (self-attention, LayerNorm, FFN, residual) as a 4th-order tensor using vectorization operations, then compose them into a single high-order attention tensor that jointly encodes all operations. This tensor acts as an input-dependent linear operator approximating the full forward pass, enabling new types of analysis via matrix collapsing. Extensive experiments on vision (DeiT) and NLP (BERT, RoBERTa, Pythia) models show TensorLens surpasses prior aggregation methods in perturbation-based relevance scoring and more accurately captures linear relation decoding, demonstrating its richer representation and theoretical soundness.

## Method Summary
TensorLens formulates the full Transformer as a single input-dependent linear operator. Starting from standard Transformer equations, each block’s operations (self-attention, LayerNorm, FFN, residual) are vectorized into 4th-order tensors via Kronecker products and diagonal encodings. For a post‑layernorm block, the block tensor is composed as Tⁿ = L₂ⁿ (Mⁿ + I) L₁ⁿ (Aⁿ + I), where A, L, M are the tensorized attention, LayerNorm, and FFN respectively. Across N layers, these block tensors are multiplied to yield the full model tensor T ∈ ℝ^{L×D×L×D} such that vec[F(X)] = T vec[X] + b. For analysis, T can be collapsed into 2D matrices (e.g., T^{IO}) to compute input token relevances via row sums, or used directly for linear relation decoding by averaging tensors from few‑shot examples.

## Key Results
- Outperforms prior aggregation methods in perturbation tests across vision (DeiT) and NLP (BERT, RoBERTa), achieving higher AUC scores (e.g., 0.084 for DeiT‑Base, 0.158 for BERT).
- More accurately approximates linear relation decoding in LLMs compared to baselines, demonstrating richer model representation.
- Provides a theoretically grounded, unified tensor formulation that jointly encodes attention, FFNs, normalization, and residual connections.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The entire Transformer can be represented as a single input-dependent linear operator via a high-order attention tensor.
- **Mechanism:** Each sub-component (self-attention, LayerNorm, FFN, residual) is expressed as a tensor-based linear operator using vectorization rules (Kronecker products, diagonal tensors). These sub-component tensors are composed per-block (Eq. 17) and across layers (Eq. 19) to form a unified 4th-order tensor **T** ∈ ℝ<sup>L×D×L×D</sup>.
- **Core assumption:** The Transformer’s non-linear operations (softmax, GELU) can be locally approximated as linear transformations on a given input, enabling exact Jacobian-based tensorization.
- **Evidence anchors:**
  - [abstract] "formulates the full Transformer as a single input-dependent linear operator using a high-order attention tensor that jointly encodes attention, FFNs, normalization, and residual connections."
  - [section 3.2] Detailed derivations show how each layer’s operations are vectorized into tensor forms (e.g., Eq. 9 for attention, Eq. 14 for FFN).
  - [corpus] Corpus shows related work on tensor-based attention (e.g., "Kronecker attention networks", "tensor product attention") but not a unified formulation for all Transformer blocks; TensorLens is presented as filling this gap.
- **Break condition:** If a sub-component’s linearization (e.g., activation function in Eq. 13) deviates significantly from the actual non-linear behavior for specific inputs, the tensor will poorly approximate the true forward function.

### Mechanism 2
- **Claim:** The high-order tensor representation provides a more faithful proxy for the model’s internal computations than prior attention aggregation methods.
- **Mechanism:** By capturing cross-channel (within-token) and cross-token interactions simultaneously, the tensor encodes more model parameters (including FFNs, embeddings) than matrix-based aggregations (e.g., attention rollout). Perturbation relevance scores derived from the tensor more accurately reflect token importance.
- **Core assumption:** Higher-resolution representation (4th-order tensor vs. 2nd-order matrices) correlates with better alignment to model behavior, measurable via perturbation tests.
- **Evidence anchors:**
  - [section 4.1] Figures 3, 4, 6, 7 show TensorLens variants achieve higher AUC scores than all baselines (e.g., DeiT‑Base AUC 0.084 vs. best baseline 0.059; BERT AUC 0.158 vs. best baseline 0.089).
  - [abstract] "TensorLens outperforms prior aggregation methods in perturbation tests... achieving higher AUC scores."
  - [corpus] Corpus includes papers on attribution methods (e.g., AttnLRP, XAI for transformers) but none use a full tensor formulation; TensorLens’s performance edge is empirically shown against these.
- **Break condition:** For architectures or tasks where cross-channel interactions are negligible (e.g., certain decoder‑only LMs on next‑token prediction), the tensor’s additional complexity may not yield proportional gains (as seen in Table 1 for decoder‑only models).

### Mechanism 3
- **Claim:** The tensor formulation enables better approximation of linear relation decoding in LLMs compared to matrix-based Jacobian methods.
- **Mechanism:** The tensor **T** directly defines a multi-linear map between input and output token‑channel pairs. Mean tensors computed from few‑shot examples (Eq. 26) can approximate the model’s transformation for specific relations more accurately than linear approximations from intermediate states (LRE).
- **Core assumption:** Linear relation decoding efficacy is a valid probe for how well a representation captures model‑internal knowledge circuits.
- **Evidence anchors:**
  - [section 4.2] Figure 5 shows TensorLens matches or exceeds LRE accuracy across bias, common sense, and factual relation categories on Pythia‑1B.
  - [abstract] "It also more accurately approximates linear relation decoding in LLMs compared to baselines, demonstrating richer model representation."
  - [corpus] Related work (Hernandez et al., 2024) proposes LRE; TensorLens is benchmarked directly against it in the paper.
- **Break condition:** If the relation requires highly non‑linear pathways or involves deeper multi‑step reasoning beyond a single linear transformation, both tensor and LRE may fail, but the tensor’s higher order may still capture more nuance.

- **Concept:** Tensor Algebra & Vectorization (Kronecker products, vec operator, tensor contractions).

- **Concept:** Transformer Architecture Internals (self‑attention, LayerNorm, FFN, residual connections, pre/post‑layernorm variants).
  - *Why needed here:* To understand how each component is "tensorized" (Section 3.2) and composed (Eq. 17), one must know the standard equations being transformed.
  - *Quick check question:* In a post‑layernorm block, what is the order of operations for attention, residual, LayerNorm, and FFN?

- **Concept:** Linear Operator Approximation & Jacobians.

  - *Quick check question:* If F(X) is non‑linear, what does the Jacobian matrix J<sub>F</sub>(X) represent, and how does it relate to a first‑order Taylor approximation?

## Architecture Onboarding
- Component map: Input X<sup>(0)</sup> ∈ ℝ<sup>L×D</sup> → embedding layer (tensorized as part of full model via E<sub>in</sub> in Eq. 24). Each Transformer block *n* → block tensor T<sup>(n)</sup> (Eq. 17 for post‑layernorm). Sub‑components: Attention → tensor **A** (Eq. 9); LayerNorm → tensor **L** (Eq. 11); FFN → tensor **M** (Eq. 14); Residual → I+G (Eq. 16). Full model → composition T = Π<sub>n=1</sub><sup>N</sup> T<sup>(n)</sup> (Eq. 19). Output → projection via E<sub>out</sub> for class‑specific maps (Eq. 24).
- Critical path: The mathematical derivation chain: vectorization rules (Section 3.1) → per‑subcomponent tensorization (Section 3.2) → block composition (Eq. 17) → full model composition (Eq. 19). Misunderstanding any step breaks the unified view.
- Design tradeoffs:
  - *Expressivity vs. Memory:* Full 4D tensor (L²D² elements) is prohibitively large; practical use requires slicing (Appendix C) or collapsing (Section 3.5).
  - *Precision vs. Simplicity:* Tensorization of activations uses a simple ratio decomposition (Eq. 13); more sophisticated linearizations could yield tighter bounds but increase complexity.
  - *Generality vs. Architecture Specificity:* Derivation assumes standard Transformer blocks; modifications (e.g., parallel residuals in some LLMs) require adaptation (GlbEnc inapplicable per Table 1).
- Failure signatures:
  - Numerical instability in LayerNorm bound (Eq. 33) if input variance ξ(LN,X) is very small (e.g., near‑zero variance tokens).
  - Poor perturbation AUC on decoder‑only models (Table 1) suggests the tensor may be less informative for auto‑regressive, locally‑focused computations.
  - Collapsing the tensor via norm or projection (Section 3.5) may discard critical channel interactions if the chosen projection (X<sup>0</sup>, X<sup>N</sup>) is uninformative.
- First 3 experiments:
  1. **Reproduce tensor shapes:** For a small Transformer (e.g., 2 layers, L=16, D=64, H=4), compute **A**, **M**, **L** tensors for a random input and verify dimensions (Eqs. 9, 14, 11). Check that T<sup>(1)</sup> composition (Eq. 17) matches the block’s Jacobian.
  2. **Compare aggregation methods:** On a pre‑trained DeiT‑Base, compute "Tensor,In+Out" and baseline "W‑AttnResLN, Rollout" relevance maps. Perform a small‑scale perturbation test (masking 0‑10% of patches) and reproduce the AUC gap shown in Figure 3.
  3. **Relation decoding replication:** Using Pythia‑1B and the provided relation sets (bias, common sense, factual), compute mean tensor from *m*=3 examples (Eq. 26) and evaluate top‑1 accuracy against original model outputs. Compare against LRE baseline as in Figure 5.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** How does the linearization of activation functions (currently using element‑wise ratio ϕ(X)/X) affect the fidelity of the tensor representation? Could alternative tensorization schemes, such as higher‑order Taylor expansions, yield a more accurate model approximation?
- **Basis in paper:** [inferred] The authors note that "some of the linearization techniques are chosen for their simplicity rather than being derived from the intrinsic properties of optimally approximated tensors," specifically citing the activation decomposition in Eq. 13.
- **Why unresolved:** The impact of this simplification on representation quality is not evaluated; it may be suboptimal for certain activations or input regions.
- **What evidence would resolve it:** Compare different activation tensorizations on perturbation tests and relation decoding tasks, measuring improvements in AUC or accuracy.

### Open Question 2
- **Question:** Can low‑rank tensor decompositions (e.g., CP, Tucker) provide memory‑efficient approximations of the full 4th‑order tensor without significant loss in performance? What are the accuracy‑memory trade‑offs?
- **Basis in paper:** [inferred] The paper cites GPU memory limitations as constraining experiments to ≤1B parameters and proposes only a memory‑optimized computation, not compression.
- **Why unresolved:** Full tensor storage scales as O(L²D²), becoming prohibitive for large models/long contexts; compression could extend applicability but risks information loss.
- **What evidence would resolve it:** Apply varying compression levels, evaluate on standard benchmarks (perturbation AUC, relation decoding), and measure performance relative to memory savings.

### Open Question 3
- **Question:** How do tensor properties (e.g., mode ranks, sparsity) evolve during Transformer training, and can they predict or explain phenomena like rank collapse, generalization, or emergent capabilities?
- **Basis in paper:** [explicit] The authors state that TensorLens "opens the door to new perspectives on rank collapse, sparsity, and training dynamics through the lens of tensor properties" but provide no analysis.
- **Why unresolved:** No experiments track tensor statistics across training; the relationship between tensor structure and dynamics remains unexplored.
- **What evidence would resolve it:** Monitor tensor ranks/norms across training checkpoints for various models, correlate with loss curves, accuracy, and benchmark performance.

### Open Question 4
- **Question:** What model computations inherently require non‑linear descriptions that the current linear tensor fails to capture? How can the formulation be extended to incorporate such non‑linearities?
- **Basis in paper:** [inferred] The paper reports near‑random accuracy on some relations (e.g., occupation‑age), attributing it to "the inherent limitation of describing the model’s internal processes solely via linear transformations."
- **Why unresolved:** The scope of linear approximation failures is unknown; effective non‑linear extensions are not proposed.
- **What evidence would resolve it:** Analyze failure cases to characterize required non‑linearities, then develop polynomial or neural tensor enhancements and test on those relations.

### Open Question 5
- **Question:** Why are perturbation evaluations less conclusive for autoregressive decoder models, and how should TensorLens be adapted for causal attention architectures?
- **Basis in paper:** [inferred] The authors note decoder‑only models show "less clear‑cut" results, speculating that autoregressive training leads to local behavior, making perturbations less informative.
- **Why unresolved:** Causal masking likely alters tensor structure and perturbation effects; the current formulation may not be optimal for decoders.
- **What evidence would resolve it:** Compare tensor properties between encoder and decoder models; design perturbation metrics respecting causality and evaluate on decoder‑specific interpretability tasks.

## Limitations
- Memory and computational requirements: Full O(L²D²) tensor is infeasible for large models/long sequences; requires slicing or approximation, which may lose information.
- Linearization approximations: Simple ratio decomposition for activations and softmax may degrade fidelity for extreme inputs or deep stacks.
- Architecture generality: Formulation assumes post‑layernorm blocks; gains are smaller for decoder‑only and parallel‑residual models.
