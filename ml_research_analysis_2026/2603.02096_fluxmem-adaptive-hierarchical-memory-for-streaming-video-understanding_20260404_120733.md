# FluxMem: Adaptive Hierarchical Memory for Streaming Video Understanding

## Quick Facts
- **arXiv ID:** 2603.02096
- **Source URL:** https://arxiv.org/abs/2603.02096
- **Reference count:** 40
- **Primary result:** Achieves state-of-the-art streaming video understanding (76.4 on StreamingBench, 67.2 on OVO-Bench real-time) while reducing latency by 69.9% and peak GPU memory by 34.5% by discarding 65% of visual tokens without any model training.

## Executive Summary
FluxMem is a training-free framework for efficient real-time streaming video understanding. It addresses visual token explosion in multimodal large language models (MLLMs) by adaptively pruning redundant information across temporal and spatial dimensions. Using a hierarchical memory system with two core modules—Temporal Adjacency Selection (TAS) and Spatial Domain Consolidation (SDC)—it removes redundant tokens based on per-frame statistics derived via Otsu's method. This design maintains strong accuracy on online and offline benchmarks while drastically cutting computational costs.

## Method Summary
FluxMem processes streaming video frames through a hierarchical memory cascade. Visual tokens first enter a short-term buffer. When overflow occurs, the Temporal Adjacency Selection (TAS) module compares tokens in the current frame to local 3x3 neighborhoods in adjacent (past and future) frames, computing cosine distances. Otsu's method separately thresholds backward and forward scores to identify tokens with significant change, which are passed to mid-term memory. When mid-term memory overflows, the Spatial Domain Consolidation (SDC) module builds a sparse 8-connected graph on TAS-retained tokens based on pairwise spatial similarity, again thresholded by Otsu. Connected components are merged into a single mean anchor token for long-term storage. A proactive trigger, reusing TAS backward scores, detects scene switches to initiate responses. All thresholds are set automatically per frame without training.

## Key Results
- **Efficiency:** Reduces latency by 69.9% and peak GPU memory by 34.5% on OVO-Bench real-time evaluation.
- **Accuracy:** Achieves 76.4 on StreamingBench and 67.2 on OVO-Bench (real-time), setting new state-of-the-art for online video understanding.
- **Compression:** Discards 65% of visual tokens on the offline MLVU benchmark while maintaining competitive performance (73.1).

## Why This Works (Mechanism)

### Mechanism 1: Temporal Adjacency Selection (TAS)
- **Claim:** TAS reduces temporal redundancy by selectively retaining tokens that exhibit significant change compared to adjacent frames, preserving causal temporal dynamics without future access.
- **Mechanism:** For each token at (h,w) in frame *t*, compute minimum cosine distance to a 3x3 spatial window in the previous and next frame (Eqs. 1-2). Apply Otsu’s method separately to backward (s⁻) and forward (s⁺) score distributions to derive per-frame thresholds Θ⁻ and Θ⁺. A token is kept if its score exceeds *either* threshold.
- **Core assumption:** Spatially local changes (within 3x3) reliably indicate meaningful temporal variation; a single global threshold per frame suffices to separate redundant from novel content based on the distribution of local distances.
- **Evidence anchors:** [section 3.2] Details the TAS algorithm, including the 3x3 window, dual-threshold approach, and causal operation. [abstract] States TAS "removes temporally redundant tokens across adjacent frames" and uses "Otsu's method to set per-frame thresholds automatically." [corpus] Neighboring papers (e.g., StreamMem, HERMES) explore temporal token reduction but differ in approach; FluxMem’s specific use of Otsu for dual thresholds is a novel combination.
- **Break condition:** If scene motion is highly non-local (e.g., large pans), the 3x3 window may miss semantically significant changes. If the score distribution is unimodal, Otsu’s threshold may be arbitrary, leading to over- or under-pruning.

### Mechanism 2: Spatial Domain Consolidation (SDC)
- **Claim:** SDC merges spatially repetitive regions within a frame by grouping nearby retained tokens into components and replacing each with a mean anchor, reducing spatial redundancy while preserving local structure.
- **Mechanism:** On tokens retained by TAS, build a sparse 8-connected graph linking tokens within 3x3 spatial neighborhoods if their cosine distance ≤ Θₜ (Otsu-derived from pairwise spatial distances). Apply union-find to find connected components {Cₜ,ₖ}. Replace each component with its barycentric mean aₜ,ₖ.
- **Core assumption:** Spatially coherent, visually similar regions can be summarized by a single representative token without significant loss for downstream LLM understanding; a graph built on pre-filtered tokens is sufficiently sparse for efficient union-find.
- **Evidence anchors:** [section 3.2] Describes SDC’s graph construction, union-find, and anchor creation. [abstract] Notes SDC "merges spatially repetitive regions within frames into compact representations." [corpus] Related works (e.g., Token Merging) perform spatial merging but often use fixed ratios; FluxMem’s use of Otsu on pairwise distances within the TAS-filtered set is a specific design choice.
- **Break condition:** For textures or fine-grained patterns (e.g., grass), a single mean anchor may oversimplify and lose discriminative details. If Otsu’s threshold fails to separate coherent regions, merging may combine semantically distinct objects.

### Mechanism 3: Hierarchical Memory with Adaptive Thresholding
- **Claim:** The hierarchical cascade (short-term → mid-term via TAS → long-term via SDC) progressively compresses tokens while respecting causality and preserving both short-term detail and long-term context; Otsu-based adaptive thresholds automatically adjust compression strength to scene dynamics.
- **Mechanism:** Short-term memory (S) stores all recent frames. Overflow triggers TAS, whose output goes to mid-term memory (M). M overflow triggers SDC, whose anchors go to long-term memory (L). Thresholds Θ⁻, Θ⁺ (TAS) and Θₜ (SDC) are computed per-frame from score distributions via Otsu, eliminating manual tuning.
- **Core assumption:** Different temporal windows have distinct redundancy characteristics: recent frames need minimal pruning (S), medium-horizon frames have temporal redundancy best addressed by TAS (M), and long-horizon frames accumulate spatial redundancy best addressed by SDC (L). The distributions of similarity scores within each stage are bimodal enough for Otsu to find effective cutoffs.
- **Evidence anchors:** [section 3.1] Defines the three memory levels and cascaded overflow process. [section 3.3] Explains Otsu’s method for threshold selection. [section 4.5] Ablation (Table 4, Fig 3) shows full S+M+L hierarchy achieves best accuracy (71.6) with 64.3% token drop, and adaptive thresholds yield better drop-accuracy trade-offs than fixed thresholds. [corpus] StreamMem and HERMES propose hierarchical KV cache memory but with different partitioning; FluxMem’s two-stage token dropping (TAS then SDC) with Otsu thresholds is novel.
- **Break condition:** If video dynamics are extremely uniform (e.g., static camera), Otsu may prune too little. Conversely, in chaotic scenes, thresholds may prune too aggressively. Fixed capacity allocations (cₛ, cₘ, cₗ) may not suit all video lengths or query types.

## Architecture Onboarding
- **Component map:** Input frames -> Vision Encoder -> tokens -> Short-term Memory (S) -> (overflow) -> TAS -> Mid-term Memory (M) -> (overflow) -> SDC -> Long-term Memory (L) -> concatenated memory + query -> LLM -> response. Proactive trigger runs at S push using precomputed backward scores.
- **Critical path:** Frame → Vᵗ → Mₛ → (overflow) → TAS → Iₘᵗ → Mₘ → (overflow) → SDC → Aₗᵗ → Mₗ → LLM.
- **Design tradeoffs:**
  - *Training-free vs. SFT:* No training preserves base MLLM knowledge and enables plug-and-play use, but may underfit to specific domains compared to SFT (Table 5 shows SFT adds ~11% on OVO-Bench).
  - *Hierarchical vs. Monolithic:* Hierarchical preserves recent detail (S) while compressing history (M/L), but introduces complexity and fixed capacities that may not adapt to variable video lengths.
  - *Adaptive vs. Fixed Thresholds:* Adaptive (Otsu) handles dynamic scenes without tuning but relies on bimodal score distributions; fixed thresholds are simpler but brittle across content.
- **Failure signatures:**
  - High drop ratio (>85%) with performance drop: (Fig 3(a)) indicates over-pruning; likely thresholds too low due to poor score distribution (e.g., very static scenes where Otsu picks degenerate threshold).
  - Poor performance on high-motion tasks: (e.g., Action Recognition in Table 1) could indicate TAS failing to capture large motions due to 3x3 window limitation or Otsu threshold too high.
  - Memory not decreasing as expected: Check if Otsu is producing thresholds near 0 or 1; verify score computation (cosine distance) and distribution statistics.
- **First 3 experiments:**
  1. **Ablation of memory hierarchy:** Disable TAS or SDC or both (Table 4) to confirm each stage’s contribution to accuracy and token reduction. Expect full S+M+L to be best; removing M or L should reduce accuracy or increase tokens.
  2. **Adaptive vs. fixed threshold comparison:** Run with Otsu thresholds vs. manually tuned fixed thresholds across a set of videos (Fig 3(b,c)). Expect adaptive to achieve similar/better accuracy at higher drop ratios, demonstrating robustness.
  3. **Per-module efficiency break-even:** Measure per-frame overhead of TAS and SDC (ms) and ensure total < frame interval (e.g., 1000ms for 1 fps). Paper reports 4.1ms total overhead, confirming real-time feasibility.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can adaptive thresholding methods other than Otsu’s improve token reduction while preserving accuracy?
- **Basis in paper:** Section 3.3 adopts Otsu’s method for its non-parametric nature but does not compare against other thresholding schemes.
- **Why unresolved:** Without empirical comparison, it is unclear whether Otsu’s is optimal for separating redundant tokens across diverse video dynamics.
- **What evidence would resolve it:** Evaluate alternative threshold selection approaches (e.g., mixture models, learned thresholds) on MLVU and StreamingBench; report accuracy and compression ratios.

### Open Question 2
- **Question:** Do fixed memory capacities (c_s, c_m, c_l) suffice for all streaming videos, or should they adapt to video-specific statistics?
- **Basis in paper:** Section 3.1 defines capacities as fixed, and Section 4.1 manually sets them (e.g., 8, 64) without adaptation.
- **Why unresolved:** Different video lengths, motion levels, and content complexities might require different memory allocations to maintain performance and efficiency.
- **What evidence would resolve it:** Design a dynamic capacity allocation mechanism (e.g., based on scene change frequency) and compare against fixed capacities on multiple benchmarks.

### Open Question 3
- **Question:** Is the simple ratio-based trigger (r_t > γ) sufficient for proactive responses, or could richer temporal cues improve responsiveness?
- **Basis in paper:** Section 3.2 uses r_t derived from TAS scores with a manually tuned γ; no alternative triggers are studied.
- **Why unresolved:** The trigger may be sensitive to γ and might fail to capture subtle scene switches; other indicators may yield more reliable proactivity.
- **What evidence would resolve it:** Propose and evaluate different proactive triggers (e.g., using change point detection or learned classifiers) on OVO-Bench’s proactive tasks.

### Open Question 4
- **Question:** Does FluxMem’s training-free design generalize to other MLLMs besides Qwen2.5-VL?
- **Basis in paper:** All experiments (Sections 4.2–4.5) are conducted with Qwen2.5-VL only; plug-and-play claim is not tested on other models.
- **Why unresolved:** Different MLLMs have varying token distributions, attention patterns, and may respond differently to token reduction.
- **What evidence would resolve it:** Implement FluxMem with at least two other state-of-the-art MLLMs (e.g., InternVL2.5, LLaVA-Video) and measure performance on standard online/offline benchmarks.

## Limitations
- **Causal integrity in TAS:** The algorithm computes forward scores `s⁺` using frame `t+1`. In strict online streaming, `t+1` may be unavailable when processing `t`; implementation may buffer one frame, potentially violating "no future access" claims.
- **Otsu’s bimodality assumption:** Both TAS and SDC rely on Otsu finding a threshold between "redundant" and "novel" score peaks. In uniform or chaotic scenes, distributions may be unimodal, causing arbitrary thresholds that over/under-prune.
- **Capacity semantics ambiguity:** Paper gives frame counts (e.g., `cₛ=8, cₘ=64` online), but token budgets depend on per-frame token count (256 online, 64 offline) and SDC’s merging. Exact token counts per memory level and overflow logic conversion are unclear.
- **Proactive trigger sensitivity:** The scene-switch detection uses a tunable `γ` (fraction of tokens above `Θ⁻`). No default or optimal value is provided, making real-time results sensitive to this unseen hyperparameter.
- **Generalization scope:** Experiments only use Qwen2.5-VL-7B. Claims about plug-and-play use may not hold for other vision encoders/LLMs with different token distributions.
