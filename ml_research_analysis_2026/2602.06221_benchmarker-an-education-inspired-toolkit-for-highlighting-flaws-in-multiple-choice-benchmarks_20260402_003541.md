# BenchMarker: An Education-Inspired Toolkit for Highlighting Flaws in Multiple-Choice Benchmarks

## Quick Facts
- arXiv ID: 2602.06221
- Source URL: https://arxiv.org/abs/2602.06221
- Reference count: 40
- Primary result: BenchMarker audits reveal critical flaws in MCQA benchmarks: 47% TruthfulQA contaminated, 100% HellaSwag violates writing rules, 21% ScholarIQA has shortcuts, with writing errors most materially impacting LLM rankings.

## Executive Summary
Multiple-choice question answering (MCQA) benchmarks are central to LLM evaluation but often suffer from contamination (memorizable items), shortcuts (shallow cues), and writing errors that undermine construct validity. This paper presents BenchMarker, an education-inspired toolkit that automates flaw detection using LLM judges and a 19-rule item-writing rubric. Validated against 8042 human judgments across 23 models and 13 datasets, BenchMarker audits 12 NLP benchmarks, quantifying flaw prevalence and their impact on model scores. Key findings include widespread contamination in TruthfulQA (47%) and universal writing rule violations in HellaSwag (100%). The toolkit shows that writing errors are particularly detrimental, altering model rankings beyond random chance. BenchMarker achieves strong human agreement (e.g., GPT-5 Cohen’s κ=0.606 for shortcuts) and is released to foster more robust benchmark design.

## Method Summary
BenchMarker employs three independent detectors. For contamination, it queries a web search API with the question stem and correct answer, then uses an LLM judge to flag exact or partial matches online, assuming web presence implies likely inclusion in LLM training data. For shortcuts, it prompts an LLM to answer using only the choices, then infer the original question; a shortcut is signaled if the model answers correctly without the stem and the inferred question mismatches the true question. For writing errors, it applies Tarrant et al.’s (2006) 19-rule educational rubric via an LLM judge, which evaluates each MCQ for violations like ambiguous stems or implausible distractors. Each detector outputs binary flags with confidence scores, enabling per-item and aggregate flaw reporting.

## Key Results
- Audits of 12 benchmarks show 47% of TruthfulQA contaminated, 100% of HellaSwag violates multiple writing rules, and 21% of ScholarIQA contains shortcuts.
- Writing errors are the most prevalent and impactful flaw, materially changing model rankings and affecting both difficulty and discrimination parameters in IRT analysis.
- BenchMarker achieves strong human agreement, with GPT-5 reaching Cohen’s κ=0.606 for shortcuts and 0.501 for in-domain writing errors.
- Prior benchmark repairs (e.g., MMLU-Pro) solve targeted issues but introduce new flaws like implausible distractors.

## Why This Works (Mechanism)
Contamination detection relies on the assumption that if an MCQ appears on the public web, it is likely present in some LLM’s training corpus, enabling memorization. The system queries a web search API with the stem and correct answer, then uses an LLM judge to classify search results for exact or partial matches. High precision but low recall is observed for some search engines, meaning contamination may be undercounted.

Shortcut detection assumes that correct answers derived solely from choices indicate exploitable shallow cues (e.g., length heuristics). An LLM first answers with choices only, then generates a guessed original question. A second LLM judge compares the guess to the true question; a shortcut is flagged if the model is correct and the guess mismatches. This design filters cases where the inferred question matches, reducing false positives.

Writing error detection applies a standardized educational rubric (19 rules) via an LLM judge per rule. Each rule (e.g., "Focused Stem," "Plausible Distractors") is evaluated with definitions and examples. The approach assumes that such violations create ambiguity or misdirection, causing models to fail for reasons unrelated to the intended construct. It consistently surfaces issues like unclear stems and poor distractor quality, aligning with education research.

## Foundational Learning
- **Construct Validity in MCQ Design**: Ensures questions measure the intended reasoning skill, not trivial cues. Why needed: BenchMarker flags items that compromise validity (e.g., ambiguous stems). Quick check: If a stem ends with a blank, which writing rule is likely violated (e.g., "Focused Stem"), and why does this harm validity?
- **LLM-as-a-Judge Reliability**: BenchMarker’s trustworthiness depends on LLM judges agreeing with humans. Why needed: Validation with 8042 human judgments is central; users must know when automated scores are reliable. Quick check: Why does GPT-5 achieve higher κ for shortcuts (0.606) than writing errors (0.501) despite more training data for writing errors?
- **Item Response Theory (IRT) vs. Mean Accuracy**: IRT controls for model ability differences, unlike raw accuracy. Why needed: Impact analysis uses IRT to show flaw effects on difficulty/discrimination are robust. Quick check: Do contaminated items tend to have higher or lower difficulty/discriminability? What does this imply about their utility?

## Architecture Onboarding
InspectAI (Task) -> Scorers (contamination_detector, shortcut_detector, writing_flaws) -> [Optional Solver] -> Aggregator -> Persistence

Critical path:
1. Configure judge LLMs (e.g., GPT-5) and search API keys.
2. Execute `benchMarker_audit.py` on target dataset’s test set (sample ≤1000 items).
3. For each item, run the three scorers sequentially, storing judgments and confidence scores.
4. Aggregate results: compute flaw prevalence per dataset and per writing rule.
5. (Optional) Run solver LLMs on flawed and no-flaw splits to measure accuracy and ranking shifts.
6. Generate report card with prevalence plots, impact tables, and flagged item examples.

Design tradeoffs:
- Accuracy vs. Cost: Closed-source judges (GPT-5) offer highest human agreement but are expensive; open-source alternatives (e.g., Command R) are cheaper but less reliable.
- Precision vs. Recall (Contamination): Google API + GPT-5 yields high precision (0.86) but low recall; suitable for flagging likely contamination but may miss some.
- Granularity vs. Actionability: Per-rule writing error reports are informative but noisy; aggregated counts (e.g., ≥2 violations) are more robust for high-level decisions.

Failure signatures:
- Judge Failure: Low human agreement (κ < 0.4) on validation set; switch to model with higher κ per Table 2.
- API Failure: Search API errors/rate limits; implement retries and fallback to alternative engines (Table 10).
- Data Format Failure: Input MCQ schema mismatch; ensure InspectAI preprocessing adapts to dataset format.

First 3 experiments:
1. Judge Validation Replication: Run the validation suite on 50–100 MCQs (stratified by predicted flaw) to confirm judge agreement in your specific domain.
2. Single-Dataset Audit: Audit a familiar benchmark (e.g., MMLU) and manually inspect 20 flagged items per flaw type; assess whether flags are sensible.
3. Impact Analysis Pilot: Run one strong and one weak LLM on full test set and on writing-error-filtered subset; check if their ranking changes materially.

## Open Questions the Paper Calls Out
- **Cheaper contamination detection**: How can contamination detection be executed using cheaper search APIs while maintaining accuracy? Basis: Conclusion notes need for cheaper APIs. Why unresolved: Current Google API costly/limited; evidence needed: comparative evaluation of alternatives on detection accuracy and cost.
- **Efficient open-source judges**: Can open-source LLMs match closed-source judges in flaw detection? Basis: Future work on training efficient models. Why unresolved: Closed-source models expensive/restricted; evidence: fine-tune smaller LLMs on the 8042 human judgments and measure κ against closed-source and human baselines.
- **Generalizability beyond English NLP**: How well does BenchMarker generalize to non-English, domain-specific (e.g., medicine, coding), and culturally diverse contexts? Basis: Limitations state untested areas. Why unresolved: Validated on 13 English NLP datasets; evidence: apply to CMMLU, MedMCQA, CRUXEval, CulturalBench, and report LLM-human agreement.
- **Automated flaw repair**: What methods can automatically repair detected flaws? Basis: Future work on rewriting with BenchMarker as verifier. Why unresolved: Toolkit only flags flaws; evidence: iterative LLM rewrite-re-evaluate pipeline with human validation of flaw reduction and content preservation.
- **Extending to global benchmark issues**: How can BenchMarker address saturation, efficiency, and diversity? Basis: Limitations note unaddressed global issues. Why unresolved: Item-level detection insufficient; evidence: incorporate scorers for saturation (ceiling), efficiency (sample size), diversity (topic coverage), and validate with experts.

## Limitations
- Web-search contamination proxy may miss paraphrased or non-indexed items, leading to false negatives (low recall).
- Shortcut detection relies on LLM inference stability; disagreement on inferred questions may flag valid items.
- Uniform application of all 19 writing rules may flag contextually valid designs (e.g., "all of the above" in some settings).
- Generalizability limited to 13 English NLP benchmarks; other formats (e.g., free-response) and domains remain unvalidated.
