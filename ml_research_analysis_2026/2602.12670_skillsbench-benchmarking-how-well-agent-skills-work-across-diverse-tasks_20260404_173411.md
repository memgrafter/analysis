# SkillsBench: Benchmarking How Well Agent Skills Work Across Diverse Tasks
## Quick Facts
- arXiv ID: 2602.12670
- Source URL: https://arxiv.org/abs/2602.12670
- Reference count: 40
- Primary result: Curated Skills boost average pass rate by 16.2 percentage points; self-generated Skills yield no benefit (-1.3pp).

## Executive Summary
The paper introduces SkillsBench, a benchmark for evaluating Agent Skills—modular procedural knowledge packages that enhance LLM agents. It evaluates 86 tasks across 11 domains under three conditions (no Skills, curated Skills, self-generated Skills) across 7 model-harness configurations (7,308 trajectories). Results show curated Skills improve average pass rate by 16.2 percentage points, with large domain variation (Healthcare +51.9pp, Manufacturing +41.9pp, Software Engineering +4.5pp). Self-generated Skills provide no average benefit (-1.3pp), indicating models cannot reliably author effective procedural knowledge. Additional findings: focused Skills (2–3 modules) outperform comprehensive documentation, and smaller models with Skills can match larger models without them.

## Method Summary
SkillsBench comprises 86 terminal-based tasks across 11 domains, each packaged as a Docker container with an instruction file, environment, solution, and deterministic pytest verifier. Skills are delivered as modular directories containing a SKILL.md file (with YAML frontmatter and stepwise instructions) and optional resources. Evaluation runs 7 model-harness configurations (Claude Code, Gemini CLI, Codex CLI) under three Skills conditions: no Skills, curated high-quality Skills (≥9/12 quality score), and self-generated Skills authored by the agent. Each task is executed for 5 trials, yielding 7,308 trajectories. The primary metric is binary pass/fail from the verifier; secondary analysis includes skill utilization rates and normalized gains. The Harbor framework orchestrates container management, skill injection, and aggregated logging.

## Key Results
- Curated Skills boost pass rate by 16.2pp average, with domain range +4.5pp (Software Engineering) to +51.9pp (Healthcare).
- Self-generated Skills provide no average benefit (-1.3pp) and often harm performance.
- Optimal Skill design: 2-3 focused modules (+18.6pp) vs. comprehensive documentation (-2.9pp); smaller models with Skills can match larger baselines.

## Why This Works (Mechanism)
### Mechanism 1: Procedural Knowledge Gap Bridging
- Claim: Skills improve agent performance by encoding domain-specific procedural knowledge that foundation models lack from pretraining.
- Mechanism: Models possess strong pattern recognition but often fail on tasks requiring precise step-by-step workflows, API patterns, or regulatory procedures. Skills provide structured guidance (SKILL.md + resources) that transforms task-solving from recall-based reasoning to procedure lookup.
- Core assumption: Models have latent potential but need external scaffolding for specialized workflows.
- Evidence anchors:
  - [abstract] "Curated Skills raise average pass rate by 16.2 percentage points"
  - [section 4.1.3] Healthcare (+51.9pp) and Manufacturing (+41.9pp) show largest gains—domains with specialized workflows underrepresented in pretraining
  - [corpus] Neighbor papers confirm this pattern: Agent Skills analysis shows they fill capability gaps in embedded/IoT domains
- Break condition: When tasks align with model pretraining distribution (Software Engineering +4.5pp), Skills provide minimal benefit.

### Mechanism 2: Cognitive Load Optimization
- Claim: Skill efficacy follows an inverted-U relationship with quantity—2-3 focused modules maximize benefit, while comprehensive documentation harms performance.
- Mechanism: Excessive Skills consume context window and introduce conflicting guidance. Agents struggle to extract relevant information from lengthy procedural documents. Concise, stepwise guidance with examples yields highest ROI.
- Core assumption: Agents have limited context processing capacity; procedural knowledge must be modular and targeted.
- Evidence anchors:
  - [section 4.2.1] 2-3 Skills: +18.6pp; 4+ Skills: +5.9pp
  - [section 4.2.2] Comprehensive Skills: -2.9pp (negative effect)
  - [section 5] "concise, stepwise guidance... is more effective than exhaustive documentation"
- Break condition: When Skills exceed ~3 modules or contain verbose, unfocused content.

### Mechanism 3: Harness-Mediated Utilization
- Claim: Skills efficacy depends critically on agent harness implementation, not just Skill quality.
- Mechanism: Different commercial harnesses (Claude Code, Gemini CLI, Codex) have varying capabilities for Skill discovery, integration, and retrieval. Claude Code shows consistent improvement (+13.9 to +23.3pp) due to native Skills integration; Codex frequently neglects provided Skills despite context presence.
- Core assumption: Skills are passive artifacts; active utilization depends on harness design.
- Evidence anchors:
  - [section 4.1.2] "Claude Code: Highest skills utilization rate... Codex CLI: frequently neglects provided Skills"
  - [section C.4] Different harnesses use distinct injection mechanisms (various /root/. paths) and discovery methods (frontmatter parsing vs. explicit activation)
  - [corpus] Limited direct evidence; adjacent work shows harness variation affects tool use
- Break condition: When harness lacks Skills integration or proper context management.

## Foundational Learning
### Concept: Procedural vs. Declarative Knowledge Distinction
- Why needed here: Skills explicitly encode procedural knowledge ("how-to") rather than factual retrieval. Understanding this distinction is crucial for interpreting why RAG/tools differ from Skills.
- Quick check question: Would a StackOverflow answer count as a Skill? Why or why not? (Answer: No—it blends factual and procedural; Skills must be modular, reusable procedures with structured components).

### Concept: Paired Evaluation Design
- Why needed here: The benchmark's core innovation is evaluating the same task under Skills/no-Skills conditions. This isolates augmentation effects from raw model capability.
- Quick check question: Why is comparing "with Skills" vs "without Skills" on identical tasks more informative than comparing different models? (Answer: Controls for task difficulty and model variation, attributing differences to the intervention).

### Concept: Deterministic Verification in Agent Benchmarks
- Why needed here: SkillsBench uses programmatic verifiers (pytest) to avoid LLM-as-judge variance. Understanding this design choice explains the benchmark's rigor and limitations.
- Quick check question: What's a potential downside of deterministic verifiers compared to human judgment? (Answer: May miss partial credit or nuanced success criteria; tests must be precisely specified).

## Architecture Onboarding
### Component map
Task Module (Docker container with instruction, environment, solution, tests) → Skill Package (SKILL.md + resources) is injected into Agent Harness (Claude Code, etc.) → Agent Harness orchestrates LLM interaction with Task Module → Verifier (pytest in Task Module) evaluates outcome → Evaluator (Harbor) aggregates results.

### Critical path
1. Task submission → structural validation → oracle execution → human review → benchmark inclusion
2. Evaluation: harness loads environment → agent interacts → verifier runs → reward binary logged
3. Aggregation: 5 trials × 84 tasks × 7 configurations → 7,308 trajectories → pass rates computed

### Design tradeoffs
- Containerization vs. ecological validity: Isolated Docker ensures reproducibility but excludes GPU tasks and real-world toolchains.
- Deterministic verifiers vs. complex tasks: Programmatic tests avoid LLM judge variance but limit task expressiveness.
- Curated vs. ecosystem Skills: Benchmark uses high-quality Skills (score ≥9/12) but ecosystem average is 6.2/12, so results are optimistic.
- Fixed vs. adaptive context: 8K token sliding window may drop early Skills, affecting utilization.

### Failure signatures
- Infrastructure errors: VerifierTimeoutError (2 tasks excluded), Docker build failures.
- Skill neglect: Agent acknowledges Skills but doesn't use them (common in Codex).
- Negative delta: 16 tasks where Skills hurt performance—often from conflicting guidance or overhead.
- Timeout concentration: 46% of tasks have ≥1 timeout; computationally intractable tasks (gravitational-wave-detection) always timeout.

### First 3 experiments
1. Domain variance replication: Run subset of Healthcare vs. Software Engineering tasks to confirm +51.9pp vs +4.5pp gap. Isolate whether this comes from pretraining coverage or procedural complexity.
2. Skill quantity ablation: Create synthetic tasks with 1, 2, 3, 4+ Skills to verify the inverted-U curve. Test adding irrelevant Skills as control.
3. Harness swap test: Evaluate same model across different harnesses (e.g., Claude model in Claude Code vs. Gemini CLI if portable) to isolate harness effects from model effects.

## Open Questions the Paper Calls Out
- Which specific components of a Skill (instructions, code resources, examples) drive performance improvements? The paper treats Skills as monolithic packages and did not isolate contributions of individual components.
- Why do curated Skills sometimes reduce performance on certain tasks, and can we predict these failure cases? The paper reports 16 tasks with negative deltas but lacks systematic analysis of the underlying mechanisms.
- How well do Skills generalize beyond terminal-based, containerized tasks to other agent environments like GUI, web, or multi-agent systems? All experiments use terminal-based harnesses; transferability to multimodal or interactive settings is unknown.
- Can models ever autonomously generate effective Skills, or is human curation fundamentally necessary? Self-generation condition used a single prompting strategy; alternative approaches (e.g., fine-tuning, iterative refinement) may enable effective self-generation but remain unexplored.

## Limitations
- Skill quality gap: Curated Skills (≥9/12) exceed typical ecosystem quality (6.2/12), potentially overstating gains.
- Harness dependence: Results vary by harness; integration details are not fully open, limiting reproducibility.
- Ecological validity: Containerized tasks exclude GPU/real toolchains, reducing generalizability to real-world settings.

## Confidence
- Procedural Knowledge Gap: High
- Inverted-U Quantity: Medium
- Harness-Mediated Utilization: Medium
