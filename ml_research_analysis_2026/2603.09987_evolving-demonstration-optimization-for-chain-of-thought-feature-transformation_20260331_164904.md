# Evolving Demonstration Optimization for Chain-of-Thought Feature Transformation

## Quick Facts
- **arXiv ID:** 2603.09987  
- **Source URL:** https://arxiv.org/abs/2603.09987  
- **Reference count:** 40  
- **Primary result:** Achieves state-of-the-art performance on tabular benchmarks (e.g., 87.16% F1 on SpectF, 0.7406 1-RAE on OpenML-586) via a closed-loop, experience-driven LLM prompting framework.

## Executive Summary
Feature transformation (FT) is a fundamental yet notoriously difficult combinatorial search problem in tabular machine learning. This paper introduces a method that optimizes the LLM's few-shot context by evolving a library of high-performing, task-verified transformation experiences. Starting from sequences discovered by reinforcement learning (RL), the system refines them through validity checks, organizes them into Chain-of-Thought (CoT) improvement trajectories, and selects a diverse subset to condition the LLM. A closed-loop mechanism writes back downstream-verified sequences, progressively enriching the context. On multiple benchmarks, the approach consistently outperforms both classical FT methods and other LLM-based strategies, demonstrating that data-centric optimization of the demonstration context is a powerful paradigm for LLM-driven feature engineering.

## Method Summary
The method is a three-stage closed-loop system. **Stage I (RL Exploration):** An RL agent explores the feature space using downstream performance improvement as reward, collecting a raw set of high-scoring transformation sequences. **Stage II (Refinement):** These sequences undergo (a) local reliability checks (syntactic, numerical, utility), (b) organization into performance-ordered CoT trajectories with LLM-assisted gap-filling to enrich neighborhoods, and (c) entropy-guided diversity selection that balances quality and coverage to pick a final few-shot context. **Stage III (Closed-Loop Generation):** The selected context prompts an LLM to generate new candidate sequences. Valid, high-performing candidates are added to the experience library, and the context is re-selected from the updated library for the next iteration. The cycle runs for a fixed number of iterations under a bounded LLM call budget.

## Key Results
- Outperforms classical (GRFG, MOAT) and LLM-based (CAAFE, FeatLLM) baselines on diverse tabular datasets, with top scores of 87.16% F1 (SpectF) and 0.7406 1-RAE (OpenML-586).
- Closed-loop evolution yields stable, consistent gains over one-shot generation with the same number of LLM calls.
- Generalizes across multiple LLMs (GPT-4, Claude) and downstream evaluators (RF, XGBoost), confirming robustness.
- Ablation studies show the CoT trajectory organization and entropy-guided diversity selection are critical components, with their removal causing the largest performance drops.

## Why This Works (Mechanism)
**Mechanism 1: RL-Guided Seed Collection**  
Reinforcement Learning exploration provides an initial set of high-performing transformation sequences, aligning the search with downstream objectives. The RL agent selects feature-operator actions, with rewards based on downstream model improvement. This avoids blind search by biasing toward task-relevant transformations. Break condition: if RL fails to find positive-gain sequences, the seed library quality suffers.

**Mechanism 2: Three-Level Refinement into Demonstrations**  
Raw RL sequences undergo (a) validity filtering for syntactic, numerical, and utility constraints; (b) CoT trajectory construction by sorting valid sequences by score and using an LLM to fill gaps with nearby variants; (c) entropy-guided diversity selection balancing average performance, coverage, and redundancy. This creates high-quality, interpretable, and diverse few-shot examples. Break condition: insufficient diversity or excessive invalid variants undermine guidance.

**Mechanism 3: Closed-Loop Experience Evolution**  
LLM-generated sequences are evaluated downstream; valid, high-performing ones are added to the library. The context for the next iteration is re-selected from the updated library, creating a feedback loop that accumulates task-aligned experiences. Downstream verification ensures only useful transformations enter, gradually shifting the library toward optimal regions. Break condition: misaligned verification or catastrophic forgetting can cause divergence.

## Architecture Onboarding
- **Component map**: RL Explorer -> Validation Checker -> LLM Enhancer -> Diversity Selector -> LLM Generator -> Downstream Evaluator -> Write-back Module (loops back to Diversity Selector)
- **Critical path**: RL exploration collects raw experiences, which are refined and selected to form context; LLM generates new candidates; downstream verification writes back high-performers; context updates and repeats.
- **Design tradeoffs**: 
  * Quality vs. Diversity: The entropy weight in selection trades off maximizing average score against covering distinct pattern signatures.
  * RL Cost vs. LLM Cost: RL is sample-efficient but computationally heavy per sample; LLM generation is flexible but token-costly; initialization size must balance seed quality and overhead.
  * Enhancement Granularity: LLM-based gap-filling risks generating invalid or off-task variants, controlled by the same validation checks.
- **Failure signatures**: 
  * High invalid ratio in generated sequences indicates validation checks are insufficient or enhancement is too aggressive.
  * Performance plateau or drop after initial iterations suggests write-back is adding noise or the selector is stuck in a local cluster.
  * Feature usage collapse (few original features dominate) indicates library coverage is poor and entropy selection is ineffective.
- **First 3 experiments**: 
  1. **Benchmark Performance (Table 1):** Compare against classical and LLM-based baselines on diverse tabular datasets to establish overall efficacy.
  2. **Closed-loop vs. One-shot (Fig 7):** Ablate write-back by fixing the experience library (one-shot) vs. updating it (closed-loop) under equal LLM call budgets to show evolution benefits.
  3. **Three-level Refinement Ablation (Table 2):** Sequentially disable combination check, CoT organization, enhancement, and entropy-guided selection to quantify each component's contribution.

## Open Questions the Paper Calls Out
1. Why do LLMs exhibit a strong preference for simpler operators over complex ones in feature transformation tasks, and how does the evolving experience library mitigate or exacerbate this bias?
2. How does the quality and initial diversity of RL-explored sequences impact the long-term performance and convergence of the closed-loop experience evolution?
3. What specific structural attributes does the discrete signature in entropy-guided diversity selection capture, and how well does it correlate with semantic diversity of transformation experiences?
4. What is the computational cost-benefit trade-off of the LLM-based enhancement step, and can non-LLM methods (e.g., heuristic mutation) achieve comparable improvements?
5. To what extent does the proposed framework generalize to non-tabular data domains (e.g., image, text, graph), and what modifications are needed?

## Limitations
- Exact RL hyperparameters (learning rates, discount factor) and the precise formulation of the structural signature `z(e)` with its quality-diversity weights (λ, μ) are undisclosed, hindering exact replication.
- Performance critically depends on the reliability and consistency of the downstream evaluator used for verification; noisy or overfitting evaluators can misguide the closed loop.
- The method is designed for tabular feature combinations; generalization to other data modalities (image, text) is untested and likely requires significant adaptation.

## Confidence
- **SOTA performance on benchmarks:** Medium (results are strong and replicated across datasets, but generalizability to new domains is unproven).
- **Closed-loop evolutionary benefit:** High (ablation studies clearly demonstrate consistent improvement over one-shot generation under controlled budgets).
- **Cross-LLM generalization:** Medium (claims supported by testing with multiple LLMs, but scope of tested configurations is limited).
- **Robustness to downstream evaluators:** Medium (tests with RF and XGBoost show stability, but broader evaluator diversity is needed).

## Next Checks
1. **Downstream model stress test:** Repeat key experiments using a wider array of downstream models (e.g., tree-based, neural nets) and evaluation protocols to verify robustness against evaluator choice and potential overfitting.
2. **RL seed sensitivity analysis:** Replace the undisclosed RL exploration with a standard, well-documented alternative (e.g., random search with a simple policy) to assess how much performance depends on the specific RL implementation versus the refinement and loop mechanism.
3. **Diversity-weight sweep:** Perform a systematic grid search over the entropy weight (λ) and redundancy penalty (μ) in the quality–diversity objective to map the performance landscape and identify if reported values are near-optimal or fragile.
