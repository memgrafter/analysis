# Evolutionary Router Feature Generation for Zero-Shot Graph Anomaly Detection with Mixture-of-Experts

## Quick Facts
- arXiv ID: 2602.11622
- Source URL: https://arxiv.org/abs/2602.11622
- Reference count: 40
- Primary result: EvoFG achieves state-of-the-art zero-shot graph anomaly detection performance across six benchmark datasets, with top average rank in AUROC and AUPRC, including 91.62% on ACM and 93.05% on Weibo.

## Executive Summary
EvoFG is a Mixture-of-Experts framework for zero-shot graph anomaly detection that generalizes across heterogeneous graph domains. It introduces an evolutionary scheme where an LLM iteratively generates informative router features, guided by efficient Shapley value estimation for feature selection, and a memory-enhanced router trained with an invariant learning objective to capture transferable routing patterns under distribution shifts. Experiments on six datasets show consistent superiority over baselines.

## Method Summary
EvoFG first pre-trains four GNN experts (GCN, GAT, ChebNet, GPR) on source graphs using a cosine consistency loss. It then iteratively refines the router’s input features: starting from 23 handcrafted primitives, an LLM composes new features using predefined operators; a Shapley-based selector filters them using a KL-divergence utility. The memory-enhanced router is retrained with an invariant loss that minimizes anomaly loss variance across masked environments and a balancing loss to avoid expert collapse. At inference, the router assigns nodes to experts based on the final feature set, and aggregated outputs yield anomaly scores.

## Key Results
- EvoFG achieves the best average rank in AUROC and AUPRC across all six test datasets.
- It attains AUROC 91.62% on ACM and 93.05% on Weibo.
- Ablation studies confirm the contribution of each component: LLM generation, Shapley selection, memory, and invariant learning.

## Why This Works (Mechanism)
We break down the three key mechanisms:

Mechanism 1: LLM-based evolutionary feature generation expands the router feature space with diverse, semantically meaningful transformations that enhance expert routing. Starting from 23 primitive features and a set of operators, the LLM iteratively selects a category, picks k features, chooses a compatible operator, and composes a new feature across R rounds. The core assumption is that the LLM can leverage its pre-trained knowledge to propose graph-relevant feature combinations predictive of routing quality. Evidence appears in the abstract and Section 3.2. Break condition: features that are too domain-specific, numerically unstable, or irrelevant may inject noise and harm zero-shot performance.

Mechanism 2: Efficient Shapley-based feature selection identifies and retains only those router features that provide a net benefit to routing decisions. The Shapley value φ_i for a feature f_i is approximated by repeatedly splitting the full feature set into two complementary subsets S1 and S2, computing the routing utility v(·) (KL divergence between router logits and expert correctness) for each subset, and deriving marginal contributions Δ = v(S1 ∪ {f_i}) − v(S1) (or symmetrically for S2). After T iterations, the average and z-score of Δ guide selection: keep features with positive mean or statistically significant contributions. The core assumption is that the KL-based utility reliably reflects routing quality and the random partition sampling yields an unbiased Shapley estimator with moderate T. Evidence in abstract and Section 3.3. Break condition: if the router utility is noisy or misaligned with final detection accuracy, or if T is too small, the selector may discard useful features or keep harmful ones.

Mechanism 3: The memory-enhanced router trained with invariant learning captures domain-independent routing principles that generalize across graph distributions, while avoiding expert collapse. The router projects node features X̃ and router features Hʳ into queries and retrieves entries from two memory banks (node memory Φ_n, router memory Φ_r). Routing logits are computed via similarity between retrieved router memory and node memory, scaled per expert. To learn invariance, K masked versions of Hʳ are created (random feature dropping). For each environment (mask), the router produces weights, which are used to aggregate expert outputs; the anomaly loss is computed. The invariant objective LIN minimizes the mean loss across environments plus a variance penalty. A MoE balancing loss further encourages uniform expert usage. Core assumption: Invariant risk minimization can isolate causally predictive routing signals from spurious correlations, and the memory banks can accumulate these stable patterns across iterative feature generations. Evidence in abstract, Section 3.4, and 3.5. Break condition: if the masking scheme fails to reflect natural distribution shifts, or if memory banks overfit to source domains, the router may still rely on domain-specific cues. Insufficient K or λ can also lead to poor invariance.

## Foundational Learning
- **Graph Neural Networks (GNNs):** Needed because EvoFG integrates multiple GNN experts with different inductive biases; understanding message passing, aggregation, and spectral vs. spatial designs is essential to grasp how each expert interprets graph structure. Quick check: How does attention modify neighborhood aggregation in GAT compared to GCN? What does a high-pass filter in ChebNet capture?
- **Mixture-of-Experts (MoE):** The entire framework revolves around adaptive routing of nodes to experts; knowledge of gating mechanisms, soft vs. hard routing, and challenges like expert collapse is key. Quick check: What are the trade-offs between using a simple fully connected router versus a memory-enhanced one? Why is soft routing preferred in zero-shot settings?
- **Invariant Risk Minimization (IRM):** The router training explicitly enforces invariance across masked environments; IRM encourages learning features whose relationship to the label is stable across domains. Quick check: What does the variance term in LIN (Equation 19) encourage? How does IRM differ from standard ERM when facing distribution shifts?

## Architecture Onboarding
Component map: Input Graph -> Feature Preprocessor -> Primitive Feature Extractor -> [LLM Generator -> Shapley Selector] (iterative) -> Router Trainer (with Memory-Enhanced Router) -> Expert Pool -> Anomaly Scores.

Critical path (data flow):
1. Input graph is preprocessed: PCA alignment and smoothness-based sorting produce X̃.
2. Initial router features ℱ are extracted from X̃.
3. For R rounds: LLM generates m new features → ℱexpanded; Shapley selector filters → ℱ⁺; router is retrained (experts frozen) on ℱ⁺.
4. Inference: For a test graph, compute ℱ⁺, feed to trained memory-enhanced router to get weights P; aggregate expert outputs; compute anomaly scores via L2 distance.

Design tradeoffs:
- m (new features/round): Larger m accelerates growth but risks noise; smaller m is conservative but may need more rounds.
- T (Shapley samples): More samples improve selection accuracy at linear cost; recommended T≥20.
- M (memory size): Larger M stores more patterns but may overfit; balance with dataset size.
- λ (invariant weight): Controls ERM vs. invariance; too high oversimplifies, too low yields weak invariance. Typical 0.6–0.8.
- K (environments): More masks better cover domain variations; beyond 20 often diminishing returns.

Failure signatures:
- Expert collapse: One expert’s routing weight dominates all datasets (check soft routing heatmap). Remedy: increase λ or MoE balancing weight, or enlarge memory.
- High variance across random seeds: Stabilize by increasing T or using more LLM generation rounds R.
- Poor zero-shot despite good validation: Router likely overfit to source domains; increase K or λ, or reduce feature dimensionality.
- Memory overfitting: Training loss low but test loss high; reduce M or add dropout-like masking on memory retrieval.

First 3 experiments:
1. Main results: Train on PubMed & Flickr, validate on Coauthor-CS & Amazon-Photo, test on six target datasets. Confirm EvoFG’s average rank superiority in AUROC/AUPRC over baselines.
2. Ablation study: Remove components one at a time (LLM generation → random, Shapley → none, memory → FC layer, invariant loss → only KL) on a subset (e.g., Cora, ACM, Weibo) to quantify each contribution.
3. Hyperparameter sensitivity: Sweep m (5–20), R (1–5), λ (0.2–1.0), K (5–25) on a held-out validation dataset (e.g., BlogCatalog) to observe performance trends and set robust defaults.

## Open Questions the Paper Calls Out
- How does the choice of LLM (e.g., model size, architecture) affect the quality of generated router features and overall zero-shot GAD performance?
- What is the empirical computational cost of EvoFG's iterative generation pipeline as graph size and feature space grow?
- Does the invariant learning objective truly enforce domain-invariant routing decisions, or are there residual spurious correlations?
- How sensitive is the memory-enhanced router to the size of its memory banks, and what is the optimal capacity for different graph scales?
- Can the feature generation process be improved by incorporating feedback from the router's validation performance, rather than relying solely on Shapley-based selection?

## Limitations
- The LLM generation pipeline lacks details on prompts, temperature, and conditioning strategy, hindering reproducibility and analysis of LLM necessity.
- The memory bank parameter update mechanism is unspecified; it's unclear whether memory is differentiable, updated via EMA, or otherwise.
- The Shapley utility (KL divergence) may not correlate reliably with final AUROC, risking misaligned feature selection.

## Confidence
- Overall zero-shot GAD performance: Medium
- LLM-driven evolutionary feature generation: Low
- Shapley-guided feature selection: Medium
- Memory-enhanced invariant router: Medium
