# Clarify Before You Draw: Proactive Agents for Robust Text-to-CAD Generation

## Quick Facts
- **arXiv ID**: 2602.03045
- **Source URL**: https://arxiv.org/abs/2602.03045
- **Reference count**: 40
- **Primary result**: ProCAD reduces mean Chamfer distance by 79.9% relative to Claude Sonnet 4.5 and lowers invalidity ratio from 4.8% to 0.9%.

## Executive Summary
Text-to-CAD generation systems often fail when user prompts are ambiguous or inconsistent, leading to hallucinations in dimensions or invalid code. This paper introduces ProCAD, a proactive two-agent framework that resolves such ambiguities before code synthesis. A clarifying agent audits the prompt and asks minimal, targeted questions to resolve missing or conflicting specifications. A separate coding agent then translates the clarified prompt into executable CadQuery code. Both agents are fine-tuned on carefully curated datasets: the clarifier on 6,063 synthetic clarification trajectories, and the coder on a high-quality 10K text-to-CadQuery dataset built via a rigorous pipeline. Experiments show that ProCAD dramatically improves robustness to ambiguous prompts, achieving a 79.9% reduction in mean Chamfer distance and lowering the invalidity ratio from 4.8% to 0.9% compared to Claude Sonnet 4.5. The system also maintains high efficiency and resolution scores in user interactions, outperforming prior works and frontier models.

## Method Summary
ProCAD employs a two-agent architecture. The clarifying agent is fine-tuned via agentic supervised fine-tuning on 6,063 synthetic trajectories derived by programmatically perturbing unambiguous specifications to create ambiguities and simulating user answers. The agent learns to either accept a prompt or output JSON-formatted questions, formalized as an MDP with reward balancing geometric fidelity (Chamfer distance) and interaction cost. The coding agent undergoes standard supervised fine-tuning on 1,600 high-quality samples selected from a curated 10K text-to-CadQuery dataset. This dataset construction starts from CadQuery programs, renders multi-view images, uses a VLM to generate natural-language descriptions, and applies leakage and completeness checks to ensure unambiguous, high-fidelity pairs. The clarified prompt from the first agent becomes input to the coding agent, producing executable CadQuery code evaluated via mesh generation and Chamfer distance.

## Key Results
- ProCAD (clarifier + coder) reduces mean Chamfer distance by 79.9% relative to Claude Sonnet 4.5 and lowers invalidity ratio from 4.8% to 0.9%.
- The two-agent framework achieves high efficiency and resolution scores in user interaction, outperforming frontier models and prior works.
- The coding agent fine-tuned on only 1.6K high-quality samples attains near-zero invalidity (<1%) and superior geometric fidelity compared to larger models.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The clarifying agent proactively identifies and resolves specification ambiguities *before* code generation, preventing downstream hallucination.
- **Mechanism:** The agent audits the user prompt for three ambiguity types (missing dimensions, conflicting values, impossible specs) and either accepts a clear prompt or outputs targeted JSON-formatted questions. This front-loads verification, ensuring the coding agent receives a self-consistent specification.
- **Core assumption:** Users can correctly answer clear, targeted questions. An optimal policy minimizes interaction rounds by asking only essential questions.
- **Evidence anchors:**
  - [abstract] "proactive clarifying agent, which audits the prompt and asks minimal, targeted clarification questions"
  - [section 3] Formalization as MDP where agent chooses `ASK` or `ACCEPT`; reward `R = −CD(y) −λC(h)` balances geometry fidelity and interaction cost.
  - [corpus] Neighbors like *Ask-before-Plan* and *Clarify or Answer* show proactive question-asking improves robustness in planning/VQA, suggesting transferability—but **Assumption:** this directly applies to CAD code generation.
- **Break condition:** If the clarifying agent fails to detect an ambiguity (false negative) or asks redundant questions (false positive), interaction cost rises without CD improvement, degrading the trade-off.

### Mechanism 2
- **Claim:** A high-quality, concise text-to-CadQuery dataset enables a lightweight coding agent (1.6K samples) to achieve near-perfect validity and fine geometric fidelity.
- **Mechanism:** The dataset is constructed *from CadQuery code* (not from noisy expert text) via a multi-view VLM + verification pipeline, ensuring specifications are unambiguous and leakage-free. The coding agent is fine-tuned via standard SFT on these clean pairs.
- **Core assumption:** Code-to-text generation with rigorous verification yields clearer user-like prompts than human-authored expert descriptions (e.g., Text2CAD), which contain scaling noise and redundancy.
- **Evidence anchors:**
  - [section 4] Pipeline: render shape → prompt GPT-5-mini with code + images → leakage/completeness checks → human review for tough cases. Results in shorter, clearer prompts (Table 3).
  - [section 5.1] SFT on 1.6K curated samples yields IR 0.9% vs. 86.9% zero-shot Qwen, outperforming Claude 4.5 Sonnet (IR 12.9%).
  - [corpus] *CAD-coder* and *Text2CadQuery* also use SFT on large datasets (>150K), but ProCAD’s quality-over-quantity approach is distinct—**corpus evidence weak** for causal claim.
- **Break condition:** If the dataset curation pipeline fails to remove leakage or ambiguity (check thresholds too loose), the coding agent inherits noise and hallucinates, raising IR and CD.

### Mechanism 3
- **Claim:** The two-agent separation of concerns (specification audit vs. code synthesis) yields robustness to ambiguous prompts that single-model systems cannot match.
- **Mechanism:** The clarifying agent’s output (standardized prompt) becomes the coding agent’s input, creating a clear interface. The reward design implicitly trains the clarifier to minimize rounds while maximizing final CD reduction.
- **Core assumption:** Ambiguity resolution is a distinct subtask from code translation; jumbling them in one model leads to reactive hallucination. Specialization via separate fine-tuning is more effective.
- **Evidence anchors:**
  - [section 6.3] Two-agent systems (any coding agent + ProCAD-clarifier) beat single-model baselines on ambiguous prompts (e.g., Claude 4.5 Sonnet IR 4.8% → 0.9% with ProCAD-coder).
  - [section 3] Figure 1 and MDP formulation show explicit handoff; [section 5.2] agentic SFT on synthetic clarification trajectories trains the clarifier.
  - [corpus] *ClarEval* and *Ask or Assume?* evaluate clarification in coding agents, supporting the paradigm—but **no direct evidence** that separation is necessary vs. a single model trained to both clarify and code.
- **Break condition:** If the clarifier over-asks (many rounds) or under-asks (misses key specs), the coding agent receives a poor specification, and CD remains high despite low IR.

## Foundational Learning
- **Supervised Fine-Tuning (SFT) for code generation**
  - Why needed here: Both agents are fine-tuned from base LLMs (Qwen2.5-7B-Instruct) on task-specific demonstrations (unambiguous prompts → code; ambiguous → questions → corrected prompt).
  - Quick check question: Why does SFT on only 1.6K samples for the coder work so well when prior work uses >150K?
- **Agentic Supervised Fine-Tuning (trajectory modeling)**
  - Why needed here: The clarifier must produce multi-step outputs (questions, then corrected prompt) conditioned on conversation history; agentic SFT trains this sequential decision-making.
  - Quick check question: How does the training objective (Eq. 3) force the clarifier to produce *both* questions and the final corrected prompt?
- **Geometric fidelity metrics (Chamfer Distance)**
  - Why needed here: CD quantifies shape accuracy between generated mesh and ground truth; it’s the primary optimization target in the clarifier’s reward.
  - Quick check question: Why is CD preferred over, say, voxel IoU for CAD evaluation?
- **Ambiguity types in CAD specifications**
  - Why needed here: The system targets two concrete failure modes: under-specification (missing dimensions) and conflict (inconsistent values). Detection requires recognizing geometric primitives and their parameters.
  - Quick check question: In the L-shaped extrusion case, which parameters were missing? How would you phrase a clarification question for each?
- **Synthetic data generation via perturbation**
  - Why needed here: Real ambiguous human prompts are scarce; the paper synthetically perturbs clean specs to create training data for the clarifier.
  - Quick check question: What are the risks of using a simulator (GPT-5-mini) to generate both ambiguities *and* user answers?

## Architecture Onboarding
- **Component map:** User provides initial prompt → Clarifying Agent (ProCAD-clarifier) audits prompt → (if ambiguous) multi-turn Q&A with User/Simulator → Standardized prompt → Coding Agent (ProCAD-coder) generates CadQuery code → CadQuery Executor renders mesh and computes metrics → Evaluation (CD, validity). Parallel: Dataset Pipeline builds training data (multi-view rendering, VLM description, leakage/completeness checks).
- **Critical path:** `User prompt → Clarifying Agent (audit) → [if ambiguous: Q&A loop] → Standardized prompt → Coding Agent → CadQuery code → Execute → Mesh → CD.`
- **Design tradeoffs:**
  - Interaction cost vs. geometric fidelity: More questions resolve more ambiguity but increase interaction cost; λ balances trade-off.
  - Dataset curation effort vs. automation: Human review for ~20% of samples yields high quality but limits scalability.
  - Open-source base vs. frontier models: Using Qwen2.5-7B keeps training cheap but may limit reasoning depth; frontier models still benefit from clarification.
  - Synthetic vs. real ambiguity data: Synthetic data is controllable but may not capture real user ambiguity patterns.
- **Failure signatures:**
  - Clarifier false negative: Misses ambiguity → coding agent generates invalid/wrong geometry (high CD, possible IR).
  - Clarifier false positive/redundancy: Asks unnecessary questions (low efficiency score, user frustration).
  - Coding agent invalid output: Syntax error or impossible geometry → high IR, often due to poor standardized prompt.
  - Dataset leakage: VLM description copies code syntax → coder mimics code form rather than natural language → poor generalization.
  - Simulator mismatch: GPT-5-mini answers differ from real users → clarifier overfits to simulator style → poor real-world resolution.
- **First 3 experiments:**
  1. Dataset quality validation: For 1K generated descriptions, compute leakage rate (<5%) via LLM judge, completeness pass rate (>80%) via CD regeneration check, and human preference vs. Text2CAD.
  2. Coding agent zero-shot vs. fine-tuned: Test Qwen2.5-7B-Instruct on 1K unambiguous prompts from new dataset. Expected: IR drops from ~85% to <1% after SFT, CD median improves.
  3. Two-agent vs. single-model on ambiguous prompts: Fix coding agent (ProCAD-coder), compare (a) no clarification, (b) + Claude 4.5 clarifier, (c) + ProCAD-clarifier on 2.5K synthetic ambiguous set. Expected: ProCAD-clarifier yields lowest CD and IR with highest efficiency.

## Open Questions the Paper Calls Out
- **Question:** How can we collect large-scale, real-world ambiguous CAD prompts from human designers, and how does this compare to simulated data in training proactive clarification agents?  
  **Basis in paper:** [explicit] The authors state that "gathering large-scale ambiguity datasets from real-world human interactions" is a future direction, and they used GPT-5-mini simulation as a scalable alternative due to the difficulty of collecting human data.  
  **Why unresolved:** Current training relies on synthetic ambiguity generated by a single user simulator; real human ambiguity patterns, error types, and response distributions may differ, potentially leading to poorer generalization in real-world deployments.  
  **What evidence would resolve it:** Conduct large-scale collection of human-CAD interaction logs, extract ambiguous prompts and clarification dialogues, and compare the performance of agents trained on synthetic vs. human data on a held-out set of real human interactions.

- **Question:** What is the impact of user knowledge and certainty on the effectiveness of proactive clarification, given that the paper assumes users can provide correct answers if questions are clear?  
  **Basis in paper:** [explicit] The paper explicitly states: "we assume that the user can provide correct answers to any asked question as long as the question itself is clear." This assumption is not validated with real users.  
  **Why unresolved:** Real users (especially novices) may be uncertain about dimensions or may provide incorrect answers, which could propagate errors into the clarified specification and ultimately the CAD model. The system's robustness to user errors is unknown.  
  **What evidence would resolve it:** Conduct user studies where participants with varying expertise are asked clarification questions and their answers are used to generate CAD models; measure the accuracy of the final models against ground truth, and analyze how user uncertainty correlates with outcome quality.

- **Question:** Can the proactive clarification approach scale to more complex CAD models and diverse ambiguity types beyond the two types (under-specified and conflicting) considered?  
  **Basis in paper:** [inferred] The paper focuses on two ambiguity types (missing dimensions and conflicting values) and evaluates on a dataset derived from Rukhovich et al. (2025) which consists mainly of mechanical parts. The generalizability to other types (e.g., ambiguous spatial relations, unclear feature intent, assembly-level constraints) and to more complex geometries (e.g., freeform surfaces, assemblies) is unexplored.  
  **Why unresolved:** The dataset and evaluation are limited; it's unclear if the same two-agent framework would handle richer ambiguity or more complex models without significant modifications.  
  **What evidence would resolve it:** Extend the synthetic ambiguity generation to cover a broader set of ambiguity types (e.g., from CAD best practice guidelines) and evaluate on CAD models of varying complexity from multiple sources (e.g., Fusion 360 Gallery, ABC dataset). Also test on assembly-level prompts.

- **Question:** How does the quality of the clarified specification interact with the coding agent's inherent capabilities? Is the two-agent system's success mainly due to better clarification, better coding, or their synergy?  
  **Basis in paper:** [explicit] The paper shows that pairing ProCAD-clarifier with ProCAD-coder yields the best results, but they do not disentangle the contributions. They also note that their coding agent, fine-tuned on only 1.6K samples, already performs well on unambiguous prompts, suggesting high-quality prompts are critical.  
  **Why unresolved:** The experiments compare different clarifiers with fixed coders and vice versa, but there is no systematic study varying both independently to measure interaction effects. It is unclear whether a stronger coding agent alone could handle some ambiguities, or if clarification is always necessary.  
  **What evidence would resolve it:** Conduct a factorial experiment: vary coding agent strength (different model sizes, training data sizes) and clarifying agent strength (different models, training methods) and measure geometric fidelity and invalidity. This would reveal the marginal benefit of clarification and whether there are diminishing returns.

- **Question:** What are the user experience trade-offs between interaction overhead and final CAD quality, and can the system adapt to individual user preferences?  
  **Basis in paper:** [inferred] The reward function includes a cost term λ controlling trade-off, but λ is fixed in experiments. The paper reports efficiency and resolution scores from an LLM judge but does not involve real users in the loop to assess satisfaction, cognitive load, or preferred number of questions.  
  **Why unresolved:** The optimization objective is defined by the authors, not by actual user preferences. Different users might tolerate different amounts of interaction depending on their expertise, context, or the complexity of the desired model.  
  **What evidence would resolve it:** Conduct user studies where participants interact with the system with different λ settings (or different questioning strategies) and report satisfaction, perceived usefulness, and willingness to use the system. Use these to learn an adaptive policy that tailors clarification aggressiveness to user feedback.

## Limitations
- **Dataset Access:** The core 10K text-to-CadQuery dataset and 6,063 clarification trajectories are not publicly available, forcing reproduction via a potentially divergent pipeline.
- **Execution Environment:** CadQuery version, backend (OCP), and meshing parameters are unspecified, risking incomparable Chamfer distance calculations.
- **Simulator Fidelity:** Using GPT-5-mini as a user simulator introduces distribution shift; performance with real users is an unknown.
