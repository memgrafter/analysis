# MARTI-MARS$^2$: Scaling Multi-Agent Self-Search via Reinforcement Learning for Code Generation
## Quick Facts
- arXiv ID: 2602.07848
- Source URL: https://arxiv.org/abs/2602.07848
- Reference count: 40
- Primary result: Two 32B agents achieve 77.7% Pass@1 on LiveCodeBench, surpassing GPT-5.1.

## Executive Summary
MARTI-MARS² introduces a framework that integrates multi-agent reinforcement learning (RL) with tree search to overcome performance plateaus in single-agent LLMs on complex code generation. By treating multi-agent collaboration as a learnable dynamic environment, it supports both homogeneous (shared parameters) and heterogeneous (independent) agents, enabling a progression from simple multi-role systems to diverse multi-agent collectives. For inference, MARS²-T+ enhances test-time scaling with error-feedback, depth-guided exploration, and a reward model trained on collected trajectories. Evaluated on LiveCodeBench, two 32B agents achieve 77.7% Pass@1, exceeding GPT-5.1; on 14B models, Heter-MARS2 reaches 81.7% Pass@1 and 2.033 NAUADC. The work establishes a scaling law: transitioning from single-agent to homogeneous multi-role to heterogeneous multi-agent progressively raises RL performance ceilings, improves test-time scaling, and increases policy diversity.

## Method Summary
MARTI-MARS² comprises training and inference phases. During training, multiple LLM agents (either parameter-sharing or independent) interact within a multi-agent tree search. Each node expansion selects an agent and chooses between generating new candidates (GEN) or refining existing ones (CON). Code solutions are executed against test cases to produce binary rewards. Group-level advantage estimation normalizes rewards across all tree nodes, and trajectories are asynchronously dispatched to agent-specific buffers. When a buffer fills, its agent updates its policy using a GRPO-style objective, with optional stabilizers (GSPO, Overlong Penalty, TIS) in the MARS²+ variant. A reward model (RM) is trained offline on the collected trajectories. At inference (MARS²-T+), error messages from failed executions are fed back into the search, depth-dependent weighting encourages deeper exploration, and the RM selects the final solution among those passing public tests. This unified approach learns not only policy parameters but also effective collaboration dynamics and test-time search strategies.

## Key Results
- Two 32B agents achieve 77.7% Pass@1 on LiveCodeBench, surpassing GPT-5.1.
- Heter-MARS2 on 14B models reaches 81.7% Pass@1 and 2.033 NAUADC, demonstrating superior algorithmic diversity and robustness.
- A three-stage scaling law (single-agent → homogeneous multi-role → heterogeneous multi-agent) yields progressively higher RL performance ceilings, enhanced test-time scaling, and increased policy diversity.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Modeling multi-agent collaboration as a learnable dynamic environment via multi-agent RL (MARS²) raises individual agent performance ceilings and enables evolution from homogeneous to heterogeneous training.
- **Mechanism:** MARS² integrates policy learning with multi-agent tree search. Agents iteratively explore and refine within a structured search tree during rollouts. A group-level advantage estimation (Eq. 1) computes relative performance across all nodes, and data is asynchronously dispatched to agent-specific buffers. This allows agents to learn from diverse interactions, with heterogeneity (independent parameters) preventing premature policy convergence.
- **Core assumption:** Agent interaction patterns can be optimized via RL, and separating agent buffers prevents interference, preserving strategic diversity.
- **Evidence anchors:** [abstract] "MARTI-MARS2 integrates policy learning with multi-agent tree search by formulating the multi-agent collaborative exploration process as a dynamic and learnable environment. By allowing agents to iteratively explore and refine within the environment, the framework facilitates evolution from parameter-sharing homogeneous multi-role training to heterogeneous multi-agent training." [section 2.2] Details the data collection, advantage calculation (Eq. 1), data dispatching to agent buffers, and dynamic training.
- **Break condition:** Heterogeneous agents may suffer from training instability or non-convergence if interaction diversity becomes too high, as indicated by the need for MARS²+ stabilization tricks (GSPO, Overlong Penalty, TIS).

### Mechanism 2
- **Claim:** MARS²-T+ inference significantly outperforms vanilla test-time scaling by correcting shallow search bias, better utilizing error signals, and stabilizing candidate selection with a reward model.
- **Mechanism:** During inference, three coordinated enhancements are applied: (1) **Error-feedback integration** – failed nodes receive structured diagnostic information (error messages, failed inputs/outputs) to guide refinement. (2) **Dynamic depth-guided exploration** – a depth-dependent weighting (Eqs. 4-5) encourages deeper node expansion, countering shallow bias. (3) **Reward model (RM)** – an RM trained on training trajectories selects the final solution from among pass@public candidates (Eq. 7), mitigating reward hacking from sparse public tests.
- **Core assumption:** Intermediate error diagnostics and depth-aware guidance improve refinement quality, and an RM trained on diverse policy outputs can generalize to private test success.
- **Evidence anchors:** [abstract] "MARTI-MARS2-T+ adds error-feedback integration, depth-guided exploration, and a reward model trained on collected trajectories." [section 2.3] Describes the three components and their integration. Section 3.4 shows ablation results and node depth distribution improvement.
- **Break condition:** The RM may degrade performance if training trajectories lack diversity or overfit to public test artifacts; depth weighting could cause excessive exploration if γ decay is poorly tuned.

### Mechanism 3
- **Claim:** Multi-agent scaling (single → homogeneous multi-role → heterogeneous multi-agent) yields progressively higher RL ceilings, robust TTS, and policy diversity, establishing diversity as a critical scaling dimension.
- **Mechanism:** Homogeneous multi-role training (shared parameters, different roles) initial broad exploration. Heterogeneous multi-agent training (independent parameters) maintains long-term diversity as agents adapt to dynamically changing peers. Diversity metrics (NAUADC, G-Vendi) confirm increasing algorithmic and cognitive variation, which correlates with higher pass@K and better TTS gains.
- **Core assumption:** Performance scaling in complex reasoning can be driven by increasing interaction diversity *orthogonal* to model size.
- **Evidence anchors:** [abstract] "The method uncovers a scaling law: transitioning from single-agent → homogeneous multi-role → heterogeneous multi-agent progressively raises RL performance ceilings, enhances test-time scaling, and increases policy diversity." [section 3.2–3.4] Presents comparative results and Figure 8 (three-stage scaling), showing performance gaps between Homo-MARS2 and Heter-MARS2. [section 4] Diversity analysis tables (Table 3) show NAUADC/EA/G-Vendi improvements with more/heterogeneous agents.
- **Break condition:** Beyond a certain heterogeneity threshold, coordination breakdown may occur (e.g., agents failing to align on shared subgoals), causing collaborative performance to drop—though not observed in current experiments up to 3 agents.

## Foundational Learning
- **Group Relative Policy Optimization (GRPO)**: *Why needed here:* MARS² builds upon GRPO, replacing single-agent groups with agent-specific experience buffers and group-level advantage estimation. Understanding GRPO's critic-free advantage normalization is key. *Quick check:* How does GRPO compute advantages without a value network, and why is this suitable for multi-agent settings?
- **Adaptive Branching Monte Carlo Tree Search (AB-MCTS)**: *Why needed here:* MARS²-T+ extends AB-MCTS's node selection (GEN/CON via Thompson sampling) with depth guidance and error feedback. AB-MCTS is the baseline TTS method that MARS²-T+ improves upon. *Quick check:* How does AB-MCTS balance exploration (GEN) and exploitation (CON) using Beta posteriors, and what are its limitations in multi-agent refinement?
- **Multi-Agent Reinforcement Learning (MARL) Parameter Sharing**: *Why needed here:* The paper's scaling law hinges on the distinction between homogeneous (shared parameters) and heterogeneous (independent parameters) agents. The trade-off between sample efficiency (homogeneous) and diversity (heterogeneous) is central. *Quick check:* What are the pitfalls of parameter sharing in MARL (e.g., policy collapse), and how does asynchronous buffer updating in MARS² mitigate some issues?

## Architecture Onboarding
- **Component map:** Policy models (agents) → Tree search engine → Advantage calculator → Asynchronous buffer system → Dynamic trainer; Reward model (trained on trajectories) → MARS²-T+ inference module.
- **Critical path:**  
  1. Training rollout: For each problem, tree search runs; at each node an agent is selected (Beta prior), then action (GEN/CON) chosen; code validated → binary reward; trajectories collected per agent into buffers.  
  2. Async update: When an agent’s buffer fills, its policy (θ_j) is updated using GRPO-style objective on its data while other agents continue rollouts.  
  3. RM training: After sufficient rollouts, aggregate (x, y, r) pairs train the RM offline.  
  4. Inference: MARS²-T+ runs tree search with error feedback and depth guidance; among nodes passing public tests, the highest RM score is selected.
- **Design tradeoffs:**  
  *Homogeneous vs. heterogeneous:* Shared parameters enable sample efficiency but risk early convergence; independent parameters preserve diversity but require more data and may destabilize training (addressed by MARS²+ tricks).  
  *Search depth vs. width:* Depth guidance encourages deeper refinement but risks computational waste on unproductive branches; vanilla TTS favors shallow breadth.  
  *RM fidelity vs. generalization:* RM trained on policy-generated solutions risks reward hacking; using diverse trajectories and held-out benchmarks is critical.
- **Failure signatures:**  
  Stagnant Pass@1 during training → likely homogeneous policy convergence; monitor reward standard deviation across tree nodes.  
  Excessive response length and KL divergence → model "cheating" via verbosity or off-policy drift.  
  Shallow node distribution (>90% in top 3 layers during TTS) → insufficient depth guidance.  
  High variance in Pass@1(MCTS) across budgets → unstable candidate selection or RM misalignment.
- **First 3 experiments:**  
  1. Reproduce Homo-MARS² on 8B Qwen3: train with shared parameters, two roles, 100 steps; verify Pass@1 improvement over GRPO and observe convergence plateau.  
  2. Switch to Heter-MARS² (same models): compare Pass@1 trajectories; expect higher ceiling and no late-stage stagnation; measure buffer imbalance to confirm asynchronous training.  
  3. Run MARS²-T+ vs. Vanilla TTS on trained Heter-MARS² agents: use 60-node budget; validate depth distribution shift and Pass@1(MCTS) uplift; ablate RM and depth weighting to isolate contributions.

## Limitations
- Exact hyperparameters (Beta prior values, depth-weighting decay schedule, RM training configuration) are unreported, hindering precise replication.
- Evaluation is limited to LiveCodeBench and DeepCoder; generalization to other code benchmarks or domains is unknown.
- The scalability thresholds (e.g., coordination breakdown beyond 3 agents) are not explored; the scaling law's upper bounds remain uncertain.

## Confidence
- Scaling law claim (single→homo→hetero progress): **High**
- MARS²-T+ inference gains: **Medium**
- Diversity as primary driver: **Medium-High**
