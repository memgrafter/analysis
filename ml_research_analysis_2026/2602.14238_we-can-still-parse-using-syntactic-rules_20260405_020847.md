# We can still parse using syntactic rules

## Quick Facts
- arXiv ID: 2602.14238
- Source URL: https://arxiv.org/abs/2602.14238
- Reference count: 6
- Primary result: Rule-based parser achieves UAS 54.5% (dev) and 53.8% (test) on Universal Dependencies English treebanks, comparable to spaCy's 56.9% and 58.6%.

## Executive Summary
The paper explores whether syntactic parsing remains relevant in the era of transformers, proposing a novel rule-based parser that produces both dependency and constituency trees and is robust to noise such as disfluencies, punctuation, and HTML. The core method employs incremental left-to-right parsing guided by handcrafted GPSG-style rules featuring slash features to handle long-distance dependencies (e.g., relative clauses) without transformations. A custom RNN POS tagger supplies multiple weighted POS hypotheses, and a Dijkstra-like algorithm connects parsed chunks into a full tree with reranking. Evaluated on Universal Dependencies English treebanks, the system achieves average Unlabeled Attachment Scores of 54.5% on development (7 corpora) and 53.8% on test (12 corpora), approaching state-of-the-art neural parser performance (spaCy). Rule set expansion markedly improves accuracy, and the approach offers interpretability and dual structural outputs, positioning it as a candidate for explainable AI.

## Method Summary
The parser processes pre-tokenized sentences from Universal Dependencies v2.0 English treebanks (CoNLL-U format). It begins with a custom RNN POS tagger trained on UD English training data, which outputs a probability distribution over XPOS tags for each token, allowing multiple tag hypotheses. The incremental parser then constructs phrase structures token-by-token. Phrases are objects indexed by their span (start and end positions) and category. Handcrafted GPSG-style rules (145 for main results) are applied incrementally: binary rules combine adjacent phrases (with potential token skipping to accommodate noise), while unary rules project single phrases upward. If a full-span parse is not achieved, all generated phrases (chunks) are nodes in a graph; a Dijkstra-variant finds the lowest-cost path covering the sentence, connecting chunks while penalizing multiple heads and unparsed spans. A reranker selects the best full parse, which is exported simultaneously as a dependency tree (via head pointers) and a constituency tree (via phrase spans). The codebase, including rules and tagger, is provided in a GitLab repository.

## Key Results
- Unlabeled Attachment Score (UAS): 54.5% on development (7 UD corpora), 53.8% on test (12 UD corpora).
- Performance comparable to spaCy’s dependency parser (56.9% dev, 58.6% test) despite using a rule-based approach.
- Rule count scaling: UAS rises from 31.1% (63 rules) to 54.5% (145 rules) on dev set, highlighting coverage importance.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** GPSG-style rules with slash features enable handling of syntactic gaps (e.g., relative clauses) without transformational movement.
- **Mechanism:** Phrases are annotated with features (e.g., `VP/NP`) representing missing constituents. Rules like `NP → NP S/NP` project a gap-containing phrase (`S/NP`) up the tree, linking it to a filler (`NP`). This allows incremental left-to-right construction of long-distance dependencies.
- **Core assumption:** Syntactic gaps can be resolved via local feature passing and rule application, avoiding global transformations.
- **Evidence anchors:**
  - [abstract] Mentions "GPSG-style rules (e.g., slash features for gaps like 'The man I met')".
  - [section 2] Reviews GPSG's slash feature approach for gaps versus transformational grammar.
  - [section 3.1] Provides concrete rule examples: `VP-O/NP` for a VP missing an object, and `NP → NP ^S/NP` for filler-gap resolution.
  - [corpus] Corpus signals show related work on grammar-constrained decoding (e.g., "Flexible and Efficient Grammar-Constrained Decoding"), but direct evidence from this paper's evaluation is limited to qualitative examples (Figure 4) without quantitative gap-specific metrics.
- **Break condition:** If gaps require contextual or discourse-level information beyond local syntactic rules (e.g., island constraints, pragmatics), the slash feature mechanism may overgenerate or fail.

### Mechanism 2
- **Claim:** A custom RNN POS tagger producing multiple weighted tags enables the parser to explore ambiguous taggings, generating diverse parse hypotheses for reranking.
- **Mechanism:** For each token, the tagger outputs a probability distribution over possible XPOS tags. The parser creates phrase objects for each plausible tag, allowing parallel projection via rules. Weights propagate upward (sum of child weights), providing a scoring signal for final reranking.
- **Core assumption:** Syntactic ambiguity often originates at the POS level; maintaining multiple tag hypotheses preserves structural alternatives until later disambiguation.
- **Evidence anchors:**
  - [abstract] States "custom RNN POS tagger delivering probabilistic tags for multiple hypotheses".
  - [section 3.2.2] Describes the RNN tagger trained on UD data, outputting tag probabilities with cutoffs.
  - [section 3.2.7] Notes that phrase weight is the sum of children’s weights, inheriting tag uncertainty.
  - [corpus] Corpus evidence is indirect: scaling from 63 to 145 rules improved UAS by >20 points (Section 5), but the separate impact of multiple POS hypotheses vs. rule coverage is not isolated in experiments.
- **Break condition:** If tag probabilities are too diffuse (many tags with similar scores), the hypothesis space may become combinatorially large without improving accuracy, or if the tagger’s training domain mismatches test data, key tags may be omitted.

### Mechanism 3
- **Claim:** Connecting independently parsed chunks via a Dijkstra-like shortest-path algorithm and heuristic reranking handles noise and incomplete parses.
- **Mechanism:** The incremental parser may leave gaps (unparsed tokens) due to disfluencies or out-of-coverage rules. All generated phrases (chunks) are nodes in a graph; edges connect chunks that are adjacent or skip noise. The algorithm finds a minimum-cost path covering the sentence, with costs penalizing multiple heads or unparsed spans. Reranking selects the best full-span parse.
- **Core assumption:** Local parses are reliable building blocks; a global optimization over chunk sequences can yield a coherent full parse despite noise.
- **Evidence anchors:**
  - [abstract] Explicitly mentions "Chunks are connected via Dijkstra's algorithm and reranked."
  - [section 3.2.8] Details the variant of Dijkstra’s for connecting chunks and the scoring function (penalizing multiple heads, unparsed tokens).
  - [section 3.2.6] Notes that rule scanning allows skipping tokens, enabling noise accommodation.
  - [corpus] Performance on UD datasets (which include some noise) is reported, but no controlled experiment isolates the chunk-connection component’s contribution vs. rule-based projection.
- **Break condition:** If noise creates excessive small chunks (e.g., many disfluencies), the graph may have many invalid connections, or the heuristic scoring may fail to preference the correct path, especially with long gaps.

## Architecture Onboarding
- **Component map**: Tokenizer -> POS Tagger -> Phrase Creator/Indexer -> Rule Scanner -> Adjacent Phrase Finder -> Phrase Projector -> (iterative reprojection) -> Chunk Connector -> Reranker -> Exporter
- **Critical path**: Tokenization → POS tagging (multiple hypotheses) → phrase creation & indexing → iterative rule scanning & projection (binary/unary) → chunk connection (if no full-span parse) → reranking → export.
- **Design tradeoffs**:
  - Rules vs. coverage: Handcrafted rules ensure interpretability but limit domain coverage; adding rules improves UAS but increases complexity and risk of overfitting.
  - Incremental vs. global: Left-to-right projection is efficient and handles noise via skipping, but may miss non-local dependencies that require lookahead or backtracking.
  - Chunk connection vs. full parse: Dijkstra stitching allows partial parses but may incorrectly connect unrelated chunks if gap penalties are poorly tuned.
- **Failure signatures**:
  - Many unparsed tokens in final output (chunk connection failed).
  - Phrases with multiple heads (violates tree constraint; penalized by reranker).
  - UAS significantly below baseline (e.g., spaCy) on certain UD corpora (indicating rule gaps).
  - Combinatorial explosion in phrase hypotheses without convergence (POS tag probabilities too uniform).
- **First 3 experiments**:
  1. Rule scaling validation: Train with increasing rule set sizes (e.g., 63, 100, 145 rules) on UD dev set; measure UAS improvement to confirm coverage hypothesis.
  2. Gap handling test: Construct minimalist test set with relative clauses, wh-movement, and coordinated gaps; manually verify correct slash feature application and filler-gap links in output.
  3. Noise robustness check: Add artificial disfluencies (e.g., "uh", "you know") and punctuation noise to UD sentences; compare UAS with and without the chunk-connection/Dijkstra component enabled.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** What is the asymptotic computational complexity of the incremental left-to-right parsing algorithm with Dijkstra-based connection when scaling to longer sentences or larger rule sets?
- **Basis in paper:** [inferred] The method uses an incremental scan with phrase indexing and Dijkstra's algorithm to connect parsed chunks, but the paper reports no formal time complexity analysis or empirical scaling benchmarks (e.g., parse time vs. sentence length). The rule scanning and adjacent phrase scanning steps suggest potential O(n²) or worse behavior in worst-case scenarios.
- **Why unresolved:** Without a complexity analysis or runtime measurements, it is unclear whether the approach can efficiently process lengthy, noisy, or domain-specific texts (e.g., documents with HTML/emojis) compared to neural parsers that often have more predictable O(n³) bounds. The claim of handling noise via token skipping may increase combinatorial search.
- **What evidence would resolve it:** Formal analysis of the algorithm's worst-case and average-case time/space complexity, coupled with empirical benchmarks measuring parse time and memory usage across varying sentence lengths (e.g., UD sentences vs. web text) and rule set sizes (e.g., 63 vs. 145 rules).

### Open Question 2
- **Question:** To what extent does the handcrafted rule set generalize across different English domains (e.g., social media, literary text) beyond the Universal Dependencies treebanks used for training and evaluation?
- **Basis in paper:** [explicit] The parser was tested only on UD English dev/test sets (12 corpora). The authors state the rules are a "small subset" and "do not represent a comprehensive listing of English syntactic rules." They also note the system accommodates noise like HTML and disfluencies, but all evaluation is on formally annotated newswire/web text.
- **Why unresolved:** UD treebanks are predominantly newswire and web text with controlled annotation. Performance on truly noisy, informal, or domain-shifted data (e.g., tweets, novels, medical notes) is unknown. The handcrafted rules may not capture domain-specific constructions or colloquialisms, limiting real-world applicability.
- **What evidence would resolve it:** Evaluation on out-of-domain corpora (e.g., COCA, Twitter, clinical notes) with metrics like UAS and precision/recall on non-canonical structures (disfluencies, fragments). Error analysis comparing rule-coverage gaps across domains.

### Open Question 3
- **Question:** Can the dual-paradigm output (joint dependency and constituency structures) demonstrably improve performance on downstream NLP tasks compared to using either structure alone, as implied by the paper's motivation?
- **Basis in paper:** [explicit] The paper emphasizes producing "both dependency and constituency parse trees" as a key advantage, leveraging strengths of both paradigms. However, no downstream task evaluation (e.g., semantic role labeling, machine translation, information extraction) is presented.
- **Why unresolved:** While the combined representation is theoretically richer, it is unclear if this richness translates to practical gains. Downstream models are typically designed for either dependency or constituency inputs; the utility of a hybrid format is untested. The paper only reports UAS against spaCy's dependency parser.
- **What evidence would resolve it:** Controlled experiments where downstream systems are fed (a) dependency-only parses, (b) constituency-only parses, and (c) the proposed dual-structure output from this parser, measuring task-specific metrics (e.g., F1 for SRL, BLEU for MT). Analysis of where the dual structure provides unique information.

### Open Question 4
- **Question:** How does the accuracy of the custom RNN POS tagger, which provides multiple hypotheses with probabilities, impact the overall parser performance relative to using a state-of-the-art neural tagger (e.g., BERT-based) that may have higher single-tag accuracy but fewer hypotheses?
- **Basis in paper:** [inferred] The parser relies on a "custom POS tagger based on RNNs" to generate multiple tag probabilities per token, enabling multiple parse hypotheses. The paper does not compare this tagger to modern alternatives or ablates the effect of hypothesis multiplicity on final UAS. The scaling experiment (63 vs. 145 rules) confounds rule quantity with tagger accuracy.
- **Why unresolved:** It is unknown whether the parser's performance is limited by POS tagging errors or by rule coverage. The multi-hypothesis approach is central to handling ambiguity, but its contribution relative to tagger quality is unmeasured. Modern taggers may provide more accurate single tags but fewer alternatives, potentially harming recall for ambiguous constructions.
- **What evidence would resolve it:** Ablation study: (1) replace custom tagger with a state-of-the-art tagger (e.g., from Flair or Stanza) while preserving multi-hypothesis capability; (2) fix tagger and vary rule set size; (3) measure UAS and oracle accuracy (best parse among hypotheses). This would isolate the tagger's impact.

### Open Question 5
- **Question:** Can the proposed rule-based framework be extended to other languages with minimal linguist effort, as suggested, or does it require extensive language-specific rule engineering that undermines the claim of broad applicability?
- **Basis in paper:** [explicit] The conclusion states: "it is possible to expand to any new language" requiring "an inventory of possible POS tags, categories and features" and "certain CFG/GPSG rules." However, the system is evaluated only on English, and no multilingual experiments are reported.
- **Why unresolved:** The effort to create rule sets for typologically diverse languages (e.g., morphologically rich, free-word-order) is unknown. The paper's rules are tailored to English-specific phenomena (auxiliary sequences, NP compounding). Languages with different syntactic primitives (e.g., morphology-driven agreement, clitic pronouns) may need fundamentally different rule architectures, challenging the "expand to any language" claim.
- **What evidence would resolve it:** Implement and evaluate the parser on at least three diverse UD languages (e.g., Finnish, Turkish, Japanese) using language-specific rule sets. Measure (a) rule development effort (person-hours), (b) coverage of language-specific constructions, and (c) UAS relative to language-specific state-of-the-art parsers. Compare to cross-linguistic rule induction attempts.

## Limitations
- Exact rule set (145 rules) and RNN tagger hyperparameters are unreported, hindering faithful reproduction.
- The isolated impact of the chunk-connection (Dijkstra) component is unmeasured; it may be critical for noise but could overconnect in highly disfluent text.
- No controlled experiments on noise (e.g., artificial disfluencies) demonstrate the claimed robustness.

## Confidence
- GPSG slash features enable gap handling: **High**
- Reported UAS near spaCy: **Medium**
- Dijkstra chunk connection handles noise: **Low**
