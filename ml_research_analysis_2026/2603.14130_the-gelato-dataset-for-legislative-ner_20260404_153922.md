# The GELATO Dataset for Legislative NER

## Quick Facts
- **arXiv ID:** 2603.14130
- **Source URL:** https://arxiv.org/abs/2603.14130
- **Reference count:** 0
- **Primary result:** RoBERTa achieves 88.72 F1 on coarse-level legislative NER; an LLM-based second stage for fine-grained subtypes drops 14–20 points due to error propagation, while high inter-annotator agreement (up to 80.09 F1) validates dataset quality.

## Executive Summary
This paper introduces GELATO, the first dedicated dataset for U.S. legislative named entity recognition, featuring a two-level ontology (6 coarse classes, 30 fine subtypes). The authors implement a two-stage pipeline: fine-tuning transformer encoders (BERT, RoBERTa) for coarse classification, then using optimized prompts with a large language model (Qwen-32B) to predict subtypes. Results show RoBERTa dramatically outperforming BERT on level-one tasks (88.72 vs. 68.09 F1), but level-two performance suffers a 14–20 point drop due to cascading errors from the first stage. High inter-annotator agreement confirms the ontology’s clarity and the dataset’s reliability.

## Method Summary
The method uses a sequential two-stage pipeline. First, transformer models (BERT-base/large, RoBERTa-base/large) are fine-tuned on the GELATO training set (80 House bills) with hyperparameters optimized via Bayesian search. These models perform token-level classification into six coarse entity types. Second, for each predicted entity span, the pipeline extracts a 50-token context window and the predicted coarse label, then queries a frozen Qwen-32B model via prompts optimized with DSPy/MiPROv2 to select the correct fine-grained subtype from the ontology. Performance is evaluated with token-level F1 separately for both levels, including an oracle condition where stage two receives gold-level inputs.

## Key Results
- RoBERTa-large achieves a level-one F1 of 88.72, vastly exceeding BERT-large’s 68.09.
- Level-two F1 drops 14–20 points relative to level-one due to error propagation from the first stage.
- Inter-annotator agreement reaches up to 80.09 pairwise token F1, supporting the ontology’s design and annotation consistency.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** RoBERTa’s larger vocabulary and more diverse pretraining enable superior handling of legislative text’s rare tokens and dense punctuation compared to BERT.
**Mechanism:** RoBERTa’s byte-level BPE tokenization (~50k vocabulary) vs. BERT’s WordPiece (~30k) reduces unknown tokens, while pretraining on the larger CC-100 corpus exposes the model to varied governmental/legal structures. This aligns with findings that domain-agnostic models benefit from robust lexical coverage on specialized text.
**Evidence:** [Abstract] notes the 88.72 vs. 68.09 F1 gap; [Section 7] explicitly links RoBERTa’s strength to vocabulary and data diversity; [Section 8] suggests BERT-era models may need architectural adjustments to match RoBERTa.

### Mechanism 2
**Claim:** The two-stage decomposition (coarse classification → LLM-based subtype resolution) effectively manages a complex, multi-level ontology by leveraging each component’s strengths.
**Mechanism:** Stage one efficiently extracts broad entity spans using fine-tuned transformers. Stage two uses a large, knowledge-rich LLM (Qwen-32B) with optimized prompts to perform nuanced subtype disambiguation without retraining, relying on the LLM’s internal world knowledge and the prompt optimizer (DSPy) to align few-shot examples with annotation guidelines.
**Evidence:** [Abstract] describes the pipeline; [Section 4] details the two-stage flow; [Section 5.2] shows level-two F1 (e.g., 67.44) and the oracle gap (e.g., 76.60) revealing potential when stage one is accurate; [Section 6] justifies LLM choice for generalizability.

### Mechanism 3
**Claim:** High inter-annotator agreement validates the GELATO ontology and guidelines as a stable, reproducible framework for legislative NER.
**Mechanism:** Rigorous annotation (two-step process, group adjudication) and clear, non-overlapping span rules yield consistent human labels, as measured by pairwise token F1 (66.35–80.09). This consistency suggests the ontology captures linguistically distinguishably categories, a prerequisite for model learnability.
**Evidence:** [Abstract] cites IAA up to 80.09; [Section 3.3] describes the annotation workflow; Table 2 reports the IAA scores.

  - **Why needed:** Stage two relies on eliciting accurate subtype predictions from a frozen LLM via crafted prompts that include context and valid labels; optimization (e.g., DSPy) aligns the LLM’s few-shot capabilities with specific annotation rules.

## Architecture Onboarding
- **Component map:**
  Congress.gov API -> Custom tokenization (split punctuation) -> First-Level NER (roberta-large fine-tuned) -> Span extraction & context windowing (±50 tokens) -> LLM Prompter (DSPy-optimized per coarse tag) -> Qwen-32B inference -> Subtype prediction -> Evaluation (SeqScore F1)
- **Critical path:** Data ingestion → First-level training/inference → Span extraction → Context windowing → LLM prompt routing → Subtype prediction → Scoring. The pipeline is strictly sequential; first-stage errors permanently corrupt downstream outputs.
- **Design tradeoffs:**
  - **Error propagation vs. Annotation cost:** The two-stage design reduces human annotation burden (only coarse + subtype mappings needed) but makes level-two performance strictly bounded by level-one accuracy.
  - **LLM cost vs. Flexibility:** Using a 32B model (Qwen) leverages embedded knowledge but requires significant GPU memory (vLLM) and incurs high latency/cost per token compared to a smaller distilled model.
  - **Context window size (50 tokens):** Chosen to balance disambiguation and prompt length/cost; larger windows may help but increase computational overhead.
- **Failure signatures:**
  - **Level-one:** Very low `Class` F1 (~27.52) across models, with frequent confusion against `Person` and omission as 'O'.
  - **Level-two:** Subtypes with minimal training support (e.g., `Case`, `Treaty` count=0) yield F1=0; LLM refusal cases occur when no provided tag fits; persistent confusion between `Member` and `Name`.
  - **Systematic:** LLMs struggle with abstract/sub-referential types like `Parenthetical` (F1=13.33), suggesting ontological ambiguity.
- **First 3 experiments:**
  1. Replicate baseline: Fine-tune `roberta-large` with hyperparameters from Table 5 on train/dev; report test level-one F1 (expect ~88.72).
  2. Quantify error propagation: Run full two-stage pipeline; then run stage two oracle using gold-level-one spans/contexts. Compute overall and per-tag delta in level-two F1 (expect 14–20 point drop).
  3. LLM prompt stress test: For a low-performing subtype (e.g., `Parenthetical`), collect 20 false positives from stage-one predictions. Run them through the optimized prompt with `temperature=0`. Analyze LLM reasoning outputs for guideline misinterpretation.

## Open Questions the Paper Calls Out
- **Open Question 1:** What causes the systematic failure to detect `Class` entities in legislative NER, and how can models be trained to overcome this? The paper notes an open challenge in differentiating `Class` from general lexical items and `Person`, likely due to subtle linguistic cues and scarce training examples.
- **Open Question 2:** How can the two-stage NER pipeline be redesigned to prevent error cascades and improve fine-grained entity classification accuracy? The rigid dependency on first-stage predictions caps overall performance; alternative architectures (e.g., joint multi-task learning) are needed.
- **Open Question 3:** What ontological design principles ensure optimal fine-grained NER when using LLMs, minimizing semantic confusion in domain-specific tasks like legislation? LLMs struggle with semantically similar subclasses (e.g., `Member` vs. `Name`), indicating a need for clearer distinction in the guideline design.

## Limitations
- The two-stage design suffers from irrecoverable error propagation; level-two performance is fundamentally capped by level-one accuracy, as seen in the 14–20 point F1 drop.
- Dataset and codebase accessibility are unverified; the exact GitHub repository (`https://github.com/Wollaston/gelato`) and tokenization scripts (punctuation splitting) are not confirmed, blocking faithful replication.
- The LLM-based second stage is computationally expensive (32B model) and sensitive to prompt optimization; performance plummets for rare subtypes (e.g., `Parenthetical`) and when level-one errors occur.

## Confidence
- **RoBERTa superiority:** High — Strong empirical F1 gap (88.72 vs. 68.09) and mechanistic justification via vocabulary/pretraining are clearly stated and tested.
- **Two-stage viability:** Medium — Demonstrated but conditional; performance is promising only with accurate level-one inputs, and error sensitivity is well-documented.
- **IAA as validation:** High — Detailed annotation process and reported F1 scores (up to 80.09) provide solid evidence for dataset reliability, though model errors on high-IAA categories suggest subtle linguistic boundaries.
