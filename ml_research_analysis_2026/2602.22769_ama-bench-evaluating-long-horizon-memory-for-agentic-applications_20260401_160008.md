# AMA-Bench: Evaluating Long-Horizon Memory for Agentic Applications

## Quick Facts
*   **arXiv ID:** 2602.22769
*   **Source URL:** https://arxiv.org/abs/2602.22769
*   **Reference count:** 40
*   **Primary result:** AMA-Agent achieves 57.22% average accuracy on AMA-Bench, outperforming the strongest baseline (HippoRAG2) by 11.16%.

## Executive Summary
This paper introduces AMA-Bench, a benchmark designed to evaluate long-horizon memory for LLM agents using real-world and synthetic trajectories with machine-generated, causally-grounded interactions. It identifies a key gap: existing memory systems fail due to lossy compression and similarity-based retrieval that cannot handle the objective state changes in agent logs. To address this, the authors propose AMA-Agent, which employs a causality graph to preserve state transitions and a tool-augmented retrieval mechanism that combines embedding search with graph traversal and programmatic keyword lookup. Results on AMA-Bench demonstrate that specialized, agent-centric memory design—not merely scaling the base model—is the primary bottleneck for long-horizon agent performance.

## Method Summary
AMA-Bench comprises trajectories from six real-world domains (e.g., web navigation, software engineering) and two synthetic environments (BabyAI, TextWorld), each paired with question-answer sets across four categories: Recall, Causal Inference, State Updating, and State Abstraction. AMA-Agent operates in two stages. First, it constructs a **causality graph** by parsing each turn pair `(ot−1, at, ot)` to extract discrete state nodes (environment, objective inventory) and directed causality edges (state transitions) plus undirected association edges (turn-wise links). Second, for a given query, it performs hybrid **tool-augmented retrieval**: an initial embedding-based node search is followed by a self-evaluation step; if evidence is insufficient, the system routes to either graph node traversal (for causal context) or a keyword/code tool (for exact pattern matching). The final answer is synthesized from the retrieved evidence using a frozen LLM.

## Key Results
*   AMA-Agent achieves a **57.22% average accuracy** on AMA-Bench, **surpassing HippoRAG2 by 11.16%**.
*   **Ablation studies** confirm the necessity of both core components: removing the causality graph or tool-augmented retrieval causes **22–32% performance drops**.
*   Analysis reveals that **memory architecture design** (e.g., lossy compression) accounts for far greater performance variance than scaling the base language model (e.g., 8B→32B yields only 0.038 gain vs. 0.45 architecture gap).

## Why This Works (Mechanism)

### Mechanism 1: Causality Graph Preserves State Integrity
**Claim:** Explicitly modeling environmental and objective state changes via a causality graph prevents information loss during memory construction, addressing the core limitation of lossy compression for agent trajectories.
*   **Mechanism:** The system parses adjacent turn pairs `(ot−1, at, ot)` to extract discrete state nodes (environment state, object state) and directed causality edges (state transitions) plus undirected association edges (turn-wise associations). This creates a structured graph where each node represents a verifiable state snapshot, and edges encode deterministic dependencies between actions and state changes.
*   **Core assumption:** Agent trajectories contain dense, objective state transitions that are causally linked; preserving these links is more valuable than compressing raw text for retrieval accuracy.
*   **Evidence anchors:** Abstract states the approach "addresses these limitations... with a causality graph for preserving objective state information"; Section 5.1 details the construction pipeline; Section 4 (Motivation 3) shows MemoryBank's 41.3% drop from lossy compression.

### Mechanism 2: Tool-Augmented Retrieval Overcomes Similarity Limits
**Claim:** Supplementing embedding-based retrieval with structured graph traversal and programmatic keyword search mitigates the insufficiency of pure similarity search for precise, multi-hop evidence in machine-generated logs.
*   **Mechanism:** After top-K embedding retrieval, the agent self-evaluates evidence sufficiency. If insufficient, it routes to either graph node search (traversing neighborhood edges for causal context) or keyword search (executing user-written script for exact pattern matching/aggregation). This hybrid approach accesses evidence that semantic similarity may miss.
*   **Core assumption:** Similarity rankings are brittle for structured artifacts (tables, code snippets) and multi-step causal queries; direct graph traversal or script execution provides deterministic access.
*   **Evidence anchors:** Abstract mentions "tool-augmented retrieval mechanism... transcends the limitations of similarity-based retrieval"; Section 5.2 describes the three-stage retrieval; Section 4 (Motivation 3) notes HippoRAG2's 43.2% end-to-end drop despite strong constructed memory.

### Mechanism 3: Agent-Centric Design Trumps Scale
**Claim:** Performance bottlenecks in long-horizon memory stem primarily from memory architecture design (lossy compression, similarity retrieval) rather than base model scale.
*   **Mechanism:** By substituting specialized components (causality graph, tool-augmented retrieval) for generic long-context or RAG designs, the system sidesteps compounding errors from lossy processing. The architecture is tailored to the *structure* of agent trajectories (dense, objective, causal) rather than natural language redundancy.
*   **Core assumption:** The information density and causal grounding of machine-generated trajectories require a fundamentally different memory organization than dialogue-centric or document-based contexts.
*   **Evidence anchors:** Abstract states "agent-centric memory design, rather than model scale, is the key bottleneck"; Figure 7 shows scaling from 8B→32B yields minimal gain (0.038) vs. architecture variance (0.45); Section 3 contrasts AMA-Bench's machine-generated trajectories with NL-centric benchmarks.

## Foundational Learning
*   **POMDP Formalization for Agents:** The framework models agents in partially observable environments (`st` latent, `ot` observation). Memory `mt` augments policy `π(a|q, ct)` to compress/select from history `ht` beyond context limits. **Quick check:** Why can't the agent simply use full `ht` as context without memory? (Answer: Context window limits + need to persist across episodes; memory selects/compresses relevant history.)
*   **Lossy vs. Lossless Memory Construction:** Existing systems use lossy compression (summaries, facts) that discards objective state details. AMA-Agent's causality graph aims for lossless state representation. **Quick check:** Why might summarizing "the agent picked up the key" lose information needed for later queries compared to storing `in(key, inventory)` as a state node? (Answer: Summaries may omit precise timestamps, object IDs, or chain-of-thought linking to subsequent actions.)
*   **Trajectory-Grounded QA Taxonomy:** The four categories (Recall, Causal Inference, State Updating, State Abstraction) define *what* memory must support and map to observed baseline failure modes. **Quick check:** Give an example of a Type B (Causal Inference) question that would fail under pure similarity retrieval but succeed with a causality graph. (Answer: "What precondition must be true before executing action X?" requires following a causality edge backward, not matching text.)

## Architecture Onboarding
Trajectory Ingestor -> Causality Graph Builder -> Hybrid Retriever -> Answer Synthesizer. The critical path is: Ingest trajectory -> Build global causality graph (one-time) -> On query: similarity search over graph nodes -> self-evaluate sufficiency -> if insufficient, invoke graph traversal or keyword/code tool -> synthesize answer from retrieved evidence. Design tradeoffs include: high LLM cost for graph construction vs. retrieval gains; tool routing latency overhead (observed in ~30-40% of queries); dependence on embedding model quality (`Qwen3-4B-embedding`). Failure signatures: missing causality edges (check extractor prompt adherence); tool misuse by router (monitor routing distribution vs. query type); answer hallucination despite retrieval (verify evidence injection). First three experiments: 1) Run ablations (`w/o Causality Graph`, `w/o Tool-Augmented`) to confirm Tab 6 drops; 2) Execute the synthetic needle-in-haystack test (Appendix F) to measure exact needle turn retrieval rate (expect >90% for graph+tool vs. ~50% for similarity-only); 3) Profile component latency (graph construction cost amortization, tool call duration).

## Open Questions the Paper Calls Out
*   **Cross-Task Lifelong Learning:** How can memory mechanisms extend to consolidate and retrieve memories across multiple episodes/tasks, not just within a single trajectory? The paper explicitly notes this as a limitation ([conclusion]). Evidence needed: multi-task benchmarks measuring transfer/forgetting; graph modification strategies across tasks.
*   **Extraction Error Analysis:** What specific causal relationships/state transitions are most prone to errors during causality graph construction, and how do these propagate to retrieval failures? Inferred from lack of error analysis in Section 5.1 and needle ablation results. Evidence needed: ground-truth state comparisons from synthetic backends; correlation of extraction error rates with QA performance by category.
*   **Self-Evaluation Router Reliability:** Under what conditions does the self-evaluation step misclassify evidence sufficiency, affecting accuracy and efficiency? Inferred from the heuristic router (Appendix D.2) being untested. Evidence needed: annotations of whether initial top-K nodes contained answers; calibration metrics (accuracy when router says "SUFFICIENT" vs. "NEED_GRAPH").
*   **Synthetic vs. Real-World Generalization:** To what extent do BabyAI/TextWorld synthetic tasks capture real-world agent diversity, and are there domain-specific failure modes synthetic data misses? Inferred from Fig 9A showing non-perfect correlation. Evidence needed: domain-wise correlation breakdown; new synthetic tasks with richer artifacts (JSON logs, code diffs) to probe gaps.

## Limitations
*   **Implementation Opacity:** Exact graph schema, traversal depth limits, and storage format are unspecified, hindering faithful reproduction.
*   **Tool Routing Heuristics:** Thresholds for "insufficient evidence" judgment and sandboxed code execution details are opaque, introducing a brittle point.
*   **External Validation Scarcity:** 0 citations and low FMR (~0.5) suggest limited independent scrutiny; generalizability beyond AMA-Bench remains unproven.

## Confidence
*   **Causality Graph Efficacy:** High – reinforced by strong ablation evidence (22–32% drop) and clear mechanistic design, though schema details could affect implementation fidelity.
*   **Tool-Augmented Retrieval:** Medium – self-evaluation router adds a brittle point; success hinges on unstated thresholds. Needle tests support it, but real-world query distribution impact is unknown.
*   **Agent-Centric > Scale:** High – Figure 7 shows scale gains minimal vs. architecture variance. However, this may not hold for extremely short or purely narrative trajectories.

## Next Checks
1.  **Needle Hit Rate Replication:** Run the synthetic needle-in-haystack test (Appendix F). A faithful reimplementation should achieve >90% exact needle turn retrieval via graph/tool vs. ~50% for pure similarity.
2.  **Component Isolation Ablation:** Systematically remove *only* the tool router (keep graph traversal default) and *only* the graph (keep tool-augmented similarity). Measure differential impact on the four question categories to validate the claimed 22–32% combined drop.
3.  **Cross-Benchmark Generalization:** Apply AMA-Agent’s construction and retrieval to a different long-horizon agent benchmark (e.g., AgentLAB). A significant performance gap vs. baselines would strengthen the "agent-centric design" claim beyond AMA-Bench’s trajectory distribution.
