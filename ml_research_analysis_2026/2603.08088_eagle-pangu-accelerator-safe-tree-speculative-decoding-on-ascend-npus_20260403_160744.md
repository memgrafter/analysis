# EAGLE-Pangu: Accelerator-Safe Tree Speculative Decoding on Ascend NPUs

## Quick Facts
- **arXiv ID:** 2603.08088
- **Source URL:** https://arxiv.org/abs/2603.08088
- **Reference count:** 5
- **Primary result:** Achieves a 1.27× mean end-to-end decoding speedup over teacher-only greedy decoding on Ascend NPUs.

## Executive Summary
Tree speculative decoding accelerates LLM inference by verifying multiple draft tokens per teacher step, but porting it to heterogeneous accelerator backends like Ascend NPUs is brittle due to mismatched KV-cache layouts, attention masking, and indexing semantics. EAGLE-Pangu addresses these challenges for Pangu teachers with three core contributions: a branchable KV-cache manager separating committed and speculative states, an accelerator-safe tree tensorization scheme using a dummy-root index to eliminate undefined negative indices, and a fused-kernel-compatible teacher verification path with an eager fallback. On 240 turns from MT-Bench and HumanEval, it delivers a mean speedup of 1.27× (up to 2.46× at p99). Budget sweeps reveal a configuration sweet spot (M=16, D_max=10) yielding up to 1.48× mean speedup, while naive drafter context truncation harms acceptance and degrades throughput.

## Method Summary
The system introduces a cache abstraction that maintains a committed prefix cache and isolated per-branch speculative caches, ensuring correct state updates after acceptance via length-based or path-index-based commits. Tree tensorization restructures node-indexed tensors by adding a dummy root row (index 0), shifting all indices to non-negative values and enabling safe gather operations. A 4D tree attention mask, derived from an ancestor table, enforces branch isolation during the teacher’s batched forward pass and is designed to be compatible with Ascend’s fused attention kernels, with an eager fallback for debuggability. The implementation toggles between a reference mode (eager attention) for validation and a performance mode (fused kernels) for throughput.

## Key Results
- Mean end-to-end speedup of **1.27×** over teacher-only greedy decoding; p99 speedup reaches **2.46×**.
- Budget sweep identifies an optimal configuration (**M=16, D_max=10**) achieving up to **1.48×** mean speedup.
- Naive context truncation for the drafter significantly reduces token acceptance and harms overall throughput.

## Why This Works (Mechanism)

### Mechanism 1: Branchable KV-Cache Isolation
- **Claim:** A cache abstraction that maintains a committed prefix cache (C⋆) and per-branch speculative caches ({Bi}) prevents state corruption and enables correct updates after acceptance.
- **Mechanism:** At each speculative step, the committed cache is deep-copied to create isolated branch caches. The teacher forward extends only its assigned branch cache. After tree acceptance, the committed cache is updated either by keeping the first *A* steps of the selected branch (length-based commit) or by reordering according to the accepted path indices (path-index-based commit), with a prefix-sharing fast path when possible. Invariants enforce branch independence and commit equivalence to sequential execution.
- **Core assumption:** KV-cache layouts are backend-specific and not trivially copyable; deep copying provides isolation at the cost of memory overhead, but correctness depends on the commit logic reconstructing the exact sequential state.
- **Evidence anchors:** [abstract] "explicit branch/commit cache manager built on the Cache API"; [section 3.1] full description of `Replicate(C⋆)`, commit modes, and invariants; [corpus] weak—neighbors discuss KV-cache and acceleration but not this exact isolation pattern.
- **Break condition:** If the `to_legacy_cache/from_legacy_cache` round-trip fails to preserve backend-specific KV layouts exactly during reordering, the committed cache may diverge from sequential execution, corrupting subsequent decoding.

### Mechanism 2: Dummy-Root Tensorization
- **Claim:** Introducing a dummy root row (index 0) in all node-indexed tensors and shifting IDs eliminates undefined negative sentinel indices, making all gather operations accelerator-safe by construction.
- **Mechanism:** For *M* speculative nodes (excluding root), allocate tensors with an extra row representing the root state (committed prefix). Define `eid(r)=0`, `eid(uk)=k`. Parent pointers `parent[k]` are mapped to `^parent[k] ∈ [0, M]`, where `π(uk)=r` maps to `0`. An ancestor table `A[ℓ,k]` is built recursively (`A[0,k]=k`, `A[ℓ+1,k] = ^parent(A[ℓ,k])`). All subsequent gathers use indices guaranteed to be in `[0, M]`.
- **Core assumption:** The dummy root row accurately represents the committed prefix’s state and that all backend gather primitives accept indices in `[0, M]` without undefined behavior for valid ranges.
- **Evidence anchors:** [abstract] "accelerator-safe tree tensorization that removes undefined negative indices by construction"; [section 3.2] formal definition of `^parent`, `eZ`, `A`, and invariant checks; [corpus] weak—no neighbor validates dummy-root pattern for NPU portability.
- **Break condition:** If the backend’s gather kernel has a hidden upper bound (e.g., `index < max_tensor_dim` but not documented) and `M` exceeds it, or if the dummy root row fails to correctly propagate the committed prefix’s representation to depth-1 nodes, context will be incorrect.

### Mechanism 3: Fused-Kernel-Compatible Tree Masking
- **Claim:** A 4D tree attention mask built from the ancestor predicate (`Anc(j,k)=1` iff *j* is ancestor of *k*) prevents cross-branch leakage while satisfying fused kernel constraints, and an eager fallback ensures debuggability.
- **Mechanism:** For batched speculative tokens of length `M_max`, construct a dense mask `M_tree[k,j] = 0` if `Anc(j,k)=1` and both slots are valid; else `-∞`. This mask is broadcast to the fused kernel’s expected shape (e.g., `[B,1,M_max,M_max]`). Padded slots have `valid[k]=0` and are fully masked. The teacher forward runs with this mask, reading from `C⋆` and writing KV to the selected branch cache. Logits are gathered for proposed tokens `τ[k]` only for `valid[k]=1`.
- **Core assumption:** The fused attention kernel accepts a dense mask with `0`/`-∞` values and that the ancestor predicate computed via `A` exactly matches the intended tree structure. The eager fallback path must implement the same masking semantics.
- **Evidence anchors:** [abstract] "fused-kernel-compatible teacher verification path with a debuggable eager fallback"; [section 3.3] mask construction formula, `Anc` definition via `A`, and safety guarantees; [corpus] weak—neighbors like DeFT and SwiftSpec address tree masking but for different stacks.
- **Break condition:** If the fused kernel’s mask interpretation differs (e.g., expects `bool` mask, different broadcasting), leakage occurs. If the ancestor table `A` is built incorrectly (e.g., not covering all depths), some ancestor relationships are missed, causing invalid attends.

## Foundational Learning
- **Concept: KV caching in autoregressive transformers**  
  *Why needed here:* Tree speculative decoding relies on extending the KV cache from a shared prefix into multiple speculative branches. Understanding how key/value states are stored and updated per layer is essential to reason about cache isolation and commit operations.  
  *Quick check question:* What would happen if a branch cache extension mutated the committed cache’s KV tensors in-place?

- **Concept: Speculative decoding acceptance rules**  
  *Why needed here:* The system’s correctness hinges on the acceptance procedure selecting a valid prefix extension and updating the cache accordingly. The branchable cache manager’s commit modes must preserve the distributional equivalence promised by the acceptance rule.  
  *Quick check question:* Explain why, after acceptance, the committed cache must be *exactly* what sequential teacher execution would have produced for the accepted tokens.

- **Concept: Tree attention masking**  
  *Why needed here:* Preventing cross-branch information leakage is critical; the mask must enforce that each speculative token attends only to its ancestors. The mask construction and validation are tied to the tensorization scheme.  
  *Quick check question:* Given a tree with nodes `u1(parent=r)`, `u2(parent=u1)`, `u3(parent=r)`, what should `M_tree[2,3]` be and why?

## Architecture Onboarding
- **Component map:**  
  TreeTensorizer → TeacherVerifier → AcceptanceLogic → CacheManager.commit()  
  Supporting: CacheManager (main_cache, branch_caches), TraceLogger

- **Critical path (fused performance mode):**  
  1. Draft tree built.  
  2. TreeTensorizer produces padded `^parent`, `A`, `valid`, `τ`.  
  3. Construct dense `M_tree` from `A` and `valid`.  
  4. TeacherVerifier runs fused forward: uses `C⋆` as prefix, `τ` as speculative tokens, `M_tree` as attention mask. Writes KV into selected branch cache.  
  5. Gather logits for `τ[k]` where `valid[k]=1`.  
  6. AcceptanceLogic runs to get `path_indices`/`A`.  
  7. CacheManager.commit(path_indices) updates `main_cache`.  
  8. Loop.

- **Design tradeoffs:**  
  - Deep copy vs. view-based sharing: Deep copy guarantees isolation but copies large KV tensors; sharing views risks pollution and requires complex reference counting.  
  - Dense mask vs. compact encoding: Dense mask is simple and fused-kernel friendly but scales as O(M_max²); compact encoding saves memory but may add kernel complexity.  
  - Full reorder vs. prefix-sharing fast path: Fast path avoids moving long prefix KV blocks but requires checking that `path_indices` preserves prefix order; a failed check falls back to full reorder.

- **Failure signatures:**  
  - Cache mismatch error: Trace shows committed cache after commit differs from sequential reference (invariant violation). Likely commit logic bug or non-idempotent backend cache update.  
  - Invariant check failure: `Range`/`Acyclicity`/`Validity closure` fails during tensorization. Indicates malformed tree or incorrect padding handling.  
  - Silent acceptance drop: `accept_L` much lower than expected without crashes. Could be mask leakage, incorrect context (dummy root not set), or drafter quality issue.  
  - Fused kernel crash: Error from backend about mask shape or index bounds. Likely `M_tree` shape mismatch or `^parent` exceeding tensor dim.

- **First 3 experiments:**  
  1. **Invariant smoke test (reference mode):** Run a single turn with a simple tree (e.g., M=4, depth 2). Verify all structural invariants pass and that the mask’s ancestor predicate matches a brute-force check over node pairs.  
  2. **Cache equivalence check (reference mode):** For an accepted path, compare `main_cache` after commit against a sequentially built cache (teacher steps on accepted tokens). Should match exactly (within backend precision).  
  3. **Fused vs. eager parity (analysis variant):** With `PANGU_FORCE_EAGER_ATTN=1` and fused on, run same prompts; `accept_L` and final outputs should match. Discrepancies indicate mask or gather bugs in fused path.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can we reduce the overhead of tree attention masking and cache commitment in tree speculative decoding as the speculative tree grows, particularly through more compact mask representations and deeper kernel fusion?
- **Open Question 2:** How can we improve the trade-off between drafter quality and computational cost in tree speculative decoding, e.g., via speculation-aware distillation or adaptive branching policies?
- **Open Question 3:** How does tree speculative decoding perform under longer-context workloads, multi-turn conversations with tool use, and multi-device serving?
- **Open Question 4:** Can we design a more efficient branchable KV-cache manager that avoids deep copying for branch isolation, perhaps via copy-on-write or shared prefix techniques?
- **Open Question 5:** What context management policies for the drafter can reduce context length without significantly harming acceptance, given that naive truncation degrades performance?

## Limitations
- Draft model architecture and vocabulary subset construction are not detailed, hindering exact replication.
- Pangu backend’s fused attention kernel contract and cache layout are proprietary; integration relies on vendor flags and undocumented overrides.
- Evaluation uses only 240 turns (MT-Bench + HumanEval), limiting generalizability to longer or domain-specific outputs.
- Deep-copy of KV caches per branch may impose significant memory overhead; scalability beyond reported speeds remains unquantified.

## Confidence
- **Branchable KV-cache isolation:** Medium – supported by paper’s invariants and reference-mode tests, but lacks independent validation across backends.
- **Dummy-root tensorization:** Medium – formally eliminates negative indices; backend safety inferred from absence of crashes, not exhaustively proven for all NPU drivers.
- **Fused-kernel-compatible masking:** Medium – mask construction is well-described and parity with eager fallback is claimed, yet external audits for cross-branch leakage are absent.
- **End-to-end speedup (1.27× mean, 2.46× p99):** Medium – empirical on a narrow test set; hardware/driver specifics may limit reproducibility.
- **Budget sweet spot (M=16, D_max=10):** Medium – sweep results are plausible but could be dataset-specific.

## Next Checks
1. **Invariant smoke test:** Run a minimal tree (M=4, depth≤2); verify all structural invariants (Range, Acyclicity, Validity closure) and brute‑force check that the ancestor table `A` matches explicit parent pointers.
2. **Cache equivalence check:** After each acceptance, compare the committed cache against a sequentially built cache from the teacher on the accepted tokens; any mismatch indicates a commit logic flaw.
3. **Fused vs. eager parity:** Execute identical prompts in both fused-performance mode and eager-reference mode (`PANGU_FORCE_EAGER_ATTN=1`). Acceptance lengths (`accept_L`) and final outputs must be identical; discrepancies reveal fused kernel bugs.
