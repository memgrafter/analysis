# OCRTurk: A Comprehensive OCR Benchmark for Turkish

## Quick Facts
- **arXiv ID:** 2602.03693
- **Source URL:** https://arxiv.org/abs/2602.03693
- **Reference count:** 15
- **Primary result:** Introduced OCRTurk, the first standardized OCR benchmark for Turkish with element-wise evaluation across 180 manually annotated documents.

## Executive Summary
OCRTurk addresses the lack of real-world, element-specific OCR evaluation for Turkish. The benchmark provides 180 manually annotated Turkish documents (academic articles, theses, slide decks, non-academic articles) across three difficulty levels, with ground truth in unified Markdown. Seven OCR models were evaluated using dedicated metrics for text (NED, TCS), tables (TEDS, NED), equations (BLEU, CDM, NED), and figures (MSE, DreamSim). PaddleOCR achieved the strongest overall performance, particularly in raw text and equations, while DeepSeekOCR led in figure extraction. All models performed worst on slideshows and degraded on harder documents. Turkish Character Sensitivity (TCS) varied widely, highlighting persistent challenges with diacritics.

## Method Summary
The benchmark construction involved collecting 180 diverse Turkish PDF documents, manually converting them into unified Markdown ground truth, and classifying them into easy (text only), medium (text plus one simple element), and hard (complex layouts) difficulty levels. Seven state-of-the-art OCR models were run on each document. Their outputs were post-processed and segmented into element types (text, tables, equations, figures), which were then compared to ground truth using specialized metrics: NED and TCS for text, TEDS/NED for tables, BLEU/CDM/NED for equations, and MSE/DreamSim for figures. Performance was aggregated by document category and difficulty level.

## Key Results
- PaddleOCR achieved the best overall scores: text NED 0.08, TCS 0.82; equations NED 0.06, BLEU 0.94, CDM 0.95; DeepSeekOCR led in figure MSE 0.04.
- Models performed highest on non-academic documents and lowest on slideshows.
- Turkish Character Sensitivity (TCS) scores varied significantly across models (range 0.47–0.88), with HuanyanOCR achieving the highest.
- Performance consistently degraded as document difficulty increased.

## Why This Works (Mechanism)
**Mechanism 1: Element-wise evaluation isolates failure modes.**  
Claim: By computing dedicated metrics for each document element (text, tables, equations, figures), the benchmark reveals which components are problematic, enabling targeted model improvement. The mechanism assumes OCR outputs can be reliably segmented into elements and that failures are not uniformly distributed. Evidence includes the paper’s explicit use of element-wise metrics [section 4.1] and adaptation from related benchmarks like OmniDocBench. Break condition: if models return only raw text without element separation, scores become incomparable.

**Mechanism 2: Difficulty stratification measures robustness under increasing challenge.**  
Claim: Documents are stratified by structural complexity (easy: text only; medium: one simple element; hard: otherwise), exposing performance degradation as complexity rises. The mechanism assumes difficulty can be objectively defined by features like multi-line equations or multi-row tables and correlates with OCR challenge. Evidence: abstract notes performance drop on harder levels; section 3 details criteria. Break condition: if difficulty labels do not correlate with actual error rates (e.g., subtle quirks in "easy" docs).

**Mechanism 3: Turkish Character Sensitivity (TCS) targets language-specific diacritics.**  
Claim: TCS calculates error rates on a predefined set of Turkish-specific characters (ç, ğ, ı, ö, ş, ü, Ç, Ğ, İ, Ö, Ş, Ü), complementing general text metrics by focusing on confusions critical for Turkish. The mechanism assumes models trained on high-resource languages systematically mishandle these characters. Evidence: abstract reports significant TCS variation; section 4.1.1 defines TCS; related work (Yılmaz et al., 2025) highlights Turkish character confusion. Break condition: if models are already optimized for Turkish, TCS may show ceiling effects.

## Foundational Learning
- **Concept: Element-wise document parsing**  
  Why needed here: OCRTurk evaluates tables, equations, and figures separately from raw text, recognizing that extraction and error measurement differ by element type.  
  Quick check: Why might table extraction require TEDS instead of NED, and what structural aspect does TEDS capture?

- **Concept: Difficulty stratification in benchmarks**  
  Why needed here: The benchmark’s easy/medium/hard split is central to assessing model robustness on structurally complex documents.  
  Quick check: What features define "hard" OCR difficulty, and why might slideshows be harder than academic papers?

- **Concept: Language-specific OCR challenges**  
  Why needed here: Turkish has unique orthographic features (dotted/dotless i, consonant doubling) that cause systematic errors; TCS explicitly targets these.  
  Quick check: How might an English-trained OCR misinterpret "BEŞERİ", and why is a dedicated Turkish character metric necessary?

## Architecture Onboarding
**Component map:**  
Data Repository (180 PDFs + Markdown GT) -> Model Inference Wrapper (per-model scripts) -> Post-processing Module (clean text, extract elements) -> Evaluation Engine (compute element metrics) -> Aggregation & Reporting (summarize scores)

**Critical path:**  
1. Input selection: choose PDF subset (e.g., hard slideshows).  
2. Inference: run model wrapper to generate output.  
3. Post-processing: clean output, split into elements.  
4. Evaluation: apply appropriate metric per element vs. ground truth.  
5. Aggregation: compute average scores for the subset.

**Design tradeoffs:**  
- Manual annotation vs. scale: high-quality ground truth but limited dataset size (180 pages).  
- Unified Markdown: ensures consistency but may lose structure from models not outputting Markdown natively.  
- Element-wise metrics: provide fine-grained insights but depend on accurate element segmentation from model outputs.

**Failure signatures:**  
- Missing figure outputs: only 3 of 7 models returned figures, indicating limited figure extraction support.  
- Poor Turkish character handling: models like Nvidia Nemotron v1.1 show TCS as low as 0.47, revealing systematic diacritic errors.  
- Slideshow performance drop: all models score lowest on slideshows, suggesting layout understanding issues.

**First 3 experiments:**  
1. Baseline replication: run PaddleOCR on entire benchmark and verify reported numbers (NED ≈ 0.08, TCS ≈ 0.82) within ±0.01.  
2. Category isolation: evaluate all models on non-academic documents only to confirm highest average scores (~0.94) and inspect ease factors.  
3. Error pattern validation: manually inspect 10 hard document outputs for Turkish character substitutions (e.g., 'ğ' → 'ġ') and table structural errors to correlate with described failure modes.

## Open Questions the Paper Calls Out
**Open Question 1**  
Question: How does expanding OCRTurk in size and document diversity affect robustness and generalizability of OCR model evaluations for Turkish?  
Basis: Limitations section states manual annotation limited dataset to 180 documents; expansion planned for future work.  
Why unresolved: No empirical evidence on performance estimate changes with larger, more diverse benchmarks.  
What evidence would resolve: Evaluate same models on expanded benchmark (500+ pages, new categories like legal/medical) and compare performance distributions and confidence intervals.

**Open Question 2**  
Question: Why do OCR models systematically misrecognize Turkish diacritics and special characters (e.g., 'ğ', 'ş'), and how can this be mitigated?  
Basis: Error analysis reports recurring errors: 'ğ' split into breve + 'g', 'ş' as cedilla + 's', misinterpretation of uppercase 'İ'. Paper does not investigate root causes.  
Why unresolved: Errors persist across models; underlying reasons unanalyzed.  
What evidence would resolve: Ablation studies on training data coverage, model architecture modifications (e.g., subword attention), and language-specific preprocessing. Compare models fine-tuned on Turkish vs. multilingual-only training.

**Open Question 3**  
Question: What specific features of Turkish slideshows cause them to be the most challenging document type, and how can models adapt?  
Basis: Category results show slideshows have lowest average score; authors attribute to "inherently unstructured nature" but do not disentangle aspects.  
Why unresolved: Coarse categorization does not pinpoint exact challenges (e.g., irregular layouts, font variability).  
What evidence would resolve: Annotate slideshows with fine-grained features (text block shapes, font diversity) correlated with error rates, or generate synthetic slideshows with controlled variations.

**Open Question 4**  
Question: Why do many state-of-the-art OCR models fail to extract figures, and what architectural or training modifications are needed for unified element extraction?  
Basis: Table 3 shows only DeepSeekOCR, Docling, PaddleOCR have valid figure metrics; others return dashes. Paper does not analyze why.  
Why unresolved: Without understanding gaps, progress on full document parsing (including figures) remains limited.  
What evidence would resolve: Compare architectures (region proposal networks, multimodal components) and training objectives (figure detection tasks) between successful and failing models. Build a dedicated figure extraction benchmark.

## Limitations
- Dataset size and diversity limited to 180 documents across four categories; generalizability to other Turkish document types (e.g., legal, medical) or larger scales is unknown.
- Element-wise metrics depend on models producing separable outputs; systems returning only raw text may yield incomparable scores.
- Difficulty stratification based on simple rules (presence of tables/equations) lacks statistical validation that "hard" documents indeed yield higher error rates.

## Confidence
- Claim 1 (Element-wise evaluation isolates failure modes): **Medium**. Evidence shows varied element performance, but segmentation failure break condition not tested.
- Claim 2 (Difficulty stratification reflects increasing challenge): **Medium**. Performance drop on "hard" docs supports it, but criteria ad-hoc and lack correlation analysis.
- Claim 3 (TCS measures critical Turkish character errors): **High**. Directly targets known pitfalls; significant model variation (0.47–0.88) shows discriminative power.

## Next Checks
1. Replication study: run PaddleOCR on full benchmark and verify key metrics (NED ~0.08, TCS ~0.82) within ±0.01; test a monolithic-output model to assess element-wise score robustness.
2. Segmentation failure analysis: for models without native element separation, apply post-processing heuristics to extract tables/equations and measure variance in TEDS/BLEU versus ideal segmentation.
3. Cross-domain robustness: evaluate top models on 50 scanned Turkish documents (e.g., old magazines, forms) to quantify performance drop compared to digital PDFs.
