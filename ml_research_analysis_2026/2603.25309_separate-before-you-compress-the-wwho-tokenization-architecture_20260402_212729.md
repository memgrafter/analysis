# Separate Before You Compress: The WWHO Tokenization Architecture

## Quick Facts
- **arXiv ID:** 2603.25309
- **Source URL:** https://arxiv.org/abs/2603.25309
- **Reference count:** 28
- **Primary result:** WWHO reduces Token-to-Word Ratio by 61.7% for Sinhala and 27.0% for Hindi versus OpenAI's o200k_base, while guaranteeing zero syllable fragmentation.

## Executive Summary
Standard Byte-Pair Encoding (BPE) tokenizers inefficiently process Abugida scripts (e.g., Sinhala, Devanagari) by fragmenting linguistically atomic syllables into meaningless sub-character units. This "Token Tax" inflates token counts and harms reasoning efficiency. The WWHO architecture solves this by routing text through a script partitioner, a Deterministic Finite Automaton (DFA)-based syllabifier that extracts complete syllables, and a syllable-aware BPE variant that merges only within these boundaries. Evaluated on 1.5 million sentences, WWHO achieves dramatic token reductions and a verified zero-breakage guarantee, effectively extending context windows for Abugida languages by up to 4.38×.

## Method Summary
WWHO employs a three-layer pipeline. First, a **Router** uses Unicode block ranges to split text into Abugida and non-Abugida segments, absorbing zero-width joiners (ZWJ/ZWNJ) to preserve script boundaries. Second, a **LinguisTrie**—a DFA configured with language-specific schemas—applies a maximal-munch strategy to extract every linguistically atomic syllable from Abugida segments, guaranteeing no fragmentation. Third, **SGPE** (Syllable-aware GPE) performs standard BPE training and merging exclusively on these syllable units; non-Abugida text is tokenized with a conventional BPE (o200k_base). The system unifies both vocabularies via a meta-offset to produce a single token stream. Trained on a 30M-sentence mixed corpus, the SGPE vocabulary size is 128,001 with a prune frequency threshold of 100.

## Key Results
- **Sinhala:** TWR 1.274, 4.83 characters/token (61.7% fewer tokens than o200k_base).
- **Hindi:** TWR 1.181 (27.0% reduction vs. o200k_base).
- **Mixed-script (35% Sinhala, 45% Hindi, 20% English):** Overall TWR 1.240, reducing tokens by 36.7%, 39.6%, and 60.2% relative to o200k_base, Llama 4 Scout, and DeepSeek V3 respectively.
- **Context capacity:** Up to 4.38× effective extension for Abugida languages.
- **Zero-breakage guarantee:** 100% round-trip consistency on 122 million characters.

## Why This Works (Mechanism)
The core innovation is **decoupling script detection from subword merging**. BPE algorithms operate blindly over characters, causing syllable breakup in complex scripts where grapheme clusters exceed single code points. WWHO prevents this by first isolating Abugida text and replacing character-level merging with syllable-level merging. The LinguisTrie's DFA is deterministic and exhaustive, ensuring every possible valid syllable (including conjuncts with ZWJ/ZWNJ) is captured as a single, immutable unit. SGPE then applies statistical compression only within these pre-bounded units, never across syllable boundaries. This preserves linguistic integrity while still allowing data-driven merge decisions within the safe atomic set. For non-Abugida scripts, the standard BPE remains unaffected, maintaining compatibility and efficiency.

## Foundational Learning
1. **Abugida Script Structure:** Why needed? Abugida characters combine consonants, vowels, and diacritics into clusters (e.g., Devanagari ligatures) that are single linguistic units but multiple Unicode code points. Quick check: Confirm a single grapheme cluster (e.g., "क्ष") is represented by >1 code point.
2. **Deterministic Finite Automaton (DFA) for Syllabification:** Why needed? Provides a fast, linear-time, complete scanner for all valid syllable forms without exceptions. Quick check: Implement a simple state machine for one script; verify it covers all test clusters from the paper's Table 3.
3. **Token Tax:** Why needed? Inflated token counts waste context window space and increase computational cost for Abugida languages. Quick check: Tokenize identical Sinhala text with o200k_base and a naive whitespace split; compare token counts.
4. **Zero-Breakage Guarantee:** Why needed? Ensures perfect reversibility: tokenize → detokenize yields original text. Critical for reliable data pipelines. Quick check: Round-trip a sentence containing complex conjuncts (e.g., Sinhala "ත්‍රිවිභාජනය") through the pipeline; check for character loss.
5. **Boundary-Aware Merging:** Why needed? Standard BPE counts pairs across any boundary, merging sub-syllabic pieces. SGPE restricts pair counting to within LinguisTrie syllables. Quick check: Audit SGPE's pair frequency logs; ensure no pair spans two consecutive syllables.
6. **Meta-Vocabulary Unification:** Why needed? Combines two independent token sets (BPE and SGPE) into a single ID space without collision. Quick check: Tokenize mixed text; verify SGPE IDs start after BPE's max ID and there are no overlaps.

## Architecture Onboarding
**Component Map:** Input Text -> Router -> (LinguisTrie -> SGPE) for Abugida segments OR (Standard BPE) for non-Abugida segments -> Unified Token Stream

**Critical Path:** For Abugida text, the mandatory path is Router → LinguisTrie → SGPE. The Router's accuracy is foundational; any misclassification sends text to the wrong processor, causing either fragmentation (if Abugida goes to BPE) or inefficiency (if ASCII goes to SGPE).

**Design Tradeoffs:**
- *Schema specificity vs. generalization:* Each script requires a handcrafted DFA schema (character classes, transitions). This ensures zero-breakage but adds engineering overhead per language.
- *Linear scan overhead vs. fragmentation cost:* The DFA runs in O(n) time with small constant factors, trading negligible latency for massive token reduction.
- *Boundary discipline vs. compression potential:* Strict syllable boundaries limit merges; SGPE may achieve lower compression than unrestricted BPE on Abugida, but the net token reduction is still huge due to starting from atomic units.

**Failure Signatures:**
- Round-trip test fails on any Abugida string → DFA schema incomplete or buggy.
- Token count for pure ASCII text increases vs. baseline → Router absorbing too many characters or BPE not used directly.
- High [UNK] rate on Abugida test set → SGPE vocabulary too small or training corpus mismatch.
- Token IDs overlap between SGPE and BPE ranges → Meta-vocabulary offset misconfigured.

**First Three Experiments:**
1. **DFA Schema Validation:** Compare the repository's LinguisTrie JSON/config against Tables 3 & 4 in the paper. Run the DFA on all example clusters from the paper; ensure 100% match.
2. **Boundary Enforcement Audit:** Instrument SGPE's pair counting to log any candidate pair where the two characters belong to different LinguisTrie syllables. The count must be zero.
3. **Meta-Vocabulary Integrity Check:** Tokenize a mixed-script sentence (e.g., "ආයුබෝවන් hello अatonin"). Extract all token IDs; verify SGPE IDs are contiguous and start at `V_BPE`, with no overlap.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does the WWHO tokenizer affect downstream NLP task performance (e.g., accuracy, perplexity) for Abugida languages when used in LLMs?
- **Basis in paper:** [explicit] The conclusion states that future work will include "extensive downstream evaluations."
- **Why unresolved:** The paper only evaluates tokenization efficiency (TWR, CPT); it does not measure whether reduced token fragmentation improves model capabilities like reasoning, generation quality, or task-specific metrics for Sinhala or Hindi.
- **What evidence would resolve it:** Integrate WWHO into LLMs (e.g., by fine-tuning or pretraining), evaluate on benchmarks for Abugida languages (e.g., Sinhala/Hindi sentiment analysis, QA), and compare performance against models using standard tokenizers like o200k_base.

### Open Question 2
- **Question:** Can the WWHO framework be generalized to other complex scripts (e.g., Arabic, Thai, Tibetan) without modification to the core algorithm?
- **Basis in paper:** [explicit] The authors plan to "scale the WWHO framework to support Abugida and other complex scripts."
- **Why unresolved:** The architecture is only implemented and tested on Sinhala and Devanagari; its claim of script-independence via JSON schemas remains unverified for scripts with different linguistic structures (e.g., abjads, syllabaries).
- **What evidence would resolve it:** Define valid language schemas (character classes, DFAs) for diverse scripts, implement LinguisTrie for each, and empirically validate zero-breakage and token reduction similar to the Abugida case studies.

### Open Question 3
- **Question:** What is the computational overhead of the LinguisTrie layer (DFA-based syllabification) compared to standard BPE in terms of tokenization speed and memory usage?
- **Basis in paper:** [inferred] The paper emphasizes linguistic benefits but provides no benchmarks for the Router or LinguisTrie performance.
- **Why unresolved:** Tokenization speed impacts LLM training and inference scalability; the DFA's linear scan might be efficient, but real-world throughput versus byte-level BPE is unknown.
- **What evidence would resolve it:** Benchmark tokenization latency and memory footprint on large corpora (including long texts) for WWHO versus o200k_base, and analyze how overhead scales with context length and script complexity.

## Limitations
- **DFA Schema Fidelity:** The exact executable schema format (JSON structure, state transition encoding) in the `Remeinium/WWHO` repository is unknown; mismatches could break the zero-breakage guarantee.
- **SGPE Boundary-Aware Implementation:** The precise mechanism of how syllable boundaries constrain BPE pair counting and merging is not detailed; incorrect implementation would undermine token reduction claims.
- **Corpus Filtering Opacity:** The exact filtering criteria for the 30M-sentence training corpus are unspecified, potentially affecting SGPE's learned merges and generalizability.

## Confidence
- **Token Reduction Claims (TWR/CPT vs. baselines):** Medium. Relies on correct implementation of all WWHO layers and faithful reproduction of the training corpus.
- **Zero-Breakage Guarantee (100% round-trip):** High, *if* the DFA schema is correctly implemented and exhaustive for attested conjuncts.
- **Effective Context Window Extension:** Medium. Derived from TWR reductions; confidence follows TWR claim.
