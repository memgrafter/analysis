# TuneShift-KD: Knowledge Distillation and Transfer for Fine-tuned Models

## Quick Facts
- arXiv ID: 2603.24518
- Source URL: https://arxiv.org/abs/2603.24518
- Reference count: 31
- Primary result: TuneShift-KD transfers knowledge from a fine-tuned LLM to a target model without original data, achieving +4.80% (GSM8K), +13.5% (MBPP), +6.94% (BBH) improvements for Gemma-2B→7B.

## Executive Summary
TuneShift-KD addresses the challenge of distilling specialized knowledge from a fine-tuned large language model (LLM) into a target model without access to the original fine-tuning dataset. It leverages differences in perplexity between the fine-tuned and base models to identify prompts that reflect the specialized knowledge. Starting from a few seed examples, it iteratively generates synthetic prompts using an instruction-tuned LLM, filters prompt-response pairs via the perplexity criterion, and then trains the target model via knowledge distillation. Evaluations on GSM8K, MBPP, and BBH show substantial gains over the Trans-LoRA baseline, with improvements up to 35.7% on GSM8K using Qwen2.5 models. The method is architecture-agnostic and does not require the source base model, substituting it with a generic pretrained model.

## Method Summary
The method proceeds in three phases: (1) Synthetic data generation: given 5 seed examples, an instruction-tuned LLM (e.g., GPT-4o) is prompted to generate 20 similar prompts per seed. The instruction LLM’s responses are discarded; only the prompts are kept. (2) Perplexity-based filtering: for each prompt, both the source fine-tuned model and a base model (or a generic substitute) generate a response. The perplexity of the fine-tuned model’s response under the fine-tuned model is computed. A pair is retained if the fine-tuned model’s perplexity is below a threshold τ=1.5 and the base model’s perplexity is at least 1.5. The pool of retained (prompt, fine-tuned response) pairs is iteratively expanded by sampling new seeds from the pool until at least 250 examples are collected. (3) Knowledge distillation: the target model (with LoRA adapters, rank 8, α=16, dropout=0.05) is trained on the filtered dataset using sequence-level negative log-likelihood loss, with AdamW (lr=2e-5, 20 epochs, FP16). The resulting target model is evaluated on the downstream benchmark.

## Key Results
- For Gemma-2B→7B transfer: +4.80% on GSM8K, +13.5% on MBPP, +6.94% on BBH.
- With Qwen2.5 models: +35.7% on GSM8K, +18.1% on MBPP.
- Outperforms Trans-LoRA across all evaluated benchmarks.
- The method remains effective even when the true source base model is replaced by a generic pretrained model.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Perplexity differences between fine-tuned and base model responses identify specialized knowledge.
- **Mechanism:** For a given prompt, generate responses from both models. Select pairs where the fine-tuned model has low perplexity (high confidence) and the base model has high perplexity (low confidence). This gap indicates knowledge acquired during fine-tuning.
- **Core assumption:** Fine-tuning shifts the model's probability distribution, creating a measurable perplexity gap only on in-distribution prompts.
- **Evidence anchors:** Abstract statement; Section 3.3 theoretical derivation; literature on perplexity for filtering.
- **Break condition:** Fails if both models show similar perplexity (general knowledge or unlearned concepts) or both high (overly difficult prompts).

### Mechanism 2
- **Claim:** Iterative synthetic prompt generation expands the training set efficiently.
- **Mechanism:** Start with 5 seed examples. Use an instruction-tuned LLM to generate 20 similar prompts per seed. Filter these prompts via Mechanism 1, then add accepted pairs to the dataset. Repeat with new seeds from the expanded pool.
- **Core assumption:** Prompts generated from seed examples sufficiently cover the specialized knowledge distribution.
- **Evidence anchors:** Abstract; Section 3.4 description; literature on synthetic data generation.
- **Break condition:** Degrades if generated prompts diverge from the true specialized distribution.

### Mechanism 3
- **Claim:** Knowledge distillation on filtered pairs transfers specialized behavior to the target model.
- **Mechanism:** Train target model via negative log-likelihood on responses from the fine-tuned model for the filtered prompt-response pairs.
- **Core assumption:** The target model can learn the fine-tuned model's distribution from these curated examples.
- **Evidence anchors:** Abstract; Section 3.1 defines the NLL distillation objective; literature on knowledge distillation.
- **Break condition:** Fails if synthetic data is low quality or misaligned, leading to negative transfer.

## Foundational Learning
- **Concept: Perplexity as model confidence.**
  - *Why needed:* Core filtering criterion relies on interpreting perplexity values.
  - *Quick check:* How does lower perplexity on a response indicate higher model confidence in that response?
- **Concept: Knowledge distillation loss functions.**
  - *Why needed:* Understanding how the target model learns from teacher outputs.
  - *Quick check:* What is the training objective in Equation 1 and why use NLL instead of KL divergence?
- **Concept: Synthetic data generation with few-shot prompting.**
  - *Why needed:* The method depends on generating relevant prompts without original data.
  - *Quick check:* Why discard the instruction-tuned LLM's responses and only keep its prompts?
- **Concept: LoRA (Low-Rank Adaptation) for efficient fine-tuning.**
  - *Why needed:* Target model is trained with LoRA adapters to reduce computational cost.
  - *Quick check:* How does LoRA approximate full fine-tuning with low-rank matrices?
- **Concept: Perplexity thresholding for data selection.**
  - *Why needed:* The τ=1.5 filter determines which synthetic examples are kept.
  - *Quick check:* Why 1.5? How might the threshold interact with model scale?
- **Concept: Iterative dataset expansion.**
  - *Why needed:* To improve coverage of the specialized knowledge distribution.
  - *Quick check:* Could a single generation step suffice? What are the trade-offs?

## Architecture Onboarding
- **Component map:**
  - Source fine-tuned model (teacher) -> Perplexity filtering module <- Source base model (or substitute)
  - Instruction-tuned LLM (prompt generator) -> Synthetic prompts -> Filtering -> Training pool
  - Target model (with LoRA) <- Knowledge distillation training loop <- Filtered (prompt, response) pairs
- **Critical path:** Seed prompts -> synthetic prompt generation -> dual-model response generation -> perplexity filtering -> dataset expansion -> knowledge distillation training loop.
- **Design tradeoffs:**
  - **Prompt generator choice:** External LLM (GPT-4o) offers diversity but adds cost/API dependency; using source model itself reduces cost but may limit diversity.
  - **Filter threshold:** Fixed τ=1.5 is simple and robust; adaptive thresholds could improve precision at the cost of tuning effort.
  - **Data volume vs. quality:** More iterations expand dataset size, but low-quality filtered examples harm distillation; the 1.5 perplexity gate balances this.
- **Failure signatures:**
  - Target accuracy equals or falls below "Target (no LoRA)" baseline.
  - t-SNE visualization shows clustered, low-diversity prompts.
  - High proportion of filtered examples with teacher perplexity >1.5 but incorrect responses.
- **First 3 experiments:**
  1. **Ablation: Filtering rules.** Run with no filter, low-low, high-high, and default low-high (Table 5). Expect default to yield highest target accuracy.
  2. **Baseline comparison:** Replicate Trans-LoRA results on GSM8K/MBPP/BBH (Tables 1-3). Expect TuneShift-KD to show greater improvement.
  3. **Source base substitution:** Replace true source base with generic model (e.g., Llama2-7B for Gemma-2B, Table 4). Expect minor accuracy drop versus using true base, demonstrating flexibility.

## Open Questions the Paper Calls Out
1. What is the optimal perplexity threshold τ for different model scales, architectures, and tasks? The paper uses τ=1.5 universally with limited ablations.
2. What properties must a substitute base model have when the true source base is unavailable? The paper shows one substitution experiment but lacks general guidelines.
3. Why does TuneShift-KD succeed on procedural tasks (GSM8K, MBPP) but not factual MMLU? The boundary between transferable and non-transferable knowledge types remains unclear.

## Limitations
- Exact evaluation protocol (few-shot count, prompt template, answer parsing) is not fully described, hindering direct replication.
- The paper does not release code, so reported numbers cannot be independently verified.
- Dependence on a third‑party instruction‑tuned LLM introduces cost, API variability, and potential bias.
- Fixed perplexity threshold may not generalize across tasks and model scales.
- No statistical significance tests are provided; gains may be within variance.

## Confidence
