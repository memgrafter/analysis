# LUMEN: Longitudinal Multi-Modal Radiology Model for Prognosis and Diagnosis

## Quick Facts
- **arXiv ID:** 2602.21142
- **Source URL:** https://arxiv.org/abs/2602.21142
- **Reference count:** 0
- **Primary result:** LUMEN significantly improves longitudinal prognostic VQA (e.g., BLEU-4 0.375 vs. NVILA-8B 0.020 on difference questions) while maintaining strong diagnostic accuracy.

## Executive Summary
Medical vision-language models (VLMs) for radiology currently struggle with longitudinal reasoning—interpreting sequential chest X-rays (CXRs) to predict disease progression. LUMEN addresses this by introducing a multi-image, multi-task instruction fine-tuning framework built on the NVILA-8B backbone. It leverages a novel longitudinal instruction dataset derived from MIMIC-CXR and Medical-Diff-VQA, augmented with structured predictions from an expert model (TorchXRayVision). The model demonstrates substantial gains on prognostic visual question answering tasks while preserving diagnostic performance, showing that VLMs can be effective for both retrospective comparison and prospective forecasting in radiology.

## Method Summary
LUMEN fine-tunes the NVILA-8B model using a combination of existing diagnostic single-image VQA data and newly created longitudinal two-image instructions. Each training sample includes one or two CXRs and a natural language question. To guide the model, textual representations of expert model predictions (18 disease probabilities, age, race, view) are prepended to the question. The longitudinal dataset is generated by rephrasing "difference" questions (comparing two images) into "prognostic" questions (predicting future state) using a separate VLM. The model is trained end-to-end on this multi-task data to handle both diagnostic and prognostic reasoning in a single framework.

## Key Results
-   On prognostic difference questions, LUMEN dramatically outperforms the NVILA-8B baseline: BLEU-4 0.375 vs. 0.020, ROUGE-L 0.656 vs. 0.206.
-   On open-ended prognostic prediction questions, LUMEN achieves BLEU-4 0.095 vs. 0.019.
-   Diagnostic performance remains strong, with close-ended accuracy at 0.863 and Llama Score 8.565, indicating no trade-off in standard interpretation.

## Why This Works (Mechanism)

### Mechanism 1
-   **Claim:** Processing multiple images in a single forward pass enables the model to learn direct feature correspondences and changes across time points, which is prerequisite for longitudinal reasoning.
-   **Mechanism:** The NVILA-8B backbone natively supports multi-image inputs. LUMEN fine-tunes this capability by constructing instruction pairs where the input includes both a "main" and a "reference" CXR from different studies. The vision encoder processes both images, and the multimodal projector and LLM are trained to compare their representations within the same context window, learning to ground temporal differences in the visual features.
-   **Core assumption:** The model's architecture can effectively align and attend to features from two separate images within its existing token and attention framework without a dedicated temporal module.
-   **Evidence anchors:**
    -   [abstract]: "...multi-image, multi-task instruction fine-tuning framework on NVILA-8B..."
    -   [section 2.5]: "We fine-tuned the pretrained NVILA-8B... using both diagnostic and enhanced prognostic instructions with two-image input (LUMEN)."
    -   [corpus]: Neighbor papers like "Spot the Difference" and "Region-Specific Retrieval Augmentation" also focus on two-image comparison, suggesting this is a recognized architectural approach for this task type.
-   **Break condition:** If the visual token capacity of the base model is insufficient to represent two high-resolution CXRs plus text, performance may degrade due to context window limits or feature crowding.

### Mechanism 2
-   **Claim:** Injecting structured, text-formatted expert model predictions into the instruction data provides a high-level semantic scaffold that guides the LLM toward clinically relevant reasoning patterns.
-   **Mechanism:** For each image, predictions from TorchXRayVision (18 disease probabilities, age, race, view) are converted into discrete textual tokens (e.g., "maybe yes: Pneumonia"). These tokens are prepended to the human instruction. This transforms the abstract visual task into a structured "report interpretation" task the LLM is adept at, effectively distilling expert knowledge into a format that bootstraps the model's own generation.
-   **Core assumption:** The LLM component can correctly interpret and reason over these symbolic expert prediction tokens as contextual priors.
-   **Evidence anchors:**
    -   [section 2.3]: "To enhance interpretability for the LLM, disease probabilities were mapped to a text-based format with four confidence levels..."
    -   [section 2.2/2.4]: The overall instruction design combines image, expert text, and question, implying the text is a critical input modality.
    -   [corpus]: The D-Rax paper (neighbor `154899`) is explicitly cited as using this "eXpert model predictions" strategy, and VILA-M3 also incorporates segmentation data.
-   **Break condition:** If the expert model's prediction format or the calibration thresholds (0.25, 0.5, 0.75) is mismatched to the LLM's training distribution or introduces systematic bias (e.g., over-reliance on "no" predictions for rare diseases), the scaffold could mislead rather than help.

### Mechanism 3
-   **Claim:** Generating a longitudinal instruction dataset by transforming *difference* questions into *prognostic* questions creates a synthetic but coherent learning signal for future-state prediction, bridging the gap between retrospective comparison and prospective forecasting.
-   **Mechanism:** The original Medical-Diff-VQA contains QA pairs comparing two images (Time A vs. Time B). The authors used Llama-3.2-Vision to rephrase the *answer to the difference question* (which describes change) into an answer to a *new question* about the future state at Time B+Δ. This effectively translates a known historical change into a hypothetical future outcome, creating (question, image_T1, predicted_future_answer) triples for training.
-   **Core assumption:** The semantic and pathological patterns of change observed in the past (between Time A and B) are sufficiently generalizable and deterministic to predict a plausible future state (at Time B+Δ) from only the image at Time B. This assumes disease progression follows learnable, image-detectable patterns.
-   **Evidence anchors:**
    -   [section 2.4]: "To formulate prognostic questions, we used Llama-3.2-11B-Vision-Instruct... to predict future changes in the reference image."
    -   [section 3.1]: Results show improvement on prediction questions (BLEU-4 0.095 vs. 0.019), suggesting the synthetic data provides a useful, though imperfect, signal.
    -   [corpus]: No direct neighbor uses this exact data transformation trick for prognosis, indicating it's a novel contribution of this work. Weak corpus anchor for this specific mechanism.
-   **Break condition:** This mechanism will break if disease trajectories are highly stochastic, heavily treatment-dependent, or if the Δ time interval is too long/short. The synthetic answers may also inherit biases or hallucinations from the Llama-3.2 generator used to create them.

## Foundational Learning
-   **Concept: Multi-modal (Vision-Language) Instruction Tuning**
    -   **Why needed here:** The entire LUMEN framework is built on fine-tuning a pre-trained VLM (NVILA-8B) with structured (image, instruction, response) triples. An engineer must understand how to format data for such models, how the projection layer aligns vision and language features, and the difference between pretraining (contrastive/next-token) and instruction tuning (following dialogue).
    -   **Quick check question:** How does the loss function in instruction tuning typically differ from standard autoregressive language modeling, and why is this important for learning to follow varied question formats?
-   **Concept: Longitudinal Data Representation in Deep Learning**
    -   **Why needed here:** The core problem is moving from single-image to sequential-image reasoning. An engineer needs to grasp common strategies (concatenation, separate encoders with cross-attention, recurrent units) and their trade-offs in context window usage and temporal feature fusion.
    -   **Quick check question:** What are the primary architectural ways to feed a sequence of N images to a single-image VLM backbone, and what are the computational bottlenecks for N=2 vs. N>2?
-   **Concept: Evaluation Metrics for Generated Medical Text**
    -   **Why needed here:** The paper highlights the inadequacy of BLEU/ROUGE for clinical correctness and introduces an LLM-as-judge (Llama Score). An engineer must understand why lexical overlap fails in medical contexts and the design of rubric-based LLM evaluation.
    -   **Quick check question:** What specific properties of medical VQA (e.g., answer polarity, rare findings) cause standard n-gram metrics to be misleading, and how does an LLM-evaluator address this?

## Architecture Onboarding
-   **Component map:** Input (1-2 CXRs + Question + Expert Text) -> Vision Encoder (Independent per image) -> Projection Layer (To LLM space) -> LLM Backend (Attends to concatenated tokens) -> Output (Generated Response)
-   **Critical path:** Data Preparation (MIMIC-CXR + Medical-Diff-VQA + new prognostic instructions) -> Expert Model Inference (TorchXRayVision) -> Instruction Formatting (with expert text) -> Multi-image Fine-tuning of NVILA-8B -> Evaluation on diagnostic & prognostic test splits.
-   **Design tradeoffs:**
    -   **2-images vs. N-images:** The architecture uses a fixed 2-image input for simplicity and to match dataset construction. Scaling to N>2 requires dynamic batching or a temporal pooling mechanism, increasing memory complexity.
    -   **Expert text as prefix vs. suffix:** Prepending expert predictions provides strong priors but may constrain the LLM if predictions are wrong. Suffixing could allow more open-ended generation but provides less guidance.
    -   **Long vs. short answers:** They fine-tuned on LLM-expanded longer answers for "naturalness," but this risks verbosity and hallucination compared to the original concise Medical-Diff-VQA answers used for some evaluations.
-   **Failure signatures:**
    -   **High diagnostic accuracy but low prognostic scores:** Model has not learned temporal reasoning; it's just doing single-image diagnosis on the "main" image and ignoring the "reference."
    -   **Low recall on open-ended questions with high BLEU:** Model is generating plausible-sounding but clinically incorrect or overly generic text (e.g., "no significant findings" for a positive case), exploiting lexical overlap.
    -   **Performance collapse when expert predictions are incorrect:** Indicates over-reliance on the scaffold. Should be tested by corrupting expert labels.
-   **First 3 experiments:**
    1.  **Baseline replication:** Run NVILA-8B (no fine-tuning) on the diagnostic and difference VQA test sets to establish the severe performance gap (e.g., BLEU-4 ~0.02 on difference questions).
    2.  **Single-task fine-tuning:** Fine-tune NVILA-8B *only* on the original (single-image) diagnostic instructions to confirm it acquires diagnostic capability but fails at longitudinal tasks, isolating the need for multi-task training.
    3.  **Ablation - remove expert predictions:** Train a LUMEN variant without the TorchXRayVision text tokens to quantify the contribution of the expert scaffold to both diagnostic and prognostic performance.

## Open Questions the Paper Calls Out
### Open Question 1
-   **Question:** What performance gains can be achieved by extending LUMEN to process sequences of more than two longitudinal CXR images for prognostic VQA?
-   **Basis in paper:** [explicit] "Another limitation of our model is that it incorporates only two images corresponding to two studies at different time points. Using a sequence of multiple temporal images could further enhance the benefits of longitudinal data training." (Section 4, Conclusion)
-   **Why unresolved:** The current LUMEN architecture is constrained to two-image inputs, and the potential of longer sequences to capture complex disease progression patterns remains unexplored.
-   **What evidence would resolve it:** Train variants of LUMEN with varying numbers of input images (e.g., 3–5) on a multi-time-point dataset, and evaluate improvements on difference and prediction questions using lexical and clinical metrics.

### Open Question 2
-   **Question:** How does integrating comprehensive clinical information, such as treatment history, impact the prognostic accuracy and clinical validity of VLMs?
-   **Basis in paper:** [explicit] "Future work should explore multi-modal training that incorporates comprehensive clinical information such as treatment to further enhance clinical validity." (Section 4, Conclusion)
-   **Why unresolved:** LUMEN uses only imaging data and time intervals; treatment and other clinical factors critically influence disease trajectories but are omitted, limiting real-world applicability.
-   **What evidence would resolve it:** Construct a multi-modal dataset pairing CXRs with treatment records, and compare VLM performance (with/without clinical data) on prognosis tasks, validated against actual patient outcomes or expert assessments.

### Open Question 3
-   **Question:** What evaluation frameworks can robustly measure prognostic VQA performance given the inherent uncertainty and lack of definitive ground truth in outcome prediction?
-   **Basis in paper:** [explicit] "Forecasting patient outcomes from reference images remains an open challenge." and "handling outcome-related questions, many of which lack a definitive ground-truth answer." (Introduction and Section 3.2)
-   **Why unresolved:** Current metrics (e.g., BLEU, Llama Score) may not reflect clinical correctness for uncertain prognostic tasks, and ground truth is often synthetically derived or limited.
-   **What evidence would resolve it:** Establish a benchmark with clinician-validated prognostic labels and develop metrics that assess uncertainty calibration, clinical utility, or correlation with longitudinal patient outcomes.

## Limitations
-   Public release of the longitudinal instruction dataset is pending; without it, exact reproduction is hampered.
-   Prompt templates for data enhancement and prognostic question generation are not disclosed, leading to variability.
-   Synthetic prognostic answers derived from Llama-3.2-Vision may introduce hallucinations; generalization to real future states is unclear.

## Confidence
-   **Multi-image temporal reasoning via NVILA-8B backbone:** Medium. Architecture supports two images, but no dedicated ablation shows necessity vs. single-image baselines.
-   **Expert prediction scaffold improves learning:** Medium-High. Inspired by prior work (D-Rax) and appears in data pipeline, but impact not isolated experimentally.
-   **Synthetic longitudinal dataset bridges retrospective to prospective:** Low-Medium. Novel approach lacks direct validation; performance gains modest on prediction tasks (BLEU-4 0.095 vs. 0.019).

## Next Checks
1.  **Ablate expert predictions:** Train a LUMEN variant without TorchXRayVision text tokens; compare diagnostic accuracy and prognostic scores to quantify scaffold contribution.
2.  **Stress test multi-image capacity:** Evaluate with more than two CXR time points (e.g., three) to identify context window or attention bottlenecks; measure performance decay.
3.  **Inject expert errors:** Corrupt a subset of expert predictions (e.g., flip a disease label) to probe model robustness and detect over-reliance on potentially inaccurate scaffold.
