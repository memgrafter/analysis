# Frequent Pattern Mining approach to Image Compression
## Quick Facts
- **arXiv ID:** 2602.00100
- **Source URL:** https://arxiv.org/abs/2602.00100
- **Reference count:** 27
- **Primary result:** A lossy image compression method replacing JPEG's DCT with k-means clustering and closed frequent sequence mining, achieving compression ratios up to 5.35 on Lena (k=8) with PSNR 35.85–44.02 dB and SSIM 0.94–0.99, averaging 45% improvement over JPEG and GIF.

## Executive Summary
This paper introduces a novel lossy image compression technique that substitutes the discrete cosine transform (DCT) in JPEG with a pipeline combining k-means clustering and closed frequent sequence mining. Pixel values are first quantized into a small set of integer identifiers via k-means per color channel, after which the resulting identifier matrices are processed as row‑wise sequence databases. A modified GSP algorithm mines closed frequent contiguous sequences, and a modified support measure (s_mod) prioritizes longer patterns while eliminating overlapping counts. The s_mod frequencies drive a Huffman encoder, producing a compact code table. Experiments on standard 512×512 images show compression ratios reaching 5.35 (Lena, k=8) versus JPEG's 1.94, with an average improvement of 45%. Image quality remains acceptable, with PSNR between 35.85 and 44.02 dB and SSIM between 0.94 and 0.99, indicating minimal perceptual loss at higher compression.

## Method Summary
The compression pipeline operates independently on each RGB channel. For a given channel, k-means clustering maps raw pixel values (0–255) to one of *k* cluster identifiers (⌈log₂*k*⌉ bits per pixel); the cluster centroids are stored for reconstruction. Each row of the resulting identifier matrix is treated as a sequence. A refined GSP algorithm mines closed frequent sequences with a minimum support threshold *α*. The modified support *s_mod* is computed by sorting these sequences in descending length, scanning the matrix to count non‑overlapping occurrences, and removing matched positions from subsequent counts. Huffman coding is then applied using *s_mod* as the frequency distribution, generating a variable‑length code table that replaces sequences in the matrix. The final compressed file concatenates the centroid tables, the Huffman code table, and the encoded bitstream. The decoder reconstructs the identifier matrix using the Huffman tree and substitutes each identifier with its corresponding centroid.

## Key Results
- Compression ratios up to 5.35 (Lena, k=8) compared to JPEG's 1.94, averaging a 45% improvement over JPEG and GIF.
- PSNR ranges 35.85 to 44.02 dB; SSIM between 0.94 and 0.99 across tested images.
- Optimal parameter ranges: *k* ≤ 10 and α ∈ [40%, 60%] for best compression‑quality trade‑off.

## Why This Works (Mechanism)
### Mechanism 1: Quantization via k-means
- **Claim:** Reducing pixel bit-depth via k-means clustering preserves perceptual similarity while enabling smaller identifiers for compression.
- **Mechanism:** k-means groups pixels into *k* clusters; each pixel is replaced by its cluster’s integer identifier. Reconstruction uses cluster mean. Spatial redundancy shifts to repeating identifier sequences.
- **Core assumption:** Pixels within a Euclidean cluster centroid are perceptually similar enough that mean substitution causes negligible distortion at moderate *k*.
- **Evidence anchors:** Abstract mentions clustering; Section III.A.2 describes cluster identifier table; examples show pixel replacement.
- **Break condition:** If *k* is too small, mean centers deviate significantly, increasing MSE and degrading PSNR below acceptable thresholds.

### Mechanism 2: Closed frequent sequence mining
- **Claim:** Closed frequent sequence mining on identifier matrices captures spatial redundancies more efficiently than block‑DCT by encoding variable‑length repeating patterns across row boundaries.
- **Mechanism:** A refined GSP algorithm mines contiguous identifier sequences level‑wise, pruning non‑closed sequences (those whose support equals a supersequence’s). This yields a minimal set of maximal repeats, reducing dictionary entries.
- **Core assumption:** Spatial correlations in natural images manifest as repeated contiguous identifier sequences in the row‑major ID matrix.
- **Evidence anchors:** Abstract mentions replacing DCT with closed frequent sequence mining; Section III.A.3 presents Algorithm 2 and pruning table.
- **Break condition:** If sequences are predominantly short or highly fragmented, the closed‑sequence set cardinality approaches the frequent‑sequence set, bloating the code table.

### Mechanism 3: Modified support (*s_mod*) to eliminate overlapping counts
- **Claim:** Modified support (*s_mod*) eliminates overlapping counts, prioritizing longer sequences and shrinking the Huffman code table.
- **Mechanism:** Closed sequences are sorted descending by length. For each sequence, all its non‑overlapping occurrences are removed from the ID matrix; supports of remaining sequences are decremented accordingly. Shorter sequences’ counts are depleted if their occurrences are subsumed by longer ones.
- **Core assumption:** Longer sequences provide more bits‑per‑symbol savings; thus, their exclusive encoding should invalidate overlapping counts of shorter subsequences.
- **Evidence anchors:** Abstract mentions proposed mechanism for frequency reduction; Section III.A.3 shows *s_mod* calculation example.
- **Break condition:** If removal order is not strictly length‑descending, *s_mod* may not minimize code table size.

## Foundational Learning
- **k-means clustering**
  - **Why needed:** To quantize high‑dimensional pixel values (0–255) into a small set of discrete identifiers, enabling compact representation and pattern mining on a smaller alphabet.
  - **Quick check:** How does increasing *k* affect (a) cluster purity/intra‑cluster variance and (b) the average length of mined frequent sequences?
- **Closed frequent sequential pattern mining (GSP‑based)**
  - **Why needed:** To find maximal repeating contiguous identifier sequences that can be replaced by dictionary codes, avoiding redundant storage of subsequences.
  - **Quick check:** What is the computational trade‑off between mining all frequent sequences and then pruning closed ones vs. incremental closed‑sequence pruning?
- **Huffman coding on modified frequencies**
  - **Why needed:** To assign prefix‑free variable‑length codes to patterns based on *s_mod*, ensuring more frequent (after overlap removal) patterns get shorter codes, minimizing encoded size.
  - **Quick check:** Why is Huffman applied to *s_mod* rather than raw support counts, and what would happen if raw supports were used?

## Architecture Onboarding
- **Component map:**  
  Input RGB image → Per‑channel split → k‑means per channel → ID matrices → Modified GSP → Closed sequences with raw support → s_mod calculation → Adjusted frequencies → Huffman encoder → Code table + compressed stream. Decoder reverses with stored cluster centers and Huffman tree.
- **Critical path:** Clustering output (ID matrices) → Sequence mining → s_mod adjustment → Huffman encoding. Delays in mining (high *k*, low α) bottleneck compression.
- **Design tradeoffs:**
  - *k*: Low (*k*≤10) increases compression ratio but lowers PSNR; high *k* (>24) degrades CR.
  - α: Low α yields more/longer sequences (smaller per‑sequence cost) but larger code table; high α (≥60%) reduces table size but may leave patterns unencoded.
  - Time: Mining dominates; O(|matrix| × candidate_generation).
- **Failure signatures:**
  1. PSNR drop >10 dB vs. JPEG suggests *k* too low or cluster distortion high.
  2. Compressed size larger than predicted indicates s_mod not applied or α too low (excessive patterns).
  3. Memory explosion during GSP suggests α too low or poor candidate pruning.
- **First 3 experiments:**
  1. **Parameter sweep (k):** Fix α=46%, vary *k* ∈ {8,15,24} on Lena. Record CR, PSNR, SSIM, runtime. Expect CR ↓ and PSNR ↑ with *k*.
  2. **Parameter sweep (α):** Fix *k*=8, vary α ∈ {30%,46%,60%}. Measure CR and mining time. Expect CR peaks ~40–60% and time ↑ as α ↓.
  3. **Baseline comparison:** At *k*=8, α=46%, compare CR, PSNR, SSIM against JPEG (quality factor ~50) and GIF on 512×512 test images (Lena, Peppers). Validate claimed ~45% CR improvement and SSIM >0.94.

## Open Questions the Paper Calls Out
1. **Integrating spatial neighborhood information into clustering** – The authors propose equipping the algorithm with a better clustering technique that uses pixel neighbourhood properties to improve image quality without sacrificing compression gains.
2. **Mining 2D sub‑matrices instead of 1D sequences** – Mining sub‑matrices could capture spatial patterns across rows, potentially yielding a significant improvement in compression ratio.
3. **Scalability of modified GSP** – The runtime for large images (e.g., 4K resolution) is unknown; extensive simulations on larger datasets are needed to assess time complexity and optimization opportunities.
4. **Comparison with modern codecs** – The paper only compares against JPEG and GIF; performance relative to contemporary codecs (JPEG2000, WebP, AVIF, HEIC) remains unevaluated.

## Limitations
- **Parameter sensitivity:** Compression‑quality trade‑off is highly sensitive to *k* and α; optimal ranges may not generalize to all image types, especially noisy or highly textured ones.
- **Implementation ambiguities:** Critical details (k‑means initialization, exact α definition, scanning order for s_mod, binary serialization format) are unspecified, hindering exact replication and fair comparison.
- **Scalability concerns:** Experiments are limited to 512×512 images; the computational cost of the GSP‑based mining step for high‑resolution images is not analyzed.

## Confidence
- **Core mechanism (k‑means → sequence mining → s_mod):** High
- **Reported compression ratios and quality metrics:** Medium
- **Generalizability to diverse images/resolutions:** Low

## Next Checks
1. **Clarify α computation:** Determine whether α is a percentage of the number of rows (i.e., α_count = ⌈α × 512⌉) or another base, and test its impact on code table size and compression ratio.
2. **Validate s_mod coverage:** After s_mod computation, verify that the sum of s_mod × sequence length across all patterns equals the total number of pixels (512×512 per channel). Adjust scanning order until full coverage consistent with the paper's examples is achieved.
3. **Benchmark code table size:** Implement a minimal binary serialization for centroid and Huffman tables, measure overhead, and compare against the paper’s reported code table size (e.g., 15.165 kB for Lena, k=8) to assess feasibility of claimed compression ratios.
