# Token-Oriented Object Notation vs JSON: A Benchmark of Plain and Constrained Decoding Generation

## Quick Facts
- arXiv ID: 2603.03306
- Source URL: https://arxiv.org/abs/2603.03306
- Reference count: 2
- Primary result: Plain JSON achieves the highest one-shot and final accuracy; TOON is token-efficient only for aligned structures; JSON-SO minimizes tokens but harms strong model accuracy.

## Executive Summary
This paper benchmarks Token-Oriented Object Notation (TOON) against JSON for large language model output generation, evaluating token efficiency and accuracy. Across 21 models and four test schemas, plain JSON consistently achieves the highest one-shot and final accuracy. Constrained-decoding JSON (JSON-SO) reduces token usage but degrades accuracy, particularly for capable models. TOON provides a favorable accuracy/token ratio only for data structures aligned with its concise syntax patterns (e.g., tabular, nested-uniform arrays), where it can reduce tokens by over 20%. However, for complex, deeply nested structures, TOON performance collapses. The core finding is that TOON's efficiency depends on amortizing a fixed "prompt tax" over sufficiently large outputs, following a non-linear scaling curve.

## Method Summary
The benchmark uses four Pydantic-defined test cases (`users`, `order`, `company`, `invoice`) with gold-standard JSON and TOON outputs. For each of 21 models via the Nebius API, generations are produced under three conditions: plain JSON (J), JSON with structured output via constrained decoding (JSON-SO, JSO), and one-shot TOON (T). A task-specific prompt initiates generation; outputs are validated against the Pydantic schema. Failures trigger up to three repair cycles, where the previous output and validation error are appended to the prompt. After canonicalization, one-shot accuracy, final accuracy, and total tokens (prompt + completion) are measured, with temperature set to 0 and 10 runs per case.

## Key Results
- Plain JSON achieves the highest one-shot and final accuracy across all models and structures, establishing it as the most reliable format.
- TOON yields a positive accuracy/token trade-off only for "aligned" data structures (e.g., `users` case: 22% fewer tokens than JSON with 90.5% one-shot accuracy) but fails catastrophically on non-aligned schemas (e.g., 0% one-shot on `company`).
- JSON-SO offers the lowest token usage but trades off accuracy, with significant degradation for larger models (e.g., Hermes-405B one-shot accuracy drops from 92.5% to 35.0%).

## Why This Works (Mechanism)
**Mechanism 1: Amortized Prompt Tax**  
TOON's token efficiency is not inherent but emerges from a trade-off between a fixed prompt overhead ("prompt tax") and variable syntax savings. The heavy one-shot TOON prompt incurs a constant cost; net savings occur only when the generated output is large enough that cumulative reductions from TOON's compact syntax outweigh this initial investment. For small outputs, the prompt dominates the token budget. Evidence: Section 7.4 states TOON benefits only when output amortizes the fixed prompt cost. Break condition: For small or simple outputs, TOON is less efficient than minimal-prompt JSON.

**Mechanism 2: Constrained Decoding Interference**  
Constrained decoding (e.g., via xgrammar) can degrade generation quality for strong models by restricting the token sampling space to enforce grammatical validity. For models with robust innate knowledge of JSON, this rigid masking may prune high-probability, semantically correct token sequences, forcing suboptimal paths and early errors. Evidence: Section 7.1 reports Hermes-405B one-shot accuracy dropping from 92.5% to 35.0% with JSON-SO; cited reference [2] discusses similar interference. Break condition: Weaker models benefit from scaffolded constraints; strong models are hindered.

**Mechanism 3: Schema Alignment Dependency**  
TOON's viability is strictly determined by topological alignment between the data schema and TOON's optimized patterns (uniform arrays, shallow nesting). Its syntax rules (e.g., `arrayName[N]{fields}:`) maximize token savings and clarity for "aligned" structures. For deep, non-uniform, or recursive nesting ("non-aligned"), the model must generate more complex, error-prone TOON sequences, negating advantages and causing accuracy collapse. Evidence: Section 7.2 shows catastrophic one-shot failure for non-aligned cases like `company`. Break condition: Schemas with heterogeneous arrays, deep nesting, or recursion exceed TOON's concise patterns, leading to inefficiency and inaccuracy.

## Architecture Onboarding
Component map: Prompt templater -> Model inference engine -> Output validator -> Canonicalizer -> Repair loop controller -> Token counter & metrics aggregator.  
Critical path: Prompt -> Model Generation -> Validation -> (Success? -> End) / (Failure? -> Repair Prompt -> Model Generation -> up to 3 cycles) -> Canonicalization -> Comparison -> Metrics.  
Design tradeoffs: Heavy one-shot TOON prompt enables learning but creates high fixed cost; strict Pydantic ensures gold-standard comparison but repair depends on informative errors; temperature=0 reduces variance but doesn’t guarantee determinism.  
Failure signatures:  
- TOON: indentation drift, incorrect array count `[N]`, misuse of tabular `{fields}:`, unclosed blocks.  
- JSON-SO: early cutoff or repetition due to restrictive grammar masking.  
- General: missing required fields, type mismatches from validation.  
First 3 experiments:  
1. Reproduce aligned/non-aligned split: Run `users` (aligned) and `company` (non-aligned) cases across 2–3 models to confirm TOON’s dramatic accuracy gap.  
2. Measure amortization threshold: For `order` case, generate synthetic variants with 1, 5, 10, 20 line-items; plot total tokens (J vs. T) to locate crossover where T becomes cheaper.  
3. Test prompt tax sensitivity: Create a minimal TOON prompt (rules only, no example) and compare accuracy/tokens to full paper prompt; quantify overhead contribution.

## Open Questions the Paper Calls Out
**Open Question 1**  
At what output size does TOON's total token cost (including prompt overhead) fall below JSON's for aligned data structures? The benchmark used fixed small cases; no systematic scale variation to find crossover.

**Open Question 2**  
Does TOON suffer from indentation drift in long-context generations, causing validation failures? All test cases had small outputs; no stress tests on very deep nesting or large arrays.

**Open Question 3**  
Would enforcing TOON syntax via constrained decoding (e.g., xgrammar) improve accuracy for complex structures compared to one-shot in-context learning? Only unconstrained one-shot TOON was evaluated; constrained decoding for TOON was not tested.

**Open Question 4**  
Can schema-specific prompt examples (tailored per test case) reduce TOON structural errors versus a universal prompt? Benchmark used one universal TOON prompt; prompt engineering per schema was not explored.

## Limitations
- The definition of "alignment" (tabular/nested-uniform vs. deep/non-uniform) is based on observed performance but lacks a formal, predictive taxonomy for unseen schemas.
- The heavy one-shot TOON prompt’s components (rules, example, instruction) are not isolated; the minimal viable prompt and its cost breakdown remain unknown.
- The benchmark uses only four curated Pydantic models, raising questions about generalizability to broader real-world structured data diversity (e.g., graphs, mixed-type arrays).

## Confidence
- **High**: Constrained decoding degrades one-shot accuracy for strong models (e.g., Hermes-405B: 92.5% → 35.0%); evidence is specific and aligns with cited literature.
- **Medium**: TOON’s net efficiency follows a non-linear amortization curve; logically sound and supported by case comparisons, but lacks cross-dataset validation of exact curve shape.
- **Low**: TOON’s failure on non-aligned structures is inherent to its rule set; evidence shows collapse on two cases, but without formal schema taxonomy or rule ablation, cause could be underspecified prompts.

## Next Checks
1. **Schema Alignment Threshold Test**: Generate a continuum of schemas by varying nesting depth (1–5) and array homogeneity (homogeneous vs. heterogeneous). Plot TOON one-shot accuracy against a continuous "alignment score" to locate the precise failure boundary.
2. **Prompt Tax Ablation**: For the aligned `users` case, construct three TOON prompts: (a) rules only, (b) rules + reference example, (c) minimal natural language instruction. Compare one-shot accuracy and total token cost to quantify overhead per component.
3. **Cross-Dataset Generalization**: Re-run the benchmark on an external structured generation benchmark (e.g., `JSONSchemaBench` or a subset of `Spider`). Test whether the aligned/non-aligned split and amortization pattern hold for non-curated schemas and tasks.
