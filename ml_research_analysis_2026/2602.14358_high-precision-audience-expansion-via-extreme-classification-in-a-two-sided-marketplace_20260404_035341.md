# High Precision Audience Expansion via Extreme Classification in a Two-Sided Marketplace

## Quick Facts
- **arXiv ID:** 2602.14358  
- **Source URL:** https://arxiv.org/abs/2602.14358  
- **Reference count:** 21  
- **Primary result:** Offline matched baseline booked location recall (-0.04%) while improving precision (+11.01%) and retrieved listings (+9.91%); online A/B test (+0.17% uncancelled bookers) with ~66M users.

## Executive Summary
This paper presents a high-precision audience expansion system for a two-sided marketplace (e.g., Airbnb). The system replaces traditional rectangular geographic retrieval bounds with an extreme multiclass classifier that predicts a compact set of high-precision S2 cells (level-11, ~360K classes) from the search context. The classifier’s thresholded probability output queries only those cells likely to contain a booked listing. Offline evaluation shows it nearly matches the baseline’s recall of booked locations (-0.04%) while improving precision by +11.01% and increasing retrieved listings by +9.91%. In an online A/B test with ~66M users, it increased uncancelled bookers by +0.17%. The method leverages extreme classification techniques, including vocabulary reduction and continental sharding, to make training and inference feasible.

## Method Summary
The authors formulate the retrieval problem as predicting the probability distribution over S2 cell IDs given a search query and the target class of booked listings. To handle the extreme label space (~360K level-11 cells that historically contained a booking), they reduce the vocabulary to cells with historical bookings and shard models by destination continent (Europe, Americas, Rest of World). A deep neural network (4 layers) is trained with sampled softmax loss. At inference, the appropriate continental model scores candidate cells; a hand-tuned threshold λ selects a compact set, which is translated into a Lucene disjunctive query to retrieve listings. This replaces the baseline’s fixed rectangular bounds, reducing unbookable areas while maintaining recall.

## Key Results
- **Offline:** Recall -0.04% (nearly identical to baseline), Precision +11.01%, Retrieved Listings +9.91%.
- **Online:** +0.17% increase in uncancelled bookers in an A/B test with ~66M users.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Replacing continuous rectangular geographic bounds with a discrete, high‑precision set of S2 cells reduces the inclusion of unbookable locations in the retrieval set.
- **Mechanism:** The classifier predicts probabilities over ~360K level‑11 S2 cells derived from historical bookings. By thresholding, only cells with high predicted likelihood of containing a booked listing are selected. The baseline’s rectangular bound must include all area between the destination and a distant bookable location (e.g., between Cancún and Playa del Carmen), inevitably capturing intervening unbookable regions.
- **Core assumption:** The distribution of booking locations, conditioned on search context, is sufficiently concentrated within a small number of discrete S2 cells to allow effective thresholding.
- **Evidence anchors:** [abstract] “replaced rectangular geographic retrieval bounds with an extreme multiclass classifier predicting high‑precision S2 cells… using a thresholded probability output to query only those cells.”; [section 3.1] Formulates the problem as P(C=c_i | B=1, Q=q); [section 2] “This new approach will allow us to simultaneously remove inventory in unbookable locations… and surface new inventory from previously unsurfaced bookable locations.”; [corpus] Related work supports location‑based search but does not challenge the S2 discretization assumption.

### Mechanism 2
- **Claim:** Training an extreme multiclass classifier on a reduced, booking‑derived vocabulary (~360K classes) is computationally tractable and effective for predicting relevant geographic cells.
- **Mechanism:** The label space is reduced from all possible ~25M level‑11 S2 cells to only those that ever contained a booked listing. The problem is decomposed by destination continent into three smaller models (~85K–139K classes each). This reduction, combined with sampled softmax loss (~25K negative samples), makes training a deep neural network feasible without hierarchical or tree‑based extreme classification methods.
- **Core assumption:** A model trained only on historically booked cells can generalize to predict potential bookable cells (including new ones) based on search context, and the continent‑based sharding preserves sufficient generalization within continental clusters.
- **Evidence anchors:** [section 3.4] Details the vocabulary reduction to ~360K classes and 3‑way continental sharding; [section 3.3] Explains why S2 cells provide mutually exclusive, deterministic, similarly‑sized classes; [section 4.3] Notes the baseline retrieval bounds model also uses region indicators; [corpus] Weak direct evidence; related work mentions extreme classification in text domains.

### Mechanism 3
- **Claim:** Thresholded probability output from the classifier enables a tunable recall‑precision trade‑off, allowing the system to match the baseline’s recall of booked locations while significantly improving precision and retrieved inventory.
- **Mechanism:** The hand‑tuned threshold λ (per continental model) is set during offline evaluation to match the baseline’s *Booked Listing Location Recall*. Because the predicted cell set is more precise (targets only high‑probability cells), this matching recall comes with fewer false positive cells, yielding higher precision and more retrieved listings within those correct cells (+9.91%).
- **Core assumption:** The relationship between a cell’s predicted booking probability and its actual precision is stable enough that a single static threshold λ per continent can optimally balance the trade‑off for all queries within that continent.
- **Evidence anchors:** [section 3.6] “We convert the dense distribution… into a compact set… by retaining only those whose predicted booking likelihood exceeds a hand‑tuned threshold λ… The choice of λ trades off recall… and retrieval cost.”; [section 4.4] “We select booking probability thresholds λ for each region’s model by matching the baseline retrieval bound model’s Booked Listing Location Recall.”; [Table 1] Shows offline outcome: recall nearly identical (-0.04%), precision +11.01%, retrieved listings +9.91%; [corpus] No direct counter‑evidence; related work discusses dynamic thresholding as future work.

## Foundational Learning
- **S2 Geometry & Hierarchical Spatial Indexing** – *Why needed:* S2 cells partition the globe into a fixed, hierarchical grid of mutually exclusive, equal‑area cells with deterministic IDs. Level‑11 cells (~3 km × 3 km) serve as the classification label space and are indexed in Lucene for efficient lookup. *Quick check:* If S2 cells are hierarchical, what are the trade‑offs in using level‑11 cells versus coarser (level‑9) or finer (level‑13) levels for this retrieval problem?
- **Extreme Multi‑Label Classification** – *Why needed:* Predicting from ~100K–140K classes is far beyond standard multi‑class tasks. Techniques like sampled softmax, vocabulary reduction, and problem decomposition (sharding) make it feasible; the assumption that classification performance scales to this extreme regime is central. *Quick check:* Why is sampled softmax with 25K negatives necessary here, and what is a key risk of using it (e.g., bias in negative sampling)?
- **Two‑Stage Retrieval & Ranking Architecture** – *Why needed:* This system is a *retrieval* layer, not the final ranker; its purpose is to produce a candidate set of listings via S2 cell filtering for downstream, more expensive ranking models. The engineer must separate concerns: this model optimizes for precision/recall of *geographic relevance*, not final booking conversion. *Quick check:* How could an improvement in retrieval precision lead to a *decrease* in final bookings if the downstream ranker is not retrained?

## Architecture Onboarding
### Component Map
Feature Store → Continental Router → Regional Scorers (3 DNNs, continent‑specific) → Thresholding Service → Query Translator → Lucene Index → Downstream Pipeline

### Critical Path
User search request → feature extraction → continental classifier selection → DNN scoring → thresholding → Lucene query construction & execution → candidate listing set → downstream filters & ranking → results

### Design Tradeoffs
- **Precision vs. Recall vs. Latency:** Lower λ increases recall (more cells, more listings) but harms precision and increases query fan‑out (slower Lucene queries). The chosen λ balances these offline to match baseline recall.
- **Model Complexity vs. Serving Cost:** Sharding reduces per‑model size/compute but requires routing logic and may miss cross‑continent patterns (e.g., global tourist flows). A single global model was deemed intractable.
- **Feature Set vs. Robustness:** Features were restricted to those least susceptible to overfitting and out‑of‑distribution issues, sacrificing some signal for stability.

### Failure Signatures
- **High latency / query timeouts:** If λ is too low, the disjunctive Lucene query contains thousands of cell terms, causing slow OR‑query execution. Monitor `num_cells_predicted` and Lucene query execution time.
- **"Map blowing up" or irrelevant geography:** If the classifier predicts cells far from the logical destination (e.g., predicting European cells for a "San Francisco" search), it indicates severe model error or feature pipeline bug (e.g., mis‑assigned continent).
- **Recall drop in online metrics:** A mismatch between offline‑booked‑recall and online‑booker impact suggests the held‑out data may not reflect online distribution, or that the recall metric is not perfectly aligned with business value (e.g., recalling a cell with listings that all get filtered out later).

### First 3 Experiments
1. **Unit test S2 cell mapping:** Verify that for a known booked listing with lat/long, the `s2_lvl_11` field in the index matches the cell ID predicted by the model for the corresponding attributed search query. (Validates core data pipeline correctness).
2. **Offline threshold sweep per region:** For each regional model, sweep λ and plot precision‑recall. Confirm the chosen λ (e.g., 0.0005 for Europe) indeed matches baseline recall and identify if a different λ could offer a better precision‑recall trade‑off for a subset of high‑volume queries.
3. **Canary test on a single continent:** Deploy the model for only the "Americas" region in an A/B test (with other regions on baseline). Isolate impact to verify no cross‑region interference and confirm the offline precision‑recall gains translate to the Americas’ user population before a full rollout.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Should the probability threshold λ be learned per query rather than set per region?
- **Basis in paper:** [explicit] Listed as future work: "learning the threshold per query"
- **Why unresolved:** Current thresholds are static (0.0005–0.00075) and tuned to match baseline recall; they may not handle query‑specific uncertainty or objectives.
- **What evidence would resolve it:** Model that predicts optimal λ from query features; A/B test against static thresholds on precision, recall, and uncancelled bookers.

### Open Question 2
- **Question:** Can hierarchical softmax using S2's quadtree structure improve efficiency or accuracy over sampled softmax?
- **Basis in paper:** [explicit] Proposed as next step: "exploiting the S2 hierarchy for hierarchical soft‑max"
- **Why unresolved:** Sampled softmax with 25K negatives is costly; hierarchical approach could reduce computation by exploiting S2 structure.
- **What evidence would resolve it:** Implement hierarchical softmax aligned with S2 tree; compare training/inference speed and precision‑recall metrics on validation data.

### Open Question 3
- **Question:** Which omitted baseline features or new engineered features would improve model performance while maintaining computational efficiency?
- **Basis in paper:** [explicit] Feature engineering listed as next step; they used only "a subset of features… that were the least susceptible to these issues" (overfitting, out‑of‑distribution).
- **Why unresolved:** The baseline retrieval bounds model used more features; some potentially valuable ones were excluded without testing.
- **What evidence would resolve it:** Feature importance analysis and systematic reintroduction of baseline features plus new engineered features, with validation on held‑out data and monitoring for overfitting and latency.

## Limitations
- Relies on concentration of bookings within level‑11 S2 cells; in low‑density areas the cells may be too coarse, forcing low thresholds and harming precision.
- Static per‑continent threshold λ ignores intra‑continent query heterogeneity (e.g., urban vs. rural).
- Vocabulary limited to historically booked cells could omit new bookable locations.
