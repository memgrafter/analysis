# DependencyAI: Detecting AI Generated Text through Dependency Parsing

## Quick Facts
- **arXiv ID:** 2602.15514
- **Source URL:** https://arxiv.org/abs/2602.15514
- **Reference count:** 12
- **Primary result:** Achieves F1 scores of 88.94 (multi-way) and 96.12 (multilingual) on M4GT-Bench using only syntactic dependency labels, matching or exceeding transformer-based detectors like XLM-R in several languages.

## Executive Summary
DependencyAI introduces a lightweight, interpretable detector for AI-generated text that relies exclusively on syntactic dependency relation labels as features. By vectorizing parsed dependency labels with TF-IDF (1,2)-grams and training a LightGBM classifier, the method demonstrates strong performance on the M4GT-Bench benchmark. It competes effectively with more complex transformer models, particularly in multilingual settings, and highlights that systematic dependency patterns—not just lexical content—are a robust signal for detection. However, analysis indicates vulnerabilities to domain shifts and generator-specific stylistic variations.

## Method Summary
The pipeline begins with standard dependency parsing of input text to extract universal dependency relation labels (e.g., `nsubj`, `obj`, `punct`). These labels are treated as a sequential "syntactic fingerprint." The label sequences are vectorized using TF-IDF with (1,2)-grams to capture both individual dependencies and common adjacent pairs. A LightGBM classifier is then trained on these features to distinguish human-written from AI-generated text or to classify the generator source. No lexical tokens, embeddings, or semantic features are used.

## Key Results
- On multi-way detection (multiple generators/domains), DependencyAI achieves an F1 score and accuracy of **88.94**, outperforming other feature-based detectors and matching XLM-R.
- In multilingual detection, it surpasses XLM-R with an overall **F1 of 96.12**, including exceptional performance on Russian (**F1 99.50**).
- Feature importance analysis shows that language-agnostic patterns like `UNSPECIFIED` dependencies and interactions with punctuation are highly predictive, offering interpretability.

## Why This Works (Mechanism)
AI-generated text, despite its fluency, exhibits subtle but consistent syntactic distributional shifts in dependency structures compared to human writing. LLMs may overuse or underuse certain grammatical relations, create atypical dependencies, or handle punctuation and function words differently. These patterns manifest in the frequency and co-occurrence of Universal Dependency labels, which TF-IDF captures effectively. The LightGBM model learns to recognize these distributional anomalies as a strong, language-agnostic signal, distinct from lexical or semantic fingerprints.

## Foundational Learning
- **Dependency Parsing (Universal Dependencies):** Maps grammatical relations between words. *Why needed:* Provides a normalized, language-agnostic representation of syntax. *Quick check:* Can parse a sentence and list the `deprel` labels for each token.
- **TF-IDF Vectorization:** Weighs term (or n-gram) frequency by inverse document frequency. *Why needed:* Converts variable-length dependency label sequences into fixed-length feature vectors, highlighting distinctive patterns. *Quick check:* Given two small document sets of dependency sequences, compute TF-IDF for bigrams manually.
- **LightGBM Gradient Boosting:** A tree-based ensemble classifier. *Why needed:* Efficiently models non-linear interactions between dependency n-gram features. *Quick check:* Understand how boosting builds additive trees and handles categorical/numerical features.
- **M4GT-Bench Benchmark:** A standard multi-generator, multi-domain dataset for AI text detection. *Why needed:* Provides a controlled, comparable evaluation suite. *Quick check:* Know its composition (generators like GPT-3, domains like news, essays).
- **Multi-way vs. Binary Classification:** Distinguishing among multiple generators vs. just human vs. AI. *Why needed:* Assesses model granularity and robustness to generator diversity. *Quick check:* Understand how a single classifier can handle >2 classes (softmax objective).
- **Feature Importance (SHAP/Gain):** Interpretability methods for tree models. *Why needed:* Reveals which dependency patterns drive predictions, supporting the core hypothesis. *Quick check:* Can interpret a gain-based importance plot for a LightGBM model.

## Architecture Onboarding
**Component Map:**
Raw Text -> Dependency Parser (Extract `deprel` labels) -> Label Sequence -> TF-IDF Vectorizer (1,2-grams) -> Feature Vector -> LightGBM Classifier -> Prediction (Human/Generator ID)

**Critical Path:** The signal fidelity path is: Text quality -> Parser accuracy -> Label sequence fidelity -> TF-IDF capture of distributional shifts -> Model learning. Parser errors or domain-specific label set mismatches directly degrade input quality.

**Design Tradeoffs:**
- *Pros:* Extremely lightweight, interpretable, language-agnostic features, no need for large pretrained models or lexical data.
- *Cons:* Ignores semantics and word choice; fully dependent on parser quality; may fail on highly adversarial or paraphrased text that alters surface syntax while preserving meaning.

**Failure Signatures:**
- **Domain Shift:** Sudden drop in accuracy on a new domain (e.g., social media) not seen during training, especially for certain generators (as observed).
- **Parser Error Propagation:** Systematic misclassifications correlated with known parser weaknesses (e.g., long-distance dependencies, informal grammar).
- **Generator Convergence:** Inability to distinguish between two generators with highly similar syntactic distributions in a given domain.

**First 3 Experiments:**
1. **Baseline Replication:** Run the exact pipeline on M4GT-Bench train/test splits, reproducing reported F1/accuracy scores for multi-way and multilingual tasks.
2. **Ablation - n-gram Range:** Compare performance of TF-IDF using only unigrams (1) vs. (1,2)-grams vs. only bigrams (2) to validate the design choice.
3. **Parser Impact Test:** Swap the dependency parser (e.g., from spaCy to Stanza) and measure performance delta to quantify parser robustness.

None.

## Limitations
- Systematic overprediction for certain generators in unseen domains indicates limited cross-domain robustness.
- Reliance solely on dependency labels ignores potentially critical lexical, semantic, and discourse cues; parser errors may propagate.
- Performance is validated only on M4GT-Bench; applicability to newer LLMs or adversarially perturbed text is unknown.

## Confidence
- **Competitive performance on M4GT-Bench:** High
- **Superior multilingual detection vs. XLM-R:** Medium
- **Robustness of dependency patterns as a universal signal:** Medium/Low
- **Generator-specific stylistic influence on generalization:** Medium

## Next Checks
1. **Out-of-distribution (OOD) stress test:** Evaluate DependencyAI on completely unseen generators (e.g., GPT-4, Claude 3) and domains (e.g., social media, creative writing) not in M4GT-Bench; measure performance drop vs. in-distribution baseline.
2. **Head-to-head with latest SOTA detectors:** Replicate experiments comparing against current transformer-based detectors (e.g., DeBERTa-v3, RAID) on identical M4GT-Bench splits; verify if performance parity holds under fair resource/access constraints.
3. **Ablation and error analysis:** (a) Remove dependency features, use only other syntactic cues (POS tags); (b) test alternative vectorizers (e.g., embeddings); (c) manually analyze 100 misclassifications to quantify parser error contribution and identify failure modes per generator.
