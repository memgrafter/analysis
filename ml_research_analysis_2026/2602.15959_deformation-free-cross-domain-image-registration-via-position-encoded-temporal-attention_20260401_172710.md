# Deformation-Free Cross-Domain Image Registration via Position-Encoded Temporal Attention

## Quick Facts

- **arXiv ID:** 2602.15959  
- **Source URL:** https://arxiv.org/abs/2602.15959  
- **Reference count:** 30  
- **Primary result:** Achieves state-of-the-art on FIRE-Reg-256 (SSIM 0.928, PSNR 33.47 dB) and HPatches-Reg-256 (SSIM 0.450, PSNR 21.01 dB) with 1.87× speedup over SAS‑Net.

## Executive Summary

Cross-domain image registration, where geometric misalignment is coupled with appearance shift, is tackled by factorizing each image into a domain‑invariant scene representation and a global appearance statistic. The moving image’s scene features are combined with the fixed image’s appearance code via Adaptive Instance Normalization (AdaIN), eliminating explicit deformation estimation. A position‑encoded cross‑frame attention module enriches the scene representation with temporal context from neighboring frames, exploiting coherence in sequential acquisitions. The resulting GPEReg‑Net attains state‑of‑the‑art accuracy on retinal and synthetic affine benchmarks while running significantly faster than prior works.

## Method Summary

GPEReg‑Net consists of four components: a Scene Encoder (U‑Net with InstanceNorm) strips per‑image intensity statistics to produce a 64‑channel feature map `s`. An Appearance Encoder (CNN + Global Average Pooling) yields a 32‑dimensional global code `a` capturing intensity profile. For sequential inputs, a Global Position Encoding module fuses learnable and sinusoidal position embeddings with multi‑head cross‑frame attention over a sliding window of `k=2` neighbors; its output is residual‑scaled and added to `s`. An Image Decoder (three AdaIN‑Conv blocks) finally recombines the enriched scene features `s̃` with the appearance code `a` to output the registered image `Î_r`. Training uses an L1 reconstruction loss plus an L2 scene‑consistency term (`λ=10`). The architecture avoids any spatial warping layer; registration is achieved solely by factorization and recombination.

## Key Results

- SOTA on FIRE‑Reg‑256: SSIM 0.928, PSNR 33.47 dB.  
- SOTA on HPatches‑Reg‑256: SSIM 0.450, PSNR 21.01 dB.  
- 1.87× faster inference than SAS‑Net (69 FPS on RTX 5090).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Cross‑domain registration reduces to recombining a domain‑invariant scene representation from the moving image with a global appearance statistic from the fixed image via AdaIN, eliminating explicit deformation estimation.  
- **Mechanism**: The Scene Encoder (U‑Net with InstanceNorm) produces spatial structure features `s ∈ ℝ^{64×H×W}` by stripping per‑image intensity statistics. The Appearance Encoder (CNN + GAP) produces a 32‑dim global code `a` encoding intensity profile. AdaIN modulates `s` using `a`’s channel‑wise affine parameters, transferring target appearance onto aligned scene structure.  
- **Core assumption**: Domain shift is predominantly global (e.g., illumination, contrast) and orthogonal to spatial structure; scene features from both domains align after InstanceNorm.  
- **Evidence anchors**: [abstract] “decomposing each image into a domain‑invariant scene representation and a global appearance statistic, such that registration reduces to recombining the scene structure of I_m with the appearance of I_f via Adaptive Instance Normalization (AdaIN). This factorization eliminates the need for explicit deformation field estimation.”; [section 2.2] “Instance Normalization (IN), which strips per‑instance intensity statistics while preserving spatial structure.”; [corpus] weakly supported: neighbors (SAS‑Net, disentanglement paper) explore similar factorization but lack GPEReg‑Net’s temporal attention; this is an active research thread with moderate FMR scores (0.465‑0.612), indicating emerging but not saturated evidence.  
- **Break condition**: When domain shift includes spatially‑varying appearance (e.g., local shadows, specularities) that a global code cannot capture; or when geometric misalignment exceeds the capacity of scene features to encode correspondence (e.g., large non‑rigid deformations).

### Mechanism 2
- **Claim**: Position‑encoded cross‑frame attention exploits temporal coherence in sequential acquisitions by enriching scene features with inter‑frame context from a sliding window of neighbors.  
- **Mechanism**: The Global Position Encoding module fuses (1) learnable embeddings `e_t` from a table of size N, (2) fixed sinusoidal encodings `p_t` for smooth frequency interpolation, and (3) multi‑head cross‑frame attention (H=4) over `k=2` neighboring frames. A two‑layer MLP fuses these, and the output is added to scene features with scaling α=0.1: `s̃ = s + α·W_proj(g_t + c_t)`.  
- **Core assumption**: Adjacent frames in a sequence share similar scene structure; temporal context improves representation consistency. Sinusoidal encoding generalizes beyond training sequence length, while learnable embeddings adapt to dataset‑specific positioning.  
- **Evidence anchors**: [abstract] “position‑encoded cross‑frame attention mechanism that fuses learnable and sinusoidal position embeddings with multi‑head attention over a sliding window of k neighboring frames, enriching the scene representation with inter‑frame context.”; [section 2.3] Details of GPE module, including “cross‑frame multi‑head attention (H=4) that queries the current frame’s spatially‑averaged scene features against a running cache of k=2 neighboring frames.”; [corpus] Authors’ prior work on temporal models (Bio‑inspired Mamba, Ancestral Mamba) suggests expertise, but no direct evidence of effectiveness in neighbors; paper’s FIRE dataset (sequential retinal scans) is the primary validation.  
- **Break condition**: For non‑sequential (single‑pair) registration, the GPE module is unnecessary and may inject noise. Also, with abrupt scene changes between frames or when `k` is too small to capture relevant context, the attention could aggregate irrelevant features. The fixed embedding table limits extrapolation to sequences longer than N.

### Mechanism 3
- **Claim**: The orthogonal factorization—InstanceNorm preserves spatial structure while GAP discards spatial information—theoretically justifies that scene features become domain‑invariant, enabling registration via AdaIN recombination alone.  
- **Mechanism**: Information‑theoretically, InstanceNorm in the Scene Encoder removes per‑channel first/second‑order statistics (mean, variance) but retains spatial activation patterns. The Appearance Encoder’s GAP collapses all spatial dimensions, leaving only channel‑wise statistics. AdaIN then rescales normalized scene features with target appearance’s affine parameters, effectively transferring appearance while preserving spatial correspondence.  
- **Core assumption**: The two factors are approximately independent: “what” (scene structure) and “how” (appearance). If factorization succeeds, `S(I_m) ≈ S(I_f)` despite intensity differences, so aligning `s_m` to `s_f` is automatic; AdaIN merely recolors.  
- **Evidence anchors**: [section 3.4] “Instance normalization in S removes per‑channel first‑ and second‑order statistics (µ_c, σ_c), retaining only the spatial structure of feature activations. Global average pooling in A discards all spatial information, retaining only channel‑wise statistics. These two operations define an approximately orthogonal factorization: s captures ‘what is where’ while a captures ‘how it looks.’”; [abstract] Implicit in “decomposing each image into a domain‑invariant scene representation and a global appearance statistic.”; [corpus] Neighbors (SAS‑Net, disentanglement paper) use similar disentanglement; moderate FMR scores (0.465‑0.612) suggest the approach is promising but not universally proven.  
- **Break condition**: If the two factors are not truly orthogonal—e.g., some appearance cues are embedded in spatial structure (texture‑dependent edges) or scene features retain domain information—then `S(I_m) ≠ S(I_f)` and AdaIN alone cannot align. Limitations section acknowledges: “spatially‑varying domain shifts (e.g., local illumination gradients) may require a spatially‑conditioned appearance map a(x).”

## Foundational Learning

### Concept: Instance Normalization (IN)
- **Why needed here**: Ensures scene features are invariant to per‑image brightness/contrast variations. Without IN, scene features would encode domain‑specific intensity, breaking the factorization assumption.  
- **Quick check**: Does IN completely remove domain information, or could higher‑order statistics or spatial correlations still carry domain signals?

### Concept: Adaptive Instance Normalization (AdaIN)
- **Why needed here**: The recombination operator that transfers target appearance onto source scene without spatial warping. It uses target appearance code to compute channel‑wise affine parameters applied to normalized source features.  
- **Quick check**: Since AdaIN only applies a single affine transform per channel, can it handle spatially‑varying appearance differences? What if the misalignment includes local intensity shifts?

### Concept: Position Encoding in Transformers
- **Why needed here**: Encodes temporal frame index into a vector that attention can use to distinguish frames and model proximity. The combination of learnable and sinusoidal embeddings provides both adaptability and extrapolation capability.  
- **Quick check**: Why not use only sinusoidal or only learnable embeddings? What failure modes does the fusion guard against?

## Architecture Onboarding

**Component map:**  
Scene Encoder S: I_m → s_m (64×H×W); Appearance Encoder A: I_f → a_f (32‑dim); Global Position Encoding G: (s_m, t) → s̃_m; Decoder D: AdaIN(s̃_m, a_f) → Î_r.

**Critical path:**  
1. Input moving image I_m, fixed image I_f, frame index t.  
2. Scene extraction: s_m = S(I_m).  
3. Appearance extraction: a_f = A(I_f).  
4. Temporal enrichment: s̃_m = G(s_m, t) using cross‑frame cache (k=2).  
5. Recombination & decoding: Î_r = D(AdaIN(s̃_m, a_f)).  
6. Loss: L = ||Î_r – I_f||₁ + λ·||S(I_m) – S(I_f)||₂² (λ=10).

**Design tradeoffs:**  
- Scene Encoder depth vs speed: Deeper U‑Net preserves finer details but increases latency; 4‑level design balances performance (69 FPS).  
- Appearance code size (32): Low‑dim forces global summary; larger may capture spatial appearance (bad for factorization).  
- Temporal window size (k=2): Small window reduces computation and assumes smooth motion; larger may capture longer dependencies but risks mixing dissimilar frames.  
- Residual scaling (α=0.1): Subtle addition prevents destabilizing scene features; higher α risks overwriting structure.  
- InstanceNorm in Scene Encoder: Critical for domain invariance; BatchNorm would mix statistics across batch and fail.

**Failure signatures:**  
- High L_scene: Scene features from moving and fixed images not aligned → check by visualizing S(I_m) vs S(I_f); if they differ significantly, factorization broken (perhaps IN ineffective or network undertrained).  
- Temporal artifacts: Flickering or ghosting in sequential outputs → inspect cross‑frame attention weights; may indicate attention aggregating from occluded or moving objects.  
- Appearance mismatch: Î_r has wrong global intensity/contrast despite good alignment → verify a_f matches target domain distribution; maybe Appearance Encoder undertrained.  
- Over‑smooth results: Loss of fine details → scene feature resolution may be too low; consider increasing Scene Encoder channels or adding skip connections to decoder.

**First 3 experiments:**  
1. Ablation: Remove AdaIN (directly decode s_m without appearance transfer) → expect significant SSIM/PSNR drop on both datasets, proving appearance transfer necessary.  
2. Ablation: Disable GPE (k=0) → measure performance drop on FIRE (sequential) vs HPatches; expect bigger drop on FIRE if temporal context helps.  
3. Vary appearance code dimensionality (16, 32, 64, 128) → expect peak at 32; smaller loses appearance fidelity (lower PSNR), larger may not improve or slightly degrade if spatial leakage occurs.

## Open Questions the Paper Calls Out

### Open Question 1  
- **Question:** How can the appearance model be extended to handle spatially‑varying domain shifts, such as local illumination gradients or spatially‑correlated noise?  
- **Basis:** Limitations explicitly state that the global appearance code captures only global intensity statistics; a spatially‑conditioned appearance map a(x) may be needed.  
- **Why unresolved:** Evaluation only on datasets with predominantly global shifts; spatially‑varying shifts not systematically tested.  
- **What evidence would resolve it:** Introduce datasets with controlled local intensity variations and compare global vs spatially‑conditioned appearance models using SSIM/PSNR and residual analysis.

### Open Question 2  
- **Question:** Can the position encoding module be made adaptive or continuous to generalize beyond fixed‑length sequences, and how does this affect temporal coherence modeling?  
- **Basis:** Limitations note fixed embedding table E∈R^{N×64} limits generalization to sequences longer than N frames.  
- **Why unresolved:** Performance on variable‑length or streaming sequences is unexplored.  
- **What evidence would resolve it:** Evaluate on longer video sequences, replacing the fixed table with continuous encoding (e.g., sinusoidal interpolation) or learned adaptive embeddings, and measure registration consistency (temporal NCC) and robustness to sequence length changes.

### Open Question 3  
- **Question:** Under what conditions does the assumed orthogonal factorization between scene (via instance normalization) and appearance (via global pooling) break down, particularly for complex domain shifts involving non‑global statistical changes?  
- **Basis:** The method relies on an information‑theoretic argument that IN discards first/second‑order statistics while GAP discards spatial information; this is not validated beyond two datasets with mostly global shifts.  
- **Why unresolved:** Experiments lack datasets where domain shifts involve spatially‑structured intensity changes (e.g., stain variation in histopathology).  
- **What evidence would resolve it:** Design controlled experiments where domain shifts are purely global vs spatially‑varying, then analyze mutual information between learned scene features s and appearance codes a, or visualize feature maps for residual appearance information in s.

### Open Question 4  
- **Question:** How sensitive is the temporal attention mechanism to the sliding window size k, and does the optimal k depend on the temporal coherence scale of the underlying sequences?  
- **Basis:** GPE uses a fixed sliding window of k=2 without ablation; this hyperparameter may significantly affect performance depending on motion dynamics.  
- **Why unresolved:** No analysis of varying k; critical for sequences with different motion speeds.  
- **What evidence would resolve it:** Ablation study on both benchmarks (and possibly a new dynamic sequence dataset) varying k (1, 2, 4, 8) and measuring registration accuracy (SSIM/PSNR) and temporal smoothness (frame‑to‑frame feature consistency). Correlate optimal k with estimated motion velocity or frame rate.

## Limitations

- Scene‑appearance factorization may fail for spatially‑varying domain shifts (e.g., local illumination gradients).  
- Temporal attention design is ambiguous; details of neighbor‑cache management and fusion are underspecified, and the module may be unnecessary or harmful for single‑pair registration.  
- Generalization to large non‑rigid deformations or complex real‑world domain shifts is not demonstrated.

## Confidence

- **Factorized Registration (AdaIN recombination):** Medium (supported by two datasets but theoretical orthogonality not rigorously proven).  
- **Position‑Encoded Temporal Attention:** Low (evidence limited to sequential retinal scans; no isolation of temporal contribution on non‑sequential data).  
- **Efficiency Advantage:** High (concrete FPS/latency numbers provided).

## Next Checks

1. **Feature Statistics Audit:** Quantify domain invariance by measuring channel‑wise mean/variance of S(I) after InstanceNorm across different input domains. If |µ_c| > 0.01 or |σ_c – 1| > 0.05 consistently, factorization is weak.  
2. **Attention Cache Behavior Inspection:** During inference on a sequential test set, log cached neighbor features and attention weights. Expect attention to peak on temporally adjacent frames (|t_neighbor – t_current| ≤ 1). Low variance or focus on distant frames indicates cache misconfiguration.  
3. **Non‑Sequential Generalization Test:** Run the trained model on a single‑pair registration benchmark (e.g., IXI, OASIS) without temporal context (disable GPE). A >1 dB PSNR drop relative to the GPE‑enabled version on FIRE would confirm that gains are sequential‑specific; if performance remains competitive, the scene factorization alone is robust.
