# NeSy-Route: A Neuro-Symbolic Benchmark for Constrained Route Planning in Remote Sensing

## Quick Facts
- **arXiv ID:** 2603.16307
- **Source URL:** https://arxiv.org/abs/2603.16307
- **Reference count:** 40
- **Primary result:** Introduces a neuro-symbolic benchmark with 10,821 optimally solved route planning tasks; evaluation of state-of-the-art MLLMs reveals severe deficiencies in constrained planning (best adherence 18.7–32.7%, cost ratios 1.24–12.87).

## Executive Summary
NeSy-Route addresses the lack of constrained route planning benchmarks for multimodal LLMs in remote sensing. It presents a fully automated pipeline that combines high-fidelity semantic masks with heuristic A-star search to generate a large, diverse dataset of planning problems with provably optimal solutions. The benchmark employs a three-level hierarchical evaluation protocol to separately measure textual constraint understanding, text-image constraint alignment, and the final constrained route planning task. Results from evaluating leading MLLMs show a critical performance collapse, particularly on the planning stage, highlighting a fundamental gap in current models' abilities to integrate perception, reasoning, and planning under complex spatial constraints.

## Method Summary
The benchmark is built from OpenEarthMap remote sensing images and their segmentation masks. An automated pipeline first samples a configuration (agent type, objective, start/end land cover classes, allowed classes). From this, a natural language query is generated using DeepSeek-V3.2 and validated by Gemini-3-Pro. The segmentation mask is processed via morphological erosion to create pure region blobs for reliable visual grounding. A ground-truth solver constructs a cost map from symbolic traversability (`V_trav`) and preference (`V_pref`) vectors, then applies A-star search to produce an optimal sparse waypoint trajectory. Models are evaluated on three hierarchical tasks: (1) extracting `V_trav`/`V_pref` from text, (2) aligning these constraints to specific regions in the image, and (3) generating a feasible, low-cost waypoint path given start/end points. Metrics include Traversability Matching (TM), Preference Ranking (PR), Region Matching (RM), Adherence Rate (AR), Violation Ratio (VR), and Cost Ratio (CR) compared to the optimal path.

## Key Results
- Established a large-scale benchmark with 10,821 instances acrossEasy/Medium/Hard difficulties, each with a provably optimal solution.
- Hierarchical evaluation exposes a severe bottleneck: all tested MLLMs exhibit very low adherence (18.7–32.7%) and high cost ratios (up to 12.87) on the final constrained planning task.
- Performance degrades sharply with scene complexity, and strong performance on constraint extraction/alignment does not translate to planning success.

## Why This Works (Mechanism)
### Mechanism 1: Symbolic Constraint Extraction from Text
**Claim:** MLLMs must convert natural language mission descriptions into formal binary traversability and ordinal preference vectors before any spatial reasoning can occur.  
**Mechanism:** The model parses the text query `Q` to output `V_trav` (binary traversability per land class) and `V_pref` (priority rankings). This symbolic grounding is the prerequisite for all downstream tasks.  
**Core assumption:** The textual description contains unambiguous, logically consistent constraints that map directly to the predefined knowledge base rules.  
**Evidence anchors:**  
- [abstract] "Textual constraint understanding... decode natural language instructions into formal symbolic logic."  
- [section 3.2] Formally defines `f_text: Q → (V_trav, V_pref)` as Task 1's objective.  
- [corpus] Supported by neighboring work identifying symbolic extraction as a foundational bottleneck.  
**Break condition:** If `V_trav` misclassifies a land cover's traversability (e.g., marks water as traversable for a pedestrian), all subsequent stages fail. Evidence: Tab. 4 shows models with low TM cannot achieve high scores in later tasks.

### Mechanism 2: Cross-Modal Constraint Anchoring
**Claim:** The model must correctly identify which visual regions in the segmentation map correspond to which textual land-cover classes and then apply the symbolic vectors to those specific regions.  
**Mechanism:** Given `Q` and an image `I` with region IDs, the model outputs `V'_reg` (region IDs per class), `V'_trav`, and `V'_pref`. This aligns abstract symbols to concrete pixel groups.  
**Core assumption:** The segmentation map contains pure, identifiable regions for each relevant land class.  
**Evidence anchors:**  
- [abstract] "Text–Image constraint alignment... anchor these symbolic constraints to specific identified regions."  
- [section 3.2] Defines `f_align: (Q, I) → (V'_reg, V'_trav, V'_pref)` and the region matching metric (RM).  
- [section 3.3] Describes morphological erosion to create "maximum inscribed pure regions."  
**Break condition:** Failure in `V'_reg` (low RM) or misapplication of `V'_trav/V'_pref`. Evidence: Tab. 5 shows performance drops sharply from Task 1 to Task 2.

### Mechanism 3: Cost-Aware Spatial Planning with Symbolic Constraints
**Claim:** The model must generate a sparse waypoint sequence that, when densified, respects the cost map (`W(p)`) and finds a low-cost path between given points.  
**Mechanism:** The model predicts `τ` (waypoints). The evaluator reconstructs a dense path using A-star on `W(p)` where non-traversable pixels have infinite cost and traversable pixels have costs `max(V'_pref) - V_pref[class] + 1`. Optimality is defined by minimizing `Σ W(p)`.  
**Core assumption:** The model can perform spatial reasoning over a 2D grid and implicitly minimize cumulative cost.  
**Evidence anchors:**  
- [abstract] "Constrained route planning... generate an executable waypoint sequence... minimize the cumulative cost."  
- [section 3.2] Formulates `f_plan: (I, Q, S, E) → τ` with the minimization objective.  
- [section 3.3] Details A-star search and proves optimality conditions for the ground-truth solver.  
**Break condition:** Generated waypoints `τ` include non-traversable pixels (high VR) or the resulting path has a high cost ratio (CR). Evidence: Tab. 6 shows best AR only 18.7–32.7% and CR up to 12.87.

## Foundational Learning
- **Concept: Land Cover Traversability Taxonomy**  
  *Why needed:* The entire benchmark rests on a predefined ontology (8 classes) with agent-specific traversability rules (Always, Conditionally, Never). Models must internalize this symbolic knowledge to extract correct vectors.  
  *Quick check:* For a pedestrian agent (Tab. 1), which land cover classes are *conditionally traversable* (TC)?

- **Concept: Cost Map Construction from Preference Rankings**  
  *Why needed:* Planning quality is judged by cumulative cost. The model must understand that a higher `V_pref` value means *lower* traversal cost (`cost = max(V'_pref) - V_pref[class] + 1`).  
  *Quick check:* If `V'_pref` for Road is 4 and for Bareland is 1 (on a 1–5 scale), which terrain contributes less to the path cost?

- **Concept: Heuristic Search Optimality**  
  *Why needed:* The ground-truth paths are *provably optimal* under the cost map. Understanding "optimal" (minimizing `Σ W(p)`) is key to interpreting the CR metric.  
  *Quick check:* If a model's path has a CR of 1.0, how does its total cost compare to the ground-truth path's cost?

## Architecture Onboarding
- **Component map:** Knowledge Base -> Query Synthesizer -> Semantic Grounding (Morphological Erosion) -> Trajectory Solver (GT A-star) -> Symbolic Evaluator. Model processes (I, Q, S, E) at the end.
- **Critical path:** KB defines rules -> Sample configuration -> Generate/validate Q -> Ensure image supports Q -> Erode mask for pure regions -> Build region graph -> Apply traversability mask -> Construct cost map W(p) -> Run A-star for τ* -> Evaluate model τ against τ*.
- **Design tradeoffs:** Automation vs. Diversity (scales to 10k+ but may lack linguistic nuance); Symbolic rigor vs. Realism (pure regions, noise-free KB ensure clean eval but not real-world noise); Optimality guarantee (A-star provides provable GT only because W(p) is discrete and noise-free).
- **Failure signatures:**  
  Task 1: Low TM/FM → cannot parse textual constraints.  
  Task 2: RM/TM drop from Task 1 → visual grounding failure; negative PR → mis-ranking.  
  Task 3: Low AR → waypoints on non-traversable pixels; High CR → inefficient path; High VR → severe constraint violation.
- **First 3 experiments:**  
  1. **Benchmark replication:** Run GPT-5.1 on all tasks; verify Tab. 4–6 numbers.  
  2. **Ablation on visual difficulty:** Evaluate one model on Task 2/3 across Easy/Medium/Hard; confirm performance degradation.  
  3. **Cross-task correlation analysis:** Plot Task 1 TM vs. Task 2 TM vs. Task 3 AR; reproduce finding that strong early performance does not ensure planning success.

## Open Questions the Paper Calls Out
**Open Question 1**  
*Question:* How can MLLM architectures be redesigned to effectively integrate perception, reasoning, and planning for constrained route planning, moving beyond the "perception-then-planning" pipeline that leads to performance collapse in complex scenes?  
*Basis in paper:* [explicit] The authors state that "current remote sensing MLLMs rely on outdated architectures" and find a "disparity" where models that avoid obstacles produce highly inefficient global paths.  
*Why unresolved:* Existing MLLMs are sequence-to-sequence generators not optimized for symbolic constraint satisfaction and cost minimization. The benchmark reveals a cognitive gap between recognizing traversable regions and synthesizing a globally optimal path.  
*What evidence would resolve it:* Development and rigorous evaluation (using NeSy-Route) of a novel architecture or training paradigm that explicitly reasons over a symbolic world model before generating a trajectory.

**Open Question 2**  
*Question:* To what extent do the symbolic constraints and optimal solutions in NeSy-Route generalize to real-world, dynamic remote sensing scenarios (e.g., changing weather, moving obstacles, partial map observability)?  
*Basis in paper:* [inferred] The benchmark uses static masks and deterministic A*; the motivation cites "disaster relief" which involves dynamics, but the framework is static and fully observable.  
*Why unresolved:* Automated generation guarantees optimal solutions for a fixed cost map, not testing replanning, sensor noise, or temporal variation.  
*What evidence would resolve it:* An extension introducing temporal dynamics, stochasticity, or partial observability, evaluating robust planning or incremental replanning.

**Open Question 3**  
*Question:* What specific mechanisms in vision-language models cause the severe performance degradation from Task 2 (text-image constraint alignment) to Task 3 (planning), and can improved cross-modal grounding directly mitigate planning failures?  
*Basis in paper:* [explicit] Hierarchical analysis shows "strong performance in the first and second tasks does not ensure success in the third task." Tables 5–6 show models like Qwen3-VL-235B-A22B have good alignment but poor planning.  
*Why unresolved:* The paper identifies the gap but does not diagnose its root cause—is it lack of spatial reasoning, inability to compose constraints into an optimization problem, or difficulty generating precise coordinates?  
*What evidence would resolve it:* Fine-grained error analysis on planning failures for models with high Task 2 scores. Intervention studies where correct symbolic vectors are *provided* for Task 3 to isolate the bottleneck.

**Open Question 4**  
*Question:* Can the neuro-symbolic generation and evaluation loop of NeSy-Route be leveraged to create targeted training data that specifically improves the weakest link—constrained planning—in current MLLMs?  
*Basis in paper:* [explicit] The paper presents NeSy-Route as an *evaluation* benchmark and hopes it can "support further research." The generation framework is fully automated and symbolic.  
*Why unresolved:* While the benchmark identifies deficiencies, it does not explore its use as a *training* resource. It is unknown if fine-tuning on these planning problems can instill the capability or if architectural changes are prerequisite.  
*What evidence would resolve it:* A study where MLLMs are fine-tuned on the Task 3 training portion; evaluation would test if fine-tuning closes the gap on test set and generalizes.

**Open Question 5**  
*Question:* How do the definitions of traversability and preference in the knowledge base influence the complexity of the planning problem and model performance, and are the current definitions sufficiently nuanced for diverse real-world agents?  
*Basis in paper:* [explicit] The KB defines three traversability levels and four agent types. The complexity score (D) incorporates topological metrics but not the *logical complexity* of constraint rules.  
*Why unresolved:* Difficulty is stratified by visual scene complexity, not by combinatorial complexity of the symbolic constraint vector. It is unclear if models fail more on problems with many "conditional" classes or complex preference orders.  
*What evidence would resolve it:* An ablation where difficulty is controlled by number of conditional traversability classes or preference ranking depth. Extending the agent KB with more nuanced profiles (e.g., "wheelchair user") would test generalizability.

## Limitations
- Prompt templates and output parsing logic are unreleased, risking implementation bias in evaluations.
- Morphological erosion parameters (kernel size, iterations) for region purity are unspecified, affecting visual grounding difficulty.
- Knowledge base oversimplifies real-world traversability (ignoring context like weather or agent condition).
- Synthetic queries lack natural language nuance, potentially underrepresenting real mission descriptions.

## Confidence
- **Symbolic extraction bottleneck:** High (Tab. 4 shows strong Task 1→3 correlation; break condition validated).
- **Cross-modal alignment bottleneck:** High (Tab. 5 shows consistent Task 1→2 drop; RM metric directly tests grounding).
- **Planning deficiency:** High (Tab. 6 shows uniformly low AR/high CR across models; optimality provably defined).
- **Difficulty sensitivity:** High (performance degrades sharply from Easy→Hard; H_inter/H_count metrics correlate).
