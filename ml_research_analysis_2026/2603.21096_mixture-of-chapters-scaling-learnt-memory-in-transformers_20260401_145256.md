# Mixture of Chapters: Scaling Learnt Memory in Transformers
## Quick Facts
- arXiv ID: 2603.21096
- Source URL: https://arxiv.org/abs/2603.21096
- Reference count: 40
- Primary result: Adding a learned latent memory bank with chapter‑based routing reduces pretraining loss (2.79 vs 2.86 iso‑FLOP) and greatly improves retention on knowledge benchmarks after instruction fine‑tuning (e.g., ARC‑Challenge forgetting drops from 6.69 to 2.68 points).

## Executive Summary
Transformers lack explicit memory storage; this work augments decoder‑only models with a persistent, learned memory bank of latent tokens accessed via cross‑attention. To scale the bank to 262 K tokens, it partitions the bank into chapters and uses a lightweight router to select a small subset per input, keeping attention cost tractable. In iso‑FLOP comparisons, the memory‑augmented model achieves lower pretraining validation loss and superior retention on knowledge benchmarks after heavy instruction fine‑tuning. Freezing the memory bank during fine‑tuning yields similar results, demonstrating robustness to catastrophic forgetting and providing complementary scaling capacity.

## Method Summary
The proposed Mixture of Chapters (MoC) embeds a fixed‑size trainable memory matrix \(M \in \mathbb{R}^{N_m \times d}\) into a decoder‑only transformer. At memory layers (inserted at depths 2, 6, 10, 14), the current token hidden states \(H\) generate queries \(Q = \text{RMSNorm}(H)W_Q\), while the memory bank provides keys \(K = M W_K\) and values \(V = M W_V\). Cross‑attention \(\text{softmax}(QK^\top/\sqrt{d_h})V\) is added residually to \(H\).

To handle large \(N_m\) (262 K), \(M\) is partitioned into \(C\) chapters of equal length \(T\) (so \(N_m = C \cdot T\)). A router computes a sequence‑level representation \(r = \text{mean}(H, \text{dim}=1)\), then logits \(p = \text{softmax}(W_r r + b_r)\). The top‑\(k\) chapters (plus a shared chapter) are selected; only their concatenated tokens form \(M_S\). Router probabilities scale each chapter’s tokens before RMSNorm. Auxiliary losses (load‑balance and z‑loss) stabilize training. Pre‑training uses 10 B tokens from FineWeb‑Edu, followed by instruction fine‑tuning on UltraChat; the memory bank can be frozen during fine‑tuning to preserve factual knowledge.

## Key Results
- Lower pretraining validation loss (2.79 vs 2.86 under iso‑FLOP).
- Knowledge retention after instruction fine‑tuning: on ARC‑Challenge the vanilla model drops 6.69 pp while MoC drops only 2.68 pp; on BoolQ vanilla drops 6.24 pp while MoC gains +0.24 pp.
- Freezing the memory bank during fine‑tuning yields comparable performance to updating it, confirming robustness to catastrophic forgetting.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Adding a persistent, learned memory bank of latent tokens provides an explicit substrate for storing and retrieving factual knowledge, complementary to implicit parameter storage.
- **Mechanism:** A fixed‑size matrix of randomly initialized latent tokens \(M \in \mathbb{R}^{N_m \times d}\) is maintained and trained end‑to‑end. At designated layers, the current token activations \(H\) produce queries via \(Q = \text{Norm}(H)W_Q\), while the memory bank provides keys and values via \(K = M W_K\), \(V = M W_V\). Cross‑attention \(\text{softmax}(QK^\top/\sqrt{d_h}) V\) retrieves relevant memory content, which is added residually to \(H\).
- **Core assumption:** Knowledge can be effectively encoded and organized in a compact, addressable latent space separate from the main model parameters, and this separation reduces interference during continued training.
- **Evidence anchors:**
  - Abstract: "adds a learned latent memory bank accessed via cross‑attention... explicit associative memory provides complementary capacity."
  - Section 5.1: Full specification of \(\text{MemRead}(H, M)\) with projections and residual addition.
  - Corpus: Weak – neighboring papers focus on MoE sparsity and long‑context methods; none directly evaluate a learned cross‑attention memory bank for retention. The closest is "Memory Layers at Scale" [4] cited in the paper.
- **Break condition:** If the memory bank fails to capture useful patterns beyond what the backbone learns (e.g., validation loss does not improve in iso‑FLOP), the mechanism does not provide complementary capacity.

### Mechanism 2
- **Claim:** Partitioning the memory bank into chapters and routing each input sequence to a small subset enables scaling to very large memory capacities (262K tokens) with tractable compute.
- **Mechanism:** The bank \(M\) is split into \(C\) chapters \(\{M^c \in \mathbb{R}^{T \times d}\}\), where \(N_m = C \times T\). A lightweight router computes a sequence‑level representation \(r = \text{Pool}(H)\) and scores chapters with \(p = \text{softmax}(W_r r + b_r)\). The top‑\(k\) chapters are selected; only their concatenated tokens \(M_S\) are used for cross‑attention, reducing cost from \(O(L N_m)\) to \(O(L k T)\).
- **Core assumption:** Inputs can be effectively assigned to a small, relevant subset of memory chapters at the sequence level, and this coarse‑grained sparsity preserves retrieval quality while dramatically cutting attention FLOPs.
- **Evidence anchors:**
  - Abstract: "partitions the memory bank into chapters and uses a lightweight router to select a small subset per input... enabling scaling to 262K memory tokens while maintaining tractable computation."
  - Section 5.2: Formal description of chapter partition, routing (\(\text{TopK}(p, k)\)), and routed attention over \(M_S\).
  - Corpus: Moderate – active work on MoE sparsity (e.g., "ButterflyViT" [265426], "MiTA Attention" [114675]) and token/index‑based sparsity, but not sequence‑level chapter routing for a memory bank. This is a novel application of MoE routing principles to memory selection.
- **Break condition:** If the router's selections are consistently irrelevant (low load‑balance, high loss on knowledge tasks), the sparse access degrades performance below a dense small bank.

### Mechanism 3
- **Claim:** An explicit, frozen memory bank mitigates catastrophic forgetting of factual knowledge during heavy post‑training (e.g., instruction fine‑tuning), providing architectural robustness.
- **Mechanism:** The memory bank, once trained during pre‑training, serves as a stable repository. During continued training on new objectives (IFT), the backbone adapts while the bank remains unchanged (or changes minimally). The cross‑attention mechanism allows the backbone to continue retrieving anchored facts from the static bank, reducing interference between old and new learning.
- **Core assumption:** Factual knowledge stored in the latent memory bank is less susceptible to gradient‑based overwriting than knowledge embedded solely in the dense backbone parameters, because the bank is a separate, sparse, and (optionally) frozen component.
- **Evidence anchors:**
  - Abstract: "improved knowledge retention under continued training, with robustness to forgetting when transitioning between training phases... freezing the memory bank during fine‑tuning yields similar results."
  - Section 6.2: Table 2: Vanilla drops 6.69 pp on ARC‑C and 6.24 pp on BoolQ; MoC drops only 2.68 pp and gains +0.24 pp. Figure 2 (right) shows IFT loss curves are nearly identical with bank frozen.
  - Corpus: Weak – includes "catastrophic forgetting" papers (e.g., [30] cited) and continual learning in LLMs [36], but none connect it to a frozen, cross‑attended memory bank of this design. The evidence is empirical from this paper's experiments.
- **Break condition:** If the IFT objective is highly contradictory to pre‑training facts (e.g., unlearning), even the memory bank might not prevent interference, or the backbone may learn to ignore a frozen bank.

## Foundational Learning
### Cross‑Attention for Memory Retrieval
- **Why needed:** The memory bank is not a sequential cache but a random‑access store. Cross‑attention is the differentiable mechanism that allows variable‑length token sequences to query a fixed, large set of latent memory slots, computing weighted sums of memory values based on query‑key similarity.
- **Quick check:** If you swap the roles (use memory tokens as queries and sequence as keys/values), what qualitative change in retrieval behavior would you expect, and why is the proposed direction (sequence queries) more suitable for associative recall?

### Mixture‑of‑Experts (MoE) Routing as Conditional Computation
- **Why needed:** MoC adapts the MoE principle of sparse activation: instead of routing to expert FFNs, it routes to chunks of memory (chapters). Understanding MoE's load‑balancing losses, top‑k gating, and expert parallelism is key to interpreting the router's objective and potential failure modes (e.g., router collapse).
- **Quick check:** What would happen if the router were trained without any auxiliary load‑balancing loss? How might the chapter utilization distribution change, and what secondary effects could this have on knowledge coverage?

### Catastrophic Forgetting in Sequential Fine‑Tuning
- **Why needed:** The paper's retention claim sits within the continual learning literature. Forgetting in LLMs during IFT is often due to gradient updates overwriting weights important for previously learned tasks. An architectural "anchor" like a frozen bank could theoretically reduce this.
- **Quick check:** Why does increasing context length during IFT (1024→2048) potentially exacerbate forgetting in the vanilla model, and how might a memory bank help decouple context adaptation from fact retention?

## Architecture Onboarding
**Component map (plain text):**  
Input -> Embedding -> Transformer Block 1 -> ... -> Memory Layer (Router selects chapters from shared Memory Bank, performs Cross‑Attention, adds residual) -> continue through remaining Transformer Blocks -> LM Head -> Output. The Memory Bank is a static matrix partitioned into chapters; the Router outputs a probability distribution over chapters for each sequence.

**Critical path:**  
1. Pre‑training: All components (backbone, memory bank, router) are trained end‑to‑end with router auxiliary losses. The model is trained on a 10 B token subset of FineWeb‑Edu for 9600 steps.  
2. Checkpoint save: The trained memory bank and router weights are saved alongside the backbone.  
3. Instruction fine‑tuning (IFT): Load the checkpoint. Optionally freeze the memory bank (and possibly the router). Continue training the backbone (and memory‑layer projections) on UltraChat_200k for 2 epochs with a lower learning rate. Evaluate on knowledge benchmarks.

**Design tradeoffs:**  
- **Bank size \(N_m\) vs. compute:** Larger \(N_m\) increases capacity but requires more chapters \(C\) or tokens‑per‑chapter \(T\) to keep \(k \cdot T\) manageable; FLOPs scale with \(k \cdot T\), not \(N_m\).  
- **Shared vs. per‑layer bank:** The paper uses a single shared bank for all memory layers. Per‑layer banks would add parameters but could allow specialized memory per layer.  
- **Router granularity:** Sequence‑level routing is cheap but coarse; token‑level routing would be more precise but much more expensive.  
- **\(k\) (chapters selected):** Higher \(k\) improves recall potential but increases memory‑attention FLOPs linearly.

**Failure signatures:**  
- **Router collapse:** Router outputs near‑uniform or concentrates on 1‑2 chapters. Monitor chapter utilization entropy; high auxiliary loss may indicate struggle.  
- **Poor chapter specialization:** All chapters show similar query distributions. Check per‑chapter query similarity histograms.  
- **Degraded retrieval:** Ablation: removing the memory bank *improves* validation loss suggests the bank is distracting or poorly trained.  
- **Forgotten bank:** Freezing the bank *harms* IFT performance (unexpected) suggests the bank was insufficiently pretrained or mis‑routed during IFT.

**First 3 experiments:**  
1. **Memory bank ablation:** Train a model without the memory bank (detached or zeroed). Compare pre‑training loss and IFT forgetting; expect significantly worse forgetting.  
2. **Routing sweep over \(k\):** Train models with \(k \in \{1,2,4,8,16,32,64\}\) (keeping \(N_m\), \(C\) fixed). Plot validation loss and ARC‑Challenge/BoolQ retention vs. \(k\); expect a knee‑point of diminishing returns.  
3. **Bank freezing confirmation:** During IFT run three variants: (a) freeze bank and router, (b) freeze bank only, (c) train all. Compare IFT loss curves and final benchmark scores; (a) ≈ (b) and (c) not significantly better.

## Open Questions the Paper Calls Out
- **Scaling laws for learned memory:** How does performance scale with memory bank size and pretraining compute under iso‑FLOP conditions? The current study uses a fixed 262 K tokens and one pretraining duration; systematic sweeps are needed.  
- **Token‑level routing efficiency:** Can token‑level routing be implemented efficiently (e.g., with optimized kernels) to reduce memory overhead compared to sequence‑level routing?  
- **Dynamic memory updates:** Can the memory bank be updated during continued training or inference without degrading the forgetting robustness observed with frozen banks?  
- **Chapter specialization and interpretability:** How do chapters in the router specialize across input domains? Can targeted interventions (e.g., zeroing specific chapters) localize stored knowledge and allow editing?

## Limitations
- Router auxiliary losses (load‑balance equation, z‑loss) and the meaning of "routed scaling factor 2.5" are not fully specified, hindering exact replication.  
- Details of "shared/routed mixing normalized with RMSNorm" and integration of the always‑active shared chapter remain ambiguous.  
- The paper does not analyze potential router collapse or provide mitigation strategies; load‑balance tuning may be critical.

## Confidence
- **Explicit memory bank as complementary store:** Medium – iso‑FLOP loss gains are shown, but rely on underspecified routing.  
- **Chapter routing enables scaling to 262 K tokens:** Medium – scaling is demonstrated, yet router design (losses, scaling) is critical and not fully disclosed.  
- **Frozen memory mitigates catastrophic forgetting:** High – consistent IFT results and freezing ablations strongly support robustness.

## Next Checks
1. **Memory bank ablation:** Train without memory bank; expect higher pretraining loss and much larger forgetting on ARC‑Challenge/BoolQ.  
2. **Router \(k\) sweep:** Vary top‑\(k\) (e.g., 1,2,4,8,16,64) and plot validation loss and retention to identify knee‑point.  
3. **Freezing study:** Compare (a) freeze bank+router, (b) freeze bank only, (c) train all during IFT; expect (a) ≈ (b) and both not worse than (c).
