# EuroLLM-22B: Technical Report

## Quick Facts
*   **arXiv ID:** 2602.05879
*   **Source URL:** https://arxiv.org/abs/2602.05879
*   **Reference count:** 40
*   **Primary result:** A 22B-parameter model trained from scratch for 35 languages, achieving competitive multilingual performance through a three-phase curriculum on ~4T tokens and a model-judged post-training dataset.

## Executive Summary
EuroLLM-22B is a decoder-only transformer model designed to address the underrepresentation of European languages in open large language models. Trained from scratch, it natively supports all 24 official EU languages plus 11 additional languages. Its development centers on a carefully curated pre-training corpus (EuroWeb) and a three-phase curriculum that progressively exposes the model to higher-quality data. Post-training uses a large, high-quality multilingual instruction dataset (EuroBlocks-22B) with responses selected by a model-based judge. The model demonstrates strong performance on both English and multilingual benchmarks, with releases including the base and instruction-tuned models, training corpora, and code.

## Method Summary
The training process involves three distinct phases. Phase 1 uses a broad, lower-quality web corpus (~3.6T tokens) at a constant learning rate. Phase 2 introduces higher-quality filtered data (e.g., FineWeb-edu high-tier) while linearly annealing the learning rate over 400B tokens. Phase 3 uses the highest-quality curated documents (Wikipedia, ArXiv, Books), extends the context from 4K to 32K via RoPE scaling (θ from 1e4 to 1e6), and decays the learning rate to zero. The pre-training corpus, EuroWeb, combines filtered web data, parallel corpora, code/math, and synthetic data, all tiered by quality. For post-training, the model is fine-tuned for 5 epochs on EuroBlocks-22B (~10.6M examples), where responses from multiple strong open models are selected by Skywork-Gemma2-27B as a reward model.

## Key Results
*   On English benchmarks: MMLU 69.8, GSM8K 85.5, HumanEval 53.9.
*   On multilingual EU evaluations: MMMLU 65.6, ARC-C 84.1, MGSM 77.8, FLORES-200 88.9.
*   Shows consistent gains over earlier EuroLLM versions in instruction following, reasoning, and STEM tasks without sacrificing translation quality.

## Why This Works (Mechanism)

### Mechanism 1: Three-Phase Pre-training Curriculum
A progressive schedule that stabilizes learning and improves final performance. The model first acquires broad knowledge from large-scale, lower-quality data, then refines capabilities on high-quality, dense-signal data, and finally adapts to long contexts without catastrophic forgetting.
*   **Evidence anchors:** [abstract] "three-phase pre-training curriculum over ~4 trillion tokens." [section 2.2] Details the token counts and learning rate schedule per phase. [section 2.3] Describes how web data is divided into three quality tiers for each phase.

### Mechanism 2: Massive, Filtered Multilingual Corpus (EuroWeb)
Aggressive, language-aware filtering and strategic source mixing ensure sufficient token frequency and data quality for all 35 supported languages. This includes web data (RedPajama, HPLT, MADLAD, CulturaX, mC4), parallel corpora (Europarl, ParaCrawl), code/math (The Stack, OpenWebMath), and synthetic math data, all processed with pipelines like CCNet, Bifixer/Bicleaner, and EuroFilter.
*   **Evidence anchors:** [abstract] "pre-training corpus, EuroWeb, combines filtered multilingual web data..." [section 2.3] Lists specific sources and filtering steps. Neighboring corpora (EuroLLM-9B, Salamandra) indicate a community-scale effort.

### Mechanism 3: Model-Judged Post-training (EuroBlocks-22B)
Using a strong reward model (Skywork-Gemma2-27B) to select the best response from multiple model outputs across diverse sources creates a high-quality, multilingual instruction set. Removing structured reasoning traces avoids "cheating" on reasoning benchmarks while maintaining diverse format coverage.
*   **Evidence anchors:** [abstract] "post-training uses... EuroBlocks-22B with responses selected by model-based judges." [section 3.1] Details the data sources, regeneration, and judging process. [section 4.6] Shows gains in IFEval/MMLU/GSM8K with stable translation, indicating no trade-off.

## Architecture Onboarding
**Component map:** Tokenizer (128k BPE) -> Transformer Blocks (54 layers, 6144 dim, GQA: 48q/8kv, SwiGLU, RMSNorm) -> RoPE (base θ=1e6, 32K ctx) -> Training System (Megatron-LM fork with 3-phase scheduler) -> Data Pipeline (EuroWeb pre-training -> EuroBlocks-22B post-training)

**Critical path:** Tokenizer training -> Pre-train Phase 1 (broad web) -> Phase 2 (mixed quality) -> Phase 3 (high-quality + 32K ctx) -> SFT on EuroBlocks-22B -> Evaluation

**Design tradeoffs:**
*   Context length (32K) vs. compute: Fewer sequences/batch, potential stability issues during extension.
*   Multilingual coverage vs. per-language performance: Fixed 128k vocab may under-tokenize low-resource languages.
*   GQA efficiency vs. expressivity: 8 KV heads reduce memory but may limit long-range dependency modeling.

**Failure signatures:**
*   Perplexity spikes >10% at phase 2/3 boundaries.
*   Low-resource language performance poor despite overall good metrics.
*   Translation metrics stable but instruction following degrades post-SFT.

**First 3 experiments:**
1.  Compute average tokens/word for each language on held-out EuroWeb; flag >1.5 as under-tokenized.
2.  Log validation perplexity per language across pre-training phases; investigate spikes.
3.  Compare pre-SFT and post-SFT checkpoints on FLORES (translation) and IFEval (instruction); check for >5pt translation drop vs. >10pt instruction gain.

## Open Questions the Paper Calls Out
*   **OQ1:** Does EuroFilter's English-adapted quality classifier maintain consistent filtering accuracy across all 35 languages, especially low-resource EU ones?
*   **OQ2:** Does using a single non-European reward model (Skywork-Gemma2-27B) introduce biases that disadvantage certain European languages or discourse styles in EuroBlocks-22B?
*   **OQ3:** Is the chosen linear RoPE scaling (θ from 1e4 to 1e6) optimal for all languages at 32K context, or do some degrade more?
*   **OQ4:** Is ~4T tokens near an efficiency ceiling for 22B params covering 35 languages, or would a much larger budget (e.g., 15T) yield disproportionate gains?
*   **OQ5:** How does removing structured reasoning traces from EuroBlocks-22B impact complex multilingual STEM reasoning capabilities?

## Limitations
*   **EuroWeb construction details:** Exact source versions, filtering thresholds, and deduplication pipelines are not fully documented.
*   **Training infrastructure specifics:** Megatron-LM fork hyperparameters (parallelism, optimizer, checkpointing) and exact hardware allocation are omitted.
*   **Post-training data mixing:** Precise proportions of sources in EuroBlocks-22B and judge model behavior across languages are undisclosed.

## Confidence
*   Three-phase curriculum: **Medium** (supported by section 2.2, but no ablation).
*   EuroWeb multilingual sufficiency: **Medium-Low** (scale is large, but per-language filtering impact unvalidated).
*   EuroBlocks-22B judging pipeline: **Medium** (model-based selection promising, but cross-language bias unmeasured).
*   Overall multilingual performance numbers: **High** for raw results, **Medium** given dependency on proprietary judges.
