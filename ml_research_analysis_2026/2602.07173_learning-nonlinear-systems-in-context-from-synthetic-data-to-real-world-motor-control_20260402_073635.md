# Learning Nonlinear Systems In-Context: From Synthetic Data to Real-World Motor Control

## Quick Facts
- **arXiv ID**: 2602.07173  
- **Source URL**: https://arxiv.org/abs/2602.07173  
- **Reference count**: 0  
- **Primary result**: Two-stage pretrained transformer on 60k synthetic systems enables one-shot in-context feedforward control for real motors with only a few finetuning examples, significantly reducing RMSE compared to PI and physics-based baselines (e.g., 0.48 vs. 0.76 and 1.74 on ramp velocity).

## Executive Summary
Motor feedforward control under nonlinearities and varying loads typically demands careful tuning or accurate physical models. This paper introduces a transformer-based approach that leverages large-scale synthetic pretraining to achieve one-shot in-context learning from minimal real data. The method first learns a discrete signal representation via an Encodec-style encoder-decoder, then embeds system dynamics using contrastive learning over input–output pairs. After pretraining on 60k synthetic linear and nonlinear systems, the model is finetuned on just a few real motor examples. On real brushless DC and stepper motors, it outperforms classical PI and physics-based feedforward controllers in prediction accuracy. The results demonstrate that synthetic pretraining combined with contrastive system embeddings can effectively bridge the gap to real-world control with scarce data.

## Method Summary
The training pipeline has three stages. First, a signal representation model (Encodec-based encoder-decoder) is trained on the entire synthetic dataset to reconstruct both input and output signals, learning a discrete tokenization of continuous waveforms. Second, a system behavior model processes pairs of tokenized input–output sequences from the same system (plus a learnable system token) through self-attention with relative positional encoding, producing a system embedding *z*. A contrastive loss (Eq. 1) groups embeddings from the same system together, while a signal prediction head uses *z* to forecast the output tokens from a new input sequence (MSE loss, Eq. 2). Both losses are optimized jointly. Third, for a real motor, the signal encoder is frozen and all but one layer of the system model are frozen; the remaining layer is lightly finetuned (20 epochs) on 2–5 collected (target velocity, torque current) pairs. At inference, a single untuned example from a new motor/load acts as a prompt to predict the feedforward torque current for a novel velocity trajectory.

## Key Results
- Ramp target velocity on an unseen motor: RMSE 0.48 (proposed) vs. 0.76 (physics feedforward) vs. 1.74 (PI).
- Two-inertia system: RMSE 0.45 vs. 0.46 (physics) vs. 1.91 (PI).
- Ablations confirm that both pretraining stages and the inclusion of nonlinear synthetic data are essential for the observed performance.

## Why This Works (Mechanism)
The two-stage pretraining builds a robust representation of signal dynamics and a geometry where systems with similar behavior are embedded near each other. Contrastive learning forces the system embedding to capture dynamical characteristics from only a few examples. Pretraining on a diverse set of LTI and NTI systems yields features that generalize to real motors; finetuning updates only a single layer to align the synthetic representation with real dynamics while avoiding overfitting. Consequently, the model can perform in-context learning: an untuned motor example serves as a prompt that conditions the prediction for new trajectories, achieving accurate feedforward control with minimal real data.

## Foundational Learning
- **Transformer in‑context learning**: Enables conditioning on few examples without weight updates. Quick check: After pretraining, feed a prompt and query from the same synthetic system; the model should reconstruct the query output accurately.
- **Contrastive learning**: Clusters similar system embeddings. Quick check: On synthetic test set, compute cosine similarities: same‑system >0.9, different‑system ~0.
- **Discrete tokenization (Encodec)**: Converts continuous signals to transformer‑compatible tokens. Quick check: Reconstruct synthetic signals with MSE <1e‑3.
- **Synthetic‑to‑real transfer**: Leverages abundant simulated data. Quick check: After finetuning on 2–5 real pairs, one‑shot RMSE on a held‑out motor should beat PI.
- **Motor control fundamentals**: Relation between torque current (*i_q*) and velocity (*ω*). Quick check: Verify that data (target *ω*, measured *i_q*) are properly normalized and that baseline controllers are reasonably tuned.
- **Relative positional encoding**: Allows attention to generalize across positions. Quick check: Ablate relative encoding; performance should degrade on variable‑length sequences.

## Architecture Onboarding
Component map:  
Input signals → Signal Encoder (Encodec‑style, frozen after Stage 1) → Discrete tokens → System Behavior Model (system token + pair tokens → self‑attention w/ relative pos. enc. → system embedding *z*) → Signal Prediction Block (*z* + query input tokens → output tokens).  

Critical path: During pretraining, reconstruction loss (Stage 1) and combined contrastive + reconstruction loss (Stage 2) drive learning. Finetuning updates only one layer of the system behavior model on few real examples.  

Design tradeoffs:  
- Freezing the signal encoder preserves representation but limits adaptation to real signal characteristics.  
- Updating only one layer reduces overfitting but may be insufficient if synthetic data poorly matches real dynamics.  
- NTI generation (deadzone, saturation) is simple; more complex motor nonlinearities (friction, backlash) might remain unaddressed.  

Failure signatures:  
- After Stage 2, t‑SNE of *z* shows no clear per‑system clusters.  
- Finetuning loss on real pairs plateaus at a high value.  
- One‑shot RMSE on real motors remains comparable to or worse than PI.  

First experiments:  
1. Train the signal encoder alone; confirm low reconstruction error on synthetic validation set.  
2. After Stage 2, compute pairwise cosine similarities for system embeddings on the synthetic test set; expect high within‑system and near‑zero between‑system scores.  
3. Finetune on 2 real pairs and evaluate one‑shot prediction on a new motor/load; verify RMSE surpasses baselines.

## Limitations
- Key hyperparameters (learning rates, batch sizes, contrastive temperature, model dimensions) are not reported, hindering exact replication.  
- Synthetic nonlinearities (deadzone, saturation) may not fully capture real motor effects like Coulomb friction or backlash, limiting transferability.  
- Real‑world evaluation details (e.g., exact data collection for “untuned” vs. “well‑tuned” pairs, test waveform parameters, definition of “unseen” splits) are underspecified.

## Confidence
- Two‑stage pretraining efficacy: **Medium** (ablations support its role, but performance may be sensitive to unreported hyperparameters).  
- Generalization from synthetic to real with minimal data: **Medium** (results on two motor platforms are promising but scope is limited and test conditions unclear).  
- One‑shot in‑context learning capability: **Medium** (demonstrated, but definition of “one‑shot” and prompt construction could affect reproducibility).  
- Superiority over PI and physics‑based baselines: **Medium** (large reported improvements, but insufficient baseline details raise fairness concerns).
