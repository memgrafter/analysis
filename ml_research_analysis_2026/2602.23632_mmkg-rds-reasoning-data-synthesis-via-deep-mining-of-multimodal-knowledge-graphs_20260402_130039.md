# MMKG-RDS: Reasoning Data Synthesis via Deep Mining of Multimodal Knowledge Graphs
## Quick Facts
*   arXiv ID: 2602.23632
*   Source URL: https://arxiv.org/abs/2602.23632
*   Reference count: 40
*   Primary result: Constructed MMKG-RDS-Bench (14,950 samples, 5 domains, 17 tasks) and demonstrated a 9.2% reasoning accuracy gain for Qwen3 models fine-tuned on small synthetic subsets.

## Executive Summary
MMKG-RDS addresses critical flaws in existing reasoning data synthesis—limited long-tail knowledge coverage, poor verification, and low interpretability—by introducing an end-to-end framework that builds and mines multimodal knowledge graphs (MMKGs). It features fine-grained extraction from tables/formulas/images, customizable schema and path sampling, and multidimensional quality scoring. The resulting MMKG-RDS-Bench benchmark and synthesized data significantly improve model reasoning performance and help expose weaknesses in multimodal tasks like table and formula reasoning.

## Method Summary
The framework implements a five-layer pipeline: (1) **Preprocessing** parses heterogeneous documents (PDF, images, spreadsheets) into structured chunks and multimodal elements; (2) **KG Builder** constructs a heterogeneous graph with seven node types (e.g., TextChunk, Table, Formula) and sixteen relation types, mining entities from non-textual nodes; (3) **Storage** interfaces with graph databases like Neo4j; (4) **Synthesis** samples subgraphs via ACS/DFS, generates reasoning traces, and produces QA pairs using templates with entity blurring/pronoun substitution; (5) **Analysis** applies semantic deduplication and three-dimensional quality scoring (support, difficulty, complexity) before export.

## Key Results
*   Created MMKG-RDS-Bench with 14,950 samples covering 5 domains and 17 distinct reasoning task types.
*   Fine-tuning Qwen3 models (0.6B/8B/32B) on small, difficulty-filtered synthetic subsets improved reasoning accuracy by 9.2%.
*   Framework generates distinct, challenging data for table and formula tasks, successfully highlighting model weaknesses and enabling creation of complex, targeted benchmarks.

## Why This Works (Mechanism)
### Mechanism 1: Multimodal Node Integration
*   **Claim:** Incorporating explicit nodes for tables, formulas, and images increases long-tail knowledge coverage and granularity versus text-only graphs.
*   **Mechanism:** Extracts fine-grained content from non-textual elements and links them to text chunks via explicit relations, enriching semantic density and enabling cross-modal reasoning paths.
*   **Core assumption:** Valuable long-tail knowledge resides in structured/visual formats often missed by pure text extraction.
*   **Evidence anchors:** [abstract] seven node types capturing document logic; [section 4.2] stage-2/3 mining from non-textual nodes; [Table 2,9] distinguishing multimodal node support.
*   **Break condition:** Parsing/VLM errors in multimodal nodes introduce noise, reducing coverage gains and possibly generating invalid paths.

### Mechanism 2: Customizable Path Sampling
*   **Claim:** User-defined schemas and diverse sampling strategies generate task-specific, complex data with better distribution control than fixed approaches.
*   **Mechanism:** Allows schema configuration and selection from 32+ task types. Uses ACS for subgraph sampling and DFS with constraints for path generation. QA generation applies entity blurring and pronoun substitution to increase difficulty.
*   **Core assumption:** Effective reasoning data requires deliberate control over graph topology and linguistic obfuscation; one-size-fits-all sampling yields poor data.
*   **Evidence anchors:** [abstract] configurable schemas, 32+ task types; [section 4.3] details on ACS, DFS, and QA tactics; [Table 1] comparison showing superior type/task support.
*   **Break condition:** Poorly aligned schemas or overly restrictive/loose sampling constraints yield data lacking meaningful complexity or coverage.

### Mechanism 3: Multidimensional Quality Scoring
*   **Claim:** Evaluating data along support, difficulty, and complexity dimensions provides more effective verification and interpretability than single-metric filtering.
*   **Mechanism:** Filters data via (1) semantic deduplication; (2) "support" check using majority-voting models to ensure path-answer alignment; (3) "difficulty" from strong/weak model performance gaps; (4) "complexity" from structural/linguistic factors.
*   **Core assumption:** A single metric cannot capture multifaceted training data needs; interpretable scores allow fine-tuning distribution.
*   **Evidence anchors:** [abstract] metrics covering complexity, fidelity, difficulty; [section 4.4] definitions of each dimension; [section 5.4] fine-tuning gains validate difficulty utility.
*   **Break condition:** Model hallucination in support voting or reliance on a single model pair for difficulty can mislabel data quality.

## Foundational Learning
*   **Concept: Multimodal Knowledge Graph Construction**
    *   Why needed: Core innovation is building a KG with first-class nodes for tables/formulas/images, not just text. Engineers must understand extraction, normalization, and interlinking across modalities.
    *   Quick check: How does the framework link a formula node to text chunks describing its reaction, and why is this link critical for formula-centric QA?
*   **Concept: Graph-Based Data Synthesis Pipelines**
    *   Why needed: MMKG-RDS is a cascade (parsing → KG → sampling → QA). Engineers must grasp how subgraph sampling and path generation determine reasoning structure.
    *   Quick check: For a task comparing table values then applying a formula, which node/relation types are needed in the path, and how does QA generation ensure the question tests that comparison?
*   **Concept: Interpretable Quality Metrics for Synthetic Data**
    *   Why needed: The framework's value includes interpretable filtering. Engineers must implement and tune support/difficulty/complexity scoring and understand trade-offs (e.g., computational cost of model voting).
    *   Quick check: What are the three quality dimensions, and how would high-support/low-difficulty data be useful for training a reasoning model?

## Architecture Onboarding
*   **Component map:** Preprocessing (parsers) -> KG Builder (extraction/disambiguation) -> Storage (Neo4j) -> Synthesis (sampling/trace/QA) -> Analysis (scoring/export)
*   **Critical path:** Raw documents (PDF/JSON) -> Document Parsing (MinerU) -> Structured chunks/multimodal elements -> KG Builder (entity/relation extraction, multimodal mining) -> Knowledge Graph (Neo4j) -> Subgraph Sampling (ACS) -> Path Generation (DFS) -> QA Generation (templates + blurring) -> Deduplication & Quality Filtering -> Final dataset (JSON/ShareGPT)
*   **Design tradeoffs:**
    *   Schema rigidity vs. automation: Manual schema ensures accuracy but limits domain adaptability; auto-schema induction could increase coverage but risk noise.
    *   Parsing completeness vs. speed: MinerU handles most documents but fails on cross-page tables/paragraph splits; custom heuristics add complexity.
    *   Quality score fidelity vs. cost: Support metric uses three model votes; difficulty relies on two model sizes, which may not generalize.
    *   Multimodal extraction depth vs. hallucination: Mining from images/tables enriches graph but introduces VLM hallucination risks.
*   **Failure signatures:**
    *   Sparse edges (e.g., chunk→formula) indicate poor multimodal linking, reducing diversity in table/formula tasks.
    *   Low accuracy on table/image tasks suggests flawed synthetic data or model weakness; verify with case studies.
    *   Over-filtering by support (many samples removed) reduces dataset size/diversity; monitor support pass rate.
    *   Parsing errors (e.g., split tables) create incomplete nodes, breaking reasoning paths.
*   **First 3 experiments:**
    1.  **Cross-model task performance:** Run Qwen3 series on 10 task types to validate scaling law and identify weak tasks (tables/formulas).
    2.  **VLM input modality ablation:** Test Qwen3-VL on text-only, image-only, and image+text inputs for image tasks to check modality gaps.
    3.  **Fine-tuning with difficulty-filtered data:** Sample 1k "hard" vs. "simple+medium" data, fine-tune Qwen3 models, and compare accuracy gains.

## Open Questions the Paper Calls Out
*   **Dynamic schema construction:** How can the framework automate ontology generation to eliminate manual schema design? The authors note manual schemas limit applicability; future work plans dynamic schema induction.
*   **Improved document parsing:** What specific parsing improvements are needed for paragraph segmentation across images, cross-page tables, and multi-sub-graph image captions? Current tools (MinerU) still split logical units incorrectly.
*   **Mitigating VLM hallucination:** How can hallucination in image-derived entity extraction be mitigated without over-filtering valid but unverifiable entities? Cross-document verification discards some useful entities, while accepting hallucinations corrupts the graph.
*   **Computational optimization:** What architectural/algorithmic optimizations can reduce overhead from large model latency and long documents? The graph construction process is currently slow, hindering scalability.

## Limitations
*   Requires manual schema construction per domain, limiting generalizability and scalability.
*   Document parsing (MinerU) may fragment complex layouts (e.g., cross-page tables, paragraphs interrupted by images).
*   VLM-based extraction of tables/formulas/images can introduce hallucinations, compromising graph fidelity.
*   Quality metrics (support, difficulty) are model-dependent; robustness across different LLM families is untested.
*   High resource demands (8×A800, ~8 hours) hinder wide reproducibility and scaling.
*   Benchmark is constructed mainly from scientific documents; generalization to other domains (e.g., legal) is unknown.

## Confidence
*   **Multimodal KG improves long-tail coverage**: Medium (validated by node statistics but dependent on parsing/VLM accuracy).
*   **Customizable sampling yields diverse tasks**: Medium (algorithms detailed, but schema-design expertise may limit practical diversity).
*   **Multidimensional scoring ensures quality**: Medium (supported by fine-tuning gains, yet model-dependent).
*   **Synthetic data boosts reasoning accuracy**: Medium (9.2% improvement shown for Qwen3 on 5 domains, but limited to small subsets and specific scales).
