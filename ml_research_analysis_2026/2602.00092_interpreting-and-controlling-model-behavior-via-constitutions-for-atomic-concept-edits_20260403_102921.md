# Interpreting and Controlling Model Behavior via Constitutions for Atomic Concept Edits
## Quick Facts
- arXiv ID: 2602.00092
- Source URL: https://arxiv.org/abs/2602.00092
- Reference count: 40
- Primary result: Atomic Concept Edits (ACEs) with constitution optimization achieve 1.86× average improvement in success rate over non-constitution baselines across three tasks.

## Executive Summary
The paper tackles the challenge of black-box interpretability for generative models by proposing a systematic method to interpret and control model behavior through prompt edits. The core idea is Atomic Concept Edits (ACEs), which treat prompts as compositions of atomic concepts that can be added, removed, or replaced. An autorater evaluates model outputs to quantify the impact of each edit. A constitution—a set of natural-language rules—is iteratively evolved to steer edits toward desired task outcomes while preserving output diversity.

Experiments on three tasks (word count, math problem difficulty, text-to-image alignment) demonstrate that the ACE + constitution approach yields a 1.86× average improvement in success rate compared to baselines without constitutions. The method also uncovers model-specific behavioral patterns, such as GPT-Image's sensitivity to relational element removal and GPT-5's distraction by irrelevant variables. Moreover, learned constitutions generalize across models and maintain diverse outputs, suggesting a promising direction for controllable text and image generation.

- Learned constitutions preserve output diversity and generalize across different model architectures.

The process resembles reinforcement learning with a natural-language policy, where the constitution serves as an interpretable guide for action selection.

## Foundational Learning
This work contributes to the field of black-box interpretability, a foundational challenge in understanding and controlling deep generative models. The method introduces a concept-based intervention approach where prompts are decomposed into atomic concepts that can be manipulated. The constitution optimization loop can be viewed as a form of automated rule induction or program synthesis, where natural-language rules are evolved based on performance feedback. These ideas connect to broader themes in interpretability, such as feature attribution (though here features are textual concepts) and reinforcement learning from human or artificial feedback. The approach demonstrates that interpretable, human-readable rules can be learned to control model behavior without direct access to model weights, offering a scalable direction for practical interpretability.

## Architecture Onboarding
The method architecture comprises two main components: (1) the Atomic Concept Editor and (2) the Constitution Optimizer. The Atomic Concept Editor generates edits by applying operations (add, remove, replace) to atomic concepts extracted from the initial prompt. The Constitution Optimizer maintains a population of natural-language rules (the constitution) and iteratively updates them using autorater scores. The critical path is: (a) generate a batch of ACEs, (b) query the model with each edited prompt, (c) score outputs with the autorater, (d) select high-scoring edits and their associated edit patterns, (e) refine the constitution to encode patterns associated with success (e.g., via evolutionary algorithms or rule induction), and (f) use the updated constitution to guide future ACE generation, biasing toward patterns consistent with the constitution. Design tradeoffs include balancing exploration (trying novel edits) vs. exploitation (focusing on known successful patterns), and preserving output diversity while optimizing for task-specific success. Potential failure signatures: constitutions may become overly restrictive, eliminating diversity; or they may overfit to idiosyncrasies of a specific model, reducing generalization. First experiments typically start with a small seed set of atomic concepts and a simple initial constitution (e.g., heuristic rules like "avoid removing relational elements"), then run multiple iterations of the loop while monitoring diversity metrics.
