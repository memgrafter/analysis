# FUSE: Failure-aware Usage of Subagent Evidence for MultiModal Search and Recommendation

## Quick Facts
- **arXiv ID:** 2601.02365
- **Source URL:** https://arxiv.org/abs/2601.02365
- **Reference count:** 18
- **Primary result:** Context Compression achieves 93.3% intent accuracy, 86.8% routing success (with fallbacks), 99.4% recall, and 88.5% NDCG@5, with 45% lower p95 latency and 8× fewer input tokens than chain-of-thought.

## Executive Summary
Creative assistants often rely on multimodal search over large asset repositories, but raw-image prompting leads to high latency and cost. FUSE introduces a Grounded Design Representation (GDR), a compact JSON serialization of canvas state, to replace pixel-based inputs. Seven context budgeting strategies are evaluated for feeding this representation to search subagents. The optimal strategy, Context Compression, condenses the planner’s enriched prompt and GDR into a semantically dense input that preserves key constraints while drastically reducing token count. On a dataset of 788 real-world queries, Context Compression achieves 93.3% intent accuracy, 86.8% routing success (with fallbacks), 99.4% recall, and 88.5% NDCG@5. It reduces p95 latency by 45% and uses 8× fewer tokens than chain-of-thought, demonstrating that strategic context summarization outperforms both over-detailed and minimal prompting in production.

## Method Summary
FUSE replaces raw image prompts with a structured Grounded Design Representation (GDR). The GDR is a typed JSON that captures canvas elements—including geometry, styles, colors, and LLaVA-generated captions—along with user selections. A Planner first enriches the user query with canvas hints, then a GDR Generator produces this compact representation. The enriched prompt and GDR are fed into a search subagent after applying one of seven context budgeting strategies (e.g., Baseline, Zero-Shot, Context Compression). The subagent implements a five-stage pipeline: pre-processing (schema validation), intent understanding (expanding query with constraints), content-type routing, recall (asset retrieval), and ranking (scoring by relevance).

To diagnose failures and select fallback policies, FUSE introduces a Pipeline Attribution Layer. After each stage, simple checks compute metrics—semantic similarity for intent alignment, exact match for routing sanity, zero-hit rate for recall health, and NDCG for ranking stability. These metrics attribute failures to a specific stage, enabling targeted offline tuning or real-time fallback activation. The Context Compression strategy, which distills the Planner’s prompt and GDR into a concise yet information-rich input, emerges as optimal across all metrics while minimizing latency and token cost.

## Key Results
- **Context Compression** attains 93.3% intent accuracy, 86.8% routing success, 99.4% recall, and 88.5% NDCG@5.
- Reduces p95 latency by 45% and input tokens by 8× compared to chain-of-thought.
- Outperforms both comprehensive (Baseline) and minimal (Zero-Shot) contextualization strategies in production pipelines.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Replacing raw-image prompting with a compact, structured Grounded Design Representation (GDR) reduces multimodal processing cost and latency while preserving essential contextual constraints for retrieval.
- **Mechanism:** The system serializes canvas state (elements, layout, styles, colors, selections) into a typed JSON instead of transmitting and processing raw pixel data. This structured schema is injected into the search subagent’s prompt, providing semantic and geometric constraints (e.g., "find cars with contrast against green") without vision-language model overhead.
- **Core assumption:** The design metadata captured in GDR (geometry, LLaVA captions, color roles) is sufficient to ground user intent and feasibility constraints for retrieval, avoiding the need for expensive image patch encoding.
- **Evidence anchors:**
  - [abstract] "FUSE replaces most raw-image prompting with a compact Grounded Design Representation (GDR): a selection-aware JSON of canvas elements..."
  - [Section III.A] "We instead moved to a more compact, typed contextual schema (intent + canvas constraints) that drives retrieval/ranking with explicit contrast and feasibility checks."
  - [corpus] Weak direct evidence; neighboring papers focus on sequential search/recommendation or intent embedding, not on structured design representation for cost reduction.
- **Break condition:** If the GDR fails to capture critical visual semantics required for a query (e.g., nuanced texture, brand-specific patterns), retrieval quality may degrade despite lower cost.

### Mechanism 2
- **Claim:** Strategic context summarization (Context Compression) optimally balances information density and computational efficiency, outperforming both over-detailed (Baseline) and under-detailed (Zero-Shot) prompting strategies.
- **Mechanism:** The variant compresses the planner-provided GDR and enriched prompt into a concise, semantically-rich input for the intent/routing model. This reduces token count (8× fewer than Chain-of-Thought) and latency (45% lower p95 vs. Baseline) while preserving key constraints that drive high intent match (93.3%) and routing success (86.8%).
- **Core assumption:** There exists an optimal point of context condensation where non-essential details are pruned without losing critical disambiguating information; this point is discoverable via systematic evaluation.
- **Evidence anchors:**
  - [abstract] "Context Compression achieves optimal performance across all pipeline stages... with 45% lower p95 latency and 8x fewer input tokens than chain-of-thought."
  - [Section IV.F] "Context Compression emerges as the superior strategy... achieving 93.3% intent accuracy, 86.8% routing success, 99.4% recall, and 88.5% NDCG@5."
  - [corpus] Neighbors like "Session Context Embedding for Intent Understanding" explore context representation but do not evaluate compression strategies under strict cost budgets.
- **Break condition:** For highly ambiguous or complex queries that rely on multiple few-shot examples (e.g., rare asset classes), compression may remove necessary exemplars, causing intent or routing failures.

### Mechanism 3
- **Claim:** A stage-wise pipeline attribution layer that converts subagent signals into simple operational checks (intent alignment, routing sanity, recall health, ranking stability) enables failure diagnosis and targeted policy adjustments in production.
- **Mechanism:** After each pipeline stage, metrics (e.g., semantic similarity for intent, exact match for routing, zero-hit rate for recall, NDCG for ranking) are computed against expected outputs. These are aggregated to attribute failures to specific stages, informing real-time fallback activation or offline tuning (e.g., adjusting content-type confidence thresholds).
- **Core assumption:** Failures in multi-agent retrieval are separable by stage; attributing them to intent, routing, recall, or ranking allows for precise interventions rather than monolithic component retraining.
- **Evidence anchors:**
  - [Section III.D] "To evaluate pipeline performance, we developed Pipeline Attribution Framework that classifies failures into four distinct attribution categories..."
  - [Section IV] Results show variances across strategies (e.g., routing varied 12 points, recall 6.3 points), indicating stage-specific sensitivity to context budgeting.
  - [corpus] Neighbors discuss error analysis broadly (e.g., "Failure risk analysis of pipelines") but not the proposed stage-wise check framework for agentic systems.
- **Break condition:** If failures are interdependent (e.g., poor ranking due to upstream intent error), attribution may misassign blame, leading to ineffective fixes.

## Architecture Onboarding

**Component map:** Planner (infers intent from raw query + canvas hint) → GDR Generator (outputs structured JSON) → Search Subagent (with Entity Search Handlers per asset type) → Attribution Layer (computes stage metrics) → Fallback Router.

**Critical path:** Raw user query → Planner-enriched prompt + GDR → Context Budgeting variant (e.g., Compression) → Intent/Routing model → Recall handler → Ranker → Attribution checks → Top-K results.

**Design tradeoffs:**
- *Token cost vs. quality:* More context improves recall/ranking but increases latency and API cost.
- *Context richness vs. noise:* Few-shot examples help ambiguity but may introduce irrelevant cues for sparse asset classes.
- *Real-time vs. offline:* Attribution enables live fallback decisions but adds computation; offline tuning requires historical failure logs.

**Failure signatures:**
- *Routing failure:* Incorrect content-type prediction (e.g., "fireworks" routed to video not photo) detected by exact-content-type mismatch.
- *Recall failure:* Zero-hit queries detected by empty result set.
- *Ranking failure:* High-similarity asset ranked low (NDCG@5 drop).
- *Intent failure:* Subprompt semantic mismatch with expected query expansion (e.g., "beans" → "black beans" not "coffee beans").

**First 3 experiments:**
1. **A/B test context strategies:** Deploy Baseline vs. Context Compression vs. Zero-Shot on shadow traffic; compare intent accuracy, routing success, and p95 latency using the Attribution Framework’s stage metrics.
2. **Fallback activation study:** For Zero-Shot and Retrieval-Augmented (low routing success), measure improvement when fallback routing is enabled; quantify gain per strategy (expected: +5-8% routing success).
3. **Attribution validation:** Manually re-annotate 100 failure cases to verify the Attribution Layer’s stage assignments; adjust thresholds (e.g., intent similarity cutoff) if misattribution rate >15%.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Does the Grounded Design Representation (GDR) omit critical visual or contextual details necessary for accurate multimodal retrieval in complex or niche creative workflows?
- **Basis:** [inferred] The paper proposes GDR as a compact alternative to raw-image prompting but does not evaluate its coverage against raw-image baselines or test for semantic loss in scenarios with intricate layouts, artistic styles, or ambiguous object relationships.
- **Why unresolved:** The evaluation uses query-level metrics without measuring design fidelity, conducting GDR component ablations, or comparing against raw-image prompts in controlled settings; potential information loss remains unknown.
- **What evidence:** Comparative A/B tests with raw-image prompts across diverse design domains (e.g., abstract art, detailed collages), user studies assessing result appropriateness, or automatic metrics for visual-semantic alignment and layout preservation.

### Open Question 2
- **Question:** What specific aspects of context compression or baseline prompts drive their superior routing performance, and can these insights be generalized to improve content-type prediction for underrepresented asset classes?
- **Basis:** [inferred] Routing success varies by up to 12 percentage points (Table I), with context-lean strategies like Zero-Shot (72.7%) lagging far behind Compression (84.1%). The paper attributes this to "stable contextual guidance" but does not isolate which GDR fields or prompt structures are most influential.
- **Why unresolved:** The attribution framework identifies routing failures but does not perform granular error analysis to pinpoint whether factors like color palettes, LLaVA captions, layout metadata, or few-shot examples are key; this limits actionable optimization for sparse asset categories.
- **What evidence:** Ablation studies systematically removing GDR attributes, probing the intent model's attention weights or feature importance, and controlled experiments varying prompt content while measuring routing accuracy across diverse content types (e.g., icons, shapes, video).

### Open Question 3
- **Question:** Can the pipeline attribution framework be automated for real-time failure detection and dynamic policy selection without violating latency budgets, and what is the optimal balance between attribution granularity and system throughput?
- **Basis:** [inferred] The framework uses "simple checks" (intent alignment, routing sanity, etc.) for offline tuning and policy selection but is not described as operating in real-time; the paper notes policy choices are "on demand" but does not explore automated, continuous attribution.
- **Why unresolved:** Real-time adaptation could enhance robustness but may add overhead; the trade-off between attribution accuracy (e.g., finer failure modes) and added latency is unmeasured, leaving a gap for production deployment at scale.
- **What evidence:** Implementing an automated attribution module (e.g., lightweight classifiers or LLM-as-judge) and evaluating its impact on end-to-end latency, policy switch effectiveness, and overall success rates in live A/B tests compared to the current heuristic-based approach.

## Limitations
- GDR’s structured representation may fail to capture nuanced visual semantics (e.g., textures, brand patterns), risking retrieval quality for some queries.
- The exact algorithm and prompt used for Context Compression are undisclosed, hindering reproduction and optimization.
- Attribution layer thresholds (e.g., intent similarity cutoffs) and fallback logic are unspecified; interdependent failures could lead to misattribution and ineffective policy adjustments.
