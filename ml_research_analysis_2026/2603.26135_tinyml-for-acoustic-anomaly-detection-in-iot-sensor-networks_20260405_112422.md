# TinyML for Acoustic Anomaly Detection in IoT Sensor Networks

## Quick Facts
- **arXiv ID:** 2603.26135  
- **Source URL:** https://arxiv.org/abs/2603.26135  
- **Reference Count:** 15  
- **Primary Result:** A quantized int8 TinyML model achieves 91% test accuracy and balanced F1-scores of 0.91 for normal and anomalous sound classes, with a memory footprint of ~60 kB, enabling feasible on-device acoustic anomaly detection.

## Executive Summary
This paper tackles real-time, energy-efficient acoustic anomaly detection in IoT sensor networks by moving processing from the cloud to the edge. It proposes a TinyML pipeline that extracts Mel Frequency Cepstral Coefficients (MFCCs) from audio and trains a compact fully connected neural network for binary classification (normal vs. anomalous sounds) using the UrbanSound8K dataset. After 8-bit post-training quantization via TensorFlow Lite, the model attains 91% test accuracy and a balanced F1-score of 0.91 while consuming only ~60 kB of memory. The work demonstrates that lightweight on-device machine learning can deliver reliable, low-latency anomaly detection for scalable IoT applications, though hardware validation and real-world robustness remain open.

## Method Summary
The method uses the UrbanSound8K dataset, grouping its 10 classes into normal (e.g., engine idling, air conditioner, children playing) and anomalous (e.g., siren, gunshot, jackhammer, dog bark) sounds, with the assignment of the remaining classes unspecified. Audio is resampled to 16 kHz and padded/trimmed to a fixed length yielding a 13×32 MFCC matrix per clip, which is flattened to a 416‑dimensional vector. A two‑layer fully connected network (128 and 64 ReLU units, 0.2 dropout) with a sigmoid output is trained using Adam (learning rate 0.001), binary cross‑entropy, early stopping (patience 5), and ReduceLROnPlateau. The best floating‑point model is quantized to int8 using TensorFlow Lite with a representative dataset, shrinking the model to ~60 kB. Evaluation uses accuracy, F1‑score, ROC AUC, and average precision on a held‑out test set.

## Key Results
- Quantized int8 model test accuracy: **91%**
- Balanced class F1‑scores: **0.91** for both normal and anomalous
- Model footprint after quantization: **~60 kB**
- Minimal accuracy drop from float32: 4 % (95 %→91 %)

## Why This Works (Mechanism)
### Mechanism 1: MFCC Feature Compression
MFCCs reduce raw audio into a compact, perceptually relevant representation by framing the signal (40 ms, 50% overlap), applying Mel filterbanks, and performing a discrete cosine transform to yield 13 coefficients per frame. This preserves critical spectral patterns for discriminating anomalous urban sounds (e.g., sirens, gunshots) from normal ambience while keeping the input size manageable for microcontrollers. *Break condition:* If anomalies are highly transient or high‑frequency events poorly captured by MFCC spectral envelopes, or if microphone noise distorts the filterbank response.

### Mechanism 2: Post‑Training Quantization
The model’s floating‑point weights are scaled and converted to 8‑bit integers, enabling efficient integer arithmetic on microcontrollers. TensorFlow Lite quantization reduces the model size by ~4× (from float32 to int8) with only a small accuracy loss (4 %) and maintains discriminative power. *Break condition:* If the model is sensitive to low‑precision weights (e.g., sharp decision boundaries) or the MCU lacks hardware int8 support, causing software emulation overhead.

### Mechanism 3: Shallow Fully Connected Architecture
A two‑layer dense network with dropout regularization generalizes well to the MFCC feature space. The binary sigmoid output simplifies decision‑making for anomaly alerts. The design assumes that normal/anomalous sounds are approximately separable in the MFCC space without temporal modeling. *Break condition:* If anomalies require long‑range temporal context (e.g., evolving sounds) or if the binary grouping oversimplifies nuanced acoustic classes.

## Architecture Onboarding
- **Component map:**  
  Audio Input (16 kHz mono PCM) -> MFCC Extractor (40 ms frames, 50% overlap, 13 coefficients) -> Flattening (416‑D vector) -> Classifier (Dense128→Dropout→Dense64→Dropout→Sigmoid) -> Quantizer (TensorFlow Lite int8) -> Deployment Wrapper (TFLM C++ library)

- **Critical path:**  
  Audio capture -> MFCC extraction -> quantized model inference -> thresholding (default 0.5) -> anomaly alert if probability > threshold.

- **Design tradeoffs:**  
  Accuracy vs. footprint: Smaller hidden layers reduce memory but risk underfitting.  
  Binary vs. multi‑class: Binary simplifies but cannot differentiate anomaly types.  
  MFCC vs. spectrogram: MFCCs are compact but may lose phase information; spectrograms preserve more but increase input size.

- **Failure signatures:**  
  Memory overflow: Model or MFCC buffer exceeds MCU SRAM (>64 kB on Cortex‑M4).  
  High latency: Inference >100 ms per clip, breaching real‑time requirements.  
  Degraded robustness: Accuracy drops >10% on noisy real‑world data vs. UrbanSound8K.

- **First 3 experiments:**  
  1. Reproduce MFCC pipeline: Process a known UrbanSound8K sample (e.g., siren.wav) and visualize the 13×32 MFCC heatmap.  
  2. Sanity‑check training: Train for 5 epochs on 10% of data; expect loss decrease >0.1 per epoch and accuracy >70%.  
  3. Quantization validation: Convert float model to int8 using TFLite; verify ~4× size reduction and <5% accuracy drop on hold‑out set.

## Open Questions the Paper Calls Out

2. Can pruning and knowledge distillation further reduce computational overhead while maintaining 91% accuracy?  
3. How robust is the pipeline in real‑world IoT networks with diverse acoustics, sensor noise, and unseen sounds?  
4. Can the system be extended to multi‑class anomaly detection and continuous streaming within MCU constraints?  
5. What modifications (e.g., alternative features, tiny CNNs) most effectively reduce misclassifications from spectral overlap (e.g., street music vs. sirens)?

## Limitations
- **Label mapping ambiguity:** Unclear which UrbanSound8K classes belong to each binary group, affecting dataset composition and metrics.  
- **Hyperparameter conflicts:** Contradictory batch size (32 vs 64) and omitted training details hinder perfect replication.  
- **Generalization gap:** Evaluation limited to clean UrbanSound8K; no real‑world noise, hardware tests, or fine‑grained anomaly typing.

## Confidence
- **MFCC efficacy:** Medium – established feature but no ablation against alternatives or robustness tests.  
- **Quantization benefit:** High – demonstrated 4% accuracy drop with 4× size reduction, consistent with TinyML practice.  
- **FC network adequacy:** Medium – achieved balanced F1=0.91 on dataset, but no comparison to temporal models or out‑of‑distribution testing.  
- **Overall feasibility:** Medium – dataset results promising, but missing hardware validation and real‑world noise evaluation.
