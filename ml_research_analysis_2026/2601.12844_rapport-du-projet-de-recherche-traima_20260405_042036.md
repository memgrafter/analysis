# Rapport du Projet de Recherche TRAIMA

## Quick Facts
- **arXiv ID:** 2601.12844
- **Source URL:** https://arxiv.org/abs/2601.12844
- **Reference count:** 0
- **Primary result:** Established a methodological foundation for automating multimodal classroom interaction analysis, highlighting transcription standardization and a tripartite model of explanatory sequences.

## Executive Summary
The TRAIMA project investigated machine learning techniques to automate the analysis of multimodal classroom interactions, focusing on explanatory sequences in French language teaching. It defined explanatory discourse as a tripartite structure (opening, core, closure) to serve as a classification target. Through a detailed review of transcription conventions and manual annotation of the INTER-EXPLIC corpus, the project produced a rigorous methodological framework that emphasizes the need for standardized, theory‑explicit transcriptions and researcher reflexivity. Data collection was halted by the March 2020 lockdown, and no operational system was delivered, but the work lays essential groundwork for future AI‑assisted analysis in educational multimodality.

## Method Summary
The methodology combined a state‑of‑the‑art survey of multimodal transcription conventions (ICOR, Mondada, GARS, VALIBEL, Ferré) with manual annotation of the INTER-EXPLIC corpus (~30 hours) captured via the TechnéLAB platform. Researchers identified explanatory sequences using interactional linguistic principles, comparing two independent transcriptions to expose variability in gesture coding and temporal alignment. Existing digital tools (ELAN, ANVIL) and ASR systems (VOCAPIA) were evaluated for integration potential. The project did not implement a machine learning pipeline; instead, it proposed a future hybrid human‑computer system where automatic suggestions are validated by experts.

## Key Results
- Manual transcription is inherently variable and theory‑laden; divergent conventions (e.g., ICOR vs. Mondada) produce non‑reproducible data representations, creating a bottleneck for scalable automation.
- The INTER-EXPLIC corpus and the tripartite definition of explanatory discourse (opening, core, closure) provide a reference dataset and a bounded target for automatic segmentation and classification.
- High‑fidelity synchronized capture (TechnéLAB) is essential for discovering the multimodal features (verbal, prosodic, gestural) relevant to explanatory sequences; future AI tools must embed researcher reflexivity and explicit theoretical foundations.

## Why This Works (Mechanism)

### Mechanism 1: Transcription variability as a barrier to automation
- **Claim:** Variability in manual multimodal transcription blocks scalable automation.
- **Mechanism:** Theoretical positioning and analytical goals lead to divergent transcription choices (e.g., descriptive vs. interpretative, gesture granularity), producing non‑reproducible data unsuitable for training consistent ML models.
- **Core assumption:** Automation requires standardized, inter‑subjectively stable data representations.
- **Evidence:** Side‑by‑side comparison of two manual transcripts of the same sequence revealed structural differences (e.g., gesture labels "pointe" vs. "+déictique+"); survey of conventions showed divergent encoding logics.
- **Break condition:** A shared, theoretically explicit transcription protocol validated across annotators could reduce variability.

### Mechanism 2: Tripartite sequence as a grounded ML target
- **Claim:** Defining explanatory discourse as a tripartite sequence (opening, core, closure) provides a theoretically bounded unit for machine classification.
- **Mechanism:** Anchoring analysis in interactional linguistics transforms vague "explanatory" labels into a sequentially organized phenomenon with identifiable moves, creating a target pattern for ML detection.
- **Core assumption:** ML can segment and classify phenomena if they are defined by recurrent, observable structural and functional properties.
- **Evidence:** The INTER‑EXPLIC corpus contains >100 manually identified explanatory episodes following this structure; the definition is explicitly based on interactional linguistics.
- **Break condition:** If the tripartite structure proves unstable or non‑generalizable across diverse pedagogical contexts, the classification target becomes invalid.

### Mechanism 3: High‑fidelity capture as prerequisite for feature discovery
- **Claim:** High‑fidelity, synchronized multimodal capture (TechnéLAB) is a necessary precondition for discovering the feature set relevant to explanatory sequences.
- **Mechanism:** Without infrastructure guaranteeing aligned, high‑quality audio‑video‑gaze data, researchers cannot reliably observe co‑occurrence and temporal relationships between modalities; this ground truth defines ML‑compatible annotation categories.
- **Core assumption:** Salient features for automatic categorization must be empirically derived from raw, richly synchronized multimodal data.
- **Evidence:** The platform’s multi‑camera video, synchronized audio, eye‑tracking, and digital traces enabled detailed description of “explications paraverbales et non‑verbales”; analysis relied on this data.
- **Break condition:** If lower‑cost capture methods produce sufficiently synchronized data for coarse feature extraction, TechnéLAB’s necessity diminishes.

## Foundational Learning

### Concept 1: Multimodal Transcription Convention Variability
- **Why needed:** The project’s core finding is that manual transcription is not neutral; engineers must understand why experts produce different transcriptions of the same video to grasp the “data problem” for AI.
- **Quick check question:** Looking at the two transcriptions on pages 19–24, what are two specific, non‑trivial differences in how the teacher’s gesture at timestamp ~00:25 is represented (e.g., description detail, functional label, synchronization)?

### Concept 2: Interactional Sequence as Analytical Unit (Tripartite Model)
- **Why needed:** The automation target is not isolated words or gestures but a structured interactional sequence (opening problem, core explanation, closure ratification); this shifts the ML problem from token classification to sequence detection.
- **Quick check question:** In the provided example, identify the verbal and gestural cues that mark the transition from the “opening” (problem posing) to the “core” (explanatory move).

### Concept 3: Transcription as Theoretical Act (Reflexivity)
- **Why needed:** Transcription choices (what to note, how to code gestures) are guided by the researcher’s theory of meaning; for engineers, “ground truth” labels are theory‑laden, not objective facts—ML will learn the theory, not “reality.”
- **Quick check question:** How does Julie Rançon’s interpretative label “iconique” for a gesture, versus Emilie Remond’s descriptive “montre l’index et le majeur,” reflect different theoretical commitments about what a gesture *is*?

## Architecture Onboarding

### Component map
TechnéLAB capture (multicam, audio, eye‑tracking) -> Manual annotation with conventions (ELAN/ANVIL) -> Tiered annotation files -> Feature extraction scripts (Python/Praat) -> Sequence labeling model (CRF/BiLSTM) -> Proposed semi‑automatic validation interface

### Critical path
1. Secure/collect high‑quality, synchronized multimodal corpus in a TechnéLAB‑style environment.
2. Manually annotate a small, gold‑standard subset using a single, agreed convention (e.g., Mondada for gesture, ICOR for talk) to establish a consistent answer key.
3. Extract low‑level features (audio prosody, video motion, pose) and align them to manual annotations.
4. Train and evaluate a sequence model (e.g., BiLSTM‑CRF) on the gold set; performance is the primary feasibility metric.

### Design tradeoffs
- **Granularity vs. Feasibility:** Fine‑grained gesture annotation (Ferré) provides richness but is extremely slow; coarser functional coding (Tellier) scales better for ML but loses nuance. *Tradeoff:* Start coarse for initial models.
- **Tool Lock‑in:** ELAN offers interoperability; ANVIL provides better hierarchical categories. Choice affects collaboration and data format. *Tradeoff:* Prioritize ELAN for community support.
- **Signal Quality Dependency:** Clean audio yields better ASR; classrooms are noisy. Investing in hardware (individual mics) may outperform sophisticated noise‑reduction algorithms initially.

### Failure signatures
- **Data‑level:** Low inter‑annotator agreement (Cohen’s Kappa < 0.6) on gold‑set categories. *Action:* Halt modeling; reconvene on annotation manual.
- **Model‑level:** Model performance ~random on test set. *Action:* Check feature extraction; likely inconsistent annotations or inadequate features.
- **System‑level:** Proposed semi‑automatic tool increases total annotation time (correction > manual). *Action:* Improve model accuracy or adjust feature set before integration.

### First 3 experiments
1. **Transcription Convergence Pilot:** Two annotators independently code 5 minutes of the same INTER‑EXPLIC sequence using one convention (e.g., Mondada). Compute Cohen’s Kappa for segment boundaries and gesture labels. Goal: Kappa > 0.7.
2. **ASR Baseline on Classroom Audio:** Run Whisper on 1 hour of TechnéLAB‑style audio (with individual mics). Compute word error rate (WER) and categorize errors. Goal: WER < 30%.
3. **Feature Correlation Analysis:** On the gold‑standard segment, extract simple features (turn duration, gestures/minute, pitch slope). Compute correlation/conditional probability with segment labels (opening/core/closure). Goal: Identify predictive low‑level features.

## Open Questions the Paper Calls Out

1. **Operationalizing the tripartite model:** How can the theoretical tripartite model of explanatory discourse (opening, core, closure) be operationalized into computational features for automatic detection in multimodal classroom recordings? The project defined the structure manually but did not implement an algorithmic solution. Resolution requires a prototype that extracts verbal, gestural, and prosodic cues and validates segmentation against manually annotated gold standards.

2. **ML‑compatible annotation categories:** Which annotation categories within existing multimodal transcription schemes (e.g., ICOR, Mondada, Tellier) are most amenable to machine learning classification, and what corpus size is needed to train robust models for each? The project only assessed theoretical compatibility; no empirical testing was performed. Resolution requires systematic benchmarking of ML classifiers on a shared corpus, producing learning curves that indicate minimum training sizes for target accuracy.

3. **Mitigating transcription variability:** How can the variability and interpretative bias in manual multimodal transcriptions—highlighted by divergent annotations of the same sequence—be mitigated to produce consistent ground truth for automated systems? The project documented the issue but did not develop or evaluate standardization methods. Resolution requires a standardized transcription protocol with explicit decision rules, tested by multiple annotators to achieve high inter‑annotator agreement; application of this protocol to generate a gold‑standard dataset.

4. **Design principles for hybrid tools:** What design principles should guide the development of hybrid human‑computer tools that integrate automatic speech/gesture recognition with researcher reflexivity, as proposed for future work? The concept was outlined but not specified. Resolution requires a proof‑of‑concept interface linking ASR and computer vision outputs to an annotation environment where researchers can intervene in real time, evaluated through user studies on efficiency, consistency, and analytical usefulness.

## Limitations
- **Data accessibility:** The INTER‑EXPLIC corpus (~30 hours) and TechnéLAB hardware/sync protocols are not publicly documented, preventing replication of data collection and annotation.
- **Methodological metrics:** No quantitative inter‑annotator agreement scores (e.g., Cohen’s Kappa) were reported, making it impossible to define a reliable gold standard for ML training.
- **Pipeline absence:** The project did not produce any trained models, train/test splits, or baseline performance metrics; future work must build the ML pipeline from scratch.

## Confidence
- **Mechanism 1 (Transcription variability blocks automation):** High confidence. Direct evidence from side‑by‑side transcriptions and convention survey.
- **Mechanism 2 (Tripartite sequence as ML target):** Medium confidence. Theoretically grounded in interactional linguistics but untested across diverse classrooms.
- **Mechanism 3 (TechnéLAB as necessary precondition):** Medium confidence. Strongly supported as the project’s infrastructure, but alternative capture methods may suffice for coarse feature discovery.

## Next Checks
1. **Transcription convergence pilot:** Have two annotators independently code 5 minutes of the same INTER‑EXPLIC sequence using a single convention (e.g., Mondada). Compute Cohen’s Kappa for segment boundaries and gesture labels. Success threshold: Kappa > 0.7.
2. **ASR error floor measurement:** Run a modern ASR (e.g., Whisper) on 1 hour of TechnéLAB‑style classroom audio (with individual mics). Compute word error rate (WER) and categorize errors. Success threshold: WER < 30%.
3. **Tripartite generalizability test:** Re‑annotate a new sample (different teacher/subject/level) using the tripartite schema. Measure agreement on sequence identification and transition points. Success threshold: >80% agreement on segment labels.
