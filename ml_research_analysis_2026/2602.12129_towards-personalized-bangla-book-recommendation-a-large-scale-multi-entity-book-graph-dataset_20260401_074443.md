# Towards Personalized Bangla Book Recommendation: A Large-Scale Multi-Entity Book Graph Dataset

## Quick Facts
- **arXiv ID:** 2602.12129
- **Source URL:** https://arxiv.org/abs/2602.12129
- **Reference count:** 40
- **Primary result:** Introduced RokomariBG, a large-scale heterogeneous Bangla book graph (127K books, 64K users, 2M+ edges) and identified a two-tower retrieval model as top performer (NDCG@10 = 0.204).

## Executive Summary

The paper introduces **RokomariBG**, the first large-scale structured dataset for Bangla book recommendation, built from the e-commerce platform Rokomari.com. It comprises 127,000 books, 64,000 users, and over 2 million edges across eight heterogeneous relation types (e.g., purchases, ratings, authorship, categories). This resource addresses the scarcity of data in the low‑resource Bangla language and enables research on graph‑based recommendation.

The authors conduct a comprehensive benchmark of recommendation models on this dataset, ranging from matrix factorization to graph neural networks. They find that a neural **two‑tower retrieval model**, which incorporates side features (book metadata, textual descriptions) and relational knowledge through a multi‑relational graph encoder, achieves the best performance (NDCG@10 = 0.204, NDCG@50 = 0.276). Ablation studies highlight the importance of both the graph’s multi‑relational structure and textual metadata, particularly for users with limited interactions. The work also outlines promising future directions, including language‑specific pretraining, explainability, and fairness analysis.

## Method Summary

**Data collection and graph construction.** The authors scraped data from Rokomari.com, extracting user–book interactions (purchases, ratings), book attributes (title, author, category, publisher), and user profiles. These were organized into a heterogeneous information network where nodes represent users, books, authors, categories, and publishers, and edges represent eight relation types (e.g., user→book, book→author). The graph contains 127K books, 64K users, and >2M edges. Textual fields (book descriptions, user reviews) were embedded using a multilingual sentence transformer.

**Model training and evaluation.** The recommendation task was formulated as retrieval: given a user, rank all candidate books. Baselines included MF, LightGCN, and other GNN variants. The proposed two‑tower model uses a multi‑relational GNN to generate initial node embeddings, then feeds user and book embeddings into separate MLP encoders that also ingest side features (e.g., book category, author, text embedding). The dot product of the final user and item embeddings gives a score; the model is trained with BPR loss and evaluated using NDCG@k and Hit@k. Ablation experiments removed side features or specific relation types to measure their impact.

## Key Results
- Two‑tower retrieval architecture achieves best performance: **NDCG@10 = 0.204**, NDCG@50 = 0.276.
- Ablation studies confirm that **multi‑relational graph structure** and **textual metadata** are critical contributors, with cold‑start user performance dropping significantly when either is removed.
- The **RokomariBG dataset** is the first large‑scale heterogeneous graph for Bangla books, containing 127K books, 64K users, and over 2 million edges across eight relation types.

## Why This Works (Mechanism)
The two‑tower model succeeds because it jointly exploits the multi‑relational graph structure and rich side information. The graph propagation layer aggregates signals from different entity types (e.g., books by the same author, users in the same category), enabling the model to handle sparsity by borrowing strength from related nodes. Side features, especially textual embeddings, capture content‑based affinities that complement collaborative signals. The separate towers allow pre‑computation of item embeddings for efficient retrieval at scale, while the dot‑product interaction provides a simple yet effective scoring function. Ablation results demonstrate that removing either relational edges or text features harms accuracy, confirming that the synergy between these mechanisms is essential.

## Foundational Learning
- **Heterogeneous Graph Neural Networks (HGNNs)**  
  *Why needed*: To model the eight distinct relation types in the Bangla book graph, preserving semantics and enabling information flow across different entity types.  
  *Quick check*: Implement a mini heterogeneous graph with two node types and two edge types; verify that the HGNN produces different embeddings for the same node under different edge types.
- **Two‑Tower (Dense Retrieval) Models**  
  *Why needed*: Enables scalable recommendation by pre‑computing item embeddings and performing fast nearest‑neighbor search, crucial for millions of books.  
  *Quick check*: Index 100K book embeddings in an approximate nearest neighbor library (e.g., FAISS) and measure query latency for a single user (< 50 ms).
- **Cold‑Start Recommendation**  
  *Why needed*: Many Bangla books and users have few interactions; leveraging side information and graph structure is vital to provide meaningful recommendations.  
  *Quick check*: Split the test set by user interaction count; confirm that model performance degrades gracefully as interaction count decreases rather than collapsing.
- **Multimodal and Language‑Specific Embeddings**  
  *Why needed*: Bangla text (titles, descriptions) carries nuanced semantics; Bangla‑specific pretrained models can capture these better than multilingual ones trained on dominant languages.  
  *Quick check*: Compare Bangla‑BERT and mBERT embeddings on a small downstream task (e.g., book title clustering) to observe relative gains.
- **Fairness in Recommendation**  
  *Why needed*: To ensure that the system does not systematically disadvantage certain authors (e.g., by gender) or regions, which could arise from biased interaction data.  
  *Quick check*: If author gender is available, compute group‑level exposure (e.g., proportion of recommended books by women authors) and compare against the distribution in the catalog.

## Architecture Onboarding
#### Component Map
User interactions, book metadata, text -> Build heterogeneous graph -> Multi‑relational GNN -> Node embeddings -> User encoder (MLP) + Item encoder (MLP + text) -> User embedding × Item embedding (dot product) -> Relevance score

#### Critical Path
1. Collect and clean data from Rokomari; extract interactions and attributes.  
2. Build heterogeneous graph with defined node/edge types and split into train/val/test.  
3. Train multi‑relational GNN to produce contextualized node embeddings.  
4. Construct two‑tower model by attaching side feature encoders to user and book nodes.  
5. Train end‑to‑end with BPR loss, optimizing user–item pair rankings.  
6. Evaluate using NDCG@k and Hit@k on test set; perform ablations.

#### Design Tradeoffs
- **Graph expressiveness vs. computation**: Adding more relation types and GNN layers improves model capacity but increases memory usage and training time. The two‑tower design mitigates inference cost by allowing offline item embedding computation, but the GNN must still be run periodically when the graph updates.
- **Side information richness vs. noise**: Incorporating many metadata fields and text can boost performance, yet some fields may be noisy or missing; careful feature engineering and handling of missing values (e.g., unknown tokens) is required.
- **Model size vs. overfitting**: Given the moderate dataset size (2M edges) and low‑resource language, large transformer‑based text encoders may overfit; using frozen multilingual sentence embeddings or smaller Bangla models is a pragmatic tradeoff.

#### Failure Signatures
- **Cold‑start collapse**: If NDCG for users with ≤5 interactions is near zero, the model fails to leverage side information or graph structure for sparse users.
- **Embedding degeneration**: The variance of item embeddings is very low (e.g., < 1e‑5), indicating the model is not learning discriminative representations; often caused by too high learning rate or insufficient regularization.
- **Training instability**: BPR loss fluctuates or increases, suggesting issues with negative sampling or gradient scaling; monitor loss curves and adjust batch size or sampler.

#### First Experiments
1. **Baseline MF**: Train a standard matrix factorization model (no side features, no graph) to establish a lower bound and verify the data pipeline.
2. **Two‑tower without side features**: Train the full two‑tower model but remove all side inputs (metadata and text); this isolates the contribution of the GNN‑derived embeddings alone.
3. **Two‑tower without GNN**: Use identity or random embeddings for users/books (no multi‑relational propagation) to confirm that the relational graph provides essential signal beyond side features.

## Open Questions the Paper Calls Out
#### Open Question 1
- **Question:** How can Bangla‑specific pretrained language models be integrated to improve multimodal book recommendation?
- **Basis in paper:** [explicit] Abstract states that the dataset enables "future work on language‑aware and multimodal recommendation with pretrained Bangla or multilingual language models."
- **Why unresolved:** Benchmarking used only off‑the‑shelf multilingual sentence transformers; no evaluation of Bangla‑optimized models (e.g., Bangla‑BERT) or multimodal extensions beyond text.
- **What evidence would resolve it:** Comparative experiments training Bangla‑specific and multilingual embeddings on the dataset, measuring NDCG@10 gains, and exploring multimodal fusion with available metadata.

#### Open Question 2
- **Question:** What relational and side feature‑based strategies are most effective for cold‑start users and items in heterogeneous Bangla book graphs?
- **Basis in paper:** [explicit] Abstract and Section 5.4 identify cold‑start recommendation as a key direction; ablation studies show removing relations or side features severely degrades cold‑start performance (NDCG@10 drops from 0.103 to 0.057–0.069).
- **Why unresolved:** No dedicated cold‑start algorithms are proposed; the optimal way to leverage the multi‑entity graph for cold‑start users/items remains unclear.
- **What evidence would resolve it:** Develop and evaluate cold‑start‑specific architectures (e.g., meta‑learning, graph prototypical networks) on the dataset's cold‑start subsets, tracking NDCG@10 and Hit@50.

#### Open Question 3
- **Question:** How can the heterogeneous multi‑entity graph structure be exploited to generate interpretable recommendations for Bangla books?
- **Basis in paper:** [explicit] Abstract lists "explainable recommendation" as a future task facilitated by RokomariBG.
- **Why unresolved:** Current models are black‑box; the graph's relational paths (e.g., user→book→author→category) could naturally explain recommendations but are not utilized for explainability.
- **What evidence would resolve it:** Implement path‑based or attention‑based explainable GNNs (e.g., GNNExplainer) on the dataset, conduct user studies in Bangla to assess explanation quality and trust.

#### Open Question 4
- **Question:** What fairness and bias issues exist in Bangla book recommendation systems, and how can they be measured and mitigated using the dataset's entity diversity?
- **Basis in paper:** [explicit] Abstract includes "fairness and bias analysis" as a research direction enabled by the dataset.
- **Why unresolved:** No fairness audit is performed; the dataset may reflect biases (e.g., gender in authors, regional popularity in categories) that recommenders could perpetuate.
- **What evidence would resolve it:** Audit dataset for biases across sensitive attributes (gender, region), compute fairness metrics (e.g., exposure disparity, demographic parity), and evaluate bias mitigation techniques (e.g., re‑ranking) on recommendation accuracy and fairness.

#### Open Question 5
- **Question:** Can cross‑lingual transfer learning from high‑resource languages improve recommendation performance for low‑resource Bangla, and which transfer methods are most effective?
- **Basis in paper:** [explicit] Abstract mentions "cross‑lingual transfer learning" as a promising direction for the dataset.
- **Why unresolved:** Dataset is monolingual Bangla; cross‑lingual approaches (e.g., using English data or aligned embeddings) are unexplored despite code‑mixed reviews suggesting multilingual potential.
- **What evidence would resolve it:** Train models with cross‑lingual embeddings (e.g., mBERT), augment data via machine translation, or transfer from English recommendation datasets, measuring NDCG@10 improvements on Bangla test set.

## Limitations
- **Platform bias**: Data from a single source (Rokomari) may overrepresent popular books and a narrow user segment, limiting the diversity of the Bangla book ecosystem.
- **Public access uncertain**: No confirmation that the dataset will be released publicly, hindering external validation and reproducibility.
- **Modest metrics**: The reported NDCG@10 = 0.204 may be insufficient for practical deployment, and the baseline selection omits recent state‑of‑the‑art deep recommenders, possibly inflating the apparent gains.

## Confidence
- Dataset scale & heterogeneity: **High**
- Two‑tower model superiority: **Medium**
- Value of multi‑relational structure and textual metadata: **Medium**

## Next Checks
1. **Public release & replication**: Ensure the dataset and code are publicly available; have independent teams reconstruct the graph, rerun benchmarks, and verify the reported metrics.
2. **Cross‑platform test**: Evaluate the top model on a different Bangla book dataset (e.g., from another retailer or library) to assess generalizability beyond Rokomari.
3. **Temporal split**: Perform a time‑based train‑test split (e.g., train on interactions from 2020–2022, test on 2023) to verify whether multi‑relational graph features remain predictive for future interactions.
