# Pencil Puzzle Bench: A Benchmark for Multi-Step Verifiable Reasoning

## Quick Facts
- arXiv ID: 2603.02119  
- Source URL: https://arxiv.org/abs/2603.02119  
- Reference count: 40  
- Primary result: Agentic iteration improves top model success from 20.2% to 56.0% (+35.7pp); solution compressibility predicts difficulty 4.2× better than move count.

## Executive Summary
Pencil Puzzle Bench introduces a benchmark for evaluating multi-step reasoning in language models using 300 logic puzzles with per-move verification. The benchmark provides two evaluation modes: direct ask (single-shot move list) and agentic (iterative tool calls with step-level feedback). Evaluation of 51 models reveals two key capability axes: reasoning effort and agentic iteration. Agentic iteration yields substantial gains, particularly for weaker models, with Claude Opus 4.6 improving from 0.3% to 30.0% and GPT-5.2@xhigh from 20.2% to 56.0%. Additionally, the benchmark’s step-level verifier enables dense reward signals and shows that solution compressibility is a far stronger predictor of puzzle difficulty than move count. These findings highlight the value of external verification and iterative refinement for complex reasoning tasks.

## Method Summary
Pencil Puzzle Bench is distributed as a Python package that wraps the pzprjs puzzle engine. It includes a “golden” set of 300 puzzles across 20 varieties, each represented by a unique solution trace. Models are evaluated in two settings: (1) direct ask, where the model outputs a JSON list of moves in one inference call; (2) agentic, where the model interacts via tool calls (make_move, check_board, etc.) and receives per-move constraint violation feedback from the verifier. The verifier checks each move against variety-specific rules and returns violation details, enabling dense reward shaping. Primary metrics are success rate (complete puzzle without violations), turn count, and cost. The benchmark also includes infrastructure for generating solutions and analyzing difficulty via compressibility.

## Key Results
- Agentic iteration yields large improvements: Claude Opus 4.6 +30.0pp (0.3%→30.0%), GPT-5.2@xhigh +35.7pp (20.2%→56.0%).
- Agentic attempts require substantial effort: median 29 turns (17 minutes), maximum 1,221 turns (14.3 hours).
- Solution compressibility predicts puzzle difficulty 4.2× better than move count (adjusted R² 0.385 vs 0.092).
- Agentic solves three puzzle varieties never solved directly; best direct success 27.0%, best agentic 56.0%.

## Why This Works (Mechanism)

**Mechanism 1: Agentic iteration compensates for weak reasoning**  
- **Claim**: Agentic iteration with step-level verification compensates for weak internal reasoning by enabling course correction from localized constraint violations.  
- **Mechanism**: The agentic harness provides a loop where the model makes moves, receives deterministic feedback on which specific rule was violated, and can revise its partial solution. This externalizes the verification and repair process that strong single-shot reasoning would perform internally.  
- **Core assumption**: Models can correctly interpret and act upon localized error feedback to progressively converge on a valid solution state.  
- **Evidence**: Agentic gains range from +4.8pp for strong reasoners to +30.0pp for weak ones; median 29 turns per attempt.  
- **Break condition**: Models ignore feedback or repeatedly violate the same rule, preventing convergence.

**Mechanism 2: Solution compressibility as difficulty predictor**  
- **Claim**: Solution compressibility is a superior predictor of puzzle difficulty compared to move count because it captures solution structure entropy.  
- **Mechanism**: Highly compressible solution sequences have repetitive, patterned moves that allow models to generalize from partial progress. Low-compression solutions require novel decisions at each step, increasing cognitive load. Compression ratio (zlib size / raw size) quantifies structural regularity.  
- **Core assumption**: Model performance correlates with algorithmic information content of the solution trajectory, not just length.  
- **Evidence**: Compressibility explains 38.5% of variance (R²_adj) vs. 9.2% for move count; predicts difficulty 4.2× better.  
- **Break condition**: Compressibility fails to generalize across puzzle varieties due to confounding factors.

**Mechanism 3: Dense reward infrastructure via step-level verification**  
- **Claim**: Step-level verification infrastructure enables dense reward shaping for RL training by exposing per-move, per-constraint violation counts and types.  
- **Mechanism**: The pzprjs `check()` function returns violation details (rule broken, offending cells) after each move. These can be composed into reward functions (e.g., violation-delta shaping) providing intermediate feedback.  
- **Core assumption**: Dense, interpretable rewards improve sample efficiency and convergence in RL for reasoning tasks.  
- **Evidence**: The verifier reports rule violations and offending cells; the benchmark is designed to support process supervision and RL.  
- **Break condition**: Violation signals are noisy or inconsistent across instances, leading to unstable reward shaping.

## Foundational Learning

**Constraint-Satisfaction Verification**  
- **Why needed here**: All puzzles are constraint-satisfaction problems; understanding how each move affects global and local constraints is fundamental to interpreting feedback and planning corrections.  
- **Quick check**: For a puzzle type like Slitherlink, list local vs. global constraints and how a single violation might be repaired.

**Process Supervision Signals**  
- **Why needed here**: The benchmark’s value lies in providing step-level validation data, prerequisite for training process reward models or RL policies that learn from intermediate steps.  
- **Quick check**: Design a reward function using per-move violation counts to incentivize reducing total violations; what edge cases arise (e.g., temporary violations during construction)?

**Iterative Refinement Loops**  
- **Why needed here**: Agentic evaluation shows many models require multiple attempts with feedback. Understanding how to structure and optimize the make-move → check → revise loop is key to building effective agents.  
- **Quick check**: In the agentic harness, what are failure modes (e.g., getting stuck on same rule, context overflow)? How would you detect and recover?

## Architecture Onboarding

**Component map**: Puzzle engine (pzprjs) → Solution generator (cspuz-solver2) → Benchmark harness (pencil-puzzle-bench) → Agentic framework → Dataset curators.

**Critical path**:  
1. Load puzzle URL → deserialize to pzprjs state.  
2. Receive model move → apply to internal board.  
3. Run `check()` → return violations [] if valid.  
4. If complete, terminate; else return state+violations to model.  
5. Track turn count, duration, termination reason.

**Design tradeoffs**: ASCII vs multimodal (text vs images); step verification granularity (every move vs. periodic); agentic loop limits (5000-move cap vs. long solutions).

**Failure signatures**: API timeouts (35% failure at high effort); repeated violation of same rule; context decay over long runs; tool misuse (malformed moves).

**First 3 experiments**:  
1. Single-puzzle direct-ask baseline: Load one puzzle, call model with DirectAsk prompt, parse JSON moves, apply sequentially, record success and first violation step.  
2. Agentic loop on simple puzzle: Use a small puzzle with a model, run 5 agentic attempts, logging violations and outcomes to measure loop stability.  
3. Step-verification sanity check: For a solved puzzle, replay its solution trace move-by-move and assert `check()` returns no violations at each step.

## Limitations
- Exact inference configurations (temperature, timeouts, token budgets) for the 51 models are not disclosed, hindering replication.
- The full dataset of 62,231 puzzles used in compressibility analysis is not released; only the 300-puzzle golden set is available.
- Prompt templates in Appendix B may differ slightly from those used in actual experimental runs.

## Confidence
- Agentic iteration (Mechanism 1): Medium (large empirical gains but assumption about feedback interpretation may not hold universally)
- Compressibility predictor (Mechanism 2): Medium (strong regression metrics but external validation blocked by data unavailability)
- Dense reward infrastructure (Mechanism 3): Low (described but no RL experiments; claim remains theoretical)

## Next Checks
1. Replicate agentic evaluation on golden set with a different model (e.g., Claude Sonnet 4.6) and compare agentic gap to reported values.
2. Verify step-level verifier correctness by replaying solution traces and injecting common errors to confirm detection.
3. Validate compressibility predictor by computing compressibility for all 300 golden puzzles and regressing against model success rates; expect compressibility to explain >4× more variance than move count.
