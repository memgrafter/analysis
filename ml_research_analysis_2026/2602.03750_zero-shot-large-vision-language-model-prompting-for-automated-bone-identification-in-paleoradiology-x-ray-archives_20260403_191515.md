# Zero-shot large vision-language model prompting for automated bone identification in paleoradiology x-ray archives

## Quick Facts
- **arXiv ID:** 2602.03750
- **Source URL:** https://arxiv.org/abs/2602.03750
- **Reference count:** 0
- **Primary result:** 92% main bone, 80% projection view, 100% laterality on expert-validated sample; scalable at 11 images/min at $0.0085/image.

## Executive Summary
Paleoradiology X-ray archives are highly heterogeneous, impeding efficient content navigation and triage. This study presents a zero-shot prompting pipeline using GPT-4o Vision to automatically identify the main bone, projection view, and laterality of skeletal X-rays. The pipeline converts raw DICOM files into standardized bone-windowed PNGs, processes them with a carefully engineered system prompt that directs attention to diagnostically relevant cues (e.g., a reference object for scale), and extracts structured JSON outputs. Validated on a random sample of 100 images by an expert paleoradiologist, the system achieved 92% accuracy for main bone, 80% for projection view, and 100% for laterality, with Cohen's κ values of 0.899, 0.598, and 1.000 respectively. At an average throughput of 11 images per minute and a cost of $0.0085 per image, the approach enables scalable curation of large archives with minimal expert review.

## Method Summary
The study analyzed 8423 DICOM X-ray files from 11 London excavation sites, exhibiting high heterogeneity due to fragmentation, ad-hoc positioning, and variable metadata. Each DICOM was preprocessed by applying a bone window using the image's WindowWidth/WindowCenter values via a Value of Interest Look Up Table (VOI LUT), enforcing MONOCHROME2 photometry, and linearly rescaling pixel intensities to an 8-bit range before saving as PNG. The zero-shot pipeline then queried GPT-4o Vision (June 2025 release) with each PNG using a system prompt that instructed the model to: (1) consult an explicit list of common bones, (2) estimate scale using a reference object (paperclip), and (3) output a strict JSON object containing the bone, view, laterality, and confidence level (High/Medium/Low). The temperature was set to 0.3 for deterministic outputs. Responses were parsed, validated, and aggregated into a master spreadsheet. An expert paleoradiologist evaluated a random 100-image subset to compute accuracy and Cohen's κ for each annotation field.

## Key Results
- **Main bone identification:** 92% accuracy, Cohen's κ = 0.899
- **Projection view identification:** 80% accuracy, Cohen's κ = 0.598
- **Laterality identification:** 100% accuracy, Cohen's κ = 1.000
- **Processing throughput:** 11 images/minute at $0.0085 per image

## Why This Works (Mechanism)

### Mechanism 1: Prompt-based zero-shot reasoning
- **Claim:** A domain-specific, structured system prompt enables zero-shot reasoning by constraining the LVLM's output space and directing attention to diagnostically relevant visual cues (e.g., reference object scale).
- **Mechanism:** The engineered prompt provides a precise task definition, an explicit bone taxonomy, and critical heuristics (e.g., "estimate bone length using the reference object"). This reduces semantic ambiguity and guides the model's internal attention mechanisms toward invariant features like size relative to a known scale rather than solely texture or shape, which are highly variable in archaeological specimens.
- **Core assumption:** The LVLM possesses pre-trained knowledge of skeletal anatomy and typical radiograph projections that can be activated and directed via prompt conditioning, without requiring gradient updates.
- **Evidence anchors:** The abstract highlights the "carefully engineered prompt"; Section 2.3 details iterative prompt development including the explicit bone list and scale-based instructions; the corpus lacks direct neighbor evidence but aligns with general prompt learning principles.
- **Break condition:** If the visual information is fundamentally outside the model's pre-training distribution (e.g., severe fragmentation, atypical imaging artifacts), the prompt's heuristics may fail. Failure analysis shows errors on bones with "similar structure, size, or both" and ambiguous views.

### Mechanism 2: Standardized bone-windowing preprocessing
- **Claim:** Pre-processing raw DICOM files into standardized, bone-windowed PNGs creates a consistent visual input format that aligns with the LVLM's training and emphasizes skeletal structures.
- **Mechanism:** Applying a bone window (via VOI LUT using DICOM's WindowWidth/WindowCenter) and enforcing MONOCHROME2 photometry maximizes contrast between bone (bright) and background (dark). This normalization mitigates heterogeneity from different X-ray sources and exposure settings, presenting a cleaner, more clinically familiar image to the model.
- **Core assumption:** The LVLM's visual encoder is sensitive to intensity distributions and contrast; a standardized window improves feature extraction for bone edges and cortical density.
- **Evidence anchors:** The abstract notes conversion to bone-windowed PNGs; Section 2.2 describes the conversion process in detail.
- **Break condition:** If bone mineralization is extremely low (e.g., juvenile or highly degraded bone), the standard window may fail to highlight structures, assuming a typical adult bone density window.

### Mechanism 3: Structured confidence output for triage
- **Claim:** The structured JSON output format with an explicit confidence field ("High"/"Medium"/"Low") enables automated triage, separating high-certainty automated annotations from cases requiring expert review.
- **Mechanism:** The prompt instructs the model to report confidence based on anatomical landmark clarity and reference object utility. This creates a discrete, machine-readable signal that downstream systems can use to filter results, focusing expert effort on ambiguous cases.
- **Core assumption:** The model's self-reported confidence correlates with actual error probability, allowing effective prioritization of human-in-the-loop validation.
- **Evidence anchors:** The abstract mentions "low or medium confidence flags for ambiguous cases"; Section 2.3 includes confidence instruction; Section 3.1 notes one medium-confidence case.
- **Break condition:** The model may be overconfident on novel failure modes it cannot recognize; validation showed only one medium-confidence case, limiting statistical power on this triage mechanism's reliability.

## Architecture Onboarding
- **Component map:**  
  Ingestor → Preprocessor → Prompt Engine → LVLM Client → Response Parser → Tagger/Formatter → Validation Interface

- **Critical path:**  
  DICOM → PNG → (API Call + Prompt) → JSON → Spreadsheet Row. Latency dominated by API network call (~5.2s/image).

- **Design tradeoffs:**  
  - Cloud API vs. On-Premise: Cloud (GPT-4o) offers state-of-the-art accuracy and zero maintenance but introduces cost, privacy, and dependency risks. On-premise open-source LVLM trades accuracy for data control and fixed cost.  
  - Prompt Complexity vs. Token Cost: Adding more heuristics and examples improves accuracy but increases token usage and cost.  
  - Strict JSON vs. Natural Language: Forcing JSON enables easy parsing but may constrain reasoning expressiveness and increase parsing failures if format drifts.

- **Failure signatures:**  
  - JSON parse error: Model output not valid JSON.  
  - Hallucinated bone: Bone field reports non-skeletal objects.  
  - Confidence-inaccuracy mismatch: Model flags "High" confidence on a misclassified image.  
  - API transient failure: Network timeout, rate limit.

- **First 3 experiments:**  
  1. **Prompt Ablation:** Run the full pipeline on the development test set with the original prompt, then sequentially remove: (a) the explicit bone list, (b) the scale instructions, (c) the confidence instruction. Measure delta in main-bone accuracy.  
  2. **Preprocessing Window Test:** Compare bone identification accuracy using different window settings (standard soft-tissue window, no windowing, automated histogram-based window) to validate the bone-windowing assumption.  
  3. **Confidence Threshold Tuning:** For all 2219 processed images, manually review a stratified sample of "High" vs. "Medium/Low" confidence outputs. Compute empirical error rates per confidence level to establish an actionable threshold for expert review.

## Open Questions the Paper Calls Out
- **Open Question 1:** What specific prompt modifications can reduce the high misclassification rate between anteroposterior (AP) and lateral femoral views?
- **Open Question 2:** How well does the zero-shot LVLM pipeline generalize to paleoradiology archives with substantially different geographic origins, preservation states, or imaging equipment?
- **Open Question 3:** Can open-source, on-premise LVLMs match GPT-4o's accuracy for bone identification while mitigating cloud API cost and privacy barriers?
- **Open Question 4:** What is the operational accuracy and reliability of the system for automatic detection of fractures and abnormal features?

## Limitations
- **Preprocessing specifics:** Exact bone-windowing parameters (WindowWidth/WindowCenter) are unreported, hindering faithful reproduction.
- **Reference object assumption:** The pipeline assumes a consistent 2-inch paperclip is present for scale; its actual prevalence and size fidelity across the archive are unverified.
- **Confidence reliability:** Model self-reported confidence is poorly validated (only one medium-confidence case), making triage effectiveness uncertain.
- **Generalization boundary:** Performance likely degrades on severely fragmented bones or atypical projections not well-represented in GPT-4o's training distribution.
