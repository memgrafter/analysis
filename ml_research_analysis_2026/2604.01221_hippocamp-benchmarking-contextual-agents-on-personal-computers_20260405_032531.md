# HippoCamp: Benchmarking Contextual Agents on Personal Computers

## Quick Facts
- **arXiv ID**: 2604.01221
- **Source URL**: https://arxiv.org/abs/2604.01221
- **Reference count**: 40
- **Primary result**: State-of-the-art agents achieve only 48.3% profiling accuracy and 62.8% factual retention on realistic personal file system tasks, with the main bottleneck in post-retrieval reasoning stages.

## Executive Summary
HippoCamp introduces the first benchmark for contextual agents operating in realistic personal computer environments with multimodal data and long-horizon reasoning. It constructs device-scale environments from real user profiles (42.4 GB, 2000+ files), generates 581 question-answering tasks covering search, evidence perception, and multi-step reasoning, and provides 46.1K step-wise annotated trajectories for fine-grained failure diagnosis. Evaluation reveals that current state-of-the-art models perform poorly, and the primary limitation lies not in retrieval but in subsequent stages: evidence discrimination, multimodal grounding, and entity binding.

## Method Summary
The benchmark builds environments by aggregating authentic personal file systems, preserving heterogeneity in file types, structures, and multimodal content (text, images, audio). Tasks are programmatically generated to require agents to reason across this data, simulating real user queries. Each task includes a natural language question, a ground truth answer, and a trajectory of executable steps with file-level evidence annotations. This design allows isolating failure modes and measuring performance at each reasoning stage, from retrieval to final answer synthesis.

## Key Results
- Agents achieve low absolute performance: 48.3% profiling accuracy and 62.8% factual retention.
- Retrieval quality (F1) decouples from answer accuracy, indicating post-retrieval bottlenecks.
- Failure analysis highlights evidence discrimination, multimodal grounding, and entity binding as critical weaknesses.

## Why This Works (Mechanism)
HippoCamp works by exposing a fundamental gap: retrieval is relatively tractable, but turning retrieved files into correct answers is not. The benchmark’s design decouples these stages through controlled evaluations. Results show that even with high retrieval F1, agents fail to select minimal sufficient evidence, align cross-modal references (e.g., textual constraints with images), or disambiguate multiple entities (e.g., user vs. family members). This pinpoints the bottleneck to reasoning *after* retrieval, where current agents lack robust mechanisms for evidence selection, multimodal integration, and entity-aware processing.

## Foundational Learning
1. **Evidence Discrimination**
   - *Why needed*: To filter noisy retrieved candidates and identify a minimal set of files that sufficiently answer the query.
   - *Quick check*: Given a retrieved file list, can the agent select only those directly supporting the answer?

2. **Multimodal Grounding**
   - *Why needed*: To align and reason over heterogeneous content (e.g., matching a description in a document to an image).
   - *Quick check*: Does the agent correctly associate a textual constraint (e.g., "photo taken in 2020") with the corresponding visual evidence?

3. **Entity Binding**
   - *Why needed*: To track and attribute evidence to the correct referent when multiple characters (e.g., user, spouse, pet) share the file system.
   - *Quick check*: Can the agent avoid misattributing a health routine file to a pet instead of the user?

4. **Verification Loops**
   - *Why needed*: To cross-check final answers against localized evidence, reducing hallucination and improving traceability.
   - *Quick check*: Does the agent confirm that each claim in its answer is supported by at least one specific file?

## Architecture Onboarding
**Component map**: Query -> File Retriever -> Evidence Filter -> Multimodal Encoder -> Entity Tracker -> Answer Generator -> Verification Module (optional)

**Critical path**: A natural language query initiates file retrieval based on embedding similarity. Retrieved files pass through an evidence filter to remove irrelevance. A multimodal encoder processes remaining files, aligning text, images, and audio. The entity tracker disambiguates references to people or objects. The answer generator synthesizes a response, which may optionally be verified against evidence IDs.

**Design tradeoffs**: High-recall retrieval burdens later stages with noise; precise retrieval risks missing relevant files. Joint multimodal encoding improves accuracy but increases computational cost. Explicit entity tracking adds overhead but reduces misattribution. Skipping verification speeds inference but raises hallucination risk.

**Failure signatures**: Evidence hallucination (citing non-retrieved files), grounding avoidance (ignoring multimodal cues), entity misbinding (attributing evidence to wrong referent), and verification deficit (answers untraceable to files).

**First experiments**:
1. Perfect retrieval ablation: Provide gold-standard retrieved files to quantify post-retrieval errors.
2. Multimodal disable: Remove non-text processing to measure grounding impact.
3. Add verification: Implement a final step that rechecks answer claims against evidence IDs.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How can agents improve evidence discrimination to convert retrieved files into correct answers, given the observed decoupling between retrieval F1 and answer accuracy?
- Basis in paper: [inferred] The analysis in Section 5.1 reveals that retrieval quality and answer quality decouple: methods with high retrieval F1 (e.g., ReAct) have low accuracy, while some with lower retrieval (e.g., Terminal Agent) achieve higher accuracy. The authors identify evidence discrimination as a primary bottleneck.
- Why unresolved: Current agents lack mechanisms to select minimal sufficient evidence from retrieved candidates, leading to noise in reasoning. This is evidenced by the F1–accuracy gap and failure modes like grounding avoidance and evidence hallucination.
- What evidence would resolve it: Controlled experiments comparing different evidence selection strategies (e.g., re-ranking, minimal set cover, verification loops) on HippoCamp, with metrics that measure the precision of the evidence used in the final answer.

### Open Question 2
- Question: How can agents achieve robust multimodal grounding to align evidence across different modalities (e.g., textual constraints with visual content) in personal file systems?
- Basis in paper: [explicit] The paper states "multimodal grounding" as a primary bottleneck (Abstract, Page 1). Section 5.2 shows failures in cross-modal reasoning (e.g., photo requirements vs. images). Table 3 reports perception accuracy as low as 13.2%–28.5% on profiling.
- Why unresolved: Current models treat modalities in isolation or fail to localize cross-modal references precisely. HippoCamp’s low perception accuracy indicates that even after retrieval, agents struggle to interpret heterogeneous content.
- What evidence would resolve it: Development of architectures that jointly encode multimodal context with fine-grained localization; evaluation on HippoCamp cross-modal tasks using evidence-level grounding metrics (atomic units) to measure alignment correctness.

### Open Question 3
- Question: How can agents maintain accurate entity binding in multi-entity personal environments to prevent misattribution of evidence to the wrong referent?
- Basis in paper: [explicit] The paper identifies "entity binding" as a bottleneck (Abstract). Section 5.2 describes ChatGPT Agent Mode attributing health routines to a pet instead of the user. Perception accuracy on profiling remains low (Table 3).
- Why unresolved: Agents do not explicitly model distinct entities sharing the file system; they assume first-person references map to the user. This leads to errors when multiple characters (family, pets) appear in the same environment.
- What evidence would resolve it: Evaluation on HippoCamp queries that require disambiguating multiple co-occurring entities; measuring accuracy on entity-sensitive profiling questions; designing memory architectures that track entity-specific evidence graphs.

### Open Question 4
- Question: How can we incorporate explicit verification loops that re-bind final answers to localized file evidence to reduce hallucination and improve traceability?
- Basis in paper: [explicit] Section 5.2 identifies "verification deficit" as a failure pattern; Section 5.3 recommends adding an "explicit final-stage check." No evaluated method includes such a loop.
- Why unresolved: Agents produce answers without checking consistency against a minimal evidence set. This permits errors to propagate unchecked. The F1–accuracy gap shows answers are often not traceable to retrieved files.
- What evidence would resolve it: Implement agent architectures with a final verification step that cross-references answer claims with evidence IDs; evaluate on HippoCamp by comparing answers with and without verification, using evidence F1 as an auxiliary metric.

## Limitations
- **Generalizability**: Benchmark uses 42.4 GB from 2000+ files, but may not capture diverse OS, file structures, or user behaviors in global personal computers.
- **Task scope**: 581 QA tasks emphasize search and reasoning, potentially omitting dynamic agent actions like file editing or multi-application workflows.
- **Evaluation context**: Performance claims rely on specific SOTA models; newer architectures or fine-tuning could alter results, and bottleneck attribution may conflate retrieval with semantic understanding.

## Confidence
- **Benchmark creation** (environments, tasks, trajectories): High
- **SOTA performance** (48.3% profiling, 62.8% retention): Medium
- **Post-retrieval bottleneck** attribution: Medium

## Next Checks
1. **Cross-dataset replication**: Rebuild HippoCamp using a separate corpus of personal profiles (e.g., different demographics or OS) to validate environmental robustness.
2. **Temporal model evaluation**: Test current SOTA models (e.g., GPT-4o, Claude 3.5) on HippoCamp to assess performance shifts and bottleneck persistence.
3. **Component ablation**: Design controlled experiments with perfect retrieval inputs to isolate post-retrieval stages (evidence discrimination, grounding), quantifying their individual error contributions.
