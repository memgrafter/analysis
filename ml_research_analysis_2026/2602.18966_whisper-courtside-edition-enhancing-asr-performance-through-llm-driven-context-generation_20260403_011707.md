# Whisper: Courtside Edition Enhancing ASR Performance Through LLM-Driven Context Generation

## Quick Facts
- arXiv ID: 2602.18966
- Source URL: https://arxiv.org/abs/2602.18966
- Reference count: 40
- Primary result: Multi-agent LLM pipeline reduces WER by 17.0% relative (0.217→0.180, p<0.001) on NBA commentary without retraining.

## Executive Summary
This paper introduces Whisper: Courtside Edition, a system that enhances OpenAI's Whisper ASR for domain-specific speech using large language models. Targeting NBA basketball commentary—a domain dense with proper nouns and jargon—the system intercepts Whisper's initial transcript and processes it through three specialized LLM agents that identify context, named entities, and jargon. These agents generate a compact prompt that guides Whisper's decoder via its initial_prompt mechanism, all without retraining the model. On 421 evaluation segments, the full pipeline achieves a 17.0% relative reduction in word error rate (WER) compared to the base Whisper, with 40.1% of segments improved and only 7.1% degraded, significantly outperforming direct transcript post-editing.

## Method Summary
The method operates in two stages. First, Whisper transcribes the audio to an initial text transcript. Second, this transcript is fed into a multi-agent pipeline: a context identification agent, a named entity recognition (NER) agent, and a jargon detection agent—all implemented using GPT-4o. Each agent extracts domain-relevant information, which is then merged and compressed into a concise contextual prompt. This prompt is supplied to Whisper's initial_prompt parameter for a second decoding pass on the same audio. The entire process requires no retraining of Whisper and leverages the base model's ability to incorporate prompt-based conditioning.

## Key Results
- Relative WER reduction of 17.0% (from 0.217 to 0.180, p<0.001) on 421 NBA commentary segments.
- 40.1% of segments showed improved WER, while only 7.1% degraded.
- The approach significantly outperforms direct LLM-based transcript post-editing.

## Why This Works (Mechanism)
Whisper's initial_prompt mechanism biases the decoder toward tokens present in the prompt, effectively expanding its effective vocabulary for the domain. The multi-agent LLM pipeline extracts high-value context—such as player names, team names, and sport-specific terms—that are frequently misrecognized by the base model. By compressing this information into a short prompt (within Whisper's token limits), the system provides targeted guidance without overwhelming the decoder. The specialization of agents ensures that noise from irrelevant information is minimized, leading to a net improvement in transcription accuracy.

## Foundational Learning
1. **ASR (Automatic Speech Recognition)**: Why needed: The core task of converting speech to text; the paper aims to improve ASR in challenging domains. Quick check: Does the system maintain performance on general speech?
2. **Whisper**: Why needed: A state-of-the-art ASR model that supports prompt-based conditioning via initial_prompt. Quick check: Is Whisper's initial_prompt effective for domain adaptation?
3. **LLM (Large Language Model)**: Why needed: Provides robust language understanding for extracting context and generating prompts. Quick check: Can GPT-4o reliably identify domain entities from noisy transcripts?
4. **Named Entity Recognition (NER)**: Why needed: To isolate proper nouns (e.g., player names) that are common in commentary and often misrecognized. Quick check: Does the NER agent achieve high recall on domain entities?
5. **Context-Aware Prompting**: Why needed: To inject domain knowledge into the ASR decoder without retraining. Quick check: Does the prompt length fit within Whisper's constraints and still help?
6. **Initial_prompt Mechanism**: Why needed: A Whisper feature that conditions decoding on a given text prefix. Quick check: How sensitive is Whisper to prompt content and length?

## Architecture Onboarding
- **Component Map**: Whisper (first pass) -> Transcript -> (Context Agent -> C, NER Agent -> N, Jargon Agent -> J) -> Merge & Compact -> Prompt -> Whisper (second pass with initial_prompt)
- **Critical Path**: The sequence from first Whisper transcription through the slowest LLM agent, merging/compaction, and the second Whisper decoding. Parallelization of the three agents reduces overall latency.
- **Design Tradeoffs**:
  - Prompt informativeness vs. length: Longer prompts may contain more context but risk truncation or dilution.
  - LLM API cost/latency vs. accuracy: Using GPT-4o yields high-quality extraction but adds ~3.3s latency and cost; local LLMs could reduce these but may lower extraction quality.
  - Two-pass decoding vs. single-pass: The pipeline requires two Whisper decodings, doubling ASR latency; future work explores single-pass integration.
- **Failure Signatures**:
  - High WER on segments where the first transcript is extremely inaccurate, leading to erroneous context extraction.
  - Segments with novel jargon or names not in the LLM's knowledge base result in uninformative prompts.
  - The 7.1% degraded segments likely stem from prompt-induced bias toward incorrect tokens.
- **First Experiments**:
  1. **Baseline Reproduction**: Run Whisper (without prompt) on a small subset to confirm base WER matches reported values.
  2. **Agent Isolation**: Evaluate each LLM agent separately by using only its extracted information to form prompts and measure individual WER impact.
  3. **Latency Profiling**: Measure end-to-end latency (including two Whisper passes and LLM calls) to identify bottlenecks for real-time deployment.

## Open Questions the Paper Calls Out
1. **Generalization to Other Domains**: Does the approach work for medical or legal transcription? Basis: Future Work lists cross-domain validation. Why unresolved: Evaluation only on NBA commentary. Resolution: Test on other dense proper noun/jargon datasets.
2. **Real-Time Low-Latency Deployment**: Can the system run without commercial LLM APIs? Basis: Future Work mentions real-time optimization. Why unresolved: Current GPT-4o adds ~3.3s latency and cost. Resolution: Implement local LLMs and parallel agents, benchmark latency and cost.
3. **Video Context Integration**: Would incorporating visual cues improve accuracy? Basis: Future Work suggests multimodal enhancement. Why unresolved: Pipeline uses only text. Resolution: Integrate video descriptions and test on video-aligned commentary.
4. **Adaptive Learning from Feedback**: Can the system adapt to evolving terminology via user feedback? Basis: Future Work includes adaptive learning. Why unresolved: Knowledge bases are static. Resolution: Add feedback loops to update lexicons and evaluate longitudinal performance.

## Limitations
- Evaluation limited to a single narrow domain (NBA commentary, 421 segments), restricting generalizability.
- No ablation studies; the contribution of each specialized agent to the 17% WER reduction is unknown.
- Performance gains are bounded by Whisper's base capabilities and its initial_prompt mechanism; effectiveness on noisy, conversational, or multi-speaker audio is unclear.

## Confidence
- **Primary Claim (17% WER Reduction)**: High. Statistically significant result with clear improvement/degradation breakdown.
- **Pipeline Design & Mechanism**: Medium. Plausible multi-agent process but lacks componentwise ablation and prompt analysis.
- **Generalizability & Superiority**: Low. No evidence for transfer to other domains or advantage over alternative adaptation methods beyond direct post-editing.

## Next Checks
1. Conduct cross-domain evaluation on at least two additional dense proper noun/jargon domains (e.g., soccer commentary, medical dictation) to measure transferability.
2. Perform a systematic ablation study by removing/isolating each agent and by using only the final generated prompt to quantify marginal contributions.
3. Compare the initial_prompt approach against lightweight fine-tuning of Whisper on a small in-domain dataset (e.g., 1-2 hours) to assess competitiveness.
