# FedGraph-VASP: Privacy-Preserving Federated Graph Learning with Post-Quantum Security for Cross-Institutional Anti-Money Laundering

## Quick Facts
- **arXiv ID:** 2601.17935  
- **Source URL:** https://arxiv.org/abs/2601.17935  
- **Reference count:** 27  
- **Primary result:** Achieves F1-score 0.508 on Elliptic Bitcoin AML detection, outperforming FedSage+ by 12.1% with post-quantum secured boundary embedding exchange.

## Executive Summary
Cross-institutional anti-money laundering (AML) faces a dilemma: siloed data misses laundering patterns that span multiple Virtual Asset Service Providers (VASPs), yet sharing raw transaction data violates privacy regulations. FedGraph-VASP proposes a federated graph learning framework where VASPs collaboratively train Graph Neural Networks without exposing sensitive data. The core method exchanges compressed, non‑invertible embeddings of “boundary” accounts (those involved in cross‑VASP transactions), secured by hybrid post‑quantum cryptography (Kyber‑512 + AES‑256‑GCM). On the Elliptic Bitcoin dataset with a realistic Louvain partitioning, FedGraph-VASP reaches an F1‑score of 0.508, a 12.1% improvement over the generative FedSage+ baseline. A privacy audit shows that reconstruction attacks on the shared embeddings yield only R² = 0.32, indicating limited feature leakage. The approach balances utility, privacy, and forward‑looking quantum security, though it incurs significant communication overhead (~18.5 MB/round) and exhibits membership inference vulnerability.

## Method Summary
FedGraph-VASP assumes multiple VASPs (clients) each holding a local transaction graph. Clients train local two‑layer GraphSAGE models to generate node embeddings. Accounts that appear in cross‑VASP transactions (boundary nodes) are identified beforehand via a Private Set Intersection (PSI) protocol. After local training, each client extracts embeddings for its boundary nodes, encrypts them using a hybrid post‑quantum scheme (Kyber for key encapsulation, AES‑256‑GCM for data encryption), and sends them along with model weight updates to a central server. The server aggregates weights via FedAvg and routes the foreign boundary embeddings back to the respective clients. Upon reception, each client decrypts the foreign embeddings and computes a **boundary alignment loss** (1 − cosine similarity) between its local boundary embedding and the received foreign embedding for the same account. This loss encourages consistent representations of shared accounts across VASPs, supplementing the standard node classification loss. The combined loss improves detection of cross‑silo laundering patterns while keeping raw transaction data on‑premise. Key hyperparameters include 128‑dimensional hidden layers, three local epochs per round, Adam optimizer (lr=0.01, weight decay=5e‑4), 50 communication rounds, and alignment loss weight λ=0.1.

## Key Results
- **F1‑score:** 0.508 on Elliptic Bitcoin dataset, a 12.1% improvement over FedSage+ (0.453).  
- **Embedding privacy:** Reconstruction adversary achieves R² = 0.32, indicating limited invertibility of shared embeddings.  
- **Communication cost:** ~18.5 MB per round (significantly higher than vanilla FedAvg’s 131 KB but considered acceptable for high‑value AML).

## Why This Works (Mechanism)

#### Mechanism 1: Boundary Embedding Exchange
FedGraph-VASP shares only compressed, non‑invertible embeddings of boundary nodes (accounts engaged in cross‑VASP transactions) instead of raw data. Each client’s local GraphSAGE generates these embeddings, which are sent to a central server and redistributed to peers. The non‑linear message‑passing of GNNs is assumed to hinder exact feature reconstruction. Evidence: the paper’s abstract and Section III.B describe the approach; empirical inversion R²=0.32 supports the privacy claim. **Break condition:** If an inversion attack achieves R² → 0.8, the core privacy guarantee collapses.

#### Mechanism 2: Hybrid Post‑Quantum Encryption
All exchanged embeddings are encrypted using a Kyber‑512 KEM combined with AES‑256‑GCM. Kyber establishes a quantum‑resistant shared secret; this secret keys AES for authenticated encryption. This KEM‑DEM hybrid protects against “harvest now, decrypt later” attacks from both classical and future quantum adversaries. Evidence: The paper’s abstract and Section III.C detail the hybrid architecture and liboqs implementation. **Break condition:** If the underlying Module Learning With Errors problem is efficiently solved by quantum computers or if AES‑256 is broken, the encryption fails.

#### Mechanism 3: Boundary Alignment Loss
After receiving foreign boundary embeddings, each client computes a cosine‑similarity loss between its local embedding and the foreign embedding for the same shared account. This alignment loss encourages consistent latent representations across VASPs, improving detection of cross‑silo laundering patterns. Evidence: Equation (2) and (3) define the loss; Table I shows FedGraph‑VASP outperforms baselines, suggesting alignment helps. **Break condition:** If reducing alignment loss does not correlate with higher F1 in ablations (e.g., λ sweep), the mechanism is ineffective.

## Architecture Onboarding
**Component map:**  
Clients: Subgraph storage → GraphSAGE GNN → Boundary node extractor → PQC encryptor.  
Server: FedAvg aggregator ↔ Routing/distribution for foreign embeddings.

**Critical path:**  
1. Client trains local GNN for E epochs.  
2. Extracts embeddings for locally known boundary nodes.  
3. Encrypts embeddings via hybrid PQC tunnel (Kyber+AES).  
4. Sends encrypted embeddings + model weights to server.  
5. Server aggregates weights via FedAvg and routes foreign embeddings back.  
6. Client decrypts foreign embeddings and computes boundary alignment loss (cosine similarity).

**Design tradeoffs:**  
- *Communication:* ~18.5 MB/round vs. FedAvg’s 131 KB; acceptable for high‑value AML.  
- *Privacy vs. utility:* Higher embedding dimensionality may improve detection but could increase inversion risk; trade‑off not fully quantified.  
- *Topology sensitivity:* Works best when cross‑silo connectivity is moderate to high (Louvain: 0.24%, METIS: 33%); performance degrades in sparse regimes.

**Failure signatures:**  
- Performance drop: F1 significantly below local training in sparse graphs (observed on Ethereum).  
- Privacy failure: Embedding inversion R² > 0.5 (current best is 0.32).  
- Convergence stall: F1 plateaus below centralized baseline (0.620) in high‑connectivity regimes.

**First 3 experiments:**  
1. Replicate main Bitcoin result: Use Elliptic dataset with Louvain partitioning (K=3) for 50 rounds; confirm F1 ≈0.508 ±0.01 over 5 seeds.  
2. Privacy audit: Train reconstruction adversary (MLP) on shared embeddings; report MSE and R² (target: R² < 0.35).  
3. Ablation on λ: Vary boundary loss weight (0.01, 0.1, 0.5) and measure F1 change; expect minimal impact (<1%) as per Table III.

## Open Questions the Paper Calls Out
- **Topology‑dependent performance:** The paper reports that embedding exchange excels on Bitcoin (connected graphs) while generative imputation (FedSage+) dominates on Ethereum (sparse graphs). The underlying structural or statistical reasons for this trade‑off (e.g., modularity, homophily) are not analyzed.  
- **Membership inference leakage:** A privacy audit shows very high MIA AUC (0.95), expected for non‑private GNNs on sparse graphs. The feasibility and utility trade‑offs of integrating differential privacy (e.g., DP‑SGD) into this cross‑silo GNN setting remain open.  
- **PSI integration:** The methodology assumes a trusted PSI coordinator for boundary identification. Replacing it with a cryptographically secure (post‑quantum) PSI protocol introduces unknown overhead and security composability issues.  
- **Extreme fragmentation:** Performance degrades as the number of clients increases (K=8), leading to very low cross‑silo connectivity. Adaptive variants of the boundary alignment loss to maintain utility in such ultra‑sparse regimes are unexplored.

## Limitations
- **PSI and server trust:** The protocol relies on an unspecified Private Set Intersection mechanism and a server capable of decrypting all embeddings; the key distribution and trust model are not detailed, hindering deployment and security analysis.  
- **Data leakage risk:** Using Louvain community detection on the full temporal graph likely introduces lookahead bias (future edges influence partitioning), potentially inflating reported performance.  
- **Baseline reproducibility:** Critical baselines (especially FedSage+) lack complete hyperparameter descriptions, preventing fair comparison and independent replication.

## Confidence
- **Detection performance (F1=0.508):** High  
- **Embedding privacy (R²=0.32):** Medium  
- **Post‑quantum security (Kyber‑512 + AES‑256‑GCM):** High
