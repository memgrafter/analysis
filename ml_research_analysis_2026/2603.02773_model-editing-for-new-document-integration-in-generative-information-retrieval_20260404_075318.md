# Model Editing for New Document Integration in Generative Information Retrieval
## Quick Facts
- **arXiv ID:** 2603.02773
- **Source URL:** https://arxiv.org/abs/2603.02773
- **Reference count:** 40
- **Primary result:** DOME matches full retraining performance on new documents (Recall@1 0.686 vs 0.693) while reducing forgetting (F_n=0.003) and adaptation time by over 40%.

## Executive Summary
Generative retrieval (GR) models, which generate document identifiers (docIDs) for retrieval, fail to generalize to newly added documents. Standard incremental training is computationally expensive and causes catastrophic forgetting of the initial collection. This paper introduces DOME, a model editing framework that efficiently integrates new documents by targeting critical decoder feed-forward network (FFN) layers and employing a hybrid-label adaptive training strategy to create discriminative edit vectors. On Natural Questions and MS-MARCO benchmarks, DOME achieves retrieval performance on new documents comparable to full model retraining while almost eliminating forgetting on the initial corpus. It also reduces adaptation time per document by over 40% and outperforms existing model editing approaches like MEMIT and AlphaEdit.

## Method Summary
DOME operates in three stages. First, it identifies the critical decoder FFN layers responsible for mapping semantic representations to docID tokens via an "average patching" analysis—replacing a layer's output with its training set average and measuring the drop in docID prediction accuracy. Typically, five consecutive middle-to-late decoder layers are selected. Second, for each new document, it generates multiple pseudo-queries and optimizes an edit vector δ for each (query, docID prefix, target token) tuple. The optimization uses a hybrid target distribution that linearly mixes the model's original output (soft label) and the one-hot ground truth (hard label), with the mixing coefficient λ increasing from 0.3 to 1.0 over 50 steps. This produces discriminative updates that preserve query-specific diversity. Third, it constructs a global update matrix Δ by assembling key-value pairs from the new edits (K1, V1) and a sample of preserved pairs (K0, V0) from the initial corpus. Δ for the final critical layer is computed via a closed-form solution that minimizes interference with K0. Updates for preceding layers are scaled by inverse layer distance and applied sequentially, with forward passes re-run to refresh keys for subsequent layers.

## Key Results
- Achieves Recall@1 of 0.686 on NQ, comparable to full retraining (0.693), with a forgetting score F_n of 0.003.
- Reduces adaptation time by over 40%, requiring 2.14 seconds per document versus 3.54s for incremental training.
- Outperforms existing model editing methods (MEMIT, AlphaEdit) on new document retrieval and forgetting mitigation.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Identifying and targeting specific decoder FFN layers (middle-to-late) is essential because these layers store the critical knowledge for mapping semantic representations to docID tokens.
**Mechanism:** The "average patching" technique replaces a layer's output with its average over the training set. A significant drop in docID token prediction accuracy after patching identifies that layer as crucial for the mapping.
**Core assumption:** The docID mapping function is hierarchically organized within the decoder, with middle-to-late FFN layers being the final stage where semantic features are transformed into discrete token predictions.
**Evidence anchors:** [abstract] "...targets critical decoder FFN layers..." [section 5.1] "...locate the crucial layers that store docID-mapping knowledge via average patching...altering their outputs significantly degrades retrieval accuracy." [section A.1, Figure 5] Patching FFN layers in the middle and final stages causes the largest drop in token prediction probability across all docID positions.
**Break condition:** If patching analysis shows no single set of layers causes a statistically significant accuracy drop, the assumption of concentrated mapping knowledge is violated, and the layer selection strategy fails.

### Mechanism 2
**Claim:** A hybrid-label adaptive training strategy creates discriminative edit vectors for new docID mappings, solving the "indistinguishable edit vectors" problem caused by limited docID vocabularies.
**Mechanism:** The training loss uses a target distribution that is a linear mix of the model's original output (soft label) and the one-hot ground truth (hard label). The mixing coefficient λ increases from a small value to 1.0. The soft component maintains query-specific diversity in the edit vectors early on; the hard component later enforces precise token generation.
**Core assumption:** Edit vectors optimized only with hard labels (one-hot) for the same target docID token collapse into similar directions because the loss gradient is identical. Injecting the model's own output distribution as a soft target preserves enough per-query variation to produce distinguishable updates.
**Evidence anchors:** [abstract] "...employs a hybrid-label adaptive training strategy that combines soft labels...with hard labels for precise docID mapping." [section 4.2] Demonstrates high cosine similarity between edit vectors for GR requests with the same target docID when using one-hot labels. [section 5.2] Details the adaptive coefficient λ and the optimization objective. [section 6.4, Figure 4] Shows the hybrid strategy reduces pairwise similarity among edit vectors sharing the same target docID.
**Break condition:** If the edit vectors for queries with different contexts but the same target docID remain highly correlated (cosine similarity >0.9) after hybrid training, the strategy fails to inject sufficient discriminative signal.

### Mechanism 3
**Claim:** Applying edits via a constrained closed-form solution that minimizes interference with preserved knowledge (K0, V0) effectively mitigates catastrophic forgetting on the initial document collection.
**Mechanism:** The update matrix Δ is computed to align new key-value pairs (K1, V1) while minimizing the norm of Δ applied to preserved key-value pairs from the original corpus (K0, V0). This is solved in closed form using a Frobenius norm objective. To further reduce interference, the Δ for the final layer is distributed across preceding layers scaled by inverse layer distance.
**Core assumption:** The original docID mapping knowledge can be sufficiently captured by a representative sample of key activations (K0) and their original outputs (V0) from the initial corpus. Modifying parameters in a direction that least disturbs the outputs for these preserved keys minimizes forgetting.
**Evidence anchors:** [abstract] "...minimizing forgetting on the initial collection (forgetting score F_n = 0.003)." [section 3.2] Presents the constrained optimization objective: `min ||(Wout+Δ)K1 - V1||^2_F + ||ΔK0||^2_F`. [section 5.3] Describes distributing the update across layers and re-running forward passes to refresh keys. [section 6.3, Table 3] DOME achieves F_n=0.003, vastly outperforming other editing methods (e.g., ROME F_n=0.317).
**Break condition:** If the forgetting score (F_n) increases monotonically with the number of new documents added, the preservation constraint (K0K0^T) is insufficient to protect the original knowledge subspace under cumulative edits.

## Foundational Learning
- **Concept: Generative Retrieval (GR)**
  - **Why needed here:** The entire paper operates within the GR paradigm where retrieval is framed as docID sequence generation. Understanding that a model's failure is specific to generating *unseen* docID tokens (not semantic understanding) is the root problem definition.
  - **Quick check question:** In GR, what is the fundamental difference between the encoder's role and the decoder's role, and which component fails when new documents are added?

- **Concept: Transformer FFN as Key-Value Memory**
  - **Why needed here:** Model editing techniques like MEMIT/ROME are predicated on the interpretation that a Transformer's FFN layer acts as a key-value store. This conceptual framework is directly imported to define the edit operation (modifying W_out to change the 'value' for a given 'key').
  - **Quick check question:** Given the equations `k = σ(W_in * h)` and `m = W_out * k`, what do the vectors `k` and `m` conceptually represent in the context of fact/knowledge editing?

- **Concept: Catastrophic Forgetting**
  - **Why needed here:** The primary motivation for avoiding incremental training is its tendency to overwrite previously learned knowledge. The paper's core value proposition is a method that integrates new knowledge *without* this forgetting. Understanding this failure mode defines the "preservation" objective.
  - **Quick check question:** Why does standard fine-tuning (incremental training) on new documents typically lead to catastrophic forgetting of the initial document collection in GR models?

## Architecture Onboarding
- **Component map:** Critical Layer Locator -> Edit Vector Optimizer -> Update Constructor & Applier
- **Critical path:** Layer Identification → Edit Vector Calculation (per new doc) → K/V Assembly for Final Layer → Δ Calculation for Final Layer → Scaled Δ for Preceding Layers → Sequential Application. The path is linear but with a feedback loop: applying an update at layer `j` requires re-forwarding through later layers to get fresh keys for their `Δ` calculations.
- **Design tradeoffs:** 
  - *Layer Range:* Editing too few layers may not inject enough capacity for new mappings; too many layers increases forgetting risk and computational cost. The paper finds middle-to-late decoder layers are optimal.
  - *Hybrid Label Schedule:* Starting λ too high loses query-specific diversity; starting too low or increasing too slowly fails to enforce hard token generation. A linear schedule from 0.3 to 1.0 over ~50 steps is chosen.
  - *Memory for Preservation:* Using `K0` from a small sample saves compute but may poorly approximate the full original knowledge subspace, leading to forgetting. The tradeoff is between efficiency and robustness.
- **Failure signatures:**
  - **Discriminability Failure:** High cosine similarity (>0.8) between edit vectors `δ_i` for different queries targeting the same docID token. Signals hybrid training isn't working.
  - **Forgetting Failure:** Significant drop (>5% absolute) in R@1/R@10 on the initial document set after adaptation. Indicates the `Δ` calculation or distribution is interfering with preserved knowledge.
  - **Capacity Failure:** Low R@1 on new documents (<0.5) despite editing. Suggests either the wrong layers were targeted, or the edit vectors `δ_i` are not strong enough to override the model's default (incorrect) predictions.
  - **Efficiency Failure:** Time per document (TPD) close to or exceeding incremental training baselines (~3.5s). Suggests the optimization or sequential application process is not streamlined.
- **First 3 experiments:**
  1. **Patching Analysis (Section 5.1, Appendix A.1):** Systematically patch (replace with average) each decoder layer's FFN/Self-Attn/Cross-Attn outputs and measure docID token prediction accuracy. This empirically justifies focusing edits on middle-to-late FFN layers.
  2. **Ablation on Hybrid-Label Strategy (Section 6.4, Table 4):** Remove the soft component ("w/o soft label") or hard component ("w/o hard label") and measure performance on new documents. This isolates the contribution of the adaptive mixing.
  3. **Scalability with Number of New Documents (Appendix A.2, Figure 6):** Incrementally add 100, 200, 300, 500, 1000 new documents and plot performance on both initial and new sets. This tests the robustness of the forgetting mitigation and the edit capacity as the task grows.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can DOME be extended to edit attention layers or encoder representations to further improve adaptation to new documents?
- **Basis in paper:** [explicit] The conclusion states: "In future work, we will focus on further improving the efficiency of the editing process and on exploring adaptation strategies for additional modules, including attention layers and encoder representations."
- **Why unresolved:** The current DOME only edits decoder FFN layers; editing other components may capture additional mapping knowledge but risks interference with existing retrieval capabilities.
- **What evidence would resolve it:** Apply DOME’s editing framework (critical layer identification, hybrid-label training) to attention or encoder modules, and evaluate retrieval performance on new documents and forgetting on the initial corpus.

### Open Question 2
- **Question:** What is the optimal number and generation method of pseudo-queries per new document for maximizing DOME’s edit vector discriminability?
- **Basis in paper:** [inferred] The ablation study (Table 4) shows performance gains when increasing pseudo-queries from 1 to 7, but does not explore beyond 7 or alternative generation strategies (beyond docTTTTTquery).
- **Why unresolved:** Pseudo-queries provide contextual signals for new documents; insufficient or low-quality queries may yield ineffective edit vectors, while excessive queries could introduce noise or computational overhead.
- **What evidence would resolve it:** Systematically vary the number of pseudo-queries (e.g., 1, 3, 5, 7, 10, 20) and compare generation methods (e.g., LLM-based, query expansion) on multiple datasets, measuring retrieval accuracy and time cost.

### Open Question 3
- **Question:** How does DOME scale to very large numbers of new documents (e.g., tens of thousands to millions) in terms of computational efficiency and retrieval effectiveness?
- **Basis in paper:** [inferred] Experiments only evaluate up to 1,000 new documents (Appendix A.2); real-world scenarios involve much larger updates, and the closed-form update (Eq. 8) may become costly.
- **Why unresolved:** The matrix operations in the update construction could grow superlinearly, and cumulative edits might increase catastrophic forgetting despite constraints.
- **What evidence would resolve it:** Run DOME with increasing new document counts (e.g., 10k, 100k, 1M) on a large corpus, measuring update time, memory usage, and performance on both initial and new collections.

### Open Question 4
- **Question:** Can the hybrid-label adaptive training strategy be effectively transferred to other model editing tasks (e.g., factual knowledge editing) where multiple contexts map to the same target?
- **Basis in paper:** [inferred] The hybrid-label strategy is designed for GR’s overlapping docID targets; other editing tasks typically have unique targets but may still face ambiguity in some cases.
- **Why unresolved:** The soft-to-hard mixing may improve edit vector diversity and precision in other settings, but its benefits and appropriate schedule are unknown outside GR.
- **What evidence would resolve it:** Implement hybrid-label editing on standard benchmarks (e.g., ZsRE, CounterFact), compare edit success, locality, and portability against one-hot editing, and analyze edit vector similarity.

## Limitations
- Critical hyperparameters for base GR training (optimizer, LR, epochs) and edit optimization (LR, steps) are unspecified, forcing assumptions that may affect reproduction fidelity.
- Implementation details (pseudo-query generation beyond docTTTTTquery, K0 sampling strategy) are not fully detailed, introducing potential sensitivity.
- The scalability boundary is untested; cumulative edits on very large new document sets may degrade forgetting mitigation despite the preservation constraint.
