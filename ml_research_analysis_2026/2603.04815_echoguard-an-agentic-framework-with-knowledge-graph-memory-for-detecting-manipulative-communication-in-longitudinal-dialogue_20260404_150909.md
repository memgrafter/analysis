# EchoGuard: An Agentic Framework with Knowledge-Graph Memory for Detecting Manipulative Communication in Longitudinal Dialogue

## Quick Facts
- **arXiv ID:** 2603.04815
- **Source URL:** https://arxiv.org/abs/2603.04815
- **Reference count:** 8
- **Primary result:** Proposes EchoGuard, an agentic framework using Knowledge Graph memory to detect subtle, longitudinal manipulative communication (e.g., gaslighting) via a Log-Analyze-Reflect loop and Socratic prompting, with evaluation planned via multi-arm RCT and ablation studies.

## Executive Summary
EchoGuard addresses a critical gap in AI-assisted detection of manipulative communication: existing systems fail to capture context-dependent, longitudinal patterns due to limited memory and stateless designs. The framework introduces a Knowledge Graph (KG) as persistent episodic memory within an agentic loop. User interactions are structured into the KG, which is queried against a semantic KG of manipulation patterns. An LLM then generates Socratic prompts grounded in the retrieved subgraph, guiding users toward self-discovery without direct labeling. The paper contributes a novel architecture and outlines a comprehensive evaluation strategy—including a randomized controlled trial and ablation studies—to isolate the effectiveness of graph-based memory and constrained prompting.

## Method Summary
The framework operates through a three-phase agentic loop. First, a Structured Logger captures user-submitted interaction logs (utterance, speaker, emotional and cognitive states) and enriches an episodic Knowledge Graph with nodes and edges. Second, a Pattern Detection Engine queries this episodic KG against a pre-defined semantic KG that encodes six manipulation tactics and their psychological markers (e.g., Gaslighting indicated by self-doubt and reality denial phrases), combining graph traversal with semantic similarity search (Sentence-BERT). Third, a Reflective Prompt Generator uses an LLM to produce Socratic prompts constrained by template rules (prohibiting diagnostic language and directives), grounded in the retrieved subgraph evidence, and adaptively tuned via user feedback. The system is designed for scalability and safety, with planned ablations to test the contributions of graph memory versus alternatives and the efficacy of prompt constraints.

## Key Results
- Novel integration of Knowledge Graph memory with an agentic loop for longitudinal manipulation detection, overcoming context window limitations.
- Hybrid pattern detection operationalizing psychological tactics via graph queries and semantic matching against curated phrase banks.
- KG-grounded Socratic prompt generation to foster user self-discovery while avoiding reactance from direct labeling.
- Comprehensive evaluation plan: multi-arm RCT with a Manipulation Recognition Task; ablation studies isolating graph memory and constrained prompting contributions.

## Why This Works (Mechanism)

### Mechanism 1: Persistent Episodic Memory via Knowledge Graph
- **Claim:** A Knowledge Graph as persistent episodic memory enables detection of context-dependent, longitudinal manipulation patterns that stateless or vector-based systems miss.
- **Mechanism:** The agent structures each user-logged interaction into a graph (nodes: events, people, emotions; edges: relationships like `participated_in`, `felt_emotion`). This graph state allows multi-hop traversal to identify patterns (e.g., intermittent reinforcement) that emerge over time, impossible from isolated utterances or finite context windows.
- **Core assumption:** Manipulation tactics are defined by relational and temporal patterns across interactions, not single utterances.
- **Evidence anchors:** Abstract and Section 2.1 state that existing agentic AI lacks structured, longitudinal memory, leading to failure due to limited context windows and catastrophic forgetting; Section 2.1 details how the persistent state S in a KG enables contextual adaptation, threshold calibration, and tool orchestration.
- **Break condition:** If manipulation tactics are primarily identifiable from single-turn linguistic cues without requiring relational history, the overhead of graph maintenance is unnecessary.

### Mechanism 2: Hybrid Pattern Detection via Semantic KG
- **Claim:** Querying the user’s episodic KG against a semantic KG of manipulation markers operationalizes psychological constructs into computable, explainable signals.
- **Mechanism:** A pre-defined semantic KG encodes tactics with psychological markers (e.g., Gaslighting `indicated_by High_Self_Doubt_Marker`, `indicated_by Reality_Denial_Marker`). The engine runs graph queries on the episodic KG to find subgraphs matching marker patterns, supplemented by semantic similarity (Sentence-BERT) against curated phrase banks, yielding weighted confidence scores per tactic.
- **Core assumption:** Psychological manipulation tactics have consistent, detectable computational signatures (e.g., emotion-phrase co-occurrence patterns) that can be formalized in a graph schema.
- **Evidence anchors:** Section 2.3 describes operationalizing six tactics via hybrid graph-based reasoning and semantic analysis; abstract mentions querying the KG against a semantic KG of patterns.
- **Break condition:** If manipulation tactics are too culturally or relationally variable to encode in a stable, generic semantic KG, pattern specificity fails, increasing false negatives.

### Mechanism 3: KG-Grounded Socratic Prompt Generation
- **Claim:** KG-grounded, constrained Socratic prompt generation scaffolds user self-discovery while maintaining safety and autonomy, avoiding reactance from direct diagnostic labeling.
- **Mechanism:** The LLM prompt generator is constrained by (1) template rules (no labels like "abuser," no directives like "leave"), (2) grounding in the retrieved subgraph (specific emotions, phrases, detected tactics), and (3) an adaptive loop that updates based on user feedback. The KG provides concise, relevant context, preventing hallucination or overgeneralization.
- **Core assumption:** Users can recognize manipulation through guided self-reflection prompted by evidence from their own history, rather than being told a verdict; this preserves agency and reduces defensiveness.
- **Evidence anchors:** Section 2.4 details the three-layer constraint architecture prohibiting diagnostic language and LLM grounding with structured data; abstract describes generating targeted Socratic prompts grounded by the subgraph.
- **Break condition:** If users in distress require explicit, direct labeling to break awareness gaps effectively, the Socratic approach is too slow or ambiguous, increasing risk.

## Foundational Learning
- **Knowledge Graph (Graph Database) Fundamentals:** Needed to correctly model interactions as nodes/edges and execute multi-hop queries (e.g., "find all interactions where user felt Self-Doubt after a Reality_Denial phrase from Person_X"). *Quick check:* How would you design node and edge types to connect an `Interaction_Event` node to both a `Person` node and an `Emotion` node, and what property stores the utterance text?
- **Agentic Loop (ReAct-style Tool Orchestration):** Needed because the agent autonomously cycles through Log → Analyze → Reflect, selecting tools based on its current graph state. *Quick check:* In the Log-Analyze-Reflect loop, what condition in the KG state would cause the agent to prioritize the Pattern Detection Engine over the Structured Logger for the next user action?
- **Psychological Manipulation Taxonomies:** Needed because the semantic KG’s pattern definitions (e.g., Gaslighting vs. Guilt Induction markers) are the detection ground truth. *Quick check:* What is a key computational difference in the graph pattern for "Emotional Blackmail" (threat of withdrawal) versus "Guilt Induction" (invocation of obligation)?

## Architecture Onboarding
- **Component map:** User Input -> Structured Logger -> Episodic KG Store -> Pattern Detection Engine -> Reflective Prompt Generator -> User Output; Semantic KG Store (static) referenced by Pattern Detection Engine; Adaptive Feedback Loop updates detection thresholds and prompt style based on user feedback.
- **Critical path:** User submits log → Logger creates graph nodes/edges → Agent queries Detection Engine (using semantic KG patterns) → Engine returns matched subgraph + confidence → Prompt Generator creates constrained, grounded question → User receives prompt → User feedback updates agent state/thresholds.
- **Design tradeoffs:**
  - *KG expressiveness vs. construction cost:* Richer schema captures more nuance but requires more logging effort and complex queries.
  - *LLM grounding vs. flexibility:* Strict KG grounding ensures safety/relevance but may miss context not in the graph; more LLM freedom risks unsafe outputs.
  - *Pattern specificity vs. cultural validity:* Six tactics are Western psychology-based; overfitting reduces cross-cultural applicability.
- **Failure signatures:**
  - *False Positive Cascade:* Overly sensitive detection + ungrounded LLM leads to prompts labeling healthy assertiveness as manipulation.
  - *Graph Sparsity Failure:* New user with few logs → KG too sparse for multi-hop queries → falls back to ineffective single-turn analysis.
  - *Prompt Hallucination:* Even with grounding, LLM generates unsafe advice or diagnostic labels if system prompt is weak.
- **First 3 experiments:**
  1. KG vs. Vector Store Baseline: Implement vector database (e.g., Pinecone) for episodic memory instead of KG. Run both on vignettes requiring longitudinal reasoning (e.g., "intermittent reinforcement"). Measure precision/recall for tactic detection.
  2. Ablation: Prompt Constraint Efficacy: Compare full EchoGuard vs. variant removing "no diagnostic labels" constraint. Measure user-reported reactance (survey) and willingness to continue.
  3. Scalability Stress Test: Populate a single user’s episodic KG with 1,000+ interaction nodes. Measure query latency for multi-hop pattern matching (e.g., "find all Emotion:Self-Doubt nodes within 3 hops of a Reality_Denial phrase from the same person"). Identify bottlenecks.

## Open Questions the Paper Calls Out
1. **Does the full EchoGuard framework significantly improve users' ability to recognize manipulative communication compared to control conditions in a randomized controlled trial?**  
   *Basis:* Explicitly planned multi-arm RCT with primary outcome via Manipulation Recognition Task (Section 3.1).  
   *Why unresolved:* Evaluation strategy proposed but not executed; efficacy data pending.  
   *Resolution evidence:* Statistical results from RCT showing significantly higher recognition scores for full EchoGuard versus controls.

2. **How does the Knowledge Graph-based episodic memory compare to alternative memory systems (e.g., vector databases) in detecting longitudinal manipulation patterns?**  
   *Basis:* Inferred from planned ablation studies and baseline comparisons to isolate graph memory contributions (Sections 3.2, 3.3).  
   *Why unresolved:* Comparative studies not yet performed; no empirical data on memory trade-offs.  
   *Resolution evidence:* Results from ablation experiments quantifying detection accuracy, efficiency, and scalability of KG memory versus alternatives.

3. **Are the manipulation patterns defined in the semantic KG culturally universal, or do they require significant adaptation for different cultural contexts?**  
   *Basis:* Inferred from acknowledgment that patterns derive from Western psychology and need "significant cultural specificity validation" (Section 4, Conclusion).  
   *Why unresolved:* No cross-cultural validation conducted; cultural generalizability is an assumption.  
   *Resolution evidence:* Empirical validation across diverse cultural groups measuring pattern detection accuracy and user perceived relevance.

4. **What is the false positive rate in EchoGuard's detection, and how do these incidents correlate with user distress or safety outcomes?**  
   *Basis:* Explicitly identifies false positives as a "primary concern" and plans Failure Mode Analysis (Section 4, 3.4).  
   *Why unresolved:* Failure mode analysis proposed; false positive rates and psychological impact unknown.  
   *Resolution evidence:* Data from failure mode analysis reporting false positive frequencies from RCT, correlated with user-reported distress/anxiety.

5. **To what extent do KG-grounded Socratic prompts foster user self-discovery of manipulation tactics without inducing psychological reactance, compared to generic or ungrounded prompts?**  
   *Basis:* Inferred from framework emphasis on KG-grounded prompts for self-discovery and avoidance of reactance (Section 2.4), and ablation studies comparing prompt methods (Section 3.3).  
   *Why unresolved:* Efficacy of grounding versus other strategies not empirically tested; relies on theoretical design.  
   *Resolution evidence:* User study results from ablation conditions measuring self-discovery indicators (insight depth, engagement) and reactance indicators (defensiveness, drop-off).

## Limitations
- Operational definitions of the six manipulation tactics and their semantic phrase banks in the static KG are unspecified, risking pattern detection validity.
- Precise formulation of the three-layer prompt constraint architecture and adaptive feedback rules is unclear, limiting reproducibility and safety guarantees.
- Heavy reliance on a niche corpus (average neighbor FMR 0.545, low citations) raises questions about generalizability across cultural or relational contexts.

## Confidence
- Semantic KG specification (tactics and phrase banks): **Low**
- Prompt constraint architecture and adaptive rules: **Medium**
- Cross-cultural applicability of pattern definitions: **Medium**

## Next Checks
1. **Semantic KG Validation:** Conduct expert elicitation with clinical psychologists to review and refine the six tactic schemas and phrase banks, ensuring psychological validity and reducing false negatives.
2. **Prompt Constraint Efficacy Trial:** Run a within-subjects study comparing the constrained Socratic prompt generator against an unconstrained version, measuring user reactance (via survey) and self-reported insight gain.
3. **Cross-Domain Generalizability Test:** Evaluate the full framework on a hold-out dialogue corpus from a different domain (e.g., customer service vs. personal relationships) to isolate overfitting to the original dataset’s context.
