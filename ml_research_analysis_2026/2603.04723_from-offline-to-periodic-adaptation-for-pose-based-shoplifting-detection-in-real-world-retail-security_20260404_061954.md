# From Offline to Periodic Adaptation for Pose-Based Shoplifting Detection in Real-world Retail Security

## Quick Facts
- arXiv ID: 2603.04723
- Source URL: https://arxiv.org/abs/2603.04723
- Reference count: 40
- Periodic adaptation with pose-based anomaly detection outperforms offline baselines in 91.6% of evaluations on standard metrics.

## Executive Summary
Retail security systems face significant challenges in scalability, privacy preservation, and performance degradation due to domain drift over time. This paper introduces a pose-based unsupervised anomaly detection framework designed for deployment on IoT edge devices. The system processes streaming video, uses adaptive thresholds to filter frames, accumulates pseudo-normal data across multiple cameras, and incrementally retrains the model at fixed intervals. A new large-scale multi-camera dataset, RetailS, containing both staged and real-world incidents, is introduced for evaluation. Experimental results demonstrate that periodic adaptation, particularly with half-day update cycles, substantially improves detection performance compared to static offline models while remaining computationally feasible for edge hardware.

## Method Summary
The proposed pipeline operates in two phases: real-time inference and periodic adaptation. During inference, video frames are processed to extract human body poses, which are scored by an unsupervised anomaly detector (e.g., a pose autoencoder). An adaptive thresholding mechanism, optimized via the H_PRS metric (harmonic mean of precision, recall, and specificity), filters out high-scoring (likely normal) frames. These filtered pseudo-normal samples are stored in a shared buffer across cameras. Periodically (e.g., twice daily), the system retrains the anomaly detection model using the accumulated pseudo-normal data, producing an updated model deployed back to the edge. This closed-loop process aims to adapt to gradual environmental changes (lighting, layout, typical customer behavior) without requiring labeled anomaly data.

## Key Results
- Periodic adaptation (half-day cycles) beats offline baselines in 91.6% of AUC-ROC and AUC-PR evaluations on the RetailS dataset.
- Model retraining completes in under 30 minutes on edge hardware, enabling practical deployment.
- Threshold optimization with H_PRS significantly reduces false alarm rates compared to fixed thresholds.
- Half-day update cycles consistently outperform daily cycles, suggesting more frequent adaptation better counters domain drift.

## Why This Works (Mechanism)
The framework addresses domain drift by periodically updating the model’s definition of "normal" using continuously collected, unlabeled pseudo-normal samples from the operational environment. This feedback loop allows the system to acclimate to slow changes in scene geometry, illumination, and typical customer movements without manual relabeling. The pose-based representation focuses on skeletal structure, enhancing privacy by avoiding raw pixel data and providing invariance to clothing and appearance. Adaptive thresholds, tuned to balance precision and recall, mitigate false positives from benign but uncommon activities. The multi-camera pseudo-normal pooling increases data diversity and robustness compared to per-camera isolation.

## Architecture Onboarding
**Component Map**: Video Stream -> Pose Extractor -> Anomaly Scorer -> Adaptive Filter -> Pseudo-Normal Buffer -> Periodic Retrainer -> Updated Model

**Critical Path**: The real-time inference path (Pose Extractor -> Anomaly Scorer -> Adaptive Filter) must maintain low latency for live detection. The periodic retraining path (Pseudo-Normal Buffer -> Periodic Retrainer -> Updated Model) operates in the background, updating the Anomaly Scorer parameters and potentially the Adaptive Filter thresholds. The buffer aggregates data across all camera feeds to build a richer normality model.

**Design Tradeoffs**:
- **Latency vs. Accuracy**: More complex pose models improve detection but increase per-frame processing time on edge hardware.
- **Freshness vs. Stability**: Shorter adaptation cycles react faster to drift but risk overfitting to transient noise; longer cycles are more stable but may lag.
- **Pseudo-normal Purity**: Aggressive filtering (high threshold) yields cleaner normal data but reduces buffer growth rate; permissive filtering increases data volume but risks including anomalies.

**Failure Signatures**:
- **Spike in false positives**: May indicate threshold too low, or new benign activity mislabeled as anomalous by the current model.
- **Spike in false negatives**: May indicate model drifted too far (pseudo-normal buffer contaminated with anomalies) or threshold too high.
- **Stagnant performance**: Adaptation cycle may be too infrequent, or buffer diversity insufficient to capture new normality patterns.
- **Edge resource exhaustion**: Retraining takes too long, causing service interruption; may require cycle lengthening or model simplification.

**First Three Experiments**:
1. **Baseline pose extraction validation**: Run a standard pose estimator (e.g., HRNet) on sample RetailS footage to verify keypoint accuracy and frame processing rate on target edge hardware.
2. **Offline model bootstrapping**: Train an initial anomaly detector (pose autoencoder) on a small, manually verified normal dataset; evaluate its clean-test AUC-ROC/AUC-PR to establish a pre-adaptation baseline.
3. **Simulated drift detection**: Inject a controlled change (e.g., camera angle shift, new mannequin) into a test video stream; observe degradation in offline model performance and measure how many adaptation cycles are needed for recovery.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: Does the periodic adaptation framework generalize to new retail stores?
- Basis in paper: [explicit] RetailS dataset is from a single store; cross-store evaluation not performed.
- Why unresolved: Multi-store deployments are typical; transferability of adaptations is unknown.
- What evidence would resolve it: Deploy and evaluate on at least two other retail locations; measure performance drop and adaptation speed.

### Open Question 2
- Question: Over long-term use, does pseudo-normal sample accumulation bias the model and increase false negatives?
- Basis in paper: [explicit] The pipeline filters frames with low anomaly scores to form pseudo-normal training data (Sec. III-B); long-term effects are not analyzed.
- Why unresolved: The feedback loop may exclude rare normal patterns, narrowing the normality concept and causing false negatives.
- What evidence would resolve it: Track buffer diversity (e.g., pose clusters) across many cycles and correlate with false negative rate; test diversity preservation methods.

### Open Question 3
- Question: Can adaptive update scheduling (drift-triggered) outperform fixed half-day/daily intervals?
- Basis in paper: [inferred] Only fixed half-day and daily frequencies are evaluated; adaptive triggers are unstudied.
- Why unresolved: Fixed intervals may waste computation or miss rapid drifts; adaptivity could optimize the trade-off.
- What evidence would resolve it: Implement drift detection (e.g., error trends) to trigger updates; compare AUC, FPR, and compute cost against fixed schedules over long-term.

### Open Question 4
- Question: What other domain adaptation mechanisms (e.g., adversarial, meta-learning) are effective for streaming IoT anomaly detection?
- Basis in paper: [explicit] Related Work states: “explicit mechanisms for domain adaptation in streaming IoT contexts remain underexplored.”
- Why unresolved: Periodic retraining may not be optimal; alternatives might offer finer-grained adaptation or better stability.
- What evidence would resolve it: Integrate alternative methods (e.g., adversarial, meta-learning) into the pipeline and benchmark against periodic retraining using standard metrics.

## Limitations
- The RetailS dataset originates from a single store, limiting claims about cross-environment generalization.
- The reported "91.6% of evaluations" statistic lacks clarity on the number of splits, baselines, or metrics involved.
- Edge training time is given without hardware specifications (CPU/GPU, RAM), hindering assessment of broad feasibility.
- The pseudo-normal collection strategy risks including anomalous poses, potentially biasing the model over time.

## Confidence
- **Periodic adaptation superiority** (AUC-ROC/AUC-PR): **High** (standard metrics, consistent improvements reported).
- **Efficient edge training & optimal half-day cycles**: **Medium** (missing hardware details, unclear experimental conditions for cycle comparison).
- **H_PRS threshold optimization** (false alarm reduction): **Medium** (claim made but not quantitatively vs. alternatives).
- **RetailS dataset contribution** (large-scale multi-camera retail anomaly): **Medium** (similar existing datasets question uniqueness).

## Next Checks
1. **Cross-dataset validation**: Test the framework on a publicly available alternative retail pose anomaly dataset to evaluate generalization beyond a single store environment.
2. **Ablation on pseudo-normal contamination**: Systematically inject known anomalies into the pseudo-normal buffer at varying proportions to measure impact on detection performance and false negative rates.
3. **Statistical significance testing**: Perform paired statistical tests (e.g., t-tests) across multiple random data splits to confirm that observed AUC improvements are statistically significant (p < 0.05).
