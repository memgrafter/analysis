# Counterfactual Maps: What They Are and How to Find Them

## Quick Facts
- arXiv ID: 2602.09128
- Source URL: https://arxiv.org/abs/2602.09128
- Reference count: 39
- Primary result: A method for globally optimal counterfactual explanations for tree ensembles that achieves millisecond query latency after one-time preprocessing, is orders of magnitude faster than exact methods, and consistently returns optimal solutions.

## Executive Summary
This paper introduces an efficient method for generating globally optimal counterfactual explanations for tree ensemble models. The core idea is to precompute a "counterfactual map" by extracting the ensemble's equivalent partition into labeled axis-aligned hyperrectangles and indexing each target class's regions with a volumetric KD-tree. At query time, a branch-and-bound search over the KD-tree identifies the nearest hyperrectangle of the desired class, and projecting the input onto it yields an optimal counterfactual. Empirical results on high-stakes datasets show that after a one-time preprocessing, the approach achieves millisecond-level query latency, is orders of magnitude faster than state-of-the-art exact methods, and consistently returns optimal solutions. In contrast, heuristic methods often fail to find feasible counterfactuals or return suboptimal ones.

## Method Summary
The method consists of two phases: preprocessing and query. In preprocessing, the tree ensemble is compressed into an equivalent partition of axis-aligned hyperrectangles, each with a constant prediction, using a heuristic "born-again" extraction. For each target class, the set of hyperrectangles predicting that class is indexed with a volumetric KD-tree that stores bounding boxes for subtrees. During a query, given an input point and a desired target class, a branch-and-bound search traverses the KD-tree to find the nearest hyperrectangle of that class. The optimal counterfactual is obtained by projecting the input onto that hyperrectangle via coordinate-wise clamping. The preprocessing is a one-time cost; subsequent queries run in sublinear time on average.

## Key Results
- Millisecond query latency after one-time preprocessing.
- Orders of magnitude faster than exact methods (e.g., OCEAN).
- Consistently returns optimal solutions; heuristics often fail or return up to 10× suboptimal.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A trained tree ensemble’s decision function can be exactly represented as a finite, disjoint set of axis-aligned hyperrectangles, each labeled with a constant prediction.
- **Mechanism:** The “born-again tree” extraction (Vidal & Schiffer, 2020) intersects the split conditions across all trees to construct this equivalent rectangular partition. This transforms the model from an ensemble of paths into a single, explicit geometric partition.
- **Core assumption:** The extraction algorithm (heuristic variant) produces a partition that is *globally faithful* to the original ensemble’s predictions without requiring a minimal (exponentially large) set of rectangles.
- **Evidence anchors:**
  - [abstract]: “any tree ensemble can be compressed into an equivalent partition of labeled hyperrectangles”
  - [section 2]: Formal definition of the partition **H** and the claim of faithfulness.
  - [corpus]: Weak direct evidence; neighboring papers discuss tree ensembles but not this specific compression.
- **Break condition:** Extraction fails or produces a partition that is too large to index efficiently, stated as a preprocessing bottleneck in Section 6.

### Mechanism 2
- **Claim:** A globally optimal counterfactual for a query point **x** targeting class **y’** is obtained by projecting **x** onto its nearest hyperrectangle in the set **Hy’** under the chosen distance metric **dp**.
- **Mechanism:** This redefines counterfactual search as a nearest-region problem. The optimal counterfactual’s distance is `dp(x, H⋆)` where `H⋆ ∈ argmin_{H ∈ Hy’} dp(x, H)`. Projection `Π_H(x)` is a closed-form, coordinate-wise clamp to the hyperrectangle bounds.
- **Core assumption:** The piecewise-constant nature of the ensemble means the search for minimal change is confined to moving **x** into the closest region of the target class; no intermediate points outside these regions can be optimal.
- **Evidence anchors:**
  - [abstract]: “optimal counterfactual for a point corresponds to its projection onto the nearest rectangle with an alternative label”
  - [section 2]: Definition 2.1 formalizes the counterfactual map `ˆfy’` as identifying this nearest region.
  - [corpus]: Neighbors discuss counterfactuals but not this specific geometric nearest-region framing for ensembles.
- **Break condition:** For **p=2**, the Voronoi boundaries are non-polyhedral (Proposition 2.2), but the branch-and-bound search remains valid. A break would occur if the projection formula were invalid for mixed feature types, though the paper handles scaling.

### Mechanism 3
- **Claim:** A volumetric KD-tree indexed by the hyperrectangles of each target class **y’** supports exact, sublinear nearest-region queries via branch-and-bound, enabling millisecond query latency after a one-time preprocessing.
- **Mechanism:** The KD-tree stores bounding boxes for subtree regions. During a query, a priority queue explores nodes in order of increasing lower bound `dp(x, bounding_box)`. If a node’s bound exceeds the best-found distance, its entire subtree is pruned without losing the optimal solution.
- **Core assumption:** The lower bound `dp(x, B(v))` is admissible (never overestimates the distance to any hyperrectangle in the subtree), which holds because `B(v)` contains all rectangles in its subtree.
- **Evidence anchors:**
  - [section 3.2]: Describes the branch-and-bound traversal and Lemma C.2 proving the bound (`lb(v) ≤ dp(x, H)` for `H ∈ H(v)`).
  - [section 3.2, Theorem 3.1]: Asserts correctness and global optimality of the query algorithm.
  - [corpus]: KD-trees are standard for spatial search, but this volumetric application to hyperrectangle sets is novel per paper’s claim.
- **Break condition:** The KD-tree becomes highly unbalanced (e.g., many rectangles clustered in one subset), degrading query time toward linear. The amortization assumption (one-time cost offset by many queries) fails if few counterfactuals are requested.

## Foundational Learning
- **Concept: Piecewise-constant functions & hyperrectangular partitions**
  - *Why needed here:* The entire method rests on the model’s output being constant over axis-aligned hyperrectangles. Understanding this geometry is essential to see why projection yields optimal counterfactuals.
  - *Quick check question:* “If a random forest’s prediction is constant over a hyperrectangle, what is the minimal-L1 change to flip the prediction from that region?”

- **Concept: Nearest-neighbor/nearest-region search**
  - *Why needed here:* The counterfactual map is a nearest-region oracle. The KD-tree algorithm is a specialized form of branch-and-bound nearest-neighbor search adapted to regions (sets), not points.
  - *Quick check question:* “How does a branch-and-bound search use lower bounds to prune a search space without missing the true nearest neighbor?”

- **Concept: Born-again tree ensemble extraction**
  - *Why needed here:* This is the preprocessing algorithm that converts the forest into the hyperrectangle partition **H**. Without it, the KD-tree index cannot be built.
  - *Quick check question:* “What is the key trade-off in Vidal & Schiffer’s heuristic extraction versus the dynamic programming approach?”

## Architecture Onboarding

### Component Map
Preprocessing: (a) Extract partition **H** from forest using born-again heuristic. (b) For each class **y’**, build volumetric KD-tree over rectangles in **Hy’**.
Query: (a) Given query point **x** and target **y’**, traverse KD-tree for **Hy’**. (b) Find nearest rectangle `H⋆` via branch-and-bound. (c) Return projection `Π_H⋆(x)`.

### Critical Path
- *Preprocessing:* Rectangle extraction → KD-tree construction (per class). Extraction can dominate time for deep/large forests.
- *Query:* Traverse KD-tree → Compare bounding box bounds → Evaluate leaf rectangles → Project. Traversal depth is logarithmic on average.

### Design Tradeoffs
- *Extraction minimality vs. speed:* Minimal partition (DP) has fewer rectangles but costly extraction; heuristic is faster but may yield more rectangles, increasing KD-tree size.
- *Distance metric:* L∞ yields tighter bounds and faster pruning; L1/L2 may visit more nodes. Choice affects user-facing recourse cost.
- *Memory vs. latency:* Storing all rectangles explicitly in leaves uses more memory but avoids recomputation. KD-tree node bounding boxes must be precise to avoid over-pruning.

### Failure Signatures
- *Incorrect counterfactual:* Check that `Π_H⋆(x)` lies within `H⋆` and that the ensemble predicts `y’` at that point. Failure indicates a non-faithful partition extraction.
- *Slow query:* Profiling shows high node visitation count, suggesting poor KD-tree balance or loose bounds. Could also indicate `Hy’` is very large.
- *No feasible counterfactual:* The query algorithm may return `H⋆=null` only if `Hy’` is empty (no region with target class), not due to search failure.

### First 3 Experiments
1. *Correctness Validation:* For a small synthetic forest, enumerate all hyperrectangles and brute-force compute optimal counterfactuals. Compare against CF-Maps output to verify identical distances and projections.
2. *Latency Benchmark:* Time CF-Maps query (post-preprocessing) vs. OCEAN (cold-start) for 1000 random queries on a medium forest (e.g., 50 trees, depth 7). Verify subsecond vs. seconds/minutes scaling.
3. *Scalability Stress Test:* Vary forest size (trees: 10→100) and depth (3→10). Measure preprocessing time, KD-tree size, and query latency. Confirm that CF-Maps’ query time grows slowly (sublinear) while OCEAN’s grows superlinearly.

## Limitations
- Heuristic extraction may produce larger-than-minimal partitions, increasing KD-tree size and preprocessing time; fidelity to minimal partition not quantified.
- Query efficiency is metric-dependent; L1/L2 may degrade to near-linear time in high dimensions.
- Assumes continuous, scaled features; robustness to categorical, missing, or sparse data is unaddressed.
- Preprocessing amortization requires many queries; low-volume use cases may still be slower than heuristics.

## Confidence
- Hyperrectangle representation & projection optimality: High
- Branch-and-bound correctness & global optimality: High
- Practical scalability & millisecond latency claims: Medium

## Next Checks
1. Heuristic extraction fidelity: On a suite of synthetic forests with known minimal partitions, compare the heuristic’s rectangle count and coverage against the dynamic programming oracle. Quantify any over-partitioning and its correlation with forest depth/size.
2. Metric sensitivity benchmark: For fixed forests, measure average node visitation count and query latency under L1, L2, and L∞ on high-dimensional datasets (d>20). Validate the claim that L∞ pruning is substantially tighter.
3. Categorical feature stress test: Extend the method using common encodings (e.g., one-hot) and re-run latency/optimality tests. Check if the axis-aligned assumption breaks down (e.g., via encoded feature interactions) and whether projected counterfactuals remain feasible/optimal.
