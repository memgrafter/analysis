# Preference-Aligned LoRA Merging: Preserving Subspace Coverage and Addressing Directional Anisotropy

## Quick Facts
- **ArXiv ID:** 2603.26299
- **Source URL:** https://arxiv.org/abs/2603.26299
- **Reference count:** 40
- **Primary result:** TARA consistently outperforms prior merging methods across vision and NLI benchmarks by preserving LoRA subspace coverage and reweighting directions to mitigate anisotropy, achieving up to 76.3% normalized accuracy on vision tasks.

## Executive Summary
Merging multiple Low-Rank Adaptation (LoRA) adapters into a single model is challenging because naive merging causes destructive interference, collapsing task-specific directions and creating imbalanced influence (anisotropy). This paper introduces TARA, a method that maintains the full span of LoRA subspaces—either by retaining all rank-1 factors or by constructing a shared SVD basis—and learns direction-wise coefficients to balance sensitivity across tasks. Optimization uses a smooth Tchebycheff scalarization guided by a preference vector and a pseudo-loss computed from calibration data. Experiments on CLIP (vision) and LLaMA-3 (NLI) show that TARA surpasses both generic and LoRA-aware merging baselines, yielding higher average task performance, better joint-task retrieval, and stronger generalization to unseen tasks, with only modest computational overhead.

## Method Summary
TARA addresses LoRA merging in two stages. First, it preserves subspace coverage by either (Variant A) stacking all rank-1 factors from each adapter or (Variant B) projecting concatenated task updates onto a shared orthonormal basis via SVD. Second, it learns a weight ϕ for each direction to mitigate anisotropy—where some directions dominate the loss response—by minimizing a smooth Tchebycheff scalarization of per-task pseudo-losses (predictive entropy on calibration data). User preferences ρ weight the scalarization, and anchors zᵢ are the solo-task losses. The merged weight update is W = W₀ + Σ ϕₖ Sₖ. Optimization uses AdamW on ϕ, requiring only a small calibration set per task.

## Key Results
- On eight vision benchmarks, TARA Variant B achieves 76.3% average normalized accuracy vs. AdaMerging’s 70.0%.
- On six NLI benchmarks, Variant B reaches 80.3% vs. AdaMerging’s 78.7%.
- Joint‑task Hits@5 improves to 85.1%, with better generalization to unseen tasks.
- Both variants show robust performance across preference sweeps, tracing smooth Pareto fronts while baselines remain suboptimal.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Preserving individual LoRA rank-1 directions or a shared SVD basis prevents collapse of the merged model’s effective subspace rank, maintaining task-specific representational capacity.
- **Mechanism:** Instead of merging full task vectors ΔWᵢ = BᵢAᵢᵀ (which causes destructive interference), TARA retains all rank-1 factors bᵢⱼaᵢⱼᵀ (Variant A) or projects concatenated ΔWᵢ onto an SVD basis (Variant B). This preserves the span of LoRA directions from all tasks.
- **Core assumption:** LoRA adapters for different tasks occupy low-dimensional, weakly aligned subspaces; collapsing them into a single vector discards independent directions.
- **Evidence anchors:** Abstract: “preserving subspace coverage by either retaining individual rank‑1 LoRA factors (Variant A) or constructing a shared SVD basis (Variant B)”. Section 3.2: erank analysis shows Rank‑1 stack retains ~70% of per‑task sum vs. collapse in ΔW stack. Section 4: Variant B computes SVD on X = [ΔW₁,...,ΔWₙ] and builds per-task components Sᵢₖ = σₖ uₖ vₖᵢᵀ.
- **Break condition:** If tasks are highly similar and their LoRA subspaces already strongly overlap, Variant B’s SVD cost may outweigh benefits over Variant A.

### Mechanism 2
- **Claim:** Direction-wise reweighting of LoRA components mitigates anisotropy—the imbalance where some low-rank directions dominate the loss response—aligning model sensitivity with task preferences.
- **Mechanism:** TARA learns a coefficient ϕ per direction (Variant A: per rank‑1 factor; Variant B: per shared basis component). The smooth Tchebycheff objective adjusts ϕ to balance influence across tasks per preferences, effectively reducing the condition number of the task-loss Jacobian restricted to the LoRA span.
- **Core assumption:** The mapping from LoRA direction coefficients ϕ to task loss changes Δf is anisotropic (high κ(J)), so equal scaling harms some tasks more than others.
- **Evidence anchors:** Section 3.3: Proposition 1 gives anisotropy bound σ_min(J)||ϕ||₂ ≤ ||Jϕ||₂ ≤ σ_max(J)||ϕ||₂. Empirical spectra show large κ(J). Section 4: Merged model W(ϕ) uses directional weights; optimizing Ψ(ϕ,ρ) aligns ϕ with preference‑weighted gradient g(ρ;W).
- **Break condition:** If all task losses respond proportionally to all LoRA directions (isotropic Jacobian, κ(J) ≈ 1), uniform averaging suffices.

### Mechanism 3
- **Claim:** Smooth Tchebycheff scalarization (Ψ) enables learning direction weights that honor user preferences by balancing worst‑case task performance while avoiding hard Pareto optimization pitfalls.
- **Mechanism:** Ψ aggregates task pseudo‑losses via exp(ρᵢ |fᵢ − zᵢ| / α). Temperature α controls smoothing: small α prioritizes laggards (Chebyshev‑like), large α approximates weighted sum. Anchors zᵢ are solo-task entropy losses.
- **Core assumption:** A smooth scalarization yields a model on/near the Pareto front, and entropy pseudo‑loss approximates true task loss without ground‑truth labels during merging.
- **Evidence anchors:** Abstract: “smooth Tchebycheff scalarization incorporates user task preferences”. Section 4: Eq. (16) defines Ψ(ϕ,ρ); zᵢ are entropy losses from individual adapters. Section 5.1: Comparisons to AdaMerging show TARA achieves higher averages, indicating effective preference alignment.
- **Break condition:** If entropy pseudo‑loss poorly correlates with true task loss, learned ϕ may misalign with actual performance.

## Foundational Learning
- **Concept: Effective Rank (erank)**
  - *Why needed here:* Measures true dimensionality of the LoRA subspace. High erank indicates broad, non‑redundant direction coverage; a drop after merging signals collapse.
  - *Quick check:* If merging eight LoRA adapters, the erank of their combined rank‑1 stack is 80% of the sum of individual eranks. Does this indicate strong coverage or collapse?
- **Concept: Task‑Loss Jacobian Anisotropy**
  - *Why needed here:* The Jacobian J maps small LoRA direction perturbations to task loss changes. Its condition number κ(J) quantifies anisotropic sensitivity—key to understanding why uniform merging hurts some tasks more.
  - *Quick check:* If σ_max(J)=10.0 and σ_min(J)=0.1, what is the range of possible loss change ratios for two directions with equal coefficient magnitude?
- **Concept: Smooth Tchebycheff Scalarization**
  - *Why needed here:* Converts a multi‑task preference vector ρ into a single scalar objective optimizable with gradient methods. Smoothing parameter α trades off worst‑task focus (small α) vs. balanced averaging (large α).
  - *Quick check:* As α → ∞, how does Ψ(ϕ,ρ) relate to a simple weighted sum of task losses?

## Architecture Onboarding
Component map: LoRA Adopters (Bᵢ,Aᵢ) -> Direction Builder (Variant A: stack rank‑1 factors; Variant B: SVD on concatenated ΔWᵢ) -> Direction Weights ϕ -> Merged Weights W(ϕ)=W₀+ΣϕₖSₖ -> Optimizer (AdamW on Ψ) -> Final Merged Model.

Critical path:
1. Load each task’s LoRA (Bᵢ,Aᵢ). Compute either all rank‑1 factors bᵢⱼaᵢⱼᵀ or concatenated ΔWᵢ.
2. For Variant B: compute SVD of concatenated ΔWᵢ to get shared uₖ, σₖ, vₖᵢ.
3. Build direction set {Sₖ}; initialize ϕ (e.g., 0.4).
4. For T iterations: forward merged model on calibration batch; compute per‑task entropy; aggregate into Ψ; back‑propagate to update ϕ.
5. Construct final W = W₀ + ΣϕₖSₖ.

Design tradeoffs:
- Variant A: Lower memory/compute; may retain finer task info but suffers more cross‑task interference.
- Variant B: Higher upfront SVD cost; better global interference reduction, typically higher final accuracy.
- α: Small α emphasizes worst‑task performance (robust but potentially unbalanced); large α yields smoother trade‑offs. Paper finds stability for α ≥ 0.5.
- Training iterations: Both benefit from more updates (500 shown); Variant B plateaus earlier (~250 iterations).

Failure signatures:
- Subspace collapse: erank(Rank‑1 stack) − erank(ΔW stack) large after merging indicates destructive interference not mitigated.
- Anisotropy mismatch: Directional sensitivity profiles h(ρ;W) for different ρ remain highly misaligned (high ξ) after optimization → preference not respected.
- Convergence to poor fixed points: Optimization stagnates with high validation entropy; ϕ stops changing but pseudo‑loss remains elevated → learning rate/initialization issue.
- Memory blowup: Variant B SVD on large concatenated matrix may OOM; fallback to Variant A or block‑wise SVD.

First 3 experiments:
1. Validate subspace retention: Compute erank of merged LoRA directions (final ϕ). Should be close to pre‑merge Rank‑1 stack’s erank.
2. Test anisotropy reduction: Estimate task‑loss Jacobian condition number κ for merged model under varied ρ. Should be lower than Task Arithmetic baseline.
3. Benchmark preference sweep: Select two diverse tasks, vary ρ along simplex, plot joint accuracy. TARA should trace a smooth Pareto curve; baselines cluster at suboptimal points.

## Limitations
- Calibration set size and source unspecified (assumed 500 samples from training split).
- Variant B’s SVD retention threshold (total rank R) not fixed; may affect subspace coverage.
- Predictive entropy pseudo‑loss correlation with true task loss unvalidated for all data types.
- Assumption of weakly aligned LoRA subspaces may fail for highly similar tasks, reducing Variant B’s benefit.

## Confidence
- Subspace preservation (Mechanism 1): High. Empirical erank analysis shows Rank‑1 stack retains ~70% of pre‑merge sum; SVD variant maintains coverage.
- Anisotropy mitigation (Mechanism 2): Medium. Theoretical bound and κ reduction demonstrated, but break condition if task Jacobians are isotropic.
- Preference alignment via smooth scalarization (Mechanism 3): Medium. Optimization effective in experiments, but relies on pseudo‑loss validity and may misalign if entropy poorly correlates with true loss.
