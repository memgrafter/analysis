# BHDD: A Burmese Handwritten Digit Dataset

## Quick Facts
- arXiv ID: 2603.21966
- Source URL: https://arxiv.org/abs/2603.21966
- Reference count: 12
- Primary result: First public Burmese handwritten digit dataset (87,561 MNIST-format images) with simple CNN baselines achieving 99.83% test accuracy.

## Executive Summary
BHDD introduces the first publicly available benchmark for handwritten Burmese digits, filling a gap for Myanmar’s round-script characters. The dataset comprises 87,561 grayscale images standardized to 28×28 pixels, collected from over 150 contributors via a mobile app that performed real-time preprocessing and a two-stage quality assurance process. Baseline models—including an MLP and two CNNs—achieve high accuracy (>99.8%), indicating that Burmese digits are highly learnable despite morphological similarities among some pairs. Error analysis shows misclassifications concentrate on visually similar digits (0/1, 0/8, 3/1, 5/8), highlighting the script’s intrinsic challenges. The dataset is released under CC BY-SA 4.0 to promote research on Burmese handwriting recognition.

## Method Summary
The dataset construction combined community engagement with careful preprocessing. Contributors wrote digits on paper and photographed sheets using an Android app that applied adaptive thresholding and contour detection in real time, allowing them to adjust parameters and retake until extracted digit contours appeared clean. This on-device processing minimized submission of low-quality images. After submission, a two-stage quality assurance pipeline—first by a 20-member annotation team using a chatbot-based tool, then by two data engineers—removed mislabeled, illegible, and duplicate images. The final images were centered and resized to 28×28 grayscale. The train/test split was contributor-based to prevent writer leakage: 60,000 balanced training images (6,000 per class) and 27,561 test images reflecting natural collection frequencies (unbalanced). Baseline models were implemented in scikit-learn (MLP) and PyTorch (CNNs). The improved CNN incorporated batch normalization after each convolutional layer and on-the-fly augmentation (rotation, translation, scaling), trained with cosine learning rate annealing and weight decay. This systematic process yielded a high-quality benchmark with strong baseline performance.

## Key Results
- BHDD is the first public handwritten digit dataset for Burmese script, containing 87,561 MNIST-format images.
- Simple baseline models achieve high test accuracy: MLP (99.40%), two-layer CNN (99.75%), and augmented CNN with batch normalization (99.83%).
- Error analysis of 27,561 test samples shows 47 misclassifications, clustering among visually similar digit pairs (0/1, 0/8, 3/1, 5/8).

## Why This Works (Mechanism)

### Mechanism 1: Real-time preprocessing improves sample quality
The mobile app performed adaptive thresholding and contour detection on-device, providing contributors immediate visual feedback on extracted digit contours. This allowed them to adjust parameters and retake photos until the contours were clean before submission, preventing obviously poor-quality images from entering the pipeline and reducing downstream cleaning burden. *Break condition:* If the preprocessing algorithms are not robust to varied lighting, paper types, or camera qualities, contributors may become frustrated and submit fewer or lower-quality samples despite feedback.

### Mechanism 2: Two-stage QA removes semantic errors
A human-in-the-loop quality assurance process involved a 20-member annotation team reviewing samples via a chatbot-based tool, followed by a final verification pass by two data engineers. This two-stage approach effectively removed mislabeled, illegible, and duplicate images that automated metrics might miss. *Break condition:* Inconsistent annotation guidelines or an inefficient review tool could introduce human error or bottlenecks, allowing systematic errors (e.g., a common writing style mislabeled by all reviewers) to persist.

### Mechanism 3: Consistent round forms yield high accuracy
Burmese digits’ round, loop-based construction leads to sharp mean images and relatively contained variance regions, indicating strong consensus on basic digit forms. This structural consistency allows even a simple two-layer CNN to learn separable features, resulting in >99.8% test accuracy. *Break condition:* If the test set includes writing styles or distortions far outside the training distribution (e.g., extremely messy handwriting), performance could drop, as suggested by the remaining errors clustering on inherently similar pairs (0/1, 0/8).

## Foundational Learning
- **Community-sourced data collection**: The dataset’s scale (87k images from 150+ people) depends on a non-expert, distributed collection effort. Understanding its biases (age, location, writing surface) is crucial for interpreting model performance. *Quick check:* What are the potential demographic and environmental biases introduced by collecting primarily from Yangon-based students and professionals using A4 paper and phone cameras?
- **MNIST-format standardization**: The 28×28 grayscale format enables direct comparison with decades of MNIST-derived research. However, it forces a lossy transformation (cropping, centering, resizing) from original photos, which may discard useful stylistic information. *Quick check:* How does the forced 28×28 centering transform the aspect ratio and stroke thickness of the original handwritten digits, and could this transformation artificially reduce confusion between some classes?
- **Balanced training vs. natural test distribution**: The training set is balanced (6,000 per class), while the test set reflects natural collection frequencies (unbalanced). This tests model robustness to class imbalance but complicates accuracy interpretation. *Quick check:* If a model is trained on a balanced set but tested on an unbalanced set with some very rare classes (e.g., class 9: 389 samples), is a high overall accuracy meaningful, or should performance be reported per class?

## Architecture Onboarding
**Component map:** Physical collection (handwriting on paper) → Mobile capture & real-time preprocessing (OpenCV-based adaptive thresholding, contour detection, cropping to 28×28) → Two-stage QA (crowdsourced annotation tool → engineer verification) → Dataset packaging (pickle/IDX formats with fixed contributor-based train/test split).

**Critical path:** The most fragile sequence is: Mobile app preprocessing parameters (per-photo) → contour extraction → 28×28 centering → human QA judgment → final image inclusion. A failure at any step creates a silent quality drop.

**Design tradeoffs:**
- Train/test split by contributor (no writer leakage) vs. natural class distribution in test set. This ensures writer-independence but makes test accuracy a function of both model strength and the luck of which contributors’ sheets were assigned to the test set.
- Mobile-based, on-device preprocessing (low barrier, immediate feedback) vs. potential for non-uniform parameter choices by contributors leading to subtle dataset shifts.
- High-resolution source photos downsampled to 28×28. This follows MNIST convention but may lose fine details crucial for distinguishing the most similar pairs (0/1).

**Failure signatures:**
- Unexpectedly high variance in mean pixel intensity per class could indicate inconsistent preprocessing or lighting conditions not corrected by the app.
- A confusion matrix dominated by a single pair (0/1) suggests the representation bottleneck is the script’s inherent similarity, not data noise.
- Duplicate images detected post-QA would indicate a failure in the “verified unique” claim, compromising train/test independence.

**First 3 experiments:**
1. Reproduce the mobile preprocessing pipeline: Using the app’s described parameters (adaptive thresholding, contour detection), run a set of collected photo sheets to verify the extraction yield and quality matches the paper’s description (~low yield requiring over-collection).
2. Validate the QA process: Manually inspect a random sample of 100 images from the final dataset, comparing them to the raw contours from the app to estimate the false negative rate (illegible images that passed QA).
3. Train the provided baseline models: Implement the MLP, two-layer CNN, and improved CNN exactly as described (layers, dropout, augmentation) to reproduce the reported 99.83% test accuracy. This confirms the dataset’s usability and the baseline’s validity.

## Open Questions the Paper Calls Out
**Open Question 1:** How can BHDD be extended to cover Myanmar consonants and full characters, and what new challenges arise? The authors state this as future work; extending to the full script involves many more classes with potentially finer distinctions and connected strokes, requiring new datasets and analysis of confusion patterns.

**Open Question 2:** How does the natural test-set imbalance (class frequencies 6,856 down to 389) affect the reliability and interpretation of model accuracy metrics? The authors intentionally left the test set unbalanced to reflect natural distribution, but standard accuracy can be misleading with skewed classes; per-class precision/recall and robustness on rare digits need empirical validation.

**Open Question 3:** What specific low-level visual features (e.g., stroke curvature, loop closure degree) distinguish confusing digit pairs like 0/1 and 5/8, and can these features be automatically extracted to improve classification? Error analysis identifies confused pairs but does not quantify features; understanding precise cues could guide targeted data augmentation or model modifications.

**Open Question 4:** How did the mobile app’s adaptive preprocessing parameters influence the final dataset’s bias toward certain stroke thicknesses or digit clarity, and did this affect writer representation? Preprocessing metadata is captured but not analyzed; it may have selectively retained clearer samples, potentially skewing the dataset toward certain writing styles, ink densities, or contributor groups.

## Limitations
- Collection bias: Dataset sourced primarily from Yangon-based students and professionals using A4 paper and phone cameras, limiting diversity in writing surfaces, age, and regional styles. Generalization to other Burmese-speaking populations is unproven.
- Formatting constraints: Forced MNIST-style 28×28 centering may discard stylistic information (aspect ratio, stroke thickness) crucial for distinguishing visually similar digits (e.g., 0/1), potentially underestimating script difficulty.
- Test-set imbalance: Unnatural class distribution (389–6,856 samples) complicates accuracy interpretation; rare classes (e.g., digit 9) may have unreliable performance estimates despite balanced training.
