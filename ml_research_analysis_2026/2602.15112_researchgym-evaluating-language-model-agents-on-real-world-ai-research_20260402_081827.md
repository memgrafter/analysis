# ResearchGym: Evaluating Language Model Agents on Real-World AI Research

## Quick Facts
- **arXiv ID:** 2602.15112
- **Source URL:** https://arxiv.org/abs/2602.15112
- **Reference count:** 40
- **Primary result:** Frontier LLM agents exhibit a sharp capability-reliability gap, achieving state-of-the-art performance only unreliably (6.7% end-to-end success) despite occasional peaks.

## Executive Summary
ResearchGym introduces a benchmark for evaluating language model agents on closed-loop AI research by transforming five recent papers into 39 executable sub-tasks with objective metrics. Testing a GPT-5-based agent revealed severe reliability issues: it improved over baselines in only 1 of 15 end-to-end runs (6.7%) and completed just 26.5% of sub-tasks on average. Remarkably, it once exceeded a human reference solution on an ICML 2025 Spotlight task, suggesting frontier agents can reach state-of-the-art performance but do so unreliably. Similar failure patterns were observed across Claude Code and Codex, with key issues including impatience, poor resource management, overconfidence in weak hypotheses, coordination difficulties, and context length limits.

## Method Summary
ResearchGym constructs a closed-loop research environment where agents must read a paper’s repository, formulate hypotheses, implement experiments via code execution, evaluate results against objective metrics, and iterate. Each paper is decomposed into granular sub-tasks (e.g., reproducing a specific figure, ablating a component) with auto-gradable success criteria based on validation performance. Agents interact with a Python execution sandbox and have access to the original codebase as a baseline. The evaluation measures end-to-end research success (improving the baseline) as well as sub-task completion rates across multiple runs with fixed time and compute budgets.

## Key Results
- GPT-5-based agent improved over baseline in 1 of 15 end-to-end evaluations (6.7% success, 11.5% average gain).
- Average sub-task completion rate: 26.5% across all agents.
- One run exceeded the human reference solution on an ICML 2025 Spotlight task.
- Failure modes consistent across frontier models: impatience (early termination), poor time/resource management, overconfidence in weak hypotheses, difficulty parallelizing experiments, and context length limits causing state tracking degradation.
- Performance typically plateaued after ~9 hours due to inefficient use of remaining time.

## Why This Works (Mechanism)
ResearchGym works because it forces agents through a realistic, iterative research cycle with concrete, executable deliverables. By grounding evaluation in actual recent papers and requiring code-based experimentation, it tests more than static knowledge or one-step reasoning—it probes long-horizon planning, tool use, error debugging, and adaptive learning. The automatic, metric-driven grading eliminates subjectivity and enables large-scale, reproducible testing. The decomposition into sub-tasks also isolates specific research capabilities (e.g., hypothesis generation, implementation, analysis), providing finer-grained failure diagnostics than end-to-only metrics.

## Foundational Learning
1. **Closed-loop research simulation**  
   *Why needed:* Real research requires cycles of proposal, execution, and analysis, not just a single answer.  
   *Quick check:* Verify each task demands at least three distinct experiment iterations to succeed.

2. **Objective, auto-gradable metrics**  
   *Why needed:* Enables scalable, unbiased evaluation without human raters.  
   *Quick check:* Ensure metric values correlate with expert human judgment on a sample of completed sub-tasks.

3. **Sub-task decomposition**  
   *Why needed:* Breaks complex research into measurable units to pinpoint agent weaknesses.  
   *Quick check:* Confirm each sub-task has a binary or continuous score that can be computed from execution outputs.

4. **Baseline code integration**  
   *Why needed:* Provides a fair starting point and measures incremental improvement.  
   *Quick check:* Reproduce original paper results from the provided baseline to validate its correctness.

5. **Failure mode taxonomy**  
   *Why needed:* Systematic categorization guides targeted architectural improvements.  
   *Quick check:* Annotate failed agent runs and achieve >80% inter-annotator agreement on mode labels.

## Architecture Onboarding
**Component map:**  
Task Specification -> Planner -> Executor -> Environment (Code Sandbox) -> Evaluator -> Feedback -> Planner

**Critical path:**  
Planner generates an experiment plan (e.g., “modify model architecture, train, validate”) → Executor translates plan into code → Environment runs code and returns outputs (logs, metrics) → Evaluator scores against objective → Feedback (results, errors) updates Planner for next iteration.

**Design tradeoffs:**  
- *Context length vs. memory:* Longer histories improve state tracking but risk overflow; external memory may help but adds complexity.  
- *Exploration vs. exploitation:* Broad hypothesis sampling increases success chance but wastes time on dead ends; greedy deepening may miss breakthroughs.  
- *Time allocation:* Spending time on literature search vs. experimentation; poor budgeting leads to early plateau.

**Failure signatures:**  
- Performance plateauing after ~9 hours despite remaining budget.  
- Repeated proposals of minor variations on the same approach (e.g., only LoRA+regularization).  
- Frequent timeouts from inefficient code or unnecessary large-scale training.  
- Context overflow errors or loss of early experiment details.

**First experiments:**  
1. Add retrieval-augmented memory for past experiment results to mitigate context degradation.  
2. Introduce a hierarchical planner that sets high-level goals and delegates sub-tasks to specialized modules.  
3. Implement a diversity bonus in the reward function to encourage exploration beyond template-based hypotheses.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** What factors determine when frontier LLM agents can reliably achieve state-of-the-art research outcomes versus failing?
- **Basis in paper:** [explicit] The paper identifies a "sharp capability-reliability gap" where "the agent improves over the provided baselines from the repository in just 1 of 15 evaluations (6.7%)" yet "once exceeded the human reference solution on an ICML 2025 Spotlight task, indicating that frontier agents can occasionally reach state-of-the-art performance, but do so unreliably."
- **Why unresolved:** The paper documents extensive failure modes (impatience, resource mismanagement, overconfidence, context limits) but cannot pinpoint which combination or threshold causes the sporadic success. It remains unclear whether reliability failures stem primarily from agent design, insufficient budget, or inherent task properties.
- **What evidence would resolve it:** Large-scale controlled experiments varying agent design (scaffolds, prompting, tools) across thousands of runs on ResearchGym to correlate specific design choices with success rates, combined with failure mode analysis to identify necessary and sufficient conditions for reliable improvement.

### Open Question 2
- **Question:** How can agent architectures be improved to maintain coherent long-horizon planning and resource management beyond 9 hours?
- **Basis in paper:** [explicit] "performance gains concentrate early in the run and typically plateau after approximately 9 hours" and the analysis states that "degraded state tracking under context accumulation" causes inefficient use of remaining time. Context length limits are listed as a "hard limit" failure mode.
- **Why unresolved:** The paper identifies the symptom (plateau after 9 hours) and a contributing factor (context degradation) but does not evaluate architectural interventions like external memory, hierarchical planning, or better context summarization. The root cause—whether purely a context window issue or a more fundamental planning deficiency—remains unclear.
- **What evidence would resolve it:** Implement and compare multiple context management strategies (e.g., retrieval-augmented state tracking, graph-based plan representations, adaptive summarization) on ResearchGym tasks, measuring impact on plateau time, completion rates, and resource efficiency relative to a baseline ReAct agent.

### Open Question 3
- **Question:** How can agents be encouraged to explore genuinely diverse hypothesis spaces rather than converging on template-based variations of a single approach?
- **Basis in paper:** [inferred] The qualitative analysis reveals that "despite superficially different method names, agents consistently propose minor variations of the same underlying approach." For example, all continual learning runs proposed LoRA + Fisher/EWC regularization, and cross-modal retrieval runs all used entropy minimization. This indicates a failure to explore beyond a narrow set of familiar patterns.
- **Why unresolved:** The paper documents this convergence but does not isolate whether it stems from baseline code bias, insufficient literature search, prompt-induced anchoring, or lack of exploration incentives in the agent's objective function. The mechanism driving this collapse to templates is unknown.
- **What evidence would resolve it:** Ablation experiments that (a) remove or alter baseline code visibility, (b) provide explicit diversity rewards or multi-armed bandit exploration, (c) vary literature-search tools and prompts, then measure hypothesis diversity via code/idea clustering. Success would show increased exploration breadth without sacrificing depth.

### Open Question 4
- **Question:** Can smaller models be trained on agent trajectories from frontier models to develop competent research capabilities at reduced cost?
- **Basis in paper:** [explicit] The Discussion states: "Training.Gym-style environments are commonly used to generate high-quality training data for fine-tuning agents via reinforcement learning or expert iteration. However, ResearchGym tasks are sufficiently difficult that only frontier LLMs achieve non-trivial performance, prohibiting direct training experiments. We nonetheless release all trajectories from our experiments to support future work. Exploring whether smaller models can be trained on traces from stronger agents remains an open question beyond our current scope."
- **Why unresolved:** While the authors release trajectories, they did not attempt imitation learning or RL fine-tuning due to cost and difficulty. It is unknown whether the research reasoning demonstrated by frontier models can be distilled into smaller, more efficient models without significant capability loss.
- **What evidence would resolve it:** Take the collected GPT-5 trajectories, perform supervised fine-tuning and/or RL (e.g., GRPO) on models of varying sizes (e.g., 7B, 13B, 70B), then evaluate the fine-tuned models on ResearchGym. A positive result would show non-trivial transfer (> baseline performance) from smaller models.

### Open Question 5
- **Question:** How can objective evaluation of research success be extended to include multi-modal reasoning tasks and theoretical/symbolic research (e.g., theorem proving) while maintaining benchmark integrity?
- **Basis in paper:** [inferred] The Discussion explicitly lists multi-modality and subjective/theoretical research as omissions: "Multi-modality. Our current task set does not include research problems requiring multi-modal reasoning, such as medical imaging, video understanding, or speech processing." and "Subjective Research. We purposefully exclude purely theoretical, analysis-driven, or proof-based papers. Evaluating success in these domains is inherently subjective and often requires expert human verification."
- **Why unresolved:** These omissions represent gaps in ResearchGym's coverage of real-world research. Creating objective, executable grading for multi-modal tasks or proof-based work is challenging but necessary for a comprehensive research agent benchmark. The paper does not propose solutions.
- **What evidence would resolve it:** Design and implement 2–3 representative tasks from multi-modal domains (e.g., model interpretability for vision models, audio-based diagnosis) or formal theorem proving, where success can be defined through automated verification (e.g., test-suite accuracy, proof assistant acceptance). Integrate them into ResearchGym and demonstrate that they can be run under the same feasibility constraints, then evaluate frontier agents on them.

## Limitations
- **Sample size & selection bias:** Benchmarked on only 5 recent papers (39 sub-tasks); representativeness of broader AI research is unknown.
- **Human reference ambiguity:** Unclear if "human reference solution" was from original authors or a standardized replication; affects interpretation of "state-of-the-art" claims.
- **Resource/config transparency:** Compute budget, time limits, and agent hyperparameters are not detailed, hindering precise failure mode attribution.

## Next Checks
1. **Cross-benchmark replication:** Run the same agent(s) on PaperBench and MLR-Bench to test if the low success rate pattern holds across differently constructed research environments.
2. **Extended task sampling:** Expand the benchmark to 25+ diverse recent papers (including non-ML domains) to quantify selection bias in the original 5-paper subset.
3. **Resource-constrained ablation:** Re-run the successful ICML 2025 task with tight time/compute budgets to test if its "exceeding human" outcome is robust or a low-probability artifact.
