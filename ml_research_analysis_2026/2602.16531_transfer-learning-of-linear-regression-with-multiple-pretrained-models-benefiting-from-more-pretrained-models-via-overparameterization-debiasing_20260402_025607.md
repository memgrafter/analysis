# Transfer Learning of Linear Regression with Multiple Pretrained Models: Benefiting from More Pretrained Models via Overparameterization Debiasing

## Quick Facts
- arXiv ID: 2602.16531  
- Source URL: https://arxiv.org/abs/2602.16531  
- Reference count: 40  
- Primary result: A multiplicative debiasing technique (scaling assumed task operators by source sample size/dimension or via validation) corrects overparameterization bias and achieves consistency; without it, adding more overparameterized pretrained models can fail to improve or even degrade performance.

## Executive Summary
This paper investigates multi-source transfer learning in linear regression when all pretrained source models are overparameterized. Overparameterization induces an attenuation bias that shrinks the estimated source parameters toward zero, which in turn harms the transfer step. The authors show that naively aggregating many such biased sources does not improve target performance and can lead to inconsistency. To address this, they propose a multiplicative debiasing strategy: the assumed linear relationships between source and target (operators \(H_j\)) are scaled by factors \(\rho_j = \min(1, n_j/d)\) when source sample sizes \(n_j\) are known, or by a common scalar \(\tilde{\rho}\) tuned on a validation set when the sources are anisotropic. Theoretical analysis demonstrates that debiasing restores consistency – the test error converges to the Bayes optimum as the number of sources \(m \to \infty\) – whereas the non‑debiased transfer remains inconsistent. Empirically, debiasing reduces the bias‑variance trade‑off and unlocks the benefits of using many overparameterized pretrained models. The burden for gain is quantified: one needs more than \(1 + d/\sqrt{n_{\text{source}}}\) models to see improvement.

## Method Summary
Transfer is formulated as regularized least squares on the target:  
\(\hat{\beta}_{TL} = \arg\min_{\beta} \|y - X\beta\|_2^2 + n\alpha_{TL} \sum_{j=1}^m \|\hat{H}_j\beta - \hat{\theta}_j\|_2^2\),  
where \(\hat{\theta}_j\) are pretrained source parameters and \(\hat{H}_j\) encode assumed task relations. When sources are overparameterized (\(d > n_j\)), the minimum‑norm solution for \(\hat{\theta}_j\) is attenuated by \(\rho_j = n_j/d\), i.e., \(\mathbb{E}[\hat{\theta}_j|\beta] = \rho_j H_j\beta\). This bias propagates to the transferred predictor. Debiasing replaces each \(\hat{H}_j\) by \(\rho_j\hat{H}_j\) (or uses a scaled identity \(\tilde{\rho}I\) when source covariances are unknown). The closed‑form solution involves \(R = (\sum_{j=1}^m \hat{H}_j^\top \hat{H}_j)^{1/2}\) and is solved via \((X^\top X + n\alpha_{TL} R)^{-1}X^\top y\). Hyperparameters \(\alpha_{TL}\) (and possibly \(\tilde{\rho}\)) are chosen by target validation, then the model is retrained on the full target data.

## Key Results
- Overparameterized sources exhibit a multiplicative bias (shrinkage by \(n_j/d\)) that limits the effectiveness of multi‑source transfer and can cause inconsistency.
- Multiplicative debiasing (using known \(\rho_j\) or validation‑tuned \(\tilde{\rho}\)) restores consistency; the test error converges to the Bayes optimal as \(m\to\infty\).
- Without debiasing, benefiting from multiple overparameterized sources requires \(m > 1 + d/\sqrt{n_{\text{source}}}\); with debiasing the benefit holds for large \(m\) even when this condition is not met.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Transfer learning with multiple pretrained models improves target performance by penalizing deviation from all pretrained parameters simultaneously.
- **Mechanism:** The target predictor is learned by solving a regularized least‑squares optimization:  
  \(\hat{\beta}_{TL} = \arg\min_{\beta} \|y - X\beta\|^2_2 + n\alpha_{TL} \sum_{j=1}^m \|\hat{H}_j\beta - \hat{\theta}_j\|^2_2\).  
  This combines target data fitting with a soft constraint that keeps the learned parameters close to each pretrained model \(\hat{\theta}_j\) through assumed operators \(\hat{H}_j\).
- **Core assumption:** The source tasks are related to the target task via linear transformations, and the pretrained models contain useful information for the target.
- **Evidence anchors:**  
  - [abstract] describes the formulation and indicates that the penalty extends prior single‑pretrained‑model work.  
  - [Section 3.3] derives the closed‑form solution and introduces the matrix \(R\) that aggregates the \(\hat{H}_j\).
- **Break condition:** The benefit diminishes if the number of pretrained models \(m\) is too small, specifically if \(m \le 1 + d/\sqrt{n_{\text{source}}}\) (see condition on page 2). Additionally, without addressing overparameterization bias (Mechanism 2), the approach may become inconsistent.

### Mechanism 2
- **Claim:** Overparameterized pretrained models introduce an inductive bias that attenuates the learned parameter vector toward zero relative to the true target parameters, harming transfer performance.
- **Mechanism:** When a source model is overparameterized (\(d > n_{\text{source}}\)), the minimum \(\ell_2\)-norm least‑squares solution lies in the span of the source training examples. Consequently, the conditional expectation shrinks by a factor \(n_{\text{source}}/d\) (or more generally \(\rho_j = \min(1, n_{\text{source}}/d)\)) along any direction. This attenuation persists in the transfer step and does not vanish by adding more biased models.
- **Core assumption:** Source data matrices are isotropic Gaussian (Assumption 4.1) and target parameters are isotropic (Assumption 3.2), enabling a simple scalar shrinkage factor.
- **Evidence anchors:**  
  - [Section 3.1] defines the overparameterized least‑squares solution as the minimum norm solution.  
  - [Section 5.4] explicitly derives \(E[\hat{\theta}_j|\beta] = \rho_j H_j\beta\) with \(\rho_j\) given in (12)–(13).  
  - [Theorem 5.4] proves inconsistency for overparameterized sources.
- **Break condition:** The bias becomes severe when the overparameterization level \(d/n_{\text{source}}\) is large and the number of pretrained models is insufficient to average out the noise (Theorem 5.8). Anisotropic source covariances also break the simple scalar factor (Lemma 5.10), requiring more sophisticated debiasing.

### Mechanism 3
- **Claim:** A multiplicative debiasing factor applied to the assumed task relation operators (e.g., scaling by \(n_{\text{source}}/d\) for overparameterized sources) corrects the attenuation and restores consistency.
- **Mechanism:** The debiasing replaces the identity or true \(H_j\) in the penalty by \(e\hat{H}_j = \rho_j \hat{H}_j\) (or \(\hat{H}_j = I\) with a tuned scalar \(\tilde{\rho}\) when source statistics are unknown). This aligns the effective shrinkage in the penalty with the actual bias of the pretrained models, yielding an unbiased transfer predictor under isotropic assumptions (Theorem 5.6) and enabling consistency as \(m \to \infty\) (Theorem 5.7).
- **Core assumption:** The true task relations \(H_j\) are either known or can be approximated by scaled identities; also, the shrinkage factor \(\rho_j\) is either known (from \(n_j\)) or can be selected via validation (Algorithm 2).
- **Evidence anchors:**  
  - [Section 5.4] introduces the debiasing and Theorem 5.6 proves unbiasedness for isotropic sources.  
  - [Section 5.5] extends to anisotropic sources via a validation‑tuned scalar \(\tilde{\rho}\).  
  - [Theorem 5.7] shows consistency with debiasing, contrasting Theorem 5.4’s inconsistency.
- **Break condition:** Debiasing may increase variance if the scaling factor is too small for highly overparameterized models, especially when \(m\) is not large enough (Theorem 5.8). Condition: \(m > 1 + d/n_{\text{source}}\) for benefit.

## Foundational Learning
- **Overparameterized least‑squares and the minimum ℓ₂‑norm solution:**  
  *Why needed:* The analysis hinges on the fact that when \(d > n\), the ordinary least‑squares problem has infinitely many solutions, and the chosen one has minimum norm, which introduces the overparameterization bias.  
  *Quick check:* What is the expected value of the minimum norm solution given the true parameters, and how does it depend on the ratio \(d/n\)?
- **Multi‑source transfer learning via parameter penalization:**  
  *Why needed:* This is the core algorithmic framework; understanding how multiple sources are combined through a single penalty hyperparameter is crucial.  
  *Quick check:* How does the matrix \(R = (\sum_{j=1}^m \hat{H}_j^\top \hat{H}_j)^{1/2}\) affect the closed‑form solution?
- **Bias‑variance decomposition for high‑dimensional estimators:**  
  *Why needed:* The paper explains why overparameterization increases bias and how adding more models can reduce variance; this trade‑off underlies the debiasing strategy.  
  *Quick check:* In the decomposition \(\mathbb{E} = \sigma^2_\epsilon + \text{Bias}^2 + \text{Variance}\), how does each term scale with the number of pretrained models \(m\) and the overparameterization level?
- **Random matrix theory and Marchenko‑Pastur asymptotics:**  
  *Why needed:* The theoretical results rely on deterministic equivalents of random quadratic forms and Stieltjes transforms.  
  *Quick check:* What does the function \(g(-\phi;\gamma)\) represent, and when does it approach zero?

## Architecture Onboarding

**Component map:**  
Target data \((X, y)\), validation set, and source statistics \((n_j, d)\) feed into a **Debiasing controller** that computes scaling factors \(\rho_j\) (or a common \(\tilde{\rho}\)). The **Pretrained model store** provides \(\hat{\theta}_j\). The **Optimizer** uses \(X, y\) and the debiased operators to compute the closed‑form predictor \(\hat{\beta}\). The **Hyperparameter tuner** searches over \(\alpha_{TL}\) (and \(\tilde{\rho}\) if needed) using validation error, selects the best, and triggers a final training run on the full target data. Flow: Data → Debiasing → Optimizer → Predictor, with the tuner looping around.

**Critical path:**  
1. Decide debiasing strategy: if source sizes \(n_j\) known and isotropy plausible, set \(\rho_j = \min(1, n_j/d)\) (Algorithm 1); otherwise prepare a grid for \(\tilde{\rho}\).  
2. For each candidate \((\alpha_{TL}, \tilde{\rho})\), compute \(R = (\sum_{j=1}^m \hat{H}_j^\top \hat{H}_j)^{1/2}\) (with debiased \(\hat{H}_j\)) and solve the closed‑form predictor on the target training set.  
3. Evaluate on the validation set; pick the hyperparameters with lowest error.  
4. Retrain on the full target data with the selected hyperparameters to obtain the final \(\hat{\beta}\).  
5. Optionally, repeat with different random splits to estimate bias‑variance components.

**Design tradeoffs:**  
- *Debiasing vs numerical stability:* Using \(\rho_j = n_j/d\) can make \(\sum \hat{H}_j^\top \hat{H}_j\) small, worsening the condition of \(X^\top X + n\alpha_{TL} R\) for an overparameterized target. A larger \(\alpha_{TL}\) helps but may introduce bias.  
- *Number of pretrained models:* Increasing \(m\) reduces variance but may amplify bias if debiasing is mis‑specified.  
- *Validation cost:* Tuning an extra scalar \(\tilde{\rho}\) expands the grid search, increasing computational load; using known \(n_j\) collapses this dimension.

**Failure signatures:**  
- Test error does not converge as \(m\) grows, especially for overparameterized sources → likely missing or incorrect debiasing.  
- Matrix inversion warnings (singular/near‑singular) → debiasing factor too small relative to \(\alpha_{TL}\); consider larger \(\alpha_{TL}\) or switching to true \(H_j\) if stable.  
- Validation error high across all hyperparameter combos → source models may be unrelated or too noisy; revisit source selection.  
- Debiasing benefits vanish when source covariance is anisotropic but isotropic factor is used → switch to validation‑tuned \(\tilde{\rho}\) or estimate the source covariance.

**First 3 experiments:**  
1. **Reproduce Figure L.2:** For a high‑condition circulant \(H_j\), compare test error vs. \(\gamma_{\text{src}}\) for \(m=1\) and \(m=10\), with and without debiasing (using scaled identity). Validate the large performance gap.  
2. **Bias‑variance decomposition:** Compute empirical squared bias and variance for pairs \((\gamma_{\text{src}}, m)\) using the algorithm in Appendix M; confirm that debiasing reduces bias at the cost of increased variance, and that variance drops as \(m\) grows.  
3. **Delearned debiasing factor:** Implement Algorithm 2 for anisotropic sources (exponential‑decay \(\Sigma_z\)). Plot the validation‑chosen \(\tilde{\rho}\) vs. \(\gamma_{\text{src}}\) and compare test errors to isotropic debiasing \(\rho=1/\gamma_{\text{src}}\); observe adaptation to anisotropy.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Can the overparameterization debiasing approach be theoretically analyzed for anisotropic source covariances, yielding a closed‑form factor (rather than validation‑based tuning)?
- **Basis in paper:** In Section 5.5 and Appendix P the authors discuss anisotropic source data and state that the isotropic factor \(1/\gamma_{\text{src}}\) is replaced by a single scalar \(\rho\) chosen via validation (Algorithm 2). No theoretical derivation is provided for the anisotropic case.
- **Why unresolved:** The paper only supplies an empirical solution (validation tuning) without insights into the optimal debiasing under anisotropy, which is crucial for practical settings where source covariance is unknown and non‑uniform.
- **What evidence would resolve it:** A theoretical formula for the optimal scaling operator (or at least its spectral properties) that depends on the source covariance, derived via random matrix theory, together with a proof that using it yields consistency without a validation set.

### Open Question 2
- **Question:** Can the proposed debiasing method be extended to nonlinear transfer learning scenarios, such as pretrained neural networks?
- **Basis in paper:** In the conclusion the authors state: “These findings provide theoretical and conceptual foundations for leveraging multiple overparameterized models, offering new directions for research beyond linear regression.”
- **Why unresolved:** The analysis relies on linearity and random matrix theory for Gaussian designs; extending to deep networks is nontrivial and requires new tools to characterize overparameterization bias and design effective debiasing for nonlinear architectures.
- **What evidence would resolve it:** A rigorous analysis of overparameterization bias in pretrained neural nets (e.g., lazy training regime) and an algorithm analogous to multiplicative debiasing that empirically improves transfer learning, supported by theory (e.g., consistency guarantees) in a simplified nonlinear model.

### Open Question 3
- **Question:** Could a more flexible debiasing that learns a separate scaling operator per source model, rather than a common scalar, improve performance when source tasks have heterogeneous relationships?
- **Basis in paper:** The debiasing algorithm (Alg. 1) uses \(e\hat{H}_j = \rho_j I_d\) where \(\rho_j\) is either \(1\) (underparameterized) or \(n_j/d\) (overparameterized) – the same formula for all models based solely on their overparameterization level. The paper does not consider varying the scaling beyond this deterministic rule or matrix‑valued operators.
- **Why unresolved:** Heterogeneous source tasks with different directions of relevance might benefit from tailoring the debiasing operator per source; the current assumption of isotropy and uniform scaling may limit performance in mixed settings.
- **What evidence would resolve it:** Formulate a more general debiasing that introduces separate parameters for each source (e.g., diagonal scaling in the eigenbasis of source covariance), derive conditions under which such flexibility lowers asymptotic error, and provide empirical validation on synthetic scenarios with heterogeneous \(H_j\) matrices.

## Limitations
- Assumptions of isotropic Gaussian sources and linear relations may not hold in practice, potentially invalidating the debiasing.
- The debiasing factor \(\rho_j\) requires knowledge of source sample size \(n_j\) and dimension \(d\); inaccuracies can lead to over‑ or under‑correction.
- The derived condition \(m > 1 + d/\sqrt{n_{\text{source}}}\) is asymptotic; its finite‑sample tightness is uncertain.
- Empirical evaluation is largely synthetic; real‑world transfer scenarios remain underexplored.
