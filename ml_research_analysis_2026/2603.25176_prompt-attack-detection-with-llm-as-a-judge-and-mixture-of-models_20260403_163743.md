# Prompt Attack Detection with LLM-as-a-Judge and Mixture-of-Models
## Quick Facts
- **arXiv ID:** 2603.25176
- **Source URL:** https://arxiv.org/abs/2603.25176
- **Reference count:** 28
- **Primary result:** A structured LLM-as-a-Judge approach using lightweight models achieves F1 up to 0.871 with ~1.5s latency, and a Mixture-of-Models provides only modest, pairing-dependent gains.

## Executive Summary
This paper tackles the problem of detecting prompt attacks (e.g., jailbreaks, injections) in live LLM systems under strict production latency constraints. It proposes using general-purpose, lightweight LLMs (like `gemini-2.0-flash-lite`) as judges, guided by a structured reasoning prompt that decomposes intent, verifies safety signals, assesses harm, and mandates self-reflection. A Mixture-of-Models (MoM) layer aggregates judgments from multiple such judges. Evaluated on a curated dataset of 929 real-world and red-teamed prompts, the structured judge outperforms encoder-based classifiers, specialized safety LLMs, and proprietary guardrails in accuracy and latency. MoM yields only small improvements for carefully selected model pairs but often degrades with larger ensembles. The system is deployed in production for Singapore public service chatbots.

## Method Summary
The core method employs an **LLM-as-a-Judge** architecture where a lightweight LLM processes each input through a mandatory, taxonomy-guided reasoning chain: (1) intent decomposition (categorizing as workflow instruction, factual overview, etc.), (2) safety-signal verification, (3) harm assessment, and (4) self-reflection on a draft verdict before a final boolean decision. The qualitative verdict and confidence level are mapped to a numerical score (0.0–1.0). For **Mixture-of-Models (MoM)**, multiple judges run in parallel; their scores are combined via a weighted sum (weights summing to 1), and a threshold τ determines the final binary flag. Optimal weights and τ are selected via grid search on validation folds to maximize F1. The approach is evaluated against baselines including encoder classifiers (PromptGuard), specialized security LLMs (Qwen3Guard), and proprietary guardrails (Amazon Bedrock).

## Key Results
- Structured LLM-as-a-Judge achieved F1 scores up to 0.871 (`gpt-5.1`) and 0.844 (`gemini-2.0-flash-lite-001`) with latency as low as 1.52 seconds, surpassing all tested baselines.
- The Mixture-of-Models provided only modest improvements (e.g., +0.0164 F1 for `gpt-5.1 + gpt-5-mini`); performance frequently degraded when adding more models or poorly paired judges.
- The system is deployed in production for Singapore public service chatbots, demonstrating real-world applicability under latency constraints.

## Why This Works (Mechanism)
### Mechanism 1: Structured Reasoning Stabilizes Lightweight Judges
**Claim:** Mandating explicit intent decomposition, safety-signal verification, harm assessment, and self-reflection enables lightweight, general-purpose LLMs to outperform both specialized classifiers and unguided judges in prompt-attack detection.
**Mechanism:** The structured prompt transforms the binary classification task into a constrained reasoning pipeline. This forces the model to surface and validate decision-critical features (e.g., distinguishing benign workflow instructions from harmful method specifications, verifying the presence of safety signals), reducing brittleness on ambiguous, "grey-area" inputs where surface-level heuristics fail.
**Evidence anchors:**
- [abstract] describes the "structured reasoning process involving explicit intent decomposition, safety-signal verification, harm assessment, and self-reflection."
- [section 3.2] details the taxonomy and mandatory steps; Figure 1 shows F1 improvement over OpenAI Guardrails' direct verdict approach.
- [corpus] contextualizes the need for such defenses by highlighting vulnerabilities in naive LLM-as-a-Judge setups.
**Break condition:** If a novel attack pattern evades the taxonomy's capture (e.g., a new framing technique that bypasses "Framing Stripping"), performance would regress toward that of an unconstrained judge.

### Mechanism 2: Mixture-of-Models Gains Are Pairing-Specific and Fragile
**Claim:** MoM can yield mild detection improvements, but only with carefully chosen, complementary model pairings; larger or poorly matched ensembles typically degrade performance.
**Mechanism:** Aggregating discrete scores from multiple LLM judges via a weighted linear combination can correct individual errors if judges' mistakes are uncorrelated. The grid search over the discrete output space efficiently finds weight/threshold configurations that implement beneficial decision boundaries.
**Evidence anchors:**
- [abstract] notes "only modest gains observed" and "performance often degrading as more models were added."
- [section 4.5] Table 3 shows positive gains only for specific pairs (e.g., `gpt-5.1 + gpt-5-mini`), while most mixtures underperform their strongest constituent and all quad mixtures degrade.
- [corpus] discusses voting ensembles in traditional ML but does not contradict the paper's empirical finding that "more models" does not always help in this context.
**Break condition:** If all judges share correlated failure modes (e.g., all fail on creative social engineering attacks), the ensemble cannot surpass the best single model and will likely amplify noise.

### Mechanism 3: Curated Dataset Exposes Real-World Weaknesses
**Claim:** A dataset blending real benign chatbot traffic with ART-generated adversarial prompts better reflects production deployment challenges than standard benchmarks, leading to more meaningful and generalizable evaluation.
**Mechanism:** Including complex "False Positive Traps" (legitimate but suspicious-looking workflow instructions) and diverse, up-to-date attack patterns (social engineering, code-mixed payloads) forces the detector to rely on deep semantic understanding rather than shallow keyword heuristics. This simulates the distribution shift and novel attack surfaces encountered in live systems.
**Evidence anchors:**
- [abstract] mentions a "curated dataset combining benign queries from real-world chatbots with adversarial prompts generated via automated red teaming (ART)."
- [section 2.1] critiques existing benchmarks for "outdated, repetitive attack templates" and "benign samples that are too simple."
- [section 3.1] describes dataset construction: 770 benign samples from Singapore public service chatbots (including traps) and 159 adversarial samples from PAIR ART covering grey-area patterns.
**Break condition:** If the ART generation or benign data collection stagnates and fails to capture emerging vectors (e.g., new multi-modal obfuscation), the evaluation will not predict live performance.

## Foundational Learning
- **Concept: Structured Chain-of-Thought (CoT) for Classification**
  - **Why needed here:** Transforms a binary verdict into an enforceably explicit reasoning trace (intent category, safety signals, harm level, self-reflection), hypothesized to stabilize lightweight LLM judgments on ambiguous inputs.
  - **Quick check question:** How would you design a prompt to force a model to both classify an input and then critique its own classification before finalizing?
- **Concept: Automated Red Teaming (ART) for Adversarial Data Generation**
  - **Why needed here:** Provides a scalable method to generate diverse, evolving prompt-attack examples that reflect real-world adversary behavior, avoiding reliance on static, outdated templates.
  - **Quick check question:** What is a key limitation of using static, community-collected jailbreak prompts for evaluating production guardrails?
- **Concept: Ensemble Decision Thresholding on Discrete Outputs**
  - **Why needed here:** MoM aggregates judgments from multiple LLM judges; understanding grid search over discrete score combinations (due to fixed model outputs) is crucial for efficient hyperparameter optimization without continuous optimization.
  - **Quick check question:** If two models output scores from {0, 0.2, ..., 1.0}, why does a grid search over weights and thresholds cover all unique decision boundaries even with finite step size?

## Architecture Onboarding
- **Component map:** Input dispatcher -> (Parallel) LLM Judge instances (with structured prompt) -> Score aggregator (weighted sum) -> Threshold comparator -> Binary verdict. Optional: confidence scorer mapping from qualitative levels to numerical scores.
- **Critical path:**
  1. Receive input + conversation history.
  2. Each judge executes structured reasoning (Framing Stripping, taxonomy checks, self-reflection) producing a numerical score.
  3. Aggregator computes weighted sum.
  4. Compare against threshold τ to output final "attack"/"benign" flag.
- **Design tradeoffs:**
  - Latency vs. Accuracy: More/faster judges reduce latency but may sacrifice F1; high-capacity judges improve F1 but increase cost/latency.
  - MoM Size vs. Robustness: Adding more judges often introduces conflicting signals and degrades F1; optimal ensembles are small (2–3) and carefully paired.
  - Threshold Sensitivity: Lower τ increases recall but raises false positives; set per risk tolerance.
- **Failure signatures:**
  - High false positive rate on complex benign workflows (e.g., system configuration instructions) due to overzealous "detailed_harm_methods" classification.
  - Latency spikes when any judge in the MoM ensemble experiences high load or slow response.
  - MoM performance collapse when adding a judge with highly correlated errors (e.g., both fail on creative framing attacks).
- **First 3 experiments:**
  1. **Ablation of Structured Prompt:** Run a single judge (e.g., `gemini-2.0-flash-lite-001`) with the proposed structured prompt vs. OpenAI Guardrails' direct verdict prompt on a held-out subset; expect higher F1 from structured version.
  2. **MoM Pairwise Discovery:** Evaluate all possible pairs from a candidate set (e.g., {`gpt-5.1`, `gpt-5-mini`, `claude-haiku-4.5`, `gemini-2.0-flash-lite`}) via grid search; identify pairs with positive gain (>0.01 F1 over best single) and pairs with significant degradation.
  3. **Latency-Throughput Stress Test:** Deploy the selected MoM configuration (e.g., best pair) under increasing query load; measure P99 latency and monitor for variance spikes indicating straggler judges. Adjust judge hardware or reduce ensemble size if latency budget violated.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** What specific characteristics of model pairings (e.g., architecture, training objective, output style) lead to positive gains in the Mixture-of-Models (MoM) approach versus degradation?
- **Basis in paper:** The results show that MoM performance is highly dependent on specific combinations (e.g., `gpt-5.1 + gpt-5-mini` gains +0.0164 F1, while `claude-haiku-4.5 + gemini-2.0-flash-lite-001` degrades -0.0278 F1). The paper states "performance often degrades as more models are added" and "gains are concentrated in a small number of complementary combinations," but does not identify the underlying complementary signals.
- **Why unresolved:** The paper uses grid search to find optimal weights but does not analyze *why* certain pairs succeed. Understanding the pairing principles (e.g., diversity in error types, calibration differences) is crucial for practical MoM deployment.
- **What evidence would resolve it:** An error analysis comparing confusion matrices of individual models within successful vs. failing combinations. Ablation studies isolating specific model traits (e.g., precision vs. recall bias, token distribution) as predictors of MoM synergy.

### Open Question 2
- **Question:** Does the structured taxonomy-guided reasoning process (framing stripping, intent categorization, self-reflection) generalize to detecting more nuanced or novel attack patterns beyond those captured in the current 929-sample dataset?
- **Basis in paper:** The dataset is noted as limited in scale: "our evaluation relies on a curated dataset of 929 prompts... may not capture the full diversity of prompt-attack strategies." The structured prompt design is the core proposed innovation.
- **Why unresolved:** The dataset combines real Singapore chatbot traffic with ART-generated attacks. Its coverage of "evolving attack patterns" is acknowledged as incomplete. The structured reasoning's robustness to truly novel obfuscation or multi-modal attacks (e.g., embedding attacks in images) is untested.
- **What evidence would resolve it:** Longitudinal evaluation on a continuously updated red-teaming dataset. Stress-testing the prompt with adversarial examples designed to break each reasoning step (e.g., framing that evades stripping, ambiguous safety signals). Cross-dataset validation on independent benchmarks like HackAPrompt or TensorTrust after retraining the taxonomy.

### Open Question 3
- **Question:** Why does enabling internal "thinking mode" in LLM judges consistently *decrease* F1 scores across all evaluated models, contradicting the typical CoT benefit for complex tasks?
- **Basis in paper:** "Across all evaluated models, thinking mode does not improve F1 score. In all cases, non-thinking configurations outperform their thinking counterparts." The paper cites external prompting guidance but provides no empirical analysis of *why* thinking harms this specific discriminative task.
- **Why unresolved:** The paper hypothesizes that "additional internal reasoning can introduce unnecessary complexity," but this is speculative. The task is binary classification of a user prompt, not a generative problem. The interaction between structured external CoT (mandated by the prompt) and internal model reasoning is not explored.
- **What evidence would resolve it:** Qualitative analysis of model outputs in thinking vs. non-thinking modes—do thinking traces lead to over-complication, inconsistency, or deviation from the structured schema? Log-prob or attention analysis to see if internal reasoning conflicts with the enforced output structure. Testing if the effect holds for different model sizes or with different CoT constraints.

### Open Question 4
- **Question:** How does the proposed LLM-as-a-Judge approach scale in terms of cost, throughput, and maintainability for large-scale, multi-lingual, or domain-specific deployments beyond Singapore's public service chatbots?
- **Basis in paper:** The system is deployed for "Singapore public service chatbots." Latency is measured on a local Apple M2 chip, but cost per 1K tokens or total operational cost is not discussed. The prompt is English-only and tailored to a specific governance context.
- **Why unresolved:** Production guardrails must handle high QPS, multiple languages, and varied domain policies (e.g., healthcare, finance). The structured prompt's taxonomy and rules are likely English-centric and may not transfer without significant localization. Cost comparisons to specialized lightweight classifiers (e.g., `PromptGuard 2`) at scale are absent.
- **What evidence would resolve it:** Pilot deployments in other domains/languages with adapted taxonomies. TCO analysis comparing MoM/judge pipelines against optimized encoder models under real traffic loads. A/B testing on user-facing metrics (e.g., false positive impact on user satisfaction).

### Open Question 5
- **Question:** Can the structured output schema and confidence scoring (mapped to 0.0–1.0) be optimized or learned to better align with deployment-specific risk tolerances, rather than using manually defined thresholds?
- **Basis in paper:** The mapping from qualitative verdict/confidence to numerical scores is a fixed lookup table (Table 1). Threshold `τ` is tuned via grid search on validation data. The paper states this allows "fine-grained control over defense sensitivity."
- **Why unresolved:** The fixed mapping is arbitrary (e.g., "False (Safe) Low" = 0.4, "True (Attack) Low" = 0.6). This linear separation may not reflect true model uncertainty or the asymmetric cost of false negatives vs. false positives in production. The paper does not explore learning this mapping or threshold from operational feedback loops.
- **What evidence would resolve it:** An analysis of calibration—do the model's qualitative confidence levels correlate with empirical accuracy? Could a simple logistic regression mapping from model logits or ensemble scores improve F1 at a given recall target? Deployment studies where thresholds are dynamically adjusted based on real-time attack/benign ratios.

## Limitations
- **Private dataset:** The 929-sample evaluation set is not public, is single-domain (Singapore public services), and may not capture the full diversity of real-world prompt-attack strategies.
- **MoM hyperparameter opacity:** Grid search details for weights (step size) and threshold ranges are not fully disclosed; reported modest MoM gains may depend on specific, unreported tuning choices.
- **Latency & reproducibility:** Latency measured on an Apple M2 chip may not reflect cloud hardware; API configurations (max_tokens, timeout) are unspecified. LLM non-determinism is acknowledged but not quantified.

## Confidence
- **Structured reasoning improves detection over direct prompts:** Medium-High (supported by ablation showing improvement, but generalizability to other lightweight models is uncertain).
- **MoM yields only modest, pairing-dependent gains:** Medium (empirical grid search found positive gains for a few pairs but degradation for most ensembles; suggests benefit is fragile).
- **Curated dataset reflects production challenges better than standard benchmarks:** Medium (combines real benign traffic and ART attacks for realistic difficulty, yet remains small and single-domain).

## Next Checks
1. **Structured prompt ablation:** Run identical judges (e.g., `gemini-2.0-flash-lite`) with the published structured prompt versus a direct verdict prompt on a held-out subset; report F1 difference with confidence intervals over ≥5 random seeds.
2. **MoM pairing analysis:** For a diverse panel of lightweight LLM judges, compute pairwise agreement (Cohen’s κ) on validation scores; correlate with MoM F1 gain (over best single) from a fine-grained grid search (weight steps ≤0.05). Test if low agreement predicts positive gain.
3. **Cross-benchmark generalization:** Evaluate the best single-judge configuration (structured prompt) on a standard public prompt-injection benchmark (e.g., AdvBench or GPTFuzzer). Compare in-domain vs. out-of-domain F1 to quantify overfitting to the curated dataset.
