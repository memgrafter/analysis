# LensWalk: Agentic Video Understanding by Planning How You See in Videos

## Quick Facts
- **arXiv ID:** 2603.24558  
- **Source URL:** https://arxiv.org/abs/2603.24558  
- **Reference count:** 40  
- **Primary result:** Without any fine-tuning, LensWalk boosts strong VLMs: on LVBench, accuracy rises from 57.1% to 68.6% (+11.5) with o3; on Video‑MME long, from 63.1% to 70.0% (+6.9) with GPT‑4.1 and from 64.7% to 71.4% (+6.7) with o3.

## Executive Summary
LensWalk addresses a key limitation in video understanding: current methods rely on static, preprocessed video representations and cannot adaptively seek raw evidence as reasoning evolves. It introduces an agentic framework where an LLM reasoner actively controls observation through a tight reason‑plan‑observe loop. The agent dynamically specifies temporal scopes and sampling density using three complementary tools—Scan Search for broad cue discovery, Segment Focus for fine‑grained fact extraction, and Stitched Verify for cross‑segment verification. Timestamp anchors and a subject memory table ensure coherent multi‑turn grounding. Applied to strong VLMs (o3, GPT‑4.1) without fine‑tuning, LensWalk substantially improves accuracy on multiple benchmarks while using far fewer frames and lower peak token counts than retrieval‑based agents.

## Method Summary
LensWalk redefines video understanding as an active, iterative process. An LLM reasoner receives a query, video metadata, and interaction history, then emits a tool call specifying: a tool (scan, focus, stitch), a guiding sub‑question, temporal interval(s), and sampling parameters. The corresponding VLM observer processes the sampled frames and returns time‑anchored evidence. A subject memory table tracks entities and their appearance intervals; timestamp anchors are embedded in frame batches to cite exact moments. The loop repeats until the reasoner declares confidence. This design enables adaptive evidence gathering—allocating observation budget where needed—without any model fine‑tuning.

## Key Results
- On **LVBench**, accuracy jumps from 57.1% to 68.6% (+11.5) with o3.  
- On **Video‑MME long**, gains of +6.9% (GPT‑4.1) and +6.7% (o3).  
- **Efficiency:** Uses ~290 frames vs. >8000 in retrieval‑based agents, with lower peak token usage.

## Why This Works (Mechanism)

### Mechanism 1: Adaptive Observation Loop
- **Claim:** The reason‑plan‑observe loop adapts observation scope and density to the evolving reasoning state, enabling targeted evidence gathering.  
- **Mechanism:** At each turn, the LLM reasoner ingests the query, video metadata, and accumulated history, then emits a tool call specifying tool, sub‑question, temporal interval(s), and sampling parameters. The VLM observer processes the sampled frames and returns time‑anchored evidence. The cycle repeats until sufficient confidence triggers a final answer.  
- **Core assumption:** Reasoning and perception are tightly coupled; the agent can reliably decide where to look next based on prior evidence.  
- **Evidence anchors:** Abstract and Section 3.2 describe the loop; neighboring agentic video papers (e.g., VideoZoomer) highlight iterative refinement, but LensWalk uniquely controls raw video access directly.

### Mechanism 2: Complementary Toolkit
- **Claim:** A minimal yet expressive toolkit of three VLM‑based tools (Scan Search, Segment Focus, Stitched Verify) supports a wide range of query‑driven observation strategies.  
- **Mechanism:**  
  - *Scan Search* partitions a broad interval into slices, samples sparsely per slice, and returns per‑slice summaries for fast cue discovery.  
  - *Segment Focus* densely samples a single continuous interval to extract fine‑grained details or verify a hypothesis.  
  - *Stitched Verify* combines frames from multiple non‑contiguous segments into one context for cross‑segment reasoning (e.g., before/after comparisons).  
- **Core assumption:** No single observation mode fits all information needs; adaptive allocation of temporal scope and sampling density is necessary to handle sparse, multi‑granular video evidence.  
- **Evidence anchors:** Abstract and Section 3.3 detail the tools; Section 4.4’s behavioral taxonomy shows human‑like strategies emerging from tool diversity.

### Mechanism 3: Lightweight Grounding
- **Claim:** Timestamp anchors and a subject memory table provide lightweight grounding that maintains temporal and entity consistency across multi‑turn interactions, enabling scalable long‑horizon reasoning.  
- **Mechanism:**  
  - *Timestamp anchors* are textual tags inserted into frame sequences during observation, prompting the VLM to cite exact seconds in its output.  
  - *Subject memory table* is a global JSON‑like registry updated after each turn; it stores canonical entity identifiers, summarized attributes, and appearance intervals. The reasoner consults this table to avoid re‑identifying entities and to plan re‑observations of ambiguous ranges.  
- **Core assumption:** Without explicit grounding, the agent would lose track of which moments support which facts, leading to contradictory or repetitive reasoning.  
- **Evidence anchors:** Abstract and Section 3.4 introduce these mechanisms; Section 4.3 ablations show removing either reduces accuracy on long videos.

## Architecture Onboarding
**Component map:**  
User query + video metadata -> Reasoner -> Tool call (with parameters) -> Frame sampler (based on tool) -> VLM observer -> Timestamp anchors & Subject memory table update -> Reasoner (next step) -> ... -> Final answer

**Critical path:**  
1. Receive user question and video metadata.  
2. Reasoner emits a tool call with parameters (tool, interval, fps, sub‑question).  
3. System samples frames from specified intervals, embeds timestamp anchors, and queries VLM observer.  
4. Observation text returned, timestamps noted, subject table merged.  
5. History and memory updated; repeat from step 2 until `finish`.  
6. Return final answer.

**Design tradeoffs:**  
- *Active vs. preprocessing cost:* No offline captioning, but more LLM‑VLM calls → higher inference time but lower token waste.  
- *Tool granularity:* More tools increase flexibility but also prompt complexity; three tools strike a balance.  
- *Memory size:* Subject table caps at ~15 recent entities to control context; may drop older but relevant entities.  
- *Sampling density:* Higher fps yields more detail but consumes frames/tokens; agent must budget across tools.

**Failure signatures:**  
- *Static Repetition* – identical tool calls on same segment without progress.  
- *Premature Conclusion* – terminating after a single strong cue without verification.  
- *Evidence Dilution* – excessive turns; strong early evidence becomes buried in long history.  
- *Persistent Ambiguity* – never finds needed visual evidence (e.g., relies on subtitles only).

**First 3 experiments:**  
1. **Main results** – LensWalk applied to strong VLMs (o3, GPT‑4.1) yields large gains on LVBench (+11.5%), Video‑MME long (+6.9%), MMVU (+2%), etc., outperforming prior agents.  
2. **Ablation study** – Removing Scan Search causes the biggest drop (–4.6%); disabling Timestamp Anchor or Subject Memory also lowers accuracy, confirming their roles.  
3. **Efficiency analysis** – LensWalk achieves similar or better accuracy than retrieval‑based agents while using far fewer frames (≈290 vs. >8000) and lower peak token counts, demonstrating adaptive budget allocation.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can LensWalk avoid premature conclusions?  
- **Basis in paper:** [inferred] The paper identifies "Premature Conclusion" as a failure mode (Section C.3).  
- **Why unresolved:** The agent sometimes terminates after a single observation based on frequent but potentially misleading cues, lacking a verification mechanism.  
- **What evidence would resolve it:** Incorporate a confidence threshold or self‑critique step; evaluate reduction in early termination errors on benchmark cases.

### Open Question 2
- **Question:** How can evidence dilution be mitigated?  
- **Basis in paper:** [inferred] Section C.3 describes "Evidence Dilution" where strong early evidence is drowned by later irrelevant observations.  
- **Why unresolved:** The agent does not weight or prioritize evidence, leading to recency bias and loss of decisive information.  
- **What evidence would resolve it:** Implement dynamic memory with relevance scoring; test if accuracy improves on queries where early evidence is correct.

### Open Question 3
- **Question:** How can static repetition loops be detected and broken?  
- **Basis in paper:** [inferred] "Static Repetition" behavior (Section C.3) shows the planner stuck in identical tool calls without progress.  
- **Why unresolved:** The planner lacks meta‑cognitive monitoring to recognize stagnation and shift strategy.  
- **What evidence would resolve it:** Add loop detection heuristics or a progress metric; measure decrease in repeated calls and improved accuracy.

### Open Question 4
- **Question:** How can the subject memory table scale beyond the fixed 15‑entity limit?  
- **Basis in paper:** [explicit] The memory table keeps at most 15 subjects prioritized by recency (Section 3.4).  
- **Why unresolved:** This arbitrary cap may omit important entities in videos with many characters or objects, harming long‑horizon coherence.  
- **What evidence would resolve it:** Test variable‑size memory or advanced entity resolution; evaluate on entity‑dense videos to measure performance gain.

## Limitations
- **LLM reasoning dependency:** Performance relies on the LLM’s planning; errors can accumulate across turns.  
- **Memory capacity limit:** The subject memory table caps at ~15 entities, which may omit relevant entities in complex long videos.  
- **Benchmark limitations:** Evaluation on curated QA benchmarks may not reflect real‑world video understanding.
