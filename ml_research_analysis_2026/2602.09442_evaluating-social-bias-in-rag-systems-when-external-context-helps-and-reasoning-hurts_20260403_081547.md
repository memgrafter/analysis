# Evaluating Social Bias in RAG Systems: When External Context Helps and Reasoning Hurts
## Quick Facts
- arXiv ID: 2602.09442
- Source URL: https://arxiv.org/abs/2602.09442
- Reference count: 40
- Primary result: Standard RAG consistently reduces social bias across 13+ types, while RAG with Chain-of-Thought (CoT) prompting paradoxically increases bias despite higher accuracy.

## Executive Summary
This paper evaluates social bias in Retrieval-Augmented Generation (RAG) systems by comparing bias scores before and after RAG augmentation and with Chain-of-Thought (CoT) prompting. Using multiple LLMs (Meta-Llama-3-8B-Instruct, Mistral-7B-v0.1), retrieval corpora (WikiText-103, C4), and 13+ bias types measured via SCW, BOLD, and HolisticBias, the study finds that standard RAG mitigation is robust: 9/10 bias types in SCW and all 13 in HolisticBias. However, integrating CoT into RAG, while improving accuracy, amplifies bias and strengthens correlations between bias and negative metrics like toxicity. Faithfulness analysis shows CoT reasoning is heavily influenced by retrieved documents (74.78% word overlap), with bias shifting dynamically as context accumulates. The work uncovers a fairness-accuracy trade-off and calls for bias-aware reasoning frameworks.

## Method Summary
The experimental pipeline uses a RAG system built with LangChain and Chroma vector database. Documents from WikiText-103 and a 0.5% random subset of C4 are chunked into 250-word pieces and indexed using the all-mpnet-base-v2 sentence embedding model. For each query from bias evaluation datasets (StereoSet, CrowS-Pairs, WinoBias combined as SCW; BOLD; HolisticBias), the system retrieves the top-5 most similar chunks via cosine similarity. Three conditions are evaluated: (1) baseline (no retrieval), (2) standard RAG (retrieved docs appended to prompt), and (3) RAG+CoT (LLM instructed to produce step-by-step reasoning citing docs before final answer). Bias is measured through SCW log-probability differences between stereotype and anti-stereotype words, and via standard deviation of metric distributions (sentiment, toxicity, gender polarity, regard, emotion variance) for BOLD/HolisticBias. CoT faithfulness is assessed by truncating reasoning at various checkpoints (1 sentence, 25%, 50%, 70%) and forcing an answer, computing word overlap with retrieved docs, and tracking bias shifts.

## Key Results
- Standard RAG consistently reduces bias: 9/10 bias types in SCW; all 13 types in HolisticBias.
- RAG with CoT increases bias despite higher accuracy, with stronger correlation between bias scores and negative metrics like toxicity.
- CoT reasoning shows high faithfulness to retrieved content (74.78% word overlap) and bias inclinations shift dynamically as reasoning accumulates.

## Why This Works (Mechanism)
The bias reduction from standard RAG is attributed to the contextual diversity introduced by retrieved documents, which disrupts the model's reliance on stereotypical patterns by providing alternative narratives or counterexamples. In contrast, CoT prompting encourages the model to articulate explicit reasoning steps, which can reinforce spurious correlations present in the retrieved context or the model's priors. The faithful integration of retrieved content into CoT (evidenced by high word overlap) means that bias present in the documents or amplified through reasoning propagates into the final output, leading to increased bias even as overall accuracy improves. This reveals a tension between interpretability/accuracy and fairness when reasoning is made explicit.

## Architecture Onboarding
**Component Map**: 
Query -> Vector Retriever (Chroma + all-mpnet-base-v2) -> Top-5 Retrieved Docs -> Generation (LLM) -> Output. For CoT: Generation includes Reasoning step (citing docs) then Final Answer.

**Critical Path**: 
1. Input query is embedded and matched against document embeddings.
2. Top-5 relevant chunks are returned.
3. Prompt is constructed: baseline (query only), standard RAG (query + docs), or RAG+CoT (query + docs + instruction to reason).
4. LLM generates response; for CoT, reasoning is truncated at checkpoints for ablation.
5. Output is evaluated for bias and other metrics.

**Design Tradeoffs**: 
- Standard RAG vs. RAG+CoT: CoT improves task accuracy but exacerbates bias, highlighting a fairness-accuracy trade-off.
- Retrieval corpus: Larger, more diverse corpora may improve bias mitigation but increase retrieval latency and computational cost.
- Chunk size: Smaller chunks increase retrieval precision but may lose broader context; larger chunks provide more context but risk including irrelevant information.

**Failure Signatures**: 
- Homogeneous retrieved documents (low diversity) fail to disrupt stereotypes.
- Miscomputed bias metrics due to incorrect tokenization or classifier mismatches.
- CoT truncation cutting mid-sentence, creating incoherent reasoning that invalidates faithfulness measurements.
- Model version drift (e.g., Llama-3 variant) leading to different bias patterns.

**First Experiments**:
1. Run baseline bias evaluation without retrieval to establish initial bias levels.
2. Apply standard RAG (top-5) and measure bias change across all datasets.
3. Implement RAG+CoT and compare bias scores and accuracy against the first two conditions.

## Limitations
- C4 0.5% sampling method (random seed, stratification) is unspecified, potentially skewing retrieval diversity.
- Prompt templates for bias evaluation before RAG (BOLD/HolisticBias) are not provided, requiring assumptions.
- CoT truncation metric (tokens vs. sentences) is ambiguous, and generation hyperparameters (temperature, max tokens) are unreported.
