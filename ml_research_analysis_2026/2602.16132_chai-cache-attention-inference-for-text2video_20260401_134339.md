# CHAI: CacHe Attention Inference for text2video

## Quick Facts
- **arXiv ID:** 2602.16132
- **Source URL:** https://arxiv.org/abs/2602.16132
- **Reference count:** 8
- **Primary result:** Training-free cross-inference caching via Cache Attention achieves a 3.35× speedup on VBench with only 8 denoising steps (vs. 30), while maintaining video quality within 0.3% of the baseline.

## Executive Summary
CHAI introduces a training-free acceleration method for text-to-video diffusion models by reusing latent representations from prior inferences through a novel Cache Attention mechanism. Unlike prior work that heuristically skips steps or directly substitutes entire latents, CHAI selectively attends to entity-level features (objects/scenes) from cached latents within the attention layers of a Diffusion Transformer (DiT). This preserves prompt-specific details while providing a structural "head start" in the early, high-change denoising steps. Evaluated on OpenSora 1.2, CHAI delivers substantial latency reductions (3.35× on VBench, 1.65× on diverse VidProM prompts) with negligible quality loss, outperforming intra-inference caching baselines like AdaCache.

## Method Summary
CHAI operates in two phases: a caching phase (full 30-step inference) and a fast inference phase (8 steps). For a new prompt, it first extracts object/scene entities using an NLP parser (spaCy) and encodes them with a vision-language model (LongCLIP). These embeddings are queried against a vector database (Faiss) storing entries from prior cached prompts. On a cache hit (any entity matches), the system retrieves a stored latent tensor from a prior run (aligned to the current denoising step) and activates Cache Attention in the first spatial self-attention block of the DiT model during denoising steps 2, 3, and 4. In these layers, the Query (Q) is computed from the current latent, while the Key (K) and Value (V) are derived from the cached latent, allowing selective feature reuse. On a cache miss, a full 30-step run is performed and new cache entries are created. Cache management uses an LRU policy within a fixed storage budget.

## Key Results
- Achieves a **3.35× speedup** on VBench (692 prompts) using 8 denoising steps, with VBench score 0.7985 vs. baseline 0.8018 (0.3% difference).
- Under a tight 10% cache budget on VidProM (1000 prompts), achieves a **1.65× speedup** with a **52% entity-level cache hit rate** (vs. 14.7% for whole-prompt reuse).
- Cache hit rates exceed **83%** with just 1GB of storage. Outperforms AdaCache in latency (3.75s vs. 4.36s) and quality (VBench 0.7985 vs. 0.7883).

## Why This Works (Mechanism)
### Mechanism 1: Cache Attention for Selective Feature Reuse
- **Claim:** Cache Attention enables selective reuse of entity-level features from cached latents without direct substitution, preserving prompt-specific details.
- **Mechanism:** The Cache Attention layer modifies standard spatial self-attention in a DiT block. For a new diffusion step, the Query (Q) comes from the current prompt-modulated latent, while Key (K) and Value (V) are taken from a cached latent corresponding to a semantically similar prompt (identified via entity embeddings). This allows the model to "attend to" relevant pre-computed structural features (e.g., a beach scene) while preventing irrelevant cached content (e.g., a party) from dominating.
- **Core assumption:** The semantic structure of shared entities is encoded in the latent space and can be selectively extracted via attention without corrupting the new prompt's specific details.
- **Evidence anchors:** 
  - Abstract: "Cache Attention as an effective method for attending to shared objects/scenes across cross-inference latents."
  - Section 3.2: "allows the prompt-modulated Gaussian noise query (Q) to selectively pick features of relevant entities from the latent cache."
  - Corpus: Weak; neighboring papers use different caching strategies but do not evaluate attention-based selective reuse.
- **Break condition:** If cached latent's entity features are too dissimilar or interfere with the current prompt's composition, attention may fail to suppress irrelevant content, causing semantic leakage. NIRVANA-VID (direct substitution) suffers this, implying Cache Attention's selectivity is key.

### Mechanism 2: Entity-Level Cross-Inference Caching
- **Claim:** Entity-level caching achieves high hit rates on diverse, realistic video prompt distributions, making cross-run acceleration viable where whole-prompt reuse fails.
- **Mechanism:** Instead of matching entire prompts (often unique), the system extracts object and scene entities using NLP (spaCy) and matches their embeddings (LongCLIP) against a vector database (Faiss). A cache hit occurs if any entity in the new prompt matches an entity from a cached prompt, enabling reuse of that cached latent.
- **Core assumption:** Video prompts, while unique in full text, sufficiently overlap on key entities (nouns) to make granular reuse effective and frequent.
- **Evidence anchors:** 
  - Abstract: "prompts often share common entities such as objects or scenes."
  - Section 3.1: Empirical analysis: "caching 300 prompts produces around 60% cache hit rate" for entity similarity vs. low whole-prompt similarity.
  - Section 4.2: Under 10% cache budget, entity-level hit rate is 52% vs. whole-prompt's 14.7%.
- **Break condition:** Prompts with no common entities (e.g., "rocket launch" vs. "broccoli soup") will always be cache misses. Cache pollution from irrelevant entity matches could reduce overall hit rate.

### Mechanism 3: Early-Step Caching Schedule
- **Claim:** Applying cached latents only in early, high-change denoising steps (2nd, 3rd, 4th) with a reduced total step count (e.g., 8) balances latency reduction and quality preservation.
- **Mechanism:** CHAI schedules Cache Attention to be active only in the first block of denoising steps 2, 3, and 4. The first step uses random noise so caching is ineffective. Later steps (beyond 4th) have smaller feature changes per step (per rectified flow scheduler), so marginal benefit diminishes. Running only 8 total steps (vs. 30) is made viable by the structural "head start" from cached early steps.
- **Core assumption:** The largest structural changes occur in the first few denoising steps; reusing a high-quality latent from these steps provides a stronger prior for a short 8-step run than starting from pure noise.
- **Evidence anchors:** 
  - Section 3.2: "caching provides little benefit after the 4th denoising step" and "avoid using the cached block in the first denoising step."
  - Section 4.1: 8-step CHAI achieves VBench 0.7985 vs. 30-step OpenSora 0.8018 (0.3% difference).
  - Section 2.2.1: Intra-inference methods cannot skip early steps due to large feature changes.
- **Break condition:** If the cached latent's semantic content is too divergent, injecting its structure in early steps may bias the generation irrecoverably. For prompts requiring precise spatial relationships not captured by entities, the early-step "head start" may not compensate for reduced steps.

## Foundational Learning
- **Concept:** Diffusion Denoising Process (DDPM/DDIM).  
  *Why needed:* To understand what is being cached (3D latent tensors at specific timesteps) and why skipping steps is non-trivial (early steps make large structural changes). The acceleration mechanism operates on this iterative refinement.
  *Quick check:* Why is the first denoising step generally not skippable in intra-inference caching but can be replaced by a cached latent in cross-inference caching?
- **Concept:** Attention Mechanism in Transformers (specifically DiT).  
  *Why needed:* Cache Attention is a modification of standard Q, K, V computation in Spatial Self-Attention. Understanding that K and V define the "memory" to attend to, while Q is the "current query," is key to seeing how cached information is selectively integrated.
  *Quick check:* In the Cache Attention layer, which components (Q, K, or V) come from the current prompt's latent state, and which come from the cached latent? What is the functional consequence of this design?
- **Concept:** Semantic Similarity & Embedding Spaces (CLIP).  
  *Why needed:* The cache lookup relies on matching entity embeddings (from LongCLIP) to find reusable latents. This requires understanding that semantic similarity is computed in a joint text-image embedding space.
  *Quick check:* If the entity extractor misses a key object from the prompt, what is the likely impact on cache hit rate and final video quality for a good cached candidate?

## Architecture Onboarding
- **Component map:**  
  Entity Extractor (spaCy) -> Vector DB (Faiss) <- Latent Store -> Modified DiT (OpenSora 1.2 with Cache Attention) <- Scheduler (defines active steps/blocks)  
  Cache Policy Engine (LRU) manages Latent Store and Vector DB eviction.
- **Critical path:**  
  - **Cache Hit Path:** Prompt -> Entity Extractor -> Vector DB lookup (find candidate) -> Latent Store fetch (get cached latent at steps 8,12,16) -> Modified DiT in `fast` mode for 8 steps (Cache Attention active on steps 2–4, first block) -> Output.  
  - **Cache Miss Path:** Prompt -> Entity Extractor -> Vector DB lookup (no match) -> Modified DiT in `full` mode for 30 steps (Cache Attention disabled) -> Output -> write new cache entry (store latents from steps 8,12,16 and entity embeddings).
- **Design tradeoffs:**  
  - **Cache Budget vs. Hit Rate:** Larger cache (more GB, more prompts) increases hit rate (Fig 9) but higher memory/storage cost; saturating returns (~5GB for ~89%).
  - **Step Count vs. Quality:** Fewer denoising steps (e.g., 8) drastically reduces latency but risks quality loss; Cache Attention's benefit is making such low-step counts viable.
  - **Granularity (Entity vs. Whole Prompt):** Entity-level yields higher hit rates on diverse data but risks mismatched composition; whole-prompt is precise but rarely hits.
  - **Storage Overhead:** Each cached prompt stores 3 latent tensors (~1.3MB for 240px); schedule (steps 2,3,4) defines storage.
- **Failure signatures:**  
  - **Low Cache Hit Rate:** System falls back to slow `full` mode frequently; monitor entity extraction quality and similarity thresholds.
  - **Semantic Leakage/Artifacts:** Output contains elements from cached prompt not in current prompt; indicates Cache Attention's selectivity failed; may need stricter entity matching or adjusting attention strength.
  - **Temporal Incoherence or Flickering:** Particularly if cached latent is from a video with different motion patterns; check if entity similarity is superficial but motion semantics differ.
- **First 3 experiments:**  
  1. **Quality-Latency Tradeoff Baseline:** Run OpenSora 1.2 (30 steps), NIRVANA-VID (whole-prompt reuse, 8 steps), and CHAI (entity-reuse, 8 steps) on VBench. Expect: CHAI quality ~baseline (0.3% drop), NIRVANA-VID significant drop; CHAI latency 3.35× faster.
  2. **Realistic Workload (Constrained Cache):** Use VidProM prompts sequentially. Populate cache with first 100. Test on next 1000 with 10% cache budget. Expect: CHAI hit rate ~52%, 1.65× speedup; NIRVANA-VID hit rate ~15%, negligible speedup.
  3. **Cache Scaling & Policy:** Vary cache size (1GB to 10GB) and policy (FIFO, LRU, LFU) over 100k VidProM prompts. Expect: >83% hit rate at 1GB (LRU/LFU best for small), saturation ~89% at 5GB.

## Open Questions the Paper Calls Out
- **Question 1:** How can CHAI compress cached latents (e.g., via quantization) to reduce memory while preserving Cache Attention's feature reuse, and what is the quality/speed trade-off at higher resolutions?  
  *Basis:* Section 6 (Future Work) calls for efficient latent storage via compression to handle higher-resolution video generation.
- **Question 2:** Can Cache Attention be extended to combine multiple cached latents from different prompts sharing overlapping entities to improve robustness without causing feature interference?  
  *Basis:* Section 6 suggests extending Cache Attention to fuse multiple cached latents but notes the need to avoid interference.
- **Question 3:** Can intra- and cross-inference caching be unified into an adaptive scheduler that dynamically selects the optimal strategy based on prompt semantics and denoising stage, achieving greater speedup without quality loss?  
  *Basis:* Section 6 proposes a unified inference scheduler that combines both intra- and cross-inference caching to make adaptive decisions.

## Limitations
- Exact STDiT block modification (which layers/blocks replaced with CacheAttention) is unclear from the paper.
- Scheduler alignment (mapping between 30‑step cached latents and 8‑step usage steps) is inferred but not explicitly defined.
- Retrieval policy for multiple matches (selection criteria) is unspecified and may impact hit quality.
- Entity extraction relies on spaCy noun chunks; robustness to varied phrasing or complex entities is untested.
