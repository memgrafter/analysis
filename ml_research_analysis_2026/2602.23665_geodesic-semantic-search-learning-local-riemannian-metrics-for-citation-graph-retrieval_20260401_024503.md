# Geodesic Semantic Search: Learning Local Riemannian Metrics for Citation Graph Retrieval

## Quick Facts
*   **arXiv ID:** 2602.23665
*   **Source URL:** https://arxiv.org/abs/2602.23665
*   **Reference Count:** 19
*   **Primary Result:** Learning node-specific Riemannian metrics for geodesic retrieval yields a 23% relative improvement in Recall@20 over a SPECTER+FAISS baseline on a large citation graph.

## Executive Summary
Standard embedding-based retrieval for citation graphs uses fixed Euclidean distances, which fails to capture the heterogeneous, non-Euclidean geometry of scientific knowledge where similarity varies across research areas. This paper introduces Geodesic Semantic Search (GSS), which learns a local, node-specific Riemannian metric for each paper. Retrieval computes shortest-path distances (geodesics) under these spatially-varying metrics on the citation graph, followed by reranking and filtering. A hierarchical coarse-to-fine search reduces computational cost. On a citation prediction benchmark with 169K papers, GSS achieves a 23% relative gain in Recall@20 and a 46% gain on tasks bridging distinct research concepts, while a hierarchy reduces latency by 4× with minimal quality loss.

## Method Summary
GSS learns a local positive-definite metric tensor **G**<sub>i</sub> for each node *i* via a Graph Attention Network (MetricGAT). The metric is parameterized as **G**<sub>i</sub> = **L**<sub>i</sub><strong>L</strong><sub>i</sub><sup>⊤</sup> + ε**I**, where **L**<sub>i</sub> ∈ ℝ<sup>d×r</sup> is a low-rank factor (r=32). Training uses a multi-component loss combining contrastive learning on geodesic distances, a ranking loss, a smoothness regularizer on neighboring **L**<sub>i</sub>, and an embedding-hop correlation loss. At inference, for a query, a FAISS search finds seed nodes. A multi-source Dijkstra algorithm computes shortest-path distances using the source node's metric on each edge (w(*u,v*) = d<sub><strong>G</strong><sub>u</sub></sub>(*u,v*)). Results are reranked with Maximal Marginal Relevance and filtered by path coherence. For efficiency, a pre-computed k-means cluster hierarchy enables a coarse-to-fine top-down search, drastically cutting the nodes explored by Dijkstra.

## Key Results
*   GSS achieves a 23% relative improvement in Recall@20 over the SPECTER+FAISS baseline on a 169K paper citation prediction task.
*   On concept bridging tasks (connecting distant research areas), performance improves by 46% (Bridge@10).
*   A 3-level hierarchical search reduces latency by ~4× (from 847ms to 198ms) while maintaining 98.3% of the flat search quality and yields semantically coherent retrieval paths (coherence score 0.78).

## Why This Works (Mechanism)

### Mechanism 1: Learning Local Metrics
The core claim is that a fixed global metric (like Euclidean distance) cannot optimally capture the heterogeneous geometry of a citation graph. GSS addresses this by learning a distinct, node-specific Riemannian metric **G**<sub>i</sub> for each paper. This metric is parameterized via a low-rank matrix **L**<sub>i</sub> (ensuring positive-definiteness) and is trained to make geodesic distances on the graph align with semantic relevance. The fundamental assumption is that different semantic regions (e.g., dense machine learning clusters vs. interdisciplinary areas) require locally adapted notions of similarity. Evidence includes the reported overall performance gains and the formal guarantee of metric validity (Proposition 1). A break condition would be if the optimal full-rank metrics require very high rank, making the low-rank (r=32) approximation insufficient.

### Mechanism 2: Geodesic Paths for Concept Bridging
Geodesic distances under learned local metrics retrieve relevant papers that direct cosine similarity misses, especially for "concept bridging" queries. The mechanism aggregates many small, locally meaningful steps through intermediate nodes along a citation path. Theorem 3 formalizes that if a semantically coherent path exists with cumulative (scaled) geodesic distance less than the direct embedding dissimilarity, the target will be ranked higher. This relies on the assumption that high-quality, coherent paths exist in the citation graph even between conceptually distant areas. Evidence is the 46% gain on Bridge@10 and the provided example paths (e.g., Differential Geometry → NLP) that maintain semantic coherence. This fails if the graph lacks connecting paths (poor connectivity) or for very recent papers with few citations (cold start).

### Mechanism 3: Hierarchical Coarse-to-Fine Search
Computing geodesics via Dijkstra on the full graph is slow. GSS uses a pre-built k-means cluster hierarchy to reduce latency with little quality loss. The mechanism is a top-down search: first find top-k clusters at the coarsest level via full Dijkstra, then recursively search within the best child clusters. Proposition 2 bounds the approximation error based on cluster diameters. The assumption is that best candidates are concentrated in a few large clusters and that distances between cluster centers approximate distances between internal nodes. Evidence is the 4× speedup with 98.3% quality retention for a 3-level hierarchy. This breaks down if clustering is too coarse (large cluster diameters violate the error bound) or if the top clusters do not contain the true targets.

## Foundational Learning
*   **Riemannian Metric & Geodesic Distance:** A metric tensor **G**<sub>i</sub> defines local distance. On a graph, the geodesic distance between two nodes is the sum of local Mahalanobis distances (using the source node's metric) along the shortest path. *Why needed:* Replaces fixed Euclidean distance with a spatially-varying measure tailored to the citation graph's heterogeneous geometry.
    *   **Quick check:** Given nodes *i*, *j* with metrics **G**<sub>i</sub>, **G**<sub>j</sub>, the edge weight *w(u,v)* in Dijkstra is d<sub><strong>G</strong><sub>u</sub></sub>(*u,v*) because the step is taken from *u*'s perspective using its local geometry.
*   **Low-Rank Matrix Factorization for Metric Learning:** Parameterizing **G**<sub>i</sub> = **L**<sub>i</sub><strong>L</strong><sub>i</sub><sup>⊤</sup> + ε**I** ensures positive-definiteness and reduces parameters from O(d²) to O(dr). *Why needed:* Makes learning a unique metric per node tractable and prevents overfitting.
    *   **Quick check:** The +ε**I** term (ε>0) guarantees strict positive-definiteness even if **L**<sub>i</sub> is rank-deficient; without it, **L**<sub>i</sub><strong>L</strong><sub>i</sub><sup>⊤</sup> could be singular, making the Mahalanobis distance undefined.
*   **Graph Neural Networks (GAT) for Node-Level Output:** MetricGAT uses a Graph Attention Network to produce a distinct output (embedding **h**<sub>i</sub> and metric factors **L**<sub>i</sub>) for each node based on its neighborhood. *Why needed:* Provides the inductive bias to generate node-specific metrics informed by local graph structure.
    *   **Quick check:** The final GAT layer's output is split by two linear heads: one (embedding head) produces the 256-d **h**<sub>i</sub>, and the other (metric head) produces a vector reshaped into the 256×32 matrix **L**<sub>i</sub>.

## Architecture Onboarding
**Component map:**
SPECTER embeddings (768-d) input -> MetricGAT (3-layer GAT, K=4 heads) -> dual heads: Embedding head (LayerNorm+MLP) -> **h**<sub>i</sub> (256-d); Metric head (MLP+reshape) -> **L**<sub>i</sub> (256×32). Training uses combined loss (contrastive + ranking + smoothness + hierarchical). Inference pipeline: FAISS seed selection -> Multi-source Dijkstra (using w(u,v)=d<sub><strong>G</strong><sub>u</sub></sub>(u,v)) -> MMR reranking -> Path coherence filter. Optional: Hierarchical search replaces Dijkstra with top-down traversal of k-means cluster hierarchy.

**Critical path:**
1.  Train MetricGAT on a pre-2020 citation graph using the multi-loss objective to learn **h**<sub>i</sub> and **L**<sub>i</sub>.
2.  For a query *q*, compute its embedding **h**<sub>q</sub> with the trained model and retrieve ~√N seed papers via FAISS cosine search.
3.  Run multi-source Dijkstra from all seeds on the full graph, computing edge weights with the source node's learned metric.
4.  Take top-2*k* candidates by Dijkstra distance, rerank with MMR for diversity, filter out paths with low coherence (θ<sub>c</sub>=0.3), return top-*k*.
5.  (Hierarchical variant) Replace step 3 with a coarse-to-fine search over a pre-built k-means cluster hierarchy.

**Design tradeoffs:**
*   **Metric rank *r***: Low rank (e.g., *r*=8) underfits local geometry; high rank (e.g., *r*=64) overfits and increases compute. Paper finds *r*=32 optimal.
*   **Smoothness loss λ<sub>smooth</sub>**: Critical for path coherence. Removing it drops Recall@20 by 13%. Too high oversmooths; too low causes discontinuous metrics.
*   **Hierarchy depth vs. quality**: More levels (4) give better speedup (4×) but lower quality retention (96.1%) vs. 3 levels (98.3%).
*   **MMR λ**: Balances relevance (geodesic distance) and diversity. Not tuned extensively; default value not specified.

**Failure signatures:**
*   **High metric variance in dense clusters**: Visualized in paper; causes unstable Dijkstra paths.
*   **Poor path coherence**: Many candidates filtered at stage 4 (threshold θ<sub>c</sub>=0.3). Indicates bad metrics or poor graph connectivity.
*   **Variable latency spikes**: Multi-source Dijkstra runtime is inconsistent (e.g., 847±524 ms). Suggests queries in dense, poorly connected regions.
*   **Cold start for new papers**: Papers with few citations provide weak neighborhood signal to MetricGAT, harming their metric estimation and retrieval performance for queries about them.

**First 3 experiments:**
1.  **Metric rank ablation**: Train with *r* ∈ {8, 16, 32, 64, 128}. Hypothesis: R@20 peaks at *r*=32 and drops for higher ranks due to overfitting.
2.  **Smoothness loss ablation**: Train with λ<sub>smooth</sub> = 0. Hypothesis: Significant drop in R@20 and path coherence, validating the regularizer's necessity.
3.  **Hierarchical vs. flat search**: Compare flat Dijkstra against hierarchies with 2, 3, 4 levels. Measure latency, nodes visited, and R@20 quality ratio. Hypothesis: 3-level hierarchy provides best speed-quality tradeoff (~4× speed, ~98% quality).

## Open Questions the Paper Calls Out
*   **Can GSS be trained without citation supervision?** The current method relies on citation edges for losses. Unsupervised metric learning using only node features and topology would broaden applicability to graphs without explicit relational data.
*   **How can retrieval latency be reduced further for real-time applications?** Hierarchical search improves efficiency but 198ms latency exceeds FAISS's 2.3ms. Algorithmic optimizations (e.g., A* with learned heuristics, GPU acceleration) are needed for interactive scale.
*   **How can GSS handle streaming or evolving citation graphs?** The approach assumes a static graph. Incremental update rules for metrics and embeddings are needed to avoid costly full retraining as new papers and citations appear.
*   **How does GSS perform on very recent papers with few citations (cold-start problem)?** New, low-degree nodes lack graph connectivity for meaningful geodesics. Hybrid metrics combining learned Riemannian and content-based similarity for such nodes are a potential solution.

## Limitations
*   **Unreported hyperparameters:** Negative sampling proportions, MMR λ value, and exact hierarchical search parameters (pooling ratio ρ, levels for claimed speedup) are missing, hindering exact replication.
*   **Static base embeddings:** Performance is tied to the fixed SPECTER embeddings; degradation would occur if the base representation changes.
*   **Path coherence threshold sensitivity:** The θ<sub>c</sub>=0.3 filter is chosen without sensitivity analysis; its impact on recall is unclear.

## Confidence
*   **Local Riemannian metrics improve retrieval** (23% relative Recall@20 gain): **Medium**. Strong internal results but lack cross-dataset validation and sensitivity analysis for key unreported hyperparameters.
*   **Concept bridging gain** (46% Bridge@10): **Medium**. Promising but confined to a single benchmark; robustness uncertain.
*   **Hierarchical efficiency** (4× latency reduction with ~98% quality): **High**. Results are clearly reported and consistent across configurations, though exact hyperparams for "4×" claim are unspecified.

## Next Checks
1.  **Negative sampling impact:** Systematically vary hard/in-batch/random negative sampling ratios on the validation set and measure Recall@20 to quantify their effect on the reported 23% gain.
2.  **MMR λ tuning:** Perform a hyperparameter sweep for MMR's λ ∈ {0, 0.1, ..., 1}, evaluating nDCG@20 and candidate diversity to determine if reported values are optimal.
3.  **Hierarchical search parameters:** Test pooling ratios ρ ∈ {0.5, 0.6, 0.7} and hierarchy levels L ∈ {3, 4}, measuring mean latency and R@20 retention vs. flat search to verify the 4× speedup with ≤2% loss claim.
