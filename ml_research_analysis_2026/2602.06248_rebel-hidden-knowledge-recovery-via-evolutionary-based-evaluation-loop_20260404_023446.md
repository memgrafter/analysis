# REBEL: Hidden Knowledge Recovery via Evolutionary-Based Evaluation Loop
## Quick Facts
- **arXiv ID:** 2602.06248
- **Source URL:** https://arxiv.org/abs/2602.06248
- **Reference count:** 40
- **Primary result:** REBEL reveals that many state-of-the-art unlearning methods provide only superficial protection, achieving attack success rates up to 60% on TOFU and 93% on WMDP, substantially exceeding static baselines.

## Executive Summary
REBEL is a novel black‑box adversarial attack framework designed to evaluate the robustness of machine unlearning in large language models. It employs an evolutionary loop where a hacker LLM iteratively mutates prompts based on judge feedback to extract supposedly forgotten knowledge from an unlearned target model. Evaluated on TOFU and WMDP benchmarks, REBEL achieves high Attack Success Rates (up to 60% and 93% respectively), far surpassing static baselines. The results expose a critical flaw: standard unlearning metrics and relearning tests often fail to detect residual knowledge, indicating that many current unlearning methods achieve only superficial forgetting.

## Method Summary
REBEL treats unlearning evaluation as an adversarial search problem. Given a forget‑set query and its hidden answer, it initializes a population with the benign query. In each iteration, the target model is queried with every prompt in the population, and a judge model (either an LLM or a logit‑based scorer) assigns a leakage score to each response. The top‑K prompts with highest scores become elites; the hacker model mutates each elite to produce new candidate prompts, forming the next population. The loop repeats for up to five iterations or until a prompt triggers a leak (score above threshold). The final attack success rate is the proportion of forget‑set examples for which any generated prompt yields a leak. Baselines include directly querying the model with the original prompt and Leak@K (K stochastic generations of the original prompt). Hyperparameters include mutation counts m = [1500,80,50,40,40] and top‑K = [20,12,8,5,3] across iterations, totaling ~4220 prompts per query. This design is black‑box, requiring only query access to the target model and the hidden answer for the judge.

## Key Results
- **Attack Success Rates (ASR):** up to 60% on TOFU and 93% on WMDP, far above Leak@1000 (max 45% TOFU, 66% WMDP).
- **Static metrics mismatch:** Standard forgetting metrics (ROUGE, likelihood, retention accuracy) show poor correlation with adversarial recoverability, exposing a gap in current evaluation.
- **Superficial protection:** Many state‑of‑the‑art unlearning methods (e.g., NPO, SimNPO) exhibit high ASR, indicating they only suppress knowledge on the surface.

## Why This Works (Mechanism)
### Evolutionary Loop Reliability
REBEL's evolutionary search reliably discovers adversarial prompts that elicit hidden knowledge from unlearned models. Starting from benign forget‑set queries, a hacker LLM generates a population of mutated prompts. Each prompt is sent to the target unlearned model; a judge evaluates the response against the hidden answer, producing a leakage score. Top‑K prompts by score are retained and mutated again. This evaluate‑select‑mutate cycle iterates until a prompt triggers a leak or the budget is exhausted. The approach assumes the hacker can produce semantically meaningful mutations and that the judge's score reflects progress. Evidence from the paper includes the algorithmic description (Section 3.2, Figure 2) and the high ASR results. If the judge underestimates partial leaks or the hacker fails to diversify, the search may stagnate.

### Dense Judge Signal
Using an LLM as a judge provides a dense, interpretable signal that guides prompt evolution more effectively than binary success/failure. The judge outputs a continuous score in [0,1] indicating how much the response reveals the hidden answer. This continuous ranking allows incremental progress even when the answer is not fully leaked. The paper describes two scoring options: an LLM judge for generative tasks and a logit‑loss for multiple‑choice. Ablations confirm that scores ≥0.95 correspond to exact or detailed paraphrases, while borderline scores (~0.80) capture partial leakage, demonstrating consistency. A poorly calibrated judge could mislead the evolution.

### Failure of Static Metrics
Standard unlearning metrics (benign probe accuracy, likelihood, ROUGE) fail to predict vulnerability to adaptive adversarial probing, thus underestimating residual knowledge. REBEL compares ASR with traditional forgetting metrics (1‑ROUGE‑L, 1‑Prob, 1‑AccBio) and relearning dynamics, showing large mismatches: e.g., NPO vs. SimNPO have similar standard metrics but vastly different ASR. This indicates that static metrics only measure surface suppression, not robust forgetting, and that adversarial probing exposes a distinct failure mode.

## Architecture Onboarding
### Component Map
Target Model (MU) → Hacker Model (MH) → Judge Model (MJ) → Evolution Controller (which then feeds back to MH). The Evolution Controller orchestrates initialization, iteration, top‑K selection, and termination. The loop is: Controller initializes population → MH modifies prompts → MU responds → MJ scores → Controller selects elites → repeat.

### Critical Path
1. Receive forget‑set query *q* and hidden answer *a*.
2. Initialize population *P* with *q*.
3. For each iteration (max 5):
   a. For each prompt *p*∈*P*, query MU to get response *y*.
   b. Evaluate *y* with MJ to obtain score *s*.
   c. If *s* exceeds leak threshold, return *p* as successful jailbreak.
   d. Else, select top‑K prompts by *s*.
   e. Use MH to mutate each selected prompt *m* times, forming new *P*.
4. If max iterations reached without success, return FAILURE.

### Design Tradeoffs
- **Black‑box vs. white‑box:** REBEL uses only query access, making it widely applicable but less sample‑efficient than gradient‑based attacks.
- **Judge reliability:** LLM judge handles generative tasks flexibly but requires calibration; logit judge is precise for multiple‑choice but inflexible.
- **Mutation strategy:** Score‑tiered instructions (low/medium/high) adapt mutation magnitude; heuristic balances exploration/exploitation but depends on MH’s instruction following.
- **Population schedule:** Larger initial *m* (exploration) discovers diverse jailbreaks early; smaller later *k* (exploitation) refines; hybrid schedules optimize cost‑vs‑leakage.

### Failure Signatures
- **Stagnation:** No score improvement over several iterations → judge inconsistency or MH’s mutation failure.
- **Judge degeneration:** MJ outputs uniform scores → loss of discriminative power.
- **Overfitting to judge:** Prompts that include the hidden answer verbatim but do not actually leak from MU due to misalignment.
- **Budget exhaustion:** FAILURE return; could indicate truly effective unlearning or suboptimal hyperparameters.

### First 3 Experiments
1. **Sanity check:** Run REBEL on a non‑unlearned (original) model. Expect near‑100% ASR quickly, confirming the loop can find leaks when knowledge is present.
2. **Judge calibration:** Sample 100 prompt‑response pairs from an early REBEL run; have a human annotate leakage. Compute agreement (e.g., Cohen’s κ) between human and MJ scores to verify reliability.
3. **Ablate mutation strategy:** Compare ASR using score‑tiered instructions versus uniform mutation (no tiering) on a small subset (e.g., 50 samples). This validates the adaptive guidance for MH.

## Open Questions the Paper Calls Out
1. **Augmenting unlearning objectives:** How can machine unlearning objectives be augmented to ensure robustness against adaptive adversarial prompting such as REBEL's evolutionary jailbreaks? The authors suggest incorporating jailbreak prompts as additional training signal. Current methods optimize for suppression under benign queries but fail under adaptive attacks, leaving a gap. Resolution would require a new unlearning algorithm that integrates adversarial prompt generation, showing reduced ASR without harming retention.
2. **Algorithmic properties influencing vulnerability:** What specific properties of unlearning algorithms (e.g., objective functions, optimization strategies) determine their vulnerability to REBEL's evolutionary attacks? Results show large ASR variance across methods despite similar standard scores, but the paper does not analyze why. An ablation correlating algorithmic choices (use of reference models, loss shaping, KL penalties) with adversarial recoverability across benchmarks would help.
3. **Judge reliability and bias:** How reliable is the LLM‑based judge used in REBEL for detecting subtle knowledge leakage, and how does its bias affect reported attack success rates? The authors acknowledge the judge may miss subtle disclosures, biasing ASR downward, and manual validation shows some calibration. A large‑scale human evaluation comparing judge scores to human annotations, possibly leading to a more robust metric, is needed.
4. **Poor correlation of standard metrics:** Why do standard forgetting metrics (e.g., likelihood on forget set, ROUGE‑L) correlate poorly with adversarial recoverability as measured by REBEL? This undermines confidence in current evaluation standards. A theoretical or empirical analysis identifying which aspects of model behavior are captured by benign metrics but not adversarial ones, or vice versa, would clarify the discrepancy.

## Limitations
- **Reproducibility:** ASR numbers depend on access to the exact unlearned target models, which are not publicly released yet.
- **Underspecified judge details:** Calibration threshold and prompt structure are insufficiently described, risking score inconsistencies across implementations.
- **Hyperparameter sensitivity:** Evolutionary parameters (population sizes, mutation counts) are tightly tuned; performance may degrade with different compute budgets or model scales.

## Confidence
