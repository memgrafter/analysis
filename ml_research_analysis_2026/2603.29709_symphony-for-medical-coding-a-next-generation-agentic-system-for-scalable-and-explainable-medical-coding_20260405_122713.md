# Symphony for Medical Coding: A Next-Generation Agentic System for Scalable and Explainable Medical Coding

## Quick Facts
- **arXiv ID:** 2603.29709
- **Source URL:** https://arxiv.org/abs/2603.29709
- **Reference count:** 15
- **Primary result:** Symphony achieves state-of-the-art medical coding performance (e.g., 64.1 F1 on ACI), outperforms leading foundation models, provides span-level evidence for 98.9% of predictions, and adapts to new coding systems without retraining.

## Executive Summary
Symphony is an agentic system that automates medical coding by mimicking the reasoning process of human experts. It decomposes the task into four sequential steps—evidence extraction, index navigation, tabular validation, and code reconciliation—with each step implemented as an LLM-powered agent that directly consults official coding guidelines. Evaluated across five diverse datasets (inpatient, outpatient, emergency, subspecialty) in the US and UK, Symphony sets new performance benchmarks, outperforms models like GPT-4 and Claude, and delivers transparent, span-level explanations for its predictions, enabling auditability and trust in clinical workflows.

## Method Summary
Symphony employs a pipeline of four specialized agents without any supervised training. The Evidence Extractor identifies relevant clinical concepts and supporting text spans. The Index Navigator searches the alphabetic index of the coding ontology to find corresponding terms. The Tabular Validator navigates the hierarchical code tables to select the most precise code, enforcing inclusion/exclusion rules. Finally, the Code Reconciler applies mutual exclusivity constraints. Agents access structured, machine-readable versions of official guidelines (e.g., ICD-10-CM), enabling dynamic reasoning over the full code space rather than a fixed label set. This design supports zero-shot adaptation to new coding systems by simply updating the guideline resources.

## Key Results
- **State-of-the-art performance:** Achieves micro-F1 scores of 64.1 on ACI-BENCH (outpatient) and 65.2 on AMB (ambulatory), surpassing all baselines including GPT-4, Claude, and Gemini under full-code evaluation.
- **Explainability:** Provides span-level evidence for 98.9% of predictions, with character-level F1 of 0.459 and span IoU of 0.471 against human annotations on MDACE.
- **Adaptability:** Transfers to the UK NHS ICD-10 system (NEURO dataset) without retraining, scoring 32.9 F1 vs. 18.1 for GPT-4.

## Why This Works (Mechanism)

### Mechanism 1: Structured Workflow Mirrors Human Expert Reasoning
- **Claim:** Decomposing medical coding into discrete, guideline-grounded steps improves accuracy and generalizability compared to end-to-end classification.
- **Mechanism:** The four-pillar agentic pipeline explicitly follows the cognitive steps human coders use: extracting evidence, consulting the alphabetic index, validating against tabular rules, and reconciling conflicts. Each agent has direct, structured access to the official coding guidelines, enabling ontology-aware reasoning.
- **Core assumption:** The explicit, sequential process is more robust and interpretable than training a model on historical code assignments.
- **Evidence anchors:** Abstract states Symphony "reason[s] over the clinical narrative with direct access to the coding guidelines"; Section 3.1 defines the four pillars; neighboring papers (e.g., "Code Like Humans") validate the paradigm.
- **Break condition:** If guidelines are not available in a machine-readable, regularly structured format, the workflow cannot execute as designed, reverting to less accurate generic text-to-code mapping.

### Mechanism 2: Open-Set Reasoning Enables Scalability and Adaptation
- **Claim:** By avoiding training on a closed label set, Symphony dynamically handles the full, evolving code ontology and adapts to new systems without retraining.
- **Mechanism:** At inference, agents query the provided structured coding resources (e.g., the entire ICD-10-CM index and tables) to search, match, and validate codes. This eliminates the need to bake a specific code set into model parameters.
- **Core assumption:** LLMs can effectively navigate the semantic and structural relationships within a coding ontology via tool-like access, without gradient-based fine-tuning on that ontology.
- **Evidence anchors:** Abstract notes "without retraining"; Section 3.1 states CLH supports "open-set coding" and robustness on rare codes; Table 5 shows strong zero-shot transfer to UK ICD-10.
- **Break condition:** If a new coding system has a radically different structure (e.g., no alphabetic index), the agents' retrieval and navigation prompts may fail without adaptation.

### Mechanism 3: Early Evidence Extraction Guarantees Explainability
- **Claim:** Span-level evidence is naturally produced by isolating the extraction step, enabling transparent audit trails.
- **Mechanism:** The first agent extracts text spans that justify clinical concepts, which are carried forward and linked to final codes. The output always includes these spans, creating a direct, human-verifiable connection between note and code.
- **Core assumption:** Evidence extraction is a separable and reliable sub-task; extracted spans remain valid through mapping and validation steps.
- **Evidence anchors:** Abstract mentions "span-level evidence"; Section 4.2.4 reports 98.9% coverage and span-level F1 scores on MDACE; Section 3.1 highlights explainability for validation and review.
- **Break condition:** If the clinical text lacks explicit mentions (e.g., inferred diagnoses), the extractor may miss evidence, causing false negatives that later steps cannot recover.

## Foundational Learning

1. **Coding Guidelines & Ontology Structure**  
   *Why needed:* Agents must interpret official documents (e.g., ICD-10-CM Official Guidelines) that define inclusion/exclusion rules, sequencing, and hierarchies.  
   *Quick check:* For "acute myocardial infarction," which guideline sections do Index Navigation and Tabular Validation consult to distinguish I21.3 from I21.9?

2. **Agentic Workflow Design**  
   *Why needed:* The system's strength lies in decomposing a complex task into discrete, LLM-executable steps with clear inputs/outputs.  
   *Quick check:* What precise output format does Evidence Extraction produce for Index Navigation, and what failure modes can occur at this interface?

3. **Retrieval-Augmented Reasoning over Structured References**  
   *Why needed:* Agents do not rely solely on parametric knowledge; they perform constrained lookups in coding resources (index, tables).  
   *Quick check:* How does Tabular Validation resolve multiple valid code options from an index term (e.g., "see code also")? What guideline principle guides the final selection?

## Architecture Onboarding
- **Component map:** Input Processor -> Agent 1 (Evidence Extractor) -> Agent 2 (Index Navigator) -> Agent 3 (Tabular Validator) -> Agent 4 (Code Reconciler) -> Output Formatter. Guideline Loader indexes structured documents for Agents 2 and 3.
- **Critical path:** The sequential agent chain; failure at any step halts or corrupts subsequent processing.
- **Design tradeoffs:**  
  - *Structured guidelines vs. speed:* Using explicit documents ensures auditability but adds latency.  
  - *Granular evidence vs. cost:* Fine spans increase explainability but token usage.  
  - *Agent specialization vs. overhead:* Four agents improve accuracy but increase LLM calls and orchestration complexity.
- **Failure signatures:**  
  - High recall, low precision: Evidence Extractor too permissive or Validation weak.  
  - Low recall, high precision: Evidence Extractor too conservative or Index Navigation failing.  
  - Missing evidence spans (<98.9%): Extraction prompt inadequate.  
  - Poor performance on new ontology (e.g., NEURO): Guideline Loader or agent prompts not general.
- **First 3 experiments:**  
  1. Unit test agent interfaces with a simple sentence (e.g., "Type 2 diabetes" → E11.9) to isolate pipeline breaks.  
  2. Stress test guideline robustness by reformatting a section of ICD-10-CM guidelines and measuring performance change.  
  3. Ablate Tabular Validator by replacing it with a "first-code-from-index" rule; quantify F1 drop on MDACE.

## Open Questions the Paper Calls Out
1. **Label noise and conservative coding practices** – Discrepancies in UK NEURO dataset may stem from broader reference annotations reflecting NHS conservatism, not model error. Unresolved: How to evaluate when gold standards are subjective?
2. **Incomplete clinical documentation** – Missing operation notes in MDACE likely hurt procedure coding. Unresolved: How does Symphony perform when key sections (e.g., operative reports) are absent, as common in emergency settings?
3. **Computational scalability and latency** – No reported throughput or resource use under load. Unresolved: Can the multi-agent workflow handle high-volume, concurrent real-world deployments?

## Limitations
- Exact prompting templates, state management, and error handling are undisclosed, hindering exact replication.
- Performance is sensitive to LLM version and prompt engineering; results may not generalize across models.
- System requires coding guidelines in machine-readable, regularly structured formats; deviations could break the workflow.
- No statistical significance testing; cost, latency, and integration challenges are unexplored.

## Confidence
- **Performance superiority** (SOTA on five datasets): Medium – strong results but lack independent verification and may be prompt-sensitive.
- **Zero-shot adaptation** to new coding systems: Medium – promising NEURO results but untested across diverse guideline structures.
- **Explainability** (span-level evidence, 98.9% coverage): High – directly evaluated against human annotations.
- **Multi-step workflow necessity**: Low – no systematic ablation isolating each agent’s contribution.

## Next Checks
1. **Exact replication:** Re-run the full pipeline on ACI and MDACE using the same LLM (e.g., GPT-4) and report micro-F1; acceptable variance <2%.
2. **Ablation of Tabular Validator:** Replace the Tabular Validator with a "first-code-from-index" rule and measure F1 drop on MDACE; quantifies the validation step’s value.
3. **Cross-format robustness:** Apply Symphony to a guideline with a different structure (e.g., SNOMED CT or manually reformatted ICD-10) and evaluate performance degradation; tests generalizability beyond US-style documents.
