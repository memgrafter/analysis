# On-Device Super Resolution Imaging Using Low-Cost SPAD Array and Embedded Lightweight Deep Learning

## Quick Facts
*   **arXiv ID:** 2603.27018
*   **Source URL:** https://arxiv.org/abs/2603.27018
*   **Reference Count:** 23
*   **Primary Result:** A 363.80 KB quantized CNN enables 4.5 fps video streaming from a 32x48 SPAD array to 256x256/512x512 outputs on an Arduino UNO Q, with depth SSIM up to 0.995 and intensity MS-SSIM up to 0.963 on synthetic data.

## Executive Summary
This paper introduces LiteSR, a lightweight dual-branch convolutional neural network designed for joint super-resolution (SR) of intensity and depth maps from a low-resolution (32x48) SPAD array sensor. The model uses a bicubic residual learning framework with separate branches for each modality, where the intensity branch guides the depth reconstruction. It achieves high-fidelity results on synthetic datasets and demonstrates successful deployment on a resource-constrained Arduino UNO Q microcontroller through aggressive INT8 quantization, enabling real-time video-rate streaming with a small memory footprint.

## Method Summary
LiteSR employs a dual-branch CNN architecture. The intensity branch processes the raw SPAD data to generate a high-resolution intensity image. Its features, via a guidance mechanism, condition the depth branch, which reconstructs the high-resolution depth map. The core learning objective is residual prediction against a bicubic upsampled baseline. For embedded deployment, the full-precision model (1.36 MB for 4x SR) is quantized to INT8, reducing the size by 74% to 363.80 KB with minimal performance drop, facilitating execution on microcontrollers.

## Key Results
*   On synthetic SPAD data, LiteSR achieves depth SSIM/PSNR up to 0.995/49.32 dB and intensity MS-SSIM/PSNR up to 0.963/30.42 dB for 4x/8x SR, significantly outperforming bicubic interpolation.
*   Embeddability: A quantized 4x SR model runs at ~4.5 fps with 172.8 ms latency on an Arduino UNO Q.
*   Model size is reduced from 1.36 MB (FP32) to 363.80 KB (INT8) for 4x SR, demonstrating scalable efficiency.

## Foundational Learning
*   **SPAD Array Imaging:** Single-Photon Avalanche Diode arrays capture time-correlated single-photon data, providing low-resolution intensity and depth (via Time-of-Flight) but with high temporal resolution and low light requirements. *Why needed:* Defines the low-cost, low-resolution input sensor constraints. *Quick check:* Understands the raw data format (histogram/timestamp per pixel).
*   **Super-Resolution (SR) / Bicubic Interpolation:** SR reconstructs a high-resolution image from a low-resolution input. Bicubic interpolation is a classical baseline using smooth polynomial fitting. *Why needed:* Establishes the task and the simplest baseline to beat. *Quick check:* Knows bicubic smooths edges and may lose high-frequency detail.
*   **Residual Learning:** A neural network learns to predict the *difference* (residual) between a target and a simple baseline (e.g., bicubic upsampled input). *Why needed:* Stabilizes and accelerates training for mapping low-res to high-res; easier for network to learn fine details. *Quick check:* Recognizes the output is `HR = Bicubic(LR) + Network(LR)`.
*   **Dual-Branch / Modality-Specific Networks:** Separate neural pathways process different input data types (intensity vs. depth) before fusion. *Why needed:* Depth and intensity have different statistical properties and optimal feature representations; separate branches prevent interference. *Quick check:* Identifies branches are merged/conditioned later, not processed identically.
*   **Cross-Modality Guidance / Conditioning:** Features from one modality (intensity) are used to influence or weight the processing of another (depth). *Why needed:* Depth from SPADs is noisy; high-resolution intensity edges provide strong structural priors to regularize depth reconstruction. *Quick check:* Looks for feature transfer (e.g., addition, multiplication, attention) from intensity branch to depth branch.
*   **Post-Training Quantization (INT8):** Converting a model's weights and activations from 32-bit floating point to 8-bit integers after training. *Why needed:* Drastically reduces model size and computational cost for memory-constrained microcontrollers. *Quick check:* Confirms quantization-aware training or simple PTQ was used and accuracy drop was minimal.

## Architecture Onboarding
**Component Map:**
Low-Res SPAD Data (Intensity+Depth) -> Shared Initial Conv -> Intensity Branch -> Intensity Features -> Intensity-SR Output & Guidance Signal -> Depth Branch (using Guidance) -> Depth-SR Output

**Critical Path:** The critical path flows from input through the shared convolutional stem, then bifurcates. The intensity branch processes independently to produce its output and guidance features. The depth branch's reconstruction is critically dependent on receiving and utilizing this intensity guidance signal before its final layers.

**Design Tradeoffs:**
*   **Accuracy vs. Speed/Size:** The use of a simple CNN (vs. transformers) and aggressive INT8 quantization prioritizes embedded feasibility over synthetic SOTA performance.
*   **Modality Separation vs. Early Fusion:** Separate branches increase parameter count slightly but allow specialized processing vs. a single multi-channel input network.
*   **Bicubic Residual Target:** Stabilizes training but may limit maximum achievable quality if the bicubic baseline is very poor for certain patterns.

**Failure Signatures:**
*   **Depth Failure:** Loss of fine geometric detail, oversmoothing, or "copy-paste" of intensity edges without proper disparity scaling, visible as inconsistent depth at object boundaries.
*   **Intensity Failure:** Blurring of high-frequency texture, ringing artifacts, or color/brightness shifts (if color SPAD data was used, not specified).
*   **Deployment Failure:** Inference latency spikes or crashes on constrained MCU due to buffer overflow (unquantized models) or unsupported operations.

## Limitations
*   **Real-World Validation Sparse:** Claims beyond synthetic data rely on qualitative metrics (Laplacian variance, visual smoothness) without quantitative comparison to a synchronized high-resolution ground truth.
*   **Baseline Narrowness:** Primary comparison is to bicubic interpolation, not to other modern lightweight SR networks, making the efficiency-performance trade-off claim less absolute.
*   **Hardware Specificity:** Embedded results are validated only on the niche Arduino UNO Q; generalizability to other common embedded platforms (Raspberry Pi, STM32) is not established.
