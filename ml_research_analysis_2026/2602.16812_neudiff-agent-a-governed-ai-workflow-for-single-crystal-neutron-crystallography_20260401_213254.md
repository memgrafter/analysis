# NeuDiff Agent: A Governed AI Workflow for Single-Crystal Neutron Crystallography
## Quick Facts
- **arXiv ID:** 2602.16812
- **Source URL:** https://arxiv.org/abs/2602.16812
- **Reference count:** 3
- **Primary result:** Automates the TOPAZ reduction-integration-refinement-validation pipeline under explicit governance, achieving a 4.6–5.0× speedup (435 min → ~90 min) and producing a publication-ready CIF with zero checkCIF level A or B alerts.

## Executive Summary
Analysis of neutron single-crystal diffraction data is bottlenecked by manual, expert-intensive processing. NeuDiff Agent addresses this by automating the complete TOPAZ instrument pipeline using a tool-using large language model (LLM) operating within a governed framework. This framework constrains the agent to an allowlist of validated tools, enforces fail-closed verification gates at critical workflow stages, and records full provenance. In a benchmark on a standard dataset, the system reduced end-to-end wall time by nearly fivefold while delivering a structurally refined CIF that passes standard validation without alerts, demonstrating that rigorous governance can enable both acceleration and reliability in a high-stakes scientific workflow.

## Method Summary
NeuDiff Agent orchestrates the TOPAZ data processing chain—reduction, integration, refinement, and validation—via an LLM controller that executes predetermined, allowlisted tools (e.g., Mantid scripts, SHELXL). The workflow is defined as a state machine where progression to the next stage requires passing a verification gate. These gates perform automated checks on intermediate outputs; failure triggers a "fail-closed" halt, requiring explicit human authorization to proceed or intervene. All actions, tool invocations, and gate outcomes are logged for complete provenance. The benchmark compared automated runs (using Gemini and GPT-OSS) against a manual expert reference on the scolecite dataset, measuring total time and final CIF quality via checkCIF.

## Key Results
- **4.6–5.0× speedup:** End-to-end wall time reduced from 435 minutes (manual) to 86.5 ± 4.7 minutes (Gemini) and 94.4 ± 3.5 minutes (GPT-OSS).
- **Zero high-severity alerts:** The final deposited CIF contained no checkCIF level A or B alerts, meeting a key publication standard.
- **Governed automation:** The fail-closed gate design prevented propagation of errors, with human interventions occurring only at gate failures.

## Why This Works (Mechanism)
NeuDiff Agent succeeds by embedding safety and accountability directly into the automation framework. The allowlist restricts the LLM to a curated set of well-defined, instrument-specific tools, preventing "creative" but incorrect tool usage. Fail-closed verification gates act as automated quality control checkpoints; they rigorously test intermediate products (e.g., reduced data quality, refinement convergence) before workflow continuation, ensuring errors are caught early and requiring human judgment only for exceptional cases. Full provenance recording creates an immutable audit trail, enabling reproducibility and post-hoc analysis of any intervention. This governance model balances the LLM's speed in executing routine steps with human expert oversight precisely where uncertainty is highest.

## Foundational Learning
- **Tool-using LLM:** Why needed:To automate specialized scientific software without requiring the LLM to re-implement domain logic. Quick check:Can the LLM correctly select tool parameters based on prior stage outputs?
- **Fail-closed verification gates:** Why needed:To automate error detection and prevent silent failure propagation in a multi-step pipeline. Quick check:Do gates reliably reject outputs that violate predefined acceptance criteria (e.g., poor data statistics)?
- **Provenance recording:** Why needed:To generate a reproducible, auditable record of every decision and data transformation for scientific rigor. Quick check:Can the entire workflow be reconstructed from logs, including all interventions?
- **Allowlist constraint:** Why needed:To limit the agent's action space to safe, validated operations, reducing attack surface and unexpected behavior. Quick check:Is the agent ever observed attempting to call tools outside the allowlist?
- **Human-in-the-loop at gates:** Why needed:To leverage expert judgment for ambiguous failures that automated checks cannot resolve. Quick check:Are interventions infrequent and do they typically resolve the blocking issue?

## Architecture Onboarding
**Component map:** User -> LLM Agent -> [TOPAZ Reduction Tool -> Gate 1 -> TOPAZ Integration Tool -> Gate 2 -> Refinement Tool -> Gate 3 -> Validation Tool -> Gate 4] -> Final CIF & Provenance Log.  
**Critical path:** Data receipt → Reduction (Mantid) → Integration → Structure refinement (SHELXL) → Validation (checkCIF) → CIF output.  
**Design tradeoffs:** Strict governance (allowlist, gates) adds overhead and may increase interventions but is prioritized over raw speed to ensure reliability for publication. The system is highly specialized for TOPAZ, sacrificing generality for deep optimization of one instrument's pipeline.  
**Failure signatures:** 1) Gate rejection (most common), 2) Tool execution error (e.g., timeout, crash), 3) LLM tool-selection error (mitigated by allowlist).  
**First three experiments:** 1) Execute the full workflow on the provided scolecite benchmark dataset to verify baseline functionality and timing. 2) Deliberately corrupt intermediate data (e.g., bad mask) to trigger each gate and measure detection sensitivity. 3) Run the pipeline with a novice user handling gate interventions to assess usability and decision burden.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How general and robust are the current fail-closed verification gates across diverse TOPAZ datasets with varying crystal systems, experimental conditions, and data quality?
- Basis in paper: [explicit] The Conclusion states: "Extending controlled replay to additional TOPAZ datasets spanning varied crystal systems, experimental conditions, and data quality will quantify how general the current verification gates are and identify failure modes that require new checks or improved tool wrappers."
- Why unresolved: The evaluation is limited to a single reference-case benchmark (scolecite dataset), so the gates' performance on other dataset types remains untested.
- What evidence would resolve it: Repeating the controlled replay protocol with a statistically significant set of diverse TOPAZ datasets, measuring gate failure rates, intervention frequencies, and final CIF validation outcomes to assess generality.

### Open Question 2
- Question: To what extent can the NeuDiff Agent framework, with its governed workflow and provenance model, be adapted and deployed for other neutron or X-ray diffraction instruments that have different reduction-integration-refinement pipelines?
- Basis in paper: [inferred] The paper focuses exclusively on TOPAZ-specific tools (e.g., Mantid scripts for TOPAZ, SHELXL integration) and does not discuss portability; the state machine and allowlisted tools are tailored to TOPAZ's workflow.
- Why unresolved: The system design is instrument-specific, and no evidence is provided on cross-instrument generalizability, leaving assumptions about adaptability unverified.
- What evidence would resolve it: Implementing NeuDiff Agent for a different instrument (e.g., another neutron diffractometer or an X-ray system), mapping its tools and states to the new workflow, and evaluating if governance and provenance benefits persist.

### Open Question 3
- Question: How does the user's level of crystallographic expertise influence the intervention burden, recovery efficiency, and overall time-to-result when interacting with the governed workflow?
- Basis in paper: [inferred] The benchmark uses a fixed prompt protocol and human-in-the-loop at gates, but user expertise is not varied or reported; the system assumes user authorization for corrections without accounting for skill differences.
- Why unresolved: The evaluation likely involves experienced users (given the manual reference run), but the paper does not address whether novice users would face higher intervention rates or longer decision times, which impacts scalability.
- What evidence would resolve it: Conducting controlled user studies with participants spanning novice to expert levels, measuring metrics like number of interventions per gate, time spent on authorizations, and final success rates under identical workflow conditions.

## Limitations
- Benchmark limited to a single dataset (scolecite), preventing assessment of generality across crystal systems and data qualities.
- Governance implementation specifics (exact allowlist, gate thresholds, wrapper logic) are not detailed, hindering replication and independent stress-testing.
- "Publication-ready" claim relies solely on absence of checkCIF A/B alerts; other quality dimensions (e.g., chemical reasonableness, higher-level validation) are unevaluated.
- Provenance completeness and its utility for real-world debugging or audit are asserted but not demonstrated in a collaborative or regulatory context.

## Confidence
- **Automation feasibility:** Medium (achieved on one dataset but robustness unproven).
- **Speedup (4.6–5.0×):** Medium (low standard deviation on test set suggests reliability, but sample size unknown).
- **Zero checkCIF alerts:** High for the specific tested data, but low for broad generalization due to limited dataset diversity.
- **Governance model (safety via allowlist/gates):** Low (conceptual framework presented; empirical validation of safety benefits is indirect and limited).

## Next Checks
