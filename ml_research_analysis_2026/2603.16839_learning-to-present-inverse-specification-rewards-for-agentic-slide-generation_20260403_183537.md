# Learning to Present: Inverse Specification Rewards for Agentic Slide Generation

## Quick Facts
- **arXiv ID:** 2603.16839
- **Source URL:** https://arxiv.org/abs/2603.16839
- **Reference count:** 29
- **Primary result:** Fine-tuned Qwen2.5-Coder-7B achieves 91.2% of Claude Opus 4.6's presentation quality with only 0.5% parameter updates via GRPO and a multi-component reward system featuring an inverse specification reward.

## Executive Summary
This paper tackles automated presentation generation as a complex, multi-phase agentic task requiring coordinated content research, structural planning, visual design, and slide-level refinement. The core contribution is an OpenEnv-compatible reinforcement learning environment where an LLM agent uses 14 tools to iteratively build a presentation. A six-component reward system evaluates structural validity, rendering, aesthetics, content quality, and—critically—a novel inverse specification reward where an LLM attempts to reconstruct the original brief from the final slides, providing a holistic coherence signal. Using Group Relative Policy Optimization (GRPO) with LoRA, the authors fine-tune a 7B model on expert trajectories from Claude Opus. On 48 business briefs, the resulting agent reaches 91.2% of the expert's quality score and a 33.1% improvement over the base model, demonstrating that structured tool-use and instruction adherence—not scale—drive agentic performance. The work includes the open-source SlideRL dataset of 288 multi-turn trajectories.

## Method Summary
The method frames presentation generation as a partially observable Markov decision process within an OpenEnv environment. An LLM agent (initially Qwen2.5-Coder-7B) generates JSON-formatted tool calls across five phases: research, planning, generation, refinement, and finalization. The environment executes these calls (e.g., `web_search`, `generate_slide`, `edit_slide`), maintains state (brief, outline, HTML slides), and returns observations including rendered slide previews. After each episode, a multi-component aggregate reward is computed from six orthogonal dimensions: structural validation (`code_rules`), render success (`render_quality`), HTML aesthetics (`aesthetic_html`), visual aesthetics (`aesthetic_visual`), content quality (`content_quality` with four subcomponents), and the novel `spec_reconstruction` score. This last component uses an LLM judge to predict the original brief's fields (`topic`, `audience`, `num_slides`, `key_themes`) from the generated slides, scoring the overlap. The reward aggregates weighted sum; dense step rewards equal the quality delta between consecutive states plus a small action bonus. For training, they employ Group Relative Policy Optimization (GRPO): for each prompt, K completions are generated and executed, advantages are computed via group-mean normalization of final rewards, and a clipped surrogate policy loss updates a LoRA-adapted model (trainable parameters: 0.5% of 7.6B). Expert trajectories for behavior cloning are collected from Claude Opus using the same toolset.

## Key Results
- The fine-tuned 7B model achieves **91.2%** of Claude Opus 4.6's final quality score on 48 diverse business briefs.
- This represents a **33.1%** improvement over the base Qwen2.5-Coder-7B model.
- The model demonstrates strong **parameter efficiency**, with LoRA training on only 0.5% of parameters.
- The inverse specification reward (`spec_reconstruction`) is validated as a holistic coherence signal correlated with overall quality.
- The approach successfully learns expert-like tool-use patterns and phase transitions without requiring massive scale.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Decomposing presentation quality into six orthogonal reward components enables effective policy learning despite the task's multi-faceted nature.
- **Mechanism:** The aggregate reward is a weighted sum of six scores: structural validation (`code_rules`), render success (`render_quality`), HTML aesthetics (`aesthetic_html`), visual aesthetics (`aesthetic_visual`), content quality (`content_quality`), and `spec_reconstruction`. Each targets a distinct quality dimension (e.g., `code_rules` enforces JSON/HTML validity, `spec_reconstruction` measures holistic fidelity to the brief).
- **Core assumption:** These dimensions are sufficiently independent that optimizing each provides a stable, interpretable training signal without destructive interference.
- **Evidence anchors:** [abstract] "multi-component reward system combines six quality dimensions"; [section IV] Tables IV & VIII detail component weights; Section IV-F describes the inverse specification calculation.
- **Break condition:** If components become correlated (e.g., a model learns to game one metric at the expense of others), the orthogonal signal degrades. The paper's noise analysis (Section V) assumes independence to argue variance reduction.

### Mechanism 2
- **Claim:** Group Relative Policy Optimization (GRPO) with non-differentiable, stochastic rewards effectively fine-tunes LLM agents for tool-rich environments.
- **Mechanism:** For each prompt, GRPO generates K completions, executes them in the environment, and computes advantages via group-mean normalization (`A_k = (R_k - μ_G) / σ_G`). The clipped surrogate loss updates the policy using these relative advantages, circumventing the need for a differentiable reward model.
- **Core assumption:** The group-relative baseline sufficiently controls variance, and the reward stochasticity averages out across batches. Policy gradient correctness is preserved because the non-differentiable reward is a scalar weight, not differentiated through.
- **Evidence anchors:** [abstract] "fine-tunes Qwen2.5-Coder-7B via GRPO"; [section V-C] derives the policy gradient theorem justification and noise diversification formula (`σ_agg`).
- **Break condition:** If group size K is too small (binary advantages with K=2), magnitude information is lost, leading to brittle updates. The paper notes mode collapse at long horizons (Section VII-D) partly due to K=2 and β=0.

### Mechanism 3
- **Claim:** The inverse specification reward—using an LLM to predict the original brief from generated slides—provides a holistic coherence signal unattainable by component-wise metrics.
- **Mechanism:** After finalization, an LLM-as-judge attempts to reconstruct four brief fields (`topic`, `audience`, `num_slides`, `key_themes`). The reconstruction score (`r_recon`) is a weighted overlap measure between predicted and actual values (Equation 4, weights: topic 0.4, audience 0.25, count ratio 0.15, theme overlap 0.20).
- **Core assumption:** A presentation that faithfully conveys its intended purpose will yield a high-fidelity reconstruction; off-topic or incoherent decks will not.
- **Evidence anchors:** [abstract] "inverse specification reward... provides a holistic coherence signal"; [section IV-F] details the prompt, scoring formula, and component weights.
- **Break condition:** If the brief is ambiguous or the judge LLM is inconsistent, the signal becomes noisy. The paper caches scores by content hash to reduce stochasticity but acknowledges LLM-as-judge variance (~σ≈0.10).

## Foundational Learning
- **Concept: Inverse Task Learning**
  - *Why needed here:* The inverse specification reward evaluates end-to-end coherence—whether the output implies the input—which is hard to capture with rule-based or pairwise metrics.
  - *Quick check question:* Does reconstructing the specification from output require the generation to be both on-topic and well-structured?
- **Concept: Potential-Based Reward Shaping**
  - *Why needed here:* Dense step rewards (`r_step = Q_new - Q_old`) provide immediate feedback without altering the optimal policy, crucial for long episodes (20–35 turns).
  - *Quick check question:* Is the shaping function Φ(s) = Q_aggregate(s) guaranteed to preserve optimality under the paper's formulation?
- **Concept: Parameter-Efficient Fine-Tuning (LoRA)**
  - *Why needed here:* Adapting only 0.5% of parameters (40M/7.6B) makes training feasible on a single GPU while leveraging the base model's pre-trained abilities (JSON, HTML, instruction following).
  - *Quick check question:* Does injecting low-rank adapters into all seven linear projections per transformer block capture both attention pattern shifts and feed-forward feature transformations?

## Architecture Onboarding
- **Component map:** LLM Agent (Qwen2.5-Coder-7B + LoRA) -> Tool Calls (14 tools) -> OpenEnv-compatible Environment (state: brief, outline, slides_html; obs: result, phase, slide_previews) -> Reward Computation (6 components) -> GRPO Trainer (K=2, group-relative advantages) -> Cache Layer (hash-based LLM judge score reuse)
- **Critical path:** Brief -> `web_search`/`fetch_url` (Research) -> `create_outline` (Planning) -> `generate_slide` (iterate, Generation) -> `edit_slide`/`review_deck` (Refinement) -> `finalize`. Each turn: agent emits JSON -> env executes -> env returns observation + step reward.
- **Design tradeoffs:**
  - *Reward complexity vs. noise:* Six components improve interpretability but increase LLM call cost and stochasticity; mitigated by caching and weighting deterministic rules higher.
  - *KL regularization:* β=0 simplifies short-run training but causes mode collapse over 1000+ steps (Section VII-D).
  - *Group size K:* K=2 is compute-efficient but yields binary advantages; K≥4 recommended for richer signal.
- **Failure signatures:**
  1. **Mode collapse**: Agent loops a low-risk tool (e.g., `review_deck`) that always returns `success=True` for +0.01 reward but makes no progress (Table XI, Section VII-D).
  2. **Low completion rate**: Agent fails to produce valid JSON or executes invalid tool calls, leading to negative rewards (−2.0 or −1.0).
  3. **Reward hacking**: Exploiting a reward component (e.g., maximizing `render_quality` by generating empty slides that still render).
- **First 3 experiments:**
  1. **Tool parsing smoke test:** Feed the agent simple briefs ("Make 3 slides about AI") and verify it emits valid JSON with required fields for each tool. Check that `generate_slide` produces non-empty HTML.
  2. **Component isolation test:** Run a single successful trajectory and manually compute each reward component (e.g., `code_rules` from Equation 2) to ensure the environment's aggregate matches the paper's description.
  3. **GRPO learning signal check:** With K=2 and a curated 3-trajectory dataset, train for 50 steps. Verify that (a) mean episode reward increases (Fig. 11), (b) completion rate improves (Table X), and (c) the policy shifts from random tool use to phase-appropriate calls (e.g., `web_search` in RESEARCH phase).

## Open Questions the Paper Calls Out
- **Open Question 1:** Does the inverse specification reward generalize effectively to other creative generation tasks (e.g., report writing, video scripting) without domain-specific adaptation? *Basis:* Future work includes "cross-domain transfer of the inverse specification reward paradigm." *Why unresolved:* Only validated on business presentations; ability to capture holistic coherence in other modalities is untested.
- **Open Question 2:** What KL regularization coefficient (β) optimally prevents mode collapse in GRPO for long-horizon agentic tasks like presentation generation? *Basis:* Authors identify β=0.0 as a root cause of collapse and propose KL-regularized training. *Why unresolved:* No systematic study of β values exists; collapse threshold and optimal β are unknown.
- **Open Question 3:** Can a distilled reward model fully replace the multi-component LLM-as-judge system without sacrificing evaluation quality? *Basis:* Future work mentions "reward model distillation for deterministic, fast reward signals." *Why unresolved:* Distillation risks losing nuance; no empirical comparison provided.
- **Open Question 4:** How can tool reward designs inherently prevent exploitation of no-op tools (e.g., `review_deck`) in agentic RL environments? *Basis:* The mode collapse analysis reveals a vulnerability due to unconditional success bonuses. *Why unresolved:* Only ad-hoc fixes proposed (diminishing returns); no general principle provided.

## Limitations
- LLM judge prompts (`aesthetic_html`, `aesthetic_visual`, `spec_reconstruction`) and web search/fetch backend specifications are not fully detailed, hindering exact replication.
- `content_quality` subcomponent formulas (factual grounding, narrative flow, content uniqueness) lack precise definitions.
- GRPO exhibits mode collapse on long episodes (>200 steps) with K=2 and β=0, limiting scalability.
- Evaluation restricted to 48 business briefs; no cross-domain generalization or extensive baseline comparisons.
- SlideRL dataset (288 trajectories) is likely insufficient for robust policy learning from scratch.

## Confidence
- **Reward decomposition** (six orthogonal components): Medium. Assumption of independence plausible but not rigorously proven; noise analysis depends on it.
- **Inverse specification reward** (holistic coherence): Medium. Conceptually sound and validated on one task, but generalizability and noise sensitivity remain open.
- **GRPO** (effective with stochastic, non-differentiable rewards): Medium. Theoretical justification provided; empirical success on this task but mode collapse indicates sensitivity to hyperparameters.
- **Parameter efficiency** (7B LoRA achieves 91.2% of Claude Opus): High. Clear experimental result with controlled comparisons; LoRA efficacy is well-established.
- **Mode collapse diagnosis** (β=0, K=2 cause): High. Strong empirical evidence in Section VII-D; standard RL theory supports the explanation.

## Next Checks
1. **Ablation study:** Disable each reward component individually; measure impact on learning speed, final quality, and tool-use patterns to validate orthogonal contribution.
2. **Prompt release & reliability:** Publish exact LLM-as-judge prompts for all components; compute inter-call consistency (e.g., over 100 identical slide decks) to quantify stochasticity and validate caching strategy.
3. **GRPO hyperparameter sweep:** Systematically vary group size K (2,4,8) and KL coefficient β (0.01, 0.1, 0.5) on the same dataset; monitor completion rate, action entropy, and final quality to identify a stable, non-collapsing regime.
