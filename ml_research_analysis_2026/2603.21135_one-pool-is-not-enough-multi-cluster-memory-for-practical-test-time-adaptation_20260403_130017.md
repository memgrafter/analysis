# One Pool Is Not Enough: Multi-Cluster Memory for Practical Test-Time Adaptation

## Quick Facts
- arXiv ID: 2603.21135
- Source URL: https://arxiv.org/abs/2603.21135
- Reference count: 40
- Primary result: MCM reduces classification error by 2.96% on average and up to 12.13% on DomainNet compared to single-cluster memory baselines.

## Executive Summary
Practical test-time adaptation (PTTA) deals with adapting a pre-trained model to non-stationary test streams that exhibit temporal correlations. Standard memory-based TTA methods use a single memory pool, which fails to capture the inherent multi-modality of such streams, leading to imbalanced supervision and suboptimal adaptation. This paper proposes Multi-Cluster Memory (MCM), which partitions stored samples into multiple clusters using lightweight pixel-level descriptors. MCM introduces Adjacent Cluster Consolidation (ACC) to control memory growth and Uniform Cluster Retrieval (UCR) to ensure balanced sampling across all modes during adaptation. Integrated with three existing memory-based TTA methods across four benchmarks (CIFAR-10-C, CIFAR-100-C, ImageNet-C, DomainNet), MCM achieves consistent error reductions averaging 2.96% and up to 12.13% on DomainNet. Diagnostic analyses confirm that MCM maintains superior memory balance, entropy, and mode coverage compared to single-cluster designs.

## Method Summary
MCM replaces the single memory bank of existing TTA methods with a dynamic multi-cluster structure. Each incoming test sample is described by its channel-wise mean and variance across spatial dimensions, yielding a compact descriptor. Using Euclidean distance, the sample is assigned to the nearest cluster centroid if within threshold τ (default 0.3); otherwise a new cluster is created. Each cluster can store up to N samples (e.g., 64). When the total number of clusters exceeds a maximum K_max (derived from number of classes), Adjacent Cluster Consolidation merges the two closest clusters in terms of centroid distance, preserving temporal adjacency to avoid losing complementary modes. To retrieve samples for adaptation, MCM employs Uniform Cluster Retrieval: it samples an equal number of samples from each active cluster, ensuring that all represented modes contribute equally to the gradient. The adaptation step then uses the retrieved set with the chosen TTA method’s loss (e.g., consistency between student and teacher in a Mean Teacher framework). The teacher model is updated via exponential moving average. This design maintains a balanced and representative memory even as the test stream evolves through multiple domains.

## Key Results
- Average error reduction of 2.96% across corruption benchmarks; up to 12.13% on DomainNet.
- Performance gains scale with the complexity of the label space.
- MCM demonstrates superior memory balance, entropy preservation, and mode coverage compared to single-cluster memory.

## Why This Works (Mechanism)
The core mechanism is recognizing that practical test streams, despite temporal correlation, contain multiple distinct distributional modes due to different corruptions or domains. Gaussian Mixture Model analysis on sliding windows of test data consistently yields an optimal number of components far greater than one (µK* >5), proving that the target distribution is inherently multi-modal. This invalidates the single-cluster memory assumption and motivates a design that can maintain multiple clusters.

To realize this, MCM employs pixel-level channel statistics (mean and variance per channel) as lightweight descriptors. These directly reflect low-level image variations caused by common corruptions (e.g., noise, blur) and are more discriminative for clustering than high-level CNN features. Each sample is assigned to its nearest cluster centroid if within a threshold τ; otherwise a new cluster is spawned. This creates clusters aligned with appearance modes. Empirical validation shows that using pixel-stat descriptors reduces error by over 10 percentage points compared to CNN features on CIFAR-100-C.

Once clusters are formed, MCM ensures balanced supervision via Uniform Cluster Retrieval (UCR): during adaptation, it samples an equal number of memory samples from each cluster. This prevents any single mode from dominating the gradient, a common failure of single-cluster memory. To manage memory growth, Adjacent Cluster Consolidation (ACC) merges the closest pair of temporally adjacent clusters when the cluster count exceeds a set maximum, preserving historical mode coverage. The combination of these components yields sustained memory balance, high entropy, and comprehensive mode coverage, directly translating into improved adaptation performance.

## Architecture Onboarding
**Component map**:  
Stream processor → Descriptor extractor → Cluster manager → Retrieval module → Adaptation engine

**Critical path**:  
1. Receive a test batch.  
2. For each sample, compute descriptor (channel-wise mean/variance).  
3. Cluster manager: assign to nearest cluster if distance to centroid ≤ τ; else spawn new cluster.  
4. If assigned cluster is full, evict sample with highest replacement score H(x) = λ_t·(1/(1+exp(-A/N))) + λ_u·(U/ log N_c) + λ_d·||dx−D_k||^2 (age, entropy, descriptor distance).  
5. If total clusters > K_max, trigger Adjacent Cluster Consolidation: find closest adjacent pair and merge their samples, keeping the N lowest-uncertainty ones.  
6. For adaptation, Retrieval module samples uniformly: for each active cluster, draw ⌊N_adapt/K⌋ samples.  
7. Adaptation engine updates the model using the retrieved set (e.g., consistency loss between student and teacher).  
8. Teacher model is updated via exponential moving average.  

**Design tradeoffs**:  
- τ: Small τ causes fragmentation (many tiny clusters, frequent ACC); large τ blends modes (heterogeneous clusters). Empirically robust around 0.3 for pixel stats.  
- ACC vs. global merging: ACC merges only temporally adjacent clusters, preserving complementary modes from non-overlapping parts of the stream; global merging may lose such diversity.  
- Per-cluster capacity N: Fixed size simplifies but may under-represent larger modes; dynamic sizing could improve balance.  
- Descriptor choice: Pixel statistics work well for corruption shifts but may be less effective for geometric or semantic shifts; alternative descriptors needed.

**Failure signatures**:  
- Mode collapse: Memory imbalance ratio >10x (seen in SCM) indicates one cluster dominates; MCM keeps ratio near 1.  
- Over-fragmentation: Too many clusters with fewer than N samples; high ACC frequency and unstable K; suggests τ too low.  
- Descriptor mismatch: Using CNN features instead of pixel stats causes large performance drop (~10% error increase on corruption benchmarks).

**First 3 experiments**:  
1. Stream clusterability analysis: Sliding window GMM fit to test stream, plot BIC vs. K; confirm optimal K* ≫ 1 across datasets.  
2. Ablation study: Add MCM components incrementally (multi-cluster → +ACC → +UCR) on a TTA baseline; measure error reduction at each step.  
3. Memory diagnostics over time: Compare SCM and MCM on metrics (cluster imbalance, GMM entropy, mode coverage); MCM should maintain balanced coverage while SCM degrades.

## Open Questions the Paper Calls Out
- How can MCM’s computational overhead be reduced for high-resolution inputs or larger models without sacrificing adaptation performance? (Future work suggests efficient approximations.)
- Can MCM’s pixel-level channel statistics descriptor effectively handle domain shifts driven by geometric transformations or high-level semantic changes? (Untested.)
- How can MCM be extended to structured output tasks like object detection or segmentation? (Open direction.)
- Does a graph-based cluster management strategy improve mode coverage and stability for streams with non-linear domain transitions? (Proposed alternative.)
- Can replacing raw sample storage with compact or learned representations enable scaling to large foundation models and multi-modal systems? (Memory footprint reduction.)

## Limitations
- Replacement score coefficients (λ_t, λ_u, λ_d) are not specified; tuning may affect stability.
- Precise corruption stream ordering (protocol from [38]) is not detailed, hindering exact reproducibility.
- Evaluation focuses on corruption benchmarks and DomainNet; generalization to other shift types remains unverified.
