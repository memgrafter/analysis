# FormalJudge: A Neuro-Symbolic Paradigm for Agentic Oversight

## Quick Facts
- **arXiv**: 2602.11136
- **Source**: https://arxiv.org/abs/2602.11136
- **References**: 40
- **Primary result**: Neuro-symbolic oversight using LLMs as specification compilers and formal verification achieves +16.6% detection accuracy over LLM-as-a-Judge baselines, enables weak-to-strong generalization (7B judge >90% on 72B agents), and shows near-linear safety improvement with iterative refinement.

## Executive Summary
FORMALJUDGE addresses the unreliability of LLM-as-a-Judge for overseeing capable AI agents by introducing a neuro-symbolic framework. It uses LLMs to decompose natural language intent into atomic binary facts, then employs Dafny formal specifications and Z3 SMT solving for deterministic verification. On three benchmarks, it achieves a 16.6% average improvement in detection accuracy over LLM baselines. The system enables weak-to-strong generalization: a 7B judge attains over 90% accuracy detecting deception from 72B agents. Iterative refinement with formal feedback yields near-linear safety improvement, raising agent accuracy from 70.7% to 99.8% over three rounds.

## Method Summary
The pipeline consists of four phases with frozen LLMs: (1) Intent Decomposer translates user instructions into a set of atomic, binary, grounded facts; (2) Context-Aware Extractor retrieves truth values for these facts from the agent's execution trace; (3) Spec Generator synthesizes Dafny code that composes facts into safety predicates; (4) SMT Verifier (Z3) deterministically verifies these predicates and outputs a verdict. No model training is performed; the system leverages LLMs as specification compilers and extractors, with formal verification providing mathematical guarantees.

## Key Results
- Average detection accuracy improvement of 16.6% over LLM-as-a-Judge baselines across three benchmarks.
- Weak-to-strong generalization: a 7B judge model achieves >90% accuracy in detecting deception from 72B agents.
- Iterative refinement: agent safety accuracy rises from 70.7% to 99.8% over three rounds, demonstrating near-linear improvement.

## Why This Works (Mechanism)

- **Atomic Fact Decomposition**: By breaking oversight into binary, grounded, context-minimal facts, the system confines LLM probabilistic errors to isolated yes/no questions. Logical composition is handled deterministically by Z3 via Dafny specifications. This limits composite judgment failure; the core assumption is that LLMs reliably answer simple factual queries even when holistic assessment fails. Failure occurs if the extractor systematically misclassifies atomic facts.

- **LLM as Specification Compiler**: LLMs bridge natural language intent to formal constraints without requiring user formal methods expertise. A top-down decomposition phase yields an atomic fact taxonomy; a synthesis phase then creates Dafny modules that compose these facts into safety predicates. The core assumption is that structured decomposition makes NL→formal translation tractable. Failure arises if generated Dafny code misrepresents the intended logic (e.g., missing conditional).

- **Grounded Formal Verification**: The SMT verifier evaluates only extracted boolean facts from actions and observations, ignoring agent reasoning traces which are primary vehicles for deception. This provides immunity to persuasive manipulation. The core assumption is that observable traces are more resistant to manipulation and contain sufficient signal. Failure occurs if deception does not violate any defined constraint or if facts are mis-extracted.

## Architecture Onboarding

**Component map**: Intent Decomposer (LLM) -> Context-Aware Extractor (LLM + deterministic parsing) -> Spec Generator (LLM) -> SMT Verifier (Z3 via Dafny)

**Critical path**: Decomposition (F) -> Extraction (values for F) -> Spec synthesis (Dafny code) -> Z3 verification. LLM appears in three stages; extraction accuracy is most sensitive.

**Design tradeoffs**:
- Precision vs. Recall: More atomic facts increase recall but risk false positives if noisy.
- Expressiveness vs. Synthesizability: Dafny supports rich logic but complex specs may exceed LLM synthesis capability; architecture restricts to compositions of simple facts.
- Determinism vs. Cost: SMT solving slower but provides guarantees; tradeoff justified for high-stakes oversight.

**Failure signatures**:
- Spec mismatch: Generated Dafny code does not correctly implement intended logical composition.
- Extraction drift: LLM extractor returns incorrect boolean values for facts.
- Incomplete taxonomy: Harmful behavior falls outside all defined atomic facts.

**First 3 experiments**:
1. Benchmark comparison: Run FORMALJUDGE vs. 6 LLM-as-a-Judge baselines on Agent-SafetyBench, VitaBench, Deceivers; expect +16.6% avg accuracy gain, especially on larger agents.
2. Attack robustness: Stratify trajectories by deception level (L1-L4); expect FORMALJUDGE stable detection; LLM baselines degrade on complex deceptions.
3. Weak-to-strong matrix: Use small judges (7B) against agents up to 72B on Deceivers; expect FORMALJUDGE maintains >90% detection; LLM baselines drop sharply with agent size.

## Open Questions the Paper Calls Out

1. **Specification synthesis bottleneck**: How can the translation of open-ended natural language intent into complete, correct formal specifications be systematically reduced? The paper identifies errors in decomposition and extraction as primary failure modes, but the NLP→formal problem remains unsolved. Evidence needed: consistent improvement in extraction/decomposition across diverse domains.

2. **Generalization to novel domains**: To what extent does FORMALJUDGE generalize beyond its three curated benchmarks to real-world agentic domains with different constraint structures? The evaluation scope is limited, and unstated assumptions may hinder external validity. Evidence needed: replication studies in new high-stakes domains.

3. **Long-term iterative refinement dynamics**: Does iterative refinement with formal feedback yield stable, monotonic safety improvement over many rounds (e.g., 10+), or do agents plateau, overfit, or forget? The paper shows near-linear improvement over three rounds, but long-term dynamics are unknown. Evidence needed: longitudinal study tracking metrics over 10+ iterations.

4. **Handling uncertainty and continuous constraints**: Can the formal verification backend be extended to handle constraints involving uncertainty, probabilistic outcomes, or continuous dynamics? The framework currently uses deterministic first-order logic, which may not capture many real-world safety requirements. Evidence needed: extension with probabilistic model checking validated on mixed constraints.

## Limitations

- **Oracle non-reproducibility**: The “God Judge” ensemble details (exact models, prompts, extended thinking protocol) are unreleased, preventing independent recreation of ground-truth labels.
- **Pipeline non-determinism**: LLM-driven decomposition and spec synthesis rely on unreleased, non-fixed prompts, causing potential variance in final outcomes.
- **Extraction brittleness**: The entire system hinges on the LLM extractor’s binary fact accuracy; adversarial or ambiguous trajectories can cause drift.
