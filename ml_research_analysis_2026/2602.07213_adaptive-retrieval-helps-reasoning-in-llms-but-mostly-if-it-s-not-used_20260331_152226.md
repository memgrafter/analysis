# Adaptive Retrieval helps Reasoning in LLMs -- but mostly if it's not used
## Quick Facts
- arXiv ID: 2602.07213
- Source URL: https://arxiv.org/abs/2602.07213
- Reference count: 30
- Primary result: Adaptive retrieval yields modest net gains (+1.1pp on GSM8K, +6.4pp on MATH‑500) but never retrieving at all is even better (+2.1pp on GSM8K, +19.5pp on MATH‑500).

## Executive Summary
Large language models (LLMs) often lack up‑to‑date or specialized knowledge, harming their reasoning. This paper investigates adaptive retrieval, where the LLM itself decides during chain‑of‑thought (CoT) reasoning whether to query an external math knowledge base. Using Llama‑3.1‑8B‑Instruct and a two‑stage retrieval system (BAAI/bge‑m3 dense search + FAISS HNSW + BAAI/bge‑m3‑reranker), the authors compare adaptive retrieval against standard CoT and static retrieval (single pre‑search) on GSM8K and MATH‑500. Adaptive retrieval improves over CoT by 1.1 percentage points on GSM8K (82.1%→83.2%) and by 6.4pp on MATH‑500 (44.2%→50.6%). However, static retrieval harms performance, dropping by 6.3pp on GSM8K and 1.8pp on MATH‑500. Strikingly, the agent’s accuracy is highest when it does *not* retrieve: 84.2% on GSM8K (+2.1pp over CoT) and 63.7% on MATH‑500 (+19.5pp). The decision to forgo retrieval proves a reliable metacognitive signal of competence, and the benefit of adaptive retrieval lies primarily in avoiding unnecessary retrieval rather than the retrieved content itself.

## Method Summary
The study evaluates three reasoning strategies in a zero‑shot setting. (1) **CoT**: Standard chain‑of‑thought prompting (prompt A.2.3) with no retrieval. (2) **Static Retrieval‑CoT**: A single retrieval at the beginning, using the original problem as query; the top‑5 retrieved documents are prepended to the prompt (prompt A.2.4). (3) **Adaptive Retrieval‑CoT**: The LLM generates reasoning steps interleaved with special `<search>` tags. When a `<search>query</search>` tag appears, generation pauses, the system extracts the query, executes the two‑stage retrieval pipeline, and injects the results along with a strict integration prompt (A.2.6) as a new user message. The LLM then resumes reasoning until it emits a final answer within `<answer>` tags. Retrieval uses the OpenMathInstruct‑2 corpus, preprocessed into concise canonical summaries via a summary prompt (A.2.7) for optimal performance. Generation is greedy with `max_new_tokens=1024`.

## Key Results
- CoT baseline: 82.1% on GSM8K, 44.2% on MATH‑500.
- Static Retrieval‑CoT: 75.8% on GSM8K (‑6.3pp), 42.4% on MATH‑500 (‑1.8pp).
- Adaptive Retrieval‑CoT: 83.2% on GSM8K (+1.1pp), 50.6% on MATH‑500 (+6.4pp).
- Adaptive no‑retrieval traces: 84.2% on GSM8K (+2.1pp), 63.7% on MATH‑500 (+19.5pp).
- Retrieval invocation rate: 7% on GSM8K, 38.8% on MATH‑500, increasing with problem difficulty (14%→60%).

## Why This Works (Mechanism)
We identify three mechanisms that explain the findings.

**Mechanism 1 – Self‑Regulated Information Flow.** Adaptive retrieval allows the LLM to query external knowledge only when its internal confidence is low. The model inserts `<search>` tags based on an internal assessment of knowledge gaps. Retrieved content is integrated via a structured prompt that encourages abstract reasoning. The correlation between retrieval rate and problem difficulty (rising from 14% to 60%) supports this mechanism. If the model’s confidence calibration breaks down (e.g., excessive retrieval on easy problems or zero retrieval on hard ones), the benefits vanish.

**Mechanism 2 – Static Context Injection Harms.** Placing retrieved information before reasoning introduces potentially irrelevant context that distracts the LLM. The “retrieve‑then‑read” paradigm forces the model to process extra tokens alongside its reasoning, leading to confusion, hallucination, or derailment. The observed 6.3‑pp drop on GSM8K with static retrieval confirms this effect, especially since the model’s internal knowledge is often sufficient. Even with high‑quality corpus, a static burst of information can be detrimental.

**Mechanism 3 – Not Retrieving Is a Signal of Competence.** When the model correctly judges it has the necessary knowledge, it refrains from retrieval. This self‑filtering preserves a clean reasoning context and yields higher accuracy than both CoT and retrieval‑included traces (e.g., +19.5pp on MATH‑500). The positive correlation between no‑retrieval and correctness is a reliable metacognitive indicator. However, overconfidence could cause the model to miss needed knowledge, harming performance on some problems.

## Architecture Onboarding
**Component map (data/control flow):**  
User (problem) -> System Prompt (CoT/Static/Adaptive) -> LLM Agent (generation) -> [if `<search>` detected] -> Tool Interface (extract query) -> Retrieval Module (dense + re‑rank on Knowledge Index) -> Retrieved Documents -> Context Manager (injects with Integration Prompt) -> back to LLM Agent -> [if `<answer>` produced] -> Output.

**Critical path:**  
1. Input problem formatted with the appropriate system prompt is sent to the LLM.  
2. LLM begins generating reasoning steps.  
3. If a `<search>` tag is emitted, generation pauses; the query is extracted and retrieval is executed.  
4. Retrieved knowledge is injected into the context immediately following the `<search>` block, wrapped in `<retrieved_knowledge>` and accompanied by the Integration Prompt.  
5. LLM resumes generation, now informed by the new evidence.  
6. When the LLM eventually emits `<answer>value</answer>`, the answer is extracted and returned.  
7. The process terminates.

**Design tradeoffs:**  
- Adaptive vs. static: Adaptive gives better accuracy but higher latency (multiple retrievals, longer context).  
- Corpus choice: Broader corpus (MathPile) covers more topics but includes noise; curated OpenMathInstruct‑2 yields higher precision but may miss niche theorems.  
- Re‑ranking: Cross‑encoder improves relevance at the cost of compute; can be disabled for speed.  
- Integration prompt: Strict abstract extraction reduces copying errors but may discard useful numeric examples.  
- Temperature: Greedy (0) ensures consistency; higher temperature increases query diversity but also instability.  
- Max new tokens: Set to 1024 to accommodate long reasoning; too short truncates answers.  
- Retrieval budget: Top‑5 after re‑rank; adjusting k trades relevance against context size.

**Failure signatures:**  
- Excessive retrieval (>50% on easy problems) indicates under‑confidence; may need threshold tuning.  
- Zero retrieval on hardest level suggests over‑confidence; model may not invoke when needed.  
- Retrieved blocks frequently labeled “not helpful” point to corpus‑query mismatch.  
- Multiple `<search>` tags without a final answer risk infinite loops; enforce max search count.  
- Integration leading to verbatim copying suggests rules are too strict; loosen or add verification.  
- Static retrieval accuracy dropping >5pp relative to CoT confirms static context harm.  
- High variance across runs with temperature > 0 signals instability.

**First 3 experiments:**  
1. **Baseline CoT:** Run using standard CoT prompt (A.2.3) on both benchmarks; record accuracy.  
2. **Static Retrieval‑CoT:** Retrieve once with the problem string, prepend top‑5 documents to the prompt, then run CoT; measure accuracy.  
3. **Adaptive Retrieval‑CoT:** Implement the search‑tool loop with adaptive prompt (A.2.5); log overall accuracy and per‑problem retrieval decisions; compare to baseline and analyze retrieval frequency by difficulty.

## Open Questions the Paper Calls Out
- *Under what specific problem characteristics (e.g., topic, required knowledge type, reasoning depth) does adaptive retrieval actually improve accuracy versus harming it?* The paper notes varied examples (e.g., Sophie Germain identity helps, Melanie sales hurts) but lacks systematic breakdown.
- *Is the observed positive correlation between not retrieving and higher accuracy a general property of LLM reasoning across domains beyond mathematics?* Evidence is limited to GSM8K and MATH‑500.
- *Does the harm caused by static retrieval stem primarily from the introduction of irrelevant documents, the method of context injection, or the fixed timing of retrieval before reasoning?* The paper only shows the effect, not the cause.
- *Can the adaptive retrieval decision mechanism be improved beyond the current prompt‑based approach, e.g., through fine‑tuning or reinforcement learning, to increase the precision of retrieval invocations?* The current crude method may leave performance on the table.

## Limitations
- OpenMathInstruct‑2 dataset format and accessibility are not specified, hindering precise reconstruction of the summarized knowledge base.
- The exact user‑message layout for Static Retrieval‑CoT is ambiguous (placement and delimiting of retrieved information), which could affect reproducibility.
- Corpus analysis shows only moderate topical similarity to existing work and no citation data, indicating that the adaptive retrieval claim is still emerging and lacks extensive community validation.

## Confidence
- Adaptive retrieval improves reasoning over CoT: **Medium** (depends on correct summarization and retrieval implementation).
- Static retrieval harms performance: **High** (robust effect across RAG literature).
- Not retrieving signals competence: **Medium** (correlation sensitive to prompt design and model calibration).
- Retrieval frequency scales with difficulty: **High** (directly measurable, less‑implementation‑dependent).
