# Boosting Document Parsing Efficiency and Performance with Coarse-to-Fine Visual Processing

## Quick Facts
- **arXiv ID:** 2603.24326  
- **Source URL:** https://arxiv.org/abs/2603.24326  
- **Reference count:** 40  
- **Primary result:** PaddleOCR-VL-L achieves state-of-the-art on OmniDocBench v1.5 with an overall score of 92.62, using only 2,561 vision tokens and processing pages 53.1% faster with lower VRAM usage than MinerU2.5.

## Executive Summary
Document parsing at high resolution suffers from quadratic computational costs due to redundant background areas. This paper introduces PaddleOCR-VL, a coarse-to-fine architecture that first employs a lightweight Valid Region Focus Module (VRFM) to identify semantically relevant regions, dramatically reducing the number of visual tokens needed. A compact 0.9B-parameter vision-language model then performs detailed recognition within these regions. Evaluations on OmniDocBench v1.5 show state-of-the-art performance (92.62 score) with superior element-level accuracy and significant efficiency gains: 2,561 tokens vs 3,256 for competitors, 53.1% faster inference, and reduced VRAM consumption.

## Method Summary
PaddleOCR-VL adopts a two-stage coarse-to-fine processing pipeline. In the coarse stage, the VRFM quickly scans the full-resolution document image to produce a binary mask highlighting semantically valid regions (e.g., text blocks, formulas). This mask allows the system to discard background and irrelevant pixels, yielding a small set of informative patches. In the fine stage, these patches are embedded and fed into PaddleOCR-VL-0.9B, a compact vision-language model trained for document tasks, which produces token-level predictions for text, layout, and mathematical expressions. The combination ensures that only essential visual content is processed, cutting quadratic costs while preserving accuracy.

## Key Results
- OmniDocBench v1.5 overall score of **92.62**, surpassing MinerU2.5 (90.67) with **2,561 vision tokens** versus 3,256.  
- Best element-level scores: **text Edit Distance 0.035**, **formula CDM 90.90**.  
- **53.1% faster** page processing than MinerU2.5 and **lower VRAM** usage.

## Why This Works (Mechanism)
The coarse-to-fine mechanism directly attacks the quadratic scaling problem. By identifying valid regions early, VRFM eliminates background computation, reducing the number of patches fed into the expensive VL model. The compact VL model is then applied only to relevant content, shrinking the effective input sequence. This yields a double efficiency gain: fewer tokens means lower memory and faster attention, while the lightweight VRFM adds negligible overhead. The accuracy remains high because the valid regions capture nearly all semantic content, as evidenced by SOTA results on OmniDocBench.

## Architecture Onboarding
**Component Map**  
Input Image -> Valid Region Focus Module (VRFM) -> Valid Region Mask -> Patch Embedding -> PaddleOCR-VL-0.9B -> Multimodal Output  

**Critical Path**  
1. Image loaded at full resolution.  
2. VRFM generates a binary mask of valid regions in a single forward pass.  
3. The mask filters the image; only patches within valid regions are extracted and embedded.  
4. Embedded patches are fed as a token sequence to PaddleOCR-VL-0.9B.  
5. The model predicts token-level labels (text, layout, formulas).  
6. Post-processing assembles structured output (e.g., JSON).  

**Design Tradeoffs**  
- VRFM overhead vs. token reduction: VRFM is lightweight, so its cost is amortized by large token savings.  
- Mask recall vs. precision: A more permissive mask includes more tokens (higher recall) but may retain background, reducing efficiency; a stricter mask risks dropping faint text (lower recall).  
- Model capacity: The 0.9B parameter model is small, relying on high-quality input (valid regions) to match larger models. This trades off raw capacity for speed and memory.  

**Failure Signatures**  
- High text Edit Distance indicates VRFM likely omitted important text regions (e.g., low contrast, non-Latin).  
- Token count close to full resolution suggests VRFM failed to suppress background (poor mask quality or threshold).  
- Inconsistent formula recognition points to issues in the region selection or VL model's handling of mathematical symbols within sampled patches.  

**First Experiments**  
1. **VRFM Mask Quality**: Visualize and quantitatively evaluate VRFM masks against document layout annotations on a varied sample (clean, noisy, multi-script).  
2. **Token Budget Ablation**: Adjust VRFM's selection threshold and measure resulting token count, inference speed, and OmniDocBench score to map the efficiency-accuracy curve.  
3. **Component Isolation**: Run the VL model on full-resolution images (bypass VRFM) to measure the raw cost of the model and confirm that all gains stem from token reduction.

## Limitations
- Generalizability not tested beyond OmniDocBench v1.5; performance on other benchmarks (e.g., PubLayNet, custom noisy scans) is unknown.  
- VRFM's decision-making lacks interpretability; failure modes on complex layouts or degraded documents are unanalyzed.  
- Hardware efficiency claims are based on a single GPU setup; validation across multiple architectures and memory-limited environments is pending.

## Confidence
- SOTA performance on OmniDocBench v1.5: **High** (specific scores provided)  
- Token reduction & inference efficiency vs. MinerU2.5: **High** (quantified comparison)  
- Element-level recognition (text ED, formula CDM): **High** (metric-driven)  
- General applicability to diverse real-world documents: **Medium/Low** (single-dataset evaluation only)

## Next Checks
1. **Cross-dataset replication**: PaddleOCR-VL should be tested on additional benchmarks (e.g., DocVQA, PaperMMA) to evaluate consistency of performance gains.  
2. **VRFM failure-case analysis**: Systematically inspect VRFM attention/masks on challenging documents (overlapping text, stains, non-Latin scripts) to identify systematic miss patterns.  
3. **Hardware-diverse efficiency test**: Replicate speed and VRAM measurements on multiple GPU architectures (NVIDIA Ampere, Hopper, AMD MI300) to confirm hardware-agnostic advantages.
