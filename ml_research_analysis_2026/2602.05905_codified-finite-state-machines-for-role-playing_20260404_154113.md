# Codified Finite-state Machines for Role-playing

## Quick Facts
- **arXiv**: 2602.05905  
- **Source**: https://arxiv.org/abs/2602.05905  
- **References**: 40  
- **Primary result**: CFSM reduces cost 25× while improving NLI consistency (82.65/84.60 vs 81.10) on Fandom Benchmark; CPFSM further boosts Best@K.

## Executive Summary
Maintaining consistent character states in LLM-based role-playing is challenging because latent traits (e.g., personality, abilities) can drift across long narratives. This paper introduces Codified Finite-State Machines (CFSM) and Codified Probabilistic FSM (CPFSM), frameworks that automatically convert textual character profiles into executable state transition logic. Evaluated on the Fandom Benchmark (5,141 scenes, 83 characters), CFSM outperforms textual profile and state summarization baselines in action consistency while drastically cutting computational cost. CPFSM adds probabilistic transitions, improving response diversity. Results hold across model scales from 1B to GPT-4.1, demonstrating robustness and generalizability.

## Method Summary
CFSM codification uses an LLM to extract discrete states from a character profile and generate a `get_next_state` function composed of binary‑questions that check transition conditions. At runtime, each turn receives a scene‑action tuple; a relevance filter and active/passive classifier determine the character’s involvement. For CFSM, the current state and binary‑question answers deterministically yield the next state. CPFSM extends this by maintaining a probability distribution over states; the same binary questions produce logits that, via softmax, update the distribution stochastically. The updated state then grounds the response generation, reusing existing codified‑profile prompts. A small discriminative model (e.g., a distilled 0.1B DeBERTa) evaluates binary questions cheaply, avoiding full LLM inference and enabling large efficiency gains.

## Key Results
- CFSM achieves average NLI scores of 82.65 for main characters and 84.60 for minor characters on the Fandom Benchmark, surpassing textual profile (81.10) and state summarization baselines.
- CPFSM improves Best@K response quality by modeling transition probabilities, enabling finer‑grained behavioral diversity.
- CFSM requires only 30.17 forward passes per turn versus 130.78 for prompt‑based state simulation—a 25× cost reduction—while attaining perfect accuracy on synthetic validation sequences.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Automatic codification of textual character profiles into FSMs using LLMs ensures interpretable and consistent state tracking in role‑playing.  
- **Mechanism**: LLM extracts discrete states from profile, then generates a transition function with binary questions for condition checking, executed per action to update state.  
- **Core assumption**: Character states and transitions can be finitely represented and binary conditions suffice for most transitions.  
- **Evidence anchors**:  
  - [abstract]: "automatically codifies textual character profiles into FSMs using LLM‑based coding"  
  - [section 3.2]: "CFSMs extract key states and transitions directly from the profile, producing interpretable structures that enforce character consistency"  
  - [corpus]: Weak; corpus neighbors on FSMs but not codification for RP.  
- **Break condition**: If profile is ambiguous or states poorly defined, codification yields inaccurate FSMs, causing state drift in RP outputs.

### Mechanism 2
- **Claim**: Probabilistic transitions in CPFSM capture behavioral uncertainty, improving response diversity and Best@K performance.  
- **Mechanism**: Pre‑defined binary questions generate logit scores for each state‑to‑state transition; softmax updates state probability distribution, guiding response generation.  
- **Core assumption**: Character actions often have multiple valid outcomes; probability distributions model this ambiguity better than deterministic rules.  
- **Evidence anchors**:  
  - [abstract]: "CPFSM further improved Best@K response quality by modeling transition probabilities, enabling finer‑grained behavioral diversity."  
  - [section 3.3]: "CPFSMs maintain a state probability distribution… derived by prompting the LLM with pre‑defined transition questions."  
  - [section 5.4]: Empirical Best@K improvement with sampled state distributions over baselines.  
- **Break condition**: Poorly calibrated binary questions lead to noisy probability distributions; overhead may not benefit highly deterministic scenarios.

### Mechanism 3
- **Claim**: CFSM drastically reduces computational cost by executing pre‑codified transitions instead of per‑step LLM prompting.  
- **Mechanism**: State updates via deterministic or probabilistic logic require fewer forward passes as binary questions can use efficient discriminators (e.g., distilled models).  
- **Core assumption**: Many transitions can be resolved with simple checks without full LLM inference, maintaining accuracy.  
- **Evidence anchors**:  
  - [abstract]: "CFSM required only 30.17 forward passes per turn compared to 130.78 for prompt‑based state simulation, representing a 25× cost reduction."  
  - [section 4]: Synthetic validation shows CFSM perfect accuracy with lower cost; prompt‑based degrades with sequence length.  
  - [section 5.5]: Efficiency analysis confirms reduced forwards per turn and codification overhead.  
- **Break condition**: Complex transitions requiring deep semantic understanding may force fallback to larger models, eroding efficiency gains.

## Architecture Onboarding

**Component map**: Profile Parser → State Extractor → Transition Coder → FSM Module (CFSM/CPFSM) → Condition Checker (binary_question) → State Tracker → RP Response Generator. Binary_question uses a small discriminative model; RP generation uses a larger model.

**Critical path**: Per turn: (1) Parse scene‑action tuple; (2) Check character relevance and active/passive role via discriminator; (3) Update state: CFSM executes get_next_state, CPFSM updates distribution via transition matrix; (4) Ground response in updated state and scene; (5) Generate character utterance with RP model.

**Design tradeoffs**:
- CFSM vs. CPFSM: determinism (speed, compatibility) vs. probabilistic nuance (diversity, fine‑grained control).
- Codification granularity: Full O(n²) transition questions vs. efficient O(n+k) with defaults (section 5.5).
- Model selection: Larger codifiers (gpt‑4.1) for complex FSMs; smaller (qwen3) sufficient for CPFSM question generation.

**Failure signatures**:
- State drift: Binary questions miss key triggers; monitor via NLI score drops or manual inspection of state logs.
- High computational overhead: Excessive transition checks; profile number of questions and forward passes per turn.
- Coverage gaps: Overuse of “Other” state; analyze state distribution histograms for imbalance.
- Codification bugs: Invalid FSM code; validate with synthetic traces before deployment.

**First 3 experiments**:
1. Synthetic validation: Implement Mario/COD/Tyrion FSMs; compare CFSM accuracy and forward passes against prompt‑based LLM simulation on generated sequences.
2. Baseline benchmarking: Run CFSM on Fandom Benchmark with gpt‑4.1 and llama‑1B; compare NLI scores to textual profile, codified profile, PromptTrans, etc.
3. Ablation study: Remove state registration, “Other” state, or specific FSM types (personality/identity/ability); measure NLI impact to identify critical components.

## Open Questions the Paper Calls Out

1. **Can CFSMs be automatically constructed directly from unstructured narrative plots?**  
   - *Question*: How can CFSMs be automatically constructed directly from unstructured narrative plots (e.g., raw story texts) rather than relying on pre‑written character profiles?  
   - *Basis in paper*: [explicit] Listed as future work in the conclusion: "(1) automatically building CFSMs directly from narrative plots rather than pre‑written profiles".  
   - *Why unresolved*: Current codification requires structured profiles; extending to raw plots would broaden applicability but introduces challenges in state extraction from ambiguous or non‑linear narratives.  
   - *What evidence would resolve it*: A pipeline that ingests raw story text, identifies latent character states and transitions via LLM‑based extraction, and generates executable FSM code validated against plot‑consistent action sequences.

2. **Can CFSMs dynamically acquire new states during long‑form role‑play?**  
   - *Question*: Can CFSMs dynamically acquire new states (e.g., new skills or emotional shifts) during long‑form role‑play without pre‑specifying the entire state space?  
   - *Basis in paper*: [explicit] Mentioned as future work: "(3) enabling dynamic updates to the state set, allowing characters to acquire new skills or traits over time."  
   - *Why unresolved*: The framework assumes a fixed state set; dynamic addition could improve adaptability but risks state explosion or incoherent transitions.  
   - *What evidence would resolve it*: An extension that monitors trajectory divergence and triggers LLM‑based proposal of new states, with mechanisms to merge or prune states while preserving transition consistency.

3. **How should probabilistic transitions be validated against human intuition?**  
   - *Question*: How should probabilistic transitions in CPFSMs be validated against human intuitions of character behavior or established narrative theory?  
   - *Basis in paper*: [inferred] CPFSM introduces probabilistic transitions but evaluation relies on NLI scores against reference actions; no human study assesses whether the probability distributions align with nuanced character portrayal.  
   - *Why unresolved*: NLI scores measure surface action matching but not the plausibility of behavioral uncertainty; without human judgment, it’s unclear if CPFSM’s stochasticity captures authentic character ambiguity.  
   - *What evidence would resolve it*: Pairwise human evaluations comparing CPFSM‑generated behaviors to deterministic CFSM and baselines, focusing on perceived realism and diversity in character reactions.

4. **Do CFSMs generalize to open‑ended, co‑created role‑play?**  
   - *Question*: Do CFSMs generalize to truly open‑ended, co‑created role‑play scenarios where the plot is not predetermined (e.g., human collaborative storytelling) and state transitions must adapt to unforeseen events?  
   - *Basis in paper*: [inferred] Evaluation uses the Fandom Benchmark with scripted scenes; the paper speculates on open‑ended use but does not test against emergent, unscripted narratives.  
   - *Why unresolved*: Scripted benchmarks control for plot coherence; open‑ended co‑creation introduces uncertainty in scene composition and action relevance, potentially breaking codified transitions.  
   - *What evidence would resolve it*: Deployment in human‑AI collaborative RP sessions, measuring state trace stability and narrative coherence against human co‑writers’ assessments over multiple sessions.

5. **What is the theoretical scalability limit of codification overhead?**  
   - *Question*: What is the theoretical scalability limit of codification overhead (O(n²) vs. O(n+k)) as the number of character states and transition complexity increases in large‑scale, multi‑faceted角色们?  
   - *Basis in paper*: [explicit] Discusses O(n+k) optimization to reduce codification cost but does not analyze asymptotic behavior for extremely large state sets or deeply nested transitions.  
   - *Why unresolved*: Current analysis is empirical on Fandom Benchmark; theoretical bounds on codification time and maintenance for thousands of states (e.g., in epic fantasy ensembles) are unknown.  
   - *What evidence would resolve it*: Formal analysis of codification pipeline complexity combined with stress tests on synthetic profiles with varying state cardinalities, measuring both codification time and runtime transition accuracy.

## Limitations
- Assumptions that character states are finitely representable and binary conditions suffice may fail for nuanced or evolving profiles.
- Efficiency gains rely on a highly accurate binary‑question discriminator; frequent fallback to full LLM inference would erase the 25× reduction.
- Evaluation on scripted benchmarks may not reflect real‑world narrative complexity, leaving open the robustness of CFSMs in open‑ended, co‑created role‑play.

## Confidence
- **High**: Reported NLI scores and cost reduction on the large‑scale Fandom Benchmark.
- **Medium**: Generalization across model scales (1B to GPT‑4.1) and CPFSM’s Best@K improvements.
- **Low**: Long‑term robustness and applicability beyond controlled synthetic and benchmark settings.
