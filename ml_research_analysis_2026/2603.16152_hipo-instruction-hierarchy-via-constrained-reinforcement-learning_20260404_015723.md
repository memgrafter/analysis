# HIPO: Instruction Hierarchy via Constrained Reinforcement Learning

## Quick Facts
- **arXiv ID:** 2603.16152
- **Source URL:** https://arxiv.org/abs/2603.16152
- **Reference count:** 40
- **Primary result:** HIPO enforces system prompt compliance via constrained RL, achieving ≥0.70 system compliance on conflicting tests while improving user utility and reducing jailbreak success rates.

## Executive Summary
Hierarchical Instruction Following (HIF) requires models to prioritize system-level constraints over conflicting user requests, a challenge not solved by standard RLHF or DPO. HIPO reformulates HIF as a Constrained Markov Decision Process (CMDP) where system compliance is a hard constraint and user utility is maximized within the feasible region. Using a primal‑dual safe RL algorithm, it dynamically balances these objectives with decoupled LLM‑as‑judge rewards. Evaluated on Qwen, Phi, and Llama models (1.7B–8B), HIPO consistently meets a 0.7 compliance threshold while delivering Pareto improvements in user utility and modestly lowering jailbreak attack success. Mechanistic analysis reveals a learned internal shift of attention toward system tokens, corroborating the constraint mechanism.

## Method Summary
HIPO treats hierarchical alignment as a CMDP with a primary objective to satisfy the system prompt (reward \(r_{\text{sys}}\)) and a secondary goal to maximize user utility (\(r_{\text{user}}\)). The policy \(\pi_\theta\) is trained using a group‑relative policy gradient (GRPO) that normalizes advantages within a batch of \(G\) sampled responses. For each step, the algorithm: samples a prompt, generates \(G\) responses from an old policy, judges each with two LLM‑based evaluators, computes standardized advantages \(A_{\text{user}}\) and \(A_{\text{sys}}\), combines them as \(A = A_{\text{user}} + \lambda A_{\text{sys}}\), and updates \(\pi_\theta\) via a PPO‑style clipped surrogate objective plus a KL penalty against a frozen 4‑bit reference model. The Lagrange multiplier \(\lambda\) is adjusted with a primal‑dual update based on an exponential moving average of batch‑average \(r_{\text{sys}}\); if compliance falls below threshold \(\tau\), \(\lambda\) rises to enforce the constraint, otherwise it decays to refocus on user utility. This adaptive scheduling removes the need for manually tuning reward weights and yields stable convergence.

## Key Results
- System compliance ≥0.70 on conflicting prompts across Qwen3 (1.7B/4B/8B), Phi‑3‑3.8B, and Llama3.2‑3B, meeting the τ=0.7 criterion.
- Significant gains in user utility, e.g., Qwen3‑1.7B improves from 0.60/0.36 (SFT) to 0.70/0.47 (HIPO).
- Jailbreak attack success decreases by 5–14% absolute relative to baselines, without increasing over‑refusal on aligned prompts.
- Attention analysis shows a statistically significant shift toward system tokens (SysUserRatio +0.501), confirming the internal effect of the constraint.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** HIPO enforces system prompt compliance as a hard constraint by formulating HIF as a Constrained MDP, guaranteeing policy updates only maximize user utility within a feasible region where system instructions are respected.  
**Mechanism:** The CMDP maximizes \(J_{\text{user}} = \mathbb{E}[r_{\text{user}}]\) subject to \(J_{\text{sys}} = \mathbb{E}[r_{\text{sys}}] \ge \tau\). Using a Lagrangian, the objective becomes \(\max_\theta \min_{\lambda\ge0} \mathcal{L}(\theta,\lambda)=J_{\text{user}}+\lambda(J_{\text{sys}}-\tau)\). The policy gradient then uses a combined advantage \(A_{\text{comb}}=A_{\text{user}}+\lambda A_{\text{sys}}\).  
**Core assumption:** The LLM‑as‑judge reliably evaluates system compliance across diverse responses.  
**Evidence anchors:**  
- [abstract] “HIPO addresses Hierarchical Instruction Following… formulates HIF as a Constrained Markov Decision Process… enforcing system compliance as a hard constraint via primal‑dual safe RL.”  
- [section 3] “We formulate the HIF problem as a CMDP… primary objective is to ensure compliance to the system prompt.”  
- Community: Prior work on instruction hierarchies (e.g., IH‑Challenge) motivates the need for explicit constraint handling.  
**Break condition:** If the compliance judge under‑estimates violations, \(\lambda\) may become mis‑calibrated, leading to either constraint breaches or excessive conservatism.

### Mechanism 2
**Claim:** The primal‑dual update with a dynamic \(\lambda\) automatically balances system compliance and user utility without manual reward weighting, adapting to each batch’s difficulty.  
**Mechanism:** After each batch, \(\lambda\) is updated as \(\lambda^{t+1} = \max(0, \lambda^t - \eta_\lambda ( \frac{1}{G}\sum_i r_{\text{sys}}^i - \tau ))\). An exponential moving average (EMA) of \(r_{\text{sys}}\) smooths the signal. If the batch’s average system reward drops below \(\tau\), \(\lambda\) increases, amplifying \(A_{\text{sys}}\); once the constraint is consistently met, \(\lambda\) decays to zero, shifting focus to user utility.  
**Core assumption:** The EMA tracks long‑term constraint satisfaction and stabilizes \(\lambda\) updates.  
**Evidence anchors:**  
- [abstract] “using a primal‑dual safe reinforcement learning approach, the algorithm dynamically enforces system prompt compliance.”  
- [section 4.2] Detailed \(\lambda\) update rule with EMA and adaptive decay.  
- Prior safe RL literature (e.g., Safe RLHF) uses similar Lagrangian schemes.  
**Break condition:** An unsuitable learning rate \(\eta_\lambda\) or EMA decay can cause \(\lambda\) divergence or oscillation, preventing convergence.

### Mechanism 3
**Claim:** Constrained optimization induces an internal attention reallocation toward system tokens, a mechanistic signature that encodes hierarchy without explicit attention interventions.  
**Mechanism:** The penalty on \(r_{\text{sys}}\) (scaled by \(\lambda\)) encourages the model to allocate more attention to the system prompt when generating the first token; over training this shifts the attention distribution: increased mass on system spans (SysMass), decreased on user spans (UserMass), and higher SysUserRatio.  
**Core assumption:** The attention distribution at response onset reflects the model’s internal prioritization and causally influences compliance.  
**Evidence anchors:**  
- [abstract] “Mechanistic analysis confirms a statistically significant internal shift toward system tokens (SysUserRatio +0.5).”  
- [section 6] Quantitative metrics: SysMass increase, UserMass decrease, SysUserRatio +0.501 (p<0.01).  
- Contrast with baselines that manually modify attention (Split‑Softmax, FocalLoRA).  
**Break condition:** Architectures without standard attention (e.g., state‑space models) may not exhibit this shift, requiring alternative explanations.

## Foundational Learning
- **Concept: Constrained Markov Decision Process (CMDP)**  
  _Why needed:_ Formalizes hierarchical instruction following with a mandatory compliance constraint and a separate utility objective, enabling mathematically grounded guarantees.

- **Concept: Primal‑dual optimization for safe RL**  
  _Why needed:_ Adaptively enforces safety constraints without a fixed penalty weight, automatically balancing constraint satisfaction and performance.  
  _Quick check:_ In HIPO, what causes \(\lambda\) to increase, and how does a higher \(\lambda\) affect the policy gradient signal?

- **Concept: Group‑relative policy gradient (GRPO)**  
  _Why needed:_ Eliminates a separate value network, reduces variance, and supports multiple decoupled rewards by normalizing within a sampled group.  
  _Quick check:_ Why compute advantages relative to the mean and standard deviation of a group of responses for the same prompt?

## Architecture Onboarding
**Component map:**  
Dataset (SystemCheck) → prompts → policy \(\pi_\theta\) → \(G\) responses → LLM judges → \(r_{\text{sys}}\), \(r_{\text{user}}\) → group stats → standardized advantages \(A_{\text{user}}, A_{\text{sys}}\) → combine with \(\lambda\) → PPO‑style update + KL penalty vs. frozen 4‑bit reference → dual update \(\lambda\) (EMA) → feedback.

**Critical path:**  
1. Sample a prompt \(x \sim D\).  
2. Draw \(G=4\) responses \(\{y_i\}\) from old policy \(\pi_{\theta_{\text{old}}}\) (store log‑probs).  
3. Query judges to obtain \(r_{\text{sys}}^i\), \(r_{\text{user}}^i\) for each response.  
4. Compute group mean and standard deviation for each reward; if std \(< 1e-8\) set advantage to 0.  
5. Normalize: \(A_{\text{user}} = (r_{\text{user}} - \mu_{\text{user}})/\sigma_{\text{user}}\), \(A_{\text{sys}} = (r_{\text{sys}} - \mu_{\text{sys}})/\sigma_{\text{sys}}\).  
6. Combine: \(A_{\text{comb}} = A_{\text{user}} + \lambda A_{\text{sys}}\).  
7. Compute new log‑probs under current policy; policy loss \(= -\frac{1}{G}\sum_i A_{\text{comb}}^i \log\pi_\theta(y_i|x) + \beta \text{KL}(\pi_\theta \| \pi_{\text{ref}})\). Update policy with AdamW.  
8. Update \(\lambda\): batch_avg_sys = mean(\(r_{\text{sys}}\)); ema_r_sys = 0.9·ema_r_sys + 0.1·batch_avg_sys; \(\lambda = \max(0, \lambda - \eta_\lambda (\text{ema_r_sys} - \tau))\); clip \(\lambda \le 20\). Periodically copy \(\theta\) to \(\theta_{\text{old}}\).

**Design tradeoffs:**  
- Group size \(G\): Larger improves advantage stability but increases judge latency; typical \(G=4\).  
- \(\lambda\) update: EMA introduces lag but prevents spikes; decay rate must balance responsiveness and stability.  
- Reference model quantization (4‑bit NF4): reduces memory at minor KL accuracy cost.  
- Threshold \(\tau\): higher values enforce stricter safety but may degrade utility; trade‑off is dataset‑dependent.  
- KL penalty coefficient \(\beta\): needed to prevent excessive deviation from reference; too high may hinder constraint learning.

**Failure signatures:**  
- \(\lambda\) explodes or becomes NaN → reduce \(\eta_\lambda\) or increase \(\beta\).  
- System compliance stuck below \(\tau\) → check judge reliability, possibly increase training steps or adjust \(\lambda\) initialization.  
- Over‑refusal on aligned prompts (near‑zero user reward) → \(\lambda\) too large; lower \(\lambda_{\text{init}}\) or \(\eta_\lambda\).  
- Training instability (loss spikes) → lower learning rate, increase group size, tighten PPO clip range (if used).  
- Zero advantage variance → increase \(G\) or add epsilon to denominator.

**First 3 experiments:**  
1. **Main replication:** Train HIPO on Qwen3‑1.7B with \(\tau=0.7\); evaluate on conflicting and aligned test splits. Confirm system compliance ≥0.7 on conflict and improved user utility over SFT/DPO baselines.  
2. **Ablation on \(\lambda\) scheduling:** Replace dynamic \(\lambda\) with a fixed scalar weight (static \(\lambda=2.0\) or scalarized reward) and compare Pareto balance; expect either compliance or utility to degrade.  
3. **Mechanistic validation:** Extract attention weights at the first generated token for 200 samples before and after training; compute SysUserRatio; perform paired t‑test to verify significant increase supporting the attention shift hypothesis.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can deterministic, decoding-time interventions (e.g., constrained beam search) complement HIPO's training-time optimization to further reduce constraint violations in highly adversarial or out-of-distribution hierarchical prompts?
- **Basis in paper:** [explicit] "exploring deterministic, decoding-time interventions could further mitigate deviations in highly adversarial or out-of-distribution edge cases" (Sec. 8, Limitations).
- **Why unresolved:** HIPO optimizes constraints in expectation over the policy distribution, which may not guarantee per-instance compliance under worst-case prompt perturbations.
- **What evidence would resolve it:** Compare HIPO against a hybrid approach (HIPO + decoding-time constraint enforcement) on a benchmark of adversarial hierarchical prompts, measuring violation rates and user utility.

### Open Question 2
- **Question:** To what extent does the observed attention shift toward system tokens (increased SysUserRatio) directly cause improved system compliance, versus being a correlated byproduct of other learned representations?
- **Basis in paper:** [inferred] Mechanistic analysis shows a statistically significant shift in attention metrics (Tab. 3), but the paper notes "attention weights do not constitute strict causal proofs" (Sec. 6). The causal link is implied but not established.
- **Why unresolved:** The analysis is correlational; improved compliance might arise from other internal changes (value function updates, hidden state shifts) coinciding with attention reallocation.
- **What evidence would resolve it:** Conduct an intervention where the attention pattern of a HIPO‑trained model is manually perturbed to mimic the base model's distribution; measure drop in compliance. Conversely, impose HIPO's attention pattern on the base model and measure compliance gains.

### Open Question 3
- **Question:** How sensitive is HIPO's performance to the choice of the system compliance threshold \(\tau\), and can an adaptive thresholding mechanism (e.g., based on prompt difficulty or user utility gradient) improve the Pareto frontier?
- **Basis in paper:** [explicit] The paper sets \(\tau=0.7\) and notes HIPO can reach any point on the Pareto frontier by varying \(\tau\). Sensitivity analysis and optimal threshold selection are not provided.
- **Why unresolved:** The trade‑off between strictness and utility may be non‑uniform across prompts; a single global \(\tau\) might be suboptimal.
- **What evidence would resolve it:** Sweep \(\tau\) across a range (e.g., 0.5–0.95) for multiple models, plot system compliance vs. user utility curves, and analyze whether prompt features correlate with optimal \(\tau\).

### Open Question 4
- **Question:** Does HIPO's constrained optimization generalize to hierarchical instructions with *more than two levels* (e.g., system > developer > user) or with *soft, non-binary constraints* (e.g., "mostly comply with X unless Y")?
- **Basis in paper:** [inferred] The CMDP formulation and experiments focus on a binary system/user hierarchy with a hard compliance constraint. Real‑world workflows often involve multiple, possibly soft, priority layers.
- **Why unresolved:** The primal‑dual mechanism is designed for a single constraint; extending to multiple constraints introduces stability and credit assignment challenges.
- **What evidence would resolve it:** Create a multi‑level instruction dataset (system > developer > user) and adapt HIPO to handle multiple constraints (e.g., multiple multipliers). Evaluate whether the model respects the full priority order and compare user utility against ablations.

### Open Question 5
- **Question:** Can the computational overhead of using frontier LLMs as judges be reduced without compromising decoupled reward quality, for example by distilling the judge into a smaller, task‑specific reward model?
- **Basis in paper:** [explicit] "generating the decoupled reward signals currently relies on frontier LLMs‑as‑a‑judge… Future work could address this by distilling these capabilities into smaller, specialized proxy reward models" (Sec. 8, Limitations).
- **Why unresolved:** The paper demonstrates the necessity of decoupled evaluation but does not explore distillation; the robustness of smaller proxies to reward hacking or nuance loss is unknown.
- **What evidence would resolve it:** Train smaller reward models (e.g., DeBERTa, small LLMs) on datasets generated by the frontier judge for both system compliance and user utility. Compare training stability, final performance, and compute cost of HIPO when using proxy judges vs. frontier judges.

## Limitations
- **Dataset accessibility:** SystemCheck is not publicly released; exact replication of data distribution is impossible.
- **Judge model dependence:** The method critically relies on high‑quality LLM‑as‑judge models; substitutions may alter reward scales and rankings.
- **Implementation gaps:** Some hyperparameters (e.g., PPO clip range, EMA details) are not fully specified, requiring approximations that could affect reproducibility.
