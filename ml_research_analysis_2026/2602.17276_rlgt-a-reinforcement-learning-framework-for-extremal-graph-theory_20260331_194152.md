# RLGT: A reinforcement learning framework for extremal graph theory

## Quick Facts
- arXiv ID: 2602.17276
- Source URL: https://arxiv.org/abs/2602.17276
- Reference count: 40
- Primary result: Successfully disproved 25 conjectured inequalities on Laplacian spectral radius and obtained new lower bounds for Ramsey numbers and Turán-type problems.

## Executive Summary
RLGT is a novel, modular framework that applies reinforcement learning (RL) to extremal graph theory. It unifies support for directed/looped graphs and multiple edge colors through an efficient graph representation, and strictly separates graph-building environments from learning agents. The framework was used to refute 25 conjectured inequalities on the Laplacian spectral radius and to discover new lower bounds for Ramsey numbers and Turán-type problems (forbidden cycles of length three and four). Empirical results highlight that the Deep Cross-Entropy agent combined with the Linear Build environment is especially effective for conjecture refutation, while other agent-environment combinations show variable stability.

## Method Summary
The approach frames extremal graph construction as a Markov decision process. An environment manages the state of a graph under construction and defines actions (e.g., assigning a color to an edge, flipping edges). An agent learns a policy to select actions that maximize a user-defined graph invariant function. Typical usage: (1) define a graph invariant `f(G)` that encodes the conjecture to be refuted; (2) choose a deterministic environment such as `LinearBuildEnvironment` that constructs the graph edge-by-edge; (3) select an agent, with `DeepCrossEntropyAgent` recommended for sparse-reward tasks; (4) run the RL loop across many episodes, periodically updating the policy based on elite-performing graphs; (5) retrieve the best graph when its invariant exceeds zero. The framework handles graph conversions and vectorized operations internally, enabling efficient invariant evaluation on batches of graphs.

## Key Results
- Disproved 25 conjectured inequalities on the Laplacian spectral radius.
- Obtained new lower bounds for Ramsey numbers and Turán-type problems (forbidden cycles of length three and four).
- Identified Deep Cross-Entropy agent with Linear Build environment as particularly effective for conjecture refutation.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** The unified `Graph` class with automatic conversions between eight supported formats (e.g., adjacency matrix, bitmask, flattened orders) removes representation bottlenecks, allowing researchers to focus on graph invariant functions rather than data transformations.
**Mechanism:** A single `Graph` object encapsulates all format-specific NumPy arrays, converting on-demand between representations. This relies on a canonical internal state and lazy conversion.
**Core assumption:** Graph invariant computations often require specific formats; manual conversion is error-prone and time-consuming.
**Evidence anchors:** Section 3.1 details the eight formats and the `Graph` class wrapper; the Abstract states "unified support" and "efficient graph representation."
**Break condition:** If a new invariant requires a format outside the eight supported (e.g., incidence matrix), the `Graph` class becomes a limiting factor.

### Mechanism 2
**Claim:** The strict separation between `GraphEnvironment` (state transitions, action masks) and `GraphAgent` (policy learning) modularizes the RL loop, enabling independent development and testing of graph-building logics and learning algorithms.
**Mechanism:** `GraphEnvironment` subclasses implement `_initialize_batch` and `_transition_batch`; `GraphAgent` subclasses implement `step`. The environment does not depend on the agent's internals.
**Core assumption:** Combinatorial optimization via RL can be decomposed into search space (environment) and search strategy (agent).
**Evidence anchors:** Section 3.2 describes the abstract class and separation; Abstract mentions "clean and modular design" and "agent treated as a separate entity."
**Break condition:** If an environment requires a learning signal that depends on agent internals (e.g., critic gradients affecting state transitions), the separation forces awkward callbacks.

### Mechanism 3
**Claim:** The Deep Cross-Entropy (DCE) agent paired with the Linear Build environment is particularly effective for conjecture refutation because the episodic, sparse-reward, sequential construction aligns with DCE's elitist population-based training, which efficiently explores combinatorial spaces without relying on credit assignment over long trajectories.
**Mechanism:** Linear Build constructs graphs edge-by-edge with a sparse terminal reward. DCE generates many episodes, selects top-performing graphs by invariant, and retrains a policy network to reproduce their action sequences, avoiding high-variance gradient estimates.
**Core assumption:** Finding a single counterexample in a vast search space benefits from DCE's generate-and-select approach over incremental policy-gradient updates.
**Evidence anchors:** Abstract states DCE+Linear Build is particularly effective; Section 4.1 & Example 3.5 show successful disprovals while other combos have variable stability.
**Break condition:** If the invariant provides dense feedback, policy-gradient methods (REINFORCE/PPO) might converge faster, reducing DCE's advantage.

## Foundational Learning
- **Concept: Reinforcement Learning (MDPs, policies, episodic vs. continuing tasks)**
  - Why needed: The entire framework models graph construction as an MDP. Understanding states, actions, rewards, and task structure is essential for using agents and environments correctly.
  - Quick check question: In the Linear Build environment, what is the episode length, and when is the graph invariant reward computed?
- **Concept: Extremal Graph Theory (graph invariants, Laplacian spectral radius, Ramsey/Turán problems)**
  - Why needed: The goal is to maximize/minimize a graph invariant `f(G)` over a graph family. Users must formulate conjectures as `f(G) <= 0` and design `f` properly.
  - Quick check question: How would you convert the conjecture "For any triangle-free graph on `n` vertices, `ex(n, C3) <= floor(n^2/4)`" into a graph invariant function for RLGT?
- **Concept: Python scientific stack (NumPy vectorization, PyTorch for agents)**
  - Why needed: Graph batches are NumPy arrays; invariant computations rely on vectorized operations. The DCE/REINFORCE/PPO agents are PyTorch modules; users must define policy networks and optimizers.
  - Quick check question: In `graph_invariant` functions, why is `astype(np.float32)` often used on results, and what might happen if you forget to handle division-by-zero in degree averages?

## Architecture Onboarding
**Component map**: The packages form a dependency chain: `graphs` (core Graph class) → `environments` (GraphEnvironment subclasses) → `agents` (GraphAgent subclasses). Data flows: environments output state batches converted to Graph batches for agents; agents output actions fed back to environments.

**Critical path**:
1. Define your graph invariant function `f(graph_batch: Graph) -> np.ndarray`. Must handle batches, return float32, and penalize invalid graphs.
2. Choose an environment class matching the problem (e.g., `LinearBuildEnvironment`) and configure its parameters (`graph_order`, `edge_colors`, `flattened_ordering`, etc.).
3. Select an agent (`DeepCrossEntropyAgent` recommended for conjecture refutation); configure policy network architecture and DCE hyperparameters (generation size, elite fraction).
4. Run the RL loop: `agent.reset()` → `agent.step()` until success (`best_score > 0`) or max steps.
5. Retrieve the counterexample via `agent.best_graph`.

**Design tradeoffs**:
- **Modularity vs. Performance:** The `Graph` class's automatic conversions add overhead; for massive-scale runs manual conversion to a single format may be faster but loses flexibility.
- **Deterministic vs. Nondeterministic environments:** Deterministic environments are easier to debug; nondeterministic generators can improve exploration but complicate reproducibility.
- **Sparse vs. Dense rewards:** Sparse terminal rewards align with DCE; dense per-step rewards are needed for policy-gradient methods and require careful `delta_f` design.

**Failure signatures**:
- Agent fails to improve (`best_score` stuck): likely sparse/informative reward or too small population; increase generation size or switch to DCE.
- Frequent crashes on disconnected graphs: invariant function may not handle invalid graphs; assign negative penalty and avoid exceptions.
- High memory usage: reduce generation size or batch size for large graphs.
- Poor counterexample quality: experiment with `flattened_ordering` and initial graph generators.

**First 3 experiments**:
1. Run Example 3.5 (`a1_example` in `agent_examples.py`) to validate DCE+Linear Build disproving a Laplacian conjecture; ensure counterexample found within ~200 steps for n=16.
2. Run Example 3.2 (`environment_examples.py`) to manually step through a `LinearBuildEnvironment` with a simple invariant; verify state vectors and graph matrices.
3. Run `auto_laplacian_solver.py` (Section 4.1) to replicate all 25 disproofs; check that `auto_laplacian_solutions.txt` contains valid bitmask graphs and that `auto_laplacian_checker.py` verifies them without errors.

## Open Questions the Paper Calls Out
1. **Improving REINFORCE and PPO stability** – The paper reports variable stability for these agents. Future work should investigate modifications to enhance their performance in extremal graph RL tasks.
2. **Exploring alternative RL methods** – Only three methods (DCE, REINFORCE, PPO) are implemented. Other state-of-the-art algorithms (e.g., Monte Carlo Tree Search, AlphaZero, Q-learning) remain untested and may generalize better.
3. **Designing new RL environments, including nondeterministic ones** – All existing environments are deterministic. Nondeterministic graph-building processes (e.g., probabilistic edge modifications) could improve exploration and are supported by the framework.
4. **Interpreting the failure to refute Conjecture 4.3** – The agent approached known extremal values but found no counterexample. It is unclear whether the conjecture is true or a limitation of RLGT; a formal proof or a successful refutation with a modified approach would resolve this.

## Limitations
- Hyperparameter settings and complete invariant implementations for the 25 disproofs are not fully documented, hindering exact reproducibility.
- The `Graph` class’s eight supported formats may be insufficient for some invariants (e.g., incidence matrix), and the strict agent-environment separation could break if learning signals depend on agent internals.
- Absence of comparative efficiency benchmarks against specialized graph theory implementations leaves performance claims unsubstantiated.

## Confidence
- **Unified Graph class**: Medium (implementation exists but break conditions possible).
- **DCE+Linear Build effectiveness**: High (empirical success on 25 conjectures with verification).
- **New Ramsey/Turán bounds**: Low (no supporting evidence in the excerpt).
