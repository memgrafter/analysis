# Neuro-Symbolic Activation Discovery: Transferring Mathematical Structures from Physics to Ecology for Parameter-Efficient Neural Networks

## Quick Facts
- **arXiv ID:** 2601.10740
- **Source URL:** https://arxiv.org/abs/2601.10740
- **Reference count:** 18
- **Primary result:** An activation discovered on particle physics data transfers to ecological classification, achieving 82.4% accuracy on Forest Cover with only 5,825 parameters—a 5.5× reduction compared to a conventional model requiring 31,801 parameters (83.4% accuracy).

## Executive Summary
This paper presents Neuro-Symbolic Activation Discovery, a framework that uses Genetic Programming (GP) to extract interpretable activation functions from a source domain (e.g., particle physics) and transfer them to a target domain (e.g., ecology). The core finding is a “Geometric Transfer” phenomenon: a formula like `x·cos(x)`, evolved on continuous physics data, also benefits ecological classification, leading to hybrid architectures that are 18–21% more parameter-efficient. Transfer succeeds only between continuous Euclidean domains; it fails when moving from continuous to discrete data (text). A novel efficiency metric, \(E_{param} = AUC / \log_{10}(\text{Parameters})\), formalizes the trade-off, showing that smaller models with tailored activations can match the performance of much larger standard networks.

## Method Summary
The approach comprises three stages. First, **Discovery**: GP is run on a 10% stratified subset of the source dataset (e.g., HIGGS) with a function set `{add, sub, mul, sin, cos, |·|}` to evolve a symbolic activation formula. Second, **Generalization**: all feature indices in the formula are replaced with a generic input `x`, yielding a domain-agnostic activation function (e.g., `x·cos(x)`). Third, **Transfer and Training**: the symbolic string is dynamically compiled into a differentiable PyTorch module. This activation is used in a hybrid neural network (with BatchNorm before each activation) and trained on the target dataset. Evaluation compares accuracy, AUC, and \(E_{param}\) against baseline models of varying sizes. Key hyperparameters include GP population = 500, generations = 5, and parsimony pressure = 0.01.

## Key Results
- **Geometric Transfer:** Activation discovered on HIGGS (e.g., `x·cos(x)`) transfers to Forest Cover classification, achieving 82.4% accuracy with just 5,825 parameters vs. 83.4% for a heavy ReLU model requiring 31,801 parameters (5.5× reduction, 1% accuracy drop).
- **Hybrid Efficiency:** Lightweight Hybrid models (with discovered activations) consistently achieve 18–21% higher \(E_{param}\) than larger ReLU-based baselines across multiple datasets.
- **Modality Boundary:** Transfer fails from continuous (physics/ecology) to discrete (text) domains, indicating the method’s applicability is restricted to continuous Euclidean spaces sharing geometric primitives.

## Why This Works (Mechanism)

### Mechanism 1: Geometric Primitive Transfer
- **Claim:** Activation functions encoding oscillatory, multiplicative structure (e.g., `x·cos(x)`) transfer between continuous Euclidean domains because they capture shared geometric primitives like periodicity and gradient invariance.
- **Mechanism:** GP discovers a symbolic formula on source-domain data; its functional form, when abstracted (`Xi→x`), encodes an inductive bias (e.g., wave-like patterns) that is mathematically relevant to the target domain’s continuous spatial structure, improving gradient efficiency.
- **Core assumption:** Domains share a “Geometric Grammar”—features derive from continuous measurements in Euclidean space governed by smooth, often periodic, relationships.
- **Evidence anchors:** Abstract and section 6.1 note that both HIGGS and Forest Cover involve continuous measurements; the oscillatory structure of σ_phys(x) captures periodic patterns relevant across domains. Support is largely empirical.
- **Break condition:** Transfer fails when source and target differ in fundamental data modality (e.g., continuous → discrete word frequencies).

### Mechanism 2: Inductive Bias Reduces Representational Burden
- **Claim:** Hybrid architectures combining a discovered, domain-specific activation with a lightweight network achieve superior parameter efficiency (\(E_{param}\)) because the activation’s inductive bias reduces the representational burden on weights.
- **Mechanism:** The discovered activation pre-processes hidden layer outputs with a domain-appropriate non-linearity. This reduces the number of subsequent weights needed to model the same decision boundary, trading increased per-activation computation for a dramatic reduction in total parameters.
- **Core assumption:** Standard activations (ReLU, GELU) lack the specific inductive bias needed for efficient representation of certain continuous scientific data distributions.
- **Evidence anchors:** Abstract and section 5.3 (Table 5) show Light Hybrid models outperform Heavy baselines in \(E_{param}\). Neighboring work on hardware-native activations indirectly supports the premise that activation choice impacts parameter needs.
- **Break condition:** If the discovered formula is poorly matched to the target data (e.g., overfitted discovery on a small/noisy target set), efficiency gains vanish or reverse.

### Mechanism 3: Efficiency Metric Captures Diminishing Returns
- **Claim:** The parameter efficiency metric \(E_{param} = AUC / \log_{10}(\text{Parameters})\) reveals that smaller models with tailored activations can outperform over-parameterized baselines, aligning with “diminishing returns” in neural scaling laws.
- **Mechanism:** Logarithmic scaling of parameters in the denominator penalizes order-of-magnitude size increases more than linear scaling. A model that achieves near-optimal AUC with few parameters scores higher than one needing many parameters for a marginal gain, formalizing the efficiency trade-off.
- **Core assumption:** Model utility scales sub-linearly with parameter count (supported by scaling laws), making raw parameter count a misleading sole proxy for capability.
- **Evidence anchors:** Section 3.3.1 defines \(E_{param}\) and justifies log scaling. Section 5.3 reports consistent 18–21% \(E_{param}\) improvements for Light/Hybrid models.
- **Break condition:** If scaling laws do not apply to the specific task/architecture (e.g., extreme under-parameterization where AUC collapses), the metric may misrepresent practical utility.

## Architecture Onboarding
- **Component map:** Discovery Module (GP) -> Generalization Module -> Compilation Module -> Hybrid Training Pipeline
- **Critical path:** 1) GP Discovery on 10% source subset; 2) Formula Generalization (replace all `Xi` with `x`); 3) Compilation into PyTorch module; 4) Hybrid Architecture Definition (insert discovered activation with BatchNorm); 5) Training & Evaluation; 6) Transfer Test (apply source formula to target dataset).
- **Design tradeoffs:**
  - *GP Configuration:* Small `generations=5` & `population=500` for speed vs. risk of missing complex formulas; function set restrictiveness vs. expressivity.
  - *Stability:* Unbounded activations necessitate BatchNorm and shallow depth (tested up to 2 layers).
  - *Transfer Strategy:* Using a formula from a large, clean source (HIGGS) may be more robust than discovering on a small/noisy target (Forest Specialist failure).
- **Failure signatures:**
  - Training instability: NaN loss or explosion if BatchNorm is omitted for unbounded activations.
  - No transfer benefit: Applying source formula to target yields lower accuracy than standard activations (e.g., Physics→Text).
  - Specialist underperformance: Target-domain discovery performs worse than transfer, indicating overfitting to discovery subset noise.
- **First 3 experiments:**
  1. **GP Convergence Check:** Run discovery on a small synthetic dataset (e.g., `y = sin(x1)*x2 + noise`) with seeds 42,43,44. Verify formula diversity is low and parsimony favors simple forms. Confirm no NaN outputs in compiled module on random tensor.
  2. **Activation Sanity Test:** Train a minimal Light network (e.g., 1 layer, 10 neurons) on a simple dataset (e.g., XOR or concentric circles) using a discovered formula from a prior run. Compare learning curve to ReLU. Goal: confirm the formula is trainable and not vanishing/exploding.
  3. **Transfer Proof-of-Concept:** Use the HIGGS-discovered `σ_phys(x)=x·cos(x)` on a small, clean continuous dataset (e.g., a subset of Forest Cover). Benchmark against ReLU/GELU in identical Light architecture. Expected: similar or better accuracy/\(E_{param}\), validating the Geometric Transfer premise before full-scale runs.

## Limitations
- GP discovery configuration (pop = 500, gens = 5) may overfit the 10% source subset; deeper searches could yield different formulas.
- Stability relies on BatchNorm before unbounded activations and shallow depth (≤2 layers); applicability to deeper architectures is unknown.
- Transfer tested on only one pair (HIGGS→Forest Cover); the “Geometric Grammar” claim lacks broader validation.
- \(E_{param}\) is novel; its correlation with real-world efficiency (e.g., latency, memory) is unestablished.
- Dynamic compilation via `exec` risks reproducibility; subtle bugs may cause silent failures.
