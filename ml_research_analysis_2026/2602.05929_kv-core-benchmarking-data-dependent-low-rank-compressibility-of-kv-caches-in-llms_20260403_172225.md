# KV-CoRE: Benchmarking Data-Dependent Low-Rank Compressibility of KV-Caches in LLMs

## Quick Facts
- **arXiv ID**: 2602.05929  
- **Source URL**: https://arxiv.org/abs/2602.05929  
- **Reference count**: 40  
- **Primary result**: Keys are consistently more compressible than values; cross-lingual variation exceeds domain variation; Normalized Effective Rank (NER) strongly correlates with compression performance degradation (Pearson \(r=0.88\) for values, \(0.64\) for keys).

## Executive Summary
KV-CoRE introduces a benchmark for analyzing the data-dependent low-rank compressibility of KV-caches in large language models. By applying incremental SVD to cached key/value activations across datasets, it computes Normalized Effective Rank (NER) to quantify compressibility per layer. Evaluation across multiple models and languages reveals systematic patterns: keys are more compressible than values, compressibility varies more across languages than domains, and layer-wise NER profiles are non-uniform. NER correlates strongly with performance loss under compression, offering a predictive metric for adaptive compression strategies.

## Method Summary
KV-CoRE processes a dataset by extracting per-token key and value activations from each attention layer. Instead of storing the full activation matrix \(K\) of size \(l \times d\) (sequence length \(\times\) projection dimension), it incrementally accumulates the covariance matrix \(C = K^\top K\) token by token, requiring only \(O(d^2)\) memory. After processing all tokens, an eigen-decomposition of \(C\) yields the right singular vectors and singular values of \(K\), equivalent to a full SVD. For each layer, it computes Normalized Effective Rank (NER) as \(e^{\sum p_i \log p_i} / r\), where \(p_i\) are normalized singular values and \(r\) is the full output dimension. NER measures the “evenness” of the spectrum; lower NER indicates a more skewed spectrum and higher intrinsic low-rank structure. The framework supports per-layer analysis and can generate compression matrices \(W_K V_k\) and \(V_k^\top\) for actual low-rank inference.

## Key Results
- Keys have lower NER than values across all evaluated models and datasets.
- Cross-lingual variation in NER is greater than cross-domain variation for the same language.
- NER strongly predicts performance drop when compressing KV-caches (Pearson \(r=0.88\) for values, \(0.64\) for keys).

## Why This Works (Mechanism)
KV-CoRE’s effectiveness rests on three pillars:

1. **Incremental SVD via covariance accumulation** avoids storing the full activation matrix. By updating \(C = K^\top K\) per token, the final eigen-decomposition produces singular vectors/values identical to a full SVD. This reduces memory from \(O(l d)\) to \(O(d^2)\), enabling dataset‑level analysis.
   - *Evidence*: Algorithm 1 and proof in Section 2.3; compared to full SVD, it yields identical Frobenius‑norm errors.

2. **Normalized Effective Rank (NER)** captures the skew of the singular value spectrum. Lower NER signifies that a few singular values capture most of the variance, implying high compressibility with little information loss when truncated. Empirically, NER correlates strongly with compression‑induced perplexity increases (Figure 5).
   - *Evidence*: Pearson \(r=0.88\) (values) and \(0.64\) (keys) across many model–dataset pairs (Section 4.3).

3. **Systematic data‑dependent patterns** emerge from large‑scale benchmarking. Keys are consistently more compressible than values; multilingual data show larger NER spread than English domains; layer‑wise NER often follows a U‑shape, reflecting architectural and training influences.
   - *Evidence*: Table 1, Figure 2, and Appendix B.1.

## Foundational Learning
- **Concept: Singular Value Decomposition (SVD) & Eckart‑Young Theorem**
  - *Why needed*: SVD finds the optimal low‑rank approximation of a matrix by truncating singular values; the Eckart‑Young theorem guarantees minimal Frobenius‑norm error.
  - *Quick check*: For matrix \(K\) with singular values \([10, 2, 0.5]\), the best rank‑1 approximation error is \(\sqrt{2^2 + 0.5^2} = \sqrt{4.25}\).

- **Concept: Effective Rank & Normalized Effective Rank (NER)**
  - *Why needed*: Effective rank (\(e^{\sum p_i \log p_i}\)) quantifies how many singular values are “active”. NER normalizes by the matrix’s rank, providing a dimensionless compressibility score.
  - *Quick check*: Singular values \([5,5,0,0]\) give \(erank = 2\), \(NER = 1\) (no low‑rank structure). For \([10,0,0,0]\), \(erank \approx 1.39\), \(NER \approx 0.347\) (high compressibility).

- **Concept: KV‑Cache in Autoregressive Decoding**
  - *Why needed*: The KV‑cache stores past \(k_t, v_t\) to avoid recomputation; its memory bandwidth is a bottleneck for long contexts. Understanding its size and structure is key to compression.
  - *Quick check*: For a 7B model with GQA (32 heads, 128‑dim), per‑token cache is \(32 \times 128 \times 2 \times 2 = 32\,\mathrm{KB}\) (fp16).

## Architecture Onboarding
- **Component map** (plain text flow):  
  Dataset → Model Forward Pass (extract \(k_t, v_t\)) → Covariance Accumulator (\(C \gets K^\top K\)) → Eigen‑Decomposition Module → NER Calculator → Layer‑Wise Analyzer → (Optional) Compression Matrix Generator.

- **Critical path**: Token stream enters model, per‑layer hooks capture activations, covariance matrices are updated online, after all tokens an eigen‑decomposition on each \(C\) yields \(V, \Sigma\), then NER is computed and aggregated for analysis.

- **Design tradeoffs**:
  - *Memory vs. Accuracy*: Incremental method uses \(O(d^2)\) memory instead of \(O(l d)\); assumes \(d \ll l d\).
  - *Static vs. Adaptive*: KV‑CoRE produces fixed, dataset‑specific compression; real‑time adaptation would need lightweight proxies like NER.
  - *Per‑Layer vs. Global*: Layer heterogeneity suggests per‑layer compression ratios, increasing system complexity but improving overall compression.

- **Failure signatures**:
  - *Memory explosion*: If projection dimension \(d\) is very large (>16k), the \(d \times d\) covariance matrix may exceed GPU memory.
  - *Poor NER‑performance correlation*: A model/dataset with high NER but robust compression (or vice versa) would break the primary predictive assumption.
  - *Layer‑wise anomaly*: A layer with NER near 1 indicates full rank usage; aggressive compression there would catastrophically degrade quality.
  - *Corpus mismatch*: Calibration data unrepresentative of deployment distribution yields misleading \(V_k\) matrices and suboptimal compression.

- **First 3 experiments**:
  1. *Replicate NER profile*: Use a small open model (e.g., Phi‑3‑mini) and Alpaca (1k tokens). Implement incremental SVD and verify the U‑shaped layer‑wise NER curves reported in Appendix B.1.
  2. *Validate optimality*: For a single layer, compute full SVD on \(K\) and the incremental \(V_k\). Confirm that truncated reconstructions \(K_k = U_k \Sigma_k V_k^\top\) yield identical Frobenius‑norm error for the same rank \(k\).
  3. *Test NER‑performance link*: Using the same setup, apply low‑rank compression with \(V_k\) at varying compression ratios. Compute perplexity on a held‑out set and derive ND‑PPL. Correlate ND‑PPL with NER; expect positive correlation (\(r \ge 0.64\)).

## Open Questions the Paper Calls Out
1. **Dynamic adaptive compression**: How to design algorithms that adjust compression ratios in real time based on per‑layer NER or other signals while minimizing overhead and maintaining stability? KV‑CoRE only provides diagnostic insights.
2. **NER’s weaker correlation for keys**: Why does NER predict compression sensitivity less well for keys (\(r=0.64\)) than values (\(r=0.88\))? What additional metrics (e.g., attention entropy, gradient sensitivity) could improve prediction?
3. **Cross‑layer dependencies**: KV‑CoRE analyzes layers independently. Could joint optimization of compression across multiple layers yield better memory‑quality trade‑offs than per‑layer decisions?
4. **Cause of rank collapse in low‑resource languages**: Some languages (e.g., Arabic, Finnish) exhibit unusually low NER. Is this due to tokenization artifacts, insufficient pretraining data, or inherent linguistic properties? How can training or data curation mitigate detrimental collapse?
5. **Data‑driven compressibility**: Can KV‑CoRE metrics guide pretraining data selection to intentionally shape KV‑cache compressibility for deployment under bandwidth constraints?

## Limitations
- **Generalizability**: Evaluations cover 5 model families and limited English domains plus 15 languages; findings may not transfer to newer architectures or unseen data distributions.
- **NER robustness**: The NER‑performance correlation is strong but not perfect (e.g., LLaMA‑2‑7B outliers); NER alone may not suffice for precise compression decisions.
- **Memory scaling**: The \(d \times d\) covariance matrix could become prohibitive for extremely large projection dimensions (e.g., >16k), requiring further approximations.

## Confidence
- **KV‑CoRE algorithm correctness**: High (theoretical equivalence proven, straightforward implementation).
- **NER as compressibility predictor**: Medium (empirical evidence strong but limited model diversity; moderate correlation for keys).
- **Systematic patterns (keys > values, cross‑lingual > domain, layer heterogeneity)**: Medium (consistent across tested models/datasets but lacking external validation).

## Next Checks
1. **Cross‑architecture replication**: Compute NER for a different family (e.g., Falcon‑40B) on a non‑English corpus; verify keys have lower NER than values and that layer‑wise profiles retain U‑shape.
2. **NER–performance correlation validation**: Perform actual KV compression using derived \(V_k\) matrices; measure ND‑PPL across a range of ranks; compute Pearson correlation; confirm \(r \ge 0.64\).
3. **Memory stress test**: For a model with projection dimension \(>10{,}000\) (e.g., 70B+ parameter models), attempt covariance accumulation; record memory usage and identify the dimension at which the process fails.
