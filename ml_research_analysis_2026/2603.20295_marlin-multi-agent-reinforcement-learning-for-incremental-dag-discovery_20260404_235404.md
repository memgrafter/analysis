# MARLIN: Multi-Agent Reinforcement Learning for Incremental DAG Discovery

## Quick Facts
*   **arXiv ID:** 2603.20295
*   **Source URL:** https://arxiv.org/abs/2603.20295
*   **Reference Count:** 11
*   **Primary Result:** A multi-agent RL framework for incremental causal discovery that disentangles invariant and state-specific relationships, consistently outperforming state-of-the-art baselines on synthetic and real-world non-stationary data streams while offering a parallel variant for significant speedups.

## Executive Summary
MARLIN addresses the challenge of learning causal directed acyclic graphs (DAGs) from online, non-stationary data streams. It introduces a multi-agent reinforcement learning framework where two specialized agents—one state-specific (reinitialized per system state) and one state-invariant (persisting across states)—collaboratively discover causal edges. Their policies generate separate DAGs that are fused to form the final structure for each data batch. A key innovation is a parameterized mapping from a continuous action space to a valid DAG, enabling efficient single-step policy learning. An efficient parallel variant, MARLIN-M, factors the action space for further runtime reduction. Evaluations on synthetic Linear-Gaussian and nonlinear datasets, as well as real-world root cause analysis tasks, demonstrate superior accuracy and efficiency compared to prior methods.

## Method Summary
MARLIN frames incremental DAG discovery as a multi-agent RL problem. For each batch of data corresponding to a system state, a state-specific agent (using an LSTM encoder for current batch statistics) and a state-invariant agent (using a FC encoder for aggregate prior knowledge) each propose a DAG via a shared policy network. The policy outputs a continuous action vector that is deterministically transformed into an acyclic adjacency matrix: the first `d` elements define a node ordering `h`, the remaining `d²` elements form a binary mask `S` via thresholding, and the final matrix is `A = H ⊙ S` (Hadamard product). The agents are guided by a reward combining a negative BIC score with decoupling terms that encourage the specific agent to diverge from past structures and the invariant agent to remain consistent. The final DAG is a weighted fusion (`β=0.5`) of both agents' outputs. A convergence monitor using Jensen-Shannon divergence between consecutive DAGs enables early stopping. For efficiency, MARLIN-M parallels the policy's action space factorization.

## Key Results
*   MARLIN achieves higher TPR, F1-score, and AUROC with lower FDR, SHD, and SID compared to baselines like RL-BIC and CORL on synthetic Linear-Gaussian and nonlinear datasets.
*   Its parallel variant, MARLIN-M, reduces average time per batch (ATB) by over 60% with minimal performance degradation.
*   On real-world root cause analysis tasks (OnlineBoutique, SWaT), MARLIN attains superior identification metrics (PR@K, AP@K, MRR) and competitive runtime.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Disentangling state-invariant and state-specific causal relationships via two dedicated RL agents enables efficient incremental learning in non-stationary streams.
*   **Mechanism:** A state-specific RL agent (reinitialized each new system state) learns causal edges unique to the current data distribution, while a state-invariant RL agent (continuously updated) accumulates stable, cross-state relationships. Their policies generate separate DAGs (˜G, ¯G), which are fused via a weighted sum (e.g., β=0.5) to form the final DAG per batch.
*   **Core assumption:** The underlying causal system transitions partially: some causal mechanisms persist across states (invariant), while others are state-dependent (specific).
*   **Evidence anchors:**
    *   [abstract] "disentangles state-invariant and state-specific causal relationships using two agents."
    *   [section 4.2] Detailed architecture of the two agents, their reinitialization/continuation policies, and fusion action ˆa=β˜a+(1−β)¯a.
    *   [corpus] Weak: Related corpus papers (e.g., ALIAS) focus on single-agent offline DAG learning; no direct multi-agent incremental analogs.
*   **Break condition:** The disentanglement assumption fails if causal relationships change completely at every transition (no invariant structure), causing the invariant agent to learn misleading patterns.

### Mechanism 2
*   **Claim:** Mapping a continuous real-valued vector to the DAG space via a parameterized decomposition (A = H ⊙ S) avoids explicit acyclicity enforcement, enabling efficient single-step policy learning.
*   **Mechanism:** An action vector *a* is split: first *d* values define a ranking *h* for an upper-triangular FC matrix *H*; remaining *d²* values thresholded define a binary mask *S*. The Hadamard product A = H ⊙ S yields an acyclic DAG by construction (since *H* is strictly upper-triangular by the ranking).
*   **Core assumption:** The decomposition in Eq. 5 (A=H⊙S with H derived from a total order) can represent any DAG (as per Teyssier & Koller 2012).
*   **Evidence anchors:**
    *   [abstract] "maps a continuous real-valued space to the DAG space as an intra-batch strategy."
    *   [section 4.1] Explicit formulation of Eq. 4–6, citing Charpentier et al. (2022) and Massidda et al. (2023) for acyclicity via permutation/upper-triangular matrices.
    *   [corpus] Strong: Corpus neighbor "Reinforcement Learning for Causal Discovery without Acyclicity Constraints" (ALIAS) uses a similar unconstrained mapping; "Tree Search in DAG Space" also explores DAG-space actions.
*   **Break condition:** Fails if the mapping cannot efficiently cover sparse DAGs (mask *S* becomes nearly zero), leading to poor exploration in large, sparse graphs.

### Mechanism 3
*   **Claim:** Factoring the action space into independent subspaces enables parallel policy execution (MARLIN-M), drastically reducing per-batch runtime with minimal accuracy loss.
*   **Mechanism:** The continuous action vector *a* has semantically distinct components (e.g., *h* for ordering, *s* for masking). Each component can be sampled/optimized in parallel by separate workers; their results combine post-hoc to form the full *a* and thus the DAG.
*   **Core assumption:** The contribution of each subspace to the final DAG score is approximately independent, so parallel exploration doesn’t disrupt the joint optimization.
*   **Evidence anchors:**
    *   [abstract] "leverages a factored action space to enhance parallelization efficiency."
    *   [section 5] Describes MARLIN-M variant and reports significantly lower ATB (e.g., Table 1: 32s vs. 81s) with slight SHD/F1 trade-off.
    *   [corpus] Weak: Corpus neighbor "Leveraging factored action spaces for efficient offline reinforcement learning in healthcare" is in a different domain; no causal discovery parallels.
*   **Break condition:** Breaks if the subspaces are highly coupled (e.g., mask *S* depends critically on exact ordering *h*), causing parallel sampling to yield invalid or low-reward DAGs disproportionately.

## Foundational Learning
### Concept: Reinforcement Learning for Combinatorial Optimization
*   **Why needed:** MARLIN frames DAG discovery as an RL task: the agent selects a continuous action *a* that maps to a discrete DAG, receiving a reward (negative BIC score). Understanding policy gradients, actor-critic training, and exploration-exploitation is essential to grasp how MARLIN navigates the super-exponential DAG space.
*   **Quick check:** How does the reward function balance BIC score minimization with the decoupling terms (Eq. 7,8) to enforce structure disentanglement?

### Concept: Incremental Learning in Non-Stationary Environments
*   **Why needed:** The paper addresses online DAG learning where data batches come from shifting distributions (system states). Core to MARLIN is the incremental update—reusing prior knowledge (invariant agent) while adapting to new data (specific agent). Understanding catastrophic forgetting, replay buffers (not used here), and state transition detection (via M-SSA) is key.
*   **Quick check:** Why is the state-invariant agent not reinitialized at new states, while the state-specific agent is?

### Concept: Graph Neural Networks for Structure Encoding
*   **Why needed:** Both agents use a GCN to encode the current estimated DAG (from previous batch) combined with data embeddings. This provides structural context for policy generation. Understanding graph convolutions, message passing, and how graph attributes are fused is necessary to follow the agent architecture.
*   **Quick check:** What is the purpose of concatenating the previous DAG adjacency matrix with the batch embedding (˜zl_t) to form the attributed graph input to the GCN?

## Architecture Onboarding
### Component map:
Data Batch X^l_t -> [State-Specific Encoder: LSTM(X^l_t) -> ˜z^l_t] & [State-Invariant Encoder: FC(X_{t-1}) -> ¯z^{l-1}_t -> concat(¯z^{l-1}_t, ˜z^l_t) -> ¯z^l_t] -> [GCN(Previous DAG G^{l-1}_t + embedding) -> Policy Network -> Sample Action] -> [Fusion: ˆa = β˜a + (1-β)¯a] -> [DAG Generator: A = H⊙S] -> [Reward: -BIC + decoupling term] -> [Actor-Critic Update] -> [Convergence Check: JS Divergence ξ].

### Critical path:
For each batch *l* in state *p_t*: 1) Encode current batch and prior state data via separate encoders. 2) Combine embeddings with previous DAG into an attributed graph. 3) Encode graph via GCN and decode to sample continuous actions (˜a, ¯a) from respective policies. 4) Fuse actions to get ˆa and map to DAG ˆG. 5) Compute reward using BIC score and decoupling term. 6) Perform policy update via TD error. 7) Compute JS divergence between consecutive DAGs; stop early if threshold exceeded.

### Design tradeoffs:
*   **β fusion weight:** Default 0.5 balances agents; tuning needed for domains with more/less invariant structure.
*   **Early stopping threshold (ξ):** Higher values speed up training but risk premature convergence on noisy batches.
*   **Parallelization (MARLIN-M):** Splits action vector; reduces ATB by ~60% but may slightly hurt accuracy on complex nonlinear graphs due to loss of holistic action evaluation.

### Failure signatures:
1.  **Agent collapse:** State-specific and invariant DAGs become identical (low decoupling term impact), indicating failed disentanglement → check L˜G/L̄G values.
2.  **No convergence:** JS divergence never exceeds threshold across many batches → revisit learning rates, reward scaling, or β.
3.  **Poor structure metrics:** High SHD/FDR on synthetic data with known ground truth → suspect inadequate exploration (increase entropy regularization) or flawed decoupling term weights (λ1, λ2).
4.  **MARLIN-M degradation:** Accuracy drop >5% on small graphs → parallel sampling too coarse; simplify subdivision or reduce parallelism.

### First 3 experiments:
1.  **Synthetic LG baseline (d=20, e=1):** Verify MARLIN beats RL-BIC/CORL in TPR/F1/SHD. Check ablation: MARLIN vs. MARLIN-S (single-agent) shows multi-agent advantage.
2.  **Nonlinear robustness (GP dataset):** Confirm MARLIN maintains lead over non-RL methods (NOTEARS, DAG-GNN) which fail on nonlinearities. Ensure MARLIN-M’s accuracy drop is acceptable (<3% F1).
3.  **Real RCA (SWaT):** Run root cause analysis; check PR@K/AP@K improvements and ATC reduction. Validate that learned DAGs capture meaningful system dependencies (qualitative inspection if ground truth unavailable).

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** How well does MARLIN's intra-batch DAG generation policy (Eqs. 4–6) scale to highly complex, dense, or cyclic-in-formation causal structures beyond the evaluated Synthetic Linear-Gaussian and specific nonlinear models?
*   **Basis:** [inferred] The evaluation primarily uses specific synthetic datasets (LG, LE, QR, GP) and real-world RCA tasks with known metric limitations. The method's mapping from a real-valued vector to a DAG without explicit acyclicity constraints is introduced in Section 4.1, but its theoretical limits for arbitrary SEMs are not analyzed.
*   **Why unresolved:** The paper demonstrates effectiveness on tested benchmarks but does not provide theoretical generalization bounds or extensive testing on extremely dense graphs, graphs with near-cycles, or SEMs with highly nonlinear, non-additive, or non-continuous noise. The robustness of the projection method (H from h, S from thresholding) to such cases is an open methodological assumption.
*   **What evidence:** Comprehensive experiments on synthetic datasets with systematically varied graph density, strength of nonlinearities, and noise distributions (e.g., heavy-tailed, mixture models) coupled with theoretical analysis of the projection's failure modes or identifiability conditions.

### Open Question 2
*   **Question:** What is the sensitivity of MARLIN's performance to the hyperparameters λ₁ and λ₂ in the decoupling reward terms (Eqs. 7, 8), and how should they be automatically tuned in a truly online, non-stationary stream where prior states are unreliable?
*   **Basis:** [explicit] The paper introduces decoupling terms L̃ and L̄ with weights λ₁ and λ₂ (Section 4.2) but sets β=0.5 by default and provides no sensitivity analysis or adaptive strategy for these coefficients across diverse transition scenarios.
*   **Why unresolved:** The balance between exploiting invariant structure and adapting to new state-specific information is critical. Fixed weights may fail under varying transition magnitudes (e.g., e% in synthetic data) or in real streams with unpredictable change magnitudes. The paper does not discuss how to set these without prior knowledge of the non-stationarity.
*   **What evidence:** An ablation study varying λ₁, λ₂ across a wide range on synthetic datasets with different transition noise rates (e%), and a proposed online adaptation rule (e.g., based on detected change magnitude or validation-like metrics within the stream). Performance robustness curves would show operational ranges.

### Open Question 3
*   **Question:** To what extent does the factored action space in MARLIN-M introduce approximation errors compared to the full joint action space, and what structural properties of the causal graph determine when parallelization incurs a significant performance penalty?
*   **Basis:** [inferred] Section 5 introduces MARLIN-M with factored action space for parallelization, noting a "slight accuracy drop" likely due to decomposition limiting "holistic causal modeling." However, no quantitative analysis isolates this error's source (e.g., independent subspace exploration vs. reconstruction artifacts) or identifies graph families where it is negligible vs. severe.
*   **Why unresolved:** The claim of minimal performance loss is based on overall metrics (Table 1, 2). Without controlled experiments comparing MARLIN-M to a non-factored MARLIN on graphs with specific properties (e.g., high modularity vs. highly interconnected), we cannot understand the trade-off's foundations. This limits practitioners' ability to choose between variants for their specific domain.
*   **What evidence:** Designed experiments where synthetic graphs are generated with controlled modularity (e.g., using cluster premixtures) and edge density between modules. Measure performance gap (ΔTPR, ΔF1) between MARLIN and MARLIN-M as a function of these graph properties to derive a "parallelizability index" or guideline.

### Open Question 4
*   **Question:** How robust is MARLIN's early stopping criterion based on the Jensen-Shannon (JS) divergence threshold (Eq. 9) to varying batch sizes, noise levels, and rates of true causal change within a system state? Could it cause premature convergence in some scenarios and inefficient over-exploration in others?
*   **Basis:** [explicit] The paper defines a convergence measure ξ using JS divergence between edge distributions of consecutive DAGs (Section 4.2, Eq. 9) and states termination when ξ exceeds a threshold. However, the threshold value is not specified, and its calibration across different data regimes is not discussed.
*   **Why unresolved:** Early stopping is crucial for efficiency in online streams. A fixed threshold might be too lenient for small, stable batches (causing unnecessary iterations) or too strict for noisy batches with constant small fluctuations (causing premature halt before learning the true state DAG). The paper provides no analysis of this dynamic.
*   **What evidence:** Empirical analysis on synthetic streams where the true DAG within a state is fixed but batch size and noise variance vary. Track ξ over batches and correlate threshold crossing with actual graph convergence (distance to ground truth DAG). Propose an adaptive threshold, e.g., a function of batch size or noise estimate.

### Open Question 5
*   **Question:** Does the disentanglement into state-specific and state-invariant agents (Section 4.2) correctly identify causal edges that are truly invariant vs. specific, or could it misattribute edges, especially when the data stream contains "forgetting" effects or gradual concept drift rather than discrete state transitions?
*   **Basis:** [inferred] The framework assumes a clear separation: some edges are constant across states (invariant), others appear only in specific states (specific). This is modeled via separate policies and decoupling rewards. However, real-world non-stationarity (as noted in Section 1) is often continuous or gradual, not discrete batch-wise changes. The paper uses a change point detector but the agent design assumes clean, discrete state boundaries.
*   **Why unresolved:** If a causal relationship weakens gradually over several batches (e.g., coefficient drift in a linear SEM), is it captured as "state-specific" to the latest batch or incorrectly as "invariant"? The decoupling terms (Eqs. 7, 8) use hard complement operations and dissimilarity constraints that may not model smooth transitions well. The evaluation uses discrete state transitions (synthetic) and discrete faults (real RCA), which align with the assumption but do not test it under drift.
*   **What evidence:** Experiments on synthetic streams with gradual parameter drift (e.g., linear SEM coefficients change linearly over batches) without discrete state changes. Analyze the learned DAGs: do invariant edges persist with stable strengths, and are drifting edges captured as state-specific in the final state or as a mix? Compare against a baseline without disentanglement.

## Limitations
*   **Disentanglement assumption validity:** The core premise that causal edges split cleanly into state-invariant and state-specific sets may not hold for all real-world non-stationary systems. Success is contingent on the existence of a meaningful invariant component.
*   **Implementation & hyperparameter opacity:** Critical training parameters (learning rates, λ₁/λ₂, ξ threshold, S-mask thresholding) and exact neural architectures (GCN layers, LSTM size) are omitted, hindering faithful reproduction and sensitivity analysis.
*   **State transition detection reliance:** The framework depends on Multivariate Singular Spectrum Analysis (MSSA) for detecting system state changes, but provides no implementation details or parameter settings, a key prerequisite for applying MARLIN to a new data stream.

## Confidence
*   **Disentanglement Mechanism:** Medium. Conceptual design is clear and supported by ablations, but external validity to arbitrary non-stationary processes is an untested theoretical claim.
*   **DAG Mapping Mechanism (A=H⊙S):** High. The construction is a well-established technique (cited) with strong theoretical guarantees for acyclicity.
*   **Parallelization Efficiency (MARLIN-M):** High. The reported runtime reduction is an empirical result from the paper's experiments, though the minor accuracy trade-off is noted.
