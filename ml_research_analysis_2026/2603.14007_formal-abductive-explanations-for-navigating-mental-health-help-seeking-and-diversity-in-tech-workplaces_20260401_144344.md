# Formal Abductive Explanations for Navigating Mental Health Help-Seeking and Diversity in Tech Workplaces

## Quick Facts
- **arXiv ID:** 2603.14007
- **Source URL:** https://arxiv.org/abs/2603.14007
- **Reference count:** 5
- **Primary result:** A formal abductive explanation framework applied to a neural network (74% accuracy) reveals that while 31.27% of decisions are biased concerning gender, critical features like family history (x3) and comfort discussing mental health with coworkers (x15) drive the majority of unbiased predictions.

## Executive Summary
This work tackles the lack of formal justifications for AI predictions about mental health help-seeking in tech workplaces, which undermines trust and fairness. It introduces a formal abductive explanation (AXP) framework to compute minimal, sufficient feature sets that guarantee each prediction from a neural network trained on the Mental Health in Tech Survey. The analysis shows that although a significant portion of decisions rely on gender (31.27%), most are unbiased. It identifies core determinants: family history (x3) is indispensable for 34% of all cases and 69.1% of negative predictions, while comfort discussing mental health with coworkers (x15) is critical for 22% of all cases and 42.8% of positive predictions. Specific feature combinations, such as (x1 ∧ x15) for positive predictions, account for many decisions. These precise explanations enable principled model selection, fairness auditing, and recourse planning.

## Method Summary
The method involves training a neural network (74% accuracy) on a binarized version of the Mental Health in Tech Survey (18 Boolean features). The trained model is converted into an exact logical/SMT formula. For each input instance, an abductive explanation (AXP) is computed: a minimal set of feature values that alone guarantees the prediction. This is done via a greedy algorithm that iteratively tests if removing a feature changes the outcome using an SMT solver. To audit bias, the process is constrained to exclude the protected attribute (gender); if an AXP still exists without it, the decision is unbiased. Explanations are aggregated to identify critical features (appearing in all explanations for some cases) and frequent feature combinations, revealing common decision pathways.

## Key Results
- 31.27% of model decisions are biased concerning gender, with biased decisions more frequent for negative predictions.
- Family history (x3) is indispensable for 34% of all cases and 69.1% of negative predictions.
- Comfort discussing mental health with coworkers (x15) is critical for 22% of all cases and 42.8% of positive predictions.
- Feature combination (x1 ∧ x15) explains 105 positive predictions, indicating a common decision pattern.

## Why This Works (Mechanism)
Formal abductive explanations (AXPs) provide rigorous, instance-specific justifications by computing minimal sufficient feature sets. For a given input and its prediction, the algorithm tests each feature's necessity by checking if flipping it (while holding others constant) changes the outcome. Features whose removal alters the prediction are retained, yielding a minimal set such that any individual sharing it will receive the same prediction. This relies on exactly modeling the classifier's decision boundary as an SMT formula and using constraint solving to verify feature necessity. The method fails if the model cannot be converted to a logical representation or if solving becomes intractable.

AXPs enable precise, instance-level bias auditing by determining whether a protected attribute is necessary for a decision. For each instance, the AXP computation is constrained to exclude the protected feature. If a minimal explanation still exists without it, the decision is unbiased; if all minimal explanations require the protected feature, the decision is biased. This isolates exactly which predictions rely on the sensitive attribute, assuming algorithmic bias manifests as indispensability of the protected attribute. The approach may misidentify bias if the protected attribute is perfectly correlated with another feature or if it is incorrectly specified.

Aggregating AXPs across populations reveals critical features and common decision patterns. By counting feature frequencies in explanations per prediction class, one identifies "critical" features. Frequent feature combinations indicate common decision pathways. This assumes that features appearing frequently in minimal explanations are causally influential drivers. Aggregation may mislead if explanations are highly heterogeneous or if training data is imbalanced.

## Foundational Learning
- **Concept: Boolean Feature Representation and Binarization**  
  *Why needed here:* The AXP method requires discrete, Boolean features to compute minimal sufficiency via constraint solving. The paper's dataset was binarized, converting all inputs to 0/1.  
  *Quick check:* If a feature like "age" is continuous, how would you discretize it to preserve predictive signal while enabling AXP computation?

- **Concept: Neural Network to SMT/Logical Formula Conversion**  
  *Why needed here:* To apply formal abduction, the black-box neural network must be transformed into an exact, checkable logical formula. This involves encoding each neuron's weighted sum and activation as constraints.  
  *Quick check:* What are the risks of precision loss when converting ReLU activations to linear constraints in an SMT formula?

- **Concept: Abductive vs. Counterfactual Explanations**  
  *Why needed here:* AXPs are sufficient reasons (features that alone guarantee the outcome), differing from counterfactuals (minimal changes to flip the outcome). This distinction is central to the paper's "rigorous justification" claim.

## Architecture Onboarding
Data Preprocessing -> Model Training -> SMT Conversion -> AXP Engine -> Analysis Modules. The critical path is: Raw data → Binarized dataset → Trained NN → SMT formula → Loop over all instances: [Compute AXP] → Store explanation → [Bias check] → Aggregate for critical features/combinations → Report statistics.

Design tradeoffs include: accuracy vs. interpretability (simpler models may yield shorter explanations but lower accuracy); binary vs. continuous (binarization simplifies computation but discards nuance); exhaustiveness vs. scalability (greedy algorithm is fast but may not find all minimal explanations). Failure signatures are: SMT solver returns "unknown" or times out; no AXP found for an instance; explosion in explanation length. First three experiments: 1) Sanity check with synthetic data having a known logical rule; 2) Bias replication with shuffled gender labels; 3) Clinical face validation of top critical feature combinations by mental health professionals.

## Limitations
- Exact dataset version, preprocessing details (binarization thresholds, missing value handling), and neural network architecture/hyperparameters are not fully specified, hindering exact replication.
- The SMT encoding for non-linear activations (ReLU, sigmoid) is conceptually described but lacks implementation specifics; precision loss or incorrect constraints could cause solver failures or incorrect AXPs.
- The greedy AXP algorithm is not guaranteed to find all minimal explanations; it may miss shorter sets when multiple minimal subsets exist, potentially affecting bias and criticality assessments.
