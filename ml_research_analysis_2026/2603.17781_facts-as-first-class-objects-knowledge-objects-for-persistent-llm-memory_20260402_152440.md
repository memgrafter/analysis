# Facts as First Class Objects: Knowledge Objects for Persistent LLM Memory
## Quick Facts
- **arXiv ID**: 2603.17781
- **Source URL**: https://arxiv.org/abs/2603.17781
- **Reference count**: 6
- **Primary result**: Knowledge Objects (KOs) achieve 100% exact-match accuracy across all corpus sizes (N=10–10,000) with constant cost, defeating context rot and adversarial retrieval failures.

## Executive Summary
This paper identifies "context rot" as a fundamental failure mode of persistent LLM memory, where summarization-based compaction causes catastrophic fact loss and silent goal drift. The proposed solution, Knowledge Objects (KOs), stores facts as externally addressable hash-keyed tuples, enabling O(1) retrieval independent of context window. Combined with density-adaptive switching to exact matching, KOs achieve perfect accuracy and constant cost scaling, validated across diverse benchmarks and models.

## Method Summary
The authors compare three memory approaches: in-context (serializing facts into prompts), retrieval-augmented generation (RAG) using embeddings, and the proposed Knowledge Objects (KOs). KO stores facts as (subject, predicate, object) tuples in an external database with SHA-256 keys derived from normalized subject and predicate. Queries are parsed to extract these keys, which are looked up exactly. For ambiguous or adversarial cases, a density-adaptive monitor computes the semantic density ρ of embedding-based retrieval results; if ρ exceeds τ=0.85, the system switches to exact key matching. The evaluation uses a synthetic pharmacology corpus (N=10–10,000), adversarial fact groups, multi-hop queries, and compaction experiments, measuring accuracy, cost, and constraint preservation.

## Key Results
- KO retrieval achieves 100% exact-match accuracy across all corpus sizes (10 to 10,000 facts), while in-context memory degrades sharply beyond context window limits.
- Density-adaptive hybrid retrieval yields 100% Precision@1 on adversarial facts where pure embedding RAG fails (20%).
- Multi-hop reasoning accuracy improves from 31.6% (in-context) to 78.9% (KO); compaction causes 60% fact loss and 54% constraint erosion.

## Why This Works (Mechanism)
- **Mechanism 1: Compaction Catastrophe**
  - **Claim**: In-context memory suffers catastrophic fact loss under compaction.
  - **Mechanism**: When context approaches capacity, summarization compacts prose into fixed-length summaries. Because summarization prioritizes gist and patterns, it discards precise values, exceptions, and specific numerical facts.
  - **Core assumption**: Lossy compression of fact-dense structured data cannot preserve arbitrary precision; specific tokens (e.g., IC50 values) are the first sacrificed.
  - **Evidence anchors**: Abstract: "compaction loss (60% facts lost at 36.7× compression)"; Section 6.1 experiment; cross-model replication in Table 5.
  - **Break condition**: If compaction ratio exceeds ~10×, fact recall drops below 50% (Table 5).

- **Mechanism 2: Silent Goal Drift**
  - **Claim**: Cascading compaction erodes project constraints silently.
  - **Mechanism**: Constraints appear once in natural conversation; summarization treats them as minor details vs. procedural content, and repeated compaction progressively drops non-default specifics, reverting behavior to defaults without confidence drop.
  - **Core assumption**: Summarization models are biased toward preserving common/general content over rare, specific constraints.
  - **Evidence anchors**: Abstract: "54% constraints erode after three compaction rounds"; Section 6.2 experiment (20 constraints → 46% correct after 3× compaction).
  - **Break condition**: After 2+ compaction rounds, non-default constraint retention falls below 60% (Table 4).

- **Mechanism 3: Knowledge Objects**
  - **Claim**: KOs avoid context rot via discrete hash-addressed storage.
  - **Mechanism**: Facts stored externally as (subject, predicate, object, provenance) tuples with SHA-256 keys on (subject, predicate). Retrieval is O(1) hash lookup independent of corpus size, bypassing reprocessing and thus avoiding capacity limits, compaction, and semantic interference.
  - **Core assumption**: Exact key matching on discrete identifiers eliminates embedding-space crowding and makes memory persistence independent of context window.
  - **Evidence anchors**: Abstract: "100% exact-match accuracy across all corpus sizes... 252× lower cost"; Section 7.1 (hash key design); cross-model replication confirms compaction loss is architectural.
  - **Break condition**: Query parsing fails to extract canonical (subject,predicate) that matches stored key (observed 20% failure on adversarial phrasing, section 7.3).

## Foundational Learning
- **Concept: Semantic Density (ρ)**
  - **Why needed here**: Determines when embedding retrieval fails (adversarial facts) and triggers density-adaptive switching to exact matching. High ρ means retrieved candidates are too similar for cosine discrimination.
  - **Quick check question**: "If four facts share >97% cosine similarity but have different object values, what property of the retrieved set indicates embedding retrieval will fail?" (Answer: High density ρ)

- **Concept: Orthogonality Constraint**
  - **Why needed here**: Theoretical basis for why neural memory (including compaction) loses facts—interference grows with N·ρ. Full O(N²) attention within window avoids collapse, but compaction reintroduces a fixed-size bottleneck.
  - **Quick check question**: "Why does Claude maintain 100% accuracy at N=7,000 in-context but lose 60% after compaction? Which architectural property changes?" (Answer: The switch from full attention to fixed-size summarization changes the memory mechanism, violating orthogonality.)

- **Concept: Hash-Based Exact Matching**
  - **Why needed here**: Core KO mechanism; provides O(1) retrieval without semantic similarity, immune to adversarial facts and capacity scaling.
  - **Quick check question**: "How does computing a hash on (subject, predicate) guarantee the same fact is retrieved regardless of corpus size or embedding model?" (Answer: Because the hash key is deterministic and unique for each unique (subject,predicate), lookup is exact and independent of semantic space.)

## Architecture Onboarding
**Component map**: Query Parser (Claude Haiku) -> Key Generator (SHA-256) -> KV Store (SQLite/PostgreSQL) -> Answer Generator (Claude Sonnet). Density Monitor sits between embedding retrieval and exact lookup to trigger switching.

**Critical path**: Parse -> Hash -> DB.get() -> Generate. Must maintain 100% parsing accuracy; DB lookup must be atomic.

**Design tradeoffs**:
- Parsing vs. schema: Flexible natural parsing vs. risk of predicate mismatch; solved by synonym mapping.
- Cost vs. latency: 2 LLM calls per query vs. single long context; constant O(1) cost wins at N > ~500.
- Simplicity vs. features: Flat KO store vs. full knowledge graph; tradeoff is engineering complexity for robust fact-level memory.

**Failure signatures**:
- Parsing miss: Query phraseology non-standard → wrong key → "not found" (20% on adversarial phrasing).
- DB outage: Entire KO layer fails; fallback to in-context if available.
- Hash collision: Negligible with SHA-256, but theoretically possible; monitor with uniqueness constraint.
- Density misclassification: τ too low → unnecessary exact match overhead; too high → adversarial failures.

**First 3 experiments**:
1. Scale validation: Run KO pipeline at N=10,000 facts (beyond any context window); expect 100% exact-match accuracy and constant ~$0.002/query cost.
2. Compaction comparison: Store 2,000 facts in-context, compact 36.7×, measure fact recall vs. KO baseline (expect 60% loss vs. 100%).
3. Density-adaptive thresholding: On adversarial facts corpus (within-group similarity >0.97), measure P@1 with/without density switching (expect 100% only with adaptive τ=0.85).

## Open Questions the Paper Calls Out
1. How can Knowledge Objects be reliably extracted from unstructured conversational data where facts are embedded in natural dialogue rather than explicit queries? The paper identifies predicate normalization as future work to address the 20% parsing failure rate.
2. Can the KO architecture's advantage on multi-hop reasoning be extended to longer inference chains (3+ hops) without degradation, and what are the failure modes at scale? The paper suggests this as a key direction after 2-hop results.
3. What is the optimal integration strategy for combining KO retrieval with existing RAG pipelines to handle both capacity limits and adversarial facts efficiently? The paper explicitly identifies integration with RAG as future work.
4. How can the density threshold (τ=0.85) for density-adaptive retrieval be automatically calibrated and adapted across different embedding models and corpus types? The paper notes that optimal threshold may require per-model calibration.

## Limitations
- Unknown: exact synthetic corpus generation algorithm (naming scheme, assay types) and how confusable/adversarial pairs are constructed.
- Unknown: precise prompt format for in-context memory (natural language vs. structured text) and query phrasing used in experiments.
- Unknown: compaction instruction template, target length, and which Claude model performed summarization.
- Unknown: how τ=0.85 was learned (validation set size, method) and whether it generalizes to other embedding models.
- Unknown: details of Titans training (learning rate, number of epochs, optimization) and evaluation protocol.
- Unknown: exact text of the 20 project constraints and the turn-by-turn conversation script for goal drift.
- Unknown: exact token counts for the KO pipeline’s parsing and answer stages (∼500/∼300) used for cost calculation.
- Unknown: generation of multi-hop queries (manual vs. automatic; validation of hop correctness).
