# Antidistillation Fingerprinting
## Quick Facts
- **ArXiv ID:** 2602.03812
- **Source URL:** https://arxiv.org/abs/2602.03812
- **Reference count:** 40
- **Primary result:** ADFP reduces detection p-value by nearly an order of magnitude while preserving model accuracy, and achieves higher ROC-AUC in unsupervised student detection compared to prior watermarking.

## Executive Summary
The paper tackles the problem of detecting model distillation—determining whether a student model has been fine‑tuned on a teacher’s outputs. Existing output watermarking techniques (e.g., red‑and‑green‑list) use static token biases, forcing a harsh trade‑off: stronger fingerprints degrade generation utility. Antidistillation fingerprinting (ADFP) aligns the fingerprinting goal with the student’s learning dynamics. It uses a proxy model to compute logit perturbations that directly maximize the expected green‑list token probability after the student fine‑tunes. Evaluations on GSM8K (math reasoning) and OASST1 (dialogue) show ADFP dominates prior art on the quality‑fingerprinting Pareto frontier. On GSM8K, ADFP reduces the detection p‑value by nearly an order of magnitude (e.g., 0.01 vs 0.09) while preserving or improving accuracy. In unsupervised closed‑weight student detection, ADFP achieves an ROC‑AUC of 0.903 vs 0.835 for the baseline. The approach remains effective even when the student’s architecture differs from the proxy.

## Method Summary
ADFP builds on red‑and‑green‑list watermarking but replaces the static bias with a dynamic perturbation that accounts for how the student learns. During teacher generation, for each token the system computes a green list S from a secret key k and the context. A proxy model supplies the token distribution q(·|context). From this, a perturbation ΔADS is derived—it approximates the gradient of the student’s per‑step fine‑tuning loss with respect to the teacher’s logits and targets tokens that are both probable under q and in the green list. The teacher’s logits are perturbed as z' = z + λ·ΔADS (λ controls strength) before sampling. After the student fine‑tunes (e.g., via LoRA) on the fingerprinted dataset, detection uses a held‑out evaluation set X: the fraction of tokens that fall in the green list (the GTP statistic) is computed and converted into a p‑value via Hoeffding’s inequality; a low p‑value indicates the presence of the fingerprint. This design directly maximizes detectability while minimizing unnecessary distortion, yielding a better utility‑fingerprint trade‑off.

## Key Results
- On GSM8K, ADFP lowers the detection p‑value by almost 10× (0.01 vs 0.09) compared to the red‑and‑green‑list baseline at equal teacher accuracy.
- In unsupervised detection with closed‑weight student models, ADFP achieves ROC‑AUC 0.903 vs 0.835 for the baseline.
- ADFP Pareto‑dominates prior art across both GSM8K (math) and OASST1 (dialogue) datasets, achieving stronger detection for the same generation quality.

## Why This Works (Mechanism)
ADFP works by aligning the fingerprinting objective with the student’s fine‑tuning dynamics, ensuring the watermark signal is efficiently absorbed. The core mechanism uses a proxy model to compute a perturbation ΔADS that directly maximizes the expected green‑list token probability (GTP) after the student updates. This perturbation is derived from the gradient of the per‑step fine‑tuning loss with respect to the teacher’s logits; focusing on tokens with high probability under the proxy model steers the student’s optimization toward the green list. The isotropic assumption (gradient Gram matrix ∝ identity), which holds exactly when only a final linear layer is trained (e.g., LoRA), simplifies ΔADS to a green‑list bias scaled by token probability. Detection then tests the GTP statistic via Hoeffding’s bound, yielding a conservative p‑value.

Effective transfer requires the proxy’s gradients to approximate the student’s update rule; large architectural or training mismatches weaken the fingerprint. The GTP test assumes independent token samples, so strong autocorrelation could compromise validity. Nonetheless, experiments confirm ADFP remains robust even when the student and proxy differ in architecture (e.g., Qwen vs. Llama), and the detection test is reliable under the evaluated conditions.

## Architecture Onboarding
**Component map**  
Teacher model → Fingerprinting sampler (adds λ·ΔADS) → token output. The sampler uses a hash function H to compute the green list S from context and secret key, and a proxy model to obtain distribution q. The student model later fine‑tunes on the collected data. The detection module evaluates the student with the same hash to compute GTP and a p‑value.

**Critical path**  
1. Fingerprinted generation: For each token, compute S = H(context, k); get q from proxy; compute ΔADS from q and S; perturb teacher logits z' = z + λ·ΔADS; sample token.  
2. Student fine‑tuning: Train student θ_s (e.g., with LoRA) on the fingerprinted dataset.  
3. Unsupervised detection: On a separate evaluation set X, compute empirical GTP; derive p‑value via Hoeffding’s inequality; below threshold (e.g., 0.05) indicates fingerprint presence.

**Design tradeoffs**  
- Fingerprint strength vs. utility: Larger λ improves detection but may hurt teacher accuracy; ADFP achieves a better trade‑off.  
- Proxy‑student alignment: Using the same model as proxy gives best results but requires knowing the student; a different proxy is more general but less effective.  
- Supervision in evaluation: Unsupervised (X disjoint from training) is realistic but provides weaker signal; supervised (X = training data) shows an upper bound.

**Failure signatures**  
- High p‑value (>0.1) despite fine‑tuning on fingerprinted data → poor transfer.  
- Large drop in teacher answer‑forced accuracy or NLL increase → over‑perturbation harming utility.  
- ROC‑AUC near 0.5 → fingerprint not detectable above chance.

**First 3 experiments**  
1. Reproduce trade‑off curves: For various λ/δ on GSM8K (unsupervised open‑weight), plot p‑value vs. teacher accuracy; verify ADFP dominates red‑and‑green‑list.  
2. Stress proxy mismatch: Use Qwen2.5‑3B as teacher/proxy and Llama‑3.2‑3B as student; compare p‑values at fixed teacher accuracy to gauge robustness.  
3. Partial fingerprinting: Vary the percentage α of fingerprinted data in student training (0%–100%); confirm ADFP keeps p‑values low even for α ≤ 20%.

## Open Questions the Paper Calls Out
- **Minimal fingerprint coverage:** What fraction of fingerprinted data is needed for reliable detection across architectures and domains? The paper studies limited conditions on GSM8K; a systematic study across diverse models and tasks is required.  
- **Proxy‑student compatibility:** How exactly does architectural distance between proxy and student affect ADFP effectiveness, and is there a point of diminishing returns? The paper tests only two cases; a controlled continuum of architectural variations would quantify robustness.  
- **Better detectors:** Could statistical tests beyond the average green‑list token probability (e.g., sequential tests, likelihood ratios, learned classifiers) achieve higher detection accuracy or require fewer evaluation samples? The paper relies solely on Hoeffding’s bound on GTP; no alternatives are explored.

## Limitations
- **Proxy approximation:** Effectiveness hinges on the proxy model’s gradients approximating the student’s update; architectural or training mismatches weaken the fingerprint.  
- **Isotropic assumption:** The derivation assumes the gradient Gram matrix ∝ identity, which is exact only for linear adapters (e.g., LoRA); for full fine‑tuning the perturbation may be suboptimal.  
- **Evaluation scope:** Experiments are confined to two datasets (GSM8K, OASST1) and specific model families; broader domain and architecture generalization remains unproven.

## Confidence
- **Fingerprint transfer:** High confidence (clear experimental evidence across settings).  
- **Utility preservation (Pareto dominance):** High confidence (consistent trade‑off improvements).  
- **Robustness to proxy‑student mismatch:** Medium confidence (limited tested mismatches; more extensive validation needed).
