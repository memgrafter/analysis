# AgentLAB: Benchmarking LLM Agents against Long-Horizon Attacks

## Quick Facts
- **arXiv ID**: 2602.16901
- **Source URL**: https://arxiv.org/abs/2602.16901
- **Reference count**: 40
- **Primary result**: Long-horizon attacks achieve 53–82% success rates across major LLM agents, significantly outperforming one-shot attacks and defeating common single-turn defenses.

## Executive Summary
LLM agents operating in long-horizon, tool-rich settings are vulnerable to multi-turn attacks that exploit temporal dynamics, yet existing security benchmarks focus only on single-turn threats. AgentLAB introduces the first systematic benchmark for long-horizon attacks, defining five attack families—intent hijacking, tool chaining, objective drifting, task injection, and memory poisoning—across 28 realistic environments with 644 test cases. It employs an adaptive multi-agent framework (planner, attacker, judge) that iteratively refines adversarial prompts based on the target agent’s behavior. Evaluation of major agents (GPT-4o, GPT-5.1, Qwen-3, Llama-3, Gemini-3, Claude-4.5) reveals average attack success rates of 53–82% (overall ~70%), with long-horizon attacks significantly outperforming one-shot baselines (e.g., GPT-4o: 79.9% vs 62.5%). Common single-turn defenses (Self-Reminder, Llama-Guard, DeBERTa detectors) prove largely ineffective, exposing a critical security gap and the urgent need for new protective mechanisms tailored to extended interactions.

## Method Summary
The AgentLAB benchmark comprises 644 test cases spanning 28 diverse agentic environments (e.g., WebShop, email workspaces) that simulate real-world deployments with tools and persistent memory. Each test case targets one of five long-horizon attack families. The attack framework uses a planner to decompose malicious tasks, an attacker to iteratively craft and refine prompts based on the target agent’s responses (using optimization like TextGrad when progress stalls), and a judge to evaluate whether the malicious objective was achieved. Target agents are equipped with standard tool-use and memory capabilities. Evaluation metrics include Attack Success Rate (ASR) and Turn-to-Success (T2S), with comparisons against one-shot baseline attacks and existing defenses (Self-Reminder, Llama-Guard, Repeated Prompt, DeBERTa Detector). A minimum viable reproduction involves setting up the benchmark code, configuring target agents for a subset of environments, and running the adaptive attack framework with specified model configurations (e.g., planner: GPT-5.1 temp 0.5, attacker: Qwen3-14B-Abliterated, judge: GPT-5.1 greedy).

## Key Results
- Average attack success rate (ASR) across five attack types ranges from 53% to 82% (overall ~70%).
- Long-horizon attacks substantially outperform one-shot baselines (e.g., GPT-4o: 79.9% vs 62.5% ASR).
- Common single-turn defenses (Self-Reminder, Llama-Guard, DeBERTa detectors) are largely ineffective against extended attacks.

## Why This Works (Mechanism)
### Adaptive Multi-Agent Attack Generation
The adaptive multi-agent framework consists of a planner that decomposes malicious tasks, an attacker that executes and iteratively refines prompts based on the target agent’s responses (using optimization like TextGrad when progress stalls), and a judge that evaluates whether the malicious objective has been achieved. This closed-loop system dynamically adapts to the agent’s behavior, overcoming static safeguards. It assumes the adversary can observe the agent’s responses (black-box or white-box). Evidence: Section 4.2 details the framework and its adaptive optimization.

### Attack Decomposition Over Multiple Turns
Long-horizon attacks distribute the malicious payload across multiple interactions, with each turn appearing benign or only mildly suspicious. The cumulative effect steers the agent toward the malicious goal while evading per-turn defenses that lack multi-turn context. This relies on the assumption that existing safety mechanisms operate independently on each user message or tool output. Evidence: Table 2 and Figure 7 show ASR growing with allowed attack turns, confirming the advantage of decomposition.

### Realistic, Tool-Rich Environments
By embedding attacks in 28 diverse agentic environments (e.g., WebShop, email workspaces) that feature persistent memory and tool usage, AgentLAB reveals vulnerabilities that synthetic benchmarks miss. The ecological validity increases the practical impact of the findings. The underlying assumption is that vulnerabilities observed in these realistic simulations transfer to production deployments. Evidence: Environments are sourced from established benchmarks (SHADE-Arena, AgentDojo, WebShop) and augmented with production-relevant capabilities.

## Architecture Onboarding
**Component map**:  
Malicious Task -> Planner -> Attacker -> Target Agent <-> Environment -> Judge -> Evaluator

**Critical path**:  
1. Initialize environment and target agent.  
2. Planner creates an attack plan from the malicious task.  
3. Attacker executes the plan over multiple turns, adaptively refining prompts based on the agent’s responses.  
4. Judge evaluates the final trajectory to determine if the malicious task succeeded.  
5. Evaluator logs metrics (ASR, T2S); for ablations, parameters like maximum attack turns (nturn) and optimization steps (nopt) are varied.

**Design tradeoffs**:
- Attacker model choice: Using an unconstrained model (e.g., Qwen3-Abliterated) increases attack potency but may overestimate real-world risk; a safer model yields more conservative estimates.
- Adaptivity mechanism: TextGrad provides gradient-free optimization but adds computational cost; simpler iterative refinement is cheaper but less effective.
- Memory bank vs static examples: Dynamic retrieval of successful attack exemplars improves success rates but depends on historical data storage.
- Turn budget: Too low underestimates long-horizon risks; too high may cause diminishing returns and evaluation slowdown.

**Failure signatures**:
- Stagnant ASR despite increasing nturn or nopt suggests the attack strategy is fundamentally misaligned with the environment.
- High variance across random seeds indicates non-robust evaluation; the attack may be sensitive to initial conditions.
- The judge frequently disagrees with manual inspection, signaling a need for better evaluation criteria.
- Defense mechanisms (e.g., Self-Reminder) show unexpectedly high effectiveness, possibly due to overfitting to the attack framework.

## Open Questions the Paper Calls Out
1. **What defense mechanisms can effectively mitigate long-horizon attacks across diverse LLM agents, given that existing single-turn defenses fail?**  
   - Basis: The paper explicitly states that defenses designed for one-shot attacks are difficult to retrofit for long-horizon scenarios, calling for tailored defense mechanisms (Conclusion) and demonstrates in Table 4 that Self-Reminder, Llama-Guard, and DeBERTa detectors show inconsistent and often limited effectiveness.  
   - Why unresolved: The benchmark is attack-only; no effective long-horizon defenses are proposed or evaluated. The security gap remains unaddressed.  
   - What evidence would resolve it: Development of a defense that reduces Attack Success Rate (ASR) by >80% on average across all five attack types and all six evaluated agent models on AgentLAB, with demonstrated transferability to new attack variants not seen during training.

2. **Do the vulnerability patterns measured by AgentLAB accurately predict real-world security risks in production LLM agent deployments outside the benchmark's 28 environments?**  
   - Basis: AgentLAB claims “ecological validity” by using environments from SHADE-Arena, AgentDojo, WebShop, and Agent-SafetyBench. However, these are curated academic benchmarks; real-world deployments may involve proprietary tools, different memory architectures, and novel domains not represented, potentially leading to different vulnerability profiles.  
   - Why unresolved: The paper does not validate whether attack success rates on AgentLAB correlate with security outcomes in actual deployments. Without such validation, the benchmark’s utility for guiding real-world security measures is uncertain.  
   - What evidence would resolve it: A study measuring long-horizon attack success rates on a representative sample of production LLM agents (e.g., commercial AI assistants, enterprise automation tools) and analyzing correlation with their performance on AgentLAB. Strong correlation (e.g., Spearman’s ρ > 0.7) would support generalizability.

3. **Can we identify reliable early-warning signals during the progression of a long-horizon attack that enable detection and intervention before the malicious task is completed?**  
   - Basis: AgentLAB’s evaluation metrics focus on final outcomes: Attack Success Rate (ASR) and Turn-to-Success (T2S). The paper analyzes how these metrics vary with attack turns and optimization steps but does not investigate whether successful attacks exhibit distinct intermediate trajectories that could be detected before catastrophic execution.  
   - Why unresolved: Current defenses must either prevent attacks entirely or accept failure. Mid-execution detection could allow timely human intervention or automatic rollback, providing a more practical safety layer.  
   - What evidence would resolve it: Analysis of large-scale AgentLAB trajectories identifying features (e.g., tool call sequences, reasoning patterns, memory retrievals) that distinguish attacks that will succeed from those that will fail, at early turns (e.g., within first 3-5 turns). A detector achieving >90% true positive rate at <10% false positive rate at turn 3 would demonstrate feasibility.

4. **What common mechanistic vulnerabilities underlie LLM agents' susceptibility to all five attack families in AgentLAB, and can a single defense strategy address multiple attack types simultaneously?**  
   - Basis: The five attacks—intent hijacking, tool chaining, objective drifting, task injection, memory poisoning—are presented as distinct categories with different adversarial vectors (user vs. environment) and strategies. The paper does not explore whether they share underlying causes, such as over-reliance on context, poor credit assignment across turns, or memory coherence failures.  
   - Why unresolved: If each attack requires a bespoke defense (as implied by the paper’s conclusion), security becomes a whack-a-mole game. A unified theory could lead to more robust and efficient protections.  
   - What evidence would resolve it: Ablation experiments that systematically vary attack parameters (e.g., number of turns, adaptivity, memory usage) across all five attack families to isolate common failure modes. Then, a defense inspired by the common mechanism that demonstrably reduces ASR for at least three of the five attack types on multiple agent models.

## Limitations
- **Proprietary model dependence**: Results rely on unreleased models (GPT-5.1, Claude-4.5, Gemini-3); substituting with available APIs (e.g., GPT-4o) may understate attack success rates.
- **Benchmark completeness**: 28 environments may not capture all real-world agent deployments; missing tool types (e.g., code executors) or memory systems could bias vulnerability rankings.
- **Judge reliability**: Ground-truth action sequences and evaluation prompts are undisclosed; automated scoring might diverge from human judgment without calibration.

## Confidence
- Long-horizon attacks outperform one-shot: High confidence
- Adaptive multi-agent framework efficacy: Medium confidence
- Ecological validity transfer: Low confidence
