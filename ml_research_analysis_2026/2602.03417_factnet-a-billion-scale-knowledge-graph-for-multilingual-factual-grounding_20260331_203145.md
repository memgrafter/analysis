# FactNet: A Billion-Scale Knowledge Graph for Multilingual Factual Grounding

## Quick Facts
- **arXiv ID:** 2602.03417
- **Source URL:** https://arxiv.org/abs/2602.03417
- **Reference count:** 40
- **Primary result:** Billion-scale multilingual KG with 92.1% grounding precision and new benchmark standards (KGC MRR 0.298, MKQA F1 41.36, MFC accuracy 0.73).

## Executive Summary
FactNet addresses large language model hallucinations by providing a billion-scale, auditable knowledge graph. It deterministically aligns 1.7B Wikidata statements with 3.01B evidence pointers from 316 Wikipedia editions via a three-layer architecture (FactStatement/FactSense/FactSynset), enabling byte-level reproducibility. The associated FactNet-Bench establishes rigorous evaluation standards for knowledge graph completion, multilingual QA, and fact checking, demonstrating strong performance even in low-resource languages.

## Method Summary
The pipeline consumes fixed Wikimedia dumps (Wikidata JSON, Wikipedia XML) through strictly deterministic stages: view extraction (sentences, infoboxes, tables), canonical normalization, and hierarchical matching. Each output layer retains byte-level pointers to source dumps, enabling exact reconstruction. FactStatement stores language-neutral triples; FactSense links statements to evidence spans with offsets; FactSynset merges equivalent cross-lingual statements via a versioned normalization policy. This design guarantees auditability while scaling to billions of facts.

## Key Results
- **Scale:** 1.7B atomic statements, 3.01B evidence pointers, covering 316 Wikipedia editions.
- **Grounding precision:** 92.1% overall, with per-type precision ranging from 88.9% (lexical) to 97.3% (wikilink).
- **Benchmark scores:** KGC text-aware MRR 0.298, MKQA Macro F1 41.36, MFC accuracy 0.73 (with evidence F1 0.31).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Deterministic, snapshot-based construction guarantees byte-level auditability and reproducibility.
- **Mechanism:** The pipeline processes fixed Wikimedia dumps (Wikidata JSON, Wikipedia XML) through non-stochastic stages: deterministic view extraction (sentence/infobox/table), canonical normalization policy π, and ordered matching. Every output (FactStatement, FactSense, FactSynset) retains pointers (page id, revision id, view type, locator) that allow exact reconstruction from the raw dumps.
- **Core assumption:** Wikimedia dumps are stable snapshots; deterministic parsers and normalization rules produce identical outputs given identical inputs.
- **Evidence anchors:**
  - [abstract] "strictly deterministic construction pipeline, ensuring that every evidence unit is recoverable with byte-level precision."
  - [section 2] "The construction is snapshot-based... every record retains original source identifiers."
  - [corpus] Weak for direct proof; neighboring papers (e.g., AtlasKV) focus on scaling RAG, not deterministic provenance.
- **Break condition:** Changes to Wikimedia dump formats, parser libraries (e.g., mwparserfromhell), or normalization rules without versioning would invalidate pointers.

### Mechanism 2
- **Claim:** The three-layer architecture (FactStatement/FactSense/FactSynset) decouples atomic assertions, textual grounding, and cross-lingual unification, enabling independent audit of each layer.
- **Mechanism:** FactStatement stores language-neutral Wikidata triples with qualifiers/references. FactSense links a statement to a specific evidence span in a language-specific Wikipedia edition via deterministic offsets. FactSynset merges equivalent statements across languages via normalization policies, providing canonical identifiers for downstream tasks.
- **Core assumption:** Separating structural facts from their textual mentions and cross-lingual equivalence allows lossless reconstruction and targeted filtering (e.g., by evidence type or language).
- **Evidence anchors:**
  - [abstract] "three-layer graph (FactStatement/FactSense/FactSynset)... ensuring byte-level reproducibility."
  - [section 2.1] Explicit schema definitions for each layer with provenance tracking.
  - [corpus] HiFACTMix uses graph-aware models for claim verification but lacks FactNet's layered provenance.
- **Break condition:** If the normalization policy π is inconsistently applied or merge reasons are not recorded, synset equivalence becomes non-auditable.

### Mechanism 3
- **Claim:** Ordered, datatype-aware matching with conservative fallbacks maximizes precision while maintaining deterministic grounding.
- **Mechanism:** For each subject page, matchers run in priority order: structure-based (infobox/table mappings), link-based (Wikilinks to entity QIDs), lexical (literal value matching within sentences). Fallback title matching is conservative (exact normalized title, single non-disambiguation page). This yields high precision (92.1%) at the cost of recall, especially in low-resource languages.
- **Core assumption:** Lexical and structural overlap between Wikidata values and Wikipedia text is sufficient for high-precision alignment without learned models.
- **Evidence anchors:**
  - [section 2.3] "ordered, datatype-aware matchers... We do not perform full relation extraction."
  - [section 3.4] Precision by match type: WIKILINK ENTITY 97.3%, INFOBOX FIELD 94.4%, LEXICAL VALUE 88.9%.
  - [corpus] T-REx uses distant supervision but lacks FactNet's pointer stability and multilingual scope.
- **Break condition:** Introduction of fuzzy matching or model-based alignment would break determinism and reduce precision.

## Foundational Learning
- **Concept: Distant Supervision**
  - *Why needed here:* FactNet aligns Wikidata statements to Wikipedia text without manual annotation; understanding its assumptions (e.g., "a fact mentioned on a subject page is evidence for that fact") is crucial to interpret grounding precision and missingness.
  - *Quick check question:* Why might a true Wikidata statement fail to align under distant supervision? (Answer: implicit phrasing, evidence on non-subject pages, template mapping gaps.)

- **Concept: Knowledge Graph Canonicalization**
  - *Why needed here:* FactSynsets merge equivalent statements via normalization policy π; this affects graph structure and benchmark splits. Misunderstanding canonicalization risks data leakage in KGC.
  - *Quick check question:* How do time-precision truncation and unit conversion impact synset merging, and why are they flagged with merge reasons? (Answer: They relax equivalence but preserve semantic intent; merge reasons allow users to filter.)

- **Concept: Multilingual Text Normalization**
  - *Why needed here:* Offsets and matching rely on language-specific normalization packs (Unicode form, segmentation rules). Inconsistencies would break pointer re-localization and cross-lingual alignment.
  - *Quick check question:* Why does FactNet use different segmentation backends (Stanza vs. rule-based) and how does it ensure deterministic offsets? (Answer: Backends are pinned by language pack IDs; offsets are on normalized strings, not raw bytes.)

## Architecture Onboarding
- **Component map:** Wikimedia dumps -> View extraction -> Normalizer -> Matcher -> Aggregator -> Edge Derivation -> Release
- **Critical path:** Dump → View → Match → Synset → Edge. The most failure-prone stage is Matching (within-page alignment), especially for low-resource languages.
- **Design tradeoffs:**
  - Precision over recall: strict datatype matching excludes paraphrastic evidence.
  - Determinism over coverage: no ML components, no fuzzy matching.
  - Provenance over convenience: byte-offset pointers require dump access for full reconstruction.
- **Failure signatures:**
  - Low recall in Tier 3 languages (64% loss at matching stage).
  - Evidence gap: only 31.8% of multilingual synsets have evidence in ≥2 languages.
  - RelationEdge precision drop at 2-hop (0.882) due to pivot ambiguity.
- **First 3 experiments:**
  1. Reproduce grounding precision audit: Run stratified sampling protocol (Appendix C.4) on a small dump subset to verify the 92.1% estimate.
  2. Test pointer stability: Sample 10k FactSenses, attempt re-localization from dumps using released parsers; expect >99% exact match.
  3. Run KGC baseline: Train a text-aware model (e.g., SimKGC) with predicate masking (Appendix D.3) and verify MRR ≈ 0.298; compare to unmasked ablation (MRR ≈ 0.351) to confirm leakage control.

## Open Questions the Paper Calls Out
1. How can neuro-symbolic alignment improve recall for low-resource languages while preserving byte-level auditability? (Future iterations will aim to bridge this coverage gap through controlled neuro-symbolic alignment strategies that enhance recall without sacrificing traceability.)
2. How can FactNet's schema be extended to represent complex n-ary relations and event-centric frames? (Expanding the schema to support complex n-ary relations is needed.)
3. How can FactNet transition from monolithic snapshots to a differential update model that tracks knowledge evolution? (Implementing dynamic, diff-based update mechanisms to synchronize with the evolving knowledge landscape.)
4. How can neural proposals for ungrounded statements be integrated while maintaining evidentiary trustworthiness? (Use small and localized language models to propose candidate spans; add only after rule-based verification or high-confidence NLI check.)
5. How can we construct a robust hallucination detection benchmark using negative evidence mined from FactNet? (Explicitly mine sentences that refute specific claims to incorporate negative evidence.)

## Limitations
- Deterministic pipeline depends on unmodified Wikimedia dumps and pinned parsers; format changes break pointers.
- Normalization policy π must be consistent; merge reasons are critical for cross-lingual equivalence.
- Grounding precision (92.1%) lacks independent replication; stratified audit needed.
- Benchmark scores risk leakage if Dev/Test synsets contaminate training; filtering must be verified.
- Low-resource segmentation relies on Stanza models; missing models force fallbacks, altering offsets.
