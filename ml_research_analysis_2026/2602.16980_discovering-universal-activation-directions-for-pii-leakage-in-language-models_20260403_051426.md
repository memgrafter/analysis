# Discovering Universal Activation Directions for PII Leakage in Language Models

## Quick Facts
- **arXiv ID:** 2602.16980
- **Source URL:** https://arxiv.org/abs/2602.16980
- **Reference count:** 40
- **Primary result:** UniLeak discovers latent activation directions that, when added during inference, amplify PII extraction by up to 13,399 unique records and, when subtracted, reduce leakage by up to 3,562 records—all without access to training data.

## Executive Summary
The paper investigates the internal representational mechanisms behind personally identifiable information (PII) leakage in language models. It introduces UniLeak, a framework that identifies *universal activation directions*—latent vectors in the residual stream—using gradient-based optimization on model-generated outputs annotated for PII. These directions are universal across prompts and models; applying them during inference systematically increases PII generation, while subtracting them mitigates leakage. The approach operates without any knowledge of the original training data or ground-truth PII, offering a new tool for privacy auditing and defense.

## Method Summary
UniLeak proceeds in three stages. First, it generates 200k sequences from the target model using baseline extraction attacks (e.g., BOS sampling). These sequences are automatically annotated for PII spans via regular expressions (emails, phone numbers) and the Flair NER tagger (names), yielding class-specific datasets \( D^{(c)}_{\text{gen}} \). Second, for each PII class \( c \), it optimizes layer-specific vectors \( v^{(c)}_\ell \) by minimizing the negative log-likelihood **only on tokens labeled as class \( c \)** across batches from \( D^{(c)}_{\text{gen}} \), with the vectors added to the residual stream at the first token position during the forward pass. Third, at inference, the learned directions can be **added** to amplify PII leakage in new prompts, **subtracted** to mitigate it, or **implanted** into the embedding matrix for a minimal poisoning attack. The entire pipeline requires no access to the model’s training data.

## Key Results
- **Amplification:** Combining UniLeak with baseline attacks increases unique training PII records by up to 13,399 across three models (GPT-Neo-125M, Phi-2, Llama-3-8B) and two datasets (Enron, TREC). The extracted PII sets are largely non-overlapping with baseline attacks, demonstrating complementary value.
- **Mitigation:** Subtracting the directions reduces PII leakage by up to 3,562 records while preserving generation quality in most cases.
- **Efficiency & Universality:** The directions are most effective when applied to **early layers**, enabling a simple embedding poisoning attack that adds the layer-0 direction to the BOS token embedding.

## Why This Works (Mechanism)
The existence of universal activation directions implies that PII leakage is driven by consistent, low-dimensional patterns in the model’s internal representations that are independent of the input prompt. By optimizing these directions on self-generated data annotated with PII, UniLeak aligns the residual stream with the model’s own “PII-generating” mode. Steering the activations at the first token position biases the entire generation trajectory toward states that favor PII recall. The universality across models and layers suggests a common memorization mechanism in LLMs where certain latent directions persistently activate training data associations.

## Foundational Learning
1. **Self-generated data for privacy auditing**  
   *Why needed:* Enables analysis without original training data, addressing data access barriers.  
   *Quick check:* Compare PII extraction rates on self-generated vs. held-out training samples; should be correlated.

2. **Gradient-based direction optimization**  
   *Why needed:* Finds minimal perturbations that increase target behavior (PII generation) without retraining.  
   *Quick check:* During optimization, monitor validation loss on PII tokens; it should decrease steadily.

3. **Residual stream intervention**  
   *Why needed:* Allows precise, layer-specific control over model computations.  
   *Quick check:* Apply a random direction at an early layer and verify output changes (even if nonsensical).

4. **Early layer effectiveness**  
   *Why needed:* Interventions in initial layers suffice for amplification, reducing side effects on coherence.  
   *Quick check:* Test amplification across layers; expect peak effect in layers 1–5 for models tested.

5. **Automated PII annotation via regex and NER**  
   *Why needed:* Scales labeling of sensitive information in generated text.  
   *Quick check:* Manually inspect 100 annotated sequences; precision/recall should be high for structured PII (email, phone).

## Architecture Onboarding
- **Component map:**  
  Data Generation → Annotation → Direction Optimization → Inference Application  
  (Model sampling) → (regex/Flair labeling) → (gradient descent on PII tokens) → (amplify/mitigate/poison)

- **Critical path:**  
  Generate 200k sequences → Annotate PII spans → For each PII class, optimize \( v^{(c)}_\ell \) by minimizing loss **only on PII tokens** → Apply \( v^{(c)}_\ell \) at first token position during new generations.

- **Design tradeoffs:**  
  - All layers vs. single layer: All layers yield stronger amplification but higher quality risk; single early layer balances.  
  - First token vs. all positions: First token only prevents degenerate, repetitive outputs.  
  - Initialization scale \( \sigma \): Too high causes optimization instability; too low slows convergence.

- **Failure signatures:**  
  - Validation loss spikes during optimization → reduce \( \sigma \) or ensure intervention only at first token.  
  - Generated text is repetitive/nonsensical → check that steering is applied **only** at the first token position.  
  - Low amplification despite correct setup → verify \( D^{(c)}_{\text{gen}} \) contains sufficient true training PII; ensure loss masks non-PII tokens.  
  - Mitigation causes severe incoherence → especially when combined with optimized prompts (e.g., Private Investigator); evaluate on broader prompts.

- **Exactly 3 first experiments:**  
  1. Replicate the annotation pipeline on 1000 generated sequences using the same regex patterns and Flair `ner-english-large` model; compute PII labeling rate.  
  2. Run direction optimization for a single PII class (e.g., email) on layer 0 with 5k sequences; confirm validation loss decreases over 3 epochs.  
  3. Apply the learned direction at the first token to a simple prompt (“My email is”) and check if generated emails belong to the training domain (e.g., Enron-style addresses).

## Limitations
- Exact regex patterns and Flair NER model version for PII annotation are unspecified, affecting reproducibility of the labeling step.
- The Private Investigator baseline relies on optimized single-token prompts from Keum et al. (2025), whose procedure is not detailed.
- Dataset split seeds, preprocessing details, and the precise definition of “training PII” (e.g., verbatim match criteria) are unclear.
- Resource requirements (GPU memory, time) for UniLeak optimization on large models (e.g., Llama-3-8B) are not fully documented.

## Confidence
- **Amplification of PII extraction:** Medium (strong empirical gains but depend on annotation quality and self-generated data richness).
- **Mitigation via direction subtraction:** Medium (significant reduction shown, but quality trade-offs emerge in some settings).
- **Universality across layers/models:** Medium (validated on three models; broader architectural generalization remains to be tested).
