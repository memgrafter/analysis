# Predicting The Cop Number Using Machine Learning

## Quick Facts
- **arXiv ID:** 2602.16600
- **Source URL:** https://arxiv.org/abs/2602.16600
- **Reference count:** 10
- **Primary result:** Machine learning models (tree-based ensembles and GNNs) predict cop number with high accuracy (up to 97.79% macro-F1) from graph structure.

## Executive Summary
This study addresses the challenge of predicting the cop number—the minimum number of cops required to capture a robber in a pursuit‑evasion game on a graph—directly from graph structure. The authors evaluate two complementary approaches: classical machine learning using 34–40 handcrafted graph invariants (e.g., connectivity, clique size, treewidth) and graph neural networks (GNNs) that operate on raw adjacency. Tree‑based ensembles (Histogram Gradient Boosting) achieve 97.79% macro‑F1, while a Graph Isomorphism Network using only node degrees reaches 94.65% accuracy. Interpretability analysis confirms that the most predictive features align with known theoretical bounds, offering both a scalable approximation for intractable exact computation and new insights for graph theory.

## Method Summary
The dataset comprises approximately 300,000 connected graphs with 2–13 vertices, each labeled with its exact cop number (1, 2, or 3). For classical machine learning, the authors compute 34–40 structural invariants and preprocess them: convert to numeric, impute missing values with the median, and apply z‑score normalization. A stratified 80/20 train/test split is used. Models include Decision Tree, Random Forest, Histogram Gradient Boosting (HistGB), and Logistic Regression, all trained with class weighting to handle severe imbalance (75.95% class 2). For deep learning, each graph is converted to a PyTorch Geometric `Data` object with node degree as the sole feature (normalized per graph). A Graph Isomorphism Network (GIN) with three GINconv layers, BatchNorm, ReLU, global add pooling, and an MLP classifier is trained with dropout 0.3, Adam optimizer (lr=1e‑3), batch size 16, and 30 epochs. All models are evaluated on accuracy, macro‑F1, and confusion matrices; interpretability relies on SHAP values and permutation importance.

## Key Results
- Tree‑based ensembles (HistGB) achieve 97.79% macro‑F1, with most misclassifications occurring between cop numbers 1 and 2.
- Graph Neural Networks (GIN) using only degree features achieve 94.65% accuracy, demonstrating that raw topology carries strong predictive signal despite minimal input.
- Interpretability identifies node connectivity, clustering coefficients, clique size, and treewidth as the top predictive features, corroborating theoretical graph‑theory results.

## Why This Works (Mechanism)
### Mechanism 1: Handcrafted features encode structural determinants
**Claim:** Handcrafted graph structural features provide sufficient information to predict cop number with high accuracy.  
**Mechanism:** Features such as node connectivity, clique size, and treewidth act as proxies for theoretical bounds on pursuit‑evasion difficulty; they quantify graph resilience (e.g., disjoint paths) and robber mobility constraints, both mathematically linked to cop number.  
**Core assumption:** The selected 34–40 invariants capture the dominant structural determinants for small graphs (2–13 vertices), and their interactions are learnable by tree‑based models.  
**Evidence:** Interpretability shows top features align with known theory; HistGB reaches 97.79% macro‑F1.  
**Break condition:** Introducing graphs with cop number ≥4 may expose missing higher‑order patterns not present in the current feature set.

### Mechanism 2: Tree ensembles capture non‑linear interactions
**Claim:** Tree‑based ensembles effectively model non‑linear interactions between correlated graph features to separate cop number classes.  
**Mechanism:** Decision trees partition the feature space using axis‑aligned splits; ensembles aggregate many such rules to reduce variance and handle class imbalance, capturing complex thresholds (e.g., “if treewidth > 2 and clique size < 4 then c(G)=2”).  
**Core assumption:** Cop number boundaries in the handcrafted feature space are definable by piecewise‑constant decision surfaces approximable by trees.  
**Evidence:** Gradient Boosting outperforms logistic regression (0.9779 vs. 0.9437 accuracy), confirming non‑linear separability; SHAP vs. permutation importance reveals feature correlation handling.  
**Break condition:** If cop number depends on subtle global properties not captured by local thresholds, deep trees may become necessary, increasing overfitting risk.

### Mechanism 3: GNNs learn from raw topology
**Claim:** Graph Neural Networks (GIN) can learn cop number directly from raw graph topology (node degrees only), implying cop number is strongly encoded in adjacency structure.  
**Mechanism:** GIN’s message‑passing layers aggregate neighborhood information; with degree as initial feature, the network iteratively builds structural representations (e.g., cycles, articulation points). Global pooling then yields a graph‑level embedding for classification.  
**Core assumption:** GIN’s Weisfeiler‑Lehman power is sufficient to distinguish cop numbers using only degree features.  
**Evidence:** GIN achieves 94.65% accuracy, only 3.2% below HistGB, confirming topology alone carries predictive signal.  
**Break condition:** For graphs with identical degree distributions but different cop numbers due to non‑local properties (e.g., graph products), degree‑only GIN may fail without additional positional encodings.

## Architecture Onboarding
**Component map:**  
Data loader (SQLite) → Feature preprocessor → Model trainers (Decision Tree, Random Forest, HistGB, Logistic Regression) / GNN pipeline (PyTorch Geometric) → Interpretability engine (SHAP, permutation)

**Critical path:**  
1. Data loading  
2. Feature preprocessing (numeric conversion, median imputation, z‑score standardization)  
3. Stratified 80/20 train/test split  
4. Model training (HistGB or GIN)  
5. Evaluation (accuracy, macro‑F1, confusion matrix)  
6. Interpretability (SHAP on Random Forest, permutation importance)  

*GNN variant:* after step 1, convert graphs to PyTorch Geometric `Data` objects with degree features; then GIN training (3 layers, dropout 0.3, Adam lr=1e‑3, batch 16, 30 epochs); then evaluation.

**Design tradeoffs:**  
- Handcrafted features vs. GNN: Features offer interpretability and higher accuracy; GNNs avoid manual engineering but are less transparent and slightly less accurate on minority classes.  
- Tree ensemble complexity: HistGB balances speed and performance; deeper trees may overfit the small cop‑number‑3 cluster.  
- GNN depth: 3 layers chosen for small graphs (2–13 vertices); deeper may overfit, shallower may lose structural information.

**Failure signatures:**  
- High false negatives for cop number 3 (especially GNN: 100/276 missed) → model not trustworthy for extremal graph search.  
- Logistic regression confusion between classes 1 and 2 → indicates non‑linear feature relationships.  
- Disagreement between SHAP and permutation importance rankings → warns of multicollinearity; interpret with caution.

**First 3 experiments:**  
1. Baseline: Train HistGB on all 34–40 features; record accuracy, macro‑F1, confusion matrix. Expect >97% accuracy, errors mainly between classes 1 and 2.  
2. Ablation: Train GIN with degree‑only features; compare accuracy to HistGB. Expect ~94–95% accuracy, no false predictions of cop number 3 for lower‑class graphs.  
3. Interpretability: Compute SHAP values for Random Forest on 800‑sample; cross‑check with permutation importance. Expect connectivity, clique size, treewidth in top 5 for both; investigate discrepancies.

## Open Questions the Paper Calls Out
1. **Do pretrained graph foundation models enhance cop number prediction for larger graphs?**  
   The authors suggest future work could explore graph foundation models; currently models are trained only on ≤13‑vertex graphs, so transferability is unknown. Proposed evidence: fine‑tune a foundation model on the cop dataset and evaluate on 14–20‑vertex graphs.

2. **Does adding top predictive features (connectivity, clustering, clique size, treewidth) to GNNs improve cop number prediction?**  
   Incorporating the highest‑ranked importance features may boost performance, but this remains untested.

3. **Can ML models generalize to larger graphs (≥14 vertices) and predict cop numbers >3?**  
   External validity is limited by graph size; scaling to bigger graphs and higher cop numbers is an open challenge.

4. **How can we interpret feature importance reliably given high correlation among graph invariants?**  
   SHAP assumes feature independence, which may be violated; correlation‑aware methods (e.g., hierarchical SHAP, conditional permutation) are needed.

## Limitations
- **Dataset accessibility:** The curated SQLite database (~300k graphs) is not publicly released; recreating it requires re‑implementing the cop‑number algorithm and feature calculations, risking drift and inconsistency.  
- **Hyperparameter gaps:** Key hyperparameters (e.g., GIN hidden dimensions, MLP architecture, HistGB learning rate) are unreported, hindering faithful reproduction and potentially affecting performance.  
- **Feature correlation confounders:** SHAP’s independence assumption may misrepresent true feature contributions due to high correlation among graph invariants, complicating interpretability.

## Confidence
- Handcrafted feature sufficiency: High  
- Tree ensemble efficacy: Medium  
- GNN topology learning: Low
