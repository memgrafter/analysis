# Exploring Recommender System Evaluation: A Multi-Modal User Agent Framework for A/B Testing

## Quick Facts
- arXiv ID: 2601.04554
- Source URL: https://arxiv.org/abs/2601.04554
- Reference count: 40
- Primary result: Agent reliably ranks models aligned with real-world metrics; agent-generated data improves downstream AUC by up to 0.0036; visual modality critical (gains halved without it).

## Executive Summary
Online A/B testing for recommender systems is costly and slow. This paper introduces A/B Agent, a multi-modal LLM agent framework that simulates user interactions within a sandbox environment mimicking real recommendation user interfaces. The agent processes both textual metadata and visual posters, maintains long- and short-term memory, and operates under a fatigue system to produce realistic session dynamics. Results show that the agent’s simulated metrics (CTR, CVR, AR) correlate with offline model quality metrics (Recall@20, NDCG@20). Furthermore, data generated by the agent can augment training data, yielding downstream AUC improvements of up to 0.0036 (e.g., DeepFM from 0.7520 to 0.7542). Ablation studies confirm the essential role of visual perception, as removing posters halves the performance gains.

## Method Summary
The framework builds a sandbox recommendation environment that renders items via a two-page UI: a homepage list displaying movie posters, titles, genres, and ratings, and a detail page with full metadata and overview. An LLM-based agent interacts with this UI by issuing actions (click, next page, back, watch and rate, exit) based on its static user profile (demographics), a dynamic preference summary (LLM-generated from interaction history), retrieved memories from past interactions (using both textual and visual embeddings), and the current session context stored in short-term memory. A fatigue system assigns costs to actions that depend on action type and estimated interest; sessions terminate when accumulated fatigue reaches zero. By simulating many users and sessions, the framework aggregates interactions to compute evaluation metrics (CTR, CVR, AR) that can rank recommendation models or generate synthetic interaction data for model training. The approach is validated on the MM-ML-1M dataset, an enriched MovieLens-1M with posters and IMDb metadata.

## Key Results
- Agent-simulated CTR/CVR/AR rankings (e.g., DeepFM > AFN) align with real-world Recall@20 and NDCG@20.
- Agent-generated interaction data improves downstream model AUC by up to 0.0036 (e.g., DeepFM from 0.7520 to 0.7542).
- Ablation study: Removing visual modality (posters) reduces downstream AUC gains by half.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Multimodal perception (text + poster images) enables the agent to simulate realistic user engagement with a recommendation UI, leading to evaluation outcomes (CTR, CVR, AR) that align with offline model quality metrics (Recall@20, NDCG@20).
- **Mechanism:** The sandbox environment presents items via a multi-page UI (homepage list + detail page) that includes both textual metadata (title, genres, overview) and visual posters. The agent's action module processes this multimodal input to make click/view/rate decisions, mimicking how real users gather evidence from different information granularities before committing. This creates behavior trajectories with higher fidelity than text-only simulators.
- **Core assumption:** Real user decisions on platforms like Netflix/IMDb are influenced by a combination of textual descriptions and visual poster aesthetics. Simulating this perception process is necessary for accurate outcome prediction.
- **Evidence anchors:**
  - [abstract]: "...fails to simulate the perception process... due to the lack of real environments and visual perception capability."
  - [section 2.3.1]: Detailed UI design separating homepage (poster+title+rating+genre) and detail page (adds overview+metadata).
  - [section 3.5 (Ablation)]: "Without it [visual modality], gains reduce by half." Removing posters from the UI halved the downstream AUC improvement from agent-generated data.
  - [corpus]: The neighbor "SimUSER" paper also uses LLM-based simulation but is noted in [Table 7] as lacking multi-modal support, positioning A/B Agent's contribution as addressing this gap.
- **Break condition:** If the visual modality (poster images) is removed from the environment, the agent's simulated CTR/CVR rankings and the utility of its generated data for model augmentation degrade significantly, as evidenced by the ablation study.

### Mechanism 2
- **Claim:** A dual-memory system (long-term with textual/visual retrieval + short-term session context) provides stable yet adaptive user modeling, preventing repetitive behavior and enabling consistent preference expression across sessions.
- **Mechanism:** Long-term memory stores past interactions and retrieves relevant past experiences using embedding similarity (text via `text-embedding-3-small`, image via CLIP) to ground decisions in persistent taste. Short-term memory tracks the current session's actions and observations, maintaining contextual coherence (e.g., not clicking the same movie twice in one session). This combination allows the agent to exhibit both long-term consistency (e.g., preferring drama across sessions) and short-term exploration diversity.
- **Core assumption:** Human-like recommendation browsing involves both enduring preferences and in-session adaptive exploration. Memory mechanisms are required to model this interplay, not just current page context.
- **Evidence anchors:**
  - [section 2.4.2]: Explicit design of "long-term and short-term memory" with "textual and visual retrieval" for long-term memory. Short-term memory stores "interface type, local observations, estimated interest levels, and action."
  - [section 3.3.1]: "Agent exhibits consistently higher CTR, CVR, and AR under recommendation lists with more positive items." This stable preference alignment is facilitated by memory retrieval reinforcing consistent interests.
  - [section 3.4 (Case Study, Case 2 & 3]": Agent skips a drama page based on historical disinterest (long-term memory) and later rates a drama highly based on past high ratings for similar films, showing memory's role in consistent taste.
- **Break condition:** If memory retrieval (especially long-term, cross-session) is disabled, the agent's behavior would become myopic and inconsistent, failing to show stable preference alignment across different recommendation lists or sessions. This would degrade the correlation between simulated metrics and real model performance.

### Mechanism 3
- **Claim:** A fatigue system that modulates action costs based on interest level and action type introduces realistic session termination and non-linear exploration patterns, aligning agent activity traits (low/medium/high) with real user engagement distributions.
- **Mechanism:** Each action (click, page nav, watch/rate) consumes a fatigue value. The cost is a base coefficient modulated by the agent's estimated interest in the current item/page (`F = C_a * (φ_max - (ι - ι_min)/(ι_max - ι_min) * (φ_max - φ_min))`). Higher interest reduces perceived fatigue cost. When accumulated fatigue reaches zero, the session ends. This creates a dynamic trade-off: high-interest items are "cheaper" to engage with, encouraging deep dives on appealing content, while low-interest browsing exhausts resources faster, leading to earlier exit.
- **Core assumption:** Real user sessions are bounded by cognitive or time resources, and engagement intensity varies non-linearly with interest. Simple fixed-step or probability-based termination fails to capture this.
- **Evidence anchors:**
  - [section 2.4.4]: Full specification of fatigue cost formula and "high-frequency"/"medium-frequency"/"low-frequency" action categorization.
  - [section 3.3.2]: "Agents with different activity levels exhibit distinct click distributions... mean number of clicks shifts from 3.2 (low) to 4.0 (medium) and 5.8 (high)." This shows the fatigue system successfully modulates overall session length (number of clicks), a key activity trait.
  - [section 3.4 (Case Study, Case 4)]: Agent exits due to a mismatch (old release year) compounded by "High fatigue (25.4/30)", demonstrating fatigue as a direct exit trigger.
- **Break condition:** If the fatigue system is removed or replaced with a fixed-step limit (e.g., exit after N actions), the distribution of session lengths (clicks per session) would become uniform or random, failing to reproduce the Gaussian-like shifts correlated with assigned activity levels. Agent behavior would become overly exploitative or show unnatural session persistence.

## Foundational Learning
- **Concept: Multimodal Information Perception**
  - *Why needed here:* The framework's core innovation is a UI that mirrors real platforms (posters, text metadata). An engineer must understand that the agent's decision-making is not just about text tokens but involves interpreting visual aesthetics (poster design, color) and textual semantics (genre, plot).
  - *Quick check question:* How does the agent's decision to click a movie on the homepage differ when it has access to only the poster vs. only the title+genre? What does this imply for simulator design?

- **Concept: LLM-as-Agent Prompting & State Representation**
  - *Why needed here:* The agent's "brain" is an LLM (GPT-4o, etc.) triggered with a structured prompt containing `{user_profile}`, `{user_preference}`, `{relevant_interaction_history}` (long-term memory retrieval), and `{in_session_history}` (short-term memory). An engineer must learn to craft prompts that elicit consistent, goal-directed behavior from a generative model within a constrained action space.
  - *Quick check question:* What are the risks of the LLM generating an action not in the allowed set (e.g., "I want to share this movie" instead of "click", "next page")? How does the framework enforce valid action selection?

- **Concept: Simulation Validation via Behavioral Alignment**
  - *Why needed here:* The paper does not claim perfect simulation but "alignment." The engineer must learn to validate a simulator not by matching exact click logs, but by checking if *relative model rankings* and *downstream utility* (data augmentation AUC gains) match real-world trends. Key metrics are CTR/CVR/AR *relative differences* between models, not absolute values.
  - *Quick check question:* If Agent-A reports a CTR of 0.45 for Model X and 0.40 for Model Y, and Agent-B reports 0.30 and 0.25 respectively, what is the critical validation criterion regarding real-world A/B test results for X vs. Y?

## Architecture Onboarding
- **Component map:**
  1.  **MM-ML-1M Dataset:** Enriched MovieLens with posters and full metadata (IMDb ratings, directors, etc.). Feeds the sandbox UI.
  2.  **Recommendation Sandbox Environment (UI):** Two-page interface (Homepage list, Detail page). Renders items from a recommendation model's output list (top-20). Exposes multimodal state (image tags, text fields) to the agent.
  3.  **A/B Agent (LLM-based):**
      - **Profile Module:** Static user attributes (age, gender) + dynamic preference summary (LLM-generated from history).
      - **Memory Module:** Long-term (cross-session history, retrieved via text/image similarity) + Short-term (current session log).
      - **Action Module:** Parses UI state + memory, prompts LLM for next action, executes valid action.
      - **Fatigue System:** Tracks and computes fatigue cost per action; triggers exit at zero.
  4.  **Interaction Data Pipeline:** Collects agent actions (clicks, views, ratings) and computes simulation metrics (CTR, CVR, AR) for evaluation.

- **Critical path:**
  1.  **Initialization:** Load a user's interaction history from ML-1M. Generate their static profile and LLM-summarized preference.
  2.  **Session Start:** Reset agent's short-term memory and fatigue. Fetch the top-20 recommendations from the target model (e.g., DeepFM) for this user.
  3.  **Step Loop:**
      a. Render the current UI page (Homepage: 5 items from the list; Detail Page: 1 full item).
      b. Agent retrieves relevant long-term memories (using current UI's text/visual features as query).
      c. Agent constructs prompt with: profile, preference, retrieved long-term memory, short-term session memory, current UI observation.
      d. LLM generates a natural language "thought" and an action token (`click`, `next_page`, `watch_and_rate`, `back`, `exit`).
      e. Framework parses action, updates short-term memory, computes and deducts fatigue.
      f. If action causes navigation, update UI state and loop.
  4.  **Termination:** Session ends when agent issues `exit` or fatigue reaches 0.
  5.  **Aggregation:** After N simulated users/sessions, aggregate actions to compute CTR (clicks/impressions), CVR (detail views/clicks), AR (average ratings given). Compare these *relative values* across models to real-world Recall/NDCG.

- **Design tradeoffs:**
  - **Fidelity vs. Cost:** High-fidelity multimodal UI and LLM reasoning are computationally expensive (API costs, latency). A minimal viable simulator might use a text-only UI and smaller LLM, but will lose visual modality benefits (see ablation).
  - **Generality vs. Domain Specificity:** The framework is built for movie recommendation (posters, metadata). Adapting to another domain (e.g., news, e-commerce) requires building a new sandbox UI with appropriate multimodal signals (article thumbnails, product images) and possibly adjusting the fatigue cost coefficients for domain-specific action frequencies.
  - **Exploration Control:** The fatigue system is a heuristic. Its parameters (`C_a`, `φ_max/min`, `ι_max/min`) are tuned on a small set (Table 8 shows different values for GPT-4o vs. mini). Poor tuning could make agents either too passive (high fatigue costs) or hyperactive (low costs), misrepresenting user engagement.

- **Failure signatures:**
  - **Metric Inversion:** Simulated CTR/CVR ordering contradicts known model strength from offline evaluation (e.g., Random > DeepFM). Indicates fundamental flaw in agent decision logic or environment rendering.
  - **No Variance / Repetitive Loops:** All agents exhibit identical click patterns or loop on `next_page`/`back` without meaningful engagement. Suggests prompt issues, LLM temperature too low, or missing fatigue constraints.
  - **High Exit Rate on First Page:** Most sessions end on homepage without clicks. Could indicate unrealistic fatigue settings, preference summaries that are too restrictive, or a mismatch between recommended items and agent preferences.
  - **Data Augmentation Degradation:** Adding agent-generated data *lowers* downstream model AUC. Signals that simulation distribution is far from real user distribution (e.g., agents only click "drama" while real users are diverse).

- **First 3 experiments:**
  1.  **Basic Model Ranking Replication:** Run the full simulation pipeline (100+ simulated users per model) for a known model pair (e.g., Pop vs. Random). Verify that the agent produces a statistically significant CTR/CVR gap in the expected direction. This validates the basic end-to-end mechanism.
  2.  **Visual Modality Ablation Test:** Re-run the simulation for a single model (e.g., DeepFM) with two UI conditions: full multimodal vs. text-only (hide poster). Measure the change in generated data's utility by training a small downstream model (e.g., FM) on the augmented data and comparing AUC. A significant drop confirms the visual modality's critical role per the paper.
  3.  **Fatigue System Sanity Check:** Run identical agent sessions with the fatigue system **disabled** (fixed session length of 20 steps) vs. **enabled**. Compare the distribution of total actions per session. Enabled fatigue should produce a right-skewed or Gaussian-like distribution; disabled should produce a sharp peak at the fixed limit. Also check if fatigue-enabled sessions show higher CTR on high-interest items (as per the cost formula).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can external influences like social media and peer interactions be effectively integrated into the A/B Agent framework to better reflect real-world user decision-making contexts?
- **Basis in paper:** [explicit] The Discussion section states: "our framework operates within a closed environment, overlooking external real-world influences like social media and peer interactions that shape user decisions."
- **Why unresolved:** The current sandbox environment is isolated, limiting its ability to simulate the full complexity of user behavior influenced by external factors, which could affect A/B testing validity.
- **What evidence would resolve it:** Incorporate social network data or external information streams (e.g., trending topics, friend recommendations) into the simulation; then compare agent-generated metrics (CTR, CVR, model rankings) against real-world A/B test results that include such external signals.

### Open Question 2
- **Question:** What specific techniques can mitigate hallucinations and repetitive behaviors in LLM-based agents to enhance simulation reliability and behavioral diversity for A/B testing?
- **Basis in paper:** [explicit] The Discussion acknowledges: "intrinsic LLM issues, such as hallucinations and repetitive behaviors, may compromise simulation reliability."
- **Why unresolved:** LLM flaws can cause agents to generate unrealistic or inconsistent actions, undermining confidence in agent-based A/B testing as a substitute for real user data.
- **What evidence would resolve it:** Implement and evaluate methods like fact-checking against item metadata, stochastic action sampling with diversity constraints, and memory-based novelty incentives. Measure reduction in hallucination rates (via manual/automated checks) and increased behavioral entropy compared to human interaction logs.

### Open Question 3
- **Question:** How sensitive are the agent's session dynamics and engagement patterns to the fatigue system's parameterization (e.g., base coefficients, interest-based modifiers), and do these parameters generalize across user segments with different activity traits?
- **Basis in paper:** [inferred] The fatigue model (Equation 1) uses heuristically set parameters (Table 8), but no sensitivity analysis or cross-user validation is provided.
- **Why unresolved:** The fatigue parameters directly control session length and exploration intensity; if not well-calibrated, the agent may misrepresent real user engagement distributions.
- **What evidence would resolve it:** Conduct systematic parameter sweeps; evaluate metrics like average session length, click distributions, and exit rates. Correlate these with real user session data segmented by activity level (low/medium/high) to identify parameter regimes that best match observed behavior.

### Open Question 4
- **Question:** Beyond static movie posters, what additional visual modalities (e.g., video thumbnails, dynamic UI elements, color schemes) prevalent on real recommendation platforms are critical for faithful user behavior simulation, and how should they be incorporated into the multimodal agent?
- **Basis in paper:** [inferred] Ablation studies (Section 3.5) show that removing poster images halves the performance gain, indicating visual importance. However, the framework only uses static posters, while real platforms employ richer visual cues.
- **Why unresolved:** Other visual aspects (e.g., thumbnail imagery, layout design) likely influence user attention and clicks but are not modeled, potentially limiting simulation fidelity.
- **What evidence would resolve it:** Extend the sandbox UI and dataset to include additional visual features (e.g., trailer previews, banner ads). Perform incremental ablations: add each visual type and measure changes in agent CTR/CVR and downstream AUC improvements. Validate against eye-tracking or click-through data from real users to identify most impactful visuals.

### Open Question 5
- **Question:** Does the agent's memory module adequately capture and adapt to long-term preference drift (i.e., evolving user tastes over time), and how does unmodeled drift impact the accuracy of long-horizon A/B testing simulations?
- **Basis in paper:** [inferred] The memory module retrieves past interactions to inform decisions but assumes preferences are stable; no experiments examine temporal preference shifts or their effects.
- **Why unresolved:** Real users' interests change; an agent that cannot model drift may simulate short-term interactions well but fail in evaluations requiring long-term preference consistency.
- **What evidence would resolve it:** Simulate controlled preference drift scenarios (e.g., gradual genre preference shifts across user histories). Analyze memory retrieval relevance over time and compare agent behavior (clicks, ratings) against ground-truth evolving preferences. Assess degradation in model ranking correlation (vs. real-world metrics) over extended simulation periods.

## Limitations
- **Dataset construction:** Exact IMDb fields, poster specifications, and entity resolution for MM-ML-1M are undocumented, risking dataset shift.
- **Fatigue parameters:** Base coefficients (φ_max/min, ι_max/min) and interest level computation are unspecified, critically affecting session length and engagement distributions.
- **Memory retrieval:** No details on retrieval size (top-k), similarity thresholds, or fusion of text/visual results, risking inconsistent long-term behavior.

## Confidence
- Multimodal perception criticality: **High confidence** (ablation shows 50% gain drop without visuals).
- Memory system stability: **Medium confidence** (case studies support, but retrieval details missing).
- Fatigue system modeling activity: **Medium confidence** (activity shifts documented, but parameters unvalidated).
- Downstream AUC gains: **Medium-Low confidence** (small effect sizes ~0.0036; sensitive to data augmentation design).

## Next Checks
1. **Replicate visual modality ablation:** Train a downstream model (e.g., DeepFM) on data generated with full multimodal UI vs. text-only UI. Confirm that the AUC improvement with full UI is at least double that with text-only (target: ΔAUC_full ≈ 0.0022, ΔAUC_text ≈ 0.0011).
2. **Fatigue parameter sensitivity sweep:** Vary key parameters (φ_max, φ_min, interest scaling) by ±20% and measure stability of agent CTR rankings (e.g., DeepFM > AFN) and session length distributions. Ensure no metric inversion occurs.
3. **Memory retrieval size ablation:** Ablate the long-term retrieval top-k (try k=1,3,5,10). Measure Kendall tau between agent CTR rankings and real Recall@20 rankings. Expect degradation when k is too small (<3) or too large (>10).
