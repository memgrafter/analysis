# SimMOF: AI agent for Automated MOF Simulations

## Quick Facts
- arXiv ID: 2603.29152
- Source URL: https://arxiv.org/abs/2603.29152
- Reference count: 40
- Primary result: SimMOF automates MOF simulations via an LLM-based multi-agent framework, achieving near-perfect workflow success rates, high quantitative accuracy (<3% error), and efficient high-throughput screening without sacrificing candidate quality.

## Executive Summary
SimMOF is an AI agent framework designed to automate the end-to-end pipeline of Metal-Organic Framework (MOF) computational simulations. It interprets natural language queries, plans dependency-aware computational workflows, generates valid input files, orchestrates simulation tools, and performs autonomous error recovery. By leveraging a multi-agent architecture with large language models, it eliminates the need for expert manual intervention. Evaluations show near-perfect success in creating executable workflows for common tasks (e.g., geometric analysis with Zeo++, adsorption with RASPA) and high accuracy in predicted properties. In high-throughput screening, it efficiently filters large compound databases while preserving top performers, demonstrating significant productivity gains.

## Method Summary
SimMOF employs a modular multi-agent system powered by GPT-5 via the OpenAI API, with no model fine-tuning. Behavior is controlled through prompt engineering and structured JSON outputs. Key agents include: a query agent for intent parsing, a working agent for generating directed acyclic graphs of jobs with dependency management, simulation agents for tool invocation (Zeo++, RASPA, LAMMPS, VASP), and an error agent for closed-loop validation and correction. Input generation uses a RAG agent to retrieve methodological parameters from a literature corpus and a structure agent to map MOF identifiers to external databases (CoRE MOF, CSD). The workflow progresses from natural language query through planning, parallel execution, error monitoring, and result synthesis, with RAG ensuring domain-specific grounding and the error agent enabling robustness.

## Key Results
- Near-perfect success rates (e.g., 100% for basic Zeo++ tasks, high for RASPA) in generating executable workflows from natural language queries.
- High quantitative accuracy, with most calculated properties deviating less than 3% from reference values for standard MOF-adsorbate systems.
- Efficient high-throughput screening: reduced a database of 3,786 MOF compounds to 1,000 candidates while retaining all top performers based on target properties.

## Why This Works (Mechanism)
- **Mechanism 1: Dependency-Aware Planning** – The working agent decomposes queries into a directed acyclic graph of jobs, enforcing sequential dependencies (e.g., geometry optimization before binding energy calculation) and parallelizing independent tasks based on encoded MOF simulation protocols. Reliability hinges on the LLM's procedural knowledge; failures occur for novel, non-standard workflows not represented in training data or the RAG corpus.
- **Mechanism 2: Knowledge-Grounded Input Generation** – The input agent uses RAG to access literature-derived parameters (force fields, cutoffs) and a structure agent resolves material identifiers to crystal files, ensuring chemical and computational validity. Success depends on retrieval of relevant, high-quality methodological snippets and accurate database mapping; failures arise from irrelevant retrievals or ambiguous identifiers.
- **Mechanism 3: Autonomous Error Recovery** – An error agent pre-validates inputs and post-inspects logs, recognizing common failure patterns (e.g., convergence errors, parameter mismatches) and applying deterministic corrections (e.g., tweaking inputs, switching solvers) for re-execution. Effectiveness relies on the LLM's ability to diagnose known issues; novel or complex failures without prescribed fixes lead to unrecoverable halts.

## Architecture Onboarding
- **Component map:** Task Management -> Query Agent, Working Agent, Response Agent; Simulation -> Zeo++ Agent, RASPA Agent, LAMMPS Agent, VASP Agent; Assistance -> RAG Agent, Structure Agent, Input Agent, Error Agent, Analysis Agent, Screening Agent.
- **Critical path:** Natural Language Query → Query Agent (intent parsing) → Working Agent (DAG planning) → Parallel execution: Structure Agent (DB lookup), Input Agent (file generation), Simulation Agents (tool runs) → Error Agent (validation/recovery loop) → [Analysis Agent if needed] → Response Agent (NL synthesis).
- **Design tradeoffs:** Modularity vs. LLM call overhead; generalization via GPT-5 vs. control via prompt engineering; autonomy vs. transparency via modification logging.
- **Failure signatures:** Plan-level: inconsistent DAG (e.g., cyclic dependencies); Input-level: syntactically invalid files caught pre-execution; Execution-level: tool failures with unrecognized log patterns.
- **First 3 experiments:**
  1. Simple geometric query ("Calculate largest cavity diameter of UiO-66") to validate end-to-end flow without error recovery.
  2. Underspecified query ("What is surface area of a MOF?") to test clarification handling by the Query Agent.
  3. Error injection with incompatible force field (e.g., CH4 parameters for CO2) to assess the Error Agent's detection and correction.

## Open Questions the Paper Calls Out
1. **Generalization to rare failures:** Performance may degrade for underrepresented protocols; paper suggests fine-tuning or expert knowledge integration but lacks systematic methodology for handling out-of-distribution tasks.
2. **MLIP impact on accuracy:** The role of machine-learned potentials in prescreening geometries for DFT is not isolated; deviations in binding energy could stem from MLIP ranking bias or sampling limits.
3. **RAG retrieval reliability:** No validation of whether retrieved literature snippets are contextually appropriate or aligned with best practices, risking propagation of outdated or inapplicable methods.
4. **Scaling to inverse design:** SimMOF executes predefined workflows reactively but lacks closed-loop capabilities for autonomous hypothesis generation and iterative optimization across simulation cycles.
5. **Error recovery boundaries:** Limits for handling cascading failures across interdependent tools are unclear; complex multi-step errors (e.g., invalid structure propagating through multiple jobs) are not stress-tested.

## Limitations
- RAG corpus specifics (composition, sources, preprocessing) are unspecified, undermining reproducibility of knowledge grounding.
- Screening agent heuristic thresholds (e.g., geometric filters, MLIP cutoffs) are opaque, limiting understanding of generalizability to other MOF chemistries.
- Error agent's diagnostic scope is bounded; its effectiveness for novel or complex failure modes beyond common pitfalls is unverified.

## Confidence
- Automated End-to-End Execution: High (supported by near-perfect success rates and detailed architecture)
- Quantitative Accuracy (<3% error): Medium-High (validated for common properties but tool/dataset specific)
- Efficient High-Throughput Screening: Medium (demonstrated on one database; robustness unproven)
- Robust Error Recovery: Low-Medium (based on internal studies; external validation on diverse failures lacking)

## Next Checks
