# EVA: Efficient Reinforcement Learning for End-to-End Video Agent
## Quick Facts
- arXiv ID: 2603.22918
- Source URL: https://arxiv.org/abs/2603.22918
- Reference count: 40
- Primary result: EVA outperforms general MLLMs by 6–12% and adaptive agents by 1–3% on six benchmarks, achieving high efficiency (e.g., 51.8% on LSDbench with only 6.2K visual tokens).

## Executive Summary
EVA redefines video understanding by enabling agents to *plan before perceiving*. It uses an iterative loop of summary, planning, action, and reflection to autonomously decide *what*, *when*, and *how* to watch, driven by a flexible `frame_select` tool that controls temporal span, frame count, and resolution. A three‑stage training pipeline (SFT cold‑start, KTO for failure avoidance, GRPO for RL) bridges imitation and online reinforcement learning. EVA reaches state‑of‑the‑art accuracy on long‑video benchmarks while using only ~20–30 frames and drastically fewer tokens than prior methods.

## Method Summary
The problem is cast as an active perception MDP: the initial state contains only the query, and actions are calls to `frame_select` with four continuous parameters. The agent generates interleaved reasoning (Summary, Planning, Action, Reflection) and iteratively refines its visual evidence before producing a final answer. Training starts with SFT on 10k synthetic trajectories to learn tool‑call formatting and basic selection patterns. KTO then refines the policy on 11k labeled success/failure trajectories, pruning obvious failure modes (e.g., guessing, inefficient sampling) before online RL. Finally, GRPO optimizes the policy with a composite reward (accuracy + format) and a KL penalty to a reference model, encouraging efficient strategies while avoiding reward hacking.

## Key Results
- LSDbench: 51.8% accuracy using only 6.2K visual tokens (+2.6% over baseline).
- Long‑video benchmarks: LongVideoBench 55.1%, MLVU 60.5%, VideoMME 59.9%, LVBench 38.1% with ~20–30 frames.
- Consistent gains: +6–12% over general MLLMs and +1–3% over adaptive agents across six benchmarks.

## Why This Works (Mechanism)
### Mechanism 1: Planning‑before‑perception iterative loop
The agent reasons on the query alone to generate a plan (temporal window, frame count, resolution), then executes a single tool call to acquire only the planned evidence, reflects on sufficiency, and repeats. This decouples reasoning from perception, avoiding distraction from irrelevant uniformly sampled frames and optimizing token usage. The core assumption is that a textual plan generated before visual input can effectively guide selective perception. Internal evidence includes the MDP formulation where the initial state contains only the query ([section 3.1]) and the claim that planning‑first avoids visual misguidance ([section 6.1]). The mechanism likely fails when the initial plan is fundamentally misaligned with the video’s content structure or when the tool’s parameter space cannot capture necessary details.

### Mechanism 2: Three‑stage training pipeline (SFT → KTO → GRPO)
1) **SFT cold‑start** provides a stable behavioral prior via 10k high‑quality synthetic trajectories, teaching tool‑call format and basic reasoning. 2) **KTO** uses labeled success/failure trajectories (without pairwise preferences) to correct recurrent failure patterns (e.g., guessing without evidence) before online RL, improving robustness and convergence. 3) **GRPO** performs online policy optimization with composite rewards (accuracy + format) and a KL penalty to the reference model, learning to balance reasoning depth and token efficiency across diverse rollouts. The assumption is that each stage addresses a specific bottleneck, and ablations show incremental gains: SFT alone performs poorly, KTO reduces token use and improves scores, and GRPO further reduces tokens while increasing accuracy ([section 4.3]). Potential failure occurs if any stage’s dataset is low quality or unrepresentative, or if catastrophic forgetting outweighs the KL regularization.

### Mechanism 3: Flexible frame‑selection tool
The tool exposes four parameters (`start_time`, `end_time`, `nframes`, `resize`), creating a large continuous action space. The agent learns policies that start with low‑resolution global scans (long temporal span, high `nframes`, low `resize`) to locate regions of interest, then perform high‑resolution zooms (short span, high `nframes`, high `resize`) on specific segments. This replaces prior rigid tools that only adjust time range. The core assumption is that fine‑grained control across temporal, quantity, and spatial dimensions is necessary for adaptive perception. Behavioral analysis shows EVA’s evolution: initial exploration with large `nframes` and long spans, followed by sharp reductions in `nframes` and time range while `resize` increases, indicating zooming ([section 6.3]). Efficiency gains are evident: EVA uses ~20–30 frames (∼6–20K tokens) to match or exceed baselines that use 256+ frames (∼50–700K tokens). The mechanism is bounded by hardware/video codec limits and may fail for queries requiring simultaneous inspection of multiple non‑contiguous high‑detail segments if multi‑window calls are unsupported.

## Foundational Learning
- **Markov Decision Process (MDP) formulation for active perception**  
  *Why needed:* The entire problem is an agent interacting with a video environment via tool calls, where state includes history and acquired evidence, and actions are tool parameters; understanding MDPs is prerequisite to grasp policy optimization (GRPO).  
  *Quick check:* Given state `s_t = {q, h_t, F_t}`, what constitutes a valid action `a_t`, and how does the reward signal depend on the trajectory `τ`?

- **Tool‑integrated Reinforcement Learning for LLM agents**  
  *Why needed:* EVA’s core innovation is an agent that *chooses* when and how to use a perception tool. The training stages (SFT → KTO → GRPO) are specific instantiations of this paradigm, requiring understanding of how offline demonstrations, preference learning, and online RL integrate.  
  *Quick check:* Why is KTO (a single‑preference method) preferred over DPO for the multi‑turn, variable‑length trajectories in this agent setup?

- **KL‑regularized Policy Optimization (GRPO)**  
  *Why needed:* GRPO is the final online RL algorithm. It prevents the policy from diverging too far from the reference model (SFT+KTO), which is crucial when the reward signal (ROUGE/CSV) is sparse and the action space is huge.  
  *Quick check:* In the objective `max E[R(τ)] – λ E[KL(π_θ||π_ref)]`, what is the likely effect of increasing the coefficient `λ` on exploration and final performance?

## Architecture Onboarding
**Component Map:**  
Base Model (Qwen2.5‑VL‑7B) → Tool Call Generator → `frame_select` tool → Frame Buffer → Reflection Module → GRPO update.  
Reward Modules: CSV judge (MCQ), ROUGE‑L (open‑ended), Format reward. Training Stages: SFT → KTO → GRPO.

**Critical Path:**  
1. Initialize from Qwen2.5‑VL‑7B.  
2. Train on EVA‑SFT (10k samples) to learn tool‑call format and basic reasoning patterns.  
3. Train on EVA‑KTO (11k chosen/rejected trajectories) to prune failure modes.  
4. Initialize GRPO with SFT+KTO model; for each batch generate 8 rollouts per sample, compute mixed rewards, apply GRPO update with KL penalty to reference model.  
5. Periodically collect failure rollouts, generate new QA via teacher MLLM (Data‑Enhanced GRPO), and merge into training set.

**Design Tradeoffs:**  
- Token efficiency vs. accuracy: Aggressive `resize` and low `nframes` save tokens but risk missing details; the policy must escalate only when needed.  
- Open‑ended vs. MCQ data in GRPO: Open‑ended prevents reward hacking via guessing but is noisier (ROUGE); MCQ is clean but easier to game. Mixed data (90% OE, 10% MCQ) balances this.  
- Tool simplicity vs. expressivity: The 4‑parameter tool is learnable but may be insufficient for queries needing multiple disjoint segments; adding multi‑window calls would increase action space complexity.

**Failure Signatures:**  
- Over‑exploration: Many rounds and high total tokens with stagnant accuracy.  
- Reward hacking: High training accuracy but poor generalization, often with minimal visual evidence.  
- Tool misuse: Invalid parameters (e.g., `nframes` > duration) or redundant calls without meaningful change.  
- Catastrophic forgetting: Post‑KTO/GRPO performance drops on SFT‑style simple queries.

**First 3 Experiments:**  
1. **SFT Sanity Check:** Verify the model generates valid `frame_select` JSON and basic summary/planning on 100 held‑out SFT samples; check for hallucinated parameters.  
2. **KTO Preference Validation:** After KTO, compare rejection rate on known failure trajectories; expect >80% of original failures now classified as “rejected”.  
3. **GRPO Data Mix Ablation:** Train three GRPO models for one step: (a) MCQ‑only, (b) OE‑only, (c) Mixed (90/10). Evaluate on VideoMME (mixed) and a held‑out MCQ set; expect the mixed model to win on both.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** How can we build more flexible tool ecosystems for video agents, allowing dynamic creation and use of new tools beyond frame selection?  
- **Basis in paper:** “Future work will explore more flexible tool ecosystems” (Conclusion).  
- **Why unresolved:** The current tool interface is fixed, preventing adaptation to new tasks or modalities.  
- **What evidence would resolve it:** Demonstrate an agent that can define, learn, and invoke novel tools (e.g., audio analysis) and evaluate on diverse video tasks to show improved coverage and performance.

### Open Question 2
**Question:** How can video agents develop self‑evolving reasoning strategies that adapt their planning and reflection loops from experience?  
- **Basis in paper:** “self‑evolving reasoning strategies” (Conclusion).  
- **Why unresolved:** The current reasoning loop is hand‑designed; automatic adaptation could yield better efficiency and generalization.  
- **What evidence would resolve it:** Implement a system where the agent modifies its reasoning policy (e.g., when to reflect) and show performance gains across tasks without human tuning.

### Open Question 3
**Question:** How can cross‑modal memory mechanisms be integrated into video agents to combine information from visual, audio, and textual streams over long durations?  
- **Basis in paper:** “cross‑modal memory mechanisms” (Conclusion).  
- **Why unresolved:** EVA processes only visual frames, ignoring other modalities that may contain crucial cues for understanding long videos.  
- **What evidence would resolve it:** Add a memory module that stores multimodal features and evaluate on benchmarks requiring audio‑visual‑text integration, measuring improved accuracy.

## Limitations
- **Generalization scope unclear:** Evaluation uses curated long‑video QA benchmarks; performance on unstructured, low‑quality, or multi‑narrative videos remains unknown.
- **Reward signal noise:** Open‑ended ROUGE‑L scores may not perfectly correlate with human judgment, risking misalignment in GRPO; the 10% MCQ mix only partially mitigates this.
- **Tool expressivity bottleneck:** The single‑window `frame_select` tool may fail queries requiring simultaneous comparison of disjoint scenes (e.g., compare outfit colors at 0:15 and 2:30).

## Confidence
- **Mechanism 1 (Planning‑before‑perception loop):** Medium  
- **Mechanism 2 (SFT → KTO → GRPO pipeline):** Medium  
- **Mechanism 3 (Flexible frame‑selection tool):** Medium‑High  

## Next Checks
1. **Adversarial multi‑window test:** Generate 50 QA pairs explicitly requiring evidence from ≥2 non‑contiguous temporal windows. Run EVA and measure failure rate due to inability to plan multi‑window calls in a single reflection cycle.
2. **Human plan‑video alignment eval:** For 100 LSDbench samples, extract EVA’s initial textual plan and have annotators judge (yes/no) whether the planned window contains necessary evidence. A <70% alignment rate would invalidate the core assumption that textual plans reliably guide perception.
3. **Training‑stage ablation with frozen components:** Train three models: (a) SFT + GRPO (no KTO), (b) KTO + GRPO (random init, no SFT), (c) full pipeline but with randomized KTO labels. Compare accuracy and token use on MLVU. If (a) or (b) match full EVA, the staged pipeline’s claimed synergy is overstated.
