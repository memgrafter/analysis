# Semantic Token Clustering for Efficient Uncertainty Quantification in Large Language Models
## Quick Facts
- **ArXiv ID**: 2603.20161
- **Source URL**: https://arxiv.org/abs/2603.20161
- **Reference count**: 20
- **Primary result**: STC achieves comparable AUROC (0.767–0.902) to state-of-the-art uncertainty quantification methods while reducing inference-time overhead by ~98%.

## Executive Summary
The paper introduces Semantic Token Clustering (STC), a novel method for uncertainty quantification in large language models (LLMs) that aggregates next-token probabilities over semantically consistent token clusters. Unlike existing methods that rely on repeated sampling or external models, STC operates with a single generation by precomputing token clusters offline via embedding similarity and then, during inference, augmenting them with prefix matching. Evaluated on multiple LLMs (Llama, Mistral, Qwen) and QA datasets (NQ, TQA, WQ), STC matches the AUROC performance of state-of-the-art baselines like CCP while cutting inference overhead by approximately 98%. The method requires no auxiliary models, runs efficiently on CPU, and demonstrates that both embedding clustering and prefix matching are essential for effective uncertainty estimation.

## Method Summary
STC consists of two phases: offline precomputation and online inference. In the precomputation phase, for a given model, token embeddings (concatenated input and output embeddings) are clustered using agglomerative clustering (cosine distance, k=16k). Stopwords and Arabic numerals are excluded. This yields a mapping from each token to a semantic cluster identifier. During inference, the model generates a response greedily. For each generated token \(y_i\) at step \(i\), the method retrieves the set \(T_{e_i}\) of tokens sharing the same cluster as \(y_i\) (embedding-based) and the set \(T_{p_i}\) of vocabulary tokens that are prefixes of the remaining generated string \(y_{i:}\) after normalization (prefix matching). The aggregated conditional probability \(\hat{p}_c(y_i \mid x, y_{<i})\) is the sum of the model's next-token probabilities over \(T_i = T_{e_i} \cup T_{p_i}\). The final uncertainty score is \(S(x,y) = 1 - \prod_{i} \hat{p}_c(y_i \mid x, y_{<i})\). This approach avoids repeated sampling and leverages only a single forward pass per token.

## Key Results
- STC achieves AUROC scores between **0.767 and 0.902** across three models (Llama, Mistral, Qwen) and three QA datasets, comparable to CCP and other baselines.
- Inference-time overhead is reduced by **approximately 98%** relative to state-of-the-art methods like CCP, with negligible added cost on CPU.
- Ablation studies confirm that **both embedding clustering and prefix matching** are complementary; removing either significantly degrades performance.

## Why This Works (Mechanism)
### Mechanism 1: Semantic Clustering Reduces Lexical Uncertainty
Grouping tokens into semantically coherent clusters (based on embedding similarity) and summing their probability mass captures the model’s confidence in a semantic concept rather than a specific lexical form. This mitigates false uncertainty arising from synonymous tokens (e.g., “TV” vs. “television”). The core assumption is that tokens with similar embeddings are semantically interchangeable in context. Evidence: [abstract], [section 4] formalizes the cluster aggregation; ablation in Table 2 shows benefit. Break condition: poor clustering due to polysemy or embedding noise can mislead.

### Mechanism 2: Prefix Matching Captures Surface-Form Consistency
Prefix matching adds tokens that are prefixes of the subsequent generated string (after normalization) to the cluster at each step. This ensures that the aggregated probability includes surface forms that match the realized output (e.g., “tele” when “television” follows), complementing embedding clustering which might miss such variations due to slight embedding differences. Evidence: [section 4] defines \(T_{p_i}\); Table 2 ablation shows performance drop without prefix matching. Break condition: if the generated form has no matching prefixes, prefix matching contributes nothing.

### Mechanism 3: Offline Clustering Enables Efficient Inference
By computing token clusters once offline, STC shifts all heavy computation (clustering over the entire vocabulary) out of the inference loop. At inference time, only lightweight prefix checks and probability lookups are needed, avoiding expensive repeated sampling or external models. This yields dramatic overhead reduction (≈98%) and allows efficient CPU execution. Evidence: [abstract] mentions offline clustering; Figure 3 and Tables 7–8 show timing. Break condition: if the model’s vocabulary or embeddings change (e.g., fine-tuning), clusters must be recomputed.

## Foundational Learning
- **Token probability distributions**: Understanding that LLMs output a probability distribution over the entire vocabulary at each decoding step is fundamental. STC manipulates these distributions by summing over clusters instead of using the single token’s probability. *Quick check*: If a model assigns 0.6 to “TV” and 0.3 to “television” but generates “TV”, why would the single-token probability (0.6) overestimate uncertainty? (It ignores that the model is also confident in “television”.)  
- **Semantic vs. lexical uncertainty**: Uncertainty should reflect the model’s confidence in the meaning, not the exact surface form. A model that is semantically confident but unsure about wording should have low uncertainty. *Quick check*: Why might a model generating “Lond.” (incomplete) have higher uncertainty than “London”, even if both intend the same entity?  
- **Computational cost vs. fidelity trade-off**: STC exchanges some potential accuracy (compared to multi-sample methods) for massive efficiency gains. *Quick check*: Why might generating five samples with temperature be computationally prohibitive for a real-time QA system, despite capturing more diversity?  

## Architecture Onboarding
**Component map**: Precomputation module (offline agglomerative clustering) -> Inference module (greedy generation + per-token cluster/prefix aggregation -> final score product).  

**Critical path**:  
1. Load precomputed token-to-cluster map.  
2. For each input, generate full response y greedily.  
3. For each token position i in y:  
   a. Retrieve cluster of y_i, get T_{e_i} (tokens in same cluster).  
   b. Compute T_{p_i} by normalizing y_{i:} and checking which vocabulary tokens are its prefixes.  
   c. Sum probabilities of tokens in T_i = T_{e_i} ∪ T_{p_i}.  
   d. Multiply running product by this aggregated probability.  
4. Output uncertainty score S = 1 - product.  

**Design tradeoffs**:  
- Cluster count (k=16k): larger k yields finer clusters but more memory.  
- Prefix normalization: case- and space-insensitive; could affect subword handling.  
- Aggregation: product of aggregated probabilities vs. alternative functions (e.g., sum) not explored.  

**Failure signatures**:  
- Ablation drop >0.01 AUROC when removing either embedding or prefix matching (Table 2) indicates poor cluster coherence or ineffective prefix heuristic.  
- Inference overhead >10 ms/token suggests inefficient prefix scanning (e.g., O(|V|) per step); a prefix trie could optimize.  
- Uncalibrated scores (low PRR in Table 6) may require post-hoc calibration.  

**First 3 experiments**:  
1. Validate clustering quality: inspect top clusters (like Table 3) for semantic coherence and stopword exclusion.  
2. Replicate main AUROC: run STC on 100 NQ samples with Llama-2-7B; expect AUROC ≥0.76.  
3. Measure CPU inference overhead: time per token for greedy generation vs. full STC; overhead should be <1% (e.g., <0.03 ms if greedy is 3 ms). If higher, profile prefix matching.

## Open Questions the Paper Calls Out
- **Closed-source applicability**: STC requires token logits and embeddings, which are unavailable in proprietary LLMs. How can the method be adapted for such models?  
- **Contextual embeddings**: Using static embeddings may cause polysemy noise; would contextualized embeddings improve robustness?  
- **Calibration**: STC uncertainty scores are not explicitly calibrated; can post-hoc calibration improve reliability for high-stakes decisions?  
- **Aggregation function**: The product of cluster probabilities is used without comparison; could alternative aggregations (e.g., min, learned) perform better?  

## Limitations
- Precomputed clusters are static and ignore contextual polysemy; they become stale after model updates or fine-tuning.  
- Evaluation limited to closed-book QA (NQ, TQA, WQ); transfer to open-ended tasks (dialogue, code generation) is untested.  
- Prefix matching normalization details (e.g., handling subwords, punctuation) are underspecified and may affect reproducibility.
