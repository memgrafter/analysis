# AutoSkill: Experience-Driven Lifelong Learning via Skill Self-Evolution
## Quick Facts
- arXiv ID: 2603.01145
- Source URL: https://arxiv.org/abs/2603.01145
- Reference count: 40
- Primary result: Extracted 1,858 versioned skills from WildChat-1M, demonstrating lifelong capability accumulation without model retraining.

## Executive Summary
AutoSkill addresses the problem of LLM agents failing to accumulate personalized capabilities across sessions. It is a training-free framework that extracts explicit, versioned skill artifacts from dialogue traces, manages them via retrieval-assisted merging, and dynamically injects relevant skills into future requests. Applied to the WildChat-1M dataset, AutoSkill extracted 1,858 diverse skills with iterative refinement (e.g., version 0.1.34), and case studies confirm practical reuse in counseling and professional rewriting.

## Method Summary
AutoSkill operates via two coupled loops. First, skill-enhanced response generation: a query rewriter optimizes the current query for retrieval; a hybrid retriever (dense + BM25) fetches relevant skills from a SkillBank; the response generator conditions on these skills. Second, skill evolution: an extractor analyzes recent user queries to propose new skill candidates; a judge compares each candidate with the nearest existing skill to decide addition, merging, or discarding; a merge module performs semantic union with version bumping if needed. All components are prompt-driven LLMs; no model parameters are updated.

## Key Results
- 1,858 skills extracted from WildChat-1M, covering programming, writing, and domain-specific tasks.
- Skills exhibit iterative refinement; e.g., `professional_text_rewrite` reached version 0.1.34.
- Case studies demonstrate editable `SKILL.md` artifacts that enable consistent reuse of user-specific workflows.

## Why This Works (Mechanism)
### Mechanism 1: Skill Extraction from User Queries
**Claim**: Stable user preferences and workflows are abstracted into explicit, reusable skill artifacts from dialogue history.
**Mechanism**: An extraction module analyzes a recent window of user queries using a prompt to identify durable, portable constraints or procedures, filtering out one-off requests and generalizing specifics into a structured skill format.
**Core assumption**: Reusable patterns are detectable in user queries and persist across interactions.
**Evidence**: From WildChat-1M, 1,858 skills extracted with versioning; extraction principles focus on recent rounds and portable rules.
**Break condition**: If queries are transient or lack recurring patterns, extraction yields no skills.

### Mechanism 2: Retrieval-Assisted Skill Management & Versioned Merging
**Claim**: The skill bank evolves through controlled, retrieval-informed decisions that prevent duplication and enable iterative refinement.
**Mechanism**: For a new candidate, the system retrieves the most similar existing skill; a judge compares them on capability axes; if merge is decided, a merge module performs semantic union, preserving identity and incrementing the version.
**Core assumption**: Skills representing the same capability should evolve as a single versioned artifact.
**Evidence**: Case study shows `professional_text_rewrite` at v0.1.34 and `psychological counselor` at v0.1.0, indicating different evolution rates.
**Break condition**: If retrieval fails to find a similar neighbor, the system adds, potentially causing fragmentation; poor judge prompts cause incorrect decisions.

### Mechanism 3: Hybrid Skill Retrieval & Context Injection
**Claim**: Relevant skills are dynamically selected and injected at inference time to adapt responses without retraining.
**Mechanism**: Query is rewritten into retrieval-optimized form; hybrid scorer combines dense and BM25 relevance; skills exceeding a threshold are rendered and injected into the chat prompt.
**Core assumption**: Combined semantic and lexical matching effectively surfaces skills matching implicit constraints.
**Evidence**: Skill metadata includes `triggers` and `tags` serving as lexical signals; high-frequency tags suggest effectiveness.
**Break condition**: Poor query rewriting leads to irrelevant retrieval; threshold misconfiguration causes noise or no injection.

## Foundational Learning
1. **Explicit vs. Implicit Knowledge Representation**
   - *Why needed*: AutoSkill externalizes learned behavior as inspectable `SKILL.md` artifacts, enabling oversight, editing, and portability, unlike latent memory or policy drift.
   - *Quick check*: What are two practical benefits of having editable skill files compared to a system that only improves via model self-reflection?
2. **Retrieval-Augmented Generation (RAG) for Behavioral Knowledge**
   - *Why needed*: AutoSkill applies RAG to procedural knowledge; understanding standard RAG is prerequisite to grasping hybrid skill retrieval.
   - *Quick check*: Why might pure dense retrieval fail for skills that specify strict output formats (e.g., "only output the rewritten text")?
3. **Version Control for Non-Code Artifacts**
   - *Why needed*: Skill versioning allows incremental refinement without duplication, borrowing from software engineering for prompt-based specs.
   - *Quick check*: If a user subtly changes a constraint (e.g., from "professional tone" to "casual tone with emojis"), how should the version number change and what should the merge process preserve/discard?

## Architecture Onboarding
- **Component map**:
  M_rw (query rewrite) -> Retriever (hybrid scoring with M_emb) -> SkillBank -> Render -> M_chat (response)
  Concurrent maintenance: M_ext -> M_judge -> M_merge -> SkillBank update

- **Critical path**:
  1. User sends query q_t and history h_t.
  2. M_rw produces rewritten query ~q_t.
  3. Retriever fetches top-K skills H_t from SkillBank using hybrid relevance.
  4. M_chat generates response r_t with injected skills C_t = Render(H_t).
  5. Background: M_ext proposes new skill z_t from recent user queries Q_u^t; M_judge compares z_t to nearest neighbor s*_t; M_merge updates SkillBank (add/merge/discard) with version bump if merged.

- **Design tradeoffs**:
  - Training-free vs. prompt quality: No model updates, but efficacy depends on prompt design for extraction, judging, merging.
  - Explicit skills vs. storage growth: Artifacts enable inspection but risk bloat; discard and merge logic are crucial filters.
  - Hybrid retrieval vs. complexity: Improves recall but adds tuning (λ, η) and latency.

- **Failure signatures**:
  - Skill explosion: Many low-confidence, overlapping skills (judge too permissive, discard weak).
  - Retrieval noise: Irrelevant skills injected (query rewriting poor, η too low, skill descriptions bad).
  - Version drift: Merged skill incoherent (merge prompt fails to reconcile conflicts).
  - Stagnation: No new skills added (extraction too conservative) or no merges (judge always adds).

- **First 3 experiments**:
  1. **Extraction Sanity Check**: Feed 10 conversations with known stable preferences; inspect extracted SKILL.md for correctness and generality.
  2. **Retrieval Precision Test**: For a known skill, craft queries that should/shouldn't trigger it; measure retrieval at varying η and λ; assess query rewriting impact.
  3. **Merge Simulation**: Create sequence of user feedback on a recurring task; run maintenance loop; check version bump and coherence of final skill.

## Open Questions the Paper Calls Out
1. **Conflict Resolution in Merging**: How does AutoSkill handle contradictory constraints when merging skills? The paper lacks explicit conflict resolution algorithms, risking inconsistent merged artifacts. Evidence: Systematic experiments introducing controlled contradictions to measure output consistency and user preference.
2. **Scalability Limits**: What are retrieval latency and maintenance overhead as skill count grows? No empirical analysis for large repositories. Evidence: Benchmarking retrieval times and maintenance duration across increasing skill counts.
3. **Cross-User/Domain Transfer**: To what extent can skills transfer across users or domains? Claims exist but no validation. Evidence: Apply SkillBank from one subset to another (e.g., English programming to Chinese writing) and measure performance.
4. **Exclusion of Model Responses**: Does restricting extraction to user queries limit skill richness? Model responses may encode preferences not evident in queries. Evidence: Ablation study comparing queries-only vs. queries+responses on skill diversity and downstream performance.

## Limitations
- Lack of automatic quantitative benchmarks; reliance on corpus stats and selective case studies may not generalize.
- Hyperparameter sensitivity (λ, η, K) unspecified; performance likely degrades with poor tuning.
- Implementation gaps in incremental indexing, embedding model choices, and module sharing hinder reproduction.
