# AMES: Approximate Multi-modal Enterprise Search via Late Interaction Retrieval

## Quick Facts
- **arXiv ID:** 2603.13537
- **Source URL:** https://arxiv.org/abs/2603.13537
- **Reference count:** 11
- **Primary result:** AMES achieves nDCG@10 of 62.5 on the ViDoRe V3 benchmark using the ColQwen3.0 backbone, competitive with the prior SOTA of 54.1.

## Executive Summary
AMES tackles the problem of fine-grained multimodal retrieval in enterprise search by enabling late-interaction scoring without specialized infrastructure. It introduces a two-stage pipeline: first, parallel token-level approximate nearest neighbor (ANN) search with per-document Top-M MaxSim approximation; second, an exact MaxSim re-ranking of a shortlist. Implemented natively in Apache Solr via parent/child indexing, AMES preserves standard enterprise features like metadata filtering and scalability. On the ViDoRe V3 benchmark, AMES reaches nDCG@10 = 62.5 with the ColQwen3.0 backbone, matching or exceeding prior state-of-the-art. The approach offers a practical path to deploy multimodal late-interaction models at scale.

## Method Summary
AMES indexes each retrievable unit (e.g., document page, image, video segment) as a parent document. Its fine-grained embeddings—text tokens, image patches, video frames—are stored as child documents in a shared vector space. At query time, the system encoder produces token-level embeddings for the query. For each query token, an ANN search (dot product) is run over child embeddings, optionally filtered by modality. The first-stage aggregator performs per-token max similarity over child hits, then sums the top-M values per parent for each modality. Modality-specific scores are normalized using median and median absolute deviation (MAD) and fused (default equal weighting) to produce a candidate ranking. The top-N parents are shortlisted. In the second stage, all child embeddings for these parents are fetched and a batched matrix multiplication computes the exact MaxSim score; parents are re-ranked accordingly. This design allows high-recall candidate generation with efficient vector search and high-precision re-ranking using accelerators.

## Key Results
- nDCG@10 of 62.5 on ViDoRe V3 (English Industrial subset) with ColQwen3.0, surpassing the reported SOTA of 54.1.
- Two-stage pipeline maintains compatibility with enterprise features such as metadata filtering and scales to large corpora via standard Solr deployment.
- Approach is model-agnostic: reported with multiple backbones and supports text, image, and video modalities.

## Why This Works (Mechanism)
### Mechanism 1: Two-Stage Approximate→Exact Retrieval
**Claim:** AMES attains competitive late-interaction ranking quality at scale by decoupling high-recall candidate generation from high-precision re-ranking.
**Mechanism:** Stage 1 conducts parallel token-level ANN searches over child embeddings, retrieving a limited set per token. For each candidate parent, the system takes the maximum similarity per query token, then sums the highest M values (Top-M aggregation) to form an approximate score. This efficiently narrows the corpus to a shortlist R(Q). Stage 2 then recomputes the exact MaxSim score by considering all child embeddings of every shortlisted parent, using batched operations on accelerators. The core assumption is that the approximate Top-M aggregation preserves sufficient recall of relevant parents, and the shortlist size N is small enough to make full MaxSim computation feasible. A break condition arises if Stage 1’s approximation poorly correlates with true MaxSim (e.g., due to overly aggressive top-K or M), causing relevant parents to be omitted irrecoverably.

### Mechanism 2: Parent/Child Indexing for Unified Multimodal Semantics
**Claim:** Storing token/patch/frame embeddings as child documents under shared parent units enables late-interaction scoring within a standard enterprise search engine without modality-specific retrieval logic.
**Mechanism:** Each retrievable unit becomes a parent document. Its fine-grained embeddings are separate child documents linked to the parent and stored in a shared embedding space. ANN search operates exclusively on children; the aggregation of per-token maxima and Top-M sum occurs client-side per parent, leveraging the parent/child grouping to efficiently retrieve all children of a shortlisted parent. The design assumes the parent/child relationship supports efficient child retrieval and that metadata can be stored at the parent level for final filtering. A break condition is when backend support for high fan-out child retrieval is lacking or grouping semantics are lossy, making Stage 2 slow or impossible.

### Mechanism 3: Modality-Aware Fusion via Robust Normalization
**Claim:** AMES fuses independently retrieved text and visual evidence through median/MAD normalization and weighted combination, aligning scales while preserving distinct contributions.
**Mechanism:** For multimodal corpora, Stage 1 conducts separate ANN retrievals per modality (using an embedding_source filter). This yields per-document scores A_text(d) and A_image(d) derived from Top-M aggregation. Each modality’s scores are normalized using median and median absolute deviation (MAD) to Z_text(d) and Z_image(d). The final candidate score is a weighted sum w_text·Z_text + w_image·Z_image, with equal weighting as default. The core assumption is that raw similarity distributions differ yet can be robustly aligned; equal weighting is a reasonable starting point. A break condition occurs if distributions are non-overlapping or MAD unstable, causing misalignment and potential dominance by one modality.

## Foundational Learning
### Concept: Multi-vector (late-interaction) retrieval
- **Why needed:** AMES relies on fine-grained token/patch-level matching (MaxSim) which outperforms single-vector similarity for localized content, avoiding alignment loss from vector compression.
- **Quick check:** What is the computational complexity difference between computing MaxSim (sum_i max_j (q_i · d_j)) and a single-vector dot-product (sum_i q_i · sum_j d_j / |D|) for a query with |Q| tokens and a document with |D| child embeddings?

### Concept: Approximate Nearest Neighbor (ANN) search
- **Why needed:** Stage 1 must efficiently search over millions of child embeddings; ANN provides a recall-speed trade-off essential for interactive query times.
- **Quick check:** How does increasing numCandidates in an ANN query affect Stage 1 recall and the workload of Stage 2?

### Concept: Parent/child document grouping in search engines
- **Why needed:** The architecture models fine-grained embeddings as children of a retrievable parent, enabling late-interaction scoring within an enterprise search engine that expects document-centric indexing.
- **Quick check:** In Solr’s parent/child model, where is the vector field indexed for ANN search, and how are child embeddings retrieved for a given parent during re-ranking?

## Architecture Onboarding
**Component map:** 
Embedding Encoder -> Indexing Pipeline -> Query Processor -> Stage 1 Aggregator -> Candidate Manager -> Stage 2 Re-ranker -> Filtering Engine

**Critical path:** A query is tokenized and embedded; parallel ANN calls over child documents retrieve initial hits. Client-side aggregation computes per-token max, top-M sum per parent, and applies modality normalization/fusion. The top-N parents become candidates. The system then fetches all child embeddings for these parents and performs batched matrix multiplication to compute exact MaxSim, yielding the final ranking.

**Design tradeoffs:**
- Index cardinality vs. expressiveness: One child per embedding explodes index size but preserves fine-grained matching.
- Stage 1 recall vs. Stage 2 cost: Larger candidate pool N improves recall but increases exact MaxSim workload.
- Top-M M value vs. noise: Smaller M reduces noise but risks dropping relevant low-scoring tokens.
- Accelerator reliance: Stage 2 re-ranking requires GPU/MPS; without it, latency may become prohibitive.

**Failure signatures:**
- Low nDCG@10: likely Stage 1 recall insufficient; check recall@N and increase top-K or numCandidates.
- High Stage 2 latency: candidate set N too large for accelerator memory; reduce N or optimize batch size.
- Metadata filter misapplication: ensure filters are applied at parent level for final results and at child level (e.g., embedding_source) during ANN.

**First 3 experiments:**
1. Measure Stage 1 recall by exhaustively computing true MaxSim on a sample and comparing to AMES’s shortlist; tune top-K/numCandidates to achieve >90% recall.
2. Perform modality fusion ablation: individually enable text or image only to evaluate the impact of equal weighting and MAD normalization.
3. Validate metadata filtering correctness by indexing documents with parent-level fields (project_id, doc_type) and verifying both Stage 1 ANN and final results respect the filters.

## Open Questions the Paper Calls Out
1. **Hyperparameter sensitivity:** How do Stage 1 parameters (Top-M, candidate pool size N, per-token top-K) systematically affect the recall-precision trade-off? The paper notes evaluation did not include systematic ablation.
2. **Systems performance:** What are the end-to-end latency, throughput, and memory consumption of the AMES Solr implementation at scale? The paper does not report a full systems analysis.
3. **Modality fusion generality:** Does the robust normalization + equal weighting strategy generalize to arbitrary modality combinations (e.g., text+video, image+audio) or is it tuned for text+image?
4. **Top-M aggregation impact on recall:** What is the effect of per-document Top-M on Stage 1 recall, especially for queries with many low-relevance tokens?
5. **Index cardinality effects:** How does the explosion of child documents affect Solr’s index size, update throughput, and filter performance in large deployments?

## Limitations
- Stage 1 recall is not quantified; the system may miss relevant parents if approximate parameters are too aggressive.
- No empirical scalability data: index cardinality, query latency, and throughput at large scale remain unevaluated.
- Hyperparameter choices (M=12, N=80, K=10) are presented without ablation; optimal operating points are unknown for different datasets.
- Modality fusion weights are fixed at 0.5/0.5; adaptivity to different modality pairs is not investigated.
- The impact of Top-M truncation on recall is not measured, leaving a gap in understanding the recall-precision trade-off.
