# Doctor-RAG: Failure-Aware Repair for Agentic Retrieval-Augmented Generation

## Quick Facts
- **arXiv ID:** 2604.00865  
- **Source URL:** https://arxiv.org/abs/2604.00865  
- **Reference count:** 40  
- **Primary result:** A diagnosis-and-repair framework that localizes errors via a coverage-gated taxonomy and reuses validated reasoning prefixes, improving answer accuracy by up to +25.8% EM and reducing token consumption by up to 26.8% versus full reruns.

## Executive Summary
Doctor-RAG tackles the inefficiency of failure correction in agentic retrieval-augmented generation (RAG) systems, which traditionally require full reruns when errors occur. It introduces a two-stage diagnosis-and-repair framework. The diagnosis phase classifies failures using a coverage-gated taxonomy, while the repair phase minimally intervenes by reusing validated reasoning prefixes and re-executing only the erroneous steps. Evaluated on three multi-hop QA benchmarks, the DR-RAG variant yields substantial gains: up to +25.8% exact match accuracy and up to 26.8% token reduction compared to rerun baselines, with consistent improvements across different backbone models.

## Method Summary
The method extends a standard agentic RAG pipeline with Diagnosis and Repair modules. During execution, the agent (a Retriever-Reasoner loop) produces a trace of retrieval actions and reasoning steps. If the final answer is flagged as incorrect (by an external verifier or ground truth), the Diagnosis module analyzes the trace and assigns a failure type from a predefined taxonomy that considers retrieval coverage (e.g., insufficient, irrelevant, or contradictory). The Repair module then identifies the longest prefix of the trace that led to correct intermediate states and resumes execution from that point, applying targeted corrections such as additional retrieval for uncovered entities. This selective re-execution avoids full recomputation, saving tokens and time.

## Key Results
- Answer accuracy improves by up to +25.8% exact match (EM) on multi-hop QA benchmarks.
- Token consumption is reduced by up to 26.8% compared to full rerun strategies.
- Gains hold across multiple backbone language models, indicating broad applicability.

## Why This Works (Mechanism)
Doctor-RAG achieves efficiency by localizing failures to specific reasoning steps rather than discarding the entire trajectory. The coverage-gated taxonomy ensures repairs address the root cause: if failure stems from missing information, only the retrieval for uncovered aspects is repeated; if reasoning is flawed, only those steps are re-generated. Reusing validated prefixes preserves correct intermediate work, dramatically cutting token waste. This precision yields higher accuracy (by correcting the actual error) and lower cost (by avoiding unnecessary work), outperforming naive reruns that recompute everything.

## Architecture Onboarding
**Component map:**  
Input -> Retriever -> Reasoner -> [Failure Detector] -> Diagnosis (Taxonomy Engine) -> Repair Scheduler -> (re-execute Reasoner from validated prefix) -> Answer.  
The system augments a base agentic RAG loop with Failure Detector, Diagnosis, and Repair modules.

**Critical path:**  
Normal: Retrieve → Reason iteratively → Answer.  
Repair: Detect failure → Diagnose error type → Identify validated prefix → Resume Reasoner from prefix with adjustments → Answer.

**Design tradeoffs:**  
- Reasoning step granularity: finer steps enable precise repair but increase trace overhead; coarser steps reduce tracking cost but may limit localization accuracy.  
- Coverage threshold: a high threshold reduces false re-retrievals but may miss subtle coverage gaps; low threshold increases recall but risks unnecessary retrieval.  
- Prefix length: longer prefixes maximize token savings but could embed earlier undetected errors if validation is imperfect.

**Failure signatures:**  
Incorrect final answer (when ground truth available), self-consistency check failure, contradictions in the trace, low confidence scores, or unmet coverage criteria (e.g., retrieved documents fail to cover all question entities).

**First experiments:**  
1. Baseline comparison: Run Doctor-RAG and full-rerun on a small multi-hop QA subset, measuring exact match accuracy and total tokens.  
2. Taxonomy validation: Human-annotate error types for 100 failure cases and compute agreement with the taxonomy's predictions.  
3. Ablation study: Disable coverage-gating and record changes in accuracy and token usage to quantify its impact.
