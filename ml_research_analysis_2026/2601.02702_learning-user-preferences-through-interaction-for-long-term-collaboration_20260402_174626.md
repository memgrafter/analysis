# Learning User Preferences Through Interaction for Long-Term Collaboration

## Quick Facts
- **arXiv ID**: 2601.02702  
- **Source URL**: https://arxiv.org/abs/2601.02702  
- **Reference count**: 40  
- **Primary result**: Memory-augmented agents improve task success by up to 4.6%, reduce user effort, and shorten conversations in long-term collaboration.

## Executive Summary
This paper addresses the challenge of enabling AI agents to learn and adhere to user preferences over extended, multi-session collaborations. It introduces MULTISESSIONCOLLAB, a benchmark featuring user simulators with distinct preferences that engage in problem-solving tasks across multiple sessions. The core innovation is a memory mechanism that persists and refines preference information via session-level reflections. Experiments with Llama-3.3-70B show that memory alone increases task success, reduces user effort, and shortens dialogues. Further, training the reflection module with reinforcement learning (GRPO) yields additional gains, as demonstrated on Qwen-2.5-7B. A human study with 19 participants corroborates these findings, showing fewer turns and higher satisfaction when agents possess memory. The work highlights the importance of long-term memory and reflective learning for effective human-agent collaboration.

## Method Summary
The paper introduces MULTISESSIONCOLLAB, a benchmark for long-term human-agent collaboration. It features user simulators with distinct preferences that interact with agents across multiple sessions on problem-solving tasks. The core method is a memory-augmented agent architecture where a memory component persists user preferences. After each session, a reflection module processes the interaction log to produce a concise preference update, which is then incorporated into memory. This allows the agent to accumulate personalized knowledge over time. The reflection module can be trained using reinforcement learning (GRPO) to optimize for user satisfaction rewards, leading to improved preference extraction. The method is evaluated with Llama-3.3-70B and Qwen-2.5-7B, showing benefits of memory and RL training.

## Key Results
- For Llama-3.3-70B, adding memory increased task success from 41.78% to 46.38% (+4.60%), reduced user effort from 2.98 to 1.96 (-1.02), and shortened conversations from 15.96 to 14.53 turns (-1.43).  
- For Qwen-2.5-7B, RL training of the reflection module (GRPO) boosted task success by 3.43% over the non-RL baseline.  
- In a human user study (N=19), agents with memory required fewer turns (e.g., by session 3: 4 vs 8 in mixed-domain, 6 vs 10 in coding) and achieved higher scores on preference adherence, retention, confidence, and satisfaction.

## Why This Works (Mechanism)
Memory enables the agent to retain user preferences across sessions, preventing the need for users to repeatedly state their likes and dislikes. Session-level reflections act as a processing step that distills raw interactions into concise, actionable preference updates, ensuring that memory remains relevant and uncluttered. This continuous loop of interaction, reflection, and memory update allows the agent to gradually build a personalized model of the user. Training the reflection module with GRPO further aligns it with user satisfaction by optimizing for rewards derived from user behavior, thereby improving the quality of the extracted preferences.

## Foundational Learning
- **Long-term preference learning**: *Why needed?* To adapt to users over multiple interactions rather than treating each session independently. *Quick check:* Does the agent's performance improve in later sessions compared to earlier ones?
- **Memory-augmented agents**: *Why needed?* To store and retrieve user-specific preferences across sessions, enabling continuity. *Quick check:* Is the memory consulted during response generation, and does disabling it degrade performance?
- **Session-level reflection**: *Why needed?* To summarize and extract relevant preference signals from noisy interaction logs, making memory updates efficient and focused. *Quick check:* Do reflection outputs correlate with explicit user feedback or satisfaction metrics?
- **Reinforcement learning from user feedback (GRPO)**: *Why needed?* To train the reflection policy without requiring labeled data, using reward signals derived from user behavior. *Quick check:* Does RL training lead to higher task success compared to a non-trained or rule-based reflection module?

## Architecture Onboarding
**Component map**: User Simulator -> Agent (Policy + Memory) -> Interaction Log -> Reflection Module -> Memory Update -> (next session) Agent.

**Critical path**: The agent processes user input by consulting memory and generating a response. After the session, the interaction log is fed to the reflection module, which produces a preference update. This update modifies the memory, which then influences the agent's behavior in subsequent sessions.

**Design tradeoffs**:
- *Memory size*: Larger memory retains more details but incurs higher retrieval cost and noise; smaller memory is efficient but may lose nuance.
- *Reflection depth*: Deeper reflection yields richer updates but increases computational overhead and risk of overfitting; shallow reflection is faster but may miss subtle signals.
- *RL training*: GRPO can optimize reflection quality but adds training complexity and potential instability; rule-based reflection avoids training overhead but may be less adaptive.

**Failure signatures**:
- Memory corruption or overwriting, leading to loss of learned preferences and performance drop.
- Reflection generating irrelevant or contradictory updates, detectable by inconsistency with user feedback.
- RL divergence or reward hacking, where the reflection module optimizes for reward without genuine user satisfaction improvement.

**First experiments**:
1. Evaluate agent performance across sessions with and without memory to isolate memory's effect.
2. Ablate the reflection module (e.g., replace with raw logging) to measure its contribution.
3. Compare GRPO-trained reflection against supervised or rule-based baselines to assess RL benefits and stability.

## Open Questions the Paper Calls Out
The provided summary does not explicitly list open questions from the authors. However, based on the limitations discussed in the paper, several important directions for future research emerge:
- Improving the fidelity of user simulators to better reflect real human preferences.
- Evaluating the approach across a broader range of language models and domains.
- Conducting larger-scale human studies with diverse participants to confirm generalizability.
These questions highlight the need for further validation and extension of the proposed framework.

## Limitations
- MULTISESSIONCOLLAB relies on user simulators with uncertain fidelity to real human preferences; results may not transfer to actual users.
- Reported improvements are modest (e.g., +4.6% success) and limited to two LLM families; performance may vary elsewhere.
- Human study included only 19 participants, limiting statistical power and demographic generalizability.

## Confidence
- **Memory improvements** (Claim 1): Medium  
- **RL training gains** (Claim 2): Low  
- **Human study validation** (Claim 3): Medium  

## Next Checks
1. Large-scale human replication: Recruit >100 diverse participants to validate memory benefits on turns, adherence, and satisfaction in mixed and coding sessions.
2. Cross-model assessment: Evaluate the memory-augmented agent on at least three additional LLMs (e.g., GPT-4, Claude-3, Mistral-7B) to test generalizability.
3. Ablation study: Compare full reflective memory against a simple finite-context window to isolate the effect of persistent reflections.
