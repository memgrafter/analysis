# Negative-Aware Diffusion Process for Temporal Knowledge Graph Extrapolation

## Quick Facts
- **arXiv ID**: 2602.08815
- **Source URL**: https://arxiv.org/abs/2602.08815
- **Reference count**: 33
- **Primary result**: Achieves state-of-the-art MRR 49.03% on ICEWS14, outperforming prior diffusion method DiffuTKG (47.58%).

## Executive Summary
Temporal Knowledge Graph (TKG) extrapolation aims to predict future facts from historical data. Existing diffusion-based approaches suffer from two key limitations: they condition solely on positive evidence during denoising and use cross-entropy ranking objectives that poorly calibrate denoised embeddings. This paper introduces NADEx, a negative-aware diffusion model that addresses these gaps. NADEx encodes subject-centric histories of entities, relations, and time intervals into sequential embeddings, perturbs the target object with Gaussian noise, and reconstructs it using a Transformer denoiser conditioned on the contextual history. A cosine-alignment regularizer leverages batch-wise negative prototypes to sharpen decision boundaries against implausible candidates. Experiments on four TKG benchmarks (ICEWS14, ICEWS18, ICEWS05-15, GDELT) show consistent state-of-the-art improvements, with robust performance even under limited training data.

## Method Summary
NADEx follows a diffusion-based framework for TKG extrapolation. For a given subject, the model constructs a sequence of historical facts (entity, relation, time) and encodes each into an embedding, producing a context sequence. The target object's embedding is corrupted by adding Gaussian noise according to a forward diffusion process. A Transformer-based denoiser takes the noisy object embedding and the context sequence as input, predicting the original clean object embedding. During training, the model optimizes a ranking loss (e.g., cross-entropy) together with a cosine-alignment regularizer. This regularizer uses negative prototypes derived from other objects in the batch to pull the predicted object embedding closer to the positive object and push it away from negatives in cosine space, thereby improving calibration and discriminative power.

## Key Results
- On ICEWS14: MRR 49.03%, Hit@10 70.55%, surpassing DiffuTKG (MRR 47.58%).
- Consistent gains on ICEWS18, ICEWS05-15, and GDELT.
- Maintains superior performance even when training data is limited.

## Why This Works (Mechanism)
The negative-aware diffusion process explicitly incorporates negative evidence through batch-wise prototypes, enabling the denoiser to learn to distinguish plausible objects from implausible ones. The cosine-alignment regularizer directly optimizes the geometry of the embedding space, aligning predictions with positives and separating them from negatives in cosine similarity, which yields well-calibrated ranking scores. The Transformer denoiser effectively aggregates the sequential historical context, capturing temporal dependencies and patterns essential for extrapolation. Together, these components close the two gaps in prior diffusion methods, leading to more accurate and robust TKG prediction.

## Foundational Learning
1. **Temporal Knowledge Graph (TKG)**
   - *Why needed*: Provides the structured, time-stamped data (subject, relation, object, timestamp) that the model extrapolates.
   - *Quick check*: Verify datasets consist of quadruples with explicit timestamps; ensure history extraction respects temporal ordering.

2. **Diffusion Models**
   - *Why needed*: Formulate the corruption and reconstruction of object embeddings as a forward noising process and reverse denoising, enabling generative-style prediction.
   - *Quick check*: Confirm the presence of a forward noise schedule (e.g., Gaussian noise addition with increasing variance) and a learned denoising network.

3. **Transformer Architecture**
   - *Why needed*: Processes the sequence of historical embeddings with self-attention, capturing long-range dependencies and temporal patterns.
   - *Quick check*: Inspect the denoiser for multi-head attention layers and positional encoding; ensure it conditions on the entire context sequence.

4. **Batch-wise Negative Prototypes**
   - *Why needed*: Generate implicit negative examples from the current batch to define a discriminative decision boundary without explicit negative sampling.
   - *Quick check*: Verify that negative prototypes are computed as aggregated embeddings (e.g., mean or max) of non-target objects in the batch.

5. **Cosine-Alignment Regularizer**
   - *Why needed*: Aligns predicted object embeddings with positives and separates them from negatives in cosine space, improving ranking calibration.
   - *Quick check*: Check the loss function for a term that computes cosine similarity between predictions and positive/negative prototypes and applies a contrastive objective.

## Architecture Onboarding
**Component map**:
History Encoder -> Context Sequence; Target Object -> Noisy Object (via forward diffusion); Context Sequence + Noisy Object -> Transformer Denoiser -> Reconstructed Object; Reconstructed Object + Batch Negative Prototypes -> Cosine-Alignment Regularizer; Combined with Ranking Loss -> Total Loss.

**Critical path**:
During training: (1) Sample a fact (subject, relation, object, time); (2) Retrieve subject's historical facts; (3) Encode history into a sequence; (4) Sample noise level, add Gaussian noise to object embedding; (5) Input noisy embedding and context sequence to Transformer denoiser; (6) Compute denoised object embedding; (7) Compute ranking scores vs. all objects; (8) Generate batch negative prototypes; (9) Apply cosine-alignment regularizer; (10) Backpropagate total loss.

**Design tradeoffs**:
- Batch size: Larger batches produce more diverse negative prototypes but increase memory usage; very small batches may yield noisy prototypes and hurt discrimination.
- Diffusion steps: More steps increase modeling flexibility but slow training and inference; the variance schedule must balance noising and denoising difficulty.
- Transformer depth: Deeper models can capture complex temporal patterns but risk overfitting on limited TKGs and incur higher computational cost.
- History length: Longer histories provide richer context but increase sequence length, affecting Transformer efficiency; truncation may lose distant but relevant events.

**Failure signatures**:
- Significant performance drop when batch size is reduced, indicating reliance on batch negatives.
- Degradation after excessive diffusion steps (e.g., >1000), suggesting denoiser struggles to recover fine details.
- Poor calibration (e.g., low MRR but similar Hit@1) if cosine regularizer weight is too low; conversely, over-regularization may cause underfitting.
- Sensitivity to the noise schedule; an improperly tuned variance schedule leads to unstable training or poor convergence.

**First experiments**:
1. **Baseline replication**: Train NADEx on ICEWS14 with official hyperparameters, evaluate MRR and Hit@10, and compare to reported values.
2. **Ablation study**: Remove the cosine-alignment regularizer and replace the Transformer denoiser with a single-layer MLP (ignoring sequence) to quantify each component's contribution.
3. **Batch size sensitivity**: Train with batch sizes {64, 256, 1024} on a subset of ICEWS14, measure MRR and training time, and observe correlation between batch size and performance.
