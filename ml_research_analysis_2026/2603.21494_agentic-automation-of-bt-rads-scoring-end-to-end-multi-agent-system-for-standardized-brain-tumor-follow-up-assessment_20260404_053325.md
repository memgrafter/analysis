# Agentic Automation of BT-RADS Scoring: End-to-End Multi-Agent System for Standardized Brain Tumor Follow-up Assessment

## Quick Facts
- arXiv ID: 2603.21494
- Source URL: https://arxiv.org/abs/2603.21494
- Reference count: 40
- Primary result: System achieved 76.0% accuracy vs 57.5% for initial clinical assessments (+18.5 percentage points, P<.001) on 492 consecutive exams.

## Executive Summary
This paper presents an end-to-end multi-agent system to automate BT-RADS scoring for post-treatment glioma MRI. The system combines a CNN-based tumor segmentation module, an LLM extractor that retrieves relevant clinical variables (steroid status, bevacizumab status, radiation completion date) from unstructured notes, and a deterministic scorer that applies the BT-RADS decision logic. In a retrospective evaluation of 492 consecutive exams, the system achieved 76.0% accuracy compared to 57.5% for initial clinical assessments (P<.001), demonstrating significant improvement. The extractor agent achieved high accuracy (87.8–97.2%) in identifying clinical variables. The system showed particularly high sensitivity for context-dependent categories (e.g., BT-1b 100%, BT-1a 92.7%) and strong positive predictive value for BT-4 (92.9%), suggesting clinical utility as a decision support tool.

## Method Summary
The pipeline begins with MRI preprocessing using a pre-trained nnU-Net CNN to segment four compartments (enhancing tumor, non-enhancing tumor, edema, cavity). Volume changes for FLAIR and enhancement are computed relative to a baseline scan. An LLM-based extractor agent (20B parameter, schema-constrained with Pydantic) processes the associated clinical note to output structured values for steroid status, bevacizumab status, and radiation date, each with an evidence span for verification. A scorer agent implements the BT-RADS flowchart as a deterministic rule engine, consuming the volumetric percentages and extracted variables to produce a final BT-RADS category. An orchestrator coordinates these components, handling errors and data flow. The system was validated against a neuroradiologist's reference standard on 492 consecutive follow-up exams, with initial clinical BT-RADS scores from radiology reports used as a comparator.

## Key Results
- Overall accuracy: 76.0% vs 57.5% for initial clinical assessments (P<.001)
- High sensitivity for context-dependent categories: BT-1b 100%, BT-1a 92.7%, BT-3a 87.5%
- Extractor agent accuracy: 87.8–97.2% for clinical variables; BT-4 positive predictive value: 92.9%

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Automated extraction of structured clinical variables (steroid status, bevacizumab status, radiation date) from unstructured radiology notes enables systematic integration of context that is often missed or inconsistently applied in manual scoring.
- **Mechanism:** An LLM-based extractor agent processes clinical notes using schema-constrained generation (via Pydantic) to output categorical values with linked evidence spans. This transforms free-text into discrete, programmatically usable inputs for the decision logic.
- **Core assumption:** The relevant clinical context for BT-RADS scoring is reliably documented in the associated clinical notes, even if not in a structured format.
- **Evidence anchors:**
  - [abstract] "extractor agent identified clinical variables... from unstructured clinical notes"
  - [section 2.3] "Schema-constrained generation with Pydantic validation ensures outputs conform to predefined categorical formats... Each extraction includes an evidence span"
  - [section 3.5] Extractor accuracy: 87.8–97.2%
- **Break condition:** If critical medication timing or radiation completion details are absent from the notes, the extraction will fail or be incorrect, propagating error to the final score.

### Mechanism 2
- **Claim:** Deterministic algorithmic application of BT-RADS decision logic, integrating volumetrics and extracted context, standardizes scoring and eliminates common human error modes (e.g., incorrect window application, missed medication effects).
- **Mechanism:** The scorer agent implements the published BT-RADS flowchart as sequential rules. It takes volumetric percentage changes (from CNN segmentation) and the extracted categorical variables, then routes the case through logic trees (e.g., bevacizumab effect overrides volumetric thresholds for certain categories).
- **Core assumption:** The published BT-RADS flowchart is a complete and correct representation of the scoring rules for all cases.
- **Evidence anchors:**
  - [abstract] "scorer agent applying algorithmic BT-RADS logic"
  - [section 2.3] "scorer agent implements BT-RADS decision logic through sequential rule application (Figure 2)"
  - [section 3.7] Analysis of initial clinical errors: "27/492 (5.5%) failed to identify medication effects... 13/492 (2.6%) failed to correctly apply post-radiation window criteria"
- **Break condition:** Cases where the BT-RADS rules are inherently ambiguous or contradictory (evidenced by the 3 non-standard expert annotations) cannot be resolved deterministically.

## Foundational Learning
- **Concept: BT-RADS Scoring Logic**
  - **Why needed here:** The entire system's value is in faithfully implementing a complex, multi-factor clinical scoring rule. Understanding the decision tree (Figure 2), especially how medications (steroids, bevacizumab) and radiation timing modify volumetric interpretation, is non-negotiable for debugging or extending the system.
  - **Quick check question:** "For a case with stable volumes (±20%) but active bevacizumab, what BT-RADS category is assigned, and why?"

- **Concept: Multi-Agent LLM Orchestration**
  - **Why needed here:** The system's architecture separates concerns: extraction (LLM agent), rule application (scorer agent), and coordination (orchestrator). Misunderstanding the handoff points (e.g., what format the extractor's output has) will break integration.
  - **Quick check question:** "What are the three core agent types in this system, and what is the primary output of each?"

- **Concept: Volumetric Threshold Ambiguity**
  - **Why needed here:** The largest error source (44.1%) is cases near the ±20% stability or 40% worsening thresholds. This isn't a 'bug' but a feature of discretizing continuous data. An engineer must understand that small segmentation variance can flip categories here, and that accuracy metrics will inherently plateau below 100%.
  - **Quick check question:** "If an enhancement volume change is calculated as +38% by the CNN but +42% by expert manual segmentation, what is the likely impact on the final BT-RADS category?"

## Architecture Onboarding
- **Component map:**
  - **Input:** DICOM MRI series + associated clinical notes (unstructured text).
  - **Segmentation Module:** nnU-Net CNN → 4 compartment masks (enhancing, non-enhancing, edema, cavity) → total FLAIR & enhancement volumes → % change from baseline.
  - **Extractor Agent:** 20B parameter LLM (GPT-oss) → clinical note → structured dict {steroid_status, bevacizumab_status, radiation_date} + evidence_spans. Schema enforced via Pydantic.
  - **Scorer Agent:** Rule engine implementing Figure 2 flowchart → integrates volumetrics + extracted dict → final BT-RADS category (BT-0 to BT-4 with subcategories).
  - **Orchestrator:** Coordinates pipeline execution, handles data flow, manages failures (e.g., segmentation error, extraction confidence).
  - **Output:** Final BT-RADS score, all extracted variables with evidence, volumetric measurements.

- **Critical path:** Clinical notes → Extractor Agent → (steroid, bevacizumab, radiation date) + evidence → Scorer Agent + (FLAIR %Δ, Enhance %Δ) → BT-RADS category. Segmentation runs in parallel before scorer invocation.

- **Design tradeoffs:**
  - **Local vs. Cloud LLM:** Paper uses local open-weight (20B) for privacy/cost. Tradeoff: lower accuracy/capability vs. stateful cloud APIs (GPT-4). Extraction accuracy (87-97%) suggests local 20B is sufficient for this constrained schema task.
  - **Schema Rigidity:** Pydantic validation prevents malformed outputs but cannot handle novel phrasings not in training distribution. Too rigid = failures; too loose = garbage outputs.
  - **Volumetric Aggregation:** Using total volumes simplifies logic but misses "new enhancing lesion" rule nuance (BT-4 criterion). A lesion-wise analysis add-on could improve BT-4 sensitivity.

- **Failure signatures:**
  - **Extraction failure:** Pydantic validation error → fallback to "none"/"unknown"? System likely aborts or uses conservative defaults.
  - **Threshold boundary flips:** Confusion matrix shows misclassifications clustered between adjacent categories (BT-2/BT-3c, BT-3c/BT-4). Look for %Δ values near ±20% or 40%.
  - **Algorithm limitation:** High BT-3b error (57.1% sensitive). Indicates rule for discordant volume trends (FLAIR↑, Enhance↓ or vice versa) does not match expert intuition.
  - **Segmentation quality:** 8/509 excluded for quality. Over/under-segmentation shifts %Δ, causing misclassification at thresholds.

- **First 3 experiments:**
  1. **Extraction Sanity Check:** Run extractor on 50 curated notes with gold-standard variable labels. Measure per-variable accuracy and identify common error patterns (e.g., misreading "discontinued steroids" as "active").
  2. **Threshold Stress Test:** Isolate all cases where either FLAIR or enhance %Δ falls within ±5% of a critical threshold (±20%, 40%). Re-run scorer with ±1% perturbations to simulate segmentation noise. Quantify how often category flips.
  3. **Head-to-Head with Initial Clinical Assessments:** Replicate the paper's primary analysis on a held-out set (if available) or a temporal split. Confirm the 18.5 pp accuracy gain and the asymmetric discordance pattern (system correct / clinician wrong > vice versa).

## Limitations
- Unknowns block faithful reproduction: proprietary segmentation model details, exact LLM configuration and prompt, and baseline scan selection algorithm.
- Single-expert reference standard and retrospective study design.
- Potential overfitting to one institution's note style and inherent ambiguity in BT-RADS rules for edge cases (e.g., BT-3b).

## Confidence
- Accuracy improvement (+18.5 pp): Medium
- Extractor agent performance (87.8–97.2%): Medium
- Deterministic rule standardization: High (consistent application), Medium (completeness)

## Next Checks
1. Extractor generalization test: Run the extractor agent on a temporally hold-out set or external institution’s notes. Measure per-variable accuracy and failure modes (e.g., temporal reasoning for radiation completion).
2. Threshold robustness audit: For all cases with volume changes within ±5% of critical thresholds (±20%, +40%), re-run scorer with ±1% simulated segmentation noise. Quantify category flip rate and identify most sensitive thresholds.
3. Blinded head-to-head replication: Conduct a prospective or multi-center validation comparing system output to expert panel consensus (vs. single expert). Include initial clinical assessments as a third arm to confirm the magnitude of improvement.
