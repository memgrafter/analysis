# Closing Reasoning Gaps in Clinical Agents with Differential Reasoning Learning

## Quick Facts
- arXiv ID: 2602.09945
- Source URL: https://arxiv.org/abs/2602.09945
- Reference count: 40
- Primary result: DRL with Qwen3-8B achieves 81.28±0.47 accuracy on RVA-QA vs 56.97±0.57 base model (+24.31 points).

## Executive Summary
Clinical decision support agents must provide not only correct answers but also transparent, logically sound reasoning. Differential Reasoning Learning (DRL) introduces a systematic method to identify and repair reasoning gaps by representing reasoning as directed acyclic graphs (DAGs), comparing them against trusted references, and converting discrepancies into natural-language instructions that are retrieved at test time. This approach avoids model retraining and adapts the agent’s behavior in-context.

Evaluations on medical QA benchmarks (MedQA, MedMCQA) and an internal Return Visit Admission (RVA) prediction task show substantial gains. On RVA-QA, DRL with Qwen3-8B achieves 81.28±0.47 accuracy compared to 56.97±0.57 for the base model—a 24-point improvement. Smaller but consistent improvements appear on public benchmarks. Clinician review confirms that DRL-corrected reasoning aligns better with expert judgment, demonstrating enhanced reasoning fidelity alongside accuracy. Ablations highlight the importance of high-quality physician-authored rationales and an effective top-k retrieval strategy.

## Method Summary
DRL constructs a Differential Reasoning Knowledge Base (DR-KB) from training data. First, it extracts typed DAGs from reference rationales (e.g., physician notes) and the agent’s chain-of-thought using an LLM prompt. Next, it computes a clinically weighted graph edit distance (GED) between the two graphs, employing an LLM-as-a-judge to match nodes semantically and identify discrepancies such as missing facts, hallucinations, or incorrect inferences. These discrepancies are transformed into natural-language instructions and stored in the DR-KB. At inference, for a test question, the system retrieves the top-k most relevant instructions via BM25 and appends them to the agent’s prompt. The agent then generates an answer (multiple-choice) with the guidance, without any parameter updates. The agent model (e.g., Qwen3-8B or LLaMA-3.1-8B-Instruct) and the graph extraction/GED module (e.g., Gemini-2.5-Flash) are distinct; the pipeline is dataset-agnostic and was evaluated on MedQA, MedMCQA (filtered to sepsis/chest pain/stroke), and a proprietary RVA-QA dataset.

## Key Results
- On RVA-QA, DRL with Qwen3-8B achieves 81.28±0.47 accuracy vs 56.97±0.57 for the base model (+24.31 points).
- Modest but consistent improvements are observed on MedQA and MedMCQA.
- Clinician review indicates DRL-corrected reasoning better aligns with clinical judgment, improving reasoning fidelity alongside answer accuracy.

## Why This Works (Mechanism)
DRL works by turning systematic error diagnosis into actionable, in-context corrections. The key insight is that reasoning can be captured as a structured graph (DAG) where nodes represent facts, hypotheses, and actions, and edges encode logical relationships. Comparing the agent’s reasoning graph to a trusted reference via graph edit distance (GED) pinpoints exactly where the agent deviates—e.g., missed evidence, spurious claims, or flawed inference steps. Using an LLM as a judge allows semantic matching of nodes despite surface-level differences, and a clinical weighting emphasizes medically critical elements. Each discrepancy is distilled into a natural-language instruction that explicitly states the problem and the intended correction. Storing these instructions in a searchable knowledge base (DR-KB) enables retrieval of relevant patches for new questions, guiding the agent without retraining. The dramatic improvement on RVA-QA (where high-quality physician rationales are available) shows that accurate references yield high-value patches; more modest gains on public benchmarks (with LLM-generated rationales) suggest that patch quality is bounded by reference fidelity. In sum, DRL improves reasoning fidelity by continuously learning from past reasoning errors and applying targeted fixes at inference time.

## Foundational Learning
- **Reasoning Graphs (DAGs)**:
  - *Why needed*: Provide a structured, comparable representation of an agent’s reasoning steps (facts, hypotheses, actions) that reveals logical gaps more precisely than free-form text.
  - *Quick check*: Verify that all nodes have explicit types (fact/hypothesis/action) and that edges form a directed acyclic graph (no cycles).
- **Graph Edit Distance (GED)**:
  - *Why needed*: Quantifies the structural differences between two reasoning graphs, allowing identification of specific node/edge insertions, deletions, or substitutions that constitute reasoning gaps.
  - *Quick check*: Ensure node and edge weights reflect clinical importance (e.g., factual errors weighted higher than stylistic differences).
- **LLM-as-a-Judge**:
  - *Why needed*: Performs semantic matching of graph nodes (e.g., “myocardial infarction” vs “heart attack”) to overcome lexical variability and accurately compute GED.
  - *Quick check*: Sample matched node pairs and confirm semantic equivalence with human annotation; measure agreement.
- **BM25 Retrieval**:
  - *Why needed*: Efficiently selects the most relevant instructions from the DR-KB given a new question, enabling in-context adaptation.
  - *Quick check*: Tune BM25 parameters (k1, b) on a held-out set to maximize retrieval precision; monitor for overly generic or irrelevant top-k results.
- **Differential Reasoning Knowledge Base (DR-KB)**:
  - *Why needed*: Accumulates corrective instructions over time, turning individual error diagnoses into reusable knowledge that improves future reasoning without retraining.
  - *Quick check*: Periodically deduplicate and cluster instructions to maintain diversity and prevent redundancy from bloating the KB.
- **In-context Learning**:
  - *Why needed*: Injecting retrieved instructions into the prompt steers the agent away from known reasoning pitfalls on a per-question basis.
  - *Quick check*: Ensure the combined prompt (question + instructions) stays within the model’s context window; prune or reorder instructions if necessary.

## Architecture Onboarding
**Component Map**:

Training Phase:
[Reference Rationale] --> (Graph Extraction LLM) --> [Ref Graph]
[Agent CoT on training samples] --> (Graph Extraction LLM) --> [Agent Graph]
[Ref Graph, Agent Graph] --> (GED Analysis with LLM-as-judge) --> [Discrepancy Report]
[Discrepancy Report] --> (Instruction Generator) --> [Instruction] --> (Store) --> [DR-KB]

Inference Phase:
[Test Question] --> (BM25 Retrieval) --> [Top-k Instructions] --> (Prompt Construction) --> [Agent Model] --> [Answer]

**Critical Path**: The system relies on the prior construction of a high-quality DR-KB; without it, retrieval cannot occur. The critical path includes: (1) producing accurate reference and agent graphs, (2) computing meaningful GED discrepancies, (3) generating clear instructions, (4) retrieving the most relevant instructions for a new query, and (5) generating the final answer under guidance.

**Design Tradeoffs**:
- LLM-based extraction/GED offers flexibility but introduces variability and cost; rule-based alternatives would be more predictable but less adaptable.
- Lexical BM25 is lightweight and interpretable but may miss semantically similar but lexically divergent instructions; dense retrieval could improve relevance at the expense of compute and embedding maintenance.
- Storing many fine-grained instructions increases coverage but risks context overflow and noise; coarse instructions reduce noise but may lack specificity.
- Larger top-k values provide more diverse guidance but increase the chance of including irrelevant patches; smaller k limits context but may miss critical corrections.
- Physician-authored rationales yield higher-quality references but are expensive to obtain; LLM-generated rationales scale but may contain inaccuracies that propagate into instructions.

**Failure Signatures**:
- Incomplete or erroneous graph extraction (e.g., missing key nodes) leading to invalid discrepancy reports.
- LLM-as-judge mismatches: either failing to recognize semantically equivalent nodes or incorrectly matching non-equivalent ones, which produces flawed instructions.
- BM25 retrieving off-topic instructions that confuse the agent and degrade accuracy.
- Overly generic instructions that do not address the specific reasoning gap, rendering the patch ineffective.
- DR-KB contamination: duplicate or contradictory instructions that cause conflicting guidance.
- Prompt length exceeding the agent’s context window when many instructions are retrieved, causing truncation or errors.

**First Experiments**:
1. Validate graph extraction quality on a manually annotated sample: compare automatically extracted DAGs to ground-truth graphs for nodes/edges; report precision/recall.
2. Measure consistency of the LLM-as-judge: run the GED step multiple times on the same graph pair and compute agreement on node matches and discrepancy types; also compare with clinician judgments on a subset.
3. Evaluate retrieval and impact: on a held-out test set, vary BM25 top-k (1,3,5,10); measure retrieval precision (instructions relevant to the query) and final agent accuracy; identify the k that balances relevance and context constraints.

## Open Questions the Paper Calls Out
1. **Mitigating errors in LLM-based extraction and matching**: The pipeline’s reliance on LLMs for graph extraction and semantic node matching introduces noise; the paper calls for stronger schema validation and uncertainty-aware discrepancy scoring to filter low-quality patches.
2. **Scaling the DR-KB**: As the knowledge base grows, questions remain about retrieval efficiency, instruction overlap, and diminishing returns; evaluating performance with thousands of instructions is necessary.
3. **Robustness to noisy references**: DRL assumes high-quality reference rationales; its behavior when references are incomplete, contradictory, or of varying expertise is unknown, especially in real-world settings where perfect references are scarce.
4. **Retrieval strategy**: The use of lexical BM25 is a baseline; it is unclear whether semantic dense retrieval (e.g., embedding-based) would yield more relevant patches and further improve reasoning fidelity.
5. **Generality beyond QA**: DRL was tested on multiple-choice QA; whether the approach extends to open-ended tasks like generating differential diagnoses, treatment plans, or risk stratification narratives requires adaptation of the reasoning graph schema and discrepancy analysis.

## Limitations
- The source of reference rationales for public benchmarks (MedQA, MedMCQA) is unspecified; using LLM-generated surrogates may degrade instruction quality compared to physician-authored rationales.
- Prompt engineering details for graph extraction and GED are not fully disclosed, leading to potential variability in reproduction and performance.
- The internal RVA-QA dataset is not publicly available, limiting the ability to reproduce the most significant gains reported.

## Confidence
- Method validity: Medium
- Public benchmark results: Medium
- RVA results: High
- Implementation feasibility: Low

## Next Checks
1. Ablation with human vs. LLM reference rationales: On a held-out public subset, compare instructions derived from physician notes versus those from a strong LLM (e.g., Gemini-2.5-Pro) to quantify any degradation in patch quality and downstream accuracy.
2. Prompt sensitivity analysis: Systematically vary the phrasing of the graph extraction prompt (e.g., node/edge definitions, examples) and measure stability of extracted graphs and final agent performance to identify robust prompt designs.
3. Cross-dataset generalization: Build a DR-KB from one clinical domain within MedQA (e.g., sepsis cases) and apply it to a different domain (e.g., cardiology) to assess the transferability of learned instructions across medical specialties.
