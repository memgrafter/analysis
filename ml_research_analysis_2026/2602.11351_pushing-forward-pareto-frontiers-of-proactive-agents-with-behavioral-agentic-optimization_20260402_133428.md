# Pushing Forward Pareto Frontiers of Proactive Agents with Behavioral Agentic Optimization

## Quick Facts
- **arXiv ID:** 2602.11351
- **Source URL:** https://arxiv.org/abs/2602.11351
- **Reference count:** 28
- **Primary result:** BAO improves Pass@U-2 to 53.5% with User Involvement Rate 21.5% on Function-Gym (Qwen3-4B), matching GPT-4o.

## Executive Summary
Proactive LLM agents must balance task performance with user engagement; these objectives often conflict. This paper introduces Behavioral Agentic Optimization (BAO), a framework combining behavior enhancement (via supervised fine-tuning with teacher-generated demonstrations that include retrospective reasoning and prospective planning) and behavior regularization (turn-level reward shaping to penalize redundant user queries and overthinking) within a reinforcement learning loop using GRPO. Evaluated on the UserRL benchmark, BAO significantly advances the Pareto frontier, achieving higher success rates with substantially lower user involvement than prior methods and even matching or exceeding GPT-4o on some tasks. Additionally, BAO mitigates reward hacking, a common issue in LLM policy optimization.

## Method Summary
BAO employs a two-stage training pipeline. First, a teacher model (GPT‑4o) is prompted to generate interaction trajectories that explicitly demonstrate retrospective reasoning (e.g., memory management, hypothesis refinement) and prospective planning (e.g., dynamic scheduling, strategic querying) for each task. These demonstrations are used to supervised fine‑tune a base LLM (e.g., Qwen3‑4B), providing a warm‑start that equips the agent with multi‑turn reasoning and information‑gathering capabilities. Second, the fine‑tuned model is further optimized with reinforcement learning using GRPO, a policy gradient algorithm. The reward is shaped per turn: besides the environment reward, penalties are applied for consecutive user‑involved actions (to discourage unnecessary queries) and for early termination with excess thinking tokens (to prevent overthinking). This regularization guides the policy toward high performance with low user involvement, pushing the Pareto frontier.

## Key Results
- On Function‑Gym with Qwen3‑4B, BAO achieves Pass@U‑2=53.5% (vs 41.0% for UserRL) and reduces User Involvement Rate to 21.5% (vs 37.6%).
- BAO pushes the Pareto frontier forward across all UserRL tasks, matching or exceeding GPT‑4o’s performance.
- BAO mitigates reward hacking in LLM‑as‑judge settings, avoiding degenerate solutions while maintaining performance.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The trade‑off between task performance and user engagement in proactive LLM agents can be effectively modeled and optimized as a multi‑objective problem.
- **Mechanism:** By formulating the proactive agent training as maximizing expected cumulative reward (task performance) while penalizing the number of user‑involved actions (user engagement), the optimization seeks Pareto‑optimal policies that balance these objectives.
- **Core assumption:** Task performance and user engagement are inherently conflicting; increasing user involvement may improve performance but at the cost of user satisfaction.
- **Evidence anchors:**
  - [abstract]: “We formulate this challenge as a multi‑objective optimization (MOO) problem, with user engagement and task performance as potentially conflicting objectives.”
  - [section 3]: “Proactive Agent Training. … is formulated as an MOO problem that balances task performance maximization and user engagement minimization.”
  - [corpus]: The corpus search returned papers on agentic systems and behavioral strategy but none explicitly model proactive agent training as MOO, indicating limited direct prior work.
- **Break condition:** If the objectives are not conflicting (e.g., if performance plateaus after a certain user engagement level), then MOO may not yield a frontier; a single‑objective approach could suffice.

### Mechanism 2
- **Claim:** Injecting retrospective reasoning and prospective planning behaviors via SFT equips proactive agents with necessary multi‑turn reasoning capabilities for efficient information gathering and hypothesis management.
- **Mechanism:** Using a teacher model (e.g., GPT‑4o) to generate demonstration traces that explicitly exhibit memory management, hypothesis refinement (retrospective), and dynamic scheduling, strategical querying (prospective), then performing SFT on these traces instills these behaviors in the student model.
- **Core assumption:** These inter‑turn behaviors are learnable via demonstration and beneficial for long‑horizon proactive interactions.
- **Evidence anchors:**
  - [abstract]: “combines behavior enhancement to enrich proactive reasoning and information‑gathering capabilities.”
  - [section 4.2.1]: Describes the SFT warm‑start with behavior‑enhanced data and the specific behaviors.
  - [section 4.1]: Defines retrospective reasoning and prospective planning behaviors.
  - [corpus]: Related work like *BehaviorSFT* focuses on behavioral token conditioning but not specifically on retrospective/prospective planning for proactive agents; thus, the specific combination is novel.
- **Break condition:** If SFT‑injected behaviors are not retained during RL or if they do not translate to improved exploration, the enhancement fails.

### Mechanism 3
- **Claim:** Turn‑level reward shaping penalties during RL regularize agent behavior, suppressing inefficient patterns (redundant user queries, overthinking) and mitigating reward hacking.
- **Mechanism:** Augmenting environment rewards with penalties: (1) λ_ans for consecutive user‑involved actions without prior environmental information gain, and (2) λ_think for trajectories terminating early with excessive thinking tokens. These guide the policy away from undesired interaction patterns.
- **Core assumption:** Left unregularized, RL agents exploit task rewards by overusing user feedback or generating verbose outputs, hurting user experience and causing reward hacking.
- **Evidence anchors:**
  - [abstract]: “behavior regularization to suppress inefficient or redundant interactions.”
  - [section 4.2.2]: Equations (2) and (3) for penalty terms.
  - [section 5.3]: Ablation results show w/o BR leads to higher UR and lower Pass@U‑1.
  - [section 5.5]: BAO reduces reward hacking compared to UserRL.
  - [corpus]: *Inform* (from corpus) addresses reward hacking via information‑theoretic modeling but not via turn‑level penalties in multi‑turn proactive settings; thus, the approach is distinct.
- **Break condition:** If penalties are too strong, they may discourage necessary user interactions or thinking; if too weak, they fail to regularize.

## Architecture Onboarding
### Component map
The BAO architecture consists of:
- Behavior Enhancement Module: Generates SFT data with retrospective and prospective behaviors using a teacher model (GPT-4o).
- SFT Trainer: Fine‑tunes the base LLM on the enhanced dataset.
- RL Module: Runs GRPO with behavior regularization (penalties for redundant user interactions and overthinking) on the SFT model.
- Evaluation: Uses UserRL benchmark tasks (Function‑Gym, Telepathy‑Gym, Turtle‑Gym) to compute Pass@U‑k and UR.

### Critical path
1. Start with a pretrained LLM.
2. Generate behavior‑enhanced demonstration traces via teacher prompting.
3. Perform SFT on these traces to get initial policy.
4. Interact with UserRL environments during RL, compute turn‑level rewards with regularization.
5. Update policy with GRPO using group advantages.
6. Repeat steps 4–5 until convergence.

### Design tradeoffs
- Teacher model choice: Using a proprietary model (GPT‑4o) ensures high‑quality behaviors but introduces dependency and cost; open‑source teachers may reduce diversity.
- SFT vs RL: SFT quickly instills behaviors but may not optimize for final objectives; RL fine‑tunes but risks reward hacking without regularization.
- Regularization coefficients: λ_ans and λ_think require tuning; domain‑specific tasks may need different values.
- Turn‑level advantage estimation: Using per‑turn advantages (as in GRPO) simplifies credit assignment but may ignore long‑term dependencies.

### Failure signatures
- Metrics: UR > 0.3 indicates overuse of user interactions; Pass@U‑1 < 0.2 suggests poor early performance.
- Training instability: Large variance in rewards across group rollouts may indicate poor advantage estimation.
- Reward hacking: Training reward increases while evaluation reward decreases; also, answer token length grows excessively.
- Behavior degradation: Low exploration ratio (env_actions/user_actions) and high Self‑BLEU in queries show lack of diverse information seeking.

### First 3 experiments
1. Ablation: Compare full BAO against w/o BE and w/o BR on all tasks to quantify each component's impact on Pass@U‑1/2 and UR.
2. Pareto frontier analysis: For each model, vary allowed user interactions (k) and plot pass rates; compare frontiers between BAO and UserRL to demonstrate improvement.
3. Behavior analysis: Compute exploration ratio, query diversity (Self‑BLEU, embedding similarity), and answer diversity; verify BAO increases diversity and reduces redundant interactions.

## Limitations
- Undisclosed hyperparameters (λ_ans, λ_think, GRPO settings) hinder reproducibility and robustness analysis.
- Dependence on GPT‑4o as teacher, with incomplete prompt specifications for all tasks, introduces variability and barrier to open‑source replication.
- Experimentation limited to three synthetic UserRL tasks; real‑world applicability and generalization are unknown.
