# Dynamic Personality Adaptation in Large Language Models via State Machines

## Quick Facts
- arXiv ID: 2602.22157
- Source URL: https://arxiv.org/abs/2602.22157
- Reference count: 40
- Primary result: Demonstrated a state machine framework that enables LLMs to dynamically adapt personality during conversation, with evidence of interpersonal complementarity in a medical education user study; lightweight classifiers achieved zero error rates.

## Executive Summary
Large language models typically lack the ability to adapt their personality in real time during conversations. This paper introduces a model‑agnostic framework that uses probabilistic state machines to represent latent personality states along the Interpersonal Circumplex (agency and communion). After each user message, an analyzer module produces scores that influence state transitions; the resulting state selects prompt fragments that steer the generative LLM’s communicative style. A medical‑education user study with 40 participants showed that the system dynamically adjusted its personality, demonstrating interpersonal complementarity (e.g., patient warmth increased when the trainee expressed warmth). Moreover, the scoring pipeline could rely on lightweight, fine‑tuned 0.5B parameter classifiers with accuracy comparable to large LLMs and zero error rates, making the approach efficient for deployment.

## Method Summary
The task is to dynamically adapt an LLM agent’s personality during a dialogue. Inputs are user messages (in German) and a role description (a virtual patient). The system targets two personality axes (agency and communion), each discretized into five states. The core apparatus consists of independent state machines per axis; after every turn, an analyzer (either a prompted LLM, a LoRA‑fine‑tuned model, or a classification‑head‑augmented model) produces a numeric score for each axis. This score is converted into a probability distribution over states and fed as an “outside influence” to the user’s state machine. The assistant’s state machine then updates using the user’s state probabilities (with sign‑adjusted correlation). The new assistant states map to textual descriptions that are concatenated into a dynamic system prompt. The generative LLM (GPT‑4.1 in the study) produces the assistant’s reply conditioned on this prompt. The pipeline is evaluated by (1) scoring accuracy against a human‑annotated test set and (2) a user study measuring personality trajectories and complementarity.

## Key Results
- The system successfully adapted its personality state during interactions, with the virtual patient exhibiting significant interpersonal complementarity (e.g., warmth increased in response to user warmth).
- Fine‑tuned 0.5B parameter classifiers achieved accuracy comparable to large LLMs and reduced error rates to zero on a human‑annotated test set.

## Why This Works (Mechanism)

### Mechanism 1: Probabilistic State Machine Architecture
- **Claim:** The probabilistic state machine architecture enables the assistant’s personality to evolve dynamically during conversation.
- **Mechanism:** Each personality dimension is modeled as a finite‑state machine with weighted transition probabilities. After every user message, an analyzer provides scores that serve as outside influences. The next state is computed as a linear combination of default state, current state, old state probabilities, and outside influences, then sampled (or chosen deterministically). The selected state maps to a textual prompt fragment that shapes the LLM’s communicative style.
- **Core assumption:** Personality can be discretized into a small set of meaningful states along a dimension, and transitions follow psychological locality (neighboring states are more likely). The Markov property holds given current state and exogenous influences.
- **Evidence anchors:**  
  - [abstract] The framework “employs state machines to represent latent personality states, where transition probabilities are dynamically adapted to the conversational context.”  
  - [section] Sec 3.3.1 defines the state machine structure and Sec 3.3.2 details the weighted combination of influences that determines transition probabilities.  
  - [corpus] Corpus contains closely related work (e.g., PERSONA, SAC) that also pursue dynamic personality control, but citation counts are zero and FMR scores are moderate (avg 0.501), indicating that the idea is still nascent and not heavily validated.
- **Break condition:** If transition probabilities collapse to a single state or fail to reflect user behavior over many turns, the adaptation mechanism breaks down.

### Mechanism 2: Lightweight Message Scoring
- **Claim:** Lightweight, fine‑tuned classifiers (0.5B parameters) can accurately score messages along personality axes in real time.
- **Mechanism:** The analyzer module processes each user message using a dedicated model (either prompted LLM, LoRA‑fine‑tuned, or classification‑head). The model outputs a numeric score for each axis; this score is converted into a probability distribution over states (e.g., by giving probability 1 to the matching state). The distribution feeds the state machine as outside influence.
- **Core assumption:** Personality cues are sufficiently present in short conversational messages and can be learned from synthetic training data that adequately covers the target domain.
- **Evidence anchors:**  
  - [abstract] “The scoring pipeline maintains comparable precision even when utilizing lightweight, fine‑tuned classifiers instead of large‑scale LLMs.”  
  - [section] Sec 4.1 and Table 1 show that fine‑tuned 0.5B models achieve accuracy comparable to larger models and reduce error rates to zero.  
  - [corpus] Includes papers on personality inference from language supporting the feasibility of automated scoring.
- **Break condition:** Systematic bias or a rising error rate in the analyzer would corrupt the state updates and render adaptation ineffective.

### Mechanism 3: Prompt‑Based Steering
- **Claim:** System‑prompt reconfiguration based on the current state steers the generative LLM’s output to match the desired personality.
- **Mechanism:** After the state machine selects a new state for each axis, the corresponding textual description (e.g., “You are rather cautious…”) is retrieved. The prompt assembler concatenates a fixed role description, these dynamic fragments, and the dialogue history to form the full system prompt. The generative LLM then produces the assistant’s reply conditioned on this prompt.
- **Core assumption:** LLMs are sufficiently instruction‑following that changes in the system prompt lead to observable, consistent shifts in communicative style across turns.
- **Evidence anchors:**  
  - [abstract] “These scores function as dynamic state variables that systematically reconfigure the system prompt, steering behavioral alignment throughout the interaction.”  
  - [section] Sec 3.3.3 precisely describes the generation workflow and the composition of the dynamic prompt.  
  - [corpus] Works like Activation‑Space Personality Steering explore alternative steering methods, implying prompt‑based steering is a known, though not universally proven, technique.
- **Break condition:** If the LLM ignores the injected personality fragments or reverts to a default style, the adaptation becomes invisible to the user.

## Architecture Onboarding
### Component Map
- Chat UI (displays conversation, sends user messages)
- Analyzer module (one per axis; uses LLM or fine‑tuned classifier)
- Personality State Machines (per axis; store state and transition probabilities)
- Prompt Assembler (combines fixed role description with dynamic state descriptions)
- Generative LLM (produces assistant replies)
- Visualization layer (optional; shows highlights, state plots)
- Configuration store (holds state parameters, prompts, weights)

Flow: Chat UI → Analyzer → State Machines (User & Assistant) → Prompt Assembler → Generative LLM → Chat UI. Visualization passively observes state machines and analyzer output; configuration store provides initial parameters.

### Critical Path (per user message)
1. Receive user message.
2. Analyzer produces scores for each axis.
3. User state machine updates using analyzer scores as outside influence.
4. Assistant state machine updates using the resulting user state probabilities (with sign‑adjusted correlation).
5. Retrieve textual descriptions for the new assistant states.
6. Assemble full system prompt (role + all axis descriptions).
7. Generative LLM generates assistant reply.
8. Send reply; optional logging for visualization.

### Design Tradeoffs
- Model‑agnostic prompt steering vs. fine‑grained control: Prompt changes are simple but may be less reliable than parameter‑level methods.
- Number of states: More states increase granularity but demand higher analyzer accuracy and risk instability.
- Deterministic vs. probabilistic: Deterministic mode for user tracking yields stable profiles; probabilistic for assistant adds natural variation.
- Analyzer size: Small fine‑tuned models reduce latency/cost but may sacrifice accuracy; trade‑off depends on deployment constraints.

### Failure Signatures
- Analyzer emits non‑numeric or out‑of‑range outputs → spikes in error rate.
- State machine shows oscillations or fixation on one state → personality appears static or jittery.
- Assistant responses ignore dynamic prompt fragments → no observable personality shift.
- Visualization mismatches (predicted vs observed trajectories) → model mis‑calibration.
- User study shows no complementarity → system not adapting effectively.

### First 3 Experiments
1. *Message‑level vs sentence‑level analysis* – compared granularities and found message‑level yields better adaptation.
2. *Analyzer benchmark* – evaluated multiple LLMs and fine‑tuning strategies on a human‑rated dataset; selected GPT‑4.1 mini (best accuracy) and fine‑tuned 0.5B classifiers (zero error).
3. *User study* – 40 participants interacted with a virtual patient; measured personality trajectories and interpersonal complementarity, confirming the framework’s behavioral impact.

## Open Questions the Paper Calls Out
1. **How can we improve the accuracy of real‑time personality scoring from short messages, especially for dimensions like communion, and reduce reliance on large LLMs?**  
   Basis: moderate accuracy in Table 1 and synthetic data limitations; unresolved due to fine‑tuned models’ poor performance on communion and potential bias.

2. **How can the state machine’s transition parameters be calibrated to reflect empirical interpersonal dynamics and ensure stable, realistic personality adaptation over extended conversations?**  
   Basis: heuristic parameter choices; observed reversion to default in longer interactions; parameters may not capture true psychological processes.

3. **How do personality dimensions dynamically interact, and how can the framework be extended to model cross‑dimensional dependencies rather than treating axes independently?**  
   Basis: independent axes assumption; human personality dimensions often correlate; independence may produce incoherent states.

4. **Does the architecture generalize beyond the Interpersonal Circumplex to other personality models (e.g., Big Five) and to multimodal inputs (e.g., speech, video), and what modifications are required?**  
   Basis: claims of model‑agnosticism but only IPC/text were evaluated; broader applicability untested.

## Limitations
- Synthetic training data (1,210 sentences) and human‑annotated test set (109 messages) are unreleased, raising concerns about analyzer generalizability.
- State machine parameters (weights, σ) were heuristically tuned for a single medical‑education scenario; their transferability to other contexts remains unknown.
- The user study had a small sample size (N=40) and was domain‑specific, limiting confidence in the robustness and generalizability of the observed complementarity effect.

## Next Checks
1. **Analyzer generalizability test**: Collect a new corpus of at least 200 natural German conversational messages, obtain IPC scores from three psychology experts, and evaluate fine‑tuned 0.5B classifiers and GPT‑4.1 mini (accuracy, mean distance, error rates).
2. **Parameter sensitivity ablation**: Systematically vary state machine influence weights (w_d, w_c, w_o, w_q) and σ in simulation; measure stability, adaptation speed, and failure rates to identify robust parameter regions.
3. **Cross‑domain user study replication**: Replicate the medical education experiment in at least two additional domains (e.g., AI tutor, customer support) with total sample N>100, track personality state evolution, and compute interpersonal complementarity metrics across domains.
