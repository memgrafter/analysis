# Ruyi2 Technical Report

## Quick Facts
- arXiv ID: 2602.22543
- Source URL: https://arxiv.org/abs/2602.22543
- Reference count: 8
- Primary result: Introduces a stable Familial Model architecture enabling "Train Once, Deploy Many" with 2–3× training speedup; DaE framework for 1.7B variant reduces added parameters by 40% with <2% performance loss; Ruyi2-1.7B outperforms Qwen3-1.7B by 23.46 points on MMLU.

## Executive Summary
Ruyi2 presents a novel "Familial Model" architecture that leverages shared parameters and early-exit capabilities to produce multiple deployable sub-models (1.7B, 8B, 14B) from a single training run. Built on Megatron-LM with 3D parallelism, it achieves a 2–3× training speedup over its predecessor while maintaining performance parity with independently trained Qwen3 models of the same size. For edge deployment, the Decompose after Expansion (DaE) framework expands the 1.7B model with additional transformer blocks and then compresses them via SVD, reducing added parameters by 40% with less than 2% accuracy loss. Comprehensive benchmarks show Ruyi2-1.7B surpasses Qwen3-1.7B by 23.46 MMLU points (62.77 vs 39.31), and larger variants deliver consistent improvements on reasoning and knowledge tasks.

## Method Summary
Ruyi2 employs a multi-branch architecture where a shared transformer backbone (e.g., 40 layers) supports multiple early-exit heads at intermediate depths, allowing a single training process to yield sub-models of varying capacities. The training pipeline integrates Megatron-LM's 3D parallelism (tensor, pipeline, data) to efficiently optimize a joint loss that aggregates outputs from all exits using time-dependent weights. It comprises continued pre-training on a high-quality ~800B-token corpus, multi-stage supervised fine-tuning on ~4M instruction examples, and reinforcement learning with GRPO. For the 1.7B branch, the Decompose after Expansion (DaE) technique freezes the original backbone, appends three new transformer blocks with zero-residual connections and random internal initialization, continues pre-training on a STEM-focused corpus, applies SFT and RL, then compresses the newly added blocks using SVD-LLM v2 to achieve a 40% parameter reduction with minimal performance degradation.

## Key Results
- 2–3× training speedup over prior Ruyi model.
- DaE reduces added parameters by 40% with less than 2% performance loss for the 1.7B variant.
- Ruyi2-1.7B outperforms Qwen3-1.7B by 23.46 points on MMLU (62.77 vs 39.31).
- Larger variants (8B, 14B) show consistent gains on reasoning (GSM8K, MATH) and knowledge benchmarks.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** A single training run produces multiple deployable sub-models (1.7B, 8B, 14B) with comparable performance to independently trained models, achieving a "Train Once, Deploy Many" paradigm.
- **Mechanism:** A shared transformer backbone with lightweight early-exit heads attached at intermediate layers. All sub-models (branches) share parameters for the common layers, while only the exit-specific layers (projection heads) and any expanded blocks are distinct. A joint optimization framework aggregates losses from all exits during training.
- **Core assumption:** The shared backbone can learn representations that are simultaneously optimal for the full 40-layer model and the shallower 3-layer and 22-layer branches without catastrophic gradient interference.
- **Evidence anchors:**
  - [abstract] "Ruyi2 introduces a stable 'Familial Model'...a single training session yields multiple deployable sub-models, realizing a 'Train Once, Deploy Many' paradigm."
  - [section 2] "Ruyi2 Familial Models use a shared backbone and multiple exit heads...all sub-models share the parameters of the common layers, so no separate models need to be trained from scratch."
  - [corpus] Evidence is weak; neighboring papers (e.g., Ruyi2.5) describe similar paradigms but do not provide independent validation of the core mechanism's stability.
- **Break condition:** If the weighted loss aggregation (Equation 1) fails to balance the learning signals for the main backbone versus the auxiliary exits, leading to degraded performance on one or more branches.

### Mechanism 2
- **Claim:** For the smallest (1.7B) branch, the "Decompose after Expansion" (DaE) framework can double its effective parameter count (via added blocks) and then reduce the *added* parameters by 40% with less than 2% performance loss on key benchmarks.
- **Mechanism:** A two-stage process: 1) **Stabilized Block Expansion:** Append N=3 new Transformer blocks to the 1.7B branch's exit, freezing the original backbone. New blocks use zero-residual output initialization (Wo=0, Wdown=0) and random internal weight initialization to avoid optimization inertia. 2) **Post-training Low-Rank Decomposition:** Apply SVD-based compression (from SVD-LLM v2) to the *newly added* blocks, reconstructing them with low-rank matrices based on activation statistics to meet a target parameter budget.
- **Core assumption:** Randomized internal initialization allows new blocks to learn novel representations complementary to the frozen backbone, and the learned representations are robust to low-rank approximation without losing the gained capacity.
- **Evidence anchors:**
  - [section 4.3.2] "We apply a stabilized block expansion strategy...we impose a strict initialization constraint...Blockk(h) = 0 ⇒ hL+k = hL+k−1...we adopt randomized internal initialization."
  - [section 4.3.2] "To control the parameter budget...we perform SVD-based weight decomposition...reducing the parameter count by 40% with only marginal performance degradation."
  - [section 4.4.2] "Applying the SVD-based decomposition...resulted in a marginal performance drop of less than 2%, while significantly reducing the added parameter count by 40%."
- **Break condition:** If the expanded model, after SVD compression, suffers a performance drop greater than the claimed 2% threshold on a held-out validation set, indicating the decomposition was too aggressive for the learned representations.

### Mechanism 3
- **Claim:** The Ruyi2 training framework, built on Megatron-LM with 3D parallelism (tensor, pipeline, data), enables efficient large-scale joint optimization of the Familial Model, achieving a 2–3× training speedup over the prior Ruyi model.
- **Mechanism:** Integration of the multi-exit architecture with a 3D-parallel training backend. Customized loss aggregation (Equation 1) and "pipeline-aware backpropagation" are engineered to harmonize the gradient flows from multiple exits with the communication schedules of pipeline parallelism, mitigating the gradient interference problem that plagues naive multi-exit training at scale.
- **Core assumption:** The optimization complexity introduced by joint training (multiple loss terms, shared parameters) can be systematically managed within a 3D-parallel framework without causing pipeline bubbles, straggler effects, or destabilizing the backbone's convergence.
- **Evidence anchors:**
  - [abstract] "By using 3D parallel training, it achieves a 2–3× speedup over Ruyi...establishing a new 'Train Once, Deploy Many' paradigm."
  - [section 1] "existing early-exit methodologies often exhibit incompatibility with these distributed training mechanisms...Ruyi2 implements several critical advancements...By integrating 3D parallel training, the framework is systematically optimized."
  - [section 4.3] "The 3D-parallel compatible Familial Models training framework...resolves the gradient interference challenge of large-scale joint optimization via customized loss aggregation and pipeline-aware backpropagation."
- **Break condition:** If scaling the number of GPUs for 3D parallelism does not yield near-linear speedups due to overhead from synchronizing gradients across multiple exits, or if the final model quality degrades compared to a baseline trained without early exits.

## Foundational Learning
- **Concept: Early-Exit / Adaptive Computation**
  - *Why needed here:* This is the core architectural innovation. Understanding why and where to place exit heads, and how they create a family of models from one backbone, is fundamental to grasping Ruyi2's value proposition.
  - *Quick check question:* What are the trade-offs when deciding the layer depth at which to place an early-exit head (e.g., layer 3 vs. layer 22 in a 40-layer model)?

- **Concept: Parameter-Efficient Fine-Tuning (PEFT) & Freezing**
  - *Why needed here:* The DaE framework for the 1.7B variant freezes the original 1.7B backbone entirely while only training newly added blocks. This is a specific PEFT strategy to prevent catastrophic forgetting during capacity expansion.
  - *Quick check question:* In the DaE Stage 1 (CPT), why is it critical to freeze the original backbone parameters, and what would be the risk if they were also updated?

- **Concept: Low-Rank Matrix Factorization (SVD for Compression)**
  - *Why needed here:* The second stage of DaE uses SVD to compress the newly added blocks. Understanding how a weight matrix W ≈ UΣV^T can be approximated by a truncated rank-r version (U_r Σ_r V_r^T) is key to seeing how 40% parameter reduction is achieved.
  - *Quick check question:* How does the compression ratio for a specific layer get determined in the SVD-LLM v2 method described (Equation 6), and what does the "theoretical truncation loss" L_min represent?

## Architecture Onboarding
- **Component map:**
  1.  Shared Backbone: Standard Transformer blocks (layers 1-40) from Qwen3-14B-Base. Parameters fully shared across all branches.
  2.  Exit Heads: Lightweight projection layers (ϕ_i) attached at specific depths (e.g., after layer 3 for 1.7B, layer 22 for 8B). They map hidden state to vocabulary logits.
  3.  DaE Blocks (1.7B only): 3 additional Transformer blocks appended after the 1.7B branch's native exit layer. Their internal weights are randomly initialized; their output projections are zero-initialized.
  4.  Training Framework: Megatron-LM with 3D parallelism (tensor, pipeline, data). Orchestrates joint optimization across all branches via loss aggregation (L_total).
  5.  Post-training Pipeline: Multi-stage process: Continued Pre-training (CPT) -> Supervised Fine-tuning (SFT) -> Reinforcement Learning (GRPO). SVD compression is applied as a final step to DaE blocks after RL.

- **Critical path:**
  1.  Initialize backbone from Qwen3-14B-Base. Initialize branch-specific layers (heads, DaE blocks) as described.
  2.  Run joint multi-branch pre-training on ~800B tokens with scheduled loss weights (λ_k).
  3.  Perform multi-stage SFT on ~4M instructions.
  4.  For 1.7B branch only: Apply DaE (expand with frozen backbone, CPT, SFT, RL), then apply SVD compression to the 3 new blocks.
  5.  Deploy: At inference, based on latency/compute target, route to appropriate exit (original 1.7B, 8B, or full 14B).

- **Design tradeoffs:**
  - **Parameter Sharing vs. Branch Specialization:** More sharing reduces total parameters and training cost but risks a "jack-of-all-trades" backbone that doesn't optimally serve any branch. The loss scheduling (λ_k decay) is a tradeoff to prioritize backbone convergence later.
  - **Expansion Depth vs. Compression Ratio (DaE):** Adding more blocks (N) increases potential capacity gain but also increases the absolute parameter count to be compressed. A higher compression ratio risks losing the gains from expansion.
  - **Training Stability vs. Innovation (DaE Init):** Layer cloning (copying weights) is stable but causes inertia; random internal init is innovative but risks destabilizing the frozen backbone. Zero-residual paths are the tradeoff to enable the random init safely.

- **Failure signatures:**
  - **Gradient Interference:** Training loss for the main 14B branch plateaus or increases while early-exit branch losses decrease, indicating the shared backbone is being optimized for shallower exits at the expense of the full model.
  - **Optimization Inertia (DaE):** Loss curve for the expanded (layer-cloned) model descends much slower than the random-init model, as shown in Figure 6. The expanded blocks fail to contribute new features.
  - **Catastrophic Compression:** After SVD, the 1.7B model's MMLU score drops by >5 points (well beyond the claimed 2%), indicating the low-rank decomposition destroyed critical information in the expanded blocks.
  - **Pipeline Straggler:** With 3D parallelism, one GPU in a pipeline stage consistently lags due to unequal compute from branches (some batches exit early, some go deep), causing bubbles and destroying the 2-3x speedup.

- **First 3 experiments:**
  1.  **Loss Dynamics Comparison:** Train two 1.7B+3-block models: one with layer-cloned new blocks, one with random-initialized new blocks (both with zero-residual paths). Plot total training loss vs. steps. Expect the random-init model to converge faster and to a lower loss (evidence: Figure 6).
  2.  **SVD Compression Sensitivity:** For the DaE-expanded 1.7B model (post-RL), apply SVD at varying compression ratios (e.g., 0%, 20%, 40%, 60%) to the new blocks. Evaluate MMLU, GSM8K, MATH. Expect <2% drop at 40% ratio, significant drop at 60%.
  3.  **3D Parallel Scaling Efficiency:** Measure tokens-per-second per GPU for training the full Ruyi2 (all branches joint) on 256, 512, 1024 GPUs. Compare to a baseline where three separate models (1.7B, 8B, 14B) are trained independently on the same total compute. Expect near-linear speedup for Ruyi2 and 2-3x overall throughput gain over the baseline "train thrice" approach.

## Open Questions the Paper Calls Out
Based on the paper's stated future work, the following open questions remain:
1. How should loss weights (λₖ) be scheduled during joint training to balance gradient interference across exits while ensuring all sub-models converge optimally?
   - Basis: Section 4.3.1 describes λₖ as time-dependent but provides no general principle; a theoretical framework for interference mitigation or adaptive scheduling is lacking.
   - What evidence: Systematic study of λₖ schedules (constant, linear decay, adaptive based on exit loss magnitude) across model sizes and datasets, measuring per-exit accuracy and full-model performance, with gradient norm analysis per layer.
2. Can early-exit architectures inherently reduce hallucinations and improve long-context processing reliability, or do they exacerbate these issues by truncating necessary computation?
   - Basis: Section 5.2 lists "mitigating hallucinations and improving stability in long-context processing" as persistent open problems.
   - What evidence: Evaluate Ruyi2 on hallucination datasets (e.g., TruthfulQA) and long-context benchmarks (e.g., needle-in-haystack, PG19), comparing early-exit vs. full-depth behaviors, with layer-wise attribution.
3. Does the DaE framework's parameter efficiency and performance retention generalize beyond the 1.7B branch, or are its gains specific to small models due to higher redundancy?
   - Basis: DaE is validated only on the 1.7B variant; the paper suggests scalability challenges for larger models but provides no empirical data.
   - What evidence: Apply DaE to Ruyi2-8B and Ruyi2-14B branches, measuring compression ratios vs. performance on reasoning/knowledge benchmarks, and analyze singular value spectra.
4. How can dynamic exit policies be designed to adaptively select exit points based on input complexity without introducing prohibitive overhead or mis-exits?
   - Basis: Section 5.3 states future work will explore "more sophisticated dynamic exit policies," indicating current fixed-layer exits are a limitation.
   - What evidence: Implement and compare confidence estimators (e.g., softmax entropy, hidden-state variance) at each exit, measure added inference cost and accuracy on diverse inputs, and study failure cases.

## Limitations
- Exact hyperparameters (λₖ scheduling, learning rates, batch sizes) are unreported.
- Proprietary dataset specifics (sources, filtering thresholds, deduplication implementations, data mixing ratios) remain unknown.
- Validation of the core mechanisms relies solely on internal experiments; independent reproducibility is not demonstrated.
