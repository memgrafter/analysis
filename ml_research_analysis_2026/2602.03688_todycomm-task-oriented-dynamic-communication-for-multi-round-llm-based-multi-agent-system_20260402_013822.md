# TodyComm: Task-Oriented Dynamic Communication for Multi-Round LLM-based Multi-Agent System

## Quick Facts
*   **arXiv ID:** 2602.03688
*   **Source URL:** https://arxiv.org/abs/2602.03688
*   **Reference count:** 40
*   **Primary result:** A dynamic communication framework that outperforms baselines by up to 13.5 percentage points on MMLU under adversarial settings, while maintaining token efficiency and scaling to 20 agents.

## Executive Summary
TodyComm introduces a framework for multi-round LLM-based multi-agent systems where the communication topology is dynamically adapted each round based on agent behavior. It computes per-agent reliability "credit" scores using a gated recurrent network that aggregates historical responses and interactions. These credits drive a deterministic process to construct a directed acyclic communication graph that prioritizes high-credit agents and respects constraints like budgets. A final credit-weighted vote makes the decision. The system is trained end-to-end with REINFORCE, using task accuracy as the reward. This approach enables robust performance in environments with adversarial agents and limited communication bandwidth.

## Method Summary
The core of TodyComm is a policy that selects a per-round communication graph. For each round, agent outputs from the previous round are used to construct node features. A gated recurrent network (GRN) processes these features and a hidden state to produce a credit score for each agent. These credits are used to sample participation indicators (active/inactive for the round) and to deterministically build a directed acyclic graph (DAG) by adding edges in descending credit order while respecting a predefined edge mask and any node-degree budgets. The selected graph governs message passing between active agents. After the final communication round, a final GRN update produces decision credits; a weighted vote among active agents yields the final answer. The entire policy—sampling probabilities and DAG construction logic—is optimized with REINFORCE, where the reward is the task utility (e.g., accuracy) of the final answer.

## Key Results
*   On MMLU with ≤2 adversarial agents, TodyComm achieves 72.11% accuracy, surpassing the strongest baseline by 7.36 percentage points; with 3 adversaries, it achieves 68.85% (a 13.5 pp gap); with 4 adversaries, 64.71%.
*   It maintains token efficiency comparable to static pruning methods and scales effectively to systems with 20 agents under node-wise degree constraints.
*   It attains >85% accuracy in detecting which agents are adversarial (ADAcc).

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Agent reliability is quantified via temporal credit scores computed by a gated recurrent network (GRN), enabling behavior-driven topology adaptation.
*   **Mechanism:** The GRN aggregates per-round node features (self, neighbor, difference information) and hidden states to produce a credit score $c_i^t$ for each agent $i$ at round $t$. Higher credits indicate greater estimated contribution and reliability.
*   **Core assumption:** An agent's past behaviors and interactions provide a predictive signal for its future reliability in a dynamically changing environment.
*   **Evidence anchors:**
    *   [abstract] "computes per-agent credit scores via a gated recurrent network that aggregates historical responses and interactions"
    *   [section 4.2.1] Details the GRN update: $h_i^t = \text{GRN}(h_i^{t-1}, f_i^t)$, $c_i^t = \text{MLP}(h_i^t)$.
*   **Break condition:** If the GRN fails to capture meaningful temporal patterns, credit scores become uninformative, leading to random or maladaptive graph construction.

### Mechanism 2
*   **Claim:** The communication graph is deterministically constructed each round as a DAG by prioritizing edges from high-credit agents, ensuring structural validity and resource constraints.
*   **Mechanism:** Given sampled participation indicators $a_i^t$, agents are ranked by descending credit. Edges are added in this order while respecting a predefined edge mask, DAG acyclicity, and optional node-wise degree budgets.
*   **Core assumption:** Privileging information flow from higher-estimated-reliability agents yields more robust task performance, especially under adversarial noise.
*   **Evidence anchors:**
    *   [abstract] "deterministically constructs a directed acyclic communication graph by prioritizing high-credit agents"
    *   [section 4.2.1] Algorithm 4 formalizes the credit-ranked edge addition process.
*   **Break condition:** If the credit ranking is incorrect, the deterministic construction locks in poor patterns, potentially isolating reliable agents or empowering adversaries.

### Mechanism 3
*   **Claim:** The overall system is optimized via REINFORCE policy gradient using task utility as reward, aligning the dynamic communication policy with end-task performance.
*   **Mechanism:** The policy's log-probability (from participation sampling) is multiplied by the task reward in the gradient estimator $\nabla_\theta \mathbb{E}[\sum_t \gamma^{T+1-t} \log P^t u_q(\tau)]$, reinforcing earlier actions that lead to high utility.
*   **Core assumption:** Task-level utility provides a sufficient signal for shaping per-round, graph-level communication actions in a sparse-reward, multi-round setting.
*   **Evidence anchors:**
    *   [abstract] "Optimized with REINFORCE using task utility as reward"
    *   [section 4.3] Explicitly defines the REINFORCE gradient update.
*   **Break condition:** If the reward signal is too sparse or noisy, policy gradient learning may be unstable or converge to suboptimal topologies.

## Foundational Learning
*   **Concept: Multi-Agent Reinforcement Learning (Credit Assignment)**
    *   *Why needed:* TodyComm must assign responsibility for task outcomes to specific agents and their communication patterns across rounds. The GRN-based credit is a form of centralized credit assignment.
    *   *Quick check:* How does the GRN's many-to-one structure aggregate information from all $T$ rounds to produce a *per-round* credit $c_i^t$?
*   **Concept: Graph Neural Networks / Topology Learning**
    *   *Why needed:* The problem is framed as learning a sequence of communication graphs. Understanding graph representation and constraints (DAG, budgets) is foundational.
    *   *Quick check:* Why must the inter-agent communication graph $G_t^C$ be a DAG, and how does Algorithm 4 enforce this during construction?
*   **Concept: Policy Gradient Methods (REINFORCE)**
    *   *Why needed:* The action space (discrete graphs) is combinatorial. Policy gradient with a score function estimator is a canonical way to optimize such policies with a scalar reward.
    *   *Quick check:* In Equation (7), what is the role of the discount factor $\gamma^{T+1-t}$, and why is it applied to the log-probability of earlier round actions?

## Architecture Onboarding
*   **Component map:**
    1.  Credit GRN: node features $f_i^t$, hidden state $h_i^{t-1}$ -> credit $c_i^t$
    2.  Participation Sampler: credits $c_i^t$ -> binary $a_i^t$ and $\log P^t$
    3.  DAG Constructor: credits $c_i^t$, participation $a_i^t$, edge mask $M$, budgets -> graph $G_t^C$
    4.  Decision Voter: final credits $c_i^{T+1}$, participation $a_i^{T+1}$ -> weighted vote
*   **Critical path:** Agent output $o_i^{t-1}$ -> Node feature $f_i^t$ -> GRN -> Credit $c_i^t$ -> Sampler -> $a_i^t$ -> DAG Constructor -> $G_t^C$ -> Agent LLM calls with messages -> New $o_i^t$. (Repeats for $t=2..T$, then Decision Voter).
*   **Design tradeoffs:**
    *   *Exploration vs. Stability:* $\epsilon$-greedy in sampler enables exploration but may introduce high-variance edges during training.
    *   *Complexity vs. Scalability:* GRN aggregates cross-round history, increasing parameter count. Node-wise budgets are essential for scaling to $N=20$.
    *   *Credit Generality vs. Specificity:* Using a single GRN for both communication and decision credits forces a trade-off; the paper uses an extra GRN update at $T+1$ for decision-specific credit.
*   **Failure signatures:**
    *   Accuracy collapse under >50% adversaries.
    *   High token usage (overly dense graphs).
    *   Non-converging ADAcc (plateaus below ~85%).
*   **First 3 experiments:**
    1.  Ablation: Remove ranking in DAG construction (Table 5).
    2.  Ablation: Remove agent removal (keep all agents in decision) (Table 5 "w/o removal").
    3.  Evaluate under node-wise degree budgets (Table 3).

## Limitations
*   Implementation details (prompts, GRN architecture, node feature calculations) are underspecified.
*   REINFORCE's high variance may cause unstable training with sparse rewards.
*   Adversarial simulation parameters (timing, attack style) are vague and may not capture all real-world threat models.

## Confidence
*   **Mechanism 1 (GRN credit scoring):** Medium (theoretical plausibility but limited empirical validation of credit quality).
*   **Mechanism 2 (Deterministic DAG construction):** Medium (algorithm clear but heavily dependent on credit accuracy).
*   **Mechanism 3 (REINFORCE optimization):** Low (sparse reward likely unstable; no comparison to alternative RL methods).
