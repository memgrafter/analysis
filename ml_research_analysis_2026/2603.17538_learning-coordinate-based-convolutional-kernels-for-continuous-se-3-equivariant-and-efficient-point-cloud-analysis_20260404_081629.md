# Learning Coordinate-based Convolutional Kernels for Continuous SE(3) Equivariant and Efficient Point Cloud Analysis

## Quick Facts
- **arXiv ID**: 2603.17538  
- **Source URL**: https://arxiv.org/abs/2603.17538  
- **Reference count**: 40  
- **Primary result**: Achieves 91.37% accuracy on ModelNet40 under random rotations and sets new state-of-the-art on multiple 3D point cloud tasks, including pose registration (0.63° rotation error) and S3DIS semantic segmentation (61.80% mIoU).

## Executive Summary
3D point cloud analysis requires models that remain unaffected by arbitrary rigid transformations, i.e., SE(3)-equivariant. Existing equivariant convolutions either scale poorly or lack continuous coverage. This paper introduces **ECKConv** (Equivariant Coordinate-based Kernel Convolution) to tackle both challenges. ECKConv defines the kernel domain in the double coset space SE(3)/SO(2), which ensures continuous SE(3) equivariance by mapping physically distinct neighbor points to unique orbits. The kernel is computed explicitly using a coordinate-based network with Gaussian embedding, enabling efficient memory usage and enhanced local geometry learning. Through a reordered computation, the memory cost during backpropagation is reduced from O(A K C_in C_out) to O(A (K C_in + C_in C_out)). ECKConv is validated on classification, pose registration, part segmentation, and large-scale semantic segmentation, demonstrating top-tier accuracy and memory efficiency.

## Method Summary
ECKConv processes a point cloud by first gathering neighbor points within a fixed radius around each centroid via ball query. For each neighbor, it computes relative coordinates, transforms them using the inverse of the centroid's SE(3) transform, and then parameterizes the neighbor by double coset parameters [β_g, r_g, z_g] that describe its orbit. These continuous coordinates are embedded using Gaussian positional encoding and fed into a small MLP (F_θ) to produce weight coefficients ω_j. A set of learnable linear basis maps W_j (j=1..A) are combined as a weighted sum Σ_j ω_j W_j to form an explicit kernel, which is applied to the neighbor's feature. The resulting transformed features are summed over all neighbors. An optional residual connection can be added. The reordering of the summation (pull neighbor sum outside the product with W_j) drastically reduces memory consumption during backpropagation, enabling larger networks and anchor basis sizes while maintaining SE(3) equivariance.

## Key Results
- **ModelNet40 classification**: 91.37% accuracy (with normals) under random rotations, matching top equivariant methods.  
- **Pose registration**: Mean rotation error 0.63°, translation RMSE 0.010.  
- **S3DIS Area 5 semantic segmentation**: mIoU 61.80%, setting a new SOTA among rotation-invariant approaches, while maintaining memory efficiency.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Defining the kernel domain in the double coset space SE(3)/SO(2) ensures continuous SE(3) equivariance by mapping physically distinct neighbor points to unique orbits under rigid motions.
- **Mechanism**: The double coset parameters [β_g, r_g, z_g] (derived from Euler angles and displacement) are invariant to the combined left action of SO(2) and right action of SO(2) in SE(3). This means that when the entire point cloud undergoes an arbitrary SE(3) transformation, the relative geometry encoded by these parameters remains consistent for corresponding local neighborhoods, allowing the kernel value to transform predictably under the group action.
- **Core assumption**: The locality assumption holds—relevant geometric context is captured within a ball query radius; points with identical topology relative to a centroid lie on the same SE(3)/SO(2) orbit.
- **Evidence anchors**:
  - [abstract] "It defines the kernel domain in a double coset space SE(3)/SO(2), ensuring continuous equivariance."
  - [section 4.1] "A double coset element... uniquely representable as [β_g, r_g, z_g]... convolution equivariant to continuous SE(3) can be built with the kernel depends on them."
  - [corpus] Weak evidence; the neighboring papers discuss equivariant kernels but do not specifically address double coset spaces for SE(3) point clouds.
- **Break condition**: If the local neighborhood contains points with different topological relationships to the centroid (e.g., mixing parts from different object instances), the orbit labeling fails and equivariance is not guaranteed.

### Mechanism 2
- **Claim**: Using explicit kernel computation with coordinate-based networks (Gaussian embedding) improves memory scalability and enhances local geometry learning compared to implicit kernel designs.
- **Mechanism**: The kernel value κ(¯x_i; θ) is expressed as a weighted sum of linear basis maps W_j. The weights ω_j(¯x_i; θ) are produced by a small neural network F_θ operating on Gaussian-embedded double coset coordinates. This separation allows reordering the computation so that the expensive weight matrices W_j are multiplied by the sum of neighbor features, rather than each neighbor feature individually, reducing the backpropagation gradient memory complexity.
- **Core assumption**: The Gaussian embedding [Ψ(¯β_i/π), Ψ(¯r_i), Ψ((¯z_i+1)/2)] with fixed bandwidth σ=0.05 effectively parameterizes the continuous double coset space for learning; the explicit basis-linear combination is sufficiently expressive.
- **Evidence anchors**:
  - [abstract] "its explicit kernel design using coordinate-based networks enhances its learning capability and memory efficiency."
  - [section 4.2.2] "κ(s(x)^{-1}x_i ; θ, [W_j]) = Σ_{j=1}^A ω_j(¯x_i ; θ) W_j"
  - [section 4.3] Proposition 4.1 proving cost reduction from O(A K C_in C_out) to O(A (K C_in + C_in C_out)).
- **Break condition**: If the Gaussian embedding fails to represent high-frequency variations in the double coset manifold, or if the basis dimension A is too small relative to the complexity of the true kernel function, expressive capacity degrades.

### Mechanism 3
- **Claim**: The reordered explicit kernel computation (Equation 11 vs. Equation 10) reduces memory overhead during backpropagation, enabling larger anchor basis A and deeper networks while maintaining SE(3) equivariance.
- **Mechanism**: The summation over neighbors is pulled outside the multiplication with the output-weight matrices W_j. During backpropagation, the gradient ∇_{ω_j} Y requires storing intermediate sums of neighbor features, not the full per-neighbor outer products W_j ⊗ f(x_i). This changes the dominant term from A·K·C_in·C_out to A·(K·C_in + C_in·C_out).
- **Core assumption**: Device memory is a primary bottleneck for scaling equivariant models; the number of anchor bases A and neighbor count K dominate memory consumption over other factors.
- **Evidence anchors**:
  - [section 4.3] "the cost from the derivative by θ... reduces from O(A K C_in C_out) to O(A(K C_in + C_in C_out))."
  - [table 2] ECKConv uses comparable memory to E2PN (discrete) while having ~10x more parameters (27.7M vs 2.7M), demonstrating memory efficiency for parameter scaling.
- **Break condition**: If the neighborhood size K is very small, the O(K C_in) term becomes negligible and the savings diminish; however, for typical K~32-64 the reduction is substantial.

## Foundational Learning
- **Concept**: Group theory for continuous symmetries (SE(3), SO(2), quotient and double coset spaces).  
  *Why needed*: Understanding why the kernel domain SE(3)/SO(2) yields SE(3)-equivariant operations requires knowing how group actions partition the space into orbits and how representations act on feature fields.  
  *Quick check*: "What is the geometric meaning of a double coset element in SE(3)/SO(2) and why is it sufficient to parameterize a 3D local neighborhood up to SE(3) transformations?"
- **Concept**: Intertwiner framework for equivariant convolutions.  
  *Why needed*: The paper builds on this framework to derive the kernel constraint (Equation 3) that guarantees equivariance when the kernel domain is a homogeneous space rather than the group itself.  
  *Quick check*: "In the intertwiner framework, what constraint must the kernel function satisfy with respect to the subgroup H2 to ensure G-equivariance?"
- **Concept**: Coordinate-based neural networks (MLPs with positional encoding).  
  *Why needed*: The Gaussian embedding maps continuous double coset coordinates to a high-dimensional space where a small MLP can learn the weight coefficients ω_j for the explicit kernel; this replaces a naive distance-based gating unsuitable for the double coset metric.  
  *Quick check*: "Why can't a simple Euclidean distance in R^3 be used to compute the kernel weights for the double coset parameters [¯β_i, ¯r_i, ¯z_i]?"

## Architecture Onboarding
- **Component map**: Ball query → neighbor coordinate extraction → double coset parameterization → Gaussian embedding → weight network (F_θ) → coefficient vector ω_j → explicit kernel construction Σ_j ω_j W_j → neighbor feature transformation and aggregation → (optional residual connection) → output features.
- **Critical path**: Ball query → double coset encoding → Gaussian embedding → F_θ → ω_j → Σ_j (ω_j * (Σ_i f(x_i))) → output features.
- **Design tradeoffs**:
  - *Kernel expressivity vs. isotropy*: The double coset parameterization is isotropic (no directional bias), which limits anisotropic feature learning (e.g., normal estimation) but maintains simplicity and scalability.
  - *Explicit vs. implicit kernel*: Explicit kernel (ECKConv) improves memory scaling and allows more parameters; implicit kernel (CSEConv) may have slightly lower memory but suffers O(A K C_in C_out) memory during backprop.
  - *Anchor basis size A*: Larger A increases model capacity but linearly increases memory for the W_j matrices and the ω computation.
- **Failure signatures**:
  - *Equivariance violation*: Performance drops significantly when evaluating on randomly rotated test data compared to aligned data (see Table 1: non-equivariant methods like PointNet++ drop from 89% to 9%).
  - *Local geometry loss*: Poor part segmentation results (e.g., CSEConv mIoU ~35% in Table 4) indicate failure to learn fine-grained local structures.
  - *Memory bottleneck*: Out-of-memory errors at reasonable batch sizes signal that the reordering trick (Equation 11) is not implemented or anchor basis A is too large.
- **First 3 experiments**:
  1. **ModelNet40 classification** under random rotations (I/SO(3) and SO(3)/I): Confirms continuous SE(3) equivariance by achieving similar accuracy with rotated training or testing (ECKConv-Normal 91.37% in both regimes).
  2. **ModelNet40 pose registration** (with DCP head): Tests local feature matching under arbitrary SE(3) transforms; low mean rotation error (0.63°) and translation RMSE (0.010) show robust equivariant features.
  3. **ShapeNet part segmentation**: Validates learning of fine local geometries; high instance mIoU (83.78%) under rotations demonstrates that the explicit kernel captures detailed part structures despite equivariance constraints.

## Open Questions the Paper Calls Out
1. **How can ECKConv overcome its isotropic kernel design and scalar-type feature confinement to effectively handle anisotropic point cloud tasks, such as normal estimation or molecular structure prediction?**  
   *Basis in paper*: Section 10 explicitly states: "These factors decrease the directional expressivity of ECKConv to certain types of point cloud tasks where the point feature should be anisotropic... Expanding the resolvable domain of ECKConv would be an important future research direction."  
   *Why unresolved*: The kernel domain uses double coset elements grouped by SO(2) rotations, yielding isotropic representations. The feature space is scalar, lacking directional vectors or higher-order tensors needed for anisotropic properties.  
   *What evidence would resolve it*: Extend ECKConv to incorporate vector or tensor features via irreducible representations, evaluate on tasks like surface normal prediction or equivariant force field estimation, comparing accuracy and equivariance error against scalar-only ECKConv and steerable baselines.

2. **Can the memory-efficient explicit kernel formulation of ECKConv be integrated with the expressive, steerable convolution kernels based on irreducible representations without sacrificing scalability?**  
   *Basis in paper*: The conclusion identifies this as a key direction: "Expanding the resolvable domain of ECKConv would be an important future research direction that balances our scalable architecture with the inefficient yet expressive kernel designs from the previous steerable convolution studies."  
   *Why unresolved*: Steerable methods use Wigner matrices and spherical harmonics for full SO(3) expressivity but incur high computational costs. ECKConv’s explicit linear maps trade expressivity for efficiency; merging both paradigms poses architectural and complexity challenges.  
   *What evidence would resolve it*: Design a hybrid where steerable kernels are applied in low-dimensional subspaces or selectively per layer, benchmark on large-scale datasets (e.g., S3DIS) for memory usage, throughput, and accuracy compared to pure steerable and ECKConv models.

3. **How robust is ECKConv to errors in normal vector estimation when true normals are unavailable, given its reliance on normals or heuristic coset augmentation for S² input?**  
   *Basis in paper*: Inferred – The method uses either ground-truth normals or Algorithm 1 (coset augmentation) to lift points to S², but no experiments assess performance under normal noise, missing normals, or heuristic failures.  
   *Why unresolved*: Real-world point clouds often have inaccurate or missing normals; the heuristic (PCA-based) may fail on sparse or planar regions, potentially degrading equivariance and performance.  
   *What evidence would resolve it*: Systematically perturb normals (e.g., Gaussian noise, random unit vectors) or remove them on ModelNet40 and S3DIS, compare accuracy drops between ECKConv and methods not requiring normals (e.g., VN, DGCNN w/ augmentation), and analyze failure cases.

4. **Do the fixed hyperparameters—ball query radius per layer and Gaussian embedding bandwidth (σ=0.05)—limit ECKConv’s adaptability to non-uniform point densities or varying geometric scales in real-world scans?**  
   *Basis in paper*: Inferred – Ball query uses fixed radii; Gaussian embedding fixes σ=0.05. Ablations vary embedding dimension (Ψ) and anchor count (A) but not σ or radii, assuming uniform density and scale.  
   *Why unresolved*: Real datasets like S3DIS exhibit non-uniform sampling; fixed parameters may yield suboptimal receptive fields or embedding generalization, affecting local geometry learning.  
   *What evidence would resolve it*: Test on density-varied versions of S3DIS/ShapeNet, adapt radii based on local k-NN distances or learn σ via hypernetworks, measure segmentation/classification mIoU changes and memory footprint.

## Limitations
- Exact hyperparameters (e.g., Gaussian embedding bandwidth, weight network architecture) are not fully specified, hindering exact replication.
- The double coset representation assumes neighborhoods have consistent topology; equivariance may break if local regions mix distinct parts.
- Sensitivity to normal vector errors; real-world point clouds often have inaccurate or missing normals, which could degrade performance.
