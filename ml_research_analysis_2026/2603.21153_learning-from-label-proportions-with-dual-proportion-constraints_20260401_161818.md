# Learning from Label Proportions with Dual-proportion Constraints
## Quick Facts
- **arXiv ID:** 2603.21153
- **Source URL:** https://arxiv.org/abs/2603.21153
- **Reference count:** 40
- **Primary result:** LLP-DC consistently outperforms prior LLP methods across five benchmark datasets and various bag sizes by enforcing dual-proportion constraints at bag and instance levels.

## Executive Summary
Learning from Label Proportions (LLP) is a weakly supervised setting where only bag-level class proportions are available for training an instance-level classifier. The proposed LLP-DC method addresses this by introducing dual-proportion constraints. It combines a bag-level loss that aligns the mean model prediction per bag with the given proportion, and an instance-level loss that uses hard pseudo-labels. These pseudo-labels are generated via a minimum-cost maximum-flow algorithm, which assigns labels to instances in a bag while strictly satisfying the proportion constraint. This two-level approach creates a bidirectional training loop: the bag loss anchors learning to the available aggregate supervision, while the instance loss on proportion-consistent pseudo-labels sharpens decision boundaries. Evaluated on standard vision benchmarks (CIFAR-10/100, SVHN, Fashion-MNIST, MiniImageNet) with bag sizes from 16 to 128, LLP-DC achieves superior accuracy compared to state-of-the-art LLP methods, with training efficiency comparable to other efficient baselines.

## Method Summary
LLP-DC trains a model using only bag-level class proportions. For each bag, two independent augmentations of each instance are created: a weak view and a strong view. The model processes the weak views to obtain prediction probabilities. A minimum-cost maximum-flow algorithm is then applied to these probabilities to generate *hard* pseudo-labels for the instances, ensuring the final assignment exactly matches the bag's given proportion. The total loss has two components: (1) a **bag-level loss** computes the cross-entropy between the average of the weak-view predictions and the true proportion vector; (2) an **instance-level loss** computes the cross-entropy between the strong-view predictions and the flow-generated pseudo-labels, but only for instances where the model's confidence (max probability) exceeds a threshold τ. The losses are weighted by λ and summed. This decouples proportion alignment (using weak views) from discrimination learning (using strong views and strict pseudo-labels).

## Key Results
- On **CIFAR-10** (bag size 16), LLP-DC achieves **95.97%** accuracy vs. **95.00%** for prior best (L2P-AHIL).
- On **CIFAR-100** (bag size 16), it achieves **80.32%** vs. **78.65%**.
- On **MiniImageNet** (bag size 128), it achieves **19.01%** vs. **16.91%**.
- Performance gains are consistent across all tested datasets (CIFAR-10/100, SVHN, Fashion-MNIST, MiniImageNet) and bag sizes (16, 32, 64, 128).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Aligning the mean of model predictions per bag with the given label proportion provides a stable training signal that respects the aggregate supervision without collapse.
- **Mechanism:** The bag-level loss (`L_bag`) computes the cross-entropy between the average softmax output over weak augmentations in a bag and the provided proportion vector α. This encourages the model's *expected* instance-level distribution to match the observed bag-level statistic.
- **Evidence anchors:** Formal definition in [section 3.2]; adoption as a standard baseline in neighboring LLP work; break condition noted for very large/imbalanced bags where the signal is too weak.
### Mechanism 2
- **Claim:** Generating hard pseudo-labels that strictly satisfy the bag proportion via minimum-cost maximum-flow provides accurate, noise-free instance-level supervision.
- **Mechanism:** Instance prediction probabilities (`p_ik`) are treated as negative log costs. A multistage flow graph (source → instances → labels → sink) is constructed with capacities enforcing exactly `m * α_iy` units of flow to each label node `y`. The min-cost max-flow solution yields the highest-probability label assignment that perfectly matches α.
- **Evidence anchors:** Detailed graph construction and optimality proof in [section 3.1.2]; experimental curves showing pseudo-labels rapidly achieve near-perfect proportion satisfaction [section 4.3]; contrast with soft/iterative methods (e.g., ROT) in related work.
### Mechanism 3
- **Claim:** Jointly optimizing the bag-level loss and the instance-level loss on flow-generated pseudo-labels creates a synergistic loop thatcombines stability and discrimination.
- **Mechanism:** The total loss `L = L_bag + λ * L_ins` uses different augmentations: `L_bag` on weak views to match proportions; `L_ins` on strong views against the flow pseudo-labels (from weak views). This separation prevents collapse while ensuring both losses operate under the same proportion constraint.
- **Evidence anchors:** Explicit formulation in [section 3.2]; consistent outperformance over methods using only one constraint (e.g., DLLP, ROT, L2P-AHIL) in [section 4.2]; sensitivity analysis showing robustness to λ [Fig. 5].

## Foundational Learning
- **Concept: Weakly Supervised Learning (LLP Setting)**
  - *Why needed:* LLP defines the problem: supervision is only at the bag level (class proportions), not at the instance level. All mechanisms must operate under this constraint.
  - *Quick check:* For a bag of 10 instances with proportion [0.7, 0.3] for 2 classes, what are the possible sets of true instance labels? (Any multiset with exactly 7 from class 0 and 3 from class 1.)
- **Concept: Instance-level Pseudo-labeling**
  - *Why needed:* LLP-DC's core innovation is converting bag proportions into instance labels. Understanding pitfalls (noise, drift) is key to appreciating the flow algorithm's strict constraint.
  - *Quick check:* Why might directly using the model's argmax prediction per instance as a pseudo-label fail under LLP? (It ignores the bag proportion constraint, leading to assignments that don't match α.)
- **Concept: Optimization as a Network Flow Problem**
  - *Why needed:* The flow algorithm is the engine for generating strict pseudo-labels. It transforms a combinatorial assignment into a polynomial-time solvable linear program.
  - *Quick check:* In the flow graph, what do the capacities on edges from label nodes to the sink represent? (The required count `m * α_iy` for each label `y`, enforcing the proportion exactly.)

## Architecture Onboarding
- **Component map:** 
  Input Data -> Augmentation Module (weak/strong splits) -> Encoder+Classifier (f->g) -> Softmax -> [For each bag: Flow Solver (min-cost max-flow) -> Hard Pseudo-labels] -> Loss Calculator (L_bag from weak avg & α; L_ins from strong views & pseudo-labels, filtered by τ) -> Combined Loss (L_bag + λ*L_ins) -> Backpropagation -> Model Update.
- **Critical path:** 
  1. Load batch of bags. 
  2. Generate weak (`x_w`) and strong (`x_s`) augmentations for all instances. 
  3. Forward pass on `x_w` to get predictions `p`. 
  4. **Per bag:** Construct flow graph from `p` and α; solve min-cost max-flow to get hard assignments `ŷ`. 
  5. Compute `L_bag` = CE(mean(`p`), α). 
  6. Compute `L_ins` = CE(predictions on `x_s`, `ŷ`) for instances with max(`p`) ≥ τ. 
  7. Combine `L = L_bag + λ*L_ins`. 
  8. Backpropagate and update model.
- **Design tradeoffs:**
  - **Flow cost vs. strictness:** Exact proportion satisfaction via polynomial-time flow (O(m²l²) per bag) vs. softer, approximate methods (e.g., Sinkhorn in ROT).
  - **Threshold τ:** Higher τ improves pseudo-label quality but reduces coverage (fewer samples in `L_ins`); lower τ increases noise but provides more signal.
  - **λ weighting:** Balances stability (`L_bag`) and discrimination (`L_ins`); requires tuning but is robust across moderate ranges.
- **Failure signatures:**
  - Pseudo-label ratio (fraction of instances with confidence > τ) remains very low throughout training → model not learning; consider reducing augmentation strength or adjusting λ/τ.
  - Pseudo-label accuracy (if validated) plate far below final test accuracy → flow pseudo-labels are systematically wrong; increase warm-up with pure `L_bag`.
  - Training becomes unstable after introducing `L_ins` (loss spikes) → λ too high or τ too low; reduce λ or increase τ.
- **First 3 experiments:**
  1. **Reproduce Table 1:** Verify LLP-DC's main results against DLLP, L2P-AHIL, ROT, etc., on CIFAR-10/100, SVHN, etc., for bag sizes 16–128.
  2. **Run Ablation on Dual Constraints:** Train with (a) `L_bag` only (λ=0), (b) `L_ins` only (using flow but no `L_bag`), (c) full LLP-DC. Expect (c) > (a) > (b) typically.
  3. **Conduct Sensitivity Analysis:** Sweep λ ∈ {0, 0.25, 0.5, 1, 2} and τ ∈ {0, 0.3, 0.6, 0.9, 0.95} on CIFAR-10 (bag size 16); confirm performance stability and identify degradation at extremes.

## Open Questions the Paper Calls Out
- **Adaptive sample selection:** How to extend LLP-DC with dynamic thresholds, curricula, or teacher-student frameworks to refine pseudo-label quality while preserving proportion constraints?
- **Standardized real-world benchmarks:** What standardized vision datasets with natural bag-level proportions should be established for fair LLP comparisons? Current work uses synthetic bagging of standard datasets.
- **Variable bag sizes:** Does LLP-DC remain effective when bag sizes vary significantly? Experiments only use fixed sizes; variable sizes could affect flow construction and stability.
- **Scalability of flow computation:** Can the O(m²l²) cost of the min-cost max-flow be reduced for very large bags/classes without compromising strict proportion satisfaction? Approximations are untested.

## Limitations
- **Implementation details unspecified:** Exact flow solver interface, graph construction nuances, and pseudo-label refresh frequency are not detailed, hindering exact replication.
- **Early pseudo-label noise:** On difficult datasets (e.g., MiniImageNet) or with large bags, initial model predictions may be poor, risking noisy instance-level gradients; the static τ and warm-up schedule are not optimized.
- **Scalability unproven:** The flow complexity's impact on runtime for very large bag sizes (`m`) or number of classes (`l`) is only benchmarked up to m=128; performance for larger scales is unknown.

## Confidence
- **Dual-constraint superiority:** High (consistent gains across 5 datasets, ablations confirm synergy).
- **Flow pseudo-label accuracy:** Medium (curves show good proportion satisfaction, but early noise risk remains especially on hard datasets).
- **Robustness & efficiency:** Medium (stable in sensitivity tests, runtime comparable to baselines for tested sizes; scalability unverified).
- **Generalization to variable bag sizes:** Low (no empirical evidence; inferred claim only).
