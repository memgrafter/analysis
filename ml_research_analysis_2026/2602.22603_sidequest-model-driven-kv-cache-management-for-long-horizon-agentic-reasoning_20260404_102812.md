# SideQuest: Model-Driven KV Cache Management for Long-Horizon Agentic Reasoning

## Quick Facts
- **arXiv ID**: 2602.22603
- **Source URL**: https://arxiv.org/abs/2602.22603
- **Reference count**: 16
- **Primary result**: Reduces peak token usage by up to 65% with ≤2% accuracy loss on in-distribution tasks and ≤5% on out-of-distribution tasks.

## Executive Summary
Long-running agentic workflows, such as multi-step web browsing, suffer from explosive growth in the KV cache due to accumulated tool outputs and intermediate reasoning. Conventional heuristic-based compression methods (e.g., attention-score pruning) fail because token utility in these settings is dynamic and non-monotonic—a piece of information may be crucial early on, become temporarily obsolete, and then be needed again later. SideQuest addresses this by enabling the model itself to reason about token staleness via a parallel auxiliary thread, thus avoiding pollution of the main context with management tokens. Trained on only 215 synthetic traces, SideQuest achieves substantial memory savings with minimal accuracy degradation and demonstrates significant throughput improvements in real-world serving.

## Method Summary
SideQuest introduces a parallel auxiliary thread that periodically analyzes the current ReAct state (including open tool responses/cursors and the original user goal) to decide which cursors have become stale and should be evicted from the KV cache. The auxiliary thread runs concurrently with the main reasoning thread, appends a trigger phrase to the shared context to generate its reasoning and deletion commands, and exits without retaining its tokens in the main context. The eviction is then applied atomically. The system is trained via a pipeline that uses hindsight annotation: for correct main-task traces, the "last-use index" of each cursor is computed, and an annotation model generates plausible in-the-moment reasoning for eviction decisions at triggered intervals. The base model is fine-tuned with a hybrid objective combining cross-entropy on auxiliary traces and logit distillation on main traces to preserve core reasoning skills.

## Key Results
- Peak token usage reduced by up to 65% compared to uncompressed baseline.
- Accuracy loss minimal: ≤2% on in-distribution (FRAMES) and ≤5% on out-of-distribution (BrowseComp) tasks.
- Outperforms all heuristic baselines (H2O, SnapKV, R-KV) in the efficiency-utility trade-off.
- Production serving shows 83.9% higher throughput and 53.9% lower KV cache usage.

## Why This Works (Mechanism)
### Mechanism 1: Parallel Auxiliary Thread Avoids Context Pollution
- **Claim**: Executing KV cache management in a parallel auxiliary thread prevents management tokens from polluting the model's primary attention context.
- **Mechanism**: The system spawns an asynchronous auxiliary thread that shares the same KV cache but generates its own output sequence (reasoning about token staleness followed by deletion commands). These management tokens are not retained in the main context after the auxiliary thread completes; only the eviction action is applied.
- **Core assumption**: Interleaving management tokens into the main ReAct trajectory would degrade reasoning quality by consuming context slots and potentially introducing irrelevant information into the attention window.
- **Evidence anchors**: [abstract] "framed as an auxiliary task executed in parallel to the main reasoning task... avoiding pollution of the main context." [section 3.1] Describes the parallel architecture, synchronization, and transient nature of auxiliary thread tokens.
- **Break condition**: If auxiliary thread generation latency becomes a bottleneck or if the shared context introduces unintended interference during concurrent attention computation.

### Mechanism 2: Model-Driven Reasoning Captures Dynamic Utility
- **Claim**: The Large Reasoning Model (LRM) itself can capture the dynamic, non-monotonic utility of tokens across multi-step agentic workflows more effectively than static heuristics.
- **Mechanism**: At triggered intervals, the auxiliary thread analyzes the current ReAct state—including open tool outputs (cursors) and the user's original goal—and reasons about which tool responses have served their purpose and are now stale. It outputs structured deletion commands based on semantic understanding rather than proxy metrics.
- **Core assumption**: A model's semantic reasoning over the task state and conversation history can identify when a piece of retrieved information is no longer needed for future synthesis, even if it was historically important.
- **Evidence anchors**: [abstract] "leverages the Large Reasoning Model (LRM) itself to perform KV cache compression by reasoning about the usefulness of tokens." [section 3] Explains the challenge of dynamic utility, the definition of "last-use index," and examples like Cursor 0 becoming obsolete.
- **Break condition**: The model's reasoning fails to recognize future relevance (e.g., prematurely evicts a cursor needed for final answer citation) or misidentifies stale content.

### Mechanism 3: Data-Efficient Training via Hindsight Annotation
- **Claim**: A small, high-quality dataset (215 traces) synthesized via hindsight analysis can train the model to perform auxiliary KV eviction without catastrophic forgetting.
- **Mechanism**: The training pipeline uses correct traces from a base policy. For each cursor, it computes a "last-use index." At fixed intervals, it identifies expired cursors, masks some as already evicted, and uses an annotation model to generate concise reasoning explaining why the remaining open cursors are stale. The model is fine-tuned on this auxiliary data combined with main traces via logit distillation.
- **Core assumption**: Last-use index is a reliable proxy for staleness in hindsight; an LLM can generate plausible in-the-moment reasoning for eviction decisions when provided with the partial context and target deletions.
- **Evidence anchors**: [abstract] "trained on just 215 samples... minimal degradation in accuracy." [section 3.3] Details the data synthesis pipeline.
- **Break condition**: Incorrect last-use labeling or low-quality auxiliary reasoning from the annotation model leads to poor generalization.

## Architecture Onboarding
- **Component map**:
  Trigger Controller -> Auxiliary Thread -> Shared KV Cache (read/write) -> Eviction Module -> Main Thread (resumes)
- **Critical path**:
  1. Main thread completes a turn; trigger condition (t mod K == 0) met.
  2. System appends trigger phrase ("**Memory management mode**") to shared context and spawns auxiliary thread.
  3. Auxiliary thread generates reasoning about cursor staleness and outputs deletion list.
  4. System waits for main thread's current turn to finish (synchronization).
  5. Eviction module removes KV entries for specified cursors.
  6. Auxiliary thread terminates; main thread resumes with reduced context.
- **Design tradeoffs**:
  - *Parallel vs. sequential*: Parallel avoids context pollution but adds transient compute cost; sequential would be simpler but degrade main task latency.
  - *Eviction granularity*: SideQuest evicts entire tool responses (cursors); finer-grained token pruning could be more aggressive but risks breaking coherence.
  - *Data efficiency vs. coverage*: Training on 215 traces is efficient but may limit robustness on out-of-distribution tasks (observed 5% accuracy drop on BrowseComp).
- **Failure signatures**:
  - High *non-completion rate* from unparsable responses (seen in heuristic baselines), indicating coherence breakdown from poor pruning.
  - *Accuracy drop on complex/high-effort tasks* when model misidentifies stale vs. useful cursors.
  - *Auxiliary thread latency* exceeding main thread step time, reducing overall throughput gains.
  - *Eviction of citation-needed cursors*, causing final answer to lack required references.
- **First 3 experiments**:
  1. **Efficiency-utility trade-off**: Plot accuracy vs. peak token usage/KV reads for SideQuest vs. H2O, SnapKV, R-KV across FRAMES/BrowseComp (Medium/High effort).
  2. **Failure mode analysis**: Categorize non-completion rates by root cause (unparsable, context limit, turn limit) to demonstrate SideQuest's robustness.
  3. **Serving performance**: In SGLang, measure throughput, normalized KV usage, and total runtime at varying batch sizes to quantify real-world impact.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: To what extent does increasing the training dataset size and diversity improve SideQuest's accuracy on out-of-distribution agentic tasks?
- **Basis in paper**: Section 5 (Limitations) states that the observed accuracy degradation on BrowseComp is hypothesized to stem from limited training data (215 samples), and scaling to a larger, more diverse distribution would close the gap.
- **Why unresolved**: The current training data is small and sourced only from FRAMES; generalization to other domains or distributions remains unvalidated.
- **What evidence would resolve it**: Train SideQuest on a significantly larger and more diverse set of agentic traces (e.g., thousands of samples spanning multiple domains) and measure accuracy changes on OOD benchmarks like BrowseComp.

### Open Question 2
- **Question**: Can SideQuest's auxiliary thread be effectively extended to prune obsolete intermediate reasoning steps (thought tokens) without compromising logical coherence?
- **Basis in paper**: Section 5 explicitly identifies that current eviction is scoped only to tool responses, and extending to thought pruning is a promising future direction.
- **Why unresolved**: The utility and dynamics of thought tokens may differ from tool outputs; aggressive pruning could disrupt multi-step reasoning chains.
- **What evidence would resolve it**: Annotate staleness of thought tokens in reasoning traces, adapt the training pipeline to include thought-eviction targets, and evaluate on long-horizon tasks for both memory savings and answer coherence.

### Open Question 3
- **Question**: How well does SideQuest generalize to non-web-browsing agentic domains, such as automated software engineering or multi-modal reasoning?
- **Basis in paper**: Section 6 proposes applying SideQuest to coding agents as a future direction, indicating domain generalization is an open question.
- **Why unresolved**: Evaluation is limited to web-browsing benchmarks (FRAMES, BrowseComp); other domains may involve different context growth patterns, tool types, and reasoning structures.
- **What evidence would resolve it**: Port SideQuest to coding agent benchmarks (e.g., SWE-bench) or multi-modal tasks, comparing memory reduction and success rates against both uncompressed baselines and heuristic methods.

### Open Question 4
- **Question**: Would a hybrid system combining heuristic KV cache compression with SideQuest's model-driven eviction yield a superior efficiency-utility trade-off?
- **Basis in paper**: Section 5 notes that exploring a combination of heuristic and model-driven approaches is an interesting avenue for future research.
- **Why unresolved**: The paper presents SideQuest as an alternative to heuristics but does not investigate integration; potential synergies remain unexplored.
- **What evidence would resolve it**: Implement a hybrid method that applies heuristics first and then SideQuest's auxiliary reasoning, evaluate on benchmarks for Pareto improvements in memory usage versus accuracy, and analyze failure modes.

## Limitations
- Model architecture (gpt-oss series) and tokenization undisclosed, preventing exact replication of LoRA targets and cursor mapping.
- Local server tools and KV eviction implementation (e.g., `clear_kv`) not fully detailed; memory measurements may vary.
- Training pipeline uses automatic last-use annotation; labeling errors could propagate to eviction policy.
- Auxiliary thread compute overhead not deeply characterized; may become bottleneck under load.
- Out-of-distribution accuracy drop (up to 5%) indicates limited robustness.

## Confidence
- Parallel auxiliary thread avoids context pollution: **High** (explicit synchronization design, transient tokens).
- Model-driven reasoning captures dynamic utility: **Medium** (no direct ablation; plausibly confounded with base model capability).
- Data-efficient training (215 samples) sufficient: **Medium** (reported results but limited diversity may impair generalization).
- Overall efficiency claims (65% token reduction, ≤2%/5% loss): **High** (consistent across benchmarks and serving tests).
