# Do Mixed-Vendor Multi-Agent LLMs Improve Clinical Diagnosis?

## Quick Facts
- **arXiv ID:** 2603.04421
- **Source URL:** https://arxiv.org/abs/2603.04421
- **Reference Count:** 40
- **Primary Result:** Mixed-vendor multi-agent systems (using o4-mini, Gemini-2.5-Pro, Claude-4.5-Sonnet) achieve new state-of-the-art clinical diagnosis accuracy by pooling complementary model biases, outperforming both single-model and homogeneous multi-agent setups.

## Executive Summary
This paper evaluates whether using multiple LLM vendors in a multi-agent framework improves clinical diagnostic accuracy, addressing the risk of correlated failures in teams composed of identical models. Testing on rare disease (RareBench) and general diagnosis (DiagnosisArena) benchmarks, the Mixed-Vendor Multi-Agent Conversation (MAC) configuration consistently surpassed both single-LLM baselines and Single-Vendor MAC teams. The performance gain is attributed to the system's ability to combine diverse, complementary reasoning paths, effectively rescuing correct diagnoses that homogeneous teams would miss.

## Method Summary
The study uses the MAC framework, where three doctor agents and a supervisor engage in a round-robin dialogue. Doctors propose ranked diagnoses with justifications; the supervisor monitors, gives feedback, and terminates the conversation upon consensus or at a 13-turn limit. Three configurations are compared: (1) Single-LLM (direct diagnosis), (2) Single-Vendor MAC (three identical model agents), and (3) Mixed-Vendor MAC (three different vendor models as doctors). Models tested include o4-mini-0416, gemini-2.5-pro, and claude-4.5-sonnet, with o4-mini as the default supervisor. Evaluation is performed on RareBench subsets (MME, HMS, LIRICAL) using Recall@k, and on DiagnosisArena using Top-k accuracy, with an LLM judge (o4-mini) and a retrieval-based method (BioLORD-2023).

## Key Results
- Mixed-Vendor MAC achieves **Recall@1 of 39.31%** on combined RareBench, exceeding the best Single-Vendor MAC (36.63%) and best Single-LLM (37.58%).
- On DiagnosisArena, Mixed-Vendor MAC reaches **Top-1 accuracy of 36.36%**, versus the best Single-Vendor MAC's 35.76%.
- Overlap analysis shows mixed-vendor teams rescue more correct diagnoses missed by homogeneous teams than they discard, indicating expanded solution space via complementary inductive biases.

## Why This Works (Mechanism)
The performance gain stems from **complementary inductive biases** across vendor models. Homogeneous teams (Single-Vendor MAC) exhibit correlated errors, where shared biases lead to convergent hallucination or oversight. Mixed-vendor teams pool diverse reasoning patterns; a correct diagnosis proposed by one vendor can be preserved, refined, and ultimately selected by the supervisor even if other vendors initially overlook or reject it. This process rescues cases where all homogeneous agents fail, outweighing any new errors introduced by diversity.

## Foundational Learning
- **Multi-Agent LLM Systems**: Multiple LLMs interacting via structured dialogue. *Why needed*: Enables debate, consensus-building, and error correction beyond single-model reasoning. *Quick check*: Implement a two-agent debate on a factual QA task; does consensus improve accuracy?
- **LLM Evaluation in Healthcare**: Assessing diagnostic outputs against gold-standard labels. *Why needed*: Clinical tasks require precise, reliable metrics; standard NLP metrics may not capture clinical validity. *Quick check*: Compare exact-match vs. UMLS-based semantic similarity for symptom-disease pairs.
- **Bias Diversity Across Vendors**: Different model architectures/training data induce varied reasoning biases. *Why needed*: Diversity can mitigate systematic blind spots if managed correctly. *Quick check*: Run a small set of clinical cases through multiple vendor APIs; calculate pairwise agreement (Cohen's κ) to quantify divergence.
- **Consensus Mechanisms**: Protocols (like supervisor termination) for determining when agent groups agree. *Why needed*: Prevents infinite loops and aims to extract a reliable collective decision. *Quick check*: Simulate varying consensus thresholds (e.g., 2/3 vs. unanimous) on a toy problem; measure impact on accuracy and turns.
- **Clinical Decision Support Systems**: AI tools that assist, not replace, clinicians. *Why needed*: This work targets augmentation, requiring careful validation on realistic clinical data. *Quick check*: Verify that system outputs include justifications and confidence scores suitable for clinician review.

## Architecture Onboarding
**Component Map (Plain Text)**
Doctor Agents (o4-mini, Gemini-2.5-Pro, Claude-4.5-Sonnet) -> Round-Robin Dialogue (max 13 turns) -> Supervisor Agent (o4-mini) -> Termination Decision -> Final Ranked List (Top-5/10)

**Critical Path**
1. Input case formatted as phenotype summary or narrative.
2. Each doctor agent, in fixed order, proposes a ranked diagnosis list with justification.
3. Supervisor analyzes the full conversation history after each turn.
4. If consensus detected (or turn limit reached), supervisor outputs final ranked list; else, supervisor provides feedback to all doctors and cycle repeats.

**Design Tradeoffs**
- *Vendor Diversity vs. Coordination Overhead*: More vendors increase potential coverage but also raise communication complexity and risk of incoherence.
- *Supervisor Model Choice*: Using a strong model (o4-mini) as supervisor is effective but creates a dependency; weaker supervisors may fail to mediate effectively.
- *Turn Limit vs. Convergence*: A fixed limit (13 turns) prevents infinite loops but may cut short productive debate on complex cases.

**Failure Signatures**
- *Single-Vendor MAC*: Uniformly incorrect convergences (all agents hallucinate same wrong diagnosis).
- *Mixed-Vendor MAC*: "Consensus trap" where a cohesive incorrect majority overrides a correct minority signal.
- *General*: Supervisor prematurely terminates on superficial agreement without verifying medical plausibility.

**First 3 Experiments**
1. **Baseline Single-LLM**: Run each vendor model (o4-mini, Gemini, Claude) independently on a small sample (e.g., 20 RareBench cases) to establish per-model performance.
2. **Single-Vendor MAC Replication**: Implement a three-agent team with identical models (e.g., all o4-mini) and the supervisor protocol; verify performance relative to single-LLM baseline.
3. **Mixed-Vendor MAC Activation**: Assemble the heterogeneous doctor team; confirm that the Mixed-Vendor configuration outperforms the best Single-Vendor MAC on the same sample.

## Limitations
- **Dataset Accessibility**: RareBench subsets and the 2024 DiagnosisArena case selection criteria lack clear public sourcing, hindering exact replication.
- **Protocol Underspecification**: The supervisor's "consensus detection" logic is referenced but not concretely defined, introducing implementation variability.
- **Evaluation Sensitivity**: The LLM judge (o4-mini) may penalize clinically equivalent but lexically different diagnoses; BioLORD matching thresholds are not detailed.

## Confidence
- **Performance Improvement Claim (Mixed-Vendor > Single-Vendor/Single-LLM)**: Medium. Results are numerically clear on two benchmarks, but reproducibility is uncertain due to dataset/implementation ambiguities.
- **Mechanism Claim (Complementary Biases Rescue Missed Diagnoses)**: Medium. Overlap analysis is suggestive but not causal; depends on faithful protocol execution.
- **Generalizability Claim (to other tasks/vendors)**: Low. Tested only on rare disease diagnosis with three specific models; no evidence of broader applicability.
