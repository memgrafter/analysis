# Rethinking Atomic Decomposition for LLM Judges: A Prompt-Controlled Study of Reference-Grounded QA Evaluation
## Quick Facts
- arXiv ID: 2603.28005
- Source URL: https://arxiv.org/abs/2603.28005
- Reference count: 23
- Primary result: Holistic judges match or exceed atomic performance on ASQA and QAMPARI (especially for incomplete answers) while using 1.4–2.3× fewer tokens; TruthfulQA shows a small atomic edge.

## Executive Summary
The paper examines whether atomic decomposition—breaking candidate answers into claims for verification—actually improves LLM-based judges for reference-grounded QA evaluation, or if any observed benefit is merely due to the richer prompting typically associated with such decomposition. Through a controlled comparison of a self-decomposing single-prompt atomic judge against a prompt-controlled holistic judge (identical inputs + detailed rubric) across three QA benchmarks (TruthfulQA, ASQA, QAMPARI) with 200 examples each and four model families, the authors find that holistic judges match or exceed atomic performance on ASQA and QAMPARI, with statistically reliable gains for three model families. The advantage is concentrated in detecting partially supported answers (incompleteness). Holistic judges also generate far fewer tokens (1.4–2.3× reduction). TruthfulQA shows a small atomic edge. Both judge types are highly sensitive to reference quality. The results suggest that for completeness-sensitive QA evaluation, the self-decomposing atomic pattern offers no clear benefit over a well-designed holistic prompt.

## Method Summary
The study implements two judge designs: an atomic judge that prompts the LLM to decompose the candidate answer into atomic claims and verify each against the reference; and a holistic judge that uses a detailed rubric covering correctness, completeness, unsupported detail, and style bias without decomposition. Both judges receive identical inputs (question, reference, candidate) and output a JSON verdict. The evaluation runs on 200 source examples per dataset from TruthfulQA, ASQA, and QAMPARI, using four model families (Claude, GPT, Gemini, DeepSeek) with temperature 0 and controlled max tokens. Accuracy against gold labels (supported/partially_supported/unsupported) is measured, along with output token counts. Three prompt variants per judge family are tested to ensure robustness. Statistical significance is assessed via source-level paired sign tests and cluster bootstrap confidence intervals.

## Key Results
- Holistic judges match or exceed atomic judges on ASQA and QAMPARI across all model families, with significant gains for three families.
- The holistic advantage is largely confined to the `partially_supported` class (detecting incomplete answers), where accuracy improvements reach up to +33 percentage points.
- Holistic judges use 1.4–2.3× fewer tokens on ASQA and QAMPARI; TruthfulQA shows a small atomic edge (+0.7–1.5%).
- Both judge types are highly sensitive to reference-quality degradation (e.g., paraphrasing or removal of reference).

## Why This Works (Mechanism)
We present three plausible mechanisms for the observed holistic advantage, based on the paper’s evidence and reasoning.

### Mechanism 1: Fragmentation of Completeness Reasoning
The atomic prompt asks for claim‑by‑claim verification, which may aggregate only binary support flags without tallying which reference items were never addressed, thus missing omissions. The holistic prompt includes a completeness dimension that explicitly asks for “coverage” and “missing information”, prompting a global scan. Evidence: The variant ablation shows that atomic judges are weaker specifically on `partially_supported` cases (Table 4), while holistic maintains high coverage detection. Break condition: If an atomic judge receives pre‑decomposed claims from an external component still shows the deficit, then fragmentation inherent to self‑decomposition is not the primary cause.

### Mechanism 2: Explicit Completeness Instruction
The holistic rubric explicitly lists “completeness” as an evaluation dimension, directing the model’s attention to missing information. The atomic prompt focuses on claim verification without a separate completeness question. The schema‑matched ablation (atomic‑style JSON output without decomposition) yields lower accuracy on ASQA compared to holistic (Table 7), suggesting the completeness dimension, not just format, matters. Break condition: Adding a literal completeness instruction to the atomic prompt should close the gap; removing it from holistic should remove the advantage.

### Mechanism 3: Token Inefficiency Without Accuracy Gain
Atomic judges generate 1.4–2.3× more tokens due to claim enumeration, but these extra tokens do not boost accuracy. The budget control experiment shows atomic accuracy on ASQA remains flat across 128/256/512 token limits, while holistic remains higher with fewer tokens. This indicates the atomic judge’s extra tokens are spent on verbosity rather than useful reasoning. Break condition: If increasing the atomic budget far beyond 512 tokens (e.g., 2048/4096) yields a significant jump, then token limit was the bottleneck; a flat trend would confirm inefficiency.

## Foundational Learning
- **Concept: Reference‑grounded evaluation**  
  Why needed: The judges must adhere to a provided reference answer rather than rely on internal knowledge, mimicking benchmark evaluation. Quick check: If a judge uses parametric knowledge to judge a candidate that is factually correct but differs from the reference, is that a failure? It is a failure because the task is to assess reference support, not independent truth.

- **Concept: Atomic decomposition**  
  Why needed: The core pattern being tested; involves extracting atomic factual claims from the candidate and verifying each against the reference. Quick check: How does an atomic judge produce its final verdict from the list of supported/unsupported claims? Typically it aggregates (e.g., if any unsupported → unsupported; else if all supported → supported; else partially_supported). Could that process miss missing information? Yes, if the aggregation only considers presented claims and does not check for reference items not covered.

- **Concept: Completeness‑sensitive classification**  
  Why needed: The three‑way label (supported/partially_supported/unsupported) penalizes omissions; detecting partially_supported is where the main difference appears. Quick check: Given a reference with three facts and a candidate that includes two correctly but omits the third, what is the gold label? It should be partially_supported, because the candidate is not fully supported.

- **Concept: Prompt‑controlled comparison**  
  Why needed: To fairly compare atomic vs holistic judges, the study matches inputs, output format, and detail level, controlling for prompt richness. Quick check: If one judge uses a longer prompt, could that alone explain performance differences? Yes, richer prompts may provide more guidance. The study addresses this by using multiple variants per family and ensuring similar input/JSON structure.

## Architecture Onboarding
The evaluation pipeline consists of five components: (1) Input loader reads a JSONL row containing `question`, `reference`, `candidate`; (2) Prompt selector injects these into the chosen judge template (atomic or holistic), producing system + user prompts; (3) LLM inference engine calls the specified model API with temperature 0 and a `max_tokens` limit; (4) Output parser validates the JSON and extracts the `verdict`; (5) Evaluator compares the verdict to the gold label and records accuracy. For atomic judges, the prompt requests intermediate lists (`atomic_claims`, `supported_claims`, etc.), but these are not used in accuracy calculation.

**Critical path**: Input → prompt → LLM generation → JSON parsing → label comparison. The judge template choice (atomic vs holistic) is the independent variable; any formatting or extraction error can break the process.

**Design tradeoffs**:
- Atomic judges produce 1.4–2.3× more tokens (claim enumeration), increasing cost and latency, while offering interpretability via per‑claim audit trails. They underperform on incompleteness detection for ASQA and QAMPARI.
- Holistic judges are token‑efficient and achieve equal or better accuracy on completeness‑heavy tasks, but lack the fine‑grained audit trail.
- The findings suggest that for benchmark‑style reference‑support classification, the holistic pattern is a competitive (often better) default, challenging the assumption that decomposition is inherently beneficial.

**Failure signatures**:
- Ignoring reference: Accuracy drops dramatically when the reference is degraded or removed (especially on ASQA). Monitor high flip rates under swapped references.
- Incompleteness blindness: Atomic judges often misclassify `partially_supported` as `supported`; watch for low partial‑class accuracy.
- Prompt instability: Small wording changes cause large accuracy swings; the study used three variants per family to detect this.
- Truncation: If LLM output is cut off before the final verdict (missing JSON fields), parsing fails. Ensure `max_tokens` is sufficiently high and check JSON completeness.

**First 3 experiments**:
1. Prompt variant sanity check: Run all six prompt templates (atomic v1‑v3, holistic v1‑v3) on a small balanced set (20 examples per dataset, 60 total). Verify JSON parses and that the accuracy pattern roughly matches the paper (holistic > atomic on ASQA, near tie on TruthfulQA).
2. Token accounting and budget test: Measure output token counts for both judge families on ASQA and QAMPARI to replicate the 1.4–2.3× gap. Then perform budget ablation: set `max_tokens` to 128, 256, 512 and run the full 200‑example set; plot accuracy vs. budget to observe the flat line for atomic.
3. Reference perturbation validation: Follow the grounding ablations: for each judge, test with reduced references (shorter paraphrases) and with no reference (empty string). Replicate the large accuracy drops on ASQA and relative stability on TruthfulQA.

## Open Questions the Paper Calls Out
- Does the holistic advantage persist for multi‑stage atomic pipelines (e.g., extract‑then‑verify) or with externally supplied claim decompositions? The paper only tested the self‑decomposing single‑prompt pattern.
- What is the causal mechanism behind the holistic judge's superior incompleteness detection? The study offers hypotheses (fragmentation, completeness‑instruction) but cannot isolate them.
- Do the findings generalize to non‑QA tasks (e.g., summarization, instruction following) or to open‑domain/RAG evaluation where references are retrieved documents?
- Is the ASQA label‑definition mismatch (benchmark penalizing omissions vs. human factual correctness) a systematic benchmark flaw or a valid stricter completeness standard?
- Can the holistic advantage be transferred to atomic judges via prompt engineering (e.g., adding explicit completeness instructions) without losing decomposition benefits?

## Limitations
- Exact source IDs and candidate constructions for the 200 examples per dataset are not public, hindering exact replication.
- Prompt variants v2/v3 are described but the primary mapping to the main table is unclear; one must run all variants to aggregate, as the authors did.
- The study covers three datasets and four model families; generalization to other domains or newer models is uncertain.
- Mechanistic explanations remain post‑hoc; fragmentation vs. completeness‑instruction effects are not experimentally disentangled.
- Token budget tests only go up to 512 tokens, leaving open whether larger budgets could close the atomic gap.

## Confidence
- **Main performance claim** (holistic ≥ atomic on ASQA/QAMPARI): High
- **Per‑class advantage** (partially_supported detection): High
- **Token‑efficiency claim**: Medium
- **Mechanistic explanation** (fragmentation/completeness): Medium
- **Reference‑sensitivity**: High

## Next Checks
1. Pre‑decomposition test: Run atomic judge with claims extracted by an external component to see if the partial‑support deficit persists; this isolates the effect of self‑decomposition fragmentation.
2. Completeness instruction ablation: Augment the atomic prompt with an explicit completeness query (e.g., “Assess overall coverage of the reference”) and compare to holistic. If the gap closes, completeness prompting is key.
3. Extended token budget: Increase atomic judge max‑tokens to 2048/4096 on ASQA and QAMPARI. A significant accuracy jump would indicate prior token limits were the bottleneck; a flat trend confirms true inefficiency.
