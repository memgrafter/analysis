# How RL Unlocks the Aha Moment in Geometric Interleaved Reasoning

## Quick Facts
- **arXiv ID:** 2603.01070  
- **Source URL:** https://arxiv.org/abs/2603.01070  
- **Reference count:** 40  
- **Primary result:** Faire achieves an average verification score of 45.37 (vs. <25 for GPT-5.2 and Gemini-2.5-Pro) and 74.82% answer accuracy on Faire‑Bench, surpassing SFT interleaved (62.48%).

## Executive Summary
Supervised fine‑tuning (SFT) on interleaved geometric reasoning data degrades performance because the model learns to imitate the surface alternation of text and diagrams without internalizing the causal dependency between diagram construction and logical deduction. To address this, the authors introduce **Faire**, a reinforcement learning framework that enforces *functional alignment* via a tri‑perspective verifier: geometric consistency (code executability), perceptual admissibility (visual clarity), and semantic alignment (reasoning–diagram consistency). On the Faire‑Bench corpus (7,989 K12 problems), Faire substantially outperforms strong baselines in both verification scores and answer accuracy. Ablations confirm that all three verifiers are essential, and analysis reveals a pronounced entropy shift in token distributions, marking an “Aha moment” where plotting becomes an internal scaffold rather than a superficial pattern.

## Method Summary
Faire trains a multimodal LLM to generate interleaved textual reasoning and GeoGebra code snippets. The training uses reinforcement learning (GRPO) with a reward that combines a sparse binary term for answer correctness and dense scores from three verifiers: **C<sub>geo</sub>** checks geometric validity via executable assertions in the GeoGebra kernel; **C<sub>perc</sub>** evaluates visual clarity of the rendered diagram using a vision‑language model; **C<sub>sem</sub>** ensures the diagram semantically matches the preceding reasoning by parsing code into a structured representation and comparing it to the text. The policy is optimized to maximize expected reward while staying close to a reference model via a KL penalty. Training data comes from the Faire‑Bench corpus, which contains correct interleaved solutions for K12 geometry problems.

## Key Results
- **Verification scores:** Faire average 45.37; GPT‑5.2 24.62; Gemini‑2.5‑Pro 19.86. Component scores: Parser 37.27, Code 60.39, Judge 38.44.
- **Accuracy:** Faire 74.82% vs. SFT interleaved 62.48% (text‑only SFT ~68%).
- **Ablation:** Removing any verifier degrades both accuracy and verification average, confirming the necessity of all three constraints.

## Why This Works (Mechanism)

**Mechanism 1: SFT induces distributional alignment, not functional alignment.**  
SFT optimizes token‑level likelihood, which decomposes into independent predictions of reasoning steps and plotting actions. This encourages the model to reproduce the surface format of interleaved data but does not enforce that the diagram provides useful information for subsequent deduction. Formally, SFT may fail to lower the conditional entropy \(H(Y|T,V)\) and can even increase it. Evidence: the abstract states SFT leads to degradation; Section 3.2 provides formal analysis; related work notes alignment challenges. If SFT did not degrade accuracy on this task, the mechanism would not apply.

**Mechanism 2: Tri‑perspective verification is necessary and complementary for functional alignment.**  
The three verifiers cover complementary aspects of a functional diagram: C<sub>geo</sub> ensures mathematical validity (executable code passes geometric assertions), C<sub>perc</sub> ensures the rendered diagram is visually interpretable (no clutter, proper contrast), and C<sub>sem</sub> ensures the diagram exactly instantiates the geometric intents expressed in the reasoning. Together they verify the edges \(T \rightarrow V\), the node \(V\), and the edge \(V \rightarrow Y\) of the causal graph. Evidence: abstract and Section 3.3 define the constraints; Table 4 shows that removing any verifier hurts performance. If a single verifier could match full‑set performance, the claim of necessity would be false.

**Mechanism 3: RL induces the “Aha moment” via reward‑driven entropy shift.**  
The GRPO objective maximizes expected reward, directly encouraging trajectories where diagrams are correct, executable, clear, and semantically aligned. Over training, the model’s token distribution shifts: entropy increases on drawing, numeric, and reasoning tokens, indicating active computation rather than template‑driven imitation. This entropy shift marks the “Aha moment” where plotting becomes an internal, functional scaffold. Evidence: abstract mentions the entropy shift; Section 5.3 (Figure 5) shows top entropy‑increased tokens; qualitative examples contrast SFT’s surface‑aligned diagrams with RL’s state‑consistent constructions. If RL failed to improve verification scores or trigger entropy shifts despite a correct reward, the claimed behavioral shift would not occur.

## Architecture Onboarding
**Component map:**  
Multimodal LLM → generates interleaved text + GeoGebra code → Renderer (GeoGebra sandbox) → diagram image → Three verifiers (VLM‑Judge, Parser‑Judge, GGB‑Verifier) → scores → Reward aggregator (sparse correctness + weighted verifier sum) → GRPO optimizer → policy update (with KL penalty to reference model).

**Critical path:**  
1. Problem input → model samples interleaved trajectory (text + code).  
2. Code is rendered to a diagram image.  
3. Three verifiers independently compute their scores.  
4. Reward combines answer correctness and verifier scores.  
5. GRPO computes advantages and updates policy.

**Design tradeoffs:**  
- Verifier design: Using a VLM for perceptual checks introduces bias and compute cost; simpler heuristics may be less robust.  
- Reward shaping: Sparse correctness provides strong signal; dense verifier scores guide intermediate steps. Balancing β is critical.  
- Scalability: Running three verifiers per sampled trajectory is expensive; requires parallelism and efficient rendering.  
- Generality vs specificity: Current verifiers are geometry‑specific; extending to other domains requires redesign, though the tri‑perspective principle may transfer.

**Failure signatures:**  
- High verifier scores but low answer accuracy → reward hacking (diagrams pass checks but reasoning ignores them).  
- No entropy shift → insufficient reward signal or optimization instability.  
- Category‑specific collapse (e.g., on conic sections) → gaps in verifier coverage.  
- Ablation sensitivity not observed → claimed necessity of verifiers is false.

**First 3 experiments:**  
1. Reproduce SFT degradation: Train SFT on interleaved split (4,643 samples) and evaluate on eval split (1,025). Expect accuracy ~62.5% vs. text‑only SFT ~68%.  
2. Validate verifier discrimination: Sample outputs from SFT and RL models; compute each verifier score separately. Show SFT may have decent image similarity but low semantic/formal scores, while RL improves across all three.  
3. Ablation of verifiers: Train RL agents with leave‑one‑out verifier sets (as in Table 4). Expect significant drops in both accuracy and verification average when any verifier is removed.

## Open Questions the Paper Calls Out

**Question 1:** Is reinforcement learning uniquely necessary to achieve functional alignment, or could alternative training approaches (e.g., contrastive learning, supervised constraints) produce similar gains?  
**Basis:** The authors state: "We posit that Reinforcement Learning (RL) is necessary to move beyond superficial distributional alignment toward functional alignment."  
**Why unresolved:** The paper only compares SFT and RL; other paradigms are unevaluated.  
**What evidence would resolve it:** Systematic comparison of RL with contrastive learning or auxiliary supervised losses on Faire‑Bench, measuring tri‑perspective verification scores and answer accuracy.

**Question 2:** Are the three verifier perspectives (geometric consistency, perceptual admissibility, semantic alignment) sufficient for all geometric reasoning tasks, or might more complex problems require additional constraints?  
**Basis:** The authors define the three as necessary and sufficient based on a causal graph, supported by an ablation that shows all three are needed, but validation is limited to planar K–12 geometry.  
**Why unresolved:** Sufficiency may not extend to richer geometry (e.g., solid geometry, transformations) where other failure modes could occur.  
**What evidence would resolve it:** Apply Faire to extended benchmarks (e.g., solid geometry, geometric transformations) and analyze whether passing all three verifiers still guarantees functional alignment; identify any recurring errors that escape detection.

**Question 3:** Does the Faire framework generalize to non‑geometric domains requiring interleaved reasoning with external tools (e.g., physics simulations, chemical structures)?  
**Basis:** The conclusion expresses hope that the work "encourages verifiable interleaved reasoning beyond geometry, and motivates stronger assertion synthesis with executable tools."  
**Why unresolved:** The tri‑perspective verifier is specifically designed for GeoGebra diagrams; other domains may need different notions of executability and perceptual clarity.  
**What evidence would resolve it:** Adapt Faire to a new domain by constructing analogous verifiers (e.g., simulation stability check, state interpretability, semantic alignment) and test whether RL improves over SFT on that domain’s interleaved reasoning tasks.

## Limitations
- Evaluation confined to K12 geometry using GeoGebra; broader applicability to other visual reasoning tasks is unknown.
- Perceptual verifier relies on a VLM whose biases may affect scoring; heavy RL training limits reproducibility.
- The “Aha moment” is inferred from entropy shifts, an indirect measure.

## Confidence
- **SFT degradation claim:** High (empirical and theoretical support).  
- **Tri‑perspective necessity claim:** Medium (ablations are strong but domain‑specific; perceptual scorer may not be optimal).  
- **RL‑induced aha claim:** High (consistent accuracy gains and entropy shifts across splits).

## Next Checks
- **Cross‑domain test:** Evaluate on an independent geometry dataset (e.g., Geometry3K) to assess generalization of the tri‑perspective reward.  
- **Verifier design ablation:** Replace the VLM perceptual judge with a simple heuristic (e.g., contrast measure) and compare final accuracy to quantify the VLM’s contribution.  
- **Mediation analysis:** At inference, intervene by preventing diagram generation; a large accuracy drop would confirm that diagrams serve as functional scaffolds.
