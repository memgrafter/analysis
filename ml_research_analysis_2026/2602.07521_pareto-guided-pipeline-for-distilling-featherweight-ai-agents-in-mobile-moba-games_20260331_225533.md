# Pareto-guided Pipeline for Distilling Featherweight AI Agents in Mobile MOBA Games

## Quick Facts
- **arXiv ID**: 2602.07521
- **Source URL**: https://arxiv.org/abs/2602.07521
- **Reference count**: 40
- **Primary result**: Achieves a 40.32% win rate against the teacher agent while reducing inference latency by 12.4× (to 0.436 ms/frame) and energy consumption by 15.6× (to 0.49 mAh/game).

## Executive Summary
Deploying large-scale MOBA AI agents on mobile devices is challenging due to severe latency and energy constraints that make standard models impractical. This paper introduces a Pareto-optimality guided distillation pipeline that first profiles a teacher agent to identify computational bottlenecks, then designs a lightweight student architecture using efficient MLPs and a max-fusion gate instead of complex encoders and LSTMs. A constrained architecture search approximates the Pareto frontier across performance and efficiency metrics. The resulting Featherweight Agent, validated on *Honor of Kings* 3v3, lies on the empirical Pareto frontier, drastically improving efficiency over both the teacher and standard compression techniques (e.g., pruning, quantization) while maintaining a competitive win rate.

## Method Summary
The pipeline consists of five stages: (1) **Profiling**: The teacher model is analyzed to pinpoint modules (encoder, LSTM) dominating FLOPs and parameters. (2) **Student Design**: A new architecture replaces the encoder and LSTM with parallel MLPs and introduces a triplet max-fusion gate for inter-hero coordination, with tunable hyperparameters (layer counts, dimensions). (3) **Constrained Search**: Candidates are sampled uniformly within 1–20% of teacher FLOPs. (4) **Distillation**: Each candidate is trained via knowledge distillation (KL divergence, temperature τ=4) on a replay buffer of 2M state-action transitions. (5) **Selection**: Models are evaluated on win rate and on-device metrics (latency, energy, memory, size); non-dominated points form the Pareto frontier, from which a final agent satisfying deployment thresholds (e.g., win rate >40%, latency <0.5 ms) is chosen.

## Key Results
- The Featherweight Agent achieves **40.32% win rate** against the teacher, with **12.4× lower latency** (0.436 ms/frame) and **15.6× lower energy** (0.49 mAh/game).
- It **significantly outperforms** standard compression methods (low-rank decomposition, pruning, quantization), which suffer far larger performance drops.
- Ablations confirm each design choice (MLP fusion, max-fusion gate, search constraints) contributes to the Pareto-optimal trade-off.

## Why This Works (Mechanism)
Profiling reveals the teacher’s encoder and LSTM consume ~83% of FLOPs and ~80% of parameters, yet are not strictly necessary for decision-making. Replacing them with parallel MLPs removes sequential dependencies, while a max-fusion gate enables cheap team-level coordination via max-pooling of public hero embeddings. This architectural simplification directly cuts dominant costs. Knowledge distillation then transfers the teacher’s policy to the student despite structural differences, preserving strategic performance. Finally, a constrained search across 1–20% teacher FLOPs systematically explores the multi-objective space, ensuring the selected model is non-dominated in win rate versus efficiency metrics.

## Foundational Learning
- **Knowledge Distillation (KD)**: Transfers the teacher’s policy by minimizing KL divergence between output distributions. Softened with temperature τ=4, it allows the student to mimic the teacher’s "dark knowledge" (relative action preferences). *Why needed*: The student’s architecture differs substantially from the teacher; KD bridges the gap without requiring identical structures. *Quick check*: What happens if τ is set too high (e.g., 10) or too low (e.g., 1)?
- **Pareto Optimality**: Defines multi-objective optimization where an agent is non-dominated if no other agent is at least as good in all metrics (win rate, latency, energy, memory, size). *Why needed*: Mobile deployment requires balancing competitive performance with tight resource budgets; Pareto optimality formally captures these trade-offs. *Quick check*: If Agent A has higher win rate but higher latency than Agent B, can A Pareto-dominate B? Why or why not?
- **Mobile Inference Constraints**: Real-time MOBA games demand per-frame latency <0.5 ms and per-game energy <0.5 mAh on typical mobile hardware (e.g., Snapdragon 8 Gen 3). *Why needed*: These constraints are absolute thresholds that invalidate models exceeding them, regardless of win rate. *Quick check*: Why might inference latency be more critical than model size for MOBA agents on mobile?

## Architecture Onboarding
- **Component map**: Feature Extraction Module (per-hero CNN/MLP) -> Feature Fusion Module (cross-modal & cross-temporal MLPs) -> Triplet Max-Fusion Gate (max-pool public embeddings across 3 heroes) -> Prediction Heads (hero-specific MLPs for hierarchical actions)
- **Critical path**: Input (13,758-dim hero vector) → parallel feature extraction → concatenation → MLP-based fusion → max-fusion across heroes → action-specific MLP heads → masked action selection.
- **Design tradeoffs**: 
  - *Model scale*: Larger student (+3.68% win rate) increases latency by 37.8%; smaller reduces latency by 12.8% but drops win rate 42.9%.
  - *Module choices*: Removing LSTM increases latency 32.6% with negligible win rate change; removing encoder increases latency 10.7× but improves win rate to 45.21%.
  - *Search budget*: FLOPs constrained to 1–20% of teacher; too narrow may miss optimal points, too broad yields non-mobile models.
- **Failure signatures**: 
  - Win rate <40% against teacher indicates insufficient KD transfer or architectural mismatch.
  - Latency reduction <5× suggests bottlenecks (e.g., LSTM) remain.
  - Pareto frontier stagnates (few non-dominated points) signals search space exhaustion.
  - Memory >160 MB or size >10 MB violates mobile constraints.
- **First 3 experiments**:
  1. **Bottleneck Profiling**: Run teacher on validation set, measure per-module FLOPs/params; confirm encoder+LSTM dominate.
  2. **Architecture Ablation**: Distill student variants with teacher modules reintroduced (add LSTM, add encoder); measure win rate and latency changes.
  3. **Pareto Search Validation**: Sample 20 architectures across FLOPs intervals, distill each, plot win rate vs. latency; verify final agent lies on frontier and dominates baselines.

## Open Questions the Paper Calls Out
- Can the Pareto-guided distillation pipeline generalize to diverse mobile game genres beyond MOBA?
- How might adaptive KD strategies (dynamic temperature, loss weighting) improve the performance-efficiency trade-off?
- To what extent can integrating fine-grained mobile hardware characteristics (e.g., NPU microarchitecture) push the Pareto frontier for specific devices?
- Is the triplet max-fusion gate optimal for inter-hero communication, or could lightweight attention yield better trade-offs?

## Limitations
- Teacher model specifics (transformer encoder, LSTM variant) are underscribed, risking replication errors.
- On-device measurement protocol (power tool, thermal state, frame sampling) is vague, potentially causing metric variance.
- Architecture search sampling distribution and candidate count are unclear, raising questions about frontier robustness.

## Confidence
- **Bottleneck profiling**: High – directly confirmed by Table 1.
- **MLP fusion & max-gate design**: Medium – supported by ablations but causality not fully isolated.
- **Pareto-guided search**: Medium – empirical frontier depends on search space and KD stability; needs broader validation.
- **Overall results**: High – reported with statistical tests, though generalizability across games is untested.

## Next Checks
1. Replicate teacher profiling: implement teacher, measure per-module FLOPs/params, verify encoder+LSTM consume >80% combined.
2. Ablate fusion components: create students with (a) LSTM instead of MLP, (b) no max-fusion gate, (c) dot-product attention; compare win rate and latency.
3. Test Pareto robustness: rerun search with larger candidate set (e.g., 1,000 samples) and alternative sampling; assess stability of nondominated points.
