# Scaling DoRA: High-Rank Adaptation via Factored Norms and Fused Kernels
## Quick Facts
- **arXiv ID**: 2603.22276
- **Source URL**: https://arxiv.org/abs/2603.22276
- **Reference count**: 30
- **Primary result**: 1.5–2.0× inference speedup and 1.5–1.9× gradient speedup versus Hugging Face PEFT’s DoRA implementation, with up to 7 GB lower peak VRAM.

## Executive Summary
DoRA (Weight-Decomposed Low-Rank Adaptation) improves parameter-efficient fine-tuning by recomposing frozen pretrained weights with a low-rank update and a learnable magnitude vector. However, computing per-row norms for high-rank adaptation requires materializing a large dense intermediate, leading to excessive memory consumption on single GPUs. This paper introduces two systems techniques to overcome this bottleneck: (1) a factored norm that algebraically decomposes the squared norm into base, cross, and Gram terms, reducing memory from O(d_out·d_in) to O(d_out·r + r²); (2) fused Triton kernels that collapse four sequential element-wise operations into a single memory-efficient pass, cutting memory traffic by ~4×. Evaluated on six 8–32B vision-language models across multiple NVIDIA GPUs, the approach yields 1.5–2.0× faster inference, 1.5–1.9× faster gradient computation, and up to 7 GB lower peak VRAM while preserving high numerical fidelity. Extensive microbenchmarks and training runs confirm these gains.

## Method Summary
The core challenge in high-rank DoRA is the memory cost of computing ∥W+sBA∥_row for every output row, where W is frozen, B and A are low-rank matrices (BA), and s is a scalar. The proposed factored norm expands the squared row-wise norm into three terms: base ∥W∥²_row, cross 2s⟨W,BA⟩_row, and BA norm s²∥BA∥²_row. The cross term is computed via a chunked matrix multiplication U = W Aᵀ (fp32 accumulation) and element-wise multiplication with B, while the BA norm uses the precomputed Gram matrix G = A Aᵀ. Chunking along d_in bounds working memory to O(d_out·r + r²).

The second optimization fuses the four-step composition Δ = (g−1)⊙base + g⊙s⊙lora into a single Triton kernel. The kernel reads base, lora, and g once, writes Δ, and merges backward gradient computation for training. This reduces memory passes from ~12 to ~4 and leverages higher bandwidth utilization (∼50% of peak HBM versus ∼20% for eager). The fused kernel also uses a stable formulation that avoids catastrophic cancellation when g≈1, a universal property of trained DoRA models.

Integration with Hugging Face PEFT is achieved through a dispatch layer that selects the optimal path (fused backward for training, fused forward for inference, or an eager fallback) based on tensor shapes and hardware thresholds.

## Why This Works (Mechanism)
**Factored norm**  
The dense product BA = B @ A is never materialized. Instead, row-wise inner products ⟨W,BA⟩_row are computed as (B ⊙ (W Aᵀ)) · 1, where W Aᵀ is accumulated in chunks. The BA norm ∥BA∥²_row is derived from the Gram matrix G = A Aᵀ and the row-wise sum of B⊙(G Bᵀ). These intermediates scale with O(d_out·r + r²), eliminating the O(d_out·d_in) memory spike. This works because W is frozen (safe to chunk), r ≪ d_in, and fp32 accumulation prevents overflow.

**Fused Triton kernels**  
Standard PyTorch executes four separate element-wise kernels, each reading large tensors from HBM. Fusing them into one kernel reduces memory traffic by ~4× and amortizes launch latency. The operation is memory-bandwidth-bound for large activation shapes; thus reducing traffic yields near-linear speedup. The kernel also fuses backward pass computation, further cutting memory for gradient computation.

**Stable compose form**  
Trained DoRA models keep g = m/∥W+sBA∥_row very close to 1 (mean ≈1.0, std ≈0.0015). The naive expression g⊙(s·lora+base)−base subtracts two nearly equal numbers, causing underflow to zero in bf16/fp16. The stable form (g−1)⊙base + g⊙s⊙lora keeps the small correction explicit and computes s·lora first, then scales, preserving precision especially when intermediates are kept in fp32. This is critical because the correction term is often O(1e−3) relative to base values.

## Architecture Onboarding
**Component map**  
dora.py → norm.py (factored norm) → dispatch.py → kernels.py (fused forward/backward) or eager fallback

**Critical path** (training forward)  
1. `_compute_norm` computes wnorm via factored method (chunked matmuls).  
2. Compute g = m / max(wnorm, eps) in fp32.  
3. `_compose_with_dispatch` selects fused backward kernel (if shapes large).  
4. Fused kernel reads base, lora, g; writes inner = s*lora + base (saved); delta = (g−1)*base + g*inner; returns base+delta.  
Backward fused kernel recomputes d_lora = g*s*d_out and d_base = (g−1)*d_out; dmag gradient via separate reduction.

**Design tradeoffs**  
- Factored norm trades extra compute (multiple chunked matmuls) for memory; gains increase with rank and d_in.  
- Fused kernel uses more registers; autotuning (`ROWS_PER_PROGRAM`) balances occupancy across GPU architectures.  
- Dispatch thresholds (e.g., d_out≥2048 and batch·seq·d_out≥2048·6144) are empirical; may need retuning for future hardware.  
- fp32 accumulation in norm increases transient memory; must use `torch.no_grad()` and disable autocast.

**Failure signatures**  
- OOM during forward: factored norm not active or chunk budget too small; check `PEFT_DORA_NORM_CHUNK_MB`.  
- Low speedup on small activations: fused dispatched incorrectly; lower thresholds or set `PEFT_DORA_FUSED_BACKWARD=0`.  
- Logit drift (cosine <0.9999): naive compose or fused magnitude division; revert to stable form and ensure division outside Triton.  
- NaNs/INF in g: norm returned zero; check epsilon and chunk alignment; ensure `max(wnorm, eps)`.  
- torch.compile graph breaks: dropout enabled; set dropout=0 or adjust dispatch.
