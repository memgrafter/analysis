# WESR: Scaling and Evaluating Word-level Event-Speech Recognition

## Quick Facts
- **arXiv ID:** 2601.04508
- **Source URL:** https://arxiv.org/abs/2601.04508
- **Reference count:** 31
- **Primary result:** Introduces WESR-Qwen, achieving Macro F1 38.0% on WESR-Bench and outperforming commercial APIs like Gemini-3-Pro by significant margins, with only a modest 1.2–1.4% absolute WER increase.

## Executive Summary
This paper introduces Word-level Event-Speech Recognition (WESR), a novel task that integrates non-verbal vocal events (e.g., laughing, crying) into speech transcriptions at the word level. It presents WESR-Bench, a 927-utterance expert-annotated test set with a position-aware evaluation protocol that separates ASR errors from event detection failures. To train models, the authors construct WESR-Train, a 1,767-hour bilingual corpus automatically annotated with Gemini. Fine-tuning models like Whisper and Qwen3-Omni on this data yields WESR-Qwen, which significantly outperforms open-source and commercial baselines, particularly on continuous events, while preserving ASR quality.

## Method Summary
The authors define WESR as generating text transcripts interleaved with discrete (`[event]`) and continuous (`<event>...</event>`) tags aligned to word positions. They build WESR-Train (1,767 hours) by aggregating and denoising audio from multiple sources (e.g., NonverbalTTS, web audio), then annotating with Gemini 2.5-Pro using a detailed prompt. For evaluation, WESR-Bench is created via expert annotation. Models are fine-tuned from pretrained audio-language backbones (Whisper, Kimi-Audio, Qwen3-Omni) by adding event tags as special tokens and training on the interleaved sequence-to-sequence task. A position-aware evaluation protocol first aligns hypothesis and reference transcripts while preserving tags, then maps events to word/inter-word positions to compute precision, recall, and F1 per tag, decoupling event errors from ASR mistakes.

## Key Results
- WESR-Qwen achieves a macro F1 of 38.0% on WESR-Bench, outperforming Gemini-3-Pro (32.3%) and other baselines.
- On continuous events, WESR-Qwen reaches F1 0.641 vs. 0.543 for Gemini-3-Pro.
- Fine-tuning incurs only a small ASR degradation: +1.2–1.4% absolute WER on Common Voice.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Explicit word-level tagging of discrete and continuous events enables models to learn fine-grained associations between speech content and paralinguistic cues, capturing how event placement alters meaning.
- **Mechanism:** By interleaving event tags directly into the transcription at word or span boundaries, the model is trained to jointly predict lexical content and event occurrence with temporal precision. This contrasts with utterance-level classification or frame-level detection that lose alignment with words.
- **Evidence anchors:** The abstract emphasizes "precise localization"; Section 3 defines point and span tags and shows meaning changes with position; Section 4.3 reports 29.13% of test utterances contain multiple tags, indicating complex interactions.

### Mechanism 2
- **Claim:** Large-scale training on a diverse, weakly supervised corpus (WESR-Train) provides the coverage and variability needed for robust event-speech modeling.
- **Mechanism:** The corpus aggregates 1,767 hours from multiple sources and uses Gemini for automatic annotation, followed by human review on the benchmark. This scale exposes the model to many event types in varied settings, allowing fine-tuning to adapt pretrained models.
- **Evidence anchors:** Section 5.1 describes the 1,767-hour bilingual construction; Section 5.2 reports consistent Macro F1 improvements (37.7–38.0%) across three backbones; Section 5.3 shows WESR-Qwen outperforms few-shot models by large margins.

### Mechanism 3
- **Claim:** The position-aware evaluation protocol decouples ASR errors from event detection failures, providing a reliable signal for targeted model improvement.
- **Mechanism:** The protocol first aligns hypothesis and reference transcripts while preserving event tags, then maps events to unified word/inter-word positions. This ensures event metrics are computed only when surrounding lexical content matches.
- **Evidence anchors:** Section 4.4 details the three-step evaluation; Section 5.4 demonstrates higher continuous-event F1 partly due to partial credit for span overlap; Section 5.5 shows ASR quality is largely preserved.

## Foundational Learning
- **Concept: Automatic Speech Recognition (ASR)**
  - **Why needed:** WESR extends ASR by adding non-verbal event tags; understanding baseline ASR metrics (WER) and architectures is essential to grasp how event tags are integrated and how ASR performance is preserved.
  - **Quick check:** What does a WER of 10% indicate about an ASR system’s output, and how might adding non-verbal tags affect this metric?
- **Concept: Vocal Event Detection (VED)**
  - **Why needed:** VED focuses on classifying non-speech sounds; WESR combines VED with ASR at the word level. Knowing traditional VED highlights the novelty of fine-grained alignment.
  - **Quick check:** How does frame-level event detection differ from word-level event tagging in terms of output representation and application?
- **Concept: Sequence-to-Sequence Evaluation with Spans**
  - **Why needed:** WESR’s evaluation requires comparing sequences containing both words and event spans. Understanding span-based metrics and alignment algorithms is key to interpreting results.
  - **Quick check:** Why is it insufficient to use standard sequence accuracy (e.g., exact match) for evaluating continuous event spans, and what does the position-aware metric instead compute?

## Architecture Onboarding
- **Component map:** Data pipeline (denoising, filtering, retrieval, annotation) -> Model backbone (pretrained audio-language model with added event tokens) -> Fine-tuning (supervised training on WESR-Train) -> Evaluation (tagged transcription generation, event-preserving alignment, position mapping, F1 calculation).
- **Critical path:** High-quality annotations (WESR-Bench) -> large-scale training data (WESR-Train) -> backbone fine-tuning -> position-aware evaluation -> iterative per-category performance analysis.
- **Design tradeoffs:**
  - Annotation cost vs. scale: Using Gemini reduces cost but risks noise; human review on the benchmark ensures quality but is expensive.
  - Tag granularity: 21 categories balance expressiveness and annotatability; merging categories could improve robustness but lose nuance.
  - Discrete vs. continuous tags: Continuous spans allow partial credit but require accurate boundaries; discrete tags need exact position matching.
  - ASR vs. event performance: Adding event tags may slightly harm ASR; tradeoff controlled by training data mix and loss weighting.
- **Failure signatures:**
  - Very low F1 on continuous events (<0.2) -> model fails to learn span boundaries.
  - Large WER increase (>5% absolute) on clean test sets -> event training interferes with ASR.
  - High variance across categories -> dataset imbalance or ambiguous tag definitions.
  - Alignment failures in evaluation (e.g., many unmatched words) -> ASR errors too severe, possibly due to poor audio quality or domain mismatch.
- **First 3 experiments:**
  1. Baseline replication: Fine-tune Whisper-large-v3 on WESR-Train and evaluate on WESR-Bench; expect Macro F1 ~37.7% and WER increase ~1.4% on Common Voice.
  2. Ablation - training data source: Compare performance when using only web-collected Gemini-annotated data vs. including other datasets to measure contribution of diversity.
  3. Per-category error analysis: Compute F1 for each tag; identify low-performing categories (e.g., `<panting>`, `[breathing]`) and investigate whether they lack training examples or have ambiguous acoustic cues.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can the WESR approach generalize to languages beyond English and Chinese, particularly those with different morphological structures or lower resource availability?
- **Basis in paper:** "Language Coverage: Our system is currently verified only for English and Chinese. While the underlying methodology is language-agnostic, its generalization capabilities to languages with different morphological structures or lower resource availability remain unverified."
- **Why unresolved:** The paper only evaluates on English and Chinese; no evidence for other languages.
- **What evidence would resolve it:** Collect and annotate WESR-Bench style datasets for typologically diverse languages and evaluate existing WESR models on them to measure cross-lingual transfer performance.

### Open Question 2
- **Question:** How can we construct high-quality WESR training data without relying on expensive commercial APIs like Gemini or extensive expert annotation?
- **Basis in paper:** "Resource Intensity: The construction of our high-quality dataset relies on the commercial Gemini API and expert annotation. While this ensures data quality, it presents a trade-off in terms of cost-efficiency and scalability."
- **Why unresolved:** The current pipeline is expensive; no cheaper alternatives proposed or evaluated.
- **What evidence would resolve it:** Develop and compare alternative data construction pipelines (e.g., self-training with model pseudo-labels, synthetic data generation) on both cost and resulting model performance.

### Open Question 3
- **Question:** What architectural modifications to existing ASR models would most effectively improve continuous event detection and boundary prediction?
- **Basis in paper:** Continuous events achieve significantly lower performance than discrete events despite fine-tuning; the paper notes they are "a greater challenge" requiring "accurate span boundaries."
- **Why unresolved:** The paper fine-tunes off-the-shelf models without architectural changes; the relative weakness on continuous events persists.
- **What evidence would resolve it:** Systematically modify architectures (e.g., adding boundary detection heads) and measure incremental gains on continuous event F1, particularly span overlap metrics.

### Open Question 4
- **Question:** How can we improve detection performance for low-energy, subtle acoustic events like breathing and sighing?
- **Basis in paper:** Results show extremely poor performance on `[breathing]` (F1 0.023) and consistent challenges with "subtle, low-energy acoustic features" across all models.
- **Why unresolved:** No specific analysis or targeted solutions for these difficult categories are provided.
- **What evidence would resolve it:** Analyze failure cases for subtle events, develop focused data augmentation, and measure per-category F1 improvements specifically on breathing/sigh tags.

### Open Question 5
- **Question:** How does the quality of automatically generated training annotations (using Gemini) affect the performance ceiling of WESR models, and can semi-supervised or human-in-the-loop approaches improve the training set quality?
- **Basis in paper:** The training corpus includes 1,299 hours automatically annotated with Gemini, while only 473 hours come from manually annotated datasets; the test set is expert-annotated.
- **Why unresolved:** No analysis of annotation quality or experiments controlling for training data noise.
- **What evidence would resolve it:** Estimate label noise in the Gemini-annotated portion, correlate noise levels with model errors, and train models on subsets of higher-quality manual annotations vs. automatic to isolate the impact of annotation quality.

## Limitations
- The core assumption that event position consistently alters meaning across diverse speakers/contexts is not validated beyond provided examples.
- Reliance on Gemini for 1,767h of annotations introduces unknown systematic noise that could propagate to fine-tuned models.
- The alignment protocol’s robustness to severe ASR errors (e.g., large deletions within event spans) is theoretically a break condition but not stress-tested.

## Confidence
- **Mechanism 1 (Fine-grained tagging):** Medium. Evidence shows implementation and some multi-tag cases, but the causal link between word-level alignment and improved semantic capture is inferred, not directly measured.
- **Mechanism 2 (Large-scale training):** Medium. Strong correlation between training scale and performance, but confidence is limited by unquantified noise in the Gemini-annotated corpus.
- **Mechanism 3 (Position-aware evaluation):** High. The protocol is precisely specified, logically sound, and empirically separates ASR/event errors as intended.

## Next Checks
1. **Alignment Stress Test:** Run the evaluation protocol on WESR-Bench with synthetically corrupted ASR output (e.g., word deletion rates >30% within event spans). Measure failure rate of the alignment algorithm and consequent F1 instability.
2. **Human Label Consistency Study:** Have expert annotators re-label a random subset (n≥100) of WESR-Bench for inter-annotator agreement on event type and span boundaries. Compare agreement to the assumed quality of the original benchmark.
3. **Cross-Corpus Zero-Shot Test:** Evaluate WESR-Qwen on a held-out, independently annotated corpus like NVSpeech-170k without fine-tuning. A significant drop in Macro F1 would indicate dataset-specific biases in WESR-Train.
