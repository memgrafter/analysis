# Wireless communication empowers online scheduling of partially-observable transportation multi-robot systems in a smart factory

## Quick Facts
- **arXiv ID:** 2603.23967  
- **Source URL:** https://arxiv.org/abs/2603.23967  
- **Reference count:** 37  
- **Primary result:** The proposed communication‑enabled framework reduces makespan by up to 54.42% compared to local reasoning baselines, with an optimal communication interval D≈25 yielding a 17.27% improvement for 60 AGVs under limited channel resources.

## Executive Summary
The paper tackles the challenge of online collision‑free and congestion‑free routing for automated guided vehicles (AGVs) in smart factories under partial observability due to limited sensor ranges. Decentralized decision‑making without communication leads to inefficiencies. The proposed solution tightly integrates wireless machine‑to‑machine (M2M) networking with scheduling: AGVs periodically exchange intention information (planned routes, current states) via a retransmission‑free multi‑link transmission scheme to a central edge server. The server performs multi‑robot task assignment using simulated annealing and broadcasts a global spatiotemporal congestion map. Each AGV then executes distributed route planning with a congestion‑aware A* algorithm, merging the global and local maps to produce globally informed paths. Under high AGV loads (>30) and even with a single channel, the scheme significantly reduces makespan, demonstrating the necessity of task‑oriented communication‑computation co‑design.

## Method Summary
The framework comprises a centralized edge server and distributed AGVs. The edge server receives uplink transmissions containing each AGV’s current location and planned route every D time slots. From these, it constructs a global congestion map predicting future occupancy and runs a simulated annealing‑based multi‑robot task allocation (MRTA) to assign tasks. It then broadcasts the global map and task routes to all AGVs. Each AGV merges the global map with its locally sensed map and uses a congestion‑aware A* search over spatiotemporal states (node, time) to plan paths that avoid predicted congestion (penalizing nodes with occupancy ≥ κ*). AGVs execute their plans and apply simple right‑of‑way rules for imminent collisions. If communication fails, they fall back to local reasoning using the last received global map and current local observations. The wireless uplink uses a contention‑based multi‑link protocol: each transmitting AGV randomly selects S out of C orthogonal channels and sends without retransmission; success requires at least one collision‑free channel.

## Key Results
- Makespan reduction up to 54.42% compared to local reasoning baselines, even with high AGV loads (K>30) and limited channels (C=S=1).
- With 60 AGVs, an optimal communication interval of D≈25 yields a 17.27% improvement over local reasoning, highlighting the trade‑off between information freshness and cyber‑collision probability.
- Multi‑link transmission (S>1) enhances reliability and scheduling performance at low AGV‑to‑channel ratios (K/C), but its advantage diminishes under high contention, where single‑link (S=1) becomes preferable.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Exchanging AGVs’ intention information (planned routes, current states) via wireless M2M communication supplements each AGV’s partial local observation, enabling globally informed route adjustments.
- **Mechanism:** AGVs periodically transmit their navigation route Pₖ and current location lₖ to a central edge server. The server fuses this data to construct a global spatiotemporal congestion map M_global and broadcasts it. Each AGV merges M_global with its locally observed map M_local,ₖ to form an enhanced observation that approximates the global state.
- **Break condition:** If the communication interval D is too large, M_global becomes stale; if packet loss is too high, the enhanced observation diverges from the true global state, reintroducing partial observability.

### Mechanism 2
- **Claim:** A congestion‑aware spatiotemporal A* algorithm, guided by the merged congestion map, plans collision‑free and congestion‑free routes by penalizing node‑time pairs with predicted occupancy ≥ κ*.
- **Mechanism:** The search space expands from physical nodes v to state tuples (v, t). The path cost function ϕ(n′) = g(n′) + h(n′) + c(n′) adds a congestion penalty c(n′) when M_merged(v′, t′) ≥ κ*. This steers the search away from predicted high‑density areas.
- **Break condition:** If M_global is inaccurate due to outdated routes or communication loss, the penalty may misdirect the search, creating inefficient paths or new congestion points.

### Mechanism 3
- **Claim:** A retransmission‑free, contention‑based multi‑link transmission scheme provides a suitable trade‑off between reliability and timeliness for M2M scheduling traffic, exploiting frequency diversity to mitigate cyber collisions without retransmission delays.
- **Mechanism:** Each AGV randomly selects S out of C orthogonal channels and transmits the same packet simultaneously on all S. Success requires at least one collision‑free copy. The success probability and throughput are derived from the inclusion‑exclusion principle, balancing S, C, AGV count K, and transmission probability Pₜ = 1/D.
- **Break condition:** Under very high AGV‑to‑channel ratios (K/C large), the success probability decays faster with larger S, making single‑link (S=1) superior; the scheme fails if P_success approaches zero, leading to complete loss of shared state.

## Architecture Onboarding
### Component map
Edge Server -> Access Points -> AGVs

### Critical path
1. Task arrival → Edge server runs SA‑MRTA → Generates task routes Rₖ.  
2. AGVs periodically report Pₜₖ, lₜₖ → Access Points → Edge server.  
3. Edge server constructs M_global from all Pₜₖ → Broadcasts M_global and Rₖ.  
4. Each AGV merges M_global with local M_local,ₖ → Runs congestion‑aware A* (Alg. 2) to generate new Pₖ.  
5. AGV executes planned actions, applying right‑of‑way rules for imminent collisions.  
6. If communication fails (no new M_global), AGV reverts to local reasoning using last M_global and current local sensing.

### Design tradeoffs
- **Communication interval D:** Small D → fresh data but high cyber collision probability; large D → low collision but stale M_global. Optimal D* (≈25 for K=60, C=S=1) balances these.
- **Selected channels S:** Multi‑link (S>1) improves reliability at low AGV‑to‑channel ratio K/C; at high K/C, contention penalty makes S=1 better.
- **Multi‑link vs. Reservation:** Under high K/C, reservation‑based MACs (not implemented) might be needed instead of contention‑based multi‑link.

### Failure signatures
- **Communication failure:** Packets lost due to cyber collisions (high K, low C, small D). Symptoms: AGV receives outdated or no M_global → performance degrades toward local reasoning baseline.
- **Algorithmic failure:** M_global inaccurate (e.g., uncommunicated route changes) → A* misdirected → post‑replanning congestion/collisions.
- **Safety fallback:** When M_global missing, AGV falls back to M_local,ₖ + last M_global + right‑of‑way rules. Prevents physical collisions but may cause waiting.

## Limitations
- Task due dates generation rule unspecified, affecting scheduling constraints and tardiness evaluation.
- Local spatiotemporal map construction algorithm (M_local,ₖ) unclear, impacting fallback behavior accuracy.
- Simulated annealing parameters (initial temperature, LNS removal size) and the congestion penalty value P_congestion are not provided, hindering full reproducibility.
- Production robot scheduling algorithm that generates task release streams is not described, making dynamic task arrival generation approximate.
