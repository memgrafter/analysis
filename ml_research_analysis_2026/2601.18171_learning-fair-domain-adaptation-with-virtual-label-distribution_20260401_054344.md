# Learning Fair Domain Adaptation with Virtual Label Distribution

## Quick Facts
- arXiv ID: 2601.18171
- Source URL: https://arxiv.org/abs/2601.18171
- Reference count: 0
- Primary result: VILL improves worst-case category fairness in UDA; e.g., CDAN+VILL on OfficeHome raises Worst-5 accuracy from 20.3% to 26.8% while keeping global accuracy ~68%.

## Executive Summary
Unsupervised Domain Adaptation (UDA) often suffers from poor category fairness, where a few classes significantly underperform relative to the average. This paper introduces Virtual Label-distribution-aware Learning (VILL), a plug-and-play framework that addresses this by dynamically adjusting the learning focus. VILL computes a virtual label distribution from model pseudo-labels on the target domain at each epoch, then uses it to (i) re-weight source samples, giving more importance to underrepresented classes, and (ii) apply a KL-divergence-based re-balancing loss on target predictions, nudging the decision boundary toward fairness. Integrating VILL into four UDA baselines (CDAN, MDD, ATDOC, PDA) on OfficeHome and Office datasets yields consistent gains in worst-N accuracy (e.g., +6.5% Worst-5 on OfficeHome for CDAN) without degrading global accuracy. The approach offers a simple yet effective mechanism to mitigate class-level bias in domain adaptation.

## Method Summary
VILL augments any existing UDA method with two complementary objectives. At the start of each training epoch, the current model generates pseudo-labels for all unlabeled target samples. From these, a virtual label distribution \(v\) (per-class frequencies) is obtained and scaled to \(E_i = (N_i/N_t) \times C\), where \(C\) is the number of classes. A weight vector \(\omega\) is then computed as \(\omega_i = (1 + \alpha \exp(-E_i)) / \sum_k (1 + \alpha \exp(-E_k))\) with a fixed \(\alpha=5.0\). During training, source samples are fed through the base model, and a weighted cross-entropy loss \(L_{RW}\) is applied using \(\omega\) as class weights. For target samples, besides the base method’s domain alignment loss \(L_{DA}\), VILL adds a re-balancing loss \(L_{RB} = D_{KL}(p \| \omega)\), where \(p\) is the mean softmax prediction over the batch. The total loss is \(L = L_{RW} + \gamma L_{DA} + \beta L_{RB}\) with \(\beta=0.05\) and \(\gamma\) inherited from the baseline. The module operates plug-and-play and is trained for the standard number of epochs (usually 100), updating \(\omega\) every epoch.

## Key Results
- VILL consistently improves worst-case category fairness across four UDA baselines (CDAN, MDD, ATDOC, PDA) on OfficeHome and Office datasets.
- On OfficeHome, CDAN+VILL increases average Worst-5 accuracy from 20.3% to 26.8% and Worst-10 accuracy similarly, while global accuracy remains around 68.0% (no drop compared to CDAN alone).
- The gains demonstrate that VILL enhances performance on the hardest classes without sacrificing overall accuracy, addressing a key limitation of standard UDA methods.

## Why This Works (Mechanism)
VILL improves category fairness through a two-fold mechanism. First, by deriving \(\omega\) from the (noisy) pseudo-label distribution on the target, it realistically captures which classes are currently under‑represented according to the model’s belief. Updating \(\omega\) each epoch allows it to track the evolving classifier. Second, re‑weighting the source loss magnifies the gradient signal for underrepresented classes, forcing the model to learn features for those classes more effectively. Meanwhile, the KL divergence loss on target predictions directly pushes the model’s target predictions toward the balanced distribution \(\omega\), correcting decision‑boundary bias that would otherwise favor majority classes. The combination ensures that both the source training and target adaptation are guided by a dynamically balanced objective, mitigating the typical long‑tail performance drop seen in UDA. The plug‑and‑play design ensures compatibility with a wide range of alignment‑based UDA methods.

## Foundational Learning
Key concepts underlying VILL:

- **Unsupervised Domain Adaptation (UDA)**: Learning to transfer knowledge from a labeled source domain to an unlabeled target domain. Needed because target labels are unavailable; VILL builds on standard UDA frameworks.
  - *Quick check*: What loss would you use if you had no target labels? (Answer: Only source supervised loss plus some domain alignment.)
- **Category Fairness**: Minimizing performance disparity across classes, especially improving worst‑case accuracy. VILL targets this by balancing learning.
  - *Quick check*: How is worst‑N accuracy computed? (Answer: Sort classes by accuracy, average the lowest N.)
- **Pseudo‑labeling**: Generating provisional target labels from model predictions. VILL uses these to estimate class distribution.
  - *Quick check*: Why not use true target labels? Because they are unavailable; pseudo‑labels are the only signal.
- **Re‑weighting**: Adjusting sample loss contribution via class weights. In VILL, source loss is re‑weighted by \(\omega\).
  - *Quick check*: What effect does up‑weighting a class have on its learning? (Answer: Increases gradient contribution, potentially improving its classifier.)
- **KL‑divergence loss**: Measures discrepancy between two distributions. VILL uses \(D_{KL}(p \| \omega)\) to align target predictions with \(\omega\).
  - *Quick check*: Why KL and not reverse KL? (Answer: The paper uses forward KL to encourage predictions to match \(\omega\); reverse would have different properties.)
- **Plug‑and‑play module**: A self‑contained component that can be added to existing methods without altering their core architecture. VILL exemplifies this design.
  - *Quick check*: What must be preserved for a module to be plug‑and‑play? (Answer: It should not interfere with the base method’s forward/backward flow, only augment the loss.)

## Architecture Onboarding

**Component Map**  
Start epoch:  
- Compute pseudo-labels for all target samples using current model.  
- Compute virtual label distribution v (class counts) → scaled E_i → ω_i = (1+α exp(-E_i))/Σ(1+α exp(-E_k))  

During training per batch:  
Source batch:  
features_s = f(x_s), preds_s = g(features_s)  
L_RW = weighted CE(preds_s, y_s; weight=ω)  
Target batch:  
features_t = f(x_t), preds_t = g(features_t)  
L_DA = base domain alignment loss  
p = mean(softmax(preds_t))  
L_RB = KL(p || ω)  
Total loss L = L_RW + γ * L_DA + β * L_RB  

**Critical Path**  
1. At epoch start, pseudo-label generation must precede weight computation.  
2. Both source re‑weighting and target KL loss must use the same \(\omega\).  
3. The total loss combines VILL’s terms with the base method’s alignment term. Missing any step breaks the fairness objective.  

**Design Tradeoffs**  
- *Dynamic vs static ω*: Update per epoch provides adaptability but adds computation; a static ω would not track model progress.  
- *Source re‑weighting only on source*: avoids noisy target labels; but target KL loss still influences domain adaptation.  
- *Hyperparameters α and β*: Control intensity of re‑weighting and re‑balancing; too high may destabilize training, too low may be ineffective. Defaults (α=5, β=0.05) work across tasks but may need tuning for extreme shifts.  
- *Computational cost*: Extra forward pass over full target set each epoch (to get pseudo‑labels) increases runtime modestly.  

**Failure Signatures**  
- ω collapses to near‑zero weights for many classes (check distribution entropy).  
- Training loss spikes or diverges, especially after ω updates.  
- Worst‑N accuracy does not improve or global accuracy drops significantly.  
- The KL loss becomes dominant or negligible relative to other terms.  
- Pseudo‑label noise causes oscillations in ω over epochs.  

**First Three Experiments**  
1. **Baseline replication**: Reproduce a base UDA method (e.g., CDAN) on OfficeHome to confirm global accuracy (~68%) and worst‑5 accuracy (~20.3%).  
2. **VILL integration**: Add VILL to the baseline, using epoch‑wise ω computation, weighted source loss, and KL loss with β=0.05. Train with identical hyperparameters.  
3. **Evaluation and comparison**: Compute per‑class accuracy on target test set, derive worst‑5 and worst‑10 metrics, and compare against baseline. Ensure global accuracy remains stable.  

## Open Questions the Paper Calls Out
The paper raises several unresolved questions:

1. **Generalization to non‑classification UDA tasks**: Does VILL improve category fairness in segmentation or detection, where predictions are spatially distributed? (Potential impact: adapt to pixel‑level or object‑level shifts.)  
2. **Sensitivity to pseudo‑label quality**: How does noise in early pseudo‑labels affect the virtual label distribution and ultimately fairness? (No error propagation analysis.)  
3. **Hyperparameter universality**: Are α and β stable across diverse domain shifts, or do they require task‑specific tuning? (Defaults used without sensitivity study.)  
4. **Source‑domain re‑balancing**: Could applying the KL loss to the source (with true labels) also improve fairness without harming accuracy? (Currently restricted to target.)  
5. **Fairness vs group fairness**: How does worst‑N accuracy correlate with established group fairness metrics (e.g., demographic parity) when classes align with sensitive attributes? (Ethical implications.)  

## Limitations
- **Unknown baseline details**: Lack of official code and exact hyperparameters (learning rates, γ values) hinders faithful replication of reported numbers.  
- **Pseudo‑label protocol ambiguity**: The paper does not specify whether hard argmax or temperature‑scaled softmax is used, nor whether confidence filtering is applied, making exact ω computation unclear.  
- **Reliance on pseudo‑label quality**: Early‑training noise in pseudo‑labels could skew ω and destabilize training, possibly undermining the fairness gains.  

## Confidence
- Consistent worst-N improvement: **Medium** (results from paper but not independently verified).  
- Well‑specified mechanism: **High** (mathematical formulation is explicit).  
- Global accuracy maintenance: **Low‑Medium** (depends on baseline replication; blocked by unknowns).
