# Not All Pretraining are Created Equal: Threshold Tuning and Class Weighting for Imbalanced Polarization Tasks in Low-Resource Settings

## Quick Facts
- **arXiv ID:** 2603.23534  
- **Source URL:** https://arxiv.org/abs/2603.23534  
- **Reference count:** 8  
- **Primary result:** Best macro-F1 0.8032 on English binary detection validation; per-label threshold tuning yields gains exceeding 20 points on multi-label tasks.

## Executive Summary
This paper addresses polarization detection in low-resource languages (English and Swahili) under severe class imbalance across three hierarchical subtasks: binary detection, multi-label target classification, and multi-label manifestation identification. The core method combines Transformer models with class-weighted loss functions and iterative stratified splitting for multi-label data, followed by a two-stage per-label threshold tuning procedure to optimize macro-F1. Key findings indicate that general multilingual models outperform African language-specialized ones by 10–15 points, while naive multilingual training causes negative transfer. Error analysis highlights persistent failures on implicit polarization, code-switching, and distinguishing heated political discourse from genuine polarization.

## Method Summary
Preprocessing demojizes emojis, removes URLs/user mentions/hashtag symbols (retaining text), lowercases, and normalizes whitespace, truncating/padding to 128 tokens. For binary classification (Subtask 1), stratified 80/20 splits are used with `CrossEntropyLoss` and class weights (`compute_class_weight='balanced'`). For multi-label subtasks (2 and 3), iterative stratified splitting preserves multi-label distributions, and `BCEWithLogitsLoss` uses per-label positive class weights `w_pos,i = n_neg,i / n_pos,i`. Six Transformer models are fine-tuned (e.g., mDeBERTa-v3-base). After training, a two-stage threshold tuner searches per-label thresholds: first a coarse global optimum from {0.20,0.25,…,0.80}, then fine per-label search within ±0.15 of that global value in 0.01 increments while holding other thresholds fixed, maximizing validation macro-F1.

## Key Results
- mDeBERTa-v3-base achieves 0.8032 macro-F1 on English binary detection validation.
- Threshold tuning provides gains exceeding 20 points macro-F1 on multi-label tasks (e.g., Swahili manifestations from 0.14 to 0.556).
- General multilingual models outperform Swahili-specialized models by 10–15 points; naive multilingual mixing reduces performance by 5–15 points due to negative transfer.

## Why This Works (Mechanism)
**Mechanism 1: Class-weighted loss functions**  
- **Claim:** They mitigate severe label imbalance by assigning higher loss penalties to minority classes.  
- **Mechanism:** For multi-label, per-label weight `w_pos,i = n_neg,i / n_pos,i` multiplies the BCE loss, forcing the model to prioritize rare positive labels.  
- **Core assumption:** The model’s decision boundary can be adjusted via loss weighting without losing representational capacity.  
- **Evidence:** Ablation shows removing class weights degrades English Subtask 1 macro-F1 by 8.2 points (0.8032 → 0.7214).  
- **Break condition:** Extreme imbalance (>100:1) may still provide insufficient gradient; weights may misrepresent false positive costs or noisy rare-class data.

**Mechanism 2: Iterative stratified splitting**  
- **Claim:** It preserves joint label distributions across train/validation splits better than random splitting, yielding reliable validation estimates for macro-F1.  
- **Mechanism:** Algorithms like `iterative_train_test_split` iteratively assign instances to minimize divergence of per-label frequencies between split and full dataset, avoiding validation sets lacking rare labels.  
- **Core assumption:** A validation set mirroring the multi-label distribution is necessary for trustworthy hyperparameter tuning and early stopping.  
- **Evidence:** Section 4.4 explicitly replaces stratified with iterative splitting due to extreme imbalance (e.g., 47% all-zero instances).  
- **Break condition:** Greedy iterative algorithm may fail for very high label cardinality or complex correlations; assumes training distribution reflects true task distribution.

**Mechanism 3: Per-label threshold tuning**  
- **Claim:** Optimizing thresholds per label for macro-F1 outperforms a single global threshold (default 0.5).  
- **Mechanism:** Two-stage search: (1) coarse global threshold `θ*` maximizing macro-F1; (2) fine per-label search within ±0.15 of `θ*` in 0.01 increments, fixing other thresholds.  
- **Core assumption:** Optimal precision/recall trade-off differs per label due to imbalance; validation set is large enough to avoid overfitting.  
- **Evidence:** Ablation: default threshold gives 0.14 macro-F1 vs. 0.556 after tuning (+26.5 points) for Swahili Subtask 2.  
- **Break condition:** High risk of overfitting to validation, especially with small sets or many labels; greedy per-label optimization may not find global optimum.

## Foundational Learning
**Concept: Macro-averaged F1 as primary metric**  
- **Why needed:** The shared task uses macro-F1, which weights all labels equally—critical for extreme imbalance where micro-F1 would be dominated by majority classes. System design (loss weighting, threshold tuning) is driven by this metric.  
- **Quick check:** If a model gets F1=0.9 for a frequent label and F1=0.1 for a rare label, macro-F1 = (0.9+0.1)/2 = 0.5. Micro-F1 would be much higher due to many frequent instances; macro-F1 is preferred here to penalize ignoring rare labels.

**Concept: Multi-label classification formulation**  
- **Why needed:** Subtasks 2 and 3 allow multiple correct tags per instance, requiring sigmoid outputs (not softmax), `BCEWithLogitsLoss` (not `CrossEntropyLoss`), and per-label F1 averaging. It complicates splitting and error analysis.  
- **Quick check:** Key architectural difference: multi-label uses independent sigmoid per label; multi-class uses single softmax over classes. `CrossEntropyLoss` is inappropriate for multi-label because it assumes mutually exclusive classes.

**Concept: Class imbalance & cost-sensitive learning**  
- **Why needed:** Dataset shows ratios like 16:1 and 47% all-zero instances. Standard training collapses to predicting the majority negative class. Class weighting assigns higher cost to minority errors.  
- **Quick check:** Formula: `w_pos,i = n_neg,i / n_pos,i`. For a label appearing in 2% of instances, `n_pos` is small, `n_neg` is large → weight >>1, increasing loss penalty for missing positives.

## Architecture Onboarding
**Component map**  
Input Processor -> Transformer Encoder -> Classification Head -> Loss Module -> Threshold Tuner -> Evaluation Scorer

**Critical path**  
1. Preprocess raw text into tokenized IDs.  
2. Forward pass through Transformer and head to get logits.  
3. Apply weighted loss during training; update weights.  
4. After training, generate validation set predictions (sigmoid scores).  
5. Run threshold tuner on validation scores to find per-label `θ_i`.  
6. Inference: apply tuned `θ_i` to sigmoid scores for binary predictions.  
7. Evaluate with macro-F1.

**Design tradeoffs**  
- **Model Choice vs. Data Volume:** General multilingual models (mDeBERTa) outperformed Swahili-specialized ones despite Swahili data being larger—architectural strength may outweigh in-language pretraining when downstream data is sufficient.  
- **Threshold Tuning vs. Overfitting:** Tuning yields huge gains (+20+ points) but risks severe overfitting to validation; validation set must be large enough to support tuning `k` thresholds.  
- **Naive Multilingual Training:** Mixing English and Swahili causes negative transfer (-5 to -15 points); cross-lingual transfer requires careful adaptation (e.g., adapters) to avoid interference.

**Failure signatures**  
1. High variance on validation curves indicates unstable training from inappropriate LR, batch size, or loss weighting.  
2. Collapse to all-negative predictions for multi-label tasks if class weights are omitted; check per-label precision/recall for minority labels.  
3. Validation macro-F1 >> test macro-F1 (>10 points) signals threshold tuning overfit or distribution shift.  
4. Poor performance on implicit polarization/code-switching (from error analysis) suggests reliance on surface cues and tokenizer issues.

**First 3 experiments**  
1. Replicate baseline: Train `DistilBERT-multilingual` on English Subtask 1 with default 0.5 threshold and no class weighting; expect ~0.72 macro-F1.  
2. Add class weighting only to Experiment 1; expect ~0.80 macro-F1 (isolates weighting gain).  
3. Add per-label threshold tuning to Experiment 2’s model; expect large gain for multi-label tasks (e.g., from 0.14 to ~0.55).

## Open Questions the Paper Calls Out
1. **Why do general multilingual Transformer models consistently outperform language-specialized models on polarization detection in low-resource languages despite the latter’s targeted pretraining?** The paper presents this as a key finding but does not investigate underlying factors such as pretraining data diversity, model architecture, or capacity differences.  
2. **What specific mechanisms cause negative transfer in naive multilingual training for polarization detection, and how can cross-lingual transfer be optimized?** The paper identifies negative transfer but does not analyze causes (e.g., parameter interference, linguistic divergence) or explore remedies.  
3. **How can threshold tuning for multi-label imbalanced classification be regularized to prevent overfitting on validation data?** The paper notes test performance drops 10–15 points below validation but does not evaluate alternative selection strategies or regularization.  
4. **Why do models systematically fail on implicit polarization cues and code-switched text, and what modifications could improve robustness?** Error analysis reveals failures on dog whistles and code-switching but lacks analysis of feature representations or targeted interventions.

## Limitations
- Insufficient description of iterative splitting details (initialization, convergence) hampers reproducibility.  
- Threshold tuning may overfit validation, with test drops up to 15 points.  
- Naive multilingual mixing causes negative transfer without analysis of causes or solutions.  
- Error analysis lacks quantitative breakdowns; official test labels unavailable for independent verification.

## Confidence
- Class-weighted loss effectiveness: **High** (ablation +8.2 points).  
- Iterative stratified splitting necessity: **High** (preserves multi-label distribution).  
- Threshold tuning gains: **High** (ablation +26.5 points), but practical **Medium** due to overfitting risk.  
- Multilingual model superiority: **Medium** (empirical, limited languages).  
- Negative transfer occurrence: **Medium** (consistent 5–15 point drops).  
- Error analysis insights: **Medium** (qualitative only).

## Next Checks
1. **Ablation across seeds:** Train with/without class weighting on all subtasks with 5 random seeds; report mean/variance of macro-F1 to confirm robustness.  
2. **Cross-validated threshold tuning:** Replace single-validation threshold search with 5-fold cross-validation; compare validation macro-F1 and estimate test performance to quantify overfitting.  
3. **Split stability analysis:** Generate 10 random iterative splits and 10 random stratified splits; compare per-label F1 variance for rare labels to validate iterative stratification necessity.
