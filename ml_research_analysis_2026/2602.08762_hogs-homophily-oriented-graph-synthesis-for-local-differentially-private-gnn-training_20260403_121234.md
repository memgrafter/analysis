# HoGS: Homophily-Oriented Graph Synthesis for Local Differentially Private GNN Training

## Quick Facts
- **ArXiv ID:** 2602.08762  
- **Source URL:** https://arxiv.org/abs/2602.08762  
- **Reference count:** 40  
- **Primary result:** HoGS generates a synthetic graph under LDP for both links and features, leveraging homophily for bidirectional denoising to significantly improve GNN classification accuracy, especially at low privacy budgets.

## Executive Summary
HoGS is a framework for training Graph Neural Networks (GNNs) under local differential privacy (LDP) that protects both node adjacency lists and feature vectors. It addresses a key gap: prior methods either safeguarded only links or suffered severe utility loss when protecting both. HoGS collects LDP-perturbed data from nodes, then reconstructs a synthetic graph by exploiting graph homophily—the tendency of similar nodes to connect. The reconstruction proceeds in two coupled stages: feature similarity guides a Bayesian update of noisy adjacency to recover cleaner topology, and the resulting link probabilities weight the aggregation of noisy neighbor features. This bidirectional denoising mitigates LDP-induced noise without consuming additional privacy budget. Across three datasets and three GNN architectures, HoGS consistently outperforms baselines, with particularly large gains under tighter privacy constraints.

## Method Summary
HoGS operates in three phases. First, each node locally perturbs its binary adjacency list using Randomized Response (RR) with budget εₐ and its continuous feature vector using the 1‑Bit mechanism with budget ε_f (εₐ + ε_f = ε, controlled by δ). The curator receives these noisy outputs. Second, the curator reconstructs topology: for every node pair, it computes cosine similarity between noisy feature vectors as a prior link probability, combines this with the likelihood of the observed noisy adjacency bits via Bayes’ rule to obtain a posterior connection probability Pᵢⱼ, and retains edges where Pᵢⱼ exceeds a threshold τ. Third, for feature reconstruction, each node aggregates noisy features of potential neighbors (those with Pᵢⱼ ≥ 0.5) weighted by their Pᵢⱼ to produce a denoised feature vector. The resulting synthetic graph (Ê, X̂) satisfies ε‑LDP by sequential composition and post-processing. Finally, standard GNNs are trained on this synthetic graph for node classification.

## Key Results
- HoGS substantially outperforms state‑of‑the‑art LDP baselines (FP-BLink, FP-LDPGen, Solitude) on Cora, CiteSeer, and LastFM across GCN, GraphSAGE, and GAT architectures.
- Accuracy gains are most pronounced under lower privacy budgets (e.g., ε=3–5) and on attention‑based GAT, which is sensitive to noisy topology.
- Ablation studies confirm that both the homophily‑guided topology reconstruction and the probabilistic feature aggregation are essential; removing either degrades performance to baseline levels.

## Why This Works (Mechanism)
### Mechanism 1: Feature-Similarity-Guided Link Denoising
- **Claim:** HoGS uses noisy node feature vectors to compute cosine similarity as a prior probability for link existence, which is combined with noisy adjacency list evidence via Bayesian estimation to reconstruct a less noisy graph topology.
- **Mechanism:** For each node pair (vᵢ, vⱼ), compute feature similarity sᵢⱼ = (X̃ᵢ·X̃ⱼ)/(‖X̃ᵢ‖‖X̃ⱼ‖). Treat sᵢⱼ as prior Pr[(Aᵢⱼ, Aⱼᵢ)=(1,1)]. Compute likelihoods lᵢⱼ and l'ᵢⱼ from observed noisy bits (Ãᵢⱼ, Ãⱼᵢ) under edge-LDP using RR parameters. Posterior Pᵢⱼ = (lᵢⱼ·sᵢⱼ)/(lᵢⱼ·sᵢⱼ + l'ᵢⱼ·(1−sᵢⱼ)). Retain links where Pᵢⱼ ≥ τ.
- **Core assumption:** Homophily holds—nodes with similar true features are more likely connected. Noisy features retain enough signal for similarity to correlate with true link probability.
- **Evidence anchors:**  
  [abstract]: "leverages the phenomenon of homophily... feature similarity informs Bayesian reconstruction of noisy links"  
  [section III-C]: Detailed algorithm using cosine similarity as prior and Bayes' rule with noisy adjacency evidence.  
  [corpus]: Neighbor "Blink" uses Bayesian estimation but requires degree budget; HoGS replaces degree prior with feature similarity, avoiding extra budget.
- **Break condition:** If the graph is strongly heterophilic (similar features anti-correlate with links), similarity prior becomes misleading, worsening topology reconstruction.

### Mechanism 2: Probabilistic-Weighted Feature Denoising
- **Claim:** HoGS aggregates noisy neighbor features using posterior link probabilities Pᵢⱼ as weights, suppressing contribution from unreliable connections to reconstruct cleaner node features.
- **Mechanism:** For each node vᵢ, define potential neighbor set Vᵢ = {vⱼ | Pᵢⱼ ≥ 0.5}. Reconstruct feature X̂ᵢ = (Σ_{vⱼ∈Vᵢ} Pᵢⱼ·X̃ⱼ) / (Σ_{vⱼ∈Vᵢ} Pᵢⱼ). High-weight links (high Pᵢⱼ) dominate; low-weight links (noise-induced) are downweighted.
- **Core assumption:** Neighboring nodes share similar features (homophily). The synthetic topology's link probabilities reliably indicate which noisy neighbor features are likely informative.
- **Evidence anchors:**  
  [abstract]: "reconstructed links weighted by connection probability aggregate noisy features"  
  [section III-D]: Explicit weighted averaging equation and rationale against naive K-hop aggregation.  
  [corpus]: Neighbor "Solitude" uses sparse spurious edge filtering; HoGS uses probabilistic weighting, more nuanced under high noise.
- **Break condition:** If topology reconstruction is poor (many false positives with high Pᵢⱼ), aggregation incorporates dissimilar features, corrupting X̂ᵢ. Particularly if τ is too low.

### Mechanism 3: LDP-Compliant Bidirectional Synthesis
- **Claim:** HoGS generates a synthetic graph (Ê, X̂) satisfying ε-LDP (ε=εₐ+ε_f) by separately perturbing adjacency lists and feature vectors, then post-processing without additional privacy budget consumption.
- **Mechanism:** Sequential composition: adjacency perturbation (εₐ-edge LDP) + feature perturbation (ε_f-feature LDP) → combined (εₐ+ε_f)-LDP. Post-processing (Bayesian reconstruction, weighted aggregation) preserves LDP per Theorem 2.
- **Core assumption:** Sequential composition theorem holds for edge-LDP and feature-LDP definitions. Post-processing does not increase privacy loss.
- **Evidence anchors:**  
  [abstract]: "theoretically prove that HoGS satisfies LDP"  
  [section IV-A]: Lemma 3 (perturbations satisfy edge/feature LDP) and Theorem 4 (composition + post-processing yields ε-LDP).  
  [corpus]: Neighbor "BLink" also uses sequential composition for edge-LDP; HoGS extends to dual protection with feature-based prior.
- **Break condition:** If definitions of edge-LDP/feature-LDP are misaligned with actual attacker capabilities (e.g., feature bit-flip not the relevant neighborhood), privacy guarantee may not match intuitive risk.

## Foundational Learning
- **Concept: Local Differential Privacy (LDP)**  
  *Why needed here:* HoGS’s entire data collection phase operates under LDP; understanding ε, composition, and mechanisms (RR, 1-Bit) is essential to reason about privacy budget split (δ) and noise impact.  
  *Quick check question:* If a node spends εₐ=2 on adjacency and ε_f=1 on features, what is the total ε for the combined output? How does sequential composition apply?
- **Concept: Graph Homophily**  
  *Why needed here:* Homophily is the core empirical property enabling bidirectional denoising; without it, feature similarity isn’t a valid prior for links and neighbor aggregation isn’t helpful.  
  *Quick check question:* Why is homophily particularly useful for denoising under LDP, compared to just preserving graph sparsity?
- **Concept: Graph Neural Network (GNN) Message Passing**  
  *Why needed here:* HoGS aims to produce a synthetic graph suitable for standard GNN training; understanding that GNNs aggregate neighbor features explains why topology and feature noise both harm utility.  
  *Quick check question:* In a 2-layer GCN, a node’s representation depends on how many hops of neighbors? How would LDP noise in links vs. features each affect this aggregation?

## Architecture Onboarding
- **Component map:** Information Collection (LDP perturbation of adjacency and features) -> Topology Reconstruction (Bayesian link recovery using feature similarity) -> Feature Reconstruction (weighted aggregation of noisy features) -> Synthetic Graph -> GNN Training  
- **Critical path:** Per-node LDP perturbation (εₐ, ε_f) -> Global pairwise cosine similarity & posterior computation (O(n²d)) -> Thresholding to obtain edge set Ê -> Per-node weighted feature aggregation using Pᵢⱼ to produce X̂.  
- **Design tradeoffs:**  
  - **δ (privacy allocation):** Smaller δ puts more budget on topology (εₐ), helping structure-sensitive datasets (e.g., Cora); larger δ favors feature quality (ε_f), helping high-dimensional datasets (e.g., LastFM).  
  - **τ (link threshold):** Higher τ yields sparser, purer graphs (good for sparse graphs, low ε); lower τ yields denser graphs capturing more true edges but risks false positives (good for dense graphs, high ε).  
  - **l (feature aggregation iterations):** l=0 uses only direct neighbors; l>0 propagates reconstructions further, but error may compound. Data-driven choice needed.  
- **Failure signatures:**  
  - Accuracy near random or baseline (e.g., Solitude) under low ε: bidirectional denoising failing due to excessive noise; consider increasing τ or adjusting δ.  
  - Synthetic graph extremely dense (|Ê| ≫ |E|): τ too low; raise τ.  
  - Synthetic graph disconnected: τ too high or feature similarity too weak; lower τ or check homophily level.  
  - GAT performance collapse under low ε: attention mechanism sensitive to noisy false neighbors; try higher τ or lower l.  
- **First 3 experiments:**  
  1. **Baseline comparison:** Run HoGS vs. FP-BLink, FP-LDPGen, Solitude on GCN/GraphSAGE/GAT across ε=3–8. Expect HoGS to dominate, especially at low ε and on GAT.  
  2. **Ablation:** Compare HoGS to "BLink+FR" (BLink topology + HoGS feature recon) and "TR+KProp" (HoGS topology + KProp feature recon). Expect HoGS full pipeline to win, validating bidirectional design.  
  3. **Parameter sweep:** Vary δ∈{0.1,0.5,0.9} and τ∈{0.5,0.7,0.9} on Cora and LastFM. Expect opposite δ trends (Cora favors smaller δ, LastFM larger) and τ sensitivity depending on graph density and ε.

## Open Questions the Paper Calls Out
- **How can HoGS be extended to protect richer graph attributes like edge weights while maintaining utility?** The current framework only handles binary links and continuous features; edge weights introduce additional sensitivity and require modified LDP mechanisms.  
- **What is the theoretical relationship between graph homophily degree and the optimal privacy budget allocation parameter δ, to avoid dataset-dependent grid search?** HoGS requires per-dataset tuning of δ, limiting deployability; the trade-off between topology/feature utility and homophily strength is not modeled.  
- **How robust is HoGS’s homophily-based reconstruction on graphs with low or negative homophily (heterophilic graphs)?** All experiments use homophilic citation/social networks; if homophily is weak, the Bayesian reconstruction prior may mislead link recovery.  
- **Does the independent LDP perturbation of adjacency lists and feature vectors in HoGS inadvertently violate privacy guarantees if underlying data correlations are exploited?** The privacy analysis assumes independent perturbations, but graph data often exhibits attribute–structure correlations (e.g., homophily itself), which could reduce effective privacy under advanced attacks.  
- **Can HoGS’s O(n²d) computational complexity be reduced to handle large-scale graphs (e.g., millions of nodes) without significant utility loss?** The all-pairs cosine similarity and link probability calculations become prohibitive for large n; the paper only tests graphs up to ~7k nodes.

## Limitations
- The 1‑Bit mechanism requires a known feature range [α,β]; the paper does not specify whether or how features were normalized, potentially affecting denoising and privacy accounting.  
- Parameter `l` (number of feature‑reconstruction iterations) is ambiguous; the paper searches over {0,1,2} but the algorithmic effect for `l>0` is unclear.  
- Homophily assumption may not generalize; performance on heterophilic graphs is not evaluated, limiting claims about broad applicability.

## Confidence
- **Superior accuracy under low ε:** High – comprehensive experiments across three datasets and three GNNs, with strong baselines.  
- **Theoretical LDP guarantee:** Medium – proof sketch relies on sequential composition and precise edge/feature LDP definitions; possible gaps if attacker model differs.  
- **Bidirectional denoising mechanism:** Medium – ablations support the design but homophily’s isolated contribution is not fully quantified; failure on non‑homophilic graphs would weaken the claim.
