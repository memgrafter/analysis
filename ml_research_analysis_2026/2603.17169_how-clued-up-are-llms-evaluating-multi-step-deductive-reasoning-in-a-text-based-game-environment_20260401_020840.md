# How Clued up are LLMs? Evaluating Multi-Step Deductive Reasoning in a Text-Based Game Environment
## Quick Facts
- **arXiv ID**: 2603.17169  
- **Source URL**: https://arxiv.org/abs/2603.17169  
- **Reference count**: 40  
- **Primary result**: LLM agents achieved only 4 correct wins across 18 games, with fine-tuning not reliably improving performance and reasoning precision being more critical than knowledge volume.

## Executive Summary
This study evaluates whether large language model (LLM) agents can perform sustained multi-step deductive reasoning in a long-horizon, interactive setting using a text-based multi-agent implementation of Clue. Six agents—variants of GPT‑4o‑mini and Gemini‑2.5‑Flash, with and without fine‑tuning on logic puzzles—were evaluated over 18 simulated games. Results show poor overall performance, with only 4 correct accusations. Fine‑tuning did not yield consistent gains; it degraded GPT‑4o‑mini’s win rate while providing only marginal improvement for Gemini. A key finding is that accumulating more deductions does not translate to better accusation accuracy—reasoning precision is paramount.

## Method Summary
The authors built a custom Clue game engine with 21 unique cards (suspects, weapons, rooms). Six agents played each game, each maintaining a private hand and a knowledge state aggregating shown cards and suggestion history. At each turn, agents performed a deduction phase (inferring opponent cards from disprovals) and an action phase (suggest or accuse). Prompts required structured outputs: SUMMARY, REASONING, SUGGESTION/ACCUSATION, and (for show‑card responses) SHOW. Two models were tested in baseline (6 games) and fine‑tuned (12 games) configurations. Fine‑tuning used the Mind Bender logic puzzle dataset (50 training, 10 validation) with default API settings. Performance metrics included win rate, accusation accuracy (0–3 correct cards), deduction quality (correct vs. incorrect inferences), knowledge accumulation (unique known cards, capped at 18), and parse failure rate (triggering reprompts or fallback random actions).

## Key Results
- Agents won only 4 of 18 games; no condition achieved perfect scores.
- Fine‑tuning degraded GPT‑4o‑mini wins (5/12 baseline → 3/12 fine‑tuned) and gave Gemini‑2.5‑Flash only marginal gains.
- The fine‑tuned GPT‑4o‑mini agent accumulated the most deductions but had the worst accusation accuracy, highlighting a disconnect between knowledge volume and reasoning precision.

## Why This Works (Mechanism)
The paper does not propose a positive mechanism; instead, observed failure modes explain poor results. **Parse failures**—when models deviate from required output formats—trigger reprompts or fallback to random actions, disrupting strategic play. **Reasoning inconsistencies**—contradictory deductions across turns—cause agents to abandon a coherent game state, effectively rendering the knowledge base unusable. These issues are exacerbated by the long‑horizon, interactive nature of the game, where early mistakes compound and structured prompts may overly constrain natural reasoning.

## Foundational Learning
- **Deductive Reasoning**  
  *Why needed*: Core task is inferring hidden cards from disprovals.  
  *Quick check*: Track consistency of each deduction against prior knowledge; flag contradictions.
- **Knowledge Accumulation**  
  *Why needed*: Building a complete case requires synthesizing information over many turns.  
  *Quick check*: Measure unique known cards per round; cap at 18 (total cards minus solution).
- **Multi‑Agent Interaction**  
  *Why needed*: Information is asymmetric; agents must interpret others’ suggestions and show‑cards.  
  *Quick check*: Count how often suggestions are disproved and by whom.
- **Prompt Engineering**  
  *Why needed*: Enables parsing LLM outputs into game actions; poor phrasing causes failures.  
  *Quick check*: Monitor parse failure rate; refine if >10%.
- **Fine‑Tuning**  
  *Why needed*: Adapt models to step‑by‑step reasoning on logic puzzles.  
  *Quick check*: Compare training/validation accuracy (e.g., >85%) with in‑game performance.

## Architecture Onboarding
The system comprises:  
**Game Engine** → **LLM Agent** (with **Prompt Template**) → **Parser** → **Metrics Logger**; shared **Game State** updated after each phase.

Critical path per turn:  
1. Deduction phase (analyze disprovals)  
2. Action phase (issue suggestion or accusation)  
3. Show‑card phase (if applicable)  
4. Update knowledge state and proceed to next agent.

Design tradeoffs:  
- Structured prompts ensure parseable output but may constrain natural reasoning and increase fallback risk if models drift.  
- Fine‑tuning on abstract puzzles may not transfer to complex, dynamic game interactions.  
- Random fallback actions prevent stalls but introduce noise that disproportionately harms strategic play.

Failure signatures:  
- High parse failure rate → prompt inadequacy.  
- Reasoning contradictions → unstable knowledge base.  
- Low accusation accuracy despite high knowledge accumulation → lack of logical integration.

## Limitations
- Small sample sizes (6–12 games per condition) limit statistical reliability.  
- Critical implementation details (exact prompt phrasing, knowledge state serialization) are incomplete, hindering exact replication.  
- The Mind Bender puzzle dataset used for fine‑tuning is not provided, and fine‑tuning hyperparameters are unreported.

- Fine‑tuning degrades GPT‑4o‑mini win rate: Medium

- LLMs struggle with multi‑step deduction in Clue: Medium
