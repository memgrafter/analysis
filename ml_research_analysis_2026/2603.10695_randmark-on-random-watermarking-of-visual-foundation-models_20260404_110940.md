# RandMark: On Random Watermarking of Visual Foundation Models

## Quick Facts
- **arXiv ID:** 2603.10695
- **Source URL:** https://arxiv.org/abs/2603.10695
- **Reference count:** 28
- **Primary result:** A random watermarking method achieving high detection rates (>90%) for watermarked models and near-zero false positives after functional perturbations, maintaining downstream task performance.

## Executive Summary
RandMark is a novel framework for watermarking visual foundation models (VFMs) such as CLIP and DINOv2. It co-trains a lightweight encoder-decoder pair on a secret trigger set with random additive noise to embed a binary watermark into the model's internal feature representations. The watermark is designed to survive common functional adaptations like fine-tuning and pruning, enabling reliable ownership verification. Verification is performed by feeding multiple noisy versions of the trigger set through the suspect model and aggregating Hamming distances, with a statistical hypothesis test providing strong guarantees on false positives and misdetections. Experiments demonstrate that RandMark outperforms existing fingerprinting methods, achieving high true positive rates (>90%) for fine-tuned and pruned models while preserving task performance and maintaining near-zero false positives. Theoretical analysis via Chernoff bounds ensures that, given sufficient trigger samples, the probability of incorrectly accepting a non-watermarked model or rejecting a watermarked one can be made arbitrarily small (e.g., <10⁻⁶).

## Method Summary
RandMark’s watermarking process begins with a secret trigger set of N images (e.g., 1000 ImageNet samples) and a binary message m (n=32 bits). During co-training, each trigger image is perturbed with random noise ε ~ N(0,σ²I) and passed through a small encoder e that produces an signal added to the VFM f’s intermediate representation. The modified VFM f̃ is jointly trained with the decoder d to minimize two objectives: (1) the discrepancy between the original and watermarked representations (to preserve utility) and (2) the message extraction loss between the true m and d’s output from the perturbed representation (to strengthen the watermark). The perturbation ε is both a training and a verification tool. At verification time, the suspect model h processes K noisy variants of each trigger; the decoder extracts m' from each output. The average Hamming distance ρ(x) is computed per trigger, and if ρ(x) ≤ τ for enough triggers (i.e., (1/N) Σ 1[ρ ≤ τ] ≥ R), the model is claimed to be watermarked. The statistical test exploits that dependent models yield consistently low ρ (due to the learned correlation) while independent models yield random matches. Hyperparameters (λ, σ², N, K, n) and thresholds (τ, R) are chosen empirically to balance detection strength, robustness, and computational overhead. The method is model-agnostic, applying to any VFM architecture, and the watermark resides in the representation space, making it resilient to weight-level changes such as fine-tuning or pruning.

## Key Results
- **High detection after functional perturbations:** True positive detection rate > 90% for watermarked CLIP/DINOv2 after fine-tuning on classification (E-commerce) and segmentation (FoodSeg103) tasks and after 50% unstructured pruning.
- **Near-zero false positives:** False positive rate < 0.5% for independent models, including different architectures (ViT vs. CNN) and models trained from scratch, outperforming baseline fingerprinting methods (ADV-TRA, IPGuard).
- **Utility preservation:** Watermarked models maintain comparable downstream task performance (e.g., mIoU) to non-watermarked counterparts, while existing methods often degrade accuracy.

## Why This Works (Mechanism)

### Mechanism 1: Embedding via co‑training with random noise
- **Claim:** A watermark is embedded into the internal feature representations of a VFM by co‑training a lightweight encoder‑decoder pair on a fixed set of trigger images with random additive noise.
- **Mechanism:** For each trigger image `x`, a binary message `m` is combined with a random transformation `ε_j ~ N(0, σ²I)` to create a perturbed input `x+ε_j`. A small encoder `e(x+ε_j, m)` produces a signal that is added to the VFM's representation before the decoder `d` attempts to extract the message. The VFM, encoder, and decoder are trained jointly to minimize the representation deviation (`||f(x) - f̃(x)||²`) and the message extraction loss (`||m - m'_j||²`), making the representation statistically carry the watermark.
- **Core assumption:** Modifying the representation on a small, secret trigger set does not catastrophically degrade the VFM's general utility across unrelated images and tasks, and the learned watermark signal persists through common functional adaptations like fine‑tuning.
- **Evidence anchors:** [abstract] "...leverages a small encoder‑decoder network to embed digital watermarks into an internal representation of a hold‑out set of input images."; [section 3.3] "we fine‑tune the source model together with the lightweight encoder and decoder networks... to minimize both the average discrepancy... and the variance... of the extracted binary messages."; [section 4.1] "To embed watermarks, we use a random subset of N=1000 images from the ImageNet dataset... the watermark information to be incorporated while preserving model functionality."
- **Break condition:** If the trigger set is too small or the co‑training loss weights are misconfigured, the watermark may either (a) be absent in the representations (high misdetection) or (b) degrade the VFM's core functionality on non‑trigger data, causing the owner to reject the watermarked model.

### Mechanism 2: Statistical verification via random transformations
- **Claim:** Ownership is verified by statistically distinguishing the distribution of extracted messages from a suspect model versus an independent model, using a pre‑defined threshold on the average Hamming distance over multiple random transformations of the trigger set.
- **Mechanism:** During verification, `K` random transformations (`x+ε_j`) of each trigger image are fed through the suspect model `h`. The decoder extracts `m'_j` from `h(x+ε_j)`. The average Hamming distance `ρ(x) = (1/K) Σ ||m - m'_j||₁` is computed. If `ρ(x) ≤ τ` for a sufficient number of trigger images (Equation 7), the model is classified as watermarked. The randomness across `ε_j` is designed so that for a *functionally related* model (`f' ~ f`), `ρ` is consistently low, while for an *independent* model (`g ⊥ f`), `ρ` is high with high probability.
- **Core assumption:** The random transformations cause the extracted watermark bits from a dependent model to have a high probability of matching the embedded message (`r(Ω_f|x) ≈ 1`), while an independent model's bit‑matching probability (`r(Ξ|x)`) is near random chance (≈0.5 for n=32). The law of large numbers over `N` trigger images amplifies this distinction.
- **Evidence anchors:** [abstract] "random watermark embedding, which makes the watermark statistics detectable in functional copies of the watermarked model... low probability of false detection for non‑watermarked models and a low probability of false misdetection for watermarked models."; [section 3.4] "v(f, f') is expected to be small for f' ~ f and v(f, g) is expected to be large for g ⊥ f... we estimate the probabilities of the method to yield low detection rates for functionally dependent models and high detection rates for independent models."; [section 3.5] Provides Chernoff bounds (Lemma 1) to theoretically upper‑bound the misdetection/false‑positive probabilities based on the empirical detection rate `R`.
- **Break condition:** If the random transformation variance (`σ²`) is too low, an attacker might reverse‑engineer and remove the watermark. If too high, even the watermarked model's `ρ` might exceed `τ` due to excessive representation perturbation, causing false misdetection. The threshold `τ` and `R` must be set based on empirical distributions (section 3.4, Remark 1).

### Mechanism 3: Representation‑space embedding for robustness
- **Claim:** The method's robustness stems from embedding the signature into the *representation space* rather than directly into weights or final logits, making it resilient to fine‑tuning and pruning that preserve the core representation function.
- **Mechanism:** The watermark is injected into the intermediate feature map output of the VFM for trigger images. Common functional attacks (fine‑tuning on downstream tasks, unstructured pruning) are modeled as operations that produce a model `f'` that is *functionally similar* to `f` on a broad distribution of inputs. Because the watermark signal is baked into the response of `f` (and thus `f'`) to a *specific, secret set of inputs* under random transformations, it survives as long as the representation for those trigger inputs remains correlated. The use of random transformations makes the extracted signature a *statistic* (mean/variance) of a random variable, which is harder to eliminate via deterministic fine‑tuning.
- **Core assumption:** There is no known fine‑tuning or pruning procedure that can simultaneously (a) drastically alter the VFM's representation on the secret trigger set under diverse transformations *and* (b) preserve the model's utility on the intended downstream task distribution. The threat model (section 3.3) assumes adversaries cannot access the trigger set or the encoder/decoder.
- **Evidence anchors:** [abstract] "successfully detects model ownership after various functional perturbations, including fine‑tuning on downstream tasks (classification and segmentation) and unstructured pruning, where existing fingerprinting methods fail."; [section 2.2] Contrasts with weight‑space smoothing [2,21] and notes that existing methods for classifiers "are not directly tailored to the broader capabilities of VFMs."; [section 5 & Table 2] Empirical results show high detection rates (`R↑`) for fine‑tuned and pruned models, and low rates for negative suspect models of different architectures. Table 1 shows the baseline "Randomized Smoothing" method fails after fine‑tuning, while RandMark preserves both segmentation mIoU and WM detection.
- **Break condition:** An attacker with full knowledge of the method and a large query budget might perform adversarial training on the trigger set to explicitly decorrelate the representations. The paper's threat model does not consider adaptive attacks with trigger set knowledge.

## Foundational Learning

**Concept: Visual Foundation Models (VFMs)**  
- **Why needed here:** VFMs (e.g., CLIP, DINOv2) are pre‑trained for general representation learning and fine‑tuned for diverse downstream tasks. RandMark targets this class; unlike single‑task classifiers, their value lies in transferable features, so watermarking must not hinder transferability.  
- **Quick check:** Why might a watermark designed for a fixed‑classification‑head model fail when applied to a VFM like CLIP that is fine‑tuned for segmentation?

**Concept: Digital Watermarking vs. Fingerprinting**  
- **Why needed here:** RandMark is an active watermarking method (owner embeds a secret signature) rather than a passive fingerprinting method that derives an identifier from model internals. The mechanism relies on altering model behavior on specific inputs.  
- **Quick check:** What is the fundamental operational difference between the watermarking approach in RandMark and a fingerprinting method like ADV‑TRA [26] as described in section 2.2?

**Concept: Probabilistic Hypothesis Testing & Concentration Bounds**  
- **Why needed here:** Ownership verification is a statistical test; thresholds (τ, R) and theoretical guarantees (false positive/misdetection probabilities) are derived using Bernoulli sums, Chernoff bounds, and confidence intervals (sections 3.4, 3.5).

## Architecture Onboarding

**Component map:** The system comprises a secret trigger set X (N images), a binary watermark m (n bits), a lightweight encoder e, a watermarked visual foundation model f̃, a decoder d, and a verification module. Random noise ε ~ N(0,σ²I) is applied to trigger images. During training, for each (x,m) and sampled ε, the encoder produces a perturbation Δ = e(x+ε, m) that is added to f’s representation at a chosen layer, yielding f̃(x+ε). The decoder then attempts to recover m from this representation. The three networks are trained jointly with losses on representation preservation and message extraction. During verification, the same trigger images with K random ε samples each are fed through the suspect model h; the decoder extracts m'_j from each output; the average Hamming distance ρ(x) is computed; ownership is declared if ρ(x) ≤ τ for a sufficient fraction of triggers.

**Critical path:**
1. **Watermark Injection:** At each training step, sample (x, m) from the trigger set and a random ε; compute encoder output Δ; add to VFM’s intermediate features; compute loss L = λ_rep ||f(x) - (f’s perturbed output)||² + λ_msg ||m - d(perturbed output)||²; backpropagate through e, f̃, d.
2. **Verification:** For a suspect model h, for each x_i ∈ X and for j=1..K, sample ε_j, retrieve h(x_i+ε_j) representation, run d to get m'_j, compute ρ(x_i) = (1/K) Σ ||m - m'_j||₁. Compute detection rate R(h,X,τ) = (1/N) Σ 1[ρ(x_i) ≤ τ].
3. **Decision:** If R(h,X,τ) ≥ R (predefined threshold), claim watermarked; else not.

**Design tradeoffs:**
- *Watermark strength (λ) vs. Utility:* Higher λ reinforces the watermark but may harm representation quality and downstream performance.
- *Randomness (σ²) vs. Robustness/Debuggability:* Larger σ² yields more diverse samples, improving robustness to fine‑tuning but increasing variance in ρ, requiring larger K and N for stable estimates.
- *Trigger set size (N) and K vs. Cost:* Larger N and K reduce statistical error (Lemma 1) but linearly increase verification time.
- *Watermark length (n) vs. Detection certainty:* Longer n lowers random‑match probability (0.5^n) but for a fixed τ the bound on ρ becomes tighter, potentially raising false negatives if σ² is low.

**Failure signatures:**
- *High false positive:* Independent models yield ρ ≤ τ often; suggests σ² too low or decoder not sufficiently discriminating.
- *High false negative:* Watermarked models yield ρ > τ; suggests λ too low, or fine‑tuning altered representations too much.
- *Unstable ρ:* High variance across ε samples; increase K or σ².
- *Utility degradation:* Downstream task performance drops; reduce λ or encoder capacity.

## Open Questions the Paper Calls Out

**Open Question 1**  
- **Question:** Does RandMark maintain effectiveness across a broader spectrum of visual foundation model architectures beyond ViTs, such as convolutional or hybrid designs?  
- **Basis in paper:** [inferred] Experiments are restricted to CLIP and DINOv2 (both ViT‑based). The claimed model‑agnostic nature lacks validation on other VFM architectures.  
- **Why unresolved:** Architectural differences may alter internal representations and watermark dynamics. Without evaluation, generalizability remains uncertain.  
- **What evidence would resolve it:** Systematic testing on diverse VFM backbones (e.g., ConvNeXt, Swin, multimodal models) under identical perturbations, reporting detection rates.

**Open Question 2**  
- **Question:** How robust is RandMark against adaptive attacks like knowledge distillation or adversarial fine‑tuning that explicitly target watermark removal?  
- **Basis in paper:** [inferred] The threat model includes standard fine‑tuning and pruning; knowledge distillation is only mentioned in passing and not evaluated. Adversarial strategies aware of the watermarking mechanism are absent.  
- **Why unresolved:** An attacker could optimize a loss to suppress watermark extraction while preserving functionality, potentially breaking verification. Current evaluations do not cover such threats.  
- **What evidence would resolve it:** Simulate attacks where the adversary fine‑tunes with a watermark‑removal objective or distills from a clean model, then measure detection rates compared to baseline.

**Open Question 3**  
- **Question:** What is the quantitative relationship between the hyperparameter λ (balancing representation preservation and watermark strength) and downstream task performance across different VFMs and tasks?  
- **Basis in paper:** [inferred] The loss function includes λ, but the paper uses a fixed value without sensitivity analysis. The trade‑off between detection rate and task metrics is not explored.  
- **Why unresolved:** Practitioners lack guidance on λ selection; an inappropriate value may degrade utility or robustness, requiring costly tuning.  
- **What evidence would resolve it:** Conduct a sweep over λ for each VFM‑task pair, plotting detection rate vs. task metric (e.g., accuracy, mIoU), and possibly derive a theoretical bound linking λ to these metrics.

**Open Question 4**  
- **Question:** How does compromising the secrecy of the trigger image set and watermark message affect the security guarantees of RandMark?  
- **Basis in paper:** [explicit] The method assumes secret triggers and message: "secret input image used for watermarking". However, the scenario where these are leaked is not analyzed.  
- **Why unresolved:** If an attacker obtains the triggers and message, they could craft targeted removal attacks or produce false negatives. The dependence on secrecy is unquantified.  
- **What evidence would resolve it:** Simulate compromise by giving attackers full knowledge of triggers and message, then attempt removal via fine‑tuning/pruning. Compare detection rates to the secret setting and evaluate potential spoofing success.

## Limitations
- No adaptive attack evaluation – attacker with trigger set knowledge could fine‑tune to break watermark.
- Only two VFM architectures (CLIP, DINOv2) tested; generalizability to other VFMs uncertain.
- Statistical verification thresholds (τ, R) rely on empirical calibration; worst‑case bounds may be loose in practice.

## Confidence
- **Embedding mechanism:** Medium – depends on hyperparameters, limited ablations.
- **Verification test:** Medium‑High – theory sound but i.i.d. assumption may not hold.
- **Robustness to functional perturbations:** Medium – strong empirical results but only standard fine‑tuning/pruning evaluated.
