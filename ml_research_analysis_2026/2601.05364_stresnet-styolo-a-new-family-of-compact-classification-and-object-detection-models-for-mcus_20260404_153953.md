# STResNet & STYOLO : A New Family of Compact Classification and Object Detection Models for MCUs

## Quick Facts
- **arXiv ID:** 2601.05364
- **Source URL:** https://arxiv.org/abs/2601.05364
- **Reference Count:** 34
- **Primary Result:** STResNetMilli achieves 70.0% ImageNet Top-1 with 3.0M parameters; STYOLOMicro achieves 30.54% COCO mAP with 1.69M parameters, both running efficiently on STM32N6 MCUs using only standard convolutions.

## Executive Summary
This paper introduces STResNet (classification) and STYOLO (detection), a family of compact models designed for microcontrollers (MCUs) and neural processing units (NPUs). The core innovation is "CompressNAS," a framework that combines Tucker decomposition with a hardware-aware Neural Architecture Search (NAS) using Integer Linear Programming (ILP). This process optimally compresses a ResNet backbone by selecting layer-specific decomposition ranks under strict flash/parameter budgets, while exclusively using standard 1x1 and 3x3 convolutions to ensure predictable, efficient execution on embedded hardware. An architectural tweak—adding a projection layer in the stem—drastically reduces peak RAM usage for the detector variant with minimal accuracy loss.

## Method Summary
The methodology centers on CompressNAS. Starting from a ResNet-18 backbone, each convolutional layer is factorized via Tucker decomposition into a sequence of smaller kernels (1x1, 3x3, 1x1), reducing parameters and FLOPs. A NAS search, formulated as an ILP problem, then selects the optimal rank (compression factor) for every decomposed layer. The search objective trades off a predicted accuracy drop (estimated by an MSE-based zero-cost proxy computed from a single forward pass) against flash size reduction, subject to a predefined hardware constraint (e.g., maximum flash or parameter count). The resulting architectures, STResNet, use only standard convolution operations. For detection, the pretrained STResNet backbone is integrated with a YOLOX-style neck and head, with channel-projection layers to match feature dimensions. A key modification for memory-constrained devices reduces channels in the stem's final layer and restores them later via a projection, cutting peak activation memory.

## Key Results
- STResNetMilli (3.0M params) achieves 70.0% ImageNet Top-1 accuracy, outperforming MobileNetV1 (0.75x) and ShuffleNetV2 (0.5x) in accuracy-efficiency trade-offs on STM32N6 (18.29ms, 1.39MB RAM).
- STYOLOMicro (1.69M params) achieves 30.54% COCO mAP, surpassing YOLOv5n, with a RAM-efficient variant (STYOLOMicro-Proj) reducing memory by 42% (4.26MB → 2.46MB) for less than 0.5% mAP loss.

## Why This Works (Mechanism)
### Mechanism 1: CompressNAS (Tucker + ILP Search)
The claim is that combining Tucker decomposition with an ILP-based NAS to select per-layer ranks yields highly compressed ResNet variants competitive on MCUs. Tucker decomposes a convolution into three smaller ones, reducing parameters. The NAS globally searches for the rank configuration that minimizes an accuracy drop proxy (MSE) while meeting a flash constraint. Success hinges on the proxy correlating with true fine-tuned accuracy; if not, selected ranks cause larger-than-expected accuracy loss.

### Mechanism 2: Standard Convolutions for Hardware Efficiency
Using only 1x1 and 3x3 standard convolutions (avoiding depthwise separable or other specialized ops) ensures predictable, high-throughput inference on MCUs/NPUs. These fixed-function accelerators are heavily optimized for standard convs, avoiding dispatch overhead, quantization instability, and poor kernel fusion associated with exotic operators. This design may increase theoretical FLOPs but delivers better real-world latency and quantization robustness. The advantage collapses if the target hardware has ultra-efficient专用 accelerators for depthwise convolutions.

### Mechanism 3: Stem Projection Layer for RAM Reduction
A strategically placed 1x1 projection layer in the stem block reduces peak runtime RAM by ~42% with negligible accuracy loss for STYOLO. The stem's final 1x1 convolution (8→32 channels) outputs a large, high-channel feature map that dominates memory. Reducing these early channels (32→16) and adding a later projection (16→64) shrinks the maximum intermediate tensor size. Savings in external memory accesses can even improve latency. The approach fails if the backbone is highly sensitive to early feature richness.

## Foundational Learning
- **Tucker Decomposition:** A tensor factorization method that splits a convolutional kernel (M, N, k, k) into three smaller kernels (M, R, 1, 1), (R, R, k, k), (R, N, 1, 1). **Why needed:** It is the core compression primitive in CompressNAS. *Quick check: For input N=64, output M=128, k=3, and rank R=32, what is the approximate FLOP ratio of the decomposed layer vs. standard convolution?*
- **Hardware-Aware NAS with ILP:** Formulating the architecture search as an Integer Linear Program to globally optimize per-layer decisions (ranks) under explicit hardware constraints (e.g., flash). **Why needed:** It transforms the compression problem from heuristic to systematic, finding a Pareto-optimal trade-off between accuracy and size. *Quick check: Why might a per-layer accuracy proxy (one batch) be preferred over full retraining during search, and what is a key risk of this approximation?*
- **Quantization for MCUs:** The process of converting floating-point models to low-precision integers (e.g., INT8) for efficient execution on integer-only hardware. **Why needed:** MCUs/NPUs require quantization; standard convolutions are claimed "quantization-friendly" versus depthwise convolutions, which can suffer from activation distribution narrowness causing large accuracy drops. *Quick check: What is a typical post-training quantization (PTQ) challenge for depthwise separable convolutions that standard convolutions avoid?*

## Architecture Onboarding
- **Component map:** CompressNAS Engine -> STResNet Backbone Family -> STYOLO Detector (with channel-projected neck) -> RAM-Efficient Variant (with stem projection).
- **Critical path:** Base ResNet -> Per-layer Tucker rank proposals -> MSE & flash estimation -> ILP search -> Selected STResNet architecture -> ImageNet pre-training -> (Detection) Attach YOLOX neck/head -> Fine-tune on COCO with layer-wise LR scaling. The stem projection is a post-tuning modification for RAM.
- **Design tradeoffs:**
  - Accuracy vs. Compression: Higher ILP flash constraint → higher ranks → better accuracy (e.g., Tiny 71.6% vs. Pico 48.8%).
  - Standard Ops vs. Specialized Efficiency: Standard 3x3 convs guarantee hardware support and quantization stability at the cost of higher theoretical FLOPs.
  - RAM vs. Latency: Stem projection reduces peak RAM (42%) and may improve latency by cutting memory accesses.
  - Pre-trained Backbone vs. End-to-End: ImageNet-pretrained STResNet backbones yield faster convergence and higher mAP in STYOLO.
- **Failure signatures:**
  - CompressNAS accuracy drop >5%: MSE proxy may be invalid, ILP constraint too aggressive, or fine-tuning insufficient.
  - STYOLO mAP << YOLOv5n (~28%): Check neck projection dimensions, learning rate schedule, or backbone initialization.
  - RAM >4MB on STM32N6: Stem projection layer not applied or insufficient.
  - Quantized accuracy collapse: Model may rely on operations sensitive to quantization (should be mitigated by standard convs), indicating poor calibration.
- **First 3 experiments:**
  1. **Decomposition Impact Validation:** For a single ResNet block, apply Tucker with ranks R=[8,16,32,64]. Compute MSE proxy and finetune briefly; verify proxy correlates with accuracy loss.
  2. **ILP Search Sanity Check:** Run CompressNAS with varying flash constraints. Expect selected ranks to monotonically increase with budget. Force a rank outside the ILP's Pareto front to measure accuracy penalty.
  3. **Projection Layer RAM Profiling:** Deploy STYOLOMicro with/without stem projection on STM32N6. Profile peak activation memory to confirm the ~42% reduction originates from the stem's output tensor.

## Open Questions the Paper Calls Out
- **Mixed-Precision Quantization in CompressNAS:** How can mixed-precision quantization be integrated into the CompressNAS framework to jointly optimize bit-width and layer decomposition rank for improved accuracy-efficiency trade-offs on MCUs?
- **Multi-Task Adaptation:** How can the STResNet backbone be effectively adapted for multi-task edge vision tasks (e.g., segmentation, keypoint detection) while preserving the hardware efficiency demonstrated in classification and detection?
- **Cross-Hardware Adaptive Compression:** What cross-hardware adaptive compression methods can automatically tune decomposition ranks and channel scaling in CompressNAS for diverse MCU, NPU, and DSP architectures?

## Limitations
- **NAS Search Transparency:** Exact ILP formulation, search space details (rank step sizes), and accuracy-drop tolerances are undisclosed, limiting verification of claimed optimality.
- **Training Details:** Missing critical hyperparameters (batch size, LR schedule specifics, QAT method) and precise MSE proxy computation create reproduction risk.
- **Proxy Generalizability:** The MSE-based zero-cost proxy's correlation with finetuned accuracy across all layers and ranks is assumed but not externally validated.

## Confidence
- **STResNet/STYOLO achieve SOTA accuracy-efficiency on MCUs:** **Medium** (Relies on internal benchmarks; hardware data is strong but not cross-validated against all recent competitors like MCUNet in identical settings).
- **CompressNAS yields hardware-efficient architectures:** **Medium** (Architectural outcomes are concrete, but search mechanism's optimality is unverified due to undisclosed ILP details).
- **Standard convolutions enable predictable MCU efficiency:** **Medium-High** (Supported by hardware latency data and logical argument; lacks head-to-head test vs. specialized ops on same hardware with matched metrics).
- **Stem projection reduces RAM by 42% with minimal loss:** **High** (Directly evidenced by Table 8; mechanism is clear and validated).
