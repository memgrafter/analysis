# ITQ3_S: High-Fidelity 3-bit LLM Inference via Interleaved Ternary Quantization with Rotation-Domain Smoothing

## Quick Facts
- **ArXiv ID:** 2603.27914
- **Source URL:** https://arxiv.org/abs/2603.27914
- **Reference count:** 13
- **Primary result:** On NVIDIA RTX 5090 with LLaMA-3 8B, ITQ3_S achieves WikiText-2 perplexity 6.52 (vs FP16 6.14), 1.5× higher throughput than 4-bit baselines, and reduces memory footprint to 3.1 GiB via 3.125 bits/weight.

## Executive Summary
ITQ3_S presents a novel approach to ultra-low-bit quantization of large language model weights, targeting 3-bit precision without the typical catastrophic loss in model quality. The core idea is to pre-rotate each 256-element weight block with a deterministic Fast Walsh-Hadamard Transform (FWHT), which smooths the distribution by redistributing outlier energy, enabling effective uniform ternary quantization. The rotated values are then quantized to {-1,0,+1}, packed in an interleaved 3-bit format optimized for NVIDIA's DP4A instructions, and stored with per-block scales.

During inference, a fused CUDA kernel loads the packed weights, unpacks and dequantizes them directly into shared memory, applies the exact inverse FWHT in-place, and feeds the recovered weights to Tensor Cores. This design eliminates any extra memory traffic for dequantized weights and ensures mathematically exact reconstruction up to the quantization error. On an RTX 5090, LLaMA-3 8B quantized with ITQ3_S attains WikiText-2 perplexity 6.52 (vs. 6.14 for full precision and 7.03 for prior 3-bit work), narrowing the FP16 gap by 57%. It also delivers 960 decode and 51,200 prefill tokens per second, exceeding 4-bit alternatives by 1.5×, while shrinking the model to just 3.1 GiB.

## Method Summary
The offline quantization pipeline processes weight tensors in fixed 256-element blocks. Each block undergoes a Fast Walsh-Hadamard Transform; the transformed values are scaled by an optimal factor α* = 0.798σ (derived from Gaussian MSE minimization) and zero-point adjusted. Quantization to ternary levels follows, with values mapped to bit patterns and packed two-per-32-bit word in an interleaved layout to align with DP4A instruction boundaries. Per-block scale and zero-point metadata are stored alongside.

The online inference kernel (`load_tiles_itq3_s`) is launched with 256 threads per block. Each thread extracts its assigned 3-bit values from the packed global memory load via bitwise operations, dequantizes to half precision, and stores into shared memory. After a barrier, all threads cooperatively perform an 8-stage in-place inverse FWHT butterfly directly in shared memory, applying a single final scaling. The recovered weight tile is then used in matrix multiplication via Tensor Cores. This fusion avoids writing intermediate dequantized weights to global memory, preserving fidelity and maximizing data locality.

## Key Results
- WikiText-2 perplexity: 6.52 (vs FP16 6.14, IQ3_S 7.03), reducing the FP16 gap by 57%.
- Throughput: 960 decode tokens/s and 51,200 prefill tokens/s on RTX 5090, exceeding 1.5× that of 4-bit alternatives.
- Memory footprint: 3.1 GiB for LLaMA-3 8B using 3.125 bits/weight; theoretical reconstruction error strictly smaller than any uniform 3-bit baseline under equal bit constraints.

## Why This Works (Mechanism)

### Mechanism 1: Distribution Smoothing via FWHT
- **Claim:** The deterministic Fast Walsh-Hadamard Transform (FWHT) rotation smooths heavy-tailed weight distributions by spreading outlier energy uniformly across all transformed coefficients, making them amenable to uniform ternary quantization.
- **Mechanism:** For a weight block of 256 elements, the FWHT (a self-inverse orthogonal transform) mixes all entries. A single large outlier $w_j = M$ contributes only $M/\sqrt{256}$ to each transformed coefficient, reducing the $\ell_\infty$ norm. By the Central Limit Theorem for Walsh transforms, the transformed entries converge to a near-Gaussian distribution with smaller dynamic range, allowing a tighter ternary grid scale $d_k$.
- **Core assumption:** Transformer weight matrices contain structured inter-channel outliers that dominate the dynamic range of uniform quantizers. The FWHT's mixing property effectively redistributes this outlier energy.
- **Evidence anchors:**
  - [abstract]: "pre-rotating the weight space via FWHT prior to quantization, effectively spreading outlier energy across the entire vector and inducing a near-Gaussian distribution amenable to uniform ternary coding."
  - [section 3.1]: Theorem 1 (Distribution Smoothing) and Corollary 1 (Outlier Suppression) formalize the expected $\ell_\infty$ reduction factor of $w_{\text{max}}/(3\sigma)$ for $n=256$.
  - [corpus]: Neighbors like QuIP# [4] use random rotations for incoherence, but ITQ3_S's deterministic FWHT is a specific instance. The corpus shows active research on rotation-based methods, supporting the premise that rotations mitigate outlier issues. *Evidence strength: moderate; corpus shows related approaches but not direct validation of FWHT's specific smoothing effect.*
- **Break condition:** If weight distributions are already near-Gaussian with minimal outliers, the FWHT rotation provides negligible smoothing benefit, and its compute overhead may not be justified.

### Mechanism 2: Interleaved Ternary Packing for DP4A
- **Claim:** Interleaved ternary packing aligns 3-bit quantized values into 32-bit words optimized for the RTX 5090's DP4A (INT8×INT4) instruction, maximizing memory throughput and Tensor Core utilization during matrix multiplication.
- **Mechanism:** Two ternary nibbles (each representing a 3-bit value) are packed into a single 32-bit word with a selector bit. The CUDA kernel uses a single 32-bit load and bitfield extraction to recover two ternary values simultaneously. This aligns with the DP4A unit's 32-bit granularity and ensures 128-byte cache-line alignment for the 100-byte ITQ3_S block, minimizing memory traffic.
- **Core assumption:** The Blackwell architecture's DP4A unit achieves peak efficiency when processing data aligned to 32-bit words, and the memory subsystem benefits from cache-line-aligned accesses.
- **Evidence anchors:**
  - [abstract]: "optimized DP4A and Tensor Core scheduling in the interleaved memory layout."
  - [section 4.2]: Defines the interleaved packing scheme (Eq. 9) explicitly for DP4A optimization.
  - [section 5.3]: Notes the kernel design "maximizing L1 cache utilization."
  - [corpus]: Neighbors like TeLLMe v2 use table-lookup matmul for ternary LLMs on FPGAs, indicating hardware-aware packing is a known efficiency lever. *Evidence strength: weak; corpus does not address NVIDIA DP4A specifically.*
- **Break condition:** On architectures without efficient sub-32-bit integer instructions (e.g., older GPUs, CPUs), the interleaving overhead may outweigh benefits, requiring a different packing scheme.

### Mechanism 3: Fused Inverse Transform for Zero-Overhead Dequantization
- **Claim:** Fusing the 256-point inverse Walsh-Hadamard Transform (IFWHT) into the CUDA shared-memory loading stage eliminates off-chip memory traffic for dequantized weights and ensures mathematically exact round-trip reconstruction (up to ternary quantization error).
- **Mechanism:** After loading and dequantizing ternary values into shared memory, the kernel performs the IFWHT butterfly stages in-place within shared memory. Because the FWHT is involutory ($H^{-1} = H$), applying the same butterfly steps recovers the original weight vector exactly, except for the quantization error introduced in the transformed domain. This avoids storing intermediate dequantized weights in global memory.
- **Core assumption:** The 256-element weight tile fits entirely within the 192 KB shared memory per SM of the RTX 5090, and the butterfly stages can be synchronized efficiently with `__syncthreads()`.
- **Evidence anchors:**
  - [abstract]: "fuses the exact inverse transform into CUDA shared-memory loading for zero-error round-trip fidelity."
  - [section 5.2]: Algorithm 2 explicitly details the fused kernel: dequantize to shared memory, then IFWHT butterfly stages, then matmul.
  - [section 5.3]: Proposition 1 proves $\hat{w} \approx H^{-1}(Hw) = w$, with error bounded solely by ternary quantization.
  - [corpus]: No direct evidence; this is a novel kernel-fusion contribution specific to ITQ3_S. *Evidence strength: none from corpus; relies solely on paper's proof and implementation.*
- **Break condition:** If shared memory capacity is insufficient for the block size (e.g., on smaller GPUs) or if synchronization overhead dominates, the kernel would need to fall back to a multi-pass approach with global memory traffic, breaking the zero-overhead claim.

## Foundational Learning

#### Walsh-Hadamard Transform (WHT)
- **Why needed here:** The core innovation relies on the WHT's properties: self-inverse, orthogonal, and ability to mix vector entries uniformly. Understanding the butterfly algorithm and normalization ($1/\sqrt{n}$) is essential to grasp why the IFWHT can be fused without extra scaling steps.
- **Quick check question:** Why does the WHT's self-inverse property ($H^2 = I$) enable exact reconstruction after quantization in the transform domain?

#### Ternary Quantization
- **Why needed here:** ITQ3_S uses a 3-value quantizer $\{-1, 0, +1\}$ per weight, requiring careful scale computation ($d_k$) to minimize distortion. The interleaved packing scheme builds on this ternary set.
- **Quick check question:** How does the optimal ternary scale $\alpha^* \approx 0.798\sigma$ for a Gaussian distribution derive from minimizing MSE, and why is it smaller than the uniform 3-bit grid spacing?

#### CUDA Shared Memory & Warp-Level Primitives
- **Why needed here:** The fused kernel's performance hinges on using shared memory for the IFWHT and warp shuffles for the MMVQ path. Understanding memory hierarchy, bank conflicts, and synchronization is critical to replicate the design.
- **Quick check question:** What is the role of `__syncthreads()` in the IFWHT butterfly stages, and why could omitting it cause race conditions?

## Architecture Onboarding
**Component map:** Offline pipeline: FWHT → compute per-block scale $d_k$ & zero-point $z_k$ → ternary quantization → interleaved 3-bit packing → store to disk. Online kernel (load_tiles_itq3_s): global load of packed quants & scales → unpack 3-bit values → dequantize to shared memory → in-place 256-point IFWHT → feed to MMA (Tensor Core) instructions.

**Critical path:** The latency-determining sequence is: global memory load (packed quants) → bitfield unpack → dequantize → 8-stage IFWHT (with syncs) → MMA. The IFWHT's $O(n \log n)$ steps and synchronization points are the dominant additional cost vs. a baseline 3-bit dequantizer.

**Design tradeoffs:**
- *FWHT block size:* Larger $n$ improves distribution smoothing (lower perplexity) but increases IFWHT overhead and shared memory pressure. Paper's ablation shows $n=256$ as optimal for RTX 5090.
- *Interleaving vs. simplicity:* Interleaving complicates packing/unpacking but is necessary for DP4A throughput. A non-interleaved layout would simplify code but likely reduce decode speed by >15%.
- *Normalization factor:* Applying $1/\sqrt{256}$ once after all butterfly stages (vs. per-stage) reduces floating-point operations but requires careful scaling to avoid overflow in half-precision intermediate sums.

**Failure signatures:**
- *Quality collapse:* Perplexity degradation >0.5 vs. IQ3_S indicates insufficient smoothing (try larger block size or check FWHT implementation).
- *Low throughput:* Decode speed <800 tok/s on RTX 5090 suggests suboptimal memory coalescing (check 128-byte alignment) or excessive shared memory bank conflicts (check butterfly access pattern).
- *Numerical drift:* If validation perplexity varies run-to-run, suspect finite-precision error in IFWHT (use float instead of half in shared memory).

**First 3 experiments:**
1. *Validate FWHT smoothing:* On a held-out weight block, compute $\|Hw\|_\infty$ vs. $\|w\|_\infty$ and plot histograms of $Hw$ and $w$. Expect $\|Hw\|_\infty$ to be ~3× smaller and distribution to appear more Gaussian.
2. *Benchmark fused kernel throughput:* Compare `load_tiles_itq3_s` against a baseline IQ3_S dequantizer (no IFWHT) using CUDA events. Measure the % overhead of the 8-stage IFWHT; expect ~2% as reported.
3. *Ablation: block size & interleaving:* Run LLaMA-3 8B with $n \in \{128, 256, 512\}$ and with/without interleaving. Record WikiText-2 PPL and decode tok/s. Confirm $n=256$ gives best PPL/speed tradeoff and interleaving improves throughput by ≥10%.

## Limitations
- **Packing format precision:** The exact interleaved 3-bit layout for DP4A optimization is underspecified; minor deviations could break memory alignment or throughput.
- **Hardware-specific tuning:** Claims about Blackwell architecture efficiency (DP4A, shared memory) lack cross-architecture validation; older GPUs may fall back poorly.
- **Corpus validation gap:** Neighboring papers (e.g., TeLLMe v2) use ternary quantization but do not independently verify FWHT’s outlier-smoothing effect for LLMs.
