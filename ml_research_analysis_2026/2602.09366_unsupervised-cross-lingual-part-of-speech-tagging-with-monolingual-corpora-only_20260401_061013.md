# Unsupervised Cross-Lingual Part-of-Speech Tagging with Monolingual Corpora Only

## Quick Facts
- **arXiv ID:** 2602.09366  
- **Source URL:** https://arxiv.org/abs/2602.09366  
- **Reference Count:** 39  
- **Primary Result:** Using only monolingual data, the proposed framework achieves >60% POS tagging accuracy on 28 low-resource language pairs via unsupervised NMT and multi-source projection.

## Executive Summary
Cross-lingual part-of-speech (POS) tagging for low-resource languages traditionally depends on parallel corpora to project annotations from a resource-rich source. This work eliminates that requirement by leveraging unsupervised neural machine translation (UNMT) to generate pseudo‑parallel sentences from monolingual data. The pipeline translates a high‑resource source (e.g., English) into the target language, aligns the sentences with GIZA++, projects POS tags from a Stanza‑annotated source, calibrates multiple projections via majority voting on overlapping words, and trains a BiLSTM tagger on the resulting labeled target data.  

On 28 language pairs, the method surpasses 60% tagging accuracy for every target, matching the performance of a baseline that uses genuine parallel corpora. For typologically similar languages (Portuguese, Afrikaans) it even exceeds the parallel baseline by 2.6–3.3%, and multi‑source calibration yields an average improvement of 1.3% over prior single‑source approaches. The results demonstrate that high‑quality cross‑lingual POS tagging is feasible without any parallel resources.

## Method Summary
The framework uses only monolingual corpora for both source and target languages. For each source‑target pair:

1. **UNMT training** – A Lample‑et‑al. model is trained on 10M CC‑100 sentences per language using denoising autoencoding and back‑translation.  
2. **Pseudo‑parallel generation** – The trained UNMT translates 100k Europarl source sentences into the target language.  
3. **Source POS annotation** – Source sentences are tagged with Stanza (trained on Universal Dependencies).  
4. **Word alignment** – Bidirectional GIZA++ aligns the pseudo‑parallel pair; alignments with probability < 0.1 are discarded.  
5. **Tag projection** – POS tags are projected from source to target using the alignments, enforced by token/type constraints (each target token receives at most one tag, and repeated tokens share a tag).  
6. **Multi‑source calibration** – When multiple source languages are available, overlapping words in the target sentences are identified (exact string match). For each overlapping word, the final POS tag is decided by majority vote among the projections.  
7. **Target POS tagger** – A BiLSTM+softmax model, using word and affix n‑gram embeddings, is trained on the projected target sentences and evaluated on the UD test set.

Hyperparameters for UNMT and the tagger are listed in Tables 3 and 4 of the paper.

## Key Results
- Achieves **>60% tagging accuracy** on all 28 target languages, comparable to a parallel‑corpora baseline.
- For typologically similar languages (e.g., Portuguese, Afrikaans), **outperforms the baseline by 2.6–3.3%**.
- Multi‑source projection yields an **average improvement of 1.3%** over previous single‑source methods.

## Why This Works (Mechanism)
The UNMT system produces pseudo‑parallel sentences of sufficient lexical and structural similarity to support reliable word alignment, even for distant language pairs. Token/type constraints ensure consistent tag assignments across repeated tokens, reducing projection noise. Multi‑source calibration aggregates independent projections, effectively voting out errors and increasing coverage for words that appear in translations from several sources. Finally, the BiLSTM tagger learns robust patterns from the large, albeit noisy, projected dataset, achieving strong performance on the true UD test sets.

## Foundational Learning
- **Unsupervised Neural Machine Translation (UNMT)**  
  *Why needed:* Generates pseudo‑parallel data without parallel corpora.  
  *Quick check:* Train on a held‑out validation set; compute BLEU scores (target >10 for distant, >25 for similar languages).

- **Word Alignment (GIZA++)**  
  *Why needed:* Maps source tokens to target tokens for POS projection.  
  *Quick check:* Visualize alignment matrices or compute precision against a small gold‑aligned set.

- **Cross‑lingual Projection with Token/Type Constraints**  
  *Why needed:* Enforces one‑tag‑per‑token and consistency for repeated tokens, mitigating alignment errors.  
  *Quick check:* Ablate the constraints and measure tag consistency on a sample of projected sentences.

- **Multi‑source Calibration (Majority Voting)**  
  *Why needed:* Combines projections from different sources to resolve ambiguities and improve accuracy.  
  *Quick check:* Compare single‑source vs. multi‑source projection quality on overlapping target words.

## Architecture Onboarding
**Component map:**  
Monolingual corpora (CC-100) → UNMT training → UNMT model → Translate Europarl source → Pseudo‑parallel sentence pairs → Source POS tagging (Stanza) → Bidirectional word alignment (GIZA++) → Filter low‑confidence alignments (α=0.1) → Tag projection with token/type constraints → Multi‑source majority voting (for overlapping words) → Projected target training set → BiLSTM POS tagger → Evaluation on UD test set.

**Critical path:**  
1. Train UNMT for each source‑target pair.  
2. Translate the fixed Europarl set.  
3. Align and project POS tags.  
4. Apply multi‑source calibration (if multiple sources).  
5. Train the BiLSTM tagger.  
6. Evaluate on the target UD test set.

**Design tradeoffs:**  
- **UNMT quality** vs. compute: higher quality requires more data and longer training.  
- **Alignment threshold α**: low α increases coverage but adds noise; high α reduces noise but may leave many words unannotated.  
- **Single‑ vs. multi‑source**: multi‑source improves accuracy but requires training several UNMT models and handling overlapping‑word logic.  
- **BiLSTM simplicity** vs. potential performance: more complex models (e.g., Transformers) might tag better but were not explored.

**Failure signatures:**  
- UNMT BLEU < 10 → likely tagging accuracy < 60%.  
- Alignment density (fraction of target tokens aligned) below ~70% → insufficient training instances.  
- Multi‑source degrades accuracy → overlapping words are rare or ambiguous.  
- High OOV rate on UD test set relative to projected vocabulary → poor generalization.

**Three first experiments:**  
1. **Data verification** – Confirm CC‑100/EUROPARL download, preprocessing, and BPE application; check vocabulary sizes.  
2. **UNMT training** – Train a small UNMT model (e.g., en→pt) on 1M sentences for 10 epochs; monitor validation BLEU to ensure convergence.  
3. **End‑to‑end pipeline test** – Using the trained UNMT, generate pseudo‑data for 10k sentences, project tags, train the BiLSTM tagger, and evaluate on a UD test set; compare to the paper’s reported score.

## Limitations
- The method is sensitive to UNMT quality, which depends on hyperparameters (noise function, back‑translation schedule) not fully disclosed.  
- Multi‑source calibration logic (e.g., how “best‑performing” pseudo‑target sentences are chosen and how overlapping words are detected) is underspecified, hindering exact replication.  
- Performance on typologically distant languages falls below the >60% claim, limiting universality.  
- Requires large monolingual corpora (10M sentences) for both source and target, which may be unavailable for the lowest‑resource languages.

## Next Checks
1. **Reproduce UNMT BLEU with variants** – For at least one language pair (e.g., en→pt), train UNMT with different noise drop rates (0.1, 0.3, 0.5) and back‑translation schedules (every epoch vs. every 5 epochs); measure validation BLEU to test robustness of reported scores.  
2. **Audit multi‑source calibration** – For a target language with multiple sources (e.g., Basque from en, es, fr), manually inspect 50 sentence triples; reconstruct majority voting under exact‑string and lemmatized overlap; record how often the vote differs from single‑source projections.  
3. **Alignment threshold sensitivity** – For a single source‑target pair, vary the alignment probability threshold α from 0.01 to 0.5; for each, project tags, train the POS tagger, and evaluate on UD test; identify the optimal threshold and assess whether the fixed α=0.1 is near‑optimal.
