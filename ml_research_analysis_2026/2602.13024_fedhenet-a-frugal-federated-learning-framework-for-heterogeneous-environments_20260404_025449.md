# FedHENet: A Frugal Federated Learning Framework for Heterogeneous Environments
## Quick Facts
- **arXiv ID**: 2602.13024
- **Source URL**: https://arxiv.org/abs/2602.13024
- **Reference count**: 5
- **Primary result**: FedHENet achieves competitive accuracy (e.g., 83.69% in extreme non-IID) with up to 70% energy reduction via a single communication round and hyperparameter-free design.

## Executive Summary
Federated Learning (FL) faces significant challenges in heterogeneous environments: high computational costs due to iterative local training, client drift caused by non-IID data distributions, and privacy risks from sharing raw gradients. FedHENet tackles these inefficiencies by employing a frozen, pre‑trained feature extractor (ResNet-18 on ImageNet) and learning only the final output layer via a closed‑form analytical solution (ROLANN) that leverages homomorphic encryption (CKKS). This design eliminates the need for multiple communication rounds, local fine‑tuning, and hyperparameter tuning, while preserving privacy by keeping client statistics encrypted throughout aggregation. Evaluations on CIFAR-10 and CIFAR-100 under extreme non‑IID splits demonstrate that FedHENet achieves high accuracy (e.g., 83.69% vs. 33‑40% for baselines), reduces energy consumption by up to 70%, and exhibits superior stability, all with negligible homomorphic encryption overhead (<5% time, 2.25× payload size).

## Method Summary
FedHENet’s protocol is strikingly simple: all clients and the server share an identical, non‑trainable backbone (a ResNet‑18 pretrained on ImageNet). Each client extracts fixed‑dimensional feature vectors from its local images using this frozen extractor. From these features, it computes a matrix \(M^k\) that captures the regularized least‑squares relationship to the local labels. \(M^k\) is encrypted with the CKKS homomorphic encryption scheme, while the singular value decomposition components \(U^k, S^k\) are transmitted in plaintext. A coordinator aggregates all encrypted \([[M^k]]\) by homomorphic summation, then constructs global matrices \(U, S\) from the plaintext \(U^k, S^k\). Using the closed‑form solution \(W = U \cdot (S \cdot S + \lambda I)^{-1} U^T [[M]]\), the coordinator derives the optimal classifier weights \(W\) in a single analytical step, decrypts, and broadcasts the plaintext weights back to the clients. No local backpropagation, iterative rounds, or hyperparameter searches are required, drastically cutting computational load, communication volume, and carbon footprint.

## Key Results
- **Accuracy on extreme non‑IID**: FedHENet attains 83.69% on CIFAR‑10 (single‑class client assignments), while FedAvg and FedProx collapse to 33‑40%.
- **Energy reduction**: Up to 70% savings; e.g., 11.5 Wh vs. 36.5 Wh for CIFAR‑10 (\(N=10\)) and 118.9 Wh vs. ~240 Wh for CIFAR‑100 (\(N=100\)).
- **Efficiency and privacy**: Homomorphic encryption adds negligible overhead (<5% computation time, payload increase of ~2.25×) and protects client data; the method is hyperparameter‑free, removing tuning emissions.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Using a frozen, pre‑trained feature extractor eliminates costly local fine‑tuning and provides a common representation space.
- **Mechanism:** All clients and the server share an identical, non‑trainable backbone (ResNet‑18 pretrained on ImageNet). Clients map their local images to fixed‑dimensional embeddings, removing local backpropagation through the bulk of the network.
- **Core assumption:** Generic, high‑level visual features extracted from a large dataset (ImageNet) are sufficiently transferable and stable across heterogeneous client data distributions for the downstream classification task.
- **Evidence anchors:**
  - [abstract]: "...using a fixed, pre‑trained feature extractor... we avoid costly local fine‑tuning."
  - [section 2]: "...combines a fixed, pre‑trained... feature extractor... By not performing any fine‑tuning, we avoid high computational and energy costs."
  - [corpus]: Neighboring papers on federated learning for heterogeneous devices and one‑shot FL frequently use frozen backbones for efficiency, providing indirect context.
- **Break condition:** Performance degradation would occur if the target domain data is extremely dissimilar from ImageNet (e.g., medical microscopy, satellite radar), where the frozen features lack task‑relevant semantics.

### Mechanism 2
- **Claim:** Learning the output layer via a closed‑form analytical solution (ROLANN) using homomorphically encrypted client statistics enables exact, single‑round global aggregation.
- **Mechanism:** Instead of iterative gradient descent on local data, each client computes a specific matrix \(M^k\) (a weighted correlation between features and target pre‑activations) from its frozen features. This \(M^k\) is homomorphically encrypted (CKKS) and sent to a coordinator. The coordinator sums all encrypted \([[M^k]]\) and, using publicly shared SVD components (\(U, S\)), computes the global optimal weights \(W\) in one analytical step via \(W = U\cdot(S\cdot S+\lambda I)^{-1}U^T [[M]]\).
- **Core assumption:** The problem of learning the final linear layer can be reformulated as a regularized least‑squares problem with a closed‑form solution, and the sensitive information is contained solely within the encrypted \(M^k\) matrix.
- **Evidence anchors:**
  - [abstract]: "...learning only a single output layer... analytically aggregating client knowledge in a single round of communication using homomorphic encryption."
  - [section 2]: Detailed equations (1)-(3) define the SVD decomposition and the closed‑form weight calculation.
  - [section 3]: Table 3 shows the HE overhead is negligible (<5% time, 2.25× payload).
- **Break condition:** The linear assumption of ROLANN may fail for highly non‑linear decision boundaries. Furthermore, if the encryption scheme (CKKS) is broken or if noise growth in the homomorphic operations during summation exceeds the scheme's parameters for large \(K\), exact decryption fails.

### Mechanism 3
- **Claim:** The single‑round protocol inherently eliminates client drift and removes the need for hyperparameter tuning, leading to superior stability and sustainability.
- **Mechanism:** Because the global model weights are computed exactly from aggregated encrypted statistics in one shot, there is no iterative local optimization where client updates could diverge due to heterogeneous data. The method has no learning rate, local epochs, or regularization coefficients to tune for convergence.
- **Core assumption:** Exact aggregation of client knowledge (via the analytical solution) produces a globally optimal model without the need for iterative consensus‑building steps used in FedAvg/FedProx.
- **Evidence anchors:**
  - [abstract]: "...eliminating iterative local training and hyperparameter tuning... superior stability performance... hyperparameter‑free."
  - [section 3]: Table 1 shows FedHENet maintains ~83.6% accuracy in extreme non‑IID ("single class") where FedAvg/FedProx collapse to ~33‑40%. Text states: "FedHENet, relying on exact analytical aggregation, remains immune to drift."
  - [section 3]: Discussion on energy savings explicitly links frugality to the elimination of the hyperparameter tuning phase.
- **Break condition:** If the feature distributions across clients are so heterogeneous that the shared frozen backbone produces non‑alignable embeddings, the single aggregated \(M\) may not represent a coherent global decision boundary, leading to poor accuracy.

## Foundational Learning
- **Concept:** Federated Learning (FL) Heterogeneity (Statistical & Systems)
  - **Why needed here:** The paper's primary motivation is addressing "client drift" and inefficiency caused by non‑IID (statistically heterogeneous) data and heterogeneous client capabilities. Understanding the core FL problem (distributed optimization without data centralization) and the specific failure mode of FedAvg under heterogeneity is prerequisite.
  - **Quick check question:** Why does averaging local gradients (FedAvg) fail when each client's data has only a subset of classes (e.g., "single‑class" scenario)?
- **Concept:** Homomorphic Encryption (CKKS scheme)
  - **Why needed here:** The privacy guarantee and the core single‑round mechanism rely on performing arithmetic operations directly on encrypted client data (\([[M^k]]\)). Understanding that CKKS allows approximate arithmetic on real numbers (vs. integer‑only schemes like BFV) is key to seeing why it's chosen for this statistical aggregation.
  - **Quick check question:** What is the fundamental difference between "somewhat" and "fully" homomorphic encryption, and why is CKKS (a leveled, somewhat HE scheme) sufficient for this one‑step aggregation?
- **Concept:** Regularized Least Squares / Ridge Regression
  - **Why needed here:** The ROLANN layer's training is mathematically equivalent to a ridge regression problem solved in closed form. The paper's equation (3) \(W = U\cdot(S\cdot S+\lambda I)^{-1}U^T [[M]]\) is a direct application of this. Grasping this connection is essential to understand why no gradient descent is needed.
  - **Quick check question:** In the closed‑form solution \(w = (X^TX + \lambda I)^{-1}X^Ty\), what role does the regularization term \(\lambda I\) play, and how does it relate to the \(S\cdot S+\lambda I\) term in the SVD‑based formulation?

## Architecture Onboarding
- **Component map:** Client (compute encrypted \([[M^k]]\) and plaintext \([U^k,S^k]\)) → Coordinator (homomorphic aggregation, analytical weight computation) → Client (receive plaintext \(W\) and deploy)
- **Critical path:** Feature extraction (\(X^k\)) → \(M^k\) computation → HE encryption → Communication → Homomorphic aggregation → Analytical weight synthesis → Broadcast → Deployment. The single round defines the path.
- **Design tradeoffs:**
  - *Frozen Backbone vs. Adaptability:* Extreme computational/energy savings vs. loss of domain‑specific feature tuning.
  - *HE Payload vs. Privacy:* Larger encrypted \(M^k\) (2.25×) vs. strong confidentiality (gradients/masks not shared).
  - *Single‑Round vs. Model Capacity:* Frugality/stability vs. limitation to a linear classifier on top of fixed features.
- **Failure signatures:**
  - **Low accuracy in deployment:** Mismatch between ImageNet pre‑training domain and client data domain (frozen features are irrelevant).
  - **Coordinator decryption failure:** Noise accumulation in summed \([[M]]\) exceeds CKKS parameters (scale/\(\log Q\)), often with massive client counts (\(N\)).
  - **MQTT message loss/partition:** Single‑round protocol has no retry mechanism built‑in; a lost client message yields an incomplete aggregation and invalid \(W\).
- **First 3 experiments:**
  1. **Replication of Table 1:** Run the exact CIFAR‑10/100 experiments with \(N=10\), \(\alpha=0.1\) and "single‑class" to verify the stark accuracy contrast with FedAvg/FedProx.
  2. **HE Overhead Isolation:** Measure time and payload size for \(M^k\) computation/encryption/decryption with and without HE (as in Table 3) to isolate the cost of the privacy mechanism.
  3. **Feature Space Divergence Test:** Artificially corrupt the input to the frozen backbone (e.g., Gaussian noise, color channel swap) to simulate domain shift and measure accuracy drop, testing the "common representation" assumption.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does FedHENet's performance (accuracy, efficiency) scale when deployed on real‑world, resource‑constrained heterogeneous edge hardware (e.g., Raspberry Pi clusters) compared to simulated environments?
- **Basis in paper:** [explicit] "For future work, we plan to validate FedHENet on heterogeneous edge hardware (e.g., Raspberry Pi clusters) to precisely measure real‑world performance metrics."
- **Why unresolved:** The paper's experiments were conducted on a high‑end workstation. Performance on devices with vastly different compute, memory, and power constraints (common in FL scenarios) is unknown and could affect feasibility and measured frugality.
- **What evidence would resolve it:** Empirical benchmarking of FedHENet (and baselines) on a physical testbed of diverse edge devices, measuring accuracy, execution time, energy consumption, and communication overhead under realistic network conditions.

### Open Question 2
- **Question:** Can the FedHENet framework, which relies on a frozen pre‑trained backbone, be effectively extended to other foundational vision architectures like Vision Transformers (ViTs), and does this impact its frugality and robustness trade‑offs?
- **Basis in paper:** [explicit] "We will also explore the use of other foundational backbones, such as Vision Transformers."
- **Why unresolved:** The study uses a frozen ResNet‑18. ViTs have different feature representations and computational properties. The closed‑form ROLANN solution depends on feature dimensionality and statistical properties; changing the backbone could affect the analytical aggregation's stability, accuracy, and the size/security of the encrypted matrix \([[M]]\).
- **What evidence would resolve it:** Implementing FedHENet with frozen ViT variants (e.g., ViT‑Base, small). Comparing accuracy, stability under non‑IID, communication payload size (impact on HE), and computational cost against the ResNet‑18 results on standard datasets.

### Open Question 3
- **Question:** At what scale (number of clients \(K\)) does the linear increase in homomorphic encryption (HE) computation and communication payload for \([[M]]\) become a dominant bottleneck, negating FedHENet's frugal advantages compared to iterative methods?
- **Basis in paper:** [inferred] The paper notes HE overhead (2.25× payload inflation, <5% time) is "negligible for a moderate number of clients" but "could become more noticeable in massive‑scale federations, where encryption and communication costs scale linearly with the client count." The experiments are limited to \(N=500\) max.
- **Why unresolved:** The "massive‑scale" threshold is undefined. A linear scaling cost for HE operations and decryption on the server may eventually outweigh the savings from a single round, especially if client count grows into the thousands or tens of thousands.
- **What evidence would resolve it:** A formal complexity analysis and empirical stress tests with simulated large client populations (\(K > 1000\), 10,000). Measuring server‑side decryption/aggregation time and total communication volume per client to identify the crossover point where HE overhead surpasses the cumulative cost of multiple gradient‑based rounds.

### Open Question 4
- **Question:** Does FedHENet's analytical solution and immunity to client drift hold for all forms of extreme data heterogeneity, or is its robustness specific to the Dirichlet‑based and "single‑class" non‑IID distributions tested?
- **Basis in paper:** [inferred] The paper tests Dirichlet (\(\alpha=0.1\)) and extreme "single‑class" scenarios, claiming immunity to drift. However, it does not test other pathological heterogeneity patterns (e.g., covariate shift, concept shift, or unbalanced feature distributions) that could affect the closed‑form least‑squares solution's assumptions.
- **Why unresolved:** The ROLANN derivation assumes a linear relationship between features and targets. Certain heterogeneity forms might create feature distributions where the aggregated global least‑squares solution is suboptimal or unstable, even if drift from iterative optimization is avoided.
- **What evidence would resolve it:** Designing and testing new, rigorous non‑IID splits representing other heterogeneity axes (e.g., feature skew, label permutation, varying sample quality) and evaluating if FedHENet's accuracy advantage over FedAvg/FedProx persists across all tested cases. Analyzing the condition number of the aggregated feature matrix could provide theoretical insight.

## Limitations
- Regularization parameter \(\lambda\) is not disclosed; though the method is described as hyperparameter‑free, \(\lambda\) still influences the solution and its optimality.
- CKKS configuration (polynomial degree, scaling factor, multiplicative depth) is omitted, which may affect correctness, performance, and decryption reliability at scale.
- Energy consumption values lack hardware and power‑measurement details, making the reported Wh comparisons environment‑dependent and difficult to reproduce.

## Confidence
- **Accuracy on extreme non‑IID (CIFAR‑10/100)**: **High** – Repeated experiments with strong baselines support the claim; domain mismatch unlikely for CIFAR.
- **Energy reduction (~70 %)**: **Medium** – Savings are clear but hardware‑specific; missing measurement context lowers certainty.
- **Privacy via CKKS homomorphic encryption**: **Medium** – Cryptographically sound, yet implementation parameters are unspecified; potential configuration pitfalls remain.
- **Hyperparameter‑free design**: **Low‑Medium** – \(\lambda\) still exists and its default value may be task‑dependent; the claim of complete freedom from tuning is questionable.
