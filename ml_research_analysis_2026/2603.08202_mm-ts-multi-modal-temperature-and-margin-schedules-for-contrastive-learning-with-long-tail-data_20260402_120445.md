# MM-TS: Multi-Modal Temperature and Margin Schedules for Contrastive Learning with Long-Tail Data
## Quick Facts
- **arXiv ID:** 2603.08202
- **Source URL:** https://arxiv.org/abs/2603.08202
- **Reference count:** 40
- **Primary result:** MM-TS improves zero-shot image-text retrieval (e.g., R@1 on Flickr30K: +3.4% over CLIP) and video-text retrieval, achieving new state-of-the-art results.

## Executive Summary
The paper proposes Multi-Modal Temperature and Margin Schedules (MM-TS) to address suboptimal representation learning in multi-modal contrastive learning with long-tail data. Fixed temperature or margin parameters fail to adapt to varying semantic densities across classes. MM-TS dynamically adjusts these parameters via a two-component schedule: a global cosine decay over training steps and per-sample shifts derived from clustering text embeddings to approximate visual data density. Higher temperatures are assigned to dense clusters (head classes) to encourage group-wise discrimination, while lower temperatures benefit sparse clusters (tail classes) for instance discrimination. The unified approach extends to both InfoNCE and max-margin losses. Evaluated on four datasets, MM-TS yields consistent improvements in zero-shot retrieval and sets new state-of-the-art results.

## Method Summary
MM-TS modifies the contrastive loss by introducing a sample-wise temperature (or margin) τᵢ = τ_base(t) + sh(cᵢ), where τ_base(t) follows a cosine schedule over training steps t, and sh(cᵢ) is a shift based on the size of cluster cᵢ to which sample i’s text embedding belongs. For InfoNCE (as in CLIP), the similarity matrix is scaled row-wise by τᵢ. For max-margin losses, the fixed margin is replaced by τᵢ. The clusters are obtained once before training via K-Means on text embeddings (e.g., SentenceBERT) with a fixed number K (e.g., 200). The shift values are linearly mapped from cluster sizes to a range [sh⁻, sh⁺]. This dynamic adjustment aligns the loss function with the underlying data density, improving discrimination for both head and tail classes.

## Key Results
- On Flickr30K, MM-TS achieves a +3.4% improvement in R@1 over CLIP.
- It sets new state-of-the-art results on image-text and video-text retrieval across Flickr30K, MSCOCO, EPIC-KITCHENS-100, and YouCook2.
- Ablations confirm the synergy of the global cosine schedule and distribution-based shift; the shift alone provides up to +0.9% mAP on EPIC-KITCHENS-100.

## Why This Works (Mechanism)
Long-tail distributions contain head classes with many samples and tail classes with few. Fixed temperature in contrastive learning is suboptimal: head classes benefit from higher temperature to group semantically similar instances, while tail classes require lower temperature to focus on instance-level discrimination. MM-TS assigns higher temperatures to samples from dense text clusters (proxies for visual head classes) and lower temperatures to sparse clusters (tail). The global cosine schedule further modulates temperature over time—starting higher to encourage broad learning and annealing to refine representations. This dynamic adaptation balances the trade-off between group-wise and instance-wise discrimination, leading to better overall representation quality, especially for tail classes.

## Architecture Onboarding
**Component map:**  
Raw captions → Text encoder (SentenceBERT) → Text embeddings → K-Means clustering → Cluster assignments → Cluster sizes → Shift values (per cluster) → Stored per training sample → Training loop: Visual encoder (ResNet/Video net) → Visual embeddings → Similarity matrix S → Row-wise scaling by τᵢ (τ_base + shift) → Loss (InfoNCE or max-margin) → Backpropagation → Parameter update

**Critical path:**  
1. Pre-processing: Compute text embeddings for all training captions, cluster them, derive per-cluster shift, and assign each training sample its shift value.  
2. Training iteration: For a batch, compute visual and text embeddings, form similarity matrix, scale each row i by τᵢ = τ_base(t) + sh(cᵢ), compute loss, and update model parameters.

**Design tradeoffs:**  
- *Static vs. dynamic clustering:* Pre-computing clusters is efficient but may diverge from evolving visual embeddings; periodic reclustering improves accuracy at computational cost.  
- *Number of clusters K:* Small K merges distinct semantics; large K yields noisy size estimates. Paper uses K=200 for large datasets.  
- *Shift bounds (sh⁻, sh⁺):* Too wide risks training instability (negative τᵢ); too narrow reduces adaptation.  
- *Base schedule:* Cosine decay is smooth but requires tuning period T and amplitude α; alternative schedules (linear, exponential) could be explored.

**Failure signatures:**  
- *Negative temperatures:* If α or shifts are too large, τᵢ ≤ 0 occurs → NaNs in logits. Detect by monitoring min τᵢ per batch.  
- *Poor text clusters:* If captions in a cluster are thematically inconsistent, shifts become uninformative. Detect by manually sampling clusters.  
- *Incorrect broadcasting:* Scaling entire similarity matrix instead of row-wise nullifies per-sample adaptation. Verify by checking that rows have different scales.  
- *Cluster collapse:* Excessively high τᵢ for head classes may cause all head embeddings to converge, hurting discrimination. Monitor intra-cluster similarity.  
- *Video caption aggregation:* Using only one sentence for multi-sentence captions may misrepresent sample semantics. Compare full-caption vs. sentence-mean embeddings.

**Exactly 3 first experiments:**  
1. **Setup & Data:** Install PyTorch, Transformers; download CC3M or YouCook2; build a data loader that returns (image/video, caption) pairs, sampling frames for videos as in the original pipeline.  
2. **Distribution Estimate:** Use a pre-trained SentenceBERT (or DistilBERT for CC3M) to embed all training captions. Run K-Means with K=200. Compute cluster sizes Kc and shift values sh(c) = ((Kc − min(K)) / (max(K) − min(K))) · (sh⁺ − sh⁻) + sh⁻, using supplementary hyperparameters (e.g., sh⁻=0.05, sh⁺=0.10). Save shift per training sample.  
3. **Training with MM-TS:** Initialize a CLIP model (ResNet-50). Set total steps T, default τ₀=0.01, and α (e.g., 0.04). At step t, compute τ_base(t) = τ₀ + α·cos(2πt/T). For each batch sample i, set τᵢ = τ_base + stored_shift. Compute InfoNCE loss with row-wise scaling by τᵢ. Optimize with Adam; track zero-shot retrieval on a validation set.

## Limitations
- The cosine temperature schedule (Eq. 7) is ambiguously typeset; period T, offset, and scaling factors are unclear, hindering exact replication.
- Default temperature τ_default is only given for CLIP’s InfoNCE (0.01); for other losses (e.g., max-margin) and architectures, the base value is unspecified.
- Clustering for datasets with multiple annotations (EPIC-KITCHENS-100) or multi-sentence captions (YouCook2) is not detailed: how verb/noun labels or sentence aggregates map to a single shift per sample remains unknown.
- The method assumes static text clusters approximate visual density; if text-visual distribution mismatch is severe, the shift may misguide training.
