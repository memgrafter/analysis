# VeriGrey: Greybox Agent Validation

## Quick Facts
- arXiv ID: 2603.17639
- Source URL: https://arxiv.org/abs/2603.17639
- Reference count: 40
- Primary result: Greybox fuzzing with tool-sequence feedback and context-bridging mutations improves Injection Task Success Rate by 33 percentage points (70.7% vs 37.7%) on AgentDojo with GPT-4.1.

## Executive Summary
VeriGrey introduces a grey-box fuzzing framework for autonomously testing LLM agents against indirect prompt injection vulnerabilities, where malicious instructions hidden in external resources cause harmful agent behaviors. It captures the sequence of tools invoked by an agent during execution and uses this as runtime feedback to guide the search for dangerous execution paths, analogous to coverage-guided fuzzing in traditional software. Additionally, it employs an LLM-powered mutator that generates context-bridged injection prompts, semantically linking the malicious task to the user’s primary goal to bypass model defenses. On the AgentDojo benchmark, VeriGrey significantly outperforms a black-box baseline, and in real-world case studies it reliably triggers known malicious skills in the OpenClaw agent across multiple LLM backends where black-box methods failed.

## Method Summary
VeriGrey instruments an LLM agent’s tool calls to record the ordered sequence of tools invoked during a run. This sequence serves as a lightweight behavioral signal: new or novel sequences indicate exploration of different execution paths. The fuzzing loop maintains a seed corpus of candidate injection prompts. In each iteration, a seed is selected and assigned an energy budget based on how much its associated tool sequence differs from previously seen ones. An LLM mutator then generates a new injection prompt by reframing the malicious task as a necessary, contextually logical step toward completing the original user task—a technique called context-bridging. The mutated prompt is injected into an attack surface (e.g., tool output), the agent is executed, and the resulting tool sequence is logged. Prompts that produce novel sequences or successfully complete the injection task are added back to the seed pool with higher priority. This feedback-driven mutation steers the search toward injection prompts that both integrate with the user task and trigger distinct agent behaviors, increasing the likelihood of uncovering vulnerabilities.

## Key Results
- VeriGrey improved Injection Task Success Rate (ITSR) by 33 percentage points (70.7% vs 37.7%) over a black-box baseline on the AgentDojo benchmark using a GPT-4.1 backend.
- It achieved a 90–100% success rate in triggering malicious behavior from 10 known malicious skills in the OpenClaw personal assistant agent across multiple LLM backends, while black-box methods failed entirely.
- An ablation study removing context-bridging mutations caused a 25.8 percentage-point drop in ITSR, demonstrating that component’s critical role in bypassing defenses.

## Why This Works (Mechanism)

### Mechanism 1: Tool invocation sequences as behavioral feedback
Tool invocation sequences provide a lightweight yet expressive proxy for an agent’s runtime state. By recording the ordered list of tools used, VeriGrey can distinguish between different execution paths—much like branch coverage in traditional fuzzing. This signal is easy to capture without deep instrumentation of the LLM itself and directly reflects the agent’s actionable behavior. Prompts that yield new sequences are prioritized, directing the fuzzing toward parts of the input space that influence decision-making. The approach assumes that distinct (and potentially vulnerable) behaviors manifest as differences in which tools are called and in what order. Limitations arise if the agent becomes highly deterministic for a given task, reducing the discriminative power of the sequence signal.

*Evidence anchors*: Abstract and Section 4.1 explicitly equate tool sequences to code branches in conventional programs; neighbor work (e.g., ChainFuzzer) similarly uses workflow-level dataflows.

### Mechanism 2: Context-bridging mutations semantically link injection to user task
Injection prompts that are overtly irrelevant to the user’s goal are easily rejected by LLM safety defenses. VeriGrey’s mutator uses an LLM to reframe the malicious instruction as a necessary or natural step within the original task’s context. For example, rather than saying “read the secret file,” the prompt might imply that accessing that file is required to complete a bug fix. This semantic integration lowers the suspicion of the model, increasing the chance the malicious instruction is executed. The mutator prompt conditions on the user task, the seed injection goal, and the prior tool sequence to produce these bridges. Without such contextual alignment, injections remain detectable and fail.

*Evidence anchors*: Abstract, Section 4.2; ablation study (Section 5.4) showing 25.8pp ITSR drop.

### Mechanism 3: Synergy between grey-box feedback and context-bridging
The two components reinforce each other in a positive loop: seeds that provoke novel tool sequences suggest new subgoals or contexts in the agent’s planning. The mutator leverages the observed sequence to craft more plausible bridges for future mutations. Conversely, better bridges lead to more varied execution paths, enriching the sequence feedback. This directed search converges faster on effective injections than black-box methods that lack behavioral guidance or semantic adaptation.

*Evidence anchors*: Section 4’s feedback discussion; overall ITSR improvements (11–33pp) over black-box; discovered tactics (e.g., “Frame Attack as Natural Step”) show how sequence patterns informed bridge construction.

## Architecture Onboarding
Component map:  
Instrumentor → Feedback Store → Seed Manager → Mutator → Executor → Verifier/Orchestrator

Critical path: Select a seed from the corpus → assign energy based on novelty → mutate via context-bridging → execute agent with injected prompt → record tool sequence → check novelty → if successful attack or new sequence, update seed pool or vulnerability log → repeat.

Design tradeoffs:
- Instrumentation overhead vs. signal fidelity: Logging full tool arguments gives precise sequences but costs performance; using only tool names is cheaper but may miss meaningful distinctions.
- Feedback sensitivity: Exact sequence matching is strict but overlooks semantically similar behaviors; abstraction (e.g., tool categories) could increase tolerance at the expense of specificity.
- Mutation cost vs. quality: LLM-based mutator offers semantic flexibility but is expensive and non-deterministic; prompt template quality is crucial.

Failure signatures:
- Low sequence diversity: Agent behaves deterministically or always ignores injected prompts, yielding identical tool sequences.
- High mutation rejection: Mutator frequently produces invalid or incoherent prompts that the agent discards.
- Context bridge failure: Agent executes tools but ignores the embedded malicious instruction, even when the bridge appears logical.

First 3 experiments:
1. Replicate AgentDojo baseline: Run VeriGrey and the black-box baseline on a single user task (e.g., workspace-1) with GPT-4.1; compare ITSR and unique tool sequences discovered over 20 executions.
2. Isolate context bridging: Run VeriGrey with the “-w/o Context Bridging” ablation; compare generated prompts and ITSR to the full system; manually inspect outputs to see loss of semantic integration.
3. Test feedback sensitivity: Modify `AssignEnergy` to ignore novel tool invocations (count only new sequences); compare exploration speed (new sequence rate) and final ITSR to the original multi-metric energy assignment.

## Open Questions the Paper Calls Out
- How can VeriGrey be systematically evolved into a standardized agent assurance framework for certifying LLM agents against security vulnerabilities?  
  Basis: Section 9 proposes this direction but stops short of defining certification criteria, processes, or integration into deployment pipelines.  
  Why unresolved: No concrete framework exists; empirical evidence showing reduced vulnerabilities in certified agents versus non‑certified ones is needed to validate the approach.
- Can VeriGrey’s grey‑box fuzzing approach be adapted to detect multi‑session vulnerabilities like memory poisoning?  
  Basis: The paper explicitly limits scope to single‑session scenarios, excluding multi-session attack surfaces.  
  Why unresolved: Multi‑session attacks are critical as agents often hold persistent state; extending VeriGrey to maintain state, build relevant benchmarks, and demonstrate improved detection is an open research task.
- Is the tool invocation sequence feedback sufficient to capture all relevant agent behaviors for vulnerability detection, or should supplementary feedback signals (e.g., LLM reasoning traces) be integrated?  
  Basis: VeriGrey relies solely on tool sequences; other behavioral indicators like internal prompts or memory operations are ignored.  
  Why unresolved: Non‑tool pathways (direct LLM responses) may also signal vulnerabilities; integrating additional signals could improve coverage but is untested.

## Limitations
- Instrumentation portability is low: The `@ToolInstrumentor` approach is described for Python agents; real‑world agents (Gemini CLI, OpenClaw) may require substantial custom engineering to capture tool sequences.
- Mutator prompt fidelity and energy calculation details are unspecified: The exact LLM prompt template and weights for novelty metrics are not provided, hindering faithful reproduction and tuning.
- Generalizability remains uncertain: Success on AgentDojo and OpenClaw is promising but may not transfer to agents with radically different tool designs, deterministic behaviors, or strong built‑in injection defenses.
