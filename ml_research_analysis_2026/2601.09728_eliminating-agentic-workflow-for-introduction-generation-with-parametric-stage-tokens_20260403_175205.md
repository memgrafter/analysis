# Eliminating Agentic Workflow for Introduction Generation with Parametric Stage Tokens

## Quick Facts
- **arXiv ID:** 2601.09728  
- **Source URL:** https://arxiv.org/abs/2601.09728  
- **Reference count:** 40  
- **Primary result:** STIG achieves structural rationality up to 0.832 (vs. AutoSurvey's 0.658) and content coverage 0.442 while using 3.3× fewer tokens by eliminating agentic workflows and generating complete introductions in a single inference.

## Executive Summary
This paper introduces STIG (Stage-Token Introduction Generator), a method that replaces multi-agent workflows for research paper introduction generation with a single LLM inference using parametric stage tokens. By encoding the writing process into eight special tokens (e.g., ⟨STAGE0⟩), STIG avoids error accumulation and high token overhead typical of agentic pipelines. Fine-tuned on ACL papers, STIG significantly improves structural rationality and content coverage while reducing token consumption by over threefold compared to state-of-the-art agentic systems like AutoSurvey.

## Method Summary
STIG transforms the logical stages of introduction writing (four subsections × two phases: outline and content) into discrete tokens added to the model's vocabulary. The system is trained via supervised fine-tuning on annotated ACL papers, where each stage is explicitly marked. During inference, given the paper's metadata (title, abstract, figures/tables, reference abstracts), the model receives a prompt ending with ⟨STAGE0⟩ and generates a single continuous token stream containing all eight stage delimiters. A post-processing parser extracts content sections and discards outlines to produce the final introduction. This design collapses the multi-step agentic orchestration into one forward pass, eliminating inter-agent errors and reducing computational cost.

## Key Results
- Structural rationality (SR) reaches 0.832 on ACL 2025 papers, a 17.4% improvement over AutoSurvey (0.658).  
- Content coverage (CC) is 0.442, and narrative quality (perplexity) is strong (<25).  
- Token usage is only about 5k tokens per introduction, compared to ~17k for AutoSurvey (3.3× reduction).

## Why This Works (Mechanism)
The paper identifies three linked mechanisms:

1. **Elimination of multi-step agentic orchestration** – STIG replaces a pipeline of specialized agents with a single inference conditioned on stage tokens, avoiding error propagation and token overhead. The model directly produces the full structured output without intermediate API calls. Evidence includes the abstract’s claim of eliminating external agentic workflows and Section 2.1’s critique of agentic workflows.

2. **Parametric encoding of workflow stages** – Stage tokens act as control tokens. During SFT on data with explicit stage annotations, the model learns the mapping from tokens to text functions and the required order/transitions, internalizing orchestration logic into parameters. Evidence: Section 3.1 explains the learning process; Section 3.2 describes the dataset with eight stage-token pairs.

3. **Single-inference structured decoding** – Autoregressive generation produces a continuous token stream with embedded markers. The model’s next-token prediction, conditioned on the full prefix, respects stage boundaries and yields coherent sequential text. Evidence: Equation (2) models joint probability over stages; Section 5.6 shows token efficiency; Section 5.1 demonstrates higher SR.

Break conditions: brittle stage transitions under distribution shift, failure of tokens to trigger correct modes, and parsing issues with missing or mis‑bounded stage delimiters.

## Foundational Learning
Three key concepts underpin STIG:

- **Instruction Tuning for Structured Output** – Standard pretraining does not teach models to generate text following a predefined rhetorical structure. STIG requires the model to adhere to a strict stage order. Quick check: can the base model reliably output an outline then content for each subsection in a single generation without swapping sections?

- **Text Segmentation and Logical Flow** – Training data construction requires accurately parsing introductions into four canonical subsections and then into outlines vs. content. This demands domain‑specific knowledge of rhetorical conventions. Quick check: given a raw intro paragraph, can you annotate its subsection and whether it is an outline point or an elaboration?

- **Token-Level Conditioning with Special Tokens** – Stage tokens must act as strong semantic switches. The model must learn that ⟨STAGE0⟩ triggers a background outline mode distinct from ⟨STAGE2⟩ for problem/limitations content. Quick check: after adding eight new token IDs, does fine‑tuning treat them as learnable parameters rather than frozen tokens?

## Architecture Onboarding
The STIG system comprises these components in sequence:

Input Processor -> Prompt Builder -> SFT Model -> Structured Decoder -> Stage Parser -> Evaluator

- **Input Processor** extracts title (T), abstract (A), figures/tables (F), table captions (TA), and reference abstracts (R).  
- **Prompt Builder** prepends a system prompt (Appendix C) and appends ⟨STAGE0⟩ to the material string.  
- **SFT Model** is a base LLM (Qwen2.5‑7B‑Instruct or Llama3.1‑8B‑Instruct) with extended token vocabulary (eight stage‑token pairs) fine‑tuned on the annotated eight‑stage sequences.  
- **Structured Decoder** autoregressively generates the full token stream in one pass.  
- **Stage Parser** splits the output on ⟨STAGEk⟩…⟨ENDk⟩ pairs, discards outline sections (odd stages), and concatenates content sections (even stages) to produce the final introduction.  
- **Evaluator** computes metrics: structural rationality (SR), content coverage (CC), semantic similarity (SS), narrative quality (NQ), and hard constraint checks (QC); it also counts tokens.

**Critical Path**
1. **Data preparation:** Parse ACL papers, extract introduction subsections, generate outlines via GPT‑4o, and annotate with eight stage‑token pairs.  
2. **Model fine‑tuning:** Train the extended‑vocabulary model with cross‑entropy loss on all tokens, updating stage token embeddings.  
3. **Inference:** For a new paper, feed materials + ⟨STAGE0⟩ into the model; autoregressively generate the full token sequence; parse to extract the introduction.  
4. **Evaluation:** Compare the parsed output against gold using SR, CC, SS, etc.; measure total token usage.

**Design Tradeoffs**
- Fixed 8‑stage schema simplifies learning but may not fit all paper styles (e.g., merged problem/method); customization requires retraining or dynamic tokens.  
- Domain‑specific training (ACL) yields high performance; cross‑domain transfer (e.g., CVPR) shows reduced SR without target‑domain fine‑tuning.  
- Enforcing stage delimiters may constrain natural flow; the model might overfit to clean boundaries at the cost of transitional elegance.

**Failure Signatures**
- Stage token confusion: ⟨STAGE2⟩ used but background content generated → SR drops.  
- Missing or duplicate ⟨ENDk⟩ tokens: parser fails to extract a subsection → CC penalized.  
- Incoherent transitions: content in ⟨STAGE1⟩ does not logically follow ⟨STAGE0⟩ outline.  
- Token leakage: stage tokens appear inside content sections, confusing parsing.  
- Domain mismatch: model ignores tokens or produces irrelevant structure on non‑CS papers.

**First 3 Experiments**
1. **Replicate Table 1:** Train STIG (Qwen2.5‑7B) on ACL data and evaluate on ACL 2025 test set; verify SR ≥0.82 and token count ~5k vs. ~17k for AutoSurvey.  
2. **Ablation (Table 2):** Train “Stage Writing w/o FT” (agentic pipeline) and “FT w/o Stage Writing” (full‑text SFT) to confirm both components are necessary for top SR.  
3. **Token efficiency audit:** Implement all baselines (Pure Prompt, ELABORATE, Outline Writing, AutoSurvey) with identical input preprocessing; count tokens end‑to‑end to validate the 3.3× reduction claim.

## Open Questions the Paper Calls Out
- **Generalization to non‑CS fields:** No cross‑disciplinary evaluation; rhetorical structures differ, so performance on biology/humanities is unknown.  
- **Optimal number of stage tokens:** Only 4‑stage and 8‑stage compared; no systematic exploration of intermediate granularities.  
- **Sensitivity to annotation quality:** Training uses GPT‑4o annotations; noise tolerance is untested.  
- **Fine‑grained error analysis:** Aggregate metrics show improvements but lack taxonomy of errors reduced/introduced by STIG.

## Limitations
- Results are limited to computer science conferences; generalization to other domains is unproven.  
- Training hyperparameters and exact procedures are not fully disclosed, hindering exact reproducibility.  
- Structural rationality metric relies on a large classifier with an unspecified prompt, creating an evaluation bottleneck.  
- Parsing depends on correct stage delimiter emission; missing/broken delimiters are not reported.  
- Efficiency gains assume identical material extraction pipelines; variations in figure/table processing could alter token counts.

## Confidence
- Eliminating agentic workflow: **Medium** – SR improvements shown, but fixed schema may fail under distribution shift.  
- Parametric stage tokens: **Medium** – encoding via SFT is plausible; robustness of token‑to‑stage mapping unverified.  
- Single‑inference efficiency: **Medium‑High** – token reduction demonstrated; baseline implementations not open‑sourced may affect fairness.  
- Generalization beyond CS: **Low** – only limited cross‑domain experiments.  
- Annotation quality tolerance: **Low** – no robustness tests provided.
