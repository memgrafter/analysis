# TimeGNN-Augmented Hybrid-Action MARL for Fine-Grained Task Partitioning and Energy-Aware Offloading in MEC

## Quick Facts
- arXiv ID: 2601.06191
- Source URL: https://arxiv.org/abs/2601.06191
- Reference count: 40
- Primary result: TG-DCMADDPG converges within ~60 episodes, reduces average energy consumption to <260 units and execution latency to ~24 units, and maintains a task completion rate >98% (up to 99.6% with 15 servers), outperforming state-of-the-art baselines.

## Executive Summary
Mobile edge computing (MEC) systems face the challenge of jointly optimizing task partitioning and offloading decisions under energy constraints and dynamic network conditions. This paper presents TG-DCMADDPG, a framework that integrates a temporal graph neural network (TimeGNN) predictor with a discrete-continuous multi-agent deep deterministic policy gradient (DC-MADDPG) algorithm. The TimeGNN forecasts future server states (e.g., CPU load, energy, bandwidth) from a short history, reducing the need for frequent online state broadcasts. The DC-MADDPG agents operate under centralized training and decentralized execution, handling hybrid actions: discrete server selection (up to two servers via Gumbel‑Softmax) and continuous controls (offloading ratio, transmission power).

In simulations, TG-DCMADDPG achieves rapid convergence within approximately 60 episodes, lowers average energy consumption to below 260 units, reduces execution latency to around 24 units, and sustains a task completion rate above 98% (reaching 99.6% with 15 edge servers), while scaling effectively and surpassing state-of-the-art baselines.

## Method Summary
The target problem is the joint optimization of fine-grained task partitioning and offloading in a mobile edge computing network with energy‑constrained mobile devices and multiple MEC servers. Each mobile device (agent) generates computational tasks and must decide which one or two servers to offload to, what fraction of the task to offload (splitting ratio), and the transmission power, while respecting energy limits and aiming to minimize a weighted sum of energy consumption and execution latency. The system state evolves dynamically due to varying task arrivals, server workloads, and channel conditions.

The proposed TG-DCMADDPG framework consists of two main components. First, a TimeGNN predictor ingests a temporal buffer of the last K_hist=5 multi‑dimensional server states (CPU load, residual energy, bandwidth, etc.) structured as a dynamic graph. Using spatial message passing (a normalized adjacency matrix) and temporal encoding (GRU), it learns spatiotemporal dependencies and produces a one‑step‑ahead prediction ˆs_{t+∆} for each server. This prediction is concatenated to each agent’s current local observation to form an augmented input. Second, a DC‑MADDPG algorithm employs a centralized critic Q_ϕ that evaluates the global state and joint actions, while each agent runs an actor µ_θ that consumes the augmented observation and outputs a hybrid action: a discrete one‑hot vector for server selection (sampled via Gumbel‑Softmax) and two continuous values for offloading ratio (sigmoid‑scaled to [0,1]) and transmission power. Training follows the CTDE paradigm: experiences are stored in a replay buffer D_RL, and the critic is updated via TD learning, while actors are updated using the deterministic policy gradient. The TimeGNN is updated online from the temporal buffer. Hyperparameters include prediction every K_pred steps, discount factor γ, and soft target updates (τ=0.01).

## Key Results
- Convergence: Approximately 60 episodes.
- Performance: Average energy consumption <260 units, execution latency ~24 units, task completion rate >98% (up to 99.6% with 15 servers).
- Scalability: Outperforms state‑of‑the‑art baselines across varying numbers of edge servers.

## Why This Works (Mechanism)

### Mechanism 1: TimeGNN Predictor Reduces Online Interactions
The TimeGNN forecasts future server states (CPU load, energy, bandwidth) using a temporal graph neural network. It processes a historical buffer of server states arranged as a dynamic graph, applying spatial message passing through a normalized adjacency matrix and temporal encoding via a GRU. After several layers, an MLP produces a one‑step‑ahead prediction, which is concatenated to each agent’s local observation. This augmented state allows agents to anticipate server conditions without waiting for fresh measurements, reducing online interactions. The core assumption is that server state trajectories are temporally smooth and spatially correlated across neighboring servers. Evidence: The abstract highlights reduced online interactions; Section V.B details the spatial‑temporal update and augmentation; and Fig. 3 shows faster convergence compared to a purely reactive DC‑MADDPG. The approach fails if server dynamics become highly stochastic (e.g., abrupt energy harvesting or load spikes), leading to large prediction errors that misguide agents.

### Mechanism 2: DC‑MADDPG Enables Fine‑Grained Hybrid‑Action Coordination
The DC‑MADDPG algorithm operates under the CTDE paradigm. Each mobile device hosts an actor that outputs a hybrid action: a discrete one‑hot vector for selecting up to two target servers (sampled via Gumbel‑Softmax for differentiability) and continuous values for the offloading ratio and transmission power. A centralized critic Q_ϕ approximates the joint state–action value, capturing inter‑agent dependencies. During execution, actors use only their local augmented observations, making the system fully decentralized. The assumption is that the hybrid action space is necessary for fine‑grained control and that the critic can model cooperative effects despite the discrete‑continuous mix. Evidence: The abstract and Section V.C formalize the hybrid action, TD target, critic loss and actor gradient. Related work on hybrid‑action MARL provides context but does not directly validate this design. A potential break condition arises if the discrete action space grows too large, causing Gumbel‑Softmax sampling instability or insufficient critic capacity to capture combinatorial interactions.

### Mechanism 3: Synergy Between TimeGNN and DC‑MADDPG
Integrating TimeGNN predictions with DC‑MADDPG yields foresighted coordination: actors plan based on anticipated server conditions, reducing myopic energy‑latency trade‑offs and lowering communication overhead from fewer online state broadcasts. The augmented observation ˜o_n^t = [o_n^t, ˆs_{t+∆}] supplies predictive context, enabling proactive offloading decisions. This synergy is evidenced by the significantly faster convergence of TG‑DCMADDPG versus DC‑MADDPG without TimeGNN (Fig. 3) and the superior final cost metrics. The core assumption is that near‑future state forecasts are valuable for long‑term optimization and that the inference cost (∼2.1 ms per slot) is outweighed by gains. However, if the prediction horizon ∆ is too large or errors accumulate, the augmented state becomes misleading, possibly degrading performance relative to a reactive policy.

## Architecture Onboarding

### Component Map
- **TimeGNN Predictor**: Consumes the temporal buffer B_Temp (last K_hist observations) and outputs predicted future server states ˆs_{t+∆} for all servers.
- **DC‑MADDPG Agents**: Each actor takes the augmented observation ˜o_n^t = [o_n^t, ˆs_{t+∆}] and emits a hybrid action a_n^t (discrete one‑hot for up to two servers via Gumbel‑Softmax, continuous offloading ratio and power).
- **Centralized Critic**: Q‑network approximates the value of global state and joint actions, trained with TD errors.
- **Buffers**: D_RL stores transitions (o_t, a_t, r_t, o_{t+1}) for RL; B_Temp is a FIFO queue storing the most recent K_hist observations for TimeGNN input.

### Critical Path
1. Every K_pred time steps, construct a dynamic graph G_t from B_Temp and run the TimeGNN to obtain ˆs_{t+∆}.
2. For each mobile device n, form the augmented observation ˜o_n^t by concatenating the current observation with ˆs_{t+∆}, feed it to the actor µ_θ, and sample the hybrid action a_n^t (discrete part via Gumbel‑Softmax).
3. Execute the joint action a_t in the environment; receive immediate reward r_t and next observations o_{t+1}.
4. Append o_{t+1} to B_Temp and store the transition (o_t, a_t, r_t, o_{t+1}) into D_RL.
5. Sample a minibatch from D_RL, update the critic to minimize the TD loss, update the actor using the policy gradient, and perform soft target‑network updates (τ=0.01).

### Design Tradeoffs
- **Prediction frequency vs. staleness**: More frequent predictions (small K_pred) provide fresher forecasts but increase computational overhead for updating B_Temp and running TimeGNN (∼2.1 ms per slot). Too infrequent predictions risk decisions based on outdated server states.
- **Hybrid action stability**: The Gumbel‑Softmax temperature τ must be annealed; a high temperature yields nearly uniform discrete samples (random selection), while a low temperature harms differentiability and exploration. Continuous outputs (splitting ratio, power) must be bounded appropriately (e.g., via sigmoid and scaling).
- **CTDE partial observability**: Actors rely solely on local augmented observations; if TimeGNN predictions are inaccurate, agents have no recourse to coordinate using the full global state during execution.

### Failure Signatures
- **Critic loss divergence**: Indicates unstable joint‑action value estimation, possibly due to non‑stationarity from simultaneous agent learning or insufficient exploration in the hybrid action space.
- **High average energy/latency despite convergence**: Suggests systematic bias in TimeGNN predictions (e.g., under‑predicting future load), causing agents to overload servers and degrade performance.
- **Drop in task completion rate with more servers**: Points to scalability limits in the discrete server selection component, where the combinatorial space overwhelms the Gumbel‑Softmax sampling or the critic’s capacity to capture interactions.

### First 3 Experiments
1. **TimeGNN prediction error ablation**: Compare the framework’s performance using ground‑truth future states (oracle), the learned TimeGNN predictions, and a naive predictor (last observed state) to isolate the impact of prediction accuracy on final cost metrics.
2. **Hybrid action space validation**: Ablate the hybrid design by contrasting it with (a) a purely discrete action space (server selection only, with fixed splitting ratios) and (b) a purely continuous soft server selection (e.g., via attention weights) to confirm the necessity of the hybrid approach.
3. **Prediction horizon sensitivity**: Vary the prediction horizon ∆ (e.g., 1, 3, 5 steps) and prediction frequency K_pred to map the trade‑off region where forecasting improves performance versus where staleness degrades it.

## Open Questions the Paper Calls Out

### Open Question 1: Impact of Fixed One‑Step Prediction Horizon in Volatile MEC
**Basis:** The paper employs a fixed one‑step‑ahead prediction (∆=1) and evaluates benefits on immediate next‑state augmentation, without exploring multi‑step forecasting or longer episodes.  
**Why unresolved:** Simulation episodes are short (10 time slots); the trade‑offs between prediction horizon and error accumulation over extended periods are not examined.  
**What would resolve:** Conduct experiments varying ∆ (e.g., 1, 3, 5) and measure cumulative reward, convergence speed, and energy conservation over longer horizons, including stress tests with highly dynamic server trajectories.

### Open Question 2: Bias from Gumbel‑Softmax Relaxation in Discrete Server Selection
**Basis:** The hybrid action uses Gumbel‑Softmax for differentiable sampling of the discrete server selection component.  
**Why unresolved:** The paper does not analyze the temperature annealing schedule or the discrepancy between the relaxed continuous distribution and the final one‑hot sample; no comparison to alternative discrete methods (e.g., straight‑through estimators) is provided.  
**What would resolve:** An ablation study comparing Gumbel‑Softmax with other differentiable strategies, measuring task completion rate, load variance across servers, and final policy entropy; also investigating the sensitivity to temperature schedules.

### Open Question 3: Scalability of the Centralized Critic with Increasing Mobile Devices
**Basis:** The DC‑MADDPG algorithm relies on a centralized critic that observes the global state and all agents’ actions. Experiments scale the number of edge servers but keep the number of mobile devices fixed.  
**Why unresolved:** As the number of agents grows, the critic’s input dimensionality increases, potentially straining its capacity to model complex inter‑agent dependencies under partial observability (agents only see local augmented observations).  
**What would resolve:** Stress tests that increase the number of mobile devices (e.g., 5, 10, 20) while keeping servers constant, tracking performance metrics (reward, latency, completion rate), critic loss stability, and possibly introducing decentralized critics for comparison.

### Open Question 4: Robustness of TimeGNN to Channel Impairments and Asynchronous Reporting
**Basis:** The simulation assumes ideal, periodic collection of server states (every two intervals) and uses a static path‑loss model without fast fading or shadowing.  
**Why unresolved:** Real MEC deployments suffer from noisy channel estimates, packet loss, and asynchronous state updates, which could degrade the quality of the historical sequences fed to TimeGNN.  
**What would resolve:** Robustness experiments that inject synthetic noise or simulate packet loss and delays into the historical state sequences, assessing the resulting prediction error and downstream performance; optionally retrain TimeGNN with augmented noisy data.

## Limitations
- **Architecture specifics**: Exact network dimensions, activation functions, and integration details of the TimeGNN’s GRU with graph layers are not provided, hindering exact replication.
- **Reward formulation**: The precise reward signal r_t and handling of constraint violations (e.g., energy budget) are unspecified, risking misaligned policy learning.
- **Action space ambiguity**: The meaning of the 3‑dimensional one‑hot discrete action (whether it selects a single server or a fixed pair) is unclear, affecting correct implementation.

## Confidence
- Performance claims (energy <260, latency ~24, task completion >98%): Medium
- TimeGNN utility (reduced interactions, foresight): Low
- DC‑MADDPG hybrid‑action efficacy: Medium
