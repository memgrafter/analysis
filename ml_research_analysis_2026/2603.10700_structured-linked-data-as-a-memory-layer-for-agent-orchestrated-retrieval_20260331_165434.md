# Structured Linked Data as a Memory Layer for Agent-Orchestrated Retrieval

## Quick Facts
- arXiv ID: 2603.10700
- Source URL: https://arxiv.org/abs/2603.10700
- Reference count: 40
- Primary result: Enhanced entity pages with materialized links and agent instructions improve RAG accuracy by ~30% over plain HTML/JSON-LD, while JSON-LD alone provides negligible gain under flat-text ingestion.

## Executive Summary
This paper investigates how structured linked data, specifically enhanced entity pages that materialize knowledge graph relationships and provide explicit navigational cues, can serve as a memory layer for retrieval-augmented generation (RAG). The authors test various document formats—plain HTML, HTML with embedded JSON-LD, and enhanced pages with additional Schema.org markup, breadcrumbs, and llms.txt-style instructions—using both standard single-pass RAG and agentic RAG with link traversal. Key findings show that while JSON-LD alone yields minimal improvement (likely due to flat-text ingestion), the enhanced format delivers substantial accuracy gains (~30%) across both retrieval paradigms. The agent’s multi-step reasoning primarily compensates for poorly formatted sources, with little additional benefit on enhanced pages. The work suggests that investing in enriched, machine-actionable page templates can simplify retrieval architectures and reduce reliance on complex agentic pipelines.

## Method Summary
The study evaluates RAG performance on 349 queries across four domains (editorial, legal, travel, e-commerce) using 158 entities. Seven experimental conditions manipulate (a) document format: plain HTML, HTML+JSON-LD, enhanced entity page, and Enhanced+ variant; and (b) retrieval type: standard (single retrieval call to Gemini 2.5 Flash) and agentic (Google ADK ReAct agent with tools: search_documents, follow_entity_link, search_knowledge_graph). Documents are indexed in Vertex AI Vector Search 2.0 using gemini-embedding-001 (hybrid semantic+keyword). Accuracy and Completeness are scored 1–5 by an LLM judge (Gemini 3.0 Flash) using ground truth derived from the knowledge graph. The core hypothesis is that materializing linked data into natural language within retrieved documents improves downstream generation.

## Key Results
- JSON-LD embedding alone provides marginal accuracy gain (+0.17 on 1–5 scale, Cohen’s d=0.18) under flat-text ingestion.
- Enhanced entity pages yield large improvements: +29.6% accuracy for standard RAG (d=0.60) and +29.8% for agentic RAG (d=0.61).
- Agentic RAG substantially lifts plain HTML (+0.74 accuracy) but offers negligible gain on enhanced pages (C3 vs C6: 4.69 vs 4.70), indicating agents primarily compensate for poor document structure.
- Enhanced+ variant achieves highest absolute scores (4.85/5 accuracy) but incremental gain over base enhanced is not statistically significant (d=0.08).

## Why This Works (Mechanism)
### Mechanism 1: Link Materialization via Enhanced Presentation
The enhanced entity page improves RAG by materializing structured data from linked entities directly into the initial retrieved document’s visible HTML, transforming multi-hop retrieval into single-pass. Plain HTML and JSON-LD-only pages store related entity data as dereferenceable URIs but do not include resolved properties (e.g., a restaurant’s “hotel” relationship only shows a URI, not the hotel’s name or description). An agent must follow these links via HTTP requests to gather missing context. The enhanced page pre-resolves these URIs and embeds key properties (name, description, coordinates) as natural language text, providing a self-contained information packet. This addresses the flat-text ingestion limitation where RAG systems treat each document as one undifferentiated text field, ignoring JSON-LD blocks. Evidence: Domain analysis shows largest gains in SalzburgerLand and WordLift Blog where KG data is absent from baseline HTML. Break condition: If the retrieval system natively extracts and indexes JSON-LD separately (e.g., as a structured field), the marginal benefit of materialization diminishes because structured data could be retrieved directly without link traversal.

### Mechanism 2: Explicit Navigational Affordances
The enhanced format adds visible dereferenceable links, type breadcrumbs, and llms.txt-style agent instructions that reduce ambiguity and guide efficient discovery. Human-readable relation labels (e.g., “brand:”, “location:”) and explicit tool instructions help both human readers and AI agents identify which URIs are worth extracting or following. This lowers the planning burden on the agentic ReAct loop and aids standard RAG’s LLM in parsing raw text. Evidence: Section 3.3 describes these components; Section 4.7 shows agents on Enhanced+ pages follow fewer links (0.4) than on plain HTML (1.0) while achieving higher accuracy. Break condition: Advanced agents might infer relationships from opaque URIs without labels, or queries requiring no link traversal minimize the affordances’ value.

### Mechanism 3: Agentic Retrieval Compensates for Structural Deficits
The agentic pipeline’s primary value lies in compensating for poorly formatted source documents. On plain HTML/JSON-LD, agent tool calls (follow_entity_link, search_knowledge_graph) reconstruct missing context by exploring the KG. On enhanced pages, where necessary context is already present, the agent adds little value and may introduce inefficiency. Evidence: C3 (enhanced, standard: 4.69) and C6 (enhanced, agentic: 4.70) have nearly identical accuracy, whereas agent lift on plain HTML is large (+0.74). Agents also follow significantly fewer links on Enhanced+ pages. Break condition: Queries inherently requiring aggregation across distinct entities (e.g., “compare A and B”) might reactivate the agent’s value even with enhanced pages.

## Architecture Onboarding
Component map: Input Query → Vertex AI Vector Search (indexes 7 document collections) → Reasoning Layer: Standard RAG uses Gemini 2.5 Flash (single pass); Agentic RAG uses Google ADK agent with ReAct loop and tools (search_documents, follow_entity_link, search_knowledge_graph) → Structured Data Layer: WordLift Knowledge Graph (serves entity pages via content negotiation) → Evaluation: LLM Judge (Gemini 3.0 Flash) scores Accuracy/Completeness.

Critical path (Agentic RAG with Enhanced Page): User query → ADK agent calls search_documents → Vertex AI returns top-K enhanced entity pages → Agent parses visible links and llms.txt instructions → Agent calls follow_entity_link on promising URIs (fewer calls due to rich context) → WordLift KG returns JSON-LD for related entity → Agent synthesizes all context into final answer.

Design tradeoffs:
- Flat-text ingestion vs. structured parsing: Simpler but discards structure; structured indexing could make JSON-LD beneficial but requires complex retrieval.
- Agent complexity vs. document preparation: Complex agentic pipeline can compensate for poor structure; enhanced templates are a one-time editorial effort that simplifies retrieval and reduces agent burden.
- Evaluation circularity vs. ecological validity: KG-derived ground truth favors conditions surfacing KG data, directly testing the hypothesis but possibly overstating gains compared to human-curated answers.

Failure signatures:
- Low accuracy on factual queries for C1/C2: Retriever cannot find specific property values in flat text.
- High “links followed” for C4 (plain HTML, agentic): Agent is inefficiently traversing due to lack of navigational affordances.
- Large domain-specific gains (SalzburgerLand, WordLift Blog) vs. near-zero for e-commerce: Confirms link materialization helps where KG holds unique data.
- Near-zero Δ between C3 and C6: Agent provides no lift when format is optimized.

First 3 experiments:
1. Replicate H1 baseline: Compare C1 (Plain HTML, Standard RAG) vs. C2 (HTML+JSON-LD, Standard RAG). Expect minimal gain (~+0.17).
2. Test enhanced page effect: Compare C1 vs. C3 (Enhanced, Standard RAG). Expect large gain (~+1.04).
3. Test agentic compensatory effect: Compare C2 vs. C5 (JSON-LD, Agentic vs Standard) and C1 vs. C4 (Plain HTML, Agentic vs Standard). Expect large lift on plain HTML (+0.74) but smaller lift on JSON-LD (+0.50).

## Open Questions the Paper Calls Out
1. Isolated effect of link materialization vs. navigational affordances: The enhanced page bundles both; no ablation separates these. Need variants with materialization only or navigation only.
2. Structured-data-aware retrieval: Would separately indexing JSON-LD as structured metadata yield significant gains from JSON-LD alone? Flat-text ingestion may cause null result for H1.
3. Generalization to other systems: Results are specific to Vertex AI and gemini-embedding-001. Need replication with OpenAI embeddings, Pinecone, etc.
4. Domain predictors: Which characteristics (baseline HTML richness, KG coverage, link density) predict improvement magnitude? Not measured systematically.
5. Production validation: Would enhanced pages improve accuracy in live AI search engines? Requires field experiment on real websites with control groups.

## Limitations
- Model substitution risk: Using non-Gemini models may alter results due to capability differences.
- Incomplete KG service specs: `search_knowledge_graph` tool API is underspecified, risking functional divergence.
- Document generation uncertainty: Unclear if repository provides pre-rendered HTML or requires template rendering, risking format inconsistencies.
- Agent behavior defaults: Unstated ADK configuration may cause tool-call pattern divergence from reported values.

## Confidence
- Enhanced page format shows large gains: High (consistent d≈0.6 across retrieval types, domain analysis supports).
- JSON-LD alone provides marginal gain: High (tiny d=0.18 replicated, attributed to flat-text ingestion).
- Agentic retrieval primarily compensates for poor format: High (large agent lift on plain HTML, negligible on enhanced; tool call reduction evidence).
- Break condition for multi-hop queries: Medium (logical inference from data, not directly tested by query set).
