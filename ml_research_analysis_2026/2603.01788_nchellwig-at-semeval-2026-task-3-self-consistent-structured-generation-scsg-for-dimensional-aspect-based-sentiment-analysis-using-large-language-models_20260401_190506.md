# nchellwig at SemEval-2026 Task 3: Self-Consistent Structured Generation (SCSG) for Dimensional Aspect-Based Sentiment Analysis using Large Language Models

## Quick Facts
- **arXiv ID:** 2603.01788
- **Source URL:** https://arxiv.org/abs/2603.01788
- **Reference count:** 22
- **Primary result:** Self-consistency with 15 executions improves continuous F1 by ~1.0 point over single inference, with vLLM PagedAttention reducing evaluation time by over 26x.

## Executive Summary
This paper introduces Self-Consistent Structured Generation (SCSG), a method to improve the reliability of Dimensional Aspect-Based Sentiment Analysis (DimABSA) predictions from large language models. SCSG fine-tunes a LLM with LoRA to generate structured tuples of `(aspect, category, opinion, valence, arousal)` and applies self-consistency: for each input, the model generates multiple outputs with temperature sampling, and only tuples appearing in a strict majority of runs are retained, with valence and arousal averaged. To mitigate the computational cost of repeated inference, the system leverages vLLM's PagedAttention to batch all predictions and reuse key-value caches across the identical prompt prefixes. On SemEval-2026 Task 3's multilingual benchmark, SCSG yields statistically significant continuous F1 improvements and ranks in the top seven for all language-domain combinations.

## Method Summary
SCSG combines parameter-efficient fine-tuning with a self-consistency aggregation. A quantized Gemma-3-27B-Instruct model is fine-tuned via LoRA (rank 64) on the task-specific structured output format using response-only loss. During inference, for each test instance, the model generates *k* outputs (15 for DimASTE, 10 for DimASQP) with temperature 0.8 using vLLM in a single batched request. A majority voting filter (`≥⌈k/2⌉+1` occurrences) selects tuples based on matching aspect, opinion, and (for DimASQP) category terms; valence and arousal values for consensus tuples are averaged across runs. Final predictions are post-processed: out-of-range values are clipped, spans not present in the input are discarded, and unsupported categories are filtered.

## Key Results
- Average continuous F1 improved from 55.52 to 56.50 on DimASTE and from 46.10 to 47.37 on DimASQP across 6 languages and multiple domains.
- The system ranked in the top seven for all 12 language-domain configurations, achieving second place on three English subsets and first place on Tatar-Restaurant for DimASTE.
- vLLM's PagedAttention with batched inference provided a 26.6×–28.2× speedup over non-batched self-consistency evaluation.

## Why This Works (Mechanism)

### Mechanism 1: Self-Consistency Aggregation Filters Stochastic Noise
Executing the LLM *k* times with temperature sampling (*t*=0.8) induces variation. Retaining only tuples achieving majority consensus (`≥⌈k/2⌉+1` occurrences) suppresses low-confidence, noisy outputs. For consensus tuples, valence/arousal are averaged, reducing variance. The core assumption is that frequent tuples reflect the model's robust internal representation.
- **Evidence:** Abstract and section 2.2 define the voting threshold and claim statistically significant improvements.
- **Break condition:** If the model is highly deterministic even at *t*=0.8, all outputs may be identical, rendering voting ineffective. Extreme task ambiguity may cause no tuple to reach consensus, collapsing recall.

### Mechanism 2: PagedAttention KV Cache Reuse Mitigates Compute Cost
vLLM's PagedAttention virtualizes the key-value cache, allowing cached states from the shared prompt prefix to be reused across the *k* forward passes. Batched inference co-locates all *k*×*N* generations, maximizing GPU utilization and avoiding redundant prefix computation.
- **Evidence:** Abstract and section 2.3 describe KV cache reuse and batched processing. Appendix F empirically shows 26.6×–28.2× speedup.
- **Break condition:** Significant prompt length variation causes memory fragmentation, reducing reuse efficiency. Very large *k* may exceed memory capacity for storing multiple caches.

### Mechanism 3: LoRA Fine-Tuning Aligns Base LLM to Structured Output
LoRA adapts the base LLM (Gemma-3) to the specialized tuple format and multilingual domain knowledge with minimal catastrophic forgetting, using response-only training to focus learning on output tokens.
- **Evidence:** Section 2.1 details LoRA hyperparameters (rank 64, target: attention+MLP) and response-only loss. Section 3 confirms 4-bit quantized Gemma-3-27B as the primary model.
- **Break condition:** If the base model is too small or misaligned, LoRA may insufficiently teach structured generation. A single multilingual LoRA may cause cross-lingual interference.

## Foundational Learning

**Concept: Self-Consistency (SC) Voting**
- **Why needed:** SC transforms a stochastic generator into a robust estimator by exploiting central tendency; consensus correlates with confidence, improving cF1.
- **Quick check:** With *k*=15, a tuple appearing in 8 runs is included (8≥8). If it appears in 7, it is excluded (7<8).

**Concept: Valence-Arousal Continuous Scoring (cF1)**
- **Why needed:** DimABSA uses continuous 1–9 dimensions. cF1 partially credits near-miss VA predictions only after exact categorical match (aspect/opinion/category), so mechanisms must preserve categorical precision while optimizing regression.
- **Quick check:** A prediction with correct spans but VA=(5.0,5.0) vs. gold=(5.0,4.9) does not get full cTP; partial credit is based on normalized Euclidean distance.

**Concept: vLLM PagedAttention for Batch Inference**
- **Why needed:** SC's *k*×*N* inferences are computationally prohibitive without kernel-level optimizations that reuse the KV cache for identical prompt prefixes.
- **Quick check:** For 1,000 test instances with *k*=15, naive loop requires 15,000 forward passes. Batched PagedAttention processes all in fewer passes by reusing cached prefix states, yielding ~26× speedup.

## Architecture Onboarding

**Component map:**
LoRA fine-tuned Gemma-3-27B -> Prompt template -> SC loop controller -> vLLM inference server (PagedAttention) -> Raw tuple extraction -> Majority voting aggregator -> Post-validation (span check, range clip, category filter) -> Final tuples

**Critical path:**
Input text -> Formatted prompt -> *k* parallel inferences via vLLM (shared KV cache) -> Raw output parsing -> Voting (majority threshold) -> Span validation and VA clipping -> Category filtering -> Output list

**Design tradeoffs:**
- *k* (views): Higher *k* improves reliability but increases latency; chosen optimal *k*: 15 (DimASTE), 10 (DimASQP) via dev set sweep.
- Batch size: Larger batches improve vLLM throughput but require more GPU memory for *k*×*N* concurrent generations.
- LoRA rank (*r*=64): Higher rank may improve adaptation but increases memory; 64 chosen from prior ABSA work.
- Temperature (*t*=0.8): Balances diversity vs. stability; lower *t* reduces variance but may reduce consensus diversity.

**Failure signatures:**
- **Low recall:** Consensus threshold too high or span validator too strict; check tuple occurrence distribution across *k* runs.
- **Low precision:** Threshold too low or span validator too lenient; inspect for hallucinations.
- **VA bias:** Averaging may smooth extreme values toward 5.0; check raw VA distribution in consensus tuples.
- **Memory overflow:** *k*×*N* batch exceeds GPU capacity; monitor utilization and reduce batch size.

**First 3 experiments:**
1. **Baseline replication:** Run with *k*=1, same prompt, no voting. Expect lower cF1 than Table 2; confirms SC effect baseline.
2. **View count sweep:** Test *k* ∈ {1,5,10,15,20} on dev set. Plot cF1 vs. *k*; verify diminishing returns after optimal point (~10–15).
3. **Efficiency benchmark:** Measure seconds per example with vLLM batched vs. unbatched SC (*k*=15). Expect ~26×–28× speedup as in Appendix F.

## Open Questions the Paper Calls Out
- **Few-shot prompting for low-resource languages:** How effectively can few-shot variants improve performance for low-resource languages and domains? The paper only evaluated full fine-tuning; few-shot was not explored.
- **Efficient Multi-View Prompting (MvP) for LLMs:** How can MvP, which multiplies training data by permutation count, be adapted to LLMs without prohibitive overhead? MvP was not implemented; efficient strategies are needed.
- **Multilingual joint training:** Does training a single model on combined data from all languages improve performance, especially for low-resource languages? The current approach trains separate models per language-domain.
- **Adaptive voting thresholds:** Is the strict majority threshold (`≥⌈k/2⌉+1`) optimal for the precision-recall trade-off? The paper used a fixed threshold without ablation; adaptive thresholds may improve cF1.

## Limitations
- **Prompt translations:** Non-English prompts are not provided; minor translation variations could affect reproducibility.
- **LoRA targeting underspecified:** Unclear which Gemma-3 modules were adapted (e.g., specific linear layers, vision layers), impeding faithful replication.
- **Voting threshold justification:** Optimal *k* chosen on dev set, but no analysis of consensus rates or cases where voting harms performance; generalizability uncertain.

## Confidence
- **Self-consistency improves cF1:** Medium. Results are reported, but ablation isolating voting from multiple sampling is absent.
- **vLLM PagedAttention enables feasible SC:** Medium. Timing data is provided, but batching/configuration details are sparse.
- **LoRA adaptation yields correct structured generation:** Low. Fine-tuning details are standard but underspecified; no error analysis on format adherence.

## Next Checks
1. **Ablation on aggregation method:** Compare majority voting (*k*=15) against simple averaging of all *k* outputs on dev sets to isolate the consensus filter's contribution.
2. **LoRA module targeting analysis:** Replicate training with two variants: (a) only attention modules, (b) attention+MLP. Measure cF1 difference to infer impact of claimed targeting.
3. **vLLM batching reproduction:** Log GPU memory usage and throughput for batched vs. unbatched SC (*k*=15). Confirm near-linear speedup and that PagedAttention reuse accounts for >80% of the gain.
