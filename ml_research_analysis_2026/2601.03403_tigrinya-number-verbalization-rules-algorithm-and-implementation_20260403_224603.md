# Tigrinya Number Verbalization: Rules, Algorithm, and Implementation

## Quick Facts
- **ArXiv ID**: 2601.03403  
- **Source URL**: https://arxiv.org/abs/2601.03403  
- **Reference count**: 40  
- **Primary result**: A deterministic rule‑based system for Tigrinya number verbalization with an open‑source Python implementation; evaluation of six frontier LLMs shows severe deficiencies (best accuracy 65%), demonstrating the superiority of explicit linguistic rules for this low‑resource language.

## Executive Summary
Tigrinya, a low‑resource language, lacked systematic resources for number verbalization, hindering NLP applications such as text‑to‑speech and accessibility tools. This paper formalizes Tigrinya’s linguistic rules—including a conjunction suffix system for compounds, scale‑word handling, and special cases like hundred allomorphy—into a deterministic algorithm for number‑to‑word conversion. The authors released an open‑source Python library covering cardinals, ordinals, dates, times, currency, and phone numbers. To assess the need for such a system, they evaluated six frontier large language models (LLMs) on a curated 100‑example test set; the best model (Claude Opus 4.5) achieved only 65% accuracy, while GPT‑5 Mini scored a mere 1%. These results underscore that implicit probabilistic modeling fails for this intricate, low‑resource task, whereas the rule‑based system achieves perfect coverage.

## Method Summary
The authors designed a rule‑based algorithm that decomposes any integer into a list of parts based on magnitude scales (thousand, million, etc.). Each part is verbalized by a sub‑engine that handles numbers below 1000, applying digit and ten lookup tables and allomorphic rules for the hundred. After conversion, the parts are joined with the conjunction suffix “ን” on every component except in simple (single‑part) cases or in the teen exception (11–19). The system is implemented in Python and supports additional numeric categories—ordinals, dates, times, currency, phone numbers—through category‑specific wrappers. For evaluation, the authors constructed a test set of 100 examples across these categories and compared the rule‑based output against zero‑shot generations from six LLMs using exact string match.

## Key Results
- **Open‑source release**: The Python library (`tigrinya-numbers`) provides full coverage of cardinals, ordinals, dates, times, currency, and phone numbers.
- **LLM evaluation failure**: Frontier models perform poorly; Claude Opus 4.5 reaches 65% accuracy, GPT‑5 Mini only 1%.
- **Perfect rule‑based accuracy**: The deterministic system achieves 100% accuracy on the test set, proving the effectiveness of explicit rule documentation.

## Why This Works (Mechanism)
The deterministic success stems from three tightly integrated linguistic mechanisms:

1. **Mandatory Conjunction Suffix “ን” for Compounds**  
   In any multi‑part number, Tigrinya obligatorily attaches the enclitic “ን” to *every* constituent component (digits, tens, or scale words), creating a linked structure (e.g., 25 → “ዕስራን ሓሙሽተን”). Single‑part numbers omit the suffix. The algorithm implements this by appending “ን” to all but the last part during the final join, as formalized in Section 3.1.

2. **Scale Words as Ordinary Components with Context‑Sensitive Standalone Form**  
   Scale words (e.g., “ሽሕ” thousand) follow the same compounding logic. They appear without “ን” only when they are the sole non‑zero element at their magnitude (e.g., 25 000 → “ዕስራን ሓሙሽተን ሽሕ”). If any lower‑magnitude component follows, the scale takes “ን” (e.g., 25 001 → “ዕስራን ሓሙሽተን ሽሕን ሓደን”). This is encoded via the `ISSIMPLE` predicate and the presence of lower components during scale iteration (Section 3.3).

3. **Allomorphic Variation of “Hundred”**  
   The word for hundred, “ሚእቲ”, changes form in compounds. Standalone hundreds use “ሚእቲ”; in multi‑part numbers the stem becomes “ሚእት” and receives “ን” → “ሚእትን”. This alternation is triggered by the same compounding condition and is handled by a replacement when the part list length is one (for standalone) or via the regular join (for compounds), as described in Section 3.2.

These mechanisms, grounded in the authors’ linguistic analysis, yield a concise, fully deterministic converter that generalizes across all covered numeric categories.

## Foundational Learning
Three key linguistic concepts underpin the algorithm:

- **Base‑10 compositional morphology**: Tigrinya numerals are built from a fixed lexicon of digit roots (1–9), suppletive tens (10, 20, …, 90), and scale words (hundred, thousand, million, etc.). Correct decomposition depends on knowing which values have independent lexical forms (e.g., 20 = “ዕስራ”, not “ክልተ ዓሰርተ”).  
  *Quick check*: What is the canonical word for 70? (Answer: ሰብዓ)

- **Teen exception (11–19)**: Numbers 11–19 are lexicalized as “ዓሰርተ” (ten) followed directly by the digit unit, *without* an intervening “ን”. For example, 17 = “ዓሰርተ ሸውዓተ”. The algorithm must treat these as single “simple” units to avoid inserting an erroneous conjunction.  
  *Quick check*: How is 17 correctly verbalized? (Answer: ዓሰርተ ሸውዓተ)

- **Ordinal bifurcation**: Ordinal numbers have two regimes: 1st–10th use suppletive forms that vary by gender (e.g., masculine 1st = “ቀዳም”, feminine 1st = “ቀዳመይቲ”), while 11th and above are constructed periphrastically by prefixing “መበል” to the cardinal. The `num_to_ordinal` routine must first check the magnitude and gender flag.  
  *Quick check*: What is the feminine form of “7th”? (Answer: ሻውዐይቲ or ሻብዐይቲ)

## Architecture Onboarding
- **Component map** (plain text):  
  User API (`num_to_cardinal`, `num_to_ordinal`, `num_to_currency`, …) → Decomposer (scale‑iteration loop) → Core engine (`CONVERT<1000`) → Joiner (conjunction suffix application) → Output.

- **Critical path**: Input integer → loop over scales (thousand, million, …) extracting quotient and remainder → for each non‑zero quotient, call `CONVERT<1000` to produce a string → accumulate parts → after loop, process final remainder (<1000) → now have list of parts → if list length == 1, apply hundred allomorphy replacement (if needed) → if list length > 1, join parts with “ን” suffix (joiner adds “ን” to every part except the last) → produce final string.

- **Design tradeoffs**:  
  - *Deterministic rules vs. probabilistic models*: Guarantees full coverage and exactness, whereas LLMs fail on rare patterns.  
  - *Explicit decomposition vs. monolithic conversion*: Breaking numbers into scale‑based parts simplifies conjunction logic but requires careful handling of the `ISSIMPLE` predicate.  
  - *Eritrean variant default*: Adopting a single dialect provides a clear baseline but may limit immediate regional applicability.

- **Failure signatures**:  
  - Missing “ን” on any non‑initial component (e.g., “ዕስራ ሓሙሽተ” for 25).  
  - Incorrect teen handling (e.g., “ዓሰርተን ሸውዓተን”).  
  - Wrong hundred form (“ሚእቲ” used in a compound like 203).  
  - Scale word lacking “ን” when followed by lower components (e.g., “ሽሕ ሓደ” for 25 001).

- **First 3 experiments**:  
  1. `num_to_cardinal(25)` → expected `ዕስራን ሓሙሽተን`  
  2. `num_to_ordinal(1, feminine=True)` → expected `ቀዳመይቲ`  
  3. `num_to_currency(5.55, 'ERN')` → expected `ሓሙሽተ ናቕፋን ሓምሳን ሓሙሽተን ሳንቲምን`

## Open Questions the Paper Calls Out
1. **Mathematical expressions**: How to extend the system to handle equations and arithmetic operations in Tigrinya?  
2. **Dialectal variation**: To what extent do regional variants (Eritrean vs. Ethiopian) deviate from the documented rules?  
3. **LLM generalization**: Do the observed LLM failures generalize beyond the 100‑example set and models without official Tigrinya support?  
4. **Other numeric constructs**: Which remaining numeric forms (fractions, measurement units, large ordinals) are uncovered and how can they be integrated?  
5. **LLM error attribution**: Which specific linguistic features cause the most frequent LLM mistakes, and can rule‑augmented prompting or fine‑tuning improve accuracy?

## Limitations
- **External validation gap**: The rules are not corroborated by independent linguistic corpora or native speaker judgments; neighboring academic work engages minimally with Tigrinya numeral morphology.
- **LLM evaluation opacity**: Prompt templates, sampling parameters, and exact model versions are unspecified, hindering exact replication.
- **Normalization ambiguity**: The Unicode normalization form (NFC vs. NFD) used during string matching is not stated, potentially affecting reported accuracies.

## Confidence
- **Conjunction suffix “ን” as the primary compounding operator**: Medium confidence (strongly supported by the paper’s formalization but lacking external linguistic citation).
- **Scale‑word context‑sensitive standalone vs. compound distinction**: Medium confidence (clearly described but not independently validated).
- **Hundred allomorphy (“ሚእቲ” vs. “ሚእትን”)**: Medium confidence (based on authors’ analysis without comparative evidence).
