# Explainable Multimodal Aspect-Based Sentiment Analysis with Dependency-guided Large Language Model

## Quick Facts
- **arXiv ID:** 2601.06848
- **Source URL:** https://arxiv.org/abs/2601.06848
- **Reference count:** 22
- **Primary result:** A dependency-guided prompt strategy for multimodal LLMs improves classification (macro‑F1) and generates faithful, aspect‑grounded explanations for MABSA.

## Executive Summary
Multimodal aspect‑based sentiment analysis (MABSA) aims to predict sentiment toward specific aspects in text‑image pairs, but existing methods lack explainability. This work reformulates MABSA as a generative task using multimodal large language models (MLLMs). The core innovation is a **dependency‑syntax‑guided strategy**: for each aspect term, a subtree of the unified dependency tree (spanning across sentences) is extracted, textualized in a structured format, and injected into the MLLM prompt. This guides the model to focus on syntactically relevant context. The authors augment the Twitter2015 and Twitter2017 datasets with natural language explanations by prompting Qwen3‑VL‑32B under gold sentiment constraints. Fine‑tuning Qwen3‑VL‑4B/8B and Ministral‑3‑8B via LoRA yields consistent gains: e.g., Qwen3‑VL‑8B macro‑F1 rises from 70.2% to 73.0% (Twitter2015) and 71.1% to 73.4% (Twitter2017). The approach also produces aspect‑grounded explanations, outperforming prior prompt‑based methods and approaching non‑prompt state‑of‑the‑art.

## Method Summary
The method comprises three main stages. First, the original MABSA datasets (Twitter2015/Twitter2017) are augmented with natural language explanations. Using Qwen3‑VL‑32B, each sample (image, text, aspect, gold sentiment) is prompted to generate an explanation consistent with the sentiment. Second, for each text, a **unified dependency tree** is constructed: sentences are parsed individually, then a directed edge from the root of sentence *m* to the root of sentence *m‑1* is added, connecting all sentences. For a given aspect term, the corresponding node is identified (by matching the aspect string and taking its syntactic head token). A subtree containing all nodes within *n* directed hops (best *n*=2) of that node is pruned. The retained edges are textualized as `parent -> child (dependency_relation)` and concatenated. Third, this syntax text is included in a prompt to a multimodal LLM, which is fine‑tuned via LoRA to jointly predict a sentiment label and a free‑form explanation. Training uses 10 epochs, batch size 1, AdamW optimizer, learning rate 1e‑5, LoRA rank 4, alpha 16, dropout 0.1. During inference, the same prompt (without syntax for the baseline) is used to generate outputs, from which the sentiment label is parsed.

## Key Results
- Qwen3‑VL‑8B macro‑F1 improves by **+2.8%** on Twitter2015 (70.2%→73.0%) and **+2.3%** on Twitter2017 (71.1%→73.4%).
- The generated explanations are **faithful and aspect‑grounded**, achieving higher BLEU/ROUGE/BERTScore than prior prompt‑based approaches.
- The dependency‑guided approach consistently outperforms the same MLLM without syntax across training and zero‑shot settings, and approaches non‑prompt SOTA classification performance.

## Why This Works (Mechanism)
The dependency‑syntax guidance works by constraining the model’s attention to syntactically relevant tokens around the aspect term. The unified tree captures cross‑sentence dependencies, and pruning within a small number of hops (*n*=2) retains a focused yet sufficiently rich context, discarding distant noise. Textualizing edges as explicit relations provides a structured scaffold that the MLLM can parse and utilize for both classification and explanation. The LoRA fine‑tuning adapts the pre‑trained MLLM to this specialized prompt format without catastrophic forgetting, preserving its multimodal reasoning while aligning it with the syntactic cues. The generation of explanations is further anchored by the gold sentiment constraint during dataset creation, ensuring a tight coupling between label and rationale.

## Architecture Onboarding
**Component Map:**  
Original Data -> Qwen3‑VL‑32B (explanation generation) -> Augmented Dataset  
Text -> Dependency Parser -> Unified Tree -> Pruner (aspect subtree) -> Prompt Builder -> MLLM (LoRA) -> Output (Sentiment, Explanation)

**Critical Path:** Data preparation (original + explanations) → dependency parsing and pruning → prompt construction → LoRA fine‑tuning → evaluation (classification & explanation metrics).

**Design Tradeoffs:**  
- Generative vs discriminative: Generative allows explanations but may sacrifice some classification accuracy.
- Dependency depth (*n*): Smaller *n* reduces noise but may miss key cues; larger *n* retains more context but introduces irrelevant tokens. Optimal *n*=2 was found empirically.
- Parser choice: Different syntactic parsers yield different trees; tradeoff between accuracy and speed.
- Model size: Larger MLLMs (8B) perform better but cost more; smaller models (4B) are more accessible.
- Prompt format: Must balance clarity for the model and ease of parsing; deviations may cause format failures.

**Failure Signatures:**  
- Outputs missing required prefixes (`Sentiment:` or `Explanation:`) or containing extra text.
- Explanations that do not reference the aspect or image inconsistently.
- Classification performance significantly below reported numbers, possibly due to parser errors or incorrect aspect node selection.
- Training instability (loss spikes) indicating LoRA hyperparameter mismatch.

## Open Questions the Paper Calls Out
1. **Question:** How can generative MLLM‑based frameworks for MABSA achieve classification accuracy comparable to non‑prompt, discriminative methods while maintaining high‑quality explainability?  
   **Basis in paper:** [explicit] The authors note that their approach, despite improving over vanilla MLLMs, does not surpass non‑prompt SOTA in classification metrics (Table 4, Sec 4.1), attributing this to using pre‑trained MLLMs with syntactic cues without architectural modifications.  
   **Why unresolved:** The generative paradigm may inherently trade off fine‑grained classification accuracy for explanation fluency, or the prompt‑based format may limit optimization for sentiment labels.  
   **What evidence would resolve it:** Ablation studies separating classification and generation objectives within the same model, or hybrid architectures that use discriminative heads for labels alongside generative explanation modules.

2. **Question:** What principle determines the optimal depth (*n*) for aspect‑centered dependency pruning in MLLM‑based MABSA across different models and settings?  
   **Basis in paper:** [explicit] Experiments show that moderate pruning (e.g., *n*=2) often works best in fine‑tuning, but stricter pruning (*n*=1,2) sometimes outperforms in zero‑shot (Sec 4.1, 4.2; Tables 3,5). No theoretical guidance is provided.  
   **Why unresolved:** The optimal depth likely depends on the aspect‑context complexity and model capacity; current heuristics lack adaptability to data or model variations.  
   **What evidence would resolve it:** Large‑scale analysis correlating pruning depth with preservation of sentiment‑critical edges across diverse datasets, or an adaptive mechanism that learns optimal subtree size during training.

3. **Question:** How reliable are LLM‑generated explanations as training data for explainable MABSA, and what biases might they introduce?  
   **Basis in paper:** [explicit] The training explanations were generated by Qwen3‑VL‑32B with gold sentiment constraints, but only 10% were manually verified (Sec 3.1). The remaining 90% are assumed correct without comprehensive validation.  
   **Why unresolved:** LLMs may produce plausible but incorrect or image‑neglectful explanations consistent with the sentiment label, leading to noisy training signals that limit model robustness.  
   **What evidence would resolve it:** Full human annotation of the generated dataset to quantify error rates and types (e.g., hallucination, multimodal inconsistency), followed by controlled experiments measuring performance drop when training on subsets with known errors.

4. **Question:** Which specific dependency relations in the aspect‑centered subtree are most critical for sentiment reasoning, and can selective emphasis improve performance?  
   **Basis in paper:** [inferred] Ablation removing dependency relation labels (while keeping structure) degrades performance (Sec 4.3), indicating relation types provide useful signals. However, all relations are encoded uniformly in the textualization.  
   **Why unresolved:** Relations like `nsubj` (subject) or `amod` (adjectival modifier) may be more sentiment‑predictive than others like `det` (determiner), but this is unexplored.  
   **What evidence would resolve it:** Feature importance analysis (e.g., attention weighting) on the dependency edges to identify high‑impact relations, then modifying the prompt or model to weight these relations more heavily and measuring classification/generation gains.

## Limitations
- Ambiguity in mapping multi‑word aspect terms to a single dependency tree node (e.g., head token selection) is not fully specified.
- The dependency parser type and version are not fixed, leading to variability in the generated syntax prompts.
- The augmented explanation dataset is not publicly released, requiring re‑generation with Qwen3‑VL‑32B and manual verification, which hampers exact replication.
- The best‑performing models (Qwen3‑VL‑8B, Ministral‑3‑8B) may be proprietary, limiting accessibility for some researchers.
