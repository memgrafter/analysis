# MATHENA: Mamba-based Architectural Tooth Hierarchical Estimator and Holistic Evaluation Network for Anatomy

## Quick Facts
- arXiv ID: 2604.00537
- Source URL: https://arxiv.org/abs/2604.00537
- Reference count: 36
- Primary result: Unified framework for four dental diagnosis tasks (tooth detection, caries segmentation, anomaly detection, developmental staging) from Orthopantomograms, achieving state-of-the-art on PARTHENON with reduced computational overhead.

## Executive Summary
MATHENA introduces a unified framework to perform four key dental diagnosis tasks—tooth detection, caries segmentation (CarSeg), anomaly detection (AD), and developmental staging (DDS)—directly from Orthopantomograms (OPGs). It addresses efficiency and integration challenges by combining MATHE, a Mamba-based detector with directional Vision State Space (VSS) blocks for linear-complexity global context, and HENA, a Mamba-UNet with a Global Context State Token (GCST) for per-tooth multi-task analysis. A triple-head design with upstream CarSeg training and frozen feature transfer stabilizes learning and cuts training time by 3.5×. On the curated PARTHENON benchmark (15,062 instances), MATHENA outperforms CNN and Transformer baselines, reporting 93.78% mAP@50 for detection, 90.11% Dice for CarSeg, 88.35% for AD, and 72.40% accuracy for DDS.

## Method Summary
MATHENA processes OPGs in two stages. First, MATHE detects teeth using a YOLOv8m backbone where standard C2f blocks at deep stages (P4/P5) are replaced with C2fSSM containing four-directional VSS units to capture long-range dependencies in O(N) time. A BiFPN module fuses multi-scale features, and detection heads use WIoU loss. Detected teeth are cropped into 224×224 patches and fed to HENA, a Mamba-UNet encoder-decoder. A learnable global token is prepended to the bottleneck feature sequence; after Mamba processing, its state generates FiLM parameters to modulate skip connections. The decoder produces three outputs: caries segmentation, anomaly masks, and developmental stage labels. Training is sequential: the shared backbone is first trained on CarSeg, then frozen; AD is fine-tuned on the decoder, and DDS is learned via linear probing on the bottleneck. This strategy leverages caries segmentation’s dense supervision to regularize features while avoiding catastrophic forgetting.

## Key Results
- Tooth detection mAP@50: 93.78%
- Caries segmentation Dice: 90.11%
- Anomaly detection: 88.35%
- Developmental staging accuracy: 72.40%

## Why This Works (Mechanism)
- **Directional VSS for O(N) global context**: MATHE’s C2fSSM blocks employ Mamba’s selective SSM to scan feature maps in four directions (horizontal/diagonal), aggregating spatially coherent dental arch dependencies linearly with sequence length. This replaces quadratic self-attention. Evidence is provided in the abstract and Section 3.1; however, the break condition—performance drop if dental pathologies disrupt directional coherence—is not validated by ablation.
- **GCST for per-tooth modulation**: HENA compresses holistic semantics into a single global token `Tg` at the bottleneck; its output state is broadcast and used to derive FiLM parameters (γ, β) for each skip connection, enabling task-specific feature modulation with minimal overhead. Evidence is from Section 3.2; the break condition—potential loss of spatially resolved details (e.g., localized caries)—is not tested by increasing token count.
- **Frozen backbone transfer**: Sequential training first learns shared dental representations via CarSeg, then freezes the backbone while attaching AD/DDS heads. This prevents catastrophic forgetting, leverages caries segmentation’s dense supervision, and reduces training/inference time by 3.5×/1.4×. Evidence is in the abstract and Section 3.2; however, the assumption that CarSeg features universally transfer to AD/DDS is questionable given DDS’s lower accuracy.

## Foundational Learning
- **State Space Models (SSM) and Mamba**: Needed for linear-complexity sequence modeling to replace attention’s O(N²) cost; directional scanning extends SSMs to 2D vision tasks. Quick check: How does Mamba’s hardware-aware selective scanning differ from fixed scanning in earlier SSMs (e.g., S4), and why is directionality added for vision?
- **Multi-scale feature fusion (BiFPN)**: Needed to combine fine-grained (small teeth, root apices) and contextual (arch shape) features in high-resolution OPGs. Quick check: What is BiFPN’s computational cost vs. standard FPN, and how do learnable fusion weights affect gradient flow in detection?
- **Transfer learning via frozen upstream features**: Needed to efficiently adapt a shared backbone to multiple tasks with limited downstream data (AD/DDS). Quick check: What alternative strategies (e.g., adapters, progressive unfreezing) could break the assumed stability/freezing benefit?

## Architecture Onboarding
Component map: OPG input -> MATHE backbone (CNN early, C2fSSM at P4/P5) -> BiFPN -> detection heads (bounding boxes) -> per-tooth cropping -> HENA encoder (DWSep blocks) -> Mamba bottleneck with GCST -> decoder (transpose conv + GCST skip fusion) -> triple heads (CarSeg mask, AD mask, DDS label).  
Critical path: MATHE detection (high recall via pseudo-labels) -> cropping -> HENA multi-task with frozen backbone after CarSeg upstream training.  
Design tradeoffs:  
- Mamba vs. Transformer: Mamba offers linear complexity but directional VSS may miss isotropic long-range context (Transformer still outperforms CNN-only).  
- GCST simplicity vs. capacity: Single token reduces parameters but may bottleneck fine-grained task learning; skip fusion mitigates this.  
- Triple-head freezing: Gains efficiency (3.5× train time reduction) but risks underfitting downstream tasks (DDS ACC 72.40% suggests limitation).  
Failure signatures:  
- Detection mAP@50 <89% indicates GCST or BiFPN failure (ablation: w/o GCST -4.36%, w/o BiFPN -3.14%).  
- CarSeg/AD Dice <87% suggests Mamba bottleneck or skip fusion degradation (w/o Mamba BN: -2.36%, w/o GCST skip: -3.15%).  
- DDS ACC <70% may stem from frozen backbone discarding developmental cues or limited DDS data (only 380 images).  
First 3 experiments:  
1. Ablate directional VSS in MATHE: replace four-directional scanning with single/random directions; expect mAP@50 drop if directionality matters.  
2. Test GCST token capacity: vary token count (1,4,8); monitor CarSeg/AD Dice for nonlinear improvement.  
3. Compare transfer strategies: train triple-head with frozen backbone vs. full fine-tuning vs. adapter-based tuning for AD/DDS; assess stability (loss variance) and final metrics.

## Open Questions the Paper Calls Out
1. **Why does DDS accuracy (72.40%) significantly underperform CarSeg (90.11%) and AD (88.35%)?** Likely due to limited DDSNet data (380 images) or insufficient features; unresolved without error analysis by stage/tooth type, correlation with CarSeg quality, or metadata experiments.
2. **How does GCST compare to other global context methods (e.g., self-attention, pooling) in performance-efficiency trade-offs?** Only an ablation (removal) is provided; no direct comparison. Needs controlled replacements with comparable parameters, evaluating Dice/ACC, FLOPs, memory, and stability.
3. **Is sequential frozen-backbone training optimal?** Could joint training or progressive unfreezing improve multi-task synergy? Needs comparison with simultaneous multi-task (balanced/uncertainty-weighted losses) and adapter-based tuning.

## Limitations
- Missing architecture specifics (C2fSSM layer count, GCST dimensions) blocks faithful replication.
- No directional VSS ablation; the core mechanism remains untested.
- DDS accuracy low (72.40%) with only 380 images, limiting clinical utility.
- Frozen backbone assumption that CarSeg features universally transfer to AD/DDS may be invalid.
- Evaluation restricted to PARTHENON; external validation absent.
