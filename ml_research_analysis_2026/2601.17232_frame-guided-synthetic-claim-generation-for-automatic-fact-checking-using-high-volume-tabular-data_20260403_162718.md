# Frame-Guided Synthetic Claim Generation for Automatic Fact-Checking Using High-Volume Tabular Data

## Quick Facts
- **arXiv ID**: 2601.17232
- **Source URL**: https://arxiv.org/abs/2601.17232
- **Reference count**: 0
- **Primary result**: Generated 78,503 multilingual claims from 434 OECD tables (avg. 500K+ rows) using a frame-guided pipeline; baseline fact-checking system accuracy only 36.0%, with evidence retrieval as the primary bottleneck.

## Executive Summary
This paper addresses a critical gap in fact-checking benchmarks: the lack of high-volume tabular data. The authors introduce a novel frame-guided methodology that programmatically extracts statistically significant data points from 434 OECD tables (each averaging over 500,000 rows) using six semantic frames, generating 78,503 realistic claims in English, Chinese, Spanish, and Hindi. Knowledge-probing experiments confirm that large language models have not memorized these specific facts (only 2% exact match), ensuring the dataset requires genuine retrieval and reasoning. Evaluation of a baseline modular system (decomposition, retrieval, SQL generation, verdict synthesis) yields low accuracy (36.0%) and reveals evidence retrieval as the main bottleneck: table retrieval 32.2% and data retrieval 18.3%. The work highlights challenges in multilingual fact-checking and provides a large-scale, multilingual benchmark for future research.

## Method Summary
The dataset construction pipeline begins by preprocessing 434 OECD statistical tables to remove nulls and ensure a minimum time-window coverage (≥20 countries across ≥2 years). For each table, the algorithm identifies measure combinations and applies six predefined semantic frames (e.g., Top‑K, Constant‑Change, Historical‑Extreme) to programmatically select notable data points (e.g., highest/lowest ranks, continuous trends). These selected tuples serve as ground truth for claim generation: an LLM (Qwen3‑225B‑A22B) is prompted to produce natural language claims in English, which are then filtered using two LLM judges (Llama 3.3 70B and Qwen3‑225B‑A22B) for factual consistency. False claims are created by applying systematic perturbations (numeric, rank, duration, binary). The same English claims are translated into Chinese, Spanish, and Hindi using the LLM to create a multilingual set. The test set holds out ≥10% of tables (2,837 claims), with the remainder for training (75,666 claims). The baseline fact-checking system decomposes each claim into atomic subclaims using an LLM, retrieves the most relevant table via multilingual embeddings (gte‑multilingual‑base), generates an executable SQL query conditioned on the table schema and sampled distinct categorical values (BM25 for high‑cardinality columns), executes the query, and judges each subclaim against the results before aggregating to a final verdict.

## Key Results
- **Dataset scale**: 78,503 multilingual claims derived from 434 OECD tables (avg. 500K+ rows), covering six semantic frames.
- **Memorization check**: LLMs predict exact masked numeric values for only 2% of claims, demonstrating the dataset effectively probes retrieval capability.
- **Baseline performance**: Overall claim accuracy 36.0%; table retrieval accuracy 32.2%; data retrieval accuracy 18.3%, indicating severe evidence retrieval bottlenecks.

## Why This Works (Mechanism)
### Mechanism 1: Frame-guided claim diversity
Predefined semantic frames (Change_position_on_a_scale, Comparing_at_two_different_points_in_time, Comparing_two_entities, Occupy_rank, Constant‑Change, Historical‑Extreme) provide algorithmic rules to extract statistically significant patterns (e.g., top‑k ranks, continuous trends) from cleaned tables. This programmatic selection ensures a diverse set of realistic claim structures without LLM bias, as the model only paraphrases already selected facts. Core assumption: these frames reliably map to extractable patterns. Evidence: section 2.2 and 2.3.2 detail extraction logic for each frame. Break condition: insufficient statistical patterns yield no samples, limiting diversity.

### Mechanism 2: High-volume tables invalidate memorization
The sheer scale and specificity of OECD tables (500K+ rows each) make exact factual instances extremely unlikely to appear in LLM pre‑training. Knowledge‑probing shows only 2% exact match on masked value prediction, and claim‑knowledge alignment F1‑score of 21.1%, confirming low memorization. Thus, any correct verification must involve retrieving and processing the exact external table rows. Core assumption: negligible overlap with common corpora. Evidence: abstract and section 4.4 report the 2% exact match and alignment metrics. Break condition: if future LLMs are trained on this dataset, the memorization baseline would rise, weakening the benchmark.

### Mechanism 3: Multilingual pipeline reveals cross‑lingual gaps
True English claims are translated into Chinese, Spanish, and Hindi by the LLM while preserving grounded data references. This tests systems’ ability to handle linguistic variation without relying on English‑centric memorized facts. Baseline performance drops notably for Hindi (lower human quality, worse retrieval), suggesting language‑specific challenges. Core assumption: translation preserves factual grounding and frame semantics. Evidence: abstract and section 2.4 describe multilingual generation; Table 1 and section 4.1 show Hindi quality 66% vs ~90% for others, and Table 4 shows retrieval lag.

## Architecture Onboarding
The baseline system follows a modular pipeline:
**Component map**: Claim Decomposer -> Table Retriever -> SQL Generator -> Verdict Synthesizer
**Critical path**: Input claim is decomposed into atomic subclaims. For each subclaim: (a) Table Retriever searches a pre‑computed corpus of table representations (name + description + categorical values) using cosine similarity of multilingual embeddings; (b) SQL Generator produces an executable SQL query given the table schema and sampled distinct categorical values (BM25 for columns with >20 unique values), retrying up to 3 times on execution failure; (c) query is executed, and results are fed to the Verdict Synthesizer which judges the subclaim as True/False/Not Enough Information (NEI); (d) subclaim verdicts are aggregated to a final claim verdict. **Design tradeoffs**: Serializing full tables (e.g., TabSQLify) is infeasible for 500K‑row tables; modularizing retrieval introduces failure points. Atomic subclaims permit heterogeneous evidence but increase cumulative error risk. Context compression via unique categorical values and BM25 balances prompt length vs. completeness but may omit relevant filter values. **Failure signatures**: >50% NEI predictions indicate retrieval failure; low table retrieval for Hindi suggests embedding bias; high True‑NEI means correct tables not found; SQL errors reveal insufficient schema conditioning. **First 3 experiments**: 1) Decomposition sanity check: manually verify atomicity and exhaustiveness of subclaims for a random sample; 2) Table retrieval ablation: replace retriever with random table selector to confirm baseline inefficacy; 3) SQL error analysis: log execution failures and test few‑shot correction to estimate ceiling if retrieval were perfect.

## Open Questions the Paper Calls Out
1. **How can fact‑checking systems overcome the evidence retrieval bottleneck in high‑volume tables?**  
   Basis: "Our analysis identifies evidence retrieval as the primary bottleneck, with models struggling to find the correct data in massive tables." Table retrieval accuracy is 32.2% and data retrieval 18.3%. Why unresolved: The baseline achieves only 36.0% claim accuracy with 53% NEI, indicating systemic retrieval failure. What evidence would resolve it: novel retrieval architectures (e.g., hierarchical indexing, learned representations) that demonstrably improve table and data retrieval on this benchmark.

2. **Can the frame‑guided claim generation methodology be extended to the three excluded semantic frames (Ratio, Recurring_action, Uniqueness_of_trait)?**  
   Basis: The paper excluded these frames because programmatically identifying interesting and unambiguous data samples was particularly challenging. Why unresolved: these claim types remain unexplored, limiting diversity. What evidence would resolve it: Algorithms that reliably select significant data points for these frames from high‑volume tables, validated by human evaluation of claim quality and relevance.

3. **What factors cause the lower quality of Hindi claims (66% human‑rated good) compared to other languages (87–91%), and how can multilingual generation be improved?**  
   Basis: Hindi had a much lower rate of 66% good claims; annotator comments noted phrasing issues like "among OECD countries." Why unresolved: Quality disparities hinder Hindi fact‑checking research and raise fairness concerns. What evidence would resolve it: Detailed error analysis of Hindi claims and implementation of language‑specific generation strategies (e.g., tailored prompts, post‑editing) to achieve parity.

## Limitations
- The dataset release URL is anonymous and may not persist, blocking replication.
- Exact LLM prompts, generation hyperparameters, and held‑out table split are undisclosed; key definitions (e.g., "data retrieval accuracy") are ambiguous.
- Multilingual claim generation relies on LLM translation; semantic drift could bias results, especially for Hindi where quality is lower.
- Baseline system performance is low, and systematic error analysis is lacking; most failures stem from evidence retrieval.

## Confidence
- **Mechanism 1 (Frame‑guided selection)**: Medium confidence; frames are well‑defined but no quantitative diversity metrics.
- **Mechanism 2 (High‑volume forces retrieval)**: High confidence; knowledge‑probing strongly indicates negligible memorization.
- **Mechanism 3 (Multilingual pipeline)**: Medium confidence; cross‑lingual gaps documented but translation fidelity unverified.

## Next Checks
1. **Reproduce table retriever**: Compute per‑language table retrieval accuracy on the test set and analyze embedding similarity distributions to diagnose failures (e.g., for Hindi).
2. **Frame‑selection ablation**: Generate a contrasting dataset using random data point selection (no frames) and compare claim diversity and human‑rated realism to validate the frame‑guided approach.
3. **Audit translation fidelity**: Back‑translate 200 multilingual claims to English and have bilingual annotators verify preservation of data references and frame semantics; report drift rates, especially for Hindi.
