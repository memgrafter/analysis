# Uncertainty-Aware Dynamic Knowledge Graphs for Reliable Question Answering

## Quick Facts
- **arXiv ID**: 2601.09720  
- **Source URL**: https://arxiv.org/abs/2601.09720  
- **Reference count**: 12  
- **Primary result**: Confidence-filtered dynamic KG (τ=0.8) improves mortality prediction AUROC by +18.1% and AUPRC by +27.4% over historical baseline.

## Executive Summary
Static knowledge graphs often yield unreliable answers in clinical QA due to incomplete or noisy evidence. This work proposes uncertainty‑aware dynamic knowledge graphs (PKGs) that build patient‑specific graphs incrementally from EHRs, assign LLM‑derived confidence scores to each fact triple, and filter low‑confidence evidence during retrieval. On a mortality prediction task using MIMIC‑III, the filtered PKG achieves AUROC 0.575 and AUPRC 0.135, showing significant relative gains over a non‑filtered baseline. An interactive demo visualizes the evolving confidence‑annotated graphs and answer differences.

## Method Summary
The system constructs a patient‑specific PKG by incrementally merging per‑visit extracted triples (diagnoses, procedures, medications) into a historical graph, canonicalizing entities to standard terminologies (e.g., UMLS) and enriching with an external static medical KG. Each triple receives a confidence score *s* ∈ [0,1] via an LLM that reasons over contextual evidence from current and historical graphs. For QA, the retriever selects triples either from the full historical graph (baseline) or from a filtered variant where only triples with *s* ≥ τ (optimal τ=0.8) are used; the retrieved triples are fed to an LLM to generate the final answer.

## Key Results
- Filtered PKG (τ=0.8): **AUROC 0.575** (+18.1% relative), **AUPRC 0.135** (+27.4% relative) vs. Historical baseline.
- Confidence threshold τ=0.8 identified as optimal on MIMIC‑III mortality prediction.
- Interactive demo illustrates how confidence‑aware filtering improves answer reliability.

## Why This Works (Mechanism)

### Mechanism 1: Incremental PKG Construction
Claim: Building a patient‑specific knowledge graph incrementally from sequential EHR visits captures longitudinal context and evolving patient state.  
Mechanism: For each visit, entities/relations are extracted, canonicalized to standard terminologies, and merged into a cumulative historical graph. An external static KG provides additional background links, yielding enriched graph variants.  
Core assumption: Earlier visits inform later ones; canonicalization aligns surface variations to shared concepts.  
Evidence anchors: Abstract mentions “incrementally construct patient‑specific graphs” and “dynamic construction of evolving KGs”; Section II‑A details “Dynamic KG Construction” with Latest/Historical graphs and enrichment.  
Break condition: Missing visit timestamps or canonicalization failures prevent reliable longitudinal accumulation.

### Mechanism 2: LLM‑Based Confidence Scoring
Claim: Assigning confidence scores to triples via LLM reasoning over contextual evidence quantifies evidential reliability.  
Mechanism: For each triple (h,r,t), the system gathers a context of related triples from current/historical graphs and feeds this structured context to an LLM, which outputs a calibrated plausibility score *s* ∈ [0,1].  
Core assumption: LLMs can produce well‑calibrated consistency judgments when supplied with relevant structured context.  
Evidence anchors: Abstract states “assign confidence scores to triples via LLM reasoning over contextual evidence”; Section II‑B presents Confidence Estimation (Eq. 1) and prompt design.  
Break condition: Uncalibrated LLM scores (e.g., overconfidence) or context omitting contradictory evidence lead to misleading confidence estimates.

### Mechanism 3: Confidence‑Filtered Retrieval
Claim: Removing low‑confidence triples before retrieval reduces noise and improves QA accuracy.  
Mechanism: During retrieval, only triples with confidence ≥ τ (e.g., τ=0.8) form T(τ). These filtered triples (with scores) are passed to the LLM to generate answers.  
Core assumption: Noisy or unsupported triples harm LLM reasoning; filtering enhances signal and reduces hallucinations.  
Evidence anchors: Abstract reports filtered PKG gains; Section II‑C defines confidence‑aware retrieval (Eq. 2); Section III‑B quantifies improvements.  
Break condition: Poor correlation between confidence and truth, or τ chosen too high/low, degrades performance.

## Foundational Learning
- **Dynamic Knowledge Graphs**  
  *Why needed*: Represents patient data as an evolving, connected structure rather than isolated records, enabling longitudinal reasoning.  
  *Quick check*: How does merging a new visit’s triples into a historical graph preserve temporal context while avoiding duplication?

- **Confidence Scoring with LLMs**  
  *Why needed*: Provides a numeric measure of how well each medical fact fits the patient’s overall history and external knowledge, allowing uncertain facts to be handled explicitly.  
  *Quick check*: What components of the context (e.g., past triples, static KG links) most influence the LLM’s confidence score for a medication‑disease triple?

- **Retrieval‑Augmented Generation (RAG)**  
  *Why needed*: Supplies the LLM with grounded, structured evidence from the PKG to produce factual answers instead of relying solely on parametric knowledge.  
  *Quick check*: In a RAG pipeline, how does the size and relevance of the retrieved set affect the trade‑off between answer completeness and hallucination risk?

## Architecture Onboarding
- **Component map**:  
  EHR Input -> Entity/Relation Extractor -> Canonicalizer -> Dynamic KG Store -> Confidence Scorer -> Retriever -> LLM Generator -> Visualization

- **Critical path**:  
  1. Ingest new EHR visit → extract and canonicalize triples.  
  2. Merge triples into Historical graph to form Latest variant.  
  3. Enrich Latest with external static KG links.  
  4. Compute confidence scores for all triples using context from Historical + Enriched graphs.  
  5. Store Confidence‑aware and Filtered (τ=0.8) variants.  
  6. On query, retrieve from selected variant; pass to LLM for answer.  
  7. Render graph and answer in UI.

- **Design tradeoffs**:  
  - Confidence threshold vs. recall: Higher τ reduces noise but may discard useful rare facts; optimal τ is dataset‑dependent.  
  - Graph richness vs. latency: Enriching with external KG improves context but increases retrieval and prompt size.  
  - LLM‑based scoring vs. cost: Powerful LLM yields better calibration but raises compute expense and response time.

- **Failure signatures**:  
  - Degraded predictive performance (AUROC/AUPRC drop below baseline) indicates confidence mis‑calibration or over‑filtering.  
  - Inconsistent confidence distributions (e.g., many triples with near‑identical scores) suggest poor prompt design or insufficient context diversity.  
  - High retrieval latency or LLM prompt exceeding token limit points to an oversized graph variant.  
  - Visualization clutter (overlapping edges, unreadable labels) signals redundant triples from canonicalization/merge issues.

- **First 3 experiments**:  
  1. **Mortality prediction evaluation**: Run zero‑shot LLM on Historical, Confidence‑aware, and Filtered PKGs (τ=0.8) across MIMIC‑III; report AUROC/AUPRC.  
  2. **Threshold sweep**: Vary τ from 0.0 to 1.0 to identify optimal operating point and verify performance stability.  
  3. **Qualitative what‑if analysis**: Use demo to select predefined cases; compare baseline and confidence‑aware answers to illustrate how low‑confidence triples mislead without filtering.

## Limitations
- LLM prompt and context for confidence scoring are undisclosed, hindering replication and calibration checks.  
- Triple extraction/canonicalization schema from EHRs is underspecified, risking graph integrity.  
- Absolute QA performance (AUROC 0.575, AUPRC 0.135) remains low, limiting clinical applicability.

## Confidence
- Incremental PKG construction: **Medium** – Concept clear, but merge rules and canonicalization details are sparse.  
- LLM‑based confidence scoring: **Low** – Core mechanism relies on an opaque prompt; calibration in medical context is unverified.  
- Confidence‑filtered retrieval: **Medium** – Reported improvement, but threshold choice and generalization are uncertain.

## Next Checks
1. **Prompt audit and calibration**: Reimplement confidence scoring; assess score distribution and correlation with gold‑standard triple accuracy.  
2. **Threshold sweep**: Test τ ∈ [0.5,0.95], plot AUROC/AUPRC curves to find optimal threshold and stability region.  
3. **Ablation study**: Compare dynamic vs. static graphs, with/without external KG enrichment, and filtered vs. baseline retrieval to isolate contributions.
