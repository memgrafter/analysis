# RuleSmith: Multi-Agent LLMs for Automated Game Balancing

## Quick Facts
- **arXiv ID:** 2602.06232  
- **Source URL:** https://arxiv.org/abs/2602.06232  
- **Reference count:** 17  
- **Primary result:** RuleSmith achieves near-balanced win rates (~51%|49%) on CivMini using acquisition-based adaptive sampling with ~3500 games, significantly outperforming fixed-sampling baselines and random search, and the optimized parameters transfer across model capacities.

## Executive Summary
RuleSmith introduces a novel framework for automated balancing of asymmetric strategy games. It combines multi-agent LLM self-play—where specialized agents interpret textual rulebooks and generate actions—with Bayesian optimization over a multi-dimensional rule parameter space. A key innovation is acquisition-based adaptive sampling, which allocates more evaluation games to promising rule configurations, dramatically improving sample efficiency. On the CivMini benchmark, the system consistently converges to balanced win rates from imbalanced initializations, using only ~3500 self-play games over 100 iterations. The resulting parameters are interpretable and demonstrate transferability across different LLM capacities, effectively compensating for skill asymmetries.

## Method Summary
RuleSmith treats game balancing as a black-box optimization problem over 12 discrete rule parameters. It employs Bayesian optimization (BO) with a Gaussian process (GP) surrogate operating on a continuous relaxation of the parameter space. Each iteration proposes a continuous candidate $\tilde{\theta}_t$, which is deterministically projected to a valid discrete configuration $\theta_t$ via rounding/quantization. An adaptive sampler then determines the number of self-play games $N_t$ to allocate to $\theta_t$, scaling $N_t$ with the candidate’s expected improvement (EI): more games for high‑EI points, fewer for low‑EI points. Evaluation uses two LLM agents (Empire, Nomads) that receive faction‑specific rulebooks, state summaries with RAG‑retrieved snippets, and output JSON actions. After $N_t$ games, the balance loss $L(\theta_t)$ (based on win/draw rates) is computed and the GP is updated. The cycle repeats until a balanced configuration is found.

## Key Results
- RuleSmith converges to win rates of 51% (Empire) vs 49% (Nomads) with equally sized LLM models, achieving near‑perfect balance.
- Acquisition‑based adaptive sampling reaches this balance with ~3500 total games; fixed‑sampling baselines (e.g., 16 or 32 games per candidate) with comparable total budgets fail (e.g., 34%|66% or 61%|39%).
- Optimized rule parameters are interpretable and transfer across model capacity pairings, systematically compensating for skill asymmetries between LLM variants.

## Why This Works (Mechanism)

### Mechanism 1: Multi‑agent LLM self‑play as a flexible evaluator
- **Claim:** LLM‑based self‑play provides a zero‑shot, adaptable way to evaluate candidate rule configurations.
- **Mechanism:** For a given $\theta$, two specialized LLM agents (Empire, Nomads) receive textual rulebooks and structured game states; they output simultaneous actions in JSON. Multiple independent games yield empirical win/draw rates that form the balance loss $L(\theta)$.
- **Core assumption:** LLM agents can parse rulebooks, produce legal actions, and exhibit sufficiently strategic behavior to approximate human or optimal play for the purpose of estimating faction strength.
- **Evidence anchors:** Abstract states that LLM agents interpret rulebooks and game states; Section 3.2 details state construction, RAG retrieval, JSON format, and PASS fallback. Corpus includes related LLM‑game work (e.g., AvalonBench, MALBO) that supports feasibility.
- **Break condition:** If agents consistently produce illegal actions, fail to parse, or resort to degenerate strategies (e.g., always PASS), the win‑rate estimates become meaningless.

### Mechanism 2: Acquisition‑based adaptive sampling for sample efficiency
- **Claim:** Allocating evaluation budget proportionally to EI focuses computation on the most informative rule configurations.
- **Mechanism:** A GP surrogate models $L(\theta)$ with a Matérn 5/2 kernel. Expected Improvement guides candidate selection. The number of self‑play games $N_t$ for a candidate is set as $N_t = N_\text{min} + (N_\text{max} - N_\text{min}) \times \text{EI} / \max_{i\le t}\text{EI}$, concentrating samples on promising/uncertain points.
- **Core assumption:** EI reliably predicts the value of additional evaluation; increasing samples on high‑EI points reduces noise where it most improves optimization.
- **Evidence anchors:** Abstract mentions the approach; Section 3.3 gives the formula; Section 4.4 (Table 3) shows adaptive sampling achieves balance (~3500 games) while fixed $N$=16 or 32 (similar total) fails, directly supporting the efficiency claim.
- **Break condition:** If the GP posterior becomes poorly calibrated due to extreme non‑stationarity or LLM noise, EI rankings become misleading and budget allocation wastes effort.

### Mechanism 3: Discrete projection via continuous relaxation
- **Claim:** Searching a continuous relaxation of the discrete rule space allows standard BO techniques to be applied without a discrete optimizer.
- **Mechanism:** Proposals $\tilde{\theta}$ are made in a continuous hypercube. A deterministic projection $D(\cdot)$ (rounding to integers or quantizing to 0.1 steps) converts $\tilde{\theta}$ to a valid discrete configuration $\theta = D(\tilde{\theta})$.
- **Core assumption:** The loss landscape over the continuous relaxation is smooth enough that nearby $\tilde{\theta}$ values map to discrete $\theta$ with similar losses, and the continuous optimum projects to a good discrete optimum.
- **Evidence anchors:** Section 3.3 describes projection; Section 4.1 lists parameter precisions; Table 3 shows the method works on CivMini’s 12‑dimensional space.
- **Break condition:** If the true discrete optimum is an isolated spike with no continuous neighbors of similarly low loss, the continuous BO may converge to $\tilde{\theta}$ whose projection $\theta$ is far from optimal.

## Architecture Onboarding

### Component Map
Bayesian Optimizer (GP + Expected Improvement) → Discrete Projection (D) → Adaptive Sampler → LLM Agent Module (Empire/Nomads) → Game Engine (CivMini) → Evaluation Loop → Bayesian Optimizer (update)

### Critical Path
The optimizer proposes a continuous candidate $\tilde{\theta}_t$. This is projected to a discrete configuration $\theta_t = D(\tilde{\theta}_t)$. The adaptive sampler uses the EI of $\tilde{\theta}_t$ to set the number of evaluation games $N_t$. The LLM Agent Module runs $N_t$ self‑play games via the Game Engine, producing outcomes. The Evaluation Loop aggregates win/draw rates and computes the loss $L(\theta_t)$. The GP dataset is updated with $(\theta_t, L(\theta_t))$, and the optimizer proceeds to the next iteration.

### Design Tradeoffs
- *LLM-as-evaluator vs. RL agents:* LLMs offer zero‑shot flexibility but are slow, noisy, and costly; RL agents would be faster but require per‑rule training.
- *Adaptive sampling under a total budget:* The total budget is loosely bounded by max iterations and $N_\text{max}$; candidates with very high EI still get at most $N_\text{max}$ games, so the total number of games per iteration varies.
- *Continuous relaxation:* Enables use of standard BO but risks proposing $\tilde{\theta}$ whose discrete projection is invalid or far from optimal if the discrete space is sparse.

### Failure Signatures
- **Parsing/validity crash:** LLM outputs malformed JSON or illegal actions more than ~20% of the time; prompts or JSON schema likely need refinement.
- **Stagnant loss:** $L(\theta)$ does not decrease over many iterations; possible GP mis‑specification, too little average $N_t$, or no balanced configuration exists in the space.
- **Overfitting to LLM quirks:** Optimized parameters exploit InternVL‑specific biases; validate by evaluating with a different LLM (e.g., GPT‑4).
- **Discretization shock:** Projected $\theta_t$ always sits at parameter extremes; may indicate the continuous optimum lies between discrete steps, losing fidelity.

### First 3 Experiments
1. **Sanity check LLM self‑play:** Using a known hand‑balanced $\theta$, run 50 self‑play games with identical LLM agents. Win rates should be $50\% \pm 5\%$. Failure indicates fundamental bias or rule‑following issues.
2. **Ablate adaptive sampling:** Run full BO with fixed $N_t = 16$ for all iterations (total games similar to adaptive run). Compare convergence speed and final best $L(\theta)$; adaptive should outperform and reach balance while fixed fails (as per Table 3).
3. **Parameter transfer test:** Take the best $\theta$ found for InternVL3.5‑8B vs 8B and evaluate it under InternVL3.5‑2B vs 2B. A large loss increase (>0.2) indicates overfitting to model‑capacity asymmetries rather than generic balance.

## Limitations
- **GP hyperparameters** (length scales, noise variance, mean function) are unreported, risking suboptimal BO convergence.
- **LLM evaluation reliability** is fragile; if agents frequently produce illegal actions or degenerate strategies, loss estimates become invalid.
- **Discrete projection suitability** may fail on more combinatorial or sparsely sampled rule spaces where the loss landscape is highly non‑smooth.

## Confidence
- Multi‑agent LLM self‑play as evaluator: **Medium** (evidence from CivMini, but depends on unspecified prompt details)
- Acquisition‑based adaptive sampling: **High** (ablation directly demonstrates necessity and efficiency)
- Discrete projection via continuous relaxation: **Medium** (works on 12‑parameter CivMini; untested on larger/combinatorial spaces)
