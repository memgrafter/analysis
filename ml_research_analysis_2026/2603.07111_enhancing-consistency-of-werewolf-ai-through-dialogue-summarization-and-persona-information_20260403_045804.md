# Enhancing Consistency of Werewolf AI through Dialogue Summarization and Persona Information

## Quick Facts
- **arXiv ID:** 2603.07111
- **Source URL:** https://arxiv.org/abs/2603.07111
- **Reference count:** 9
- **Primary result:** LLM-based Werewolf agents maintain contextual and character consistency across multi-day dialogues using dialogue summarization and persona embedding.

## Executive Summary
This paper addresses the challenge of maintaining consistency in large language model (LLM) agents for the Werewolf game, a multi-day dialogue-based deduction game. The authors propose two core techniques: (1) dialogue summarization, where an LLM condenses each day's dialogue into a concise summary that is carried forward to subsequent days, and (2) persona embedding, where each role is assigned a fixed persona description and example utterances to enforce tone and behavior. In self-match games, agents demonstrated the ability to correctly reference information from earlier summaries, maintain stable and distinct character voices, and act in line with declared voting intentions. Evaluation relies on qualitative log analysis; no quantitative metrics are reported.

## Method Summary
The method integrates summarization and persona conditioning into the LLM agent's prompt. At the end of each day, an LLM generates a summary capturing key claims, suspicions, and divination results. For future days, these summaries replace the full dialogue history to manage context length. Each agent is assigned a role-specific persona: a set of descriptive traits and 3–5 example utterances that define the desired tone (e.g., a "king" for the seer, an "energetic soccer teen" for the werewolf). Additionally, hand-crafted "speaking strategies" (behavioral guidelines) are selected per day for certain roles. For critical actions like voting, a chain-of-thought (CoT) prompting step ensures reasoning aligns with the history. The full prompt combines the task description, persona, rules, selected strategy, prior summaries, and the current day’s dialogue so far.

## Key Results
- Agents accurately recall and reference information from previous days’ summaries (e.g., identifying the seer on Day 2 based on a Day 0 summary).
- Personas yield consistent and distinguishable character voices across the game (e.g., hesitant speech for the possessed, energetic slang for the werewolf).
- Final voting actions match previously declared intentions, demonstrating coherent behavior without contradictions.

## Why This Works (Mechanism)
The approach succeeds because dialogue summarization compresses the conversation into a distilled form that retains essential facts while reducing context length and interference from irrelevant utterances. Persona embedding steers the LLM’s output style through in-context examples and descriptive traits, anchoring the agent’s identity. Chain-of-thought prompting forces explicit reasoning, reducing inconsistencies between stated beliefs and actions. Together, these components mitigate the challenges of long-range dependency and role immersion in multi-day dialogues.

## Foundational Learning
The method builds on several key concepts:
- **Chain-of-Thought (CoT) Prompting**: Encourages step-by-step reasoning before final output, improving transparency and reducing contradictions. *Why needed*: Ensures decisions are traceable to historical context. *Quick check*: Verify that reasoning steps explicitly reference prior summaries or utterances.
- **Persona Conditioning**: Using descriptive traits and example utterances to shape the LLM’s output style. *Why needed*: Maintains character consistency across diverse game states. *Quick check*: Compare lexical features (e.g., formality, slang) across an agent’s turns.
- **Dialogue Summarization**: Condensing multi-turn dialogues into concise overviews. *Why needed*: Manages context window limits while preserving key information for later reference. *Quick check*: Assess summary completeness by checking for presence of key claims and role declarations.
- **Role-Specific Strategies**: Hand-crafted behavioral guidelines (e.g., seer reports divination first). *Why needed*: Provides domain-specific heuristics that compensate for LLM’s lack of game theory expertise. *Quick check*: Observe if agents follow the chosen strategy in their utterances.

## Architecture Onboarding
**Component Map**:  
Game Engine → Summary Generator (LLM) → Summary Store → Agent Prompt Constructor → LLM Agent → Utterance/Action → Game Engine  

**Critical Path**:  
1. At day end, summary generator produces a daily summary from raw dialogue.  
2. The summary is stored and later retrieved for subsequent days.  
3. For each agent turn, the prompt constructor compiles persona, rules, selected strategy, prior summaries, and current dialogue.  
4. The LLM agent generates a response; for critical actions, a CoT step is inserted.  
5. The game engine executes the action and updates the state.

**Design Tradeoffs**:  
- *Summary length vs. information retention*: Shorter summaries fit context windows but may omit subtle clues; longer summaries risk exceeding limits or diluting focus.  
- *Persona specificity vs. flexibility*: Highly specific personas reduce drift but may hinder adaptation to unusual game events.  
- *Strategy selection mechanism*: Using an LLM to pick strategies adds dynamism but introduces nondeterminism; rule-based selection is predictable but less adaptive.

**Failure Signatures**:  
- Missing references to prior summaries (e.g., agent ignores earlier seer claims).  
- Lexical drift (agent adopts vocabulary from others or becomes generic).  
- Action-utterance mismatch (declared vote differs from final vote).  
- Summary quality degradation (key facts absent or distorted).

**First Experiments**:  
1. **Baseline Comparison**: Run games with full history (no summarization) vs. summarized history to measure impact on reference accuracy and context length.  
2. **Persona Variation**: Test different persona descriptions (varying number of examples, level of detail) to identify minimal effective persona.  
3. **Consistency Metrics**: Implement automated checks for the three failure signatures: reference recall, style consistency (e.g., embedding similarity across days), and action-utterance alignment.

## Limitations
- Qualitative evaluation only; lacks quantitative consistency metrics, making it hard to measure effect size or compare baselines.  
- Hand-crafted personas and strategies limit reproducibility and may not generalize to other roles or settings.  
- Experiments confined to self-match games within the AIWolfDial 2024 simulator; generalizability to other environments, LLMs, or human-AI mixes is unknown.

## Confidence
- **Contextual consistency via summaries**: Medium confidence – plausible mechanism and qualitative evidence, but no quantified retention rates.  
- **Persona coherence**: Low confidence – stability claimed from manual review; no lexical or embedding analysis provided.  
- **Action-utterance consistency**: Medium confidence – CoT and structured prompts likely help, but absence of parsed logs or contradiction rates leaves claim unverified.

## Next Checks
1. Define and report quantitative consistency metrics: e.g., percentage of utterances correctly referencing entities from prior summaries, cosine similarity of utterance embeddings across days for persona drift, and rate of declared vs. actual vote matching.  
2. Conduct full ablation studies comparing the full method (summaries+persona) against ablations: no summarization (full history), no persona (generic prompt), summaries only, persona only. Measure all three consistency metrics to isolate contributions.  
3. Test generalizability by replicating the exact setup in a different open-source Werewolf simulator (e.g., `werewolves` Python package) and compare consistency metrics across environments.
