# AOrchestra: Automating Sub-Agent Creation for Agentic Orchestration

## Quick Facts
- arXiv ID: 2602.03786
- Source URL: https://arxiv.org/abs/2602.03786
- Reference count: 40
- Primary result: AOrchestra achieves a 16.28% relative improvement in pass@1 over the strongest baseline with Gemini-3-Flash; supervised fine-tuning adds +11.51% pass@1 on GAIA; in-context cost-aware routing reduces average cost by 18.5% while improving accuracy.

## Executive Summary
AOrchestra introduces a unified, framework-agnostic agent abstraction that models any agent as a four-tuple ⟨Instruction, Context, Tools, Model⟩. A central orchestrator dynamically instantiates specialized sub-agents by synthesizing this tuple—curating relevant context, selecting tools and models, and delegating execution—enabling automated, plug-and-play sub-agent creation for complex, long-horizon tasks. The system demonstrates significant performance gains on GAIA, SWE-Bench-Verified, and Terminal-Bench, and further benefits from learnable orchestration (supervised fine-tuning) and cost-aware model routing (in-context learning).

## Method Summary
AOrchestra employs a training-free orchestrator that decomposes user goals and outputs `Delegate(Φ)` actions, where Φ = (I, C, T, M). The orchestrator curates task-relevant context, selects a minimal tool subset, and picks a model for each sub-task. Sub-agents execute within the environment until completion, returning observations to the orchestrator, which then decides the next step. The orchestrator can be improved via supervised fine-tuning (SFT) on expert trajectories collected through the same framework, and via iterative in-context learning (ICL) to optimize cost-performance trade-offs by adjusting the prompt based on rollout metrics. Implementation uses Gemini-3-Flash, DeepSeek-V3.2, Claude-4.5-haiku, and tools like Serper, Jina, and E2B sandboxes.

## Key Results
- 16.28% relative improvement in pass@1 over strongest baseline (Gemini-3-Flash) on GAIA, Terminal-Bench, SWE-Bench-Verified.
- Supervised fine-tuning yields an additional +11.51% pass@1 on GAIA.
- In-context learning for cost-aware routing reduces average cost by 18.5% and improves accuracy, shifting the Pareto frontier.

## Why This Works (Mechanism)
**Mechanism 1: Dynamic tuple-based instantiation.** The four-tuple abstraction allows the orchestrator to automatically create specialized sub-agents on demand, avoiding the rigidity of pre-defined roles. For each subtask, it synthesizes a clear instruction, a curated context slice, a minimal tool subset, and an appropriate model. This dynamic creation reduces human engineering and supports heterogeneous capabilities. Break condition: if no suitable tools or models exist, or creation overhead outweighs gains.

**Mechanism 2: Explicit context curation.** The orchestrator injects only task-relevant history into the sub-agent’s Context, filtering out distracting or redundant details that cause context rot in long chains. An ablation on GAIA shows curated context outperforms both no-context and full-context baselines. Break condition: if the curation heuristic misses critical cues due to poor semantic matching.

**Mechanism 3: Learnable orchestration.** The orchestrator policy is improved via supervised fine-tuning (SFT) to imitate expert trajectories and via in-context learning (ICL) to optimize cost-aware model routing. SFT yields +11.51% pass@1 on GAIA; ICL reduces cost by 18.5% while improving accuracy. Break condition: SFT data distribution mismatch or noisy ICL cost signals may degrade behavior.

## Architecture Onboarding
**Component map:** Orchestrator (main) → synthesizes tuples → Sub-Agent executors; Tuple ⟨I, C, T, M⟩ defines sub-agent config; Tool pool (shared actions); Model router (selects model); Context curator (filters history); Reviewer/summarizer (for training data).

**Critical path:** 1. User query → orchestrator outputs `Delegate(Φ)`. 2. Sub-agent runs with (I, C, T, M) until `Finish`. 3. Observation returned to orchestrator. 4. Orchestrator updates state and repeats. 5. Ends when orchestrator outputs `Finish(y)`.

**Design tradeoffs:** Dynamic creation vs. latency; curated context vs. risk of omitting info; cost-aware routing vs. potential performance drop; framework-agnostic plug-and-play vs. missed optimizations; tuple simplicity vs. under-specification.

**Failure signatures:** Repeated delegation without state progression; high cost with low pass rate; sub-agent failures (missing tools/context); incorrect "done" status.

## Open Questions the Paper Calls Out
- **Open Question 1:** Can the orchestrator's model selection policy be fully automated and optimized to consistently approach the Pareto frontier without manual tuning? Current in-context learning still requires human-designed loops; reinforcement learning (e.g., GRPO) is suggested but untested.
- **Open Question 2:** What standardized evaluation framework can rigorously test the "plug-and-play" claim for arbitrary sub-agent implementations? Existing evaluation uses a limited set of frameworks; stress-testing across diverse architectures is needed.
- **Open Question 3:** Does supervised fine-tuning yield diminishing returns for longer-horizon tasks compared to reinforcement learning, and can a hybrid approach overcome imitation learning limits? SFT may not teach failure recovery or adaptation to novel decompositions.
- **Open Question 4:** How does the orchestrator's context curation mechanism work under the hood, and can it be replaced by a learned retriever/compressor? The current prompt-based curation might be inconsistent; learnable alternatives could improve relevance and token efficiency.
- **Open Question 5:** To what extent does the four-tuple abstraction handle tasks requiring dynamic redefinition of subtask boundaries or iterative feedback loops? Evaluation uses moderate horizons; scalability to very long workflows and dynamic replanning remains unknown.

## Limitations
- The 2K expert orchestration trajectories used for SFT are not public, blocking replication of the SFT gains.
- The `OPTIMIZE` procedure for in-context learning is underspecified, making the cost-aware routing results non-reproducible.
- The context curation heuristic is not fully described; risk of omitting critical information in long trajectories.

## Confidence
- Tuple-based dynamic instantiation: Medium
- Curated context benefit: High
- Learnable orchestration gains: Medium
