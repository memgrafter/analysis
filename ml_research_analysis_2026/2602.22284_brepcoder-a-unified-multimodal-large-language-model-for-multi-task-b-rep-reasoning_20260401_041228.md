# BrepCoder: A Unified Multimodal Large Language Model for Multi-task B-rep Reasoning

## Quick Facts
- **arXiv ID:** 2602.22284
- **Source URL:** https://arxiv.org/abs/2602.22284
- **Reference Count:** 40
- **Primary Result:** A single multimodal LLM processes industry-standard B-rep inputs for multiple CAD tasks via a two-stage training strategy, achieving SOTA reverse engineering (Chamfer Distance 0.464×10⁻³) and high accuracy on completion, error correction, and CAD-QA without task-specific architectures.

## Executive Summary
BrepCoder introduces a unified Multimodal Large Language Model (MLLM) that directly consumes Boundary Representation (B-rep) data—the standard geometric representation in CAD—to perform diverse engineering tasks. It translates CAD modeling sequences into executable Python-like code, enabling a single model to handle reverse engineering, completion, error correction, and CAD Question Answering. A two-stage training pipeline first aligns B-rep with code via reverse engineering pre-training, then fine-tunes on downstream tasks, eliminating the need for specialized architectures per task and demonstrating strong cross-task generalization.

## Method Summary
BrepCoder processes B-rep data (faces, edges, vertices) through a B-rep encoder, mapping it to a latent space aligned with Python-like CAD code. The model undergoes pre-training on a large-scale reverse engineering dataset, learning to reconstruct modeling sequences from B-rep inputs. This is followed by task-specific fine-tuning for completion (predicting missing modeling steps), error correction (fixing erroneous code), and CAD-QA (answering text queries about models). The unified code-based output space allows the same decoder to serve all tasks, with lightweight task adapters during fine-tuning.

## Key Results
- **Reverse Engineering:** Chamfer Distance 0.464×10⁻³ (52.26% improvement over prior SOTA), Invalid Ratio 0.86%.
- **Completion & Error Correction:** ACCcmd >92.69, ACCparam >87.94 (completion); ACCcmd 99.08, ACCparam 93.74 (error correction).
- **CAD-QA:** 79% accuracy on a proprietary QA dataset, showing reasoning beyond pure geometry.

## Why This Works (Mechanism)
The two-stage training strategy is key: pre-training on reverse engineering forces the model to learn a bidirectional mapping between B-rep topology and sequential CAD operations. This establishes a robust internal representation where geometry and code are symbiotic. Subsequent fine-tuning then adapts this shared latent space to task-specific objectives (e.g., predicting next commands, correcting errors, or answering questions) without relearning foundational alignments. The unified code output also simplifies evaluation and ensures generated operations are executable.

## Foundational Learning
- **B-rep (Boundary Representation):** Geometric modeling via faces, edges, vertices. *Why needed:* Primary input modality; model must parse topological/geometric relationships. *Quick check:* Can model parse STEP/IGES files into explicit face-edge graphs?
- **Multimodal Alignment:** Mapping between 3D geometry and symbolic code. *Why needed:* Bridge non-Euclidean B-rep data to sequential code tokens. *Quick check:* Does latent space interpolation produce coherent geometry-code pairs?
- **Reverse Engineering as Pre-text Task:** Predicting code from B-rep. *Why needed:* Self-supervised pre-training signal that enforces geometric-code correspondence. *Quick check:* Can model reconstruct code for unseen B-rep models with low invalid rate?
- **Code Generation for CAD:** Python-like DSL for modeling operations. *Why needed:* Unifies diverse CAD tasks into a single text-generation framework. *Quick check:* Are generated code snippets executable in a CAD kernel (e.g., OCCT)?
- **Task Generalization via Shared Latent:** One model for multiple tasks. *Why needed:* Avoids catastrophic forgetting and leverages common geometric-code priors. *Quick check:* Does fine-tuning on one task degrade performance on others?

## Architecture Onboarding
Component map: B-rep Encoder → B-rep-Code Aligner (pre-training) → Shared Code Decoder → Task-Specific Heads (Completion/Correction/QA)

Critical path: For reverse engineering, B-rep → encoder → decoder → code. For completion/correction, partial code → decoder → full code. For CAD-QA, B-rep + text query → encoder → decoder → text answer.

Design tradeoffs: Two-stage training risks negative transfer if fine-tuning data diverges from pre-training distribution; code-based output may limit expressiveness for non-operation-based tasks (e.g., material properties). B-rep encoder capacity must balance detail vs. sequence length.

Failure signatures: High Invalid Ratio in reverse engineering (code fails to generate valid B-rep); low ACCparam on complex features (e.g., splines); CAD-QA failures on questions requiring spatial reasoning beyond explicit geometry.

## Limitations
- External validation absent: SOTA metrics lack replication on independent CAD benchmarks; reliance on proprietary datasets.
- Generalization scope unclear: Robustness to diverse B-rep formats (e.g., from different CAD software) and complex geometries is unverified.
- Architecture trade-offs opaque: Sensitivity of two-stage training to data distribution, computational costs, and potential task interference are not detailed.

## Confidence
- Reverse engineering metrics (Chamfer Distance, Invalid Ratio): **Medium**. Significant improvement but evaluation may be dataset-specific.
- Completion/error correction accuracies (ACCcmd/ACCparam): **Medium**. High scores suggest strong code-generation, yet parameter accuracy thresholds may not capture nuanced CAD semantics.
- CAD-QA accuracy (79%): **Low**. Promising but on unspecified dataset; general reasoning ability across diverse engineering queries needs broader testing.

## Next Checks
1. **Benchmark replication:** Run BrepCoder on a public CAD dataset (e.g., ABC) using the same evaluation protocol to confirm reported metrics.
2. **Cross-format stress test:** Evaluate performance on B-rep files from multiple CAD kernels (Parasolid, ACIS) to measure representation robustness.
3. **Efficiency & ablation study:** Measure inference time/memory footprint; ablate the two-stage training to isolate contributions of pre-training versus fine-tuning.
