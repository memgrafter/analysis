# Embedding-Aware Feature Discovery: Bridging Latent Representations and Interpretable Features in Event Sequences

## Quick Facts
- **arXiv ID:** 2603.15713
- **Source URL:** https://arxiv.org/abs/2603.15713
- **Reference count:** 13
- **Primary result:** EAFD couples pretrained event-sequence embeddings with an LLM-driven feature generator, achieving up to +5.8% relative gains over SOTA embeddings on open benchmarks and up to +12.55% improvement on proprietary financial data.

## Executive Summary
EAFD addresses the long-standing gap between black-box embeddings and manually crafted features in industrial financial machine learning. By using a pretrained encoder to produce user embeddings from transaction sequences, the system iteratively proposes interpretable statistical features via an LLM. Each candidate is evaluated on two axes: alignment (how well it explains the embedding) and utility (whether it adds new predictive signal). The reflective loop steers the LLM toward features that either recover latent information or fill missing gaps. In extensive experiments across four public benchmarks and a large private dataset, EAFD consistently outperforms strong embedding baselines and weaker feature engineering approaches, establishing a new state-of-the-art.

## Method Summary
The framework takes raw event sequences and a frozen pretrained encoder as inputs. An LLM-based generator creates Python code for candidate features (e.g., aggregations, temporal statistics). Generated features are executed on a validation set, then scored: alignment is measured by R² of a model predicting embeddings from the feature; utility is the downstream loss reduction when the feature is concatenated to the embeddings. Scores and qualitative examples are formatted into a reflection prompt for the LLM, enabling a self-debugging, iterative refinement. After a fixed number of iterations, features with positive utility are selected within a budget and concatenated with the original embeddings. A downstream model (CatBoost) is trained on this joint representation for classification or regression tasks.

## Key Results
- Relative improvement up to **+5.8%** over state-of-the-art embeddings on open-source benchmarks.
- Gains up to **+19%** compared to weaker embedding baselines.
- On a proprietary dataset, EAFD boosts multi-target classification accuracy by **12.55%** and reduces regression error by **3.87%**.

## Why This Works (Mechanism)

### Mechanism 1: Dual-Regime Operation
The framework scores features on two independent axes: *Alignment* (R² of predicting embeddings from the feature) quantifies how much latent information the feature recovers, while *Utility* (downstream loss reduction) measures complementary predictive value. This bifurcation allows the LLM to explore both explanatory features (that reinterpret embedding content) and augmentative features (that fill blind spots). The core assumption is that pretrained embeddings mix recoverable information with gaps; scoring breaks this mixture. Evidence includes explicit definitions in Section 3 and the decomposition in Figure 2d. The process plateaus when no new features achieve meaningful alignment and utility scores become non‑positive.

### Mechanism 2: LLM Generator with Reflective Feedback
An LLM produces executable Python code for features, conditioned on previous iteration’s scores and high‑performing feature examples. A debug mode catches execution errors and feeds them back to the LLM for correction, enabling a closed learning loop. This directs the LLM toward task-aware code that respects the embedding‑aware criteria. The mechanism relies on the LLM’s ability to synthesize valid feature definitions when provided structured feedback. Evidence appears in the paper’s description of the generator loop and debug mode (Section 3). The loop stalls if the LLM repeatedly fails to produce executable code or all proposals are rejected by the thresholds.

### Mechanism 3: Feature‑Guided Decomposition of Embedding Space
By categorizing features into high‑alignment (explaining embedding content) and high‑utility (adding new signal), EAFD decomposes the joint feature‑embedding space into three semantic regions: latent (information only in embeddings), interpretable (explained by features), and blind‑spot (missing from both). This mapping reveals which aspects of the data (e.g., temporal patterns, amount distributions) are under‑encoded by a given encoder, enabling targeted interventions like guided fine‑tuning or privacy erasure. Evidence includes the abstract’s mention of decomposition and the empirical group reconstruction analysis (Section 4.3). The approach is limited by the granularity of the generated feature groups and the scoring metrics.

## Foundational Learning
- **Self‑Supervised Representation Learning for Event Sequences**  
  *Why needed:* EAFD uses a frozen pretrained encoder (e.g., CoLES via contrastive learning, NTP via next‑event prediction). Understanding these objectives explains the inherent biases that create “blind spots.”  
  *Quick check:* How might a contrastive objective versus a next‑event prediction objective lead to different information being prioritized in the embedding space?

- **Automated Feature Engineering with Large Language Models**  
  *Why needed:* The core generator is an LLM that writes feature code; one must grasp prompting strategies, code‑generation pitfalls, and how to supply effective scoring feedback.  
  *Quick check:* What are the risks of using an LLM to generate features from raw event sequences, and how does the debug mode mitigate them?

- **Information Complementarity vs. Redundancy**  
  *Why needed:* Distinguishing features that add new signal from those that merely re‑express embedding information is essential to avoid wasted computation or performance drops.  
  *Quick check:* If a feature has high alignment *and* high utility, what does that suggest about the embedding or the feature, and is such a feature desirable?

## Architecture Onboarding

### Component Map
Pretrained Encoder (f_θ) -> Embeddings (Z) -> LLM Generator (G) -> Generated Feature Code -> Feature Executor -> Feature Matrix g_k(S) -> Alignment Module (predict Z from g_k, compute R² A(g_k)) & Utility Module (compare downstream loss with/without g_k, compute U(g_k)) -> Reflection Formatter (packages A, U, examples) -> (feeds back to G) -> After iterations, Feature Categorizer & Selector -> Selected Complementary Features -> Concatenated Representation [Z, selected features] -> Downstream Model (CatBoost)

### Critical Path
1. Compute frozen embeddings Z from raw sequences.
2. Repeat for up to 5 iterations: G proposes feature code → Execute → Compute alignment A(g_k) and utility U(g_k) → Format reflection → Return to G.
3. Keep features with U(g_k) > 0.
4. Select top‑B complementary features by utility.
5. Train final CatBoost on [Z, selected features].

### Design Tradeoffs
- **Frozen vs. Fine‑tuned Encoder:** Freezing ensures stability but may miss adaptation opportunities; the paper shows guided fine‑tuning can help but risks overfitting.
- **LLM Backbone:** Larger models (gpt‑oss‑120B) produce more diverse, executable features but at higher cost and latency; smaller models may require more debug cycles.
- **Feature Budget:** Too small limits discovery; too large adds noise. The paper uses a fixed budget but does not detail selection beyond top‑U(g_k).

### Failure Signatures
- LLM repeatedly produces non‑executable code even after debug cycles.
- Alignment scores plateau while utility remains non‑positive, indicating no useful features can be found.
- Downstream performance degrades when adding features, suggesting score mis‑estimation or data leakage.

### First Experiments
1. **Baseline verification:** Generate embeddings with a pretrained encoder (e.g., CoLES) and train a CatBoost downstream model to confirm that baseline scores match reported numbers.
2. **Loop sanity check:** Run a single EAFD iteration with a very small feature budget (e.g., 1 feature) using a deterministic LLM setting to ensure the reflection‑generation‑execution pipeline works end‑to‑end.
3. **Score calibration:** Manually compute alignment (R² of predicting embeddings from a known handcrafted feature) and utility (downstream loss delta) to validate the scoring modules before scaling to LLM‑generated features.

## Open Questions the Paper Calls Out
- **Multi‑agent orchestration:** Could specialized agents for generation, selection, and refinement, coordinated via embedding‑aware signals, improve discovery?
  - *Basis:* Paper explicitly proposes this as future work.
  - *Why unresolved:* Not implemented or evaluated.
  - *Resolution evidence:* Build a multi‑agent EAFD variant and compare performance, efficiency, and feature diversity against the single‑agent system.

- **Integration with ensemble embeddings:** How can EAFD reason over multiple pretrained encoders and adapt feature exploration under representational uncertainty?
  - *Basis:* Paper suggests integrating with ensemble embeddings.
  - *Why unresolved:* Current framework uses a single frozen encoder.
  - *Resolution evidence:* Extend EAFD to accept multiple embedding models, measure whether joint reasoning yields complementary features and improved robustness compared to single‑embedding EAFD.

- **Automatic encoder tuning:** Can EAFD’s interpretability signals systematically tune encoder architectures and training objectives?
  - *Basis:* Paper notes that interpretation signals provide a foundation for automatic encoder tuning.
  - *Why unresolved:* Only a one‑off guided fine‑tuning example is shown; no closed‑loop system.
  - *Resolution evidence:* Develop a system where alignment/complementarity metrics directly modify encoder training (e.g., loss functions, architecture changes) and demonstrate sustained gains.

- **Scalability in production:** How does EAFD’s computational cost and feature management scale to millions of users and strict latency constraints?
  - *Basis:* Paper acknowledges industrial latency constraints but lacks detailed scaling analysis.
  - *Why unresolved:* Iterative LLM overhead not measured in large‑scale deployment.
  - *Resolution evidence:* Conduct scalability experiments with varying sequence lengths and user counts; perform A/B testing in a live system.

- **Cross‑domain and multilingual robustness:** Does EAFD generalize to non‑English event sequences or domains like healthcare/IoT?
  - *Basis:* All evaluated datasets are English‑centric financial benchmarks; LLM is English‑dominant.
  - *Why unresolved:* No cross‑lingual or cross‑domain evaluations.
  - *Resolution evidence:* Test EAFD on multilingual or diverse‑domain event sequence datasets, measure feature quality and performance adaptation needs.

## Limitations
- **Reproducibility gaps:** Exact prompt design, reflection format, hyperparameters, and data split definitions are not disclosed, hindering faithful replication.
- **LLM dependency:** The framework relies on a proprietary model (gpt‑oss‑120B); open‑source substitutes may yield different feature quality and behavior.
- **Encoder rigidity:** Using a frozen encoder may limit the discovery of truly complementary features, as suggested by the paper’s own fine‑tuning experiments.
