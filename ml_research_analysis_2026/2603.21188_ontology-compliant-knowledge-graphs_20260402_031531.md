# Ontology-Compliant Knowledge Graphs

## Quick Facts
- arXiv ID: 2603.21188
- Source: https://arxiv.org/abs/2603.21188
- Reference count: 24
- Primary result: Introduced ontology-compliant KGs to achieve internal alignment (matched classes up from 46.15% to 92.31%) and external alignment (top-1 accuracy up from 0.03% to 25.86% using DeepWalk).

## Executive Summary
Knowledge graphs (KGs) often suffer from non-compliance with their governing ontologies, causing interoperability and data quality issues. This paper proposes "ontology-compliant KGs" to enforce bidirectional alignment: internal compliance aligns KG terms with ontology definitions, reducing misaligned nodes and unused ontology elements; external compliance enables automatic alignment across different ontologies via intermediate compliant schemas; and pattern-based compliance allows flexible representation using ontology fragments evaluated via multi-criteria. A building-sector case study demonstrates substantial improvements: matched class rates increase from 46.15% to 92.31% and cross-ontology top-1 accuracy rises from 0.03% to 25.86% with embedding-based bridging.

## Method Summary
The approach comprises three algorithmic components. First, **internal compliance** (Algorithm 1) performs multi-level entity alignment (string, heuristic, semantic, topological) between a KG and its ontology, followed by ontology reconstruction to restore hierarchies. Second, **external compliance** (Algorithm 2) applies internal compliance to two KG/ontology pairs, jointly embeds the resulting compliant schemas, and predicts cross-ontology term matches via nearest-neighbor search. Third, **pattern-based compliance** decomposes ontologies into fragments (by abstraction level), generates candidate fragment sets, and selects the most compliant representation using Liebig's law and downstream task performance (e.g., classification accuracy). The building sector (Brick, RealEstateCore, Haystack) serves as the evaluation domain.

## Key Results
- Internal compliance increased matched classes from 46.15% to 92.31% while reducing unused ontology elements.
- External compliance improved top-1 accuracy from 0.03% to 25.86% (DeepWalk; Struc2Vec achieved higher) for cross-ontology property matching.
- Pattern-based compliance exhibited variable performance across abstraction levels, with classification accuracy peaking at certain fragment granularities.

## Why This Works (Mechanism)
### Mechanism 1: Internal Compliance Reshapes KG and Ontology
- **Claim:** Internal compliance matches KG terms to ontology definitions, eliminating unused ontology elements and reducing misaligned KG nodes.
- **Mechanism:** A two-phase algorithm (Entity Alignment, Ontology Reconstruction) progresses through four matching levels (pure string, heuristic, semantic, topological) with confidence scoring. Misaligned KG nodes are replaced by the most relevant ontology terms; the ontology is then reconstructed by restoring class/subclass hierarchies from matched entities.
- **Core assumption:** The KG's intended semantics can be approximated by mapping its terms to definitions in the original ontology, and unused ontology elements are those not referenced by any matched term.
- **Evidence:** Table 1 shows reshaped ontologies increasing matched classes from 46.15% to 92.31% and decreasing unused ontology size.
- **Break condition:** If confidence scores drop sharply at higher matching levels (e.g., Level 4), the reconstruction may introduce semantic distortions.

### Mechanism 2: External Compliance Bridges Ontologies via Compliant Schemas
- **Claim:** External compliance enables automatic alignment between KGs governed by different ontologies by using internally compliant schemas as intermediate bridges.
- **Mechanism:** Algorithm 2 first applies internal compliance (Algorithm 1) to each KG/ontology pair, producing clean, reduced schemas. These compliant schemas are embedded jointly in a shared vector space. Unmatched terms between the two original ontologies are then linked by nearest-neighbor search in this space, leveraging overlapping nodes in the compliant schemas as anchors.
- **Core assumption:** Embedding models trained on a graph combining KG data and compliant ontology schemas will place semantically similar terms—even from originally disconnected ontologies—in close vector proximity, provided the compliant schemas share some common nodes.
- **Evidence:** Table 2 demonstrates that using the proposed intermediate-schema method, top-1 accuracy improves from 0.03% (random) to 25.86% (DeepWalk) for the property match between Brick and RealEstateCore.
- **Break condition:** If the two compliant schemas share no overlapping concepts, the shared embedding space lacks anchoring points and the alignment fails (accuracy remains near random).

### Mechanism 3: Pattern-Based Compliance Selects Ontology Fragments
- **Claim:** Pattern-based compliance allows a KG to be represented by different, equally valid combinations of ontology fragments (from various source ontologies), selected via multi-criteria evaluation.
- **Mechanism:** An ontology is decomposed into fragments (e.g., by abstraction level: spaces, equipment, points). For a given KG, multiple fragment sets are generated and evaluated using criteria such as Liebig's law (minimum sufficiency across metrics) and joint learning performance (e.g., classification accuracy on KG embeddings). The best fragment set is chosen as the compliant representation.
- **Core assumption:** A KG's semantics can be captured by multiple non-identical ontology fragment sets, and their compliance can be compared objectively using metrics tied to downstream tasks.
- **Evidence:** Figure 7 shows classification accuracy varying across different fragments and abstraction levels, supporting the need for selection.
- **Break condition:** If all candidate fragment sets perform poorly on the evaluation metric, the method cannot select a compliant representation, indicating the fragments are semantically inadequate for the KG's content.

## Foundational Learning
- **TBox vs. ABox:** Understanding the distinction between ontology schema (TBox) and data instances (ABox) is essential because non-compliance arises from mismatches between the KG's data and its intended schema.
  - Quick check: "If a KG contains an instance of a class not defined in its ontology, is this a TBox problem or an ABox problem?" (Answer: TBox, because the schema lacks the class definition.)
- **Graph Embedding for Semantic Similarity:** Mechanism 2 relies on embedding models (DeepWalk, Node2Vec) to place ontology terms in a vector space where proximity reflects semantic similarity, enabling cross-ontology alignment via the shared vector space.
  - Quick check: "Why does training an embedding model on a graph that includes both KG triples and ontology class hierarchies help align terms from two different ontologies?" (Answer: The joint graph creates a unified topological and lexical context, pulling semantically equivalent terms—even from different ontologies—closer together if they share intermediate compliant nodes.)
- **Liebig's Law of the Minimum:** Pattern-based compliance uses Liebig's law to select ontology fragments: overall compliance is limited by the least-satisfied criterion among metrics like namespace count, hierarchy depth, and classification accuracy.
  - Quick check: "If Fragment A scores high on 'namespace count' but low on 'hierarchy depth', and Fragment B is the opposite, how would Liebig's law choose between them?" (Answer: The fragment with the higher minimum score across all criteria is selected, because the overall compliance is capped by the weakest dimension.)

## Architecture Onboarding
Component map: Input Pre-processor → Matching Engine → Reconstruction Manager → Embedding Bridge → Pattern Evaluator

Critical path: Raw KG + Ontology → Internal Compliance (Algorithm 1) → Compliant Schema 1 & 2 → Embedding Bridge (Algorithm 2) → Cross-Ontology Matches → Pattern Evaluator → Selected Fragment Set

Design tradeoffs:
- **Confidence vs. Coverage:** Higher matching levels increase coverage but reduce average confidence; system must balance precision/recall via a threshold.
- **Embedding Model Choice:** Struc2Vec gives high top-k accuracy but may overfit; DeepWalk is simpler but less accurate. Choice depends on lexical similarity of ontologies.
- **Fragment Granularity:** Finer fragments increase flexibility but explode evaluation search space; coarser fragments reduce options but may miss optimal combinations.

Failure signatures:
- **Internal:** High `Unused Ontology Size` after reshaping indicates poor matching coverage; low `Entity Matching Rate` suggests KG terms diverge too much from ontology.
- **External:** Top-1 accuracy near 0% implies no bridging link exists between compliant schemas.
- **Pattern:** All fragment sets show steep accuracy drop at higher abstraction levels, indicating none capture KG semantics robustly.

## Limitations
- Exact KG instance graphs, synthetic mismatch generation procedures, and embedding hyperparameters are undocumented.
- Code availability is restricted (access on request), hindering reproducibility.
- Evaluation is confined to the building sector, limiting generalizability to other domains.

## Confidence
- Internal compliance (Mechanism 1): Medium (strong internal metrics but no external validation)
- External compliance (Mechanism 2): Medium (embedding bridge plausible but hyperparameter-sensitive)
- Pattern-based compliance (Mechanism 3): Low (novel Liebig’s law application, variable results, no external support)
