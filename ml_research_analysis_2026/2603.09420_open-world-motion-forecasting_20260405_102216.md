# Open-World Motion Forecasting

## Quick Facts
- **arXiv ID:** 2603.09420
- **Source URL:** https://arxiv.org/abs/2603.09420
- **Reference count:** 40
- **Primary result:** OMEN, the first end-to-end class-incremental motion forecasting framework, achieves state-of-the-art mAPf on nuScenes and Argoverse 2 while reducing training time by ~40% versus full retraining.

## Executive Summary
This paper introduces *open-world motion forecasting*, addressing the real-world challenge of sequentially learning new object classes without forgetting previously learned ones, all under imperfect perception conditions. The proposed solution, OMEN, is an end-to-end class-incremental framework built on a DETR-style architecture. It generates motion pseudo-labels for known classes using future detections, filters false positives via a vision-language model, and combats catastrophic forgetting with a variance-based replay strategy that samples informative motion sequences. On nuScenes and Argoverse 2, OMEN significantly outperforms prior class-incremental methods, maintains performance on old classes, demonstrates zero-shot real-world transfer, and extends to class-incremental planning.

## Method Summary
OMEN adapts a pre-trained motion forecasting model (based on SparseDrive) to new object classes incrementally. For each incremental step with a new dataset containing a novel class, the previous model generates pseudo-labels for all known classes: it detects objects in current and future frames, associates them via maintained query identity, and uses future 3D positions as motion pseudo-labels. A vision-language model (Grounded SAM 2) filters these proposals by projecting 3D keypoints to 2D image masks and keeping only those where a majority falls within a mask of the correct class. To mitigate forgetting, a replay buffer is constructed by scoring all past sequences based on the variance of their motion query features relative to class means; the top-scoring sequences are stored. Training alternates between the new class’s ground-truth data and a mixture of filtered pseudo-labels and replay sequences, with a two-stage schedule (detection head first, then full model).

## Key Results
- On nuScenes per-class incremental (6 steps), OMEN achieves **15.60% mAPf** vs. CL-DETR’s 14.35%.
- On nuScenes group-incremental (3 steps), OMEN achieves **12.65% mAPf** vs. 12.02%.
- On Argoverse 2 20-2 setting, OMEN achieves **29.36% mAPf** vs. 26.51%.
- Training time is reduced by **~40%** compared to full retraining on all classes.

## Why This Works (Mechanism)

### Mechanism 1: Future-Detection-Based Pseudo-Label Generation
- **Claim:** The model generates motion forecasting pseudo-labels for previously learned classes in new datasets by leveraging its own future 3D object detections, avoiding the need for ground-truth trajectories.
- **Mechanism:** The end-to-end DETR-based architecture propagates object queries across time. For a new dataset containing a novel class, the previous model (`Φi−1`) processes multi-view images to produce 3D detections at the current and future timesteps. The 3D center coordinates of each detected object are transformed into the current ego-vehicle coordinate frame using homogenous transformation matrices, forming pseudo-labels for future motion.
- **Core assumption:** Query identity is maintained across frames via the model’s tracking mechanism, so future detections correspond to the same object instances as the current frame.
- **Evidence anchors:**
  - [abstract] "... employs a pseudo-labeling strategy to first generate motion forecasting pseudo-labels for all known classes..."
  - [section III.B.1] "...use the 3D object positions estimated by the detection decoder for the images from future time steps up to T... we do not require any external method to derive object associations..."
- **Break condition:** If query association fails (e.g., due to occlusions, rapid appearance changes, or crowded scenes), the future detections may incorrectly associate objects, generating invalid motion pseudo-labels that introduce noise.

### Mechanism 2: Vision-Language Model-Guided False Positive Filtering
- **Claim:** A vision-language model (VLM) filters false positive detections from the pseudo-label proposals, improving upstream detection quality and preventing the model from learning spurious motion patterns.
- **Mechanism:** For each 3D detection proposal, multiple 3D keypoints are sampled from its feature query and projected to all multi-view images. The VLM (Grounded SAM 2) provides 2D instance masks for known classes. A proposal is kept as a true positive pseudo-label only if the absolute majority of its projected keypoints fall within a VLM mask of the same class. Unmatched or low-confidence proposals are discarded or down-weighted.
- **Core assumption:** The VLM provides accurate, open-vocabulary segmentation masks for known classes in the image space, serving as a robust, annotation-free oracle.
- **Evidence anchors:**
  - [abstract] "...filters false positives via vision-language model matching."
  - [section III.B.2] "...employ the Grounded SAM 2 vision-language model (VLM) to reduce the number of FPs... If the absolute majority of the projected points... lies in at least one view inside an instance mask... we keep this pseudo-label proposal as a true positive."
- **Break condition:** If the VLM systematically fails on domain shifts (e.g., novel viewpoints, weather, or object appearances), it may produce false negatives (correct detections filtered) or false positives (incorrect masks retained), degrading pseudo-label quality.

### Mechanism 3: Query Feature Variance-Based Replay Sampling
- **Claim:** A replay buffer populated with sequences selected for high variance in the latent motion query space effectively mitigates catastrophic forgetting by preserving informative motion patterns of old classes.
- **Mechanism:** For each sequence in the old dataset, the model’s motion queries for all ground-truth objects are extracted. The per-class mean motion query is computed. A sequence’s score for a class is the sum of squared deviations of its object queries from that class mean. The top-scoring sequences (highest variance) are stored in the replay buffer, split evenly across old classes.
- **Core assumption:** Sequences with high variance in the motion query latent space correspond to scenes with diverse, non-linear, or otherwise informative motion patterns critical for retaining forecasting knowledge.
- **Evidence anchors:**
  - [abstract] "...variance-based replay strategy sampling informative motion sequences to combat catastrophic forgetting."
  - [section III.C] "...we base the replay buffer on statistics about the motion queries... select the P sequences with the highest scores as replay samples per class because they generally represent scenes with a high to moderate number of moving objects with linear and non-linear future trajectories."
- **Break condition:** If motion query variance is not predictive of true motion diversity (e.g., variance stems from detector noise, background clutter, or static objects misclassified as moving), the replay buffer may store uninformative or misleading sequences, offering limited protection against forgetting.

## Architecture Onboarding
- **Component map:** Image Encoder → Detection Decoder → Motion Decoder (end-to-end pipeline); VLM Module (Grounded SAM 2) for false positive filtering; Replay Buffer Manager for variance-based sequence selection; Training Loop integrates pseudo-labels, replay, and new-class fine-tuning.
- **Critical path:** New class data arrives → old model generates detection & motion pseudo-labels for known classes → VLM filters false positives → variance-based replay sequences from old data added → model trained on combined set (new class GT + old class pseudo-labels + replay).
- **Design tradeoffs:**
  - *Replay buffer size:* Larger `Nreplay` better combats forgetting but increases memory/storage; paper uses fixed 30 sequences.
  - *VLM confidence threshold:* Lower `θ` yields more pseudo-labels but more FPs; paper uses `θ=0.3`.
  - *Pseudo-label source:* Using future detections (vs. current-frame predictions or GT) improves accuracy for non-linear motion but depends on reliable multi-frame tracking.
- **Failure signatures:**
  - Increasing false positive rate in old-class predictions over incremental steps.
  - Sharp drop in mAP_f for early-learned classes after adding new classes.
  - VLM filtering removing too many true positives (low recall) or retaining too many FPs (low precision).
- **First 3 experiments:**
  1. **Baseline comparison:** Run forgetting baseline (no replay/pseudo-labeling) vs. OMEN on per-class incremental nuScenes to quantify catastrophic forgetting.
  2. **Ablation - Pseudo-label source:** Compare motion pseudo-labels generated from future detections (OMEN) vs. current predictions (baseline) to validate the design choice.
  3. **Ablation - Replay strategy:** Compare variance-based replay vs. random selection vs. DINOv3-based selection (Table VI) to confirm that motion query variance selects more informative sequences for forecasting.

## Open Questions the Paper Calls Out
- **How can OMEN be effectively adapted to closed‑loop planning where the ego‑vehicle’s actions influence future observations?** The current study only evaluates open‑loop planning; closed‑loop introduces feedback loops, non‑stationary data distributions, and safety‑critical constraints. It is unknown whether the class‑incremental mechanisms remain stable or suffer from catastrophic forgetting when actions alter the scene.
- **How does OMEN handle previously learned classes that become completely absent in later incremental steps?** The experiment did not enforce absence of classes in subsequent steps, which could lead to increased forgetting due to missing pseudo‑labels. Real deployments may encounter such absence (e.g., seasonal or geographical shifts).
- **Can the reliance on ground‑truth annotations for novel classes be eliminated, enabling OMEN to learn new classes from unlabeled data?** Manual labeling of novel classes is a bottleneck. If the framework could generate its own pseudo‑labels for novel classes (e.g., via vision‑language models or self‑supervision), it would become more scalable and truly open‑world.
- **Does incorporating high‑definition (HD) maps or online map generation improve open‑world motion forecasting, and how does it affect incremental learning?** Maps provide strong priors about lane geometry and traffic rules, potentially aiding prediction. However, maps may require updates as new classes appear or environments change, and their integration might interact with the incremental learning mechanisms in unknown ways.

## Limitations
- Code availability is uncertain; as of the provided text, the repository is not publicly released, hindering independent verification.
- VLM implementation details (model versions, prompts, mask IoU thresholds, keypoint sampling) are not fully specified, making exact replication difficult.
- The replay buffer size is fixed at 30 sequences without thorough sensitivity analysis; this hyperparameter may significantly affect the forgetting-plasticity trade-off.
- Evaluation is limited to nuScenes and Argoverse 2; generalizability to other datasets, sensor modalities, or extreme domain shifts is unclear.
- The method relies on ground-truth annotations for novel classes during incremental steps, which is a practical bottleneck for truly open-world deployment.

## Confidence
- **Overall OMEN effectiveness (SOTA mAPf, training time reduction):** Medium – results are self‑reported; code not yet public, so independent verification pending.
- **Pseudo-label generation via future detections:** Medium – relies on query identity tracking, which may fail under occlusions or crowded scenes.
- **VLM false‑positive filtering:** Medium – depends on Grounded SAM 2’s segmentation accuracy; domain shifts could degrade performance.
- **Variance‑based replay sampling:** Medium – assumes motion query variance correlates with trajectory diversity; plausible but not fully validated across all scenarios.
- **Zero‑shot real‑world transfer:** Low – limited evaluation; transfer performance may vary significantly across unseen environments.
