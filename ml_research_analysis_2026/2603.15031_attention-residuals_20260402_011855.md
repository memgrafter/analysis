# Attention Residuals

## Quick Facts
- **ArXiv ID**: 2603.15031
- **Source URL**: https://arxiv.org/abs/2603.15031
- **Reference count**: 40
- **Primary result**: Attention Residuals (AttnRes) replaces fixed residual accumulation with softmax attention over preceding layer outputs, enabling selective aggregation; Block AttnRes reduces overhead and scales to 48B models, yielding consistent loss improvement and notable downstream gains (+7.5 on GPQA-Diamond, +3.1 on HumanEval).

## Executive Summary
Standard residual connections in PreNorm architectures suffer from hidden-state growth and dilution of contributions as depth increases. This paper introduces Attention Residuals (AttnRes), which replaces the fixed summation of residual branches with a learned, input-dependent attention mechanism over all preceding layer outputs. This selective aggregation mitigates dilution while maintaining compatibility with existing Transformer training. To address the O(Ld) memory and communication costs of full AttnRes, the authors propose Block AttnRes, which partitions layers into blocks and attends over block summaries, reducing overhead to O(Nd). Combined with cache-based pipeline communication and a two-phase inference strategy, Block AttnRes becomes a practical drop-in replacement with minimal overhead (<4% training, <2% inference). Scaling laws demonstrate consistent validation loss improvement, and Block AttnRes matches a baseline with 1.25× more compute. On a 48B Kimi Linear model pre-trained on 1.4T tokens, AttnRes yields bounded output magnitudes, uniform gradient distribution, and superior downstream performance across 14 benchmarks, with especially large gains on complex reasoning tasks (+7.5 on GPQA-Diamond, +3.1 on HumanEval).

## Method Summary
AttnRes introduces a learnable query vector w_l for each layer l. Instead of adding the residual branch directly, the layer’s input is computed as a weighted sum of all previous layer outputs (including the embedding), with weights given by a softmax attention over normalized keys: α_{i→l} = softmax(exp(w_l^⊤ RMSNorm(k_i))). This allows input-dependent, selective aggregation. To reduce the O(L) memory and communication cost, Block AttnRes partitions the L layers into N blocks (typically N≈8). Within a block, standard residuals are used; at block boundaries, the block’s summary (sum of outputs) is computed and used as a key for subsequent blocks. System optimizations include caching block summaries across pipeline virtual stages to avoid redundant transfers and a two-phase inference schedule that batches inter-block queries and merges intra-block outputs with online softmax. These changes incur less than 4% training and 2% inference overhead.

## Key Results
- Consistent validation loss improvement across scaling law experiments; Block AttnRes achieves compute equivalence of 1.25× more baseline compute.
- On the 48B Kimi Linear model: bounded output magnitudes, uniform gradient distribution, and gains on all 14 downstream benchmarks.
- Absolute improvements: +7.5 on GPQA-Diamond and +3.1 on HumanEval.

## Why This Works (Mechanism)
**Mechanism 1: Selective aggregation through attention**
- **Claim**: Attention Residuals (AttnRes) replaces fixed residual accumulation with softmax attention over preceding layer outputs, enabling each layer to selectively aggregate earlier representations with learned, input-dependent weights.
- **Mechanism**: Each layer computes a pseudo-query w_l and attends to keys k_i = v_i (prior outputs) with softmax weights α_{i→l} = exp(w_l^⊤ RMSNorm(k_i)) / Σ. Input h_l = Σ α_{i→l} v_i.
- **Core assumption**: Depth-wise selective retrieval mitigates PreNorm dilution by preventing uniform growth of hidden-state magnitudes.
- **Evidence anchors**: [abstract]; §3.1; corpus includes "Value Residual Learning" identifying dilution.
- **Break condition**: If attention weights collapse to uniform (e.g., poor initialization), AttnRes reverts to standard residuals, losing benefits.

**Mechanism 2: Block partitioning for efficiency**
- **Claim**: Block AttnRes partitions layers into blocks, attending over block summaries to reduce memory and communication from O(Ld) to O(Nd).
- **Mechanism**: Layers grouped into N blocks; each block outputs a summary b_n = Σ f_j(h_j). Layers attend to prior blocks and intra-block partial sums.
- **Core assumption**: Block summaries preserve essential cross-layer information while cutting overhead proportional to block count N (≈8 optimal).
- **Evidence anchors**: [abstract]; §3.2; Fig. 2 pseudocode.
- **Break condition**: Excessively large block size (e.g., S≥16) dilutes selective aggregation, approaching baseline.

**Mechanism 3: Infrastructure optimizations**
- **Claim**: Cache-based pipeline communication and two-phase inference make Block AttnRes practical with <4% training and <2% inference overhead.
- **Mechanism**: Caching blocks across pipeline virtual stages avoids redundant transfers; two-phase computation batches inter-block queries and merges intra-block outputs via online softmax.
- **Core assumption**: System-level scheduling amortizes O(L) costs to O(N) per layer.
- **Evidence anchors**: [abstract]; §4; Algorithm 1.
- **Break condition**: Without caching, pipeline communication scales as O(C) with virtual stages; without two-phase, inference I/O scales linearly with L.

## Architecture Onboarding
**Component map**: Learned per-layer query w_l → RMSNorm on prior outputs (keys) → dot-product scores → softmax → weighted sum of values (prior outputs) → aggregated input h_l to layer. For Block AttnRes: layers grouped into blocks; each block maintains a summary (sum of outputs). Layers attend over previous block summaries and, if within a block, the current partial sum. System components: block partition controller, block summary buffers, cache manager for cross-stage communication, and two-phase attention scheduler (batched inter-block, sequential intra-block).

**Critical path**:
1. Initialize all w_l = 0.
2. Insert AttnRes before each Transformer layer’s function f_l, computing h_l via attention over prior sources.
3. For Block AttnRes, maintain `blocks` list and `partial_block` per Fig. 2 pseudocode.
4. Integrate with distributed training: ensure block summaries are cached and transmitted only at block boundaries.
5. During inference, implement two-phase schedule: batch queries within a block, then sequential intra-block with online softmax merge.

**Design tradeoffs**:
- Full vs. Block AttnRes: Full offers max selectivity but O(L) memory; Block reduces to O(N) with N≈8 recovering most gains.
- Block size S: Smaller S preserves granularity but increases N (if fixed L); paper finds S=4–8 optimal.
- Learned vs. input-dependent query: Learned w_l avoids per-token projection; input-dependent improves loss but adds latency.

**Failure signatures**:
- Training divergence or no improvement if w_l not zero-initialized.
- No loss reduction if RMSNorm omitted from key normalization.
- Memory explosion in pipeline if caching not implemented; monitor block transfer counts.
- Performance drop if block size too large (compare validation loss across S sweeps).

**First 3 experiments**:
1. Baseline comparison: Train a small model (e.g., 194M active parameters from Table 2) with baseline, Full AttnRes, and Block AttnRes (N=8); confirm validation loss improvement.
2. Initialization ablation: Train Block AttnRes with random w_l vs. zero init; expect instability or higher loss without zero init.
3. Block size sweep: Vary S (e.g., 1, 2, 4, 8, 16) on fixed compute; validate that S=4–8 matches full performance while reducing memory per Table 1.

## Open Questions the Paper Calls Out
**Open Question 1**: Can more memory-efficient linear-complexity attention mechanisms (e.g., state-space models) be effectively integrated into AttnRes's depth-wise attention to further reduce the O(L²) or O(LN) costs for very deep models? Basis: Section 6.1; unresolved because not explored; resolution would require implementing and scaling linear-depth attention variants on large-scale models and comparing against softmax-based AttnRes.

**Open Question 2**: What is the optimal block size S (or number of blocks N) for AttnRes across diverse model scales (depth, width, MoE sparsity) and hardware configurations? Basis: Section 5.3 and Fig. 6 (sweep on small models); unresolved because only evaluated on small models and a single 48B config; resolution would involve comprehensive scaling study with varying N across model sizes and hardware, measuring loss, throughput, memory, and communication.

**Open Question 3**: Does using an input-dependent query (computed from the current hidden state) provide a net benefit in large-scale pre-training when accounting for its added computational cost and sequential dependency during inference? Basis: Section 5.3; unresolved because not tested on the main 48B run; resolution would integrate an input-dependent query into Block AttnRes training of the 48B model and measure final loss, downstream performance, throughput, and inference latency.

**Open Question 4**: What specific properties of the depth-wise attention kernel ϕ(q,k) are most critical for AttnRes's success (e.g., normalization, RMSNorm on keys, score function), and can simpler or more hardware-efficient kernels match its performance? Basis: Section 5.3 ablations (softmax vs sigmoid, RMSNorm removal); unresolved because kernel design space not systematically explored; resolution would conduct large-scale ablation on kernel variants (normalization, key transforms, scoring functions) on large models.

**Open Question 5**: What is the causal mechanism by which AttnRes improves downstream task performance (especially on complex reasoning like GPQA-Diamond)? Is it due to better gradient flow uniformity, reduced representation dilution, or learned depth-wise skip connections? Basis: Correlational evidence (gradient uniformity, bounded magnitudes, attention patterns); unresolved because no causal interventions; resolution would involve targeted experiments (e.g., zeroing attention to early layers, adding learned skip connections to baseline, mediation analysis).
