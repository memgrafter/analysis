# PlanaReLoc: Camera Relocalization in 3D Planar Primitives via Region-Based Structure Matching

## Quick Facts
- **ArXiv ID**: 2603.20818
- **Source URL**: https://arxiv.org/abs/2603.20818
- **Reference count**: 40
- **Primary result**: Plane-centric 6-DoF camera relocalization; on ScanNet median rotation 3.8°, translation 0.20m; pose recall 73.1% at (0.5m,15°); matching F1-score 64.3% (ScanNet) and 58.6% (12Scenes).

## Executive Summary
PlanaReLoc addresses 6-DoF camera relocalization in indoor scenes by representing the 3D map as a set of planar primitives instead of a point cloud. Given a query RGB image, it recovers 2D plane segments via a frozen depth estimator and RANSAC plane fitting, matches them to the 3D map planes using learned embeddings and a transformer, and estimates the camera pose via robust optimization. The approach requires neither textured maps nor per-scene training and achieves state-of-the-art accuracy on ScanNet and 12Scenes.

## Method Summary
The pipeline comprises five stages. (1) Monocular plane recovery: a pretrained MoGe-2 predicts metric depth; RANSAC fits planes to the depth map, yielding image-plane segments. (2) Plane embedding: query planes aggregate image features; map planes are encoded with a PointNet-based network that consumes their point clouds and shapes. (3) Matching: a transformer stack with rotary positional encoding on plane normals produces a soft assignment matrix; mutual nearest neighbor selection with a threshold establishes correspondences. (4) Pose estimation: rotation is solved robustly from two non-parallel plane pairs via RANSAC; translation is obtained by weighted least squares with scale compensation. (5) Pose refinement: the pose is further optimized by aligning rendered map depth to the query plane segments. Training uses a two-stage procedure with negative log-likelihood supervision on the assignment matrix, AdamW optimizer, batch size 16 on two A800 GPUs for approximately 12 hours.

## Key Results
- Median rotation 3.8°, translation 0.20m on ScanNet.
- Pose recall 73.1% at (0.5m, 15°) on ScanNet.
- Matching F1-score 64.3% on ScanNet, 58.6% on 12Scenes.

## Why This Works (Mechanism)
Planar primitives offer a compact, semantically meaningful representation suited to indoor environments. The learned embedding aligns 2D image planes with 3D map planes by jointly modeling geometry (normals) and appearance. The transformer captures long-range interactions and robustly handles noisy proposals. Mutual nearest neighbor matching enforces one-to-one correspondences, while robust pose estimation from planar constraints reduces sensitivity to outliers. Final depth-alignment refinement further improves accuracy. Crucially, relying on geometry rather than texture allows operation in low-texture or repetitive scenes.

## Architecture Onboarding
The codebase implements the aforementioned pipeline end-to-end.
Component map: Monocular plane recovery -> Plane embedding -> Transformer matching -> Pose estimation -> Pose refinement

Critical path: Input image → depth prediction → plane extraction → plane feature embedding → transformer matching → pose estimation → (optional) pose refinement.

Design tradeoffs:
- Planar maps vs. point clouds: lower memory and simpler matching, but may miss fine details.
- Transformer vs. simpler matchers: higher accuracy at the cost of compute; could be replaced by a lightweight matcher for real-time needs.
- Pose refinement: improves results but adds runtime; number of optimization iterations can be tuned for speed.

Failure signatures:
- Excessive tiny or missing planes → problems in depth estimation or RANSAC thresholds.
- Low matching F1-score → poor embedding learning or inappropriate Mutual Nearest Neighbor threshold.
- High rotation error with many good matches → inaccurate normal estimation or insufficient non-parallel plane pairs.
