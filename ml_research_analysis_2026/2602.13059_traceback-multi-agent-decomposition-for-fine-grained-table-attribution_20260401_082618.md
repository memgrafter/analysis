# TraceBack: Multi-Agent Decomposition for Fine-Grained Table Attribution
## Quick Facts
- arXiv ID: 2602.13059
- Source URL: https://arxiv.org/abs/2602.13059
- Reference count: 31
- Primary result: Achieves cell-level attribution precision 89.81 and recall 78.84 on FetaQA, substantially outperforming baselines (best baseline 56.50 and 46.16).

## Executive Summary
TraceBack tackles the problem of fine-grained, cell-level attribution in table question answering, which is crucial for verifiability and trust. It introduces a modular multi-agent framework that sequentially prunes tables to relevant rows and columns, decomposes questions into semantic sub-questions, and grounds each answer span to specific supporting cells, capturing both explicit and implicit reasoning evidence. The authors also release CITEBench, a benchmark of 1,500 manually annotated examples with phrase-to-cell mappings, and propose FairScore, a reference-less metric that aligns atomic facts from predicted cells and answers. Extensive experiments on ToTTo, FetaQA, and AITQA show TraceBack substantially outperforms strong baselines, achieving cell-level precision of 89.81 and recall of 78.84 on FetaQA. FairScore closely tracks human judgments, enabling scalable evaluation without gold cell labels.

## Method Summary
TraceBack is a modular pipeline of five LLM agents that operate on a single table, question, and answer. First, the Column Relevance Identification agent selects necessary columns (explicit and implicit). Second, the Evidence Span Extractor generates a SQL-like filtering condition to prune irrelevant rows, reducing noise. Third, the Query Decomposition agent breaks the question into semantically coherent sub-questions aligned with intermediate reasoning steps. Fourth, the Sub-Query Attribution agent grounds each sub-question to exact cell coordinates in the pruned table. Finally, the Final Attribution agent consolidates all sub-question cells into a phrase-to-cell mapping aligned with the answer. FairScore is a separate reference-less evaluation metric that converts predicted cells and the answer into atomic facts, then uses an LLM to align them and compute precision/recall.

## Key Results
- On FetaQA, TraceBack achieves 89.81 precision and 78.84 recall, beating the best baseline (56.50, 46.16) by large margins.
- Similar substantial gains on ToTTo and AITQA.
- FairScore correlates strongly with human judgments (83.20 P / 88.34 R agreement) and preserves method rankings, enabling reference-less evaluation.

## Why This Works (Mechanism)
### Mechanism 1
The Query Decomposition agent breaks the original question into semantically coherent sub-questions, each requiring specific table evidence. The Sub-Query Attribution agent then grounds each sub-question to exact cell coordinates, capturing both explicit answer spans and implicit intermediate values (e.g., filter conditions, computed durations). This isolates evidence for each reasoning step. Core assumption: complex table QA answers rely on multi-step evidence chains, not just final answer cells. Evidence: abstract states decomposition and grounding capture explicit and implicit evidence; Section 4.2 notes the goal is to surface implicit dependencies. Break condition: if sub-questions are not faithful to the original answer's reasoning (e.g., missing a filtering step), the final cell set will be incomplete.

### Mechanism 2
The Column Relevance Identification agent selects necessary columns (explicit and implicit). The Evidence Span Extractor generates SQL-like filtering conditions over these columns to extract a minimal relevant row subset. This pruned table is used downstream, preventing LLMs from being distracted by irrelevant data. Core assumption: full tables contain many distractors; precision improves when models operate on a concise, relevant subset without losing essential rows. Evidence: abstract mentions pruning to relevant rows and columns; Section 4.2 details the Evidence Span Extractor and its goal to preserve the complete reasoning chain; Section 5.2 ablation "w/o Table Pruning" shows precision drops on ToTTo/FetaQA and recall drops overall. Break condition: over-aggressive pruning that filters out rows needed for implicit computation (e.g., a row used only for a comparative filter) will cause recall failure.

### Mechanism 3
FairScore compares atomic facts derived from predicted cells and answers to estimate attribution precision and recall without human cell labels. Predicted cells and the answer are each converted into minimal declarative atomic facts. An entailment-based LLM scorer aligns cell-derived facts to answer-derived facts. Precision = matched cell-facts / total cell-facts; Recall = matched answer-facts / total answer-facts. Core assumption: attribution quality can be approximated by measuring how well facts derivable from predicted cells cover the facts in the answer, without explicit cell-to-phrase mapping. Evidence: abstract describes FairScore; Section 6 details the three-stage conversion/comparison pipeline and shows FairScore closely tracks human judgments; Section 6.1 Table 6 shows FairScore underestimates absolute scores but preserves relative ordering; human agreement check yields 83.20 P / 88.34 R. Break condition: if answer decomposition into atomic facts is noisy (e.g., splits a single fact into multiple fragments) or cell-to-fact conversion is lossy (e.g., misses row context), alignment scores will be unreliable.

## Foundational Learning
### Structured Data as Relational Graphs
- **Why needed**: The framework manipulates tables via column/row selection, requiring understanding of headers, data types, and relational constraints (e.g., filtering conditions).
- **Quick check**: Given a table with columns `Start_Time`, `End_Time`, `Event`, how would you compute the duration for a specific event? Which cells are *implicitly* needed versus *explicitly* stated in the answer?

### Multi-Hop Reasoning Decomposition
- **Why needed**: The Query Decomposition agent must identify all sub-steps (filters, aggregations, comparisons) required to derive the answer from the table.
- **Quick check**: For the question "Among renewable sources costing ≤50/MWh and scalability≥3, which is most efficient?", list the minimal sub-questions that map directly to table operations.

### Attribution as Evidence Alignment
- **Why needed**: The core task is mapping answer text to supporting cells, including implicit evidence. This differs from answer correctness; it requires verifying sufficiency and non-contradiction of the cell set.
- **Quick check**: If an answer says "Wind Power, 30–45% efficiency" and the gold cells are `[Wind, 30-45%]` and `[Solar, 30-50]` (cost column), is the attribution sufficient? Why or why not?

## Architecture Onboarding
### Component Map
Input (Table T, Question q, Answer a) → Column Relevance Identification → Evidence Span Extractor → Query Decomposition → Sub-Query Attribution → Final Attribution → (Optional) FairScore

### Critical Path
The sequential pipeline: Column Relevance → Evidence Span → Query Decomposition → Sub-Query Attribution → Final Attribution. Pruning (Agents 1-2) must precede decomposition (Agent 3) as per best-performing variant (Table 5).

### Design Tradeoffs
- LLM dependency: Each agent uses few-shot prompting; performance sensitive to model choice (GPT-4o vs. Qwen2.5-7B in Lite version) and prompt design.
- Sequential vs. joint: Running decomposition before pruning reduces precision; processing one subquery at a time also hurts precision—joint reasoning over all sub-questions in pruned table context is better.
- Granularity: Cell-level is hardest; row/column metrics are easier but less informative for trust.

### Failure Signatures
- Over-pruning: Agent 2's SQL filters exclude rows needed for implicit comparisons → high precision, low recall.
- Under-decomposition: Agent 3 generates too-coarse sub-questions → Agent 4 attributes large cell sets, poor precision.
- Misalignment: Agent 5 fails to merge sub-question cells into answer spans correctly → correct cells but wrong phrase mapping.
- FairScore underestimation: Especially on AITQA; may not distinguish subtle differences in compositional answers.

### First 3 Experiments
1. **Agent 1 validation**: On 50 examples, manually check if selected columns include all implicit columns needed (e.g., `Start_Time`/`End_Time` for "duration"). Expected: >95% inclusion.
2. **Pruning sanity check**: Run Agent 2's SQL on ground-truth relevant rows; measure % of gold rows retained and % of irrelevant rows filtered. Target: >90% gold retention, >70% irrelevant filtering.
3. **Sub-question faithfulness**: Use an NLI model (as in paper) to verify each sub-question's answer is entailed by the original answer. Target: >90% entailment; if lower, decomposition is drifting.

## Open Questions the Paper Calls Out
### Open Question 1
**Question**: How can we design an interpretable and scalable framework for cell-level attribution that traces both final answers and intermediate reasoning steps to specific table cells?  
**Basis in paper**: The introduction explicitly asks this question.  
**Why unresolved**: TraceBack provides a solution for single tables but its scalability to large tables and diverse schemas is not proven; modular design may introduce latency.  
**What evidence would resolve it**: Compare unified vs. modular architectures on tables of increasing size and complexity, reporting attribution accuracy and inference time.

### Open Question 2
**Question**: How can TraceBack be extended to handle multi-table joins, hierarchical schemas, and complex reasoning like aggregation?  
**Basis in paper**: Future Work states: "extending TraceBack to more complex reasoning (e.g., aggregation and multi-hop over multiple tables)" and Limitations note it is "restricted to single-table settings."  
**Why unresolved**: Real-world QA often requires combining multiple tables; TraceBack currently cannot handle joins or hierarchical data.  
**What evidence would resolve it**: Create a multi-table attribution benchmark, design new agents for join inference, and evaluate on it.

### Open Question 3
**Question**: How can FairScore be improved to provide accurate absolute precision estimates and robustly handle compositional or ambiguous answers?  
**Basis in paper**: Limitations: "FAIRSCORE ... tends to underestimate absolute precision, especially for compositional or ambiguous answers."  
**Why unresolved**: Underestimation reduces trust in the metric; current alignment may fail on complex answer structures.  
**What evidence would resolve it**: Use richer semantic matching (e.g., LLM-based entailment), calibrate with human judgments, and test on diverse answer types.

### Open Question 4
**Question**: How well do attribution methods generalize to non-English, domain-specific, and highly heterogeneous table formats?  
**Basis in paper**: Inferred from Limitations: "CITEBENCH currently covers only English Wikipedia-style tables... generalization ... remains untested" and performance is "sensitive to domain shift."  
**Why unresolved**: All evaluations are on English datasets; applicability to other languages and domains is unknown.  
**What evidence would resolve it**: Build multilingual/domain-specific benchmarks (e.g., scientific, financial), evaluate TraceBack and baselines, and analyze cross-domain performance.

## Limitations
- **Reproducibility gaps**: Exact LLM hyperparameters (temperature, top_p) and complete few-shot prompts for each agent are unreported, hindering exact replication.
- **Evaluation details missing**: The NLI model used for sub-question faithfulness (RoBERTa variant) and FairScore's alignment prompts and LLM are not specified.
- **Generalization untested**: Experiments are limited to English Wikipedia-style tables (CITEBench); performance on non-English, domain-specific, or highly heterogeneous tables remains unknown.

## Confidence
- **High**: FairScore human correlation (Sec 6.1).
- **Medium**: Decomposition/pruning mechanisms (ablations confirm benefit).
- **Low**: Generalizability beyond English Wikipedia-style tables.

## Next Checks
1. Pruning recall safety: Run Evidence Span Extractor on queries requiring implicit comparative rows (e.g., “highest efficiency among X”) and measure gold-row retention vs. baseline.
2. Sub-question faithfulness: Replicate the NLI check using three different pretrained models (e.g., RoBERTa-large, DeBERTa) on 100 CITEBench examples; report variance in entailment scores.
3. FairScore calibration: Apply FairScore to 50 non-English tables (e.g., multilingual WikiTables) with human annotators to test whether reference-less scores still preserve ranking order.
