# Parameter Efficient Fine Tuning Llama 3.1 for Answering Arabic Legal Questions: A Case Study on Jordanian Laws
## Quick Facts
* **arXiv ID:** 2601.17364  
* **Source URL:** https://arxiv.org/abs/2601.17364  
* **Reference Count:** 11  
* **Primary Result:** LoRA fine-tuning of 4-bit quantized Llama-3.1-8B on a custom dataset of 6,000 Jordanian legal QA pairs yields significant gains (BLEU 0.290, ROUGE-L 0.081), with the non-instruct base model slightly outperforming the instruct variant.

## Executive Summary
This study tackles Arabic legal question-answering by fine-tuning Llama-3.1-8B on Jordanian law. The authors create a custom dataset of 6,000 QA pairs from 18 laws using GPT-3.5 Turbo, then apply parameter-efficient fine-tuning (LoRA) with 4-bit quantization to adapt the model on a single GPU. Fine-tuning substantially improves performance over the base models on BLEU and ROUGE-L metrics, demonstrating that resource-efficient adaptation is viable for this low-resource, high-specialization domain. Notably, the plain base model marginally surpasses the instruct-tuned variant after adaptation.

## Method Summary
A custom dataset of approximately 6,000 (Question, Answer, Context) triples was automatically generated from 3,578 articles across 18 Jordanian laws using GPT-3.5 Turbo. The data was split 80/20 into train and test sets. Two 8-billion parameter Llama 3.1 models were used: the base and instruct variants, both loaded in 4-bit precision (`bnb-4bit`). Parameter-efficient fine-tuning (PEFT) with LoRA adapters (rank `r=16`, `alpha=16`, dropout 0) was applied, targeting key projection layers. Training used the Unsloth framework for 1 epoch with a learning rate of 2e-4, batch size 2, and gradient accumulation on an NVIDIA A100 GPU. Performance was evaluated via BLEU and ROUGE-L scores against the test set references.

## Key Results
* Parameter-efficient fine-tuning with LoRA and 4-bit quantization enabled successful adaptation of an 8B model to Arabic legal QA on consumer-grade hardware.
* Both fine-tuned models significantly outperformed their respective base models, with the best model achieving BLEU 0.290 and ROUGE-L 0.081.
* The fine-tuned plain Llama-3.1 base model slightly exceeded the fine-tuned instruct variant on these lexical overlap metrics.

## Why This Works (Mechanism)
### Mechanism 1
* **Claim:** LoRA adapters improved task-specific performance while minimizing compute/memory overhead.
* **Mechanism:** LoRA freezes pre-trained weights and injects trainable low-rank matrices into attention layers, allowing the model to learn narrow, task-specific updates for Arabic legal QA without modifying all 8B parameters.
* **Core assumption:** The base model already possesses sufficient Arabic and reasoning capability; adaptation requires only a small "update path."
* **Evidence anchors:** [abstract] mentions PEFT with LoRA and 4-bit for resource efficiency; [section III.C] details LoRA config (r=16, alpha=16).
* **Break condition:** If the base model lacks foundational Arabic legal understanding, LoRA's low-rank updates may be insufficient.

### Mechanism 2
* **Claim:** 4-bit quantization was necessary to fit the 8B model and its training states within a 40GB GPU.
* **Mechanism:** Quantization reduces weight precision from 16/32-bit to 4-bit integers, drastically cutting VRAM requirements and enabling training that would otherwise be impossible.
* **Core assumption:** The information loss from 4-bit is tolerable for this fine-tuning task; the framework correctly handles quantized operations.
* **Evidence anchors:** [abstract] specifies `bnb-4bit` models; [section III.C] states 4-bit reduces memory and speeds training.
* **Break condition:** If the task demands fine-grained semantic precision, quantization noise could offset fine-tuning gains.

### Mechanism 3
* **Claim:** The custom dataset of 6,000 Jordanian legal QA pairs was the primary driver of improved performance.
* **Mechanism:** The dataset provided targeted supervision on language patterns, procedures, and doctrines specific to Jordanian law, steering the model's output distribution.
* **Core assumption:** The GPT-3.5 Turbo-generated triples are sufficiently accurate and diverse to represent the true distribution of Arabic legal questions.
* **Evidence anchors:** [abstract] describes the 6,000 QA dataset; [section III.B] details GPT-3.5 Turbo generation from law articles.
* **Break condition:** High noise in the generated data or lack of coverage for key concepts would limit learning regardless of PEFT/quantization.

## Architecture Onboarding
**Component map:**  
Data Source (18 Jordanian laws) -> Parser/Extractor (3,578 articles) -> QA Generator (GPT-3.5 Turbo) -> Dataset Split (80/20) -> Base Model Loader (4-bit Llama-3.1) -> PEFT Wrapper (LoRA config) -> Training Loop (Unsloth, LR=2e-4, batch=2) -> Evaluation (BLEU, ROUGE-L)

**Critical path:** Clean law articles → High-quality QA triples → Correct 4-bit+LoRA model setup → Valid metric calculation. Brittle points: dataset quality and model integration.

**Design tradeoffs:**  
* Speed vs. Cost vs. Quality: 1 epoch chosen for speed; more could improve accuracy but risk overfitting on small data.
* Quantization vs. Fidelity: 4-bit enabled training but may degrade fine-grained legal distinction learning.
* Base Model Choice: Plain base's "blank slate" was more malleable than instruct model's pre-existing style.

**Failure signatures:**  
1. VRAM OOM despite 4-bit (e.g., incorrect gradient accumulation or long sequences).
2. Zero BLEU/ROUGE improvement (LoRA not applied, data not loaded, training failure).
3. Verbose/generic outputs (dataset failed to teach conciseness, rank too low).
4. High Arabic UNK rate (tokenizer struggles with legal jargon).

**First 3 experiments:**  
1. Sanity Check - Loss Curve: Run 10 training steps; confirm loss decreases. If not, check data loading and LoRA.
2. Ablation - Dataset Size: Train on 10% data (600 samples); expect significantly lower scores to quantify scale dependence.
3. Baseline - No-LoRA: Attempt full fine-tuning on a tiny subset (100 samples) if memory allows; compare delta to assess LoRA's contribution.

## Open Questions the Paper Calls Out
### Open Question 1
How do fine-tuned Arabic legal models perform in a full RAG pipeline with unstructured legal documents (e.g., court rulings, memos) compared to curated law articles? *Basis:* Future Work states the next step is testing within a complete RAG environment with noisy, unstructured content.

### Open Question 2
Does expanding the training dataset to include multiple Arabic dialects and legal systems from different countries improve model generalization beyond Jordanian law? *Basis:* Future Work proposes expanding to diverse Arabic dialects and legal systems to improve cross-regional adaptability.

### Open Question 3
Why does the base (non-instruct) Llama-3.1 model slightly outperform the instruct variant after fine-tuning on Arabic legal QA, contrary to expectations? *Basis:* Results note this but provide no empirical analysis; authors speculate about prior instruction-tuning biases.

### Open Question 4
Are automatic metrics like BLEU and ROUGE sufficient to evaluate legal QA accuracy, or do they fail to capture critical legal reasoning aspects? *Basis:* Authors state human evaluation is crucial, implying limitations of n-gram overlap for domain tasks.

## Limitations
* **Dataset generation black box:** The exact GPT-3.5 prompt, parameters, and post-filtering are unspecified, creating uncertainty about the factual accuracy and diversity of the 6,000 QA pairs.
* **Metric-goal misalignment:** BLEU and ROUGE-L measure lexical overlap, not legal correctness, reasoning soundness, or citation accuracy—critical for legal QA.
* **Unexpected model comparison:** The base model's slight outperformance of the instruct variant is observed but not explained, leaving the mechanism ambiguous.

## Confidence
* **"PEFT/LoRA enabled efficient fine-tuning"**: High Confidence. Methodology standard, hardware specs given, strong neighbor corpus support.
* **"The custom dataset drove performance gains"**: Medium Confidence. Dataset creation described, but quality is unknown; gains could also stem from base model adaptation.
* **"Fine-tuned models significantly improved over base"**: Medium Confidence. Reported deltas provided, but no statistical tests and metrics are weak proxies for legal accuracy.
* **"Base model outperformed Instruct variant"**: Low Confidence. Result presented without ablation or analysis; could be a fluke, prompt quirk, or true signal.

## Next Checks
1. **Dataset Audit:** Manually verify a stratified sample (e.g., 50 QA triples) against source law articles to calculate hallucination/error rate. This tests the core assumption of dataset quality.
2. **Ablation on Training Dynamics:** Re-run fine-tuning with more epochs (3-5) and larger train split (90%). Monitor validation loss and metrics to diagnose if 1 epoch caused underfitting and if gains scale.
3. **Supplemental Factuality Evaluation:** Conduct human evaluation or use a robust LLM-as-judge prompt where legal experts (or a model like GPT-4) score outputs for correctness, completeness, and reasoning on 100 test questions. Correlate with automatic metrics.
