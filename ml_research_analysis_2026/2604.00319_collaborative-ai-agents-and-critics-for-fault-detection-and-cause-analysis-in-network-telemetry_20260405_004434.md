# Collaborative AI Agents and Critics for Fault Detection and Cause Analysis in Network Telemetry

## Quick Facts
- **arXiv ID:** 2604.00319
- **Source URL:** https://arxiv.org/abs/2604.00319
- **Reference count:** 22
- **Primary result:** A federated multi-agent system with separate critics minimizes network telemetry fault analysis cost via multi-time scale stochastic updates, achieving near-optimal centralized performance (cost ratio ~1) with O(m) communication overhead, where XGBoost agents excel at detection and LLM agents provide richer severity analysis.

## Executive Summary
This paper tackles fault detection and cause analysis in network telemetry—a critical task for maintaining network reliability—by proposing a federated multi-agent system. In this system, AI agents (employing either classical machine learning like XGBoost or generative LLMs) handle multimodal tasks such as identifying faults, while separate AI critics evaluate the agents' responses and provide feedback. A central server coordinates updates to minimize the overall system cost without requiring agents or critics to share their local cost functions or communicate directly. The convergence of the time-average active states to optimal values is guaranteed through multi-time scale stochastic approximation. Evaluated on a real network telemetry dataset, XGBoost-based agents outperformed LLM-based ones for fault detection (accuracy 0.9644, F1-score 0.9656), whereas LLMs like Llama3.2 flagged a higher proportion of critical faults for severity analysis. The system's total cost ratio relative to a centralized convex optimum converges to approximately 1, demonstrating near-optimal distributed operation.

## Method Summary
The approach implements a federated multi-agent framework where each modality (e.g., detection, severity) has a set of AI agents and dedicated critics. Agents process input data (network telemetry CSV and logs) to produce predictions (fault yes/no, severity, cause). Critics score these predictions against criteria like accuracy and relevance. A central server aggregates feedback and broadcasts signal vectors Θj(k) and Θc j(k) to agents and critics per modality j. Using multi-time scale stochastic iteration—with step sizes η0j/(1+αj k) for agents and βj k for critics—agents and critics update their active states (selection probabilities) based on these signals (Algorithm 2 & 3). This ensures the time-averages of active states minimize the global cost without direct agent-critic communication. For evaluation, XGBoost agents are trained on a preprocessed balanced dataset (2/3 train, 1/3 test). LLM agents use Ollama with models like Llama3.2, integrated via Langchain and a RAG pipeline (ChromaDB with mxbai-embed-large) to retrieve relevant log snippets for context. The system's performance is assessed via detection metrics (accuracy, F1) and severity classification, with convergence measured against a centralized CVX benchmark.

## Key Results
- XGBoost agents achieve superior fault detection performance (accuracy 0.9644, F1-score 0.9656) compared to LLM-based agents.
- LLM agents (e.g., Llama3.2) flag a higher proportion of critical faults for severity analysis than other LLMs like Granite.
- The system's total cost ratio to the centralized CVX optimum converges to near 1, validating the multi-time scale stochastic approximation approach.

## Why This Works (Mechanism)
The mechanism relies on two key elements: (1) **Decoupled multi-time scale updates**—agents and critics operate on distinct step-size schedules (agents with αj ∈ (0.5,1), critics with βj ∈ (0,0.5)), creating a separation of time scales that stabilizes the iterative process and drives time-averages to the optimal solution of the constrained cost minimization problem; (2) **Critic-mediated feedback**—critics evaluate agent outputs against multi-dimensional criteria (accuracy, relevance, etc.) and generate scalar scores that inform the central server's signal updates, which in turn guide agents' probabilistic action selection without exposing local cost functions. This structure allows the system to navigate the trade-off between exploration and exploitation while maintaining federated privacy. The O(m) communication overhead arises because the central server broadcasts only one signal vector per modality m (e.g., detection, severity), independent of the number of agents or critics.

## Architecture Onboarding
**Component Map:**  
Network Telemetry Data → AI Agents (XGBoost/LLM) → Predictions → Critics → Scores → Central Server → Feedback Signals (Θj, Θc j) → AI Agents & Critics (update active states)  

**Critical Path:** Data ingestion → Agent prediction (fault detection/severity) → Critic evaluation → Server signal broadcast → Agent/critic state update → Iteration until convergence. The path is cyclical, with the server as the sole communication hub.

**Design Tradeoffs:**  
- *Centralized vs. Distributed Coordination*: A central server simplifies consensus but introduces a single point of failure/bandwidth bottleneck; the O(m) overhead mitigates scalability limits.  
- *Classical ML vs. LLM Agents*: XGBoost offers deterministic, fast, high-accuracy detection on tabular data but lacks explainability for cause analysis; LLMs provide natural language reasoning for severity/cause but suffer from non-determinism and higher computational cost.  
- *RAG Context Scope*: Larger retrieval sets improve context but increase latency and risk noise; the paper uses k=3 neighbors as a tradeoff.

**Failure Signatures:**  
- Non-convergence of time-average active states (x̄ji, ȳjν) → step-size parameters misconfigured or critic scores uninformative.  
- High communication volume → redundant broadcasts or large signal vectors (but theory predicts O(m)).  
- LLM agent inconsistency → prompt sensitivity, temperature settings, or irrelevant RAG retrievals causing varying severity classifications.

**First Three Experiments:**  
1. Reproduce convergence: Run the multi-time scale algorithm with given parameters (η0j=0.034, αj=0.14, βj=0.51) on preprocessed data; plot cost ratio vs. iteration and verify it approaches 1.  
2. Validate XGBoost detection: Train XGBClassifier on the same 2/3 train split; compute accuracy/F1 on test set; expect ~0.965 ± 0.01.  
3. Test LLM severity with RAG: For all fault-positive samples, query Llama3.2 via the provided prompt (Query 5.1) with ChromaDB context; measure critical fault percentage and compare to reported 25.8%.

## Open Questions the Paper Calls Out
1. **Real-time deployment viability**: How does the system perform on live network streams with concept drift and latency constraints? (Conclusion, Section 6)  
2. **Root of XGBoost vs. LLM performance gap**: Why does classical ML outperform LLMs on fault detection despite LLMs' general reasoning strengths? (Section 5.2 & 5.3.1)  
3. **Finite-time convergence guarantees**: Do the multi-time scale algorithms provide bounds on convergence speed or transient performance, or only asymptotic almost-sure convergence? (Abstract, Section 4)  
4. **Scalability under realistic network conditions**: Does the O(m) communication overhead hold with contention, packet loss, and serialization delays as agent/critic numbers grow? (Remark 4.9)  
5. **LLM bias vs. RAG quality**: Are severity/cause analysis differences across LLMs due to model biases or the retrieved context's relevance? (Inferred from Fig 10, 11)

## Limitations
- **Parameter and seed opacity**: Exact random seeds and cost function coefficients (ai, bi, ci, di, a′ν) are undisclosed, hindering exact replication of convergence plots and cost ratios.  
- **Critic scoring underspecification**: Weights and thresholds for critic score aggregation (e.g., "if score below threshold" in Algorithm 2) are not detailed, affecting feedback signal behavior.  
- **Dataset accessibility**: Dataset 4 from [15] may not be publicly available; preprocessing steps (label balancing, column filtering) must be reverse-engineered to ensure identical input distribution.  
- **LLM non-determinism**: Output variance due to temperature, sampling, and prompt sensitivity can impact severity classification reproducibility unless strict controls are applied.

## Confidence
- **Theoretical guarantees (convergence, O(m) overhead)**: High – proofs are provided and algorithm well-specified.  
- **Fault detection accuracy (XGBoost ~0.965)**: Medium – depends on data split; seeds not given but procedure is clear; expected variance ±0.01.  
- **LLM severity analysis (critical flag rates)**: Medium – evaluation relies on LLM outputs; prompt and RAG details partially missing; non-determinism risk.  
- **Cost ratio convergence to CVX optimum**: Medium – empirical results may vary with random coefficients and step-size tuning; theoretical asymptotic guarantee is solid.
