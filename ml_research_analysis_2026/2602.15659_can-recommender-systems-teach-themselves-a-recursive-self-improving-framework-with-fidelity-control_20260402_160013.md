# Can Recommender Systems Teach Themselves? A Recursive Self-Improving Framework with Fidelity Control
## Quick Facts
- **arXiv ID**: 2602.15659
- **Source URL**: https://arxiv.org/abs/2602.15659
- **Reference count**: 40
- **Primary result**: Recursive self-improvement with fidelity-controlled synthetic data yields up to +13.92% Recall@10 gain after three iterations.

## Executive Summary
Extreme data sparsity in recommender systems limits model scalability and performance. The authors propose a Recursive Self-Improving Recommender (RSIR) framework that enables a model to generate its own training data. Starting from a real-data-trained model, RSIR iteratively generates synthetic user interaction sequences using the current model, filters them via a fidelity mechanism to ensure consistency with the user preference manifold, and then trains a successor on the combined real and filtered synthetic data. This closed-loop process densifies the training distribution without external resources. Theoretically, RSIR acts as a data-driven implicit regularizer, smoothing the optimization landscape toward flatter minima. Empirically, across four e-commerce datasets (Amazon Toys, Beauty, Sport, and Yelp) and three sequential recommender backbones (SASRec, CL4SRec, HSTU), a single iteration yields Recall@10 improvements of 3–8% over the best baselines. Gains compound over multiple iterations; for example, HSTU on Sports achieves a +13.92% Recall@10 gain after three iterations. Moreover, weaker models can generate effective curricula for stronger ones, and RSIR remains computationally efficient.

## Method Summary
The paper does not provide explicit reproduction notes. However, the core method of RSIR can be summarized as follows:

RSIR implements a closed-loop, recursive training procedure. Given an initial model trained on real data, each iteration consists of: (1) generating synthetic user interaction sequences using the current model (e.g., via autoregressive decoding); (2) applying a fidelity filter that scores each synthetic sequence for consistency with the user preference manifold (e.g., likelihood under a held-out model or distance to real data clusters) and retaining only high-fidelity samples; (3) merging the filtered synthetic data with the original training set; and (4) training a new successor model from scratch on this augmented dataset. The successor then becomes the current model for the next iteration. The fidelity control is essential to prevent distribution shift and ensure that synthetic data reflects genuine user preferences. Theoretically, the iterative augmentation is viewed as an implicit regularizer that smoothens the loss landscape, encouraging convergence to flatter minima and better generalization. The framework is architecture-agnostic and has been instantiated with SASRec, CL4SRec, and HSTU.

## Key Results
- Single‑iteration RSIR improves Recall@10 by 3–8% over the best baselines on Amazon Toys/Beauty/Sport and Yelp datasets with SASRec, CL4SRec, and HSTU backbones.
- Gains compound over multiple iterations; e.g., HSTU on Sports achieves +13.92% Recall@10 after three iterations.
- Weaker models can generate synthetic data that effectively improves stronger models, and RSIR maintains efficiency comparable to standard training.

## Why This Works (Mechanism)
- The fidelity filter guarantees that synthetic sequences stay on the true user preference manifold, preventing the introduction of out-of-distribution or misleading samples.
- Recursively augmenting the training set with high‑fidelity synthetic data densifies the sparse interaction data, providing richer gradient signals and more robust parameter updates.
- The iterative process implicitly regularizes the model: the data distribution gradually shifts toward regions that satisfy both real data reconstruction and plausible generation, smoothing the loss landscape and promoting flatter minima that generalize better.

## Foundational Learning
- **Data Sparsity**  
  *Why needed*: Real user‑item interactions are extremely sparse, leading to overfitting and limited model capacity.  
  *Quick check*: Compute sparsity ratio (#interactions)/(#users × #items); if <1%, sparsity is a critical issue.

- **Synthetic Data Generation**  
  *Why needed*: To augment scarce real interactions without collecting additional user data.  
  *Quick check*: Implement a basic generator using your model’s prediction head; sample sequences and verify diversity (e.g., item coverage >60%).

- **Fidelity Filtering**  
  *Why needed*: To ensure synthetic sequences reflect genuine preferences and avoid distribution drift.  
  *Quick check*: Define a fidelity score (e.g., likelihood under a held‑out model) and set a threshold that retains ~70–80% of samples; monitor downstream performance.

- **Implicit Regularization**  
  *Why needed*: RSIR’s recursion is hypothesized to smooth the optimization landscape, improving generalization.  
  *Quick check*: After training, measure loss sharpness (e.g., via loss perturbation); flatter landscapes should correlate with higher validation scores.

- **Recursive Self‑Improvement**  
  *Why needed*: Bootstraps model performance using its own generated data, enabling continuous improvement without external supervision.  
  *Quick check*: Run ≥2 iterations on a small dataset and track validation metrics; expect monotonic improvement if fidelity is well‑controlled.

## Architecture Onboarding
- **Component Map**:  
  `Current Model -> Synthetic Sequence Generator -> Fidelity Filter -> Augmented Dataset -> Successor Model Training -> New Current Model` (loop)

- **Critical Path** (one iteration):  
  1. Generate synthetic sequences with the current model.  
  2. Filter synthetic sequences via fidelity criteria.  
  3. Merge filtered synthetic data with the original training set.  
  4. Train a successor model on the merged dataset.  
  5. Replace the current model with the successor and repeat.

- **Design Tradeoffs**:  
  - *Fidelity vs. Diversity*: Higher thresholds yield safe but potentially low‑diversity data; lower thresholds increase diversity but risk noise.  
  - *Computational Cost*: Generation and filtering add overhead; multiple iterations multiply cost, requiring a balance between gain and resources.  
  - *Model Capacity*: Stronger backbones produce higher‑quality synthetic data but are more expensive; weaker models may still generate useful curricula for stronger ones with careful tuning.

- **Failure Signatures**:  
  - Degrading validation performance after one or more iterations (bias amplification or data drift).  
  - Synthetic data diversity collapse (e.g., repetitive sequences, low item coverage).  
  - Consistently low fidelity scores or overly permissive thresholds leading to noisy training and unstable losses.

- **First Three Experiments**:  
  1. *Baseline Comparison*: Train a baseline model without RSIR and compare to a single‑iteration RSIR on the same backbone and dataset; evaluate Recall@10 and NDCG.  
  2. *Fidelity Threshold Sensitivity*: Vary the fidelity threshold (e.g., quantiles) and measure performance and diversity (item coverage, pairwise similarity) to locate a robust operating point.  
  3. *Multi‑Iteration Scaling*: Run RSIR for 1, 2, and 3 iterations on a small dataset (e.g., Amazon Toys) to observe whether gains compound or saturate; track training time and memory usage.

## Limitations
- Synthetic data bias and collapse risk due to recursive generation without explicit diversity‑ensuring mechanisms.
- Theoretical foundation gap: the claim that RSIR induces an implicit regularizer toward flatter minima lacks formal proof and empirical validation (e.g., Hessian‑based flatness metrics).
- Evaluation scope is limited to three e‑commerce sequential datasets and three specific backbones; generalizability to other domains (video/music), interactive settings, or modern LLM‑based recommenders remains unknown, and scalability to larger models/datasets is unverified.

## Confidence
- **High confidence**: The empirical gains (Recall@10 improvements of 3–13.92%) are robust across tested datasets and backbones, backed by clear numerical results and strong baselines.
- **Medium confidence**: The assertion that weaker models can generate effective curricula for stronger ones is supported by cross‑backbone experiments but within a narrow family of sequential recommenders.
- **Low confidence**: The theoretical interpretation of RSIR as an implicit regularizer promoting flatter minima remains speculative; no formal proof or direct empirical evidence (e.g., flatness measurements) is provided.

## Next Checks
1. **Cross‑domain & architecture test**: Apply RSIR to at least two non‑e‑commerce sequential recommendation datasets (e.g., MovieLens sequences, Twitch viewing logs) with a modern LLM‑based sequential recommender backbone (e.g., RecBole’s BERT4Rec variant) to probe generalizability.
2. **Synthetic data diversity & bias audit**: Quantify diversity of generated sequences using metrics like average pairwise similarity (embedding‑based) and coverage of item/long‑tail distribution; correlate fidelity filter thresholds with bias amplification across iterations.
3. **Fidelity filter ablation & theoretical validation**: Compare RSIR against a variant that adds synthetic data without filtering; measure optimization landscape flatness (e.g., via loss perturbation sharpness) and generalization gap across iterations to test the implicit regularization hypothesis.
