# TabDLM: Free-Form Tabular Data Generation via Joint Numerical-Language Diffusion

## Quick Facts
- **arXiv ID**: 2602.22586
- **Source URL**: https://arxiv.org/abs/2602.22586
- **Reference count**: 35
- **Primary result**: Unifies continuous and masked diffusion in a single MDLM to generate high-fidelity heterogeneous tabular data, substantially outperforming diffusion and LLM baselines on free-form text and numerical alignment.

## Executive Summary
TabDLM addresses the challenge of generating realistic tabular data that mixes continuous numerical values with free-form text. Existing methods struggle: diffusion models often degrade text quality, while LLMs sacrifice numerical precision. TabDLM solves this by combining continuous diffusion for numbers and masked diffusion for text within one Masked Diffusion Language Model (MDLM) backbone. It represents numbers as single, trainable token embeddings, enabling joint bidirectional denoising. The approach achieves state-of-the-art results on multiple benchmarks, showing significant reductions in shape and trend errors and high downstream utility, demonstrating effective cross-modality modeling.

## Method Summary
TabDLM employs a single MDLM (LLaDA-8B) to jointly denoise both numerical and textual features. Numerical values are normalized and encoded into fixed-dimensional embeddings via a pretrained MLP encoder and a trainable linear projector, treating each number as one token. Text columns are tokenized normally. During training, a shared noise level *t* corrupts the input sequence: Gaussian noise is added to numerical embeddings, and text tokens are independently masked. The MDLM, trained with LoRA adapters, predicts both the original text tokens (via a frozen LM head) and denoised numerical embeddings (via learnable projectors and a frozen MLP decoder). A weighted loss combines text cross-entropy and numerical MSE. Sampling starts from pure Gaussian noise for numbers and all-mask for text, iteratively denoising both modalities synchronously until final decoding.

## Key Results
- On the Amazon dataset, TabDLM reduces Shape error by 39.8% and Trend error by 85.6% compared to the strongest baseline.
- Achieves near-real-data downstream utility as measured by Machine Learning Efficiency (MLE) on standard tabular datasets.
- Substantially outperforms both diffusion-based (e.g., TabDiff) and LLM-based baselines on benchmarks requiring coherent numerical-text alignment (MathExpr, ProfileBio).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: TabDLM achieves joint modeling of numerical and text features by integrating continuous diffusion and masked diffusion within a single Masked Diffusion Language Model (MDLM) backbone, enabling bidirectional cross-modality denoising.
- **Mechanism**: The MDLM processes a concatenated sequence of a schema prompt, categorical/text token sequences, and numerical token embeddings. Numerical values are encoded as single tokens via a trainable encoder, while text features use standard tokenization. During training, the same noise level *t* is applied to both modalities: numerical values are corrupted with Gaussian noise (continuous diffusion), and text tokens are independently masked (discrete diffusion). The bidirectional attention in MDLM captures dependencies across all tokens, including between numerical and textual embeddings.
- **Core assumption**: A unified diffusion process with shared noise scheduling can effectively learn joint distributions over heterogeneous data types without sacrificing modality-specific fidelity.
- **Evidence anchors**:
  - [abstract]: "TabDLM unifies continuous diffusion for numerical values with masked diffusion for text within a single masked diffusion language model (MDLM) backbone."
  - [section 2.2]: Details the architecture, including the concatenation of numerical embeddings and text tokens into the MDLM input sequence.
  - [corpus]: Neighboring papers like TabDiff (FMR 0.617) address mixed-type tabular diffusion but not free-form text; TabDLM extends diffusion to heterogeneous tabular data with text, as indicated by the corpus focus on structured data only.
- **Break condition**: If the MDLM's bidirectional attention fails to align numerical and textual semantics (e.g., generated text contradicts numerical values), the joint denoising assumption breaks, leading to inconsistent cross-modality outputs.

### Mechanism 2
- **Claim**: Trainable numeric token embeddings represent continuous numbers as discrete tokens, preserving numerical precision while integrating seamlessly into the MDLM's token-based diffusion process.
- **Mechanism**: A pretrained MLP encoder first normalizes numerical values (via quantile transformation) and maps them to *r*-dimensional embeddings. A learnable linear projector then transforms these to *d*-dimensional embeddings matching the MDLM's hidden size. During decoding, a symmetric projector and pretrained MLP decoder reconstruct the original number. These embeddings are treated as single tokens in the MDLM sequence.
- **Core assumption**: Continuous numerical distributions can be accurately approximated by fixed-size token embeddings with sufficient model capacity, avoiding fragmentation issues in standard LLM tokenization.
- **Evidence anchors**:
  - [section 2.2]: Explicitly describes the "Number encoder module" with ENC and PROJ<sup>e</sup>, and the symmetric decoder with PROJ<sup>d</sup> and DEC.
  - [abstract]: Highlights "trainable numeric token embeddings" as enabling joint bidirectional denoising.
  - [corpus]: Corpus evidence is weak; no neighboring paper directly uses token-based numerical embeddings in diffusion for tabular data—most (e.g., TabSyn, TabDDPM) use continuous latent spaces or separate discrete bins.
- **Break condition**: If the projection layers (PROJ<sup>e</sup>, PROJ<sup>d</sup>) or fixed encoder/decoder lack capacity, numerical reconstruction error increases (e.g., in L<sub>num</sub> loss), causing precision loss in generated values.

### Mechanism 3
- **Claim**: A shared noise schedule *t* for both modalities synchronizes denoising dynamics, promoting the learning of cross-column dependencies through the MDLM's unified generative process.
- **Mechanism**: During training, a single *t* ∈ [0,1] is sampled per batch. Numerical features are corrupted by adding Gaussian noise with variance σ*(t)* (continuous diffusion), while text tokens are masked with probability 1−ᾱ*(t)* (masked diffusion). The MDLM is trained to denoise both simultaneously, using a weighted loss L = L<sub>text</sub> + λ(*s*)L<sub>num</sub>. This forces the model to handle correlated corruption across modalities.
- **Core assumption**: Aligning noise levels across numerical and textual features allows the model to capture mutual dependencies more directly than separate or autoregressive processes.
- **Evidence anchors**:
  - [section 2.3]: "In TABDLM, we use a single *t* for both continuous diffusion and discrete masked diffusion."
  - [abstract]: Mentions "joint bidirectional denoising" implying synchronized processes.
  - [corpus]: TabDiff (FMR 0.617) uses per-feature noise schedules for mixed-type data, suggesting alternative designs; TabDLM's shared schedule is simpler but noted as potentially suboptimal in limitations.
- **Break condition**: If numerical and textual features require disparate noise schedules for optimal modeling (e.g., different convergence rates), the shared *t* may cause unstable training or poor modality alignment, as hinted in the limitations section.

## Foundational Learning
- **Concept**: Diffusion Models (Score-based or SDE formulations)
  - **Why needed here**: TabDLM builds on continuous diffusion (for numbers) and masked diffusion (for text), requiring understanding of forward noising processes, reverse denoising, and noise schedules like VE-SDE.
  - **Quick check**: "How does the variance schedule σ(*t*) in continuous diffusion affect the distribution of noisy samples?"
- **Concept**: Masked Language Models (BERT-style bidirectional transformers)
  - **Why needed here**: The MDLM backbone relies on bidirectional attention to denoise masked tokens, which is core to text generation and cross-modality context.
  - **Quick check**: "Why might bidirectional attention be better than autoregressive generation for modeling tabular column dependencies?"
- **Concept**: Tokenization and Embedding for Heterogeneous Data
  - **Why needed here**: TabDLM must handle numerical values (continuous) and text (discrete tokens) in a shared embedding space, using numeric token embeddings and standard text tokenization.
  - **Quick check**: "What are the trade-offs between representing numbers as subword tokens versus learned continuous embeddings?"

## Architecture Onboarding
- **Component map**: Schema prompt -> Text tokenization + Numerical encoder (ENC + PROJ<sup>e</sup>) -> Concatenated embeddings -> MDLM backbone (LLaDA-8B + LoRA) -> Text LM head (frozen) + Numerical decoder (PROJ<sup>d</sup> + DEC)
- **Critical path**:
  - **Training**: Input tabular record → normalize numbers, tokenize text → encode numbers to embeddings via ENC and PROJ<sup>e</sup> → concatenate with schema prompt and text tokens → sample shared *t* → add Gaussian noise to numerical embeddings, mask text tokens → feed to MDLM → decode outputs: text tokens via LM head, numerical embeddings via PROJ<sup>d</sup> and DEC → compute L<sub>text</sub> (cross-entropy) and L<sub>num</sub> (MSE) → backpropagate weighted loss L = L<sub>text</sub> + λ(*s*)L<sub>num</sub>.
  - **Sampling**: Start from Gaussian noise for numerical embeddings and all-mask for text tokens → for each step *t*: inject current numerical embeddings, run MDLM to predict masked text tokens and denoised numerical embeddings → update both modalities → after *T* steps, decode final text tokens and numerical values.
- **Design tradeoffs**:
  - Fixed pretrained encoder/decoder vs. end-to-end: Freezing reduces training cost but may limit numerical fidelity; projectors are tunable to adapt to MDLM space.
  - Shared noise schedule vs. modality-specific: Simpler implementation but may not optimize for differing data dynamics; per-feature schedules (as in TabDiff) could improve numerical modeling.
  - Large MDLM (8B parameters) vs. efficiency: Boosts text quality and cross-modality learning but slows sampling; LoRA mitigates memory but not inference speed.
- **Failure signatures**:
  - Numerical drift: Decoded numbers deviate from true distributions (high L<sub>num</sub>), indicating projector or decoder insufficiency.
  - Text incoherence: Generated text ignores numerical/categorical context (low match rates in MathExpr/ProfileBio), suggesting poor cross-attention or noise schedule mismatch.
  - Slow convergence: High validation loss, possibly due to λ(*s*) warm-up imbalance or frozen components misaligned with MDLM.
- **First 3 experiments**:
  1. MathExpr dataset: Evaluate Operation Match Rate and Expression Match Rate to test if generated LaTeX aligns with numerical values and operators.
  2. ProfileBio dataset: Measure Biography Match Rate to assess consistency between structured attributes and free-form text.
  3. Amazon dataset: Compute Shape/Trend errors and Machine Learning Efficiency (MLE) to gauge distribution fidelity and downstream utility with real free-text tabular data.

## Open Questions the Paper Calls Out
- **Question**: Can TabDLM's sampling efficiency be improved via techniques like block diffusion or KV caching without compromising generation fidelity?
  - **Basis**: The limitations section states TabDLM's sampling is slower than task-specific methods due to its large MDLM backbone.
  - **Why unresolved**: The paper proposes these acceleration methods as future work but provides no empirical evaluation of their impact on TabDLM's joint numerical-language generation.
  - **Evidence**: Implement block diffusion and KV caching in TabDLM, then measure trade-offs between sampling speed and distribution fidelity on heterogeneous tabular benchmarks.
- **Question**: Would modality-specific noise schedules improve TabDLM’s joint denoising performance compared to the current shared noise schedule?
  - **Basis**: The limitations note that coupling numerical and text denoising with a single time step may be suboptimal.
  - **Why unresolved**: TabDLM uses a unified noise schedule by design; no ablation compares it against separate schedules for continuous and discrete diffusion.
  - **Evidence**: Train TabDLM variants with independent noise schedules for numerical and text/categorical features, then evaluate Shape/Trend errors and downstream utility to determine if decoupling denoising dynamics yields better cross-modality alignment.
- **Question**: To what extent does TabDLM rely on partial training (frozen encoder/decoder/MDLM + LoRA) versus full fine-tuning for its performance?
  - **Basis**: The implementation freezes most pretrained components and only trains projections and LoRA modules, assuming this is sufficient for multimodal adaptation.
  - **Why unresolved**: The paper never compares partial training to full fine-tuning of the entire MDLM backbone and numerical encoder/decoder.
  - **Evidence**: Run controlled experiments with full fine-tuning of TabDLM (unfreezing all parameters) versus the current partial training setup, measuring changes in generation fidelity, sampling stability, and risk of catastrophic forgetting in the pretrained language modeling capabilities.

## Limitations
- Shared noise schedule may be suboptimal (paper acknowledges); could misalign modalities.
- Fixed numeric encoder/decoder may limit precision; projector capacity untested.
- Cross-modality semantic alignment via attention is assumed but not validated; risk of contradictions.
- Limited external validation: neighboring work has lower FMR, no direct replication.

## Confidence
- **Joint MDLM backbone**: Medium. Architecture clear, but semantic alignment not fully validated.
- **Numeric token embeddings**: Medium. Novel, works empirically, but capacity concerns remain.
- **Shared noise schedule**: Low. Simpler but likely suboptimal; alternatives exist.
- **Overall performance**: Medium. Strong results but require independent verification.
