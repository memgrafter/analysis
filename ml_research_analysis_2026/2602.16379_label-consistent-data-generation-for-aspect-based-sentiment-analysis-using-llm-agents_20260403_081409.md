# Label-Consistent Data Generation for Aspect-Based Sentiment Analysis Using LLM Agents
## Quick Facts
- **arXiv ID**: 2602.16379
- **Source URL**: https://arxiv.org/abs/2602.16379
- **Reference Count**: 18
- **Primary Result**: An agentic data augmentation pipeline with a verifier agent significantly improves label consistency (e.g., ATSC: 80.37% vs 72.94%) and downstream performance for low-resource ABSA models compared to raw prompting.

## Executive Summary
Aspect-Based Sentiment Analysis (ABSA) is limited by scarce fine-grained annotations. This paper proposes an agentic pipeline using a ReAct-style framework where a generator agent creates synthetic sentences conditioned on aspect-polarity pairs and stylistic policies, and a separate evaluator agent verifies label correctness before acceptance. Compared to a single-step prompting baseline using the same LLM, the agentic method produces synthetically labeled data with much higher label consistency. Mixing this agentic data with limited real data improves performance for a modestly sized model (T5-Base) across multiple ABSA subtasks and datasets, effectively narrowing the gap with a heavily instruction-tuned model (Tk-Instruct).

## Method Summary
The method is a two-agent system. First, a **generator agent** samples 1–4 aspect–polarity pairs from a real training example and extracts a "style policy" (e.g., formality, sentence length, grammar). It then uses a structured prompt to generate a candidate sentence that should incorporate the sampled aspects and sentiments in the extracted style. Second, an **evaluator agent** runs two verifications: an exact substring check to ensure all aspect terms are present, and an LLM-based polarity check to judge if the sentiment expressed toward each aspect matches the provided label. Only sentences passing both checks are accepted; otherwise, the generator retries (up to alimit). A raw prompting baseline uses the same generation prompt but omits the verification and retry loop.

## Key Results
- Label consistency on Rest16 (judged by a fine-tuned Tk-Instruct) is substantially higher for the agentic method vs. raw prompting (ATE: 78.17% vs 43.89%; ATSC: 80.37% vs 72.94%; ASPE: 33.89% vs 18.33%).
- Mixing agentic-generated data (1:1 ratio) with real data consistently improves T5-Base F1 scores across three ABSA tasks (ATE, ATSC, ASPE) on four SemEval datasets, with maximum gains of +3.60 (ATSC) and +2.62 (ASPE).
- The heavily instruction-tuned Tk-Instruct shows marginal or negative gains from synthetic data mixing, while the agentic augmentation provides a larger relative improvement for the less-capable T5-Base.

## Why This Works (Mechanism)
The core mechanism is the **decoupled verification loop**. The evaluator agent acts as an external, automated critic that filters out generated sentences where the LLM failed to correctly bind the provided aspect terms and polarities to the new text. This rejection-and-retry process systematically reduces label noise in the synthetic corpus. By conditioning generation on extracted stylistic policies from real examples, the synthetic data also preserves diverse surface forms. The resulting higher-quality synthetic data provides a more reliable learning signal for the downstream model than unfiltered generations.

## Foundational Learning
- **ReAct Framework**: The agentic pipeline follows the Reason+Act paradigm where an LLM reasons about tool use. *Why needed*: Enables separation of generation and verification as distinct, callable steps. *Quick check*: Confirm the system has distinct "generate" and "verify" tool invocations with interleaved reasoning.
- **Aspect-Based Sentiment Analysis (ABSA)**: The fine-grained task of extracting aspect terms (ATE), classifying sentiment per aspect (ATSC), or both jointly (ASPE). *Why needed*: Defines the specific label structure (term+polarity pairs) that synthetic data must preserve. *Quick check*: Verify the dataset format uses per-aspect sentiment annotations.
- **Label Consistency**: The proportion of synthetic examples where the text's expressed sentiment matches the provided polarities for all mentioned aspects. *Why needed*: Primary quality metric for synthetic ABSA data; noisy labels harm training. *Quick check*: A judge model (here, Tk-Instruct fine-tuned on real data) evaluates a held-out synthetic set.
- **Instruction Tuning**: Training models to follow natural language prompts/instructions. *Why needed*: Both the generator/evaluator agents and the downstream Tk-Instruct rely on this capability. *Quick check*: The paper uses Qwen2.5-14B (likely instruction-tuned) for generation.
- **Data Augmentation via Synthesis**: Using a model to create new training examples. *Why needed*: Addresses scarcity of fine-grained ABSA annotations. *Quick check*: Synthetic sets are mixed with original training data at defined ratios (e.g., 1:1).

## Architecture Onboarding
**Component Map**: 
Sampled (Aspect, Polarity) + Style Policy -> Generator Agent (LLM + Prompt) -> Candidate Sentence -> Evaluator Agent -> [Substring Check] -> [Polarity LLM Check] -> (Accept) -> Synthetic Example OR (Reject) -> Retry Loop -> Next Sample

**Critical Path**: The generate-then-verify loop is the essential innovation. The generation prompt itself is identical to the baseline; the performance delta comes from the evaluator's rejection of invalid outputs and subsequent retries.

**Design Tradeoffs**: 
- **Strictness vs. Yield**: A strict evaluator (exact substring, conservative polarity judgment) improves label consistency but lowers the acceptance rate, requiring more LLM calls and time.
- **Automation vs. Gold Labels**: Using an LLM as a judge for polarity avoids costly human annotation but introduces a new source of bias/inconsistency.
- **Style Conditioning**: Extracting a style policy from a single real sentence may capture idiosyncrasies rather than generalizable styles, potentially over-constraining generation.

**Failure Signatures**:
- Very low acceptance rate (<20%) indicates evaluator is too strict or generator cannot satisfy the constraints.
- High downstream performance degradation when using synthetic-only data suggests residual label noise or distribution shift.
- Parsing failures (e.g., inability to extract `Terms=` and `Polarity=` from generator output) break the pipeline.

**First Three Experiments**:
1. **Isolate Evaluator Impact**: Run the generator without retries (all outputs accepted) vs. with the evaluator. Compare label consistency and downstream T5-Base performance when mixing the resulting datasets 1:1 with real data.
2. **Ablate Style Conditioning**: Generate data with the agentic pipeline but using a null/random style policy instead of extracting from a real sentence. Measure impact on label consistency and downstream diversity/F1.
3. **Judge Model Robustness**: Evaluate the same set of agentic-generated examples using multiple judge models (e.g., different instruction-tuned LLMs, or a rule-based sentiment analyzer) to see if the reported label consistency gains hold across oracles.

## Limitations
- The exact implementation of style extraction (heuristic vs. LLM-based), the precise label inclusion check (punctuation, lemmatization handling), and the full ReAct-style prompts for agent reasoning are underspecified, hindering exact replication.
- Label consistency is measured by a single judge model (Tk-Instruct fine-tuned on Rest16), which may not be a perfect gold standard and could favor its own generated patterns.
- The reported gains are primarily for T5-Base; heavily instruction-tuned models like Tk-Instruct see little benefit, limiting the method's applicability to already-capable models.

## Confidence
- **Agentic pipeline yields higher label consistency vs. raw prompting**: Medium (results are clear but dependent on inferred implementation details).
- **Mixing agentic synthetic data improves T5-Base performance**: Medium (training setup is standard, but data quality hinges on underspecified generation verifier details).
- **Tk-Instruct shows marginal/negative gains**: Low (insufficient detail on its training/evaluation to fully explain the divergence).
- **Agentic augmentation narrows the T5-Base vs. Tk-Instruct gap**: Medium (supported by comparative numbers but bounded by uncertainties in the synthetic data quality).
