# Argumentative Human-AI Decision-Making: Toward AI Agents That Reason With Us, Not For Us

## Quick Facts
- **arXiv ID:** 2603.15946
- **Source URL:** https://arxiv.org/abs/2603.15946
- **Reference count:** 40
- **Primary result:** Integrates LLMs with computational argumentation to enable contestable, revisable AI decisions via natural language.

## Executive Summary
The paper addresses the complementary limitations of computational argumentation (CA) and large language models (LLMs): CA requires domain-specific engineering, while LLMs lack transparency. It proposes an integrated approach where LLMs handle argument mining (extracting structures from text) and synthesis (generating arguments), while CA provides deterministic solvers for reasoning with formal semantics. This enables AI agents to construct, evaluate, and revise argumentation frameworks through natural language, making decisions contestable and revisable. Systems like Argumentative LLMs and ArgRAG separate LLM-generated arguments from solvers, improving auditability and reducing hallucinations. Applications in medical decision support (ArgMed-Agents) and scientific peer review demonstrate structured, interpretable reasoning. However, evaluation metrics for human-AI interaction loops remain an open challenge.

## Method Summary
The core method combines LLMs with formal computational argumentation (e.g., Dung's frameworks). LLMs extract or generate arguments from natural language input, which are formalized into an argumentation framework (nodes and attacks). Deterministic CA solvers then apply formal semantics (e.g., grounded or stable extensions) to compute acceptable positions. The output includes both a decision and a justification trace, allowing users to challenge or revise the framework. This separation ensures that the reasoning engine is transparent and auditable, while the LLM provides flexibility in handling unstructured text.

## Key Results
- Systems such as Argumentative LLMs and ArgRAG separate LLM-generated arguments from deterministic solvers, enhancing auditability and reducing hallucinations.
- Demonstrated applications in medical decision support (ArgMed-Agents) and scientific peer review show structured, interpretable reasoning.
- The paradigm shifts from opaque AI outputs to collaborative, revisable argumentative dialogues, though evaluation metrics for such loops remain underdeveloped.

## Why This Works (Mechanism)
The synergy stems from leveraging the strengths of both components: LLMs excel at processing natural language and generating arguments without extensive domain engineering, while CA provides rigorous, transparent evaluation via formal semantics. By isolating argument generation (LLM) from acceptability computation (CA solver), the system achieves auditability—arguments can be inspected, challenged, and revised. The natural language interface makes the system accessible, and the deterministic solver ensures consistent, revisable outcomes, enabling a dialectical process where humans and AI co-construct decisions.

## Foundational Learning
1. **Computational Argumentation (CA):** Formal models (e.g., Dung's frameworks) for representing and evaluating conflicting arguments. *Why needed:* Provides transparent, mathematically grounded reasoning. *Quick check:* Define an argumentation framework and compute its grounded extension.
2. **Large Language Models (LLMs):** Neural models for text generation and understanding. *Why needed:* Enables flexible extraction/generation of arguments from natural language. *Quick check:* Prompt an LLM to extract claims and premises from a paragraph.
3. **Argumentation Mining:** Automatically identifying argument structures (claims, premises, attacks) in text. *Why needed:* Converts unstructured input into formal representations. *Quick check:* Given a text, label each sentence as claim, premise, or non-argument.
4. **Argument Synthesis:** Generating arguments for or against a position. *Why needed:* Populates the argumentation framework with diverse viewpoints. *Quick check:* Instruct an LLM to produce a pro and con argument on a debated topic.
5. **Formal Semantics for CA:** Rules (e.g., admissible, stable) for determining argument acceptability. *Why needed:* Computes consistent sets of arguments. *Quick check:* For a given attack graph, list all stable extensions.
6. **Human-AI Interaction Loops:** Iterative refinement through dialogue. *Why needed:* Allows contestability and revision of decisions. *Quick check:* Design a protocol where a user can object to an argument and trigger recomputation.

## Architecture Onboarding
**Component map:** User input → LLM (argument extraction/synthesis) → CA formalization (build framework) → Solver (apply semantics) → Output (decision + justification) → User feedback → revision loop.

**Critical path:** Natural language → argument mining → framework construction → semantic solving → output generation.

**Design tradeoffs:**  
- LLM flexibility vs. noise: Broad coverage but may introduce irrelevant/biased arguments.  
- Separation vs. expressiveness: Isolating solvers aids auditability but may limit complex reasoning.  
- Natural language interface: Lowers barriers but introduces ambiguity requiring disambiguation.

**Failure signatures:**  
- LLM produces off-topic or factually incorrect arguments.  
- Attacks between arguments are misrepresented or missing.  
- Solver returns inconsistent extensions (e.g., violates conflict-freeness).  
- User feedback is not properly integrated into the framework revision.

**First three experiments:**  
1. **Argument mining validation:** Compare LLM-extracted argument structures against gold-standard annotations (e.g., IBM Debater corpus) to measure precision/recall of claim and premise identification.  
2. **Solver robustness test:** Feed frameworks generated from LLM outputs under varied prompts to the CA solver; assess consistency of extensions and sensitivity to prompt variations.  
3. **Usability pilot:** Recruit domain experts (e.g., clinicians) to use ArgMed-Agents on sample cases; collect qualitative feedback on interpretability, trust, and perceived decision quality.

## Open Questions the Paper Calls Out
The paper highlights the lack of evaluation metrics for human-AI interaction loops as a major open challenge, making it difficult to measure the effectiveness of contestable and revisable decision-making in real-world settings.

## Limitations
- The approach still relies on LLMs for argument generation, which may propagate biases or errors despite separation from solvers.
- Evaluation metrics for human-AI interaction loops are underdeveloped, hindering assessment of real-world impact.
- Some domain-specific tuning may be necessary, limiting generalizability across diverse fields.
