# PanCanBench: A Comprehensive Benchmark for Evaluating Large Language Models in Pancreatic Oncology

## Quick Facts
- **arXiv ID:** 2603.01343
- **Source URL:** https://arxiv.org/abs/2603.01343
- **Reference Count:** 40
- **Primary Result:** A human-in-the-loop pipeline generated 3,130 question-specific rubrics from 282 patient questions, revealing wide model score variance (46.5%–82.3%), substantial hallucination rates (6.0%–53.8%), and no significant benefit from web search for top models.

## Executive Summary
PanCanBench introduces a rigorous evaluation framework for large language models (LLMs) in pancreatic oncology, moving beyond multiple-choice accuracy to assess clinical completeness, factual accuracy, and web-search integration. Using a hybrid human-AI pipeline, oncology fellows developed detailed rubrics for real-world patient questions. An LLM-as-a-judge system, validated against human experts, scored 22 models. Key findings include a trade-off where reasoning-optimized models achieved higher completeness but also higher hallucination rates, and web search integration failed to improve performance for leading models. AI-generated rubrics inflated scores but preserved relative rankings, highlighting both the value and limitations of automated evaluation.

## Method Summary
The benchmark uses 282 de-identified patient questions from the Pancreatic Cancer Action Network. A four-phase human-in-the-loop pipeline produced 3,130 binary, question-specific rubric criteria: two oncology fellows independently drafted rubrics; an AI polisher enforced clarity and consistency; AI merged overlapping items; a third fellow finalized. Model responses were generated for 22 LLMs (with/without web search for select models). Evaluation employed GPT-5 as a judge using the rubrics, validated with human graders (Cohen’s κ ≈ 0.53). Factuality was assessed via atomic claim decomposition and dual LLM verification (GPT-5 + Gemini-2.5 Pro). Web-search metrics included triggering rate, resource appropriateness, and supportive link percentage. AI-only rubrics were generated for comparison.

## Key Results
- Rubric completeness scores varied widely across models (46.5% to 82.3%).
- Hallucination rates were substantial, ranging from 6.0% (GPT-4o, Gemini-2.5 Pro) to 53.8% (Llama-3.1-8B).
- Reasoning-optimized models (e.g., o3) scored highest on completeness but produced inaccuracies more frequently than less reasoning-focused models.
- Enabling web search did not yield statistically significant score improvements for top models (p > 0.25).
- AI-generated rubrics inflated absolute scores by ~17.9 points but preserved relative model rankings.

## Why This Works (Mechanism)
### Mechanism 1: Human-in-the-loop rubric generation ensures clinical validity and LLM grading reliability
The hybrid pipeline (independent human drafting, AI polishing with consistency checks, semantic merging, final human review) produces unambiguous, binary rubrics that an LLM judge can apply reliably. This balances expert diversity with clarity. Evidence: LLM-human agreement (Cohen’s κ = 0.528) matches human-human agreement (0.518); F1 scores are comparable (LLM 0.838 vs. human 0.855). Break condition: If AI polishing fails to resolve ambiguities (e.g., >20-point scorer differences) or Fellows’ rubrics diverge excessively, merged rubrics become inconsistent, lowering agreement.

### Mechanism 2: Reasoning optimization can increase completeness but also hallucination, revealing a trade-off
Reasoning models generate longer, structured responses that cover more rubric items (higher completeness) but may infer beyond training data, introducing plausible inaccuracies. Rubrics reward inclusion but rarely penalize individual factual errors, while a separate factuality check (atomic claims + dual judges) reveals such errors. Evidence: o3 achieved the highest rubric score (82.3%) but a higher error rate than GPT-4o or Gemini-2.5 Pro. Break condition: If rubrics incorporated per-claim factuality checks, the trade-off might diminish; or if models improve training to reduce hallucinations without sacrificing reasoning depth.

### Mechanism 3: Web search integration fails to improve clinical responses due to knowledge crowding out and poor source quality
Top models often trigger web search but retrieve low-authority content (e.g., generic health sites). Incorporating such results can cause models to omit critical internal knowledge ("knowledge crowding out"), reducing net completeness. Additionally, criteria requiring references are often unmet due to generic links or missing citations. Evidence: Paired t-tests show no significant improvement (Gemini p=0.2544, GPT-5 p=0.6494); resource appropriateness is moderate (GPT-5 83%, Gemini 56%); failure modes include missing specifics. Break condition: If retrieval focuses on high-authority sources (e.g., PubMed) and integration preserves internal knowledge, web search could become beneficial.

## Architecture Onboarding
**Component map:**  
Patient Questions -> Rubric Factory (Fellow 1 Draft -> AI Polish -> AI Merge -> Fellow 3 Review) -> Final Rubrics -> Model Response Generator (22 LLMs, with/without web search) -> Evaluation Core (LLM Grader + Factuality Checker + Web Search Analyzer) -> Scores/Metrics -> Validation Suite (Human Grading -> Agreement Metrics) -> Analysis

**Critical path:**  
1. Collect 282 questions; assign to Fellows for initial rubric design.  
2. AI polishing & sanity check; merge rubrics; third Fellow review; finalize rubrics.  
3. Generate model responses (with/without web search).  
4. Run LLM grader for completeness scores.  
5. Run factuality check (atomic claims + dual judges).  
6. For web-search models, compute triggering rate, resource appropriateness, supportive link %.  
7. Generate AI rubrics and re-score.  
8. Validate LLM judge with human grades.  
9. Analyze results: score distributions, hallucination rates, web impact, AI rubric inflation.

**Design tradeoffs:**  
- Human rubric creation: gold-standard validity vs. high cost/time; AI-only rubrics reduce cost but inflate absolute scores (~17.9 points) and may miss subtle errors.  
- LLM-as-a-judge: scalable but potentially biased; mitigated by human validation (κ ~0.53) but not perfect.  
- Factuality via atomic claims + dual LLMs: reduces false positives but increases computational cost and may have false negatives.  
- Web search integration: expected to improve with up-to-date sources, but current retrieval often yields low-quality links and causes knowledge crowding out, negating benefits.

**Failure signatures:**  
- LLM-judge agreement with humans drops below 0.45 (rubric ambiguity).  
- Larger models in same family do not outperform smaller ones (rubric insensitivity).  
- Factuality error rate >30% for any deployed model.  
- Web search triggering rate <60% on complex questions, or resource appropriateness <40%.  
- AI-generated rubrics produce drastically different rankings (Spearman <0.8) vs. human rubrics.

**First 3 experiments:**  
1. Reproduce LLM-judge validation: Randomly select 40 questions, have two human experts grade, compute human-human and LLM-human Cohen’s κ and F1; confirm LLM-human κ > 0.5.  
2. Sanity-check rubrics: Compare scores of two models from same family but different sizes (e.g., Llama-3.1-8B vs. 70B) on a subset; larger model should score higher; if not, investigate rubric items.  
3. Factuality pipeline smoke test: Run atomic claim decomposition and dual verification on responses from a high-hallucination model (Llama-3.1-8B) and a low-hallucination model (GPT-4o); verify error rates differ by at least 20 percentage points.

## Open Questions the Paper Calls Out
- **How can AI-generated rubrics be improved to avoid score inflation while maintaining relative ranking stability compared to human expert rubrics?** AI rubrics cannot yet replace human rubrics due to systematic over-scoring, limiting their validity as a scalable evaluation standard. Evidence needed: Systematic studies testing prompt engineering, human-in-the-loop refinement cycles, and cross-domain validation.
- **What specific mechanisms cause web search integration to degrade clinical completeness in LLM responses, and how can retrieval orchestration be optimized?** Root causes—such as attention displacement, context window mismanagement, or conflicting evidence synthesis—remain unclear. Evidence needed: Controlled experiments logging token-level attention, ablation studies on search result ranking and citation strategies.
- **How can open-source LLMs be made significantly more factually reliable for medical applications, given their high hallucination rates?** Factors driving poor factuality—training data contamination, alignment gaps, or architectural limitations—are not isolated. Evidence needed: Comparative analyses of training corpora, targeted fine-tuning with verified medical sources, factuality-focused reinforcement learning.
- **Does the human-in-the-loop evaluation pipeline and the PanCanBench findings generalize to other medical specialties beyond pancreatic cancer?** Pancreatic cancer involves unique clinical reasoning; performance trends and rubric design challenges may differ. Evidence needed: Replication studies in other high-stakes specialties (e.g., cardiology, neurology) comparing model performance distributions and error types.

## Limitations
- **Proprietary model dependency:** Core evaluation relies on GPT-5 as judge and Gemini-2.5 Pro for factuality, preventing independent verification without paid API access; web-search integration details are opaque.
- **Dataset accessibility:** Full public release of all 3,130 rubrics is unverified; Hugging Face link may contain only questions or a subset, blocking full rubric-scoring reproduction.
- **Implementation gaps:** Exact judge prompt formatting, JSON parsing logic, and API configuration for web search are incompletely specified, risking scoring drift and reproducibility issues.

## Confidence
- **Human-in-the-loop rubric validity:** High – Robust inter-rater agreement (κ ~0.52) validates the pipeline’s clinical soundness.
- **Reasoning vs. factuality trade-off:** Medium – Clear correlation shown (o3 high completeness, high error rate), but causal mechanism remains inferred; not experimentally isolated.
- **Web search ineffectiveness:** Medium-Low – Paired t-tests show non-significant gains (p > 0.25), but small N for citation-required subset (40) limits power; qualitative failure modes are anecdotal.
- **AI rubric inflation:** High – Direct comparative score difference (+17.9) is empirically measured, though effect size may vary with prompt engineering.
