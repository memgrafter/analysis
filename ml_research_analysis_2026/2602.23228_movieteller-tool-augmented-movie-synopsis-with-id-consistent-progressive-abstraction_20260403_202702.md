# MovieTeller: Tool-augmented Movie Synopsis with ID Consistent Progressive Abstraction

## Quick Facts
*   **arXiv ID:** 2602.23228
*   **Source URL:** https://arxiv.org/abs/2602.23228
*   **Reference Count:** 26
*   **Primary Result:** A training-free, tool-augmented pipeline that improves VLM-generated movie synopsis quality, achieving up to +39% LLM-as-a-Judge score, +117% ID consistency, and 62% human preference.

## Executive Summary
MovieTeller is a training-free pipeline designed to overcome two critical failures of Vision-Language Models (VLMs) when generating synopses for full-length movies: inconsistent character identification (ID) and poor narrative coherence over long contexts. It does so by orchestrating two core innovations: (1) a **specialist face recognition tool** that injects factual character groundings (names and bounding boxes) into VLM prompts to anchor descriptions in verifiable facts, and (2) a **progressive abstraction** process that hierarchically condenses scene-level descriptions into chapter summaries and a final synopsis, mitigating long-context limitations. Evaluated on 100 movies, MovieTeller shows substantial gains in ID consistency, narrative coherence, and human preference compared to direct VLM summarization and other baselines.

## Method Summary
The pipeline processes a movie video `V` and cast metadata `M` in three stages. First, **preprocessing** uses PySceneDetect for shot-based scene segmentation and extracts one keyframe per scene, filtered by a brightness/contrast quality gate. Second, a **factual grounding tool** (InsightFace) matches faces in each keyframe to a pre-built actor image database `B`, producing a set `G` of `(character name, bounding box)` pairs. The VLM (e.g., Qwen2.5-VL) is prompted with the keyframe and its associated `G` to generate a detailed, ID-consistent scene description `c_i`. Third, **progressive abstraction** groups sequential scene descriptions into chapters, uses the VLM to summarize each chapter into `c'_k`, and finally synthesizes all chapter summaries into a coherent movie synopsis `D_final` using a final integration prompt.

## Key Results
*   LLM-as-a-Judge overall score improved by up to 39% (2.17 → 3.02) versus direct VLM summarization.
*   ID Consistency score surged by 117% (1.75 → 3.80).
*   Human evaluators preferred the MovieTeller output in up to 62% of pairwise comparisons.

## Why This Works (Mechanism)

### Mechanism 1: Factual Grounding via Specialist Tool Augmentation
Injecting character identities and spatial locations from an external face recognition model into the VLM's prompt reduces character hallucination. The tool processes keyframes to produce a set `G` of `(name, bounding box)` pairs from a cast database, which is formatted into a constrained prompt. This steers the VLM to ground its descriptions in provided facts rather than inventing identities.
*   **Break condition:** If the face recognition tool fails to detect a main character (low confidence/no match), that character may be omitted or misidentified in the output.

### Mechanism 2: Progressive Abstraction for Long-Context Mitigation
The monolithic task is decomposed hierarchically: scene descriptions are generated in parallel, then chunked into chapters for summarization, and finally integrated into a synopsis. Each stage condenses information, keeping inputs within the VLM's context window and mirroring human cognitive summarization to improve narrative flow.
*   **Break condition:** Poor initial scene descriptions propagate errors through the abstraction stages ("garbage in, garbage out").

### Mechanism 3: Scene Segmentation and Quality-Controlled Keyframe Extraction
PySceneDetect partitions the video into semantically coherent scenes. A single keyframe per scene is extracted and filtered by a dual-threshold check on brightness and pixel standard deviation to discard non-informative frames (e.g., fades, black screens). This ensures a manageable, high-signal image set for the VLM.
*   **Break condition:** Inaccurate scene detection or an overly strict quality gate can misrepresent narrative segments or discard critical but dimly lit scenes.

## Architecture Onboarding
**Component map:**
Raw Movie Video `V` + Cast Metadata `M` → Scene Segmentation & Keyframe Extraction → Face Recognition Tool (InsightFace) → Factual Groundings `G` → VLM (Scene Description `C_scene`) → Chapter Grouping → VLM (Chapter Summaries `c'_k`) → VLM (Final Synopsis `D_final`)

**Critical path:** The face recognition step is a critical upstream dependency for the first VLM call. Errors in `G` directly impact scene description quality.

**Design tradeoffs:**
*   *Training-Free vs. Tool Reliability:* Avoids fine-tuning costs but inherits errors from off-the-shelf models (face recognition misses, VLM hallucinations).
*   *Modularity vs. Error Propagation:* Components are swappable, but early errors (bad keyframes, incomplete `G`) cascade without feedback.
*   *Computational Parallelism:* Scene description and chapter summarization stages are embarrassingly parallel, improving speed.

**Failure signatures:**
*   *Tool Stage:* Low face recognition recall in `G` (few matched bounding boxes per frame).
*   *VLM Scene Stage:* Scene descriptions `c_i` ignore provided names in `G`.
*   *Abstraction Stage:* Chapter summaries `c'_k` are sparse, repetitive, or contradictory; final synopsis has logical gaps.
*   *Systemic:* Low LLM-as-a-Judge scores specifically in **ID Consistency** or **Narrative Coherence**.

**First 3 experiments:**
1.  **Component Isolation - Face Recognition:** Run InsightFace on sample keyframes. Manually verify `(name, bbox)` pairs against video to quantify precision/recall of `G`.
2.  **Prompt Adherence Test - VLM Grounding:** For keyframes with `G`, run VLM with `P_desp`. Audit if output uses provided names and references bounding boxes.
3.  **Progressive Abstraction Sanity Check:** Feed two ground-truth chapter summaries to VLM with `P_synopsis`. Evaluate if the integrated output retains key points from both.

## Open Questions the Paper Calls Out
*   **How does integrating audio modality (dialogue, sound events) affect narrative coherence and factual accuracy?** The current visual-only approach omits potentially critical audio context.
*   **How sensitive is performance to the completeness and quality of the pre-built face database?** Real-world scenarios may have fewer or noisier reference images than the 2 high-quality per-actor standard.
*   **Can a dynamic, context-aware tool-invocation strategy improve efficiency and maintain ID consistency?** The current static, per-keyframe tool use may be suboptimal for scenes with varying character density.

## Limitations
*   **Unknown Prompt/Chunking Details:** Exact templates for `P_sum` and `P_synopsis`, and the scene-to-chapter grouping heuristic (size, overlap) are unreported, requiring reverse-engineering.
*   **Tool-Dependent Performance:** Results are bounded by face recognition recall and scene detection accuracy; failures in these upstream tools propagate.
*   **Evaluation Scope:** Tested on 100 movies; robustness to diverse genres, animation, or poor video quality is not thoroughly established.

## Confidence
*   **High:** End-to-end performance gains (LLM Judge, human preference) are strongly evidenced by paper experiments.
*   **Medium:** Specific mechanistic contributions (tool augmentation, progressive abstraction) are supported by internal ablations but lack independent replication.
*   **Low:** Generalizability beyond the evaluated benchmark and robustness to component failures (e.g., missed face matches) are not stress-tested.

## Next Checks
