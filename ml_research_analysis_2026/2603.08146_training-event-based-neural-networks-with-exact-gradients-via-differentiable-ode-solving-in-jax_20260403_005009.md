# Training event-based neural networks with exact gradients via Differentiable ODE Solving in JAX

## Quick Facts
- **ArXiv ID:** 2603.08146
- **Source URL:** https://arxiv.org/abs/2603.08146
- **Reference count:** 20
- **Primary result:** Eventax achieves up to 99.28%±0.13% on Yin-Yang and 97.50%±0.07% on MNIST with exact gradients and flexible neuron models.

## Executive Summary
Eventax presents a novel framework for training spiking neural networks (SNNs) that combines differentiable numerical ODE solvers with event-based spike handling. This integration resolves the long-standing trade-off between flexibility (supporting arbitrary neuron dynamics) and exact gradient computation. By leveraging JAX and Diffrax, Eventax computes gradients that are exact with respect to the forward simulation for any neuron model defined by ODEs, eliminating the need for closed-form spike time solutions. The framework demonstrates strong empirical performance on benchmark tasks, including 99.28%±0.13% accuracy on Yin-Yang (QIF, integral loss), 97.50%±0.07% on MNIST (LIF, exponential-integral loss), and 100% on delayed-XOR with an EGRU recurrent unit. Its modular architecture supports a wide range of neuron models, from standard LIF to complex multi-compartment dendritic neurons, making it a versatile tool for precise temporal learning.

## Method Summary
Eventax models neurons as continuous-time systems governed by an ODE `dy/dt = f(t,y)` and a spike condition `g(t,y)`. Users define a `NeuronModel` class specifying dynamics, threshold, input integration, and reset rules. The core simulation engine, `EvNN`, orchestrates event-driven integration using Diffrax solvers, which monitor the spike condition via root-finding to detect exact event times. Upon a spike, the state is advanced, the neuron resets, and input events are scheduled for connected cells. Gradients are computed with the adjoint method for ODEs, using Diffrax’s recursive checkpointing to balance memory and compute. The entire pipeline is JAX-native, enabling just-in-time compilation and vectorized batching. The framework accommodates both time-to-first-spike (TTFS) and state-based readouts (e.g., max potential, integral), and trains with standard optimizers like AdamW.

## Key Results
- **Yin-Yang:** 99.28%±0.13% accuracy with QIF hidden layer and integral loss.
- **MNIST:** 97.50%±0.07% accuracy with LIF and exponential-integral loss.
- **Delayed-XOR:** 100% accuracy using an EGRU recurrent unit.
- **Model support:** Successfully applied to LIF, QIF, EIF, Izhikevich, EGRU, and a multi-compartment dendritic neuron model.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Eventax computes gradients that are exact with respect to the numerical forward simulation for any ODE-defined neuron model, without needing closed-form solutions for spike times or state evolution.
- **Mechanism:** The framework integrates neuron ODE dynamics using a differentiable numerical solver (Diffrax). Spike events are treated as continuous-time discontinuities detected via root-finding on a spike condition function `g(t, y)`. When `g` changes sign, the solver locates the exact event time `t_event` and advances the state to that point. Gradients flow through the solver's computational steps and through `t_event` via the implicit function theorem, avoiding surrogate approximations.
- **Core assumption:** The neuron's dynamics are well-defined by an ODE `dy/dt = f(t, y)` and a continuously monitored spike condition `g(t, y)`. The numerical solver's step size is sufficient to detect sign changes accurately.
- **Evidence anchors:**  
  [abstract] "... combines differentiable numerical ODE solvers with event-based spike handling. ... computes gradients that are exact with respect to the forward simulation for any neuron model defined by ODEs, without requiring closed-form solutions."  
  [section III.D] "Diffrax’s ODE solvers perform this integration while simultaneously monitoring threshold crossings. When a neuron’s spike condition changes sign between two solver steps, Diffrax invokes a root-finding procedure to locate the exact spike time... Gradients are backpropagated directly through the solver steps, while the dependence of t_event on the model parameters is handled via the implicit function theorem."  
  [corpus] The neighboring corpus focuses on efficiency and sparse training but does not directly challenge the mechanism of exact gradients via differentiable ODE solving. Evidence for the mechanism's novelty is primarily internal to the paper.
- **Break condition:** If the spike condition `g(t, y)` is non-smooth or the ODE `f` is stiff/ill-conditioned, root-finding may fail or become numerically unstable, breaking the exact gradient guarantee. A too-large solver step size could also bypass a spike event entirely.

### Mechanism 2
- **Claim:** The framework's modular `NeuronModel` interface (dynamics, spike condition, reset) enables support for diverse neuron models (LIF, QIF, EIF, Izhikevich, EGRU, multi-compartment) without framework-level changes.
- **Mechanism:** Users define a class implementing `dynamics(t, y)`, `spike_condition(t, y)`, `input_spike(y, w)`, and `reset_spiked(y, mask)`. The core `EvNN` simulation loop is model-agnostic; it calls these methods during integration and event handling. This decouples the numerical event-handling engine from the specific biological or mathematical neuron definition.
- **Core assumption:** All neuron behaviors can be expressed as a set of ODEs (for continuous dynamics) and instantaneous reset rules applied at discrete event times. The state `y` structure is consistent across methods.
- **Evidence anchors:**  
  [section III.B] "Each neuron model `NeuronModel` specifies its initial state, ODE dynamics `ẏ=f(t,y)`, spike condition, input-spike update rule, and reset behaviour... The framework already accommodates a wide range of models... while remaining straightforward to extend with custom models."  
  [section III.C] Lists implemented models (LIF, QIF, EIF, Izhikevich, EGRU) and a complex multi-compartment dendritic model (Eqs. 2-5), demonstrating the breadth of supported dynamics.  
  [corpus] Neighbors like "ILIF" and "Gated Parametric Neuron" propose specific neuron variants, suggesting the field values modular neuron definitions. Eventax's API generalizes this.
- **Break condition:** A neuron model requiring history-dependent dynamics beyond the current state vector `y` (e.g., infinite-delay filters, adaptation with long time constants not captured in `y`) would require extending the state definition, potentially complicating the interface. Non-ODE-based dynamics (e.g., discrete maps) are not natively supported.

### Mechanism 3
- **Claim:** By using JAX's auto-differentiation and Diffrax's recursive checkpoint adjoint, Eventax achieves memory-efficient backpropagation through long continuous-time trajectories without sacrificing gradient exactness.
- **Mechanism:** The adjoint method for ODEs is used to compute gradients during the backward pass, avoiding the need to store all intermediate states. Diffrax's implementation, combined with JAX's just-in-time compilation and vectorization (`vmap`), allows this to be applied to the event-laden simulation. Recursive checkpointing stores only selective solver states, recomputing others during the adjoint solve.
- **Core assumption:** The adjoint ODE itself is well-posed and can be solved accurately by the same Diffrax machinery. The memory savings from checkpointing outweigh the recomputation cost for typical network sizes and sequence lengths.
- **Evidence anchors:**  
  [abstract] "Built in JAX, our framework uses Diffrax ODE-solvers to compute gradients that are exact... by using Diffrax’s recursive checkpoint adjoint, we inherit memory-efficient checkpointing without sacrificing gradient accuracy."  
  [section II] "Like BPTT, we differentiate through the steps of the numerical solver... Like event-based methods, we obtain exact spike times via root-finding... This combination yields exact gradients... Additionally, by using Diffrax’s recursive checkpoint adjoint, we inherit memory-efficient checkpointing."  
  [corpus] The "Bullet Trains" paper also addresses parallelization of temporally precise SNN training, but uses a different approach (layer-wise parallelism). Eventax's adjoint-based memory efficiency is a distinct, complementary mechanism.
- **Break condition:** For extremely long simulations or very large batches, the recomputation overhead in the adjoint phase could become prohibitive. The memory footprint, while reduced, may still be high for massive networks if checkpoint intervals are too sparse.

## Foundational Learning
- **Concept: Continuous-time neural dynamics as Initial Value Problems (IVPs)**  
  *Why needed here:* Eventax treats every neuron's membrane potential evolution between spikes as an IVP: `y(t0) = y0`, `dy/dt = f(t, y)`. Solving these IVPs is the core of the forward pass. Understanding state evolution, time constants, and equilibrium points is essential to define `f`.  
  *Quick check question:* Given a LIF neuron with `τ dV/dt = -(V - E_L) + I(t)`, what is the state vector `y` and the dynamics function `f`? (Ans: `y = V`; `f(t, V) = (-(V - E_L) + I(t)) / τ`).

- **Concept: Event detection via root-finding on a discontinuity condition**  
  *Why needed here:* Spikes are defined by a condition (e.g., `V >= V_th`). This condition `g(t, y)` is monitored during ODE integration. When it crosses zero, a root-finder (e.g., bisection) pinpoints `t_spike`. This is how exact spike times are found without analytic solutions.  
  *Quick check question:* If `g(t, y) = V(t) - V_th`, and you know `V` at times `t_i` and `t_{i+1}` with `g(t_i) < 0` and `g(t_{i+1}) > 0`, what does the root-finder compute? (Ans: The time `t_event ∈ (t_i, t_{i+1})` where `V(t_event) = V_th`).

- **Concept: The adjoint method for gradient computation through ODE solvers**  
  *Why needed here:* To compute `∂L/∂θ` where the forward pass solves an ODE, the adjoint method solves a backwards ODE for the gradient of the loss w.r.t. the state. This is how gradients flow through the continuous dynamics and, via the implicit function theorem, through the event times.  
  *Quick check question:* In backpropagation through an ODE solver, what is the primary purpose of solving the adjoint ODE? (Ans: To compute the gradient of the loss with respect to the initial state `y(t0)` and parameters `θ` without storing the full trajectory).

## Architecture Onboarding
**Component map**
- `NeuronModel` (abstract): User-defined module. Implements: `initial_state(n)`, `dynamics(t, y)`, `spike_condition(t, y)`, `input_spike(y, w)`, `reset_spiked(y, mask)`.
- `EvNN` (core class): Manages the event-driven simulation loop. Holds network connectivity, neuron instances, and a spike event buffer. Key methods: `__call__` (step between events), `ttfs()` (run to first output spike), `state_at_t()` (run to final time).
- Diffrax solver: The numerical ODE integrator (e.g., `Euler`, `Tsit5`). Configured with an event handler (`root_finder`) that monitors `spike_condition`.
- Wrapper classes (e.g., `AMOS`, `Refractory`): Functional wrappers that take a `NeuronModel` and return a new model with modified behavior (e.g., limiting to one spike).
- Loss functions: User-defined JAX functions that take the output of `ttfs()` or `state_at_t()` and compute a differentiable scalar loss.

**Critical path**
1. User instantiates `FFEvNN` with a list of `NeuronModel` instances (layers), connectivity, and solver settings.
2. For a batch, input spike times are loaded into the event buffer.
3. `EvNN.ttfs()` or `state_at_t()` is called. The core loop:
   a. Query next event time from buffer.
   b. Call Diffrax to solve ODE from current `(t, y)` to *at least* that next event time.
   c. Diffrax detects a spike if `spike_condition` changes sign. It finds `t_spike` exactly.
   d. `EvNN` advances state to `t_spike`, applies `reset_spiked` to the spiking neuron, and schedules new output events (input spikes for connected neurons) at `t_spike`.
   e. Loop until termination condition (all outputs spiked for TTFS, or final time reached for state-based).
4. Loss is computed on the collected output (spike times or states).
5. `jax.grad` (via `value_and_grad`) computes gradients through the entire simulation, including through solver steps and event times.

**Design tradeoffs**
- **Accuracy vs. Speed:** Smaller ODE solver step sizes yield more accurate spike times and better gradient fidelity but increase compute cost linearly. Throughput scales with step size.
- **Model Flexibility vs. Analytic Efficiency:** Eventax's generic solver supports any ODE neuron but is slower than analytic methods (like EventProp for LIF) which compute `t_spike` in closed-form. Trade-off is flexibility for complex models (QIF, dendritic).
- **Memory vs. Recomputation:** Using Diffrax's adjoint with checkpointing reduces memory but increases backward-pass compute. Disabling adjoint (storing all states) increases memory but may speed up backprop.

**Failure signatures**
- **Dead neurons:** Neurons that never spike (zero spike count). Observed with LIF in Yin-Yang experiments. Causes: Poor weight/bias initialization, insufficient driving input, or excessive leak. Result: No gradient signal for those neuron's parameters.
- **Solver non-convergence:** Diffrax fails to find a root for `spike_condition` or the ODE solve diverges. Often due to too large step size, stiff dynamics, or poorly scaled parameters.
- **Gradient NaNs/Infs:** Can arise from exploding potentials in models like QIF if not handled (e.g., by using AMOS wrapper or state-based output layers with LI units). Also from `log(softmax)` when all output spike times are `inf`.

**First 3 experiments**
1. **Yin-Yang with TTFS loss and AMOS-wrapped LIF:** Validate the basic pipeline: encode dataset as input spikes, define a simple 2-layer network, use `ttfs()` loss (Eq 8), ensure AMOS wrapper restricts to one spike. Expect ~91% accuracy.
2. **Yin-Yang with state-based (integral) loss and QIF hidden layer:** Replace LIF with QIF, use `state_at_t()` and integral logit (Eq 11). Expect ~99.28% accuracy.
3. **Multi-compartment neuron on Yin-Yang:** Use the dendritic model (Eqs 2-5) as the only neuron (2 neurons total, one per class) with TTFS loss. Expect ~96% accuracy.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can synaptic and axonal delays be effectively integrated into Eventax for learning, and what performance improvements do they bring on temporally precise tasks?
- **Basis in paper:** The authors state the event-based formulation is "naturally suited to learning synaptic and axonal delays" as a future direction but have not implemented it.
- **Why unresolved:** Delay learning requires extending the framework to handle time-dependent propagation, which may interact complexly with the event-driven solver and gradient computation.
- **What evidence would resolve it:** Implement learnable delay parameters, train on tasks known to benefit from delays (e.g., auditory processing), and compare accuracy, spike timing, and convergence against non-delay models.

### Open Question 2
- **Question:** What are the memory-accuracy trade-offs when integrating Diffrax's Backsolve adjoint method with event-based dynamics, and can it maintain stable training?
- **Basis in paper:** The authors note Diffrax has a Backsolve adjoint for memory efficiency, but it is "not yet integrated with event handling"; integrating it would yield low-memory training but potentially at the cost of gradient exactness.
- **Why unresolved:** Event detection creates discontinuities that may conflict with Backsolve's assumptions, risking gradient errors or instability; this trade-off is unexplored.
- **What evidence would resolve it:** Implement combined Backsolve+event handling, measure memory consumption and gradient error (e.g., via gradient check) on benchmark tasks, and assess training convergence and final accuracy.

### Open Question 3
- **Question:** What initialization or pseudo-dynamic strategies most effectively mitigate the "dead neuron" problem across diverse neuron models like LIF and QIF?
- **Basis in paper:** The paper observes dead neurons (no spikes) especially in LIF, and suggests "careful parameter initialization strategies or pseudo-dynamics approaches" as solutions but does not test them.
- **Why unresolved:** Dead neurons receive no gradient signal, hindering learning; the efficacy of remedies likely depends on neuron dynamics (e.g., voltage derivative near threshold), which varies by model.
- **What evidence would resolve it:** Systematically test initializations (e.g., bias current, weight scales) and pseudo-dynamics (e.g., Klos et al.'s method) on LIF, QIF, etc., measuring spike rates, gradient norms, and task accuracy across seeds.

### Open Question 4
- **Question:** How do ODE solver configurations (e.g., step size, method) affect the accuracy, efficiency, and gradient stability when training complex multi-compartment neuron models?
- **Basis in paper:** The performance analysis varies step size for QIF on Yin-Yang, but does not extend to the more complex multi-compartment model, which showed sensitivity to initialization and high firing rates.
- **Why unresolved:** Multi-compartment models have higher-dimensional, stiff dynamics; solver settings may critically impact event detection, gradient precision, and computational cost, yet no guidelines exist.
- **What evidence would resolve it:** Train multi-compartment networks with diverse solvers (Euler, RK4) and step sizes, evaluating test accuracy, spike consistency, runtime, and gradient variance to identify robust configurations.

## Limitations
- **Reproducibility gaps:** Exact weight initialization bounds, MNIST `tmax_in`, and state-based loss integration details are unspecified, which could affect reported numbers.
- **Exact gradient guarantee break conditions:** The guarantee may fail for non-smooth spike conditions, extreme stiffness, or excessively large solver step sizes; these edge cases are not empirically stress-tested.
- **Scalability quantification:** Claims about memory efficiency via adjoint/checkpointing are qualitative; actual memory/throughput trade-offs for large MNIST-scale networks are not provided.
