# DocDancer: Towards Agentic Document-Grounded Information Seeking

## Quick Facts
- **arXiv ID:** 2601.05163
- **Source URL:** https://arxiv.org/abs/2601.05163
- **Reference count:** 40
- **Primary result:** End-to-end trained open-source agent achieves SOTA on MMLongBench-Doc (56.8 F1) and DocBench (85.5 accuracy) with only 5k synthetic training instances.

## Executive Summary
DocDancer redefines document question answering as an agentic information-seeking problem. It uses a simple yet effective two-tool framework (Search and Read) to explore long, structured documents and an Exploration-then-Synthesis pipeline to generate high-quality training data where the agent first builds a knowledge graph through iterative exploration before synthesizing complex, grounded QA pairs. Trained on just 5,000 such synthetic trajectories, DocDancer sets new state-of-the-art results on two major document understanding benchmarks, demonstrating that agentic exploration can be learned efficiently from synthetic data.

## Method Summary
The core of DocDancer is a tool-driven agent that alternates between Search (identifying relevant coarse sections via textual signals) and Read (extracting fine-grained evidence, including visual content). The Exploration-then-Synthesis data generation pipeline starts with a document, runs a multi-step random-walk exploration to accumulate a set of diverse observations (implicit knowledge graph), then uses multi-observation reasoning to synthesize QA pairs that require connecting information across the document. Training uses masked observation loss to teach the model when and how to invoke tools. This approach circumvents the scarcity of human-annotated multi-step DocQA data.

## Key Results
- 56.8 F1 on MMLongBench-Doc, surpassing previous SOTA.
- 85.5 accuracy on DocBench, also a new record.
- Consistent outperformance of OS-QA across all metrics and benchmarks with only 5,000 training instances.

## Why This Works (Mechanism)
### Mechanism 1: Exploration-then-Synthesis Data Generation
The pipeline generates high-quality training data by having the agent iteratively explore a document (modeled as a random walk over an implicit knowledge graph) before synthesizing questions that require connecting the collected observations. The core assumption is that explicit exploration intent prevents shallow or redundant evidence collection. Evidence includes the abstract’s claim of addressing data scarcity and Section 3.2’s formalization. Break condition: shallow exploration or failed intent modeling yields insufficiently diverse evidence, degrading QA complexity.

### Mechanism 2: Two-Tool Agent Design
Search and Read together enable effective exploration of long, structured documents: Search provides global guidance, while Read performs localized extraction (including visual elements). The simplicity of a two-tool set is assumed to facilitate efficient learning while still covering textual and visual signals. Evidence: abstract and Section 3.1. Break condition: if document complexity (e.g., intricate diagrams) exceeds tool capabilities, exploration quality degrades.

### Mechanism 3: Synthetic Data Efficiency
Training on the synthesized 5k instances elicits multi-step reasoning and tool use in open-source models, compensating for the lack of human annotations. The assumption is that quality outweighs quantity. Evidence: consistent SOTA results on two benchmarks and outperformance of OS-QA (Section 4.2). Break condition: insufficient model capacity or degradation in synthetic data quality would prevent matching human-annotated baselines.

## Architecture Onboarding
**Component map:** Qwen3-30B-A3B-Thinking-2507 (or Qwen3-4B-Thinking-2507) → Exploration-then-Synthesis pipeline → 5,000 synthetic trajectories → DocDancer agent with Search/Read tools.

**Critical path:** Document processing → Exploration trajectory building → Synthesis of QA pairs → Training with masked observation loss.

**Design tradeoffs:** Simple two-tool design vs. comprehensive multi-tool systems; synthetic data quality vs. scale; model size vs. performance.

**Failure signatures:** Incorrect answers due to shallow exploration; inability to perform cross-page reasoning; poor tool invocation during inference (e.g., unnecessary Search calls).

**First 3 experiments:** 
1. Verify Search tool locates relevant sections on documents with known answer positions.
2. Confirm Read tool correctly extracts information from section IDs returned by Search.
3. Assess synthetic data quality by checking whether generated QA pairs necessitate multi-step reasoning.

## Open Questions the Paper Calls Out
- **Random walk vs. explicit knowledge graph:** The paper uses a random walk to implicitly model document structure but does not compare to explicit graph construction. How do these approaches differ in data quality and diversity?
- **Impact of external models:** The choice of multimodal model (Mm) and rejection-sampling model (Mt) likely affects synthetic data quality and downstream performance, but systematic ablation is lacking.
- **Two-tool vs. five-tool:** DocDancer’s two-tool design outperforms DocAgent’s five-tool approach, but the learning dynamics and reasons for this advantage (e.g., sample efficiency, failure modes) are not analyzed.

## Limitations
- Synthetic data may not fully capture real-world document complexity (e.g., handwritten notes, noisy scans).
- Visual reasoning capability depends entirely on the chosen multimodal model (Mm); performance on complex diagrams/charts is unstated.
- Evaluation is limited to English documents and two specific benchmarks; domain and language generalization are unknown.
- No ablation on tool count; a single unified tool might perform similarly.

## Confidence
- Exploration-then-Synthesis data quality: **Medium** (sound concept but lacks direct comparison to alternatives)
- Tool-driven framework effectiveness: **High** (clear design and strong benchmark support)
- Synthetic data efficiency: **High** (consistent SOTA with small dataset aligns with known trends)

## Next Checks
1. **Human data comparison:** Manually annotate 100 real DocQA instances and compare model performance on synthetic vs. human data to measure distribution gap.
2. **Cross-language generalization:** Test DocDancer on non-English long-document benchmarks to assess language dependency.
3. **Tool usage analysis:** Log and categorize tool invocation patterns on a diverse document set to identify common failure modes (e.g., over-reliance on Search, Read extraction errors).
