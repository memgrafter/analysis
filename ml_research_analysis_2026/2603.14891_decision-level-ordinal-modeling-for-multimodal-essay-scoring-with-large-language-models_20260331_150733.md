# Decision-Level Ordinal Modeling for Multimodal Essay Scoring with Large Language Models

## Quick Facts
- **arXiv ID:** 2603.14891
- **Source URL:** https://arxiv.org/abs/2603.14891
- **Reference count:** 28
- **Primary result:** DLOM improves multimodal AES QWK from 0.492 (generation SFT) to 0.516 (DLOM-GF) on EssayJudge and text-only AES QWK from 0.646 to 0.697 (DLOM-DA) on ASAP/ASAP++.

## Executive Summary
Standard LLM-based automated essay scoring (AES) relies on generating score tokens, which is sensitive to prompt design and decoding choices and struggles with multimodal inputs where visual relevance varies. This paper introduces Decision-Level Ordinal Modeling (DLOM), which repurposes the LLM’s language modeling head to directly predict scores by extracting logits over a predefined ordered set of score tokens. For multimodal AES, DLOM-GF adds a gated fusion module to adaptively combine text-only and multimodal score logits at the decision level. For text-only AES, DLOM-DA incorporates a distance-aware regularization term to better respect ordinality. Experiments on multimodal EssayJudge and text-only ASAP/ASAP++ benchmarks show consistent improvements in Quadratic Weighted Kappa (QWK), with gains particularly notable on higher-level discourse traits and reduced sensitivity to prompt variations.

## Method Summary
DLOM modifies the standard supervised fine-tuning (SFT) pipeline for AES. First, a backbone LLM (Qwen3-VL-8B-Instruct for multimodal, Qwen3-8B for text-only) is trained via generation-based SFT to output a single score token given an essay (and optionally an image) and a fixed prompt. The core DLOM change reuses the LM head: instead of decoding, the model extracts logits for a predefined set of score token IDs (e.g., "0", "1", ...) at the final sequence position. Prediction is the argmax over these logits, trained with cross-entropy against the gold score. For multimodal inputs, DLOM-GF runs two branches—one text-only, one multimodal—each producing score logits *z*<sup>(t)</sup> and *z*<sup>(m)</sup>. A gating module computes α = sigmoid(linear(tanh([*z*<sup>(m)</sup>; *z*<sup>(t)</sup>]))) and fuses logits as *z* = α·*z*<sup>(m)</sup> + (1−α)·*z*<sup>(t)</sup>. For text-only, DLOM-DA adds a SmoothL1 loss between the expected score (∑ *p*<sub>*k*</sub>·*k*) and the gold score, with a learnable weight λ, to the cross-entropy. Both extensions train end-to-end.

## Key Results
- **Multimodal EssayJudge:** Generation SFT baseline average QWK = 0.492 → DLOM = 0.504 → DLOM-GF = 0.516.
- **Text-only ASAP/ASAP++:** Generation SFT average QWK = 0.646 → DLOM = 0.685 → DLOM-DA = 0.697.
- Improvements are especially pronounced for discourse-related traits; DLOM reduces performance variance across different prompt designs.

## Why This Works (Mechanism)
Decision-level modeling bypasses the noisy decoding pipeline used in generation-based AES. By extracting logits directly from the LM head over a fixed set of score tokens, DLOM eliminates sensitivity to prompt phrasing, decoding strategies (temperature, top-*p*), and tokenization artifacts that can distort generated outputs. The cross-entropy loss directly optimizes the model to produce well-separated logits for each ordinal score. For multimodal inputs, the gated fusion in DLOM-GF allows the model to dynamically decide, per sample, how much to trust text-only versus multimodal evidence at the decision level, rather than committing early to a fused representation. This is crucial when an image’s relevance to the scoring task is heterogeneous. DLOM-DA’s distance-aware regularization further encourages the predicted probability distribution to have an expected score close to the gold label, reinforcing the ordinal structure beyond simple classification boundaries.

## Foundational Learning
- **Ordinal classification:** Scores are ordered categories; models should respect rank distances. *Why needed:* Standard classification ignores ordinality, leading to arbitrary penalties for mis-ordering. *Quick check:* Use loss functions that incorporate label distances (e.g., ORD; expected score regularization).
- **LM head reuse for direct prediction:** Instead of generating tokens, extract logits for a target set from the LM head. *Why needed:* Avoids decoding errors and enables direct optimization on score space. *Quick check:* For a given input, retrieve logits at the final position for predefined token IDs; ensure they correlate with scores.
- **Gated fusion at decision level:** Combine multiple modality-specific score distributions via a learned gate. *Why needed:* Modality relevance varies per essay; feature-level fusion may commit prematurely. *Quick check:* Gate α should differ across samples and correlate with modality usefulness.
- **Distance-aware regularization:** Penalize deviation between predicted expected score and true score. *Why needed:* Cross-entropy alone does not guarantee ordinal consistency in predicted probabilities. *Quick check:* Compute expected score from softmax(logits); add SmoothL1 loss to total objective.
- **Quadratic Weighted Kappa (QWK):** Metric for inter-rater agreement that weights disagreements by squared ordinal distance. *Why needed:* AES scores are ordinal; QWK accounts for severity of mispredictions. *Quick check:* Compute QWK from predicted and gold score matrices; values range [-1,1], higher is better.
- **Supervised fine-tuning (SFT) with generation:** Train LLM to output score tokens via standard language modeling. *Why needed:* Provides a strong baseline and initializes LM head for DLOM. *Quick check:* Model generates a single token (e.g., "4") given essay and prompt; evaluate token accuracy.

## Architecture Onboarding
**Component map:**  
Essay (text) ± Image → Backbone LLM (Qwen) → Final hidden state → LM head → Score logits *z*  
For multimodal: Text-only branch (text only) → *z*<sup>(t)</sup> ; Multimodal branch (text+image) → *z*<sup>(m)</sup> → Gated fusion (α from [*z*<sup>(m)</sup>; *z*<sup>(t)</sup>]) → Fused *z*  
For text-only: *z* → Expected score *ȳ* = ∑ softmax(*z*)<sub>*k*</sub>·*k* → Distance loss L<sub>dist</sub>  
All components trained with cross-entropy L<sub>CE</sub>(*z*, *y*) (+ L<sub>dist</sub> for DA) end-to-end.

**Critical path:**  
Input encoding → backbone forward pass → extract last-token hidden state → linear projection via LM head → score-token logits → (fusion or regularization) → loss → backpropagation.

**Design tradeoffs:**  
- DLOM vs. generation: DLOM removes decode-time stochasticity but requires predefined score token set; may not generalize to unseen score ranges.
- DLOM-GF: Decision-level fusion avoids feature interference but depends on both branches producing meaningful logits; gate introduces parameters that could collapse.
- DLOM-DA: Regularization improves ordinality but adds hyperparameter λ; improper λ may destabilize training.

**Failure signatures:**  
- Gating weight α near 0 or 1 for all samples (branch collapse).  
- Learnable λ in DLOM-DA stuck at extreme (0 or 1) after training.  
- Multi-digit scores (e.g., 10) tokenized into subwords, breaking the one-token-per-score assumption.  
- High variance in QWK across CV folds, especially on small multimodal dataset.  
- Inconsistent logit extraction: top predicted token IDs do not correspond to intended numeric scores.

**First experiments:**  
1. **Tokenization audit:** For each trait, enumerate score range (e.g., 0–6). Verify that each integer has a single token ID in the tokenizer. If not (e.g., "10" splits), add special tokens or adjust extraction.  
2. **Baseline SFT replication:** Train generation-based SFT on a small subset (e.g., 100 essays) with a fixed prompt; report token accuracy and QWK to establish baseline before DLOM.  
3. **Gate behavior probe:** After training DLOM-GF, compute α per sample on validation set; check distribution (should not be degenerate) and correlate α with essay length, image type, or performance difference between text-only and multimodal branches.

## Open Questions the Paper Calls Out
- **Q1:** To what extent does the effectiveness of DLOM generalize beyond Qwen-based LLMs? The study only uses Qwen models; validation on other architectures (Llama, GPT, etc.) is needed.
- **Q2:** Can distance-aware regularization be integrated with DLOM-GF’s gated fusion for multimodal AES? The paper leaves combining ordinal constraints with multimodal fusion as future work.
- **Q3:** What specific prompt design and decoding factors cause generation-based AES sensitivity, and how exactly does decision-level modeling mitigate them? The claim is phenomenological; a controlled factorial experiment is required.
- **Q4:** How does the learned gating function in DLOM-GF behave across traits, image types, or human-annotated modality relevance? The gate is a black box; analysis of α values could interpret model decisions.
- **Q5:** Does the fixed set of predefined score tokens limit nuanced ordinal boundaries, and how sensitive is performance to the textual representation of these tokens (e.g., "1" vs. "low")? Token semantics are unexplored.

## Limitations
- Tokenization mismatch: assumes one token per score level; multi-digit scores (e.g., 10–12 in ASAP prompt 8) likely break logit alignment.
- Missing reproduction details: exact prompt templates, hyperparameters (learning rates, epochs, λ/β values), and dataset splits are not fully specified.
- Model scope: experiments limited to Qwen family; generality to other LLM architectures is uncertain.

## Confidence
- **DLOM improves AES over generation-based SFT:** Medium – results are positive but rely on unspecified tokenization and hyperparameters.
- **DLOM-GF yields further multimodal gains:** Medium – improvement modest; gating behavior not analyzed.
- **DLOM-DA yields further text-only gains:** Medium – contribution depends on λ/β; sensitivity not explored.
- **Decision-level modeling reduces prompt sensitivity:** Medium – claim lacks systematic quantification; needs controlled testing.
- **Stronger gains on discourse traits:** Medium – observed trend but not validated across diverse datasets/traits.

## Next Checks
1. **Tokenization verification:** Explicitly map each score level to a single token ID; for multi-digit scores, add special tokens or modify extraction. Re-run key experiments and report QWK differences.
2. **Hyperparameter sensitivity analysis:** Grid search over learning rates (1e-5, 2e-5, 5e-5), batch sizes (8, 16), SFT epochs (1,3,5), DLOM epochs, and DA’s λ/β. Report mean and standard deviation of QWK across runs.
3. **Prompt robustness evaluation:** Design multiple prompt templates (vary instruction phrasing, order, system messages) for both generation SFT and DLOM. Evaluate on a representative ASAP subset; compute QWK variance across templates and compare to baseline.
