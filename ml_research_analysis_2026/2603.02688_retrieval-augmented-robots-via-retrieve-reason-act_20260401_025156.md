# Retrieval-Augmented Robots via Retrieve-Reason-Act

## Quick Facts
* arXiv ID: 2603.02688  
* Source URL: https://arxiv.org/abs/2603.02688  
* Reference count: 26  
* Primary result: Retrieving the full manual improves connection F1 by 20.4% (0.537 vs. 0.446) on IKEA Assembly, but remains 44.8 points below the oracle (0.985).

## Executive Summary
This paper proposes Retrieval-Augmented Robotics (RAR) to enable zero‑shot furniture assembly. RAR follows an iterative Retrieve‑Reason‑Act loop: it retrieves relevant visual manuals, grounds 2D diagrams to 3D parts via a labeled parts overview, and synthesizes executable assembly plans using a frozen multimodal LLM (GPT‑4o). On the IKEA Furniture Assembly benchmark, RAR with full manual retrieval achieves a connection F1 of 0.537, a 20.4% gain over a zero‑shot baseline (0.446). However, the large gap to the oracle (0.985) indicates that the main bottleneck lies in visual procedural understanding rather than retrieval. Simulation experiments demonstrate successful end‑to‑end execution for simple to moderate furniture items.

## Method Summary
The task is to predict assembly sequences (pairwise part connections) for unseen furniture items. Inputs per item include its category, name, number of parts, a parts overview image (rendered 3D parts with labels), and assembly manual pages (images). The method uses a frozen multimodal LLM (GPT‑4o) combined with two retrieval modules: BM25 (k1=1.5, b=0.75) for exact manual lookup by category name, and CLIP (ViT‑B/32) + FAISS (L2) for visual similarity retrieval of up to three manuals within the same category (excluding the target). The LLM prompt combines system instructions, the baseline information (category, name, part count, parts overview), and the retrieved manual images; it outputs JSON connections. No training occurs—variations are only in the retrieval content. Performance is measured by connection F1, precision, recall, and exact match.

## Key Results
* Full manual retrieval yields connection F1 0.537, 20.4% higher than zero‑shot reasoning (0.446).
* Oracle (human‑annotated manual) reaches F1 0.985, leaving a 44.8‑point gap.
* End‑to‑end simulation validates assembly execution for simple to moderate furniture items.

## Why This Works (Mechanism)
Retrieval provides task‑specific visual instructions that the LLM can reason over. The parts overview acts as a mapping key, grounding abstract 2D diagrams to concrete 3D part indices. This combination allows the model to synthesize plausible connection sequences even for novel furniture. The significant improvement over zero‑shot confirms that external knowledge (manuals) is essential. The remaining gap to the oracle indicates that current VLMs struggle with multi‑page procedural understanding and fine‑grained part disambiguation, particularly for visually similar components.

## Architecture Onboarding
**Component map**  
Dataset (manuals, part .obj files) → Parts Overview Renderer → Retrieval Module (BM25 / CLIP‑FAISS) → Selected Manuals → GPT‑4o (with Parts Overview) → JSON Connections

**Critical path**  
1. Retrieve relevant manual pages (or whole manual).  
2. Construct prompt: system message + baseline info (category, name, part count, parts overview) + retrieved images.  
3. Call GPT‑4o API (temperature 0.0).  
4. Parse JSON output into connections.  

**Design tradeoffs**  
- BM25 (exact category match) vs. CLIP‑FAISS (visual similarity): BM25 ensures correct category but fails for ambiguous names; CLIP handles cover variations but may retrieve manuals from a different sub‑type.  
- Full manual vs. cover‑page only: full manual provides sequential detail but increases context length and may overwhelm the LLM; cover page is concise but lacks step‑by‑step info.  
- Frozen LLM vs. fine‑tuning: frozen model avoids overfitting and is easy to deploy, but may lack domain‑specific reasoning; fine‑tuning could improve procedural parsing but requires data and compute.  

**Failure signatures**  
- Low recall (many missed connections): suggests poor visual grounding or inability to parse diagrams.  
- High false positives (spurious connections): often due to part index confusion in the parts overview.  
- Low exact match: indicates the LLM loses track of assembly state across multiple manual pages.  

**First three experiments**  
1. **Zero‑shot baseline** – run the pipeline with no retrieval (only parts overview) to measure inherent LLM capability.  
2. **Exact manual retrieval (BM25)** – retrieve the ground‑truth manual by category name and compare performance against zero‑shot.  
3. **Full manual vs. cover‑page only** – using CLIP‑FAISS retrieval, supply either all retrieved pages or only the cover page to quantify the value of multi‑page information.

## Open Questions the Paper Calls Out
### Open Question 1
*Question:* How can visual grounding be scaled to handle assemblies with many visually similar parts, where current methods fail due to part disambiguation limitations?  
*Basis in paper:* Performance degrades nonlinearly with part count; shelves (many similar rectangular panels) achieve the lowest F1 (0.272). The parts overview appears insufficient for subtle geometric distinctions.  
*Why unresolved:* The paper identifies visual grounding as the primary bottleneck but does not explore architectural changes to improve fine‑grained part identification.  
*What evidence would resolve it:* Systematic experiments on synthetic assemblies varying part similarity, combined with ablation of visual grounding components (e.g., multi‑view rendering, attention mechanisms).

### Open Question 2
*Question:* Does incorporating iterative re‑retrieval based on execution feedback improve robustness in long‑horizon assembly compared to the one‑time retrieval used in the paper's RAR loop?  
*Basis in paper:* The framework uses a single retrieval at the start; the model struggles with incomplete part tracking across manual pages.  
*Why unresolved:* No investigation of dynamic re‑retrieval (e.g., upon action failure) to recover from local errors.  
*What evidence would resolve it:* An ablation comparing static retrieval against a version that re‑triggers retrieval upon detection of plan divergence, measuring success rates on complex assemblies (>10 parts) in simulation.

### Open Question 3
*Question:* To what extent does the method’s performance, demonstrated in simulation with idealized part representations (colored cubes with labels), transfer to real‑world scenarios with perceptually challenging furniture (e.g., occlusions, varying textures, poor lighting)?  
*Basis in paper:* The robotic execution section uses simplified “colored cube” parts; the paper acknowledges this simplification but does not test robustness to real‑world perception noise.  
*Why unresolved:* The claim that retrieval‑augmented reasoning can drive physical assembly has not been validated under realistic perceptual conditions.  
*What evidence would resolve it:* Real‑world robot experiments assembling actual IKEA furniture using the same pipeline but with vision systems for part localization, comparing connection F1 and execution success against the simulation baseline.

### Open Question 4
*Question:* Can architectural modifications to vision‑language models (beyond prompting GPT‑4o) specifically enhance multi‑page procedural reasoning, addressing the observed failure to integrate local assembly steps into a coherent global structure?  
*Basis in paper:* The 44.8‑point F1 gap between Full Manual and Oracle is attributed to difficulty “maintaining structured spatial state over long visual instruction sequences” and “tracking relationships across multiple manual pages.”  
*Why unresolved:* The paper uses an off‑the‑shelf VLM without tailored architectures for sequential diagram interpretation; no specialized techniques (e.g., memory‑augmented networks, graph construction) are explored.  
*What evidence would resolve it:* Develop and evaluate a fine‑tuned or architecturally modified VLM (e.g., with explicit state tracking modules or page‑graph integration) on the IKEA dataset, measuring reduction in the Oracle gap and improvements in multi‑page consistency metrics.

### Open Question 5
*Question:* How well do learned assembly patterns from retrieved visual manuals generalize to entirely novel furniture categories not present in the training corpus, and what factors limit cross‑category transfer?  
*Basis in paper:* Within‑category retrieval significantly outperforms cross‑category retrieval (F1 0.513 vs 0.441). The authors note that “structural similarity (same furniture type) matters more than superficial visual similarity.”  
*Why unresolved:* The experiment only tests within‑category vs. unrestricted cross‑category retrieval; it does not probe boundaries of transfer (e.g., can chair patterns inform a novel hybrid object?).  
*What evidence would resolve it:* A held‑out evaluation where the retrieval corpus excludes entire categories (e.g., train on chairs and tables, test on shelves and desks), analyzing which topological or geometric features enable transfer and quantifying the performance drop.

## Limitations
* The exact rendering parameters for the parts overview (camera angle, resolution, lighting, label styling) are unspecified, risking variance in visual grounding performance.  
* The verbatim LLM prompt (system and user messages) is not disclosed; prompt engineering can heavily influence output compliance and reasoning quality.  
* Retrieval implementation details (FAISS hyperparameters, BM25 tokenization/stopwords) are omitted, making exact replication difficult.  
* The IKEA dataset’s accessibility is unclear; it may require direct author request, hindering broad reproducibility.  
* The claim that visual procedural understanding is the bottleneck is inferred from the oracle gap and lacks explicit ablation separating retrieval from grounding errors.

## Confidence
- **High:** The high‑level RAR framework (Retrieve‑Reason‑Act loop using a frozen multimodal LLM) is clearly described and well‑specified.  
- **Medium:** The reported 20.4% F1 improvement from full manual retrieval is a direct experimental outcome, but its exact magnitude depends on unreported implementation details (prompt, rendering).  
- **Low:** The conclusion that the primary bottleneck is visual procedural understanding (rather than retrieval) is an inference from the oracle gap and has not been validated by an explicit ablation.

## Next Checks
1. **Ablate Part Disambiguation:** Intentionally blur or alter labels in the parts overview image; a severe performance drop would confirm that part grounding is the dominant failure mode.  
2. **Test Sequential State Tracking:** Compare performance using the full manual versus a single‑page “summary” image condensing all diagrams; minimal difference would indicate the LLM fails to integrate information across pages.  
3. **Verify Dataset & Rendering Pipeline:** Obtain the dataset from the authors or an alternative source, implement the rendering pipeline as described, and measure variance in F1 scores when altering rendering parameters (e.g., ±15° camera angle) to quantify robustness to unspecified choices.
