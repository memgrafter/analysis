# Closing the gap on tabular data with Fourier and Implicit Categorical Features

## Quick Facts
- **arXiv ID:** 2602.23182
- **Source URL:** https://arxiv.org/abs/2602.23182
- **Reference count:** 13
- **Primary result:** A combined preprocessing method (ICF detection + Learned Fourier Features) applied to MLP/ResNet backbones matches or surpasses XGBoost on classification tasks and narrows the gap on regression tasks with categorical features.

## Executive Summary
Neural networks consistently underperform tree-based models like XGBoost on tabular data. The authors identify two key deficiencies: a bias toward overly-smooth solutions that misalign with typically non-smooth tabular functions, and an inability to handle numerical features that behave categorically (Implicitly Categorical Features, ICFs). They propose a two-part preprocessing solution: (1) statistical detection and explicit one-hot encoding of ICFs, and (2) injection of high-frequency basis functions via Learned Fourier Features (LFF). These components are applied mutually exclusively per hyperparameter search run, allowing the model to discover the optimal encoding strategy for each dataset. Evaluated on 681 tabular tasks, the approach (MLP+F|C, ResNet+F|C) significantly closes the performance gap, even exceeding XGBoost on classification and achieving notable "spikes" on specific datasets.

## Method Summary
The method introduces a dual-path preprocessing router applied to raw tabular data before a standard MLP or 1D-ResNet backbone. For each training run, the router randomly selects one of two paths. **Path 1 (ICF):** Numerical features with cardinality below a threshold or passing a statistical significance test (Chi-square for classification, ANOVA/Mutual Info for regression) are binned and one-hot encoded; all other features are zero-padded. **Path 2 (LFF):** All features are standardized, mixed via a linear or convolutional layer, and transformed using a Fourier basis `cos(π·Z) ⊕ sin(π·Z)` to produce an embedding of fixed dimension `M`. The backbones (MLP or ResNet-1D) process this fixed-shape representation. Models are trained with AdamW and cosine annealing, using 150 random hyperparameter seeds per configuration to select the best validation model.

## Key Results
- Combined preprocessing (`MLP+F|C`, `ResNet+F|C`) matches or exceeds XGBoost on binary classification tasks across the benchmark.
- On regression tasks with categorical features, a performance gap remains, with `MLP+F|C` still lagging behind XGBoost.
- Large performance "spikes" occur on specific datasets (e.g., `eye_movements`, `year`) when hyperparameter search discovers the optimal preprocessing (ICF or LFF) for that data.

## Why This Works (Mechanism)

### Mechanism 1: Implicitly Categorical Feature (ICF) Handling
**Claim:** Tree-based models inherently handle numerical features that are implicitly categorical by creating discrete splits, while neural networks fail unless these features are explicitly preprocessed into a categorical representation.
**Mechanism:** Neural networks have a continuity bias, applying learned embeddings uniformly across the numerical range. For features where the target relationship is discontinuous (i.e., high correlation only after binning), this smooth processing loses signal. Tree-based models natively partition the feature space, naturally capturing such discontinuities. Detecting ICFs via statistical tests (χ², ANOVA, MI) and one-hot encoding them restores the missing signal for neural networks.
**Evidence:** [abstract, sec 1] The authors contrast intrinsic tree capability with neural bias. Ablation shows XGBoost gains no benefit from ICF preprocessing, confirming trees already handle them.

### Mechanism 2: Mitigating Smoothness Bias with Fourier Features
**Claim:** Deep neural networks have an inductive bias toward smooth solutions, which misaligns with the often non-smooth true functions in tabular data. Learned Fourier Features (LFF) counteract this bias.
**Mechanism:** Standard networks with ReLU activations exhibit spectral bias, preferentially fitting low-frequency components. LFF projects inputs into a high-dimensional space spanned by fixed high-frequency sine/cosine basis functions. This provides a rich set of basis functions upfront, allowing the network to represent sharp thresholds and discontinuities without requiring deep layers to learn them from scratch.
**Evidence:** [abstract, sec 3.3] Directly cites spectral bias and uses established Fourier feature methodology (Tancik et al., 2020) to address it.

### Mechanism 3: Synergistic Dual-Path Design
**Claim:** The mutually exclusive random selection between ICF and LFF per hyperparameter run allows the model to discover which preprocessing strategy (categorical encoding vs. non-smooth modeling) is optimal for a given dataset, leading to complementary gains.
**Mechanism:** Different datasets (or features within) have different underlying structures: some benefit from explicit categorical encoding (ICF path), others from enhanced non-smooth modeling capacity (LFF path). The random search over this binary choice, alongside other hyperparameters, acts as a form of architecture search that identifies the correct inductive bias for the task. Ablation confirms complementarity: some datasets improve with ICF, others with LFF.
**Evidence:** [sec 5.1, 5.3, 5.4] Combined models substantially outperform XGBoost on classification. Performance "spikes" and ablations show datasets where one path dominates the other.

## Foundational Learning
- **Concept: Implicitly Categorical Features (ICFs)**
  - *Why needed here:* Core premise; numerical features can have categorical-like statistical properties (high target correlation only after discretization). Recognizing this explains why naive continuous embedding fails.
  - *Quick check:* How would you use a chi-square test to decide if a numerical feature should be treated as categorical for a classification problem?
- **Concept: Spectral Bias / Smoothness Prior in Neural Networks**
  - *Why needed here:* Explains the fundamental limitation of standard MLPs/ResNets on tabular data. LFF is the direct countermeasure.
  - *Quick check:* Why might a ReLU network struggle to learn a perfect step function from finite data, even with enough parameters?
- **Concept: Fourier Feature Embeddings**
  - *Why needed here:* The technical mechanism (LFF) to inject high-frequency capacity. Understanding random Fourier features links theory to implementation.
  - *Quick check:* What effect does increasing the embedding dimension `M` in LFF have on model capacity and risk of overfitting?

## Architecture Onboarding
**Component map:** Raw Tabular Data -> ICF Detection Module -> Preprocessing Router (random choice per run) -> Encoded Tensor (ICF-path or LFF-path) -> Backbone (MLP or ResNet-1D) -> Task Head -> Prediction

**Critical path:** The router's random choice (ICF vs. LFF) is the decisive hyperparameter. It determines the entire feature transformation pipeline before data enters the backbone. The backbone itself is fixed (MLP or ResNet).

**Design tradeoffs:**
- *ICF:* Lower `min_cardinality` captures more potential ICFs but risks misencoding truly continuous features. Binning granularity (implicit via test thresholds) trades off noise vs. information loss.
- *LFF:* Larger `lff_dim (M)` increases high-frequency capacity but raises overfitting risk and computation. Choice between `LinearLFF` (feature mixing) and `Conv1x1LFF` (parameter sharing) affects rotational invariance assumptions.
- *Backbone:* ResNet-1D (rotation-variant) vs. MLP (rotation-invariant) should align with data's natural orientation (per Grinsztajn et al.).

**Failure signatures:**
- No "spiking" performance in random search budgets, suggesting ICF/LFF discovery fails or neither applies.
- Base ResNet performance severely lags XGBoost, indicating architectural implementation errors (padding, channel handling).
- LFF runs overfit rapidly on small datasets with high `lff_dim`.
- ICF path fails if `chi_thresh`/`ANOVA_thresh` are too strict/lenient, missing true ICFs or creating false positives.

**First 3 experiments:**
1. **ICF-only ablation on `eye_movements`:** Fix router to ICF path. Expect a large performance "spike" over base model, isolating ICF contribution.
2. **`lff_dim` sweep on `year`:** Fix router to LFF path. Vary `M` (32→256). Expect a clear performance peak, confirming capacity tuning necessity.
3. **ICF test threshold sweep on `covertype`:** Vary `chi_thresh` (classif.) across search range. Plot validation accuracy vs. threshold. Expect a sensitive region indicating effective ICF detection.

## Open Questions the Paper Calls Out
- **What dataset properties determine when ICF or LFF preprocessing yields significant gains?** The paper notes substantial performance variation across datasets but does not analyze the determining factors (e.g., feature cardinalities, target complexity, sample size).
- **Can we design more accurate and robust methods for detecting implicitly categorical features?** Current detection relies on simple statistical tests with heuristic thresholds; the authors hope for more advanced, possibly learned, detection methods.
- **Why does the performance gap with XGBoost persist on regression tasks with categorical features despite ICF and LFF?** Results show neural methods still slightly lag on such tasks; the underlying cause (e.g., target distribution, interaction complexity) is not investigated.

## Limitations
- Exact binning strategy (number of bins, method) for ICF statistical tests is unspecified, directly impacting detection reliability.
- Critical ResNet-1D implementation details (padding, channel progression, residual connections) are ambiguous, risking architectural mismatch in reproduction.
- Reliance on the Grinsztajn et al. (2022) benchmark's specific data preprocessing and splits without provided access hinders exact replication.
- Ambiguity in LFF pipeline order (mixing before/after Fourier) and exact dimension handling for `LinearLFF` vs. `Conv1x1LFF`.

## Confidence
- **Mechanism 1 (ICF necessity):** Medium. Strong ablation evidence (XGBoost unaffected by ICF), but confidence tempered by unknown binning strategy.
- **Mechanism 2 (LFF for smoothness bias):** High. Theoretically sound and builds on established Fourier features work; primary risk is implementation error.
- **Mechanism 3 (Synergistic preprocessing):** Medium. Empirical "spikes" and complementary ablations support synergy, but the mutually exclusive random selection may fail for datasets requiring both ICF and LFF simultaneously.
