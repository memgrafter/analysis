# SPARC: Separating Perception And Reasoning Circuits for Test-time Scaling of VLMs

## Quick Facts
- **arXiv ID:** 2602.06566
- **Source URL:** https://arxiv.org/abs/2602.06566
- **Reference count:** 39
- **Primary result:** SPARC improves VQA accuracy by up to 6.7% on V* and 4.6% on OOD remote sensing while using 200× fewer tokens, and matches 30× larger models with only 0.1% token usage on XLRS.

## Executive Summary
SPARC introduces a novel two-stage inference framework for vision-language models (VLMs) that separates perception (visual search) from reasoning to enable robust and efficient test-time scaling. By prompting the VLM to first perform Implicit Relevance Detection (IRD) to localize question-relevant image regions, and then reasoning only over those high-resolution crops, SPARC avoids cascading errors and compresses the visual context. The method supports asymmetric compute allocation: cheap, repeated perception rollouts can be fused via Weighted Box Fusion (WBF) to refine crop selection, while the expensive reasoning step runs only once on a small set of crops. Experiments on Qwen3VL and Molmo2 show significant gains: on V*, SPARC with Qwen3VL-4B improves accuracy by 6.7 percentage points, and with Qwen3VL-8B reaches 91.2%—matching models 30× larger—while processing only 0.1% of visual tokens on the XLRS remote-sensing benchmark. Fine-tuning the perception module at low resolution (256px) further boosts performance, demonstrating the effectiveness of decoupled scaling.

## Method Summary
SPARC processes an image and question in two stages. First, the image is downsampled (e.g., to 256 px) and the VLM is prompted to perform Implicit Relevance Detection (IRD), outputting spatial coordinates (bounding boxes for Qwen, points for Molmo) of regions relevant to answering the question. The perception stage can be repeated multiple times with stochastic decoding to generate diverse crop hypotheses. Next, overlapping boxes from these rollouts are optionally fused using Weighted Box Fusion (WBF) to produce a compact set of high-confidence crops. Each crop is then extracted from the original high-resolution image and resized to a consistent resolution. In the second stage, the VLM is prompted with the global low-resolution image together with all extracted crops to produce the final answer. No parameter updates are needed for the base version; optionally, the perception module can be fine-tuned via LoRA on synthetic IRD data at low resolution to improve localization.

## Key Results
- **+6.7%** accuracy on V* with Qwen3VL-4B over monolithic chain-of-thought.
- **+4.6%** on out-of-distribution remote sensing vs. "thinking with images" while using **200× fewer tokens**.
- **91.2%** on V* with Qwen3VL-8B—matching models **30× larger**—and processes only **0.1%** of visual tokens on XLRS.
- Weighted Box Fusion across up to **8 rollouts** yields up to **9.3%** additional gains.

## Why This Works (Mechanism)

1. **Decoupling Perception and Reasoning**  
   SPARC splits inference into explicit visual search (IRD) followed by reasoning over localized crops. This prevents cascading errors from small perceptual mistakes, as the reasoning step only sees crops that are assumed to contain the relevant evidence. Oracle experiments show that even low-resolution predictions with modest overlap (20%) can surpass full-resolution monolithic models, confirming the reasoning backbone’s competence given correct crops (Section 3.2).

2. **Visual Context Engineering via Crops**  
   Global search runs at low resolution (e.g., 256 px), and only identified regions are extracted at high resolution from the original image. This restores fine-grained details lost in downsampling while drastically reducing token count. On XLRS, SPARC processes approximately 0.1% of visual tokens yet achieves superior accuracy (Section 4.2), demonstrating the efficiency of localized high-resolution processing.

3. **Asymmetric Test-Time Scaling with WBF**  
   Multiple cheap perception rollouts generate diverse crop hypotheses; Weighted Box Fusion merges them into a small, high-confidence set. The expensive reasoning step processes only this refined set, enabling efficient self-consistency. Accuracy increases monotonically with up to 8 rollouts while the average final crop count remains low (~3.3), confirming the scalability of the perception branch (Section 5.2).

## Architecture Onboarding

**Component map**  
Off-the-Shelf VLM → Perception Module (IRD) → (Optional: Weighted Box Fusion Aggregator) → Crop Extractor & Resizer → Reasoning Module. An optional SFT Adapter (LoRA) can be attached to the VLM for perception fine-tuning.

**Critical path**  
1. *Input:* Question + high-resolution image.  
2. *Stage 1 (Perception):* Downsample image to target resolution (e.g., 256 px). Prompt the VLM with the question and downsampled image; parse output to get coordinates. Repeat N times if using WBF.  
3. *Aggregation:* Apply WBF to merge overlapping boxes into a final crop set.  
4. *Crop preparation:* Extract each final crop from the original high-resolution image; resize each crop to a fixed size (e.g., longest side 256 px).  
5. *Stage 2 (Reasoning):* Construct a prompt containing the global low-res image and all crops; prompt the VLM; decode final answer.

**Design tradeoffs**  
- **Resolution choice:** Lower global resolution reduces cost but may harm IRD accuracy; 256 px is found to be a sweet spot where the task remains non‑trivial.  
- **Crop count vs. context:** More crops increase token budget but may capture more relevant context; WBF’s deduplication keeps the count low while preserving coverage.  
- **SFT vs. zero‑shot:** Fine‑tuning the perception module boosts accuracy but requires curated synthetic data and risks overfitting to the teacher distribution.

**Failure signatures**  
- **Perception failure:** IRD outputs coordinates entirely outside the image or irrelevant crops. *Diagnose:* Visualize crops on the image.  
- **Crop‑answer misalignment:** Crop contains the correct object but the reasoning answer is wrong. *Diagnose:* Manually verify crop relevance; may indicate reasoning bottleneck.  
- **WBF over‑merging:** Distinct, non‑overlapping relevant regions are merged into a single large crop, diluting focus. *Diagnose:* Low final crop count when multiple objects are clearly present.  
- **Resolution mismatch:** Crops extracted from the downsampled global image instead of the original. *Diagnose:* Verify crop extraction references the original high‑res image array.

**First 3 experiments**  
1. **Crop Overlap Ablation:** Systematically shift/modulate ground‑truth crops (or use provided annotations) and measure VQA accuracy vs. IoU at global resolutions 256, 512, Full. Expect strong correlation; 256 px with perfect crops should approach Full performance.  
2. **WBF Scaling Test:** Implement N=1,4,8 IRD rollouts (temperature=0.7). Apply WBF (IoU≥0.5). Measure end‑to‑end VQA accuracy and average final crop count. Expect accuracy ↑ with N, crop count ↑ sub‑linearly.  
3. **SFT Training & Transfer:** Perform supervised fine‑tuning (LoRA) of the perception module at 256 px using synthetic data (teacher models as in Section 6.1). Evaluate on V* at 256 px and Full resolution. Expect improved 256 px accuracy and possible transfer to Full.

## Open Questions the Paper Calls Out

**Open Question 1**  
*Question:* Does using a stronger teacher model for generating synthetic perception data improve the fine‑tuned perception module’s performance, particularly for smaller student models?  
*Basis:* The authors attribute the lack of improvement for Molmo2‑4B to a “distillation bottleneck” from using a weak teacher (Molmo2‑8B), hypothesizing a stronger teacher would resolve this.  
*Why unresolved:* This hypothesis is not tested systematically; the relationship between teacher capability and synthetic data quality remains unclear.  
*Resolution:* Generate perception datasets using teachers of varying strengths (e.g., larger models or ensembles) and evaluate downstream VQA accuracy for student models of different scales, measuring correlation between teacher performance and student gains.

**Open Question 2**  
*Question:* Why does training the perception module at low resolution (e.g., 256 px) often outperform full‑resolution training, and is this effect generalizable beyond natural image benchmarks?  
*Basis:* Results show SPARC SFT at 256 px yields higher accuracy than full‑resolution SFT for Qwen3VL across multiple benchmarks, with authors suggesting low‑res acts as a regularizer.  
*Why unresolved:* The regularizer hypothesis is unverified; other factors like overfitting or task‑specific biases may contribute. It is unknown if this holds for domains requiring fine details (e.g., medical imaging) or varied visual styles.  
*Resolution:* Conduct ablation studies varying only training resolution, analyze feature representations (e.g., via probing) for robustness, and test on diverse datasets (e.g., satellite, schematics).

**Open Question 3**  
*Question:* For tasks requiring integrated perception and reasoning—such as relational reasoning or context‑dependent localization—does SPARC’s decoupled pipeline introduce performance limitations compared to monolithic approaches?  
*Basis:* The paper notes IRD is ill‑posed because optimal crops depend on downstream reasoning, implying perception and reasoning can be interdependent. Benchmarks used (e.g., V*) emphasize object localization, not complex integration.  
*Why unresolved:* SPARC’s separation may force premature commitment to crops, losing global context needed for reasoning about relationships or ambiguous scenes. This is not evaluated on tasks where perception must be iterative or globally aware.  
*Resolution:* Evaluate SPARC on benchmarks designed for multi‑hop or relational reasoning (e.g., visual question answering with spatial logic), comparing against “thinking with images” and measuring accuracy drop from crop‑based context loss.

**Open Question 4**  
*Question:* What is the primary factor behind SPARC’s out‑of‑distribution gains on remote sensing data: enhanced perception generalization from training, or computational efficiency from token reduction?  
*Basis:* SPARC low‑res models surpass full‑resolution baselines on XLRS while using ~0.1% of visual tokens, but the paper does not isolate the contribution of perception vs. token efficiency.  
*Why unresolved:* Both improved perception (via SFT) and compressed contexts likely play roles, but their relative importance is unknown. This affects how to optimize for OOD scenarios.  
*Resolution:* Ablate by evaluating perception‑only accuracy (e.g., localization metrics) on OOD data, and separately vary token budgets while fixing perception quality to disentangle effects of perception training and context compression.

## Limitations

- **Generalization:** Claims are validated only on Qwen3VL and Molmo2; decoupling may fail on VLMs with fundamentally different architectures (e.g., late fusion vs. early fusion).
- **Global Context Loss:** The crop‑based approach inherently discards global layout and background context. Performance on tasks requiring whole‑image understanding (e.g., scene classification, global counting) is unknown and likely degraded.
- **SFT Data Dependency:** The strong SFT results (91.2% on V*) rely on synthetic training data distilled from massive teacher models (235B/8B). Replication without these teachers is impossible, limiting accessibility.

## Next Checks

1. **Cross‑VLM Generalization Test:** Implement SPARC on a distinct VLM family (e.g., LLaVA, InternVL). Run the core two‑stage pipeline on V* with greedy decoding. *Expected:* If the decoupling thesis is architecture‑agnostic, accuracy gains over monolithic CoT should persist (>3% improvement). Failure would indicate VLM‑specific circuits.
2. **Global Context Failure Mode Analysis:** Curate a subset of V* or COCO questions where the correct answer requires non‑local context (e.g., “What is on the wall to the left of the door?”). Run SPARC and manually inspect crops. *Expected:* SPARC accuracy should drop significantly vs. monolithic inference; quantify the drop to define the boundary of applicability.
3. **Token Efficiency Profiling:** Instrument the actual inference pipeline to measure total FLOPs and wall‑clock time for SPARC (256 px search + k crops) vs. a naive full‑resolution (e.g., 1024 px) monolithic forward pass on XLRS. *Expected:* SPARC should show >10× reduction in visual token processing FLOPs with minimal accuracy trade‑off. Discrepancy would reveal overheads (e.g., multiple perception passes, crop formatting).
