# DIALECTIC: A Multi-Agent System for Startup Evaluation

## Quick Facts
*   **arXiv ID:** 2603.12274
*   **Source URL:** https://arxiv.org/abs/2603.12274
*   **Reference count:** 40
*   **Primary result:** A multi-agent LLM system matches human VC precision (0.333) and a GPT IO baseline (0.29) on startup success prediction (AUC-PR 0.2422) while generating interpretable investment arguments.

## Executive Summary
Venture capitalists face a bandwidth tradeoff between screening depth and volume in early-stage investing. DIALECTIC addresses this by automating the due diligence process with a structured, multi-agent LLM system. It organizes unstructured startup data into a hierarchical fact base, simulates an investment committee debate to refine pro and contra arguments, and produces a numeric score for ranking. Backtested on 259 real startups, it achieves human-level precision and provides a full precision-recall frontier, allowing investors to flexibly set screening thresholds based on capacity.

## Method Summary
DIALECTIC is a three-phase pipeline. First, a decomposer agent expands four seed questions (general, team, product, market) into an industry-specific hierarchical question tree. An answer agent populates this tree using company data and targeted web searches for leaves, aggregating responses bottom-up to form a structured fact base. Second, generator agents create initial pro and contra arguments from the fact base. These undergo iterative refinement: critics identify flaws, an evaluator scores arguments on a 14-criteria taxonomy, and a refiner improves them; only the top-scoring arguments survive each round. Third, a decision score is computed as the difference between summed pro and contra scores, adjusted by a safety threshold. This score ranks opportunities and enables threshold-based screening without any model training.

## Key Results
*   Achieves an AUC-PR of 0.2422 on a held-out test set of 259 startups.
*   Matatches the precision of human VCs (0.333) and a GPT IO baseline (0.29) at operating points along the precision-recall frontier.
*   Generates interpretable, evidence-backed arguments for due diligence and allows flexible threshold selection for screening.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Structuring unstructured startup data into a hierarchical question tree improves systematic coverage and relevance of facts for evaluation.
*   **Mechanism:** A decomposer expands four seed questions into industry-specific sub-question trees. An answer agent populates this tree using company data and web searches at leaves, aggregating child responses upward to build a dense, organized fact base `F`.
*   **Core assumption:** The hierarchy ensures comprehensive yet tailored fact gathering, reducing missed critical information.
*   **Evidence anchors:** [abstract] "gathers factual knowledge ... and organizes these facts into a hierarchical question tree." [section 3.1] Formal definitions of decomposer `Q` and answer agent `A` with post-order aggregation. [section B.2] Adaptation of ProbTree for VC contexts.
*   **Break condition:** If sub-questions are irrelevant or non-hierarchical for an industry, the fact base becomes noisy/incomplete, degrading downstream arguments.

### Mechanism 2
*   **Claim:** Iterative critique and refinement of pro/contra arguments through simulated debate surfaces a narrow set of high-quality, persuasive points, mimicking investment committee dynamics.
*   **Mechanism:** Generators create `K` initial arguments per stance. Critics act as devil's advocates, generating critiques. An evaluator scores each argument+critisic on 14 criteria. A refiner revises arguments based on scores. A survival-of-the-fittest retains only top `K_t` per iteration, forcing convergence.
*   **Core assumption:** Structured adversarial interaction and quality-directed refinement improve argument cogency more than single-pass generation.
*   **Evidence anchors:** [abstract] "iteratively critiques and refines these arguments through a simulated debate, which surfaces only the most convincing arguments." [section 3.2] Formal definitions for `G`, `C`, `E`, `R` and iterative survivor selection `S_t+1`. [figure 2] Argument quality scores increase from T=0 to T=2.
*   **Break condition:** Inconsistent evaluator scoring or trivial critiques may cause overfitting to artifacts rather than genuine quality, potentially degrading performance after T=2.

### Mechanism 3
*   **Claim:** Aggregating quality scores of final surviving arguments into a decision score (`σ_T = σ⁺_T - σ⁻_T + τ`) enables robust ranking and threshold-based screening, matching human precision.
*   **Mechanism:** The system sums evaluator scores for the final `K_T` pro arguments (`σ⁺_T`) and contra arguments (`σ⁻_T`). The margin, adjusted by `τ`, forms the decision score, providing a full precision-recall frontier via threshold tuning.
*   **Core assumption:** The sum of quality-assessed arguments per stance is a monotonic proxy for investment conviction; the margin separates successful from unsuccessful startups.
*   **Evidence anchors:** [abstract] "produces numeric decision scores that allow investors to rank ... matching the precision of human VCs." [section 3.3] Definition of `σ_T` and decision rule `σ_T > 0`. [figure 4] Successful startups cluster at higher decision scores.
*   **Break condition:** If evaluator criteria poorly correlate with actual success (e.g., overweighting style), the summed score becomes a noisy ranking signal, limiting precision.

## Foundational Learning
*   **Concept: Hierarchical Question Decomposition (ProbTree-inspired)**
    *   Why needed: Transforms broad seed questions into granular, answerable sub-questions tailored to an industry, ensuring a structured, comprehensive fact base.
    *   Quick check: How does a post-order traversal of the question tree enable aggregation of low-level facts into high-level insights?
*   **Concept: Argument Quality Taxonomy (Wachsmuth et al., 2017) adapted to VC context**
    *   Why needed: Provides a multi-dimensional rubric for scoring arguments beyond plausibility, to cogency, credibility, and global sufficiency.
    *   Quick check: Why is "Global Sufficiency" (anticipating counterarguments) particularly critical in a high-stakes, noisy domain like VC?
*   **Concept: Multi-Agent Debate as Convergence Mechanism**
    *   Why needed: Models iterative refinement of investment theses in a committee, using critique and survival-of-the-fittest to filter weak arguments and strengthen strong ones.
    *   Quick check: What is the risk of using a single, static `K_t` (e.g., `K=5` for `t≠T`) across all iterations, and how might it affect debate diversity?

## Architecture Onboarding
*   **Component map:** Decomposer -> Answer Agent -> Fact Base F -> (Generator -> Critic -> Evaluator -> Refiner) x T iterations -> Final Survivors S_T -> Decision Score σ_T -> Rank/Threshold
*   **Critical path:** Company Data -> Decomposer -> Answer Agent -> Fact Base F -> (Generator -> Critic -> Evaluator -> Refiner) × T iterations -> Final Survivors S_T -> Decision Score σ_T -> Rank/Threshold
*   **Design tradeoffs:**
    *   Iteration depth (`T`) vs. computational cost/over-refinement: More iterations improve quality but risk redundancy/drift (AUC-PR drops at T≥3).
    *   Survivor count (`K_t`) vs. diversity/coverage: Larger `K_t` explores more angles but retains lower-quality arguments; smaller values converge faster but may miss valid points.
    *   LLM consistency (temperature 0.0 for Answer, 0.5 for others): Deterministic fact-gathering vs. stochastic argumentation. Tradeoff between reproducibility and creative exploration.
*   **Failure signatures:**
    *   Low average argument quality scores (<50/98 max) after `T` iterations.
    *   Uniform decision score distribution (little separation between success/failure).
    *   High variance in AUC-PR across different `K_T`, `T`, `τ` hyperparameters.
    *   Evidence usage ratios (Table 1) deviating significantly from 1.0 for all aspects, indicating systematic bias in fact utilization (e.g., ignoring market data).
*   **First 3 experiments:**
    1. Hyperparameter sweep on validation set: Vary `T` (0-3) and `K_T` (1-5) to replicate Figure 2, confirming optimal `T=2, K=4` and observing quality/Recall/AUC-PR tradeoff curve.
    2. Evidence utilization audit: For a sample of arguments, trace cited `qa_indices` back to the fact tree. Calculate per-aspect (General, Team, Product, Market) usage ratios as in Table 1. Verify ratios cluster near 1.0; significant deviation indicates a flaw in the generator's fact selection.
    3. Controlled baseline comparison: Run the GPT-IO baseline with the *same* temporally filtered web search results and company summary as DIALECTIC's Answer Agent. This isolates the value of the multi-agent debate structure from raw information advantage.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How does DIALECTIC's performance and argument quality evolve when evaluated over multiple historical data snapshots and longer time horizons?
    *   **Basis in paper:** [explicit] Future Research section: "Evaluating argument-based screening systems across multiple historical data snapshots and longer time horizons would better separate decision-time information from realized outcomes..."
    *   **Why unresolved:** Current backtest uses a single historic Crunchbase snapshot (Jan 2022) and fixed success definition (Series A+ by Sept 2025), limiting understanding of robustness to temporal variations and long-term outcomes.
    *   **What evidence would resolve it:** A longitudinal backtest using sequential snapshots (e.g., quarterly) from the decision date onward, measuring stability of scores/arguments over time and correlating with outcomes beyond Series A.
*   **Open Question 2:** Does moving beyond binary success labels to continuous or multi-dimensional outcome measures improve calibration and utility of decision scores?
    *   **Basis in paper:** [explicit] Future Research: "moving beyond binary success labels toward multi-level, time-dependent, or continuous outcome measures would better capture heterogeneous venture trajectories..."
    *   **Why unresolved:** Success is binary (Series A+ by fixed date), abstracting exit size, IRR, failure modes—critical for VC return modeling.
    *   **What evidence would resolve it:** A study evaluating DIALECTIC against outcomes like valuation multiple at exit, IRR, or survival time, analyzing whether ranking better predicts economic returns or risk-adjusted performance.
*   **Open Question 3:** What specific aspects of the multi-agent debate (e.g., agent role specialization, critique depth, turn structure, stopping criteria) drive improvements in argument quality and predictive performance?
    *   **Basis in paper:** [explicit] Future Research: "deeper analysis of debate dynamics, including agent role diversity, critique depth, turn structure, and stopping criteria, could shift evaluation from aggregate performance toward understanding when and why multi-agent argumentation improves reasoning or fails."
    *   **Why unresolved:** Paper reports aggregate results (AUC-PR) without ablating or analyzing the debate process itself; unclear which components (iterations, critic effectiveness) are most impactful.
    *   **What evidence would resolve it:** Controlled experiments varying one debate parameter at a time (e.g., debate rounds, initial arguments, presence/absence of critic) while measuring changes in argument quality scores, fact utilization, and predictive accuracy.
*   **Open Question 4:** How robust is DIALECTIC's performance and argumentation process to variations in LLM choice, prompting strategies, and the fixed 14-criteria evaluation scheme?
    *   **Basis in paper:** [inferred] Implementation uses a single model (`gpt-5-mini-2025-08-07`) with fixed temperatures and a static 14-question evaluator prompt adapted from Wachsmuth et al. (2017); no sensitivity tests reported.
    *   **Why unresolved:** LLM capabilities/biases vary significantly; argument quality taxonomies and their VC adaptation are assumptions not validated against expert human judgments.
    *   **What evidence would resolve it:** Sensitivity analysis running the full pipeline with multiple LLMs (e.g., Claude, Llama) and alternative evaluator prompts; correlating automatic scores with human expert ratings of argument persuasiveness.

## Limitations
*   Private dataset (259 startups from five VC funds) prevents faithful reproduction; any surrogate risks distribution shift and look-ahead bias.
*   Target LLM (`gpt-5-mini-2025-08-07`) is unavailable; other models may yield different results.
*   Unspecified initial argument count `K₀` (assumed 5) and reliance on a single backtest limit generalizability.

## Confidence
*   Hierarchical fact gathering: Medium (logical design, but no ablation against flat QA).
*   Iterative debate: Medium (quality scores improve over iterations, yet scores may not reflect true strength and lack human validation).
*   Aggregated decision score: Low (depends on private data and unreleased LLM; replication blocked, so external validity highly doubtful).
