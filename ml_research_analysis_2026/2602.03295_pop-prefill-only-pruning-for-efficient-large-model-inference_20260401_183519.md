# POP: Prefill-Only Pruning for Efficient Large Model Inference

## Quick Facts

- **arXiv ID**: 2602.03295
- **Source URL**: https://arxiv.org/abs/2602.03295
- **Reference count**: 38
- **Primary result**: Prefill-Only Pruning achieves up to 1.37× prefill latency speedup on long contexts (2048 tokens) while retaining 97% of GSM8K accuracy on Llama-3.1, outperforming structured pruning baselines and matching unstructured pruning accuracy with better hardware compatibility.

## Executive Summary

Large language model inference suffers from high latency during the prefill stage, especially for long prompts. POP (Prefill-Only Pruning) addresses this by exploiting the inherent asymmetry between prefill (context encoding) and decode (next-token prediction): deep layers are essential for decode but largely redundant for prefill. POP uses a virtual gate mechanism to estimate layer importance separately for each stage, identifies the least important layers for prefill (typically the deepest third), and skips their attention and feed‑forward computations during prefill while preserving their key and value projections to maintain a valid KV cache. A boundary handling strategy ensures the last prompt token is processed by the full model, protecting the first generated token’s accuracy. Evaluations on Llama‑3.1, Qwen3‑VL, and Gemma‑3 show POP reduces Time‑to‑First‑Token by up to 1.37× for 2048‑token contexts with minimal accuracy loss, offering a practical trade‑off for compute‑bound serving scenarios.

## Method Summary

POP consists of an offline calibration phase and an online inference phase. During calibration, the model processes a small set of long‑context samples with virtual gates attached to each layer’s residual branch. Separate gate sets for prefill and decode allow computing the expected squared gradient of the loss with respect to each gate, serving as an importance score for that layer in each stage. Layers with the lowest prefill importance (by default the last third) are selected for pruning. In online inference, for a given prompt of length *N*, tokens 1 to *N*−1 are processed in the prefill stage: for each pruned layer, only the key and value projections are applied and their outputs stored in the KV cache; the attention and feed‑forward blocks are bypassed (identity residual). The final token *x_N* is then processed as the first decode step using the full model, incorporating the KV cache built during prefill. Subsequent decode steps also use the full model. Independent KV projections add negligible overhead (<5%) and ensure the full decode model receives consistent KV states, while boundary handling prevents accuracy degradation at the start of generation.

## Key Results

- Up to **1.37×** reduction in prefill latency (Time‑to‑First‑Token) for 2048‑token contexts across multiple model families.
- Minimal accuracy impact: retains **97%** of GSM8K performance on Llama‑3.1 and comparable scores on other benchmarks (MMLU, HumanEval, etc.).
- Outperforms structured pruning methods (SliceGPT, ShortGPT) which cause catastrophic generation collapse, and matches the accuracy of unstructured pruning (Wanda) while being significantly more hardware‑friendly.

## Why This Works (Mechanism)

**Mechanism 1: Asymmetric Layer Importance**  
POP attaches virtual gates to each layer’s residual path and computes the expected squared gradient of the loss with respect to these gates separately for prefill and decode stages. This yields a per‑layer importance score for each stage. Analysis consistently shows that deeper layers have high decode importance but low prefill importance, meaning they are critical for predicting the next token but largely redundant for encoding the context. Therefore, pruning these deep layers during prefill removes unnecessary computation without harming the decode stage’s accuracy. The core assumption—that the squared gradient reliably estimates layer removal impact—is validated by the observed stability of decode performance. If deep layers were also important for prefill, pruning them would degrade context representation and overall quality.

**Mechanism 2: Independent KV Projections**  
When a layer is pruned during prefill, POP still applies only the key and value linear transformations (W_K, W_V, with layer‑norm and RoPE) to the layer input and stores the results in the KV cache. The attention and feed‑forward blocks are skipped. These independent KV projections generate cache entries that are semantically compatible with the full model’s subsequent attention computations, because the full model expects raw projected keys and values from every layer. The overhead of these projections is minor (<5% of total prefill compute) compared to executing the full layer. Skipping both attention and FFN for pruned layers thus yields substantial speedup while preserving cache integrity; omitting the KV projections would cause decode failure, as confirmed by ablations.

**Mechanism 3: Boundary Handling**  
To prevent error propagation from the pruned prefill into the first generated token, POP shifts the boundary between stages: the prefill processes all prompt tokens except the last one (*x₁:N₋₁*), while the final token *x_N* is processed by the full model as the first decode step. This ensures that the representation used to predict the first new token has passed through every layer, including those pruned during prefill. The assumption is that the first token’s distribution is highly sensitive to the last prompt token’s full processing; without this safeguard, the first‑token accuracy drops sharply. The added cost of one extra full‑model decode step is negligible compared to the prefill savings, especially for long prompts.

## Foundational Learning

**Transformer Inference Stages (Prefill vs. Decode)**  
Why needed here: POP exploits the fundamental asymmetry between the two stages: prefill processes the entire prompt in parallel to build the KV cache, while decode generates tokens autoregressively, combining current token encoding with cached keys/values. This difference in computational patterns and sensitivity to layers underpins POP’s stage‑aware pruning.

**Virtual Gate Importance Estimation**  
Why needed here: POP estimates layer importance without physically removing layers by attaching learnable gate scalars to residual branches. The expected squared gradient of the loss with respect to these gates (under a specific sampling scheme) approximates the impact of setting the gate to zero, i.e., pruning the layer. This efficient estimator enables stage‑specific analysis.

**KV Cache in Autoregressive Generation**  
Why needed here: POP’s independent KV projections must produce cache entries that remain valid for the full decode model. Understanding that the KV cache stores projected keys and values for all previous tokens, which are then attended to by every layer during decode, clarifies why skipping only attention/FFN but not KV projections preserves functionality.

## Architecture Onboarding

**Component map**: Calibration module → Importance analyzer → Pruner → Inference orchestrator, which during execution employs KV projection wrapper and Boundary handler.

**Critical path**:  
*Offline*: Calibrate on a small dataset → compute stage‑specific importance scores → select pruned layers (e.g., last third).  
*Online per request*: Prefill (tokens 1..*N*−1 with pruned layers, using KV projections to fill cache) → Decode start (process token *N* with full model) → Decode loop (autoregressive generation with full model).

**Design tradeoffs**:  
- **Pruning ratio**: Larger ratios increase speedup but risk accuracy drop; 33% was empirically optimal.  
- **Independent KV projections**: Adds ~5% overhead but is essential for cache consistency; omitting them causes decode collapse.  
- **Boundary handling**: Costs one extra full‑model decode step but prevents first‑token quality collapse.  
- **Memory footprint**: Full model weights remain loaded for decode, so peak VRAM unchanged; POP targets compute‑bound prefill latency only.

**Failure signatures**:  
- **Accuracy collapse on generative tasks**: Large drops on GSM8K/HumanEval indicate missing boundary handling or incorrect KV projection handling.  
- **Insufficient speedup on long contexts**: If speedup does not scale with sequence length, pruning may not be applied correctly or boundary overhead may dominate.  
- **Representation mismatch accumulation**: Excessive pruning (>50%) causes sharp accuracy declines, suggesting deep‑layer redundancy has limits.  
- **Cache corruption**: If independent KV projections are omitted (e.g., “w/o Indep. KV Proj.” ablations), decode fails catastrophically because later layers lack proper KV states.

**First 3 experiments**:  
1. **Accuracy benchmarking**: Compare POP against Wanda (unstructured), SliceGPT, and ShortGPT across multiple models and tasks to demonstrate minimal accuracy loss despite larger pruning ratio.  
2. **Prefill latency measurement**: Measure Time‑to‑First‑Token for varying sequence lengths and image resolutions, showing up to 1.37× speedup on long contexts while baselines either fail to speed up (Wanda) or lose accuracy.  
3. **Ablation studies**: Validate design components by removing independent KV projections or boundary handling, and explore pruning ratio sensitivity to confirm the chosen 33% ratio is near‑optimal.

## Open Questions the Paper Calls Out

1. **Memory reduction**: Can POP be modified to reduce peak memory consumption during inference? Currently the full model weights must reside in memory for decode, limiting applicability on memory‑constrained devices. Evidence: The limitations section notes POP does not alleviate peak VRAM usage. Resolution would require designing a variant that offloads pruned layer weights or shares weights between stages.
2. **Disaggregated integration**: How can POP be effectively integrated into disaggregated inference systems where prefill and decode run on separate hardware? Such systems (e.g., DistServe) could benefit from stage‑specific optimizations, but adapting POP involves non‑trivial engineering. Evidence: The paper mentions adaptation efforts are needed.
3. **Complementarity with other techniques**: Does stage‑aware pruning combine safely with other efficiency methods like quantization or sparse attention without compromising accuracy? The conclusion suggests extending stage‑aware optimization beyond pruning, but interactions may cause instability. Evidence: No experiments combining POP with quantization or sparse attention are presented.
4. **Long‑generation quality**: What are the long‑term effects of POP’s boundary handling on generation quality for extremely long outputs (>10k tokens)? The boundary shift ensures the first token uses the full model, but error accumulation over many tokens might degrade coherence. Evidence: The paper only evaluates standard benchmarks, not very long generations.

## Limitations

- **Calibration sensitivity**: Importance scores depend on a small set (200) of long‑context calibration samples; robustness to dataset distribution and context length is unknown.
- **Generality**: Deep‑layer redundancy was observed on three model families (Llama, Qwen, Gemma) but may not generalize to other architectures (e.g., MoE, different normalization or activation functions).
- **Limited speedup**: Acceleration applies only to prefill; decode remains unchanged, and boundary handling adds a full‑model step, so end‑to‑end throughput gains are modest for short prompts and may diminish for highly balanced prefill/decode workloads.
