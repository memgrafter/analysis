# SenseMath: Do LLMs Have Number Sense? Evaluating Shortcut Use, Judgment, and Generation
## Quick Facts
- arXiv ID: 2604.01988
- Source URL: https://arxiv.org/abs/2604.01988
- Reference count: 27
- Primary result: LLMs show limited number sense: they rarely use available numerical shortcuts without explicit prompting, overgeneralize applicability, and fail to generate valid shortcut-admitting problems.

## Executive Summary
SenseMath introduces a benchmark to evaluate whether large language models (LLMs) possess number sense—specifically, the ability to recognize numerical structure and apply shortcuts selectively. The benchmark comprises 4,800 items across eight shortcut categories, with strong, weak, and control variants at four-digit scales. Five OpenAI models were tested on three tasks: Shortcut Use, Applicability Judgment, and Problem Generation. Results indicate that under standard chain-of-thought (CoT) prompting, models use shortcuts in less than 40% of amenable problems; explicit “number sense” prompting raises usage to 68–86% and yields up to a 15% accuracy gain for capable models. However, models exhibit a high YES bias in applicability judgments, failing to discriminate between strong and control items, and problem generation performance is low, with only 2–24% of outputs passing all quality checks. The study concludes that LLMs achieve procedural shortcut execution without structural understanding, revealing a gap in true number sense.

## Method Summary
The authors created the SenseMath benchmark, consisting of 4,800 arithmetic problems designed to test recognition of numerical shortcuts (e.g., numbers with trailing zeros). Each problem falls into one of eight shortcut categories and appears in three variants: a “strong” version where the shortcut is clearly applicable, a “weak” version where it is less obvious, and a “control” version with no shortcut. Problems are scaled to four-digit numbers to increase complexity. Five OpenAI models (including GPT-4o-mini and GPT-4.1-mini) were evaluated on three tasks: (1) Shortcut Use – measuring how often the model applies the shortcut when solving; (2) Applicability Judgment – determining whether the model correctly decides a shortcut applies; (3) Problem Generation – prompting the model to create new problems that admit a specified shortcut. Performance was compared between standard CoT prompting and an explicit “number sense” prompt that encourages shortcut recognition. Evaluation used automatic checks for correctness, validity, and adherence to the shortcut.

## Key Results
- Explicit “number sense” prompting significantly increases shortcut usage (from <40% to 68–86%) and improves accuracy by up to 15% on strong shortcuts for capable models.
- Models overgeneralize shortcuts in applicability judgments, showing a high YES bias; e.g., GPT-4o-mini said YES to 100% of strong but 0% of control items, indicating a failure to discriminate.
- Problem generation is largely unsuccessful: only 2–24% of generated problems pass all six automatic quality checks; the main issue is inability to create valid shortcut-admitting problems.

## Foundational Learning
The study relies on several key concepts:

- **Numerical shortcut recognition**: The core ability to detect exploitable numerical structure (e.g., numbers ending in zero) that simplifies calculation. *Why needed?* To define the specific aspect of number sense under investigation. *Quick check*: Does the model apply the simplification correctly when it is applicable?
- **Chain-of-thought (CoT) prompting**: A technique that elicits intermediate reasoning steps from LLMs. *Why needed?* To encourage transparent problem-solving and allow measurement of shortcut usage. *Quick check*: Does the model produce a coherent reasoning trace that reveals whether it considered the shortcut?
- **Benchmark variants (strong/weak/control)**: Three conditions that systematically vary the presence and salience of a shortcut. *Why needed?* To test whether models can discriminate appropriate from inappropriate shortcut application. *Quick check*: Does the model apply the shortcut more often on strong variants than on weak or control?
- **Number sense prompting**: An explicit instruction encouraging models to look for shortcuts before solving. *Why needed?* To probe whether models can leverage shortcut recognition when directly prompted. *Quick check*: Does the prompt increase both shortcut usage and accuracy compared to standard CoT?

## Architecture Onboarding
The paper does not discuss model architecture or onboarding procedures in detail; models are accessed via black-box APIs. The experimental pipeline can be summarized:

- **Component map**: Prompt -> LLM -> Response -> Automatic Evaluation
- **Critical path**: The model receives a problem and a prompting strategy (CoT or number sense), generates a solution with reasoning, and the response is parsed to determine shortcut usage, correctness, and (for generation) validity.
- **Design tradeoffs**: Using automatic checks enables large-scale evaluation but may miss nuanced errors; black-box models limit insight into internal representations.
- **Failure signatures**: Low shortcut usage under standard CoT, high YES bias in applicability, and poor problem generation quality.
- **First experiments**: (1) Compare shortcut usage between standard CoT and number sense prompting. (2) Test models on strong vs. weak vs. control variants. (3) Evaluate generated problems against six quality criteria.

## Limitations
- Number sense is narrowly defined as shortcut recognition, excluding other facets like estimation or magnitude comparison.
- The benchmark covers only eight shortcut categories and four-digit numbers, limiting generalizability to broader numerical contexts.
- Model selection is restricted to five proprietary OpenAI models, leaving open the behavior of open-source LLMs.

## Confidence
- Shortcut use increases with explicit prompting: High
- Overgeneralization in applicability judgment: Medium
- Problem generation failure: High

## Next Checks
1. Test a diverse set of LLMs, including open-source (e.g., Llama-3, Mistral) on the SenseMath benchmark to assess generalizability of findings.
2. Extend the benchmark to cover additional numerical reasoning tasks (estimation, rounding, fractional comparisons) to evaluate broader number sense.
3. Conduct human evaluation of generated problems to verify the six automatic checks and pinpoint specific failure modes in problem creation.
