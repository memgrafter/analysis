# QueryPlot: Generating Geological Evidence Layers using Natural Language Queries for Mineral Exploration

## Quick Facts
- arXiv ID: 2602.17784
- Source URL: https://arxiv.org/abs/2602.17784
- Reference count: 40
- Primary result: QueryPlot automates mineral prospectivity mapping by generating evidence layers from natural language queries, achieving ~50% recall of known sites with top 10% polygons and up to 77.4% F1 alignment with expert tracts; integration into supervised learning improves balanced accuracy by 5.98% and F1 by 1.43%.

## Executive Summary
QueryPlot is a framework that transforms geological map polygons and deposit model documents into textual descriptions, computes semantic similarity via transformer embeddings, and produces ranked geospatial evidence layers for mineral exploration. In a case study on tungsten skarn deposits in the western United States, the top 10% of ranked polygons captured about 50% of known mineral occurrences, increasing to 90% with a 500 m buffer. The generated layers aligned closely with expert permissive tracts, reaching an F1 score of 77.4%. Furthermore, adding QueryPlot’s contact layer to a supervised geophysical/geochemical classifier boosted balanced accuracy by 5.98% and F1 by 1.43%, demonstrating the complementary value of text-based geological retrieval.

## Method Summary
QueryPlot ingests USGS State Geologic Map (SGMC) polygons and mineral deposit documents. Polygon attributes (e.g., rock types, age) are concatenated into descriptive text; deposit documents are parsed and summarized into structured models using GPT‑4o. Both user queries (derived from deposit models) and polygon descriptions are encoded with a pretrained sentence transformer; cosine similarity ranks polygons by geological relevance. Top‑ranked polygons are buffered, intersected, and buffered again to create evidence layers (e.g., contact zones). The pipeline is deployed via a Streamlit UI and outputs geospatial files. Evaluation against expert permissive tracts and known sites, plus integration into a supervised model, validates the approach.

## Key Results
- Top 10% of ranked polygons captured ~50% of known mineral sites, rising to ~90% with 500 m buffering.
- Evidence layers achieved up to 77.4% F1 when aligned with expert permissive tracts.
- Adding QueryPlot’s contact layer to a supervised geophysical/geochemical model increased balanced accuracy by 5.98% and F1 by 1.43%.

## Why This Works (Mechanism)
### Mechanism 1: Semantic similarity scoring via transformer embeddings
- **Claim:** Semantic similarity scoring via transformer embeddings identifies geologically relevant polygons from textual descriptions.
- **Mechanism:** Polygon attributes are concatenated into textual descriptions. A user query and each polygon description are encoded into dense vectors by a pretrained sentence transformer. Cosine similarity between vectors ranks polygons; top‑ranked ones form an evidence layer.
- **Core assumption:** Geological concepts (e.g., “tonalite”, “limestone”) have consistent semantic representations in the embedding space, such that syntactically different but geologically similar terms yield high similarity.
- **Evidence anchors:** [abstract] “Semantic similarity between queries and polygon descriptions is computed via transformer embeddings, producing ranked geospatial layers.” [section 3.4] Details the embedding function \(M_\theta\), similarity calculation \(s_i = \cos(\mathbf{q}, \mathbf{v}_i)\), and thresholding to select polygons \(P_\tau\).
- **Break condition:** If the embedding model’s training corpus lacks geological terminology, semantic relationships may not be captured, leading to low recall of known sites.

### Mechanism 2: LLM‑summarized deposit models
- **Claim:** LLMs distill lengthy geological documents into concise, structured descriptive deposit models that capture essential deposit‑type characteristics.
- **Mechanism:** Long documents (e.g., Cox & Singer reports) are concatenated, parsed via OCR, and summarized using an LLM (GPT‑4o) with a few‑shot prompt specifying a JSON output (rock types, age range, etc.). The summary serves as a canonical query source.
- **Core assumption:** LLMs can reliably extract and structure key deposit attributes from unstructured text without significant hallucination or omission of critical discriminative features.
- **Evidence anchors:** [abstract] “summarizes deposit models from documents using LLMs.” [section 3.3.2] Describes using GPT‑4o with few‑shot prompts to generate “concise, structured descriptive deposit models.”
- **Break condition:** If source documents are incomplete or the prompt is poorly engineered, the resulting deposit model may miss unique identifying characteristics (e.g., specific alteration minerals), degrading retrieval specificity.

### Mechanism 3: Complementary signal to supervised models
- **Claim:** QueryPlot‑generated evidence layers provide complementary geological signal to traditional geophysical/geochemical layers, improving supervised mineral prospectivity mapping performance.
- **Mechanism:** The continuous similarity scores are rasterized and added as an input channel to a supervised model (e.g., self‑supervised encoder + MLP classifier). The model learns associations between this channel and known deposit locations.
- **Core assumption:** The semantic similarity signal encodes spatially coherent geological favorability not fully represented in standard grids.
- **Evidence anchors:** [abstract] “Integrating QueryPlot layers into supervised learning boosted balanced accuracy by 5.98% and F1 by 1.43%.” [section 4.2] Reports quantitative improvement when adding the contact layer to the GFM4MPM pipeline (Bal. Acc. 72.39 → 78.37, F1 48.97 → 50.40).
- **Break condition:** If the evidence layer is spatially auto‑correlated with existing inputs or contains artifacts, it may add noise, reducing classifier performance.

## Foundational Learning
- **Transformer‑based sentence embeddings**  
  *Why needed:* Maps heterogeneous geological text (queries, polygon descriptions) into a shared vector space where semantic proximity indicates geological similarity.  
  *Quick check:* If two descriptions share key terms (“skarn”, “limestone”) but use different syntax, will a general‑purpose model (e.g., bge‑base) likely assign high cosine similarity? Why?

- **Geospatial polygon operations (dissolve, buffer, intersection)**  
  *Why needed:* SGMC polygons are deduplicated (dissolved), buffered to model contact aureoles, and intersected to combine evidence layers into a final prospective region.  
  *Quick check:* Why buffer *before* intersecting host and source layers for skarn deposits? What geological process does this approximate?

- **Mineral deposit type taxonomy (e.g., CMMI classification)**  
  *Why needed:* Deposit models are tied to specific types; correct selection ensures the query targets the right environment.  
  *Quick check:* For a query “carbonate‑hosted copper”, which deposit model should be used, and what key attribute distinguishes it?

## Architecture Onboarding
**Component map:**  
Data Ingestion → Preprocessing → Embedding Engine → Similarity & Filtering → Layer Composition → UI/Export

**Critical path:** Load & preprocess SGMC → generate/load deposit models → encode polygons → user query → compute similarities → filter & buffer → visualize/export. *Bottleneck:* Embedding all polygons (~7k multi‑polygons) is a one‑time cost; per‑query cost is low.

**Design tradeoffs:**  
- *Resolution vs. Coverage:* Detailed geologic maps improve precision but increase compute time and may reduce coverage if attribution is sparse.  
- *General vs. Domain Embeddings:* Off‑the‑shelf models (BGE, GTE) are easy but may underperform on geological semantics; fine‑tuning requires a large labeled dataset.  
- *Hard vs. Soft Filtering:* The percentile threshold τ is a “soft” semantic filter; adding a hard spatial filter (e.g., tectonic belt) would require extra GIS data.

**Failure signatures:**  
- *Artifacts:* Straight lines along state boundaries indicate unreconciled SGMC data across states.  
- *Low recall:* Known sites fall outside top‑ranked polygons; suspect query terms mismatch map unit nomenclature (e.g., “granite” vs. “quartz monzonite”).  
- *Noise in supervised learning:* Adding QueryPlot layer degrades metrics; suspect spatial autocorrelation with existing inputs or large false‑positive blocs.

**First 3 experiments:**  
1. Replicate tungsten skarn case study: Use provided SGMC subset and deposit model. Generate host/source layers, compute contact layer, compare visually and quantitatively (IOU, F1) against permissive tracts.  
2. Embedding model sensitivity test: Swap between BGE‑base, BGE‑large, GTE‑base on the same query. Plot recall@10% and F1 vs. permissive tracts to validate model choice.  
3. Supervised integration test: Take GFM pipeline, add QueryPlot contact layer as 20th input channel. Re‑train MLP classifier on tungsten skarn sites; verify >1% F1 gain on test set.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can a domain‑specific embedding model for geological language be created and evaluated?  
  *Basis:* The paper explicitly notes the lack of domain‑specific fine‑tuning and reliance on general‑purpose models.  
  *Why unresolved:* No large‑scale, high‑quality geological sentence‑pair datasets with similarity scores exist.  
  *What evidence would resolve it:* A benchmark dataset of annotated geological sentence pairs and a study showing performance gains of a fine‑tuned model.

- **Open Question 2:** What methods can mitigate state‑boundary artifacts in evidence layers caused by the non‑integrated SGMC?  
  *Basis:* The paper identifies straight‑line artifacts along state boundaries due to unreconciled units.  
  *Why unresolved:* No harmonization solutions are proposed or evaluated.  
  *What evidence would resolve it:* Implementations of boundary‑aware aggregation or smoothing techniques demonstrating reduced artifacts without loss of fidelity.

- **Open Question 3:** How can non‑geological factors (economic viability, land access, environmental constraints) be integrated into QueryPlot?  
  *Basis:* The work focuses solely on geological data and algorithms, excluding these factors.  
  *Why unresolved:* The current system only processes geological polygons and deposit models; multi‑criteria integration is unexplored.  
  *What evidence would resolve it:* A modified pipeline that ingests, weights, and fuses socioeconomic/regulatory layers, validated by comparison to known viable projects.

- **Open Question 4:** Can an automated ETL framework handle heterogeneity of diverse geological databases for use in systems like QueryPlot?  
  *Basis:* Data collection and preprocessing required major manual effort; no generalizable tool exists.  
  *Why unresolved:* The paper manually processed SGMC; different databases have varying schemas and formats.  
  *What evidence would resolve it:* An open‑source tool that accepts a new geologic map database, automatically infers a schema for polygon descriptions, and integrates it with minimal configuration.

- **Open Question 5:** To what extent are the performance and optimal hyperparameters transferable across different mineral deposit types?  
  *Basis:* Evaluation was solely on tungsten skarn; models for >120 deposit types were curated but not tested.  
  *Why unresolved:* Deposit models differ in terminology, richness, and spatial scales; optimal thresholds and buffers may vary.  
  *What evidence would resolve it:* A multi‑deposit‑type benchmark (e.g., porphyry copper, MVT lead‑zinc) applying the same or per‑type‑optimized QueryPlot configuration, comparing layer alignment and recall.

## Limitations
- Permissive tracts dataset (Lederer et al., 2021) may be inaccessible, blocking unsupervised F1 validation.
- Exact buffer distances (r1, r2) that achieved 77.4% F1 are unreported; grid‑search ranges are approximate.
- Embedding model choice (BGE vs. GTE variants) is unspecified, risking reproducibility of semantic similarity scores.

## Confidence
- Semantic retrieval (Mechanism 1): **Medium**
- LLM summarization (Mechanism 2): **Low**
- Complementary value (Mechanism 3): **High**

## Next Checks
