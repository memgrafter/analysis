# Multi-view Graph Convolutional Network with Fully Leveraging Consistency via Granular-ball-based Topology Construction, Feature Enhancement and Interactive Fusion

## Quick Facts
- **arXiv ID**: 2603.26729  
- **Source URL**: https://arxiv.org/abs/2603.26729  
- **Reference count**: 40  
- **Primary result**: State-of-the-art accuracy/F1 on 9 datasets, with up to 6.5% absolute ACC improvement on WebKB.

## Executive Summary
The paper introduces MGCN-FLC, a multi‑view graph convolutional network designed to overcome three key limitations of existing GCN‑based multi‑view methods: noisy kNN‑based graph construction, neglect of inter‑feature consistency, and incomplete inter‑view fusion. MGCN-FLC integrates three novel modules: (1) a granular‑ball clustering approach that adaptively constructs high‑homophily topology; (2) a feature enhancement module that captures inter‑feature consistency via similarity matrices and mixed pooling; and (3) an interactive fusion module that explicitly models pairwise view interactions. Evaluated on nine benchmark datasets for semi‑supervised node classification, MGCN‑FLC achieves state‑of‑the‑art accuracy and F1 scores, with improvements of up to 6.5% absolute accuracy over previous methods, and consistently ranks first across diverse data characteristics.

## Method Summary
MGCN-FLC processes multi‑view data where each view provides a distinct feature representation for the same set of nodes. For each view, the topology construction (TC) module first clusters nodes into granular balls (GBs) using an unsupervised splitting criterion (stop when a GB contains ≤ √N nodes). Intra‑GB connections are fully connected to create dense, high‑homophily neighborhoods; inter‑GB connections are formed by linking representative nodes of nearest neighboring GBs. The intra‑ and inter‑adjacency matrices are fused with a learnable weight α and then combined across views to produce a unified adjacency matrix A. The feature enhancement (FE) module computes a normalized feature similarity matrix S = (F^T F) / (||F^T||·||F||), derives similarity features X_s = X·S, concatenates them with original features X, and applies mixed pooling (β max‑pooling + (1−β) average‑pooling) to yield enhanced view‑specific embeddings H^v. The interactive fusion (IF) module aligns these embeddings to a common dimension via a sparse autoencoder. For each view v, it aggregates element‑wise products with every other view v′ to form interaction features C^v = Σ_{v′≠v} (H^v ⊙ H^{v′}). A shared‑weight fully connected layer then fuses all C^v into the final node representation H. A two‑layer GCN consumes A and H to produce predictions via softmax. The entire model is trained end‑to‑end on labeled nodes using cross‑entropy loss.

## Key Results
- State‑of‑the‑art performance on 9 datasets for semi‑supervised node classification.  
- Up to 6.5% absolute accuracy improvement on the WebKB dataset.  
- Consistently top‑ranked across diverse data distributions.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Granular‑ball‑based topology construction yields higher homophily ratios than kNN by adaptively grouping similar nodes and connecting them both within and between groups.  
- **Mechanism:** Unsupervised GB clustering splits nodes until each ball contains ≤ √N nodes. Intra‑GB full connections create dense, high‑homophily neighborhoods. Inter‑GB connections (via nearest neighbor balls) maintain global connectivity. The unified topology A = Σπ^v[αA_inter + (1−α)A_intra] adaptively balances local/global information per view.  
- **Core assumption:** Message passing in GCNs works best when edges connect nodes with similar labels (homophily). Higher homophily ratio → more effective neighbor aggregation.  
- **Evidence anchors:**  
  - [abstract] "granular ball algorithm, which clusters nodes into granular balls with high internal similarity to capture inter‑node consistency"  
  - [section 3.1] "nodes within the same GB demonstrate a high‑level similarity, leading to strong categorical consistency"  
  - [section 4.8.1] ablation shows TC module drop causes severe performance degradation; Fig. 8 shows MGCN‑FLC achieves higher homophily than kNN/GBCM‑GCN baselines  
- **Break condition:** If data distribution is extremely heterogeneous such that no local ball can achieve high purity, GBs may not improve homophily over kNN. The √N splitting parameter may be inappropriate for very small N (< 100).

### Mechanism 2
- **Claim:** Feature enhancement captures inter‑feature consistency by injecting similarity‑based features through mixed pooling, producing richer representations than raw features alone.  
- **Mechanism:** Compute feature similarity matrix S = (F^v)^T F^v / (||(F^v)^T||₂ ||F^v||₂), generate similarity features X_s^v = X^v S, stack X^v ∥ X_s^v, then apply H^v = β·MP(X_input) + (1−β)·AP(X_input). Max pooling extracts salient feature interactions; average pooling preserves global similarity patterns.  
- **Core assumption:** Feature similarity matrices encode meaningful consistency patterns; transforming features via X S and pooling enhances discriminative information.  
- **Evidence anchors:**  
  - [abstract] "feature enhancement module that improves feature representations by capturing inter‑feature consistency"  
  - [section 3.2] "multiplication by S^v … acquire inter‑feature consistency information"  
  - [section 4.8.1] ablating FE yields consistent performance drops (Caltech101‑7: −5.5% ACC), demonstrating its contribution  
- **Break condition:** S = F^T F becomes noisy when d_v ≫ N (high‑dimensional sparse features). The full‑range similarity may incorporate low‑relevance features as noted in conclusion.

### Mechanism 3
- **Claim:** Interactive fusion fully exploits inter‑view consistency through exhaustive pairwise feature interactions, outperforming view‑level fusion or concatenation.  
- **Mechanism:** Align dimensions via sparse autoencoders → compute pairwise interactive features c^{(v,v′)} = H^v ⊙ H^{v′} → aggregate C^v = Σ_{v′≠v} c^{(v,v′)} → fuse with shared weights H = Σ_v σ(C^v ⊙ W_share + b_share). This explicitly models all view pairs.  
- **Core assumption:** Element‑wise products between view‑specific features capture fine‑grained consistency patterns lost in view‑aggregated fusion.  
- **Evidence anchors:**  
  - [abstract] "interactive fusion module that enables each view to deeply interact with all other views, thereby obtaining more comprehensive inter‑view consistency"  
  - [section 3.3] "explicitly and fully leverage inter‑view consistency"  
  - [section 4.8.3] pairwise IF outperforms view‑attention (+18.5% ACC on Caltech101‑7) and view‑shared feature (+27.7% ACC) variants  
- **Break condition:** Computational cost O(V² N d) grows quadratically with views. Assumption fails if some views are highly redundant/noisy; pairwise interactions may add noise rather than signal.

## Foundational Learning

### Concept: Graph homophily ratio
- **Why needed here:** The entire TC module aims to maximize homophily—the proportion of edges connecting nodes with same label—because GCN message passing relies on this assumption. The paper shows MGCN‑FLC achieves higher homophily than kNN/GBCM‑GCN.  
- **Quick check question:** If you construct a graph with low homophily (many edges cross labels), what happens to a standard 2‑layer GCN's ability to propagate label information?

### Concept: Feature similarity matrices
- **Why needed here:** FE module uses S = F^T F normalized to encode pairwise feature relationships. Understanding this matrix operation reveals how inter‑feature consistency is mathematically captured and injected via X S.  
- **Quick check question:** In S = F^T F / (||F^T||·||F||), what geometric interpretation does entry S_{ij} have about features i and j?

### Concept: Sparse autoencoders for dimension alignment
- **Why needed here:** Multi‑view features have different dimensions (d_v). The sparse autoencoder aligns them to a common dimension d while adding regularization to prevent overfitting. Its encoder output O^{L/2,v} is used in IF.  
- **Quick check question:** Why include sparsity regularization (D_KL term) in the autoencoder rather than using a simple linear projection for alignment?

## Architecture Onboarding

### Component map:
1. **Topology Construction (TC):** Input: per‑view features X^v → GB clustering (Algorithm 1) → generate GBs → intra‑GB adjacency A_intra^v (Eq2) → inter‑GB adjacency A_inter^v via representative nodes (Eq4) → fuse A^v = α A_inter^v + (1−α) A_intra^v → unify A = Σ_v π^v A^v  
2. **Feature Enhancement (FE):** Input: X^v → similarity S^v = (F^v)^T F^v / norms → X_s^v = X^v S^v → stack [X^v, X_s^v] → mixed pooling: H^v = β·MP + (1−β)·AP  
3. **Interactive Fusion (IF):** Input: H^v from FE → sparse autoencoder (encoder) → aligned O^{L/2,v} → pairwise products c^{(v,v′)} = O^v ⊙ O^{v′} → aggregate C^v = Σ_{v′≠v} c^{(v,v′)} → shared‑weight fusion: H = Σ_v σ(C^v ⊙ W_share + b_share)  
4. **GCN Classifier:** Inputs: unified topology A (from TC) + combined features H (from IF) → two‑layer GCN (Eq17) → softmax output Z (Eq18)

### Critical path:
Data flow: X^v (all views) → parallel TC (per‑view) → A; parallel FE (per‑view) → H^v → parallel sparse autoencoders → O^v → parallel IF aggregation → C^v → shared fusion → H → GCN → predictions. The TC and FE modules are independent per‑view; IF requires all views’ enhanced features; GCN requires both A and H.

### Design tradeoffs:
- **GB complexity:** GB clustering O(N log m) vs kNN O(N²). GB adapts to local density but adds √N hyperparameter and representative node selection.  
- **Two‑level connections:** Intra‑GB (dense, high homophily) vs inter‑GB (sparse, global). α is learnable; Fig.4 shows both connection types needed (best α ∈ (0,1)).  
- **Mixed pooling:** β balances max‑pooling (salient features) and average‑pooling (global context). Fig.5 shows optimal around β=0.6.  
- **Pairwise interaction:** Captures view‑pair specific consistency but O(V²) cost. V typically small (3‑12 in experiments), so acceptable. Alternative: view‑level attention (cheaper but coarser, Table5 shows worse).

### Failure signatures:
- **TC failure:** If α collapses to 0 or 1 (check training logs), model ignores one connection type. May indicate one ball type creates noise. Solution: add L2 regularization on α or reinitialize.  
- **FE failure:** If β → 0 or 1, mixed pooling degenerates. Check whether similarity matrix S becomes near‑constant (features uncorrelated) → maybe features need normalization.  
- **IF failure:** If shared weight gradients vanish, view interactions may be ignored. Inspect C^v norms—if one view dominates, its features may be too strong; consider normalization before aggregation.  
- **Autoencoder failure:** If reconstruction loss L_sa doesn’t decrease → encoder not learning. Check sparsity parameter ρ; if too extreme, network may fail to learn. Reduce γ weight or increase hidden dimension.

### First 3 experiments:
1. **TC ablation:** Replace GB topology with kNN (optimize k via validation). Measure homophily ratio and ACC drop. Expect: lower homophily, performance drop especially on WebKB (6.5% gap shown in Table3).  
2. **FE ablation:** Remove feature enhancement (use raw X^v instead of H^v). Test across datasets. Expect: consistent ACC drop, largest on Caltech101‑7 (−5.5%), demonstrating inter‑feature consistency importance.  
3. **IF variant test:** Compare pairwise IF against view‑level attention and view‑shared feature baselines from Table5. Run on datasets with complementary views (Caltech101‑7, NUS‑WIDE). Expect: pairwise IF significantly superior.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question:** Does clustering features within each view before computing the inter‑feature similarity matrix mitigate the introduction of low‑relevance features, thereby improving the quality of the enhanced representations, especially for high‑dimensional or sparse data?  
- **Basis in paper:** [explicit] The authors identify in the conclusion that the feature enhancement module's use of "full‑range feature similarity" may introduce low‑relevance information, affecting feature quality. They propose clustering features within a view and computing similarity only intra‑cluster as future work.  
- **Why unresolved:** The current method uses a global, unclustered similarity matrix. The proposed clustered alternative is suggested but not implemented or evaluated, leaving its efficacy and generalizability unknown.  
- **What evidence would resolve it:** An ablation study comparing the original feature enhancement module against a variant that first clusters features (e.g., via k‑means on the feature dimension) and computes similarity matrices only within clusters. Performance should be tested across datasets with varying feature sparsity and dimensionality (e.g., Reuters vs. MNIST).

### Open Question 2
- **Question:** How does the performance and computational efficiency of the interactive fusion module scale as the number of views (V) increases significantly (e.g., V > 20), given its quadratic complexity relative to V?  
- **Basis in paper:** [inferred] The paper's complexity analysis (Section 3.5) shows the interactive fusion module has a term O((V−1) N d), implying quadratic growth with V. The experiments (Section 4) use at most 12 views (ProteinFold). The authors note the number of views is "typically not high," but do not test scalability to high‑view scenarios.  
- **Why unresolved:** The model's practicality for applications with very many views (e.g., multi‑modal data with dozens of sensors or feature extractors) is untested. The quadratic term could become prohibitive.  
- **What evidence would resolve it:** Running MGCN‑FLC on synthetic or real datasets with a controlled, increasing number of views (e.g., by splitting existing views or using multi‑view datasets with >20 views), measuring both accuracy/F1‑score and wall‑clock training time as V grows. A comparison against a linear‑complexity fusion alternative would benchmark scalability.

### Open Question 3
- **Question:** Under what conditions (e.g., based on inter‑view feature similarity or label consistency) does the interactive fusion module provide the most significant benefit over simple fusion strategies (e.g., weighted sum), as suggested by the inconsistent gains observed in the ablation study?  
- **Basis in paper:** [inferred] The ablation of the interactive fusion module (Table 3) shows large accuracy drops on some datasets (e.g., Caltech101‑7, MNIST, ProteinFold) but minimal change on others (e.g., BBCnews, WebKB, NGs). The authors hypothesize this occurs when individual views already have highly similar and powerful classification capabilities, leaving "limited room" for the module.  
- **Why unresolved:** No quantitative analysis links the magnitude of the ablation effect to measurable properties of the multi‑view data (e.g., average pairwise view correlation, homogeneity of per‑view classifier accuracy). The precise conditions triggering the module's value are not formalized.  
- **What evidence would resolve it:** Compute dataset‑level statistics (e.g., mean cosine similarity between view feature matrices after autoencoding, variance in individual view classification accuracy) and correlate them with the performance difference between MGCN‑FLC and its ablated version (MGCN‑FLC^if). A predictive model or threshold for when interactive fusion is essential would clarify its applicability.

### Open Question 4
- **Question:** Is the fixed termination criterion of √N for granular‑ball (GB) splitting optimal for constructing high‑homophily topologies across diverse datasets, or does an adaptive, data‑driven GB size yield better homophily ratios and downstream accuracy?  
- **Basis in paper:** [inferred] The topology construction module uses the unsupervised GB algorithm with a fixed √N split threshold (Algorithm 1). The authors claim this balances size and quantity but cite only the original GB paper [30]. They analyze homophily ratios of resulting topologies (Fig. 8) but do not vary the splitting criterion.  
- **Why unresolved:** The √N criterion is a heuristic. Different datasets may have varying optimal GB sizes depending on cluster density, label distribution, or feature scale. A suboptimal fixed size could limit topology quality.  
- **What evidence would resolve it:** Conduct sensitivity analysis by varying the split threshold (e.g., c·√N for c in [0.5, 2.0]) or using alternative criteria (e.g., based on intra‑GB density or a small validation set). Measure resulting homophily ratios of the topology and final node classification accuracy to identify a superior, potentially adaptive, strategy.

### Open Question 5
- **Question:** Can the proposed MGCN‑FLC framework be effectively extended to extremely large‑scale graphs (e.g., N > 100,000 nodes) without prohibitive computational cost, given its reliance on operations with O(N²) complexity (e.g., full intra‑GB connections, similarity matrix computation)?  
- **Basis in paper:** [inferred] The complexity analysis (Section 3.5) simplifies to O(N D² + N²), dominated by an N² term. The largest dataset in experiments is NUS‑WIDE with N=2400. The runtime comparison (Fig. 9) shows MGCN‑FLC is slower than some baselines, though the authors deem it "acceptable." No experiment approaches large‑scale graph benchmarks (e.g., ogbn‑products with >2M nodes).  
- **Why unresolved:** The N² term suggests poor scalability. The granular‑ball approach reduces connections compared to full graphs but still involves intra‑GB full connections. Performance and feasibility on massive graphs are unverified.  
- **What evidence would resolve it:** Evaluate MGCN‑FLC on standard large‑scale graph node classification datasets (e.g., from Open Graph Benchmark). Implement approximate or sampling strategies for GB construction and similarity computation to reduce complexity, and report accuracy‑efficiency trade‑offs compared to scalable GCN baselines.

## Limitations
- Granular‑ball clustering algorithm details are underspecified, leading to variability in topology quality and reproducibility.  
- Hyperparameter search ranges (α, β, ρ, γ) are not fully described, which may hinder optimal performance and reproducibility.  
- The feature enhancement module may introduce irrelevant information when features are high‑dimensional or sparse; the interactive fusion module has quadratic complexity in the number of views and could become inefficient or noisy with many views.
