# Analyzing Fairness of Neural Network Prediction via Counterfactual Dataset Generation

## Quick Facts
- arXiv ID: 2602.10457
- Source URL: https://arxiv.org/abs/2602.10457
- Reference count: 40
- Primary result: A counterfactual dataset generation method that flips minimal training labels to change a neural network's prediction, achieving 9–22% success on larger datasets—significantly higher than random (2.5–7.5%) and distance-based baselines.

## Executive Summary
This paper presents a novel fairness auditing technique that searches for counterfactual datasets—small modifications to training labels—that cause a neural network to flip its prediction for a specific test input. Unlike input perturbation methods, the approach alters the training data itself, directly probing the effect of label bias. The core method combines a linear regression surrogate (exploiting ReLU networks’ piecewise linearity to approximate the impact of label flips) and neuron activation similarity (to find training examples similar to the test input). Evaluated on seven fairness datasets with over 1100 test cases, the method discovers counterfactual datasets for 9–22% of test inputs on larger datasets, often with just one label flip, and with negligible overhead compared to retraining. The results demonstrate that neural network predictions can be extremely sensitive to tiny label changes, highlighting the importance of such audits for individual fairness.

## Method Summary
Given a test input and a trained model, the algorithm searches for a counterfactual dataset (CFD) within a bias budget *m* (maximum number of label flips) and subject to filtering rules (ϕ, ψ) that preserve dataset properties like protected attribute distributions. To avoid retraining at each step, a linear regression surrogate is trained on the model’s penultimate layer features to predict how label flips affect the test prediction. Candidate flips are selected based on neuron activation similarity between training examples and the test input, focusing changes on relevant examples. The surrogate estimates the effect of each candidate, and the most promising flips are applied; the model is retrained on the modified dataset to verify whether the test prediction flips. The process iterates until a CFD is found or the budget is exhausted.

## Key Results
- Outperforms random and distance-based baselines by 3–5× in success rate (9–22% vs 2.5–7.5%).
- Often requires only a single label flip to change a test prediction (one-shot CFDs).
- Selected training examples for flipping are more representative of the test input than those chosen by baselines.
- Computational overhead is negligible relative to full retraining due to the surrogate‑guided search.

## Why This Works (Mechanism)
The method leverages two properties of ReLU networks: piecewise linearity and meaningful activation spaces. The piecewise linear structure means the network behaves linearly within each region, allowing a linear model trained on penultimate features to accurately approximate the effect of small changes (label flips) on the output locally. Neuron activation similarity, computed from the same penultimate layer, provides a metric for identifying training points that are semantically close to the test input in the model’s representation. By prioritizing flips of similar examples, the search increases the chance of influencing the test decision. The surrogate avoids retraining until verification, making the process efficient while still guaranteeing exactness via final retraining.

## Foundational Learning
- **Counterfactual Fairness**: Requires an individual’s outcome to remain invariant under interventions on protected attributes. Why needed: Motivates generating alternative datasets to test fairness. Quick check: How does counterfactual fairness differ from statistical parity?
- **Piecewise Linear Networks**: ReLU networks partition the input space into polyhedral regions where the function is linear. Why needed: Justifies using a linear surrogate for local approximation. Quick check: How does network depth affect the number of linear regions?
- **Influence Estimation**: Approximating the impact of a training point on model predictions. Why needed: To rank candidate flips without retraining. Quick check: Why are exact influence functions computationally expensive?
- **Activation Similarity**: Using vector of neuron activations as a feature for similarity. Why needed: To select training examples that share internal representations with the test input. Quick check: Why might activation similarity be more meaningful than raw input distance?
- **Bias Budget (*m*)**: Maximum number of training labels permitted to flip. Why needed: Constrains modifications to realistic levels of bias. Quick check: How would increasing *m* affect the difficulty of finding a CFD?

## Architecture Onboarding
**Component Map**  
Input Data -> Feature Extraction (Network) -> Linear Regression Surrogate -> Counterfactual Search (uses Activation Similarity) -> Candidate CFD -> Retrain Model -> Check Prediction Change

**Critical Path**  
1. Compute penultimate layer activations for the test input and all training examples.  
2. Train linear regression surrogate on original training data (features = activations, target = model output).  
3. For each training example, compute activation similarity to test input.  
4. Generate candidate label flips within bias budget *m* and filtering rules, prioritizing by similarity and surrogate‑predicted influence.  
5. Retrain the model on the candidate-modified dataset; evaluate the test prediction.  
6. If the prediction flips, return the CFD; else, iterate with new candidates until budget exhausted.

**Design Tradeoffs**  
- *Heuristic vs. Exhaustive*: The surrogate and similarity guide the search to avoid combinatorial explosion but may miss valid CFDs.  
- *Efficiency vs. Accuracy*: Approximating via surrogate speeds up search but can be inaccurate for label flips far from the original data; retraining ensures correctness but is costly.  
- *Generality vs. Specificity*: The piecewise linear assumption works for ReLU MLPs but may not extend cleanly to other architectures.

**Failure Signatures**  
- Surrogate predictions show low correlation with actual retraining outcomes.  
- Activation similarity yields high‑scoring candidates that never cause a flip, indicating poor alignment with decision boundaries.  
- Search exhausts the bias budget without finding any CFD, suggesting over‑constraining or ineffective heuristics.

**First Three Experiments**  
1. **Replication**: Reproduce the main result on the Adult dataset, verifying success rate and one‑shot CFD frequency.  
2. **Ablation**: Disable the linear regression surrogate or activation similarity individually to quantify each component’s contribution.  
3. **Surrogate Validation**: For a sample of candidate flips, compare surrogate‑predicted changes to actual changes after retraining to assess calibration.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How can we automatically determine suitable filtering rules (ϕ, ψ) and the bias budget (m) for counterfactual dataset generation without requiring extensive domain expertise?
- Basis in paper: [explicit] The authors state: "determining appropriate filtering rules (ϕ and ψ) and bias budget (m) to reflect real-world scenarios for auditing label bias requires domain expertise from the social sciences and is beyond the scope of this paper."
- Why unresolved: The current framework leaves these critical parameters to be manually set, limiting its practical deployment to contexts where social science experts are available. An automated or data-driven approach would make the method more accessible and adaptable.
- What evidence would resolve it: A study proposing a method to infer ϕ and ψ from data properties (e.g., protected attribute distributions, fairness metrics) or from user-defined fairness goals, and a way to calibrate m based on statistical estimates of label noise, evaluated on a variety of fairness datasets to show consistent identification of meaningful CFDs.

### Open Question 2
- Question: Can the proposed counterfactual dataset generation approach be extended to other neural network architectures (e.g., convolutional neural networks, recurrent neural networks, Transformers) and non-ReLU activation functions while maintaining efficiency and effectiveness?
- Basis in paper: [inferred] The methodology relies heavily on the piecewise linearity of ReLU networks; for sigmoid/tanh they use a threshold approximation but do not evaluate it. Moreover, all experiments are on feedforward multi-layer perceptrons.
- Why unresolved: The piecewise linear analysis is key to the linear regression surrogate and neuron activation similarity. For architectures with different connectivity patterns or non-piecewise-linear activations, these heuristics may not hold or may require significant modification.
- What evidence would resolve it: Adaptation of the scoring techniques to other architectures, perhaps by linearizing the network locally (e.g., via first-order Taylor expansion) or using alternative influence estimation methods, followed by experimental validation on standard datasets where those architectures are common (e.g., image classification with CNNs).

### Open Question 3
- Question: Is it possible to avoid full model retraining at each iteration of the counterfactual dataset search, for example by using fine-tuning, weight interpolation, or influence-based approximations, to reduce the computational overhead?
- Basis in paper: [inferred] The algorithm retrains the model from scratch for each candidate dataset; runtime analysis shows retraining dominates. The authors note that influence functions were too expensive, but do not explore approximate updates.
- Why unresolved: Full retraining, even with early stopping, can be prohibitively expensive for large datasets or complex models. An efficient surrogate for the effect of label changes on the prediction could dramatically speed up the process and enable larger-scale audits.
- What evidence would resolve it: Development of a technique that can quickly estimate the new model's prediction for a given test input after label flips without retraining, or a method to update weights in a few steps, with empirical validation showing that the approximate CFD generation remains effective (comparable success rate) while reducing runtime.

### Open Question 4
- Question: What factors in neural network training (e.g., model capacity, regularization, data imbalance) cause individual predictions to be so sensitive to very small label changes (e.g., a single flip), and how can we train models that are more robust to such label bias?
- Basis in paper: [inferred] The results show that flipping just one training label often suffices to change a test prediction (one-shot CFDs), indicating high sensitivity. The paper discusses the implications but does not investigate the root causes or mitigation.
- Why unresolved: Understanding the sources of this sensitivity is crucial for building fairer and more trustworthy models. Without such insights, we lack guidance on designing models that are less vulnerable to dataset bias.
- What evidence would resolve it: An analysis correlating model sensitivity (measured as prevalence of one-shot CFDs) with training hyperparameters and dataset characteristics, and the proposal of training modifications (e.g., robust loss functions, data augmentation, consistency regularization) that reduce sensitivity, demonstrated through experiments showing fewer one-shot CFDs while maintaining accuracy.

## Limitations
- Heuristic components lack theoretical guarantees; their reliability on non-linear models or complex architectures is uncertain.
- Evaluation is limited to seven small tabular datasets, so generalizability to high‑dimensional or unstructured data is unknown.
- The claim of negligible computational overhead is unsupported by quantitative runtime comparisons to full retraining.
