# PSPA-Bench: A Personalized Benchmark for Smartphone GUI Agent

## Quick Facts
- **ArXiv ID:** 2603.29318  
- **Source URL:** https://arxiv.org/abs/2603.29318  
- **Reference count:** 40  
- **Primary result:** State-of-the-art GUI agents perform poorly on personalization tasks; the best model achieves APR 0.695 and PPR 0.621, with persistent memory and reasoning capability being key for long-term adaptation.

## Executive Summary
Current smartphone GUI agent benchmarks fail to evaluate personalization due to sparse user-specific data and binary or fixed-path metrics. PSPA-Bench addresses this by introducing Task Decomposition Graphs (TDGs) to model personalized tasks via universal steps and preference-driven steps. It generates diverse instructions through slot-filling without large user logs and evaluates agents using trace-graph alignment, producing metrics such as APR, PPR, and their incremental variants. Evaluation of 11 agents reveals generally poor performance, with reasoning-oriented models and agents leveraging persistent memory showing better adaptation over time.

## Method Summary
PSPA-Bench constructs TDGs—directed acyclic graphs where nodes are unit instructions labeled as fixed (user-invariant) or flexible (preference-sensitive). Templates derived from TDGs contain parameterized slots corresponding to flexible nodes. Synthetic user profiles define distributions over slot values, combining long-term (stable) and short-term (oscillatory) preferences. Instructions are instantiated by sampling from these distributions. Agents execute tasks on physical smartphones across 22 third-party apps, and their action traces are aligned to TDGs via an LLM-based mapper. The optimal TDG path is selected by maximizing matched nodes, with tie-breaking rules. Metrics include APR (fraction of all nodes completed), PPR (fraction of flexible nodes completed), and incremental variants (e.g., ∆APR) to measure adaptation across repeated tasks.

## Key Results
- The top agent (Mobile-Agent E) achieves APR 0.695 and PPR 0.621, indicating substantial room for improvement.
- Agents with persistent memory (Reflexion, Mobile-Agent V2) exhibit consistent long-term gains in ∆APR and ∆PPR.
- Reasoning-oriented models (e.g., Claude-3.5-Sonnet) outperform general LLMs; perception capability is foundational; reflection combined with long-term memory is critical for personalization.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Task Decomposition Graphs (TDGs) enable explicit modeling of personalized tasks by separating universal steps from preference-driven steps, capturing diverse user workflows within a single representation.  
**Mechanism:** A TDG is a directed acyclic graph where nodes are minimal unit instructions and edges denote execution dependencies. Nodes are labeled as fixed (`U_f`, user-invariant) or flexible (`U_p`, preference-sensitive). Any source-to-sink path defines a valid task completion, allowing multiple execution strategies that differ in flexible node choices.  
**Core assumption:** Personalization primarily affects which flexible nodes are selected and in what order, while fixed nodes remain constant across users for the same high-level task.  
**Evidence anchors:** Abstract and Section 3.1 define TDGs and fixed/flexible nodes; Appendix D.3 validates alignment accuracy.  
**Break condition:** If user preferences involve continuous parameters or complex conditional dependencies not encodable as discrete flexible nodes, the TDG may under-represent valid strategies.

### Mechanism 2
**Claim:** Template-driven instruction generation from TDGs overcomes user data sparsity by producing diverse, realistic personalized instructions without requiring large-scale user logs.  
**Mechanism:** The TDG is converted into a template where flexible nodes become parameterized slots (e.g., `<price_range>`). A user profile `ρ` defines distributions over slot types (long-term logarithmic weights, short-term sinusoidal weights). Instructions are instantiated by sampling slot values from `D_ρ` and filling the template while respecting dependencies.  
**Core assumption:** User preferences can be modeled as distributions over discrete slot values, and these distributions are stable enough to generate coherent instructions mirroring real user behavior.  
**Evidence anchors:** Abstract; Section 3.2 describes template conversion and profile simulation; Appendix C details weight formulations.  
**Break condition:** Mis-specified preference distributions or an inflexible template backbone may yield unrealistic instructions that fail to capture true personalization.

### Mechanism 3
**Claim:** Trace-graph alignment with TDGs yields fine-grained, preference-aware evaluation metrics (APR, PPR, ∆APR, ∆PPR) that measure both immediate execution quality and long-term adaptation.  
**Mechanism:** After agent execution, its action trace `T` is aligned to the TDG via an LLM-based mapper `m: T → U ∪ {∅}`. The optimal path `P*` maximizes matched unit instructions; ties are broken by preferring more flexible nodes, then shorter paths, then earlier matches. APR = completed unit instructions on `P*` / total unit instructions on `P*`. PPR restricts to flexible nodes. Incremental variants compare metrics before and after experience accumulation.  
**Core assumption:** The TDG fully captures all valid execution paths, and the LLM-based alignment accurately maps actions even with deviations.  
**Evidence anchors:** Abstract; Section 3.3 formalizes alignment and metrics; Section D.3 reports 93% alignment accuracy and Cohen’s κ=0.86.  
**Break condition:** Alignment errors (due to ambiguous UI states, OOD actions) or omitted TDG paths compromise metric reliability.

## Architecture Onboarding
**Component map:**  
TDG Constructor → Template Generator → User Profile Simulator → Instruction Instantiation Engine → Agent Execution Environment → Trace Recorder → Trace-Graph Alignment Module → Metrics Calculator → Results Aggregator.  
For long-term adaptation, the cycle repeats with memory-enabled agents and user-specific experience accumulation.

**Critical path:**  
(a) Design scenario → construct TDG → (b) generate template → (c) for each user profile, instantiate instructions → (d) agent executes → (e) trace recorded → (f) align trace to TDG → (g) compute metrics → (h) repeat tasks for long-term adaptation → (i) aggregate and compare agents.

**Design tradeoffs:**  
- Expressiveness vs. Scalability: Richer TDGs capture more personalization nuances but increase alignment complexity and evaluation cost.  
- Automated alignment vs. Human validation: LLM alignment scales but requires human validation; fully automated risks drift.  
- Template diversity vs. control: High slot diversity yields varied instructions but may produce unrealistic combinations; constrained domains trade realism for coverage.  
- Physical devices vs. Simulators: Physical phones add realism (latency, pop-ups) but are slower; simulators offer speed but may miss real-world dynamics.

**Failure signatures:**  
- Low Fleiss’ κ (<0.8) in human validation of alignment → ambiguous TDG or instructions.  
- High variance in APR/PPR across runs for same agent → non-deterministic agent or unstable alignment.  
- Poor correlation (ρ < 0.8) between APR and human ratings → misaligned metrics.  
- Agents with persistent memory show no positive ∆APR → ineffective memory utilization.  
- PPR consistently lower than APR → agent struggles with flexible/preference steps.

**First 3 experiments:**  
1. **Alignment Validation:** Run LLM alignment on 100 human-annotated traces; compute accuracy, precision, recall, F1, Cohen’s κ. Target: ≥0.93 accuracy, κ≥0.86.  
2. **Template Quality Assessment:** Generate instructions via static, random, and dynamic preference models; conduct human evaluation to compute win-rates. Expect dynamic > static > random.  
3. **Agent Benchmarking:** Evaluate 2–3 GUI agents (e.g., LLM+A11y, Mobile-Agent V2, Mobile-Agent E) on 100 tasks from 2 scenarios; compute APR, PPR, CT, CPT. Verify ranking and adaptation trends.

## Open Questions the Paper Calls Out
- How to extend personalized GUI agents to dynamic mobile environments? Current evaluations use static tasks, neglecting real-world UI dynamics.
- How can real user data be used in benchmarks without privacy violations? Synthetic data may not reflect true user diversity; privacy laws restrict user log collection.
- Can Task Decomposition Graphs be automatically constructed for scalable benchmark development? Manual TDG creation limits coverage; automation would require generating correct TDGs from descriptions or demonstrations.

## Limitations
- TDG expressiveness may under-represent preferences involving continuous parameters or complex conditional flows not captured by discrete flexible nodes.
- Template-driven generation relies on synthetic user profiles; unrealistic preference distributions could yield instructions that do not mirror authentic user behavior.
- LLM-based trace-graph alignment accuracy may drift on out-of-distribution agent traces, despite strong reported human agreement.

## Next Checks
1. **Validate TDG coverage:** Compile real-user task traces (from user studies or public logs) and measure the proportion of valid execution paths included in the TDGs.
2. **Stress-test alignment robustness:** Generate agent traces with deliberate deviations (e.g., extra steps, skipped nodes) and evaluate alignment accuracy drop against human annotations.
3. **Human evaluation of template quality:** Replicate the paper’s user study with out-of-sample participants to confirm that dynamically generated instructions are perceived as realistic and personalized.
