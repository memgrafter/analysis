# Agent2Agent Threats in Safety-Critical LLM Assistants: A Human-Centric Taxonomy

## Quick Facts
- **arXiv ID:** 2602.05877
- **Source URL:** https://arxiv.org/abs/2602.05877
- **Reference count:** 27
- **Primary result:** AgentHeLLM framework and open-source tool enable systematic threat modeling for safety-critical LLM agents via a human-centric taxonomy and bi-level graph search.

## Executive Summary
The paper addresses a critical security gap in LLM-based in-vehicle agents: existing frameworks conflate assets (what to protect) with attack paths (how to attack), violating safety-critical engineering principles. The authors introduce AgentHeLLM, a threat modeling framework that enforces separation of concerns. It leverages a human-centric asset taxonomy derived from the Universal Declaration of Human Rights and a formal graph-based attack path model that distinguishes poison paths (malicious data propagation) from trigger paths (activation actions). The framework is realized in an open-source Attack Path Generator that automates multi-stage threat discovery using a bi-level A* and BFS search strategy, enabling systematic enumeration of recursive attack structures inherent to agentic systems.

## Method Summary
The core method comprises two innovations: (1) a human-centric asset taxonomy that categorizes assets based on fundamental human rights, providing a technology-agnostic view of what requires protection; (2) a graph-based attack path model that represents attacks as directed edges, explicitly separating poison edges (malicious data spread) from trigger edges (activation conditions). To automate threat enumeration, the authors built an open-source tool that applies a bi-level search: a high-level A* search plans attack stages, while a low-level BFS exhaustively explores concrete path instantiations within each stage. This approach efficiently navigates the exponential space of multi-stage attacks in LLM agent ecosystems.

## Key Results
- Introduced AgentHeLLM, a threat modeling framework that enforces asset/attack-path separation via a human-centric taxonomy and a formal graph model.
- Released an open-source Attack Path Generator that uses bi-level A*/BFS to automate discovery of recursive multi-stage attack paths.
- Demonstrated systematic enumeration of attack structures in LLM agent systems, highlighting flaws in prior conflation-based approaches.

## Why This Works (Mechanism)
The framework succeeds by explicitly decoupling asset definition from attack-path analysis, aligning with safety-critical engineering tenets. The human-centric taxonomy offers an abstract, rights-based classification that remains independent of implementation details, reducing conflation risks. The graph model captures recursion by treating poison and trigger edges as distinct, enabling the bi-level search to systematically explore both data propagation and activation conditions. The bi-level strategy balances efficiency (A* heuristics guide stage selection) and thoroughness (BFS ensures completeness within stages), making it tractable to uncover complex multi-stage attacks that would evade flat search methods.

## Foundational Learning
- **Human-centric asset taxonomy**  
  *Why needed:* Provides a universal, technology-agnostic asset categorization to avoid mixing assets with attack vectors.  
  *Quick check:* List three asset classes derived from UDHR principles (e.g., privacy, autonomy, safety).
- **Poison vs. Trigger paths**  
  *Why needed:* Separates malicious data ingestion (poison) from activation conditions (trigger), clarifying attack stages.  
  *Quick check:* In a given attack scenario, identify the poison and trigger components.
- **Bi-level search (A* + BFS)**  
  *Why needed:* Efficiently explores combinatorial attack spaces by dividing high-level stage planning (A*) from low-level path expansion (BFS).  
  *Quick check:* Estimate the search space for 10 stages with 5 options each; would pure BFS be feasible?
- **Recursive attack structures**  
  *Why needed:* LLM agents can invoke each other recursively, creating nested attack surfaces; modeling recursion is essential for completeness.  
  *Quick check:* Can an attack path include a step that calls another agent which then calls back? (Yes)

## Architecture Onboarding
**Component map:**  
System Specification -> Asset Taxonomy Module -> Attack Graph Builder (poison/trigger edges) -> Bi-level Search Controller (A* stage planner + BFS path expander) -> Attack Path Enumerator -> Results Output

**Critical path:**  
Input system model → classify assets → construct attack graph → run bi-level search → enumerate and rank attack paths.

**Design tradeoffs:**  
- Separation of concerns vs. modeling overhead: Taxonomy adds clarity but requires manual mapping to technical components.  
- Bi-level efficiency vs. completeness: A* heuristics speed stage selection but may miss optimal paths; BFS ensures thoroughness within stages at higher cost.  
- Human-centric taxonomy vs. domain specificity: Universal rights-based categories may lack granularity for standards like ISO 26262, needing adaptation.

**Failure signatures:**  
- Empty output despite known vulnerabilities (false negatives).  
- Excessive spurious paths (false positives).  
- Performance collapse on large agent networks (high CPU/memory).  
- Inconsistent asset classifications across similar systems.

**First experiments:**  
1. Run AgentHeLLM on a toy in-vehicle agent with 2–3 LLMs and injected vulnerabilities to confirm detection of known patterns (e.g., prompt injection via poisoned navigation data).  
2. Compare generated attack paths against expert analysis to measure recall and precision.  
3. Stress-test with a simulated agent network of 10+ heterogeneous LLMs to evaluate scalability and identify failure thresholds.

## Limitations
- Unproven mapping of human-rights taxonomy to concrete technical assets in automotive safety contexts.  
- Lack of empirical validation for the poison/trigger path separation beyond theoretical modeling.  
- No real-world deployment evidence; scalability of bi-level search for complex agent ecosystems remains untested.

## Confidence
- Framework and tool availability: **High**  
- Conceptual separation of asset vs. attack path: **Medium**  
- Practical utility of human-centric taxonomy: **Low**  
- Discovery of previously unknown recursive threats: **Low**
