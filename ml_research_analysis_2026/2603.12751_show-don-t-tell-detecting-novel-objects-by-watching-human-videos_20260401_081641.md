# Show, Don't Tell: Detecting Novel Objects by Watching Human Videos

## Quick Facts
- **arXiv ID:** 2603.12751
- **Source URL:** https://arxiv.org/abs/2603.12751
- **Reference count:** 40
- **Primary result:** A single human demonstration video can be automatically converted into a labeled dataset to train a lightweight object detector (MOD) that significantly outperforms open-set VLMs on novel object detection and enables efficient robot task execution.

## Executive Summary
We introduce "Show, Don't Tell," a method that enables robots to detect and recognize novel objects shown during human demonstrations without any language prompting. The core contribution is the Salient Objects Dataset Creation (SODC) pipeline, which automatically extracts a labeled dataset from one video by leveraging hand-object interactions as a supervision signal. A fine-tuned Manipulated Objects Detector (MOD) trained on this dataset surpasses state-of-the-art vision-language models in detection accuracy on multiple benchmarks. The full system integrates an LLM for planning, MOD for manipulated object detection, and a VLM for place location detection, resulting in reliable on-robot execution of sorting tasks with novel objects.

## Method Summary
The approach comprises three stages. First, SODC processes a 15‑second RGB demo video: an off‑the‑shelf hand‑object model (HOIST‑Former) segments grasped objects frame‑by‑frame; each mask is tracked forward and backward using a multi‑object tracker (SAMURAI); the resulting mask tracks are converted to bounding boxes and clustered spatially (per frame via DBSCAN with IoU distance) and temporally (across frames via DBSCAN with Jaccard distance) to assign consistent object identities. Second, a lightweight Faster R‑CNN detector (MOD) is fine‑tuned on the automatically generated bounding box dataset using standard losses and augmentations. Third, in the integrated robot system, MOD detects manipulated objects during execution, a VLM identifies place locations, and an LLM translates a sub‑sampled video into a high‑level plan. The pipeline trains MOD in 3‑4 minutes and infers in ~100 ms.

## Key Results
- MOD significantly outperforms VLMs (RexOmni, GroundingDINO, YoloWorld) on detection metrics (mAP, mAR, F1) across In‑House and Meccano datasets, achieving up to 2× higher mAP than RexOmni with human prompts.
- A human prompting study revealed a 43% failure rate for novel objects after five VLM prompt attempts, underscoring the inefficiency that MOD avoids.
- On‑robot deployment on sorting tasks with novel objects resulted in fewer missed detections and object confusions compared to VLM baselines; the system processes a 15‑second video in 4‑7 minutes and executes tasks successfully with limited human intervention.

## Why This Works (Mechanism)
The method succeeds by (1) extracting a clean, instance‑level dataset solely from the human demonstration via hand‑object interaction as a supervision signal; (2) training a specialized, fast detector on that data, thereby bypassing the need for semantic labels or language prompts; and (3) integrating these components into a closed‑loop robot system where the detector's accuracy and speed directly translate to reliable task execution. The hand‑object detector anchors the process to task‑relevant objects, while spatiotemporal clustering aggregates noisy tracks into consistent object instances. This approach trades the broad generalization of VLMs for high precision on the specific objects present in the demo.

## Foundational Learning
- **Hand‑Object Interaction Models (e.g., HOIST‑Former):** Needed to segment grasped objects without class labels; quick check: How does the architecture generalize to arbitrary object shapes while being robust to hand occlusion?
- **Multi‑Object Tracking (e.g., SAMURAI):** Needed to propagate initial grasp masks through the video, creating full object tracks even after release; quick check: How does the tracker maintain identity through temporary occlusions and background clutter?
- **Spatiotemporal Clustering (DBSCAN):** Needed to merge multiple short tracks belonging to the same physical object across space and time; quick check: Why use a two‑stage per‑frame then temporal clustering instead of a single global graph clustering?

## Architecture Onboarding
Component map: Input (RGB demo video) -> SODC (HOIST‑Former → SAMURAI -> BBox conversion -> Spatial DBSCAN -> Temporal DBSCAN) -> MOD Training (Faster R‑CNN finetune) -> Plan Generation (LLM + VLM) -> Execution (Scene Graph -> Skills -> Robot) -> Human Intervention.

Critical path: The SODC pipeline is foundational; its output quality directly determines MOD's performance. SODC runtime (4‑7 min for 15s video) is the longest step. MOD training (3‑4 min) and plan generation occur in parallel.

Design tradeoffs: Speed vs. generalization (MOD is fast but view‑specific); Automation vs. robustness (full automation but relies on hand‑object detector); Instance vs. category recognition (MOD learns exact instances, not semantic classes).

Failure signatures:
- SODC: Poor clustering (too many/few object labels) indicates tracking or clustering errors.
- MOD: High missed detections at novel viewpoints suggest insufficient viewpoint diversity in training data.
- Plan: Incorrect skill sequences from LLM misinterpretation of the demo.
- Execution: Object confusion in scene graph may stem from MOD's low discriminability between similar objects.

Three first experiments:
1. SODC sanity check: Run SODC on a demo with known objects; inspect tracks for completeness and label consistency.
2. MOD vs. VLM comparison: Evaluate MOD and VLM baselines on a held‑out test video; verify MOD's superiority.
3. On‑robot closed‑loop test: Execute a simple sorting task using the full pipeline; measure detection success rate and human interventions.

## Open Questions the Paper Calls Out
1. What specific data augmentation or architectural modifications can most effectively mitigate MOD's overfitting to demonstration viewpoints?
2. To what extent can the SODC pipeline's automatic dataset creation be effectively repurposed for training models on vision tasks beyond object detection, such as instance segmentation or human activity parsing?
3. Can alternative importance signals (e.g., gaze fixation, audio cues) replace hand‑object interactions in the SODC pipeline to include non‑manipulated but task‑critical objects, and does this improve robot task success in scenarios where key objects are not directly manipulated?
4. How sensitive is the end‑to‑end "Show, Don't Tell" system to the choice of in‑hand object detector, and would a more accurate or robust in‑hand detector significantly improve the quality of the SODC‑generated dataset and the final MOD's performance?

## Limitations
- The method assumes all task‑relevant objects are manipulated at least once; untouched objects are not detected.
- Generalization to new viewpoints or scenes is limited because MOD is trained on a single demo; overfitting to that view is a common failure.
- SODC relies on HOIST‑Former's hand‑object segmentation quality, which is noisy and can propagate errors.

## Confidence
- **High:** A single video can be automatically converted into a labeled dataset for instance detection of the shown objects.
- **Medium:** The SODC dataset is clean enough to train a detector that outperforms VLMs on those objects.
- **Low:** The system generalizes robustly to novel scenes, viewpoints, or tasks beyond the demonstrated sorting scenario.
