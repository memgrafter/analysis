# A Multi-Agent Framework for Interpreting Multivariate Physiological Time Series

## Quick Facts
- **arXiv ID:** 2603.04142
- **Source URL:** https://arxiv.org/abs/2603.04142
- **Reference count:** 40
- **Primary result:** Agentic AI's value lies in selective externalization of computation, improving explanations for limited-capability models but degrading them for thinking models, while tool-based computation excels on codifiable metrics.

## Executive Summary
The paper addresses trustworthy AI deployment for interpreting multivariate physiological time series in emergency care, where explanations must align with clinical workflows. It introduces Vivaldi, a role-structured multi-agent system (triage, doctor, consultant, coder, synthesizer) orchestrated by a central manager, contrasting with zero-shot LLM inference. In a clinical pilot with six emergency medicine experts (109 evaluations), agentic pipelines showed model-dependent effects: for non-thinking and medically fine-tuned models, they improved expert-rated explanation justification (+6.9) and relevance (+9.7); for thinking models, they degraded relevance (up to -14) and trust despite better diagnostic precision (ESI F1 +3.6). Explicit tool-based computation via the Coder agent yielded near-perfect performance on codifiable metrics (Shock Index, qSOFA, MAP) but inconsistent gains on subjective targets (pain score, length of stay). Visualization utility increased across models, though chart comprehensibility trade-offs varied. The findings indicate that agentic orchestration’s benefit is selective, primarily aiding models with limited internal reasoning through externalized structure and computation.

## Method Summary
The task was to implement Vivaldi and compare its agentic pipeline against zero-shot LLM inference. Inputs were derived from the MC-MED dataset: per-patient records including demographics, vital signs time series (HR, BP, SpO₂, RR, Temp), past medical history, and medications. The objective was to evaluate explanation quality (expert-rated on six dimensions) and clinical metric accuracy (ESI F1, pain/LOS MAE, deterministic metric F1). The method used frozen LLM backbones across five specialized agents orchestrated by a Vivaldi manager, with shared state via a Shared Memory Buffer. Agents operated sequentially in iterations (max 3) with role-specific prompts; the Coder agent executed Python code in a sandbox for calculations/visualizations. Inference used temperature 0.2 (except Claude 4.5 default 1.0) and structured outputs. Evaluation combined expert ratings and automated surrogate metrics.

## Key Results
- Agentic orchestration improved explanation justification (+6.9 points) and relevance (+9.7 points) for non-thinking and medically fine-tuned models but degraded relevance (up to -14) and trust for thinking models.
- Explicit tool-based computation (Coder agent) achieved near-perfect F1 on codifiable metrics (Shock Index, qSOFA, MAP) with gains from 40.7 to 65.4 for non-thinking models, but showed limited or inconsistent improvements for subjective targets (pain score, length of stay).
- Visualization utility increased across all models, though chart comprehensibility trade-offs varied by model family and agentic configuration.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Agentic orchestration improves explanation quality for models with limited internal reasoning (non-thinking, medically specialized) but degrades it for models with strong internal reasoning (thinking models).
- **Mechanism:** External decomposition and role specialization compensates for missing reasoning capabilities in smaller/less-capable models by providing structure they lack. For thinking models that already perform implicit multi-step reasoning, adding external agentic structure introduces coordination overhead that diffuses attention and reduces focus on salient clinical factors.
- **Core assumption:** Clinical explanation quality depends on matching the reasoning structure to the model's intrinsic capabilities.
- **Evidence anchors:**
  - Abstract: "agentic AI's value lies in the selective externalization of computation and structure rather than as a universal performance enhancer"
  - Section 6, Tables 1–2: Non-thinking models show +6.9–11.2 point gains in relevance/justification; thinking models show −7.1 to −17.2 point losses
- **Break condition:** When the model already has strong zero-shot reasoning (thinking models), the added structure fails to improve and often harms explanation quality.

### Mechanism 2
- **Claim:** Explicit tool-based computation (Coder agent executing Python code) dramatically improves performance on objectively codifiable clinical metrics (Shock Index, qSOFA, MAP) but provides inconsistent or no benefit for subjective clinical judgments.
- **Mechanism:** LLMs have well-documented weaknesses in precise numerical calculation. Delegating deterministic computations to executable code bypasses this limitation. Subjective metrics (pain score, LOS) require contextual clinical reasoning that cannot be reduced to code, so external computation doesn't help.
- **Core assumption:** Some clinical tasks are primarily computational (codifiable) while others require human-like judgment (subjective).
- **Evidence anchors:**
  - Abstract: "near-perfect performance on codifiable metrics... with F1 gains from 40.7 to 65.4 for non-thinking models, but showed limited or inconsistent improvements for subjective targets"
  - Section 6 RQ2, Table 3: Perfect/near-perfect F1 for qSOFA/SI/MAP in agentic mode; pain/LOS show no consistent improvement or worsen
- **Break condition:** For tasks requiring contextual judgment beyond pure calculation (pain, LOS), explicit tool delegation doesn't yield consistent benefits.

### Mechanism 3
- **Claim:** Role-structured agents aligned with clinical workflows improve explanation relevance and justification by matching clinician expectations for how information should be organized and presented.
- **Mechanism:** Multi-agent decomposition mirrors real ED workflows (triage → rounds with iterative hypothesis → curbside consult → quantitative analysis → synthesis). This produces explanations with the right structure, sequence, and role of evidence that clinicians expect, increasing perceived relevance and justification.
- **Core assumption:** Clinician trust and utility judgments are influenced by how well AI outputs match their mental models and workflow patterns.
- **Evidence anchors:**
  - Abstract: "explanations must align with clinical workflows and expert expectations"
  - Section 4: Detailed mapping: Triage (safety baseline), Doctor (iterative workup), Consultant (curbside consult), Coder (lab-like computations), Synthesizer (final note)
- **Break condition:** If the role decomposition doesn't accurately reflect actual clinical workflows or if clinicians prefer different information structures, alignment benefits diminish.

## Foundational Learning

- **Concept: Emergency department clinical reasoning workflow**
  - **Why needed:** The entire agent architecture is designed to mirror how ED teams actually reason through cases (triage first, then attending workup with iterative refinement, peer consultation, targeted calculations, final synthesis).
  - **Quick check:** What are the typical stages of clinical reasoning when an ED physician evaluates a new patient with abnormal vitals?

- **Concept: Deterministic vs. subjective clinical metrics**
  - **Why needed:** Determines what should go in the Coder agent (executable calculations) vs. what remains LLM-driven inference. Critical for Mechanism 2.
  - **Quick check:** For ESI triage level, is there a precise formula or does it require clinical judgment integrating multiple factors?

- **Concept: Model reasoning capability spectrum (thinking vs. non-thinking)**
  - **Why needed:** Explains the model-dependent effects (Mechanism 1). Systems like Claude/Gemini vs Llama/MedGemma behave differently under agentic orchestration.
  - **Quick check:** What characteristics distinguish a "thinking" model (with strong chain-of-thought) from a "non-thinking" one in this study?

## Architecture Onboarding

- **Component map:**
  Vivaldi Orchestrator → Shared Memory Buffer; Triage Agent → Doctor Agent → (loop: Doctor → Consultant → Coder → Doctor) → Synthesizer Agent. All agents read/write via SMB; Coder executes Python in sandbox; Triage generates initial metrics/visuals; Doctor drives iterations; Consultant critiques; Synthesizer produces final report.

- **Critical path:**
  1. SMB populated with patient data → Triage Agent computes metrics/context → SMB updated.
  2. Doctor Agent reads SMB → analysis → writes assessment to SMB.
  3. Consultant Agent reads → critique → SMB.
  4. Doctor prescribes tasks → Coder executes → results/visuals to SMB.
  5. Doctor ranks visuals, checks sufficiency.
  6. If sufficient: Synthesizer reads all → final report; else: repeat from step 2 (max 3 iterations).

- **Design tradeoffs:**
  - Latency vs. quality: Agentic workflows increase latency 5–38× but may improve explanation quality for certain models.
  - Structure vs. flexibility: Role specialization helps weaker models but may constrain thinking models.
  - Explicit vs. implicit computation: Code execution guarantees precision on metrics but may not help subjective judgments.
  - Iteration depth: More rounds improve thoroughness but increase cost/time; capped at 3.

- **Failure signatures:**
  - Syntax failures: Coder Agent generates invalid Python (e.g., ≤ instead of <=), causing retry loops and latency spikes.
  - Model mismatch: Using agentic orchestration with thinking models shows degraded relevance/trust despite improved ESI F1.
  - Workflow drift: Agents requesting unavailable data (labs) or duplicating tasks violates constraints.
  - Context overflow: Doctor's rank-select-prune must limit visuals to top-3; failure causes memory issues.
  - Decision inconsistency: Synthesizer overriding Doctor's ESI/pain/LOS estimates (prevented by prompt constraints).

- **First 3 experiments:**
  1. Zero-shot vs. agentic comparison: Same model families evaluated on identical patient cases; measure expert-rated dimensions (factuality, relevance, justification, trust, utility, clarity).
  2. Codifiable metric benchmark: Test shock index, qSOFA, MAP with/without Coder agent to isolate effect of explicit tool use.
  3. Model stratification analysis: Aggregate results by thinking/non-thinking model classes to validate Mechanism 1; also test medically fine-tuned (MedGemma) vs general models.

## Limitations
- Dataset access and expert evaluation replication are infeasible without original resources; surrogate metrics may not capture nuanced clinical judgment.
- Model equivalence is uncertain due to ambiguous proprietary model names (GPT-5.2, Claude 4.5); using close APIs introduces unknown variance.
- Neighboring literature provides limited direct support for agentic orchestration effects; most focuses on time-series analysis.

## Confidence
- **Tool-use on codifiable metrics:** High (consistent near-perfect F1 gains).
- **Workflow alignment benefit:** Medium (detailed architecture but limited external validation).
- **Model-dependent orchestration effects (degradation for thinking models):** Low (intriguing but post-hoc model class definitions; no corroborating corpus).
