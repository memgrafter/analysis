# A Picture of Agentic Search
## Quick Facts
- arXiv ID: 2602.17518
- Source URL: https://arxiv.org/abs/2602.17518
- Reference count: 40
- Primary result: Agentic RAG systems generate cleaner, less diverse queries and exhibit higher duplication and termination rates; ASQ dataset and logging toolkit released.

## Executive Summary
The paper introduces a methodology to capture complete interaction traces from agentic Retrieval-Augmented Generation (RAG) systems and releases the Agentic Search Queryset (ASQ). ASQ spans three datasets (HotpotQA, Researchy Questions, MS MARCO) and evaluates three agents with two retrievers, yielding thousands of query-document-thought sequences. Analysis reveals that agentic searchers issue many more queries, produce longer traces, and behave differently from humans: they duplicate queries more often and terminate sessions more frequently, while repeating queries less. Moreover, synthetic queries contain fewer spelling errors and lower lexical diversity, implying that IR systems must adapt caching and pre-processing strategies for agent-driven workloads.

## Method Summary
The authors built a logging framework that intercepts an agent's decoding loop and retriever calls without modifying the agent's core logic. Using parseable control tags (e.g., `<search>`, ``, `<answer>`), each iteration is extracted into a frame containing the synthetic query, retrieved document IDs, and any reasoning thoughts. Frames are stored in sharded TSV files per query, forming an end-to-end trace. The system was applied to three agents (Search-R1 variants and AutoRefine) on three benchmark datasets, using BM25 and a cross-encoder reranker. The dataset (ASQ) and toolkit are publicly released to enable further study of agentic search behavior.

## Key Results
- Agents issue up to 265% more searches than smaller models; traces reach up to 186 iterations.
- Compared to human sessions, agents show higher probabilities of query duplication (DUP) and session termination (OUT), and lower repetition (REP).
- Synthetic queries have significantly fewer spelling errors (5% vs 16%) and lower hapax legomena (21-43% vs 62-78%), indicating cleaner and more repetitive term usage.

## Why This Works (Mechanism)
**Mechanism 1**  
*Claim:* The trace logging methodology captures complete agentic search trajectories without altering agent behaviour.  
*Mechanism:* During decoding, control tags are parsed via regex and retriever calls are intercepted. Each iteration logs a frame (query, doc IDs, thoughts) to storage.  
*Core assumption:* Agents use consistent, parseable control tags and expose retriever calls at a hookable point.  
*Evidence:* [abstract] introduces methodology; [section 4.2] details iterative extraction, interception, error handling; neighbouring papers (Search-R1, AutoRefine) confirm tag usage.  
*Break condition:* Adoption of opaque APIs or tag syntax changes would break regex parsing; non-interceptable retrievers would yield incomplete data.

**Mechanism 2**  
*Claim:* ASQ reveals fundamental differences in agentic vs human query reformulation patterns, captured via Markov transition probabilities.  
*Mechanism:* Queries are mapped to states (IN, ADD, REM, DUP, REP, CH, OUT). Transition matrices across all traces show agents have higher DUP/OUT and lower REP than humans, indicating more looping and termination.  
*Core assumption:* The state model adequately captures behavior and the human baseline (Pass et al.) is comparable.  
*Evidence:* [section 6.2] presents transition matrices; [section 6.3] shows within-trace evolution; [abstract] summarises differences.  
*Break condition:* Misclassification of states or baseline mismatch could create artifacts.

**Mechanism 3**  
*Claim:* Lexical and statistical differences between synthetic and organic queries suggest that IR systems need adaptations (e.g., re-evaluating pre-processing and caching).  
*Mechanism:* ASQ shows synthetic queries have fewer spelling errors (5% vs 16%) and lower hapax legomena (21-43% vs 62-78%). High within-trace query similarity (Jaccard 35-83%) boosts semantic caching potential, while low exact-match repetition reduces traditional caching utility.  
*Core assumption:* ASQ characteristics are predictive of future agentic workloads.  
*Evidence:* [section 7] discusses implications; [abstract] states query differences; [section 6.1] notes comparable query lengths.  
*Break condition:* If agents become more human-like in errors or diversity, suggested adaptations may be unnecessary.

## Architecture Onboarding
**Component map:**  
Agent (LLM) -> emits control tags; Retriever (BM25, MonoElectra) -> returns ranked doc IDs; Logger -> intercepts decoding and retriever, parses tags, writes frames; Storage -> sharded TSV files per query (answers, synthetic_queries, thoughts, ranked_lists).

**Critical path:**  
1. User query `q0` embedded in agent prompt.  
2. Agent begins decoding; logger monitors token stream.  
3. On `<search>` tag, extract query, call retriever, intercept doc IDs.  
4. Log query and doc IDs to current frame.  
5. On ` or `<refine>`, log text.  
6. On `<answer>`, log answer and end trace.  
7. After each iteration, append frame to TSV files identified by `qid` and iteration number.

**Design tradeoffs:**  
- Interception vs post-hoc: Interception captures incomplete runs but needs agent-specific hooks; post-hoc parsing is simpler but may lose early exits.  
- Sharded TSV: Enables selective access but creates many small files; compression adds I/O overhead.  
- Regex parsing: Flexible for new agents but fragile to syntax changes; grammar-based parsers would be more robust.

**Failure signatures:**  
- Missing or out-of-order iteration numbers.  
- Empty or malformed query/doc fields.  
- Absence of answer file (incomplete run).  
- Regex parse failures leading to early exit.

**First 3 experiments:**  
1. Load a complete trace and verify frame count matches reported length; each frame contains query and ranked list.  
2. Recompute DUP/REP/OUT statistics for one agent/dataset and compare to paper values (e.g., Table 2).  
3. Simulate caching: for a trace, compute exact-match vs semantic (Jaccard-based) hit rates.

## Open Questions the Paper Calls Out
**Open Question 1**  
- *Question:* How can we create relevance judgments for sub-queries generated by agentic RAG systems to evaluate intermediate retrieval steps?  
- *Basis:* [explicit] "we do not provide relevance judgments for sub-queries, limiting the ability to evaluate intermediate retrievals."  
- *Why unresolved:* Sub-queries are dynamic and ambiguous; human judgment at scale is costly and potentially inconsistent.  
- *What evidence would resolve it:* A scalable, reliable methodology for sub-query judgment collection or an automatic proxy validated against end-task performance.

**Open Question 2**  
- *Question:* How can datasets of agentic search behavior be maintained over time despite the rapid release of new agent architectures?  
- *Basis:* [explicit] "Frequent releases of new agents make ASQ susceptible to inherent staleness."  
- *Why unresolved:* Each agent may use different control tags, reasoning structures, and actions, requiring custom interception; the pace of innovation outpaces manual updates.  
- *What evidence would resolve it:* An extensible logging framework that automatically adapts to novel agent designs (e.g., schema inference or standardized APIs), validated on several recent agents with minimal manual effort.

**Open Question 3**  
- *Question:* Without production logs, how can we understand the long-tail distribution of agent-generated queries for system provisioning and caching?  
- *Basis:* [explicit] "Since organic, full-scale, production logs are publicly unavailable, we ground ASQ on query sets sampled from existing benchmarks. While this prevents the study query frequency and long-tail distributions..."  
- *Why unresolved:* Benchmark queries are a non-random sample and likely miss rare or emerging patterns; the long-tail is critical for capacity planning.  
- *What evidence would resolve it:* A generative model of agentic query streams that reproduces long-tail statistics from partial logs, or a method to extrapolate from benchmark data using behavior patterns, validated against held-out scenarios.

## Limitations
- The logging methodology depends on stable XML-style tags and interceptable retrievers; changes could cause parsing failures.
- The Markov state model may misclassify reformulation behaviors, potentially distorting observed differences.
- Human baseline comparison may not be directly comparable across tasks and interfaces.
- Findings are based on only three agents and two retrievers; generalisability to other setups is uncertain.
- Query lexical characteristics may evolve, reducing relevance of suggested IR adaptations.

## Confidence
- Logging methodology validity: **Medium-High**  
- Behavioral divergence (DUP/OUT/REP): **Medium**
