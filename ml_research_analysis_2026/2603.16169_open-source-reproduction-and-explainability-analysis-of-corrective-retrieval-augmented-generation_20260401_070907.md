# Open-Source Reproduction and Explainability Analysis of Corrective Retrieval Augmented Generation

## Quick Facts
*   **arXiv ID:** 2603.16169
*   **Source URL:** https://arxiv.org/abs/2603.16169
*   **Reference count:** 11
*   **Primary result:** An open-source CRAG pipeline using Wikipedia API and Phi-3-mini matches original PopQA accuracy (54.4% vs. 54.9%) and shows the T5 evaluator relies on named entity alignment, not semantic relevance.

## Executive Summary
This work reproduces the Corrective Retrieval Augmented Generation (CRAG) system using only free and open-source components, replacing the proprietary Google Search API and closed LLaMA-2 model with a Wikipedia retrieval pipeline and Phi-3-mini. The open-source implementation achieves nearly identical performance on the PopQA benchmark and a modest improvement over a vanilla RAG baseline on ARC-Challenge. Furthermore, a SHAP-based explainability analysis reveals that the T5 retrieval evaluator, a core component of CRAG, predominantly uses shallow lexical matching of named entities rather than deeper semantic understanding to score document relevance, identifying key failure modes such as poor generalization to science questions and low accuracy for rare entity types.

## Method Summary
The reproduction substitutes the original system’s proprietary and closed components with open-source alternatives while preserving the core CRAG workflow. The Google Search API is replaced by a deterministic, four-stage Wikipedia retrieval pipeline (direct page lookup, typed suffix guess, search API, disambiguation resolution). The LLaMA-2 generator is replaced with Phi-3-mini-4k-instruct. The original fine-tuned T5-large checkpoint is retained as the retrieval evaluator, with its fixed score thresholds (τ⁺=0.59, τ⁻=-0.99) governing the Correct/Ambiguous/Incorrect actions. Knowledge refinement for the Correct action (decompose, re-score, discard poor strips) is implemented as described. The system’s performance is evaluated on PopQA and ARC-Challenge, and a SHAP analysis is conducted on the T5 evaluator to interpret its decision-making.

## Key Results
*   The open-source pipeline achieves comparable performance on PopQA (54.4% accuracy vs. original 54.9%) and 85.2% on ARC-Challenge, slightly exceeding a vanilla RAG baseline (84.8%).
*   SHAP analysis shows the T5 evaluator’s relevance scores are overwhelmingly driven by matching named entities between the question and document, functioning primarily as an entity alignment detector.
*   The Wikipedia fallback pipeline yields an 82.3% hit rate on PopQA Ambiguous questions, but the evaluator exhibits failure modes including low accuracy on science questions (ARC-Challenge) and question types dominated by Ambiguous actions (e.g., author, director).

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** System performance remains comparable when proprietary components (Google Search API, LLaMA-2) are replaced with open-source/free alternatives (Wikipedia API, Phi-3-mini).  
**Mechanism:** The CRAG workflow—retrieve → evaluate → correct—does not depend on the specific backend, only on functional outputs (relevant documents, coherent text). The T5 evaluator’s decisions and decomposition/recomposition logic are preserved.  
**Core assumption:** Replacement components provide sufficiently similar functional outputs despite architectural and training data differences.  
**Evidence anchors:** Near-identical PopQA accuracy (54.4% vs. 54.9%) and competitive ARC-Challenge result (85.2% vs. 84.8% RAG baseline).  
**Break condition:** If replacement outputs diverge significantly (e.g., Wikipedia’s entity-focused corpus vs. web index; Phi-3’s parameter space vs. LLaMA-2), the evaluator’s thresholds or generator’s prompt responsiveness may fail, causing performance collapse.

### Mechanism 2
**Claim:** The T5 retrieval evaluator primarily learns a shallow lexical/entity alignment heuristic rather than deep semantic relevance, explaining its failure modes.  
**Mechanism:** SHAP attributions show the model’s score is driven by matching named entities (person, place, title) between question and document. This creates brittleness: high scores when entities match, low scores when they don’t, regardless of whether the document’s content answers the question.  
**Core assumption:** Token-level SHAP reliably surfaces the features the model uses, and patterns generalize beyond the small qualitative sample.  
**Evidence anchors:** SHAP examples: “Henry” token contributes +0.150 in a correct match, -0.280 in an irrelevant doc; “Titan” subword gets negative attribution for a “Titanic” question. Per-question-type analysis shows low accuracy for “Ambiguous-dominant” types (author, director, genre) where entity names are less predictive of answer content.  
**Break condition:** This heuristic fails for questions where the answer is not the named entity in the question (e.g., “Who directed Titanic?” → “James Cameron”), or documents containing the correct entity in an irrelevant context, or domains (science) with different question structures.

### Mechanism 3
**Claim:** The Wikipedia fallback pipeline for the Ambiguous/Incorrect actions provides a free but incomplete substitute for commercial web search, with coverage gaps directly impacting performance.  
**Mechanism:** A deterministic, multi-stage lookup (direct page → typed suffix → search API → disambiguation) maximizes the chance of finding a relevant Wikipedia article. Its 82.3% hit rate on PopQA Ambiguous questions is sufficient to maintain performance, but the 17.7% failure rate means some queries receive no external context.  
**Core assumption:** Wikipedia’s entity-centric knowledge base is sufficiently comprehensive for the entity-centric PopQA dataset, and the multi-stage heuristic reliably resolves the correct article when it exists.  
**Evidence anchors:** Pipeline description and reported 82.3% hit rate on PopQA Ambiguous questions. Low accuracy on author/composer/director types (22–32%) suggests even with Wikipedia fallback, retrieved content may be insufficient or evaluator misclassifies.  
**Break condition:** For entity types or domains with poor Wikipedia coverage (e.g., very recent events, niche pop culture, highly technical science), the hit rate drops below a viable threshold, causing Ambiguous/Incorrect actions to default to generator parametric knowledge alone, degrading accuracy.

## Architecture Onboarding
Component map: Query → Entity Extractor → Retriever (Contriever) → T5 Evaluator → Action Decision → [Correct: Knowledge Refinement → Generator] or [Ambiguous/Incorrect: Wikipedia Fallback → Generator]

Critical path: The evaluator is the central decision point. Its score on the original retrieval dictates the entire subsequent path: a high score triggers refinement and generation with refined context; a low/medium score triggers the Wikipedia fallback and generation with that context.

Design tradeoffs:
*   Wikipedia vs. Web Search: Wikipedia offers free, structured, high-precision knowledge but limited scope and coverage gaps; Google Search provides breadth but is costly and noisy.
*   Fixed T5 thresholds vs. Adaptive: Using fixed thresholds from PopQA is simple but suboptimal for other datasets (e.g., ARC-Challenge); per-dataset tuning would improve performance but requires validation data.
*   Phi-3-mini vs. LLaMA-2: Phi-3-mini is smaller, open, and strong on science (helping ARC), but may have different knowledge cutoffs or stylistic biases; comparison is confounded by different model families.

Failure signatures:
*   High Ambiguous action rate (>80%) on a dataset suggests the T5 evaluator is out-of-distribution and rarely finds a “clearly correct” document.
*   Low Ambiguous accuracy even with Wikipedia fallback (<30%) indicates either Wikipedia retrieval failed, retrieved articles are irrelevant, or the generator cannot extract the answer.
*   Low Correct accuracy on specific question types (e.g., Religion at 5%) signals that “relevant” documents per T5 do not contain the answer entity.
*   SHAP shows strong negative attribution on the question’s main entity token for a Correct action; indicates evaluator failure.

First 3 experiments:
1.  **Reproduce Baselines:** Run Vanilla RAG (top-1 Contriever doc → generator) and CRAG (full pipeline) on PopQA long-tail subset. Verify ~51.4% (RAG) and ~54.4% (CRAG) to confirm pipeline functionality.
2.  **Action Distribution Sanity Check:** On PopQA, compute the percentage of Correct/Ambiguous/Incorrect actions. Expect ~54% Correct, ~27% Ambiguous, ~18% Incorrect. Large deviation indicates T5 scoring or threshold issues.
3.  **Wikipedia Fallback Hit Rate:** For all queries triggering Ambiguous/Incorrect, log whether the Wikipedia pipeline returned a non-empty document. Calculate the hit rate; expect ~82% on PopQA Ambiguous questions. A much lower rate suggests a bug in the pipeline.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can the T5 evaluator be fine-tuned to improve generalization across diverse question types beyond biographical entities?  
  *Basis:* The authors state future work should fine-tune on more diverse question types. The current evaluator, trained on PopQA, is biased toward entity-centric questions, leading to poor out-of-domain performance (e.g., 88.3% Ambiguous on ARC-Challenge).  
  *Why unresolved:* Without generalization, CRAG’s correction mechanism fails in many contexts.  
  *What evidence would resolve it:* Construct a fine-tuning dataset with diverse question types and evaluate the fine-tuned evaluator on held-out domains (e.g., ARC-Challenge), expecting reduced Ambiguous rates and improved overall accuracy.
*   **Open Question 2:** What lightweight, free alternatives to commercial web search APIs can provide higher coverage than Wikipedia for the Incorrect and Ambiguous actions?  
  *Basis:* The authors call for investigating lightweight alternatives that provide higher coverage than Wikipedia alone. Wikipedia’s hit rate is 82.3% on PopQA Ambiguous, leaving 17.7% uncovered.  
  *Why unresolved:* The Wikipedia pipeline leaves a significant fraction of queries without external context, limiting CRAG’s ability to correct poor retrievals.  
  *What evidence would resolve it:* Systematically evaluate candidate open knowledge sources (e.g., DBpedia, Wikidata, Common Crawl snippets, open web search engines) on the same Ambiguous set. Compare hit rates and downstream CRAG accuracy; a successful alternative must significantly exceed Wikipedia’s coverage while remaining lightweight and free.
*   **Open Question 3:** How can SHAP-based explainability for the T5 evaluator be scaled to statistically robust levels while preserving interpretability?  
  *Basis:* The authors note future work should conduct larger-scale SHAP analysis with statistical validation across 50 or more samples per action type; their current analysis uses only 9 samples.  
  *Why unresolved:* The SHAP findings are anecdotal; without statistical validation, conclusions may not generalize, and deeper insights remain elusive.  
  *What evidence would resolve it:* Compute SHAP for a large random sample (e.g., 100–200 per action type). Aggregate attributions by token categories and compute statistical metrics (means, confidence intervals). Develop summarization techniques (e.g., clustering of attribution patterns) to handle large-scale results.

## Limitations
*   The exact source and licensing for the original fine-tuned T5-large evaluator checkpoint are unspecified, a critical dependency for faithful reproduction.
*   The operational definition of the Wikipedia pipeline’s “hit rate” (82.3% on PopQA Ambiguous) is ambiguous (e.g., “contains answer entity” vs. “returns any non-empty result”), hindering accurate benchmarking.
*   The SHAP analysis is based on a very small sample (9), so the claim that the evaluator primarily uses entity alignment lacks statistical generalizability.

## Confidence
*   **Open-source replacement parity:** High – supported by direct, near-identical accuracy numbers on PopQA and a competitive result on ARC-Challenge.
*   **T5 evaluator’s entity bias:** Medium – SHAP examples are compelling but limited; per-question-type accuracy drop provides correlative but not causative evidence.
*   **Wikipedia fallback coverage:** Medium – stated hit rate is key but its undefined criteria and acknowledged 17.7% failure gap leave precise impact uncertain.

## Next Checks

2.  **Define & recompute Wikipedia hit rate:** Establish a clear success criterion (e.g., retrieved text must contain the gold answer entity). Apply the 4-stage pipeline to the Ambiguous subset and recompute the hit rate; compare to the reported 82.3% to assess implementation fidelity.
