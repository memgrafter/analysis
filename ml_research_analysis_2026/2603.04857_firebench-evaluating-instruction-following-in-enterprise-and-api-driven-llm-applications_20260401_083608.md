# FireBench: Evaluating Instruction Following in Enterprise and API-Driven LLM Applications

## Quick Facts
- **arXiv ID:** 2603.04857
- **Source URL:** https://arxiv.org/abs/2603.04857
- **Reference count:** 11
- **Primary result:** The top model (DeepSeek-V3.1) achieves only 74.0% overall instruction-following accuracy, with no model exceeding 75% on enterprise-critical dimensions.

## Executive Summary
FireBench introduces a benchmark to evaluate large language models on instruction-following tasks critical for enterprise and API-driven applications, where outputs must adhere to strict formats, procedural sequences, and content constraints. Built from 2,470 real-world samples, it defines six verifiable capability dimensions: output format compliance, ordered responses, item ranking, overconfidence, positive content requirements, and negative content requirements. Evaluation of 11 LLMs reveals that precise instruction following remains a significant challenge, with top scores below 75% and substantial performance variability across dimensions. Reasoning-enhanced models show dramatic advantages on multi-step tasks like item ranking, while all models exhibit brittleness in format compliance when faced with adversarial variants, indicating overfitting to common patterns during post-training.

## Method Summary
FireBench constructs its dataset by adapting existing enterprise-focused sources (e.g., LongBench V2, GPQA Diamond) through dimension-specific constraint injection. For each sample, the benchmark imposes a specific instruction-following requirement: exact output formatting (e.g., JSON, LaTeX boxing), strict sequential information gathering, accurate sorting of tabular data, appropriate refusal on uncertain queries, and adherence to mandatory or forbidden content elements. Model outputs are evaluated via programmatic validators for deterministic categories (format, order, ranking, overconfidence) and via a GPT-4.1 judge with rubrics for the two content-requirement categories. Overconfidence is assessed by comparing responses from a standard prompt and an uncertainty-aware prompt, requiring consistent correctness to score a pass.

## Key Results
- No model exceeds 75% overall accuracy; the highest score is 74.0% (DeepSeek-V3.1).
- Reasoning variants dramatically outperform non-reasoning counterparts on item ranking (e.g., +77 percentage points for GPT-5.1).
- All models show sharp performance drops on adversarial format variants (e.g., GPT-4.1: 100% → 53% on `\boxed[]`), revealing brittleness.
- Performance varies widely across the six dimensions within individual models, with no model dominating uniformly.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Reasoning-enhanced models achieve substantially higher accuracy on multi-step ordering tasks (e.g., item ranking) because explicit chain-of-thought enables systematic comparison and correct sorting.
- **Mechanism:** Item ranking requires parsing a table, comparing values across rows according to a specified attribute and order, and reproducing the top‑N rows exactly. Without intermediate reasoning, models may skip comparisons or misapply sorting rules. Reasoning models generate step‑by‑step thoughts that break the problem into manageable sub‑tasks (e.g., “extract all rows”, “compare X”, “order by Y”), reducing cognitive load and error propagation.
- **Core assumption:** Explicit reasoning steps improve performance on tasks that involve deterministic operations over structured data, provided the model can accurately parse and operate on the structure.
- **Evidence anchors:**
  - FireBench reports “Reasoning variants consistently outperform non‑reasoning ones, particularly in item ranking (e.g., +77 percentage points for GPT‑5.1).”
  - Table 2 shows GPT‑5.1 Medium Thinking scores 93% on Ranking while GPT‑5.1 Instant scores only 16% (a 77‑point gap). Similar patterns appear for Qwen3 and Kimi K2 pairs.
  - The neighboring AGENTIF benchmark similarly finds that agentic scenarios with complex constraints benefit from reasoning, offering convergent evidence.
- **Break condition:** The advantage diminishes if the task does not require multi‑step comparison or if the reasoning process introduces hallucinations that corrupt the sorting logic.

### Mechanism 2
- **Claim:** Format compliance is brittle because models overfit to the limited distribution of format patterns seen during post‑training, failing to generalize to syntactically similar but novel formats.
- **Mechanism:** During post‑training, models repeatedly encounter a narrow set of output formats (e.g., `\boxed{}`) and learn to produce them with near‑perfect accuracy. When confronted with adversarial variants (e.g., `\boxed[ ]`), the model’s learned pattern does not match, leading to refusal or incorrect output. This indicates reliance on surface‑level pattern matching rather than understanding the abstract rule “place the answer inside the specified delimiters”.
- **Core assumption:** Format compliance is treated as a memorization task rather than as a semantic constraint on output structure, due to insufficient diversity in training data.
- **Evidence anchors:**
  - FireBench states: “Formatting remains brittle, with sharp drops on adversarial format variants, suggesting overfitting to common patterns during post‑training.”
  - For GPT‑4.1, accuracy on the standard `\boxed{}` format is 100%, but drops to 53% on the adversarial version; Qwen3 Instruct falls from 100% to 73% (Section 4, Figure 2).
  - Corpus evidence is limited; nearby benchmarks like FollowBench focus on response quality rather than format robustness, so FireBench is among the first to expose this specific brittleness.
- **Break condition:** If post‑training data included a wide variety of format constraints, the performance gap would narrow; however, current practices appear inadequate.

### Mechanism 3
- **Claim:** Instruction‑following capability is multi‑dimensional, with high variance across the six FireBench categories, meaning that overall scores hide specific weaknesses that matter for enterprise deployment.
- **Mechanism:** Each dimension tests a distinct competency: format compliance (structural parsing), ordered responses (procedural adherence), item ranking (logical manipulation), overconfidence (uncertainty calibration), positive/negative content (constraint satisfaction). A model may excel in one area (e.g., GPT‑4.1 in format and content) while failing in another (ranking, overconfidence) because the underlying skills are not strongly correlated and training data likely emphasizes some over others.
- **Core assumption:** There is no single underlying factor (e.g., general intelligence) that dominates performance; instead, instruction following comprises loosely coupled sub‑skills.
- **Evidence anchors:**
  - “Performance varies significantly across dimensions, indicating no single model dominates uniformly.”
  - Figure 2 shows standard deviations up to 25.5 percentage points for top models; rankings shift dramatically (e.g., GPT‑4.1 ranks 1st in three categories but 5th/6th in Ranking and Overconfidence).
  - The Instruction Gap paper also observes “inconsistent adherence to custom instructions,” supporting the multi‑dimensional nature.
- **Break condition:** Future models might achieve uniformly high scores across all dimensions, collapsing the variance; current results show this is not the case.

## Foundational Learning

- **Concept: Verifiable Instruction Following in Enterprise APIs**  
  - *Why needed here:* Enterprise deployments require outputs that can be parsed automatically (e.g., JSON, XML) and must follow strict step‑by‑step procedures. This shifts the focus from free‑form chat to deterministic, machine‑readable interactions.  
  - *Quick check question:* What are two examples of constraints that are critical for API‑driven applications but not typically evaluated in chat‑oriented benchmarks? (e.g., exact output format, mandatory field order, refusal on insufficient information.)

- **Concept: Capability Dimensions as Independent Axes**  
  - *Why needed here:* Understanding that the six FireBench dimensions measure separate skills helps interpret why a model can be strong in one area and weak in another, and why a single overall score is misleading.  
  - *Quick check question:* Name three of the six FireBench dimensions and briefly describe what each tests (e.g., Ordered Responses: must collect information in a strict sequence; Overconfidence: must decline when uncertain; Negative Content: must avoid forbidden elements).

- **Concept: Adversarial Evaluation for Robustness**  
  - *Why needed here:* FireBench includes adversarial format variants to expose overfitting. This concept teaches that robustness must be tested by perturbing the input specification slightly while keeping the underlying constraint unchanged.  
  - *Quick check question:* What is the difference between the standard `\boxed{}` and the adversarial `\boxed[ ]` format in FireBench, and why does the latter reveal overfitting? (Answer: The adversarial variant changes the delimiter slightly; models trained on the common pattern fail to generalize the rule “place answer inside delimiters”.)

## Architecture Onboarding
- **Component map:** Source Datasets -> Constraint Generators -> Prompt Construction -> Model Inference -> Validators (Programmatic + LLM Judge) -> Aggregation
- **Critical path:** Raw data → constraint injection → prompt construction → model inference → validation (programmatic or LLM‑based) → per‑sample pass/fail → category aggregation → final report. The path must preserve deterministic ordering for Ordered Responses and ensure exact verbatim matching for Ranking.
- **Design tradeoffs:** Programmatic verification provides objective, fast, and reproducible scoring but can only handle well‑defined outputs; LLM judging allows flexible content checks but introduces cost, latency, and potential bias. FireBench uses programmatic checks wherever possible and reserves GPT‑4.1 (or similar) judges for the two content‑requirement categories, striking a balance.
- **Failure signatures:** (1) Large drop on adversarial formats indicates overfitting to common patterns. (2) Low Ordered Responses scores reveal inability to maintain multi‑turn procedural constraints. (3) Discrepancy between reasoning and non‑reasoning variants on Ranking highlights lack of inherent sorting logic. (4) High overconfidence failure (i.e., answering when should refuse) shows poor uncertainty calibration.
- **First 3 experiments:**  
  1. **Baseline evaluation:** Run the entire model suite on all 2,470 samples to establish a performance map and compare to reported numbers.  
  2. **Format robustness ablation:** Isolate the format subset and contrast results on standard vs. adversarial variants for each model, quantifying brittleness.  
  3. **Reasoning impact isolation:** Compare paired reasoning/non‑reasoning model variants on Ranking and other dimensions to verify the reasoning advantage and understand its scope.

## Limitations
- Sub-type sample distribution (e.g., format constraint breakdown) is undisclosed, preventing detailed analysis of performance within each dimension.
- Full evaluation rubrics and judge prompts for positive/negative content requirements are not public, making exact replication of LLM judging difficult.
- Configuration for the GPT‑4.1 judge (model version, temperature, prompt wording) and handling of edge cases in rubrics are unspecified.
- Complete list of adversarial format variants beyond `\boxed[ ]` and their precise definitions are missing, limiting format compliance tests.

## Confidence
- **Reasoning boost in ranking:** High (consistent ~77pp gap across model pairs).
- **Format brittleness from overfitting:** Medium (direct FireBench data but weak external validation).
- **Multi-dimensional variance:** High (clear score spreads and shifting rankings).
- **Overall score ceiling (<75%):** High (directly reported).

## Next Checks
1. **Replicate format robustness:** Run standard vs. adversarial variants (e.g., `\boxed{}` vs. `\boxed[]`) on all models; expect significant drops.
2. **Isolate ranking advantage:** Compare paired reasoning/non-reasoning models (e.g., GPT-5.1 Thinking vs. Instant) on ranking tasks; verify ~77pp gap.
3. **Cross-validate content scores:** Use AGENTIF’s similar constraint-evaluation protocol to re-judge a subset of FireBench’s positive/negative content samples; assess convergence.
