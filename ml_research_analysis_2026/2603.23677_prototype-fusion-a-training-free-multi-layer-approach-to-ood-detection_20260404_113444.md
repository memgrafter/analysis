# Prototype Fusion: A Training-Free Multi-Layer Approach to OOD Detection

## Quick Facts
- **arXiv ID:** 2603.23677  
- **Source URL:** https://arxiv.org/abs/2603.23677  
- **Reference count:** 21  
- **Primary result:** A training-free, post-hoc OOD detection method that aggregates L2-normalized class prototypes from multiple intermediate convolutional layers, improving AUROC by up to 4.41% and reducing FPR@95% TPR by up to 13.58% over state-of-the-art on CIFAR-10/100 and ImageNet-1k.

## Executive Summary
Out-of-distribution (OOD) detection is critical for safe deployment of deep learning systems. This paper introduces Prototype Fusion, a training-free, post-hoc technique that enhances OOD detection by combining features from multiple intermediate layers of a frozen pretrained image classifier. The method constructs L2-normalized class prototypes from a small in-distribution (ID) calibration set and then, for each test sample, computes the maximum cosine similarity to these prototypes in each selected layer. These per-layer scores are aggregated (typically uniformly) into a final ID likelihood; OOD samples yield low scores. Evaluations across ResNet, DenseNet, and RegNet backbones on standard benchmarks show consistent and significant improvements in AUROC and FPR@95% TPR compared to prior works. The approach requires only a modest calibration set and no additional training, making it practical for real-world applications.

## Method Summary
Prototype Fusion operates in two phases: calibration and inference. During calibration, for a chosen subset of convolutional layers (typically the last three stages), the method extracts global average-pooled features from a frozen pretrained model for each ID calibration sample. These features are L2-normalized, and for each class, the mean of the normalized features across calibration samples becomes the L2-normalized class prototype for that layer. At inference, given a test image, the same feature extraction is performed. For each selected layer, the cosine similarity between the test sample’s normalized feature vector and every class prototype is computed; the maximum similarity for that layer is recorded. The per-layer maximum similarities are aggregated (using uniform weights by default) to produce a similarity score. The final OOD score is defined as one minus this aggregated similarity. A detection threshold is set using a validation set to achieve a desired true positive rate (e.g., 95%) on ID data.

## Key Results
- **AUROC improvement** up to 4.41% on average across CIFAR-10/100 and ImageNet-1k benchmarks compared to previous post-hoc detectors.
- **FPR@95% TPR reduction** up to 13.58%, indicating fewer false alarms while maintaining high ID recall.
- Uniform weighting across the last three stages and calibration set sizes between 5% and 25% of the ID training data achieve optimal performance.
- Gains are consistent across multiple architectures (ResNet, DenseNet, RegNet) and OOD datasets (iSUN, LSUN, Places, Textures, SVHN, iNaturalist).

## Why This Works (Mechanism)
The method exploits the observation that different intermediate layers in a deep network capture features at varying levels of abstraction—from low-level edges to high-level semantics. ID samples tend to align well with class prototypes in many layers, while OOD samples fail to match any prototype in most layers. By aggregating maximum cosine similarities across layers, the detector leverages complementary evidence and becomes more robust than relying on a single layer (typically the penultimate). L2-normalization ensures that similarity is based on angular distance, which is invariant to feature magnitude and beneficial for comparing prototypes. The prototype mean condenses the ID class distribution into a representative point; the maximum similarity operation accounts for intra-class variation by allowing the test sample to match any class prototype. The aggregation effectively averages out noise and outliers, leading to a more discriminative score.

## Foundational Learning
The method builds on several key concepts:

**Out-of-Distribution (OOD) Detection**  
*Why needed:* In safety-critical applications, models must recognize when inputs come from a distribution different from the training data, as predictions on such data are unreliable.  
*Quick check:* Given a trained classifier and a set of ID vs OOD samples, can you compute a score that separates them? Try using softmax confidence or Mahalanobis distance.

**Post-hoc / Training-free Detection**  
*Why needed:* Retraining or modifying the model is often impractical; a post-hoc method can be applied to any pretrained model without altering its parameters.  
*Quick check:* Can you design an OOD detector that only uses the features of a frozen model and a small ID calibration set? Implement MaxSoftmax or Mahalanobis as baselines.

**Feature Normalization (L2)**  
*Why needed:* Normalizing features to unit length transforms inner products into cosine similarities, making the similarity measure angular and magnitude-invariant. This is crucial when comparing features from layers with different activation scales.  
*Quick check:* Take two feature vectors, compute their dot product, then L2-normalize them and compute dot product again—the latter is the cosine similarity. Observe that scaling one vector does not affect the normalized dot product.

**Prototype-based Classification**  
*Why needed:* A prototype (mean of class features) provides a compact representation of an ID class, enabling simple nearest-neighbor-like similarity comparisons.  
*Quick check:* Given a set of feature vectors per class, compute the mean per class and classify a new sample by nearest prototype (e.g., using cosine similarity). Compare accuracy to a linear classifier.

**Cosine Similarity**  
*Why needed:* Cosine similarity measures the angle between vectors, which is insensitive to feature magnitude and suitable for high-dimensional, norm-sensitive features.  
*Quick check:* For two unit vectors, cosine similarity equals dot product. Compute similarities between random vectors and observe ranges.

**Multi-layer Feature Aggregation**  
*Why needed:* Single-layer features may be insufficient for discriminating OOD; combining information from multiple depths captures both semantic and low-level patterns.  
*Quick check:* Given a model with several intermediate layers, compute OOD scores (e.g., maximum softmax probability) per layer and combine by averaging. Does combining improve detection?

## Architecture Onboarding
To implement Prototype Fusion, consider the system components and flow:

**Component Map**  
Calibration Data -> Prototype Bank Construction -> Test-time Feature Extraction -> Per-layer Scoring -> Similarity Aggregation -> Threshold Decision

**Critical Path**  
The sequence from calibration to final OOD score:  
1. Select a set of convolutional layers (usually the last three stages).  
2. Extract and L2-normalize features for all calibration samples from each layer.  
3. Compute per-class mean vectors (prototypes) from these normalized features.  
4. For a test sample, repeat feature extraction and normalization for the same layers.  
5. For each layer, compute cosine similarity between test features and all class prototypes, take the maximum.  
6. Average the per-layer maximum similarities (uniform weights) to get an overall ID score.  
7. Classify as OOD if 1 - score exceeds a threshold.

**Design Tradeoffs**  
- **Layer selection:** Using more layers may capture complementary information but also introduce redundancy or noise. The paper finds the last three stages work best; earlier layers may be too low-level, and the final layer may be too task-specific.  
- **Weighting scheme:** Uniform averaging is simple and effective, but learned weights could potentially adapt to the importance of each layer, though the paper reports no significant gain over uniform.  
- **Calibration set size:** Larger sets yield more stable prototypes but are less practical; the method works with as little as 5% of ID training data, beyond which gains plateau.  
- **Prototype construction:** The mean of normalized features is sensitive to outliers; robust alternatives (median, trimmed mean) were not explored.

**Failure Signatures**  
- **Prototype collapse:** When per-class prototypes are too close (low inter-class cosine distance), ID and OOD samples become indistinguishable. Diagnose by computing average pairwise prototype similarity; values near 1 indicate collapse.  
- **Layer misalignment:** If the wrong layers are selected (e.g., too early or too late), per-layer maximum similarities may not separate ID/OOD. Check per-layer AUROC; a large variation suggests poor layer choice.  
- **Calibration deficiency:** With too few calibration samples, prototype variance increases, leading to unstable scores. Monitor the standard deviation of calibration features within each class.  
- **Preprocessing mismatch:** Because features are L2-normalized, any difference in image resizing or normalization between calibration and test phases can distort similarity magnitudes. Ensure identical preprocessing pipelines.

**First Three Experiments**  
1. **Baseline replication:** On CIFAR-10 with ResNet-18, use the last three residual stages, 10% calibration, uniform weighting. Report AUROC and FPR@95% TPR against benchmarks (e.g., Mahalanobis, MaxSoftmax). Expect results close to Table 1.  
2. **Layer ablation:** Systematically vary the set of layers (e.g., include earlier stages, exclude the final stage) and measure impact on OOD performance. Identify the combination that yields the best AUROC; verify that the last three stages are indeed optimal or if other combinations perform similarly.  
3. **Calibration size sweep:** Vary calibration set size from 1% to 50% of the ID training data. Plot AUROC and FPR@95% TPR against size. Confirm the 5–25% plateau and pinpoint the minimum effective size for CIFAR-10 and ImageNet-1k.

## Open Questions the Paper Calls Out
The paper leaves several directions for future work:

1. **Vision Transformers applicability:** The method was evaluated only on CNNs. It is unclear whether the multi-layer prototype fusion approach transfers to ViTs or Swin Transformers, which have different feature hierarchies (patch embeddings, attention layers). Testing on these architectures would determine if the claim of model-agnosticism holds.  
2. **Learned layer weights:** Uniform weighting performed best among simple heuristics, but the paper did not explore optimizing weights on a validation set (e.g., by gradient-based maximization of AUROC). Learned weights could potentially adapt to the varying discriminative power across layers.  
3. **Robust prototype construction:** Using the mean of normalized features is simple but may be sensitive to outliers, especially with very few calibration samples. Alternatives like median, trimmed mean, or clustering-based prototypes could improve stability and performance.  
4. **Near-OOD and adversarial robustness:** The evaluation focused on far-OOD datasets (e.g., iSUN vs ImageNet). It remains unknown how well the method detects subtle distribution shifts (e.g., CIFAR-10 vs CIFAR-100) or adversarial examples designed to mimic ID features.

## Limitations
- The precise definition of "last three stages" is architecture-dependent; the paper provides concrete mapping only for ResNet-like models. For other architectures (e.g., DenseNet, RegNet), the layer selection must be manually determined, which may affect reproducibility and performance.
- Uniform weighting and the 5–25% calibration range were identified through ablations on limited benchmarks; these optimalities may not generalize to all model-OOD dataset combinations.
- The method's effectiveness on near-OOD and adversarial examples is untested, leaving a gap in understanding its robustness under more subtle but realistic distribution shifts.

## Confidence
- **Model-agnostic claim:** Medium. The method is described generically, but exact layer selection for non-ResNet models is not provided, creating a risk of incorrect implementation.
- **Uniform weighting optimality:** Medium. The paper's ablation (Figure 4) supports this, yet the configuration space was limited; other weighting schemes (e.g., learned) might outperform on unseen setups.
- **Calibration set size requirements:** High. The calibration size ablation (Figure 2) clearly shows plateauing performance beyond 5–25% across multiple datasets.

## Next Checks
To validate and extend the findings, we propose:

1. **Define explicit layer mapping for non-ResNet models:** For RegNet and DenseNet, produce a standardized mapping of "stage" to module names (e.g., `regnet.stage4`, `densenet.transition3`). Then, rerun ImageNet experiments and compare AUROC/FPR to the reported numbers to confirm that performance matches when using the correct layers.
2. **Calibration size sensitivity on ImageNet-1k:** Conduct a systematic experiment varying calibration set from 1% to 100% of ImageNet training data (by number of images or per-class count). Plot metrics to pinpoint the exact point of diminishing returns and verify the 5–25% range for large-scale data.
3. **Test learned layer weights:** Implement a simple weight optimization that tunes layer weights on a validation set (e.g., via grid search or gradient-based maximization of AUROC). Evaluate on at least two architectures (e.g., ResNet-50 and RegNetY) and compare to uniform weighting. A significant improvement would challenge the conclusion that uniform is best.
