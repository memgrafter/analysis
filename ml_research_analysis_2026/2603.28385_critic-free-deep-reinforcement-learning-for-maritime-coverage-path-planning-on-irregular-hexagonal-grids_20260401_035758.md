# Critic-Free Deep Reinforcement Learning for Maritime Coverage Path Planning on Irregular Hexagonal Grids

## Quick Facts
- **arXiv ID:** 2603.28385  
- **Source URL:** https://arxiv.org/abs/2603.28385  
- **Reference count:** 36  
- **Primary result:** Achieved 99.0% Hamiltonian success rate on unseen maritime grids, with paths 7% shorter and 24% fewer heading changes than baselines, while operating under 32 ms inference time.

## Executive Summary
This paper addresses maritime coverage path planning (CPP) on irregular hexagonal grids, a problem complicated by geometric constraints and inefficient traditional decomposition methods. The authors propose a Transformer-based pointer policy trained via a critic-free Group-Relative Policy Optimization (GRPO) scheme, which avoids value-function instability by comparing trajectories within the same instance. On 1,000 test environments, the Best-of-16 sampling strategy with 2-opt refinement yields a 99.0% success rate in generating Hamiltonian paths (visiting all cells exactly once), more than doubling the best heuristic baseline (46.0%). The resulting paths are also 7% shorter and have 24% fewer heading changes. Inference runs under 32 ms per instance on a laptop GPU, demonstrating potential for real-time deployment in maritime autonomy.

## Method Summary
The method frames CPP as a sequential decision-making problem on a graph representation of an irregular hexagonal grid. A Transformer encoder processes the graph structure and node features, while a pointer-network-style decoder autoregressively generates a visitation order. Training uses a critic-free GRPO algorithm: for each training instance, multiple trajectories are sampled, and the advantage of each action is computed relative to the group’s performance, eliminating the need for a separate value network and its associated instability. Action masking ensures only valid neighboring cells are selected. Final solutions are refined with a lightweight 2-opt local search.

## Key Results
- **99.0% Hamiltonian success rate** on 1,000 unseen test instances using Best-of-16 sampling plus 2-opt, compared to 46.0% for the best heuristic baseline.
- **Path quality**: produced paths are 7% shorter and exhibit 24% fewer heading changes than the closest DRL baseline.
- **Real-time inference**: all tested inference modes (greedy, Best-of-N) run under 32 ms per instance on a laptop GPU (NVIDIA RTX 2060).

## Why This Works (Mechanism)
The approach succeeds by combining three key ideas: (1) **Graph Transformer** effectively captures irregular connectivity and long-range dependencies in hexagonal grids; (2) **Critic-free GRPO** stabilizes training by using group-relative advantages, avoiding bias and instability from approximate value functions; (3) **Action masking** enforces feasibility (no revisit, connectivity) during decoding. The Best-of-N sampling with 2-opt acts as a test-time enhancer, trading multiple forward passes for higher-quality solutions without altering the learned policy.

## Foundational Learning
These core concepts underpin the work:
- **Coverage Path Planning (CPP)**: The task of finding a path that covers all cells with minimal repetition. *Why needed*: Defines the problem structure and evaluation metrics. *Quick check*: Can you distinguish between lawn-mower patterns and Hamiltonian CPP?
- **Irregular Hexagonal Grids**: Discretization of maritime areas into hexagonal cells with non-uniform adjacency due to shorelines and obstacles. *Why needed*: Matches operational constraints of surface vehicles better than rectangular grids. *Quick check*: How does hex grid connectivity differ from 4- or 8-connected grids?
- **Transformer-based Pointer Networks**: Use self-attention to encode graph structure and a pointer decoder to select nodes. *Why needed*: Handles variable-sized graphs and permutation-invariant outputs. *Quick check*: What role does the attention mask play in encoding graph connectivity?
- **Critic-Free Reinforcement Learning**: Policy gradient methods that estimate advantages without a learned value function (e.g., using baselines from sampled returns). *Why needed*: Reduces approximation error and training instability from value-function misspecification. *Quick check*: How does GRPO’s group-relative baseline differ from a simple moving average baseline?
- **Group-Relative Policy Optimization (GRPO)**: Advantage estimation where each trajectory’s return is centered by the mean return of trajectories from the same instance. *Why needed*: Provides lower-variance gradient estimates while remaining instance-specific. *Quick check*: Derive the GRPO gradient update from the group-relative advantage definition.
- **Hamiltonian Path in CPP**: A path that visits each cell exactly once; optimal in terms of total distance if all cells must be covered. *Why needed*: Serves as a strict feasibility benchmark. *Quick check*: Why is a Hamiltonian path not always possible on an irregular grid?

## Architecture Onboarding
- **Component Map**: Irregular Hex Grid Environment -> Graph Encoder (Transformer) -> Node Embeddings -> Policy Decoder (Pointer Network with Action Masking) -> Sampled Trajectories -> GRPO Group-Advantage Computation -> Policy Gradient Update -> Updated Parameters
- **Critical Path**: During training: for each batch of instances, sample `k` trajectories per instance using current policy, compute individual returns, calculate group-relative advantages (subtract mean return of the group), and perform a policy gradient step. During inference: encode graph, decode action sequence autoregressively with masking, optionally repeat multiple times and refine with 2-opt.
- **Design Tradeoffs**: 
  - *Critic-free vs. actor-critic*: GRPO avoids value-function approximation error but may increase gradient variance; the group baseline mitigates this but requires multiple samples per instance.
  - *Transformer scaling*: Self-attention complexity is quadratic in number of cells; current evaluation limited to small graphs (|V|∈[28,46]).
  - *Action masking*: Ensures feasibility but adds computational overhead and must be perfectly aligned with environment rules.
- **Failure Signatures**: 
  - No Hamiltonian path exists due to connectivity constraints; policy may still output invalid sequences if masking fails.
  - Policy converges to a suboptimal local behavior (e.g., early commit to long detours).
  - Inference latency exceeds budget on larger graphs.
- **First Three Experiments**:
  1. **Ablation on GRPO**: Replace GRPO with standard PPO (using a critic) and compare training stability and final success rate on a fixed validation set.
  2. **Scaling test**: Evaluate the trained policy on synthetically generated graphs of sizes 10, 20, 30, 40, 50 cells to identify performance degradation thresholds.
  3. **Best-of-N analysis**: Test Best-of-1 (greedy), Best-of-4, Best-of-16, Best-of-64 on the test set to quantify marginal gains in success rate and path quality versus inference time.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can non-uniform coverage priorities be integrated into the current framework, and what is the impact on path quality and priority adherence in simulated maritime scenarios?
- **Basis in paper**: [explicit] The authors state: "First, non-uniform coverage priorities can be incorporated by activating the hexscore field already embedded in the node features, enabling time-critical surveillance where high-value zones (e.g., distress areas informed by drift models) are visited preferentially." (Section 7)
- **Why unresolved**: The current experiments only consider uniform coverage (w_i=0), and the hexscore channel is present but inactive; thus the effect of priority weighting on policy behavior and performance remains unknown.
- **What evidence would resolve it**: Generate test instances with diverse priority maps (e.g., clustered high-value zones, gradients) and evaluate the trained policy (with hexscore enabled) on metrics: (i) priority-weighted coverage completeness, (ii) time-until-high-priority-zone-visitation, and (iii) trade-offs with overall path efficiency. Alternatively, fine-tune the policy on such instances to assess adaptability.

### Open Question 2
- **Question**: What graph partitioning and sub-tour allocation strategies are most effective for multi-agent coordination in hexagonal grid CPP, and how does fleet size and heterogeneity affect mission performance?
- **Basis in paper**: [explicit] The authors note: "Second, multi-platform coordination can be addressed by partitioning the AOI graph and assigning sub-tours to heterogeneous assets, extending the single-agent formulation to multi-agent fleet-level planning." (Section 7)
- **Why unresolved**: The present work focuses on a single sensing platform; multi-agent introduces coordination challenges (e.g., task allocation, collision avoidance, heterogeneous capabilities) that are not addressed.
- **What evidence would resolve it**: Implement a multi-agent extension where a central coordinator partitions the graph (e.g., via clustering or spectral methods) and assigns sub-tours to agents with different motion constraints. Evaluate coverage completion, makespan, and communication overhead on AOIs of varying connectivity and compare against heuristic partitionings.

### Open Question 3
- **Question**: Does allowing a bounded number of node revisits under a time budget improve Hamiltonian success rates and reduce dead-end failures on highly constrained hexagonal topologies?
- **Basis in paper**: [explicit] The authors write: "Third, node revisitation under a time budget, architecturally supported but not evaluated in the present study, could improve coverage robustness on highly constrained topologies where strict single-visit Hamiltonian paths are fragile." (Section 7)
- **Why unresolved**: The current action masking strictly forbids revisits; although the architecture could accommodate them (e.g., by modifying the mask and reward), no experiments explore this trade-off.
- **What evidence would resolve it**: Modify the environment to permit revisits with a kinematic penalty, then retrain or fine-tune the policy. Compare Hamiltonian success rates on the test set, especially on the 10 failing instances, and analyze the distribution of revisit counts versus improvements in coverage completion.

### Open Question 4
- **Question**: Which architectural modifications (e.g., sparse attention, hierarchical decoding) enable the Transformer policy to maintain high success rates (>95%) on hexagonal grids with 100–200 cells while keeping inference latency under 100 ms?
- **Basis in paper**: [explicit] The authors state: "Fourth, scaling to larger AOIs (e.g., hyper-resolution maritime grids with 100+cells) will involve exploring architectural variants, such as alternative attention mechanisms, sparse graph representations, or region-level hierarchical decomposition, to further accelerate training and inference." (Section 7)
- **Why unresolved**: The current model is evaluated on small graphs (|V| ∈ [28,46]); larger graphs may cause computational blowup and degrade generalization due to longer horizons and sparser connectivity.
- **What evidence would resolve it**: Generate synthetic datasets with 100–200 hexagonal cells and train model variants (e.g., local attention with global memory, graph pooling, hierarchical planning). Report HSR, path quality, and latency; identify approaches that scale sub-quadratically without sacrificing performance.

### Open Question 5
- **Question**: How does the policy trained on synthetic hexagonal grids transfer to real-world maritime environments, and what domain adaptation techniques (e.g., fine-tuning, synthetic-to-real augmentation) are needed to maintain performance?
- **Basis in paper**: [explicit] The authors mention: "Finally, validation on real maritime charts (e.g., Chilean archipelago coastlines) and deployment on autonomous surface vehicles under realistic oceanographic conditions and sensor models represent the natural applied extension of this framework toward operational Maritime Domain Awareness." (Section 7)
- **Why unresolved**: All experiments use a synthetic dataset calibrated to operational parameters; real nautical charts include shoreline artifacts, bathymetric constraints, and sensor uncertainty that may break assumptions.
- **What evidence would resolve it**: Construct a dataset from real nautical charts (e.g., Chilean coast), discretize into hexagonal grids with obstacles, and evaluate the pretrained policy. Measure performance drop in HSR and path metrics. Then fine-tune on a small real set and assess recovery, potentially with domain randomization during training to improve robustness.

## Limitations
- **Domain-specific evaluation**: Experiments use a synthetic hexagonal grid model; performance under real maritime complexities (dynamic weather, moving obstacles, bathymetry) is unknown.
- **Baseline comparison gap**: Main comparisons are against DRL baselines; classical/heuristic CPP methods (e.g., spiral, boustrophedon) are not extensively benchmarked on the same irregular grids.
- **Hardware assumptions**: Real-time inference claim (<32 ms) is measured on a laptop GPU; embedded maritime systems (e.g., PLCs, low-power SOCs) may have different latency and power constraints.

## Confidence
- **Hamiltonian Success Rate (99.0%)**: Medium – Strong on the specific test distribution of synthetic irregular grids, but generalizability to other topologies or real charts is unproven.
- **Path Quality (7% shorter, 24% fewer heading changes)**: Medium – Quantitative improvement vs. DRL baselines is clear, but limited comparison to non-DRL planners makes the absolute advantage uncertain.
- **Real-Time Inference (<32 ms)**: High – Directly measured on specified hardware (NVIDIA RTX 2060); the main uncertainty is transfer to target deployment hardware.

## Next Checks
1. **Test on physically realistic maritime scenarios** incorporating sailing constraints (e.g., minimum turn radius, currents) and stochastic obstacles to probe robustness beyond perfect-grid assumptions.
2. **Benchmark against non-DRL heuristic CPP methods** (e.g., spanning-tree-based, cellular decomposition) on the same irregular grids to isolate the contribution of the learned policy vs. the 2-opt refinement.
3. **Measure inference latency and power consumption on representative embedded hardware** (e.g., NVIDIA Jetson, maritime-certified PLC) to validate real-time deployment claims outside a laptop GPU environment.
