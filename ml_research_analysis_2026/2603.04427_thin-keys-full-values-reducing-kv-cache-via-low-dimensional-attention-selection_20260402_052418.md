# Thin Keys, Full Values: Reducing KV Cache via Low-Dimensional Attention Selection

## Quick Facts
- **arXiv ID:** 2603.04427
- **Source URL:** https://arxiv.org/abs/2603.04427
- **Reference count:** 39
- **Primary result:** For existing models, SVD plus light QK fine-tuning saves 75% of the key cache at only ~2% quality cost; composes with GQA/quantization for up to 16× total compression.

## Executive Summary
TheKV cache in Transformer inference, especially for long contexts, consumes substantial memory. This work exploits the asymmetry between selection (Q·K) and value transfer (V): selection requires far fewer dimensions than value representation. The proposed method applies truncated SVD to a pretrained model’s key projection matrix, using the thin left singular vectors as the new key projection (stored in cache) and absorbing the right singular vectors into the query projection (computed per-step). This shrinks the key cache with zero retraining cost. At the 7B scale, training from scratch with 1/4th key dimension matches full-attention perplexity while using 12% fewer parameters and training 8% faster. For existing models, a light QK fine-tuning recovers most quality, enabling significant memory savings that compose with other compression techniques like GQA and quantization.

## Method Summary
For a pretrained model, each layer’s key projection matrix \(W_K \in \mathbb{R}^{d \times d}\) is factorized via truncated SVD: \(W_K \approx A_{d \times r} B_{r \times d}\) with rank \(r \ll d\). The new key projection is set to \(W'_K = A\), producing \(r\)-dimensional keys stored in the cache. The right factor \(B^\top\) is absorbed into the query projection: \(W'_Q = W_Q B^\top\). Since queries are ephemeral and never cached, this repartitioning reduces the key cache size at zero cost—the attention scores remain algebraically identical. For aggressive ranks (e.g., \(r = d/4\)), a short QK-only fine-tuning (few epochs on a small corpus) recovers most of the quality loss. The method is applied offline to a pretrained checkpoint; deployment uses standard attention kernels with adjusted key dimensions.

## Key Results
- At 7B scale, training from scratch with \(d_{\text{select}} = d_{\text{model}}/4\) matches full-attention perplexity (9.24 vs. 9.25) while using 12% fewer parameters and training 8% faster.
- For existing models (e.g., Mistral-7B), SVD plus light QK fine-tuning saves 75% of the key cache at only ~2% perplexity cost.
- For a 7B model with 128K context, this saves ~25GB per user, enabling ~60% more concurrent users on the same hardware.
- Composes with GQA and quantization for up to 16× total key cache compression.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Factored keys via truncated SVD shrink the KV cache with zero retraining cost by absorbing compressed key projection into the query path.
- **Mechanism:** For a pretrained key projection matrix \(W_K \in \mathbb{R}^{d \times d}\), compute SVD \(W_K \approx A_{d \times r} B_{r \times d}\) with rank \(r \ll d\). Deploy \(W'_K = A\) (thin keys, stored in cache) and absorb \(B^\top\) into the query projection \(W'_Q = W_Q B^\top\) (computed per step, never cached). Attention scores \(q'_i k'^\top_j = x_i W_Q B^\top A^\top x_j^\top = x_i W_K x_j^\top\) remain algebraically identical.
- **Core assumption:** Queries are ephemeral, so their increased compute/memory cost does not affect kv cache; keys are cached, so reducing their dimensionality directly cuts memory.
- **Evidence anchors:**
  - [abstract] "factorize each key projection \(W_K \approx A B\) via truncated SVD, set \(W'_K = A\) as the new key projection producing compact r-dimensional keys for the cache, and absorb \(B^\top\) into the query projection (\(W'_Q = W_Q B^\top\)) at zero cost—since queries are never cached."
  - [section 2.3] "we obtain thin keys from any pretrained full-key model for free, simply by repartitioning the existing weights."
  - [corpus] Neighbors like KQ-SVD and ReCalKV also use SVD for KV compression, but do not exploit the query-key asymmetry; this paper's novelty is the zero-cost query absorption.
- **Break condition:** If \(W_K\) has no rapidly decaying singular values (i.e., full rank effectively), then truncation at low \(r\) will catastrophically degrade attention fidelity, as seen in both-Q+K compression in Table 1.

### Mechanism 2
- **Claim:** Selection (QK) requires only \(O(\log N)\) dimensions to distinguish \(N\) relevant token categories, while value transfer needs full \(d\) dimensionality.
- **Mechanism:** Attention weights are scalar scores (a ranking problem). By the Johnson–Lindenstrauss lemma, embedding \(N\) points to preserve pairwise dot-product order requires only \(O(\log N)\) dimensions. Thus, the per-head QK dimension \(d_{\text{select}}/h\) can be far smaller than the value dimension \(d_{\text{model}}/h\) without harming the model's ability to select relevant tokens.
- **Core assumption:** The effective number of distinct selection patterns \(N\) (syntactic roles, semantic clusters) is polylogarithmic in vocabulary size or context length, not linear.
- **Evidence anchors:**
  - [abstract] "selection requires only \(O(\log N)\) dimensions to distinguish among \(N\) relevant token categories (e.g., syntactic roles, semantic clusters, positional patterns)—far fewer than value transfer needs."
  - [section 2.2] "By the Johnson–Lindenstrauss lemma, N points can be embedded into \(O(\log N)\) dimensions while preserving pairwise distances."
  - [corpus] KQ-SVD and HashEvict provide empirical evidence that keys are highly compressible, but do not directly establish the \(O(\log N)\) theoretical bound. Haris and Onak (2025) prove \(\Omega(\log n)\) lower bounds, supporting the order of magnitude but not the exact constant.
- **Break condition:** If the actual number of distinct selection patterns \(N\) grows super-logarithmically (e.g., with context length or vocabulary), then a fixed small \(d_{\text{select}}\) will fail to maintain ranking quality, causing perplexity increases as in low-rank experiments.

### Mechanism 3
- **Claim:** Factored keys compose with existing KV cache reduction methods (GQA, MLA, quantization) for multiplicative savings.
- **Mechanism:** Factored keys independently reduce per-head key dimensionality. Since GQA reduces head count and MLA reduces joint KV dimensionality, applying thin keys on top further shrinks the key cache per remaining KV head. Quantization then compresses the remaining numeric precision.
- **Core assumption:** The compression from different axes (head count, per-head dimension, bit width) is multiplicative and does not interact pathologically.
- **Evidence anchors:**
  - [abstract] "composes with GQA and quantization for up to \(16\times\) total key cache compression."
  - [section 3.3] Table 6 shows GQA-8 + thin keys achieves 84.4% total KV savings vs GQA-8 alone at 75%.
  - [section 6] "Thin keys compose with KV quantization (INT4): dimensionality reduction removes low-rank redundancy, then quantization compresses remaining elements, yielding up to \(16\times\) combined key cache compression (4× from thin keys × 4× from INT4)."
  - [corpus] "Quantize What Counts" advocates asymmetric bit allocation between keys/values, aligning with the idea that keys and values have different compression needs; this provides indirect support for composability.
- **Break condition:** If combining methods introduces kernel incompatibilities (e.g., Flash Attention assumptions) or if one method already extracts all available low-rank structure (e.g., MLA's joint latent), then additional thin-key compression yields diminishing returns or requires architectural changes.

## Foundational Learning

- **Concept: Asymmetric roles in attention (QK selection vs. V transfer)**
  - Why needed here: The entire method hinges on understanding that queries/keys produce scalars (selection) while values carry representations (transfer). Without this distinction, one would not expect different dimensionality requirements.
  - Quick check question: If you halve the key dimension but keep value dimension full, what part of the attention computation changes and what stays identical?

- **Concept: Truncated SVD as optimal low-rank approximation**
  - Why needed here: Factored keys rely on SVD to split \(W_K\) into thin key and absorbed query parts. Understanding that the top-\(r\) singular values/vectors provide the best rank-\(r\) approximation (in Frobenius norm) is key to why this factorization is principled.
  - Quick check question: Given a matrix \(W\), how do you construct matrices \(A\) (thin) and \(B\) (absorbed) such that \(AB \approx W\) and \(\|W - AB\|_F\) is minimized for a fixed rank?

- **Concept: Autoregressive KV cache memory dynamics**
  - Why needed here: The motivation is memory bottleneck during decoding. Knowing that for each generated token you store keys/values for all previous tokens (size \(2 \times n \times d_{\text{model}} \times L\)) explains why reducing key dimension saves memory per user.
  - Quick check question: For a 7B model with 32 layers, \(d_{\text{model}}=4096\), and 128K context, how many GB does the key cache occupy in fp16? How does that change if \(d_{\text{select}} = d_{\text{model}}/4\)?

## Architecture Onboarding

- **Component map:**
  Pretrained weights -> Extract \(W_K\) and \(W_Q\) per layer -> Truncated SVD on \(W_K\) -> Obtain \(A\) (thin) and \(B\) (absorbed) -> Set new \(W'_K = A\) -> Compute new \(W'_Q = W_Q B^\top\) -> Deploy with standard attention (key cache stores \(A^\top x\), queries use \(W'_Q\)) -> Optional: QK-only fine-tuning.

- **Critical path:**
  1. Choose target rank \(r = d_{\text{select}}\) (e.g., \(d/4\)).
  2. For each layer, load pretrained \(W_K \in \mathbb{R}^{d \times d}\), compute truncated SVD to get \(A \in \mathbb{R}^{d \times r}\) and \(B \in \mathbb{R}^{r \times d}\).
  3. Save \(A\) as the new \(W'_K\); compute and save \(W'_Q = W_Q B^\top\) (or keep \(B\) and multiply \(W_Q\) at load time).
  4. Deploy model with standard attention kernels, but key cache entries are now \(r\)-dimensional.
  5. (Optional) Light QK fine-tuning (few epochs, <1% pretraining data) to recover quality at aggressive ranks.

- **Design tradeoffs:**
  - Rank choice: Larger \(r\) → less quality loss, less saving. Conservative: \(r = d/2\) (50% key cache saved, ~2% PPL cost). Aggressive: \(r = d/4\) (75% saved, ~2% cost with fine-tuning).
  - Fine-tuning: Without fine-tuning, quality drop is >2% at \(d/4\); with 3 epochs of QK-only fine-tuning, drop drops to ~2%. Fine-tuning data should be domain-matched if evaluating on specialized tasks (e.g., math).
  - Composability: Can layer with GQA (reduce heads) and quantization (reduce bits). Order: first thin keys, then GQA, then quantization to avoid interference.

- **Failure signatures:**
  - Immediate: Perplexity spike on validation set after SVD without fine-tuning, especially at low \(r\) (e.g., >10% at \(d/4\)).
  - Downstream: Larger drops on reasoning tasks (GSM8K) vs. knowledge tasks (MMLU); GSM8K recovers with domain-matched fine-tuning.
  - Training instability: If training from scratch with thin keys, watch early training; thin keys sometimes lead but must converge by ~150K steps (Figure 2). If divergence occurs, reduce learning rate or increase \(r\).

- **First 3 experiments:**
  1. **Exp 5 (GPT-2 SVD):** Apply zero-cost SVD to pretrained GPT-2. Verify K-only compression at rank 384 (\(d/2\)) gives ~2% PPL increase; Q-only compression is much worse. Confirms key compressibility asymmetry.
  2. **Exp 7 (7B from-scratch):** Train LLaMA-7B from scratch with \(d_{\text{select}} = d/4\) vs full. Should see identical or better perplexity at 20B tokens with 12% fewer params and 8% faster training. Validates that thin keys are not harmful at scale.
  3. **Exp 8 (Mistral-7B SVD+FT):** Take pretrained Mistral-7B, apply SVD to \(W_K\) at rank 256 (\(d/4\)), then QK fine-tune 3 epochs on WikiText-103. Expect residual PPL gap ~2% and downstream task gaps <2% except GSM8K (~13% without math fine-tuning). Validates practical deployment path.

## Open Questions the Paper Calls Out

- **Question 1:** At Chinchilla-optimal training budgets (e.g., ~140B tokens for a 7B model), does using thin keys (\(d_{\text{select}} = d_{\text{model}}/4\)) incur any quality degradation relative to full attention?
- **Question 2:** How do advanced capabilities—specifically in-context learning, instruction following, and long-context retrieval—respond to QK dimensionality reduction compared to standard perplexity and the five downstream tasks evaluated?
- **Question 3:** What structural property explains the marked asymmetry where key projections are far more compressible than query projections via SVD, and can this be leveraged to design factorization schemes beyond truncated SVD?
- **Question 4:** How does the optimal \(d_{\text{select}}\) scale with maximum context length? Does the theoretical \(O(\log N)\) selection requirement imply more dimensions per head for very long contexts?

## Limitations
- Fine-tuning hyperparameters (learning rate, batch size, optimizer) are underspecified, making exact replication of the ~2% quality cost difficult.
- Handling of cases where the target rank is not divisible by the number of attention heads is not described; shape mismatches or suboptimal head allocation could affect results.
- The theoretical \(O(\log N)\) bound for selection dimensionality, while plausible, lacks direct empirical validation in large language models.
- Composability beyond GQA and quantization (e.g., with Multi-head Latent Attention) is not demonstrated; interactions may not be perfectly multiplicative.
- Very aggressive compression (e.g., rank = d/8) without domain-matched fine-tuning might cause severe drops on reasoning tasks, limiting practical deployment.

## Confidence
- **Zero-cost SVD factorization shrinks KV cache:** High – algebraic identity and GPT-2 experiments confirm.
- **Selection requires \(O(\log N)\) dimensions:** Medium – supported by the Johnson–Lindenstrauss lemma, but empirical evidence in attention is indirect.
- **Composability with GQA/quantization:** High – Table 6 quantifies up to 84.4% total KV savings.
- **From-scratch 7B with 1/4 key dimension matches full perplexity:** High – training curve in Figure 2 shows identical convergence.
- **SVD + light QK fine-tuning saves 75% key cache at ~2% cost:** Medium – depends on fine-tuning details and may vary with domain.
