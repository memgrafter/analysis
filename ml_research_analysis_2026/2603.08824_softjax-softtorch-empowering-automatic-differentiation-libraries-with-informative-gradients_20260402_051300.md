# SoftJAX & SoftTorch: Empowering Automatic Differentiation Libraries with Informative Gradients

## Quick Facts
- **arXiv ID:** 2603.08824  
- **Source URL:** https://arxiv.org/abs/2603.08824  
- **Reference Count:** 40  
- **Primary Result:** SoftJAX and SoftTorch provide unified, drop‑in soft differentiable replacements for discrete operations, enabling informative gradients and offering configurable smoothness modes with competitive performance; benchmarks show soft sorting networks as fastest (1.0 ms for n=4096, ~3.8× speedup over hard baseline) and FastSoftSort as most memory‑efficient, while a collision‑detection case study demonstrates successful gradient flow to all vertices.

## Executive Summary
Automatic differentiation (AD) frameworks struggle with discrete operations such as sorting, argmax, and thresholding because their gradients are zero or undefined at discontinuities, leading to uninformative gradients. SoftJAX (for JAX) and SoftTorch (for PyTorch) address this problem by providing a comprehensive suite of soft‑differentiable operators that serve as drop‑in replacements for common discrete primitives. These libraries unify previously scattered implementations, offering configurable smoothness levels (smooth, c0, c1, c2) and support for straight‑through estimation. Benchmarks reveal that soft sorting networks achieve the lowest runtime (1.0 ms for n=4096, ~3.8× faster than the hard baseline) while FastSoftSort scales linearly in memory. In a collision‑detection case study, soft ops propagate gradients to all polygon vertices, whereas the hard version yields sparse updates. Overall, SoftJAX and SoftTorch empower practitioners to incorporate discrete decisions into end‑to‑end learned systems without sacrificing performance or usability.

## Method Summary
SoftJAX and SoftTorch implement soft versions of discrete operations by replacing hard discontinuities with smooth approximations. For elementwise functions (e.g., clip, threshold), they use smooth Heaviside approximations parameterized by a temperature τ. For axiswise operations (sort, argsort, top‑k, rank, median) they employ a diversified toolkit: optimal transport formulations (via Sinkhorn iterations), neural sorting (via simplex/permutahedron projections, e.g., NeuralSort, SoftSort), and sorting networks (e.g., SmoothSort, SortingNet). Each operator supports multiple smoothness modes—smooth, c0, c1, c2—which control the differentiability properties of the relaxation. Straight‑through estimation (STE) is also integrated to preserve discrete outputs during the forward pass while still using soft gradients in the backward pass. The libraries are built as extensions to JAX and PyTorch, leveraging their autograd engines and JIT compilation to deliver seamless integration and high performance.

## Key Results
- Consolidated fragmented soft‑operator implementations into production‑ready, well‑documented libraries with consistent APIs for JAX and PyTorch.
- Soft sorting networks emerge as the fastest method (1.0 ms for n=4096), delivering ~3.8× speedup over a hard sorting baseline.
- FastSoftSort exhibits linear memory scaling, making it the most memory‑efficient approach for large inputs.
- Collision detection case study (MJX manifold‑point selection) shows that soft ops yield non‑zero gradients for all vertices, while the hard code produces only a sparse signal.

## Why This Works (Mechanism)
The core insight is to replace non‑differentiable, piecewise‑constant operations with continuously differentiable surrogates. Smooth Heaviside approximations (e.g., logistic sigmoid, arctan) enable gradient flow for elementwise thresholds by controlling the transition steepness via a temperature parameter τ. For sorting and ranking, the problem can be reformulated as an optimal transport task: sorting a vector is equivalent to finding a permutation that minimizes the Earth Mover’s Distance to the uniform distribution. Regularized optimal transport (Sinkhorn) provides a smooth, differentiable permutation matrix. Alternative approaches like neural sorting project arguments onto the probability simplex or permutahedron, yielding continuous relaxations of argmax and rank. Sorting networks offer a deterministic, fully differentiable architecture with favorable runtime characteristics. All methods can be combined with straight‑through estimation, which uses the soft gradient while preserving the hard output in the forward pass, thereby reducing bias. The libraries expose these mechanisms behind a uniform interface, allowing users to select the desired trade‑off between smoothness, speed, memory, and gradient quality.

## Foundational Learning
- **Automatic Differentiation (AD):** Traces computations to compute gradients automatically; needed to incorporate softops seamlessly into training loops.  
  *Quick check:* `grad(lambda x: x**2)(3.0)` should return `6.0` in JAX/PyTorch.
- **Discrete Operations in AD:** Ops like sorting, argmax, and thresholding are non‑differentiable at jump points, causing zero or uninformative gradients.  
  *Quick check:* Compute `grad(lambda x: x.argmax())(random_tensor)`; observe almost all zero gradients.
- **Smooth Relaxations:** Replace step functions with smooth approximations (e.g., sigmoid) parameterized by temperature τ; enables gradient flow.  
  *Quick check:* Use a sigmoid instead of a threshold; gradient should be non‑zero near the transition.
- **Optimal Transport for Sorting:** Formulate sorting as a transport problem; Sinkhorn iterations yield a differentiable soft permutation matrix.  
  *Quick check:* Apply Sinkhorn to a cost matrix and verify that the resulting matrix approximates a permutation as τ→0.
- **Straight‑Through Estimator (STE):** Forward pass uses the hard discrete operation; backward pass substitutes a soft gradient. Bridges the gap between exact discrete outputs and differentiable learning.  
  *Quick check:* Implement STE for a sign function; the forward output should be ±1 while backward yields a bounded gradient.
- **Simplex and Permutahedron Projections:** Project onto constrained sets to obtain valid probability vectors or ranking relaxations; essential for maintaining permutation‑like properties.  
  *Quick check:* Project a vector onto the probability simplex and verify sum‑to‑one and non‑negative entries.

## Architecture Onboarding
**Component map:**  
User Application → SoftJAX/SoftTorch API → Soft Operator Dispatcher → Specific Implementation (e.g., SoftSort, FastSoftSort, OT‑based sort) → Relaxation Engine (smooth Heaviside / Sinkhorn / sorting network) → JAX/PyTorch Autograd Kernel → GPU Execution

**Critical path:**  
Forward: Input tensor → soft op → (optional projection) → output.  
Backward: Gradient w.r.t. output → custom VJP rule → gradient propagation through relaxation → gradient w.r.t. input.

**Design tradeoffs:**  
- Smoothness (τ) vs approximation bias / gradient variance.  
- Computational complexity: OT methods O(n²) time/memory; sorting networks O(n log n) but fixed depth; FastSoftSort linear memory but more complex.  
- Straight‑through estimation yields discrete outputs at the cost of gradient bias.

**Failure signatures:**  
- NaNs or extreme values from non‑converged Sinkhorn iterations (check residual).  
- Out‑of‑memory for large n with quadratic methods.  
- Vanishing/exploding gradients when τ is too small/large.  
- Non‑deterministic outputs due to random anchor initialization (fix seeds).

**First experiments:**  
1. **Gradient validity:** Compute `grad(lambda x: soft_sort(x, τ=0.1).sum())(x)` and verify all gradient entries are non‑zero and well‑behaved.  
2. **Performance profiling:** Time forward‑backward of `soft_sort` for n ∈ {1024, 2048, 4096} across methods; compare to `jax.numpy.sort`.  
3. **Collision detection demo:** Replace hard manifold point selection in MJX with `manifold_points_softjax`; compute gradient and confirm full coverage across polygon vertices.
