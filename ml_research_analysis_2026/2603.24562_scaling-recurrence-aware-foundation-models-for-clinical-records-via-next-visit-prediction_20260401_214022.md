# Scaling Recurrence-aware Foundation Models for Clinical Records via Next-Visit Prediction
## Quick Facts
- arXiv ID: 2603.24562
- Source URL: https://arxiv.org/abs/2603.24562
- Reference count: 40
- Primary result: RAVEN (144M parameters, λ=0.5) achieves macro-average AUROC of 0.780 at 2 years and 0.752 at 5 years in zero-shot disease forecasting, outperforming next-token simulation baselines and rivaling a fully fine-tuned BERT model without task-specific training.

## Executive Summary
The paper introduces RAVEN, a recurrence-aware foundation model for longitudinal electronic health records (EHRs) that addresses the pitfall of standard next-token objectives, which are inflated by chronic disease repetition. RAVEN employs a loss weighting scheme that downweights previously observed events during pretraining, encouraging focus on novel clinical changes. This approach enables efficient zero-shot disease forecasting via a single forward pass, avoiding costly Monte Carlo rollouts. Evaluated on seven conditions, RAVEN achieves state-of-the-art zero-shot performance. Scaling analysis reveals a U-shaped relationship between model capacity and performance in data-constrained regimes, highlighting the need to match model size to data volume. The work demonstrates promising generalization to an external benchmark despite significant feature loss.

## Method Summary
RAVEN is pretrained on a large-scale EHR dataset (1.29M patients) using a next-visit multi-label prediction objective. The model processes sequences of visits, where each visit is an unordered set of clinical tokens (diagnoses, medications, labs). A special separator token (<sep>) is inserted between visits. At each <sep>, the model predicts the set of tokens in the subsequent visit. The key innovation is a recurrence-aware loss: for each positive target token, its weight is set to max(λ^{c(k, H_v)}, w_min), where c(k, H_v) counts prior occurrences of token k in the patient’s history, λ is a decay factor (0<λ≤1), and w_min is a minimum weight. This downweights chronic repetitions. The architecture is a decoder-only Transformer with a visit-level causal mask (full attention within a visit, causal across visits) and RoPE positional encoding based on days since first visit. For zero-shot disease forecasting at horizon H, a <sep> token with positional embedding corresponding to t+H is appended; the model’s output logits at that position are pooled over the disease-specific code set to produce a risk score. Inference requires only a single forward pass, avoiding autoregressive rollout.

## Key Results
- RAVEN (144M, λ=0.5) macro-average AUROC: 0.780 at 2 years, 0.752 at 5 years across seven diseases, surpassing all next-token simulation baselines (which use 100 Monte Carlo rollouts).
- The model’s on-time prediction rate nearly doubles for acute MI when λ decreases from 1.0 to 0.25, demonstrating improved sensitivity to novel onsets.
- Scaling analysis shows a U-shaped validation loss curve: with fixed data, increasing model size beyond an optimum degrades performance; optimal capacity (144M) matches the full 1.29M-patient cohort.
- On external EHRSHOT benchmark, RAVEN achieves competitive AUROC (e.g., 0.627 for acute MI) despite a 75% loss of input features due to mismatched clinical code systems.

## Why This Works (Mechanism)
### Mechanism 1: Recurrence-Aware Loss Weighting
The loss weighting scheme downweights tokens that have appeared frequently in the patient’s history, reducing the gradient contribution from chronic repetitions. This encourages the model to allocate capacity to predicting less frequent, potentially novel clinical events. The weight for a positive token k is w = max(λ^{c(k, H_v)}, w_min), where c counts prior occurrences, λ ∈ (0,1] is a decay factor, and w_min is a floor. Evidence: Figure 3 shows on-time rate for acute MI nearly doubles from λ=1.0 to λ=0.25. Break condition: overly strong downweighting (small λ) may harm rare-disease signals.

### Mechanism 2: Horizon-Conditioned Single-Pass Inference
Appending a <sep> token with positional embedding corresponding to the desired horizon H allows the model to directly output a risk score conditioned on that horizon in one forward pass. This avoids Monte Carlo simulation of future trajectories. The model’s logits at the <sep> position are pooled over the disease’s code set and passed through a sigmoid. Evidence: RAVEN matches or exceeds rollout baselines with a single pass. Break condition: requires the model to have internalized temporal dynamics; fails if data lacks long-horizon transitions or architecture cannot capture time dependencies.

### Mechanism 3: Data-Constrained Capacity Matching
In a regime with finite, repeated-epoch training, validation loss follows a U-shaped curve versus model size. Initially, more parameters improve performance; beyond an optimum, overfitting occurs because capacity exceeds the effective information in the fixed dataset. This contradicts standard LLM scaling (near-infinite data). Evidence: Figure 5a shows U-curves with minima shifting right as data budget increases; Figure 6c,d shows 144M parameters yield peak macro AUROC, larger models underperform. Break condition: if truly new data (beyond epochs) becomes available, the overfitting region may shift right, allowing larger models to improve.

**Concept: Data-Constrained Scaling Regime**  
Why needed: Unlike web-scale LLMs, EHR foundation models face finite patient pools; capacity must be matched to data budget to avoid degradation. Quick check: With 500k patients and 50M parameters, the U-curve suggests not increasing parameters further; instead, acquire more data.

## Architecture Onboarding
**Component map**:  
Input Encoder -> Visit-level Transformer -> Next-Visit Head -> Recurrence-Aware Loss Weighter  
(Also: RoPE positional encoding based on inter-visit time; patient-rank sinusoidal embedding for packed sequences.)

**Critical path**:  
1. Tokenize raw EHR into a visit-ordered sequence with <sep> tokens; add age bin/demographic tokens.  
2. Pack multiple patient windows into one sequence, augment each token with a sinusoidal patient-ID embedding.  
3. Forward pass through Transformer with visit-level causal mask (within-visit full attention, across-visits causal).  
4. At each <sep>, apply next-visit head (linear projection + sigmoid) to predict next visit tokens.  
5. Compute weighted BCE loss: positive targets weighted by max(λ^{prior_count}, w_min), negatives weight 1.  
6. Inference: Append <sep> with horizon-H positional encoding; single forward pass; pool logits over disease code set (sum then sigmoid) for risk score.

**Design tradeoffs**:  
- Within-visit order: unordered sets vs. arbitrary ordering; tradeoff: semantic correctness vs. losing intra-visit signals.  
- Recurrence regularization strength λ: stronger (smaller λ) improves on-time rate but may harm AUPRC/rare diseases. Paper uses λ=0.5 as balance.  
- Capacity vs. data: U-shaped curve shows over-parameterization harmful with limited data; need to match capacity to data budget.

**Failure signatures**:  
1. Poor on-time rate despite good AUROC → model repeats chronic conditions; likely λ too high or evaluation cohorts not filtered for prior history.  
2. Validation loss U-curve absent or minima at smallest model → training instability, data leakage, or insufficient capacity.  
3. Zero-shot transfer to EHRSHOT fails (AUROC ~0.5) → severe ontology mismatch or feature loss; check code coverage.

**First 3 experiments**:  
1. Reproduce scaling curve: Train RAVEN (λ=0.5) on 10%, 25%, 50%, 100% data budgets, sweeping model sizes {14M, 47M, 144M, 446M}. Plot validation loss vs. parameters for each budget; expect U-shape with minima shifting right as data increases.  
2. Recurrence regularization ablation: Train 144M model with λ ∈ {1.0, 0.75, 0.5, 0.25} on full data. Evaluate zero-shot 2-year AUROC and on-time rate for acute MI and dementia; expect on-time rate ↑ as λ ↓, AUROC peak near λ=0.5.  
3. Zero-shot transfer sanity check: Apply pretrained 144M/λ=0.5 model to EHRSHOT acute MI task using provided code mappings; report AUROC; expect ~0.62; if <0.55, debug mappings and coverage.

## Open Questions the Paper Calls Out
1. How do recurrence-aware foundation models scale with larger and more diverse datasets, and does the observed U‑shaped validation loss curve generalize beyond a single health system? The study is limited to one cohort of 1.29M patients.
2. Can zero‑shot disease forecasting be improved by robustly handling mismatched clinical code systems and missing features across institutions, rather than relying on lossy mappings? On EHRSHOT, ~75% feature loss occurs due to code-system mismatches.
3. Should recurrence‑aware regularization strength λ be adapted per disease condition or learned from data, instead of using a single global value? The optimal λ varied across conditions in experiments.
4. What is the best way to generate long, coherent patient trajectories using a next‑visit prediction framework, and how does trajectory generation quality impact downstream clinical simulation tasks? The generative potential is not fully leveraged.
5. Can incorporating hierarchical relationships among clinical codes (e.g., ICD‑10 chapters, SNOMED hierarchies) improve generalization and handle out‑of‑vocabulary codes? The flat vocabulary misses broader semantic similarities.

## Limitations
- The recurrence-aware loss may suppress rare-disease signals (e.g., pancreatic cancer) when λ is too small.
- External generalization to EHRSHOT suffers from ~75% feature loss due to code-system mismatches, limiting robustness and reproducibility.
- Important hyperparameters (w_min, patient-ID sinusoidal encoding details, lab discretization thresholds, early-stopping patience) are not fully specified, hindering exact replication.

## Confidence
- Zero-shot forecasting & single-pass inference: High (well-specified evaluation, consistent results).
- Recurrence regularization mechanism: Medium (on-time rate improvements shown, but limited disease ablation and rare-condition trade-offs).
- Data-constrained scaling optimality: High (clear U-shaped curves and capacity shifts across budgets).
- External generalization robustness: Medium (competitive AUROC but mapping and coverage issues).
