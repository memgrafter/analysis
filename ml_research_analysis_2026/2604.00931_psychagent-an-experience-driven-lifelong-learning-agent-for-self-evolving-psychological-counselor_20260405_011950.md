# PsychAgent: An Experience-Driven Lifelong Learning Agent for Self-Evolving Psychological Counselor

## Quick Facts
- **arXiv ID:** 2604.00931
- **Source URL:** https://arxiv.org/abs/2604.00931
- **Reference count:** 40
- **Primary result:** PsychAgent achieves state-of-the-art on the PsychEval benchmark, surpassing strong general LLMs (e.g., GPT-5.4, Gemini-3) and domain-specific baselines on all counselor- and client-level metrics.

## Executive Summary
Current AI psychological counselors remain static after training, lacking the human-like ability to continuously evolve therapeutic skills from clinical experience. PsychAgent introduces an experience-driven lifelong learning framework built on three engines: (1) Memory-Augmented Planning Engine (maintains longitudinal client profiles and session goals), (2) Skill Evolution Engine (extracts new therapeutic skills from high-reward dialogues into a hierarchical tree), and (3) Reinforced Internalization Engine (improves model parameters via rejection fine-tuning on optimal sessions). On the PsychEval benchmark, PsychAgent (based on Qwen3-32B) consistently outperforms prior methods. Human evaluation with 522 dialogues ranks PsychAgent first, and analysis shows improved client emotional trajectories and cross-therapy skill reuse.

## Method Summary
PsychAgent operates through iterative cycles of interaction and internalization. Before each session, the Memory-Augmented Planning Engine synthesizes prior session summaries and client profiles into a strategic goal. During the session, the base model generates responses conditioned on retrieved atomic therapeutic skills from a hierarchical skill tree and the session plan. After the session, a reward model scores parallel rollout trajectories; the optimal one is selected. The Skill Evolution Engine then extracts new atomic skills from this optimal trajectory and updates the skill tree via an append/merge policy. Periodically, the Reinforced Internalization Engine fine-tunes the base model on the aggregated optimal trajectories using rejection fine-tuning. This closed loop allows the agent to autonomously refine its skills and planning from experience.

## Key Results
- Counselor-level shared score: **7.32** (vs. 5.88 for Qwen3-Max, 6.25 for TheraMind)
- Human evaluation (522 dialogues) ranks PsychAgent **first** across Ethics, Interaction, Intervention, Perception.
- Analysis demonstrates improved client emotional trajectories and cross-therapy functional skill reuse.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The Memory-Augmented Planning Engine (MAPE) sustains longitudinal therapeutic continuity, which is critical for effective multi-session counseling.
- **Mechanism:** MAPE constructs a dynamic client profile (Pt) and episodic summaries (Ht) updated after each session. Before a new session, it performs plan reasoning to synthesize these memories into a strategic session goal (Gt), which guides response generation.
- **Core assumption:** Counseling effectiveness depends on coherent long-term context; static context windows or one-off memories are insufficient.
- **Evidence anchors:** [abstract] “Memory-Augmented Planning Engine maintains longitudinal client profiles and session goals.” [section] Section 3.1 details “Dynamic Memory Construction” and “Goal-Oriented Strategic Planning.” [corpus] Neighboring systems (e.g., CA+, TheraMind) address long-term engagement but do not update a structured memory with skill evolution.
- **Break condition:** If memory extraction fails to capture key updates or planning misaligns with the therapeutic stage, longitudinal consistency degrades, leading to repetitive or contradictory counselor behavior.

### Mechanism 2
- **Claim:** The Skill Evolution Engine (SEE) autonomously expands the agent’s therapeutic skill repertoire from successful dialogues, leading to richer and more adaptable interventions.
- **Mechanism:** After a session, SEE retrieves the most relevant meta-skill based on the session goal, extracts a new atomic skill from the high-reward optimal trajectory, and a management policy decides to either append the new skill or merge it with a similar existing one, updating the hierarchical skill tree T.
- **Core assumption:** Expert counselors continuously abstract reusable techniques from clinical experience; a static skill library cannot capture this growth.
- **Evidence anchors:** [abstract] “Skill Evolution Engine extracts new therapeutic skills from high‑reward dialogues into a hierarchical tree.” [section] Section 3.2 describes hierarchical skill taxonomy, context‑aware retrieval, and generative skill evolution. [corpus] Existing AI counseling works (e.g., PsyDT, PsychēChat) focus on style modeling or emotion tracking but lack automatic skill extraction and tree management.
- **Break condition:** Extraction of low-quality or redundant skills, or unbounded tree growth without pruning, would clutter the knowledge base and impair retrieval precision.

### Mechanism 3
- **Claim:** The Reinforced Internalization Engine (RIE) converts the explicit skills and planning logic into improved model parameters via rejection fine‑tuning, yielding more intuitive and consistent counseling behavior.
- **Mechanism:** For each session step, the agent generates N parallel candidate dialogues, scores them with a reward model, selects the optimal trajectory (S*), and uses only that trajectory (with its associated skills and plan) to fine‑une the model. Rejected candidates serve as implicit negatives.
- **Core assumption:** Successful counseling experiences can be distilled into the model’s weights through supervised fine‑tuning on the best trajectories, mimicking reflective practice.
- **Evidence anchors:** [abstract] “Reinforced Internalization Engine improves model parameters via rejection fine‑tuning.” [section] Section 3.3 outlines “Iterative Trajectory Rollout and Selection” and “Internalization via Rejection Fine-Tuning.” [corpus] Synthetic data generation frameworks like MAGneT create multi‑turn dialogues but do not integrate them back into the model.
- **Break condition:** Mis‑scored reward trajectories (e.g., reward hacking) or excessive fine‑tuning without regularization could cause catastrophic forgetting or drift away from therapeutic principles.

## Foundational Learning
- **Concept:** Dynamic Memory Construction  
  **Why needed here:** Multi‑session counseling requires the agent to track evolving client circumstances, emotional states, and intervention outcomes; forgetting or mis‑recording these details harms continuity.  
  **Quick check:** After a session where the client mentions starting a new job, how does the agent update the client profile Pt and session summary Ht?

- **Concept:** Hierarchical Skill Taxonomy  
  **Why needed here:** Therapeutic skills range from broad orientations (e.g., CBT) to atomic actions (e.g., Socratic questioning). A structured tree enables precise selection and systematic evolution without overwhelming the retrieval space.  
  **Quick check:** If a new skill “Thresholded Thought Recording” is extracted from a CBT session, under which meta‑skill and stage should it be inserted?

- **Concept:** Rejection Fine‑Tuning  
  **Why needed here:** Standard supervised fine‑tuning on static data cannot adapt to interactive experience; rejection sampling over parallel rollouts provides a mechanism to reinforce successful strategies while implicitly penalizing failures.  
  **Quick check:** Given N=8 rollouts with rewards R1…R8, how is the optimal session S* chosen and how does it affect the training objective?

## Architecture Onboarding
**Component map:** Base Model (Qwen3-32B) + Memory (Pt, Ht) + Skill Tree (T) -> Memory-Augmented Planning Engine (produces Gt) -> Response Generation (conditioned on Gt & retrieved skill κ) -> Client Interaction -> Post‑session: Skill Evolution Engine (updates T) & Reinforced Internalization Engine (periodic fine‑tuning) -> Updated Memory/Skill Tree/Model

**Critical path:**
1. Initialize memory, skill tree, and model.
2. For each client session:
   a. Load prior memory (Pt‑1, Ht‑1).
   b. Run MAPE to produce session goal Gt.
   c. For each dialogue turn: retrieve relevant atomic skill κ from T given (ui, Mt, Gt), prepend κ, and generate response.
   d. After session completion, compute reward R; select optimal trajectory S*t via rejection sampling from N rollouts.
   e. Update memory: extract new attributes and summary to form (Pt, Ht).
   f. Run SEE to extract new skills and possibly merge, updating T.
3. Periodically (e.g., after every M sessions) collect all optimal sessions {S*t} and perform one step of rejection fine‑tuning on the model.

**Design tradeoffs:**
- Skill tree depth vs. retrieval speed: Deeper hierarchy offers fine‑grained categorization but requires careful similarity matching; flatter structure risks ambiguity.
- Number of rollouts N: Larger N yields better exploration but increases compute cost linearly.
- Memory representation: Structured (profile + summaries) is interpretable and space‑efficient but may lose nuances compared to raw dialogue history; the hybrid approach balances detail and abstraction.
- Rejection fine‑tuning vs. full RL: RFT is simpler and more stable but might not optimize token‑level decisions; full RL could address that but introduces complexity and instability.

**Failure signatures:**
- Client emotional trajectories plateau or worsen across sessions.
- Skill tree shows increasing duplicate atomic skills or excessive branching without merging.
- Counselor responses become incoherent across sessions (e.g., contradictory advice), indicating memory update failure.
- Reward model scores become too uniform, making selection uninformative (potential reward hacking).
- Fine‑tuning leads to sudden drop in performance on validation metrics (catastrophic forgetting).

**First 3 experiments:**
1. **Baseline replication:** Train PsychAgent on the PsychEval training split and evaluate on the official benchmark; verify scores exceed Qwen3‑Max and TheraMind as in Table 1.
2. **Ablation validation:** Remove each engine one at a time (MAPE, SEE, RIE) and confirm performance drop as reported in Table 3, especially the larger impact of SEE.
3. **Skill evolution audit:** Extract skills from a sample of high‑reward dialogues and manually inspect the proportion that adds practical increments beyond the initial library (as in Section C.1).

## Open Questions the Paper Calls Out

### Question 1
How do the individual contributions of the Memory-Augmented Planning, Skill Evolution, and Reinforced Internalization engines disentangle in real-world, long-term counseling outcomes?
**Basis in paper:** Ablation studies show all three improve performance, with Skill Evolution removal causing the largest drop. However, results are on the PsychEval benchmark (simulated dialogues). Future work needs evaluation "in more realistic counseling settings".
**Why unresolved:** Unclear whether gains stem primarily from skill discovery/internalization, improved longitudinal coherence, or their synergy in a dynamic, open-ended environment. The benchmark may not isolate the unique value of self‑evolution.
**What evidence would resolve it:** A controlled longitudinal study with real or high‑fidelity simulated clients, where each engine is systematically disabled or replaced across multiple therapy modalities. Outcome measures should include both counselor competence metrics and validated client symptom change over many sessions.

### Question 2
To what extent are the "practice‑grounded" skills extracted by the Skill Evolution Engine genuinely novel therapeutic techniques versus adaptive refinements or contextual instantiations of pre‑existing canonical skills?
**Basis in paper:** Case studies state: "the strongest supported conclusion is not that the model invents entirely new therapy techniques, but that it reliably distills practically enriched skill units." Novelty is defined as adding "non‑trivial practical increments" like thresholds, templates, sequencing rules.
**Why unresolved:** The definition of "non‑trivial" is qualitative and anchored to the initial skill library's granularity. Unclear if these increments represent meaningful clinical innovation or just session‑specific parameterization. The audit found "no sufficiently supported candidates for entirely novel therapy techniques" but this depends on the library's completeness and audit criteria.
**What evidence would resolve it:** A blinded expert panel review comparing extracted skills against canonical literature for each therapy school. Panel rates each skill on dimensions like "novel intervention principle," "new application context for known principle," and "parameter refinement." A taxonomy of skill "increment types" linked to clinical guidelines would clarify the nature of the evolution.

### Question 3
Does the internalization process via Rejection Fine‑Tuning (RFT) lead to robust, generalizable skill mastery, or does it risk overfitting to the reward model's preferences and the specific trajectories in the training rollout?
**Basis in paper:** RIE uses RFT on the "optimal session" selected from parallel rollouts by a reward model (LLM‑as‑a‑Judge). Performance gains are shown but diversity or robustness of internalized behaviors is not analyzed. Human evaluation shows strong agreement but a "ceiling effect" on some dimensions.
**Why unresolved:** RL‑style fine‑tuning on model‑generated trajectories can propagate and amplify biases in the reward model or lead to "reward hacking." The paper does not report measures like variance of selected optimal trajectories, out‑of‑distribution generalization tests, or analysis of failures on atypical dialogues.
**What evidence would resolve it:** (1) Analyze consistency of the internalized model's skill selection across diverse client profiles and unexpected conversational turns. (2) Test on held‑out therapy schools or novel problem types not seen during evolution. (3) Compare trajectories from the internalized model to those from the retrieval‑based version to identify which skills become "intuitive" and which are lost, assessing clinical appropriateness of this shift.

### Question 4
Are the observed cross‑therapy functional skill reuses (e.g., "Goal‑to‑Practice Bridge") evidence of genuine principle‑based generalization or merely superficial pattern matching on common dialogue scaffolding (e.g., "summarize and assign homework")?
**Basis in paper:** Section C.3 claims "cross‑therapy reuse at the functional‑family level" and lists families like "Progress Consolidation Package" appearing across multiple schools. It qualifies: "the strongest evidence does not come from exact cross‑therapy bundles... instead, the more informative pattern is cross‑therapy reuse at the functional‑family level."
**Why unresolved:** Evidence is based on manual case studies and frequency counts. Difficult to rule out that these "families" reflect generic conversational routines common to all supportive dialogues rather than therapy‑specific principles successfully ported. "Exact cross‑therapy combinations remain limited."
**What evidence would resolve it:** A fine‑grained ablation where specific micro‑skills within a functional family are ablated (e.g., remove the "rating" or "template" component in the "Rated Reappraisal Loop") and measure the drop in effectiveness across different therapy contexts. If the core functional logic is truly transferable, disrupting it should harm performance in all involved therapies similarly. Alternatively, probe the model's internal representations to see if the same neural pathways are activated when deploying the same functional package in different therapy contexts.

### Question 5
How does the Skill Evolution Engine's hierarchical skill tree manage conflicts and hierarchies between therapeutic paradigms (e.g., CBT vs. Psychodynamic) as new skills are added, and does this structure support or hinder the emergence of integrative approaches?
**Basis in paper:** The hierarchical tree is defined with Root Paradigms (CBT, Humanistic, etc.) as the top level. The evolution process adds atomic skills under a retrieved Meta‑Skill *within a stage*. The paper does not discuss what happens if a new skill extracted from a CBT trajectory is conceptually more aligned with a Humanistic Meta‑Skill, or if skills from different roots conflict. Cross‑therapy reuse suggests some integration, but the tree structure enforces hard boundaries at the paradigm level.
**Why unresolved:** The evolution policy (πmgmt) only decides to append or merge *within the identified Meta‑Skill branch*. There is no mechanism for re‑categorizing a skill under a different Root Paradigm or Meta‑Skill if the initial retrieval was suboptimal. This could lead to a siloed knowledge base that does not evolve toward a truly integrative counselor.
**What evidence would resolve it:** Analyze the distribution of evolved skills: do they remain strictly within their initial paradigm's branches? Are there cases where a skill from one paradigm is repeatedly applied in another context? Implement a meta‑categorization step that allows skills to be re‑parented based on usage patterns across therapies, and measure if this improves cross‑therapy transfer or causes instability.

## Limitations
- Reward model details (architecture, training data, rubrics) are undisclosed; reliance on LLM‑as‑a‑Judge may introduce biases and reward hacking vulnerabilities.
- Skill management policy (append/merge thresholds) is vague, risking noisy, redundant, or unbounded skill trees.
- Memory update mechanics (extraction prompts/models) are unspecified; potential loss of critical client information.

## Confidence
- **Memory‑Augmented Planning Engine** enables longitudinal continuity: **Medium** (ablation indicates benefit but independent validation of memory fidelity lacking).
- **Skill Evolution Engine** autonomously expands therapeutic skills: **Medium** (strong ablation impact but extraction quality and threshold sensitivity unverified).
- **Reinforced Internalization Engine** improves model via rejection fine‑tuning: **Medium** (performance gains observed but stability and reward model dependence need further study).

## Next Checks
1. **Reward model transparency:** Rebuild the reward model using open‑source LLMs with documented rubrics; compare session selection fidelity and final performance.
2. **Skill extraction robustness:** Systematically vary similarity thresholds for skill merging; evaluate resulting tree size, retrieval precision, and downstream counseling quality.
3. **Longitudinal stability test:** Run PsychAgent over 20+ sessions per client in a simulated environment, tracking memory consistency, skill usage drift, and client emotional trajectory to detect forgetting or regression.
