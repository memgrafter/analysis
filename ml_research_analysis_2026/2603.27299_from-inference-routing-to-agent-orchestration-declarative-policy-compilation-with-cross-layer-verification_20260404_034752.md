# From Inference Routing to Agent Orchestration: Declarative Policy Compilation with Cross-Layer Verification

## Quick Facts
- **arXiv ID:** 2603.27299
- **Source URL:** https://arxiv.org/abs/2603.27299
- **Reference count:** 16
- **Primary result:** A multi-target compiler emits verified, cross-layer consistent artifacts from a single non-Turing-complete DSL, eliminating policy drift for signal thresholds, routing logic, and audit trails across inference gateways, orchestration frameworks, protocol boundaries, and infrastructure.

## Executive Summary
Managing content-aware routing across separate architectural layers (inference gateway, agent orchestration, protocol gates, infrastructure) typically suffers from policy drift and coordination overhead because each layer’s configuration evolves independently via ad-hoc implementations. This paper introduces a declarative policy language and a compiler that generates verified artifacts for all target layers from a single source file. The compiler enforces invariants such as exhaustiveness, conflict-freedom, and referential integrity, ensuring that a single parameter change propagates atomically to every deployed component. Audit traces are structurally coupled to the compiled decision logic, guaranteeing that logs faithfully represent executed behavior. The approach is production-deployed for inference routing and prototyped for orchestration (LangGraph, OpenClaw), protocol gates (MCP, A2A), and infrastructure (Kubernetes, YANG/NETCONF).

## Method Summary
The core method is a multi-target compiler for a restricted, non-Turing-complete domain-specific language (DSL). The DSL declares signals (e.g., `jailbreak`, embedding intents), groups them for tie-breaking, and defines decision trees with branching conditions on signal thresholds. The compiler performs static analysis on the abstract syntax tree (AST) to verify five cross-layer properties: exhaustiveness (all inputs reach a branch), conflict-freedom (conditions are mutually exclusive), dead branch detection, referential integrity (e.g., network endpoints vs. routes), and cross-compilation consistency. It then emits target-specific artifacts: configuration for an inference gateway, Python code (LangGraph) or JSON hooks (OpenClaw) for orchestration, gate functions for MCP/A2A, and Kubernetes/YANG specifications for infrastructure. Each emitted artifact embeds a hash of the DSL source, enabling drift detection. Signal models are assumed pre-calibrated; the DSL only references them by name and sets thresholds.

## Key Results
- **Cross-layer consistency:** A single DSL source guarantees identical policy parameters (e.g., thresholds) across all compiled targets; changing one value requires only recompilation.
- **Compiler-enforced verification:** Static checks ensure decision trees are exhaustive and conflict-free, with decidability guarantees varying by signal type (crisp, geometric, classifier).
- **Structurally coupled auditability:** The audit trace schema is generated from the same AST as the routing logic, making it impossible for logs to describe a different execution path than the one taken.

## Why This Works (Mechanism)

### Mechanism 1: Single-Source Compilation Enforces Cross-Layer Consistency
- **Claim:** A single DSL source compiled to multiple targets eliminates policy drift across layers (inference gateway, agent orchestration, protocol gates, infrastructure).
- **Mechanism:** The compiler emits verified artifacts for each target from the same declarative source, enforcing compiler invariants (exhaustiveness, conflict-freedom, referential integrity) and embedding a consistent source hash. A parameter change (e.g., threshold) propagates to all targets in one step.
- **Core assumption:** The DSL's non-Turing-complete semantics enable static analysis that is both tractable and composable across heterogeneous emission targets.
- **Evidence anchors:**
  - Abstract: "a single parameter change (e.g., a signal threshold) propagates to every target in one step, eliminating the primary source of policy drift."
  - Section 5.4: "A single set of signal declarations governs the full stack... If the administrator changes the jailbreak threshold from 0.8 to 0.75, every target... updates on recompilation."
- **Break condition:** If any target requires runtime logic not expressible in the DSL (e.g., mutable state, loops), that layer diverges from the compiled source, re-introducing drift.

### Mechanism 2: Audit Traces Generated from the Decision AST
- **Claim:** Audit traces are structurally coupled to the decision logic, making it impossible for logs to describe a different decision tree than executed.
- **Mechanism:** The compiler generates the audit trace schema directly from the same AST that produces the routing logic. The trace includes named components, thresholds crossed, and branch identifiers. An append-only reducer ensures sequential integrity during execution.
- **Core assumption:** The orchestration framework's state channel (e.g., LangGraph's `audit_trace` field with `operator.add` reducer) preserves the trace without tampering.
- **Evidence anchors:**
  - Section 4.1: "The trace structure is generated from the same AST that generates the routing logic. It is not possible for the trace to describe a different decision tree than the one that executed."
  - Section 4.1: "The audit trace channel uses an append-only reducer. Downstream nodes can append but not overwrite previous entries."
- **Break condition:** If the persistence layer allows direct modification of audit entries, structural correspondence alone does not guarantee integrity; cryptographic hash chaining would be needed.

### Mechanism 3: Type-Based Verification Decidability
- **Claim:** Verification guarantees (exhaustiveness, conflict-freedom, referential integrity) are made explicit per signal type, with decidable properties for crisp/geometric signals and empirical testing for opaque classifiers.
- **Mechanism:** The compiler performs static analysis based on signal predicate type: crisp predicates (Boolean) are fully decidable via BDD/SMT; geometric predicates (embedding similarity) are decidable under vector space assumptions; classifier predicates (jailbreak, PII) rely on `Test` block validation.
- **Core assumption:** The decidability hierarchy from ProbPol (Liu et al., 2026) correctly classifies signal types and the compiler implements the corresponding checks.
- **Evidence anchors:**
  - Section 4.3: "Decidability by signal type... Crisp predicates... are fully decidable; geometric predicates... are decidable under assumptions; classifier predicates... are opaque functions; only empirical testing is possible."
  - Section 3.1: Compiler performs "five cross-target checks: (i) exhaustiveness... (ii) conflict-freedom... (iii) dead branch detection... (iv) referential integrity... (v) cross-compilation consistency."
- **Break condition:** If signal definitions change at runtime (e.g., model retraining) without recompilation, the static guarantees no longer match the deployed signal behavior.

## Foundational Learning
- **Non-Turing-complete DSL design:** The language restriction (no mutable state, loops) enables decidable verification (exhaustiveness, conflict-freedom) across all targets. Without it, static analysis becomes undecidable.  
  *Quick check:* Can you prove that every possible input to a `Decision_Tree` reaches exactly one `ELSE` branch? If yes, the DSL's design succeeded.
- **Signal_Group tie-breaking via Voronoi normalization:** Prevents co-firing of multiple intent signals by using softmax with temperature τ→0, ensuring at most one signal exceeds the >1/k threshold.  
  *Quick check:* If two embedding signals receive identical cosine similarity scores after softmax, what routing outcome occurs? (Answer: Both fall below >1/k, triggering the `ELSE` branch.)
- **Compilation target mapping:** Different frameworks (LangGraph vs. OpenClaw) and infrastructure layers (K8s, YANG) have fundamentally different execution models; the compiler translates DSL constructs while preserving semantics.  
  *Quick check:* How does a `NETWORK` block become a valid Kubernetes `NetworkPolicy` egress rule? (Answer: Extract `host`, `port`, `methods`; emit `to: - ipBlock: cidr: 0.0.0.0/0 except: [...] ports: [...]`, cross-referenced with skills.)

## Architecture Onboarding
- **Component map:**  
  `.sr` DSL source -> Compiler (static analysis, verification) -> emitted artifacts (inference gateway config, LangGraph/OpenClaw code, MCP/A2A gate functions, K8s/YANG specs) -> runtime execution (orchestration framework, infrastructure controllers) with audit trace appended.
- **Critical path:**  
  1. Edit `.sr` file (change threshold, add signal, modify tree).  
  2. Run compiler: `dslc policy.sr --targets all`.  
  3. Compiler validates; fails if branch unsatisfiable or signal undefined.  
  4. Emits artifacts with embedded `source-hash`.  
  5. Deploy artifacts to respective systems.  
  6. Runtime executes: signals evaluate → decision tree traversed → audit trace appended → target action invoked.
- **Design tradeoffs:**  
  - Expressiveness vs. verifiability: DSL excludes loops/mutable state; complex orchestration stays in host framework (LangGraph nodes, plugins). Policy layer only gates decisions.
  - Compilation vs. runtime coupling: Signal models referenced by name; thresholds baked in. Model changes require DSL recompilation.
  - Single source vs. target-specific tuning: Same threshold applies to all layers; context-specific tuning requires separate `SIGNAL` declarations or trees.
- **Failure signatures:**  
  - Audit trace mismatch: `branch_idx` does not correspond to any `DECISION_TREE` in current `.sr` → stale artifact or log tampering.
  - Cross-target hash divergence: `source-hash` label differs between K8s ConfigMap and NetworkPolicy → incomplete propagation.
  - Unsatisfiable branch: Compiler error "Branch condition is a strict subset of higher-priority branch" → dead code.
  - Signal co-firing: `Signal_Group` softmax yields multiple signals > 1/k → conflict.
  - Model-score mismatch: All inputs take default branch → embedding/threshold calibration mismatch.
- **First 3 experiments:**  
  1. **Propagation test:** Change an embedding threshold in `.sr`, recompile, verify new value in LangGraph, OpenClaw, K8s ConfigMap, YANG module.
  2. **Conflict detection test:** Add a branch with `embedding("intent_A") AND embedding("intent_B")` in a `Signal_Group`; compiler should flag "Signal co-firing violation".
  3. **Audit trace integrity test:** Execute a workflow, capture audit trace, confirm `branch_idx` and `thresholds_crossed` match current `.sr`; compare `source_hash` to K8s ConfigMap label.

## Limitations
- Geometric signal conflict detection assumes vector space decidability; real embedding distributions may violate assumptions, causing false positives/negatives.
- Opaque classifiers (jailbreak, PII) rely on empirical `TEST` blocks; coverage is limited to provided cases, leaving unseen model behaviors unverified.
- Several target emitters (OpenClaw hooks, YANG/NETCONF, `PolicySpec` CRD) are described but not fully implemented or validated.
- Signal model calibration thresholds are hand-tuned; no procedure for maintaining consistency when underlying models retrain or drift.

## Confidence
- **Cross-layer consistency (Mechanism 1):** Medium. Production deployment for inference routing provides evidence, but only prototype validation for other layers; compiler invariant enforcement remains a black box.
- **Audit trace coupling (Mechanism 2):** Low. Claim of "impossible" divergence assumes perfect reducer integrity and no log tampering; no independent validation exists.
- **Verification guarantees (Mechanism 3):** Medium. Decidability hierarchy is theoretically grounded in prior work (ProbPol), but empirical validation is narrow (synthetic tests, limited signal types).

## Next Checks
1. **Cross-target propagation stress test:** Change a threshold and a `Signal_Group` member simultaneously in a complex policy. Recompile and automatically diff all emitted artifacts (LangGraph, K8s, YANG) to confirm atomic updates and identical `source-hash`.
2. **Geometric signal conflict boundary test:** Construct `DECISION_TREE` branches with overlapping embedding predicates near the decision boundary (e.g., cosine similarity 0.701 vs 0.699). Validate compiler flags conflicts or unsatisfiable branches as predicted.
3. **Audit trace adversarial integrity test:** Execute a route that exploits a classifier's edge case (e.g., jailbreak signal near threshold). Manually alter a single audit log entry's `branch_id` and verify that downstream trace-to-policy reconciliation detects the mismatch.
