# MammoWise: Multi-Model Local RAG Pipeline for Mammography Report Generation

## Quick Facts
- **arXiv ID**: 2602.22462  
- **Source URL**: https://arxiv.org/abs/2602.22462  
- **Reference count**: 40  
- **Primary result**: MammoWise, a local multi-model VLM pipeline with RAG and QLoRA fine-tuning, achieves state-of-the-art mammography report generation (BERTScore up to 0.9401) and classification (BI-RADS accuracy 0.7545) on VinDr-Mammo and DMID datasets.

## Executive Summary
Mammography reporting is a high-volume, time-sensitive task where automated support can alleviate radiologist workload. MammoWise addresses this by introducing a privacy-preserving, locally deployable pipeline that integrates multiple open-source vision-language models (MedGemma, LLaVA-Med, Qwen2.5-VL) served via Ollama. The system supports flexible prompting strategies—zero-shot, few-shot, and chain-of-thought—and includes an optional retrieval-augmented generation (RAG) module using ChromaDB to incorporate case-specific context. For classification tasks (BI-RADS, breast density, calcifications), the authors demonstrate that prompting alone yields high variance, but QLoRA fine-tuning of MedGemma dramatically stabilizes and improves accuracy. Evaluated on VinDr-Mammo and DMID, MammoWise attains strong report quality (BERTScore up to 0.9401, ROUGE-L up to 0.4347) and classification metrics that match or exceed prior state-of-the-art. The framework provides a practical, extensible architecture for local VLM deployment in mammography, unifying prompting, RAG, and fine-tuning.

## Method Summary
MammoWise is a modular pipeline that processes mammography images through several stages. First, images are preprocessed and optionally fed into a multimodal RAG module that queries a ChromaDB vector store to retrieve relevant historical cases. These retrieved contexts, along with few-shot examples and chain-of-thought instructions, are assembled into a prompt. The prompt is then passed to one of several open-source VLMs (MedGemma, LLaVA-Med, Qwen2.5-VL) served locally via Ollama, which generates either a free-text report or classification labels. For classification, the authors initially experiment with direct prompting but observe high variance; they subsequently apply QLoRA (quantized low-rank adaptation) to fine-tune MedGemma on annotated data, yielding a stable, high-accuracy classifier. The entire system runs locally, ensuring data privacy and allowing flexible configuration of models, prompts, and RAG usage.

## Key Results
- Report generation benefits from few-shot and RAG, achieving BERTScore up to 0.9401 and ROUGE-L up to 0.4347 on VinDr-Mammo and DMID.
- Classification accuracy sees dramatic improvement with QLoRA fine-tuning of MedGemma: BI-RADS 0.7545, breast density 0.8840, calcification 0.9341, matching or exceeding previous SOTA; prompting-only approaches show high variance.
- RAG provides modest gains on some classification tasks but is insufficient for stable performance; fine-tuning is essential for reliable results.

## Why This Works (Mechanism)
MammoWise succeeds through a synergistic combination of three key techniques. First, it leverages powerful open-source VLMs pre-trained on medical data, providing a strong baseline for image understanding and text generation. Second, the optional RAG module injects case-specific knowledge from a curated database of similar mammograms, enhancing report comprehensiveness and reducing hallucinations, particularly for rare findings. Third, QLoRA fine-tuning efficiently adapts the VLM to the specific classification tasks with minimal additional parameters, stabilizing performance and overcoming the high variance observed in prompting-only setups. The local deployment via Ollama ensures low-latency, privacy-conscious inference, while the modular design allows systematic exploration of prompting strategies and model choices.

## Foundational Learning
- **Vision-Language Models (VLMs)**: Needed to jointly interpret medical images and generate coherent radiology reports. Quick check: Does the model produce fluent, medically plausible descriptions from images?
- **Retrieval-Augmented Generation (RAG)**: Needed to supplement the model’s knowledge with up-to-date, case-specific examples, improving accuracy and reducing hallucinations. Quick check: Does retrieved context measurably enhance report quality on similar cases?
- **QLoRA (Quantized Low-Rank Adaptation)**: Needed to fine-tune large VLMs efficiently on limited classification data without catastrophic forgetting. Quick check: Does parameter-efficient adaptation yield better classification accuracy than prompting alone?
- **Local Model Serving (Ollama)**: Needed for privacy-preserving, offline deployment with controlled infrastructure. Quick check: Can the pipeline run on available hardware with acceptable latency and memory footprint?
- **Chain-of-Thought Prompting**: Needed to encourage step-by-step reasoning for complex medical tasks. Quick check: Does explicit reasoning improve classification consistency and explainability?

## Architecture Onboarding
**Component map** (plain text):  
Input Image → Preprocessing → [Optional RAG: Query ChromaDB → Retrieve Context] → Prompt Assembly (few-shot + chain-of-thought) → VLM Inference (via Ollama: MedGemma/LLaVA-Med/Qwen2.5-VL) → Output (Report/Classification).  
For classification, a fine-tuning branch exists: Annotated data → QLoRA fine-tuning → Fine-tuned MedGemma.

**Critical path**: The core generation flow: image → (RAG) → prompt → VLM → report. The classification path branches at the VLM stage, either using the base model via prompting or the fine-tuned variant.

**Design tradeoffs**:  
- Local vs. cloud: Local ensures privacy but constrains model size/speed; cloud offers more compute but raises security concerns.  
- Model selection: Multiple VLMs enable comparison but increase maintenance; MedGemma was prioritized for fine-tuning due to its medical pretraining.  
- RAG vs. fine-tuning: RAG is flexible and avoids retraining but depends on database quality; fine-tuning yields stable classification but requires labeled data and additional compute.  
- Prompt complexity: Few-shot and chain-of-thought improve quality but increase token usage and latency.

**Failure signatures**:  
- Low BERTScore/ROUGE indicates poor report generation.  
- High variance in classification accuracy across random seeds or prompts signals instability in prompting-only approaches.  
- Out-of-memory errors during inference suggest hardware limitations for local VLM deployment.  
- Slow retrieval from ChromaDB or long inference times hinder real-time clinical use.

**First experiments** (exactly 3):  
1. Baseline evaluation: Run zero-shot prompting with all three VLMs on a validation set to compare raw generation quality and classification performance.  
2. RAG ablation: Enable RAG with varying numbers of retrieved cases (k=1,3,5) to measure impact on report similarity and classification accuracy.  
3. Fine-tuning optimization: Perform QLoRA fine-tuning of MedGemma with different rank values (r=8,16,32) and learning rates to identify the best trade-off between accuracy and overfitting on classification tasks.

## Limitations
- Generalizability: Evaluation is restricted to VinDr-Mammo and DMID; performance on other vendors, populations, or imaging protocols is unknown.  
- Operational practicality: No reporting of inference latency, memory footprint, or hardware requirements, leaving real-world throughput for high-volume clinical use uncertain.  
- Clinical utility: Metrics are limited to linguistic similarity and classification accuracy; no human evaluation of report correctness, omission of critical findings, or impact on radiologist workflow.

## Confidence
- Report generation quality (BERTScore/ROUGE): Medium  
- Classification accuracy (QLoRA-fine-tuned MedGemma): Medium‑High  
- Classification accuracy (prompting-only): Low  
- "Practical, extensible framework" claim: Low  
- Privacy-preserving local deployment: Medium
