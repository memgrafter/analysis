# Poster: Camera Tampering Detection for Outdoor IoT Systems

## Quick Facts
- arXiv ID: 2602.05706
- Source URL: https://arxiv.org/abs/2602.05706
- Reference count: 7
- Primary result: CNN achieves 99.75% accuracy but requires 37.8 MB and 2400 training images; rule-based uses 8 reference images, 8.77 KB, and processes in 0.07 sec/image with 90.50% accuracy.

## Executive Summary
This study tackles camera tampering detection in outdoor IoT systems using still images, targeting blur, rotation, and obstruction from vandalism or environmental factors. Two approaches are evaluated: a rule-based technique leveraging ORB keypoint matching, Laplacian blur detection, and homography for rotation, calibrated with only 8 normal reference images; and a CNN with custom convolutional layers trained on 2400 balanced images. The CNN significantly outperforms in accuracy (99.75% vs. 90.50%), but demands far more resources (37.8 MB model, 2400 samples). The rule-based method is ultra-lightweight (8.77 KB) and fast (0.07 sec/image), making it suitable for resource-constrained edge devices with minimal calibration, illustrating a core accuracy-resource trade-off for real-world deployment.

## Method Summary
The rule-based method establishes a baseline of normal scene appearance from 8 reference images. For a test image, it computes ORB keypoints and matches them against all references using BFMatcher. A low count of "good matches" flags potential tampering, triggering specific checks: Laplacian variance for blur, pixel intensity standard deviation for obstruction, and homography to estimate rotation angles (flagging >50°). No abnormal examples are required. The CNN uses a custom architecture: three convolutional blocks (32, 64, 128 filters) with ReLU and max-pooling, flattened into a dense layer (128 units) and a sigmoid output for binary classification. It is trained on 2400 images (50% abnormal) to learn discriminative tampering features. Both methods are tested on a single 10-day outdoor dataset.

## Key Results
- CNN achieves superior performance: accuracy 0.9975, precision 0.9983, recall 0.9966, F1-score 0.9974.
- Rule-based method yields lower metrics: accuracy 0.9050, precision 0.9036, recall 0.9066, F1-score 0.9051.
- CNN requires 37.8 MB model size and 2400 training samples; rule-based uses only 8 reference images (8.77 KB) and processes in 0.07 sec/image.

## Why This Works (Mechanism)
1. **Rule-based deviation detection**: Measures statistical deviation from a baseline of normal reference images. ORB keypoint matching identifies stable features; low match counts trigger blur (Laplacian variance), obstruction (pixel std-dev), or rotation (homography >50°) checks. Assumes tampering alters keypoint stability, sharpness, or uniformity. Evidence: [abstract] outlines ORB/Laplacian/homography; [section 2.1] details pipeline. Break condition: unmodeled environmental changes (e.g., new foliage, lighting shifts) cause false positives without reference updates.
2. **CNN feature learning**: Learns discriminative patterns directly from labeled data. Convolutional layers extract hierarchical features from pixels; dense layer classifies. Assumes training diversity captures tampering imperfections. Evidence: [abstract] CNN architecture and accuracy; [section 2.2] layer specs and dataset size. Break condition: distribution shift (new location, unseen tamper types) degrades performance without retraining.
3. **Resource-accuracy trade-off**: Rule-based depends on reference images (8 normals, no abnormal), yielding tiny footprint (8.77 KB) but lower accuracy. CNN depends on 2400 balanced images, yielding high accuracy (37.8 MB) but heavy compute. Evidence: [abstract] trade-off statement; [section 2.3, Table 1] direct comparison. Break condition: rule-based fails with insufficient references; CNN fails on edge hardware limits or if abnormal data is scarce.

## Foundational Learning
- **ORB Feature Detection**: Detects stable keypoints for matching under rotation/illumination changes. Needed for rule-based baseline comparison. Quick check: Why might ORB fail on severely blurred images? (Blur reduces distinct keypoints, lowering match counts.)
- **CNN Binary Classification**: Uses layered convolutions to learn hierarchical tampering features from pixels. Needed for supervised discrimination. Quick check: How does class imbalance affect training, and how is it addressed here? (Balanced dataset (50% abnormal) used.)
- **Homography Estimation**: Computes geometric transformation matrix to derive rotation angle. Needed for quantifying rotational tampering. Quick check: What assumption does homography make about the scene, and when might it be violated? (Assumes planar scene or parallel camera; violated by 3D depth or non-rigid obstructions.)

## Architecture Onboarding
- **Component map**: Input → Grayscale → Branch A: ORB → BFMatcher → Threshold → {Laplacian→blur, std-dev→obstruction, homography→rotation} | Branch B: Conv(32)→Pool→Conv(64)→Pool→Conv(128)→Pool→Flatten→Dense(128)→Sigmoid→Classification.
- **Critical path**: Rule-based: Extract ORB from test and 8 references; match; count good matches; if below threshold, apply blur/obstruction checks; if above, compute homography and check angle >50°. CNN: Preprocess to tensor; forward pass through conv blocks and dense layer; threshold sigmoid output.
- **Design tradeoffs**: Rule-based: ultra-lightweight (8.77 KB), no abnormal data, fast (0.07 sec/image), but accuracy limited (90.50%) and sensitive to environmental drift. CNN: high accuracy (99.75%), robust within distribution, but heavy (37.8 MB), requires 2400 labeled images, slower on edge.
- **Failure signatures**: Rule-based: False positives from routine scene changes (e.g., moving leaves reducing matches); false negatives if tampering preserves keypoint counts (e.g., subtle obstruction). CNN: Overfitting to specific tamper patterns; failure on novel types (e.g., adhesive films) or new viewpoints.
- **First 3 experiments**:
  1. Reproduce rule-based threshold calibration: Using 8 normal references, compute distribution of good matches between normal-normal pairs; set threshold (e.g., 5th percentile); validate on normal test set.
  2. Benchmark CNN inference on edge hardware (e.g., Raspberry Pi 2): Measure latency, RAM usage with 37.8 MB model; assess real-time feasibility.
  3. Stress-test rule-based rotation: Generate synthetic rotations (10° increments) from normal image; verify homography angle accuracy; confirm 50° threshold corresponds to perceptible rotation.

## Limitations
- Rule-based method is sensitive to unmodeled environmental changes (e.g., seasonal foliage, lighting shifts), likely causing false positives without frequent reference updates.
- CNN performance depends on training data diversity; the 2400-image dataset's coverage of tamper types and conditions is unspecified, risking poor generalization to novel attacks or new sites.
- Evaluation lacks real-world edge hardware benchmarks and considers only still images, ignoring temporal video-based tampering attacks.

## Confidence
- **High**: Performance metrics (CNN vs rule-based accuracy, precision, recall) — directly compared in Table 1.
- **High**: Resource efficiency claims (model size, inference time) — explicitly reported.
- **Medium**: Real-world deployability on edge devices — logical but not empirically validated on typical hardware.
- **Low**: Generalization to new environments — no stress tests for distribution shift across locations or seasons.
