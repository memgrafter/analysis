# AsgardBench -- Evaluating Visually Grounded Interactive Planning Under Minimal Feedback

## Quick Facts
- arXiv ID: 2603.15888
- Source URL: https://arxiv.org/abs/2603.15888
- Reference count: 40
- Primary result: Top vision-language models achieve 68–77% success with images, but drop to 22–36% in text-only conditions.

## Executive Summary
AsgardBench introduces a benchmark to isolate visually grounded interactive planning under minimal feedback. Built on AI2-THOR, it removes navigation and low-level control, focusing on conditional branching due to state variations. Agents must replan each turn based on visual observations and minimal success/failure signals. Evaluations of state-of-the-art VLMs show a significant drop in performance without visual input, highlighting the critical role of visual grounding. Ablations confirm reliance on visual cues like the hand overlay and previous-state images. The benchmark exposes weaknesses in visual grounding, state tracking, and plan repair.

## Method Summary
AsgardBench evaluates agents on 108 tasks across 12 types in the AI2-THOR simulator. At each turn, the agent receives two RGB images (previous and current state, with a translucent hand overlay when holding an object), action history with success/failure feedback, available objects/actions, world rules, the task instruction, and three in-context examples. The agent outputs a full action plan; only the first action executes, after which a new observation and feedback are provided. This loop forces continuous replanning. No training is performed; pretrained VLMs are queried via API with temperature 0. Success is binary: all task-specific goals must be satisfied. Ablations modify inputs (e.g., text-only, remove hand overlay, no previous image) to test dependencies.

## Key Results
- State-of-the-art VLMs (e.g., Claude Opus 4.5, Kimi-K2.5) achieve 68–77% success with image input, but only 22–36% in text-only conditions.
- Providing detailed error messages improves text-only performance but still lags behind image-based results for the strongest models.
- Ablations removing the hand overlay or previous-state image reduce accuracy by several percentage points, confirming reliance on visual cues for state estimation.

## Why This Works (Mechanism)

### Mechanism 1
The benchmark isolates visually grounded interactive planning by removing navigation and low-level control and limiting feedback to minimal success/failure signals. This eliminates confounds that could enable success via textual priors or memorized templates, forcing agents to interpret visual observations to infer object states and adapt plans. The core assumption is that interactive planning in embodied environments fundamentally depends on visual grounding. Evidence includes the abstract and section 3 describing the restricted inputs, and neighboring works that retain navigation. The sharp drop in text-only performance (22–36% vs 68–77%) confirms the mechanism; high text-only success would indicate the isolation failed.

### Mechanism 2
Systematic state variations (e.g., clean vs. dirty items) create controlled branching points where a single instruction yields multiple valid execution paths. The agent must observe the current scene and adjust its plan accordingly, rather than following a fixed script. The core assumption is that conditional branches provide a precise measure of an agent’s ability to ground planning in perceptual state. Evidence: the abstract notes variations create conditional branches; section 3.1 explains that steps vary and a single instruction can branch; section 4 links performance drops to visual grounding weaknesses. Confirmed by the fact that performance degrades without visual input, showing agents cannot ignore visual state.

### Mechanism 3
The turn-based replanning loop—requiring full plan generation each step but executing only the first action—creates a persistent demand for agents to reconcile expected and observed states, exposing failures in internal model maintenance. At each turn, the agent receives its prior plan, current images, and minimal feedback, and must evaluate whether the planned sequence remains valid and revise accordingly. This prevents reliance on a one-time plan and forces state tracking and mismatch detection. Evidence: abstract describes the loop; section 3.2 explains continuous reconciliation; section 5.3 shows performance degrades when only the current state is provided, supporting the need for visual history. The break condition is that if a single static plan could solve all variations without revision, the loop would be unnecessary; but task variations deliberately preclude that.

## Foundational Learning

**Concept: Visual grounding for state estimation**  
*Why needed here:* The agent must translate raw pixels into discrete state facts (e.g., "Mug is dirty", "Mug is held", "SinkBasin contains a plate") to choose correct actions.  
*Quick check question:* Given an AI2-THOR image, can you accurately report whether an object is clean/dirty, open/closed, and held/placed?

**Concept: Minimal feedback interpretation**  
*Why needed here:* The agent receives only success/failure signals after each action, not diagnostic messages. It must infer the cause of failure by comparing images and reasoning about world rules.  
*Quick check question:* If you attempt "PICKUP Mug" and get failure, what visual differences between before/after images would explain why? (e.g., mug still on counter, already holding something)

**Concept: Conditional plan adaptation**  
*Why needed here:* The initial plan may become invalid due to unexpected state. The agent must retain goal information and replan based on new observations, including remembering what has already been accomplished.  
*Quick check question:* After several steps, you realize the plate you intended to use is dirty and must be cleaned. How do you update your plan while preserving progress toward the goal?

## Architecture Onboarding

**Component map:**  
- *Input wrapper*: collects images, action history, prior plan, task description; formats prompt.  
- *Vision encoder*: processes RGB images to extract object features; may use pretrained VLM or CNN+detector.  
- *State inference module*: converts vision outputs into structured state (object properties, containment, held item).  
- *Memory module*: stores persistent facts across turns (e.g., cleaned items, completed steps); could be text buffer or symbolic knowledge base.  
- *Planner*: language or vision-language model that consumes current state, memory, prior plan, and goal to generate revised full action sequence.  
- *Action executor*: sends first action to AI2-THOR, receives new observation and feedback.

**Critical path:**  
1. Initialize memory, get initial observation.  
2. For each step: run vision encoder on current and previous images; state inference produces current state.  
3. Combine current state, memory, action history, and prior plan into prompt.  
4. Planner outputs action list; executor sends first action to simulator.  
5. Executor returns new observation and success/failure; update memory and previous image.  
6. Loop until termination.

**Design tradeoffs:**  
- *Centralized vs modular*: Single large VLM as perception+planner simplifies integration but may be costly; modular design allows specialized components but requires alignment between modules.  
- *Memory representation*: Free-text "Things to Remember" is flexible but unreliable; structured symbolic state is precise but hard to ground from images. The paper shows mixed benefits for text memory, indicating need for better mechanisms.  
- *Visual history length*: Two images (current+previous) help (ablation shows gain), but more images could improve long-term consistency at the cost of context length and compute.

**Failure signatures:**  
- High proportion of "Undoable" actions: indicates state tracking errors (e.g., trying to pick up while holding something).  
- Repeated termination due to action loops: agent failed to adjust plan after mismatches.  
- Large gap between image-based and text-only performance: confirms reliance on visual grounding; if small, suggests images not effectively used.  
- Performance drop when removing hand overlay: shows fragility in held-object state estimation.

**First 3 experiments:**  
1. **Baseline replication**: Run a strong VLM (e.g., Kimi-K2.5) with default prompt and full images. Expect success ~68% (Table 6). Validates implementation.  
2. **Text-only ablation**: Remove images, provide only textual scene description or no visual info. Expect sharp drop (~22% for Kimi). Confirms visual grounding necessity.  
3. **Hand overlay removal**: Present images without translucent hand, adjust inventory prompt. Expect performance drop (~7% absolute for Kimi per Figure 10). Validates reliance on held-object cues.

## Open Questions the Paper Calls Out

**Open Question 1**  
- Question: What memory mechanisms beyond prompting can support reliable state maintenance in interactive planning?  
- Basis in paper: [explicit] The "Things to Remember" ablation showed inconsistent benefits; the authors state prompt-based memory scaffolding is insufficient for reliable state maintenance.  
- Why unresolved: The paper did not evaluate alternative architectures (e.g., external memory, structured state tracking).  
- What evidence would resolve it: Integrating memory-augmented VLMs or state-tracking modules; a significant performance lift on AsgardBench would confirm state maintenance as the key bottleneck.

**Open Question 2**  
- Question: How can multimodal agents tightly integrate perception, memory, and planning rather than as separate modules?  
- Basis in paper: [explicit] The conclusion states progress requires "integrating perception, memory, and planning more tightly" and that current models "can't treat these components as loosely connected modules."  
- Why unresolved: The paper does not specify integration strategies or test unified architectures.  
- What evidence would resolve it: Developing models with iterative perception-planning loops and comparing their AsgardBench success to modular baselines.

**Open Question 3**  
- Question: Are failures in AsgardBench due more to perception errors or planning deficiencies, and how can these be disentangled?  
- Basis in paper: [inferred] Performance drops without vision show visual grounding is necessary, but the paper does not separate perception from planning errors when vision is present. Error analysis shows both visual misinterpretations and state tracking issues.  
- Why unresolved: No controlled ablations independently degrade perception or planning.  
- What evidence would resolve it: Systematically varying visual fidelity (blur, masks) and planning horizon while measuring error types on AsgardBench.

**Open Question 4**  
- Question: How can navigation be added to interactive planning benchmarks without conflating navigation skill with planning skill?  
- Basis in paper: [explicit] The paper cites omission of navigation as a key limitation and suggests "incorporating controlled navigation" as future work.  
- Why unresolved: No benchmark isolates planning when navigation is required.  
- What evidence would resolve it: Extending AsgardBench with discrete navigation steps; comparing planning success before and after addition would show transferability.

## Limitations
- Hand overlay rendering details (coordinates, scaling, asset) are undocumented, hindering replication of its visual grounding role.
- Prompt structure and injection timing of the "Things to Remember" memory buffer are unclear, affecting model consistency.
- The deterministic state machine algorithm for task generation, including randomization bounds and precondition checks, is not fully specified.

## Confidence
- Isolation of Planning: High
- Conditional Branching: High
- Replanning Loop: Medium
