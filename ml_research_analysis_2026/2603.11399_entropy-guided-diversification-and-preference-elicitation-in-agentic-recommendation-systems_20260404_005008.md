# Entropy Guided Diversification and Preference Elicitation in Agentic Recommendation Systems

## Quick Facts
- **arXiv ID**: 2603.11399
- **Source URL**: https://arxiv.org/abs/2603.11399
- **Reference count**: 4
- **Primary result**: Entropy-guided adaptive preference elicitation and diversification reduces unnecessary interactions and improves novelty and diversity in ambiguous recommendation queries.

## Executive Summary
Ambiguous user queries in agentic recommendation systems often cause either excessive iterative interactions or premature collapse of the search space. This paper introduces an Intelligent Decision Support System (IDSS) that uses entropy as a unified signal to coordinate adaptive preference elicitation, uncertainty-aware ranking, and diversification through grid presentation. By quantifying uncertainty over item attributes, entropy directs which questions to ask and how to present recommendations, enabling efficient clarification. Simulation-based evaluation on a car recommendation dataset shows that entropy-guided questioning significantly reduces unnecessary follow-ups and boosts novelty (e.g., Newness from 0.602 to 0.946 without EntropyQ for short queries). The full system with Maximal Marginal Relevance (MMR) diversification achieves high intra-list diversity (ILD up to 0.779) while maintaining precision (Precision@9 up to 0.918). A pilot user survey (n=12) indicated that 9 participants preferred outputs after two follow-up questions. However, limitations include simulation-only validation, a small user sample, and lack of statistical rigor, calling for larger-scale real-world studies.

## Method Summary
The IDSS operates iteratively: given an initial ambiguous query, it computes entropy for each attribute across the candidate item set. The attribute with highest entropy is selected for the next user question, as it promises the greatest reduction in uncertainty. After the user’s response, the candidate set is filtered, entropies are recomputed, and the cycle repeats until a stopping condition (e.g., entropy threshold or maximum questions) is met. For ranking, the system employs a coverage-risk optimization that scores items based on their ability to cover diverse preferences while minimizing irrelevance risk. Finally, MMR re-ranks the top items to enhance diversity, and the results are presented in a grid aligned with the highest-entropy dimensions, helping users compare and refine choices.

## Key Results
- Entropy-guided questioning reduces unnecessary follow-ups; for short queries, the Newness metric rises from 0.602 to 0.946 without EntropyQ, demonstrating the benefit of targeted questions.
- The full IDSS with MMR diversification yields intra-list diversity (ILD) up to 0.779 and Precision@9 up to 0.918, balancing diversity and accuracy effectively.
- In a pilot user study (n=12), 9 participants preferred outputs after two follow-up questions, indicating user acceptance of the adaptive interaction.

## Why This Works (Mechanism)
Entropy effectively captures preference uncertainty: high-entropy attributes indicate wide variation across items, meaning the user’s preference is unclear. By focusing questions on these attributes, the system efficiently narrows the candidate space. The coverage-risk optimization balances exploration (diversity) and exploitation (relevance), using entropy to weight the coverage term. MMR diversification ensures the final list is not redundant, while the grid presentation leverages high-entropy dimensions to make trade-offs explicit, facilitating user decision-making. Ablations confirm that each component contributes uniquely to the observed gains.

## Foundational Learning
1. **Entropy**  
   *Why needed*: To identify attributes where user preferences are most uncertain, thus guiding elicitation.  
   *Quick check*: Compute entropy over the distribution of an attribute across candidate items; higher values indicate greater uncertainty.

2. **Preference Elicitation**  
   *Why needed*: Ambiguous queries require interactive clarification to avoid overwhelming or irrelevant results.  
   *Quick check*: Implement a questioning strategy that selects attributes with the highest entropy.

3. **Coverage-Risk Optimization**  
   *Why needed*: To produce a recommendation list that is both diverse and precise.  
   *Quick check*: Use a weighted combination of coverage (diversity) and risk (irrelevance) scores for ranking.

4. **MMR (Maximal Marginal Relevance)**  
   *Why needed*: To increase intra-list diversity without sacrificing too much precision.  
   *Quick check*: Apply MMR re-ranking: iteratively select items that maximize relevance minus similarity to already chosen items.

5. **Grid Presentation**  
   *Why needed*: To help users perceive differences along key dimensions and articulate preferences.  
   *Quick check*: Sort items by high-entropy attributes and display in a matrix layout.

6. **Adaptive Interaction**  
   *Why needed*: To efficiently handle ambiguous queries by adjusting questions and recommendations based on incremental feedback.  
   *Quick check*: Update entropy after each user response and recompute the next action.

## Architecture Onboarding
**Component map**: User Query -> Entropy Calculator -> Adaptive Question Selector -> Uncertainty-aware Ranker -> MMR Diversifier -> Grid Presentation

**Critical path**:
1. System receives an ambiguous user query.
2. Entropy Calculator computes uncertainty for each attribute of the candidate item set.
3. Adaptive Question Selector picks the attribute with maximum entropy to ask the user.
4. User response filters the candidate set; entropy is recomputed.
5. Steps 3–4 repeat until a stopping condition (entropy below threshold or max questions) is met.
6. Uncertainty-aware Ranker scores items using coverage-risk optimization.
7. MMR Diversifier re-ranks the top-k items for diversity.
8. Grid Presentation displays items along high-entropy dimensions.

**Design tradeoffs**:
- *Interaction depth vs. user fatigue*: More questions reduce uncertainty but may annoy users; entropy threshold and max question limit balance this.
- *Diversity vs. precision*: MMR introduces diversity but can lower relevance; coverage-risk optimization mitigates by weighting risk.
- *Generalization vs. domain specificity*: Entropy relies on attribute distributions; sparse or high-dimensional data may yield unreliable estimates.

**Failure signatures**:
- Stagnant entropy: Entropy fails to decrease after several questions, indicating ineffective elicitation or non-discriminative attributes.
- User disengagement: Skipping questions or expressing frustration suggests over-questioning.
- Sharp precision drop: If diversity gains come with large Precision@k decline, diversification is too aggressive.
- Confusing grid: Users struggle to interpret the layout, implying chosen entropy dimensions are not intuitive.

**First experiments**:
1. **Baseline simulation**: Compare IDSS against random questioning and static filtering on the car dataset, measuring number of questions, precision, and diversity.
2. **Ablation study**: Disable each core component (entropy-guided questioning, coverage-risk ranking, MMR) to quantify individual contributions.
3. **Pilot user study**: Recruit 12 participants to interact with the system on ambiguous car queries; collect satisfaction scores and feedback on the number of follow-up questions.

## Limitations
- Evaluation limited to simulation on synthetic car data; real-world user behavior may differ.
- Pilot user study very small (n=12) and potentially biased; conclusions are preliminary.
- No statistical significance testing reported; robustness of metric improvements uncertain.
