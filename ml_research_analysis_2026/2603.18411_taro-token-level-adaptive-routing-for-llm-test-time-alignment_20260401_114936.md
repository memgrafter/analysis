# TARo: Token-level Adaptive Routing for LLM Test-time Alignment

## Quick Facts
- **arXiv ID:** 2603.18411
- **Source URL:** https://arxiv.org/abs/2603.18411
- **Reference Count:** 40
- **Primary Result:** TARo uses a lightweight router to dynamically combine a frozen base model and a step-wise reward model at each token, improving reasoning accuracy by up to +22.4% over the base model on MATH500 (e.g., Llama-3.1-8B: 32.0% → 54.4%) and by up to +8.4% over GenARM, with zero-shot transfer to larger model scales.

## Executive Summary
TARo introduces a test-time alignment framework that enhances the reasoning capabilities of frozen large language models without any parameter updates to the base model. It trains a step-wise reward model on mathematical preference traces and a lightweight token-level router that modulates the influence of the base and reward models during generation. The router operates on per-token logits, allowing it to selectively apply reward guidance only at tokens critical for logical consistency (e.g., operators, reasoning scaffolds) while relying on the base model's domain-specific vocabulary. Evaluated on math (MATH500), clinical (MedXpertQA), and instruction-following (AlpacaEval) benchmarks, TARo achieves substantial gains over base models and prior test-time alignment methods. The router's design based on logits (rather than hidden states) enables direct transfer from a small model to a larger one within the same family without retraining.

## Method Summary
TARo consists of three trained/frozen components: a base LLM (frozen), a reward LLM (frozen, fine-tuned on math step preferences via DPO), and a lightweight router MLP (trained). The router takes as input the concatenated logits (or top-k logits with index embeddings) from both models at each decoding step and outputs an adaptive coefficient α_t ∈ (0,1). The guided next-token distribution is a weighted mixture: (1−α_t)·softmax(z_base_t) + α_t·softmax(z_reward_t). Router training is supervised: given a gold token trajectory, the router is optimized to minimize the negative log-likelihood of the gold token under the guided distribution, optionally with entropy regularization to encourage decisive routing. The entire system is trained on a small subset (1,000 samples) of Math-StepDPO-10K, optionally mixed with UltraFeedback, and operates entirely at inference time.

## Key Results
- On MATH500, TARo improves Llama-3.1-8B from 32.0% to 54.4% (+22.4%) and Qwen-2.5-3B from 18.2% to 25.4% (+7.2%) over the base model.
- It outperforms the test-time alignment baseline GenARM by up to +8.4% (e.g., Qwen-2.5-3B: 25.4% vs. GenARM 23.4%).
- The router transfers zero-shot to larger backbones (Llama-3.1-70B, Qwen2.5-14B) when trained with logits, yielding significant gains on in-domain (MATH500) and out-of-domain tasks (MedXpertQA, AlpacaEval).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Token-level routing adaptively directs reward-model guidance to reasoning-critical tokens (operators, scaffolds) while relying on the base model for problem-specific vocabulary.
- **Mechanism:** The router predicts a dynamic weight α_t per decoding step, combining base and reward logits. This allows fine-grained control where the reward model influences only tokens that affect logical consistency, reducing interference with domain-specific language.
- **Core assumption:** Reasoning-relevant tokens have distinct statistical patterns in the reward model's logit distribution compared to the base model.
- **Evidence anchors:** abstract specifies "token-level adaptive routing... dynamically modulate base and reward model logits at each token"; §3.3 details router design; Table 2 shows highest α_t tokens include mathematical operators/scaffolds (e.g., "cases", "Step") while low-α tokens are problem-context words.

### Mechanism 2
- **Claim:** Using logits (vs. hidden states) as router inputs enables zero-shot transfer from small to large base models.
- **Mechanism:** Logits are defined over a fixed vocabulary space, whereas hidden-state representations vary with model scale/architecture. The router trained on small-base logits can thus interpret large-base logits without retraining.
- **Core assumption:** Vocabulary space (token IDs) is consistent across scales; logit distributions reflect comparable semantic confidence despite base-model capability differences.
- **Evidence anchors:** §5.3 ablation shows routers using logits transfer to larger backbones, while hidden-state routers do not; Fig. 3 shows router trained on Llama-3.1-8B improves Llama-3.1-70B without retraining; Table 7 shows logit-based router outperforms hidden-state on OOD tasks when scaled.

### Mechanism 3
- **Claim:** Step-wise reward training on mathematical traces provides targeted logical consistency signals that, when applied token-wise, improve reasoning even on out-of-domain tasks.
- **Mechanism:** The reward model is optimized on fine-grained preferences (correct vs. incorrect next steps in math derivations). At test time, its per-token logits encode coherence heuristics that benefit any structured reasoning, not just math.
- **Core assumption:** Logical coherence signals (e.g., valid algebraic manipulations) are transferable across domains like clinical reasoning or instruction following.
- **Evidence anchors:** abstract states reward guidance generalizes to clinical reasoning and instruction following; §3.2 describes reward model training on Step-DPO-10K; Table 1 shows MedXpertQA improvements (up to +13.2%) despite reward trained on math.

## Foundational Learning
- **Concept: Test-time alignment**  
  *Why needed here:* TARo operates entirely at inference, steering a frozen base model via a reward model without modifying parameters. Understanding this avoids confusion with post-training methods like RLVR.  
  *Quick check question:* How does test-time alignment differ from SFT or RLHF in terms of model updates and deployment flexibility?

- **Concept: Token-level reward decomposition**  
  *Why needed here:* The reward model outputs token logits; the scalar trajectory reward is decomposed into sum of token log-likelihoods. This allows per-token modulation.  
  *Quick check question:* If a reward model assigns high log-prob to an erroneous token, how might the router's adaptive α_t mitigate its impact?

- **Concept: Mixture-of-experts (MoE) routing principles**  
  *Why needed here:* TARo treats base and reward models as "experts" with a learned router. Key MoE ideas: dynamic weighting vs. fixed gating, and importance of scale-agnostic features for router portability.  
  *Quick check question:* Why is a prompt-level router (single α per sequence) insufficient for structured reasoning tasks compared to token-level?

## Architecture Onboarding
- **Component map:** Base LLM (frozen, z_base_t) and Reward LLM (frozen, z_reward_t) → Router MLP (lightweight, α_t) → Guided distribution: (1−α_t)·softmax(z_base_t) + α_t·softmax(z_reward_t) → Sample token → repeat.
- **Critical path:**  
  1. **Reward model preparation:** Fine-tune a pretrained model (e.g., DeepSeek-R1-Distill-Llama-8B) on Math-StepDPO-10K using DPO loss (Eq. 3, β_r=0.1) to produce token-level logits.  
  2. **Router training:** Freeze base and reward models. For each step in a training trajectory (from Math-StepDPO-10K/UltraFeedback), extract base and reward logits (either full concatenation or top-k with index embeddings). Train an MLP (hidden dim 128) to predict α_t that minimizes NLL of the gold token under the guided distribution, with optional entropy regularization (λ).  
  3. **Inference integration:** Load all three models. At each decoding step: compute z_base_t and z_reward_t, extract features, predict α_t via router, combine distributions, sample token.  
  4. **Cross-scale transfer:** For same-family models, use the router checkpoint trained on a small base directly on a large base (logits input only) without retraining.
- **Design tradeoffs:**  
  - *Feature type:* Full logits (2V) generalize best but memory-intensive; top-k (K≈1000) efficient but may lose signal if critical tokens excluded; index embeddings add token-ID awareness but require an embedding table.  
  - *Entropy regularization:* Encourages confident α_t (near 0/1) but over-regularization can starve reward model (Table 4: inconsistent effects across models).  
  - *Router capacity:* MLP with hidden dim 128 is lightweight; larger may overfit to base-reward dynamics seen during training.
- **Failure signatures:**  
  - *No improvement:* α_t ≈ 0 always → reward unused. Check: base/reward too similar? reward under-trained? Reduce entropy λ or increase reward capacity.  
  - *Degraded OOD:* Using hidden states as input → switch to logits; ensure reward/base vocab match.  
  - *Memory bottleneck:* Full logits on large-vocab models (e.g., Llama 128K) → switch to top-k (K=1000 works per Table 4).  
  - *Poor transfer to larger base:* Router trained on hidden states will fail → retrain router with logits on small base.
- **First 3 experiments:**  
  1. **Token-level vs. prompt-level ablation:** Train router predicting single α vs. per-token α on MATH500. Expect token-level > prompt-level by significant margin (Table 9).  
  2. **Feature input ablation:** Compare router performance using (base+reward logits) vs. (reward hidden states only) vs. (base+reward hidden states) on MATH500 and MedXpertQA. Expect logits to generalize better (Table 7).  
  3. **Zero-shot scale transfer:** Train router on Llama-3.1-8B (or Qwen-2.5-3B) with logits, then apply directly to Llama-3.1-70B (or Qwen2.5-14B). Evaluate on MATH500 and MedXpertQA. Expect consistent gains, especially on in-domain (Fig. 3).

## Open Questions the Paper Calls Out
- **Open Question 1:** Does the math-trained router generalize to non-math reasoning domains?  
  *Basis in paper:* Transfer to MedXpertQA/AlpacaEval may be due to shared reasoning structure; reward model is math-only. *Why unresolved:* Only three benchmarks tested; broader transfer unknown. *What evidence would resolve it:* Evaluate router on diverse reasoning tasks (physics, commonsense, code) vs. domain-specific routers.
- **Open Question 2:** What logit features influence router α and do they predict correctness?  
  *Basis in paper:* Paper correlates high-α tokens with operators/scaffolding but not causally. *Why unresolved:* Router is black-box; unclear which logit properties matter or if beneficial. *What evidence would resolve it:* Ablate inputs (shuffle indices, mask probabilities) and measure α/accuracy; analyze token features across models.
- **Open Question 3:** Can router be trained without gold tokens?  
  *Basis in paper:* Router uses supervised fine‑training on Math‑StepDPO‑10K gold tokens, requiring step‑wise ground truth. *Why unresolved:* Dependence on gold traces limits applicability to supervised domains. *What evidence would resolve it:* Propose/evaluate unsupervised objectives (RL on final reward, contrastive) and compare performance.
- **Open Question 4:** How does base/reward strength gap affect optimal λ for entropy regularization?  
  *Basis in paper:* Entropy helps Qwen but hurts Llama; authors hypothesize link to strength gap but didn't study. *Why unresolved:* Interaction not quantified; hyperparameter selection unclear for new model pairs. *What evidence would resolve it:* Vary reward strength for fixed base, sweep λ, and analyze correlation between base-reward gap and optimal λ.

## Limitations
- Token-level routing pattern (high-α tokens = reasoning scaffolds) is correlational; causal necessity not proven—could be an artifact of the training data or reward model.
- Logit-based transferability assumes consistent vocabulary and comparable logit distributions across scales; may fail with different tokenizers or extreme capability gaps.
- Cross-domain reward transfer (math-trained reward improving clinical/instruction tasks) lacks theoretical guarantee; could reflect superficial dataset similarities rather than general logical coherence.

## Confidence
- **High:** Token-level routing pattern existence (Table 2 evidence); within-family zero-shot transfer when using logits (Fig. 3, Table 7).
- **Medium:** Cross-domain reward transfer (empirical support on MedXpertQA/AlpacaEval but weak mechanistic explanation).
- **Low:** Cross-family transfer (e.g., Qwen router to Llama base) and robustness to extreme base-reward capability gaps.

## Next Checks
1. **Ablate high-α tokens:** Run TARO with forced α_t=0 for operator/scaffold tokens vs. only for contextual words on MATH500; quantify accuracy drop to test if identified tokens are causally critical.
2. **Vocabulary mismatch stress test:** Apply router trained on Llama-3.1-8B (128K vocab) to a base model with a different tokenizer (e.g., Mistral 32K). Measure performance decay to validate logit-space alignment assumption.
3. **Control reward model training:** Train a step-wise reward on *non-math* structured data (e.g., logic puzzles). If TARO still improves MedXpertQA, it supports transfer via general coherence; if not, math-specific heuristics dominate.
