# Evaluating Prompt Engineering Techniques for RAG in Small Language Models: A Multi-Hop QA Approach

## Quick Facts
- **arXiv ID:** 2602.13890
- **Source URL:** https://arxiv.org/abs/2602.13890
- **Reference count:** 40
- **Primary result:** Novel hybrid prompts raise accuracy by up to 6% over standard RAG but increase latency 8–10×; optimal prompts differ by model (Qwen2.5-3B favors decomposition, Gemma3-4B excels with expert synthesis).

## Executive Summary
This paper studies prompt engineering for retrieval-augmented generation (RAG) with small language models (SLMs) on multi-hop question answering. Evaluating 24 prompt templates (baseline, literature-derived, novel hybrids) on HotpotQA with Qwen2.5-3B-Instruct and Gemma3-4B-It, the authors find that advanced prompts (e.g., decomposition, synthesis) boost accuracy by up to 6 percentage points but incur an 8–10× latency penalty. Model-specific affinities emerge: Qwen2.5-3B performs best with step-by-step decomposition prompts, while Gemma3-4B achieves top accuracy with a concise expert-synthesis prompt that is also the fastest among advanced options. Simple instruction-tuned prompts maximize efficiency for both models. The study highlights a fundamental accuracy–latency trade-off and the need to match prompt strategy to model capacity and application constraints.

## Method Summary
The study evaluates 24 prompt templates (1 standard baseline, 9 from prior literature, 14 novel hybrids) on HotpotQA using two SLMs: Qwen2.5-3B-Instruct and Gemma3-4B-It. The RAG pipeline uses pre-retrieved passages from the RAGBench dataset. For each (model, prompt) pair, the system formats the prompt with context and question, generates an answer, records wall-clock generation time, and scores the output with a custom LLM-as-judge metric (SLLM). SLLM weights semantic alignment (35%), accuracy (25%), coherence, completeness, and utility. Efficiency is computed as SLLM divided by processing time. No model training occurs; the focus is purely on prompt design while holding retrieval fixed.

## Key Results
- Hybrid prompts achieve peak accuracies of 83.0% (Qwen) and 84.6% (Gemma), improving up to 6 percentage points over the standard RAG prompt.
- Advanced prompts incur an 8–10× latency increase compared to the baseline.
- Model-specific optimal prompts emerge: for Qwen, multi-hop compact/decomposition offers the best accuracy–latency balance; for Gemma, expert_synthesis_prompting yields top accuracy while being the fastest among advanced prompts.
- Simple instruction_tuned prompts maximize efficiency (SLLM/time) for both models.

## Why This Works (Mechanism)
### Mechanism 1: Decomposition Prompts Enhance Multi-Hop Reasoning
- **Claim:** Prompts that break complex questions into sub-questions or step-by-step reasoning improve accuracy for SLMs on multi-hop QA.
- **Mechanism:** The prompt provides an external reasoning scaffold, compensating for the SLM's limited parametric reasoning capacity by guiding it to sequentially process and synthesize facts from multiple documents.
- **Core assumption:** SLMs can reliably follow explicit intermediate reasoning steps when properly instructed.
- **Evidence anchors:**
  - [abstract] "novel hybrid prompts achieved peak accuracies of 83.0% (Qwen) and 84.6% (Gemma)"
  - [section] 5.3 "Decomposition as a Robust Strategy: Prompts like multi_hop_compact_prompting and multi_hop_decomposition_prompting were highly effective on both models."
  - [corpus] Limited direct support; related work (e.g., paper 63130) notes SLMs benefit from structured guidance but does not directly test decomposition.
- **Break condition:** If the induced reasoning steps cause output length to exceed latency budgets (>10–15s) or if the model fails to correctly synthesize sub-answers (low SLLM score <0.7), the decomposition approach becomes counterproductive.

### Mechanism 2: Model Capacity Dictates Prompt Affinity
- **Claim:** The optimal prompt strategy is model-specific, depending on parameter count and architecture.
- **Mechanism:** Larger models (e.g., Gemma3-4B) possess sufficient reasoning depth to interpret high-level, persona-driven instructions efficiently, while smaller models (e.g., Qwen2.5-3B) require more granular, explicit scaffolding to achieve comparable accuracy.
- **Core assumption:** Parameter scale and architectural design fundamentally shape how a model processes and executes prompt-guided reasoning.
- **Evidence anchors:**
  - [abstract] "Model-specific affinities emerged: for Qwen, multi-hop compact/decomposition offered the best accuracy–latency balance; for Gemma, expert_synthesis_prompting reached top accuracy while remaining the fastest among advanced prompts."
  - [section] 4.2 "expert_synthesis_prompting on Gemma3 4B demonstrates that for a sufficiently capable model... a well-crafted, high-level instruction can be more effective and computationally cheaper than prompts that enforce lengthy, explicit step-by-step reasoning chains."
  - [corpus] Paper 63130 states: "Small language models (SLMs; 1-12B params)... are sufficient and often superior for agentic workloads" – indirectly supports that capacity influences suitable prompting.
- **Break condition:** Transferring a prompt optimized for one SLM to another without empirical validation leads to significant performance degradation, especially if the target model has notably different scale or architecture.

### Mechanism 3: Complexity-Induced Accuracy–Latency Trade-off
- **Claim:** Increasing prompt complexity to boost reasoning depth yields higher accuracy but incurs a steep, often superlinear, rise in processing latency.
- **Mechanism:** More elaborate prompts (e.g., those requiring intermediate reasoning chains) generate longer outputs and demand more computational steps, directly increasing wall-clock time.
- **Core assumption:** Inference latency scales primarily with generated token count and the number of reasoning hops induced by the prompt.
- **Evidence anchors:**
  - [abstract] "However, they incurred an 8–10× latency increase."
  - [section] 5.1 "The key result... uncovers a significant accuracy-latency trade-off... increase by a factor of 8 to 10 compared to baseline."
  - [corpus] Weak; general RAG efficiency concerns appear in neighbors (e.g., 33156) but not specifically this trade-off.
- **Break condition:** When application constraints impose hard latency limits (e.g., <2s for interactive use), even accuracy-optimal prompts become infeasible, forcing selection of simpler, faster templates.

## Architecture Onboarding
Component map: Query Input -> Retriever -> Prompt Manager -> Generator -> Evaluator -> Metrics Collector

Critical path:
1. Receive question.
2. Retrieve relevant documents (from dataset or live retriever).
3. Prompt Manager selects template, formats prompt with context & question.
4. Generator runs inference; timer starts before, stops after output.
5. Evaluator scores answer; SLLM computed from weighted dimensions.
6. Metrics: accuracy (SLLM), latency, efficiency logged.

Design tradeoffs:
- Accuracy vs. Latency: Hybrid prompts (e.g., optimized_multi_hop_prompting) maximize accuracy but increase latency 8–10×; instruction_tuned minimizes latency but sacrifices ~6% accuracy.
- Model selection: Gemma3-4B offers better speed/accuracy baseline but may have licensing or hardware constraints vs. Qwen2.5-3B.
- Prompt selection: Must be empirically matched to model; no single prompt dominates both accuracy and efficiency across models.

Failure signatures:
- Latency >10s on hybrid prompts for Qwen2.5 indicates over-scaffolding; consider compact variants.
- SLLM <0.6 on advanced prompts suggests model cannot handle reasoning depth; fallback to simpler templates.
- Large accuracy gap (>5%) between models on same prompt signals model-prompt mismatch; re-evaluate prompt for weaker model.
- High variance across runs indicates prompt instability; add few-shot examples or increase temperature.

First 3 experiments:
1. Baseline establishment: Run standard_context_aware on both models; record SLLM and latency baselines.
2. Literature prompt sweep: Test 9 literature-derived prompts; identify top 2 by accuracy and top 2 by efficiency per model.
3. Hybrid validation: Test 3–5 top novel hybrids (e.g., optimized_multi_hop_prompting, multi_hop_compact_prompting, expert_synthesis_prompting); measure accuracy gain vs. latency cost; select best per model for target deployment profile.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** To what extent do the identified optimal prompts (e.g., `expert_synthesis_prompting` for Gemma, `multi_hop_compact_prompting` for Qwen) generalize to other Small Language Models (SLMs) beyond the two evaluated, and to other multi-hop QA datasets with different reasoning patterns (e.g., comparative, boolean, or open-domain)?
- **Basis in paper:** [explicit] The authors state the research gap as the "optimization of RAG for Small Language Models (SLMs) remains a critical research gap" (Abstract) and note "model-specific affinities emerged" (Section 4.3). They explicitly call for work extending beyond large models and for systematic hybrid evaluation (Section 2.4).
- **Why unresolved:** The study evaluates only two specific SLMs (Qwen2.5-3B-Instruct, Gemma3-4B-It) on a single dataset (HotpotQA). Performance differences may be model-specific or dataset-specific, limiting the universality of the recommendations in Table 6.
- **What evidence would resolve it:** A follow-up study evaluating the top-5 performing prompts from this work on a diverse panel of at least 5 additional SLMs (e.g., Phi-3, Mistral-7B, Llama-3.2-3B) across multiple multi-hop QA benchmarks (e.g., 2WikiMultiHopQA, MuSiQue). Analysis would determine if the same prompt-model affinity patterns hold.

### Open Question 2
- **Question:** What is the causal mechanism behind the steep (8–10×) latency increase for novel hybrid prompts? Is it primarily driven by (a) the explicit generation of intermediate reasoning steps (Chain-of-Thought), (b) the increased token count in more complex prompt templates themselves, or (c) a combination that induces longer, more verbose final outputs?
- **Basis in paper:** [inferred] The paper measures processing time as "wall-clock time from the time a formatted prompt is entered... to the time the full response is generated" (Section 3.4.3) and notes hybrid prompts "incurred an 8–10× latency increase" (Key outcome). The design of hybrid prompts integrates CoT, self-refinement, and hierarchical synthesis (Section 3.3), which inherently encourage longer, step-by-step generation.
- **Why unresolved:** The study reports latency as an aggregated metric but does not decompose the source of the delay (prompt size vs. reasoning token generation vs. final answer length). This prevents targeted optimization (e.g., can we keep accuracy gains while constraining reasoning verbosity?).
- **What evidence would resolve it:** An ablation experiment measuring token count and generation speed for: (1) the base prompt template length, (2) the average number of intermediate reasoning tokens generated, and (3) the final answer token count, across a subset of high- and low-latency prompts. This would isolate the primary contributor to the latency overhead.

### Open Question 3
- **Question:** For the Gemma3-4B-It model, why does the `expert_synthesis_prompting` prompt uniquely break the typical accuracy-latency trade-off, achieving both top accuracy and the best efficiency among novel prompts? What specific architectural or training characteristics of this SLM enable efficient processing of high-level, persona-based instructions over explicit step-by-step ones?
- **Basis in paper:** [explicit] The paper highlights this as a key anomaly: "the prompt yielding the highest accuracy... was concurrently the fastest (6.98s) and most efficient (0.121) among the entire novel set" for Gemma (Section 4.2.2). They speculate it relates to "Gemma's larger capacity and advanced architecture" (Section 5.2) but do not investigate the mechanism.
- **Why unresolved:** The paper establishes the correlation (better model performance + prompt style) but does not probe the *why*. Understanding this could inform principles for matching prompt style to model architecture, moving beyond empirical trial-and-error.
- **What evidence would resolve it:** A diagnostic analysis comparing Gemma's internal attention patterns or layer activations (using probes or saliency maps) during generation with `expert_synthesis_prompting` versus a verbose CoT-style prompt (e.g., `optimized_multi_hop_prompting`). Concurrently, a similar analysis on Qwen2.5-3B would test if the difference stems from architectural features (e.g., attention head diversity, feed-forward network size) or training data.

### Open Question 4
- **Question:** How robust and reliable is the custom SLLM evaluation metric (weighted sum of semantic alignment, accuracy, coherence, completeness, utility) compared to human expert judgments, and does its weighting scheme (e.g., semantic alignment at 35%) inadvertently bias results toward certain prompt styles (e.g., those producing verbose, semantically similar but factually redundant answers)?
- **Basis in paper:** [explicit] The authors developed SLLM because "RAGAS... revealed significant limitations" and "heavily reliance on lexical overlap... was inadequate" (Section 3.4.1). They state weights were "empirically assigned based on relative importance" (Section 3.4.2) but provide no inter-rater reliability study or human validation.
- **Why unresolved:** The metric is central to all conclusions (accuracy rankings, Table 6 recommendations). Without validation against human evaluation, it's unclear if SLLM favors certain structural answer patterns (e.g., longer, structured outputs from hybrid prompts) that happen to align with its dimensions but not with true answer quality.
- **What evidence would resolve it:** A human evaluation study where domain experts score a stratified sample (e.g., 200 instances) of model outputs from top and bottom-ranked prompts using the same five dimensions. Compute correlation (e.g., Spearman's rho) between SLLM scores and human averages. Perform sensitivity analysis by varying the weight parameters to see if prompt rankings change significantly.

### Open Question 5
- **Question:** Do the observed prompt affinities and efficiency-accuracy trade-offs hold when the RAG retrieval component is optimized for the specific SLM (e.g., using query expansion or re-ranking tuned for model size), rather than using the fixed, pre-retrieved passages from RAGBench?
- **Basis in paper:** [inferred] The study uses "pre-retrieved passages and distractors" from RAGBench to "focus primarily on prompt design" (Section 3.2). The authors acknowledge retrieval is part of RAG but isolate the generator component. The quality, relevance, and noise level of the retrieved context are known to critically interact with prompt design.
- **Why unresolved:** The fixed retrieval context may be sub-optimal for the smaller SLMs' context window or comprehension abilities. A prompt that works well with high-quality, concise passages might fail with noisier retrievals, and vice versa. The reported trade-offs may be partly an artifact of the fixed retrieval quality.
- **What evidence would resolve it:** An experiment replicating the prompt evaluation but with a dynamic retrieval module (e.g., using a BM25 or a small dense retriever) whose parameters (chunk size, top-k, query rewriting) are co-optimized with the prompt for each SLM. Compare the resulting prompt rankings to those from the static-retrieval setup.

## Limitations
- Incomplete prompt templates: Appendix C is truncated, preventing exact replication of hybrid prompts.
- Test set size ambiguity: paper cites 18,720 instances vs. RAGBench's 390; unclear how the test set was constructed.
- Evaluation and retrieval details unspecified: GPT-4o-mini call parameters and retrieval context aggregation are missing, affecting score consistency and input.
