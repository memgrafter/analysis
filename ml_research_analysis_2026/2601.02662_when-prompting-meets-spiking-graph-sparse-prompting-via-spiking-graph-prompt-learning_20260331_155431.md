# When Prompting Meets Spiking: Graph Sparse Prompt Learning via Spiking Graph Prompt Learning
## Quick Facts
- **arXiv ID:** 2601.02662
- **Source URL:** https://arxiv.org/abs/2601.02662
- **Reference count:** 40
- **Primary result:** Learns sparse prompts via spiking neurons, achieving 2–5% accuracy gains and improved robustness over dense baselines on 11 datasets for few-shot node classification.

## Executive Summary
Existing graph prompt methods, such as Graph Prompt Feature (GPF) learning, modify all node feature dimensions uniformly, introducing redundancy and making prompts sensitive to noise. This paper introduces **SpikingGPF**, a novel approach that uses Integrate-and-Fire (IF) spiking neurons to learn **dual sparsity**: a sparse coefficient matrix selects a subset of prompt atoms per node, and a signed IF mechanism applies these atoms to only a subset of feature dimensions. This design yields a compact, lightweight prompt that focuses modifications on salient information. Experiments on 11 datasets with multiple pre-trained GNNs show consistent accuracy improvements of 2–5% in few-shot node classification and superior robustness under structural and feature perturbations compared to dense baselines.

## Method Summary
SpikingGPF learns two sparse matrices: (1) a coefficient matrix **S** ∈ ℝ<sup>n×K</sup> that selects which of K prompt atoms (stored in **B** ∈ ℝ<sup>K×d</sup>) to use for each node, and (2) a prompt matrix **P** = **S** **B**<sup>⊤</sup> that applies these atoms sparsely across feature dimensions. **S** is computed by projecting node features via a linear layer, then processing the results through T sequential IF neurons that integrate, fire binary spikes when a membrane potential exceeds threshold μ, and softly reset; the averaged outputs are softmax-normalized to induce sparsity. **P** is derived by taking the weighted atom combination for each node and passing it through T *signed* IF neurons, which fire +1, -1, or 0 per feature dimension based on whether an integrated potential exceeds ±γ; the averaged signed outputs yield a sparse per-node prompt. Training freezes the pre-trained GNN backbone **f**<sub>Φ</sub> and optimizes **B**, the linear projection **W**, and a downstream linear classifier **θ** using Adam. Sparsity is controlled by hyperparameters μ, γ, and T, balancing compactness and expressiveness.

## Key Results
- **Accuracy gains:** SpikingGPF outperforms GPF and GPF-plus by 2–5% in few-shot node classification across 11 benchmark datasets with various pre-trained GNNs (GraphCL, SimGRACE, GraphMAE, EdgePred).
- **Robustness:** Maintains significantly higher accuracy than baselines under Random Attack (20–100% edge perturbation) and Metattack (5–10% perturbation), demonstrating resilience to both structural and feature noise.

## Why This Works (Mechanism)

### Mechanism 1: Sparse atom selection via IF neurons
- **Claim:** Learning a sparse coefficient matrix **S** via Integrate-and-Fire neurons selects a relevant subset of prompt atoms for each node.
- **Mechanism:** Node features **X** pass through a linear projection **W** to produce integration values α<sub>ik</sub>. These values charge T sequential IF neurons per node. Each neuron integrates (adds α<sub>ik</sub> to membrane potential), fires a binary 1 if potential exceeds threshold μ (otherwise 0), then softly resets. The average output across T neurons is softmax-normalized to yield **S**.
- **Core assumption:** Temporal accumulation and thresholding naturally induce sparsity in **S**, allowing each node to use only the most relevant prompt atoms.
- **Evidence anchors:** Abstract states learning a sparse coefficient matrix via IF neurons. Section IV.A details equations (4)–(9) and Fig. 1 illustrates the pipeline. Fig. 2 visualizes **S** sparsity increasing with μ and decreasing with T.
- **Break condition:** If μ is too low or T too large, **S** becomes dense, losing compactness. If μ is too high or T too small, **S** may become overly sparse, discarding useful signal.

### Mechanism 2: Sparse feature modification via signed IF
- **Claim:** A signed IF mechanism generates a sparse per-node prompt **p**<sub>i</sub> by thresholding feature dimensions, enhancing robustness to feature noise.
- **Mechanism:** The sparse coefficient **s**<sub>i</sub> weights the prompt atom set **B**, producing weighted values. These are integrated across T signed IF neurons. Each neuron fires a signed spike (+1, -1, or 0) per feature dimension based on whether the integrated potential exceeds +γ or -γ. The average output across T neurons gives the final sparse prompt **p**<sub>i</sub>.
- **Core assumption:** Signed firing allows the prompt to both add and subtract feature information selectively, while threshold γ controls per-dimension sparsity.
- **Evidence anchors:** Abstract mentions signed IF generating sparse prompts. Section IV.B details equations (11)–(14) and Fig. 3. Fig. 4 shows **p**<sub>i</sub> sparsity increasing with γ and decreasing with T.
- **Break condition:** Excessive sparsity (high γ, small T) may zero out important modifications. Insufficient sparsity (low γ, large T) fails to reduce noise sensitivity and computational cost.

### Mechanism 3: Dual sparsity synergy
- **Claim:** The combination of sparse **S** and sparse **p**<sub>i</sub> yields a compact, lightweight, and robust prompting design that outperforms dense baselines.
- **Mechanism:** Two-stage sparsity—first selecting a subset of prompt atoms via **S**, then applying them to a subset of feature dimensions via **p**<sub>i</sub>—creates a highly compressed prompt representation, reducing active parameters and focusing modifications on salient features.
- **Core assumption:** Not all prompt atoms or feature dimensions are equally useful for every node; a sparse combination is more efficient and less prone to noise.
- **Evidence anchors:** Abstract notes dual sparsity yields compactness and robustness. Section IV includes constrained optimization (Eq. 15). Ablation in Fig. 7 shows both sparse stages contribute gains. Section V.C robustness experiments (Figs. 5–6) under attacks show slower accuracy degradation than baselines.
- **Break condition:** If either sparsity stage is misconfigured (e.g., **S** too sparse leaves no atoms to combine, or **p**<sub>i</sub> too sparse discards all prompt effects), the synergy fails. The trade-off between sparsity and expressiveness must be tuned per dataset.

## Architecture Onboarding
**Component map:**  
Pre-trained GNN **f**<sub>Φ</sub> + Graph **G**(**X**,**A**) + Prompt Atoms **B** -> S-learning Module (Linear Projection **W** + T IF neurons) -> Sparse coefficient **S** -> P-learning Module (Signed IF neurons) -> Sparse prompt **P** (where **P** = **S** **B**<sup>⊤</sup>) -> Prompted features **X** + **P** -> frozen **f**<sub>Φ</sub> -> Node embeddings -> Linear classifier **θ** -> Output

**Critical path:**  
1. Forward: **X** -> **W** -> α -> T IF neurons (integrate, fire, reset) -> average -> softmax -> **S**.  
2. **S** and **B** -> weighted atoms **s**<sub>i</sub>**B** -> T signed IF neurons -> average -> **p**<sub>i</sub>.  
3. Form **P** = **S** **B**<sup>⊤</sup>, add to **X**.  
4. Pass **X**+**P**, **A** through frozen **f**<sub>Φ</sub> to get embeddings.  
5. Apply **θ**, compute downstream loss (e.g., cross-entropy).  
6. Backpropagate loss to update **B**, **W**, **θ** (**f**<sub>Φ</sub> frozen).

**Design tradeoffs:**  
- **μ/γ vs. T:** Higher thresholds and lower timesteps increase sparsity but risk losing signal; lower thresholds and higher timesteps increase density/computation.  
- **K (prompt atoms):** More atoms increase capacity but add parameters and potential redundancy; paper uses K=10.  
- **Signed vs. standard IF:** Signed firing (+1/-1) allows subtractive prompting but may increase sensitivity; standard (0/1) is simpler.  
- **Frozen backbone:** Enables parameter efficiency but limits adaptation to pre-trained features.

**Failure signatures:**  
- **Over-sparsity:** Accuracy drops sharply as μ/γ increase beyond a point (Fig. 8); **S** or **P** becomes too binary, model underfits.  
- **Under-sparsity:** **S** or **P** nearly dense, similarity to GPF baseline, no robustness gain under noise (Figs. 5–6), higher memory/compute.  
- **IF implementation bugs:** Non-sparse outputs if fire condition or reset logic is incorrect (e.g., forgetting soft reset).  
- **Poor generalization:** If pre-trained **f**<sub>Φ</sub> and downstream task are misaligned, even sparse prompts may fail.

**First 3 experiments:**  
1. **Sparsity visualization:** On KarateClub, set T=4, vary μ (for **S**) and γ (for **P**), visualize coefficient/prompt matrices (Figs. 2, 4) to confirm sparsity trends.  
2. **Ablation study:** Train four models on Cora: (a) GPF (dense), (b) sparse **P** only (fix **S** dense), (c) sparse **S** only (fix **P** dense), (d) full SpikingGPF (both sparse). Compare accuracies (Fig. 7).  
3. **Robustness check:** Take a trained model (e.g., on Cora with GraphCL pre-training), apply Random Attack (20–100% edge perturbation) and Metattack (5–10% perturbation). Plot accuracy vs. perturbation rate for SpikingGPF vs. GPF/GPF-plus (Figs. 5–6); expect slower degradation for SpikingGPF.

## Open Questions the Paper Calls Out
1. How do the spiking neuron hyperparameters (firing thresholds μ/γ, timesteps T) generalize across graphs with varying structural properties (e.g., homophily, density) in terms of the sparsity-performance trade-off?
2. What is the causal mechanism by which sparse prompts improve robustness—does sparsity primarily filter noise, select salient features, or both?
3. Can the dual sparsity design (sparse **S** and sparse **P**) be effectively adapted to other data-level prompt types, such as edge prompts (e.g., EdgePrompt) or subgraph prompts?
4. How does the computational overhead of SpikingGPF’s spiking neuron simulations compare to alternative sparsity-inducing methods (e.g., L1 regularization) in terms of training time, memory, and inference latency?

## Limitations
- **Hyperparameter sensitivity:** Optimal thresholds (μ, γ) and timesteps (T) vary per dataset, requiring validation-based grid search with no generalizable guidelines.
- **Missing pre-training details:** Exact protocols (augmentations, epochs) for GraphCL, SimGRACE, etc., are unspecified, making baseline replication difficult.
- **No efficiency quantification:** Claims of compactness and lightweight design lack concrete metrics (FLOPs, memory usage, latency).

## Confidence
- Dual-sparsity effectiveness (2–5% accuracy gains): **Medium** – supported by 11 datasets but hyperparameter-dependent.
- Robustness under attacks: **Medium** – trends consistent, yet attack implementations may differ.
- Spiking mechanism induces sparsity: **High** – equations and visualizations confirm expected behavior.
- Parameter efficiency: **Low** – no direct measurement provided.
