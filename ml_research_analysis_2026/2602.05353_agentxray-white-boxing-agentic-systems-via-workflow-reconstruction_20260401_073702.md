# AgentXRay: White-Boxing Agentic Systems via Workflow Reconstruction
## Quick Facts
- **arXiv ID**: 2602.05353  
- **Source URL**: https://arxiv.org/abs/2602.05353  
- **Reference count**: 11  
- **Primary result**: Achieves average static functional equivalence (SFE) of 0.426 across five domains, outperforming AFlow (0.339), with 8–22% token reduction and workflow length up to 6.

## Executive Summary
AgentXRay introduces Agentic Workflow Reconstruction (AWR) to address the black-box nature of LLM agentic systems. By leveraging only observable input-output pairs, it synthesizes interpretable white-box workflows using Monte Carlo Tree Search (MCTS) over a unified primitive space of agent roles and tools. A scoring-based Red-Black pruning mechanism focuses the search by balancing quality, depth, and width. Evaluated across five domains, AgentXRay achieves superior functional equivalence, deeper workflows, and reduced token consumption compared to unpruned baselines.

## Method Summary
AgentXRay treats workflow reconstruction as a search problem over a combinatorial space defined by agent roles (e.g., planner, executor) and tools (e.g., API calls). It employs MCTS to explore potential workflow graphs that could produce the observed input-output mappings. The search is guided by a Red-Black pruning heuristic that scores candidate branches on multiple criteria—including I/O match quality, workflow depth, and structural width—to concentrate computational effort on promising regions. This allows efficient synthesis of interpretable workflows without internal access to the black-box agent.

## Key Results
- Average SFE score of 0.426 across five domains, surpassing unpruned MCTS (AFlow, 0.339).
- Reduces token consumption by 8–22% relative to unpruned search.
- Enables workflow exploration up to length 6, while unpruned MCTS stagnates at length 2.

## Why This Works (Mechanism)
MCTS systematically explores the vast space of possible agent workflows by simulating rollouts and updating node values, balancing exploration and exploitation. The Red-Black pruning mechanism enhances efficiency by discarding low-potential branches early, using a composite score that reflects not just I/O match (quality) but also structural properties (depth, width). This prevents exhaustive enumeration and directs search toward workflows that are both functionally accurate and structurally plausible, explaining the gains in both performance (SFE) and efficiency (token/length).

## Foundational Learning
1. **Monte Carlo Tree Search (MCTS)**  
   *Why needed*: Efficiently explores combinatorial workflow spaces without exhaustive enumeration.  
   *Quick check*: Implement MCTS for a simple game (e.g., tic-tac-toe) to understand node expansion and backpropagation.

2. **Agentic Workflows as Primitives**  
   *Why needed*: Provides a structured, reusable space of roles and tools for reconstruction.  
   *Quick check*: Model a known LLM agent (e.g., a web-browsing assistant) as a graph of roles and tool invocations.

3. **Static Functional Equivalence (SFE)**  
   *Why needed*: Quantifies reconstruction accuracy when ground-truth workflows are inaccessible.  
   *Quick check*: Given two black-box systems and a set of inputs, compute SFE by comparing their output sets.

4. **Score-Based Branch Pruning**  
   *Why needed*: Reduces search space and computational cost while retaining high-quality solutions.  
   *Quick check*: Design a scoring function for a decision tree (e.g., combining accuracy and depth) and prune nodes below a threshold.

## Architecture Onboarding
- **Component map**: Input-Output Pairs → Primitive Space Definition → MCTS Engine (with Red-Black Pruner) → Workflow Synthesizer → Output Workflow  
- **Critical path**: Observed I/O pairs initialize the search; MCTS iteratively expands workflow candidates; Red-Black pruning discards low-scoring branches; the synthesizer returns the highest-scoring workflow graph.  
- **Design tradeoffs**: Pruning aggressiveness trades off between efficiency and risk of missing viable workflows; deeper searches yield more complex workflows but increase token costs.  
- **Failure signatures**: (a) High SFE with semantically incorrect workflows (e.g., wrong tool order), (b) Pruning eliminates branches that could lead to functionally equivalent but structurally different workflows, (c) Stagnation at shallow depths despite available primitives.  
- **First three experiments**:  
  1. **Baseline validation**: Run AgentXRay on a single domain with known ground-truth workflows to verify basic reconstruction capability.  
  2. **Pruning sensitivity**: Vary Red-Black scoring weights (quality vs. depth vs. width) and measure impact on SFE and token usage.  
  3. **Depth scaling**: Test maximum achievable workflow length across domains with/without pruning, controlling for token budgets.

## Limitations
- Evaluation restricted to five specific domains; generalizability to novel agent architectures or tool sets is uncertain.
- Red-Black pruning heuristics may introduce bias, potentially discarding viable workflows if the scoring proxy misaligns with true functional equivalence.
- SFE metric only measures final I/O match, ignoring semantic correctness, safety, or human interpretability of reconstructed workflows.

## Confidence
- Workflow reconstruction feasibility (AgentXRay synthesizes workflows from I/O): **Medium**  
- Search efficiency and depth gains (8–22% token reduction, length 6 vs. 2): **Medium**  
- Functional equivalence performance (SFE 0.426 avg.): **Medium**
