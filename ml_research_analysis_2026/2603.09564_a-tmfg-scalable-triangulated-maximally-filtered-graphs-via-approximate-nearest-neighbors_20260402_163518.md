# a-TMFG: Scalable Triangulated Maximally Filtered Graphs via Approximate Nearest Neighbors

## Quick Facts
- **arXiv ID:** 2603.09564  
- **Source URL:** https://arxiv.org/abs/2603.09564  
- **Reference count:** 30  
- **Primary result:** a-TMFG scales construction of Triangular Maximally Filtered Graphs to N=100,000 via approximate nearest neighbors, achieving high structural fidelity (Jaccard up to 0.96) with near-linear runtime.

## Executive Summary
The Triangular Maximally Filtered Graph (TMFG) is a parsimonious, planar graph construction method that is computationally intractable for large datasets due to its O(N²) memory and runtime requirements. This paper introduces the Approximate TMFG (a-TMFG) algorithm, which replaces the dense correlation matrix with an approximate nearest neighbor index (HNSW) and a static sparse k-NN graph. Key optimizations include bounding the active face universe, lazy deletion in the priority queue, centroid caching, and a global rescue phase that uses cached centroids to query the HNSW index when local search stalls. Evaluated on synthetic Gaussian Markov Random Field data, a-TMFG attains Jaccard scores up to 0.96 relative to exact TMFG, while scaling near-linearly (O(U N)) and constructing graphs for N=100,000 in approximately 500 seconds. This enables parsimonious graph construction from large tabular data for downstream machine learning.

## Method Summary
a-TMFG constructs a maximal planar graph incrementally by greedily selecting the best (face, node) pair according to a correlation-based score. Instead of storing an explicit N×N correlation matrix, it builds an HNSW approximate nearest neighbor index on the data and a sparse k-NN graph. An initial clique is selected from the k-NN graph to seed the first triangular face. The algorithm then repeatedly pops the top candidate from a priority queue; valid candidates trigger local expansion (adding a node, subdividing the face into three new faces, scoring new candidates from the k-NN graph), while an exhausted queue triggers a global rescue phase that batch‑queries the HNSW index with centroids of all active faces to find new frontier nodes. To control memory, the active face universe is limited to a fixed size U, and lazy deletion ensures O(1) amortized checks for validity. Face centroids are cached upon creation to avoid redundant computation. Parameters k (k‑NN size), U (face universe bound), and HNSW search depth govern the trade‑off between fidelity and speed.

## Key Results
- Structural fidelity: Jaccard similarity up to 0.96 compared to exact TMFG for optimal parameters (α ∈ [0.2, 0.3], k ≥ 50) on synthetic GMRF data.
- Scalability: Near‑linear time complexity (O(U N)); construction for N=100,000 completes in ~500 seconds, whereas exact TMFG becomes intractable beyond N≈25,000.
- Enables parsimonious graph construction from large tabular datasets, facilitating downstream machine learning applications.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The dense O(N²) correlation matrix used in exact TMFG is replaced with an approximate nearest neighbor index (HNSW) and a static sparse graph (k‑NN), reducing memory and initial search complexity.
- **Mechanism:** The k‑NN graph provides local connectivity to seed the initial clique and guide local neighborhood exploration. The HNSW index allows dynamic, efficient querying of frontier nodes (those not yet integrated) during the global rescue phase, bypassing the need to store or compute all pairwise correlations.
- **Core assumption:** Nearest neighbors within the k‑NN graph are sufficient proxies for the highest‑magnitude correlations relevant for building the TMFG’s planar structure, and the HNSW index can efficiently retrieve frontier nodes even as the integrated set grows.
- **Evidence anchors:**
  - [abstract] "employs k‑Nearest Neighbors Graphs (kNNG) for initial construction, and implements a memory management strategy to search and estimate missing correlations on‑the‑fly."
  - [section 3] "By substituting the exhaustive correlation matrix with a Hierarchical Navigable Small World (HNSW)[10] index (I) and a static sparse graph (G), we heavily reduce the search space complexity."
  - [corpus] Strong evidence for the use of graph‑based ANNS (e.g., HNSW) for scalable similarity search.
- **Break condition:** If the chosen k is too small relative to the underlying manifold’s intrinsic dimensionality, the initial k‑NN graph may be fragmented, over‑triggering the global rescue phase and potentially altering local dependency structures.

### Mechanism 2
- **Claim:** Bounding the size of the active face universe (F) and using lazy deletion in the priority queue (Q) control memory usage and reduce scoring complexity from O(N²) to approximately O(U×N), where U ≪ N.
- **Mechanism:** Only a limited subset of the theoretically possible 2N‑4 faces are retained (U). Candidates are pushed to a priority queue; when popping, faces/nodes already integrated are lazily discarded (O(1) check) instead of being removed from the heap. This keeps the active search space small.
- **Core assumption:** The distribution of selected faces in exact TMFG shows most selections occur near an "exploration frontier" (recently added faces), meaning older, distant faces can be pruned with little impact on the final graph’s topology.
- **Evidence anchors:**
  - [section 2] "most selected faces are located near the end of F (i.e., L_j = 0) suggesting one can 'forget' the earlier faces in F to at least halve its size, without severely impacting the quality."
  - [section 3] "We limit the maximum number of active faces (F) stored in memory. Candidates are evaluated and pushed to a priority queue (Q). By utilizing lazy deletion during the extraction phase, we skip outdated edges in O(1) time, reducing the scoring complexity to approximately O(U×N)."
  - [section 4.4] Empirical validation shows Jaccard score plateaus when |F| is ~0.2‑0.5N, supporting the frontier hypothesis.
- **Break condition:** If the data’s dependency structure is highly uniform or non‑hierarchical, face selection might be more uniformly distributed across the universe, making aggressive pruning detrimental.

### Mechanism 3
- **Claim:** Centroid caching of face sum‑vectors avoids redundant computation, and a global rescue phase using cached centroids ensures connectivity when local search exhausts.
- **Mechanism:** Upon creation, the centroid (sum of node features) for each face is computed and stored. If the local k‑NN graph exhausts (Q returns null), the centroids of all currently active faces are batch‑queried against the HNSW index. Since nodes already integrated are marked as deleted in the HNSW index, the query returns new frontier nodes, which are scored and pushed back into Q.
- **Core assumption:** Cached centroids are valid representatives for scoring candidate connections until the face is removed, and the HNSW index, with its hierarchical structure, can efficiently perform a batch nearest neighbor search that skips the large set of already‑integrated nodes.
- **Evidence anchors:**
  - [section 3] "To prevent redundant mathematical operations, the sum‑vector (centroid) of each face is computed once upon creation and cached. If the local search stalls, these cached vectors are passed directly to the HNSW index… the HNSW index automatically bypasses the interior of the graph."
  - [section 3] "Global Rescue Phase:… the cached centroid vectors of all currently active faces in F are queried against the HNSW index I in a single batch."
- **Break condition:** If the k‑NN graph G is severely disconnected and the HNSW index’s recall is insufficient (e.g., due to poor index parameters), the rescue phase may fail to find bridging edges, leading to a disconnected final graph.

## Foundational Learning
- **Planar Graph Triangulation (Maximal Planar Graphs)**  
  *Why needed*: The TMFG/a‑TMFG output is a maximal planar graph (3N‑6 edges). Understanding face subdivision (replacing a triangle with three new triangles by connecting a new node to all vertices of the face) is core to the algorithm’s incremental construction logic.  
  *Quick check*: What topological property forces the number of edges to be exactly 3N‑6 in a planar graph where every face (including the outer one) is a triangle?

- **Greedy Algorithm with Priority Queue**  
  *Why needed*: The TMFG is a greedy, edge‑adding algorithm that at each step selects the (face, node) pair maximizing a correlation‑based score. The priority queue is the central data structure managing this selection. Understanding lazy deletion and its O(1) amortized cost is key to the scalability claim.  
  *Quick check*: In a greedy graph‑building algorithm with a priority queue, what is the trade‑off when implementing "lazy deletion" versus actively removing outdated entries from the heap?

- **Gaussian Markov Random Field (GMRF)**  
  *Why needed*: GMRFs are the ground‑truth data generative model used for evaluation. They encode sparse, neighborhood‑dependent structures (via precision matrix) that align with the planar, local‑dependency philosophy of TMFG. The parameter α controls the influence of 2‑hop neighbors, testing the method’s sensitivity to short‑range vs. longer‑range effects.  
  *Quick check*: In a GMRF defined by Y = X + Σ_{j∈N(i)} X_j, what does the sparsity pattern of the inverse covariance (precision) matrix represent?

## Architecture Onboarding
- **Component map:**  
  1. Approximate NN Index (HNSW): Stores all data points; supports fast query(centroid_vector, exclude_integrated=True) returning nearest non‑integrated nodes.  
  2. Static k‑NN Graph (G): Pre‑computed sparse adjacency list (k neighbors per node). Used for local neighborhood scoring and initial seed clique selection.  
  3. Face Universe (F): Limited‑size container (max U) holding active faces. Each face f stores its vertex IDs and cached centroid vector.  
  4. Priority Queue (Q): Max‑heap of scored candidates (score, face_id, node_id). Supports pop() with lazy skip check.  
  5. Integration Mask: Boolean array (size N) marking nodes already added to the graph.  
  6. Rescue Module: Triggered when pop() fails; batch‑queries HNSW with centroids of all active faces F, scores results, repopulates Q.

- **Critical path:**  
  1. **Init:** Build HNSW (I) and k‑NN graph (G) from data X. Select seed clique from G’s dense triangles, compute centroids, initialize F and Q.  
  2. **Main loop (until 3N‑6 edges):** pop() from Q. If candidate valid → Local Expansion: add edges, mark node integrated, update I (mark deleted), prune F if |F|>U, subdivide face (replace f with 3 new faces), for each new face fetch neighbors from G, compute scores, push to Q.  
  3. **If pop() invalid (null):** Global Rescue: batch‑query I with centroids of all f in F, score returned nodes against F, push best pairs to Q.  
  4. **Return** final edge list.

- **Design tradeoffs:**  
  - **k (kNNG size) vs. Connectivity & Cost:** Small k reduces initial build time but may fragment the graph, increasing rescue frequency. Large k improves local guidance but increases initial O(Nk log N) HNSW build cost and memory.  
  - **U (Face Universe Limit) vs. Fidelity:** Small U enforces memory limit but may prune valuable frontier faces, lowering Jaccard score. Large U improves fidelity but increases PQ size and heap operation cost. Optimal region appears near 0.2‑0.5N.  
  - **HNSW ef/M parameters vs. Rescue Quality:** Higher HNSW search depth (ef) improves recall of frontier nodes during rescue, at the cost of query time.

- **Failure signatures:**  
  - **Disconnected final graph:** Check component count > 1. Likely cause: k too small, or HNSW ef too low causing rescue failures.  
  - **Low Jaccard similarity to exact TMFG:** Likely cause: U too small (aggressive pruning), or α in GMRF too high (data has strong 2‑hop effects, making 1‑hop based TMFG unstable).  
  - **Runtime spikes or non‑linear scaling:** Monitor PQ size and rescue frequency. Spikes may indicate U is too large (PQ bloat) or k‑NN graph is causing many re‑scoring operations.  
  - **Edge count ≠ 3N‑6:** Indicates a bug in termination condition or face subdivision logic.

- **First 3 experiments:**  
  1. **Sanity Check vs. Exact TMFG:** Run a‑TMFG on small N (e.g., 500) with very large U and high k. Verify edge count (3N‑6) and compute Jaccard score against exact TMFG. Should be ~1.0.  
  2. **Parameter Sweep for k & U:** On medium N (e.g., 10,000) from GMRF (α=0.25), vary k (10, 30, 50, 100) and U (0.1N, 0.3N, 0.5N). Plot Jaccard vs. runtime to identify elbow region (as in Fig 7).  
  3. **Stress Test Connectivity:** Deliberately set k very low (e.g., 3) on N=20,000. Monitor frequency of "Global Rescue" triggers (count null pops) and compute connectivity metrics (components, average path length). Tests robustness of rescue mechanism.

## Open Questions the Paper Calls Out
1. **Adaptive tuning:** How can the universe limit |F| and neighborhood size k be adaptively tuned during runtime to optimize the trade‑off between computational efficiency and structural fidelity without prior knowledge of the dataset?  
2. **Generalization to real‑world data:** To what extent does a‑TMFG’s performance and the properties of the resulting graphs generalize to real‑world tabular data with complex noise structures, outliers, and non‑Gaussian distributions, beyond the controlled GMRF synthetic evaluations?  
3. **Theoretical approximation guarantees:** What are the theoretical approximation guarantees of a‑TMFG relative to the exact TMFG? Specifically, how does the bounded active face universe, k‑NN initialization, and greedy face selection affect the worst‑case bound on edge set overlap (Jaccard similarity) or graph metric preservation?  
4. **Bias from global rescue:** Does the global rescue phase, designed to reconnect disconnected components, systematically bias the local topology of the a‑TMFG compared to the exact TMFG, and if so, can this bias be characterized or mitigated?

## Limitations
- HNSW index parameters and face‑universe pruning policy are underspecified; these choices may significantly affect trade‑offs between fidelity and speed.
- Evaluation is confined to synthetic GMRF data; real‑world data with noise, non‑Gaussian dependencies, or complex manifold structure could degrade performance.
- The claimed near‑linear scaling holds only if the active face limit U is bounded independently of N; if U scales with N (as in experiments), asymptotic complexity reverts to O(N²) albeit with a smaller constant.

## Confidence
- **High structural fidelity**: High on synthetic GMRF (Jaccard ≤ 0.96), but Medium for generalization to real data.
- **Scalability**: Medium; empirical timing up to N=100k is convincing but lacks theoretical guarantee for strictly subquadratic scaling when U ∝ N.
- **Mechanism efficacy**: Medium; evidence (e.g., face distribution, rescue triggers) is plausible but not exhaustively validated.

## Next Checks
1. **Parameter sensitivity sweep:** Systematically vary HNSW parameters (M, ef), k‑NN size k, and face limit U across multiple datasets to produce robust default settings and quantify trade‑offs between Jaccard, runtime, and connectivity.
2. **Connectivity guarantee analysis:** Stress‑test with very low k and low HNSW ef; measure rescue trigger frequency and final component count; derive sufficient conditions (e.g., minimum k for a connected kNNG) to ensure a connected output.
3. **Real‑world benchmarking:** Apply a‑TMFG to diverse tabular datasets (e.g., genomics, finance); compare downstream task performance (e.g., semi‑supervised classification) against standard graph sparsification methods (k‑NN, MST, graphical lasso).
