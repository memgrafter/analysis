# Latent Space Communication via K-V Cache Alignment

## Quick Facts
- **arXiv ID**: 2601.06123
- **Source URL**: https://arxiv.org/abs/2601.06123
- **Reference count**: 19
- **Primary result**: Aligns key-value caches across LLMs via lightweight adapters to enable direct state sharing, improving language modeling and enabling zero-shot transfer of soft prompts.

## Executive Summary
Large language models (LLMs) from different pretraining runs often have incompatible internal representations, hindering collaborative inference and skill sharing. This paper introduces a method to align the key-value (KV) cache—the hidden states used during autoregressive generation—into a shared latent space. By attaching small adapter modules to each frozen LLM, the KV cache of any model can be translated to and from this common space, allowing models to directly read and write each other’s internal states. Experiments with Gemma-2 models of varying sizes demonstrate that prefix caches translated through the shared space improve language modeling performance (lower negative log-likelihood) and can even surpass each model’s standalone capability. Moreover, soft prompts learned on one model can be transferred zero‑shot to others with different architectures, achieving performance close to per‑model fine‑tuning. The adapter‑based design scales linearly with the number of models and permits adding new models without retraining existing adapters.

## Method Summary
The method equips each LLM \(m_i\) with two lightweight adapter networks: \(T[m_i \rightarrow \Sigma]\) maps its local KV cache (shape \(B \times S \times L_i \times D_i\)) into a shared latent space \(\Sigma\) of fixed dimension \(Q\); \(T[\Sigma \rightarrow m_i]\) maps from \(\Sigma\) back to \(m_i\)’s cache structure. The base models remain frozen; only adapters are trained. Training uses a suffix language modeling objective. Given a source model \(m_i\) and a target model \(m_j\), we compute the source KV cache for a prefix, translate it to \(\Sigma\) and then to the target’s cache format, and feed this translated cache to \(m_j\) as a prefix for predicting the suffix tokens. The cross‑entropy loss on the suffix tokens is backpropagated only through the two adapters. The shared space \(\Sigma\) has no predetermined layer‑wise correspondence; its dimension \(Q\) must be divisible by each model’s number of layers \(L_i\). Adapters employ a cross‑attention mechanism over the input KV block, with separate transforms for keys and values. For a pool of \(N\) models, training randomly samples source‑target pairs each step, learning a complete translation graph. At inference, any model’s KV cache can be translated to any other model via its adapters, enabling direct inter‑model communication and zero‑shot transfer of cache‑based modules such as soft prompts.

## Key Results
- KV cache translation yields lower negative log‑likelihood on target models compared to using their own caches, often exceeding standalone performance.
- Soft prompts trained on one model can be transferred to models of different sizes/architectures without additional training, matching per‑model fine‑tuning performance.
- The adapter design scales linearly with the number of models; adding a new model only requires training its two adapters, leaving existing ones unchanged.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Adapter modules can learn to translate a model’s internal KV cache state into a shared latent space and back, enabling direct state transfer between models with frozen parameters.
- **Mechanism:** For each model \(m_i\), two adapter modules are trained: \(T[m_i \rightarrow \Sigma]\) maps its local KV cache into a shared space \(\Sigma\) of fixed size \(Q\); \(T[\Sigma \rightarrow m_i]\) maps from \(\Sigma\) back into the model’s local cache structure. The shared space \(\Sigma\) has no predetermined layer‑wise correspondence, forcing the output adapters to learn appropriate reconstruction.
- **Core assumption:** The structural differences between models’ latent spaces can be overcome by learning an intermediary space where cached representations from different models become approximately interchangeable.
- **Break condition:** If the divergence between two models’ KV cache manifolds is too great for the adapter capacity, translation quality degrades catastrophically.

### Mechanism 2
- **Claim:** Training the adapters with a suffix language modeling loss, rather than a reconstruction loss, is sufficient and more effective for aligning latent spaces because it directly optimizes for downstream utility.
- **Mechanism:** The primary loss \(L_{LM}\) conditions the target model on a translated prefix cache from a source model and evaluates cross‑entropy loss on subsequent tokens. This aligns the shared space to preserve features predictive of future tokens in the target model’s distribution. The authors find that reconstruction loss is unnecessary when the task loss is present.
- **Core assumption:** A shared space aligned for the specific task (language modeling) will be more useful than one aligned for generic reconstruction.
- **Break condition:** If the task‑loss signal is too sparse or models have disjoint vocabularies, the mechanism may fail without an auxiliary reconstruction loss.

### Mechanism 3
- **Claim:** A successfully aligned global latent space enables zero‑shot portability of learned modules (like soft prompts) that manifest as KV cache prefixes, as the module’s cache can be translated into any model’s space.
- **Mechanism:** A soft prompt \(P\) trained on model \(m_s\) produces a KV cache \(KV_s(P)\). This cache is translated via \(T[m_s \rightarrow \Sigma]\) and \(T[\Sigma \rightarrow m_t]\) to produce \(KV_t(P)\), which model \(m_t\) can use as a prefix to replicate the behavior.
- **Core assumption:** Task‑specific knowledge learned by one model via prefix tuning is adequately captured within its KV cache and that this state’s translation through the shared space preserves semantic intent.
- **Break condition:** If the learned module’s efficacy depends on idiosyncratic features not represented in the cache, translation will fail to recover the intended function.

## Foundational Learning
- **Concept: Transformer Key-Value Cache Mechanics**  
  The method operates on the KV cache—the set of key and value vectors computed during autoregressive generation. Understanding that this cache is a compressed, stateful representation of the context is fundamental. The cache shape is \((B, S, L, D)\) where \(B\) is batch size, \(S\) is sequence length, \(L\) is number of layers, and \(D\) is model dimension. The layer‑wise structure (\(L\)) is a key challenge for cross‑model translation.
- **Quick check question:** What is the dimensional structure \((B, S, L, D)\) of a KV cache for a batch of sequences, and why is its layer‑wise structure a key challenge for cross‑model translation?

- **Concept: Adapter-Based Parameter-Efficient Fine-Tuning**  
  Adapters are small, trainable modules inserted into a frozen model. Here they are applied not to model inputs/outputs but to internal latent states (KV caches). This modularity enables linear scaling with number of models and avoids modifying pretrained parameters.
- **Quick check question:** If adapters are inserted between model layers or at the cache level, what are the trade‑offs in terms of added latency versus expressiveness compared to fine‑tuning the entire model?

- **Concept: Representation Alignment in Deep Networks**  
  The core hypothesis is that disparate models’ representations can be aligned. This relates to theories about the geometry of neural networks; the paper tests alignment in the dynamic, stateful context of KV caches.
- **Quick check question:** What does it mean for two models’ latent spaces to be “aligned,” and why might a task‑specific loss (language modeling) yield a better shared space than a generic reconstruction loss?

## Architecture Onboarding
- **Component map:**  
  Base Models (\(m_i\)): Frozen LLMs (e.g., Gemma‑2) with standard transformer architectures. Each produces a KV cache of shape \((B, S, L_i, D_i)\).  
  Adapters \(T[m_i \rightarrow \Sigma]\) and \(T[\Sigma \rightarrow m_i]\): Two lightweight transformer‑based networks per model. They translate between the model’s KV cache and the shared space \(\Sigma\). They use layer‑wise cross‑attention over the input KV block and separate transforms for keys and values.  
  Shared Space \(\Sigma\): An implicit, global space of dimension \(Q\). No dedicated parameters; it is the hub state between adapters. All models route through it.  
  Training Loop: Processes batches of text. For selected model pairs \((m_i, m_j)\): compute \(KV_i\) from source prefix; translate to \(KV_j\) via adapters; compute suffix LM loss on target model \(m_j\); backpropagate only through adapters.

- **Critical path:**  
  1. **Data Pipeline:** Generate KV caches for prefixes from all source models. Must store or recompute caches on‑the‑fly.  
  2. **Adapter Forward Pass:** For translation \(m_i \rightarrow m_j\): run \(T[m_i \rightarrow \Sigma]\) on \(KV_i\), then \(T[\Sigma \rightarrow m_j]\) on result. Feed into \(m_j\)’s prefill with the translated cache.  
  3. **Loss Computation:** Compute cross‑entropy on suffix tokens. Base models are frozen, so gradients flow only through the two adapters.  
  4. **Path Sampling:** For a pool of \(N\) models, there are \(N(N-1)\) directed paths. Training samples a subset per step (e.g., 1‑2 paths).

- **Design tradeoffs:**  
  - **Adapter Size vs. Performance:** Larger adapter capacity (via `embed_dim_factor` and `translation_dim_factor`) improves alignment but adds compute/memory. Linear maps are a baseline but may require dimension blow‑up.  
  - **Shared Space Dimension \(Q\):** Must be divisible by all \(L_i\). Larger \(Q\) increases expressiveness but also parameter count and training memory.  
  - **Path Sampling:** Using all paths is combinatorial. Fewer paths per step reduces compute but may hurt generalization; paper finds 1‑2 paths often sufficient. Trade‑off between training stability and coverage.

- **Failure signatures:**  
  - Cyclic translation loss > identity loss: Translating \(KV_i \rightarrow \Sigma \rightarrow m_i\) yields worse LM loss than using original \(KV_i\), indicating adapters cannot preserve their own model’s state.  
  - High variance across translation directions: Some \(m_i \rightarrow m_j\) paths work, others fail, suggesting uneven latent divergence.  
  - No improvement over random soft‑prompt in module portability: Translated modules perform no better than random initialization, indicating shared space doesn’t preserve task semantics.

- **First 3 experiments:**  
  1. **Verify Cyclic Consistency:** Train adapters for a single model pair \((m_1, m_2)\). Evaluate \(L_{LM}\) for original \(KV_1\) vs. cycle‑translated \(KV_1\). Expect improvement after training.  
  2. **Ablate Adapter Architecture:** Replace cross‑attention adapters with linear maps; compare performance and parameter count. Test if linear maps suffice for similar models.  
  3. **Test Zero‑Shot Module Portability:** Without meta‑training on portability, take a soft‑prompt learned on \(m_1\), translate its KV cache to \(m_2\) via adapters, and evaluate task loss. Expect significant gap to per‑model fine‑tuning baseline.

## Open Questions the Paper Calls Out
1. **Scalability to Heterogeneous Models**  
   - **Question:** Can the framework scale effectively to pools with significantly different architectures (e.g., decoder‑only vs. encoder‑decoder, Mixture‑of‑Experts) and much larger parameter counts (e.g., >10B)?  
   - **Basis in paper:** Conclusion states scaling to larger, more heterogeneous pools as an immediate next step.  
   - **Why unresolved:** Experiments only on small Gemma‑2 models (100M–400M) with identical architecture. Scalability to vastly different architectures/scales remains untested.  
   - **What evidence would resolve it:** Systematic experiments aligning KV caches between models of disparate architectures and scales, measuring translation fidelity and downstream LM performance.

2. **Alternative Alignment Objectives**  
   - **Question:** Does the suffix LM loss capture all necessary signals, or could auxiliary losses (contrastive, adversarial, trajectory‑based) improve alignment and transferability?  
   - **Basis in paper:** Section 7.3 shows reconstruction loss is unnecessary when using suffix LM loss, but no other objectives are explored.  
   - **Why unresolved:** The paper dismisses reconstruction loss but does not compare to other alignment objectives common in latent space literature.  
   - **What evidence would resolve it:** Ablation comparing suffix LM loss against alternative objectives (e.g., InfoNCE, adversarial, cycle‑consistency) on both LM performance and module portability.

3. **Portability of Non‑Soft‑Prompt Modules**  
   - **Question:** How portable are non‑soft‑prompt modules (e.g., LoRA weights, full checkpoints, reasoning chain caches) through the shared latent space?  
   - **Basis in paper:** Section 6 focuses exclusively on soft prompts; the abstract mentions “learned skills such as soft prompts” but not generality to other module types.  
   - **Why unresolved:** Soft prompts are low‑rank and directly map to initial KV caches; other modules (e.g., LoRA) may not manifest as simple cache translations.  
   - **What evidence would resolve it:** Experiments translating various module types (LoRA weights, chain‑of‑thought caches) through the shared space and evaluating utility on target models.

4. **Theoretical Properties of the Shared Space**  
   - **Question:** What are the theoretical properties (e.g., uniqueness, stability, dimensionality) of the learned shared latent space \(\Sigma\), and how does its geometry relate to individual models’ spaces?  
   - **Basis in paper:** The paper treats \(\Sigma\) as implicit; no analysis of its intrinsic structure is provided.  
   - **Why unresolved:** Understanding \(\Sigma\) could inform design choices (e.g., size \(Q\)), explain generalization, and relate to universal embedding hypotheses.  
   - **What evidence would resolve it:** Analytical studies of \(\Sigma\)’s representations (e.g., probing for disentangled factors, CCA alignment metrics, testing linearity vs. nonlinearity).

5. **Complex Collaborative Inference Paradigms**  
   - **Question:** Can the framework enable more complex collaboration beyond single‑step prefix‑suffix LM (e.g., multi‑turn agent conversations, dynamic model cascades, iterative reasoning)?  
   - **Basis in paper:** Conclusion mentions future work on agentic and software engineering tasks; introduction hints at cascades but experiments only test single‑step translation.  
   - **Why unresolved:** The current evaluation is limited to held‑out text prediction after one cache translation. Multi‑round state exchange behavior is unknown.  
   - **What evidence would resolve it:** Implement and test scenarios like multi‑agent debate, iterative cascade refinement, or mixture‑of‑experts routing using the shared space, measuring task success.

## Limitations
- Exact C4 preprocessing, train/validation splits, and handling of variable‑length sequences are not specified, hindering exact replication.
- Adapter architecture details (e.g., cross‑attention masking, layer‑wise connectivity, separate key/value transforms) are described conceptually but lack pseudocode or precise specifications.
- Hyperparameter sweep results (optimal learning rates, batch sizes per model size) are not reported, leaving best configurations ambiguous.
- Soft‑prompt training protocol for module transfer (prompt length, optimization steps) is underspecified, limiting assessment of zero‑shot portability generality.

## Confidence
- Adapter translation mechanism: Medium
- Suffix LM loss sufficiency: High
- Zero‑shot module portability: Medium

## Next Checks
1. **Exact adapter replication**: Implement cross‑attention adapters with layer‑wise processing and separate K/V input transforms; verify that cyclic translation loss does not exceed baseline after training on a single model pair.
2. **Hyperparameter recovery**: For a fixed model pair (e.g., Gemma‑2 200M → 400M), reproduce the learning rate and batch size sweep; report the configuration that maximizes NLL improvement on validation.
3. **Cross‑task portability test**: Train a soft prompt on a new task (e.g., sentiment classification) using a source model; translate its KV cache to a target model via pre‑trained adapters; evaluate task accuracy against random prompts and per‑model fine‑tuning.
