# Thinking with Tables: Enhancing Multi-Modal Tabular Understanding via Neuro-Symbolic Reasoning

## Quick Facts
- **arXiv ID:** 2603.24004
- **Source URL:** https://arxiv.org/abs/2603.24004
- **Reference count:** 40
- **Primary result:** Neuro-symbolic framework achieves 10% average accuracy gain over open-source baselines on TVMU benchmarks, matching or exceeding proprietary models.

## Executive Summary
This paper introduces "Thinking with Tables" (TWT), a neuro-symbolic framework designed to tackle the challenge of reasoning over tables extracted from images using both textual and visual cues. TWT addresses three core difficulties: variable table structures and data incompleteness, complex feature dependencies, and task heterogeneity across question answering and prediction. By employing a code-based reasoning mechanism within an external sandbox and a two-stage training process (Task-Oriented Supervised Fine-Tuning and Adaptive Loss-Scaled Reinforcement Learning), TWT demonstrates strong performance across eight benchmark datasets, consistently outperforming open-source baselines and matching or surpassing proprietary models.

## Method Summary
TWT uses a neuro-symbolic approach where a multimodal language model (MLLM) generates Python code to interact with an external sandbox. This sandbox provides access to data files (CSV, images) and pretrained models (e.g., ResNet50) for precise, verifiable operations. The system operates in a closed loop: the model generates code with structured tags (`<analy>`, `<code>`, `<code_results>`, `<answer>`), the sandbox executes the code, and results are fed back for subsequent reasoning. Training occurs in two stages: TO-SFT, which learns diverse task pipelines from synthesized trajectories, and AL-GRPO, which refines performance using answer-based rewards while encouraging stable, executable code generation through adaptive loss scaling.

## Key Results
- TWT achieves an average 10% accuracy gain over open-source baselines across eight TVMU benchmarks.
- The framework matches or exceeds proprietary models like GPT-5.1 and Qwen3-VL-Plus.
- TWT shows particular strength in handling incomplete tables, modeling feature-target relationships, and generalizing across heterogeneous task requirements.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Code-based neuro-symbolic reasoning in a constrained external sandbox enables robust handling of structurally variable and incomplete tables.
- **Mechanism:** The model generates executable Python code within a sandbox that can read actual data files. Execution results are fed back for subsequent reasoning, creating a closed loop where each step is grounded in verifiable data operations.
- **Core assumption:** Symbolic code execution provides reliable intermediate states that can compensate for missing/ambiguous visual information.
- **Evidence anchors:** Program-aided reasoning in sandbox; limited corpus overlap with prior work.
- **Break condition:** Fails when table structures are so degraded that code-based extraction cannot recover meaningful relationships.

### Mechanism 2
- **Claim:** Two-stage training (TO-SFT then AL-GRPO) decouples task-pipeline acquisition from outcome optimization, addressing heterogeneity across QA and prediction tasks.
- **Mechanism:** TO-SFT uses curated trajectories to internalize distinct problem-solving pipelines. AL-GRPO then applies RL with answer-based rewards and adaptive loss scaling to refine final accuracy while stabilizing code generation across task types.
- **Core assumption:** Task heterogeneity manifests primarily in pipeline structure, not in underlying reasoning primitives.
- **Evidence anchors:** Two-stage training description; TO-SFT masking to prevent memorization; AL-GRPO's selective loss computation.
- **Break condition:** If TO-SFT data is too narrow, AL-GRPO cannot recover missing pipeline variants.

### Mechanism 3
- **Claim:** Adaptive loss scaling in AL-GRPO encourages executable and stable code generation without requiring handcrafted code-level rewards.
- **Mechanism:** During RL sampling, only outputs where all code segments terminated normally contribute to the policy gradient loss, creating an implicit incentive for runnable code while still optimizing for final answer correctness.
- **Core assumption:** Code stability is a necessary condition for correct answers; filtering out failed executions reduces training noise.
- **Evidence anchors:** AL-GRPO loss computation details; improved code execution accuracy on most datasets after AL-GRPO.
- **Break condition:** When correct solutions require exploring code paths that initially fail, the filter removes those trajectories.

## Foundational Learning
- **Concept:** Neuro-symbolic integration
  - **Why needed here:** TWT relies on neural perception for multimodal understanding but uses symbolic code for precise operations on tabular data. Without this hybrid paradigm, one might misinterpret the system as "just prompting for code."
  - **Quick check question:** Why can't chain-of-thought alone replace the code-execution loop in TWT's design?

- **Concept:** Reinforcement learning from outcome rewards
  - **Why needed here:** AL-GRPO's adaptive scaling is critical for moving beyond imitation learning to optimize for correct answers across heterogeneous tasks. Understanding KL-penalized policy gradient methods is necessary to interpret the training objective.
  - **Quick check question:** How does AL-GRPO differ from standard PPO in handling sparse rewards from code execution?

- **Concept:** Tabular data peculiarities
  - **Why needed here:** TVMU tasks involve tables with merged cells, missing values, hierarchical headers, and non-standard layouts. The framework's robustness to variable structures depends on handling these variabilities.
  - **Quick check question:** Why would a standard MLLM struggle with a three-line table format compared to TWT?

## Architecture Onboarding
- **Component map:** Base MLLM (Qwen3-VL-8B) → Interaction protocol module → Sandbox executor → Training pipeline (TO-SFT data synthesizer + AL-GRPO optimizer)
- **Critical path:**
  - Inference: User query → model generates `<analy>` + `<code>` → sandbox runs code → returns `<code_results>` → model iterates → final `<answer>`.
  - Training: Synthesize trajectories → TO-SFT trains pipeline patterns → Sample outputs → Filter successful executions → Compute AL-GRPO loss → Update policy.
- **Design tradeoffs:**
  - Safety vs. expressivity: Sandbox restricts file access and execution time but limits complex external tool integration.
  - Data efficiency vs. generalization: TO-SFT requires high-quality synthesized trajectories; AL-GRPO needs diverse samples to avoid collapse.
  - Immediate correctness vs. long-term stability: AL-GRPO's loss scaling favors stable code but may filter exploratory solutions.
- **Failure signatures:**
  - Model repeatedly outputs code that times out or crashes sandbox.
  - Performance gap between TO-SFT and +AL-GRPO is negative or negligible.
  - Code execution accuracy drops on a specific dataset while final accuracy improves.
- **First 3 experiments:**
  1. Main results: Evaluate TWT vs 7 baselines on 8 TVMU benchmarks showing ~10% avg gain.
  2. Ablation: Measure impact of removing TO-SFT or AL-GRPO stages.
  3. Code stability analysis: Compare code execution accuracy before/after AL-GRPO.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How sensitive is the quality of TWT's training data to the 10% relative error tolerance for regression tasks in the synthesis pipeline, and does this tolerance affect the model's robustness to noisy or incomplete tables at test time?
- **Basis in paper:** The data synthesis process accepts regression samples where "a relative error of up to 10% is tolerated" (Page 5).
- **Why unresolved:** The tolerance parameter directly controls the trade-off between trajectory validity and diversity, potentially impacting performance on real-world tables with more noise or missing values.
- **What evidence would resolve it:** Ablation study varying the tolerance (e.g., 5%, 10%, 15%, 20%) and measuring model accuracy on benchmarks, particularly under artificially corrupted table conditions.

### Open Question 2
- **Question:** Why does code execution accuracy on TAT-QA decrease after AL-GRPO training while overall task accuracy improves, and what does this suggest about the relationship between code stability and complex reasoning capability?
- **Basis in paper:** The authors report a slight decrease in code execution accuracy on TAT-QA after AL-GRPO, but claim overall performance improvements indicate enhanced reasoning capability on complex tasks (Page 8).
- **Why unresolved:** The conventional expectation is that more accurate code execution leads to better final answers. The counterintuitive trend raises questions about whether the model generates more ambitious or error-prone code that occasionally fails but leads to correct answers via fallback mechanisms.
- **What evidence would resolve it:** Qualitative examination of code snippets before and after AL-GRPO on TAT-QA samples, classifying error types and correlating per-sample code success/failure with final answer correctness.

### Open Question 3
- **Question:** Can TWT generalize to TVMU tasks beyond the two categories (multimodal QA and prediction) on which it was trained, such as table summarization, data imputation, or cross-lingual table understanding, without additional fine-tuning?
- **Basis in paper:** Training data synthesis and evaluation are limited to eight datasets covering only QA and prediction, though the paper claims TWT addresses task heterogeneity.
- **Why unresolved:** The two-stage training internalizes specific pipelines; it is unclear if the learned policy is flexible enough to adapt to new task specifications via in-context learning alone.
- **What evidence would resolve it:** Zero-shot or few-shot evaluation on additional TVMU tasks using out-of-distribution benchmarks.

## Limitations
- Sandbox safety constraints may artificially limit the model's ability to perform complex operations, potentially underestimating its true reasoning capability.
- TO-SFT's reliance on synthesized trajectories from stronger models raises questions about whether learned pipelines transfer to truly unseen table structures.
- AL-GRPO's adaptive loss scaling may filter out innovative but initially unstable solution paths.

## Confidence
- **High confidence** in core mechanism validity (code-based neuro-symbolic reasoning for TVMU)
- **Medium confidence** in training effectiveness (two-stage process yields consistent improvements)
- **Low confidence** in safety/performance boundary conditions (sandbox limits, code execution filtering)

## Next Checks

3. Measure performance degradation when sandbox execution is replaced with simulated code execution to quantify sandbox overhead.
