# Khatri-Rao Clustering for Data Summarization

## Quick Facts
- arXiv ID: 2603.06602  
- Source URL: https://arxiv.org/abs/2603.06602  
- Reference count: 40  
- Primary result: The Khatri-Rao clustering paradigm produces more succinct data summaries (fewer parameters) than standard centroid-based clustering with minimal accuracy loss, achieving up to 81% lower inertia on synthetic data and up to 85% parameter reduction in deep clustering.

## Executive Summary
The paper addresses redundancy in centroid-based clustering summaries for large datasets. It introduces the Khatri-Rao clustering paradigm, where cluster centroids are generated by aggregating smaller sets of protocentroids via Khatri-Rao operators (sum or elementwise product). Two concrete instantiations are proposed: Khatri-Rao k-Means, which optimizes the standard k-Means inertia under a factorized centroid representation, and a Khatri-Rao deep clustering framework that jointly compresses autoencoder weights and latent centroids. Experiments show that these methods achieve significant parameter savings—e.g., up to 81% lower inertia than k-Means with equal parameters on synthetic data, and up to 85% reduction in deep clustering parameters—while maintaining comparable clustering accuracy on real-world datasets.

## Method Summary
Khatri-Rao k-Means replaces the explicit set of k centroids with p sets of protocentroids (θ¹,…,θᵖ). Each virtual centroid μ_{j₁…jₚ} is formed on-the-fly by combining one protocentroid from each set using an aggregator ⊕ (sum or product). The algorithm alternates between assigning points to the nearest virtual centroid and updating the protocentroids in closed form (Proposition 6.1), thereby reducing the number of free parameters from k=∏hᵢ to ∑hᵢ. The Khatri-Rao deep clustering framework extends this idea to autoencoder-based clustering (e.g., DKM, IDEC). It (a) constrains latent centroids to the Khatri-Rao structure and (b) reparameterizes each autoencoder weight matrix W as a Hadamard product of q smaller factor pairs (W = (A₁⊙B₁)⊙…⊙(A_q⊙B_q)), which allows controlling the trade-off between reconstruction quality and parameter count. The combined loss (clustering + reconstruction) is optimized via backpropagation, with an iterative rank‑adjustment step to ensure the compressed autoencoder matches the uncompressed reconstruction error.

## Key Results
- Khatri-Rao k-Means uses fewer parameters (h₁+h₂ vs. h₁⋅h₂) and achieves up to 31–81% lower inertia than standard k-Means with equal parameter budgets on synthetic data.  
- Khatri-Rao deep clustering reduces parameter counts by up to 85% with minimal impact on accuracy; on MNIST, the parameter ratio is 0.74 while maintaining similar NMI.  
- Case studies demonstrate superior color quantization (43% lower inertia than k-Means) and improved communication‑efficiency trade‑offs in federated learning.

## Why This Works (Mechanism)

### Mechanism 1: Succinct centroid representation via Khatri‑Rao factorization
- **Claim:** Centroids can be represented more succinctly by expressing them as the Khatri‑Rao aggregation (sum or elementwise product) of smaller sets of protocentroids, rather than as independent vectors.  
- **Mechanism:** Instead of storing k independent centroid vectors (≈k×m parameters), store p sets of h₁,…,hₚ protocentroids (total ∑ᵢhᵢ vectors). Each of the k = ∏ᵢhᵢ centroids is generated on‑the‑fly by combining one protocentroid from each set via the aggregator (⊕).  
- **Core assumption:** The underlying cluster structure can be effectively captured by this factorized, interactive representation. The paper demonstrates this on the stickfigures dataset where additive interactions between upper/lower body protocentroids generate all poses.  
- **Evidence anchors:** [abstract] “centroids arise from the interaction of two or more succinct sets of protocentroids.” [section 4] Formalizes Problem 1 (Khatri‑Rao k‑Means) where centroid μᵢ = θⱼ₁¹ ⊕ θⱼ₂² … ⊕ θⱼₚᵖ. [corpus] Neighbor papers focus on standard or deep clustering; none address Khatri‑Rao factorization, indicating novelty.  
- **Break condition:** If the true cluster centroids do not exhibit a near‑factorizable structure under the chosen aggregator (+ or ×), enforcing the Khatri‑Rao constraint will force a poor fit, increasing inertia/loss significantly compared to unconstrained centroids with the same parameter budget.

### Mechanism 2: Alternating optimization for Khatri‑Rao k‑Means
- **Claim:** The Khatri‑Rao k‑Means algorithm optimizes the standard k‑Means objective (inertia) while respecting the Khatri‑Rao structure, using alternating closed‑form updates for protocentroids.  
- **Mechanism:** It alternates between: (1) assigning points to the ∏ᵢhᵢ virtual centroids (computed on‑the‑fly from protocentroids), and (2) updating each protocentroid set by solving a constrained sub‑problem. For aggregator ⊕=×, the update for θⱼ¹ uses a ratio of weighted Hadamard products (Proposition 6.1).  
- **Core assumption:** The alternating optimization will converge to a local optimum where the Khatri‑Rao structure is approximately valid and inertia is reduced relative to a standard k‑Means solution with the same number of free parameters (∑ᵢhᵢ).  
- **Evidence anchors:** [section 6] Algorithm 1 details steps; Proposition 6.1 gives closed‑form update rules. [section 9.2] On synthetic Blobs and Classification datasets, Khatri‑Rao k‑Means with p=2 and h₁=h₂ achieves up to 31–81% lower inertia than k‑Means using only h₁+h₂ parameters. [corpus] Neighbor papers address different k‑Means variants; none use Khatri‑Rao factorization.  
- **Break condition:** The coupled update rules (changing one protocentroid affects all centroids that include it) make the objective landscape more rugged than standard k‑Means, leading to poorer local minima without careful initialization or many restarts (noted in section 6).

### Mechanism 3: Joint compression in deep clustering
- **Claim:** The Khatri‑Rao deep clustering framework compresses both the latent‑space centroids (via Khatri‑Rao structure) and the autoencoder weights (via Hadamard decomposition), achieving large parameter reductions with minimal accuracy loss.  
- **Mechanism:** (a) Latent centroids are constrained as in Mechanism 1. (b) Each weight matrix Wˡ of the autoencoder is reparameterized as a Hadamard product of q smaller factor matrices: Wˡ = (Aˡ₁⊙Bˡ₁)⊙…⊙(Aˡ_q⊙Bˡ_q). A factor‑rank of r allows representing a rank‑rᵖ matrix using only 2qr vectors.  
- **Core assumption:** (a) The latent space learned by the autoencoder can be clustered effectively with factorized centroids. (b) The weight matrices of a performant autoencoder admit a low‑rank Hadamard decomposition that preserves reconstruction quality.  
- **Evidence anchors:** [section 7] Problem 2 and Equation (6) define the reparameterization. Section 7 states “the Khatri‑Rao deep clustering framework can compress the data summaries produced by deep clustering algorithms by up to 85% with negligible loss in accuracy.” [table 3] On 13 datasets, Khatri‑Rao variants (DKM/IDEC) use 15–79% of the parameters of the originals while often matching or exceeding NMI/ARI. [section 9.4] In federated learning (FEMNIST), Khatri‑Rao‑FkM achieves ~5× lower inertia at equal communication cost.  
- **Break condition:** If the reparameterized autoencoder cannot achieve reconstruction loss comparable to the full autoencoder (despite rank adjustment), the subsequent clustering will suffer. The paper’s strategy to iteratively increase rank until loss matches is a mitigation, not a guarantee.

## Foundational Learning
**Centroid‑based clustering (e.g., k‑Means)**  
*Why needed here:* Khatri‑Rao k‑Means is a direct extension. Understanding the assignment‑update loop, inertia objective, and the independence of centroid updates is essential to see the novelty of coupled protocentroid updates.  
*Quick check question:* In standard k‑Means, why does updating a centroid by the cluster mean minimize inertia for that cluster given fixed assignments?

**Matrix decompositions (Khatri‑Rao and Hadamard products)**  
*Why needed here:* The entire paradigm rests on these operators. The Khatri‑Rao product generates all combinations of vectors from sets (for centroids). The Hadamard (elementwise) product is used for both the ⊕=× aggregator and for autoencoder reparameterization.  
*Quick check question:* How does the number of parameters in a Khatri‑Rao representation (∑ᵢhᵢ) compare to the number of explicit centroids it can generate (∏ᵢhᵢ)? What about a Hadamard product of two d×r matrices?

**Autoencoder‑based deep clustering (e.g., DKM, IDEC)**  
*Why needed here:* The deep clustering framework extends these specific algorithms. One must understand the joint optimization of reconstruction loss and clustering loss in a latent space to grasp why compressing both centroids and autoencoder parameters is beneficial.  
*Quick check question:* In DKM/IDEC, what is the role of the Student’s t distribution and the target distribution in the clustering loss L_cluster?

## Architecture Onboarding
**Component map:**  
Data points → Virtual centroids (computed from protocentroid sets {θⁱ} via aggregator ⊕) → Assignments (hard matrix for k‑Means or soft for deep) → Loss (inertia or L_cluster + w_rec L_rec) → Update step (closed‑form for protocentroids in k‑Means; gradient descent for deep, including autoencoder weights reparameterized via Hadamard products) → (Deep) Autoencoder weights → back to virtual centroids.

**Critical path:**  
1. Initialize protocentroids (random or k‑Means++‑style).  
2. Compute virtual centroids μ_{j₁,…,jₚ} = θ¹_{j₁} ⊕ … ⊕ θᵖ_{jₚ}.  
3. Assign each data point to the nearest centroid (hard for k‑Means; soft via current assignments for deep clustering).  
4. Update protocentroids: For k‑Means, solve closed‑form subproblems (Proposition 6.1); for deep clustering, perform gradient descent on total loss, backpropagating through the aggregator and Hadamard reparameterization.  
5. Repeat steps 2–4 until convergence (centroid movement < ε or max iterations).

**Design tradeoffs:**  
- **p (number of protocentroid sets):** Higher p yields more compression (hᵖ centroids from p×h vectors) but makes optimization harder and reduces interpretability. Paper recommends p=2.  
- **Aggregator (⊕):** Sum (+) is easier (linear interactions). Product (×) can capture multiplicative effects but may cause instability. Choice is heuristic; sum generally better for deep clustering.  
- **Hadamard factors (q) and ranks (r):** More factors/rank increase autoencoder capacity and reconstruction quality but decrease compression. Default q=2; ranks are iteratively increased until compressed autoencoder reconstruction loss ≤ uncompressed loss.

**Failure signatures:**  
- **High inertia/loss:** Khatri‑Rao structure not suitable or optimization stuck in bad local minimum.  
- **Non‑convergence or runtime blowup:** p too large leading to combinatorial number of virtual centroids; consider memory‑efficient on‑the‑fly centroid computation.  
- **Degenerate protocentroids (zeros/NaNs):** Especially with ⊕=×; use regularization, clipping, or restart.  
- **Deep clustering:** Compressed autoencoder reconstruction loss remains significantly higher than uncompressed even after rank adjustment → clustering quality will degrade; increase ranks or adjust factors.

**First 3 experiments:**  
1. **Synthetic validation:** Run Khatri‑Rao k‑Means with p=2, h₁=h₂ vs. standard k‑Means with h₁⋅h₂ and h₁+h₂ centroids on synthetic Blobs/Classification datasets; expect Khatri‑Rao to achieve inertia comparable to k‑Means(h₁⋅h₂) but with only h₁+h₂ parameters.  
2. **Aggregator sensitivity:** Compare ⊕=+ vs. ⊕=× on datasets with/without multiplicative structure; expect product may underperform unless data has multiplicative factors.  
3. **Deep clustering compression:** Train DKM/IDEC and Khatri‑Rao variants on MNIST; track parameter count ratio and NMI/ARI; expect Khatri‑Rao uses 20–80% of parameters with <0.05 NMI drop, and compressed autoencoder reconstruction loss within 1–2% of uncompressed.

## Open Questions the Paper Calls Out
**Open Question 1:** How can datasets that inherently exhibit additive or multiplicative Khatri‑Rao structures be effectively characterized or detected?  
*Basis:* The conclusion explicitly identifies this as the most pressing challenge.  
*Why unresolved:* The paradigm assumes such structure may exist but provides no method to identify it; without detection, it is unclear when Khatri‑Rao clustering will yield benefits over standard approaches.  
*What evidence would resolve it:* Development and validation of statistical or learning‑based techniques that infer the presence of Khatri‑Rao structure, estimate its parameters (number of sets, cardinalities, aggregator), and demonstrate accuracy on synthetic data with known structure and improved summary compression on real data.

**Open Question 2:** Can the Khatri‑Rao clustering paradigm be applied to centroid‑free clustering algorithms (e.g., hierarchical clustering)?  
*Basis:* The paper states “Investigating whether our ideas can also be applied to clustering algorithms that do not rely on centroids, such as hierarchical clustering, is left to future research.”  
*Why unresolved:* The current formulation relies on explicit centroid representations; centroid‑free methods lack such a representation, making it nontrivial to incorporate Khatri‑Rao constraints without altering the fundamental algorithmic approach.  
*What evidence would resolve it:* A reformulation of a centroid‑free method (e.g., hierarchical clustering) that incorporates Khatri‑Rao structured prototypes, showing improved succinctness of summaries while maintaining or matching clustering quality on standard benchmarks.

**Open Question 3:** How can the number of clusters be automatically determined within the Khatri‑Rao deep clustering framework?  
*Basis:* The paper notes “for deep clustering, a Khatri‑Rao variant of such algorithms as DipDECK or DeepDPM, which also optimize the number of underlying clusters, can be designed.”  
*Why unresolved:* Existing Khatri‑Rao deep clustering requires specifying the number of protocentroids and sets; without automatic selection the method is less applicable to datasets where the true cluster count is unknown.  
*What evidence would resolve it:* A Khatri‑Rao extension of DipDECK or DeepDPM that jointly optimizes assignments, protocentroids, and the effective number of clusters (e.g., via Bayesian Information Criterion or statistical tests), validated on synthetic data with ground‑truth cluster counts and competitive performance on real datasets.

## Limitations
- Aggregator selection (sum vs. product) is heuristic and product may cause numerical instability.  
- Khatri‑Rao k‑Means runtime and memory scale with ∏ hᵢ; large p or hᵢ can lead to blowup.  
- No theoretical error bounds relative to unrestricted centroids; generalization to sparse data and streaming settings untested.

## Confidence
- Factorized centroid representation: High (synthetic), Medium (real).  
- Khatri‑Rao k‑Means inertia reduction: High on synthetic blobs/classification; Medium on real data.  
- Deep clustering compression (up to 85% parameter reduction): Medium (minor NMI drops on some datasets; success hinges on careful rank selection).  
- Federated learning advantage: Medium (demonstrated only on FEMNIST).

## Next Checks
1. **Aggregator auto‑selection:** Design a heuristic (e.g., based on residual PCA) to choose sum vs. product; validate on synthetic datasets with known additive/multiplicative structure; compare achieved inertia against an oracle that knows the true structure.  
2. **Scalability stress test:** Run Khatri‑Rao k‑Means with p=3 and hᵢ≈10 (k=1000) on a large dataset (e.g., ImageNet features); measure runtime, memory consumption, and convergence stability across different initialization strategies.  
3. **Deep compression robustness:** Systematically vary the number of Hadamard factor pairs q and the rank‑doubling schedule on MNIST and CIFAR‑10; plot reconstruction loss vs. clustering NMI to identify the practical limits of compression and sensitivity to hyperparameters.
