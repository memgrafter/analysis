# Pareto-Optimal Anytime Algorithms via Bayesian Racing
## Quick Facts
- **arXiv ID**: 2603.08493
- **Source URL**: https://arxiv.org/abs/2603.08493
- **Reference count**: 20
- **Primary result**: PolarBear reduces function evaluations by 59% on MA-BBOB benchmarks while aligning with traditional analyses, handles unknown optima and heterogeneous instances, and outputs a Pareto set that supports arbitrary time preferences.

## Executive Summary
PolarBear presents a Bayesian framework for comparing anytime optimization algorithms without requiring normalization or known optima. By using ordinal rankings rather than objective values, it aggregates performance across heterogeneous instances while preserving tradeoffs over computational budgets. The core method defines Pareto dominance over time: an algorithm is non-dominated if no competitor beats it at all timepoints. A temporal Plackett-Luce model enables adaptive racing, eliminating dominated algorithms with calibrated uncertainty. On MA-BBOB benchmarks, PolarBear reduces function evaluations by 59% (1.72e8 vs 4.2e8) compared to exhaustive evaluation, while reproducing conclusions of traditional EAF/AOCC analyses. It also handles scenarios with unknown optima and heterogeneous instance distributions (e.g., GP-BBOB with wall-clock time), yielding a Pareto set that supports arbitrary monotonic time preferences without additional experiments.

## Method Summary
PolarBear’s method addresses the anytime algorithm comparison problem by modeling rankings at each timepoint with a Plackett-Luce distribution. The algorithm ratings θ(t) vary over time, and a prior (e.g., independent Dirichlet or Gaussian process) shares information across timepoints. Bayesian inference updates the posterior over θ(t) as batches of rankings are observed. The racing loop adaptively samples new instances, runs candidate algorithms up to their unresolved time budgets, and collects rankings. Pairwise dominance is assessed via posterior probabilities: an algorithm A is α-dominated by B if P(θ_B(t) > θ_A(t) ∀ t) ≥ α. Dominated algorithms are eliminated, and the process terminates when all pairwise relations within the candidate set are resolved, yielding a Pareto set that supports arbitrary monotonic time preferences post-hoc.

## Key Results
- 59% reduction in function evaluations on MA-BBOB (1.72e8 vs 4.2e8) while aligning with EAF/AOCC analyses.
- Successfully handles unknown optima and heterogeneous instances (e.g., GP-BBOB with wall-clock time), identifying a Pareto set of {NONE, SEP} after 528 instances.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: Rankings enable scale-free, normalization-free aggregation across heterogeneous instances.
- Mechanism: By discarding cardinal objective values and observing only ordinal rankings of algorithm performance at each timepoint, PolarBear avoids the need for instance-specific bounds (e.g., optima) and the instability of min-max normalization. The Plackett-Luce model’s IIA property ensures pairwise win probabilities are unaffected by the presence of other algorithms, allowing coherent pooling of rankings across arbitrary instance distributions.
- Core assumption: Performance differences in objective value do not carry reliable, comparable meaning across instances or problem landscapes. Only relative ordering is trustworthy.
- Evidence anchors:
  - [abstract] "By using rankings rather than objective values, our approach requires no bounds, no normalization, and aggregates coherently across arbitrary instance distributions without requiring known optima."
  - [section 2] "Rankings require none of these assumptions. The statement that 𝐴 beats 𝐵 on a given instance is meaningful regardless of objective scale... Rankings extract exactly the information we can trust, namely relative performance, without requiring assumptions about what objective differences mean."
  - [corpus] Corpus neighbors focus on multi-objective optimization and Pareto fronts; the paper’s distinct contribution is applying ranking invariance to *temporal* anytime comparison, not just static multi-objective problems.
- Break condition: If objective values are on a known, comparable scale with uniform difficulty (rare in practice), cardinal information could improve efficiency. Violating IIA (e.g., portfolio effects where adding an algorithm changes pairwise beliefs) would invalidate the elimination logic.

### Mechanism 2
- Claim: Temporal Pareto dominance preserves tradeoffs over budget, supporting any monotonic time preference without additional experiments.
- Mechanism: An algorithm is non-dominated if no competitor beats it at *every* timepoint. This defines a Pareto set over time. Any strictly increasing preference functional over time (e.g., weighted integral, early-bias) selects an algorithm from this set. The posterior over ratings supports computing the preference value distribution for any such functional post-hoc.
- Core assumption: User preferences over computational budget are unknown at benchmarking time but are strictly monotonic in win probability (more is always better).
- Evidence anchors:
  - [abstract] "defines Pareto dominance over time—an algorithm is non-dominated if no competitor beats it at all timepoints."
  - [section 4] "Algorithm 𝐴 is optimal under some 𝑢 ∈ 𝒰 if and only if 𝐴 ∈ 𝒫." Proof shows Pareto set membership is necessary and sufficient for optimality under some strictly monotonic 𝑢.
  - [corpus] Corpus papers often collapse performance to scalars (AOCC) or use fixed cutpoints; PolarBear explicitly preserves the full temporal Pareto frontier.
- Break condition: If user preferences are non-monotonic (e.g., penalizing early performance), the Pareto characterization may not suffice. The IIA assumption also underpins that adding algorithms doesn’t change pairwise dominance relations.

### Mechanism 3
- Claim: Bayesian racing with temporal Plackett-Luce models enables adaptive, uncertainty-aware elimination of dominated algorithms, minimizing experimental cost.
- Mechanism: A posterior over time-varying ratings is updated with each batch of observed rankings. Algorithms are eliminated when the posterior probability of being dominated at all timepoints exceeds a threshold (𝛼). Adaptive batching and resolution modes (pointwise vs. crossing) focus evaluations on informative comparisons. Termination occurs when all pairwise relations within the candidate Pareto set are resolved.
- Core assumption: Performance trajectories evolve smoothly or independently enough that the prior (e.g., GP, independent Dirichlet) effectively shares information across timepoints, allowing early confident inference.
- Evidence anchors:
  - [abstract] "Bayesian inference over a temporal Plackett-Luce ranking model provides posterior beliefs about pairwise dominance, enabling early elimination of confidently dominated algorithms."
  - [section 4.1] Defines 𝛼-dominance and anytime dominance using posteriors. Section 4.2 details elimination and resolution modes.
  - [section 5.1] Synthetic examples show correct Pareto set recovery with fewer evaluations than exhaustive runs.
- Break condition: If performance trajectories are highly volatile or non-smooth, temporal priors may over-smooth, leading to premature elimination. The procedure’s sample efficiency gains depend on clear dominance or crossing patterns; nearly equivalent algorithms require many samples regardless.

## Foundational Learning
- **Independence of Irrelevant Alternatives (IIA)**
  - Why needed: IIA ensures pairwise win probabilities are invariant to the inclusion/exclusion of other algorithms, essential for valid elimination and dynamic algorithm addition.
  - Quick check: If you observe that A beats B on an instance, does adding a third algorithm C change your belief about whether A beats B? (In PL, no.)

- **AnyTime Pareto Optimality**
  - Why needed: Captures algorithms optimal under some strictly monotonic time preference, providing a minimal, preference-agnostic output for unknown budgets.
  - Quick check: Can an algorithm that never has the highest win probability at any single timepoint still be in the Pareto set? (Yes, if it crosses others and is non-dominated.)

- **Posterior-based Resolution vs. Frequentist p-values**
  - Why needed: PolarBear needs the probability that A dominates B at all timepoints to eliminate and stop; posterior gives direct probability, p-value does not.
  - Quick check: What does a 0.99 posterior probability of A dominating B mean, and how does it differ from a p-value of 0.01?

## Architecture Onboarding
- **Component map**:
  1. Ranking observer: Collects best-so-far solutions at each timepoint for all algorithms on an instance, produces a full ranking (handles ties via expansion).
  2. Temporal PL model: Parameterized by time-varying ratings θ(t) (simplex) or log-utilities μ(t). Supports independent Dirichlet (per-timepoint), GP/HSGP/random walk/B-spline (smooth temporal).
  3. Posterior inference engine: MCMC (NUTS) for accuracy; Pathfinder/Laplace for speed (independent models). Parallelizes across timepoints for independent priors.
  4. Elimination logic: Computes pairwise α-dominance (pointwise or joint) and (ε,α)-equivalence from posterior samples.
  5. Resolution controller: Tracks which pairs are resolved. Implements strict or crossing resolution. Manages adaptive batch sizing.
  6. Racing loop: Samples unresolved algorithms on new instances, updates posterior, checks elimination/resolution, terminates when all pairs in candidate set resolved.

- **Critical path**: Posterior update → pairwise relation checks for all candidate pairs → elimination → resolution update → sample allocation decision. Elimination can cascade (eliminating A may resolve B’s pairs with others).

- **Design tradeoffs**:
  - Model choice: Independent Dirichlet + Pathfinder (fast, parallel) vs. temporal GP (smooth, joint queries, slower). Temporal models needed for joint dominance; independent sufficient for pointwise but may over-sample.
  - Elimination: Pointwise (allows stopping algorithms early per timepoint) vs. joint (more conservative, avoids negative correlation pitfalls).
  - Resolution: Strict (required for arbitrary preferences) vs. crossing (saves samples by early resolution of crossing trajectories, but yields looser posteriors).
  - Batch size: Small batches minimize wasted evaluations but incur inference overhead; large batches amortize cost but may oversample resolved pairs. Adaptive heuristic doubles/halves based on resolution rate.

- **Failure signatures**:
  - Premature elimination: If pointwise elimination used with negatively correlated posteriors (e.g., “A better early, B better late” uncertainty), algorithms may be eliminated incorrectly. Switch to joint elimination or use temporal model.
  - Non-convergence: If posterior remains diffuse after many samples, either data is uninformative (algorithms nearly equivalent) or model is mis-specified (e.g., wrong smoothness). Check ESS/R̂ diagnostics.
  - Slow crossing detection: If two algorithms have subtle performance differences across time, crossing resolution may require many samples. Consider relaxing α or ε if practical equivalence is acceptable.
  - Tie explosion: Many exact ties (e.g., on easy problems) can slow inference with expansion. Consider subsampling permutations or tie-aware PL parameterization.

- **First 3 experiments**:
  1. Synthetic ground truth validation: Sample true ratings from a Matérn GP, generate rankings via Gumbel noise. Run PolarBear with same model class; verify recovered Pareto set matches truth and sample efficiency. Vary model misspecification (e.g., wrong lengthscale) to test robustness.
  2. Replication of traditional benchmark: On MA-BBOB with known optima, compare PolarBear’s Pareto set and posterior to EAF/ECDF/AOCC conclusions. Check that eliminated algorithms correspond to clear inferiority in ECDF plots. Measure total evaluations saved.
  3. Heterogeneous instance distribution test: Use GP-BBOB or similar with unknown optima and varying dimensions. Run PolarBear with wall-clock time as budget. Verify that it identifies a Pareto set without normalization, and that the posterior supports meaningful selection under different time preferences.

## Limitations
- Exact prior hyperparameters and batch adaptation thresholds are not specified, potentially affecting reproducibility and sample efficiency.
- The Independence of Irrelevant Alternatives (IIA) assumption may be violated if algorithms exhibit portfolio effects or context-dependent performance.
- Temporal smoothness priors (e.g., GP kernels) are weakly specified; misspecification could cause premature elimination or slow convergence.

## Confidence
- Ranking-based scale-free aggregation: High
- Temporal Pareto optimality preserving preferences: Medium
- Bayesian racing sample efficiency: Medium
