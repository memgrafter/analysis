# When Benchmarks Lie: Evaluating Malicious Prompt Classifiers Under True Distribution Shift

## Quick Facts
- **arXiv ID**: 2602.14161  
- **Source URL**: https://arxiv.org/abs/2602.14161  
- **Reference count**: 40  
- **Primary result**: LODO evaluation reveals an 8.4 percentage point AUC overestimation in standard splits; 28% of top SAE features are dataset-dependent shortcuts; an activation-based classifier achieves 81.8% weighted accuracy and 0.912 pooled AUC on out-of-distribution data.

## Executive Summary
Malicious prompt classifiers are typically evaluated using random train-test splits across aggregated benchmark datasets, which inflates performance estimates because models exploit dataset-specific superficial patterns (shortcuts) rather than learning generalizable indicators of malicious intent. This paper introduces Leave-One-Dataset-Out (LODO) evaluation, where each dataset is held out entirely as a test set, to measure true out-of-distribution generalization. Across 18 heterogeneous datasets and 105K samples, LODO exposes an average 8.4 percentage point drop in pooled AUC compared to standard splits. Sparse autoencoder (SAE) analysis shows that 28% of the top interpretable features are dataset-dependent shortcuts, and an 18-way dataset classifier reaches 96.6% accuracy, confirming strong dataset distinguishability. Activation-based classifiers (using raw model activations) achieve 81.8% weighted accuracy and 0.912 pooled AUC under LODO, far surpassing production guardrails (PromptGuard 2, LlamaGuard) and LLM-as-judge on indirect/agentic attacks (7–37% detection). Finally, weighting explanations by LODO feature retention filters dataset artifacts and yields more reliable rationales.

## Method Summary
The authors gather 18 malicious/benign prompt datasets (105K samples total, with some capped for size) spanning harmful requests, jailbreaks, indirect injections, and extraction attacks. Prompts are rendered using the Llama-3.1-8B-Instruct chat template, optionally including tool schemas for agentic scenarios. Model activations are extracted from the residual stream at layer 31 (last user token position -5). For interpretability, a sparse autoencoder (SAE) at layer 27 encodes activations into ~131k features. A linear classifier (L2-regularized logistic regression) is trained on these features. Evaluation compares random splits within the combined corpus to LODO: for each dataset, the classifier is trained on all other datasets and tested on the held-out one. Shortcuts are identified by measuring LODO coefficient retention for each feature (retention < 0.5 indicates dataset dependence). Explanations are generated by multiplying standard feature attributions by retention scores. The approach is benchmarked against production guardrails (PromptGuard 2, LlamaGuard) and an LLM-as-judge baseline on indirect attacks.

## Key Results
- Standard train-test splits overestimate classifier performance by 8.4 percentage points (pooled AUC) due to dataset-specific shortcuts.
- Under LODO, 28% of top SAE features are dataset-dependent shortcuts; an 18-way dataset classifier achieves 96.6% accuracy, confirming strong dataset distinguishability.
- An activation-based classifier (raw features) achieves 81.8% weighted accuracy and 0.912 pooled AUC on LODO, while production guardrails and LLM-as-judge fail on indirect/agentic attacks (7–37% detection).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Standard cross-validation overestimates classifier generalization because models exploit dataset-specific superficial patterns (shortcuts) rather than learning semantically meaningful attack features.
- **Mechanism**: When training and test samples originate from the same dataset sources, any feature correlated with dataset provenance (e.g., formatting quirks, source-specific jargon) becomes a valid predictor. The classifier learns these shortcuts instead of generalizable malicious intent signals.
- **Core assumption**: Benchmark datasets contain unique, identifiable artifacts (e.g., single-class datasets, formatting conventions) that serve as trivial classification cues when datasets are mixed in train-test splits.
- **Evidence anchors**:
  - [abstract] "aggregate metrics show an 8.4 percentage point AUC inflation"
  - [section 5.1] Per-dataset accuracy gaps range from 1.2% to 25.4% between held-out test (same-source) and LODO (different-source) evaluation.
  - [corpus] Corpus evidence is weak; neighboring papers focus on attack creation or generic detection, not distribution-shift evaluation protocols.
- **Break condition**: If all datasets are perfectly homogeneous in style and content (no distinctive artifacts), or if training data includes every possible dataset distribution, shortcuts cannot be exploited. This is rare in practice.

### Mechanism 2
- **Claim**: A substantial fraction of top SAE features (28%) are dataset-dependent shortcuts, meaning their predictive power vanishes when the contributing dataset is held out.
- **Mechanism**: Sparse autoencoder features, while designed to be interpretable concepts, can still capture dataset-specific patterns (e.g., email headers from Enron, password-extraction framing from Mosscap). The LODO coefficient retention metric identifies these by measuring feature weight stability across dataset holdouts.
- **Core assumption**: Features with low retention across LODO folds derive their signal from specific dataset compositions rather than invariant semantic properties of malicious/benign content.
- **Evidence anchors**:
  - [abstract] "28% of top SAE features are dataset-dependent shortcuts"
  - [section 5.2] Table 4 taxonomy: pure shortcuts (predict dataset identity) and context-dependent shortcuts (signal depends on dataset mix). Dataset classifier achieves 96.6% accuracy, confirming distinguishability.
  - [corpus] Corpus lacks direct analysis of SAE feature stability across dataset holdouts; this is a novel diagnostic introduced in this work.
- **Break condition**: If all top features maintain consistent coefficients (>90% retention) across all LODO folds, no dataset shortcuts exist. This would require datasets to be indistinguishable in SAE feature space.

### Mechanism 3
- **Claim**: LODO-weighted explanations (feature contributions multiplied by retention scores) filter dataset artifacts, yielding more reliable rationales for classifier decisions on out-of-distribution inputs.
- **Mechanism**: Standard feature attribution (activation × coefficient) highlights influential features but cannot distinguish whether a feature's high weight is generalizable or a shortcut. Multiplying by LODO retention downweights features that are unstable across dataset holdouts, promoting features that consistently predict the class label regardless of dataset provenance.
- **Core assumption**: Features stable across LODO folds are more likely to capture genuine malicious/benign semantics rather than dataset-specific correlations.
- **Evidence anchors**:
  - [abstract] "LODO-weighted explanations filter dataset artifacts for more reliable detection rationales."
  - [section 5.4] 98.1% of samples show reranking of top-20 features when applying LODO weights; demoted features have mean retention 0.265 vs. promoted 0.990 (Cohen’s d=5.60, p<0.001).
  - [corpus] No direct corpus evidence; this is an original contribution of the paper.
- **Break condition**: If retention scores do not correlate with human judgments of feature relevance, or if all features are equally stable, LODO weighting provides no benefit. This would imply either no shortcuts exist or stability is unrelated to interpretability.

## Foundational Learning
- **Concept: Domain Generalization & LODO Evaluation**
  - **Why needed here**: Understanding why standard train-test splits fail requires knowing that OOD generalization must be measured by holding out entire data sources (domains), not just random samples. LODO is the core evaluation protocol proposed.
  - **Quick check question**: If a classifier trained on datasets A+B+C is tested on held-out samples from A (random split), does this measure generalization to a *new* dataset D? Why or why not?

- **Concept: Dataset Shortcuts (Spurious Correlations)**
  - **Why needed here**: The failure mode is not sample-level spurious correlations but *dataset-level* artifacts. Recognizing this distinction is key to diagnosing why models fail on new datasets.
  - **Quick check question**: Can a feature that perfectly predicts "Enron email" but is irrelevant to malicious content still be useful in standard evaluation? How does LODO expose this?

- **Concept: Sparse Autoencoder (SAE) Features for Interpretability**
  - **Why needed here**: SAE features decompose activations into potentially interpretable concepts, enabling shortcut analysis and explanation generation. However, they introduce their own generalization gaps vs. raw activations.
  - **Quick check question**: If an SAE feature strongly activates on both malicious samples from Dataset X and benign samples from Dataset Y, could it still be a useful classifier feature? Under what conditions?

## Architecture Onboarding
### Component map
Dataset Collection -> Activation Extractor -> SAE Encoder (optional) -> Classifier -> LODO Evaluator -> Shortcut Analyzer -> Explanation Generator

### Critical path
Data -> (chat template) -> Activation extraction -> SAE encoding (optional) -> Classifier training (on N−1 datasets) -> Hold-out evaluation -> Retention computation -> Explanation weighting.

### Design tradeoffs
- **Raw vs. SAE features**: Raw activations generalize better (AUC 0.912 vs 0.838) but are less interpretable. SAE enables explanations but suffers more from shortcuts.
- **LODO computational cost**: Requires training K classifiers for K datasets (tractable for linear probes, expensive for fine-tuning).
- **Threshold selection**: Fixed 0.5 threshold is dataset-agnostic but suboptimal; per-dataset calibration varies widely (0.01–0.73 optimum). Deployment requires held-out calibration.
- **Model access**: Activation-based approach needs white-box model access (open-weight only). For closed APIs, use a sidecar open model or distill into text-based classifier.

### Failure signatures
- **High CV / high LODO gap**: >5 percentage point drop from CV to LODO indicates shortcut reliance.
- **Heterogeneous per-dataset LODO scores**: Wide accuracy range across held-out datasets (e.g., 42.8% on harmbench vs. 98.9% on injecagent) signals uneven generalization.
- **Low retention features**: Top features with r_j < 0.5 are likely shortcuts; if many such features exist, classifier may fail on new distributions.
- **Baseline failure on indirect attacks**: PromptGuard/LlamaGuard <40% detection on BIPIA/InjecAgent shows architectural limitations for agentic scenarios.

### First 3 experiments
1. **Replicate LODO gap**: Train logistic regression on raw activations using standard 80/20 split *within* combined datasets; compute pooled AUC. Then run LODO (train on 17, test on 1); compare. Expect ~8pp gap.
2. **Shortcut identification**: Compute LODO retention for top-50 SAE features. Verify >25% are shortcuts (retention <50%). Train an 18-way dataset classifier on SAE features; expect >95% acc.
3. **Baseline comparison on indirect attacks**: Evaluate PromptGuard 2, LlamaGuard, and Llama-as-Judge on BIPIA and InjecAgent under LODO. Expect <40% detection for production guardrails, while activation classifier achieves >60%.

## Open Questions the Paper Calls Out
1. **What training techniques most effectively reduce the LODO generalization gap while maintaining performance across all attack types?**  
   The authors state in Section 6: "Systematically reducing the LODO gap remains an open challenge" after noting mixed results with Group DRO and DANN. Initial experiments showed high variance, improving some datasets while regressing others, and results varied across random seeds.

2. **Why do linear probes on model activations substantially outperform zero-shot LLM-as-judge prompting for detecting indirect prompt injections?**  
   The paper highlights that Llama-as-Judge achieved only 21.5% detection on InjecAgent, while activation probes reached 99%, noting "We hypothesize that models encode safety-relevant signals in activations that are difficult to elicit through prompting." The hypothesis is not formally tested; it's unclear whether recognition (probes) is easier than articulation (prompting), or if distributed activation patterns don't map cleanly to natural language.

3. **To what extent do dataset-specific shortcuts affect raw activation-based classifiers, and can we quantify and mitigate them without SAE decomposition?**  
   The paper analyzes shortcuts only on SAE features, finding 28% of top features are dataset-dependent. However, the LODO gap persists for raw activations (0.912 vs 0.996 AUC), and raw activations are polysemantic, making shortcut characterization difficult. The authors note this as a limitation.

4. **Can the LODO evaluation protocol be extended beyond prompt attack detection to other security-critical NLP tasks with benchmark aggregation issues?**  
   In Section 7, the authors suggest "extend this evaluation methodology to other security domains" as future work, implying LODO's applicability is not yet established beyond their context. The paper only evaluates on prompt injection/jailbreak benchmarks. Other security tasks may have different data characteristics and shortcut structures.

5. **How can we calibrate detection thresholds for prompt attack classifiers to maintain low false positive rates across heterogeneous out-of-distribution datasets?**  
   Section H.1 shows per-dataset optimal thresholds vary widely (0.01 to 0.73 under LODO), and using t=0.5 causes significant F1 loss on some datasets (17pp on BIPIA). Threshold calibration is distribution-dependent; a single threshold cannot optimize all attack types. The paper uses t=0.5 as a default but acknowledges deployment requires per-distribution calibration.

## Limitations
- Exact SAE checkpoint for layer27 (Arditi, 2024) and feature indexing not uniquely identified; may cause variation in shortcut metrics.
- Logistic regression hyperparameters (e.g., `C`, solver) and sample-capping method (random/stratified) are unreported; assumptions could affect quantitative results.
- Activation extraction details (batch size, device, padding) are not fully documented; may introduce minor differences.
- No official test splits for 6 datasets prevents exact replication of held-out test metrics reported in the paper.

## Confidence
- **LODO protocol effectiveness**: High – the evaluation methodology is clearly described and logically sound.
- **Quantitative claims** (8.4pp AUC inflation, 28% shortcut fraction): Medium – unreplicated hyperparameters and SAE version introduce uncertainty.
- **Robustness of activation-based classifier** to new datasets: Low – only one model (Llama-3.1-8B-Instruct) was tested; no ablations over layers/positions.

## Next Checks
1. **Hyperparameter sensitivity**: Re-run LODO logistic regression with varied `C` (0.1–10) and solvers (liblinear, saga) to quantify gap stability; expect >5pp gap across reasonable settings.
2. **SAE feature audit**: Using the exact Arditi (2024) layer-27 SAE (publicly released), recompute retention for top-50 features; verify shortcut rate remains >25% and dataset classifier >95% accuracy.
