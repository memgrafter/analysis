# VietNormalizer: An Open-Source, Dependency-Free Python Library for Vietnamese Text Normalization in TTS and NLP Applications

## Quick Facts
- **arXiv ID:** 2603.04145
- **Source URL:** https://arxiv.org/abs/2603.04145
- **Reference count:** 1
- **Primary result:** A zero-dependency, rule-based Python library that normalizes Vietnamese non-standard words (numbers, dates, times, currency, percentages, acronyms, loanwords) for TTS/NLP, enabling high-throughput processing without GPU or external APIs.

## Executive Summary
VietNormalizer addresses the absence of a lightweight, standalone Vietnamese text normalization tool for TTS and NLP. Existing solutions either rely on heavy neural dependencies or lack comprehensive coverage of structured non-standard words (NSWs). The library provides a deterministic, rule-based pipeline with pre-compiled regular expressions and customizable CSV dictionaries. It has been adopted in production systems like VietSuperSpeech and covers NSW classes (e.g., dates, currency with VND/USD) that other Vietnamese tools do not. The primary outcome is a publicly available, installable package (via PyPI) that performs normalization entirely on CPU with no external dependencies. No quantitative accuracy metrics are reported; success is measured by functional deployment and breadth of coverage.

## Method Summary
The library employs a purely rule-based approach with no neural components. A `VietnameseTextProcessor` class applies a fixed sequence of pre-compiled regex transformations for specific NSW classes: Unicode normalization, dates, times, currency (VND/USD), percentages, general numbers, and finally dictionary-based replacement. Number verbalization handles Vietnamese-specific irregularities (e.g., "linh một" for numbers ending in 1 in the 21–29 range). Two CSV dictionaries (acronyms, loanwords) allow users to extend coverage without code changes. All regex patterns are compiled once during initialization to minimize per-utterance overhead, supporting batch processing at scale. The system is implemented in pure Python 3.8+ with zero external dependencies.

## Key Results
- Provides a zero-dependency, installable Python library for Vietnamese text normalization.
- Covers a broad set of NSW classes (numbers, dates, times, currency, percentages, acronyms, loanwords) with rules tailored to Vietnamese conventions.
- Enables high-throughput CPU-based processing, adopted in production TTS pipelines.
- Offers user-extensible CSV dictionaries for acronym expansion and loanword transliteration.

## Why This Works (Mechanism)

### Mechanism 1: Deterministic Rule-Based Pipeline
- **Claim:** A fixed, rule-based sequence can convert structured Vietnamese NSWs into spoken forms without neural models.
- **Mechanism:** The `VietnameseTextProcessor` applies regex transformations in a priority order (Unicode → dates → times → currency → percentages → numbers → dictionaries). Each NSW class has dedicated functions with Vietnamese-specific logic, such as recursive number decomposition handling irregular forms ("một mươi" vs. "linh một"). Ambiguities (e.g., "2/9" as date vs. fraction) are resolved by pattern priority.
- **Evidence anchors:**
  - Abstract: Mentions a "unified, rule-based pipeline" for integers, dates, times, currency, percentages, and Unicode.
  - Section 3.1: Explicit normalization order.
  - Corpus contrast: Prior work (ViSoLex, ViLexNorm) targets social media lexical normalization, a different NSW scope.
- **Break condition:** Fails on context-dependent ambiguities not decidable by pattern priority (Section 4.3).

### Mechanism 2: Pre-Compiled Regex for High Throughput
- **Claim:** Pre-compiling all regex patterns at initialization enables efficient batch processing.
- **Mechanism:** Patterns are compiled once via `re.compile()` during `VietnameseNormalizer` instantiation. Dictionary keys are joined into a single alternation regex, ensuring input scanning is *O(n)* in text length, independent of dictionary size.
- **Evidence anchors:**
  - Section 3.4: States pre-compilation enables "high-throughput batch processing... tens of thousands of utterances per minute on a single CPU core."
  - Zero dependencies: Implementation in pure Python avoids neural/GPU overhead.
- **Break condition:** Very large dictionaries (>10k entries) may cause regex backtracking or high init memory; not profiled.

### Mechanism 3: CSV Dictionary Extensibility
- **Claim:** User-replaceable CSV dictionaries allow customization for acronyms and loanwords without code changes.
- **Mechanism:** The normalizer loads two CSV files mapping raw tokens to normalized forms (e.g., "NASA" → "na-sa"). These mappings are integrated into the final single-pass regex replacement. Dictionaries can be reloaded at runtime via `reload_dictionaries()`.
- **Evidence anchors:**
  - Section 3.3: Describes built-in CSV dictionaries and runtime reloading.
  - Listing 1: Code example showing custom dictionary paths.
- **Break condition:** Ambiguous dictionary entries (multiple expansions) lead to non-deterministic replacement order based on regex alternation.

## Foundational Learning
- **Concept:** Text Normalization (TN) for TTS
  - **Why needed:** TN converts raw text (e.g., "14:30", "1.500.000đ") into a canonical spoken form ("mười bốn giờ ba mươi phút", "một triệu năm trăm nghìn đồng") for acoustic models.
  - **Quick check:** For "GDP tăng 5%", the normalized form should be "ji-di-pe tăng năm phẩy trăm" before phoneme conversion.
- **Concept:** Non-Standard Words (NSWs) Classification
  - **Why needed:** VietNormalizer implements a subset of semiotic classes (cardinal, date, time, money, measure, abbreviation) tailored to Vietnamese. This taxonomy explains ambiguities (e.g., "2/9" as date, fraction, or address).
  - **Quick check:** In "Cắm USB vào máy", "USB" is an acronym/loanword, not a measure or verbatim foreign word; it should be expanded/transliterated (e.g., "u-ni-ét").
- **Concept:** Vietnamese Number Verbalization Irregularities
  - **Why needed:** Vietnamese numbers have context-sensitive forms (e.g., "một" → "một mươi" in 10–19, "linh một" in 21–29, "mốt" in 21–29 units). The recursive algorithm hardcodes these.
  - **Quick check:** 101 = "một trăm linh một", 110 = "một trăm mười", 115 = "một trăm mười lăm". Differences arise from tens/units irregularities.
- **Concept:** Regex Pre-compilation and Single-Pass Dictionary Replacement
  - **Why needed:** Performance relies on avoiding per-utterance regex compilation and *O(n·|D|)* loops. A single compiled alternation regex scans text in *O(n)*.
  - **Quick check:** With 1,000 acronyms, `re.compile("|".join(keys))` scans the text once; a loop with `str.replace` does 1,000 full scans per utterance—depth-first matching is slower.

## Architecture Onboarding
- **Component map:** `VietnameseNormalizer` (public API) -> `VietnameseTextProcessor` (logic) + CSV dictionaries (acronyms, loanwords). The processor holds pre-compiled regex patterns for NSW classes; the normalizer compiles a final dictionary pattern from CSVs.
- **Critical path:** `normalize(text)` → (if preprocessing) sequential calls: `_normalize_unicode` → `_normalize_date` → `_normalize_time` → `_normalize_currency` → `_normalize_percentage` → `_normalize_numbers` → final `re.sub(_dict_pattern, ...)`. Order prevents partial matches (e.g., currency symbols inside dates).
- **Design tradeoffs:**
  - Rule-based vs. neural: Zero dependencies and deterministic output vs. inability to learn from noisy data or handle social-media NSWs.
  - Coverage vs. ambiguity: Broad NSW class coverage vs. unresolved context-dependent ambiguities (e.g., "2/9").
  - Performance vs. flexibility: Pre-compiled regex ensures speed but dictionary reload requires re-compiling a large alternation pattern.
- **Failure signatures:**
  - Unnormalized NSWs in output: Missing pattern or priority conflict (e.g., fraction consumed by date pattern).
  - Incorrect tones/diacritics in number/date output: Bug in number recursion or irregular form mappings.
  - Slow initialization: Extremely large custom dictionary (>50k entries) causing regex compilation lag.
- **First 3 experiments:**
  1. **Number coverage test:** Input numbers like 0, 10, 21, 105, 1.000.000, 1.5, -3.14. Verify outputs ("không", "mười", "hai mươi mốt", "một trăm linh năm", "một triệu", "một phẩy năm", "âm ba phẩy mười bốn").
  2. **Date/time priority test:** Check "Họp ngày 2/9" → "ngày hai tháng chín" (date) vs. "Tỷ lệ 2/9" → "hai phẩy chín" (fraction). Priority (dates before fractions) may mis-normalize the fraction case.
  3. **Dictionary extension test:** Add "FPT" → "Phát triển Công nghệ" to `acronyms.csv`. Reload via `reload_dictionaries()`. Confirm `normalize("Tôi làm ở FPT")` outputs "Tôi làm ở Phát triển Công nghệ". Test conflicts: if "FPT" and "PT" both exist, regex alternation order (dict insertion order) determines which matches first.

## Open Questions the Paper Calls Out
- **How to resolve context-dependent ambiguities in Vietnamese TN without neural models?** Future work plans context-window heuristics and POS tagger integration (Sec 7).
- **How to accurately identify and normalize proper nouns (names, organizations, locations)?** Not orthographically identifiable; suggests integrating an NER module (Sec 7).
- **How to normalize unseen code-switched terms (Vietnamese-English mixtures) without exhaustive dictionaries?** Plans token-level language identification (Sec 7).
- **How to implement inverse text normalization (ITN) for Vietnamese?** Future release planned (Sec 7).

## Limitations
- No quantitative accuracy metrics (precision/recall) for any NSW class; real-world error rates unknown.
- Built-in dictionary size and contents (acronyms/loanwords) are not disclosed; out-of-the-box coverage cannot be audited without repository access.
- Ambiguous NSWs (e.g., "2/9") are resolved by fixed priority; frequency and impact of misnormalizations are unmeasured.
- Performance claims (e.g., "tens of thousands of utterances per minute") lack published benchmarks or scalability tests with large custom dictionaries.

## Confidence
- **Rule-based pipeline for structured NSWs:** Medium. Design is sound for predictable patterns, but lacks test-set validation.
- **Pre-compiled regex for high throughput:** Medium. Theoretical advantage clear, but no empirical throughput data or backtracking risk analysis.
- **CSV dictionary extensibility:** High. Mechanism is straightforward and demonstrably functional; low failure risk.
