# A Rule-based Computational Model for Gaidhlig Morphology

## Quick Facts
- **arXiv ID:** 2602.12132
- **Source URL:** https://arxiv.org/abs/2602.12132
- **Reference count:** 1
- **Primary result:** Derived inflected forms increase recognition coverage of real-text lexemes from 20% (lemmas only) to over 44%.

## Executive Summary
This paper tackles the lack of data for building NLP tools for low-resource languages like Scottish Gaelic, where neural models are impractical. It introduces a rule-based computational model that extracts structured lexical data from Wiktionary into a Standardised Vocabulary Format (SVF). The SVF enables two key utilities: (1) SQL-based relational storage to quantify morphological patterns (e.g., 49% of nouns pluralise with -an), and (2) a Python rule-engine that derives all inflected forms from principal parts. Testing against a frequency list shows that including derived forms boosts text recognition coverage from 20% to over 44%. The approach leverages limited crowd-sourced data to produce interpretable morphology utilities for education and analysis.

## Method Summary
The pipeline begins with the English Wiktionary XML dump. A custom parser extracts only Gàidhlig entries and their principal parts (e.g., noun singular/plural/genitive) into a standardized text file (SVF). After cleaning near-duplicates (e.g., accent variants), the SVF loads into a relational database (`Facal` table). SQL queries analyze pattern frequencies. A Python rule engine reads the SVF and applies a grammar rule-base to generate all inflected forms, stored in an `AllForms` table. Recognition coverage is evaluated by matching these forms against an external frequency list derived from online Gaelic learning materials.

## Key Results
- Structured extraction of ~6,500 lemmas with principal parts from Wiktionary into SVF.
- Quantification via SQL reveals that 49% of nouns pluralise with the suffix `-an`.
- Recognition coverage of real-text lexemes increases from 20% (lemmas only) to over 44% when derived inflected forms are included.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Converting semi-structured Wiktionary entries into SVF creates a structured dataset of principal parts for reliable downstream processing.
**Mechanism:** A custom parser filters the Wiktionary dump for Gàidhlig entries, extracts principal parts (e.g., NS, NP, GS for nouns), and outputs them in a fixed-format text file, discarding explanatory text and non-content words.
**Core assumption:** The principal parts listed in Wiktionary are sufficient to generate all other inflected forms via consistent grammatical rules.
**Break condition:** Missing or inconsistent principal parts (marked "?") prevent rule generation for those lexemes.

### Mechanism 2
**Claim:** Storing SVF data in a relational database allows efficient SQL queries to quantify morphological pattern frequencies.
**Mechanism:** The SVF loads into a single `Facal` table; SQL queries (e.g., `LIKE '%an'`) count pattern occurrences, yielding statistics like the -an plural percentage.
**Core assumption:** The Wiktionary lexicon sample is representative of the language's morphological distributions.
**Break condition:** Wiktionary bias toward literary/archaic forms could make quantified patterns unreflective of contemporary usage.

### Mechanism 3
**Claim:** A declarative rule engine derives all inflected forms from principal parts, significantly increasing recognizable text forms.
**Mechanism:** Python classes (`Facal`, `Faclair`) load SVF data; a separate rule file maps grammatical forms to principal parts or transformations (lenition, etc.); the `inflect()` method applies rules based on POS and gender.
**Core assumption:** The rule-base comprehensively captures productive morphological processes except for a small irregular set.
**Break condition:** Incomplete rule coverage or missing principal parts limit derivation completeness.

## Architecture Onboarding
- **Component map:** Wikimedia dump -> Gàidhlig JSON extractor -> SVF generator -> Data cleaner -> SQL database loader -> Rule engine (Facal/Faclair + grammar rules) -> Analysis tools (SQL/Python).
- **Critical path:** Download dump → Extract Gàidhlig entries → Generate SVF → Clean data → Load SQL → Author rules → Generate forms → Evaluate coverage.
- **Design tradeoffs:** Single `Facal` table vs. separate POS tables; prioritizing common patterns vs. irregular exceptions; including theoretical vs. only attested forms in `AllForms`.
- **Failure signatures:** High "?" rate in SVF (>30% nouns missing parts); low coverage increase (<25% gain); SQL anomalies (e.g., 0% for -an plurals).
- **First 3 experiments:** 1) SVF round-trip test for a known entry like "bàta". 2) Pattern quantification sanity check: expect ~49% -an plurals. 3) Rule application test: decline "saoghal" and verify correct lenition in forms like "shaoghail".

## Open Questions the Paper Calls Out
### Open Question 1
What is the precise nature and extent of missing principal parts in the Wiktionary-derived dataset, and can a systematic methodology reliably fill these gaps? The paper notes ~30% of nouns have missing parts but doesn't distinguish causes (non-existent forms, regularly derived omissions, compounds). A manual audit of missing cases and controlled gap-filling via corpus search is needed.
### Open Question 2
What is the actual accuracy and coverage of the rule-base on diverse, contemporary Gaidhlig text beyond the controlled frequency list? The 44% coverage gain is against a learner-oriented list; performance on raw, dialectally varied text is unknown. A rigorous evaluation on a separate authentic corpus is required.
### Open Question 3
Can a hybrid approach, using rule-generated synthetic paradigms to augment sparse data, improve neural NLP models for Gaidhlig? The authors speculate but haven't tested efficacy. An experiment mixing synthetic data with real corpus for training a neural tagger would resolve this.

## Limitations
- Parser for Wiktionary templates is undocumented; handling of variants leads to missing principal parts and extraction errors.
- Wiktionary sample may be biased toward literary/archaic forms, so quantified patterns (e.g., 49% -an plurals) might not reflect contemporary usage.
- Rule-base is incomplete and phonological transformations may not cover all environments, risking incorrect/incomplete inflections.

## Confidence
- SVF extraction completeness: Medium (works for most entries but gaps and reproducibility issues remain).
- SQL pattern quantification: Medium (queries sound but depend on Wiktionary representativeness; no external validation).
- Recognition coverage improvement: Low-to-Medium (44% gain plausible but could be inflated by non-attested forms and noisy frequency list).
