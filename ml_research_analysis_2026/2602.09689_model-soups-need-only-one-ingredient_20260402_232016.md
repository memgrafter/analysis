# Model soups need only one ingredient

## Quick Facts
- **arXiv ID**: 2602.09689
- **Source URL**: https://arxiv.org/abs/2602.09689
- **Reference count**: 40
- **Primary result**: MonoSoup recovers out-of-distribution robustness from a single fine-tuned checkpoint via spectral decomposition, matching or exceeding multi-checkpoint model soups while preserving in-distribution accuracy.

## Executive Summary
Fine-tuning large pre-trained models improves in-distribution (ID) performance but often degrades out-of-distribution (OOD) robustness. Model Soups—averaging weights from multiple fine-tuned checkpoints—mitigates this but is computationally expensive. MonoSoup introduces a single‑checkpoint, data‑free, hyperparameter‑free alternative: it decomposes each layer’s fine‑tuning update using singular value decomposition (SVD) into high‑energy (task‑specific) and low‑energy (potentially robust) components, then automatically reweights them per layer using layer‑wise spectral statistics. On CLIP models fine‑tuned on ImageNet, MonoSoup improves average OOD accuracy by ~1% and recovers up to 8% on weak checkpoints while maintaining ID performance. On Qwen3 language models, it gains up to 9.2 points on mathematical reasoning benchmarks. The method thus delivers robust gains from one checkpoint without extra training or storage overhead.

## Method Summary
MonoSoup operates on a pre‑trained model \(\theta_0\) and a single fine‑tuned checkpoint \(\theta_{\text{FT}}\). For each layer \(\ell\), it computes the weight update matrix \(W^{(\ell)} = W^{(\ell)}_{\text{FT}} - W^{(\ell)}_{0}\). Applying SVD yields \(W^{(\ell)} = U^{(\ell)} \Sigma^{(\ell)} V^{(\ell)\top}\). An entropy‑based effective rank \(k^{(\ell)}\) (derived from the normalized singular value distribution) splits the spectrum: top \(k^{(\ell)}\) singular vectors form the high‑energy component \(W^{(\ell)}_{\text{High}}\); the remainder forms the low‑energy component \(W^{(\ell)}_{\text{Low}}\). Two signals—spectral decay \(\rho^{(\ell)} = (\sigma_{k^{(\ell)}+1}/\sigma_1)^2\) and alignment \(\cos\alpha^{(\ell)} = \|W^{(\ell)}_{\text{Low}}\|_F / \|W^{(\ell)}\|_F\)—are combined into a learned weight \(\lambda^{(\ell)}_{\text{Low}} = \rho^{(\ell)} + (1-\rho^{(\ell)})\cos\alpha^{(\ell)}\) (and \(\lambda^{(\ell)}_{\text{High}} = 1 - \lambda^{(\ell)}_{\text{Low}}\)). The edited update is \(W^{(\ell)}_{\text{MonoSoup}} = \lambda^{(\ell)}_{\text{High}} W^{(\ell)}_{\text{High}} + \lambda^{(\ell)}_{\text{Low}} W^{(\ell)}_{\text{Low}}\). Final weights are \(\tilde{\theta} = \theta_0 + \sum_\ell W^{(\ell)}_{\text{MonoSoup}}\). The process is data‑free, requires no hyperparameter tuning, and adds negligible computation (one SVD per layer).

## Key Results
- On CLIP ViT‑B/32 fine‑tuned on ImageNet, MonoSoup raises average OOD accuracy (across ImageNet‑V2, ‑R, ‑Sketch, ‑A, ObjectNet) by ~1% over the fine‑tuned baseline and matches multi‑checkpoint Model Soups.
- It recovers up to 8% OOD performance on the weakest individual checkpoint while preserving in‑distribution accuracy.
- For Qwen3‑0.6B fine‑tuned on mathematical reasoning data, MonoSoup yields gains of up to 9.2 points on benchmarks like GSM8K, GSMPlus, and MMLU‑Pro‑Math.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Fine‑tuning updates can be decomposed into subspaces with distinct roles; high‑energy directions capture task‑specific adaptation (specialization), while low‑energy directions preserve pre‑trained features useful for OOD robustness.
- **Mechanism**: For each layer’s weight update matrix \(W^{(\ell)} = W^{(\ell)}_{\text{FT}} - W^{(\ell)}_0\), apply SVD: \(W^{(\ell)} = U^{(\ell)} \Sigma^{(\ell)} V^{(\ell)\top}\). Partition spectral mass at index \(k\) computed via entropy‑based effective rank. The high‑energy component \(W^{(\ell)}_{\text{High}}\) (top \(k\) singular vectors) dominates the update, driving ID accuracy. The low‑energy orthogonal complement \(W^{(\ell)}_{\text{Low}}\) retains subtler, distributed signal that, if preserved, mitigates OOD degradation.
- **Core assumption**: Low‑energy components contain residual pretrained information critical for robustness, not just noise—validated by showing that truncating them (even at high retention like 95%) harms OOD in large‑scale fine‑tuning (ImageNet shifts).
- **Evidence anchors**: 
  - [abstract] "decomposes it into high‑energy (task‑specific) and low‑energy (potentially robust) components"
  - [section 4] "low‑energy WLow contains residual updates that, despite potentially capturing noise, may preserve information critical for OOD robustness" and Figure 3b showing truncation hurts OOD.
  - [corpus] Weak; neighbors discuss model soups generally, not this spectral decomposition.
- **Break condition**: If low‑energy components are purely noise (e.g., in small‑scale task arithmetic benchmarks, as noted), discarding them helps. But for large‑scale fine‑tuning with natural OOD shifts, the break condition is not met; low‑energy components carry essential robustness signals.

### Mechanism 2
- **Claim**: The optimal re‑weighting of high/low subspaces can be determined automatically per layer using two complementary signals—spectral decay (\(\rho\)) and alignment (\(\cos\alpha\))—without hyperparameters.
- **Mechanism**: Compute spectral decay ratio \(\rho^{(\ell)} = (\sigma_{k+1}/\sigma_1)^2\) (steep vs. flat spectrum) and alignment \(\cos\alpha^{(\ell)} = \|W^{(\ell)}_{\text{Low}}\|_F / \|W^{(\ell)}\|_F^2\) (fraction of update energy in low‑energy part). Combine via \(\lambda^{(\ell)}_{\text{Low}} = \rho^{(\ell)} + (1-\rho^{(\ell)})\cos\alpha^{(\ell)}\), satisfying boundary conditions: suppress low‑energy when spectrum sharp and misaligned; retain when spectrum flat or highly aligned.
- **Core assumption**: The product \(\rho \cdot \cos\alpha\) captures the signal‑to‑noise ratio of low‑energy directions; high \(\rho\) or high \(\cos\alpha\) indicates low‑energy content is meaningful and should be preserved.
- **Evidence anchors**: 
  - [section 4] Defines \(\rho\) and \(\cos\alpha\), derives bilinear weighting from boundary conditions, and states "this formulation ensures that re‑emphasizing WLow occurs only when the update is distributed across weak directions or carries significant fractional energy."
  - [section 5.4] Ablation in Figure 5 shows combining both signals yields strongest OOD without sacrificing ID.
- **Break condition**: If spectral decay and alignment are completely uncorrelated with robustness (e.g., in architectures where fine‑tuning updates are isotropic), the weighting rule would not improve over uniform mixing. But empirical results show consistent gains.

### Mechanism 3
- **Claim**: Layer‑wise anisotropic re‑weighting (vs. uniform scalar interpolation) is necessary because different layers exhibit heterogeneous spectral properties; a single global coefficient cannot capture the varying trade‑off between specialization and robustness across the network.
- **Mechanism**: Apply the learned \(\lambda^{(\ell)}_{\text{High}}, \lambda^{(\ell)}_{\text{Low}}\) per layer \(\ell\) to edit the update: \(W^{(\ell)}_{\text{MonoSoup}} = \lambda^{(\ell)}_{\text{High}} W^{(\ell)}_{\text{High}} + \lambda^{(\ell)}_{\text{Low}} W^{(\ell)}_{\text{Low}}\). This produces a final edited checkpoint \(W^{(\ell)}_{0} + W^{(\ell)}_{\text{MonoSoup}}\).
- **Core assumption**: The optimal ID‑OOD balance is layer‑dependent; earlier layers may need less adjustment while deeper layers (more task‑specific) require more careful modulation. This is supported by CKA analysis showing deeper layers drift more from pretrained features on OOD.
- **Evidence anchors**: 
  - [section 4] "enables MonoSoup to dynamically accommodate the heterogeneous spectral properties across various layers"
  - [appendix J] Figure 13 shows distribution of \(\lambda\) values across ConvNeXt layers, with significant separation and fluctuation, especially in deeper stages, confirming anisotropy.
  - [section 5.4] "Unlike scalar interpolation methods such as Wise‑FT, which enforce a uniform scaling factor ... MonoSoup applies anisotropic scaling."
- **Break condition**: If all layers have identical spectral/alignment profiles, a global coefficient would suffice. But empirical coefficient distributions (Figure 13) show clear layer‑wise variation, violating this condition.

## Foundational Learning
- **Concept: Singular Value Decomposition (SVD) of weight matrices**  
  **Why needed**: Core to partitioning each layer’s fine‑tuning update into orthogonal subspaces of varying energy.  
  **Quick check**: Given a weight update matrix \(W\), what do the singular values \(\sigma_i\) represent, and how does the Frobenius norm relate to them?

- **Concept: Effective rank (entropy‑based)**  
  **Why needed**: Provides a data‑free, automatic way to determine the split index \(k\) between high‑ and low‑energy subspaces without a manual threshold \(R\).  
  **Quick check**: How does the entropy‑based effective rank \(\exp(-\sum p_i \ln p_i)\) differ from a simple count of nonzero singular values?

- **Concept: Cosine similarity between task vectors**  
  **Why needed**: Measures alignment of fine‑tuning updates; high alignment predicts successful merging (Section 3). Also used in \(\cos\alpha\) to quantify fractional energy in low subspace.  
  **Quick check**: Why would high cosine similarity between two models’ task vectors correlate with better merged OOD performance?

## Architecture Onboarding

### Component Map
Pre‑trained weights \(W_0\) and fine‑tuned weights \(W_{\text{FT}}\) → compute update \(W = W_{\text{FT}} - W_0\) → apply SVD to \(W\) → compute effective rank \(k\) from singular value distribution → split into \(W_{\text{High}}\) (top \(k\)) and \(W_{\text{Low}}\) (remaining) → compute spectral decay \(\rho = (\sigma_{k+1}/\sigma_1)^2\) and alignment \(\cos\alpha = \|W_{\text{Low}}\|_F / \|W\|_F\) → derive \(\lambda_{\text{Low}} = \rho + (1-\rho)\cos\alpha\) and \(\lambda_{\text{High}} = 1 - \lambda_{\text{Low}}\) → merge update \(W_{\text{MonoSoup}} = \lambda_{\text{High}} W_{\text{High}} + \lambda_{\text{Low}} W_{\text{Low}}\) → final weights \(\tilde{W} = W_0 + W_{\text{MonoSoup}}\).

### Critical Path
1. Load single fine‑tuned model and its pretrained initialization.
2. For each layer: compute update matrix, run SVD, compute effective rank \(k\), split subspaces, compute \(\rho\) and \(\cos\alpha\), derive \(\lambda\) values, combine subspaces.
3. Replace layer weights with edited version; save new checkpoint.

### Design Tradeoffs
- **Variance threshold \(R\) vs. automated effective rank**: Fixed \(R\) introduces a hyperparameter but may be more stable; automated rank is hyperparameter‑free but could be sensitive to numerical noise.
- **Anisotropic vs. scalar mixing**: Layer‑wise coefficients enable finer control but increase complexity; scalar mixing (e.g., Wise‑FT) is simpler but less expressive.
- **Storage/computation**: Requires one extra forward pass to compute SVDs (negligible vs. training multiple models) and storage of one edited checkpoint.

### Failure Signatures
- All \(\lambda^{(\ell)}_{\text{Low}}\) near 0 → collapse to high‑energy only, losing OOD gains.
- All \(\lambda^{(\ell)}_{\text{Low}}\) near 1 → collapse to low‑energy only, losing ID accuracy.
- Layer coefficients nearly uniform → indicates spectral profiles too homogeneous or implementation error.
- Edited model performs worse than fine‑tuned on both ID and OOD → suggests low‑energy components were predominantly harmful noise.

### First 3 Experiments
1. **SVD spectrum inspection**: On a single layer of a fine‑tuned CLIP model, plot singular values of the update. Verify long tail and that effective rank \(k\) is dramatically smaller than matrix rank.
2. **Weak checkpoint recovery**: Apply MonoSoup to the worst‑OOD checkpoint from the CLIP suite (e.g., M‑14). Expect >7% OOD recovery with minimal ID drop.
3. **Anisotropy check**: After running MonoSoup, print \(\lambda^{(\ell)}_{\text{High}}\) and \(\lambda^{(\ell)}_{\text{Low}}\) across layers. Confirm they are not identical (mean gap >0.3) and vary with depth.

## Open Questions the Paper Calls Out
1. **How can the variance threshold \(R\) be made fully adaptive and architecture‑agnostic?** The paper acknowledges that \(R\) is currently a fixed scalar (default ~0.8) and may require adaptation across architectures, which undermines the hyperparameter‑free claim.
2. **What is the precise theoretical mechanism linking spectral reweighting to improved OOD robustness?** While empirical evidence shows preservation of pre‑trained features, the causal chain—whether it preserves invariant features, suppresses spurious correlations, or both—remains unclear.
3. **Why do MonoSoup's layer‑wise coefficients vary anisotropically across architecture depth and type?** The observed heterogeneity suggests fine‑tuning impacts different architectural components dissimilarly, but the paper does not analyze the reasons behind this variation.
4. **Does MonoSoup's effectiveness generalize to modalities and tasks beyond vision classification and mathematical reasoning?** The hypothesis may not hold universally; spectral properties in other domains (e.g., audio, video, generation) could differ.
5. **What is the fundamental reason MonoSoup complements Wise‑FT, and can their combination be theoretically characterized as a multi‑stage optimization over a low‑loss manifold?** The geometric relationship between the pre‑trained, fine‑tuned, MonoSoup‑edited, and Wise‑FT‑interpolated points is not modeled.

## Limitations
- **Bias parameters**: The method does not specify whether biases should be included in the SVD decomposition; separate handling may be required.
- **Convolutional kernel reshaping**: The flattening order for 4D kernels (e.g., output‑channel vs. input‑channel) is not defined, potentially altering spectral properties.
- **Core assumption validity**: Low‑energy update components might be pure noise in small‑scale or isotropic fine‑tuning scenarios, breaking the robustness benefit.

## Next Checks
1. **Bias inclusion/exclusion test**: Run MonoSoup with and without including bias parameters in the update decomposition; compare ID and OOD accuracy to determine if biases need special handling.
2. **Convolutional flattening order ablation**: For ConvNeXt, compare two flattening strategies—(out × in·kernel) vs. (in × out·kernel)—and measure changes in effective rank distribution and OOD performance.
3. **Small‑task break condition verification**: Fine‑tune a ViT on a small dataset (e.g., Stanford Dogs) and apply MonoSoup; check whether low‑energy truncation degrades OOD robustness, as predicted by the break‑condition hypothesis.
