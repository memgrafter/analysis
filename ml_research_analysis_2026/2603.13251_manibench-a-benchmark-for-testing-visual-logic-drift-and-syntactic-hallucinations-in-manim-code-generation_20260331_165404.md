# ManiBench: A Benchmark for Testing Visual-Logic Drift and Syntactic Hallucinations in Manim Code Generation

## Quick Facts
- **arXiv ID:** 2603.13251
- **Source URL:** https://arxiv.org/abs/2603.13251
- **Reference count:** 16
- **Primary result:** Introduces a four-metric framework for LLM-generated Manim code, revealing that top models achieve only 66.7% executability and that heuristic alignment scores saturate near 1.0 due to keyword overfitting, while pedagogical element coverage remains universally low (~0.17).

## Executive Summary
ManiBench is a benchmark designed to evaluate large language models on generating Manim animation code, specifically targeting two failure modes: visual-logic drift (misalignment between code and intended mathematical narrative) and syntactic hallucinations (use of non-existent or deprecated APIs). It provides a framework with four automated metrics—Executability, Version-Conflict Error Rate, Alignment Score, and Coverage Score—applied to a pilot dataset of 12 problems derived from 3Blue1Brown's source code. Results show that state-of-the-art models still struggle, with moderate executability, pervasive omission of pedagogical elements, and heuristic alignment metrics that fail to detect incorrect keyword usage.

## Method Summary
The evaluation pipeline is fully automated. It starts with a problem database containing prompts, required visual events, and conflict notes. LLMs generate code via various prompting strategies. Outputs are executed in a sandboxed Manim CE environment (60s timeout) to measure executability and capture errors. A static analyzer uses regex and AST parsing against a catalog of 145 Manim GL→CE conflicts to compute Version-Conflict Error Rate. Alignment and Coverage scores are approximated heuristically via keyword and pattern matching on the source code, serving as conservative lower-bound estimates of visual-logic fidelity and pedagogical element inclusion, respectively.

## Key Results
- Top models (Claude-Sonnet-4, Kimi-K2.5) achieve 66.7% code executability.
- Average Coverage Score is 0.17, indicating consistent omission of pedagogical elements like annotations and structural clarity.
- Few-shot prompting improves executability by 11.1 percentage points; version-aware prompting eliminates API conflict errors.
- Heuristic Alignment saturates near 1.0 for most models (e.g., Llama-3.1-8B at 1.0), revealing keyword overfitting without visual verification.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The Alignment Score approximates visual-logic fidelity by checking for the presence and temporal ordering of required visual events via code token analysis.
- **Mechanism:** A weighted sum over required visual events (presence * timing accuracy) is computed using keyword and pattern matching on generated source code, serving as a conservative lower-bound estimate of whether the animation will match the intended mathematical narrative.
- **Core assumption:** The presence and sequencing of specific Manim method calls (e.g., `animate.move_to`, `Create`, `Wait`) in the source code correlates with correct visual output and temporal flow.
- **Evidence anchors:**
  - [abstract] "Alignment Score... weighted fraction of required visual events that are both present and temporally accurate."
  - [section 5.3] Formal definition with weights `wi`, presence `pi`, and timing `ti`.
  - [corpus] Corpus identifies related "visual-logic" frameworks (e.g., ride-hailing adjudication) but lacks direct evidence for animation-specific logic; evidence strength is **weak**.
- **Break condition:** If generated code contains required keywords but implements them incorrectly (e.g., wrong object, inverted sequence), the heuristic will produce a false positive, inflating the score.

### Mechanism 2
- **Claim:** The Version-Conflict Error Rate (VCER) identifies syntactic hallucinations related to Manim API version drift by statically scanning for deprecated or mismatched constructs.
- **Mechanism:** Regex and AST-based pattern matching against a catalog of 145 documented Manim GL → CE incompatibilities flags mixed-API usage, renamed methods, and signature mismatches.
- **Core assumption:** Version-conflict errors are a discrete, detectable class of syntactic hallucinations that can be identified without executing the code.
- **Evidence anchors:**
  - [abstract] "targeting... Syntactic Hallucinations (valid Python referencing non-existent or deprecated Manim APIs)."
  - [section 7.1] "eight recurring categories" of incompatibilities (e.g., `CONFIG` dict → `__init__`, `ShowCreation` → `Create`).
  - [corpus] Papers like "CodeHalu" and "CoHalLo" study code hallucinations via execution/probing, providing indirect support for static detection approaches.
- **Break condition:** If a hallucination involves a valid but semantically incorrect API call that is not on the predefined conflict list, it will not be counted, underestimating VCER.

### Mechanism 3
- **Claim:** The automated evaluation framework enables reproducible, large-scale benchmarking but its heuristic Alignment and Coverage scores are conservative lower-bound estimates that saturate due to keyword overfitting.
- **Mechanism:** The pipeline executes code in a sandbox for executability/VCER, while Alignment/Coverage rely on keyword-bank heuristics that detect concept presence but cannot verify rendered correctness.
- **Core assumption:** Automated, human-free evaluation is necessary for scalability, and keyword detection is a sufficient proxy for pedagogical element inclusion.
- **Evidence anchors:**
  - [section 8.1] "Alignment and Coverage are approximated heuristically via keyword and pattern matching... serve as conservative lower-bound estimates."
  - [section 9.6] "Heuristic alignment saturates. Most models achieve alignment>0.90 because keyword detection cannot distinguish correct implementation from keyword presence."
  - [corpus] Corpus lacks direct parallels for animation-specific automated evaluation; evidence strength is **weak to moderate**.
- **Break condition:** When models learn to cram required keywords without implementing the corresponding visual logic, Alignment/Coverage scores become meaningless (as observed with Llama-3.1-8B's perfect 1.0 alignment despite 8.3% executability).

## Foundational Learning
- **Concept:** Manim's temporal and scene-based execution model.
  - **Why needed here:** Code must not only be syntactically correct but also sequence animations (`self.play`, `Wait`) and manage Scene lifecycles (`construct` method) to create coherent visuals.
  - **Quick check:** In a Manim `Scene`, what is the purpose of the `self.wait()` method, and what visual-logic error occurs if it is omitted between two transformation animations?
- **Concept:** Manim CE vs. Manim GL API divergence.
  - **Why needed here:** Models must generate code compatible with the actively maintained Manim CE; using GL-specific patterns (e.g., `manim_imports_ext`, `CONFIG` dict) causes runtime failures or silent semantic errors.
  - **Quick check:** How would you rewrite a Manim GL scene that uses `self.frame.reorient()` to be compatible with Manim CE?
- **Concept:** Pedagogical animation elements (annotation, mapping, evidence, structure).
  - **Why needed here:** The Coverage Score measures whether generated code includes elements that aid learning (e.g., `MathTex`, `set_color`, `DecimalNumber`, `VGroup`). Omission leads to low coverage even if the animation is technically correct.
  - **Quick check:** List two specific Manim classes or methods that would fulfill the "Mathematical Annotation" and "Structural Clarity" sub-dimensions of the Coverage Score.

## Architecture Onboarding
- **Component map:**
  Problem DB -> LLM Generation Module -> Sandbox Executor -> Static Analyzer -> Heuristic Scorer -> Result Aggregator
- **Critical path:** Problem Prompt → LLM Generation → Sandbox Execution → (if success) Static Analysis & Heuristic Scoring → Metric Computation.
- **Design tradeoffs:**
  - Automation vs. Accuracy: Full automation enables large-scale runs but forces reliance on flawed heuristics for alignment/coverage; human evaluation is planned but not implemented.
  - Heuristic Coverage vs. False Positives: Broad keyword lists increase detection recall but cause saturation (e.g., `1.0` alignment from mere keyword presence).
  - Version-Awareness Scope: Cataloging 145 conflicts covers common cases but misses nuanced semantic mismatches not tied to a specific API signature.
- **Failure signatures:**
  - High Alignment + Low Executability: Indicates keyword stuffing without working code (e.g., Llama-3.1-8B: Al=1.0, Ex=8.3%).
  - Zero Executability + Perfect VCER: Model avoids known conflicts but fails on basic syntax/scene structure (e.g., Qwen-2.5-Coder: Ex=0%, VC=0%).
  - Low Coverage (~0.17) universally: Suggests models omit pedagogical elements regardless of executability.
- **First 3 experiments:**
  1. Baseline reproducibility: Run all zero-shot models on the 12-problem pilot set; verify that executability and VCER match reported values for Claude-Sonnet-4 (Ex≈66.7%, VC≈0%) and Kimi-K2.5.
  2. Prompting strategy isolation: On Gemma-3-27B, run each of the 5 strategies (3 trials) to confirm few-shot improves executability (+11.1pp) and version-aware eliminates VCER.
  3. Heuristic stress test: Manually inspect 10 high-alignment (≥0.9) but low-executability outputs to quantify keyword overfitting rate; expect majority to be syntactically invalid or missing core scene classes.

## Open Questions the Paper Calls Out
- **Question 1:** Why do state-of-the-art LLMs consistently produce Manim code with uniformly low coverage of pedagogical elements (average 0.17), even when executability is moderate?
  - **Basis:** Coverage Score averaged 0.17 across all models, and prompting strategies did not improve it beyond 0.20.
  - **Why unresolved:** The root cause is unknown—it could stem from training data lacking rich animation examples, benchmark design not incentivizing pedagogical depth, or models failing to internalize multi-dimensional teaching cues.
  - **Resolving evidence:** Ablation studies varying prompt specificity, analysis of model attention to coverage-related tokens, or fine-tuning on annotated 3B1B scenes.
- **Question 2:** Can vision-based evaluation (e.g., VLM grading or frame-level comparison) effectively resolve the heuristic alignment saturation problem where keyword matching yields near-perfect scores despite visual-logic drift?
  - **Basis:** Heuristic Alignment saturates near 1.0 for most models, but authors state it "cannot distinguish correct implementation from keyword presence" and call for "vision-based evaluation."
  - **Why unresolved:** No VLM-based or human evaluation was conducted; the current metric is a proxy that may not correlate with actual visual fidelity.
  - **Resolving evidence:** Implement a two-stage evaluation: render all outputs, score with a VLM fine-tuned on animation correctness, then compare against keyword heuristics and human judgments.
- **Question 3:** Do version-aware prompting strategies (e.g., enumerating forbidden ManimGL constructs) generalize to improve API correctness and executability for a diverse set of frontier models beyond Gemma-3-27B?
  - **Basis:** Version-aware prompting eliminated VCER for Gemma-3-27B and few-shot improved executability, but only Gemma was tested across all strategies; other models were zero-shot only.
  - **Why unresolved:** It is unclear if these gains are model-specific or broadly applicable; Claude-Sonnet-4 and Kimi-K2.5 already show low VCER zero-shot, but their response to version-aware prompts is unknown.
  - **Resolving evidence:** Re-run the full prompting strategy suite on at least two other high-executability models (Claude-Sonnet-4, Kimi-K2.5) and measure changes in VCER and executability.
- **Question 4:** Is the identified visual-logic drift (e.g., missing events, temporal misalignments) actually pedagogically harmful, or do high keyword-based alignment scores suffice for effective learning?
  - **Basis:** The paper defines visual-logic drift but notes "pedagogical failure" is unvalidated; alignment is heuristic, and "user studies could address this gap."
  - **Why unresolved:** ManiBench measures code properties, not learning outcomes; an animation could pass keyword checks yet mislead learners through subtle timing errors.
  - **Resolving evidence:** Conduct a controlled user study with novices learning concepts from animations generated by high-alignment vs. drift-prone models, measuring comprehension gains and misconception rates.

## Limitations
- Exact **Manim CE version** used is unspecified, risking execution/VCER variability.
- **Alignment/Coverage keyword lists and regex patterns** are unreleased; heuristic saturation (e.g., Llama-3.1-8B Al=1.0) suggests overfitting cannot be recomputed without source.
- **Problem-specific success thresholds** (e.g., what constitutes "temporal accuracy" for a `Wait` call) are not fully documented.

## Confidence
- **High:** Executability and VCER metrics (reproducible via sandbox + static analysis).
- **Medium:** Heuristic Alignment/Coverage as conservative lower-bounds (mechanism clear but uncalibrated).
- **Low:** Claims about "visual-logic fidelity" beyond keyword presence (no human validation).
