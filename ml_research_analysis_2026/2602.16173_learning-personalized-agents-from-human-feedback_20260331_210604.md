# Learning Personalized Agents from Human Feedback

## Quick Facts
- **arXiv ID:** 2602.16173
- **Source URL:** https://arxiv.org/abs/2602.16173
- **Reference count:** 40
- **Primary result:** PAHF, a framework with explicit per-user memory and dual feedback channels (pre-action clarification and post-action integration), significantly reduces initial personalization error and enables rapid adaptation to preference drift, outperforming no-memory and single-channel baselines on embodied manipulation and online shopping benchmarks.

## Executive Summary
The paper introduces PAHF (Personalization from Human Feedback), a framework for continual personalization of AI agents that addresses failure to align with individual, evolving user preferences—especially for new users and under preference drift. PAHF maintains an explicit per-user memory and operates a three-step loop: pre-action clarification to resolve ambiguity, action execution based on retrieved preferences, and post-action feedback integration to update memory. Evaluated on embodied manipulation and online shopping benchmarks using LLM-based simulators, PAHF consistently achieves higher success rates and lower personalization error compared to baselines lacking memory or one feedback channel. The results empirically prove that combining dual feedback with explicit memory is critical for robust personalization in dynamic environments.

## Method Summary
PAHF tackles personalization via an explicit memory backend (SQLite/FAISS) storing per-user preference notes. For each task, the agent: (1) retrieves relevant memories; if ambiguous, it asks a single pre-action clarifying question; (2) executes an action conditioned on retrieved memories and any clarification; (3) receives post-action feedback, where a salience detector filters relevant portions, summarizes them, and updates memory (add/merge). The agent uses ReAct with an LLM (GPT-4o/4.1/Llama-4-Scout). Evaluation follows a four-phase protocol: Phase 1 (initial learning), Phase 2 (initial testing), Phase 3 (preference drift introduction), Phase 4 (post-drift testing). Metrics include Success Rate (SR) on test phases, Feedback Frequency (FF), and Average Cumulative Personalization Error (ACPE). Baselines: No Memory, Pre-action Only, Post-action Only.

## Key Results
- PAHF achieves the highest Phase 2 and Phase 4 success rates in both domains: embodied manipulation (70.5% and 68.8%) and online shopping (41.3% and 70.3%), significantly outperforming all single-channel and no-memory baselines.
- Dual feedback channels are essential: ablating either pre-action or post-action feedback causes substantial performance drops, especially during drift adaptation (Phase 3→4).
- PAHF reduces initial personalization error and adapts quickly to drift, as measured by lower ACPE during learning phases, demonstrating effective continual personalization.

## Why This Works (Mechanism)
PAHF succeeds because its two feedback channels address complementary failure modes: pre-action clarification resolves initial ambiguity that would otherwise cause early mistakes and corrupt memory, while post-action feedback corrects errors and adapts memory to preference drift. The explicit memory provides persistent, retrievable preference records across tasks. The salience detector ensures only relevant feedback updates memory, mitigating noise. The three-step loop creates a tight perception-action cycle that incrementally refines the user model, enabling robust personalization even when preferences evolve.

## Foundational Learning
- **Explicit per-user memory:** Stores interpretable preference notes for retrieval across tasks. *Why needed:* Enables recall of past interactions and long-term personalization. *Quick check:* Verify memory entries are added after feedback and retrieval returns relevant notes for new contexts.
- **Pre-action clarification:** Asks clarifying questions when retrieved context is ambiguous. *Why needed:* Prevents early erroneous actions that would introduce noise into memory. *Quick check:* Confirm the agent triggers a question when retrieval confidence is low or context is empty.
- **Post-action feedback integration:** Processes user feedback after action execution to update memory. *Why needed:* Corrects mistakes and adapts to preference drift. *Quick check:* Ensure feedback is parsed by the salience detector and memory is updated (added/merged) each task.
- **Salience detector:** Filters feedback to incorporate only salient information. *Why needed:* Avoids memory bloat and prevents irrelevant/contradictory updates. *Quick check:* Check that only feedback with high relevance scores triggers memory updates.
- **Drift adaptation:** Detects and responds to changing preferences over time. *Why needed:* User preferences are not static; the agent must adjust. *Quick check:* In Phase 3 (drift), verify memory updates occur and Phase 4 performance improves relative to Phase 2.
- **ReAct with LLM:** Provides reasoning and action generation using prompts that include memory and feedback. *Why needed:* Leverages LLM’s language understanding to interpret preferences and generate appropriate actions. *Quick check:* Inspect prompts to ensure retrieved memories and pre-action feedback are included and that `Action:` outputs are correctly parsed.

## Architecture Onboarding
- **Component map:** 
  User -> (Natural request) -> Agent (with Memory) -> (Pre-action question) -> User -> (Clarification) -> Agent -> (Action) -> Environment -> (Post-action feedback) -> Salience Detector -> Memory Update -> (updated Memory)
- **Critical path:** The three-step iterative loop for each task: (1) retrieve from memory; if ambiguous, ask clarification; (2) generate action using memory and clarification; (3) execute, collect feedback, detect salience, update memory.
- **Design tradeoffs:**
  - *Explicit memory:* Interpretable and editable but may not scale to very large histories; implicit neural memory could compactly store complex patterns but loses interpretability.
  - *Single-question limit:* Minimizes user burden but may leave residual ambiguity; multi-turn clarification could improve accuracy at cost of interaction overhead.
  - *Simple note merging:* Efficient but may not handle contradictory feedback; conflict resolution strategies could improve robustness.
- **Failure signatures:**
  - *No clarifying questions:* Check if retrieval returns empty/low-similarity results and if the clarification prompt is triggered.
  - *Memory bloat/irrelevant retrieval:* Monitor note count growth and retrieval relevance scores; adjust top-k and similarity threshold τ.
  - *Drift not detected:* In Phase 3, if success rates do not improve, verify the drift detector fires and post-action updates occur.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can more sophisticated memory architectures (e.g., hierarchical, structured, or neural) be integrated into PAHF to improve scalability and long-term context retention? *Basis:* Limitations state current memory is simple and future work could integrate advanced systems. *Why unresolved:* Impact on continual personalization remains unexplored. *Evidence needed:* Implement alternative memory backends, evaluate on long-horizon tasks, measure retrieval accuracy and memory growth.
- **Open Question 2:** How can PAHF robustly handle noisy, inconsistent, or erroneous human feedback without destabilizing the learned preference model? *Basis:* Limitations note feedback noise and basic filtering. *Why unresolved:* No conflict detection or noise modeling. *Evidence needed:* Noise-aware memory updates with confidence weighting; test on simulated feedback with varying noise levels.
- **Open Question 3:** What enhancements to the agent’s reasoning process (e.g., chain-of-thought, tool use, stronger LLMs) are necessary to close the performance gap on challenging benchmarks like online shopping? *Basis:* Limitations state shopping remains challenging with modest success rates. *Why unresolved:* Standard ReAct may lack fine-grained reasoning for conjunctive feature matching. *Evidence needed:* Incorporate advanced reasoning (tree search, program-aided) and larger models; isolate effect on shopping benchmark.
- **Open Question 4:** How does allowing multi-turn clarification interactions (beyond the current single-question limit) affect personalization accuracy, learning speed, and user burden? *Basis:* Limitations mention single-turn constraint and suggest multi-turn strategies. *Why unresolved:* Trade-off between user effort and improved personalization is unknown. *Evidence needed:* A/B tests with humans comparing single-turn vs. adaptive multi-turn, measuring success, clarification count, satisfaction.

## Limitations
- Exact dataset generation parameters (seeds, persona-rule mappings) and hyperparameters (retrieval top-k, similarity threshold τ, question limit) are undocumented, requiring reverse-engineering and causing potential reproduction variance.
- Evaluation relies on LLM-based simulators (embodied) and hybrid deterministic judges (shopping); real human feedback behavior may differ, limiting generalizability to real deployments.
- Short evaluation horizon (4 phases) and small user sets (40 embodied, 20 shopping) do not test long-term adaptation, scalability to hundreds of users, or multi-domain transfer.

## Confidence
- PAHF outperforms baselines on provided benchmarks: **High** (structured protocols, multiple metrics, consistent ablations).
- Dual feedback + explicit memory is necessary: **High** (significant ablation gaps across both domains).
- Framework generalizes to real users/other domains: **Medium-Low** (simulator-based, limited task diversity and user count).
