# MURE: Hierarchical Multi-Resolution Encoding via Vision-Language Models for Visual Document Retrieval
## Quick Facts
- **arXiv ID:** 2603.13349
- **Source URL:** https://arxiv.org/abs/2603.13349
- **Reference count:** 40
- **Primary result:** MURE (PaliGemma-3B) achieves state-of-the-art on ViDoRe V1/V2; with 512 tokens it surpasses ColPali by +0.8% (V1) and +0.6% (V2) while using 50% fewer tokens; the full model outperforms ColMate by +1.9% (V1) and +2.3% (V2) in NDCG@5.

## Executive Summary
Visual Document Retrieval (VDR) must balance fine-grained details with global layout. MURE introduces a hierarchical multi-resolution encoding framework built on Vision-Language Models. It samples document images at multiple resolutions, fuses features via Resolution-level Matryoshka Representation Learning, and compresses tokens with semantic-aware clustering. On ViDoRe benchmarks, MURE attains state-of-the-art performance while using significantly fewer tokens than prior SOTA models.

## Method Summary
MURE processes a document by first partitioning the image into a set of predefined grids (e.g., 1×1, 1×2, 2×2, 2×3). Each grid region is resized to the VLM's input resolution and encoded by a shared vision encoder. The multi-resolution feature maps are concatenated and fed to a LLM backbone, which performs cross-modal fusion and generates a sequence of token embeddings. To support flexible token budgets, Resolution-level Matryoshka Representation Learning organizes the sequence into nested segments representing coarser to finer resolutions; training employs a weighted contrastive loss over all nested representations. During offline indexing, a Hierarchical Agglomerative Clustering (HAC) algorithm merges tokens with high cosine similarity until a predefined budget N_t is reached, yielding a compact document representation. At retrieval, queries are encoded by the LLM, and relevance is computed via late interaction (MaxSim) between query and document tokens.

## Key Results
- MURE with 512 tokens beats full-resource ColPali by +0.8% on ViDoRe V1 and +0.6% on V2, while using 50% fewer tokens.
- The full MURE model outperforms ColMate by +1.9% (V1) and +2.3% (V2) in NDCG@5.
- MURE achieves state-of-the-art among its class on both ViDoRe V1 and V2.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Multi-resolution sampling captures complementary visual cues across scales, improving retrieval robustness for both coarse layout and fine details.
- **Mechanism:** The image is partitioned into multiple grids (e.g., 1×1, 1×2, 2×2, 2×3). Each grid splits the image into regions that are resized to the VLM’s input resolution and encoded by a shared vision encoder. The resulting feature maps from all grids are concatenated to form a hierarchical feature set.
- **Core assumption:** No single resolution optimally captures all relevant visual information; different queries benefit from different spatial granularities.
- **Evidence anchors:** Abstract states “multi-resolution sampling strategy … to capture both high-level layout structure and low-level granular details”; Section 3.2 formalizes the process; related work (e.g., DocPruner) focuses on token pruning rather than multi-resolution encoding, indicating a distinct approach.
- **Break condition:** Predefined grids may not align with a document’s natural layout (e.g., extreme aspect ratios), causing distortion and loss of structural integrity; additionally, encoding multiple grids may introduce overhead that outweighs benefits for simple documents.

### Mechanism 2
- **Claim:** Resolution-level Matryoshka Representation Learning (RMRL) fuses multi‑granular features into nested representations that support flexible truncation and maintain performance across token budgets.
- **Mechanism:** After encoding, features from all resolutions are concatenated and passed through the LLM backbone. The output sequence is partitioned into segments corresponding to each resolution level. Nested representations D(k) are formed by concatenating segments from the coarsest up to level k. Training uses a weighted sum of contrastive losses across all levels to ensure each nested representation is semantically meaningful.
- **Core assumption:** Coarser representations can serve as effective approximations of finer ones, and training with nested objectives encourages hierarchical feature alignment.
- **Evidence anchors:** Abstract mentions “resolution-level Matryoshka representation learning (RMRL) for effective feature fusion”; Section 3.3.2 defines the nested structure and joint loss; corpus cites prior Matryoshka Representation Learning (MRL) but RMRL applies it at resolution level rather than token level.
- **Break condition:** If granularity levels are too close, nested representations may lack discriminative power at coarser levels; mis‑specified loss weights could cause some levels to be undertrained, degrading truncated performance.

### Mechanism 3
- **Claim:** Semantic‑aware hierarchical clustering compresses the multi‑resolution token sequence into a fixed budget while preserving semantic relevance, enabling efficient indexing.
- **Mechanism:** During offline indexing, Hierarchical Agglomerative Clustering (HAC) merges token embeddings based on cosine similarity in a bottom‑up manner until the token count reaches a predefined budget N_t. The resulting cluster centroids form the final document representation.
- **Core assumption:** Tokens with high cosine similarity share semantic content and can be merged without significant loss.
- **Evidence anchors:** Abstract includes “semantic‑aware hierarchical clustering mechanism for visual token compression”; Section 3.5 describes the HAC process; corpus notes DocPruner performs adaptive patch‑level pruning, while MURE’s HAC operates on the entire multi‑resolution sequence.
- **Break condition:** If the token budget is too low, critical fine‑grained details may be lost even after merging; cosine similarity may not capture all aspects of visual semantics (e.g., spatial relationships), leading to suboptimal merges.

## Foundational Learning
- **Late Interaction (MaxSim)** – Needed to compute query‑document relevance by matching each query token to the most similar document token, avoiding quadratic cost while preserving fine‑grained matching. *Quick check:* How does MaxSim aggregate token‑level similarities into a final score?

## Architecture Onboarding
- **Component map:** Multi-resolution sampler → Vision encoder → LLM backbone → RMRL module → HAC compressor → stored centroids. Query path: Text → LLM → MaxSim scorer.
- **Critical path:** Input image → multi‑resolution splitting → per‑grid encoding (Vision encoder) → feature concatenation → LLM fusion → RMRL partitioning into nested segments → (optional truncation at level k) → HAC compression → document representation. Retrieval: Query → LLM encoding → MaxSim similarity against stored centroids.
- **Design tradeoffs:** Number of granularity levels (coverage vs. complexity), token budget N_t (storage vs. accuracy), loss weights {w_k} (balance across levels), grid configurations (alignment with document aspect ratios).
- **Failure signatures:** Performance collapse when N_t < 64 tokens; high variance on irregular layouts if grids mis‑align; training instability if loss weights are poorly set.

## Limitations
- Misalignment of fixed multi‑resolution grids with extreme or irregular document layouts can distort regions and degrade retrieval.
- Semantic‑preserving HAC compression may discard spatially critical tokens because cosine similarity does not capture layout relationships.
- Generalizability to non‑rectangular documents, multilingual content, or other domains remains unvalidated.

## Confidence
- Multi‑resolution complementarity: High
- RMRL flexible truncation: Medium
- HAC semantic preservation: Low
