# Memory Caching: RNNs with Growing Memory

## Quick Facts
- **arXiv ID:** 2602.24281  
- **Source URL:** https://arxiv.org/abs/2602.24281  
- **Reference count:** 32  
- **Primary result:** Memory Caching (MC) caches intermediate RNN memory states to enable effective memory capacity that grows with sequence length, improving long-context recall while offering a flexible O(NL) complexity trade-off between standard RNNs (O(L)) and Transformers (O(L²)).

## Executive Summary
Recurrent neural networks (RNNs) suffer from a fixed-size memory that degrades performance on long-context tasks where Transformers excel due to their quadratic growing memory. This paper introduces Memory Caching (MC), which caches compressed memory checkpoints from segmented sequences, allowing RNNs to retrieve information from a growing effective memory. Four aggregation strategies—including gated residual and sparse selective caching—are proposed. Empirically, MC consistently improves RNN variants across language modeling (e.g., Titans perplexity on WikiText-103 from 20.04 to 19.14), long-context benchmarks (LongBench accuracy up to +0.8%), and needle-in-a-haystack retrieval, narrowing the gap with Transformers in recall-intensive scenarios while providing a tunable efficiency trade-off.

## Method Summary
Memory Caching processes sequences by first splitting them into segments. Within each segment, a recurrent memory module (e.g., linear attention, Deep Linear Attention, Titans) compresses tokens into a final memory state (checkpoint), which is cached. During generation, for each token, the output is computed by aggregating the online memory from the current segment with all previously cached memories. Four aggregation strategies are offered: (1) simple summation; (2) Gated Residual Memory (GRM), which applies input-dependent gating based on query-cached memory similarity; (3) Memory Soup, which interpolates cached memory parameters; and (4) Sparse Selective Caching (SSC), which selects only the top‑k relevant cached memories via a router. The total computational complexity is O(NL), where N is the number of cached segments, allowing interpolation between O(L) (N=1) and O(L²) (N=L).

## Key Results
- Titans perplexity on WikiText-103 improved from 20.04 to 19.14.
- LongBench average accuracy increased by up to +0.8%.
- MC narrows the performance gap with Transformers on long-context recall tasks while offering flexible efficiency trade-offs; SSC provides strong results with minimal overhead.

## Why This Works (Mechanism)

### Mechanism 1: Caching Checkpoints for Growing Memory
- **Claim:** MC mitigates the fixed-size memory bottleneck of standard RNNs by caching compressed representations of past segments, enabling direct access to a growing effective memory.
- **Mechanism:** The sequence is split into segments. Each segment's recurrent module compresses its tokens into a final state (checkpoint). During retrieval, the current token's output aggregates the online memory from the current segment with all cached memories from prior segments, allowing information from the entire history to be accessed without sequential compression into a single fixed state.
- **Core assumption:** Cached memory states retain sufficient information about their segments to be useful later.
- **Evidence:** The abstract states caching "checkpoints of their memory states" to grow "effective memory capacity." Section 3 defines retrieval using cached memories. Related work on linear attention and Log‑Linear also emphasizes memory scaling for recall.
- **Break condition:** If segment compression is too lossy (segment size exceeds memory module capacity), cached states become uninformative, degrading recall.

### Mechanism 2: Controllable O(NL) Complexity Trade-off
- **Claim:** MC provides a controllable computational complexity trade-off of O(NL) that interpolates between O(L) of standard RNNs (N=1) and O(L²) of Transformers (N=L), where N is the number of cached segments.
- **Mechanism:** N equals the number of segments. Retrieval per token requires O(N) operations (forward passes over cached states), so total cost scales with N. Adjusting segment size (constant C gives N=⌊L/C⌋; logarithmic gives N=O(log L)) directly controls the complexity vs. memory capacity trade-off.
- **Core assumption:** Increasing N (smaller segments) improves recall by providing more direct access points but incurs linear overhead.
- **Evidence:** The abstract notes a "flexible trade-off that interpolates." Section 4.2 derives O(NL) complexity and discusses constant vs. logarithmic segmentation. Efficient attention variants (e.g., MoBA) similarly aim to reduce quadratic cost while preserving recall.
- **Break condition:** N too small reverts to standard RNN; N approaches L incurs quadratic cost and prohibitive memory overhead.

### Mechanism 3: Advanced Aggregation Enhances Retrieval
- **Claim:** Specific aggregation strategies (GRM, Memory Soup, SSC) enhance retrieval relevance and/or efficiency over simple summation of cached states.
- **Mechanism:** 
  - GRM adds input-dependent gating (γ) to weight contributions of each cached memory, computed via similarity between query and segment context.
  - Memory Soup interpolates the *parameters* of cached memory modules, creating a new data‑dependent memory function (effective for non‑linear memories).
  - SSC uses a router to select only top‑k relevant cached memories per token, reducing retrieval cost.
- **Core assumption:** Selective or parameter‑level fusion yields more contextually accurate and/or efficient retrieval than uniform summation.
- **Evidence:** Sections 3.1–3.3 detail formulations. Section 5 ablations show removing gating or context‑dependence hurts performance; SSC provides comparable accuracy with minimal overhead (Figure 4). Mixture‑of‑Experts and adaptive attention are common in efficient Transformers, supporting selective memory access.
- **Break condition:** Poor gating/routing may select irrelevant memories or ignore critical ones. Memory Soup's parameter interpolation may create non‑sensical functions if cached parameters are incompatible.

## Architecture Onboarding
- **Component map:**  
  Segmenter -> Memory Module (per segment) -> Cache Bank -> Aggregation Function -> Output  
  (Router for SSC sits between Query and Aggregation)
- **Critical path:** For each token x_t in segment s: (a) Update online memory M^{(s)}_t via recurrence over its segment. (b) At output step, compute query q_t. (c) Query: apply aggregation over online memory and all (or selected subset of) cached memories to produce y_t. (d) After segment s finishes, cache its final state M^{(s)}_{L(s)}.
- **Design tradeoffs:**  
  - *Segment size:* Smaller → larger N → higher recall potential but higher O(NL) cost; larger → lower cost but risk of memory overflow within segment.  
  - *Aggregation:* GRM/Memory Soup → attend to all cached (higher recall, O(N) cost); SSC → sparse selection (lower cost, potential recall drop if routing fails).  
  - *Memory type:* Linear memories make GRM and Memory Soup mathematically equivalent; deep/non‑linear memories differentiate them. Deep memories may offer more expressivity but higher compute per memory forward pass.  
  - *Caching strategy:* Checkpoint‑based (memory state initialized from previous segment's final state) vs. independent compressors (fresh initialization per segment). Checkpointing may preserve continuity but risk interference; independent modules avoid interference but lose state carry‑over.
- **Failure signatures:**  
  - *Recall degradation on long contexts:* Likely segment size too large → memory overflow within segment; or aggregation too simplistic losing relevant info.  
  - *Excessive memory usage:* N too large (tiny segments) or dense aggregation on many segments → GPU OOM. Switch to SSC or increase segment size.  
  - *Training instability:* Deep memory modules with aggressive caching may cause optimization issues; try simpler linear memories first or reduce learning rate.  
  - *Poor efficiency gains:* If segment size ≈ 1, MC approaches attention (N≈L) with overhead from caching/recombination → no speedup. Use larger segments or SSC.
- **First 3 experiments:**  
  1. **Language modeling baseline:** Train DLA with and without MC (GRM, segment 256) on FineWeb subset (context 4096). Compare WikiText‑103 perplexity; expect MC to improve by ~0.3 (Table 1).  
  2. **Needle‑in‑a‑haystack:** Use 16K context, hide a target fact deep. Evaluate base RNN vs. RNN+SSC at varying depths. Expect MC to maintain high accuracy at greater depths where base RNN fails (Table 2).  
  3. **Throughput scaling:** Train models with varying context lengths (2K, 4K, 8K, 16K). Plot tokens/sec vs. context; expect MC (especially SSC) to degrade slower than Transformer (O(L²)) and be comparable to base RNN (O(L)) for small N, but increase with N (Figure 4).

## Open Questions the Paper Calls Out
- **What more expressive pooling or routing mechanisms can enhance Memory Caching's performance?** The conclusion suggests using more expressive pooling or routing beyond mean pooling and linear similarity.
- **For linear memory modules, when does Memory Caching collapse to standard recurrence, and how can this be prevented?** Section 4.1 notes that linearity causes the residual variant to mathematically collapse (Equation 13); understanding precise conditions and safeguards is open.
- **What segmentation strategy (constant, logarithmic, adaptive) optimally balances memory capacity and computational cost across tasks and sequence lengths?** The paper discusses trade‑offs but lacks a principled method to choose segment lengths.
- **How do checkpoint caching and independent compressors compare in terms of learning dynamics and final performance for different memory architectures?** Section 3.4 presents two perspectives with advantages and disadvantages (referenced in Section 5.6), but no systematic analysis.

## Limitations
- Exact architectures (number of layers, hidden dimensions) for the 760M/1.3B RNN baselines are not provided; only Transformer details appear in Table 6, hindering exact replication.
- Hyperparameters for Titans/DLA (inner learning rate η, gating parameters α, β) and GRM gating (e.g., whether u_t derives from x_t or q_t, W_u dimensions) are unspecified.
- Potential interference between cached memory states from different segments is not discussed; this could limit scaling to many segments.
- Memory overhead of caching is not quantified across segment counts, making efficiency trade‑offs less actionable.

## Confidence
- **MC grows effective memory:** High. Mechanism is clearly described, and consistent improvements across WikiText‑103, LongBench, and needle tasks support it.
- **O(NL) complexity trade‑off:** High. Scaling derivation is straightforward, and throughput experiments confirm interpolation between RNN and Transformer.
- **Aggregation strategies (GRM, Soup, SSC) improve retrieval/efficiency:** Medium. Ablations show benefits, but theoretical nuances (GRM vs. Soup equivalence for linear memories, SSC routing sensitivity) may affect generalizability.
