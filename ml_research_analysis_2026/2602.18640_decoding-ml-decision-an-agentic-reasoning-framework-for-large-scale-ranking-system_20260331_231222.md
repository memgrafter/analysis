# Decoding ML Decision: An Agentic Reasoning Framework for Large-Scale Ranking System

## Quick Facts
- **arXiv ID**: 2602.18640
- **Source URL**: https://arxiv.org/abs/2602.18640
- **Reference count**: 18
- **Primary result**: GEARS achieves 94% Top-1 accuracy and 0.96 nDCG@5 in offline policy selection, and delivers consistent metric lifts (0.011%–0.37%) across nine real-world product surfaces.

## Executive Summary
GEARS is an agentic framework that automates the translation of ambiguous product intents into deployable ranking policies. It combines Specialized Agent Skills to encode expert analytical procedures, Vibe Optimization to map high-level goals to executable constraints via tolerance-based Pareto expansion, and Deterministic Lifecycle Governance hooks to enforce feature stability and statistical robustness. In extensive offline and online evaluations, GEARS significantly outperforms strong baselines and yields reliable metric improvements while maintaining guardrail compliance.

## Method Summary
The pipeline processes a natural-language instruction and a tabular dataset of experimental ranking policies. First, the intent parser extracts objectives and constraints, generating a search specification. Then, the GAS candidate generator (Wu et al., 2025) produces a diverse set of near-Pareto-optimal policies using tolerance-based frontier expansion. The insight generator, augmented with Specialized Agent Skills and a Domain Knowledge Brain, analyzes candidates and ranks them via an LLM (Claude Sonnet). Finally, deterministic governance hooks apply pre-search feature stability filters and post-candidate statistical robustness checks to discard brittle policies, outputting a final ranked list. No model training is involved; the system orchestrates existing tools and data.

## Key Results
- **Offline accuracy**: 94% Top-1 accuracy (vs 77% for Code-as-Action) and nDCG@5 of 0.96 across 100 experimental instructions.
- **Online lifts**: Consistent metric improvements (0.011% to 0.37%) across nine diverse product surfaces.
- **Robustness**: Selected policies maintain guardrail compliance and deployment stability, demonstrating near-Pareto efficiency with reduced human effort.

## Why This Works (Mechanism)
Specialized Agent Skills modularize expert knowledge into step-by-step analytical scripts, enabling the LLM to perform nuanced policy evaluation that mimics human experts. Vibe Optimization bridges the gap between vague intents and concrete search by using tolerance-based Pareto expansion, which explores a broader set of tradeoffs than strict Pareto optimality. Deterministic Lifecycle Governance hooks act as safety nets, filtering out policies that rely on unstable features or exhibit temporal fragility, thus ensuring that only robust policies reach deployment. Together, these components create a closed-loop discovery process that consistently finds high-quality policies with minimal manual intervention.

## Foundational Learning
1. **Agentic Reasoning**  
   *Why needed*: Enables autonomous, multi-step decision-making by orchestrating tools and data.  
   *Quick check*: Does the system independently plan and execute sequences of actions (e.g., parse, generate, analyze, filter)?

2. **Pareto Frontier Expansion**  
   *Why needed*: Generates a diverse candidate set that approximates optimal tradeoffs under multi-objective constraints.  
   *Quick check*: Are policies admitted within a tolerance τ of the Pareto front, not just on the front itself?

3. **Specialized Agent Skills**  
   *Why needed*: Encodes domain-specific analytical procedures (e.g., feature stability audits) in reusable modules.  
   *Quick check*: Are skills structured as files containing instructions and scripts that can be progressively loaded?

4. **Vibe Optimization**  
   *Why needed*: Translates ambiguous natural language intents into precise search specifications and constraints.  
   *Quick check*: Does the intent parser output metric weights, thresholds, and constraint types?

5. **Deterministic Lifecycle Governance**  
   *Why needed*: Ensures policy robustness by filtering based on feature stability and statistical consistency.  
   *Quick check*: Are there pre- and post-filters with clear thresholds (e.g., cohort shift ≤15%)?

## Architecture Onboarding
**Component map**: 
Instruction -> Intent Parser -> GAS Candidate Generator -> Insight Generator -> Governance Hooks (Pre-filter + Post-filter) -> Final Ranked Policies

**Critical path**: Parsing the instruction → Generating diverse candidates via GAS → Ranking candidates using LLM with Skills → Applying governance filters → Output.

**Design tradeoffs**:  
- *Tolerance τ*: Larger τ increases candidate diversity but may include suboptimal policies; smaller τ risks missing good tradeoffs.  
- *Skill granularity*: Fine-grained skills improve analysis but increase context length; coarse skills may lose nuance.  
- *Governance strictness*: Stricter thresholds enhance robustness but may reject viable policies; looser thresholds risk brittle deployments.

**Failure signatures**:  
- Selected policies fail pre-filter due to feature instability (high cohort shift).  
- LLM ranking contradicts expert judgment (low nDCG).  
- GAS expansion produces too few candidates (empty frontier).  
- Skills not loaded, leading to generic analysis.

**First three experiments**:  
1. Replicate the offline benchmark using synthetic policy data and a vanilla LLM prompt (no Skills) to establish a baseline.  
2. Sweep tolerance τ values to analyze tradeoff between candidate set size and final policy quality.  
3. Simulate feature shift distributions and vary governance thresholds to assess sensitivity and identify optimal operating points.

## Limitations
- **Proprietary dependencies**: Exact implementation of Specialized Agent Skills and Domain Knowledge Brain is undisclosed, hindering faithful replication.
- **GAS opacity**: Critical hyperparameters and HTE computation details for the candidate generator (Wu et al., 2025) are unavailable.
- **Governance thresholds**: The 15%/45% stability thresholds are derived from internal benchmarks not described, making hook validation imprecise.

## Confidence
- **Claim**: GEARS significantly outperforms baselines in offline policy selection. **Confidence**: Medium (internally validated but not independently reproducible).  
- **Claim**: Governance hooks effectively filter brittle policies. **Confidence**: Medium (ablation evidence but thresholds may be context-specific).  
- **Claim**: GEARS reduces human engineering effort. **Confidence**: Low (qualitative, no quantitative measurement).
