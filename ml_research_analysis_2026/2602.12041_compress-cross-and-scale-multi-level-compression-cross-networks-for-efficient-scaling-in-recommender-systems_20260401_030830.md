# Compress, Cross and Scale: Multi-Level Compression Cross Networks for Efficient Scaling in Recommender Systems

- arXiv ID: 2602.12041
- Source URL: https://arxiv.org/abs/2602.12041
- Reference count: 32

## Executive Summary
Recommender systems require effective modeling of high-order feature interactions, but existing approaches face trade-offs among accuracy, computational cost, and scalability. This paper proposes the Multi-Level Compression Cross network (MLCC), which combines hierarchical compression (global and local) with a dynamic Progressive Layered Crossing module to achieve expressive yet parameter-efficient interactions. A multi-channel extension, MC-MLCC, further enables horizontal scaling via parallel subspaces.

Extensive evaluations on public benchmarks and an industrial advertising platform demonstrate MLCC/MC-MLCC's advantages. The models outperform strong DLRM baselines by up to 0.52% AUC, reduce parameters and FLOPs by up to 26× on industrial data, and yield a cumulative +32% improvement in ad delivery value (ADVV) in online A/B testing, all while meeting strict latency constraints.

## Method Summary
MLCC processes sparse categorical features by first learning embeddings, then applying global compression to reduce dimensionality across all features, followed by local compression within feature groups to capture fine-grained interactions. The Progressive Layered Crossing (PLC) module dynamically combines these compressed embeddings using a learned MLP that adapts to the data, enabling high-order cross features without explicit pairwise expansion. MC-MLCC partitions features into multiple channels processed independently, allowing linear scaling of capacity and computation with the number of channels. This design yields a compact model that maintains expressive power and is amenable to parallelization.

## Key Results
- MLCC/MC-MLCC achieve up to 0.52% higher AUC than strong DLRM baselines (Wukong, DCNv2) on public datasets.
- On an industrial dataset, the models reduce parameters and FLOPs by up to 26× compared to baselines.
- Online A/B testing in a large advertising platform reports a cumulative +32% improvement in ADVV under strict latency constraints.

## Why This Works (Mechanism)
The hierarchical compression in MLCC addresses the curse of dimensionality in high-order feature interactions. Global compression aggregates information across all features into a lower-dimensional space, reducing redundancy and computational overhead. Local compression then refines the representation within feature subspaces, preserving important interactions that might be lost in the global reduction. The Progressive Layered Crossing module dynamically learns to combine these compressed representations via a lightweight MLP, effectively modeling high-order dependencies without the need for explicit feature crosses. This adaptive mechanism ensures that the model remains expressive while staying parameter-efficient. MC-MLCC’s multi-channel design partitions features into independent subspaces, enabling horizontal scaling: each channel processes its own set of compressed embeddings, and their outputs can be concatenated or aggregated, allowing the model to increase capacity linearly with the number of channels without increasing per-channel complexity. The combination of compression and crossing thus yields models that are both accurate and efficient, making them suitable for large-scale industrial recommender systems with tight latency budgets.

## Architecture Onboarding
### Component Map
Input embeddings -> Global Compression (GC) -> Local Compression (LC) groups -> Progressive Layered Crossing (PLC) modules (stacked) -> Output aggregation (for MC-MLCC: multiple channels concatenated) -> Prediction head

Sparse Features -> Embedding Lookup -> GC -> LC (per group) -> PLC1 -> PLC2 -> ... -> PLC_L -> Channel Fusion (MC-MLCC) -> MLP -> Sigmoid

### Critical Path
The data flows from embedding lookup through compression stages, then through the stacked PLC layers where dynamic crossing occurs, finally aggregating across channels if multi-channel is used, and producing a prediction. The key computational cost lies in the PLC modules; compression stages reduce dimensionality to keep costs low.

### Design Tradeoffs
- **Compression Ratio**: Higher compression reduces parameters and FLOPs but may lose information; MLCC balances via two-stage compression.
- **Number of PLC Layers**: Deeper PLC can model more complex interactions but increases latency; the paper uses a few layers.
- **Channel Count (MC-MLCC)**: More channels increase capacity and parallelism but also total FLOPs; partitioned features must be chosen to avoid imbalanced workloads.
- **Dynamic vs Static Crossing**: Using an MLP (dynamic) vs fixed cross weights; dynamic offers adaptability but adds slight overhead.

### Failure Signatures
- **Performance drop with aggressive compression**: If global/local compression ratios are too high, AUC degrades significantly.
- **Channel imbalance**: In MC-MLCC, if features are unevenly partitioned, some channels become bottlenecks, hurting latency.
- **PLC overfitting**: With many PLC layers on small data, the model may overfit despite compression.
- **Latency violation**: If the per-layer FLOPs of PLC are not carefully controlled, p99 latency may exceed constraints.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How does hierarchical compression in MLCC specifically mitigate embedding collapse, a phenomenon where high-dimensional embeddings become redundant or low-rank?
- Basis in paper: [inferred] The paper discusses embedding collapse in related work (Section 2.2) and introduces compression via GC and LC to improve efficiency, but no direct analysis or measurement of embedding spectral properties (e.g., effective rank) is provided to confirm collapse mitigation.
- Why unresolved: Without quantifying representation quality, it is unclear whether MLCC's gains stem from alleviating collapse or from other architectural benefits like structured interactions.
- What evidence would resolve it: Conduct experiments measuring embedding spectrum (e.g., singular value decay) or effective rank for MLCC versus baselines (e.g., DNN, Wukong) across varying embedding dimensions, and correlate with performance changes.

### Open Question 2
- Question: What is the optimal feature partitioning strategy for MC-MLCC's multi-channel design, and should feature semantics (e.g., cardinality, type) influence channel allocation to maximize efficiency?
- Basis in paper: [inferred] MC-MLCC partitions features uniformly across channels (Equation 10), but the paper does not explore whether feature-aware partitioning could further improve performance or parameter efficiency given diverse feature interactions.
- Why unresolved: Uniform partitioning is assumed optimal, but features with different characteristics (e.g., high vs. low cardinality) may benefit from specialized channels, potentially enhancing representational capacity without extra cost.
- What evidence would resolve it: Compare uniform partitioning with heuristic or learned partitioning strategies (e.g., clustering features by embedding size or importance scores) on AUC and FLOPs, testing if channel-aligned features yield better scaling ROI.

### Open Question 3
- Question: Can integrating attention mechanisms into the PLC module capture higher-order interactions more effectively than the dynamic MLP, while maintaining comparable computational efficiency?
- Basis in paper: [explicit] The paper describes an attention-inspired analogy for PLC (Section 3.3) but does not implement or compare against standard self-attention (e.g., as in AutoInt), leaving open whether attention could enhance expressiveness with controlled overhead.
- Why unresolved: Attention might model dependencies more flexibly but often incurs quadratic cost; it is unknown if a hybrid design (e.g., sparse attention or linear approximations) could outperform the MLP-based dynamiccross in PLC under latency constraints.
- What evidence would resolve it: Replace the MLP in PLC with an attention sublayer (e.g., multi-head attention with shared keys) and evaluate trade-offs between AUC gains and FLOPs increase across head numbers and embedding sizes, using matched computational budgets.

## Limitations
- The paper’s claims rely heavily on internal industrial datasets and proprietary A/B testing infrastructure, limiting external verification.
- Reported efficiency gains (e.g., 26× reduction) are measured against unspecified DLRM variants and may not generalize across hardware or serving setups.
- The AUC improvements on public benchmarks are modest (up to 0.52%) and their practical significance depends on baseline performance and dataset difficulty.
