# LLM Olympiad: Why Model Evaluation Needs a Sealed Exam

## Quick Facts
* arXiv ID: 2603.23292
* Source URL: https://arxiv.org/abs/2603.23292
* Reference count: 18
* Primary result: Empirical evidence (GSM8k-Platinum rank shifts; up to 13% drop on GSM1k) demonstrates benchmark fragility, motivating sealed exam protocol.

## Executive Summary
Large language model (LLM) evaluations suffer from fragility due to test-set contamination, overfitting, and variable evaluation protocols. To address these issues, the authors propose an Olympiad-style sealed exam: tasks remain confidential until scoring, model submissions are frozen before disclosure, and a centralized harness executes all submissions uniformly. After evaluation, tasks and code are released for transparency. 

Empirical evidence from math benchmarks (GSM8k-Platinum and GSM1k) demonstrates significant rank changes and accuracy drops up to 13% on fresh problem sets, confirming overfitting to existing tests. The sealed exam protocol aims to yield more reliable and harder-to-game comparisons for high-stakes model evaluations.

## Method Summary
The sealed exam protocol consists of three core phases. First, task confidentiality: evaluation tasks are withheld from participants until the scoring phase. Second, freeze-and-commit: model submissions (weights or inference APIs) are frozen prior to task disclosure, preventing last-minute adjustments that could exploit knowledge of the test. Third, centralized execution: a standardized harness runs all frozen submissions on the sealed tasks under identical conditions, and a scoring engine computes metrics. After results are published, all tasks and evaluation code are released to ensure transparency and enable independent audit. This design eliminates participant-side variability and contamination while aligning incentives toward robust models.

## Key Results
* Significant rank changes observed on the cleaned GSM8k-Platinum benchmark, indicating instability in current leaderboards.
* Fresh problem set GSM1k reveals accuracy drops of up to 13% for state-of-the-art models, demonstrating overfitting to existing tests.
* The proposed sealed exam protocol directly addresses benchmark fragility, test-set contamination, and incentive misalignment in LLM evaluation.

## Why This Works (Mechanism)
The sealed exam mitigates three critical pressures in LLM evaluation. Fragility is reduced because participants cannot tune their models to the specific test items; their submissions are frozen before seeing tasks, so results reflect inherent capability rather than overfitting. Contamination is prevented by keeping tasks secret until scoring, eliminating the risk that models have been trained on leaked data. Incentive misalignment is addressed by decoupling model updates from the evaluation event; developers are motivated to build generalizable models rather than shortcuts optimized for known benchmarks. Centralized execution further removes variability in hardware, libraries, and scoring implementations, ensuring a level playing field. Together, these elements produce more reliable and harder-to-game rankings.

## Architecture Onboarding
**Component map**:  
Submission Registry -> Centralized Harness <- Task Repository (sealed) -> Scoring Engine -> Results  
Post-evaluation: Task & Code Release

**Critical path**:  
1. Participants upload frozen model snapshots to Submission Registry.  
2. Task Repository remains sealed; no access during submission period.  
3. Centralized Harness retrieves a frozen snapshot and the sealed tasks.  
4. Harness executes the model on tasks under controlled environment.  
5. Scoring Engine evaluates outputs against reference answers.  
6. Results are published; then tasks and evaluation code are released.

**Design tradeoffs**:  
- Centralization improves fairness but introduces scalability challenges and a potential single point of failure.  
- Secrecy prevents contamination but may limit transparency until after results; early disclosure could leak tasks.  
- Freeze requirement may hinder teams that iterate rapidly, possibly discouraging participation.

**Failure signatures**:  
- Unusually high performance compared to prior checks, suggesting possible task leakage.  
- Discrepancy when re-running the same frozen submission, indicating harness non-determinism or tampering.  
- Unauthorized access logs to the Task Repository during the submission window.

**First experiments**:  
1. **Unit testing**: Verify each component (Submission Registry, Harness, Scoring Engine) in isolation using mock data and interfaces.  
2. **Smoke test**: Run a full pipeline with a trivial baseline model (e.g., random guesser) on a small sealed task set to confirm end-to-end correctness.  
3. **Security validation**: Attempt to retrieve sealed tasks from outside the Harness to ensure confidentiality controls are properly enforced.

## Limitations
* **Scalability unproven**: The protocol’s cost, logistics, and potential for accidental leakage in a large multi-organizational setting have not been tested.
* **Limited domain evidence**: Evaluation was restricted to two mathematics benchmarks, raising questions about applicability to coding, multimodal reasoning, or other tasks.
* **Transparency gaps**: The paper lacks statistical details (e.g., variance, confidence intervals) for rank shifts and accuracy drops, and provides no reproducibility notes, impeding independent verification.

## Confidence
* Fragility of current benchmarks: **High**  
* Sealed exam design effectiveness: **Medium**  
* Overfitting evidence (GSM1k drop): **Medium**  
* Higher-assurance evaluations: **Low**

## Next Checks
1. Orchestrate a multi-vendor sealed exam trial across a diverse benchmark suite (math, code, reasoning) and compare ranking stability with traditional open evaluation.
2. Assess contamination vulnerability by deliberately exposing a subset of tasks to a subset of participants before the freeze and measuring associated performance gains.
3. Release the complete evaluation harness and conduct an external reproducibility audit where independent teams re-execute frozen submissions on the sealed tasks to confirm results and surface discrepancies.
