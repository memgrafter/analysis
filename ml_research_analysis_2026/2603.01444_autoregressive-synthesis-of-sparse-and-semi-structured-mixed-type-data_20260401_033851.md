# Autoregressive Synthesis of Sparse and Semi-Structured Mixed-Type Data

## Quick Facts
- **arXiv ID:** 2603.01444  
- **Source URL:** https://arxiv.org/abs/2603.01444  
- **Reference count:** 40  
- **Primary result:** Origami is the first architecture to natively synthesize sparse, semi-structured JSON records without flattening, outperforming six baselines in fidelity, utility, and detection robustness even under up to 38% sparsity, while achieving high privacy scores.

## Executive Summary
Existing synthetic data generation methods assume dense, fixed-schema tables, faltering with modern sparse, hierarchical semi-structured data like JSON. Flattening such data scales poorly and destroys structural information. This paper introduces Origami, an autoregressive transformer that directly tokenizes JSON records into sequences of keys, values, and structural tokens, preserving sparsity and hierarchy. Origami combines Key-Value Position Encoding for order-invariant representation, a dual-head output (discrete for tokens, Mixture of Gaussians for continuous numerics), and grammar/schema constraints to guarantee valid JSON. Evaluated on five datasets, Origami surpasses six state-of-the-art baselines across fidelity, utility, and detection metrics, remains robust under extreme sparsity (up to 38%), and achieves high privacy without memorization. This work establishes the first end-to-end solution for semi-structured synthesis, enabling privacy-preserving sharing and analysis of complex data formats.

## Method Summary
Origami processes each JSON record as a flat sequence of tokens: keys, values (discrete or continuous), and structural markers (e.g., object/array delimiters). A transformer-based autoregressive model captures dependencies between tokens. To handle the order-invariance of key-value pairs within objects, it uses Key-Value Position Encoding (KVPE) where each key receives a unique identifier via a learned embedding table; positional encoding then depends on the key’s nested path rather than its sequence position. During training, the model predicts the next token using a dual-head output: a discrete head (cross-entropy) for categorical/string tokens and a continuous head (Mixture of Gaussians) for high-cardinality numerics, naturally accommodating mixed types. Grammar constraints enforced by a pushdown automaton prune invalid next tokens at each step, with a compiled mask table enabling efficient constrained decoding. Additional training tricks include shuffling key order for robustness and left-padding to reduce padding overhead.

Generation proceeds token-by-token with the constraint decoder guaranteeing syntactic validity, followed by post-processing (clipping, snapping to enums, rounding). The architecture uses 8 transformer layers, d_model=64, feed-forward dimension 512, 4 attention heads, and 5 MoG components. Training uses AdamW with learning rates between 1e-4 and 5e-4, batch sizes 64 or 128, for 50–400 epochs depending on dataset, with FP16 acceleration.

## Key Results
- Origami state-of-the-art performance across all five benchmark datasets (Adult, Diabetes, Electric Vehicles, Yelp, DDXPlus), outperforming six baselines (GAN, VAE, diffusion, autoregressive) in fidelity, utility, and detection metrics.
- Robustness to extreme sparsity: maintains high scores even when up to 38% of values are missing, while other methods fail or degrade substantially.
- Privacy preservation: DCR scores ≥0.97 and negligible exact matches, indicating synthetic data does not simply memorize training records.

## Why This Works (Mechanism)
Origami succeeds because it models native JSON structure directly, preserving sparsity and hierarchy. Its autoregressive transformer captures complex token dependencies. Key-Value Position Encoding ensures order-invariance of key-value pairs, essential since JSON objects have no intrinsic key order. The dual-head output appropriately handles mixed discrete and continuous types, with Mixture of Gaussians offering flexibility for high-cardinality numerics. Grammar constraints via a pushdown automaton enforce syntactic validity during generation, eliminating the need for costly post-hoc filtering. These innovations avoid the distortion introduced by flattening, enabling the model to learn the true data distribution and generate high-fidelity synthetic records with accurate presence patterns and value distributions even for sparse features.

## Foundational Learning
- **Autoregressive modeling** – Predicts tokens sequentially to model joint distribution; *why needed*: enables tractable density estimation and easy constraint integration; *quick check*: next-token loss decreases during training.
- **Key-Value Position Encoding (KVPE)** – Assigns keys unique path-based embeddings; *why needed*: removes bias from arbitrary key ordering in JSON objects; *quick check*: same key at same path yields identical embeddings regardless of sequence position.
- **Dual-head output (discrete + MoG)** – Separate heads for categorical and high-cardinality numeric tokens; *why needed*: accommodates mixed data types with appropriate likelihoods; *quick check*: numeric tokens trained with MoG loss (negative log-likelihood), categoricals with cross-entropy.
- **Grammar constraints (pushdown automaton)** – Prunes invalid next tokens using a compiled mask table; *why needed*: ensures syntactically valid JSON without post-processing; *quick check*: generated samples parse without errors and satisfy JSON schema.
- **Sparsity handling** – Predicts key presence as explicit tokens; *why needed*: models missingness patterns naturally; *quick check*: presence accuracy matches real data sparsity distribution.
- **Left-padding** – Minimizes padding tokens in batched sequences; *why needed*: reduces computational waste; *quick check*: batches contain few leading padding tokens relative to right-padded baseline.

## Architecture Onboarding
- **Component map**: Raw JSON → Tokenizer (keys/values/structural tokens) → Key-Value Position Encoder → Transformer (8 layers) → Dual-Head Output Layer (discrete & MoG) → Constraint Decoder (pushdown automaton) → Synthetic JSON
- **Critical path**: Tokenization preserves structure → KVPE adds order-invariant embeddings → Transformer contextualizes → Dual-head predicts next token type → Constraint decoding enforces validity → Post-processing improves utility.
- **Design tradeoffs**: 
  - Autoregressive generation is slow but allows tractable density and easy constraints; parallel generation would sacrifice these.
  - Dual-head simplifies mixed types but requires careful loss weighting to balance discrete and continuous objectives.
  - Constraint decoding adds overhead but guarantees validity; free generation with filtering would be inefficient and yield low sample efficiency.
- **Failure signatures**: 
  - Invalid JSON output indicates constraint decoder misconfiguration.
  - High detection score (synthetic easily spotted) suggests distribution mismatch; inspect presence and value sub-scores.
  - Poor fidelity on sparse numeric columns points to insufficient MoG components or training issues.
  - GPU OOM on large datasets – reduce batch size or model dimension.
- **Three first experiments**: 
  1. Train on Adult dataset with default config; ensure training/validation loss converge within 400 epochs.
  2. Generate 1,000 samples and validate JSON structure programmatically; expect 100% valid.
  3. Evaluate Adult metrics; target fidelity >0.99, utility (TSTR F1 ratio) >0.995, detection score >0.955 (ROC AUC ~0.52), matching paper Table 3.

## Open Questions the Paper Calls Out
1. **Multi-collection relational data** – Extending Origami to handle foreign-key dependencies and cross-record consistency.
2. **Cardinality estimation** – Using Origami’s tractable density to estimate query result sizes on semi-structured data.
3. **Direct predictive modeling** – Training models on native semi-structured records (e.g., graph neural networks) with origami-synthesized data instead of flattened tables.
4. **Outlier detection** – Leveraging likelihood scores from Origami to identify anomalies in semi-structured distributions.

## Limitations
- Hyperparameter schedules (learning rate decay, early stopping thresholds) are not fully documented; reproduction relies on default validation-based choices.
- Metric implementations (e.g., decomposed column shapes) may vary if the public repository differs from the paper description.
- Scalability: larger datasets (Yelp, DDXPlus) risk GPU OOM, requiring manual batch size tuning and careful memory management.
