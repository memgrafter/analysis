# ArcMark: Multi-bit LLM Watermark via Optimal Transport
## Quick Facts
- **arXiv ID:** 2602.07235
- **Source URL:** https://arxiv.org/abs/2602.07235
- **Reference count:** 40
- **Primary result:** ArcMark achieves the first capacity-optimal distortion-free multi-bit watermark for LLMs, significantly outperforming prior multi-bit schemes (BiMark, MPAC) in message and bit accuracy while preserving text quality.

## Executive Summary
ArcMark tackles the previously unknown information-theoretic capacity of embedding multi-bit watermarks in large language model (LLM) outputs without altering the average next-token distribution. The core innovation treats watermarking as a channel coding problem with side information, combining random linear channel codes, per-token randomness, and an optimal transport (OT) layer that precisely preserves the LLM’s token marginal. The OT mapping translates a circular target angle derived from the encoded message and random shift into a probability distribution over the vocabulary that matches the LLM’s original next-token probabilities, thereby guaranteeing a distortion‑free embedding. Theoretically, the authors derive a capacity expression for this setup and prove that ArcMark attains it under simplifying i.i.d. uniform binary token assumptions. Empirically, ArcMark surpasses state‑of‑the‑art multi-bit watermarks (BiMark, MPAC) across Llama2‑7B and Llama3‑8B for messages of 3, 8, and 16 bits, with the performance gap widening for longer messages; perplexity remains indistinguishable from unwatermarked generation, confirming the distortion-free claim.

## Method Summary
ArcMark encodes a \(k\)-bit message \(m\) into a codeword \(C = m \cdot G \bmod p\) where \(G\) is a random linear generator matrix over \(\mathbb{Z}_p\) and \(p=2^k\). At each generation step \(t\), a secret permutation \(\Pi_t\) of the vocabulary and a random side‑information value \(V_t \sim \text{Uniform}\{0,\dots,r-1\}\) are generated. The target angle on the unit circle is set to \(z_t = 2\pi\bigl(C_t/p + V_t/r\bigr) \bmod 2\pi\). The LLM produces a next‑token probability vector \(Q\) (its usual softmax). An optimal transport problem \(Q_{X|Z}\) is solved to find a conditional distribution over tokens that maps the circular representation (via \(\Pi_t\)) to \(z_t\) while exactly matching the marginal \(Q\). Implementation uses a Sinkhorn iteration with a small entropy regularizer \(\epsilon\). Sampling from \(Q_{X|Z=z_t}\) yields the watermarked token. Decoding removes the side information \(V_t\) from each token (using \(\Pi_t\)) to recover estimates \(\hat{C}_t\), then finds the message whose codeword angular distances sum to a minimum. The design ensures each token carries information about the whole message.

## Key Results
- **Capacity success:** Under i.i.d. uniform‑binary token distribution, ArcMark achieves the derived information‑theoretic capacity, proving optimality for that setting.
- **Empirical advantage:** For 3‑, 8‑, and 16‑bit messages, ArcMark consistently yields higher message accuracy (full‑message recovery) and bit accuracy than BiMark and MPAC, with larger gains for longer messages.
- **Distortion‑free quality:** Watermarked text maintains perplexity statistically indistinguishable from unwatermarked generation on Llama2‑7B and Llama3‑8B.

## Why This Works (Mechanism)
ArcMark’s effectiveness stems from three tightly coupled design choices:  
1. **Linear block coding** spreads each bit of the message across all tokens, ensuring that every token carries partial information about the whole message and enabling efficient error correction.  
2. **Side information** (\(V_t\)) decorrelates the embedding across time steps, simplifying decoding and avoiding interference.  
3. **Optimal transport** solves a constrained redistribution problem: it finds a token‑level conditional distribution that exactly preserves the LLM’s marginal while steering the expected circular angle toward the target. The Sinkhorn algorithm approximates this OT map efficiently. Because the marginal constraint is satisfied exactly, the watermark does not bias the token distribution, which explains the unchanged perplexity and the "distortion‑free" property.

## Foundational Learning
- **Channel coding with side information:** The scenario where the encoder knows random parameters (here \(V_t\)) that the decoder also knows. Needed because side information allows decorrelation and simplifies capacity analysis. Quick check: Are the side‑info values \(V_t\) public and used identically at encoder/decoder? Yes.
- **Optimal transport (Sinkhorn):** Finds a transport plan that minimizes a cost while matching marginals. The entropy‑regularized version yields fast approximations. Quick check: Does the Sinkhorn solution produce a coupling with row sums exactly equal to \(Q\) after scaling? Yes.
- **Linear error‑correcting codes over integers:** Messages multiplied by a random generator matrix add redundancy. Quick check: Is the code linear over \(\mathbb{Z}_p\)? Yes.
- **Circular representation:** Tokens are mapped to an angle via a secret permutation; the target angle combines codeword and side info. Quick check: Is the angle computation modulo \(2\pi\)? Yes.
- **Distortion‑free watermarking:** The watermark should not alter the average next‑token distribution. Quick check: Does ArcMark enforce that the marginal of the watermarked distribution matches the original LLM’s next‑token probabilities? Yes, by OT marginal constraint.

## Architecture Onboarding
**Component map:**  
LLM -> Encoder (message to codeword C, randomness V, permutation Π) -> Optimal Transport Solver (Sinkhorn) -> Sampled Token -> Context update -> repeat

**Critical path:** Given current context, LLM outputs logits → softmax yields \(Q\); Encoder computes target \(z_t\); OT solver constructs coupling \(P\) satisfying \(P_{\text{row sums}=Q}\); row \(V_t\) of \(P\) yields token probabilities; sampling produces next token; loop continues.

**Design tradeoffs:**  
- Entropy regulator \(\epsilon\) vs. marginal matching: smaller \(\epsilon\) yields sharper probabilities but may break exact marginal equality; larger \(\epsilon\) is easier to compute but blurs the target angle.  
- Side‑info range \(r\) vs. decoding ambiguity: larger \(r\) reduces ambiguity but increases OT matrix size (vocab × r) and memory.  
- Vocabulary truncation vs. distortion: Using top‑K reduces memory but may alter marginal; full vocabulary preserves distribution but expensive.

**Failure signatures:**  
- Low message accuracy despite high bit accuracy: decoding error, check marginals and permutation consistency.  
- Perplexity increase: marginal constraint violated; re‑examine Sinkhorn convergence.  
- Memory overflow: OT matrix too large; reduce \(r\) or use top‑K.

**First three experiments:**  
1. **Marginal check:** After Sinkhorn, compute row sums of the coupling and compare to \(Q\); maximum absolute deviation should be < 1e‑3.  
2. **Hyperparameter sweep:** Vary \(\epsilon\) (e.g., 0.05, 0.1, 0.2) and max iterations; plot message accuracy and perplexity to find stable regime.  
3. **Baseline replication:** Implement MPAC and BiMark exactly as described, run with identical prompts and models, verify reported performance gap.

## Open Questions the Paper Calls Out
- **Capacity for general token distributions:** What is the information‑theoretic capacity of distortion‑free multi‑bit watermarking beyond the i.i.d. uniform‑binary case?  
- **Impact of feedback:** Can exploiting the fact that the watermarker sees the generated tokens improve decoding error or reduce complexity?  
- **Broad applicability of capacity‑achieving schemes:** Can channel‑coding watermarking achieve capacity for non‑i.i.d. processes and large alphabets?  

## Limitations
- **Unspecified implementation details:** Critical hyperparameters (Sinkhorn \(\epsilon\), iteration limit, tolerance), exact permutation generation, and whether OT runs on full or truncated vocabulary are missing, hindering exact replication.  
- **Unrealistic theoretical assumptions:** Capacity proof requires i.i.d. tokens uniformly distributed over binary pairs, which never holds in real LLM generation, leaving practical capacity unknown.  
- **Limited empirical scope:** Experiments cover only two Llama models and the C4‑RealNewslike dataset; generalizability to other architectures and domains remains unverified.
