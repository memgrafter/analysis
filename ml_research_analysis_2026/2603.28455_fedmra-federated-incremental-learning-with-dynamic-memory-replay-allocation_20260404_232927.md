# FeDMRA: Federated Incremental Learning with Dynamic Memory Replay Allocation

## Quick Facts
- **arXiv ID:** 2603.28455
- **Source URL:** https://arxiv.org/abs/2603.28455
- **Reference Count:** 22
- **Primary Result:** Dynamic dual-channel memory allocation significantly reduces catastrophic forgetting in non-IID FCIL/FDIL/FCDIL, achieving state-of-the-art average accuracy (e.g., 85.26% on FCDIL at α=1.0) and robustness under strong heterogeneity (α=0.5).

## Executive Summary
FeDMRA addresses catastrophic forgetting in Federated Class-Incremental Learning (FCIL) under non-IID data distributions. Standard replay methods use fixed exemplar memory, which fails to account for client heterogeneity in data distribution and contribution to the global model. The framework introduces a server-side dynamic memory allocation strategy that computes per-client and per-class memory quotas based on a dual-channel importance metric combining client model update deviation and local data distribution skew. On the client side, exemplars are selected using a personal information model guided by gradient norms, and local training employs a composite loss combining cross-entropy, KL distillation toward the global model, and an output magnitude regularizer. Evaluated on three medical image datasets across FCIL, FDIL, and FCDIL tasks, FeDMRA consistently outperforms baselines, demonstrating the effectiveness of adaptive memory management in mitigating forgetting while maintaining fairness.

## Method Summary
FeDMRA operates in a federated incremental setting where clients sequentially learn new classes/domains. The core innovation is a two-stage memory allocation mechanism. First, the server dynamically assigns each client a total exemplar budget per task (`m_c,t`) using a dual-channel importance score `b_c,t + d_c,t`. `b_c,t` captures the client's model update deviation from the global model (indicating contribution), while `d_c,t` measures the discrepancy between the client's class distribution and the global distribution (indicating data rarity). Second, within each client, the allocated budget is split across classes (`m_{y,c,t}`) proportionally to a blend of local and global class frequencies. Before training on a new task, each client selects exemplars for past classes by maintaining a personal information model (regularized toward the global model) and choosing samples with the largest gradient norms. The local model is then trained on new data mixed with these exemplars using a loss that combines classification (`L_CE`), knowledge distillation from the global model (`L_KL`), and an output norm penalty (`L_MG`) to stabilize learning.

## Key Results
- Under Dirichlet heterogeneity α=1.0, FeDMRA achieves state-of-the-art performance on FCDIL with 85.26% average accuracy (`Aavg`) and 83.35% last accuracy (`Alast`), significantly surpassing Re-Fed (80.74% `Aavg`, 67.72% `Alast`).
- Robustness holds under stronger heterogeneity (α=0.5), with FCDIL results of 83.57% `Aavg` and 85.79% `Alast`, confirming the effectiveness of dynamic allocation.
- Superior performance is reported across FCIL, FDIL, and FCDIL tasks on three hematology image datasets (Matek-19, Acevedo-20, HLwbc).

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Dynamic memory allocation based on dual-channel importance (client model deviation and data distribution) optimizes the use of limited exemplar storage across heterogeneous clients, thereby mitigating catastrophic forgetting.
- **Mechanism:** The server computes a client-level importance score combining the deviation of the client’s local model from the global model (`b_c,t`) and the alignment of the client’s class distribution with the global distribution (`d_c,t`). These scores are normalized to allocate a total memory budget `M` to each client. Within each client, class-level memory is allocated proportionally to a weighted blend of local and global class frequencies. This ensures clients that contribute more to global updates or have rare classes receive more memory for replay.
- **Core Assumption:** The magnitude of a client’s model update indicates its contribution to global knowledge, and the distribution discrepancy between a client and the global data reflects its need for additional replay memory to balance performance.
- **Evidence Anchors:**
  - [abstract]: "proposes a dynamic memory allocation strategy for exemplar storage based on the data replay mechanism. This strategy fully taps into the inherent potential of data heterogeneity, while taking into account the performance fairness of all participating clients"
  - [section]: Section 4.1, Equations (5)–(8) detail the dual-channel indices and allocation formulas.
  - [corpus]: Limited direct corpus evidence; neighboring works like Class-wise Balancing Data Replay (arXiv:2507.07712) address memory allocation with class-balancing heuristics but not dual-channel importance.
- **Break Condition:** If the Dirichlet heterogeneity is extreme (α very low), some clients may have negligible data for certain classes, leading to zero allocation for those classes and potential forgetting. Also, if model updates become uninformative (e.g., due to poor local training), the allocation may not reflect true contribution.

### Mechanism 2
- **Claim:** Selecting exemplars via a personal information model that is regularized towards the global model and ranking samples by gradient norms yields more representative and stable replay samples, which better preserve knowledge across tasks.
- **Mechanism:** Each client maintains a personal information model, initialized from the global model and updated on old data with an extra momentum-like term pulling it toward the global model. The gradient norm of each sample on this model is computed over several iterations; samples with larger gradient norms are selected for the exemplar set. This prioritizes samples that are more diagnostic for the old tasks.
- **Core Assumption:** Samples that induce larger gradients on the personal information model are more critical for maintaining performance on previous classes when replayed.
- **Evidence Anchors:**
  - [section]: Section 4.2, Equation (9) and the paragraph "Example Set Selection" describe the personal information model update and selection criterion.
  - [corpus]: Not directly addressed; corpus papers like Better Generative Replay (arXiv:2302.13001) focus on generating pseudo-samples rather than selecting real ones.
- **Break Condition:** If the personal information model overfits to the local old data due to strong heterogeneity, its gradient norms may not generalize to the global distribution, leading to suboptimal exemplars.

### Mechanism 3
- **Claim:** The composite client-side loss (cross-entropy + KL divergence with global model + L2 output penalty) simultaneously encourages adaptation to new tasks, preserves old knowledge via knowledge distillation, and stabilizes training, thus reducing catastrophic forgetting.
- **Mechanism:** `L_CE` minimizes classification error on new data. `L_KL` (KL divergence between local and global model outputs) distills knowledge from the global model, which has accumulated information from all clients and previous tasks, into the local model, preventing deviation from old knowledge. `L_MG` penalizes large output norms, which curbs excessive confidence and improves generalization.
- **Core Assumption:** Aligning local model outputs with the global model’s outputs on new data is an effective proxy for maintaining performance on old classes, and bounding output magnitudes prevents overfitting.
- **Evidence Anchors:**
  - [section]: Section 4.2, Equations (11)–(13) and the surrounding text define the losses and their intended effects.
  - [abstract]: Implicitly, the abstract mentions "optimization objectives to update the edge clients" and "mitigate catastrophic forgetting".
- **Break Condition:** If the global model has already degraded on old classes (e.g., due to poor aggregation), KL distillation may propagate poor knowledge. Also, the hyperparameter δ requires careful tuning; too large `L_MG` may hinder learning.

## Foundational Learning
- **Concept:** Federated Learning (FL)
  - **Why needed:** FeDMRA builds on FL where multiple clients collaboratively train a global model without sharing raw data. Non-IID data and communication constraints are central challenges addressed via dynamic memory allocation.
  - **Quick Check:** In standard FL, how is the global model updated from local client updates? (Answer: Typically via weighted averaging, e.g., FedAvg, with weights proportional to local data sizes.)
- **Concept:** Catastrophic Forgetting
  - **Why needed:** In incremental learning, models forget previously learned tasks when trained on new data. FeDMRA’s core goal is to mitigate this in a federated context using replay and regularization.
  - **Quick Check:** Why does catastrophic forgetting occur more severely in non-IID federated settings? (Answer: Clients have skewed class distributions, so fixed replay memory may not cover all classes adequately.)
- **Concept:** Memory Replay (Exemplar-based Continual Learning)
  - **Why needed:** FeDMRA uses replay where a subset of old samples (exemplars) is stored and mixed with new data during training. Dynamic allocation of this memory is the key innovation.
  - **Quick Check:** What is the typical exemplar set size in classic continual learning like iCaRL, and how is it usually allocated across classes? (Answer: Fixed budget, often equally per class or per sample set.)

## Architecture Onboarding
- **Component Map:**
  - **Server:** Receives local model updates and class distribution statistics from clients after each task; computes client-level importance scores (`b_c,t`, `d_c,t`) and allocates memory quotas (`m_c,t`) using Eq. (7); computes class-level allocations (`m_{y,c,t}`) using Eq. (8); broadcasts global model (aggregated via FedAvg) and memory quotas to clients.
  - **Client:** Maintains local dataset, exemplar cache (filled according to allocated `m_{y,c,t}`), and a personal information model; selects exemplars before training on a new task by computing gradient norms on the personal model and picking top `m_{y,c,t}` samples per class (Algorithm 2); trains local model on new data plus exemplars using loss `L_FINAL` (Eq. 13); uploads model parameters and class distribution to server.
- **Critical Path (per communication round/task):**
  1. Server sends global model `w_g,t-1` and memory quotas (from previous allocation) to clients.
  2. Clients fill exemplar sets based on quotas (if new task) using personal information model (steps 4–6 of Algorithm 2).
  3. Clients train on new task data `D_t` concatenated with exemplars, optimizing `L_FINAL` (Eq. 13). Update local model to `w_c,t`.
  4. Clients compute class distribution (counts per class in `D_t`) and send `w_c,t` + distribution to server.
  5. Server aggregates models via FedAvg to get `w_g,t`.
  6. Server computes new importance scores and allocates memory for next task (`m_{c+1,t}`, `m_{y+1,c,t}`).
  7. Repeat.
- **Design Tradeoffs:**
  - **Memory Overhead:** Each client must store personal information model and gradient norms temporarily; total exemplar memory is capped by `M`, but local computation increases.
  - **Communication Cost:** Sending class distribution adds O(|Y|) per client per round, negligible compared to model parameters.
  - **Fairness vs. Global Performance:** Allocating more memory to high-contribution clients improves global accuracy but may neglect low-contribution clients; the dual-channel design aims to balance.
  - **Stability of Allocation:** Frequent reallocation may cause variability; the paper uses allocation per task, a tradeoff between adaptability and stability.
- **Failure Signatures:**
  - **Memory allocation collapse:** If some clients receive near-zero memory for all classes (due to low `b_c,t` and `d_c,t`), monitor their old-class accuracy; a sharp drop indicates failure.
  - **Exemplar selection degradation:** If the personal information model diverges (e.g., its loss on old data increases), selected exemplars may be unrepresentative; check by sampling a few exemplars visually or via feature clustering.
  - **Training instability:** If `L_MG` weight δ is too high, training loss may not converge; if too low, forgetting occurs quickly (monitor per-class accuracy on validation set of old classes).
  - **Communication bottlenecks:** If uploading large models is problematic, consider compression; but the paper does not address this.
- **First 3 Experiments:**
  1. **Allocation correctness test:** Simulate a scenario with 2 clients, known class distributions, and known model update deviations. Feed these into the server’s allocation code and verify that `m_c,t` and `m_{y,c,t}` match manual calculations (using Eq. 7 and 8). This checks the math implementation.
  2. **Baseline comparison on small dataset:** Run FeDMRA and a fixed-memory baseline (e.g., equal per client) on FCIL-M with only 2 tasks (e.g., first two incremental steps). Compare `A_avg` and `A_last`. Expect FeDMRA to show improvement, confirming dynamic allocation benefits.
  3. **Ablation of loss components:** Train with (a) only `L_CE`, (b) `L_CE` + `L_KL`, (c) full loss (`L_CE+L_KL+δ L_MG`) on a simple FCIL task. Plot per-class accuracy over tasks to see the effect of each component on forgetting.

## Open Questions the Paper Calls Out
- **Open Question 1:** To what extent does FeDMRA's dynamic memory allocation generalize beyond blood cell classification datasets to other medical or non-medical federated incremental learning tasks?
  - **Basis:** The discussion (Appendix E) explicitly states reliance on a single dataset may limit generality; empirical validation is restricted to three hematology image datasets (Matek-19, Acevedo-20, HLwbc). Fundamental assumptions about dual-channel importance with different modalities/domain shifts remain untested.
  - **Resolution Evidence:** Systematic evaluation on diverse benchmark suites for federated continual learning (e.g., Split CIFAR-100, CORe50, multi-hospital clinical datasets) with varied heterogeneity levels (α) and task sequences (CIL, DIL, CDIL).
- **Open Question 2:** Does the proposed dynamic memory allocation actually improve fairness across clients in non-IID settings, or does it primarily optimize global average performance at the expense of worst-case client performance?
  - **Basis:** The abstract and introduction emphasize "performance fairness," but experiments report only average accuracy (`Aavg`) and last accuracy (`Alast`) without fairness-specific metrics (e.g., per-client accuracy variance, worst-client accuracy).
  - **Resolution Evidence:** Reporting per-client final accuracy distributions under different α, correlating allocated memory size (`m_c,t`) with client performance, and comparing fairness indices (e.g., Jain's index) against fixed-baseline replay.
- **Open Question 3:** Is the additive combination of client-level (`b_c,t`) and class-level (`d_c,t`) importance indices (Eq. 7) theoretically justified, or could a learned, non-linear fusion better balance model update deviation and data distribution heterogeneity?
  - **Basis:** The dual-channel metric uses a simple weighted sum. Hyperparameter sensitivity (Table 3) shows performance varies with settings, suggesting the fixed linear combination may be suboptimal across heterogeneity regimes.
  - **Resolution Evidence:** Ablation studies comparing linear vs. learned fusion mechanisms; sensitivity analysis on relative scaling of `b_c,t` and `d_c,t`; deriving a principled objective (e.g., game-theoretic) to guide fusion for maximizing a fairness-forgetting trade-off.
- **Open Question 4:** What is the precise interaction between the local regularization losses (`L_KL`, `L_MG`) and the dynamically allocated exemplar replay in preventing catastrophic forgetting—does dynamic memory reduce the burden on regularization, or are they complementary and redundant?
  - **Basis:** The ablation study (Table 4) shows both dynamic memory ("dy") and regularization components improve `Aavg` and `Alast`, but the joint effect is not decomposed. The relative contribution under different memory allocation schemes is unclear.
  - **Resolution Evidence:** Controlled experiments varying memory size independently of regularization strength, measuring per-task forgetting, and possibly visualizing decision boundary changes or gradient alignment between local and global models under different allocations.

## Limitations
- Exact client count `C` and Dirichlet sampling implementation for published results are unspecified; precise memory distribution per client is unclear.
- Architecture and training details of the "personal information model" used for exemplar selection (eq.9) are not elaborated, hindering replication.
- Allocation collapse under severe non-IID (α → 0) is not evaluated; risk of zero memory for some classes remains untested.
- No ablation isolating the dual-channel importance components (`b_c,t` vs. `d_c,t`) or comparing exemplar selection to alternatives (e.g., herding).
- Hyperparameter sensitivity (`α`, `λ`, `δ`) only partially explored; optimal values may vary across datasets.

## Confidence
- **Dual-channel dynamic memory allocation** (Mechanism 1): **Medium**. Equations seem sound and results indicate benefit, but break conditions under extreme heterogeneity untested; no isolation of channel contributions.
- **Personal information model exemplar selection** (Mechanism 2): **Medium**. Gradient-norm selection is novel but lacks comparison to simpler heuristics; overfitting of personal model is a noted risk.
- **Composite client loss** (Mechanism 3): **High**. Uses well-established KL distillation and output regularization; consistent improvements observed across tasks.

## Next Checks
1. **Allocation edge-case testing:** Simulate extreme α=0.1 and near-zero `b_c,t`; verify server equations (7)–(8) produce non-negative, proportional memory and that each class receives non-zero allocation when data exists.
2. **Ablation of importance channels:** On FCIL-M, run with only `b_c,t` or only `d_c,t` (set other to zero) at α=1.0 and 0.5. Compare `Aavg`/`Alast` to full dual-channel to quantify each channel’s marginal gain.
3. **Exemplar selection benchmark:** Replace gradient-norm selection with random sampling and with herding on fixed memory budget. Measure performance difference to isolate the contribution of the selection criterion beyond dynamic allocation.
