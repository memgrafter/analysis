# Frozen Policy Iteration: Computationally Efficient RL under Linear $Q^π$ Realizability for Deterministic Dynamics

## Quick Facts
- **arXiv ID**: 2603.00716
- **Source URL**: https://arxiv.org/abs/2603.00716
- **Reference count**: 40
- **Primary result**: Achieves minimax optimal regret $eO(\sqrt{d^2 H^6 T})$ and PAC sample complexity $eO(d^2 H^6 / \varepsilon^2)$ under linear $Q^π$ realizability with deterministic transitions, using a polynomial-time algorithm without simulator access.

## Executive Summary
This paper tackles online reinforcement learning under the linear $Q^π$ realizability assumption with deterministic transitions, stochastic rewards, and stochastic initial states. The proposed Frozen Policy Iteration (FPI) algorithm ensures computational efficiency by using only high-confidence trajectory segments and freezing policy updates for states where all actions are sufficiently covered by existing data. This keeps all data effectively on-policy. A multi-level accuracy scheme balances exploration and exploitation for regret minimization. FPI achieves minimax optimal regret and PAC sample complexity, closing a key computational-statistical gap. Empirical evaluation on CartPole-v1 and InvertedPendulum-v4 shows practical benefits of freezing, with polynomial time and space complexity.

## Method Summary
FPI operates in an online RL setting with an MDP having deterministic transitions and stochastic rewards. For each timestep $h$, the algorithm maintains a dataset $D_h$. At the start of episode $t$, it constructs a policy $\pi_t$: for a state $s$ at step $h$, if all actions $(s,a)$ are "covered" (i.e., their features lie within an elliptical confidence set derived from $D_{t,h}$), then $\pi_t(s)$ is the greedy action according to a least-squares estimate of $Q$ using only the "frozen" portion (first $k_t(s)$ samples) of $D_{t,h}$. Otherwise, an exploratory action is chosen. The agent executes $\pi_t$, collects a trajectory, and identifies the last step $h_t$ where $(s_{h_t}, a_{h_t})$ was uncovered. Only that pair, with the cumulative reward from $h_t$ onward, is added to $D_{h_t}$; all earlier data are discarded. For regret minimization (Algorithm 2), a multi-level accuracy controller adjusts the confidence radius across levels to dynamically trade off exploration and exploitation. Least-squares estimation uses ridge regularization ($\lambda = 10^{-3}$ in experiments). The algorithm uses tile-coded features (bounded $\|\phi\|_2 \leq 1$ after scaling).

## Key Results
- **Regret**: $eO(\sqrt{d^2 H^6 T})$, minimax optimal for linear bandits ($H=1$).
- **PAC sample complexity**: $eO(d^2 H^6 / \varepsilon^2)$.
- **Computational**: Polynomial time and space; no simulator required.
- **Empirical**: Freezing improves performance on CartPole-v1 and InvertedPendulum-v4.

## Why This Works (Mechanism)
FPI’s efficiency stems from two synergistic ideas:  
1. **On-policy data via high-confidence segments**: By only adding the last uncovered state-action pair from each trajectory, all stored data are guaranteed to be on-policy with respect to the policy that generated them. This eliminates distribution shift in policy evaluation.  
2. **Freezing updates for covered states**: Once a state has all its actions covered, its policy is fixed (greedy w.r.t. current Q-estimate) and never updated. This reduces variance in policy updates and focuses exploration on uncertain states.  
The multi-level accuracy scheme (Algorithm 2) further refines exploration: higher accuracy levels (smaller confidence radii) are activated as estimates become more precise, allowing the algorithm to gradually shift from exploration to exploitation. Linear $Q^π$ realizability enables efficient least-squares estimation, while deterministic transitions ensure that covering a state-action pair permanently reduces uncertainty for that pair.

## Foundational Learning
- **Linear $Q^π$ realizability**  
  *Why needed*: Assumes $Q^π(s,a) = \theta^\top \phi(s,a)$ for some $\theta$; enables linear regression for function approximation.  
  *Quick check*: Collect data under a exploratory policy; perform least-squares and verify low residual error on held-out data.

- **Deterministic transitions**  
  *Why needed*: Guarantees that visiting $(s,a)$ always leads to the same next state, simplifying confidence set construction and ensuring covering is monotonic.  
  *Quick check*: For fixed $(s,a)$, simulate multiple times; next state should be identical (ignoring reward noise).

- **High-confidence trajectory segments**  
  *Why needed*: Adding only the last uncovered pair keeps all data on-policy, avoiding off-policy bias in Q-estimation.  
  *Quick check*: Track which pairs are added; they should correspond to the first uncovered pair encountered when rolling out the current policy.

- **Freezing policy updates**  
  *Why needed*: Prevents unnecessary policy changes in well-explored states, reducing variance and computational overhead.  
  *Quick check*: Monitor states that become covered; their greedy action should remain fixed thereafter unless the dataset changes (which it doesn’t for covered states).

- **Elliptical confidence sets**  
  *Why needed*: For linear models, confidence bounds are naturally defined by $\|\phi(s,a)\|_{\Sigma^{-1}}$, where $\Sigma$ is the covariance matrix. This yields tight, adaptive uncertainty quantification.  
  *Quick check*: For a given $D_h$, compute $\Sigma_h = \lambda I + \sum_{(s,a)\in D_h} \phi(s,a)\phi(s,a)^\top$; check that $\sqrt{\phi(s,a)^\top \Sigma_h^{-1} \phi(s,a)}$ is the confidence radius.

- **Multi-level accuracy scheme**  
  *Why needed*: Allows adaptive control of exploration aggressiveness across different accuracy levels, improving regret guarantees.  
  *Quick check*: In Algorithm 2, the active level $l_h^{(t)}$ should increase as the confidence interval narrows, eventually using the finest level.

## Architecture Onboarding
Component map:
   Environment -> Trajectory -> FPI Agent -> Policy $\pi_t$
   FPI Agent:
     $D_h$ (per step h) -> Cover Check -> Policy Construction (greedy or exploratory)
     -> Least-Squares Estimator (frozen portion) -> $Q_t$
     -> Multi-level accuracy controller (Algorithm 2)

Critical path:
1. At episode start, for each step $h$ and encountered state $s$, evaluate $\text{Cover}(D_{t,h}, \varepsilon)$ for all $a \in \mathcal{A}$.
2. Construct $\pi_t$: if all actions covered, pick $\arg\max_a Q_t(s,a)$; else pick an uncovered action (exploratory).
3. Execute $\pi_t$ for $H$ steps, obtaining trajectory $(s_1,a_1,\dots,s_H,a_H)$ and rewards.
4. Find last $h_t$ such that $(s_{h_t},a_{h_t}) \notin \text{Cover}(D_{t,h_t}, \varepsilon)$ (using pre-update $D_{t,h_t}$). Add $(s_{h_t},a_{h_t}, \sum_{h=h_t}^H r_h)$ to $D_{h_t}$.
5. Update $Q_t$ for each $h$ using frozen portion of $D_h$ (first $k_t(s)$ samples for each $s$).
6. For Algorithm 2: adjust multi-level parameters $l_h^{(t)}$ and possibly $\varepsilon^{(l)}$.

Design tradeoffs:
- **Exploration vs. exploitation**: $\varepsilon$ controls covering; larger $\varepsilon$ increases exploration but may slow convergence. Theoretical scaling $\varepsilon = \Theta(H\alpha)$ involves constants not provided empirically.
- **Data efficiency vs. staleness**: Only one pair added per trajectory minimizes off-policy data but may delay learning if uncertain states occur early. Freezing avoids overwriting good estimates but may prevent recovery from early errors.
- **Memory vs. accuracy**: Storing all covariance matrices per step is costly; the paper stores only the last 20 per step, sacrificing some accuracy for memory.

Failure signatures:
- **Stagnant performance**: If $\varepsilon$ is too small, few states become covered, policy remains exploratory. Increase $\varepsilon$ or use a decay schedule.
- **Numerical instability**: Covariance matrices become ill-conditioned as $k$ grows. Ensure $\lambda > 0$ and monitor condition numbers; consider storing only recent data (as in paper).
- **High variance in regret (Algorithm 2)**: Frequent level switching indicates thresholds are too sensitive. Increase the number of levels $L$ or adjust $\Delta_l$.
- **Freezing too early**: If performance degrades after freezing, verify the covering condition is truly indicating sufficient coverage. In deterministic settings, a state should be covered only if all actions lie within the confidence ellipse.

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions for future work. However, based on its assumptions (linear $Q^π$ realizability, deterministic transitions) and limitations (narrow empirical evaluation, unspecified theoretical constants), several natural directions emerge:
- Extending FPI to stochastic transitions and/or nonlinear function approximation.
- Tightening the regret bounds' dependency on $d$ and $H$, or improving computational efficiency for larger problems.
- Conducting a more extensive empirical study across diverse environments (e.g., stochastic MDPs, continuous control with deep features).
- Clarifying the theoretical constants and their practical implications for hyperparameter tuning.

## Limitations
- Strong assumptions: linear $Q^π$ realizability and deterministic transitions may not hold in practice; robustness unexplored.
- Limited evaluation: only two simple benchmarks (CartPole, InvertedPendulum); no tests on stochastic transitions, continuous control, or deep features.
- Theoretical constants: precise values (e.g., $C$ in Theorem 1) and mapping from empirical $\varepsilon=1$ to theoretical $\tilde{\varepsilon} = \Theta(H\alpha)$ are unspecified, hindering hyperparameter selection.
- Computational analysis: polynomial claim assumes idealized operations; actual overhead of multi-level scheme not analyzed.

## Confidence
- **Polynomial time/space**: High – clearly follows from LS on finite datasets ($O(d^3)$ per step).
- **Regret/PAC bounds**: Medium – proofs provided but rely on undefined constants and strong realizability assumptions; limited empirical validation.
- **Freezing improves performance**: Medium – two experiments show gains, but benchmarks are narrow and sensitivity to $\varepsilon/\lambda$ not thoroughly tested.
- **Gap closure (without simulator)**: Medium – theoretical progress under narrow assumptions; practical impact restricted.

## Next Checks
1. Clarify and implement Algorithm 2 with explicit dataset management and action selection rules (especially $A^{(l)}_t(s)$ for $l=1$); validate regret scaling on a controlled linear $Q^π$ MDP where ground truth is known.
2. Perform systematic ablation over $\varepsilon$ to empirically determine its effect on coverage and regret, and compare to the theoretical $H\alpha$ scaling.
3. Test FPI on additional environments (e.g., Acrobot, stochastic variants) to assess generalizability and the robustness of freezing beyond the original deterministic benchmarks.
