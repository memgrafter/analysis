# GoAgent: Group-of-Agents Communication Topology Generation for LLM-based Multi-Agent Systems

## Quick Facts
*   **ArXiv ID:** 2603.19677
*   **Source URL:** https://arxiv.org/abs/2603.19677
*   **Reference Count:** 40
*   **Primary Result:** A group-centric topology generator for LLM-based multi-agent systems that achieves state-of-the-art accuracy (93.84% average) with ~17% lower token consumption than prior node-centric methods.

## Executive Summary
GoAgent introduces a paradigm shift from building multi-agent communication networks agent-by-agent to constructing them from predefined, collaborative groups. The method first uses an LLM to propose candidate groups relevant to the task. It then autoregressively selects and connects these groups, employing a Conditional Information Bottleneck (CIB) to prune redundant links and filter out noise from prior interactions. Evaluated on six standard benchmarks, this approach yields superior task accuracy and more efficient token usage, addressing core challenges of coordination overhead and communication noise in LLM-based multi-agent systems.

## Method Summary
GoAgent's process begins with an LLM-powered group enumeration phase. Given a task description, it generates a set of potential agent groups that could collaboratively address subtasks. Following this, a selection and connection phase iteratively builds the topology: at each step, it chooses the next most beneficial group to add and determines its connections to already-included groups. A key innovation is the Conditional Information Bottleneck (CIB), which dynamically evaluates the mutual information between a candidate connection and the remaining task context, filtering links that contribute mostly redundant or historical information. This results in a sparse, task-optimized communication graph where the fundamental unit is a coherent group rather than an individual agent.

## Key Results
*   Achieves 93.84% average accuracy across six benchmarks, setting a new state-of-the-art.
*   Reduces token consumption by approximately 17% compared to prior node-centric topology generation methods.
*   Demonstrates improved performance by explicitly modeling collaborative groups as atomic construction units and filtering communication noise.

## Why This Works (Mechanism)
The core innovation is the conceptual shift from a **node-centric** to a **group-centric** construction paradigm. By treating a pre-vetted, functionally coherent group as the atomic unit, GoAgent reduces the complexity of the search space for optimal topologies. It avoids the combinatorial explosion of considering every possible pairwise connection between individual agents. The Conditional Information Bottleneck (CIB) then acts as a precision filter on this group-level skeleton, removing links that do not carry novel, task-critical information. This two-stage process (group proposal, then filtered connection) efficiently builds a communication structure that is both semantically meaningful (via groups) and parsimonious (via CIB).

## Foundational Learning
*   **Group-Centric Construction:** Treating a set of agents as a single, functionally inseparable unit for topology design. *Why needed:* Reduces search space complexity and ensures connectivity is proposed for semantically relevant clusters. *Quick check:* Does the method's search space scale with number of candidate groups (G) rather than agents (A), where G << A?
*   **Conditional Information Bottleneck (CIB):** A technique to select connections that maximize information about the task goal while minimizing irrelevant or redundant information (e.g., historical chat). *Why needed:* To combat noise and redundancy in multi-agent dialogue, improving efficiency without losing critical coordination signals. *Quick check:* Is the objective function `I(connection; task | context)` or similar, where context includes prior history?
*   **Autoregressive Topology Building:** Constructing the graph sequentially by adding one group at a time and deciding its connections. *Why needed:* Allows for dynamic, context-aware decisions where the value of a new connection depends on the existing partial graph. *Quick check:* Is the graph built in a fixed number of steps equal to the number of selected groups?
*   **LLM as Group Proposer:** Using a large language model's world knowledge and reasoning to hypothesize which agent combinations are relevant for a given task. *Why needed:* Manual definition of all potential groups for open-ended tasks is infeasible; the LLM provides a flexible, task-aware prior. *Quick check:* Is the group enumeration prompt free-form, asking for "groups that could collaborate on [task]"?
*   **Communication-Efficient MAS:** Designing multi-agent systems where the volume of inter-agent messaging is minimized while preserving or enhancing performance. *Why needed:* LLM inference costs are token-bound; reducing communication directly lowers monetary cost and latency. *Quick check:* Is the primary efficiency metric total tokens exchanged between agents during task execution?
*   **Topology Generation:** The algorithmic problem of automatically determining *which* agents communicate *with whom* in a multi-agent system. *Why needed:* A poorly connected topology leads to failure (isolated agents) or waste (over-communication). *Quick check:* Does the method output a graph (adjacency matrix or edge list) defining the communication channels?

## Architecture Onboarding
**Component Map:** Task Description -> LLM GroupEnumerator -> Candidate Groups Pool -> GroupSelector (autoregressive) + CIB Filter -> Selected Group & Connection Decisions -> Final Communication Topology -> Task Execution by Agent Groups.

**Critical Path:** The main execution flow is: (1) Enumerate candidate groups, (2) Initialize empty topology, (3) Loop: select next best group from pool via scoring function, (4) For that group, evaluate potential connections to existing groups using CIB, (5) Add group and accepted connections to topology, (6) Repeat until stopping criterion.

**Design Tradeoffs:** 
*   **Scalability vs. Optimality:** LLM-based enumeration is flexible but may miss optimal groups for complex tasks; exhaustive search is optimal but intractable.
*   **CIB Strength vs. Information Loss:** A very tight information bottleneck maximizes token savings but risks filtering out weak but necessary signals; a loose bottleneck saves fewer tokens.
*   **Autoregressive Greediness vs. Global Optimum:** The sequential, myopic selection of groups may lead to suboptimal global topologies compared to a full-graph optimization.

**Failure Signatures:**
*   **Group Enumeration Failure:** Candidate pool contains no groups relevant to the core task, leading to a topology that cannot solve the problem.
*   **CIB Filter Misconfiguration:** Bottleneck hyperparameter (e.g., β) set too high, causing critical coordination links to be pruned, resulting in agent groups working at cross-purposes.
*   **Selection Stagnation:** The scoring function repeatedly selects the same type of group or fails to incorporate new group types, leading to a homogenous and ineffective topology.

**First 3 Experiments:**
1.  **Reproduce Baseline Results:** Run GoAgent on the six reported benchmarks using the exact paper's prompts, LLM, and CIB parameters to verify the 93.84% accuracy and 17% token reduction claims.
2.  **Ablation - Group Enumeration Source:** Replace the LLM-based group enumerator with a simple, exhaustive list of all possible agent pairs/triplets (for small-scale tests). Measure the performance delta to isolate the benefit of learned group proposals.
3.  **Ablation - CIB On/Off:** Disable the Conditional Information Bottleneck filter, allowing all candidate connections. Compare accuracy and token consumption against the full GoAgent to directly measure the CIB's contribution to efficiency and potential information loss.

## Limitations
*   **Scalability of Group Enumeration:** LLM-based enumeration of task-relevant groups may fail for complex, open-ended, or dynamically evolving tasks where the optimal group structure is unknown.
*   **Sensitivity of CIB Filtering:** The effectiveness and parameter sensitivity of the Conditional Information Bottleneck for redundancy filtering across diverse noise profiles require further validation.
*   **Benchmark Generalizability:** Evaluation is limited to six academic/standard benchmarks; performance on real-world, long-horizon, or highly ambiguous tasks remains unproven.

## Confidence
*   **Novel Group-Centric Formulation:** Medium. The conceptual shift is clear and justified, but its practical boundaries need broader testing.
*   **Reported Accuracy Improvement (~93.84% avg):** Medium. Specific to the reported experimental setup; reproducibility and generalizability are unverified.
*   **Reported Communication Efficiency (~17% token reduction):** Low. Highly dependent on baseline implementations, CIB parameters, and task nature; the mechanism's net benefit requires closer scrutiny.
