# On Linear Separability of the MNIST Handwritten Digits Dataset

## Quick Facts
- **arXiv ID:** 2603.12850
- **Source URL:** https://arxiv.org/abs/2603.12850
- **Reference count:** 25
- **Primary result:** The MNIST dataset is not universally linearly separable; separability depends critically on the specific binary task (pairwise vs. one-vs-rest) and the data subset (training, test, or combined).

## Executive Summary
This paper empirically investigates the long-standing debate over whether the MNIST handwritten digits dataset is linearly separable. By formulating linear separability as a convex feasibility problem—a linear program with a constant objective—the authors systematically tested all pairwise (45) and one-vs-rest (10) binary classification tasks across the standard MNIST training set (60,000 samples), test set (10,000 samples), and their combination. Using the CVXPY library with the CLARABEL solver, they determined feasibility based on the solver’s status. The results reveal that separability is not a monolithic property: on the full training set, seven specific digit pairs (2–3, 2–8, 3–5, 3–8, 4–9, 5–8, 7–9) are non-separable, and no one-vs-rest task is separable. The combined set mirrors these outcomes. The smaller test set shows all pairwise pairs separable but mixed one-vs-rest results (digits 0–4, 6, and 7 separable; 5, 8, 9 not). The study concludes that claims about MNIST’s linear separability must always be qualified by the exact binary task and data partition considered.

## Method Summary
The authors cast linear separability as a linear programming feasibility problem: given binary labels \(y_i \in \{-1, +1\}\) and feature vectors \(x_i\) (flattened 28×28 pixel values), they seek \(w, b\) such that \(y_i (w^T x_i + b) \ge 1\) for all samples. This is implemented in CVXPY as `cp.Problem(cp.Minimize(0), [cp.multiply(y, X @ w + b) >= 1])`. The solver’s status (`OPTIMAL` vs. `INFEASIBLE`) directly indicates separability. Experiments cover all 45 pairwise and 10 one-vs-rest tasks on the training set, test set, and their concatenation. No feature scaling or additional preprocessing is mentioned; raw integer pixel values (0–255) are used. The CLARABEL solver is auto-selected by CVXPY. Execution time is recorded as a secondary metric.

## Key Results
- **Training set (60k):** Seven digit pairs are non-separable (2–3, 2–8, 3–5, 3–8, 4–9, 5–8, 7–9); all one-vs-rest tasks are non-separable.
- **Combined set (70k):** Mirrors the training set outcomes.
- **Test set (10k):** All pairwise pairs are separable; one-vs-rest results are mixed—digits 0–4, 6, and 7 are separable, while 5, 8, and 9 are not.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Linear separability of a two-class dataset can be definitively tested by formulating it as a convex feasibility problem.  
**Mechanism:** The condition \(y_i(w^T x_i + b) \ge 1\) for all samples is expressed as a linear program with a constant objective (minimize 0). The existence of a feasible solution \((w, b)\) is mathematically equivalent to the existence of a separating hyperplane. Modern interior-point solvers (e.g., CLARABEL) return a certificate of either optimality (feasible) or infeasibility.  
**Core assumption:** The solver’s returned status is reliable and numerically sound for the given problem size and formulation.  
**Evidence anchors:** The paper explicitly describes the LP formulation (Eq. 2) and CVXPY implementation, using `p.status` as the direct decision criterion. The corpus does not challenge this approach.  
**Break condition:** Solver failure to converge to a definitive status (e.g., `USER_LIMIT`, `NUM_ERROR`) or numerical instability in large, high-dimensional problems could invalidate the verdict.

### Mechanism 2
**Claim:** The linear separability of a complex multi-class dataset like MNIST is not a monolithic property but depends critically on the specific binary task (pairwise vs. one-vs-rest) and the exact data subset (train, test, combined).  
**Mechanism:** By decomposing the 10-class problem into 45 independent pairwise binary tasks and 10 one-vs-rest tasks, and repeating on three distinct partitions, the study generates a matrix of outcomes. This reveals that separability varies across configurations because the geometry of each binary subset differs.  
**Core assumption:** Separability of a specific binary subset is an intrinsic property of its feature-label distribution, independent of other tasks.  
**Evidence anchors:** Result tables (1–3, 6–8) show clear patterns: training set has non-separable pairs and no one-vs-rest successes; test set shows all separable pairs but partial one-vs-rest.  
**Break condition:** If the standard train/test split were adversarially or non-randomly constructed, the observed dependency might be an artifact. The paper uses the widely accepted split.

### Mechanism 3
**Claim:** Execution time of the LP feasibility solve correlates with the underlying geometric difficulty (separability) of the dataset, providing a secondary proxy indicator.  
**Mechanism:** Intuitively, when classes are nearly inseparable or have complex, intermingled boundaries, the convex optimization problem is harder for the interior-point solver, leading to longer solution times. Non-separable cases in the larger training set consistently took 15.9–24.7 seconds, while separable test pairs solved in 0.6–2.0 seconds.  
**Core assumption:** Solver iteration count and time are primarily determined by the point cloud geometry, not random variance or hardware noise, within a fixed formulation.  
**Evidence anchors:** Tables 5 and accompanying text explicitly compare execution times, noting longer times for non-separable cases.  
**Break condition:** This correlation may not hold for different solvers, problem formulations (e.g., QP for maximum margin), or if non-separability is “easy” to prove. Timing is indicative, not definitive.

## Foundational Learning
**Concept: Linear Separability & Separating Hyperplane**  
*Why needed:* It is the core property being investigated. Understanding the formal definition (\(w^T x + b = 0\), sign constraints) is essential to grasp what the LP tests.  
*Quick check:* If you have two classes of points in 2D that are perfectly mixed (like two interleaved crescents), can a single straight line separate them? What about two distinct clusters?

**Concept: Convex Optimization & LP Feasibility**  
*Why needed:* This is the computational engine. The candidate must understand that a feasibility LP is a special case of convex optimization where the objective is constant, and the solver’s job is purely to satisfy constraints or prove none exist.  
*Quick check:* What is the difference between a feasible LP (solution exists) and an optimal LP (solution found that minimizes an objective)? Why is the former sufficient for testing separability?

**Concept: Dataset Partitioning & Task Definition (Pairwise vs. One-vs-rest)**  
*Why needed:* The paper’s main finding is that the answer to “Is MNIST linearly separable?” is meaningless without specifying the binary task and data subset. This concept is key to interpreting the results matrix correctly.  
*Quick check:* For digit ‘5’, what does “pairwise separability with 3” mean? What does “one-vs-rest separability for 5” mean? How do the training samples for these two tasks differ?

## Architecture Onboarding
Component map: **Data Loader** -> **Task Generator** -> **CVXPY Model Builder** -> **Solver Orchestrator** -> **Result Aggregator**  
Critical path: The solver call is the single expensive operation; all other steps (data slicing, model construction) are negligible. Path: load data -> slice for binary task -> build & solve LP -> interpret status.  
Design tradeoffs:  
- **Solver choice:** CLARABEL (default) vs. other interior-point solvers (e.g., SCS, ECOS); trade-off between speed and robustness on large (60k×784) problems.  
- **Problem formulation:** Using `min 0` (pure feasibility) is faster and more direct than `min ||w||^2` (hard‑margin SVM), which solves a QP and returns a hyperplane but is unnecessary for a yes/no answer.  
Failure signatures:  
1. `p.status` not in `[OPTIMAL, INFEASIBLE]` (e.g., `USER_LIMIT`, `NUM_ERROR`).  
2. Solver crashes on large problems (training/combined sets).  
3. Wildly inconsistent solve times for the same task across runs (non‑determinism or resource contention).  
First 3 experiments:  
1. **Reproduce Table 1 (Training Pairwise)** – For digit pair (2,3), load `X_train, y_train`, encode labels as ±1, run LP. Expect `p.status == INFEASIBLE` and time ~20 s.

## Open Questions the Paper Calls Out
1. **Discrepancy in one‑vs‑rest separability between training and test sets**  
   The paper reports that all one‑vs‑rest tasks are non‑separable on the training set, but some (digits 0–4, 6, 7) are separable on the test set. It attributes this to sample size but does not investigate whether the difference stems from random sampling variation, inherent distributional shifts, or overfitting to a smaller set. No hypothesis testing or cross‑validation is performed to assess statistical reliability.  
   *Resolution:* Conduct permutation tests comparing class distributions between splits; repeat on multiple random splits to evaluate separability stability as sample size varies.

2. **Comparison of linear separability testing methods**  
   The paper only loosely compares its LP approach with Zhong et al.’s minimum enclosing ball (MEB) method (which was unavailable for full testing) and dismisses LIBSVM as approximate. It does not implement or benchmark other theoretically sound methods (e.g., convex hull intersection) on the full MNIST dataset.  
   *Resolution:* Implement and benchmark multiple separability algorithms (LP, MEB, convex hull) on identical MNIST subsets, measuring agreement on separable/non‑separable cases and runtime, especially for high‑dimensional (784‑pixel) inputs.

3. **Geometric explanation for non‑separable digit pairs**  
   The paper empirically identifies seven non‑separable pairwise combinations (2–3, 2–8, 3–5, 3–8, 4–9, 5–8, 7–9) and notes that digits 0, 1, and 6 are separable from all others. It references a prior linear separability degree ranking but offers no analysis of why these patterns exist—e.g., whether they relate to digit shape similarities, feature correlations, or manifold overlaps.  
   *Resolution:* Perform geometric and statistical analysis of pixel‑space distributions for non‑separable vs. separable pairs: compute inter‑class Mahalanobis distances, visualize class clusters in reduced dimensions, or train a linear model to extract distinguishing features.

## Limitations
- Solver configuration (tolerances, iteration limits) is not explicitly reported, which may affect borderline feasibility decisions.
- The paper does not state whether pixel values were normalized; scaling influences LP condition numbers and could change separability outcomes.
- Results rely on the standard MNIST train/test split; a different random split might alter patterns, especially for the smaller test set where all pairwise pairs were separable.
