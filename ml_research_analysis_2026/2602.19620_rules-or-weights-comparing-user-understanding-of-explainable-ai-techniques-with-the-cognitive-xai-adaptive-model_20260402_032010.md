# Rules or Weights? Comparing User Understanding of Explainable AI Techniques with the Cognitive XAI-Adaptive Model

## Quick Facts
- **arXiv ID:** 2602.19620
- **Source URL:** https://arxiv.org/abs/2602.19620
- **Reference Count:** 40
- **Primary Result:** CoXAM, a cognitive computational rationality model, explains human interpretation of rule-based and weight-based XAI better than standard ML proxies by adapting reasoning strategies to trade off decision utility against cognitive effort.

## Executive Summary
This study introduces the Cognitive XAI-Adaptive Model (CoXAM) to address the lack of a cognitive framework for comparing linear (weight-based) and rule-based (decision tree) XAI techniques. CoXAM models users as adaptive agents who select reasoning strategies—like feature attribution or tree traversal—by balancing expected decision utility against mental effort, using a shared memory architecture (ACT-R chunks) for both XAI types. In a validation study with 340 participants, CoXAM achieved a superior fit to human responses compared to three machine learning proxy models. Key findings include that counterfactual tasks are harder than forward prediction, rules are harder to recall than weights, and the helpfulness of an XAI schema depends on the underlying data structure (weights better for Wine Quality, rules for Mushrooms). The model also identifies feature attribution as an effective strategy for larger attribute values, while the availability heuristic consistently performed poorly.

## Method Summary
CoXAM is a computational rationality framework where a reinforcement learning controller selects from seven elicited reasoning strategies (three forward, four counterfactual) to maximize a value function `V(s) = U(correct decision) - γ * E[time]`. A shared declarative memory store, based on ACT-R chunks, encodes both weight factors and decision tree nodes, enabling flexible cross-schema reasoning. Forward strategies use a drift-diffusion model (DDM) to generate choice probabilities and times; counterfactual strategies produce attribute changes. The model was fitted to human trial-by-trial data from a summative study involving two tabular datasets (Mushroom, Wine Quality), with and without XAI. Cognitive parameters (retrieval threshold `κ`, opportunity cost `γ`, noise `ν`, margin `ε`) were optimized per participant to minimize negative log-likelihood of human choices, and compared against baseline proxies (KNN, Decision Tree, Linear Regression) using NLL and BIC.

## Key Results
- CoXAM provided the best fit to human decisions (lowest NLL, BIC) among all compared models, including ML proxies.
- Counterfactual simulation tasks were consistently more difficult than forward prediction tasks.
- Rule-based explanations were harder for users to recall and use accurately compared to weight-based ones.
- The effectiveness of an XAI schema was context-dependent: weights aided understanding for the Wine Quality dataset, while rules were more helpful for the Mushroom dataset.
- Strategy analysis revealed that the Feature Attribution strategy outperformed Approximate Calculation for attributes with larger values, and the Availability Heuristic was the least effective reasoning approach.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Human strategy selection for XAI interpretation optimizes a trade-off between decision utility and cognitive effort (time).
- **Mechanism:** CoXAM uses computational rationality. For each candidate reasoning strategy `s`, it computes a Value `V(s) = U(correct decision) - γ * E[time]`, where `γ` is an opportunity-cost parameter. The controller (an RL agent) selects the strategy with the highest expected Value based on current cognitive parameters and task context.
- **Evidence anchors:**
  - [abstract] "CoXAM employs computational rationality to choose among reasoning processes based on the trade-off in utility and reasoning time."
  - [section 5.4.3] Formal definition of `V(s)` and the controller's reinforcement learning setup.
- **Break condition:** The mechanism fails if users are insensitive to time costs or if utility is not primarily defined by single-trial correctness (e.g., in learning tasks).

### Mechanism 2
- **Claim:** A unified, shared memory architecture (ACT-R chunks) can encode both weight-based (linear factors) and rule-based (decision tree nodes) XAI schemas, enabling flexible strategy use.
- **Mechanism:** Different information types are stored as declarative memory chunks. Retrieval cues (e.g., attribute name) access these chunks, with activation increasing with use. This allows the same cognitive machinery to support strategies for both XAI types.
- **Evidence anchors:**
  - [section 5.1] Detailed description of chunk types for Weights and Rules.
  - [section 5.2.1 & 5.2.3] Implementation of forward strategies that access these common memory structures.
- **Break condition:** The mechanism fails for XAI schemas not decomposable into discrete symbolic chunks (e.g., saliency maps) or if users process rules and weights in fundamentally different memory systems.

### Mechanism 3
- **Claim:** The strategy controller's pre-training on auxiliary datasets provides inductive biases about strategy efficacy that generalize to new XAI tasks.
- **Mechanism:** The RL controller (PPO) is pre-trained on several tabular datasets to learn general priors about strategy performance. During a target task, it starts with these priors and updates its policy based on trial outcomes.
- **Evidence anchors:**
  - [section 5.4.4] "We therefore first pre-train the controller on several auxiliary tabular datasets to learn general priors about strategy success rates and timing."
  - [section 7.1 & 7.3] Model fitting results show CoXAM successfully predicts human decisions across different datasets and XAI schemas.
- **Break condition:** Pre-training fails if auxiliary datasets are too dissimilar from the target task in structure (e.g., all linear) or if humans do not transfer strategy priors across domains.

## Foundational Learning

### Concept: Computational Rationality (Bounded Optimality)
- **Why needed here:** It is the theoretical foundation for CoXAM's strategy selection. Without understanding that human cognition optimizes a utility-time trade-off rather than pure accuracy, the model's core Value function and controller design would not make sense.
- **Quick check question:** What two components are combined in the Value function `V(s)` to determine strategy choice, and what parameter controls their relative weighting?

### Concept: ACT-R Declarative Memory
- **Why needed here:** CoXAM's memory module is directly built on ACT-R's chunk retrieval model. Understanding activation (`ln(n_i / ∏Δ t_ij) - mismatches + noise`) and retrieval threshold `κ` is essential to grasp how facts about XAI are stored, forgotten, and recalled, which fundamentally limits or enables each reasoning strategy.
- **Quick check question:** How does the memory chunk for a decision tree threshold differ from one for a linear factor in terms of retrieval cues and potential for interference?

### Concept: The Seven Elicited Reasoning Strategies
- **Why needed here:** These are the concrete behavioral units the model simulates. Knowing the distinctions (e.g., Approximate Calculation vs. Feature Attribution; Root vs. Leaf Threshold Crossing) is necessary to interpret CoXAM's strategy selection outputs and understand *why* certain XAI-dataset combinations work better.
- **Quick check question:** Which two strategies are common across both forward and counterfactual simulation tasks, and what key mental shortcut distinguishes their "inverse" forms?

## Architecture Onboarding

- **Component map:** Input Interface -> Memory Store (ACT-R Chunks) -> Strategy Controller (RL Agent) -> Strategy Implementations (7 modules) -> Computational Rationality Module -> Output. For Feature Attribution, a parallel Parameter Update step modifies Gaussian beliefs.
- **Critical path:** Input arrives -> Memory retrieves relevant chunks -> Controller selects `(strategy s, effort a, subset X, depth d)` based on state -> Strategy executes, computes evidence `e`, and produces decision/choice -> DDM (forward) or explicit timing (counterfactual) -> Value `V(s)` calculated -> Reward returned to controller.
- **Design tradeoffs:**
  - **Generic DDM vs. Specialized Models:** A single drift-diffusion process simplifies implementation but may not capture strategy-specific decision noise perfectly.
  - **Pre-training Scope:** Training on only four auxiliary datasets limits breadth; a more diverse corpus could improve generalization but increases cost.
  - **Strategy Granularity:** The seven strategies are parsimonious but may not capture all nuances for complex XAI schemas.
  - **Static XAI vs. Adaptive User:** CoXAM assumes a static, global explanation; it does not model dynamic user requests or interactive sense-making.
- **Failure signatures:**
  - **Poor Model Fit:** High NLL/BIC compared to baselines indicates inability to reproduce human choices.
  - **Strategy Mismatch:** Controller's selected strategy distribution is inconsistent with qualitative findings from the formative study.
  - **Parameter Sensitivity:** Results are highly sensitive to `γ`, `κ`, `ν`/`ε`. Implausible values (e.g., near-zero retrieval failures) signal misspecification.
  - **Dataset Shift:** Performance degrades on datasets with more attributes, non-linear interactions beyond tree depth, or different distributions than pre-training set.
- **First 3 experiments:**
  1.  Replicate key empirical findings: Run CoXAM on Wine Quality and Mushrooms. Verify it reproduces (a) lower forward accuracy for Rules vs. Weights (without XAI), (b) counterfactual tasks being harder than forward, (c) context-dependent XAI effectiveness (Weights better for Wine, Rules for Mushrooms).
  2.  Analyze strategy selection: Inspect the controller's policy. Does it prefer Feature Attribution for Wine Quality (large attribute values) and Approximate Calculation for Mushrooms (smaller values)? Compare strategy prevalence to human data (Fig. 7, 10).
  3.  Test cognitive parameter sensitivity: Vary `γ`, `κ`, `ν`/`ε`. Confirm increasing `γ` leads to smaller `X` (fewer attributes) and lower accuracy. Check higher `κ` harms Rule-based strategies more than Feature Attribution. Validate larger `ε` (margin) improves counterfactual success.

## Open Questions the Paper Calls Out
- **Question 1:** How do different topological representations of rule-based XAI (e.g., Rule Lists, Decision Sets) affect user reasoning strategies compared to decision trees, and can CoXAM’s shared memory framework be extended?
  - **Basis:** [explicit] CoXAM converts rules to DNF, neglecting parsing topology differences (Section 8.3.1).
  - **Why unresolved:** Only decision trees evaluated; other formats may engage distinct cognitive processes.
  - **Resolution evidence:** A user study comparing formats with think-aloud protocols; extend CoXAM with format-specific chunks and traversal heuristics; fit to new strategy data.
- **Question 2:** How do visual encoding choices in XAI interfaces (e.g., lollipop charts vs. tables) influence strategy effectiveness, and can CoXAM be enhanced with a visual attention module?
  - **Basis:** [explicit] Study used fixed tabular UI; future work should integrate "how users read popular XAI visualizations" (Section 8.3.2).
  - **Why unresolved:** Visual design may bias attention and alter memory/strategy, but CoXAM assumes purely symbolic parsing.
  - **Resolution evidence:** An experiment manipulating visual encodings, measuring eye-tracking and strategy use. Integrate a computational rationality model of visual attention into CoXAM.
- **Question 3:** Beyond simulation accuracy, how do XAI schemas impact trust, satisfaction, or collaborative decision-making, and can CoXAM’s framework model these?
  - **Basis:** [explicit] Evaluation omits other goals like "trust, satisfaction and robustness" (Section 8.5).
  - **Why unresolved:** CoXAM optimizes for decision utility and time; user experience metrics involve affective/social factors not currently modeled.
  - **Resolution evidence:** Extend the Value function with terms for trust calibration or satisfaction. Collect subjective ratings in a study and fit extended CoXAM to predict both performance and self-reports.
- **Question 4:** How accurately does CoXAM’s memory model capture real user recall errors for rule-based explanations, especially for deeper trees, and might retrieval failures bias counterfactual reasoning?
  - **Basis:** [inferred] Formative study noted recall errors; summative study's fixed order may have minimized memory load.
  - **Why unresolved:** Retrieval threshold tunes overall failure rates but not content-specific errors (e.g., attribute swaps). Memory improvement with use may not capture interference.
  - **Resolution evidence:** A study isolating memory effects with recall probes after delays, varying tree depth and attribute similarity. Fit parameters to explicit recall data, analyze if systematic errors predict counterfactual inaccuracy.
- **Question 5:** Does pre-training on only four auxiliary tabular datasets introduce dataset-specific priors that limit generalization to novel distributions (e.g., higher cardinality), and how can the prior be made more robust?
  - **Basis:** [inferred] Controller pre-trained on "several auxiliary tabular datasets"; authors admit limited corpus may embed specific priors (Section 8.6).
  - **Why unresolved:** Strategy selection might be tailored to statistical properties of pre-training data; performance may degrade on different domains.
  - **Resolution evidence:** Evaluate CoXAM on new datasets with diverse characteristics (more attributes, mixed types) without retraining. If performance drops, augment pre-training with broader datasets or use meta-learning for a more adaptable prior.

## Limitations
- Missing per-condition strategy probabilities, PPO controller details (architecture, state, auxiliary data), and baseline smoothing parameters (`α`) prevent full replication and fair comparison.
- Individual cognitive parameters (`κ`, `γ`, `ν`, `ε`) were not released; their ranges and psychological plausibility are unknown.
- The strategy set of seven types may omit important reasoning variants, especially for more complex or visually presented XAI.

## Confidence
- **Computational rationality mechanism:** Medium – aligns with trade-off theory but no direct manipulation validates the assumed balance.
- **Unified memory representation:** Medium – ACT-R implementation is plausible, but no alternative memory architectures were tested.
- **Pre-training transfer generality:** Low – auxiliary datasets are undisclosed; no ablation demonstrates the necessity of pre-training.
- **Empirical adequacy (fit superiority):** Medium – pattern replication is high (direct descriptive), but fit superiority is medium due to missing baseline implementation details.

## Next Checks
1.  **Full controller replication:** Obtain the pre-trained PPO policy and state representation. Run CoXAM with its adaptive controller (no fixed strategy mixture) on the study data. Compare NLL/BIC and strategy distributions to the fixed-mixture approximation used in this report.
2.  **Pre-training ablation:** Train the RL controller from scratch on only the Wine and Mushroom datasets (no auxiliary data). Compare model fit and strategy diversity to the pre-trained model to quantify the contribution of pre-training.
3.  **Parameter plausibility and sensitivity:** Re-fit individual cognitive parameters (`κ`, `γ`, `ν`, `ε`) with tighter, psychologically grounded bounds (e.g., `κ` ∈ [0.5, 1.5]). Analyze the distribution of fitted values and perform a sensitivity analysis to ensure results are not driven by implausible parameter extremes.
