# Enhancing Post-Training Quantization via Future Activation Awareness
## Quick Facts
- **arXiv ID:** 2602.02538
- **Source URL:** https://arxiv.org/abs/2602.02538
- **Reference count:** 0
- **Primary result:** FAQ improves PTQ for LLMs by fusing current and future activations, reducing calibration sensitivity and boosting accuracy, especially at low bits (e.g., 3-bit).

## Executive Summary
Post-training quantization (PTQ) compresses large language models without fine-tuning, but current methods use only present-layer activations, leading to bias and error accumulation. This paper introduces Future-Aware Quantization (FAQ), which incorporates a lightweight preview of future-layer activations to guide weight quantization. By fusing current activations with a window-wise average of subsequent layers, FAQ reduces sensitivity to calibration data and preserves critical weights. Evaluations on models like Qwen3 and LLaMA show consistent improvements over RTN and AWQ, with notable gains at aggressive bit-widths and lower variance across calibration sets, all with negligible overhead.

## Method Summary
FAQ enhances PTQ by augmenting the activation distribution used to compute quantization scales. For each layer, during calibration, it collects the current-layer activations \(a_i\) and computes a preview \(a_{pvw_i}\) as the average of activations from the next \(j\) layers. These are fused via \(\tilde{a}_i = \gamma a_i + (1-\gamma)a_{pvw_i}\), with fixed hyperparameters \(\gamma=0.85\) and \(j=3\). The base scale \(s_i\) is derived from \(\tilde{a}_i\), and a per-channel multiplier \(c_i\) is optimized via grid search on calibration data to minimize reconstruction loss, without backward passes or data reconstruction. This approach introduces minimal computational cost while mitigating quantization bias from noisy or biased calibration data.

## Key Results
- On Qwen3-8B (4-bit), FAQ boosts ARC accuracy from 0.4778 to 0.5043 and PIQA from 0.7459 to 0.7535 over AWQ.
- On Qwen2.5-0.5B (3-bit), FAQ lowers WikiText2 perplexity from 29.13 to 25.96.
- FAQ exhibits lower variance in performance across varying calibration set sizes, enhancing robustness.

## Why This Works (Mechanism)
FAQ reduces quantization bias by considering future-layer activation statistics. Standard PTQ uses only current-layer activations, which may be unrepresentative or noisy, especially with limited or biased calibration data. Future activations provide a smoother, more global view of the forward pass, helping to preserve weights that are important for subsequent layers. The window-wise preview acts as a regularizer, preventing overfitting to instantaneous activation patterns. The fixed fusion factor \(\gamma\) and small window size \(j\) ensure that the preview is informative yet computationally cheap, avoiding error propagation while compensating for calibration imperfections. This leads to more robust quantization scales and lower variance in downstream task performance.

## Architecture Onboarding
**Component Map:**  
Calibration Dataset -> Forward Pass -> Current Activations \(a_i\) and Future Activations \(a_{l+1},...,a_{l+j}\) -> Window Average \(a_{pvw_i}\) -> Fusion \(\tilde{a}_i = \gamma a_i + (1-\gamma)a_{pvw_i}\) -> Base Scale \(s_i\) -> Grid Search for Multiplier \(c_i\) -> Quantized Weight \(Q(W_i, s_i c_i)\)

**Critical Path:**  
The process flows from loading calibration data, running a forward pass to capture activations for all layers, computing the preview for each layer by averaging next \(j\) layers' activations, fusing with current activations, deriving scale, and optimizing per-channel multiplier via grid search on reconstruction loss. Final quantized weights replace original weights for inference.

**Design Tradeoffs:**  
- Fixed hyperparameters (\(\gamma, j\)) vs. per-model tuning: fixed values reduce search overhead but may not be optimal for all architectures.
- Preview window size: larger \(j\) incorporates more context but risks noise from distant layers; small \(j\) is cheaper but less robust.
- Fusion simplicity: linear fusion is efficient but may not capture non-linear relationships between layers.

**Failure Signatures:**  
- Performance drop if preview layers are incorrectly selected (e.g., using previous layers).
- High variance if calibration data is too small or domain-mismatched, despite FAQ's robustness claim.
- Overhead spikes if window size or fusion computation is not implemented efficiently.

## Limitations
- Hyperparameter transferability: Fixed \(\gamma=0.85\) and \(j=3\) may not generalize to all model architectures; per-model tuning could improve results but adds cost.
- Preview implementation details: Ambiguity in layer selection (which exact activations are averaged) and handling of variable sequence lengths/batches may affect reproduction fidelity.
- Theoretical assumptions: Theorem 1 relies on one dominant channel and large weight positions, which is not empirically validated across diverse LLMs.

## Confidence
