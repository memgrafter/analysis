# FlashOptim: Optimizers for Memory-Efficient Training

## Quick Facts
- **ArXiv ID:** 2602.23349
- **Source URL:** https://arxiv.org/abs/2602.23349
- **Reference count:** 40
- **Primary result:** FlashOptim reduces AdamW memory from 16 to 7 bytes per parameter (5 with gradient release) and SGD from 12 to 6 bytes, while preserving accuracy and throughput, enabling larger model training on limited hardware.

## Executive Summary
Mixed-precision training with standard optimizers like AdamW requires 16 bytes per parameter (FP32 master weights and optimizer states), which becomes prohibitive for large models. FlashOptim tackles this memory bottleneck through two innovations: (1) ULP-based weight splitting, storing a 16-bit weight plus a quantized 8-bit error term to achieve near-24-bit precision, and (2) companding functions (softsign for momentum, square-root for variance) applied before 8-bit group-wise quantization to reshape heavy-tailed distributions and minimize quantization error. Combined with 16-bit gradients, these techniques cut AdamW memory to 7 bytes per parameter (5 with gradient release) and SGD to 6 bytes, halve checkpoint sizes, and maintain accuracy and throughput. Evaluations on ResNet-50 (ImageNet), GPT-2 pretraining, and Llama-3.1-8B finetuning confirm the claims, with a notable case study reducing peak memory from 175 GiB to 113 GiB for Llama-3.1-8B.

## Method Summary
FlashOptim modifies the standard optimizer state representation to drastically reduce memory. The core techniques are:
- **ULP-based weight splitting:** The FP32 master weight θ is split into a 16-bit low-precision weight θ′ (BF16) and an 8-bit error term ρ. The error is quantized within the interval ±ULP(θ′)/2, allowing reconstruction of θ with high precision: ˆθ = θ′ + ρ·ULP(θ′)/(2·N) with N=127 for INT8. This yields effective ~24-bit precision.
- **Companded 8-bit optimizer state quantization:** For AdamW states (momentum m and variance v), group-wise quantization (group size 32) is preceded by a companding transform to reshape the distribution: momentum applies softsign ϕₘ(x)=2x/(1+|x|) (invertible), variance applies square-root ϕᵥ(x)=√x. After normalization by group absmax, the transformed values are quantized to INT8 (momentum) or UINT8 (variance). During the optimizer step, states are dequantized by inverting the companding and scaling.
- **Gradients:** Kept in BF16 (2 bytes). Optional gradient release (zeroing after update) saves an additional 2 bytes.
The optimizer step is implemented with fused Triton kernels, ensuring compatibility with existing training stacks (FSDP, ZeRO, activation checkpointing).

## Key Results
- Memory per parameter: AdamW reduced from 16 → 7 bytes (5 with gradient release), SGD from 12 → 6 bytes; checkpoint size halved from 12 → 5 bytes.
- No measurable accuracy loss on ResNet-50 (ImageNet), GPT-2 pretraining (FineWeb10B), and Llama-3.1-8B finetuning (OpenMathInstruct-2, evaluated on GSM8k).
- Throughput overhead negligible due to fused Triton kernels.
- Case study: Llama-3.1-8B peak memory 175 GiB → 113 GiB, enabling training on limited hardware.

## Why This Works (Mechanism)
FlashOptim’s memory savings stem from aggressive quantization of optimizer states while controlling error. ULP-based splitting ensures that the 16-bit weight representation, though coarse, is corrected by an 8-bit term that captures the residual within a tight bound (half an ULP), effectively achieving ~24-bit precision for the master weight. For momentum and variance, which have heavy-tailed distributions, direct 8-bit quantization would cause large errors, especially in the tails. The companding transforms (softsign for momentum, sqrt for variance) compress dynamic ranges and make distributions more uniform, so that group-wise INT8/UINT8 quantization incurs minimal error. Crucially, these transforms are invertible, allowing exact reconstruction during the update. By keeping gradients in BF16 and using fused kernels, computational overhead is avoided. The error bounds are tight enough that training dynamics remain stable, as evidenced by unchanged convergence and accuracy.

## Architecture Onboarding
**Component map**: Data -> Model forward (BF16 weights) -> Loss -> Backward (BF16 gradients) -> Optimizer step:
  - Reconstruct FP32 master weight: θ = θ′ (BF16) + ρ (INT8) * (ULP(θ′)/(2·127))
  - Dequantize momentum: m = inverse_softsign( dequantize(INT8_m) * scale_m )
  - Dequantize variance: v = ( dequantize(UINT8_v) * scale_v )^2
  - Compute AdamW update: θ′ ← θ′ − lr·(m/(√v+ε) + λ·θ′)
  - Re-quantize momentum and variance with companding and group scales
  - Optionally release gradients (set to zero)
Primary state tensors: θ′ (BF16, 2 B), ρ (INT8, 1 B), INT8 momentum (1 B), UINT8 variance (1 B), group scales (FP16, ≈1/16 B per param). Total ≈7 B/param for AdamW.

**Critical path**: Reconstruction → dequantization (momentum & variance) → update computation → apply to θ′ → re-quantization (momentum & variance) → (optional) release gradients. These steps are fused in Triton kernels to minimize launch overhead.

**Design tradeoffs**:
- Memory vs. precision: 8-bit states reduce memory but increase quantization error; companding mitigates error at cost of extra non-linear transforms.
- Group size (G=32): Smaller groups adapt better to channel-wise variations, reducing error, but increase scale storage overhead; larger groups reduce overhead but may increase error. G=32 balances ~1/16 B overhead per parameter.
- Computation vs. memory: Dequantization/re-quantization adds compute, but fused kernels hide latency; net gain from reduced memory pressure enabling larger models.

**Failure signatures**:
- Training divergence: likely missing companding on variance or incorrect ULP bounds; verify sqrt transform before variance quantization and correct reconstruction formula.
- Memory not reduced: optimizer states stored in FP32; ensure FlashAdamW is used and states are INT8/UINT8.
- Throughput drop: non-fused kernels or frequent synchronizations; check Triton compilation and gradient release usage.
