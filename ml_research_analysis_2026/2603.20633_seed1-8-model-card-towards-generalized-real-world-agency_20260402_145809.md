# Seed1.8 Model Card: Towards Generalized Real-World Agency

## Quick Facts
- **arXiv ID:** 2603.20633  
- **Source URL:** https://arxiv.org/abs/2603.20633  
- **Reference count:** 40  
- **Primary result:** Achieves state-of-the-art on GAIA (87.4), BrowseComp-en (67.6), and ScreenSpot-Pro with tool-use (73.1) via a unified agentic interface integrating LLM/VLM, search, code execution, and GUI interaction.

## Executive Summary
Seed1.8 demonstrates generalized real-world agency by combining a strong base LLM/VLM with a unified interface that dynamically orchestrates tools for search, code execution, and GUI interaction. It sets new records on key agentic benchmarks (GAIA, BrowseComp-en, ScreenSpot-Pro) and multimodal tasks (OmniDocBench, MMLB-NIAH 128k), while showing competitive performance on internal economic benchmarks. The model supports configurable thinking modes for latency-accuracy trade-offs and reports significant token efficiency in video understanding.

## Method Summary
The model integrates a capable base LLM/VLM with a unified agentic framework that routes tasks to appropriate tools (search, code, GUI) based on real-time context. This allows seamless switching between modalities and tool types without task-specific fine-tuning. The system employs a planning component to decompose complex queries into executable steps, leveraging the base model’s reasoning alongside external tool outputs. No specialized per-domain training is required; instead, the interface generalizes across web browsing, document analysis, code-based problem-solving, and GUI navigation.

## Key Results
- State-of-the-art on GAIA (87.4), BrowseComp-en (67.6), and ScreenSpot-Pro with tool-use (73.1).
- Record performance on OmniDocBench (0.106 NED) and MMLB-NIAH 128k (72.2).
- Competitive scores on internal benchmarks: Education (60.8), Finance (62.0).
- Claims of token efficiency gains in video understanding and configurable thinking modes for latency-cost trade-offs.

## Why This Works (Mechanism)
The unified agentic interface acts as a central orchestrator, allowing the base LLM/VLM to dynamically select and sequence tools based on task demands. This decouples general reasoning from tool-specific execution, enabling the model to handle diverse real-world scenarios—from web searches to GUI interactions—without retraining. The configurable thinking modes adjust the depth of internal reasoning versus external tool reliance, balancing accuracy and speed. Token efficiency in video tasks likely stems from selective frame processing guided by the model’s contextual understanding rather than uniform sampling.

- **Multimodal Fusion**: Required to process text, images, and GUI screenshots seamlessly. Quick check: Performance on OmniDocBench and ScreenSpot-Pro.
- **Tool Orchestration**: Essential for sequencing actions in multi-step problems. Quick check: Success rate on BrowseComp-en’s complex queries.
- **Configurable Thinking Modes**: Allows tuning latency-accuracy trade-offs for different deployment scenarios. Quick check: Measure inference time vs. accuracy across mode settings.
- **Long-Context Handling**: Critical for documents and lengthy videos. Quick check: Accuracy drop-off on MMLB-NIAH beyond 128k context.
- **Token-Efficient Video Understanding**: Reduces computational cost by avoiding naive frame sampling. Quick check: Compare tokens used per video against fixed-sampling baselines.

## Architecture Onboarding
Component map: Base LLM/VLM -> Task Planner -> Tool Router -> Execution Modules (Search, Code, GUI) -> Response Generator  
Critical path: Input understanding -> task decomposition -> tool selection -> tool execution -> response synthesis  
Design tradeoffs: Configurable thinking modes balance reasoning depth and latency; unified interface simplifies integration but may add routing overhead.  
Failure signatures: Incorrect tool selection (e.g., using search for coding tasks), incomplete task decomposition, GUI misreading (e.g., misinterpreting buttons).

1. Ablate tool access on GAIA to isolate contribution of each module.
