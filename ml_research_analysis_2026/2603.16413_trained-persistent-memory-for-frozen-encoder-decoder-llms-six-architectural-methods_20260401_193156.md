# Trained Persistent Memory for Frozen Encoder--Decoder LLMs: Six Architectural Methods

## Quick Facts
- **arXiv ID:** 2603.16413
- **Source URL:** https://arxiv.org/abs/2603.16413
- **Reference count:** 15
- **Primary result:** Persistent memory can be added to frozen encoder-decoder LLMs via six adapter-based latent-space architectures, achieving positive memory recall (8–15% at 10× capacity) with modest adapter tax (2–4%), while three methods collapse at 1× capacity.

## Executive Summary
Frozen encoder-decoder LLMs discard latent states after each turn, preventing inter-session memory. This work introduces six adapter-based architectures that add persistent memory via a latent-space bank updated each turn with differentiable write/read operations; only small adapters are trained while the backbone remains frozen. Evaluated on LoCoMo with a headroom-normalized forgetting curve, the stateless baseline scores 0% recall. At 10× memory capacity, all six methods achieve positive recall (8–15% range); at 1×, three collapse, proving capacity is critical. M.2 XAttn and M.6 Slot dominate at low capacity; M.4 Hebbian leads at high capacity. Cumulative knowledge curves show steady accumulation (e.g., M.6 Slot: +9.7% net gain). Adapter tax is modest (2–4%), with net benefit positive for most at sufficient capacity. This pilot demonstrates feasibility and establishes a design space for latent persistent memory.

## Method Summary
The approach augments a frozen encoder-decoder model (Flan-T5-XL) with a persistent memory bank \(P_t \in \mathbb{R}^{n_P \times d}\) that stores encoder outputs across turns. Write operations update \(P_t\) from the current encoder representation \(Z_t\) using fixed random projections (e.g., content-based attention with \(W_Q, W_K, W_V\)), while read operations inject memory into the decoder via a trainable memory adapter \(\theta_{\text{Mem}}\). Training proceeds in two phases: Phase 1 (Type 1) optimizes only \(\theta_{\text{Mem}}\) via backpropagation through the frozen backbone with writes detached; Phase 2 (Type 2) freezes \(\theta_{\text{Mem}}\) and updates \(P_t\) online without gradients, enabling continual accumulation without weight changes. Six architectural variants differ in where memory is injected (pre-encoder, parallel decoder branch, or KV extension), the write mechanism (attention-coupled, Hebbian, slot-based), and whether read is delegated to the decoder or explicit. Hyperparameters include AdamW (lr = 1e‑4, weight decay = 1e‑2), memory capacity \(n_P\) (64 for 1×, 640 for 10×), and decay \(\gamma = 0.95\).

## Key Results
- Stateless baseline: 0% memory recall.
- At 10× capacity, all methods achieve 8–15% recall; at 1×, M.1, M.3, and M.5 collapse to near-zero.
- M.2 XAttn and M.6 Slot perform best at low capacity; M.4 Hebbian leads at high capacity.
- Cumulative knowledge gain: e.g., M.6 Slot shows +9.7% net gain.
- Adapter tax is modest (2–4%), and net benefit is positive for most methods when capacity is sufficient.

## Why This Works (Mechanism)
**Mechanism 1: Latent-space persistent memory bank**  
A persistent memory bank \(P_t\) stores continuous encoder representations; write and read operations are fully differentiable and occur inside the forward pass. Write uses fixed random projections and attention-like addressing (e.g., \(P_t = \gamma P_{t-1} + A_t^\top V\) with \(A_t = \text{softmax}(Z_t W_Q (P_{t-1} W_K)^\top / \sqrt{d})\)). Read either delegates to the frozen decoder (by projecting \(P_{t-1}\) into additional key–value pairs) or retrieves explicitly via the adapter. The core assumption is that the frozen decoder’s cross-attention can effectively use memory entries after projection by the trainable adapter. The paper’s Section 4 and abstract explicitly describe this differentiable latent-space approach.

**Mechanism 2: Adapter-only training**  
Only a small memory adapter \(\theta_{\text{Mem}}\) is updated; the entire backbone (encoder and decoder) stays frozen. During training, gradients flow through the frozen decoder (and sometimes encoder) to update \(\theta_{\text{Mem}}\), while writes are detached to bound the computation graph. After training, \(\theta_{\text{Mem}}\) is frozen and the memory bank updates online without gradients, enabling lifelong accumulation without weight changes. This preserves pre-trained knowledge and minimizes compute. The abstract and Section 5 confirm that only small adapters are trained while the backbone remains frozen.

**Mechanism 3: Two-phase conversational learning**  
A two-phase regimen enables the model to become more knowledgeable with each interaction. Phase 1 (offline) optimizes \(\theta_{\text{Mem}}\) via truncated BPTT over conversation windows, with writes detached. Phase 2 (online) freezes \(\theta_{\text{Mem}}\) and updates \(P_t\) turn-by-turn, compressing history into a fixed-size latent array indefinitely. The trained write and read rules are expected to remain stable for unseen inputs. The abstract and Section 5 detail the phases, and cumulative knowledge curves (e.g., M.6 Slot’s +9.7% net gain) demonstrate steady accumulation.

## Foundational Learning
- **Cross-Attention in Encoder–Decoder Transformers**: The standard cross-attention mechanism (queries from decoder, keys/values from encoder) is fundamental because all six methods modify how the decoder accesses memory—either by extending the KV cache or adding parallel branches. *Quick check*: In a frozen encoder-decoder model, how does the decoder’s cross-attention normally use the encoder’s output \(Z_t\)?
- **Parameter‑Efficient Fine‑Tuning (PEFT)**: The approach trains only a tiny adapter while keeping the large backbone frozen, aligning with PEFT paradigms like prefix tuning or LoRA. *Quick check*: What is the core idea behind prefix tuning, and how does it differ from full fine-tuning?
- **Forgetting‑Curve Evaluation for Memory Systems**: The primary metric is the headroom-normalized memory recall rate as a function of evidence lag, measuring how well persistent state resists decay over long horizons. *Quick check*: How is the memory recall rate \(\rho_q(m)\) computed, and why is it normalized by headroom?

## Architecture Onboarding
**Component map (data flow):**  
Input turn \(x_t\) → frozen encoder \(E_{\text{frozen}}\) → encoder output \(Z_t\); write rule updates memory bank \(P_t\) from \(Z_t\); \(P_t\) persists to next turn; read rule (with trainable \(\theta_{\text{Mem}}\)) consumes \(P_{t-1}\) to produce memory context; frozen decoder \(D_{\text{frozen}}\) attends to \(Z_t\) and memory context → output \(\hat{y}_t\).

**Critical path per turn:**  
1. Encode current turn: \(x_t \xrightarrow{E_{\text{frozen}}} Z_t\).  
2. Write: \(P_t = \text{Write}(P_{t-1}, Z_t)\) (detached during training).  
3. Read: Compute memory context from \(P_{t-1}\) and \(\theta_{\text{Mem}}\); inject into decoder alongside \(Z_t\).  
4. Decode: \(D_{\text{frozen}}\) generates \(\hat{y}_t\) using \(Z_t\) and memory context.  
5. Persist: \(P_t\) is carried to the next turn.

**Design tradeoffs:**  
- *Injection point*: before encoder (M.1), inside decoder as parallel branch (M.2, M.5), or as KV extension (M.3, M.4, M.6). Affects interference with frozen pathways.  
- *Write mechanism*: attention-coupled (M.1–3, M.5), Hebbian outer product (M.4), sparse slot addressing (M.6). Capacity sensitivity varies; sparse addressing helps at low capacity.  
- *Read delegation*: delegated (frozen decoder selects) vs. explicit (adapter retrieves). Delegated reduces parameters but relies on pre-trained attention; explicit gives adapter control but adds parameters.  
- *Capacity*: Bank size \(n_P\) is critical; methods differ in scalability (e.g., at 1× capacity, three methods collapse).  
- *Adapter tax*: Methods with explicit gating (M.5, M.6) can suppress memory when empty, reducing interference.

**Failure signatures:**  
- At 1× capacity, M.1, M.3, M.5 collapse to near-zero recall (Figure 9 left, Table 3).  
- Negative net benefit (adapter hurts more than memory helps) for M.1, M.3, M.5 at 1× (Table 5).  
- Hebbian (M.4) shows flat decay (resists overwrite) but lower short-lag height; Slot (M.6) and XAttn (M.2) dominate at low capacity.  
- Near-zero knowledge accumulation (\(\Delta K \approx 0\)) indicates failure to learn from experience (Table 4).

**First 3 experiments:**  
1. **Baseline run**: Execute stateless baseline (no memory) on LoCoMo to establish zero memory recall and raw QA F1 for headroom calculation.  
2. **Capacity scaling**: Train all six methods at 1× and 10× capacity; compare forgetting curves to identify capacity‑dependent failures and successes.  
3. **Ablation of write‑side training**: Freeze write‑side projections as in the paper vs. allow gradients through write; verify that detached writes do not harm performance and keep computation graph bounded.

## Open Questions the Paper Calls Out
1. **Scaling to larger memory and models**: Do the observed capacity‑dependent performance hierarchies (e.g., M.2/M.6 dominating at low capacity, M.4 leading at high) persist when scaling to industrial‑scale memory banks (millions of slots) and larger backbone models (e.g., decoder‑only LLMs)?
2. **End‑to‑end training vs. adapter‑only**: To what degree does unfreezing the backbone improve memory recall, and which components (encoder, decoder, or both) contribute most to gains?
3. **Mechanism behind capacity‑dependent differences**: What is the underlying mechanism by which Hebbian associative memory (M.4) exhibits superior long‑lag retention at high capacity, while slot‑based (M.6) and attention‑coupled (M.2) methods are more robust at low capacity?
4. **Decoder representational slack**: Does the frozen decoder’s cross‑attention possess sufficient representational slack to meaningfully attend to memory entries projected by trained adapters, or is the decoder itself a fundamental bottleneck requiring architectural modifications?
5. **Cross‑domain and long‑term generalization**: How do the six memory architectures generalize across diverse dialogue domains (task‑oriented vs. social) and longer lifetimes (hundreds of sessions) beyond LoCoMo’s 30‑session, single‑domain benchmark?

## Limitations
- **LoCoMo preprocessing unspecified**: Exact train/val/test splits, QA pair filtering, and evidence turn mapping are not documented, hindering exact replication.
- **Decoder injection ambiguity**: For some methods (e.g., M.2, M.5), the mechanism for injecting memory into the decoder (e.g., “per‑layer hooks”) is vague, potentially leading to implementation variation.
- **Capacity‑dependent collapse unexplained**: The paper shows that some methods fail at 1× capacity but succeed at 10×, yet provides no theoretical analysis of why capacity interacts with architecture this way.

## Confidence
- **Latent persistent memory feasibility**: Medium  
- **Adapter‑only training sufficiency**: Medium  
- **Two‑phase learning stability**: Medium
