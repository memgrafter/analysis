# SupChain-Bench: Benchmarking Large Language Models for Real-World Supply Chain Management

## Quick Facts
- **arXiv ID:** 2602.07342
- **Source URL:** https://arxiv.org/abs/2602.07342
- **Reference count:** 40
- **Primary result:** SupChain-Bench introduces a two-part benchmark for supply chain LLM evaluation; SupChain-ReAct achieves 75.51% tool-calling accuracy without SOPs, surpassing many SOP-guided models.

## Executive Summary
Supply chain management demands reliable, long-horizon, multi-step tool orchestration, yet no standardized benchmark existed to evaluate LLMs in this setting. This paper presents SupChain-Bench, a benchmark comprising a Knowledge QA module and a Function-Calling benchmark, the latter evaluated under both SOP-guided and SOP-free conditions. Experiments across multiple LLMs reveal substantial performance gaps, especially in maintaining procedural consistency over many steps. The authors also propose SupChain-ReAct, a framework that autonomously synthesizes procedural guidance via multi-path ReAct trajectories and answer-level majority voting. Without any handcrafted SOPs, SupChain-ReAct attains the strongest and most consistent tool-calling accuracy (e.g., 75.51% on SOP-free tasks), establishing procedural reliability as a key challenge for LLM-based supply chain agents.

## Method Summary
The authors construct a supply chain QA dataset (435 items) from sanitized operational documents, covering multiple-choice, single-choice, and true/false questions. For function-calling, they build a simulated database (TradeOrders, FulfillmentOrders, WarehouseOrders, etc.) and define JSON tool schemas; each query requires a multi-step SOP to retrieve the correct answer. Evaluation is performed under four conditions: QA with/without contextual documents, and function-calling with/without a handcrafted SOP prompt. Ground truth for tool tasks is generated by deterministic SOP execution. The SupChain-ReAct framework is introduced as an SOP-free alternative: it samples five parallel ReAct trajectories (reasoning + tool calls) per query and selects the final answer by majority vote, thereby synthesizing a procedural plan on the fly. Performance is measured by exact-match accuracy, token usage, and tool-call length.

## Key Results
- SupChain-Bench exposes large performance gaps among LLMs in long-horizon tool orchestration; many models fail to complete tasks requiring more than 25 tool calls.
- Providing explicit SOPs boosts accuracy on shorter tasks but does not reliably close the gap on complex, multi-step workflows.
- SupChain-ReAct, without any handcrafted SOPs, achieves the highest tool-calling accuracy (75.51% on SOP-free setting), demonstrating that autonomous procedural synthesis can match or exceed SOP-guided performance.

## Why This Works (Mechanism)
The paper identifies three mechanisms that explain the observed results.

**Mechanism 1: SOPs as a reliability crutch for short-horizon tasks.**  
An explicit SOP offers a deterministic, step-by-step plan that reduces the planning burden on the model, shifting its role from autonomous sequencing to faithful execution. This improves accuracy on simpler, short-horizon tasks but does not enable reliable long-horizon execution. Evidence shows that while GPT models follow full instruction sequences, others (Claude, Gemini, Qwen) frequently terminate early when given an SOP, revealing a "good-enough stopping rule" that favors efficiency over exhaustive completion.

**Mechanism 2: Multi-path ReAct with voting synthesizes robust procedural guidance.**  
SupChain-ReAct runs multiple parallel ReAct trajectories, each generating a candidate execution plan. Answer-level majority voting aggregates these trajectories into a consensus outcome, implicitly deriving a stable procedure without external SOPs. This approach compensates for the model's inability to generate and persist with a single correct plan, leading to superior performance in SOP-free settings (75.51% accuracy) across top proprietary models.

**Mechanism 3: High-quality domain context eliminates critical knowledge gaps.**  
Access to operationally relevant documents (e.g., SOPs) yields dramatic accuracy improvements, especially for tool-calling (up to ~60 percentage points). The gains indicate that LLMs possess broad but shallow supply chain knowledge; precise, scenario-specific procedural details are missing from pre-training. Supplying this context bridges the gap, enabling both better QA and correct tool sequencing.

## Architecture Onboarding
**Component map**  
SupChain-Bench dataset (QA + Function-Calling) → Evaluation Harness → Target LLMs.  
SOP Module feeds handcrafted SOP prompts into the harness for guided evaluations.  
SupChain-ReAct wraps the LLM as an intermediate layer that performs multi-trajectory ReAct and majority voting for autonomous planning.

**Critical path**  
1. **Curation**: Sanitize real-world supply chain operational documents to build a knowledge base.  
2. **Generation**: Use a 3-agent pipeline (o3-mini → Claude 4 Sonnet → Gemini 2.5 Pro) to create and refine QA pairs; programmatically execute SOPs to generate ground-truth tool call sequences.  
3. **Verification**: Human experts verify all QA pairs; tool-calling questions are validated by oracle script outputs.  
4. **Evaluation**: Run target models under the four conditions (QA w/wo context; Tool-calling w/wo SOP) and compute accuracy, token usage, and call length.  
5. **Framework Proposal**: Implement SupChain-ReAct as a zero-shot procedural synthesis alternative to handcrafted SOPs.

**Design tradeoffs**  
- *SOP-Guidance*: Offers high control and short-horizon accuracy but requires expensive expert authoring and is brittle to task variations.  
- *SupChain-ReAct*: Removes SOP authoring overhead and generalizes better, but incurs higher inference cost (5× sampling) and performance varies across model families.  
- *Context Window*: Truncating documents to 2000 characters is pragmatic for simulation but may discard long-range dependencies present in real documents.

**Failure signatures**  
- Early termination: model stops tool calls before processing all required entities.  
- Schema mismatch: tool arguments use incorrect field names or types.  
- Field omission: model fails to extract all required fields from tool responses, especially nested data.  
- State inconsistency: final answer contradicts earlier retrieved information.

**First 3 experiments**  
1. **Baseline Establishment**: Run representative models (GPT-5, Claude-4-Sonnet, Qwen3-Max) on the full benchmark to reproduce main accuracy results and gaps.  
2. **SOP Impact Isolation**: Compare a single model (e.g., Claude-4-Sonnet) in SOP-guided vs. SOP-free modes, analyzing tool-call length distribution and per-difficulty accuracy.  
3. **SupChain-ReAct Replication**: Implement SupChain-ReAct (5 ReAct paths, majority vote) and evaluate on additional models (GPT-4.1-mini, Deepseek-V3) to confirm accuracy lift over single-trajectory ReAct.

## Limitations
- The dataset may not capture the full diversity of real-world supply chain scenarios; human validation details are limited.  
- Using SOPs as ground truth may bias evaluation toward SOP-guided methods, potentially undervaluing autonomous planning approaches.  
- SupChain-ReAct was evaluated only on top-tier proprietary models; its effectiveness for open-source models remains unknown.

## Confidence
- **SOP short-horizon boost, long-horizon fail**: Medium  
- **SupChain-ReAct autonomy**: Medium  
- **Context huge gains**: High
