# ECCO: Evidence-Driven Causal Reasoning for Compiler Optimization
## Quick Facts
- arXiv ID: 2602.00087
- Source URL: https://arxiv.org/abs/2602.00087
- Reference count: 40
- Primary result: ECCO achieves an average 24.44% cycle reduction over LLVM -O3 across seven benchmarks.

## Executive Summary
Compiler auto-tuning typically relies on either black-box search, which lacks semantic guidance, or LLMs that may engage in superficial pattern matching with opaque causality. ECCO introduces an evidence-driven causal reasoning framework that combines a reverse-engineering pipeline to extract verifiable IR/feature/performance evidence, a two-stage LLM policy optimization (SFT + GRPO) to produce evidence-grounded rationales, and a collaborative Strategist-Tactician inference where LLM-predicted intents bias a genetic algorithm’s mutations. Evaluated on seven benchmark suites, ECCO reduces cycles by an average 24.44% over LLVM -O3, outperforming strong baselines (CFAST 23.70%, GRACE 23.14%, direct LLM ~16%). An interpretability audit confirms >78% rationale faithfulness, and ablations demonstrate that both the evidence extraction and genetic algorithm collaboration are essential for the full gain.

## Method Summary
ECCO’s methodology comprises three integrated innovations. First, a reverse-engineering pipeline processes optimal pass sequences to extract low-level IR features and performance metrics, constructing a corpus of causal Chain-of-Thought (CoT) rationales. Second, this corpus is used to fine-tune an LLM via supervised fine-tuning (SFT) followed by group relative policy optimization (GRPO), aligning the model to generate evidence-grounded explanations. Third, at inference time, the LLM acts as a Strategist, predicting high-level optimization intents (e.g., “enhance loop parallelism”) that condition a genetic algorithm (Tactician) to mutate pass sequences more effectively. The GA explores the combinatorial space of pass ordering, guided by the LLM’s intent-based bias, yielding optimized compiler flags for target programs.

## Key Results
- **Performance**: 24.44% average cycle reduction vs. LLVM -O3; exceeds CFAST (23.70%), GRACE (23.14%), and direct LLM (~16%).
- **Interpretability**: >78% of generated rationales are faithful to extracted evidence.
- **Ablation insights**: LLM alone (without GA) peaks at ~19.4%; GA collaboration adds ~5% gain, highlighting the importance of combinatorial precision.

## Why This Works (Mechanism)
ECCO succeeds by bridging the gap between semantic guidance and combinatorial search. The evidence extraction pipeline grounds optimizations in measurable IR and performance changes, producing verifiable CoT rationales that mitigate LLM hallucination. The SFT+GRPO alignment trains the LLM to internalize these causal relationships, enabling it to predict high-level intents that meaningfully bias the GA’s mutations. This symbiosis allows the LLM to contribute strategic insight without exhaustive search, while the GA provides the precision needed to explore the vast pass combination space. The result is a system that leverages both data-driven causality and evolutionary computation, achieving superior and interpretable optimization.

## Foundational Learning
**Concept 1: Causal reasoning in compiler optimization**  
*Why needed:* To move beyond correlation and ensure that suggested pass sequences have a true performance impact.  
*Quick check:* For a candidate pass sequence, measure performance delta on a controlled microbenchmark and verify it aligns with the predicted effect (e.g., reduced memory traffic).

**Concept 2: IR/feature/performance evidence extraction**  
*Why needed:* Provides verifiable, low-level justification for optimization decisions, forming the basis of the CoT corpus.  
*Quick check:* Confirm that extracted IR features (e.g., loop count, memory access patterns) correlate with observed performance changes across random pass sequences.

**Concept 3: Chain-of-Thought (CoT) fine-tuning**  
*Why needed:* Teaches the LLM to articulate reasoning steps, enhancing interpretability and alignment with evidence.  
*Quick check:* Generate CoT rationales for known-good optimizations and check that steps reference extracted IR/feature evidence.

**Concept 4: Genetic algorithm (GA) for pass ordering**  
*Why needed:* Explores the combinatorial space of pass sequences efficiently, complementing LLM’s high-level guidance.  
*Quick check:* Compare GA’s best-found sequence against random search on a small benchmark; expect significantly better performance.

**Concept 5: LLM policy optimization (SFT + GRPO)**  
*Why needed:* Aligns the LLM’s output with both performance outcomes and evidence fidelity, avoiding superficial pattern matching.  
*Quick check:* Measure improvement in rationale faithfulness and sequence quality after each training stage on a holdout set.

**Concept 6: Strategist-Tactician collaboration**  
*Why needed:* Marries LLM’s semantic understanding with GA’s combinatorial precision, yielding gains unattainable by either alone.  
*Quick check:* Ablate one component (e.g., use random intents instead of LLM) and quantify performance drop relative to full system.

## Architecture Onboarding
**Component map:**  
Evidence Extraction -> Corpus Formation -> LLM SFT -> LLM GRPO -> Tuned LLM (Strategist) -> GA (Tactician) -> Optimized Pass Sequences

**Critical path:**  
1. Collect raw pass sequences and performance data (e.g., from autotuning runs).  
2. Run evidence extraction to generate IR features and performance metrics.  
3. Assemble CoT corpus linking passes to evidence and outcomes.  
4. Perform LLM SFT on corpus, then GRPO to optimize for evidence alignment.  
5. Deploy tuned LLM to provide intents for GA during inference.  
6. Execute GA with intent bias to produce final optimization recommendations.

**Design tradeoffs:**  
- Evidence extraction cost vs. rationale fidelity: More detailed evidence yields richer CoT but increases preprocessing overhead.  
- SFT only vs. SFT+GRPO: GRPO improves alignment but adds training complexity and compute.  
- Pure LLM generation vs. GA collaboration: LLM alone may miss combinatorial interactions; GA adds search cost but gains ~5% performance improvement.

**Failure signatures:**  
- Low rationale faithfulness (<70%) indicates evidence extraction or LLM alignment issues.  
- GA fails to improve over random search suggests intent bias is ineffective or GA parameters are misconfigured.  
- Performance regressions on specific benchmarks may reveal corpus bias or overfitting.

**First experiments:**  
- Run evidence extraction on a small sample (e.g., 10 programs) and manually verify that extracted IR features logically explain performance differences.  
- Evaluate the fine-tuned LLM on a validation set: compute CoT faithfulness (via automated or expert review) and compare pass sequence quality against baseline.  
- Compare GA with and without LLM intent bias on a single benchmark suite to isolate the benefit of collaboration (expected ~5% gain).

## Limitations
- Evaluation scope excludes nearest-neighbor papers (e.g., Compiler-R1, Synergy-Guided tuning), so relative performance against these methods is unknown.
- Evidence faithfulness audit lacks methodological details (e.g., evaluation design, sample size), undermining confidence in causal robustness claims.
- Results are confined to seven benchmark suites; scalability to large, heterogeneous real-world codebases remains unproven.

## Confidence
- Performance superiority (24.44% avg gain): Medium  
- Interpretability audit (>78% faithfulness): Low-Medium  
- Ablation criticality (Evidence/CoT necessity): Medium
