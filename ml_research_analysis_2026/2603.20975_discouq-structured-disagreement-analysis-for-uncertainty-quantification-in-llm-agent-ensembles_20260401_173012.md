# DiscoUQ: Structured Disagreement Analysis for Uncertainty Quantification in LLM Agent Ensembles

## Quick Facts
- **arXiv ID:** 2603.20975
- **Source URL:** https://arxiv.org/abs/2603.20975
- **Reference count:** 10
- **Primary result:** DiscoUQ-LLM (logistic regression on LLM-extracted disagreement features) achieves the best average AUROC (0.802) and lowest expected calibration error (0.036) on a 5-agent Qwen3.5-27B ensemble across StrategyQA, MMLU, TruthfulQA, and ARC-Challenge.

## Executive Summary
DiscoUQ addresses the limitation of majority voting in multi-agent LLM systems, which discards semantic information in disagreements. The method introduces two complementary families of features—linguistic (evidence overlap, minority argument strength, divergence depth) extracted via a fixed LLM analyzer, and geometric (cluster distances, dispersion) derived from agent reasoning embeddings—and combines them with vote confidence via simple classifiers. Evaluated on four QA benchmarks, DiscoUQ-LLM outperforms the strongest baseline (LLM Aggregator) in AUROC and calibration, with the largest gains on ambiguous weak-disagreement cases. The approach requires only one extra LLM call per non-unanimous question, offering an efficient and well-calibrated uncertainty estimate.

## Method Summary
Given a set of agent reasoning texts and answers for each question, DiscoUQ computes structured features only for non-unanimous cases. Linguistic features (6 scores + categorical divergence depth) are extracted via a fixed LLM prompt (temperature 0) that introspects the full disagreement. Geometric features (7 statistics) are computed from the pairwise cosine-distance matrix of sentence-transformer embeddings (BGE-large-env1.5). These are concatenated with raw vote confidence (the proportion of agents agreeing on the majority answer) to form a feature vector. Three model variants are trained: M1 (logistic regression on linguistic features), M2 (logistic regression on geometric features), and M3 (a two-layer MLP on all features). Training uses 5-fold stratified cross-validation to predict a binary label indicating whether the majority answer is correct, with the model’s sigmoid output serving as a calibrated confidence score.

## Key Results
- DiscoUQ-LLM (M1) achieves the highest average AUROC (0.802) and lowest ECE (0.036) across four benchmarks, surpassing the LLM Aggregator baseline (AUROC 0.791, ECE 0.098).
- The geometric-only variant (DiscoUQ-Embed, M2) performs on par with the best non-LLM baseline in AUROC but with dramatically better calibration.
- DiscoUQ’s features generalize across domains, with minimal performance drop when training on one benchmark and testing on another, and yield the largest gains on ambiguous, weak-disagreement cases.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Linguistic structure features extracted via LLM prompting capture semantically meaningful disagreement patterns (e.g., evidence overlap, minority argument strength) that are predictive of majority correctness.
- **Mechanism:** For non-unanimous questions, a fixed analyzing LLM (temperature 0) processes the full reasoning texts from all agents and outputs six normalized scores. These scores encode qualitative aspects of the disagreement: shared factual base (`eoverlap`), novelty/strength of minority arguments (`enew`, `estr`), expressed certainty (`econf`), reasoning complexity (`ecplx`), and the stage of divergence (`d`). The scores are combined with the raw vote confidence in a logistic regression to produce a calibrated probability.
- **Core assumption:** The analyzing LLM can reliably introspect and score these abstract reasoning properties from the provided texts, and these scores are consistent and discriminative across questions.
- **Evidence anchors:**  
  [abstract] "extracts two complementary families of features... linguistic properties (evidence overlap, minority argument strength, divergence depth)... extracted via LLM prompting."  
  [section 3.2.1] Detailed description of the six linguistic features and the prompting procedure.  
  [corpus] Corpus evidence is weak; neighboring papers (e.g., "CoE: Collaborative Entropy...") address cross-model semantic disagreement but do not validate LLM-based introspection for feature extraction.
- **Break condition:** If the analysis LLM's scoring becomes inconsistent (low self-consistency across re-prompts) or if the features show low correlation with correctness in validation data, the predictive mechanism fails.

### Mechanism 2
- **Claim:** The geometric structure of agent reasoning embeddings (cosine-distance relationships) encodes useful disagreement signals (e.g., cluster tightness, separation) that are predictive of ensemble correctness.
- **Mechanism:** Reasoning texts are embedded using a fixed sentence transformer. Seven geometric features are computed from the pairwise cosine-distance matrix: overall dispersion, majority/minority cohesion, cluster distance, minority outlier degree, majority centrality, and PCA variance ratio. These quantify how "clustered" the agents are by their representations. Combined with vote confidence in a logistic regression, they model disagreement as a geometric property of the embedding space.
- **Core assumption:** The embedding model maps semantically similar reasoning to proximal vectors, and disagreement patterns that matter for correctness manifest as measurable geometric distortions (e.g., a polarized minority forms a distinct, cohesive cluster).
- **Evidence anchors:**  
  [abstract] "embedding geometry (cluster distances, dispersion, cohesion)... from agent embedding similarities."  
  [section 3.2.2] Explicit formulas for the seven geometric features.  
  [section 5.1] "DISCOUQ-Embed... performs on par with the best non-LLM baseline... but with dramatically better calibration," supporting the informativeness of geometric signals.
- **Break condition:** If the embedding model is insensitive to the relevant semantic distinctions in the agents' reasoning (e.g., treats all reasoning chains as similar), or if geometric features show no predictive power in ablation studies (e.g., PCA variance ratio removal causes large performance drop per Table 3), the mechanism fails.

### Mechanism 3
- **Claim:** A simple classifier (logistic regression or small MLP) on the combined feature set effectively maps structured disagreement signals to well-calibrated confidence estimates, outperforming using vote confidence alone or a black-box aggregator.
- **Mechanism:** The feature set (linguistic + geometric + vote confidence) is fed into a supervised classifier trained to predict whether the majority answer is correct. The classifier learns weights that integrate the multi-faceted disagreement information. The sigmoid output of logistic regression provides natural probability calibration; the MLP (M3) attempts to model non-linear interactions but risks overfitting.
- **Core assumption:** The constructed feature set captures a sufficient statistic of the disagreement's relevance to correctness, and the relationship between these features and the binary correctness label is learnable with a simple model given the training data size.
- **Evidence anchors:**  
  [section 3.3] "M1: logistic regression on the 9 LLM structure features... M2: logistic regression on the 8 embedding... M3: a two-layer MLP on all features."  
  [section 5.1 & Table 1] M1 achieves best average AUROC (0.802) and lowest ECE (0.036), demonstrating the effectiveness of the learned integration.  
  [section 6.1] Cross-benchmark generalization (near-zero performance degradation) supports that the learned patterns are domain-general.
- **Break condition:** If the feature set is fundamentally incomplete (e.g., misses a critical dimension of disagreement), if the training data is too small or unrepresentative causing overfitting (evidenced by M3's drop on ARC-Challenge), or if the correctness label noise is high, the learned model will not generalize.

## Foundational Learning

**Concept: Multi-agent LLM ensembles and the limitation of vote-based confidence**  
- **Why needed here:** DiscoUQ's premise is that majority vote confidence (`c_vote`) is a shallow signal. An engineer must understand the base system (K=5 agents with distinct roles) and why a 3-to-2 vote is ambiguous before appreciating structured features.  
- **Quick check question:** What are two different scenarios that would yield the same vote confidence (e.g., 3/5) but have different implications for the reliability of the majority answer?

**Concept: Uncertainty quantification metrics for classification (AUROC, ECE)**  
- **Why needed here:** The paper's core claim is improved discrimination (AUROC) and calibration (ECE). An engineer must interpret these metrics to evaluate DiscoUQ's performance and understand the calibration advantage of logistic regression.  
- **Quick check question:** Why does vote counting produce inherently coarse confidence values (only K+1 distinct levels), and how does that limit calibration?

**Concept: Basic feature engineering from text (LLM-as-feature-extractor) and embeddings (cosine similarity statistics)**  
- **Why needed here:** DiscoUQ's innovations are the specific linguistic and geometric features. An engineer must grasp how raw agent outputs are transformed into structured numerical features.  
- **Quick check question:** For the 'divergence depth' feature, what does a 'late' divergence pattern imply about the agents' shared evidence, and why is it a positive signal for majority correctness?

## Architecture Onboarding

**Component map:**  
Agent Pool (5 role-specialized LLMs) -> Reasoning Extraction (capture `reasoning_text`, `final_answer` per agent) -> Feature Modules (Linguistic Analyzer [LLM call] + Embedding Calculator [sentence transformer + geometry]) -> Classifier (logistic regression or MLP) -> Output (calibrated confidence, optionally majority answer)

**Critical path:** For each question, agent responses are collected. If non-unanimous, the Linguistic Analyzer and Embedding Calculator run in parallel to produce a feature vector, which is fed to the Classifier to output confidence. Unanimous questions default to confidence = 1.0 (or can be processed with default features).

**Design tradeoffs:**  
- DiscoUQ-LLM (M1) vs. DiscoUQ-Embed (M2): LLM features have higher semantic fidelity but cost 1 extra LLM call per non-unanimous question; embed features are free after model download but are a noisier proxy.  
- Logistic regression (M1/M2) vs. MLP (M3): LR is more interpretable, robust, and better calibrated on small/noisy data; MLP risks overfitting when error rates are very low (e.g., ARC-Challenge).  
- Feature set size: More features (M3’s 17) can capture interactions but increase overfitting risk; M1’s 9-feature LR hits the best tradeoff.

**Failure signatures:**  
- Calibration collapse on high-accuracy benchmarks: On ARC-Challenge (base accuracy ~96%), all DiscoUQ methods underperform simple vote counting in AUROC; signal is too sparse.  
- Overfitting in DiscoUQ-Learn: M3’s AUROC drops significantly on ARC-Challenge and shows high variance in cross-validation, indicating the MLP memorizes noise in the minority error class.  
- LLM feature extraction inconsistency: If the analyzing LLM’s scores are low-variance or misaligned with human judgment, linguistic features lose predictive power.  
- Embedding geometry insensitivity: If pairwise cosine similarities are uniformly high, geometric features become uninformative.

## Open Questions the Paper Calls Out

1. Does DiscoUQ's structured disagreement analysis transfer effectively to open-ended text generation tasks, and what new evaluation metrics are needed for uncertainty in such settings?  
   *Basis:* Conclusion states extension to open-ended generation is a future direction; limitations note evaluation was only on closed-form QA.  
   *Why unresolved:* Current framework and metrics (AUROC, ECE) are designed for discriminative QA; open-ended generation requires gradational or multi-faceted correctness.

2. How universally do the learned disagreement structure features (linguistic and geometric) generalize across fundamentally different LLM architectures and scales (e.g., dense vs. MoE, decoder-only vs. encoder-decoder, <10B vs. >100B parameters)?  
   *Basis:* Limitation (2) acknowledges that generalization across model families is only partially explored via a limited heterogeneous experiment.  
   *Why unresolved:* Experiments primarily used one model family (Qwen3.5-27B); systematic variation of model capabilities, objectives, and representations is lacking.

3. Can DiscoUQ's confidence estimates be dynamically calibrated in an online deployment setting where data distribution shifts over time, without requiring periodic full retraining on new labeled data?  
   *Basis:* Conclusion mentions "developing online calibration methods that adapt structure weights over time" as future work; current methods are trained offline.  
   *Why unresolved:* Real-world applications face distribution drift; offline-trained classifiers may become miscalibrated, and no adaptation mechanism is proposed.

4. How sensitive are the LLM-extracted linguistic structure features (evidence overlap, argument strength, etc.) to the capability and prompting of the analyzing LLM itself, especially for complex, multi-step reasoning chains?  
   *Basis:* Limitation (3) states that feature quality depends on the analyzing model’s introspection, which may degrade for more complex reasoning.  
   *Why unresolved:* Feature extraction is meta-reasoning; if the analyzer is weak or poorly prompted, it may misjudge disagreement patterns. The paper does not vary the analyzer or test on longer reasoning traces.

5. Does increasing the number of agents beyond the current 5 introduce qualitatively new disagreement structures (e.g., multiple minority clusters, cyclic majorities) that are not captured by the current feature set, and how does predictive performance scale?  
   *Basis:* Limitation (5) notes that scaling to larger agent pools may introduce different disagreement dynamics; feature design assumes a single majority/minority split.  
   *Why unresolved:* All experiments use 5 agents; the relationship between agent count and feature informativeness is unexplored, and non-linear effects (factional splits, embedding dimensionality) are unaddressed.

## Limitations
- Exact prompts and agent system messages are undocumented, possibly affecting feature reliability and reproducibility.
- DiscoUQ-LLM adds an LLM call per non-unanimous question, increasing cost relative to vote-only baselines.
- Performance drops on high-accuracy benchmarks (e.g., ARC-Challenge) where disagreement signals are sparse; the MLP variant (M3) shows overfitting risk.
- Generalization to heterogeneous agent pools or non-Qwen base models remains unproven.

## Confidence
- **Linguistic feature effectiveness:** Medium — modest AUROC gain (+0.011) but relies on unvalidated LLM introspection; prompt variations may break the signal.
- **Geometric feature effectiveness:** High — robust AUROC/ECE improvements across all four benchmarks, insensitive to prompt details.
- **Classifier integration (logistic regression):** High — best AUROC and lowest ECE; simple model generalizes well.
- **Classifier integration (MLP):** Medium — overfitting risk on low-error benchmarks (ARC-Challenge drop).
- **Cross-benchmark generalization:** High — minimal performance loss when transferring between StrategyQA, MMLU, TruthfulQA.
