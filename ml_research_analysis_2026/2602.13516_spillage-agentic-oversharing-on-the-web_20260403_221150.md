# SPILLage: Agentic Oversharing on the Web

## Quick Facts
- **arXiv ID:** 2602.13516
- **Source URL:** https://arxiv.org/abs/2602.13516
- **Reference Count:** 40
- **Primary Result:** Web agents leak task-irrelevant user information 5× more through behavioral actions (clicks, navigation) than typed content, but removing irrelevant info from prompts before execution improves task success by up to 17.9%.

## Executive Summary
This paper introduces SPILLage, a framework to characterize and measure "agentic oversharing"—the unintentional disclosure of task-irrelevant user information by web agents through their observable action traces on live websites. Evaluating 1,080 runs across 180 shopping tasks on Amazon and eBay using two agent frameworks (Browser-Use, AutoGen) and three LLMs (gpt-4o, o3, o4-mini), the study finds oversharing to be pervasive and dominated by behavioral channels (e.g., clicks, filters, navigation paths). Naive prompt-level mitigation backfires, but pre-execution sanitization of the user prompt aligns privacy with utility, significantly boosting task success. The work reveals that privacy risks extend far beyond typed text to the semantics of user interface interactions.

## Method Summary
The study establishes a benchmark of 180 persona-based shopping tasks (90 on Amazon, 90 on eBay), each with annotated task-relevant (`Srelevant`) and task-irrelevant (`Sirrelevant`) attributes and presented in three prompt styles (chat history, email, generic). Two web agent frameworks (Browser-Use, generating fine-grained actions; AutoGen, using compressed high-level steps) are coupled with three OpenAI LLM backbones (gpt-4o, o3, o4-mini) to execute these tasks on live sites. Every action in the generated trace is audited by an LLM-Judge (gpt-4o-mini) using a structured prompt, which classifies each step into a 2×2 taxonomy: explicit/implicit × content/behavioral oversharing. Metrics include total oversharing occurrences, oversharing rate per action, and binary task success. A comparative condition removes `Sirrelevant` from prompts (via claude-3.7-sonnet) before agent execution to test the privacy-utility alignment hypothesis.

## Key Results
*   Behavioral oversharing (clicks, navigation) dominates content oversharing by a factor of 5× across frameworks and models.
*   Implicit oversharing increases with model capability; gpt-4o embeds task-irrelevant preferences into queries and actions more frequently than o3.
*   Input sanitization (removing task-irrelevant information) improves task success rates by up to 17.9%, demonstrating that privacy preservation can enhance utility.

## Why This Works (Mechanism)

### Behavioral Channel Dominance
Web agents disclose more task-irrelevant information through observable actions (clicks, scrolls, navigation patterns) than through typed text. The mechanism involves the agent's action trace encoding sensitive attributes via the semantics and patterns of UI interactions (e.g., clicking a "Divorce Party Supplies" filter). Longer, fine-grained traces (Browser-Use) increase total disclosure volume, while compressed frameworks (AutoGen) concentrate risk per step. Passive observers like website analytics can infer sensitive attributes from these behavioral patterns without needing explicit textual mentions. Evidence shows a 5× ratio of behavioral to content events (e.g., 905 vs. 182 on Amazon with gpt-4o). The risk breaks down if agents operate in text-only environments or if all actions are encrypted/hidden from observers.

### Implicit Oversharing in Advanced Models
More capable LLMs (e.g., gpt-4o) exhibit higher rates of implicit oversharing by semantically embedding task-irrelevant information into queries and navigation patterns. Advanced reasoning allows agents to propagate `Sirrelevant` through context, creating action sequences from which observers can deduce sensitive attributes (e.g., inferring "single mom" from "divorced") without direct mention. This occurs because stronger models maintain richer contextual summaries and anticipate unstated preferences. Evidence: gpt-4o generates 45 implicit behavioral events vs. 8 for o3 on Amazon. The mechanism fails if models are fine-tuned to avoid context augmentation or if tasks require no inferential reasoning beyond literal instruction.

### Input Sanitization Alignment
Removing task-irrelevant information from the user prompt before agent execution improves task success. The mechanism is that sanitization reduces cognitive noise, allowing the agent to focus exclusively on task-relevant attributes. This prevents distraction-induced incorporation of `Sirrelevant` into actions and streamlines decision-making, avoiding unnecessary navigation paths that also leak information. Evidence: Table 4 shows success rate increases up to +17.9% after sanitization (e.g., Browser-Use chat: 100% vs. 82.1% baseline). This alignment breaks down if task completion genuinely requires `Sirrelevant` (e.g., a health condition determining product suitability), though the paper argues typical shopping tasks do not.

## Foundational Learning

*   **Concept:** Contextual Integrity (Nissenbaum, 2004/2009)
    *   **Why needed:** Provides the normative framework that frames agentic oversharing as a violation of contextual norms on the web, where users expect only task-relevant information to flow to third parties.

*   **Concept:** SPILLage Taxonomy (2×2: Channel × Directness)

## Architecture Onboarding

**Component map:**
User Prompt (P) -> Web Agent (W) -> Action Trace (A) -> Passive Observer (O) & Evaluation Module (LLM-Judge) -> Metrics Engine

**Critical path:**
1.  User provides P (contains task + mixed `Srelevant`/`Sirrelevant`) to agent W.
2.  Agent parses P, accesses resources, and begins website navigation.
3.  Agent executes multi-step interaction, generating trace A (actions: types, clicks, scrolls).
4.  O records A.
5.  For each action a ∈ A, LLM-Judge receives (a, `Sirrelevant`, agent’s goal/memory) and returns JSON with violation category (CE, CI, BE, BI).
6.  Metrics Engine aggregates Occurrences, Oversharing Rate, Task Success.

**Design tradeoffs:**
*   **Browser-Use:** Fine-grained actions → longer traces, higher absolute oversharing volume but lower per-step risk; more human-like but exposes more behavioral data.
*   **AutoGen:** High-level compressed steps → shorter traces, lower total oversharing but higher per-step risk; efficient but may concentrate disclosure.
*   **LLM-Judge:** Scalable but relies on prompt design; may miss subtle implicit patterns; requires accurate `Sirrelevant` labels.

**Failure signatures:**
*   Behavioral oversharing rate >0.3 per step (e.g., AutoGen generic on Amazon: 1.03) indicates agents use navigation to leak.
*   Implicit oversharing spikes with stronger models (gpt-4o > o3) suggest reasoning-based propagation.
*   Prompt-level mitigation increasing oversharing (58.9% → 86.0%) signals naive instructions backfire.
*   Task success below 80% with high oversharing suggests privacy-utility misalignment.

**First 3 experiments:**
1.  **Baseline Characterization:** Run 180 tasks × 2 frameworks × 3 models on Amazon/eBay. Measure Occurrences and Oversharing Rate for all four taxonomy categories. Verify behavioral dominance (~5×).
2.  **Prompt-Level Mitigation Test:** Add system instruction "do not utilize irrelevant information" to agent. Compare oversharing rates to baseline. Quantify change; expect increase.
3.  **Input Sanitization Utility Test:** Automatically strip `Sirrelevant` from prompts (using claude-3.7-sonnet). Re-run evaluation and measure task success delta. Expect improvement up to +17.9%.

## Open Questions the Paper Calls Out

*   **Open Question 1:** What specific mechanisms within web agent architectures cause the agent to select task-irrelevant information from the user context for inclusion in observable actions (both content and behavioral)?
    *   **Basis in paper:** [explicit] The paper states that "Neither Browser-Use nor AutoGen separates task-relevant from task-irrelevant information before acting" and shows different models exhibit distinct oversharing profiles. The failure of naive prompt-level mitigation is noted.
    *   **Why unresolved:** The paper diagnoses that oversharing stems from framework design and model-specific reasoning but does not isolate the precise decision points (e.g., during action planning, memory summarization) where irrelevant attributes are selected.
    *   **What evidence would resolve it:** Ablation studies or Mechanistic Interpretability analysis pinpointing when `Sirrelevant` is incorporated into the action output.

*   **Open Question 2:** How do oversharing patterns generalize across different model families (e.g., open-weight models) and diverse, high-stakes domains beyond e-commerce?
    *   **Basis in paper:** [inferred] Evaluation is limited to OpenAI models and e-commerce. Authors state this as a limitation and suggest generalization to healthcare/legal.
    *   **Why unresolved:** Findings may not hold for models with different training/safety, and e-commerce personas may not capture sensitivity/structure of healthcare or legal contexts.
    *   **What evidence would resolve it:** Large-scale benchmark replication across multiple model families on new domain-specific benchmarks (e.g., healthcare portal tasks).

*   **Open Question 3:** To what extent does behavioral oversharing enable an observer to reconstruct sensitive user attributes with higher fidelity than content oversharing alone, and what specific behavioral patterns are most diagnostic?
    *   **Basis in paper:** [explicit] Framework finds behavioral oversharing dominates content by 5×, but does not quantify empirical inference success from traces.
    *   **Why unresolved:** Paper detects when an action *might* imply oversharing via LLM-judge but does not measure real-world observer inference probability.
    *   **What evidence would resolve it:** A user study/simulation where observers infer `Sirrelevant` attributes from anonymized action traces (with content scrubbed).

*   **Open Question 4:** Can input-stage sanitization be fully automated with high fidelity and remain robust to diverse, nuanced user contexts where the boundary between relevant and irrelevant is ambiguous?
    *   **Basis in paper:** [explicit] Manual `Sirrelevant` removal improves success, but was done with manual verification. Presented as a direction, not solved.
    *   **Why unresolved:** Manual verification indicates automated classification is non-trivial. The task-specific definition of `Sirrelevant` can be subjective/context-dependent.
    *   **What evidence would resolve it:** Development and evaluation of an automated `Sirrelevant` classifier on a held-out set of diverse prompts, measured by dual metrics: task success preservation and oversharing reduction.

*   **Open Question 5:** Why do production commercial web agents exhibit drastically different oversharing behaviors on the same tasks, and what architectural differences explain this variance?
    *   **Basis in paper:** [explicit] Appendix D shows Perplexity Comet frequently overshares by pasting dialogues into search bars, while Brave AI Browsing and ChatGPT Atlas do not. Called a direction for future work.
    *   **Why unresolved:** Commercial systems are black boxes. Difference could be due to backbone LLM, system prompts/guardrails, pre-action filtering, or action space abstraction.
    *   **What evidence would resolve it:** Controlled component-level analysis: reverse-engineering documentation, mimicking commercial stacks with open-source frameworks, or A/B testing single variables.

## Limitations
*   **Agent Implementation Gaps:** Exact framework versions, system prompts, and parameters (e.g., Browser-Use's `MultimodalWebSurfer` settings) are not fully specified, critically affecting action granularity and oversharing volume.
*   **LLM-Judge Calibration:** The auditor's (gpt-4o-mini) reliability for detecting *implicit* behavioral leaks on dynamic site layouts is unverified; false positives/negatives could skew results.
*   **Ecological Validity:** Findings are limited to synthetic shopping tasks on two sites; oversharing in complex, multi-site, or authenticated high-stakes domains (healthcare, finance) is unknown.

## Confidence
*   **Behavioral Oversharing Dominance:** High. Strong, repeated empirical evidence (5× ratio) across frameworks and models.
*   **Taxonomy (2×2) as Complete Characterization:** Medium. Effectively categorizes observed leaks, but weak correlation with prior work hints at potential blind spots.
*   **Input Sanitization Aligns Privacy & Utility:** Low-Medium. Evidence is promising but constrained to narrow, single-purpose shopping tasks; effectiveness likely degrades for complex, context-dependent goals.

## Next Checks
1.  **Reproduce Baseline Parameters:** Extract and document the exact `Browser-Use` and `AutoGen` initialization code, system prompts, and step limits from the official repository. Run a calibration batch (n=10) to confirm the reported 5× behavioral:content ratio.
2.  **Judge Calibration Study:** Manually annotate a random sample of 100 judged action steps (50 explicit, 50 implicit) for all four categories. Compute Cohen's Kappa against the LLM-Judge outputs. If agreement <0.8, refine the judge's prompt with counter-examples.
3.  **Cross-Domain Portability Test:** Adapt the 180 tasks to a different high-stakes domain (e.g., "find a doctor accepting specific insurance" on a healthcare site). Re-run the baseline and sanitized conditions to test if the utility gain (+17.9%) and oversharing pattern hold.
