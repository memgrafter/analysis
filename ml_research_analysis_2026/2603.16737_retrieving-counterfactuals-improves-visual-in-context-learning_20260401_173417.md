# Retrieving Counterfactuals Improves Visual In-Context Learning

## Quick Facts
- **arXiv ID:** 2603.16737
- **Source URL:** https://arxiv.org/abs/2603.16737
- **Reference count:** 40
- **Primary result:** CIRCLES boosts VLM in-context learning by retrieving counterfactual demonstrations via attribute-guided composed image retrieval, achieving significant accuracy gains over standard similarity-based methods on fine-grained classification and VQA benchmarks.

## Executive Summary
Vision-language models (VLMs) struggle with fine-grained attribute reasoning during in-context learning (ICL) because standard retrieval selects examples that are correlated but not causally relevant. CIRCLES addresses this by generating counterfactual demonstrations: it uses the VLM to identify key attributes from the query, synthesizes captions that intervene on those attributes, retrieves matching images via composed image retrieval (CIR), and merges these with standard nearest-neighbor examples. Evaluated on CUB, Flowers, OK-VQA, and VizWiz with Gemma3 and Qwen2.5-VL backbones, CIRCLES consistently outperforms RICES, MUIER, and MMICES, with larger gains for smaller models and under data scarcity. The method highlights the value of causal contrast in ICL.

## Method Summary
CIRCLES is a test-time retrieval augmentation method. For a query image and question, it first prompts the backbone VLM to extract a ranked list of discriminative attribute-value pairs. For each attribute, the VLM generates a counterfactual caption describing the image with that attribute changed to a different plausible value. Using composed image retrieval (CIR), it scores all training candidates by summing image-caption similarity (via CLIP) and, for VQA, question-question similarity. The top examples per attribute form the *causal* set. Separately, standard image-only retrieval provides a *correlational* set. The two sets (total budget 32) are merged into a prompt, which the backbone VLM uses to generate the answer. The approach requires no training and works with any VLM.

## Key Results
- On CUB (fine-grained bird classification), Gemma3-4B with CIRCLES achieves **71.97%** accuracy vs. **65.40%** for RICES.
- On Flowers, it reaches **93.32%** exact match vs. **86.70%** for RICES.
- On OK-VQA, it obtains **31.27%** exact match vs. **26.65%** for RICES, with up to **16.28%** relative improvement when 75% of training data is removed.

## Why This Works (Mechanism)
### Mechanism 1: Attribute-Guided Intervention Identification
- **Claim:** CIRCLES improves VLM reasoning by identifying key visual attributes that are causally relevant to the query answer.
- **Mechanism:** The backbone VLM is prompted to extract a ranked list of succinct attribute-value pairs (e.g., "belly pattern: solid") from the query image and question. These attributes serve as intervention points for generating counterfactual scenarios.
- **Core assumption:** The VLM can reliably identify attributes that are semantically meaningful and discriminative for the task, even without explicit attribute supervision.
- **Evidence anchors:** [section 3.2] defines the extraction process; [section 4.6, Table 6] shows modest but consistent improvements when using ground-truth dataset attributes instead of extracted ones, supporting that attribute quality matters.
- **Break condition:** Extracted attributes are non-discriminative (e.g., generic like "small size") or irrelevant to the classification criteria, leading to counterfactuals that do not isolate causal factors.

### Mechanism 2: Counterfactual Caption Synthesis for Composed Retrieval
- **Claim:** Generating text descriptions that describe the query image under an attribute intervention (do(a_i = v'_i)) enables retrieval of visually similar images that differ only in that targeted attribute.
- **Mechanism:** For each identified attribute, the VLM synthesizes a "counterfactual caption" that modifies the attribute while keeping other aspects constant. This caption, combined with the query image's original embedding, is used in a composed image retrieval (CIR) scoring function (image-caption similarity + question-question similarity) to find training images matching the counterfactual description.
- **Core assumption:** Textual descriptions of unrealized attribute states can be reliably linked to real images in the training set that visually exemplify those states, effectively creating "nearest neighbors" in a counterfactual direction.
- **Evidence anchors:** [section 3.2] defines the CIR scoring function; [section 4.5, Table 2] shows that adding a question-question similarity term improves OK-VQA performance; [section 4.5] demonstrates that OSrCIR (direct caption synthesis) outperforms CIReVL (caption editing), linking caption quality to gains.
- **Break condition:** The CIR module fails to retrieve images that are both visually faithful to the counterfactual caption *and* semantically relevant (i.e., both similarity scores are not simultaneously high), yielding irrelevant or misleading counterfactual examples.

### Mechanism 3: Complementary Demonstration Construction (Causal + Correlational)
- **Claim:** Merging counterfactual examples (from CIR) with standard nearest-neighbor examples (from IR) creates a demonstration set that teaches the VLM both prototypical concepts and attribute-level contrasts, reducing reliance on spurious correlations.
- **Mechanism:** The final in-context set R = R_causal ∪ R_corr combines (a) top-k images from standard image-only retrieval (R_corr) that provide globally similar, realistic examples, and (b) top-k images from composed retrieval for each intervened attribute (R_causal) that highlight the effect of specific attribute changes.
- **Core assumption:** VLMs in ICL benefit from a mix of positive/typical examples (IR) and contrastive/exceptional examples (CIR) to disentangle causal features. IR alone risks reinforcing dataset biases; CIR alone may lack coherent class prototypes.
- **Evidence anchors:** [abstract] states the merging strategy; [section 3.4] defines the final set; [section 4.6, Table 9] ablation shows IR+CIR consistently outperforms IR-only and CIR-only; [section 4.4, Figure 4] shows gains grow under information scarcity where IR neighbors become less reliable.
- **Break condition:** The fixed demonstration budget (K=32) is too small to include enough high-quality examples from both IR and CIR, leading to noise overwhelming signal. Also, if CIR retrievals are consistently poor, adding them degrades performance.

## Foundational Learning
- **Retrieval-Augmented In-Context Learning (RA-ICL)**  
  *Why needed:* CIRCLES builds on RA-ICL, where a model's test-time predictions are conditioned on dynamically retrieved (image, question, answer) tuples. Changing the retrieval scoring function directly changes the prompt's demonstration set.  
  *Quick check:* If you change the retrieval scoring function, which part of the model's input changes? → The set of demonstration examples in the prompt.

- **Composed Image Retrieval (CIR)**  
  *Why needed:* The core innovation uses CIR—retrieving images based on a *combination* of a reference image and a *modification text* (e.g., "change belly to solid")—to approximate counterfactuals.  
  *Quick check:* How does the query for composed retrieval differ from standard image retrieval? → Standard uses only an image; CIR uses an image plus text describing the desired change.

- **Counterfactual Reasoning (Informal)**  
  *Why needed:* The paper's thesis is that showing a model "what would this image look like if attribute X were different?" helps it learn X's causal role.  
  *Quick check:* What is the key difference between retrieving a *similar* bird image and retrieving a bird image where only the *belly pattern* has been changed? → The latter explicitly contrasts the target attribute while keeping other factors constant.

## Architecture Onboarding
Component map: Query (I_q, Q_q) → Attribute Extractor (VLM) → Counterfactual Generator (VLM per attribute) → Composed Retriever (CIR scoring) → Standard Retriever (IR scoring) → Context Integrator (merge R_causal, R_corr) → VLM Inference (answer generation)

Critical path: Query → Attribute extraction → (for each attribute: caption synthesis → CIR scoring) → IR scoring → merge → VLM answer. Failures often occur at Attribute Extraction or CIR Scoring.

Design tradeoffs:
- Computational: CIRCLES adds ~10% token overhead vs. RICES due to multiple VLM calls; tradeoff: overhead for robustness under data scarcity.
- CIR Implementation: OSrCIR (direct caption synthesis) vs. CIReVL (caption edit); OSrCIR yields better retrieval quality but may be more computationally intensive per call.
- Budget Allocation: More CIR examples help, but optimal split between IR and CIR depends on total budget and dataset; breadth (more attributes) vs. depth (more per attribute) tradeoff.

Failure signatures:
1. Non-discriminative attributes: Extracted attributes are vague (e.g., "small bird") and do not vary across classes, making counterfactuals uninformative.
2. Weak CIR alignment: Retrieved images for a counterfactual caption are visually disaligned (e.g., wrong species, changed background), providing misleading contrast.
3. Query-agnostic CIR: If question-question similarity (s_txt) is omitted for VQA, CIR retrieves images matching the edited visual description but answering a different question type, confusing the VLM.

First three experiments:
1. **Attribute sanity check:** Run attribute extraction on 20 random CUB queries. Manually inspect if top 1-2 attributes are valid discriminative features (e.g., "black head markings"). If >50% are vague ("bird", "small"), refine the VLM prompt.
2. **CIR retrieval validation:** For a fixed query and its top attribute, generate a counterfactual caption. Retrieve top-5 CIR candidates. Visually inspect if >3 candidates match the caption's edited attribute while resembling the query in other aspects. If not, the CIR scoring or caption may be flawed.
3. **IR vs. CIR contribution test:** On a small subset (e.g., 50 CUB queries), run three pipelines: IR-only (RICES), CIR-only (only R_causal), and full CIRCLES. Expect: CIR-only performs poorly on fine-grained classification (lacks prototypes), IR-only is decent, full CIRCLES best. If CIR-only is >IR-only, CIR might be retrieving near-identical images, not true counterfactuals.

## Open Questions the Paper Calls Out
1. **How can the computational overhead of CIRCLES be reduced while maintaining its performance gains?**  
   *Basis:* [explicit] Appendix B discusses efficiency and suggests precomputed embeddings or joint encoders as future work.  
   *Why unresolved:* Current implementation requires multiple VLM calls for attribute extraction and caption generation, which may hinder scalability.  
   *What evidence would resolve it:* Implement a more efficient variant (e.g., with precomputed attribute-aware embeddings) and compare inference time and accuracy against the original on large datasets.

2. **Do the counterfactual examples retrieved by CIRCLES correspond to valid causal interventions, and does enforcing causal validity improve ICL performance?**  
   *Basis:* [inferred] The authors state that CIRCLES does not perform formal causal identification but approximates interventions via CIR.  
   *Why unresolved:* It is unclear whether the retrieved examples truly isolate attribute effects or exploit spurious correlations, limiting interpretability and robustness.  
   *What evidence would resolve it:* Design a controlled study with known causal structures (e.g., synthetic datasets with ground-truth causal attributes) to measure the causal validity of retrieved examples and correlate with downstream accuracy.

3. **What is the optimal balance between standard retrieval and counterfactual retrieval in CIRCLES for different tasks and model scales?**  
   *Basis:* [inferred] Figure 6 shows performance varies with the number of IR and CIR examples, and optimal allocation shifts with budget.  
   *Why unresolved:* The paper only explores a limited set of hyperparameters; a systematic understanding across diverse scenarios is lacking.  
   *What evidence would resolve it:* Conduct a comprehensive grid search over IR/CIR ratios on multiple datasets and model sizes, and develop a heuristic or learned allocator based on task characteristics.

4. **How sensitive is CIRCLES to the quality of attribute extraction, and can we build more robust attribute selectors?**  
   *Basis:* [inferred] Appendix C shows failures due to non-discriminative attributes, and Appendix D shows modest gains with ground-truth attributes.  
   *Why unresolved:* The VLM-based attribute extraction is a potential bottleneck, but its impact is not thoroughly quantified.  
   *What evidence would resolve it:* Evaluate CIRCLES with various attribute extraction methods (e.g., different prompts, models, or supervised attribute predictors) and measure performance correlation with attribute discriminativeness scores.

## Limitations
- **Implementation gaps:** Missing OSrCIR system prompt, default number of attributes, and similarity normalization details; classification prompt requires supplementation from the appendix.
- **Attribute extraction reliability:** VLM may produce non-discriminative attributes (e.g., "small"), leading to uninformative counterfactuals.
- **CIR retrieval dependency:** Success hinges on caption plausibility and image-caption alignment; failures yield misleading contrasts.
- **Foundational anchoring:** Limited direct citations to CIR/counterfactual ICL foundations indicate novelty but weaker connection to established validation literature.

## Confidence
- **Attribute-guided intervention:** Medium – ground-truth attribute ablation yields gains, but reliability of auto-extracted attributes is not fully validated.
- **Counterfactual caption synthesis:** Medium – OSrCIR outperforms CIReVL, showing caption quality matters; however, human evaluation of counterfactual plausibility is absent.
- **Complementary demonstrations (IR+CIR):** High – consistent ablations across datasets prove synergy, though optimal budget split remains dataset-specific.
