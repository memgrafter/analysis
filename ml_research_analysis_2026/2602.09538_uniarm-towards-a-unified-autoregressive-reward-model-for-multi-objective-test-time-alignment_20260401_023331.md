# UniARM: Towards a Unified Autoregressive Reward Model for Multi-Objective Test-Time Alignment

## Quick Facts
- arXiv ID: 2602.09538
- Source URL: https://arxiv.org/abs/2602.09538
- Reference count: 38
- Primary result: UniARM introduces MoSLoRA for unified multi-objective reward modeling, achieving +18.5% Hypervolume and +30.2% Mean Inner Product over PARM on safety alignment, and enabling weak-to-strong guidance without extra latency.

## Executive Summary
UniARM addresses the challenge of aligning large language models (LLMs) with multiple, potentially conflicting objectives at test time. Instead of training separate reward models or entangling parameters, it unifies them via a single autoregressive reward model that uses Preference-Modulated & Shared LoRA (MoSLoRA). This architecture extracts shared features in a preference-agnostic manner and then applies a modulation module that conditionally transforms these features using a mixed preference vector, enabling precise trade-off control. Experiments on safety and helpfulness tasks show substantial improvements over prior work (e.g., +18.5% Hypervolume) and demonstrate that a small UniARM (7B) can effectively guide a much larger frozen LLM (65B) without increasing inference cost. The work opens avenues for efficient, flexible multi-objective alignment.

## Method Summary
UniARM proposes a unified reward modeling approach for test-time alignment. The core is MoSLoRA, which combines a shared LoRA-based feature extractor with a preference-modulated affine transformation. The shared module captures common representations across objectives, avoiding the feature entanglement that plagues independent or concatenated reward models. A modulation module generates scale (γ) and shift (β) parameters from a continuous preference vector, which are then applied feature-wise to the shared representation. This design allows the same reward model to dynamically adapt to any trade-off specified by the preference vector, eliminating the need for multiple specialized models. The reward model is trained autoregressively and can be used to guide LLM generation via methods like best-of-n or reward-weighted decoding.

## Key Results
- Outperforms PARM on safety alignment: Hypervolume +18.5%, Mean Inner Product +30.2%.
- Weak-to-strong guidance: a 7B UniARM directing a frozen 65B LLM yields HV/MIP improvements of 9.1%/6.8% (safety) and 5.4%/10.7% (assistant).
- No additional parameters or inference latency compared to using a single reward model.

## Why This Works (Mechanism)
UniARM’s effectiveness stems from its decoupled handling of shared and preference-specific information. The shared LoRA module learns a common representation that captures features relevant to all objectives, reducing redundancy and preventing the mixing of preference-specific signals that occurs when objectives share entangled parameters. The modulation module then applies simple affine transformations (scaling and shifting) to these shared features, conditioned on a mixed preference vector. This conditioning allows the model to re-weight and re-calibrate the shared features along different dimensions as needed for each objective combination, enabling fine-grained control over trade-offs. Because the modulation is lightweight and operates on extracted features rather than modifying the base model's weights, it introduces negligible overhead and can be combined with any frozen LLM at test time.

## Architecture Onboarding
**Component Map:**  
Input Token Sequence -> Base LLM (frozen) -> Shared LoRA Feature Extractor -> Modulation Layer (preference-conditioned affine) -> Reward Prediction Head

**Critical Path:**  
During inference, the input text is first encoded by the base LLM. A shared LoRA module (applied to selected layers) extracts a generic feature representation. A preference vector (mixed for desired trade-offs) is fed to the modulation module, which produces scaling (γ) and shifting (β) parameters. These are applied element-wise to the shared features, yielding a modulated representation. Finally, the reward head maps this representation to the final reward output (e.g., a token representing the score). The process introduces no extra steps beyond a standard reward model forward pass.

**Design Tradeoffs:**  
- *Parameter Efficiency vs. Capacity*: Using LoRA keeps added parameters tiny, but the low-rank bottleneck may limit the richness of preference-specific adaptations.  
- *Shared Representation vs. Specificity*: A single shared feature extractor simplifies training but might discard nuances unique to certain objectives; the affine modulation attempts to recover those at test time.  
- *Frozen Base vs. Adaptability*: Freezing the LLM reduces compute and avoids catastrophic interference, but may restrict adaptation if the base model’s features are misaligned with reward objectives.

**Failure Signatures:**  
- Modulation outputs degenerate values (e.g., γ ≈ 0, β ≈ 0) → the model behaves like a generic reward model ignoring preferences.  
- Large variance in γ across objectives → potential overfitting or unstable trade-off control.  
- Shared features collapse to near-constant → modulation cannot recover meaningful diversity, leading to poor hypervolume.

**First Experiments:**  
1. **Ablation of Modulation**: Compare full UniARM against a variant without the modulation module (i.e., only shared features → reward head) to quantify the contribution of preference conditioning.  
2. **Preference Dimensionality Scaling**: Train UniARM with mixed preference vectors of varying dimensions (k = 2, 3, 4, 5) on a dataset with that many objectives, measuring hypervolume and MIP to assess scalability.  
3. **Cross-Domain Generalization**: Apply UniARM trained on safety objectives to a new domain (e.g., balancing conciseness vs. informativeness) using only a small amount of new preference data, to test transferability of the shared representation.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How does UniARM perform on multi-objective alignment tasks beyond human preference, such as balancing creativity versus factual accuracy or diversity versus consistency?
- Basis in paper: [explicit] The conclusion states: "Future work could investigate its effectiveness in other tasks involving trade-offs among creativity and factual accuracy, diversity and consistency, as well as reasoning performance and computational cost."
- Why unresolved: All experiments focus on safety alignment and helpful assistant tasks; no evaluation on other objective types exists.
- What evidence would resolve it: Apply UniARM to datasets or benchmarks that measure creativity/factuality trade-offs, diversity/consistency, etc., and compare HV/MIP or task-specific metrics against relevant baselines.

### Open Question 2
- Question: What theoretical mechanism allows MoSLoRA to mitigate feature entanglement compared to PBLoRA?
- Basis in paper: [inferred] The paper claims MoSLoRA "alleviates feature entanglement" by using a shared feature extractor and modulation, but provides no formal analysis.
- Why unresolved: Without theory, it is unclear whether the architecture inherently prevents entanglement or if gains are incidental; this limits understanding and further improvements.
- What evidence would resolve it: Provide mathematical analysis of gradient flows, or visualization (e.g., t-SNE) of feature spaces showing separation of preference-specific signals in MoSLoRA vs mixing in PBLoRA.

### Open Question 3
- Question: How does UniARM handle a larger number of preference dimensions (k > 3) in terms of Pareto front quality and parameter overhead?
- Basis in paper: [inferred] Experiments only cover up to three dimensions (helpfulness, harmlessness, humor). The MoSLoRA design is parameter-efficient, but its behavior with many objectives is untested.
- Why unresolved: High-dimensional preference spaces may lead to sparse data, optimization difficulties, and degraded control granularity; also, the mixed preference vector representation may become less expressive.
- What evidence would resolve it: Conduct experiments with synthetic or real datasets containing 4–6 preference dimensions, measuring hypervolume, MIP, and coverage; analyze parameter scaling.

### Open Question 4
- Question: Can UniARM effectively guide significantly larger base models (e.g., >70B parameters) while retaining its efficiency gains?
- Basis in paper: [inferred] The paper shows a 7B UniARM guiding a frozen 65B model (weak-to-strong). However, larger model scales (e.g., 70B, 100B, or 1T) are not explored.
- Why unresolved: The effectiveness of a relatively small reward model may depend on the base model size; scaling might require larger reward models to capture nuanced preferences.
- What evidence would resolve it: Train UniARM on a fixed small size (e.g., 7B) and test it guiding base models of 70B, 100B, and beyond; evaluate alignment gains and check if performance plateaus or degrades.

## Limitations
- Evaluation scope limited to two multi-objective scenarios (safety and assistant) on a single model family (Llama); generalization to other trade-offs unknown.
- No statistical significance testing (e.g., across multiple random seeds) or confidence intervals reported; reliability of results uncertain.
- Weak-to-strong guidance claim lacks comparison to standard steering methods (e.g., DPO, RLAIF) and does not disclose absolute baseline performance, making the magnitude of improvement hard to contextualize.
