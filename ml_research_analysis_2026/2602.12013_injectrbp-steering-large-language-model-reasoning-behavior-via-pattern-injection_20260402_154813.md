# InjectRBP: Steering Large Language Model Reasoning Behavior via Pattern Injection

## Quick Facts
- **arXiv ID:** 2602.12013  
- **Source URL:** https://arxiv.org/abs/2602.12013  
- **Reference count:** 40  
- **Primary result:** Parameter-free pattern injection improves LLM reasoning accuracy by up to 8.67% on challenging benchmarks (GPQA, MATH, AIME25, MBPP) using Qwen3 models.

## Executive Summary
Large language models (LLMs) use chain-of-thought (CoT) reasoning to solve complex problems, but prompt-based adjustments often lack systematic analysis of behavioral patterns. This paper shows that LLMs adapt their reasoning behaviors to different question types, and these patterns correlate with answer quality. By structurally injecting effective behavior patterns—either imitating past correct answers (InjectCorrect) or optimizing via reinforcement learning (InjectRLOpt)—the authors steer the model's reasoning trajectory without any parameter updates. Evaluations on Qwen3 models across multiple reasoning benchmarks yield accuracy gains of up to 5.34% and 8.67%, demonstrating that behavioral pattern steering is a powerful, training-free approach to enhance LLM reasoning.

## Method Summary
The proposed methods operate entirely at inference time. First, reasoning traces from a dataset are segmented using double-newline delimiters and classified into behavior types (e.g., Planning, Verification) via predefined control phrases. This yields behavior chains (sequences of behavior markers). Two distribution-building strategies are then employed: (1) InjectCorrect computes conditional frequencies of next behaviors given the last $n-1$ behaviors, using only chains that led to correct answers. (2) InjectRLOpt formulates behavior selection as a Markov decision process where states are $(n-1)$-gram contexts, actions are next behaviors, and rewards are terminal accuracy. A value function $Q(s,a)$ is estimated from empirical returns, and a reliability-aware softmax policy samples actions, down-weighting low-visitation pairs. During test-time generation, after each reasoning segment, the system samples the next behavior from the target distribution and prepends the corresponding control phrase to the prompt, thereby steering the subsequent reasoning path.

## Key Results
- InjectCorrect improves accuracy by up to **5.34%** on average across datasets and model scales.
- InjectRLOpt achieves gains up to **8.67%**, with consistent improvements on GPQA, MATH, AIME25, and MBPP.
- Cross-domain pattern injection generally harms performance, indicating that effective patterns are task-specific.

## Why This Works (Mechanism)
### Mechanism 1: Adaptive Behavior Distributions
- **Claim:** Models adapt reasoning behavior patterns to question types, and these patterns correlate with answer quality.
- **Mechanism:** The model’s generative policy implicitly learns to emit sequences of behavior markers (e.g., repeated “Wait” for verification) that are effective for a given task. Different problem types favor different pattern distributions.
- **Core assumption:** The distribution of behavior patterns is predictive of success; patterns frequent in correct answers for a task are beneficial.
- **Evidence anchors:** 
  - Abstract: “We observe that models exhibit adaptive distributions of reasoning behaviors when responding to specific types of questions.”
  - Section 5.2: Table 1 shows dataset‑specific top patterns (e.g., EEE on GPQA vs. CCC on AIME25).
  - Corpus: Neighboring work on activation steering supports malleability, but adaptation evidence is internal.

### Mechanism 2: Structural Injection Steers Trajectories
- **Claim:** Structurally injecting behavior patterns (via control phrases) steers the reasoning trajectory and influences final answer quality.
- **Mechanism:** At segment boundaries, the system samples the next behavior from a target distribution conditioned on recent history, then appends a control phrase (e.g., “Wait”) to prompt that behavior.
- **Core assumption:** The model reliably follows the control phrase and generates reasoning consistent with the prompted behavior.
- **Evidence anchors:**
  - Abstract: “structurally injecting these patterns can substantially influence the quality of the models’ reasoning processes and outcomes.”
  - Section 4.2: Formal definition of injection probability P(b|c) based on n‑gram frequencies.
  - Section 5.2: Table 3 shows accuracy changes when patterns are masked, demonstrating causal impact.

### Mechanism 3: Optimized Pattern Distribution via Data or RL
- **Claim:** Optimizing the behavior pattern distribution using historical data (InjectCorrect from correct answers, InjectRLOpt via reinforcement learning) improves accuracy without parameter updates.
- **Mechanism:** InjectCorrect uses conditional frequencies from correct chains. InjectRLOpt treats behavior selection as an MDP, estimates $Q(s,a)$ from empirical returns, and samples via reliability‑aware softmax.
- **Core assumption:** An optimized behavior distribution yields higher success; aligning the model’s on‑the‑fly selection with this distribution improves outcomes.
- **Evidence anchors:**
  - Abstract: Gains “up to 5.34% and 8.67%” for InjectCorrect and InjectRLOpt.
  - Section 4.3: Equations for InjectCorrect (Eq 10) and InjectRLOpt (MDP, Eq 12, reliability weight).
  - Section 5.2: Table 2 shows consistent improvements across datasets and model scales.

## Architecture Onboarding
- **Component map:**  
  Behavior Extractor → Pattern Analyzer → Injection Controller  
  (Value Estimator integrated within Pattern Analyzer for InjectRLOpt)
- **Critical path:**  
  1. Collect dataset of reasoning chains with correctness labels.  
  2. Extract behavior chains using Extractor.  
  3. Build target distribution: InjectCorrect → $P_{\text{corr}}(b|c)$; InjectRLOpt → estimate $Q(s,a)$, define $\pi(a|s)$ via reliability‑aware softmax.  
  4. Inference: generate CoT, after each segment use Controller to inject behavior; continue until conclusion.
- **Design tradeoffs:**  
  - **n‑gram order:** $n=3$ balances motif capture and sparsity; smaller $n$ misses motifs, larger $n$ suffers sparsity.  
  - **InjectCorrect vs InjectRLOpt:** InjectCorrect is simpler but context‑limited; InjectRLOpt uses context and RL but needs more data and hyperparameters ($\gamma$, $c$).  
  - **Reliability weight $f(N)$:** Regularizes noisy $Q$-values but introduces sensitivity to $c$.
- **Failure signatures:**  
  - Cross‑domain pattern injection hurts performance.  
  - Model ignores control phrases, so no behavior change occurs.  
  - Data sparsity leads to arbitrary injections for rare contexts.  
  - Spurious correlations: patterns frequent in correct answers may not be causative.
- **First 3 experiments:**  
  1. **Behavior pattern analysis (RQ1):** Compute top n‑grams across datasets to show adaptation (Table 1, Figure 2).  
  2. **Cross‑injection transfer (RQ2):** Inject patterns from one dataset into another to test domain specificity (Table 4).  
  3. **Performance evaluation (RQ3):** Compare InjectCorrect/InjectRLOpt vs. baseline across models/datasets, with hyperparameter ablation (Table 2, Table 5).

## Open Questions the Paper Calls Out
- **Question 1:** What more diverse behavior patterns (beyond 3‑grams) can be investigated to further improve reasoning?  
  *Basis:* Explicitly stated: “Due to computational constraints, our experiments and analyses only consider 3‑gram behavior patterns.”  
  *Why unresolved:* Longer or alternative pattern representations could yield gains but were not explored due to cost and sparsity.
- **Question 2:** Can post‑training techniques (supervised fine‑tuning, reinforcement learning) explicitly optimize reasoning behavior beyond test‑time injection?  
  *Basis:* Explicitly suggested: “Future work may employ post‑training techniques… to explicitly optimize the model’s reasoning behavior.”  
  *Why unresolved:* The paper only modifies behavior at inference; it’s unknown whether training to internalize patterns yields more fundamental improvements.
- **Question 3:** Do the observed behavior pattern adaptations generalize to other model families beyond Qwen3?  
  *Basis:* Inferred: Study exclusively uses Qwen3 models; no other architectures tested.  
  *Why unresolved:* Unclear if findings are specific to Qwen3 or general to LLMs.
- **Question 4:** How robust is the marker‑based behavior extraction to linguistic variations or non‑English contexts?  
  *Basis:* Inferred: Extraction relies on fixed English control phrases (Table 6); no coverage or cross‑lingual analysis.  
  *Why unresolved:* May miss behaviors not signaled by predefined markers or fail in multilingual settings.

## Limitations
- **Injection mechanics unspecified:** Exact token handling, marker selection, and context detection are not detailed.
- **Data splits and hyperparameters unknown:** Training/evaluation splits and baseline generation settings (temperature, top_p) are unreported.
- **n‑gram sparsity:** Rare contexts lead to unreliable sampling, especially for InjectRLOpt, limiting coverage and effectiveness.
