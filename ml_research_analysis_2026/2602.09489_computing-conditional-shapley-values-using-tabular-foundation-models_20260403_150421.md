# Computing Conditional Shapley Values Using Tabular Foundation Models

## Quick Facts
- **ArXiv ID**: 2602.09489
- **Source URL**: https://arxiv.org/abs/2602.09489
- **Reference count**: 0
- **Primary result**: TabPFN-based conditional Shapley value estimation achieves state-of-the-art accuracy with dramatic runtime reductions (days to hours).

## Executive Summary
Conditional Shapley values are a powerful but computationally intensive tool for explaining machine learning models, especially when features are dependent. This paper introduces the use of TabPFN, a tabular foundation model that leverages in-context learning, to approximate the conditional expectations required for Shapley values without retraining per coalition. Through extensive experiments on simulated and real datasets, the authors demonstrate that TabPFN, particularly in a separate regression scheme, often matches or exceeds the accuracy of existing methods while drastically reducing runtime. The approach makes conditional Shapley values practically feasible for larger tabular datasets.

## Method Summary
The paper tackles the challenge of computing conditional Shapley values, which requires estimating the contribution function v(S) = E[f(x) | x_S = x*_S] for all coalitions S. Traditional methods are slow because they require either sampling from conditional distributions or retraining models for each coalition. The proposed solution uses TabPFN, a pre-trained tabular foundation model, in two ways: (1) separate regression, where a distinct TabPFN model is trained (via in-context learning) for each coalition S using only the features in S; (2) surrogate regression, where a single TabPFN model is trained on an augmented dataset that includes all coalitions by masking features. The separate regression approach is more accurate but scales exponentially with the number of features, while surrogate regression is more scalable but may suffer from misaligned missingness patterns.

## Key Results
- TabPFN in separate regression consistently achieves the best or near-best accuracy on simulated and real datasets (e.g., lowest MSEv on Abalone).
- For non-smooth predictors (e.g., random forests), TabPFN is marginally less accurate than tree-based methods but with a fraction of the runtime (reducing computation from days to hours on Adult dataset).
- The separate regression formulation outperforms surrogate regression in most settings.

## Why This Works (Mechanism)
### Mechanism 1
**Claim**: TabPFN's in-context learning eliminates the need for retraining a separate model for each conditional expectation, drastically reducing computational time.
**Mechanism**: TabPFN is pre-trained on a synthetic prior over tabular datasets. At inference, it takes the entire training dataset (X_train, y_train) and a set of test points X_test as input in a single forward pass, using the training data as context to make predictions for X_test without any weight updates. For Shapley value estimation, this allows estimating v(S) = E[f(x) | x_S = x*_S] by conditioning on the features x_S and treating x_{\bar{S}} as missing, all within one forward pass per coalition S.
**Evidence**: Abstract states TabPFN overcomes computational hurdle by leveraging in-context learning. Section 3 describes the single forward pass and no retraining. Neighbor papers (e.g., ExplainerPFN) also explore tabular foundation models for zero-shot feature importance.
**Break condition**: If context size exceeds 50,000 (for v2.5), TabPFN cannot process the augmented dataset for surrogate methods. Performance may degrade if test data's missingness patterns are underrepresented in the synthetic pre-training prior.

### Mechanism 2
**Claim**: Separate regression using TabPFN per coalition yields higher accuracy than surrogate regression because it tailors the conditional model precisely to the features in S.
**Mechanism**: For each coalition S, a dedicated TabPFN model is trained (via in-context learning) using only the features in S from the original training data to predict f(x). This isolates the learning to the relevant conditional distribution p(x_{\bar{S}} | x_S). In contrast, surrogate regression trains one model on an augmented dataset where all coalitions are represented, but with artificially masked features, leading to a noisier learning signal for any specific S.
**Evidence**: Section 2.2 and 4 show that separately trained models consistently yield the best performance. Section 5 notes that separate regression with TabPFN performs best on the first three datasets.
**Break condition**: For very high-dimensional data (M large), the O(2^M) separate models become computationally intractable. If the predictive model f is non-smooth, tree-based separate regressors may match or exceed TabPFN's accuracy.

### Mechanism 3
**Claim**: TabPFN's ensemble of multiple forward passes stabilizes conditional expectation estimates.
**Mechanism**: By default, TabPFN produces predictions by averaging an ensemble obtained from multiple forward passes with slightly altered inputs (e.g., bootstrapped context, feature noising). This ensemble approximates Bayesian model averaging over the pre-trained prior, yielding more robust conditional mean estimates for v(S).
**Evidence**: Section 3 describes the ensemble. Section 4 shows that increasing the number of estimators from one to eight improves accuracy but at the cost of longer computation times.
**Break condition**: For stable, low-variance datasets, the ensemble may provide negligible gains, making single-estimator runs cost-effective.

## Foundational Learning
- **Shapley Values and Contribution Function**: The method computes Shapley values φ_j by evaluating the contribution function v(S)=E[f(x) | x_S = x*_S] for all coalitions S. Understanding equation (1) and the efficiency axiom is essential because it requires 2^M expectations. *Quick check*: Given f(x)=x₁x₂+ε with independent features, what is φ₁ for x*=(1,2) if v({1})=E[f(1,X₂)] and v({})=E[f(X₁,X₂)]?
- **Conditional Expectation Estimation Paradigms**: The paper contrasts Monte Carlo (sampling from p(x_{\bar{S}}|x_S)) vs. regression (learning g_S(x_S)≈E[f(x)|x_S]). TabPFN implements the latter. *Quick check*: Why might a parametric method (e.g., Gaussian copula) fail even if it correctly models the joint distribution but f is highly nonlinear?
- **In-Context Learning in Foundation Models**: TabPFN's core innovation: no gradient-based training at test time; the model "learns" the conditional mapping from the context (X_train, y_train) in one forward pass. *Quick check*: If TabPFN was pre-trained only on synthetic Gaussian data, what might happen when applied to a dataset with categorical features and complex dependencies?

## Architecture Onboarding
- **Component map**: Data handler -> Context constructor -> TabPFN predictor -> Shapley aggregator -> Evaluator
- **Critical path**: Load data & model f -> For each test point x* -> For each coalition S (separate) or once (surrogate) -> Build context for S -> Query TabPFN for v(S, x*) -> Aggregate into φ_j(x*) -> Evaluate metrics.
- **Design tradeoffs**:
  - Separate vs. Surrogate: Separate is more accurate (esp. smooth f) but O(2^M) models; surrogate uses one model but suffers from missingness pattern misalignment. Use separate when M≤12 and accuracy critical; surrogate only if M large and runtime paramount.
  - Ensemble size: 8 estimators default; use 1 if time-limited and data low-noise.
  - Version choice: v2.5-R (real-trained) may help if real data distribution differs from synthetic, but minimal differences; v2 is open-source and adequate.
  - Augmented vs. Direct surrogate: Always use augmented (mask features in context) because direct (mask in query only) fails due to unseen missingness patterns during pre-training.
- **Failure signatures**:
  - High MSEv with low runtime: Likely due to direct surrogate or missingness mismatch in augmented context. Check that augmented context size (2^M-2)*L ≤ 50,000 for v2.5.
  - Runtime explodes in surrogate augmented: Context size ~5e4 examples means each forward pass is costly; consider reducing L or using separate regression if M allows.
  - TabPFN predictions NaN or extreme: Context may have constant columns after masking; ensure at least some non-missing examples per feature in context.
  - Accuracy worse than simple LM/GAM: For non-smooth f (e.g., random forest), switch to tree-based separate regressors (CatBoost, RF).
- **First 3 experiments**:
  1. Replicate simulation (Gaussian, ρ=0.5, M=8, GAM f): Implement separate regression with TabPFN v2.5-D (1 estimator). Compute MAE vs. true Shapley. Expect MAE ~0.01–0.02.
  2. Test augmented surrogate on Abalonecont (M=7): Build augmented context with L such that (2^7-2)*L ≈ 5e4. Compare MSEv to separate regression. Expect worse MSEv (≥1.2) but faster than separate.
  3. Validate break condition for Adult (M=14): Attempt separate regression? M=14 → 16384 models—feasible but slow. Test surrogate augmented (by coalition size) to reduce context size. Expect MSEv ~0.03, close to CatBoost surrogate (0.026) but much faster (days vs. 35 days).

## Open Questions the Paper Calls Out
- **Question 1**: How can TabPFN be fine-tuned to better capture the column-wise missingness patterns that arise in the surrogate regression formulation? The authors suggest pre-training or fine-tuning on datasets with explicit missing data patterns.
- **Question 2**: Would increasing the allowable context size beyond 50,000 allow the augmented surrogate approach to achieve accuracy comparable to separate regression?
- **Question 3**: Can modifications to TabPFN’s architecture or pre-training close the accuracy gap for non-smooth predictive models while preserving its computational advantage?

## Limitations
- Exact data splits, baseline hyperparameters, and categorical encoding for Adult are not reported, affecting reproducibility.
- TabPFN v2.5 context limit (≤50k) restricts augmented surrogate to M≈10; separate regression scales as O(2^M) calls, limiting use beyond M≈14.
- For non-smooth f, TabPFN's accuracy is only marginally worse than tree-based methods; the accuracy-speed trade-off is not fully characterized.

## Confidence
- **High**: TabPFN eliminates retraining per coalition, drastically reducing runtime. (Supported by abstract, section 3, and empirical speedups.)
- **Medium**: Separate regression outperforms surrogate. (Consistently observed in simulation and real datasets with M≤11, but may fail for non-smooth f or high M.)
- **Medium**: Ensemble averaging stabilizes Shapley estimates, but data-dependent break-even not studied.
