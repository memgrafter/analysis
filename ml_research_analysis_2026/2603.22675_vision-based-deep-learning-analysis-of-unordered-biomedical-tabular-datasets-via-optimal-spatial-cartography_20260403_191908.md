# Vision-based Deep Learning Analysis of Unordered Biomedical Tabular Datasets via Optimal Spatial Cartography

## Quick Facts
*   **arXiv ID:** 2603.22675
*   **Source URL:** https://arxiv.org/abs/2603.22675
*   **Reference Count:** 40
*   **Primary Result:** Dynomap consistently outperforms classical and deep tabular baselines, achieving up to 18% higher accuracy and macro-F1 gains in multiclass cancer subtype classification and 8% in Parkinson’s detection.

## Executive Summary
Dynomap introduces a method to apply vision-based models, such as CNNs, to unordered biomedical tabular data by learning a task-optimized spatial layout for features. It assigns each feature a learnable 2D coordinate and uses an end-to-end differentiable rendering process to convert a sample's feature vector into an image. The spatial layout and predictive model are optimized jointly, allowing the arrangement to adapt to the specific prediction task. Across diverse biomedical datasets, Dynomap achieves superior classification performance and produces interpretable, biologically meaningful spatial organizations that validate through spatial statistics. The approach enables the use of powerful vision architectures on tabular data while providing insights into feature relationships.

## Method Summary
Dynomap transforms a tabular sample into an image via a differentiable renderer. Each of the G features has a learnable 2D coordinate. For a given sample, a gating layer modulates feature values. The renderer computes an image by summing Gaussian kernels centered at each feature's coordinate, with kernel width dynamically scaled by the gated feature magnitude. This image is processed by a CNN. The CNN's feature vector is concatenated with the gated tabular vector and fed to a classifier. The total loss combines the prediction loss (e.g., cross-entropy) with layout regularization terms (centering, spreading, repulsion) applied to the coordinates. All components—coordinates, CNN, classifier—are trained jointly. Training stops when feature coordinates stabilize (mean displacement below a threshold).

## Key Results
*   Dynomap outperformed classical (Random Forest, XGBoost) and deep (TabM, TabPFN) tabular baselines on multiple biomedical datasets, with up to 18% higher accuracy and macro-F1 gains.
*   Learned layouts exhibited non-random, class-specific feature clustering, validated by Moran's I and kNN purity metrics.
*   Spatial organizations were task-dependent; different classification objectives (e.g., binary cancer detection vs. multi-subtype classification) led to different feature arrangements for the same dataset.

## Why This Works (Mechanism)
### Mechanism 1: Differentiable Spatial Transformation
Dynomap converts unordered features into a spatially organized image. Each feature is assigned a learnable 2D coordinate. A sample's feature values modulate Gaussian kernels centered at these coordinates; their sum creates a continuous spatial map (image). This rendering is differentiable, allowing gradients to update feature coordinates during backpropagation. The core assumption is that features with correlated predictive signals should be placed nearby, enabling CNN filters to capture local interactions. **Break condition:** Non-differentiable rendering (e.g., hard nearest-neighbor assignment) would block gradient flow to coordinates.

### Mechanism 2: Task-Adaptive Layout via Joint Optimization
The feature layout and classifier are optimized simultaneously under a unified loss. The loss includes prediction error and regularization terms on coordinates (center, spread, repulsion). Gradients from the prediction loss propagate through the CNN and renderer to the coordinates, driving them to arrange in a way that minimizes task error. The core assumption is that a layout minimizing prediction loss will naturally cluster features important for the task. **Break condition:** Omitting or mis-weighting regularization terms can cause coordinate collapse (all features overlap) or random dispersion.

### Mechanism 3: Task-Specific Reorganization
Because the layout is optimized for a specific loss function, the gradient signals differ per task. Features critical for Task A will cluster, but a different task (Task B) may emphasize other features or interactions, yielding a distinct spatial pattern. The core assumption is that different classification objectives highlight different feature subsets and interaction patterns, which a fixed ordering cannot optimally serve. **Break condition:** Freezing the layout across tasks prevents reorganization, degrading performance on tasks with different predictive feature sets.

## Foundational Learning
*   **Concept: Spatial Inductive Bias**
    *   **Why needed:** CNNs exploit locality and translation equivariance. Tabular data lacks intrinsic spatial structure; Dynomap creates an artificial but learnable topology to grant CNNs this bias.
    *   **Quick check:** Shuffling feature coordinates after training should significantly drop CNN performance if spatial bias is utilized.
*   **Concept: Differentiable Rendering**
    *   **Why needed:** To update feature positions via gradient descent, the transformation from feature vector to image must be differentiable w.r.t. coordinates. Gaussian kernel summation provides this.
    *   **Quick check:** Using a hard assignment (pixel takes nearest feature's value) would be non-differentiable at boundaries, blocking coordinate updates.
*   **Concept: End-to-End Joint Optimization**
    *   **Why needed:** Pre-computing a fixed layout (e.g., via PCA) cannot adapt to the specific prediction task. Joint optimization aligns the layout with the loss landscape.
    *   **Quick check:** Freezing coordinates after initialization should cause a notable drop in macro-F1, especially on imbalanced or multi-class tasks, compared to full joint training.

## Architecture Onboarding
Input → Feature Gating → (Learnable Coordinates + Rendering Engine) → CNN Backbone → Fusion with Gated Vector → Classifier Head → Loss + Layout Regularization
*   **Critical path:** The gradient must flow from the prediction loss backward through the CNN → Rendering Engine → Coordinates module to enable layout learning. The renderer's differentiability is essential.
*   **Design tradeoffs:**
    *   **Kernel σ scaling:** σ_i = 0.5 + 4.5 * tanh(|x̃_i|) adapts spread to feature magnitude but may cause instability for near-zero values. Constant σ is simpler but less adaptive.
    *   **Image resolution (P):** Larger P (e.g., 64) provides finer granularity but increases CNN cost. Too small causes excessive overlap; too large with few features yields sparse images.
    *   **Regularization weights:** L_layout balances cohesion (L_center, L_spread) and dispersion (L_repel). Too strong repulsion prevents meaningful clustering; too weak allows collapse.
*   **Failure signatures:**
    *   Random layout: Spatial statistics (Moran's I, kNN purity) not above null; attributions uniformly distributed.
    *   Coordinate collapse: Many features share nearly identical coordinates; rendered image shows a single bright blob.
    *   Layout drift: Coordinates never stabilize; velocity threshold not met. May indicate inconsistent loss gradients or too-high learning rate for coordinates.
    *   No task-specific reorganization: Attributions for different classes are spatially intermingled; high Jaccard similarity of class neighborhoods.
    *   Performance inversion: A strong tabular baseline (e.g., XGBoost) suddenly outperforms Dynomap,Suggesting broken gradient flow to coordinates.
*   **First 3 experiments:**
    1.  **Synthetic sanity check:** Train on binary data where Class A uses features 1-10 (high) and Class B uses 11-20 (high). Expect: Class A samples show a bright cluster for features 1-10; Class B for 11-20; Moran's I >> 0.
    2.  **Ablation - frozen layout:** Compare macro-F1 of full Dynomap vs. version with coordinates frozen after initialization on a multi-class dataset (e.g., TCGA-BRCA). Expect significant drop (>5%) for frozen layout.
    3.  **Layout stability test:** Run 5 trainings with different random seeds on the same dataset. Align final layouts via Procrustes analysis. Expect low pairwise Procrustes distances. High variance indicates unstable topologies.

## Open Questions the Paper Calls Out
*   **Question 1:** Does Dynomap's performance and interpretability extend to vision transformer (ViT) architectures when applied to biomedical tabular data? *Basis:* Paper states compatibility but only evaluates CNNs. *Why unresolved:* Interaction between learned spatial layouts and self-attention is untested.
*   **Question 2:** How does the choice of differentiable rendering function (e.g., Gaussian kernel) impact layout quality and task performance? *Basis:* Gaussian is used without comparison to alternatives. *Why unresolved:* Other kernels (Epanechnikov, box, learnable) might preserve information better or yield more stable layouts.
*   **Question 3:** Are the spatially clustered features biologically meaningful (e.g., correspond to known pathways)? *Basis:* Paper shows spatial clustering via Moran's I/kNN purity but no systematic biological validation. *Why unresolved:* Without enrichment analysis (GO/KEGG), it's unclear if neighborhoods reflect true functional relationships.
*   **Question 4:* How does Dynomap scale with extremely high-dimensional data (>100,000 features)? *Basis:* Abstract claims scalability, but experiments use ≤4,000 HVGs. *Why unresolved:* Per-feature coordinate optimization and rendering may become computationally expensive or degrade optimization at larger scales.
*   **Question 5:* How reproducible are learned layouts across random seeds, splits, and hyperparameters? *Basis:* Only Parkinson dataset shows some consensus (Figure S26); no comprehensive stability assessment. *Why unresolved:* Interpretability hinges on consistent feature neighborhoods; high variability would undermine trust.

## Limitations
*   **Architectural underspecification:** Exact CNN layers, filter counts, and pooling strategy are not provided, affecting capacity and gradient flow.
*   **Rendering parameters unknown:** Grid resolution, padding fraction, and interpolation method for the differentiable renderer are missing, impacting image fidelity.
*   **Reproducibility gaps:** No specified random seeds, exact CV splits, or baseline hyperparameters (e.g., for TabM, TabPFN) hinder exact performance verification.

## Confidence
*   **Spatial organization via learnable coordinates:** Medium. Core rendering equation is specified, but implementation details (vectorization, numerical stability) are critical.
*   **Joint optimization necessity:** Medium. Theory is sound; empirical proof depends on correct implementation of layout regularization and stabilization.
*   **Task-specific reorganization:** Low. Evidence is primarily qualitative (attribution maps). Weak quantitative metrics (e.g., Jaccard similarity of class neighborhoods across tasks) are not reported.
