# Online Learning for Dynamic Constellation Topologies
## Quick Facts
- arXiv ID: 2603.25954
- Source URL: https://arxiv.org/abs/2603.25954
- Reference count: 31
- Primary result: Convex offline topology optimization matches +Grid without orbital plane assumptions; OCG offers 37% faster per-iteration online computation than OGD.

## Executive Summary
This paper addresses dynamic satellite network topology configuration under orbital movement and maneuvering, without assuming fixed orbital plane structure. The core method formulates topology finding as a convex optimization problem using weighted least squares with Laplacian matrices, expressing connectivity constraints and utility preferences. The dynamic nature is handled via online convex optimization (OCO) algorithms—Online Gradient Descent (OGD) and Online Conditional Gradient (OCG). Offline results show the formulation matches state-of-the-art +Grid performance despite no structural assumptions, with comparable graph statistics (e.g., average degree 3.61 vs 3.94, average shortest path 4.93 vs 14.01, connected components reduced to 1 from 14). In the online setting, OCG converges to the offline strategy but with higher initial error than OGD, while achieving 37% faster per-iteration computation (5.163 ms vs 7.099 ms for OGD), highlighting a trade-off between convergence speed and computational cost.

## Method Summary
The method consists of two parts: an offline convex solver and an online learning loop. Offline, given satellite and base station positions, a connectivity matrix P is constructed via field-of-view approximations (hyperplane and/or conical constraints) to indicate feasible inter-satellite links. A utility matrix U encodes preferences, using reciprocal distance and scaling base stations more heavily. The topology is represented by a weighted graph Laplacian matrix X, optimized under weighted least squares with a trace term to encourage edge density, subject to Laplacian properties (symmetry, zero row-sum) and degree bounds. Online, at each time step, the environment changes (due to orbital motion), producing new P_t and U_t and thus a convex loss function f_t(X). The online algorithm (OGD or OCG) updates X_t without recomputing from scratch. OGD takes a gradient step and projects onto the convex decision set K; OCG solves a linear subproblem over K and blends the solution with the previous iterate. Both are initialized with the offline solution at t=0. Experiments use a simulated moving constellation (e.g., 18 satellites in one orbital plane and 2 fixed base stations) to compare convergence and iteration time.

## Key Results
- Offline formulation matches +Grid performance without orbital plane assumptions (average degree 3.61 vs 3.94, average shortest path 4.93 vs 14.01, connected components: 1 vs 14).
- Online Conditional Gradient (OCG) converges to the offline strategy but with higher initial error than Online Gradient Descent (OGD).
- OCG achieves 37% faster per-iteration computation (5.163 ms vs 7.099 ms for OGD), demonstrating a trade-off between convergence speed and computational cost.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** The problem of finding a dynamic network topology can be formulated as a convex optimization problem using a weighted least squares objective with a Laplacian matrix variable.
- **Mechanism:** The satellite network topology is represented by a weighted graph Laplacian matrix `X`. The objective `||(X-P)⊙U||_F^2 - Tr(Λ⊙X)` encourages `X` to be close to a target connectivity matrix `P` (which encodes feasible links via 0/-1 entries) while being weighted by a utility matrix `U` (e.g., reciprocal distance) and a trace term `Tr(Λ⊙X)` that encourages a higher total edge count (since trace of Laplacian = 2 * number of edges). Constraints enforce symmetry, zero row-sums, degree bounds (max ISL/BSL), and off-diagonal bounds.
- **Core assumption:** The satellite network topology is adequately modeled as an undirected graph where the Laplacian matrix properties (symmetry, zero row-sum) are valid and the weighted least squares formulation yields a feasible, connected topology when solved.
- **Evidence anchors:**
  - [Section 4] "we formulate the problem of finding a topology X for a set of satellites and base stations... as a weighted least squares... arg min_X ||(X-P)⊙U||_F^2 - Tr(Λ⊙X)... The properties of a Laplacian matrix are added as constraints."
  - [Abstract] "formulates topology finding as a convex optimization problem using weighted least squares with Laplacian matrices"
  - [corpus] The corpus contains papers on satellite routing and dynamic topology (e.g., refs [2,20-23]), providing thematic context but no direct empirical evidence for this specific formulation's convexity or solution quality.
- **Break condition:** If the feasible set defined by the connectivity constraints (from `P` and FOV approximations) and Laplacian constraints is non-convex or empty, the convex formulation fails.

### Mechanism 2
- **Claim:** The dynamic, time-varying nature of the topology problem can be addressed using an online convex optimization (OCO) framework, where a sequence of convex loss functions (one per time step) is minimized sequentially without knowledge of future functions.
- **Mechanism:** At each discrete time step `t`, the environment (satellite positions, channel states) reveals a convex loss function `f_t(X)`, derived from the current utility matrix `U_t` and connectivity matrix `P_t`. An online algorithm (e.g., OGD or OCG) selects a topology `X_t` from the convex decision set `K` (defined by constraints) after observing `f_t`. Regret is measured against a dynamic comparator (optimal sequence in hindsight). OGD uses a gradient step followed by Euclidean projection onto `K`. OCG iteratively solves linear subproblems (linear minimization oracle) over `K`, avoiding projection.
- **Core assumption:** The sequence of loss functions `f_t` is convex and the decision set `K` is convex and closed. The dynamics (changes in `P_t`, `U_t`) are adversarial or stochastic but do not violate convexity per round.
- **Evidence anchors:**
  - [Section 3] "Online Learning, also referred to as Online Convex Optimization (OCO)... a player must iteratively choose an action over some convex set K, while an adversary selects a convex cost function f_t a posteriori."
  - [Section 5] "We tested the performance of two Online Convex Optimization (OCO) algorithms: Online Gradient Descent (OGD)... and Online Conditional Gradient (OCG)."
  - [corpus] The corpus includes papers using RL for routing (e.g., "Shaping Rewards, Shaping Routes"), suggesting exploration of non-OCO methods, but offers no direct validation of OCO's suitability for this specific dynamic topology problem.
- **Break condition:** If the loss function `f_t` becomes non-convex due to unmodeled dynamics (e.g., discrete link states, routing constraints), the OCO framework guarantees do not hold and performance may degrade significantly.

### Mechanism 3
- **Claim:** The design of the utility matrix `U` and connectivity matrix `P` encodes domain knowledge (e.g., inverse distance, field-of-view constraints) that steers the convex solver toward physically realizable and communication-efficient topologies, enabling the no-structure assumption to match structured methods like +Grid.
- **Mechanism:** `P` is constructed such that `P_ij = -1` if satellites `i` and `j` are within mutual field-of-view (approximated by hyperplane/conical constraints), else `0`. This encodes a *desire* for connection where possible. `U` weights these desired edges; by using reciprocal distance, nearer neighbors are strongly preferred. Base stations are given higher utility weight to prioritize their connections. The optimization trades off fitting these preferences (`||(X-P)⊙U||_F^2`) against encouraging total edges (`-Tr(Λ⊙X)`), under degree constraints.
- **Core assumption:** The FOV approximation (hyperplane/conical) accurately identifies physically possible inter-satellite links (ISLs) for the given orbital mechanics. The utility metric (reciprocal distance) is a sufficient proxy for link quality/benefit in the absence of more complex metrics (e.g., SNR, atmospheric effects).
- **Evidence anchors:**
  - [Section 4] "we know that some of these satellites cannot physically connect with others by approximating the field of view of the satellite... we developed an approximation that uses hyperplanes... We adopt the reciprocal of the inter-satellite distance as the utility metric."
  - [Table 1] The offline method (Ours H, H+C) achieves comparable graph statistics to +Grid (which uses orbital plane structure), suggesting the utility/FOV encoding effectively substitutes for explicit plane knowledge.
  - [corpus] Related papers (e.g., refs [20,21,23]) use similar distance-based or SNR-based metrics for ISL selection, providing indirect support for the utility design principle.
- **Break condition:** If the FOV approximation is too coarse (e.g., ignores atmospheric blocking, antenna pointing errors) or the utility function poorly correlates with actual network performance (e.g., ignores interference, congestion), the resulting topology may have many infeasible or low-quality links.

## Foundational Learning
- **Concept: Convex Optimization**
  - **Why needed here:** The core problem formulation (weighted least squares with linear matrix constraints) must be convex for the offline solver (CVXPY) to find a global optimum efficiently and for the OCO framework's regret guarantees to apply.
  - **Quick check question:** Is the objective function a convex function of the Laplacian matrix `X` (considering the Frobenius norm and linear trace terms), and are all constraints affine (linear equality/inequality)?
- **Concept: Online Convex Optimization (OCO)**
  - **Why needed here:** The topology must adapt sequentially to changing conditions (orbital movement, failures) without recomputing a full global optimum each step. OCO provides algorithms (OGD, OCG) with regret bounds for this sequential decision-making under convexity.
  - **Quick check question:** What is the key difference between static and dynamic regret in OCO, and why might dynamic regret be more appropriate for a time-varying satellite network?
- **Concept: Graph Laplacian**
  - **Why needed here:** The Laplacian matrix compactly encodes graph topology (connectivity, degree) and its properties (symmetry, zero row-sum) are used as constraints to ensure a valid undirected graph topology.
  - **Quick check question:** For an unweighted graph Laplacian `L`, what does `L_ii` represent, and what is the relationship between `trace(L)` and the number of edges `m`?

## Architecture Onboarding
- **Component map:**
  1. `FOV Approximator`: Takes satellite positions → outputs connectivity matrix `P` (binary mask for possible ISLs).
  2. `Utility Calculator`: Takes positions + metadata (e.g., node type) → outputs utility matrix `U` (e.g., 1/distance, scaled for base stations).
  3. `Convex Solver (Offline)`: Solves the full problem (Eq 2-7) from scratch at each time step using CVXPY; serves as gold standard.
  4. `Online Learner (OGD/OCG)`: Maintains iterate `X_t`. At each step: receives `U_t`, `P_t` → forms `f_t` → updates `X_t` via OGD (gradient + projection) or OCG (LMO iterations).
  5. `Decision Set K`: Encapsulates all constraints (symmetry, degree bounds, etc.); provides projection (for OGD) and linear minimization oracle (for OCG).
- **Critical path:** Positions → (`FOV`, `Utility`) → `P_t`, `U_t` → `Online Learner` → `X_t` (topology).
- **Design tradeoffs:**
  - **OGD vs OCG:** OGD: Lower initial error, higher per-iteration cost (projection). OCG: Higher initial error, ~37% faster per iteration (linear solves). Trade-off: convergence speed vs. per-step computational budget.
  - **FOV approximation fidelity:** Single hyperplane (fast, coarse) vs. hyperplane+cone (slower, more accurate). Trade-off: computational latency vs. feasible link set accuracy.
  - **Utility design simplicity:** Reciprocal distance (simple, fast) vs. learned/complex metrics (potentially better performance, overhead). Trade-off: model expressiveness vs. computation/measurement cost.
- **Failure signatures:**
  - **Non-convergence of OCG:** Error plateaus at high level → likely LMO implementation error or decision set `K` not properly defined.
  - **Degenerate topology:** All `X_ij = 0` or violates degree constraints → utility weights `Λ` too weak, or `P` has no feasible edges.
  - **High churn:** Frequent link additions/removals despite smooth orbital movement → FOV approximation too sensitive, or utility matrix too noisy.

Compute average residual per entry vs. offline method (Eq 8). Measure wall-clock time per iteration. Verify OCG's higher initial error but lower per-iteration time.
  3. **Stress Test FOV Approximation:** For a single orbital plane, vary FOV approximation complexity (none, hyperplane only, hyperplane+cone). Identify point of diminishing returns where added complexity yields minimal topology change but significant compute increase.

## Open Questions the Paper Calls Out
1. **Question:** Can incorporating richer ISL metrics (e.g., link latency, queue congestion, signal quality) improve topology resilience and routing performance compared to the distance-based utility?
   **Basis in paper:** [explicit] The authors state in the Discussion that "there is space for improvement by considering more meaningful ISL characteristics" beyond the reciprocal of distance.
   **Why unresolved:** The current utility model is simplistic and may not capture real-time network conditions that affect reliability and throughput, especially under dynamic traffic loads.
   **What evidence would resolve it:** Simulation studies integrating multi-metric utilities, comparing graph properties (e.g., spectral gap, betweenness) and routing metrics (e.g., end-to-end delay, packet loss) under realistic traffic patterns and failure scenarios.

2. **Question:** How do alternative OCO algorithms (e.g., Online Mirror Descent, optimistic variants) affect the trade-off between convergence speed and per-iteration computational cost for dynamic satellite topologies?
   **Basis in paper:** [explicit] The authors mention future work to "further analyze and develop OCO algorithms" after only evaluating OGD and OCG.
   **Why unresolved:** The observed trade-off (OCG faster per iteration but higher initial error) may not be optimal; other algorithms could offer better regret guarantees or practical performance.
   **What evidence would resolve it:** Empirical comparison of multiple OCO algorithms on the same dynamic constellation dataset, measuring cumulative dynamic regret, wall-clock time per iteration, and sensitivity to step-size tuning.

3. **Question:** What conditioning strategies (e.g., warm-starting from recent topologies, using predictive models of orbital motion) most effectively accelerate convergence in online topology learning?
   **Basis in paper:** [explicit] The authors propose to "test different approaches to condition the topologies generated by OCO algorithms" beyond the initial offline solution.
   **Why unresolved:** Conditioning only on the initial offline topology leads to OCG's high initial error; leveraging temporal correlations might reduce adaptation latency.
   **What evidence would resolve it:** Experiments varying conditioning inputs (e.g., last online solution, exponential moving average, short-term trajectory forecasts) and measuring convergence rate (residual decay) and stability.

4. **Question:** Does the proposed offline convex formulation remain tractable and effective for large-scale, heterogeneous mega-constellations with mixed orbital shells (e.g., MEO, LEO) and abrupt topology disruptions (e.g., satellite failures, collision avoidance maneuvers)?
   **Basis in paper:** [inferred] Evaluation uses a small, homogeneous Iridium-like constellation (66 satellites) with smooth orbital dynamics; scalability to thousands of satellites and robustness to non-stationary events is not addressed.
   **Why unresolved:** The problem size (matrix dimensions) and FOV approximation cost could become prohibitive; the convex formulation may not capture sudden connectivity losses or heterogeneous link capabilities.
   **What evidence would resolve it:** Large-scale simulations using realistic constellation parameters (e.g., Starlink shells) and injected failure events, tracking solver time, memory usage, graph connectivity metrics, and dynamic regret under abrupt changes.

## Limitations
- Convex formulation: The paper does not prove convexity; empirical success is suggestive but not conclusive.
- OCO suitability: OGD/OCG are applied without dynamic regret bounds for this specific loss sequence; assumptions may not hold under real orbital dynamics.
- Utility/FOV design: Heuristic scaling (base stations ×100, Λ=100) and coarse FOV approximations may not generalize to heterogeneous constellations or richer link metrics.
