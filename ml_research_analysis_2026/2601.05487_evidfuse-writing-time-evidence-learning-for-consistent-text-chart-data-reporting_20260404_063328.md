# EvidFuse: Writing-Time Evidence Learning for Consistent Text-Chart Data Reporting

## Quick Facts
- arXiv ID: 2601.05487
- Source URL: https://arxiv.org/abs/2601.05487
- Reference count: 40
- Primary result: EvidFuse achieves top average rank in both LLM-as-judge and human evaluations for chart quality, text-chart alignment, and report-level usefulness.

## Executive Summary
EvidFuse introduces a training-free multi-agent framework for generating consistent and insightful data reports by interleaving narrative drafting with on-demand visualization construction. It addresses the evidence freeze problem in staged pipelines (text-first or graph-first) by having a Real-Time Evidence Construction Writer request charts from a Data-Augmented Analysis Agent mid-writing. The agent returns grounded visualizations and captions which are injected into the writer’s context, conditioning subsequent claims on actual evidence. Evaluated across three data sources and six criteria, EvidFuse attains the highest average rank in both automatic and human assessments, demonstrating superior chart quality, text-chart alignment, and report-level usefulness. Ablation studies confirm the necessity of both the dedicated analysis agent and real-time data interaction.

## Method Summary
The framework consists of two cooperating agents: (1) a Data-Augmented Analysis Agent (A′) that, given a fine-grained visualization request, accesses raw tables, plans a chart specification (type, title, data, labels), calls a code execution tool (T) to render the chart, and generates a grounded caption; and (2) a Real-Time Evidence Construction Writer (W) that first produces a structured outline from the user request and a data overview (DO), then incrementally writes the report. Whenever W identifies a need for visual evidence, it emits a `<visualization>` tag, suspends, and receives the chart and caption from A′ via a `<visualization_result>` injection. The writer then resumes, now conditioned on the new visual evidence. This writing-time evidence construction dynamically expands the evidence space, enabling deeper, decision-oriented insights without relying on precomputed or post-hoc charts. The system requires no training, only careful prompting and tool orchestration.

## Key Results
- Top average rank in both LLM-as-judge and human assessments across six criteria (chart layout, readability, text-chart consistency, textual depth, informativeness, visual consistency).
- Ablation studies show that removing the dedicated analysis agent significantly degrades chart quality and chart-grounded reasoning (e.g., readability rank worsens from 1.8 to 2.7 on USAFacts).
- EvidFuse produces reports with higher information content (e.g., OWID: 18 vs. Direct baseline 14.40) and more visualizations, indicating on-demand evidence expansion.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Writing-time evidence construction improves text-chart consistency by conditioning narrative claims on actual, on-demand visualizations rather than pre-fixed or post-hoc ones.
- **Mechanism:** The Real-Time Evidence Construction Writer pauses narrative generation upon emitting a `<visualization>` tag, receives a grounded chart and caption from the Data-Augmented Analysis Agent, and injects this visual evidence directly into the generation context before resuming. This loop ensures subsequent textual claims are explicitly constrained by the just-generated visual evidence.
- **Core assumption:** LLMs can effectively incorporate newly injected multimodal context (chart + caption) to steer subsequent text generation toward alignment with that evidence.
- **Evidence anchors:**
  - [abstract] "writing-time evidence construction dynamically expands the evidence space and directly conditions subsequent claims on actual charts."
  - [section 4.2] "Whenever W needs evidence... it emits an analysis request... suspended... A′ returns... injected back into the context. W resumes writing conditioned on the returned visualization."
- **Break condition:** If the writer model fails to attend to or incorporate the injected visual evidence in its subsequent generations, the consistency benefit collapses.

### Mechanism 2
- **Claim:** Decoupling visualization analysis (Data-Augmented Analysis Agent) from long-form drafting (Writer) improves chart quality and analytical depth by dedicating specialized capacity and context to the non-trivial visualization task.
- **Mechanism:** The Analysis Agent operates with a focused memory containing EDA-derived overview, raw table access, and tool-calling capability for code-based rendering. This separation prevents the writer from being burdened with concurrent narrative coherence and visualization specification tasks.
- **Core assumption:** Task decomposition and specialized agent memory lead to superior performance on each sub-task compared to a monolithic model.
- **Evidence anchors:**
  - [section 4.1] "We decouple visualization analysis from long-form drafting... assigning data analysis and visualization workload to a dedicated Data-Augmented Analysis Agent..."
  - [section 5.4 Ablation] "removing A′... grades chart-level quality and chart-grounded reasoning, with clear drops on Read. and Depth." (e.g., USAFacts Read. rank worsens 1.8→2.7).
- **Break condition:** If the Analysis Agent's outputs are consistently low-quality or misaligned, the decoupling becomes a failure point.

### Mechanism 3
- **Claim:** On-demand expansion of the evidence space during writing enables decision-oriented, multi-step insights beyond predefined or surface-level analysis.
- **Mechanism:** The writer's outline is high-level, and specific visualization requests are generated incrementally based on the evolving narrative context. This allows the evidence space to grow in direct response to analytical needs as they emerge in the draft.
- **Core assumption:** A human-like analyst benefits from requesting new visual evidence mid-writing to test hypotheses or explore angles that weren't initially foreseen.
- **Evidence anchors:**
  - [abstract] "enables on-demand expansion of the evidence space... deeper, decision-relevant analysis without being restricted to a fixed set of precomputed insights."
  - [section 4.2] "This loop of evidence-write process enables dynamically deeper, decision-relevant insights tailored to R_user."
  - [section 5.5 Discussion] "EvidFuse contains the most information in reports... EvidFuse attains highest Content. score." (e.g., OWID: 18 vs. Direct's 14.40).
- **Break condition:** If the writer's requests become repetitive, off-topic, or fail to explore new analytical dimensions, the expanded evidence space may increase length without increasing true informational depth.

## Foundational Learning
- **Tool-Augmented LLM Agents (Function Calling)**  
  **Why needed:** The Analysis Agent must execute code to render charts reliably. The framework depends on the agent's ability to invoke the tool `T`, interpret outputs, and iterate.  
  **Quick check:** Given a YAML spec, can you trace the sequence: Analysis Agent → Tool `T` → Code Execution → Chart Image? What happens if execution fails?

- **Plan-and-Write Paradigm for Long-Form Generation**  
  **Why needed:** The Writer first creates a structured outline `O` from user intent and data overview, then incrementally drafts. This roadmap guides when to request visual evidence, preventing disjointed interleaving.  
  **Quick check:** How does the outline influence placement and purpose of `<visualization>` tags? If the outline is poor, what is the likely failure mode for final report coherence?

- **Multi-Modal Context Injection during Autoregressive Generation**  
  **Why needed:** Injecting a chart image and caption into the text generation stream requires understanding how LLMs process non-text modalities. The mechanism assumes subsequent tokens will be grounded in this evidence.  
  **Quick check:** When the writer resumes after `<visualization_result>`, what specific attention patterns must capture the relationship between the injected visual evidence and the next claim? How might this fail with smaller context windows?

## Architecture Onboarding
- **Component map:**  
  Input (R_user, D) → Pre-processor (A → DO) → Writer (W) ↔ Analysis Agent (A′) ↔ Tool (T) → Interleaved history (CT)

- **Critical path:**  
  1. Compute Data Overview (DO) via initial EDA (Agent A).  
  2. Writer W generates outline O.  
  3. Loop: W produces text chunk t_i. If t_i contains `<visualization>q_i</visualization>`, pause W; invoke A′(q_i) → (c_i, s_i); inject `<visualization_result><img src=...>{s_i}</visualization_result>`; resume W. Terminate on `<EOS>`.

- **Design tradeoffs:**  
  - Latency vs. Depth: Real-time requests increase API calls and time (~2-3x vs. DeepAnalyze) but enable deeper insights. Caching frequent aggregations could mitigate.  
  - Agent Specialization vs. Coordination Overhead: Decoupling improves per-component quality (ablation shows drop without A′) but introduces handoff failure risks (e.g., writer ignores returned chart, A′ returns invalid chart).  
  - Deterministic Rendering vs. Creative Flexibility: Tool T uses code for reliable charts, limiting spontaneous visual design choices a monolithic LLM might attempt.

- **Failure signatures:**  
  - Low visualization density (<3-4 charts in long report) → likely early A′ failures (syntax errors) causing writer to stop asking.  
  - Chart-text misalignment despite interleaving → writer's resumed text does not reference injected chart; check caption specificity and writer prompt emphasis.  
  - Repetitive/generic charts → A′ produces same chart type for diverse requests; check spec planning richness and DO exploitation.

- **First 3 experiments:**  
  1. **Baseline interleaving sanity check:** Use a trivial single-table dataset (e.g., sales by month). Force W to emit a `<visualization>` request on the first sentence. Verify A′ returns a valid chart and W’s next sentence explicitly references it (e.g., "As shown in the chart...").  
  2. **Ablation of DO augmentation:** Run with A′ having no DO (only raw tables). Compare chart relevance and caption quality against full DO. Expect drop in A′’s ability to choose correct tables/variables.  
  3. **Failure recovery test:** Instrument T to randomly fail (e.g., 30% of code executions). Measure: (a) retries per request; (b) whether W’s subsequent text quality degrades after a failed injection.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How can the computational overhead and latency of write-time evidence construction be reduced without sacrificing report quality?
- **Basis in paper:** The Limitations section states: "Additional time and API cost for write-time visual evidence construction... Future work can improve robustness via verified execution and self-repair... engineering optimizations such as caching or reusing intermediate aggregations, batching compatible requests, and parallel tool execution further reduce the cost while preserving evidence fidelity."
- **Why unresolved:** The paper identifies cost and latency as practical barriers but does not implement or evaluate specific optimization strategies, leaving them as future work.
- **What evidence would resolve it:** Systematic experiments comparing different optimization techniques (e.g., caching, batching, model distillation) on cost-quality trade-offs across diverse datasets, measuring impacts on report metrics and resource usage.

### Open Question 2
- **Question:** What mechanisms can ensure robust visualization execution and recovery when code generation fails repeatedly during real-time interaction?
- **Basis in paper:** The Limitations section notes: "Since EvidFuse needs code execution to render visualization result, repeated execution failures may reduce the amount and quality of visual evidence in long reports... Future work can improve robustness via verified execution and self-repair, such as type-safe data adapters, unit checks on aggregations, constrained chart templates, as well as graceful fallback strategies."
- **Why unresolved:** The paper documents a failure case where code errors lead to cascading reductions in visualization requests, but no built-in recovery mechanisms are implemented or tested.
- **What evidence would resolve it:** Implementation and evaluation of error-handling strategies (e.g., automated code validation, iterative self-correction, fallback visualizations) in the visualization tool T, measuring their effect on maintaining evidence density and report coherence under failure conditions.

### Open Question 3
- **Question:** How can "decision-oriented insight depth" be formally defined and measured beyond current heuristic-based LLM/human rubrics?
- **Basis in paper:** The paper emphasizes "decision-oriented insight depth" as a key goal and evaluates it via a metric ("Textual Information Depth") based on rubrics about multi-dimensional coverage and closed-loop logic. However, the metric relies on subjective ranking and may not capture actual decision-support utility.
- **Why unresolved:** The evaluation criteria are derived from data journalism and visualization principles but lack grounding in real-world decision-making tasks. It is unclear whether higher rubric scores correlate with improved analyst or stakeholder decisions.
- **What evidence would resolve it:** User studies with domain experts assessing reports for actionable insights, or correlation analyses between rubric scores and outcomes of decisions made based on the reports.

### Open Question 4
- **Question:** To what extent does the quality of the initial outline planning affect the final report's coherence and depth, and can outline generation be dynamically improved during writing?
- **Basis in paper:** The writer follows a "plan-and-write" paradigm with a single upfront outline, but the paper does not analyze sensitivity to outline quality or explore iterative outline revision. The interleaving focuses on evidence construction, not plan adaptation.
- **Why unresolved:** The framework assumes a fixed outline guides the interleaving process; a poor outline might constrain evidence-seeking or lead to disjointed narratives, but this is not studied. No mechanisms exist for the writer to revise the outline based on interim findings.
- **What evidence would resolve it:** Ablation studies comparing reports generated from human-optimized vs. LLM-generated outlines, or implementations of dynamic outline revision (e.g., allowing the writer to update the outline after major evidence insertions), measuring impacts on coherence and insight depth.

### Open Question 5
- **Question:** How does EvidFuse generalize to domains with highly complex, unstructured, or multi-modal data (e.g., combining tables with text, images, or time-series)?
- **Basis in paper:** The framework is evaluated on table-centric reports from three structured data sources. The Data-Augmented Analysis Agent assumes access to raw tables and EDA summaries, but the paper does not address data with heterogeneous formats or higher dimensionality.
- **Why unresolved:** The reported results are limited to multi-table scenarios; scalability to data with mixed modalities or extreme size is unexamined. The agent's EDA background and visualization tool may not generalize.
- **What evidence would resolve it:** Extending EvidFuse to new benchmarks with unstructured/multi-modal data (e.g., scientific papers with plots and text, financial reports with logs and images) and measuring performance on chart quality, alignment, and insight depth compared to domain-specific baselines.

## Limitations
- **Prompt sensitivity**: Many components rely on detailed prompts (EDA knowledge, code generation, critique) that are not fully specified, leading to potential reproducibility issues.
- **Unknown data access pattern**: It remains unclear whether the Analysis Agent loads entire CSVs into context or uses external table query tools, affecting scalability and performance.
- **Context management**: The paper does not address how long reports that exceed the model’s context window are handled (truncation, summarization), which is critical for real-world deployment.

## Confidence
- **Mechanism 1 (writing-time conditioning):** Medium – supported by algorithmic description and textual evidence, but core assumption of LLM attention to injected context lacks direct validation.
- **Mechanism 2 (agent decoupling):** High – strong ablation evidence shows significant quality drops without the dedicated analysis agent.
- **Mechanism 3 (on-demand evidence expansion):** Medium – claims align with EDA principles and report-length metrics, but no direct proof that new insights are truly deeper versus merely more numerous.

## Next Checks
1. **Core loop sanity test:** Use a single-table dataset (e.g., monthly sales). Force an early `<visualization>` tag; verify the writer’s next sentence explicitly references the returned chart.
2. **Data Overview ablation:** Run the pipeline with and without the EDA-derived `DO` provided to the analysis agent; measure changes in chart relevance and caption specificity.
3. **Tool failure stress test:** Inject random code-execution failures (30%) and track retry count, final chart validity, and downstream text consistency after failed injections.
