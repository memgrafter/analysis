# Robust Federated Learning via Byzantine Filtering over Encrypted Updates

## Quick Facts
*   **arXiv ID:** 2602.05410
*   **Source URL:** https://arxiv.org/abs/2602.05410
*   **Reference Count:** 40
*   **Primary Result:** Proposes an encrypted Byzantine filtering mechanism for federated learning that achieves 90–94% F1-score in identifying malicious updates under CKKS homomorphic encryption, with marginal utility loss and 6–24 second per-round filtering runtime.

## Executive Summary
This paper tackles the dual challenge of privacy and Byzantine resilience in federated learning (FL) by proposing a system where a server can filter malicious model updates without decrypting them. The core method involves training Support Vector Machine (SVM) meta-classifiers on simulated "shadow" Byzantine attacks. These classifiers are then used for homomorphic inference on encrypted updates (using the CKKS scheme) to compute a weight for each update. Updates are reweighted before aggregation, nullifying malicious contributions. Evaluations on multiple benchmarks show high detection accuracy and practical runtimes, and the approach remains effective against combined attacks and when updates are protected with differential privacy.

## Method Summary
The system operates in two phases. **Offline**, the server generates a labeled dataset of "shadow updates" by simulating honest local training and various Byzantine attacks (backdoor, gradient-inversion, label-flipping, shuffling) on non-IID data partitions. For each attack type and model layer, it trains an SVM classifier, optimizing for a score that balances detection F1-score with computational efficiency in the encrypted domain. The chosen classifiers rely on Supervised PCA (SPCA) for dimensionality reduction and linear/low-degree polynomial kernels. **Online**, workers encrypt their model updates (or a selected layer's weights) with CKKS and send them to the server. The server computes the update delta, applies the encrypted filter (SPCA projection, SVM kernel evaluation, approximated sigmoid activation) to assign a weight in `[0,1]` to each update. It then aggregates the reweighted updates, normalizes by the sum of the weights (using a homomorphic inverse), and bootstraps the resulting ciphertext before broadcasting the new global model. All operations preserve the confidentiality of the individual updates.

## Key Results
*   The encrypted filtering achieves **90–94% F1-score** in identifying Byzantine updates across multiple benchmarks (FEMNIST, CIFAR10, GTSRB, ACSIncome).
*   Model utility loss is marginal compared to an ideal, attack-free baseline, even under 50% Byzantine workers.
*   Filtering runtime per aggregation round is **6–24 seconds**, dominated by homomorphic operations like SVM projection and inversion, with bootstrapping being a significant component.

## Why This Works (Mechanism)
### Mechanism 1
*   **Claim:** Byzantine workers can be identified from encrypted model update deltas using meta-classifiers trained on shadow attacks.
*   **Mechanism:** The server trains SVM meta-classifiers on labeled shadow updates generated by simulating diverse Byzantine attacks (backdoor, gradient-inversion, label-flipping). At runtime, for each worker's encrypted delta `J∆t_i`, the server computes filter value `JPt_i = Filter_P(J∆t_i)` via homomorphic SVM inference (SPCA projection + kernel evaluation + smooth activation). Updates are scaled by their filter weights before FedAvg aggregation, effectively nullifying malicious contributions.
*   **Core assumption:** The anomalies introduced by Byzantine behaviors (e.g., gradient ascent direction, backdoor-induced weight patterns) create statistically separable signatures in the parameter space that persist even after encryption, and these signatures are consistent across varied local data distributions.
*   **Evidence anchors:** [abstract] "training SVM meta-classifiers on labeled shadow updates... to detect malicious behavior directly from encrypted model updates"; [section 4.2] Details on considered filtering properties; [section 6] Algorithm 3 for shadow update generation.
*   **Break condition:** If Byzantine workers craft updates that statistically mimic honest updates from non-IID data (e.g., adaptive attacks matching local gradient distributions), separability collapses and filter accuracy drops below convergence threshold.

### Mechanism 2
*   **Claim:** SVM inference on CKKS-encrypted data can be made efficient enough for practical FL by optimizing model architecture (SPCA) and using FHE-friendly approximations.
*   **Mechanism:** First, apply Supervised PCA to the selected layer's weights to reduce dimensionality while maximizing class separability. Second, constrain SVM to linear or low-degree polynomial kernels (degree 1-2) to avoid high-degree polynomial approximations in CKKS. Third, approximate the Heavyside step with a scaled Sigmoid evaluated via Chebyshev polynomials using Paterson-Stockmeyer method. Fourth, use Newton-Raphson (2 iterations) for encrypted division in normalization.
*   **Core assumption:** (1) A single layer captures the Byzantine signal sufficiently; (2) Linear/quadratic kernels achieve acceptable separation given SPCA; (3) Smooth Sigmoid provides adequate soft-thresholding; (4) Newton-Raphson converges quickly because filter sum `S_t` is in `[0,1]`.
*   **Evidence anchors:** [section 7.2] SPCA comparison; [section 7.3] Grid search showing optimal configs often degree 1; [section 8.2] Chebyshev approximation details; [section 8.3] Newton-Raphson convergence.
*   **Break condition:** If SPCA fails to reduce dimensionality while maintaining separability (dim > 64), or if optimal kernel degree >2, or if Newton-Raphson fails to converge within 2 iterations for significant fraction of `S_t` values.

### Mechanism 3
*   **Claim:** Weighted aggregation of encrypted updates and model normalization can be performed entirely under CKKS without decryption, preserving privacy while canceling Byzantine contributions.
*   **Mechanism:** After filtering, each update `θt_i` is multiplied by its encrypted weight `JPt_i`. The server homomorphically sums these scaled updates and the sum of weights `JS_{t+1}K`. The inverse of `JS_{t+1}K` is approximated via Newton-Raphson to get `JS_{t+1}^{inv}K`. The normalized model is `Jθ_{t+1}K = Jθ_{t+1}^{scaled}K · JS_{t+1}^{inv}K`. The server then bootstraps `Jθ_{t+1}^{fresh}K` for next round. Workers collaboratively decrypt `Jθ_{t+1}K` using threshold CKKS.
*   **Core assumption:** The filter weights are correctly computed in the encrypted domain as rational approximations, and their sum `S_t` is bounded away from zero to avoid division by near-zero; Newton-Raphson provides sufficient precision for CKKS parameters.
*   **Evidence anchors:** [section 5] Algorithm 2 steps 5-10; [section 8.3] Algorithm 4 for FHEInverse; [section 9.1] Table 6 runtime breakdown.
*   **Break condition:** If filter weights become extremely small (`∑ weights < ε`) due to over-filtering, inverse amplification causes large noise growth and decryption failure; or if Newton-Raphson approximation error exceeds CKKS noise budget.

## Foundational Learning
*   **Concept: Federated Learning (FedAvg)**
    *   Why needed here: The entire system builds on FedAvg's local-update-then-aggregate paradigm; modifications must preserve FedAvg's convergence properties.
    *   Quick check question: In FedAvg, why does local epoch count E affect the number of secure aggregations per epoch compared to FedSGD? How does that impact FHE overhead?
*   **Concept: Homomorphic Encryption (CKKS)**
    *   Why needed here: CKKS enables computation on encrypted model updates without decryption, preserving privacy during aggregation and filtering.
    *   Quick check question: What is the difference between leveled FHE and bootstrapped FHE? Why does the paper need bootstrapping even though they use a leveled scheme initially?
*   **Concept: Byzantine Attacks in FL**
    *   Why needed here: The threat model includes both data poisoning (backdoor, label-flipping) and model poisoning (gradient ascent) that the filter must detect.
    *   Quick check question: Distinguish between "preventing convergence" attacks (e.g., gradient ascent) and "poisoned convergence" attacks (e.g., backdoor). How does the filter's design address both?
*   **Concept: Supervised PCA (SPCA)**
    *   Why needed here: SPCA reduces the dimensionality of model updates while maximizing the separability between honest and Byzantine classes, which is critical for efficient and effective FHE-based SVM inference.
    *   Quick check question: How does SPCA differ from standard unsupervised PCA in the context of training a classifier for Byzantine detection?
*   **Concept: Threshold CKKS**
    *   Why needed here: Allows the server to construct a ciphertext (the new global model) that can only be decrypted if a sufficient number of workers collaborate, preventing the server from learning the model and maintaining end-to-end privacy.
    *   Quick check question: What is the role of the threshold `τ` and the collusion threshold `B_coll` in this collaborative decryption scheme?

## Architecture Onboarding
*   **Component map:** Worker local training (SGD/DP-SGD) -> Encrypt update (CKKS) -> Send to Server. Server receives -> Compute delta -> Filter_P (SPCA proj -> SVM proj -> Sigmoid) -> Scale updates -> Aggregation & Normalization (inverse) -> Bootstrap -> Broadcast encrypted model. Workers collaborative decrypt (threshold CKKS) -> Update local model. Crypto module handles all CKKS ops with precomputed keys.
*   **Critical path:** Shadow data collection (offline) -> SVM training & hyperparameter selection (offline) -> Deployment -> For each FL round: (1) Worker encrypts update, (2) Server receives, (3) Server computes delta, (4) Server performs encrypted filtering (SPCA+SVM+Sigmoid), (5) Server aggregates & normalizes, (6) Server bootstraps (can overlap), (7) Workers decrypt & update.
*   **Design tradeoffs:**
    *   Accuracy vs runtime: Higher F1 requires more support vectors or higher kernel degree → increased FHE time. The `C_FHE_SVM` score formalizes this tradeoff.
    *   Layer selection: Early layers may capture generic features; later layers may encode task-specific anomalies. Must evaluate separability per model.
    *   Dimensionality: Lower SPCA dim reduces matrix-vector product cost but risks losing discriminative info; trade-off between dim=8 and dim=64.
    *   Parallelism: More support vectors can be evaluated in parallel if hardware allows (factor `P` in score).
*   **Failure signatures:**
    *   Validation: During shadow training, if any attack's SVM F1 < ~85%, expect poor filtering.
    *   Runtime: If total `Filter_P` exceeds worker update + communication time by >2x, server becomes bottleneck.
    *   Convergence: If test accuracy gap to no-attacker baseline exceeds bound from Corollary 4 given `q`, `µb`, `σb`, then filter quality insufficient.
    *   Decryption: If collaborative decryption fails (insufficient active workers `τ`) or noise exceeds threshold, model becomes corrupted.
*   **First 3 experiments:**
    1.  **Shadow update sanity check:** Generate plaintext shadow updates for one attack (e.g., backdoor). Train SVM without SPCA. Expect >90% F1 on held-out plaintext test set. Confirms attack signal exists.
    2.  **Layer separability analysis:** For each layer, compute honest vs Byzantine cluster distance after SPCA(8). Pick layer with max separation (e.g., C1 in GTSRB). Validates layer choice.
    3.  **FHE operation benchmarking:** Using sample encrypted update from target layer, time each step: (a) SPCA projection, (b) SVM projection, (c) Sigmoid (Chebyshev), (d) Newton-Raphson inverse. Compare against reported runtimes.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can the proposed Byzantine filtering approach be effectively extended to other homomorphic encryption schemes beyond CKKS?
    *   **Basis in paper:** From the conclusion: "As future works, we will investigate the extension of this methodology to other sets of homomorphic encryption schemes..."
    *   **Why unresolved:** The current implementation is tightly coupled with CKKS-specific features such as approximate arithmetic, SIMD operations, and bootstrapping. Other schemes (e.g., BFV, BGV) have different number representations, noise growth characteristics, and native operations, which may require fundamentally different filtering circuit designs and optimizations.
    *   **What evidence would resolve it:** A working implementation of the filtering mechanism on at least one other FHE scheme (e.g., BFV) with comparable detection accuracy and runtime performance, along with an analysis of the trade-offs compared to CKKS.
*   **Open Question 2:** Can the meta-classifier-based filtering reliably detect Byzantine attacks that are specifically crafted to evade detection by exploiting the encrypted domain and the known feature extraction process?
    *   **Basis in paper:** From the conclusion: "explore the detection of increasingly complex Byzantine attack vectors via FHE-friendly machine-learning models and techniques."
    *   **Why unresolved:** The training data for the SVM filters consists of simulated attacks with predefined patterns. An adversary aware of the filtering mechanism (e.g., which layer and SPCA components are used) could design attacks that produce updates that appear benign in those features while still achieving their malicious objective. The robustness of the filter against adaptive attacks is not evaluated.
    *   **What evidence would resolve it:** Adversarial training or robustness evaluation where attackers are given full knowledge of the filtering pipeline and attempt to generate evasive updates. Success would be measured by the drop in F1-score and the ability of such attacks to still harm convergence when filtered.
*   **Open Question 3:** How do strong differential privacy guarantees (e.g., ϵ ≤ 1) affect the separability of honest and Byzantine updates in the encrypted domain, and can the filter be made more resilient to DP-induced noise?
    *   **Basis in paper:** From Appendix E: "the strong-privacy regime introduces substantial distortions... the discriminative signal captured by the SPCA components is weakened." The paper states the approach remains effective with DP but experiments show degradation under strong DP.
    *   **Why unresolved:** DP-SGD adds significant noise and clipping to updates, which can obscure the statistical differences between honest and malicious updates that the SVM relies on. The paper does not propose solutions to maintain filtering performance under strong DP, which is critical for deployments requiring high privacy.
    *   **What evidence would resolve it:** Experimental results showing that modifications to the filter (e.g., using different layers, increasing SPCA dimensionality, or training on DP-shadow updates) can restore high F1-scores even at low ϵ. Alternatively, theoretical analysis of DP's effect on the feature distribution and derivation of new features robust to noise.
*   **Open Question 4:** Can the selection of the optimal layer and dimensionality for SPCA be automated rather than relying on manual grid search, and how does this automation impact the overall efficiency and accuracy of the encrypted filter?
    *   **Basis in paper:** From Section 7.2: "To showcase our approach, we consider four models... Figure 5 shows the exploration of optimal SVM configurations." The process involves grid search over layers and dimensions, which is computationally expensive and may not scale to many architectures.
    *   **Why unresolved:** The grid search is a brute-force approach that requires training and evaluating many SVM configurations. For new model architectures, this process must be repeated. An automated method (e.g., based on heuristics or learned selection) would make the system more practical and adaptable.
    *   **What evidence would resolve it:** A proposed algorithm that, given a model architecture and a small calibration set of updates, automatically selects the layer and SPCA dimension that optimize the trade-off between predictive performance (F1-score) and FHE computation cost, validated across multiple architectures and attacks.

## Limitations
*   The filter's reliance on a single model layer and SPCA may fail to capture Byzantine signals that are distributed across multiple layers or are too subtle under strong non-IID honest data distributions.
*   The threat model evaluation is based on known, simulated attacks; the filter's robustness against adaptive adversaries who specifically tailor updates to evade the known filtering mechanism (e.g., by matching SPCA feature distributions) remains an open question.
*   Critical experimental hyperparameters (exact threshold `τ` for collaborative decryption, DP `δ` and noise multiplier, Dirichlet `α` for FL splits) are not fully specified, hindering exact replication and performance benchmarking on new hardware.

## Confidence
*   **Byzantine Detection (F1-score):** Medium. Relies on the separability of shadow attack simulations; untested against adaptive, evasive attacks.
*   **Encrypted SVM Efficiency:** Medium. Depends on specific SPCA dimensionality and kernel degree choices; efficiency may degrade for larger models or if a more complex kernel is truly necessary.
*   **Encrypted Aggregation & Privacy:** High. Based on standard, well-understood CKKS operations with clear correctness arguments for the weighted averaging protocol.
*   **Resilience under Differential Privacy:** Low. Paper acknowledges significant performance degradation under strong DP (ϵ ≤ 1) without providing a robust solution.

## Next Checks
1.  **Cross-dataset generality test:** Replicate the entire pipeline (shadow generation, filter training, encrypted FL) on a standard NLP FL benchmark like Shakespeare. Verify that the target F1-score (>85%) and runtime envelopes are maintained against the same suite of attacks.
2.  **Scalability stress benchmark:** Measure the end-to-end `Filter_P` runtime on a significantly larger model (e.g., ResNet-18 on CIFAR-10). Compare the breakdown (SPCA, SVM, Sigmoid, Inverse) against the reported 6-24s range to identify the primary scaling bottleneck.
3.  **Adaptive attack simulation:** Implement an adaptive attack where the adversary has white-box knowledge of the filtering pipeline (selected layer, SPCA matrix, SVM support vectors) and uses optimization (e.g., projected gradient descent) to craft updates that yield high filter weights (`P_t ≈ 1`) while still implementing a harmful backdoor or gradient-ascent objective. Quantify the resulting F1-score drop and damage to final model accuracy.
