# Enhancing Building Semantics Preservation in AI Model Training with Large Language Model Encodings
## Quick Facts
- arXiv ID: 2602.15791
- Source URL: https://arxiv.org/abs/2602.15791
- Reference count: 24
- Primary result: LLM-based encodings (compacted LLaMA-3 1,024D) achieved a weighted average F1-score of 0.8766, outperforming one-hot encoding's 0.8475.

## Executive Summary
This study investigates replacing conventional one-hot encoding with large language model (LLM) embeddings—such as OpenAI's text-embedding-3 and Meta's LLaMA-3—for training GraphSAGE models on BIM subtype classification. The core premise is that LLM embeddings capture nuanced semantic relationships between building object subtypes, which one-hot vectors cannot. By using cosine embedding loss to train the model to replicate the LLM's semantic space and applying Matryoshka for dimensionality reduction, the method achieves superior classification accuracy. The compacted 1,024-dimensional LLaMA-3 embedding notably surpassed the one-hot baseline, demonstrating that LLM-based encodings preserve finer semantic distinctions critical for AI comprehension in AECO.

## Method Summary
The approach substitutes discrete one-hot labels with dense, continuous LLM-generated embeddings for each BIM subtype. A GraphSAGE model is trained to output vectors that align geometrically with these target embeddings via cosine loss, rather than using cross-entropy on class indices. To reduce computational overhead, high-dimensional LLM embeddings (e.g., 4,096D) are compressed with the Matryoshka model, which preserves nearest-neighbor rankings in lower dimensions (e.g., 1,024D). At inference, a node's predicted embedding is compared via cosine similarity to all stored subtype embeddings to assign a label, effectively performing nearest-neighbor classification in the learned LLM-derived semantic space.

## Key Results
- Compacted LLaMA-3 (1,024D) embedding achieved a weighted average F1-score of 0.8766, surpassing the one-hot baseline of 0.8475.
- Dimensionality reduction via Matryoshka frequently boosted performance relative to original high-dimensional LLM embeddings.
- LLM embeddings effectively captured subtle semantic relationships between building object subtypes, enabling more accurate classification.

## Why This Works (Mechanism)
**Mechanism 1: LLM Embeddings Encode Relational Semantics**
Pretrained LLMs generate vector embeddings by learning statistical co-occurrences from vast text corpora, implicitly encoding semantic similarities (e.g., "parapet wall" nearer to "balcony parapet wall" than to "foundation"). This geometric arrangement preserves nuanced, non-uniform distances between building subtypes, unlike equidistant one-hot vectors. Evidence includes the abstract's F1-score improvement and section 3's statement that LLM embeddings capture relative similarities. Break condition: LLM training corpora may lack sufficient AECO jargon, leading to poor subtype distinction.

**Mechanism 2: Cosine Loss Forces Semantic Space Learning**
Replacing classification loss with cosine embedding loss optimizes the GraphSAGE model to produce output vectors geometrically similar to target LLM embeddings, rather than forcing discrete class boundaries. This guides the model to internalize the continuous semantic topology defined by the LLM. The architecture uses a 1,024-dimensional output layer to match the target embedding dimension. Evidence from section 3.1 and the experimental setup. Break condition: Inadequate model capacity to map BIM graphs into the LLM's high-dimensional space.

**Mechanism 3: Matryoshka Compaction Retains Salient Signals**
Matryoshka projects high-dimensional embeddings into lower-dimensional nested subspaces, preserving nearest-neighbor rankings. This compaction retains the most discriminative semantic cues for the 42 subtypes while removing less informative dimensions, often improving performance. Evidence: section 5 shows compacted LLaMA-3 (0.8766) outperformed original (0.8714). Break condition: Over-compression may collapse critical distances between hard-to-distinguish subtypes.

## Foundational Learning
- **Semantic Triangle (Triangle of Reference):** Distinguishes referent (real BIM object), reference (abstract subtype concept), and symbol (numeric encoding). Needed to understand why encoding choice impacts semantic comprehension. Quick check: For "penthouse core slab," the referent is the actual physical element, the reference is the abstract concept, and a one-hot symbol is a sparse binary vector while an LLM embedding is a dense vector reflecting textual semantics.
- **Graph Neural Networks (GNNs) for Structured Data:** GNNs like GraphSAGE aggregate neighborhood information in graphs (BIM objects as nodes, relationships as edges), leveraging contextual semantics provided by LLM encodings. Needed because BIM data is relational, not isolated. Quick check: Why is GraphSAGE better than an MLP for BIM subtype classification? Because it considers spatial and containment relationships between objects, which are crucial for context.
- **Cosine Similarity as an Embedding Space Metric:** Measures angular proximity between vectors, aligning with LLM embeddings' normalized unit vectors. Needed as the loss function operates on cosine similarity, not Euclidean distance. Quick check: If "core wall" and "horizontal wall" have cosine similarity 0.85, they are semantically close; one-hot would treat them as completely distinct with zero similarity.

## Architecture Onboarding
Component map:
BIM Graph Preprocessor -> LLM Encoding Service -> Matryoshka Dimensionality Reducer -> GraphSAGE Model (3 layers, 1024-dim) -> Training Loop (Cosine Loss) -> Inference Classifier (Nearest-Neighbor Lookup)

Critical path:
Data Preparation -> Target Embedding Generation (LLM + Matryoshka) -> Model Definition (Output Dim = Target Embed Dim) -> Training (Cosine Loss) -> Evaluation (Nearest-Neighbor in Embedding Space)

Design tradeoffs:
- LLM Choice vs. Domain Fit: Larger general LLMs may capture broader semantics but introduce noise; smaller fine-tuned models might be more precise.
- Compacted vs. Original Dimensions: Lower dimensions reduce compute and may denoise, but risk losing subtleties; must match model capacity.
- Loss Function: Cosine loss is essential; cross-entropy would destroy continuous semantic structure.

Failure signatures:
- Mismatched Dimensions: GraphSAGE output dim ≠ target embedding dim → training crashes or NaNs.
- Embedding Space Drift: Model converges but nearest-neighbor lookup yields confused classifications for similar subtypes; check t-SNE plots.
- Matryoshka Over-compression: Too small target dimension (e.g., 256D) → performance drops below one-hot.
- API/Model Inconsistency: Non-deterministic LLM embeddings → irreproducible runs.

First 3 experiments:
1. Embedding Quality & Separation: Generate LLM embeddings for all 42 subtypes, compute pairwise cosine similarities, visualize with t-SNE. Expect coherent clusters for semantically related groups. Goal: Confirm LLM encodes meaningful distinctions for this taxonomy.
2. Loss Function Verification: Train a tiny model on a synthetic subset with cross-entropy vs. cosine loss. Expect cosine loss to produce output embeddings matching target LLM similarities. Goal: Prove custom loss functions as intended.
3. Dimensionality Sweep & Capacity Alignment: For one LLM, vary compacted target dimensions (256D, 512D, 1024D) with fixed 1024D model. Expect peak performance when target dim ≈ model output dim. Goal: Find optimal compacted dimension.

## Limitations
- Generalization to niche AECO jargon is uncertain; LLMs may lack exposure to specialized subtype distinctions (Medium confidence).
- Performance is highly sensitive to precise alignment between model output dimension and target embedding dimension (High confidence).
- Direct evidence that cosine loss forces the model to replicate LLM's semantic topology is circumstantial; no ablation on output embedding space structure (Low-Medium confidence).

## Confidence

- Cosine loss preserves semantic topology: Low-Medium confidence
