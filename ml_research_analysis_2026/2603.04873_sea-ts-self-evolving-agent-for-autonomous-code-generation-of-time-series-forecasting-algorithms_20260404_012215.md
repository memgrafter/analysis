# SEA-TS: Self-Evolving Agent for Autonomous Code Generation of Time Series Forecasting Algorithms

## Quick Facts
- **arXiv ID**: 2603.04873
- **Source URL**: https://arxiv.org/abs/2603.04873
- **Reference count**: 40
- **Primary result**: SEA-TS reduces MAE by 40% on Solar-Energy benchmark vs TimeMixer; improves WAPE by 8.6% (solar PV) and 7.7% (residential load) on proprietary data; and achieves 26.17% MAPE vs TimeMixer's 29.34%.

## Executive Summary
SEA-TS is a self-evolving agent that autonomously generates and optimizes time series forecasting algorithms, addressing key challenges in conventional ML development such as data scarcity, distribution shift, and diminishing returns. It integrates Metric-Advantage Monte Carlo Tree Search for discriminative reward signals, automated code review with running prompt refinement to prevent logical flaws like data leakage, and Global Steerable Reasoning for cross-trajectory knowledge transfer, all within a MAP-Elites archive to maintain architectural diversity. On the public Solar-Energy benchmark, SEA-TS reduces MAE by 40% relative to TimeMixer. On proprietary datasets, it lowers WAPE by 8.6% for solar PV and 7.7% for residential load forecasting compared to human-engineered baselines, and achieves 26.17% MAPE versus TimeMixer's 29.34%. The framework also autonomously discovers novel patterns, including physics-informed monotonic decay heads and learnable hourly bias correction.

## Method Summary
SEA-TS operates an iterative self-evolution loop that combines Monte Carlo Tree Search (MCTS) with large language model (LLM) code generation. At each iteration, an UCT selector picks a parent node from a search tree; a prompt assembler constructs a full prompt from base, running, and context components; an LLM generates candidate code; a sandbox executes the code and computes a performance metric; an automated code reviewer flags logical flaws; a global reasoner compares the current node against the global best and worst solutions to extract transferable insights; a prompt updater refines the running prompt with distilled findings; and an MCTS backpropagator computes a normalized advantage reward and updates tree statistics. A MAP-Elites archive maintains elite solutions across three behavioral dimensions (architecture type, feature engineering, training sophistication) to ensure diversity. The reward signal is a z-score normalized advantage that scales with the historical metric distribution, providing discriminative guidance. The system runs for T=500 iterations using GPT-5 or Qwen3-coder-plus, with 343 archive cells.

## Key Results
- Solar-Energy benchmark: MAE reduced by 40% relative to TimeMixer.
- Proprietary solar PV forecasting: WAPE reduced by 8.6% vs human-engineered baseline.
- Proprietary residential load forecasting: WAPE reduced by 7.7%; MAPE 26.17% vs TimeMixer's 29.34%.

## Why This Works (Mechanism)
### Mechanism 1: Metric-Advantage MCTS (MA-MCTS)
- **Claim**: Provides a discriminative, adaptive reward signal that directs search toward high-potential solutions while avoiding inflated scores from flawed code.
- **Mechanism**: The advantage \( A_j = (\mu(M) - M_j)/\sigma(M) \) z-score normalizes each new metric \( M_j \) against the historical distribution \( M \). The reward \( R_j = A_j \) (for non-buggy code) is statistically scaled, so a fixed absolute improvement yields a larger reward as \( \sigma(M) \) shrinks during maturation. Breakthroughs (\( A_j \gg 1 \)) strongly backpropagate, while mediocre gains yield weak signals.
- **Core assumption**: The historical metric distribution \( M \) accurately reflects the current search landscape and \( \sigma(M) \) reliably decreases as better solutions are found.
- **Evidence anchors**: 
  - Abstract: "replaces fixed rewards with a normalized advantage score for discriminative search guidance"
  - Section 3.3: Equation 6 defines advantage and states it provides "discriminative (Aj ≫ 1 for breakthroughs), adaptive (scale adjusts as M evolves), and metric-agnostic reward signals."
- **Break condition**: If \( M \) is too small or noisy early in search, \( \mu(M) \) and \( \sigma(M) \) become unstable, making \( A_j \) unreliable and potentially misguiding search.

### Mechanism 2: Code Review with Running Prompt Refinement
- **Claim**: Prevents reward hacking (e.g., data leakage) by persistently encoding corrective patterns into the generation prompt, stopping flawed logic from recurring.
- **Mechanism**: After a node executes without runtime error, an LLM reviewer flags logical flaws (e.g., \( b_j=true \)). The review findings are distilled into the running prompt \( P_{run} \), which is concatenated with the base prompt for all future generations. This creates a persistent, accumulating safeguard.
- **Core assumption**: The distilled review insights are sufficiently general and precise to prevent recurrence of the *class* of error, not just the specific instance.
- **Evidence anchors**:
  - Abstract: "automated code review with running prompt refinement to prevent recurrence of similar errors"
  - Section 3.4.3: "the running prompt \( P_{run} \) is updated after every code review... Both the review findings and the Global Steerable Reasoning insights are distilled... persistently encoding strategies in \( P_{run} \)."
  - Section 3.4.2: Lists specific review checks: "data leakage in feature engineering", "incorrect inverse normalization", "train-test contamination".
- **Break condition**: If prompt update distillation fails to extract a generalizable rule or introduces contradictions into \( P_{run} \), the safeguard degrades and similar flaws may reappear.

### Mechanism 3: Global Steerable Reasoning
- **Claim**: Enables cross-trajectory knowledge transfer by comparing each node against global best (\( N^* \)) and worst (\( N^\perp \)) solutions, allowing the agent to emulate high-level strategies and avoid pitfalls from unrelated branches.
- **Mechanism**: For each evaluated non-buggy node, the system constructs a prompt \( P_{global} \) containing the code, plan, and metric of \( N^* \), \( N^\perp \), and the current node. An LLM generates a summary of strategies to emulate/avoid. This summary is fed into \( P_{run} \) (persistent) and also appended to the current node's context for its children.
- **Core assumption**: The global best and worst solutions are sufficiently distinct and representative of high/low performance to yield extractable, transferable insights.
- **Evidence anchors**:
  - Abstract: "compares each node against global best and worst solutions, enabling cross-trajectory knowledge transfer"
  - Section 3.5.2: "We construct a structured comparison: \( P_{global} = \{(c^*, p^*, M^*), (c^\perp, p^\perp, M^\perp), (c_j, p_j, M_j)\} \)" and "enables cross-trajectory knowledge transfer: insights from one search branch inform generation in entirely different branches."
  - Section 3.5.3: Notes the comparison summary is fed into the running prompt refinement.
- **Break condition**: If global best and worst become architecturally very similar (e.g., search converges prematurely), the comparison yields trivial or non-actionable insights.

## Foundational Learning
- **Monte Carlo Tree Search (MCTS) with UCT**: Needed because SEA-TS's search loop is built on MCTS, balancing exploration vs exploitation via the UCT formula \( UCT(N_j) = Q_j/n_j + C \sqrt{\ln(n_{parent})/n_j} \). *Quick check*: If a node has high \( Q_j/n_j \) but low visit count \( n_j \), will UCT select it? Why? (Answer: Yes, because the exploration term \( C \sqrt{\ln(n_{parent})/n_j} \) will be large when \( n_j \) is small, potentially outweighing a slightly lower exploitation term.)
- **Reward shaping and normalization**: Needed because raw metric improvements \( \Delta M \) are poor signals; the Metric-Advantage reward uses z-score normalization \( (x-\mu)/\sigma \) to create a relative, discriminative scale. *Quick check*: In late search, \( \sigma(M) \) is small. Does a constant absolute metric improvement yield a larger or smaller \( A_j \) compared to early search? What is the behavioral effect? (Answer: Larger \( A_j \) because dividing by a smaller \( \sigma \) amplifies the same absolute difference; this means later improvements are rewarded more heavily, accelerating fine-tuning.)
- **Quality-Diversity (QD) optimization with MAP-Elites**: Needed to maintain diverse elite solutions across behavioral dimensions, preventing premature convergence to a single architecture. *Quick check*: If two solutions have identical performance \( M \) but fall into different MAP-Elites cells (different \( d_1, d_2, d_3 \)), what does the archive do with them? (Answer: Both are kept as elites in their respective cells because the archive stores the best performer per cell; if they are in different cells, they both occupy those cells.)

## Architecture Onboarding
- **Component map**: UCT Selector -> Prompt Assembler -> LLM Generator -> Sandbox Executor -> Code Reviewer -> Global Reasoner -> Prompt Updater -> MCTS Backpropagator -> MAP-Elites Manager.
- **Critical path**: The iterative self-evolution loop (steps 3–28 in Algorithm 1). Failures in sandbox execution or LLM generation halt progress. The \( P_{run} \) update is a key feedback mechanism shaping all subsequent generations.
- **Design tradeoffs**:
  - LLM call cost vs search depth: 4 potential LLM calls per iteration; more calls improve signal quality but increase cost and latency.
  - Archive dimensionality: 3 dimensions (as used) balance diversity and budget; more dimensions increase cell sparsity; fewer risk convergence.
  - \( C \) in UCT: Higher \( C \) favors exploration (trying new parents), lower favors exploitation (deepening promising branches); paper uses \( \sqrt{2} \).
- **Failure signatures**:
  - Stagnant \( Q_j/n_j \): No improvement for many iterations suggests local optimum; check \( P_{run} \) for overfitting or \( \sigma(M) \) collapse.
  - High buggy rate (\( b_j=true \)): Persistent logical flaws; likely \( P_{run} \) ineffective or base prompt lacks clear constraints.
  - Archive cell starvation: Many MAP-Elites cells remain empty; dimensions may be poorly defined or \( P_{archive} \) sampling not encouraging diversity.
- **First 3 experiments**:
  1. Sanity check: Run with \( T=10 \) iterations on a trivial synthetic dataset. Verify loop executes, \( M_j \) computed, \( P_{run} \) grows, \( N^* \) updates.
  2. Component isolation: Disable code review (always \( b_j=false \)). Expect rapid performance inflation due to reward hacking (data leakage). Re-enable and compare.
  3. Archive behavior: Log which MAP-Elites cells get populated over \( T=100 \). Verify diversity across \( d_1 \) (architecture type). Try forcing all \( d_1=0 \) (tree-based) and compare convergence speed to baseline.

## Open Questions the Paper Calls Out
- How can the MAP-Elites archive dimensions be automatically determined from task characteristics instead of manual definition? (Section 3.6 and future work)
- What is the most effective mechanism for injecting domain-specific knowledge (e.g., physical laws, priors) into the SEA-TS search process? (Future work)
- How can coding agents and deep research agents be integrated into a unified framework to enable on-demand knowledge retrieval for expert-level algorithm design? (Section 4.3.2)
- Can multi-objective optimization (accuracy, latency, model size) be effectively incorporated into SEA-TS to produce deployment-ready models? (Future work)

## Limitations
- Missing full source code and exact prompt templates hinder faithful replication; sandbox execution, tree structures, and archive indexing details are undisclosed.
- Running prompt refinement's distillation logic and potential for prompt degradation/contradiction over iterations are not specified, risking safeguard failure.
- Global reasoning relies on sufficient archive diversity; if MAP-Elites converges poorly, insights become trivial; proprietary dataset and baseline details are also undisclosed.

## Confidence
- MA-MCTS discriminative reward: Medium (mechanism defined, but early-search stability unvalidated)
- Code review preventing leakage: High (specific checks listed, but depends on LLM accuracy)
- Global Steerable Reasoning transfer: Medium/Low (conceptually sound, but effectiveness hinges on archive diversity and insight generalizability)
- Autonomous discovery of novel patterns: Low (claims lack ablative evidence; may be emergent from search space)

## Next Checks
1. Code review efficacy test: Disable automated review (always `b_j=false`) and run SEA-TS on Solar-Energy. Expect rapid metric inflation from leakage (e.g., features using future data). Re-enable review and compare final MAE and leakage flag rates.
2. Prompt degradation audit: Periodically sample `P_run` during a long run (T>200). Manually inspect for contradictory rules (e.g., "avoid leakage" vs "use rolling stats without shift"). Track repetition of review findings—persistent identical findings suggest ineffective distillation.
3. Archive diversity verification: After T=100, log MAP-Elites cell occupancy per dimension (`d1` architecture type, `d2` feature engineering, `d3` training sophistication). Compute entropy across cells. Artificially constrain `d1` to one type and measure convergence speed drop versus unrestricted search.
