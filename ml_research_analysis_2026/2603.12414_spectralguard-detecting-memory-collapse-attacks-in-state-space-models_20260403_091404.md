# SpectralGuard: Detecting Memory Collapse Attacks in State Space Models

## Quick Facts
- **arXiv ID:** 2603.12414
- **Source URL:** https://arxiv.org/abs/2603.12414
- **Reference count:** 40
- **Primary result:** SpectralGuard detects memory collapse attacks with F1=0.961 (non-adaptive) and 0.842 (adaptive), adding <15 ms per-token overhead and generalizing to hybrid SSM-Attention architectures.

## Executive Summary
State Space Models (SSMs) such as Mamba are shown to be vulnerable to a novel attack—Hidden State Poisoning—where adversarial inputs drive the spectral radius of the discretized transition operator toward zero, collapsing the model’s effective memory from millions to dozens of tokens without any detectable anomalies in the output distribution. This paper introduces SpectralGuard, a real-time monitoring system that tracks spectral stability across all model layers using a multi-layer classifier based on spectral radius, variance, and spectral gap features. SpectralGuard achieves high detection accuracy (F1=0.961) against non-adaptive attackers and retains robust performance (F1=0.842) even under strong adaptive attacks, with minimal computational overhead (<15 ms per token). It generalizes to hybrid SSM-Attention architectures and causal experiments confirm the spectral radius as a mechanistic control variable for memory, establishing that output-only defenses are provably insufficient.

## Method Summary
The paper first establishes a theoretical link between the spectral radius ρ(¯A) of the discretized state transition matrix and the effective memory horizon Heff of an SSM. As ρ approaches 1 from below, information decays slowly and the horizon expands; as ρ approaches 0, the horizon collapses exponentially. Building on this, the authors demonstrate a gradient-based attack, HiSPA, that manipulates the input-dependent discretization step Δt to minimize ρ across the sequence, causing catastrophic memory loss while preserving output plausibility.

To counter this threat, they propose SpectralGuard, a lightweight runtime monitor. SpectralGuard hooks into each layer to capture the discretized operator ¯At, estimates its spectral radius via a few power iterations, and aggregates features (mean ρ, variance, spectral gap) over a sliding window across all layers. A logistic classifier, trained on benign and attack data, decides whether to block the output. The system is calibrated on held-out benign data and operates with sub-millisecond per-layer overhead, making it suitable for deployment.

## Key Results
- SpectralGuard detects non-adaptive memory collapse attacks with F1 score 0.961 and maintains F1=0.842 against adaptive attackers aware of the threshold.
- The monitor adds negligible overhead (<15 ms per token) and generalizes to hybrid architectures like Zamba2 (F1=0.891).
- Causal intervention experiments confirm that directly clamping the spectral radius degrades performance on memory-intensive tasks, establishing ρ as a mechanistic control variable.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The effective memory horizon of an SSM is fundamentally bounded by the spectral radius ρ(¯A) of its discretized transition operator.
- **Mechanism:** The recurrence `ht = ¯At ht−1 + ...` causes information from the initial state `h0` to decay geometrically at rate ρ(¯A). Theorem 1 gives a bound on `Heff` in terms of ρ(¯A), condition number κ(¯A), and the controllability Gramian. As ρ → 1⁻, decay slows and `Heff` grows; as ρ → 0, `Heff` collapses.
- **Core assumption:** The SSM operates in a linearly stable regime (ρ(¯A) < 1) and the bound assumes a stationary spectral radius; selective SSMs modulate ρ token-by-token.
- **Evidence anchors:** [abstract] "the spectral radius ρ(¯A) of the discretized transition operator governs effective memory horizon"; [section 3.1] Theorem 1 and Corollary 2; corpus includes "Spectral State Space Models" and related formalism.
- **Break condition:** The bound is a worst-case ceiling; empirical horizons are often much shorter due to token-dependent ρ fluctuations, task-specific capacity limits, and interference from subsequent inputs. It remains diagnostically useful: when ρ drops, `Heff` must shrink—though the quantitative prediction is loose.

### Mechanism 2
- **Claim:** Adversarial inputs can force spectral collapse by minimizing ρ(¯At) via gradient-based manipulation of the input-dependent discretization step Δt (HiSPA attack), destroying long-range reasoning without output-level alarms.
- **Mechanism:** Selective SSMs compute `Δt = σ(WΔ xt)`. An attacker with white-box access optimizes the input sequence `x1:T` to minimize `Σt ρ(exp(Δt A))` using PGD, driving eigenvalues toward zero and causing exponential state contraction (e.g., `0.31^0 ≈ 6e-6`) that obliterates history while keeping output distributions plausible.
- **Core assumption:** The attacker can compute gradients through `xt → Δt → ¯At → ρ`; the input-dependent discretization creates a gradient pathway from token choice to spectral properties.
- **Evidence anchors:** [abstract] "adversarial inputs drive the spectral radius ... toward zero, causing memory collapse ... without output-level alarms"; [section 2.4] "the input-dependent discretization introduces a gradient pathway"; [section 4.4] attack algorithm and threat model.
- **Break condition:** Requires white-box gradient access and a selective SSM with input-dependent Δ. Black-box settings or fixed-Δ SSMs (e.g., S4) are not vulnerable. The attack may also fail if the model uses robust discretization (e.g., clamps Δt) or if spectral radius cannot be driven sufficiently low due to parameter constraints.

### Mechanism 3
- **Claim:** Output-only defenses are provably insufficient against spectral collapse (Theorem 3), and monitoring internal dynamics via SpectralGuard provides a deployable, conditionally complete defense.
- **Mechanism:** SpectralGuard computes ρ(¯At) per layer in real-time via the power method (k=3), aggregates features (mean ρ, variance, spectral gap) across all layers, and classifies with a logistic model. It triggers when the minimum ρ in a sliding window `w` falls below threshold `ρmin`, blocking outputs.
- **Core assumption:** Memory-collapsing attacks necessarily reduce ρ(¯At) below a critical threshold (ρcritical ≈ 0.90)—empirically supported by the phase transition and causal intervention.
- **Evidence anchors:** [abstract] "prove an evasion existence theorem ... introduce SpectralGuard"; [section 3.3] Theorem 3 proof; [section 4.6] Algorithm 2; [section 5.3] empirical results (F1=0.961 non-adaptive, F1=0.842 adaptive).
- **Break condition:** The completeness guarantee (Theorem 4) is conditional on the spectral collapse assumption. Attacks that degrade memory via non-spectral mechanisms (e.g., corrupting specific eigenvectors while preserving ρ) could evade. Adaptive attackers might mimic benign multi-layer spectral statistics, though residual separability remains (F1=0.842). False positives occur if benign ρ drops below `ρmin`.

## Architecture Onboarding
**Component map:**
1. **Victim SSM:** Mamba (or hybrid like Zamba2) with `d_state=16`, 24–48 layers. Key components: continuous matrix `A`, input projections `WΔ` → `Δt`, discretization `¯At = exp(Δt A)`.
2. **HiSPA Attacker:** PGD optimizer on input tokens, loss `Σt ρ(¯At)`, with output plausibility constraint (low KL to benign distribution).
3. **SpectralGuard Monitor:** Forward hooks capture `¯At` per layer; power method estimates ρ; sliding window aggregates; logistic classifier on 48-dimensional feature vector (ρ, variance, gap × 24 layers); threshold gate.
4. **Calibration module:** Held-out benign data to set `ρmin` and train classifier.

**Critical path:**
During inference, for each token and each layer:
`xt` → `Δt` (via `WΔ`) → `¯At = exp(Δt A)` → power method (k=3) → feature vector update → `min(window)` check → if below `ρmin` → `BLOCK`; else update `ht` → output `yt`.
The critical computational cost is O(L·d_state²) for L layers (matrix-vector products), which is negligible vs. forward pass (≈0.02% FLOPs).

**Design tradeoffs:**
- **Single-layer vs. multi-layer:** Single-layer (monitor one layer) is simpler but brittle against adaptive attackers that can keep ρ above threshold on that layer. Multi-layer uses cross-layer statistics (variance, gaps) and achieves F1=0.961 vs 0.619.
- **Threshold ρmin:** Lower → fewer false negatives but more false positives. Calibrated on benign data to balance. Paper uses ρmin=0.30 based on phase transition (ρcritical≈0.90) and benign distribution tail.
- **Window size w:** Larger w catches slow attacks but adds latency. w=10 optimal (perfect detection, +0ms vs w=5).
- **Power iterations k:** k=1 noisy (F1=0.94), k=2 sufficient (FPR=0), k=3 recommended (default). More iterations add latency without gain.

**Failure signatures:**
1. **Spectral collapse pattern:** Sustained ρ < ρmin across layers 4–10 specifically (Figure 7), while early layers 0–3 remain high. If collapse occurs only in late layers, may be less critical.
2. **High FPR on benign:** If benign prompts trigger, ρmin may be too low or window too short. Check benign ρ distribution calibration.
3. **Adaptive evasion:** If adversarial ρ distributions overlap benign ones on the 48-D feature space, the classifier's precision/recall will drop (as seen: F1 from 0.961 to 0.842 under multi-layer-aware attack).
4. **Latency spike:** If power method or feature aggregation exceeds budget (sub-15ms target), consider reducing monitored layers (critical layers 4–10 only) or reducing k.

**First 3 experiments:**
1. **Spectral horizon validation (Exp 1):** Run associative recall (N=500) across context distances {10,1k}. Plot accuracy vs. measured ρ(¯A). Verify phase transition at ρ≈0.90 and Pearson r≈0.49.
2. **HiSPA attack demonstration (Exp 2):** Take a benign CoT prompt, run gradient-based HiSPA (Algorithm 1, 50 PGD steps). Measure ρ collapse and accuracy drop on 4 tasks. Visualize hidden-state trajectories (PCA) to see contraction.
3. **SpectralGuard end-to-end (Exp 3):** With calibrated ρmin and trained multi-layer classifier, evaluate on 500 balanced prompts (250 benign, 250 adversarial). Report F1, AUC, FPR, latency. Repeat under adaptive attack (adversary aware of threshold) to stress-test.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Is the Pareto trade‑off between lexical evasion and spectral damage fundamental or an artifact of current attack algorithms?
- **Basis in paper:** [explicit] "Systematic exploration of this frontier across diverse attacker families will reveal whether the trade‑off is fundamental or an artifact of current optimization strategies" (Section 6.6).
- **Why unresolved:** The evaluation covers three attacker families with limited regularization weights; alternative constructions might achieve high lexical stealth while causing significant spectral collapse.
- **What evidence would resolve it:** A comprehensive benchmark of a broad spectrum of attacks (including black‑box, white‑box, and adaptive variants) plotting lexical indistinguishability versus spectral damage. If no attack breaks the frontier, the trade‑off is intrinsic; otherwise, it may be surmountable.

### Open Question 2
- **Question:** Can adversarial robust training on frontier adaptive prompts narrow the gap between non‑adaptive and adaptive detection performance?
- **Basis in paper:** [explicit] "Retraining the detector with frontier adversarial prompts and calibrated thresholds can close the gap between non‑adaptive (F1=0.961) and adaptive (F1=0.842) performance" (Section 6.6).
- **Why unresolved:** SpectralGuard was not retrained on adaptive attacks; its threat model only covers non‑adaptive and limited adaptive settings.
- **What evidence would resolve it:** Train a multi‑layer spectral classifier on a dataset that includes state‑of‑the‑art adaptive attacks (e.g., multi‑layer‑aware HiSPA). Compare detection metrics on held‑out adaptive attacks with and without adversarial training; a significant increase in F1 toward the non‑adaptive baseline would confirm the benefit.

### Open Question 3
- **Question:** Do spectral collapse signatures hold universally across SSM variants and hybrid recurrent‑Transformer models?
- **Basis in paper:** [explicit] "Extending the framework to additional SSM and hybrid architectures (Mamba‑2 variants, Jamba) will test whether spectral collapse signatures are universal properties of recurrent computation" (Section 6.6).
- **Why unresolved:** Experiments are limited to Mamba‑1 and Zamba2; newer architectures like Mamba‑2, RWKV, Jamba, and RetNet might exhibit different dynamics.
- **What evidence would resolve it:** Replicate the HiSPA attack and spectral monitoring on these models. If the attack consistently induces ρ drop and SpectralGuard detects it with similar accuracy, the property is universal; otherwise, architecture‑specific adjustments are needed.

### Open Question 4
- **Question:** How does the presence of attention layers in hybrid models affect the propagation and recovery from SSM spectral collapse?
- **Basis in paper:** [explicit] "In Zamba2, attention pathways can partially mask downstream effects of SSM collapse… Controlled clamp‑release experiments measuring time‑to‑recovery would clarify this interaction" (Limitation 2).
- **Why unresolved:** The paper observed collapse but did not quantify attention’s compensatory role or temporal recovery dynamics.
- **What evidence would resolve it:** Clamp spectral radius in SSM sub‑blocks of hybrid models for increasing numbers of tokens, then release and measure accuracy recovery speed. Ablate attention layers to isolate their contribution. Comparison with pure SSMs would quantify masking effects.

### Open Question 5
- **Question:** Can an attacker collapse memory without reducing the spectral radius, for example via eigenvector manipulation or selective state corruption?
- **Basis in paper:** [explicit] "The theoretical possibility of attacks that degrade memory through mechanisms other than spectral radius reduction… such attacks would evade SpectralGuard in its current form and represent an important direction for future work" (Theorem 4 Remark and Section 6).
- **Why unresolved:** SpectralGuard relies on monitoring ρ as a proxy; attacks preserving ρ but altering other spectral properties (e.g., condition number, eigenvector alignment) might still cause collapse yet remain undetected.
- **What evidence would resolve it:** Construct attacks that target non‑spectral factors (e.g., minimizing smallest eigenvalue or perturbing specific state dimensions) while keeping ρ above threshold. Evaluate whether these attacks cause significant accuracy drops on memory‑heavy tasks without triggering SpectralGuard.

## Limitations
- **Theoretical bound looseness:** The worst-case bound on memory horizon is loose; empirical horizons are much shorter due to token-dependent spectral fluctuations and task interference.
- **Attack scope:** HiSPA vulnerability only demonstrated for white-box selective SSMs; other SSM variants (black-box, fixed-Δ) remain untested.
- **Defense assumptions:** SpectralGuard assumes all memory-collapse attacks reduce spectral radius; attacks that evade this (e.g., via eigenvector manipulation) or strong adaptive attackers (F1=0.842) could succeed. Deployment factors like calibration shifts and real-world batching are not fully stress-tested.

## Confidence
- Spectral radius governs memory horizon: Medium
- Adversarial spectral collapse via HiSPA: Medium‑High
- SpectralGuard’s deployable efficacy: Medium

## Next Checks
1. **Generalization test:** Run SpectralGuard on non-selective SSMs (e.g., S4, HIPPO) and hybrid architectures beyond Zamba2 to validate multi-layer feature robustness across discretization schemes.
2. **Black-box attack evaluation:** Craft transferable adversarial prompts without gradient access (e.g., boundary-based attacks) and measure SpectralGuard’s detection rate; if evasion occurs, investigate spectral-agnostic attack vectors.
3. **Distribution shift stress test:** Calibrate SpectralGuard on one text domain (e.g., code) and evaluate false positive/negative rates on radically different domains (e.g., multilingual, structured logs) to assess calibration stability.
