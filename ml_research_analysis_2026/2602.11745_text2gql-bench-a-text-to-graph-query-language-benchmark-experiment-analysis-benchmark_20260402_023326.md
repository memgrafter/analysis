# Text2GQL-Bench: A Text to Graph Query Language Benchmark [Experiment, Analysis & Benchmark]
## Quick Facts
- arXiv ID: 2602.11745
- Source URL: https://arxiv.org/abs/2602.11745
- Reference count: 40
- Primary result: Text2GQL-Bench reveals a stark dialect gap: strong LLMs achieve ≤4% zero-shot execution accuracy on ISO-GQL; fine-tuning with target GQL examples yields up to 45.1% execution accuracy.

## Executive Summary
Text2GQL-Bench introduces the first comprehensive benchmark for translating natural language questions into graph query language (GQL) queries. It provides a large-scale dataset of 178,184 (Question, Query) pairs across 13 domains, a scalable construction framework, and a multi-faceted evaluation methodology covering grammatical validity, string similarity, semantic alignment, and execution accuracy. Evaluations with state-of-the-art language models reveal a significant performance gap: in zero-shot settings, even powerful LLMs achieve at most 4% execution accuracy on ISO-GQL, indicating limited inherent capability. Incorporating three exemplars via few-shot prompting raises accuracy to approximately 50%, though grammatical correctness remains below 70%. Importantly, fine-tuning an 8-billion parameter open-weight model on the benchmark data yields 45.1% execution accuracy and 90.8% grammatical validity, underscoring that exposure to target GQL examples is the primary lever for improvement.

## Method Summary
The authors propose a scalable framework for generating (Question, Query) pairs, likely by sampling graph schemas and associated GQL queries, then producing natural language questions. However, the exact details of query generation, schema sampling, and annotation (synthetic vs. human) remain insufficiently documented, hindering exact replication. The evaluation method computes grammatical validity (ISO-GQL syntax adherence), string similarity, semantic alignment, and execution accuracy against a database.

## Key Results
- Zero-shot execution accuracy for strong LLMs ≤4% on ISO-GQL.
- 3-shot prompting increases execution accuracy to ~50%, but grammatical validity ≤70%.
- Fine-tuned 8B model achieves 45.1% execution accuracy and 90.8% grammatical validity.

## Why This Works (Mechanism)
The paper does not provide an explicit mechanism analysis; however, the superior performance of fine-tuned models suggests that exposure to target GQL examples is crucial for learning the syntax and semantics of graph queries. Few-shot improvements indicate that in-context examples help but are limited by the model’s pre-trained knowledge of ISO-GQL.

## Foundational Learning
- **ISO-GQL (Graph Query Language)**  
  *Why needed*: The target formalism; understanding its clauses (MATCH, WHERE, RETURN) and semantics is essential to judge correctness.  
  *Quick check*: Can you write a simple MATCH‑RETURN query? Do you know how to express filters and aggregations?

- **Natural Language to Query Translation**  
  *Why needed*: Core task of mapping NL descriptions to formal queries.  
  *Quick check*: Given a question and a graph schema, can you sketch the corresponding query structure?

- **Synthetic Data Generation**  
  *Why needed*: The benchmark scales via automated generation; diversity and noise injection affect model learning.  
  *Quick check*: What techniques exist for generating synthetic (NL, query) pairs? How can surface realization be varied while preserving meaning?

- **Evaluation Metrics**  
  *Why needed*: To measure both syntactic correctness (grammatical validity) and functional correctness (execution accuracy).  
  *Quick check*: How is execution accuracy computed? What does grammatical validity capture (parser‑based check)?  

## Architecture Onboarding
**Component Map**: Schema Sampler → Query Generator → Question Generator → Evaluation Module  
**Critical Path**: The generation process flows sequentially: sample a graph schema → generate a GQL query valid against that schema → produce a natural language question describing the query’s intent → evaluate the pair for quality and correctness.  
**Design Tradeoffs**:
- *Scalability vs. Diversity*: The framework prioritizes large‑scale generation, potentially reducing query complexity and domain variety.
- *Synthetic vs. Human Annotation*: Automated generation avoids costly labeling but may yield unnatural or simplistic questions.
- *Standard Compliance vs. Practicality*: Strict ISO‑GQL adherence ensures syntactic correctness but may not reflect real‑world, more permissive dialects.  
**Failure Signatures**:
- Low grammatical validity (<70%) in model outputs indicates difficulty with ISO‑GQL syntax.
- Near‑zero zero‑shot execution accuracy highlights a dialect gap: models lack pre‑trained GQL knowledge.
- Performance collapse on out‑of‑domain schemas suggests overfitting to the training distribution.  
**First Experiments**:
1. Zero‑shot evaluation of state‑of‑the‑art LLMs (e.g., GPT‑4, Claude) on the test set to establish baseline capability.
2. Few‑shot prompting with three exemplars from the same domain to measure in‑context learning gains.
3. Fine‑tuning an 8B open‑weight model on the training data and assessing execution accuracy and grammatical validity.

## Limitations
- Dataset construction details (synthetic vs. human, schema sampling) are vaguely specified, limiting reproducibility.
- Evaluation focuses on ISO‑GQL; generalizability to other graph query dialects (e.g., Cypher, SPARQL) is unverified.
- Grammatical validity metric (70% ceiling) may reflect rigid ISO compliance rather than practical usability; human evaluation is absent.

## Confidence
- Benchmark scale/coverage: **High**
- Zero‑shot ≤4% execution accuracy: **Medium**
- Few‑shot ~50% execution gain: **Medium**
- Fine‑tuned model 45.1% exec./90.8% grammar: **Medium**
- Dialect gap as primary barrier: **Medium**
