# Issues with Measuring Task Complexity via Random Policies in Robotic Tasks
## Quick Facts
- arXiv ID: 2602.18856
- Source URL: https://arxiv.org/abs/2602.18856
- Reference count: 40
- Primary result: RWG-based task complexity metrics (PIC, POIC) produce incorrect rankings in robotic manipulation tasks, due to static random policies failing to capture exploration dynamics.

## Executive Summary
This paper evaluates the reliability of Random Policy Generation (RWG)-based task complexity metrics—statistical analysis of random policy returns, Policy Information Capacity (PIC), and Policy-Optimal Information Capacity (POIC)—in robotic manipulation tasks with known relative difficulty. The tasks include 1-link versus 2-link arms and dense versus sparse rewards. While SAC learning curves confirm the expected ordering (1-link easier than 2-link; dense easier than sparse), PIC and POIC yield contradictions: PIC suggests the 2-link task is easier than the 1-link under the same reward, and POIC suggests sparse rewards are easier than dense for the same arm. The authors attribute these failures to the static nature of RWG, which does not capture exploration dynamics and performs poorly when high-performing policies are sparsely distributed. A structured task framework is proposed to benchmark future complexity metrics.

## Method Summary
The authors implement six manipulation environments: three arms (1-link, 2-link, 2-link with obstacle) combined with two reward types (dense and sparse). For each task, they sample 10,000 random MLP policies (two hidden layers of 32 ReLU units each, no bias) from a standard normal prior, execute each policy for 500 episodes, and record cumulative returns. From these returns, they compute the mean (M_n) and variance (V_n) across policies, and derive PIC and POIC by binning min-max normalized returns into B=10^5 bins and estimating entropy. Statistical significance is assessed via bootstrapped 95% confidence intervals (1,000 resamples) and Welch’s t-tests. To validate the expected difficulty, they train Soft Actor-Critic (SAC) agents, using Hindsight Experience Replay (HER) for sparse rewards, and compare learning curves.

## Key Results
- PIC incorrectly ranks the 2-link arm as easier than the 1-link arm under the same dense reward.
- POIC incorrectly ranks sparse rewards as easier than dense rewards for the 2-link arm.
- SAC learning curves confirm the expected difficulty ordering, contradicting the RWG-based metrics.

## Why This Works (Mechanism)
The inconsistencies arise because RWG samples static random policies from a fixed prior without any interaction with the environment. This approach fails to capture the exploration dynamics that are critical in reinforcement learning. In tasks where high-performing policies are sparsely distributed in the policy space (e.g., due to narrow optimal regions or obstacles), random sampling rarely encounters them, leading to return distributions that do not reflect true task difficulty. Consequently, entropy-based metrics like PIC and POIC become misleading, as they measure the spread of random returns rather than the learnability of the task.

## Foundational Learning
1. **Random Policy Generation (RWG)**  
   *Why needed*: To estimate task difficulty by analyzing performance of a broad set of untrained policies.  
   *Quick check*: Verify policy architecture (2-layer MLP, 32 units, no bias) and prior (N(0,I)) match the paper.

2. **Policy Information Capacity (PIC)**  
   *Why needed*: To quantify the information content of the return distribution under random policies.  
   *Quick check*: Compute entropy using B=10^5 bins after min-max normalization; ensure binning covers full return range.

3. **Policy-Optimal Information Capacity (POIC)**  
   *Why needed*: To emphasize returns near the maximum, approximating optimal performance.  
   *Quick check*: Confirm weighting scheme (e.g., proximity to max return) is correctly implemented.

4. **Bootstrapped Confidence Intervals**  
   *Why needed*: To assess statistical reliability of metric estimates.  
   *Quick check*: Perform 1,000 resamples and verify 95% CI width is reasonable.

5. **Welch’s t-test**  
   *Why needed*: To compare metrics between tasks without assuming equal variance.  
   *Quick check*: Apply pairwise and check p-values against significance threshold.

6. **Soft Actor-Critic (SAC)**  
   *Why needed*: To provide a ground-truth measure of task difficulty via learning curves.  
   *Quick check*: Train SAC on each task and compare sample efficiency; sparse tasks should use HER.

## Architecture Onboarding
- **Component map**: Task definitions (1-link, 2-link, obstacle; dense, sparse) → Random Policy Generator (RWG) → Return Collector (M=500 episodes per policy) → Metric Computation (PIC, POIC) → Statistical Analysis (bootstrapping, t-test). SAC Trainer provides validation.
- **Critical path**: Define tasks → run RWG (N=10^4 policies, M=500 episodes) → compute normalized returns → bin and compute entropies → compare metrics across tasks.
- **Design tradeoffs**: N=10^4 balances coverage and compute; M=500 stabilizes return estimates; B=10^5 bins yields fine-grained entropy; min-max normalization makes metrics scale-invariant but sensitive to outliers.
- **Failure signatures**: (1) Return distributions lack high-performing policies (sparsity). (2) PIC/POIC rankings contradict SAC learning curves. (3) High variance in bootstrapped CIs indicating insufficient samples.
- **First experiments**:  
  1. Reproduce return distribution plots (M_n, V_n) for 1-link dense and 2-link dense.  
  2. Compute PIC and POIC for all six task variants and verify the reported contradictions.  
  3. Train SAC on each task to confirm expected difficulty ordering (1-link < 2-link; dense < sparse).

## Limitations
- Physics engine, timestep, and integration method are unspecified, hindering exact replication.
- SAC+HER implementation details for sparse tasks are missing, limiting validation of learning curves.
- Evaluation is restricted to three simple arms, so generalizability to more complex tasks is unclear.

## Confidence
- PIC incorrectly ranks 2-link > 1-link (dense): **High**
- POIC incorrectly ranks sparse > dense (2-link): **High**
- Static RWG fails due to sparsity of high-return policies: **Medium**

## Next Checks

2. Quantify high-return sparsity: For each task, measure the proportion of random policies achieving >90% of max return; test correlation with PIC/POIC error magnitude.
3. Use SAC training data: Compute PIC/POIC on policies from SAC checkpoints (including early random and later learned). Check if metrics then match expected difficulty, supporting the exploration dynamics hypothesis.
