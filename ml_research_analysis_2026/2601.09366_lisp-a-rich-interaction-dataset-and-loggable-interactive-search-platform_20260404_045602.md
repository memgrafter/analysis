# LISP -- A Rich Interaction Dataset and Loggable Interactive Search Platform

## Quick Facts
- **arXiv ID**: 2601.09366
- **Source URL**: https://arxiv.org/abs/2601.09366
- **Reference count**: 40
- **Primary result**: A publicly released dataset and loggable search platform that enables investigation of user factors in IIR, with illustrative analysis showing topic interest significantly modulates search behavior.

## Executive Summary
This paper introduces LISP, a comprehensive dataset and interactive search platform designed to support research in Interactive Information Retrieval (IIR). The authors conducted a within-subject study with 61 participants across 122 sessions, using a custom-built search interface for argument retrieval. Participants' cognitive traits (perceptual speed) and topic interests were measured, and detailed interaction logs were recorded. The main contribution is a publicly available resource combining rich logs with user characteristics. An analysis of the dataset reveals that topic interest significantly influences search behavior: higher interest leads to more queries but less time per query and fewer document markings. The released infrastructure aims to lower barriers for reproducible IIR research and user simulation.

## Method Summary
The study employed a within-subject experimental design where each participant performed search tasks on topics rated as high-interest and low-interest. A total of 61 participants completed 122 search sessions using the LISP platform, which logs detailed interactions (queries, clicks, dwell times, argument markings). Prior to the search tasks, participants completed a web-based perceptual speed test and rated their interest in a set of topics. After each search session, they provided feedback. The collected data includes session logs, participant profiles (including perceptual speed scores and interest ratings), and task assignments. The entire infrastructure—including the search interface, test implementations, and study scripts—is open-sourced to support replication and extension.

## Key Results
- Released a public dataset and reproducible study infrastructure for IIR.
- Topic interest significantly modulates search behavior: high interest yields more queries but reduced time per query and fewer document interactions (p < 0.05).
- No significant effects of perceptual speed on the measured interaction metrics.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: The LISP dataset enables systematic investigation of how user characteristics (e.g., topic interest) influence interactive search behavior.
- **Mechanism**: By pairing fine-grained interaction logs (queries, clicks, time stamps) with pre-measured user traits (perceptual speed, topic interest ratings) in a controlled within-subject design, the dataset isolates trait effects while controlling for individual baselines.
- **Core assumption**: Observable search behaviors are measurably modulated by stable user traits and transient context (topic interest), and these modulations are captured by the logging granularity.
- **Evidence anchors**: 
  - [abstract] "The dataset combines detailed interaction logs ... with user characteristics, including perceptual speed, topic-specific interest ..."
  - [section 3] "We used a within-subject study design ... topic interest the within-subject variable."
- **Break condition**: If the within-subject variance in interest ratings is insufficient to produce detectable behavioral differences, or if the logging misses key interactions, the causal inference weakens.

### Mechanism 2
- **Claim**: The provided platform and study framework lower the barrier for creating comparable, reusable IIR resources, accelerating cumulative research.
- **Mechanism**: By open-sourcing a fully documented, adaptable search interface ("lisp") with integrated logging, a perceptual speed test implementation, and study scripts, the authors reduce the replication cost and variability of future data collections.
- **Core assumption**: Resource reuse in IIR is primarily hindered by lack of accessible infrastructure, not lack of methodological knowledge.
- **Evidence anchors**: 
  - [abstract] "To facilitate reproducibility and reuse, we provide a fully documented study setup, a web-based perceptual speed test, and a framework ..."
  - [section 2] "Infrastructures ... are rarely reused but instead redeveloped from scratch, as they are difficult to adapt ..."
- **Break condition**: If the platform's adaptability proves insufficient for common IIR tasks (e.g., graded relevance, different document types), or if documentation is inadequate, reuse remains limited.

### Mechanism 3
- **Claim**: The dataset can serve as a validation benchmark for user simulators that incorporate individual differences.
- **Mechanism**: Simulated user behaviors (e.g., click probabilities, query patterns) can be directly compared against the logged human behaviors stratified by user traits (e.g., high-interest vs. no-interest sessions), moving beyond aggregate metrics.
- **Core assumption**: Current user simulators lack systematic validation against real behavior that accounts for user traits, limiting their realism.
- **Evidence anchors**: 
  - [abstract] "The resource enables ... to develop or validate user simulators that account for such variability."
  - [section 1] "User simulation offers a scalable alternative ... but click models mostly rely on simplified assumptions ... lack systematic validation against real behavior."
- **Break condition**: If the simulator evaluation metrics are not aligned with the logged interaction types, or if trait effects are too small to model reliably, validation utility diminishes.

## Foundational Learning

1. **Within-Subject Experimental Design in IIR**  
   **Why needed**: The core analysis compares the same participants under high- vs. no-interest conditions, requiring understanding of how this design controls for individual baseline differences to isolate the effect of topic interest.  
   **Quick check**: Why is a within-subject design more powerful than a between-subject design for studying topic interest effects in this study?

2. **Interaction Logging Granularity**  
   **Why needed**: The dataset's value hinges on capturing not just final outcomes (e.g., documents saved) but the process (query reformulations, snippet views, dwell times). Understanding what events are logged and their temporal resolution is key to reuse.  
   **Quick check**: Which interaction events in Table 2 (section 5.3) are derived from sequence logging versus summary counts?

3. **User Factors in IIR (Perceptual Speed, Task Interest)**  
   **Why needed**: The paper posits these as critical moderators of search behavior. A researcher must grasp what these constructs measure (e.g., perceptual speed as simple visual processing speed) and why they might affect interaction pacing or effort.  
   **Quick check**: Based on the discussion (section 5.4), why might high topic interest lead to fewer documents marked per query despite more queries issued?

## Architecture Onboarding

**Component Map**  
Pre-study questionnaire (frontend) -> Perceptual Speed Test (frontend) -> Topic assignment (backend) -> Search session (frontend+backend+corpus) -> Post-study questionnaire (frontend) -> Data anonymization (backend) -> Dataset packaging

**Critical Path**  
Participant recruitment → Pre-study (interest ratings + PS test) → Automatic topic assignment (high/no interest) → Search session 1 (logged) → Search session 2 (logged) → Post-study questionnaire → Data anonymization → Dataset packaging (logs + profiles).

**Design Tradeoffs**  
- Lab setting vs. ecological validity: Controlled 10-minute tasks on a specific corpus ensure clean logs and trait measurement but limit generalizability to natural search.
- BM25 simplicity vs. modern rankers: Using a classic TF-IDF variant ensures reproducibility and focuses analysis on user behavior, not ranker artifacts, but may not reflect current search engine experiences.
- Fixed order of PS test strings: Ensures comparability but may introduce practice/order effects not counterbalanced.

**Failure Signatures**  
- Missing or incomplete log files for a session, often due to browser crashes or network issues during the 10-minute task.
- Mismatched participant IDs between log files and profile data, breaking trait-behavior linkage.
- PS test scores clustered at ceiling (too easy) or floor (too hard), reducing variance for between-subject analysis.
- Topic assignment failure: If a participant rates few topics, the heuristic may force a weakly vs. strongly interested topic pairing, weakening the interest manipulation.

**First 3 Experiments**  
1. **Replicate Illustrative Analysis**: Run the Wilcoxon/Mann-Whitney tests on the provided dataset to confirm the interest effect on "time per query" and "snippets per query" (Table 2). Validates understanding of the data schema and statistical approach.
2. **Simulator Baseline Comparison**: Implement a simple cognitive user simulator (e.g., one that adjusts query frequency based on a "interest" parameter) and compare its session-level Markov model transition probabilities against the human high-interest vs. no-interest models using Jensen-Shannon divergence.
3. **Platform Adaptation Stress Test**: Modify the "lisp" interface to a different document type (e.g., short news articles) and corpus, then run a pilot with 3-5 participants to check if logging remains complete and the task completion logic holds. Documents the required code changes.

## Open Questions the Paper Calls Out

1. **Question**: Do the effects of topic interest and perceptual speed on search behavior generalize beyond the specific argument retrieval task and student sample used in the study?  
   **Basis in paper**: [inferred] Section 5.5 (Limitations) notes the dataset's limited size and single-domain focus restrict generalizability.  
   **Why unresolved**: The study had a small homogeneous sample (61 students) in only one domain, so external validity is uncertain.  
   **What evidence would resolve it**: Replication studies across diverse domains with larger samples, using the released platform or similar setups.

2. **Question**: How does search task type (e.g., opinion-driven vs. factual) moderate the effect of topic interest on user search behavior?  
   **Basis in paper**: [inferred] Section 5.4 (Discussion) suggests task design explains differences with prior work, stating interest effects "depend strongly on task type."  
   **Why unresolved**: Only one task type (argument gathering) was tested; no comparative evidence exists.  
   **What evidence would resolve it**: Controlled experiments that vary task type while measuring interest effects, potentially adapting the LISP platform.

3. **Question**: How can interactive user simulators for IIR be designed to incorporate contextual factors (e.g., current query, document rank, task state) to better mimic real user behavior?  
   **Basis in paper**: [explicit] Section 5.6 (Conclusion) warns that without context, "important dynamics are lost," and Section 6 (Outlook) calls for simulators accounting for situational factors.  
   **Why unresolved**: Existing simulators often ignore context; it is unclear which features are most predictive and how to integrate them effectively.  
   **What evidence would resolve it**: Developing context-aware simulators and validating them against the LISP interaction logs.

4. **Question**: What factors explain variability in users' relevance judgments for arguments, as measured by inter-rater agreement on marked arguments, and how do cognitive traits and topic interest affect consistency?  
   **Basis in paper**: [explicit] Section 6 (Outlook) states the logs allow "analyses such as inter-rater agreement on marked arguments across participants and topics."  
   **Why unresolved**: The dataset contains markings but no agreement analysis was performed; subjectivity and consistency remain unknown.  
   **What evidence would resolve it**: Computing agreement metrics from LISP data and correlating with user profile and topic characteristics.

5. **Question**: To what extent do retrieval scores (e.g., BM25) and document characteristics influence user interactions, and can these be effectively modeled alongside user traits to predict behavior?  
   **Basis in paper**: [explicit] Section 6 (Outlook) proposes "developing models that incorporate retrieval scores and document characteristics to explain user interactions."  
   **Why unresolved**: The paper did not analyze the impact of retrieval scores; such predictive models are absent.  
   **What evidence would resolve it**: Building and evaluating models that use LISP data including retrieval scores, document length, etc., to predict user actions.

## Limitations
- Generalizability: Findings from a lab-based, 10-minute argument-retrieval task may not generalize to natural, open-ended search.
- Logging granularity: The platform tracks events like queries and clicks but may miss nuanced behaviors (e.g., reading strategies, reasoning depth).
- Reuse potential: The infrastructure’s adaptability to other IIR tasks (e.g., exploratory search, different corpora) remains unproven.

## Confidence
- **Dataset & illustrative analysis**: High
- **Platform reusability**: Medium
- **Simulator validation utility**: Low-Medium
