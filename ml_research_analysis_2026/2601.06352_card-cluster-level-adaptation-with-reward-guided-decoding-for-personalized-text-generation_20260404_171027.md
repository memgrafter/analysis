# CARD: Cluster-level Adaptation with Reward-guided Decoding for Personalized Text Generation

## Quick Facts
- arXiv ID: 2601.06352
- Source URL: https://arxiv.org/abs/2601.06352
- Reference count: 31
- Primary result: CARD achieves state-of-the-art performance (10/12 best) on LaMP and LongLaMP benchmarks with minimal per-user training time and storage, scaling efficiently to many users and remaining effective even with sparse user histories.

## Executive Summary
Personalizing large language models to individual writing styles typically requires expensive per-user fine-tuning, which does not scale. CARD addresses this by combining cluster-level LoRA adaptation with decoding-time steering. Users are clustered by style; each cluster has a LoRA adapter trained on its members' data. For individualization, pairs of user-authored text (positive) and the cluster model's output (negative) are used to learn a user-specific preference vector via pairwise ranking loss. At inference, this vector modulates the logits of the frozen cluster LoRA model through a low-rank projection applied only to the top-k tokens. Results on the LaMP and LongLaMP benchmarks show that CARD attains the best performance in 10 out of 12 settings, dramatically reducing per-user training costs compared to fine-tuning baselines. The approach's efficiency and effectiveness make it suitable for large-scale deployment.

## Method Summary
CARD's training proceeds in three stages. First, user histories are encoded with a frozen encoder (BAAI/bge-m3) and clustered via k-means. Second, for each cluster, a LoRA adapter (rank 16) is trained on all aggregated prompt-response pairs from that cluster using standard cross-entropy loss. Third, using the trained cluster adapters, preference pairs are constructed: for each user instance, the cluster model generates a response to the same prompt; this becomes the negative example, while the user's original response is positive. A shared projection head P and matrix U are learned, along with a per-user vector λ_u, by optimizing the Bradley–Terry pairwise loss on these pairs. The logit correction Δℓ_t = U (z_t ⊙ λ_u) is added only to the top-k tokens, where z_t is derived from the concatenated last four hidden states of the decoder.

At inference for a known user, the corresponding cluster LoRA and the user's λ_u are loaded. For a new prompt, the model runs with the cluster LoRA; at each decoding step, the hidden state is projected, multiplied by λ_u, transformed by U, and the resulting correction is added to the top-k cluster logits before sampling. For a new user, only λ_u needs to be trained quickly on the user's few historical pairs, freezing all other parameters.

## Key Results
- CARD achieves state-of-the-art performance, winning 10 of 12 evaluation settings across LaMP and LongLaMP benchmarks.
- It reduces per-user training time and storage by an order of magnitude compared to fine-tuning-based baselines, scaling efficiently to many users.
- The method remains effective even with sparse user histories (as few as 5 examples), and human evaluations favor CARD outputs for stylistic fidelity.

## Why This Works (Mechanism)
### Mechanism 1: Hierarchical cluster-level and user-level adaptation
- **Claim**: CARD achieves efficient fine-grained personalization by hierarchically combining cluster-level LoRA adaptation with decoding-time user-specific steering while keeping the backbone frozen.
- **Mechanism**: User histories are encoded and clustered (k-means). Each cluster trains a LoRA adapter via supervised fine-tuning. At inference, the cluster LoRA provides baseline logits; a learned user vector λu modulates a projected representation (z_t) to produce a low-rank logit correction Δℓ_t, added only to top-k tokens.
- **Core assumption**: Stylistic preferences are hierarchically structured: group patterns captured by cluster adapters, individual deviations encoded in a low-dimensional steering vector.
- **Evidence anchors**: Abstract and Section 2.2 describe the pipeline; Section 4.2 ablation "w/o Vec" shows removing user vectors causes ~96% performance drop from CARD's improvement, confirming they drive personalization.
- **Break condition**: Poor cluster assignment forces λu to counteract large errors, risking instability or semantic drift. Extremely sparse histories may lead to poorly estimated λu.

### Mechanism 2: Implicit preference learning from contrastive outputs
- **Claim**: CARD constructs high-quality preference pairs without manual annotation by contrasting a user's output (positive) with the cluster LoRA's output on the same prompt (negative), isolating stylistic deviations from topical content.
- **Mechanism**: For each (prompt, user response), generate cluster output using the user's cluster LoRA on the same prompt; treat user response as y^+, cluster output as y^-. Optimize λ_u and shared projection with Bradley–Terry loss.
- **Core assumption**: Stylistic preferences are consistent across prompts; cluster LoRA preserves semantics but uses group style, providing a clean style contrast.
- **Evidence anchors**: Abstract highlights implicit preference learning; Section 2.4 details construction; Section 4.3 shows strong sample efficiency (L=5 histories outperform non-personalized).
- **Break condition**: If cluster LoRA output is too close to user style, contrast weak; if cluster output is incoherent or semantically unfaithful, training signal becomes noisy.

### Mechanism 3: Decoding-time logit modulation with low-rank correction
- **Claim**: Decoding-time logit modulation via a low-rank user preference vector enables precise, efficient, and non-destructive personalization by steering only the top-k token probabilities with a minimal per-user footprint.
- **Mechanism**: Shared head computes z_t = P(h_t) from concatenated last four layers; s_t= z_t ⊙ λ_u; Δℓ_t = U s_t_u; add β·Δℓ_t only to top-k tokens from baseline logits.
- **Core assumption**: Stylistic preferences can be captured in a low-dimensional space (J≈128) and applied multiplicatively; restricting to top-k avoids corrupting low-probability tokens.
- **Evidence anchors**: Section 2.5 defines the equations; Section 4.4 shows optimal J=128 and β=1.0; Section 4.2 case study demonstrates balance between semantics and style.
- **Break condition**: Misaligned λu degrades coherence; inappropriate k (too small excludes needed tokens, too large reduces efficiency and risks overcorrection).

## Foundational Learning
- **Clustering for user grouping**: Why needed here: CARD uses k-means clustering on user embeddings to discover stylistically similar users, enabling shared cluster LoRA adapters that amortize adaptation costs and provide a strong prior for cold-start users. Quick check: What factors influence cluster quality, and how does the paper validate robustness to cluster size? (Answer: Embedding encoder quality and choice of K; Figure 5 shows stable performance across K=20–100.)
- **LoRA (Low-Rank Adaptation)**: Why needed here: LoRA allows efficient learning of cluster-specific style adaptations with minimal additional parameters (rank r=16), making it feasible to maintain multiple cluster adapters without excessive storage or training time. Quick check: Why is LoRA preferable to full fine-tuning for cluster-level adaptation in terms of efficiency and scalability? (Hint: parameter count and memory.)
- **Implicit preference learning from contrastive outputs**: Why needed here: Manual preference labeling is prohibitive; by constructing pairs (user output vs. cluster LoRA output on same prompt), CARD turns personalization into a pairwise ranking problem solvable with Bradley–Terry loss, requiring only existing user-authored text. Quick check: How does using cluster LoRA output as negative avoid confounding by topical content compared to random negatives? (Answer: Same prompt ensures topic/content is held constant, isolating style.)
- **Decoding-time reward-guided steering**: Why needed here: Personalization at inference only (frozen backbone, frozen cluster LoRA) with per-user vectors λu yields minimal storage per user (O(J)) and instant switching, essential for large-scale deployment. Quick check: Why might injecting personalization at decoding rather than during training improve scalability? (Answer: No per-user gradient updates; only need to store/load λu; backbone unchanged.)

## Architecture Onboarding
### Component map
1. User history (raw texts) → frozen encoder (BAAI/bge-m3) → user embedding e_u.
2. Clustering (k-means) on e_u → cluster assignment c(u).
3. For each cluster c: aggregate (prompt, response) pairs from its users → train LoRA adapter Θ^c_LoRA on backbone LLM.
4. Preference pair construction: For each user instance, use cluster's LoRA to generate y^- given same prompt; positive y^+ is user's original response.
5. Learn shared projection P (hidden→J) and matrix U (|V|×J), plus per-user λ_u, via Bradley–Terry loss on pairs (with top-k logit correction).
6. Inference: Load cluster LoRA and λ_u. At each decode step, compute z_t from last four hidden states, apply correction Δℓ_t = U (z_t ⊙ λ_u) to top-k logits of cluster model, sample token.
7. New user: Encode history → cluster assignment → train λ_u on user's pairs (only λ_u updated) using frozen cluster LoRA and shared P,U.

### Critical path
**Training phase**:
- Encode all training users’ histories → embeddings.
- Run k-means clustering → assign each user to cluster c(u).
- For each cluster, train a LoRA adapter Θ^c_LoRA on its users’ data with cross-entropy loss.
- For each user instance, generate negative response using the user’s cluster LoRA on the same prompt; construct preference pairs.
- Freeze backbone and all cluster LoRAs; initialize shared P, U, and all λ_u; train with Bradley–Terry pairwise loss.

**Inference for known user**:
- Load the assigned cluster LoRA and the user’s λ_u.
- For a new query, build the task prompt.
- Run the model with the cluster LoRA; at each step, compute correction from z_t, λ_u, and add it to the top-k cluster logits.
- Sample next token and repeat until EOS.

**New user adaptation**:
- Compute user embedding from available history, assign to nearest cluster.
- Load the cluster’s LoRA and the shared P,U.
- Initialize λ_u randomly (or zero) and train for a few gradient steps (e.g., 3 epochs) on the user’s preference pairs, keeping all other parameters frozen.
- Deploy with the trained λ_u.

### Design tradeoffs
- **Cluster granularity (K)**: More clusters reduce intra-cluster variance but increase storage; shown robust across K=20–100.
- **User vector dimensionality (J)**: Balances expressivity vs. overfitting; J=128 optimal.
- **Steering strength (β)**: Controls personalization override; β=1.0 best, higher leads to semantic drift.
- **Representation depth (S)**: Concatenating last four layers works best; more layers dilute signal.
- **Top-k**: Larger k improves coverage but increases O(k·J) compute; default k=10 provides good tradeoff.
- **Frozen backbone vs. full fine-tuning**: Avoids catastrophic forgetting and per-user storage blowup, but limits adaptation for users far from cluster prior.
- **Implicit pair quality**: Relies on cluster LoRA quality; if negatives are weak, the ranking signal may be noisy.

### Failure signatures
- **Cluster misassignment**: User style far from centroid → inaccurate baseline → overcorrection by λ_u → instability.
- **Sparse/noisy user history**: λ_u poorly estimated → performance sensitive to <5 examples.
- **Over-amplification**: β too high or λ_u magnitude too large → garbled outputs, loss of core content.
- **Under-correction**: β too low or λ_u too small → outputs remain overly generic.
- **Top-k too small**: Relevant style tokens excluded → ineffective personalization.
- **Projection size mismatch**: Incorrect handling of hidden state shape (e.g., forgetting to concatenate 4 layers of size 4096) causes runtime errors.
- **Poorly trained cluster LoRA**: High cluster cross-entropy indicates unreliable baseline → consider early stopping or more data per cluster.

### First 3 experiments
1. **Ablation study**: Remove LoRA (only user vector) and remove user vector (only cluster LoRA) to quantify contributions. Result: user vectors account for ~96% of CARD's improvement over non-personalized, confirming they are the primary driver.
2. **Low-resource evaluation**: Vary number of user histories (L=1–20) to assess sample efficiency and cold-start robustness. CARD outperforms baselines even with very few examples, demonstrating strong few-shot capability.
3. **Hyperparameter sensitivity**: Sweep user vector dimension J (32,64,128,256), steering strength β (log scale), representation depth S (1,4,8), and cluster count K (20–100). Identify optimal settings: J=128, β=1.0, S=4, and performance stable across K=20–100.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: Can alternative clustering algorithms beyond k-means improve the capture of complex user stylistic relationships and enhance personalization performance?
- **Basis in paper**: [explicit] The limitations section states that "our offline group modeling relies on unsupervised K-means clustering, which, despite its simplicity and scalability, may not fully capture complex user relationships or latent personalization structures."
- **Why unresolved**: The paper adopts k-means primarily for computational efficiency but does not investigate whether more sophisticated clustering (e.g., spectral, deep clustering) could yield better group separations and downstream personalization. The trade-off between clustering quality and scalability remains unexplored.
- **What evidence would resolve it**: Systematic benchmarking of various clustering approaches on LaMP/LongLaMP tasks, measuring both cluster internal coherence (e.g., silhouette score) and external personalization metrics (ROUGE, human evaluation). Ablation studies could isolate the impact of cluster quality on final performance.

### Open Question 2
- **Question**: Does representing users with multiple or dynamic preference vectors improve modeling of diverse behaviors and temporal preference evolution compared to a single static vector?
- **Basis in paper**: [explicit] The limitations note that "we represent each user with a single preference vector during decoding, which may limit expressiveness when modeling diverse behaviors or evolving user preferences over time."
- **Why unresolved**: CARD uses one fixed λu per user, assuming stable preferences. However, users may exhibit context-dependent styles (e.g., formal vs. informal) or drift over time. The framework lacks mechanisms to adapt vectors based on input context or historical trends.
- **What evidence would resolve it**: Extensions using context-aware vectors (e.g., conditioned on input topics) or time-sensitive updates (e.g., exponential moving averages of past vectors). Evaluation on datasets with timestamped user histories would show whether dynamic representations reduce performance decay over time.

### Open Question 3
- **Question**: How can we design interpretable user preference vectors where individual dimensions correlate with specific stylistic or linguistic attributes (e.g., formality, emotion, syntax)?
- **Basis in paper**: [explicit] The authors state that "the dimensions of the learned user preference vectors are not explicitly interpretable, making it difficult to associate individual dimensions with specific stylistic or linguistic attributes."
- **Why unresolved**: The vector is learned end-to-end via pairwise loss without interpretability constraints. This obscures what each dimension represents, hindering debugging, user trust, and potential manual tuning.
- **What evidence would resolve it**: Applying post-hoc analysis tools like probing classifiers, concept activation vectors (CAVs), or sparsity-inducing regularization to align vector dimensions with annotated style features. Human evaluations could assess if interpretable vectors allow targeted style adjustments.

### Open Question 4
- **Question**: Can temporal preference drift be effectively modeled within CARD's decoding-time framework to maintain personalization quality for long-term users?
- **Basis in paper**: [explicit] The limitations acknowledge that "we do not explicitly model temporal dynamics or preference drift in this work" and that "the effectiveness of personalization is inherently constrained by the quality and availability of user data."
- **Why unresolved**: The user vector λu is trained once from historical data and remains static, ignoring that user writing styles may change. This could lead to performance degradation for users with long histories or evolving preferences.
- **What evidence would resolve it**: Incorporating temporal signals into vector learning (e.g., time-weighted losses, recurrent updates) and evaluating on longitudinal splits of LaMP/LongLaMP. Metrics could track personalization quality over simulated user lifespans or against time-sliced test sets.

## Limitations
- **Clustering quality**: The use of k-means clustering is not thoroughly validated; sensitivity to embedding model, distance metric, and number of clusters remains unexplored, and misassignment may degrade personalization.
- **Implicit preference pairs**: The assumption that cluster LoRA outputs serve as effective negatives is not directly verified; if those outputs are semantically unfaithful or too similar to the user’s style, the ranking signal may be noisy.
- **New user adaptation**: The procedure for rapidly estimating λ_u for unseen users (e.g., number of gradient steps, initialization) is underspecified and may struggle with very few historical examples (<5).

## Confidence
- **Hierarchical adaptation (cluster LoRA + user steering)**: High confidence — supported by strong ablation showing user vectors account for ~96% of improvement.
- **Implicit preference learning**: Medium confidence — assumes clean style contrast from cluster negatives, but no direct validation of negative quality.
- **Decoding-time low-rank steering**: High confidence — identified as primary driver in ablations; sensitivity analyses confirm design.
- **Benchmark performance (10/12 best)**: High confidence — consistent results across LaMP and LongLaMP tasks.
- **Cold-start robustness (few-shot)**: Medium confidence — effective with L≥5 but performance varies at extreme sparsity and noisy data.

## Next Checks
1. **Clustering robustness test**: Vary clustering algorithms (k-means, spectral, hierarchical) and embedding models; correlate silhouette scores with personalization gains to quantify sensitivity.
2. **Top-k training consistency**: Train λ_u with full-vocab vs. top-k masked logit correction; compare inference performance. If gap exists, retrain with top-k to confirm intended behavior.
3. **New user protocol benchmark**: Systematically vary gradient steps (1–10), learning rates, and initialization (zero/random) on users with 1–5 histories; identify stable settings and performance plateaus.
