# CA-HFP: Curvature-Aware Heterogeneous Federated Pruning with Model Reconstruction

## Quick Facts
- **arXiv ID:** 2603.12591
- **Source URL:** https://arxiv.org/abs/2603.12591
- **Reference Count:** 14
- **Primary Result:** Personalized structured pruning guided by curvature-aware metrics enables heterogeneous clients to train efficiently while maintaining aggregation compatibility, achieving ~75% reduction in communication/computation with minimal accuracy loss under non-IID data.

## Executive Summary
Federated learning on resource-constrained edge devices faces dual challenges: limited computational/communication budgets and statistical heterogeneity (non-IID data). Standard federated averaging (FedAvg) struggles with these constraints as it requires uniform model architectures and full parameter exchange. CA-HFP introduces a framework for **personalized structured pruning** where each client prunes its model according to a curvature-aware importance metric, drastically reducing local computation and upload size. A key innovation is a **server-side reconstruction mechanism** that maps each client's heterogeneous submodel back into a common global parameter space, allowing FedAvg-like aggregation without sacrificing personalization. This decouples local efficiency from global coordination, yielding superior accuracy and resource savings compared to existing heterogeneous federated learning and pruning baselines on standard benchmarks.

## Method Summary
CA-HFP operates in two phases per communication round. **Locally**, each client computes a curvature-aware loss perturbation metric (e.g., based on Hessian approximations or loss sensitivity) to score filter/channel importance in its current model. It then performs structured pruning (e.g., removing entire convolutional filters) according to a target sparsity ratio, producing a device-specific submodel. **At the server**, received heterogeneous submodels are passed through a learned reconstruction function (e.g., a small neural network or linear mapping) that projects each submodel's parameters into the global model's parameter space. These reconstructed parameters are then aggregated via weighted averaging (like FedAvg) to update the global model, which is redistributed to clients for the next round. The reconstruction ensures that despite different pruned architectures, all updates contribute to a coherent global model, while clients retain their personalized masks.

## Key Results
- **Accuracy preservation:** On CIFAR-10 with Dirichlet α=1.0, CA-HFP achieves 90.15% accuracy vs. 80.01% for FedMP and comparable to unpruned FedAvg.
- **Communication reduction:** Per-client uploads drop to ~3.95M parameters (VGG on CIFAR-10) from 15.1M (FedMP) and 25.6M (FedAvg), a ~75% reduction.
- **Computation reduction:** Local FLOPs reduced to 10.2G from 40.3G (FedMP) and 25.6G (FedAvg), enabling feasible execution on edge hardware.

## Why This Works (Mechanism)
The curvature-aware perturbation metric identifies parameters whose removal minimally impacts loss landscape flatness, preserving model capacity in critical directions while aggressively pruning redundant filters. Device-specific pruning accommodates heterogeneous data distributions: clients with minority classes can retain class-specific filters. Server-side reconstruction is the linchpin—it learns to invert the pruning mask's effect, mapping sparse submodel updates back to the dense global space. This prevents the aggregation incompatibility that typically plagues heterogeneous federated learning (e.g., FedMP's separate heads), allowing a single global model to coherently absorb diverse updates. The combination yields personalized efficiency without fracturing the global knowledge pool.

## Foundational Learning
**Federated Learning (FL):** Distributed training where clients keep data local; only model updates are shared. *Why needed:* Enables privacy-preserving, collaborative learning across organizations/devices. *Quick check: Can a system train a model without centralizing raw data?*

**Structured Pruning:** Removing entire structural components (e.g., convolutional filters, attention heads) to reduce model size and computation. *Why needed:* Achieves real inference speedups on hardware, unlike unstructured pruning. *Quick check: Does pruning reduce FLOPs and memory footprint measurably?*

**Curvature-aware Metric:** Importance scores derived from loss Hessian or perturbation analysis (e.g., Fisher information). *Why needed:* Identifies parameters in flat minima regions, leading to more robust pruning. *Quick check: Are pruned models less sensitive to weight perturbations?*

**Non-IID Data:** Statistical heterogeneity across clients where data distributions differ significantly. *Why needed:* Reflects real-world edge scenarios (e.g., different user preferences). *Quick check: Does performance degrade as Dirichlet α decreases?*

**Personalized FL:** Training device-specific models while leveraging global knowledge. *Why needed:* Addresses heterogeneity that hurts one-model-fits-all approaches. *Quick check: Do clients achieve better local accuracy than a shared global model?*

**Model Aggregation in Heterogeneous FL:** Combining updates from different architectures/masks. *Why needed:* Standard FedAvg requires identical models; heterogeneity breaks it. *Quick check: Can server combine parameter tensors of different shapes?*

## Architecture Onboarding
**Component Map:**
Client Curvature Computation -> Device-Specific Structured Pruning -> Submodel Transmission -> Server Reconstruction Network -> Global Aggregation (FedAvg) -> Global Model Distribution -> Next Round Training

**Critical Path:** The reconstruction step is the essential liaison—without it, heterogeneous submodels cannot be aggregated. Its efficacy determines whether personalization gradients align in the global space.

**Design Tradeoffs:**
- *Personalization vs. Global Coherence:* Deeper personalization (more aggressive/client-specific pruning) risks distorting the global update landscape; reconstruction must balance invertibility with regularization.
- *Reconstruction Overhead vs. Communication Savings:* The server-side mapping adds compute/memory cost, but this is amortized across clients and typically negligible compared to saved uplink bandwidth.
- *Curvature Estimation Cost vs. Pruning Quality:* Approximate curvature (e.g., via K-FAC or diagonal Hessian) reduces client compute but may degrade mask optimality.

**Failure Signatures:**
- Accuracy divergence between global model and client local models under high non-IID (α << 0.5).
- Reconstruction loss remains high after training, indicating poor mapping generalization.
- Pruning ratios vary wildly across clients, suggesting curvature metric instability.
- Server memory spikes during reconstruction if submodel diversity is too high.

**First Three Experiments to Run:**
1. **Extreme Heterogeneity Stress Test:** Set Dirichlet α ≤ 0.1 or assign each client only 1-2 classes. Monitor CA-HFP's global accuracy decay and reconstruction error vs. FedMP and FedPer.
2. **Reconstruction Overhead Isolation:** Time the server reconstruction step per round for varying numbers of clients (e.g., 10, 100, 1000) and compare total round latency to FedMP's direct aggregation. Isolate reconstruction network size vs. accuracy trade-off.
3. **Hardware Deployment Pilot:** Implement CA-HFP on a Raspberry Pi 4 (ARM Cortex-A72) using TensorFlow Lite. Measure per-round energy consumption, thermal throttling events, and actual network traffic (bytes) against simulated claims.

## Limitations
- Algorithmic details (exact curvature perturbation formula, reconstruction loss) are omitted, hindering exact replication.
- Evaluation confined to vision tasks (FMNIST, CIFAR) with ResNet/VGG; generalizability to NLP or transformers is unknown.
- No real-device experiments; simulated resource gains may not account for memory fragmentation, OS scheduling, or hardware-specific acceleration quirks.
- Theoretical relationship between personalization depth (pruning ratio spread) and global convergence stability is not bounded.

## Confidence
- **Accuracy Preservation vs. Baselines:** Medium — Supported by reported numbers, but hyperparameter/config details missing limit independent verification.
- **Communication/Computation Reduction:** High — Parameter and FLOP counts are quantitative and directly reproducible; discrepancies would be clear.
- **Convergence Robustness under Heterogeneity:** Medium — Convergence curves shown for limited α values; extreme non-IID (α→0) not thoroughly validated.
- **Reconstruction Efficacy for Aggregation:** Low — Novel technique with no external validation; risk of hidden bias or distortion in mapping process is unquantified.
