# Why Linear Interpretability Works: Invariant Subspaces as a Result of Architectural Constraints

## Quick Facts
- **arXiv ID:** 2602.09783
- **Source URL:** https://arxiv.org/abs/2602.09783
- **Reference count:** 26
- **Primary result:** Linear interpretability methods succeed because transformer linear interfaces (unembedding, attention OV) enforce context‑invariant subspaces for semantic features, backed by multi‑model, multi‑task empirical validation (up to ~95% accuracy).

## Executive Summary
This paper tackles a key puzzle in mechanistic interpretability: why do simple linear probes and sparse autoencoders effectively extract semantic features from highly nonlinear transformer models? The authors introduce the **Invariant Subspace Necessity theorem**, arguing that because transformers transmit information through linear interfaces (e.g., the unembedding matrix and attention OV circuits), any feature that is consistently decoded by such interfaces must reside in a linear subspace that is invariant across contexts. A closely related **Self‑Reference Property** posits that a token’s own embedding direction serves as the basis for its semantic feature. The theory is tested across eight classification datasets and four model families (LLaMA3‑8B, Mistral‑7B, GPT2‑Small, LLaMA3.2‑3B). Zero‑shot probes (using token directions alone), unsupervised linear probes, and sparse autoencoders all recover consistent directional structure, with classification accuracies reaching up to ~95%. Moreover, sparse autoencoder features activated by class tokens overlap significantly with those from contextual instances, confirming the existence of shared invariant subspaces. The results provide a principled architectural explanation for the empirical success of linear interpretability techniques.

## Method Summary
The study evaluates three linear probing methods on per‑attention‑head residual stream activations from multiple transformer models. (1) **Zero‑Shot Probe**: class token directions (normalized mean of class token embeddings) are used directly as classifiers; no training is involved. (2) **Unsupervised Probe**: a linear transformation is learned on class token activations via a contrastive loss (Eq. 8) using only class‑token pairs, then applied to instance activations. (3) **Sparse Autoencoder (SAE) Probe**: an SAE is trained on instance activations only; classification uses the SAE’s feature directions. For all probes, an instance is classified by projecting its representation onto normalized class directions and selecting the class with the largest projection magnitude. Data comprises eight classification tasks (Animals, Countries, Emotional Sentences, Literary Quotes, Cartoon Phrases, Languages, Fruits, Companies) with implicit prompts per class. Metrics include classification accuracy, cosine similarity between class token and instance vectors, and overlap in top‑k SAE features between class tokens and instances.

## Key Results
- Zero‑shot probes achieve up to ~95% accuracy (LLaMA3‑8B on Animals) without any training.
- Unsupervised probes and sparse autoencoders recover consistent directional structure across models and tasks.
- SAE features activated by class tokens significantly overlap with those from related contextual instances, confirming shared invariant subspaces.

## Why This Works (Mechanism)
The paper’s core theoretical claim is the **Invariant Subspace Necessity theorem**: any semantic feature that is reliably decoded by a linear interface (e.g., the unembedding matrix or an attention OV circuit) must occupy a linear subspace of the residual stream that is invariant to context. This is because these interfaces are linear operators; for a feature to be consistently extracted across different inputs, its representation must lie in a fixed subspace independent of surrounding tokens. The **Self‑Reference Property** is a key derivation: the embedding of a class token itself (e.g., “France”) provides a directional vector that approximates the feature’s invariant subspace. Consequently, linear probes—whether zero‑shot (using token directions), contrastive (learning a linear mapping from class tokens), or SAE‑based—can successfully decode semantic information because they implicitly or explicitly discover these context‑invariant directions. The empirical success across diverse models and tasks demonstrates that such invariant subspaces are a widespread consequence of transformer architecture.

## Foundational Learning
**Invariant Subspace**  
*Why needed:* The theorem states that features decoded by linear interfaces must lie in a subspace that does not vary with context.  
*Quick check:* Compute the cosine similarity between a class token’s representation and instance representations of the same class; high similarity indicates invariance.

**Linear Interface**  
*Why needed:* These components (unembedding matrix, attention OV circuit) are the sole channels through which information exits the residual stream; their linearity constraints force features into invariant subspaces.  
*Quick check:* Verify that the relevant operations are indeed linear (matrix multiplications) in the model’s forward pass.

**Self‑Reference Property**  
*Why needed:* It explains why a token’s own embedding can serve as a probe direction for its semantic feature, enabling zero‑shot classification.  
*Quick check:* Project instance activations onto the class token direction; high projection magnitudes for correct classes confirm the property.

**Context Invariance**  
*Why needed:* A feature must be represented consistently across different prompts to be linearly decodable.  
*Quick check:* Compare representations of the same class in varied contexts (e.g., “France” in “I love France” vs. “France is beautiful”); measure similarity.

**Attention OV Circuit**  
*Why needed:* The product of value and output matrices (OV) linearly transforms the residual stream and is a primary interface for attention‑based communication.  
*Quick check:* Extract O and V matrices from a head and confirm their product implements a linear map.

**Sparse Autoencoder (SAE)**  
*Why needed:* SAEs are used to discover interpretable features that may occupy invariant subspaces, providing an unsupervised validation.  
*Quick check:* Train an SAE on activations; inspect top‑activating examples for each feature to interpretability.

## Architecture Onboarding
**Component map (plain text):**  
Token Embeddings -> Residual Stream (layer 1) -> ... -> Residual Stream (layer N) -> Unembedding Matrix -> Output Logits  
Within each layer: Residual Stream -> Attention Heads (Q, K, V, O) -> Head Outputs (summed into residual) -> MLP -> Residual Stream  
Critical linear interfaces: Attention OV circuit (V * O) and Unembedding Matrix.

**Critical path:** Information flows from input tokens through the residual stream. At each layer, attention heads compute OV transformations that linearly mix the residual stream. The final residual state is projected by the unembedding matrix to produce logits. Semantic features that are consistently decoded by these linear operators must therefore be encoded in invariant subspaces of the residual stream.

**Design tradeoffs:** Using linear projections for communication (unembedding, OV) simplifies decoding and supports interpretability but may restrict the model’s ability to encode highly nonlinear relationships within a single subspace. Residual connections mitigate vanishing gradients but also blend features across layers, making isolation of invariant subspaces layer‑dependent.

**Failure signatures:**  
- A linear probe yields near‑random accuracy, suggesting the feature is not conveyed via linear interfaces or lacks context invariance.  
- SAE features from class tokens show little overlap with those from contextual instances, violating the self‑reference property.  
- Multi‑token class labels produce inconsistent results depending on which subword is used, indicating tokenization contamination.

**Three first experiments:**  
1. Zero‑shot probe: Use normalized class token embeddings as directions and classify instances by projection magnitude.  
2. Unsupervised probe: Train a linear classifier on class token activations with contrastive loss, then evaluate on instances.  
3. SAE probe: Train a sparse autoencoder on instance activations; compare top‑k activated features between class tokens and instances.

## Limitations
- Prompt templates and full instance lists for the eight datasets are not provided, blocking exact replication of the input pipeline.
- Tokenization details (e.g., handling multi‑token classes) and precise layer/head selection criteria are unspecified, introducing ambiguity in activation extraction.
- The Invariant Subspace Necessity theorem assumes linear interfaces are the sole communication channels, potentially overlooking nonlinear pathways in later MLPs or QK circuits.

## Confidence
- **Invariant Subspace Necessity Theorem:** Medium (theoretical derivation is clear but relies on simplifying assumptions about communication pathways)
- **Empirical Success of Linear Probes:** High (robust multi‑dataset, multi‑model evidence with high accuracies)
- **Self‑Reference Property:** Medium‑Low (compelling directional overlap results, but depends critically on correct extraction of “pure” token directions)

## Next Checks
1. **Exhaustive head/layer sweep:** Replicate the zero‑shot probe across all layers and heads for one dataset (e.g., Animals) and produce a full accuracy heatmap to verify reported high‑performing heads are not a selection artifact.
2. **Multi‑token class token stress test:** For multi‑token classes (e.g., “United States”), compare three extraction strategies—first token, last token, mean of tokens—and measure accuracy drops to test robustness of the self‑reference property.
3. **SAE overlap baseline:** Compute top‑k SAE feature overlap between class token and instances after randomly permuting the instance’s feature activations; if overlap remains significant, it would indicate a spurious correlation in the metric.
