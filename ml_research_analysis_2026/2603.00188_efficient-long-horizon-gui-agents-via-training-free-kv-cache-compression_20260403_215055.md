# Efficient Long-Horizon GUI Agents via Training-Free KV Cache Compression

## Quick Facts
- arXiv ID: 2603.00188
- Source URL: https://arxiv.org/abs/2603.00188
- Reference count: 40
- Primary result: ST-Lite reduces KV cache to 10–20% budget, achieving 2.45× decoding acceleration while matching or exceeding full‑cache performance, with a 7.3% average success‑rate improvement over prior SOTA.

## Executive Summary
Long‑horizon GUI agent tasks suffer from KV cache explosion as interaction histories grow. Existing compression methods misalign with GUI‑specific attention patterns, which exhibit uniformly high sparsity across all transformer layers. This paper presents ST‑Lite, a training‑free framework that combines Component‑centric Spatial Saliency (CSS) to preserve UI element structures via local neighborhood analysis, and Trajectory‑aware Semantic Gating (TSG) to filter redundant historical states using dynamic semantic similarity. Evaluated on AITW and AgentNetBench, ST‑Lite with only 10–20% of the cache achieves up to 2.45× speedup and even outperforms full‑cache baselines by mitigating context poisoning.

## Method Summary
ST‑Lite operates during decoding after the prefill phase. It allocates the cache budget uniformly across all layers, justified by observed uniform sparsity. For each token in the existing KV cache, it computes a base importance score (A_base) from the accumulated attention of the final observation window. Visual tokens receive an additional spatial saliency boost (Φ_space) derived from the local uniformity of their hidden states within a 3×3 Moore neighborhood; low uniformity indicates a semantic boundary. Historical visual tokens are gated by TSG: each token’s redundancy ρᵢ is its maximum cosine similarity to any token in the current frame. Tokens are sorted by ρ, and a dynamic threshold τ_red is set at the B‑th rank (B = budget). Only tokens with ρᵢ ≤ τ_red are retained (M_time = 1). The final score is M_time·(A_base + Φ_space) for visual tokens and A_base for text tokens. The top B tokens by score are kept for the next decoding step.

## Key Results
- 2.45× decoding acceleration with 10–20% cache budget.
- Outperforms state‑of‑the‑art compression methods by an average of 7.3% in success rate on GUI benchmarks.
- Surpasses full‑cache performance on long‑horizon tasks (e.g., AITW) by effectively suppressing context poisoning.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** GUI‑VLM attention patterns exhibit uniform high sparsity across all transformer layers, making layer‑wise hierarchical budget allocation (e.g., PyramidKV, VL‑Cache) misaligned and prone to chaotic budget distribution.  
**Mechanism:** The discrete, structured nature of GUI screenshots (sparse functional elements on uniform backgrounds) yields similarly sparse attention distributions irrespective of network depth. Hierarchical methods assume a pyramidal funneling where shallower layers attend broadly and deeper layers focus narrowly. When the actual sparsity gradient |∇ₗ S(𝑙)| ≈ 0, the normalization step amplifies numerical noise, causing erratic and semantically destructive budget splits.  
**Core assumption:** The spatial distinctiveness of UI components is a layer‑agnostic property; critical structural tokens require preservation across all layers.  
**Evidence anchors:**  
- Abstract notes that GUI attention patterns are uniformly sparse and that VL‑Cache leads to severe semantic loss.  
- Section 3.3 states that unlike general visual tasks, GUI agents exhibit uniform sparsity, justifying uniform budget allocation (with Figure 3).  
**Break condition:** If a specific GUI‑VLM or dataset shows significant variance in attention sparsity across layers (|∇ₗ S(𝑙)| > ε), uniform allocation fails; a hybrid or data‑driven strategy becomes necessary.

### Mechanism 2
**Claim:** Component‑centric Spatial Saliency (CSS) preserves the structural integrity of interactive UI elements by identifying tokens with high local distinctiveness within a Moore Neighborhood (3×3 grid), separating functional boundaries from uniform backgrounds.  
**Mechanism:** For each visual token’s hidden state hᵤ,ᵥ, CSS computes a Local Uniformity Score Hᵤ,ᵥ as the average cosine similarity with its 8 immediate neighbors. A low Hᵤ,ᵥ indicates a semantic edge (high saliency). The final Spatial Saliency Score Φ_space = 1 - Hᵤ,ᵥ is added to the base attention score, biasing retention toward pixels on component boundaries.  
**Core assumption:** The local spatial manifold (3×3 grid) is a sufficient and hyperparameter‑free proxy for identifying high‑frequency structural content of rasterized GUI elements.  
**Evidence anchors:**  
- Section 4.1 describes the Moore Neighborhood design as zero‑hyperparameter and efficient.  
- Section 5.3 (Table 1) shows "ST‑Lite (CSS only)" yields the most significant improvements on single‑frame high‑resolution ScreenSpot Pro, demonstrating CSS’s role in spatial grounding.  
- Section 5.5 (Figure 7(a)) visualizes CSS heatmaps tightly contouring interactive elements, while baselines show fragmented attention.  
**Break condition:** If GUI elements are defined by large, uniform‑filled regions (e.g., a big blue button with no internal boundaries), the local contrast metric may fail to identify them as salient.

### Mechanism 3
**Claim:** Trajectory‑aware Semantic Gating (TSG) mitigates historical redundancy and "context poisoning" in long‑horizon tasks by dynamically filtering visually repetitive KV pairs using a dynamic semantic similarity threshold.  
**Mechanism:** For each historical token ℎᵢ, TSG computes redundancy ρᵢ = max cosine similarity between ℎᵢ and any token in the current frame’s hidden states (H_curr). All historical ρᵢ scores are sorted ascendingly. The dynamic threshold τ_red is set to the ρ value at rank B (budget). Tokens with ρᵢ > τ_red are evicted (M_time = 0). This ensures only the B most unique historical tokens are retained.  
**Core assumption:** Visual repetition in GUI workflows (e.g., static backgrounds, repeated menus) corresponds directly to semantic redundancy for future action prediction. A token’s maximum similarity to the current view is a valid proxy for its future utility.  
**Evidence anchors:**  
- Section 4.2 describes filtering out visually repetitive KV pairs to distill the trajectory into critical state transitions.  
- Section 5.2 notes that context simplification can lead to better‑than‑full‑cache performance; TSG mitigates context poisoning.  
- Section 5.3 (Table 1) shows "ST‑Lite (TSG only)" dramatically improves long‑horizon AITW and AgentNetBench, isolating TSG’s effect.  
**Break condition:** If a task requires memory of visually identical but temporally distinct states (e.g., returning to a previous menu with changed context), TSG’s similarity threshold would erroneously evict necessary tokens.

## Foundational Learning
- **Concept: KV Cache Mechanics in Autoregressive Decoding**  
  *Why needed:* The paper targets the linear growth of the KV cache (K, V ∈ ℝ^{L×D}) during decoding. Understanding that cached keys/values avoid recomputation frames compression as selective eviction.  
  *Quick check:* "If you compress the KV cache by 80%, what is the direct computational benefit during the decoding step of generating the 100th action in a 50‑step GUI task?"

- **Concept: GUI‑Specific Visual Redundancy**  
  *Why needed:* GUI data has unique redundancy patterns (high‑density but loose‑relation noise, discrete components on uniform backgrounds) compared to natural images. This underpins why LLM/VLM compression methods fail.  
  *Quick check:* "Why would a window‑based greedy eviction method (SnapKV) perform worse on a GUI task with many identical menu screens than on a natural video captioning task?"

- **Concept: Transformer Layer Functional Specialization (or Lack Thereof)**  
  *Why needed:* The "uniform high‑sparsity" finding contradicts the common belief in hierarchical information processing (shallower layers = broad, deeper layers = fine). This diagnostic invalidates PyramidKV/VL‑Cache for GUI.  
  *Quick check:* "If you plotted layer‑wise attention entropy for a GUI agent vs. an image captioning model, what distinct pattern would you expect to see for the GUI agent?"

## Architecture Onboarding
**Component map:**  
Base Attention Prior → Component‑centric Spatial Saliency (Φ_space) + Trajectory‑aware Semantic Gating (M_time) → Integrated Scoring & Eviction

**Critical path:**  
1. Prefill phase processes initial instruction & first screenshots, populating full KV cache.  
2. At each decoding step, current query states (Q_curr) are available.  
3. For every token i in existing KV cache:  
   - Compute A_base(i) using observation window (last δ tokens).  
   - If visual token:  
     * Compute Φ_space(i) via 3×3 neighborhood cosine similarity on its original frame’s grid.  
     * Compute redundancy ρᵢ as max cosine similarity between its key vector and all keys in Q_curr.  
     * Add ρᵢ to a pool.  
4. Sort the historical ρ pool ascendingly; set τ_red = ρ value at rank B (budget).  
5. For each visual i, set M_time(i) = 1 if ρᵢ ≤ τ_red else 0.  
6. Compute final score S_i: for visual tokens S_i = M_time·(A_base + Φ_space); for text tokens S_i = A_base.  
7. Select top B indices I_keep. Prune K[I_keep], V[I_keep] for next step.

**Design tradeoffs:**  
- Training‑free vs. optimality: avoids retraining but heuristics (local neighborhood, max similarity) may not perfectly align with true utility.  
- Uniform budget vs. adaptive: simplifies implementation but discards potential gains if minor layer variation exists.  
- Computational overhead: CSS/TSG add O(L) per step; prefill overhead negligible (<2%) but must be profiled.  
- Hyperparameter: only δ (observation window size) needs tuning; not specified, presumably robust.

**Failure signatures:**  
1. **CSS failure:** Attention heatmaps fragmented or shifting off UI elements on ScreenSpot. Diagnostic: visualize retained tokens; if component skeletons broken, H distribution problematic.  
2. **TSG failure:** Long‑horizon performance decays rapidly with history length, matching SnapKV’s decay. Diagnostic: plot success vs. number of history frames; check ρᵢ distribution and τ_red value.  
3. **Integration failure:** Full ST‑Lite underperforms CSS‑only or TSG‑only ablations on a benchmark. Diagnostic: isolate which gate (spatial or temporal) causes destructive interference.

**First 3 experiments:**  
1. **Reproduce Diagnostic Analysis:** On chosen GUI‑VLM (e.g., UI‑TARS), compute layer‑wise attention sparsity on AITW sample. Confirm |∇ₗ S(𝑙)| small (<0.05?) to validate uniform sparsity premise.  
2. **Isolate CSS Efficacy:** Run ST‑Lite with TSG disabled at 20% budget on ScreenSpot Pro. Compare accuracy to SnapKV and full cache; significant lift confirms CSS spatial preservation.  
3. **Isolate TSG Efficacy & Less‑is‑More:** Run ST‑Lite with CSS disabled at 20% budget on AITW. Compare success to full cache and SnapKV. Surpassing full cache indicates TSG’s noise suppression. Also plot performance vs. history frames to verify scalability.

## Open Questions the Paper Calls Out
1. **End‑to‑end learnable KV cache compression** – Why: ST‑Lite uses handcrafted heuristics; a learnable policy could better align with model dynamics. What evidence: a differentiable compression module trained on GUI tasks with task success as reward, evaluated across benchmarks.  
2. **Joint optimization with agent training** – Why: Compression applied post‑training; co‑optimization could induce compressible trajectories. What evidence: integrate compression into RL training loop; compare sample efficiency and robustness against separately trained agents.  
3. **Universality of uniform high‑sparsity** – Why: ST‑Lite’s uniform budget relies on this observation; if future GUI VLMs exhibit hierarchical sparsity, the method may falter. What evidence: measure layer‑wise attention sparsity across diverse GUI VLMs (different architectures, sizes, training data) and domains.  
4. **Mechanism of “Less‑is‑More”** – Why: The hypothesis that compression removes harmful context lacks a detailed analysis. What evidence: controlled experiments measuring semantic similarity decay, synthetic noise injection, and attention distribution changes with/without compression.  
5. **RLHF vs. SFT robustness** – Why: RLHF‑aligned agents (UI‑TARS) tolerate aggressive compression better than SFT‑only (OpenCUA). Understanding this could help engineer robust agents. What evidence: compare internal representations (attention entropy, activation sparsity) of RLHF vs. SFT models; or gradually vary RL fine‑tuning and test compression robustness.

## Limitations
- Key hyperparameters (δ, visual/text token mapping, temporal partitioning) are unspecified, hindering faithful reproduction.  
- The uniform high‑sparsity assumption may not hold for all GUI‑VLM architectures or datasets, potentially degrading performance.  
- TSG might over‑evict when visually identical states reappear with different semantic intents (e.g., same menu at different task stages).

## Confidence
- Uniform high‑sparsity across layers: **Medium** (supported by limited model validation but not broadly confirmed).  
- CSS effectiveness: **High** (strong gains on ScreenSpot Pro and clear visualizations).  
- TSG “less‑is‑more” effect: **Medium‑High** (significant long‑horizon improvements, but break condition not fully tested).  
- Overall ST‑Lite generality: **Medium** (results demonstrated on two models, but missing hyperparameters and modality handling affect reproducibility).

## Next Checks
1. **δ sensitivity analysis:** Vary observation window size (δ=1,5,10,20) on AITW; measure success rate variance to confirm robustness and identify optimal δ.  
2. **Modality detection verification:** Implement a heuristic for distinguishing visual vs. text tokens (e.g., by positional embedding ranges or special token IDs); run ablations with misaligned assignment to quantify performance drop and validate the scheme.  
3. **TSG break‑condition stress test:** Construct GUI trajectories containing repeated identical screenshots with task context switches (e.g., same settings menu at different stages); evaluate ST‑Lite vs. full cache to detect over‑eviction failures.
