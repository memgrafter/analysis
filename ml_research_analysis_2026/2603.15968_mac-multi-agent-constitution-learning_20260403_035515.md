# MAC: Multi-Agent Constitution Learning
## Quick Facts
- **arXiv ID:** 2603.15968
- **Source URL:** https://arxiv.org/abs/2603.15968
- **Reference count:** 40
- **Primary result:** MAC improves F1 by over 50% versus GEPA and MIPRO on PII tagging, matches supervised fine-tuning without parameter updates, and generates human-readable auditable rules.

## Executive Summary
MAC introduces a multi-agent system for automatic constitution learning from limited labeled data, addressing key limitations of existing prompt optimizers that require many labels and produce unstructured outputs. By iteratively proposing, evaluating, and refining structured rule sets through specialized agents (Annotator, Decision, Creator, Editor), MAC achieves significant performance gains on PII tagging across legal, healthcare, and finance domains. The method not only outperforms state-of-the-art prompt optimizers by over 50% in F1 but also matches supervised fine-tuning without any parameter updates, while maintaining transparency through human-readable constitutions. Extensions like MAC+ (agent fine-tuning) and reMAC (test-time retrieval) further boost performance and generalize to tool-calling tasks, demonstrating structured rule optimization as an effective, transparent alternative.

## Method Summary
MAC optimizes a constitution—a structured set of natural-language rules—using a fixed pipeline of four agents. The Annotator applies the current constitution to a data batch to produce predictions. The MATCH function compares predictions to ground truth, computes F1, and extracts error sets (false negatives/positives). The Decision agent analyzes these errors and selects an update operation (add, edit, remove) with rationale and target rule index. Depending on the operation, the Creator or Editor agent proposes a new or revised rule, which is validated on the same batch; if performance improves, the constitution is updated. This loop runs iteratively with periodic validation on a held-out set to select the best constitution. The structured rule representation prevents incoherent growth and enables auditability, while decomposition into specialized agents reduces per-call complexity and improves reliability, especially for smaller models.

## Key Results
- MAC improves F1 by over 50% compared to GEPA and MIPRO on PII tagging across legal, healthcare, and finance datasets.
- Achieves performance comparable to supervised fine-tuning without any parameter updates, demonstrating the effectiveness of rule-based optimization.
- Generates human-readable, auditable constitutions; MAC+ (agent fine-tuning) and reMAC (test-time retrieval) provide additional boosts, and the approach generalizes to tool-calling tasks.

## Why This Works (Mechanism)
MAC outperforms unstructured prompt optimizers by optimizing over a structured rule set (constitution) rather than monolithic text. The system represents the constitution as an explicit list of natural-language rules, with updates constrained to adding, editing, or removing individual rules. This preserves a fixed format and prevents the "diminishing returns" and incoherence seen in unstructured prompt growth, making it more effective for limited data while maintaining interpretability and auditability.

Decomposing the constitution learning process into specialized agents (Annotator, Decision, Creator, Editor) improves reliability and enables effective use of smaller models. The multi-agent design breaks the complex, end-to-end prompt optimization problem into sequential, well-defined subtasks (execution, diagnosis, generation, refinement). Each agent focuses on a single cognitive function, reducing the reasoning burden per LLM call and stabilizing the overall system, as evidenced by MAC's strong performance even with 3B models.

MAC+ and reMAC provide complementary performance boosts by addressing model capacity and domain specificity. MAC+ uses distillation: a large model generates high-quality reasoning traces for each agent's role, which fine-tune a smaller model, transferring task structure without memorizing domain data. reMAC augments the learned constitution at inference by retrieving and few-shot prompting with relevant training examples, combining abstract rules with concrete context. Both extensions show consistent gains, though their effectiveness relies on trajectory quality and retrieval relevance.

## Architecture Onboarding
Component map: Annotator Agent → MATCH Function → Decision Agent → (Creator Agent or Editor Agent) → Validation Loop

Critical path: The core optimization loop: Annotator executes on batch B → MATCH computes errors (FN, FP) → Decision selects operation (ADD/EDIT/REMOVE) and target → Creator/Editor proposes revised rule → Annotator re-evaluates on same batch → if F1 improves, accept new constitution. This repeats iteratively with periodic validation on held-out data to track the best constitution.

Design tradeoffs:
- Transparency vs. Performance: Strict rule structure ensures auditability but may limit expressiveness; MAC uses natural-language rules to mitigate.
- Model Capacity vs. Cost: Decomposition enables smaller models (3B) but performance scales with size; MAC+ uses distillation to decouple.
- Generality vs. Specificity: Learned rules are general; reMAC adds specific examples at test time, trading some auditability for performance on niche terminology.

Failure signatures:
- Decision Agent bias: Smaller models (3B) show bias toward adding rules, leading to verbose constitutions and potential overfitting.
- Task complexity ceiling: MAC underperforms on dense tasks (e.g., Healthcare with 49 types) with 3B models due to limited error-diagnosis capacity.
- Rule interactions: Risk of conflicting rules as constitution grows; current single-batch validation may miss long-term interplay effects.

## Limitations
- Rule verbosity and pruning: Decision agent bias toward ADD, especially in 3B models, risks oversized constitutions; REMOVE action's necessity is untested.
- Task complexity ceiling: MAC underperforms on fine-grained, dense tasks with smaller models due to limited error-diagnosis capacity.
- Rule interactions: Unaddressed risk of conflicting rules as constitution scales, as validation only uses single-batch acceptance.

## Confidence
- Structured vs. Unstructured Advantage: Medium (strong internal evidence, weak external support; break condition untested).
- Multi-Agent Decomposition: Medium (demonstrated reliability gains, but break conditions lack empirical falsification).
- MAC+ & reMAC Boosts: High for reported results; Medium for transferability (distillation quality and retrieval relevance assumptions).
