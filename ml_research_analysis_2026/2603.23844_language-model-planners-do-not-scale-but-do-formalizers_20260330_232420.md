# Language Model Planners do not Scale, but do Formalizers?
## Quick Facts
- arXiv ID: 2603.23844
- Source URL: https://arxiv.org/abs/2603.23844
- Reference count: 22
- Key outcome: LLM formalizers significantly outperform LLM planners on scaled BlocksWorld problems, with divide-and-conquer and higher-order formalizer techniques addressing specific failure modes.

## Executive Summary
This paper investigates whether language model (LLM) formalizers, which generate formal problem representations like PDDL for downstream planners, scale better than LLM planners that produce action sequences directly. The study reveals that while standard LLM planners fail catastrophically as problem size increases (dropping below 20% accuracy by 30 blocks in a 100-block BlocksWorld benchmark), LLM formalizers maintain substantially better performance, with some models retaining near-perfect accuracy at large scales. The research introduces and evaluates two key techniques - divide-and-conquer formalization and LLM-as-higher-order-formalizer - that address specific scaling challenges, particularly for problems with compressed natural language descriptions that map to exponentially larger formal structures.

## Method Summary
The paper evaluates LLM planners versus formalizers on scaled BlocksWorld problems with up to 100 blocks (state space ~10^165). Multiple models including Gemini 3 Flash, Qwen2.5-Coder, and GPT-4o-mini are tested using a benchmark suite that varies block count systematically. The evaluation framework generates ground-truth PDDL for comparison, measuring accuracy across different problem sizes. Two novel techniques are introduced: divide-and-conquer formalization (generating headers then iterating over sentences) and LLM-as-higher-order-formalizer (where the LLM generates a program that algorithmically produces PDDL). The study also identifies and characterizes "unraveling" problems where compressed natural language descriptions map to exponentially larger formal structures.

## Key Results
- Standard LLM planners drop below 20% accuracy by 30 blocks on 100-block BlocksWorld problems
- LLM formalizers scale substantially better: Gemini 3 Flash retains 100% accuracy, Qwen2.5-Coder stays above 70% until 80 blocks
- Divide-and-conquer technique improves Qwen2.5's accuracy from 30% to 100% at 100 blocks
- LLM-as-higher-order-formalizer restores Gemini 3 Flash to 100% accuracy on unraveling problems and reduces Qwen2.5's initial condition errors from 64% to 16% of failures

## Why This Works (Mechanism)
The superior scaling of LLM formalizers stems from their ability to leverage deterministic solvers for the computationally intensive search process, while the LLM handles only the translation from natural language to formal specification. This separation of concerns allows the LLM to focus on a simpler task (representation generation) rather than the complex sequential decision-making required for direct planning. The divide-and-conquer technique reduces cognitive load by breaking down complex problem descriptions into manageable components. The higher-order formalizer approach further improves robustness by having the LLM generate algorithmic code that systematically produces the formal representation, reducing the burden of handling exponentially large structures directly.

## Foundational Learning
- **PDDL (Planning Domain Definition Language)**: Standard formalism for representing planning problems; needed because it provides a structured, unambiguous representation that solvers can process efficiently
- **BlocksWorld domain**: Classic planning benchmark where blocks must be stacked according to constraints; serves as a controlled environment to test scaling properties
- **LLM scaling limits**: Understanding how model performance degrades with problem size is critical for practical deployment
- **Divide-and-conquer strategy**: Breaking complex problems into smaller subproblems; essential for managing cognitive load in large problem descriptions
- **Higher-order programming**: Programs that generate other programs; enables systematic generation of large formal structures
- **Unfolding/unraveling problems**: Problems where natural language descriptions compress exponentially large structures; critical to identify because they expose fundamental limitations of direct generation approaches

## Architecture Onboarding
- **Component map**: Natural Language Description -> LLM Formalizer -> PDDL -> Deterministic Planner -> Action Sequence
- **Critical path**: The translation from natural language to PDDL is the bottleneck; solver performance is deterministic and not the limiting factor
- **Design tradeoffs**: Direct planning (simplicity, single model) vs. formalization (complexity, two-stage but better scaling)
- **Failure signatures**: Standard formalizers fail on unraveling problems where compressed descriptions map to exponential formal structures; shows as high initial condition errors
- **First experiments**: 1) Test scaling behavior across 5-100 block range with multiple models, 2) Implement divide-and-conquer technique on failing cases, 3) Apply higher-order formalizer to unraveling problem variants

## Open Questions the Paper Calls Out
The paper does not explicitly call out open questions beyond the immediate technical contributions and evaluations presented.

## Limitations
- Evaluation limited to single BlocksWorld domain and its variants, raising generalizability concerns
- No systematic exploration of prompt engineering or few-shot prompting strategies
- Benchmark relies on ground-truth PDDL generation rather than end-to-end plan execution and evaluation

## Confidence
- **High Confidence**: Comparative scaling behavior between LLM planners and formalizers is well-established through controlled experiments
- **Medium Confidence**: Effectiveness of divide-and-conquer and higher-order formalizer techniques shows promise but needs broader validation
- **Low Confidence**: Proposed solution for unraveling problems lacks comprehensive validation across different problem structures
