# Circuit Representations of Random Forests with Applications to XAI

## Quick Facts
- arXiv ID: 2602.08362
- Source URL: https://arxiv.org/abs/2602.08362
- Reference count: 40
- Primary result: Algorithm 3 compiles random forests into NNF circuits (up to 1000 trees) within minutes and enables linear-time computation of complete/general reasons for exhaustive explanation enumeration (sufficient/necessary reasons, contrastive explanations, robustness, shortest flips), with downstream tasks often in milliseconds.

## Executive Summary
Random forests are powerful but opaque; providing formal, guaranteed explanations for their decisions is challenging. This paper addresses the problem by compiling a random forest classifier into a tractable logical representation: first into negation normal form (NNF) circuits using odd-even sorting networks, then (optionally) into weak test-once decision graphs. These representations allow linear-time computation of complete and general reasons, which in turn enable enumeration of all minimal sufficient reasons, necessary reasons, contrastive explanations, decision robustness (the smallest number of feature changes needed to flip the decision), and all shortest decision flips. Empirically, the compilation algorithm is significantly more efficient than prior approaches, generating smaller circuits faster; for forests up to 1000 trees compilation takes at most 323.9 seconds. Downstream tasks such as robustness computation and shortest flip enumeration are completed in milliseconds for most datasets, scaling effectively to classifiers with up to 100 trees, thereby facilitating exhaustive explanation across a variety of datasets.

## Method Summary
The method operates in two compilation phases. First, each decision tree is translated into a class formula expressed as an NNF circuit. For binary classification, these per-tree formulas are processed by an odd-even sorting network where comparators are interpreted as disjunction (max) and conjunction (min); the output at position ⌈n/2⌉ encodes the majority vote, yielding an NNF circuit for the forest. For multi-class, pairwise comparisons between the target class and others are constructed and conjoined. Second, the raw NNF circuit can be used directly for some tasks, but to guarantee linear-time computation of complete and general reasons, the circuit is transformed into a weak test-once decision graph via the recursive Apply algorithm. This conversion enforces that each feature appears at most once on any root-to-leaf path (with feasible states), preserving tractability. From this representation, complete reasons (all minimal sufficient conditions) and general reasons (extended to handle non-binary features) are derived in closed form. These reasons feed into modules that enumerate sufficient and necessary reasons, compute decision robustness (minimum flips), and find all shortest decision flips. For contrastive explanations, the target class formula is negated and its complete reason is computed (requiring the decision graph representation). The pipeline thus converts a black-box random forest into a fully transparent, formally grounded explanation engine.

## Key Results
- Compilation Algorithm 3 outperforms prior methods, producing smaller circuits faster; for forests up to 1000 trees, compilation time ≤ 323.9 seconds.
- Downstream explanation tasks (robustness, shortest flips) are computed in milliseconds for most datasets, scaling to classifiers with up to 100 trees.
- The approach enables exhaustive enumeration of all sufficient/necessary reasons and contrastive explanations across diverse UCI/PMLB datasets.

## Why This Works (Mechanism)
### Mechanism 1: Sorting Network Compilation to NNF Circuits
**Claim:** Random forest class formulas can be compiled into tractable NNF circuits via sorting networks, avoiding auxiliary variables and enabling direct representation of majority voting.  
**Mechanism:** For each decision tree, generate its class formula as an NNF circuit. For binary classification, feed these circuits into an odd-even sorting network, interpreting comparators as disjunction (max) and conjunction (min), and take the output corresponding to the majority threshold (⌈n/2⌉). For multi-class, construct pairwise comparisons between the target class and every other class using negated class formulas, then conjoin the outputs.  
**Core assumption:** Sorting networks efficiently encode majority functions with O(n log n) size and O(log² n) depth for n inputs, and NNF circuits can be combined via disjunction/conjunction without introducing negation.  
**Evidence anchors:**  
  - Abstract: “compile a random forest classifier into a set of circuits… via sorting networks”.  
  - Section 3 (pp. 8–10): Algorithms 1–3 and Figure 4 showing circuit construction.  
**Break condition:** If the number of trees (n) is very large (e.g., >1000), circuit size grows as O(S + nk log² n), leading to memory/time overflow; also, if tree class formulas are not NNF, sorting network integration fails.

### Mechanism 2: Weak Test-once Decision Graph Conversion
**Claim:** NNF circuits can be transformed into weak test-once decision graphs, ensuring linear-time computation of complete and general reasons for any decision.  
**Mechanism:** Apply Algorithm 4 recursively during the sorting network’s max/min operations. The algorithm tracks feasible states per variable via a path parameter, merging decision nodes while pruning inconsistent edges to enforce that a variable is tested at most once with feasible states on any root-to-leaf path.  
**Core assumption:** The input NNF circuits are built from only literals, ∧, ∨; the path tracking in Algorithm 4 correctly enforces weak test-once by intersecting state sets at each variable node.  
**Evidence anchors:**  
  - Section 4 (pp. 11–12): Algorithm 4 and its use in Algorithm 3A; Figure 5 demonstrating the transformation.  
**Break condition:** If the input NNF has deeply nested shared subformulas with repeated variable tests in infeasible states, the conversion may cause exponential blowup due to edge duplication; caching helps but worst-case remains uncontrolled.

### Mechanism 3: Robustness and Shortest Flips via Complete/General Reasons
**Claim:** Decision robustness (minimal feature changes to flip) and all shortest flips can be computed efficiently from the complete reason (monotone NNF) and general reason (locally fixated NNF).  
**Mechanism:**  
  - **Robustness** (Algorithm 5): On an or-decomposable complete reason, recursively compute minimal variable count across ∧-children and sum across ∨-children, yielding the smallest number of features to flip (and the set V of variable sets achieving this).  
  - **Shortest flips** (Algorithm 7): From the general reason, convert to CNF (Algorithm 6), extract clauses with variable sets exactly in V, then close each variable set’s clauses under resolution (variable depletion) to generate all shortest general necessary reasons (GNRs); every violation of a shortest GNR is a shortest flip.  
**Core assumption:** Complete reason is monotone and or-decomposable; general reason is locally fixated; the set V from robustness exactly matches variable sets of shortest GNRs.  
**Evidence anchors:**  
  - Section 4 (pp. 13–16): Algorithms 5–7 and Propositions 1–2 linking NRs/GNRs to shortest flips.  
  - Appendix: Proofs of Lemma 3 and Proposition 5.  
**Break condition:** If the class formula is not weak test-once, complete/general reasons may not be efficiently computable; if V is empty (no flip possible), the decision is already maximally robust; resolution may be slow if many shortest clauses exist.

## Architecture Onboarding
### Component map
Random Forest Compiler (Algorithm 3) → Reason Generator → Explanation Engine. The CE Module also uses the Compiler’s output (class formula) and the complete reason computation for contrastive explanations.

### Critical path
1. Input random forest → Compile class formulas (Algorithm 3).  
2. For a test instance, identify predicted class(es) → compute class formula for that class.  
3. Compute complete reason (linear in class formula size if weak test-once) and general reason (requires additional traversal).  
4. Feed complete reason to Algorithm 5 for robustness and set V.  
5. Feed general reason and V to Algorithm 6 → 7 to get all shortest GNRs.  
6. Extract explanations: SRs = prime implicants of complete reason; NRs = prime implicates; shortest flips = all violations of shortest GNRs.

### Design tradeoffs
- Algorithm 3B (NNF circuits) vs. 3A (decision graphs): 3B is faster and yields smaller circuits but cannot compute contrastive explanations (requires weak test-once). 3A adds overhead but enables all explanations.  
- Sorting networks vs. additive encoding: Avoids auxiliary variables, giving direct class formulas, but circuit size grows as O(n log n) with tree count n; suitable for moderate n (empirically up to 1000 trees).  
- Exact vs. approximate: The approach provides formal guarantees (complete enumeration) at the cost of potentially high compilation memory for very large forests.

### Failure signatures
- Memory explosion during Algorithm 3 for large n (e.g., >1000 trees) or high tree depth; monitor circuit node count.  
- Non-weak test-once circuits if using 3B, causing exponential reason computation; verify by checking variable repetition on paths.  
- Ties in random forest (instance in multiple classes) require merging classes or handling separately; the paper assumes single-class for robustness but extends via negation for contrastive explanations.  
- Algorithm 7 slowdown if many shortest clauses or variables; monitor CNF clause count before resolution.

### First 3 experiments
1. **Compilation benchmark:** Run Algorithm 3B on a small random forest (e.g., 10 trees, 4 features) and verify node count matches expected O(n log n) growth; compare against Table 1 timing.  
2. **Reason correctness:** For a known decision tree (e.g., Figure 2), compute complete reason for a given instance and check it equals the conjunction of the two SRs shown; also verify NRs are prime implicates.  
3. **Robustness validation:** For an instance, compute robustness r and enumerate all single-feature flips; confirm none flip the decision if r>1, and exactly r features suffice if r matches minimal observed change.

## Open Questions the Paper Calls Out
### Open Question 1
**Question:** What is the worst-case computational complexity (time and space) of Algorithm 4 (Apply) for combining weak test-once decision graphs?  
**Basis in paper:** The paper explicitly states: “We currently do not have a useful bound on the complexity of Algorithm 4 but will evaluate it empirically in Section 5” (page 12).  
**Why unresolved:** A theoretical bound is essential for predicting scalability to larger decision graphs; empirical results cover only a limited set of datasets and cannot reveal worst-case behavior.  
**What evidence would resolve it:** Formal analysis of the recursive conjoin/disjoin procedure, deriving bounds in terms of graph sizes, variable counts, and feasible states per variable.

### Open Question 2
**Question:** Can the proposed circuit compilation approach be efficiently adapted to gradient boosted tree ensembles, and if so, how does the circuit size and compilation time compare to random forests?  
**Basis in paper:** The introduction identifies gradient boosted trees as a major tree-based method but the paper develops the technique solely for random forests (which use majority voting). The algorithm relies on sorting networks to encode majority functions.  
**Why unresolved:** Gradient boosted trees are widely used; extending the explanation framework would broaden applicability. The compilation method would need to handle additive combinations instead of majority.  
**What evidence would resolve it:** A modified compilation algorithm that encodes the additive aggregation (e.g., via threshold circuits) and empirical benchmarks comparing circuit growth and compilation times to the random forest case.

### Open Question 3
**Question:** How does the size of the compiled circuit scale with the cardinality of categorical features (i.e., number of possible states per feature)?  
**Basis in paper:** The discrete formula framework permits arbitrary finite states, but the experimental evaluation uses datasets with low to moderate cardinality (maximum 7 classes in the segment dataset). Real-world data often contains high-cardinality categorical features not represented in the experiments.  
**Why unresolved:** High cardinality could cause an exponential blowup in the number of edges in the decision graph, undermining the claimed tractability. This potential limitation remains unexplored.  
**What evidence would resolve it:** Systematic experiments with synthetically increased cardinalities; theoretical analysis of how circuit size grows with the number of states per variable.

### Open Question 4
**Question:** Are the formally sound explanations (e.g., complete sets of sufficient reasons, contrastive explanations) more comprehensible or useful to human decision-makers than popular model-agnostic approximations like LIME or SHAP?  
**Basis in paper:** The paper argues for formal guarantees but provides no human-centered evaluation. The introduction positions model-agnostic methods as lacking guarantees yet widely used, implying a trade-off between rigor and utility that is not addressed.  
**Why unresolved:** The ultimate goal of explainable AI is to aid human understanding; formal correctness does not automatically translate to better human explanations. Without user studies, the practical value of exhaustive formal explanations is unknown.  
**What evidence would resolve it:** Controlled experiments with domain experts measuring task performance, trust calibration, or subjective comprehension when using the formal explanations versus LIME/SHAP on the same classifiers.

## Limitations
- Extraction of per-tree class formulas from standard ML libraries (e.g., scikit-learn) is underspecified, hindering faithful reproduction.
- The Apply algorithm’s caching strategy and worst-case memory management are omitted; for certain NNF structures it may cause exponential blowup, breaking linear-time guarantees.
- The equivalence ¬R_i ≡ ⋂_{j≠i} R_j for multi-class contrastive explanations is assumed but not proven; ties in random-forest votes are not thoroughly addressed.

## Confidence
- Theoretic soundness (sorting-network NNF compilation, weak test-once conversion): **High**
- Efficiency of compilation (Algorithm 3) and downstream tasks: **Medium**
- Exhaustiveness of explanation enumeration: **Medium**
- Scalability to large forests: **Medium**
