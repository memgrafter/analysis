# Autonomous Continual Learning of Computer-Use Agents for Environment Adaptation

## Quick Facts
- **arXiv ID**: 2602.10356
- **Source URL**: https://arxiv.org/abs/2602.10356
- **Reference count**: 40
- **Primary result**: ACuRL achieves 4–22% performance improvements across six diverse digital environments while avoiding catastrophic forgetting, using an autonomous curriculum reinforcement learning framework and an automatic evaluator.

## Executive Summary
Computer-use agents (CUAs) must adapt to new digital environments without costly human data. This paper presents ACuRL, an autonomous curriculum reinforcement learning framework. ACuRL first has the agent explore a target environment to collect experience. A curriculum task generator then iteratively creates new tasks tailored to the agent’s evolving abilities, using the gathered experience and past performance feedback. Reliable reward signals are provided by CUAJudge, an automatic evaluator with 93% human agreement. Evaluated on six environments (LibreOffice suite, Thunderbird, Celestia, KAlgebra), ACuRL yields 4–22% gains on target environments in both intra- and cross‑environment continual learning scenarios, while preserving performance on previously learned environments. Analysis shows highly sparse parameter updates (~80% unchanged), explaining efficient adaptation.

## Method Summary
ACuRL comprises four main components: (1) Experience collection: the base agent (UI‑TARS‑1.5‑7B) autonomously explores the target environment, recording trajectories and performing context reviews on web‑crawled contexts. (2) Iterative curriculum RL: at iteration 0, a curriculum generator (GPT‑5) synthesizes atomic tasks from the experience. The agent is trained on these tasks using the GRPO algorithm (group size 8, batch 16, 75 steps, learning rate 1e‑6). After training, success rates on the task set are obtained. For later iterations, tasks are partitioned into easy (>70%), medium (30–70%), and hard (<30%) groups; the generator creates the next task set by increasing complexity of easy tasks, varying contexts of medium tasks, and decomposing hard tasks into subtasks. (3) CUAJudge: an automatic evaluator that compares the agent’s final state to the goal state and verifies key points; it uses Qwen3‑VL‑8B or GPT‑5‑mini. (4) Infrastructure: a unified environment manager handles batch creation/deletion with fault tolerance, and asynchronous preloading reduces idle time. Training and evaluation are run in a feedback loop until convergence.

## Key Results
- **Performance gains**: Across six environments, ACuRL improves success rates by 4–22% in both intra‑ and cross‑environment continual learning settings.
- **No catastrophic forgetting**: The agent retains or improves performance on previously learned environments after adapting to new ones.
- **Sparse updates**: Approximately 80% of model parameters remain unchanged during adaptation, indicating selective learning.

## Why This Works (Mechanism)
ACuRL succeeds by closing a self‑reinforcing loop: autonomous exploration collects a broad experience base without human effort; the curriculum generator uses this experience and the agent’s success rates to create tasks that are always at an appropriate difficulty—challenging enough to promote learning but not so hard as to cause failure; and CUAJudge supplies dense, human‑aligned reward signals that enable stable RL optimization. The combination of continuously adjusting task difficulty and reliable rewards drives steady improvement. Moreover, the observed sparsity of parameter updates suggests the agent learns by fine‑tuning only a small subset of weights, which likely protects previously acquired knowledge and prevents catastrophic forgetting while allowing rapid adaptation.

## Foundational Learning
Key concepts underlying ACuRL:

- **Reinforcement Learning (RL)**: The agent learns by interacting with the environment and optimizing a reward signal. *Why needed*: Provides a framework for learning from sparse binary outcomes. *Quick check*: Does the agent’s performance improve with more training steps?
- **Continual Learning**: Learning sequentially across multiple environments without forgetting past skills. *Why needed*: Real‑world agents face new environments over time. *Quick check*: After learning a new environment, does performance on old environments degrade?
- **Curriculum Learning**: Gradually increasing task difficulty to improve learning efficiency. *Why needed*: Prevents the agent from being overwhelmed and guides exploration. *Quick check*: Do generated tasks become more complex across iterations?
- **Automatic Reward Evaluation**: Using a model (CUAJudge) to assign rewards instead of human‑annotated rewards. *Why needed*: Scales to many environments without human cost. *Quick check*: Does the evaluator agree with human judgments (>90%)?
- **Parameter Sparsity**: Updating only a small fraction of model weights during fine‑tuning. *Why needed*: Reduces interference with previously learned knowledge. *Quick check*: What percentage of parameters change after training? (target ~80% unchanged)

## Architecture Onboarding
**Component map**: Explorer (agent + environment) → Experience buffer → Curriculum generator (LLM) → Task set → Agent trainer (GRPO + CUAJudge) → Updated agent. The loop then feeds evaluation results back to the curriculum generator.

**Critical path**:
1. Agent explores target environment, collecting trajectories.
2. Experience buffer accumulates trajectories and context reviews.
3. Curriculum generator creates initial atomic tasks (Iteration 0).
4. Agent trains on tasks using GRPO; rewards provided by CUAJudge.
5. Agent is evaluated on the task set to obtain per‑task success rates.
6. Tasks are partitioned (easy/medium/hard); generator synthesizes next task set.
7. Repeat steps 4–6 for subsequent iterations.

**Design tradeoffs**:
- *LLM choice*: Using GPT‑5 yields high‑quality tasks and evaluations but introduces dependency on proprietary models and may be costly; substituting open models risks lower performance.
- *Exploration noise*: Autonomous exploration can generate low‑quality or irrelevant experiences, potentially degrading curriculum quality.
- *Sparse updates*: While they mitigate forgetting, they might limit the agent’s capacity to acquire entirely new skills requiring widespread weight changes.
- *Heuristic thresholds*: The 70%/30% partitioning for task difficulty is simple but not optimized; alternative partitions could affect learning dynamics.

**Failure signatures**:
- Stagnant learning: success rates fail to improve across iterations; likely caused by unchallenging tasks or mis‑aligned generator.
- Reward mis‑specification: high variance in training loss or divergence between CUAJudge and human judgments; indicates unreliable evaluator.
- Resource exhaustion: frequent environment crashes or out‑of‑memory errors; points to infrastructure issues in environment management or asynchronous preloading.

**Three first experiments**:
1. **CUAJudge replication with open models**: Replace GPT‑5‑mini with Qwen3‑VL‑8B or GPT‑4o‑mini, evaluate agreement with human judgments on a 100‑trajectory sample; target >90% agreement.
2. **Two‑iteration ACuRL proof of concept**: On LibreOffice Impress, run two full iterations and measure improvement on a held‑out test set; expect >5% gain to validate the framework.
3. **Parameter sparsity check**: After training, compute the fraction of unchanged model parameters; confirm ~80% sparsity as reported, indicating selective adaptation.

## Limitations
- **GPT‑5 dependency**: Both the curriculum generator and CUAJudge rely on unreleased GPT‑5 models, hindering reproducibility and potentially limiting performance when using substitutes.
- **Environment orchestration details**: Specifications for software versions, OS settings, and fault‑tolerant management are not open‑sourced, which may cause subtle reproducibility gaps.
- **Compute intensity**: Results were obtained with 8×H100 GPUs and a 96‑CPU server; smaller setups may require hyperparameter retuning or may be infeasible.

## Confidence
- Performance gains (4–22%): **Low** – tightly coupled to GPT‑5‑driven curriculum and rewards.
- No catastrophic forgetting: **Medium** – validated across six environments but depends on stable experience replay and curriculum design.
- Sparse parameter updates (~80% unchanged): **High** – directly measured and likely robust to implementation variations.

## Next Checks
1. Replicate CUAJudge with open models (e.g., Qwen3‑VL‑8B) and measure human agreement on 100+ trajectories; target >90%.
2. Generate curriculum tasks with different LLMs (GPT‑4o, Claude‑3.5, Llama‑3.1‑405B) using the same experience buffer; compare task diversity and complexity progression against the original.
3. Test parameter sparsity generalizability by applying ACuRL to a different base agent (e.g., UI‑TARS‑7B vs. 1.5‑7B) and measuring the fraction of unchanged parameters after training.
