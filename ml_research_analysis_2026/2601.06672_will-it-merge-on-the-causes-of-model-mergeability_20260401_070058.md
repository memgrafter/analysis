# Will it Merge? On The Causes of Model Mergeability

## Quick Facts
- arXiv ID: 2601.06672
- Source URL: https://arxiv.org/abs/2601.06672
- Reference count: 40
- Primary result: Base model prior knowledge is the dominant factor in mergeability; higher base accuracy or smaller probability gaps lead to higher mergeability scores.

## Executive Summary
This paper investigates why merging model updates (specifically LoRA adapters) succeeds or fails by introducing a metric called mergeability. Mergeability quantifies how well an individual update preserves its performance when combined with others. Through experiments on PopQA (example-level) and Lots-of-LoRAs (task-level), the authors find that the base model's prior knowledge about the task is the strongest predictor of mergeability. In contrast, properties of the adapter weights or training data difficulty show weak or inconsistent correlations. As a practical application, weighted merging inversely proportional to base accuracy improves retention of low-accuracy tasks with minimal harm to high-accuracy ones.

## Method Summary
The study defines mergeability score S(θ∆) for a LoRA adapter θ∆ as its average performance after being merged with M randomly sampled other adapters, repeated N times. Two experimental settings are used: (1) PopQA, where adapters are trained to correct individual QA examples the base model got wrong; (2) Lots-of-LoRAs, using a collection of adapters for diverse tasks, filtered to those achieving ≥99% accuracy. Mergeability is computed using the KNOTS merging algorithm. The authors correlate S with three factors: base model knowledge (Δbase or base task accuracy), weight properties (Frobenius norm and σ_max of BA), and training data difficulty (perplexity, context length). LoRA adapters are trained with rank r=64, α=128, on the mlp.up_proj layer for 10 epochs at learning rate 4e-3.

## Key Results
- Base model prior knowledge is the dominant factor: higher base accuracy or smaller Δbase strongly correlate with higher mergeability across both datasets.
- Weight properties (Frobenius norm, σ_max) and training data difficulty show weak or inconsistent correlations with mergeability.
- Mergeability is an intrinsic trait of the update; scores are stable across different random merge sets and base models (within tested families).
- Weighted merging inversely proportional to base accuracy improves low-accuracy task retention with minimal high-accuracy task degradation.

## Why This Works (Mechanism)
The paper's core insight is that an adapter's mergeability hinges on how much the base model already knows about the task. If the base model has high prior accuracy or narrow probability gap (Δbase), the adapter learns a small, focused update that is less likely to conflict with other adapters during merging. Conversely, when the base model is weak, the adapter must make larger, more disruptive weight changes, increasing interference when merged. This explains why base knowledge dominates over weight norm or data difficulty: even a difficult dataset might yield a high-mergeability adapter if the base model already has relevant knowledge. The KNOTS merging algorithm likely mitigates interference by aligning adapter subspaces, but the intrinsic nature of the update (shaped by base knowledge) remains the primary determinant.

## Foundational Learning
- **Mergeability Score (S)**: Quantifies adapter robustness to merging; computed via repeated random merges. *Why needed*: Enables systematic study of merge success factors. *Quick check*: Verify that S distributions are non-uniform and stable across different M/N samples.
- **LoRA (Low-Rank Adaptation)**: Parameter-efficient fine-tuning method; adapters are low-rank matrices applied to specific layers. *Why needed*: Provides modular updates that can be merged. *Quick check*: Confirm adapter rank (r=64) and target layer (mlp.up_proj) match paper.
- **Base Knowledge Metrics**: Δbase (PopQA) measures base model's probability gap; base task accuracy (Lots-of-LoRAs). *Why needed*: Primary correlated factor; indicates how much the adapter must override prior knowledge. *Quick check*: Compute Δbase for a sample adapter; expect negative correlation with S.
- **KNOTS Merging Algorithm**: A merging technique from Stoica et al. (2025) that aligns adapter subspaces to reduce interference. *Why needed*: Primary merging method used to compute S; its properties affect absolute S values but not relative correlations. *Quick check*: Ensure implementation matches cited paper (if available).
- **Task-Level vs. Example-Level Mergeability**: Two granularities studied: single example adapters (PopQA) vs. full task adapters (Lots-of-LoRAs). *Why needed*: Tests generality of findings across abstraction levels. *Quick check*: Verify that PopQA adapters correct individual examples, while Lots-of-LoRAs adapters achieve ≥99% task accuracy.
- **Weight Properties (Frobenius norm, σ_max)**: Measures of adapter magnitude and singular value spread. *Why needed*: Hypothesized causes of mergeability; found to be weakly correlated. *Quick check*: Compute these for adapters; expect no strong monotonic trend with S.

## Architecture Onboarding
Component map: Base Model (Llama-3.2-3B, Qwen-2.5-3B, Mistral-7B) -> LoRA Adapters (trained on task-specific data) -> Merge Algorithm (KNOTS) -> Merged Model -> Performance Evaluation (task accuracy) -> Mergeability Score S.

Critical path: Select base model and dataset -> Filter examples/tasks -> Train LoRA adapters -> Compute S via repeated random merges -> Correlate S with candidate factors.

Design tradeoffs: Using LoRA ensures parameter efficiency and merge compatibility but may limit adapter expressiveness compared to full finetuning. Choosing KNOTS over simpler averaging (mean) or sign-based (TIES) reduces interference but requires SVD computations. PopQA example-level adapters control for data difficulty but may not generalize to task-level behavior. Lots-of-LoRAs offers broader validation but inherits unknown adapter training details from the collection.

Failure signatures: (1) S histogram接近 uniform (vs. bimodal/segregated); (2) Correlation with base knowledge absent or reversed; (3) High variance in S across different M/N samples; (4) Adapter training success rate deviates significantly from reported ~77.55% (PopQA).

First experiments: (1) Replicate mergeability computation on a small subset (e.g., 50 adapters) using KNOTS; plot S distribution to verify non-uniformity. (2) For same adapters, compute base accuracy/Δbase; check monotonic trend when binning by S. (3) Implement basic weighted merging (inverse base accuracy) on a held-out merge set; measure trade-off between high- and low-accuracy task retention.

## Open Questions the Paper Calls Out
The paper does not explicitly list open questions beyond its correlational analysis. However, the reproduction notes highlight uncertainties around the exact KNOTS implementation, the full Lots-of-LoRAs evaluation pipeline, and the lack of causal ablation studies to confirm base knowledge as the primary driver.

## Limitations
- Exact hyperparameters of KNOTS merging algorithm are unspecified, risking implementation divergence.
- The Lots-of-LoRAs experiment lacks detail on adapter layer configurations and evaluation prompts, hindering full replication.
- Random seeds for merge sampling are unreported, preventing exact score reproduction and stability verification.
- Correlations are observational; no controlled experiments isolate base knowledge from confounding factors like adapter convergence.
