# Expert Threshold Routing for Autoregressive Language Modeling with Dynamic Computation Allocation and Load Balancing

## Quick Facts
- **arXiv ID**: 2603.11535
- **Source URL**: https://arxiv.org/abs/2603.11535
- **Reference count**: 40
- **Primary result**: Expert Threshold (ET) routing enables fully causal, dynamic computation allocation and load balancing for autoregressive MoE models without auxiliary losses, matching Expert Choice validation loss while being inference-efficient.

## Executive Summary
Token-choice Mixture-of-Experts (TC-MoE) limits dynamic computation per token and requires auxiliary losses for load balancing. Expert Choice (EC) enables dynamic allocation but is non-causal, preventing use in autoregressive models. This paper introduces Expert Threshold (ET) routing, where each expert maintains an exponential moving average (EMA) threshold estimated from the global token distribution. Tokens are independently routed to experts if their router score exceeds that expert's threshold. This mechanism achieves dynamic computation and load balancing without auxiliary losses, and is fully causal because routing decisions depend only on the current token and historical thresholds. In 2.4B parameter pretraining on FineWeb-Edu, ET reduces cross-entropy loss by 0.067 compared to TC—equivalent to 1.6× fewer training tokens—and matches EC's validation loss (~2.84) while enabling causal inference. ET achieves near-perfect load balancing and stable routing consistency comparable to large-batch EC without inference-time batch coordination.

## Method Summary
ET routing replaces per-batch top-k selection with per-expert thresholds derived from an EMA of the k-th largest router score in each batch. Each expert i maintains a threshold c_i updated as c_i ← β·c_i + (1−β)·kth_largest(r[:,:,i]), where r are router logits. During both training and inference, a token is assigned to expert i if its router score r_t,i > c_i. This decouples routing from batch composition, ensuring causality. A warmup phase using EC for the first 4k steps initializes thresholds. Capacity constraints are applied only during training to prevent OOM. The router uses sigmoid gates to weight expert outputs independently of the binary routing mask.

## Key Results
- On FineWeb-Edu, ET reduces cross-entropy loss by 0.067 vs TC-MoE, equivalent to 1.6× fewer training tokens.
- ET matches Expert Choice validation loss (~2.84) while enabling causal inference.
- Achieves near-perfect load balancing and stable routing consistency comparable to large-batch EC without inference-time batch coordination.

## Why This Works (Mechanism)
**Mechanism 1**: ET uses EMA thresholds to approximate the (1/E)-quantile of the global token score distribution. Each expert's threshold tracks the k-th largest score across batches, so tokens scoring above are routed. Routing depends only on the current token's score and the historical threshold, eliminating batch dependence and ensuring causality. The EMA, with decay β=0.999, provides a stable estimate of the desired activation rate. Evidence: abstract and section 3 state the independence and EMA estimation. Break condition: If the token score distribution shifts significantly or β is too high, the EMA may become stale, causing routing collapse or expert starvation.

**Mechanism 2**: Load balancing is achieved in expectation through population-level thresholding rather than per-batch constraints. Instead of forcing each expert to process exactly N/E tokens per batch (as in EC), ET allows fluctuations around the target because the threshold is fixed between updates. Over many batches, expected load matches the target, and hardware parallelism absorbs mild imbalance. Evidence: section 4.3.1 notes stable thresholds with fluctuating usage; section 4.3.3 shows specialization comparable to EC without large-batch coordination. Break condition: If capacity factor C is too low, clipping during training may cause train-inference mismatch; if too high, occasional overload could cause OOM.

**Mechanism 3**: ET is fully causal for autoregressive generation because routing does not require comparing scores across tokens in a batch. EC selects top-k tokens per expert within the batch, necessitating access to future token scores during training (information leakage). ET's threshold-based decision uses only the current token's score and the expert's EMA threshold, making it compatible with sequential decoding. Evidence: abstract and section 4.3.7 contrast ET's independence with EC's batch dependence. Break condition: During EMA warmup (first 4k steps), ET relies on EC fallback; omitting warmup leads to early expert starvation due to underactive thresholds.

## Architecture Onboarding
Component map: Router -> Threshold Module (per-expert EMA) -> Binary Router (score > threshold) -> Capacity Enforcement (training only) -> Gating (sigmoid) -> MoE output. Warmup Controller switches from EC to ET.

Critical path:
1. Compute router logits r [B,S,E] (B=batch, S=sequence, E=num_experts).
2. Retrieve current thresholds c_i from EMA buffer.
3. Compute binary mask z_{t,i} = (r_{t,i} > c_i) for all token positions.
4. During training: for each expert i, find k-th largest value in r[:,:,i] across batch, then update c_i ← β·c_i + (1−β)·kth_largest.
5. Apply capacity constraints: for each expert, clip/pad assignments to lie within [(1−C)·N/E, (1+C)·N/E] (training only).
6. Dispatch tokens to assigned experts, compute expert outputs weighted by sigmoid gates on original scores, combine via all-to-all communication if using expert parallelism.
7. Return MoE output and updated thresholds (for training).

Design tradeoffs:
- β (EMA decay): Higher β (e.g., 0.999) yields stable thresholds but slow adaptation; lower β increases load variance. Effective memory ≈ 1/(1−β) batches.
- Capacity factor C: Balances OOM risk vs. train-inference mismatch. Paper uses C=0.5, showing minimal clipping after warmup.
- Warmup steps: EC for first 4k steps prevents early starvation; too short risks unreliable EMA, too long wastes compute.
- Gating function: Sigmoid instead of softmax decouples routing decision from gate magnitude, aligning with loss-free balancing literature.
- Shared expert: Always-active expert improves performance (~0.02 loss) by providing stable baseline; trades parameter efficiency for quality.

Failure signatures:
- High starvation rate: Many tokens assigned to zero experts → threshold too high → check EMA initialization, warmup duration, or router weight scale.
- High saturation rate: Many tokens dropped due to capacity overflow → threshold too low or batch statistics skewed → reduce β or inspect token score distribution.
- Large train-eval loss gap: Indicates threshold does not generalize from training batches to single-token inference → likely due to small training batch size or insufficient EMA convergence.
- Routing instability: Large changes in token-expert assignments between checkpoints → inspect EMA updates; may indicate noisy k-th order statistics (small batch) or exploding/vanishing router gradients.
- Poor specialization: Heatmaps show diffuse expert activation → may indicate insufficient training, too many experts, or poor capacity factor.

First 3 experiments:
1. Main results replication: Train d20 model (2.4B total) with ET (β=0.999, warmup 4k steps) and compare validation CE loss and CORE score against TC (aux loss) and EC (512k batch). Expect ET to match EC 512k loss (~2.620) and beat TC by ~0.067.
2. Warmup ablation: Train ET without warmup and monitor cutoff-EMA stability, expert usage, starvation rate, and validation loss for first 10k steps. Expect unstable thresholds, low raw usage, high starvation, and worse final loss.
3. Capacity constraint monitoring: During ET training (post-warmup), log per-expert load statistics; compute saturation and starvation rates. Expect both to remain low (< few percent), confirming that inference can safely omit capacity limits.

## Open Questions the Paper Calls Out
**Open Question 1**: How does the duration of the Expert Choice warmup period affect Expert Threshold training stability and final performance, and could it be determined adaptively rather than fixed?
**Open Question 2**: Does Expert Threshold maintain its load-balancing and dynamic computation advantages when scaling to significantly larger models (e.g., >10B parameters) and longer sequence lengths?
**Open Question 3**: How does the EMA decay rate β impact the trade-off between routing stability and adaptivity in Expert Threshold, and is the default β=0.999 universally optimal?
**Open Question 4**: Does the population-level threshold in Expert Threshold reduce the entropy of expert assignments compared to batch-level Expert Choice, and could this limitation harm performance on tasks requiring high expert diversity?

## Limitations
- EMA staleness risk: The EMA threshold may not adapt quickly to significant distribution shifts during long training runs, potentially degrading load balance.
- Warmup dependency: The 4k-step EC warmup is presented as necessary to prevent early starvation; its absolute necessity vs. alternative initialization is unproven.
- Capacity factor sensitivity: The chosen C=0.5 is justified by minimal clipping post-warmup, but the threshold for "safe" C across different batch sizes, expert counts, or model scales is not systematically derived.

## Confidence
- Causal dynamic allocation: High. Routing depends only on token score and historical threshold; no batch-level coupling.
- Load balancing without aux losses: Medium. Validated on one model scale (2.4B) with specific hyperparameters; robustness to other regimes is assumed.
- Performance parity with Expert Choice: Medium. Matches EC at 512k batch on FineWeb-Edu; gap under different data distributions or smaller batch sizes is possible.

## Next Checks

2. Capacity factor stress test: Train ET with C=0.3 and C=0.7 on same setup. Log per-expert capacity clipping frequency and train-eval loss gap. Expected: C=0.3 → frequent clipping/OOM risk; C=0.7 → minimal clipping but possible train-inference mismatch.
3. Long-run distribution shift simulation: After converged ET training, switch evaluation to a held-out domain (e.g., code or math corpora) without further threshold updates. Compare per-expert activation rates and validation loss against in-domain eval. Expected: moderate increase in starvation/saturation if score distribution shifts substantially, indicating EMA adaptation limits.
