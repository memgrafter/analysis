# AP-OOD: Attention Pooling for Out-of-Distribution Detection

## Quick Facts
- **arXiv ID:** 2602.06031
- **Source URL:** https://arxiv.org/abs/2602.06031
- **Reference count:** 40
- **Primary result:** AP-OOD reduces FPR95 from 27.84% to 4.67% on XSUM summarization and from 77.08% to 70.37% on WMT15 translation in the unsupervised setting, substantially outperforming baselines like Mahalanobis, KNN, and Deep SVDD.

## Executive Summary
AP-OOD introduces an attention-based framework for out-of-distribution (OOD) detection in natural language processing. It replaces mean pooling with learnable query vectors to aggregate token embeddings via attention, preserving token-level anomalies that simple averaging obscures. The method computes a directional Mahalanobis distance between a sequence representation and a global in-distribution prototype derived from the entire ID corpus. AP-OOD operates effectively in both unsupervised and semi-supervised settings; with auxiliary outlier data, performance improves monotonically. On summarization (XSUM) and translation (WMT15 En-Fr) benchmarks, it achieves dramatic reductions in false positive rate at 95% true positive rate (FPR95) compared to prior methods.

## Method Summary
AP-OOD uses a frozen pre-trained language model (encoder or decoder) to extract token embeddings for a sequence. It learns multiple query vectors (heads) that perform attention-based pooling over the token embeddings, producing a sequence representation per head. A global in-distribution prototype is computed by applying the same attention pooling to the concatenated embeddings of the entire ID training corpus. The OOD score is a sum of squared directional distances between each head’s sequence representation and its corresponding prototype, plus a regularization term. Training minimizes the average squared distance for ID sequences; in the semi-supervised setting, it also maximizes distance for auxiliary OOD samples via a modified loss. Hyperparameters include the number of heads \(M\), token dimension per head \(T\) (with \(M \cdot T \approx D\), the embedding dimension), and inverse temperature \(\beta\). Memory-efficient mini-batch attention over the concatenated corpus enables scalability.

## Key Results
- Unsupervised on XSUM: mean FPR95 drops from 27.84% (best baseline) to 4.67%.
- Unsupervised on WMT15 En-Fr: mean FPR95 drops from 77.08% to 70.37%.
- Semi-supervised with auxiliary outliers: AUROC improves monotonically as more AUX samples are added, surpassing competing methods at all counts.

## Why This Works (Mechanism)
AP-OOD succeeds by addressing two key limitations of prior OOD detection methods: the dilution of token-level anomalies via mean pooling and the inability of a single global covariance (as in Mahalanobis) to capture multimodal structure in the token embedding space.

First, mean pooling averages token embeddings, which can obscure local anomalies when individual tokens deviate from the in-distribution (ID) manifold but their mean lies near the ID centroid. AP-OOD uses learnable query vectors to compute attention weights, allowing the model to focus on informative tokens whose embeddings are most relevant to the ID distribution. This preserves anomalies that would otherwise be averaged away, as demonstrated in a toy example where mean pooling fails but attention pooling succeeds.

Second, AP-OOD extends the Mahalanobis distance by decomposing it into multiple learned directions. Instead of a single global covariance matrix, each head defines a direction \(w_j\); the squared distance is the sum of squared differences between projected pooled representations and a global prototype computed via attention over the full ID corpus. This multi-head approach captures multimodal structure in the token embedding space, where different directions may correspond to different clusters or aspects of the ID distribution.

Third, the method seamlessly transitions to a semi-supervised setting when auxiliary OOD data is available. The loss function encourages larger distances for auxiliary samples, shaping a decision boundary that better separates ID from plausible OOD examples. This supervised extension improves performance as more auxiliary samples are provided, without sacrificing unsupervised capability.

Evidence anchors include the toy experiment (Figures 1–2) showing attention pooling’s advantage, the reduction of AP-OOD to standard Mahalanobis under specific settings (Appendix B.4), and empirical results on XSUM and WMT15 where AP-OOD consistently outperforms baselines. Break conditions exist: if all tokens in an OOD sequence are individually ID-like, attention may still fail; if the ID distribution is isotropic, multi-head gains diminish; and if auxiliary data is misaligned with true OOD, the supervised boundary may degrade.

## Foundational Learning
- **Attention pooling**: A differentiable alternative to mean/max pooling that computes a weighted sum of tokens using softmax attention. *Why needed*: AP-OOD’s core innovation is using attention to weight tokens by relevance to the ID distribution, preserving anomalies. *Quick check*: How does the attention weight for a token depend on the query vector \(w\) and the token embedding?
- **Mahalanobis distance**: A measure of distance between a point and a distribution, incorporating covariance. *Why needed*: AP-OOD generalizes this baseline; understanding its formulation (with a single global covariance) is key to seeing the improvement from directional decomposition. *Quick check*: What does the Mahalanobis distance measure in terms of covariance, and how does Equation (6) decompose it?
- **Semi-supervised OOD detection with auxiliary outliers**: Using labeled OOD examples to shape the decision boundary. *Why needed*: AP-OOD’s loss changes when auxiliary data is present; this is a major contribution. *Quick check*: Why might auxiliary OOD data improve detection beyond the unsupervised case, and what risk does it introduce?
- **Directional Mahalanobis decomposition**: Expressing the Mahalanobis distance as a sum over orthogonal directions. *Why needed*: AP-OOD’s score aggregates per-head squared distances; this decomposition underlies its ability to handle multimodal ID distributions. *Quick check*: How does summing squared projections onto learned directions approximate a full covariance-based distance?
- **Mini-batch attention pooling**: Approximating attention over a massive concatenated corpus using small batches. *Why needed*: Directly materializing the full ID corpus in memory is infeasible; this trick enables scalability. *Quick check*: What is the trade-off between computational overhead and memory savings when using mini-batches versus full concatenation?

## Architecture Onboarding
- **Component map**: Input sequence -> Frozen LM token embeddings -> Learnable query weights (multiple heads) -> Attention pooling module (AttPool) -> Per-head sequence representations -> Global prototype (via attention over concatenated ID corpus) -> Per-head squared distance -> Summed score -> Loss (unsupervised or supervised). Supervised branch: auxiliary OOD embeddings contribute to loss via cross-entropy-like term.
- **Critical path**: For a given sequence, extract token embeddings \(Z\). For each head \(j\), compute pooled representation \(\bar{z}_j = Z \text{ softmax}(\beta Z^T W_j)\) and prototype \(\mu_j = \tilde{Z} \text{ softmax}(\beta \tilde{Z}^T W_j)\) where \(\tilde{Z}\) is the concatenated ID corpus. Compute per-head squared distance \(d_j^2 = (\text{Tr}(W_j^T \bar{z}_j) - \text{Tr}(W_j^T \mu_j))^2\). Sum to get \(d^2\), then score \(s(Z) = -d^2 + \sum_j \log \|W_j\|_F^2\). During training, accumulate \(d^2\) over a batch, backpropagate to update \(W_j\) and \(\beta\).
- **Design tradeoffs**:
  - Memory vs. performance: Full attention over concatenated corpus \(\tilde{Z}\) is \(O(NS)\) memory; mini-batch approximation (Algorithm 2) reduces memory at slight computational overhead.
  - Parameter count: Intended \(M \cdot T = D\) to match Mahalanobis parameter count, but scaling up (e.g., \(M=1024, T=16\)) improved results, suggesting larger capacity helps.
  - Inverse temperature \(\beta\): Controls attention sharpness; tuned on validation. Too low → near-uniform pooling; too high → over-concentration.
  - Dot product vs. Euclidean: Paper uses dot product (aligning with Transformer attention); toy example uses Euclidean. Experiments show dot product far superior in high-D text settings.
- **Failure signatures**:
  - Overfitting: When \(T\) is large and \(M\) small, model may overfit to ID training data.
  - Underfitting: If \(M \cdot T\) too small, insufficient capacity to capture ID distribution.
  - AUX misalignment: Supervised variant degrades if auxiliary OOL distribution diverges from true OOD.
  - \(\beta=0\) collapse: Reduces to mean-pooling Mahalanobis, losing token-level sensitivity.
- **First 3 experiments**:
  1. **Toy experiment (Section 3, Figures 1–2)**: Synthetic 2D data with overlapping token means; mean pooling fails while attention pooling learns a discriminative direction.
  2. **Unsupervised benchmark on summarization (Section 3, Table 1)**: Train on 100k XSUM sequences; evaluate on four OOD datasets. AP-OOD achieves mean FPR95 4.67% vs. 27.84% for best baseline.
  3. **Semi-supervised scaling (Section 3, Figure 3)**: Vary AUX sample count (0–10k) on XSUM embeddings; AP-OOD’s AUROC increases monotonically and dominates competing methods.

## Open Questions the Paper Calls Out
- **Theoretical conditions**: What assumptions on token embedding distributions are necessary for AP-OOD’s score to provably separate ID and OOD sequences, and how robust is it to violations in real LLM embeddings?
- **Scaling to LLMs**: How does performance scale with model size and context length, and what are computational bottlenecks for billion-parameter models with 128k+ tokens?
- **Head interpretability**: Do different attention heads learn specialized, semantically meaningful detection patterns that could enable more interpretable or robust detectors?
- **Auxiliary data selection**: How does the choice of auxiliary outlier distribution affect generalization to unseen OOD types, and can AUX selection be optimized without OOD annotations?
- **Unification with generative uncertainty**: How does AP-OOD compare to recent uncertainty methods using LLM generative capabilities (e.g., semantic entropy), and can embedding-based and generative approaches be combined?

## Limitations
- Backbone training hyperparameters (e.g., PEGASUS fine-tuning details, Transformer base steps) are not fully specified.
- Data split definitions (which 100k ID samples, ID validation/test boundaries) and embedding extraction protocols (layer choice, encoder/decoder, special tokens) are unclear.
- Supervised hyperparameter \(\lambda\) per dataset is unreported; AUX data selection is noted as crucial but not systematically studied.
- Evaluation is limited to summarization (XSUM) and translation (WMT15 En-Fr); performance on other tasks, languages, or modern LLMs remains unknown.

## Confidence
- **Mechanism 1** (attention preserves anomalies): High – supported by toy experiment and consistent superiority over mean pooling.
- **Mechanism 2** (directional Mahalanobis): Medium – plausible theory but ablations on head count vs. capacity are limited.
- **Mechanism 3** (semi-supervised scaling): Medium – gains with more AUX samples shown, but boundary sensitivity to AUX quality not fully characterized.
- **Overall performance on XSUM**: High – large, consistent improvements across multiple OOD datasets.
- **Overall performance on WMT15**: Medium – improvement present but smaller relative gain; results may be less robust.

## Next Checks
1. Ablate the number of heads \(M\) and token dimension per head \(T\) independently, including cases where \(M \cdot T \neq D\), to isolate the effect of capacity from parameter parity with Mahalanobis.
2. Test sensitivity to embedding layer choice (early vs. late layers), use of encoder vs. decoder outputs, and inclusion/exclusion of special tokens across multiple backbone models.
3. Evaluate AP-OOD on diverse architectures (e.g., BERT, T5) and languages (e.g., Chinese summarization) to assess generalizability beyond the reported summarization and translation tasks.
