# Fast Flow Matching based Conditional Independence Tests for Causal Discovery

## Quick Facts
- ArXiv ID: 2602.08315
- Source URL: [https://arxiv.org/abs/2602.08315](https://arxiv.org/abs/2602.08315)
- Reference count: 40
- Primary result: FMCIT enables fast conditional independence testing via flow matching, achieving high power and controlled type‑I error; GPC‑FMCIT improves precision‑recall balance in causal discovery.

## Executive Summary
This paper introduces FMCIT, a novel conditional independence test that learns the joint distribution of variables once using flow matching and then performs fast conditional imputation for any CI query via Picard–RePaint sampling. Extensive experiments on post‑nonlinear SEMs show that FMCIT maintains a type‑I error around 0.05 and attains near‑perfect power even under high‑dimensional conditioning. To scale causal discovery, the authors propose GPC‑FMCIT, a guided PC skeleton learner that combines cheap FisherZ screening with a budgeted number of FMCIT refinements. On a Sachs flow‑cytometry dataset, FMCIT achieves the highest F1 score (0.784) while being substantially faster than kernel‑based competitors.

## Method Summary
FMCIT first trains a flow matching model to capture the full joint distribution over all observed variables. For a conditional independence test of \(X \perp Y \mid Z\), the method uses the trained flow to generate counterfactual samples under the null hypothesis via Picard–RePaint conditional imputation. These imputed samples, combined with the original data, yield a test statistic (e.g., distance correlation) and a p‑value. GPC‑FMCIT embeds this test into a PC‑style algorithm: it applies a linear FisherZ test to screen out many obvious independencies, then spends a limited budget of expensive FMCIT tests on remaining uncertain edges, providing an explicit bound on the number of CI queries and improving the precision‑recall trade‑off.

## Key Results
- FMCIT achieves type‑I error ≈0.05 and power near 1.0 on high‑dimensional post‑nonlinear SEMs (e.g., p=200, n=500).
- GPC‑FMCIT outperforms EPC‑ECIT and FisherZ‑PC in F1 (0.621 vs 0.594 and 0.583) on the same SEMs with moderate runtime (110.6 s).
- On the Sachs dataset, FMCIT attains F1=0.784 with a runtime (29 s) far below kernel‑based tests.

## Why This Works (Mechanism)
Flow matching provides a flexible, tractable model of the joint distribution that can be trained once and reused for many CI queries. Picard–RePaint leverages the learned flow for efficient conditional sampling without retraining, turning each CI test into a lightweight imputation step. This decoupling drastically reduces per‑query cost while preserving the ability to model complex, non‑linear dependencies. Moreover, the hybrid screening strategy in GPC‑FMCIT limits the number of expensive tests, keeping overall runtime moderate without sacrificing accuracy.

## Foundational Learning
- **Flow Matching**: Technique to train normalizing flows by matching a learned velocity field to the data distribution. *Why needed*: Offers an efficient way to model complex joint distributions with exact likelihoods and fast sampling. *Quick check*: Compare sample statistics (means, covariances) from the flow to those of the training set; they should align closely.
- **Picard–RePaint**: Conditional sampling method that iteratively refines samples by solving a stochastic differential equation backward in time using the flow. *Why needed*: Enables conditional imputation under the null without rebuilding the model for each query. *Quick check*: For a simple conditional distribution (e.g., bivariate Gaussian), verify that generated samples recover the conditional mean and variance.
- **Conditional Independence Test**: Statistical procedure to decide whether \(X\) and \(Y\) are independent given \(Z\). *Why needed*: Core primitive for constraint‑based causal discovery algorithms. *Quick check*: Apply the test to independent Gaussian variables; the rejection rate should match the nominal level (e.g., 5%).
- **PC Algorithm**: Classic constraint‑based causal discovery method that systematically tests conditional independencies to infer the skeleton and orient edges. *Why needed*: Provides a systematic framework for constructing causal graphs from CI tests. *Quick check*: Run PC on data generated from a known DAG with ample samples; it should recover the correct skeleton with high precision/recall.
- **FisherZ Test**: Fast CI test based on partial correlations for linear Gaussian data. *Why needed*: Serves as a cheap initial screen in GPC‑FMCIT to reduce the number of expensive non‑linear tests. *Quick check*: Compare FisherZ p‑values to known partial correlation values in a linear Gaussian setting.

## Architecture Onboarding
**Component map**:  
Data → Flow Training → CI Query (Conditioning → Picard–RePaint → Imputed samples → Statistic) → Decision.  
GPC‑FMCIT extension: Flow Training → FisherZ Screening → Budgeted FMCIT Refinement → Final Graph.

**Critical path**: Training the flow model is the most computationally intensive phase; after training, each CI test costs a number of Picard–RePaint steps. GPC‑FMCIT’s screening reduces the number of expensive FMCIT calls, shifting the bottleneck to the number of screening tests and the allocation budget.

**Design tradeoffs**:
- Flow capacity vs. overfitting: Larger networks capture complex dependencies but may overfit on limited data.
- Sampling steps vs. speed/accuracy: More Picard–RePaint steps improve conditional sample quality but increase per‑test latency.
- Budget size vs. discovery accuracy: A larger refinement budget improves graph recovery but raises total runtime.

**Failure signatures**:
- Type‑I error significantly above nominal suggests flow mis‑specification or insufficient sampling.
- Low power indicates the conditional imputer fails to capture the true conditional distribution.
- Excessive runtime points to either too many refinement queries or an inefficient flow implementation.
- Poor F1 in GPC‑FMCIT may arise from inappropriate budget allocation or screening thresholds.

**First experiments**:
1. **Sanity check**: Train FMCIT on linear Gaussian data (n=1000, p=10) and verify type‑I error control at α=0.05 for both unconditional and conditional tests.
2. **Imputation quality**: For a known post‑nonlinear SEM, compare conditional distributions from Picard–RePaint to the ground truth using KL divergence.
3. **End‑to‑end discovery**: Run GPC‑FMCIT on a small synthetic DAG (p=5) and evaluate skeleton precision/recall against the true graph.
