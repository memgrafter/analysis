# Neuromem: A Granular Decomposition of the Streaming Lifecycle in External Memory for LLMs

## Quick Facts
- **arXiv ID:** 2602.13967
- **Source URL:** https://arxiv.org/abs/2602.13967
- **Reference count:** 40
- **Primary result:** Neuromem decomposes external memory into five design dimensions and reveals that the underlying data structure sets an accuracy ceiling, aggressive semantic compression severely degrades performance, and generative steps impose a high latency tax with little gain.

## Executive Summary
Neuromem introduces a systematic framework for evaluating External Memory Modules (EMMs) under realistic streaming conditions where insertions and retrievals interleave. By decomposing the memory lifecycle into five design dimensions—data structure, normalization, consolidation, query formulation, and context integration—the authors isolate the accuracy and latency costs of each component. Evaluations on three benchmarks (LOCOMO, LONGMEMEVAL, MEMORYAGENTBENCH) show that performance degrades as memory accumulates (13–44% drop), with temporal queries being the hardest. The data structure choice fundamentally limits accuracy, while aggressive compression harms both accuracy and latency. Generative strategies like query decomposition add significant latency (>1 second) without meaningful accuracy improvements. In contrast, heuristic consolidation policies (e.g., heat-based migration) offer better efficiency for online streaming.

## Method Summary
The core contribution is a streaming evaluation protocol that treats memory operations as a chronological request stream. The authors implement a modular serving stack with interchangeable modules for each of the five design dimensions (D1–D5). The protocol processes events sequentially: for an INSERT, it applies normalization (PREINS), updates the data structure (D1), then consolidation (POSTINS); for a RETRIEVE, it formulates the query (PRERET), searches the current memory state, and integrates results (POSTRET). Evaluations run at fixed intervals (e.g., every 20% of the stream) to track performance evolution. Primary metrics are token-level F1 (with Porter stemming) for reasoning accuracy and insertion/retrieval latency in milliseconds. Experiments use `pangu-1b` on Huawei Ascend 910B and `Llama-3.1-8B` on Nvidia A6000. Controlled ablations fix all but one dimension to isolate effects.

## Key Results
- Memory accumulation degrades retrieval accuracy by 13–44%, with temporal queries showing the steepest decline.
- The data structure (e.g., hybrid Inverted+Vector) establishes an accuracy ceiling; aggressive semantic compression (e.g., triplet extraction) reduces F1 by over 50% while increasing insertion latency tenfold.
- Generative steps (query decomposition, multi-query fusion) impose a “latency tax” often exceeding one second with negligible or negative accuracy gains; heuristic policies like heat-based migration provide superior efficiency for streaming.

## Why This Works (Mechanism)
The five-dimensional decomposition isolates the contributions of each design decision, enabling precise attribution of accuracy and latency costs. By standardizing the streaming protocol and evaluation schedule, the paper ensures that comparisons across configurations reflect true online behavior rather than offline batch processing. The modular stack allows systematic ablation, revealing that the data structure’s retrieval capability fundamentally limits performance, while generative augmentations introduce overhead without commensurate benefits. Heuristic consolidation policies, which avoid expensive LLM calls, maintain efficiency under streaming constraints.

## Foundational Learning
- **Streaming evaluation protocol:** Interleaves insertions and retrievals to mimic real-time interaction. *Why needed:* Static, batched evaluations do not capture memory state evolution or temporal dependencies. *Quick check:* Confirm that for any query, only information from earlier inserts is accessible.
- **Memory lifecycle decomposition (D1–D5):** Splits memory processing into data structure, normalization, consolidation, query formulation, context integration. *Why needed:* Allows modular analysis and swapping of components. *Quick check:* Verify that varying one dimension while holding others constant changes only the intended aspect.
- **Token-level F1 with stemming:** Measures reasoning accuracy by comparing generated tokens to ground truth after normalization. *Why needed:* Captures partial matches and lexical variations common in long-form answers. *Quick check:* Ensure stemming is applied consistently across predictions and references.
- **Backpressure-controlled scheduling:** Processes events sequentially to enforce temporal causality. *Why needed:* Prevents future data from leaking into past queries. *Quick check:* Log max timestamp of retrieved contexts for each query; must be < query timestamp.
- **Latency breakdown:** Separates costs of memory operations from LLM generation. *Why needed:* Attributes overhead to the memory module itself. *Quick check:* Instrument code to time PREINS/POSTINS, PRERET/SEARCH/POSTRET independently.

## Architecture Onboarding
The Neuromem stack processes a chronologically ordered request stream `R`. The scheduler handles each event in order: for INSERTs, it runs PREINS (normalization), updates the data structure (D1), then POSTINS (consolidation). For RETRIEVEs, it executes PRERET (query formulation), performs a search on the current memory state `M(k*)`, and applies POSTRET (context integration). The memory state `M(k)` evolves incrementally; retrieval uses the state as of the query’s timestamp.

**Component map (plain text):** Request Stream -> Scheduler -> {INSERT: PREINS -> D1 Update -> POSTINS; RETRIEVE: PRERET -> D1 Search -> POSTRET} -> Results

**Critical path:** The end-to-end latency for an INSERT is the sum of PREINS, D1 update, and POSTINS times; for a RETRIEVE, it is PRERET + search(D1) + POSTRET. The scheduler ensures no overlap between operations on the same memory state.

**Design tradeoffs:** Accuracy vs. latency (e.g., richer normalization/consolidation improves recall but increases insertion time); data structure complexity vs. scalability (e.g., graph-based structures capture relations but incur high update costs); generative augmentation vs. responsiveness (e.g., query decomposition may improve multi-hop retrieval but adds >1s).

**Failure signatures:** (1) Temporal causality violation: any retrieved context has timestamp ≥ query timestamp. (2) Dimension leakage: an ablation intended to vary D1 also changes D2–D5 behavior. (3) Latency contamination: reported insertion/retrieval latencies include LLM generation time.

**First experiments:** (1) Run baseline evaluation on LOCOMO with all minimal modules (e.g., D1=Fifo Queue, D2=None, D3=None, D4=None, D5=Augment) to establish performance floor. (2) Perform systematic ablation: for each dimension, vary its implementation while fixing others to baseline, measure F1 and latency at checkpoints. (3) Conduct a latency breakdown: instrument each subcomponent and report average times per operation to identify bottlenecks.

## Open Questions the Paper Calls Out
1. **Can algorithmic innovations in incremental graph update mechanisms and asynchronous LLM extraction pipelines achieve sub-second insertion latency for graph-based memory systems under realistic streaming loads?**  
   *Basis:* The paper excludes HIPPORAG due to poor scaling; graph updates can take minutes to hours.  
   *Why unresolved:* Current approaches suffer quadratic growth and sequential LLM calls.  
   *Evidence needed:* Prototype with scalable updates and async extraction showing consistent sub-second latency as memory grows to thousands of interactions.

2. **What fundamental properties should a benchmark possess to enable granular evaluation of memory state evolution in streaming scenarios?**  
   *Basis:* Scarcity of datasets curated for dynamic memory evolution prevents monitoring intermediate states.  
   *Why unresolved:* Existing long-horizon benchmarks only provide final query-answer pairs, lacking per-operation state annotations.  
   *Evidence needed:* A new benchmark with fine-grained, time-stamped ground truth for expected memory contents after each update.

3. **What specific conditions determine whether generative query formulation or context integration strategies deliver sufficient accuracy gains to offset their latency tax?**  
   *Basis:* Generative steps inflate processing times by an order of magnitude with negligible or negative accuracy gains.  
   *Why unresolved:* Boundary conditions (query complexity, memory noise, model capability) are unknown.  
   *Evidence needed:* Controlled experiments varying query difficulty, memory quality, and backbone model size to find crossover points where generative intervention becomes beneficial.

4. **What formal definitions and implementation mechanisms can establish clear distinctions between working memory and long-term storage to enable effective hybrid consolidation policies?**  
   *Basis:* Absence of established definitions prevents application of hybrid consolidation strategies.  
   *Why unresolved:* Systems treat all information uniformly or use simplistic temporal thresholds.  
   *Evidence needed:* A theoretical framework defining memory tiers by operational characteristics (retention duration, access frequency, update rate) plus implementations showing tier-aware consolidation improves the accuracy-latency trade-off.

## Limitations
- **Unknown hyperparameters:** Exact thresholds for decay eviction, extraction limits, summarization models, and retrieval `top-k` are unreported, preventing precise replication of trade-offs.
- **Evaluation schedule ambiguity:** The phrase “fixed intervals (e.g., 20%)” lacks exact checkpoint counts/timestamps per dataset, risking misaligned degradation curve comparisons.
- **Implementation gaps:** API contracts for modular swapping (D1–D5) and state serialization are only pseudocoded; subtle integration bugs could invalidate ablation isolation.

## Confidence
- Degradation with memory accumulation & temporal query difficulty: High
- Data structure sets accuracy ceiling: High
- Aggressive compression harms accuracy/latency: Medium
- Generative steps impose “latency tax” with negligible gains: Medium
- Heuristic policies (e.g., heat-based migration) are efficient: Medium
