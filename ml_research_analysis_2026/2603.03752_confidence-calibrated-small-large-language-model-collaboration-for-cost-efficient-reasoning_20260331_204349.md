# Confidence-Calibrated Small-Large Language Model Collaboration for Cost-Efficient Reasoning

## Quick Facts
- **arXiv ID:** 2603.03752  
- **Source URL:** https://arxiv.org/abs/2603.03752  
- **Reference count:** 40  
- **Primary result:** COREA cascades a calibrated small language model with a large one, reducing inference cost by 21.5% on out-of-domain math datasets and 16.8% on non-math datasets while limiting the absolute pass@1 accuracy drop to within 2% compared to using the large model alone.

## Executive Summary
Large language models (LLMs) deliver strong reasoning capabilities but at high computational cost. This paper introduces COREA, a collaborative framework that routes queries from a small language model (SLM) to an LLM based on the SLM’s self‑assessed confidence. The SLM is trained with reinforcement learning to align its verbalized confidence (a number between 0 and 1) with actual accuracy, ensuring reliable deferral decisions. Experiments show that COREA achieves significant cost savings—up to 21.5% on math datasets—with minimal accuracy loss, while also improving the SLM’s calibration. The approach offers a practical path to cost‑efficient deployment of reasoning systems without sacrificing performance.

## Method Summary
COREA employs a two‑stage cascade. In the first stage, an SLM processes a query and generates a chain‑of‑thought, a final answer enclosed in `\boxed{}`, and a confidence score in `\confidence{}`. If the confidence meets or exceeds a threshold *T* (typically the baseline LLM’s pass@1 on the evaluation set), the SLM’s answer is returned; otherwise the query is forwarded to a more capable LLM. The SLM is fine‑tuned via Group Relative Policy Optimization (GRPO) using a composite reward: a binary correctness reward, a format reward to enforce the required output structure, and a confidence reward (e.g., L1 distance) that aligns the verbalized confidence with an estimated probability of correctness. This probability is computed from the group accuracy of *N* rollouts per question. The training objective simultaneously improves reasoning accuracy and confidence calibration. During deployment, a cost calculator accounts for token usage and model size disparity to measure savings.

## Key Results
- **Cost reduction:** COREA lowers average inference cost by 21.5% on out‑of‑domain math datasets (Math500, GSM8K, OlympiadBench) and by 16.8% on non‑math datasets (GPQA, CommonsenseQA) relative to using the LLM alone.
- **Accuracy preservation:** The absolute drop in pass@1 is kept within 2% across all evaluated datasets.
- **Calibration gain:** Reinforcement learning with confidence calibration (RLCC) reduces Expected Calibration Error (ECE) compared to RLVR alone, and verbalized confidence outperforms alternative confidence signals (AvgProb, Probe, Router) in the accuracy‑cost trade‑off.

## Why This Works (Mechanism)

### Mechanism 1: Confidence‑based routing reduces cost while maintaining accuracy
The system processes each query with an SLM instructed to output reasoning, an answer, and a confidence score. If confidence ≥ threshold *T*, the SLM’s answer is final; otherwise the query is deferred to an LLM. Cost savings arise from answering “easy” questions with the cheaper SLM. The key assumption is that the SLM’s verbalized confidence, after calibration, correlates with its actual probability of being correct.  
**Evidence anchors:**  
- [abstract] Reports 21.5% cost reduction on OOD math with <2% accuracy drop.  
- [section 3.1] Describes the cascade architecture and confidence instruction.  
- [corpus] Related work on SLM‑LLM routing exists, but COREA’s use of *calibrated verbalized confidence* is novel.  
**Break condition:** Poor calibration (high ECE) leads to misrouting—either excessive LLM usage (negating savings) or accuracy drops.

### Mechanism 2: RL with confidence calibration improves reasoning and alignment
During GRPO training, the reward combines correctness, format adherence, and a confidence term (e.g., `R_L1 = -|p̂ - y_c|`), where `p̂` is the group accuracy from *N* rollouts and `y_c` is the verbalized confidence. This encourages the SLM to output lower confidence when incorrect and higher when correct, simultaneously boosting reasoning skill and calibration.  
**Evidence anchors:**  
- [section 3.2] Defines the composite reward and group‑level `p̂` estimation.  
- [section 5.3] Shows RLCC‑trained models (e.g., L1‑SLM) have lower ECE than RLVR‑only models across datasets.  
- [corpus] Related work on confidence training uses different objectives (e.g., Brier score), but RL for calibration is shared.  
**Break condition:** Small rollout size *N* yields noisy `p̂`, destabilizing learning; L2 reward instability observed in experiments.

### Mechanism 3: Verbalized confidence is a viable, trainable self‑assessment signal
The SLM is prompted to generate `\boxed{answer}` followed by `\confidence{score}`. RL training shapes the model’s internal representations so that this textual score becomes predictive of correctness, eliminating the need for separate confidence probes or routers.  
**Evidence anchors:**  
- [section 3.1] Specifies the exact prompt format.  
- [section 5.2] Demonstrates that COREA (using the SLM’s own verbalized confidence) outperforms AvgProb, Probe, and Router baselines in the accuracy‑cost trade‑off.  
- [corpus] Works like “SaySelf” explore verbalized confidence but not within a cascading RL framework.  
**Break condition:** Failure to output a valid confidence (low `Confidence Output Ratio`) forces fallback to the LLM or causes failure.

## Architecture Onboarding
**Component map (plain text):**  
Training: DeepMath16K data → GRPO loop (sample N=8 rollouts per question) → compute group accuracy `p̂` → calculate reward `R` (correctness + format + confidence) → update SLM policy.  
Inference: New query → SLM generates (reasoning, answer, confidence) → if confidence ≥ T (threshold = Baseline LLM’s pass@1 on eval set) → output SLM answer; else → query LLM → output LLM answer.  
Cost Calculator tracks token counts and model‑size‑scaled costs for both models.

**Critical path:**  
1. **Training phase:** For each batch, sample *N* responses per question using current SLM. Compute `p̂`. Apply reward `R` to each response. Optimize SLM via GRPO with KL and entropy regularization. Repeat until convergence.  
2. **Deployment phase:** For a new query, run SLM inference, parse confidence `c`. If `c ≥ T`, return SLM answer; else run LLM inference and return its answer. Record accuracy and token counts for cost analysis.

**Design tradeoffs:**  
- **Threshold *T* vs. cost‑accuracy:** Higher *T* increases deferrals (higher cost, higher accuracy); tuning needed on a validation set.  
- **Rollout size *N*:** Larger *N* improves `p̂` accuracy but increases training compute/memory. Diminishing returns beyond *N=8*; *N=4* is acceptable.  
- **Confidence reward function:** L1 is recommended for stability and calibration; KL can be unstable; L2 showed high ECE; sample‑level rewards (e.g., `Sample_L1`) are theoretically improper but still effective.

**Failure signatures:**  
- **High ECE (>0.3) on validation:** Confidence poorly calibrated; check reward scaling, rollout size, training steps.  
- **Low `Confidence Output Ratio` (<90%):** SLM often fails required format; increase format reward weight or use few‑shot examples.  
- **Negative cost savings:** If `Avg Cost` > `Baseline LLM Cost`, the cascade is ineffective; likely due to *T* set too low or overconfident SLM on hard questions.  
- **Large OOD accuracy drop (>5%):** Potential overfitting; need more diverse training data or regularization.

**First 3 experiments:**  
1. **Baseline SLM capability & calibration check:** Run the untuned SLM (no RL) on `DeepMath500` with the confidence prompt. Measure Pass@1, ECE, and `Confidence Output Ratio`. Expect: low accuracy, very high ECE (>0.4), possibly low format adherence.  
2. **RLVR vs. RLCC comparison:** Train two SLMs: one with standard RLVR (only `R_correct`), one with RLCC (add L1 `R_confidence`). Evaluate both on `DeepMath500` for Pass@1 and ECE. Expect similar Pass@1 but RLCC has significantly lower ECE.  
3. **Threshold sweep and cost‑accuracy curve:** For the trained RLCC SLM, run inference on `DeepMath500` with confidence thresholds *T* ∈ [0.0, 1.0] in steps of 0.05. For each *T*, compute Pass@1 and Avg Cost. Plot the curve, identify the *T* that matches Baseline LLM’s Pass@1, and report the corresponding cost reduction.

## Open Questions the Paper Calls Out
**Open Question 1: How can verbalized confidence scores be made more continuous to enable smooth cost‑accuracy trade‑offs in COREA?**  
*Basis in paper:* [explicit] The authors state in Limitations that "the verbalized confidence score after training still tend to be discrete instead of continuous although the prompt instructs the model to output a continuous value in [0, 1]."  
*Why unresolved:* Discrete scores cause non‑smooth transitions when adjusting confidence thresholds, limiting fine‑grained control over cost and accuracy in deployment.  
*What evidence would resolve it:* Develop and evaluate techniques such as continuous token prediction or modified training objectives that enforce smooth confidence outputs, measuring improvements in calibration metrics (e.g., ECE) and threshold sensitivity across datasets.

**Open Question 2: What methods can ensure simultaneous convergence of all reward components in RL training for confidence calibration?**  
*Basis in paper:* [explicit] The authors note that "the model can still balance among different reward components even when the composite reward converges" and explicitly ask "how to ensure all components simultaneously converge is worth further study."  
*Why unresolved:* Instabilities in multi‑objective RL can lead to suboptimal confidence calibration or reasoning ability, affecting the reliability of deferral decisions and overall system performance.  
*What evidence would resolve it:* Investigate adaptive reward weighting, curriculum learning, or alternative RL algorithms, and demonstrate stable convergence and improved metrics (Pass@1, ECE) on multiple datasets with consistent training runs.

**Open Question 3: How does the parameter count disparity between SLM and LLM influence the cost‑efficiency and accuracy of collaborative reasoning systems like COREA?**  
*Basis in paper:* [explicit] The authors mention that "the parameter count disparity between the SLM and LLM has a significant impact on the cost gain" and admit they "did not extensively discuss different SLM and LLM combinations."  
*Why unresolved:* Current evaluations use limited pairings (e.g., 7B+32B); understanding scale effects is crucial for optimizing deployments with varying model sizes and cost structures.  
*What evidence would resolve it:* Conduct systematic experiments with diverse SLM‑LLM size ratios (e.g., 1B+70B, 13B+70B), analyzing cost‑accuracy trade‑offs using the defined cost model and identifying optimal pairing strategies for different budget constraints.

**Open Question 4: Why does confidence calibration degrade on out‑of‑domain datasets like GPQA, and how can it be improved?**  
*Basis in paper:* [inferred] From results, on GPQA, COREA shows a larger Pass@1 drop (–5.1%) compared to other datasets, attributed to "less well‑calibrated confidence scores," indicating poor generalization.  
*Why unresolved:* Poor calibration on challenging OOD tasks limits the reliability of deferral decisions, leading to higher costs or reduced accuracy when SLMs misjudge their capabilities.  
*What evidence would resolve it:* Analyze calibration errors on GPQA and similar datasets (e.g., via reliability diagrams), test domain adaptation or robust calibration methods (e.g., temperature scaling, ensemble approaches), and measure improvements in ECE and system cost under OOD settings.

## Limitations
- Underspecified implementation details: the exact prompt template, few‑shot examples, and the formulation of the format reward `R_format` are not fully described, hindering exact replication.
- The GRPO algorithm specifics (e.g., baseline network, GAE parameters) and the referenced `SimpleRL-reason` code are unavailable, requiring assumptions for reproduction.
- Cost‑saving claims rely on empirical token counts that are not reported; additionally, verbalized confidence often remains discrete and may not generalize to out‑of‑domain tasks, with the confidence output ratio occasionally below 100%.
