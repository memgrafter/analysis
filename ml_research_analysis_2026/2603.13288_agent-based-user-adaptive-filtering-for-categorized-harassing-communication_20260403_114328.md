# Agent-Based User-Adaptive Filtering for Categorized Harassing Communication

## Quick Facts
- **arXiv ID:** 2603.13288  
- **Source URL:** https://arxiv.org/abs/2603.13288  
- **Reference Count:** 40  
- **Primary Result:** Personalized adaptive agents trained on individual user feedback significantly outperform both a general population-level classifier and a user's majority-vote baseline in predicting filtering choices for categorized harassing tweets.

## Executive Summary
This paper tackles the limitation of uniform content moderation by proposing agent-based personalized filtering. The core idea is that users vary widely in their tolerance for different categories and intensities of harassment (e.g., threats vs. insults), so a one-size-fits-all filter misaligns with many individuals' preferences. The authors built a crowdsourced dataset of 5,231 tweets and collected over 26,000 filtering decisions from approximately 360 users. Statistical analysis confirmed significant variability in user perceptions across harassment categories and intensities. They then trained per-user classifiers (Naive Bayes, SVM, Random Forest) on individual feedback and demonstrated that these personalized agents consistently achieved higher accuracy in predicting that user's future filtering choices compared to a filter trained on aggregated population data. The results validate that adaptive personalization can better respect individual preferences in harassment moderation.

## Method Summary
The study uses a two-phase approach. First, a dataset of tweets was manually categorized into a taxonomy of seven harassment types plus non-harassment. Crowdsourced workers (simulating users) then rated each tweet for harassment intensity and indicated whether they would filter it. This yielded a matrix of user-tweet filtering decisions. Second, for each simulated user, the authors trained supervised binary classifiers (Naive Bayes, SVM, Random Forest) on that user's subset of decisions, using tweet features derived from TF-IDF text representations and category labels. They evaluated these personalized models against a general classifier trained on majority-vote labels from all users and against a trivial majority baseline per user, using 10-fold cross-validation per user. Statistical tests (ANOVA, Tukey HSD, Wilcoxon Signed-Rank) were employed to validate the significance of user variability and performance differences.

## Key Results
- Statistical tests (ANOVA, Tukey HSD) show highly significant variability in user filtering choices based on harassment category and intensity, with intensity alone having a very large effect size (η² = 0.972).
- Personalized agent-based filters (Naive Bayes, SVM, Random Forest) consistently outperformed the general population-level classifier in accuracy for the majority of individual users.
- The Naive Bayes agent significantly outperformed the user-specific majority-vote baseline (Wilcoxon test), demonstrating value beyond a simple heuristic.

## Why This Works (Mechanism)

### Mechanism 1: Personalization is Necessary Due to Significant Inter-User Variability
- **Claim:** A uniform global filter fails because user perceptions of harassment vary significantly across categories and intensities.
- **Mechanism:** The observed statistical variability in user responses to identical tweets indicates that individual tolerance thresholds differ. An agent trained on a specific user's feedback can internally model that user's unique decision boundaries for different harassment types.
- **Core Assumption:** Individual filtering preferences are sufficiently stable and systematic (not random) to be learnable from a relatively small set of labeled examples (~60 tweets per user).
- **Evidence Anchors:** [abstract] "statistical tests confirmed significant variability..."; [section 5] ANOVA, Tukey HSD, Confidence Interval Coefficient tests; [section 5.1.1] η² = 0.972 for intensity effect.
- **Break Condition:** If a user's preferences are highly inconsistent over short timeframes (high intra-user variance), a model trained on past feedback would fail to predict future choices.

### Mechanism 2: Personalized Agents Learn Individual Decision Boundaries
- **Claim:** A classifier trained on an individual's explicit feedback more accurately predicts that user's future filtering decisions than a model trained on aggregated population data.
- **Mechanism:** Supervised classifiers (NB, SVM, RF) learn a mapping from tweet features (text, category) to the specific user's binary filtering choice, capturing their personal tolerance profile.
- **Core Assumption:** The mapping from tweet features to a user's filtering choice is learnable and that the "true" preference label (from the user's action) is observable and stable enough for training.
- **Evidence Anchors:** [abstract] "personalized agent-based filters... consistently outperformed a general population-level classifier"; [section 6.2] Figure 7 shows personalized accuracy exceeding general for most users; [section 6.3] Wilcoxon test shows NB agent significantly beats user majority baseline.
- **Break Condition:** If user feedback is noisy/deceptive or if the feature representation (e.g., bag-of-words) cannot capture the semantic nuances driving the user's decision, model performance degrades.

### Mechanism 3: Categorical Disambiguation Enables Nuanced Personalization
- **Claim:** Disambiguating harassment into fine-grained categories (e.g., threats vs. insults) is essential for effective personalization, as tolerance varies by category type.
- **Mechanism:** The taxonomy provides a structured label space, allowing an agent to learn category-specific thresholds (e.g., "filter all threats but only extreme insults") rather than a single global aggression threshold.
- **Core Assumption:** The defined categories are psychometrically valid and meaningful to users, such that category membership reliably influences tolerance.
- **Evidence Anchors:** [section 2] Taxonomy grounded in psychological literature; [section 5] Confidence Interval Coefficient analysis shows filtering rates differ significantly across categories at the same intensity level.
- **Break Condition:** If category labels are unreliable (low inter-annotator agreement) or if users do not perceive or reason in terms of these discrete categories, learning category-specific preferences becomes meaningless.

## Foundational Learning
- **Concept:** Supervised Classification (Naive Bayes, SVM, Random Forest)
  - **Why needed:** To learn a mapping from tweet features to an individual user's binary filtering choice, building the per-user predictive model.
  - **Quick check:** How would you structurally represent a tweet's features (e.g., TF-IDF vectors) and a user's filtering label to train a Naive Bayes classifier for that user?
- **Concept:** Statistical Hypothesis Testing (ANOVA, Tukey HSD, Wilcoxon Signed-Rank)
  - **Why needed:** To rigorously prove that user variability is not due to chance (Mechanism 1) and that performance differences between filter types are statistically significant (Mechanism 2).
  - **Quick check:** What does a significant ANOVA result on intensity levels tell us about user behavior, and why is a follow-up Tukey test necessary?
- **Concept:** Crowdsourced Ground Truth Collection
  - **Why needed:** The study lacks longitudinal individual user data; it uses MTurk to simulate multiple users' reactions to a fixed tweet set, creating a large dataset for analyzing variability and training per-user agents.
  - **Quick check:** What are key methodological limitations of using MTurk workers as proxies for real social network users, and how might that affect the validity of the learned agent models?

## Architecture Onboarding
- **Component map:** Social Media Platform Source (Twitter API) -> Pre-processor & Featurizer -> User Profile Store (holds per-user classifier models) -> Adaptive Agent (the classifier for a specific user) -> Feedback Loop Interface (captures user actions) -> Filtering Decision Engine (applies agent to new tweets).
- **Critical path:** A new tweet arrives -> is featurized -> the user's adaptive agent scores it -> if the score exceeds the user's implicit threshold, the tweet is filtered/flagged -> the user sees the result and may provide explicit feedback (e.g., "undo") -> this feedback is stored and periodically used to retrain/update that user's agent model.
- **Design tradeoffs:** 
  - *Personalization vs. Cold Start:* New users have no feedback, requiring a fallback to a general model or simple rule. Performance improves with more interaction data.
  - *Computational Cost vs. Granularity:* Maintaining a separate model per user is resource-intensive versus a single global model; future work considers user clustering to reduce model count.
  - *Feature Representation vs. Scalability:* Rich features (e.g., embeddings) may boost accuracy but increase storage/processing per user; the paper uses simpler TF-IDF/category features.
- **Failure signatures:**
  - *High False Positive Rate for Sensitive Users:* Agent frequently filters tweets the user would accept, signaled by frequent user overrides ("show this"). Likely cause: insufficient/noisy training data for that user.
  - *Low Discriminatory Power for Middle-Tolerance Users:* Agent accuracy hovers near 50% for users with moderate filtering rates (Figure 7 V-shape trough). Likely cause: user preferences are genuinely ambiguous or context-dependent, not learnable from text alone.
  - *Concept Drift:* User's tolerance changes over time, but the static agent is not updated. Symptom: increasing mismatch between filtered content and user preferences. Requires continuous learning.
- **First 3 experiments:**
  1. **Replicate Statistical Variability Analysis:** Using the provided dataset and responses, reproduce ANOVA and Tukey HSD tests to confirm significance of category and intensity on filtering choices.
  2. **Train & Compare General vs. Personalized Models:** For each simulated user, hold out their last 10-15 labels as a test set. Train a general model on all *other* users' data and a personalized model on that user's first ~50 labels. Compare test-set accuracy.
  3. **Evaluate Against Majority Baseline & Test Significance:** For each user, compute accuracy of a trivial "majority" classifier (always predict the user's most frequent choice). Compare the personalized model's accuracy to this baseline using the Wilcoxon Signed-Rank Test.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can unsupervised clustering of users with similar harassment tolerance profiles reduce the computational overhead of maintaining per-user adaptive agents?
- **Open Question 2:** What algorithmic approaches enable adaptive agents to detect and adjust to temporal shifts in a user's harassment perception and filtering preferences?
- **Open Question 3:** To what extent does the limited per-user training data (average ~60 labeled tweets) constrain the performance and robustness of personalized filters, and can techniques like data augmentation or meta-learning overcome this?
- **Open Question 4:** Do demographic and psychographic user attributes correlate with distinct harassment tolerance clusters, and can incorporating such features improve the accuracy of user grouping and filter personalization?

## Limitations
- Key methodological details missing (e.g., exact keyword queries, feature extraction parameters, tweet assignment strategy to users).
- Use of MTurk workers as proxies for real users limits generalizability; actual user preferences may be less stable.
- Small per-user sample size (~60 labels) risks overfitting and may not reflect real-world data sparsity.

## Confidence
- **Claim 1 (User variability across categories/intensities is significant):** High. Strongly supported by large-effect-size ANOVA and Tukey HSD tests.
- **Claim 2 (Personalized agents outperform global/majority baselines):** Medium. Significant gains shown in cross-validation, but constrained by simulated MTurk data and small per-user samples.
- **Claim 3 (Categorical disambiguation is necessary for personalization):** Medium. Evidence of category-wise differences exists, but category validity and user alignment are not fully established.
