# SeeUPO: Sequence-Level Agentic-RL with Convergence Guarantees

## Quick Facts
*   **arXiv ID:** 2602.06554
*   **Source URL:** https://arxiv.org/abs/2602.06554
*   **Reference Count:** 40
*   **Primary Result:** A critic-free RL algorithm for multi-turn LLM agents that guarantees convergence to the global optimum via backward induction, achieving 24%-55% relative gains on agentic benchmarks with superior training stability.

## Executive Summary
Training LLM agents for multi-turn tasks via reinforcement learning (RL) suffers from a lack of convergence guarantees and training instability. SeeUPO addresses this by reformulating the problem as a sequentially-executed multi-agent bandit. It updates each turn's policy in reverse order (last to first), treating later turns as fixed "agents" providing optimal continuation values. This enables the application of Heterogeneous-Agent Mirror Learning theory, ensuring monotonic improvement and convergence to the globally optimal policy. The method uses a critic-free group-relative advantage estimator with batch-level normalization, avoiding value network bias. Experiments on AppWorld and BFCL v4 with 14B Qwen models show large performance gains and robust training, avoiding the catastrophic failures common in baselines like PPO and GRPO.

## Method Summary
SeeUPO transforms multi-turn RL into a contextual bandit problem over the full trajectory. For a task of *T* turns, it treats each turn *t* as a distinct virtual agent sharing the initial state *s₀* and the final joint reward. Training proceeds in iterations. First, *G* trajectories are sampled for each of *B* initial states. A global advantage for each full trajectory is computed as its reward minus the group mean reward for that initial state (GRAE), then batch-normalized. The policies for each turn are updated sequentially in reverse order (*t = T, T-1, ..., 1*). When updating turn *t*, the policies for turns *t+1* to *T* are already fixed to their latest values. The update uses a PPO-style clipped surrogate objective where the advantage surrogate *M_t* is constructed by recursively multiplying importance ratios from turn *t* onward with the final global advantage. This process guarantees that each update optimizes against an already-optimal continuation, leading to global optimality via backward induction.

## Key Results
*   On Qwen3-14B, SeeUPO achieves relative gains of 43.3%-54.6% on AppWorld/BFCL v4 compared to baselines.
*   On Qwen2.5-14B, it achieves relative gains of 24.1%-41.9% on the same benchmarks.
*   Training is exceptionally stable, completely avoiding the catastrophic performance collapses observed in PPO, GRPO, and GSPO.

## Why This Works (Mechanism)

### Mechanism 1: Multi-Agent Abstraction of Turns
*   **Claim:** Modeling each turn as a virtual agent transforms multi-turn RL into a sequentially-executed multi-agent bandit problem, enabling application of MARL convergence theory.
*   **Mechanism:** SeeUPO maps turn *t* to virtual agent *t*, sharing the initial state *s₀* and joint reward. Policies are updated sequentially rather than jointly, turning a single policy optimization into a sequence of single-agent updates with fixed subsequent policies.
*   **Break condition:** If turns are not sequentially dependent (e.g., parallel decisions), the agent abstraction fails to enforce execution order, breaking backward induction and global optimality guarantees.

### Mechanism 2: Reverse-Order Sequential Updates
*   **Claim:** Updating policies in reverse execution order (T → T−1 → … → 1) enables backward induction, ensuring each turn optimizes against already-optimal continuation values, guaranteeing convergence to the global optimum.
*   **Mechanism:** At iteration *k*, updates are performed turn-by-turn backward. When updating turn *t*, policies of later turns (*t*+1…T) are already updated to their latest values, effectively providing the optimal continuation value *V⁎*. This makes the fixed-point condition of the HAML update equivalent to global optimality via backward induction.
*   **Break condition:** Non-reverse orders (natural or random) break the backward induction guarantee; natural order may only converge to a local optimum relative to the current continuation value.

### Mechanism 3: Critic-Free Advantage Estimation via GRAE with Batch Normalization
*   **Claim:** Group-relative advantage estimation combined with batch-level normalization provides unbiased advantage estimates in the bandit setting while preserving the drift functional needed for convergence, avoiding the structural bias that plagues GRAE-PPU in MDPs.
*   **Mechanism:** For each initial state *s₀*, sample *G* joint trajectories; advantage = *r*(*s₀, a₁:T*) − mean_{*G*}(*r*). In the bandit model, there are no state transitions, so *V*(*s₀*) is the true value and the group mean is an unbiased Monte Carlo estimator. Batch-level normalization divides by a constant, leaving the argmax of the clipped objective unchanged.
*   **Break condition:** If the environment has significant state transitions (non-bandit), GRAE becomes structurally biased. If normalization is state-dependent (group-level), the drift functional changes, violating Mirror Learning conditions.

## Foundational Learning
### Concept: Mirror Learning Framework
*   **Why needed here:** SeeUPO inherits convergence from HAML, which extends Mirror Learning. Mirror Learning formalizes policy update as maximizing a mirror operator combining advantage and drift, guaranteeing monotonic improvement if drift/neighborhood satisfy specific conditions.
*   **Quick check:** What two properties must the drift function satisfy? (Nonnegativity: *D*(*π̃|s*) ≥ 0 with equality at *π̃*=*π*; Zero gradient: ∇*̃π D*(*π̃|s*)|_{*π̃*=*π*} = 0.)

### Concept: Heterogeneous-Agent Mirror Learning (HAML)
*   **Why needed here:** SeeUPO’s turn-updates are an instance of HAML with a fixed reverse order instead of random. HAML decomposes joint advantage into per-agent contributions and proves sequential updates with valid drift yield monotonic improvement.
*   **Quick check:** In standard HAML, what update order is assumed for convergence to Nash equilibrium? (Random permutation at each iteration. SeeUPO’s reverse order exploits the fixed sequential execution structure to get global optimality without random permutations.)

### Concept: Sequence-Level vs Token-Level RL Modeling
*   **Why needed here:** SeeUPO operates at the sequence level, treating each turn as a single action. This makes the multi-turn problem a contextual bandit rather than a token-level MDP with non-deterministic transitions, enabling unbiased advantage estimation and simpler credit assignment.
*   **Quick check:** How does token-level RL model state transition for multi-turn interactions? (By concatenating environment feedback and prior tokens to the state, making transitions non-deterministic and credit assignment across tokens difficult.)

## Architecture Onboarding
### Component map
Input Trajectories -> Build Turn-Oriented Sample Pools (D_1...D_T) -> Compute Global Advantage (GRAE + BatchNorm) -> Initialize M_{T+1} -> Reverse Update Engine (t=T..1: Compute M_t, Update θ_t) -> Updated Policies (θ_1...θ_T)

### Critical path
1.  **Data collection:** For *B* initial states, sample *G* trajectories → obtain (*s₀*, *a₁:T*, *r*) tuples.
2.  **Build turn pools:** For each turn *t*, extract samples (*s₀*, *a₁:t−1*, *a_t*) from trajectories into pool *D_t*.
3.  **Compute global advantage:** For each trajectory, *Â = r − mean_{group}(r)* → initialize *M_{T+1}*.
4.  **Reverse update:** For *t = T downto 1*: compute *M_t* (Eq. 8), perform gradient step on *θ_t* using Eq. 6; if *t>1*, store updated *M_t* for next batch (forward pass on next *t*); else set final *θ_{k+1} = θ_1*.
5.  **Iterate:** Repeat steps 1–4 for *K* iterations.

### Design tradeoffs
*   **Critic-free vs convergence:** GRAE removes need for a value network but requires bandit assumption and batch normalization; otherwise bias breaks convergence.
*   **Turn-oriented batching vs memory efficiency:** Separate pools simplify sequential updates but duplicate storage of *s₀* and history; for long dialogues, padding/placeholders needed.
*   **Batch-level vs group-level normalization:** Batch-level uses single constants per global batch, preserving argmax and drift; group-level scales per *s₀*, introducing state-dependent factors that violate drift nonnegativity (Theorem 9).

### Failure signatures
*   **Catastrophic collapse:** Success rate drops to near zero early in training, accompanied by loss spikes. Likely causes: too small *G* (high variance in *Â*), or incorrect turn-pool construction (mismatched actions).
*   **Gradient explosion/vanishing:** Training becomes NaN or stalls; check *M_t* magnitude across turns. Explosion indicates *Â* scale too large; vanishing suggests poor reward shaping.
*   **Poor turn-level credit assignment:** Early turns show no improvement while late turns improve; verify *M_t* properly incorporates importance ratios from later turns (Eq. 8). If missing, turns only optimize their immediate return, not global.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** Does parameter sharing in SeeUPO violate the heterogeneity assumption of HAML, and would explicit turn-specific parameterization improve performance or theoretical guarantees?
*   **Basis in paper:** [explicit] "Future work could explore explicit turn-specific parameterization to better satisfy the heterogeneity assumption."
*   **Why unresolved:** The current implementation uses shared parameters; it is unclear whether the large parameter space inherently yields functionally distinct policies per turn.
*   **What evidence would resolve it:** Compare SeeUPO with turn-specific modules (e.g., separate LoRA adapters) against the shared-parameter version on multi-turn benchmarks, measuring policy divergence and task success.

### Open Question 2
*   **Question:** Can SeeUPO's sequence-level RL approach be effectively transferred to alternative LLM training paradigms beyond next-token prediction, such as multi-token or diffusion-based models?
*   **Basis in paper:** [explicit] "This approach may have potential applications in alternative paradigms such as multi-token/sentence prediction or rectified flow diffusion architectures, which could be explored in future research."
*   **Why unresolved:** The paper's formulation assumes next-token prediction; other paradigms involve different action spaces and credit assignment mechanisms that may affect convergence.
*   **What evidence would resolve it:** Implement SeeUPO within a multi-token prediction framework or a diffusion-based decoder and evaluate convergence guarantees and task performance on agentic benchmarks.

### Open Question 3
*   **Question:** Does the reverse update order guarantee global optimality in more general multi-turn settings with stochastic environment state transitions or partial observability?
*   **Basis in paper:** [inferred] The theory assumes a contextual bandit structure ("sequentially-executed multi-agent single-turn bandit problems") with no explicit state dynamics; real agentic environments often have stateful transitions.
*   **Why unresolved:** Theorem 2 requires the absence of state transitions; extending the backward induction argument to MDPs with stochastic transitions remains an open theoretical challenge.
*   **What evidence would resolve it:** Extend the HAML analysis to include explicit state transitions, then empirically test SeeUPO in environments with stochastic dynamics or POMDPs, comparing to methods that model state.

### Open Question 4
*   **Question:** How does SeeUPO's sample efficiency compare to critic-dependent methods under realistic conditions where value function approximation is imperfect?
*   **Basis in paper:** [inferred] The paper highlights critic-free benefits but does not analyze sample complexity; the theoretical guarantee of GAE-PPU assumes perfect value functions, while SeeUPO avoids this but may require more rollouts.
*   **Why unresolved:** The trade-off between computational overhead and sample efficiency is not quantified in terms of number of environment interactions needed for convergence.
*   **What evidence would resolve it:** Run controlled experiments varying the number of rollouts per update step, measuring training time versus total samples to reach a target performance, and compare with PPO under similar constraints.

## Limitations
*   Theoretical guarantees strictly require the bandit assumption (no state transitions) and batch-level normalization; applicability to general MDPs remains unvalidated.
*   Empirical gains are reported only on two benchmarks with specific models (Qwen2.5/3-14B); generalizability to other architectures/tasks is unknown.
*   Implementation details in veRL and full hyperparameters are underspecified, hindering exact reproduction.

## Confidence
*   **Performance gains (43–54% on Qwen3):** High (internal experiments, but external reproducibility uncertain).
*   **Convergence guarantees via backward induction:** Medium (theorem depends on strict assumptions; limited external anchors in corpus).
*   **Stability vs. baselines:** Medium (supported by figures, but catastrophic failure modes of baselines may be environment-specific).
