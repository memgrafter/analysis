# DeepContext: Stateful Real-Time Detection of Multi-Turn Adversarial Intent Drift in LLMs

## Quick Facts
*   **arXiv ID:** 2602.16935
*   **Source URL:** https://arxiv.org/abs/2602.16935
*   **Reference Count:** 40
*   **Primary Result:** Achieves state-of-the-art F1 score (0.84) for multi-turn jailbreak detection with sub-20ms inference latency, significantly outperforming stateless guardrails (F1 ~0.67).

## Executive Summary
DeepContext addresses a critical "Safety Gap" where existing LLM guardrails, which are inherently stateless, fail to detect sophisticated multi-turn adversarial attacks (e.g., Crescendo). These attacks incrementally "groom" the model across a conversation, with no single turn being overtly malicious. The proposed solution is a stateful monitoring framework that tracks the temporal trajectory of user intent using a Gated Recurrent Unit (GRU). Each user utterance is encoded via a fine-tuned BERT model with task-specific attention weighting. The resulting embedding updates a persistent GRU hidden state, which is combined with the current turn's embedding via a residual connection for a final safety classification. This design enables early detection of intent drift while maintaining production-grade computational efficiency.

## Method Summary
DeepContext reformulates safety detection as a state-space problem. For each conversational turn `t`, the user utterance (and optionally the prior assistant response) is processed by a fine-tuned BERT encoder. A learned task-attention mechanism then produces a compact, safety-optimized embedding `e_t` by weighting relevant token features. This embedding is fed into a 3-layer GRU, which updates its persistent hidden state `h_t` to synthesize the cumulative conversational history. The GRU's projected state `ϕ(h_t)` is concatenated with the current turn's `e_t` to form a hybrid risk vector `R_t`. This vector, containing both long-term memory and immediate semantic signal, is passed through a multi-layer perceptron (MLP) with LayerNorm and GELU activations to produce a final harm probability `y_t`. The model is trained end-to-end with a Binary Cross-Entropy and Focal loss.

## Key Results
*   **State-of-the-Art Detection:** Achieves an F1 score of **0.84** on multi-turn jailbreak benchmarks, substantially outperforming leading stateless guardrails like Llama-Prompt-Guard-2 and Granite-Guardian (both ~0.67).
*   **Early Threat Identification:** Detects adversarial intent after a mean of **4.24 turns**, enabling intervention before a final policy violation occurs.
*   **Computational Efficiency:** Maintains a **sub-20ms inference latency** on a T4 GPU, demonstrating that stateful modeling can be viable for real-time production deployments.

## Why This Works (Mechanism)

### Mechanism 1: Persistent State for Intent Drift
*   **Claim:** A recurrent hidden state allows detection of incremental adversarial "intent drift" across turns that stateless models miss.
*   **Mechanism:** The GRU maintains and updates a persistent hidden state `h_t` with each turn's embedding `e_t`. This state acts as a latent summary of the conversation's trajectory, enabling the model to recognize when a sequence of individually benign-looking queries collectively constitutes a policy violation.
*   **Core Assumption:** Multi-turn attacks like Crescendo create a detectable, low-risk gradient over time, rather than a single high-risk turn.
*   **Evidence Anchors:** [abstract] states the framework uses a GRU to track "the temporal trajectory of user intent." [section 3.1] explicitly "reformulate[s] safety detection as a state-space problem."
*   **Break Condition:** The mechanism fails if adversarial intent can be introduced in a single, high-risk turn without preceding context, or if an attack maintains a constant, undetectably low-risk profile per turn without cumulative signaling.

### Mechanism 2: Task-Attention for Turn-Level Signal
*   **Claim:** Task-attention weighted BERT embeddings provide a high-fidelity, safety-oriented semantic signal per turn that is efficient for recurrent processing.
*   **Mechanism:** After BERT encoding, a task-specific attention mechanism learns to weigh token embeddings, amplifying features most relevant to safety policies (e.g., prompt injection markers). This produces a fixed-size `e_t` vector optimized for the safety task.
*   **Core Assumption:** A smaller, task-optimized embedding contains sufficient safety-relevant signal for the GRU to track intent drift, avoiding the cost of full-text re-processing.
*   **Evidence Anchors:** [section 3.2.1] describes the Task-Attention mechanism producing a weighted embedding. [section 3.2.2] links this lean embedding design to the achieved sub-20ms latency.
*   **Break Condition:** The signal is insufficient if the safety-relevant context is highly distributed across long texts or relies on subtle patterns not captured by BERT's fine-tuning.

### Mechanism 3: Hybrid Residual for Dual-Perspective Detection
*   **Claim:** A hybrid residual architecture combining the recurrent state (`h_t`) and the current turn's raw embedding (`e_t`) enables detection of both "slow-burn" multi-turn drift and sudden single-turn violations.
*   **Mechanism:** The GRU's projected state `ϕ(h_t)` is concatenated with the current turn's `e_t` to form `R_t`. This provides the classifier with both long-term contextual memory and immediate, high-precision semantic features.
*   **Core Assumption:** The optimal representation for multi-turn safety is a dual-perspective vector that separates (but combines) temporal accumulation from instantaneous content.
*   **Evidence Anchors:** [section 3.2.3] states this combination achieves robustness against both "slow-burn" grooming and sudden injections. [section 4.4] shows strong single-turn performance (F1 0.98), validating the instantaneous detection path.
*   **Break Condition:** The design is suboptimal if the optimal decision requires an inseparable fusion of history and current context, or if the residual path introduces detrimental noise.

## Foundational Learning
*   **Concept: Recurrent Neural Networks (GRUs)**
    *   **Why needed:** The entire stateful mechanism depends on understanding how a GRU updates its hidden state `h_t` based on input `e_t` and previous state `h_{t-1}`, specifically how the update and reset gates manage forgetting and retaining relevant adversarial signal over time.
    *   **Quick Check:** "In a GRU, what is the functional difference between the update gate `z_t` and the reset gate `r_t` in the context of tracking incremental adversarial intent?"
*   **Concept: Task-Attention / Weighted Pooling**
    *   **Why needed:** The quality of the turn-level embedding `e_t` is critical. Understanding how post-encoder attention weights are learned and applied to specific tokens explains why the signal is "high-fidelity" and safety-focused.
    *   **Quick Check:** "How does a task-attention mechanism (applied after Transformer encoding) differ from the self-attention within the Transformer, and why is this separation beneficial for a real-time safety monitor?"
*   **Concept: State-Space Formulation of Security**
    *   **Why needed:** The paper's core innovation is reframing the problem from a stateless classifier `f(u_t)` to a state estimator that maintains a hidden representation `h_t`. Grasping this shift is fundamental.
    *   **Quick Check:** "What does the hidden state `h_t` *represent* in the DeepContext framework: a summary of past text, a probability of harm, or an abstract 'intent drift' vector?"

## Architecture Onboarding
*   **Component Map:**
    Raw Utterance `u_t` → BERT Encoder (fine-tuned) → Task-Attention Pooling → Turn Embedding `e_t` (1024D) → 3-Layer GRU (hidden 2048D) → Updated Hidden State `h_t` → Linear Projection `ϕ(h_t)` (1024D) → Concatenation with `e_t` → Risk Vector `R_t` (5120D) → MLP (LN → Linear→GELU→Linear) → Sigmoid Output `y_t`
*   **Critical Path:** The persistent memory flows through the GRU state `h_t`. The critical computation per turn is: `e_t`(from BERT+Attention) → GRU Update → `h_t` → `ϕ(h_t) + e_t` → `R_t` → `y_t`. `h_t` is carried forward to the next turn.
*   **Design Tradeoffs:**
    *   **GRU vs. LSTM:** GRU chosen for ~25% fewer parameters/FLOPs to meet the sub-20ms latency target. Trade-off: potentially less capability for very long-range dependencies than a deep LSTM, but deemed sufficient for typical attack lengths.
    *   **Residual Concatenation vs. Addition:** Concatenation `[ϕ(h_t); e_t]` preserves independent information streams. Addition would force them into the same feature space, risking signal interference. Trade-off: larger `R_t` dimension increases classifier parameters.
    *   **Single Epoch Training:** Prevents overfitting to specific attack phrases in the training data, promoting generalization to novel drift. Trade-off: may underfit on complex, nuanced attack patterns.
*   **Failure Signatures:**
    *   **High Mean Turns to Detection (MTTD > 6):** GRU state is not accumulating adversarial signal. Possible causes: weak `e_t` embeddings, poor GRU initialization, or excessive dropout.
    *   **High False Positive Rate on Function-Calling Data:** Task-attention is over-indexing on code-like syntax or tool-use terminology as adversarial, failing to disentangle benign functional intent.
    *   **Collapse to Stateless Performance (F1 near baselines):** The classifier is ignoring `h_t`. Likely causes: broken gradient flow from `R_t` through the MLP to the GRU, or a degenerated GRU state (e.g., all zeros).
*   **First 3 Experiments:**
    1.  **Single-Turn Sanity Check:** Freeze the GRU (set `h_0=0` and disable updates). Evaluate on a single-turn benchmark like JailBreakBench. Expected: F1 ~0.98, confirming the `e_t` + MLP path alone is a competent stateless guardrail.
    2.  **Synthetic Drift Test:** Craft a simple 3-turn Crescendo-style attack (e.g., benign -> probing -> synthesis request). Run with GRU **enabled**. Expected: monotonically increasing predicted probability (e.g., 0.1 -> 0.4 -> 0.9) across turns, verifying stateful risk accumulation.
    3.  **Residual Path Ablation:** Compare full model performance on the multi-turn benchmark against a variant using `R_t = ϕ(h_t)` (no residual concatenation). Expected: significant drop in F1/Recall, confirming the residual's role in preserving single-turn sensitivity and contextual anchoring.

## Open Questions the Paper Calls Out
*   **Generalized Intent Alignment:** How can the recurrent intent state be extended from binary safety to generalized intent trajectory alignment for monitoring drift in autonomous agent workflows? The current model optimizes a single binary objective; agentic alignment requires a richer, multi-dimensional representation of intent.
*   **Dynamic Policy Controls:** Can the continuous risk vector `R_t` effectively power dynamic, non-binary policies (e.g., adaptive friction, privilege degradation) without causing user frustration or creating a new attack surface? The paper only evaluates binary blocking.
*   **Explainable Hybrid Tracking:** How can deterministic, explainable threat tracking (rule engines) be integrated with the probabilistic GRU state to reduce false positives in high-noise environments (e.g., dev conversations) and provide verifiable audit trails? The paper identifies this as a key limitation but provides no solution.
*   **Long-Horizon & Federated Scaling:** Can the GRU-based design scale to extremely long conversations (hundreds of turns) and federated scenarios (intent tracking across multiple, interconnected LLM agents) without catastrophic forgetting or state explosion? Evaluations only cover up to 49 turns in a single thread.
*   **Stateless LLM Guardrail Gap:** Why do state-of-the-art LLM-based guardrails (Llama-Guard, Granite-Guardian) perform worse with full conversation context vs. a sliding window, and can architectural modifications to these models close the gap with recurrent approaches? The paper attributes this to "signal dilution" but does not diagnose the root cause.

## Limitations
*   **Data Ambiguity:** Training data composition, labeling conventions for mixed/benign datasets, and proprietary subset details are underspecified, hindering faithful reproduction.
*   **Architectural Opacity:** Critical implementation details—exact task-attention mechanism (single vector vs. multi-head), MLP depth and residual structure, BERT fine-tuning strategy—are not fully described.
*   **Evaluation Constraints:** The exact test set construction, classification threshold, and evaluation metric calculations (e.g., how MTTD is computed on conversations with multiple harmful turns) are not publicly disclosed.

## Confidence
*   **GRU-based stateful tracking of intent drift:** Medium (Core mechanism is logically sound and supported by comparative evaluation, but dependent on opaque training data and hyperparameters).
*   **Task-attention weighted BERT embeddings:** Medium (Plausible and cited as key to efficiency, but implementation details missing).
*   **Hybrid residual (h_t + e_t) architecture:** Medium (Validated by performance differential between single-turn and multi-turn benchmarks, but specific residual design not fully elaborated).
*   **Reported overall F1 0.84 on multi-turn jailbreak detection:** Low (Cannot be independently verified without access to the exact test set, code, and trained model).

## Next Checks
1.  **Single-turn baseline validation:** Freeze the GRU state and evaluate the model on a standard single-turn jailbreak dataset (e.g., JailBreakBench). The expected strong performance (~F1 0.98) must be replicated to confirm the foundational turn-level classifier is sound before assessing stateful gains.
2.  **Synthetic drift monotonicity test:** Run a hand-crafted, multi-turn Crescendo attack through the full model and verify that the predicted harm probability increases monotonically across turns (e.g., low -> medium -> high), confirming the GRU state is effectively accumulating adversarial drift.
3.  **Residual connection ablation:** Empirically compare the full model's multi-turn performance against a variant where the risk vector `R_t` is defined *only* as `ϕ(h_t)` (no concatenation with `e_t`). A significant drop in F1/Recall would confirm the residual's necessity for preserving instantaneous signal.
