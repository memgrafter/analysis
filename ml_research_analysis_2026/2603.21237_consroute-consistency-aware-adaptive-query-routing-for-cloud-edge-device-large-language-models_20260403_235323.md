# ConsRoute:Consistency-Aware Adaptive Query Routing for Cloud-Edge-Device Large Language Models

## Quick Facts
*   **arXiv ID:** 2603.21237
*   **Source URL:** https://arxiv.org/abs/2603.21237
*   **Reference Count:** 39
*   **Primary Result:** ConsRoute maintains ≥95% of cloud-only accuracy while cutting end-to-end latency and inference cost by nearly 40%.

## Executive Summary
ConsRoute introduces a query routing system for heterogeneous cloud-edge-device LLM deployments. It addresses the core challenge of deciding, per query, whether a resource-constrained device model (DLM) suffices or if a more powerful edge (ELM) or cloud (CLM) model is necessary. The system learns to make this decision by reusing the DLM’s own computational work—specifically, its prefilling hidden states augmented with a consistency-focused prompt—as a lightweight, on-device query representation. A router is trained to predict the semantic consistency between the DLM’s likely output and that of a stronger model, using a reranker for supervision. Routing thresholds are learned per semantic cluster via Bayesian optimization and updated online to adapt to changing network conditions and query distributions. The approach eliminates the need for separate query encoders and demonstrates significant efficiency gains over state-of-the-art routers.

## Method Summary
ConsRoute’s pipeline consists of an offline training phase and an online routing phase. Offline, for a corpus of queries, responses from a device LLM (DLM), edge LLM (ELM), and cloud LLM (CLM) are generated. A pre-trained reranker computes the semantic similarity (consistency score) between the DLM response and each stronger model’s response. This score is optionally augmented with correctness or LLM-judge feedback and fused to form a soft supervisory label. Concurrently, for each query, a representation is extracted by appending a fixed prompt (“The consistency between the small language model and large language model responses for the above query is:”) to the query and running the DLM’s prefilling pass; the final-layer hidden state of the EOS token is taken as the embedding. A lightweight on-device MLP is trained to predict the fused consistency score from this embedding. The training embeddings are clustered (K-means), and for each cluster, Bayesian optimization searches for a pair of routing thresholds (τ₁, τ₂) that maximize a utility function balancing accuracy, latency, and cost. Online, for a new query, its embedding is assigned to the nearest cluster; the router predicts a consistency score, and the cluster’s thresholds determine routing: score > τ₁ → DLM; τ₂ < score ≤ τ₁ → ELM; score ≤ τ₂ → CLM. Observed outcomes feed back to periodically update the cluster thresholds.

## Key Results
*   Achieves ≥95% of the accuracy of a cloud-only (CLM) baseline while reducing end-to-end latency and inference cost by ~40%.
*   Consistently outperforms state-of-the-art routers (RouteLLM, MixLLM) across multiple datasets (MMLU, GSM8K, HumanEval, MT-Bench) and varying network conditions.
*   The cluster-specific Bayesian thresholding enables effective adaptation to dynamic network latency shifts (e.g., “Bad→Good”) without manual retuning.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Using a reranker to directly measure semantic similarity between DLM and higher-tier outputs provides a finer-grained, more faithful supervision signal for training the router than scalar reward/quality differences.
*   **Mechanism:** A pre-trained reranker model produces a continuous similarity score `SIM(x)` comparing the DLM's response to an ELM/CLM response. This score, possibly augmented with correctness-based rules or an LLM judge, serves as the target consistency label `S(x)` for training the on-device predictor `f_θ`.
*   **Core Assumption:** The reranker's score reliably correlates with human judgment of whether the DLM's output preserves the core semantics of a stronger model's output.
*   **Evidence Anchors:**
    *   [Abstract] “leverages a reranker to directly assess the semantic gap between responses… yielding fine-grained soft supervision signals.”
    *   [Section IV-C] Details the reranker similarity computation (Eq. 3) and label augmentation (Eq. 5). Figure 4 shows the reranker score has a stronger linear correlation with human-annotated consistency than reward model scores or BartScore.
    *   [Corpus] Neighboring routers (MixLLM, RouteLLM) rely on scalar reward gaps, positioning ConsRoute's reranker-based approach as a distinct innovation. Corpus evidence is weak for direct validation of *why* it’s better; the paper’s internal analysis is strong.

### Mechanism 2
*   **Claim:** Reusing the DLM’s prefilling hidden states—augmented with a fixed consistency-oriented prompt—as the query representation eliminates the overhead of a separate encoder while producing embeddings predictive of output consistency.
*   **Mechanism:** The user query `x` is concatenated with a prompt `p` (“The consistency… is:”) and an EOS token. The DLM processes this in its standard prefilling pass. The final-layer hidden state at the EOS position, `h_T`, is extracted and fed to the router MLP. The prompt is designed to “nudge” the DLM’s internal representations to encode information relevant to future output consistency.
*   **Core Assumption:** The DLM’s prefilling computation inherently contains cues about its likely answer quality/consistency, and the prompt reliably steers its representations toward encoding this predictive information.
*   **Evidence Anchors:**
    *   [Abstract] “reuses the device LLM’s prefilling hidden states… augmented with a consistency-focused prompt… eliminating extra encoders.”
    *   [Section IV-B] Describes the prompt-guided extraction (Eqs. 1–2). Table III shows the prompted implicit representation (87.92% accuracy) significantly outperforms the unprompted variant (82.34%) with minimal added latency (20.9ms vs. 20.4ms).
    *   [Corpus] Other routers use separate BERT encoders for query representation, highlighting ConsRoute’s novel reuse. Generalizability depends on DLM capacity; smaller or less instruction-tuned DLMs may not produce effective prompted representations.

### Mechanism 3
*   **Claim:** Learning cluster-specific routing thresholds via Bayesian optimization, with online updates, allows the system to adapt to heterogeneous query difficulties and dynamic network conditions better than a single global threshold.
*   **Mechanism:** Training embeddings `h_T` are clustered (K-means). For each cluster `C_k`, a Gaussian Process surrogate models the utility function `U_k(τ₁, τ₂)` over threshold pairs. Bayesian optimization (Expected Improvement) proposes threshold evaluations to maximize utility. During deployment, per-query utility outcomes (`correctness`, `latency`, `cost`) are collected and periodically used to update the surrogate and thresholds for the relevant cluster.
*   **Core Assumption:** Queries within the same semantic cluster have similar optimal routing trade-offs (i.e., similar cost-benefit thresholds for escalation), and the utility landscape can be efficiently explored with limited evaluations.
*   **Evidence Anchors:**
    *   [Abstract] “cluster-specific routing thresholds are learned via Bayesian optimization, with online updates for adaptation.”
    *   [Section IV-D] Details clustering, utility definition (Eq. 9), and the online adaptation loop (Algorithm 2). Figure 11 shows thresholds evolve under changing network conditions, shifting routing strategy and improving accuracy.
    *   [Corpus] Neighbors use fixed or latency-constrained thresholds. No prior work directly evaluates adaptive Bayesian threshold tuning in this context; evidence is primarily from ConsRoute’s experiments.

## Foundational Learning
*   **Concept:** Semantic similarity (via reranker) vs. scalar quality metrics for supervision.
    *   *Why needed here:* Understanding why a reranker’s fine-grained similarity score is a better training target for a router than a scalar reward difference (e.g., CLM reward - DLM reward) is key to grasping ConsRoute's core innovation over prior routers like RouteLLM.
    *   *Quick check:* How could two responses (from DLM and CLM) both receive high reward scores from a model yet still differ meaningfully on key aspects of the query?
*   **Concept:** Prefilling and decoding in autoregressive LLMs.
    *   *Why needed here:* The mechanism reuses the DLM's prefilling hidden states. One must understand that prefilling processes the full input sequence and produces the KV cache for subsequent token-by-token decoding, making the representation extraction "free" (no extra forward pass).
    *   *Quick check:* Why is the final-layer hidden state of the EOS token a reasonable pooled representation of the input sequence after the consistency prompt has been processed?
*   **Concept:** Bayesian optimization for hyperparameter/tuning.
    *   *Why needed here:* It's the engine for learning and adapting cluster-specific routing thresholds. Knowing it builds a surrogate model (e.g., Gaussian Process) of an expensive-to-evaluate function and uses acquisition functions (like Expected Improvement) guides comprehension of the adaptive thresholding process.
    *   *Quick check:* In ConsRoute, what is the “expensive function” being optimized, and why can’t its optimum be found by simply grid-searching all possible threshold pairs?

## Architecture Onboarding

**Component map:**
User Query -> Representation Extractor (DLM Prefilling + Prompt) -> `h_T` -> Router (`f_θ`: MLP) -> Predicted Consistency `Ŝ(x)` -> Cluster Manager (nearest centroid lookup) -> Threshold Store (retrieve `(τ₁ᵏ, τ₂ᵏ)`) -> Routing Decision (DLM/ELM/CLM). Parallel: Offline Supervisor (Reranker + Augmentation) generates labels `S(x)` for training `f_θ`. Online Updater feeds back outcomes to refine cluster thresholds via Bayesian Optimization.

**Critical path (online routing):**
1. Receive query `x`.
2. Construct input `x' = x || p || [EOS]`.
3. Run DLM prefilling on `x'` → obtain `h_T` (last layer, EOS position). *(If DLM is routed to, its KV cache from this step is reused for decoding.)*
4. Compute router prediction `Ŝ(x) = f_θ(h_T)`.
5. Find nearest cluster centroid: `k* = argmin_k ||h_T - c_k||²`.
6. Retrieve thresholds `(τ₁, τ₂)` for cluster `k*`.
7. If `Ŝ(x) > τ₁` → route to DLM. Else if `Ŝ(x) > τ₂` → route to ELM. Else → route to CLM.
*(Adds network RTT + inference time at chosen tier.)*

**Design tradeoffs:**
*   **Representation fidelity vs. overhead:** Using DLM prefilling states is extremely efficient but may be less explicitly tuned for routing than a dedicated encoder. The consistency prompt is a lightweight steering mechanism with marginal latency cost.
*   **Cluster granularity vs. adaptation cost:** More clusters (`K`) allow finer-grained threshold specialization but reduce the number of samples per cluster for Bayesian optimization, slowing/throttling reliable online updates.
*   **Reranker dependency vs. label quality:** The entire supervision signal depends on the reranker's judgment. A biased or domain-mismatched reranker propagates errors into `f_θ`, with no easy correction mechanism online.

**Failure signatures:**
*   **Clustering failure:** PCA/t-SNE of `h_T` reveals clusters that mix queries of obviously different difficulty levels (e.g., simple factual vs. complex reasoning), or a single cluster shows high variance in DLM accuracy. This indicates the representation space doesn't align with threshold sensitivity, dooming per-cluster thresholds.
*   **Reranker bias failure:** Systematic patterns where queries of a certain type (e.g., creative writing, code generation) are consistently routed to DLM but produce low-quality outputs. Manual inspection reveals the DLM and CLM outputs diverge semantically on key points the reranker misses.
*   **Prompt steering failure:** The "prompted" and "unprompted" representations show little difference in downstream routing accuracy, or the `h_T` vectors from prompted/unprompted passes are nearly identical. This suggests the DLM architecture/tuning ignores the prompt, nullifying the core representation mechanism.

**First experiments:**
1.  **Probe representation quality:** Train a linear probe on `h_T` to predict a proxy for query difficulty (e.g., DLM zero-shot accuracy on a held-out set). A high probe accuracy indicates `h_T` encodes difficulty-relevant information.
2.  **Stress test clustering:** Run the full pipeline with varying `K` (number of clusters). Plot cluster purity (using DLM accuracy bins) and final utility. Look for the "elbow" where utility plateaus but clusters remain semantically coherent.
3.  **Reranker ablation:** Replace Qwen3-Reranker with a different model (e.g., BGE-Reranker). Retrain `f_θ` and recompute routing metrics. A significant drop indicates sensitivity to reranker choice and potential brittleness.

## Open Questions the Paper Calls Out
*   **Does the reranker-based consistency supervision generalize across diverse NLP domains beyond the benchmark datasets used?** The paper evaluates on RouterBench (MMLU, GSM8K, HumanEval, MT-Bench) but does not test domain shift scenarios (e.g., biomedical, legal texts). Reranker models may capture domain-specific semantic patterns; failure in new domains could degrade routing accuracy. Resolution would require testing ConsRoute on out-of-domain datasets with human-annotated consistency labels.
*   **How robust is the prompt-guided representation extraction to variations in DLM architecture or tokenization?** The method assumes the fixed prompt reliably steers DLM hidden states toward consistency-aware encoding. This may not hold for smaller, less instruction-tuned, or architecturally distinct models (e.g., non-transformer, different tokenizers). Evidence is needed across a wider spectrum of device model capabilities.

## Limitations
*   **Unreported hyperparameters:** Bayesian optimization details (acquisition function, GP kernel, number of iterations) and the exact cost model/λ weights in the utility function are unspecified, hindering precise replication of the reported trade-offs and adaptation dynamics.
*   **Reranker dependency bias:** The supervision signal is entirely contingent on the reranker's judgment, whose training data and potential biases are not disclosed. This could lead to systematic routing failures for query types the reranker misjudges (e.g., creative vs. factual).
*   **DLM capacity assumption:** The prompt-guided representation reuse assumes the DLM is sufficiently capable and instruction-tuned to have its internal representations steered by the prompt. Performance likely degrades with weaker device models, limiting applicability on ultra-low-resource devices.

## Confidence
*   **Reranker supervision superiority:** **High**. Strong internal evidence (Figure 4) demonstrates the reranker score's superior correlation with human consistency labels compared to reward models or BartScore.
*   **Prompted prefilling representation effectiveness:** **Medium**. The ablation (Table III) shows a significant gain over unprompted representation, but generalizability to smaller/less-capable DLMs is an open question.
*   **Cluster-specific Bayesian thresholding & adaptation:** **Medium**. Adaptation benefits are empirically shown (Figure 11), but the effectiveness hinges on the quality of the `h_T` clustering; no external validation confirms clusters align with optimal thresholds across diverse, unseen query distributions.

## Next Checks
1.  **Reranker robustness test:** Replace the Qwen3-Reranker with multiple off-the-shelf alternatives (e.g., BGE-Reranker, Cohere Rerank) and evaluate routing accuracy, latency, and cost across all benchmark datasets to measure sensitivity.
2.  **Representation probing diagnostic:** Train linear probes on the extracted `h_T` vectors to predict known query difficulty metrics (e.g., DLM zero-shot accuracy, query length, task type). Compare probe performance against a random baseline to quantify how much predictive information the prompt actually injects.
3.  **Cluster semantic coherence audit:** Apply dimensionality reduction (t-SNE/PCA) to the training `h_T` vectors. Manually or automatically (via topic modeling) label clusters for semantic similarity and predicted difficulty. Measure cluster purity and inter-cluster variance to validate that the learned clusters meaningfully correspond to groups with similar routing thresholds.
