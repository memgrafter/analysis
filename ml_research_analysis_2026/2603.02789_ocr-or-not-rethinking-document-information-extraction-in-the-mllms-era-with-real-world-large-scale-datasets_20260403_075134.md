# OCR or Not? Rethinking Document Information Extraction in the MLLMs Era with Real-World Large-Scale Datasets

## Quick Facts
- arXiv ID: 2603.02789
- Source URL: https://arxiv.org/abs/2603.02789
- Reference count: 5
- Primary result: High-capacity MLLMs (e.g., Gemini 1.5 Pro) achieve comparable or superior mean F1-scores with image-only input (76.8) versus OCR-only (74.1), indicating OCR is often unnecessary.

## Executive Summary
This paper challenges the conventional OCR-first pipeline for document information extraction (IE) by benchmarking multimodal LLMs on two large-scale real-world business datasets. It finds that state-of-the-art models like Gemini 1.5 Pro can directly extract structured information from document images, matching or exceeding OCR-based pipelines while significantly reducing schema-ambiguity errors. Furthermore, systematic prompt and schema optimization yields additional performance gains, demonstrating that OCR-free MLLM pipelines are both effective and tunable without external preprocessing.

## Method Summary
The study evaluates out-of-the-box multimodal LLMs via zero-shot prompting on two internal business document datasets (C1: supply chain; C2: finance). For each document, three input modalities are compared: image-only, OCR-text-only, and image+OCR. Performance is measured by macro F1-score over extracted key–value pairs. A hierarchical automated error analysis diagnoses failures: a field-level handler logs mismatches, an LLM reasons to categorize errors (e.g., text misinterpretation, schema ambiguity), and BERT clustering groups similar root causes. The authors also apply prompt and schema refinements to optimize image-only performance.

## Key Results
- Gemini 1.5 Pro achieves a mean F1 of 76.8 with image-only input, comparable to OCR-only (74.1) and higher than image+OCR (75.0).
- Image-only inputs reduce total errors and lower schema-ambiguity errors substantially (30% vs. 62% for OCR-only).
- Prompt and schema refinement boosts image-only F1 to 78.9, a 2.1-point gain over the baseline.

## Why This Works (Mechanism)
### 1. Implicit OCR in Vision Encoders
- **Claim:** High-capacity MLLMs possess sufficient implicit optical character recognition capability within their vision encoder to directly extract accurate text from document images.
- **Mechanism:** The vision transformer, trained on web-scale data containing documents, learns to resolve glyphs, reading order, and layout directly from pixels, preserving spatial context that separate OCR might lose.
- **Core assumption:** Pre-training data included diverse, high-quality document images.
- **Evidence anchors:** Gemini 1.5 Pro's image-only F1 (76.8) matches OCR-only (74.1); section 4.3.1 states advanced models extract directly without OCR.
- **Break condition:** Smaller or less document-focused models show degraded image-only performance.

### 2. Unified Layout Reasoning
- **Claim:** Image-only input reduces schema-ambiguity errors because the MLLM processes the document as a unified whole, better capturing global layout and structural hierarchy.
- **Mechanism:** The model's multimodal attention fuses visual layout features with textual semantics, preserving 2D positioning; OCR+LLM pipelines use a linear text stream that loses precise spatial relationships.
- **Core assumption:** The architecture effectively integrates vision and text during processing.
- **Evidence anchors:** Section 5 notes reduced schema-ambiguity; Figure 5 shows Error C at 30% for image-only vs 62% for OCR-only.
- **Break condition:** For extremely simple or machine-generated documents, the advantage may be negligible.

### 3. Prompt and Schema Optimization
- **Claim:** Image-only performance is sensitive to prompt and schema design, and refinements yield measurable gains, making the pipeline optimizable without OCR.
- **Mechanism:** The MLLM acts as a general reasoner; clear instructions, format constraints, and field definitions steer its internal reasoning toward consistent, correct outputs.
- **Core assumption:** The model has latent extraction ability but needs steering for the specific schema.
- **Evidence anchors:** Section 5 reports mean F1 increase from 76.8% to 78.9% after enhancements; Appendix E shows refined template adds validation and attention cues.
- **Break condition:** If the schema is inherently ambiguous or content is beyond model knowledge, gains diminish.

## Foundational Learning
- **Multimodal Transformer Architecture:** Needed to understand how an MLLM processes images as visual tokens and jointly attends with text, underpinning implicit OCR and layout reasoning. Quick check: How does patch embedding and positional encoding preserve 2D layout that linear OCR text loses?
- **Hierarchical Error Analysis:** The paper's diagnostic tool; moves from mismatch detection to LLM-based categorization to root cause clustering, essential for understanding why image-only works better. Quick check: What distinguishes a mid-level error reason (e.g., "text misinterpretation") from a highest-level failure source (e.g., "schema inconsistency")?
- **Schema-Guided Information Extraction:** The task is structured extraction against a predefined JSON schema; schema design directly impacts prompt effectiveness and Mechanism 3. Quick check: How might changing a field description from "item number" to "the sequential number of the line item in the table" affect performance on complex documents?

## Architecture Onboarding
- **Component map:** `Document Image -> MLLM Client (with prompt) -> Raw JSON Response -> Output Parser -> Structured Output -> Evaluation & Error Analysis -> LLM Reasoner -> Error Clusters -> Insights -> Prompt/Schema Refiner -> (back to MLLM)`
- **Critical path:** `Document Image -> MLLM(Image-only Prompt) -> Raw JSON Response -> Parser -> Structured Output -> Evaluation (F1) -> Error Handler -> LLM Reasoner -> Error Clusters -> Insights -> Prompt/Schema Update`
- **Design tradeoffs:**
  - Accuracy vs. Latency/Cost: Image-only avoids OCR overhead but may have higher MLLM latency; total error reduction may justify.
  - Pipeline Simplicity vs. Control: MLLM-only is simpler and reduces total errors but is a black box; OCR+LLM offers intermediate debugging.
  - Generalization vs. Optimization: Out-of-the-box MLLMs generalize across layouts/languages; peak performance requires prompt/schema tuning, which is simpler than fine-tuning.
- **Failure signatures:**
  - **Text Misinterpretation (A):** Correct text extracted but assigned to wrong schema field.
  - **Image-to-text Extraction Issue (B):** Incorrect transcription of visible string (e.g., "I" vs "1").
  - **OCR Schema Ambiguity (C)** (OCR-only): OCR text misalignment causes LLM to pick wrong value from multiple plausible.
  - **Format/Compliance:** Invalid JSON, wrong format, etc.
- **First 3 experiments:**
  1. **Modality Baseline:** Run same document batch through MLLM with image-only, OCR-only, image+OCR prompts. Compute macro F1 to confirm image-only vs. OCR-only gap.
  2. **Automated Error Census:** For top 100 failures, run hierarchical analysis (Handler + LLM Reasoner). Quantify error category proportions; validate if Error C dominates OCR-only.
  3. **Prompt Refinement A/B Test:** Modify prompt based on error census (e.g., add unit attention, refine field description). Rerun image-only on held-out set; measure F1 gain (target >1-2%).

## Open Questions the Paper Calls Out
1. **What specific model characteristics determine OCR-free capability?**  
   Basis: Performance varies across models; Gemini 1.5 Pro succeeds while others degrade.  
   Why unresolved: Essential for model selection/design but factors not isolated.  
   Evidence needed: Comparative analyses across documented architectures, probing studies, controlled pre-training data experiments.

2. **Does few-shot learning improve weaker models' image-only performance?**  
   Basis: Limitations state few-shot not validated; study is zero-shot only.  
   Why unresolved: Few-shot may provide crucial context, especially for models with poor zero-shot visual reasoning.  
   Evidence needed: Few-shot experiments with varying exemplars for image-only vs OCR-enhanced inputs across multiple models.

3. **What is the individual contribution of prompt components (schema, exemplars, instructions) to performance gains?**  
   Basis: Combined refinements yielded 2.1% F1 gain, but no ablation.  
   Why unresolved: Without disentangling, developers lack guidance on where to focus optimization.  
   Evidence needed: Ablation study systematically varying each component while measuring F1 and error category shifts.

4. **Can reasoning models improve the hierarchical error analysis?**  
   Basis: Limitations suggest integrating O1/DeepSeek R1 could enhance categorization.  
   Why unresolved: Automated error analysis is crucial; reasoning models may better handle nuanced spatial/schema errors.  
   Evidence needed: Replace LLM reasoning step with a reasoning model, re-analyze failures, compare categorization consistency against human labels.

## Limitations
- Internal datasets (C1/C2) and schemas are undisclosed, hindering external validation and generalizability.
- OCR-only baseline relies on an unspecified in-house OCR engine; results may not transfer to standard tools (e.g., Tesseract).
- LLM-based hierarchical error categorization lacks published prompts/templates, risking inconsistent classification in replications.

## Confidence
- Claim 1 (Image-only matches OCR-only for high-capacity MLLMs): High.
- Claim 2 (Image-only reduces schema-ambiguity errors): Medium.
- Claim 3 (Prompt/schema optimization yields gains): Medium.
- Claim 4 (Implicit OCR capability in vision encoders): Low.

## Next Checks
1. Replicate on public business document datasets (e.g., DocVQA, RVL-CDIP) using standardized OCR (Tesseract) to confirm performance gap persists.
2. Ablate the OCR schema-ambiguity error category by manually inspecting a random sample of OCR-only failures to quantify LLM vs human judgment alignment.
3. Test prompt refinement transferability by applying the paper's optimized prompt template to a different domain (e.g., legal contracts) to determine domain generality.
