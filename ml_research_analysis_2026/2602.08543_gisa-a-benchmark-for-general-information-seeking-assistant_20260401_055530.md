# GISA: A Benchmark for General Information-Seeking Assistant

## Quick Facts
- **arXiv ID**: 2602.08543  
- **Source URL**: https://arxiv.org/abs/2602.08543  
- **Reference count**: 24  
- **Primary result**: Best model (Claude 4.5 Sonnet, thinking) achieves only 19.30% exact match.

## Executive Summary
GISA tackles key shortcomings of existing search agent benchmarks—unrealistic query construction, narrow focus (either deep or wide search), and static answers vulnerable to data contamination—by introducing a human-crafted benchmark of 373 authentic queries. It defines four structured answer formats (item, set, list, table) that enable deterministic evaluation via exact match and F1 metrics, while integrating both deep reasoning and broad aggregation. A live subset with periodically updated answers resists memorization, and complete human search trajectories support process-level supervision. Evaluation of 15 state-of-the-art LLMs and commercial systems reveals uniformly low performance, with even the best model at 19.30% EM, and notable degradation on tasks requiring complex planning and comprehensive information gathering, underscoring substantial room for improvement.

## Method Summary
The GISA benchmark package provides encrypted query JSONs (with type, topic, stable/live label), ground-truth answers in CSV format adhering to item/set/list/table schemas, and JSON logs of full human search trajectories (queries, results, clicks, timestamps). Agents interact via two tools: `Search` (Google via Serper API, top-10 results) and `Browse` (Jina API, summarized), with a strict limit of 30 tool calls per query. Evaluation normalizes predictions and ground truth (lowercasing, whitespace stripping, numeric formatting) then computes exact match and type-specific metrics (F1 for sets/lists, order score via Sequence Matcher for lists, row/item F1 for tables). Resources include a GitHub repository with evaluation scripts, a public leaderboard, system prompts, and tool schemas. Reproduction requires API keys, dataset download, agent execution following the ReAct loop with provided prompts, answer extraction from `<answer>` tags, and script-based scoring.

## Key Results
- State-of-the-art models perform poorly: Claude 4.5 Sonnet (thinking) leads with 19.30% exact match.
- Performance drops significantly on queries requiring complex planning and comprehensive information gathering.
- Inference-time scaling (e.g., Best@k) and thinking modes yield gains but with high token costs, and high tool usage does not correlate with better results.

## Why This Works (Mechanism)
### Mechanism 1
Claim: Human-crafted queries ensure authenticity and alignment with real-world information needs.  
Mechanism: Annotators generate seed questions via a browsing-inspired workflow: visit domain-specific websites, freely explore content, and document spontaneously arising questions, mimicking natural curiosity.  
Core assumption: Authentic queries reflect genuine search challenges and prevent optimization toward artificial tasks.  
Evidence anchors: Abstract mentions "human-crafted queries that reflect authentic information-seeking scenarios"; Section 3.1.1 describes the workflow.  
Break condition: If human annotation introduces demographic/topical biases or generated queries become too narrow despite brainstorming.

### Mechanism 2
Claim: Structured answer formats with deterministic metrics enable objective, reproducible evaluation.  
Mechanism: Answers constrained to item, set, list, or table types with explicit schemas and sorting rules, allowing exact match and F1-based scoring without LLM judgment.  
Core assumption: Strict formatting eliminates subjectivity and stabilizes evaluation across runs and model types.  
Evidence anchors: Abstract states "four structured answer formats... enabling deterministic evaluation"; Section 3.1.2 emphasizes deterministic and reproducible evaluation; Section 3.2.2 details metrics.  
Break condition: If formatting constraints force unnatural answer representations or normalization fails on real-world variations (e.g., date formats, duplicates).

### Mechanism 3
Claim: Live subset and human trajectories jointly resist data contamination and support process-level agent improvement.  
Mechanism: Live queries have periodically updated answers to prevent memorization; complete human search logs provide gold-standard trajectories for imitation learning and verification.  
Core assumption: Static benchmarks are vulnerable to pre-training data leakage; process data teaches effective search strategies beyond final answers.  
Evidence anchors: Abstract and Section 3.1.2 describe live subset for contamination resistance; Section 3.1.3 details trajectory logging via browser extension.  
Break condition: If live updates are infrequent/inconsistent or human trajectories are not generalizable to diverse agent architectures.

## Architecture Onboarding
Component map: Encrypted query JSON files → ground-truth answer CSV files → human trajectory JSON logs → evaluation scripts → leaderboard.  
Critical path: (1) Load query and current date; (2) Run agent with Search/Browse tools (max 30 calls); (3) Extract final answer from `<answer>` tags via regex; (4) Normalize prediction and ground truth (lowercase, strip formatting, handle numbers/dates); (5) Compute EM and type-specific metrics; (6) Log results for leaderboard.  
Design tradeoffs: Human annotation ensures high quality but limits scale (373 queries) and is costly; structured formats enable deterministic eval but may constrain task expressiveness; live subset requires ongoing maintenance effort.  
Failure signatures: (1) Answer extraction fails due to missing code block or malformed TSV; (2) Normalization errors (e.g., date parsing, duplicate handling); (3) Metric mismatches from schema violations (e.g., wrong table columns); (4) Trajectory logging gaps (missing initial queries or noise).  
First 3 experiments:
1. **Pipeline validation**: Run evaluation on 5 random queries with a simple rule-based agent to ensure parsing, normalization, and metric scripts work without errors.
2. **Contamination check**: Test a state-of-the-art model (e.g., Claude 4.5 Sonnet) on stable vs. live subsets; expect lower performance on live if contamination is minimized.
3. **Behavioral alignment**: Compare agent search queries and clicked URLs against human trajectories using Jaccard similarity; low similarity may indicate poor search strategy imitation.

## Open Questions the Paper Calls Out
1. How can search agent benchmarks be designed to effectively and simultaneously evaluate both deep reasoning and broad information aggregation within unified, realistic tasks? Basis: Existing benchmarks "tend to focus on either locating specific information or aggregating information from multiple sources"; GISA integrates both but design principles for unified evaluation are not established. Evidence needed: Reproducible methodology for constructing tasks that inherently require both deep and wide search, validated by human solvability and model performance correlation.
2. What architectural or training modifications can significantly improve an agent's ability to perform effective multi-hop reasoning, thorough web exploration, and dynamic query refinement? Basis: Error analysis shows 49.2% of failures at "search level" (ineffective queries, failure to exploit hyperlinks, inability to initiate verification queries). Why unresolved: Current models exhibit these failure modes; solutions not explored. Evidence needed: Ablation studies showing specific enhancements (e.g., modified planning modules, link ranking heuristics, conflict detection) reduce these errors.
3. How can search agents be trained to better imitate human search behaviors using human search trajectories? Basis: Humans issue fewer queries but browse more pages; positive correlation between behavioral similarity and performance. Why unresolved: Trajectories released but not used for training in paper; how to leverage them (SFT, RL, distillation) remains open. Evidence needed: Models fine-tuned/RL-trained on GISA trajectories show improved behavioral similarity metrics and overall task performance.
4. Beyond static test sets, what are effective and scalable methodologies for maintaining benchmark integrity against data contamination? Basis: Live subset introduced but costly; update frequency, viable size, and alternative strategies not explored. Evidence needed: Comparative study of anti-contamination strategies (live subsets, synthetic temporal queries, automatic freshness verification) measuring longevity and cost-effectiveness against models with continuously updated training data.
5. What is the optimal trade-off between inference-time computation and tool-calling efficiency for maximizing performance per unit cost, and how can this be dynamically managed? Basis: Inference-time scaling helps, thinking mode gains but high token use; high tool usage doesn't correlate with better performance. Why unresolved: Non-monotonic relationship; adaptive strategies not investigated. Evidence needed: Meta-controller or adaptive policy that dynamically allocates resources, matching/exceeding fixed-budget agents at lower cost or significantly outperforming at comparable cost.

## Limitations
- Normalization specifics for edge cases (dates, whitespace, duplicates) are unclear, risking metric inconsistencies.
- Live subset update processes and query selection are opaque, limiting validation of contamination resistance.
- Human search trajectories may not generalize to diverse agent architectures or tool implementations.
- Scale is modest (373 queries); human brainstorming may introduce topical or demographic biases.

## Confidence
- Mechanism 1 (Human-crafted queries): Medium. Evidence from workflow description is plausible, but corpus lacks direct validation; risk of unstated biases.
- Mechanism 2 (Structured formats): Medium. Deterministic metrics well-defined, but neighbor benchmarks suggest format diversity adds complexity, and real-world variability may break schemas.
- Mechanism 3 (Live subset & trajectories): Low. Conceptual strength clear, but corpus support weak; no empirical evidence yet that trajectories improve agent planning.
