# Learning to Rank Caption Chains for Video-Text Alignment

## Quick Facts
- **arXiv ID**: 2603.25145  
- **Source URL**: https://arxiv.org/abs/2603.25145  
- **Reference count**: 40  
- **Primary result**: Ranking optimization with Plackett-Luce DPO on totally ordered caption chains outperforms binary DPO and MPO on video-text alignment benchmarks, with joint vision-language fine-tuning being essential.

## Executive Summary
Standard Direct Preference Optimization (DPO) uses binary pairwise preferences, which fails to capture that lower-ranked captions can still be visually faithful. This work introduces a ranking-based solution: an LLM systematically degrades a high-quality caption by inserting visually‑grounded errors while preserving its structure, producing a totally ordered caption chain. The VLM is trained with a Plackett‑Luce ranking loss on the full chain, alongside a next‑token prediction loss, and with both vision encoder and language model fine‑tuned jointly.

Experiments on PE‑Video and MSR‑VTT demonstrate that ranking optimization consistently surpasses binary DPO and listwise alternatives across LLM‑judge metrics (relevance, descriptiveness, temporal consistency). Human evaluation shows a 56% preference for ranking over DPO, and long‑form multiple‑choice QA accuracy improves (e.g., 83.2% → 82.6%). Crucially, the gains vanish if the vision encoder is frozen, underscoring the need for end‑to‑end training. Longer caption chains yield additional improvements, suggesting the method scales well.

## Method Summary
The method consists of two main stages. First, an offline data generation pipeline constructs the RCC dataset. For each video, a detailed ground-truth caption is obtained using an LLM (Claude 3.7 Sonnet). Starting from this caption, an iterative degradation process introduces one visually‑grounded error (e.g., object misidentification, attribute alteration) at each step while strictly preserving the structure and previously inserted errors. This produces a totally ordered chain \(c_1 \succ c_2 \succ \dots \succ c_n\) where each caption is progressively less faithful to the video. The error type is sampled uniformly from a predefined set to ensure diversity.

Second, a VLM (e.g., Qwen2.5-VL) is fine‑tuned with LoRA on both its vision encoder and language backbone. The loss function combines a Plackett‑Luce ranking loss over the whole chain and a next‑token prediction (NTP) loss on the top caption (weight \(\lambda=0.1\)) to prevent generation collapse. Given video \(x\) and chain \([c_1,\dots,c_n]\), the model produces scores \(s_i = \beta (\log \pi_\theta(c_i|x) - \log \pi_{\text{ref}}(c_i|x))\). The ranking loss is \(-\sum_{i=1}^n \log \frac{\exp(s_i)}{\sum_{j=i}^n \exp(s_j)}\). Training uses AdamW (lr=1e‑6, \(\beta=0.3\), batch size 8) for 1k steps. Evaluation uses LLM‑as‑a‑judge (Claude 3.7) metrics (relevance, descriptiveness, temporal consistency, fluency), human preference, LF‑MCQA accuracy (Qwen2.5‑VL), and TempCompass matching.

## Key Results
- **Ranking surpasses binary DPO and MPO**: On PE‑Video and MSR‑VTT, Plackett‑Luce DPO achieves higher LLM‑judge scores; e.g., PLM on PE‑Video: Relevance 7.67 vs 7.57 (DPO), Descriptiveness 7.72 vs 7.59, Temporal Consistency 7.93 vs 7.78.
- **Human preference**: Ranking captions are favored 56% over DPO‑generated captions.
- **Downstream QA improvement**: Long‑form multiple‑choice QA accuracy increases (Qwen2.5‑VL: 83.2% vs 82.6% with DPO).
- **Joint fine‑tuning is essential**: Freezing the vision encoder collapses performance to DPO/SFT levels; ranking gains vanish.
- **Longer chains help**: Extending chain length yields monotonic improvements up to at least length 10.

## Why This Works (Mechanism)
### Mechanism 1: Systematic Degradation Creates Totally Ordered Training Data
- **Claim**: Repeatedly inserting visually‑grounded errors into a high‑quality caption while preserving structure generates a chain where each caption is strictly less faithful to the video than the previous one.
- **Mechanism**: Starting from a detailed ground‑truth caption, an LLM introduces one error type (e.g., object misidentification, attribute change) per step. The mutation is constrained to maintain prior text and structure, ensuring \(\text{Errors}(c_k) \subsetneq \text{Errors}(c_{k+1})\). This creates a clean, total order of decreasing visual fidelity.
- **Core assumption**: Each introduced error reliably and measurably reduces the caption's faithfulness to the video, and preserving structure isolates the error's impact from linguistic variation.
- **Evidence anchors**:
  - [abstract] "proposes a method to generate challenging, totally ordered caption chains at scale through repeated caption degradation."
  - [section 3.1] Details the mutation process: "we start by sampling an error type... an LLM then mutates c_k to introduce an error... while ensuring that the mutated caption c_{k+1} maintains c_k’s structure."
  - [corpus] Neighbors like "LiPO: Listwise Preference Optimization" and "Curry-DPO" also explore ranking/curriculum data, supporting the value of ordered data, but the specific degradation mechanism is unique to this paper.
- **Break condition**: If the LLM fails to preserve prior errors or introduces non‑visual changes, the total order breaks. Human inspection found 89% of chains maintained order, with only 3% containing noise from generation errors.

### Mechanism 2: Plackett‑Luce Ranking Loss Teaches Fine‑Grained Visual Discrimination
- **Claim**: Optimizing the full ranking via the Plackett‑Luce model forces the VLM to learn nuanced visual differences between similar captions, unlike binary DPO which only distinguishes "good" from "bad".
- **Mechanism**: The loss computes the product over positions of the probability that a caption at rank \(i\) is preferred over all lower‑ranked ones. This encourages the model to assign progressively lower scores to captions with more errors, capturing a spectrum of visual fidelity. The inclusion of a next‑token prediction (NTP) loss prevents generation collapse.
- **Core assumption**: The total order in the caption chain corresponds to a gradient of visual faithfulness, and the model's scoring function can learn to reflect this gradient.
- **Evidence anchors**:
  - [abstract] "DPO’s binary 'winner‑takes‑all' formulation fails to capture that lower‑ranked captions can remain visually faithful... ranking optimization outperforms binary DPO."
  - [section 3.3] Derives the Plackett‑Luce DPO objective from the ranking model: "P(y_1 ≻ ... ≻ y_n |x) = ∏_i exp(r(x,y_i)) / ∑_{j=i} exp(r(x,y_j))"
  - [section 4.1] Tab. 2 shows ranking consistently beats DPO/MPO on all metrics (e.g., PLM PE‑Video Rel: 7.67 vs 7.57).
- **Break condition**: If the chain order is invalid or the NTP loss weight is insufficient, the model may collapse to generating few tokens or fail to rank correctly. Experiments showed NTP was necessary to prevent collapse.

### Mechanism 3: Joint Vision‑Language Fine‑Tuning is Necessary for Ranking Gains
- **Claim**: The vision encoder must be fine‑tuned alongside the LLM for ranking objectives to improve vision‑text alignment; freezing it nullifies gains.
- **Mechanism**: Ranking requires the vision encoder to produce embeddings sensitive to the subtle visual differences reflected in the caption errors. End‑to‑end training allows gradient flow from the ranking loss back into the vision encoder, adapting it to these fine‑grained distinctions. This contrasts with common practice in DPO for VLMs, where the vision encoder is frozen.
- **Core assumption**: The vision encoder's pretrained representations are not sufficiently tuned to the fine‑grained (细粒度) differences needed for ranking caption chains, and the ranking loss provides a learning signal that must propagate to the vision encoder.
- **Evidence anchors**:
  - [abstract] "gains vanish if the vision encoder is frozen, highlighting the necessity of joint vision‑language fine‑tuning."
  - [section 4.3] Tab. 7 compares frozen vs. trainable vision encoders for Qwen2.5‑VL: Ranking with frozen encoder yields Relevance 7.34, but with trainable encoder it jumps to 7.46. DPO shows negligible difference.
  - [section 4.3] "finetuning the language model alone is insufficient to rank the captions. End‑to‑end training enables the vision encoder to learn the fine‑grained visual representations."
- **Break condition**: If the vision encoder is frozen, the ranking loss cannot update visual representations, and performance plateaus at SFT/DPO levels. The mechanism also assumes the vision encoder has sufficient capacity to adapt; a shallow or bottlenecked encoder may limit gains.

## Foundational Learning
### Concept: Direct Preference Optimization (DPO)
- **Why needed here**: The paper directly contrasts its ranking approach with standard DPO, which uses pairwise (Bradley‑Terry) preferences. Understanding DPO's binary "winner‑takes‑all" objective is prerequisite to seeing its limitation for vision‑language tasks where captions can vary continuously in faithfulness.
- **Quick check question**: How does the Bradley‑Terry model used in DPO differ from the Plackett‑Luce model used for ranking?

### Concept: Vision‑Language Model (VLM) Architecture
- **Why needed here**: The mechanisms rely on the VLM's ability to process both video (vision encoder) and text (LLM backbone). The finding that vision encoder fine‑tuning is critical requires understanding the typical frozen‑vision‑encoder paradigm in VLM post‑training.
- **Quick check question**: Why might freezing the vision encoder during DPO be suboptimal for detailed video caption ranking?

### Concept: Ranking Losses (Plackett‑Luce vs. Hinge)
- **Why needed here**: The core training signal is a listwise ranking loss. Knowing how Plackett‑Luce differs from pairwise losses (like hinge) explains why it better models total order and why experiments compared them.
- **Quick check question**: What is the key mathematical difference between the Plackett‑Luce loss and a margin‑free hinge loss for ranking?

## Architecture Onboarding
### Component map
1. Video Input → Vision Encoder → Visual embeddings.
2. Caption Chain Generator (offline, LLM‑based) → totally ordered caption chain \([c_1, c_2, ..., c_n]\).
3. VLM (trainable): Vision encoder + LLM backbone (e.g., PerceptionLM, Qwen2.5‑VL) with LoRA adapters. Input: video + prompt "Rank captions: ..." Output: scores/log‑probabilities for each caption index.
4. Loss Module: Plackett‑Luce ranking loss + next‑token prediction loss (weight 0.1). Loss computed over predicted ranking vs. ground‑truth order.
5. Evaluation Suite: LLM‑as‑a‑judge (relevance, descriptiveness, temporal consistency), human eval, downstream QA (LF‑MCQA), TempCompass.

### Critical path
1. **Data Prep**: Generate `Rcc` dataset — for each video, recaption to get detailed `c_1`, then iteratively degrade using LLM with error‑type conditioning.
2. **Training Loop**: For each batch, feed video and caption chain to VLM, get scores \(s_i\), compute Plackett‑Luce loss \(L = -\sum_{i=1}^n \log( \frac{\exp(s_i)}{\sum_{j=i}^n \exp(s_j)} )\) plus NTP loss on \(c_1\).
3. **Joint Fine‑tuning**: Update *both* vision encoder and LLM via LoRA. Gradient from ranking loss must reach vision encoder.
4. **Evaluation**: Test on captioning benchmarks (PE‑Video, MSR‑VTT, VDC, ARGUS) and LF‑MCQA. Compare to DPO (uses only top‑2), MPO (uses all but ignores order), SFT.

### Design tradeoffs
- **Off‑policy vs. On‑policy Data**: Off‑policy (this work) allows reuse across models and error‑type biasing, but may be less tailored. On‑policy (e.g., response improvement) is model‑specific and costly to regenerate.
- **Chain Length**: Longer chains give more gradient signal but increase memory/compute. Figure 4 shows monotonic gains; scaling limit is open.
- **Loss Choice**: Plackett‑Luce vs. hinge vs. RankNet. Plackett‑Luce best; hinge avoids margin‑widening but underperforms. NTP loss essential to prevent generation collapse.
- **Error Conditioning**: Uniform error‑type sampling vs. free degradation. Conditioning yields better results by ensuring diversity and controllability.

### Failure signatures
1. **Chain order invalid**: LLM fails to preserve previous errors or inadvertently corrects them → human eval shows <89% total order. Fix: Stricter LLM prompting, heuristic verification.
2. **Vision encoder frozen**: Ranking gains vanish. Symptom: performance ≈ DPO/SFT. Fix: Ensure vision encoder parameters are included in optimizer.
3. **Generation collapse**: Model outputs degenerate/short captions. Symptom: low fluency or n‑gram overlap. Fix: Increase NTP loss weight (default 0.1).
4. **Benchmark mismatch**: Gains on LLM‑judge metrics but not on n‑gram (METEOR/ROUGE). Indicates LLM‑judge sensitivity to subtle differences; n‑gram may be insufficient.

### First 3 experiments
1. **Replicate Ranking vs. DPO**: Train PLM/Qwen on `Rcc‑PVD` with ranking, DPO (top‑2), MPO, SFT. Evaluate on PE‑Video LLM‑judge metrics. Expect ranking to win on relevance/descriptiveness/temporal consistency.
2. **Ablate Vision Encoder Fine‑tuning**: Train ranking model with vision encoder frozen vs. trainable. Verify massive drop when frozen (Table 7). This is the key diagnostic.
3. **Vary Chain Length**: Train ranking models with chain lengths {2, 3, 5, 10}. Plot metrics vs. length (like Figure 4). Expect monotonic improvement, confirming chain length as a lever.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: What are the practical and theoretical limits of chain length scaling for ranking optimization—at what point do longer caption chains yield diminishing returns or become computationally prohibitive, and does performance eventually saturate or degrade?
- **Basis in paper**: (Sec. 4.3) "Further exploration of the scalability limits with extended chain lengths remains a promising direction for future research" and Figure 4 shows consistent but potentially sublinear gains with longer chains.
- **Why unresolved**: The paper demonstrates improvements with longer chains but does not investigate asymptotic behavior, optimization stability, or task‑specific optimal lengths.
- **What evidence would resolve it**: Systematic experiments varying chain length (e.g., 2–20 captions) across multiple model scales and datasets, measuring performance relative to compute cost, alongside analysis of gradient dynamics or ranking loss landscapes at different chain lengths.

### Open Question 2
- **Question**: Why does vision encoder finetuning prove essential for ranking‑based DPO but largely unnecessary for standard (binary) DPO or SFT in video‑text alignment, and what specific visual representations are learned during joint optimization that enable finer‑grained discrimination?
- **Basis in paper**: (Sec. 4.3, Tab. 7) "Crucially, gains vanish if the vision encoder is frozen" for ranking, while SFT and DPO show minimal sensitivity; the authors suggest ranking requires "fine‑grained visual representations" but do not explain the mechanistic difference.
- **Why unresolved**: The paper presents the empirical result but lacks ablation studies or representational analysis (e.g., probing, attention visualization) to identify what the vision encoder learns under ranking that it does not under binary objectives.
- **What evidence would resolve it**: Comparative analysis of frozen vs. tuned vision encoder representations (e.g., via linear probing on fine‑grained visual attributes, gradient‑based attribution, or analysis of attention maps) for models trained with ranking vs. DPO; controlled experiments varying the difficulty of visual distinctions in caption chains.

### Open Question 3
- **Question**: Can the proposed caption degradation and ranking paradigm be effectively adapted to an on‑policy setting where chains are constructed from the target model’s own generations, and would such adaptation yield further improvements by tailoring the difficulty to the model’s current weaknesses?
- **Basis in paper**: (Limitations, Appendix H) "Adapting our method to modify model‑generated captions in an on‑policy manner constitutes a promising direction for future research" — current data is generated off‑policy using a fixed LLM.
- **Why unresolved**: The paper compares off‑policy ranking to some on‑policy DPO baselines but does not explore on‑policy chain generation; off‑policy chains may not optimally challenge a specific model’s failure modes.
- **What evidence would resolve it**: Implementation of an on‑policy variant where the target model generates initial captions, an LLM degrades them into chains, and the model is trained on its own chains; comparison to off‑policy chains across model iterations to measure adaptation benefits and potential pitfalls like distribution collapse.

### Open Question 4
- **Question**: What is the theoretical relationship between ranking granularity (i.e., total order vs. binary preferences) and improvements in visual grounding fidelity—does maximizing the probability of correct total orders inherently encourage the model to encode more precise visual detail, and can this be formalized in a reward model framework?
- **Basis in paper**: (inferred) The authors argue that binary DPO fails to capture that "lower‑ranked captions can remain visually faithful," implying that ranking forces discrimination along a continuum of visual accuracy, but no formal model is provided.
- **Why unresolved**: The paper uses Plackett‑Luce DPO as a tool but does not analyze why its gradient updates differently shape visual‑language representations compared to binary Bradley‑Terry; the connection between ranking loss and learned visual specificity remains intuitive rather than derived.
- **What evidence would resolve it**: Theoretical analysis deriving the expected gradient difference between ranking and binary objectives under assumptions about visual error types; empirical measurement of visual detail retention in generated captions (e.g., precision/recall of visual attributes) correlated with ranking performance; controlled experiments with synthetic chains where visual fidelity is quantifiable.

### Open Question 5
- **Question**: How does the choice of LLM for caption chain generation (e.g., Claude 3.7 Sonnet vs. GPT‑OSS) affect the quality and difficulty of the ranking data, and what properties of the generator LLM are most critical for producing chains that robustly train VLMs?
- **Basis in paper**: (inferred) The authors use Claude 3.7 Sonnet for main data generation and GPT‑OSS for some ablations, noting judge correlations but not analyzing generator impact; the degradation strategy relies on LLM ability to introduce precise visually‑grounded errors while preserving structure.
- **Why unresolved**: It is unclear whether chain effectiveness is tied to the generator’s visual reasoning, linguistic style, or error diversity; potential biases in the generator’s error types could shape what the VLM learns.
- **What evidence would resolve it**: Generate identical caption chains with multiple LLMs of varying capabilities and train/evaluate VLMs on each; analyze error type distributions and chain validity rates per generator; measure correlation between generator’s own visual captioning accuracy and the usefulness of its generated chains.

## Limitations
- **Implementation details missing**: Exact Claude prompts for chain generation and LLM‑as‑judge scoring, LoRA hyperparameters (rank, alpha, target modules), and handling of variable chain lengths are not specified.
- **Chain validation dependence**: Caption chains rely on the LLM’s ability to insert errors without altering structure; only 89% of chains maintained total order, with 3% containing generation noise, risking imperfect training signals.
- **Evaluation reliance on single LLM judge**: The primary metrics come from one LLM (Claude 3.7 Sonnet), which may have inherent biases; cross‑judge calibration was limited to a single additional model.

## Confidence
- **Ranking optimization superiority**: **High** (consistent improvements across LLM‑judge, human eval, and downstream QA).
- **Necessity of joint vision‑language fine‑tuning**: **High** (clear ablation in Table 7).
- **Total order from systematic degradation**: **Medium** (depends on LLM behavior; 3% noise observed; 89% order validity).
- **Longer chains yield gains**: **Medium** (monotonic improvement observed up to length 10, but scaling limits unknown).

## Next Checks
