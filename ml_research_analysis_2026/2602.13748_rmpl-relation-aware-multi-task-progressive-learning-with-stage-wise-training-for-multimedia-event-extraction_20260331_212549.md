# RMPL: Relation-aware Multi-task Progressive Learning with Stage-wise Training for Multimedia Event Extraction

## Quick Facts
- **arXiv ID:** 2602.13748
- **Source URL:** https://arxiv.org/abs/2602.13748
- **Reference Count:** 40
- **Primary Result:** A two-stage framework that warms up a vision-language model with heterogeneous unimodal and relational supervision, then fine-tunes on MEE, achieving absolute F1 gains up to 10.17% (multimedia mention) and 22.87% (argument role) on M2E2.

## Executive Summary
Multimedia Event Extraction (MEE) suffers from a lack of task-specific training annotations. RMPL addresses this low-resource challenge through a progressive two-stage training paradigm. Stage I performs a unified "warm-up" using heterogeneous supervision from unimodal text/image event extraction and multimedia relation extraction, forcing the model to learn shared, modality-agnostic event representations under a single schema. Stage II then specializes this generalist model for the specific MEE tasks of event mention and argument role extraction using mixed text-image data. This approach consistently outperforms baselines and prior state-of-the-art on the M2E2 benchmark across multiple vision-language models, demonstrating effective knowledge transfer from related source tasks.

## Method Summary
RMPL is a two-stage framework for training Vision-Language Models (VLMs) on Multimedia Event Extraction without in-task training data. **Stage I (Unified Schema Warm-up):** The VLM is trained to generate linearized outputs for three related source tasks—textual event extraction (ACE2005), visual event extraction (SWiG), and multimedia relation extraction (MNRE)—using a single decoder head and a control token that specifies the task schema. The combined loss `L_I = αL_t + βL_i + λL_r` encourages shared, event-centric representations across modalities and relations. **Stage II (Fine-grained Specialization):** The warmed-up checkpoint is fine-tuned separately on the target MEE objectives (event mention classification and argument role labeling) using a mixed corpus of text and image examples, allowing the model to adapt its decision boundaries to the M2E2 output format and evaluation criteria (e.g., bounding box grounding).

## Key Results
- **Consistent Gains:** RMPL improves over baselines and prior SOTA in text-only, image-only, and multimedia settings on the M2E2 benchmark.
- **Large Absolute Improvements:** With Qwen2-VL-7B, achieves +10.17% F1 for multimedia event mention and +22.87% F1 for argument role extraction.
- **Ablation Support:** Removing relation supervision (`λ=0`) or skipping the warm-up stage (`w/o Warm`) leads to significant performance drops, validating the two-stage design and the role of cross-modal relational knowledge.

## Why This Works (Mechanism)

### Mechanism 1: Heterogeneous Supervision Builds Shared Representations
- **Claim:** Training on unimodal event extraction and multimedia relation extraction under a unified schema establishes shared, modality-agnostic event primitives.
- **Mechanism:** The linearized schema forces the model to generate structured outputs (event types, arguments, relations) from text, images, and cross-modal data. This exposes the backbone to event semantics in isolation and relational patterns across modalities, encouraging a common representation space.
- **Core Assumption:** Fundamental event semantics (type, argument roles) are modality-independent (e.g., textual "arrest" and visual "detention" share a core concept).
- **Evidence Anchors:** Abstract states the use of heterogeneous supervision for shared representations. Section 4.2 details the conditional generation formulation `pθ(Y|D, τ)`. Ablations showing benefit from including relation extraction support this.

### Mechanism 2: Progressive Specialization Adapts to Target Task
- **Claim:** Stage II fine-tuning with mixed-modality data specializes the general representations from Stage I to MEE's specific output formats and grounding requirements.
- **Mechanism:** Starting from the warmed model, separate fine-tuning on event mention and argument role extraction recalibrates output heads for M2E2's evaluation metrics (e.g., IoU for visual arguments) while retaining cross-modal understanding.
- **Core Assumption:** Stage I representations contain sufficient general event knowledge but require task-specific tuning.
- **Evidence Anchors:** Section 4.3 describes Stage II's role. Section 5.2 shows consistent improvement from "Warm-up" to "RMPL (full)". Section 5.4.1 ablation ("w/o Warm") confirms Stage II adds value.

### Mechanism 3: Relation Extraction Provides Structural Inductive Bias
- **Claim:** Incorporating multimedia relation extraction as an auxiliary task improves argument disambiguation and cross-modal grounding.
- **Mechanism:** Relation triples (`<head, relation, tail>`) model dependencies between entities across text and image. Predicting these forces the model to learn structured relational knowledge directly applicable to argument structure (e.g., distinguishing Agent from Instrument).
- **Core Assumption:** Relational structure is a crucial, underspecified inductive bias for event extraction.
- **Evidence Anchors:** Abstract includes relation extraction. Section 4.2 loss `L_I` includes `L_r`. Ablations ("w/o RE") in Section 5.4.1 show performance drops, especially for argument roles.

## Foundational Learning
- **Concept: Multi-Task Learning (Heterogeneous Supervision)**
  - *Why needed:* RMPL jointly trains on distinct source tasks (text EE, visual EE, relation extraction) to bootstrap a model for an unannotated target task (MEE). Understanding gradient interactions and shared vs. task-specific parameters is key.
  - *Quick Check:* In loss `L_I = αL_t + βL_i + λL_r`, what is the risk of setting `λ` too high relative to `α, β`?
- **Concept: Transfer Learning & Progressive Training**
  - *Why needed:* The two-stage pipeline (warm-up → specialization) is a specific transfer form. One must reason about what knowledge transfers (general event semantics, cross-modal alignment) vs. what is learned de novo (task-specific heads, MEE format).
  - *Quick Check:* Why not simply train a single model on mixed data from Stage I and Stage II objectives simultaneously?
- **Concept: Unified Schema / Prompt Engineering for Structured Output**
  - *Why needed:* RMPL uses a linearized schema as a common interface for all supervision sources. This design determines what information is generated and how heterogeneous data is rendered into a consistent signal.
  - *Quick Check:* How would the failure mode differ if the schema for textual event extraction used a different slot order than for visual event extraction?

## Architecture Onboarding
- **Component map:**
  Backbone VLM (e.g., Qwen2-VL-7B) -> Unified Schema Generator (Stage I, with control token τ) -> [Save Checkpoint] -> Task-Specific Heads (Stage II for EM & AR) -> M2E2 Evaluation
- **Critical path:** Preprocess external datasets (ACE, SWiG, MNRE) -> Train Stage I with unified schema & mixed loss (400 steps, LR 1e-5) -> Save warmed checkpoint -> Load & fine-tune Stage II heads on mixed text/image for EM and AR (800 steps, LR 3e-5) -> Evaluate on M2E2.
- **Design tradeoffs:**
  - **Mixing Ratios (α:β:λ):** Balanced (1:1:1) optimal per Figure 3. Too high λ biases toward abstract patterns; too low weakens alignment.
  - **Stage Duration:** 400 warm-up vs. 800 fine-tune steps. More warm-up risks overfitting to source tasks; fewer risks unstable representations.
  - **Schema Design:** Exact linearization format (key names, order) is crucial but not detailed, a key implementation gap.
- **Failure signatures:**
  - **Poor multimedia F1 but good unimodal F1:** Indicates failed cross-modal alignment. Check if λ was effective or if warm-up representations are modality-specific.
  - **High recall, low precision in arguments:** Over-generation. Likely insufficient Stage II specialization or noisy data mixing.
  - **Stable performance from Warm-up to full RMPL:** Stage II had no effect. Check LR, head init, or if backbone was frozen.
- **First 3 experiments:**
  1.  **Reproduce Warm-up Baseline:** Train only Stage I (α:β:λ=1:1:1) on ACE+SWiG+MNRE. Evaluate zero-shot on M2E2 text-only and image-only mention F1. Expect moderate gains over non-warmed VLM.
  2.  **Ablation: Remove Relation Supervision (λ=0):** Train Stage I with only αL_t + βL_i, then full RMPL Stage II. Expect a significant drop in multimedia argument role F1, validating Mechanism 3.
  3.  **Mixing Ratio Sweep:** Train Stage I with λ ∈ {0.5, 1.0, 2.0} (α=β=1), then full RMPL. Replicate Figure 3's U-shaped curve to confirm 1:1:1 optimum and sensitivity.

## Open Questions the Paper Calls Out
- **Open Question 1:** Can RMPL be generalized to other multimedia IE tasks (e.g., multimodal NER, temporal ordering)?
  - *Basis:* Section 6 states intent to extend RMPL broadly.
  - *Why Unresolved:* Only evaluated on MEE; other tasks may have different structures and supervision needs.
  - *Resolution Evidence:* Systematic evaluation on other multimedia IE benchmarks with appropriate adaptations.
- **Open Question 2:** How to incorporate wider MEE objectives (temporal, causal links) into the unified framework without conflict?
  - *Basis:* Section 6 plans to incorporate more objectives for richer joint supervision.
  - *Why Unresolved:* Risk of task interference, schema complexity, optimization issues; design space unexplored.
  - *Resolution Evidence:* Controlled incremental addition of objectives, measuring MEE performance and developing conflict mitigation strategies.
- **Open Question 3:** What is the optimal mixing proportion of heterogeneous sources during Stage I, and can it be adaptive?
  - *Basis:* Section 5.4.2 tests fixed ratios (1:1:0.5, 1:1:1, 1:1:2) with 1:1:1 best, but no adaptive method.
  - *Why Unresolved:* Optimal ratio likely varies with model/data/target; manual tuning is inefficient.
  - *Resolution Evidence:* Develop an automatic mixing method (e.g., gradient-based, uncertainty weighting) validated across settings.
- **Open Question 4:** How robust is RMPL to domain shifts between source (ACE, SWiG, MNRE) and target (M2E2) data?
  - *Basis:* Inferred dependence on external datasets; no analysis of domain mismatch sensitivity.
  - *Why Unresolved:* Domain shifts could weaken transferred representations; real-world scenarios may have scarce/mismatched source data.
  - *Resolution Evidence:* Controlled domain shift experiments (alternative corpora, simulated noise) and exploration of domain adaptation techniques within RMPL.

## Limitations
- **Schema & Data Mixing Underspecified:** Exact linearized prompt templates for unified schema and the precise strategy for constructing mixed Stage II data are not provided, blocking faithful reproduction.
- **Source-Task Alignment Risk:** The mapping process from ACE2005/SWiG/MNRE schemas to M2E2's 8 event types and roles is unclear; misalignment could explain performance variance.
- **Representation Causality Inferred:** The proposed mechanisms are supported by ablations but lack direct probing analyses to causally link representations to performance gains.

## Confidence
- **Performance Gains (High):** Reported absolute F1 improvements on standard M2E2 benchmark are specific and consistent across VLMs; internal ablations support staged approach.
- **Mechanism Attribution (Medium):** Plausible roles for heterogeneous supervision and progressive training are supported by ablations (e.g., removing RE hurts), but without representation probing, causality is inferred.
- **Reproducibility (Low):** Key implementation details (prompts, data mixing protocol) are omitted; described hyperparameters may be sensitive, and neighboring work uses similar motifs without validating RMPL's specific design.
