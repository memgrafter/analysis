# Optimal Bayesian Stopping for Efficient Inference of Consistent LLM Answers

## Quick Facts
- arXiv ID: 2602.05395
- Source URL: https://arxiv.org/abs/2602.05395
- Reference count: 40
- Primary result: A Bayesian stopping rule with L-aggregation (L=3) reduces LLM calls by up to 50% while maintaining or improving accuracy compared to prior-free baselines.

## Executive Summary
The paper tackles the computational inefficiency of improving LLM reasoning accuracy via repeated sampling (self-consistency). It proposes a Bayesian stopping rule that leverages prior knowledge about answer distributions to decide when enough consistency is reached, thus avoiding wasteful fixed-budget sampling. Because exact Bayesian updating is intractable for many candidate answers, the authors introduce an efficient L-aggregated approximation that tracks only the L-1 most frequent answers. They prove theoretically that L=3 is sufficient for asymptotic optimality and strictly dominates prior-free baselines. Empirically, L=3 matches the sample efficiency of the exact Bayesian method (which is far slower) while cutting the number of required LLM calls by up to 50% compared to the prior-free adaptive baseline, and even improves answer accuracy in some cases.

## Method Summary
The method frames mode identification as a sequential hypothesis test. After each LLM sample, the algorithm updates the posterior probability that the most frequently observed answer is the true mode, using a prior over answer probabilities derived from historical data. Sampling stops once this posterior exceeds 1−δ. To avoid the factorial complexity of exact inference over all possible answer assignments, the authors propose L-aggregation: they keep explicit counts for only the top L−1 most frequent answers and aggregate the rest into an “other” category. This reduces the state space to O(K^L) terms. Theoretical analysis shows that for L≥3, the asymptotic stopping time rate matches that of the exact Bayesian rule, and under prior uncertainty (a set of candidate priors) L≥3 strictly outperforms prior-free methods. The algorithm is implemented via dynamic programming to compute the aggregated posterior efficiently.

## Key Results
- L=3 achieves the same asymptotic sample efficiency as the exact Bayesian method while being computationally feasible.
- Compared to the prior-free adaptive baseline (ASC), L=3 reduces the number of LLM calls by up to 50% at high confidence levels, with equal or better mode and answer accuracy.
- Under prior uncertainty, L≥3 maintains a strict asymptotic advantage over prior-free methods, whereas L=2 can perform arbitrarily worse when candidate priors are hard to distinguish.

## Why This Works (Mechanism)
### Mechanism 1
*Claim:* Leveraging an informative Bayesian prior over answer probabilities allows an adaptive stopping rule that requires fewer samples than prior-free methods to achieve a target confidence in the mode.
*Mechanism:* The stopping decision is framed as sequential hypothesis testing. After each sample, the posterior probability that the most frequent observed answer is the true mode is computed using Bayes' rule. Sampling stops once this posterior exceeds 1−δ. This uses prior knowledge about typical answer distributions (e.g., peaked vs. flat) learned from historical data to calibrate confidence more efficiently than a non-informative (Beta) prior, which demands more samples to distinguish a true leader.
*Core assumption:* The prior distribution over answer probabilities for a given question type is stable and can be estimated from a related dataset. The generative process for LLM answers is IID given the true answer distribution.
*Evidence anchors:*
  - Abstract: "leverage Bayesian prior information to save on sampling costs, stopping once sufficient consistency is reached."
  - Section 2.1: Formulation of the stopping time n⋆ as the first time the posterior P(H1 | Cn) ≥ 1−δ.
  - Section 4.1: Extension to uncertain prior with a hyper-prior over ΠM.
  - Corpus: BEACON (paper_id=64284) explores Bayesian stopping but without the L-aggregation insight and its theoretical guarantees.
*Break condition:* If the prior is severely misspecified for a new query (e.g., the true answer distribution is not in the candidate set ΠM and is very different), the Bayesian rule may stop prematurely with high confidence in a wrong answer or require excessive samples.

### Mechanism 2
*Claim:* The factorial complexity of computing the exact posterior (over all possible answer assignments) can be reduced to polynomial time O(K^L * n^2) with negligible asymptotic loss in sample efficiency by tracking only the top L−1 most frequent answers and aggregating the rest ("L-aggregation"), and L=3 is sufficient for asymptotic optimality.
*Mechanism:* The exact posterior requires summing over all injective mappings ψ from observed distinct answers to the K latent answer labels. The L-aggregated posterior condenses the count-of-counts state Cn into C_L^n by keeping explicit counts only for the top L−1 frequencies, lumping all others. This collapses the number of terms from O(K!) to O(K!/(K−L+1)!) ≈ O(K^L). The key theoretical result is that the expected stopping time under the L-aggregated rule converges to the exact optimal rate as δ→0 for any L≥3, because the log-likelihood ratio needed for stopping depends only on the top two frequencies in the limit.
*Core assumption:* The stopping decision depends primarily on the ratio of the top two observed frequencies and their absolute difference, not on the detailed structure of the long tail of low-frequency answers. The answer probability vector is ordered p1 > p2 ≥ ... .
*Evidence anchors:*
  - Section 3.1: Definition of C_L^n and the approximation P(H1 | C_L^n).
  - Section 3.3: Theorem 3.1 states lim_{δ→0} E[n⋆,L]/log(1/δ) = 1/((p1−p2) log(p1/p2)) for L≥3, matching the exact posterior rate.
  - Table 1: Empirically, L=3 achieves sample counts nearly identical to L=K (exact) across confidence levels, while L=2 is less efficient.
  - Corpus: BEACON (paper_id=64284) uses a related but different approximation (tracking only the top answer’s count) and lacks the L=3 optimality guarantee.
*Break condition:* If the answer distribution has a very heavy tail where p3 is not negligible compared to p1−p2 (e.g., p1≈p2≈p3), the L=3 approximation may lose more information, leading to a higher (worse) finite-sample stopping time than the exact rule, though it remains asymptotically optimal.

### Mechanism 3
*Claim:* Even under prior uncertainty (the true prior is one of M candidates), an L≥3 aggregated posterior strictly dominates prior-free baselines in asymptotic stopping time, while L=2 can perform arbitrarily worse if the prior set contains hard-to-distinguish distributions.
*Mechanism:* With a hyper-prior over candidate priors ΠM, the posterior is a weighted mixture over the M exact posteriors. The L-aggregation is applied within each prior. For L=2, the stopping time rate depends on a quantity J2,m†(p1) that combines D_KL(p1||p2,m) and an additional term when the odds ratio of the true prior is between those of the best and second-best candidate. This term can blow up if p1 and p2 are close under the best-matching prior, making L=2 arbitrarily inefficient. For L≥3, the rate depends on a KL divergence between compressed probability vectors (p1,...,p_{L−1}, 1−∑_{i=1}^{L−1} p_i) that is always strictly smaller than the prior-free rate, guaranteeing Pareto improvement.
*Core assumption:* The candidate prior set ΠM is fixed and known. The true prior π is one of the candidates (or can be approximated by one). The same L-aggregation properties hold within each prior.
*Evidence anchors:*
  - Section 4.1: Definition of P_{ΠM}(H1 | C_L^n) and the stopping time n⋆,L_{ΠM}.
  - Theorem 4.1: For L=2, the asymptotic rate is 1/J2,m†(p1). For L≥3, it is 1/J_L2,m†(pL). The text notes J_L2,m†(pL) equals the known-prior rate when the best prior matches the true one (m† = m⋆), and is always < the prior-free rate.
  - Remark 5: Example showing L=2 can yield a rate ~555 vs. prior-free ~6.64 when priors are confused.
  - Table 2: Synthetic data with easy/hard-to-distinguish priors shows L=3 (uncertain) maintains efficiency vs. L=2 (uncertain) which degrades significantly on the hard prior.
  - Corpus: CGES (paper_id=71175) and BEACON consider uncertain priors differently without the L-aggregation analysis.
*Break condition:* If the candidate prior set is very large and contains many similar distributions (small m† gap), the benefit over prior-free diminishes even for L≥3. If the true prior is not well-approximated by any π_m ∈ ΠM, performance may degrade.

## Foundational Learning
- **Concept: Sequential Hypothesis Testing (Wald, 1992)**
  - *Why needed here:* The paper frames mode identification as sequentially deciding whether a hypothesis (answer A is the mode) is true with high confidence, minimizing samples. This underpins the Bayesian stopping rule and the asymptotic analysis of stopping times.
  - *Quick check:* What is the key difference between a sequential test and a fixed-sample test in terms of expected sample size for a given error rate?

- **Concept: Self-Consistency for LLMs (Wang et al., 2022)**
  - *Why needed here:* This is the application context. The goal is to identify the most consistent (mode) answer from multiple LLM samples efficiently. Understanding the baseline (fixed-budget majority voting) is essential to see the value of adaptive stopping.
  - *Quick check:* What is the primary computational cost of standard self-consistency, and why is a fixed budget potentially wasteful?

- **Concept: KL Divergence & Sanov's Theorem**
  - *Why needed here:* The asymptotic stopping time rates are expressed in terms of KL divergences between Bernoulli or multinomial distributions arising from the likelihood ratios. Sanov's theorem is used in the proof (Appendix B) to characterize the large deviations rate for the "other" answers' allocation.
  - *Quick check:* What does a smaller KL divergence D_KL(p1||p2) imply about the ease of distinguishing two answer distributions?

- **Concept: Bayesian Prior Elicitation**
  - *Why needed here:* The method relies on an informative prior over answer probabilities; understanding how to obtain such a prior from historical data is crucial for practical deployment.
  - *Quick check:* How might one construct a prior distribution for a new question type given only a small set of similar past questions?

- **Concept: Multinomial Counting & Sufficiency**
  - *Why needed here:* The state of the sequential test is captured by the counts of answers; the L-aggregation compresses this sufficient statistic while retaining asymptotic optimality.
  - *Quick check:* Why are the raw counts of each answer a sufficient statistic for the mode under IID sampling?

## Architecture Onboarding
*Component map:*
Prior Estimator -> LLM Sampler -> Counter & Sorter -> L-Aggregator -> Posterior Computer -> Stopping Threshold Check -> (loop back to LLM Sampler until stop)

*Critical path:*
1. Prior Estimator computes or selects prior π or hyper-prior λ from historical data.
2. LLM Sampler generates an answer; Counter & Sorter updates counts.
3. L-Aggregator compresses counts to C_L^n (top L−1 frequencies and residual).
4. Posterior Computer takes C_L^n and prior(s) and computes P(H1|C_L^n) via dynamic programming (Algorithm 2).
5. Stopping Threshold Check compares posterior to 1−δ; if not met, return to step 2.
6. When threshold met, output the most frequent observed answer.

*Design tradeoffs:*
- **L selection:** L=2 is fastest (O(K^2 n^2)) but can suffer large sample cost under prior uncertainty (Theorem 4.1). L=3 is the sweet spot: near-optimal sample efficiency with minimal extra cost vs. L=2. L=K (exact) is intractable for large K.
- **Prior knowledge:** Using a single known prior is simplest and most efficient. Using a candidate set ΠM handles uncertainty but adds a multiplicative factor M to posterior computation and may still be misled if ΠM is large/poorly separated.
- **Confidence δ:** Smaller δ (higher confidence) requires more samples. The Bayesian rule correctly adapts n to δ; prior-free rules often over-sample at high confidence.
- **Answer set size K:** The O(K^L) complexity means even L=3 becomes costly if K is huge (hundreds). In practice, K is limited by distinct LLM outputs per question, often <50.

*Failure signatures:*
- **Mode collapse in prior:** If historical data shows one answer dominates overwhelmingly for a question type, the prior p1 will be high, leading to very fast stopping. This is correct if the new query is similar, but catastrophic if the new query's true mode is different (prior misspecification).
- **L=2 under uncertain priors:** As shown in Remark 5 and Table 2 (hard prior), L=2 can require vastly more samples than L≥3 or prior-free when top-two probabilities are close across candidate priors (p1≈p2 under some π_m).
- **Dynamic K:** The analysis assumes fixed K. If the LLM's potential answer vocabulary is very large and many rare answers appear, the aggregation L might need to be larger to capture the effective "gap" between the top contenders.
- **Non-IID samples:** The theory assumes IID draws from a fixed π. If the LLM's distribution drifts over time (e.g., due to temperature decay or prompt variation), the posterior updates become mis-calibrated.

*First 3 experiments:*
1. **Synthetic prior validation (Section 5.2, Table 1):** With a fixed known prior π=(0.5,0.2,0.1,0.1,0.05,0.03,0.01,0.01), compare L=2,3,4 vs. exact (L=K) and prior-free (ASC) over varying 1−δ. Verify L=3 matches exact sample efficiency and beats ASC, while L=2 is slightly worse. Measures: Mode Accuracy, Num. Gen.
2. **Synthetic uncertain prior (Section 5.2, Table 2):** With two candidate priors (easy vs. hard to distinguish), compare L=2 and L=3 under the uncertain-prior algorithm vs. ASC. Show L=3 maintains efficiency and accuracy on the hard prior, while L=2 degrades dramatically. Measures: Mode Acc., Num. Gen. per prior subset.
3. **Real-world FEval-TTC (Section 5.3, Table 3):** On CommonsenseQA with Qwen-2.5-72B, GPT-4o mini, LLaMA-3.1-405B. Construct known prior (per-query empirical distribution) and uncertain prior (from train/test split). Compare L=2,3 (both settings) to ASC. Show L=3 (uncertain) matches ASC's mode accuracy at high confidence while using far fewer samples (e.g., 1 vs 5+ at 1−δ=0.95), and maintains answer accuracy. Measures: Answer Acc., Mode Acc., Num. Gen.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** When does the true answer belong to runner-up candidates rather than the mode, and what distributional properties of LLM outputs cause this?
- **Basis in paper:** [explicit] The authors explicitly state: "Understanding exactly when and why the runner-ups outperform the mode remains a compelling subject for future investigation for efficient inference of LLM answers."
- **Why unresolved:** This insight could yield improved stopping rules that consider top‑k candidates, potentially increasing accuracy without extra sampling.
- **What evidence would resolve it:** A theoretical characterization linking the probability of the true answer being in the top‑2 to features like probability gaps, entropy, or reasoning path diversity, validated across diverse LLMs and reasoning tasks.

### Open Question 2
- **Question:** How robust is the L‑aggregated stopping rule to prior misspecification or poor estimation from limited historical data?
- **Basis in paper:** [inferred] The paper assumes an exactly known prior or a candidate prior set; no analysis of robustness to errors in the prior is provided.
- **Why unresolved:** In practice, priors must be estimated, and misspecification could cause over‑ or under‑stopping, damaging both efficiency and final accuracy.
- **What evidence would resolve it:** Sensitivity experiments varying prior quality and quantity, together with finite‑sample theoretical bounds for the posterior approximation under misspecification.

### Open Question 3
- **Question:** Is L=3 universally optimal for finite‑sample performance, or can an adaptive aggregation level improve efficiency?
- **Basis in paper:** [inferred] While the authors prove L=3 is asymptotically optimal, they fix L=3 in experiments and do not explore whether larger or adaptive L might reduce sample complexity in realistic non‑asymptotic regimes.
- **Why unresolved:** Finite‑sample tradeoffs might differ; using more groups (L>3) could capture useful information for early stopping on hard instances.
- **What evidence would resolve it:** Systematic comparisons of L=2,3,4 and potentially adaptive L‑selection across confidence levels and datasets, measuring both number of LLM calls and computational overhead.

### Open Question 4
- **Question:** How can one automatically construct a compact, informative candidate prior set ΠM from a large pool of historical question distributions?
- **Basis in paper:** [inferred] The method requires a given ΠM, and the authors note that the prior is more valuable when ΠM is small and well‑separated; however, no algorithm for selecting such a set is proposed.
- **Why unresolved:** Real‑world scenarios may involve a vast corpus of past questions; selecting a representative subset that retains Bayesian signal while limiting set size is critical for practical benefit.
- **What evidence would resolve it:** Algorithms that cluster or select priors based on divergence measures, supported by theoretical guarantees on their regret relative to using the full collection of candidates.

## Limitations
- **Implementation ambiguity:** The dynamic programming for ˜S_ψ (Algorithm 2) is described but not fully detailed; small errors could invalidate posterior calculations.
- **Reproducibility gaps:** Real‑world experiments on FEval‑TTC lack specifics (random seeds, number of candidate priors M, training set size, hyper‑prior details), preventing exact replication.
- **Theoretical assumptions:** The analysis assumes IID LLM outputs, a fixed finite answer space K, and an ordered probability vector. Violations (e.g., drifting distribution, many rare answers) may break asymptotic guarantees.
- **Prior uncertainty:** The benefit of L≥3 hinges on the candidate set ΠM containing a prior close to the true one; otherwise performance can degrade, as hinted by the L=2 failure case.
