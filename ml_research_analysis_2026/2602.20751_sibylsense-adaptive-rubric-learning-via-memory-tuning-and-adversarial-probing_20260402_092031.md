# SibylSense: Adaptive Rubric Learning via Memory Tuning and Adversarial Probing
## Quick Facts
- arXiv ID: 2602.20751
- Source URL: https://arxiv.org/abs/2602.20751
- Reference count: 38
- Primary result: Automates fine-grained rubric creation via memory tuning and adversarial probing, improving discriminative power and downstream RL win rates.

## Executive Summary
SibylSense tackles the challenge of scaling robust reward design for open-ended generation by automating the creation of consistent, fine-grained evaluation rubrics. It employs a frozen rubric generator guided by a tunable memory bank of validated rubric items, scored by a verifier that discriminates between expert references and candidate answers. The system alternates between inner-loop memory tuning (updating items using verification gaps) and an outer adversarial candidate refresh loop (training an adversary to expose rubric blind spots). On medical QA (RaR-Medicine) and document summarization (GovReport), iterative memory tuning improves rubric discriminative power, and the resulting rubrics yield higher downstream reinforcement learning win rates against base models, with adversarial refresh providing incremental gains.

## Method Summary
SibylSense uses a frozen rubric generator to produce candidate rubric items, which are stored in a fixed-size memory bank. A verifier scores each item by its ability to distinguish expert reference answers from model-generated candidates. Inner-loop memory tuning updates the memory bank by replacing low-value items with new ones that better address verification gaps. Outer-loop adversarial refresh trains an adversary to generate challenging candidate answers that expose weaknesses in the current rubric set; these hard candidates replace easy ones in the pool, driving continuous rubric expansion. This closed loop iteratively refines rubrics toward greater discriminative capacity.

## Key Results
- Iterative memory tuning increases rubric discriminative power (preference accuracy rises with iterations), outperforming few-shot and original rubrics on both RaR-Medicine and GovReport.
- SibylSense rubrics yield higher downstream RL win rates against base models (e.g., 60.6% vs. 51.2% on RaR-Medicine).
- Adversarial candidate refresh provides additional gains beyond memory tuning alone.

## Why This Works (Mechanism)
The frozen generator ensures rubric diversity without costly retraining, while the tunable memory bank focuses on high-value items. Verification gaps directly target weakness in discriminative ability, guiding precise updates. Adversarial refresh uncovers blind spots by forcing rubrics to evaluate challenging cases, preventing overfitting to easy examples. This self-improving cycle creates rubrics that are both fine-grained and robust, translating to better reward signals for downstream RL.

## Foundational Learning
1. **Discriminative Rubric Learning**: Rubrics are validated by their ability to prefer expert answers over candidates. *Why needed*: Ensures rubrics capture meaningful quality differences. *Quick check*: Correlate rubric scores with human preference judgments.
2. **Memory-Augmented Adaptation**: A fixed-capacity memory bank stores and iteratively updates high-performing items. *Why needed*: Enables scalable refinement without retraining the generator. *Quick check*: Ablate memory updates; performance should degrade.
3. **Adversarial Robustness**: An adversary generates hard candidates to stress-test rubrics. *Why needed*: Prevents rubrics from becoming complacent and missing edge cases. *Quick check*: Rubric accuracy on adversary-generated candidates should improve over iterations.
4. **Verification Gap Analysis**: Gaps between verifier scores and expected outcomes drive memory updates. *Why needed*: Targets specific weaknesses rather than random exploration. *Quick check*: Analyze updated items for improved discrimination on previously failed cases.
5. **Closed-Loop Self-Improvement**: Inner tuning and outer refresh form a cyclic process. *Why needed*: Enables continuous adaptation without human intervention. *Quick check*: Run multiple loops; discriminative accuracy should not decrease.
6. **Reward Model Transfer**: Learned rubrics serve as reward models for RL. *Why needed*: Directly improves downstream generation quality. *Quick check*: Policy trained with SibylSense rubrics should achieve higher win rates than baseline rewards.

## Architecture Onboarding
Component map: Frozen Rubric Generator -> Initial Memory Bank -> Verifier (scores items) -> Memory Tuning (updates based on gaps); Adversary -> Candidate Pool -> Verifier (tests rubrics) -> Adversarial Refresh (updates candidate pool). Memory Bank and Candidate Pool interact cyclically.

Critical path: 1) Generate initial rubric items. 2) Score items with verifier. 3) Tune memory by replacing low-value items. 4) Train adversary on current rubrics. 5) Generate adversarial candidates and refresh pool. 6) Repeat from step 2.

Design tradeoffs: Frozen generator vs. tunable memory—stability vs. adaptability. Adversarial refresh vs. overfitting—robustness vs. bias to current verifier. Memory size—larger memory increases diversity but slows tuning.

Failure signatures: 1) Rubric accuracy plateaus early. 2) Adversarial candidates become noise or trivial. 3) Memory updates degrade performance on held-out cases. 4) Downstream RL gains vanish or reverse.

First experiments: 1) Replace verifier with different model sizes/architectures to test robustness. 2) Ablate adversarial refresh: compare memory tuning only vs. full system. 3) Transfer to a new domain (e.g., code generation) with minimal prompt adaptation.

## Limitations
- Generalizability limited to two domains (medical QA, summarization); uncertain transfer to other open-ended tasks.
- Dependency on external frozen rubric generator and verifier quality; failure modes not analyzed.
- Risk of overfitting rubrics to the adversarial process and current verifier biases.

## Confidence
- Automated fine-grained rubric creation: Medium (plausible but restricted to specific generator/verifier setup).
- Iterative discriminative power gains: Medium (observed on two datasets, lacks statistical significance and seed variance reporting).
- Downstream RL improvement: Medium (higher win rates vs. base models, missing comparisons to strong baselines).
- Adversarial refresh benefits: Medium (incremental gains reported, ablation is shallow).

## Next Checks
1. Cross-domain validation: Apply SibylSense to at least two new tasks (e.g., code generation, dialogue) and compare against baseline rubrics.
2. Ablation study: Isolate the effect of adversarial refresh by comparing memory tuning alone vs. full system.
3. Verifier robustness: Measure rubric stability under different verifier models (size, architecture) and prompt variations.
