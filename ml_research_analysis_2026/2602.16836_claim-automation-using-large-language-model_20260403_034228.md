# Claim Automation using Large Language Model

## Quick Facts
- **arXiv ID**: 2602.16836
- **Source URL**: https://arxiv.org/abs/2602.16836
- **Reference count**: 38
- **Primary result**: Domain-adaptive fine-tuning of an 8B LLM achieves 100% format compliance and 81.5% accuracy on structured corrective-action generation, surpassing larger commercial models in semantic alignment.

## Executive Summary
This paper addresses the challenge of deploying large language models (LLMs) in regulated, data-sensitive insurance domains. The authors develop a governance-aware component to generate structured corrective-action recommendations from unstructured warranty claim narratives. By locally fine-tuning a pretrained LLM (DeepSeek-R1-Distill-Llama-8B) using Low-Rank Adaptation (LoRA) on approximately 2 million historical claims, they scope the model to an intermediate claim automation task. Results show that domain-specific fine-tuning substantially outperforms general-purpose and prompted models, achieving perfect format compliance, high accuracy on valid outputs, and superior semantic alignment compared to larger commercial LLMs like GPT-5.2. The work demonstrates that targeted fine-tuning can align LLM outputs with operational data distributions while maintaining data governance.

## Method Summary
The authors preprocessed a proprietary dataset of ~2 million historical warranty claims through a five-stage pipeline: duplicate removal, abbreviation normalization, misspelling correction, administrative text removal, and filtering of incomplete narratives. Each sample was formatted as an instruction (concatenated Complaint and Cause fields) and a target response (Correction field) adhering to a strict schema (`corrective action(s) include(d): <action>`). For training, they locally deployed `deepseek-ai/DeepSeek-R1-Distill-Llama-8B` and applied LoRA (rank 32, alpha 32) to all transformer projections (Q, K, V, O, gate, up, down). Training used masked autoregressive loss computed only on response tokens, with AdamW (learning rate 6e-5, batch size 8, gradient accumulation 4) for one epoch in mixed precision (FP16). Inference employed sampling (temperature=1.0, top-k=50). Evaluation combined automated metrics (BERT cosine similarity, LLM-as-a-Judge) with human rubrics on a high-quality subset.

## Key Results
- The fine-tuned model achieved **100% format compliance** and **100% validity** on the test set.
- On valid outputs, accuracy reached **81.5%**, with **92.0%** on a manually verified high-quality subset.
- The 8B model **surpassed larger commercial LLMs** (e.g., GPT-5.2) in semantic alignment as measured by LLM-as-a-Judge and BERT similarity.
- Approximately **80% of evaluated cases** achieved near-identical semantic matches to ground truth corrections.

## Why This Works (Mechanism)
Domain-adaptive fine-tuning aligns the LLM’s output distribution with the specific structure, terminology, and operational constraints of warranty claim narratives. Local deployment ensures data privacy and governance, while LoRA efficiently adapts model weights with minimal computational overhead, preserving general knowledge while specializing. The masked autoregressive training objective forces the model to condition its generation strictly on the provided instruction, improving instruction-following and reducing hallucination. Together, these elements produce outputs that are both structurally consistent (format compliance) and semantically accurate (actionable corrections), enabling integration into automated claims-processing pipelines.

## Foundational Learning
1. **LoRA (Low-Rank Adaptation)**: Efficient fine-tuning by decomposing weight updates into low-rank matrices. *Why needed*: Adapts large LLMs with limited compute and memory. *Quick check*: Verify LoRA rank (32) and targeted modules (all projections).
2. **Masked Autoregressive Training**: Loss computed only on response tokens, ignoring instruction tokens. *Why needed*: Focuses learning on generating correct responses conditioned on inputs. *Quick check*: Confirm loss mask ignores prompt tokens during training.
3. **Format Compliance**: Strict adherence to a predefined output schema. *Why needed*: Enables deterministic parsing and downstream automation. *Quick check*: Regex validation of outputs against schema pattern.
4. **Semantic Similarity Metrics** (BERT cosine, LLM-as-a-Judge): Measure contextual meaning match beyond surface form. *Why needed*: Captures equivalence in diverse phrasings of corrective actions. *Quick check*: Compute scores on a validation sample with known references.
5. **Data Preprocessing Pipeline**: Multi-stage cleaning (deduplication, normalization, etc.). *Why needed*: Reduces noise and standardizes input for consistent model learning. *Quick check*: Track vocabulary size reduction and OOV token rates before/after.
6. **Local Deployment**: Running LLM on-premise without external APIs. *Why needed*: Meets data governance and privacy requirements in regulated sectors. *Quick check*: Audit inference code for any external network calls.

## Architecture Onboarding
Component map: Raw Claims -> Preprocessing Pipeline -> Instruction Formatter -> DeepSeek-R1-Distill-Llama-8B (LoRA-adapted) -> Output Parser -> Structured Corrections.
Critical path: Preprocessing (ensures data quality) -> LoRA fine-tuning (domain adaptation) -> Inference with schema enforcement (usable output).
Design tradeoffs: LoRA vs full fine-tuning (efficiency vs capacity); local inference (privacy/control) vs cloud (scale/updates); strict schema (automation) vs flexible generation (robustness to variation).
Failure signatures: Low format compliance indicates weak schema prompting or insufficient constraint; poor semantic similarity suggests domain misalignment or incomplete LoRA coverage; high validity but low accuracy points to content errors (incorrect actions/parts).
First experiments: 1) Reimplement preprocessing on a small claim sample, quantify normalization effects. 2) Train a minimal LoRA model (rank 8) for few steps, validate loss masking and output format. 3) Evaluate format compliance and BERT similarity on a held-out set, compare to zero-shot baseline.

## Limitations
- Proprietary dataset (2M claims) and exact preprocessing rules (abbreviation dictionaries, misspelling lists) are inaccessible, risking data distribution mismatch in reproduction.
- Precise output schema syntax (e.g., “include” vs. “included”) and high-quality subset selection criteria are under-specified, threatening exact metric replication.
- Claims of superiority over commercial LLMs lack disclosed test conditions (prompting strategies, inference parameters), limiting comparative confidence.
