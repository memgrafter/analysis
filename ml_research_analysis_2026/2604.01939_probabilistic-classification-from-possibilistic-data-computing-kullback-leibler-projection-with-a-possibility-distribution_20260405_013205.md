# Probabilistic classification from possibilistic data: computing Kullback-Leibler projection with a possibility distribution

## Quick Facts
- **arXiv ID:** 2604.01939
- **Source URL:** https://arxiv.org/abs/2604.01939
- **Reference count:** 40
- **Primary result:** Kullback-Leibler projection onto a convex set respecting possibility ordering yields significant accuracy gains over antipignistic baselines, particularly under ambiguous supervision and small-data regimes.

## Executive Summary
This paper tackles multi-class classification where each training instance is labeled with a normalized possibility distribution rather than a single class. The core contribution is defining a convex admissible set of probability vectors that honor the dominance constraints derived from the possibility distribution (i.e., necessity lower bounds and possibility upper bounds on event probabilities, while preserving the ordering among events). Given a model's predictive distribution, the authors compute its Kullback-Leibler (KL) projection onto this set using Dykstra's algorithm with negative entropy Bregman projections. The KL divergence to this projection becomes the training loss, quantifying the minimal correction required to make predictions consistent with the possibilistic supervision. Empirical evaluations on synthetic data and the ChaosNLI benchmark demonstrate that this projection-based approach outperforms fixed antipignistic (necessity-based) and vote-proportion targets, with absolute improvements up to 33.5% on synthetic data and 4.7% on ChaosNLI in challenging ambiguous scenarios. The algorithm is efficient for up to 100 classes, taking ~1 second to reach high precision, making it practically viable.

## Method Summary
The method constructs an admissible set ℛ of probability distributions p that simultaneously satisfy: (1) N(A) ≤ p(A) ≤ Π(A) for all events A, where N and Π are necessity and possibility measures derived from the possibilistic label; and (2) linear "shape constraints" that enforce the ordering among events as dictated by the possibility distribution (e.g., if Π(A) < Π(B) then p(A) ≤ p(B)). This set is a convex polytope. For a model's output distribution q, the KL projection p* = argmin_{p∈ℛ} KL(p||q) is found by iteratively applying Bregman projections onto the half-spaces defining ℛ, using Dykstra's algorithm to guarantee convergence. The training loss is KL(p*||q), which penalizes predictions that deviate from the admissible region. This framework allows learning from ambiguous, distributional supervision without committing to a single probabilistic interpretation, while respecting the semantic relationships embedded in the possibility distribution.

## Key Results
- Projection target reduces test error relative to antipignistic baseline by up to 33.5% absolute on synthetic data with high ambiguity and small datasets.
- On ChaosNLI, projection-based learning achieves up to 4.7% absolute improvement over antipignistic and vote-proportion targets across multiple train/validation splits.
- Dykstra-based projection converges in ~3000 cycles for n=100 classes within ~1 second, demonstrating practical efficiency for moderate-scale multi-class problems.

## Why This Works (Mechanism)
The mechanism succeeds because the admissible set ℛ is both semantically faithful and computationally tractable. It is convex due to linear constraints, enabling projection via cyclic Bregman updates. The KL projection finds the closest admissible distribution to the model's raw output q in an information-theoretic sense, ensuring that the loss reflects minimal necessary adjustment. By optimizing models to minimize this projected KL, learning is steered toward predictions that inherently respect the possibility ordering and the bounds imposed by necessity and possibility. This avoids the over-simplification of fixed targets like the antipignistic distribution, which collapses all ambiguity into a single probability vector, and instead allows the model's confidence to be refined within the constraints.

## Foundational Learning
- **Possibility Theory:** Provides necessity N(A) and possibility Π(A) measures from possibilistic labels; defines the constraint bounds N(A) ≤ p(A) ≤ Π(A).
  - *Quick check:* Confirm N(A) = 1 - Π(¬A) and that the antipignistic distribution (p(A)=N(A)) is always feasible in ℛ.
- **Kullback-Leibler Divergence:** Serves as the projection metric and loss; convex in its first argument, suitable for Bregman projections.
  - *Quick check:* Verify KL(p||q) = ∑ p_i log(p_i/q_i) and is finite only when p_i=0 ⇒ q_i=0.
- **Convex Polytopes:** ℛ is defined by linear inequalities; projection onto such sets is fundamental in convex optimization.
  - *Quick check:* Encode constraints as matrix A p ≤ b and check feasibility via linear programming.
- **Dykstra's Algorithm:** Cyclic projection algorithm for intersecting convex sets; used here for KL projection onto ℛ.
  - *Quick check:* Implement with correction variables; monitor decreasing KL objective and constraint violations.
- **Bregman Divergences:** Generalization of KL; negative entropy F(p)=∑ p_i log p_i yields B_F(p||q)=KL(p||q) + ∑ q_i - ∑ p_i.
  - *Quick check:* Derive Bregman projection update for a half-space: p_new = argmin_{p∈H} B_F(p||q_old).
- **Linear Shape Constraints:** Additional inequalities enforcing p(A) ≤ p(B) whenever Π(A) < Π(B); preserve possibility ordering.
  - *Quick check:* For a possibility distribution Π, enumerate all pairs (A,B) with Π(A)<Π(B) and add constraint p(A) ≤ p(B).

## Architecture Onboarding
- **Component Map:**  
  Possibility Distribution Π → Define Linear Constraints (N≤p≤Π, ordering) → Construct Admissible Set ℛ → Dykstra's Algorithm (with Bregman projections) → KL Projection p* → Compute Loss KL(p*||q) → Backpropagation.
- **Critical Path:** The Dykstra projection loop dominates computation; each cycle evaluates all half-space constraints and updates the iterate and auxiliary correction terms.
- **Design Tradeoffs:** Convexity guarantees tractable projection but may restrict ℛ more than necessary if ordering constraints are too strong; KL projection is sensitive to zero probabilities in q, requiring smoothing or careful initialization.
- **Failure Signatures:** 
  - Dykstra fails to converge within reasonable cycles (e.g., >10^5).
  - ℛ is empty (infeasible constraints), detected by initial LP feasibility check.
  - Projected p* violates ordering constraints due to numerical precision issues.
  - Wall-clock time grows superlinearly with number of classes n beyond ~100.
- **First Three Experiments:**
  1. **Baseline Comparison:** Train a classifier with projection loss vs. antipignistic target on synthetic data with controlled ambiguity (varying entropy of Π); measure test accuracy.
  2. **Scalability Profiling:** For increasing n (10, 50, 100, 200, 500), measure average Dykstra cycles and time to achieve constraint violation < 1e-8 on random feasible points.
  3. **Constraint Ablation:** Remove dominance (ordering) constraints from ℛ; compare test accuracy on ChaosNLI and a synthetic dataset with ambiguous labels to quantify the contribution of ordering preservation.

## Limitations
- **Dataset Breadth:** Validation is limited to one real-world benchmark (ChaosNLI) and synthetic data; generalization to other domains (e.g., medical, financial) with different ambiguity sources is unknown.
- **Scalability Ceiling:** Efficiency demonstrated only up to n=100 classes (~1 sec); performance for thousands of classes or high-dimensional features is untested, and Dykstra's convergence may degrade.
- **Theoretical Robustness:** The "linear shape constraints" enforcing possibility ordering are novel but lack extensive theoretical justification and testing on edge-case possibility distributions (e.g., nearly uniform Π).

## Confidence
- **Projection improves accuracy vs. antipignistic:** Medium (statistically significant on two testbeds but lacking data diversity)
- **Convex admissible set definition:** High (mathematically sound derivation from possibility axioms)
- **Algorithm efficiency (n~100):** Medium-High (empirical runtime reported, but no asymptotic complexity analysis)
- **ChaosNLI outperformance:** Medium (multiple splits used, but single-dataset risk remains)
