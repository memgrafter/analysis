# How Far Can We Go with Pixels Alone? A Pilot Study on Screen-Only Navigation in Commercial 3D ARPGs

## Quick Facts
- **arXiv ID:** 2602.18981  
- **Source URL:** https://arxiv.org/abs/2602.18981  
- **Reference count:** 35  
- **Primary result:** Milestone success rates up to ~88% on some Dark Souls III routes, but no route completion in Elden Ring; pure pixel-based navigation is insufficient for general ARPG levels.

## Executive Summary
This pilot study investigates whether autonomous navigation in complex 3D ARPG levels is possible using only screen pixels, without access to game state. It employs a pretrained visual affordance detector (STP/MSTP) to identify candidate exit points from single frames and combines it with a finite-state controller and optional visual memory bank to follow designer-defined milestone routes. Across four games (Dark Souls I/III, Elden Ring, Black Myth: Wukong) and six routes, the agent achieves moderate success on some Dark Souls III segments but fails completely on Elden Ring routes. The work establishes a reusable milestone-based benchmark but concludes that purely vision-based sense-making, lacking explicit 3D reasoning and long-range connectivity, cannot robustly handle the navigational complexity of commercial ARPGs.

## Method Summary
The task is to traverse predefined routes composed of six visual milestones using only live RGB frames. The perception stack employs a pretrained STP/MSTP model: STP generates candidate "selectable traverse points" (bounding boxes), and MSTP chooses the most promising candidate per frame. A finite-state machine (FSM) controller issues pulsed camera rotations and forward movements based on the MSTP's location relative to a central dead zone. An optional visual memory bank reweights STP candidates by penalizing sectors associated with past failures. No training is conducted; evaluation uses automated milestone detection via template matching and resets via save files. Primary metrics are per-milestone segment success (MS) and full route success (RS).

## Key Results
- Achieved MS up to ~88% on some Dark Souls III routes (e.g., V0), but performance is inconsistent across segments and games.
- The FSM controller improved robustness on specific segments but did not consistently outperform a naive baseline that directly steers toward MSTP.
- Zero route success (0% RS) on Elden Ring; visual memory bank sometimes degraded performance.

## Why This Works (Mechanism)
The approach operates on a closed-loop perception-control cycle. At each frame, the STP detector scans the RGB image and proposes a set of candidate "selectable traverse points" (bounding boxes) likely to correspond to traversable exits. The MSTP selector then picks the single most promising candidate based on learned visual criteria. The FSM controller receives the selected point's position relative to a central dead zone in the image; if the point lies outside, the FSM issues discrete camera rotation pulses to bring it toward the center. Once centered, the FSM issues a forward movement pulse to advance. This simple reactive scheme allows the agent to follow a corridor toward the selected exit without requiring continuous state estimation. The visual memory bank records recent outcomes (success/failure at each sector) and reweights STP candidates in similar sectors to avoid repeating mistakes, thereby mitigating local minima. The milestone-based evaluation uses template matching to detect arrival at each checkpoint and reset to the next segment.

The mechanism relies on several key assumptions: that traversable exits are visually salient and can be distinguished from distractors in single frames; that centering an exit and moving forward will generally lead to progress; and that short-term memory of failing sectors improves exploration. However, the pipeline is limited by the affordance detector's accuracy (e.g., confusion with non-traversable objects), the FSM's discrete actions (causing overshoot), and the lack of long-range planning or 3D scene understanding. These limitations become acute in environments with ambiguous geometry, narrow passages, or deceptive visual patterns, leading to the observed failures in Elden Ring.

## Foundational Learning
1. **Visual Affordance Detection**  
   *Why needed:* Replaces game-state geometry with pixel-based exit prediction.  
   *Quick check:* Does STP output consistently align with actual traversable exits under varying lighting and angles?

2. **Finite-State Machine Control**  
   *Why needed:* Provides structured, deterministic reactions to noisy perception outputs.  
   *Quick check:* Can FSM stabilize control despite MSTP jitter without oscillation?

3. **Milestone-Based Evaluation**  
   *Why needed:* Defines progress via visual checkpoints, enabling screen-only assessment.  
   *Quick check:* Are milestone templates sufficiently distinctive for reliable matching across runs?

4. **Screen-Only Navigation**  
   *Why needed:* Operates without engine hooks, applicable to commercial games.  
   *Quick check:* Does screen capture latency noticeably impact action timing and success?

5. **Visual Memory Bank**  
   *Why needed:* Mitigates local minima by penalizing historically failing regions.  
   *Quick check:* Does memory degrade when milestone detection produces false negatives?

6. **Discrete Action Space**  
   *Why needed:* Simplifies control in the absence of continuous state estimation.  
   *Quick check:* Are pulse timings adequate for stable turning without overshoot?

## Architecture Onboarding
**Component Map:**  
Screen Capture -> STP Detector -> MSTP Selector -> FSM Controller (with Memory Bank) -> Game Actions (Camera/Forward)

**Critical Path:**  
Frame input -> STP generates candidate boxes -> MSTP picks one box -> FSM computes error relative to dead zone -> Issue pulse actions if error exceeds threshold -> Update memory with outcome -> Repeat until milestone template match triggers reset.

**Design Tradeoffs:**  
- Fixed perception (no training) ensures reproducibility but limits adaptability to new games.  
- Discrete actions simplify control but may cause overshooting and imprecise alignment.  
- Memory bank adds robustness to local failures but introduces hyperparameters and risk of false penalties.

**Failure Signatures:**  
- Repeated selection of visually salient non-traversables (e.g., shelves) → STP model confusion between salience and traversability.  
- Stalled "ADVANCE" state with forward keypress but no progress → collision on narrow/oblique geometry (e.g., stairs).  
- Performance drop when memory enabled → false-negative outcome labeling or poor sector similarity matching.

**First Three Experiments:**  
1. Run naive baseline (direct MSTP steering, no FSM/memory) on all routes to isolate detector-only performance.  
2. Compare FSM-only vs. Full (with memory) on segments where naive fails to quantify memory's net effect.  
3. Vary template matching thresholds and MSTP selection criteria to measure sensitivity of success rates to perception parameters.

## Open Questions the Paper Calls Out
1. How can the visual navigation benchmark be decoupled from the specific STP/MSTP affordance model to allow fair evaluation of diverse perception systems?
2. What alternative perception-control architectures (e.g., end-to-end RL, learned topological maps) can improve screen-only navigation robustness beyond the current finite-state controller and memory bank?
3. How can visual affordance models be mitigiated against dataset-driven biases, such as the left-turn preference, to handle visually symmetric or ambiguous scenes?
4. Can integrating explicit 3D reasoning (e.g., depth estimation, collision modeling) resolve navigation failures on narrow geometries and vertical transitions in complex ARPG levels?

## Limitations
- Underspecified hyperparameters (FSM thresholds, memory parameters) and perception backbone details hinder exact reproduction.
- Strong dataset/game-specific biases in affordance detector cause complete failure on Elden Ring routes, but root cause (visual style vs. geometry) is unanalyzed.
- Visual memory bank's occasional degradation is observed but not isolated; may stem from false-negative milestone detection.
- Pilot-scale evaluation (6 routes across 4 games) limits generalizability of the insufficiency claim.

## Confidence
- **High:** Milestone-based evaluation protocol and FSM controller design are clearly described and reusable.
- **Medium:** Claims about specific failure modes (e.g., stair navigation, left-turn bias) are supported by aggregated logs but lack full ablation.
- **Low:** Broad conclusion that "purely vision-based sense-making without 3D reasoning is insufficient" due to limited game coverage and potential confounds from unoptimized FSM/memory parameters.

## Next Checks
1. Extract exact FSM/memory hyperparameters from codebase and validate performance against reported rates on a known route (e.g., DS3 V0).
2. Disable memory bank on a failing Elden Ring segment to determine if memory penalties cause collapse; inspect memory logs for false-negative sector labeling.
3. Design a simple, matched corridor route in an unseen ARPG (e.g., *Lies of P*) to test if failure is due to detector biases or fundamental geometric limitations.
