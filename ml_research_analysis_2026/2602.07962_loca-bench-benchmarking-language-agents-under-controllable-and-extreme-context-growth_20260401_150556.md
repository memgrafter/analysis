# LOCA-bench: Benchmarking Language Agents Under Controllable and Extreme Context Growth
## Quick Facts
- arXiv ID: 2602.07962
- Source URL: https://arxiv.org/abs/2602.07962
- Reference count: 29
- Primary result: All models suffer sharp accuracy drops as context grows (e.g., Claude-4.5-Opus: 96% at 8K → 14.7% at 256K); frontier models maintain 2–3× higher accuracy than open-source at long contexts; programmatic tool calling improves success rates by 5–15 absolute points and reduces trajectory length by 30–60%.

## Executive Summary
LOCA-bench introduces a benchmark to evaluate language agents under controllable, extreme context growth, revealing a phenomenon termed "context rot". By systematically scaling the initial environment description from 8K to 256K tokens while keeping task semantics fixed, the authors show that all models experience sharp accuracy drops as context length increases, with frontier models demonstrating 2–3× higher accuracy than open-source models at the longest contexts. Furthermore, advanced context engineering techniques, particularly programmatic tool calling, can mitigate these declines by improving success rates by 5–15 absolute percentage points and reducing trajectory length by 30–60%. The benchmark provides both diagnostic insights into failure modes (deteriorating reasoning, suppressed exploration) and a testbed for evaluating context management strategies.

## Method Summary
LOCA-bench evaluates agents on 15 scalable tasks across 7 domains (e.g., Canvas, Email, BigQuery). Each task is instantiated with environment states that produce initial descriptions of varying lengths (8K to 256K tokens) via a generator that accepts configuration parameters (e.g., number of courses). Agents interact with these environments using tool calls within a ReAct scaffold. Performance is measured by binary accuracy: the final environment state is compared against ground truth via execution-based verification. Secondary metrics include trajectory length and number of tool calls. The evaluation pipeline automatically varies context length and seeds, yielding 525 samples per model. The benchmark is implemented with mock servers to ensure reproducibility.

## Key Results
- All models exhibit sharp accuracy declines with increasing context length; e.g., Claude-4.5-Opus drops from 96% at 8K to 14.7% at 256K, while open-source models fall below 10% at the longest contexts.
- Frontier models maintain 2–3× higher accuracy than open-source models at 256K tokens.
- Advanced context engineering, especially programmatic tool calling, improves accuracy by 5–15 absolute percentage points and cuts trajectory length by 30–60%.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Agent accuracy declines as environment description length increases because multi-step, multi-source reasoning deteriorates under long context pressure.
- **Mechanism:** The agent must retrieve and integrate information from multiple tool outputs (e.g., Canvas announcements and emails) while preserving relationships (e.g., exam-to-course mapping). Long contexts dilute attention and working memory, causing models to overlook critical sources or fail to combine evidence correctly.
- **Core assumption:** The model’s reasoning capacity is limited relative to context size; beyond a certain length, integration errors rise sharply.
- **Evidence anchors:** The abstract identifies “declining complex reasoning” as a key failure mode; section 3.3 shows a model ignoring email data and never consulting the Canvas dashboard, producing an incomplete exam schedule; neighboring work (e.g., 100‑LongBench) focuses on static retrieval, not dynamic agentic reasoning.
- **Break condition:** If models maintained high accuracy (>90%) across all context lengths without increasing reasoning errors, the mechanism would be falsified.

### Mechanism 2
- **Claim:** Exploration intensity decreases as context grows, leading to premature task termination and incomplete information gathering.
- **Mechanism:** Accumulated tool outputs consume context budget, creating implicit pressure to avoid further expansion. The model behaves conservatively, often stopping after limited interaction (e.g., fetching only the first page of products). This self‑imposed limit is reflected in plateauing trajectory lengths despite linearly growing environments.
- **Core assumption:** Models trade off context consumption against action; they may truncate exploration to manage the fixed window.
- **Evidence anchors:** The abstract explicitly notes that “models tend to explore less and behave more conservatively when the context becomes long.” Section 3.2 (Figure 3) shows trajectory length and tool calls plateau after 96K, indicating suppressed exploration relative to environment growth. Section 3.3 (Figure 4) provides a concrete failure: the model reads only the first 100 products, incorrectly concludes none match, and stops.
- **Break condition:** If trajectory length scaled linearly with environment size at all lengths, or if exploration remained exhaustive regardless of context pressure, the mechanism would be invalid.

### Mechanism 3
- **Claim:** Advanced context engineering—especially programmatic tool calling—significantly mitigates context rot, lifting accuracy by 5–15 absolute points and cutting trajectory length by 30–60%.
- **Mechanism:** Programmatic tool calling lets the model write code that processes tool outputs internally and returns only the final result, drastically reducing raw text entering the context. It also encourages structured workflows (e.g., pagination loops) that improve exploration efficiency. Other strategies (memory tools, context awareness) also help by pruning or summarizing history.
- **Core assumption:** Context pressure is a primary driver of failure; reducing effective input size and organizing interactions yields measurable gains.
- **Evidence anchors:** The abstract quantifies the improvements from “advanced context engineering—especially programmatic tool calling.” Section 4.2 (Table 2) shows consistent gains: e.g., GPT‑5.2‑Medium accuracy improves from 38.7 → 49.3 and trajectory shrinks from 141K → 102K at 128K. Section 4.2 notes that programmatic tool calling “reduces trajectory length while improving accuracy” across all tested models.
- **Break condition:** If applying these strategies produced no significant improvement in accuracy or trajectory length, the claimed causal benefit would be disproven.

## Foundational Learning
- **Concept: Agentic Tool Use**  
  *Why needed:* The benchmark evaluates agents that interact with environments through tools; understanding how tool calls and outputs contribute to context growth is essential to grasp the root cause of context rot.  
  *Quick check:* How does an agent’s tool usage pattern (number of calls, output size) change as environment description length increases, and what does that imply about exploration?
- **Concept: Context Management Strategies**  
  *Why needed:* The paper’s key findings revolve around various context engineering techniques; engineers must know their trade‑offs to extend or deploy effective scaffolds.  
  *Quick check:* Contrast tool‑result clearing with programmatic tool calling in terms of how they reduce context pressure and which is more effective under long‑context conditions.
- **Concept: Execution‑Based Verification**  
  *Why needed:* LOCA‑bench scores tasks by comparing the final environment state to a ground‑truth state; this binary outcome underpins all reported results and must be implemented correctly for any new task.  
  *Quick check:* What does the evaluation script check to determine success, and why is this method robust to variations in intermediate reasoning?

## Architecture Onboarding
**Component map:** The system consists of (1) mock servers (local databases mimicking external APIs like Canvas, Email, BigQuery), (2) a task generator that instantiates scalable environment states from templates based on configuration parameters, (3) an agent scaffold (default ReAct) that orchestrates model reasoning and tool calls, (4) a context‑engineering module pluggable into the scaffold (e.g., tool‑result clearing, programmatic tool calling), and (5) an evaluation engine that runs the agent, captures the final environment, and scores it against ground‑truth state.

**Critical path:** Adding a new task follows: define environment templates (courses, exams, etc.) → implement a generator that accepts config parameters (e.g., number of courses) → write a verification script that checks the final environment state → register the task with the evaluation runner. The pipeline then automatically varies the description length, executes the agent, and logs metrics.

**Design tradeoffs:** Decoupling environment, tools, and scaffold enhances extensibility but increases integration complexity. Mock servers simplify setup and reproducibility but may not capture all real‑service behaviors (e.g., network latency, auth). Binary success evaluation is objective but coarse; it does not reward partial progress.

**Failure signatures:**
1. Monotonic accuracy drop with increasing context length.
2. Trajectory length plateau despite larger environment (indicating exploration suppression).
3. Agent ignoring entire data sources (e.g., never calling Email tool).
4. Scaffold misconfiguration (e.g., overusing sub‑agents) leading to rapid context bloat without task progress.

**First 3 experiments:**
1. Baseline replication: Run the default ReAct scaffold (no context engineering) for at least one frontier model (e.g., Claude‑4.5‑Opus) and one open‑source model across all context lengths; verify that the accuracy pattern matches Table 1 (sharp drop at 256K).
2. Strategy ablation: For a fixed model (e.g., GPT‑5.2‑Medium) at 128K, enable each context‑engineering technique separately; record accuracy and trajectory length to identify the most effective methods (expected: programmatic tool calling).
3. Scaffold comparison: Integrate Claude Agent SDK and Anthropic’s programmatic tool calling wrapper; compare performance to the paper’s in‑house implementation (Table 3) to assess reproducibility and scaffold sensitivity.

## Open Questions the Paper Calls Out
- **Question 1:** What mechanisms drive context rot in language agents?  
  *Basis in paper:* The paper defines context rot and documents sharp performance degradation as context length increases (e.g., Table 1, Figure 1).  
  *Why unresolved:* The phenomenon is empirically observed but not causally explained; underlying factors (e.g., attention limitations, reasoning decay) remain unknown.  
  *What evidence would resolve it:* Controlled experiments that systematically vary context content (noise vs. relevant information) while measuring internal model behaviors (attention patterns, retrieval accuracy) could isolate primary drivers.
- **Question 2:** Why do frontier models exhibit stronger resistance to context rot compared to open-source models?  
  *Basis in paper:* Main results show frontier models maintain 2–3× higher accuracy at 256K context length (Table 1) and retrieve more tool outputs (Figure 3).  
  *Why unresolved:* The gap could stem from model architecture, training data, or proprietary context engineering; the paper does not disentangle these factors.  
  *What evidence would resolve it:* Ablation studies equipping open-source models with frontier-style context management, or direct comparisons of internal representations (e.g., hidden state analysis) could reveal the source of the advantage.
- **Question 3:** What design principles make programmatic tool calling effective, and why does the official Anthropic implementation outperform custom ones?  
  *Basis in paper:* Programmatic tool calling yields the largest accuracy gains and trajectory reduction (Table 2, Section 4.2); Anthropic's implementation achieves 49.3% vs. 40.0% for the authors' version at 128K.  
  *Why unresolved:* Implementation details are not disclosed; it is unclear whether benefits come from better code execution, tighter tool integration, or model-scaffold alignment.  
  *What evidence would resolve it:* Reverse-engineering the two implementations, releasing formal specifications, or user studies comparing variants could identify critical features that drive superiority.

## Limitations
- Mock servers may not capture real-world service behaviors (latency, authentication quirks).
- Binary success metric is coarse and ignores partial progress.
- Undisclosed Anthropic implementation details hinder exact replication of top gains.

## Confidence
- Mechanism 1 (reasoning deterioration): Medium confidence (strong internal evidence but limited cross-scaffold validation).
- Mechanism 2 (exploration suppression): Medium confidence (clear plateauing trajectories in their setup; generalizability untested).
- Mechanism 3 (context engineering benefit): Medium confidence overall; Low for replicating Anthropic-specific gains due to undisclosed details.
- Architecture/design: High for the authors' toolkit; Medium for broader agent frameworks.
