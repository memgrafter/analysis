# Grow, Assess, Compress: Adaptive Backbone Scaling for Memory-Efficient Class Incremental Learning

## Quick Facts
- **arXiv ID**: 2603.08426
- **Source URL**: https://arxiv.org/abs/2603.08426
- **Reference count**: 39
- **Primary result**: GRACE achieves state-of-the-art accuracy while reducing memory footprint by up to 73% compared to purely expansionist models; in memory-aligned evaluations it outperforms prior art by up to 3.71 percentage points.

## Executive Summary

Class Incremental Learning (CIL) requires models to learn new classes sequentially without forgetting previous ones. Expansion-based approaches avoid catastrophic forgetting by allocating new parameters for each task, but they lead to uncontrolled parameter growth and high memory consumption. This paper introduces GRACE (Grow, Assess, Compress), a dynamic framework that manages model capacity through three cyclic phases per task: **Grow** (adds a temporary provisional backbone trained in isolation), **Assess** (evaluates saturation of the current mergeable backbone using normalized effective rank), and **Compress** (merges the provisional backbone into the mergeable backbone via importance-aware initialization and dual-level knowledge distillation). By postponing expansion until necessary and consolidating when capacity is saturated, GRACE maintains plasticity while drastically reducing memory footprint. Experiments on CIFAR-100 and ImageNet-100 demonstrate that GRACE achieves state-of-the-art accuracy and compresses parameters by up to 73% relative to expansion-only baselines. In memory-aligned evaluations with equal budgets, it surpasses previous methods by up to 3.71 percentage points.

## Method Summary

GRACE processes incremental tasks sequentially with a fixed rehearsal buffer. For each task:

1. **Grow**: A new provisional backbone $\phi_{prov}$ is added and trained on the current task data $\tilde{D}_t$ combined with rehearsal exemplars $E$, while all existing backbones (fixed $\phi_{fixed}$ and mergeable $\phi_{merge}$) are frozen. An auxiliary classifier $W_{aux}$ encourages the provisional backbone to distinguish current classes and maintain cross-task separability (via an “old-classes” supercategory). The expanded classifier $W$ is trained with loss $L_{exp} = CE(f_{exp}, y) + CE(f_{aux}, y_{aux})$ followed by Weight-Align.

2. **Assess**: The normalized effective rank (̃eRank) of feature matrices from $\phi_{merge}$ on $\tilde{D}_t \cup E$ is computed. ̃eRank serves as a saturation score; if it falls below threshold $\tau$, compression is triggered.

3. **Compress**: A student backbone $\phi_{st}$ is initialized as a weighted combination of $\phi_{merge}$ and $\phi_{prov}$ using preservation factor $P$ and bias factor $B$ with hyperparameter $\gamma$: $\phi_{st} = w\cdot\phi_{merge} + (1-w)\cdot\phi_{prov}$. The student is then trained with dual-level knowledge distillation: logit-level KL divergence from the expanded model (temperature $T$) and feature-level MSE between projected student features and concatenated teacher features. After training, $\phi_{merge} \leftarrow \phi_{st}$ and $\tau \leftarrow \rho\cdot\tau$. If expansion was chosen, $\phi_{prov}$ is promoted to $\phi_{merge}$, the old $\phi_{merge}$ moves to $\phi_{fixed}$, and $\tau$ is reset to $\tau_1$.

The buffer $E$ is managed via herding selection (fixed size 2000 in reported experiments).

## Key Results
- On CIFAR-100 and ImageNet-100, GRACE achieves state-of-the-art average accuracy.
- Reduces memory footprint by up to 73% compared to purely expansionist models.
- In memory-aligned evaluations with identical budgets, it outperforms prior art by up to 3.71 percentage points.

## Why This Works (Mechanism)

### Mechanism 1: Provisional Backbone Isolation
- **Claim**: Adding a provisional backbone per task allows learning novel features without interfering with consolidated knowledge.
- **Mechanism**: During Grow, all existing backbones are frozen. The new backbone is trained on the current task data plus rehearsal buffer using an auxiliary classifier that encourages cross-task separability (includes an “old-classes” supercategory).
- **Core assumption**: Isolating new weights prevents catastrophic interference with frozen weights representing past tasks.
- **Evidence anchors**: Abstract and Section 3.3 describe the freeze and auxiliary classifier; neighboring papers study parameter-efficient expansion but not this exact design.
- **Break condition**: If the auxiliary classifier fails to achieve sufficient accuracy on the current task, the provisional backbone may not have learned adequate task-specific features before assessment.

### Mechanism 2: Effective Rank–Driven Assessment
- **Claim**: Assessing the mergeable backbone’s saturation via normalized effective rank (̃eRank) informs whether to expand or compress architecture, preventing unbounded growth.
- **Mechanism**: Compute the effective rank (eRank) of feature matrices from the mergeable backbone on the current task plus rehearsal buffer. Normalize by $\min$(sample count, feature dimension) to get a saturation score between 0‑1. Compare against a threshold $\tau$; if score < $\tau$, compress; else, expand.
- **Core assumption**: Effective rank, as a measure of feature matrix rank collapse, reliably indicates representational capacity utilization; saturation (low eRank) means the backbone’s features are over‑specialized or redundant relative to task complexity.
- **Evidence anchors**: Abstract and Section 3.4 define ̃eRank and its role as a decision gate. No strong evidence in the corpus linking eRank directly to generalization on new classes.
- **Break condition**: If eRank fails to correlate with generalization performance on new classes (e.g., low eRank but poor validation accuracy), the saturation threshold may misguide decisions.

### Mechanism 3: Importance-Aware Merge with Dual-Level Distillation
- **Claim**: Merging the provisional backbone into the mergeable backbone via importance-aware initialization and dual-level knowledge distillation minimizes forgetting while reducing parameters.
- **Mechanism**: Initialize student backbone as $\phi_{st} = w\cdot\phi_{merge} + (1-w)\cdot\phi_{prov}$, where $w$ combines Preservation Factor ($P = |Y_{merge}|/(|Y_{merge}|+|Y^t|)$) and Bias Factor ($B = n_{new}/(n_{new}+n_{old})$). Then train student with multi‑objective loss $L_{comp} = \lambda(\alpha L_{KD} + \beta L_{feat}) + (1-\lambda)L_{CE}$, where $L_{KD}$ is logit-level KL with temperature $T$, and $L_{feat}$ is MSE between projected student features and concatenated teacher features.
- **Core assumption**: Teacher‑aware initialization reduces optimization disparity, and dual‑level distillation transfers both coarse (logit) and fine (feature) knowledge effectively.
- **Evidence anchors**: Abstract and Section 3.5 describe both components; ablation in Table 4 shows additive gains versus using either distillation level alone.
- **Break condition**: Mis‑estimated $P$ or $B$ (e.g., extreme class imbalance) may overweight one backbone, causing irreversible forgetting; insufficient $\lambda,\alpha,\beta$ may also degrade fidelity.

## Architecture Onboarding

### Component Map
- **Fixed backbones** ($\phi_{fixed}$): Fully trained, frozen backbones from tasks after they have been merged and subsequently replaced.
- **Mergeable backbone** ($\phi_{merge}$): The current consolidated backbone that can still be updated via compression.
- **Provisional backbone** ($\phi_{prov}$): Newly added trainable backbone for the current task.
- **Student backbone** ($\phi_{st}$): Created during compression; initialized from $\phi_{merge}$ and $\phi_{prov}$ and becomes the new $\phi_{merge}$.
- **Expanded classifier** ($W$): Linear layer over concatenated outputs of all active backbones (provisional + mergeable).
- **Auxiliary classifier** ($W_{aux}$): Used only during Grow to encourage cross‑task discriminative features; includes a unified “old‑classes” supercategory.
- **Rehearsal buffer** ($E$): Fixed‑size buffer of exemplars from previous classes (size $M$ = 2000 in experiments).

Relationships: Grow trains $\phi_{prov}$ with $W$ and $W_{aux}$ while $\phi_{fixed}$ and $\phi_{merge}$ are frozen. Assess computes ̃eRank from $\phi_{merge}$. If compression occurs, $\phi_{st}$ is initialized from $\phi_{merge}$ and $\phi_{prov}$, then trained with dual‑level distillation using teachers $W$, $\phi_{merge}$, and $\phi_{prov}$ (expanded model). $\phi_{st}$ replaces $\phi_{merge}$; old $\phi_{merge}$ moves to $\phi_{fixed}$. If expansion occurs, $\phi_{prov}$ is promoted to $\phi_{merge}$, the previous $\phi_{merge}$ becomes fixed, and $\tau$ resets.

### Critical Path
For each incremental task $t$:
1. **Grow**: Add $\phi_{prov}$, freeze existing backbones, expand classifier $W$, train on $\tilde{D}_t \cup E$ with loss $L_{exp}$ (cross‑entropy plus auxiliary cross‑entropy), then apply Weight‐Align.
2. **Assess**: Compute normalized effective rank of $\phi_{merge}$'s features on $\tilde{D}_t \cup E$. Compare ̃eRank to threshold $\tau$.
3. **Decision**:
   - **Compress** (if ̃eRank < $\tau$): Compute preservation factor $P$ and bias factor $B$, determine weighting $w$, initialize $\phi_{st}$ as weighted sum. Train $\phi_{st}$ with $L_{comp}$ (dual‑level KD). Set $\phi_{merge} \leftarrow \phi_{st}$ and update $\tau \leftarrow \rho\cdot\tau$.
   - **Expand** (if ̃eRank ≥ $\tau$): Promote $\phi_{prov}$ to $\phi_{merge}$; move previous $\phi_{merge}$ to $\phi_{fixed}$. Reset $\tau \leftarrow \tau_1$.

### Design Tradeoffs
- **Threshold $\tau$ and decay $\rho$**: Lower $\tau$ or higher $\rho$ leads to more frequent compression, yielding smaller models but risking premature compression (forgetting). Higher $\tau$ or lower $\rho$ favors expansion, preserving plasticity at the cost of more parameters.
- **Buffer size $M$**: Larger $M$ improves representation of old classes for both training and eRank computation, but consumes memory that could otherwise support additional backbones. Smaller $M$ may cause noisy eRank estimates.
- **Initialization weighting $\gamma$**: The power‑mean exponent $\gamma$ controls sensitivity to $P$ and $B$. Higher $\gamma$ makes weighting more responsive to imbalances but may over‑preserve old knowledge or under‑weight new tasks; lower $\gamma$ yields more uniform mixing.

### Failure Signatures
- **Parameter explosion**: $\tau_1$ set too high or $\rho$ too close to 1 results in few or no compression events; model size grows linearly with tasks.
- **Accuracy collapse during compression**: Poor initialization due to misestimated $P$ or $B$, or insufficient distillation weights ($\lambda, \alpha, \beta$), causes significant forgetting after merging.
- **Stagnant learning**: $\tau$ too low triggers compression before $\phi_{prov}$ adequately learns task‑specific features, limiting final performance.

### First 3 Experiments
1. **Grow sanity check**: After Grow on task $t$, evaluate auxiliary classifier $W_{aux}$ on classes $Y_t$. Expect >30% accuracy on CIFAR‑100 Base0 Inc10; lower indicates provisional backbone failed to learn.
2. **Assess consistency**: Track normalized ̃eRank of $\phi_{merge}$ before and after each task. Expect an upward trend as classes accumulate; the decay schedule of $\tau$ should align such that compression occurs when the slope flattens.
3. **Compress fidelity**: Immediately after a compression event, compare the merged student $\phi_{st}$ against the pre‑merge ensemble (separate $\phi_{merge}$ + $\phi_{prov}$) on a held‑out mix of old and new classes. Target <2% drop in Avg accuracy while reducing parameter count by ~50% per compression.

## Open Questions the Paper Calls Out

### Open Question 1
- **Question**: How generalizable is the normalized effective rank (eRank) as a saturation measure across diverse neural architectures (e.g., Vision Transformers, MLPs) and data modalities?
- **Basis in paper**: The paper introduces eRank as a capacity evaluation metric and uses it to decide between expansion and compression, but experiments are limited to ResNet CNNs on image classification benchmarks. The paper does not investigate whether the saturation threshold τ1 calibrated on CNNs remains meaningful for architectures with different feature space properties.
- **Why unresolved**: The eRank assumes that singular values of feature covariance reflect representational capacity utilization. This assumption may not hold for architectures with non‑convolutional layers (e.g., self‑attention in ViTs) or for non‑image data. Without validation, the applicability of GRACE’s core decision mechanism beyond CNNs is uncertain.
- **What evidence would resolve it**: A systematic study computing eRank for multiple architectures (ResNet, ViT, ConvNeXt) on standard CIL benchmarks, correlating eRank with actual performance degradation when capacity is exceeded. Could include synthetic capacity‑sweep experiments.

### Open Question 2
- **Question**: Can the saturation threshold τ1 and its decay factor ρ be set automatically for a given resource‑performance trade‑off, avoiding exhaustive grid search?
- **Basis in paper**: The paper employs a threshold decay mechanism and performs grid search over τ1∈[0.5,0.8] and ρ∈[0.9,0.98] (Appendix C). While Figure 5 shows Pareto frontiers, the selection process remains empirical and dataset‑specific. The paper acknowledges that tuning these hyperparameters allows adaptation to different constraints but does not propose a principled setting method.
- **Why unresolved**: The relationship between threshold values, model growth dynamics, and final accuracy is not formally characterized. The current approach requires significant tuning for each new scenario, which is computationally expensive and may not generalize to unseen task sequences or datasets.
- **What evidence would resolve it**: An analytical model linking eRank distributions to expected accuracy loss, enabling derivation of τ from desired bounds. Alternatively, an adaptive algorithm that adjusts τ based on online feedback (e.g., if recent compressions caused accuracy drops, increase τ).

### Open Question 3
- **Question**: Is the importance‑aware student initialization (Equation 8) optimal, and how does its performance vary with the γ parameter across different task orders and sizes?
- **Basis in paper**: The paper proposes this initialization and shows via ablation (Table 5) that it outperforms simple averaging by up to 2.26% on CIFAR‑100. However, the power‑mean formulation with γ is heuristic; the paper does not justify why this combination of preservation factor P and bias factor B is optimal, nor does it analyze γ sensitivity beyond a single reported value.
- **Why unresolved**: The weighting scheme lacks theoretical grounding. It is unclear whether other factors (e.g., gradient magnitudes, Fisher information) might yield better initialization. The choice of γ, which controls sensitivity to P and B, is not studied systematically. This could limit the method’s robustness to varying incremental scenarios.
- **What evidence would resolve it**: A thorough hyperparameter sweep over γ across diverse task orders (e.g., balanced vs imbalanced) and sizes, comparing with alternative initialization strategies (e.g., based on feature matching or importance sampling). A derivation from an objective that explicitly balances preservation and bias.

### Open Question 4
- **Question**: How does the size of the rehearsal buffer M affect the reliability of eRank‑based saturation assessment and overall GRACE performance, especially in low‑memory regimes?
- **Basis in paper**: GRACE uses a fixed buffer size (2000 images) in all experiments. The eRank is computed on the current task data plus exemplars. The paper’s memory‑aligned evaluation adjusts M to equalize memory but does not explore very small M values. The assumption that the buffer provides a stable estimate of old class feature distributions for eRank is not validated.
- **Why unresolved**: With few exemplars (e.g., <100 per class), the feature covariance from $\tilde{D}_t$ may be noisy, leading to unreliable eRank scores and suboptimal expansion/compression decisions. The impact of buffer size on decision robustness and final accuracy remains unknown, which is critical for memory‑constrained deployments.
- **What evidence would resolve it**: Experiments varying M across a wide range (e.g., 0, 50, 200, 2000) and measuring eRank variance across runs, correlation with accuracy, and the frequency of expansion vs compression decisions. Could also test the framework without any rehearsal buffer (M=0) to see if eRank still works.

## Limitations
- Hyperparameters (learning rates, epochs, distillation weights, threshold values) are not fully specified, requiring empirical tuning for replication.
- eRank computation details (sample size, centering, SVD truncation) are ambiguous, potentially affecting reproducibility and the stability of the assessment phase.
- Exact class ordering and buffer management details are missing, leading to possible mismatches in replication across different implementations.
