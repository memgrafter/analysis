# Exploratory Memory-Augmented LLM Agent via Hybrid On- and Off-Policy Optimization

## Quick Facts
- **arXiv ID:** 2602.23008
- **Source URL:** https://arxiv.org/abs/2602.23008
- **Reference count:** 40
- **Primary result:** EMPO² outperforms GRPO by 128.6% on ScienceWorld and 11.3% on WebShop, and adapts rapidly to out-of-distribution tasks with no parameter updates.

## Executive Summary
Reinforcement learning (RL) for large language model (LLM) agents often suffers from poor exploration, relying heavily on pretrained knowledge and failing to discover novel states. This paper introduces Exploratory Memory-Augmented On- and Off-Policy Optimization (EMPO²), a hybrid RL framework that uses self‑generated memory tips to guide exploration and combines on‑ and off‑policy updates to internalize beneficial behaviors. The method significantly improves performance on two challenging benchmarks (ScienceWorld and WebShop) and demonstrates rapid adaptation to out‑of‑distribution tasks without additional parameter updates, offering a promising direction for building generalizable LLM agents.

## Method Summary
EMPO² augments an LLM policy with an external memory buffer storing short reflective “tips” derived from past episode outcomes. During rollouts, with probability p = 0.25 the retrieval module selects the top‑10 most relevant tips (cosine similarity > 0.5) and appends them to the prompt; otherwise the policy uses standard prompting. After each episode, a tip is automatically generated and added to memory. Updates are performed on collected trajectories: for memory‑conditioned rollouts, the agent randomly applies on‑policy updates (retaining tips in the prompt) or off‑policy updates (discarding tips when recomputing log‑probabilities for the current policy, but still using advantages from the original memory rollout). Standard on‑policy updates are used for memory‑free rollouts. An intrinsic novelty bonus, computed via a secondary memory of state embeddings (bonus = 1/n, where n is the count of similar stored states), is added to the external reward to further encourage exploration. This hybrid design both steers the agent toward unexplored states via memory and distills the improved behavior into the base policy, ensuring robustness when memory is unavailable.

## Key Results
- EMPO² achieves relative improvements of **128.6%** on ScienceWorld and **11.3%** on WebShop over the strong online RL baseline GRPO.
- In out‑of‑distribution tasks, EMPO² adapts rapidly with only a few memory‑augmented trials and **no parameter updates**, demonstrating strong generalization.

## Why This Works (Mechanism)

### Mechanism 1
**Claim:** Self‑generated memory tips retrieved at each step steer the agent toward unexplored states and away from previously failed actions.  
**Mechanism:** During rollouts, the policy queries a memory buffer containing short reflective “tips” summarizing past outcomes. A similarity search selects the most relevant tips, which are then appended to the prompt. This augments the LLM’s context with past failures/successes, encouraging actions that differ from naive exploitation of pretrained priors.  
**Core assumption:** That memories of prior outcomes are sufficiently relevant and actionable to influence future behavior toward more fruitful regions of the state space.  
**Evidence anchors:**  
- [abstract]: “leverages self‑generated memory tips to guide exploration”  
- [section 4.1]: detailed description of tip generation, retrieval, and usage in memory‑augmented prompting  
- [corpus]: Weak evidence; similar memory‑augmented prompting appears in Reflexion and REMEMBERER, but EMPO² couples it tightly with RL updates.  
**Break condition:** If retrieved tips are irrelevant or too generic, they may mislead rather than guide, causing performance degradation or overfitting to spurious patterns.

### Mechanism 2
**Claim:** Off‑policy updates using memory‑conditioned rollouts distill beneficial behaviors into the base policy, enabling strong performance even when memory is unavailable.  
**Mechanism:** For a trajectory sampled with tips, the off‑policy mode discards tips when recomputing log‑probabilities for the current policy. The GRPO loss still uses the advantages from the original memory‑conditioned rollout, thereby encouraging the student policy to imitate teacher actions proportionally to their reward. This reward‑guided distillation internalizes the benefits of memory.  
**Core assumption:** That teacher trajectories (produced with tips) are of higher quality, and that importance weighting can safely correct the distribution shift.  
**Evidence anchors:**  
- [abstract]: “combines on‑ and off‑policy updates to make LLMs perform well with memory while also ensuring robustness without it”  
- [section 4.2]: “Off‑Policy Updates” and “Stabilizing Off‑Policy Training” describe the mechanism and masking to avoid unstable gradients  
- [corpus]: Minimal; similar reward‑guided distillation ideas exist in offline RL and knowledge distillation literature.  
**Break condition:** Excessive distribution shift (e.g., tips drastically alter action distribution) can cause high variance or NaN gradients despite masking, especially if the teacher policy is too dissimilar from the student.

### Mechanism 3
**Claim:** An intrinsic novelty reward maintains sufficient exploration pressure, preventing premature convergence to suboptimal local modes.  
**Mechanism:** A secondary memory stores distinct state representations. When encountering a new state that is not similar (cosine similarity < threshold) to any stored state, the agent receives a small bonus (r_intrinsic = 1/n, where n is count of similar past states). This encourages visiting unfamiliar regions even without external reward.  
**Core assumption:** That state novelty correlates with information gain or progress toward long‑term goals.  
**Evidence anchors:**  
- [abstract]: “An intrinsic reward further encourages novelty.”  
- [section 4.2]: “Intrinsic Rewards for Exploration” explains the novelty detection and bonus computation  
- [corpus]: Count‑based and RND bonuses are standard; EMPO² uses a lightweight similarity‑based alternative.  
**Break condition:** If novelty is not properly aligned with task progress, the agent may wander randomly, wasting steps and harming final performance.

## Architecture Onboarding

**Component map:**  
Rollout manager selects prompting mode (probability p). In memory‑augmented mode, retrieval module queries the memory buffer for top‑k similar tips, which are injected into the policy prompt; in standard mode, no tips are added. The policy generates actions for the environment. The environment returns state embeddings to the intrinsic reward module, which computes a novelty bonus. After each episode, the tip generator creates a new tip and stores it in the memory buffer. The update manager processes trajectories: for memory‑conditioned ones, it randomly chooses on‑policy (retain tips) or off‑policy (discard tips for log‑prob) updates; for standard rollouts, only on‑policy updates are applied. GRPO loss updates the policy.

**Critical path:**  
1. For each rollout step: decide memory/no‑memory → if memory, retrieve tips → condition policy → act.  
2. After episode termination: generate tip → add to memory.  
3. Update phase: split rollouts → for memory rollouts, decide update mode → compute GRPO loss (with token masking) → apply KL regularization → update policy.

**Design tradeoffs:**  
- *p (memory rollout prob):* Higher p yields more memory‑conditioned experience but risks over‑reliance; lower p preserves original policy training.  
- *q (off‑policy prob):* Higher q increases distillation internalization but may destabilize training of the memory‑augmented policy; lower q maintains more direct memory policy updates.  
- *Memory size (1000 tips):* Limits overhead but may evict useful old tips.  
- *Top‑k retrieval (10):* Balances relevance and context length; more tips could dilute signal.

**Failure signatures:**  
- Learning curve plateaus early, especially on hard tasks.  
- Memory buffer fills with duplicate or irrelevant tips (low retrieval scores).  
- Off‑policy loss produces NaNs despite masking → indicates excessive distribution shift.  
- Test performance without memory is much lower than with memory → poor internalization.  
- Intrinsic reward dominates total return → agent wanders aimlessly.

**First 3 experiments:**  
1. Ablate memory usage: set p=0 (no memory) vs default p=0.25 → expect severe drop on ScienceWorld exploration tasks.  
2. Ablate off‑policy updates: set q=0 (always on‑policy with memory) → verify if internalization to base policy suffers.  
3. Remove intrinsic reward → monitor policy entropy and learning speed; expect faster collapse to low entropy.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Would richer memory retrieval methods (e.g., neural, hierarchical) improve EMPO²’s exploration efficiency?  
- **Basis in paper:** [explicit] The conclusion notes the current “simple similarity‑based search” and that “more advanced retrieval mechanisms may further enhance performance.”  
- **Why unresolved:** No experiments with alternative retrieval techniques are presented.  
- **What evidence would resolve it:** Compare several retrieval approaches (dense vectors, approximate nearest neighbors, learned rerankers) on ScienceWorld/WebShop; measure success rate, memory size, and retrieval latency.

### Open Question 2
- **Question:** How does EMPO²’s performance scale with model size and architecture diversity?  
- **Basis in paper:** [explicit] The conclusion states that extending “to a broader range of model families and sizes… scaling to larger models may further amplify the benefits.”  
- **Why unresolved:** Results are only reported for one 7B model; scaling effects are unknown.  
- **What evidence would resolve it:** Train EMPO² on multiple model sizes (e.g., 1B, 13B, 70B) and architectures (decoder-only, encoder-decoder); track relative gains over baselines and computational cost.

### Open Question 3
- **Question:** Can EMPO² generalize to non‑embodied domains (math, coding, multi‑hop QA, multi‑modal RL) and what modifications are needed?  
- **Basis in paper:** [explicit] The conclusion proposes applying EMPO² to “mathematics, coding, multi‑hop question answering, and multi‑modal RL” as a challenging future direction.  
- **Why unresolved:** EMPO² has only been tested on two text‑based embodied environments.  
- **What evidence would resolve it:** Adapt EMPO² to standard benchmarks in those domains (e.g., MATH, HumanEval, HotpotQA); compare to strong RL/memory baselines and identify required domain‑specific tweaks.

### Open Question 4
- **Question:** Do alternative off‑policy methods (beyond importance sampling) improve hybrid learning stability and sample efficiency?  
- **Basis in paper:** [explicit] The authors mention “exploring other off‑policy techniques beyond importance sampling could be of interest to achieve more stable and efficient hybrid optimization.”  
- **Why unresolved:** The off‑policy component is fixed to one formulation; alternatives are not studied.  
- **What evidence would resolve it:** Replace the off‑policy loss with options like Q‑iteration, conservative policy updating, or dual networks; evaluate training stability, convergence speed, and final returns on challenging tasks.

## Limitations
- The embedding model used for tip/state similarity search is undisclosed, critically affecting memory relevance.
- Exact masking threshold (δ) and handling of token padding in off‑policy updates are unspecified, risking gradient explosions.
- The precise neighbor count threshold for the intrinsic novelty bonus and its scaling coefficient are unknown, possibly misaligning novelty with task progress.

## Next Checks
1. **Embedding sensitivity test:** Re‑run key experiments using at least three different embedding models (e.g., OpenAI text‑embedding‑ada‑002, Sentence‑BERT, and a randomly initialized one) to quantify performance variance from retrieval quality.
2. **Off‑policy gradient diagnostics:** During training, log the maximum importance weight per batch and the proportion of masked low‑prob tokens. Flag runs where >5% of updates have weights >100 or produce NaNs, correlating with final performance.
3. **Intrinsic reward ablation:** Systematically vary the novelty bonus coefficient (e.g., 0, 0.1, 1.0, 10.0) and measure policy entropy, step efficiency, and final return to confirm the bonus isn’t causing random wandering.
