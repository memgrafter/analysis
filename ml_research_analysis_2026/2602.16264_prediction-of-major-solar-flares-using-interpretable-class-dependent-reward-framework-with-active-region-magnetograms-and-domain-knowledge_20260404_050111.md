# Prediction of Major Solar Flares Using Interpretable Class-dependent Reward Framework with Active Region Magnetograms and Domain Knowledge

## Quick Facts
- **arXiv ID:** 2602.16264
- **Source URL:** https://arxiv.org/abs/2602.16264
- **Reference count:** 40
- **Primary result:** The Class-Dependent Reward (CDR) Transformer achieves a True Skill Statistic (TSS) of 0.829±0.059 and Brier Skill Score (BSS) of 0.489±0.120 on 10 cross-validation test sets, and on a single-active-region test set it reaches TSS 0.968±0.016, significantly outperforming the NASA/CCMC ensemble (TSS 0.853).

## Executive Summary
Solar flare prediction is hindered by extreme class imbalance; M- and X-class flares are rare events. This paper introduces a supervised Class-Dependent Reward (CDR) framework that assigns differential immediate rewards to true positives, true negatives, false positives, and false negatives during training, inspired by reinforcement learning but without a Markov decision process. Applied to a Transformer model that processes time series of magnetic features derived from SDO/HMI active region magnetograms, CDR effectively mitigates imbalance.

The CDR-Transformer attains a TSS of 0.829±0.059 and BSS of 0.489±0.120 across 10 cross-validation folds. On a filtered single-active-region test set, it achieves TSS 0.968±0.016, far exceeding the NASA/CCMC operational ensemble (TSS 0.853). SHAP analysis reveals that CDR emphasizes total unsigned current helicity (TOTUSJH), while a standard Transformer focuses on R_VALUE, indicating the reward mechanism reshapes feature learning. The framework shows robustness to reward perturbations and points toward operational forecasting.

## Method Summary
The study uses SHARP data (2010–2020) covering 808 active regions. From each active region’s magnetograms, 39 magnetic features are extracted: 31 line-of-sight (LOS) and 8 vector-derived parameters. The binary task predicts ≥M-class flares within 24 hours. Three deep learning architectures are implemented: CNN (static images), CNN-BiLSTM (image time series), and Transformer (feature time series). The CDR framework modifies training by weighting each sample’s negative log-likelihood with an immediate reward (TP=10, TN=4, FP=-20, FN=-15) based on true and predicted labels, using experience replay. Standard models use weighted cross-entropy. Performance is evaluated via TSS and BSS, with SHAP for interpretability. The optimal CDR-Transformer uses combined LOS and vector features and is benchmarked against NASA/CCMC on a 2023–2024 test set.

## Key Results
- CDR-Transformer attains TSS 0.829±0.059 and BSS 0.489±0.120 across 10 cross-validation folds, slightly surpassing its deep learning counterpart.
- On a filtered test set containing only single active regions, CDR-Transformer achieves TSS 0.968±0.016, markedly higher than NASA/CCMC’s TSS 0.853.
- SHAP analysis shows the CDR model prioritizes total unsigned current helicity (TOTUSJH), whereas the standard Transformer emphasizes R_VALUE, indicating divergent feature learning due to the reward mechanism.

## Why This Works (Mechanism)
CDR addresses class imbalance by scaling each sample’s loss by an outcome-specific reward: strong penalties for false positives/negatives and rewards for true positives/negatives. This per-sample weighting gives the minority class (flares) greater influence on gradients than coarse class weights. Experience replay stores past predictions and outcomes, ensuring a balanced mix of outcomes in each update. The Transformer’s self-attention captures long-range temporal dependencies in the 40‑step feature sequence, and the reward-weighted loss steers it to learn discriminative patterns for flaring regions. As a result, the model improves recall without inflating false alarms, yielding higher TSS.

## Architecture Onboarding
**Component map**  
Raw SHARP data (magnetograms) → Feature extraction (31 LOS + 8 vector) → Normalization → Time series sequence (40 samples/AR) → Transformer encoder (4 blocks, MHA, MLP) → Classification head (sigmoid) → Prediction → CDR reward assignment (based on true label) → Reward‑weighted loss → Backpropagation → Parameter update

**Critical path**  
1. Preprocess: Extract features, normalize, form sequences.  
2. Training loop: Sample mini‑batch from replay buffer → forward pass → compute predictions → assign rewards → compute CDR loss → backward pass → update model.  
3. Store new experiences (predictions, true labels, rewards) into replay buffer.  
4. Periodically evaluate validation set and save best model.

**Design tradeoffs**  
- CDR vs weighted cross‑entropy: CDR offers fine‑grained per‑sample weighting but introduces reward hyperparameters and replay management.  
- Feature selection: Combining LOS and vector features boosts performance but increases dimensionality; the paper found combined features optimal.  
- Model complexity: Transformer provides powerful sequence modeling but requires more data and careful regularization; 4 encoder blocks were chosen as a balance.  
- Reward values: Larger penalties for FP/FN improve minority recall but may increase false alarms; values were empirically determined.

**Failure signatures**  
- Training instability: Loss oscillations/divergence suggest extreme rewards or biased replay sampling.  
- Low validation TSS: Could indicate data leakage (AR overlap), incorrect feature extraction (especially gradient/wavelet features), or poor reward tuning.  
- Inconsistent SHAP: If feature importance deviates from expected physics (e.g., R_VALUE not dominant in baseline), check background dataset and SHAP implementation.  
- Threshold bias: Using a fixed probability threshold (e.g., 0.5) instead of TSS‑optimized threshold underreports performance.

**First three experiments**  
1. **Baseline replication**: Train standard Transformer (weighted cross‑entropy) on one CV fold with combined features; verify test TSS >0.75.  
2. **CDR advantage test**: Replace loss with CDR loss using reported rewards; compare validation TSS/BSS to baseline, expecting a small improvement.  
3. **Feature importance validation**: Compute SHAP values for both models on same test set; verify baseline highlights R_VALUE while CDR highlights TOTUSJH.

## Open Questions the Paper Calls Out
**Open Question 1**: How can the Class‑Dependent Reward (CDR) framework be adapted for operational, real‑time solar flare prediction systems? The authors mention this as future work, but it is unresolved because current evaluation uses historical cross‑validation; operational deployment requires real‑time data ingestion, low latency, integration with alert systems, and continuous model updates. Evidence: A live pipeline with benchmarking against NOAA standards and validation across multiple solar cycles.

**Open Question 2**: Can CDR be extended to predict coronal mass ejections (CMEs)? The authors propose applying CDR to CMEs, but CMEs are rarer and have different magnetic drivers, possibly needing reward recalibration. Evidence: A CME dataset with adapted features and reward values, showing performance comparable to existing CME models.

**Open Question 3**: How does the presence of multiple active regions within a single SHARP patch affect CDR performance? The paper filtered multi‑AR test sets due to performance drops, implying the model assumes independent ARs. This is unresolved because multi‑AR inputs may interfere. Evidence: Training/testing on unfiltered data, error analysis, and incorporating multi‑instance learning.

**Open Question 4**: Why do CDR and standard Transformers assign divergent feature importance (TOTUSJH vs R_VALUE)? Authors speculate reward‑driven optimization and feature stability, but physical interpretation is unclear. Evidence: Ablation studies, correlation with independent physical metrics, and expert assessment.

## Limitations
- **Exact CV split AR identifiers undisclosed**: Only aggregated class counts are provided; without specific AR numbers, verifying disjointness and avoiding data leakage is impossible.
- **Feature extraction details incomplete**: Implementation of the 31 LOS features (beyond R_VALUE and AREA_ACR) is not described; small differences in image processing can alter feature values.
- **CDR reward selection not systematically reported**: The chosen reward values (TP=10, TN=4, FP=-20, FN=-15) were found experimentally without detailing the search space or validation, risking overfitting.

## Confidence
- **Performance metrics (TSS≈0.829, BSS≈0.489)**: Medium (depends on correct CV splits and feature implementation).
- **CDR‑Transformer advantage over standard deep learning**: Low (gain is small and sensitive to unreported reward tuning).
- **SHAP feature prioritization (TOTUSJH vs R_VALUE)**: Medium (standard SHAP but background dataset may affect rankings).
- **Robustness to reward perturbations**: Low (experimental scope and statistical testing not detailed).
