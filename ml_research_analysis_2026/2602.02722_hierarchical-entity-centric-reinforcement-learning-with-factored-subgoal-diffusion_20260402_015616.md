# Hierarchical Entity-centric Reinforcement Learning with Factored Subgoal Diffusion
## Quick Facts
- **arXiv ID:** 2602.02722
- **Source URL:** https://arxiv.org/abs/2602.02722
- **Reference count:** 40

## Executive Summary
Offline goal‑conditioned reinforcement learning (GCRL) for long‑horizon tasks in multi‑entity environments with high‑dimensional observations and sparse rewards suffers from combinatorial complexity and compounding value approximation errors. This paper introduces Hierarchical Entity‑centric Reinforcement Learning (HECRL), a two‑level framework. The low level is an entity‑centric value‑based GCRL agent; the high level is a conditional diffusion model trained on entity‑factored representations to generate subgoals that modify only a small subset of entities. At test time, subgoals are sampled and filtered using the low‑level value function to ensure they lie within the policy’s competence radius; the subgoal closest to the goal is selected. The two levels are trained independently and combined post‑hoc, providing modularity.

HECRL is evaluated on new image‑based multi‑object manipulation tasks (PPP‑Cube, Stack‑Cube, Scene, Push‑Tetris). It consistently outperforms baselines: on PPP‑Cube from images it reaches 64.3% success vs. 25.0% for the non‑hierarchical entity‑centric agent (>150% improvement) and 0% for other baselines. The method generalizes to up to six cubes and longer horizons. Ablations confirm that value‑based filtering and diffusion‑based subgoal sampling are crucial; a deterministic AWR subgoal generator performs poorly.

## Method Summary
HECRL decomposes a long‑horizon goal‑conditioned task into a hierarchical structure. The low‑level component is an entity‑centric, value‑based GCRL agent that learns to achieve subgoals defined as modifications to a subset of entities. The high‑level component is a conditional diffusion model that generates candidate subgoals in the factored state space, conditioned on the current state and the final goal. During training, the low‑level agent is trained on offline data collected from the target environment, independent of the high‑level. The diffusion model is trained on a dataset of entity‑factored transitions to model plausible subgoal distributions. At test time, the high‑level draws multiple subgoal candidates; each is evaluated by the low‑level value function to estimate its feasibility, and the one with the highest value (or closest to the goal) is selected for execution. This modular separation allows each component to leverage its own data and objectives without requiring joint online interaction.

## Key Results
- On PPP‑Cube from images, HECRL achieves 64.3% success vs. 25.0% for the non‑hierarchical entity‑centric agent (>150% improvement) and 0% for all other baselines.
- The approach generalizes to increasing numbers of objects (tested up to 6 cubes) and longer horizons without performance collapse.
- Ablations show that removing value‑based filtering or replacing the diffusion generator with a deterministic AWR model drastically reduces performance, highlighting the importance of both mechanisms.

## Why This Works (Mechanism)
The hierarchical design isolates long‑horizon planning from short‑horizon control, reducing the effective planning depth each component must handle. The entity‑centric representation grounds the agent in object‑level semantics, enabling subgoals that target specific entities and supporting generalization to varying object counts. The diffusion model provides a diverse set of candidate subgoals that only alter a few entities, aligning with the low‑level policy’s limited competence radius. Value‑based filtering ensures that selected subgoals are likely achievable by the low‑level agent, preventing the selection of unreachable or out‑of‑distribution subgoals and thereby mitigating compounding errors. Independent training makes the system modular and practical for offline learning, as each level can be optimized separately with its own data source.

## Architecture Onboarding
**Component map:**  
Observation → Entity Extractor → Factored State  
Goal → Goal Encoder → Goal Embedding  
Factored State + Goal Embedding → Diffusion Subgoal Generator → Candidate Subgoals  
Candidate Subgoals + Factored State → Low‑Level Value Function → Feasibility scores → Selected Subgoal  
Selected Subgoal + Factored State → Low‑Level Policy → Action sequence (until subgoal achieved or timeout)

**Critical path:** At each decision epoch, the high‑level generates candidate subgoals, ranks them via the value function, selects the best, and then the low‑level policy executes actions to achieve that subgoal. After completion (or timeout), the process repeats.

**Design tradeoffs:**  
- Independent training simplifies development and allows using separate datasets, but may cause misalignment between high‑level proposals and low‑level capabilities.  
- Diffusion sampling offers diversity and expressiveness but incurs higher test‑time computational cost; deterministic generators (e.g., AWR) are faster but less capable, as shown by ablations.  
- Value‑based filtering relies on an accurate low‑level value function; offline distribution shift can degrade its reliability.  
- Factored state assumption requires reliable entity extraction; errors propagate to both levels.

**Failure signatures:**  
- Low‑level value function overestimates Q‑values for unreachable subgoals, leading to infeasible selections and task failure.  
- Diffusion model generates subgoals that modify too many entities or produce unrealistic configurations, causing low‑level policy failures.  
- Entity extractor misdetects or mislocates objects (especially from images), yielding incorrect factored states and faulty planning.  
- Independent training yields a high‑level generator that proposes out‑of‑support subgoals; if filtering misses them, execution fails.

**First experiments (exactly 3):**  
1. **Scalability with object count:** Run HECRL on PPP‑Cube with 1, 2, 4, and 6 cubes to measure success rate and sample efficiency.  
2. **Ablation of value filtering:** Remove the value‑based filtering step (e.g., select randomly or by diffusion score) and compare performance to the full system.  
3. **Comparison to deterministic subgoal generator:** Replace the diffusion generator with an AWR‑based deterministic generator and evaluate across the task suite.

## Limitations
- **Custom task bias:** Evaluation on newly introduced benchmarks (PPP‑Cube, Stack‑Cube, Scene, Push‑Tetris) may favor the method; performance on standard offline GCRL benchmarks remains unknown.  
- **Entity representation assumptions:** The approach relies on clean factored entity states; robustness to noisy perception (e.g., raw images without perfect object detection) is not evaluated.  
- **Independent training risk:** Low‑level and high‑level components are trained separately, risking misalignment; value‑based filtering depends on an accurate low‑level value function, which may be unreliable offline.
