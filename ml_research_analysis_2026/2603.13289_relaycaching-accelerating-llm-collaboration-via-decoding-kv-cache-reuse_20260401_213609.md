# RelayCaching: Accelerating LLM Collaboration via Decoding KV Cache Reuse

## Quick Facts
- **arXiv ID:** 2603.13289
- **Source URL:** https://arxiv.org/abs/2603.13289
- **Reference count:** 40
- **Primary result:** Achieves over 80% KV cache reuse, reduces TTFT by up to 4.7×, and maintains generation accuracy comparable to full prefill (e.g., 85.17% vs. 84.69% on GSM8K with 4 agents).

## Executive Summary
RelayCaching is a training-free inference acceleration method designed for multi-agent LLM systems. It mitigates the problem of redundant prefill computation by reusing KV caches from the decoding phase of previous agents. The method capitalizes on the observation that KV caches for identical content remain highly consistent across prefill and decode phases, with deviations caused by prefix shifts being sparse and localized. By identifying a critical middle layer range and a small set of influential tokens, RelayCaching selectively rectifies deviations, achieving high cache reuse (over 80%) and up to 4.7× reduction in time-to-first-token (TTFT) while preserving accuracy across reasoning, coding, and knowledge tasks. The approach requires no model retraining, uses a one-time offline profiling step, and demonstrates sub-linear TTFT scaling with context length, reaching a 9.2× speedup at 12k tokens.

## Method Summary
RelayCaching enables efficient KV cache reuse in sequential multi-agent LLM pipelines where each agent's output becomes the next agent's input. The core technical insight is that decoding-phase KV caches can be directly reused for subsequent prefill phases after applying a rotary position embedding (RoPE) shift, but prefix-induced deviations must be corrected. These deviations are shown to be sparse and concentrated in a U-shaped band of middle layers. The system operates in two phases: (1) offline profiling using calibration data to determine the critical layer interval [L_start, L_end] and a detection layer L_det; (2) runtime inference where, for each downstream agent's prefill, the cache manager retrieves the upstream agent's stored pre-RoPE KV and hidden state at L_start, applies RoPE rotation, fully recomputes layers from L_start to L_det, and then at L_det uses a token selector to identify a small set of tokens requiring rectification based on deviation magnitude (value cosine similarity) and accumulated attention influence. The cache manager then selectively recomputes KV for those tokens in layers L_det through L_end. Control thresholds τ_diff and τ_down balance accuracy and reuse. The method is model-agnostic for decoder-only architectures and yields significant TTFT reductions with minimal accuracy loss.

## Key Results
- Over 80% KV cache reuse across reasoning, coding, and knowledge tasks.
- TTFT reduced by up to 4.7×; sub-linear scaling with context length, achieving 9.2× speedup at 12k tokens.
- Generation accuracy maintained comparably to full prefill (e.g., 85.17% vs. 84.69% on GSM8K with 4 agents).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Decoding-phase KV caches are sufficiently aligned with full-prefill KV caches despite prefix shift, enabling direct reuse with targeted rectification.
- **Mechanism:** The system quantifies macro-level similarity (primarily via value cosine similarity) between reused decoding KV caches and ground-truth full-prefill KV caches. High baseline alignment validates the reuse premise; residual deviations are the only barrier to accuracy.
- **Core assumption:** Value cosine similarity is the primary indicator of harmful deviation for subsequent generation quality.
- **Evidence anchors:**
  - [abstract] "KV caches for identical content are highly consistent across phases, while prefix-induced deviations are sparse and localized..."
  - [section 3.1] "Decoding KV maintains high macro-level similarity... value cosine similarity is the lowest among all metrics, so we focus on it..."
  - [corpus] Neighbors (e.g., DroidSpeak, KVLink) explore KV reuse but do not directly validate the decode-to-prefill alignment pattern; evidence is weak.
- **Break condition:** If prefix variation causes global, non-sparse deviations that corrupt entire sequence representations (e.g., in highly non-local attention patterns or radically different prompt templates), macro-level alignment fails.

### Mechanism 2
- **Claim:** Residual deviations are concentrated in a specific range of middle layers (U-shaped profile), allowing rectification to be confined there for efficiency.
- **Mechanism:** A layer-range profiler identifies [L_start, L_end] by analyzing layer-wise value cosine similarity. Shallow layers are stable (high similarity); middle layers show a "U-shaped" drop (lowest similarity, most error-sensitive); deep layers partially recover. Rectifying only the middle range captures most fidelity recovery.
- **Core assumption:** Middle layers dominate the propagation of deviations to subsequent token generation.
- **Evidence anchors:**
  - [section 3.2] Figure 3a shows U-shaped profile; Figure 3b (oracle recovery) confirms similarity recovery is steepest when middle layers are substituted.
  - [appendix A] Figure 9 confirms U-shape across multiple model architectures (Llama, Qwen, DeepSeek).
- **Break condition:** If the model's critical reasoning/context-integration layers are not centrally located (e.g., in very shallow or very deep networks), the U-profile assumption fails, misidentifying the critical range.

### Mechanism 3
- **Claim:** Token-wise deviations are sparse and inter-layer correlated, enabling a small, selected subset of tokens to be recomputed for effective rectification.
- **Mechanism:** Token selector identifies high-deviation positions at a detection layer (L_det) using two criteria: (1) deviation magnitude (d_j,L_det), (2) downstream influence (accumulated attention scores + suffix awareness). Inter-layer correlation means this selection remains valid for all layers in [L_det, L_end].
- **Core assumption:** A token's deviation rank is stable across middle layers; influential tokens (even with moderate deviation) disproportionately affect output.
- **Evidence anchors:**
  - [section 3.3] Figure 4a shows sparsity; Figure 4b shows high Spearman rank correlation between adjacent layers.
  - [section 4.3] Dual-criterion selection (I_dev ∪ I_inf) yields best accuracy-reuse trade-off (Table 3 ablation).
- **Break condition:** If token deviations become dense (many tokens highly deviant) or uncorrelated across layers, selection at L_det becomes unreliable, requiring broader (inefficient) recomputation.

## Foundational Learning
### Concept: KV Cache Mechanics
- **Why needed here:** RelayCaching manipulates cached Key-Value states from the attention mechanism; understanding how these tensors store contextual information and their role in the prefill (first-pass) and decode (autoregressive) phases is fundamental.
- **Quick check question:** "During decoding, how does the KV cache grow with each new token, and why is it reused?"

### Concept: Cascading Context Redundancy in MAS
- **Why needed here:** The paper's motivation is the O(M²) cost in multi-agent systems where each agent re-processes all prior outputs. Grasping this data flow (output→input with prefix shift) explains why standard KV caching fails.
- **Quick check question:** "In a 4-agent sequential chain, how many times does the final agent's prefill recompute the first agent's output?"

### Concept: Deviation Metrics (Cosine Similarity, Attention Influence)
- **Why needed here:** The method relies on quantifying deviation (value cosine) and importance (attention accumulation) to guide selective rectification.
- **Quick check question:** "Why might value cosine similarity be a more sensitive deviation indicator than value norm for decode-to-prefill reuse?"

## Architecture Onboarding
### Component Map
Dependencies: LayerRangeProfiler → TokenSelector, CacheManager; TokenSelector → CacheManager. The LayerRangeProfiler (offline) analyzes calibration data to produce the critical layer range [L_start, L_end] and detection layer L_det. The TokenSelector (runtime) uses pre-RoPE KV at L_det and accumulated attention scores to output a set of token indices I_final requiring rectification. The CacheManager (runtime) orchestrates KV handoff between agents, applies RoPE shifts, triggers full recomputation for layers [L_start, L_det), and selectively recomputes KV for tokens in I_final across layers [L_det, L_end].

### Critical Path
1. **Calibration:** Run a summary-then-answer pipeline on 2WikiMQA; compute layer-wise value cosine similarity s_ℓ and rank correlation ρ_ℓ; derive layer parameters (L_start, L_end, L_det).
2. **Upstream Decoding (Stage i-1):** For each generated token, save pre-RoPE KV for the reuse segment; save hidden state at L_start; accumulate per-head attention scores α_t,ℓ,h,j into a token influence sum sinf(j).
3. **Downstream Prefilling (Stage i):** Re-apply RoPE to the reused KV; load the saved hidden state at L_start; fully recompute layers from L_start to L_det; at L_det, compute deviation d_j and influence sinf(j) to select I_final; selectively recompute KV for tokens in I_final in layers L_det through L_end.

### Design Tradeoffs
- **Accuracy vs. Reuse Rate:** Controlled by thresholds τ_diff (deviation) and τ_down (influence). Higher thresholds reduce rectifications, increasing reuse but potentially lowering accuracy.
- **Profiling cost vs. generality:** Offline profiling adds a one-time cost but yields task-agnostic layer configurations that generalize across tasks (Table 5).
- **Computation type:** Full recomputation of middle layers is necessary for reliable deviation detection; skipping it harms accuracy, while sparse token rectification in those layers is insufficient.

### Failure Signatures
- **Accuracy collapse:** If L_start is set too shallow (including shallow layers in the rectification range) or τ thresholds are too low, overhead increases and accuracy may drop due to incorrect token selection.
- **Low reuse:** If L_end is too early (cutting off before deep layers recover) or selection thresholds are too high, the rectification set becomes large, reducing reuse.
- **Inconsistent layer configs:** If the calibration dataset is not representative (e.g., domain mismatch), the U-shaped profile may not generalize, leading to misidentification of the critical range.

### First 3 Experiments
1. **Validation of U-shape:** On calibration data (2WikiMQA), plot layer-wise value cosine similarity for multiple models (Llama, Qwen, DeepSeek); confirm the U-shaped profile exists and the minimum similarity layer L_min lies in the middle.
2. **Sensitivity sweep:** For a fixed task (e.g., GSM8K with 2 agents), vary τ_diff and τ_down; plot accuracy versus reuse rate to locate the knee point; default thresholds (τ_diff=1.5, τ_down=1.45) are near-optimal (Figure 7).
3. **Scaling test:** Increase the number of agents (2→4) or output length (512→12k tokens); measure TTFT and reuse rate; confirm sub-linear scaling (Figure 8) and stable reuse around 80%+ as context grows.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Can RelayCaching support heterogeneous multi-agent systems where agents use different model architectures?
- **Basis in paper:** [explicit] The Discussion states: "Extension to Heterogeneous Settings... We leave this exploration to future work."
- **Why unresolved:** Direct KV cache transfer requires identical hidden dimensions and attention head configurations; mismatches prevent reuse.
- **What evidence would resolve it:** Design a projection or alignment mechanism to bridge KV spaces across architectures and evaluate on mixed-model agent workflows.

### Open Question 2
- **Question:** Can the hyperparameter thresholds be automatically adapted to new tasks or models without manual tuning?
- **Basis in paper:** [explicit] "Hyperparameter Sensitivity... may benefit from task-specific calibration or online adaptation."
- **Why unresolved:** Fixed thresholds (τdev, τinf, Lsuf) might not generalize beyond the evaluated benchmarks; manual tuning is a barrier to deployment.
- **What evidence would resolve it:** Propose an adaptive method (e.g., using a small calibration set or runtime accuracy estimation) and demonstrate consistent performance across diverse tasks.

### Open Question 3
- **Question:** Does RelayCaching maintain sub-linear TTFT scaling for extremely long contexts (e.g., >100k tokens)?
- **Basis in paper:** [inferred] Experiments covered up to 12k tokens; beyond that, the assumption that deviation tokens grow sub-linearly remains untested.
- **Why unresolved:** Multi-agent systems may generate very long contexts; the sparsity of deviations might not hold indefinitely, potentially breaking scaling.
- **What evidence would resolve it:** Evaluate RelayCaching on synthetic or real tasks with context lengths up to 100k+ tokens, measuring TTFT, reuse rate, and accuracy to confirm scaling trends.

## Limitations
- **Generalization across architectures:** The U-shaped deviation profile is validated on a limited set of decoder-only models; it may not hold for encoder-decoder or novel attention patterns, limiting transferability. Confidence: Medium.
- **Task-dependent token sparsity:** For tasks requiring fine-grained, non-local reasoning, deviations could become dense or uncorrelated, breaking the token selector's sparsity assumption. Confidence: Medium-Low.
- **Over-reliance on value cosine similarity:** The method treats value cosine as the primary harm indicator; other deviation types (key misalignment, norm shifts) might cause subtle accuracy drops not captured by evaluation metrics. Confidence: Medium.

## Confidence
- **Claim 1:** Decoding-phase KV caches are sufficiently aligned with full-prefill KV caches despite prefix shift, enabling direct reuse with targeted rectification. **Confidence:** High.
- **Claim 2:** Residual deviations are concentrated in a specific range of middle layers (U-shaped profile), allowing rectification to be confined there for efficiency. **Confidence:** Medium.
- **Claim 3:** Token-wise deviations are sparse and inter-layer correlated, enabling a small, selected subset of tokens to be recomputed for effective rectification. **Confidence:** Medium-Low.

## Next Checks
1. **Architectural stress test:** Apply RelayCaching to a non-standard architecture (e.g., encoder-decoder like T5, or a model with extreme layer counts) to verify if the U-profile and critical range detection fail.
2. **Dense deviation task evaluation:** Construct or identify a benchmark where token relevance is highly distributed (e.g., long-document QA with many equally important entities) and measure if accuracy degrades notably versus full prefill, indicating broken sparsity assumption.
3. **Multi-metric deviation analysis:** Beyond value cosine, measure accuracy impact using alternative deviation signals (e.g., Key-Value norm differences, attention distribution divergence) to validate if value cosine is indeed the dominant predictor of error.
