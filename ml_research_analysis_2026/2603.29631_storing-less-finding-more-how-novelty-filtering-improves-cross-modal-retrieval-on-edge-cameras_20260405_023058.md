# Storing Less, Finding More: How Novelty Filtering Improves Cross-Modal Retrieval on Edge Cameras
## Quick Facts
- **arXiv ID:** 2603.29631
- **Source URL:** https://arxiv.org/abs/2603.29631
- **Reference Count:** 27
- **Primary Result:** A streaming ε-net filter denoises the embedding index by retaining only semantically novel frames, enabling cross-modal retrieval that hits 45.6% on EPIC‑KITCHENS with an 8M on‑device encoder at ~2.7 mW and a 14× reduction in transmitted data.

## Executive Summary
Always‑on edge cameras generate continuous video streams that are rich in semantically redundant frames. These duplicates crowd correct results out of top‑k nearest‑neighbor search in cross‑modal retrieval (text queries → video moments). This paper proposes a streaming architecture: an on‑device ε‑net filter retains only novel frames in a single pass, building a compact denoised embedding index; a lightweight cross‑modal adapter aligns text queries to the compact image space; and a cloud re‑ranker rescues remaining alignment errors. Evaluated on two egocentric datasets (AEA, EPIC‑KITCHENS) across eight vision‑language models (8M–632M parameters), the system significantly improves retrieval compared to offline selection baselines (k‑means, farthest‑point, uniform) and achieves a practical power budget (2.7 mW) while reducing transmitted data by 14×.

## Method Summary
The system comprises three stages. First, an on‑device vision encoder (e.g., TinyCLIP) maps each video frame to a compact embedding. A streaming ε‑net filter maintains a memory of retained embeddings; a new frame is kept only if its maximum similarity to the memory is below a threshold τ, ensuring each semantic event contributes roughly one frame. Second, the retained embeddings are transmitted to the cloud, where a cross‑modal adapter (a trained MLP) projects a frozen text encoder into the image embedding space, bridging the alignment gap of the compact on‑device model. Third, for a text query, the adapter produces a query embedding that is compared against the cloud index; top candidates (e.g., 50) are re‑ranked with a larger model (e.g., SigLIP 2) to produce the final result.

## Key Results
- The streaming ε‑net filter matches or outperforms offline selection strategies (k‑means, farthest‑point, uniform, random) across eight vision‑language models on two egocentric datasets.
- Combining the filter with a LiT adapter and cloud re‑ranker yields 45.6% Hit@5 on held‑out AEA sequences using an 8M on‑device encoder, surpassing CLIP B/32 on all frames (30.7%).
- The pipeline operates at an estimated 2.7 mW on‑device power and reduces transmitted data by 14× (2 KB embeddings vs. ~150 KB raw frames).

## Why This Works (Mechanism)
### Mechanism 1: Redundancy removal resolves top‑k bias
Redundant frames from the same event occupy multiple slots in the top‑k results, crowding out frames from other events that are actually closer to the query. By retaining only novel frames (an ε‑net), each event contributes roughly one frame, so ranking shifts from cluster size to semantic distance.

### Mechanism 2: Single‑pass streaming ε‑net meets edge constraints
The filter processes each frame once: keep a frame if its similarity to all previously retained embeddings is below τ (add it to memory). This online construction yields a maximal ε‑net (coverage: every discarded frame is within ε of a retained frame; separation: no two retained frames are closer than ε) without lookahead, making it suitable for always‑on devices.

### Mechanism 3: Two‑stage alignment compensates for weak on‑device encoder
The compact on‑device encoder is power‑efficient but poorly aligned with text. A small cross‑modal adapter (LiT MLP) projects the frozen text encoder into the image space, improving query alignment. A cloud re‑ranker then corrects residual errors. These components multiply gains: the filter cleans the index, the adapter aligns the query, and the re‑ranker refines results.

- **Nearest‑neighbor search bias in high dimensions:** In high‑dimensional spaces, large clusters of near‑duplicates can dominate top‑k results even if other points are semantically closer. The ε‑net mitigates this by equalizing frame counts per event. *Quick check:* In a high‑dimensional embedding space, why might many near‑duplicate frames from the same event push other relevant frames out of the top‑k list?

## Architecture Onboarding
Component map:
On‑device RGB encoder -> Streaming ε‑net filter -> Sync (BLE) -> Cloud storage -> Cross‑modal adapter -> Cloud re‑ranker

Critical path:
1. Frame captured at 5 FPS.
2. On‑device encoder produces embedding vᵢ.
3. Filter computes max similarity to memory M; if below τ, keeps vᵢ and updates M; discards otherwise.
4. Kept embeddings are queued for BLE sync to cloud.
5. Cloud stores embeddings in an index.
6. At query time: text -> frozen text encoder -> adapter -> query embedding q.
7. Approximate nearest‑neighbor search retrieves top‑k (e.g., 50) candidates.
8. Cloud re‑ranker rescales candidates; final top‑5 returned.

Design tradeoffs:
- ε threshold τ: Lower τ increases filtering but risks dropping brief events; higher τ reduces filtering. Must match event duration distribution (Table 5).
- On‑device encoder size: Smaller models reduce power but weaken alignment; adapter and re‑ranker compensate.
- Adapter training: Requires in‑domain captions; mismatched domains underperform.
- Re‑ranker candidate count: Larger k improves recall but costs more compute; denoised index reduces required k.
- Streaming vs. offline: Streaming filter is practical for edge but may be sub‑optimal compared to offline clustering.

Failure signatures:
- Over‑filtering (τ too low): Many events have zero retained frames; recall drops (Table 5, τ=0.90 on EPIC).
- Under‑filtering (τ too high): Compression ratio low, index remains crowded, little gain.
- Poor cross‑modal alignment: On‑device alone gives low Hit@5 (e.g., TinyCLIP 11%); without adapter, gains limited.
- Threshold drift: As M grows, new frames become less novel; compression ratio gradually increases (§6).
- Over‑fitting in fine‑tuning: Large train/test gap (23 pp in Table 4) indicates poor generalization.

First three experiments:
1. Does filtering improve retrieval? Compare ε‑net against full set, k‑means, farthest‑point, uniform, random across eight models on AEA (Table 2, Figure 2). ε‑net outperforms in most models, especially compact ones.
2. Does LiT adapter close the alignment gap? Ablate adapter on TinyCLIP with full and filtered index (Table 3). Adapter gives +4.2 pp and multiplicative effect with filtering.
3. Does domain fine‑tuning help? Jointly fine‑tune image encoder and adapter on 10,911 caption‑embedding pairs; evaluate held‑out AEA/EPIC (Table 4). Gains of +8.1 pp on AEA test, but large generalization gap.

## Open Questions the Paper Calls Out
### Open Question 1: Generalization across environments
Does ε‑net novelty filtering improve cross‑modal retrieval on edge cameras in non‑kitchen environments (e.g., outdoor, industrial), where visual diversity is higher?  
*Basis:* The Limitations section notes both evaluated datasets are kitchen‑heavy and calls for validation in outdoor, industrial, or multi‑room environments.  
*Unresolved:* Current experiments are limited to kitchen‑centric datasets; generalizability to other visual contexts is unknown.

### Open Question 2: Adaptive threshold for stable streaming
Can an online adaptive threshold τ for the ε‑net filter maintain stable compression ratios and retrieval performance across long videos and varying event durations without manual tuning?  
*Basis:* The authors state τ must be matched to event duration and note compression ratio drifts over time as the buffer grows; they propose adaptive algorithms as future work.  
*Unresolved:* Fixed τ (0.92) requires dataset‑specific tuning and suffers from drift, potentially degrading retrieval in continuous, long‑duration streams.

### Open Question 3: Data needed to close fine‑tuning gap
How much additional and diverse training data is needed to close the large train/test performance gap observed in joint fine‑tuning of the on‑device encoder and LiT adapter?  
*Basis:* The paper reports a 23‑point gap (48.3% vs. 25.0%) on held‑out data and notes that more training data from diverse environments should narrow this gap.  
*Unresolved:* Fine‑tuning yields substantial gains on training data but significantly lower retrieval on unseen sequences, indicating overfitting due to the small training set (10,911 pairs from 20 sequences).

## Limitations
- AEA dataset is not publicly available; primary results cannot be independently verified.
- Implementation details are missing (exact model versions, preprocessing, adapter hyperparameters, re‑ranker configuration).
- Fixed ε threshold sensitivity: may drop brief events or retain too many frames if event duration distribution differs; performance varies with τ (Table 5).
- Fine‑tuning overfitting: Large train‑test gap (23 pp) indicates limited generalization.

## Confidence
- **Mechanism 1 (redundancy removal reduces top‑k bias):** High – supported by multi‑model, multi‑dataset experiments with statistical tests.
- **Mechanism 2 (single‑pass streaming ε‑net):** High – streaming property is inherent; offline baselines are matched or beaten under equal compression.
- **Mechanism 3 (adapter + re‑ranker compensates weak encoder):** Medium – gains shown in ablations, but depend on adapter training data and fine‑tuning details not fully disclosed; risk of domain mismatch.
