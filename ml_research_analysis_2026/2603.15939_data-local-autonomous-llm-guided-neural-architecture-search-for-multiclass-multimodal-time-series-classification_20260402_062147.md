# Data-Local Autonomous LLM-Guided Neural Architecture Search for Multiclass Multimodal Time-Series Classification

## Quick Facts
- **arXiv ID**: 2603.15939
- **Source URL**: https://arxiv.org/abs/2603.15939
- **Reference count**: 39
- **Primary result**: A modular decomposition with LLM-guided neural architecture search achieves competitive accuracy on multimodal time-series benchmarks while preserving data privacy, with notable gains on SleepEDFx (84.7% → 87.9%) and EthanolConcentration (32.7% → 44.1%).

## Executive Summary
This paper tackles the problem of automating neural architecture design for sensitive multimodal time-series classification under strict data-local constraints, where raw data cannot leave the premises. The proposed framework uses a modular decomposition: independent binary expert classifiers are trained per modality and per class, and an LLM-based controller remotely proposes expert architectures based solely on non-sensitive trial summaries (metrics, logs). All training and evaluation occur locally, ensuring data never exits the secure environment. On 22 benchmark tasks, the staged expert-fusion baseline already outperforms standard end-to-end training in most cases. Further, LLM-guided neural architecture search (NAS) yields additional improvements on several datasets, demonstrating that effective automation is possible without compromising data privacy.

## Method Summary
The method consists of two core components: a modular model decomposition and a privacy-preserving NAS loop. The model decomposes a multiclass multimodal problem into \(M \times C\) binary experts, where each expert \(f_{m,c}\) predicts whether a sample from modality \(m\) belongs to class \(c\). After all experts are trained independently, their penultimate embeddings are concatenated and fed to a lightweight fusion MLP. Training occurs in two stages: first all experts are optimized to convergence, then they are frozen while the fusion MLP is trained.

For NAS, a remote LLM controller orchestrates an iterative loop via a constrained file-based artifact interface. The controller reads `manifest.md` (search context) and `results.json` (structured outcomes) to reason about progress, then writes a `directive.json` specifying the next candidate architecture for a targeted expert. The local executor—which owns the raw data—validates the directive, trains the specified expert from scratch under a fixed protocol, evaluates it on a validation split, and writes back metrics and logs. This decouples controller intelligence from raw data access, guaranteeing locality.

## Key Results
- The staged expert-fusion baseline surpasses end-to-end training on 12 of 21 UEA datasets (e.g., ArticularyWordRecognition: 96.3% vs 91.7%).
- LLM-guided NAS improves accuracy on SleepEDFx from 84.7% (baseline) to 87.9% after 30 search cycles.
- NAS boosts EthanolConcentration accuracy from 32.7% to 44.1% after 60 cycles, recovering performance from a weak baseline.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Decomposing a multiclass multimodal problem into independent binary experts per modality and class improves representation learning and avoids interference between heterogeneous modalities and class confusions.
- **Mechanism**: Each binary expert \(f_{m,c}\) is trained on a single modality \(x_m\) to answer "is this class \(c\)?" This forces the expert's penultimate representation \(h_{m,c}(x_m)\) to encode evidence specific to that modality-class pair, rather than a shared representation that must disentangle multiple classes and modalities simultaneously. These specialized embeddings are then concatenated and fed to a fusion MLP.
- **Core assumption**: Modality-specific, class-conditional representations are more informative and less noisy for fusion than end-to-end learned shared representations, especially when modalities are heterogeneous and class structures are non-uniform.
- **Evidence anchors**:
  - [abstract]: "We adopt a modular decomposition in which we train one binary expert per class and modality... NAS is applied only to the experts."
  - [section 3.1]: "Each expert... learns what modality m has to say about whether an example belongs to class c... the expert embedding h_m,c(x_m) can therefore be interpreted as a modality-specific summary of evidence for class c."

### Mechanism 2
- **Claim**: An artifact-based file interface between a remote LLM controller and a local executor enables effective, long-horizon architecture search while guaranteeing data locality and privacy.
- **Mechanism**: The remote LLM proposes architectures by reading/writing only human-readable (`manifest.md`) and structured non-sensitive (`results.json`, `directive.json`) files. The local executor performs all data access, preprocessing, training, and evaluation, writing back only metrics, logs, and code artifacts. This decouples controller intelligence from data exposure.
- **Core assumption**: Non-sensitive, aggregated trial summaries (validation metrics, learning curves, failure traces) contain sufficient information for an LLM to guide architecture search without needing raw data or intermediate feature statistics.
- **Evidence anchors**:
  - [abstract]: "The controller observes only non-sensitive trial summaries... without ever accessing raw samples or intermediate feature representations."
  - [section 3.2]: "Communication... is mediated by files... the controller interacts with the local environment only through the constrained artifact interface... ensuring that sensitive data are not exposed."

### Mechanism 3
- **Claim**: Two-stage training (first train all binary experts to convergence, then freeze them and train the fusion MLP) provides a strong, stable baseline that is amenable to subsequent architecture search on the experts.
- **Mechanism**: Stage 1 optimizes each expert \(f_{m,c}\) independently on its binary task. Stage 2 freezes all expert weights and trains only the fusion MLP \(g(z)\) on the multiclass task using the concatenated, frozen expert embeddings. This isolates expert learning from fusion dynamics.
- **Core assumption**: The representations learned by well-performing binary experts are already suitable for fusion; optimizing the fusion head separately is sufficient and avoids destabilizing expert training via end-to-end gradients across all \(M*N\) experts.
- **Evidence anchors**:
  - [abstract]: "The staged expert-fusion baseline already improves over end-to-end training in most cases."
  - [section 3.1]: "Our default training protocol is modular and performed in two stages: experts are trained first and then frozen, after which only the fusion network is trained."
  - [results Table 1]: Staged baseline accuracy exceeds end-to-end in 12 of 21 UEA datasets (e.g., AWR: 96.3% vs 91.7%, CT: 95.8% vs 90.1%).

## Architecture Onboarding
- **Component map**:
  Local Executor (On-Premise) -> Shared Artifact Store (Filesystem) <- Remote Controller (LLM)
  Local Executor components: fixed training protocol, validation metric calculator, artifact writer.
  Remote Controller components: architecture proposer, artifact reader/writer.
  Shared Artifact Store files: manifest.md, results.json, directive.json, models/, code/.

- **Critical path**:
  1. LLM reads manifest.md and all entries in results.json.
  2. LLM formulates a modification to an expert's architecture/preprocessing.
  3. LLM writes a new directive.json specifying target (modality, class) expert and new model.py/preprocessing.py code.
  4. Local executor detects new directive.json, validates it, loads code, trains the specified expert from scratch under fixed protocol, evaluates on validation split.
  5. Executor appends results (metrics, status, trace) to results.json and updates manifest.md with a summary.
  6. Loop returns to step 1. Fusion MLP is trained only after all expert architectures for a full cycle are finalized.

- **Design tradeoffs**:
  - **Search Flexibility vs. Stability**: The LLM can propose arbitrary code changes (high flexibility) but risks generating invalid or unstable training runs. The fixed local training protocol acts as a guardrail.
  - **Privacy vs. Guidance Fidelity**: The artifact interface maximizes privacy but may omit nuanced information (e.g., per-class confusion matrices, example-level failure modes) that could guide search more efficiently.
  - **Modularity vs. Joint Optimization**: The expert-fusion split simplifies search and privacy but precludes end-to-end co-adaptation between experts and fusion. Performance gains from NAS are limited to expert quality.

- **Failure signatures**:
  - **LLM Proposals**: Frequent "failure" entries in results.json for a specific expert type (e.g., all EMG experts crash) → LLM is proposing architectures incompatible with that modality's data shape or noise profile.
  - **Search Stagnation**: Long flat lines in search trajectory plots (Figures 3 & 4) for all experts → LLM is not proposing meaningful improvements; may be stuck in a local optimum or misinterpreting metrics.
  - **Fusion Degradation**: Staged baseline accuracy (baseline staged in Table 1) is high, but LLM NAS accuracy is lower → NAS found expert architectures that perform well in isolation (high binary F1) but produce representations that are poor for the joint multiclass task (fusion MLP fails).

- **First 3 experiments**:
  1. **Baseline Staged Model Sanity Check**: Train the default expert architecture (Res-Inception) and fusion MLP on a small, easy dataset (e.g., ArticularyWordRecognition). Verify that staged baseline exceeds simple end-to-end baseline and that all binary experts achieve >90% validation accuracy. Confirms the modular pipeline works.
  2. **Single-Expert NAS Proof-of-Concept**: Run a 5-cycle NAS targeting only one expert (e.g., f_EEG,Wake on SleepEDFx). Monitor results.json to ensure the LLM proposes varied architectures and that validation F1 for that single expert improves. Isolates the NAS loop logic.
  3. **Full-Scale NAS on a Weak Baseline Dataset**: Run the full LLM NAS configuration on a dataset where the staged baseline is poor (e.g., EthanolConcentration at 32.7%). Use a longer search budget (e.g., 30+ cycles). Goal: verify the NAS can recover meaningful performance (toward 44%+) from a weak starting point, demonstrating its ability to find suitable architectures for difficult tasks.

## Limitations
- **Undocumented LLM specifics**: Exact prompt structure, system message, and model version are unreported, impeding replication and analysis of guidance fidelity.
- **Incomplete training hyperparameters**: The fixed training protocol's optimizer choice, learning rate schedule, batch size, early stopping criteria, and class imbalance handling details are missing.
- **Modular decomposition constraint**: The inherent separation of experts blocks cross-modal interactions, potentially limiting applicability to tasks where joint modality features are critical for classification.

## Confidence
- **Staged baseline superiority over end-to-end training**: High (empirical support across 12/21 UEA tasks)
- **LLM-guided NAS performance gains**: Medium (dependent on undocumented LLM specifics and search dynamics)
- **Privacy-preserving design efficacy**: Medium (interface is clearly specified but guidance fidelity from limited context remains uncertain)

3. Introduce end-to-end fine-tuning of experts after NAS to assess the performance cost of the frozen modular design.
