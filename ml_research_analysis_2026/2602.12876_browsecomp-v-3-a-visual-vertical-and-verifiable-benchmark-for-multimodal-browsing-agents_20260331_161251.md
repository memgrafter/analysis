# BrowseComp-$V^3$: A Visual, Vertical, and Verifiable Benchmark for Multimodal Browsing Agents

## Quick Facts
- arXiv ID: 2602.12876
- Source URL: https://arxiv.org/abs/2602.12876
- Reference count: 8
- Primary result: State-of-the-art multimodal browsing agents (e.g., GPT-5.2) achieve only 36% success rate, while humans reach 68%, revealing significant capability gaps.

## Executive Summary
BrowseComp-$V^3$ is a benchmark for evaluating multimodal browsing agents on deep, multi-hop reasoning that intertwines textual and visual evidence across publicly searchable web pages. It comprises 300 handcrafted questions, each annotated with expert‑validated subgoals and gold trajectories. The benchmark enforces strict public searchability of all evidence and introduces a subgoal‑driven process score alongside final‑answer accuracy. Experiments with OmniSeeker—an agent integrating diverse web and visual tools—show that even advanced models like GPT‑5.2 attain only 36% success, compared to 68% for humans. Visual grounding errors dominate failures, and the gap between process and success scores highlights challenges in long‑horizon consistency and native multimodal integration.

## Method Summary
The benchmark requires agents to answer queries by retrieving and synthesizing evidence from publicly accessible sources, including images. Each question is decomposed into ordered subgoals, forming a gold trajectory for evaluation. Agents operate with a tool suite (TextSearch, WebVisit, ImageSearch, ImageCrop, ReverseImageSearch) and are limited to 20 interaction turns. Performance is measured by Success Rate (correct final answer) and Process Score (proportion of completed subgoals). This design ensures reproducibility and isolates reasoning breakdowns, while the public‑searchability constraint prevents reliance on memorized or inaccessible information.

## Key Results
- SOTA models (GPT‑5.2) achieve 36% success; humans reach 68%.
- Tool‑augmented OmniSeeker substantially improves baselines, enabling open‑source models to match proprietary systems.
- Visual grounding errors are the predominant failure mode; a large gap between Process Score and Success Rate indicates poor long‑sequence synthesis.

## Why This Works (Mechanism)

### Mechanism 1: Multi‑level, Cross‑modal Interleaving
Claim: Enforcing multi‑level, cross‑modal interleaving of evidence across hops forces genuine multimodal integration and prevents shortcuts via parametric knowledge.  
Mechanism: Evidence is distributed across text and images within and across pages, requiring alignment (text‑image within a page), integration (combining modalities on a page), and relational reasoning (connecting across images/pages). This creates dependency chains where missing a visual detail breaks later reasoning.  
Core assumption: Real‑world deep search is not uni‑modal; success requires sequential, verifiable retrieval and synthesis.  
Evidence: Abstract and Section 3.1 specify hierarchical cross‑modal complexities; related work notes that prior benchmarks lack this strict interleaving.  
Break condition: If evidence for a subgoal can be retrieved from a single page or from text alone without visual analysis, the cross‑modal complexity collapses.

### Mechanism 2: Public Searchability Enforcement
Claim: Ensuring all evidence is publicly searchable guarantees fairness, reproducibility, and realistic tool‑use evaluation.  
Mechanism: During annotation, every evidence piece is manually verified to be discoverable via standard public search tools (text search, image search). Complete gold trajectories are recorded, filtering out questions solvable by internal knowledge or requiring inaccessible media.  
Core assumption: A valid benchmark must mirror open‑world browsing constraints; otherwise success may reflect memorization or privileged data.  
Evidence: Abstract and Section 3.1 state the evidence traceability requirement; Section 1 criticizes prior benchmarks for using non‑searchable sources.  
Break condition: If a model solves a task using parametric knowledge when the evidence is nominally public but practically unreachable (e.g., buried in deep pagination), the searchability guarantee fails.

### Mechanism 3: Subgoal‑driven Process Evaluation
Claim: Decomposing questions into discrete, ordered subgoals enables fine‑grained analysis of intermediate reasoning and systematic characterization of capability boundaries.  
Mechanism: Each question is broken into subgoals (e.g., "identify athlete", "find bracket", "extract score"). Process Score is the fraction of subgoals achieved, turning binary outcomes into diagnostic profiles that reveal failures at perception, retrieval, integration, or planning.  
Core assumption: Final‑answer accuracy is noisy for complex tasks; analyzing trajectories is necessary to understand why models fail and to guide improvements.  
Evidence: Abstract and Section 4.1 define Process Score; Section 5.1 uses it to show models complete subgoals but struggle with long‑sequence consistency.  
Break condition: If subgoals are poorly defined (overlapping, non‑sequential) or not grounded in actual retrieval steps, the score cannot reliably distinguish capability limits.

## Foundational Learning

- **Cross‑modal multi‑hop reasoning**  
  Why needed: The benchmark’s core challenge is chaining evidence across text and images over multiple retrieval steps; without understanding how modalities complement and constrain each other, an agent cannot design effective search plans.  
  Quick check: For a query about a sports event shown in an image, what visual detail must be extracted first to formulate the next text search query, and why can’t the model just describe the whole image at once?

- **Tool‑augmented agent architecture**  
  Why needed: Evaluation assumes agents can call search/vision tools; understanding the I/O contract of tools (e.g., `WebVisit` returns parsed text, `ImageCrop` returns a cropped PNG) is essential to interpret why a trajectory succeeds or fails.  
  Quick check: If an `ImageSearch` tool returns a set of candidate image URLs, what subsequent step is needed to verify which one contains the specific visual evidence required for the current subgoal?

- **Process‑level metrics vs. outcome metrics**  
  Why needed: The paper argues that high Process Score with low Success Rate indicates models can retrieve pieces but not synthesize them—a critical diagnostic. This requires thinking in terms of partial progress states.  
  Quick check: If a model achieves 80% Process Score but 10% Success Rate, what does this suggest about its failure mode? (Hint: look at section 5.1 ability boundaries.)

## Architecture Onboarding
**Component map:**  
Brain (LLM/MLLM) ↔ State Tracker ↔ Tool Suite (TextSearch, WebVisit, ImageSearch, ImageCrop, ReverseImageSearch). The Evaluator operates offline.

**Critical path:**  
1. Parse & Plan: Input (query + initial image) → Brain decomposes into ordered subgoals.  
2. First‑hop retrieval: Use TextSearch/ImageSearch based on initial clues.  
3. Iterative loop: For each subgoal: Brain selects tool → Tool Suite executes → Brain parses output → updates State Tracker → verifies subgoal completion; backtrack if needed.  
4. Synthesis: After all subgoals, Brain compiles final answer citing evidence.  
5. Logging: Full trajectory recorded for evaluation.

**Design tradeoffs:**  
- Tool generality vs. control: Generic tools (e.g., WebVisit) are flexible but return noisy HTML; specialized parsers improve precision but reduce coverage.  
- Interaction depth vs. efficiency: More turns allow correction but increase cost/time; OmniSeeker caps at 20 turns.  
- Centralized vs. modular planning: Single Brain plans all steps (simpler) vs. separate planner and reasoner (more robust but complex).

**Failure signatures:**  
- Visual grounding error: Misidentification of object/region in image.  
- Tool call failure: Invalid parameters or uninformative returns.  
- Planning drift: Agent loses track of original subgoal.  
- Subgoal fixation: Repeated attempts on one subgoal without progressing.  
- Answer vague: Final answer lacks specificity or cites non‑retrieved evidence.

**First 3 experiments:**  
1. Baseline replication: Run GPT‑5.2 (tool‑free) and GPT‑5.2‑Thinking on a 10‑question sample to verify the ~36% vs ~6% gap and confirm tool‑free models fail on cross‑modal tasks.  
2. Process score calibration: Have two human annotators independently score model trajectories against gold subgoals; measure inter‑annotator agreement and revise subgoal definitions if low.  
3. Tool ablation test: Disable ImageCrop or ReverseImageSearch in OmniSeeker and compare Success Rate drop on questions requiring inter‑image reasoning, isolating tool utility.

## Open Questions the Paper Calls Out

### Open Question 1
**Question:** How can multimodal LLMs be architecturally enhanced to natively perform cross‑modal multi‑hop reasoning without excessive reliance on external tools?  
Basis: The paper identifies a fundamental lack of native multimodal reasoning capabilities; despite tool augmentation, SOTA models achieve only 36% success, and humans outperform them significantly.  
Why unresolved: Current models depend heavily on retrieved evidence but fail to integrate and reason across modalities and hops natively, leading to shallow reasoning and inconsistency over long sequences.  
Evidence to resolve: Develop novel architectures that tightly integrate visual and textual reasoning (e.g., shared attention, cross‑modal memory) and evaluate on benchmarks like BrowseComp‑V3, comparing native vs. tool‑augmented performance on cross‑modal hops.

### Open Question 2
**Question:** What specific training objectives or data augmentation strategies can significantly reduce visual grounding and perception failures in complex, noisy web environments?  
Basis: Failure analysis shows Visual Grounding Error and Image Perception Failure dominate, especially for open‑source models. Models struggle with real‑world web noise.  
Why unresolved: MLLMs are typically trained on clean, curated datasets and lack robustness to clutter, low‑quality images, and overlays.  
Evidence to resolve: Create large‑scale noisy web‑image datasets with controlled variations and train with objectives that penalize grounding errors (e.g., contrastive learning on noisy crops). A significant drop in perception‑related failures on BrowseComp‑V3’s visual subsets would indicate progress.

### Open Question 3
**Question:** Can reinforcement learning with process‑oriented rewards (e.g., subgoal completion) effectively improve long‑horizon planning and consistency in multimodal browsing agents?  
Basis: The subgoal‑driven Process Score reveals a gap between intermediate progress and final success; models complete subgoals but fail to chain them. The conclusion suggests RL as a potential pathway.  
Why unresolved: Sparse final‑answer rewards may be inadequate; shaping rewards based on subgoal progress is proposed but untested.  
Evidence to resolve: Implement RL where agents receive rewards for completing expert‑validated subgoals; measure improvements in both Process Score and Success Rate on BrowseComp‑V3. Strong correlation would validate the approach.

### Open Question 4
**Question:** How can benchmarks for multimodal browsing agents be systematically designed to ensure both high task complexity and strict evidence traceability, and how transferable are these design principles across domains?  
Basis: BrowseComp‑V3 enforces public searchability and temporal stability to ensure reproducibility, unlike prior benchmarks with non‑searchable sources.  
Why unresolved: The paper does not address scalability to thousands of tasks, more domains, or dynamic information. Trade‑offs between complexity, searchability, and annotation cost remain unclear.  
Evidence to resolve: Build a larger multi‑domain benchmark following the same principles, with automated verification of evidence searchability. Analyze failure modes across domains to test consistency and discriminativity.

## Limitations
- **Dataset accessibility:** The 300‑question dataset with gold trajectories is described but no public release link is provided, blocking independent replication.
- **Tool implementation vagueness:** Exact API endpoints, rate limits, and parsing logic for Serper/Jina integrations are unspecified, risking implementation mismatches.
- **Subgoal definition reliability:** Process Score depends on expert‑validated subgoals, but inter‑annotator agreement is unreported, risking evaluation noise if subgoals are ambiguous.

## Confidence
- Multi‑level cross‑modal interleaving: Medium
- Public searchability enforcement: High
- Subgoal‑driven evaluation: Medium
- Overall claim that the benchmark highlights critical bottlenecks: Low
