# Do LLMs Benefit From Their Own Words?

## Quick Facts
- **arXiv ID**: 2602.24287
- **Source URL**: https://arxiv.org/abs/2602.24287
- **Reference count**: 40
- **Primary result**: Removing prior assistant responses does not degrade quality on 36.4% of turns and can improve it by avoiding context pollution; an adaptive classifier retains >95% full-context performance with only 70% of tokens.

## Executive Summary
This paper investigates whether large language models (LLMs) benefit from including their own prior responses in multi-turn conversations. Comparing standard full-context (FC) prompting with a user-turn-only (assistant-omitted, AO) approach across four models on real-world technical dialogues, the study finds that a substantial fraction of user prompts (36.4%) are self-contained and do not require assistant history. Moreover, full context can sometimes harm performance due to "context pollution"—the propagation of errors from earlier model outputs. An adaptive classifier that selectively omits assistant history based on prompt characteristics retains over 95% of FC performance while reducing context length by 5–10×, suggesting that indiscriminate storage of assistant responses is often unnecessary and potentially detrimental.

## Method Summary
The authors filtered 150 technical conversations each from WildChat and ShareLM (English, 5–10 rounds). Four LLMs generated responses per turn under two configurations: FC (full history) and AO (prior user turns only, with assistant replies replaced by a placeholder and a system message). A GPT-5 judge evaluated pairwise response quality and on-topic adherence, seeing the full conversation history. Turn-level categories (new ask, follow-up with/without feedback) were labeled using GPT-5. Finally, a logistic regression classifier was trained on metadata, embeddings, and categories to predict when AO is preferable, sweeping thresholds to balance performance and context reduction.

## Key Results
- 36.4% of user prompts are self-contained "new asks" where assistant history is not needed.
- AO sometimes outperforms FC due to context pollution from error propagation in prior assistant responses.
- An adaptive classifier retains >95% of full-context win rate while using only 70% of context tokens.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: A substantial fraction of user prompts are self-contained and do not require prior assistant responses.
- **Mechanism**: Many multi-turn user turns introduce new, independent queries or provide sufficient context intrinsically, making assistant outputs unnecessary.
- **Core assumption**: User prompts often contain all necessary information, and assistant history rarely provides critical missing details.
- **Evidence anchors**: 
  - [abstract]: "multi-turn conversations consist of a substantial proportion (36.4%) of self-contained prompts"
  - [section]: Section 2.3 defines prompt categories and quantifies new-ask turns at 36.4%.
- **Break condition**: If self-contained prompts were very rare (<10%), omitting assistant history would likely degrade performance on most turns.

### Mechanism 2
- **Claim**: Prior assistant responses can introduce errors, hallucinations, or stylistic artifacts that propagate into subsequent turns (context pollution).
- **Mechanism**: When models condition on their own earlier outputs, they may over-adopt incorrect information or patterns, leading to compounded mistakes.
- **Core assumption**: LLMs tend to overfit to their own previous generations, especially when those contain subtle errors.
- **Evidence anchors**: 
  - [abstract]: "context pollution—where models propagate errors from their own earlier outputs"
  - [section]: Section 2.5 illustrates cases where AO outperforms FC due to error propagation (e.g., code parameter leakage, hallucinated citations).
- **Break condition**: If models never made errors or users corrected them immediately, context pollution would not occur.

### Mechanism 3
- **Claim**: An adaptive classifier that predicts when assistant history is beneficial can retain near full-context performance while significantly reducing context length.
- **Mechanism**: By training on features like prompt category, embedding similarities, and metadata, the system learns to selectively omit assistant responses on turns where they are likely unnecessary or harmful.
- **Core assumption**: The need for assistant history is predictable from the current user prompt and conversation history.
- **Evidence anchors**: 
  - [abstract]: "adaptive classifier ... retains over 95% of full-context performance while using only 70% of the context tokens"
  - [section]: Section 3 describes the feature set and logistic regression model; Fig. 5 shows the performance-context tradeoff.
- **Break condition**: If prompt features have low predictive power (F1 ~0.61), the adaptive approach yields smaller gains.

## Architecture Onboarding
- **Component map**:  
  Data pipeline -> Model serving -> Context configurator -> Evaluation engine -> Prompt categorizer -> Adaptive classifier -> Analysis
- **Critical path**:  
  1. Sample and filter real-world multi-turn conversations (150 per dataset).  
  2. For each conversation and model, generate responses for every turn under both FC and AO conditions.  
  3. Evaluate all turn-wise response pairs using LLM-judge with randomized ordering.  
  4. Classify prompt categories for each turn.  
  5. Train logistic regression on a training split to predict judge preference.  
  6. Sweep thresholds on predicted probabilities to select context configuration per turn; evaluate on test set.  
  7. Measure context length savings and performance retention.
- **Design tradeoffs**:  
  - Full context preserves information but risks pollution and higher cost; AO reduces length but may lose necessary info on some turns.  
  - Fixed AO is simple but suboptimal for turns needing assistant history; adaptive improves tradeoff but adds classification overhead.  
  - Using an LLM-as-judge with full context may bias evaluations toward full-context outputs; user-turn-only judge reduces bias but might not assess turns referencing assistant replies accurately.
- **Failure signatures**:  
  - AO wins >50% on follow-up prompts without feedback, indicating over-reliance on assistant history when not needed.  
  - Adaptive classifier F1 score ~0.61 suggests weak predictive power; performance gain over simple heuristics is small.  
  - Judge-human alignment below 90% on sample could invalidate automatic evaluation.  
  - Context length reduction not observed (e.g., if assistant responses are very short) would undermine the efficiency argument.
- **First 3 experiments**:  
  1. Baseline replication: Run FC vs. AO on a small subset (e.g., 10 conversations) to confirm AO does not degrade quality significantly.  
  2. Prompt category validation: Manually verify the prompt category annotations on a sample to ensure labeling reliability.  
  3. Context pollution audit: Manually inspect turns with large AO-FC score gaps to confirm error propagation and document patterns.

## Open Questions the Paper Calls Out
1. Under which specific prompt characteristics (e.g., topic shifts, user intent clarity) is retaining prior assistant responses beneficial versus harmful? The paper identifies broad categories but does not isolate precise linguistic or pragmatic features; the adaptive classifier's modest F1 (~0.61) suggests current features are insufficient for reliable prediction.
2. How robust are the findings to the choice of LLM judge, and could judge bias from conditioning on assistant history itself inflate the perceived benefit of full context? The main evaluations use a judge that sees full history; a secondary judge seeing only user history showed AO performing better, but this shift is not fully disentangled.
3. Can more granular context-filtering strategies (beyond binary omission) effectively retain only the relevant assistant turns while discarding polluting ones? The paper demonstrates entire assistant histories are often unnecessary but does not test selective preservation of specific turns.
4. Do the results generalize to non-technical, open-domain conversations (e.g., creative writing, casual chat) where multi-turn dependence might be more implicit or stylistic? The dataset filtering explicitly selects technical conversations using math/coding keywords, limiting generalizability.
5. What causes the observed tendency for models to over-condition on prior responses (context pollution), and is it mitigated by model scale, architecture, or training objectives? Context pollution is documented across all tested models including GPT-5.2, but root causes are not investigated.

## Limitations
- Reliance on GPT-5 for evaluation and prompt categorization introduces potential biases; exact judge configuration and FC baseline system prompt are unspecified.
- Dataset is limited to technical dialogues; findings may not generalize to open-domain or social conversations.
- Adaptive classifier shows modest predictive power (F1 ~0.61), limiting the robustness of its recommendations.
- Evidence for the 36.4% self-contained prompt proportion depends on GPT-5 labeling accuracy, with weak direct corpus support.

## Confidence
- **Self-contained prompt proportion (36.4%)**: Medium – depends on GPT-5's labeling accuracy; manual verification not performed.
- **Context pollution as cause of FC degradation**: Medium – illustrated with examples but not systematically measured across all turns.
- **Adaptive filtering efficacy**: Medium – demonstrated for technical WildChat/ShareLM with specific models; generalizability uncertain due to modest classifier performance.

## Next Checks
1. Manual annotation of a stratified sample of turns to verify prompt category distribution and GPT-5's labeling accuracy.
2. Human evaluation of FC vs. AO response pairs to measure judge-human agreement and validate the LLM-as-judge setup.
3. Apply the trained adaptive classifier to a held-out non-technical conversation dataset to test generalizability beyond the technical domain.
