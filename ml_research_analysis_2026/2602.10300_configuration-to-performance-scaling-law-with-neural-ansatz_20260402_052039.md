# Configuration-to-Performance Scaling Law with Neural Ansatz

## Quick Facts
- **arXiv ID:** 2602.10300
- **Source URL:** https://arxiv.org/abs/2602.10300
- **Reference Count:** 40
- **Primary Result:** A neural model (NCPL) trained on 3,000+ pretraining logs predicts final loss from full configuration with 20–40% lower error than Chinchilla’s law and generalizes to larger scales.

## Executive Summary
This paper introduces the Neural Configuration-to-Performance Law (NCPL), a method that predicts the final pretraining loss of large language models given a full training configuration—including model size, data scale, optimizer, and hyperparameters—using a fine-tuned language model. Unlike classical scaling laws such as Chinchilla, which assume optimal hyperparameters and only depend on model and data size, NCPL captures complex, non-linear interactions across all configuration variables. Trained on a diverse dataset of over 3,000 pretraining runs, NCPL reduces mean absolute error by 20–40% compared to Chinchilla on in-distribution tasks and maintains predictive power on out-of-distribution runs using up to 10× more compute. The approach also supports joint hyperparameter tuning and loss curve prediction, demonstrating that neural ansätze can learn scalable performance forecasts from open-source logs.

## Method Summary
NCPL uses a two-stage fine-tuned LLM (Qwen3-1.7B) to map a serialized configuration string to a predicted loss residual. First, a Chinchilla scaling law is fitted per data source on the training runs to compute a baseline loss $\ell_{\text{chinchilla}}(N, D)$ based only on model size $N$ and data size $D$. The target residual is $y = \text{observed loss} - \ell_{\text{chinchilla}}$. Each configuration is encoded as a sequence of key-value pairs: categorical fields (e.g., optimizer) are tokenized with the LLM’s tokenizer, while numerical fields (e.g., learning rate) pass through a shared two-layer MLP to produce embeddings inserted as special tokens. The LLM backbone processes this mixed sequence, and a linear head applied to the last token’s hidden state predicts $y$. Stage 1 trains only the MLP and head; Stage 2 full fine-tuning refines the entire model. At inference, the predicted residual is added to the Chinchilla baseline to obtain the final loss estimate.

## Key Results
- NCPL achieves 20–40% lower mean absolute error than the Chinchilla law on in-distribution final-loss prediction, with Spearman correlations above 0.98.
- It generalizes to out-of-distribution runs with up to 10× more compute (larger $N$ and $D$) than any training example.
- NCPL enables joint tuning of multiple hyperparameters (e.g., learning rate and batch size) with performance comparable to specialized baselines and extends to predict full training loss curves accurately.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** NCPL leverages the inductive biases of a pretrained language model to encode heterogeneous training configurations and capture complex, non-linear interactions between hyperparameters.  
**Mechanism:** The configuration is serialized into a structured text-like sequence (key-value pairs). Categorical fields use standard token embeddings; numerical fields pass through a small MLP to produce dense embeddings. The transformer backbone processes this mixed representation and outputs a scalar prediction via a linear head. Pretraining on diverse natural language and code data provides priors that help generalize from limited scaling logs.  
**Core assumption:** The base LLM’s pretraining has endowed it with useful representations for structured data (e.g., recognizing that “optimizer: adamw” and “learning rate: 0.001” are semantically related) and that these representations transfer to the regression task.  
**Evidence anchors:**  
- Abstract: “Using a fine-tuned large language model (Qwen3-1.7B) trained on over 3,000 diverse pretraining logs … achieves 20–40% lower mean absolute error than the configuration-agnostic Chinchilla law.”  
- Section 3.2: “Compared to training from scratch, our ablation study shows that fine-tuning a pretrained model yields better performance on datasets with diverse configurations.”  
- Corpus: Weak—neighbors discuss scaling laws generally but not neural ansätze for configuration mappings; claim is primarily supported by the paper’s own experiments.  
**Break condition:** If the base model’s architecture cannot effectively encode structured numerical data (e.g., lacks an MLP adapter) or if pretraining data lacked similar key-value patterns, the mechanism would fail, yielding high in-distribution error.

### Mechanism 2
**Claim:** Residual learning relative to a Chinchilla-law baseline isolates configuration-specific effects beyond model and data size, simplifying the learning problem and improving extrapolation.  
**Mechanism:** For each run, a Chinchilla law is fit on the training set (per source) to predict a baseline loss based only on $N$ and $D$. NCPL is trained to predict the residual $y$ = actual loss − baseline. This removes the strong, coarse trend with scale, leaving a smoother target that depends more on hyperparameters and optimizer choices.  
**Core assumption:** The Chinchilla law approximates the dominant scaling trend reasonably well, and the residual is a lower-variance function of the remaining configuration variables.  
**Evidence anchors:**  
- Abstract: “Rather than predicting the observed loss directly, we train the model to predict the residual relative to a Chinchilla-law baseline … biases learning toward configuration-specific effects … improves extrapolation across scales.”  
- Section 3.2: “This design biases learning toward configuration-specific effects beyond the coarse dependence on model size and data size, and empirically improves extrapolation across scales (see ablations in Section B.2).”  
- Corpus: No direct support; residual prediction is a novel design choice in this context.  
**Break condition:** If the Chinchilla baseline is a poor fit (e.g., due to non-power-law behavior or data that deviates strongly from Chinchilla assumptions), the residual becomes large and noisy, hindering learning.

### Mechanism 3
**Claim:** Training on a large, diverse collection of open-source pretraining logs (multiple optimizers, hyperparameter sweeps, model architectures) enables NCPL to learn interactions and generalize to out-of-distribution scales.  
**Mechanism:** The dataset aggregates runs from Marin (various optimizers like AdamW, Lion, Muon, Kron) and StepLaw (learning rate and batch size sweeps). The model observes how different configurations affect loss across a wide range of $N$, $D$, and optimizer/hyperparameter combinations. This diversity allows it to infer interaction effects (e.g., weight decay sensitivity depends on optimizer) and to extrapolate to larger scales via the learned representation.  
**Core assumption:** The training configuration space is sufficiently covered so that the mapping from configuration to performance is learnable and that unseen OOD points lie near the convex hull of training data in the embedded space.  
**Evidence anchors:**  
- Abstract: “trained on over 3,000 diverse pretraining logs from Marin and StepLaw … generalizes to out-of-distribution runs using up to 10× more compute.”  
- Section 4.1: “The Marin dataset … systematically studies the performance and scalability of different optimizers … StepLaw project performs fine-grained sweeps over learning rate and batch size …”  
- Corpus: Weak—neighbors explore scaling laws for specific domains (e.g., video diffusion, carbon footprint) but not configuration diversity.  
**Break condition:** If the training set lacks diversity in key dimensions (e.g., all runs use AdamW, narrow learning rate ranges, only small models), then OOD generalization to new optimizers or large scales will degrade severely.

## Foundational Learning
- **Concept:** Scaling Laws (Chinchilla Law)  
  **Why needed here:** NCPL directly extends the Chinchilla scaling law, which predicts loss from model size $N$ and data size $D$ under optimal hyperparameters. Understanding its form and limitations motivates the need for a configuration-dependent predictor.  
  **Quick check question:** What are the two main variables in the Chinchilla scaling law, and what key assumption about hyperparameters does it make?
- **Concept:** Neural Networks as Universal Function Approximators  
  **Why needed here:** NCPL uses a neural ansatz because the true configuration-to-performance mapping is complex and unknown. This concept explains why a flexible, non-parametric model is chosen over a simple parametric form.  
  **Quick check question:** Why might a power-law functional form be insufficient for modeling the full configuration-to-performance relationship?
- **Concept:** Hyperparameter Tuning in Large-Scale Pretraining  
  **Why needed here:** The core problem NCPL addresses is simplifying hyperparameter selection at scale without expensive sweeps. Knowing the challenges of optimal tuning (e.g., batch size constraints, learning rate scaling) clarifies NCPL’s utility.  
  **Quick check question:** How does the Chinchilla law’s assumption of optimal hyperparameters limit its practical application in resource-constrained settings?

## Architecture Onboarding
- **Component map:**  
  Input Configuration -> Serialization (key-value string) -> Encoder (token embeddings for categorical, MLP for numerical) -> Pretrained LLM Backbone (Qwen3-1.7B) -> Last Token Hidden State -> Linear Head -> Residual Prediction $\hat{y}$ -> Add Chinchilla Baseline $\ell_{\text{chinchilla}}(N,D)$ -> Final Loss $\hat{L}$
- **Critical path:**  
  1. Fit Chinchilla baseline per source on training runs: $\ell = E + A/N^\alpha + B/D^\beta$.  
  2. Compute residual $y = \text{final\_loss} - \ell_{\text{chinchilla}}$ for all runs.  
  3. Serialize each configuration $C$ into a fixed-format string (field order: source, data size, model size, layers, heads, hidden dim, optimizer, LR, LR schedule, weight decay, batch size, max_grad_norm, min_lr, max step).  
  4. Encode string: tokenize categorical fields; for each numerical value, scale it (per Table 2) and pass through a shared two-layer MLP to produce an embedding token.  
  5. Feed the token sequence to the LLM; take the last token’s hidden state.  
  6. Apply linear head to predict $\hat{y}$; train with MSE loss.  
  7. Two-stage training: Stage 1 freeze LLM backbone, train only MLP and head (20 epochs, LR 5e-5, warmup 0.1). Stage 2 unfreeze all and continue (1000 epochs, LR 1e-5, warmup 1000 steps).  
  8. Inference: predict $\hat{y}$, then $\hat{L} = \hat{y} + \ell_{\text{chinchilla}}(N,D)$.  
- **Design tradeoffs:**  
  - *Pretrained vs. from scratch*: Fine-tuning a pretrained LLM yields better performance on diverse configs but may inherit pretraining biases; training from scratch is more flexible but requires more data.  
  - *Residual vs. direct*: Residual prediction removes the dominant scaling trend, improving extrapolation, but depends on a well-fitted baseline.  
  - *Numerical encoding*: MLP adapter for numerical values preserves ordering and magnitude; tokenizing numbers as text loses precision and was ablated as inferior.  
- **Failure signatures:**  
  - High in-distribution MAE/RMSE relative to baselines: underfitting or poor representation.  
  - OOD error spikes (especially on larger $N$/$D$): insufficient training diversity or overfitting to small-scale trends.  
  - Inability to capture known interactions (e.g., optimizer × weight decay): model capacity or data gaps.  
- **First 3 experiments:**  
  1. **Final-loss prediction ablation**: Compare fine-tuned NCPL vs. training from scratch vs. XGBoost on ID/OOD splits. Expected: Fine-tuned LLM outperforms others on Marin (diverse configs); StepLaw (narrow configs) may see smaller gains.  
  2. **Residual prediction ablation**: Train without residual (predict loss directly). Expected: Worse OOD extrapolation, as shown in Table 3.  
  3. **Loss curve prediction**: Modify NCPL to predict loss at intermediate steps (append “frac” token). Expected: Accurate curve shapes across optimizers and hyperparameters (Figure 7, 15).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does NCPL generalize to entirely new model architectures (e.g., MoE, linear attention) or datasets not present in the training logs?
- **Basis in paper:** [explicit] The authors state in the conclusion: "NCPL likely cannot extrapolate to completely unknown scenarios such as runs testing a novel model architecture or a new dataset."
- **Why unresolved:** The current training data lacks such configurations, so NCPL’s performance on them is unknown and likely limited.
- **What evidence would resolve it:** Evaluation on held-out runs from new architectures/datasets would measure generalization error, identify failure modes, and guide data collection.

### Open Question 2
- **Question:** Why does NCPL exhibit a systematic bias toward predicting larger learning rates for out-of-distribution larger models, and how can this bias be corrected?
- **Basis in paper:** [explicit] Section 4.2 reports that NCPL tends to suggest larger learning rates for larger $N$, especially at extreme OOD scales, attributing it to training set bias.
- **Why unresolved:** The hypothesis is unverified; no analysis of the training data distribution or mitigation strategies is provided.
- **What evidence would resolve it:** Controlled experiments varying training data composition (e.g., balancing learning rates across scales) and measuring OOD predictions; causal analysis of bias sources.

### Open Question 3
- **Question:** What is the theoretical justification for the residual prediction relative to the Chinchilla law in improving extrapolation, and how robust is this design to alternative baselines?
- **Basis in paper:** [inferred] The paper uses residual prediction empirically (Section 3.2) without theoretical explanation; ablations in Appendix B.2 show benefits but no deeper reasoning.
- **Why unresolved:** Understanding why this works could inform better ansätze for other scaling contexts and improve reliability.
- **What evidence would resolve it:** Analytical study of how residual modeling affects learned features; experiments with different baseline functions across diverse datasets.

### Open Question 4
- **Question:** Can NCPL’s framework be extended to predict downstream task performance (e.g., accuracy on benchmarks) instead of pretraining loss?
- **Basis in paper:** [inferred] The paper focuses on pretraining loss and mentions richer targets; Related Work discusses downstream scaling laws, but NCPL is not tested on them.
- **Why unresolved:** Downstream performance may have different dependencies on configuration; NCPL’s ability to capture this is unknown.
- **What evidence would resolve it:** Collect logs with downstream metrics; modify NCPL to predict them; compare with specialized baselines and measure extrapolation.

### Open Question 5
- **Question:** How can the community collaboratively build and maintain a shared NCPL that reliably incorporates diverse open-source logs over time without performance degradation?
- **Basis in paper:** [explicit] Conclusion suggests pooling data and continual fine-tuning but notes current data limitations and heterogeneity challenges.
- **Why unresolved:** Practical issues of data standardization, versioning, and catastrophic forgetting in continual learning are unaddressed.
- **What evidence would resolve it:** Longitudinal studies with incremental data additions; benchmarks for robustness to distribution shifts; protocols for model updates and validation.

## Limitations
- Data leakage risk in group-based splits if configurations repeat across train/ID/OOD; not fully clarified.  
- Chinchilla baseline fitting details (optimization, parameter constraints) are underspecified, which may affect residual stability.  
- OOD generalization claims are limited to larger compute but within similar optimizer/architecture families; broad applicability to novel settings remains uncertain.  
- Reliance on a single pretrained model (Qwen3-1.7B) raises questions about the generality of the neural ansatz approach.

## Confidence
- **Main performance claim (outperforms Chinchilla, high Spearman ID):** High (supported by experiments).  
- **Residual prediction mechanism:** Medium (ablation evidence, but dependent on baseline quality).  
- **Superiority of fine-tuned LLM over from-scratch:** Medium (validated but possibly dataset-specific).  
- **OOD generalization up to 10× compute:** Medium-Low (OOD split may not fully stress extrapolation).  
- **Joint hyperparameter tuning and loss curve prediction:** Medium (promising but less evaluated).

## Next Checks
1. Audit train/validation splits for exact configuration overlap; recompute metrics using strictly separated splits.  
2. Stress-test the residual approach by fitting Chinchilla baselines with varied seeds/initializations and measuring NCPL performance variance.  
3. Ablate backbone model and data diversity: test with a non-LLM architecture and with a subset excluding key optimizers to quantify their contributions.
