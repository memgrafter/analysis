# SCoOP: Semantic Consistent Opinion Pooling for Uncertainty Quantification in Multiple Vision-Language Model Systems

## Quick Facts
- arXiv ID: 2603.23853
- Source URL: https://arxiv.org/abs/2603.23853
- Reference count: 40
- Primary result: SCoOP achieves AUROC 0.866 for hallucination detection and AURAC 0.907 for abstention on ScienceQA, with microsecond-level overhead, outperforming baselines by 7–15%.

## Executive Summary
SCoOP is a training-free framework for uncertainty quantification in multi-VLM systems. It aggregates heterogeneous vision-language models by mapping their responses to a unified multiple-choice option space, estimating empirical probability distributions, and combining them via uncertainty-weighted linear opinion pooling. Each model's weight is the inverse of its response entropy, ensuring that more confident models exert greater influence. The aggregated entropy, normalized by the number of options, serves as a calibrated uncertainty estimate that enables effective hallucination detection and safe abstention. Evaluated on ScienceQA, MMMU, and MMBench, SCoOP achieves AUROC 0.866 for hallucination detection and AURAC 0.907 for abstention, surpassing baselines by 7–15% while adding negligible computational overhead. Its consistent performance across model scales, ensemble sizes, and low-accuracy regimes demonstrates robustness without sacrificing accuracy.

## Method Summary
SCoOP operates in a training-free manner. For a given image-question pair, each of the K VLMs generates N sampled responses (e.g., N = 10) using high temperature (T = 1.0) and top-p (P = 0.9) to encourage diversity. The free-text responses are parsed to extract the selected MCQ option label (A–E) via regex or semantic clustering. For each model k, an empirical probability distribution pₖ over the J options is constructed from the N samples. The entropy Hₖ of pₖ is computed. Models are weighted proportionally to the inverse of their entropy: wₖ = (1/(Hₖ + ε)) / Σᵢ (1/(Hᵢ + ε)), with ε = 1e‑6 to avoid division by zero. The aggregated probability distribution is pₐgg = Σₖ wₖ pₖ. The final predicted answer θ* is the option with maximum pₐgg. The system uncertainty is the entropy of pₐgg, normalized by log₂(J) to yield a value in [0,1]. This unified pipeline works across heterogeneous VLMs without any fine-tuning or dataset-specific training.

## Key Results
- SCoOP achieves AUROC 0.866 for hallucination detection on ScienceQA, representing a 10–13% improvement over baseline methods.
- For safe abstention, SCoOP attains AURAC 0.907 on ScienceQA, a 7–9% gain over baselines.
- The additional computational overhead of SCoOP is on the order of microseconds, negligible compared to the second‑scale inference time of individual VLMs.
- SCoOP consistently outperforms baselines across varying model scales (from small to extra‑large), different ensemble sizes (K = 2–5), and even in low‑accuracy regimes, without degrading the aggregate accuracy.

## Why This Works (Mechanism)
SCoOP’s effectiveness stems from two core principles. First, by sampling multiple responses per VLM, it captures intra‑model uncertainty: a confident model will produce nearly identical answers across samples, yielding a low‑entropy distribution; an uncertain model will show high entropy. Second, inverse‑entropy weighting ensures that models with lower uncertainty (higher confidence) exert greater influence on the aggregated prediction. This adaptive weighting mitigates the impact of noisy or hallucination‑prone models. The aggregation of diverse probability distributions smooths out individual errors and produces a calibrated uncertainty measure: the entropy of pₐgg reflects the collective agreement among models. Because the method is training‑free and only requires lightweight post‑processing, it generalizes across model architectures and tasks while incurring minimal overhead.

## Foundational Learning
- **Entropy**: A measure of uncertainty in a probability distribution; needed to quantify model confidence. Quick check: H(p) = –Σ pᵢ log pᵢ; for uniform over 5 options, H ≈ 2.32 bits.
- **Opinion Pooling**: Combining multiple probability distributions into a consensus; linear pooling is a simple weighted average. Quick check: Given two distributions p₁, p₂ and weights w₁, w₂, pooled p = w₁p₁ + w₂p₂.
- **Inverse Entropy Weighting**: Assigns higher weight to models with lower entropy; ensures confident models dominate. Quick check: wₖ ∝ 1/(Hₖ+ε); if Hₖ=0, wₖ→1 after normalization.
- **Semantic Mapping**: Converting free‑text VLM outputs to discrete option labels; essential for unifying heterogeneous responses. Quick check: A regex like `r'\(?([A‑E])\)?'` should extract “A” from “Answer: (A)”.
- **Hallucination Detection**: Treating incorrect predictions as hallucinations; using uncertainty (entropy) as an anomaly score. Quick check: High Hₐgg should correlate with wrong θ* on a validation set.
- **Abstention**: Rejecting predictions when uncertainty exceeds a threshold; trade‑off between coverage and accuracy quantified by AURAC. Quick check: Vary threshold t; compute accuracy on non‑rejected set; integrate area under the curve.

## Architecture Onboarding
**Component Map**: Input (image + MCQ) → For each VLM k=1..K: (Generate N responses → Extract option label → Compute pₖ and Hₖ) → Compute weights wₖ = inv(Hₖ) normalized → Aggregate pₐgg = Σ wₖ pₖ → Final answer θ* = argmax(pₐgg); Normalized uncertainty Hₙₒᵣₘ = entropy(pₐgg) / log₂(J) → Output (θ*, Hₙₒᵣₘ).

**Critical Path**: The sequential generation of N samples per VLM dominates latency; aggregation is negligible. If models are run sequentially, total latency = Σₖ (N · tₖ), where tₖ is per‑sample inference time. Parallelism can reduce this but the paper measures sequential sum.

**Design Tradeoffs**:
- *Sample count N*: Larger N improves entropy estimation but increases latency linearly.
- *Option extraction*: Simple regex is fast but brittle; semantic clustering (e.g., using embeddings) is robust but adds overhead.
- *Ensemble size K*: More models improve robustness and diversity but cost scales linearly; diminishing returns beyond K=5 (per paper).
- *Weighting function*: Inverse entropy is simple and calibration‑free; alternatives (e.g., learned weights) might perform better but require training.
- *Tie‑breaking*: When aggregated probabilities tie, the fallback rule (e.g., pick option with lowest entropy model) can affect accuracy.

**Failure Signatures**:
- Low accuracy despite low Hₙₒᵣₘ (overconfident wrong consensus).
- High variance in AUROC across different N or random seeds.
- Extraction failures leading to missing options (e.g., no matches from regex) causing NaNs.
- Weights near zero for some models (if Hₖ large) indicating potential over‑penalization.
- Discrepancy between reported microsecond overhead and measured latency due to parallel vs. sequential execution.

**Exactly 3 First Experiments**:
1. **Smoke test**: Run SCoOP with two small VLMs (e.g., LLaVA‑7B, Qwen2.5‑VL‑7B) on 10 ScienceQA samples using N=5. Verify that outputs are reasonable option labels and Hₙₒᵣₘ lies in [0,1].
2. **Extraction validation**: Manually inspect 50 random responses from each model to assess regex extraction accuracy. If failure rate >5%, test a more robust pattern or a lightweight LLM‑based extractor; measure impact on AUROC on a held‑out set.
3. **Sampling sensitivity**: Fix a subset of 100 ScienceQA items; vary N ∈ {1,5,10,20}. Plot AUROC and total latency. Identify the N where AUROC plateaus and overhead remains acceptable (e.g., <10% increase from N=10 to N=20).

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does the parameter scale of individual VLMs (e.g., small, medium, large, extra‑large) quantitatively impact the quality and stability of uncertainty estimates in SCoOP?
- **Basis in paper:** [explicit] RQ1 in Section 4.3 and Figure 4.
- **Why unresolved:** The paper demonstrates SCoOP’s consistent outperformance across scales, but the underlying mechanism—why gains vary from 8.9% to 15.5% over baselines—is not analyzed. It’s unclear if smaller models’ higher entropy necessitates stronger weighting, or if larger models’ consistency reduces the marginal benefit of uncertainty‑aware pooling. The interplay between model accuracy and entropy calibration across scales remains unexplored.
- **What evidence would resolve it:** Controlled experiments measuring per‑model accuracy, entropy, and correlation between them across scales. Ablations with synthetic models where uncertainty is manipulated independently of accuracy (e.g., adding calibrated noise) to isolate scale effects on weighting efficacy.

### Open Question 2
- **Question:** How does the number of VLMs (system size K) affect SCoOP’s computational efficiency versus uncertainty quality trade‑off beyond K=5?
- **Basis in paper:** [explicit] RQ2 in Section 4.3 and Figure 5; also Latency analysis in Table 1.
- **Why unresolved:** SCoOP shows stability for K=2–5, but the paper only evaluates up to 5 models. It’s unknown if stability holds for larger ensembles (e.g., K=10+) or if diminishing returns set in, especially given that inference latency scales linearly with K and N. The relationship between model diversity, K, and uncertainty quality is not characterized.
- **What evidence would resolve it:** Extend experiments to larger K (10, 20) with diverse model families. Plot AUROC/AURAC and latency vs. K, and correlate with measures of model disagreement (e.g., average pairwise voting entropy). Stress tests with highly redundant vs. diverse ensembles to isolate the effect of ensemble composition.

### Open Question 3
- **Question:** Does SCoOP’s inverse‑entropy weighting scheme inadvertently penalize accurate VLMs that happen to produce high‑entropy responses on certain inputs, and how does this affect overall accuracy?
- **Basis in paper:** [inferred] From RQ3 results (Table 2) and the discussion that Naive Selection sometimes achieves slightly higher accuracy on extra‑large models, suggesting potential trade‑offs.
- **Why unresolved:** The paper shows SCoOP is accuracy‑competitive but does not analyze cases where weighted aggregation leads to incorrect predictions despite low system entropy. The assumption that entropy reliably indicates hallucination risk (citing [18, 3]) might break down for certain model architectures or question types, potentially down‑weighting accurate but uncertain models.
- **What evidence would resolve it:** Error analysis of samples where SCoOP’s final prediction is incorrect but has low Hₐgg, comparing with individual model accuracies and entropies. Ablation studies using alternative weighting functions (e.g., based on individual model calibration scores) to see if accuracy can be improved without sacrificing uncertainty discrimination.

### Open Question 4
- **Question:** How robust is SCoOP to the semantic mapping step (matching raw responses to MCQ options) when responses are ambiguous, malformed, or contain extraneous text, and does this mapping introduce systematic bias?
- **Basis in paper:** [inferred] From Section 3.1, where semantic clustering and regex filtering are used to map responses to options, but no failure analysis is provided.
- **Why unresolved:** The mapping process is critical for unifying heterogeneous VLM outputs, but the paper does not quantify mapping error rates or their impact on uncertainty estimates. Ambiguous responses (e.g., “maybe A or B”) could be mis‑mapped, artificially inflating or deflating entropy and weights.
- **What evidence would resolve it:** Measure mapping accuracy vs. ground‑truth options on a held‑out set, possibly via human annotation. Ablate the mapping method (e.g., using different regex patterns or embedding‑based clustering) and measure variance in AUROC/AURAC. Analyze cases where mapping fails and correlates with high system entropy.

### Open Question 5
- **Question:** Can SCoOP’s framework be effectively extended to open‑ended visual question answering (free‑form VQA), and what are the key challenges in defining and aggregating “opinions” without predefined options?
- **Basis in paper:** [inferred] From Conclusion, “Future directions: expand SCoOP beyond multiple‑choice to free‑form VQA”.
- **Why unresolved:** SCoOP assumes a fixed option set Θ for probability vectors. Free‑form VQA requires semantic equivalence clustering of diverse answer strings, which is less deterministic and could introduce noise in probability estimation and entropy calculation. The paper does not address how to define the “hypothesis space” or handle infinite answer spaces.
- **What evidence would resolve it:** Implement SCoOP on an open‑ended VQA benchmark (e.g., VQAv2) using answer clustering via embeddings (e.g., CLIP) or language models. Compare hallucination detection performance against multiple‑choice baselines and analyze clustering quality’s effect on uncertainty metrics. Propose and evaluate methods for dynamic hypothesis space construction.

## Limitations
- Regex‑based option extraction may fail on malformed VLM outputs (e.g., “The answer is A because…”), leading to inaccurate probability distributions and entropy estimates.
- Exact dataset splits and model checkpoint versions are not disclosed, making faithful replication difficult and potentially introducing variance in reported numbers.
- Latency measurements are sensitive to implementation details (e.g., parallel vs. sequential inference, batch size); the claimed microsecond overhead may not hold in all practical deployment scenarios.

## Confidence
- Performance Gains (AUROC/AURAC improvements): **Medium** – core method is replicable, but extraction and split choices could shift results.
- Efficiency (microsecond overhead): **Low** – overhead is extremely small; implementation variance could erase the difference.
- Generalization (across scales, low‑accuracy regimes): **Medium** – training‑free design is robust, but multi‑model setup depends on consistent model versions.
