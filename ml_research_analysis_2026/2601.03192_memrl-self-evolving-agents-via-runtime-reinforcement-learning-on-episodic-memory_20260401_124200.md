# MemRL: Self-Evolving Agents via Runtime Reinforcement Learning on Episodic Memory

## Quick Facts
- arXiv ID: 2601.03192
- Source URL: https://arxiv.org/abs/2601.03192
- Reference count: 40
- Primary result: Enables LLM agents to self-evolve at runtime via reinforcement learning on episodic memory, yielding +3.8% CSR and +2.8% SR improvements over SOTA baselines.

## Executive Summary
MemRL introduces a framework for continuous runtime learning in LLM agents without model weight updates. It decouples stable LLM reasoning from a plastic episodic memory bank, using a Two-Phase Retrieval that first filters by semantic similarity then re-ranks by learned Q-values updated via environmental feedback. This addresses the stability-plasticity dilemma and allows agents to distinguish high-utility strategies from noise. Evaluated on four benchmarks, MemRL significantly outperforms baselines like MemP and RAG, with strong correlation between Q-values and task success. The work demonstrates a viable path toward self-improving agents that adapt safely during deployment.

## Method Summary
MemRL operates with a frozen LLM and an external memory store of tuples (intent, experience, Q). For each query, the intent is embedded. Phase A retrieves candidates by cosine similarity above a threshold, taking top k₁. Phase B re-ranks these by combining normalized similarity and normalized Q-values with weight λ (optimal 0.5), selecting top k₂. The LLM generates an action conditioned on the selected memories. After environment interaction, the reward updates the Q-values of the retrieved memories via a Monte Carlo rule: Q ← Q + α(r - Q). Successful trajectories are summarized into high-level scripts (experiences) and stored with initial Q=0. This loop enables continuous improvement without altering LLM weights, reconciling stability (frozen model) and plasticity (memory updates).

## Key Results
- Outperforms SOTA baselines (MemP, RAG) on HLE, BigCodeBench, ALFWorld, and Lifelong Agent Bench, achieving average +3.8% higher Cumulative Success Rate (runtime) and +2.8% higher Success Rate (transfer).
- Learned Q-values show strong correlation (Pearson r=0.861) with actual task success, validating the utility estimates.
- Ablations confirm λ=0.5 optimally balances semantic relevance and utility, and MemRL reduces catastrophic forgetting (forgetting rate 0.041 vs MemP's 0.051).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Decoupling stable LLM reasoning from plastic episodic memory reconciles the stability–plasticity dilemma, enabling continuous runtime learning without catastrophic forgetting.  
- **Mechanism:** The LLM weights remain frozen, providing stable inference capabilities. All experiential learning occurs externally in the memory bank where *Q*-values (estimated utilities) are updated. This prevents interference with prior knowledge while still allowing adaptation.  
- **Core assumption:** The inference distribution of the frozen LLM is stationary relative to the task distribution, making the learned utilities meaningful and stable.  
- **Evidence anchors:**  
  - [abstract] “decouples the stable reasoning of a frozen LLM from the plastic, evolving episodic memory.”  
  - [1] “MEMRL explicitly separates the stable cognitive reasoning from dynamic episodic memory.”  
  - [corpus] Neighbors focus on episodic memory and agent learning but do not directly address decoupling; inferred from paper’s own argument.  
- **Break condition:** If the frozen LLM’s representation is extremely mismatched to the target domain (e.g., lacking domain vocabulary), the retrieval may not be sufficiently grounded, limiting the effectiveness of the learned utilities.

### Mechanism 2
- **Claim:** A Two-Phase Retrieval mechanism first recalls candidates via semantic similarity and then re‑ranks them by learned *Q*-values. This filters semantically plausible but low‑utility memories, leading to significantly higher success.  
- **Mechanism:** Phase A computes cosine similarity between the query embedding and memory intents, keeping the top *k*₁ candidates above threshold δ. Phase B combines normalized similarity with normalized *Q*-values using a weighting factor λ. The final score is `(1-λ)*norm_sim + λ*norm_Q`.  
- **Core assumption:** Semantic similarity provides a necessary but not sufficient condition for utility; the learned *Q*-values capture actual outcome success under the frozen LLM policy.  
- **Evidence anchors:**  
  - [abstract] “Two-Phase Retrieval: candidates are first recalled by semantic similarity, then re‑ranked by learned Q-values.”  
  - [4.2] Equations (6) and (7), and the discussion of λ balancing relevance vs. helpfulness.  
  - [5.3.2] Ablation on λ shows peak performance at λ=0.5; extremes degrade results.  
- **Break condition:** Extreme values of λ (pure semantic or pure *Q* weighting) cause either noise dominance or loss of grounding, leading to poor generalization and increased forgetting.

### Mechanism 3
- **Claim:** Non‑parametric reinforcement learning via Monte‑Carlo style updates refines *Q*-values in the memory using environmental feedback. This enables the agent to distinguish high-utility strategies from similar noise.  
- **Mechanism:** After generating an action with retrieved context, the environment returns a reward. For each retrieved memory, the *Q*-value is updated as `Q_new ← Q_old + α·(r - Q_old)`. Over repeated interactions, *Q* converges to the expected return under the frozen LLM policy.  
- **Core assumption:** Rewards are consistent and the retrieval policy explores sufficiently to sample memories across diverse states.  
- **Evidence anchors:**  
  - [abstract] “learned Q-values (utility) which are continuously updated via environmental feedback (Monte Carlo style).”  
  - [3.2] Formal mapping of the M‑MDP to a fixed action space of memory selection and Equation (4) for updates.  
  - [5.4.1] Pearson *r*=0.861 between learned *Q* and actual task success, confirming predictive power.  
- **Break condition:** Noisy or sparse rewards (e.g., binary success without partial credit) can yield high‑variance updates; the paper mitigates this with normalization and gating, but extreme sparsity may still impede convergence.

## Foundational Learning
### Concept: Memory‑Augmented Markov Decision Process (M‑MDP)
- **Why needed here:** MemRL formalizes the interaction as an M‑MDP where the agent’s policy jointly selects a memory item and generates an action. This clarifies how retrieval becomes a decision problem.  
- **Quick check question:** How does the M‑MDP formulation justify treating memory selection as an action in the RL framework?  

### Concept: Stability–Plasticity Dilemma
- **Why needed here:** The core challenge is to learn continuously without forgetting previously acquired skills. Decoupling like MemRL aims to maintain stable reasoning while the memory remains plastic.  
- **Quick check question:** In the context of MemRL, which component provides stability and which provides plasticity?  

### Concept: Value‑Based Retrieval (Using *Q*-values)
- **Why needed here:** Instead of passive semantic matching, MemRL uses a critic (*Q*) to estimate the utility of a memory for a given query, turning retrieval into an exploitation step.  
- **Quick check question:** What is the difference between using cosine similarity and *Q*-value for ranking memories?  

## Architecture Onboarding
### Component map
Memory Store -> Two-Phase Retriever (Phase A: semantic recall; Phase B: value-aware selection) -> LLM Generator (frozen) -> Utility Updater (Monte Carlo update) -> Summarizer (generates high-level scripts) -> Memory Store.

### Critical path
1. Receive query → encode intent embedding.  
2. Phase A: retrieve top *k*₁ memories with similarity > δ.  
3. Phase B: score candidates with `score = (1-λ)*norm_sim + λ*norm_Q`, select top *k*₂.  
4. Inject selected memories as context into the frozen LLM prompt.  
5. LLM generates output/action, environment returns reward.  
6. For each selected memory, update its *Q* using the reward.  
7. Summarize new trajectory and store as a new memory (initial *Q*=0 or bootstrap).

### Design tradeoffs
- **λ balance:** λ=0 gives pure similarity (susceptible to noise); λ=1 risks semantic drift. Optimal λ≈0.5 found empirically.  
- **Retrieval sizes (*k*₁, *k*₂):** Larger *k*₁ increases recall but also noise; optimal moderate values (e.g., 5/3) maximize signal‑to‑noise.  
- **Similarity threshold δ:** Too low → noise; too high → insufficient candidates. Set at the top 20% quantile of intra‑benchmark cosine similarity.

### Failure signatures
- **High forgetting rate:** If the forgetting rate exceeds ~0.05, stability is poor; check normalization and similarity gating.  
- **Divergent *Q* values:** If *Q* averages shift rapidly or variance grows, reward noise is too high; consider multi-step updates or a lower learning rate α.  
- **No improvement over Pass@k baseline:** Indicates the memory is not capturing reusable strategies; likely due to too small/irrelevant memory or poor summarization.

### First 3 experiments
1. **Runtime Learning comparison** against RAG, MemP, etc. measuring Cumulative Success Rate across epochs to show learning trajectory.  
2. **Ablation on λ** to identify the optimal balance between semantic relevance and utility‑based selection.  
3. **Forgetting rate analysis** comparing MemRL vs. MemP to demonstrate stability and avoidance of catastrophic forgetting.

## Open Questions the Paper Calls Out
1. **Robust update protocols for long-horizon tasks**: The current step-wise Monte Carlo update is noisy with delayed/sparse rewards (Section G.1). Evidence needed: compare n-step returns or TD(λ) on long-horizon benchmarks, measuring stability and CSR.
2. **Credit assignment when multiple memories are used**: Updating all retrieved memories equally misattributes credit (Section G.2). Evidence needed: implement Shapley or value decomposition, measure improvement in Q-value correlation and performance.
3. **Cross-task generalization with low similarity**: Performance degrades when task similarity is low (Section G.3, Appendix B.3). Evidence needed: analyze across similarity levels, test hierarchical clustering or adaptive thresholds.
4. **Robustness against reward hacking and memory poisoning**: Vulnerable to false rewards and malicious memories (Section G.4). Evidence needed: simulate attacks, evaluate detection methods (outlier analysis, consistency checks).
5. **Multi-agent memory sharing in swarms**: Unclear how to share knowledge without negative interference (Section G.5). Evidence needed: experiments with many agents sharing memory, test sharing policies (utility-based, task-aware).

## Limitations
- Incomplete specification of reward mapping and summarization process per benchmark hampers exact replication.
- Lack of memory management may cause bloat and performance degradation over extended runs.
- Baseline implementations (MemP, Mem0) may not match original configurations, raising uncertainty about SOTA claims.

## Confidence
- Decoupling reconciles stability‑plasticity: Medium
- Two‑Phase Retrieval gains (λ≈0.5): Medium‑High
- Monte‑Carlo Q-values reflect true utility: High
- Overall SOTA performance: Medium
