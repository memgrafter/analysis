# Post Training Quantization for Efficient Dataset Condensation

## Quick Facts
- **ArXiv ID**: 2603.13346
- **Source URL**: https://arxiv.org/abs/2603.13346
- **Reference count**: 10
- **Primary result**: A post-training quantization framework using patch-based quantization, clustering-based group parameter sharing, and a refinement module nearly doubles test accuracy at extreme 2-bit compression (e.g., DM on CIFAR-10 IPC=1: 26.0% → 54.1%).

## Executive Summary
Dataset condensation compresses a large training set into a small synthetic set, but storing these synthetic images efficiently remains a challenge. This paper introduces a post-training quantization technique tailored for condensed datasets, which partitions images into patches, clusters similar patches to share quantization parameters, and refines the quantized images via feature matching. Applied to various distillation methods, the approach dramatically reduces storage while maintaining accuracy; for instance, at 2-bit width it improves test accuracy from 26.0% to 54.1% for DM on CIFAR-10 with IPC=1. The method consistently outperforms prior parameterized condensation baselines across multiple datasets without requiring any additional training or decoder networks.

The framework is training-free and works as a simple post-processing step, making it practical for deploying condensed datasets under stringent storage constraints. Its design addresses the severe performance degradation typically observed at very low bit-widths, enabling extreme compression that was previously impractical.

## Method Summary
The proposed post-training quantization (PTQ) pipeline starts from a full-precision condensed dataset. Each synthetic image is divided into non-overlapping patches (5×5 pixels). All patches across the dataset are clustered (e.g., via k-means) into G groups; each group shares a common quantization scale and zero-point, reducing the metadata overhead. Patches are then quantized to a low bit-width (e.g., 2-bit) using these shared parameters. The resulting quantized patches are re-assembled into images, forming an initial quantized condensed dataset. To recover accuracy lost in quantization, a refinement module iteratively updates the pixel values of the quantized images. It employs a fixed feature extractor f(·) (pre-trained on the target task) to compute features from both the quantized and original full-precision images; the L2 distance between these features is minimized via gradient steps on the pixel values. This refinement does not require training a decoder and is applied post-quantization.

## Key Results
- At 2-bit quantization, DM on CIFAR-10 (IPC=1) accuracy jumps from 26.0% to 54.1%; DATM on CIFAR-10 (IPC=10) from 66.8% to 79.0%.
- The framework consistently outperforms prior parameterized condensation methods on CIFAR-10/100, ImageNet subsets, and other domains under equal storage budgets.
- The entire process is training-free and decoder-free, achieving state-of-the-art efficiency improvements.

## Why This Works (Mechanism)
- **Patch-based quantization** confines quantization noise locally, preserving global image structure better than quantizing the whole image at once.
- **Clustering‑based group parameter sharing** reduces the number of scale/zero‑point values needed per patch type, striking a balance between storage overhead and adaptability to different patch statistics.
- **Refinement through feature matching** aligns the quantized images with the full-precision distribution in a semantic feature space, effectively correcting quantization artifacts without additional model training.

## Architecture Onboarding
### Component Map
Full-precision condensed dataset -> Patch extraction -> Clustering -> Quantization -> Refinement -> Quantized condensed dataset

### Critical Path
1. Load full-precision synthetic images.
2. Split each image into non-overlapping patches (e.g., 5×5).
3. Cluster all patches across the dataset to obtain G groups.
4. For each group, compute global quantization scale and zero‑point for the target bit‑width; quantize all patches in that group.
5. Reassemble quantized patches into initial quantized images.
6. Refinement: Use a pre‑trained feature extractor f(·) to extract features from both quantized and original images; minimize L2 feature distance by updating pixel values of the quantized images.
7. Output the final quantized condensed dataset.

### Design Tradeoffs
- **Patch size**: smaller patches better preserve details but increase metadata overhead for group indices; larger patches reduce overhead but risk blurring fine details.
- **Number of clusters (G)**: higher G adapts to patch diversity, improving quantization fidelity, but raises storage for per‑group parameters; lower G saves space but may increase error.
- **Bit‑width**: lower bits give more aggressive compression; refinement can mitigate accuracy loss but cannot fully recover beyond a point.
- **Feature extractor f(·)**: a deeper network captures richer semantics for refinement but may be slower; a shallower one is faster but may not provide a strong learning signal.

### Failure Signatures
- **Accuracy collapse**: >10% relative drop indicates over‑quantization or poor clustering.
- **Metadata bloat**: group parameters consume a large fraction of storage, suggesting too many groups (e.g., patch size too small or G too large).
- **Worsening after refinement**: if refinement step decreases accuracy, the chosen f(·) may be mismatched or the refinement learning rate might be inappropriate.

## Open Questions the Paper Calls Out
### Open Question 1
- Question: How can the proposed quantization framework be extended to incorporate soft labels from distillation methods, and what performance impact does label-aware quantization have on dataset condensation?
- Basis in paper: [explicit] The authors state: "It does not yet support methods that utilize soft labels. Future work may explore label-aware quantization."
- Why unresolved: The current implementation only considers hard labels; soft labels contain richer distributional information that could be sensitive to quantization noise.
- What evidence would resolve it: Develop a variant that quantizes synthetic images while preserving the soft label distribution (e.g., by matching feature distributions conditioned on soft labels), then evaluate on distillation methods that produce soft labels (e.g., MTT) and report accuracy compared to the original.

### Open Question 2
- Question: What quantization strategies are effective for transformer-based dataset condensation where data is represented as token embeddings rather than spatial patches?
- Basis in paper: [explicit] The authors note: "Designing quantization strategies that operate on token embeddings presents a promising direction for transformer-based models."
- Why unresolved: The method is designed for CNN-style spatial patches; transformers process sequences of tokens, requiring different handling of positional information and inter-token relationships.
- What evidence would resolve it: Adapt the patch-based quantization to token sequences (e.g., group tokens by similarity, share quantization parameters across token clusters), apply to synthetic datasets generated for ViT training, and measure accuracy under the same storage constraints.

### Open Question 3
- Question: How does the choice of patch size affect the trade-off between storage cost and downstream model accuracy in patch-based quantization?
- Basis in paper: [inferred] The paper uses a fixed non-overlapping patch size of 5×5 and does not explore other sizes, leaving the impact on performance and storage overhead unexamined.
- Why unresolved: Smaller patches increase the number of quantization parameter groups and may preserve details better but incur higher storage for group indices; larger patches reduce overhead but risk losing fine-grained information.
- What evidence would resolve it: Conduct a systematic evaluation across a range of patch sizes (e.g., 2×2, 3×3, 7×7, 10×10) on multiple datasets, measuring test accuracy and storage size under fixed bit-width, then identify the Pareto frontier.

### Open Question 4
- Question: How sensitive is the quantization-aware refinement module to the choice of the feature extraction network f(·) used in the loss function?
- Basis in paper: [inferred] The paper mentions using a neural network f(·) to extract features but does not specify its architecture or analyze its impact, assuming it is appropriately chosen.
- Why unresolved: Different feature extractors capture different levels of semantics; a suboptimal choice might fail to align the critical features needed for the downstream task, affecting final accuracy.
- What evidence would resolve it: Perform experiments with various backbones (e.g., ResNet-18, VGG-11, ViT) as f during refinement, while keeping the evaluation network fixed; compare test accuracy to assess robustness to the choice of f.
