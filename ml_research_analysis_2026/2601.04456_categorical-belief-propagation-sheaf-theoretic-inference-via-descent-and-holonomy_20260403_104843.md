# Categorical Belief Propagation: Sheaf-Theoretic Inference via Descent and Holonomy

## Quick Facts
- **ArXiv ID:** 2601.04456
- **Source URL:** https://arxiv.org/abs/2601.04456
- **Reference count:** 35
- **Primary result:** Exact inference on factor graphs is characterized as effective sheaf-theoretic descent; the Holonomy-Aware Tree Compilation (HATCC) algorithm reduces loopy BP to exact tree BP by compiling holonomy obstructions into mode variables.

## Executive Summary
Belief propagation (BP) often fails on graphs with cycles due to inconsistent local beliefs. This paper provides a categorical foundation using sheaf theory, showing that exact inference corresponds to local beliefs forming a descent datum—they must be compatible on overlaps of a factor-centric cover. The core contribution is Holonomy-Aware Tree Compilation (HATCC), which computes holonomy matrices from fundamental cycles in the factor nerve to detect when tree-structured beliefs violate full descent. Non-trivial holonomy is compiled into mode variables via quotient spaces and selector factors, transforming the augmented graph into a tree where standard BP is exact. Theoretically, this unifies tree exactness and junction tree algorithms, interpreting loopy BP failures as descent obstructions. Experiments on grid Markov random fields and random graphs show HATCC achieves exact inference with significant speedup over junction trees and detects unsatisfiable models.

## Method Summary
HATCC proceeds in a pipeline: first, build the factor nerve (factors as nodes, non-empty intersections as edges). Next, select a maximum-weight spanning tree (backbone) and identify chords (non-tree edges). For each chord, compute its fundamental cycle in the nerve; compose transport kernels (Boolean supports of factor potentials) along the cycle to obtain a holonomy matrix on the chord's interface. The holonomy relation defines an equivalence on interface states; compute mode variables as the strongly connected component quotient. For each chord, add a mode variable and a selector factor that enforces holonomy compatibility. The resulting augmented factor graph has a tree nerve, so sum‑product BP yields exact marginals. Finally, marginalize out the mode variables to obtain beliefs on original variables. The algorithm detects unsatisfiability if any selector factor has empty support.

## Key Results
- **Descent characterization:** Exact inference is equivalent to existence of a descent datum (pairwise compatible local beliefs) on a cover satisfying variable and factor coverage.
- **Holonomy obstruction:** Non‑trivial holonomy matrices computed from fundamental cycles precisely detect when tree-compatible beliefs fail to satisfy descent.
- **Empirical speedup:** HATCC outperforms junction tree algorithms on sparse graphs with small cycles and detects unsatisfiable models; complexity is O(n² d_max + c·k_max·δ_max³ + n·δ_max²).

## Why This Works (Mechanism)

### Mechanism 1: Exact inference as effective descent
**Claim:** Exact inference on factor graphs is equivalent to existence of a descent datum on a cover (local beliefs compatible on overlaps).
**Mechanism:** Construct a presheaf of local function spaces over the intersection category of a cover (factors and their intersections). Descent conditions (pairwise compatibility on overlaps) ensure local beliefs glue to a global function representing the joint distribution. For finite state spaces, the sheaf of functions is effective (Theorem 5.15). A message-passing scheme is exact iff it produces such a descent datum (Theorem 5.16).
**Core assumption:** Finite state spaces; cover covers all variables and factors exactly.
**Evidence anchors:** Theorem 5.16; Section 5 (Descent Reformulation).
**Break condition:** Cover fails to cover all variables/factors, or local beliefs are incompatible on overlaps.

### Mechanism 2: Holonomy detects descent obstructions
**Claim:** Nontrivial holonomy matrices from fundamental cycles of the factor nerve detect when cluster beliefs compatible on tree edges violate descent.
**Mechanism:** Pick a backbone spanning tree T in the factor nerve. For each chord e (edge not in T), take its fundamental cycle C_e. Compose transport kernels (Boolean supports of potentials) along C_e to get a holonomy matrix H_e: Ω(J_e)×Ω(J_e)→{0,1}. If H_e ≠ identity, some state pairs cannot consistently transport around the cycle, meaning tree compatibility does not guarantee full descent (Theorem 6.14).
**Core assumption:** Factor nerve represents intersection structure; transport kernels capture feasibility only.
**Evidence anchors:** Definition 6.13, Theorem 6.14; abstract on holonomy detection.
**Break condition:** High cyclomatic complexity (many chords), large interface sizes δ_max, or long fundamental cycles k_max increase holonomy computation cost (O(k_max·δ_max³) per chord).

### Mechanism 3: Holonomy compilation to tree BP
**Claim:** Compiling holonomy into mode variables and adding selector factors yields a tree-structured augmented graph where BP is exact; marginalizing modes recovers original marginals.
**Mechanism:** For each chord e, compute mode space Q_e as the strongly connected component quotient of the holonomy relation. Add mode variable m_e taking values in Q_e and a selector factor σ_e(x, m_e) that is 1 iff x is in mode m_e and a holonomy fixed point. The augmented factor nerve is a tree (Proposition 6.23). Run sum‑product BP on the tree; marginalize mode variables to obtain original beliefs (Theorem 6.27).
**Core assumption:** SCC quotient captures holonomy orbits; selector factors enforce feasibility; tree BP is exact.
**Evidence anchors:** Abstract on compilation to tree BP; Section 6.5 (selector factors), Proposition 6.23, Section 6.7.
**Break condition:** Many chords c increase augmented tree size; large factor clusters from original degrees make BP expensive; unsatisfiable models yield empty selector support (correctly detected).

## Foundational Learning
- **Factor graphs and belief propagation**  
  Why needed: The paper assumes standard factor graph representation and sum‑product updates. Understanding variable‑to‑factor (product of incoming messages) and factor‑to‑variable (sum over other variables after multiplying by factor) updates is essential.  
  Quick check: *What is the key difference between variable‑to‑factor and factor‑to‑variable updates in belief propagation?*  
  Answer: Variable‑to‑factor multiplies incoming messages from other factors; factor‑to‑variable multiplies incoming messages and the factor potential, then sums over all other variables.

- **Sheaf‑theoretic descent**  
  Why needed: The core theoretical result (Theorem 5.16) frames exact inference as effective descent of local beliefs along a cover. Descent data (compatibility on overlaps) and gluing are central.  
  Quick check: *Given a cover {U_i} and local sections s_i ∈ F(U_i) that agree on pairwise intersections, what additional sheaf condition ensures they glue to a global section?*  
  Answer: Compatibility on all higher intersections; for a presheaf on a poset, pairwise compatibility suffices because functoriality implies higher compatibility.

- **Gauge equivariance in message passing**  
  Why needed: Section 4 shows BP is semi‑equivariant under gauge rescalings of messages; fixed points are gauge‑invariant. This explains why multiple fixed points can represent the same normalized beliefs.  
  Quick check: *If you multiply all messages entering a variable node by a positive constant, what happens to outgoing messages after one BP update?*  
  Answer: Variable‑to‑factor messages are multiplied by that constant; factor‑to‑variable messages are unchanged because the constant sums out; overall, the gauge propagates according to Θ_G(k).

## Architecture Onboarding
- **Component map:**  
  FactorNerve -> BackboneTree -> HolonomyComputation -> ModeQuotient -> AugmentedGraph -> TreeBP -> Marginalization

- **Critical path:**  
  1. FactorNerve builds the graph of factors and intersections.  
  2. BackboneTree selects a spanning tree, finds chords and fundamental cycles.  
  3. HolonomyComputation composes transport kernels along each fundamental cycle to get holonomy matrices.  
  4. ModeQuotient computes SCCs of holonomy relations to define mode spaces.  
  5. AugmentedGraph adds mode variables and selector factors, ensuring tree structure.  
  6. TreeBP runs two‑pass sum‑product on the tree.  
  7. Marginalization sums out mode variables to obtain final beliefs.

- **Design tradeoffs:**  
  - BackboneTree choice (e.g., maximum spanning tree by log interface size) does not affect correctness but can influence holonomy computation cost via cycle lengths and interface sizes.  
  - ModeQuotient trades state‑space size for tree width: larger holonomy orbits reduce mode values but even trivial holonomy (each state its own mode) preserves correctness.  
  - AugmentedGraph adds one mode variable per chord; many chords increase memory and BP time.  
  - HolonomyComputation uses Boolean matrices for tractability; weighted versions could preserve probabilistic information but break SCC mode quotient.

- **Failure signatures:**  
  - High cyclomatic complexity (many chords) → holonomy computation and augmented tree size blow up.  
  - Large interfaces (δ_max) → holonomy matrix storage/multiplication O(δ_max²) becomes costly.  
  - Long fundamental cycles (k_max) → composing many transport matrices increases time (O(k_max·δ_max³)).  
  - Empty selector factor support → unsatisfiable model (correctly detected).

- **First 3 experiments:**  
  1. **Tree exactness baseline:** Generate random tree‑structured factor graphs; verify HATCC marginals match brute‑force enumeration.  
  2. **Holonomy obstruction detection:** Build the 4‑cycle example with alternating copy/NOT factors; HATCC should compute nontrivial holonomy and return UNSAT. Control: all identity factors yields exact marginals.  
  3. **Synchronization robustness:** For Z_k synchronization on random graphs with corrupted off‑tree edges, measure TV distance between BP and exact marginals vs. corruption fraction ε; HATCC should maintain exactness while vanilla BP diverges.

## Limitations
- Finite variable domains only; continuous spaces not addressed.
- Cubic scaling in interface size (δ_max³) and linear in number of chords c may be prohibitive for dense graphs.
- Experiments limited to grid MRFs and random graphs; no real‑world UAI benchmark validation.

## Confidence
- **Descent equivalence (Theorem 5.16):** High – rigorous proof for finite factors.
- **Holonomy obstruction detection (Theorem 6.14):** High – iff characterization established.
- **Exact inference via augmented tree BP (Theorem 6.27):** High – construction provably correct.
- **Empirical speedup over junction trees:** Medium – limited datasets; needs broader validation.
