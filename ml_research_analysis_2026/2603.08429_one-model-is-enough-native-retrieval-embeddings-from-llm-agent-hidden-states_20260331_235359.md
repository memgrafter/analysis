# One Model Is Enough: Native Retrieval Embeddings from LLM Agent Hidden States
## Quick Facts
- arXiv ID: 2603.08429
- Source URL: https://arxiv.org/abs/2603.08429
- Reference count: 8
- Primary result: Native retrieval embeddings from LLM hidden states achieve 97% of baseline Recall@10 with a 21.8× reduction in inference latency.

## Executive Summary
This paper proposes a native retrieval system that eliminates the standard two-model generate‑then‑encode pipeline for LLM agents. Instead of using a separate embedding model, it attaches a lightweight projection head to the LLM’s generation hidden states and trains it to produce embeddings directly in the retrieval space. On the QReCC benchmark, the method attains near‑parity with the baseline (97% of Recall@10 and MRR@10) while cutting per‑query latency by 21.8×. Ablations confirm that all three loss components—alignment, contrastive, and rank distillation—are essential for performance. The quality gap is statistically significant (p=0.0005) and the two methods agree on 84.2% of retrieval triggers.

## Method Summary
The method uses the LLM (Qwen3-8B) to generate search queries. For each retrieval trigger, hidden states of non‑special tokens from the last layer are cached. A 4‑component projection head—linear projection, two transformer encoder layers with learnable positional embeddings, mean pooling, and a final linear projection with L2 normalization—maps these states to an embedding vector. Training combines three losses: alignment loss (MSE between projection output and teacher embedding), contrastive loss (InfoNCE with teacher‑retrieved positives/negatives), and rank distillation loss (KL divergence between teacher and student similarity scores over the top‑128 documents). The teacher is Qwen3‑Embedding‑8B. Training uses AdamW, a cosine LR schedule (2e‑4 → 1e‑5), batch size 16, gradient clipping 1.0, and 80 epochs. After training, inference simply feeds the hidden states through the projection head, bypassing the separate embedding model.

## Key Results
- Near‑parity with baseline: retains 97% of Recall@10 and MRR@10 (a drop of 3.0–3.6%).
- 21.8× reduction in per‑query inference latency.
- All three loss components are necessary; removing any leads to significant degradation.
- The two methods agree on 84.2% of retrieval triggers; the difference is statistically significant (p=0.0005).

## Why This Works (Mechanism)
The LLM’s generation hidden states already encode the search intent. The projection head learns to transform these states into the same embedding space as a dedicated retrieval model. The alignment loss anchors the representation to the teacher’s space, the contrastive loss enforces discrimination between relevant and irrelevant documents, and the rank distillation loss preserves the teacher’s ranking preferences. Together they enable the LLM‑only system to mimic the two‑model baseline’s retrieval behavior while avoiding the second forward pass.

## Foundational Learning
- **Hidden State Retrieval**: Using intermediate activations of an LLM as a query representation.  
  *Why needed*: Avoids a separate encoding step; reuses computation already performed during generation.  
  *Quick check*: Compute the cosine similarity between mean last‑layer hidden states of paraphrased queries; they should cluster together.
- **Projection Head**: A small network (linear → transformer layers → pooling → linear + L2) that maps hidden states to the target embedding space.  
  *Why needed*: Adapts the LLM’s internal representation to match the teacher’s embedding space.  
  *Quick check*: With frozen LLM, train only the projection on a few hundred examples and verify that output dimensionality matches the teacher’s (e.g., 1024).
- **Alignment Loss**: MSE between projected embedding and teacher embedding.  
  *Why needed*: Provides a direct regression target to align the student’s output with the teacher’s space.  
  *Quick check*: On a validation set, alignment loss should decrease steadily during training and correlate with final retrieval quality.
- **Contrastive Loss**: InfoNCE loss that treats teacher‑retrieved positives as similar and other documents as negatives.  
  *Why needed*: Encourages the embedding to discriminate between relevant and irrelevant documents.  
  *Quick check*: After training, nearest‑neighbor search in the embedding space should return documents relevant to the query.
- **Rank Distillation Loss**: KL divergence between teacher and student similarity scores over a fixed set of documents.  
  *Why needed*: Transfers the teacher’s ranking knowledge, ensuring the student preserves retrieval order.  
  *Quick check*: Compute nDCG@10 for student vs. teacher on a held‑out query set; they should be close after training.

## Architecture Onboarding
**Component Map**  
LLM (generation) → Hidden States (non‑special tokens) → Projection Head (Linear → Transformer Encoder×2 → Mean Pool → Linear + L2) → Query Embedding.  
Training additionally involves Teacher Model → Target Embeddings & Top‑128 Rankings → Loss Computation.

**Critical Path**  
Inference: 1) LLM generates query tokens. 2) Extract last‑layer hidden states of non‑special tokens. 3) Pass through projection head. 4) Compute cosine similarity against document index. 5) Return top‑k results.

**Design Tradeoffs**  
- Speed vs. quality: Removing the separate embedding model yields a 21.8× speedup but incurs a small (3%) drop in retrieval metrics.  
- Simplicity vs. flexibility: The fixed projection head architecture (2 transformer layers) is efficient but may require retraining for a different LLM or teacher.  
- One‑time cost: Generating traces and teacher rankings is computationally heavy but amortized across many inference queries.

**Failure Signatures**  
- Training collapse at high learning rates (e.g., 5e‑4) leads to near‑zero metrics; loss diverges within first few batches.  
- Using only rank distillation loss fails completely; the model learns nothing without alignment loss.

**First Experiments**  
1. Generate cached hidden‑state traces for the QReCC training split by running the LLM agent and storing per‑trigger hidden states and query text.  
2. Train the projection head with the full three‑loss objective (λₐ=λ꜀=λᵣ=0.5), monitoring loss convergence and validation Recall@10.  
3. Evaluate on the test split: compute Recall@10, MRR@10, and per‑query latency; compare against the two‑model baseline and measure trigger agreement.

None.

## Limitations
- Requires the proprietary teacher model Qwen3‑Embedding‑8B; substitution with a public model may alter results.  
- Tokenization details (exact handling of BOS/EOS/PAD tokens) are unspecified, affecting hidden‑state pooling and final embedding.  
- Evaluation is limited to the QReCC benchmark; generalizability to other datasets or tasks is unknown.  
- The projection head architecture (2 transformer layers) may not be optimal and was not extensively explored.

## Confidence
- Near‑parity with baseline (97% metrics): Medium  
- Latency reduction (21.8×): High  
- Necessity of all three loss components: Medium  
- Statistical significance (p=0.0005) and 84.2% trigger agreement: Medium  

## Next Checks
1. Replace the teacher with a public embedding model (e.g., OpenAI text‑embedding‑3‑small) and re‑run training/evaluation to assess robustness.  
2. Test the approach on additional conversational search benchmarks (e.g., CAsT, TREC CAsT) to verify generalizability.  
3. Conduct a hyperparameter sweep over projection head depth (1‑4 transformer layers) and learning rate schedules to possibly narrow the performance gap.
