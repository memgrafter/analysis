# SciFig: Towards Automating Scientific Figure Generation
## Quick Facts
- **arXiv ID**: 2601.04390
- **Source URL**: https://arxiv.org/abs/2601.04390
- **Reference count**: 40
- **Primary result**: SciFig automates scientific figure generation with hierarchical layout and iterative feedback, achieving 70.1% dataset-level quality, 66.2% paper-level quality, and 57.1% of human quality with a 1,407× speedup.

## Executive Summary
SciFig introduces an end-to-end AI agent system for automating the creation of publication-quality scientific figures. The system parses method descriptions from research papers, hierarchically groups visual components into functional modules, and connects these modules to ensure clear information flow. An iterative chain-of-thought feedback loop refines layouts over multiple rounds, guided by a rubric-based evaluation framework derived from 2,219 real figures. This approach addresses the labor-intensive manual process of figure design, offering significant time savings.

In evaluations, SciFig achieves competitive automatic quality scores (70.1% dataset-level, 66.2% paper-level) and surpasses baselines like Paper2Poster and GPT-5-Image. Human studies indicate it reaches 57.1% of human-level quality while accelerating figure creation by a factor of 1,407—reducing time from approximately 9.5 days to 9.7 minutes. The pipeline and evaluation benchmark are open-sourced to support further research.

## Method Summary
SciFig's pipeline begins with a natural language parser that extracts visualization intents from the method section of a paper. It then employs a hierarchical layout generator to decompose the figure into modules (e.g., schematics, plots, tables) and arrange them with connectivity. Each module is rendered by a component agent that produces vector graphics. An iterative feedback agent uses a rubric to critique the layout and suggest improvements across multiple rounds, refining both module composition and spatial arrangement. The final output is a publication-ready figure aligned with the paper's content.

## Key Results
- Achieves 70.1% overall quality on dataset-level evaluation and 66.2% on paper-specific evaluation using the proposed rubric.
- Human evaluation shows SciFig attains 57.1% of human-level quality with a 1,407× speedup (from ~9.5 days to 9.7 minutes).
- Outperforms baselines: Paper2Poster (65.7%) and GPT-5-Image (43.1%) on automatic metrics.

## Why This Works (Mechanism)
The hierarchical layout decomposition provides a structured yet flexible scaffold: grouping related components into modules reduces the complexity of the global layout and creates natural boundaries for refinement. The iterative chain-of-thought feedback loop leverages the rubric to identify specific issues (e.g., poor modularity, unclear flow) and propose corrective actions, with each round incrementally improving the layout. Because the hierarchy stabilizes the correction space—preventing feedback from disrupting the overall structure—quality improves monotonically, unlike in flat layouts where feedback can cause instability. The rubric, derived from real figures, ensures that optimization aligns with human aesthetic and functional preferences.

*Why needed*: Allows progressive error correction by reasoning about layout flaws across multiple rounds, leading to robust improvements.

*Why needed*: Provides a reliable, automatically computable proxy for human judgment, guiding the optimization without costly human annotations.

## Architecture Onboarding
#### Component Map
The system comprises the following main components:  
- **Parser**: Extracts figure intents from the paper's method section.  
- **Layout Generator**: Creates a hierarchical module graph and spatial arrangement.  
- **Component Agent**: Renders each module as vector graphics.  
- **Feedback Agent**: Evaluates the layout using the rubric and suggests refinements.  
- **Evaluation Module**: Computes rubric scores automatically.  

Data flow: Parser → Layout Generator → Component Agent → Output. Feedback loop: Evaluation Module → Feedback Agent → Layout Generator (iterative).

#### Critical Path
1. Parse the method description to identify required visual components and their semantic roles.
2. Generate an initial hierarchical layout: group components into modules and define inter-module connections.
3. Render each module with the component agent.
4. Evaluate the composite figure using the rubric.
5. If quality threshold not met, feedback agent proposes changes to layout (module grouping, positioning) and returns to step 2.
6. Repeat iterations until convergence or max iterations, then output final figure.

#### Design Tradeoffs
- **Hierarchy vs. Flexibility**: A rigid hierarchical structure improves stability and interpretability but may limit unconventional layouts.
- **Automation vs. Customization**: Fully automated generation saves time but may not satisfy domain-specific stylistic preferences without manual overrides.
- **Iteration Count vs. Efficiency**: More feedback rounds can improve quality but increase computational cost; the system uses a fixed number of rounds (5) as a tradeoff.
- **General-Purpose vs. Domain-Specialized Components**: Using generic rendering primitives widens applicability but may lack fine-grained domain symbols (e.g., molecular structures).

#### Failure Signatures
- **Unstable Quality with Flat Layouts**: When hierarchy is removed, iterative feedback leads to non-monotonic quality changes, indicating correction instability.
- **Poor Visual Clarity**: Overlapping labels, insufficient contrast, or ambiguous flow arrows reduce readability.
- **Implementation Quality Issues**: Rasterized outputs, misaligned components, or non-vector graphics indicate component agent shortcomings.
- **Incorrect Module Grouping**: Components that belong together are placed in separate modules, breaking semantic coherence.

#### First Experiments
1. **Ablation of Hierarchical Structure**: Compare hierarchical vs. flat layouts under identical feedback iterations, measuring quality trajectory and stability.
2. **Feedback Iteration Sensitivity**: Vary the number of feedback rounds (1–10) to determine the point of diminishing returns on quality and computational cost.
3. **Cross-Domain Generalization**: Test the system on figure descriptions from non-AI fields (e.g., biology, physics) to evaluate robustness and identify domain-specific failure modes.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: What explains the critical dependency between hierarchical layout and iterative CoT feedback, where feedback alone on flat layouts leads to unstable performance, and can this insight be formalized into design principles for other multi-agent visual generation systems?
- **Basis in paper**: [inferred] The ablation study (Table 2 and Section 4.2) shows that iterative feedback on naive flat layouts yields non-monotonic quality changes across rounds (67.3 → 68.1 → 64.3 → 68.5 → 65.3), while feedback on hierarchical layouts improves quality consistently. The paper hypothesizes that hierarchical structure provides stable module boundaries that guide corrections, but no formal theory is provided.
- **Why unresolved**: Understanding this synergy could inform the design of iterative refinement in other structured generation tasks (e.g., UI design, chart creation), but the paper lacks a mechanistic analysis of why hierarchy stabilizes feedback—e.g., whether it reduces action space, limits error propagation, or aligns feedback granularity with structural priors.
- **What evidence would resolve it**: Controlled experiments varying hierarchical depth and feedback specificity, coupled with theoretical modeling (e.g., Markov decision processes over layout graphs) to quantify how hierarchy constrains the feedback correction space.

### Open Question 2
- **Question**: Why does the automatic evaluation framework yield significantly higher overall quality scores for SciFig (70.1% dataset-level) compared to human evaluation (57.1%), and what specific human judgment aspects are missing from the current rubrics or scoring mechanism?
- **Basis in paper**: [inferred] Tables 1 and 3 show consistent ranking (Original > SciFig > baselines) but a large absolute gap: SciFig’s automatic score is 13.0 points higher than human-assessed. The paper attributes this to "evaluation granularity and rater strictness" but does not dissect which rubric dimensions or criteria drive the discrepancy.
- **Why unresolved**: Without identifying the specific mismatches, it is unclear whether the rubrics miss subtle human preferences (e.g., aesthetic nuance, domain conventions) or whether the automatic agent overestimates technical correctness. This limits confidence in using the framework to guide future system improvements.
- **What evidence would resolve it**: Fine-grained error analysis comparing human and agent rationales per rubric item, possibly via expert panels, to pinpoint which criteria (e.g., "color accessibility" vs. "modular organization") exhibit the largest score differentials and why.

### Open Question 3
- **Question**: How well does SciFig generalize to scientific domains outside the AI-conference papers used for training and evaluation, particularly fields with distinct visualization conventions (e.g., molecular biology, quantum physics), and what adaptations are needed for such domain shifts?
- **Basis in paper**: [inferred] The evaluation dataset comprises 435 papers from 15 AI-centric conferences and 37 domains, but all within computer science/AI (e.g., cs.CV, cs.CL). The paper claims "comprehensive coverage" but does not test on non-AI fields. Component generation relies on controlled image generation for domain-specific icons, which may fail for unfamiliar symbol systems (e.g., chemical structures, circuit diagrams).
- **Why unresolved**: Generalization to radically different scientific visualization traditions is critical for real-world adoption, but the system’s description agent (parsing research text) and component agent (rendering) may encode AI-domain biases from training data. No experiments probe cross-domain robustness.
- **What evidence would resolve it**: Benchmarking SciFig on a held-out set of pipeline figures from non-AI fields (e.g., biology journals, physics reviews), measuring performance drops per rubric, and analyzing error modes (e.g., incorrect notation, missing domain-specific components).

### Open Question 4
- **Question**: What are the specific failure modes in Visual Clarity and Implementation Quality that cause SciFig to score lower on these dimensions (human R2: 54.0%, R6: 52.8%) compared to Structural Coherence (R3: 61.2%), and how can the component generation and feedback mechanisms be enhanced to address these?
- **Basis in paper**: [inferred] Human evaluation (Table 3) shows SciFig’s lowest scores in Visual Clarity and Implementation Quality. The paper notes "opportunities for future improvement in rendering improvement and visual polish" but provides no qualitative examples or diagnostic analysis of these weaknesses.
- **Why unresolved**: Without understanding whether failures stem from text legibility, color contrast, vector graphic artifacts, or spacing issues, targeted improvements are difficult. Lower Implementation Quality suggests the component agent may produce non-vector or pixelated outputs, while Visual Clarity issues could involve ambiguous flows or crowded labels.
- **What evidence would resolve it**: Error categorization on a sample of low-scoring figures, e.g., via expert annotation of specific visual flaws, followed by ablation of component agent design choices (e.g., typography models, arrow rendering) to isolate root causes.

## Limitations
- Evaluation rubric (from 2,219 figures) may not capture discipline-specific design norms or aesthetic preferences.
- Baseline comparisons omit concurrent works like FigGen; claims of superiority may be overstated.
- Human study details (participant expertise, sample size, evaluation protocol) are unreported, limiting confidence in "human-level" claims.

## Confidence
- Hierarchical layout & iterative refinement mechanism: **High**
- Dataset/paper-level quality scores (70.1%/66.2%): **Medium**
- Human-level quality attainment (57.1%): **Low-Medium**
- Speedup claim (1,407×): **High**
