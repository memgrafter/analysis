# DynaMoE: Dynamic Token-Level Expert Activation with Layer-Wise Adaptive Capacity for Mixture-of-Experts Neural Networks

## Quick Facts
*   **arXiv ID:** 2603.01697
*   **Source URL:** https://arxiv.org/abs/2603.01697
*   **Reference count:** 40
*   **Primary result:** DynaMoE introduces dynamic token-level expert activation and layer-wise expert scheduling, achieving up to 5.47% higher accuracy on image classification and scale-dependent perplexity improvements in language modeling, while reducing gradient variance.

## Executive Summary
DynaMoE reformulates Mixture-of-Experts (MoE) by replacing rigid fixed Top-K routing and uniform expert allocation with two core innovations: (1) a dynamic, token-level routing mechanism using a percentile threshold that activates a variable number of experts per token based on input complexity, and (2) six layer-wise expert scheduling strategies (e.g., descending, ascending) that allocate a different total number of experts to each layer. The paper provides theoretical analysis showing increased model expressivity and reduced gradient variance. Empirical results on image classification (MNIST, CIFAR-10) and language modeling (Recycling-the-Web) demonstrate that optimal schedule selection is task- and model scale-dependent, with descending schedules yielding consistent gains on image tasks.

## Method Summary
DynaMoE modifies a standard MoE layer. For each token, gate values are computed via a softmax. During training, noise is added. Instead of selecting a fixed Top-K experts, a percentile threshold τ is applied to the gate distribution to select experts `S_τ(x)`. If no expert exceeds the threshold, the top-1 is selected. The selected gate values are re-softmaxed with a temperature T to produce final weights. The layer's total expert count is not uniform; a scheduling function determines the number of experts `N_ℓ` assigned to layer ℓ. These counts are derived from a continuous formula (e.g., descending, ascending) and rounded to integers subject to a total capacity budget C. Critically, the model is trained without auxiliary load-balancing losses.

## Key Results
*   On image classification (MNIST, Fashion-MNIST, CIFAR-10), descending expert schedules consistently outperform uniform baselines by up to 5.47% in accuracy.
*   For language modeling on a small dataset, optimal schedule is scale-dependent: descending for Tiny models (6.2% PPL improvement), ascending for Small, and uniform for Medium.
*   Dynamic token-level routing improves training stability by lowering per-token gradient variance, leading to faster convergence.

## Why This Works (Mechanism)
### Mechanism 1: Dynamic Token-Level Routing
*   **Claim:** Variable experts per token based on input complexity improves expressivity and computational efficiency compared to fixed Top-K.
*   **Mechanism:** A percentile-threshold on gate values selects experts. Simpler inputs yield fewer high-gate experts (lower compute), complex inputs yield more. This increases possible activation patterns (Theorem 1) and reduces gradient variance (Theorem 2).
*   **Core assumption:** Gate value distribution meaningfully correlates with input complexity; a static threshold approximates optimal variable-K.
*   **Evidence anchors:** Abstract mentions dynamic activation based on characteristics. Section 3.2 defines `S_τ(x)`. Corpus is weak; similar concepts exist but not via this exact percentile threshold.
*   **Break condition:** Uniform or noisy gate distributions cause erratic expert counts and load imbalance.

### Mechanism 2: Layer-Wise Expert Scheduling
*   **Claim:** Allocating different numbers of experts per layer aligns capacity with the layer's representational diversity, outperforming uniform allocation.
*   **Mechanism:** Schedules (descending, ascending, etc.) define `N_ℓ`. For images, descending (more experts early) aligns with the Representational Diversity-Convergence (RDC) Principle where early layers have higher entropy/curvature. For language, optimal schedule varies with model scale.
*   **Core assumption:** Optimal `N_ℓ` is proportional to a layer-wise "representational diversity index" `D_ℓ` that has a predictable depth profile (monotonic for spatial tasks).
*   **Evidence anchors:** Abstract reports task/scale-dependent optimal schedules. Section 7.2 formalizes RDC: `N*_ℓ ∝ D_ℓ`. Corpus is weak; prior work studies semantic specialization, not depth-wise scheduling.
*   **Break condition:** If a task's `D_ℓ` profile is non-monotonic (e.g., U-shaped), predefined schedules will misallocate capacity.

### Mechanism 3: Gradient Variance Reduction
*   **Claim:** Dynamic routing and appropriate scheduling reduce gradient variance during training, improving convergence stability.
*   **Mechanism:** Using more experts in high-diversity layers (descending) averages gradients over more pathways. Dynamic selection also encourages more uniform expert utilization than fixed Top-K.
*   **Core assumption:** Gradient variance for gating/expert parameters is inversely related to routing entropy and directly related to number of independent pathways.
*   **Evidence anchors:** Abstract links dynamic routing to reduced variance. Section 4.3 derives `Var(g_dyn) ≤ Var(g_fixed) * (1 - γ/N)` under assumptions. Corpus not directly addressed.
*   **Break condition:** If expert specializations are poor (experts redundant), adding experts may not increase routing entropy and could increase variance.

## Architecture Onboarding
**Component map:**
Input Projection → [DynaMoE Layer (with LayerNorm) repeated L times] → Output Head. Each DynaMoE Layer contains: Gating Network → Expert Selection (percentile threshold) → Reweighting (temperature) → Sparse Expert Execution (ModuleList) → Residual Add.

**Critical path:**
1.  Compute gate logits `g = softmax(W_g x)`.
2.  If training, add noise `g ← g + ε, ε∼N(0,σ²)`.
3.  Compute threshold `θ = τ‑quantile(g)`.
4.  Select experts `S = {i | g_i > θ}`; if `S` empty, use `argmax`.
5.  Renormalize selected gates with temperature `T`: `s = softmax(g_S / T)`.
6.  Compute outputs `y_i = E_i(x)` for all `i ∈ S` (sparse execution).
7.  Aggregate: `y = Σ s_i * y_i`.
8.  Add residual: `h_{ℓ+1} = y + h_ℓ`.
9.  Apply LayerNorm.

**Design tradeoffs:**
*   **Threshold τ:** Lower τ increases average `K(x)` and capacity but risks load imbalance. Higher τ increases sparsity but may under-fit complex tokens.
*   **Schedule shape:** Predefined schedules are simple but task-dependent. A wrong schedule (e.g., ascending on CIFAR-10) misallocates capacity.
*   **No balancing loss:** Omitting auxiliary losses simplifies analysis but risks expert collapse on large/diverse datasets.

**Failure signatures:**
*   **Expert collapse:** One or few experts consistently activated; check per-expert activation histograms.
*   **Token overflow:** A single expert selected by a large batch fraction causes memory spikes (OOM).
*   **Schedule-task mismatch:** e.g., Ascending on CIFAR-10 yields lower accuracy than descending.
*   **Dynamic routing instability:** Training loss diverges/noisy; likely τ too low or T too high.

**First 3 experiments:**
1.  **Routing Distribution Sanity Check:** Train Tiny model on MNIST with descending. Log per-layer average `K(x)` and gate entropy. Expect `K(x)` decreases with depth, entropy ~1-2 bits.
2.  **Schedule Ablation on Fashion-MNIST:** Train Small models with all 6 schedules + uniform + MLP. Validate descending wins for image tasks.
3.  **Dynamic vs. Fixed Routing:** Within descending, compare percentile-threshold against fixed Top-K=2. Measure accuracy gap and expert utilization entropy; expect dynamic wins.

## Limitations
*   **Architectural ambiguities:** Exact integer expert counts, expert hidden size, image preprocessing, and capacity overflow handling are unspecified, hindering exact replication.
*   **Limited validation:** Theories (RDC, superposition) are explanatory narratives without formal proofs or broad empirical validation across diverse architectures and tasks.
*   **Stability concerns:** Percentile-threshold routing without auxiliary load-balancing may suffer expert collapse or token overflow if gate distributions are uniform/noisy.

## Confidence
*   **Dynamic token-level routing improves expressivity and efficiency:** Medium (theoretically plausible but empirical sensitivity to τ).
*   **Layer-wise expert scheduling yields performance gains:** Medium (improvements strong but limited to specific configurations; integer rounding could alter schedule rankings).
*   **Dynamic routing reduces gradient variance and stabilizes training:** Medium (theorem provides bound; faster convergence confounded by added capacity/schedule).
