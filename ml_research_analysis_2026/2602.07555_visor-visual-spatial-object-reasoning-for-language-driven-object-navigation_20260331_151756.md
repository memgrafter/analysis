# VISOR: VIsual Spatial Object Reasoning for Language-driven Object Navigation

## Quick Facts
- **arXiv ID:** 2602.07555
- **Source URL:** https://arxiv.org/abs/2602.07555
- **Reference count:** 40
- **Primary result:** A compact 3B-parameter unified model performs explicit image-grounded waypoint selection, achieving state-of-the-art success on CoIN-Bench and OVON while improving generalization, efficiency, and explainability over modular and embedding-based approaches.

## Executive Summary
VISOR introduces a unified Vision-Language-Action model for language-driven object navigation. Instead of relying on embedding matching or multi-pipeline systems, it performs explicit reasoning by selecting waypoint labels directly overlaid on panoramic observations. The agent processes panoramic RGB and top-down maps, outputs a structured reasoning trace (` `<think_summary>`, `<action>`), and is trained via supervised fine-tuning on the new WAYS-Bench dataset followed by Group Sequence Policy Optimization (GSPO) reinforcement learning. On CoIN-Bench and OVON benchmarks, VISOR substantially outperforms prior methods—especially in unseen environments—while demonstrating properties of Compactness, Unification, Reasoning, and Explainability (CURE).

## Method Summary
VISOR uses a Qwen 2.5 VL 3B backbone. At each navigation step, it receives a panoramic RGB image (768×256), a top-down map (256×256), and the natural language instruction. Waypoint candidates are generated via DBSCAN clustering on navigable points and labeled with random letters superimposed on the panorama. The model generates a three-part output: an internal thought, a summary, and an action tag selecting a label (or STOP). The chosen label is projected to a world coordinate, and Habitat’s shortest-path planner executes low-level motion. Training occurs in two stages: (1) Supervised Fine-Tuning (SFT) on 36K samples from WAYS-Bench with GPT-4o reasoning traces; (2) Reinforcement Learning with GSPO, using a reward combining format compliance, action correctness, and KL regularization (β=0.01) to improve navigation efficiency while preserving reasoning structure.

## Key Results
- On CoIN-Bench Val Unseen: SPL 6.07, SR 9.37, far ahead of Monolithic (SPL 0.10, SR 0.22) and PSL (SPL 2.67, SR 8.50).
- On OVON Val Unseen: SPL 11.86, SR 22.00, showing consistent gains.
- RL post-training (GSPO) improves path efficiency (higher SPL) without sacrificing success, and KL regularization is critical to maintain reasoning quality.

## Why This Works (Mechanism)
### Mechanism 1: Explicit Image-Grounded Reasoning Generalizes Better
- **Claim:** Selecting waypoint labels directly on the panoramic image forces perceptual grounding, improving generalization to unseen scenes versus implicit embedding-based policies.
- **Mechanism:** The model sees letters (A, B, C) on specific image regions and must justify its choice based on visible content. This prevents reliance on spurious embedding correlations that don’t transfer.
- **Core assumption:** Direct perceptual grounding is more robust than abstract embedding matching for novel environments.
- **Evidence anchors:** Abstract states "explicit image-grounded reasoning"; Section 4.2 shows PSL/Monolithic degrade dramatically on Val Unseen; Section 3 describes label overlay as spatial anchors.
- **Break condition:** If the model associates specific letters with success regardless of image content (e.g., always pick 'A'), grounding fails.

### Mechanism 2: Unified Model Avoids Error Propagation
- **Claim:** A single 3B-parameter Vision-Language-Action model eliminates error propagation and computational overhead of modular pipelines while retaining reasoning capability.
- **Mechanism:** All sub-tasks (perception, reasoning, action) are processed jointly in one forward pass, avoiding cascading failures from chained modules (object detector → VLM → LLM → planner).
- **Core assumption:** A 3B model has sufficient capacity for joint processing without performance loss.
- **Evidence anchors:** Abstract notes "removing the need for stitched multi-model pipelines"; Section 1 criticizes pipeline-based methods; Section 4 shows VISOR competes with modular MTU3D.
- **Break condition:** If navigation complexity exceeds single-model capacity, modular approaches might regain necessity.

### Mechanism 3: SFT on GPT-4o Traces + GSPO RL Yields Efficient Reasoning Policy
- **Claim:** Initializing with SFT on reasoning traces provides a structured prior; GSPO RL then refines actions for efficiency via navigation rewards while preserving reasoning via KL regularization.
- **Mechanism:** SFT teaches the format and correct selections; RL optimizes for success and path length using sequence-level importance ratios, with KL preventing deviation from the SFT policy.
- **Core assumption:** Reasoning behavior is learnable from demonstration and refinable with outcome rewards without explicit reasoning rewards.
- **Evidence anchors:** Section 3 details DSFT and DRL; Section 4.2 shows RL improves SPL; Section 3 notes ablating KL degrades performance.
- **Break condition:** If SFT policy is too far from optimal, RL may fail to improve or degrade reasoning; paper notes need for balanced DRL dataset to avoid reward hacking.

## Foundational Learning
- **Vision-Language Models (VLMs):** Needed because VISOR builds on Qwen 2.5 VL; understanding how transformers combine visual and textual tokens is key for architecture extensions. *Quick check:* How do decoder-only VLMs differ from encoder-decoder VLMs in multimodal fusion?
- **Group Sequence Policy Optimization (GSPO):** The RL stage uses GSPO; grasp its sequence-level importance ratio vs. token-level (GRPO) and why it suits long-form reasoning. *Quick check:* What makes sequence-level optimization more stable for trajectory-based tasks?
- **Waypoint-based Navigation:** Core formulation; decouples high-level reasoning from low-level control. *Quick check:* How does selecting waypoints (vs. discrete atomic actions) simplify training and improve generalization to new scenes?
- **Embodied Navigation Metrics (SPL, SR):** All results use these; understand tradeoffs. *Quick check:* Why might a model’s SPL increase while SR slightly decreases?
- **DBSCAN Clustering for Waypoints:** Used to generate candidate navigable points; appreciate its role in producing dense, reasonable waypoints from depth. *Quick check:* How does DBSCAN’s density-based approach help avoid obstacles compared to grid sampling?

## Architecture Onboarding
- **Component map:** Qwen 2.5 VL 3B backbone (vision encoder + language decoder) -> Input pipeline (panoramic RGB 768×256, top-down map 256×256, instruction text) -> Waypoint labeling system (random letters via DBSCAN overlaid on panorama) -> Output parser (extract `<action>` tag) -> Habitat shortest-path planner (converts label to world coordinates, executes low-level actions) -> DSFT dataset (36K GPT-4o traces) -> DRL dataset (balanced subset) -> GSPO RL.
- **Critical path:** At each step: (1) capture panoramic + map observation; (2) overlay random letter labels on waypoint candidates; (3) feed image+text prompt to VLM; (4) parse `<action>` tag; (5) map label to world coordinate; (6) execute planner to reach point; (7) repeat until `<action>STOP_NAV</action>` or step limit.
- **Design tradeoffs:**
  1. Compact 3B vs. larger VLMs: Smaller is faster/cheaper but may weaken reasoning; mitigated by task-specific SFT+RL.
  2. Panoramic+map vs. single POV: More spatial context but higher memory; requires tiling/resizing for VLM.
  3. Explicit reasoning traces vs. implicit policies: Better explainability/generalization but slower inference and prompt engineering sensitivity.
  4. Random label overlay vs. fixed: Prevents memorization of label-action shortcuts but requires consistent per-step generation.
- **Failure signatures:**
  1. Hallucinations: Model references non-existent labels or misidentifies objects.
  2. Spatial confusion: Left/right errors, ignoring spatial relations in instruction.
  3. Depth misestimation: Incorrect Stop timing (too early/late).
  4. Markovian forgetting: In last-mile, agent circles away from visible target due to no history.
- **First 3 experiments:**
  1. **SFT format validation:** Train on 100 samples; verify model outputs all three tags and selects only presented labels.
  2. **Generalization sanity check:** Evaluate SFT model on CoIN-Bench Val Unseen; should show more consistent performance across splits than Monolithic/PSL.
  3. **RL efficiency ablation:** Compare SFT-only vs. SFT+GSPO on validation; expect SPL increase while SR stays stable; also test KL regularization ablation.

## Open Questions the Paper Calls Out
- **Open Question 1:** How can historical observations and reasoning traces be incorporated to move beyond the current Markovian assumption? Basis: Conclusion suggests extending to non-Markovian; failure analysis (C.3) shows last-mile circling. Unresolved: Agent forgets previous context. Evidence needed: Memory integration (recurrent/attention over past) improving final-step success.
- **Open Question 2:** What methods can effectively reduce hallucinations in the VLM’s reasoning and output consistency? Basis: Conclusion identifies hallucinations; failure analysis (C.1) shows reasoning about non-existent labels. Unresolved: Hallucinations undermine reliability. Evidence needed: Rule-based rewards/consistency checks during RL, reducing hallucination frequency.
- **Open Question 3:** How can depth information be integrated to improve distance estimation and stop-action accuracy? Basis: Conclusion proposes depth on top-down map; failure analysis (C.2) documents depth misjudgment affecting Stop. Unresolved: Agent lacks explicit depth perception. Evidence needed: Encoding depth as extra channel (panoramic or map), evaluating stop precision and SPL.
- **Open Question 4:** How can robust spatial understanding (e.g., left/right distinctions, spatial relationships) be achieved in VLMs for navigation? Basis: Failure analysis (C.1) states robust spatial understanding remains a challenge (Kong et al., 2025). Unresolved: Misinterpretation leads to contradictory waypoint choices. Evidence needed: Spatial relation pretraining or modules, testing on benchmarks like LRR-Bench with higher relational accuracy.

## Limitations
- Exact SFT system prompt phrasing is unspecified, requiring inference.
- GSPO hyperparameters (group size, rollout batch, reward weights) are not fully detailed.
- Top-down map construction depends on external implementation (Yokoyama et al., 2024a), risking variability.
- Official evaluation splits for CoIN-Bench Val Unseen and OVON are not released.
- Image preprocessing specifics (resolution, normalization, token count) are missing, affecting input handling.

## Confidence
- **Explicit image-grounded reasoning improves generalization:** Medium-High. Supported by unseen-split ablations, but depends on proper label randomization.
- **Unified model avoids error propagation:** High. Clear advantages shown over modular baselines.
- **SFT + GSPO yields efficient reasoning policy:** Medium. RL improves SPL, but reasoning preservation relies on KL regularization; risk of reward hacking noted.

## Next Checks
1. **SFT format compliance test:** Train on a small subset (e.g., 100 samples) and verify the model outputs well-formed `<think>`, `<think_summary>`, `<action>` tags and selects only from provided labels.
2. **Generalization sanity check:** Evaluate the SFT model on CoIN-Bench Val Unseen; it should outperform Monolithic and PSL in cross-split consistency, even if absolute scores are lower.
3. **RL efficiency ablation:** Compare SFT-only vs. SFT+GSPO on a validation set; confirm SPL increases while SR remains stable, and test the impact of removing KL regularization.
