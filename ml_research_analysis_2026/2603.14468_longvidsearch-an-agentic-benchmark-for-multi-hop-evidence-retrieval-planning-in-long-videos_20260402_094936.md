# LongVidSearch: An Agentic Benchmark for Multi-hop Evidence Retrieval Planning in Long Videos

## Quick Facts
- **arXiv ID:** 2603.14468
- **Source URL:** https://arxiv.org/abs/2603.14468
- **Reference count:** 40
- **Primary result:** GPT-5 achieves 42.43% accuracy on the benchmark, with all models below 50%; accuracy decreases with hop depth while tool-call cost increases, and oracle experiments isolate retrieval planning as the bottleneck.

## Executive Summary
LongVidSearch introduces the first benchmark for evaluating agentic multi-hop evidence retrieval in long videos. It comprises 3,000 questions over 447 long videos (average 26 minutes), with each question requiring exactly k necessary evidence clips for k-hop reasoning, enforced by an N-1 adversarial ablation check. Agents interact via a unified tool interface that fixes the retrieval backend, isolating planning capabilities. Evaluation shows that even the best model (GPT-5) scores only 42.43%, and performance degrades with hop depth. Oracle experiments that provide gold evidence clips yield near-perfect accuracy, confirming that retrieval planning is the primary bottleneck. The benchmark enables analysis of the accuracy-cost trade-off in tool usage.

## Method Summary
The benchmark is built through a multi-stage adversarial pipeline: a generator agent creates candidate QA pairs from dense video captions; rule-based, semantic, and logical filters remove obvious shortcuts; an N-1 adversarial ablation check ensures each question truly requires all k evidence clips; visual grounding verifies pixel-level consistency; and human auditors perform final falsification. For evaluation, agents use three standardized tools—Search_Clips_In_Video, Get_Clip_Detail, and FINAL_ANSWER—in an iterative loop. The retrieval backend (e.g., embedding model) is fixed for all agents, so performance differences reflect query formulation and planning. Primary metrics are answer accuracy (judged by three LLMs via majority vote) and tool-call count. Oracle runs provide gold evidence clips to isolate the retrieval bottleneck.

## Key Results
- All models score below 50% accuracy; GPT-5 achieves the highest at 42.43%.
- Accuracy monotonically decreases with hop depth (2-hop → 4-hop), while average tool-call counts increase.
- Oracle experiments (gold evidence) yield near-perfect accuracy, demonstrating that retrieval planning is the main performance limiter and enabling accuracy-cost trade-off analysis.

## Why This Works (Mechanism)
1. **N-1 Adversarial Ablation Enforces Retrieval Necessity**: For a k-hop question, each evidence clip is masked one at a time; if an agent can answer correctly with any k-1 subset, the question is discarded. This eliminates pseudo-multi-hop questions where answers derive from partial evidence.
2. **Unified Tool Interface Isolates Planning**: All agents use the same three atomic tools and the same fixed retrieval backend, ensuring that performance differences stem from query generation and multi-step planning rather than retriever strength or access variations.
3. **Adversarial Multi-stage Pipeline Ensures Fidelity**: The construction pipeline sequentially applies generation, rule-based discontinuity filtering, semantic tautology removal, logical solvability check, N-1 necessity verification, visual grounding, and human falsification, effectively eliminating shortcuts and hallucinations.

## Foundational Learning
- **Multi-hop Question Answering**: Extends text-based multi-hop QA (e.g., HotpotQA) to long videos with temporally discontinuous evidence. *Why needed*: To understand why retrieval necessity is critical and how hop depth scales complexity. *Quick check*: What distinguishes a single-hop question from a true multi-hop question in terms of evidence dependency?
- **Tool-augmented Agents**: LLMs that interact with external tools (e.g., search, read) in a loop to gather evidence. *Why needed*: The benchmark evaluates agentic behavior, not static model performance. *Quick check*: In a video QA agent, what is the purpose of the FINAL_ANSWER tool and how does it differ from Get_Clip_Detail?
- **Adversarial Data Filtering & Shortcut Learning**: Automated QA generation can introduce shortcuts (semantic leakage, temporal overlap). *Why needed*: Recognizing common shortcut types is key to interpreting why many generated questions fail. *Quick check*: Why might a question like “What color is the car that crashes in the scene?” be considered to have a semantic leakage shortcut in a long-video setting?

## Architecture Onboarding
**Component map**:  
Raw Captions → Generator Agent → Rule-based Filter → Semantic Leakage Auditor → Logical Solvability Verifier → Adversarial Necessity Verifier → Visual Grounding Agent → Human Auditors → Final QA Set → Evaluation Engine  

**Critical path**: The N-1 adversarial ablation check is the central quality gate that enforces retrieval necessity; without it, pseudo-multi-hop questions would persist.  

**Design tradeoffs**:  
- *Recall vs. Precision*: Generator prioritizes recall, but precision is achieved via expensive adversarial filtering.  
- *Automated vs. Human*: Pipeline minimizes human labor but requires final human falsification as the essential quality gate.  
- *Hop-depth vs. Dataset size*: Strict necessity drastically reduces dataset size (from 11,612 to 3,000) and makes 4-hop questions sparse (14.8%).  

**Failure signatures**:  
- *Detail Missing*: Agent retrieves correct clip but fails to extract needed specifics (e.g., book title).  
- *Broken Evidence Link*: Agent misses one or more necessary clips, breaking the reasoning chain.  
- *Shortcut Survival*: Question passes pipeline but is solvable with fewer clips (detected by human audit or low oracle gap).  
- *Visual Hallucination*: Evidence description mismatches video pixels (caught by visual grounding or human audit).  

**First 3 experiments**:  
1. **Baseline Evaluation**: Run agents with different LLM backbones (GPT-5, Gemini, Qwen) using the unified tool interface; record accuracy and tool-call counts per hop level.  
2. **Oracle Retrieval**: Provide agents with exact golden evidence clips; expect near-perfect accuracy, isolating retrieval planning as the bottleneck; compute accuracy gap.  
3. **Cost-Accuracy Analysis**: Plot accuracy vs. tool-call count across models to identify efficiency (accuracy per call) and trade-offs.

## Open Questions the Paper Calls Out
1. **Why does accuracy degrade with hop depth?** The paper isolates retrieval planning as the bottleneck but does not dissect whether failures stem from query formulation, temporal reasoning, or evidence aggregation. A fine-grained hop-wise error analysis and component ablations are needed.
2. **What explains variance in accuracy-cost trade-offs?** Models with similar tool-call counts achieve different accuracies; the paper does not analyze retrieval precision (e.g., gold clip overlap) per call. Evidence: retrieval relevance correlation is missing.
3. **Do reasoning categories pose different challenges?** Categories (State Mutation, Causal Inference, Global Summary, Visual Tracking) show varying accuracy and hop distributions; the paper does not analyze category-specific failure modes or adaptive strategies.

## Limitations
- Retrieval backend specifications and agent prompt templates are undisclosed, hindering exact reproduction.
- Human audit sample is small (~300), leaving residual risk of shortcuts/hallucinations.
- Dataset size is limited (3,000 QAs) and 4-hop questions are sparse (14.8%), potentially underrepresenting deep reasoning.
