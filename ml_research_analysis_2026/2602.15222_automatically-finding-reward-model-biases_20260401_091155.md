# Automatically Finding Reward Model Biases

## Quick Facts
- arXiv ID: 2602.15222
- Source URL: https://arxiv.org/abs/2602.15222
- Reference count: 40
- Primary result: Automatically discovered reward model biases (e.g., triple spaces, hallucinated quotations) with statistical significance (p<0.01) for 10/17 candidates.

## Executive Summary
This paper tackles the challenge of identifying undesirable biases in reward models (RMs) for large language models (LLMs). The authors propose an automated pipeline that leverages an LLM to iteratively propose and refine candidate bias attributes via an evolutionary algorithm. Bias strength is measured as the average reward difference between counterfactual response pairs (one with the attribute, one without) and validated against an LLM judge. Applied to the Skywork-V2-8B reward model, the method uncovered novel biases such as a preference for triple spaces between words (RM strength up to 1.39±0.31) and hallucinated quotations (RM strength 2.52±0.51). Out of 17 candidate biases across 20 user prompt topics, 10 were statistically significant for both the reward model and the judge (p<0.01). Evolutionary search outperformed flat best-of-N in discovering diverse biases, and synthetic bias injection confirmed the pipeline’s recall, which peaked when the attribute prevalence was moderate.

## Method Summary
The pipeline begins by generating synthetic user prompts from 20 handwritten topic summaries. For each prompt, responses are sampled from a diverse set of LLMs and scored by the target reward model. An LLM then analyzes the responses (sorted by reversed reward) to propose initial candidate attributes that appear more often in higher-rewarded responses. These attributes form the initial population for an evolutionary loop: each iteration evaluates each attribute’s bias strength and judge winrate using a single rewriter model to create counterfactual pairs; candidates are filtered and selected via a Pareto frontier (maximize RM bias, minimize judge winrate); and survivors are mutated by prompting an LLM for variations. After several iterations, the remaining candidates are validated on held-out prompts using three independent rewriter models. Bias scores are pooled and subjected to Bonferroni-corrected one-sided t-tests; attributes with corrected p<0.01 for both tests pass to manual review.

## Key Results
- Discovered novel reward model biases, including a preference for triple spaces (strength 1.39±0.31) and hallucinated quotations (2.52±0.51).
- 10 of 17 candidate biases were statistically significant (p<0.01) for both the reward model and an LLM judge.
- Evolutionary search outperformed flat best-of-N, and the pipeline’s recall in synthetic bias injection peaked when attribute prevalence was moderate.

## Why This Works (Mechanism)
### Mechanism 1: Counterfactual Pair Construction and Bias Quantification
- **Claim:** The pipeline measures reward model bias by constructing minimal counterfactual response pairs and computing the average reward difference.
- **Mechanism:** For each candidate attribute, an LLM rewriter minimally edits a sampled response to either add or remove the attribute, producing two versions that differ only in the target attribute. The reward model’s scores on these pairs are averaged over many prompts to estimate bias strength. An LLM judge similarly provides a winrate.
- **Core assumption:** The rewrites are sufficiently minimal that confounding changes (length, content, tone) are negligible; any consistent reward difference can be attributed to the attribute.
- **Evidence anchors:**
  - [Abstract]: "measuring bias strength as the average reward difference between counterfactual response pairs (one with the attribute, one without) and validation against an LLM judge."
  - [Section 2.1]: "Our method... to form counterfactual pairs of assistant responses to the same user prompt, such that the main way in which the two responses differ is that one contains the attribute and the other does not."
  - [Section 2.1]: "Let us denote by fA=1 a rewrite process that transforms a response y into another response y′ = fA=1(y) such that A(y′) = 1 and that y, y′ remain as similar as possible."
  - [corpus]: The corpus contains related work on interpreting reward models (e.g., "Interpreting Language Reward Models via Contrastive Explanations") that also uses counterfactuals, but this paper’s novelty lies in automating attribute discovery.
- **Break condition:** If rewriting unintentionally alters other attributes (e.g., length, factual content), the bias measurement becomes confounded. The paper mitigates this via multiple rewriters, fidelity checks (Appendix D.1), and a high-quality rewriting rubric (Appendix D.3).

### Mechanism 2: Evolutionary Search for Bias Discovery
- **Claim:** An iterative evolutionary loop that evaluates, selects, and mutates candidate attributes efficiently discovers reward model biases that are preferred by the RM but dispreferred by a judge.
- **Mechanism:** Starting from an initial set of candidate attributes generated by an LLM, each iteration: (1) evaluates RM bias and judge winrate for every candidate, (2) selects the most promising ones via Pareto frontier selection (high RM bias, low judge bias), and (3) mutates them by prompting an LLM to propose variations. The process repeats, progressively refining and diversifying the candidate pool.
- **Core assumption:** The fitness landscape defined by (RM bias, judge bias) is navigable by LLM-based mutations; nearby attribute variations often retain or improve the bias signal, allowing incremental progress.
- **Evidence anchors:**
  - [Abstract]: "using an LLM to iteratively propose and refine candidate biases... evolutionary algorithm."
  - [Section 2.3]: "After we obtain an initial set of candidate attributes, we use an evolutionary algorithm to improve them... in each iteration, we: Evaluate the RM and judge bias strengths... Select the most promising candidates... Mutate the surviving attributes by prompting an LLM for variations."
  - [Section 3.3]: Comparative experiments show that depth‑5/branch‑4 evolutionary runs outperform flat best‑of‑N in both visualization and DABS metrics.
  - [corpus]: The corpus includes "Hypothesis Generation with Large Language Models" which similarly uses LLMs for refinement, but this paper tailors the approach to two‑objective bias discovery.
- **Break condition:** If the LLM fails to generate meaningful mutations (e.g., all variants are irrelevant or identical), the search stagnates. Poor initial candidates can also lead the loop to converge on spurious regions.

### Mechanism 3: Multi-Rewriter Validation and Statistical Filtering
- **Claim:** Final bias candidates are validated using multiple independent rewriters and Bonferroni‑corrected statistical tests, ensuring robustness and controlling false positives.
- **Mechanism:** After the evolutionary loop, each remaining attribute is re‑evaluated on a held‑out validation set using three different rewriter LLMs. The reward differences and judge winrates from all rewriters are pooled. One‑sided t‑tests assess whether the mean reward difference > 0 and mean judge winrate < 0.5. The p‑values are Bonferroni‑corrected across all candidates; only attributes with corrected p < 0.05 for both tests survive. A manual deduplication and human‑undesirability check follows.
- **Core assumption:** Consistency across diverse rewriters indicates that the measured bias stems from the attribute itself, not from a single rewriter’s quirks. Statistical tests filter out noise and sampling artifacts.
- **Evidence anchors:**
  - [Section 2.3]: "Validation... evaluate their RM and judge bias strengths on a held‑out validation split of the data, now with three different rewriter models... We pool the bias scores across all three rewriters, and filter for the candidates A such that R(A)>0, J(A)<0.5, and the Bonferroni‑corrected p<0.05 for both the RM and the judge."
  - [Table 1]: The final bias list (e.g., triple spaces, hallucinated quotations) passed these filters; many have p < 0.01.
  - [Section D.2]: Figures 6 and 7 show positive correlation across rewriters, suggesting they are not fully independent but still provide consistency checks.
- **Break condition:** If the three rewriters are too similar (e.g., same provider), they may not offer independent validation, increasing false positives. Overly stringent Bonferroni correction could also discard true biases.

## Foundational Learning
### Concept: Reward Modeling in RLHF
- **Why needed here:** The paper audits reward models (RMs), which are central to RLHF. Understanding how RMs are trained (e.g., Bradley‑Terry loss on preference pairs) and their role in shaping LLM behavior is essential to interpret biases.
- **Quick check question:** How does a reward model differ from a standard generative LLM, and why might optimizing against it lead to reward hacking?

### Concept: Counterfactual Reasoning for Causal Inference
- **Why needed here:** The method isolates an attribute’s effect by creating counterfactual pairs—responses that differ only in the presence of that attribute. This requires grasping that to attribute a reward difference to the attribute, all other factors must be held constant.
- **Quick check question:** Why can’t we simply compare responses that naturally contain an attribute to those that don’t? What threat does confounding pose?

### Concept: Multi-Objective Optimization and Pareto Frontier
- **Why needed here:** The search aims to maximize RM bias while minimizing judge winrate—two competing objectives. The Pareto frontier represents candidate attributes that cannot be improved in one objective without worsening the other, guiding selection.
- **Quick check question:** In a scatter plot of RM bias (x‑axis) vs. judge winrate (y‑axis), which quadrant contains the most promising biases? Explain why points near the lower‑right corner are preferred.

## Architecture Onboarding
### Component map
Prompt Generator -> Response Sampler -> Hypothesis Generator LLM -> Reward Model -> LLM Judge -> Rewriter Models -> Bias Evaluator -> Evolutionary Controller -> Statistical Validator -> Manual Review

### Critical path
1. Generate user prompts.
2. Sample responses and compute RM rewards.
3. Generate initial candidate attributes.
4. For each iteration: evaluate all attributes → select Pareto‑frontier → mutate survivors → deduplicate.
5. After final iteration, validate remaining attributes with three rewriters on held‑out prompts.
6. Apply statistical filters; manual review → final bias list.

### Design tradeoffs
- **Cost vs. robustness:** Using a powerful judge and three rewriters increases API costs but improves reliability. The paper notes the judge is the main bottleneck.
- **Synthetic prompt coverage:** Synthetic prompts enable controlled testing of specific topics but may miss biases that only appear on real user distributions.
- **Rewriter independence:** Three rewriters from different providers reduce single‑model artifacts, but if they are too correlated, the independence assumption weakens.
- **Evolutionary hyperparameters:** Depth (number of iterations) vs. branching (mutations per candidate). The paper finds depth 5/branch 4 performs best in limited comparisons (Section 3.3).
- **Statistical conservatism:** Bonferroni correction controls family‑wise error but may lower power; the paper uses p < 0.01 as an extra safeguard.

### Failure signatures
- **Rewrite quality:** Rubric scores (Appendix D.3) show occasional low scores (<9), indicating non‑minimal edits that could confound measurements.
- **No survivors:** If no attributes pass validation, either the RM has few biases or the pipeline parameters (e.g., mutation rate, selection pressure) are mis‑set.
- **High inter‑rewriter correlation:** Q‑Q plots (Figure 7) showing deviations from diagonal suggest rewriters introduce correlated noise.
- **Poor recall:** In the synthetic bias injection test (Section 3.4), success rates drop when the attribute is very rare or very common in samples, indicating hypothesis generation limitations.
- **Evolutionary stagnation:** The evolutionary loop fails to improve upon best‑of‑N; e.g., if DABS scores do not increase with depth.

### First 3 experiments
1. **Sanity check with known format biases:** Replicate Section 3.1: run the pipeline on a broad prompt mixture and a narrow “how‑to” dataset to recover biases like bold, lists, and exclamations. Verify results align with prior work.
2. **End‑to‑end run on a single topic:** Choose a topic (e.g., “political opinions”), execute the full pipeline, and inspect the evolution of a discovered attribute (e.g., triple spaces) as in Table 2. Examine counterfactual pairs to confirm minimality.
3. **Configuration comparison:** Implement the three depth/branch settings from Section 3.3 (best‑of‑N, depth 3/branch 8, depth 5/branch 4). Compare outputs via the visualization scatter plot and DABS metric to confirm evolutionary benefits.

## Limitations
- Exact prompts and implementations (clustering, Pareto selection) are undisclosed, hindering exact replication.
- Rewriter independence is weak due to potential correlation, possibly inflating false positives.
- Synthetic prompt distribution may not reflect real-world usage, and hypothesis generation misses attributes with extreme prevalence.

## Confidence
- Novel bias discovery: Medium
- Evolutionary search advantage: Medium
- Validation robustness: Medium

## Next Checks
1. Conduct human evaluation on a random sample of counterfactual pairs to verify minimal edits and absence of confounding factors (target >90% agreement with minimality criterion).
2. Run evolutionary search with alternative mutation LLMs (e.g., GPT-4o, Claude-3.5-Sonnet) and measure overlap and diversity of discovered biases against the original pipeline.
3. Quantify inter-rewriter correlation of bias scores (e.g., intraclass correlation); if high, re-analyze using mixed-effects models and report adjusted p-values.
