# EnterpriseOps-Gym: Environments and Evaluations for Stateful Agentic Planning and Tool Use in Enterprise Settings

## Quick Facts
- **arXiv ID:** 2603.13594  
- **Source URL:** https://arxiv.org/abs/2603.13594  
- **Reference count:** 40  
- **Primary result:** Frontier LLM agents achieve at most 37.4% task success on enterprise workflows, with strategic reasoning identified as the primary bottleneck.

## Executive Summary
EnterpriseOps-Gym introduces a rigorous benchmark for evaluating LLM agents in enterprise environments. The benchmark features a containerized sandbox with 164 relational tables and 512 tools across 1,150 expert-curated tasks spanning eight mission-critical domains (e.g., ITSM, HR, CRM). Evaluation of 14 frontier models reveals low task success: the top performer (Claude Opus 4.5) completes only 37.4% of tasks, dropping to 28.5% on policy-intensive ITSM workflows. The core finding is that long-horizon, constraint-aware planning is the dominant limitation: providing human-authored oracle plans boosts performance by 14–35 percentage points. Additionally, agents fail to safely refuse infeasible tasks (best refusal rate 53.9%), posing risks for autonomous deployment. The work demonstrates that current agents are not ready for enterprise operation and underscores the need for advances in strategic reasoning and policy adherence.

## Method Summary
The benchmark supplies a Docker-based sandbox simulating enterprise data and tools. Each task starts with a fresh database state, an instruction, and system policies. Agents operate in a ReAct loop: they observe the current state (via database queries and tool results), reason, and invoke one of 512 available tools under an oracle retrieval assumption (perfect tool selection). The loop continues until the agent declares completion or a step limit is reached. Final states are assessed by hand-written SQL verifiers that evaluate task completion, integrity constraints, permission/process compliance, and side effects. The benchmark includes 30 infeasible tasks to measure safe refusal. Evaluation aggregates pass@1 across multiple runs.

## Key Results
- Top model (Claude Opus 4.5) achieves only 37.4% overall task success; performance falls to 28.5% on policy-heavy ITSM workflows.
- Human-authored oracle plans improve performance by 14–35 percentage points, identifying strategic reasoning as the primary bottleneck.
- Agents fail to safely refuse infeasible tasks: best refusal rate is 53.9%, indicating significant safety risks.

## Why This Works (Mechanism)

**Mechanism 1: Long-horizon planning is the dominant limitation.**  
Agents struggle to generate effective plans that satisfy dense constraints and prerequisites, not due to tool execution or retrieval. The benchmark decouples planning by providing human-authored oracle plans, which yield large gains (14–35 pp). Adding distractor tools does not meaningfully hurt performance, ruling out retrieval as the bottleneck. Evidence: Section 4.4 reports the oracle plan improvement and distractor test; the abstract states "Strategic reasoning is identified as the primary bottleneck."

**Mechanism 2: Policy adherence is a major failure mode.**  
Agents violate multi-tiered policies (e.g., permission and process rules) because they do not incorporate policy constraints into planning. Policies govern permissible parameters, state transitions, and side effects. The benchmark embeds policies in system prompts and verifies compliance via SQL. Agents score lowest on policy compliance (e.g., ITSM 30.0% vs. task completion 53.7%). Evidence: Abstract notes performance drop on policy-heavy ITSM; Section 4 highlights Permission/Process Compliance as the weakest area; Table 7 shows compliance scores.

**Mechanism 3: Inability to safely refuse infeasible tasks.**  
Agents cannot reliably detect tasks that are infeasible due to policy breaches, resource constraints, or missing tools. The 30 infeasible tasks require compound constraint evaluation and clean abstention. The best model refuses only 53.9% of them; attempts often produce side effects. Evidence: Abstract reports the refusal rate; Section 4.3 details refusal behavior; qualitative analysis shows agents proceed when they should abstain.

## Architecture Onboarding

- **Component map** (plain text relationships):  
  Harness -> Tasks (1150 curated tasks)  
  Harness -> Sandbox (Docker: 164 tables, 512 tools)  
  Agent -> Tools (via API)  
  Sandbox -> Agent (observations)  
  Harness -> Verifiers (SQL scripts)  
  Verifiers -> Metrics  

- **Critical path**:  
  1. Harness initializes a fresh database instance for the task.  
  2. Harness provides agent with system prompt (policies) and user instruction.  
  3. Agent iteratively selects tools and arguments; sandbox executes and returns observations.  
  4. Loop repeats until agent declares completion or step limit.  
  5. Harness runs all SQL verifiers on the final database state.  
  6. Harness aggregates pass/fail results and records metrics.  
  7. Process repeats across tasks and models.

- **Design tradeoffs**:  
  - Realism vs. scalability: 164 tables and dense foreign keys increase ecological validity but slow simulation and complicate debugging.  
  - Policy coverage vs. clarity: More policies create richer constraints but risk ambiguity in natural language specifications.  
  - Oracle tools vs. retrieval: Perfect tool retrieval isolates planning but ignores real-world retrieval noise.  
  - Single-agent vs. multi-agent: Decomposition attempts were harmful due to sequential dependencies, suggesting some tasks resist parallelization.

- **Failure signatures** (recurring patterns):  
  - Missing prerequisite lookup: Creating records without first querying necessary foreign keys.  
  - Cascading state propagation failures: Not triggering follow-up actions mandated by policies.  
  - Incorrect ID resolution: Passing unverified identifiers instead of resolving via prior lookups.  
  - Premature completion hallucination: Declaring task completion before required steps.

- **First 3 experiments**:  
  1. Baseline replication: Run Claude Opus 4.5 on a stratified sample (e.g., 50 tasks across domains) to confirm the reported ~37% success rate.  
  2. Oracle plan ablation: Provide human-authored reference plans to the same agent; measure performance improvement (expected 14–35 pp) to isolate planning gap.  
  3. Distractor tool test: Augment the oracle toolset with 5–15 irrelevant tools; measure performance change; expect minimal degradation, confirming tool retrieval is not the bottleneck.

## Open Questions the Paper Calls Out
1. **Constraint-aware planning generation** – How can agents generate plans that explicitly reason over policy constraints, side-effect dependencies, and prerequisite structures? The paper identifies this as the highest-leverage direction; human-authored plans yield 14–35 pp gains while current models fall short. Unresolved because planning is the primary bottleneck and models violate permission/process compliance. Evidence of resolution: an agent with a dedicated planning module achieves ≥15-point absolute improvement on complex domains without increasing side effects.

2. **Long-horizon state management** – How can agents maintain a coherent world state over many tool calls to prevent error accumulation? All models show a 15–20% drop from 4-step to 16-step tasks, with increased integrity constraint failures. Unresolved because state coherence degrades with horizon length. Evidence of resolution: a state-tracking extension keeps pass@1 within 5% of the 4-step baseline on 16-step tasks and halves foreign-key violation rates.

3. **Safe refusal and escalation** – How can agents robustly detect infeasible or policy-violating requests and abstain cleanly? The best model refuses only 53.9% of 30 infeasible tasks, and attempts produce side effects. Unresolved because current refusal rates are insufficient for unsupervised deployment. Evidence of resolution: a refusal mechanism identifies >90% of infeasible cases while guaranteeing zero side effects on the provided set and generalizing to new infeasible scenarios.

## Limitations
- The planning bottleneck evidence relies on oracle tool retrieval; real-world retrieval noise may shift the primary constraint.
- Policy adherence evaluations may be inflated by natural language ambiguity; performance under formalized policies is unknown.
- Safe refusal metrics do not assess severity of side effects when refusal fails; current rates indicate deployment risk.

## Confidence
- Planning is the primary bottleneck: **High confidence** (strong evidence from oracle plan gains and distractor controls).  
- Policy adherence is a major failure mode: **Medium confidence** (clear gaps but potential ambiguity in policy specification).  
- Agents cannot reliably refuse infeasible tasks: **Low confidence** (refusal rates low but side-effect severity not fully measured).
