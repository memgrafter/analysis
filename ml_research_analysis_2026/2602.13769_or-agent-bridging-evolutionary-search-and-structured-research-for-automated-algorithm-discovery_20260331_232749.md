# OR-Agent: Bridging Evolutionary Search and Structured Research for Automated Algorithm Discovery
## Quick Facts
- **arXiv ID**: 2602.13769  
- **Source URL**: https://arxiv.org/abs/2602.13769  
- **Reference count**: 40  
- **Primary result**: OR-Agent achieves an average normalized score of 0.924 on 12 classical OR benchmarks, far exceeding prior automated discovery methods.

## Executive Summary
OR-Agent introduces a multi-agent framework that combines evolutionary search with a structured, tree-based research process for automated algorithm discovery. It organizes hypotheses as a dynamic tree, uses coordinated idea generation to reduce redundancy, and employs an Experiment Agent with callbacks for rich environmental diagnostics. A hierarchical reflection system provides multi-timescale feedback: short-term verbal gradients, long-term verbal momentum, and memory compression as semantic weight decay. Evaluated on 12 combinatorial optimization benchmarks and a SUMO cooperative driving simulation, OR-Agent substantially outperforms baselines, achieving a normalized score of 0.924 on average and dramatic improvements in the driving task. The work highlights open directions such as multimodal integration, advanced tree traversal, and external knowledge retrieval.

## Method Summary
The system orchestrates several LLM-driven agents within a fixed computational budget. A Lead Agent selects promising nodes from a Research Tree. Spawning multiple Idea Agents, it generates diverse child hypotheses in parallel while sharing context to avoid redundancy. The Code Agent then implements each child as executable code. The Experiment Agent runs the code in the target environment (e.g., OR benchmark or SUMO), invoking callbacks to gather detailed diagnostics beyond scalar scores. Feedback flows into a hierarchical reflection system: short-term reflections act as immediate verbal gradients; these accumulate into long-term reflections that provide strategic momentum; and memory compression periodically summarizes long-term content to prevent overload. Reflections inform subsequent generation steps, closing the loop. The framework uses Qwen3 for OR tasks and DeepSeek V3.2 for driving, storing all evaluated solutions in a database to enable evolutionary selection and reuse.

## Key Results
- OR-Agent attains an average normalized score of **0.924** across 12 classical operations research benchmarks, far surpassing FunSearch (0.323) and ReEvo (0.492).  
- In a cooperative driving simulation, it scores **48.00** under constrained runtime versus the best baseline’s 16.10; after extended running it reaches **90.24**, exceeding SUMO’s default 85.25.  
- Ablations demonstrate that a balanced tree depth (standard configuration) and no compression of long-term reflections yield optimal performance.

## Why This Works (Mechanism)
OR-Agent succeeds by marrying the exploratory breadth of evolutionary search with the directed rigor of a structured research workflow. The tree representation naturally encodes algorithmic lineages, enabling selective expansion while preserving ancestry for backtracking. Coordinated idea generation leverages parallel thought to produce diverse extensions from a common parent, increasing coverage without redundant proposals. The Experiment Agent’s callback mechanism enriches evaluation with environment-specific diagnostics, which feed into the reflection system to produce nuanced, verbal feedback. Hierarchical reflections provide a multi-timescale learning signal: short-term reflections offer immediate corrections (gradients), long-term reflections maintain strategic momentum, and memory compression prevents context overflow through semantic weight decay. This iterative loop of generation, evaluation, and reflection, powered by large language models, steadily discovers high-performing algorithms with minimal human intervention.

## Foundational Learning
- **Tree-Structured Hypothesis Organization**  
  *Why needed*: Offers a scaffold for systematic exploration and evolutionary selection, balancing breadth and depth while preserving ancestry.  
  *Quick check*: How would adding a child node affect future parent selection? What risks arise from an excessively deep tree?

- **Coordinated Idea Generation**  
  *Why needed*: Exploits parallel ideation to explore multiple promising continuations from a parent while avoiding redundant proposals, increasing effective branching.  
  *Quick check*: If two Idea Agents receive the same parent, what ensures their outputs differ? Why share context among them?

- **Hierarchical Reflections**  
  *Why needed*: Enables credit assignment across timescales—short-term for immediate fixes, long-term for strategic direction, and memory compression to avoid overload.  
  *Quick check*: Distinguish the roles of short-term and long-term reflections. What could go wrong if memory compression is too aggressive?

- **Experiment Agent with Callbacks**  
  *Why needed*: Closes the loop between code and environment, collecting rich diagnostics (e.g., simulation states) that feed back into reflections for domain-specific reasoning.  
  *Quick check*: Design a callback that records a time-series metric; how would this data improve future reflections?

- **Evolutionary Selection via Lead Agent**  
  *Why needed*: Focuses computational resources on nodes with demonstrated potential, mimicking natural selection to drive the search.  
  *Quick check*: What exploration issues might arise from purely greedy parent selection? How can the system maintain diversity?

## Architecture Onboarding
**Component Map**  
Lead Agent → Idea Agents → Code Agent → Experiment Agent → Environment  
Environment → Feedback → Short-term Reflection → Long-term Reflection → Memory Compression → Reflection Store  
Reflection Store → Idea Agents & Code Agent  
OR Agent (orchestrates overall workflow)  
Research Tree (stores nodes with code, metrics, reflections)

**Critical Path**  
1. Lead Agent selects a parent node from the Research Tree.  
2. Idea Agents generate multiple child hypotheses in parallel.  
3. Code Agent implements each child as executable code.  
4. Experiment Agent runs the code, invoking callbacks to gather diagnostics.  
5. Results feed into reflections: short-term (immediate verbal gradients) → long-term (accumulated momentum) → memory compression.  
6. Updated reflections stored and used to inform future generations.  
7. Successful children added to the tree; loop repeats.

**Design Tradeoffs**  
- *Tree depth*: Deeper trees allow refinement but increase cost and risk over-specialization.  
- *Children per node*: More children boost exploration breadth but dilute context and limit depth.  
- *Memory compression*: Aggressive compression loses strategic insights; mild compression may retain noise.  
- *Parent selection*: Greedy selection risks premature convergence; bandit methods could help.  
- *LLM dependence*: High-quality generations but introduce non-determinism, cost, and rate limits.

**Failure Signatures**  
- Repeated LLM API errors → misconfigured credentials or quota exhaustion.  
- Zero/NaN scores → environment mis‑setup (e.g., missing SUMO) or callback mismatch.  
- Shallow tree growth → overly strict selection or generation failure.  
- Performance drop with depth → harmful memory compression or lost momentum.  
- High idea redundancy → ineffective coordination among Idea Agents.

## Open Questions the Paper Calls Out
1. **Multimodal integration** – How can OR-Agent incorporate multi‑modal signals (e.g., images) to enhance diagnostics and reasoning?  
   *Basis*: The conclusion explicitly states this as a key open direction.  
   *Why unresolved*: Current reliance on text and code may miss failure modes not captured by metrics.  
   *Resolving evidence*: Implement visualization callbacks in robotics/autonomous driving and compare diagnostic accuracy/solution quality to text‑only baseline.

2. **Optimal number of child ideas** – What is the optimal number of children per node to balance diversity and elaboration?  
   *Basis*: Section B.3 says determining an optimal granularity a priori remains an open challenge.  
   *Why unresolved*: Too many children strain context and reduce depth; too few limit exploration.  
   *Resolving evidence*: Controlled experiments varying child count across benchmarks; plot diversification vs. performance trade‑offs.

3. **Moderate memory compression degradation** – Why does compressing long‑term reflections to moderate length (e.g., 400 words) degrade performance relative to no or aggressive compression?  
   *Basis*: Ablation results show this pattern, and the paper states the exact mechanisms warrant investigation.  
   *Why unresolved*: Unclear whether moderate compression loses critical high‑level signals or introduces noise.  
   *Resolving evidence*: Analyze retained/dropped content at different compression levels; correlate with downstream improvement; test selective preservation.

4. **Advanced tree traversal** – How can traversal strategies beyond greedy selection improve exploration‑exploitation balance in long‑running rounds?  
   *Basis*: The paper suggests PUCB‑style exploration as compatible but unexplored.  
   *Why unresolved*: Greedy selection may prematurely converge to suboptimal branches.  
   *Resolving evidence*: Implement PUCB/UCT variants; evaluate on diverse benchmarks; measure solution space coverage and final scores.

5. **Online knowledge retrieval** – Can OR‑Agent integrate literature search to accelerate ideation and improve solution quality?  
   *Basis*: The conclusion identifies integrating online knowledge retrieval as a key open direction.  
   *Why unresolved*: Current ideation depends only on internal memory; external scientific knowledge might inspire novel structures.  
   *Resolving evidence*: Attach a retrieval‑augmented module querying arXiv/Google Scholar during generation; test on benchmarks requiring up‑to‑date techniques; compare novelty and performance.

## Limitations
- **Reproducibility gaps**: Missing random seeds, exact LLM call/evaluation budgets, and hardware specifications hinder exact replication of reported scores.
- **External dependencies**: Reliance on specific LLM APIs (Qwen3, DeepSeek) introduces non‑determinism, cost, and rate‑limit issues.
- **Environment complexity**: Driving simulation requires SUMO; callback interface mismatches can lead to silent failures.
- **Theoretical understanding**: The precise reasons behind optimal tree depth and memory compression effects remain unclear, limiting generalizability.
