# Neuro-Symbolic Financial Reasoning via Deterministic Fact Ledgers and Adversarial Low-Latency Hallucination Detector

## Quick Facts
- **arXiv**: 2603.04663  
- **Source URL**: https://arxiv.org/abs/2603.04663  
- **Reference count**: 6  
- **Primary result**: VeNRA reduces systemic hallucination rates to 1.2%, achieves a 93% flip rate on adversarial pairs, and delivers a 28.7× latency speedup (142 ms vs. 4.1 s).

## Executive Summary
Standard RAG systems fail in financial question answering due to LLM arithmetic errors and vector retrieval conflating opposing financial terms (e.g., Net Income vs Net Sales). This paper introduces VeNRA, a neuro‑symbolic framework that replaces probabilistic text retrieval with deterministic variable retrieval through a Universal Fact Ledger (UFL) and Double‑Lock Grounding. Arithmetic is offloaded to deterministic Python execution, eliminating calculation hallucinations. A lightweight 3B‑parameter Sentinel model, trained on adversarially simulated financial errors, audits reasoning traces with high accuracy and low latency. Evaluations show a systemic hallucination rate of 1.2%, a 93.0% flip rate on adversarial pairs, and a 28.7× latency improvement over 70B+ models, enabling efficient high‑assurance financial reasoning.

## Method Summary
VeNRA’s pipeline comprises deterministic ingestion, retrieval, execution, and auditing. Financial documents are parsed into the UFL via a trailing‑buffer chunking algorithm and Pandas table extraction; each fact is anchored with a verbatim quote and validated by Double‑Lock Grounding (character offset matching and semantic token overlap). For a given query, the Navigator issues a RetrievalPlan; the DualRetriever fetches UFL rows and raw chunks through a Lexical Gate. The Architect LLM writes Python code that references only grounded UFL variables; this code executes in isolation, guaranteeing arithmetic correctness. Finally, the Sentinel—a 3B model trained on VeNRA‑Data (adversarially mutated traces) using a custom Micro‑Chunking loss—audits the entire trace with a single‑token budget, flagging hallucinations. The system operates with strict typing and fallback mechanisms to maintain robustness.

## Key Results
- Systemic hallucination rate compressed to **1.2%** by replacing probabilistic retrieval with deterministic variables and code execution.
- **Sentinel** achieves a **93.0%** flip rate on adversarial pairs, outperforming 70B+ models despite a 3B parameter size.
- Latency speedup of **28.7×** (142 ms vs. 4.1 s) compared to prior state‑of‑the‑art.

## Why This Works (Mechanism)
VeNRA’s effectiveness stems from three synergistic mechanisms. First, deterministic variable retrieval via the UFL and Double‑Lock Grounding eliminates vector‑based conflation of financial terms, ensuring precise fact grounding (internal UFL Bleed ≤1, EXACT alignment ∼74.5%). Second, program‑aided execution forces the LLM to generate Python code that operates on grounded variables, transferring arithmetic to an interpreter that guarantees correctness. Third, the Sentinel’s adversarial training on ecological errors (Logic Code Lie, Numeric Neighbor Trap, Time Warp, Semantic Drift) equips it to detect subtle hallucinations with high accuracy; Micro‑Chunking loss stabilizes extreme gradient weighting, enabling a compact 3B model to achieve 93% flip rates and a 142 ms single‑token inference time.

## Architecture Onboarding
- **Component map**:  
  Input → Query Navigator (SLM) → DualRetriever (Lexical Gate + Vector store) → Context Assembler → Architect LLM (PAL) → Python Executor → Sentinel (3B SLM) → Synthesizer → Output  
  Supporting: Ingestion pipeline (PDF → UFL), Double‑Lock Grounding, Micro‑Chunking Trainer.  
- **Critical path**:  
  1. Receive user query.  
  2. Navigator outputs RetrievalPlan (UFL filters + vector hypothesis).  
  3. DualRetriever fetches UFL rows and raw chunks; Lexical Gate filters candidates.  
  4. Context Assembler builds fused Markdown context.  
  5. Architect generates Python program referencing UFL variables.  
  6. Python executor computes result.  
  7. Sentinel audits (query, context, trace, result) in a single forward pass.  
  8. If verdict SUPPORTED, Synthesizer produces final answer; else reject/fallback.  
  9. Return answer.  
- **Design tradeoffs**:  
  - **Precision vs. Recall**: Double‑Lock and Lexical Gate improve precision but may reduce recall for borderline facts.  
  - **Latency vs. Accuracy**: Sentinel’s single‑token design yields 28× speedup at the cost of some nuance; mitigated by Logit Gap fallback.  
  - **Determinism vs. Coverage**: Strict typing ensures grounding but can miss non‑standard metrics.  
  - **Model size**: 3B sentinel enables edge deployment; training on adversarial data bridges gap to 70B+ models but may underfit rare error types.  
- **Failure signatures**:  
  - High UFL rejection (>40%): parsing issues or aggressive Lock 2.  
  - Sentinel spamming UNFOUNDED on clean data (low TPRclean): garbage bin effect.  
  - Low Flip Rate (<80%) on adversarial pairs: missing attack vectors or weighting issues.  
  - Context overflow (>5 chunks): truncation; check top‑k selection.  
  - LexicalGate false negatives: valid candidates dropped; adjust τlex.  
  - Frequent code execution errors: Architect misunderstanding UFL schema.  
  - Consistent Logit Gap <0.15: over‑calibration; adjust temperature/training.  
- **First 3 experiments**:  
  1. **Pipeline evaluation**: 2×2 factorial comparing (vector + CoT) vs (DualRetriever + PAL) on FinanceBench/FinQA/TAT‑QA; measure EM and hallucination rate. Expected VeNRA: ∼49% EM, 1.2% hallucination.  
  2. **Ingestion purity**: On 899 chunks, report Double‑Lock rejection (~30%), alignment tier distribution (EXACT ∼74.5%), and UFL Bleed (≤1).  
  3. **Sentinel forensic auditing**: Evaluate test set (n=812) for Composite Score M, Global Flip Rate, Recallnat, TPRclean; benchmark latency; expected M≈0.63, FR≈93%, latency ~142 ms.

## Open Questions the Paper Calls Out
1. **Universal Fact Ledger recursion**: How can the UFL be extended to capture recursive multi‑step relationships (e.g., “supplier of a supplier”) while preserving deterministic query efficiency and strict typing? The current flat table representation fails to support such multi‑hop queries, limiting supply‑chain analysis.  
2. **Referential integrity across chunks**: How to preserve footnotes and cross‑references (e.g., “See Note 12”) that span disjoint document chunks, so qualitative context is not severed? The trailing‑buffer chunking and Navigator’s lexical gate operate locally and do not maintain a document‑level reference graph.  
3. **Adaptive lexical gating**: Can Lexical Pre‑Filter and Lexical Gate thresholds (τ_lex=0.30) be dynamically adapted to avoid discarding non‑standard but valid financial metrics (e.g., custom non‑GAAP measures) while still preventing vector conflation? Fixed thresholds may over‑filter unconventional terminologies, reducing recall.  
4. **Cross‑domain generalization**: To what extent does the adversarial simulation methodology (VeNRA‑Data) and resulting Sentinel generalize to other high‑stakes domains (e.g., medical, legal) that have distinct error modes and ontologies? The four sabotage types are tailored to finance and may not transfer.

## Limitations
- The Saboteur Engine and Sentinel training hyperparameters are undisclosed, hindering full replication and simulation fidelity assessment.  
- Fixed thresholds in Double‑Lock Grounding (τsem≥0.30) and Lexical Gate (τlex≥0.30) may over‑filter, reducing recall for unconventional financial facts.  
- The fallback to raw‑text synthesis when code execution fails could reintroduce hallucinations; its impact remains unquantified.
