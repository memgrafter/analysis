# PVminerLLM: Structured Extraction of Patient Voice from Patient-Generated Text using Large Language Models

## Quick Facts
- **arXiv ID:** 2603.05776
- **Source URL:** https://arxiv.org/abs/2603.05776
- **Reference count:** 40
- **Primary result:** PVminerLLM, a fine-tuned LLM using QLoRA, achieves up to 83.82% F1 for Code prediction, 80.74% F1 for Sub-code prediction, and 87.03% F1 for Span extraction on a novel hierarchical patient voice benchmark, substantially outperforming prompt-based baselines.

## Executive Summary
Patient-generated text, such as secure messages and survey responses, contains rich social and experiential signals—the "patient voice"—but this information is rarely available in structured form, limiting its utility in outcomes research and quality improvement. This paper introduces PVminer, a new benchmark for hierarchically labeling patient voice with Codes, Sub-codes, and supporting evidence Spans, and PVminerLLM, a supervised fine-tuned large language model adapted via QLoRA. Trained on a diverse corpus, PVminerLLM demonstrates strong performance across all hierarchical tasks, with even small models (1.5B–3B parameters) proving effective, and supervised fine-tuning successfully closing the precision-recall gap inherent in prompting approaches.

## Method Summary
The authors developed PVminer, a benchmark dataset with a hierarchical annotation schema (Code → Sub-code → evidence Span) applied to patient-generated text from secure messages and survey responses. For modeling, they created PVminerLLM by applying supervised fine-tuning using QLoRA adapters to a base LLM. This efficient parameter-efficient fine-tuning approach adapts the model to the multi-task structured extraction problem without full model retraining, leveraging the diverse corpus to learn the labeling hierarchy and span boundaries.

## Key Results
- **Code prediction:** Up to 83.82% F1.
- **Sub-code prediction:** Up to 80.74% F1.
- **Span extraction:** Up to 87.03% F1.
- Supervised fine-tuning eliminates the precision-recall trade-off seen in prompt-based LLM inference.
- Models with 1.5B–3B parameters achieve performance comparable to larger models, highlighting efficiency.

## Why This Works (Mechanism)
Supervised fine-tuning with QLoRA adapters enables the base LLM to specialize in the hierarchical extraction task without catastrophic forgetting or prohibitive computational cost. The adapters learn task-specific representations for classifying Codes/Sub-codes and identifying evidence Spans, while the fixed base model retains general language understanding. This approach stabilizes predictions, improves consistency across the hierarchy, and closes the precision-recall gap because the model is directly optimized on labeled examples rather than relying on indirect instruction following.

## Foundational Learning
1. **Hierarchical Labeling for Patient Voice**
   - *Why needed:* Patient expressions contain multi-level signals (general themes → specific issues) requiring nested annotation for rich extraction.
   - *Quick check:* Measure inter-annotator agreement at each hierarchy level (Code, Sub-code) to ensure schema clarity.
2. **QLoRA (Quantized Low-Rank Adaptation)**
   - *Why needed:* Enables efficient fine-tuning of large LLMs with limited resources by updating small adapter layers while keeping the base model quantized and frozen.
   - *Quick check:* Verify adapter rank and quantization settings; confirm trainable parameter count is << total parameters.
3. **Patient-Generated Text as Data Source**
   - *Why needed:* Provides unfiltered, experiential insights not captured in clinical notes, crucial for patient-centered outcomes.
   - *Quick check:* Audit data for de-identification, demographic diversity, and text quality (e.g., spelling, informal language).
4. **Span Extraction for Evidence grounding**
   - *Why needed:* Links structured labels back to exact text excerpts, enabling transparency and auditability in research.
   - *Quick check:* Evaluate span boundary precision/recall against a gold subset; check for partial matches.
5. **Secure Messages and Survey Responses**
   - *Why needed:* Represent real-world patient communication channels with varying structure and formality.
   - *Quick check:* Analyze text length distribution, topic coverage, and source balance to avoid modality bias.

## Architecture Onboarding
**Component Map:**  
Input Text -> PVminerLLM (Base LLM + QLoRA Adapters) -> Hierarchical Output (Code, Sub-code, Evidence Spans)

**Critical Path:** Raw patient text is tokenized and fed into the base LLM; QLoRA adapters modulate hidden representations; the model jointly predicts Code, Sub-code, and span start/end positions in a hierarchical decoding step.

**Design Tradeoffs:**  
- *Model size vs. efficiency:* Smaller models (1.5B–3B) were chosen for deployability, potentially sacrificing some nuance captured by larger models.  
- *Hierarchical joint prediction:* A single forward pass predicts all labels versus separate models per level; this increases complexity but enforces consistency.  
- *Fixed base LLM vs. full fine-tuning:* QLoRA preserves general knowledge and reduces overfitting risk but may limit adaptation depth.

**Failure Signatures:**  
- Significant F1 drop on rare Codes/Sub-codes indicates under-representation in training data.  
- Inconsistent span boundaries (e.g., off-by-token errors) suggest weak localization learning.  
- High precision but low recall (or vice versa) for specific labels may reveal bias in adapter learning.

**First Experiments:**  
1. Run PVminerLLM on a held-out 5% sample of the training corpus to compare performance against in-distribution results, checking for overfitting.  
2. Manually inspect 50 random predictions where span extraction failed to identify common error patterns (e.g., boundary mismatches, context confusion).  
3. Perform an ablation study by disabling QLoRA adapters and evaluating zero-shot base model performance to quantify adaptation gain.

## Limitations
- **Reproducibility:** No code, data, or model release; independent verification impossible.  
- **Benchmark validity:** PVminer is novel but lacks external validation; annotation quality and potential annotator biases are unknown.  
- **Generalization:** Training restricted to a single source (secure messages + surveys); performance on other demographics, languages, or text types (e.g., social media) is untested.

## Confidence
- **Outperformance vs. prompt baselines:** Medium – relies on a single dataset; prompt engineering details unclear.  
- **Small-model efficacy (1.5B–3B):** Medium – no efficiency metrics or fair comparison to larger fine-tuned models.  
- **Precision-recall gap closure with fine-tuning:** Medium – expected phenomenon but magnitude task-specific; no significance tests provided.
