# The Token Games: Evaluating Language Model Reasoning with Puzzle Duels
## Quick Facts
- **arXiv ID**: 2602.17831
- **Source URL**: https://arxiv.org/abs/2602.17831
- **Reference count**: 15
- **Primary result**: The Token Games (TTG) offers a scalable, automated evaluation framework for LLM reasoning via adversarial programming puzzles, yielding Elo ratings that strongly correlate (ρ=0.75) with expert benchmarks.

## Executive Summary
The paper tackles the growing need for robust, automated evaluation of large language models (LLMs) as static benchmarks risk saturation and contamination. It introduces The Token Games (TTG), an adversarial duel framework where models alternately generate and solve Python boolean function puzzles. Solutions are verified by code execution, and Elo ratings are derived from pairwise outcomes. Evaluation of ten frontier models shows that TTG solver rankings correlate well with established benchmarks (e.g., Humanity's Last Exam). Notably, generating valid, challenging puzzles proved much harder than solving them, suggesting TTG captures distinct skills such as creativity and self-evaluation. The results demonstrate TTG as a complementary, scalable benchmark for LLM reasoning.

## Method Summary
TTG orchestrates a series of 10-round duels between two models. In each round, one model acts as proposer, generating a Python boolean function and accompanying sample tests. The generated puzzle is automatically validated by executing the sample tests; invalid submissions incur a penalty and the round ends with a win for the solver by default. If valid, the other model becomes the solver, receiving the puzzle description and attempting to produce a correct implementation. The solver’s code is executed on the full test suite (including hidden tests). The solver wins if its solution passes all tests; otherwise, the proposer wins. After each round, Elo ratings are updated based on the outcome. This fully automated pipeline allows thousands of duels to be run with minimal human intervention.

## Key Results
- Solver performance in TTG correlates strongly with expert benchmarks: Solver Win Rate ρ=0.75 with Humanity's Last Exam.
- Proposer success is much lower: best proposer win rate was 43.3% (versus 100% solver win rate when valid), highlighting the difficulty of generating high-quality puzzles.
- Across duel turns, puzzle difficulty increases: solve rates drop by ~2.5% per round for GPT-5.2 and ~1% for GPT-5 mini, indicating proposers adapt to opponent strength.

## Why This Works (Mechanism)
TTG succeeds because it replaces human-curated tasks with an automated, adversarial process that generates an effectively unbounded supply of reasoning problems. The use of code execution provides a deterministic ground truth, eliminating ambiguity. The duel format forces models to both solve and create, testing a broader spectrum of reasoning abilities, including creativity, self-evaluation, and strategic thinking. Elo ratings aggregate outcomes over many interactions, yielding stable, relative skill estimates that correlate with independent benchmarks. This combination of automation, ground-truth verification, and adversarial dynamics makes TTG a scalable and robust evaluation framework.

## Foundational Learning
**Elo Rating System**  
**Why needed**: Converts pairwise win/loss outcomes into a single skill metric that updates dynamically as models compete.  
**Quick check**: After many simulated duels between a strong and a weak model, does the strong model’s Elo increase and the weak’s decrease, converging to stable values?

**Automated Code Execution Verification**  
**Why needed**: Provides objective, scalable evaluation of puzzle solutions without human grading.  
**Quick check**: Are all solver submissions executed in a sandbox with comprehensive test suites, and do results reliably reflect correctness?

**Adversarial Puzzle Generation**  
**Why needed**: Challenges models to produce novel, non-trivial problems, probing generative and evaluative capabilities beyond standard solving.  
**Quick check**: Do generated puzzles exhibit diverse structures and include edge cases that cause typical solvers to fail?

**Self-Consistency & Iterative Refinement**  
**Why needed**: Potential to improve puzzle validity and difficulty by enabling models to verify and revise their own outputs.  
**Quick check**: If a model is prompted to run its generated puzzle on sample tests before submission, does the validity rate increase?

**Difficulty Calibration**  
**Why needed**: Maintains an appropriate challenge level so duels remain informative and not trivially easy or impossibly hard.  
**Quick check**: Is there a feedback loop (e.g., solve rate) that can inform proposers about the hardness of their puzzles?

## Architecture Onboarding
**Component Map (plain text)**  
Duel Pair Selector -> Turn Controller -> Proposer Module -> Puzzle Generator -> Puzzle Validator -> (if valid) -> Solver Module -> Solution Generator -> Solution Executor -> Outcome Scorer -> Elo Calculator -> Leaderboard

**Critical Path**  
1. Select two models from the pool for a duel.  
2. Initialize per-duel state (round count, Elo).  
3. Repeat for 10 rounds:  
   a. Alternate proposer/solver roles.  
   b. Proposer generates puzzle; Puzzle Validator checks sample tests.  
   c. If valid, solver attempts solution; Solution Executor runs full test suite.  
   d. Outcome Scorer records win/loss.  
   e. Elo Calculator updates ratings.  
4. Update global Leaderboard with final Elo changes.

**Design Tradeoffs**  
- *Automation vs. Expressivity*: Restricting puzzles to executable Python boolean functions enables automation but excludes natural-language or multi-modal reasoning tasks.  
- *Validity Checking*: Using only proposer‑provided sample tests leaves hidden tests unverified, which is necessary to prevent overfitting but risks unsound puzzles.  
- *Difficulty Calibration*: Relying on solver success as a difficulty proxy intertwines puzzle hardness with opponent skill, making independent calibration challenging.  
- *Fixed Duel Length*: Ten rounds balance cost and rating stability; longer duels improve discrimination but increase compute.

**Failure Signatures**  
- High proposer penalty rate (>50%) indicates systematic failure to generate valid puzzles.  
- Solver success rate near 0% or 100% suggests puzzles are too hard or too easy, respectively, leading to uninformative outcomes.  
- Elo ratings that do not change after many duels point to insufficient model differentiation or flawed matchmaking.  
- Repeated sandbox escapes or execution errors reveal security or implementation issues.

**First Experiments**  
1. **Elo Convergence Test**: Run thousands of duels among a small set of models with known skill gaps. Verify that Elo ratings stabilize and reflect the expected ordering after sufficient matchups.  
2. **Puzzle Validity Intervention**: Measure baseline proposer validity rate. Then introduce a self‑verification step (prompt the proposer to test its puzzle on the sample tests before submission) and compare validity rates to assess improvement.  
3. **Difficulty Scaling Analysis**: Aggregate solve rates per round across many duels. Perform regression to quantify the rate of difficulty increase (e.g., solve rate drop per round) and test whether it differs significantly between model pairs.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: What causes LLMs to frequently propose invalid or trivially solvable puzzles, and can techniques like self-consistency or iterative refinement improve proposer success?
- **Basis in paper**: [inferred] Proposers failed in 87.7% of rounds; e.g., GPT-5.2 had >97% penalties for incorrect sample solutions, indicating overconfidence or poor self-evaluation.
- **Why unresolved**: The paper does not investigate the root causes or test mitigation strategies.
- **What evidence would resolve it**: Ablation studies varying prompting (e.g., request verification steps) and measuring changes in validity and proposer win rates.

### Open Question 2
- **Question**: Does performance as a proposer in TTG predict real‑world creative skills such as generating educational problems or competitive programming challenges?
- **Basis in paper**: [explicit] The paper shows proposer win rates correlate weakly with benchmarks like HLE (ρ ≤ 0.67), suggesting distinct, unmeasured capabilities.
- **Why unresolved**: No external validation of proposer skill beyond TTG is provided; it is unclear whether these abilities transfer.
- **What evidence would resolve it**: Correlate TTG proposer metrics with independent human evaluations or performance on separate creative generation tasks (e.g., math problem design contests).

### Open Question 3
- **Question**: How does puzzle difficulty evolve over the course of a duel across a broader spectrum of models, and does increasing the number of rounds improve rating discrimination?
- **Basis in paper**: [explicit] The paper reports a decrease in solve rates by ~2.5% per turn for GPT-5.2 and ~1% for GPT-5 mini, indicating proposers ramp up difficulty.
- **Why unresolved**: It is unknown whether this pattern holds for all models and whether the fixed 10‑round duel is optimal for separating model abilities.
- **What evidence would resolve it**: Large‑scale experiments varying turn counts and opponent strengths, measuring Elo variance and stability.

### Open Question 4
- **Question**: To what extent are TTG results generalizable beyond the evaluated frontier models and the Python boolean function representation?
- **Basis in paper**: [inferred] The study included only 10 models and a single puzzle format; the authors note potential future divergence from human benchmarks as models advance.
- **Why unresolved**: Robustness of TTG as a universal benchmark remains unproven; format biases or model‑specific effects could skew rankings.
- **What evidence would resolve it**: Replicate TTG with alternative encodings (e.g., natural language, formal logic) and include a diverse set of model sizes, architectures, and training regimes.

## Limitations
- Domain restriction to Python boolean functions; may not generalize to other reasoning modalities.
- Model selection limited to 10 frontier proprietary models; performance on diverse architectures remains unknown.
- Proposer win rate (43.3% vs 100% solver) suggests a fundamental imbalance in task difficulty, possibly due to generation challenges rather than model skill.

## Confidence
- Scalability/automation of TTG: High
- Correlation with expert benchmarks: Medium
- TTG measuring distinct skills: Medium
- Increasing puzzle difficulty across turns: Medium

## Next Checks
1. **Broad model and benchmark replication**: Evaluate TTG across diverse model families (e.g., Llama, Mistral) and compute correlations with multiple established benchmarks, providing confidence intervals.  
2. **Domain transfer test**: Extend puzzles to other programming languages (JavaScript) or non‑programming reasoning tasks (logical deduction, math) to assess generalizability.  
3. **Proposer capability ablation**: Systematically vary prompting (e.g., self‑evaluation instructions) and validity checking mechanisms to determine bottlenecks in generating valid, challenging puzzles; measure impact on proposer win rate.
