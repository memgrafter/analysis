# Position: Explainable AI is Causality in Disguise
## Quick Facts
- arXiv ID: 2603.28597
- Source URL: https://arxiv.org/abs/2603.28597
- Reference count: 40
- Primary result: True structural causal model (SCM) is necessary and sufficient to answer six core XAI questions accurately, unifying XAI under causality.

## Executive Summary
The paper argues that XAI’s fragmentation arises not from a lack of methods but from the absence of a principled ground truth. It reframes all fundamental XAI queries—about data ("What?"), model ("How?"), or decisions ("Why not?")—as causal inquiries mapped onto Pearl’s Ladder of Causation. Through formal proof, it shows that a true Structural Causal Model (SCM) is both necessary and sufficient to provide accurate and complete answers to these six core questions. This establishes the SCM as the elusive ground truth, unifying XAI objectives and diagnosing failures in non-causal methods like SHAP and LIME. The work calls for advancing causal discovery and concept abstraction to approximate this ideal in practice.

## Method Summary
The proposed validation framework requires a known SCM \(M\) to generate data, upon which a black-box model \(f\) is trained. Standard XAI tools (e.g., SHAP, LIME, DiCE) are then applied to answer six core questions (Q1–Q6) on test instances. Their outputs are compared against exact, SCM-derived ground-truth answers: Q1–Q2 via observational distributions, Q3–Q4 via interventional \(do\)-calculus, and Q5–Q6 via counterfactual abduction-action-prediction. Any mismatch indicates failure. The approach assumes oracle access to the true SCM; unknowns include the precise mapping from natural-language XAI questions to unique causal queries and the impact of using an estimated SCM \(\hat{M}\) instead of the true \(M\).

## Key Results
- Theoretical proof: A true SCM is necessary and sufficient to answer Q1–Q6 accurately and completely.
- Unification: All XAI queries map onto Pearl’s ladder (observational, interventional, counterfactual).
- Diagnosis: Non-causal methods fail by conflating correlation with causation, yielding biased attributions or infeasible counterfactuals.

## Why This Works (Mechanism)
The mechanism hinges on formalizing XAI questions as causal queries with precise semantics (e.g., Q3 becomes an average treatment effect). The true SCM uniquely determines answers by encoding causal mechanisms and exogenous factors. Non-causal methods lack this structural knowledge; they rely on associational patterns that break under confounding or for counterfactuals. The proof demonstrates that only the SCM provides the necessary causal information for both correctness (necessity) and completeness (sufficiency), making it the required ground truth.

## Foundational Learning
- **Structural Causal Model (SCM)**: Encodes causal relationships via a DAG and structural equations. *Why needed*: Provides the true generative mechanism; all ground-truth answers derive from it. *Quick check*: Can all variables (including exogenous) be expressed in equations?
- **Pearl’s Ladder of Causation**: Three levels—association (seeing), intervention (doing), counterfactual (imaging). *Why needed*: Classifies causal query strength; XAI questions map to specific rungs. *Quick check*: For each Q1–Q6, identify its rung (e.g., Q3 is interventional).
- **XAI Core Questions (Q1–Q6)**: Curated set: Q1–Q2 observational, Q3–Q4 interventional, Q5–Q6 counterfactual. *Why needed*: Target set for unification proof. *Quick check*: Does each question have a clear causal interpretation?
- **Causal Query**: Formal expression like \(P(Y|do(X))\) or \(Y(x)\). *Why needed*: Enables exact computation from SCM. *Quick check*: Can natural-language questions be translated to do-calculus?
- **Ground Truth in XAI**: True causal effect from the SCM. *Why needed*: Eliminates ambiguity in explanation evaluation. *Quick check*: Is there a unique SCM-derived answer for each question?
- **Causal Abstraction**: Mapping fine-grained variables to higher-level concepts. *Why needed*: Achieves interpretability in complex models while preserving causal meaning. *Quick check*: Does abstraction preserve relations needed for Q1–Q6?

## Architecture Onboarding
Component map: True SCM (M) -> Data generation -> Training data -> Black-box model (f) -> Standard XAI tools (SHAP, LIME, DiCE) -> Explanations. Critical path: From SCM to ground-truth answers for Q1–Q6, bypassing the black box. Design tradeoffs: Oracle SCM (perfect but unavailable) vs. estimated SCM (practical but error-prone); abstraction level vs. causal fidelity. Failure signatures: (1) SHAP/LIME attributions biased by confounding (mismatch with interventional effects). (2) Counterfactuals violating structural equations (infeasible changes). (3) Drift in explanation quality when using estimated SCM. First experiments:
1. Confounded linear SCM: Train linear regression on confounded data; compute true causal effect; run SHAP; expect SHAP to reflect total association, not causal effect.
2. Counterfactual feasibility: Use DiCE on same SCM; for an instance, check if proposed counterfactual satisfies structural equations (e.g., changing X while holding Z constant).
3. Estimated SCM error: Recover SCM via NOTEARS; compute Q3–Q6; compare to true SCM ground truth; quantify fidelity loss.

## Open Questions the Paper Calls Out
1. How can we systematically discover human-interpretable concepts from deep neural networks to construct meaningful causal abstractions? *Basis*: Section 5.1 notes existing methods (e.g., TCAV) rely on predefined concepts and cannot uncover “unknown unknowns.”
2. Under what conditions can causal abstractions (e.g., grouped neural mechanisms) remain faithful to the original model's fine-grained causal structure? *Basis*: Sections 5.1 and RQ2 stress need for theoretical guarantees balancing interpretability and accuracy.
3. How can causal discovery be made scalable to high-dimensional settings (e.g., large language models) while retaining sufficient accuracy for reliable XAI? *Basis*: Section 5.1 highlights scalability as a pressing challenge; RQ3/RQ5 explore approximations.
4. How should interactive XAI systems be designed to leverage causal interventions and user feedback to iteratively refine explanations and align with stakeholder mental models? *Basis*: Section 5.2 advocates for interactive approaches; RQ6 asks how to design such systems effectively.

## Limitations
- Unclear mappings: Translation from natural-language XAI questions (e.g., Q4 about model mechanisms) to precise causal queries is ambiguous and not operationalized.
- Oracle assumption: Proofs assume perfect knowledge of true SCM; real-world settings require estimation, and error propagation is unquantified.
- Limited scope: Analysis covers only six curated questions; broader XAI objectives (fairness, safety) and stakeholder-specific queries are not addressed.

## Next Checks
1. Confounding bias replication: In linear confounded SCM \(Z \rightarrow X, Z \rightarrow Y, X \rightarrow Y\), train \(f(X)=Y\). Compute true causal effect of \(X\) on \(Y\) via \(do\)-calculus. Run SHAP; expect SHAP to return total association, not causal effect, violating Q3/Q4.
2. Counterfactual feasibility test: Generate counterfactuals for instance \((x,y)\) using DiCE. Check if proposed interventions satisfy SCM equations (e.g., changing \(X\) while keeping \(Z\) fixed). Expect violations if method ignores causal constraints.
3. Estimated SCM error propagation: Approximate true SCM from data using NOTEARS. Use \(\hat{M}\) to answer Q3–Q6; compare to true SCM ground truth. Quantify fidelity loss; test if \(\hat{M}\) meets “accurate and complete” standard.
