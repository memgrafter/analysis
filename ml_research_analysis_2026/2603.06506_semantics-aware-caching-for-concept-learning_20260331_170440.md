# Semantics-Aware Caching for Concept Learning

## Quick Facts
- **arXiv ID:** 2603.06506
- **Source URL:** https://arxiv.org/abs/2603.06506
- **Reference count:** 32
- **Primary result:** A semantics-aware cache reduces concept retrieval runtime by up to 80% for slower reasoners and overall learning by up to three orders of magnitude for refinement-based learners; LRU eviction performs best.

## Executive Summary
Class expression learning (CEL) repeatedly queries a description logic reasoner for instance sets of candidate concepts, creating a major runtime bottleneck. This paper introduces a semantics-aware caching layer that exploits description logic semantics and subsumption relationships to reuse and compute instance sets via set operations, avoiding redundant reasoner calls. Evaluated across four datasets and five reasoners (symbolic and neuro-symbolic), the cache delivers substantial speedups—up to 80% reduction in retrieval time and three orders of magnitude in total learning time for refinement-based learners—with the LRU eviction policy consistently optimal.

## Method Summary
The cache stores instance sets for concepts in a hash map. On a query, it first checks for an exact match. If missing, it applies sound syntactic heuristics (e.g., `C ⊓ D` implies `C ⊑ D`) to find a cached superconcept `D` and use `Ret(D)` as a restricted candidate set. Alternatively, it recursively decomposes the concept according to ALC semantics (e.g., `C ⊓ D` → `Ret(C) ∩ Ret(D)`), combining cached sub-concept results via set operations. The cache is pre-initialized with atomic concepts, their complements, and `∃r.⊤`, and uses an eviction policy (LRU best) to bound memory. Integrated into CEL pipelines (OCEL, CELOE, etc.), it replaces expensive reasoner calls with cheap set manipulations, validated by extensive experiments comparing semantic vs. non-semantic caching and multiple eviction strategies.

## Key Results
- Concept retrieval runtime reduced by up to 80% for slower reasoners (e.g., HermiT) and up to 20% for faster ones (e.g., Openllet) at high cache sizes.
- Overall CEL learning time accelerated by up to three orders of magnitude for refinement-based learners (e.g., OCEL).
- LRU eviction policy outperformed FIFO, LIFO, MRU, and RP across datasets and cache sizes; non-semantic caching provided negligible or negative gains.

## Why This Works (Mechanism)
**Mechanism 1:** Subsumption-based pruning. The cache uses sound syntactic heuristics to find a superconcept `D` such that `C ⊑ D`. The cached instance set `Ret(D)` restricts candidates for evaluating `C`, avoiding a full reasoner call over all individuals. This assumes `Ret(D)` is significantly smaller than the full individual set and that heuristics are correct without reasoner overhead. Evidence: Abstract states the cache uses DL semantics to derive results via set operations; Section 4.2 guarantees heuristic soundness.

**Mechanism 2:** Set-theoretic composition. For complex concepts, the cache recursively decomposes them per ALC semantics (e.g., `C ⊓ D` yields `fetchInstances(C) ∩ fetchInstances(D)`). These in-memory set operations replace reasoner calls, assuming sub-concept results are cached and set operations are cheap. Evidence: Abstract and Section 4.4 describe recursive decomposition with intersection, union, complement.

**Mechanism 3:** LRU eviction policy. LRU assumes temporal locality in CEL query patterns—recently accessed concepts are likely reused soon—and evicts the least recently used entry when full. It outperformed other policies because refinement-based learners repeatedly query related concepts during search. Evidence: Abstract and Section 6.1 show LRU best; Section 7 reports 20–60% speedup.

## Foundational Learning
**Description Logics (ALC)**: The cache’s correctness relies on ALC semantics (e.g., `C ⊓ D` as set intersection). Understanding constructors (⊓, ⊔, ¬, ∃) ensures set operations mimic reasoner output.
- Quick check: Given `Ret(A) = {1,2,3}` and `Ret(B) = {2,3,4}`, what is `Ret(A ⊓ B)` based on ALC semantics? (Answer: `{2,3}`)

**Subsumption (`C ⊑ D`)**: Subsumption enables pruning; if `C ⊑ D`, then `Ret(C) ⊆ Ret(D)`, allowing `Ret(D)` to restrict candidates for `C`.
- Quick check: If `C ⊑ D` holds, what inclusion relationship between `Ret(C)` and `Ret(D)` is guaranteed by DL semantics? (Answer: `Ret(C) ⊆ Ret(D)`)

**Set Operations**: Operations like intersection, union, complement implement recursive evaluation without a reasoner.
- Quick check: How would you compute `Ret(¬A)` if `Ret(A)` is known and the universe is `N_I`? (Answer: `N_I \ Ret(A)`)

## Architecture Onboarding
- **Component map**: Cache Store -> Subsumption Heuristic Module & Reasoner Interface (fallback); Eviction Policy Manager tracks access; Initialization Module pre-populates Cache Store.
- **Critical path**: `fetchInstances(C)` → direct cache hit → if miss, apply heuristics to find superconcept(s) `D_i` → compute candidate set `S = ⋂ Ret(D_i)` → if no `D_i`, call `reasoner.getInstances(C)` → store `(C, result)` → return result.
- **Design tradeoffs**:
  - Memory vs Speed: Larger cache reduces reasoner calls but increases memory footprint (Fig 7).
  - Semantic vs Non-Semantic: Semantic cache uses decompositions; non-semantic only exact matches, often degrading performance (Fig 1).
  - Initialization Cost: Pre-computing `Ret(A)`, `Ret(¬A)`, `Ret(∃r.A)` speeds warm-up but costs upfront time (Figs 3 vs 5).
- **Failure signatures**:
  - Low hit ratio (<20%) at moderate cache sizes indicates poor heuristic coverage or low query overlap.
  - No speedup vs baseline suggests reasoner already fast, cache too small, or workload lacks reuse (e.g., EvoLearner).
  - Memory overflow if eviction fails or `maxSize` not enforced.
- **First 3 experiments**:
  1. Establish baseline: Run target CEL learner (e.g., OCEL) without cache across all learning problems; measure average retrieval and total runtime.
  2. Compare semantic vs non-semantic: Integrate both caches with moderate size (50% of `|NC|`) and LRU; compare hit ratios and runtime reduction.
  3. Eviction policy sweep: On small dataset (Family), test all policies (FIFO, LIFO, LRU, MRU, RP) at varying cache sizes (20%, 40%, 60%, 80%, 100%); plot runtime and hit ratio to confirm LRU dominance before scaling.

## Limitations
- Random concept generation and CEL hyperparameters are underspecified, hindering exact replication.
- Subsumption heuristics are sound but incomplete; the impact of missed subsumption relations on hit ratio is unquantified.
- Memory overhead on large real-world ontologies (e.g., GO, SNOMED CT) is not evaluated; worst-case growth could limit adoption.

## Confidence
- Semantic cache runtime reduction: High
- LRU eviction policy optimal: High
- Set-theoretic composition correctness: Medium
- Non-semantic cache negligible benefit: Medium
