# Prompt-Dependent Ranking of Large Language Models with Uncertainty Quantification

## Quick Facts
- **ArXiv ID:** 2603.03336
- **Source URL:** https://arxiv.org/abs/2603.03336
- **Reference count:** 40
- **Primary result:** Prompt-dependent ranking with uncertainty quantification yields partial orders and statistically resolved dominance for LLMs across diverse prompts.

## Executive Summary
This paper addresses the critical flaw in LLM leaderboards that treat rankings as fixed point estimates, ignoring context-dependent performance and statistical uncertainty. The authors develop a prompt-dependent ranking framework based on a contextual Bradley-Terry-Luce model, where each model’s utility is a linear function of prompt covariates such as length and category. Parameters are estimated via constrained maximum likelihood, and simultaneous confidence intervals for pairwise utility differences are constructed using a max-type statistic and bootstrap. These intervals are aggregated into valid confidence sets for ranks, which naturally produce partial orders when evidence is weak. Applied to 140k human comparisons across ten LLMs, the method reveals that rankings vary substantially with prompt characteristics and that many apparent differences are statistically indistinguishable, often collapsing the ranking into a partial order. This enables decision-safe rankings that robustly identify true dominance while avoiding overconfident orderings.

## Method Summary
The core method is a contextual BTL model: utility of model \(i\) for prompt \(x\) is \(\theta_i(x) = \beta_{0i} + x^\top \beta_i\). Parameters are estimated under sum-to-zero constraints via constrained MLE to handle location invariance. Inference directly targets ranking uncertainty: for a given prompt, standardized pairwise differences are computed, and simultaneous rectangular confidence intervals are built using a max-type statistic and parametric bootstrap to control family-wise error. These intervals determine which pairwise comparisons are statistically resolved (interval excludes zero). Marginal rank sets are derived from counts of significantly worse/better models; simultaneous rank sets consider all pairs jointly. The pipeline involves data ingestion, preprocessing, constrained MLE, covariance estimation, and for each new prompt, a sequence of compute differences, bootstrap critical values, interval construction, and rank aggregation. The approach guarantees valid coverage and returns partial orders when evidence is insufficient to break ties.

## Key Results
- Rankings vary substantially with prompt characteristics (e.g., length, category).
- Many apparent rank differences are statistically indistinguishable; uncertainty-aware inference often produces partial orders.
- Grok-4 achieves a singleton top rank for specificity prompts, while for long prompts all models become statistically indistinguishable.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** The contextual BTL model with linear prompt-dependent utilities captures how LLM performance varies across prompts.
- **Mechanism:** For each LLM \(i\), utility \(\theta_i(x) = \beta_{0i} + x^\top \beta_i\); pairwise preference probability \(P(j \text{ preferred over } i) = \exp(\theta_j)/[\exp(\theta_i)+\exp(\theta_j)]\). Estimated via constrained MLE under sum-to-zero constraints to handle location invariance.
- **Core assumption:** Utilities are approximately linear in the selected prompt covariates; the chosen covariates sufficiently explain performance heterogeneity.
- **Evidence anchors:**
  - [abstract] "We model preferences using a contextual Bradley–Terry–Luce model in which the latent utility of each model depends on the input prompt."
  - [section] Section 3.1 "Prompt-Dependent Utility Specification" defines \(\theta_i(x)=\beta_{0i}+x^\top\beta_i\) and motivates its interpretability and tractability.
  - [corpus] Neighboring works (e.g., "Nonparametric LLM Evaluation from Preference Data") use flexible nonparametric models, highlighting that the linear specification is a deliberate trade‑off between flexibility and statistical efficiency.
- **Break condition:** If the true utility–covariate relationship is highly nonlinear or key interactions are omitted, the linear form will be misspecified, leading to biased rankings and potentially under‑covering confidence sets.

### Mechanism 2
- **Claim:** Simultaneous confidence intervals for utility differences, constructed via max‑type statistics and bootstrap, provide valid coverage for multiple comparisons simultaneously, enabling reliable rank inference.
- **Mechanism:** From the MLE, compute standardized differences \(Z_{ij} = (\hat{\beta}_j - \hat{\beta}_i)/se_{ij}\). Define max statistics \(T_{\text{lower}}, T_{\text{upper}}, T_{\text{symm}}\); estimate critical values by simulating from the asymptotic Gaussian of the estimator; form rectangular intervals that control the family‑wise error rate across all targeted pairs.
- **Core assumption:** Asymptotic normality of constrained MLE (Assumptions 1–4: connected comparison graph, bounded covariates, full rank design, positive definite limiting Fisher information).
- **Evidence anchors:**
  - [abstract] "constructing simultaneous confidence intervals for pairwise utility differences, then aggregating into marginal and simultaneous confidence sets for ranks, guaranteeing valid coverage."
  - [section] Section 3.4 defines the max statistics and bootstrap procedure; Section 4.1 and Theorem 4 prove the coverage property for the rectangular intervals.
  - [corpus] "Inference for ranks with applications to mobility across neighbourhoods and academic achievement across countries" (Mogstad et al., 2024) develops rank confidence sets for non‑contextual settings; this paper extends that methodology to prompt‑dependent utilities.
- **Break condition:** Violation of regularity conditions (e.g., disconnected graph, unbounded covariates) or severe model misspecification may break asymptotic normality, causing coverage to fall short of the nominal level.

### Mechanism 3
- **Claim:** Aggregating pairwise confidence intervals into rank confidence sets yields partial orders when evidence is weak, avoiding overconfident tie‑breaking while preserving coverage.
- **Mechanism:** For each model \(i\), define \(N^+_i(x)\) (models significantly worse) and \(N^-_i(x)\) (models significantly better) based on whether the simultaneous interval for the difference lies entirely above or below zero. The marginal rank set is \(\{|N^-_i|+1, \dots, M-|N^+_i|\}\). For simultaneous sets, use all pairs \(S_{\text{sim}}\) to define analogous sets.
- **Core assumption:** Rankings are fully determined by the signs of all pairwise utility differences; if a pairwise interval contains zero, the relative order is considered unresolved.
- **Evidence anchors:**
  - [abstract] "This approach yields statistically valid marginal and simultaneous confidence sets for prompt‑specific ranks... naturally returns partial orders when evidence is weak."
  - [section] Section 3.5 details the construction of \(R_{L,j}(x)\) and \(R^{\text{sim}}_{L,j}(x)\); Theorems 5 and 6 establish their coverage properties.
  - [corpus] "Prediction‑Powered Ranking of Large Language Models" (Chatzi et al.) uses a different framework and produces point ranks; our aggregation method is distinct and explicitly constructs partial orders.
- **Break condition:** When many intervals contain zero due to limited information, rank sets become wide and may be too uninformative for operational decisions; also, the method assumes transitivity of the underlying BTL model, which could be violated if the model is misspecified.

## Foundational Learning
- **Concept:** Bradley‑Terry‑Luce (BTL) model  
  - **Why needed here:** It provides the probabilistic foundation linking latent utilities to observed pairwise choices; without it we cannot connect quantitative performance to binary preference data.  
  - **Quick check:** "Given latent utilities \(u_i\) and \(u_j\), write the probability that model \(j\) is preferred over model \(i\) under the BTL model."  
- **Concept:** Constrained maximum likelihood estimation  
  - **Why needed here:** Utilities are identifiable only up to a common additive shift; constraints (\(\sum \beta_0 = 0\), \(\sum \beta = 0\)) fix that gauge and yield unique parameter estimates.  
  - **Quick check:** "Can absolute utilities be estimated from pairwise comparisons alone? If not, what motivates the sum‑to‑zero constraints?"  
- **Concept:** Simultaneous inference and family‑wise error control  
  - **Why needed here:** Rank determination depends on the joint signs of many pairwise differences; using independent marginal intervals would inflate the chance that at least one interval misses, breaking coverage for the whole ranking.  
  - **Quick check:** "If we construct 95% marginal confidence intervals for each pairwise difference independently, what is the maximum probability that all intervals simultaneously cover the true differences when \(M=10\)?" (Answer: strictly less than 95% due to multiplicity; the family‑wise error can be well above 5%.)

## Architecture Onboarding
- **Component map:**  
  Data ingestion → Model specification → Constrained MLE → Covariance estimation → Inference engine (per prompt: compute differences & SEs → Bootstrap t_α → Construct simultaneous intervals → Aggregate into rank sets) → Output ranking with uncertainty.
- **Critical path:**  
  Raw data → Preprocessing → Constrained MLE → Covariance estimation → For each new prompt: compute utility differences & standard errors → Bootstrap to obtain \(t_{\alpha}\) → Construct pairwise simultaneous intervals → Aggregate into rank sets → Output ranking with uncertainty.
- **Design tradeoffs:**  
  - Parametric vs. nonparametric utility: Linear form is interpretable and statistically efficient but may miss nonlinear effects; nonparametric (e.g., splines) adds flexibility at the cost of higher sample complexity.  
  - Simultaneous vs. marginal intervals: Simultaneous intervals guarantee valid rank coverage but can be conservative; marginal intervals are narrower but invalid for joint conclusions.  
  - Bootstrap vs. analytic critical values: Bootstrap captures finite‑sample correlation patterns but is computationally heavy; analytic approximations (e.g., extreme‑value limits) are faster but rely on stronger asymptotics.  
  - Scalability: The method assumes a fixed number of models \(M\) as comparisons \(L \to \infty\). If \(M\) is large, rank sets become very wide and the max‑statistic calculation may become expensive; dimensionality reduction or hierarchical shrinkage could be needed.
- **Failure signatures:**  
  - Non‑coverage in simulation (empirical rank coverage < nominal) → likely model misspecification or broken regularity conditions.  
  - Extremely wide or full‑range rank sets even for moderate sample sizes → possible near‑non‑identification (e.g., covariates with little variation or disconnected comparison graph).  
  - Instability across bootstrap replications → heavy‑tailed residuals or outliers; inspect pairwise choice residuals.  
  - Constraint not enforced (e.g., \(\sum \hat{\beta}_0 \neq 0\)) → check projection implementation.  
  - Slow or non‑converging MLE → ill‑conditioned design matrix; consider better optimization (L‑BFGS with projection) or regularization.
- **First 3 experiments:**  
  1. **Simulation coverage:** Simulate comparisons from a known contextual BTL with \(M=5\), \(d=2\), and \(L\) large. Fit the pipeline, compute marginal and simultaneous rank sets, and verify that over many replications the true ranks are covered at approximately 95% level.  
  2. **Replicate real‑data prompt‑length effect:** Using the Arena dataset, narrow the sample to the five models in Section 2.4, compute rank sets for token counts 100, 500, 1000, and confirm that intervals widen as length grows and that beyond ~1200 tokens all sets become \([1,5]\) as reported.  
  3. **Extrapolation stress test:** Construct extreme prompts by setting \(x = \lambda v\) with very large \(\lambda\) (e.g., simulate a covariate point far outside the training support). According to Proposition 7, rank sets should approach the full \([1,M]\) if the projected \(\beta\) differences are not statistically resolved; verify this behavior in the fitted model.

## Open Questions the Paper Calls Out
- **How can we design an adaptive mechanism that selects pairwise comparisons to minimize ranking uncertainty under a fixed evaluation budget?**  
  The paper uses a static dataset and does not address optimal or sequential selection of comparisons; evidence would be algorithms with theoretical sample complexity bounds and experiments showing fewer comparisons achieve comparable confidence than random selection.
- **How should ranking uncertainty be incorporated into LLM routing and selection decisions under constraints like latency or cost?**  
  The framework only provides confidence sets; no decision‑making procedure is proposed or evaluated. Evidence would be decision models that treat rank confidence sets as inputs, solve associated optimizations, and demonstrate real‑world robustness.
- **What are the asymptotic properties of rank confidence sets when both \(M\) and \(L\) grow jointly, and how can the framework be made robust to non‑linear prompt effects or model misspecification?**  
  Current theory assumes fixed \(M\) and \(d\) and uses linear utilities; joint asymptotics and nonparametric extensions are open. Evidence would be limit theorems for the \(M, L \to \infty\) setting and empirical studies using splines or machine learning for utilities with coverage guarantees.

## Limitations
- Linear utility may be misspecified, biasing rankings.
- Requires regularity (connected graph, bounded covariates, full rank); violations break coverage.
- Extrapolation to unsupported covariate regions yields unreliable estimates.
- BTL transitivity may not hold (cycles in data).
- Weak signals produce very wide rank sets, limiting usefulness.

## Confidence
- Linear BTL utility: Medium
- Simultaneous max‑type CIs: High
- Rank set aggregation: High

## Next Checks
1. **Nonlinearity robustness:** Simulate data with a nonlinear utility (e.g., quadratic length). Fit linear model, check rank‑set coverage over sample sizes.
2. **Covariate sensitivity:** Refit using alternative features (splines, interactions, reduced categories). Compare rank sets for key prompts; look for large changes.
3. **Transitivity audit:** Measure frequency of intransitive cycles in human preferences. High rates suggest BTL misspecification.
