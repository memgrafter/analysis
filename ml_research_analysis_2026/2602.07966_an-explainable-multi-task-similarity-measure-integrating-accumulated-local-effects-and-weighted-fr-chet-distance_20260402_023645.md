# An Explainable Multi-Task Similarity Measure: Integrating Accumulated Local Effects and Weighted Fréchet Distance

## Quick Facts
- **arXiv ID:** 2602.07966
- **Source URL:** https://arxiv.org/abs/2602.07966
- **Reference count:** 40
- **Primary result:** A novel, model‑agnostic similarity measure based on Accumulated Local Effects (ALE) curves and a weighted Fréchet distance aligns with intuitive notions of task similarity across synthetic data, Parkinson’s patient records, a large bike‑sharing dataset (264 tasks), and the CelebA image dataset.

## Executive Summary
This paper introduces an explainable multi‑task similarity measure to quantify relationships between machine learning tasks. The approach computes feature‑wise ALE curves for each task’s model, captures the global effect of each feature on predictions, and then compares these curves using a weighted Fréchet distance that accounts for data density in each segment. Feature importances weight the contributions, and an optional performance‑based scaling factor reduces the influence of poorly trained models. Evaluations on diverse datasets demonstrate that the measure recovers intuitive groupings of tasks (e.g., similar bike‑sharing stations, semantically related CelebA attributes) and provides interpretable insights for downstream applications such as task clustering and multi‑task learning.

## Method Summary
For each task, the method first computes first‑order ALE curves for all features using an equally spaced partition. These curves are then resampled onto a common grid (e.g., empirical quantiles) to ensure invariance to discretization resolution. To compare two tasks, the weighted discrete Fréchet distance is calculated between each feature of the reference task and every feature of the other task; the minimum distance per feature is retained, weighted by the reference task’s feature importance, and summed to produce an asymmetric dissimilarity score. Optionally, this score is multiplied by a factor that shrinks the influence of tasks with poor predictive performance. The resulting similarity matrix is model‑agnostic and directly interpretable through the ALE visualizations.

## Key Results
- The measure successfully groups together tasks with similar underlying data‑generating processes in synthetic experiments and adapts to distribution shifts.
- On a bike‑sharing dataset with 264 station‑level tasks, the similarity matrix reveals geographically and functionally coherent station clusters.
- On CelebA, using concept bottlenecks, the approach captures semantically meaningful similarities between attribute prediction tasks (e.g., “blond hair” and “smiling”).

## Why This Works (Mechanism)

### Mechanism 1: ALE Curves as Task Representations
- **Claim:** The similarity measure isolates and compares the average effect of each feature on model predictions using ALE curves.
- **Mechanism:** For a given task’s model, ALE curves are computed by averaging the difference in predictions over small intervals of a feature while marginalizing over other features, producing a curve (feature value vs. accumulated effect) that represents the feature’s global influence. The curve is centered to have mean zero.
- **Core assumption:** First‑order ALE sufficiently captures the feature‑outcome relationship; higher‑order interactions are negligible or implicitly captured by the model.
- **Evidence:** The method is explicitly based on ALE curves (abstract), with a formal definition of `ˆg_t j,ALE` in Section 3.2.
- **Break condition:** If the true relationship is dominated by strong feature‑feature interactions (e.g., `X1 × X2`), first‑order ALE curves may be flat and uninformative, underestimating task similarity.

### Mechanism 2: Weighted Fréchet Distance for Robust Curve Comparison
- **Claim:** The weighted Fréchet distance provides a similarity score between two ALE curves that accounts for both curve shape and the reliability of each segment based on data density.
- **Mechanism:** The discrete Fréchet distance (the “dog‑leash” measure) is computed between the polygonal ALE curves. A weight function `w(p_t(u), p_t'(v)) = max(p_t, p_t') / min(p_t, p_t')` penalizes comparisons made in regions with sparse data support, where `p_t` is the proportion of observations falling in a given interval.
- **Core assumption:** The reliability of an ALE segment is directly tied to the proportion of data in that interval; differences in high‑density regions should dominate the distance.
- **Evidence:** Section 3.3 defines weighting as a quantifier of segment reliability; Section 3.2 notes equally spaced partitions to capture data distribution shape.
- **Break condition:** Highly uneven distributions or extreme outliers may render interval proportions a poor proxy for estimate reliability; weighting by inverse variance would be more robust but is not implemented.

### Mechanism 3: Performance‑Based Scaling to Reduce Bias from Poor Models
- **Claim:** A performance‑based scaling factor adjusts the raw similarity measure to prevent low‑quality models (high loss) from artificially inflating dissimilarity scores.
- **Mechanism:** Let `L(t)` be the predictive loss of task `t`. The raw discrepancy `δ_t(t')` is multiplied by `γ(L(t), L(t')) = min(L(t), L(t')) / max(L(t), L(t'))`. This factor is near 1 for equally performing tasks and approaches 0 as the loss ratio grows, down‑weighting comparisons that involve a poorly performing model.
- **Core assumption:** Differences in predictive performance reflect model inadequacy rather than intrinsic task dissimilarity; the measure should compare the underlying functions under the premise that both are reasonably well‑specified.
- **Evidence:** Section 3.4.1 and Equation 8 present the scaling; Section 4.1 (Table 2) empirically shows reduced similarity when a weak Task 6 is included.
- **Break condition:** If both tasks have high loss, `γ` remains near 1, potentially masking the fact that neither model is trustworthy. The paper proposes a manual threshold `τ` to flag such cases.

## Architecture Onboarding

### Component Map
Trained models (one per task) → Compute ALE curves for each feature (equally spaced partition) → Standardize curves onto a common grid → Compute weighted discrete Fréchet distances between curves → Aggregate with feature importance weights → (Optional) Multiply by performance scaling factor → Asymmetric similarity matrix.

### Critical Path
Steps B (ALE computation) and D (weighted Fréchet) are the most computationally intensive; Step C (common grid resampling) is essential for robustness to discretization choices.

### Design Tradeoffs
- **Model‑agnostic vs. Explainable depth:** Uses model‑agnostic ALE, but explanation is limited to main effects; interactions are not captured.
- **Interpretability vs. Complexity:** Raw features retain semantics; using a latent space (e.g., autoencoder) could capture interactions but loses direct interpretability.
- **Resolution vs. Stability:** More ALE intervals (higher *K*) yields finer detail but increases noise; common grid resampling mitigates resolution mismatch.
- **Asymmetry:** The measure `δ_t(t')` is asymmetric due to reference‑task importance weights; this is intentional (prioritizes the reference task’s perspective) but complicates clustering (requires a symmetric matrix, e.g., by averaging).

### Failure Signatures
- **Spurious similarity:** Two tasks have identical ALE curves because both models are biased (e.g., both predict a constant). Check task performance first.
- **Noisy ALEs:** High‑frequency oscillations in ALE plots suggest insufficient data or model instability; consider smoothing or retraining with more data.
- **Discretization artifacts:** Large changes in similarity when varying the number of ALE intervals. Ensure common grid resampling is implemented.
- **Heterogeneous feature spaces:** When feature names do not align, the automatic `min_{j'}` search may find coincidental shape matches; use domain knowledge to constrain feature matching.

### First 3 Experiments
1. **Toy validation:** Using the provided synthetic dataset, verify that tasks with identical data‑generating processes yield low `δ`. Manipulate one task’s distribution for feature `X4` and confirm that similarity decreases, driven primarily by that feature’s Fréchet component.
2. **Component isolation:** On a simple dataset (e.g., bike‑sharing), compute ALE curves with different numbers of intervals *K*. Compare the resulting similarity matrices. Apply common grid resampling and demonstrate that matrices become stable and invariant to *K*.
3. **Performance flag:** Train one task with a deliberately weak model (e.g., shallow tree on complex data). Compute the similarity matrix with and without performance scaling `γ`. Confirm that similarities involving the weak task are significantly reduced in the scaled version.

## Limitations
- The exact definition of the ALE partition (equi‑width vs. equi‑depth) is ambiguous, risking irreproducibility.
- Feature importance extraction method is unspecified; different choices (permutation, SHAP, uniform) may lead to different similarity outcomes.
- The measure is asymmetric, requiring an additional step to obtain a symmetric matrix for clustering; the paper does not discuss how to merge asymmetric scores.
- First‑order ALE ignores feature interactions, which might be crucial for capturing task relationships.
