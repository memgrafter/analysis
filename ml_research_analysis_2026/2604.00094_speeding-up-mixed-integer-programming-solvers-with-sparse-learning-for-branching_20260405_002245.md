# Speeding Up Mixed-Integer Programming Solvers with Sparse Learning for Branching

## Quick Facts
- **arXiv ID:** 2604.00094  
- **Source URL:** https://arxiv.org/abs/2604.00094  
- **Reference count:** 12  
- **Primary result:** Sparse lasso-regularized models with <4% of GNN parameters run on CPU, achieve competitive accuracy (46–70% vs GNN 54–72%), and reduce solve times up to 25% on large instances across four NP-hard problem classes.

## Executive Summary
This work replaces expensive strong branching computations in mixed-integer programming solvers with sparse linear models trained via lasso regularization. By dynamically recomputing features at each branch-and-bound node and including quadratic expansions, the models capture essential nonlinearities while remaining extremely compact. Despite using only 25,000 training samples (orders of magnitude fewer than graph neural networks), the deployed CPU-only models consistently outperform SCIP’s default heuristic and even GPU-accelerated GNNs in wall-clock time on large instances. The approach demonstrates that carefully engineered sparse models can deliver high practical impact in resource-constrained settings.

## Method Summary
The method collects training data by running SCIP with vanilla full strong branching, recording normalized strong branching scores and 101 base features for each fractional integer variable at each node (with dynamic updates of LP-relaxation statistics). Features are preprocessed to remove near-constant variables and expanded quadratically (squared terms and pairwise interactions). Lasso (L1) regression is trained per problem domain using R’s `glmnet`, with λ selected by validation mean squared error. The resulting sparse coefficient vector (∼1.3k nonzero terms) is integrated into SCIP as a CPU-only branching rule: at every node, the model scores all candidates and branches on the highest-scoring variable. Training requires only 25k candidate observations, and size-matched training sets further improve performance on large instances.

## Key Results
- **Parameter efficiency:** Sparse models contain <4% of the parameters of state-of-the-art GNNs (∼1.3k vs. 64k nonzero).
- **Accuracy:** Competitive top-1 accuracy on strong branching score prediction (46–70% across four domains vs. GNN 54–72%).
- **Runtime impact:** Consistently reduces solve times versus SCIP default; on large instances, cuts runtimes by up to 25% relative to SCIP and outperforms both CPU and GPU GNN baselines despite larger tree sizes.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Sparse models (via lasso) achieve competitive prediction accuracy with far fewer parameters, enabling fast CPU inference that outweighs modest tree-size increases.
- **Mechanism:** Lasso regularization (`||β||_1` penalty) drives many coefficients to zero during training, producing compact linear/quadratic models. This reduces memory footprint and computation per prediction, allowing cheap evaluation at every node without GPU acceleration. The retained features still capture key patterns in strong branching scores.
- **Core assumption:** Effective branching decisions can be approximated by a sparse combination of informative features, even if complex nonlinear interactions (captured by GNNs) yield slightly higher top-1 accuracy.
- **Evidence anchors:**
  - [abstract] "...models with fewer than 4% of the parameters of a state-of-the-art graph neural network (GNN) while achieving competitive accuracy."
  - [section 5.1] Table 2 shows sparse models have ~1.3k nonzero parameters vs. GNN's 64k.
  - [section 5.3] Sparse models often have faster runtimes than GNN-C (CPU) and GNN-G (GPU) despite larger node counts.
- **Break condition:** If the optimal branching policy depends on highly complex, instance-specific interactions not linearly separable even with quadratic terms, sparsity may discard critical features, causing tree explosion and net slowdown.

### Mechanism 2
- **Claim:** Recalculating "static" features dynamically at each node (i.e., using current LP state) provides more relevant information than reusing root-node statistics.
- **Mechanism:** Features like constraint degrees, coefficient statistics, and pseudocosts are updated as the B&B search progresses. This adapts to changes in the active LP relaxation (e.g., constraints added/removed, variables fixed), capturing the evolving problem structure more accurately than static summaries.
- **Core assumption:** The quality of a branching candidate is influenced by the current local LP structure, not just global problem data available at the root.
- **Evidence anchors:**
  - [section 4.2] "Our work considers as dynamic many features previously considered static... we recalculate these quantities at every branching step so they track the current LP relaxation."
  - [section 3] Contrasts with Khalil et al. (2016) who reused root features.
  - [section 5.3] Sparse models using dynamic features outperform SCIP default and achieve competitive runtime, implying feature relevance.
- **Break condition:** If the distribution of LP states during search is sufficiently similar to the root node across instances, dynamic recomputation yields negligible benefit while incurring extra cost, making static features preferable.

### Mechanism 3
- **Claim:** Quadratic feature expansions are necessary for medium/large problem performance; linear models alone degrade significantly on larger instances.
- **Mechanism:** Including squared terms and pairwise interactions (e.g., `ceiling_distance × solution_value`) allows the linear model to capture nonlinear relationships between features and SB scores. This bridges part of the expressiveness gap to GNNs.
- **Core assumption:** SB scores depend on interactions between features (e.g., integrality violation and constraint tightness), not just individual feature magnitudes.
- **Evidence anchors:**
  - [section 4.4] "Using the remaining features, we construct quadratic expansions by adding squared terms and pairwise interaction products."
  - [section 5.3.3] Table 6 shows quadratic models (QL) solve more instances and run faster than linear (LL) on medium/large SC and IS; differences are smaller on small instances.
  - [section 5.4] Selected features include interaction terms like `ceiling distance × floor distance`.
- **Break condition:** If interactions are predominantly low-order or linear, quadratic terms add noise and overfitting risk, especially in small-data regimes, harming generalization.

## Foundational Learning
- **Concept: Lasso (L1) Regularization**  
  *Why needed:* To produce sparse models (<4% of GNN parameters) that are fast to evaluate on CPU while maintaining predictive power. The `λ||β||_1` penalty drives coefficients to zero.  
  *Quick check:* What happens to model coefficients as `λ` increases in the regularization path? (Answer: More coefficients shrink exactly to zero.)

- **Concept: Dynamic Feature Recalculation**  
  *Why needed:* Branching decisions depend on the *current* LP state (active constraints, variable bounds), not just root-node data. Updating features at each node captures constraint/variable changes during B&B.  
  *Quick check:* Why might a variable's "number of constraints" feature change during search? (Answer: Because constraints may be deleted or added via cutting planes, and variables may become fixed.)

- **Concept: Quadratic Feature Expansion**  
  *Why needed:* To model nonlinear relationships between raw features and SB scores within a linear framework. Interactions like `solution_value²` or `integral_violation × max_coeff` appear frequently in selected sparse models.  
  *Quick check:* If two features `x1` and `x2` individually correlate weakly with SB score, but their product `x1*x2` is strongly predictive, what does this imply about modeling? (Answer: A linear model on original features will miss this effect; quadratic expansion or nonlinear model is needed.)

## Architecture Onboarding
**Component map:**  
Data Collection (SCIP+VFS) → Preprocessing (remove near-constant, quadratic expansion) → Lasso Training (glmnet, λ tuned via validation) → Deployment (SCIP branching rule via C API)

**Critical path:** Trajectory must match exactly: collect SB tuples → preprocess identically for training and deployment → select λ on validation → integrate sparse coefficients into SCIP. Any mismatch in feature computation (e.g., dynamic vs. static) breaks performance.

**Design tradeoffs:**
- **Accuracy vs. Speed:** Larger `dfmax` (max nonzero coefficients) may improve accuracy but increase prediction time. Sparse models (<2k coefficients) still outperform GNNs in wall-clock time even with GPU.
- **Data size vs. generalization:** Small-sample training (25k candidates) is sufficient, but size-matched training (train on small/medium/large separately) helps on large instances.
- **Quadratic vs. linear:** Quadratic terms improve medium/large performance but increase feature dimension (~3k terms). Preprocessing must manage combinatorics.

**Failure signatures:**
- **Memory blowup:** Naive quadratic expansion (all pairwise interactions) explodes feature count → slow training/prediction.
- **Degenerate dynamics:** Accidentally using static features (not recomputed) degrades performance on later tree nodes.
- **Validation mismatch:** Selecting λ on a validation set drawn from different problem sizes than test set causes over/under-fitting.
- **Numerical instability:** Feature scaling mismatch between training and deployment (e.g., min-max bounds computed on root vs. dynamic nodes).

**First 3 experiments:**
1. **Replicate Table 3 (Accuracy):** Train QL/QS on small-instance data; evaluate top-1 accuracy on SB test set (20k tuples). Expect ~46–70% accuracy vs. GNN 54–72%.
2. **Runtime benchmark (Table 4):** Solve 20 medium/large instances per domain with QL, QS, GNN-C/G, SCIP default, VFS. Measure 1-shifted geometric mean time. Expect QL/QS to beat SCIP and GNN-C; QS may help on large IS.
3. **Ablation: Quadratic vs. Linear (Table 6):** Train LL (linear) vs. QL (quadratic) on large-sample small-instance data. Evaluate on medium/large instances. Expect QL to solve more instances and run faster on SC/IS.

## Open Questions the Paper Calls Out
- **Cross-domain generalization:** Can sparse models trained on the four benchmark domains (set covering, set partitioning, capacitated facility location, independent set) generalize to other MIP instances (e.g., MIPLIB) without retraining?
- **Interpretability-to-rule conversion:** Can the coefficients of sparse quadratic models be converted into a simple, non-ML branching rule with comparable performance?
- **Dynamic feature isolation:** Does updating features at each node improve performance compared to using static root-node features? The paper recomputes many features dynamically but provides no direct ablation.

## Limitations
- **Instance generation:** Exact generator code/parameters from Gasse et al. (2019) are unspecified, preventing creation of identical benchmark sets.
- **Feature definitions:** Precise formulas for some dynamic features (e.g., weighted pseudocosts, constraint aggregations) are omitted, risking implementation drift.
- **Preprocessing & expansion:** Thresholds for "near-constant" feature removal and the exact scheme for quadratic term generation (all pairwise vs. filtered) are unclear, affecting model size and computation.

## Confidence
- **Sparse model efficiency (Few parameters, CPU speed):** High – Directly measured parameter counts (<4% of GNN) and wall-clock runtime results are provided.
- **Dynamic feature necessity:** Medium – Evidence relies on comparative results against static-feature prior work; no direct ablation of dynamic vs. static within this framework.
- **Quadratic expansion necessity:** Medium – Ablation shows benefit on medium/large instances but effect size varies; linear models still competitive on small instances.
- **High data efficiency (25k samples sufficient):** High – Explicitly stated and compared to GNNs' larger sample needs; size-matched training further supports this.
