# FAME: Formal Abstract Minimal Explanation for Neural Networks

## Quick Facts
- **ArXiv ID**: 2603.10661
- **Source URL**: https://arxiv.org/abs/2603.10661
- **Reference count**: 40
- **Primary result**: FAME enables scalable formal abductive explanations for neural networks by using abstract interpretation with cardinality-constrained perturbation domains, achieving up to 25× speedups over VERIX+ and producing the first formal explanations for ResNet-2B on CIFAR-10.

## Executive Summary
FAME is a framework for computing formal abductive explanations (AXp) of neural network decisions. It overcomes the scalability bottleneck of exact methods like VERIX+, which suffer from sequential feature traversal and exponential solver calls. FAME leverages sound over-approximations from linear relaxation-based abstract interpretation (LiRPA) to certify entire batches of irrelevant features in parallel, eliminating order dependency. The method iteratively refines the perturbation domain using cardinality constraints, progressively tightening bounds and recovering more irrelevant features. A greedy knapsack heuristic efficiently selects feature batches without solving NP-hard optimization. On standard image benchmarks (MNIST, GTSRB, CIFAR-10), FAME yields explanation sizes comparable to or smaller than VERIX+ with speedups up to 25×, and scales to very deep networks (ResNet-2B) where exact solvers fail.

## Method Summary
FAME operates in two phases. **Abstract pruning**: Given input x and an ℓ∞ perturbation ball Ω(x), it computes linear upper bounds for each output class using LiRPA (CROWN). These bounds define an abstract batch certificate Φ(A); if Φ(A) ≤ 0 for a set A, then all features in A are simultaneously irrelevant under the current domain. The domain is refined to Ωₘ(x; A), restricting the number of varying features among remaining candidates to a budget m. A greedy heuristic selects a maximal batch Aₘ satisfying Φ(Aₘ) ≤ 0 by minimizing a normalized cost derived from the linear bounds. This batch is added to the free set, and the process repeats with updated A and possibly smaller m, iteratively expanding the free set. **Exact refinement**: singleton checks ensure the free set is singleton-maximal (yielding a weak AXp), and optionally VERIX+ converts it to a minimal AXp. The core innovation is using sound abstraction to bypass sequential traversal, with cardinality constraints tightening the abstraction as the free set grows.

## Key Results
- **Scalability milestone**: First formal AXp for ResNet-2B on CIFAR-10 (1024 features), infeasible for exact solvers.
- **Runtime speedup**: Up to 25× faster than VERIX+ (e.g., GTSRB-CNN: 7.4s vs 185s).
- **Explanation quality**: Smaller or comparable explanation sizes on MNIST and GTSRB benchmarks.

## Why This Works (Mechanism)
FAME’s efficiency stems from three synergistic mechanisms. **Mechanism 1: Batch certification via abstract certificate.** It computes an abstract batch certificate Φ(A; Ω) using LiRPA bounds, which aggregates the worst-case linear contributions of features in A across all non-ground-truth classes. If Φ(A; Ω) ≤ 0, then simultaneously freeing A is sound. This eliminates the sequential order dependency of prior methods. The core assumption is that LiRPA’s over-approximation is sufficiently tight to distinguish relevant from irrelevant features. Evidence: Proposition 4.2 proves soundness under sound LiRPA. Break condition: if Φ({j}) > 0 for all j, bounds are vacuous (e.g., domain too large or model non-robust). **Mechanism 2: Iterative domain refinement with cardinality constraints.** After freeing a batch A, FAME shrinks the perturbation domain to Ωₘ(x; A), limiting the number of varying features among remaining candidates to m. Recomputing LiRPA on this smaller domain often yields tighter linear bounds, making Φ more discriminative and enabling further freeing. The recursion converges to a locally maximal certified free set. Evidence: Section 5 defines Ωₘ and Algorithm 2; Section 7.1 reports a 36% size reduction on MNIST-CNN. Break condition: if no batch found for any m (A_best = ∅), refinement stagnates. **Mechanism 3: Greedy knapsack for batch selection.** Maximizing batch size under Φ(A) ≤ 0 is a multidimensional knapsack problem. FAME uses a greedy heuristic: select the feature minimizing max_{i≠c} c_{i,j} / (-b̂_i), approximating optimality with only one backward pass to compute all contributions. Evidence: Table 1 shows within 9 features of optimal with 9–12× speedup. Break condition: greedy might yield suboptimal batches, but empirical gap is small (<0.4% on average).

## Foundational Learning
- **Abstract Interpretation & LiRPA**: Sound over-approximations (e.g., linear bounds) of a network’s behavior over an input domain. *Why needed*: FAME’s batch certificate relies on LiRPA to provide sound linear relaxations (CROWN) for feature contributions. *Quick check*: Explain why the contribution term c_{i,j} = max{ W_{i,≥0}^j (x_j - x̄_j), W_{i,≤0}^j (x̄_j - x̄_j) } uses the worst-case range over the input domain.
- **Abductive Explanations (AXp)**: A subset of features that, when fixed to their nominal values, guarantees the model’s prediction despite perturbations. *Why needed*: FAME computes weak AXp (wAXp) that are singleton-maximal; understanding minimal vs. weak AXp is crucial for evaluating output. *Quick check*: Why is a minimal AXp not necessarily the smallest possible explanation? (Hint: consider subset minimality.)
- **Cardinality-Constrained Perturbation Domains (Ωₘ)**: A perturbation set where at most m features can vary (ℓ₀ constraint). *Why needed*: FAME recursively refines the domain to Ωₘ(x; A) to tighten LiRPA bounds as the free set A grows. *Quick check*: How does Ωₘ(x; A) differ from the standard ℓ∞ ball Ω(x)? What computational advantage does the former offer for batch certification?

## Architecture Onboarding
- **Component map**: Input (x, f, ϵ) -> LiRPA Backend (CROWN) computes linear bounds -> Batch Certificate evaluates Φ(A) -> Greedy Batch Selector picks features -> Domain Refinement Manager controls recursion and Ωₘ updates -> loop back to LiRPA if free set improves -> Singleton Refiner ensures singleton-maximality -> Output wAXp^A.[Optional] -> VERIX+ Refinement -> minimal AXp.
- **Critical path**: 1. Define Ω(x) from x and ϵ. 2. Run LiRPA on Ω(x) to get W, w, b̂. 3. For m = 1..|F\A|: compute c_{i,j}, run greedy selector to get Aₘ with Φ(Aₘ) ≤ 0. 4. Update A ← A ∪ argmax_m |Aₘ|. 5. If A improved, repeat from 3 with new A. 6. Else, run singleton checks on F\A. 7. Output F\A as wAXp^A.
- **Design tradeoffs**: 
  - Precision vs. Scalability: Using LiRPA (incomplete abstraction) enables GPU acceleration and batch certification but introduces an abstraction gap between wAXp^A and true AXp; exact refinement (VERIX+) is deferred to post-processing.
  - Batch size vs. Complexity: Greedy knapsack sacrifices optimality for speed; empirical gap is negligible (<0.4%).
  - Traversal order elimination: Cardinality-constrained domains avoid circular dependencies of sequential methods, at the cost of extra LiRPA recomputations (still cheaper than SAT calls).
- **Failure signatures**:
  1. **Vacuous initial bounds**: Φ(∅) > 0 indicates the relaxation cannot certify robustness even with all features freed; likely due to large ϵ or low robustness. Result: trivial full-feature explanation.
  2. **Recursive stagnation**: A_best = ∅ for all m after iterations; abstraction reached fixed point. Output is locally maximal wAXp^A under current abstraction.
  3. **Memory/time blow-up**: Deep networks (e.g., ResNet-2B) make LiRPA expensive; total runtime grows with number of batches and rounds. Greedy loop over m is potentially quadratic but early termination helps.
  4. **Soundness violation**: Buggy LiRPA or incorrect Ωₘ construction could break Φ(A) ≤ 0 guarantee. Must ensure Ωₘ(x; A) ⊆ Ω(x).
- **First 3 experiments**:
  1. **Unit test batch certificate**: Build a 2‑layer MLP with analytically known irrelevant features. Exhaustively verify that every freed feature is truly irrelevant under all perturbations, and that the final wAXp^A is robust and singleton‑maximal.
  2. **Greedy vs. exact knapsack**: On MNIST‑CNN, for various m, compute maximal batch sizes using both FAME’s greedy heuristic and an exact MILP solver (e.g., Gurobi). Report average size difference and per‑iteration runtimes.
  3. **Refinement ablation**: Run FAME with cardinality refinement enabled (card=True) and disabled (card=False) on the same input. Compare final free‑set sizes to isolate the impact of iterative domain tightening.

## Open Questions the Paper Calls Out
1. Extending LiRPA to soundly handle arbitrary finite non‑convex discrete feature domains, which would reduce over‑approximation for non‑contiguous categorical features.
2. Integrating tighter abstract interpretation methods (e.g., α‑CROWN) into FAME to reduce the abstraction gap between wAXp^A and true AXp, and quantifying the trade‑off in runtime.
3. Applying FAME beyond classification (e.g., regression) and to other properties (e.g., local stability); modifications needed to the batch certificate and domain refinement.

## Limitations
- **Soundness conditional on LiRPA**: The abstract certificate Φ is only sound if LiRPA bounds are accurate; vacuous bounds (e.g., for large ϵ) can force trivial full‑feature explanations.
- **Explanation quality gap**: FAME outputs weak AXp; conversion to minimal AXp requires expensive VERIX+ refinement, and the gap between wAXp^A and true AXp can be substantial (e.g., 477 vs 298 freed pixels on ResNet‑2B).
- **Architecture scope limited**: Evaluation restricted to CNNs on image datasets (MNIST, GTSRB, CIFAR‑10); generalization to transformers, RNNs, or tabular data remains unexplored.
