# Compressing LLMs with MoP: Mixture of Pruners

## Quick Facts
- **arXiv ID:** 2602.06127
- **Source URL:** https://arxiv.org/abs/2602.06127
- **Reference count:** 7
- **Primary result:** MoP achieves state-of-the-art accuracy for 20–40% compression on LLaMA-2/3 and LLaVA, with up to 39% end-to-end latency reduction.

## Executive Summary
MoP (Mixture of Pruners) is an iterative structured pruning framework that alternates between depth (removing entire layers) and width (removing attention heads/MLP neurons) pruning at each step. It selects the candidate that better preserves the original model's behavior after a brief recovery fine-tuning. On LLaMA-2 and LLaMA-3, MoP surpasses all baselines in accuracy across compression ratios (20–40%), and its worst run still beats the best competitor. At 30% compression on LLaMA-2 7B, it achieves 61.54% average accuracy versus 61.02% for the best baseline. The method also yields real inference speedup, reducing latency by 39% at 40% compression. Extending to the vision-language model LLaVA-1.5, text-only recovery fine-tuning maintains 77.92% of original multimodal performance at 40% compression.

## Method Summary
MoP proceeds iteratively toward a target compression ratio. At each step, it first selects a layer (the third-to-last by default) to consider for depth removal; the parameter count of that layer is computed. Two candidates are generated: (1) depth candidate: remove that layer entirely; (2) width candidate: prune attention heads and MLP neurons via activation magnitude (AMP) to remove exactly the same number of parameters as the selected layer. Both candidates undergo a short recovery fine-tuning (10×iteration steps on a subset of Alpaca) to mitigate pruning damage. Their similarity to the original model is then evaluated using a path criterion (cosine similarity, KL divergence, perplexity, or random selection) on a calibration set (WikiText-2). The candidate with higher fidelity (or randomly, if using random) is retained as the model for the next iteration. After reaching the target compression, a full recovery fine-tuning (2 epochs on Alpaca with LoRA) is applied. The process ensures fair comparison at each step via parameter matching and leverages iterative calibration to guide structural decisions.

## Key Results
- At 30% compression on LLaMA-2 7B, MoP attains 61.54% average zero-shot accuracy vs. 61.02% for the best baseline (AMP).
- At 40% compression, MoP reduces end-to-end inference latency by 39% on an RTX 4090.
- On LLaVA-1.5, MoP with text-only recovery fine-tuning preserves 77.92% of original multimodal capability at 40% compression.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** MoP’s performance gain stems from combining the complementary strengths of depth and width pruning—depth offers superior inference acceleration via reduced sequential steps, while width preserves accuracy through finer-grained component removal.
- **Mechanism:** The method iteratively selects between removing an entire layer (depth) or a parameter-equivalent set of attention heads/MLP neurons (width). This avoids exhausting one dimension, distributing compression and retaining aspects of both acceleration (from depth) and representational fidelity (from width).
- **Core assumption:** The model contains redundant structures at both layer-level and within-layer levels, and removing either can be compensated for if the other is preserved appropriately.
- **Evidence anchors:** 
  - Abstract: "MoP introduces an iterative framework that alternates between depth and width pruning at each step, selecting the candidate that better preserves the original model's behavior... achieves state-of-the-art accuracy... with its worst-performing run still exceeding the best results from competing methods."
  - Section 3.1: "While width pruning enables finer-grained selection... tending to better preserve performance... depth pruning... often yields superior inference acceleration."
- **Break condition:** If one pruning dimension (depth or width) is exhausted prematurely, the model loses the complementary benefit, leading to performance collapse faster than single-dimension baselines.

### Mechanism 2
- **Claim:** The iterative *path selection* based on short fine-tuning calibration steers MoP toward pruning decisions that minimally alter model behavior on a representative distribution, preventing catastrophic forgetting at each step.
- **Mechanism:** At each iteration, both depth and width candidates undergo minimal recovery fine-tuning (10 × i steps) before being scored against the original model using a scalar metric (cosine similarity, KL divergence, perplexity). The candidate with the higher similarity (lower divergence/perplexity) is chosen for the next iteration.
- **Core assumption:** A short, alignment-oriented fine-tuning step plus a calibration set metric reliably predicts the candidate's final post-recovery performance relative to the original model.
- **Evidence anchors:** 
  - Section 3.2: "We then apply a short recovery fine-tuning step to both candidates... before evaluation... The path criterion P scores the corresponding fine-tuned candidates... and decides whether width or depth pruning defines the next model."
  - Section 4.1.1: Random path selection performs comparably to metric-based criteria, suggesting that the *matching of pruned parameter counts* may be as crucial as the specific metric, but the iterative evaluation itself is key.
- **Break condition:** If calibration data is not representative (e.g., domain mismatch), the path metric becomes misleading, causing MoP to select a candidate that degrades task performance.

### Mechanism 3
- **Claim:** Parameter-matched pruning steps (pruning width to match the parameter count of one layer) ensure fair comparison between candidates and enable fine control over the compression trajectory.
- **Mechanism:** The algorithm computes the parameter fraction `c_t` of the layer selected for depth pruning and instructs the width pruner to remove exactly that fraction of total parameters. This creates equivalently-sized leaps in model size, making the path decision about *structure* rather than *magnitude*.
- **Core assumption:** The number of parameters removed is a valid proxy for comparing the impact of structurally different (depth vs. width) pruning operations.
- **Evidence anchors:** 
  - Section 3.2: "We want the smallest step possible... the minimum for layer pruning is one layer, so we use this as the basis and prune the equivalent number of parameters in width... ensures that we compare both candidates on a consistent basis."
  - Algorithm 1, lines 7-8: Explicitly computes `c_t = p_ℓ / TOTALPARAMS` to parameter-match the width prune.
- **Break condition:** If layer parameter counts vary dramatically (e.g., due to uneven width across layers), matching a single layer's parameters with width pruning may lead to disproportionate structural changes in some layers, harming stability.

## Foundational Learning
- **Concept:** Structured Pruning (Depth vs. Width)
  - Why needed here: Understanding the fundamental trade-off—depth removes whole transformer layers (coarse, acceleration-focused), width removes internal units like heads/neurons (fine-grained, accuracy-focused)—is essential to grasp MoP's unifying hypothesis.
  - Quick check question: What is the primary computational advantage of depth pruning over width pruning, and why might width pruning better preserve accuracy on downstream tasks?

- **Concept:** Calibration Metrics for Model Similarity (Cosine, KL, Perplexity)
  - Why needed here: The path criterion `P` relies on these metrics to quantify deviation from the original model. Knowing how each metric captures different aspects of behavior (angle, distribution, likelihood) is key to understanding the selection dynamics.
  - Quick check question: How does KL divergence between output token distributions differ from cosine similarity of logits as a measure of behavioral fidelity?

- **Concept:** Recovery Fine-Tuning (LoRA)
  - Why needed here: Pruning inevitably degrades performance; the paper's results depend on applying Low-Rank Adaptation to realign the pruned model. This step is crucial for both path evaluation (short tuning) and final model recovery.
  - Quick check question: Why is LoRA particularly suitable for fine-tuning a pruned LLM, and how might its rank and alpha parameters interact with the degree of pruning?

## Architecture Onboarding
- **Component map:** `Base Model (F) -> Depth Pruner (L) -> Depth Candidate; Base Model (F) -> Width Pruner (W) -> Width Candidate; Depth Candidate & Width Candidate -> Fine-Tuning -> Path Criterion (P) -> Selected Model -> (repeat)`. Calibration Set (D_cal) supports L, W, and P.
- **Critical path:** Initialize F(0)=F. Loop until target compression: (a) select layer ℓ* via L, compute its parameter count p_ℓ; (b) set c_t = p_ℓ / TOTALPARAMS; (c) generate F_width by width-pruning c_t via W; (d) generate F_layer by removing ℓ*; (e) short-tune both on D_tune (Alpaca subset) for 10×i steps; (f) compute path score P for each vs. F; (g) set F(t) to the winner. After loop, full recovery fine-tuning on Alpaca with LoRA.
- **Design tradeoffs:** 
  - Parameter matching precision: Width pruner must achieve high granularity to match a layer's exact parameter count; coarser methods break fair comparison.
  - Path criterion cost: Metric-based P requires forward passes; random avoids cost but may sacrifice optimality.
  - Calibration data fidelity: WikiText-2 may not represent target tasks; mismatch risks misleading decisions.
  - Short-tuning budget: 10×i steps is heuristic; too little fails alignment, too much adds overhead.
- **Failure signatures:**
  - High variance across random seeds indicates unstable path selection.
  - Disproportionate accuracy drop on specific benchmarks suggests over-pruning critical structures.
  - Low latency speedup despite high compression implies width-dominated pruning, causing poor hardware utilization.
  - Multimodal collapse after text-only RFT indicates damage to visual reasoning pathways.
- **First 3 experiments:**
  1. Baseline replication: Run pure depth and pure width pruning (same L and W as MoP) at 20%, 30%, 40% compression on LLaMA-2 7B. Establish Pareto front and confirm complementarity (replicate Figure 2).
  2. MoP with random path: Execute full MoP algorithm with random P. Verify it exceeds both pure-depth and pure-width baselines and matches/averages best competing methods from Table 2. Isolate combination effect from specific metric selection.
  3. Path criterion ablation: Compare random vs. cosine vs. KL vs. PPL on a single seed at fixed compression (e.g., 30%). Measure variance in final accuracy and path composition (% depth vs. width steps). Test if certain metrics lead to more depth/width choices and correlate with performance.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Why does text-only recovery fine-tuning (using Alpaca) effectively restore performance on visual benchmarks in pruned vision-language models (LLaVA-1.5), despite the recovery data lacking visual modalities?
- **Basis in paper:** The authors observe that text-only recovery fine-tuning can substantially restore multimodal performance and note this is the first to document such cross-modal transferability. They provide no theoretical explanation.
- **Why unresolved:** The paper presents the empirical result but does not investigate the underlying knowledge transfer or representation stabilization process.
- **What evidence would resolve it:** Ablations comparing text-only vs. multimodal fine-tuning; analysis of internal representations; controlled experiments varying text content.

### Open Question 2
- **Question:** What properties define an optimal path selection criterion (P) for MoP's iterative decisions between depth and width pruning? While random selection worked robustly, what specific metrics or learned predictors could further enhance the trade-off between accuracy and computational cost?
- **Basis in paper:** The paper tests cosine, KL, perplexity, and random, adopting random for simplicity. It states MoP is modular and can incorporate future pruning criteria, implying the optimal criterion is an open design choice.
- **Why unresolved:** No systematic search for what makes a good predictor; relationship between calibration-time metrics and final accuracy is not modeled; cost of metrics not evaluated in a formal Pareto sense.
- **What evidence would resolve it:** Large-scale correlation study of diverse metrics with final accuracy; development of a learned lightweight predictor; analysis of failure cases where the criterion makes suboptimal choices.

### Open Question 3
- **Question:** Is the parameter-matching strategy—where width pruning removes a number of parameters equivalent to one full layer—the theoretically optimal step size for maximizing accuracy at a given compression ratio, or could adaptive, non-uniform step sizing improve MoP's performance?
- **Basis in paper:** The method uses equal parameter removal per step for fair comparison, presented as a practical implementation detail, not an optimality claim.
- **Why unresolved:** No validation that equal removal is best; it's conceivable that different "exchange rates" between depth and width units could lead to better long-term retention of capability.
- **What evidence would resolve it:** Experiments varying the step size ratio; analysis of parameter sensitivity of different model components; theoretical study on the accuracy-vs.-compression landscape for mixed depth-width directions.

## Limitations
- Parameter matching after width pruning is unclear (whether layer parameters are recomputed dynamically or frozen).
- Calibration data (WikiText-2) may not represent downstream tasks; metric-based path selection could be domain-sensitive.
- Short fine-tuning budget (10×i steps) might inadequately recover candidates, producing misleading path scores.
