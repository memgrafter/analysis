# AIRS-Bench: a Suite of Tasks for Frontier AI Research Science Agents

## Quick Facts
*   **arXiv ID:** 2602.06855
*   **Source URL:** https://arxiv.org/abs/2602.06855
*   **Reference Count:** 40
*   **Primary Result:** Frontier LLM agents achieve human SOTA on only 4 of 20 novel ML research tasks under uniform 24-hour compute constraints, revealing substantial headroom for autonomous research.

## Executive Summary
AIRS-Bench introduces a benchmark of 20 agentic tasks spanning NLP, math, bioinformatics, and time series, designed to evaluate the full research lifecycle from problem formulation to code submission. Each task is defined by a standardized {problem, dataset, metric} format without baseline code. Evaluations of frontier LLMs using sequential (ReAct) and parallel (Greedy tree search) scaffolds show that parallel exploration yields superior performance. However, agents overall achieve a low average normalized score of 0.241 and a 55.1% valid submission rate, with human SOTA remaining far ahead (Elo 1674 vs. best agent 1146). The benchmark is open-sourced to drive progress in building capable AI research scientists.

## Method Summary
The benchmark consists of 20 tasks sourced from recent ML papers, each specified by a `project_description.md`, data splits (`train/`, `test/`), and an `evaluate.py` script. Agents operate in a sandbox with a 24-hour time limit on a single H200 GPU and access to a limited model cache (up to 2021). They must produce a valid `submission.csv` file. Two primary scaffold types are compared: sequential (ReAct) and parallel (Greedy tree search). Performance is aggregated via three metrics: valid submission rate (VSR), normalized score (NS), and Elo ratings, with a logarithmic "march-of-9s" transform used for NS to emphasize progress near SOTA.

## Key Results
*   Agents achieve human SOTA on only 4 tasks (e.g., *TextualClassificationSickAccuracy*, *TimeSeriesForecastingRideshareMAE*).
*   Overall valid submission rate is 55.1%, and average normalized score is 0.241.
*   Parallel scaffolds (Greedy) consistently outperform sequential ones (ReAct), and reasoning-oriented models (e.g., o3-mini) perform best.

## Why This Works (Mechanism)

### Mechanism 1: Scaffold Architecture Drives Solution Space Exploration
*   **Claim:** Parallel scaffolds (greedy tree search) enable more effective exploration of research solution spaces than sequential scaffolds (ReAct).
*   **Mechanism:** Parallel scaffolds maintain a population of candidate solutions and operators (Draft, Debug, Improve) within a search tree, allowing backtracking and diversity. Sequential scaffolds follow a single linear chain, risking premature convergence.
*   **Evidence:** [abstract] Greedy agents outperform ReAct in most cases. [section 6.1] Greedy CWM and GPT-4o significantly beat their one-shot counterparts, highlighting test-time search benefits.

### Mechanism 2: LLM Reasoning Capacity Scales with Task Difficulty
*   **Claim:** Larger, reasoning-oriented LLMs achieve higher normalized scores, especially on harder tasks, due to better planning and code generation.
*   **Mechanism:** Advanced LLMs produce more coherent plans, syntactically correct modular code, and better tool use, reducing wasted debugging steps and enabling sophisticated designs (e.g., stacking ensembles).
*   **Evidence:** [abstract] Reasoning models (gpt-oss-120b, o3-mini) perform better. [section 6.2] Successful solutions demonstrate complex design choices requiring strong synthesis.

### Mechanism 3: Normalization Method (March-of-9s) Amplifies Perceived Progress Gaps
*   **Claim:** The logarithmic "march-of-9s" transform (ϕ(s) = -log₁₀(|s - s_opt|)) makes incremental improvements near SOTA appear more significant, highlighting difficulty in reaching theoretical ceilings.
*   **Mechanism:** The transform is logarithmic in error distance; a jump from 0.90 to 0.99 (10% relative) yields a similar ϕ increase as from 0.99 to 0.999 (0.1% relative), as both represent a tenfold error reduction. This compresses the high-score region.
*   **Evidence:** [section 5.2] Explicit definition of the transform. [figure 9] NS clusters far below 1.0 even for relatively high raw scores (e.g., MAE 1.153 vs SOTA 1.185 yields NS ≈ 0.2).

## Foundational Learning
*   **Concept: Scaffold as Search Policy**
    *   *Why needed:* Understanding why tree search beats ReAct requires viewing the scaffold as a strategy for traversing a space of code solutions, not just a prompt template.
    *   *Quick check:* If a task's solution space has many local optima, which scaffold property is most important: breadth of exploration or depth of single-path refinement?
*   **Concept: Normalized Score as Relative Progress Metric**
    *   *Why needed:* Raw metrics (accuracy, MAE) are incomparable across tasks. Normalization maps them to a [0,1] scale relative to worst-observed and SOTA, enabling aggregate scores like average NS 0.241.
    *   *Quick check:* How would agent rankings change if using raw scores summed across tasks? What biases would that introduce?
*   **Concept: Valid Submission Rate as a Capability Proxy**
    *   *Why needed:* A high score requires first producing *any* runnable code that generates `submission.csv`. VSR captures the ability to complete the full pipeline (idea → runnable code → evaluation).
    *   *Quick check:* Is high VSR always correlated with high NS? What does a dissociation (high VSR, low NS) indicate?

## Architecture Onboarding
*   **Component map:**
    `metadata.yaml` -> `project_description.md` -> `prepare.py` (agent) / `evaluate_prepare.py` (eval) -> agent execution -> `submission.csv` -> `evaluate.py` -> metric JSON -> aggregation (VSR/NS/Elo).
    `utils.py` supports multiple tasks.
*   **Critical path:** Task spec creation (yaml, md, scripts) → Agent runs (24h/H200) → `submission.csv` generation → `evaluate.py` execution → metric logging → aggregate statistics.
*   **Design tradeoffs:**
    *   Uniform compute (24h/H200) prevents compute-advantaged dominance but may cap potential on harder tasks.
    *   No baseline code forces original ideation but complicates debugging agent failures.
    *   Single CSV output simplifies evaluation but loses intermediate artifacts (training curves, checkpoints).
*   **Failure signatures:**
    *   No `submission.csv` produced → VSR=0.
    *   `submission.csv` wrong shape/format → eval script error → invalid.
    *   Code crashes or exceeds 4h per node → node discarded.
    *   Agent hallucinates non-existent columns/models → caught by prepare/eval errors.
*   **First 3 experiments:**
    1. **Smoke test:** Run a One-Shot agent on *TextualClassificationSickAccuracy* to verify pipeline: files load, agent runs, `submission.csv` appears, `evaluate.py` outputs valid JSON.
    2. **Scaffold contrast:** Run Greedy vs. ReAct on 5 mixed-domain tasks with GPT-4o to observe exploratory behavior differences (tree vs. linear trace) and initial VSR gaps.
    3. **Normalization sanity check:** On one task, collect all valid scores, manually compute NS via march-of-9s and linear transforms, and verify against reported values.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** What specific limitations in agent scaffolds (e.g., context management, debugging, exploration strategies) most prevent agents from reaching or exceeding human SOTA on most AIRS-Bench tasks?
*   **Basis in paper:** [inferred] Agents exceed human SOTA in only 4 of 20 tasks and do not reach theoretical ceilings; performance varies by scaffold.
*   **Why unresolved:** Paper reports aggregate results but does not diagnose precise failure modes or bottleneck stages.
*   **What evidence would resolve it:** Fine-grained analysis of agent traces across tasks, identifying common error patterns (code crashes, metric miscalculation, iterative improvement stagnation) and correlating with scaffold design.

### Open Question 2
*   **Question:** How do computational restrictions (24-hour GPU limit, token context) quantitatively cap agent performance, and would lifting these constraints yield superhuman results on a broader set of tasks?
*   **Basis in paper:** [inferred] Authors acknowledge possible role of restrictions; average score is low (0.241 NS).
*   **Why unresolved:** All experiments use uniform constraints; potential upside of increased resources is unmeasured.
*   **What evidence would resolve it:** Follow-up experiments scaling time/compute for top agents, measuring score improvements per resource increment, and estimating saturation points per task.

### Open Question 3
*   **Question:** What are the root causes of the high invalid submission rate (average 55.1%), and how can agent architectures be made more reliable at producing valid, evaluatable outputs?
*   **Basis in paper:** [explicit] "On average, only 55.1% of the total submissions are considered valid" (Section 6).
*   **Why unresolved:** Paper does not categorize failure types (execution errors, format issues, timeout) or link them to scaffold/model characteristics.
*   **What evidence would resolve it:** Systematic logging and classification of failure modes across runs, followed by targeted interventions (better error handling, output validation scaffolds).

### Open Question 4
*   **Question:** Can the manual task creation and validation pipeline be automated to scale AIRS-Bench to more domains while preserving task quality and discriminative power?
*   **Basis in paper:** [inferred] Authors note "human validation procedures prevent the expansion at scale" and task selection was "semi-manual sourcing, creation, reviewing and verification."
*   **Why unresolved:** No automated alternative is proposed or evaluated; scalability is a future challenge.
*   **What evidence would resolve it:** Development of an automated pipeline (e.g., parsing new ML papers, extracting {problem, dataset, metric} triplets) and validation that auto-generated tasks maintain similar agent performance distributions.

### Open Question 5
*   **Question:** Beyond test-time compute, what other factors (e.g., pretraining data composition, tool integration, memory mechanisms) are most critical for achieving human-parallel autonomous research across diverse domains?
*   **Basis in paper:** [inferred] Study tests multiple LLMs and scaffolds but keeps other variables fixed (e.g., cache limited to 2021 models); performance varies widely but no ablation isolates non-compute factors.
*   **Why unresolved:** Experimental design focuses on scaffold and model comparisons under uniform constraints; contribution of other axes is unknown.
*   **What evidence would resolve it:** Controlled ablations varying access to pretrained models, tool richness, and memory while holding compute constant; analysis of successful agent traces to identify common strategies.

## Limitations
*   The 20-task suite spans only four domains (NLP, math, bioinformatics, time series), limiting generalizability.
*   The uniform 24-hour H200 budget may cap performance on harder problems.
*   The 55.1% valid submission rate reveals frequent agent failures, but root causes are not analyzed.
*   Human SOTA figures come from published papers, potentially differing in resources and evaluation conditions.
