# ARYA: A Physics-Constrained Composable & Deterministic World Model Architecture

## Quick Facts
*   **arXiv ID:** 2603.21340
*   **Source URL:** https://arxiv.org/abs/2603.21340
*   **Reference count:** 0
*   **Primary result:** Achieves state-of-the-art performance on 6 of 9 benchmarks with zero neural network parameters, deploying 111,572 specialized nano models in production with sub-millisecond inference and a perfect safety record.

## Executive Summary
ARYA proposes an alternative to monolithic neural network world models by constructing a hierarchical system-of-systems. It uses an autonomous agent (AARA) to orchestrate a vast, sparse set of specialized, physics-constrained nano models, all governed by an architecturally unfireable safety kernel. This design prioritizes determinism, formal verifiability, and compositional safety over end-to-end learning. The architecture claims state-of-the-art results on reasoning benchmarks and successful, scalable deployment across multiple industry domains, achieving high efficiency and zero safety bypasses.

## Method Summary
The core method is a composable architecture where a central orchestrator (AARA) manages a Context Network (a dependency graph of entities) and a Belief Network (for probabilistic state). Physical and logical reasoning is delegated to thousands of small, specialized nano models, each with 10K–100K parameters and constrained by formal physics rules. The Safety Kernel acts as a cryptographic gatekeeper, authorizing all state-changing operations via a formal verification "Safety Gauntlet" that uses tools like Z3. Models are improved through rapid evolutionary cycles (<20 seconds) and deployed via canary testing. The system operates without any historical customer data, supporting zero-shot deployment from domain specifications.

## Key Results
*   **Benchmark Dominance:** Achieved SOTA on 6 of 9 competitive benchmarks, including 99.89% on CLadder and 73.30 on PhysReason, using zero neural network parameters.
*   **Production Scalability:** Deployed 111,572 nano models across 7 industry domains with sub-millisecond inference latency and 87.5% sparse activation efficiency.
*   **Safety Guarantee:** Maintained a perfect safety record with zero successful bypasses across 40 documented attempts.

## Why This Works (Mechanism)
ARYA works by enforcing safety and correctness through architecture, not post-hoc policies. The unfireable Safety Kernel cryptographically signs all mutations, making bypass impossible without compromising the kernel's isolation. Determinism and accuracy stem from using small, specialized nano models trained on formal, physics-constrained data and verified via Z3, avoiding the black-box brittleness of large networks. Efficiency is gained through sparse activation, where the orchestrator's scheduler activates only the nano models relevant to the current contextual subgraph.

## Foundational Learning
*   **Context Network (DAG):** Stores entities (objects, variables) and causal dependencies. **Why needed:** Enables topological sorting for deterministic, order-aware simulation. **Quick check:** Validate that a change to node A correctly propagates only to downstream nodes B and C.
*   **Belief Network (Bayesian Filter):** Maintains probabilistic state estimates under uncertainty. **Why needed:** Fuses noisy sensor streams and handles missing data for robust perception. **Quick check:** Introduce a noisy observation; verify posterior probability updates converge correctly.
*   **Nano Model (Specialized Module):** A tiny (<100K parameter), single-purpose model (e.g., compute beam deflection). **Why needed:** Provides high accuracy within a narrow domain, enabling formal verification and evolutionary training. **Quick check:** For a 1D spring model, verify F = -kx output for varied inputs.
*   **Safety Gauntlet (Verification Pipeline):** Sequence of static analysis, formal verification (Z3), authorization, sandboxing, and regression testing. **Why needed:** Proves all state changes respect safety constraints before execution. **Quick check:** Inject a constraint-violating state change; ensure Z3 rejects it.
*   **AARA Orchestrator (Cognitive Loop):** The "sense-decide-act-learn" agent that activates nano models and updates the networks. **Why needed:** Provides the cognitive control layer that composes specialized knowledge into complex reasoning. **Quick check:** Trace a simple multi-step problem (e.g., "block on ramp") to see correct nano model sequencing.
*   **Sparse Activation Scheduler:** Selects which nano models to run based on the active context subgraph. **Why needed:** Achieves computational efficiency by avoiding unnecessary model evaluations. **Quick check:** Log activated models for a task; confirm only those relevant to the context are used.

## Architecture Onboarding
**Component Map (Plain Text):**
Safety Kernel (crypto/auth) -> AARA Orchestrator (control) -> Context Network (state DAG) & Belief Network (probabilities) -> Nano Models (specialized physics/logic) -> Domain Sensors/Actuators

**Critical Path:**
1.  Sense: Ingest sensor data, update Belief Network.
2.  Decide: AARA queries Context Network for relevant subgraph, Scheduler activates required Nano Models.
3.  Act: Proposed state change sent to Safety Kernel for Gauntlet verification.
4.  Learn: If authorized, state mutates; canary tests trigger evolutionary retraining of affected nano models.

**Design Tradeoffs:**
*   **Determinism vs. Flexibility:** Sacrifices generalist learning for verifiable, deterministic outcomes. Complex novel tasks require new nano models.
*   **Specialization Overhead:** Managing 100K+ models introduces orchestration complexity and initial knowledge engineering cost.
*   **Safety First:** The unfireable kernel may block legitimate but unusual state transitions if not all constraints are perfectly formalized.

**Failure Signatures:**
*   **Safety Bypass Attempt:** An unsigned state change observed in system logs or API traces.
*   **Cascade Error:** Incorrect prediction due to a misconfigured dependency edge in the Context Network, causing wrong topological order.
*   **Sparse Activation Failure:** Low activation efficiency (<50%) indicating poor scheduler heuristics or over-connected context graph.

**First 3 Experiments:**
1.  **1D Beam Deflection:** Implement Euler-Bernoulli nano model. Verify output against analytical solution and that Safety Kernel blocks inputs violating material property constraints.
2.  **Safety Gauntlet:** Attempt to mutate a state variable (e.g., pressure) beyond a certified safety bound. Confirm Z3 rejects it and no state change occurs.
3.  **Activation Scheduler Logging:** Run a multi-domain task (e.g., "predict object fall with friction"). Collect activation sequence; manually confirm only models for kinematics, friction, and gravity were used, achieving ~87.5% sparsity.

## Limitations
*   **Nano Model Training:** The "<20 second training cycle" and evolutionary operator details are underspecified, making replication of the self-improvement loop unclear.
*   **Orchestration at Scale:** Mechanisms for scheduling 111K+ models and enabling cross-domain knowledge transfer are not elaborated, casting doubt on the scalability claims from a minimal prototype.
*   **Safety Kernel Implementation:** The "unfireable" and "zero bypass" assertions depend on unspecified process isolation, cryptographic enforcement, and API design, lacking an independent audit trail.
