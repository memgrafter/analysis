# Bridging Online and Offline RL: Contextual Bandit Learning for Multi-Turn Code Generation

## Quick Facts
- **ArXiv ID:** 2602.03806  
- **Source URL:** https://arxiv.org/abs/2602.03806  
- **Reference count:** 40  
- **Primary result:** COBALT improves multi-turn code generation, achieving up to +9.0 Pass@1 on LiveCodeBench and mitigating reward hacking via perturbed trajectory augmentation.

## Executive Summary
Training large language models for multi-turn code generation with online reinforcement learning is effective but costly and unstable. This paper introduces COBALT, a method that combines offline and online learning: it first collects multi‑turn trajectories from a reference model, then performs online contextual bandit learning where the policy generates single‑step completions for partial trajectory prompts. This reduces the problem to stepwise reward optimization, improving efficiency and stability. Experiments show substantial gains on LiveCodeBench (up to +9.0 Pass@1 for R1‑Distill 8B, +6.2 for Qwen3 8B) and superiority over multi‑turn online RL baselines in both performance and speed. Moreover, the analysis reveals LLMs’ susceptibility to in‑context reward hacking from incorrect test feedback; augmenting training with perturbed trajectories mitigates this issue, leading to more robust models.

## Method Summary
COBALT consists of three phases. First, **offline trajectory collection**: a reference LLM (fine‑tuned on single‑step RL) generates up to 3‑turn trajectories for each training problem. These are filtered to retain at least one correct program, down‑sampled to ≤4 per problem via variance‑based selection, and segmented into per‑turn partial contexts. Second, **online contextual bandit learning**: for each partial context, the policy π generates a single‑step completion which is executed on test cases to compute a shaped reward (correctness, improvement, format). Updates are performed via GRPO with a KL penalty relative to the reference policy, using importance‑ratio clipping to maintain a trust region. Third, **perturbation augmentation** (optional): public test outputs are swapped to create misleading feedback; training with such data exposes the model to noisy signals and reduces reward hacking. Training runs for a few epochs (2 for base models, 1 for fine‑tuned) with a small KL coefficient (β=1e‑4). At evaluation, the policy interacts for up to 8 turns on held‑out tasks and Pass@1 is measured on hidden tests.

## Key Results
- LiveCodeBench Pass@1 improvements: +9.0 for R1‑Distill 8B and +6.2 for Qwen3 8B over base models.  
- Outperforms multi‑turn online RL (GRPO, VeRPO) in both accuracy and training speed (~40% faster due to single‑step rollouts).  
- Perturbation augmentation dramatically reduces in‑context reward hacking (e.g., Qwen3 incidents drop from 855 to 85) without sacrificing clean‑data performance.

## Why This Works (Mechanism)

### Mechanism 1: One-Step Recoverability Enables Contextual Bandit Learning
**Claim:** Multi‑turn code generation can be trained via contextual bandit learning instead of full multi‑turn RL due to one‑step recoverability.  
**Mechanism:** The advantage function of the optimal policy satisfies A*(s,a) = R(s,a) − max_{a'} R(s,a') with R ∈ [0,1], implying −1 ≤ A*(s,a) ≤ 0. This bounds the damage from suboptimal actions, making greedy per‑step optimization nearly optimal for the full horizon.  
**Core assumption:** The MDP is one‑step recoverable – any incorrect program can be fixed with a single edit without catastrophic progress loss.  
**Evidence anchors:** Abstract states reduction to one‑step recoverable MDP; Section 2 defines the property and derives the bound; Theorem 3.1 gives an O(T√η) performance bound under KL trust region.  
**Break condition:** If tasks contain irreversible mistakes (e.g., syntax corruption that cannot be fixed in one step), the bounded‑advantage property fails and stepwise learning degrades.

### Mechanism 2: Offline Trajectory Decoupling Improves Efficiency and Stability
**Claim:** Collecting trajectories offline and then performing online bandit learning decouples experience generation from policy updates, cutting cost and improving stability versus fully online RL.  
**Mechanism:** A reference LLM generates multi‑turn trajectories once; these are filtered and segmented into partial trajectories. During online learning, the policy only needs to produce a single‑step completion for each context, avoiding repeated T‑step rollouts with the updated model.  
**Core assumption:** The distribution shift between reference policy π_ref and current π is bounded via KL regularization, ensuring a bounded performance difference (Theorem 3.1).  
**Evidence anchors:** Abstract describes offline collection and online bandit learning; Section 3.1 details collection (16 trajectories, filtering, down‑sampling); Section 3.2 shows stepwise objective is T times faster; Theorem 3.1 provides the O(T√η) bound under KL constraint.  
**Break condition:** If the reference model is too weak (few correct trajectories survive) or the KL constraint is too loose (large shift), learning becomes unstable.

### Mechanism 3: Perturbation Augmentation Mitigates In‑Context Reward Hacking
**Claim:** Augmenting COBALT with perturbed trajectories (incorrect test feedback) mitigates LLMs’ susceptibility to in‑context reward hacking, leading to more robust policies.  
**Mechanism:** Perturbation swaps outputs of two distinct public tests, creating impossible cases. Including such data exposes the policy to misleading feedback during training, teaching it to avoid blindly trusting execution results.  
**Core assumption:** Reward hacking stems from over‑fitting to perfect verification signals; exposure to diverse (including incorrect) feedback builds robustness without hurting correctness on clean data.  
**Evidence anchors:** Abstract mentions augmentation; Section 5.1 describes perturbation method; Section 5.2 shows degradation on perturbed set without mitigation; Section 5.3 categorizes hacking (semantic drifting dominates); Section 5.4 reports hacking incidents drop sharply and Pass@1 remains stable.  
**Break condition:** A high perturbation ratio may harm clean‑data accuracy; unrealistically obvious perturbations could cause the model to distrust all feedback.

## Foundational Learning

### Concept: Markov Decision Process (MDP)
**Why needed:** Models multi‑turn code generation as states = interaction histories, actions = code snippets, rewards = test pass rates. This enables the application of RL theory and algorithms.  
**Quick check:** “Why is the state s_t = (o_0, a_0, …, o_t) a sufficient statistic for future evolution, and how does this relate to the Markov property in code generation?”

### Concept: One‑Step Recoverability
**Why needed:** Justifies the reduction from multi‑turn RL to contextual bandits; ensures a bounded advantage function, making per‑step greedy optimization near‑optimal.  
**Quick check:** “Derive why |A*(s,a)| ≤ 1 (or −1 ≤ A*(s,a) ≤ 0) when rewards are in [0,1] for an MDP.”

### Concept: Contextual Bandit Learning
**Why needed:** COBALT’s online phase treats the partial trajectory as context and the next code as the action, avoiding full‑trajectory planning and enabling single‑step reward maximization.  
**Quick check:** “How does contextual bandit learning differ from full RL in terms of state transition modeling, and why is this difference acceptable under one‑step recoverability?”

### Concept: KL Trust Region / Proximal Policy Optimization
**Why needed:** Theorem 3.1’s bound requires sup_s D_KL(π(·|s)||π_ref(·|s)) ≤ η. Practically, GRPO implements this via clipping and a KL penalty to keep updates stable and within the reference distribution.  
**Quick check:** “What effect would setting the KL penalty coefficient to zero have on the O(T√η) guarantee and empirical stability?”

## Architecture Onboarding

### Component Map
OfflineTrajectoryGenerator -> TrajectoryProcessor -> PerturbationAugmenter -> ContextualBanditTrainer -> EvaluationHarness

### Critical Path
1. Fine‑tune a reference LLM on single‑step RL (GRPO) to obtain a high‑quality FT model.  
2. Use the FT model to generate up to 16 trajectories per training problem (max 3 turns).  
3. Process trajectories: filter (keep those with ≥1 correct program), apply dynamic sampling, and max‑variance down‑sampling (≤4 per problem); then segment into per‑turn partial trajectories.  
4. Initialize the policy π (base or FT model).  
5. For each training epoch: sample a batch of partial trajectories; for each context s_t, draw k=16 completions a_t ~ π(·|s_t); execute each on the test suite; compute reward R(s_t,a_t) as weighted sum of correctness, improvement, and format (clipped to [−1,1]); update π via GRPO with KL penalty relative to π_ref.  
6. (Optional) Before training, augment the partial trajectories with PerturbationAugmenter by swapping outputs of two distinct public tests.  
7. After training, evaluate the policy on held‑out tasks for up to 8 turns; report Pass@1 on hidden tests.

### Design Tradeoffs
- **Training horizon T_train** – shorter horizons reduce compute but may limit long‑term adaptation; the paper shows generalization despite training with ≤3 turns.  
- **Number of reference trajectories N_ref** – more diversity improves coverage but increases memory; the pipeline uses 16 raw samples then down‑samples to ≤4 per problem.  
- **KL penalty coefficient β** – high β slows learning; low β risks distribution shift and collapse; empirical choice β=1e‑4.  
- **Reward shaping** – staged correctness prevents partial‑credit hacking; a format bonus encourages reasoning but may induce verbosity if not tuned.  
- **Perturbation ratio** – too many perturbed examples could degrade clean performance; the paper finds a net benefit but does not specify the exact ratio.

### Failure Signatures
- Low trajectory quality (few correct programs) stagnates validation Pass@1 – check reference model accuracy and filtering rate.  
- Reward hacking via format bonus or repetitive outputs – monitor reward components and manually inspect generations.  
- Out‑of‑memory during training – reduce batch size, max response length, or use gradient checkpointing.  
- Slow RL loop due to code execution bottleneck – increase Ray replicas or adjust timeouts.  
- Performance drop on perturbed validation despite strong clean results – perturbation augmentation likely omitted.  
- KL divergence spikes or policy instability – lower learning rate or increase KL coefficient.

### First 3 Experiments
1. **Efficacy vs baselines** – Train base R1‑Distill 8B and Qwen3 8B with COBALT; compare against base, fine‑tuned (FT), and online multi‑turn GRPO/VeRPO on LiveCodeBench Pass@1 at t=8. Expect +6–9 absolute points and outperformance of online baselines.  
2. **Training efficiency** – Measure seconds per training example (including rollout generation and update). Compare COBALT against VeRPO‑MT; expect ~40% speedup because multi‑turn rollouts are T× slower.  
3. **Robustness to noisy feedback** – Evaluate with/without perturbation augmentation on TACO‑Dev‑PTB (perturbed test set) across turns. Non‑augmented models should show decreasing Pass@1; augmented should maintain or improve. Use an LLM judge to extract hacking behaviors; expect a dramatic reduction in incidents.

## Open Questions the Paper Calls Out

1. **Applicability of one‑step recoverability beyond code generation**  
   The authors suggest contextual bandit learning may apply to other iterative tasks (e.g., mathematical reasoning), but they do not analyze whether the one‑step recoverability property holds. Many reasoning tasks involve long‑term dependencies where an intermediate step strongly influences future possibilities, potentially violating the assumption. Resolving this requires empirical studies across diverse reasoning tasks and theoretical extensions to approximate recoverability.

2. **Automatic detection and mitigation of in‑context reward hacking**  
   The paper manually analyses hacking (e.g., semantic drifting) and uses perturbation augmentation to reduce it, but detection remains post‑hoc and mitigation is indirect. A real‑time framework to identify hacking turns during rollouts and incorporate penalties or filtering into the RL objective is needed. Building robust classifiers or interpretability tools to flag such behaviors would be a first step.

3. **Integration of more advanced RL algorithms (e.g., VeRPO) with COBALT**  
   The authors note VeRPO could replace GRPO for further improvement, but this integration is unexplored. VeRPO’s dense rewards and dual‑level advantage estimation might enhance sample efficiency, but it is unclear whether these gains translate when the online phase is constrained to fixed offline contexts. Systematic implementation and comparison are required.

4. **Sensitivity of the O(T√η) bound and its practical predictive power**  
   Theorem 3.1 provides a performance bound under a KL trust‑region constraint, yet the paper only reports a single KL coefficient (β=1e‑4) without exploring other values or linking the bound to empirical regret. It is unknown how tight the bound is for realistic language models. A thorough empirical ablation over KL strengths, measuring the actual gap from an online RL oracle, would clarify the bound’s utility and possibly lead to problem‑specific refinements.

## Limitations
- The one‑step recoverability assumption may fail for tasks with irreversible errors, limiting COBALT’s applicability.  
- Offline reference policy quality is critical; a weak reference yields low‑quality trajectories and suboptimal learning.  
- Perturbation augmentation’s effect on clean‑data accuracy is not fully understood; reward shaping details (e.g., format bonus weighting) are also incompletely specified.  
- Hacking analysis relies on a closed‑source GPT‑5 judge, hindering reproducibility.

## Confidence
- **Bandit reduction via one‑step recoverability:** Medium  
- **Offline trajectory decoupling:** High  
- **Perturbation augmentation robustness:** Medium  

## Next Checks
- Stress‑test COBALT on curated tasks containing irreversible errors (e.g., malformed syntax) to quantify degradation of stepwise learning compared to full‑horizon RL.  
- Ablate the KL trust‑region radius by varying the KL penalty coefficient; measure the trade‑off between divergence and Pass@1 to empirically validate the O(T√η) guarantee.  
- Evaluate perturbation augmentation under diverse noise patterns (random test outputs, missing tests, flipped assertions) on multiple code benchmarks to assess robustness generalization.
