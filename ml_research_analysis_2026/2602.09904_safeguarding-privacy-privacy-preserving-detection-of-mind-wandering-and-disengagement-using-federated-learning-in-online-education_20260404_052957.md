# Safeguarding Privacy: Privacy-Preserving Detection of Mind Wandering and Disengagement Using Federated Learning in Online Education

## Quick Facts
- arXiv ID: 2602.09904
- Source URL: https://arxiv.org/abs/2602.09904
- Reference count: 40
- Primary result: Federated learning achieved equal or superior F1 scores compared to centralized learning on four out of five benchmark datasets for student disengagement detection.

## Executive Summary
The increasing use of webcam-based automated detection of student disengagement (e.g., mind wandering, boredom) in online education raises significant privacy concerns due to the central collection of sensitive facial video. This paper introduces a cross-device federated learning (FL) framework as a privacy-preserving alternative: local bi-LSTM models are trained on each student's device using extracted features (facial expressions, gaze, and optional eyeglass-specific cues), and only model updates are communicated to a server for aggregation, never the raw video.

Evaluated on five public datasets (Colorado, Korea, Germany, EngageNet, DAiSEE) with six FL algorithms, the method achieves F1 scores equal to or higher than centralized learning on four datasets. Notably, FedAvg outperforms centralized baselines on Colorado (46.2% vs 43.9%), Germany (52.6% vs 50.0%), EngageNet (57.4% vs 51.4%), and DAiSEE (26.2% vs 25.7%). Adding MeGlass features benefits non-mind-wandering tasks but not mind wandering detection, likely due to limited glasses-wearing participants. The results demonstrate that FL can provide effective, privacy-aware disengagement monitoring without sacrificing accuracy.

## Method Summary
The authors developed a federated learning pipeline for binary classification of student disengagement. Video data from five datasets (Colorado, Korea, Germany, EngageNet, DAiSEE) are preprocessed into 10-second clips (124 frames at 640×480). For each clip, features are extracted: OpenFace provides 709-dimensional facial landmark, gaze, and head pose features; EmoNet contributes 8-dimensional emotion features. For glass-handling, a ResNet18 fine-tuned on MeGlass yields a 256-dimensional glass feature vector per frame; its mean and standard deviation across the clip are concatenated to the bi-LSTM output. The model is a three-layer bidirectional LSTM with 100 hidden units per layer, followed by a linear projection layer.

In the cross-device FL simulation, each user is a client. Each round, 50% of clients are randomly sampled; each trains its local model for 8 epochs using SGD (batch size 4) and sends weight updates to the server. The server aggregates updates using one of six algorithms: FedAvg, FedAdam, FedProx, MOON, FedAwS, or TurboSVM-FL. The global model is then redistributed. Baselines include centralized training on all data and bagging of 15 bi-LSTMs. Performance is evaluated primarily with binary F1 score, along with precision, recall, accuracy, and AUC, using user-independent train/test splits.

## Key Results
- Federated learning (FedAvg) achieved higher F1 scores than centralized learning on four datasets: Colorado (46.2% vs 43.9%), Germany (52.6% vs 50.0%), EngageNet (57.4% vs 51.4%), and DAiSEE (26.2% vs 25.7%); only on Korea did centralized slightly lead (44.8% vs 44.2%).
- Among FL algorithms, FedProx, MOON, and FedAwS often matched or exceeded FedAvg, with FedProx showing robust performance across datasets.
- Adding MeGlass (eyeglass) features improved F1 on EngageNet and DAiSEE (boredom/off-task) but had inconsistent or negative effects on mind-wandering datasets, attributed to low representation of glasses-wearing users.

## Why This Works (Mechanism)
### Mechanism 1: Privacy through local data retention
- **Claim:** Federated learning preserves user privacy by avoiding raw video data transmission to a central server.
- **Mechanism:** Local models are trained on individual user devices using only the device's video data. Only model parameter updates (gradients or weights) are sent to a central server, which aggregates these updates (e.g., via FedAvg) to improve a global model. Raw facial video never leaves the user's device.
- **Core assumption:** Video data containing faces is highly sensitive and its central collection poses significant privacy and re-identification risks.
- **Evidence anchors:** 
  - [abstract] explicitly positions FL as a "privacy-preserving alternative" that enables "decentralized model training" to "safeguard users’ data privacy."
  - [section 2.2] details FL's workflow: "clients train...using their local datasets" and "server aggregates the collected trained models" with "no data exchange required."
  - [corpus] Corpus focuses on FL for anomaly/botnet detection; privacy mechanisms are analogous but direct educational FL evidence is sparse. Weak evidence for *educational* application specifics.
- **Break condition:** The privacy guarantee breaks if model updates themselves can be inverted to reconstruct raw data (membership inference attacks), if a client's device is compromised, or if the aggregation server is malicious.

### Mechanism 2: Mitigating data heterogeneity via advanced aggregation
- **Claim:** Federated learning can match or exceed centralized learning performance on this task by mitigating the negative effects of data heterogeneity (non-IID data) through specific aggregation algorithms.
- **Mechanism:** Standard FedAvg can suffer from "client drift" when user data distributions vary widely (e.g., different lighting, camera angles, individual behavior). Algorithms like FedProx, MOON, or FedAwS add regularization terms or contrastive losses locally, or adjust aggregation server-side, to keep local models closer to the global optimum, improving convergence and final performance.
- **Core assumption:** The natural heterogeneity in real-world online learning data (different devices, environments, user habits) is substantial and harms naive FL aggregation.
- **Evidence anchors:**
  - [section 3.3] defines data heterogeneity as a "common challenge" causing "client drift" and shows visual evidence of user-specific clusters in feature space.
  - [section 5.3] reports that "federated learning algorithms showed strong potential to outperform the centralized learning models on most datasets" and attributes this to better handling of individual patterns compared to bagging.
  - [corpus] Neighbors discuss FL heterogeneity (e.g., "FedProc for non-iid data"), but not in this educational context. Weak direct corpus support.
- **Break condition:** The performance benefit disappears if heterogeneity is extreme (e.g., some clients have only one class), communication rounds are insufficient, or local update steps are too large, causing irreconcilable client drift.

### Mechanism 3: Eyeglass-specific feature robustness
- **Claim:** Incorporating eyewear-specific features (from MeGlass) can improve model robustness for users with glasses by providing signals when standard gaze features are corrupted by reflections.
- **Mechanism:** A pre-trained ResNet18 on the MeGlass dataset extracts a 256-dim "glass feature" vector from each frame. The mean and std of these vectors over a 10-second clip are concatenated to the bi-LSTM output. This allows the final classifier to learn to down-weight unreliable gaze features when glasses are detected.
- **Core assumption:** OpenFace gaze extraction fails silently (high confidence but wrong values) when glasses cause reflections, and an external glass detector can flag this condition.
- **Evidence anchors:**
  - [section 3.1] describes the glasses problem: "reflection on the spectacles might make their eyes unrecognizable" while OpenFace confidence remains high.
  - [section 5.2] presents Table 2, showing MeGlass features improved F1 scores on EngageNet and DAiSEE (non-mind-wandering tasks) but not consistently on mind-wandering datasets.
  - [corpus] No direct mention of MeGlass or this specific feature in neighbor papers. Weak corpus evidence.
- **Break condition:** The glass detector itself fails on certain frame conditions (e.g., extreme glare, partial occlusion), the MeGlass features are not discriminative enough for the specific online-learning population, or the feature vector dimension introduces noise without sufficient labeled data to learn its utility.

## Foundational Learning
- **Concept: Federated Learning (Cross-Device)**
  - Why needed here: The entire framework hinges on training a model across many personal devices (tablets, laptops) without moving their private video data. Understanding client-server rounds, local epochs, and aggregation (FedAvg) is essential.
  - Quick check question: "What is the key difference between cross-device and cross-silo FL, and why is cross-device used here?"
- **Concept: Non-IID Data and Client Drift**
  - Why needed here: Data is naturally heterogeneous across users (different environments, glasses usage, behaviors). This is the primary technical challenge the paper addresses with different FL algorithms. Understanding why naive averaging fails is key.
  - Quick check question: "How does FedProx's proximal term aim to reduce client drift compared to standard FedAvg?"
- **Concept: Feature Extraction for Behavioral Cues**
  - Why needed here: The model does not process raw pixels. It relies on pre-trained networks (EmoNet for emotion, OpenFace for landmarks/gaze) to produce time-series of interpretable behavioral features. Understanding what these features represent (e.g., gaze direction, action units) is crucial for interpreting model decisions.
  - Quick check question: "Why is OpenFace's reported confidence score insufficient to guarantee correct gaze estimation for users with glasses?"

## Architecture Onboarding
- **Component map:**
  1.  **Client (User Device):** Holds local video dataset. Performs: (a) Frame extraction & pre-processing (downsampling, face detection), (b) Feature extraction via OpenFace & EmoNet (and optional MeGlass), (c) Local bi-LSTM training for E epochs, (d) Sends model update (weights/gradients) to server.
  2.  **Server:** Maintains global model. Performs: (a) Initialization & broadcast of global model, (b) Receives updates from selected clients, (c) Aggregation (FedAvg, FedAdam, etc.), (d) Updates and rebroadcasts global model.
  3.  **Model:** Bi-LSTM backbone (3 layers, 100 hidden units) with optional MLP projection layer. Input: sequence of feature vectors (EmoNet+OpenFace[+MeGlass stats]). Output: binary class probability.
- **Critical path:** Feature extraction (OpenFace/EmoNet on 10-sec clip) → local bi-LSTM forward/backward pass → compute update → send to server → server aggregates K selected client updates → new global model → next round.
- **Design tradeoffs:**
  - **Privacy vs. Accuracy:** FL inherently protects raw data but can introduce communication overhead and potential accuracy loss from non-IID data unless advanced aggregators (FedProx, MOON) are used.
  - **Computational Load:** Feature extraction (OpenFace) is heavy; doing this on client devices limits participation on low-power devices. The paper assumes capable devices (laptops/tablets).
  - **Personalization:** The global model may not fit all users perfectly. The paper does not explore personalized FL heads, which could improve per-user accuracy.
- **Failure signatures:**
  - **Convergence failure:** Global model loss stagnates or increases across rounds, often due to high heterogeneity or poor local learning rates.
  - **Performance collapse on minority class:** F1 score drops sharply, especially for rare "mind wandering" labels, indicating the global model is ignoring hard-to-learn patterns.
  - **High variance across seeds:** Standard deviation in F1 > 10%, suggesting unstable training, possibly from client sampling variance or sensitive hyperparameters.
- **First 3 experiments:**
  1.  **Baseline Replication:** Re-run centralized bi-LSTM on all five datasets (user-independent split) to establish performance baseline matching reported numbers (e.g., ~43.9% F1 on Colorado). Verify feature extraction pipeline consistency.
  2.  **FL Algorithm Benchmark:** Implement FedAvg, FedProx, MOON, FedAwS, FedAdam, TurboSVM-FL. For each dataset, run FL simulation (virtual clients, same user split as centralized) and compare F1/Precision/Recall against centralized baseline. Tune client LR for FedAvg first, then use for others.
  3.  **Ablation: Feature Sets:** Train centralized and FedAvg models on (a) EmoNet only, (b) OpenFace gaze only, (c) EmoNet+OpenFace full, (d) EmoNet+OpenFace gaze. Measure performance change to understand feature contribution and robustness of FL vs. central to feature choice.

## Open Questions the Paper Calls Out
1. How can feature extraction be made robust to eyeglass reflections for all users in privacy-preserving detection?
2. What are the specific privacy vulnerabilities introduced by federated learning in this educational context, and how can they be mitigated?
3. To what extent can federated learning truly personalize models for individual students without compromising model generalizability and stability?
4. How can the system reliably handle non-facial scenarios (e.g., occlusion, poor posture) to avoid distracting false positives in a deployed real-time feedback system?
5. Can the detection performance be meaningfully improved by incorporating multimodal data beyond video (e.g., interaction logs, audio) in a federated setting?

## Limitations
- Preprocessing and feature extraction details (e.g., OpenFace failure thresholds, illumination filtering) are underspecified, hindering exact replication.
- Federated learning simulation parameters (client sampling density, server optimizer settings, bagging scheme) lack full disclosure, affecting reproducibility and robustness assessment.
- The approach is tightly coupled to OpenFace/EmoNet, introducing vendor-specific biases, and the MeGlass feature integration yields inconsistent benefits due to data imbalance, with no analysis of failure modes.

## Confidence
- Privacy preservation: High for data non-exodus, Low for full privacy guarantees.
- Performance parity/superiority: Medium.
- Heterogeneity handling: Medium.
