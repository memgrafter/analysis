# SHARP: Short-Window Streaming for Accurate and Robust Prediction in Motion Forecasting
## Quick Facts
- **arXiv ID:** 2603.28091
- **Source URL:** https://arxiv.org/abs/2603.28091
- **Reference count:** 40
- **Primary result:** SHARP achieves state-of-the-art streaming performance with low latency (33 ms on an RTX 3090 GPU) on the Argoverse 2 multi-agent benchmark, demonstrating superior robustness across varying context lengths and datasets while maintaining competitive single-agent results.

## Executive Summary
SHARP tackles the problem of accurate motion forecasting in streaming scenarios where observations arrive in short, non-overlapping windows. Its key innovations are an instance-aware context streamer that preserves consistent agent representations, target-centric feature extraction from previous prediction endpoints, and a dual training objective that jointly optimizes for streamed and fixed-window inputs. These elements enable robust predictions even with highly variable history lengths. Evaluations on the Argoverse 2 multi-agent benchmark show state-of-the-art streaming performance with only 33 ms of latency per inference on an RTX 3090 GPU. The model also demonstrates strong generalization across different context lengths and datasets, while remaining competitive on standard single-agent metrics.

## Method Summary
SHARP processes motion data in short, fixed-duration chunks (e.g., 1 second) for low-latency streaming. Each chunk is encoded with a transformer-based encoder that extracts agent and lane features. To maintain consistent agent states across chunks, the framework uses an instance-aware cross-attention streamer (`fIA`) that fuses the previous chunk’s encoded context into the current one, guided by a mask that links agents by their tracking IDs. Moreover, the endpoints of the trajectories predicted in the prior step serve as anchors to collect nearby map and agent tokens (within a radius), forming target-centric features that are encoded separately. Both agent-centric (from the current window) and target-centric features are fed into a DETR-like decoder with alternating cross-attention to produce multimodal forecasts. During training, a dual loss (`L_dual = L_stream + L_chunk`) is applied: one branch uses the streamed context while the other discards it, ensuring robustness to varying history lengths. For multi-agent scenes, a global consistency module refines joint predictions by attending across all agents and modes. At inference, the model processes windows sequentially, updating the context and prior endpoints after each step.

## Key Results
- Achieves state-of-the-art streaming performance on the Argoverse 2 multi-agent benchmark.
- Low inference latency: 33 ms per scenario on an NVIDIA RTX 3090.
- Demonstrates robustness across a wide range of context lengths (0.5–8 s) and datasets (Argoverse 1, nuScenes).

## Why This Works (Mechanism)
### Mechanism 1: Instance-aware context streaming
- **Claim:** Explicit instance-aware context streaming maintains consistent latent agent representations across non-overlapping short windows, preventing representation drift as agents evolve.
- **Mechanism:** A cross-attention-based module (`fIA`) incorporates the previous scene context `S_{t-1}^{enc}` into the current window. An attention mask, derived from agent instance correspondences (tracking IDs), applies a learned bias to steer focus toward matching agents across time steps, rather than relying solely on spatial proximity.
- **Core assumption:** Agents can be reliably tracked across consecutive short windows (e.g., 1-second chunks), providing explicit correspondence signals.
- **Evidence anchors:** 
  - [abstract] "...leverages an instance-aware context streaming to maintain and update latent agent representations across inference steps."
  - [section 3.2] "We introduce instance-aware context streaming by leveraging an attention mask... selectively modulates cross-attention weights, steering focus toward matching instances via a learned bias parameter."
  - Neighbor papers (e.g., RealMotion [36]) use implicit positional streaming, making this a differentiating design choice.
- **Break condition:** Tracking failures (ID switches) or abrupt scene changes (e.g., occlusions) that break instance correspondence, causing the mask to misalign representations.

### Mechanism 2: Target-centric feature extraction
- **Claim:** Target-centric feature extraction from prior prediction endpoints focuses contextual attention on geopolitically relevant map regions, enhancing robustness when agent histories are short.
- **Mechanism:** The K endpoints from previous predictions `F^{t-1}` serve as anchors. For each endpoint, all nearby agent and lane tokens within a radius (e.g., 30 m) are aggregated into a reduced token set `C_t`. These endpoint-centric features are then fused with agent-centric scene features during decoding.
- **Core assumption:** The endpoints of recent predictions are meaningful indicators of future goal regions, and relevant context (e.g., lanes, other agents) is spatially concentrated around them.
- **Evidence anchors:** 
  - [abstract] "...extracts target-centric features from prior prediction endpoints."
  - [section 3.2] "We leverage the K trajectory endpoints from the previous inference step... as anchors to extract additional contextual features... by aggregating all tokens within a compact region of interest centered at the corresponding endpoint."
  - Neighbor "Streaming Real-Time Trajectory Prediction Using Endpoint-Aware Modeling" [Pru] explicitly studies endpoint-aware modeling, supporting relevance but not the specific streaming integration.
- **Break condition:** Highly inaccurate prior predictions (e.g., large endpoint errors) or dynamic obstacles (e.g., jaywalking pedestrians) not captured in static map context.

### Mechanism 3: Dual training objective
- **Claim:** Dual training with streaming (`L_stream`) and single-chunk (`L_chunk`) objectives forces the encoder to produce representations that are robust across both gradually accumulating and fixed-length contexts.
- **Mechanism:** During training, every short input chunk generates two outputs: one using the streamed context from previous windows (as in deployment) and one using only the current chunk (no streaming). The combined loss `L_dual = L_stream + L_chunk` optimizes for accuracy under both conditions simultaneously.
- **Core assumption:** A model trained only on full-history or fixed-window streaming will overfit to specific context lengths; exposure to both during training yields adaptable representations.
- **Evidence anchors:** 
  - [abstract] "A dual training objective further enables consistent forecasting accuracy across diverse observation horizons."
  - [section 3.5] "We propose a dual training loss... we compute separate losses for each case: L_stream for predictions... and L_chunk for predictions... The final objective is given by L_dual = L_stream + L_chunk."
  - Neighbors like FLN [46] and POP [42] address varying lengths via calibration or distillation, but not via simultaneous streaming/chunk optimization.
- **Break condition:** Extremely short initial contexts (e.g., single frame) where `L_chunk` dominates and streaming benefits are minimal, or severe distribution shift between training and deployment context-length distributions.

## Foundational Learning
- **Concept:** Local Coordinate Normalization  
  **Why needed here:** Agent states and lane polylines are expressed relative to an agent's most recent pose or lane center (Section 3.1). This removes global position dependence, allowing the model to learn motion patterns and lane shapes independently of absolute location—critical for generalizing across diverse scenes and for streaming where reference frames shift.  
  **Quick check question:** Why is expressing trajectories in an agent's local frame preferable to global (world) coordinates for streaming prediction?

- **Concept:** Cross-Attention for Context Propagation  
  **Why needed here:** The instance-aware context streamer (`fIA`) uses cross-attention to fuse `S_{t-1}^{enc}` into `S_t`. Unlike self-attention, cross-attention treats previous context as key/value and current window as query, enabling the model to ask "what from the past is relevant now?" while handling different token counts (Section 3.2).  
  **Quick check question:** In the context streaming module, what are the roles of the query, key, and value tensors, and why is their separation important for handling evolving agent sets?

- **Concept:** Winner-Takes-All Training Strategy  
  **Why needed here:** Multi-modal trajectory prediction requires assigning the highest probability to the best-fitting hypothesis among K modes. The Smooth L1 regression and cross-entropy classification losses are applied only to the mode with the smallest displacement error (Section 3.5, B.6). This prevents gradient dilution from competing modes.  
  **Quick check question:** If all K predicted modes receive regression gradients, what problem arises, and how does winner-takes-all mitigate it?

## Architecture Onboarding
- **Component map:**  
  `[A, L] → [fA, fL] → [A_enc, L_enc] → St → fIA(St, S_{t-1}^{enc}) → St_stream → fS → St_enc → fD(St_enc, Ct_enc, Q) → [F, P]`, where `Ct_enc` is produced by aggregating tokens within a radius of prior endpoints `F^{t-1}` via `fTC`. Optional: trajectory relay `fR` and global consistency module for multi-agent.

- **Critical path:** The core computational flow is `[A, L] → [fA, fL] → [A_enc, L_enc] → St → fIA(St, St-1_enc) → St_stream → fS → St_enc → fD(St_enc, Ct_enc, Q) → [F, P]`. The instance mask in `fIA` and endpoint aggregation for `Ct` are critical differentiators.

- **Design tradeoffs:**  
  1. **Window size vs. latency:** Smaller history windows reduce per-pass latency but risk losing long-term patterns; SHARP compensates via streaming.  
  2. **Instance mask reliance:** Using tracking IDs improves long-context accuracy but introduces brittleness to ID switches; the model must implicitly fall back on positional streaming if masks fail.  
  3. **Dual training cost:** Simultaneous `L_stream` and `L_chunk` computation doubles forward passes during training, increasing memory and time.

- **Failure signatures:**  
  1. **Degradation on short Tcl:** Without dual training, performance drops for `Tcl=1s` (e.g., mFDE6 increases by ~1.0 m).  
  2. **High collision rates in multi-agent:** Naive combination of marginal predictions yields many collisions; the global consistency module reduces them drastically (5,533 vs. 973 after refinement).  
  3. **Latency spikes with large batches:** Streaming modules add overhead; latency grows with batch size (35 ms @ B=32 vs. 33 ms @ B=16).

- **First 3 experiments:**  
  1. Ablate the instance-aware streamer (disable `fIA`) and expect strong degradation on long context lengths.  
  2. Sweep the weighting of `L_stream` vs. `L_chunk` in the dual loss to trade off short- vs. long-context accuracy.  
  3. Inject Gaussian noise into the prior endpoints `F^{t-1}` before target-centric aggregation to measure robustness.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** How does SHARP's short-window streaming approach handle motion trajectories involving long-term dependencies or abrupt maneuvers that are not immediately apparent from recent observations?
- **Basis in paper:** [inferred] from the failure cases shown in Supplementary Fig. 7, where SHARP fails to predict turns after waiting, driveway maneuvers, and unexpected stops. Additionally, SHARP uses short observation windows (e.g., 1 s) as described in Section 3.5, which may limit the capture of infrequent but critical long-term patterns.
- **Why unresolved:** The model's reliance on incremental updates from short contexts may not adequately accumulate evidence for behaviors that depend on extended history or sudden changes. The robustness to varying context lengths is demonstrated, but the nature of abrupt maneuvers is not specifically addressed.
- **What evidence would resolve it:** Evaluate SHARP on datasets or scenarios with annotated abrupt maneuvers, such as emergency vehicles or sudden lane changes, and measure performance degradation. Compare with models that use longer contexts to isolate the impact of window size on such events.

### Open Question 2
- **Question:** What is the operational limit of the instance-aware context streaming mechanism in scenarios with high instance association noise, such as frequent ID switches or prolonged occlusions?
- **Basis in paper:** [inferred] from the instance-aware context streaming design in Section 3.2, which uses an attention mask based on instance correspondences. Supplementary Table 8 tests robustness to synthetic mask perturbations, but real-world tracking errors may be more complex and correlated.
- **Why unresolved:** The synthetic perturbations in Table 8 are random and independent, whereas real-world tracking errors often occur in patterns (e.g., during occlusions) that could exploit the model's reliance on instance masks. The paper claims recovery from tracking discontinuities due to short windows, but this is not rigorously validated under realistic noise conditions.
- **What evidence would resolve it:** Conduct experiments on datasets with documented tracking failures, such as in dense crowds or with poor sensor coverage. Introduce realistic ID switch patterns and measure the impact on streaming performance, comparing with implicit context streaming methods.

### Open Question 3
- **Question:** Does the fixed-radius target-centric feature extraction (30 m as per Supplementary B.2) optimally capture relevant context across diverse scenarios, or would an adaptive radius improve robustness to prediction errors?
- **Basis in paper:** [inferred] from the description of target-centric features in Section 3.2 and Supplementary B.2, where a fixed radius is used without ablation. Supplementary Table 10 shows that adding noise to endpoints degrades performance, suggesting sensitivity to endpoint accuracy.
- **Why unresolved:** The fixed radius assumes uniform context importance, but in reality, the relevance of map features may vary with agent intent, scene geometry, or prediction uncertainty. An adaptive radius could better handle erroneous endpoints or varying map densities.
- **What evidence would resolve it:** Ablate the radius parameter on multiple datasets and correlate optimal radius with scenario characteristics such as agent speed, map complexity, or prediction confidence. Implement a learnable or dynamic radius mechanism and compare performance.

### Open Question 4
- **Question:** How does the global consistency module for multi-agent predictions scale with the number of agents per scene in terms of both accuracy and latency, particularly in dense traffic environments?
- **Basis in paper:** [inferred] from the multi-agent extension in Section 3.4 and Supplementary B.7, where self-attention is applied over all agents and modes. Latency is reported in Supplementary Table 17 for single-agent, and 30 ms per scenario for multi-agent, but without breakdown by agent count.
- **Why unresolved:** The global attention operation has quadratic complexity with respect to the number of agents, so for scenes with many agents (e.g., urban intersections), both computational cost and potential accuracy benefits from interaction modeling may change. The paper does not analyze this trade-off.
- **What evidence would resolve it:** Measure latency and joint prediction metrics (e.g., avgMinADE6) on scenes with varying numbers of agents, using datasets with high-density traffic or by subsampling agents. Plot performance against agent count to identify scalability limits.

## Limitations
- **Instance-aware streaming reliance:** Consistent tracking IDs are required; ID switches or occlusions can break the correspondence mask and cause representation drift.
- **Target-centric aggregation sensitivity:** Prior endpoints must be roughly accurate; large errors or dynamic obstacles not in the static map can mislead context selection.
- **Dual training scope:** May not generalize to extremely short histories (<1 s) or shifts in context-length distribution between training and deployment.
