# QuEPT: Quantized Elastic Precision Transformers with One-Shot Calibration for Multi-Bit Switching

## Quick Facts
- **arXiv ID:** 2602.12609
- **Source URL:** https://arxiv.org/abs/2602.12609
- **Reference count:** 8
- **Primary result:** QuEPT enables single-pass calibration for multi-bit elastic quantization of Transformers, reducing training time to 1/26 of PTMQ while matching or exceeding SOTA accuracy across ViTs, LLMs, and MLLMs.

## Executive Summary
QuEPT is a post-training quantization method for Transformer-based models that allows dynamic switching between multiple target bit-widths with only a single calibration pass. It introduces two core innovations: Multi-Bit Token Merging (MB-ToMe), which fuses token features across precision groups to create more quantization-robust representations, and Multi-Bit Cascaded Low-Rank Adapters (MB-CLoRA), which share a hierarchical low-rank parameter matrix across bit-width groups to strengthen inter-precision correlations. By jointly optimizing clipping thresholds and cascaded LoRA in a block-wise reconstruction process, QuEPT eliminates the need for repeated optimization per bit-width, significantly reducing deployment overhead while maintaining high accuracy.

## Method Summary
QuEPT calibrates a pre-trained full-precision Transformer in one shot. For each block, it selects three bit-widths (low, mid, high) and computes the block’s output under each. MB-ToMe merges these outputs: tokens with high cosine similarity between high- and low-bit features are retained as high-bit; all others are fused via a weighted sum of features from all three precisions. This merged input feeds the next block and serves as the reconstruction target. Simultaneously, MB-CLoRA learns a shared low-rank decomposition (matrices B and A) where the effective rank allocated to a bit-width increases as precision decreases (e.g., low-bit uses the full rank, high-bit only a leading slice). During calibration, the loss between the full-precision block output and the quantized block output (using current LoRA slice and per-precision clipping thresholds) is minimized via backpropagation, updating only the LoRA slice and clipping parameters for the sampled bit-width. After processing all blocks, the model stores all LoRA slices and clipping parameters; at inference, selecting a bit-width uses the corresponding slice and thresholds without re-optimization.

## Key Results
- On ViT-S with W4A4, QuEPT achieves 6.2% higher ImageNet accuracy than ERQ.
- On LLaMA2-7B with W4A4, QuEPT improves average zero-shot accuracy by 7.07% over QuaRot.
- On LLaVA-OneVision across mixed precision, QuEPT gains 1.5–4.3% average accuracy over MBQ.
- Training time is reduced to 1/26 of PTMQ's overhead on ViT-B while supporting real-time bit-width switching.

## Why This Works (Mechanism)

### Mechanism 1: Multi-Bit Token Merging (MB-ToMe)
**Claim:** MB-ToMe mitigates inter-bit-width conflicts by selectively preserving robust high-precision token features while fusing less stable ones, maintaining balanced feature distributions across all target precisions during block-wise reconstruction.

**Mechanism:** For each Transformer block, features from the three bit-width groups (low, mid, high) are computed. Token-wise cosine similarity between high-bit and low-bit features identifies "stable" tokens (high similarity). These stable tokens retain their high-bit representation; all others undergo weighted fusion (λ₁, λ₂, λ₃) of high, mid, and low-bit features. This creates a merged input `X'ₖ` for the next block, promoting a smoother, more quantization-robust feature distribution.

**Core assumption:** Tokens with high similarity between high-bit and low-bit representations are inherently robust to quantization noise and can serve as reliable anchors. Fusing divergent tokens reduces outlier-driven instability that disproportionately harms low-bit widths.

**Evidence anchors:**  
- Abstract: "Multi-Bit Token Merging (MB-ToMe) to dynamically fuse token features across different bit-widths, improving robustness during bit-width switching."  
- Section 3.1: Detailed formulation (Eq. 6), design rationale (Case 3 selective merge beats random/uniform), and Figure 3 showing more uniform feature distributions post-merging (lower K-S statistic).  
- Corpus: Weak direct corroboration; neighbor papers like "Instance-Aware Group Quantization" and "MetaAug" also address feature smoothing/grouping for PTQ, suggesting a recognized research direction for robustness.

**Break condition:** If the token similarity metric (e.g., cosine similarity between high/low-bit features) fails to correlate with actual quantization error per token, the selective retention policy may discard critical information or preserve noisy tokens, degrading performance across all bit-widths.

### Mechanism 2: Multi-Bit Cascaded Low-Rank Adapters (MB-CLoRA)
**Claim:** MB-CLoRA strengthens inter-bit-width parameter correlation by sharing a unified low-rank parameter matrix `(B, A)` across all bit-widths, with ranks allocated hierarchically (`r_b` increases as bit-width decreases), allowing low-bit widths to inherit compensation from higher bits.

**Mechanism:** Instead of separate LoRAs per bit-width, a single `B ∈ ℝ^{p×r}` and `A ∈ ℝ^{r×q}` are trained. For a target bit-width `b`, the effective compensation is `R(b) = B[:, :r_b] A[:r_b, :]`, where `r_b` is the cumulative rank up to its tier (e.g., for low-bit `b∈B_L`, `r_b = r_h + r_m + r_l`). During training, one bit-width per tier is sampled per iteration; gradients update the shared `A, B` and clipping parameters `α, β` simultaneously for the sampled `b`. This forces `R(b)` for lower bits to include `R(b')` of higher bits as leading submatrices.

**Core assumption:** Quantization error components for coarser (lower-bit) representations encompass, but are not identical to, those of finer (higher-bit) representations. A hierarchical low-rank basis can capture shared error modes.

**Evidence anchors:**  
- Abstract: "Multi-Bit Cascaded Low-Rank Adapters (MB-CLoRA) to strengthen correlations between bit-width groups."  
- Section 3.2: Formal rank allocation (Eq. 8), cascading definition `R_L = R_M + ΔR_l`, and ablation in Table 4 showing MB-CLoRA improves low-bit (W4A4) accuracy over independent/Fully Shared LoRAs for LLaMA2-7B.  
- Corpus: Neighbors like "LoftQ" and "QA-LoRA" combine LoRA with quantization, but use independent or separate LoRAs; MB-CLoRA’s cascading is a novel sharing pattern for elastic quantization.

**Break condition:** If quantization error patterns are not hierarchically structured (i.e., low-bit errors are not a superset of high-bit errors), cascading may force inappropriate parameter sharing, harming high-bit performance (as hinted in Table 6 where MB-CLoRA alone slightly hurt W6A6/W8A8).

### Mechanism 3: One-Shot Block-Wise Reconstruction
**Claim:** One-shot block-wise reconstruction with joint optimization of clipping thresholds (`α, β`) and cascaded LoRA enables a single calibration pass to produce a model deployable at any predefined bit-width without re-optimization.

**Mechanism:** Calibration proceeds block-by-block. For each block, weights `W` are frozen. For a sampled set of three bit-widths (one per tier), the quantized weight formula `Ŵ_b = s_w^b · clip(⌊(W + B_b A_b)/s_w^b⌉ + z_w^b, -2^{b-1}, 2^{b-1}-1)` is used, where `s_w^b` depends on learnable `α^b, β^b` (Eq. 4-5). The block’s output under each `b` is compared to the full-precision block output using MAE loss on the **MB-ToMe merged features** `X'` from the previous block. Gradients update only the LoRA slice for `b` and its `α^b, β^b`. After all blocks are processed, the model has a full set of `(A, B, α, β)`; at inference, selecting bit-width `b` uses the corresponding `R(b)`, `α^b, β^b`.

**Core assumption:** The reconstruction error for a bit-width `b` can be effectively minimized in isolation during calibration if the input features `X'` are already robustly fused (via MB-ToMe), and if parameter sharing via MB-CLoRA does not require bit-width-specific fine-tuning.

**Evidence anchors:**  
- Abstract: "reconstructs block-wise multi-bit errors with one-shot calibration... can dynamically adapt to various predefined bit-widths by cascading different low-rank adapters... without repeated optimization."  
- Section 3: Pipeline description, Eq. 1 (global objective), Eq. 9 (per-iteration loss), and Table 1 showing QuEPT matches/exceeds SOTA with single optimization vs. multi-bit PTMQ requiring repeated rounds.  
- Corpus: Neighbors like "MatGPTQ" and "MoBiQuant" also pursue multi-bit/elastic PTQ but use different strategies (MSB slicing, token-adaptive bits); QuEPT’s one-shot claim is empirically supported by its training time reduction (1/26 of PTMQ).

**Break condition:** If the calibration data slice is not statistically representative of the full deployment data distribution, the one-shot learned `(A, B, α, β)` may not generalize, causing varying degradation across bit-widths. The block-wise independence assumption could also fail if errors propagate non-locally.

## Foundational Learning
- **Concept: Post-Training Quantization (PTQ)**  
  *Why needed here:* QuEPT is a PTQ method; it assumes a pre-trained full-precision model and aims to quantize it without gradient updates on the full dataset, using only a small calibration set. Understanding PTQ’s core steps (scale/zero-point calculation, rounding, reconstruction loss) is prerequisite.  
  *Quick check question:* What is the typical trade-off in PTQ between calibration data size and quantized model accuracy? How does QuEPT’s block-wise reconstruction differ from a simple min-max calibration?

- **Concept: Token Merging/Pruning (e.g., ToMe)**  
  *Why needed here:* MB-ToMe is directly inspired by token merging techniques. The engineer must grasp how token features are merged (e.g., via similarity-based selection or weighted average) and the impact on model capacity and computational cost.  
  *Quick check question:* In standard token merging, what is the goal of merging? How does MB-ToMe’s goal differ (i.e., cross-bit-width robustness vs. pure efficiency)?

- **Concept: Low-Rank Adaptation (LoRA)**  
  *Why needed here:* MB-CLoRA builds on LoRA’s principle of decomposing weight updates into low-rank matrices. The engineer needs to understand LoRA’s injection point (added to weights before quantization), rank selection, and how it compensates for quantization error without full fine-tuning.  
  *Quick check question:* In standard LoRA for LLMs, where are the low-rank matrices applied? Why might placing LoRA *inside* the quantization operator (as in QuEPT) change the optimization dynamics compared to QLoRA?

## Architecture Onboarding

### Component Map
Frozen FP Weights (W) -> MB-CLoRA (shared B, A) -> Quantization Operator (using per-bit clipping α,β) -> MB-ToMe (merges features from three bit-widths) -> Next block input

### Critical Path
1. Start from block 0 input X (calibration data).
2. For block k: Compute X^H, X^M, X^L by running block k’s forward pass with b_H, b_M, b_L using Ŵ_b (which includes R(b)).
3. Apply MB-ToMe to X^H, X^M, X^L → X'.
4. Compute MAE loss between X' and the full-precision block k output F^l(W; X).
5. Backpropagate loss to update only A, B (all slices) and α^{b_H}, β^{b_H}, α^{b_M}, β^{b_M}, α^{b_L}, β^{b_L}.
6. X' becomes input to block k+1.
7. Repeat for all blocks.

### Design Tradeoffs
- **LoRA rank partition (r_h, r_m, r_l) vs. total rank:** Higher total rank improves capacity but increases storage. Cascading gives low bits more rank (inheriting high bits) at the expense of high-bit capacity. Independent partitions give each bit equal rank but lose sharing benefits.
- **MB-ToMe selection threshold (p%):** Higher p preserves more high-bit tokens (better high-bit fidelity) but reduces fusion benefits for low-bit robustness. Lower p increases fusion but risks losing critical high-precision information.
- **Loss function (MAE vs. MSE):** Paper shows MAE works better (Table 6). MAE may be less sensitive to outliers in reconstruction loss.

### Failure Signatures
- **High perplexity (LLMs) / Low accuracy (ViTs) on all bit-widths:** Indicates MB-ToMe is over-fusing, discarding essential high-bit token information. Check p% is too low or λ weights too balanced.
- **Good high-bit, poor low-bit performance:** Suggests MB-CLoRA cascading is insufficient; low-bit slices R(b_L) lack compensatory capacity. Increase total rank or r_l.
- **Inconsistent performance across calibration samples:** MB-ToMe’s token selection is data-dependent; unstable similarity scores indicate poor token robustness metric. Consider alternative similarity metrics (e.g., based on activation magnitude variance).
- **No improvement over independent LoRAs:** Cascading may be harming; check if error patterns are truly hierarchical (Table 4 shows benefit only for low bits).

## Open Questions the Paper Calls Out
1. **Integrate outlier mitigation into QuEPT for LLMs?**  
   Basis: Authors admit no outlier handling; suggest combining with methods like SpinQuant.  
   Why unresolved: Outliers cause quantization errors; QuEPT ignores them.  
   What evidence would resolve: Adding outlier mitigation to QuEPT and showing improved W4A4 results on LLaMA models.

2. **Overcome QuEPT's performance drop at extremely low bit-widths (2-3 bits)?**  
   Basis: Paper says performance constrained at extremely low bits, needs exploration.  
   Why unresolved: Current compensation (MB-ToMe/MB-CLoRA) insufficient for severe error.  
   Evidence: Modify these components; report gains on ViT-S/LLaMA2-7B at W2A2/W3A3.

3. **How sensitive is QuEPT to calibration data size/content? Can cost reduce?**  
   Basis: Uses small sets (1024 images, 128 samples) but no analysis.  
   Why: Calibration dependency impacts practicality.  
   Evidence: Vary calibration set size/domain; measure variance; find minimal requirements.

4. **Does QuEPT generalize to encoder-decoder transformers (e.g., T5, BART)?**  
   Basis: Only ViTs/decoder LLMs/MLLMs tested; encoder-decoder not evaluated.  
   Why: Different architectures may break reconstruction assumptions.  
   Evidence: Apply QuEPT to T5/BART; evaluate on summarization/translation; compare to PTQ baselines.

## Limitations
- MB-ToMe hyperparameters (top‑p% threshold, fusion weights) and MB-CLoRA details (rank partitions, initialization) are not fully disclosed.
- Token similarity computation specifics (quantized vs. full-precision, dimension-wise vs. pooled) are unclear.
- Calibration setup (batch size, learning rate, optimizer, steps) is unspecified, hindering exact reproduction.
- Evaluation limited to ViT, LLaMA, LLaVA; other architectures (e.g., encoder-decoder) unverified.

## Confidence
- **Mechanism 1 (MB-ToMe):** High – backed by strong ablation (Table 5) and feature distribution improvement (Figure 3).
- **Mechanism 2 (MB-CLoRA):** Medium – ablation shows low‑bit gains (Table 4) but slight high‑bit drop (Table 6); hierarchical error sharing assumption may not always hold.
- **Mechanism 3 (One‑shot reconstruction):** Medium – empirical speed‑accuracy trade‑off (Table 1) is convincing, yet depends on correct hyperparameters and calibration data.
