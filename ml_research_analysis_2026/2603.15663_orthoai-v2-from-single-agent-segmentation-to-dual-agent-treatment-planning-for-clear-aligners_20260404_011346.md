# OrthoAI v2: From Single-Agent Segmentation to Dual-Agent Treatment Planning for Clear Aligners

## Quick Facts
- **arXiv ID:** 2603.15663  
- **Source URL:** https://arxiv.org/abs/2603.15663  
- **Reference count:** 17  
- **Primary result:** Achieved a 21% relative gain in planning quality score (92.8 ± 4.1 vs 76.4 ± 8.3) on a synthetic benchmark of 200 crowding scenarios, with feasible plan rate increasing from 78% to 89% and CPU inference time of 4.2 ± 0.8 seconds.

## Executive Summary
OrthoAI v2 evolves from v1’s single-agent segmentation by introducing a dual-agent architecture that fuses DGCNN segmentation with CHaRM-based landmark detection via a confidence-weighted orchestrator. This addresses v1’s core limitations—insufficient landmark precision, an opaque scalar quality score, and absent treatment staging simulation. The system incorporates a composite six-category biomechanical scoring model and a multi-frame treatment simulator that produces temporally coherent 6-DoF tooth trajectories with evidence-based staging rules. On a synthetic benchmark, v2 achieves a planning quality score of 92.8 ± 4.1—a 21% relative improvement over v1—while increasing feasible plans from 78% to 89% and maintaining CPU deployability at 4.2 seconds.

## Method Summary
The pipeline processes an intraoral scanner (IOS) point cloud and a target movement plan through two parallel agents: Agent 1 (DGCNN) segments teeth to compute centroids and orientations, while Agent 2 (CHaRM) directly regresses 80 dental landmarks and per-tooth presence confidence. A confidence-weighted orchestrator fuses their outputs—by default averaging centroids with weights (0.4, 0.6) favoring CHaRM’s accuracy—or invokes Agent 1 sequentially for teeth with low confidence (pₜ < 0.5). The fused tooth states feed a biomechanical engine that evaluates movement against tooth-type-specific limits across six categories (biomechanics, staging, attachments, IPR, occlusion, predictability), applying severity penalties. Finally, a frame generator estimates required aligners from translation/rotation thresholds (δtrans=0.25mm, δrot=2°), then creates F = A × r frames using SLERP for rotations and linear interpolation for positions, applying staging rules (e.g., extrusion deferred until effective time t ≥ 0.6). The system is trained on synthetic data derived from Teeth3DS and IOSLandmarks-1k, with Agent 1 trained on segmentation masks and Agent 2 on heatmaps and presence labels.

## Key Results
- Planning quality score improved to 92.8 ± 4.1 from v1’s 76.4 ± 8.3 (21% relative gain).
- Feasible plan rate increased from 78% to 89%.
- Inference time on CPU: 4.2 ± 0.8 seconds.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Fusing segmentation (DGCNN) and landmark detection (CHaRM) via a confidence-weighted orchestrator improves geometric fidelity for torque/tip planning.  
**Mechanism:** Agent 2 provides direct landmark prediction; orchestrator averages centroids from both agents with default weights (w₁=0.4, w₂=0.6) based on Agent 2’s superior accuracy and lower latency. In sequential mode, Agent 1 is invoked only for teeth with low confidence (pₜ < 0.5).  
**Core Assumption:** Landmark-level precision (~1.1–1.4 mm MEDE) is necessary for accurate incisor torque and canine rotation estimation.  
**Evidence Anchors:** Abstract and section 3.2 describe fusion and error reduction; corpus shows related work but no direct validation of agent fusion.  
**Break Condition:** Systematic miscalibration of CHaRM confidence scores (e.g., overconfidence on missing teeth) could degrade fusion performance below single-agent DGCNN.

### Mechanism 2
**Claim:** Decomposing the quality score into six biomechanically motivated sub-categories with severity penalties yields more interpretable and clinically actionable feedback.  
**Mechanism:** Each tooth’s movements are evaluated against per-tooth-type limits across six categories with assigned weights (biomechanics 30%, staging 20%, attachments 15%, IPR 10%, occlusion 10%, predictability 15%). Critical/warning findings incur multiplicative penalties (×0.85, ×0.97), replacing v1’s scalar ratio.  
**Core Assumption:** Clinicians need separable failure modes rather than an opaque single score.  
**Evidence Anchors:** Abstract mentions composite model; section 4.2 defines weights and penalties; Table 1 lists movement limits.  
**Break Condition:** If clinical weightings (e.g., biomechanics 0.30) do not reflect orthodontic prioritisation, the score may misrank plans (e.g., over-penalising minor IPR).

### Mechanism 3
**Claim:** Generating multi-frame 6-DoF tooth trajectories via SLERP interpolation with evidence-based staging rules enables ClinCheck-style 4D visualisation and validates per-aligner movement budgets.  
**Mechanism:** Aligner count A estimated from translation/rotation thresholds (δtrans=0.25mm, δrot=2°). For each frame, positions linearly interpolated; rotations use SLERP. Effective time t⁽ʲ⁾_eff applies staging rules (e.g., extrusion deferred until t ≥ 0.6) to respect biomechanical principles.  
**Core Assumption:** Staging rules derived from clinical guidelines ensure biologically plausible trajectories.  
**Evidence Anchors:** Abstract describes multi-frame simulator; section 5.3 gives extrusion rule; corpus lacks direct evidence.  
**Break Condition:** Poorly calibrated δtrans/δrot thresholds could underestimate required aligners, making trajectories appear infeasible.

## Foundational Learning
- **Point-cloud deep learning (DGCNN, PointMLP):** Both agents process raw IOS point clouds; Agent 1 uses DGCNN for segmentation, Agent 2 uses a PointMLP encoder for heatmap regression. *Why needed:* Enables direct processing of unstructured 3D scans without voxelisation. *Quick check:* How does a dynamic graph CNN (DGCNN) build spatial neighborhoods versus a fixed-k NN in PointNet?
- **Clear aligner biomechanical limits:** The composite scoring engine penalises movements exceeding tooth-type-specific thresholds (from Glaser [13] and Kravitz [14]). *Why needed:* Ensures planned movements are achievable within material constraints of aligners. *Quick check:* Why is extrusion (Tz < 0) flagged as “critical” when exceeding 1.5 mm?
- **Treatment staging theory:** The frame generator implements staging rules (e.g., extrusion delay) to produce clinically plausible trajectories over F frames. *Why needed:* Aligner treatment must respect biological response timelines and anchorage requirements. *Quick check:* How does the effective time scaling t⁽ʲ⁾_eff in Eq. 10 enforce anchorage before extrusion?

## Architecture Onboarding
### Component map:
Input (IOS point cloud P + movement plan M) -> Agent 1 (DGCNN segmentation) -> Agent 2 (CHaRM landmark detection) -> Orchestrator (fusion) -> Biomechanical Engine (scoring) -> Frame Generator (trajectories) -> Output (JSON with sub-scores, findings, frames). Parallel mode: Agents 1 and 2 run concurrently; sequential mode adds confidence check between them.

### Critical path:
P -> Agent 1 & 2 (parallel) -> Orchestrator fusion -> Biomechanical Engine -> Frame Generator -> Output. Sequential mode inserts confidence check after Agent 2, invoking Agent 1 only for low-confidence teeth.

### Design tradeoffs:
- Parallel vs sequential: Parallel maximises accuracy (default weights w₂=0.6) at higher CPU cost (4.2s); sequential halves time but risks quality loss if CHaRM fails.
- Agent 2 embedding size (emb=128 vs 512): Smaller embedding reduces CPU memory/time but increases landmark error (1.38mm vs 1.12mm).
- Composite score weighting: Heuristic clinical weightings may misalign with surgeon preferences if poorly calibrated.

### Failure signatures:
- High critical alert count (>3): Unrealistic plan or poor agent fusion.
- Unrealistic trajectories (inter-frame rotation >5°): Staging rule violation or aligner count underestimation.
- Orchestrator fallback to single-agent: CHaRM confidence collapse or segmentation failure.

### First 3 experiments:
1. Validate Agent 2 (CHaRM) on 50 synthetic scans: target MEDE < 1.5mm, GPU time < 0.4s.
2. Test orchestrator modes on 20 edge cases (missing teeth, severe crowding): compare quality and CPU; ensure sequential quality drop <10% vs parallel.
3. Verify frame generator staging: For Tz < -1.0mm, assert t⁽ʲ⁾_eff = 0 for t < 0.6; check mean inter-frame displacement ≈ 0.25mm/1.8°.

## Limitations
- Training data splits, augmentations, and checkpoints undisclosed, hindering exact replication.
- Orchestrator confidence definition (pₜ) and miscalibration risk not detailed.
- Synthetic benchmark (200 crowding scenarios) may not reflect real-case variability, risking overestimated performance.
- Agent 2’s embedding size (emb=128) trade-off versus full model (emb=512) not quantified for torque/rotation sensitivity.

## Confidence
- Dual-agent fusion improves geometric fidelity: Medium (synthetic 21% gain shown, but no real-scan validation).
- Decomposed scoring enhances interpretability: Medium (theoretically motivated, absent clinician study).
- Multi-frame staging yields feasible trajectories: Low (evidence-based rules untested against actual treatment outcomes).
