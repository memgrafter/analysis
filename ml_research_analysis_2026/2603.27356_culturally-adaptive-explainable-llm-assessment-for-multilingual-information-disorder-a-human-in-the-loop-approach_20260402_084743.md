# Culturally Adaptive Explainable LLM Assessment for Multilingual Information Disorder: A Human-in-the-Loop Approach

## Quick Facts
- **arXiv ID**: 2603.27356
- **Source URL**: https://arxiv.org/abs/2603.27356
- **Reference count**: 0
- **Primary result**: Proposed a Human-in-the-Loop adaptive prompting framework; pilot results pending.

## Executive Summary
This paper tackles the cultural bias of large language models (LLMs) in multilingual information disorder assessment, where English‑centric training leads to misalignment with non‑English contexts. The authors design a Human‑in‑the‑Loop (HITL) framework that grounds LLM reasoning by dynamically retrieving target‑language exemplars from a curated bank of human‑written rationales (the InDor corpus). The pilot evaluates this adaptive prompting (English instructions plus retrieved exemplars) against static baselines on Farsi and Italian news, using automated metrics and human cultural appropriateness ratings. While primary results are not yet reported, the work outlines a systematic approach to reduce cultural misalignment and demographic disparity in LLM‑based assessments.

## Method Summary
The method builds an **Exemplar Bank** from the InDor corpus through a rigorous curation pipeline: filtering unusable records, removing article‑level binary conflicts, and resolving severe disagreements using rationale length as a tie‑breaker. The bank is split into a retrieval resource and a held‑out test set (100 Farsi and 100 Italian items). For each test item, the system computes sentence‑transformer embeddings and retrieves the top‑k semantically similar exemplars from the same‑language subset. The LLM (LLaMA 4 Maverick or Mixtral‑8x22B) is prompted under four conditions: zero‑shot in the target language (B0), static few‑shot in the target language (B1), English instructions with retrieved target‑language exemplars (M1), and target‑language instructions with the same retrieved exemplars (A1). Outputs are evaluated via severity macro‑F1, span token‑overlap F1, BERTScore, and human blinded A/B ratings of cultural appropriateness. The full architecture also includes an iterative correction loop where experts revise model outputs, enriching the exemplar bank over time.

## Key Results
- Framework and pilot design are fully specified, but empirical results are not yet available.
- Expected outcome: adaptive prompting (M1) will outperform static baselines (B1) in cultural alignment and reduce demographic disparity.
- Evaluation metrics combine automated scores with human judgments to capture cultural nuances.

## Why This Works (Mechanism)

### Mechanism 1
**Claim**: Dynamically retrieved target‑language exemplars ground the LLM’s reasoning in culturally specific patterns.  
**Mechanism**: For a test item in language ℓ, embeddings compute similarity; top‑k in‑context examples from the ℓ‑subset of the Exemplar Bank are injected into the prompt. This steers the model toward localized framing.  
**Break conditions**: Bank lacks diversity or contains low‑quality rationales; retrieval matches superficial features; LLM ignores context due to length limits.

### Mechanism 2
**Claim**: Pairing English task instructions with retrieved target‑language exemplars improves alignment compared to target‑language instructions.  
**Mechanism**: English instructions provide precise task definition, while exemplars supply cultural context; the two are decoupled to exploit strong English instruction‑tuning.  
**Break conditions**: English instructions cause misunderstanding of non‑English nuances; target‑language instructions are essential; language tension arises.

### Mechanism 3
**Claim**: Strict article‑level deduplication and conflict resolution yield a stable, non‑contradictory exemplar bank.  
**Mechanism**: Filtering removes unusable records; binary conflicts exclude items labeled both None and Problematic; severity conflicts resolved by selecting the exemplar with the longer rationale; the bank contains one representative per article.  
**Break conditions**: Length‑based selection picks verbose but low‑quality exemplars; strict deduplication discards multiple valid perspectives, narrowing cultural scope.

## Architecture Onboarding

**Component map**  
Exemplar Bank (language‑specific) -> Retrieval Module (embedding + top‑k search) -> Prompt Constructor (instruction language variable) -> LLM Generator (API call) -> Outputs (severity, span, rationale) -> Evaluation Suite (automated metrics + human ratings). Curation Pipeline (filtering, conflict resolution) feeds the Exemplar Bank; the correction loop (not yet implemented) would feed back expert revisions.

**Critical path**  
1. Build and clean the exemplar bank from InDor; split into bank and held‑out test set.  
2. For each test item, compute embeddings and retrieve k same‑language exemplars.  
3. Construct prompt according to condition (B0, B1, M1, A1).  
4. Call LLM via OpenRouter API (temperature 0.0) and parse structured output.  
5. Compute automated metrics and prepare pairs for human blinded A/B evaluation.

**Design tradeoffs**  
- Instruction language: English vs. target‑language affects precision vs. naturalness.  
- Retrieval vs. static few‑shot: dynamic adaptation vs. simplicity and compute cost.  
- Deduplication strictness: single exemplar reduces conflict but discards diverse perspectives.  
- Class distribution: bank retains natural skew, possibly biasing retrieval.  
- Context length: more exemplars improve grounding but reduce space for test item.

**Failure signatures**  
- Retrieval off‑topic: high similarity but irrelevant cultural frames.  
- LLM ignores context: outputs resemble static baseline despite retrieved exemplars.  
- Bank coverage gaps: certain cultural tropes absent → generic outputs, low human ratings.  
- Metric mismatch: high BERTScore but low human cultural appropriateness.  
- Contamination: test items appear in bank → overfitting.

**First 3 experiments**  
1. *Retrieval sanity check*: Manually review top‑3 exemplars for 50 random test items to confirm cultural/topic relevance.  
2. *Baseline replication*: Run B1 (static target‑language few‑shot) on pilot set; compare severity/span metrics to original InDor baseline.  
3. *Mini‑pilot comparison*: Execute M1 vs. B1 on 20 held‑out items; collect automated scores and quick human ratings to gauge preliminary effect size.

## Open Questions the Paper Calls Out
1. **Long‑term subjectivity drift** – How can the Hybrid Intelligence Loop prevent the exemplar bank from converging on a narrow annotator norm while maintaining stable cross‑cultural patterns?  
2. **Generalization to diverse languages** – Does the approach extend to typologically and culturally distant languages (e.g., Russian) or lower‑resourced annotation sources?  
3. **Rationale length heuristic** – Is length a valid tie‑breaker for conflicting annotations, or does it bias toward verbose annotator styles?  
4. **Instruction language effect** – Does English instruction + retrieved exemplars (M1) outperform target‑language instruction + same exemplars (A1) consistently across languages?  
5. **Iterative correction dynamics** – Can the continuous expert correction phase reduce misalignment over time, or does it risk over‑correction or annotator dominance?

## Limitations
- Access to the InDor corpus and precise test set composition remain unclear.  
- The embedding model for retrieval and the static few‑shot exemplars are not fully specified, hindering exact replication.  
- No empirical results are available yet; all effectiveness claims are prospective.
