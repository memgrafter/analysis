# ProtRLSearch: A Multi-Round Multimodal Protein Search Agent with Large Language Models Trained via Reinforcement Learning

## Quick Facts
- arXiv ID: 2603.01464
- Source URL: https://arxiv.org/abs/2603.01464
- Reference count: 28
- Primary result: Multi-round multimodal RL agent raises protein QA accuracy from 26–36% to 72–87% on new benchmark.

## Executive Summary
ProtRLSearch introduces a novel multi-round search agent that jointly processes protein sequences and natural language queries, addressing key limitations of prior text-only, single-round systems. By integrating a frozen protein encoder (ESM-2) with a large language model (Qwen3-8B) and a reinforcement learning (RL) framework, the agent performs iterative search with structured planning, tool selection, and self-correction. Evaluated on the newly proposed ProtMCQs benchmark, which requires protein sequence-aware reasoning, ProtRLSearch achieves dramatic accuracy improvements—from 35.7% to 86.9% at Level 1, 30.5% to 77.4% at Level 2, and 26.1% to 72.5% at Level 3. It also attains state-of-the-art performance on general medical QA datasets, demonstrating both the value of multimodal fusion and the effectiveness of RL-guided search. This work establishes a new paradigm for complex, sequence-constrained information retrieval.

## Method Summary
ProtRLSearch’s architecture consists of four main components. (1) A frozen ESM-2 protein encoder converts the amino acid sequence into residue-level embeddings. A learnable linear projection maps these embeddings into the LLM’s token space, after which they are concatenated with the textual query and fed together into the LLM. (2) The LLM (Qwen3-8B) first acts as a Planner: it generates a directed acyclic graph (DAG) that links protein-centric keywords to appropriate search tools (Web, Literature, UniProt). (3) The Retriever executes the tool-specific searches in parallel, scores results using a hybrid of PubMedBERT vector similarity and LLM-based relevance, and returns the top‑K snippets. (4) The LLM then serves as an Executor: it reasons over the retrieved snippets, outputs an answer, decides whether the evidence is sufficient (<decide>), and if not, produces a refined <next_query> to start a new round. The loop repeats until the Executor signals completion.

The system is trained via proximal policy optimization (PPO) on a dataset of 3,000 multimodal (protein, query, gold DAG, answer) examples. The RL reward is multi‑dimensional: Answer reward (semantic similarity to ground truth), Keywords reward (matching the gold keyword set), Tool reward (correct keyword‑tool mapping), and Format reward (valid structured tags). Weighted sum (λAns=0.5, λKW=0.2, λTool=0.2, λFmt=0.1) guides the policy to produce accurate, tool‑appropriate, and well‑formatted behavior while reducing round count and token consumption.

## Key Results
- On the ProtMCQs benchmark, accuracy jumps from 26–36% (baselines) to 72–87% across three difficulty levels.
- ProtRLSearch sets new state‑of‑the‑art results on BioMedMCQs, MedMCQA, and MedQA, confirming strong generalisation.
- Ablations show that removing the protein modality degrades accuracy by up to 17% (Level 3: 72.5% → 55.4%) and that removing RL increases token usage while lowering accuracy.

## Why This Works (Mechanism)

**1. Joint multimodal encoding enables sequence-aware retrieval**  
The protein sequence is encoded by a frozen ESM-2 and projected into the LLM’s token space, allowing the LLM to attend simultaneously to textual and sequence features. This fused representation guides the Retriever to select results that align with both the query intent and specific amino‑acid patterns (e.g., mutation sites, domains). Evidence: The protein-modality ablation causes a large accuracy drop (Table II). Break condition: If the projection fails to create cross‑modal alignment, the Retriever’s relevance does not improve over text‑only baselines.

**2. Multi‑round search with structured DAG planning corrects early deviations**  
The Planner generates a DAG linking keywords to tools; the Retriever executes parallel searches; the Executor reasons, answers, and decides whether to continue. This loop allows the agent to incorporate new evidence and refine queries, fixing initial keyword or tool mis‑choices. Evidence: The design explicitly includes <next_query> to steer subsequent rounds; the Executor’s decide signal governs loop termination. Break condition: Poor calibration of <decide> leads to premature termination or excessive rounds, harming efficiency or completeness.

**3. Multi‑dimensional RL rewards provide dense, process‑level supervision**  
Reward components (Answer, Keywords, Tool, Format) are summed with fixed weights. They supply immediate feedback on intermediate decisions (keyword selection, tool assignment) rather than only final answer correctness. This shapes stable search trajectories, prevents error propagation, and reduces token consumption. Evidence: Ablation removing RL leads to higher token use and lower accuracy (Section IV.C). Break condition: Inappropriate weight choices (e.g., over‑emphasising Format) could cause reward hacking—perfectly structured but incorrect outputs.

## Architecture Onboarding
**Component map**  
Protein Sequence → ESM‑2 Encoder → Projection Layer → LLM (Planner) → Retriever (Web / PubMed / UniProt search) → LLM (Executor) → Output (answer, decide, next_query) [loop if decide=False]

**Critical path:** The input (protein + query) is first transformed into a fused multimodal representation fed to the LLM, which produces a DAG of keywords and tools; the Retriever executes parallel searches and scores results; the returned snippets are consumed by the LLM again as Executor to produce an answer and a continuation decision; the cycle repeats until the Executor signals completion.

**Design tradeoffs**  
- *Multi‑round vs. Efficiency:* More rounds can increase accuracy on complex queries but linearly increase token usage and latency; RL aims to minimise rounds while maintaining correctness.  
- *Modality vs. Complexity:* Adding protein embeddings improves sequence‑constrained reasoning but increases input length and requires careful training of the projection layer.  
- *Reward complexity vs. Training stability:* A four‑component reward offers finer control but introduces hyper‑parameter sensitivity (λ weights) and potential for reward hacking.

**Failure signatures**  
- Planner: generates generic keywords (e.g., “protein”) that ignore specific sequence features.  
- Retriever: returns textually relevant snippets that are semantically inconsistent with the provided sequence (e.g., wrong isoform or species).  
- Executor: decides too early or produces an ineffective <next_query> that fails to address current evidence gaps.  
- Format: output missing required tags (<DAG>, <search_results>, etc.), causing pipeline crashes.

**First 3 experiments**  
1. **Ablation – Protein Modality:** Replace the protein sequence with a dummy or zero vector; expect a significant accuracy drop (e.g., Level 3 from 72.5% to ~55.4%).  
2. **Ablation – RL Rewards:** Train a variant using only the Answer reward (λ_Ans=1, others=0); anticipate more rounds, higher token consumption, and lower final accuracy.  
3. **Planner error analysis:** Manually annotate 100 failed Level‑3 cases, categorising Planner DAG errors as (a) missing sequence‑derived keyword, (b) incorrect tool mapping, or (c) malformed DAG; this isolates the primary failure point.

## Open Questions the Paper Calls Out
1. How can protein representation modules be made adaptive to generalize effectively to unseen protein families or sequences with significant evolutionary divergence? (Basis: conclusion mentions exploring adaptive protein representation learning.)  
2. For which specific types of protein‑centric queries (e.g., variant effect prediction vs. pathway integration) does multimodal sequence‑text fusion provide the greatest performance benefit, and are there query types where text‑only search is sufficient? (Basis: ablation results show differing impact across benchmarks.)  
3. Can the multi‑dimensional reward weights (λ_Ans, λ_KW, λ_Tool, λ_Fmt) be dynamically optimized per query or round to improve search efficiency and accuracy beyond the current static assignment? (Basis: weights are fixed heuristically, with no sensitivity analysis.)  
4. Does ProtRLSearch’s performance generalize uniformly across the six major protein categories (e.g., transcription factors, ion channels) covered by ProtMCQs, or are there systematic biases? (Basis: dataset covers six categories but results are aggregated.)  
5. What are the trade‑offs between using a frozen protein foundation model (ESM‑2) with a learnable projection versus jointly fine‑tuning the protein encoder with the LLM on the protein‑text alignment task? (Basis: method uses frozen encoder with linear projection; no comparison to joint training.)

## Limitations
- RL training details (hyperparameters, reward assignment across rounds, whether the Retriever’s LLM scorer is updated) are not fully specified, impeding precise replication.
- The 3,000‑sample training data and the InterPT dataset are not released; reliance on live search APIs (UniProt/PubMed) introduces variability and access barriers.
- The work is novel but sparsely validated in the broader literature (low FMR, zero citations), raising questions about generalisability beyond protein QA.
