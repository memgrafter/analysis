# ScrapeGraphAI-100k: A Large-Scale Dataset for LLM-Based Web Information Extraction

## Quick Facts
- **arXiv ID:** 2602.15189
- **Source URL:** https://arxiv.org/abs/2602.15189
- **Reference count:** 34
- **Primary result:** A 93,695-example dataset derived from 9M real-world events reveals non-linear schema complexity thresholds and enables a 1.7B model to approach 30B baseline performance via response-only fine-tuning.

## Executive Summary
ScrapeGraphAI-100k is a large-scale dataset for structured web information extraction using LLMs, created from opt-in production telemetry to capture authentic extraction challenges. It provides 93,695 curated examples, each consisting of Markdown content, a natural prompt, a JSON schema, and a validated LLM response. Analysis identifies sharp failure thresholds as schema depth exceeds 7 or key count surpasses 200. Fine-tuning a 1.7B model on a high-quality subset with response-only loss yields a key F1 of 0.8866, near a 30B baseline's 0.8915, and improves schema compliance by 15 points to 0.9167, demonstrating efficient knowledge distillation.

## Method Summary
The dataset is distilled from approximately 9 million real-world LLM extraction events collected via opt-in ScrapeGraphAI telemetry (Q2–Q3 2025). After deduplication via schema hashing and per-schema balancing (max 5 examples), 93,695 diverse examples remain. Each example includes complexity metadata (depth, key count, composite score). For fine-tuning, a subset is further filtered by schema and content length, and responses are regenerated with GPT-5-nano to produce consistent gold labels. A QLoRA setup (4-bit, LoRA rank 16) trains a 1.7B model for 2 epochs, contrasting standard fine-tuning with "response-only training" where loss is computed solely on assistant output tokens.

## Key Results
- Schema complexity predicts validation rate with non-linear drops at depth ≥7 and key count ≥200.
- A 1.7B model fine-tuned on a subset achieves key F1=0.8866, approaching a 30B baseline (0.8915).
- Response-only training improves schema compliance from 0.7667 to 0.9167 (a 15-point gain) and reduces hallucinated keys.

## Why This Works (Mechanism)

### Mechanism 1: Real-World Telemetry Captures Authentic Distribution
- **Claim:** Production telemetry yields a dataset reflecting the true diversity of schemas, languages, and failure modes encountered in practice.
- **Mechanism:** Collection from ScrapeGraphAI users during Q2–Q3 2025, followed by deduplication (schema-hash-based) and balancing (max 5 examples per schema) to reduce skew while preserving diversity.
- **Core assumption:** Real user tasks and model outputs are more representative than synthetic benchmarks.
- **Evidence anchors:** Abstract and section 3.1 describe telemetry source, opt-in consent, and PII avoidance. Corpus context (vs. IEPile) emphasizes real-world provenance.
- **Break condition:** If telemetry is skewed (e.g., toward e-commerce or GPT-4o-mini outputs), generalization to other domains/models may fail.

### Mechanism 2: Schema Complexity Metrics Predict Failure Thresholds
- **Claim:** Structural properties of the target schema directly stress LLM output generation, with sharp, non-linear drops in validation rate.
- **Mechanism:** Annotate schemas with depth, key count, cyclomatic complexity, and composite score; correlate with binary validation labels from `jsonschema-rs`.
- **Core assumption:** Complexity metrics are independent proxies for extraction difficulty.
- **Evidence anchors:** Abstract and section 3.3/Figure 2 show validation declines at depth≥7 and keys≥200; Table 2 and Appendix B provide distributions.
- **Break condition:** Thresholds may not generalize to unseen schema patterns or new LLM architectures.

### Mechanism 3: Efficient Adaptation of Small Models via Response-Only Training
- **Claim:** A dataset with diverse, validated examples and explicit schemas allows small models to learn extraction via knowledge distillation, especially when training focuses on output structure.
- **Mechanism:** Curate a filtered subset, regenerate responses with GPT-5-nano for gold labels, apply QLoRA with loss masked to assistant tokens.
- **Core assumption:** Explicit schema conditioning and structural loss gradients effectively transfer teacher capabilities to a student SLM.
- **Evidence anchors:** Abstract and section 5/Table 4 show 1.7B model approaching 30B baseline; response-only training yields 15-point compliance gain.
- **Break condition:** If gold-label regeneration shifts distribution or the subset is unrepresentative, gains may not transfer to raw telemetry.

## Foundational Learning
- **Concept:** Schema Complexity Metrics (depth, key count, cyclomatic complexity, composite score).
  - Why needed: To stratify the dataset, predict failure modes, and design adaptive extraction systems.
  - Quick check: "If a schema has depth 8 and 250 keys, what validation rate drop would you expect based on the paper's thresholds?"
- **Concept:** Validation Rate vs. Semantic Correctness.
  - Why needed: `response_is_valid` measures JSON conformance but not factual accuracy; understanding this gap is crucial for interpreting results.
  - Quick check: "Why does a high key F1 (0.8866) coexist with a low value score (0.4624)?"
- **Concept:** Parameter-Efficient Fine-Tuning (QLoRA/LoRA) and Response-Only Training.
  - Why needed: To adapt small models cost-effectively while focusing gradients on output structure, as demonstrated.
  - Quick check: "How does restricting loss to assistant tokens improve schema compliance compared to full-sequence fine-tuning?"

## Architecture Onboarding
- **Component map:** Telemetry ingestion (raw events → flattening → validation → complexity computation) -> Balancing pipeline (schema hashing → per-schema sampling → domain filter) -> Dataset curation (length filtering → optional re-generation → split creation) -> Fine-tuning engine (QLoRA → LoRA adapters → response-only masking → cosine decay) -> Evaluation suite (vLLM inference → metrics calculation).
- **Critical path:** 1. Collect 9M raw telemetry → 2. Clean/deduplicate/balance to 93,695 examples → 3. Compute complexity metadata → 4. Validate responses → 5. Curate training subset (e.g., ≤50k content) → 6. Fine-tune SLM with QLoRA → 7. Evaluate on held-out set (N=2,714).
- **Design tradeoffs:**
  - **Schema balancing vs. coverage:** Limiting to 5 examples per schema reduces tail domination but may discard rare, high-value schemas (e.g., complex scientific extraction).
  - **Validation strictness vs. semantic tolerance:** `jsonschema-rs` ensures syntactic compliance but ignores factual errors; value score captures semantics but is noisy (BLEU for strings).
  - **Teacher re-generation vs. raw telemetry:** Regenerating with GPT-5-nano creates clean labels but may shift distribution; raw telemetry preserves real outputs but includes noise.
- **Failure signatures:**
  - **Complexity-induced failure:** Validation rate plummets when schema depth ≥7 or keys ≥200 (non-linear drop).
  - **Over-generation:** High extra keys per sample (e.g., 2.64 for Qwen3 1.7B) indicate hallucination; fine-tuning reduces this (0.33).
  - **Structural-semantic gap:** Key F1 ~0.89 but value score ~0.46 suggests models learn JSON skeleton but not precise content extraction.
- **First 3 experiments:**
  1. **Replicate threshold analysis:** Hold out 10% of dataset, plot validation rate vs. depth and key count, fit piecewise regression to confirm non-linear breaks at depth=7 and keys=200.
  2. **Cross-model fine-tuning:** Train Llama-3.1-8B and Mistral-7B on the same subset with response-only loss; compare key F1 and schema compliance to Qwen3-1.7B results.
  3. **Error ablation study:** Manually sample 100 invalid responses, categorize errors (syntax, structure, semantic), and correlate with complexity metrics to validate failure mode hypotheses.

## Open Questions the Paper Calls Out
- **How can ScrapeGraphAI-100k be extended with raw HTML, DOM structure, and visual cues?** The current release only provides Markdown; an extended version including raw HTML and rendered images is needed to study structural signals.
- **How should we evaluate semantic correctness of extracted values beyond structural compliance?** Existing metrics like value_score only check type-level matches; a human-validated benchmark or knowledge-grounded verification suite is required.
- **Can we automatically induce an appropriate JSON schema from unstructured web content?** The paper leaves schema induction—predicting schema from content—as an open task without provided baselines.
- **How can we build error correction mechanisms to improve extraction outputs based on failure analysis?** The paper identifies failure modes but does not propose automatic fixes; a post-processing system using self-consistency or iterative prompting could address this.

## Limitations
- Exact curation logic (filtering byte vs. token counts, SHA256 schema-hashing implementation) is undisclosed, hindering replication of the 93,695 subset.
- Details of the GPT-5-nano re-generation pass (prompt, parameters, conflict resolution) are unknown, creating potential distribution shift.
- The precise chat template and token indices for the assistant's response—critical for response-only loss—are not specified.

## Confidence
- **Real-World Provenance & Diversity:** High (strong telemetry evidence, corpus context).
- **Complexity Thresholds:** Medium (in-paper correlations exist but lack external validation; may be model/dataset-specific).
- **Efficient SLM Adaptation:** Medium (fine-tuning results are clear but tempered by unverified response-only implementation and subset representativeness).
