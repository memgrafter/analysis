# Rethinking Machine Unlearning: Models Designed to Forget via Key Deletion

## Quick Facts
- **arXiv ID:** 2603.15033
- **Source URL:** https://arxiv.org/abs/2603.15033
- **Reference count:** 40
- **Primary result:** MUNKEY achieves near-instant unlearning (≈0 seconds) with a superior utility-forgetting trade-off, attaining the lowest Average Gap compared to nine post-hoc baselines on multiple image benchmarks.

## Executive Summary
This paper challenges the post-hoc paradigm of machine unlearning by proposing "unlearning by design": models that inherently support forgetting. The core contribution, MUNKEY, is a memory-augmented transformer that stores instance-specific information in an external memory bank as key-value pairs. Unlearning is performed by simply deleting the corresponding entry, requiring no weight updates. The architecture employs stochastic pathway dropout to ensure both image and memory pathways remain informative, and retrieval-based inference aggregates neighbor tokens to preserve utility. Across several image classification datasets, MUNKEY demonstrates an excellent balance of utility (test/retain accuracy) and forgetting (low forget accuracy and MIA resistance), while achieving near-zero time deletion.

## Method Summary
MUNKEY integrates a frozen pre-trained encoder (ViT-Base) that produces fixed keys for images, and a learnable exemplar token (value) stored per training sample in a memory bank. The backbone (ViT-Tiny) processes a sequence composed of image patch tokens and a projected token from the memory. During training, stochastic masks randomly drop either the patches or the token, forcing both pathways to be self-sufficient. With a probability, the model simulates inference by replacing the sample’s own token with an aggregation of retrieved neighbor tokens, while det gradients for those neighbors. After training, unlearning is a simple deletion of a sample’s (key, token) pair from the memory. At inference, a query’s key retrieves the top‑K nearest neighbor tokens, and the model ensembles predictions from each to produce the final output.

## Key Results
- **Instantaneous deletion:** Unlearning takes ≈0 seconds, orders of magnitude faster than retraining or fine‑tuning baselines.
- **State‑of‑the‑art trade‑off:** MUNKEY achieves the lowest Average Gap (a composite metric balancing utility and forgetting, where lower values indicate better trade‑off) compared to nine post‑hoc baselines on CIFAR‑10, CIFAR‑100, Tiny ImageNet, and three MedMNIST datasets.
- **Strong forgetting:** MUNKEY’s MIA (Membership Inference Attack) AUROC on forget sets is close to 0.5, indicating effective removal of influence from deleted samples (since an AUROC of 0.5 signifies random performance).

## Why This Works (Mechanism)
### Mechanism 1: External Memory Isolation
Instance‑specific data lives exclusively in the external memory bank as (key, value) pairs, while model weights remain static and never directly memorize any sample. Deleting a pair instantly removes that sample’s influence without weight updates.

### Mechanism 2: Retrieval‑Augmented Inference
The query’s key retrieves a few nearest neighbor tokens from memory. The model ensembles predictions from these neighbors, effectively approximating what the exact token would have produced. This maintains utility because semantically similar samples share predictive features, and the frozen encoder’s key space is meaningful.

### Mechanism 3: Stochastic Pathway Dropout
Randomly dropping either image patches or the exemplar token during training forces both pathways to develop individually predictive capabilities. This balance ensures that after unlearning (removing the token) the image pathway alone can still generalize adequately, and vice versa, preventing catastrophic utility loss.

## Foundational Learning
- **Permutation‑Invariant Architectures (Transformers):** Transformers treat any token uniformly, allowing external memory tokens to be inserted seamlessly alongside image patches. This modularity is essential for decoupling instance‑specific data from weights. *Quick check:* Why can a Transformer process a sequence containing both image patches and a learnable memory token without architectural change? **Answer:** The self‑attention mechanism processes all tokens identically, regardless of type, so concatenating different token types does not require architectural modifications.
- **External/Associative Memory:** Borrowing from Neural Turing Machines, MUNKEY stores instance‑specific information in a separate addressable store rather than in weights. This enables deletion by removing one entry. *Quick check:* What is the difference between a model parameter and a memory entry in terms of update frequency and access pattern? **Answer:** Model parameters are updated during training via gradient descent and remain fixed during inference, while memory entries are written per training sample and can be dynamically read and deleted at inference without affecting parameters.
- **Catastrophic Forgetting & Retrieval Regularization:** Simulating inference with neighbor tokens during training is a form of intentional forgetting. It prepares the backbone to function when the exact token is absent (as happens during unlearning). *Quick check:* How does randomly replacing v_i with aggregated neighbor tokens during training prepare the model for the unlearning operation? **Answer:** This forces the backbone to learn representations less dependent on the exact memory token and more robust to using retrieved neighbor tokens, mirroring the condition after unlearning when the specific token is removed.

## Architecture Onboarding
**Component map:** Frozen Key Encoder g_φ → fixed keys k_i; Image patch extractor → patch tokens z_i; Memory Bank M stores (k_i, v_i); Adapter h_ψ projects v_i → backbone dimension; Backbone f_θ processes [z_i, h_ψ(v_i)] → prediction.

**Critical path:**
- *Training:* For each sample: compute k_i, z_i; sample stochastic mask and retrieval flag; construct input (use own token or neighbor aggregate); forward through backbone; compute loss; update backbone parameters (θ), adapter (ψ), and own v_i (neighbors’ v_j are detached).
- *Unlearning:* Remove the (k_i, v_i) pair for each forget sample from M (zero‑time operation).
- *Inference:* Compute query key k_q; retrieve top‑K neighbor v_j by cosine similarity; for each neighbor, build [z_q, h_ψ(v_j)] and forward; ensemble predictions weighted by similarity.

**Design tradeoffs:**
- Memory overhead vs. unlearning speed: Storing O(N) tokens (e.g., 128‑dim) yields O(1) deletion. The overhead is modest but may become significant for massive datasets.
- Pathway balance (utility vs. forgetting): Dropout probabilities p_i, p_t must balance the two pathways; imbalance leads to high Pathway Sensitivity Score (Ps), which measures the reliance on a single pathway (lower Ps indicates better balance), and degraded trade‑off.
- Key encoder choice: A pre‑trained encoder aligned with the dataset (e.g., ImageNet for natural images) provides semantically meaningful keys. Mismatched domains (e.g., medical images) may degrade retrieval quality and thus utility.

**Failure signatures:**
- High Ps (>0.3): pathway dominance; adjust p_i, p_t to force balance.
- Low test accuracy despite low Ps: poor retrieval alignment or too small K; visualize neighbor examples.
- MIA ≈0.5 but retain accuracy collapses: memory tokens were never used (remains random); increase stimulus for memory usage (e.g., higher p_i).

**First 3 experiments:**
1. *Memory Retrieval Sanity Check:* For 100 random training samples, retrieve their top‑5 nearest neighbors by key. Verify that most neighbors share the same class. If not, the frozen encoder is the bottleneck.
2. *Deletion Smoke Test:* Pick 10 forget samples, record predictions, delete their (k,v) pairs, re‑predict. Predictions should change significantly and MIA AUROC should drop to ≈0.5. If not, pathway dropout likely failed (check Ps).
3. *Pathway Ablation:* On a validation set, compute accuracy using only patches (z_i with null token), only token (null patches with v_i), and both. The gap between only‑patch and only‑token accuracies indicates imbalance; tune p_i, p_t to reduce this gap.

## Open Questions the Paper Calls Out
1. **Beyond external memory, what other architectural instantiations of the “unlearning by design” paradigm are possible, and how do they trade off computational efficiency, utility, and unlearning fidelity?** The paper explicitly opens exploration of modular architectures beyond the presented memory‑augmented transformer.
2. **To what extent does the “unlearning by design” approach scale to high‑dimensional data (e.g., video, 3D volumes, audio) and non‑vision modalities, and does the memory‑augmented transformer foundation remain optimal?** All empirical validation is on 2D image classification, leaving scalability and modality generality unresolved.
3. **Is a frozen, pre‑trained key encoder strictly necessary for effective unlearning by design, or can the keys be learned jointly with the model without compromising the clean deletion property?** The paper assumes freezing prevents key entanglement but does not ablate this constraint; joint training might improve dataset‑specific utility at an unknown forgetting cost.
4. **What is the theoretical relationship between the proposed Pathway Sensitivity Score (Ps) and formal unlearning guarantees (e.g., certified removal, differential privacy), and can Ps be used as a proxy for certifiable unlearning?** Ps is an empirical heuristic; its connection to rigorous unlearning theory remains unexplored.
5. **Does the explicit, instance‑specific memory in MUNKEY introduce new vulnerabilities (e.g., membership inference via the memory bank itself) or novel interpretability‑utility‑forgetting trade‑offs compared to standard models?** The memory bank might enable attacks beyond standard black‑box MIA, but this security aspect is not analyzed.

## Limitations
- **Implementation ambiguities:** The exact handling of stochastic pathway dropout (e.g., broadcasting the null token to replace patches) is not fully specified, risking reproducibility.
- **Hyperparameter selection:** The procedure for choosing p_i, p_t (including the “rewind” validation strategy) is only sketched, requiring heuristics for new datasets.
- **Scalability evaluation:** Memory overhead and retrieval latency for large‑scale datasets (e.g., full ImageNet) are not quantitatively assessed, leaving real‑world deployment constraints uncertain.

## Confidence
- External memory isolation achieves clean deletion: **High**
- Retrieval‑augmented inference preserves utility: **Medium**
- Stochastic pathway dropout ensures balanced pathways: **Medium**
- Overall utility‑forgetting trade‑off: **Medium**
