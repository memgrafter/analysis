# CSE-UOI at SemEval-2026 Task 6: A Two-Stage Heterogeneous Ensemble with Deliberative Complexity Gating for Political Evasion Detection

## Quick Facts
- **arXiv ID:** 2603.12453
- **Source URL:** https://arxiv.org/abs/2603.12453
- **Reference count:** 26
- **Primary result:** Achieved a Macro-F1 score of 0.8505 on the SemEval-2026 Task 6 evaluation set, ranking 3rd.

## Executive Summary
This paper presents the CSE-UOI system for SemEval-2026 Task 6, which classifies political interview answers into three clarity levels (Clear Reply, Ambivalent, Clear Non-Reply). The solution employs a two-stage heterogeneous ensemble. Stage 1 uses two diverse LLMs (Grok and Gemini) with self-consistency (k=5) and an evasion-first strategy, combining their outputs via asymmetric weighted voting. Stage 2 introduces Deliberative Complexity Gating (DCG), a post-hoc correction that uses Gemini’s response length and Grok’s self-consistency as behavioral proxies to detect ambiguous samples and override Gemini’s vote toward "Ambivalent" in cases of model disagreement. DCG improves the Stage 1 Macro-F1 by 3.83 points, demonstrating the effectiveness of cross-model behavioral signals for post-hoc reasoning.

## Method Summary
The system is an inference-only pipeline requiring API access to Grok and Gemini. First, for each question-answer pair, both models generate five responses using a structured chain-of-thought prompt that predicts one of nine fine-grained evasion labels. These evasion labels are deterministically mapped to the three target clarity classes. Grok’s five individual evasion votes each contribute to the final clarity vote, while Gemini’s five outputs are aggregated into a single majority clarity label given a block weight of 4. The final clarity prediction is the class with the highest weighted vote sum. Second, Deliberative Complexity Gating (DCG) is applied: for the current inference batch, the 25th percentile (Q25) of average Gemini response lengths is computed. For any sample where its average Gemini length exceeds this batch threshold *and* Grok’s five evasion labels are not all identical (self-consistency < 1.0), Gemini’s clarity contribution is forcibly set to "Ambivalent" before the weighted vote is recomputed.

## Key Results
- Macro-F1 score of **0.8505** on the official evaluation set, securing **3rd place**.
- The Deliberative Complexity Gating (DCG) module improved Stage 1’s Macro-F1 by **+3.83 points**.
- Stage 1 alone underperformed a single Grok model, highlighting the initial challenge of model disagreement.

## Why This Works (Mechanism)

### Mechanism 1: Heterogeneous Dual-Model Ensemble with Asymmetric Voting
- **Claim:** A heterogeneous dual-model ensemble with self-consistency and asymmetric weighted voting reduces correlated errors and improves robustness.
- **Mechanism:** Two architecturally diverse LLMs (Grok, Gemini) generate multiple (k=5) outputs each. Within each model, evasion labels are aggregated by majority vote. Grok’s five votes count individually; Gemini’s majority clarity label receives a block weight (w=4). Final clarity is chosen by weighted sum.
- **Core assumption:** Model diversity leads to independent error patterns; disagreements are informative and static fusion (voting) can combine strengths.
- **Evidence anchors:** [abstract] describes heterogeneous ensemble via self-consistency and weighted voting. [section 3.1] details the evasion-first strategy and asymmetric weighting (5 votes for Grok, 1 block vote weight w=4 for Gemini).
- **Break condition:** If models exhibit high correlation in errors (e.g., shared bias on ambiguous language), voting may not improve over the better single model. Evidence: Stage-1 underperformed Grok-only on the evaluation set (Table 1).

### Mechanism 2: Evasion-to-Clarity Mapping as an Error Buffer
- **Claim:** Mapping fine-grained evasion labels to coarse clarity classes acts as an error buffer, preserving correct final predictions even when the model misclassifies the specific evasion type.
- **Mechanism:** The system first predicts one of nine evasion categories. A deterministic mapping (Figure 1) groups these into the three clarity classes. Confusion among evasion types within the same clarity bucket does not affect the final label.
- **Core assumption:** The evasion taxonomy has a hierarchical structure where some fine-grained confusion is benign for the coarse-grained decision.
- **Evidence anchors:** [section 3.1] states the mapping acts as an error buffer. [section 2.2] references the two-level taxonomy. Analysis showed 62.8% of evasion-level errors remained within the same clarity bucket, preserving the final prediction.

### Mechanism 3: Deliberative Complexity Gating (DCG) with Cross-Model Signals
- **Claim:** DCG uses cross-model behavioral signals (Gemini response length, Grok self-consistency) to post-hoc override Gemini’s contribution to "Ambivalent" for ambiguous disagreement cases, reducing errors.
- **Mechanism:** After Stage 1 voting, for samples where (a) average Gemini response length > batch Q25 and (b) Grok self-consistency < 1.0, DCG forces Gemini’s clarity to "Ambivalent" before re-running the weighted vote.
- **Core assumption:** Gemini’s response length is a proxy for deliberative complexity/ambiguity, and Grok’s inconsistency confirms the sample is genuinely ambiguous, not just Gemini-specific verbosity.
- **Evidence anchors:** [abstract] mentions the response-length proxy correlation. [section 3.2] explains pairing Gemini length with Grok consistency. [appendix A, Table A1] shows Cohen’s d > 0.9 for length as a discriminator. [section 5.3] reports gate firing precision (81.0% gold Ambivalent on Dev).
- **Break condition:** If the length-ambiguity correlation fails in a new domain or for a substituted model, DCG may mis-calibrate. The transductive batch-based threshold assumes batch homogeneity; a skewed batch could mis-fire.

## Architecture Onboarding
- **Component map:** Input (Q&A pair) -> Dual SC Inference (Grok k=5, Gemini k=5 with CoT) -> Evasion-to-Clarity Mapping (9 -> 3 classes) -> Asymmetric Weighted Voting (Stage 1 prediction) -> DCG Logic (Compute L_i, s_i, batch θ₁; fire gate if L_i > θ₁ AND s_i < 1.0) -> Override Gemini Clarity? -> Recompute Weighted Voting -> Final Clarity Label
- **Critical path:** Final correctness depends on (a) evasion-level accuracy of at least one model, (b) correctness of the mapping for that model’s majority, and (c) DCG correctly identifying and rectifying a wrong Gemini contribution on ambiguous disagreements.
- **Design tradeoffs:**
  - *Asymmetric weighting (5 vs 4):* Empirically favored Grok’s higher accuracy but preserved near-parity for DCG. Larger Grok weight degraded Stage-1 performance (Table 2).
  - *Transductive threshold (Q25 per batch):* Adapts to batch length distribution but requires batch inference. Fixed threshold from another split hurt performance (Table 3).
  - *DCG overrides only Gemini:* Because Gemini’s length is the primary signal, and Grok’s consistency confirms. Overriding both would discard all diversity.
- **Failure signatures:**
  - High error rate on Clear Reply ↔ Ambivalent boundary (86.8% of errors), especially in disagreement regions with low/medium Grok consistency.
  - DCG mis-fire if batch length distribution is anomalous (e.g., all short samples) or if Gemini’s length correlation breaks.
  - "CoT paradox": Grok’s step-inconsistent rationales were more accurate; Gemini’s wrong predictions used more tokens—this counter-intuitive signal was not exploited.
- **First 3 experiments:**
  1. Validate self-consistency benefit: Run each model with k=1 vs. k=5 on dev set. Expect Macro-F1 increase (~+1.0 for Grok, +0.6 for Gemini from Table 2).
  2. Test DCG sensitivity: On a fixed dev batch, vary the percentile for θ₁ from 5th to 95th. Expect robust improvement region with optimum near Q25, performance drop at very high percentiles.
  3. Isolate DCG impact on disagreement cases: Extract the 50 samples where Grok and Gemini Stage-1 clarity disagree. Run Stage-1 vs. Stage-2 on this subset. Expect significant accuracy jump (dev: 60.0% -> higher).

## Open Questions the Paper Calls Out
- What specific linguistic or contextual features define the Clear Reply ↔ Ambivalent boundary, and can a model be trained to distinguish them more effectively than the current gating heuristic?
- Does the response-length proxy for ambiguity generalize across different model architectures, scales, or domains beyond the proprietary Grok/Gemini models and the political interview context?
- Why did the multi-agent debate protocol fail to improve performance over static heterogeneous voting, and what does the asymmetric adaptation behavior (Grok preserving its correct decisions more often) imply about the models' roles in the ensemble?
- Can the transductive, batch-adaptive threshold (θ₁) in DCG be replaced by a more sample-specific, inductive gating function without relying on batch statistics?

## Limitations
- **Generalization:** DCG’s reliance on Gemini response length as an ambiguity proxy may not hold for other political domains or after model updates.
- **Batch sensitivity:** The transductive Q25 threshold can mis-calibrate on small or skewed batches, leading to over-/under-correction.
- **Residual errors:** DCG does not address 86.8% of final errors occurring at the Clear Reply/Ambivalent boundary.

## Confidence
- Heterogeneous ensemble with asymmetric voting: **Medium** (Stage-1 alone underperformed Grok-only on eval; voting benefits inconsistent).
- Evasion-to-clarity mapping buffer: **High** (Empirical analysis shows 62.8% of fine-grained errors remain within bucket).
- DCG cross-model gating: **Medium** (Strong dev improvement but depends on specific model behaviors and batch thresholds).

## Next Checks
1. *Cross-domain test:* Run the pipeline on a held-out political QA dataset (different country/issue). Measure DCG’s contribution; a significant drop suggests the length-ambiguity link is dataset-specific.
2. *Batch-size sweep:* Vary inference batch size (10, 50, 250) on dev set. Report Macro-F1 variance and Q25 stability; identify minimum batch size for reliable gating.
3. *Model swap ablation:* Replace Gemini with another LLM (e.g., Claude-3) while keeping DCG logic. If gain disappears, DCG is overly tuned to Gemini’s characteristics.
