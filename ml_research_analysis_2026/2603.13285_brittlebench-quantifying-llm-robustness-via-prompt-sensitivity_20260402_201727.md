# Brittlebench: Quantifying LLM robustness via prompt sensitivity

## Quick Facts
- **arXiv ID**: 2603.13285
- **Source URL**: https://arxiv.org/abs/2603.13285
- **Reference count**: 40
- **Primary result**: LLM performance degrades by up to 12% under realistic input perturbations, and perturbation-driven variance accounts for up to 50% of total performance variance, with single perturbations altering model rankings in 63% of cases.

## Executive Summary
Brittlebench introduces a framework to measure the robustness of large language models (LLMs) by applying semantics-preserving perturbations (e.g., typos, rephrasing) to standard benchmarks. The method decomposes overall performance variance into components due to inherent task difficulty and prompt sensitivity. Results show that robustness is a major, previously underestimated factor: performance drops by up to 12% under perturbation, and perturbation-induced variance constitutes up to half of the total variance, often changing model rankings. The study highlights the brittleness of current LLM evaluations and calls for robustness-aware benchmarking.

## Method Summary
Brittlebench extends the lm-evaluation-harness by systematically applying six categories of perturbations (word manipulation, padding, augmentation, paraphrasing, math, code) to input prompts while preserving semantics. For each model–benchmark pair, it evaluates both original and perturbed prompts using deterministic inference (log-prob for open-weight models, single-letter generation for commercial APIs). The outcome matrix (items × perturbations) is analyzed via variance decomposition: total variance is split into V_data (mean performance variation across items) and V_brittleness (performance variation across perturbations per item). Aggregated scores (Π_m for models, Π_b for benchmarks) enable cross-model and cross-benchmark comparisons. The pipeline is benchmark-agnostic, reusing harness scoring logic, and includes validation checks (e.g., cosine similarity) to ensure perturbations do not alter task semantics.

## Key Results
- Under perturbation, model accuracy drops by up to 12% absolute on average.
- A single perturbation changes relative model rankings in 63% of pairwise comparisons.
- On average, perturbation-driven variance (V_brittleness) accounts for up to 50% of total performance variance, rivaling or exceeding variance due to data difficulty (V_data).

## Why This Works (Mechanism)
The paper explains its approach through three mechanisms:

**Mechanism 1: Variance decomposition isolates prompt sensitivity from task difficulty.**  
- **Claim**: By treating data items and perturbations as random effects, the framework separates variance due to item difficulty (V_data) from that due to prompt sensitivity (V_brittleness) via the law of total variance.  
- **Mechanism**: For deterministic evaluation, inference variance vanishes; total variance = V_data + V_brittleness. The baseline performance on unperturbed prompts is taken as the model's true capability.  
- **Core assumption**: Perturbations are semantics-preserving; thus performance changes reflect surface-form sensitivity only.  
- **Evidence anchors**: Formal derivation in Section 3.1; prior work like ReliableEval supports variance-based robustness measurement.  
- **Break condition**: If a perturbation changes the gold answer or introduces new correct answers, V_brittleness conflates true difficulty with semantic drift.

**Mechanism 2: Unified perturbation taxonomy covers major real-world noise types.**  
- **Claim**: Six perturbation categories (word manipulation, padding, augmentation, paraphrasing, math, code) systematically stress-test robustness across diverse, semantics-preserving variations.  
- **Mechanism**: Perturbations are grouped by the prompt component they alter (e.g., character-level typos, added personas). This stratification enables fine-grained analysis of which noise types are most damaging and whether robustness generalizes across categories.  
- **Core assumption**: The taxonomy exhaustively captures major classes of natural input variations; within-category perturbations induce similar sensitivity patterns.  
- **Evidence anchors**: Category definitions in Section 2; results showing word-level and padding perturbations cause larger drops than paraphrasing (Section 5.1).  
- **Break condition**: Missing a major noise class (e.g., code-switching) would leave robustness assessments incomplete.

**Mechanism 3: Benchmark-agnostic pipeline ensures fair apples-to-apples comparisons.**  
- **Claim**: By wrapping lm-evaluation-harness, Brittlebench applies perturbations uniformly across tasks and models while preserving original scoring logic.  
- **Mechanism**: The system fetches datasets from the harness, applies perturbations to input strings, then runs the harness's evaluation (log-prob or API generation) without modifying reference answers or metrics.  
- **Core assumption**: The harness implements each benchmark's scoring correctly; perturbations affect only the input surface form.  
- **Evidence anchors**: Section 4 describes integration; Appendix A.1 details universal model support.  
- **Break condition**: If a benchmark's scoring is fragile to input format (e.g., regex extraction), perturbations could break scoring rather than test model robustness.

## Foundational Learning
- **Variance Components Analysis**  
  *Why needed*: The core innovation is decomposing total performance variance into V_data (task difficulty) and V_brittleness (prompt sensitivity). Without this, one cannot quantify robustness relative to difficulty.  
  *Quick check*: If Model A has 80% accuracy on clean data and 70% on perturbed data, while Model B has 75% on both, which model is more robust and why does variance decomposition capture this better than mean accuracy?

- **Semantic Preservation Criteria**  
  *Why needed*: The method hinges on perturbations not changing the intended answer. A "semantic" perturbation must preserve truth conditions relative to gold answers.  
  *Quick check*: If adding a persona ("You are a math expert") changes the correct answer choice for a question, is this perturbation truly semantics-preserving? How would you detect such a shift?

- **Deterministic vs. Stochastic Evaluation**  
  *Why needed*: The variance decomposition simplifies under deterministic inference (log-prob scoring). Understanding this design choice is key to interpreting V_brittleness.  
  *Quick check*: Why would using sampling-based decoding (temperature > 0) confound the measurement of prompt sensitivity? How would you adjust the variance formula?

## Architecture Onboarding
The system consists of:
Benchmark Loader -> Perturbation Engine -> Evaluation Harness -> Variance Calculator -> Validator

- **Critical path**: Perturbation Engine → Evaluation Harness → Variance Calculator. A failure in perturbation application (e.g., semantic drift) propagates to incorrect variance estimates.

- **Design tradeoffs**:
  - *Perturbation diversity vs. semantic preservation*: Aggressive typos better reflect real noise but risk changing meaning; the paper uses conservative, validated perturbations.
  - *Benchmark coverage vs. compute*: Evaluating 6 benchmarks × 15 perturbations × multiple models required ~1,800 runs; scaling is costly.
  - *Aggregation level*: Pooling across benchmarks for Π_m may hide task-specific brittleness patterns.

- **Failure signatures**:
  - Semantic drift: Cosine similarity between original/perturbed embeddings drops significantly for a perturbation type.
  - Non-monotonic intensity curves: Adding more typos sometimes improves performance, indicating broken perturbation logic.
  - Rank instability without performance drop: Rankings change but mean accuracy unchanged; expected brittleness but could indicate harness bugs.

- **First 3 experiments**:
  1. **Perturbation validation**: Sample 100 examples per perturbation, compute average cosine similarity (Qwen3-Embedding-8B) and have human annotators check answer equivalence. Target: >0.95 similarity, >98% answer preservation.
  2. **Variance sanity check**: On a single model (e.g., Llama3.1-8B) and benchmark (MMLU), compute V_data and V_brittleness for increasing numbers of perturbations. Expect V_brittleness to grow sublinearly if perturbations are independent.
  3. **Rank correlation baseline**: For each perturbation, compute Spearman correlation between model rankings on clean vs. perturbed sets across all models. Expect low correlation (<0.8) for padding/typos, high (>0.95) for paraphrasing, replicating Table 6.

## Open Questions the Paper Calls Out
1. **What specific reasoning architectures or test-time interventions (beyond standard chain-of-thought) most effectively reduce prompt brittleness without compromising accuracy?**  
   *Basis*: The authors note that further research is needed after finding CoT only weakly mitigates brittleness (Section 5.3, Appendix C).

2. **For benchmarks where perturbation-induced variance dominates (e.g., MMLU, GPQA), does this saturation of semantic competence indicate that current benchmarks are no longer effective at measuring true task difficulty, and how can new benchmarks be designed to better discriminate model robustness?**  
   *Basis*: They observe that for brittleness-dominant benchmarks, many models have reached similar semantic competence, making robustness the main differentiator (Section 5.2).

3. **Do LLM-generated paraphrasing perturbations introduce an unintended "ease bias" by standardizing language and reducing diversity, thereby artificially inflating robustness estimates compared to human-written paraphrases?**  
   *Basis*: The authors speculate paraphrasing might make queries easier by standardizing language but only evaluate LLM-generated paraphrases without a human control (Section 5.1).

4. **How does stochastic decoding (e.g., sampling with temperature >0) interact with prompt brittleness, and does it exacerbate or mask sensitivity compared to deterministic evaluation?**  
   *Basis*: Their variance framework assumes deterministic inference; they do not explore stochasticity (Section 3.1).

5. **Is prompt brittleness consistent across languages, or do linguistic features systematically modulate sensitivity?**  
   *Basis*: All benchmarks and models are English-centric; no multilingual analysis is performed despite known typological effects.

## Limitations
- Perturbation hyperparameters (typo probability, padding length, persona phrasing) are unspecified, hindering reproducibility.
- Few-shot configuration (number of shots, templates, example selection) is ambiguous; variations could artificially inflate brittleness.
- Paraphrase generation details (GPT-4o prompt, temperature) are missing, undermining consistency.
- The perturbation taxonomy may miss real-world noise types (e.g., code-switching, non-Latin scripts).
- Benchmark-level aggregation could obscure task-specific brittleness patterns.

## Confidence
- *Variance decomposition isolates prompt sensitivity*: **Medium**. Relies on semantics preservation; break condition is plausible but under-tested.
- *Perturbation taxonomy covers major noise types*: **Medium**. Six categories may not exhaust real-world variations.
- *Benchmark-agnostic pipeline ensures fair comparisons*: **Medium**. Depends on harness integrity; scoring fragility not fully assessed.
- *Empirical findings (12% drop, 63% rank change, 50% variance)*: **Medium**. Missing implementation details hamper exact replication, though direction aligns with prior work.

## Next Checks
1. **Hyperparameter sensitivity analysis**: Vary typo rate (5–20%), padding tokens (1–5), etc., on a subset of models/benchmarks. Confirm stability of relative rankings and variance component proportions.
2. **Human semantic validation**: Annotate 200 perturbed instances across categories. Target >98% answer preservation and >95% inter-annotator agreement.
3. **Cross-benchmark generalizability**: Run full pipeline on ≥3 additional benchmarks (e.g., HellaSwag, PIQA, GSM8K) and 4 newer models (Claude 3.5 Sonnet, GPT-4o, Llama 3.2 90B, Gemini 2.0). Check consistency of drop magnitudes, rank volatility, and variance proportions.
