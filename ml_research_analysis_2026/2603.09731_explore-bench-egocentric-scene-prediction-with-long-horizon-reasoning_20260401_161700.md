# EXPLORE-Bench: Egocentric Scene Prediction with Long-Horizon Reasoning

## Quick Facts
- **arXiv ID:** 2603.09731
- **Source URL:** https://arxiv.org/abs/2603.09731
- **Reference count:** 40
- **Primary result:** Humans achieve a unified score of ~59.1 while the best MLLM scores ~51.7 on the new egocentric long-horizon scene prediction benchmark, revealing a substantial gap; multi-turn stepwise inference yields moderate gains on long sequences at high computational cost.

## Executive Summary
MLLMs are increasingly capable but their ability to reason about long-term physical consequences of actions from an egocentric viewpoint remains under-evaluated. This paper introduces EXPLORE-Bench, a benchmark of 1,157 real first-person video instances, each pairing an initial image with a long atomic action sequence (average 113 steps) and a structured final scene annotation (object categories, visual attributes, inter-object relations). Evaluation uses fine-grained metrics: object coverage, attribute accuracy, relation score, and a unified 0–100 score. Experiments on numerous proprietary and open-source MLLMs reveal a substantial performance gap: humans score ~59.1 on the tiny set while the best model (Qwen3-VL-8B-Thinking) reaches only ~51.7; on the full set, humans similarly outperform models by ~8 points. Abnormal-case handling (e.g., unsafe states) is particularly poor, and stepwise multi-turn inference improves long-sequence performance (e.g., +3.41 on the Long subset) but incurs heavy computational overhead. The benchmark provides a standardized testbed to drive progress in long-horizon egocentric reasoning.

## Method Summary
EXPLORE-Bench is constructed from videos sourced from Ego4D/Ego-Exo4D and self-recorded clips. For each instance, an initial frame and the final frame of a continuous activity are extracted, along with a precise atomic action sequence that connects them (average 113 steps). The final scene is annotated through a multi-stage pipeline: object detection/tagging, grounding, and generation of attributes/relations using large MLLMs, followed by human-in-the-loop correction to ensure accuracy. The annotation comprises object categories, visual attributes, and inter-object relations, forming a gold scene graph.

Evaluation of a model’s free-form description of the final scene proceeds as: (1) decompose the text into candidate objects via noun extraction; (2) match each candidate to an annotated object using Sentence-BERT embeddings; (3) compute object coverage (S_obj) from the matches; (4) for each matched object, use an LLM judge to score attribute and relation accuracy on a 0–5 scale, averaged to S_att and S_rel; (5) combine these into a unified score S_uni = 0.25*S_obj + 0.35*(20*S_att) + 0.40*(20*S_rel) on a 0–100 scale. The protocol also includes an abnormal-case variant with a key-state score. For inference, the paper explores single-turn prediction and stepwise strategies (single-turn over segments or multi-turn updates with fixed segment count or sliding window size), allowing controlled assessment of long-horizon reasoning.

## Key Results
- **Human-model gap:** Humans achieve a unified score of 59.08 on the tiny set, while the best MLLM (Qwen3-VL-8B-Thinking) scores 51.69; on the full set, humans 59.08 vs best 50.96.
- **Stepwise gains:** Multi-turn inference with window_size=10 improves the unified score by +3.41 on the Long subset for Qwen3-VL-8B-Instruct compared to single-turn, but computational cost grows multiplicatively.
- **Abnormal-case weakness:** On a 20-video subset with unsafe/atypical final states, humans score 91.64 on a key-state metric (Sabn) while the best model scores only 58.22, indicating poor safety and anomaly detection.

## Why This Works (Mechanism)
### Mechanism 1: Structured scene annotation enables fine-grained evaluation
Structured annotations (object categories, attributes, relations) allow quantitative assessment of model predictions beyond coarse textual similarity. The pipeline produces a gold scene graph; evaluation decomposes a model’s free-form description into candidate objects, matches them via Sentence-BERT, and uses an LLM scorer to rate attribute/relation alignment. Spearman correlation with human judgments (ρ=0.919) validates the LLM scorer. The core assumption is that model outputs can be parsed into phrase-level units corresponding to annotated elements. If descriptions are vague or omit objects, coverage and attribute/relation scores drop sharply.

### Mechanism 2: Stepwise decomposition improves performance on long sequences at test time
Decomposing long atomic action sequences into smaller segments and applying multi-turn inference yields higher unified scores, especially on the Long subset. The action sequence is partitioned (fixed segment count or sliding window); in multi-turn, after each segment the model receives the previous scene description and updates it. This incremental state update reduces the need to track all changes simultaneously, resembling dynamic programming. The key assumption is that the model can maintain a consistent scene representation across turns. Evidence shows multi-turn with window_size=10 gives +3.41 on Long for Qwen3-VL-8B-Instruct, and multi-turn descriptions are significantly longer. Gains saturate or reverse with extreme segment sizes, and computational overhead is multiplicative.

### Mechanism 3: Abnormal-case handling reveals a gap in everyday physics and safety awareness
Models struggle with subtle abnormal states (e.g., objects falling, faucet left running) that humans detect easily, indicating deficiency in causal and safety reasoning. Predicting anomalies requires grounding in physical commonsense (e.g., a bottle without label lying horizontally is unusual). The paper introduces a 20-video abnormal-case subset with key-state annotations; model Sabn scores are far below human performance (91.64 vs 58.22). The core assumption is that models rely on statistical co-occurrence rather than explicit physical simulation, thus overlooking deviations from common scene configurations.

## Architecture Onboarding
- **Component map:**  
  Data collection -> Annotation pipeline -> Evaluation protocol -> Inference strategies
- **Critical path:**  
  1. Prepare instance (initial image, atomic action sequence, final annotation).  
  2. Run model inference (choose prompt and stepwise strategy).  
  3. Collect generated scene description(s).  
  4. Execute evaluation to obtain S_obj, S_att, S_rel, S_uni (and Sabn if abnormal).
- **Design tradeoffs:**  
  - Annotation granularity vs. cost: More detailed attributes/relations improve evaluation but increase pipeline complexity and human QC burden.  
  - LLM scorer vs. human evaluation: LLM scorer is scalable but may miss nuances; human evaluation is more accurate but expensive. Correlation (ρ=0.919) mitigates but not conclusive.  
  - Stepwise reasoning: Multi-turn yields better accuracy on long sequences but incurs multiplicative compute; single-turn is cheaper but less effective.  
  - Sliding window vs. fixed segments: Adaptive windowing can tune granularity but adds hyperparameter overhead.
- **Failure signatures:**  
  - Low object coverage: model omits many objects present in the final scene.  
  - Weak attribute/relation scores: descriptions lack visual details or spatial precision.  
  - Multi-turn inconsistencies: intermediate scenes contradict each other (e.g., object appears/disappears across turns).  
  - LLM scorer anomalies: extremely high scores for verbose but irrelevant descriptions; monitor by periodic human validation.
- **First 3 experiments:**  
  1. Replicate baseline results (e.g., Qwen3-VL-8B-Instruct on the tiny set) to confirm pipeline correctness.  
  2. Ablate stepwise parameters (segment_num, window_size) to observe performance trends and identify optimal settings for given sequence lengths.  
  3. Evaluate top models on the abnormal-case subset; perform qualitative analysis of key-state descriptions to validate failure modes.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Why do MLLMs exhibit a specific and substantial performance drop on abnormal/unsafe final states compared to normal scenes, despite decent performance on the full benchmark?
- **Basis in paper:** The paper explicitly highlights "abnormal-case handling remains poor" (Abstract, Sec. 6) and provides dedicated abnormal-case annotations showing large Sabn gaps (e.g., human 91.64 vs. GPT-5.2-Chat 62.79 in Tab. 3). It notes models fail to accurately describe key states (e.g., "The bottle without label lies horizontally").
- **Why unresolved:** The paper identifies the gap but does not diagnose the root cause. It suggests everyday experience helps humans, but why models cannot integrate commonsense physical knowledge (e.g., instability from pyramid disruption, faucet left running) from the action sequence and initial image remains unknown. Is it due to lack of physical commonsense training data, failure in long-term state tracking, or an inability to infer latent "key states" not explicitly mentioned in actions?
- **What evidence would resolve it:** Ablation studies isolating training data (e.g., adding synthetic/filtered data with abnormal outcomes), probing internal representations for anomaly detection signals, and controlled experiments varying the "common sense" complexity of action sequences while keeping visual complexity constant. Fine-grained error analysis on the 20 abnormal cases to categorize failure modes (e.g., missed state change vs. incorrect attribute) would also clarify.

### Open Question 2
- **Question:** What specific factors (e.g., state representation drift, error propagation, context window limits) cause the performance degradation as atomic action sequence length increases, and why does multi-turn stepwise reasoning only provide partial mitigation while incurring high computational cost?
- **Basis in paper:** Performance consistently drops from Short to Long subsets (e.g., Qwen3-VL-8B-Thinking S_uni: 63.24 → 58.02 in Tab. 2). While multi-turn inference improves Long-set performance (+3.41 over default), it "incurs non-trivial computational overhead" (Abstract, Sec. 5, Fig. 6).
- **Why unresolved:** The paper shows multi-turn helps but does not dissect why the default single-turn fails on long sequences. Is it because the model cannot maintain a coherent intermediate scene state over 100+ steps in one forward pass? Does error accumulate catastrophically? The trade-off between improved accuracy and multiplicative compute suggests inefficiency in current stepwise decomposition—perhaps the model re-renders too much redundant information each segment instead of performing compact state updates.
- **What evidence would resolve it:** Logging and analyzing the intermediate scene descriptions generated during stepwise reasoning to measure state consistency (e.g., object drift, attribute contradiction) across segments. Measuring attention patterns or hidden-state similarity to see if the model re-encodes the initial image excessively. Developing more efficient decomposition strategies (e.g., adaptive segmentation based on action dependency graphs) and evaluating their cost-accuracy curves. Also, testing whether extending context windows alone closes the gap.

### Open Question 3
- **Question:** Does the reliance on LLM-as-a-judge (with Qwen3-8B as the primary scorer) introduce systematic biases in the evaluation protocol, and how stable are the reported rankings under different LLM judges or human evaluation schemes?
- **Basis in paper:** The evaluation uses an LLM scorer (Qwen3-8B) and validates it via Spearman correlation with human judgments (ρ=0.919 on a 100-instance sample). It also notes other LLMs (Mistral, Hunyuan) achieve lower correlations (0.874, 0.815) in the appendix.
- **Why unresolved:** While the correlation is high, the benchmark's fine-grained scores (S_obj, S_att, S_rel) are entirely LLM-derived. The paper acknowledges "potential evaluation bias in LLM-as-a-judge" as a limitation but does not investigate whether the bias affects model comparisons—e.g., does the scorer prefer verbose, descriptive outputs (seen in Fig. 11) over concise accurate ones? Could different model families (proprietary vs. open-source) be scored unfairly due to stylistic biases in the LLM judge?
- **What evidence would resolve it:** Conducting a larger-scale human evaluation (beyond 100 instances) across all models, especially on the Long and abnormal subsets. Comparing model rankings when using multiple diverse LLM scorers (e.g., GPT-4o, Claude, open-source variants) to measure score variance. Analyzing scorer errors by manually inspecting a stratified sample of model outputs and judge rationales to identify consistent bias patterns (e.g., penalizing missing minor objects, rewarding certain phrasing).

### Open Question 4
- **Question:** To what extent does the benchmark's construction from real first-person videos (with automatic pipeline + human correction) embed dataset biases (e.g., scene distribution, action pattern frequencies) that may not reflect the full diversity of egocentric long-horizon tasks, and how do these biases impact generalizability?
- **Basis in paper:** The dataset is derived from Ego4D/Ego-Exo4D and self-recorded videos, filtered for "cooking," "repair," etc. (Sec. 3.2). It contains 1,157 instances with average 113-step sequences. The authors note "rare or abnormal cases...are still under-represented" (Limitations) and the human-in-the-loop QC accepts data at "99% accuracy," implying a clean but possibly narrow distribution. The word clouds in Fig. 2 suggest heavy concentration on kitchen/home scenarios.
- **Why unresolved:** The paper does not analyze whether performance correlates with scenario type, action verb diversity, or initial scene complexity. If models overfit to common patterns (e.g., cooking sequences), their scores may not reflect true long-horizon reasoning but rather memorization of frequent action-scene transitions. The uneven scenario distribution (Fig. 2a) could disadvantage models trained on broader data.
- **What evidence would resolve it:** Performing cross-validation scenario-wise (e.g., training on 80% of activity types, testing on held-out 20%) to measure generalization. Analyzing error rates per scenario/action cluster. Collecting and evaluating on a more balanced or adversarially sampled set (e.g., outdoor activities, complex social interactions). Also, quantifying the diversity of atomic action templates and their mapping to final states.

### Open Question 5
- **Question:** What architectural or training modifications are necessary for MLLMs to learn explicit, verifiable state tracking mechanisms that can robustly simulate long action sequences, rather than relying on implicit pattern recognition from static image-text pairs?
- **Basis in paper:** The paper frames the task as "mentally apply" a sequence to an initial image, requiring "coherent representation of what changes and what remains invariant." The poor performance (best model ~51 vs. human ~59 on tiny set) and specific failures (e.g., missing key states) suggest current MLLMs lack an internal dynamics model. Stepwise reasoning helps a bit, indicating iterative prediction is beneficial, but the high cost hints at non-ideal implementations.
- **Why unresolved:** The paper does not speculate on model architecture changes. Is the Transformer decoder's next-token prediction objective sufficient for multi-step state evolution? Should models incorporate explicit memory buffers, simulation heads, or object-centric representations? The success of thinking models is noted but not analyzed for whether they implicitly build such mechanisms.
- **What evidence would resolve it:** Ablation studies comparing architectures (e.g., adding a dedicated state encoder/decoder, using object-level slots, incorporating differentiable physics engines) on EXPLORE-Bench. Training models on auxiliary tasks like predicting intermediate states or object tracking in synthetic video data. Interpreting internal representations (e.g., probing for consistent object identity across token positions in long generations) to see if models internally track states. Also, evaluating whether models trained on stepwise data (simulated rollouts) generalize better.

## Limitations
- **Dataset accessibility:** The benchmark dataset is not yet publicly available, preventing reproduction and follow-up research.
- **Evaluation reliance on LLM-as-a-judge:** The scoring pipeline depends on an LLM whose prompts and generation parameters are under-specified; biases may exist despite reported correlation with human judgments.
- **Annotation pipeline dependencies:** Construction uses proprietary models (Qwen3-VL-235B, GPT-5.2), making full dataset reconstruction from raw videos infeasible and potentially embedding hidden biases.
