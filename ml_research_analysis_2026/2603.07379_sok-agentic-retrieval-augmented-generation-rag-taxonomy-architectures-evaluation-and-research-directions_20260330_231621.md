# SoK: Agentic Retrieval-Augmented Generation (RAG): Taxonomy, Architectures, Evaluation, and Research Directions

## Quick Facts
- **arXiv ID:** 2603.07379
- **Source URL:** https://arxiv.org/abs/2603.07379
- **Reference count:** 40
- **Primary result:** Formalizes Agentic RAG as finite-horizon POMDPs, creating a unified taxonomy across planning, retrieval, memory, and orchestration; identifies five critical research directions.

## Executive Summary
This survey systematizes the fragmented understanding of Agentic Retrieval-Augmented Generation (RAG) by formalizing it as a finite-horizon Partially Observable Markov Decision Process (POMDP). The core contribution is a multi-dimensional taxonomy spanning planning topologies, retrieval strategies, reasoning paradigms, memory models, and tool orchestration. The authors decompose architectures into a common blueprint, identify systemic risks (e.g., cascading hallucinations, memory poisoning), and argue for trajectory-level evaluation over static final-answer metrics. The paper concludes with five doctoral-scale research directions: stable adaptive retrieval, formal reasoning evaluation, memory security, cost-aware orchestration, and trust calibration.

## Method Summary
The authors conduct a comprehensive literature analysis of 40 cited works, extracting design choices across six taxonomy dimensions: planning topology, retrieval strategy, reasoning paradigm, memory/context model, memory optimization, and tool orchestration. Systems like ReAct, Self-RAG, AutoGen, and LangGraph are mapped to this framework. The analysis synthesizes a unified architectural blueprint and critiques static evaluation methods, proposing trajectory-level metrics (e.g., Progress Rate, Effective Information Rate) and highlighting open problems in security, cost, and reliability.

## Key Results
- **Unified taxonomy:** Classifies Agentic RAG systems across six design dimensions, enabling systematic comparison and design.
- **Architectural blueprint:** Decomposes systems into a common set of components (planner, retrievers, memory, orchestrator) with identified design patterns.
- **Systemic risks identified:** Highlights cascading hallucinations, memory poisoning, and cost explosion as critical failure modes.
- **Evaluation shift:** Proposes trajectory-level metrics over static final-answer accuracy to capture multi-step reasoning behavior.

## Why This Works (Mechanism)
The POMDP formalization provides a rigorous, unifying lens for Agentic RAG, framing it as sequential decision-making under uncertainty. By mapping systems to this framework, the paper reveals common architectural patterns and failure modes. Trajectory-level evaluation captures the agent’s reasoning process, enabling detection of subtle failures (e.g., compounding errors) that static metrics miss. The taxonomy surfaces design tradeoffs and trade-offs, guiding both system design and evaluation.

## Foundational Learning
- **POMDP formalization:** Treats Agentic RAG as sequential decision-making under uncertainty, enabling rigorous analysis.
  - *Why needed:* Without this, comparing systems is ad-hoc; POMDP unifies planning, retrieval, and memory under a common model.
  - *Quick check:* Can you write the belief state update equation for an agent’s memory after a retrieval step?
- **Taxonomy dimensions:** Planning (topology), Retrieval (strategy), Reasoning (paradigm), Memory (model), Memory optimization, Tool orchestration.
  - *Why needed:* Reveals design space and trade-offs; prevents reinventing equivalent architectures.
  - *Quick check:* Given a system, can you classify it into each of the six taxonomy dimensions?
- **Trajectory-level evaluation:** Metrics like Progress Rate, Effective Information Rate, faithfulness, and tool reliability.
  - *Why needed:* Static final-answer accuracy misses cascading failures and reasoning quality.
  - *Quick check:* Can you compute faithfulness for a trace where the agent made three retrieval calls?

## Architecture Onboarding
- **Component map:** Planner -> Retrieval Strategy -> Memory/Context -> Tool Orchestration -> Output (single-agent) or Planner -> Executor(s) -> Retrieval -> Memory -> Tools -> Output (planner-executor) or Multi-agent collaboration with shared memory and tools.
- **Critical path:** Planner decides next action → Retrieval fetches context → Memory updates belief state → Tools execute (if needed) → Reasoning module refines plan or answer.
- **Design tradeoffs:** One-shot vs. iterative retrieval (latency vs. accuracy); dynamic vs. static memory (adaptability vs. stability); centralized vs. decentralized orchestration (control vs. scalability).
- **Failure signatures:** Cascading hallucinations (errors compound across steps); memory poisoning (poisoned context degrades reasoning); tool reliability collapse (unreliable tools derail plans).
- **First experiments:** (1) Classify 5 systems from literature into the taxonomy; (2) Implement faithfulness metric on a public agentic trace; (3) Simulate a cascading hallucination scenario to observe error propagation.

## Open Questions the Paper Calls Out
- **How stabilize iterative retrieval under planning?** Heuristic limits cause drift and failure. Convergence bounds and drift metrics would resolve this.
- **How evaluate multi-step reasoning beyond final-answer?** Static metrics ignore steps; no rubrics. Trajectory benchmarks and expert judges would resolve this.
- **How secure persistent memory against poisoning?** Defenses fail against triggers; no recovery. Provenance, anomaly detection, and low ASR would resolve this.
- **How balance reasoning depth with cost under budget?** Uniform routing causes token explosion. Budget-aware routing, Pareto analysis, and cost reduction would resolve this.
- **How calibrate agent uncertainty and decide human escalation?** LLM miscalibration and rigid HITL. Conformal prediction, entropy, and high-precision escalation would resolve this.

## Limitations
- **Taxonomy granularity:** Some design boundaries (e.g., iterative vs. self-refining retrieval) remain fuzzy without explicit decision rules.
- **Evaluation metrics feasibility:** Proposed trajectory-level metrics lack standardized, automated implementations and remain aspirational.
- **Assumption completeness:** Analysis assumes all cited works contain sufficient architectural detail; missing details may bias the taxonomy.

## Confidence
- **High confidence:** POMDP formalization and architectural decomposition as a unifying lens.
- **Medium confidence:** Taxonomy mapping—systematic but subject to interpretation without hard decision criteria.
- **Low confidence:** Immediate applicability of trajectory-level evaluation metrics without further tooling development.
