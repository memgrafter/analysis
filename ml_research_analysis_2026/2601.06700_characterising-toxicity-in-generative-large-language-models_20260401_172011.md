# Characterising Toxicity in Generative Large Language Models

## Quick Facts
- **arXiv ID:** 2601.06700  
- **Source URL:** https://arxiv.org/abs/2601.06700  
- **Reference count:** 10  
- **Primary result:** Base LLMs generate toxic content with probability up to 99.5% on toxic prompts, while instruction-tuned variants reduce this to as low as 2.58%.

## Executive Summary
This paper investigates the propensity of generative large language models (LLMs) to produce toxic content and identifies lexical and syntactic triggers that amplify such outputs. Using the DecodingTrust dataset, the authors evaluate seven base and instruction-tuned models, scoring continuations with the Perspective API. They find that base models are extremely prone to generating toxic language, whereas instruction tuning dramatically reduces toxicity. Through attribution analysis (Layered Integrated Gradients) and syntactic parsing, they discover that nouns—particularly those targeting social groups—are high-attribution tokens, and that simple imperative clauses with ROOT dependencies frequently correlate with toxic generations. The study concludes that effective mitigation must address both lexical cues and syntactic structures in model alignment.

## Method Summary
The authors generate single continuations for each prompt in the DecodingTrust dataset using seven LLMs (including Gemma, BLOOM, LLaMA, and Mistral variants). Toxicity of each output is measured via the Perspective API’s “Toxicity” dimension, from which *Expected Maximum Toxicity* and *Toxicity Probability* are computed. For outputs scoring ≥ 0.8 (high toxicity), they apply Captum’s Layered Integrated Gradients to attribute each input token’s contribution to the toxicity score. High-attribution tokens are clustered and analysed for part-of-speech (POS) distribution using spaCy. Dependency parsing labels (e.g., ROOT) are also aggregated. A qualitative inspection of a subset of these examples supports the quantitative trends.

## Key Results
- Base models exhibit extremely high Toxicity Probability (up to 99.5%) on toxic prompts, while instruct models reduce this dramatically (down to 2.58%).  
- Lexical analysis shows that nouns—especially those targeting specific identity groups—are the most frequent high-attribution tokens.  
- Syntactic analysis reveals that ROOT dependencies (short, imperative clauses) often appear among high-attribution tokens, correlating with toxic outputs.

## Why This Works (Mechanism)

### Mechanism 1: Lexical Triggering by Toxic Nouns
- **Claim:** Prompts containing high-attribution nouns—especially those targeting specific social groups—significantly increase the probability that a generative LLM will produce toxic outputs.  
- **Mechanism:** The model applies Layered Integrated Gradients to quantify each token’s contribution to the toxicity score. Tokens with high attribution (often nouns like slurs or identity markers) are strongly weighted in the generation process, leading the model to mirror or amplify these elements in its continuation, thereby elevating overall toxicity.  
- **Core assumption:** The attribution scores accurately capture how input tokens influence the model’s toxic output; tokens with higher attribution are more causally responsible for the toxicity.  
- **Evidence anchors:** [abstract] “Lexical analysis via Captum and POS tagging shows nouns—especially those targeting specific groups—are high‑attribution tokens.” [section] Section 4.2.2–4.2.4 details the Captum attribution pipeline, k‑means clustering, and POS analysis, revealing nouns as the dominant high‑attribution category. [corpus] Neighbor paper “Mitigating Text Toxicity with Counterfactual Generation” also emphasizes the role of lexical features in detoxification, lending indirect support.  
- **Break condition:** If for a particular model the attribution method fails to surface nouns as high‑importance tokens, or if the POS distribution shows no noun dominance, the mechanism may not hold.

### Mechanism 2: Syntactic Amplification via ROOT Structures
- **Claim:** Prompts with concise syntactic forms, particularly where the ROOT dependency is a verb (short imperative clauses), are more likely to elicit toxic responses from LLMs.  
- **Mechanism:** Dependency parsing of prompt tokens shows that high‑attribution tokens frequently bear the ROOT label. Such structures are simple and direct (e.g., “<verb> …”), which may prime the model to produce similarly abrupt, potentially aggressive continuations, increasing toxicity.  
- **Core assumption:** The reliance of high‑attribution tokens on ROOT positions is causally linked to the toxicity of the generated text.  
- **Evidence anchors:** [abstract] “Syntactic analysis via dependency parsing reveals the ROOT structure (short, imperative clauses) frequently correlates with toxic outputs.” [section] Section 4.2.5 presents statistics and qualitative examples of ROOT prevalence in toxic cases.  
- **Break condition:** If ROOT tokens among high‑attribution tokens are not overrepresented compared to a baseline, the syntactic claim is unsupported.

## Foundational Learning
- **Perspective API Toxicity Scoring** – *Why needed:* Provides an automated, scalable measure of text toxicity essential for evaluating large volumes of model outputs. *Quick check:* Run the API on a set of known toxic and non‑toxic sentences; verify that slurs score > 0.7 and neutral sentences score < 0.3.  
- **Layered Integrated Gradients** – *Why needed:* Attributes the contribution of each input token to the model’s toxicity score, identifying lexical triggers. *Quick check:* Apply IG to a simple classifier on a known phrase; check that the toxic word receives the highest attribution.  
- **Part‑of‑Speech Tagging & Dependency Parsing** – *Why needed:* Morphosyntactic analysis of high‑attribution tokens reveals whether certain grammatical categories (e.g., nouns) or structures (e.g., ROOT) are associated with toxicity. *Quick check:* Use spaCy to parse a sentence and confirm the main verb is labeled ROOT and nouns are tagged correctly.  
- **Model Alignment (Base vs. Instruct)** – *Why needed:* Comparing base and instruction‑tuned models isolates the effect of safety alignment on toxicity generation. *Quick check:* Generate continuations for a toxic prompt from both versions; confirm the instruct model yields lower toxicity scores.

## Architecture Onboarding
**Component Map**  
Prompts → Model (base/instruct) → Output Texts → Perspective API → Toxicity Scores → High‑Toxicity Filter (score ≥ 0.8) → Captum Integrated Gradients → Token Attributions → POS Tagging / Dependency Parsing → Analysis

**Critical Path**  
The core pipeline starts with prompt generation, passes through model inference, toxicity scoring, selection of high‑toxicity outputs, attribution, and finally syntactic/lexical analysis that yields the paper’s main insights.

**Design Tradeoffs**  
- *Perspective API* offers fast automated scoring but introduces cultural and language biases.  
- *Layered Integrated Gradients* provides fine‑grained token importance yet is sensitive to baseline choice and number of integration steps.  
- *Dataset choice* (DecodingTrust) ensures topic diversity but limits findings to English prompts and a small set of models.  
- *Statistical vs. qualitative analysis*: quantitative POS/dependency counts are complemented by small‑scale manual inspection to capture nuance.

**Failure Signatures**  
- Toxicity scores deviate substantially from known benchmarks for standard test phrases.  
- High‑attribution tokens are nonsensical (e.g., punctuation or common words) or do not include expected toxic vocabulary.  
- POS distribution shows a very low proportion of nouns (< 20%) contrary to paper’s findings.  
- Repeated crashes in spaCy parsing due to tokenisation mismatches.

**First Experiments**  
1. *Smoke test*: Generate outputs for 5 known prompts from each model and verify they are syntactically plausible and match expected style (base: more raw; instruct: safer).  
2. *Attribution sanity*: For a prompt containing a known slur, run Captum IG and confirm the slur receives top‑5 attribution.  
3. *POS distribution check*: Aggregate high‑attribution tokens across 20 randomly selected toxic outputs, apply spaCy POS tagging, and verify nouns constitute > 40% of tokens (aligning with the paper’s dominant category). If not, review tokenisation and IG settings.

## Open Questions the Paper Calls Out
1. **How should training objectives explicitly incorporate lexical and syntactic features to improve toxicity mitigation?**  
   Basis: Section 5.5 proposes enhanced fine‑tuning to capture toxic triggers.  
   Why unresolved: Current alignment reduces but does not eliminate toxicity; joint lexical‑syntactic objectives remain untested.  
   What evidence: Multi‑task loss experiments on DecodingTrust showing significant reduction.

2. **How can automated toxicity detectors like Perspective API be combined with human feedback for context‑aware evaluation?**  
   Basis: Future Work calls for combining automated tools with human feedback loops.  
   Why unresolved: The study relied solely on Perspective API; human judgments differ and integration is unknown.  
   What evidence: Collect human ratings, calibrate API, fine‑tune with combined signal, measure human alignment.

3. **What practical input moderation strategies can effectively block harmful prompts before generation?**  
   Basis: Future Work suggests robust input moderation to intercept toxic prompts.  
   Why unresolved: Base models echo toxic inputs, but no concrete moderation was evaluated.  
   What evidence: Online comparison of filters (lexical, syntactic, classifier) measuring toxicity reduction and utility.

4. **How does toxicity vary across languages and cultures, and how can models be adapted for equitable safety?**  
   Basis: Future Work calls for diverse scenario testing across languages and contexts.  
   Why unresolved: Evaluation was English‑only; toxicity expression is language‑specific.  
   What evidence: Test multilingual models on non‑English toxic datasets, compare patterns and mitigation effectiveness.

## Limitations
- The exact version and split of the DecodingTrust dataset used are unspecified, which may hinder comparable reproduction.  
- Captum Integrated Gradients hyperparameters (e.g., number of steps, baseline, layer selection) are not reported, making the attribution results potentially unstable.  
- Perspective API version and enabled toxicity dimensions are undocumented, introducing calibration risks given known cultural biases.

## Confidence
- **Lexical triggering by toxic nouns:** Medium  
- **Syntactic amplification via ROOT structures:** Low  
- **Base vs. instruct toxicity gap:** High  

## Next Checks
1. **Reproduce core metrics with specified API version** – Re‑run toxicity measurement using Perspective API v3 with all toxicity dimensions enabled, and compare Expected Maximum Toxicity distributions against the paper’s values for at least two model pairs (e.g., Llama 3.1 base vs. instruct).  
2. **Stress‑test attribution sensitivity** – For a fixed set of high‑toxicity prompts, vary Captum’s `n_steps` (e.g., 50, 100, 200) and baseline (zero vs. random). Measure Jaccard similarity of top‑5 high‑attribution tokens; if similarity drops below 0.6, the lexical trigger claim is methodologically fragile.  
3. **Validate syntactic patterns statistically** – Using the same high‑toxicity outputs, automatically extract dependency ROOT tokens and clause length. Perform logistic regression to predict toxicity score (≥ 0.8) from ROOT presence and clause length, controlling for prompt toxicity. If coefficients are non‑significant (p > 0.05), the ROOT correlation is likely spurious.
