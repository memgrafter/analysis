# CSyMR: Benchmarking Compositional Symbolic Muisc Reasoning With MIR Tool Integration

## Quick Facts
- **arXiv ID:** 2601.11556
- **Source URL:** https://arxiv.org/abs/2601.11556
- **Reference count:** 15
- **Primary result:** Tool-augmented agent consistently outperforms all prompting and reasoning baselines by 5–7% absolute accuracy on CSyMR-Bench, with strongest improvements on analysis-heavy query categories.

## Executive Summary
CSyMR introduces a benchmark and a tool-augmented agent to address compositional symbolic music reasoning—tasks that require chaining multiple atomic analyses over symbolic scores to answer complex queries. The benchmark, CSyMR-Bench, contains 126 curated multiple-choice questions drawn from expert forums and exams, explicitly designed to require evidence aggregation across heterogeneous musical dimensions.

The agent integrates deterministic symbolic operators from the music21 library into a ReAct framework, grounding each reasoning step in verifiable evidence extraction. Experimental results show that the tool-augmented agent consistently outperforms all prompting and reasoning baselines by 5–7% absolute accuracy on CSyMR-Bench, with the strongest improvements on analysis-heavy query categories. LLM-only methods fail due to hallucination during multi-step evidence aggregation.

## Method Summary
The paper presents a ReAct-style agent that orchestrates a Planner, Thinker, Tooler, and Reviewer to iteratively decompose queries, invoke deterministic music21 operators, and aggregate evidence. The agent operates on symbolic scores in Humdrum kern format and uses a fixed set of 16 analysis functions covering six analytical dimensions. The evaluation is on CSyMR-Bench, a newly introduced benchmark of 126 multiple-choice questions requiring multi-step reasoning. The primary experiments use GPT-4.1-mini as the LLM backbone with temperature 0 and a maximum trajectory length of 12 steps.

## Key Results
- CSyMR-Bench introduced with 126 curated multiple-choice questions requiring chaining multiple atomic analyses.
- Tool-augmented ReAct agent achieves 5–7% absolute accuracy gains over all baseline methods (including LLM-only and prompting baselines).
- Gains are most pronounced on analysis-heavy query categories; LLM-only methods fail due to hallucination in complex multi-step evidence aggregation.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** Tool-augmented compositional retrieval mitigates LLM hallucination by grounding each reasoning step in verifiable symbolic evidence extraction.  
**Mechanism:** The agent decomposes a high-level query into atomic analysis operations (e.g., key estimation, Roman numeral analysis), executes them via deterministic music21 operators, and aggregates the returned evidence to bridge the semantic gap between natural language intent and structured score data, replacing ungrounded parametric inference with a deterministic evidence path R = {e₁, e₂, ..., eₙ}.  
**Core assumption:** LLMs can reliably plan and synthesize evidence when provided with accurate, low-level musical facts.  
**Evidence anchors:** The abstract and Section 3 state that the tool-augmented agent consistently outperforms baselines and transforms the task into verifiable evidence aggregation; neighboring benchmarks (e.g., WildScore) lack such deterministic tool integration.  
**Break condition:** If the deterministic toolset lacks operators for a required atomic analysis (e.g., specific voice-leading violations), the aggregation path fails and performance regresses toward LLM-only baselines.

### Mechanism 2
**Claim:** The benchmark’s design—requiring chaining of multiple atomic analyses over authentic, expert-curated queries—exposes LLMs’ limitations in compositional symbolic reasoning.  
**Mechanism:** Questions are constructed so the correct answer is not retrievable via a single lookup or isolated fact recall; instead, the answer is *implicit* and must be derived by synthesizing outputs from several independent analyses (e.g., combining key modulation detection with Roman numeral analysis across measures). This forces structured retrieval and evidence aggregation.  
**Core assumption:** Real-world music information needs often involve multi-step, cross-dimensional reasoning that isolated knowledge tests or synthetic problems fail to capture.  
**Evidence anchors:** Section 2.1 defines compositional MIR as requiring evidence aggregation across heterogeneous dimensions; Section 2.2 details curation from community discussions and exams with manual selection to retain only multi-step tasks.  
**Break condition:** If questions can be answered by a single atomic analysis or via parametric recall (e.g., “What is the key?”), the benchmark no longer tests compositional reasoning and may not differentiate tool-augmented from strong CoT models.

### Mechanism 3
**Claim:** A ReAct-style controller with a constrained tool interface enables robust planning and error recovery in multi-step symbolic analysis by separating reasoning from execution.  
**Mechanism:** The Planner/Thinker generates actionable steps and formulates tool calls, while a dedicated Tooler executes strictly typed music21 functions and returns only natural-language evidence summaries. This context isolation prevents the LLM from being distracted by raw code/debugging and forces it to operate on verified outputs; the iterative loop allows revisiting earlier steps when initial evidence is insufficient.  
**Core assumption:** LLMs can act as effective meta-reasoners over tool outputs if the tool interface is simple, reliable, and hides implementation complexity.  
**Evidence anchors:** Section 3.2 explains the context isolation strategy where raw code execution is hidden; Section 3.1 and Figure 4 show the iterative loop and recovery from mistakes (e.g., wrong initial key assumption).  
**Break condition:** If the LLM cannot generate valid tool calls (e.g., incorrect parameters) or cannot synthesize evidence from summaries, the process stalls or converges to a wrong answer.

## Foundational Learning
- **Symbolic music representation (Humdrum/kern)**  
  *Why needed:* The benchmark and agent operate on structured score representations (Humdrum kern), not audio or images. Understanding spine structure, time representations, and encoding of notes/chords is essential to grasp what the tools extract and what the LLM sees.  
  *Quick check:* Given a kern line like `**kern *M4/4 8r 8c 8d 8e`, what musical events does it represent, and how would a tool extract the pitch and duration of the first note?

- **ReAct paradigm (Reasoning + Acting)**  
  *Why needed:* The agent’s core loop (Think → Call Tool → Observe) follows ReAct. Distinguishing internal reasoning from external actions is key to understanding why tool augmentation outperforms pure CoT.  
  *Quick check:* In the case study, why is the step `[thinker] CALL_TOOL: Run a key estimation...` classified as an "Action" and not just internal "Thought"?

- **Deterministic symbolic analysis operators**  
  *Why needed:* The music21 tools (e.g., `get_roman_numeral_analysis_in_segment`) supply ground truth via algorithmic, non-probabilistic methods. Knowing they are deterministic explains why their outputs are trusted as evidence anchors and why errors arise from misapplication, not tool randomness.  
  *Quick check:* If `get_key_estimation` uses a Krumhansl-Schmuckler key-finding algorithm, what would be a plausible output for a segment in G major with no accidentals? What could cause it to output a different key?

## Architecture Onboarding
**Component map:** The architecture comprises:
- **Planner**: Decomposes the query into sub-tasks (e.g., "first find key changes, then analyze chords").
- **Thinker**: Maintains the evolving evidence path R; decides next tool call based on current evidence and remaining gaps.
- **Tooler**: Executes music21 functions; isolates code execution; returns plain-text evidence summaries.
- **Toolset**: 16 deterministic operators mapped to six analytical dimensions (e.g., key estimation, Roman numeral analysis, pitch extraction).
- **Reviewer**: Final synthesis step that selects answer letter based on aggregated evidence.

**Critical path:** Query → Planner decomposition → Thinker iteration (Think → Call Tool → Tooler execution → Evidence update) until evidence is sufficient or maximum steps (12) reached → Reviewer final answer.

**Design tradeoffs:**
- Tool coverage vs. flexibility: Fixed operators ensure reliability but may lack niche analyses (e.g., specific voice-leading violations).
- Context isolation vs. transparency: Hiding raw tool outputs prevents distraction but removes low-level data that might be needed for fine-grained synthesis.
- Iterative depth vs. latency: More tool calls allow thorough verification but increase cost and time; the 12-step cap is a practical bound.

**Failure signatures:**
- Tool misuse (invalid arguments, irrelevant tools).
- Incomplete chain (agent stops early with insufficient evidence).
- Synthesis error (Reviewer picks wrong answer despite correct tool outputs).
- Loop non-termination (agent cycles without converging, often on ambiguous key regions).

**First 3 experiments:**
1. Baseline replication: Reproduce Table 1 experiments (GPT-4.1-mini across 6 baselines + Music21 ReAct) to confirm the 5–7% gain and category-specific improvements.
2. Tool ablation: Systematically disable subsets of the 16 tools (e.g., all harmony tools) to measure impact on corresponding query categories (e.g., Chord & Harmony), validating that gains are tool-dependent.
3. Error audit: Take CoT-failing examples (Figure 4), run the tool-augmented agent, and manually inspect tool outputs to confirm they provide verifiable evidence that corrects the LLM’s false assumptions.

## Open Questions the Paper Calls Out
1. **Extending the toolset for implicit knowledge**: Can the deterministic symbolic toolset be extended or hybridized to handle query categories requiring implicit stylistic or parametric knowledge (e.g., Genre/Musician Judgment) without sacrificing accuracy on analysis-heavy tasks? *Basis:* The paper notes negligible improvements for metadata-driven categories due to the toolset's focus on explicit structural retrieval. *Why unresolved:* The paper does not explore augmenting the toolset with implicit knowledge mechanisms. *Resolving evidence:* Systematic ablation comparing current toolset against hybrid variants (e.g., adding stylistic similarity retrieval, few-shot examples of genre conventions, or a secondary classifier) across both analytical and knowledge-based categories.

2. **Representativeness of CSyMR-Bench**: How representative is the benchmark's 126-question scope and its community/exam sourcing of the full diversity of real-world compositional symbolic music information needs, particularly for non-Western, jazz, or contemporary repertoires? *Basis:* Benchmark curated from r/musictheory (2012–2022) and college-level music theory exams. *Why unresolved:* The sourcing implicitly biases the dataset toward common-practice Western art music and academic pedagogy; the paper does not analyze coverage of other idioms. *Resolving evidence:* A meta-analysis comparing query intents and dimensions in CSyMR-Bench against a larger, intentionally diverse sample of unsolicited user questions from multiple music platforms (e.g., forums for jazz, folk, film scoring) and professional contexts.

3. **Efficiency and failure mode trade-offs of the ReAct loop**: What are the computational efficiency and failure mode trade-offs of the ReAct-style planning loop as reasoning chain length and score complexity increase, and how do they relate to the 12-step trajectory cap? *Basis:* The experimental setup caps maximum trajectory length at 12 steps. *Why unresolved:* The adequacy of this cap for the most complex questions is not evaluated; the cost (latency, API calls) of tool-augmented reasoning vs. pure LLM inference is not quantified. *Resolving evidence:* An analysis correlating question difficulty (e.g., number of required atomic analyses) with actual trajectory length and success rate, including stress tests with artificially longer or more modular scores. A cost-benefit comparison of accuracy gains per additional tool call.

4. **Robustness to noise and non-standard encodings**: How robust is the tool-augmented framework to noise, errors, or non-standard encodings in the symbolic input (e.g., from imperfect OMR conversion), and what is the impact on the verifiability of the evidence aggregation chain? *Basis:* The community-derived subset was converted to symbolic Humdrum kern format via optical music recognition software. The framework assumes the input D is a well-formed symbolic music score. *Why unresolved:* The paper does not discuss error rates from the OMR pipeline or test resilience to common symbolic music errors; malformed input could produce plausible but wrong evidence e. *Resolving evidence:* Introducing controlled noise into the kern files (simulating OMR errors) and measuring the agent's accuracy degradation versus baselines. Implementing input validation tools or error-correction pre-processing and testing their efficacy.

## Limitations
- **Benchmark availability:** CSyMR-Bench (126 questions, kern files) is not publicly released, preventing full external validation and replication.
- **Tool specification:** Exact signatures, edge-case handling, and evidence summarization format for the 16 music21 operators are underspecified, hindering faithful reproduction.
- **Generalization:** It remains unclear whether the reported accuracy gains generalize to other LLM backbones, larger datasets, or non-Western symbolic traditions.
