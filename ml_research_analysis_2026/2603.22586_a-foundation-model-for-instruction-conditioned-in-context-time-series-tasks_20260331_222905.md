# A Foundation Model for Instruction-Conditioned In-Context Time Series Tasks
## Quick Facts
- **arXiv ID:** 2603.22586
- **Source URL:** https://arxiv.org/abs/2603.22586
- **Reference count:** 40
- **Primary result:** Outperforms Chronos-2 and TimesFM-2.5 on fev-bench (81.3% win rate) and GIFT-Eval, with robust zero-shot performance across forecasting, classification, and anomaly detection.

## Executive Summary
This paper introduces iAmTime, a foundation model for time series that adapts to new tasks (forecasting, imputation, classification, anomaly detection) at inference via in-context learning (ICL), without fine-tuning. It uses a hierarchical Transformer with structured tokenization to explicitly demarcate target series, covariates, and future segments within a prompt. Trained via amortized meta-learning on a large, diverse corpus of real and synthetic series, the model learns to interpret example demonstrations as task instructions. It achieves state-of-the-art zero-shot performance on multiple benchmarks, demonstrating a unified framework for instruction-conditioned time series analysis.

## Method Summary
The method centers on a structured ICL framework. Input series are normalized and split into patches, then serialized with semantic role tokens (e.g., `[TARGET SERIES]`, `[EXOG]`, `[FUTURE EXOG]`) to create a clear syntactic separation between historical context, future targets, and covariates. A hierarchical T5 encoder-decoder processes this sequence: Stage 1 encodes each patched series independently; Stage 2 fuses components within an example; Stage 3 pools each example's representation and fuses them across examples to derive a global rule that conditions the query. The decoder, using a mixture-of-experts cross-attention, predicts quantiles for the query’s future. Training combines a supervised forecasting objective with self-supervised meta-tasks (imputation, classification, source demixing), forcing the model to infer the task mapping from the structure of the demonstrations.

## Key Results
- Achieves a win rate of 81.3% and a skill score of 51.9% on fev-bench (100 tasks), surpassing strong baselines.
- On GIFT-Eval (97 evaluations), obtains the lowest CRPS and MASE ranks across varying horizons and input dimensionalities.
- Demonstrates competitive zero-shot performance on classification and anomaly detection tasks, validating its instruction-conditioned paradigm.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Structured tokenization with explicit semantic role tokens prevents representation leakage and enables the model to disentangle task-specific input-output mappings within a single context window.
- **Mechanism:** Numeric time series patches are serialized with fixed boundary tokens (`[START]`, `[MID]`, `[END]`) and role-specific tokens (`[TARGET SERIES]`, `[EXOG]`, `[FUTURE EXOG]`). These discrete anchors create hard segmentation in the token sequence, allowing separate self-attention layers to operate within well-defined scopes (per-example, per-role) without mixing unrelated subsequences.
- **Core assumption:** Explicit structural boundaries in the input sequence are necessary for a single Transformer to learn multiple, distinct task mappings (forecasting, imputation, etc.) from the same parameters without explicit task IDs.
- **Evidence anchors:**
  - [abstract] "...structured tokenization scheme that marks target series, covariates, context, and task-specific future information."
  - [section 3.2.1, 3.2.2] Formal definition of `Ser(E_i)` and `Ser(Q)` using role tokens to serialize historical/future target and covariate segments.
  - [corpus] Strong agreement: All 8 neighbor papers on ICL for time series use some form of structured prompting or demonstration formatting.
- **Break condition:** If the number of distinct semantic roles or their sequential ordering varies unpredictably across tasks during inference, the learned attention patterns may fail to generalize, causing task confusion.

### Mechanism 2
- **Claim:** Hierarchical attention fusion (per-example → example-level → cross-example) allows the model to first build robust, self-contained representations for each demonstration before aggregating them into a global "ICL rule" for the query, preventing interference between examples with different structures.
- **Mechanism:** Stage 1 encodes each 1D series patch independently. Stage 2 fuses targets/covariates *within* an example using `[START]...`[END]` boundaries. Stage 3 pools each example's representation (mean pooling, permutation-invariant) and aggregates across N examples to extract a shared rule `r_q` that conditions the query's final encoding. This isolates intra-example dynamics from inter-example reasoning.
- **Core assumption:** Effective in-context learning requires first understanding each example's input-output mapping in isolation before synthesizing a common principle across the demonstration set.
- **Evidence anchors:**
  - [abstract] "...hierarchical Transformer that performs per-example encoding, example-level fusion, and cross-example attention."
  - [section 3.4.2] Detailed three-stage architecture specification and justification for mean pooling ("permutation-invariant, parameter-free, robust to variable numbers of patches").
  - [section C.1] Ablation shows removing hierarchical fusion (via `iAmTime-NoExmp` or `iAmTime-NoToks`) drastically harms win rate/skill score.
- **Break condition:** If the number of in-context examples `N` grows very large (e.g., >>10), the single mean-pooled rule `r_q` may become an insufficient summary, losing nuanced information from diverse demonstrations.

### Mechanism 3
- **Claim:** Amortized meta-training via a diverse mixture of self-supervised time-series tasks (forecasting, imputation, anomaly detection, classification, source de-mixing) teaches the model to interpret the *future segment in examples* as the task instruction itself, enabling zero-shot task switching at inference.
- **Mechanism:** During training, each `(E_i, Q)` pair is constructed from a specific meta-task τ. The example's future targets `Xfut_i` implicitly define the mapping (e.g., "predict this future continuation" for forecasting, "output this corrected series" for anomaly detection). The model is forced to ignore the *identity* of the task and instead deduce the required output transformation from the structure of the demonstration pairs.
- **Core assumption:** The space of time-series tasks can be expressed as a distribution over input-output transformations. Exposing the model to many such transformations during pretraining allows it to learn a general "instruction-following" function within its parameters.
- **Evidence anchors:**
  - [abstract] "...combines supervised forecasting objective with self-supervised instruction-conditioned tasks... This multi-task training learns a distribution over task mappings..."
  - [section 3.4] Table 2 draws an explicit analogy between NLP self-supervised objectives and time-series meta-training tasks, mapping prediction, imputation, denoising, etc.
  - [section 4.4] Details data generation for each task class and how they are instantiated within the same ICL prompt format.
  - [section C.1] Ablation `iAmTime-NoMeta` (forecasting-only training) shows significant performance drop, proving the necessity of multi-task meta-training.
- **Break condition:** If the test-time task is a novel transformation not represented in the meta-training task distribution (e.g., a fundamentally new output structure like change-point detection with a specific label set), the model may fail to infer the correct mapping from examples.

## Foundational Learning
- **Concept:** In-Context Learning (ICL)
  - **Why needed here:** The entire framework hinges on ICL: adapting to new tasks/domains at inference without gradient updates, purely via the prompt's demonstration examples.
  - **Quick check question:** Given a prompt with 3 example `(history, future)` pairs and one query `(history)`, can you explain what output the model is expected to generate and why the examples matter?

- **Concept:** Amortized Meta-Learning
  - **Why needed here:** The model is not explicitly trained with inner-loop optimization (like MAML). Instead, the ability to adapt from context is "amortized" into the forward pass parameters through multi-task meta-training. This bridges traditional meta-learning and large-scale pretraining.
  - **Quick check question:** How does training on a *distribution* of tasks (e.g., forecasting + imputation) lead to better performance on a *new* task at test time compared to training only on forecasting?

- **Concept:** Structured Prompting (Semantic Roles)
  - **Why needed here:** Raw concatenation of multivariate series (targets, covariates) would cause "representation leakage" where attention mixes values from different roles and time horizons. Semantic tokens create an explicit, parseable syntax for the model.
  - **Quick check question:** Why is `[TARGET SERIES]` and `[EXOG]` better than just concatenating all series together? What specific ambiguity would arise without them?

## Architecture Onboarding
- **Component map:** Raw series -> Tokenizer/Embedder (ϕ) -> Stage1 Encoder (Enc_ts, per-series) -> Stage2 Encoder (Enc_ex, per-example) -> Stage3 Fusion (mean-pooling & cross-example attention -> r_q) -> Decoder (MoE cross-attention + output head) -> Quantile forecasts.
- **Critical path:** The hierarchical stages must preserve example boundaries from tokenization through Stage 3 fusion to prevent representation leakage. The query must be processed separately until fused with the global rule `r_q`.
- **Design tradeoffs:**
  - **Hierarchy vs. Simplicity:** The 3-stage hierarchy adds parameters and complexity vs. a flat Transformer over all tokens, but is necessary for scalability and preventing leakage. Tradeoff: efficiency for structural correctness.
  - **Direct Multi-Horizon vs. Autoregressive:** Direct prediction is faster and avoids error accumulation but requires the decoder to learn all horizon dependencies at once. Autoregressive could be more flexible but is slower and error-prone.
  - **Mean Pooling for `r_q`:** Parameter-free and robust to variable `N`, but may lose fine-grained information from the most relevant examples. Alternatives (e.g., attention over examples) add parameters and may overfit to specific example positions.
- **Failure signatures:**
  - **Symptom:** Model performs well on univariate forecasting but fails on tasks requiring output structure different from `Xfut` (e.g., classification constant series).
    - **Likely cause:** Inadequate meta-training task diversity; model hasn't learned to interpret arbitrary `Xfut` in examples as instruction.
  - **Symptom:** Performance degrades sharply when `dx` (number of target series) or `dz` (covariates) differs between examples and query.
    - **Likely cause:** Tokenization/positioning logic doesn't handle mismatched role counts gracefully; semantic tokens aren't sufficient to signal structural differences.
  - **Symptom:** Probabilistic forecasts are poorly calibrated (e.g., 90% quantile doesn't capture 90% of points).
    - **Likely cause:** Quantile regression head or Mixture-of-Experts gating not learning to represent full predictive distribution; possibly decoder capacity insufficient for multi-horizon, multi-quantile output.
- **First 3 experiments:**
  1. **Ablation: No In-Context Examples (`iAmTime-NoExmp`).** Train the model with `N=0` examples in every prompt. Expected outcome: Catastrophic drop in win rate/skill score (observed: ~16% drop in fev-bench win rate). Proves examples are essential, not just context.
  2. **Ablation: No Semantic Tokens (`iAmTime-NoToks`).** Remove `[TARGET SERIES]`, `[EXOG]`, etc., and rely on raw numeric concatenation. Expected outcome: Severe degradation, especially on tasks with covariates or multivariate targets (observed: largest skill score drop). Proves structural boundaries are critical.
  3. **Task Generalization Probe:** After training on all meta-tasks, construct *zero-shot* prompts for a held-out task class (e.g., "trend strength classification" not seen during training) using synthetic examples from KernelSynth. Expected outcome: If amortized meta-learning works, the model should infer the classification task from the constant `Xfut` examples and achieve non-random accuracy.

## Open Questions the Paper Calls Out
- How does the proportion and type of synthetic data (TSMixup vs. KernelSynth) in the training mixture impact the model's zero-shot performance on real-world forecasting tasks, and is there an optimal balance that maximizes robustness across domains?
- Can the hierarchical fusion mechanism be replaced by a simpler architecture (e.g., a flat transformer with appropriate positional encodings) while retaining the same level of in-context learning capability, and what are the computational trade-offs?
- What is the optimal strategy for selecting in-context examples during inference (e.g., number of examples, similarity to query, diversity), and how does it affect the model's adaptation to new tasks and domains?
- To what extent can the model perform tasks like imputation and source demixing purely through demonstration-based specification at inference time, and what are the limitations of the current instruction-conditioned formulation for such tasks?

## Limitations
- Architectural and training hyperparameters (patch size, embedding dimension, layer counts, number of MoE experts, dropout, positional encoding; history length L, forecast horizon H, max prompt length, number of examples N, curriculum schedule, optimizer settings) are not fully specified.
- The mean‑pooling rule for cross‑example fusion may lose informative details when the number of in‑context examples N becomes large (>10).
- Generalization to entirely novel task transformations (e.g., change‑point detection with arbitrary label sets) is unproven; model might fail if the meta‑training task distribution does not cover the transformation.

## Confidence
- **Structured tokenization** with explicit role tokens prevents leakage and disentangles task mappings. *Confidence: High* (ablation removing tokens shows severe drop; conceptually sound).
- **Hierarchical attention fusion** (per‑example → example‑level → cross‑example) prevents interference and builds robust representations. *Confidence: High* (ablation removing stages degrades performance substantially).
- **Amortized meta‑learning** via multi‑task self‑supervision teaches the model to interpret future segments as instructions, enabling zero‑shot task switching. *Confidence: Medium* (meta‑training ablation shows benefit, but generalization beyond seen task types is uncertain).

## Next Checks
1. **Ablation: No semantic tokens** – Train a variant without role tokens (raw numeric concatenation) and evaluate on fev‑bench. Expect large win‑rate/skill‑score drop, confirming token necessity.
2. **Scalability test for rule pooling** – Fix model architecture, vary N (1, 5, 10, 20) in prompts; track performance. A sharp decline beyond N≈10 would indicate mean‑pooling limitation, prompting design of example‑level attention.
3. **Zero‑shot novel task probe** – After full training, construct prompts for a held‑out task class (e.g., trend‑strength classification using constant label series) not in meta‑training. Accuracy significantly above random would validate amortized instruction‑following.
