# Baguan-TS: A Sequence-Native In-Context Learning Model for Time Series Forecasting with Covariates

## Quick Facts
- **ArXiv ID:** 2603.17439  
- **Source URL:** https://arxiv.org/abs/2603.17439  
- **Reference count:** 40  
- **Primary result:** Baguan-TS reduces scaled quantile loss by 4.8% versus TabPFN-TS and attains the highest win rate on the fev-bench-cov benchmark, while also leading on 27 real-world energy datasets for both point and probabilistic forecasting.

## Executive Summary
Baguan-TS introduces a novel in‑context learning (ICL) approach for time series forecasting that operates directly on raw sequences without feature engineering. The model employs a 3D Transformer to jointly capture temporal dynamics, cross‑variable dependencies, and context‑episode relationships. It further integrates a Y‑space retrieval‑based calibration that selects relevant context examples using target‑history similarity, and a context‑overfitting training strategy that mitigates oversmoothing by teaching the model to reconstruct duplicated spikes. Extensive evaluations on covariate‑aware benchmarks (fev‑bench‑cov) and 27 real‑world energy datasets demonstrate state‑of‑the‑art performance, with significant improvements in both point and probabilistic metrics.

## Method Summary
Given a set of context episodes and a query, Baguan‑TS constructs an input tensor of shape \((C\!+\!1)\times(T\!+\!H)\times(M\!+\!1)\) (contexts + query, full horizon, target + covariates). It tokenizes each variable by patching the temporal dimension (patch size P = 8) and applying random Fourier features, yielding tokens of shape \((C\!+\!1)\times S\times(M\!+\!1)\times D\). The core is a stacked 3D Transformer: each block sequentially applies attention over temporal patches (with RoPE), variable channels (with learned embeddings), and context examples (no positional encoding), followed by layer normalization and a feed‑forward network. Context sets are built via Y‑space retrieval: for a given target lookback, the model finds the \(K_{\text{ctx}}\) nearest historical windows using z‑normalized Euclidean/cosine distance. During training, a context‑overfitting auxiliary task duplicates a short segment from a context slice into the query history and trains the model to retrieve that context and reconstruct its future values, using a CRPS loss over \(K=5000\) discretized bins. Inference can run in 2D (\(C=1\)) or 3D (full) mode, with an optional ensemble of multiple configurations and stochastic perturbations (covariate shuffle, history masking) to improve robustness.

## Key Results
- Highest win rate on the fev‑bench‑cov benchmark among all compared methods.  
- Reduces scaled quantile loss by 4.8% versus TabPFN‑TS and achieves the best SQL and MASE across 30 tasks.  
- Leads on 27 real‑world energy datasets with known covariates, demonstrating superior point and probabilistic forecasting.

## Why This Works (Mechanism)

Baguan‑TS’s effectiveness arises from three synergistic mechanisms:

1. **3D Transformer Factorization**  
   The model processes input tensors across three axes—temporal patches, variable channels, and context examples—with dedicated attention in each block. Temporal attention (with RoPE) captures local time patterns; variable attention (with channel embeddings) models cross‑variable dependencies; context attention (no positional encoding) enables cross‑episode similarity. This factorization preserves structural relationships that flattened 1D tokenization discards (Section 3.2.2). Evidence: the architecture yields state‑of‑the‑art results on multivariate benchmarks (fev‑bench‑cov). Break conditions: if dynamics are trivially simple, cross‑variable correlations are negligible, or context examples are homogeneous, the added complexity may not help or could overfit.

2. **Y‑space Retrieval‑Based Forecasting**  
   Instead of relying on handcrafted covariates, Baguan‑TS builds its context set by retrieving historical windows whose target trajectories are similar (Y‑space). This feature‑agnostic approach encodes the combined effect of all drivers in the target shape and is robust to covariate noise. During training, random subsampling from a larger candidate pool mimics imperfect retrieval and increases diversity. Evidence: ablations (Table 4) show Y‑space outperforms X‑space and XY‑space; noise‑robustness experiments (Figure 8) demonstrate Y‑space degrades least under injected covariate noise. Break conditions: if the underlying process is non‑stationary and the memory is outdated, retrieved contexts may be irrelevant; if the target history is very short/noisy, covariate‑based retrieval (X‑space) might be preferable.

3. **Context‑Overfitting Strategy**  
   To mitigate oversmoothing—where ICL models interpret periodic spikes as outliers—Baguan‑TS introduces an auxiliary self‑retrieval task. It duplicates a short segment from one context slice into the query history and trains the model to identify that context and reconstruct its future. This forces attention to align with peak locations and teaches the model that identical patterns are valid signals. Evidence: synthetic spike experiments (Figures 6, 9) show the full model reconstructs sharp peaks while the baseline oversmooths; attention maps confirm peak‑step attention only appears with overfitting. Break conditions: if spikes are non‑periodic or the noise level is high, duplication might cause overfitting to spurious patterns.

## Foundational Learning
Baguan‑TS rests on several conceptual pillars:

- **In‑Context Learning (ICL)**  
  *Why needed:* The model’s core value is gradient‑free adaptation at inference via context examples; understanding ICL’s “learning from demonstration” paradigm is essential to grasp why the architecture treats context as a first‑class dimension.  
  *Quick check:* How does the model’s behavior at inference differ from standard supervised training when given a new context set \(D_c\)? *(It dynamically adjusts predictions based on provided contexts without parameter updates.)*

- **Multi‑Dimensional Attention Factorization**  
  *Why needed:* The 3D Transformer factorizes attention over temporal, variable, and context axes instead of flattening; this requires understanding how attention heads can specialize per axis and why preserving dimensionality matters for time‑series structure.  
  *Quick check:* What inductive bias does variable‑wise attention capture that temporal attention alone cannot? *(Cross‑variable dependencies and interactions, crucial for multivariate dynamics.)*

- **Retrieval‑Augmented Forecasting**  
  *Why needed:* Y‑space RBfcst is a retrieval mechanism; understanding its role in constructing context sets—and its difference from covariate‑based retrieval—is key to the calibration claim.  
  *Quick check:* Why might retrieving by target trajectory (Y‑space) be more robust to covariate noise than retrieving by covariate similarity (X‑space)? *(Because target trajectories already integrate covariate effects and are less affected by noisy covariates.)*

## Architecture Onboarding

**Component map**  
- Input tensor \(Y \in \mathbb{R}^{(C+1)\times(T+H)\times(M+1)}\) (contexts + query, full horizon, target + covariates)  
- Patching & tokenization: split temporal dimension into \(S\) non‑overlapping patches of length \(P=8\); apply random Fourier features \(\phi = Wq + b\) → \([ \cos\phi; \sin\phi ] \in \mathbb{R}^D\); add mask token for future patches  
- 3D Transformer blocks: stacked \(L=12\) blocks; each block sequentially applies (a) temporal attention with RoPE, (b) variable attention with learned variable embeddings, (c) context attention without positional encoding; residual connections and layer norm after each; feed‑forward network (dim 768) follows  
- Y‑space retrieval‑based forecasting (RBfcst): during training/inference, retrieve \(K_{\text{ctx}}\) nearest neighbors in target‑history space (z‑normalized Euclidean/cosine) from a historical memory  
- Context‑overfitting (training only): copy a short segment from a context slice into the query history; auxiliary loss requires correct retrieval of that context and reconstruction of its future values  
- Prediction head: lightweight MLP maps latent representation of future patch tokens to logits over \(K=5000\) bins (range \([-10,10]\)); softmax yields probabilities  
- Inference modes: 2D (context length = 1), 3D (full context), and ensemble (average of multiple configs with stochastic perturbations)

**Critical path**  
During inference the raw sequence is patched and tokenized, then processed by the 3D Transformer to produce context‑conditioned representations of future patches. The prediction head converts these to probabilities. Y‑space RBfcst influences the context set before it reaches the transformer; context‑overfitting modifies the training objective but is absent from the inference graph.

**Design tradeoffs**  
- 3D vs 2D: 3D captures richer interactions (temporal + variable + context) but is computationally heavier; 2D collapses the temporal axis and relies more on covariates; ensemble combines complementary strengths and balances calibration biases.  
- Y‑space retrieval: avoids feature engineering but assumes target trajectories are predictive; retrieval cost grows with memory size.  
- Context‑overfitting: improves spike recovery but risks overfitting to duplicated patterns if the data is noisy.

**Failure signatures**  
- Oversmoothing: flat forecasts missing peaks → context‑overfitting not applied or ineffective.  
- Poor calibration: predictive CDFs consistently over‑ or under‑dispersed → RBfcst might be disabled or retrieval mismatched.  
- Context mismatch: forecasts unrelated to query → retrieval failure (e.g., non‑stationary shift not captured by Y‑space).  
- High seed variance → insufficient context diversity or unstable training.

**First 3 experiments**  
1. Ablate 3D factorization: replace the 3D attention with a flattened 1D tokenization (merge temporal+variable axes) and evaluate on multivariate subsets of fev‑bench‑cov. Expect the full 3D model to achieve lower SQL.  
2. Test Y‑space robustness under covariate noise: generate synthetic series with corrupted covariates (increasing Gaussian noise) and compare SQL/MASE for Y‑space vs X‑space retrieval. Y‑space should degrade more slowly.  
3. Validate context‑overfitting: train variants with and without the self‑retrieval auxiliary loss on a spiky energy dataset (e.g., hourly load). Measure peak‑region RMSE; the full model should reconstruct sharp spikes while the baseline oversmooths.

## Open Questions the Paper Calls Out

1. **When does Y‑space retrieval fail?**  
   The paper advocates Y‑space similarity but does not analyze conditions where historical target patterns cease to be predictive (e.g., sudden regime shifts). Systematic evaluations with controlled distribution shifts could resolve this.

2. **Does context‑overfitting cause overfitting to spurious patterns?**  
   The self‑retrieval task improves spike recovery but may bias the model to match any inserted pattern, even noise, potentially harming generalization on non‑periodic data. Controlled experiments with synthetic data containing true spikes and random noise are needed.

3. **Can a learned dynamic weighting of 2D and 3D inference modes outperform static averaging?**  
   The current ensemble uses simple averaging, noting complementary residuals and opposite calibration biases. A meta‑learner that ingests input features or uncertainty estimates to weight predictions could further reduce errors.

## Limitations
- Missing full training details (hyperparameters, synthetic data generation) hinders exact replication.  
- Underspecified retrieval parameters (\(K_{\text{ctx}}\), distance weighting) and context‑overfitting segment size.  
- Vague criteria for inference ensemble selection and stochastic perturbations.

## Confidence
- **3D Transformer factorization:** Medium (design described clearly but lacks direct ablation isolating the three‑way factorization).  
- **Y‑space retrieval:** High (supported by consistent ablations and noise‑robustness experiments).  
- **Context‑overfitting:** High (synthetic spike experiments directly demonstrate mitigation of oversmoothing).
