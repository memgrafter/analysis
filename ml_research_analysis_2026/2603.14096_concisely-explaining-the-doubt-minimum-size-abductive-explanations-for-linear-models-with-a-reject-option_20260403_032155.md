# Concisely Explaining the Doubt: Minimum-Size Abductive Explanations for Linear Models with a Reject Option
## Quick Facts
- **arXiv ID**: 2603.14096
- **Source URL**: https://arxiv.org/abs/2603.14096
- **Reference count**: 36
- **Primary result**: MINABRO computes provably minimal abductive explanations for linear classifiers with reject options, achieving speedups of two orders of magnitude and more concise explanations compared to state-of-the-art methods.

## Executive Summary
The paper introduces MINABRO, a framework for generating minimum-size abductive explanations for linear classifiers equipped with a reject option. Abductive explanations identify a minimal set of features that, when fixed to their observed values, guarantee the model’s prediction (or rejection) remains unchanged for any completion of the remaining features within known bounds. For instances that are accepted (scores outside the rejection interval), MINABRO employs a greedy algorithm with O(n log n) complexity that is provably optimal. For rejected instances (scores inside the interval), it formulates a 0–1 integer linear program (ILP) that yields a minimal explanation. Experiments across ten datasets demonstrate that MINABRO is substantially faster than existing methods (e.g., on MNIST, 167 ms vs 64 727 ms for rejected instances) and produces more concise explanations (e.g., 533 vs 573 features for MNIST), all while providing full fidelity guarantees.

## Method Summary
MINABRO operates in two distinct modes depending on the instance’s classification status relative to the rejection thresholds \(t^-\) and \(t^+\). For an accepted instance (score ≤ \(t^-\) or ≥ \(t^+\)), the goal is to ensure the score stays on the correct side of the threshold even if unexplained features take extreme values. The required “coverage” to offset the worst‑case completion is computed, and each feature \(j\) contributes a fixed amount \(\delta_j\) equal to the difference between its observed contribution and its minimum possible contribution (for positives) or vice versa for negatives. Since the sum of the top‑k \(\delta\) values is maximal among any k features, the greedy selection of the largest \(\delta\) until the coverage is met yields a minimal‑cardinality set. For a rejected instance, the score must lie strictly within \((t^-, t^+)\) for all completions; this yields two linear constraints on the selected features. The problem is encoded as a 0–1 ILP where each binary variable \(z_j\) indicates whether feature \(j\) is included in the explanation. The ILP’s objective is \(\min \sum z_j\) subject to constraints that bound the maximum and minimum possible scores given the selected features. The authors solve the ILP using an off‑the‑shelf solver (PuLP/CBC). Both branches preserve fidelity: any completion of unexplained features yields the same prediction/rejection as the original instance.

## Key Results
- **Speed**: For rejected instances on MNIST, MINABRO averages 167 ms, outperforming AbLinRO by a factor of ~388× (64 727 ms) and Anchors by orders of magnitude.
- **Conciseness**: On the same MNIST rejections, MINABRO’s explanations contain on average 533 features, compared to 573 for AbLinRO.
- **Fidelity**: All explanations are provably faithful; the predicted outcome holds for every possible assignment of the unexplained features within their bounds.

## Why This Works (Mechanism)
The correctness of MINABRO hinges on two key observations. First, for an accepted instance, the worst‑case score occurs when all unexplained features are set to their minimum (for a positive) or maximum (for a negative). The extra contribution needed from the explained features is a fixed target \(T\). Each feature \(j\) can contribute at most \(\delta_j = |w_j(x_j - \alpha^{\min}_j)|\) (or analogous for negative) above the all‑minimum baseline. Because contributions are independent and additive, any set of size \(k\) can contribute at most the sum of the \(k\) largest \(\delta\) values. Therefore, the greedy algorithm—selecting features in descending order of \(\delta\) until the cumulative sum reaches \(T\)—produces the smallest possible cardinality, as any solution with fewer features would have a sum below \(T\). Second, for rejected instances, the condition that the score stays within \((t^-, t^+)\) for all completions translates exactly to the two linear constraints in the ILP. Any feasible binary vector corresponds to an explanation that satisfies both lower and upper bounds; minimizing \(\sum z_j\) yields a minimal‑size explanation. The ILP formulation is exact, and solving it to optimality guarantees minimality. Together, these mechanisms ensure that MINABRO returns provably minimal explanations with full fidelity.

## Foundational Learning
Below are core concepts needed to understand and implement MINABRO, each with a brief rationale and a quick verification.

- **Abductive explanation**: A set of features that, when fixed to their instance values, guarantees the model’s prediction for all completions of other features. *Why needed:* This is the type of explanation MINABRO generates. *Quick check:* For a linear model with bounded features, verify that for a given set E, the minimum possible score (all non‑E features at their lower bounds) still exceeds t+ for a positive instance.
- **Reject option (classification with abstention)**: Allows the model to output “reject” when the score lies in an intermediate interval [\(t^-\), \(t^+\)], trading off accuracy for safety. *Why needed:* MINABRO must explain both accepted and rejected cases. *Quick check:* Given a trained logistic regression, compute t- and t+ via Chow’s rule; ensure that instances with score between them are rejected.
- **Linear classifier with bounded features**: The model is a linear function \(s(x)=b+\sum w_j x_j\) and each feature has known lower/upper bounds \(\alpha^{\min}_j,\alpha^{\max}_j\). *Why needed:* Bounds are essential to compute worst‑case scores and the \(\delta_j\) contributions. *Quick check:* After min‑max scaling, confirm that all training and test feature values lie in [0,1].
- **Greedy algorithm for covering problems**: Picks items in order of decreasing “gain” until a target is met. *Why needed:* Provides optimal solution for accepted instances. *Quick check:* On a small synthetic example (e.g., three features with \(\delta\) values 5,3,2 and target 6), greedy picks {5,3}? Actually target 6, greedy picks 5 (sum=5<6) then 3 (sum=8≥6) uses 2 items; any single item? 5<6, 3<6, 2<6 so 2 is minimal. Verify.
- **Integer Linear Programming (ILP)**: Optimization with binary variables and linear constraints. *Why needed:* Encodes the minimal explanation problem for rejected instances. *Quick check:* Build the ILP in Eq.5 for a tiny instance (2 features) and solve by brute force to confirm the binary solution matches the minimal cardinality set that satisfies both constraints.

## Architecture Onboarding
### Component Map
InstanceInput -> PrecomputeBounds -> CategoryDecision -> (GreedySolver | ILPSolver) -> ExplanationOutput

### Critical Path
1. Receive a test instance \(x\).
2. Compute its score \(s(x)\) and compare with \(t^-\) and \(t^+\) to decide category.
3. If accepted: fetch precomputed \(\delta_j\) values, sort them, and greedily accumulate until the required coverage is reached.
4. If rejected: construct the ILP (using precomputed \(\alpha^{\min}, \alpha^{\max}, \beta_j\)), solve to optimality, and extract selected features.
5. Return the set of selected feature indices as the explanation.

The bounding precomputation (\(\alpha^{\min}_j, \alpha^{\max}_j\)) and \(\delta_j\) calculations are done once per dataset, outside the per‑instance loop.

### Design Tradeoffs
- **Greedy vs optimality**: For accepted cases, greedy is both fast and provably optimal; no trade‑off needed.
- **ILP exactness vs speed**: The ILP guarantees minimality but worst‑case complexity is exponential. The authors accept this cost for rejected instances because they are typically fewer (rejection rates are low after calibration). Practical performance is still acceptable (sub‑second on MNIST).
- **Solver choice**: Using a general‑purpose ILP solver (PuLP/CBC) simplifies implementation but may not exploit the specific two‑constraint structure; a custom branch‑and‑bound could be faster but was not pursued for simplicity.

### Failure Signatures
- **Infeasible explanations**: The returned set E does not satisfy both \(s_{\max}(E) \le t^+\) and \(s_{\min}(E) \ge t^-\) for a rejected instance. Check by enumerating extreme completions of unexplained features.
- **Non‑minimal size**: For accepted instances, compare explanation size with the lower bound obtained by summing the largest \(\delta\) values; if smaller, greedy implementation may be flawed. For rejected instances, run ILP with a time limit and a zero optimality gap; if not optimal, size may be larger.
- **Calibration mismatch**: Rejection rates or threshold widths differ significantly from those reported in Table 1. This indicates errors in the empirical risk minimization for \(t^-, t^+\).

### First 3 Experiments
1. **Greedy optimality on deterministic small data**: On a dataset with 4 features (e.g., Banknote), randomly select 100 accepted instances, run MINABRO’s greedy, and verify by exhaustive search that no smaller explanation exists.
2. **ILP fidelity on synthetic rejections**: Generate a linear model with known bounds and a pair of thresholds; for a set of deliberately crafted rejected instances (e.g., score exactly in the middle), solve the ILP and brute‑force check that the returned set E satisfies the interval condition for all completions and that no 1‑ or 2‑feature subset does.
3. **Performance replication on a subset of MNIST**: Run MINABRO on the first 100 test images of MNIST (digits 3 vs 8) and compare average explanation size and runtime for rejected instances against the numbers reported in the paper (533 features, 167 ms). This validates both the greedy and ILP paths under realistic high dimensionality.

## Limitations
- **Implementation ambiguities**: The exact procedure for threshold calibration via empirical risk minimization and ILP solver termination criteria are not fully specified, which may hinder exact reproduction.
- **Optimality guarantees**: While the greedy algorithm is claimed optimal for accepted instances, a formal proof is absent; its optimality in edge cases (e.g., zero \(\delta\) values) remains to be fully verified.
- **Scalability**: For very high‑dimensional data, solving the ILP for rejected instances could become prohibitive, though experiments on MNIST (784 features) show acceptable performance.

## Confidence
- **Algorithmic correctness & fidelity**: Medium (theoretical reasoning is sound but lacks formal proofs for greedy optimality; ILP correctness depends on solver behavior).
- **Efficiency gains**: Medium (reported speedups are based on specific implementations; variations in solver settings or hardware may affect outcomes).
- **Conciseness of reject explanations**: Medium (depends on threshold calibration and ILP optimality; minor calibration differences could alter explanation sizes).
