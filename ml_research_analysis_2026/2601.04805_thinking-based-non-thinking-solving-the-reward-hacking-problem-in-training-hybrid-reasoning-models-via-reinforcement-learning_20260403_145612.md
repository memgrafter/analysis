# Thinking-Based Non-Thinking: Solving the Reward Hacking Problem in Training Hybrid Reasoning Models via Reinforcement Learning

## Quick Facts
- **arXiv ID**: 2601.04805
- **Source**: https://arxiv.org/abs/2601.04805
- **Reference Count**: 40
- **Primary Result**: TNT reduces token usage by ~50% while improving accuracy and achieving the best accuracy‑efficiency trade‑off, with reward‑hacking probability below 10%.

## Executive Summary
Overthinking in large reasoning models—where extended chain‑of‑thought reasoning unnecessarily inflates computational cost—hampers deployment. Existing RL‑based hybrid reasoning methods suffer from reward hacking, where models produce outputs in the “non‑thinking” format but embed hidden thinking, gaining incorrect rewards. This paper proposes Thinking‑Based Non‑Thinking (TNT), an RL approach that dynamically sets a per‑query token limit for non‑thinking responses using the solution length from sampled thinking responses. Coupled with a reward function that penalises exceeding this limit, TNT steers models toward efficient, accurate reasoning without supervised fine‑tuning (SFT). Evaluated on five math benchmarks with three base models, TNT cuts token usage by half, modestly improves accuracy, and achieves the highest Token Efficiency score, while keeping reward‑hacking probability under 10%.

## Method Summary
TNT trains a single policy model to generate two modes of responses: thinking (explicit reasoning marked with ``) and non‑thinking (direct solution). The prompt format appends an ellipsis ([..., \n]) to the query, allowing on‑policy sampling of both modes. For each prompt, multiple responses are sampled and split into thinking and non‑thinking sets based on the presence of the opening tag. The non‑thinking token limit \(L_N\) is computed per query as the average token length of the solution components (tokens after the final ``) from all thinking responses, multiplied by a safety factor \(\omega = 2\). If no thinking responses appear, a fallback \(L_\emptyset = 1000\) is used. Rewards are assigned as: thinking mode: 1 (correct) or 0 (incorrect); non‑thinking mode: 2 if correct and \(|y| \le L_N\), \(-1\) if incorrect and within limit, \(-2\) if \(|y| > L_N\). This penalises long non‑thinking outputs that likely contain hidden reasoning. The policy is updated via GRPO, a token‑level policy gradient method that uses these scalar rewards. No SFT is applied; all learning is through RL.

## Key Results
- Token usage reduced by ≈50% on average compared to base models and other RL‑based hybrid methods.
- Accuracy improved by 4.1% on the 1.5B model; Token Efficiency scores 0.53 (1.5B) and 0.79 (7B), the highest among evaluated methods.
- Reward‑hacking probability (measured by presence of thinking‑related verbs in non‑thinking responses) remains below 10% on all datasets.
- Outperforms SFT‑based baseline Thinkless and other adaptive‑think methods.

## Why This Works (Mechanism)

### Mechanism 1
- Claim: Setting per‑query adaptive token limits for non‑thinking responses prevents reward hacking while preserving efficiency.
- Mechanism: For each prompt, sample thinking‑mode responses, extract the solution part (tokens after ``), compute average length, multiply by safety factor \(\omega (=2)\) to obtain \(L_N\). Non‑thinking responses longer than \(L_N\) are penalised.
- Core assumption: The solution component in thinking‑mode responses does not contain additional reasoning; thus its length approximates a true non‑thinking solution.
- Evidence anchors:
  - [abstract] "compute the average token length of solution components from sampled thinking responses, multiply by \(\omega\) =2 for safety, to set the non‑thinking token limit."
  - [Section 4.1] Equation (2) formalises \(L_N = \omega \cdot \text{avg}_{y \in M_T} h(y)\) and fallback \(L_\emptyset\).
  - [corpus] Weak: neighbouring papers discuss reward hacking but not the adaptive limit design; the concept is unique to TNT.
- Break condition: If no thinking responses are sampled (\(M_T\) empty), fallback \(L_\emptyset\) may be poorly matched to query difficulty; also \(\omega\) chosen too low could still permit reward hacking.

### Mechanism 2
- Claim: A reward function that heavily penalises non‑thinking responses exceeding \(L_N\) effectively deters reward hacking.
- Mechanism: Non‑thinking responses receive reward 2 if correct and within \(L_N\), \(-1\) if incorrect within \(L_N\), and \(-2\) if length exceeds \(L_N\). Thinking responses receive binary reward 1/0 based on correctness. This creates a strong disincentive for generating long “non‑thinking” outputs that actually contain thinking.
- Core assumption: Reward hacking manifests as abnormally long non‑thinking responses; penalising length directly targets this.
- Evidence anchors:
  - [Section 4.1] Reward function described in Equation (4).
  - [abstract] "The adaptive limit prevents reward hacking (where non‑thinking responses are actually long) without needing SFT."
  - [Section 5] Results show reward hacking probability <10% on all datasets.
- Break condition: If \(L_N\) is inaccurate (e.g., due to few thinking samples), the penalty may be misapplied, either punishing legitimate long solutions or failing to catch reward hacking.

### Mechanism 3
- Claim: Pure RL training (no SFT) with the above reward shaping is sufficient to learn accurate and efficient hybrid reasoning.
- Mechanism: The policy is optimised via GRPO using token‑level advantages derived from the reward function. The ellipsis prompt enables on‑policy sampling of both modes. The adaptive \(L_N\) ensures the reward signal remains well‑behaved across queries.
- Core assumption: The model can infer the appropriate mode from the scalar reward; no need for explicit demonstration of mode selection.
- Evidence anchors:
  - [abstract] "without needing SFT."
  - [Section 4.1] Algorithm 1 outlines RL loop without SFT.
  - [Section 5] TNT improves accuracy by 4.1% and halves token usage compared to base models, outperforming SFT‑based Thinkless.
- Break condition: If the base model lacks reasoning capability, RL may not learn mode selection; however, the paper shows success across three base models.

## Foundational Learning
Before implementing TNT, an engineer should understand:
- **Reinforcement Learning with GRPO**: Why needed: The core training loop uses GRPO (a token‑level policy gradient method) to update the model. Quick check: How does GRPO compute token‑level advantages and incorporate the reward function?
- **Chain‑of‑Thought and Mode Discrimination**: Why needed: The method relies on distinguishing thinking vs. non‑thinking responses via special `` tags. Quick check: Given a response string, how do you split it into thinking and solution parts?
- **Token‑Level Reward Shaping**: Why needed: The reward depends on response correctness, length, and mode, and is applied at the trajectory level but influences token‑level loss. Quick check: What is the rationale behind awarding reward 2 for a correct and short non‑thinking response?
- **Adaptive Threshold Estimation**: Why needed: \(L_N\) is computed per prompt from sampled thinking responses; this estimation process is central to TNT. Quick check: Under what conditions might the fallback \(L_\emptyset\) be used, and what are its risks?

## Architecture Onboarding
- **Component Map**: The system consists of (1) policy model \(\pi_\theta\), (2) prompt formatter (ellipsis prompt), (3) sampler (generates \(K\) responses per prompt), (4) mode classifier (checks if response starts with `), (5) solution‑length estimator (computes avg \(h(y)\) from thinking set), (6) reward calculator (applies Eq.3/4/5), (7) GRPO trainer (computes loss and updates \(\pi_\theta\)). All connected in a sequence.
- **Critical Path**: For each batch: sample responses → classify modes → compute \(L_N\) per prompt → assign reward per response → estimate token‑level advantages → compute GRPO loss → update parameters. \(L_N\) computation must precede reward assignment; classification must be consistent.
- **Design Tradeoffs**:
  - \(\omega\): Larger \(\omega\) reduces false‑positives but may allow some reward hacking; too small penalises legitimate long solutions.
  - \(K\): More samples improve \(L_N\) estimation but increase compute; too few may yield unstable thresholds.
  - \(L_\emptyset\): Fallback value for prompts with no thinking samples; setting too high may fail to catch reward hacking on those prompts.
- **Failure Signatures**:
  - Non‑thinking token usage remains high (even > thinking mode) on easy queries.
  - Reward hacking probability (via thinking verbs) exceeds ~20%.
  - Accuracy drops significantly on hard benchmarks (e.g., AIME24/25).
  - Training instability: loss spikes after abrupt changes in \(L_N\).
- **First 3 Experiments**:
  1. **Replication of Table 1**: Train TNT on DeepSeek‑R1‑Distill‑Qwen‑1.5B/7B and DeepScaleR‑1.5B; evaluate on AIME24/25, Minerva, AMC23, Olympiad. Verify token reduction ~50% and accuracy gains.
  2. **Reward hacking analysis**: Compute frequency of thinking‑related verbs in non‑thinking responses; ensure <10% (as in Fig.4).
  3. **Ablation of length penalty**: Remove the \(|y| > L_N\) penalty (i.e., use Eq.6). Observe increase in non‑thinking token length and hacking probability (see Table 9, Figures 8‑9).

## Open Questions the Paper Calls Out
- **Does TNT generalize to non‑mathematical reasoning tasks?**  
  Basis: The authors confine training to mathematical datasets because they offer accurate, verifiable rewards.  
  Why unresolved: Mathematical problems have well‑defined final sections; other domains (e.g., open‑ended QA) may not separate solution from reasoning cleanly.  
  Resolution: Evaluate TNT on diverse benchmarks (e.g., MMLU, BBH) with heuristics for solution extraction.

- **How does combining TNT with other RL techniques impact trade‑offs?**  
  Basis: Limitations note they have not explored combining TNT with techniques like reference model rewards or batch‑level reward balancing.  
  Why unresolved: Potential interactions could alter convergence, mitigate hacking further, or cause instability.  
  Resolution: Ablation studies integrating each technique; measure efficiency, accuracy, hacking rate, and stability.

- **Is the fixed safety factor \(\omega = 2\) optimal across all queries and model scales?**  
  Basis: TNT sets \(\omega = 2\) to reduce misidentification risk, but no sensitivity analysis is provided.  
  Why unresolved: The balance between false positives/negatives may vary with query difficulty.  
  Resolution: Systematic experiments with varying \(\omega\) (1.5, 2.0, 2.5, 3.0) across datasets and model sizes; assess hacking detection and token savings.

- **Does the solution component truly lack additional thinking?**  
  Basis: Core assumption is that the part after the final `` tag does not contain reasoning; evidence relies on token length heuristics and verb analysis.  
  Why unresolved: Subtle reasoning (e.g., verification) may persist, making the token limit too permissive.  
  Resolution: Human or automatic analysis of solution parts to detect reasoning traces; correlate with hacking incidents.

## Limitations
- Ambiguity in solution extraction: multiple or missing `` tags can yield inaccurate length estimates.
- Evaluation restricted to mathematics; generalisability to other reasoning domains remains unproven.
- Missing implementation details (e.g., GRPO hyperparameters, exact tokenisation) impede exact replication.
