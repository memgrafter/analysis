# Towards Explainable Federated Learning: Understanding the Impact of Differential Privacy

## Quick Facts
- **arXiv ID:** 2602.10100
- **Source URL:** https://arxiv.org/abs/2602.10100
- **Reference count:** 19
- **Primary result:** FEXT-DP converges faster and attains lower mean squared error than FedAVG, but differential privacy (especially ε=0.01) flattens feature importance distributions, harming explainability.

## Executive Summary
Federated learning (FL) enables collaborative model training without sharing raw data, but integrating privacy and explainability remains challenging. This paper proposes FEXT-DP, a federated decision tree framework that incorporates differential privacy (DP) via an exponential mechanism during node split selection. Evaluated on the Appliance Energy Prediction dataset with 20 clients, FEXT-DP achieves faster convergence and lower mean squared error than the neural network-based FedAVG baseline. However, DP—particularly at ε=0.01—significantly harms explainability: the mean decrease in impurity (MDI) scores become uniformly distributed across features, obscuring key predictive factors like RH_1. The study thus highlights an inherent trade-off between privacy and explainability in FL systems.

## Method Summary
FEXT-DP is a federated learning framework that trains decision tree models on distributed clients while preserving differential privacy. Each client trains a local decision tree using an exponential mechanism to select splits, adding noise proportional to the privacy budget ε. The server aggregates trees that meet a predefined accuracy threshold K (set to 0.5) to form the global model. The method is evaluated on the Appliance Energy Prediction dataset with 20 clients. Baselines include a non-DP version of FEXT-DP and FedAVG, a neural network-based federated averaging approach. Performance metrics are mean squared error (MSE) and Pearson correlation, while explainability is measured via mean decrease in impurity (MDI).

## Key Results
- FEXT-DP (ε=1) converges faster and attains lower MSE than FedAVG (e.g., ~5250 after 4 rounds vs. ~6000).
- Strong DP (ε=0.01) significantly flattens MDI feature importance, making all features appear equally important and obscuring key predictors like RH_1.
- There is a clear trade-off: increasing privacy (lower ε) degrades both utility (slightly higher MSE) and explainability.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Differential privacy (DP) applied during decision tree split selection harms model explainability by distributing feature importance (MDI scores) more uniformly across all features, rather than concentrating it on a few predictive ones.
- **Mechanism:** The exponential mechanism injects noise into the information gain calculation for candidate splits, causing non-optimal splits to be selected. This disrupts the hierarchical accumulation of feature importance, spreading impurity reduction more evenly.
- **Core assumption:** Feature importance in a deterministic tree is concentrated because the best split is always chosen; DP perturbation breaks this concentration.
- **Evidence anchors:** Abstract statements and Fig. 4-5 showing MDI becomes uniform as ε decreases (especially at ε=0.01). Corpus papers on privacy-explainability trade-offs support the tension.
- **Break condition:** As ε → ∞ (no effective DP), split selection becomes deterministic and MDI re-concentrates on predictive features; the paper shows ε=1 case is closer to non-DP.

### Mechanism 2
- **Claim:** Federated aggregation with a performance threshold K mitigates against model poisoning from malicious or low-quality local models by discarding trees that do not meet a minimum accuracy criterion.
- **Mechanism:** The server evaluates each received tree's MSE on a validation set; only trees with MSE ≤ threshold K are aggregated. This filters out trees from corrupted data or poor generalization.
- **Core assumption:** Malicious or straggling clients produce local trees with worse validation performance than honest clients; a static threshold can distinguish them.
- **Evidence anchors:** Section III description and IV-B setting K=0.5. Corpus includes related secure aggregation work.
- **Break condition:** If an attacker crafts a malicious tree that meets the threshold (e.g., via data poisoning that maintains local validation performance), the filter fails. Threshold efficacy depends on validation data representativeness.

### Mechanism 3
- **Claim:** FEXT-DP achieves faster convergence and lower error than FedAVG on the AEPD dataset because decision trees require fewer communication rounds and are less sensitive to non-IID data than gradient-based models.
- **Mechanism:** Each FL client sends a complete trained decision tree per round (vs. weight updates). Trees are model-agnostic to local data distribution shifts; server aggregates by tree selection (no weight averaging), avoiding gradient averaging instability in heterogeneous settings.
- **Core assumption:** For tabular data, tree-based models have better inductive bias and train faster per round; the FL communication pattern is more efficient for trees than for NNs.
- **Evidence anchors:** Abstract results (lower MSE, faster convergence), Section I argument, Fig. 3a showing FEXT-DP variants consistently lower than FedAVG. Corpus supports trees on tabular data.
- **Break condition:** On highly non-IID data where feature distributions differ drastically, even trees may suffer if key features are missing locally; aggregation by selection might fail if no single local tree generalizes globally, potentially allowing FedAVG with personalization to outperform.

## Foundational Learning
- **Concept: Federated Learning (Horizontal)**
  - Why needed: Understands the distributed training paradigm where data never leaves the client, and model updates (or here, trees) are aggregated by a server. Central to FEXT-DP's architecture and threat model (privacy from data isolation).
  - Quick check: In horizontal FL, what is the primary privacy guarantee provided by the distributed setup itself, before adding DP?

- **Concept: Decision Trees & Feature Importance (MDI)**
  - Why needed: Trees are the base model. Explainability is derived from their structure and MDI scores. Need to understand how splits accumulate importance and how DP injection at the split level distorts this.
  - Quick check: How is Mean Decrease in Impurity (MDI) calculated for a feature in a single decision tree?

- **Concept: Differential Privacy (Exponential Mechanism)**
  - Why needed: The core privacy-preserving technique. The exponential mechanism is used for private split selection. Understanding its sensitivity (Δgain) and budget (ε) consumption is key to predicting the explainability-utility trade-off.
  - Quick check: In the exponential mechanism, what effect does a smaller ε have on the probability distribution over candidate splits?

- **Concept: Explainability Metrics for Trees**
  - Why needed: MDI is the primary metric used to quantify explainability loss. Need to distinguish it from other metrics (e.g., SHAP) and understand that "explainability" here means feature prominence and traceability of decisions.
  - Quick check: If all features have nearly identical MDI scores, what does that imply about the model's explainability from an MDI perspective?

## Architecture Onboarding
- **Component map:**
  FL Client (with DP module) -> FL Server (with validation set) -> FL Client

- **Critical path:**
  1. Server initializes global tree ensemble and broadcasts to all clients.
  2. Each client trains a local decision tree on its data using `best_split_with_dp` (exponential mechanism).
  3. Client evaluates MSE of its local tree and the global model on a global test set; sends the one with lower MSE.
  4. Server collects trees from clients, evaluates each on its validation set, and selects those with MSE ≤ threshold K.
  5. Server aggregates selected trees into a new global ensemble (simple union).
  6. Server broadcasts the new global model to clients.
  7. Repeat steps 2-6 for up to 40 rounds or until convergence.

- **Design tradeoffs:**
  - **Privacy-Utility-Explainability Triangle:** Lower ε (more privacy) increases noise, harming utility (slightly higher MSE) and explainability (flatter MDI).
  - **Communication vs. Aggregation Complexity:** Sending full trees per round is communication-heavy but aggregation is trivial (filter+select). Contrasts with FedAVG's smaller weight updates but requires many local epochs and careful averaging.
  - **Threshold K Rigidity:** A fixed K may be suboptimal if client data qualities vary. Too high K discards many trees, slowing learning; too low admits poor trees, harming global model. No adaptive mechanism.

- **Failure signatures:**
  - **Explainability failure:** MDI heatmap shows nearly uniform color across features (all ~5% impact), indicating DP noise overwhelms signal.
  - **Utility failure:** MSE curve for a variant plateaus at a significantly higher value than non-DP baseline or diverges, suggesting ε is too small.
  - **Convergence failure:** Global model MSE oscillates or fails to decrease over rounds, possibly due to threshold K being too strict or clients' local models consistently failing to improve.

- **First 3 experiments:**
  1. **Baseline Comparison Run:** Train FEXT-DP with ε=1 and no DP on a small subset of AEPD (5 clients, 500 samples each). Plot training/validation MSE vs. rounds for both against FedAVG. Verify faster convergence and lower error for FEXT-DP.
  2. **ε Sensitivity & Explainability:** For a converged global model, extract MDI scores for ε ∈ {0.01, 0.05, 0.1, 1, ∞}. Create a heatmap like Fig. 5. Quantify by computing Gini coefficient of MDI scores per ε; expect decrease as ε lowers.
  3. **Threshold K Ablation:** Fix ε=0.1. Run with K values representing 25th, 50th (paper's 0.5), 75th, and 90th percentile of client tree MSEs from a preliminary run. Measure final global MSE and number of trees aggregated per round. Expect higher K to reduce aggregated trees per round, possibly slowing convergence but improving per-round model quality.

## Limitations
- The accuracy threshold K=0.5 is ambiguously defined (metric and dataset), directly controlling tree aggregation and thus performance.
- The differential privacy sensitivity Δ is unspecified, which changes the noise scale and affects both utility and explainability.
- It remains unclear whether clients train a single tree or an ensemble per round, and evaluation is restricted to a single dataset, limiting generalizability.

## Confidence
- DP harms explainability via uniform MDI: **High**
- Threshold K filters malicious trees: **Medium**
- FEXT-DP converges faster/lower error than FedAVG: **Medium**

## Next Checks
1. **Recover K:** Run no-DP FEXT-DP (ε=1) with candidate thresholds (e.g., R² ≥ 0.5, MSE ≤ median) on the global test set; identify which threshold reproduces the reported baseline MSE trajectory (~5500→5250 over four rounds).
2. **Find Δ:** For low ε (e.g., 0.01), test assumed Δ values (0.1, 1, 10) in the exponential mechanism. Compute the Gini coefficient of MDI scores; the Δ yielding uniformity most similar to Fig. 5 likely matches the paper's sensitivity.
3. **Clarify aggregation granularity:** Compare single-tree versus multi-tree (e.g., 5 trees) per client per round. Assess convergence speed, final MSE, and MDI distribution; the configuration that best matches the paper's results reveals the intended design.
