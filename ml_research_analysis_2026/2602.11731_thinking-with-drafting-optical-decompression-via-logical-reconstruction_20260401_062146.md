# Thinking with Drafting: Optical Decompression via Logical Reconstruction

## Quick Facts
- arXiv ID: 2602.11731
- Source URL: https://arxiv.org/abs/2602.11731
- Reference count: 31
- Primary result: TwD model achieved composite score 82.63 on VisAlg, surpassing Gemini-3-Pro (79.96) and Gemini-2.5-Pro (74.12).

## Executive Summary
Multimodal reasoning systems often suffer from a precision paradox: OCR transcribes symbols without logical topology, and generative models produce visually plausible but mathematically inaccurate outputs. To reconstruct latent logical structures from visual inputs, this paper introduces Thinking with Drafting (TwD). TwD employs a minimalist Domain-Specific Language (DSL) as a grounding intermediate representation, forcing the model to perform "optical decompression" — parsing visual information into discrete, executable logical atoms. A deterministic renderer then creates a visual proof from the DSL, enabling self-verification in a closed loop: image → DSL → rendering → verification → answer.

On the newly proposed VisAlg benchmark (11,372 bar-model algebra problems), a Qwen3-VL-8B model fine-tuned with TwD achieves a composite score of 82.63, significantly outperforming strong baselines such as Gemini-3-Pro (79.96). The approach yields high human-LLM correlation (r = 0.9575) and generalizes to set-theoretic reasoning, demonstrating that formal intermediate representations can bridge visual perception and rigorous logical reasoning.

## Method Summary
TwD centers on a graphic DSL that encodes entities (horizontal bars with status), relations (vertical alignment lines), and aggregations (brackets). Given an image and a natural language query, the model generates DSL code. This draft is passed to a deterministic renderer that produces a visual proof, allowing checks for geometric legality (alignment, bracket placement) and semantic compliance. The final answer is derived conditioned on the verified draft. Training uses the VisAlg dataset, which contains problem images paired with ground-truth DSL parses. The dataset construction pipeline involves drafting with a frontier model, refining via rule-based verifiers (checking alignment, completeness, compliance, and answer leakage), and scoring to ensure topological and geometric correctness. Supervised fine-tuning (2 epochs, LR=5e-6) aligns the model’s generation policy with the DSL’s strict invariants.

## Key Results
- Created the VisAlg benchmark with 11,372 instances covering diverse bar-model schemas, each with gold-standard DSL annotations.
- Achieved state-of-the-art composite score of 82.63 (chrF 68.29, SSIM 93.68, alignment 0.90), surpassing Gemini-3-Pro by 2.67 points.
- Showed strong generalization to set-theoretic reasoning and high human-LLM agreement (r=0.9575), validating the DSL’s role in capturing logical topology.

## Why This Works (Mechanism)
**Forced Logical Structure Extraction via DSL**  
The minimalist graphic DSL acts as a formal grammar that compels the model to resolve visual ambiguities into discrete, executable logical atoms—a process termed optical decompression. By eschewing ambiguous natural language, the DSL enforces logical rigidity and geometric constraints. Evidence: The paper states that "natural language is ambiguous and lacks strict geometric constraints. In contrast, our DSL space S enforces logical rigidity" [section 3.1]. This aligns with prior work (e.g., RECODE) advocating derendering into executable code.

**Self-Verification via Deterministic Rendering**  
Generated DSL drafts are rendered into visual proofs by a deterministic engine. This creates an explicit feedback loop where geometric legality (e.g., alignment of vertical lines with bar segments) is checkable against formal rules. Discrepancies highlight drafting errors, enabling correction. Evidence: "The mapping from a syntactically correct DSL statement to a visual verification image V is executed by a deterministic rendering engine" [section 3.3]. The dataset pipeline employs a DSL Verifier with rules for alignment, completeness, and compliance, treating rendered output as ground truth.

**Supervised Alignment with Topological Invariants**  
Fine-tuning on VisAlb teaches the model to produce DSLs that satisfy bar-model reasoning patterns (e.g., multiplicative topology, transfer operations). The model learns a direct mapping from visual-textual inputs to rigorous structures, promoting generalization across schemas. Evidence: The fine-tuned Qwen3-VL-8B reaches the highest composite score (82.63) and performs "uniformly strong across problem types" [section 5.3], indicating acquisition of a generalizable optical decompression skill.

## Foundational Learning
### Bar-Model Algebra (Singapore Math)
Why needed: The entire DSL, dataset, and evaluation are built around canonical bar-model schemas (e.g., proportional distribution, change & revert). Understanding how quantities are represented as segmented horizontal bars and how relations (e.g., "3 times") are visualized is prerequisite to interpreting DSL primitives.  
Quick check: Given "A has 5, B has 3 more than A," draw bars and alignment lines to make the "3 more" relation visually explicit and verifiable.

### Domain-Specific Language (DSL) Design & Semantics
Why needed: The DSL is the core intermediate representation. Its operators (`HL`, `VL`, `HB`, `VB`) encode entities, relations, and aggregations with strict construction rules (e.g., reduction pattern `A - t` then `-t`, transfer as paired `-t`/`+t`). Mastery of these semantics is essential for generating valid drafts and interpreting verification metrics.  
Quick check: What is wrong with `HL "A" 0 5` and `HL "B" 1 8` for "B is 3 more than A"? How would you fix it using a `VL` alignment line?

### Verification Loop & Evaluation Metrics
Why needed: The paradigm’s value lies in closed-loop verification. Understanding what is verified—structural alignment, information completeness, numerical consistency, semantic norm compliance, and answer leakage—is key to interpreting results and building similar systems.

## Architecture Onboarding
**Component map**: Input Encoder -> DSL Generator -> Topological Abstraction & Renderer -> Verifier -> Answer Generator

**Critical path**: Optical Decompression (Image → DSL) → Deterministic Rendering (DSL → Verification Image) → DSL-Conditioned Inference (DSL + Query → Answer). During training, feedback flows from the Verifier to the DSL Generator.

**Design tradeoffs**:
- DSL Expressiveness vs. Simplicity: A richer DSL can represent more complex topologies but increases generation entropy and learning difficulty. The chosen DSL is minimalist and targeted at bar-models; extending to other diagram types requires expanding primitives and rules.
- Synthetic vs. Real Data: VisAlg uses synthetic problem-DSL pairs generated by a frontier model and refined, ensuring scale and perfect ground truth but potentially lacking noise and diversity of real human-drawn diagrams.
- End-to-End vs. Staged Training: The paper uses single-stage SFT. A multi-stage approach (e.g., pre-train on synthetic code, then fine-tune on VisAlg) might improve robustness but adds complexity.

**Failure signatures**:
- Semantic Erasure: DSL is arithmetically correct but loses required multiplicative/transfer topology (e.g., representing "3 times" as addition).
- Label Injection: Final answer value appears in a DSL label, violating the diagram-as-structure principle.
- Alignment Conflict: Generated `VL` lines or `HB` brackets do not coincide with `HL` segment boundaries, indicating spatial reasoning failure.
- Code Invalidity: DSL fails to parse or render due to syntax errors or operator misuse.

**First 3 experiments**:
1. Reproduce Benchmark Scores: Fine-tune Qwen3-VL-8B on VisAlg train split (10,430 instances) with hyperparameters (2 epochs, LR=5e-6, warmup 0.05, visual token cap 2048, max seq 5128). Evaluate on test split (942) to confirm composite score ~82.63.
2. Ablation – Removing DSL: Run the base model with standard Chain-of-Thought or answer-directly prompts on VisAlg. Expect significant drop (e.g., ~45 composite score) confirming DSL necessity.
3. Generalization Probe: Test the fine-tuned model on out-of-distribution bar-model problems (e.g., from a different curriculum) or the provided set-theoretic extension. Success indicates robust optical decompression skill beyond training schema distribution.

## Limitations
- VisAlg dataset and code are not publicly available, preventing independent replication.
- Generalization is tested only on synthetic bar-models; real-world diagram diversity remains unexplored.
- LLM-judge configuration and calibration details are omitted, raising questions about metric reliability.

## Confidence
- **Performance on VisAlg**: High (clear metrics, large margin over baselines)
- **DSL necessity**: Medium (supported by reported ablation but not fully reproduced; could be confounded by training data)
- **Closed-loop verification efficacy**: Low (no controlled experiment isolating the renderer’s role; placebo effect possible)
- **Cross-schema generalization**: Medium (limited set-theoretic tests; needs broader study)
