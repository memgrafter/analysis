# Meta-Harness: End-to-End Optimization of Model Harnesses

## Quick Facts
- **ArXiv ID:** 2603.28052
- **Source URL:** https://arxiv.org/abs/2603.28052
- **Reference count:** 40
- **Primary result:** Automated outer-loop search for LLM harnesses improves accuracy up to 7.7 points with 4× fewer context tokens versus hand-engineered baselines.

## Executive Summary
Meta-Harness replaces manual LLM harness engineering with an automated outer-loop optimization system. A proposer agent generates candidate harness programs while maintaining a persistent filesystem history of all prior harnesses, including full source code, evaluation scores, and execution traces. This rich historical data enables nuanced failure diagnosis beyond scalar feedback. The system iteratively proposes, evaluates, and stores harnesses, driving progressive improvements. Across three diverse benchmarks—online text classification, retrieval-augmented math reasoning, and agentic coding—Meta-Harness achieves substantial accuracy gains and token efficiency, outperforming state-of-the-art hand-designed harnesses.

## Method Summary
Meta-Harness introduces an automated outer-loop search that iteratively discovers and refines LLM harnesses. The core loop involves a proposer agent that generates candidate harness code. The proposer has selective filesystem access to a complete history of previous harness candidates, including their source code, evaluation scores, and detailed execution traces. This history allows the proposer to analyze failures in depth, rather than relying solely on compressed scalar rewards. After proposal, the harness is evaluated on task-specific benchmarks; results are stored in the history and used to guide subsequent proposals. The process continues until a stopping condition (e.g., budget or convergence) is met.

## Key Results
- **Text classification:** +7.7 accuracy points over ACE harness with 4× fewer context tokens.
- **Math reasoning:** A single discovered harness yields +4.7 average accuracy across five held-out models.
- **Agentic coding:** Surpasses best hand-engineered baseline Terminus-KIRA and ranks first among all Haiku 4.5 agents on TerminalBench-2.

## Why This Works (Mechanism)
The system’s effectiveness stems from two key innovations: (1) access to a comprehensive, queryable history of past harness executions, which provides actionable diagnostic information (e.g., error patterns, partial successes) that scalar rewards alone cannot convey; and (2) an outer-loop search that systematically explores the harness space using an LLM-based proposer, allowing non-obvious, high-performing harness configurations to emerge through iterative refinement. The proposer’s ability to study prior traces helps it avoid repeating mistakes and to build upon successful fragments, accelerating convergence.

## Architecture Onboarding
**Component map:**  
Search Controller → Proposer → Evaluator → History Store  
History Store → Proposer (selective query)

**Critical path:**  
1. Search Controller requests a new harness candidate.  
2. Proposer queries History Store for relevant past data.  
3. Proposer generates harness code.  
4. Evaluator executes harness on benchmark tasks, collects score and trace.  
5. Results appended to History Store.  
6. Loop repeats.

**Design tradeoffs:**  
- *History breadth vs. query cost:* Full history enables diagnosis but can overwhelm the proposer; selective access mitigates this.  
- *LLM proposer vs. determinism:* Flexible but non-deterministic; search may require multiple runs.  
- *Storage vs. richness:* Keeping all traces is storage-intensive but crucial for advanced analysis.

**Failure signatures:**  
- Proposer repeatedly re-generates near-identical low-performing harnesses (local optimum).  
- Harness code crashes or exceeds resource limits during evaluation.  
- History query latency grows unbounded with store size.

**First experiments:**  
1. Validate core loop on a minimal classification task with 5 iterations.  
2. Ablate history access: compare performance with proposer unable to read past traces.  
3. Track proposal count vs. accuracy to measure search efficiency and convergence.

## Limitations
- **Generalization scope:** Promising results on three tasks; unknown transfer to other domains or model families.  
- **Ablation clarity:** No component-level breakdown; gains could stem from a single element or benchmark overfitting.  
- **Search efficiency:** Compute cost of the outer-loop search is unreported; token savings may be offset by overhead.
