# Proactive Routing to Interpretable Surrogates with Distribution-Free Safety Guarantees

## Quick Facts
- **arXiv ID:** 2603.14623  
- **Source URL:** https://arxiv.org/abs/2603.14623  
- **Reference count:** 40  
- **Primary result:** A lightweight gate classifier combined with Clopper–Pearson conformal calibration provides distribution-free guarantees on violation rates for routed inputs, achieving substantially higher coverage than baselines while maintaining controlled violations across 35 OpenML datasets.

## Executive Summary
The paper introduces a method for safe model routing: deciding when to use a cheap, interpretable surrogate model instead of an accurate but expensive black-box model, while formally ensuring that the fraction of routed inputs where the surrogate’s degradation exceeds a tolerance τ is at most α with high probability 1−δ. A lightweight gate classifier is trained to predict, from input features alone, whether routing is safe. A routing threshold is then selected via Clopper–Pearson conformal calibration on held-out data, yielding a finite-sample, distribution-free guarantee. The approach decoules discrimination (whether safe routing is feasible) from calibration (which threshold to pick), enabling efficient deployment. Empirical results on 35 OpenML datasets show significantly higher coverage than prior methods while reliably controlling violation rates.

## Method Summary
Given a black-box model f and a surrogate g, define safety label Y=1 if degradation |y−g(x)|−|y−f(x)| ≤ τ. Train a gate classifier (logistic regression) on training data to predict Y from x. Optionally calibrate its scores on a validation set. On a separate calibration set, for each candidate gate threshold t, compute n(t) routed points and k(t) unsafe among them. Use the Clopper–Pearson upper confidence bound UCBδ(k,n) to select the lowest t such that UCBδ(k(t),n(t)) ≤ α; if none exists, set t*=∞ (abstain). At test time, route to g if s(x) ≥ t*. The guarantee Pr(V(t*) > α) ≤ δ holds distribution-free under exchangeability, independent of gate calibration quality.

## Key Results
- Gate-based conformal routing achieved substantially higher coverage (e.g., 66% at τ=2.0, α=0.2) compared to regression conformal and naive baselines, while maintaining mean violation rate near 12% (within the allowed α=0.2).
- The method provided valid δ=0.1 guarantees in 84–88% of test runs, whereas regression conformal frequently violated α.
- Routing feasibility depends on the gate’s ROC geometry: a sufficient condition is AUC ≥ Φ*ₑ*(π,α), but feasible routing can occur with lower AUC if the ROC is steep near the origin.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** A lightweight gate classifier predicts input-level safety (degradation ≤ τ) from features, enabling model selection before any expensive inference.
- **Mechanism:** The gate outputs a safety score s(x) trained to distinguish safe (Y=1) from unsafe (Y=0) inputs. Routing occurs when s(x) ≥ t. This shifts the decision from output-dependent to input-dependent.
- **Core assumption:** Input features x contain statistically detectable signal about degradation d(x), allowing a classifier to achieve non-trivial AUC (≥ critical Φ*ₑ*).
- **Evidence anchors:**  
  [abstract] “The gate is trained to distinguish safe from unsafe inputs... enabling distribution-free control of the fraction of routed inputs whose degradation exceeds a tolerance τ.”  
  [section 4.1] “We train a logistic regression classifier to predict Y from input features x... The gate outputs s(x) = P(Y=1|x).”  
  [section 5.1] “Feasible routing exists if and only if there exists threshold t such that: TPR(t)/FPR(t) ≥ C(π,α).”
- **Break condition:** When base safe rate π is too low (e.g., τ ≤ 0 in experiments), even perfect separation (AUC=1) cannot satisfy feasibility condition (6). The method abstains (t*=∞).

### Mechanism 2
- **Claim:** Clopper-Pearson conformal calibration on a held-out set selects a routing threshold t⁺ guaranteeing that the routed-set violation rate exceeds α with probability at most δ, distribution-free.
- **Mechanism:** For each candidate threshold t, compute n(t) routed calibration points and k(t) unsafe among them. The CP upper confidence bound UCB₋δ(k,n) is an exact (finite-sample) upper bound on the true violation rate V(t). Select the lowest t where UCB₋δ(k(t),n(t)) ≤ α.
- **Core assumption:** Calibration and test data are exchangeable. The gate is fixed before calibration (no peeking).
- **Evidence anchors:**  
  [abstract] “A routing threshold is chosen via Clopper–Pearson conformal calibration on a held-out set, guaranteeing that the routed-set violation rate is at most α with probability 1−δ.”  
  [section 4.2] “We select t* as the lowest threshold where the Clopper–Pearson upper confidence bound on the violation rate is at most α... UCB₋δ(k, n) = B⁻¹(1−δ; k+1, n−k).”  
  [Proposition 1] “For any gate s, any distribution over (X,Y), and calibration set of size n exchangeable with the test point: Pr(V(t*) > α) ≤ δ.”
- **Break condition:** If no threshold satisfies UCB₋δ ≤ α, t₋⁺ = ∞ (abstain from routing). This occurs when the gate's ROC fails the feasibility condition (6) or when the routed calibration size n(t) is too small for the given α.

### Mechanism 3
- **Claim:** Routing feasibility and achievable coverage are determined by the ROC geometry of the gate and the base safe rate π, not by absolute AUC alone.
- **Mechanism:** The constraint V(t) ≤ α is equivalent to a likelihood-ratio condition: TPR(t)/FPR(t) ≥ C(π,α). Coverage is maximized by finding the threshold with the steepest initial ROC slope (high TPR at low FPR). A sufficient scalar condition is AUC ≥ Φ*ₑ*(π,α), but feasibility can hold even when AUC < Φ*ₑ* if the ROC is locally steep near the origin.
- **Core assumption:** The gate’s ROC curve is representative of its generalization performance. The true base rate π is stable across calibration and test.
- **Evidence anchors:**  
  [section 5.1] “Feasible routing exists if and only if... TPR(t) ≥ C(π,α) FPR(t).” [Corollary 1]  
  [Theorem 2] “If AUC ≥ Φ*ₑ*, feasible routing exists... The bound is tight.” (for concave ROC)  
  [section 6.3] “Moderate AUC can suffice due to local ROC slope... This explains successful routing at τ ∈ {0.5, 1.0} despite AUC falling below Φ*ₑ*.”
- **Break condition:** When the gate’s ROC has poor initial slope (flat near origin), even moderate π may not yield feasible routing. The sufficient AUC threshold (Φ*ₑ* or Φₑ) provides a quick check but is conservative.

## Foundational Learning
- **Concept: Binary Classification & ROC Analysis**  
  *Why needed:* The gate is a binary classifier predicting safety. Its ROC curve (TPR vs FPR as threshold varies) characterizes the tradeoff between coverage (routed fraction) and purity (low violation). Feasibility is a geometric property of this curve (Corollary 1). Understanding TPR/FPR and the likelihood ratio test (Neyman-Pearson) is key to interpreting the feasibility condition.  
  *Quick check:* Given base safe rate π=0.8 and α=0.2, compute the required likelihood ratio C(π,α). What does a ROC point (FPR=0.1, TPR=?) need to satisfy to be feasible?

- **Concept: Conformal Prediction & Finite-Sample Guarantees**  
  *Why needed:* The CP procedure provides a distribution-free high-probability guarantee on the routed-set violation rate. It leverages exchangeability and the binomial distribution to construct an exact (Clopper-Pearson) upper bound, avoiding asymptotic approximations.  
  *Quick check:* If on the calibration set, 3 unsafe points are observed out of 150 routed points, what is UCB₋δ(3,150) for δ=0.1? Would this threshold be selected if α=0.05?

- **Concept: Calibration vs. Discrimination (ECE vs. AUC)**  
  *Why needed:* The paper separates the roles: discrimination (AUC) determines if feasible routing exists and the maximum achievable coverage. Probabilistic calibration (ECE) affects which threshold is chosen and its stability, but not the validity of the CP guarantee. Distinguishing these is crucial for interpreting results (Section 5.3, 6.5).  
  *Quick check:* If a gate has perfect discrimination (AUC=1) but is severely overconfident (ECE high), what happens to the selected threshold t₋⁺ and coverage? Does the violation rate guarantee (Pr(V>α)≤δ) still hold?

## Architecture Onboarding
Gate Trainer -> Calibrator (optional) -> Conformal Threshold Selector -> Router

**Critical path:** Offline: Train gate → (optional) calibrate → run conformal on calibration set → store t₋⁺. Online: Compute s(x) → compare to t₋⁺ → route. The gate must be trained before the calibration set is used for threshold selection to maintain exchangeability.

**Design tradeoffs:**
- **Gate complexity:** Simple models (logistic regression) minimize inference cost but limit AUC. More complex gates may increase AUC but add overhead. Tradeoff: marginal AUC gain vs. per-input latency.
- **Calibration set size:** Larger n yields tighter CP bounds and more stable t₋⁺ selection. But size trades off against training/calibration data availability. Rule of thumb: ensure n >> 1/α (e.g., n≥300 for α=0.2) to avoid vacuous bounds.
- **Tolerance τ:** Smaller τ increases stringency (fewer safe inputs, lower π). Check feasibility (Proposition 2) before deployment. If π estimated from calibration is too low, abstain.

**Failure signatures:**
- **High violation rate:** Violation significantly exceeds α. Causes: (i) calibration/test data not exchangeable (covariate shift); (ii) gate’s ROC fails feasibility condition (6) but method still routed (should not happen if CP works); (iii) insufficient calibration size n leading to loose UCB.
- **Zero coverage:** Gate abstains on all test points. Likely cause: infeasible routing (π too low, AUC too poor) → conformal returns t₋⁺=∞. Check π estimate and gate AUC.
- **Threshold instability:** t₋⁺ varies wildly across random calibration splits. Symptom of poor gate calibration (high ECE) or very small n.

**First 3 experiments:**
1. **Baseline comparison (Table 2, Figure 2):** Run gate conformal, regression conformal, naive (t=0.5), oracle on 35 datasets at α=0.2. Expected: gate conformal achieves higher coverage than regression conformal while maintaining violation near α; naive violates α.
2. **Feasibility validation (Table 1, Figure 1):** For each τ, compute π (base safe rate) and gate AUC. Check: when π is low (τ≤0), coverage should be zero (abstain). When π moderate/high, coverage should increase with τ. Verify that datasets with AUC > Φ*ₑ* tend to have positive coverage.
3. **Calibration set size ablation (Appendix D):** Vary calibration size n (e.g., 50, 100, 300) and observe stability of t₋⁺ and violation rate at fixed α. Expect: smaller n → more variable t₋⁺, sometimes higher violation (due to looser UCB).

## Open Questions the Paper Calls Out
- **Open Question 1**  
  Can group-conditional conformal methods provide finite-sample safety guarantees for subgroups within the routed set?  
  *Basis:* The authors explicitly state that extending to approximate conditional guarantees via group-conditional conformal methods is an important direction.  
  *Why unresolved:* Exact conditional coverage is impossible distribution-free; combining group-conditional intervals with adaptive threshold selection is non-trivial.  
  *What evidence would resolve it:* A theoretical guarantee for group-conditional routing, an algorithm implementing it, and empirical validation showing controlled subgroup violation rates.

- **Open Question 2**  
  How can we efficiently select both τ and t* from one calibration set while maintaining the δ guarantee?  
  *Basis:* The paper evaluates τ independently but notes practitioners may want to choose τ adaptively. Existing solutions (separate tuning, Learn-Then-Test) are data-inefficient.  
  *Why unresolved:* Joint selection requires multiple testing over thresholds that nest across τ, potentially inflating error without careful correction.  
  *What evidence would resolve it:* A closed testing procedure that controls family-wise error for nested thresholds, requiring minimal extra calibration data.

- **Open Question 3**  
  Does weighted conformal prediction yield valid safety guarantees under covariate shift when density ratios are estimated?  
  *Basis:* The paper identifies exchangeability as an assumption and suggests weighted conformal, but cautions that estimating ratios introduces uncertainty.  
  *Why unresolved:* Existing weighted conformal theory assumes known ratios; estimation error may invalidate the Clopper–Pearson bound.  
  *What evidence would resolve it:* Analysis of weighted CP with ratio estimation error, robustification techniques, and empirical tests under known shift scenarios.

- **Open Question 4**  
  Can the framework be extended to hierarchical routing with multiple surrogates to optimize cost while guaranteeing per-stage safety?  
  *Basis:* Future work includes extensions to hierarchical routing frameworks.  
  *Why unresolved:* Sequential routing decisions condition on previous gates; analyzing violation propagation and calibrating multiple gates jointly is complex.  
  *What evidence would resolve it:* A multi-stage feasibility condition, a calibration scheme for hierarchical gates, and experiments showing cost savings with maintained safety.

## Limitations
- Exchangeability assumption may be violated in practice, jeopardizing the distribution-free guarantee.
- Gate performance hinges on input features containing sufficient signal about degradation; coverage can be low if this signal is weak.
- Empirical results are limited to OpenML datasets; unknown generalizability to real-world high-stakes applications.
- Hyperparameter details (e.g., regularization strength, surrogate depth selection) are underspecified, hindering exact replication.

## Confidence
- **Theoretical guarantees (feasibility, CP bound):** High. Proofs are rigorous and finite-sample.
- **Empirical superiority over baselines:** Medium. Comprehensive 35-dataset study but lacks diversity of data domains and baseline tuning.
- **Robustness to calibration quality:** Low. Paper asserts validity independent of calibration, yet empirical support is thin; sensitivity to small calibration sets remains unclear.

## Next Checks
1. **Covariate shift stress test:** Introduce synthetic or real covariate shift between calibration and test to measure violation rate inflation and gate robustness.
2. **Gate architecture ablation:** Test more expressive gates (e.g., GBDT, neural nets) to quantify coverage gains vs. inference cost and impact on feasibility.
3. **Calibration-size sweep:** For fixed α, δ, vary calibration set size (e.g., 50–1000) over many random splits; report stability of t* and empirical violation to identify minimal n for reliable operation.
