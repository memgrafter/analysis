# Hylog: A Hybrid Approach to Logging Text Production in Non-alphabetic Scripts

## Quick Facts
*   **arXiv ID:** 2601.17753
*   **Source URL:** https://arxiv.org/abs/2601.17753
*   **Reference Count:** 40
*   **Primary Result:** Hylog successfully captures fine-grained interkeystroke intervals (IKIs) across Latin pinyin, IME confirmation, and Chinese character formation—metrics unattainable with traditional keyloggers—via a hybrid architecture that synchronizes low-level keystrokes with high-frequency ecological text snapshots.

## Executive Summary
Traditional keyloggers fail to record text transformations performed by Input Method Editors (IMEs) for non-alphabetic scripts like Chinese, missing the critical intermediate pinyin stage and confirmation events. Hylog solves this by combining a low-level keystroke logger (Inputlog) with high-frequency, application-specific plug-ins for Microsoft Word and Chrome that employ a Dynamic Snapshot Window (DSW) algorithm to efficiently log visible text changes. A post-processing hybridizer module synchronizes these two asynchronous data streams into a unified dual trace. In a proof-of-concept with two Chinese translators, Hylog captured precise timing metrics—including dwell times, positive IKIs, and rollovers—for distinct linguistic layers (Latin letters, IME confirmations, Chinese characters). Validation showed high accuracy in IME event detection (e.g., 300/305 true positives) and precise synchronization (mean lag ~40–170 ms). The resulting data reveals prolonged IKIs during IME confirmation, suggesting a distinct cognitive bottleneck in non-alphabetic typing.

## Method Summary
The method is a three-stage hybrid system. First, ecological text logging plug-ins for Word and Chrome implement the DSW algorithm, which tracks only the active text segment around the cursor to compute efficient deltas between snapshots, capturing visible IME-mediated changes. Second, a standalone hybridizer module performs a three-pass process (coherence checker, solution finder, solver) to post-synchronize the keystroke log from Inputlog with the text snapshots from the plug-ins, resolving mismatches by applying IME-specific pattern-matching rules. Third, an analyzer consumes the synchronized dual trace, segments Chinese text, builds a hierarchical timestamp tree, and computes temporal metrics (dwell time, IKI, rollover) for different linguistic units. Reproduction requires installing the Hylog components, running a logging session in Word/Chrome with a Chinese IME, and post-processing the logs.

## Key Results
*   Captured fine-grained IKIs between Latin pinyin letters, IME confirmations, and final Chinese characters—measurements impossible with Inputlog alone.
*   Achieved high IME event detection accuracy (Participant 1: 300/305 true positives; Participant 2: 82/86) and precise synchronization (mean text-logging lag ~40–170 ms).
*   Revealed distinct temporal patterns: prolonged IKIs during IME confirmation (means 513ms, 1051ms) contrasted with stable dwell times (~80–111ms), enabling new hypotheses about cognitive effort in non-alphabetic production.

## Why This Works (Mechanism)

### Mechanism 1: Dynamic Snapshot Window (DSW) for Efficient Ecological Logging
*   **Claim:** The DSW algorithm efficiently captures ecologically valid text changes without redundant storage or heavy performance overhead.
*   **Mechanism:** Instead of logging full document versions, DSW dynamically tracks only the active text segment being edited (via cursor/selection), computes differences (delta) for that window, and records offsets for reconstruction. The window expands or shrinks based on cursor movement, backspaces, and selections.
*   **Core Assumption:** A typist's editing activity is localized; tracking a moving window around the cursor captures all relevant edits with minimal data.
*   **Evidence Anchors:** [abstract] mentions "Dynamic Snapshot Window algorithm" for "efficient logging"; [section III.A.2] provides detailed algorithm description, Table III, and Algorithm 1 formalization; corpus evidence for efficiency is indirect (performance claims lack external validation).
*   **Break Condition:** If typists frequently edit large, non-contiguous segments (e.g., jumping between chapters), DSW may require full-document rescans, nullifying efficiency gains.

### Mechanism 2: Hybridizer Three-Pass Synchronization
*   **Claim:** The hybridizer's three-pass process (coherence checker, solution finder, solver) robustly synchronizes low-level keystrokes with high-level IME-rendered text, resolving inherent mismatches.
*   **Mechanism:** 1) Coherence checker matches keypresses to visible Latin letters in reconstructed text to label events as coherent/incoherent. 2) Solution finder applies pattern-matching rules (e.g., syllabic division, IME confirmation) to incoherent windows. 3) Solver rewrites the keystroke log by adjusting positions/annotations based on matched patterns.
*   **Core Assumption:** Mismatches between keylogger and text logger are systematic and predictable based on IME behavior (e.g., auto-inserted syllable separators, candidate confirmation).
*   **Evidence Anchors:** [abstract] states "hybridizer module synchronizes these traces"; [section III.B] details architecture, Figure 5/6 examples, Table IV pattern rules; corpus lacks direct IME-specific synchronization studies.
*   **Break Condition:** Use of a novel IME with undocumented behaviors (e.g., predictive pre-insertion, complex dead-keys) will cause pattern rule failures, leading to unresolved incoherences and misaligned traces.

### Mechanism 3: Decomposed Temporal Metrics for Cognitive Disentanglement
*   **Claim:** Decomposing timing into dwell time (keydown-keyup), positive IKIs (keyup-keydown), and rollovers (negative IKIs) disentangles motor execution from cognitive processing in IME-mediated typing.
*   **Mechanism:** The analyzer uses the synchronized dual trace to assign timestamps to linguistic units (pinyin syllables, Chinese characters, words) and computes three separate timing metrics. This isolates mechanical constancy (dwell time) from cognitive variation (positive IKIs) and motor fluency (rollovers).
*   **Core Assumption:** Different temporal components map onto distinct cognitive/motor subsystems; prolonged IKIs at IME confirmation reflect selection/verification effort, not motor delays.
*   **Evidence Anchors:** [abstract] notes "distinct temporal patterns across linguistic layers"; [section IV.C] presents Tables VII-IX and discussion showing dwell time stability vs. IME-confirmation IKIs; corpus shows no direct biomechanical studies—evidence is internal to proof-of-concept.
*   **Break Condition:** Use of non-standard input devices (voice, gesture typing) or highly idiosyncratic IME confirmations (e.g., long-press gestures) makes the keystroke-to-linguistic-unit mapping ambiguous, corrupting metric validity.

## Foundational Learning
*   **Concept: Input Method Editor (IME) mediation**
    *   **Why needed:** Hylog's core innovation addresses the gap where alphabetic keystrokes are transformed into non-alphabetic characters via an intermediate IME layer. Understanding pinyin input, candidate selection, and conversion is essential to grasp why traditional keyloggers fail.
    *   **Quick check:** What sequence of visible text changes occurs when a Chinese typist types "zhong1" and presses spacebar to confirm the first candidate (中)?
*   **Concept: Snapshot-based change tracking (diff algorithm)**
    *   **Why needed:** The DSW algorithm relies on computing deltas (snapshots) between text states. Knowing how a diff algorithm identifies insertions/deletions is key to understanding storage efficiency and reconstruction logic.
    *   **Quick check:** If the previous snapshot captured "hello" and the new DSW captures "help", what delta would be stored (considering the typo correction)?
*   **Concept: Temporal alignment of heterogeneous event streams**
    *   **Why needed:** Hybridization merges two asynchronous logs (high-precision keystrokes, high-frequency but delayed text snapshots). Understanding timestamp sources, monotonic clocks, and coherence checking is fundamental to the system's accuracy.
    *   **Quick check:** Why might a keystroke for letter 'a' appear "incoherent" with the text logger's snapshot taken 50ms later?

## Architecture Onboarding
*   **Component map:** Plug-ins (Word/Chrome) -> Hybridizer -> Analyzer
*   **Critical path:** Text production → Word/Chrome plug-in captures snapshots + Inputlog captures keystrokes → Hybridizer aligns streams → Analyzer computes metrics. **Synchronization fidelity is the central challenge**; everything depends on accurate temporal mapping.
*   **Design tradeoffs:**
    *   **Sampling frequency vs. overhead:** Higher snapshot frequency (e.g., 100ms) captures finer edits but increases CPU/memory use; paper uses ~500ms for Word, event-driven for Chrome.
    *   **Pattern specificity vs. generality:** More IME-specific rules (Table IV) improve accuracy for Microsoft Pinyin but require adaptation for Sogou/Baidu; core architecture remains IME-agnostic but rules are not.
    *   **Dual-trace transparency vs. convenience:** Direct dual-trace output enables re-analysis but requires post-processing; a monolithic real-time viewer would be easier but less flexible.
*   **Failure signatures:**
    *   **Coherence failure:** >5% incoherent events after solution finder → likely unsupported IME behavior or major timestamp drift.
    *   **Reconstruction error:** Offsets computed incorrectly → rebuilt text diverges from screen recording; check by comparing final text.
    *   **Performance bottleneck:** Plug-in lag >200ms → DSW window may miss rapid edits; monitor CPU usage during long documents.
*   **First 3 experiments:**
    1.  **DSW efficiency benchmark:** Log a 50k-character document with 500 editing actions; compare Hylog's snapshot size vs. full-document logging at 500ms intervals. Expect ~10x reduction.
    2.  **Hybridizer validation:** Replay a logged session with known keystroke/text sequence (e.g., video-verified 100 pinyin confirmations); compute false positive/negative IME detection rates. Target: >95% precision/recall.
    3.  **Metric consistency check:** Have same participant type same Chinese paragraph twice; compare Hylog's IKI distributions (letters/characters/IME) across sessions. Expect stable dwell times, variable IME IKIs; high correlation (r>.7) in within-unit IKIs.

## Open Questions the Paper Calls Out
**Open Question 1:** How accurate is Hylog's IME event detection when applied to different input method editors (e.g., Sogou Pinyin, Baidu Pinyin), and to what extent must the pattern-matching rules be adapted for each IME?
*   **Basis in paper:** [explicit] The authors state that "for different IMEs (e.g., Sogou Pinyin, Baidu Pinyin), the pattern-matching rules may need adjustment to accommodate IME-specific behaviors, though the core architecture should remain applicable since all pinyin IMEs share fundamental features." They tested only Microsoft Pinyin IME.
*   **Why unresolved:** The hybridizer's rule-based approach was validated only with one IME; different IMEs may handle syllable segmentation, candidate confirmation, and punctuation differently, affecting coherence checking and solution finding.
*   **What evidence would resolve it:** Collect parallel logs (Inputlog + Hylog + screen recording) from participants using multiple IMEs on the same Chinese typing tasks. Manually annotate IME confirmations from video, then compute precision, recall, and F1-score of Hylog's detection per IME. Analyze rule failures to refine patterns.

**Open Question 2:** Do the distinct IKI patterns around IME confirmation events (e.g., prolonged before/after intervals) measured by Hylog correspond to increased cognitive load during character selection, as indicated by concurrent measures like eye-tracking fixation duration or retrospective difficulty ratings?
*   **Basis in paper:** [inferred] The authors interpret prolonged IKIs during IME confirmation as reflecting "a distinct cognitive bottleneck" and "computational and cognitive cost," but this is based solely on temporal patterns without independent cognitive validation. They suggest these metrics enable hypotheses about cognitive effort.
*   **Why unresolved:** The study lacked concurrent cognitive measures or subjective reports to link timing data to mental effort. The inference that longer IKIs equal higher cognitive load is plausible but not proven; alternative explanations (e.g., motor planning, reading) remain.
*   **What evidence would resolve it:** Conduct experiments combining Hylog with eye-tracking to capture visual attention during IME candidate selection. Correlate IKI durations with fixation counts/durations on candidate list. Alternatively, use think-aloud or retrospective interviews to self-report difficulty at moments identified by Hylog as high-ICI intervals. Test predictive power of IKI metrics for task outcomes (e.g., error rates, revision patterns).

**Open Question 3:** Can the Hylog hybrid architecture be effectively extended to other non-alphabetic writing systems (e.g., Japanese, Korean Hangul, Arabic), and what script-specific modifications are required to maintain high accuracy in keystroke-text synchronization?
*   **Basis in paper:** [explicit] The authors acknowledge that "each [script] represents an important direction for future work" and describe specific challenges: Japanese has multiple scripts and input methods; Korean involves syllabic composition; Arabic requires right-to-left handling. No implementations or tests exist beyond Chinese.
*   **Why unresolved:** The pattern-matching rules and DSW algorithm are designed with Chinese pinyin IMEs in mind. Other scripts may have fundamentally different input flows (e.g., Korean Hangul composition builds syllables from jamo; Japanese switches between scripts), potentially breaking coherence checking or snapshot reconstruction.
*   **What evidence would resolve it:** Develop Hylog plug-ins for representative applications in each target script (e.g., Japanese IME with romaji input, Korean Hangul input, Arabic text editors). Conduct validation studies similar to the proof-of-concept, measuring detection accuracy of script-specific events (e.g., syllable completion, script conversion) against manual coding. Document necessary architectural changes.

**Open Question 4:** Does Hylog's ecological approach (logging across multiple applications with variable snapshot frequency) introduce measurable noise or gaps in temporal precision compared to laboratory-grade keyloggers, and how does this affect the reliability of fine-grained IKI analyses?
*   **Basis in paper:** [inferred] Hylog prioritizes ecological validity by logging in standard applications (Word, Chrome) with a DSW algorithm sampling at ~500 ms. The paper reports mean logging lags of 40-170 ms and claims high accuracy, but the impact of sampling interval and application-specific delays on IKI distributions is not thoroughly examined. Traditional keyloggers like Inputlog have higher temporal precision but are non-ecological.
*   **Why unresolved:** The trade-off between ecological logging and millisecond precision is central to keylogging methodology. Hylog's snapshot-based approach may miss brief text states or introduce jitter, affecting IKI calculations, especially for fast typists or short intervals. The paper shows high accuracy in IME detection but does not quantify precision loss for sub-lexical IKIs.
*   **What evidence would resolve it:** Compare Hylog's IKIs (from dual trace) with those from a high-precision, single-application keylogger (e.g., low-level hook) in controlled tasks where participants type in both alphabetic and Chinese text. Measure differences in IKI distributions, focusing on short intervals (<200 ms). Assess whether DSW parameters (sampling rate, window size) can be optimized to minimize error without sacrificing ecological coverage.

## Limitations
*   **Implementation Black Box:** Full code for the DSW and hybridizer is not yet public, blocking exact replication of the synchronization logic and efficiency claims.
*   **IME Generalizability:** Pattern rules are validated only for Microsoft Pinyin. Performance with other major IMEs (Sogou, Baidu) is an unchecked unknown with likely different candidate behaviors.
*   **Small-Scale Validation:** Proof-of-concept used only two participants on a single task. Stability of the revealed temporal patterns across users, genres, and IMEs remains unproven.

## Confidence
*   **Hybridizer Synchronization Accuracy:** High (directly supported by strong validation metrics: 300/305 TP, precise lag measurement)
*   **DSW Algorithm Efficiency:** Medium (mechanism described and logically sound, but lacks independent benchmarking)
*   **Cognitive Hypotheses from Metrics:** Medium (data shows consistent patterns, but causal link to cognitive effort is inferential based on minimal sample)
