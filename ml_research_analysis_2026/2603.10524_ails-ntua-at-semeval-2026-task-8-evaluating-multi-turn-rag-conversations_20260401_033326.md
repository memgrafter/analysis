# AILS-NTUA at SemEval-2026 Task 8: Evaluating Multi-Turn RAG Conversations

## Quick Facts
*   **arXiv ID:** 2603.10524
*   **Source URL:** https://arxiv.org/abs/2603.10524
*   **Reference Count:** 40
*   **Primary Result:** 1st place in subtask A (retrieval) with nDCG@5=0.5776, achieving a +20.5% improvement over the baseline.

## Executive Summary
AILS-NTUA's system for SemEval-2026 Task 8 (multi-turn RAG) employs a two-phase architecture: a retrieval phase using five LLM-based query reformulations fused via a variance-aware method over a single sparse retriever, and a generation phase with a multi-stage pipeline involving answerability checking, evidence extraction, and dual-candidate judgment. The system achieved 1st place in subtask A (retrieval) and 2nd in subtask B (generation), but ranked 11th in the end-to-end subtask C. This performance drop indicates the integration mechanism, particularly the answerability gate, is the primary bottleneck limiting overall effectiveness.

## Method Summary
For retrieval (A), the system generates five diverse query reformulations using an LLM, retrieves from a single corpus-aligned sparse retriever, and fuses results using a variance-aware nested reciprocal rank fusion. This aggregates high-variance reformulation strategies first, then combines them with stable ones using corpus-specific weights. For generation (B), a multistage pipeline first checks answerability, then extracts an evidence span, drafts two candidate answers, and selects one via a judge model, with response extractiveness shaped during drafting. Task C integrates the two with an additional multi-judge answerability gate acting as a filter between retrieval and generation.

## Key Results
*   **Subtask A (Retrieval):** 1st place (nDCG@5=0.5776, +20.5% over baseline).
*   **Subtask B (Generation):** 2nd place (HM=0.7698, RLF=0.8971).
*   **Subtask C (End-to-End):** 11th place (HM=0.5409), showing a significant drop from the strong performance in A and B.

## Why This Works (Mechanism)
The analysis suggests two key strengths. First, using **query diversity over a single, corpus-aligned retriever** proves more effective than ensembling multiple different retrievers, likely because it maintains consistent document alignment while exploring varied query expressions. Second, the **variance-aware fusion** method improves robustness by dynamically weighting reformulation strategies: high-variance (potentially high-reward) strategies are aggregated separately before being combined with more stable ones, using weights tuned to the specific corpus. In generation, the staged filtering (answerability check, evidence extraction, dual drafting) aims to enforce groundedness but may introduce cumulative filtering errors that hurt recall in the end-to-end setting.

## Foundational Learning
*   **Reciprocal Rank Fusion (RRF):** A method to combine ranked lists from multiple sources. *Why needed:* To aggregate results from diverse query reformulations without requiring score normalization. *Quick check:* Apply standard RRF vs. variance-aware RRF on a sample of reformulated queries and compare nDCG.
*   **Answerability Calibration:** Determining whether a question is answerable from the given corpus. *Why needed:* To prevent generation from unsupported or unanswerable queries, reducing hallucination. *Quick check:* Evaluate the precision/recall of the answerability classifier on a held-out set with known answerability labels.
*   **Extractiveness Shaping:** Steering the generation model to produce responses closer to the source text. *Why needed:* To improve faithfulness and reduce fabrication in RAG systems. *Quick check:* Measure response extractiveness (e.g., using ROUGE-L with source passages) before and after applying the shaping technique.
*   **Variance-Aware Strategy Aggregation:** Weighting information retrieval strategies based on their stability/consistency across queries. *Why needed:* To prioritize reliable signals and mitigate the impact of outlier reformulations. *Quick check:* Compute variance of nDCG scores per reformulation across a query sample and verify higher-variance strategies receive different fusion treatment.
*   **Multi-Stage Candidate Filtering:** Sequentially applying filters (answerability, evidence, judgment) to narrow down response candidates. *Why needed:* To reduce noise and enforce quality at each step of the generation pipeline. *Quick check:* Track the retention rate of candidates at each filtering stage to identify the most aggressive filter.

## Architecture Onboarding
*   **Component Map:** Query Reformulation -> Sparse Retriever -> Variance-Aware Fusion -> Answerability Check -> Evidence Span Extraction -> Dual Candidate Drafting -> Judge Selection -> (for Task C) Multi-Judge Answerability Gate
*   **Critical Path:** The retrieval path (reformulation -> retriever -> fusion) and generation path (answerability -> extraction -> drafting -> judging) are independent until the final integration gate in Task C. The answerability gate is the critical integration point.
*   **Design Tradeoffs:** 
    *   *Single corpus-aligned retriever vs. retriever ensemble:* Chose a single retriever for consistent document space, sacrificing potential diversity from multiple retrieval algorithms.
    *   *Strict answerability gate vs. recall:* A stringent gate improves precision but likely rejects valid candidates, hurting end-to-end recall.
    *   *Corpus-specific fusion weights vs. generalizability:* Tuning weights to the task corpus maximizes performance on this dataset but may not transfer.
*   **Failure Signatures:** 
    *   Low nDCG@5 in subtask A: Indicates poor retrieval due to ineffective reformulation or fusion.
    *   Low HM in subtask C despite high A/B scores: Indicates the integration gate is rejecting too many valid generation outputs.
    *   High candidate rejection rate at early generation stages (answerability/evidence): Suggests over-filtering.
*   **First Experiments:**
    1.  Analyze a sample of failures in Task C to categorize whether rejection occurred at the retrieval phase (missing passages) or the answerability gate (rejected a valid B-output).
    2.  Re-run retrieval (A) comparing the proposed variance-aware nested RRF against standard RRF and against using individual reformulations alone, to directly test the "query diversity > retriever ensembles" claim.
    3.  Perform an error propagation audit through the generation pipeline (B), measuring candidate loss at each stage (answerability check -> extraction -> drafting -> judging) on a validation set.

## Limitations
*   The system's performance degrades significantly from subtasks A/B to the integrated C, pointing to the multi-judge answerability gate as a primary bottleneck, but the paper lacks detailed failure analysis for this integration.
*   The generalizability of the corpus-specific fusion weights and the precise mechanism/impact of "extractiveness shaping" are not thoroughly investigated.
*   There are no ablation studies isolating the contribution of individual components (e.g., variance-aware fusion vs. query diversity) to the final scores.

## Confidence
*   **High:** Reported competition metrics for subtasks A and B, as these are official results.
*   **Medium:** Descriptions of the multistage generation pipeline and variance-aware fusion method; the methodology is clear but its independent impact is not ablated.
*   **Low:** Analytical claims that "query diversity over an aligned retriever outperforms retriever ensembles" and that "answerability calibration is the primary bottleneck." These are inferred interpretations not proven via controlled experiments within the paper.
