# Shiva-DiT: Residual-Based Differentiable Top-$k$ Selection for Efficient Diffusion Transformers

## Quick Facts
- **arXiv ID:** 2602.05605
- **Source URL:** https://arxiv.org/abs/2602.05605
- **Reference count:** 40
- **Primary result:** On SD3.5-Medium (1024×1024, 50 steps, RTX 4090), Shiva-DiT achieves a 1.54× wall‑clock speedup (latency reduced from 7659.9 ms to 4989.0 ms) while improving generative fidelity: FID 16.86→16.42, CLIP Score 30.89→31.35, CLIP‑IQA 0.4567→0.4952.

## Executive Summary
Diffusion Transformers (DiTs) are computationally demanding due to quadratic attention costs. Existing token pruning methods struggle with the trilemma of differentiability, training efficiency, and strict static token budgets needed for hardware‑friendly execution. Shiva‑DiT resolves this via Residual‑Based Differentiable Top‑$k$ Selection, which enforces a deterministic token count in the forward pass and uses a residual‑aware straight‑through estimator for end‑to‑end gradient propagation to both token scores and the learnable budget $k$. Coupled with a Context‑Aware Router and an Adaptive Ratio Policy, the system learns spatiotemporal pruning schedules without manual heuristics. The result is a new Pareto frontier: a 1.54× speedup on SD3.5‑Medium together with measurable fidelity gains, achieved through static compilation that eliminates ragged tensor overhead.

## Method Summary
Shiva‑DiT integrates three core modules: (1) an **Importance Router** that scores each token using contextual features (token $x_i$, text condition $c$, timestep $t$, layer embedding $l$), with pairwise layer sharing to balance capacity and generality; (2) an **Adaptive Ratio Policy** that predicts a retention ratio $r_{t,l}$ per layer and timestep via a decoupled additive MLP, ensuring the global FLOPs target is respected through an EMA‑based budget loss; and (3) a **Differentiable Selection Module** that converts $r_{t,l}$ to an integer budget $k$ and performs a hard top‑$k$ selection. The backward pass employs a residual‑aware straight‑through estimator: soft inclusion probabilities $\pi_i$ derived from pairwise sigmoid comparisons on perturbed scores yield gradients for both scores and $k$. Training follows three stages—Router Warmup (stratified random ratios to broaden score distribution), Policy Learning (activate policy, add budget loss, inject logit noise), and Joint Tuning (unfreeze LoRA/backbone). The strict static token count per $(t,l)$ enables hardware‑aligned static compilation, avoiding ragged tensor overheads.

## Key Results
- 1.54× speedup on SD3.5‑Medium (RTX 4090): latency 7659.9 ms → 4989.0 ms.
- Improved fidelity: FID 16.86 → 16.42, CLIP Score 30.89 → 31.35, CLIP‑IQA 0.4567 → 0.4952.
- Consistent gains across Flux.1‑dev and PixArt‑Σ with similar efficiency improvements.

## Why This Works (Mechanism)

### Mechanism 1: Residual-Based Differentiable Sorting
- **Claim:** Residual-Based Differentiable Sorting enables end‑to‑end optimization of a deterministic token budget (`k`) while maintaining hardware‑friendly static tensor shapes.
- **Mechanism:** The forward pass executes a hard top‑`k` selection on importance scores, enforcing a fixed token count. The backward pass uses a residual‑aware straight‑through estimator (STE) that models the selection as a continuous gate between the active (selected) and identity (rejected) residual paths. This surrogate provides gradients for both the token scores *and* the budget parameter `k` via the soft inclusion probability $\pi_i = \sigma((k - \text{soft\_rank}_i)/\tau)$, where $\text{soft\_rank}_i$ is computed from perturbed scores using pairwise sigmoid comparisons.
- **Core assumption:** The gradient estimate from the residual paths ($\nabla_{\text{sel}}$ and $\nabla_{\text{rej}}$) is a valid directional signal for optimizing the discrete selection, and stochastic training (via score perturbation and stratified ratio sampling) ensures tokens experience both paths over time, allowing the single‑path estimator to approximate the expected gradient.
- **Evidence anchors:** [abstract]; [section 3.2] (Eqs. 5–7); [section A.2] (gradient w.r.t. $k$, sign consistency, variance analysis); neighboring work on differentiable fast top‑k (paper_id 110629) addresses related challenges but not within a residual framework.
- **Break condition:** If the estimator’s sign becomes unreliable in a highly nonlinear loss landscape, $k$ may diverge from optimal sparsity, causing fidelity collapse or no speedup. Synthetic validation (Fig. 6) shows robustness under controlled conditions, but real DiT training introduces additional complexities (e.g., multi‑layer interactions) not fully captured.

### Mechanism 2: Context‑Aware Router with Pairwise Sharing
- **Claim:** The Context‑Aware Router with pairwise parameter sharing learns a depth‑adaptive token importance metric that generalizes across varying sparsity levels required by the Adaptive Ratio Policy.
- **Mechanism:** A lightweight network conditions a token’s feature on global context (text $c$, timestep $t$, layer embedding $l$). The score is predicted via a shared projection and normalization. Parameter sharing is applied pairwise (every two adjacent layers), balancing capacity to capture local feature consistency against overfitting from per‑layer independence.
- **Core assumption:** Token redundancy exhibits local consistency across adjacent transformer layers, so a shared router can generalize effectively if not forced to learn disjoint policies. The conditioning signals ($c$, $t$, $l$) sufficiently capture the multi‑dimensional dependencies.
- **Evidence anchors:** [section 3.3] (pairwise sharing optimality, Table 2); [section 4.2] (sharing as regularizer, Fig. 5 visualizations); [section B.1] (stratified sampling yields dispersed score distribution, Fig. 7).
- **Break condition:** If spatial redundancy patterns change drastically between non‑adjacent layers (e.g., early texture vs. late semantic), pairwise sharing may force a single policy to handle conflicting objectives, degrading ranking accuracy. The ablation (Table 2) shows independent routers overfit, indicating too much capacity without sharing is harmful.

### Mechanism 3: Adaptive Ratio Policy with Decoupled Additive Modulation
- **Claim:** The Adaptive Ratio Policy with decoupled additive modulation and EMA‑budget constraint autonomously learns a spatiotemporally adaptive pruning schedule (e.g., “structure‑first”) without manual heuristics while respecting a global FLOPs target.
- **Mechanism:** A lightweight MLP predicts a retention ratio $r_{t,l}$ from timestep $t$ and layer $l$ embeddings via additive combination: $\text{logit}(r_{t,l}) = \Phi_{\text{time}}(t) + \Phi_{\text{layer}}(l) + b_{\text{anchor}}$. A global EMA ($\mu_{\text{global}}$) tracks the long‑term average ratio. The budget loss $\mathcal{L}_{\text{budget}} = \lambda \cdot r_{\text{batch}} \cdot \text{sg}[2(\mu_{\text{global}} - R_{\text{target}})]$ provides a directional signal: if the global average exceeds the target, gradients push $r_{\text{batch}}$ down (and vice versa), decoupling the constraint from mini‑batch variance.
- **Core assumption:** The optimal sparsity can be decomposed into independent spatial (layer‑wise) and temporal (timestep‑wise) components. The additive design and EMA enable stable learning of a time‑dependent schedule without collapsing to a uniform ratio. Stratified timestep sampling reduces variance of $r_{\text{batch}}$, stabilizing EMA updates.
- **Evidence anchors:** [section 3.4] (decoupled additive architecture); [section 3.4] (Eqs. 12–13, EMA and budget loss); [section 4.2] (learned heatmap, Fig. 4b: high ratios ~0.8 for later timesteps, low ~0.4 for early); [section B.4] (negligible overhead vs. dual‑pass baselines).
- **Break condition:** If the true optimal schedule is not decomposable (e.g., requires layer‑specific temporal interactions), the additive policy may underfit. The fixed‑ratio baseline (Table 3) performs worse, suggesting benefits outweigh potential modeling limitations, but the decomposition remains an assumption.

## Foundational Learning
- **Diffusion Probabilistic Models / Flow Matching** – Why needed: The paper’s objective and compatibility argument hinge on understanding the unified formulation of DDPMs and flow matching. Token pruning operates within the iterative denoising loop of a DiT backbone $F_\theta(x_t, t, c)$. Without grasping the noising/denoising process and the regression target, the motivation for temporal adaptivity is unclear. Quick check: In the unified objective $\|F_\theta(x_t, t, c) - y_t\|^2$, what does $y_t$ represent for a standard Stable Diffusion 1.5 model vs. an SD3/Flux model? How might the semantic content of tokens change as $t$ decreases (denoising progresses)?
- **Transformer Self‑Attention Complexity & Hardware Compilation** – Why needed: The core problem is quadratic $O(N^2)$ attention cost. The solution’s goal is hardware‑friendly static compilation (e.g., CUDA Graphs). Understanding why ragged tensors (variable sequence length) are detrimental—kernel launch overhead, memory reallocation, poor batching—is essential to appreciate the “Strict Budget” vertex. The paper contrasts this with methods that produce ragged tensors (e.g., DyDiT). Quick check: Why does FlashAttention’s tiling algorithm make it incompatible with methods that require a full $N\times N$ attention map? What is the practical latency impact of launching a separate kernel for each sample in a batch when sequence lengths differ?
- **Differentiable Relaxations for Discrete Operations (STE, Gumbel‑Softmax, NeuralSort)** – Why needed: The trilemma’s “Differentiability” vertex requires a method to learn discrete top‑$k$. The paper contrasts its residual‑based STE with Gumbel‑Softmax (used in DyDiT, leading to ragged tensors) and NeuralSort (quadratic memory). Understanding these alternatives clarifies why previous works failed the trilemma and how Shiva’s approach is novel. Quick check: What is the key difference between a Gumbel‑Softmax relaxation (which produces a soft mask with expected sparsity) and a straight‑through estimator applied to a hard top‑$k$ operation? Why does the former lead to unpredictable token counts (ragged tensors) while the latter can enforce a strict $k$?

## Architecture Onboarding

### Component Map
Importance Router → Adaptive Ratio Policy → Differentiable Selection Module → Hook Manager → DiT backbone. Supporting components: Budget Controller (tracks global EMA and computes budget loss) and Staged Training Scheduler (orchestrates Router Warmup, Policy Learning, Joint Tuning).

### Critical Path
- *Inference:* For each timestep $t$ and layer $l$, the Adaptive Ratio Policy outputs $r_{t,l}$, which is discretized to $k$. The Importance Router scores all tokens; the Differentiable Selection Module picks top‑$k$ indices; the Hook Manager injects this selection into the DiT block; the selected token set $X_{\text{sel}}$ flows through the remaining layers.  
- *Training:* The diffusion loss $\mathcal{L}_{\text{diff}}$ is computed on the output of the selected path. Backpropagation follows the hard selection (only $X_{\text{sel}}$ contributes). The straight‑through estimator uses stored inclusion probabilities $\pi_i$ and a residual‑based gradient that combines $\nabla_{\text{sel}}$ (from the executed forward) and an approximate $\nabla_{\text{rej}}$ (from the rejected identity path) to update token scores and $k$. The Budget Controller maintains an EMA $\mu_{\text{global}}$ of the batch mean ratio and adds $\mathcal{L}_{\text{budget}}$ to steer the global FLOPs toward the target.

### Design Tradeoffs
- **Hardware Alignment vs. Router Capacity:** Pairwise layer sharing drastically reduces router parameters (4.1 M vs. 64 M) and prevents overfitting, but may lack flexibility for highly specialized layers. The paper finds pairwise sharing optimal (Table 2).
- **Single‑Pass Efficiency vs. Gradient Fidelity:** The residual STE is single‑pass (unlike dual‑forward methods), but introduces high‑variance gradient estimates. Variance is managed by router warmup and stratified sampling, trading some fidelity for training speed.
- **Additive Policy vs. Multiplicative (FiLM):** The additive decoupling of time and layer embeddings stabilizes optimization and allows pre‑computation into a lookup table at inference. A multiplicative design might capture more complex interactions but would require per‑token computation, negating speed gains.
- **First‑Block Skip:** Skipping pruning in the first transformer block preserves nascent representations, adding negligible fixed cost and stabilizing training.

### Failure Signatures
- **Training instability:** Loss spikes or router scores collapse (near 0 or 1). Likely due to aggressive budget loss weight or insufficient router warmup.
- **Poor quality despite speedup:** Significant FID/CLIP degradation. Indicates over‑pruning (budget $k$ too low) or router misranking (salient tokens pruned). Diagnose via mask visualizations and policy heatmap.
- **No speedup / ragged tensors:** Latency unchanged vs. Vanilla. Suggests selection not properly integrated (e.g., dynamic shapes persist) or RoPE handling broken. Verify $X_{\text{sel}}$ shape reduction and kernel launch profile.
- **Policy collapse to uniform $r$:** Heatmap shows flat retention ratios. Could be dominated by budget loss or insufficient stratified timestep sampling. Check $\lambda_b$ and sampling variance.

### First 3 Experiments
1. **Synthetic Validation of Budget Learning:** Train on synthetic data with known signal tokens; verify that the learned budget $k$ converges to the true number of signal tokens (e.g., $\approx$20) when initialized too high.
2. **Router Warmup Ablation:** Compare router ranking accuracy (Spearman’s $\rho$) when trained with and without stratified ratio sampling during warmup, under a held‑out target ratio (e.g., 0.4 vs. 0.6 used in warmup). Expect more robust score distribution and better generalization with stratified warmup.
3. **Static vs. Adaptive Policy under Fixed Global Budget:** Fix global average token count (e.g., $\bar{r}=0.6$) via EMA constraint. Compare (a) fixed uniform ratio, (b) Shiva’s adaptive policy, (c) a heuristic “early low, late high” schedule. Measure validation MSE (or FID) after a few epochs; adaptive policy should converge faster and to a lower loss.

## Open Questions the Paper Calls Out
- **How can information from pruned tokens be fused or reintegrated into the active token set to preserve details in high‑density, low‑redundancy scenes?** The current hard selection discards tokens; fusion could mitigate detail loss but requires non‑trivial design to maintain efficiency.
- **How can topology‑aware RoPE selection be designed to preserve spatial relationships in models using rotary positional embeddings during token pruning?** Current implementation gathers RoPE components based on selected indices, which may not preserve relative positioning semantics; a more principled approach is needed.
- **Is the decoupled additive assumption for the adaptive ratio policy (modeling spatial and temporal redundancies as independent additive factors) valid across diverse DiT architectures and sampling schedules?** The assumption may not hold universally; evidence across a broader set of models and regimes is lacking.

## Limitations
- **Cross‑Model Generality Unknown:** The paper validates on SD3.5‑Medium and briefly on Flux.1‑dev and PixArt‑Σ, but exact hyperparameters for the latter are unspecified, making faithful replication uncertain.
- **Implementation Complexity of Hardware Alignment:** The claim of “ragged tensor overhead elimination” relies on precise integration (e.g., correct RoPE index gathering). Low‑level profiling details beyond final latency numbers are not provided, making verification difficult.
- **Gradient Estimator Variance in Practice:** The residual‑based STE is analytically justified and validated on a synthetic task, but its stability and sign consistency in the high‑dimensional, non‑convex loss landscape of a large DiT, especially under extreme sparsity, is not fully characterized.
