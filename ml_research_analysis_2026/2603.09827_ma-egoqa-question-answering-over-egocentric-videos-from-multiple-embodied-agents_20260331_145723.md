# MA-EgoQA: Question Answering over Egocentric Videos from Multiple Embodied Agents

## Quick Facts
- **ArXiv ID**: 2603.09827
- **Source URL**: https://arxiv.org/abs/2603.09827
- **Reference count**: 40
- **Primary result**: Introduces the MA-EgoQA benchmark and the EgoMAS baseline, achieving 41.41% accuracy on multi-agent egocentric QA, a 4.48% improvement over state-of-the-art (36.93% with Gemini-2.5-Flash).

## Executive Summary
MA-EgoQA is a novel benchmark for question answering over long-horizon egocentric videos captured by multiple embodied agents. The dataset comprises 1,741 multiple-choice questions derived from the EgoLife dataset, spanning six agents over seven days (266 hours). Questions are categorized into social interaction, task coordination, theory of mind, temporal reasoning, and environmental interaction, and require integrating information from at least two agents. The authors propose EgoMAS, a training-free framework that constructs a shared memory of events using 4W1H (When, What, Where, Who, How) summaries generated every 10 minutes from each agent’s video caption. During inference, EgoMAS retrieves relevant shared memories, generates agent-specific sub-queries, performs dynamic retrieval from individual agent memories, and finally produces an answer using a large language model. Experiments show that current video LLMs and LLMs perform poorly on this task (maximum 36.93% accuracy). EgoMAS improves performance to 41.41% using the same backbone (Gemini-2.5-Flash) and achieves a 4.48% absolute gain. Even with the open-source Qwen3VL-8B-Thinking model, EgoMAS matches Gemini’s accuracy under a 1M token context. The system operates with low latency (1.3 seconds). However, theory of mind remains the most challenging category, and there remains a large gap (42%) between EgoMAS and the oracle upper bound, indicating significant room for improvement.

## Method Summary
EgoMAS is a training‑free framework for multi‑agent egocentric video question answering. Given long‑horizon first‑person videos from several agents, the system first segments each stream into 10‑minute windows and generates textual captions (or transcripts). A shared memory is built by aggregating captions from all agents per window and prompting an LLM to produce structured 4W1H summaries (When, What, Where, Who, How), which are stored in a global index. Each agent also retains its own memory of raw captions. During inference, the query is matched against the shared memory using BM25 to retrieve the top‑n relevant summaries. An LLM then crafts agent‑specific sub‑queries paired with agent identifiers. For each pair, the system retrieves the top‑k memories from that agent’s personal memory using BM25 with a score threshold τ. Finally, the query and all retrieved contexts (shared and per‑agent) are provided to an LLM backbone to generate the answer. With hyperparameters n=20, k=5, τ=10, EgoMAS achieves 41.41% accuracy on MA‑EgoQA and runs in 1.3 seconds, demonstrating the effectiveness of event‑based shared memory and selective retrieval.

## Key Results
- EgoMAS achieves 41.41% average accuracy on MA‑EgoQA (test split) using Gemini‑2.5‑Flash as the backbone, outperforming the state‑of‑the‑art (36.93%) by 4.48% absolute.
- Ablations confirm the importance of agent‑wise dynamic retrieval (excluding it reduces accuracy to 30.04%) and show that stronger retrievers (e.g., NV‑Embed) further improve results.
- The benchmark reveals persistent challenges: theory of mind is the hardest category, and the oracle accuracy (83.80%) leaves a 42% gap, indicating substantial room for future work.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim**: Aggregating fragmented egocentric experiences across agents into structured 4W1H summaries at fixed intervals creates a coherent, compressed global memory that retains essential event information while discarding irrelevant details.
- **Mechanism**: Every 10 minutes, each agent’s video caption is processed; a central manager identifies key events across agents and constructs a memory entry with fields: *When* (time), *What* (action), *Where* (location), *Who* (participants), *How* (details). This aligns timelines and focuses on multi‑agent interactions.
- **Core assumption**: Key information for QA can be captured in these structured summaries without needing raw video frames or full captions.
- **Evidence anchors**:
  - [abstract] “EgoMAS leverages shared memory across embodied agents and agent‑wise dynamic retrieval.”
  - [section 5.1] “At every 10‑minute interval, each embodied agent provides a caption summarizing its own observations during the preceding time span. A centralized manager then integrates these individual captions into a system‑level summary… for each event, explicitly records the corresponding 4W1H fields: When, What, Where, Who, and How.”
  - [corpus] Neighboring papers (e.g., AlanaVLM, COMBO) address egocentric video understanding but do not specifically investigate multi‑agent shared memory construction.
- **Break condition**: If events span longer than 10 minutes or involve subtle interactions not captured by 4W1H, the shared memory may fail to preserve necessary details.

### Mechanism 2
- **Claim**: Retrieving top‑n relevant entries from the shared memory using BM25 efficiently narrows the global context to a small set of candidate events, reducing noise from the vast multi‑agent history.
- **Mechanism**: Given a query *q*, compute BM25 scores between *q* and each shared memory entry *m*, select the *n* highest‑scoring entries as the coarse context.
- **Core assumption**: Lexical overlap between query and 4W1H summaries is sufficient to surface relevant events.
- **Evidence anchors**:
  - [section 5.2] “Given a query *q*, EgoMAS first retrieves top‑*n* system‑level memories from the shared memory *M_shared* using BM25 ranking.”
  - [section 6] “RAG Baselines… outperform other non‑retrieval open‑source models while using significantly shorter input contexts.”
  - [corpus] BM25 is a standard lexical retriever; corpus contains retrieval‑related works but not directly the multi‑agent adaptation.
- **Break condition**: For queries requiring semantic similarity beyond lexical matching (e.g., synonyms, paraphrasing), BM25 may fail to retrieve relevant memories.

### Mechanism 3
- **Claim**: From the coarse system‑level context, generating agent‑specific sub‑queries and retrieving from individual agent memories fetches fine‑grained details omitted from shared summaries, enabling precise answers.
- **Mechanism**: The retrieved system‑level memories prompt an LLM to generate a list of *(agent, sub‑query)* pairs. For each pair, retrieve top‑*k* memories from that agent’s memory using BM25 with a score threshold τ.
- **Core assumption**: The system‑level context provides sufficient cues to determine which agents are relevant and what details to ask for.
- **Evidence anchors**:
  - [section 5.2] “From the retrieved system‑level context, EgoMAS generates a set of agent‑specific retrieval requests *Q_agent* = {(a_j, q_j)}… For each (a_j, q_j), EgoMAS performs agent‑level retrieval from the agent’s memory *M_{a_j}*.”
  - [section 7] Ablation in Tab. 4 shows removing agent‑wise dynamic retrieval drops accuracy from 35.55 % to 30.04 %.
  - [corpus] Limited direct support; some multi‑agent systems explore dynamic communication but not retrieval‑based fusion.
- **Break condition**: If system‑level retrieval misses critical events, agent‑wise queries will not target the right agents; or if sub‑queries are poorly generated, they may retrieve irrelevant details.

## Architecture Onboarding
**Component map**: Video Preprocessor → Shared Memory Builder → Query Processor (System Retriever → Agent Query Generator → Agent Retriever → Response Generator) → Storage

**Critical path**:
1. Offline: Preprocess videos → per‑agent caption DB.
2. Offline: Build shared memory from aligned windows → index.
3. Online: Given question *q*.
   a. Retrieve top‑*n* shared memories (BM25).
   b. Generate *(agent, sub‑query)* list from retrieved shared memories.
   c. For each agent, retrieve top‑*k* agent captions (BM25 + threshold τ).
   d. Concatenate retrieved shared + agent contexts.
   e. Generate answer with LLM.

**Design tradeoffs**:
- Fixed 10‑minute window vs adaptive segmentation: fixed is simple but may split events.
- BM25 vs dense retrieval: BM25 is fast and training‑free but limited to lexical matching; dense vectors improve semantic recall at higher compute.
- 4W1H structure vs free‑form summaries: structured fields enable precise fielded retrieval but may lose nuance.
- Threshold τ: Balances precision/recall; requires tuning per data distribution.
- Using captions only vs adding frames: Captions are cheap; frames add visual cues but increase latency and may distract (see Suppl. H).

**Failure signatures**:
- Accuracy drop on multi‑span questions (Temporal Reasoning comparison, multi‑span SI/TC) suggests retrieval fails to connect distant events.
- Performance degrades as number of required agents increases (Fig. 8) → agent query generation or cross‑agent fusion is weak.
- High oracle gap (~42 %) indicates fundamental limits in memory construction or retrieval.
- If agent‑wise retrieval returns too few memories after threshold, τ may be too high; if too many noisy memories, τ may be too low.

**First 3 experiments**:
1. Baseline replication: Implement EgoMAS with *n*=20, *k*=5, τ=10 using Gemini‑2.5‑Flash and Qwen3VL‑8B‑Thinking to reproduce Tab. 2 results.
2. Memory structure ablation: Replace 4W1H with alternatives (summary, triplet, chunk) per Suppl. Tab. 5a to validate design choice.
3. Retriever comparison: Swap BM25 with DPR and NV‑Embed (pre‑computed embeddings) to measure accuracy‑latency trade‑off, following Suppl. Tab. 5b.

## Open Questions the Paper Calls Out

**Open Question 1**  
- **Question**: Why does Theory of Mind remain the lowest‑performing category across all models in MA‑EgoQA, and what architectural innovations are needed to improve latent mental state reasoning in multi‑agent egocentric QA?  
- **Basis in paper**: [explicit] The authors explicitly state that "Theory of Mind remains the hardest category" (Abstract, Page 3) and show it has the lowest accuracies in Table 2 and analysis in Section 7.1, attributing this to the need for "inferring latent mental states" rather than extracting observable cues.  
- **Why unresolved**: Current models, including EgoMAS, still lag significantly on ToM (~15–20% behind other categories). The paper does not isolate *why* ToM is disproportionately difficult in this multi‑agent, long‑horizon setting (e.g., is it due to insufficient cross‑agent belief tracking, lack of recursive reasoning, or poor grounding of mental states in visual data?). No ablation studies target ToM‑specific components in EgoMAS.  
- **What evidence would resolve it**: A detailed error analysis categorizing ToM failures (e.g., mis‑attribution of beliefs, failure to reconcile conflicting perspectives, inability to link non‑contiguous evidence). Controlled experiments that vary the depth of recursive reasoning required (e.g., single‑agent vs. multi‑agent ToM queries) and measure performance changes. Evaluating whether dedicated modules for belief tracking (e.g., memory graphs with agent‑specific nodes) improve results.

**Open Question 2**  
- **Question**: How does MA‑EgoQA’s reliance on a single dataset (EgoLife) impact the generalizability of evaluated models to other multi‑agent environments (e.g., outdoor, workplace settings), and what modifications to the benchmark or training data are needed to ensure robustness across contexts?  
- **Basis in paper**: [explicit] The limitations section (Supplementary C) states: "MA‑EgoQA is based only on EgoLife and does not include other scenarios in different environments… This is because EgoLife is currently the only publicly available video dataset providing long‑term, egocentric videos captured simultaneously from multiple agents."  
- **Why unresolved**: All conclusions are drawn from one household setting with six agents over seven days. It is unclear whether the observed challenges (e.g., poor multi‑agent fusion, ToM difficulty) generalize to other domains (e.g., construction sites, retail environments) with different agent roles, interactions, and environmental complexity. The benchmark’s category definitions might be too tailored to domestic Collaboration.  
- **What evidence would resolve it**: Collecting and evaluating on a new multi‑agent egocentric dataset from a distinct environment (e.g., industrial, outdoor). Analyzing performance drops/gains when models trained on EgoLife are tested on synthetic or augmented data that varies setting, agent count, or activity types. Investigating which benchmark categories are most sensitive to environmental shifts.

**Open Question 3**  
- **Question**: What retrieval paradigms beyond BM25 (e.g., sparse‑dense hybrid, event‑graph‑based) can effectively capture cross‑agent temporal dependencies for long‑horizon multi‑agent video QA while maintaining scalability, and how should query understanding be improved to generate agent‑specific retrieval requests?  
- **Basis in paper**: [inferred] EgoMAS uses BM25 for retrieval, and the authors note that "stronger retrievers lead to better performance" (Limitations, Supplementary C). Table 5b shows NV‑Embed‑v2 (a dense retriever) improves accuracy but is computationally heavy. The agent‑wise dynamic retrieval step (Sec. 5.2) generates sub‑queries via a reasoning model, but its design is not ablated or compared to alternatives (e.g., learned query expansion, reinforcement learning for agent selection).  
- **Why unresolved**: The paper does not explore whether hybrid retrieval (e.g., combining BM25 with vector search) or structured retrievers (e.g., over event graphs) better handle the multi‑agent, long‑temporal challenges. The sub‑query generation process is simplistic and may fail to decompose complex queries requiring coordinated evidence from multiple agents.  
- **What evidence would resolve it**: Systematic comparison of retrieval strategies on MA‑EgoQA, measuring not only accuracy but also recall of gold evidence windows and latency. Ablating the agent‑wise dynamic retrieval module (e.g., using fixed agent selection, rule‑based sub‑query generation, or end‑to‑end learned retrieval). Analyzing correlation between retrieval quality (e.g., mean average precision on gold events) and final QA accuracy.

**Open Question 4**  
- **Question**: Under what query characteristics (category, temporal scope, number of required agents) does incorporating raw video frames degrade performance in multi‑agent egocentric QA, and how can systems adaptively select or compress visual information to avoid distraction?  
- **Basis in paper**: [explicit] The supplementary analysis (Table S11) shows that adding video frames to EgoMAS hurts accuracy in TC and ToM categories while helping SI, TR, EI. The authors conclude: "including video frames is not always beneficial and can even distract the model when unnecessary frames are provided."  
- **Why unresolved**: The paper does not diagnose *why* frames cause degradation (e.g., noise from irrelevant time periods, redundancy across agents, or the model’s inability to effectively fuse frame features with text). No adaptive mechanism is proposed to decide when to use frames. The frame sampling strategy (uniform sampling) is fixed and likely suboptimal.  
- **What evidence would resolve it**: Per‑category error analysis comparing text‑only vs. video‑inclusive runs, correlating frame utility with visual complexity or motion in relevant time windows. Developing and testing adaptive frame selection policies (e.g., based on caption confidence, event saliency, or query guidance) and measuring impact on categories where frames currently hurt.

**Open Question 5**  
- **Question**: What are the dominant failure modes responsible for the ~42% gap between EgoMAS/oracle accuracy and current model performance (e.g., retrieval failure, incorrect evidence fusion, temporal misalignment), and how should shared memory representations evolve to better aggregate distributed evidence across agents and long durations?  
- **Basis in paper**: [explicit] Oracle accuracy is 83.80% (Gemini) vs. EgoMAS 41.41% (Table 2), a massive gap. The authors state this indicates "significant room for improvement" (Sec. 6.2) and that "current approaches are unable to effectively handle multiple egocentric streams" (Abstract). The memory in EgoMAS uses fixed 10‑minute chunks with 4W1H summaries.  
- **Why unresolved**: The paper lacks a fine‑grained breakdown of where EgoMAS fails: Does it retrieve wrong event chunks? Fail to synthesize evidence across retrieved chunks? Misunderstand temporal relationships? The shared memory structure (4W1H) is static and may not capture nuanced cross‑agent interactions or long‑range dependencies. No analysis compares different memory granularities or structures (e.g., dynamic event segmentation, graph‑based memory).  
- **What evidence would resolve it**: Human or model‑based analysis of a sample of EgoMAS errors, labeling them as retrieval errors, reasoning errors, or temporal alignment errors. Ablating memory structure (e.g., varying chunk size, adding inter‑agent links, hierarchical summarization) and measuring impact on the oracle gap. Probing whether providing gold retrieval (oracle retrieval) closes the gap, isolating the bottleneck to retrieval vs. reasoning.

## Limitations
- **Unclear preprocessing**: The exact captioning model for 10‑minute clips and the format of agent‑wise memories (raw captions vs. summaries) are not specified, which impacts memory fidelity and retrieval.
- **Proprietary backbone dependence**: Key components use Gemini/GPT‑5/Qwen3‑VL, making exact replication difficult; open‑source alternatives show a performance gap.
- **Segmentation and retrieval limitations**: Fixed 10‑minute windows can split continuous events, and BM25’s lexical matching struggles with semantic variation, leading to missed retrievals.

## Confidence
- **Benchmark design (MA‑EgoQA) and category definitions**: Medium – described in paper but dataset access is restricted.
- **Shared memory construction via 4W1H summaries**: Medium – ablations show benefit, yet alternative representations unexplored.
- **Agent‑wise dynamic retrieval mechanism**: Medium – supported by ablations, but lexical retriever limitations acknowledged.
- **Reported accuracy numbers (e.g., 41.41% with Gemini)**: Low – cannot be independently verified due to proprietary models and unknown preprocessing.
- **Theory of Mind as hardest category**: Medium – intuitive but category boundaries subjective.
