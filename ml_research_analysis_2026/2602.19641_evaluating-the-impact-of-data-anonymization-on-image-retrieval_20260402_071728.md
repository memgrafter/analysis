# Evaluating the Impact of Data Anonymization on Image Retrieval

## Quick Facts
- arXiv ID: 2602.19641
- Source URL: https://arxiv.org/abs/2602.19641
- Reference count: 36
- Primary result: Models trained on original images achieve highest retrieval similarity in anonymized settings, and mnDCG with anonymized queries best predicts downstream classification accuracy.

## Executive Summary
This paper evaluates how common image anonymization techniques (blurring, pixelation, masking) affect content-based image retrieval (CBIR) performance using DINOv2 feature extractors. The authors propose a framework that measures retrieval results after anonymization against a pseudo-ground truth derived from a model trained on original images, using mean Average Precision (mAP) and a multi-level normalized Discounted Cumulative Gain (mnDCG). Experiments on three datasets—CelebA, RVL‑CDIP, and an internal DOKIQ corpus—reveal that models trained on original, non‑anonymized data (unadapted) consistently yield retrieval results most similar to the pseudo‑ground truth, regardless of the anonymization method. Retrieval performance declines as anonymization strength increases. Notably, mnDCG computed with anonymized query images exhibits the strongest correlation with downstream classification accuracy. The authors recommend retaining the original, non‑anonymized model when processing anonymized data to preserve retrieval behavior.

## Method Summary
The study constructs an evaluation framework for anonymized CBIR. For each dataset, three anonymization variants (blurring, pixelation, masking) are applied at varying degrees. Two DINOv2 models are considered: one trained on original images (unadapted) and another fine‑tuned on anonymized images (adapted). For a given query (anonymized), retrieval is performed against a feature database built from original images using the respective model. The pseudo‑ground truth consists of the ranking produced by the unadapted model for that query. Retrieval performance is quantified by mAP (using class labels as binary relevance) and mnDCG (using the unadapted model’s scores as graded relevance). To assess practical impact, the same DINOv2 features are used to train a downstream classifier; its accuracy is then correlated with the retrieval metrics. The core comparison is between adapted and unadapted models regarding how closely their retrievals mimic the pseudo‑ground truth.

## Key Results
- Unadapted models (trained on original data) consistently produce retrieval rankings most similar to the pseudo‑ground truth across all datasets and anonymization techniques.
- Retrieval similarity to the pseudo‑ground truth decreases monotonically with stronger anonymization (e.g., higher blur radius).
- mnDCG computed on anonymized queries correlates most strongly with downstream classification accuracy among the tested metrics.
- Practical recommendation: When handling anonymized images, deploy the original (non‑anonymized) model rather than a model adapted to anonymized data to preserve retrieval behavior.

## Why This Works (Mechanism)
Anonymization disrupts pixel patterns while attempting to preserve semantic content. DINOv2’s self‑supervised pretraining yields features that are relatively robust to such corruptions because they capture higher‑level semantics invariant to low‑level distortions. The unadapted model, having been trained on pristine images, internalizes richer, more discriminative representations; its retrieval on anonymized queries therefore remains closer to the "ideal" ranking derived from original images. In contrast, an adapted model trained on anonymized data may overfit to the specific artifacts introduced (e.g., blockiness from pixelation) and lose fine‑grained discriminative cues, leading to rankings that diverge more from the unadapted reference. The mnDCG’s graded relevance, based on the unadapted model’s scores, effectively captures subtle ranking changes that binary mAP misses, hence its stronger correlation with downstream performance where nuanced feature quality matters.

## Foundational Learning
- **Content‑Based Image Retrieval (CBIR)**: The core task; requires mapping images to a feature space where semantic similarity is preserved. *Why needed*: To enable search without textual metadata. *Quick check*: Given two images, extract features (e.g., with a pretrained CNN) and compute cosine similarity; high similarity should indicate visual/functional resemblance.
- **Image Anonymization**: Techniques (blur, pixelation, masking) that alter pixel values to hide identities while ideally retaining utility. *Why needed*: Privacy preservation in shared visual data. *Quick check*: Visually inspect or compute SSIM between original and anonymized images; SSIM should be low while object categories remain recognizable.
- **DINOv2 Self‑Supervised Vision Model**: A state‑of‑the‑art backbone trained with self‑distillation; produces dense or global features. *Why needed*: Provides powerful, off‑the‑shelf representations without task‑specific labels. *Quick check*: Run inference with DINOv2 on an image and verify feature dimensionality and norm distribution.
- **Evaluation Metrics for Retrieval**: mAP measures precision across recall levels; nDCG weighs position‑dependent relevance; mnDCG extends nDCG to multiple graded levels. *Why needed*: Quantify ranking quality beyond binary matches. *Quick check*: For a small ranked list with known relevances, compute nDCG manually by comparing DCG to ideal DCG.
- **Downstream Classification Utility**: A proxy for real‑world applicability; classification accuracy indicates whether retained features are semantically meaningful. *Why needed*: To link retrieval metrics to practical performance. *Quick check*: Train a linear classifier on frozen features and evaluate accuracy; compare across feature sources.

## Architecture Onboarding
The evaluation framework comprises several loosely coupled components. Datasets (CelebA, RVL‑CDIP, DOKIQ) are ingested and split into original and anonymized copies via the Anonymization Module. Two DINOv2 models—Unadapted (original‑trained) and Adapted (anonymized‑fine‑tuned)—produce feature vectors. These features index separate retrieval galleries (both built from original images). For each anonymized query, both retrieval engines return ranked lists. The Evaluation Module computes mAP (using class labels as binary relevance) and mnDCG (using the Unadapted model’s scores as graded relevance) by comparing each model’s ranking to the pseudo‑ground truth from the Unadapted model. Additionally, features from both models feed a Downstream Classifier; its accuracy is correlated against the metrics to gauge predictive power.

Critical path: Anonymized query → (Adapted model feature extraction → Retrieval → Ranking) and (Unadapted model feature extraction → Retrieval → pseudo‑ground truth Ranking) → (Metric computation comparing Rankings to pseudo‑ground truth). Parallel: same features → Classifier → Accuracy.

Design tradeoffs: Using the Unadapted model’s ranking as pseudo‑ground truth assumes it is optimal, which may bias the evaluation against Adapted models. However, this avoids costly human judgments. mAP offers simplicity but ignores ranking nuance; mnDCG captures rank‑sensitivity, explaining its better correlation with downstream utility. The framework purposely uses identical galleries (original images) to isolate the effect of query anonymization and model adaptation.

Failure signatures: (1) If mnDCG shows weak correlation with downstream accuracy, the grading scheme may misalign with true semantic utility. (2) If Adapted models sometimes outperform Unadapted on mAP but not mnDCG, it suggests they retrieve more relevant items but rank them poorly, hinting at overfitting to artifacts. (3) Severe degradation (e.g., mAP near random) for all models under heavy anonymization indicates that the anonymization is too destructive for meaningful retrieval.

First three experiments to onboard:
1. Baseline validation: Verify that mAP and mnDCG are high when using the Unadapted model with original queries (no anonymization) on all datasets.
2. Anonymization robustness test: Run the Unadapted model on anonymized queries to quantify the raw impact of anonymization on feature quality.
3. Adaptation comparison: Fine‑tune DINOv2 on each anonymization type/degree and measure the change in mAP/mnDCG relative to the Unadapted baseline; confirm that unadapted consistently remains closer to pseudo‑ground truth.

## Limitations
- **Dataset scope**: Only three datasets are used (one internal), limiting diversity and generalizability across visual domains.
- **Model limitation**: Experiments solely with DINOv2; results may differ for other CBIR architectures (e.g., CLIP, ResNet‑based).
- **Anonymization variety**: Techniques restricted to blurring, pixelation, masking; advanced or adversarial anonymizations are unexplored.

## Confidence
- Unadapted models best preserve retrieval behavior under anonymization: Medium
- Retrieval performance degrades with increased anonymization degree: High
- mnDCG with anonymized queries correlates with downstream classification accuracy: Medium
- Recommendation to retain original, non‑anonymized models: Medium

## Next Checks
1. Cross‑architecture replication: Evaluate the framework with at least two additional CBIR model families (e.g., ResNet‑based, CLIP) across the same datasets.
2. Domain expansion: Incorporate at least three new datasets from distinct domains (e.g., medical imaging, satellite imagery, industrial inspection) to test robustness.
3. Statistical rigor enhancement: Apply bootstrap resampling or permutation tests on mAP and mnDCG, and compute correlation confidence intervals across multiple random seeds to establish statistical significance.
