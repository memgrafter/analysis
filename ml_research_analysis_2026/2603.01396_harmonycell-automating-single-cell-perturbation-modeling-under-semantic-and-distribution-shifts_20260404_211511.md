# HarmonyCell: Automating Single-Cell Perturbation Modeling under Semantic and Distribution Shifts

## Quick Facts
- **arXiv ID:** 2603.01396
- **Source URL:** https://arxiv.org/abs/2603.01396
- **Reference count:** 40
- **Primary result:** HarmonyCell achieves 95% valid execution rate on heterogeneous input datasets and matches/exceeds expert-designed baselines in out-of-distribution evaluations, attaining a DeltaPCC of 0.62 on the Norman dataset.

## Executive Summary
HarmonyCell is an automated framework for single-cell perturbation modeling that simultaneously addresses two forms of data heterogeneity: semantic schema inconsistencies across datasets and statistical distribution shifts. It employs an LLM-driven Semantic Unifier to autonomously align disparate metadata into a canonical interface, eliminating manual mapping. An adaptive Monte Carlo Tree Search (MCTS) engine then synthesizes model architectures by exploring a hierarchical action space (paradigm → backbone → refinement) to match inductive biases to data properties. Integrated with a retrieval-augmented knowledge base and a ReAct-style debugging loop, the system achieves robust end-to-end execution without dataset-specific engineering, enabling scalable virtual cell construction.

## Method Summary
HarmonyCell's pipeline begins with the Semantic Unifier, which prompts a frozen LLM using raw column descriptors and sampled values to generate a JSON mapping specification. Executing this specification projects any input `.h5ad` file into a unified schema (e.g., canonical `obs` fields like `cell_type`, `perturbation_name`). A Retrieval-Augmented Agent then embeds the task description and data statistics to retrieve relevant historical runs from a persistent knowledge base for MCTS warm-starting. The MCTS engine conducts a top-down search over a three-level hierarchical action space, selecting a modeling paradigm (generative/discriminative), a backbone architecture (e.g., cVAE, ResNet), and refinements. Each candidate architecture is executed by an Executor Agent, with failures triggering an LLM-based repair cycle. Successful pipelines are stored in the knowledge base, creating a closed-loop system that improves over time.

## Key Results
- Achieved **95% valid execution rate** on heterogeneous single-cell perturbation datasets, compared to 0% for general-purpose coding agents.
- Matched or exceeded expert-designed baselines in out-of-distribution evaluations, with a **DeltaPCC of 0.62** on the Norman dataset.
- Demonstrated robust performance under both **unseen perturbation** and **unseen cell** conditions across multiple datasets.

## Why This Works (Mechanism)
### Mechanism 1: LLM-Driven Semantic Unification
- **Claim:** An LLM autonomously resolves semantic heterogeneity by inferring a canonical JSON mapping specification from raw metadata field descriptors, enabling zero-shot adaptation to uncurated datasets without manual schema engineering.
- **Mechanism:** The Semantic Unifier agent prompts a frozen LLM with raw column names and sampled values. The LLM generates a structured mapping object that captures direct field aliasing and dynamic logic expressions (e.g., converting units). This specification is executed to project disparate datasets into a strictly unified interface (e.g., canonical `obs` fields like `cell_type`, `perturbation_name`).
- **Core assumption:** The LLM can accurately infer semantic intent and mapping logic from field names and example values, treating the task as a constrained code-generation problem rather than open-ended text generation.
- **Evidence anchors:**
  - [abstract] States: "LLM-driven Semantic Unifier autonomously maps disparate metadata into a canonical interface without manual intervention."
  - [section 4.1] Details: "prompts a frozen LLM with raw field descriptors to infer a canonical JSON mapping specification M... By executing this specification, the solver projects disparate raw datasets into a strictly unified interface."
  - [corpus] Related work (e.g., CellForge, AI Scientists) shows LLMs for code generation but not specifically for schema unification; this is a novel application. Direct evidence for its efficacy is internal to this paper.
- **Break condition:** The LLM generates syntactically invalid expressions (e.g., non-Python logic) or semantically misaligned mappings (e.g., confusing `cell_type` with `cell_line`), leading to `preprocess error` during execution (as seen in ablation studies).

### Mechanism 2: Adaptive MCTS over Hierarchical Action Space
- **Claim:** A Monte Carlo Tree Search (MCTS) engine operating over a three-level hierarchical action space (Strategy → Architecture → Refinement) autonomously synthesizes model architectures with optimal statistical inductive biases for distribution shifts, balancing exploration and validation performance.
- **Mechanism:** The search space is structured: (1) Choose modeling paradigm (Generative vs. Discriminative) based on data properties (sparsity, density). (2) Select backbone (e.g., cVAE, ResNet) within chosen paradigm. (3) Refine hyperparameters/loss. MCTS uses an optimistic UCT selection (`Q_mix`) and a multi-objective reward (`R(s) = w_p·M_val + w_e·f_time`). Meta-initialization via RAG warms-start the tree with historical priors if similarity exceeds threshold τ, otherwise starts tabula rasa.
- **Core assumption:** Decomposing the vast code space into a semantically meaningful hierarchy allows top-down reasoning about statistical alignment (e.g., "sparse data → generative") and prevents invalid/low-probability action sequences, making search tractable and bias-aware.
- **Evidence anchors:**
  - [abstract] States: "adaptive Monte Carlo Tree Search engine operates over a hierarchical action space to synthesize architectures with optimal statistical inductive biases."
  - [section 4.2] Details: "We structure the action space A into a three-level hierarchy... explicitly designed to align model capacity with data statistical properties... This hierarchical decomposition enables the agent to 'reason' about statistical heterogeneity from top-down."
  - [section 5.4/Fig 5] Ablation shows hierarchical space achieves faster convergence and superior validation metrics over simpler/non-hierarchical search.
- **Break condition:** The hierarchical constraint forces commitment to a suboptimal high-level paradigm early (e.g., Generative for sparse data) if the MCTS exploration fails to find a better discriminative branch within node expansion budget, leading to local optimal performance.

### Mechanism 3: Synergistic Integration via Knowledge Base and ReAct Loop
- **Claim:** A persistent knowledge base storing successful pipelines and a ReAct-style debugging loop creates a closed-loop system where semantic unification and architectural search reinforce each other, enabling stable end-to-end execution on heterogeneous inputs.
- **Mechanism:** Successful executions (unified datasets + validated models) are stored. For new tasks, a Retrieval-Augmented Agent fetches semantically similar historical entries to warm-start MCTS. If execution fails at any node (preprocess or model error), a "Debug" special action triggers an LLM-based repair cycle that re-examines the code and data flow before retrying. This prevents catastrophic failure from single-point errors.
- **Core assumption:** Historical successful solutions contain transferable semantic mappings and architectural biases for biologically analogous tasks, and LLM-driven debugging can resolve common execution errors (e.g., shape mismatches, CUDA issues) without human intervention.
- **Evidence anchors:**
  - [abstract] Implies integration: "dual-track orchestration enables scalable automatic virtual cell modeling."
  - [section 2/Fig 2] Describes: "Retrieval-Augmented Agent for meta-initialization... Executor Agent guided by MCTS... runtime failures trigger a ReAct-style debugging loop, successfully validated pipelines are stored in a persistent knowledge base."
  - [section 5.1/Table 2] Shows 95% valid execution rate vs. 0% for baselines, attributing success to "employing the Semantic Unifier" and stable MCTS execution.
- **Break condition:** The knowledge base contains no relevant priors (ρ ≤ τ) and the tabula rasa MCTS exploration exhausts its node expansion budget within the time limit without finding a valid architecture, returning the best but potentially suboptimal model.

## Foundational Learning
- **Concept: Hierarchical Action Space in MCTS**
  - Why needed here: The architectural search space for neural networks is combinatorially huge. A flat space leads to inefficient search and invalid sequences (e.g., tuning hyperparameters before selecting model type). The hierarchy (Paradigm → Backbone → Refinement) injects domain knowledge (biological inductive biases) to constrain search to meaningful regions.
  - Quick check question: If a dataset has sparse, high-dimensional gene expression with many zeros, which top-level paradigm (Generative/Discriminative) is likely more appropriate, and why? *(Answer: Generative, because it models the data distribution manifold rather than point-wise mapping, better handling sparsity.)*

- **Concept: LLM as a Structured Code Generator (Not Chatbot)**
  - Why needed here: The LLM must output deterministic, executable Python code and JSON specifications, not conversational text. Its prompts include strict output templates, field descriptions, and few-shot examples to constrain generation.
  - Quick check question: What are two key differences between prompting an LLM for the Semantic Unifier's JSON mapping versus asking it to "explain single-cell biology"? *(Answer: 1) Output format is strictly defined (JSON with specific keys). 2) Input includes field descriptors and sampled values for grounding, not open-ended questions.)*

- **Concept: Single-Cell Data Heterogeneity (Semantic & Statistical)**
  - Why needed here: The entire problem stems from real-world data fragmentation. Semantic heterogeneity: same biological concept (e.g., "K562 cells") stored in different columns (`cell_line` vs `donor_id`) or with different identifiers. Statistical heterogeneity: distribution shifts due to different tissues, doses, or CRISPR guides that require different model biases.
  - Quick check question: Give one example of semantic heterogeneity and one example of statistical heterogeneity in single-cell perturbation data. *(Answer: Semantic: One dataset uses `perturbation` column with values "KO_TP53", another uses `gene_knockout` with "TP53". Statistical: Same cell type but different drug doses (continuous covariate shift) or completely new gene knockouts (discrete structural shift).)*

## Architecture Onboarding
- **Component map:** Raw h5ad → Semantic Unifier → Unified Dataset → Retrieval-Augmented Agent (RAG) → MCTS Engine → Executor Agent → (Success → Knowledge Base / Failure → Debug Loop) → Best Model
- **Critical path:** Raw h5ad → Semantic Unifier → Unified Dataset → (RAG → Warm-start) → MCTS Root → Iterative Selection/Expansion → Execution → (Success? → Store in KB / Failure? → Debug loop) → Best model after time limit.
- **Design tradeoffs:**
  - *Hierarchical vs. Flat Search:* Hierarchical enforces top-down decisions, reducing invalid sequences but possibly missing cross-paradigm hybrids. Flat is more flexible but intractable and prone to meaningless actions.
  - *LLM vs. Rule-Based Unifier:* LLM is flexible for unseen schemas but can hallucinate mappings; rule-based (e.g., string matching) is deterministic but brittle to novel naming.
  - *Meta-initialization:* RAG speeds convergence on similar tasks but risks negative transfer if similarity is misjudged (τ threshold critical).
- **Failure signatures:**
  - **Preprocessing errors:** "`KeyError` in mapping" → Semantic Unifier produced incorrect `source_key`.
  - **Model errors:** "CUDA out of memory" → MCTS selected too large backbone for GPU budget.
  - **Stagnation:** MCTS reward plateaus early → exploration constant C too low, or action space too constrained.
  - **Hallucinated success:** Agent manipulates validation (e.g., using test set as train) → Need strict code sandboxing.
- **First 3 experiments:**
  1. **Unit test Semantic Unifier:** Feed 5 manually altered `h5ad` files with known schema noise (e.g., `dose [nM]` vs `conc_uM`). Verify mapping JSON correctness and successful dataset unification (no `preprocess error`).
  2. **Ablation: Hierarchical MCTS:** On Norman dataset, compare full hierarchical search vs. flat search (all actions in one pool) for 16 node expansions. Track convergence speed (best DeltaPCC vs. iterations) and final performance.
  3. **End-to-end OOD validation:** Run full pipeline on Srivatsan-Sciplex3 (unseen cell task). Measure: (a) Valid execution rate, (b) Final DeltaPCC vs. baselines (Biolord, CPA), (c) Time to best model.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Is full automation of data unification, model design, and evaluation feasible for single‑cell perturbation studies?
- **Basis in paper:** [explicit] Introduction states: “How to streamline the ‘data unification–model design–evaluation’ workflow for rapid data‑value assessment remains an open question.”
- **Why unresolved:** Existing agents fail on semantic heterogeneity or require extensive manual engineering.
- **What evidence would resolve it:** An agent that, without manual mapping, achieves high pipeline success (e.g., ≥95%) across diverse heterogeneous datasets and matches expert baselines, as reported for HarmonyCell.

### Open Question 2
- **Question:** How can the computational overhead of MCTS‑based architecture search be reduced without sacrificing performance?
- **Basis in paper:** [explicit] Limitations section notes: “The MCTS engine entails higher computational overhead than static baselines.”
- **Why unresolved:** The search process is time‑consuming, limiting practical adoption and scalability.
- **What evidence would resolve it:** A modified HarmonyCell with faster search (e.g., via learned heuristics, hierarchical pruning, or surrogate models) that maintains or improves the reported accuracy and robustness.

### Open Question 3
- **Question:** Can HarmonyCell be extended to integrate multi‑modal single‑cell data (e.g., transcriptome plus epigenome) for perturbation modeling?
- **Basis in paper:** [explicit] Limitations state: “Our framework focuses on unimodal data, leaving multi‑modal integration … as key directions for future research.”
- **Why unresolved:** The current system processes only expression matrices; no multi‑omics capabilities are demonstrated.
- **What evidence would resolve it:** A version of HarmonyCell that ingests combined data types and shows improved predictive performance or novel biological insights on integrated tasks.

## Limitations
- LLM-driven Semantic Unifier accuracy is not directly measured; reliance on frozen LLM may cause hallucinations or misinterpretations of obscure metadata.
- Hierarchical MCTS could be constrained by the predefined three-level structure, potentially missing effective hybrid architectures.
- Evaluation limited to RNA‑seq perturbation data; generalizability to other modalities (e.g., scATAC‑seq, spatial) or non‑genetic perturbations is untested.
- Computational cost of MCTS and debugging cycles not quantified, raising scalability concerns for larger action spaces or long time budgets.

## Confidence
- **Semantic Unifier automation:** Medium – supported by high overall execution rate but lacks fine‑grained mapping correctness metrics.
- **Hierarchical MCTS advantage:** High – explicit ablation (Fig. 5) shows faster convergence and better validation metrics vs. non‑hierarchical baselines.
- **End‑to‑end OOD performance:** Medium‑High – strong results on two datasets but diversity of test beds is limited.
- **Synergistic integration (knowledge base + ReAct):** Medium – high valid execution rate implies synergy, but causal attribution is not isolated.
