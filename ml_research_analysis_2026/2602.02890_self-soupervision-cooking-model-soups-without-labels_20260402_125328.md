# Self-Soupervision: Cooking Model Soups without Labels

## Quick Facts
- **arXiv ID**: 2602.02890  
- **Source URL**: https://arxiv.org/abs/2602.02890  
- **Reference count**: 31  
- **Primary result**: Self-Soups extend model soups to self-supervised learning, mixing SSL-trained models without labels to achieve +3.5% robustness on ImageNet-C, +7% on LAION-C, and 67.5% average accuracy across 21 VTAB tasks.

## Executive Summary
This paper introduces **Self-Soupervision**, a framework that adapts model soups to self-supervised learning (SSL). Instead of relying on labeled data to create diverse ingredients, it inter-trains models using various SSL algorithms and hyperparameters on unlabeled data, followed by supervised fine-tuning. Parameter averaging across these ingredients yields consistent improvements. The method also includes **Self-Seasoning**, an unsupervised approach to optimize mixture coefficients using kNN entropy. Results show significant robustness gains on corrupted benchmarks and strong transfer performance on VTAB, all without increasing inference cost.

## Method Summary
Self-Soupervision begins with a pre-trained model (the *stock*). It performs multiple **SSL inter-training** runs on unlabeled data—potentially from a target or shifted distribution—varying algorithms (e.g., MAE, MoCoV3, MMCR) and hyperparameters to produce diverse base models. Each base model is then **fine-tuned** on the labeled target task with different learning rates, yielding a set of ingredient models. Finally, the parameters are **averaged** either uniformly or via **Self-Seasoning**, which optimizes mixture coefficients by minimizing the entropy of kNN predictions on unlabeled target data, thus avoiding label use.

## Key Results
- Extends model soups to SSL, enabling mixing of ingredients with different algorithms, hyperparameters, and unlabeled data sources.
- Inter-training on corrupted test data yields robustness gains of **+3.5% on ImageNet-C** and **+7% on LAION-C** over supervised soups.
- Across 21 VTAB tasks, Self-Soups achieve **67.5% average top-1 accuracy**, surpassing continued SSL+supervised soup baselines.
- Self-Seasoning obtains competitive accuracy without any labels.

## Why This Works (Mechanism)

### Mechanism 1: Linear Mode Connectivity among SSL-Trained Models
Claim: Parameter averaging of models inter-trained with different self-supervised algorithms improves accuracy because **linear mode connectivity (LMC)** holds between them.  
Mechanism: Starting from a common stock, independent SSL inter-training followed by supervised fine-tuning produces weight landscapes connected by linear paths without accuracy dips. Diversity from SSL objectives yields complementary representations, which merging captures.  
Evidence: Figure 2 shows mixing MAE, MoCoV3, MMCR ingredients outperforms any single ingredient across 8 ImageNet test sets. The paper explicitly states that LMC holds between SSL-trained ingredients—a first.  
Break condition: LMC may fail if inter-trainings are too divergent (e.g., different architectures or objectives without a common stock), causing averaged models to degrade below individual ingredients.

### Mechanism 2: Shift-Aware Inter-Training for Robustness
Claim: Inter-training on unlabeled data from a target distribution (e.g., corrupted test data) before fine-tuning on clean labels improves robustness.  
Mechanism: SSL on shifted data encourages features invariant to that shift; subsequent supervised fine-tuning combines these robust features with task discrimination.  
Evidence: Inter-training on unlabeled corrupted data boosts robustness by +3.5% on ImageNet-C and +7% on LAION-C (abstract, Table 2).  
Break condition: If the shift is not captured by SSL inductive biases (e.g., semantic changes), inter-training may not help or could harm.

### Mechanism 3: Unsupervised Seasoning via kNN Entropy Minimization
Claim: Mixture coefficients for model soups can be learned without labels by minimizing the entropy of k-nearest neighbor predictions on unlabeled data.  
Mechanism: For a candidate mixture, compute embeddings of unlabeled target data; kNN classification yields a predictive distribution. Low entropy indicates confident, clustered representations. Optimizing mixture coefficients to minimize this entropy aligns the soup with the task structure.  
Evidence: Self-Seasoning achieves competitive accuracy on VTAB without using labels (abstract, Table 5).  
Break condition: Unlabeled data that is unrepresentative or heavily imbalanced may cause overfitting to spurious clusters, yielding poor mixtures.

  *Quick check*: What is linear mode connectivity, and why is it essential for model soups to work?

- **Self-Supervised Learning (SSL)**  
  *Why needed*: Self-Souping uses SSL to create diverse ingredients without labels; knowing differences between SSL families (e.g., reconstruction vs. contrastive) explains the benefit of mixing.  
  *Quick check*: How do MAE (reconstruction) and MoCoV3 (contrastive) objectives differ, and why might mixing them help?

- **Transfer Learning and Domain Shift**  
  *Why needed*: Self-Souping targets improved transfer to new tasks and robustness to distribution shifts; understanding covariate shift motivates inter-training on target/unlabeled shifted data.  
  *Quick check*: Why might inter-training on unlabeled data from a target domain improve transfer performance compared to only fine-tuning on the source?

## Architecture Onboarding

Component map:  
Pre-trained stock → Inter-training engine (SSL on unlabeled data) → Fine-tuning engine (supervised fine-tuning) → Mixing module (uniform averaging or Self-Seasoning optimizer)

Critical path:  
1. Load pre-trained stock.  
2. For each inter‑training config (SSL algorithm, hyperparameters, data): run SSL inter‑training to get base model.  
3. For each base model: run multiple supervised fine‑tunings to get ingredient set.  
4. Mix all ingredients: either uniform average or optimize coefficients via Self‑Seasoning.  
5. Deploy the soup model.

Design tradeoffs:
- **Inter‑training data choice**: Target unlabeled data improves transfer/robustness but may be unavailable; shifted data requires synthetic/real shifted datasets.
- **SSL algorithm diversity**: Mixing across different SSL families may yield larger gains but risks LMC failure.
- **Search budget**: More inter‑trainings (M) and fine‑tunings (N) increase soup quality but linearly increase compute; Self‑Seasoning adds modest optimization cost.
- **Coefficient optimization**: Uniform mixing is cheap but suboptimal; Self‑Seasoning improves accuracy without labels but needs unlabeled target data and may overfit on small sets.

Failure signatures:
- Soup performance < best ingredient: Indicates LMC failure; check if inter‑trainings are too heterogeneous or fine‑tuning schedules cause divergence.
- Self‑Seasoning yields high kNN entropy or poor task accuracy: Unlabeled data may be unrepresentative; try more samples or different k.
- Inter‑training does not converge: SSL may be unstable on small/shifted data; adjust hyperparameters (masking ratio, temperature) or increase steps.

First 3 experiments:
1. **§4.1**: Inter‑train with three SSL algorithms (MAE, MoCoV3, MMCR) on ImageNet, fine‑tune, mix. Verifies LMC across SSL families and shows gains on corruptions.
2. **§4.3**: Inter‑train on unlabeled corrupted data (ImageNet‑C, LAION‑C), fine‑tune on clean ImageNet. Demonstrates shift‑aware robustness gains (+3.5% IN‑C, +7% LAION‑C).
3. **§4.4**: For each VTAB task, inter‑train on task’s unlabeled training data, fine‑tune, mix. Shows transfer improvements across 21 tasks, with average top‑1 accuracy 67.5%.

## Open Questions the Paper Calls Out

- **Why does linear mode connectivity (LMC) hold for self‑supervised ingredients?**  
  The paper empirically shows LMC across MAE, MoCoV3, and MMCR but provides no theoretical justification. A theoretical foundation is needed to predict when LMC will occur and guide design. Evidence: analyze loss landscape geometry or prove sufficient conditions.

- **Can Self‑Seasoning use a more effective unsupervised objective than kNN entropy?**  
  Self‑Seasoning relies solely on kNN prediction entropy; no alternative unsupervised objectives are considered. This may be suboptimal. Evidence: systematic comparison of various unsupervised objectives (e.g., clustering confidence, contrastive consistency) on VTAB.

- **Does Self‑Soupervision generalize beyond Vision Transformers to other architectures and modalities?**  
  All experiments use ViT‑B on vision tasks; applicability to CNNs or other modalities (text, audio) is unknown. Evidence: replicate mixing experiments with CNN‑based models (ResNet) on vision and transformer‑based models (BERT) on language tasks.

- **Can we achieve similar robustness gains without needing unlabeled data from the target or shifted distribution?**  
  The largest gains (+7%) need unlabeled target/shifted data, which may be unavailable. Evidence: develop alternative strategies that avoid target unlabeled data (e.g., only source data, synthetic data, improved test‑time adaptation) and evaluate against the robustness improvements of Self‑Soups.

## Limitations
- LMC for SSL‑trained models is only verified on ViT‑B with three algorithms; generalizability to other architectures and SSL families remains unknown.
- Shift‑aware inter‑training assumes SSL on shifted data yields robust features; this may fail if the shift alters semantics beyond low‑level invariances.
- Self‑Seasoning’s kNN entropy minimization lacks theoretical grounding and might overfit on small or biased unlabeled sets.

## Confidence
- LMC holds across SSL ingredients: **Medium**  
- Shift‑aware robustness gains: **Medium**  
- Self‑Seasoning learns mixtures without labels: **Low**

## Next Checks
1. Test LMC across a wider range of SSL algorithms (contrastive, generative, predictive) and model scales (ResNet‑50, ViT‑L) to assess scope.
2. Stress‑test Self‑Seasoning by varying unlabeled dataset size, class balance, and k‑NN parameters to gauge sensitivity and failure modes.
3. Ablate inter‑training data source: compare source‑only, target‑only, and mixed inter‑training across multiple distribution shifts (e.g., ImageNet‑C, ImageNet‑R, sketches) to isolate the benefit of target‑specific SSL.
