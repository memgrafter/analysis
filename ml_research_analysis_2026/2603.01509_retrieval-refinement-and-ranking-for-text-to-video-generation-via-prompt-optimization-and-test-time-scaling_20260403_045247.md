# Retrieval, Refinement, and Ranking for Text-to-Video Generation via Prompt Optimization and Test-Time Scaling

## Quick Facts
*   **arXiv ID:** 2603.01509
*   **Source URL:** https://arxiv.org/abs/2603.01509
*   **Reference count:** 40
*   **Primary result:** A training-free, inference-time prompt optimization framework (3R) that achieves state-of-the-art total score (245) on EvalCrafter, surpassing prior methods like LaVie and IPO (both 234).

## Executive Summary
The 3R framework addresses the high sensitivity of text-to-video models to prompt quality by operating entirely at test-time. It uses a retrieval-augmented generation (RAG) process to extract relevant descriptive modifiers from a pre-built database, an LLM to iteratively refine the user's prompt with these modifiers, and a vision-language model to rank multiple generated video candidates before applying temporal interpolation. This approach improves video fidelity, motion, and alignment without any fine-tuning of the base generator, though it increases inference latency.

## Method Summary
The pipeline consists of five steps. First, it retrieves relevant scene and attribute modifiers by encoding the user prompt and finding similar entries in a pre-curated relational database (D) using a sentence transformer. Second, an LLM merges these modifiers with the original prompt through iterative refinement and generates N candidate prompts. Third, a base text-to-video model (e.g., LaVie) generates N videos from these prompts. Fourth, a vision-language reward model (VisionReward) scores each video across 29 weighted quality questions to select the best candidate. Finally, a frame interpolation network enhances the selected video's temporal smoothness.

## Key Results
*   3R achieves a new state-of-the-art total score of 245 on the EvalCrafter benchmark, exceeding prior SOTA methods (234).
*   It obtains top or second-best results in the key sub-metrics of motion quality, text-video alignment, and temporal consistency.
*   Ablation studies confirm that each component (retrieval, multi-candidate generation, ranking, interpolation) contributes positively to the final performance.

## Why This Works (Mechanism)
The paper does not provide a dedicated "Why This Works" analysis. The mechanism is inferred from the method: the framework improves robustness by decoupling prompt engineering from generation. RAG injects domain-specific descriptive knowledge (modifiers) that a simple user prompt lacks. Generating multiple video candidates allows selection based on an automated, multi-dimensional quality assessment (VLM ranking) rather than a single stochastic output. Temporal interpolation then separately addresses frame-rate smoothness. This modular, test-time scaling approach circumvents the need for expensive model retraining.

## Foundational Learning
*   **Concept:** RAG for Modifier Injection
    *   **Why needed:** User prompts for video are often sparse. RAG provides a mechanism to retrieve and incorporate a rich set of pre-defined, descriptive attributes (e.g., camera motion, lighting, style) from a curated knowledge base.
    *   **Quick check:** Can the system retrieve modifiers for a simple prompt like "a dog running" that add details about environment, shot type, or dynamics without changing core semantics?
*   **Concept:** Test-Time Scaling / Compute-Optimization Trade-off
    *   **Why needed:** To improve generation quality without altering the fixed base model, the system must invest more computation (multiple forward passes) during inference.
    *   **Quick check:** Does performance consistently improve when increasing the number of candidate prompts (N) from 1 to 4, and what is the marginal cost per candidate?
*   **Concept:** Vision-Language Models as Zero-Shot Video Critics
    *   **Why needed:** Automated, dense evaluation of generated videos across multiple quality dimensions (alignment, consistency, aesthetics) is needed to rank candidates without human intervention.
    *   **Quick check:** Does the VLM's scoring correlate with human judgment on the EvalCrafter dimensions, and are its critiques qualitatively sensible?
*   **Concept:** Post-Hoc Temporal Interpolation
    *   **Why needed:** Base T2V models often generate few frames with choppy motion. A dedicated interpolation model can increase frame count and smooth transitions after the primary content is generated.
    *   **Quick check:** Does the interpolated video maintain the original content and semantics while significantly improving smoothness?
*   **Concept:** Iterative LLM Refinement with Constraints
    *   **Why needed:** Simply concatenating retrieved modifiers can create incoherent prompts. An LLM must merge them while preserving user intent, characters, and key attributes.
    *   **Quick check:** Do the refined prompts remain true to the original request while being more descriptive, or do they suffer from semantic drift?

## Architecture Onboarding
**Component Map:** User Prompt (I) -> Sentence Encoder (ϕ) -> Modifier Retrieval from Database (D) -> LLM Refinement (M_LLM, R_LLM) -> N Refined Prompts -> Base Video Generator (G) -> N Videos -> VLM Ranker (f_vqa) -> Best Video -> Frame Interpolator (E) -> Final Video

**Critical Path:** The sequence is strictly linear from retrieval to interpolation. The key branching point is the generation and ranking of N parallel video candidates.

**Design Tradeoffs:**
*   **Quality vs. Latency:** Using N>1 candidates and interpolation greatly increases total inference time (e.g., ~5s per video generation on H200).
*   **Generality vs. Specificity:** The relational modifier database (D) must be broad enough to cover diverse prompts but curated to avoid irrelevant suggestions.
*   **Automation vs. Over-Correction:** Fully automated VLM ranking avoids human bias but can over-penalize certain flaws or drift from the intended meaning.

**Failure Signatures:**
*   VLM ranking output shows semantic drift or criticizes correct elements, lowering alignment score.
*   Retrieved modifier list contains obvious irrelevant items (e.g., "eating hay" for "tranquil barn"), indicating poor similarity threshold (τ) or database noise.
*   Final video exhibits incoherent scenes or broken objects despite high ranking score, suggesting the VLM fails to capture critical defects.

**First 3 Experiments:**
1.  Reproduce the full pipeline with default parameters (N=4, τ=0.5) on a small, diverse prompt set from EvalCrafter to verify end-to-end score.
2.  Ablate the VLM ranking component: manually select the best video from the N candidates and compare its score to the VLM-selected one to quantify ranking accuracy.
3.  Analyze retrieval failure: For a set of prompts, manually inspect the top-k retrieved modifiers. Vary τ and measure impact on downstream total score to find a robust threshold.

## Open Questions the Paper Calls Out
### Open Question 1
*   **Question:** How can vision-language model (VLM) critiques be made more reliable to avoid over-correction and semantic drift during prompt refinement?
*   **Basis in paper:** The authors state that "contemporary vision-language models (VLMs) often provide over-corrective or semantically drifted critiques" and that using a VLM for critique "degrades alignment due to over-correction," as shown in ablation studies and Appendix C.3 examples.
*   **Why unresolved:** The paper identifies the problem but does not analyze its root causes (e.g., VLM training biases, critique prompt design) or propose solutions beyond noting it as future work.
*   **What evidence would resolve it:** Systematic analysis of VLM failure cases, followed by either new critique architectures (e.g., calibrated reward models) or improved prompting strategies that maintain alignment while correcting flaws.

### Open Question 2
*   **Question:** What efficient sampling or architectural modifications can reduce the high inference latency of 3R without sacrificing its performance gains?
*   **Basis in paper:** The conclusion explicitly notes that "the 3R pipeline introduces increased inference latency due to multiple-candidate sampling and dense temporal interpolation" and calls for "more efficient sampling strategies."
*   **Why unresolved:** The paper demonstrates gains but does not explore trade-offs between latency and quality, leaving the design space for optimization unexplored.
*   **What evidence would resolve it:** Empirical studies measuring performance-latency Pareto frontiers for each component (e.g., reducing candidate count, lightweight interpolation networks, or early-exit criteria).

### Open Question 3
*   **Question:** Under what conditions does the RAG-based modifier extraction fail to provide relevant enhancements, and how can retrieval be made more robust to noisy or irrelevant modifiers?
*   **Basis in paper:** The method relies on cosine similarity thresholds (τ=0.5) to filter modifiers, but Table 3 shows RAPO includes irrelevant modifiers (e.g., "eating hay" for "tranquil tableau of barn"), and the paper claims 3R's iterative merging filters these. However, the conditions causing retrieval to include irrelevant items (e.g., ambiguous user prompts, database bias) are not analyzed.
*   **Why unresolved:** The paper assumes the relation database and threshold are sufficient but does not evaluate failure modes or sensitivity to τ or database quality.
*   **What evidence would resolve it:** Error analysis on a diverse prompt set, measuring retrieval relevance vs. prompt ambiguity, and testing adaptive thresholds or reranking methods.

### Open Question 4
*   **Question:** Is the fixed number of refined prompt candidates (N=4) optimal across different prompt complexities, or should it be dynamically adjusted?
*   **Basis in paper:** The pipeline uses a fixed N=4 for prompt refinement and video generation, and Table 4 ablations compare "One Prompt" vs. "N Prompts + Video Selection." The gains from multiple candidates are shown, but the paper does not investigate whether N=4 is near-optimal or if more/ fewer candidates could yield better trade-offs.
*   **Why unresolved:** The choice of N appears arbitrary, and there is no analysis of marginal returns or cost-per-candidate, leaving open whether dynamic N (e.g., based on prompt length or initial quality) could improve efficiency or results.
*   **What evidence would resolve it:** Experiments varying N across a range (e.g., 1–10) and measuring total score vs. compute cost, potentially identifying a complexity-dependent heuristic.

## Limitations
*   **Reproducibility hurdles:** The exact structure of the relation modifier database (D from RAPO) and the full weight vector for the VisionReward VQA model are not disclosed, hindering precise replication.
*   **Inference cost:** The method incurs significant latency from generating multiple video candidates and applying temporal interpolation, making it unsuitable for real-time applications.
*   **VLM critique unreliability:** The identified failure of VLM-based ranking to sometimes degrade text-video alignment due to over-correction remains an unresolved practical limitation.

## Confidence
*   **Claim:** 3R achieves SOTA total score (245) on EvalCrafter.
    *   **Confidence:** Medium. Depends on unreproducible components (D, VQA weights) and unreported interpolation settings.
*   **Claim:** Each component (retrieval, multi-candidate, ranking, interpolation) contributes to the final gain.
    *   **Confidence:** Medium. The direction of ablation gains is supported, but exact magnitudes may vary with unknown parameters.
*   **Claim:** The method is training-free and operates at inference-time.
    *   **Confidence:** High. The pipeline explicitly requires no fine-tuning of any model.
*   **Claim:** VLM-based critique can degrade alignment.
    *   **Confidence:** High. This is directly shown in ablation studies and appendix examples.
