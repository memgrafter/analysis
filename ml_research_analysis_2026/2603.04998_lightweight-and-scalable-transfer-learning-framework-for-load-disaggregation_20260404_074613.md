# Lightweight and Scalable Transfer Learning Framework for Load Disaggregation

## Quick Facts
- **arXiv ID:** 2603.04998
- **Source URL:** https://arxiv.org/abs/2603.04998
- **Reference Count:** 29
- **Primary Result:** A lightweight transfer learning framework for NILM that reduces model size by ~90% and speeds up adaptation/inference by ~70×/~5.9× while matching state-of-the-art accuracy with only 1 day of target-domain data.

## Executive Summary
Non-Intrusive Load Monitoring (NILM) suffers from poor generalization when models trained on one set of homes are applied to others due to variations in appliance characteristics and usage patterns. Existing transfer learning approaches are often too heavy or inflexible for edge deployment. This paper introduces RefQuery, a framework that freezes a pre-trained NILM network and conditions its outputs on small, learnable appliance-specific embeddings. Adapting to a new target home requires optimizing only these low-dimensional embeddings per appliance, drastically reducing storage and computational overhead. Experiments on REDD and UK-DALE demonstrate that RefQuery achieves accuracy competitive with strong baselines like MA-TRF while cutting model size by ~90% and accelerating adaptation (70×) and inference (5.9×). The overhead per appliance is roughly 1 KB, making RefQuery suitable for real-time NILM on resource-constrained edge devices.

## Method Summary
RefQuery employs a two-stage approach. First, a base NILM model is pre-trained on a large source dataset, learning to extract features from aggregated power signals and to detect appliances. The backbone of this model is then frozen to preserve its generalized representations. Second, for each target home, a set of compact, low-dimensional embeddings (size E) is introduced for each appliance of interest. During adaptation, only these embeddings are updated via gradient descent on a small amount of target data (as little as one day). At inference, the input signal passes through the frozen backbone, and the embeddings are used to condition the output (e.g., via concatenation or FiLM-like modulation), producing appliance-level predictions. This design isolates domain-specific knowledge in the tiny embeddings, leaving the bulk of the network unchanged, thereby achieving high efficiency.

## Key Results
- Matches or exceeds state-of-the-art (e.g., MA-TRF) in MAE and F1-score on REDD and UK-DALE, even with 1-day adaptation data.
- Reduces model size by approximately 90% compared to MA-TRF.
- Accelerates adaptation by ~70× and inference by ~5.9×.
- Adds negligible per-appliance storage overhead (~1 KB), enabling incremental scaling.

## Why This Works (Mechanism)
The frozen backbone captures universal power signal features that are common across homes, such as transient patterns, harmonic content, and typical appliance signatures. The learnable embeddings act as adapters that shift the backbone’s outputs toward the specific characteristics of appliances in the target domain. Because only a small number of parameters are tuned, the model can quickly adapt with minimal data, while the bulk of the network remains unchanged and highly efficient. The conditioning mechanism ensures that the same backbone can serve multiple appliances without interference, as each appliance’s embedding modulates the features independently. This separation of generic representation and domain-specific adaptation yields excellent accuracy-efficiency trade-offs.

## Architecture Onboarding
**Component Map:**  
Aggregate Power Input -> Frozen Pre-trained Backbone -> Conditioning with Appliance Embeddings -> Per-Appliance Output Heads

**Critical Path:** The inference flow proceeds as: the raw power signal is fed into the frozen backbone to extract features; these features are then modulated by the appliance-specific embeddings (e.g., via element-wise multiplication or concatenation); finally, each appliance’s output head produces its activation and power decomposition.

**Design Tradeoffs:**  
- *Frozen backbone vs. adaptability:* Freezing yields efficiency but may limit adaptation to large domain shifts; some fine-tuning of deeper layers could be considered if compute permits.  
- *Embedding size vs. expressivity:* Smaller embeddings reduce overhead but may not capture all appliance variations; E is a tunable hyperparameter.  
- *Per-appliance heads:* Adding one head per appliance increases memory linearly; however, the heads are small and shared across homes via embeddings.

**Failure Signatures:**  
- Poor F1-score on appliances with low power consumption or intermittent usage indicates insufficient embedding capacity.  
- High MAE on certain homes suggests the backbone features are not aligned with the target domain (large domain shift).  
- Memory overflow or high latency on edge devices points to oversized embeddings or unoptimized conditioning.

## Limitations
- Generalization beyond the REDD and UK-DALE datasets remains unverified.
- Robustness to non-representative adaptation days (e.g., holidays, empty homes) is unknown.
- The frozen backbone assumption may hinder adaptation under large domain shifts.
- Pre‑training details (datasets, hyperparameters, model architecture) were not fully disclosed, hindering exact reproduction.

## Confidence
