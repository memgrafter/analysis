# Interactive LLM-assisted Curriculum Learning for Multi-Task Evolutionary Policy Search

## Quick Facts
- **arXiv ID:** 2602.10891
- **Source URL:** https://arxiv.org/abs/2602.10891
- **Reference count:** 40
- **Primary result:** Interactive LLM-assisted curriculum learning with multimodal feedback (numeric + plots + behavior visualizations) achieves performance statistically equivalent to expert-designed curricula and significantly outperforms static LLM-generated and random baselines in a 2D robot navigation task.

## Executive Summary
The paper tackles multi-task policy search where policies must generalize across diverse tasks, a problem where manual curriculum design is labor-intensive. It introduces an interactive LLM-assisted framework for online curriculum generation, where an LLM creates training arenas based on real-time feedback from evolutionary optimization (MAP-elites with genetic programming). The authors compare three feedback modalities: numeric performance metrics, numeric plus convergence plots, and numeric plus plots plus behavior visualizations. In a 2D robot navigation case study with eight-stage curricula, interactive generation significantly outperforms static LLM-generated and random baselines. Multimodal feedback (N+P and N+P+B) achieves performance statistically equivalent to expert-designed curricula. Moreover, progressive case administration beats batch training for richer feedback modalities, confirming that the LLM generates genuine learning progressions rather than arbitrary task sets.

## Method Summary
The method employs an iterative loop: an evolutionary optimizer (MAP-elites with genetic programming) evolves symbolic policies on a set of 2D navigation arenas. After each optimization stage, the best policy’s performance metrics (quality per arena) are compiled; optionally, convergence plots (quality vs. evaluations) and trajectory visualizations (paths taken) are generated. These data, formatted into a prompt, are sent to Claude Sonnet 4.5, which responds with a new arena in a constrained JSON format (grid string, plus metadata). The new arena is validated (size, unique start/target, reachability) and added to the accumulated case set. This process repeats for eight stages, with each stage using all previously generated arenas. The final policy is evaluated on a hidden test set of six arenas. Baselines include expert-designed, static LLM-generated (one-shot eight arenas), and random curricula; batch training (all cases at once) is also compared to progressive accumulation.

## Key Results
- Multimodal feedback (N+P and N+P+B) yields test performance statistically equivalent to expert-designed curricula (p > 0.05).
- Both N+P and N+P+B significantly outperform numeric-only (N), static LLM, and random baselines (p < 0.05).
- Progressive case accumulation significantly outperforms batch training for N+P and N+P+B modalities, but not for N-only, demonstrating the curriculum effect.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Interactive feedback enables the LLM to adapt curriculum difficulty to the optimizer’s learning progress.
- **Mechanism:** After each optimization stage, the optimizer sends performance metrics (and optionally plots/visualizations) to the LLM, which interprets this feedback to generate the next arena, adjusting complexity based on observed convergence and behavior.
- **Core assumption:** The LLM can correctly interpret the feedback and correlate it with appropriate arena characteristics (e.g., obstacle density, layout).
- **Evidence anchors:**
  - [abstract] "interactive LLM-assisted framework for online curriculum generation, where the LLM adaptively designs training cases based on real-time feedback from the evolutionary optimization process."
  - [section 2] The pipeline description and Figure 1 show the iterative exchange: optimizer runs on accumulated cases, sends feedback prompt, LLM responds with new case JSON.
  - [corpus] Neighbor papers like "Autonomous Curriculum Design via Relative Entropy Based Task Modifications" (arxiv:2502.21166) and "FATE: Closed-Loop Feasibility-Aware Task Generation..." (arxiv:2603.01505) explore closed-loop curriculum generation, but none combine LLM with evolutionary optimization feedback. Corpus evidence is indirect.
- **Break condition:** If the LLM consistently ignores feedback (e.g., generates harder arenas after poor performance) or produces arenas that do not correlate with performance trends, the adaptation fails and curriculum quality degrades.

### Mechanism 2
- **Claim:** Multimodal feedback (progression plots and behavior visualizations) significantly improves the LLM’s ability to generate effective curricula compared to numeric-only feedback.
- **Mechanism:** Visual representations of optimization convergence (quality over evaluations) and policy trajectories (spatial paths) provide the LLM with actionable insights about learning dynamics and behavioral bottlenecks, enabling more precise difficulty calibration.
- **Core assumption:** The LLM can accurately interpret visual data (PNG/SVG images) and extract meaningful patterns such as convergence speed, stagnation, or navigation inefficiencies.
- **Evidence anchors:**
  - [abstract] "multimodal feedback incorporating both progression plots and behavior visualizations yielding performance competitive with expert-designed curricula."
  - [section 2.1] Defines three feedback modalities: N (numeric), N+P (adds convergence plot), N+P+B (adds behavior visualization).
  - [section 4.2] Results: N+P and N+P+B outperform N (p<0.05), with no significant difference between N+P and N+P+B. Figure 4 shows test performance distributions.
  - [corpus] "Multimodal LLM-assisted Evolutionary Search for Programmatic Control Policies" (arxiv:2508.05433) uses multimodal LLM assistance but for policy search, not curriculum design. Direct evidence for curriculum learning is weak.
- **Break condition:** If adding visualizations does not improve performance over numeric-only, or if the LLM misinterprets visual cues (e.g., misreading plot axes or trajectory patterns), the multimodal advantage disappears.

### Mechanism 3
- **Claim:** Progressive case accumulation (curriculum learning) is essential for generalization, as batch training of all cases at once underperforms for richer feedback modalities.
- **Mechanism:** Gradually introducing new arenas allows the optimizer to build upon previously learned policies without catastrophic forgetting; the LLM designs a sequence that scaffolds learning, with each new case targeting emerging capabilities.
- **Core assumption:** The optimizer’s population retains knowledge from previous stages when seeded from the final population (as done in the paper), and the accumulated case set provides a diverse yet gradually challenging training distribution.
- **Evidence anchors:**
  - [abstract] "progressive case administration beats batch training for richer feedback modalities, confirming the LLM generates genuine learning progressions rather than arbitrary task sets."
  - [section 4.3] Direct comparison: progressive vs. batch administration for N, N+P, N+P+B. Figure 6 shows progressive significantly outperforms batch for N+P and N+P+B (p<0.05), but not for N.
  - [corpus] "Evolutionary Curriculum Training for DRL-Based Navigation Systems" (arxiv:2306.08870) demonstrates progressive curriculum benefits in navigation, but without LLM-generated tasks. Indirect support.
- **Break condition:** If progressive administration does not outperform batch, or if the optimizer suffers from catastrophic forgetting despite seeding (e.g., performance on early cases degrades sharply when new cases are added), the curriculum effect is lost.

## Architecture Onboarding
### Component map
Optimizer -> Feedback Generator -> LLM Interface -> Case Accumulator -> Optimizer (next stage)

### Critical path
1. Initialize: Send contextualization prompt to LLM; receive initial arena `c0`; set `C = {c0}`.
2. For each stage `i = 1 to n`:
   a. Optimize: Run MAP-elites on `C` for fixed evaluations (e.g., 10,000). Obtain best policy `s*` and final archive.
   b. Collect feedback: For each case in `C`, compute quality of `s*`. Optionally generate convergence plot (quality vs. evaluations for all cases) and/or trajectory plots (spatial paths of `s*` on each case).
   c. Query LLM: Send feedback prompt with modality-specific data (numeric metrics, plots as images) to LLM.
   d. Receive new case: Parse LLM’s JSON response to get new arena `ci`. Validate grid constraints (size, characters, reachability).
   e. Accumulate: `C ← C ∪ {ci}`.
3. Terminate: After `n` stages, return best policy from final archive (e.g., min `f(s; C_test)` on hidden test set).

### Design tradeoffs
- **Accumulation vs. reset:** Accumulating cases prevents catastrophic forgetting but increases computational cost per stage. The paper mitigates this by seeding the next population from the previous archive (25% elites + 25% mutated elites + 50% random).
- **Feedback richness:** Adding plots (N+P) and visualizations (N+P+B) improves curriculum quality but introduces prompt complexity and image-generation overhead. The paper found N+P and N+P+B statistically equivalent, suggesting plots suffice.
- **Progressive vs. batch:** Progressive administration leverages the LLM’s sequencing ability but requires more LLM calls. Batch training is cheaper but underperforms for N+P/B, indicating that the LLM’s generated sequences are true curricula, not just sets.

### Failure signatures
- **Invalid arena generation:** LLM outputs grids violating constraints (multiple `s`/`t`, unreachable, wrong row length). The system includes an internal flood-fill check but repeated failures stall progress.
- **No learning progress:** Test performance does not improve across stages (flat or degrading curves), suggesting the curriculum is not scaffolding learning.
- **Feedback ignored:** LLM generates arenas that contradict feedback (e.g., increases difficulty after poor performance, or repeats similar layouts despite calls for variety).
- **Poor generalization:** Final policy performs well on training arenas but fails on hidden test arenas, indicating overfitting or ineffective curriculum.

### First 3 experiments
1. **Replicate feedback modality comparison:** Run N, N+P, N+P+B with progressive administration to confirm that multimodal feedback significantly improves test performance over numeric-only.
2. **Progressive vs. batch test:** For each modality, compare progressive accumulation against batch administration (all cases from start) with equal total evaluations to validate the curriculum effect.
3. **Expert baseline comparison:** Run the expert-designed curriculum and interactive LLM (best modality) to verify that performance is statistically equivalent (p>0.05) as claimed.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question:** Does the pipeline enable learning, with policies improving across curriculum stages and generalizing to unseen cases? How do LLM-generated curricula compare to expert-designed, random, and static baselines? Which feedback modality is the most effective among the three investigated conditions?
- **Basis in paper:** [explicit] RQ1 is directly stated in Section 4.1.
- **Why unresolved:** The paper answers RQ1 solely based on a single 2D navigation case study; it remains unknown whether these results generalize to other domains, optimizers, or policy representations.
- **What evidence would resolve it:** Conducting experiments across a diverse set of embodied AI tasks (e.g., 3D navigation, robotic manipulation) and with various evolutionary algorithms would test the robustness and generality of the findings.

### Open Question 2
- **Question:** Are LLM-generated curricula actual curricula? Do their cases work equally well if administrated in a single batch instead of progressively?
- **Basis in paper:** [explicit] RQ2 is explicitly posed in Section 4.1.
- **Why unresolved:** While the paper shows progressive administration outperforms batch training for richer feedback, the exact mechanism (e.g., gradual complexity, avoidance of catastrophic forgetting) is not fully elucidated.
- **What evidence would resolve it:** Ablation studies that systematically vary case ordering, number of stages, and accumulation policies, combined with measurements of knowledge retention, could uncover the factors behind the progressive advantage.

### Open Question 3
- **Question:** Does the LLM really “understand” the feedback? Does it exploit it when creating new cases?
- **Basis in paper:** [explicit] RQ3 is explicitly listed in Section 4.1.
- **Why unresolved:** The current assessment relies on qualitative analysis of LLM responses; there is no quantitative proof that the LLM causally uses the provided feedback rather than following superficial patterns.
- **What evidence would resolve it:** Controlled experiments where feedback is deliberately altered (e.g., misleading convergence plots or trajectories) to observe whether the LLM adjusts the generated curricula accordingly would demonstrate its genuine use of feedback.

### Open Question 4
- **Question:** How does the interactive LLM-assisted curriculum learning approach scale to more complex robotic tasks (e.g., 3D environments, manipulation) and does it maintain performance comparable to expert-designed curricula?
- **Basis in paper:** [inferred] The conclusion identifies scaling to complex robotic tasks as a direction for future work, implying that the present evaluation is confined to a simple 2D navigation scenario.
- **Why unresolved:** The 2D navigation task involves a low-dimensional, deterministic setting. Realistic robotics often require high-dimensional sensors, partial observability, and continuous control—it is unclear whether the method remains effective in such settings.
- **What evidence would resolve it:** Adapting the framework to standard robotic benchmarks (e.g., Meta-World, simulated manipulation) and comparing LLM-generated curricula against expert-designed ones would reveal its broader applicability and potential limitations.

## Limitations
- Exact arena layouts and simulation parameters (e.g., wheel radius, ωmax) are not fully specified, forcing assumptions that could alter robot dynamics.
- LLM prompting details (temperature, extended thinking token budget) are omitted, risking nondeterminism and reproducibility problems.
- All claims derive from a single 2D navigation domain; generalizability to other tasks or policy representations remains untested.

## Confidence
- **Adaptive curriculum via interactive feedback:** Medium
- **Multimodal feedback improves curriculum quality:** High
- **Progressive accumulation beats batch training:** High
