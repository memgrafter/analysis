# DeepPlanning: Benchmarking Long-Horizon Agentic Planning with Verifiable Constraints

## Quick Facts
- arXiv ID: 2601.18137
- Source URL: https://arxiv.org/abs/2601.18137
- Reference count: 40
- Key outcome: Frontier agentic LLMs struggle with long-horizon planning; best reasoning model attains only 35.0% case accuracy on travel and 51.7% on shopping tasks

## Executive Summary
DeepPlanning introduces a benchmark for evaluating agentic planning systems on complex, multi-day travel and multi-product shopping tasks. These tasks require agents to actively gather information via tool APIs, reason under both explicit and implicit constraints, and optimize globally under budgets and time limits. Experiments reveal that even state-of-the-art reasoning models exhibit severe fragility, failing primarily in information acquisition, implicit constraint handling, and global consistency checking. The benchmark provides reproducible offline sandboxes with verifiable ground truth and automated evaluation to assess both effectiveness and efficiency of planning agents.

## Method Summary
The benchmark defines two task categories: Travel Planning (multi-day itineraries with attractions, flights, hotels, restaurants) and Shopping Planning (cart assembly with budget and coupon optimization). Each task is grounded in offline sandbox databases containing real-world data (flights, hotels, products, etc.). Agents interact via tool APIs to retrieve information and construct plans, which are then parsed and evaluated against ground truth using a rule-based system that checks for factual correctness, constraint satisfaction, and global coherence. The evaluation framework provides detailed error analysis to identify failure patterns in information gathering, local reasoning, and global optimization.

## Key Results
- Frontier reasoning models achieve only 35.0% case accuracy on travel planning and 51.7% on shopping planning
- Agents show high component-level scores but low case-level accuracy, indicating fragmented planning
- Internal reasoning and parallel tool use improve effectiveness-efficiency trade-offs
- Error analysis reveals persistent failures in information acquisition, implicit constraint handling, and global consistency checking

## Why This Works (Mechanism)

### Mechanism 1: Proactive Information Acquisition
Agents must actively retrieve dynamic, environment-specific data via tools rather than relying on parametric knowledge or assumptions; failure to do so causes cascading plan incoherence. The task design forces agents to ground plans in real-time sandbox data, and missing a single retrieval (e.g., attraction opening hours, product stock) leads to invalid local decisions that propagate globally.

### Mechanism 2: Local Constrained Reasoning
Agents must correctly apply both explicit user constraints and implicit environmental constraints at individual decision points; implicit constraints are disproportionately failure-prone. Each tool response contains constraints (e.g., seat status, opening time, stock quantity) that must be integrated into each selection. Implicit constraints require cross-referencing retrieved facts with the plan timeline.

### Mechanism 3: Global Constrained Optimization
Even with correct local decisions, agents fail to integrate them into a globally feasible, optimal plan under coupled constraints (budget, time, space), often settling for local optima. Constraints span the entire plan (e.g., total budget, no time overlaps, attraction diversity). The agent must perform combinatorial search over sequences of locally valid choices to find a set that jointly satisfies all global constraints.

## Foundational Learning

**Concept: Constraint Satisfaction Problem (CSP) Formulation**
- Why needed here: DeepPlanning tasks are inherently CSPs: variables with domains and constraints. Understanding CSP backtracking and constraint propagation explains why agents miss implicit constraints.
- Quick check question: If an agent selects a valid hotel and a valid attraction, but the travel time between them is longer than the gap in the schedule, what type of constraint failure is this?

**Concept: Information Foraging Theory**
- Why needed here: The benchmark rewards efficient information gathering. Agents must decide which tools to call, in what order, and whether to batch calls (parallel) or sequence them (sequential).
- Quick check question: Why might parallel tool calls (batching query_flight_info for multiple dates) be less effective than sequential calls for a tightly coupled itinerary?

**Concept: Combinatorial Optimization & knapsack-like problems**
- Why needed here: Shopping Planning is a multi-dimensional knapsack: items have costs, attributes, and coupons modify effective costs. The "optimal" cart requires exploring combinations, not greedy selection.
- Quick check question: Given two carts: Cart A has items summing to 4800¥ before a 300¥ coupon; Cart B sums to 4650¥ before a 150¥ coupon. Which is cheaper post-coupon? Why might an agent choose the wrong one?

## Architecture Onboarding

**Component map:**
Sandbox Databases -> Tool APIs -> Agent Loop -> Plan Parser -> Rule-based Evaluator

**Critical path:**
User Query → Agent Thought/Tool Calls → Tool Observations (data from DB) → ... → Final Plan Text → Parser → Structured Plan → Evaluator (Commonsense + Personalized + Case Accuracy)
The first missing or malformed tool call that omits a required data point (e.g., query_attraction_details for a recommended attraction) breaks the chain.

**Design tradeoffs:**
- Sequential vs. Parallel tool use: Sequential allows verification after each step but increases turns/cost. Parallel reduces turns but risks invalidating earlier assumptions if later data conflicts.
- Reasoning depth (thinking): More reasoning steps improve integration (better global scores) but increase latency. The data shows reasoning models achieve higher scores at comparable or lower interaction cost, implying reasoning consolidates actions.
- Explicit vs. Implicit constraint handling: The system prompt explicitly lists format rules but cannot enumerate all implicit constraints (e.g., "don't schedule a 1-hour meal for a 5-star restaurant known for long dining experiences").

**Failure signatures:**
- Information Acquisition: Tool calls missing for a required entity type (e.g., no query_restaurant_details for a recommended meal). [Error Pattern A1]
- Local Reasoning: Plan line matches a tool response but violates a constraint within that response (e.g., meal scheduled outside opening_time). [Pattern B1/B2]
- Global Optimization: Plan has correct local elements but fails composite evaluation: budget exceeded, time overlap, or missing diversity requirement. [Pattern C]
- Fact Displacement: Agent uses correct data in reasoning but writes a different value in final plan (e.g., price ¥100 in thought, ¥150 in output). [Pattern A3]

**First 3 experiments:**
1. **Ablate Information Foraging:** Run agent with forced omission of a critical tool (e.g., no query_road_route_info). Measure drop in Case Accuracy. Hypothesis: Severe drop, confirming proactive acquisition is non-negotiable.
2. **Stress Implicit Constraints:** Generate tasks where a popular attraction is closed on the travel date (in closing_dates). Compare performance on closed vs. open attractions. Hypothesis: Significant degradation, showing agents miss environmental state.
3. **Test Global Optimization Under Complexity:** Increase shopping task "Level" (number of cross-item constraints: coupons + budget + size/color filters). Measure Case Accuracy decay. Hypothesis: Non-linear drop, confirming combinatorial bottleneck.

## Open Questions the Paper Calls Out

### Open Question 1
- Question: How can we design agent architectures or training methods that significantly improve global consistency checking and backtracking in long-horizon planning?
- Basis in paper: The paper states agents still lack robust global consistency checking and backtracking for long-horizon, tightly coupled tasks.
- Why unresolved: Current agents fail to integrate locally correct actions into globally coherent plans, as evidenced by low case accuracy despite relatively high constraint-level scores.
- What evidence would resolve it: Development of agents that achieve high case accuracy (>80%) on DeepPlanning or similar benchmarks with tight global constraints, demonstrating effective backtracking and global consistency verification.

### Open Question 2
- Question: What specific techniques can help agents better detect and reason about implicit environmental constraints that are not explicitly stated in user queries?
- Basis in paper: The error analysis identifies "Implicit Constraint" failures (86 in Travel, 21 in Shopping) and notes implicit environmental constraints are harder to detect than explicit user requirements.
- Why unresolved: Agents currently miss implicit constraints that require active environmental interaction, leading to invalid plans even when explicit requirements are satisfied.
- What evidence would resolve it: Agents showing significantly reduced implicit constraint violation rates on DeepPlanning, particularly on tasks with hidden environmental constraints.

### Open Question 3
- Question: How can agent planning systems be made more robust to error propagation across long planning horizons, where small local mistakes cascade into global failures?
- Basis in paper: From the complexity analysis: as the number of days grows, agents must retrieve and integrate substantially more information, and small local mistakes can propagate across days and ultimately render the overall itinerary infeasible.
- Why unresolved: Current agents lack mechanisms to detect and correct early errors before they invalidate entire plans, as shown by the consistent performance drop with increased complexity.
- What evidence would resolve it: Agents whose performance remains stable (or declines minimally) as planning horizon length increases, indicating effective error containment or recovery mechanisms.

### Open Question 4
- Question: Can we develop reasoning patterns or architectural improvements that achieve better effectiveness-efficiency trade-offs, reducing the need for excessive tool calls while maintaining high planning quality?
- Basis in paper: The paper highlights the importance of reliable explicit reasoning patterns and parallel tool use for achieving better effectiveness-efficiency trade-offs, and shows reasoning improves the efficiency frontier.
- Why unresolved: While reasoning improves efficiency, frontier models still require hundreds of tool calls, making deployment costly and slow; the fundamental trade-off between thorough verification and efficiency remains unresolved.
- What evidence would resolve it: Agents achieving near-peak performance with substantially fewer tool calls through improved reasoning consolidation or predictive information gathering.

### Open Question 5
- Question: How do findings on single-turn, multi-step agent planning generalize to realistic multi-turn conversational planning scenarios where user preferences evolve?
- Basis in paper: The limitations state that while the tasks focus on single-turn, multi-step agent planning, modeling multi-turn user-agent interactions remains an important direction for future work.
- Why unresolved: Real-world planning is often iterative with dynamic constraints; single-turn benchmarks don't capture how agents handle preference updates, constraint relaxations, or incremental refinements while maintaining global consistency.
- What evidence would resolve it: New multi-turn planning benchmarks and agents that demonstrate robust adaptation to evolving user requirements over conversations, maintaining high plan validity and user satisfaction without starting from scratch each turn.

## Limitations
- The offline sandbox assumption may not reflect real-world agentic planning where APIs are rate-limited, dynamic, or incomplete
- Error pattern frequencies are based on a single evaluation pass without human-in-the-loop verification of parser/evaluator correctness
- Performance comparisons across models are confounded by varying tool call budgets and reasoning depths

## Confidence
- **High Confidence**: The existence of DeepPlanning benchmark, its task categories (travel/shopping), and the basic performance ranking (reasoning models > non-reasoning) are well-supported by the text
- **Medium Confidence**: The specific failure mechanism interpretations (e.g., "agents fail to propagate closing_dates") are plausible but inferred from error patterns without direct behavioral traces shown
- **Low Confidence**: Claims about "severe fragility" and specific quantitative rankings depend on the robustness of the evaluation pipeline, which is not independently verified in the text
