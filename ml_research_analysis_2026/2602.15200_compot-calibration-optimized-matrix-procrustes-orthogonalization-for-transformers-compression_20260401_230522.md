# COMPOT: Calibration-Optimized Matrix Procrustes Orthogonalization for Transformers Compression

## Quick Facts
- arXiv ID: 2602.15200
- Source URL: https://arxiv.org/abs/2602.15200
- Reference count: 40
- Primary result: COMPOT consistently outperforms SVD-based and sparse dictionary baselines across diverse models and domains, and integrates effectively with quantization.

## Executive Summary
Post‑training compression of Transformer models is often achieved via truncated singular value decomposition (SVD). However, SVD enforces a single shared subspace across layers, which can degrade model accuracy, especially at high compression ratios. COMPOT introduces a calibration‑driven approach that factorizes weight matrices using orthogonal dictionaries, enabling a closed‑form Procrustes update and analytical sparse coding without iterative optimization. It also employs a one‑shot dynamic allocation strategy to distribute a global compression budget across layers based on their sensitivity.

Experimental results on models ranging from 0.6B to 30B parameters and across language, vision‑language, and audio tasks show that COMPOT surpasses state‑of‑the‑art baselines such as SVD‑LLM and CoSpaDi. For example, on Llama‑3‑8B with a compression ratio of 0.2, COMPOT achieves 66.0% average accuracy versus 61.8% (SVD‑LLM) and 64.5% (CoSpaDi). COMPOT also combines synergistically with 4‑bit GPTQ quantization, yielding lower perplexity than either method alone. Moreover, COMPOT’s closed‑form updates are approximately 24× faster than iterative K‑SVD approaches.

## Method Summary
COMPOT leverages a small calibration dataset to guide weight matrix factorization. Each weight matrix is decomposed into an orthogonal dictionary and a sparse code matrix. The orthogonal constraint is enforced via a closed‑form solution to the Procrustes problem, which aligns the dictionary to the original weights while preserving orthogonality. This eliminates the need for iterative optimization. The sparse codes are then obtained analytically, avoiding pursuit algorithms. To optimally allocate a global compression budget across layers, COMPOT estimates each layer’s sensitivity from the calibration data in a single pass and distributes the budget accordingly, ensuring that more critical layers retain higher fidelity.

## Key Results
- **Llama‑3‑8B**: At compression ratio 0.2, COMPOT (dynamic) records 66.0% average accuracy, beating SVD‑LLM (61.8%) and CoSpaDi (64.5%); at 0.4, it achieves 51.7% vs SVD‑LLM’s 46.7% (CoSpaDi also 51.7%).
- **Whisper Large V3 ASR**: COMPOT maintains a word error rate (WER) of 2.46 at CR 0.2, whereas SVD‑LLM degrades to 4.12.
- **Quantization synergy**: COMPOT+GPTQ (4‑bit) on Llama‑7B yields 9.62 perplexity on WikiText‑2, lower than GPTQ‑only (16.28) and SVD‑LLM V2+GPTQ (9.97). COMPOT’s closed‑form updates are ~24× faster than iterative K‑SVD.

## Why This Works (Mechanism)
COMPOT’s effectiveness arises from orthogonal dictionary factorization, which prevents the subspace collapse inherent in truncated SVD. Each layer retains its own independent subspace, preserving representational diversity. The calibration data informs a Procrustes alignment that is solved in closed form, guaranteeing orthogonality while minimizing reconstruction error. Analytical sparse coding then provides fast, deterministic encodings. Finally, dynamic budget allocation directs compression resources toward layers that are most sensitive to distortion, maximizing accuracy under a global constraint.

## Architecture Onboarding
**Component map (plain text)**  
Calibration Dataset → Sensitivity Analysis → Dynamic Budget Allocation → [Per‑Layer Processing: (Calibration Subset → Orthogonal Dictionary Learning → Closed‑form Procrustes Alignment → Analytical Sparse Coding → Weight Reconstruction)] → Compressed Model

**Critical path**  
The overall workflow is: (1) collect calibration data; (2) estimate per‑layer sensitivity; (3) allocate compression budget; (4) for each layer, compute orthogonal dictionary, align via Procrustes, obtain sparse codes, and reconstruct; (5) assemble final model. The closed‑form nature of steps (4) ensures speed, while the one‑shot allocation avoids iterative retraining.

**Design tradeoffs**  
- *Orthogonality vs. flexibility*: Enforcing orthogonality simplifies computation but may restrict expressiveness compared to unconstrained factorizations.  
- *Calibration dependence*: COMPOT requires representative calibration data; poor choice can degrade accuracy.  
- *Dynamic allocation complexity*: Adds overhead in sensitivity estimation but yields better accuracy than uniform budget splitting.

**Failure signatures**  
- Accuracy drops significantly when calibration data is out‑of‑distribution, indicating misaligned dictionaries.  
- High compression on layers with high sensitivity leads to disproportionate performance loss; monitoring reconstruction error per layer can reveal this.  
- If the orthogonal constraint is too strict, the residual error after reconstruction may exceed tolerances, causing output degradation.
