# Towards Improved Sentence Representations using Token Graphs

**Quick Facts**
- **arXiv ID:** 2603.03389
- **Source URL:** https://arxiv.org/abs/2603.03389
- **Reference count:** 40
- **Primary result:** GLOT achieves >97% accuracy on a stress test with 90% random distractor tokens while baselines collapse, with 20× fewer parameters and >100× faster training than LoRA.

**Executive Summary**
GLOT proposes a lightweight, token-graph-based pooling module that operates on frozen large language model (LLM) outputs to construct robust sentence representations. It converts token hidden states into a sparse similarity graph, refines tokens via a graph neural network (TOKEN-GNN), and aggregates with a learnable readout. This approach preserves relational structure discarded by standard pooling (mean/max), making representations resistant to signal dilution from distractor tokens. Evaluations on GLUE and MTEB show competitive performance with significantly reduced trainable parameters and training time, especially under extreme distractor noise.

**Method Summary**
Given frozen LLM token embeddings for a sentence, GLOT first builds a latent token-similarity graph: pairwise cosine similarities are computed and edges are created where similarity exceeds a threshold τ, yielding a sparse, batchable graph. A lightweight GNN (TOKEN-GNN) then performs message passing across this graph for K layers to refine token representations by aggregating neighbor information. Finally, a learnable readout MLP scores each refined token, applies softmax to obtain importance weights, and computes a weighted sum to produce the final sentence embedding. Only the GNN and readout are trained; the LLM backbone remains frozen. The method is task-agnostic and can be applied to both encoder and decoder LLMs.

**Key Results**
- On a synthetic stress test with up to 90% random distractor tokens, GLOT maintains >97% accuracy while mean/max pooling and AdaPool collapse to random chance.
- Across GLUE and MTEB benchmarks, GLOT matches or exceeds all pooling baselines while using ~20× fewer trainable parameters and >100× less training time than parameter-efficient fine-tuning methods like LoRA.
- Ablations show optimal performance with a sparse graph (τ ≈ 0.4–0.6) and 2–4 GNN layers; the learnable readout contributes significantly to gains over fixed pooling.

**Why This Works (Mechanism)**
The core mechanism is relational learning before compression. First, constructing a latent token-similarity graph from frozen LLM embeddings preserves pairwise dependencies (e.g., negation, coreference) that standard pooling discards. Sparsification via threshold τ captures the strongest semantic connections while pruning noise. Second, message passing in TOKEN-GNN allows tokens to exchange contextual information iteratively, building richer multi-token representations that incorporate higher-order dependencies. Third, the learnable readout aggregates refined tokens in a task-sensitive manner, weighting salient tokens even without fine-tuning the backbone. Together, these steps mitigate signal dilution because distractor tokens form weak or noisy edges, limiting their influence during message passing and readout.

**Foundational Learning**
- **Graph Neural Networks (GNNs):** *Why needed:* GLOT uses message passing to propagate information across token edges, enabling relational reasoning beyond independent token processing. *Quick check:* How does a GNN layer differ from a standard MLP in handling a set of token vectors?
- **Permutation Invariance and DeepSets:** *Why needed:* Pooling must be permutation-invariant; DeepSets theory explains why simple invariant functions (mean/max) cannot capture token interactions, motivating graph-based extensions. *Quick check:* Why can’t mean pooling capture interactions between tokens like “not good”?
- **Frozen Model Adaptation:** *Why needed:* GLOT updates only a small head while keeping the LLM backbone fixed, reducing compute and avoiding catastrophic forgetting. *Quick check:* What are the trade-offs between full fine-tuning and frozen-backbone adaptation in terms of compute and performance?

**Architecture Onboarding**
- **Component map:** Frozen LLM -> Token Hidden States -> Graph Builder (cosine threshold) -> Token Graph -> TOKEN-GNN (K layers) -> Refined Tokens -> Readout MLP -> Sentence Embedding -> Task Head
- **Critical path:** Forward pass: precomputed/cached LLM hidden states -> mask valid tokens -> compute cosine similarity matrix -> threshold at τ to generate sparse edge_index -> batch graph with PyTorch Geometric -> K GNN layers (with optional Jumping Knowledge) -> token scoring MLP -> softmax per graph -> weighted sum -> task head loss.
- **Design tradeoffs:** 
  - *Graph sparsity (τ):* Low τ yields dense, noisy graphs; high τ yields sparse graphs that may miss dependencies. Optimal τ ∈ [0.4, 0.6] on GLUE.
  - *GNN depth (K):* Deeper GNNs capture multi-hop effects but risk over-smoothing; 2–4 layers are optimal.
  - *GNN type:* GAT (default) vs. GIN/GCN – more expressive GIN can slightly outperform but GAT is robust and efficient.
- **Failure signatures:**
  - Stress test accuracy below 80% at 80% distractors indicates graph construction fails to isolate signal.
  - Performance near mean/max pooling suggests ineffective graph or message passing (e.g., τ=0 giving fully connected graph).
  - Linear probing on frozen embeddings yields much lower accuracy than full GLOT, indicating task head entanglement.
- **First 3 experiments:**
  1. **Stress test robustness:** Train GLOT on synthetic sentences with increasing random distractor ratios (20% → 90%). Expect >97% accuracy at 90% distractors; failure if baseline-style collapse occurs.
  2. **GLUE benchmark comparison:** Evaluate against mean, max, [CLS]/[EOS], and AdaPool baselines across 6 frozen backbones. GLOT should consistently rank first or second.
  3. **τ ablation:** Vary threshold {0.0, 0.2, 0.4, 0.6, 0.8} on Mistral-7B. Performance should peak near τ=0.6; extreme values degrade results.

**Open Questions the Paper Calls Out**
**Open Question 1:** Can a learnable, parameterized graph construction mechanism (e.g., via attention scores or edge prediction networks) replace the fixed cosine similarity threshold in GLOT, and would this reduce task-specific hyperparameter tuning while maintaining or improving performance?  
*Basis in paper:* [explicit] The conclusion lists "exploring learnable graph construction mechanisms" as a future direction.  
*Why unresolved:* Current threshold τ requires tuning per task; a dynamic graph might adapt to task-specific relational patterns automatically.  
*What evidence would resolve it:* Train a variant with a differentiable edge predictor on diverse tasks (GLUE, MTEB). Compare performance, hyperparameter sensitivity, and learned graph structure against the fixed-threshold version.

**Open Question 2:** Does the "relational learning before compression" paradigm transfer effectively to non-NLP modalities, such as by adapting GLOT to pool patch embeddings from Vision Transformers (ViTs) for image-level representation?  
*Basis in paper:* [explicit] The conclusion suggests applying the paradigm to "other modalities, such as pooling patch embeddings in Vision Transformers."  
*Why unresolved:* GLOT is evaluated only on NLP. ViT patch tokens are analogous to word tokens, and standard pooling discards spatial relationships.  
*What evidence would resolve it:* Implement GLOT as a drop-in head for frozen ViTs (e.g., ViT-B/16). Evaluate on image classification (ImageNet) against global average pooling and attention pooling, measuring accuracy and robustness.

**Open Question 3:** Can integrating advanced GNN techniques like graph rewiring (e.g., via edge perturbations based on attention) or virtual nodes into TOKEN-GNN enhance its ability to model long-range dependencies in long-context tasks?  
*Basis in paper:* [explicit] The conclusion mentions "dynamic rewiring strategies" and "virtual nodes" as promising to "further enhance the model’s ability to capture long-range dependencies."  
*Why unresolved:* Current token graph is static from initial cosine similarities. Rewiring could let the graph evolve during message passing; virtual nodes could act as global relays. Their impact is untested.  
*What evidence would resolve it:* Augment GLOT with rewiring (e.g., stochastic edge flipping guided by attention) and/or a learnable virtual node. Evaluate on long-document tasks (e.g., arXiv clustering) and extreme distractor stress tests, measuring performance and computational overhead.

**Open Question 4:** What architectural principles determine the optimal GNN backbone (e.g., GAT, GIN, GCN) for different frozen LLMs and downstream tasks, and can this choice be predicted from properties of the token embeddings?  
*Basis in paper:* [inferred] Table 11 shows GNN architecture significantly impacts performance (e.g., GIN > GAT for Mistral on some tasks), but the paper defaults to GAT without justification.  
*Why unresolved:* Results indicate task- and model-dependent sensitivity, but no theory explains why one GNN is better for a given LLM’s embedding space.  
*What evidence would resolve it:* Conduct a large-scale study across diverse LLMs (encoders/decoders), tasks, and GNN architectures. Extract embedding statistics (e.g., isotropy, nearest-neighbor graphs) and correlate with performance. Use meta-learning to predict optimal GNN type from embedding features.

**Open Question 5:** How robust is GLOT to realistic distractor tokens that are semantically or syntactically related to the signal phrase, as opposed to the random distractor tokens used in the stress test?  
*Basis in paper:* [inferred] The stress test uses random words, which may not reflect real-world noise where distractors are often topically related or share syntax.  
*Why unresolved:* Random noise is an extreme case; natural noise (e.g., irrelevant but coherent sentences) could create spurious edges in the token graph, potentially harming performance.  
*What evidence would resolve it:* Create synthetic datasets with controlled distractor types: (i) random words, (ii) semantically related words (same domain), (iii) syntactically similar phrases. Measure classification accuracy for GLOT and baselines. Analyze graph connectivity (edge strength distribution) to see if GLOT filters spurious relations.

**Limitations**
- Stress test generation details (signal phrase templates, distractor corpus source) are underspecified, hindering exact replication and assessment of distractor realism.
- Hyperparameters (similarity threshold τ, GNN depth K, hidden dimension) per backbone/task combination are not fully reported; default τ=0.6 may not generalize across all models and tasks.
- Evaluation restricted to GLUE (6 tasks) and a subset of MTEB (7 tasks); broader benchmarks, especially for long-document modeling, are missing.
- Graph construction assumes frozen LLM embeddings possess a meaningful latent similarity structure; isotropic embeddings or model-specific biases could lead to noisy graphs.
