# TraceNAS: Zero-shot LLM Pruning via Gradient Trace Correlation

## Quick Facts
- **arXiv ID**: 2602.02891  
- **Source URL**: https://arxiv.org/abs/2602.02891  
- **Reference count**: 40  
- **Primary result**: Zero‑shot structured pruning via gradient trace alignment finds efficient sub‑networks in ~8.5 GPU hours with strong ranking correlation (Spearman ρ=0.94) and reduces search token usage by >5× relative to training‑aware baselines.

## Executive Summary
TraceNAS introduces a zero‑shot neural architecture search method for structured pruning of large language models without any training. It computes a scale‑invariant proxy—the sparsity‑weighted Pearson correlation between gradient traces of a pruned candidate and the pretrained base—within a low‑rank subspace to preserve functional inheritance. Coupled with evolutionary joint depth‑and‑width search and in‑place masking, the approach discovers high‑performing sub‑networks in about 8.5 GPU hours, an order of magnitude faster than training‑aware baselines. Across Llama‑2‑7B, Llama‑3.1‑8B, and Qwen‑2.5‑14B, TraceNAS achieves competitive or superior accuracy (e.g., 62.81% average on Llama‑2‑7B, 70.34% on Qwen‑2.5‑14B) while using only 98 M search tokens versus >0.5 B for comparators.

## Method Summary
The method takes a pretrained LLM and a small calibration set (e.g., 65 536 tokens from FineWeb‑Edu) and searches over depth and width configurations under a parameter budget. First, it computes a one‑time “functional anchor” gradient trace for the base model using LoRA adapters in a low‑rank subspace (rank r=64). Each candidate architecture is realized in‑place via binary masks and residual bypasses for dropped layers. For a candidate, the gradient trace is computed on the same calibration set, and the proxy score Φ is the sparsity‑weighted sum of Pearson correlations between corresponding layer traces. An evolutionary algorithm (population = 30, elite = 10, 50 iterations) explores the discrete search space, using I_l‑biased initialization, crossover (contiguous depth, interpolated width) and mutation (bit‑flip, Gaussian jitter). After search, the top‑scoring architecture undergoes continued pretraining to recover performance.

## Key Results
- Zero‑shot proxy Φ shows strong ranking correlation with downstream accuracy (Spearman ρ=0.94, Kendall τ=0.82).  
- Search cost reduced by ~10× relative to training‑aware baselines (≈8.5 GPU h vs. >80 GPU h).  
- Discovered models achieve competitive or better accuracy after minimal CPT: e.g., 62.81% on Llama‑2‑7B (2.7 B params) and 70.34% on Qwen‑2.5‑14B.

## Why This Works (Mechanism)

### Gradient trace alignment preserves functional inheritance
The Pearson correlation between standardized gradient traces of the base and pruned candidate measures whether the pruned model follows the same directional updates within the loss landscape. Sparsity weighting prioritizes high‑capacity sub‑blocks. The core assumption is that pretrained models occupy flat convergence basins; preserving gradient direction ensures stable post‑pruning recovery. Evidence: [abstract] “sparsity‑weighted Pearson correlation between gradient traces… aligns the pruned model with the original loss landscape”; full definitions in section 3.4. Break condition: if proxy ranking fails to correlate with downstream accuracy or gradient noise dominates.

### Low‑rank gradient projection reduces memory while capturing manifold dynamics
By attaching LoRA adapters and computing gradients in a low‑rank subspace (rank r), the method approximates full‑rank behavior with O(d²) complexity. LLM functional knowledge is assumed to lie on a low‑dimensional manifold; principal gradient components suffice. Evidence: [abstract] “computed within a low‑rank subspace”; stability shown in section C.3 (τ > 0.77 at r=2). Break condition: at very high sparsity or specific architectures, low‑rank may miss critical directions.

### Evolutionary joint depth‑and‑width search captures heterogeneous sensitivity
Simultaneous optimization of depth (layer dropping) and width (channel pruning) via an evolutionary loop enables discovery of non‑uniform architectures that outperform uniform baselines. The global gradient proxy differentiates candidates across both axes. Evidence: 5.51% gain over uniform pruning in section 4.2. Break condition: evolutionary stagnation or insufficient proxy discrimination for depth variations.

## Foundational Learning
- **Structured vs. Unstructured Pruning**  
  Structured pruning removes entire units (e.g., channels, layers) and changes model geometry, requiring analysis of global dependencies. Why needed: TraceNAS targets structured patterns (depth/width) so local metrics like weight magnitude are insufficient. Quick check: Why do magnitude‑based pruning fail for whole‑layer removal?

- **Gradient‑Based Importance Metrics**  
  Gradients capture how perturbations propagate through the network via the chain rule, revealing inter‑layer disruptions that static weight metrics miss. Why needed: The proxy relies on gradient traces to assess functional impact of a candidate architecture. Quick check: How does backpropagating through a masked graph expose global sensitivity?

- **Intrinsic Dimensionality of LLMs**  
  LLMs operate in a compressed manifold where most functional information resides in a low‑dimensional subspace of the full parameter space. Why needed: Justifies low‑rank gradient approximation; full‑rank is computationally prohibitive for billion‑scale models. Quick check: Why would full‑rank gradient computation be infeasible for Llama‑2‑7B?

- **Scale‑Invariant Metrics**  
  Pruning alters activation scales; using Pearson correlation (standardized vectors) decouples directional alignment from magnitude. Why needed: Ensures the proxy remains meaningful when model scale changes due to pruning. Quick check: Why prefer standardization (µ, σ) over raw dot product for gradient alignment?

## Architecture Onboarding

### Component map
Calibration data → compute base gradient traces (g_base) and per‑layer importance (I_l) → evolutionary loop: candidate (d, κ) → in‑place masking → forward/backward on calibration → compute g_sub → per‑active‑layer correlation ρ(l) → Φ aggregation → elite selection/crossover/mutation.

### Critical path
1. Initialize population: generate (d, κ) tuples with I_l bias, respecting parameter budget C and minimum depth.  
2. For each candidate: apply masks (top‑κ channels per active layer by I_l), bypass dropped layers via residuals.  
3. With LoRA rank r=64, run forward/backward on calibration (N=256, context length 4096) to obtain g_sub.  
4. Compute ρ(l) = PearsonCorr(g_sub[l], g_base[l]) for each active attention/MLP sub‑block; Φ = Σ (r·ρ(l)).  
5. Penalize over‑budget candidates (−∞ score).  
6. Select top‑K elites (K=10); generate next generation via crossover (contiguous depth, interpolation width) and mutation (bit‑flip depth, Gaussian jitter width).  
7. Repeat for T=50 iterations; return highest‑scoring valid architecture.

### Design tradeoffs
- *Proxy fidelity vs. cost*: Increasing calibration tokens N, context length CL, or LoRA rank r improves stability but raises compute; empirical sweet spots (N=256, CL=4096, r=64).  
- *Search granularity*: Finer width control (per attention/MLP) captures heterogeneity but expands search space; coarser layer‑level masks reduce cost.  
- *Evolution vs. random*: Evolution leverages gradient‑based scores but may converge to local optima; random explores broadly but is less efficient; population size and mutation rates balance exploration/exploitation.

### Failure signatures
- Low Kendall/Spearman correlation between Φ and actual downstream accuracy.  
- High variance in Φ across similar candidates (noisy proxy).  
- Evolutionary stagnation: no improvement in top‑10 score for many iterations.  
- Memory overflow due to too high LoRA rank or context length.

### First 3 experiments
1. *Proxy validation*: Sample 70 random architectures, compute Φ, and measure ranking correlation (τ) with WikiText‑2 perplexity and MMLU accuracy; target τ > 0.8.  
2. *Hyperparameter sweep*: Vary N ∈ {4,16,128}, CL ∈ {512,2048,4096}, r ∈ {2,64,4096} on fixed budget to identify stable settings that maintain proxy performance.  
3. *Scale test*: Apply TraceNAS to Llama‑2‑7B with target 2.7 B parameters, compare against uniform pruning and ShearedLlama after 20 B tokens of continued pretraining.

## Open Questions the Paper Calls Out
1. *Curvature modeling*: How does omitting loss‑landscape curvature affect long‑term convergence and final accuracy of pruned models during continued pretraining?  
2. *Multimodal generalization*: Does the gradient trace correlation proxy work for multimodal LLMs (e.g., vision‑language models) or does it degrade due to architectural heterogeneity?  
3. *Calibration data distribution*: How sensitive is the proxy ranking to the distribution of calibration data? Does stability hold across diverse domains or qualities?  
4. *Search algorithm optimality*: Is evolutionary search the most efficient for the discrete depth‑width space, or could alternatives (Bayesian optimization, RL) find better architectures within the same GPU‑hour budget?

## Limitations
- Calibration dataset specifics (FineWeb‑Edu filtering, packing) are unreported, risking gradient stability and reproducibility.  
- Evolutionary hyperparameters (mutation jitter, crossover range) are not precisely specified, requiring empirical tuning.  
- Weak corpus evidence; related zero‑shot pruning methods lack citation traction, limiting comparative validation.

## Confidence
- Proxy mechanism (gradient trace alignment): **Medium** (strong ranking correlation reported but depends on unreleased calibration details).  
- Low‑rank approximation efficacy: **Medium** (stability across ranks shown, yet break conditions at extreme sparsity unevaluated).  
- Evolutionary search gains: **Medium** (non‑uniform benefits demonstrated but lack sensitivity analysis to hyperparameters).

## Next Checks
1. *Calibration data ablation*: Vary calibration set size (4k–256k tokens) and source diversity to determine minimal stable set for high proxy ranking (τ>0.8).  
2. *Hyperparameter sensitivity*: Systematically sweep population size, mutation rate, and crossover range on Llama‑2‑7B to quantify robustness of final accuracy.  
3. *Head‑to‑head benchmarking*: Replicate TraceNAS search and compare against recent zero‑shot baselines (e.g., IPPRO, SparseSSM) using identical CPT budgets and evaluation suites.
