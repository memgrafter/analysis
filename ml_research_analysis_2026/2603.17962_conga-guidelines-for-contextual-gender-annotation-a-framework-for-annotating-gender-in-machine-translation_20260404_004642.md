# ConGA: Guidelines for Contextual Gender Annotation. A Framework for Annotating Gender in Machine Translation

## Quick Facts
- **arXiv ID:** 2603.17962
- **Source URL:** https://arxiv.org/abs/2603.17962
- **Reference count:** 0
- **Primary result:** The ConGA framework reveals a systematic male-default bias in MT, with models like TowerLLM and mBART over-generating masculine forms (A→M) and under-generating feminine forms (low recall) when translating ambiguous English entities to Italian.

## Executive Summary
This paper introduces the Contextual Gender Annotation (ConGA) framework, a linguistically grounded guideline for creating fine-grained, word-level gender annotations in machine translation. Applied to English-Italian translation, it establishes a gold-standard benchmark by tagging semantic gender in English source text (Masculine, Feminine, Ambiguous) and grammatical gender realization in Italian target text, linked by entity identifiers. Evaluation of two MT systems (TowerLLM, mBART) against this resource quantitatively confirms a persistent masculine bias, particularly in cases where the source is ambiguously gendered.

## Method Summary
The method involves three core steps. First, the gENder-IT dataset is manually annotated using ConGA rules in the INCEpTION platform. Annotators tag each English animate referent with semantic gender (M/F/A) based on context and each Italian corresponding word with its explicit grammatical gender (M/F). Shared numeric identifiers link the same referent across sentences and languages. Italian ambiguous forms are left untagged. Second, translations from TowerLLM and mBART are generated. Third, a custom Python script aligns the model's Italian output with the English source annotations via entity IDs. It classifies each aligned instance as a correct match, a mismatch (error or bias), or unmatched, then computes precision, recall, and F1 for masculine and feminine tags. A specific count of A→M and A→F instances measures "gender introduction bias."

## Key Results
- Both evaluated models exhibit a strong male-default bias, with dramatically more cases of ambiguous source entities resolved to masculine (TowerLLM: 215 A→M vs. 35 A→F; mBART: 221 vs. 29).
- Feminine forms are severely under-generated, with low recall (TowerLLL: 35.4%, mBART: 29.9%) compared to masculine.
- The framework provides a fine-grained, quantifiable measurement of gender bias by isolating systematic gender introduction from general translation errors.

## Why This Works (Mechanism)
### Mechanism 1
The ConGA framework's use of word-level gender tags combined with entity identifiers creates a precise alignment map between source ambiguity and target realization. By distinguishing semantic gender in English from grammatical gender in Italian and linking referents across sentences, it transforms the abstract problem of bias into a measurable alignment task. The core assumption is that bias can be quantified by comparing the source's semantic tag (or ambiguity) to the target's grammatical tag for the same entity. Evidence is seen in the annotation scheme's design and the resulting asymmetric tag counts (more English tags than Italian), which capture linguistic asymmetries like pro-drop.

### Mechanism 2
Entity-level alignment enables the computation of standard classification metrics (Precision, Recall, F1) for gender. A custom script matches tokens sharing an identifier, classifying outcomes as matches, mismatches (errors/bias), or unmatched. This operationalizes bias as a performance disparity between genders. The assumption is that the manually annotated corpus is a reliable gold standard. The dramatic difference in A→M versus A→F frequencies and the low feminine recall directly emerge from this alignment-and-count procedure, as shown in the results tables.

### Mechanism 3
Isolating mismatches where an ambiguous source (A) is resolved to a specific gender (A→M/F) cleanly separates "gender introduction bias" from errors on explicit genders (M→F/F→M). The framework's design treats any gendered output for an ambiguous input as a countable choice. The systematic asymmetry (vastly more A→M than A→F) is treated as evidence of a male-default bias, a conclusion supported by the overwhelming ratio of these counts in the results.

## Foundational Learning
- **Grammatical vs. Natural/Semantic Gender:** The entire framework rests on distinguishing a language's morphological gender system (Italian) from the real-world gender of referents inferred from context (English). Conflating them obscures whether a masculine form is grammatically required or a biased choice. *Quick check:* "The doctor is tired" → "Il medico è stanco." Is this bias if context later reveals the doctor is a woman?
- **Annotation Granularity & Inter-Annotator Agreement:** The value of ConGA depends on consistent, word-level tagging decisions. Challenges include judging stereotypical gender (e.g., "nurse") and handling ambiguous contexts. High IAA is essential for a trustworthy gold standard. *Quick check:* For "A nurse should be compassionate," should "nurse" be <F>, <A>, or something else?
- **Evaluation Metrics for Imbalanced Classification:** Bias is measured via gender-specific Precision/Recall/F1. Given extreme output imbalance (many more M tags), accuracy is misleading. Recall for the minority gender (feminine) is a critical metric. *Quick check:* If a model outputs masculine for 90% of ambiguous cases, what is its feminine recall and why is it more telling than accuracy?

## Architecture Onboarding
- **Component map:** gENder-IT Dataset -> Manual Annotation (INCEpTION, ConGA Guidelines) -> Gold Standard Annotations -> Translation Models (TowerLLM, mBART) -> Model Outputs -> Alignment & Evaluation Script -> Bias Metrics & Analysis
- **Critical path:** Dataset selection -> Manual gold-standard annotation (sequential bottleneck) -> Model inference -> Entity alignment -> Metric calculation -> Bias analysis.
- **Design tradeoffs:** 1) Low temperature (0.2) ensures semantic stability for reliable alignment but may suppress alternative gendered outputs. 2) No `<A>` tag in Italian intentionally forces ambiguous realizations to be untagged, making any gender assignment a visible, countable choice.
- **Failure signatures:** 1) High "Unmatched EN IDs" indicates poor alignment due to model divergence (e.g., paraphrasing). 2) Very low feminine recall (<30%) signals systemic under-generation. 3) Near-zero M→F/F→M error rates but extremely high A→M/A→F ratio confirms the model's primary behavior is *introducing* gender, not flipping it.
- **First 3 experiments:** 1) **IAA Pilot:** Two annotators tag 50 sentences; target Cohen's κ >0.85 (IDs), >0.80 (gender). 2) **Alignment Sanity Check:** Run script on *reference Italian translations* vs. English gold; expect near-perfect matches (ignoring pro-drop). 3) **Bias Baseline on Template Data:** Test on 100 minimal pairs (e.g., "The nurse is tired") to isolate bias from general translation error.

## Open Questions the Paper Calls Out
1.  How do varying decoding parameters (e.g., temperature) affect the stability and magnitude of the masculine-default bias?
2.  To what extent is the ConGA framework and its findings generalizable to other language pairs (e.g., English-German, English-French)?
3.  Can the fine-grained, entity-level annotations be effectively leveraged to automatically mitigate gender bias (e.g., via data augmentation or fine-tuning)?
4.  How should the framework be extended to account for non-binary gender identities and gender-neutral language preferences in the target language?

## Limitations
- The exact ConGA annotation schema configuration and full guideline document are not provided, leaving critical edge cases (proper names, invariant adjectives) to implicit judgment.
- The custom alignment and evaluation script is not released, requiring reimplementation with uncertain fidelity to the original logic.
- Findings are specific to the English-Italian gENder-IT corpus; generalizability to other language pairs and datasets is unvalidated.
- All metrics assume the manually annotated corpus is a perfect gold standard for the "correct" gender realization, with no reported extrinsic validation.

## Confidence
- **High:** The core linguistic distinction between semantic and grammatical gender and the entity-identifier mechanism are sound and clearly described.
- **Medium:** The quantification of "gender introduction bias" (A→M/F) is logical *if* annotation and alignment are reliable; the reported numerical imbalance is striking but depends on unknown annotation quality.
- **Low:** Claims about systemic bias beyond the two evaluated models on this specific dataset. Generalizability to other models, domains, or language pairs is unsupported.
