# ICDAR 2025 Competition on End-to-End Document Image Machine Translation Towards Complex Layouts

## Executive Summary
The ICDAR 2025 Competition on End-to-End Document Image Machine Translation (DIMT) introduced a benchmark for translating text within document images featuring complex layouts. The competition comprised two tracks: OCR-based, where participants used provided text and bounding boxes, and OCR-free, requiring direct image-to-markdown translation. Each track included subtasks for small (≤1B parameters) and large (>1B parameters) models. With 69 teams submitting 27 valid entries, the results demonstrated a clear performance advantage for large models over small ones. The best OCR-based method (InternVL2.5-8B-MPO) achieved 70.48 BLEU, while the top OCR-free approach reached 60.78 BLEU. These findings position large multimodal models as a promising direction for handling intricate document layouts, though OCR-free techniques remain less mature.

The competition evaluated systems on two tracks: (1) OCR-based, where competitors leveraged given OCR-derived text and layout boxes to generate translated markdown, and (2) OCR-free, requiring end-to-end image-to-markdown translation without explicit text extraction. Model sizes were split into small (≤1B) and large (>1B) categories to assess scalability. ## Key Results
- Large models significantly outperformed small models in both tracks.
- OCR-based methods consistently achieved higher BLEU than OCR-free methods.
- Top OCR-based LLM (InternVL2.5-8B-MPO) scored 70.48 BLEU; top OCR-free LLM (same framework) scored 60.78 BLEU.
- Best small models: 66.16 BLEU (OCR-based) and 59.96 BLEU (OCR-free).

## Architecture Onboarding
Component map (OCR-based):  
Image -> OCR Engine -> Text & Boxes -> Layout Analyzer -> MT System -> Translated Text & Boxes -> Markup Renderer  
Component map (OCR-free):  
Image -> VLM Encoder-Decoder (Image Encoder + LLM) -> Markdown Output  

Critical path:  
- OCR-based: Detect text regions -> Recognize text -> Translate sentences -> Reconstruct layout in markdown.  
- OCR-free: Encode image globally -> Generate markdown tokens autoregressively, implicitly modeling layout.  

Design tradeoffs:  
- OCR-based: Modular, debuggable, but error propagation from OCR and alignment.  
- OCR-free: Simpler pipeline, better joint optimization, but requires massive data/compute and struggles with fine layout details.  

Failure signatures:  
- OCR-based: Misspelled translations from poor OCR, misaligned text boxes.  
- OCR-free: Hallucinated text, collapsed columns, missing tables/figures, inconsistent markdown syntax.  

First experiments:  
1. Swap OCR backends (e.g., Tesseract vs. commercial OCR) in OCR-based pipeline.  
2. Compare small vs. large VLMs (e.g., Florence-2 vs. InternVL2.5) on OCR-free track.  
3. Test on single-column vs. multi-column documents to isolate layout difficulty.
