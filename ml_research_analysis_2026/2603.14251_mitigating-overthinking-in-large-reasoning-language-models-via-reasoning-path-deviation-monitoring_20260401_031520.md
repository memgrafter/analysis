# Mitigating Overthinking in Large Reasoning Language Models via Reasoning Path Deviation Monitoring

## Quick Facts
- arXiv: 2603.14251
- Source URL: https://arxiv.org/abs/2603.14251
- Reference count: 40
- Primary result: Average accuracy +3.9% (up to +10.6% on MATHHARD) vs. vanilla CoT; higher early‑exit on hard tasks; training‑free.

## Executive Summary
Large reasoning language models (LRLMs) often generate redundant steps—overthinking—wasting compute and sometimes harming accuracy. This paper presents RPDI‑EE, a novel early‑exit method that monitors token entropy during chain‑of‑thought (CoT) generation. Overthinking correlates with high‑entropy transition tokens (e.g., “Wait”, “But”); RPDI compares recent entropy (sliding window) to the global average and exits when the ratio exceeds a threshold, at symbolic boundaries. Evaluated on eight LRLMs across seven benchmarks, RPDI‑EE improves accuracy by up to +10.6% on MATHHARD (avg +3.9%) while reducing token count, with no extra training or answer probing.

## Method Summary
During autoregressive generation, RPDI‑EE computes the entropy \(H(t) = -\sum_v p(v)\log p(v)\) from the model’s logits. It maintains two sums: \(S_{\text{global}}\) (total entropy) and \(S_{\text{local}}\) (entropy over the most recent \(W=512\) tokens). The exit condition is checked only when the model emits a token belonging to a predefined boundary set \(B\) (e.g., newlines, punctuation, “Wait”, “But”, inherited from DEER). If at least \(W\) tokens have been generated, the global average \(G = S_{\text{global}} / i\) and local average \(L = S_{\text{local}} / W\) are computed; the RPDI is \(L/G\). When \(RPDI > \lambda=2.0\), an early‑exit token is injected and the model produces the final answer within the remaining context budget \(L_{\text{max}}\). Implemented with vLLM and greedy decoding; no training or proxy models involved.

## Key Results
- Avg accuracy +3.9% over vanilla CoT across 8 models and 7 benchmarks.
- Up to +10.6% gain on MATHHARD (DeepSeek‑R1‑Distill‑Qwen‑32B).
- Early‑exit trigger rates increase with task difficulty, and accuracy on triggered samples is preserved or improved.
- Significant token reduction without performance sacrifice on easy tasks.

## Why This Works (Mechanism)
Overthinking is characterized by repeated reconsiderations expressed via high‑entropy transition tokens. The local entropy window captures these spikes, while the global average provides a stable baseline. RPDI thus becomes a sensitive signal that the reasoning path is deviating into unproductive loops. By triggering exit only at natural boundaries, RPDI‑EE avoids disrupting coherence and leverages the model’s existing ability to produce correct answers after incomplete reasoning. The approach requires no additional parameters or separate answer‑probing passes, eliminating their associated overhead and bias.

## Foundational Learning
- **Token Entropy**: Quantifies uncertainty of next‑token distribution; needed to identify high‑entropy transition points. Quick check: For a stop word like “the”, entropy should be <0.1 bits.
- **Sliding Window Average**: Smooths short‑term entropy fluctuations; defines the “local” view. Quick check: Feed a fixed stream of low‑entropy tokens and confirm \(S_{\text{local}}\) remains constant after window fills.
- **Reasoning Path Deviation Index (RPDI)**: Ratio \(L/G\); flags when recent entropy significantly exceeds the baseline. Quick check: Simulate with known entropy values; RPDI should cross λ precisely when a spike enters the window.
- **Boundary Tokens**: Symbolic delimiters (e.g., newline, period, “Wait”, “But”) that approximate step boundaries; needed to avoid mid‑thought exits. Quick check: Sample a CoT output; ensure most boundaries occur at natural pauses (line breaks, concluding phrases).

## Architecture Onboarding
Component map:
Question → Prompt → LLM (autoregressive) → Entropy computation → Global & Local accumulators → Token in B? → Yes → RPDI calc → >λ? → Yes → Early exit → Answer generation

Critical path: generate token → compute entropy → update S_global & S_local → if token in B and i≥W → compute RPDI → condition true → inject exit token → switch to answer phase.

Design tradeoffs: Larger \(W\) delays detection but reduces false positives; lower \(\lambda\) increases exits (risk over‑truncation); richer \(B\) adds checks (overhead) but may improve exit timing.

Failure signatures: Trigger rate ≈0% → B mismatched; high trigger rate on easy sets → \(\lambda\) too low; no accuracy gain on hard sets → \(\lambda\) too high or entropy bug; Vanilla baseline far below reported → prompt or evaluation error.

## Limitations
- Boundary set \(B\) is inherited but not enumerated; approximations may affect reproducibility.
- Exact CoT prompt wording per benchmark is unreported; variations can alter entropy patterns.
- Token budget \(L_{\text{max}}\) after exit is unspecified; our implementation assumes context limit.
