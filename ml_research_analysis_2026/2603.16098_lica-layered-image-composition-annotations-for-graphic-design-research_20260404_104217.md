# LICA: Layered Image Composition Annotations for Graphic Design Research

## Quick Facts
- **arXiv ID**: 2603.16098
- **Source URL**: https://arxiv.org/abs/2603.16098
- **Reference count**: 4
- **Primary result**: LICA is a large-scale dataset of 1,550,244 hierarchical graphic design layouts (24.6M components) that introduces graphic design video via 27,261 animated layouts with component-level keyframes.

## Executive Summary
Existing graphic design datasets lack compositional structure and temporal annotations, limiting AI research to static, pixel-level analysis. LICA addresses this gap by providing a massive collection of multi-layer designs encoded as hierarchical JSON compositions. Each layout is broken down into typed components (text, image, vector, groups) with rich spatial, typographic, and style metadata. The dataset spans 20 categories and nearly one million unique templates, many with multiple variants. Critically, LICA includes 27,261 animated layouts with per-component keyframes, establishing "graphic design video" as a new modality. This structured, editable representation enables research on controlled layout generation, constraint-preserving editing, and component-centric animation—moving beyond mere image synthesis toward true design assistance.

## Method Summary
LICA was constructed using a custom rendering engine as the core annotation platform. Annotators, guided by LLM-generated user intents, built designs directly within an interface that output the canonical hierarchical JSON in real time. The engine enforced structural integrity, and quality assurance combined automated schema validation with manual visual review. The final dataset comprises 1,550,244 layouts (24.6 million components) across 20 categories, with 971,850 unique templates; 107,728 templates include up to 24 controlled variants. For animation, 27,261 layouts receive per-component keyframes, duration, and start-time annotations. The release provides JSON files and rendered PNGs, together with code to render JSON via HTML/CSS, ensuring accessibility for downstream research.

## Key Results
- 1,550,244 multi-layer layouts with full component hierarchy (24.6M components)
- Spans 20 categories, 971,850 unique templates, 107,728 templates with multiple variants
- 27,261 animated layouts with component-level keyframes, introducing graphic design video

## Why This Works (Mechanism)

### Mechanism 1: Hierarchical JSON preserves compositional relationships
**Claim:** Representing graphic designs as a hierarchical JSON composition preserves the intentional, structured relationships between design elements, enabling models to reason about layout as an editable program rather than a static image.  
**Mechanism:** The dataset encodes each design as a tree of typed components (text, image, vector, group), each with spatial, transform, and style metadata. This structure mirrors the layer-based editing paradigm of professional tools (e.g., Figma, Photoshop) and document semantics (HTML/CSS), providing a direct, lossless mapping from a generative model's output to an editable design artifact.  
**Core assumption:** That the compositional logic and constraints of professional design are faithfully captured by this component hierarchy and its attributes, and that operating at this structural level is more effective for controlled generation than pixel-based methods.  
**Evidence anchors:**  
- [abstract] "...represents each design as a hierarchical composition of typed components... rich per-element metadata... By representing design as a system of compositional layers and relationships, the dataset supports research on models that operate directly on design structure rather than pixels alone."  
- [section 2.1] "Each component of a layout is assigned to one of four primary types: image, text, vector graphic, and group. Each layout in LICA contains layout level annotations..."  
- [corpus] Corpus signals show related work focusing on "multi-layered artwork" and "layered object integration," suggesting the research community perceives this structured representation as a key direction. Direct empirical validation of the mechanism's superiority is not present in the provided corpus.  
**Break condition:** If the hierarchical structure is flattened or densely packed into a non-editable serialization (as in some prior datasets), the mechanism fails to provide editability and structured reasoning.

### Mechanism 2: Component-level keyframes define graphic design video
**Claim:** Annotating per-component keyframes and motion parameters establishes "graphic design video" as a distinct modality with sparse, semantically-driven temporal structure, different from natural video.  
**Mechanism:** For 27,261 layouts, each animated component carries explicit `animation`, `duration`, and `start-time` properties, defining its behavior on a shared timeline. This decouples motion semantics from pixel changes, allowing models to learn animation as a set of discrete, communicative intents (e.g., "headline slides in") applied to semantic layers.  
**Core assumption:** That the temporal logic of design (entrance/exit transitions, emphasis) is fundamentally compositional and component-centric, and that this can be learned from keyframe annotations without modeling physical dynamics.  
**Evidence anchors:**  
- [abstract] "We further introduce graphic design video as a new and largely unexplored challenge... through 27,261 animated layouts annotated with per-component keyframes and motion parameters."  
- [section 2.5] "Graphic design video differs fundamentally from natural video... motion is sparse, structured, and directly tied to the component hierarchy... By providing structured temporal annotations at the component level, LICA enables an entirely new class of research problems."  
- [corpus] Corpus evidence is weak; neighboring papers discuss general "text-to-image" or "graphic design" but do not address temporal, component-level animation annotation. This mechanism's novelty is claimed directly from the paper's data collection.  
**Break condition:** If temporal annotations are missing, incomplete, or not semantically aligned with component identity (e.g., only frame-level motion vectors), the distinction from natural video is lost and the modality's unique challenges cannot be studied.

### Mechanism 3: Custom rendering engine ensures structural fidelity
**Claim:** Using a custom rendering engine as an annotation platform aligns the data collection process with the target structured representation, solving the chicken-and-egg problem of needing structure to generate structure.  
**Mechanism:** Annotators build designs directly within an interface that outputs the canonical JSON hierarchy in real-time. The engine enforces structural integrity, and a QA pipeline (automated checks + manual visual review) validates that the rendered output matches the component tree. This ensures the dataset's fidelity to a structured format.  
**Core assumption:** That human annotators, guided by LLM-generated user intents, can produce high-quality, stylistically diverse designs when constrained to a structured, editable format, and that this process yields more valid training data than post-hoc extraction from flat images.  
**Evidence anchors:**  
- [section 2.6] "We designed an annotation pipeline centered around a custom rendering engine that represents each design as a hierarchy of editable components... This engine was distributed to third-party annotators... Quality assurance was enforced through a combination of automated and manual validation."  
- [section 2.6, Figure 6] Shows the generation interface and verification pipeline, illustrating the closed-loop process.  
- [corpus] Corpus does not provide evidence for or against this specific data collection mechanism; it is an internal methodological claim.  
**Break condition:** If the rendering engine's output diverges from the annotated JSON (e.g., due to bugs in the engine's layout logic) or if annotator adherence to the structured format degrades at scale, the dataset's structural fidelity is compromised.

## Foundational Learning

**Layered Composition & Document Object Model (DOM) Thinking**  
Why needed: To interpret and generate LICA's JSON layouts, one must understand nested, transformable containers (groups), property inheritance vs. overrides (e.g., character-level style ranges), and absolute vs. relative positioning. This is analogous to web development or design tool layer panels.  
Quick check: Given a JSON snippet with a group containing a rotated text element and an image with a clip path, can you compute the final screen-space bounding box for each child?

**Temporal Design Semantics**  
Why needed: The animated layouts require understanding that time is a first-class property of components, not a separate video track. Keyframes, easing, and start-time offsets define *how* and *when* an element changes, which is a design decision about narrative flow and emphasis.  
Quick check: For a text component with `duration: 2.0s`, `start-time: 0.5s`, and a keyframe defining opacity from 0 to 1, describe its visibility state from `t=0s` to `t=3s`.

**Constraint-Driven Dataset Construction**  
Why needed: LICA's scale and structure were not found but created. Understanding the "chicken-and-egg" solution—using a tool that outputs the target representation to collect the data—is key to assessing the dataset's validity and limitations (e.g., annotator-induced biases, engine capabilities).  
Quick check: Why is collecting graphic design data harder than collecting ImageNet categories, and how does LICA's approach address the core difficulty?

## Architecture Onboarding

**Component map**: The core data unit is a `layout` JSON file. Root fields: `components` (array), `width`, `height`, `category`, `template_id`. Each component has `type` (text/image/vector/group/frame_grid), `id`, `parent_id`, `transform`, `style`. `text` adds `content`, `font_family`, `style_ranges`; `image` adds `src`, `clip_path`; animated components include `animation` with `keyframes`, `duration`, `start_time`. The tree defines nested coordinate spaces; groups act as containers.

**Critical path**:  
1. Load a sample JSON layout.  
2. Recursively traverse the `components` tree, applying each component's transform relative to its parent to compute global coordinates.  
3. Render by drawing components in array order: groups set coordinate spaces; text uses font/style; images/clip_paths use assets with clipping.  
4. Validate by comparing the rendered PNG (provided) against your output.  
5. For animations, iterate over time steps, applying interpolated transforms/opacity per component's keyframes.

**Design tradeoffs**:  
- *Rendering fidelity vs. editability*: JSON prioritizes editability; exact pixel matching may suffer from font rasterization or engine-specific CSS/SVG differences.  
- *Hierarchy depth vs. performance*: Deep groups increase traversal cost; release flattens groups, simplifying traversal but losing original nesting.  
- *Attribute richness vs. sparsity*: Many components lack optional fields (e.g., empty `style_ranges`); models must handle missing data gracefully.

**Failure signatures**:  
- `parent_id` references a non-existent component → broken hierarchy.  
- `transform` string malformed or unsupported → misplacement.  
- `font_family` not in ~2700-family allowlist → fallback alters appearance.  
- For animated layouts: `start_time` + `duration` exceeds layout `total_duration` → clipping.  
- Template variants have inconsistent `category` or wildly different component counts → grouping error.

**First 3 experiments**:  
1. **Render Reconstruction**: Write a minimal renderer (e.g., Python + Cairo or HTML/CSS) that takes a single LICA JSON and produces a PNG. Compute SSIM/PSNR against the ground-truth PNG to validate coordinate system, transforms, and clipping.  
2. **Structure-to-Description**: Given a layout's JSON tree, generate the natural language `layout_description` (from metadata). This tests mapping from spatial/style to semantic intent.  
3. **Static-to-Animated Projection**: Given a static layout JSON, predict plausible `duration`, `start_time`, and a simple `keyframe` (e.g., opacity 0→1) for each text component to create a basic entrance animation. Use the 27k animated layouts as prior for typical durations and motion types.

## Open Questions the Paper Calls Out
1. **Automated, context-aware metrics for design quality**: Current metrics use simplistic geometric checks or noisy LLM judges that conflate aesthetics with structural correctness. Need human-annotated quality benchmarks across categories and models that correlate with design success while distinguishing structural soundness from aesthetic preference.
2. **Adapting vision-language models to graphic design video**: Design video motion is sparse, structured, and component-centric, unlike natural video. Requires new inductive biases beyond those trained on natural video. Need models that generate component-level animation parameters from text or predict motion trajectories.
3. **Impact of preserving hierarchical component structure**: The released dataset flattens groups, removing parent-child relationships. It is unclear if models can infer hierarchy from flat coordinates or if original structure is necessary for tasks like grouping or hierarchical manipulation.
4. **Constraint-preserving design editing at component level**: Existing inpainting models operate at pixel level, disrupting design structure when editing. Need architectures that accept component-level edit requests (e.g., "change font of headline to bold") and output updated hierarchical annotations while preserving global coherence.
5. **Leveraging template variant structure for style-consistent variations**: Variants provide natural supervision for style adherence and controlled variation, but the implicit "style identity" is undefined. Need models that generate new variants for unseen templates and analysis of transfer across categories.

## Limitations
- Schema documentation is incomplete; exact field definitions and value ranges for transforms, fonts, and animation keyframes must be inferred from sample files, risking misimplementation.
- Rendering fidelity gap: the custom engine's CSS/SVG support (e.g., text curvature, complex clip paths) is unspecified, so pixel-perfect reconstruction may fail without precise engine parity.
- Hierarchy flattening in the release destroys original nesting, breaking the claimed structural fidelity for architectural analysis and potentially impairing tasks that rely on grouping.

## Confidence
- **High**: Dataset scale and basic component counts (1.55M layouts, 24.6M components) are explicitly stated and verifiable from the release.
- **Medium**: Hierarchical JSON representation matches design tool paradigms, but fidelity to professional compositional logic is assumed, not benchmarked against actual design tool exports.
- **Low**: "Graphic design video" as a distinct modality is novel but lacks external corroboration; temporal annotations' semantic alignment with design intent is unvalidated.

2. **Hierarchy Integrity Check**: Parse all sample JSONs and count `group`-type components before and after flattening. Confirm the release notes' claim of flattening and quantify depth reduction (e.g., average original depth vs. flattened).
