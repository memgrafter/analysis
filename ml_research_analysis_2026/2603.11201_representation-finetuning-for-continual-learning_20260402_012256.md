# Representation Finetuning for Continual Learning
## Quick Facts
- arXiv ID: 2603.11201
- Source URL: https://arxiv.org/abs/2603.11201
- Reference count: 40
- Primary result: CoRe outperforms SOTA PEFT methods in continual learning benchmarks with fewer trainable parameters, achieving state-of-the-art average accuracy (e.g., 92.37% on CIFAR-100 class-incremental).

## Executive Summary
Continual learning with pre-trained models is hindered by catastrophic forgetting during fine-tuning. Existing parameter-efficient fine-tuning (PEFT) methods lack explicit mechanisms to control representation drift. This paper introduces CoRe, a framework that performs task-specific interventions within a low-rank linear subspace of hidden representations. CoRe optimizes an objective that balances stability (preserving prior knowledge) and plasticity (adapting to new tasks) via explicit constraints, including orthogonality to bound drift. Evaluated on vision transformers (ViT-B/16) across task, domain, and class-incremental benchmarks, CoRe consistently surpasses Adapter, Prompt, and SSF in average and last accuracy while using the fewest trainable parameters. For instance, on CIFAR-100 with 10 classes per task, CoRe achieves 92.37% average accuracy. Ablations confirm optimal performance at rank=8 and using all transformer blocks.

## Method Summary
CoRe extends parameter-efficient fine-tuning for continual learning by inserting low-rank linear intervention modules after each transformer block of a frozen pretrained vision backbone. For a given task, these modules are trained to transform the hidden representations while being constrained to a low-rank subspace; the transformation matrix is factorized as U·V^T with U, V ∈ ℝ^{d×r}, and an orthogonal regularization R^T R = I is applied to bound representation drift. The training objective combines the standard cross-entropy loss for the new task with a stability term that penalizes excessive deviation from the original pretrained representations (e.g., via anchor data or Jacobian regularization). After learning, the backbone remains unchanged and only the task-specific low-rank matrices are stored, yielding high parameter efficiency. At inference, the appropriate set of intervention matrices is selected according to the task identity and applied sequentially through the network.

## Key Results
- On CIFAR-100 class-incremental learning (10 classes per task), CoRe attains 92.37% average accuracy, the highest among compared PEFT methods, with the lowest number of trainable parameters.
- CoRe consistently outperforms Adapter, Prompt, and SSF across task-, domain-, and class-incremental benchmarks in both average and last accuracy.
- Ablation studies show that rank=8 yields optimal performance and that applying CoRe to all transformer blocks is beneficial.

## Why This Works (Mechanism)
CoRe confines adaptation to a low-rank linear subspace of the hidden representations, which inherently limits the magnitude of representation changes. The orthogonality constraint (R^T R = I) ensures that the subspace does not amplify any direction, thereby providing a theoretical bound on drift as shown in Theorem 1. By explicitly optimizing an objective that trades off plasticity (task loss) and stability (representation drift), CoRe learns task-specific interventions that effectively encode new knowledge while preserving past knowledge. The low-rank factorization also drastically reduces the number of trainable parameters, enabling efficient learning without overfitting.

## Foundational Learning
**Continual Learning**
- *Why needed*: The core problem addressed; aims to learn sequentially without forgetting.
- *Quick check*: After sequential training on tasks A → B, evaluate accuracy on A; minimal drop indicates effective continual learning.

**Catastrophic Forgetting**
- *Why needed*: The primary failure mode in neural networks undergoing sequential training; CoRe is designed to mitigate it.
- *Quick check*: Compute the difference in accuracy on previous tasks before and after learning a new task; a large drop signals catastrophic forgetting.

**Parameter-Efficient Fine-Tuning (PEFT)**
- *Why needed*: CoRe belongs to this family; baselines like Adapter, Prompt, SSF are PEFT methods.
- *Quick check*: Count trainable parameters as a fraction of total parameters; values <<1 indicate parameter efficiency.

**Low-Rank Matrix Factorization**
- *Why needed*: CoRe uses low-rank factorization (U·V^T) to limit the capacity of interventions and control drift.
- *Quick check*: Compute the rank of the learned intervention matrices; verify it does not exceed the chosen r.

**Orthogonal Projections**
- *Why needed*: Orthogonality constraint (R^T R = I) is central to the theoretical drift bound.
- *Quick check*: After training, compute R^T R and measure deviation from identity matrix (e.g., Frobenius norm); small deviation indicates constraint is approximately satisfied.

## Architecture Onboarding
**Component Map**
Input Image -> Patch Embedding -> Transformer Block 1 (frozen) -> CoRe Intervention 1 (low-rank matrix R1) -> Transformer Block 2 (frozen) -> CoRe Intervention 2 -> ... -> Transformer Block N (frozen) -> CoRe Intervention N -> Global Average Pooling -> Task-specific Classifier -> Output

**Critical Path**
1. Initialize pretrained ViT-B/16 backbone (weights frozen).
2. For a new task t, add fresh CoRe modules (each with trainable low-rank matrices R_l) after every transformer block.
3. Train only the CoRe parameters on task t’s data using loss L = L_task + λ * L_stability, where L_stability enforces orthogonality and possibly representation preservation on anchor data.
4. Store the learned task-specific R_l parameters.
5. At inference, given a sample and task ID, load corresponding R_l and propagate through backbone with interventions.

**Design Tradeoffs**
- *Rank (r)*: Larger r increases adaptability (plasticity) but adds parameters and risk of forgetting; smaller r improves stability but may limit performance.
- *Orthogonality Constraint*: Enforcing R^T R = I reduces representation drift but may restrict the solution space, potentially hurting accuracy.
- *Number of Intervention Layers*: Applying CoRe to all blocks yields best results (as shown in ablation) but linearly increases parameters; limiting to a subset reduces cost at the potential expense of performance.

**Failure Signatures**
- High forgetting: significant accuracy drop on previous tasks after learning a new one.
- Low current-task accuracy: poor performance on the new task despite training, indicating insufficient plasticity.
- Rank sensitivity: performance collapses when r is too low; increasing r recovers performance but may increase forgetting.
- Instability: if orthogonality is not properly maintained, training may diverge or produce erratic accuracy.

**First Experiments**
1. *Baseline Replication*: Re-run CoRe on CIFAR-100 class-incremental (10 classes/task) with ViT-B/16, verifying the reported 92.37% average accuracy and parameter count.
2. *Rank Ablation*: Evaluate CoRe with ranks {1, 2, 4, 8, 16, 32} on CIFAR-100 and plot accuracy vs. parameters to understand sensitivity.
3. *Orthogonality Test*: Compare orthogonal versus unconstrained low-rank interventions on a benchmark like MiniImageNet, measuring both current and previous task accuracy to gauge the effect of the orthogonality constraint.

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How does the optimal rank of CoRe's low-rank intervention subspace vary across continual learning benchmarks, and can it be selected adaptively?
- **Basis in paper**: [inferred] Table V shows rank=8 best for CIFAR Inc10, but no analysis across other datasets or adaptive selection.
- **Why unresolved**: The paper fixes rank=8 for all experiments, ignoring potential dataset-specific optima and scalability issues.
- **What evidence would resolve it**: Evaluate performance over a range of ranks on multiple benchmarks; design an adaptive mechanism (e.g., based on task similarity) and validate.

### Open Question 2
- **Question**: Is the orthogonality constraint R^T R = I essential for CoRe's stability, or can relaxed constraints improve the stability-plasticity trade-off?
- **Basis in paper**: [inferred] Theorem 1 and Proposition 1 assume orthogonality to bound representation drift, but no ablation on this constraint is conducted.
- **Why unresolved**: The necessity of orthogonality is not empirically verified; it may overly restrict the intervention subspace.
- **What evidence would resolve it**: Compare CoRe with orthogonal vs. non-orthogonal projections across benchmarks, measuring forgetting and accuracy.

### Open Question 3
- **Question**: How does CoRe compare against traditional continual learning methods (e.g., EWC, replay-based) in accuracy and parameter efficiency?
- **Basis in paper**: [explicit] The paper states comparisons are only with PEFT methods (Adapter, Prompt, SSF) in Section IV.B and baseline list.
- **Why unresolved**: PEFT methods differ fundamentally from classic CL approaches; CoRe's effectiveness against them remains unknown.
- **What evidence would resolve it**: Include EWC, SI, and iCaRL in experiments on the same benchmarks, reporting Avg/Last accuracy and parameter counts.

### Open Question 4
- **Question**: Can CoRe's representation finetuning be generalized to non-transformer architectures (e.g., CNNs) and other modalities like language models?
- **Basis in paper**: [inferred] CoRe is designed for ViT transformers; although ReFT originated for LLMs, CoRe's application is limited to vision.
- **Why unresolved**: The method relies on transformer-specific linear projections; its applicability to other architectures is untested.
- **What evidence would resolve it**: Adapt CoRe to CNN backbones (e.g., ResNet) and evaluate on vision CL tasks; apply to LLMs for language CL benchmarks.

## Limitations
- **Small marginal gains**: Reported improvements are marginal (e.g., 0.1% on CIFAR-100), raising concerns about statistical significance and practical impact.
- **Limited architectural scope**: All experiments use ViT-B/16; generalizability to CNNs, other ViT sizes, or language models is unknown.
- **Hyperparameter sensitivity**: Optimal rank fixed at 8; sensitivity to rank and lack of adaptive selection hinder usability.
