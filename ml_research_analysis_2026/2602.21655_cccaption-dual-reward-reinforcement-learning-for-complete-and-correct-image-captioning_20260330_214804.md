# CCCaption: Dual-Reward Reinforcement Learning for Complete and Correct Image Captioning
## Quick Facts
- arXiv ID: 2602.21655
- Source URL: https://arxiv.org/abs/2602.21655
- Reference count: 40
- Primary result: CCCaption-2B achieves state-of-the-art results: CapArena score 46.39 (vs. base 41.39), Prism average 52.80 (vs. 50.05), and Hallucinations average 70.57 (vs. 70.19).

## Executive Summary
This paper addresses the problem of incomplete and incorrect image captions generated by models trained on human-annotated captions. It introduces CCCaption, a reinforcement learning framework with dual rewards: a completeness reward that encourages captions to answer diverse visual queries from multiple MLLMs, and a correctness reward that penalizes hallucinations via sub-caption validation. Additionally, a dynamic query sampling strategy enhances training efficiency, supported by the CCaption-44k dataset. CCCaption-2B, built on Qwen3-VL-2B, sets new state-of-the-art results across benchmarks—CapArena score 46.39 (vs. base 41.39), Prism average 52.80 (vs. 50.05), and Hallucinations average 70.57 (vs. 70.19)—demonstrating consistent improvements in both completeness and correctness while reducing hallucinations.

## Method Summary
The method trains a captioning policy (Qwen3-VL-2B) via GRPO reinforcement learning with a hybrid reward \( R = \alpha R_{comp} + (1-\alpha) R_{corr} \) (\(\alpha = 0.05\)). The completeness reward \( R_{comp} \) measures the fraction of diverse visual queries (sampled from a per‑image pool in CCaption‑44k) correctly answered by the caption. The correctness reward \( R_{corr} \) decomposes the caption into atomic sub‑captions and averages their validity scores from a frozen judge MLLM. A dynamic query sampler adjusts per‑query sampling probability based on historical rollout accuracy variance to focus on queries with higher gradient signal. Training uses the CCaption‑44k dataset, which provides ~10 diverse queries per image (generated by aggregating multiple MLLMs and filtering for diversity). Hyperparameters: lr=1e‑6, 20 epochs, 5 rollouts per step.

## Key Results
- CCCaption-2B achieves CapArena score 46.39, a 5‑point gain over base Qwen3‑VL‑2B (41.39) and far above CapRL‑3B (17.56).
- Prism average improves to 52.80 (from base 50.05), indicating better completeness.
- Hallucinations average improves to 70.57 (from base 70.19), showing reduced hallucinations.

## Why This Works (Mechanism)
### Mechanism 1: Multi‑MLLM Query Aggregation for Completeness
- **Claim:** Training with a diverse, aggregated set of visual queries from multiple MLLMs produces captions that cover more salient visual facts, thereby increasing completeness.
- **Mechanism:** The framework generates a candidate query set using several MLLMs (e.g., LLaVa, Qwen, InternVL). A diversity metric based on query embedding cosine similarity (Eq. 5) filters this set to ensure high variance, approximating a more comprehensive basic information set \( B_x \). The caption model is then rewarded (Eq. 4) for successfully answering these sampled queries.
- **Core assumption:** The union of queries from diverse MLLMs better captures the space of “salient visual facts” \( B_x \) than queries from a single MLLM, which is biased by its own training and prompting.
- **Evidence anchors:**
  - [abstract]: “For completeness, we use diverse LVLMs to disentangle the image into a set of visual queries, and reward captions that answer more of these queries.”
  - [section 3.2]: Describes Algorithm 1 for multi‑MLLM query generation and the diversity filter \( V(Q_x) \). Table 4 and Figure 4 show performance and embedding coverage improvements with the CCaption‑44k dataset over “Vanilla” single‑MLLM queries.
  - [corpus]: Neighbors like “Guiding Image Captioning Models Toward More Specific Captions” and “IC3: Image Captioning by Committee Consensus” support the principle that aggregating multiple model outputs (via consensus or diversity) improves caption quality and information richness, aligning with the multi‑MLLM approach.
- **Break condition:** If the MLLMs used for query generation share significant architectural or data biases, the query diversity metric may be inflated, and the aggregated set may still miss key visual facts, leading to an incomplete approximation of \( B_x \). Performance would plateau or degrade compared to a simpler, high‑quality single‑model query set.

### Mechanism 2: Sub‑caption Decomposition for Correctness Penalty
- **Claim:** Decomposing a generated caption into atomic sub‑captions and validating each against the image using a frozen judge MLLM provides a dense correctness signal that penalizes hallucinations.
- **Mechanism:** The caption \( \hat{y} \) is broken into a set of sub‑caption queries \( Q_{\hat{y}} \). Each query is scored by a judge MLLM \( M_J \) given the image (Eq. 6). The average score forms the correctness reward \( R_{corr} \), directly penalizing captions containing ungrounded statements.
- **Core assumption:** An atomic factual statement (a “sub‑caption”) can be reliably verified as true/false by a capable third‑party MLLM, and the aggregate score correlates with the caption’s overall factuality.
- **Evidence anchors:**
  - [abstract]: “For correctness, we penalize captions that contain hallucinations by validating the authenticity of sub‑caption queries, which are derived from the caption decomposition.”
  - [section 3.2]: Formalizes \( R_{corr}(x, \hat{y}) \). Table 3 shows CCCaption‑2B reduces hallucinations compared to base Qwen3‑VL‑2B and CapRL‑3B. Figure 3 provides qualitative examples where CCCaption‑2B avoids numeric hallucinations.
  - [corpus]: Neighbors like “Cross‑modal Identity Mapping: Minimizing Information Loss” and work on hallucination benchmarks (HallusionBench) indicate a community focus on verification‑based methods for reducing modality conversion errors.
- **Break condition:** The judge MLLM \( M_J \) itself may hallucinate or have blind spots, especially on fine‑grained details. If \( M_J \)’s scoring is noisy or biased, the correctness reward becomes unreliable, potentially either being too lenient (failing to penalize real hallucinations) or too strict (penalizing valid, nuanced descriptions). The effectiveness is contingent on \( M_J \)’s own factuality capabilities.

### Mechanism 3: Dynamic Query Sampling for Gradient Efficiency
- **Claim:** Dynamically adjusting the sampling probability of individual queries based on their historical contribution (variance of rollout accuracy) increases the average group advantage within a GRPO batch, stabilizing gradients and improving training efficiency.
- **Mechanism:** For each image’s candidate query pool, the sampling probability \( c(q) \) for query \( q \) is updated. Queries that are consistently answered correctly/incorrectly by rollouts (low gradient signal) are downsampled, while “controversial” queries (high variance in correctness across rollouts) are upsampled (Eq. 7). This maintains a higher signal‑to‑noise ratio in the advantage estimates used by the GRPO policy gradient update.
- **Core assumption:** Queries that are too easy or too hard for the current policy provide minimal or unstable gradient information, respectively. Focusing computation on queries with intermediate difficulty (high advantage variance) maximizes the useful gradient per training step.
- **Evidence anchors:**
  - [abstract]: “A dynamic query sampling strategy enhances training efficiency.”
  - [section 3.2]: Details the contribution update rule using rollout accuracy variance. Section 4.3 Q3 and Figure 5 experimentally demonstrate faster convergence and higher final accuracy when the strategy is used.
  - [corpus]: **Weak evidence.** The neighbor corpus does not contain papers explicitly on dynamic sample selection within RL for captioning. The closest analogy is DAPO [58] cited in the paper, which uses dynamic sampling for general LLM RL, but this is not a direct neighbor in the retrieved set. The primary evidence is internal ablation.
- **Break condition:** If the query difficulty distribution for an image is highly skewed (nearly all queries are either trivially easy or impossibly hard for the current policy), dynamic sampling might discard most queries, leading to high variance in the remaining few and unstable training. The strategy assumes a sufficient mix of query difficulties exists within the candidate pool per image.

## Foundational Learning
- **Reinforcement Learning with Policy Gradients (e.g., GRPO)**
  - Why needed: CCCaption replaces standard cross‑entropy training with an RL objective \( J_{RL} \) to optimize non‑differentiable, extrinsic rewards (completeness/correctness). Understanding the policy gradient theorem, advantage estimation, and the specific GRPO algorithm (from DeepSeek‑R1) used in the VeRL framework is essential to grasp how the model is updated.
  - Quick check: How does GRPO use multiple rollouts per prompt to compute a group‑normalized advantage, and why does this help stabilize training compared to a simple REINFORCE baseline?

- **Multi‑Modal LLMs as Zero‑Shot Evaluators/Judges**
  - Why needed: Both reward functions rely on frozen third‑party MLLMs (e.g., Qwen‑VL, Claude) to score query answers and sub‑captions. The designer must understand the strengths (broad knowledge, instruction following) and failure modes (hallucination, inconsistency) of these judge models to interpret reward signals correctly.
  - Quick check: What are the key risks of using an MLLM like Qwen3‑VL‑32B as a judge for both completeness and correctness, and how might its own biases affect the learned caption policy?

- **Query Decomposition and Atomic Fact Extraction**
  - Why needed: The correctness reward depends on decomposing a fluent caption into a set of verifiable, atomic sub‑queries. This requires understanding techniques for sentence decomposition (e.g., via prompting an MLLM) and the definition of an “atomic” visual fact (object, attribute, relation).
  - Quick check: How does the quality of the sub‑caption decomposition (e.g., whether it produces disjoint, atomic, and exhaustive queries) directly impact the validity of the correctness reward signal?

## Architecture Onboarding
### Component map
1. **Captioning Policy Model (M_θ)**: The trainable model (e.g., Qwen3‑VL‑2B) that generates captions \( \hat{y} \) for image \( x \).
2. **Completeness Judge (M_J^{comp})**: A frozen MLLM (Qwen2.5‑VL‑3B) that answers sampled visual queries \( q \in Q_x \) based on \( \hat{y} \).
3. **Correctness Judge (M_J^{corr})**: A frozen MLLM (Qwen3‑VL‑2B) that scores sub‑caption queries \( q \in Q_{\hat{y}} \) against image \( x \).
4. **Dynamic Query Sampler**: Maintains contribution scores \( c(q) \) per query, sampled via Bernoulli for each training step.
5. **CCaption‑44k Dataset**: Provides images \( x \) and high‑diversity query pools \( Q_x \) for the completeness reward.
6. **RL Training Loop (GRPO via VeRL)**: Orchestrates rollout generation, reward computation (Eq. 8), advantage calculation, and policy update.

### Critical path
1. Initialize \( M_\theta \) (e.g., from pretrained Qwen3‑VL‑2B).
2. For each batch of images from CCaption‑44k: Sample a set of queries \( \tilde{Q}_x \) from its candidate pool using the dynamic sampler.
3. Generate \( k \) rollouts (captions) \( \hat{y}_1…\hat{y}_k \) per image using \( M_\theta \).
4. Compute \( R_{comp} \) for each rollout by having \( M_J^{comp} \) answer each \( q \in \tilde{Q}_x \).
5. Decompose each rollout \( \hat{y}_i \) into \( Q_{\hat{y}_i} \) and compute \( R_{corr} \) via \( M_J^{corr} \).
6. Combine rewards \( R = \alpha R_{comp} + (1-\alpha)R_{corr} \).
7. Compute group‑normalized advantages within each \( k \)-rollout group.
8. Update \( M_\theta \) with the GRPO policy gradient loss.
9. Update query contribution scores \( c(q) \) based on this step’s rollout accuracy variance.
10. Repeat from step 2.

### Design tradeoffs
- **Judge Model Size vs. Cost**: Using a powerful, large judge (e.g., Qwen3‑VL‑32B) improves reward reliability but slows training. The paper uses smaller judges (2B/3B) for efficiency, accepting some noise.
- **Completeness‑Correctness Balance (\( \alpha \))**: The paper finds \( \alpha=0.05 \) works well, heavily favoring correctness. This is a key hyperparameter; setting \( \alpha \) too high risks more hallucinations in pursuit of coverage.
- **Query Pool Size vs. Sampling Overhead**: Each image has ~10 candidate queries. Dynamic sampling uses 5 per step. Larger pools offer more diversity but increase memory/computation for maintaining contribution scores and sampling.

### Failure signatures
- **Hallucination Spiral**: Correctness reward weight (\( 1-\alpha \)) too low, or judge model \( M_J^{corr} \) is weak. Captions become longer (completeness reward dominates) but contain more false details. Monitor: Hallucinations benchmark score drops while Prism score rises.
- **Stagnant Completeness**: Diversity threshold \( \tau \) too high or MLLM list insufficiently diverse. Query set \( Q_x \) becomes small and homogeneous, providing a weak completeness signal. Monitor: Low variance in \( R_{comp} \) across batch, minimal change in caption length/detail.
- **Training Instability/Vanishing Gradients**: Dynamic query sampler over‑prunes. After initial epochs, \( c(q) \) for most queries drops near zero, leading to high variance from sampling only a few “controversial” queries per step. Monitor: Sudden spikes in loss, reward oscillation, or policy collapse to short, generic captions.

Verify that the diversity filter \( V(Q_x) \) successfully increases the t‑SNE spread of query embeddings compared to a single‑MLLM baseline, as shown in Figure 4.
2. **Isolate Reward Signals**: Train three ablation models (with \( \alpha=1.0 \), \( \alpha=0.0 \), and \( \alpha=0.05 \)) on a tiny CCaption‑44k subset (e.g., 1k samples). Confirm: \( \alpha=1.0 \) leads to longer but more hallucinated captions (check Hallucinations score), \( \alpha=0.0 \) leads to short, factually safe but incomplete captions (check Prism score), and \( \alpha=0.05 \) balances both.
3. **Test Dynamic Sampler Impact**: Train two models for 10 steps on the same small dataset—one with dynamic query sampling enabled, one without (sampling uniformly from candidate pool). Compare the variance of the per‑step group advantage (should be higher with dynamic sampling) and track the moving average of the completeness reward (should increase faster with dynamic sampling, per Figure 5).

## Open Questions the Paper Calls Out
1. **How to improve automatic evaluation of caption completeness/correctness beyond coarse query‑answering?**  
   **Basis in paper:** [explicit] Conclusion: “refine our evaluation metrics … more nuanced indicators.”  
   **Why unresolved:** Current MLLM‑judge metrics are biased and miss subtle errors.  
   **What evidence would resolve it:** Human‑annotated fine‑grained benchmarks; new metrics validated against them.

2. **What is the impact of diversity threshold \( \tau \) on dynamic query sampling’s efficiency and performance?**  
   **Basis in paper:** [inferred] Algorithm 1 uses \( \tau=0.1 \) without exploration.  
   **Why unresolved:** \( \tau \) controls trade‑off between query diversity and training speed; optimal value unknown.  
   **What evidence would resolve it:** Systematic study varying \( \tau \), measuring convergence speed and final scores.

3. **How should the completeness‑correctness trade‑off weight \( \alpha \) be set for different domains/model sizes?**  
   **Basis in paper:** [inferred] Fixed \( \alpha=0.05 \) due to sparse hallucinations; no tuning.  
   **Why unresolved:** \( \alpha \) may need adaptation; imbalance could harm either completeness or correctness.  
   **What evidence would resolve it:** Grid search over \( \alpha \) across datasets and model scales, report Pareto curves.

## Limitations
- Sub‑caption decomposition algorithm (prompt/template) is undisclosed; this risks reward signal variance and makes exact replication difficult.
- Dynamic query sampling update details (time window, normalization) are vague; an incorrect implementation could nullify its reported efficiency gains.
- Reliance on frozen third‑party MLLMs as judges introduces opaque biases; if these judges hallucinate or have blind spots, reward signals may not align with true human judgment of completeness/correctness.

## Confidence
- Dual‑reward mechanism (improved metrics): Medium.
- Dynamic query sampling (faster convergence): Low.
- CCaption‑44k dataset efficacy (diversity filter): High.

## Next Checks
1. **Sub‑caption quality audit:** For 100 generated captions, manually inspect the sub‑queries produced by the decomposition method. Compute the proportion that are (a) atomic, (b) disjoint, and (c) exhaustive relative to the original caption. A low atomicity rate (<80%) would invalidate the correctness reward’s premise.
2. **Judge sensitivity ablation:** Retrain a tiny model (e.g., 1k steps) using three different judge MLLMs for \( R_{corr} \) (e.g., GPT‑4o, Claude‑3.5‑Sonnet, a smaller open‑source model). If final hallucination scores (on HallusionBench) vary by more than ±5 absolute points, the method is critically sensitive to judge choice.
3. **Dynamic sampler stability test:** Run training for 100 steps with the dynamic query sampler disabled (uniform query sampling). Track the per‑step group advantage variance. If the variance with dynamic sampling is not consistently and significantly higher (>20% on average), the claimed gradient efficiency benefit is unsupported.
