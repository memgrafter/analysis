# SimRPD: Optimizing Recruitment Proactive Dialogue Agents through Simulator-Based Data Evaluation and Selection

## Quick Facts
- arXiv ID: 2601.02871
- Source URL: https://arxiv.org/abs/2601.02871
- Reference count: 40
- Primary result: SimRPD achieved 15.8% relative improvement in contact acquisition rate (3.8%→4.4%) while increasing average dialogue turns by 36.4% in real-world deployment with 50,000 candidates.

## Executive Summary
SimRPD is a three-stage framework for training recruitment proactive dialogue agents in data-scarce environments. It first trains a high-fidelity user simulator via SFT and RL to generate large-scale dialogues. Second, a dual-level Chain-of-Intention (CoI) evaluation filters synthetic data using global distribution metrics (KL/JS divergence, question diversity) and instance-level metrics (style similarity, result consistency, route consistency). Third, the agent is fine-tuned on the curated dataset using SFT and PPO with a hybrid safety and preference reward. Deployed with 50k candidates, SimRPD improved contact acquisition by 15.8% relative and increased average turns by 36.4%. Human evaluations show the lowest error rate (14.2%) among baselines.

## Method Summary
The method comprises: (1) **User Simulator Training**: A base LLM (e.g., Qwen3-8B) is fine-tuned on real `(profile, context, response)` triples via SFT, then further optimized with PPO using rewards that penalize repetition, encourage appropriate length, and align actions with real rejection patterns to boost diversity. (2) **Synthetic Data Generation & Selection**: The simulator interacts with a seed policy to produce multi-turn dialogues. Each turn is labeled with an intent category. A CoI matrix captures intent transitions. Global metrics (KL/JS divergence between CoI distributions, question diversity entropy) measure population-level alignment with real dialogues; instance metrics (style similarity via LLM judge, result consistency F1, route consistency via graph isomorphism) filter individual dialogues. A ranking plus Monte Carlo/greedy backward elimination yields a high-quality subset (e.g., 1k dialogues). (3) **Agent Training**: The selected dialogues are decomposed into `(context, agent_response)` pairs. The agent undergoes SFT for style imitation, then PPO with a hybrid reward comprising rule-based safety penalties and a learned preference model reward, optimizing long-term contact acquisition. The pipeline iterates as real deployment data becomes available.

## Key Results
- Relative improvement in contact acquisition rate: **15.8%** (from 3.8% to 4.4%) in an online A/B test with 50,000 candidates; average dialogue turns increased by **36.4%**.
- The simulator reduced distributional divergence (KL: 1.702) compared to a strong baseline (Qwen3-max: 2.301).
- Human evaluation: **14.2% average error rate**—the lowest among all baselines—with notable gains in user experience and reduced timing/logic errors.

## Why This Works (Mechanism)
**Mechanism 1: High-Fidelity Simulator via SFT+RL**  
A user simulator trained with SFT on real dialogues absorbs domain style and terminology. Subsequent RL fine-tuning with rewards that penalize repetitive loops, control response length, and encourage appropriate actions (e.g., rejections) steers the model toward diverse, realistic candidate behaviors. This two-stage process mitigates sycophancy and yields a simulator whose output distribution closely matches real interactions, as measured by lower KL/JS divergence. Evidence: Section 3.2 details the training; Section 4.2 shows quantitative improvements.

**Mechanism 2: Dual-Level CoI Data Filtering**  
The Chain-of-Intention framework operates at two levels. Globally, it compares the intent transition distribution (flattened CoI matrix) and question diversity entropy between synthetic and real data, ensuring the selected pool reflects the statistical properties of authentic recruitment dialogues. At the instance level, each synthetic dialogue is scored for style similarity (LLM judge), result consistency (outcome alignment F1), and route consistency (intent path validity within a real-world intent graph). Rank-based selection followed by Monte Carlo/greedy backward elimination balances these metrics, producing a dataset that is both statistically aligned and individually sound. Evidenced by human expert evaluation: the full SimRPD selection achieves the lowest error rate (14.2%), and ablations confirm the complementary roles of global and instance metrics.

**Mechanism 3: Agent Training with SFT+PPO and Hybrid Rewards**  
The agent is first fine-tuned on curated `(context, response)` pairs to master domain-specific responses. Then PPO optimizes a per-turn reward that combines rule-based safety constraints (e.g., no toxicity, repetition, privacy breaches) and a learned preference model score. This hybrid reward guides the policy toward acquiring contact information while preserving user experience and safety. The reinforcement stage enables the agent to plan multi-turn strategies in a partially observable environment, as reflected in the 15.8% acquisition gain.

## Architecture Onboarding
**Component Map**  
User Simulator (SFT+RL) -> Data Synthesis & Selection (Dual-Level CoI Evaluator) -> RPD Agent (SFT+PPO) -> Deployment

**Critical Path**  
1. Collect and annotate real recruitment dialogues with intent labels.  
2. Train user simulator: SFT on real (profile, context, response) pairs, then RL with diversity-focused rewards.  
3. Generate large-scale synthetic dialogues using the simulator.  
4. Apply CoI evaluation: compute global metrics (KL/JS, question diversity) and instance metrics (style, result F1, route consistency).  
5. Select a high-quality subset via ranking and iterative optimization.  
6. Train RPD agent: SFT on selected data, then PPO with hybrid safety+preference reward.  
7. Run online A/B tests, measure contact acquisition and dialogue turns.  
8. Iterate using production data.

**Design Tradeoffs**  
- *Quality vs. quantity*: Tight filtering improves per-sample quality but may reduce diversity; metric weights control this balance.  
- *Global vs. instance metrics*: Global metrics require a reliable reference set; in cold-start, only instance metrics may lead to distributional drift.  
- *Simulator fidelity vs. diversity*: Overemphasizing diversity (via RL) can degrade linguistic quality; λ hyperparameters tune the tradeoff.  
- *PPO stability*: Long dialogue horizons challenge credit assignment; single-turn updates help but may lose long-term dependencies.

**Failure Signatures**  
- Elevated KL/JS divergence between synthetic and real intent distributions.  
- Low question diversity or high repetition in simulator outputs.  
- Human evaluation error rates (hallucination, timing/logic) above 20% (as in Raw Pool baseline).  
- Online: contact acquisition rate lower than baseline or excessive turn increase without conversion gain.  
- PPO training instability (high reward variance, policy collapse).

**First 3 Experiments**  
1. *Simulator Fidelity Test*: Compare SFT-only vs. SFT+RL simulators using global and instance metrics on a held-out real set.  
2. *Data Selection Quality*: Conduct human expert evaluation on 300 scenarios, measuring error rates for hallucination, user experience, and timing/logic across baseline selection methods and SimRPD variants (with/without global/instance components).  
3. *Deployment Impact*: Run an online A/B test with ~50k candidates comparing the agent trained on SimRPD-curated data against production baseline, reporting contact acquisition rate and average dialogue turns.

## Open Questions the Paper Calls Out
**Open Question 1: Cross-Domain Generalization**  
*Question*: How can SimRPD be generalized to other business dialogue domains without heavy customization?  
*Basis*: The CoI graph and profile conditioning are deeply recruitment-specific, requiring substantial engineering for new domains.  
*Why unresolved*: Transferring the pipeline would need domain-specific intent transition extraction and profile schemas.  
*Evidence to resolve*: Apply SimRPD to a different domain (e.g., customer support) with automatic intent extraction and evaluate agent success and simulator fidelity.

**Open Question 2: Capturing Irrational and Emotional Behaviors**  
*Question*: Can user simulators better capture irrational, sarcastic, or emotionally volatile behaviors?  
*Basis*: LLM simulators struggle with irrationality and emotional shifts, leaving agents unprepared for long-tail scenarios.  
*Why unresolved*: Current RL rewards target diversity but not complex emotional dynamics or sarcasm.  
*Evidence to resolve*: Incorporate emotion modeling or adversarial objectives using real dialogues exhibiting such behaviors; assess agent robustness on similar real-user tests.

**Open Question 3: Cold-Start Data Selection**  
*Question*: How to perform data selection when no reference distribution exists?  
*Basis*: The framework depends on a Golden Reference Set for global metrics, limiting applicability without historical data.  
*Why unresolved*: KL/JS divergence cannot be computed without reference; no alternative method proposed.  
*Evidence to resolve*: Propose unsupervised or few-shot alternatives (e.g., cluster entropy, self-consistency); evaluate downstream agent performance on real deployment metrics.

**Open Question 4: CoI Metrics as Simulator Rewards**  
*Question*: Can Chain-of-Intention metrics serve as reward signals for self-evolving simulators?  
*Basis*: The conclusion suggests future work exploring using evaluation metrics as direct rewards.  
*Why unresolved*: Currently metrics are only used for data filtering; their effectiveness as RL rewards for the simulator is unknown.  
*Evidence to resolve*: Integrate CoI metrics as RL rewards for the simulator and compare agent performance against the current SFT+RL training.

## Limitations
- Missing RL hyperparameters (λ weights, PPO clip ε, learning rates) hinder exact replication of the simulator.
- Underspecified intent graph construction and graph isomorphism algorithm impede reproducibility of route consistency checks.
- Unclear reward model training protocol (pairwise vs. absolute comparisons, expert criteria) risks alignment ambiguity.
- The approach relies on a reference real dataset for global metrics, limiting cold-start scenarios.
- Evaluation is confined to a single recruitment domain; generalizability to other business dialogues remains unproven.

- Simulator fidelity through SFT+RL: **Medium**
- Dual-level CoI filtering effectiveness: **Medium**
- Agent performance gains (15.8% acquisition increase): **High**
