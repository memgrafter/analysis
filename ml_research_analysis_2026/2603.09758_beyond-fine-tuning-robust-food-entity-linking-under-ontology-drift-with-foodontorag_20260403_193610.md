# Beyond Fine-Tuning: Robust Food Entity Linking under Ontology Drift with FoodOntoRAG

## Quick Facts
- **arXiv ID:** 2603.09758
- **Source URL:** https://arxiv.org/abs/2603.09758
- **Reference count:** 26
- **Primary result:** Achieves 90.7% accuracy on Open Food Facts branded ingredients (vs. FoodSEM's 36.9%) and 97% accuracy after re-evaluation on CafeteriaFCD accounting for ontology drift, without model fine-tuning.

## Executive Summary
Food entity linking—mapping food terms to ontology concepts—suffers from **ontology drift**, where evolving knowledge bases render fine-tuned models obsolete. This paper introduces **FoodOntoRAG**, a retrieval-augmented generation (RAG) pipeline that avoids fine-tuning by combining hybrid lexical-semantic retrieval from the FoodOn ontology, an LLM-based selector with rationale, a confidence scorer, and a synonym-based retry loop. The system is model- and ontology-agnostic, requiring only standard LLM APIs and vector indexes. Evaluated on two food datasets, it vastly outperforms a fine-tuned baseline (FoodSEM) and demonstrates robust accuracy even after adjusting for annotation inconsistencies and hierarchical drift.

## Method Summary
FoodOntoRAG processes a food mention by first retrieving candidate ontology concepts via a hybrid retriever: lexical BM25 (Whoosh) and semantic cosine search (FAISS) over FoodOn labels, synonyms, definitions, and relations. The top candidates (K_lex=15, K_sem=15) are fused and fed to an LLM selector, which chooses one CURIE using two rules—exact-match preference and specificity—and outputs a rationale. A separate LLM scorer assigns a confidence score; if below a threshold (τ≈0.6–0.7), a synonym generator proposes alternative query phrasings, and the pipeline retries once. The entire system uses off-the-shelf components (e.g., `all-MiniLM-L6-v2` embeddings, Gemini Flash Lite) and no task-specific training, with parameters tuned on a validation set.

## Key Results
- 90.7% accuracy on Open Food Facts branded ingredients, far exceeding FoodSEM's 36.9%.
- After ontology-aware re-evaluation on CafeteriaFCD, accuracy reaches ~97%, with most initial "errors" reclassified as valid hierarchical matches.
- Competitive performance without fine-tuning, with interpretable rationales and confidence scores.
- Retry loop triggered in 7.5%–11.7% of cases, yielding modest accuracy gains.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Hybrid lexical-semantic retrieval maximizes candidate recall while maintaining relevance.
- **Mechanism:** Combines BM25 over lexical fields (labels, synonyms, definitions) with dense vector search on the same facets; fuses results with exact-match promotion and deduplication, returning up to K_tot candidates.
- **Core assumption:** Lexical matching captures surface variations, while semantic similarity captures conceptual neighbors; their union improves coverage.
- **Evidence anchors:** [section 3.2] details two indexes (Whoosh, FAISS), fusion rules, parameters K_lex=15, K_sem=15; [corpus] FoodSEM uses fine-tuning, not hybrid retrieval.
- **Break condition:** If embedding model is not domain-adapted, semantic retrieval may miss synonyms; if K_tot is too small, true entity may be excluded.

### Mechanism 2
- **Claim:** LLM-based selector with rubric-guided disambiguation achieves precise linking without task-specific fine-tuning.
- **Mechanism:** The LLM is prompted with the user mention, enumerated candidate concepts (ID, label, synonyms, definition, relations), and two rules: exact-match preference and specificity; it outputs a chosen ID and rationale.
- **Core assumption:** Instruction-following LLMs can reason over structured evidence to identify the most appropriate ontology concept, even for unseen terms.
- **Evidence anchors:** [section 3.3] prompt template, rules, example (LEBANESE); [corpus] competitive vs fine-tuned models supports claim.
- **Break condition:** If the true entity is absent from retrieved candidates (retrieval failure), selector cannot recover; if LLM misinterprets rules or lacks food knowledge, it may choose incorrectly.

### Mechanism 3
- **Claim:** Confidence-scored feedback loop with synonym generator improves robustness by iteratively reformulating queries when initial linking is uncertain.
- **Mechanism:** Scorer evaluates selector's choice with a continuous confidence score; if below threshold τ, it triggers synonym generator to propose alternative phrasings based on failure reason; new queries re-enter hybrid retriever, pipeline repeats (one-hop max).
- **Core assumption:** Query reformulation can bridge lexical gaps, and confidence assessment reliably detects likely errors.
- **Evidence anchors:** [section 3.4 & 3.5] scorer rubric, synonym generator prompt, one-hop loop; [corpus] retry rate (7.5%–11.7%) and modest accuracy gains indicate loop helps but not always.
- **Break condition:** If correct concept not in ontology, or synonym generator produces irrelevant variations, loop may not recover; excessive retries increase latency.

## Architecture Onboarding

**Component map:**  
Pre-processor -> Hybrid Retriever -> Selector -> Scorer -> [if confidence < τ] Synonym Generator -> Loop Controller -> Output Serializer

**Critical path:**
1. User provides a food mention (optionally with context).
2. Hybrid retriever fetches top K_lex lexical and K_sem semantic candidates, fuses into a deduplicated list.
3. Selector consumes mention and candidate list, returns chosen ID and rationale.
4. Scorer evaluates choice; if confidence >= τ, pipeline terminates.
5. If confidence < τ, scorer provides failure reason; synonym generator creates alternative queries.
6. Loop controller augments query set with alternatives, repeats steps 2–4 (one retry only).
7. Final output serialized with metadata.

**Design tradeoffs:**
- Retrieval parameters (K_lex, K_sem): Larger K improves recall but increases LLM context/noise; defaults 15 each.
- LLM selection: Larger models (GPT-4) may improve accuracy but raise cost/latency; paper uses Gemini 2.5 Flash Lite.
- Confidence threshold τ: Lower values increase acceptance but risk false positives; higher values trigger more retries (cost) but improve precision; τ=0.6–0.7 optimal.
- Synonym generator diversity: More synonyms increase coverage but may cause semantic drift; one-hop limit and query check mitigate.
- Model-agnostic design: Using generic LLMs avoids fine-tuning but may underfit specific ontology patterns.

**Failure signatures:**
- Retry rate >10% suggests ambiguous mentions or weak retrieval.
- Low confidence scores (<0.5) clustered in specific categories (e.g., geographic adjectives) indicate edge cases.
- Gap between first-pass and final accuracy (>5%) indicates synonym loop effectiveness; small gap suggests loop overhead.
- High rate of "Model_Incorrect" in adjudication (Fig. 2) shows fundamental pipeline failures.
- Latency spikes when retries are triggered.

**First 3 experiments:**
1. **Retrieval parameter sweep:** Vary K_lex and K_sem (5, 10, 15, 20) on validation; measure Acc@1, retry rate, latency; identify Pareto frontier.
2. **LLM ablation:** Replace LLM backbone for selector/scorer/generator (e.g., GPT-4, Claude, Llama-3); assess accuracy delta and cost/latency; test prompt variations (e.g., removing specificity rule).
3. **Threshold calibration:** Run pipeline with τ from 0.3 to 0.9; plot accuracy vs retry rate; choose operating point meeting precision requirements (e.g., 95%) while minimizing retries.

## Open Questions the Paper Calls Out
- **Which text embedding models maximize retrieval effectiveness?** Paper notes embedding model selection significantly affects quality and suggests exploring larger or domain-specific models, but no comparative analysis is provided.
- **What are optimal hyperparameters (K_lex, K_sem) for hybrid retrieval?** Defaults (15 each) are heuristic; trade-offs between accuracy, latency, and drift resilience across evolving ontologies are unexplored.
- **How can FoodOntoRAG be modularly extended to non-food domains?** Claims ontology-agnosticism, but validation only on FoodOn; cross-domain challenges (e.g., ChEBI, DrugBank) may break assumptions.
- **What evaluation protocols accurately reflect semantic correctness under ontology drift?** Standard Acc@1 penalizes valid hierarchical alternatives; an ontology-aware rubric accounting for drift and annotation noise is needed.

## Limitations
- Dependence on unreported LLM prompt details and API parameters (temperature, etc.), which may significantly affect behavior.
- Opacity in the ontology drift re-evaluation process for CafeteriaFCD; the 97% figure hinges on an unclear adjudication methodology.
- Limited evidence for general robustness to ontology drift; assessment is retrospective on one dataset, not a prospective stress test across ontology versions.

## Confidence
- **Claim:** Hybrid lexical-semantic retrieval design is fully specified and conventional. **Confidence:** High.
- **Claim:** Performance superiority over FoodSEM (90.7% vs 36.9%) is clearly reported. **Confidence:** Medium (depends on dataset splits and ontology versions not fully controlled for drift).
- **Claim:** Robustness to ontology drift as a general property. **Confidence:** Low (evidence is retrospective re-evaluation on one dataset, not prospective stress tests).
