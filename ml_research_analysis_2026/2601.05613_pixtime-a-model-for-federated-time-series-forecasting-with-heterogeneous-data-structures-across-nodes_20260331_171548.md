# PiXTime: A Model for Federated Time Series Forecasting with Heterogeneous Data Structures Across Nodes

## Quick Facts
- **arXiv ID**: 2601.05613
- **Source URL**: https://arxiv.org/abs/2601.05613
- **Reference count**: 9
- **Primary result**: PiXTime reduces mean squared error by 28.24% (federated) and 15.74% (non-federated) compared to DLinear across eight datasets.

## Executive Summary
PiXTime addresses federated time series forecasting where nodes have different sampling rates and variable sets. It introduces a personalized Patch Embedding to align multi-granularity series into uniform tokens and a global Variable Embedding Table to synchronize variable semantics. A shared transformer encoder-decoder with cross-attention fuses auxiliary information into the target forecast. Evaluated on eight datasets, PiXTime achieves substantial MSE reductions over DLinear (28.24% in federated, 15.74% in non-federated settings) and ablation studies confirm the contribution of each component. The design enables privacy-preserving knowledge sharing while respecting structural heterogeneity.

## Method Summary
In the federated setup, each node *i* holds a target series *x*<sub>*i*</sub> (length *T*<sub>*i*</sub>) and auxiliary series *Z*<sub>*i*</sub> (shape *T*<sub>*i*</sub> × *C*<sub>*i*</sub>), where *T*<sub>*i*</sub> and *C*<sub>*i*</sub> vary across nodes. PiXTime decouples local and shared parameters. Locally, a **Personalized Patch Embedding** splits *x*<sub>*i*</sub> into non-overlapping patches of equal physical duration (e.g., 1 hour); the samples per patch *PL*<sub>*i*</sub> differ by sampling rate. A linear layer projects each patch to dimension *D*, yielding token sequence *P*<sub>*i*</sub> of length *M*<sub>*i*</sub> = *T*<sub>*i*</sub>/*PL*<sub>*i*</sub>. A learnable abstract token *a*<sub>*i*</sub> is prepended. Shared modules include a **global Variable Embedding (VE) Table** (embeddings for all variable categories) and a transformer-based **Auxiliary Encoder** and **Target Decoder**. For auxiliaries, each node retrieves category embeddings from the VE Table and adds them to variable-wise linear projections to form *Vaux*<sub>*i*</sub>, which the Auxiliary Encoder processes. The Target Decoder takes [*a*<sub>*i*</sub>, *P*<sub>*i*</sub>]; in each layer, self-attention is followed by cross-attention where *a*<sub>*i*</sub> queries the encoded auxiliary representations. The decoder output *P*<sub>*i*</sub><sup>*L*</sup> is projected by a **local Projection Head** to the node-specific forecast length *S*<sub>*i*</sub>. During federated training (e.g., FedOPT), only shared modules (VE Table, Auxiliary Encoder, Target Decoder) are aggregated; local modules remain untouched, enabling personalization for structural heterogeneity.

## Key Results
- PiXTime reduces mean squared error by 28.24% over DLinear in federated settings.
- In non-federated settings, it reduces MSE by 15.74%.
- Ablation studies confirm the necessity of personalized Patch Embedding, VE Table, and cross-attention.

## Why This Works (Mechanism)
PiXTime’s success relies on three mechanisms:

1. **Personalized Patch Embedding** handles heterogeneous sampling rates by converting node-specific series into uniform-dimensional tokens. Patches cover the same physical interval across nodes; a linear layer maps variable-length patches (different *PL*<sub>*i*</sub>) to fixed *D*. *Assumption*: patches over identical physical intervals are semantically comparable. *Failure*: misaligned physical timestamps or non-integer patch boundaries distort alignment.

2. **Global Variable Embedding Table** aligns variable semantics. A shared table stores embeddings per category; nodes retrieve embeddings for their auxiliary variables and add them to projections. Federated averaging synchronizes the table. *Assumption*: same-named variables share meaning; aggregation yields universally useful embeddings. *Failure*: inconsistent labeling or a large number of categories causes bias and communication overhead.

3. **Cross-Attention Bridge** transfers auxiliary information to the target. The abstract token *a*<sub>*i*</sub> (prepended to target tokens) queries the encoded auxiliary representations in cross-attention, aggregating variable-wise context that influences patch tokens. *Assumption*: *a*<sub>*i*</sub> can effectively capture relevant auxiliary signals. *Failure*: uninformative or noisy auxiliaries may degrade performance.

## Architecture Onboarding
**Component map** (data flow):
Target: *x*<sub>*i*</sub> → Patch Embedding → *P*<sub>*i*</sub> + *a*<sub>*i*</sub> → Target Decoder (cross‑attention with auxiliary) → *P*<sub>*i*</sub><sup>*L*</sup> → Projection Head → forecast.
Auxiliary: *Z*<sub>*i*</sub> → VE Table + Linear → *Vaux*<sub>*i*</sub> → Auxiliary Encoder → *Vaux*<sub>*i*</sub><sup>*L*</sup> (provides K/V to cross‑attention).

**Critical path**:
1. Input target *x*<sub>*i*</sub> and auxiliary *Z*<sub>*i*</sub>.
2. Patch Embedding: split *x*<sub>*i*</sub> into patches, project to *D*-dim tokens *P*<sub>*i*</sub>, prepend abstract token *a*<sub>*i*</sub>.
3. Variable Embedding: retrieve VE Table embeddings for *Z*<sub>*i*</sub>’s categories, add to variable projections → *Vaux*<sub>*i*</sub>.
4. Auxiliary Encoder: process *Vaux*<sub>*i*</sub> through *L* self‑attention/FFN layers → *Vaux*<sub>*i*</sub><sup>*L*</sup>.
5. Target Decoder: process [*a*<sub>*i*</sub>, *P*<sub>*i*</sub>] through *L* layers; each layer: self‑attention on [*a*<sub>*i*</sub>, *P*<sub>*i*</sub>], then cross‑attention (*a*<sub>*i*</sub> as query, *Vaux*<sub>*i*</sub><sup>*L*</sup> as K/V), then FFN.
6. Projection Head: map each token in *P*<sub>*i*</sub><sup>*L*</sup> to scalar predictions of length *S*<sub>*i*</sub>.

**Design tradeoffs**:
- Personalization cost: Local modules (Patch Embedding, Projection Head) are not shared, requiring independent training per node and reducing data efficiency.
- VE Table scalability: Communication cost grows with the number of unique variable categories; large *n*<sub>all</sub> (e.g., 862 in Traffic) increases per‑round overhead.
- Sequence length variability: Decoder must handle varying *M*<sub>*i*</sub>+1 due to different *T*<sub>*i*</sub> and *PL*<sub>*i*</sub>, impacting batch efficiency.
- Abstract token locality: *a*<sub>*i*</sub> is local, preventing transfer of aggregation knowledge but allowing node‑specific adaptation.

**Failure signatures**:
- Patch Embedding failure: Inconsistent token dimensions or misaligned physical timestamps across nodes.
- VE Table divergence: Embeddings for the same variable drift apart (check cosine similarity).
- Cross‑attention noise: Ablations removing cross‑attention show no performance drop, indicating ineffective information transfer.
- Federated instability: Shared modules fail to converge or training loss fluctuates heavily across rounds.

**First 3 experiments**:
1. **Patch alignment unit test**: On synthetic data with sampling rates 15‑min and hourly, set physical patch duration to 1 hour. Verify that token index *k* covers identical physical timestamps across nodes; compute *PL*<sub>*i*</sub> = (sampling rate<sub>*i*</sub>) / (1 hour).
2. **VE Table synchronization test**: Initialize two nodes with overlapping variable categories. After one FedAvg step, confirm embeddings for shared categories are identical (within numerical precision).
3. **Federated vs. local ablation**: Split ETTh1 into nodes by sampling rate (hourly vs. 15‑min). Train PiXTime with federation vs. isolated local training; expect federation to improve both nodes’ performance, demonstrating knowledge transfer.

## Open Questions the Paper Calls Out
1. **Variable category alignment**: How to consistently align variable semantics when auxiliary sets are heterogeneous and naming may be ambiguous (e.g., "temp" vs. "temperature")? VE Table provides a mechanism but does not address canonicalization or emerging categories. *Evidence needed*: Experiments with ambiguous mappings, measuring impact of external knowledge graphs or contrastive learning on embeddings.
2. **Patch alignment under extreme granularity mismatch**: What are theoretical limits of Patch Embedding when sampling rate ratios are non‑integer or physical intervals misalign? The paper assumes non‑overlapping segmentation on a fixed physical interval but does not analyze error from non‑multiples or irregular sampling. *Evidence needed*: Analytical bounds on representation error vs. sampling rate ratios; experiments with simulated non‑integer ratios and irregular data.
3. **Scalability of VE Table**: Does VE Table become a bottleneck when *n*<sub>all</sub> is very large (e.g., tens of thousands)? Communication cost of aggregating a huge table each round may be prohibitive; no compression or hierarchical strategies are discussed. *Evidence needed*: Scaling experiments varying *n*<sub>all</sub>, measuring communication overhead and convergence; testing quantization or category clustering.
4. **Sensitivity to target distribution heterogeneity**: How does PiXTime handle statistical heterogeneity in target distributions (means/variances) separate from structural heterogeneity? Focus is on structural issues; experiments show fluctuations possibly due to target shifts. *Evidence needed*: Controlled experiments with identical structural settings but different target distributions (e.g., scaling), comparing PiXTime with FedProx/SCAFFOLD.
5. **Extension to different target variables**: Can PiXTime support multi‑task federated learning where nodes forecast different targets? Current formulation assumes a common target. *Evidence needed*: Design a variant with unique targets per node but shared auxiliaries; evaluate on multi‑target datasets (e.g., multiple traffic flows).

## Limitations
- **Hyperparameter opacity**: Model dimension *D*, number of layers *L*, and federated hyperparameters (rounds, local epochs, FedOPT specifics) are unspecified, hindering exact replication.
- **Ambiguities in design**: The physical patch duration definition and variable category mapping process are unclear, risking misalignment in practice.
- **Limited external validation**: The paper reports only self‑experiments; no independent replications or citations indicate low community scrutiny.

## Confidence
- **Personalized Patch Embedding**: Medium (mechanism is clear but lacks validation under extreme heterogeneity).
- **Global Variable Embedding Table**: Medium (novel but scalability and labeling robustness unproven).
- **Cross‑Attention Bridge**: Low (support limited to internal ablations; risk of noise).

## Next Checks
