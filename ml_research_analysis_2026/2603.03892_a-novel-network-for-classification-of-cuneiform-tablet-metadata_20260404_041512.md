# A novel network for classification of cuneiform tablet metadata

## Quick Facts
- **arXiv ID:** 2603.03892  
- **Source URL:** https://arxiv.org/abs/2603.03892  
- **Reference count:** 0  
- **Primary result:** Achieves 0.99 F1 on period classification and 98.5% accuracy on orientation task, outperforming Point-BERT.

## Executive Summary
This paper introduces a convolution-inspired network for classifying cuneiform tablet metadata from high-resolution 3D point clouds. The architecture progressively downsamples the point cloud while integrating local spatial neighbor information, and finally applies a feature-space neighbor layer at the coarsest scale to inject global context. Without any external pretraining, it consistently outperforms the transformer-based Point-BERT: 0.99 vs. 0.93 F1 on period classification, 100% accuracy on seal presence detection, and 98.5% vs. 77% on a new tablet front orientation task (where it also uncovers a labeling error). The method is designed for memory efficiency and strong performance even with limited training data (~300–700 tablets).

## Method Summary
Input consists of 32,768 points with 6 dimensions (XYZ + normals). The backbone features five spatial downsampling stages (PointNet++-style) that halve the point count per stage and apply specialized convolution-like operators: LocalEdgeConv, EdgeVertexConv, and VertexConv (with dilation in stages 3–4). After reaching 1,024 points, a final EdgeConv layer computes k‑NN in feature space to capture global relationships. Features from all six stages are concatenated, passed through a 1D convolution (1024→1024 channels), globally max‑pooled, and fed to an MLP classifier (512→128→num classes). Training uses Focal Loss for class imbalance, jitter augmentation, SGD with cosine annealing (lr=0.001), dropout 0.6, and batch size 10 for 300 epochs. The Point-BERT baseline uses ULIP‑2 pretrained weights (frozen), a DGCNN head, and 8192‑point inputs.

## Key Results
- Period classification: **0.99 F1** vs. 0.93 for Point-BERT on 747 tablets.  
- Seal presence detection: **100% accuracy**.  
- Tablet front orientation: **98.5% accuracy**, revealing an erroneous label, versus 77% for Point-BERT.

## Why This Works (Mechanism)
### Progressive spatial downsampling with integrated local neighbor features
The network adopts a PointNet++‑style pyramid, halving the point count at each layer and applying convolution‑like operators (LocalEdgeConv, VertexConv) that aggregate features from fixed‑radius spatial neighbors. This mimics 2D CNN locality while expanding the receptive field hierarchically, preserving geometric patterns (e.g., wedge shapes, curvature) essential for metadata prediction. Evidence: The abstract describes a “convolution‑inspired architecture that gradually down‑scales the point cloud while integrating local neighbor information”; Section 3.1 details the down‑scaling and neighbor computation. Break condition: if ultra‑fine details were critical, halving would degrade performance; but results show even 8192‑point input outperforms Point‑BERT, indicating hierarchical features capture the essential patterns.

### Feature‑space neighbor computation only at coarse scale
After downsampling to 1,024 points, an EdgeConv layer computes k‑NN in feature space, allowing each coarse point to integrate information from all others. This efficiently injects global context without the quadratic memory cost of full‑resolution dynamic graphs. The core assumption is that global shape cues (e.g., tablet orientation, overall curvature) are sufficiently captured at this abstraction. Evidence: Abstract mentions “final down‑scaled point cloud is then processed by computing neighbors in the feature space to include global information”; Section 3.2 explains that at 1,024 points the distance matrix is manageable. Break condition: if relationships between distant local signs were critical, the coarse abstraction might lose them; the orientation success suggests otherwise.

### Structured convolutions reduce overfitting on limited data
The method uses parameter‑sharing (1D convs) and spatially constrained operators, reducing model capacity relative to transformer‑based Point‑BERT. This strong inductive bias aligns with local geometric invariances and requires less data to generalize. Evidence: Abstract states “CNN‑like structures demonstrate better performance than transformer based models when limited training data is available”; Section 3.4 shows a larger gap on the smallest split (337 tablets: 0.96 vs. 0.89 F1). Break condition: if training data grew by an order of magnitude, transformers might close the gap; the paper recommends retraining Point‑BERT from scratch as future work.

## Foundational Learning
- **Point cloud unorderedness & PointNet max‑pooling**  
  Point clouds are unordered sets; PointNet uses a symmetric function (max pooling) to achieve permutation invariance. *Why needed*: The architecture builds on max pooling after neighbor aggregation to handle unordered points. *Quick check*: Why can’t we apply a standard 2D CNN directly to a point cloud, and how does max pooling solve the core issue?

- **Hierarchical receptive field expansion (PointNet++)**  
  Recursively grouping points into local spheres increases context and receptive field. *Why needed*: The pyramid downsampling relies on such grouping to create a convolutional hierarchy. *Quick check*: How does recursively grouping points into local clusters expand the receptive field compared to a single‑layer PointNet?

- **Transformer pretraining dependency**  
  Transformers often require large‑scale pretraining to generalize. *Why needed*: The paper contrasts its no‑pretraining approach with Point‑BERT’s reliance on ULIP‑2, highlighting data efficiency. *Quick check*: Why does Point‑BERT require frozen ULIP‑2 weights for good performance on cuneiform data, while the proposed method does not use any external pretraining?

## Architecture Onboarding
**Component map**  
Input (32,768 points × 6D) → Stage 1: LocalEdgeConv → Subsample to 16,384 → Stage 2: EdgeVertexConv → Subsample to 8,192 → Stage 3: VertexConv (dilated) → Subsample to 4,096 → Stage 4: VertexConv (dilated) → Subsample to 2,048 → Stage 5: VertexConv → Subsample to 1,024 → Stage 6: EdgeConv (feature‑space neighbors) → Concatenate features from all stages → 1D Conv (1024→1024) → MaxPool → MLP (512→128→num classes)

**Critical path**  
The spatial pyramid (stages 1‑5) builds multi‑scale features; stage 6 adds global context via feature‑space neighbors; concatenation and a 1D convolution fuse scales; global max‑pooling yields a descriptor for classification.

**Design tradeoffs**
- *Memory vs. resolution*: Downsampling reduces memory but risks losing fine details; 32,768 points improve over 8,192, while Point‑BERT fails with more points due to fixed pretraining.
- *Spatial vs. feature‑space neighbors*: Spatial neighbors are cheap but less semantic; feature‑space neighbors are expensive but capture high‑level relationships. Design limits expensive ops to the coarsest layer.
- *Inductive bias vs. flexibility*: Structured convolutions reduce parameters and overfitting but may miss long‑range dependencies; transformers capture global patterns but need vast data.

**Failure signatures**
- Overfitting: high training accuracy but low test accuracy, especially on small splits (337 tablets). Mitigated by dropout (0.6) and jitter.
- Orientation task failure: near 50% accuracy if the global context layer (stage 6) is ineffective.
- Point‑count sensitivity: performance drops sharply when reducing points; the proposed method is more robust.

## Open Questions the Paper Calls Out
