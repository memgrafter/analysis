# LifeSim: Long-Horizon User Life Simulator for Personalized Assistant Evaluation

## Quick Facts

- **arXiv ID:** 2603.12152  
- **Source URL:** https://arxiv.org/abs/2603.12152  
- **Reference count:** 40  
- **Primary result:** LifeSim introduces a BDI-grounded, environment-aware user simulator and a 1,200-scenario benchmark, revealing that LLMs excel at explicit intentions but struggle with implicit intentions and long-term preference modeling.

## Executive Summary

This paper presents LifeSim, a user simulator that models cognition via the Belief-Desire-Intention (BDI) framework within physical environments to generate coherent, long-horizon life trajectories and intention-driven dialogues. Building on LifeSim, the authors construct LifeSim-Eval, a benchmark with 1,200 scenarios across eight life domains that evaluates personalized assistants on explicit/implicit intention handling, user profile recovery, and response quality. Evaluations of over ten LLMs show strong performance on explicit intentions but significant limitations on implicit intentions and long-term preference modeling, with performance degrading as dialogue history grows. The framework provides a cognitively grounded, environment-aware testbed for advancing personalized assistant evaluation.

## Method Summary

LifeSim integrates three core engines. The BDI Cognitive Engine constructs a user’s short-term belief from long-term profile and current physical environment (time, location, weather), retrieves candidate desires from a pool, reranks them for logical consistency, and samples an intention. The BDI-Grounded Event Engine triggers events based on time intervals, then refines event details to align the intention with the spatiotemporal context. The User Behavior Engine processes assistant replies, storing informative parts in memory, inferring emotional state, deciding to continue or end the conversation, and generating the next user utterance conditioned on the original intent, memory, and emotion. Real-world mobility trajectories (Foursquare) ground the environment, while a desire pool of 113,501 event–desire pairs from human-AI conversations provides behavioral diversity. LifeSim-Eval uses this simulator to generate 1,200 scenarios (120 users × 10 events) across eight WHOQOL-based domains, evaluating models via LLM-as-Judge with metrics for intention completion, response quality, and user modeling.

## Key Results

- LLMs achieve strong performance on explicit user intentions but significant gaps on implicit intentions.
- Long-horizon preference modeling is challenging; performance degrades as dialogue history grows.
- The LifeSim-Eval benchmark effectively exposes weaknesses in current personalized assistants, particularly in maintaining persona consistency and inferring unstated needs.

## Why This Works (Mechanism)

### Mechanism 1: BDI-Environment Integration for Coherent Trajectory Generation
**Claim:** LifeSim generates coherent, personalized user life trajectories by integrating a cognitively grounded BDI model with a physically grounded event engine.  
**Mechanism:** The BDI-Based Cognitive Engine constructs a user's short-term belief from long-term profile and current environment (Env). It retrieves candidate desires from a pool, reranks them for logical consistency with belief+Env, and samples an intention. The BDI-Grounded Event Engine then takes this intention, grounds it in the specific spatiotemporal context (time, location, weather from real mobility trajectories), and refines the event details to ensure realism.  
**Core assumption:** User intentions emerge from the joint function of internal cognitive states (beliefs/desires) and external situational constraints (B=f(P,Env)). A coherent life narrative requires intentions to be both psychologically plausible and physically plausible.  
**Evidence anchors:** Paper abstract mentions BDI modeling within physical environments; Section 2.1 details belief construction and desire reranking; Section 2.2 describes environmental grounding and refinement; Table 6 shows temporal rhythm fidelity.  
**Break condition:** If belief state (profile+recent events) is inconsistent with environmental context (e.g., user with a leg injury in a location with no medical facilities), reranking/refinement may fail to produce a plausible event-intention pair.

### Mechanism 2: Intention-Driven Multi-Turn Dialogue Behavior
**Claim:** The User Behavior Engine produces realistic, intention-driven multi-turn dialogues that reflect dynamic user states (memory, emotion) and evolve based on assistant responses.  
**Mechanism:** For each turn, the engine (1) perceives the assistant’s reply, storing informative parts as memory and checking for repetition/contradiction; (2) infers a pre-response emotional state (GoEmotions taxonomy); (3) selects an action (continue/end) based on intent completion; (4) generates the next user utterance conditioned on the original intent, memory perception, emotion, and action. This creates a feedback loop where assistant behavior influences future user states.  
**Core assumption:** Realistic user dialogue results from a sequential decision process influenced by prior history (memory), affective state (emotion), and goal persistence.  
**Evidence anchors:** Abstract mentions intention-driven interactive behaviors; Section 2.3 defines the four sequential stages; Table 3 reports validation scores (Intent Alignment >95%, Persona Consistency >92%) and ablation drops when memory or emotion modules are removed; cited work (e.g., AnnaAgent) supports emotion-chain reasoning.  
**Break condition:** If assistant responses are consistently irrelevant or contradictory, memory perception may trigger negative signals, emotion may default to frustration, causing premature termination or incoherent utterances that break persona consistency.

### Mechanism 3: Benchmark for Long-Horizon Personalization
**Claim:** LifeSim-Eval benchmarks personalized assistants on explicit/implicit intention handling and long-horizon preference modeling by leveraging the simulator to create controlled, diverse, and temporally consistent test scenarios.  
**Mechanism:** LifeSim generates 1,200 scenarios (8 domains, 120 users × 10 events). Each scenario defines an explicit intention and derives implicit intentions from profile/history. Evaluation uses multi-turn dialogues with LLM-as-Judge, measuring Intent Recognition/Completion, response quality (Naturalness, Coherence), and user modeling (Profile Recovery, Persona Alignment). The long-horizon setting tests preference consistency across sequences.  
**Core assumption:** A valid benchmark must simulate complexity of real-world user states (implicit needs) and test over extended interactions where preferences must be recalled and applied. Synthetic simulation grounded in cognitive models and real trajectories provides this at scale.  
**Evidence anchors:** Abstract describes multi-turn interactive assessment; Section 3 details benchmark construction; Section 4, Tables 2 & 3 show performance gaps on implicit intentions and degradation with longer history; Table 5 compares with prior long-term memory benchmarks.  
**Break condition:** If the underlying LifeSim simulator produces low-fidelity user behavior (inconsistent persona, implausible sequences), the benchmark scenarios lack realistic challenges. The paper’s validation (Table 3, Figure 7) mitigates this, but any flaw in BDI+environment grounding cascades to benchmark validity.

## Foundational Learning

- **BDI (Belief-Desire-Intention) Model**  
  *Why needed:* This cognitive architecture models how internal states lead to actionable intentions, enabling LifeSim to move beyond reactive query-response to goal-directed, coherent simulation.  
  *Quick check:* In LifeSim’s BDI implementation, how does the “Desire” component (a goal or objective) differ from the “Intention” (a specific plan of action)?

- **Spatiotemporal Grounding in User Simulation**  
  *Why needed:* LifeSim anchors events in real physical contexts (time, location, weather) from mobility trajectories, ensuring actions are constrained by environmental realism (e.g., jogging in rain vs. heat).  
  *Quick check:* Why is using real Foursquare trajectories for environment grounding necessary, and what would fail with synthetic trajectories (e.g., random time/location assignments)?

- **Implicit vs. Explicit Intention in Dialogue**  
  *Why needed:* The benchmark evaluates on implicit intentions—needs not directly stated but inferable from context/profile—testing deeper personalization and contextual reasoning beyond surface instruction following.  
  *Quick check:* In the “parenting & childcare” domain, give one example of an explicit intention and one corresponding implicit intention derived from a user’s profile (e.g., “need for reassurance”).

## Architecture Onboarding

**Component map (plain text):**  
User Profile Pool + Physical Environment Trajectories → BDI Cognitive Engine (construct Belief, retrieve/rerank Desires, sample Intention) → Event Engine (trigger via PE=f(ΔT), refine Event) → Behavior Engine (Memory Perception, Emotion Inference, Action Selection, Response Generation) → Life Trajectory (sequence of Event, Intention, Utterance). For benchmarking: scenarios with explicit/implicit intention checklists.

**Critical path:** Profile → Belief → Intention Sample → Event Grounding & Refinement → Turn-by-turn Dialogue Generation (with memory/emotion/action loop). Consistency constraints: Intention must align with Belief, Event must align with Intention+Env, Utterance must align with Intention+Emotion+Memory.

**Design tradeoffs:**  
- *Realism vs. Scalability:* Real mobility trajectories improve temporal/spatial realism but limit scalability; synthetic trajectories would scale but lose JSD fidelity.  
- *Implicit Intention Coverage:* Defining implicit intentions via LLM+human labeling is costly (1,200 scenarios); automated methods risk lower quality.  
- *Memory Mechanism:* A simple memory store balances cost and effectiveness; a more sophisticated vector-based memory could improve long-horizon consistency but increases complexity.

**Failure signatures:**  
- Rigid Reasoning: Assistant repeats suggestions despite user corrections (indicates failure to update belief or incorporate negative feedback).  
- Insufficient Proactive Inquiry: Assistant does not ask clarifying questions for underspecified implicit needs (action selection always chooses “continue with answer”).  
- Poor Persona Utilization: Assistant gives generic advice ignoring profile traits (persona attributes not effectively conditioned).  
- Temporal Incoherence: Event sequences with impossible timing (e.g., gym after midnight in a closed location) (event trigger or refinement failure).

**First 3 experiments (reproduction):**  
1. **BDI Coherence Validation:** Sample 100 generated event-intention pairs; have human evaluators rate whether the intention logically follows from the profile and whether the event is a plausible trigger in the environment. Target plausibility >90%.  
2. **Temporal Rhythm Fidelity:** Generate 500 trajectories; compute Jensen-Shannon Divergence of inter-event intervals and monthly frequency against real Foursquare data. Expect JSD <0.229.  
3. **Behavior Engine Human-AI Alignment:** Sample 150 dialogues from single-scenario setting; have three human annotators score Naturalness/Coherence (1–5). Compute Krippendorff’s α against LLM-as-Judge scores; target α ≥ 0.77.

## Open Questions the Paper Calls Out

1. **High-stakes domain extension:** How can LifeSim be extended to healthcare, legal, or finance while addressing domain-specific knowledge and ethical constraints? Authors note this limitation; resolution requires domain-specific profiles, event engines, and expert validation.  
2. **Multimodal signals:** How can visual or physiological data be incorporated to improve realism? Currently limited to textual interactions; solving this requires cross-modal alignment and ethical handling of such data.  
3. **Stable long-horizon reasoning:** Beyond simple memory, what mechanisms enable stable preference reasoning over prolonged interactions? Simple memory showed limited or negative benefits; need architectural innovations (e.g., preference graphs) or training paradigms.  
4. **Implicit intention inference:** How can LLMs be enhanced to better infer and satisfy implicit intentions in long-horizon, multi-scenario interactions? Current models show large gaps; evidence would be improved benchmark scores with new models or fine-tuning approaches.

## Limitations

- The BDI-environment integration lacks external validation; key details (e.g., event trigger ΔT scaling) are unspecified, and prompt configurations are incompletely described.  
- The behavior engine’s long-horizon consistency and emotion modeling remain unverified beyond short human evaluations.  
- LifeSim-Eval’s implicit intentions are LLM-generated without independent assessment, and evaluation depends on LLM-as-judge with potential bias.

## Confidence

- **High:** Behavior engine’s turn-level dialogue quality (supported by ablation studies and human evaluation, e.g., Intent Alignment >95%, Persona Consistency >92%).  
- **Medium:** BDI-driven event plausibility (internal validation only) and benchmark’s ability to expose model weaknesses (consistent results but judge-dependent).  
- **Low:** Generalizability to cultures/regions without Foursquare data and scalability of profile matching (Cosine similarity matching may not generalize).
