# From Muscle to Text with MyoText: sEMG to Text via Finger Classification and Transformer-Based Decoding

## Quick Facts
- **arXiv ID:** 2601.03098
- **Source URL:** https://arxiv.org/abs/2601.03098
- **Reference count:** 40
- **Primary result:** Achieves 85.4% finger classification accuracy, 5.4% character error rate (CER), and 6.5% word error rate (WER) on the emg2qwerty dataset (30 users).

## Executive Summary
MyoText is a framework for decoding text from surface electromyography (sEMG) signals without a physical keyboard. It addresses the challenge of mapping noisy muscle activation patterns to coherent sentences by decomposing the problem along physiological and linguistic hierarchies. The system first classifies which finger activated during each keystroke using a CNN-BiLSTM-Attention model on multichannel sEMG. It then leverages standard QWERTY touch-typing ergonomics to map each finger to a small set of candidate letters. Finally, a fine-tuned T5 transformer selects the most fluent sentence from the resulting candidate word pools, using contextual information to resolve ambiguities.

Evaluated on the emg2qwerty dataset with 30 users, MyoText achieves 85.4% finger classification accuracy, 5.4% character error rate (CER), and 6.5% word error rate (WER). These results significantly outperform direct letter classification (51.2% accuracy) and prior baselines. The modular design enables on-wrist computation for the finger classifier and off-device language modeling, demonstrating robust generalization across users and non-canonical typing patterns.

## Method Summary
MyoText employs a three-stage modular pipeline. First, it processes raw sEMG signals and keystroke logs to create aligned segments (1 second before/after each keypress) labeled with the corresponding finger according to a standard QWERTY mapping. Second, a CNN-BiLSTM-Attention model classifies each sEMG segment into one of eight finger classes. Third, the predicted finger sequence is converted into candidate letter sets using the fixed QWERTY finger-to-key assignment; these sets are intersected with an English dictionary to form candidate word pools. Finally, a fine-tuned T5 transformer decoder generates the output sentence by selecting words from the corresponding pools under a constrained beam search. The system is trained with separate losses: cross-entropy for the finger classifier and language modeling loss for T5. This decomposition aligns with the physiological hierarchy of typing and allows computationally efficient split execution.

## Key Results
- Achieves 85.4% finger classification accuracy on the emg2qwerty dataset.
- Attains 5.4% character error rate (CER) and 6.5% word error rate (WER) for sentence decoding.
- Outperforms direct letter classification (51.2% accuracy) and prior baselines by a large margin.

## Why This Works (Mechanism)
### Mechanism 1: Finger-level classification reduces output space and leverages physiological consistency.
- **Claim:** Finger-level classification from sEMG improves decoding accuracy compared to direct letter prediction by aligning with the physiological structure of muscle activation.
- **Mechanism:** The CNN-BiLSTM-Attention model learns spatiotemporal patterns from multichannel sEMG that correspond to specific finger movements. By reducing the output space from 26 letters to 8 finger classes, the model faces less inter-class ambiguity (e.g., "e" and "r" typed by the same finger) and leverages the fact that a single finger’s muscle activation pattern is more consistent across different letters than letter-level patterns are across different fingers.
- **Core assumption:** sEMG signals primarily encode which finger moved, not which abstract key was pressed; multiple letters typed by the same finger produce more similar sEMG than the same letter typed by different fingers under varied posture or effort.
- **Evidence anchors:** 
  - Direct comparison shows finger classification accuracy (85.4%) vs. direct letter classification (51.2%) [abstract, §5.1.1].
  - Confusion matrix for letters shows spatially adjacent keys are commonly confused, indicating finger-level grouping reduces ambiguity.
- **Break condition:** If finger-level classification accuracy falls below ~70% on a held-out user set, the hierarchical decomposition may no longer provide a reliable foundation, causing error propagation downstream.

### Mechanism 2: Ergonomic QWERTY priors reduce effective search space.
- **Claim:** Ergonomic QWERTY finger-to-key priors reduce the effective search space for word and sentence reconstruction, making the system robust to upstream finger classification noise and non-canonical typing patterns.
- **Mechanism:** Each predicted finger maps to a small, fixed set of candidate letters (e.g., left index finger → {f, g, r, t, v}); this constraint dramatically limits the combinatorial explosion in possible words from a sequence of finger predictions. The downstream transformer only selects from these constrained pools.
- **Core assumption:** The standard QWERTY finger assignment is a reasonable prior for a large majority of trained typists, and minor deviations (e.g., typing "b" with right index) can be absorbed by the sentence-level language model.
- **Evidence anchors:** 
  - The paper applies QWERTY ergonomic priors to map each finger to a candidate letter set [abstract].
  - Section §3 details the QWERTY mapping and notes that emg2qwerty participants were screened for ≥90% adherence.
  - Augmented letter pools (simulating deviations) show only minor CER/WER increases, demonstrating robustness [§5.2.2].
- **Break condition:** If a user’s personal typing style diverges drastically from the QWERTY mapping (e.g., >50% of keys typed with non-standard fingers), the fixed letter pools may exclude the true letter, making recovery impossible even with perfect sentence context.

### Mechanism 3: Transformer language model resolves residual ambiguity via context.
- **Claim:** A fine-tuned transformer language model (T5) resolves residual ambiguity from the finger classification and letter pooling stages by leveraging long-range sentence context to select the most fluent, coherent word sequence.
- **Mechanism:** The transformer encoder processes the entire sequence of candidate word pools simultaneously. Its self-attention mechanism allows later words to disambiguate earlier ones (e.g., selecting "parts" over "parrs" after seeing "two" in the context "this has two parts"). The decoder then generates the final sentence autoregressively.
- **Core assumption:** Natural language sentences exhibit strong local and lexical constraints that a pre-trained language model like T5 has internalized, enabling it to choose the correct word from a small, plausible set even if the upstream finger prediction was noisy.
- **Evidence anchors:** 
  - A fine-tuned T5 transformer is used to reconstruct coherent sentences [abstract].
  - Section §4.4 describes constrained beam search over candidate pools; T5 Model 3 achieves 5.4% CER.
  - Error analysis shows mostly semantically plausible substitutions (e.g., "card"→"cage") and omissions, indicating the model preserves fluency but can mis-rank near-synonyms [§5.1.2].
- **Break condition:** If the candidate word pools become too large (>10 words per position) or contain no valid English words for a given position (due to extreme finger misclassification), the transformer’s selection accuracy will degrade sharply, as it is not designed to invent entirely novel words.

- **Why needed here:** The entire letter pooling stage depends on the canonical finger-to-key assignment. Knowing the home row, finger zones, and typical usage patterns (e.g., index/middle fingers are most active) explains the design and its limitations.

## Architecture Onboarding
### Component Map
Raw sEMG & key logs → Data Preparation → (sEMG, finger) → Finger Classifier → finger sequence → Letter/Word Pools → candidate pool sequence → T5 Decoder → decoded sentence.

### Critical Path
The critical path is: Raw sEMG & key logs → Data Prep → (sEMG, finger) → Finger Classifier → finger sequence → Letter/Word Pools → candidate pool sequence → T5 Decoder → decoded sentence. Upstream errors (bad finger prediction) propagate to larger candidate pools, increasing load on the T5.

### Design Tradeoffs
- **Modularity vs. End-to-End:** Modular design allows the finger classifier to run on-wrist (low power) and the T5 on a paired device. An end-to-end model would be less interpretable and harder to deploy on resource-constrained wearables.
- **Fixed Mapping vs. Personalization:** Using a static QWERTY mapping simplifies deployment but assumes user conformity. The system trades potential accuracy loss from non-canonical typists for robustness and zero per-user calibration.
- **Precision vs. Recall in Word Pools:** Strict dictionary filtering removes gibberish but may discard rare words or proper nouns. The paper notes this causes some omissions (e.g., "Uzbekistan").

### Failure Signatures
- **Finger Classifier Failure:** Confusion matrix shows off-diagonal patterns, especially between adjacent finger IDs. Symptom: large candidate word pools, low T5 confidence.
- **Ergonomic Mismatch:** Systematic errors for a specific user (e.g., "b" consistently predicted but "b" not in left index finger's pool). Symptom: the correct letter is never in the candidate set for certain positions.
- **Decoder Failure:** High WER/CER despite reasonable pool sizes. Symptoms: syntactically invalid outputs, early truncation, or repeated words. Often occurs on short, sparse phrases (low context).

### First 3 Experiments
1. **Isolate Finger Classification Performance:** Train/evaluate the CNN-BiLSTM-Attention model on the 30-user subset using both 5-fold CV and Leave-One-User-Out (LOUO) protocols. Goal: Replicate ≥85% within-user and ≥80% cross-user accuracy as reported in §5.1.1.
2. **Test Ergonomics Robustness:** Take a held-out set, manually perturb the finger-to-letter mapping for a subset of keys (e.g., assign 'b' to right index instead of left), regenerate candidate pools, and run the full pipeline (using the best T5 model). Goal: Quantify CER/WER degradation; expect minimal increase as in Fig 8.
3. **Upstream Error Propagation Stress Test:** Artificially degrade finger classifier accuracy (e.g., by injecting random label noise at controlled rates: 10%, 20%, 30%). Run the full pipeline and plot CER/WER vs. finger error rate. Goal: Characterize the T5 decoder's error-correlation capacity and identify the breaking point.

## Open Questions the Paper Calls Out
1. How does MyoText's performance scale when evaluated on all 108 participants in the emg2qwerty dataset, rather than the 30-user subset used in this study?
2. What are the real-time latency and power consumption of an integrated, wearable implementation of MyoText with on-wrist finger classification and on-phone T5 decoding?
3. How do finger-to-key mappings vary across a general population of typists, and can personalized ergonomic priors improve decoding accuracy for non-canonical typists?
4. Does the reliance on QWERTY ergonomic priors limit MyoText's applicability to alternative keyboard layouts (e.g., Dvorak, Colemak) or custom key arrangements?
5. How well does the finger classifier generalize to sEMG signals recorded with different electrode configurations, sampling rates, or hardware devices?

## Limitations
- **Reproducibility Gaps:** Exact user/keystroke splits, full finger classifier hyperparameters, candidate word filtering pipeline details, and T5 beam search settings are undisclosed, hindering exact replication.
- **QWERTY Mapping Assumption:** Fixed finger-key assignment may exclude correct letters for users with non-canonical typing styles (>50% deviation), leading to unrecoverable errors.
- **Error Propagation:** Upstream finger misclassifications inflate candidate pools; the T5 decoder’s error-correction capacity has an unknown breaking point, especially for short phrases with minimal context.
