# Complexity Agnostic Recursive Decomposition of Thoughts

## Quick Facts
- arXiv ID: 2601.04210
- Source URL: https://arxiv.org/abs/2601.04210
- Reference count: 15
- Primary result: CARD reduces token cost by 1.71–5.74× while achieving 81.4–89.2% accuracy on GSM8K and 75.1–86.8% on MATH-500 with small models.

## Executive Summary
Fixed decomposition strategies in LLMs lead to inefficiency and errors on multi-step reasoning by ignoring problem-specific difficulty. CARD introduces a preemptive complexity estimator (MRCE) that predicts a normalized complexity score and estimated steps from 30 text features before generation. This drives a two-stage adaptive solver: it first decides whether to decompose based on the estimated complexity, then allocates per-step thought budgets (1, 5–9, or 10) via recursive re-profiling of sub-problems. Evaluated on GSM8K and MATH-500 with small reasoning models (0.6B–1.7B), CARD achieves substantial token reductions while matching or exceeding the accuracy of fixed baselines like RDoLT.

## Method Summary
CARD employs a lightweight MRCE model (Qwen3-0.6B with LoRA) trained on 100k question-complexity profile pairs to extract 30 linguistic/structural features and compute a normalized complexity score ρ. For a new question, MRCE predicts ρ and an estimated step count K. If ρ exceeds a threshold (τ_dec = 3.0), the problem is decomposed into K steps; otherwise, it is solved directly. Each sub-problem is re-evaluated by MRCE to obtain ρ_i, which determines a thought budget B_i via a piecewise function: 1 for easy (ρ_i < 3.0), ⌈1.5·ρ_i⌉ for moderate (3.0 ≤ ρ_i < 6.0), and 10 for hard (ρ_i ≥ 6.0). Steps are solved independently with a context that includes the original question, a dependency graph of all steps, and prior step solutions. The best solution per step is selected and aggregated into a final answer.

## Key Results
- Achieves 81.4–89.2% accuracy on GSM8K and 75.1–86.8% on MATH-500 with small reasoning models (0.6B–1.7B), improving over fixed baselines.
- Reduces token cost by 1.71× to 5.74× compared to fixed decomposition strategies like RDoLT.
- Ablation studies confirm that the full 30-dimensional feature set is necessary for accurate complexity profiling and the observed efficiency gains.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Preemptive multi-dimensional complexity estimation prevents inappropriate decomposition depth and thought budgets.
- **Mechanism:** MRCE extracts 30 linguistic/structural features from the question text to predict a normalized complexity score (ρ) and estimated steps *before* generation begins. This score directly determines whether decomposition occurs (ρ ≥ τ_dec) and sets the initial step count K.
- **Core Assumption:** Problem difficulty is reliably inferable from surface text features (e.g., arithmetic operations, entity count, trap indicators) without requiring incremental generation.
- **Evidence Anchors:**
  - [Abstract]: "predicts problem complexity before generation and adapts decomposition accordingly."
  - [Section 3.1]: Details MRCE's 30-feature architecture and training on 100k annotated pairs; defines ρ via weighted sum of feature groups.
  - [Corpus]: Neighbor papers (e.g., RDoLT, CGAR) use fixed or reactive decomposition, lacking preemptive profiling; CARD's novelty is explicitly positioning against these.
- **Break Condition:** If MRCE's feature extraction fails for out-of-domain problems (e.g., non-mathematical reasoning), the initial decomposition decision K or ρ may be invalid, causing cascading misallocation.

### Mechanism 2
- **Claim:** Graduated, per-step thought budget allocation based on recursive re-profiling balances accuracy and token cost.
- **Mechanism:** After decomposing into K steps, MRCE re-evaluates each sub-problem s_i to compute ρ_i. A piecewise function assigns budget B_i: 1 thought for easy (ρ_i < 3.0), ⌈1.5·ρ_i⌉ for moderate (3.0 ≤ ρ_i < 6.0), and 10 for hard (ρ_i ≥ 6.0). This adapts resources to sub-problem difficulty.
- **Core Assumption:** Sub-problem complexity (ρ_i) is correlated with the minimum thoughts needed for correct solution; linear scaling (1.5·ρ_i) in the moderate range is sufficient.
- **Evidence Anchors:**
  - [Abstract]: "allocates per-step thought budgets (1, 5-9, or 10 thoughts) via recursive MRCE profiling."
  - [Section 3.2]: Presents Algorithm and equation (3) defining B_i; Table 3 shows token/accuracy trade-offs per quartile.
  - [Corpus]: Neighbors (e.g., ToT) use fixed beam search; CARD's adaptive budgets are a key differentiator.
- **Break Condition:** If ρ_i underestimates a sub-problem's true difficulty (e.g., due to missing semantic trap features), B_i may be too low, causing solution failure despite overall high ρ_q.

### Mechanism 3
- **Claim:** The dependency-graph-backed context aggregation (C_i) preserves cross-step dependencies while allowing independent thought generation per step.
- **Mechanism:** For step s_i, the context C_i aggregates the original question q, the full dependency graph G of all steps, and prior step solutions {(s_j, sol(s_j))} for j < i. This ensures each thought generation has global context without re-solving previous steps.
- **Core Assumption:** Localizing generation to a single step with global context is sufficient; re-solving prior steps is unnecessary if their solutions are preserved.
- **Evidence Anchors:**
  - [Section 3.2]: "context C_i = q ⊕ G ⊕ ⊕_{j=1}^{i-1} [s_j ⊕ sol(s_j)]"
  - [Section 4]: CARD's token savings (1.71×–5.74×) imply no redundant regeneration; contrast with CoT's monolithic chain.
  - [Corpus]: Neighbors like RDoLT also use decomposition with context, but CARD's adaptive budgets are the primary lever; dependency graph is similar but not novelly claimed.
- **Break Condition:** If dependency graph construction is erroneous (e.g., missed sequential dependencies), later steps may lack necessary information, causing silent failures even with adequate B_i.

## Foundational Learning
- **Concept: Multi-dimensional complexity profiling**
  - *Why needed here:* CARD's core innovation is moving beyond scalar difficulty (e.g., problem length) to 30 features across arithmetic, depth, semantic, and calibration groups. This enables fine-grained budget decisions.
  - *Quick check question:* If you remove "estimated_steps" from MRCE, what specific failure mode (in tokens/accuracy) would you expect based on Table 4?
- **Concept: Recursive decomposition with termination conditions**
  - *Why needed here:* Decomposition must halt when sub-problems are easy enough (ρ_i < τ_low) to avoid over-processing. The termination is dynamic, not fixed-depth like RDoLT.
  - *Quick check question:* For a problem with ρ_q = 5.2 (moderate), what is K, and how might B_i vary across steps? When would recursion stop early?
- **Concept: Token-budget-aware inference**
  - *Why needed here:* The entire point is to reduce token cost without sacrificing accuracy. Understanding the trade-off curve (Table 3) is essential for tuning τ thresholds or α scaling.
  - *Quick check question:* Why does CARD achieve 5.39× savings on the easiest quartile? What would happen if you set B_max = 5 instead of 10?

## Architecture Onboarding
- **Component map:** MRCE -> Step Decomposer -> Thought Generator -> Aggregator (with MRCE invoked recursively per step).
- **Critical path:** q -> MRCE (predict ρ_q, K) -> if ρ_q ≥ τ_dec: decompose into steps S_q with graph G -> for each s_i: MRCE(s_i) -> ρ_i -> B_i -> generate B_i thoughts with context C_i -> SelectBest -> aggregate step solutions -> final answer.
- **Design tradeoffs:**
  - MRCE size vs. accuracy: 0.6B is lightweight but may limit feature prediction fidelity; larger base could improve but increase overhead.
  - Fixed thresholds (τ_dec=3.0, τ_low=3.0, τ_high=6.0, α=1.5, B_max=10): tuned on validation sets; domain shift may require re-tuning.
  - Recursive profiling: each step re-runs MRCE, adding latency; could cache intermediate predictions if steps are similar.
- **Failure signatures:**
  - Over-decomposition: easy problems (low ρ_q) broken into many steps → token cost ≈ RDoLT. Check if MRCE underestimates simplicity; inspect feature `trap_level`/`difficulty`.
  - Under-decomposition: hard problems (high ρ_q) assigned low K or low B_i → accuracy drop. Check if `estimated_steps` is too low.
  - Dependency mismatch: steps solved in isolation but final answer inconsistent. Inspect dependency graph construction.
- **First 3 experiments:**
  1. **MRCE calibration run:** Feed 100 validation questions; compare predicted ρ vs. human difficulty ratings or downstream success rate. Adjust feature weights w if correlation is low.
  2. **Threshold sensitivity sweep:** Vary τ_dec (2.5, 3.0, 3.5) and record accuracy/tokens on a held-out set. Plot Pareto frontier to pick operating point.
  3. **Feature ablation micro-test:** On 50 problems, manually zero-out each feature group in MRCE and note changes in K and B_i assignments; expect `estimated_steps` removal to cause K=default high value.

## Open Questions the Paper Calls Out
- **Open Question 1:** Can complexity estimation be performed in a self-supervised manner using model confidence calibration, eliminating the need for manually annotated complexity profiles?
  - *Basis in paper:* The conclusion lists "self-supervised complexity estimation using model confidence calibration" as a future direction to remove manual annotation dependency.
  - *Why unresolved:* Current MRCE requires 100k labeled examples with 30 features per problem, which is costly and domain-specific. Without self-supervision, scaling to new domains remains a bottleneck.
  - *What evidence would resolve it:* A method that correlates internal model confidence (e.g., entropy, consistency) with ground-truth complexity scores on held-out data, showing accurate prediction without human annotations.
- **Open Question 2:** Can reinforcement learning (RL) with token efficiency as a reward signal learn optimal decomposition policies that adapt dynamically without relying on pre-defined thresholds like τ_dec=3.0?
  - *Basis in paper:* The conclusion proposes "learning decomposition policies through reinforcement learning with token efficiency as the reward."
  - *Why unresolved:* CARD uses hand-tuned thresholds and linear budget scaling. These may not be optimal across diverse problem types or model architectures, and the paper does not explore learning these decisions from interaction.
  - *What evidence would resolve it:* An RL-trained policy that matches or exceeds CARD's accuracy while using fewer tokens, and generalizes to unseen distributions without threshold retuning.
- **Open Question 3:** How can CARD be effectively combined with mixture-of-experts (MoE) routing to leverage multiple specialized models for different reasoning sub-problems?
  - *Basis in paper:* The conclusion suggests "combining CARD with mixture-of-experts routing for deployments that use multiple models."
  - *Why unresolved:* CARD routes all steps through a single reasoning model. MoE could assign easy steps to smaller models and hard steps to larger ones, but the framework for dynamic model assignment based on sub-problem complexity is unexplored.
  - *What evidence would resolve it:* A system where MRCE complexity estimates trigger routing decisions (e.g., sub-problem complexity <3.0 → small model; ≥6.0 → large model), demonstrating reduced compute cost while maintaining accuracy.
- **Open Question 4:** Do the 30 fine-grained features used by MRCE generalize to non-mathematical reasoning domains such as commonsense QA or code generation, or are they specifically tailored to arithmetic and algebraic structures?
  - *Basis in paper:* The conclusion notes that "other domains—commonsense reasoning, code generation, logical inference—will require domain-specific feature engineering and complexity annotation," implying the current feature set may not transfer directly.
  - *Why unresolved:* The paper evaluates only on GSM8K and MATH-500, which are math-focused. Features like "arithmetic structure" may not capture complexities in other domains. No experiments test cross-domain transfer.
  - *What evidence would resolve it:* Applying MRCE (without retraining) to diverse non-math tasks and showing that predicted complexity correlates with actual model performance. Alternatively, identifying a subset of features that are domain-agnostic versus domain-specific.

## Limitations
- Exact feature definitions and extraction methods for the 30 MRCE features are unspecified.
- The dependency graph construction algorithm is not detailed.
- The `SelectBest` mechanism is ambiguous.
- Tuned thresholds (τ_dec, α, B_max) may be overfitted to GSM8K/MATH-500 and not generalize.

## Confidence
- Overall accuracy and token reduction claims: Medium
- Mechanistic understanding (preemptive estimation, per-step budgeting, context aggregation): Low
- Necessity of multi-dimensional features: Medium
