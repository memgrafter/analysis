# genriesz: A Python Package for Automatic Debiased Machine Learning with Generalized Riesz Regression

## Quick Facts
- **arXiv ID:** 2602.17543
- **Source URL:** https://arxiv.org/abs/2602.17543
- **Reference count:** 19
- **Primary result:** The genriesz package automates debiased machine learning for linear causal/structural parameters via generalized Riesz regression, delivering asymptotically normal estimators with valid confidence intervals under standard rate conditions.

## Executive Summary
The `genriesz` Python package implements automatic debiased machine learning (ADML) through generalized Riesz regression, a unified framework that estimates Riesz representers by minimizing empirical Bregman divergences. It provides a full suite of doubly robust estimators—including regression adjustment (RA), Riesz weighting (RW), augmented Riesz weighting (ARW), and TMLE—with built-in cross-fitting and asymptotically valid Wald inference. A key innovation is automatic regressor balancing (ARB), which constructs a generator‑induced link function so that the representer fit automatically satisfies optimal moment‑matching conditions for any user‑specified basis. This modular design subsumes many existing methods (e.g., entropy balancing, covariate matching, density ratio estimation) under a single interface, supporting diverse Bregman generators and basis functions such as polynomials, RKHS, random forests, neural embeddings, and kNN catchment.

## Method Summary
At its core, `genriesz` solves a convex optimization problem to estimate the Riesz representer α₀ for a user‑defined linear functional θ₀ = E[m(W, γ₀)]. The user supplies a basis map ϕ(x) and a Bregman generator g(·), which together define a representer model α̂(x) = ζ⁻¹(ϕ(x)ᵀβ) where ζ = ∂ₐg. The package automatically derives ζ and its inverse from g, then fits β by minimizing a dual objective combining a Bregman‑Riesz loss and an ℓₚ penalty (ℓ₁ or ℓ₂). For nuisance regression γ₀, a separate (default: same basis) model is fit. Cross‑fitting generates out‑of‑fold predictions α̂ᵢ and γ̂ᵢ, which are plugged into orthogonal scores to compute RA, RW, ARW, and TMLE estimates. Standard errors and confidence intervals follow from the asymptotic linearity of the ARW/TMLE estimator, assuming nuisance rates oₚ(n⁻¹/⁴).

## Key Results
- Unifies numerous balancing‑weight and density‑ratio methods under a single Bregman‑divergence minimization framework.
- Automatic regressor balancing (ARB) guarantees optimal moment‑matching conditions for any user‑chosen basis via the generator‑induced link.
- Delivers asymptotically normal and Wald‑valid inference for all plug‑in estimators under standard rate conditions on nuisance estimates.

## Why This Works (Mechanism)

### Mechanism 1
- **Claim:** Generalized Riesz regression unifies numerous balancing‑weight and density‑ratio methods under a single Bregman‑divergence minimization framework.
- **Mechanism:** Estimating the Riesz representer α₀ by minimizing an empirical Bregman‑Riesz objective that combines a pointwise Bregman divergence BD_g(α₀ ‖ α) with the linear functional’s empirical moment.
- **Core assumption:** The Bregman generator g is convex in its second argument, and the representer model class is chosen such that the optimization problem is well‑posed.
- **Evidence anchors:**
  - [abstract]: "implement[s] automatic debiased machine learning (ADML) and generalized Riesz regression, a unified framework for estimating Riesz representers by minimizing empirical Bregman divergences. This framework includes covariate balancing, nearest‑neighbor matching, calibrated estimation, and density ratio estimation as special cases."
  - [section 2.2]: Details the primal objective (5) and dual objective (7) based on Bregman divergence minimization.
  - [corpus]: Weak anchor. The neighboring papers confirm the unifying perspective but do not provide direct evidence for *this specific implementation’s* correctness.
- **Break condition:** If the specified generator g is non‑convex or lacks a well‑defined dual, the convex optimization procedure fails to guarantee a unique or correct representer estimate.

### Mechanism 2
- **Claim:** Automatic Regressor Balancing (ARB) automatically constructs a compatible link function ζ from the generator’s derivative so that the representer fit α̂_β(x) = ζ⁻¹(x, ϕ(x)ᵀβ) satisfies optimal balancing (moment‑matching) conditions for the user‑chosen basis ϕ.
- **Mechanism:** Setting ζ(x, α) = ∂ₐg(x, α) makes the dual coordinate v(x) = ζ(x, α(x)) linear in the primal coefficient β. The Karush‑Kuhn‑Tucker (KKT) conditions of the resulting convex program directly yield balancing equations (11–13) between sample moments of α̂ϕ and the linear functional’s component m(W, ϕⱼ).
- **Core assumption:** The basis ϕ and the choice of norm penalty Ω(β) = (1/q)‖β‖_q^q (typically q ∈ {1, 2}) are such that the KKT conditions are valid and translate into a feasible slack on the balancing constraints (12 or 13).
- **Evidence anchors:**
  - [abstract]: "given a Bregman generator g and a representer model class, genriesz automatically constructs a compatible link function so that the generalized Riesz regression estimator satisfies balancing (moment‑matching) optimality conditions in a user‑chosen basis."
  - [section 2.3]: Proposition 2.1 explicitly derives the balancing conditions (11–13) from the KKT conditions of problem (10) under ARB.
- **Break condition:** If the basis functions are highly collinear, the linear system from (11) becomes ill‑conditioned, leading to unstable β̂ and thus poor moment balancing. The ℓ₁ penalty slack (12) may also be too large if λ is not tuned properly.

### Mechanism 3
- **Claim:** The suite of plug‑in estimators (RA, RW, ARW, TMLE) all achieve asymptotic normality and valid Wald confidence intervals under standard rate conditions on the nuisance estimates, because they all use the same Neyman‑orthogonal score ψ(W; θ, γ, α).
- **Mechanism:** The orthogonal score’s influence function ψ(W; θ₀, γ₀, α₀) does not depend on the first‑order error of γ̂ or α̂. Cross‑fitting ensures the empirical mean of estimated scores ψ̂ᵢ has variance equal to the influence function variance minus higher‑order terms, yielding asymptotic linearity when ‖γ̂−γ₀‖_{L²} = oₚ(n⁻¹/⁴) and ‖α̂−α₀‖_{L²} = oₚ(n⁻¹/⁴).
- **Core assumption:** The nuisance functions γ₀ and α₀ are estimated at sufficiently fast rates (typically n⁻¹/⁴ in L²(P)) and the cross‑fitting procedure maintains approximate independence between the score and the estimation error.
- **Evidence anchors:**
  - [abstract]: "It returns regression adjustment (RA), Riesz weighting (RW), augmented Riesz weighting (ARW), and targeted maximum likelihood estimation (TMLE)‑style estimators with cross‑fitting, confidence intervals, and p‑values."
  - [section 2.5]: Proposition 2.2 states asymptotic normality for ARW (and analogously TMLE) under mean‑square‑error rate conditions.
  - [corpus]: Strong anchor. The neighboring papers (e.g., Chernozhukov et al. 2022b, Kato 2026) are foundational for DML and Riesz methods, establishing the theoretical basis for this mechanism.
- **Break condition:** If the nuisance models are overfitted (rates slower than n⁻¹/⁴) or cross‑fitting is omitted in high‑capacity settings, the higher‑order bias terms do not cancel, invalidating Wald inference.

## Foundational Learning
- **Concept: Riesz Representation Theorem for Linear Functionals**  
  Why needed: It guarantees the existence of a unique representer α₀ such that the target parameter θ₀ = E[m(W, γ₀)] can be written as E[α₀(X)γ₀(X)] for all suitable γ. This identity is the cornerstone for constructing the orthogonal score.  
  Quick check: "Given a linear functional θ₀ = E[γ₀(X)], what is the analytical form of its Riesz representer α₀(x) in a standard potential outcomes model for the ATE?"

- **Concept: Bregman Divergence and Convex Duality**  
  Why needed: The Bregman divergence BD_g(α₀ ‖ α) defines the fitting loss for the representer. Its convex conjugate g* enables efficient optimization and directly yields the "weight" interpretation in the dual problem. Different choices of g (squared, KL, etc.) correspond to different balancing methods.  
  Quick check: "How does the choice of Bregman generator g(α) = α log α − (1+α)log(1+α) (binary KL) relate to entropy balancing weights?"

- **Concept: Neyman Orthogonality and Doubly‑Robust Estimation**  
  Why needed: The score ψ(W; θ, γ, α) is constructed to be orthogonal (mean‑zero) to nuisance perturbations at the true parameter θ₀. This property allows first‑order bias cancellation when plugging in inconsistent estimates γ̂, α̂, leading to √n‑consistent and asymptotically normal estimation of θ₀.  
  Quick check: "Why does the term α(X)(Y − γ(X)) in the score 'de‑bias' the plug‑in estimator based on m(W, γ)?"

## Architecture Onboarding
- **Component map:** User Input Layer (X, Y, m, basis, generator, penalties) -> Core ARB Engine (constructs ζ and ζ⁻¹) -> Nuisance Fitting Module (solves convex dual for β, fits γ̂) -> Cross‑Fitting Orchestrator (splits data, stores out‑of‑fold predictions α̂ᵢ, γ̂ᵢ) -> Estimator & Inference Module (computes RA/RW/ARW/TMLE, calculates SEs/CIs) -> Output Object (GrrResult).
- **Critical path:** Defining m -> Choosing basis -> Selecting generator -> (Optional: setting penalties) -> Calling grr_functional/grr_xxx. The ARB link construction is automatic and invisible but critical; it must succeed for the solver to work.
- **Design tradeoffs:** Flexibility vs. stability (user‑defined generators/bases risk non‑convergence); dual vs. primal (dual used for efficiency but requires accurate g*); inference reliability (cross‑fitting default vs. single fit for small data); outcome model coupling (separate basis/penalty for γ allows tailoring).
- **Failure signatures:** Solver non‑convergence (check generator convexity, scaling, increase max_iter or riesz_lam); NaNs/Infs in representer (domain violation, use branch_fn, adjust C); extremely large SEs (poor balancing, increase riesz_lam or reduce basis complexity); TMLE update failure (initial γ̂ near 0/1, try Gaussian likelihood or regularize γ̂); shape mismatches (verify X dimensions and basis construction); degenerate cross‑fits (stratify folds or set cross_fit=False).
- **First 3 experiments:**  
  1. Baseline ATE: Use PolynomialBasis(degree=2, include_bias=True), SquaredGenerator(C=0.0), riesz_penalty="l2". Verify arw/tmle agree and balance conditions (11) are small.  
  2. Entropy Balancing ATE: Switch to UKLGenerator(C=1.0) with same basis. Compare rw weights distribution to SquaredGenerator; verify balancing slack λ controlled by riesz_lam.  
  3. kNN Matching: Use riesz_method="nn_matching", M=3, outcome_models="none". Check rw estimate equals sample‑average of Y weighted by inverse propensity‑like scores; compare to manual nearest‑neighbor matching on a subset.

## Open Questions the Paper Calls Out
- **Open Question 1:** How to automatically choose a Bregman generator? The package offers several but provides no selection criterion; the choice affects balancing weights and variance.
- **Open Question 2:** How to handle clustered or dependent data? The paper notes that cluster‑robust variance is not yet supported, which is common in applied studies.
- **Open Question 3:** How to automatically tailor basis complexity and regularization to meet nuisance MSE rates? The library supports flexible bases but lacks automatic tuning to guarantee ‖α̂−α₀‖ = oₚ(n⁻¹/⁴) and ‖γ̂−γ₀‖ = oₚ(n⁻¹/⁴).

## Limitations
- Implementation not independently verified; potential bugs in convex optimization, ARB link construction, or cross‑fitting.
- User interface for custom m and basis functions is under‑documented, risking misuse (shape errors, vectorization issues).
- Hyperparameter tuning (regularization riesz_lam, basis complexity, folds) lacks guidelines; defaults may not generalize.

## Confidence
- Unifying Bregman framework: Medium‑High (theoretically solid via Bregman duality and supporting literature, but implementation‑specific claims need empirical validation).
- Automatic Regressor Balancing (ARB): Medium (Proposition 2.1 derives balancing conditions, but automatic link construction and numerical stability under diverse bases remain to be tested).
- Asymptotic normality and Wald inference: High (conditional) (built on established DML/Riesz theory; validity depends on correct ARB, cross‑fitting, and attainment of nuisance rates).
