# PyVision-RL: Forging Open Agentic Vision Models via RL

## Quick Facts
- arXiv ID: 2602.20739
- Source URL: https://arxiv.org/abs/2602.20739
- Reference count: 40
- Primary result: PyVision-Image achieves SOTA on V* (+6.9%) and WeMath (+9.6%); PyVision-Video improves VSI-Bench (+7.3%) with ~5K visual tokens vs ~45K.

## Executive Summary
PyVision-RL introduces a reinforcement learning framework to train multimodal agents without suffering from interaction collapse—the phenomenon where agents reduce tool usage and multi-turn reasoning. The framework combines an oversampling–filtering–ranking rollout strategy to select informative training trajectories and an accumulative tool reward to encourage sustained tool use. For video tasks, PyVision-Video uses on-demand context construction to achieve high efficiency. Empirical results show significant gains on vision-language benchmarks, establishing new state-of-the-art while reducing token usage.

## Method Summary
The method consists of two main components. First, for image-based tasks, PyVision-Image employs a rollout strategy that oversamples potential trajectories, filters out broken ones, and ranks the remainder by quality; during training, an accumulative reward is awarded only when the agent correctly uses tools across multiple turns, incentivizing persistent interaction. Second, for video understanding, PyVision-Video loads the full video into a Python runtime but allows the agent to selectively sample frames on-demand, drastically reducing the number of visual tokens processed. The overall training pipeline uses RL with these innovations to maintain tool usage and avoid collapse.

## Key Results
- PyVision-Image improves over prior SOTA by +6.9% on V* and +9.6% on WeMath.
- PyVision-Video attains +7.3% higher accuracy on VSI-Bench compared to Qwen2.5-VL-7B while using only ~5K visual tokens per sample instead of ~45K.
- The framework enables stable RL training with consistently increasing tool usage and performance.

## Why This Works (Mechanism)
Interaction collapse occurs because standard RL objectives may reward final success without encouraging intermediate tool usage, leading agents to bypass tools. PyVision-RL combats this by (1) ensuring training trajectories are informative and free of errors via oversampling and filtering, and by (2) adding an accumulative reward that only counts when tool calls are correct and persistent across turns. This explicit incentive prevents the agent from reducing tool reliance. For video, on-demand context construction avoids processing all frames upfront; instead, the agent dynamically samples frames relevant to the current reasoning step, guided by the task, which focuses computation on salient information and reduces token load.

## Foundational Learning
- **Reinforcement Learning (RL) for multimodal agents**: RL trains agents to maximize cumulative reward; needed to learn tool usage policies. Quick check: Can an RL agent learn to use a calculator tool for math tasks given proper reward shaping?
- **Interaction collapse**: The degradation of multi-turn tool usage during RL training; needed to understand the problem addressed. Quick check: Does the agent's tool call frequency decrease over training steps without intervention?
- **Oversampling–filtering–ranking**: A rollout selection strategy to stabilize training; needed to ensure high-quality trajectories. Quick check: Does filtering out trajectories with broken tool calls improve final performance?
- **Accumulative tool reward**: Reward added only for correct multi-turn tool use; needed to incentivize sustained interaction. Quick check: Does rewarding correct tool calls across an episode increase tool usage compared to per-step reward?
- **On-demand context construction**: For video, loading full video but sampling frames during reasoning; needed for efficiency. Quick check: Does selective frame sampling maintain accuracy while reducing tokens?

## Architecture Onboarding
Component map: Input -> Agent (policy network) -> Tool Library (Python functions) -> Rollout Manager (oversampling, filtering, ranking) -> Reward Calculator (includes accumulative tool reward) -> RL Optimizer -> Updated Policy. For video: Video Loader -> Frame Sampler (on-demand) -> Agent.

Critical path: User provides a task and (for video) a video file. The agent interacts with tools over multiple turns. Rollout manager selects and ranks trajectories. Reward calculator assigns scores. RL optimizer updates policy. For video, the agent requests frames from the sampler as needed.

Design tradeoffs:
- Oversampling increases compute but improves trajectory quality; filtering reduces noise but may discard useful variations.
- Accumulative reward requires correct labeling of tool correctness; may be complex to implement.
- On-demand sampling reduces tokens but risks missing relevant frames; depends on agent's sampling policy.

Failure signatures:
- If filtering is too aggressive, training data becomes scarce leading to overfitting.
- If accumulative reward is mis-specified, agents might develop spurious tool usage patterns.
- On-demand sampler might ignore long-term context, causing errors in tasks requiring global video understanding.
