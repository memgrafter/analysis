# Making Bielik LLM Reason (Better): A Field Report

## Quick Facts
- **ArXiv ID:** 2603.10640
- **Source URL:** https://arxiv.org/abs/2603.10640
- **Reference count:** 2
- **Primary result:** Bielik‑R:11B achieved 56% accuracy (rank 18 out of 27) on the reasoning benchmark, with strong performance on formal logic (80% propositional calculus, 89% first‑order logic).

## Executive Summary
The Bielik LLM exhibited limited reasoning, and manual assessment was inefficient. The authors developed an automated benchmark using ChatGPT‑4.1 as an LLM‑as‑judge to evaluate reasoning across diverse taxonomies. They introduced a three‑stage training pipeline: supervised fine‑tuning on 1.3 M distilled English traces, Direct Preference Optimization, and reinforcement learning on 490 k Polish verifiable tasks. A `<think>` delimiter was used to structure reasoning traces. In a 27‑model comparison, Bielik‑R:11B scored 56%, trailing top models but achieving 80% and 89% on propositional and first‑order logic subsets. Challenges include mid‑solution token limits, rigidity to instruction changes, and lack of procedural familiarity. Future work aims to extend to discourse analysis, Winograd tasks, moral dilemmas, and multi‑agent systems for Polish matura mathematics.

Key findings show that automated evaluation enabled scalable measurement, the multi‑stage training improved reasoning, and the delimiter approach facilitated reliable scoring. However, overfitting to template‑based tasks and judge bias remain risks. The project underscores the importance of verifiable rewards and explicit reasoning structures for advancing LLM reasoning.

## Method Summary
The authors implemented a multi‑stage post‑training pipeline to enhance Bielik’s reasoning. First, they performed supervised fine‑tuning (SFT) on approximately 1.3 million English reasoning traces distilled from advanced teacher models (DeepSeek, Qwen), which included explicit `<think>` delimiters to structure chain‑of‑thought. Second, they applied Direct Preference Optimization (DPO) to align model outputs with human‑like preferences without explicit reward modeling. Third, they employed reinforcement learning with verifiable rewards (RLVR) using GRPO/DAPO (via VERL) on 490 k Polish tasks across math, code, STEM, and logic, where each task had a deterministic answer enabling automated scoring. The overall process was guided by an automated evaluation benchmark that used ChatGPT‑4.1 as an LLM‑as‑judge to assign 0/0.5/1 scores based solely on final answer correctness. This modular design ensured that inference also required reasoning to be placed within `<think>` tags followed by the final answer.

## Key Results
- **Overall benchmark:** Bielik‑R:11B scored 56% (rank 18) among 27 models; top models scored 87–84%.
- **Formal logic subsets:** 80% on propositional calculus, 89% on first‑order logic.

## Why This Works (Mechanism)
### Mechanism 1: Automated LLM‑as‑Judge Benchmark
- **Claim:** Replacing manual reasoning assessment with an automated LLM‑as‑judge benchmark scaled evaluation and improved consistency.
- **Mechanism:** The team used ChatGPT‑4.1 to score model outputs on a 0 / 0.5 / 1 scale, focusing solely on final answer correctness across a diverse set of reasoning taxonomies.
- **Core assumption:** A large language model can serve as a reliable proxy for human evaluation when given clear rubrics and answer keys.
- **Evidence anchors:**
  - [abstract] describes the benchmark with LLM‑as‑judge (ChatGPT‑4.1) using 0/0.5/1 scale.
  - [section 2] details the transition from manual to automated evaluation, the abandonment of separate reasoning‑process scoring, and the adoption of the simplified scale.
  - [corpus] weak support; neighboring papers document other Bielik variants but do not directly corroborate the evaluation design.
- **Break condition:** Systematic bias in the judge model (e.g., preference for certain formats or inability to detect subtle reasoning flaws) would invalidate scores.

### Mechanism 2: Staged Training Pipeline (SFT → DPO → RLVR)
- **Claim:** Multi‑stage post‑training (supervised fine‑tuning, preference alignment, reinforcement learning on verifiable tasks) delivers robust reasoning gains.
- **Mechanism:**
  1. SFT on ~1.3 M English reasoning traces from DeepSeek, Qwen to instill chain‑of‑thought patterns.
  2. DPO on pairwise preference data to refine without explicit reward modeling.
  3. RL (GRPO/DAPO) on 143 k (later 490 k) Polish tasks with deterministic answers, enabling fully automated reward via rule‑based verification.
- **Core assumption:** Each stage contributes complementary benefits: imitation (SFT), preference shaping (DPO), and task‑specific skill sharpening through verifiable feedback (RL).
- **Evidence anchors:**
  - [abstract] outlines the three stages and the scale of data.
  - [section 3] expands on the pipeline, dataset expansion, and selection of DAPO; also notes the 490 k Polish tasks covering math, code, STEM, logic.
  - [corpus] neighboring technical reports (e.g., Bielik v3 Small [1]) describe similar multi‑stage post‑training, providing indirect context.
- **Break condition:** Overfitting to the verifiable task distribution (e.g., template‑based problems) would limit generalization to novel reasoning scenarios.

### Mechanism 3: `<think>` Delimiters for Structured Reasoning
- **Claim:** Requiring reasoning inside `<think>` tags improves evaluation reliability and helps the model isolate its thought process.
- **Mechanism:** The chat template mandates that the model emit reasoning within `<think>` tags followed by a final answer. The RL reward function parses this format to judge correctness without interference from the reasoning trace.
- **Core assumption:** Explicit structural markers enable both the model to compartmentalize reasoning and the evaluation system to reliably locate the final answer.
- **Evidence anchors:**
  - [abstract] mentions "introduced `<think>` delimiters for reasoning traces."
  - [section 3] describes the reasoning chat template with `<think>` tags.
  - [section 5] notes that Bielik's token usage is comparable to commercial models, suggesting delimiters do not bloat output.
  - [corpus] weak; neighboring Bielik technical reports may use similar chat templates but not explicitly described.
- **Break condition:** If the model fails to respect delimiters (e.g., placing answer inside tags or omitting them), scoring breaks down.

## Foundational Learning
- **Supervised Fine‑Tuning (SFT)**
  - **Why needed:** To transfer reasoning patterns from high‑quality teacher traces (DeepSeek, Qwen) into Bielik, establishing a base for chain‑of‑thought reasoning.
  - **Quick check:** What distinguishes SFT from standard language modeling fine‑tuning in this context? Answer: Use of structured reasoning traces with `<think>` delimiters.
- **Direct Preference Optimization (DPO)**
  - **Why needed:** To align model outputs with human‑like preferences without requiring explicit reward modeling.
  - **Quick check:** How does DPO differ from traditional RLHF? Answer: It directly optimizes the policy on preferences via a fixed reference model, avoiding separate reward training.
- **Reinforcement Learning with Verifiable Rewards (RLVR)**
  - **Why needed:** To refine reasoning on tasks where correctness can be automatically verified (Polish math, code, logic), providing dense feedback.
  - **Quick check:** Why are verifiable tasks essential for RL in this setting? Answer: They enable automated reward computation without human judges.

## Architecture Onboarding
- **Component map:** Evaluation bench → task generation → training pipeline (SFT → DPO → RL) → inference with `<think>` template → analysis tools.
- **Critical path:**
  1. Define reasoning taxonomies and generate tasks.
  2. Create initial evaluation with LLM‑as‑judge.
  3. Collect/distill reasoning traces for SFT.
  4. Perform SFT.
  5. Gather preference data and run DPO.
  6. Compile verifiable Polish task set.
  7. Run RL (GRPO/DAPO) with automated rewards.
  8. Deploy model template and evaluate on benchmark.
- **Design tradeoffs:**
  - ChatGPT‑4.1 as judge vs. open‑source judge: quality vs. cost/control.
  - SFT on English traces vs. Polish: leveraging strong teacher models vs. potential language mismatch.
  - Token limit: Restricting reasoning length may cause truncation; allowing longer increases compute.
  - DPO before RL: DPO shapes general behavior, but RL with verifiable rewards provides direct skill improvement.
- **Failure signatures:**
  - Model frequently exceeds token limit mid‑solution, losing points.
  - Inability to adapt when instructions change due to rigidity.
  - Low scores on formal logic despite strong performance on other tasks.
  - Repetitive or redundant reasoning loops detected by redundancy evaluator.
- **First 3 experiments:**
  1. Baseline benchmark: Run the automated LLM‑as‑judge evaluation on current Bielik‑R to establish scores across taxonomies and compare to top models.
  2. Delimiter adherence test: Provide tasks requiring reasoning within `<think>` tags; measure compliance rate and final answer correctness.
  3. Verifiable RL validation: Train a small subset (10 k tasks) with RL (DAPO) and evaluate improvement on held‑out Polish formal logic questions.
