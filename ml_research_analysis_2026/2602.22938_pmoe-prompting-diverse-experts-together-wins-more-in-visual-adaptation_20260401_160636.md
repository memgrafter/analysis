# pMoE: Prompting Diverse Experts Together Wins More in Visual Adaptation

## Quick Facts
- **arXiv ID**: 2602.22938
- **Source URL**: https://arxiv.org/abs/2602.22938
- **Reference count**: 33
- **Primary result**: pMoE achieves 80.31% average accuracy on VTAB-1K (ImageNet-21K ViT-B/16) and 47.95 mIoU on Kvasir polyp segmentation, with consistent improvements over single-expert prompt tuning baselines.

## Executive Summary
pMoE introduces a mixture-of-experts framework for parameter-efficient visual adaptation. It combines multiple pre-trained models by assigning each expert its own set of learnable prompt tokens and using a shared, learnable dispatcher to dynamically fuse these prompts across transformer layers. The method freezes all backbone parameters and only trains the prompts and dispatcher, offering a strong efficiency-effectiveness trade-off. Evaluated on 47 classification and segmentation tasks (including general and medical domains), pMoE consistently outperforms existing prompt-tuning approaches, notably achieving a +2.36% absolute gain on VTAB-1K and a +2.14 mIoU improvement on Kvasir segmentation.

## Method Summary
pMoE operates with multiple frozen pre-trained Vision Transformers (experts) such as DINO, CLIP, MAE, and MoCo v3. For each expert and each dispatcher-enabled layer, a dedicated set of expert-specific prompt tokens (EPTs) is learned and injected into that expert's input. A shared dispatcher module, implemented as an MLP, processes the current expert state (including EPTs, accumulated prompts, and patch tokens) to produce per-token dispatching weights. These weights are used to compute integrated prompts that are a weighted sum of all experts' prompt tokens for the current layer. The integrated prompts are then fed into each expert's corresponding transformer layer. This process repeats across selected layers, allowing the prompts to be retained and re-dispatched at each depth. After the final layer, the outputs (typically the [CLS] tokens) from all experts are aggregated (e.g., averaged) and passed to a task-specific head for prediction. Only the EPTs and the dispatcher are trained; the backbone experts remain fixed, preserving their pre-trained knowledge while enabling cross-expert synergy.

## Key Results
- On VTAB-1K with ImageNet-21K ViT-B/16, pMoE (augmenting LSPT) achieves 80.31% average accuracy, a 2.36% absolute improvement over LSPT.
- On Kvasir polyp segmentation, pMoE reaches 47.95 mIoU (+2.14 over the best baseline).
- Across 47 visual adaptation tasks (classification and segmentation in general and medical domains), pMoE consistently outperforms existing single-expert prompt tuning methods.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: Expert-specific prompt tokens (EPTs) enable each pre-trained model to specialize in its own representation space without gradient conflicts from other experts' prompts.
- **Mechanism**: Each expert receives a dedicated set of learnable prompt tokens that are injected into that expert's layers during forward passes. These tokens are optimized using gradients only from that expert's outputs, allowing isolated adaptation to the downstream task while preserving the expert's original pre-trained knowledge.
- **Core assumption**: Different pre-trained models (e.g., DINO vs. CLIP vs. MAE) have distinct feature distributions and optimization landscapes; mixing their prompts during training would create conflicting gradient signals and prevent any single expert from specializing effectively.
- **Evidence anchors**:
  - [abstract] "expert-specific prompt tokens" and "assigns expert-specific prompt tokens to multiple pre-trained models"
  - [section 3.2] "a dedicated set of learnable prompt tokens is assigned" to each domain expert; "expert-specific tokens are injected at the input layer"
  - [corpus] Indirect support: PMoE for continual learning (paper 160501) also isolates experts to avoid forgetting; however, pMoE's prompt isolation design is novel and not directly validated by corpus.
- **Break condition**: If all experts are architecturally identical and identically pre-trained (e.g., multiple seeds of same model), separate prompt sets confer no benefit and waste parameters; or if the downstream task requires immediate cross-expert feature alignment from the first layer (not layer-wise isolation).

### Mechanism 2
- **Claim**: The learnable dispatcher dynamically determines per-token contributions from each expert based on the current expert's state, enabling adaptive cross-expert knowledge fusion.
- **Mechanism**: At each dispatcher-enabled layer, for expert *k*, the dispatcher MLP processes `[current EPTs, accumulated prompts, patch tokens]` and produces dispatching weights **D** (shape `Np×K`). Integrated prompts for expert *k* are computed as `ˆPl[n] = D[n] × P_all[n]`, a weighted sum of all experts' *n*-th prompt tokens. This allows fine-grained, per-token routing.
- **Core assumption**: The optimal combination of expert knowledge varies by layer depth, task, and the current expert's internal representation; a learned, dynamic router can discover more effective combinations than static averaging or hand-designed rules.
- **Evidence anchors**:
  - [abstract] "learnable dispatcher to dynamically fuse their contributions across layers"
  - [section 3.3] "Dispatcher layer takes expert-specific states as inputs... output dynamic dispatching weights" and equation for `Dl_expertk`
  - [section 4.3 ablation] Table 8 shows removing dispatcher drops performance (e.g., CUB 83.07 → 83.38), confirming necessity.
  - [corpus] Patch-level routing in MoE (paper 219554) shows sample efficiency benefits from routing; however, pMoE's prompt-token-level routing is a distinct application with limited direct corpus evidence.
- **Break condition**: If experts produce nearly identical representations for all inputs (high redundancy), the dispatcher has no meaningful signal to route on; or if dispatcher capacity (MLP hidden dim) is too small to model complex routing patterns, it may default to uniform weights.

### Mechanism 3
- **Claim**: By retaining and re-dispatching accumulated prompt tokens across layers (rather than discarding them after each layer, as in VPT-deep), pMoE enables long-range prompt dependencies and more complete utilization of prompt-injected information.
- **Mechanism**: In VPT-deep, the prompt tokens appended to layer *l*'s output (`Zl+1_P`) are discarded before layer *l+1*. pMoE feeds these accumulated prompts into the dispatcher at the next layer for that expert, allowing prompt information to propagate, be recombined, and influence deeper layers.
- **Core assumption**: Prompt tokens carry high-level task-specific semantic information that should be preserved and refined throughout the network; treating them as transient input-only tokens wastes potentially valuable information for adaptation.
- **Evidence anchors**:
  - [section 3.3] "tokens `Zl_P` originally discarded by VPT-deep in equation 1 are well considered in pMoE, addressing the issue of incomplete usage of accumulated prompts across layers."
  - [section 4.3 ablation] Not directly isolated, but LSPT (which retains prompts) outperforms VPT-deep; pMoE extends this retention with MoE fusion.
  - [corpus] LSPT paper (Mo et al., 2024b) demonstrates long-term prompt retention helps; pMoE integrates this principle with MoE, though corpus doesn't validate the combined design.
- **Break condition**: If the task primarily requires low-level feature manipulation where persistent prompts cause interference or overfitting; or if the backbone's internal representations are already sufficiently rich, making additional prompt propagation unnecessary.

## Foundational Learning
**Concept: Parameter-Efficient Fine-Tuning (PEFT)**
- **Why needed here**: pMoE is a PEFT method; understanding the motivation (freezing backbone, tuning only small added components) is essential to grasp why pMoE only tunes prompts and dispatcher, not the entire multi-expert ensemble.
- **Quick check question**: What are the key trade-offs between full fine-tuning, adapter-based tuning, and prompt tuning in terms of parameter count, computational FLOPs, and risk of catastrophic forgetting?

**Concept: Vision Transformer Token Dynamics**
- **Why needed here**: pMoE operates by injecting tokens into ViT layers; understanding the distinction between [cls] token, patch tokens, and how they flow through transformer layers (including residual connections) is fundamental to predicting where and how prompts affect representations.
- **Quick check question**: In a standard ViT, describe how the classification token and patch tokens are processed differently through the transformer blocks, and what happens to the output tokens from each block?

**Concept: Mixture-of-Experts (MoE) Routing**
- **Why needed here**: pMoE adapts MoE from model-level to prompt-level; understanding classic MoE (gating network, sparse activation, load balancing) helps reason about the dispatcher's design space and potential failure modes.
- **Quick check question**: In a standard sparse MoE layer, what is the role of the gating network, why is sparse activation (only top-k experts) crucial for efficiency, and what is the "expert imbalance" problem?

## Architecture Onboarding
**Component map**:
Image -> Multiple Pre-trained Experts (K frozen ViTs, e.g., DINO, CLIP, MAE) -> each expert has expert-specific prompt tokens (EPTs) per layer -> shared Dispatcher Layer (MLP) computes dispatching weights -> Integrated prompts (weighted sum of all EPTs) -> Transformer layers (frozen weights) -> expert-specific outputs (incl. [CLS] tokens) -> Aggregation (mean of [CLS] tokens) -> Task Head (classifier/decoder)

**Critical path**:
1. For input image X, each expert generates its own patch tokens Z0_expertk via its patchifier.
2. For each dispatcher-enabled layer l (from 0 to L-1):
   - For each expert k in parallel: compute dispatcher weights Dl_expertk from current state (EPTs, accumulated Z_P, patch tokens).
   - Compute integrated prompts: ˆPl_expertk[n] = Dl_expertk[n] × P_all[n].
   - Feed [ ˆPl_expertk, Zl_expertk ] into expert k's layer l+1.
   - Obtain next-layer state Zl+1_P_expertk, Zl+1_expertk.
3. After final layer, aggregate outputs from all experts (usually mean of [cls] tokens).
4. Pass aggregated representation through task head → prediction.

**Design tradeoffs**:
- **Number of experts (K)**: More experts increase diversity and parameter count but yield diminishing returns (~6-9 optimal) and risk gradient conflicts. Choose experts with complementary pre-training (e.g., self-supervised + language-vision).
- **Dispatcher placement**: Layer-wise dispatchers (as in paper) allow dynamic routing across depths but add parameters; first-layer-only dispatcher reduces cost but limits adaptive fusion depth.
- **Prompt length (Np)**: Longer prompts increase capacity but linearly increase tunable parameters; follow VPT conventions (e.g., 10-50 tokens).
- **Dispatcher MLP architecture**: Paper uses simple MLP; could explore attention-based routers for more complex weighting but at higher cost.

**Failure signatures**:
- **Uniform dispatcher weights**: All Dl_expertk[n] ≈ 1/K. Check: dispatcher learning rate too low, or insufficient capacity (increase MLP width/depth).
- **Single-expert dominance**: One expert's prompts always weighted near 1. Check: that expert's pre-trained features are overwhelming others; consider adding entropy regularization to D or using more diverse experts.
- **Performance below single-expert average**: Indicates negative synergy/expert conflicts. Try: reduce number of experts, increase dispatcher capacity, or ensure experts' feature spaces are aligned (e.g., same normalization).
- **High variance across random seeds**: Dispatcher routing is unstable. Check: use lower learning rate for dispatcher, longer training, or more consistent prompt initialization.

**First 3 experiments**:
1. **Replicate vanilla VPT**: Single-expert VPT on one task to validate your codebase matches reported baseline numbers before adding MoE complexity.
2. **Two-expert sanity check with first-layer-only dispatcher**: Combine two experts (e.g., DINO + CLIP) with dispatcher only at input layer. Expect clear improvement over simple averaging of expert predictions. If not, visualize dispatcher weights—are they learning non-uniform routing?
3. **Dispatcher necessity ablation**: Compare full pMoE (with dispatcher) against pMoE without dispatcher (just static average of all EPTs per layer). The latter should underperform across tasks, confirming the dispatcher's role. Also inspect per-layer dispatcher weights—do they vary systematically by task type (e.g., medical vs natural)?

## Open Questions the Paper Calls Out
### Open Question 1
- **Question**: How can pMoE's dynamic dispatcher be architected to maximally balance computational efficiency with the optimal integration of diverse expert knowledge?
- **Basis in paper**: [explicit] The authors state that "determining the optimal contribution of each expert dynamically, without inflating computational costs, remains an unsolved problem." They implement a simple MLP-based dispatcher but note in Appendix C that a MoE-based dispatcher itself could be a "better design."
- **Why unresolved**: The paper's dispatcher uses a fixed MLP structure, which may not be the most parameter-efficient or expressive way to learn complex, task-dependent routing policies across experts and layers.
- **What evidence would resolve it**: Systematic comparison of dispatcher architectures (e.g., MLP vs. Transformer vs. MoE) measuring the trade-off between added tunable parameters, FLOPs, and downstream task performance across diverse benchmarks. Ablations on router complexity and sparsity mechanisms are needed.

### Open Question 2
- **Question**: What specific factors (e.g., pre-training data domain, model architecture, objective function) predict which expert combinations will yield the greatest synergistic performance gains for a given downstream task?
- **Basis in paper**: [explicit] The authors combine experts like DINO, CLIP, MAE, and MoCo v3 but do not provide a principled analysis for *why* certain combinations (e.g., DINO+CLIP in Table 9) perform better on specific tasks. The success is attributed to "cross-domain synergies" without identifying their sources.
- **Why unresolved**: Expert selection is currently empirical. Understanding the drivers of synergy (e.g., complementary feature hierarchies, invariance to pre-training augmentations) is crucial for scaling pMoE to larger, more diverse expert pools without exhaustive trial-and-error.
- **What evidence would resolve it**: A large-scale study controlling for expert pre-training variables (data distribution, supervision type, architecture) and measuring pairwise/triplet synergy scores on a taxonomy of downstream tasks (e.g., fine-grained vs. coarse classification, low-texture vs. high-texture segmentation). Analysis of expert prompt token similarity gradients during training could reveal synergy signals.

### Open Question 3
- **Question**: To what extent does pMoE mitigate, rather than inadvertently amplify, biases or failure modes present in individual expert models?
- **Basis in paper**: [inferred] The paper focuses on average performance gains across 47 tasks. There is no analysis of failure cases, error correlation between experts, or whether pMoE systematically corrects certain expert-specific weaknesses (e.g., a general model's poor segmentation细节) or merely averages out errors.
- **Why unresolved**: In high-stakes domains like medical imaging, understanding the model's reliability is as important as its average performance. pMoE's dynamic weighting could potentially down-weight a biased expert, but this is not evaluated.
- **What evidence would resolve it**: Per-task, per-expert error analysis (e.g., failure case studies on medical datasets where a single expert fails). Quantify if pMoE reduces worst-case error rates compared to the best single expert. Test for bias amplification by evaluating group fairness metrics (e.g., performance disparity across demographic subgroups in medical datasets) with and without MoE integration.

### Open Question 4
- **Question**: How does the interpretability of pMoE's learned dispatching decisions enable new insights into the knowledge representations of pre-trained vision transformers?
- **Basis in paper**: [explicit] Figure 2 visualizes the "Mixture-of-Experts path" but provides only a high-level interpretation that paths are "task-specific." The paper does not analyze *what* information each expert layer contributes or how dispatching weights correlate with input features.
- **Why unresolved**: The dispatcher's weights offer a unique lens into how a model dynamically assembles knowledge from diverse sources. Quantifying this could reveal which experts specialize in semantic vs. texture features, or which layers rely on low-level vs. high-level cues.
- **What evidence would resolve it**: Correlate dispatching weights (Dl_expertk) with: (a) input image attributes (e.g., texture strength, object size), (b) internal feature statistics (e.g., attention entropy, feature variance), or (c) pre-training data characteristics. Create saliency maps based on dispatching patterns to visualize "expert specialization" in different spatial regions or channels.

### Open Question 5
- **Question**: Can the pMoE framework be seamlessly integrated with other parameter-efficient fine-tuning (PEFT) paradigms (e.g., adapters, LoRA) to further enhance the efficiency-effectiveness trade-off?
- **Basis in paper**: [explicit] The authors claim pMoE is "compatible with various prompt-tuning baselines" and demonstrate this with VPT, GaPT, and LSPT. However, they do not test integration with non-prompt PEFT methods like adapters or LoRA, which are popular in NLP and increasingly in vision.
- **Why unresolved**: The paper establishes pMoE as a prompt-tuning enhancer, but its core innovation—dynamic expert fusion—could generalize beyond prompt tokens. Exploring hybrid PEFT strategies could unlock new efficiency frontiers.
- **What evidence would resolve it**: Implement and evaluate pMoE+Adapter (replacing prompt tokens with adapter layers) or pMoE+LoRA (using LoRA for expert-specific transformations) on a subset of VTAB/Med-VTAB. Measure parameter count, training time, and performance relative to standalone methods. The goal is to determine if the MoE routing principle is agnostic to the PEFT mechanism.

## Limitations
- Exact hyperparameters (prompt token count, dispatcher MLP architecture, number of dispatcher layers) are not fully specified, requiring empirical search for each task.
- The contribution of long-range prompt retention versus token-level dynamic routing is not disentangled, making it difficult to quantify each mechanism's individual impact.
- Expert selection criteria are unclear; the optimal combination of pre-trained models appears to be determined empirically rather than by a principled rule.

## Confidence
- Core performance claim (pMoE consistently outperforms single-expert PEFT on 47 tasks): **High**
- Mechanism 1 (Expert-specific prompts avoid gradient conflicts): **Medium**
- Mechanism 2 (Learnable dispatcher enables adaptive fusion): **Medium**
- Mechanism 3 (Accumulated prompt retention provides long-range dependencies): **Low–Medium**
