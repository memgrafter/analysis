# DFKI-Speech System for WildSpoof Challenge: A robust framework for SASV In-the-Wild

## Quick Facts
- **arXiv ID:** 2602.02286
- **Source URL:** https://arxiv.org/abs/2602.02286
- **Reference Count:** 0
- **Primary Result:** A tandem SASV system achieves a macro a-DCF of 0.2022 on the WildSpoof test set and 0.03183 on SpoofCeleb eval, significantly outperforming baselines.

## Executive Summary
This paper presents a robust Spoofing-aware Automatic Speaker Verification (SASV) system designed for real-world "in-the-wild" conditions. The core contribution is a tandem framework that first detects spoofing using a self-supervised wav2vec 2.0 frontend with a graph neural network backend and a mixture-of-experts fusion, and then verifies speaker identity with a low-complexity ReDimNet model. The system is enhanced with AS-Norm score normalization and model ensembling. Results on the WildSpoof challenge and SpoofCeleb datasets show substantial improvements in discriminative capability, as measured by the primary macro a-DCF metric.

## Method Summary
The proposed system is a two-stage tandem pipeline. Stage 1 is a spoofing detector that uses a frozen wav2vec 2.0 XLS-R model to extract layer-wise embeddings, which are fused via a learned top-3 layer Mixture-of-Experts (MoE) mechanism and classified by an AASIST graph neural network backend. Stage 2 is a speaker verifier (ReDimNet) trained with a combined SphereFace and Circle loss on mel-spectrograms, using data augmentation (MUSAN, RIRs, RawBoost). For a trial, if the spoof detector flags an utterance as spoofed, a fixed low score (-5) is assigned. Otherwise, the ASV model computes a cosine similarity between enrollment and trial embeddings. This raw score is normalized using AS-Norm with a fixed imposter cohort. Final SASV scores from multiple models are averaged in an ensemble.

## Key Results
- Macro a-DCF of **0.2022** on the WildSpoof challenge test set, substantially beating provided baselines (e.g., 0.3715, 0.7513).
- On SpoofCeleb eval, the ensemble achieves an a-DCF of **0.03183** and an SV-EER of **2.45%**.

## Why This Works (Mechanism)
The system's strength lies in its modular, robust design tailored for in-the-wild noise and spoofing attacks. The wav2vec 2.0 frontend provides rich, self-supervised representations that generalize across acoustic conditions. The MoE fusion adaptively selects the most informative transformer layers for spoofing cues, improving detection robustness. The AASIST backend captures complex spectral-temporal patterns for binary spoof/bona-fide classification. For speaker verification, ReDimNet efficiently mixes 1D and 2D feature processing, while the multi-loss training (SphereFace + Circle) enhances discriminative power. AS-Norm stabilizes scores against cohort distribution shifts, and ensembling averages out model-specific biases. The fixed rejection score for detected spoofing simplifies the SASV decision logic and avoids complex joint optimization.

## Foundational Learning
- **Self-Supervised Speech Representations (wav2vec 2.0):** Pre-trained on vast unlabeled audio, these models learn general acoustic features. *Why needed:* Provides a robust, noise-agnostic frontend for spoof detection without requiring large labeled spoof datasets. *Quick check:* Extract embeddings from a pre-trained XLS-R model and visualize t-SNE for bona-fide vs. spoof utterances.
- **Graph Neural Networks (AASIST):** Processes spectral graphs to model relational structures in audio. *Why needed:* Effectively captures irregular patterns in spoofed speech (e.g., artifacts from vocoding or conversion). *Quick check:* Implement a simple graph conv layer on a hand-crafted spectral adjacency matrix and compare performance to a CNN on a small spoof subset.
- **Mixture-of-Experts (MoE) Fusion:** Dynamically weighs and selects subset of experts (here: transformer layers). *Why needed:* Allows the spoof detector to leverage complementary information from different abstraction levels of the wav2vec encoder, improving robustness to diverse spoof types. *Quick check:* Ablate the MoE by using only the final layer vs. averaging all layers; measure EER on a held-out set.
- **Multiscale Residual Networks (ReDimNet):** Combines 1D temporal and 2D spectral processing streams. *Why needed:* Efficiently captures both fine-grained spectral details and long-term temporal patterns for speaker discrimination. *Quick check:* Replace ReDimNet's 2D branch with a simple CNN and measure SV-EER on VoxCeleb.
- **AngularMargin Losses (SphereFace, Circle):** Modify softmax to enforce angular separation between speaker classes. *Why needed:* Creates more separable speaker embeddings in cosine space, directly improving verification performance. *Quick check:* Train a basic ResNet AM-Softmax on a small speaker set and plot embedding norms/angles.
- **Adaptive Symmetric Normalization (AS-Norm):** Normalizes trial scores using cohort statistics from both enrollment and trial sides. *Why needed:* Mitigates score drift caused by varying recording conditions in the wild, leading to more consistent a-DCF. *Quick check:* Apply AS-Norm vs. no normalization on a development set with artificially added channel noise; compare EER.

## Architecture Onboarding
**Component Map:**
Input Utterance -> wav2vec 2.0 (24 layers) -> MoE (select top-3 non-final + final) -> AASIST -> Spoof Score
If Spoof Score > threshold: Output SASV = -5
Else: Utterance -> Mel-Spectrogram -> ReDimNet -> Speaker Embedding -> Cosine Similarity -> AS-Norm -> SASV Score
Multiple SASV Models -> Ensemble (average) -> Final Score

**Critical Path:** 1) Spoof detection (must reject spoof before ASV); 2) ASV embedding extraction and similarity scoring; 3) AS-Norm; 4) Ensemble fusion.

**Design Tradeoffs:**
- Tandem vs. End-to-End: Tandem simplifies training and allows specialized modules but may not optimize the joint a-DCF objective directly.
- Model Complexity: ReDimNet is chosen for low parameter count (15M) for efficiency, possibly trading off some capacity vs. a larger model.
- Fixed Rejection Score: Using -5 is a heuristic; the optimal penalty might be data-dependent and could be tuned.

**Failure Signatures:**
- MoE selects uninformative layers or gradient mismatch between frontend/backend causes spoof detection EER to plateau.
- AS-Norm cohort from a mismatched domain (e.g., clean VoxCeleb) fails to normalize scores, leading to higher SV-EER on wild data.
- Ensemble diversity is low (e.g., same seed) → no improvement over single model.
- Joint training of wav2vec and AASIST not implemented → spoofing performance degrades on unseen attacks.

**First Three Experiments:**
1. **MoE Gating Verification:** Train spoof detector with/without MoE on a subset; check that gating weights concentrate on a small set of layers (~3-5) and that validation SPF-EER improves vs. single-layer fusion.
2. **AS-Norm Cohort Sensitivity:** Construct cohorts from SpoofCeleb train, VoxCeleb2, and a held-out wild subset. Apply AS-Norm and plot score distributions for bona-fide and target trials; identify which cohort minimizes SV-EER on the WildSpoof dev set.
3. **Ensemble Composition:** Train 3 ReDimNet models with different random seeds. Fuse SASV scores by averaging and by weighted averaging (weights from validation a-DCF). Measure a-DCF delta on SpoofCeleb eval; confirm that simple averaging yields consistent gains.

## Open Questions the Paper Calls Out
### Open Question 1
Does jointly training the spoofing detector and speaker verifier in an end-to-end manner improve overall SASV performance compared to the tandem system with fixed rejection?

### Open Question 2
What is the optimal number and selection of wav2vec 2.0 transformer layers to fuse via the mixture-of-experts (MoE) for robust spoofing detection in-the-wild?

### Open Question 3
To what extent does fine-tuning a pre-trained ASV model (ReDimNet) on in-the-wild spoofed data (SpoofCeleb) affect speaker discriminability under domain shift, and what fine-tuning strategies (depth, regularization) yield the best SASV performance?

### Open Question 4
How does the system generalize to unseen spoofing attacks (e.g., novel codecs, voice conversion techniques) that were not observed during training?

## Limitations
- The tandem design, while modular, does not directly optimize the joint a-DCF objective, potentially leading to suboptimal trade-offs between spoof detection and speaker verification.
- The fixed rejection score (e.g., -5) is a heuristic choice; its optimality may vary across datasets and acoustic conditions, and it is not learned from data.
- Performance relies on pretrained models (wav2vec 2.0, ReDimNet) that may carry biases from their training corpora, possibly limiting adaptation to certain languages or accents not represented in pretraining.
- AS-Norm normalization is sensitive to the choice of cohort; using an unrepresentative cohort (e.g., from a mismatched domain) can degrade score calibration.
- The evaluation is limited to two in-the-wild datasets; further validation on additional benchmarks (e.g., ASVspoof 2021) is needed to confirm generalizability.
- The overall system complexity (two deep networks plus ensembling) may pose challenges for real-time or resource-constrained deployment despite the use of a lightweight ReDimNet.

## Confidence
The reported results are based on the official WildSpoof and SpoofCeleb evaluation protocols with standard train/dev/test splits. Multiple random seeds and model ensembling were employed to reduce variance, enhancing the reliability of the macro a-DCF and SV-EER numbers. However, the inherent variability of in-the-wild data and the reliance on a single test set for each dataset may limit the robustness of the reported performance. Moreover, hyperparameter choices (e.g., fixed rejection score, AS-Norm cohort) were tuned on development data, which might introduce optimistic bias if the development distribution differs from truly unseen environments.

## Next Checks
1. **Ablation of MoE top-k selection:** Vary the number of selected layers (k = 1, 2, 3, 4) to determine the optimal configuration for spoof detection EER and overall a-DCF.
2. **AS-Norm cohort analysis:** Compare cohorts from SpoofCeleb train, VoxCeleb2, and in-the-wild collected data; evaluate score distributions and SV-EER to identify the most robust cohort selection strategy.
3. **Fixed rejection score sensitivity:** Sweep the rejection score values (e.g., -1, -3, -5, -10) on the development set to measure its impact on the a-DCF trade-off; consider learning a rejection threshold via ROC analysis.
4. **Cross-dataset generalization:** Test the system on additional in-the-wild benchmarks such as ASVspoof 2021 logical access and deepfake datasets to assess whether performance translates beyond the original challenge data.
5. **System efficiency profiling:** Measure inference latency, memory consumption, and throughput of the full tandem pipeline (including ensemble) on target hardware to evaluate feasibility for real-world deployment.
