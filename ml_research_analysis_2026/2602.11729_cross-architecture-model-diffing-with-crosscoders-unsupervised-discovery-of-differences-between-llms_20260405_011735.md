# Cross-Architecture Model Diffing with Crosscoders: Unsupervised Discovery of Differences Between LLMs

## Quick Facts
- **arXiv ID**: 2602.11729
- **Source URL**: https://arxiv.org/abs/2602.11729
- **Reference count**: 40
- **Primary result**: Dedicated Feature Crosscoders (DFCs) enable cross-architecture diffing by partitioning the feature space, uncovering exclusive model features with high interpretability and steering effects while maintaining reconstruction quality.

## Executive Summary
Model diffing compares internal representations of LLMs to identify differences, but existing crosscoder approaches are limited to base-versus-finetune settings and naturally favor shared features over exclusive ones. This paper introduces Dedicated Feature Crosscoders (DFCs), which partition the feature dictionary into model-exclusive and shared subsets, structurally preventing exclusive features from being optimized for the other model’s reconstruction. In synthetic experiments, DFCs recover more exclusive concepts than standard crosscoders. When applied to real model pairs, DFCs discover meaningful behavioral differences such as CCP alignment in Qwen3-8B and Deepseek-R1, American exceptionalism in Llama3.1-8B-Instruct, and a copyright refusal mechanism in GPT-OSS-20B. These features demonstrate high steering-based exclusivity (up to 5/5) and produce expected behavioral shifts upon activation, while achieving reconstruction quality comparable to standard crosscoders (~81.7% fraction of variance explained). The results establish DFCs as a scalable tool for unsupervised cross-architecture model analysis.

## Method Summary
Dedicated Feature Crosscoders (DFCs) extend the crosscoder framework to cross-architecture settings by explicitly partitioning the feature dictionary into model-exclusive and shared compartments. The training pipeline begins by aligning activation pairs from the middle layers of two models (handling tokenizer mismatches with a greedy window expansion algorithm). A crosscoder encoder projects each model’s activations into a shared sparse representation using BatchTopK. The decoder for each model is masked to use only its exclusive and shared features, severing gradient flow from the other model’s reconstruction loss for exclusive features. The total loss combines reconstruction losses for both models and an auxiliary dead-feature revival loss (AuxK). This design removes the implicit prior for shared features, forcing dedicated capacity to capture residual, model-specific patterns. After training, features are interpreted via automated max-activating examples and validated with activation steering, while exclusivity is quantified using a stitching-based metric with LLM judges.

## Key Results
- In a controlled toy model, DFCs achieve higher recovery of ground-truth exclusive concepts compared to standard crosscoders, especially under limited dictionary size.
- Real-world applications reveal interpretable model-exclusive features: CCP alignment in Qwen3-8B and Deepseek-R1, American exceptionalism in Llama3.1-8B-Instruct, and a copyright refusal mechanism in GPT-OSS-20B.
- These features exhibit strong steering-based exclusivity (up to 5/5) and elicit expected behavioral changes when activated, while maintaining reconstruction fidelity (~81.7% fraction of variance explained) comparable to standard crosscoders.

## Why This Works (Mechanism)
### Mechanism 1
- Claim: Structural partitioning removes the optimization pressure to learn shared features, enabling exclusive feature discovery.
- Mechanism: By zeroing out decoder weights for the opposite model in exclusive partitions, gradients from that model’s reconstruction error are severed. Thus, exclusive features are trained only on their own model’s error and cannot minimize joint loss by becoming shared.
- Core assumption: Model-exclusive features exist as linear directions unique to one model’s activation space.
- Evidence anchors:
  - [abstract]: "DFCs, which partition the feature space into model-exclusive and shared sets by design, removing the shared prior."
  - [section 2.2]: "By structurally severing the gradient flow (e.g., features in IA receive no gradient signal from Model B’s reconstruction error), we remove the optimization pressure for these features to become shared."
  - [corpus]: The corpus confirms this work extends crosscoders to cross-architecture diffing; prior crosscoders only used for base vs finetune and had shared prior.
- Break condition: If exclusive features require nonlinear combinations or are not separable by simple linear masks, partitioning may prevent learning effective representations.

### Mechanism 2
- Claim: Dedicated capacity guarantees that some features will specialize in differences, even when shared variance dominates.
- Mechanism: By fixing a fraction of the dictionary to each model’s exclusive partition, DFCs force those features to explain residual variance not captured by shared features. This avoids the scenario in standard crosscoders where exclusive features are outcompeted by shared ones for limited capacity.
- Core assumption: The number of true exclusive features is nonzero and does not vastly exceed the dedicated partition size.
- Evidence anchors:
  - [section 3.2.1 toy model]: DFCs achieve higher exclusive concept recovery than baselines in the undercomplete regime (dictionary smaller than ground-truth concepts), where capacity is scarce.
  - [section 3.2.2]: DFCs produce more features with the maximum steering-based exclusivity score (5) compared to standard crosscoders.
  - [corpus]: Related work (Mishra-Sharma et al. 2025) notes standard crosscoders have a shared prior; DFCs explicitly counteract it.
- Break condition: If exclusive features are rarer than the partition size, reserved capacity is wasted; if more numerous, some will be missed, reducing recall.

### Mechanism 3
- Claim: DFCs accelerate exclusive feature learning by eliminating competition with shared features during training.
- Mechanism: In standard crosscoders, all features jointly minimize the combined reconstruction loss, so features that reduce error for both models (shared) are favored early. DFCs isolate exclusive partitions, allowing them to receive unimpeded gradient signals from their own model from the start.
- Core assumption: Exclusive features have similar learnability to shared ones when given dedicated gradients.
- Evidence anchors:
  - [section 3.2.1]: Figure 15 shows that in standard crosscoders, exclusive concepts are learned later than shared ones; DFCs reduce this delay.
  - [section 3.3.1]: Core exclusive features (e.g., CCP alignment) are consistently recovered across seeds and partition sizes in DFCs, suggesting robustness.
  - [corpus]: The corpus includes work on crosscoder training dynamics that highlights the challenge of capturing exclusive features.
- Break condition: If exclusive features are intrinsically harder (e.g., lower activation frequency), they may still be delayed even in DFCs.

## Foundational Learning
- **Sparse Autoencoders (SAEs)**: Why needed: Crosscoders extend SAEs to the multi-model setting; SAEs learn overcomplete dictionaries to disentangle features from a single model’s activations, addressing superposition. Quick check: How does sparsity in SAEs address superposition, and why is an overcomplete dictionary used? Answer: Sparsity encourages each activation to be represented by only a few dictionary features, which helps separate mixed features (superposition) by forcing the dictionary to have specialized features. Overcompleteness (dictionary size >> activation dimension) provides enough capacity to represent any activation with sparse combinations, mitigating the trade-off between reconstruction and interpretability.
- **Cross-Architecture Activation Alignment**: Why needed: Models with different tokenizers produce different token sequences for the same text; crosscoders require activation pairs that correspond to the same semantic content. The paper’s alignment algorithm matches decoded text via greedy window expansion. Quick check: What challenges arise when aligning activations from models with different tokenizers, and why might the final token of a matching window be used? Answer: Different tokenizers produce different token boundaries, so direct token alignment fails. The greedy window expansion aligns by expanding a window until decoded text matches, but this can fail on special characters or chat formats. The final token of a matching window is used because the crosscoder operates on a specific layer’s activations; using the final token ensures the semantic content is complete and avoids partial matches that might misalign.
- **Feature Exclusivity Metrics**: Why needed: To evaluate whether a feature is truly model-exclusive, we need metrics beyond post-hoc decoder norms. The paper introduces a steering-based exclusivity score using model stitching and LLM judges. Quick check: What is the difference between relative decoder norm and steering-based exclusivity, and why might they disagree about a feature’s exclusivity? Answer: Relative decoder norm compares the magnitude of a feature’s decoder vector in each model; a large difference suggests exclusivity but can be confounded by reconstruction needs. Steering-based exclusivity tests whether activating the feature in one model changes behavior while in the other it does not; it directly measures functional exclusivity. They may disagree if a feature has high norm in one model but still affects both models due to shared downstream mechanisms, or if a feature has moderate norm difference but is functionally exclusive due to different roles.

## Architecture Onboarding
### Component Map
Activation collector aligns token sequences from two models and extracts residual stream activations at matched positions. Crosscoder encoder consists of two linear maps (W_A^e, W_B^e) that project activations to a shared dictionary of size D; after averaging pre-activations, BatchTopK induces sparsity. Dictionary partition splits indices into I_A (A-exclusive), I_B (B-exclusive), I_S (shared). Decoder weights for opposite exclusive partitions are zeroed (masked during training). Separate reconstruction decoders (W_A^d, W_B^d) use only their allowed partitions. Loss combines reconstruction losses for both models plus an auxiliary AuxK dead-feature revival loss.

### Critical Path
1. Collect 100M aligned activation pairs from middle layers of both models on a mixed dataset.  
2. Initialize dictionary (e.g., 131072 features) and partition fractions (e.g., 5% exclusive each). Zero forbidden decoder connections.  
3. Train with Adam, BatchTopK (k=200, annealed from 1000), AuxK (α=0.03) for 100k steps. Normalize activations by median L2 norm.  
4. Post-training: For DFC, exclusive features are directly those in I_A/I_B; for standard crosscoder, select by extreme relative decoder norm. Generate automated explanations via max-activating examples.  
5. Validate promising features via activation steering: add scaled decoder vector to residual stream, generate outputs, and assess behavioral change.  
6. Compute exclusivity scores for a sample: train stitching layer, translate decoder vectors, generate steered responses for both models, and have an LLM judge rate similarity.

### Design Tradeoffs
- **Partition size**: Larger exclusive partitions increase recall of exclusive features but reduce capacity for shared ones and raise false positives. Paper uses 5% exclusive, 90% shared.
- **Sparsity (BatchTopK k)**: Controls feature density. Too low → many dead features; too high → less interpretable. Paper uses k=200.
- **AuxK coefficient α**: Balances dead feature revival vs distortion. 0.03 worked; extremes cause instability.
- **Activation normalization**: Scaling median L2 norm to sqrt((d_A+d_B)/2) ensures balanced contribution across models with different activation magnitudes.
- **Alignment algorithm**: Greedy window expansion handles tokenizer mismatches but fails (~0.9%) on special characters/chat formats.

### Failure Signatures
- High dead feature rate (>10%) indicates insufficient capacity, overly aggressive sparsity, or poor learning rate.
- Low detection score (<0.8) for most features suggests an uninterpretable dictionary.
- In toy model, exclusive concept recovery near random (e.g., ~5% for 5% exclusive) means partitioning isn’t working.
- In real models, features supposedly exclusive show strong steering effects in both models → false positive in partition assignment.
- Inconsistent recovery of known features across seeds (e.g., American exceptionalism in 4/5 runs) signals sensitivity to initialization; may need more data or larger partitions.

### First 3 Experiments
1. **Toy model validation**: Compare DFC against standard crosscoder and DSF crosscoder on synthetic data with known exclusive concepts. Measure recovery rate across dictionary sizes.
2. **Llama vs Qwen diff**: Train 5% DFC on 100M tokens. Use automated interpretability to flag features, identify CCP alignment in Qwen and American exceptionalism in Llama. Validate via steering and exclusivity scores.
3. **GPT-OSS vs Deepseek diff**: Apply same pipeline to another architecture pair. Discover copyright refusal and ChatGPT identity in GPT-OSS, and CCP alignment in Deepseek. Show steering effects and high exclusivity.

## Open Questions the Paper Calls Out
- How does the alignment algorithm's failure on ~0.9% of samples (special characters, chat formats) affect the diversity and representativeness of the training data, and thus the discovered features?
- To what extent do DFCs miss nonlinear exclusive features due to the linear architecture, and could hybrid approaches improve coverage?
- How can we reduce reliance on LLM judges for exclusivity scoring, perhaps via automated metrics or human evaluations?
- What is the theoretical relationship between partition fraction and the number/detectability of exclusive features across different model architectures?
- How can training stability and seed sensitivity be improved to ensure consistent recovery of key features like "American exceptionalism" across runs?

## Limitations
- Alignment robustness: The alignment algorithm fails on ~0.9% of samples (special characters, chat formats), potentially biasing the training corpus toward "clean" text.
- Linear assumption: DFCs rely on linear feature directions; nonlinear interactions or distributed representations may be missed or misassigned.
- Exclusivity metric reliance: Steering-based exclusivity scores use LLM judges, introducing subjectivity and possible bias in behavioral assessments.
- Partition sensitivity: Exclusive feature discovery depends on arbitrary partition fractions; wrong choices yield false positives/negatives.
- Seed instability: Some features recover inconsistently across seeds, indicating sensitivity to initialization/data.

## Confidence
- **Structural enforcement of exclusive partitions**: High confidence (validated in toy model and gradient analysis).
- **Real-world exclusive features (e.g., CCP alignment)**: Medium confidence (due to reliance on LLM judges and small sample sizes, though steering effects are strong).
- **Reconstruction quality**: High confidence (~81.7% fraction of variance explained, comparable to standard crosscoders).

## Next Checks
1. **Alignment robustness test**: Run the full pipeline on a deliberately noisy corpus (e.g., code-switched text, emojis) to quantify how alignment failures distort exclusive feature recovery rates.
2. **Activation distribution analysis**: Compare activation magnitudes of DFC-exclusive features across models; genuine exclusivity should correlate with significantly higher activation frequency/amplitude in the assigned model.
3. **Partition size cross-validation**: Systematically vary exclusive partition fractions (1%, 5%, 10%, 20%) across multiple seeds; check recovery stability of known features (e.g., CCP alignment) to identify optimal capacity allocation.
