# Dual Path Attribution: Efficient Attribution for SwiGLU-Transformers through Layer-Wise Target Propagation

## Quick Facts
- **arXiv ID**: 2603.19742
- **Source URL**: https://arxiv.org/abs/2603.19742
- **Reference count**: 27
- **Primary result**: Dual Path Attribution achieves state-of-the-art faithfulness and a 40× speedup over activation patching for component-level attribution in SwiGLU-Transformers.

## Executive Summary
Large language models based on SwiGLU demand efficient and faithful attribution methods to understand how outputs arise from inputs and internal components. Existing approaches are either computationally expensive or lack faithfulness. This paper introduces Dual Path Attribution (DPA), a target-centric framework that analytically decomposes bilinear operations in SwiGLU-Transformers into separate "content" and "control" pathways. By propagating the unembedding vector of the target token backward through a single cached forward pass, DPA computes an effective target for every residual connection, enabling dense attribution with O(1) time complexity relative to the number of components. Empirical evaluations across multiple models and datasets show DPA attains state-of-the-art faithfulness—measured by lower disruption and higher recovery AUC—while being 40× faster than activation patching on long-context tasks. DPA thus enables scalable, precise interpretability for modern LLMs.

## Method Summary
DPA operates in two phases. First, a standard forward pass is executed and all intermediate activations are cached. Second, an analytical backward propagation is performed starting from the unembedding vector of the target output token. The method exploits the bilinear structure of SwiGLU (which multiplies a gated value with a transformed input) to separate each operation into a "content" path that carries information and a "control" path that modulates it. This separation allows the derivation of a local inverse that propagates the target signal through the layer without requiring iterative numerical methods. The propagated target at each residual connection quantifies the contribution of that path to the final logit. Because the backward pass consists of a single linear pass through cached activations, the overall computational cost is O(L) where L is the number of layers, independent of the number of components (e.g., heads, neurons), yielding O(1) per-component complexity. Memory usage is dominated by the cached activations, which is comparable to that needed for activation patching.

## Key Results
- DPA achieves lower disruption and higher recovery AUC than gradient-based, attention-based, and other decomposition methods across multiple models and datasets.
- On long-context tasks, DPA is 40× faster than activation patching while using comparable memory.
- The method provides dense, component-level attribution for every attention head and MLP neuron, scaling efficiently with model size.

## Why This Works (Mechanism)
DPA’s efficiency and faithfulness stem from its analytical decomposition tailored to the SwiGLU non-linearity. SwiGLU’s bilinear form allows a precise separation of information flow into two interpretable pathways: the content (the value being transmitted) and the control (the gating mechanism). By linearizing each operation locally around the cached activation, DPA computes a first-order Taylor expansion that propagates the target signal backward exactly through the residual branches. This avoids the repeated forward passes required by activation patching and sidesteps the noise and saturation issues of gradient-based methods. The backward pass is deterministic and leverages cached data, resulting in O(L) runtime. Moreover, because the decomposition is derived from the actual forward computations, the attributions remain faithful to the model’s behavior, as confirmed by disruption and recovery metrics.

## Foundational Learning
- **SwiGLU Activation**: A gated linear unit that multiplies a linear transformation by a sigmoid-gated input. *Why needed*: Forms the core non-linearity in many modern LLMs (e.g., LLaMA). *Quick check*: Given input x, write the SwiGLU formula and compare to ReLU.
- **Attribution in Transformers**: Methods that assign responsibility for model outputs to specific inputs or internal components. *Why needed*: Essential for interpretability and debugging. *Quick check*: Describe the difference between gradient-based and perturbation-based attribution.
- **Residual Connections**: Skip connections that add a layer’s output to its input. *Why needed*: Enable gradient flow and are the points where DPA aggregates contributions. *Quick check*: Show how a gradient flows through a residual block.
- **Unembedding Layer**: Linear layer that maps final hidden state to vocabulary logits. *Why needed*: Provides the target vector for propagation. *Quick check*: Given hidden state h, compute logits as h * W_U^T.
- **Linearization/Taylor Expansion**: Approximating a non-linear function by its first-order derivative at a point. *Why needed*: DPA uses it to invert SwiGLU locally. *Quick check*: Derive the first-order expansion of f(x)=x * σ(x) around x0.

## Architecture Onboarding
- **Component Map**: Input → Token Embedding → Transformer Layers (each: LayerNorm → Attention → MLP (SwiGLU) → Residual Add) → Final LayerNorm → Unembedding → Logits. DPA inserts a backward propagation module after the forward pass.
- **Critical Path**: Forward pass caches all activations; then, for a chosen target logit, the unembedding vector is propagated backward layer-by-layer using the analytical inverses of SwiGLU and other operations, yielding an attribution tensor for each residual connection.
- **Design Tradeoffs**: Memory (caching all activations) vs. speed; linearization error vs. computational cost; faithful decomposition vs. architectural generality.
- **Failure Signatures**: Sudden spikes in attribution entropy, mismatch with activation patching for highly non-linear units, poor recovery on synthetic tasks with known ground truth.
- **First Experiments**:
  1. On a 2-layer toy Transformer, manually compute DPA attributions and compare against exhaustive ablation (removing each component) to verify correctness.
  2. On a small LLaMA model (e.g., 7B), compare DPA token attributions with gradient-based Integrated Gradients on a question-answering task to assess agreement.
  3. Measure DPA’s runtime and memory as sequence length increases (e.g., 1k, 8k, 32k tokens) and compare against activation patching to confirm the 40× speedup claim.

## Open Questions the Paper Calls Out
1. **Generalization to Discrete Routing Architectures**: DPA currently requires manual derivation of inverse functions for each non-linearity. Extending to Mixture-of-Experts or State Space Models (e.g., Mamba) is not straightforward. Needed: an automated toolkit to derive inverses for common operations, reducing per-architecture engineering.
2. **Breakdown of Linearization Approximation**: DPA relies on first-order Taylor expansions, which may fail in highly coupled or synergistic component interactions. Needed: theoretical error bounds based on activation curvature or controlled experiments on synthetic non-linear tasks to characterize failure modes.
3. **Probability-Level Attribution**: DPA traces to the target logit, not the post-softmax probability. Thus it cannot capture indirect mechanisms like suppression of competing tokens. Needed: an extension that incorporates the softmax non-linearity, or studies showing the importance of probability-level effects in competitive settings.
4. **Memory Overhead for Extreme Scales**: Caching dense intermediate activations scales with model size and context length, limiting application to trillion-parameter models or ultra-long contexts. Needed: optimizations such as activation checkpointing, quantization, or distributed computation validated on large-scale setups.

## Limitations
- **Generalizability**: DPA is specifically derived for SwiGLU-Transformers; its applicability to other activations (e.g., GELU, ReLU) or architectures remains untested.
- **Faithfulness Metrics**: Reliance on disruption and recovery AUC may not fully capture attribution quality; no human evaluation or causal robustness tests are reported.
- **Scalability**: Memory usage still scales with model size and sequence length, posing challenges for extremely large models or ultra-long contexts despite O(1) per-component time.

## Confidence
- **Efficiency (O(1) complexity, 40× speedup)**: High – supported by theoretical analysis and empirical benchmarks.
- **Faithfulness (SOTA disruption/AUC)**: Medium – validated on standard metrics but not exhaustive; baseline comparisons are limited.
- **Applicability to SwiGLU-Transformers**: High – method is tailor-made and validated on such models.
- **Generalization beyond SwiGLU**: Low – no evidence provided.
