# Evaluating Game Difficulty in Tetris Block Puzzle
## Quick Facts
- arXiv ID: 2603.18994
- Source URL: https://arxiv.org/abs/2603.18994
- Reference count: 17
- Primary result: Increasing hold (h) or preview (p) reduces difficulty (higher rewards, faster convergence); adding pentominoes increases difficulty, with the T-pentomino causing the most significant slowdown.

## Executive Summary
This paper evaluates the difficulty of Tetris Block Puzzle variants using Stochastic Gumbel AlphaZero (SGAZ), a reinforcement learning agent designed for stochastic environments with limited simulation budgets. The authors test three rule modifications: the number of holdable blocks (h), preview of held blocks (p), and the introduction of additional pentomino block types. Training rewards and convergence speed serve as difficulty metrics. Results show that increasing h or p lowers difficulty, evidenced by near-maximal rewards and rapid convergence; conversely, adding pentominoes raises difficulty, particularly the T-pentomino. The study demonstrates SGAZ as an efficient tool for systematic difficulty assessment across game variants.

## Method Summary
The evaluation employs SGAZ, which extends AlphaZero with Gumbel Top-k selection and an afterstate model to handle stochastic transitions and small simulation budgets. The Tetris environment uses an 8x8 grid and standard tetrominoes (I, J, L, O, S, T, Z). Variants manipulate h (hold capacity) and p (preview of held blocks), and introduce extra pentomino blocks (U, V, X, T). SGAZ trains via self-play for up to 500 iterations, collecting experience to update a neural network that predicts state values and afterstate values. Primary metrics are the final average training reward (last 50 iterations) and the iteration count required to consistently achieve the maximum reward cap of 6750. The authors compare these metrics across rule sets to quantify relative difficulty.

## Key Results
- Hold capacity (h) strongly affects difficulty: h=3 reached near-max reward 6544 within 61 iterations, while h=1 remained at reward 39 and did not converge.
- Increasing preview count p (with fixed h) reduced difficulty, shown by higher rewards and faster convergence.
- Adding pentomino blocks increased difficulty; for h=2, p=0, the T-pentomino required 429 iterations to converge versus 273 for the U-pentomino.
- SGAZ enabled reproducible, sample-efficient comparisons even under high stochasticity, though some extreme configurations failed to converge within the budget.

## Why This Works (Mechanism)
SGAZ combines three key ideas to evaluate game variants efficiently: (1) Gumbel Top-k selection at the root of Monte Carlo Tree Search (MCTS) focuses simulations on the most promising actions under a limited budget; (2) an afterstate model learns value estimates for stochastic outcomes after a move, accounting for chance nodes; (3) a stochastic variant of AlphaZero’s training loop alternates between self-play data generation and neural network updates. This design allows SGAZ to learn effective policies quickly despite randomness and few simulations, making it a sensitive probe for game difficulty. The training reward reflects the agent’s ability to accumulate points, while convergence speed captures how easily a near-optimal policy can be discovered—both correlate with human-perceived challenge in deterministic settings.

The following concepts underpin SGAZ and its application:

- **Monte Carlo Tree Search (MCTS):** Heuristic search that simulates trajectories from current state to estimate action values. Needed: Enables planning under limited compute. Quick check: Does the agent build a search tree to evaluate moves?  
- **Stochastic Games:** Games with random elements (e.g., block draws) where transitions depend on chance. Needed: Handling randomness is essential for Tetris; SGAZ extends AlphaZero to stochastic settings. Quick check: Are chance nodes explicitly modeled?  
- **Afterstate Model:** Predicts the value of a state after an action but before the next random event. Needed: Allows value estimation in stochastic environments by separating player decision from chance. Quick check: Does the network output a value for afterstates?  
- **Gumbel Top-k:** A top-k selection method using Gumbel noise to sample promising actions without full sorting. Needed: Improves sample efficiency in MCTS when simulation budget is small. Quick check: Is action selection biased towards high prior values with minimal overhead?  
- **AlphaZero:** A model-based RL algorithm that combines MCTS with a learned policy/value network. Needed: SGAZ builds on AlphaZero’s self-play and network update structure. Quick check: Does training alternate between self-play and network updates?

## Architecture Onboarding
**Component Map:**  
Game Environment -> Afterstate Transformer -> MCTS (with Gumbel Top-k) -> Policy & Value Network -> Training Loop  

**Critical Path:**  
1. Self-play: For each step, use MCTS with current network to select an action; execute in environment, record state, afterstate, and reward.  
2. Network update: Sample batches from replay buffer, compute loss (value + policy + afterstate), perform gradient step.  
3. Repeat, updating the network every few iterations.

**Design Tradeoffs:**  
- Simulation budget per move: Too low leads to poor exploration; too high reduces sample efficiency.  
- Afterstate modeling: Adds complexity but essential for stochasticity; may introduce bias if poorly trained.  
- Replay buffer size: Larger buffers stabilize training but increase memory and computational cost.

**Failure Signatures:**  
- Non-convergence within 500 iterations, especially for high-difficulty variants.  
- Reward collapse or high variance across seeds, indicating unstable learning.  
- Afterstate value predictions diverging from actual outcomes.

**First Three Experiments:**  
1. Baseline training (h=3, p=0, standard tetrominoes) to verify SGAZ can achieve near-max reward within ~60 iterations.  
2. Vary h ∈ {1,2,3} with p=0, measuring final reward and convergence iterations; expect monotonic improvement with higher h.  
3. Add a single pentomino (T) to baseline (h=2, p=0) and compare convergence iterations to standard set; expect significant slowdown relative to other pentominoes.

## Open Questions the Paper Calls Out
1. How does banning specific Tetris block types (e.g., excluding T-pentomino) affect game difficulty compared to adding them?  
2. To what extent do SGAZ-derived difficulty metrics correlate with human players’ perceived challenge and enjoyment?  
3. Does SGAZ reliably assess difficulty for high-complexity rule sets (e.g., two added pentominoes) where it failed to converge within the training budget?  
4. How does varying the grid size (e.g., 6x6, 10x10) interact with holding/preview rules and block additions to influence difficulty?  

## Limitations
- **Hyperparameter gaps:** exact simulation budget, network architecture, learning rate, and buffer settings are unreported, hindering exact replication.  
- **Convergence criterion ambiguous:** “consistently reach the maximum total reward” lacks quantitative definition (e.g., reward threshold, streak length).  
- **External validity untested:** Difficulty rankings rely solely on SGAZ performance; no human studies confirm alignment with player experience.

## Confidence
- Increasing hold/preview reduces difficulty: **Medium**  
- Adding pentominoes increases difficulty, especially T-pentomino: **Medium**  
- SGAZ provides efficient, reproducible comparisons: **Low**
