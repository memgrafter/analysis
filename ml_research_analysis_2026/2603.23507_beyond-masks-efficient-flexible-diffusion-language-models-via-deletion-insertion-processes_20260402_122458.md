# Beyond Masks: Efficient, Flexible Diffusion Language Models via Deletion-Insertion Processes
## Quick Facts
- arXiv ID: 2603.23507
- Source URL: https://arxiv.org/abs/2603.23507
- Reference count: 40
- Primary result: DID surpasses MDLM baselines (e.g., RADD) with up to 1.99× training and 1.58× inference speedups on fixed‑length data, and up to 3.42× training and 3.79× inference speedups on variable‑length data, without any hyperparameter tuning.

## Executive Summary
Masked Diffusion Language Models (MDLMs) suffer from computational inefficiency due to processing placeholder tokens (<MASK>) and padding (<PAD>). This work introduces Deletion‑Insertion Diffusion (DID), which replaces masking with a forward deletion process (tokens removed independently) and a backward insertion process. A tractable training objective (DISE for variable‑length, DICE for fixed‑length) uses subsequence count ratios computed efficiently via parallel dynamic programming. Experiments show DID achieves superior language modeling performance compared to strong MDLM baselines under matched compute, with significant speedups (up to 1.99× training, 1.58× inference on fixed‑length; up to 3.42× training, 3.79× inference on variable‑length) and accurate modeling of data length distributions.

## Method Summary
DID models data generation as a continuous‑time Markov chain: forward deletion gradually removes tokens until the sequence is empty; reverse insertion rebuilds the original sequence. A transformer‑based insertion‑score network takes the current (possibly partial) sequence and outputs per‑position, per‑vocabulary insertion scores. The training loss (DISE/DICE) targets the score so that it approximates the ratio of subsequence counts – the number of ways to reach the ground‑truth sequence by inserting a token after a given position. These ratios are computed exactly using a parallel prefix‑suffix dynamic programming algorithm that runs in O(mn) time for sequences of lengths m and n, avoiding the combinatorial explosion of naive enumeration. During inference, τ‑leaping samples multiple insertions per time step from the network scores, approximating the continuous reverse process. For fixed‑length data the constant length allows simplification to a cross‑entropy‑like objective (DICE) with a fixed sum constraint on the scores; for variable‑length data, DISE incorporates time conditioning and a length distribution objective.

## Key Results
- DID outperforms MDLM baselines (e.g., RADD) in language modeling when matched for compute.
- For fixed‑length data, DID achieves up to 1.99× training and 1.58× inference speedups.
- For variable‑length data, DID achieves up to 3.42× training and 3.79× inference speedups while accurately modeling length distributions.

## Why This Works (Mechanism)
**Mechanism 1: Elimination of <MASK> and <PAD> Overhead**  
DID removes the need to process placeholder tokens by replacing masking‑unmasking with deletion‑insertion. The forward process deletes real tokens until the sequence is empty, and the backward process inserts real tokens starting from empty. This avoids the ~50% FLOPs spent on <MASK> tokens in MDLMs under a log‑linear schedule and eliminates <PAD> overhead in variable‑length settings. *Evidence:* Abstract explicitly states elimination of two major overhead sources; Section 3.1 defines forward deletion; Section 4.1 reports speedups (1.99×/1.58× fixed; up to 3.42×/3.79× variable).

**Mechanism 2: Tractable Insertion‑Score Training (DISE/DICE)**  
The concrete diffusion score is intractable because the number of possible next states varies. DID introduces an insertion score parametrization ¯s(xt,t)[i,v] that predicts the contribution of inserting token *v* after position *i*. The DISE objective trains these scores to match the subsequence count ratio N(Ins(xt,i,v),x0) / N(xt,x0). For fixed‑length data this simplifies to DICE, a cross‑entropy‑like loss with a normalization constant. *Evidence:* Section 3.3 derives DISE using Lemma 1 to switch summation from states to actions; Section 3.5 shows fixed‑length simplification; Appendix D.6 provides proof via Jensen’s inequality.

**Mechanism 3: Parallel Dynamic Programming for Subsequence Counting**  
Computing the N‑ratios naively would be O(mn²V). DID uses two DP tables: prefix counts N(xt[:i], x0[:j]) and suffix counts N(xt[i:], x0[j:]). Both run in O(mn); their element‑wise product yields N(Ins(xt,i,v),x0) for all i,v in O(mn) total. Batching and log‑domain arithmetic make it feasible for typical sequence lengths. *Evidence:* Section 3.4 states the complexity reduction; Appendix E.4 details batched implementation; Appendix G.1 shows empirical sublinear scaling (power‑law exponent ≈1.26).

*Why needed:* DID models deletion and insertion as CTMCs with time‑dependent rates; the training objective (DSE) derives from CTMC time reversal properties.

**Concept: Insertion Score vs Concrete Score**  
*Why needed:* The concrete score s(xt,t)^y is intractable due to variable cardinality of possible y. Insertion score ¯s(xt,t)[i,v] provides a fixed‑shape alternative enabling efficient training and sampling.

**Concept: τ‑leaping for Parallel Sampling**  
*Why needed:* To sample multiple insertions per step for parallel decoding, approximating the CTMC with a finite Δt where several events can occur simultaneously.

## Architecture Onboarding
**Component Map (data flow)**  
Training: x0 → Forward deletion (CTMC) → x_t → Insertion Score Network → insertion scores → DP Module (prefix/suffix tables) → N‑ratios → DISE/DICE loss → gradients → optimizer/EMA.  
Inference: start with [BOS] → τ‑leaping Sampling Module (scores → multiple insertions) → x_{t-Δt} → repeat for N steps.

**Critical Path**  
1. Sample a ground‑truth sequence x0 and a time t ~ U[0,1].  
2. Construct x_t by independently keeping each non‑BOS token with probability 1−e^{−σ̄(t)}.  
3. Run the DP to compute all N(xt,x0) and N(Ins(xt,i,v),x0) ratios.  
4. Compute DISE (variable) or DICE (fixed) loss; backpropagate through the insertion‑score network.  
5. For generation, initialize xt = [BOS] at t=1; repeatedly subtract Δt = 1/N, compute per‑position insertion probabilities, sample one action per position in parallel, and apply insertions sorted by position.

**Design Tradeoffs**  
- Fixed vs. variable length: Fixed length enables time‑independent scores and the simplified DICE objective; variable length requires time conditioning and DISE.  
- DP precision: float64 is optimal but costly; float32 in log‑domain works with small numerical errors (~10⁻⁴).  
- Insertion normalization: For DICE, the network must enforce ∑_{i,v} ¯s = K−|xt| exactly (K is fixed length); for DISE the constraint is not required but scores must be positive.

**Failure Signatures**  
- DP overflow/underflow: Check for -inf or NaN in N‑ratios; switch to log‑domain implementation.  
- Normalization mismatch: If ∑_{i,v} ¯s deviates significantly from the target (K−|xt|), DICE training may diverge; enforce via output transform.  
- Degenerate generations: Compare output length distribution to training data; a mismatch suggests the score network failed to learn length dynamics.

**First 3 Experiments**  
1. DP unit test: For small sequences (|x0|=5, |xt|=2), brute‑force enumerate all deletion paths and verify DP‑computed N(xt,x0) matches.  
2. Overfitting test: Train a tiny DID (2 layers) on a single sentence until loss → 0; confirm generated samples perfectly reconstruct the example.  
3. Baseline comparison: Match FLOPs with RADD on OpenWebText‑tiny; verify >1.2× speedup while maintaining comparable perplexity.

## Open Questions the Paper Calls Out
1. **Scaling to large models and diverse datasets** – The paper notes that due to resource constraints, experiments were limited to smaller scales; performance on 10B+ parameters and large‑scale datasets remains unexplored.  
2. **Generality across MDLM variants** – Most comparisons are against RADD; other MDLM implementations (e.g., SMDM, FlexMDM) might interact differently with the deletion‑insertion paradigm, so the superiority of DID is not proven across the board.  
3. **Reducing DP overhead for very long sequences** – DP consumes 7.2%–27.6% of training time and does not scale linearly; no approximations or alternatives are explored, which could become a bottleneck for >2k token sequences.  
4. **Impact on fine‑grained linguistic coherence** – Insertion changes absolute positions, potentially affecting local dependencies like subject‑verb agreement; the paper lacks syntax‑focused evaluations (e.g., error rates on challenge sets).  
5. **Applicability of DICE simplification to variable‑length data** – DICE assumes constant |x0|, which is invalid for natural variable‑length corpora; DISE was used instead, and a mixed approach that retains DICE’s efficiency is untested.

## Limitations
- Ambiguity regarding the `<BOS>` token (whether it is included in normalization constants or deletable) may affect implementation details.  
- Exact τ‑leaping sampling procedure (e.g., number of insertions per step) is not fully specified, potentially influencing quality and measured speedups.  
- Data preprocessing details (tokenizer settings, document splitting, separator handling) are not explicitly stated, which could hinder exact replication.

## Confidence
- Elimination of `<MASK>`/`<PAD>` overhead: **High**  
- Tractability of insertion‑score objective (DISE/DICE): **Medium**  
- Feasibility of parallel dynamic programming for subsequence counting: **High**
