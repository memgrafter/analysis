# Towards Differentiating Between Failures and Domain Shifts in Industrial Data Streams

## Quick Facts
- arXiv ID: 2603.18032
- Source URL: https://arxiv.org/abs/2603.18032
- Reference count: 40
- Primary result: A three-part method (Page-Hinkley with KL divergence, CCSA domain adaptation, SHAP explanations) accurately detects changepoints and differentiates between normal product shifts and failures in industrial data streams, validated on cold rolling steel dataset.

## Executive Summary
Industrial processes often experience changes in operating conditions, such as switching products or encountering failures. Standard anomaly detectors cannot reliably distinguish between benign domain shifts (e.g., new product) and critical failures, leading to unnecessary downtime or missed alarms. This paper introduces a framework that combines change point detection, online domain adaptation, and explainable AI to address this gap. The core components are: (1) a Page-Hinkley detector fed by KL divergence estimates to flag distribution changes; (2) a supervised contrastive semantic alignment (CCSA) algorithm to quickly adapt the anomaly model to the new domain using minimal labeled data; and (3) SHAP explanations that track feature importance over time, enabling operators to visually differentiate failures from normal shifts. Evaluated on a cold rolling steel dataset with four products and a bearing failure case, the method pinpointed changepoints with high accuracy (e.g., at samples 8010, 8550, 9042, 9515 vs. true 8000, 8500, 9000, 9500). SHAP trajectories for key sensors (current_2, torque_2) showed a distinct drop during failure adaptation, contrasting with relatively stable trends during normal product shifts, which experts validated as a clear signal. The work provides a practical, interpretable approach for monitoring industrial streams.

## Method Summary
The proposed framework operates in three sequential stages. First, it continuously monitors multivariate sensor streams by computing the KL divergence between a fixed reference window and the current data window; this divergence feeds into a Page-Hinkley cumulative sum test to detect significant distribution changes. When a changepoint is flagged, the reference window is reset and the second stage begins: a supervised contrastive domain adaptation (CCSA) fine-tunes the existing anomaly detection neural network on a small batch of labeled data from the new domain, aligning feature representations between source (previous domain) and target (new domain) while preserving class separation. After adaptation, the third stage calculates SHAP values for each instance in the adaptation batch, aggregates the median SHAP per feature over time, and presents these trajectories to a human operator. The operator then decides whether the change is a normal product shift or a failure based on the observed pattern, particularly the behavior of expert-identified critical sensors. The entire pipeline is designed for online operation with limited target data.

## Key Results
- Changepoint detection achieved near-exact alignment with true product/failure boundaries (e.g., detected at 8010 vs. true 8000) on the steel dataset.
- Standard anomaly detectors (Isolation Forest, LOF, One-Class SVM, Autoencoder) raised alarms for all products and the failure case, whereas the proposed framework allowed discrimination via SHAP patterns.
- SHAP analysis revealed a pronounced decrease in median importance of sensors `current_2` and `torque_2` during failure adaptation, contrasting with relatively stable trends during normal product shifts; experts validated this as a clear signal.

## Why This Works (Mechanism)
### Mechanism 1: KL Divergence-Page-Hinkley Detector
The modified Page-Hinkley detector uses KL divergence (estimated via k-nearest neighbor distances) between a fixed reference window and the current approximate distribution. The cumulative sum of these divergence scores triggers an alarm when it exceeds a threshold, indicating a statistically significant distributional change. The detector resets the reference window upon detection, enabling it to handle multiple shifts.

### Mechanism 2: Supervised Domain Adaptation via CCSA
After a changepoint, the Contrastive Semantic Semantic Alignment (CCSA) algorithm adapts the anomaly model. It jointly optimizes a classification loss on the small set of labeled target samples and a contrastive loss that pulls together encoded representations of source and target samples of the same class (normal/anomaly) while pushing apart different classes. This aligns the feature space so that the source model generalizes to the target domain with minimal data.

### Mechanism 3: SHAP Trajectories for Discrimination
For each adaptation batch, SHAP values are computed and their median per feature is tracked over time. The key observation is that during adaptation to a bearing failure, the median SHAP values for critical sensors like `current_2` and `torque_2` drop significantly, reflecting the model’s reduced reliance on these features as it learns the failure pattern. In contrast, during normal product shifts, these feature importances remain stable. This temporal pattern is interpretable by operators and serves as the basis for distinguishing failure from domain shift.

**Why needed:** The method relies on transferring knowledge from a source domain (initial product) to a new target domain (different product or failure) without retraining from scratch. CCSA is a specific online domain adaptation technique.

**Why needed:** SHAP provides instance-level feature contributions that are aggregated over time to create a signature of model behavior, enabling human operators to interpret changes.

## Architecture Onboarding
Component map: Input Stream (multivariate sensor data) → KL-PH Detector → CCSA Adaptation Module → SHAP Explanation Module → Human Operator Interface.

Critical path: Data arrives → KL divergence computed against reference window → Page-Hinkley cumulative sum updated → if threshold exceeded, changepoint flagged → reference window reset → CCSA starts/restarts adaptation using incoming labeled batches → adapted model used for anomaly prediction → SHAP computed on each batch → median SHAP per feature tracked and displayed → operator reviews trends and classifies change as domain shift or failure.

Design tradeoffs:
- Reference window size (PH/KL): larger windows yield stable divergence estimates but increase detection latency for sudden changes; smaller windows are noisier.
- Batch size for CCSA: smaller batches allow faster adaptation but may lead to unstable training and poor alignment; larger batches require more target samples before adaptation is effective.
- SHAP explainer choice: KernelSHAP is model-agnostic but slow; TreeSHAP is fast but only for tree models. The neural network-based CCSA forces the use of a slower SHAP variant, impacting streaming performance.

Failure signatures:
- High false positive rate in PH detector: indicates mismatched window size or KL estimation parameters (e.g., k-NN) relative to drift magnitude.
- CCSA fails to converge or yields poor anomaly detection: target domain is too semantically divergent from source, or batch size is insufficient for contrastive alignment.
- SHAP values are flat (no change) or excessively chaotic: model not learning discriminative features, or the failure/product shift is not distinguishable by the model’s representation.

First 3 experiments:
1. **Changepoint Detection Validation:** Run the KL-PH detector on the known labeled stream and verify that detected indices (e.g., 8010, 8550, 9042, 9515) are within an acceptable tolerance of the true boundaries (8000, 8500, 9000, 9500).
2. **CCSA Adaptation Plausibility:** For a detected domain shift (e.g., to Product 2), evaluate the adapted model’s anomaly detection performance (AUC, F1) on a held-out batch from that product. Compare against a non-adapted source model to confirm improvement.
3. **SHAP Pattern Verification:** For the known Failure segment, perform a statistical test (e.g., t-test) on the median SHAP values of `current_2` and `torque_2` before and after the changepoint. Confirm that the decrease during failure adaptation is significantly larger than during any product shift.

## Open Questions the Paper Calls Out
#### Open Question 1: Automating SHAP-based Differentiation
- **Question:** How can the temporal dynamics of SHAP values be algorithmically analyzed to automate the differentiation between failures and domain shifts?
- **Basis:** The paper states in future works: "This process can be automated to some extent by the analysis of the dynamics of explanations over time, instead of raw feature values."
- **Why unresolved:** The current method requires a human operator to interpret SHAP plots, which is time-consuming and subjective.
- **What evidence would resolve:** Develop and validate a computational method that tracks statistical changes in SHAP value distributions (e.g., median shifts, variance) and correlates them with labeled failure and domain shift events in historical data streams.

#### Open Question 2: Extending to Concept Drift
- **Question:** Can the proposed framework be effectively extended to detect and explain concept drift, in addition to domain shifts, in industrial data streams?
- **Basis:** The paper mentions: "The other direction is to focus on concept drift instead of domain shift." and notes that existing works on concept drift lack explainability.
- **Why unresolved:** The method is designed for abrupt domain shifts; concept drift involves gradual changes in feature-label relationships, which may require different detection and adaptation strategies.
- **What evidence would resolve:** Integrate incremental concept drift detectors (e.g., ADWIN) with the domain adaptation model and SHAP explanations, then evaluate on streams with gradual shifts to measure detection accuracy and explanation quality.

#### Open Question 3: Robustness to Gradual Shifts
- **Question:** How robust is the Page-Hinkley detector with KL divergence in identifying changepoints during gradual data shifts compared to abrupt shifts?
- **Basis:** The paper uses PH for changepoint detection but acknowledges: "proper changepoint identification in the case of gradual data shifts" is a limitation, implying current implementation may fail on gradual shifts.
- **Why unresolved:** PH is designed for abrupt changes; gradual shifts might cause delayed or missed detections, affecting downstream differentiation.
- **What evidence would resolve:** Test the detector on synthetic or real datasets with controlled gradual shifts, measure metrics like detection delay and false positive rate, and compare with other drift detectors like EDDM or DDM.

#### Open Question 4: Root Cause Explanation
- **Question:** Can SHAP-based explanations be enhanced to identify root causes of failures or domain shifts, not just feature importance?
- **Basis:** The paper states: "It does not explicitly explain the root causes of the failures or the domain shifts."
- **Why unresolved:** SHAP shows how features contribute to predictions but doesn't explain why feature values changed, limiting actionable insights for maintenance.
- **What evidence would resolve:** Combine SHAP with causal inference techniques (e.g., Granger causality) or incorporate domain knowledge graphs to trace feature changes back to underlying physical causes, validated by expert feedback.

#### Open Question 5: Quantitative SHAP Patterns
- **Question:** What quantitative patterns in SHAP value distributions over time reliably distinguish failures from domain shifts?
- **Basis:** The paper shows in Figure 7 that SHAP values for current_2 and torque_2 decrease during failure but relies on visual inspection; it notes: "Automating the decision–making process... remains a direction for future research."
- **Why unresolved:** No automated thresholds or statistical tests are provided; operator judgment is needed, which may vary.
- **What evidence would resolve:** Extract features from SHAP time series (e.g., median drop magnitude, rate of change) for known events, train a classifier or rule-based system, and evaluate precision/recall on unseen streams.

## Limitations
- **Generalizability:** The approach assumes the failure and product shift domains share sufficient semantic similarity with the source for CCSA feature alignment to be effective; this may not hold for drastically new failure modes.
- **Differentiation Robustness:** The SHAP-based distinction relies on qualitative expert interpretation; the paper lacks a rigorous statistical validation that the observed patterns are consistently different across multiple product shifts and failures.
- **Ablation Absence:** The paper does not isolate the contributions of the three components (KL-PH detection, CCSA adaptation, SHAP tracking), leaving their individual impact unclear.

## Confidence
- **High:** KL-PH detector accurately identifies changepoints in the evaluated stream; mechanism aligns with established drift detection theory and is quantitatively supported.
- **Medium:** CCSA domain adaptation provides effective online model updating with limited target data; evidence is plausible but limited to one dataset and without strong baseline comparisons.
- **Low:** SHAP trajectory patterns robustly differentiate failures from domain shifts; this key claim rests on a single case study and expert opinion, without statistical generalization or automation.

## Next Checks
1. Perform a comprehensive statistical analysis of SHAP value changes across all domain shifts and the failure case (e.g., ANOVA on median SHAP shifts) to establish quantitative significance.
2. Conduct a sensitivity analysis of the KL-PH detector by varying reference window size and k-NN parameters; measure detection delay and false positive rate on the known stream to determine robust operating ranges.
3. Test the framework's limits by introducing a novel, semantically divergent failure mode not present in the source domain; verify that while the changepoint is detected, SHAP patterns do not show the expected failure signature, confirming the semantic similarity requirement.
