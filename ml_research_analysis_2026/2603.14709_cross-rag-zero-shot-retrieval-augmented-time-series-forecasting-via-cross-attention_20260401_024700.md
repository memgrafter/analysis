# Cross-RAG: Zero-Shot Retrieval-Augmented Time Series Forecasting via Cross-Attention

## Quick Facts
- **arXiv ID**: 2603.14709
- **Source URL**: https://arxiv.org/abs/2603.14709
- **Reference count**: 40
- **Primary result**: Cross-RAG achieves average MSE of 0.191, outperforming TS-RAG (0.197) and various TSFMs in zero‑shot forecasting across seven datasets.

## Executive Summary
Time series foundation models (TSFMs) often struggle to generalize zero‑shot to unseen datasets. Existing retrieval‑augmented forecasting (RAG) methods use a fixed number of retrieved samples, which can introduce irrelevant information and limit performance. Cross‑RAG addresses this by selectively attending to query‑relevant retrieved samples through cross‑attention between the query and retrieved inputs, complemented by retrieval self‑attention and a query skip‑connection. In experiments on seven datasets, Cross-RAG consistently improves forecasting accuracy, demonstrates robustness across diverse retrieval settings, and does so with minimal additional computational cost.

## Method Summary
The Cross‑RAG framework first retrieves candidate time series samples from a knowledge base given a query input. Retrieval is performed directly in data space (raw time series values) for efficiency. The core of the method is a cross‑attention module that computes interactions between the query and each retrieved sample, producing relevance‑weighted representations. A self‑attention layer further refines the retrieved context by modeling relationships among the retrieved samples. A skip‑connection adds the original query representation to the refined context before passing it to a forecasting head (e.g., a pretrained TSFM). This design allows the model to dynamically emphasize useful retrievals while preserving the query’s own information, yielding stronger zero‑shot generalization.

## Key Results
- Cross-RAG attains an average MSE of 0.191, beating the strongest RAG baseline TS‑RAG (0.197) and various TSFMs.
- Performance remains robust under varied retrieval scenarios, including different numbers of retrieved samples, random retrieval, smaller knowledge bases, and cross‑dataset retrieval.
- Efficiency analyses show data‑space retrieval is 339.5× faster than latent‑space retrieval; the added modules increase parameters by only ~4% with negligible inference overhead.

## Why This Works (Mechanism)
Cross‑RAG works because the cross‑attention mechanism explicitly models input‑level relevance between the query and each retrieved sample, allowing the model to up‑weight informative retrievals and down‑weight irrelevant ones. The self‑attention over the retrieved set captures interactions among the candidates, enriching the contextual representation. The skip‑connection ensures that the original query information is retained, preventing the model from being overwhelmed by retrieved content. Together, these components form a selective fusion that improves zero‑shot forecasting without sacrificing efficiency.

## Foundational Learning
- **Time Series Foundation Models (TSFMs)**: Pretrained models that map raw time series to forecasts. Why needed: provide a strong base without retraining. Quick check: Does the pipeline use a frozen pretrained backbone?  
- **Retrieval‑Augmented Generation (RAG)**: Augmenting a model with external knowledge retrieved from a datastore. Why needed: improve zero‑shot generalization by adapting to the query via retrieved examples. Quick check: Are external samples fetched and incorporated during inference?  
- **Cross‑Attention**: Attention mechanism between two distinct sequences (query and retrievals). Why needed: compute dynamic relevance at the input level. Quick check: Is there a layer where query tokens attend to retrieval tokens (or vice versa)?  
- **Data‑Space Retrieval**: Retrieval performed on raw time series values instead of latent embeddings. Why needed: drastically reduces retrieval latency. Quick check: Is the similarity search carried out directly on the original data?  
- **Selective Attention**: Assigning different importance weights to retrieved samples. Why needed: avoid noise from irrelevant samples. Quick check: Do attention weights vary across retrieved items rather than using uniform averaging?  
- **Skip‑Connection (Residual)**: Adding the original query representation to the transformed features. Why needed: preserve query information and ease gradient flow. Quick check: Is the query vector added to the output of the cross‑/self‑attention blocks?

## Architecture Onboarding
**Component Map**  
Query → Retriever → Retrieved Set  
Query + Retrieved Set → CrossAttention → WeightedRepresentation  
WeightedRepresentation → SelfAttention → RefinedContext  
RefinedContext + Query (skip) → ForecastHead → Predictions  

**Critical Path**  
1. A query time series is fed to the retriever, which searches a knowledge base (data‑space) to obtain the top‑k most similar raw series.  
2. The query and retrieved set are jointly processed by a cross‑attention layer, producing relevance‑weighted retrieval embeddings.  
3. Self‑attention is applied across the weighted retrieval embeddings to model inter‑retrieval relationships.  
4. The resulting context is combined with the original query embedding via a skip‑connection.  
5. The combined representation is passed to a forecasting head (e.g., a linear layer or a pretrained TSFM) to generate the prediction.

**Design Tradeoffs**  
- *Data‑space vs. latent‑space retrieval*: data‑space offers huge speed gains (339.5×) but may sacrifice some precision; latent‑space could yield more semantically similar samples at higher cost.  
- *Cross‑attention complexity*: adds parameters and quadratic attention cost, but enables dynamic weighting; using fewer heads or restricting attention can reduce overhead.  
- *Number of retrievals (k)*: more samples provide broader context but increase noise and computation; Cross‑RAG’s attention mechanism helps mitigate noise but does not eliminate the trade‑off.  
- *Fixed vs. dynamic weighting*: unlike fixed‑average baselines, Cross‑RAG’s attention allows flexible use of retrievals, but requires careful regularization to avoid over‑fitting to spurious similarities.

**Failure Signatures**  
- Performance collapse when the knowledge base contains no relevant samples (cross‑attention cannot compensate for complete absence of signal).  
- Degradation if self‑attention over‑smooths the retrieval representations, losing distinctive information.  
- Under‑utilization of retrievals if the skip‑connection dominates, effectively bypassing the retrieved context.  
- Out‑of‑memory or latency spikes when using very large k, due to attention scaling.

**First Three Experiments**  
1. Baseline validation: Run Cross‑RAG and TS‑RAG on a single dataset with a moderate k (e.g., 10) to confirm the expected improvement.  
2. Retrieval sensitivity: Vary k (e.g., 1, 5, 10, 20) and plot performance to observe the trade‑off between context richness and noise.  
3. Random retrieval sanity check: Replace the retrieved set with randomly sampled series and verify that performance drops significantly, demonstrating that the model indeed leverages relevant information.

## Limitations
- Reported MSE gains are modest (0.191 vs. 0.197) and lack statistical significance testing.  
- Evaluation covers only seven datasets with unclear domain diversity, limiting claims about broad generalizability.  
- Retrieval implementation details (knowledge base construction, indexing, potential data leakage) are missing, hindering reproducibility.  
- Baselines may not include the latest TSFMs (e.g., PatchTST, TimesNet) or recent RAG variants, possibly overstating relative performance.

## Confidence
- Accuracy improvement (Cross-RAG avg MSE 0.191 > TS-RAG 0.197): **Medium**  
- Robustness to retrieval variations (different k, random, smaller KB, cross-dataset): **Medium**  
- Efficiency gains (data-space retrieval 339.5× faster, ~4% parameter increase, negligible overhead): **High**

## Next Checks
1. Conduct paired statistical tests (e.g., Wilcoxon signed‑rank) on per‑dataset errors to confirm the significance of the observed improvements.
