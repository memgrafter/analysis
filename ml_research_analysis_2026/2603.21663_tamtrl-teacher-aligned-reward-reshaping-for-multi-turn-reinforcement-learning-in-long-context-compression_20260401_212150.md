# TAMTRL: Teacher-Aligned Reward Reshaping for Multi-Turn Reinforcement Learning in Long-Context Compression

## Quick Facts
- arXiv ID: 2603.21663
- Source URL: https://arxiv.org/abs/2603.21663
- Reference count: 40
- Primary result: TAMTRL achieves average relative improvements of 1.87% and 2.02% on Qwen3‑0.6B and 1.7B across seven long‑context benchmarks, outperforming baselines while using lower training overhead.

## Executive Summary
TAMTRL tackles temporal credit assignment in multi‑turn long‑context reinforcement learning where intermediate memory updates are unobserved. It introduces a self‑supervised teacher signal derived from the same model fed a context filtered to contain only task‑relevant documents. The teacher scores the student’s memory update via normalized token probabilities, producing turn‑level rewards that guide policy optimization. The approach avoids external evaluators and demonstrates consistent gains over strong baselines on multiple QA benchmarks with efficient training.

## Method Summary
The task is to train a model that processes long documents chunk‑by‑chunk, updating an internal memory and eventually answering a query. Formally framed as a partially observable Markov decision process, at each turn the student observes the current chunk and memory, then generates a new memory. TAMTRL uses the current policy as a teacher: for each student memory update, the teacher (same parameters) evaluates the probability of that update given the query, the student’s prior memory, and a filtered chunk containing only ground‑truth relevant paragraphs. The average token probability is min‑max normalized across the batch to yield a stable teacher score. The final turn‑level reward multiplies this score by the binary outcome reward (exact match of the final answer), ensuring that incorrect trajectories receive zero reward while correct ones are shaped proportionally. Training proceeds with the DAPO algorithm—a group‑relative policy gradient method that samples multiple rollouts per query and applies token‑level clipped updates with a dynamic sampling buffer to focus on high‑quality data.

## Key Results
- Outperforms MemAgent, LLM‑judge, and PRM with average relative improvements of 1.87% and 2.02% on Qwen3‑0.6B and 1.7B.
- Achieves gains across seven multi‑hop QA benchmarks.
- Training overhead is lower than PRM and LLM‑judge methods.

## Why This Works (Mechanism)

### Mechanism 1: Teacher‑Aligned Turn‑Level Rewards
- **Claim:** TAMTRL provides fine‑grained supervision by using the same model as a teacher, with access to globally relevant documents, to score the student’s memory update via normalized token probabilities.
- **Mechanism:** For each turn `t`, the student receives `[q, D_t, M_t]` (query, current chunk, memory) and produces `M_{t+1}`. A teacher model (identical parameters) is fed `[q, C_t, M_t]`, where `C_t` is the chunk filtered to contain only task‑relevant paragraphs. The teacher computes the average token probability of the student’s output `M_{t+1}`: `p_t = (1/|M_{t+1}|) Σ π_θ(m_{t+1}^{(i)} | [q, C_t, M_t])`. This score measures alignment with an ideal extraction of key information.
- **Core assumption:** The teacher’s probability, computed on relevant‑only context, is a proxy for the quality of the student’s memory update.
- **Evidence anchors:** Abstract mentions leveraging relevant documents as teacher signals via normalized probabilities. Section 4.3 details teacher input construction and score computation. Neighboring work (e.g., MemAgent) uses multi‑turn RL but lacks self‑supervised teacher alignment.
- **Break condition:** Poorly defined or misaligned `C_t` yields noisy teacher signals, harming performance (Section 6.5 global‑reward ablation supports this).

### Mechanism 2: Min‑Max Normalization for Reward Stability
- **Claim:** Normalizing teacher scores across the batch stabilizes the reward magnitude for advantage calculation.
- **Mechanism:** Raw average probabilities `p_t` vary widely. TAMTRL computes `ˆp_{tj} = (p_{tj} - min) / (max - min)` over all queries, turns, and rollouts in the batch, rescaling scores to `[0,1]`.
- **Core assumption:** The relative ordering within a batch is meaningful; affine transformation does not distort ordering while fixing scale.
- **Evidence anchors:** Section 4.3 explicitly describes normalization to maintain stable magnitudes. Section 6.4 ablation (`w/o mm‑norm`) leads to complete training failure, demonstrating necessity.
- **Break condition:** Extreme outliers could compress the dynamic range for typical trajectories, diminishing sensitivity.

### Mechanism 3: Multiplicative Outcome Modulation
- **Claim:** Multiplying the normalized teacher score by the binary final‑answer reward (`R_{tj} = ˆp_{tj} · r_j`) dissuades learning from incorrect final answers while providing fine‑grained signals for correct ones.
- **Mechanism:** If `r_j = 0` (final answer wrong), all turns in that trajectory receive zero reward. If `r_j = 1`, each turn’s reward is proportional to its teacher score, encouraging memory updates consistent with the teacher’s global view.
- **Core assumption:** Within correct trajectories, higher teacher‑score memory updates are more likely to lead to the correct answer.
- **Evidence anchors:** Section 4.4 explains the design. Section 6.5 shows the `plus‑reward` variant (`R = ˆp + r`) performs worse, confirming the multiplicative advantage.
- **Break condition:** In a correct trajectory, a low‑probability memory update that is actually necessary could be under‑rewarded, potentially biasing the model toward teacher‑specific patterns.

## Architecture Onboarding
- **Component map:**  
  Data Pipeline → Teacher Scoring Module → Reward Shaping Module → RL Training Module (DAPO)

- **Critical path:**  
  1. Generate a group (G=8) of rollouts per query using the old policy `π_θold`.  
  2. For each turn in each rollout, compute teacher probability using the filtered chunk `C_t`.  
  3. Min‑max normalize all turn scores across the entire batch.  
  4. Multiply normalized scores by the binary outcome reward (`EM`) to obtain per‑turn rewards `R_{tj}`.  
  5. Compute token‑level advantages (group‑relative) and update the policy with the DAPO loss.

- **Design tradeoffs:**  
  *Teacher‑student alignment cost:* Using the same model avoids external PRM/LLM‑judge training but requires two forward passes per turn (student rollout + teacher scoring).  
  *Relevance filtering dependency:* Performance relies on accurate `C_t` from ground‑truth annotations; generalization to raw documents at test time may suffer (Section 6.5).  
  *Normalization scope:* Min‑max is applied over the full batch; small or homogeneous batches could yield unstable min/max estimates.

- **Failure signatures:**  
  - Training collapse (e.g., `w/o mm‑norm` ablation leads to 0% performance).  
  - Poor generalization if the teacher overfits to the artificially filtered context.  
  - Memory degradation when trajectories with incorrect final answers receive zero rewards, discarding potentially useful intermediate updates.

- **First three experiments:**  
  1. **Validate teacher‑reward correlation:** Plot `ˆp_{tj}` vs. turn‑level correctness (using gold intermediate answers) on a validation set; expect higher scores for accurate memory updates.  
  2. **Ablate normalization:** Compare full TAMTRL against `w/o mm‑norm` and `w/o l‑norm`; monitor gradient norms and final EM to confirm necessity.  
  3. **Outcome‑only baseline:** Train MemAgent (DAPO) with only final EM reward on the same data; measure the relative improvement gap to isolate credit‑assignment benefits. Also test the `plus‑reward` variant to confirm multiplicative superiority.

## Open Questions the Paper Calls Out
1. **Robustness to annotation noise**  
   - *Question:* How robust is TAMTRL to imperfections in ground‑truth document annotations used for filtering relevant chunks during teacher scoring?  
   - *Basis:* The method relies on these annotations to construct `C_t` (Section 4.3), but no analysis of annotation errors is provided.  
   - *Why unresolved:* Real‑world datasets may have incomplete or noisy annotations; the impact on teacher probabilities and reward shaping is unknown.  
   - *Resolving evidence:* Controlled experiments introducing noise (e.g., randomly masking relevant paragraphs) and measuring performance degradation compared to clean annotations.

2. **Generalization of min‑max normalization**  
   - *Question:* Does the min‑max normalization strategy introduce dataset‑specific biases that hinder generalization to out‑of‑distribution long‑context tasks?  
   - *Basis:* Normalization is applied across all training responses (Equation 5); the paper does not investigate whether normalization statistics (min/max) generalize to diverse test distributions.  
   - *Why unresolved:* Rewards are anchored to the training set distribution; test data with different token probability scales could cause misalignment.  
   - *Resolving evidence:* Evaluate on benchmarks with vastly different information densities and compare performance with/without dataset‑specific normalization retuning.

3. **Applicability beyond QA**  
   - *Question:* Can the teacher‑aligned reward mechanism generalize to non‑QA long‑context tasks (e.g., summarization, dialogue) where turn‑level quality differs from token probability alignment?  
   - *Basis:* Experiments are limited to seven multi‑hop QA benchmarks (Section 6.1); the assumption that token probabilities reflect memory update quality may not hold elsewhere.  
   - *Why unresolved:* Tasks like summarization lack binary answer matching, and memory updates may prioritize coherence or style over factual token overlap.  
   - *Resolving evidence:* Apply TAMTRL to long‑context summarization (e.g., arXiv papers) or multi‑turn dialogue, using appropriate metrics (ROUGE, BLEU) and comparing against baselines.

4. **Effect of binary outcome reward on partially correct runs**  
   - *Question:* How does the binary outcome reward design affect learning when intermediate memory updates are partially correct but the final answer is wrong?  
   - *Basis:* Turn‑level rewards are modulated by the final outcome (`R = ˆp · r`), so all turns in an incorrect trajectory receive zero reward regardless of intermediate utility (Equation 6).  
   - *Why unresolved:* Some memory updates may correctly retain information even if later steps fail; zero reward forfeits potential learning signals, possibly slowing convergence.  
   - *Resolving evidence:* Modify the reward to incorporate intermediate correctness heuristics (e.g., partial credit for gold evidence overlap) and measure sample efficiency and final performance.

## Limitations
- Heavy reliance on ground‑truth relevance filtering (`C_t`) for teacher scoring; risks overfitting to artificial context and poor generalization to raw documents at test time.
- Ambiguity in min‑max normalization scope (batch vs. dataset) and its impact on stability with small or homogeneous batches.
- Undetailed design of dynamic sampling buffer and memory generation stop conditions hinders full reproducibility.

## Confidence
- Teacher‑aligned reward mechanism: **Medium** (ablations support, but direct correlation with true memory quality unmeasured)
- Min‑max normalization: **High** (ablation shows complete failure without it)
- Multiplicative reward design: **Medium** (plus‑reward ablation worse, assumptions may not hold for all trajectories)
- Overall benchmark improvements: **Medium** (solid results but limited analysis of generalization beyond filtered context)

## Next Checks
1. Compute correlation between normalized teacher scores (`ˆp_{tj}`) and turn‑level exact match using gold intermediate answers on a held‑out validation set.
2. Ablate normalization scope: compare batch‑wise versus global (dataset‑wide) min‑max across varying batch sizes; monitor gradient norms and training stability.
3. Train with filtered `C_t` then evaluate on raw (unfiltered) chunks to quantify the generalization gap in performance.
