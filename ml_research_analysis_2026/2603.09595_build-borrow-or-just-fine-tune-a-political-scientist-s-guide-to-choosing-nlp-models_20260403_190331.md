# Build, Borrow, or Just Fine-Tune? A Political Scientist's Guide to Choosing NLP Models

## Quick Facts
- **arXiv ID**: 2603.09595
- **Source URL**: https://arxiv.org/abs/2603.09595
- **Reference count**: 15
- **Primary result**: ConfliBERT (domain-specific pretrained) achieves higher overall accuracy (79.34% vs 75.46%) than Confli-mBERT (fine-tuned ModernBERT) on conflict event classification, with the gap concentrated in rare event categories (<2% prevalence).

## Executive Summary
Political scientists must decide whether to build domain-specific NLP models, borrow existing ones, or fine-tune general-purpose models, but lack empirical guidance on this trade-off. This study compares a domain-specific model (ConfliBERT) with a fine-tuned general model (Confli-mBERT) on the task of classifying attack types from the Global Terrorism Database. Results show that fine-tuning a modern general model performs nearly as well for frequent attack types, while domain-specific pretraining provides a substantial advantage for rare events. The findings suggest a prevalence‑dependent decision framework: for common tasks, fine‑tuning is cost‑effective; for rare categories, domain‑specific pretraining may be warranted.

## Method Summary
The authors used the Global Terrorism Database (GTD) for multi‑label classification of nine attack types. Data were split temporally: incidents before 2017 for training (170,623) and on/after 2017 for testing (37,709). The baseline model, Confli‑mBERT, was created by fine‑tuning ModernBERT‑base with a nine‑unit sigmoid head and weighted binary cross‑entropy loss where positive class weights are inversely proportional to their training frequencies. Training used the Hugging Face Trainer for 5 epochs with a learning rate of 3e‑5, batch size 16, FP16, on an NVIDIA A100. For comparison, the previously published ConfliBERT (domain‑specific pretraining) was evaluated on the same test set. Performance was assessed using overall accuracy, micro‑F1, macro‑F1, per‑class F1, and AUC‑ROC.

## Key Results
- ConfliBERT outperforms Confli‑mBERT in overall accuracy (79.34% vs 75.46%) and aggregate AUC.
- The performance gap is negligible for high‑frequency attack types (e.g., Bombing/Explosion F1: 0.96 vs 0.95; Kidnapping 0.91 vs 0.92).
- For rare events (<2% prevalence), ConfliBERT shows substantially higher F1 (e.g., Hijacking 0.70 vs 0.37; Barricade 0.49 vs 0.24; Unarmed Assault 0.66 vs 0.31).

## Why This Works (Mechanism)
**Mechanism 1: Domain‑specific pretraining boosts rare‑event performance.** Domain‑specific pretraining creates rich internal representations for domain vocabulary and patterns, acting as informative priors when labeled data is scarce. For frequent events, abundant fine‑tuning data already provides a strong signal, so the added prior contributes little. Evidence: ConfliBERT’s F1 is much higher for rare categories (e.g., Hijacking 0.70 vs 0.37) but nearly identical for common ones. Break condition: If rare categories become more prevalent (>10%) or the domain corpus lacks relevant patterns, the gap shrinks.

**Mechanism 2: Modern general models have narrowed the gap.** Training on trillions of tokens from diverse sources exposes the model to conflict‑related language, embedding useful representations before fine‑tuning. Thus, a fine‑tuned ModernBERT often suffices for common tasks. Evidence: Overall accuracy difference only 3.9 percentage points; per‑class F1 for high‑frequency categories nearly identical. Break condition: If the domain uses highly specialized jargon absent from web text, the gap widens.

**Mechanism 3: Imbalance constrains rare‑event performance.** Extreme class imbalance means few positive examples for rare events, limiting learning even with domain pretraining. Evidence: The three rarest categories together comprise <2% of data; inverse‑frequency weighting up to 277× was used, yet both models have low absolute true positives on rare classes. Break condition: If large volumes of labeled data for rare events become available, the gap would diminish.

## Architecture Onboarding
**Component Map**: Data pipeline -> Tokenizer (ModernBERT WordPiece) -> Model (ModernBERT‑base + 9‑unit sigmoid head) -> Training loop (Hugging Face Trainer, weighted BCEWithLogitsLoss) -> Evaluation (micro‑F1, per‑class F1, AUC, accuracy)

**Critical Path**: Steps to reproduce Confli‑mBERT:
1. Obtain GTD data from START and filter for the 9 attack types.
2. Split temporally: incidents before 2017 for training, on/after 2017 for test.
3. Compute class weights from training set using inverse frequencies (Equation 2).
4. Tokenize text with ModernBERT tokenizer (max length 512).
5. Initialize ModernBERT‑base with a randomly initialized 9‑unit classification head.
6. Train using weighted BCEWithLogitsLoss with the computed `pos_weight`, using Hugging Face Trainer (5 epochs, batch size 16, lr=3e‑5, linear warmup 0.1, weight decay 0.01, FP16).
7. Evaluate on test set, computing overall accuracy, micro/macro F1, per‑class F1 and AUC.
8. Download ConfliBERT and evaluate on the same test set for comparison.

**Design Tradeoffs**
- Multi‑label handling: independent sigmoid + BCE vs. multi‑class softmax; allows multiple attack types but may yield inconsistent label combinations.
- Loss weighting: aggressive weights (up to 277× for rarest class) prevent rare classes from being overwhelmed but risk destabilizing training; empirical results showed stable convergence.
- Sequence length: 512 tokens truncates longer summaries; trade‑off between context loss and memory/compute.
- Threshold: fixed 0.5 for all classes; per‑class threshold optimization on validation could improve F1, especially for rare categories.
- Model selection: chosen by validation F1; could also consider macro‑F1 or AUC to emphasize rare‑class performance.

**Failure Signatures**
- Training loss diverges or produces NaNs: learning rate too high, gradient explosion from large class weights, or numerical instability in BCE.
- High overall accuracy but near‑zero F1 on rare classes: model ignoring minority classes; verify class weights applied correctly and check data distribution.
- Model predicts the same label(s) for every input: failure in training (e.g., all weights zero) or error in label encoding.
- Out‑of‑memory errors: reduce batch size or enable gradient checkpointing; 512‑token sequences with ModernBERT are memory‑intensive.
- Inference extremely slow: confirm model is on GPU, batch size >1, and no unnecessary CPU offloading.

**First 3 Experiments**
1. Ablate class weighting: Train without inverse‑frequency weighting to quantify its impact on rare‑class F1.
2. Threshold optimization: Compute per‑class thresholds that maximize F1 on validation; re‑evaluate test set to see if this narrows the ConfliBERT gap on rare events.
3. Domain‑adaptive pretraining (DAPT): Continue pretraining ModernBERT on a large conflict‑news corpus (e.g., GDELT) before fine‑tuning; test if this replicates ConfliBERT’s rare‑event gains without full domain pretraining.

## Open Questions the Paper Calls Out
1. **Generalizability**: Do the observed patterns (fine‑tuned general model matches domain‑specific on common classes but lags on rare) generalize to other political science NLP tasks (e.g., legislative speech classification, protest detection)? The study only covered GTD; broader validation is needed.
2. **Advanced fine‑tuning**: Can techniques such as domain‑adaptive pretraining, data augmentation for rare events, or per‑class threshold optimization close the gap with ConfliBERT for rare categories? These enhancements remain unquantified.
3. **Impact of model scaling**: As general‑purpose models become larger and more broadly trained, will the advantage of domain‑specific pretraining diminish to irrelevance for all but the most specialized tasks? The comparison is static; empirical data across model generations is lacking.
4. **Zero‑shot LLM potential**: Can sophisticated prompting (few‑shot, chain‑of‑thought, retrieval‑augmented generation) enable zero‑shot LLM APIs to match the performance of fine‑tuned models on structured classification tasks like event coding? The study only tested naïve zero‑shot; the potential is speculative.

## Limitations
- Evaluation limited to a single domain (GTD); results may not generalize to other political science text‑as‑data tasks.
- ConfliBERT’s pretraining details are undisclosed, hindering full replication of the domain‑specific approach.
- The study reports accuracy and F1 but does not assess practical utility (error tolerance, computational cost), which are critical for real‑world model selection.

## Confidence
- **Domain‑specific pretraining helps for rare events**: Medium (evidence robust within GTD but may not hold for other domains with different rare‑category definitions or richer domain corpora).
- **ModernBERT fine‑tuning suffices for common tasks**: High (supported by multiple results and aligns with broader NLP trends).
- **Extreme class imbalance limits rare‑event performance**: High (clearly shown by data statistics and true positive counts).
