# Efficient Constraint Generation for Stochastic Shortest Path Problems

**Quick Facts**
- arXiv ID: 2604.01855
- Source URL: https://arxiv.org/abs/2604.01855
- Reference count: 7
- Primary result: CG-iLAO* reduces actions considered to ~40% of iLAO*, computes 3.5× fewer Q‑values, and solves benchmarks 2.8× and 3.7× faster than iLAO* and LRTDP.

**Executive Summary**
CG-iLAO* tackles the inefficiency of state‑of‑the‑art stochastic shortest path (SSP) solvers like iLAO* and LRTDP, which blindly evaluate all applicable actions during Bellman backups. By reframing heuristic search as solving a linear program with constraint generation, CG-iLAO* introduces a separation oracle that dynamically adds only those actions that are provably active (i.e., not inactive). The algorithm tracks potentially violated constraints in a set Γ, triggering checks only when the value function changes in specific ways. Empirically, CG-iLAO* examines far fewer actions and Q‑values and runs significantly faster than its predecessors, offering a robust improvement for SSP planning.

**Method Summary**
CG-iLAO* is built on iLAO*’s partial SSP formulation, which implicitly solves the full SSP via an LP. Whereas iLAO* adds every action constraint for a state upon expansion (a naive separation), CG-iLAO* introduces an efficient separation oracle. It begins with only greedy actions in the partial SSP; all other actions are inactive. The algorithm iteratively: (a) partially expands fringe states by adding greedy actions, (b) performs Bellman backups on the current policy envelope while recording value changes to update the set Γ, and (c) fixes constraints by checking Γ: if an inactive action becomes active (V(s) > Q(s,a) + ε), it is added to the partial SSP, its successors are incorporated, and the policy may change. This lazy constraint generation drastically cuts the number of Q‑value computations.

**Key Results**
- CG-iLAO* often considers only about 40% of the actions examined by iLAO* (as few as 1% on some problems).
- It computes on average 3.5× fewer Q‑values.
- It solves benchmarks 2.8× and 3.7× faster than iLAO* and LRTDP, respectively.

**Why This Works (Mechanism)**

### Mechanism 1: Reframing Heuristic Search as Constraint Generation over an LP Formulation
The SSP problem can be expressed as an LP (LP1) with constraints V(s) ≤ C(s,a) + Σₛ′ P(s′|s,a) V(s′). iLAO* implicitly solves a partial‑SSP LP (LP2) but adds all action constraints when a state becomes a variable (naive separation). CG-iLAO* replaces this with an efficient separation oracle that only adds constraints when they are violated, using the set Γ to track candidates. The partial SSP always yields a lower bound, and the oracle ensures constraints are added precisely when needed. Core assumption: the lower‑bound property holds and the oracle identifies all potentially violated constraints. Break condition: if η (the threshold for triggering Γ updates) is too large relative to ϵ, violations may be missed, leading to suboptimality or non‑termination.

### Mechanism 2: Ignoring Inactive Actions (Lazy Constraint Addition)
An action a in state s is inactive if a better (lower Q) action already exists in bA(s). CG-iLAO* starts with no actions (or only greedy ones) and adds only greedy actions during partial expansion. Inactive actions are stored as candidates and are added only when Fix‑Constrs detects that V(s) > Q(s,a) + ϵ, i.e., they become active. This shrinks the partial SSP dramatically. Core assumption: V is a lower bound on V⁎ (admissibility), so inactive actions cannot be part of an optimal policy until V increases sufficiently. Break condition: an inadmissible heuristic or an expansion rule that never adds tied greedy actions could cause the optimal action to be omitted indefinitely.

### Mechanism 3: Efficient Separation via Value‑Function Change Propagation
Instead of scanning all unexpanded actions for violations, CG-iLAO* maintains Γ, a set of (s,a) pairs that might violate V(s) ≤ Q(s,a) + ϵ. Γ is updated based on how V changes: (i) when V(s) increases, all external successors’ actions (A(s) \ bA(s)) are added to Γ; (ii) when V(s) decreases, all predecessor actions (states s′ with an action a′ leading to s) are added. Fix‑Constrs then checks only these candidates. Core assumption: non‑violated constraints remain non‑violated unless V updates in one of these two ways. Break condition: frequent value fluctuations can cause Γ to become large, increasing overhead.

**Architecture Onboarding**

- **Component map**: bS → bA → V → bπ_curr. Γ is a set of (s,a) pairs that drives constraint generation.
- **Critical path**:
  1. Initialise bS = {s₀}, bG = {s₀}, V = H.
  2. Loop:
     a. Compute policy envelope E (post‑order DFS of bπ_curr from s₀).
     b. Partly‑Expand‑Fringes on fringe states (E ∩ (bG \ G)) by adding greedy actions; recursively extend E.
     c. CG‑Backups on E \ bG until ϵ‑consistent or fringe appears/policy changes; update Γ on value changes.
     d. Fix‑Constrs: for each (s,a)∈Γ, if violation, add a to bA(s), incorporate successors, update V(s) and bπ_curr, add predators to Γ; else remove (s,a) from Γ.
  3. Terminate when F = ∅, policy stable, and residual ≤ ϵ.
- **Design tradeoffs**:
  - Expansion policy: Single‑greedy adds fewer actions but may increase Γ updates; tied‑greedy reduces Γ growth but may add unnecessary actions. Empirically similar.
  - Threshold η: Must be ≥ ϵ to avoid oscillations; η = ϵ is safe but may delay action additions; larger η risks missing violations.
  - Implementation: Partly‑Expand‑Fringes recursively expands from greedy successors (more aggressive than iLAO*); bπ_curr updated only when V changes, reducing overhead.
- **Failure signatures**:
  - No termination: η too small (oscillations) or too large (missed violations), or heuristic too uninformative (no greedy action leads to closure).
  - Suboptimal policy: Inadmissible heuristic, or optimal action never added due to η or expansion choice.
  - Excessive overhead: Γ grows large due to frequent V decreases, especially on noisy heuristics.
  - Memory exhaustion: Γ accumulates without bound if predators are over‑added or removal lagged.
- **First 3 experiments**:
  1. Compare expansion variants (single, tied, trial rollout, FF‑AO, FF‑MLO): tied and single perform best; rollouts and FF expansions add many unnecessary actions.
  2. Compare to baselines (iLAO*, LRTDP): CG‑iLAO* ignores ~60% of actions, computes 3.5× fewer Q‑values, and solves benchmarks 2.8× (iLAO*) and 3.7× (LRTDP) faster.
  3. Compare to action elimination (upper‑bound based): elimination slows all algorithms; CG‑iLAO* already discards most actions that elimination would remove, showing constraint generation’s superiority.

**Open Questions the Paper Calls Out**
- Generalization to MDPs with imprecise parameters (MDPIPs/MDPSTs): min‑max semantics may benefit from CG‑iLAO*’s action avoidance.
- Extension to SSPs with Probabilistic LTL constraints: need to integrate PLTL constraint tracking with inactive action detection.
- Applicability to probabilistic reachability model checking: adapting the separation oracle to verification problems like PRISM.
- Automatic setting of η: current η=ϵ may cause suboptimal policies; pathological examples show arbitrarily large errors for η>0; a method to bound error is needed.

**Limitations**
- Implementation details ambiguities: recursion order in Partly‑Expand‑Fringes, tie‑breaking rule for greedy actions, trial rollout termination parameters.
- Parameter η sensitivity: balance between avoiding oscillations and missing violations is delicate; no automatic tuning.
- Dependence on high‑quality admissible heuristics; poor heuristics degrade performance or cause non‑termination.
- Potential Γ blow‑up on domains with frequent value changes or large predecessor sets.

**Confidence**
- LP reformulation: High
- Lazy inactive‑action addition: Medium
- Efficient separation via Γ: Medium
