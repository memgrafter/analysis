# Reasoning Pattern Alignment Merging for Adaptive Reasoning

## Quick Facts
- **arXiv ID:** 2601.03506
- **Source URL:** https://arxiv.org/abs/2601.03506
- **Reference count:** 36
- **Primary result:** RPAM reduces generated tokens by 48.33% on MATH and 50% on OlympiadBench while matching or exceeding the accuracy of the Long-CoT baseline and outperforming Ada-R1 and ACM.

## Executive Summary
Large reasoning models (LRMs) often produce lengthy chain-of-thought (Long-CoT) even for simple queries, harming efficiency. This paper proposes Reasoning Pattern Alignment Merging (RPAM), a lightweight model merging framework that combines a Long-CoT specialist and a Short-CoT specialist without retraining. RPAM first constructs a small pattern-labeled calibration set to assign each query an appropriate reasoning style (Long or Short). It then optimizes layer-wise merging coefficients by aligning the merged model’s intermediate features with the selected model’s features while using contrastive learning to separate from the non-selected model. Evaluated on seven reasoning benchmarks using Qwen3-4B and 1.5B models, RPAM cuts token generation by nearly half on MATH and OlympiadBench while preserving or improving accuracy, outperforming strong baselines like Ada-R1 and ACM. The approach achieves a superior accuracy-efficiency trade-off with minimal calibration data and low computational overhead.

## Method Summary
RPAM takes two pretrained models: a Long-CoT model (θ^L) and a Short-CoT model (θ^S). Given a seed dataset D, it samples k responses from each model per query and labels the query with the model that achieves higher empirical accuracy (or shorter length on a tie) as the positive pattern, the other as negative. This yields a pattern-labeled set D_PL = {(x, θ_pos, θ_neg)}.

The merged model θ^M is defined via layer-wise interpolation: for each layer l, the parameters are a convex combination θ^M_l = λ^L_l θ^L_l + λ^S_l θ^S_l. The coefficients {λ^L_l, λ^S_l} are initialized (e.g., 0.5) and then optimized. For each layer l, the input x is forwarded through all three models to extract intermediate activations z^l_pos, z^l_neg, and z^l_M. The loss for layer l combines: (1) an alignment term that minimizes the L2 distance between z^l_M and z^l_pos; (2) a contrastive term that maximizes similarity between z^M and z^pos while minimizing similarity with z^neg (scaled by temperature τ and weight ω). The coefficients for layer l are updated via gradient descent to minimize L^l = L^l_align + ω·L^l_cl. This process is repeated for all layers sequentially. After optimization, θ^M can dynamically produce either short or long reasoning depending on the query, using the same architecture as the base models.

## Key Results
- **Token reduction:** 48.33% fewer tokens on MATH, 50% on OlympiadBench compared to the Long-CoT baseline.
- **Accuracy:** Matches or exceeds Long-CoT accuracy on all seven benchmarks; outperforms Ada-R1 and ACM.
- **Efficiency:** Works with as few as 32 calibration examples and incurs negligible overhead beyond a single forward pass per layer during optimization.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** RPAM assigns each query an appropriate reasoning pattern (Long-CoT or Short-CoT) by constructing a small, pattern-labeled calibration set.
- **Mechanism:** For each query in the calibration set, the method samples multiple responses from both base models, computes an empirical expected accuracy for each model, and selects the model with higher accuracy (or shorter length on a tie) as the "positive" (target) pattern. The other becomes the "negative" pattern.
- **Core assumption:** The model that produces higher empirical accuracy on a small sample of responses for a given query is a reliable proxy for the optimal reasoning pattern (Long or Short) for that query.
- **Evidence anchors:** The abstract explicitly states RPAM constructs a small pattern-labeled calibration set to assign styles. Section 4.1 details the sampling procedure (k responses), accuracy calculation (Eq.3), and selection rule (Eq.4). The corpus does not provide direct external evidence; support is primarily from the paper itself.
- **Break condition:** If the empirical accuracy estimates from k samples are noisy or unrepresentative (e.g., due to high variance in sampled outputs), the assigned pattern label could be incorrect, leading to misaligned merging objectives.

### Mechanism 2
- **Claim:** RPAM optimizes layer-wise merging coefficients so that the intermediate feature representations (z^l_M) of the merged model align with those of the selected (positive) model for each query.
- **Mechanism:** For each layer l, it minimizes the squared L2 distance between the merged model's feature z^l_M and the positive model's feature z^l_pos (Eq.7). This is performed layer-by-layer across all layers.
- **Core assumption:** Aligning the internal activations/features of the merged model with those of a model that demonstrates the desired behavior for a specific query will cause the merged model to behave like that model for that query.
- **Evidence anchors:** The abstract mentions aligning intermediate features with the selected model's features. Section 4.2 formally defines layer-wise merging, feature computation (Eq.6), and alignment loss L^l_align (Eq.7). Corpus neighbors like "LayAlign" and "LARV" explore layer-wise merging, providing contextual evidence that layer-specific adaptation is fruitful, though not for adaptive reasoning.
- **Break condition:** If the feature spaces of the Long-CoT and Short-CoT models are highly overlapping or non-linearly separable at certain layers, alignment loss alone may be insufficient to induce distinct, pattern-specific behaviors, possibly resulting in a "blurry" intermediate state.

### Mechanism 3
- **Claim:** A contrastive loss explicitly pushes the merged model's features away from the non-selected (negative) model's features, sharpening the distinction between the two reasoning patterns.
- **Mechanism:** For each layer l, a contrastive loss (Eq.8) is added to the alignment loss. It treats the positive model's feature as an anchor and maximizes similarity (via dot product scaled by temperature τ) between the merged model and this anchor, while minimizing similarity with the negative model's feature.
- **Core assumption:** Explicitly maximizing separation from the negative model's representation prevents the merged model from adopting a mixture of both patterns and encourages commitment to the selected pattern's representation.
- **Evidence anchors:** The abstract describes the contrastive objective. Section 4.3 defines binary contrastive loss L^l_cl (Eq.8) and joint objective L^l = L^l_align + ω·L^l_cl (Eq.9). Section 5.3 (ablation) removes contrastive learning ("-CES") and shows a consistent drop in accuracy and efficiency, providing strong empirical evidence. Corpus neighbors focus on merging for accuracy or safety, not contrastive shaping for reasoning pattern separation.
- **Break condition:** If temperature τ or weight ω is poorly set (too high/low), the contrastive term could dominate and destabilize training or be too weak to provide meaningful separation.

## Foundational Learning
- **Chain-of-Thought (CoT) Reasoning**: RPAM adaptively chooses between two CoT styles: verbose Long-CoT and concise Short-CoT. Long traces can improve accuracy on complex tasks but harm efficiency on simple ones. *Quick check:* What is a potential downside of always using Long-CoT reasoning, even for simple arithmetic problems?
- **Model Merging (Task Arithmetic / Weight Interpolation)**: RPAM is a merging framework; its baseline is merging models via linear interpolation (θ^M = λ_L θ^L + λ_S θ^S). Naive merging blurs specialized behaviors. *Quick check:* Why might averaging the weights of a Long-CoT and Short-CoT model fail to produce a model that can do both effectively?
- **Feature/Representation Alignment in Deep Networks**: RPAM shifts the merging objective from parameter space to representation space, claiming that matching intermediate activations (z^l) is a more reliable way to inherit behavior than matching parameters. *Quick check:* In a neural network, what does the activation/output of an intermediate layer (z^l) represent, and why might aligning these between models be a better proxy for behavioral similarity than aligning weights?

## Architecture Onboarding
**Component map:** Seed Data -> Pattern-Labeled Dataset Constructor -> Layer-wise Feature Extractor -> Coefficient Optimizer -> Final Merged Model (with Base Models θ^L and θ^S used throughout).

**Critical path:** Given seed dataset D: (1) Construct D_PL by sampling k outputs per query from θ^L and θ^S and labeling with θ_pos/θ_neg via accuracy/tie-break. (2) Initialize merged model θ^M with λ^l_L=λ^l_S=0.5 for all layers. (3) For each layer l sequentially (or in parallel): run all queries in D_PL through θ^L, θ^S, and θ^M to extract z^l_pos, z^l_neg, z^l_M; compute total loss L^l = L^l_align + ω·L^l_cl; update λ^l_L, λ^l_S via gradient descent. (4) After optimizing all layers, fix θ^M for inference.

**Design tradeoffs:**
- *Calibration Data Size (|D_PL|):* Larger sets improve pattern supervision but increase pre-processing cost (k·|D_PL| forward passes). Paper shows effectiveness from 32 to 256 examples.
- *Contrastive Weight (ω):* Balances alignment vs. separation. Too high may harm alignment; too low fails to sharpen pattern distinction. Broad effective range found.
- *Layer-wise Independence:* Optimizing each layer independently simplifies calibration but may miss cross-layer dependencies affecting final reasoning behavior.

**Failure signatures:**
- *Symptoms:* Merged model accuracy worse than both base models; response length intermediate and not adaptive.
- *Probable causes:* (1) Noisy D_PL labels (k too small or high output variance). (2) Learning rate too high for coefficient optimization. (3) Base models' representations too similar, making losses uninformative.
- *Diagnosis:* Monitor per-layer losses (L^l_align, L^l_cl). Stagnant L^l_align suggests misaligned features or bad initialization; high L^l_cl with poor accuracy may indicate ω too high.

**First 3 experiments:**
1. **Pattern Label Sanity Audit:** Manually inspect 50 (x, θ_pos) pairs from D_PL. Does θ_pos's output subjectively match expected reasoning depth? Tests heuristic validity.
2. **Layer-wise Loss Convergence:** Run optimization for a few epochs, plot L^l for early, middle, late layers. Each should decrease monotonically; stagnation indicates optimization failure.
3. **Controlled Style Transfer Test:** Craft 10 simple and 10 complex queries. After merging, measure (a) output length gap between styles, (b) accuracy on each subset. The merged model should statistically match θ^S on simples (short+correct) and θ^L on complexes (long+correct). Failure indicates poor style adaptation.

## Open Questions the Paper Calls Out
- **Scalability to larger models:** Does RPAM maintain benefits when applied to significantly larger language models (e.g., >10B parameters)? The authors limited experiments to 1.5B and 4B due to resource constraints. The coefficient optimization may not scale gracefully to more layers and parameters.
- **Merging heterogeneous architectures:** Can RPAM effectively merge models with different architectures (e.g., dense vs. MoE) or from different pretraining families? The current work assumes same architecture; merging divergent structures may cause misaligned intermediate representations.
- **Generalization beyond mathematics:** Is the pattern-labeled calibration approach generalizable to other reasoning domains like logical deduction or code generation? RPAM was evaluated only on mathematical benchmarks; non-mathematical tasks may have different characteristics and the sampling-based pattern assignment might fail to identify optimal styles.

## Limitations
- **Pattern-Labeling Heuristic Robustness:** The assumption that k-sample empirical accuracy reliably proxies optimal reasoning style may break under high output variance or for queries where both models perform poorly.
- **Feature Alignment Sufficiency:** Aligning intermediate features assumes Long/Short patterns manifest as separable representations; this may fail if differences are subtle or only appear in late layers.
- **Generalization & Scaling:** Evaluation is limited to Qwen3 4B/1.5B; effectiveness on larger models or more diverse architectures remains unproven.

## Confidence
- **Overall Accuracy-Efficiency Trade-off:** High
- **Mechanism Validity (Feature Alignment + Contrastive Loss):** Medium
- **Architectural Scalability & Pattern Generalizability:** Low
