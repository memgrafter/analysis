# DiscoPhon: Benchmarking the Unsupervised Discovery of Phoneme Inventories With Discrete Speech Units

## Quick Facts
*   **arXiv ID:** 2603.18612
*   **Source URL:** https://arxiv.org/abs/2603.18612
*   **Reference Count:** 0
*   **Primary Result:** SpidR VP-20 finetuned achieves the best reported many-to-one test results (PER 65.50%, PNMI 65.22%), but one-to-one mapping remains extremely difficult (PER 132.26%).

## Executive Summary
DiscoPhon establishes a benchmark for unsupervised phoneme discovery from discrete speech units, using a fixed 10-hour per-language evaluation protocol. Systems must map a large discrete unit vocabulary (256 units) or a constrained one-to-one set (phoneme count +1) to a gold-standard phoneme inventory. Evaluating four pretrained multilingual models (HuBERT, SpidR), the benchmark finds SpidR consistently superior. However, error rates remain very high, especially for the strict one-to-one track, indicating that while pretrained models contain phonemic information, the quality of discovery is low, varies by language, and is heavily constrained by mapping constraints and vocabulary size.

## Method Summary
The benchmark protocol involves taking a pretrained self-supervised learning (SSL) model, extracting its discrete latent units for 10 hours of speech from an "unseen" language (though within the model's pretraining multilinguality), and learning a mapping from these units to a gold-standard phoneme inventory. Two mapping scenarios are evaluated: a many-to-one task with a fixed 256-unit vocabulary and a one-to-one task where the system must produce exactly the number of phonemes plus one. Performance is measured by Phone Error Rate (PER) and Phone-Normalized Mutual Information (PNMI) for many-to-one, and PER and R-value for one-to-one.

## Key Results
*   SpidR VP-20 finetuned achieves the best many-to-one test results: PER 65.50%, PNMI 65.22%.
*   The one-to-one track is substantially harder; SpidR VP-20 finetuned test PER is 132.26% with an R-value of 10.33%.
*   Finetuning primarily reduces substitution errors; insertion errors remain the dominant error type across models and tracks.

## Why This Works (Mechanism)
DiscoPhon leverages the hypothesis that the discrete latent spaces of pretrained SSL models encode phonemic contrasts. By forcing a mapping to a known inventory, the benchmark tests whether this information is accessible and linearly separable enough for unsupervised discovery. The superior performance of SpidR, a model explicitly trained for phonetic unit discovery, suggests that architectural choices and training objectives targeting phonetic structure (e.g., using a phonetic discriminator) make the underlying representations more amenable to this downstream linear probing task.

## Foundational Learning
*   **Self-Supervised Pretraining:** SSL models learn representations from raw audio without transcriptions. *Why needed:* Provides a rich, general speech representation from which phonemic information can be extracted. *Quick check:* Does a frozen SSL model's layer show clustering by phoneme in a few-shot linear probe?
*   **Discrete Speech Units:** Continuous SSL representations are quantized into a finite set of cluster centroids (e.g., via k-means). *Why needed:* Creates a symbolic, vocabulary-like output for clustering and mapping. *Quick check:* Does the unit sequence length closely match the audio's phoneme sequence length?
*   **Phoneme Inventory:** The complete set of distinctive sounds (phonemes) for a language. *Why needed:* The gold-standard target for evaluation. *Quick check:* Is there a high-quality, universally agreed-upon IPA transcription for the evaluation languages?
*   **Linear Probe/Mapping:** Learning a simple, often linear, classifier to map discrete units to phonemes. *Why needed:* Tests if phonemic information is linearly separable in the unit space. *Quick check:* Does performance scale with probe capacity (e.g., linear vs. MLP)?
*   **Phone Error Rate (PER):** Edit distance between predicted and reference phoneme sequences. *Why needed:* Standard metric for phoneme recognition quality. *Quick check:* Does PER correlate with human perceptual judgements of segmental quality?
*   **Mutual Information (NMI, R-value):** Measures agreement between cluster (unit) and phoneme assignments, adjusted for chance. *Why needed:* Evaluates clustering quality without a one-to-one mapping constraint. *Quick check:* Is NMI/R-value stable across different clustering algorithms on the same units?

## Architecture Onboarding
**Component Map:** SSL Pretraining (wav2vec 2.0-style) -> Feature Extraction (Intermediate Layer) -> Quantization (k-means / learned codebook) -> Discrete Unit Sequence -> Linear Mapping Layer (trainable) -> Phoneme Predictions.

**Critical Path:** 1) Load frozen pretrained SSL model. 2) Pass target language audio through model, extract a specific layer's features. 3) Quantize these features into a discrete unit sequence using a fixed codebook. 4) Train a linear classifier (the mapping) to predict phonemes from unit context (e.g., 7-unit window) using a small labeled subset or the 10-hour set's forced alignment. 5) Evaluate the trained mapping on a held-out test set.

**Design Tradeoffs:** The core tradeoff is between expressiveness and constraint. A large vocabulary (256 units) allows finer-grained distinctions (many-to-one track) but makes a perfect one-to-one mapping to a smaller phoneme set impossible. The one-to-one track forces a lossy compression. Finetuning the SSL model versus using it frozen trades target-language adaptation for potential catastrophic forgetting and increased computational cost.

**Failure Signatures:** *Dominant insertion errors* indicate the unit segmentation is too fine (too many units per phoneme) or the mapping is defective. *High substitution errors* point to insufficient separation of phonemic categories in the unit space. *Vastly worse one-to-one PER* confirms the fundamental mismatch between a large fixed vocabulary and a smaller phoneme set. *Large performance variance across languages* suggests some phoneme inventories or acoustic properties are less represented in the pretrained model's space.

**First Three Experiments:**
1.  **Isolate the Codebook:** Freeze the SSL model and only train the mapping for SpidR vs. HuBERT on a single language. Measure the gap in PER/PNMI to attribute performance primarily to the quality of the discrete units versus the mapping algorithm.
2.  **Vocabulary Ablation:** For the best model (SpidR VP-20 finetuned), repeat the many-to-one evaluation with drastically smaller fixed unit vocabularies (e.g., 64, 128 units) to see how PER scales with representational budget.
3.  **Context Window Sweep:** Vary the context window size (e.g., 1, 3, 7, 11 units) fed to the linear mapping classifier for the one-to-one track to determine if longer temporal context helps reduce substitutions at the cost of potential insertions.

## Open Questions the Paper Calls Out
The paper does not explicitly list separate open research questions beyond its benchmark scope. The evaluation focuses on a narrow set of models and a fixed 10-hour protocol.

## Limitations
*   The benchmark scope is narrow, evaluating only two pretrained model families (HuBERT, SpidR) on a fixed 10-hour protocol, limiting generalizability.
*   Extremely high Phone Error Rates (>65% many-to-one, >132% one-to-one) indicate discovered inventories are far from gold standards, limiting practical utility claims.
*   The "unseen" languages are still from the pretraining corpora of the evaluated models, so true zero-shot cross-lingual discovery capability remains unverified.

## Next Checks
1.  **Expand Pretrained Model Diversity:** Re-run DiscoPhon with other major SSL families (e.g., wav2vec 2.0, WavLM, data2vec) to test if SpidR's advantage is consistent or architecture-specific.
2.  **Stress-Test Data Conditions:** Evaluate the best SpidR system under (a) <10 hours of target speech (e.g., 1 hour) and (b) with additive noise to assess robustness for low-resource and real-world scenarios.
3.  **Probe Linguistic Correlates:** Perform a detailed error analysis stratified by language family, phoneme inventory size, and phonological features (e.g., tone, clicks) to identify which linguistic characteristics most strongly predict discovery difficulty.
