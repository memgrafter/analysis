# One-Shot Hierarchical Federated Clustering

## Quick Facts
- **arXiv ID:** 2601.06404
- **Source URL:** https://arxiv.org/abs/2601.06404
- **Reference count:** 40
- **Primary result:** Achieves highest average ranks (1.3) in Purity, ARI, NMI, and ACC across ten datasets, significantly outperforming seven SOTA federated clustering methods.

## Executive Summary
Fed-HIRE is a one-shot hierarchical federated clustering framework designed to handle fragmented global clusters in non-IID client data. It combines local clusterlet extraction via Federated Clustering with Prototype Learning (FCPL) and server-side Multi-granularity Clustering with Prototype Learning (MCPL) to reconstruct a global hierarchical clustering without iterative communication. Experiments on ten datasets demonstrate state-of-the-art performance, scalability to thousands of clients, and robustness to key hyperparameters.

## Method Summary
In a single communication round, each client applies FCPL to its local data to produce a set of cluster centroids (clusterlets). These clusterlets are transmitted to a central server, which then runs MCPL to aggregate them into a multi-granular hierarchy. The hierarchical structure enables merging of fragmented local representations of the same global cluster, effectively addressing non-IID data heterogeneity. The one-shot design minimizes communication overhead while preserving clustering quality.

## Key Results
- Highest average ranks (1.3) in Purity, ARI, NMI, and ACC across ten datasets, significantly outperforming seven SOTA federated clustering methods.
- Efficient scalability demonstrated with increasing number of clients (100–1000) and data volume.
- Robust to variations in learning rate and initial cluster number parameters.

## Why This Works (Mechanism)
Fed-HIRE mitigates fragmentation by having clients generate local clusterlets that capture fine-grained structures, followed by server-side hierarchical aggregation that can merge clusterlets representing the same global cluster. The one-shot approach avoids multiple communication rounds, while the multi-granularity output accommodates varying degrees of fragmentation inherent in non-IID data.

## Architecture Onboarding
**Component map:** Local Data -> FCPL -> Clusterlets -> Server (MCPL) -> Multi-granular Hierarchy  
**Critical path:** (1) Clients run FCPL to generate clusterlets; (2) Clients transmit clusterlets to server; (3) Server runs MCPL to construct hierarchy; (4) Server outputs global result.  
**Design tradeoffs:** One-shot vs. multi-round (communication efficiency vs. potential accuracy); hierarchical vs. flat (flexibility vs. complexity); local cluster number choice (affects fragmentation handling).  
**Failure signatures:** Noisy clusterlets from poor local clustering (e.g., due to small client data); failed merges in MCPL if clusterlets are unrepresentative; overly shallow/deep hierarchies under extreme fragmentation.  
**First experiments:** (1) Validate functionality on a small synthetic dataset; (2) Compare with SOTA baselines (e.g., FedKM) on FEMNIST; (3) Scale number of clients (100–1000) to measure scalability and communication cost.

## Limitations
- Real-world deployment factors (network latency, stragglers) are unaddressed.
- Privacy guarantees (e.g., differential privacy) are not evaluated.
- Automatic selection of global cluster number hierarchy depth is not handled; MCPL requires pre-specifying depth.
