# Agent Mars: Multi-Agent Simulation for Multi-Planetary Life Exploration and Settlement
## Quick Facts
- **arXiv ID:** 2602.13291
- **Source URL:** https://arxiv.org/abs/2602.13291
- **Reference count:** 40
- **Primary result:** The Agent Mars framework reduces coordination time by up to 51% and introduces the Agent Mars Performance Index (AMPI) to evaluate multi-agent Mars missions.

## Executive Summary
Coordinating heterogeneous humans, robots, and digital services in safety-critical, resource-scarce Mars missions with communication delays demands auditable multi-agent coordination beyond toy settings. Agent Mars addresses this with a 93-agent, 7-layer hierarchical framework that incorporates cross-layer shortcuts, dynamic role handover, phase-dependent leadership, scenario-aware memory, propose-vote consensus, and translator-mediated protocols. The framework defines the Agent Mars Performance Index (AMPI) as an interpretable composite metric. Across 13 mission scenarios, curated cross-layer routing cut end-to-end time by as much as 51% and lowered message counts; functional leadership reduced overhead; dynamic role switching lowered failure rates; and translator-mediated protocols improved safety in emergencies. AMPI successfully integrates these trade-offs into a single benchmarkable score.

## Method Summary
The simulation models a Mars base crewed by 71 human operators and 22 robotic assets, organized into a 7-layer hierarchy (e.g., Commander, Operations, Functional Divisions, Asset Controllers, Physical Assets). Agents are implemented as LLM-driven entities (ChatGPT, temperature=0) with prompts derived from scenario definitions. The core mechanisms under evaluation are:
- **Routing**: Strict hierarchy versus curated cross-layer whitelist (HCLC).
- **Leadership**: Single (Commander) versus functional (e.g., Operations for daily tasks, Science for exploration).
- **Role switching**: Automatic failover from primary to backup asset controllers upon simulated outages.
- **Memory**: Short-term window (k=2) with optional long-term summarization and optional shared pool.
- **Consensus**: Two-round propose-vote with 60% quorum.
- **Protocols**: Off versus translator-mediated heterogeneous dialects.
Thirteen scenario scripts (e.g., ScienceExploration, DailyOperations, EmergencyResponse) drive the execution. Each run produces raw metrics (Time, Msgs, Failures = Nasset + Nviol + Nmiss, CrossLayer ratio, RoleSw) and the composite AMPI score, computed via weighted sums with squashing constants (w=[0.4,0.2,0.0,0.25,0.15]; KT=20, KM=50, KF=3, KS=5). A public runner (`main.py`) executes 20 deterministic runs per configuration, outputting CSV/JSON for analysis.

## Key Results
- Cross-layer routing reduced end-to-end time by up to 51% (ScienceExploration: 61.2s → 29.8s) and lowered message count in coordination-heavy scenarios.
- Functional leadership decreased overhead when work concentrated in specific functional layers.
- Dynamic role switching lowered failure rates (e.g., DailyOperations: 0.50 → 0.12) and improved completion time; translator-mediated protocols reduced failures in safety-sensitive cases (EmergencyResponse: 0.10 → 0.01), albeit with increased message overhead.
- The AMPI composite metric unified these competing objectives into a single benchmarkable score.

## Why This Works (Mechanism)
Cross-layer shortcuts bypass hierarchical hops, reducing latency and message load for time-sensitive operations. Dynamic role handover ensures continuity during asset failures, preserving mission progress and reducing counted failures. Phase-dependent leadership adapts decision-making authority to scenario requirements (e.g., functional leaders for routine tasks, centralized command for emergencies), trimming unnecessary coordination. Scenario-aware memory balances immediate context (short-term window) with summarization and sharing, maintaining relevant information without overwhelming token limits. Propose-vote consensus achieves agreement with just two rounds and a moderate quorum, minimizing round-trip delays. Finally, translator-mediated protocols allow heterogeneous agents (e.g., humans with natural language, robots with structured commands) to cooperate safely, cutting safety violations at a modest messaging cost. Together, these mechanisms yield the observed improvements.

## Architecture Onboarding
**Component Map (plain text):**
CMD -> OPS -> Asset Controllers -> Physical Assets
OPS <-> Functional Layers (Science, Engineering, Logistics, etc.)
Functional Layers <-> Asset Controllers (whitelisted)
(plus cross-layer shortcuts among certain functional layers as defined in Table 4)

**Critical Path:** A typical mission command originates from a human (CMD or Functional layer). With strict routing, it traverses down the hierarchy (CMD→OPS→Asset Controller→Asset). Cross-layer shortcuts allow direct jumps (e.g., Science→Asset Controller) if whitelisted, reducing hops. Responses follow the reverse path.

**Design Tradeoffs:**
- STRICT routing is simple and predictable but slower; CROSSLAYER speeds up communication at the cost of more complex routing logic and potential state inconsistencies.
- Single leadership centralizes decisions but can become a bottleneck; functional leadership distributes authority but may require conflict resolution.
- Role switching improves robustness but adds state tracking and backup management.
- Memory (longer context, sharing) improves decision quality but increases token usage and cost.
- Consensus ensures alignment but introduces extra message rounds.
- Translator protocols enable interoperability but add translation overhead and possible information loss.

**Failure Signatures:** Elevated failure counts (asset malfunctions, safety violations, missed deadlines), excessive message counts, long end-to-end times, high cross-layer ratio deviations, and frequent role switches. Specific patterns (e.g., spikes in Nviol under protocol-off conditions) indicate protocol-related issues.

**First Experiments:**
1. **Baseline**: Run DailyOperations with default STRICT routing, single leadership, no memory/consensus/protocols. Record Time, Msgs, Failures, AMPI.
2. **Cross-layer & Functional Leadership**: Enable CROSSLAYER routing and functional leadership in the same scenario. Expect reduced Time and Msgs, increased CrossLayer ratio.
3. **Role Switching & Failures**: Enable dynamic role switching and introduce artificial asset failures (e.g., 30% outage rate). Compare Failures and completion time against baseline; expect lower failure count and similar/better Time.

## Limitations
- Exact LLM model/version (e.g., GPT-4 variant) is unspecified, risking behavioral drift in agent responses.
- Asset outage probability `p` used for role-switching experiments is not disclosed, preventing precise replication of those results.
- No repository tag/commit hash is provided; code configuration (whitelists, memory functions, message accounting) may differ from the paper’s version.
- AMPI implementation details (e.g., whether cross-layer ratio is squashed) are ambiguous.
