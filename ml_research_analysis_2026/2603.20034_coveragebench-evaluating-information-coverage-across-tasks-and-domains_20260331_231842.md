# CoverageBench: Evaluating Information Coverage across Tasks and Domains

## Quick Facts
- arXiv ID: 2603.20034
- Source URL: https://arxiv.org/abs/2603.20034
- Reference count: 40
- Primary result: Traditional IR metrics like nDCG fail to measure whether retrieved results collectively span all relevant aspects (information coverage), a critical gap for RAG systems addressed by the nugget-based CoverageBench benchmark.

## Executive Summary
The paper identifies a fundamental limitation in information retrieval evaluation: standard metrics (nDCG, MAP) assess individual document relevance but ignore whether a retrieved set comprehensively covers all aspects of an information need. This is particularly crucial for retrieval-augmented generation (RAG), where missing a key fact can degrade output quality. To resolve this, the authors build CoverageBench by augmenting seven diverse retrieval datasets with fine-grained "nugget" annotations—atomic information units—using LLMs and manual curation. The benchmark provides unified coverage metrics (Subtopics Recall, α-nDCG) and reveals that high nDCG scores do not guarantee broad coverage; for instance, on CAsT, all systems plateau at ~0.55 StRecall@20 despite nDCG variation. CoverageBench thus enables systematic development of coverage-aware retrieval.

## Method Summary
The core method transforms seven existing retrieval datasets (NeuCLIR 2024, RAG 2024, Fair Ranking 2022, CAsT 2020, RAGTIME 2025, CRUX-MultiNews, CRUX-DUC04) into coverage testbeds. Each dataset’s topics are paired with manually/LLM-derived nuggets (atomic info units) and nugget-level relevance judgments indicating which documents support each nugget. Evaluation uses Subtopic Recall (StRecall@k) to measure the fraction of nuggets covered in top-k results and α-nDCG@k to weight nuggets by importance while discounting redundancy. No model training is involved; the focus is on evaluation infrastructure: released nugget annotations, qrels, baseline runs (BM25, Qwen3-8B with rerankers), and an evaluation script.

## Key Results
- High nDCG does not ensure coverage: on CAsT, all baseline systems achieve similar StRecall@20 (~0.55) despite nDCG variation.
- Fair Ranking dataset strongly favors BM25 due to keyword-heavy queries, highlighting coverage-relevance tradeoffs.
- CoverageBench provides a unified, reusable testbed with consistent nugget annotations across domains to drive coverage-aware retrieval research.

## Why This Works (Mechanism)
CoverageBench works by redefining retrieval success from document-level relevance to set-level informational completeness. Nuggets serve as atomic, exhaustive information units; coverage metrics quantify how many nuggets appear in the retrieved set. StRecall directly measures spanned aspects, while α-nDCG incorporates nugget importance and reduces redundancy. This exposes a key mismatch: systems optimized for nDCG (rewarding top-ranked relevant docs) may miss peripheral but valid nuggets, whereas coverage metrics penalize such gaps. The benchmark’s cross-domain consistency allows isolating coverage as a distinct dimension from topical relevance.

## Foundational Learning
**Information Coverage** – Whether a retrieved set collectively spans all relevant aspects of a query. *Why needed*: Traditional IR metrics ignore set completeness, harming RAG. *Quick check*: Does a ranked list cover all key points, or just a few in depth?
**Nugget Annotation** – Decomposing an information need into atomic, self-contained facts. *Why needed*: Enables fine-grained, interpretable coverage measurement. *Quick check*: Are nuggets mutually exclusive and collectively exhaustive for a topic?
**Subtopics Recall (StRecall@k)** – Fraction of nuggets present in top-k retrieved documents. *Why needed*: Directly quantifies coverage breadth. *Quick check*: Compute supported nuggets divided by total nuggets for a run.
**α-nDCG** – nDCG variant weighting nuggets by importance and discounting redundant nuggets. *Why needed*: Prevents systems from gaming StRecall by retrieving redundant nuggets; prioritizes diverse key info. *Quick check*: Compare α-nDCG to nDCG on same runs; lower scores indicate redundancy.
**RAG Context Need** – Retrieval for generation requires comprehensive context to avoid hallucination. *Why needed*: Coverage directly impacts downstream answer quality. *Quick check*: Does missing a nugget in context lead to missing info in generated output?
**Benchmark Unification** – A single evaluation framework across multiple retrieval tasks/domains. *Why needed*: Allows isolating coverage as a variable and comparing systems fairly. *Quick check*: Do datasets vary in query type, domain, and difficulty while using identical metrics?

## Architecture Onboarding
Component map: Raw Datasets -> Nugget Annotation (LLM + manual curation) -> Nugget Qrels -> Retrieval Systems (BM25, dense) -> Ranked Runs -> Coverage Evaluation (StRecall, α-nDCG) -> Analysis.

Critical path: 1) Annotate nuggets for each topic. 2) Create nugget-document qrels. 3) Generate ranked retrieval runs. 4) Evaluate runs against nugget qrels using provided script. 5) Compare coverage vs. relevance metrics.

Design tradeoffs: LLM-based nugget extraction (scalable but may miss nuances) vs. manual curation (accurate but costly); nugget granularity (too fine inflates difficulty, too coarse loses precision); coverage vs. relevance (systems can be tuned for one at expense of other).

Failure signatures: High nDCG + low StRecall indicates coverage blind spot; dataset-specific quirks (e.g., BM25 dominating Fair Ranking due to keyword bias); large gap between α-nDCG and nDCG suggests redundant retrieval.

First experiments: 1) Run provided evaluation script on authors’ baseline runs (BM25, Qwen3-8B) for CAsT; confirm StRecall@20 ~0.55. 2) For a single dataset, vary retrieval depth k (5–100) and plot StRecall@k vs. nDCG@k to visualize decoupling. 3) Analyze nugget distribution: per-topic nugget count, average nugget length, and coverage ceiling (max possible StRecall) to understand dataset difficulty.

## Limitations
- Annotation process opacity: exact LLM prompts and curation details for nugget derivation and nugget-document judgments are unreleased, hindering qrel replication.
- Baseline configuration ambiguity: retrieval parameters (indexing, chunking, dense model settings) are vaguely described as "defaults," limiting exact recreation of reported scores.
- Collection reconstruction risk: exact pre-processed document corpora (e.g., language filtering, passage splits) may be infeasible to reproduce without authors' scripts, altering BM25 results.

## Confidence
- CoverageBench provides a unified coverage testbed: High
- nDCG does not guarantee coverage (plateau effect observable): High
- Fair Ranking favors BM25 due to query nature: Medium
- Annotation consistency across domains: Medium
- Generalizability beyond released baselines: Low
