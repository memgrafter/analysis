# TimberAgent: Gram-Guided Retrieval for Executable Music Effect Control

## Quick Facts
- **arXiv ID**: 2603.09332
- **Source URL**: https://arxiv.org/abs/2603.09332
- **Reference count**: 40
- **Primary result**: TRR achieves the lowest normalized parameter error among all evaluated retrieval baselines, with statistically significant improvements in alignment metrics and perceptual similarity ratings.

## Executive Summary
The paper addresses the semantic gap between perceptual audio intent and editable DSP parameters in DAWs by formulating audio effect control as a retrieval task over presets. It introduces Texture Resonance Retrieval (TRR), which uses Gram matrices of mid-level Wav2Vec2 activations to capture texture-relevant co-activation patterns while discarding fine temporal alignment. Evaluated on a guitar-effects benchmark (1,063 presets, 204 queries) under a strict anti-leakage split, TRR significantly outperforms baselines like CLAP and mean-pooled Wav2Vec2 in parameter-space metrics. A multiple-stimulus listening study with 26 participants shows TRR-retrieved presets are rated higher than manual tuning and comparable to a generative baseline for similarity to reference. Ablations confirm design choices, and sensitivity analysis validates robustness to near-duplicates.

## Method Summary
Given a multimodal query (text description plus optional audio reference), the system retrieves an editable plugin preset from a knowledge base of validated effect configurations. The proposed TRR embedding computes an audio descriptor by: (1) extracting frame-level activations from mid-level transformer layers {4,5,6} (1-based) of a pre-trained Wav2Vec2 Base model; (2) projecting each frame to 32 dimensions with a frozen random linear layer; (3) computing the normalized Gram matrix (time-averaged cross-correlation) for each layer, averaging across layers, flattening, and L2-normalizing to a 1024-D vector. Similarity is measured via cosine distance. The benchmark comprises 1,267 guitar effect records, each with audio, text (concatenated Style and Feature fields), and numeric parameters. Evaluation uses Protocol-A, a strict anti-leakage split resolved by audio path grouping, with 204 test queries and 1,063 knowledge-base items. Baselines include Text-RAG (TF-IDF), Wav2Vec-RAG (mean-pooled final layer), CLAP, and FeatureNN-RAG.

## Key Results
- TRR achieves the lowest normalized parameter error (L2) among all baselines, with statistically significant improvements.
- Superior performance in cosine similarity, Accuracy@0.1, and module consistency metrics.
- Listening study: TRR-retrieved presets rated higher than manual tuning and on par with MusicGen for similarity to reference.
- Ablations confirm mid-level layers and projection dimension d=32 as optimal design choices.
- Robust to near-duplicate removal; results hold under progressive filtering.

## Why This Works (Mechanism)

### Mechanism 1: Gram Matrix Texture Capturing
TRR improves parameter alignment for texture-dominant effects by using normalized Gram matrices from projected mid-level Wav2Vec2 activations. This captures time-invariant cross-channel correlation structures, preserving texture-relevant statistical regularities (like modulation patterns) while discarding absolute temporal alignment. The core assumption is that texture perception is better signalled by aggregated co-occurrence statistics than by first-order summaries. Evidence: the paper explicitly states this design preserves texture-relevant co-activation structure (Sec. IV-B). Break condition: TRR underperforms for effects where perceptual identity depends on precise transient timing rather than stationary texture.

### Mechanism 2: Retrieval-Grounded Feasibility
Framing control as retrieval resolves the inverse problem's ill-posedness and enforces DSP feasibility. Instead of generating parameters from scratch, the system retrieves a nearest-neighbor preset from a finite, validated database, guaranteeing that parameters satisfy physical bounds and validity constraints by construction. This provides a feasible starting point for user refinement. Core assumption: a diverse preset database covers plausible parameter space regions. Evidence: the abstract and Sec. III emphasize producing valid parameter configurations. Break condition: retrieval fails if the knowledge base lacks presets representative of the user's intended texture, especially for novel or customized effect chains.

### Mechanism 3: Asynchronous Real-Time Separation
The architecture strictly separates the real-time, deterministic DSP audio callback from the asynchronous retrieval agent. The agent only updates the safe parameter set after validity checking, preventing audio thread blockage and ensuring glitch-free processing. Core assumption: real-time audio processing must be low-latency and deterministic; expensive computations happen off the critical path. Evidence: Sec. IV-A and IV-C describe the asynchronous operation; Table II shows retrieval latency (~4.5 ms) separate from audio callback. Break condition: if retrieval latency exceeds the user's expected update interval, the system feels unresponsive.

## Foundational Learning
- **Gram Matrix as Texture Descriptor**: TRR uses Gram matrices to capture second-order feature statistics, aggregating co-activations across time to make representations insensitive to frame ordering but sensitive to repeated patterns. *Why needed*: This is core to TRR's texture representation. *Quick check*: How does Frobenius-normalizing the Gram matrix (then L2-normalizing the flattened vector) affect robustness to global gain changes?
- **Constrained Parameter Spaces**: DSP parameters live in a bounded, non-convex space with dependencies (e.g., validity function C(θ)). The system enforces these after retrieval. *Why needed*: Ensures retrieved parameters are executable in the plugin. *Quick check*: If a retrieved preset violates C(θ), what simple repair strategy preserves texture while restoring validity?
- **Retrieval-Grounded vs. Generative Control**: Retrieval provides editable, inspectable outputs, unlike generative models that produce waveforms or unconstrained parameter vectors. *Why needed*: Editability is primary in DAW workflows. *Quick check*: Why might a state-of-the-art text-to-audio diffusion model be a poor baseline despite high waveform quality?

## Architecture Onboarding
- **Component map**: DSP Engine -> Safe Parameters (θ_safe) ; Retrieval Module -> Embeddings -> Validation & Projection -> θ_safe ; Diagnostic Fusion Heuristic (fallback) -> θ_safe.
- **Critical path**: Query -> TRR encoding (O(C²T_frm)) -> Approximate nearest-neighbor search -> Parameter validation -> Smoothed update to θ_safe -> DSP Engine (Φ(x_in; θ_safe)).
- **Design tradeoffs**: 
  - Random projection (frozen) vs PCA: random avoids data-dependent training, trading optimality for simplicity; ablations show comparable performance.
  - Mid-level layer set {4,5,6}: captures texture without excessive low-level detail or loss of temporal structure; single-layer similar, suggesting robustness.
  - Gram matrix dimensionality: projection to d=32 gives best efficiency/performance trade-off; larger d shows no benefit likely due to limited database coverage.
- **Failure signatures**:
  - Long-tail query failure: TRR's mean improvement masks many ties; excels on subsets where texture distinguishes similar presets.
  - Vague text degradation: text-only fails on generic queries; fusion correctly falls back to audio.
  - Modality conflict: fusion fails when text and audio disagree explicitly, indicating heuristic is fallback not integrator.
  - Near-duplicate inflation: results robust under near-duplicate removal, but exact cross-split leakage rigorously eliminated.
- **First 3 experiments**:
  1. Protocol-A retrieval benchmark comparing TRR to CLAP, Wav2Vec-RAG, Text-RAG, FeatureNN-RAG on 204 queries/1063 KB items, reporting min-max normalized L2, cosine, Acc@0.1 with bootstrap CIs and Holm-corrected significance.
  2. TRR ablations varying projection dimension, layer selection, and projection type to validate design choices.
  3. Multiple-stimulus listening study with 26 participants rating TRR vs. manual tuning vs. MusicGen on similarity to reference, using Friedman + Wilcoxon tests.

## Open Questions the Paper Calls Out
1. Does TRR's advantage generalize beyond guitar effects to other instruments, effect families, and mixing/mastering workflows?
2. How robust is TRR to real-world audio degradation (noise, compression) compared to clean synthetic queries?
3. Can TRR be extended for user personalization, learning individual timbral preferences from interaction history?
4. How does TRR compare against stronger modern audio representation baselines (e.g., PaSST, PANNs) absent from evaluation?
5. To what extent do objective parameter-space metrics correlate with human perceptual similarity judgments for retrieved presets?

## Limitations
- Dataset and Protocol-A splits not publicly released, blocking independent replication.
- Critical implementation details missing (random projection matrix, exact layer indices, CLAP variant, text vectorizer settings, active module threshold, DSP ranges).
- Listening study's manual tuning baseline provenance incomplete, limiting perceptual claim interpretability.
- TRR discards temporal ordering, potentially underperforming for effects where precise transients are crucial.
- Evaluation limited to a single guitar-effects dataset; generalizability unknown.

## Confidence
- TRR improves parameter alignment via Gram matrices – High (statistically significant improvements across metrics, thorough ablations).
- Retrieval framing guarantees executable parameters – Medium (logic sound, but knowledge base coverage not quantified).
- Asynchronous architecture meets real-time constraints – Medium (latency measured, design plausible, but no open implementation for verification).
