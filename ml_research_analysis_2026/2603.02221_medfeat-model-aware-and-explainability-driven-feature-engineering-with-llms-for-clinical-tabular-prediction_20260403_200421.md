# MedFeat: Model-Aware and Explainability-Driven Feature Engineering with LLMs for Clinical Tabular Prediction

## Quick Facts
- **arXiv ID**: 2603.02221  
- **Source URL**: https://arxiv.org/abs/2603.02221  
- **Reference count**: 38  
- **Primary result**: MedFeat outperforms existing baselines, achieving up to 7.9% AUC gain on 24-hour inpatient mortality and 28.6% F1 improvement, with robust gains even after extensive hyperparameter optimization.

## Executive Summary
MedFeat is a framework for automated feature engineering on clinical tabular data that integrates model-awareness and explainability via LLMs. It iteratively uses SHAP values to prioritize important feature subsets, prompts an LLM with model-specific guidance (e.g., emphasizing nonlinearities for linear models, robust temporal patterns for XGBoost), and validates candidates by retraining the downstream model. Evaluated across five tasks on IORD, MIMIC-IV, and HRS datasets, MedFeat consistently improves predictive performance and demonstrates robustness to temporal shift and cohort transfer.

## Method Summary
MedFeat operates in an iterative loop. It first trains a baseline model on original features and computes SHAP values on a validation set. Features are grouped (e.g., temporally correlated measurements) and sampled into small “islands” with probability proportional to normalized SHAP importance. For each island, an LLM (e.g., GPT-4o) is queried with a prompt containing the task, model type, SHAP-ranked features, and memory of past accepted/rejected transformations. The LLM returns a Python function to generate a new feature. After local validation (execution, numeric output check, no data leakage), the feature is added, the model is retrained, and validation performance is assessed. If improvement exceeds a tolerance (β=0.01), the feature is accepted; memory is updated accordingly. The process repeats for a fixed number of iterations (T=3).

## Key Results
- Achieved AUC 0.740 vs. 0.686 (7.9% gain) on 24-hour inpatient mortality.
- Delivered up to 28.6% F1 improvement; maintained +36.4% F1 gains on imbalanced tasks after full hyperparameter optimization.
- Features transferred between cohorts showed improved stability; temporal shift experiments revealed reduced performance degradation.

## Why This Works (Mechanism)
### Mechanism 1
- **Claim**: MedFeat generates more relevant features by conditioning LLM proposals on the downstream model's inductive biases.
- **Mechanism**: The framework provides model-specific guidance in prompts (e.g., emphasizing nonlinearities for linear models, robust temporal patterns for tree ensembles), steering the LLM to produce transformations that address the model's representational gaps rather than redundant patterns.
- **Core assumption**: Different learners have predictable weaknesses (e.g., linear models cannot capture interactions without explicit construction); LLMs can follow such instructions to propose complementary features.
- **Evidence anchors**: 
  - Abstract: “By incorporating model awareness, MedFeat prioritizes informative signals that are difficult for the downstream model to learn directly due to its characteristics.”
  - Section 3.4 details model-aware prompting with concrete examples for logistic regression versus XGBoost.
  - Corpus: Neighbor works like CAAFE and FeatLLM use model-agnostic prompts, underscoring MedFeat's targeted design.
- **Break condition**: If the model's inductive bias is mischaracterized or the LLM fails to adhere to instructions, generated features may be irrelevant or redundant.

### Mechanism 2
- **Claim**: SHAP-based importance sampling stabilizes and focuses feature discovery by grounding proposals in model explanations rather than noisy validation metrics.
- **Mechanism**: SHAP values from the current model inform the probability distribution for sampling "feature islands" and the content of LLM prompts (via importance rankings), ensuring concentration on high-impact features.
- **Core assumption**: SHAP scores provide a more robust signal of feature relevance than validation performance alone, especially under class imbalance and label noise.
- **Evidence anchors**: 
  - Abstract: “uses SHAP value-based explanation scores and rankings as generation signals, both to prioritize features during sampling and to condition the LLM prompt.”
  - Section 3.2 describes explainability-driven feedback; Section 3.3 defines importance-weighted island sampling.
  - Corpus: Prior LLM-based methods rely heavily on validation metrics, which can be unstable in healthcare data; SHAP offers an alternative.
- **Break condition**: If SHAP values are unreliable (e.g., extreme collinearity or small validation sets), sampling may misrank features.

### Mechanism 3
- **Claim**: Iterative feedback with memory of accepted/rejected features refines the search process, reduces redundant proposals, and improves convergence to clinically meaningful features.
- **Mechanism**: After each iteration, accepted features are added and rejected ones are logged; this memory influences future island sampling and prompt conditioning, creating a self-improving loop.
- **Core assumption**: Historical success/failure of feature transformations is predictive of future utility; tracking this metadata accelerates discovery.
- **Evidence anchors**: 
  - Abstract: “tracking successful and failed proposals to guide feature discovery.”
  - Section 3.6 outlines feedback memory updating.
  - Corpus: OCTree uses memory via decision-tree reasoning summaries, but MedFeat integrates it with explainability signals.
- **Break condition**: If early iterations produce misleading failures, memory may incorrectly suppress promising patterns.

## Foundational Learning
- **Concept**: SHAP (SHapley Additive exPlanations)  
  - **Why needed**: To compute feature importance scores that drive island sampling and prompt conditioning; provides a model-agnostic explanation method that quantifies each feature's contribution.  
  - **Quick check**: How do SHAP values differ from permutation importance in terms of consistency and computational cost for tree-based models?

- **Concept**: Inductive Biases of Tabular Models  
  - **Why needed**: To design model-aware prompts that exploit weaknesses (e.g., linear models need explicit interactions, tree ensembles may miss complex temporal aggregates).  
  - **Quick check**: Why might XGBoost still benefit from engineered features like rolling statistics despite its ability to approximate nonlinearities?

- **Concept**: LLM Prompt Engineering for Code Generation  
  - **Why needed**: To craft prompts that elicit clinically valid, executable Python transformations with constraints (e.g., "avoid trivial thresholding for XGBoost").  
  - **Quick check**: What are key elements of a prompt that ensures LLM-generated code is both safe (no data leakage) and relevant to the clinical task?

## Architecture Onboarding
- **Component map**:  
  SHAP Calculator -> Island Sampler -> LLM Generator -> Validator -> Feedback Memory -> Model Trainer (next iteration)

- **Critical path**:  
  1. Train baseline model on original features.  
  2. Compute SHAP values on validation set.  
  3. Sample K islands of m features each, proportional to normalized SHAP, grouping correlated temporal features.  
  4. For each island, build model-aware prompt with memory and query LLM.  
  5. Parse and validate generated feature functions; apply to datasets.  
  6. Retrain model for each candidate and compute validation metric.  
  7. Select best island if improvement exceeds tolerance β; update feature set, memory, and baseline model.  
  8. Repeat until T iterations.

- **Design tradeoffs**:  
  - Privacy vs. Utility: No raw patient data sent to LLM (only metadata and SHAP scores), but this may limit context for highly specific features.  
  - Computational Cost: Retraining the model for each candidate is expensive; island sampling and limited iterations mitigate this.  
  - Prompt Length vs. Diversity: Smaller islands reduce token usage but may miss cross-feature interactions; multiple islands per iteration balance exploration.

- **Failure signatures**:  
  - LLM generates syntactically invalid or non-executable code repeatedly.  
  - SHAP rankings are unstable across splits, leading to inconsistent island sampling.  
  - No validation improvement after several iterations, suggesting poor prompt design or model mismatch.  
  - Accepted features degrade performance on certain subgroups, indicating lack of fairness considerations.

- **First 3 experiments**:  
  1. **Smoke Test**: Run MedFeat for 1 iteration on a small, balanced dataset (e.g., a subset of IORD) to verify the end-to-end flow: SHAP computation, island sampling, LLM query, code execution, and model retraining.  
  2. **Ablation - Model Awareness**: Disable model-specific instructions in prompts (use generic prompts) and compare performance to full MedFeat; expect significant drops, especially for linear models.  
  3. **Cross-Model Transfer**: Apply features generated for XGBoost to a logistic regression model (or vice versa) to test adaptability; performance should degrade if model-awareness is critical.

## Open Questions the Paper Calls Out
- **Question 1**: Can reinforcement learning be integrated into MedFeat to optimize feature selection and improve predictive performance?  
  *Basis*: The conclusion states: “whether reinforcement learning can be used to improve performance with such signals remains a promising direction.”  
  *Why unresolved*: The current MedFeat uses a simple winner-takes-all selection; RL could provide a more adaptive, reward-driven mechanism.

- **Question 2**: How can clinicians' domain knowledge be effectively incorporated into MedFeat's feature engineering process to enhance clinical relevance and trust?  
  *Basis*: The conclusion mentions: “the framework could benefit from clinicians’ input.”  
  *Why unresolved*: MedFeat operates fully automatically; the optimal interaction mode for clinician feedback is unknown.

- **Question 3**: How does the presence of high collinearity and noise in clinical data affect the stability of SHAP-based importance rankings and, consequently, MedFeat's feature discovery?  
  *Basis*: The limitations note: “If the data has strong collinearity or noise, the importance ordering might vary across splits.”  
  *Why unresolved*: No empirical evaluation under varying collinearity/noise levels is provided.

- **Question 4**: To what extent do MedFeat-generated features generalize across diverse healthcare systems and coding standards beyond the evaluated cohorts?  
  *Basis*: The paper shows transfer between ICU (MIMIC) and general inpatient (IORD) populations, but broader generalization across countries/EHR systems is not tested.  
  *Why unresolved*: Healthcare data heterogeneity may limit feature portability; the LLM's role in compensating is unclear.

## Limitations
- Prompt design (exact templates, few-shot examples, model-specific phrasing) is underspecified, risking output quality divergence.
- SHAP aggregation method for temporal feature groups (e.g., mean vs. max across time points) is unclear, affecting island sampling stability.
- Memory mechanics (similarity computation, prompt conditioning beyond listing examples) lack implementation depth; early false negatives could persist.
- Environmental factors (fixed seeds, library versions, categorical handling) may cause subtle reproducibility gaps.

## Confidence
- **Model-awareness efficacy**: Medium (theoretically plausible, partially evidenced, but prompt details could alter outcomes)
- **SHAP-guided stabilization**: Medium (relies on SHAP robustness; high collinearity/small validation sets may undermine rankings)
- **Iterative memory refinement**: Low-Medium (mechanistically described but lacks implementation depth; early misleading failures could persist)
