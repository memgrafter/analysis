# Reasoning Provenance for Autonomous AI Agents: Structured Behavioral Analytics Beyond State Checkpoints and Execution Traces

## Quick Facts
*   **ArXiv ID:** 2603.21692
*   **Source URL:** https://arxiv.org/abs/2603.21692
*   **Reference count:** 11
*   **Primary result:** Introduces the Agent Execution Record (AER), a schema-level primitive that captures normalized reasoning provenance (intent, observation, inference), enabling population-level behavioral analytics and counterfactual testing; preliminary analysis shows 4–22× storage compactness vs. cumulative checkpoints.

## Executive Summary
Autonomous AI agents lack structured, queryable records of their reasoning—the why behind actions—limiting analysis to debugging single runs via state checkpoints or raw execution traces. This paper identifies a fundamental gap: reasoning provenance (intent, observations, inferences) cannot be faithfully reconstructed post-hoc from computational state alone. The core solution is the Agent Execution Record (AER), a formal schema that captures reasoning annotations contemporaneously alongside versioned plans, evidence chains, and delegation chains. This enables new analytics like pattern mining, confidence calibration, and "mock replay" for counterfactual regression testing. A reference implementation and evaluation methodology are provided, with early evidence suggesting AERs are significantly more storage-efficient than cumulative checkpoints while offering superior long-term analytical value.

## Method Summary
Reproducing the core contribution requires implementing the AER schema and instrumentation. An agent must be instrumented to log a structured record per investigation, writing files (`envelope.json`, `plans.jsonl`, `steps.jsonl`, `verdict.json`) to a dedicated directory. Each step log must capture `intent`, `tool_calls` (with input/output), `observation`, and `inference` as schema-constrained fields. The `record_verdict()` call finalizes the investigation with a structured outcome and its `evidence_chain`. The replay engine can then execute in "mock" mode, substituting recorded tool outputs while re-running the reasoning logic (via a new model/prompt) to measure divergence. A minimum viable reproduction involves: (1) setting up the AER SDK, (2) instrumenting a simple agent loop to emit valid AER steps, and (3) running mock replay to verify the divergence reporting mechanism.

## Key Results
*   **Formal Distinction:** Proven that reasoning provenance is not faithfully reconstructible from computational state checkpoints and execution traces alone due to intent multiplicity, observation ambiguity, and inference volatility.
*   **New Analytics Enabled:** AER's normalized schema supports direct population-level queries (e.g., re-plan frequency, confidence calibration) and counterfactual regression testing via mock replay without live system access.
*   **Storage Efficiency:** Preliminary analysis indicates AERs are 4–22× more compact than cumulative checkpoints (e.g., from systems like LangGraph) while retaining higher long-term analytical utility.

## Why This Works (Mechanism)

### Mechanism 1
*   **Claim:** Structured reasoning provenance cannot be faithfully reconstructed from computational state checkpoints and raw execution traces for cross-run behavioral analytics.
*   **Mechanism:** A non-identifiability argument (Section 3.2) exposes three gaps: (1) **Intent multiplicity**—different rationales can produce identical tool call sequences; (2) **Observation ambiguity**—the meaning of tool output depends on contextual reasoning; (3) **Inference volatility**—intermediate strategic reasoning varies in form and completeness. Post-hoc extraction from model responses is fragile and non-standardized.
*   **Core Assumption:** Reasoning annotations must be captured contemporaneously as schema-constrained fields to ensure stable, queryable, and comparable records across thousands of runs.
*   **Evidence Anchors:**
    *   [abstract]: "structured reasoning provenance—normalized, queryable records of why the agent chose each action, what it concluded from each observation..."
    *   [section 3.2]: "Given only the persisted computational state S₁..ₖ, reasoning provenance R₁..ₖ cannot in general be faithfully reconstructed..."
    *   [corpus]: Limited direct support; neighboring papers focus on supply-chain provenance (SBOMs) or human-agent frameworks, not this computational vs. reasoning distinction.

### Mechanism 2
*   **Claim:** The Agent Execution Record (AER) model enables population-level behavioral analytics by elevating reasoning to a first-class, schema-level primitive.
*   **Mechanism:** AER mandates the capture of `intent`, `observation`, and `inference` on every step, coupled with versioned plans (with revision rationales), evidence chains, structured verdicts, and delegation chains (Section 4). This normalized representation allows direct querying (e.g., "investigations where final inference included 'DNS misconfiguration'") without custom extraction logic per workflow.
*   **Core Assumption:** Cross-run analytics require a domain-agnostic core schema with extensible profiles to guarantee comparable semantic objects across heterogeneous agent deployments.
*   **Evidence Anchors:**
    *   [abstract]: "...captures intent, observation, and inference as first-class queryable fields... versioned plans with revision rationale, evidence chains..."
    *   [section 4]: AER components illustrated for the DBINFRA-1458 example (envelope, plans.jsonl, steps.jsonl, verdict.json).
    *   [corpus]: Neighbors like "LLM Agents for Interactive Workflow Provenance" (arxiv:2509.13978) address workflow provenance but omit agent-specific reasoning fields.

### Mechanism 3
*   **Claim:** Mock replay, powered by AERs, enables robust counterfactual regression testing using real production investigation data without access to live systems.
*   **Mechanism:** AERs store exact tool outputs and reasoning annotations. Mock replay re-executes the agent's reasoning logic step-by-step with a substituted model/prompt, feeding the recorded, deterministic tool outputs. Divergence in step-level `inference` or final `verdict` is automatically measured, isolating the impact of reasoning changes from environmental drift (Section 5.2).
*   **Core Assumption:** Tool outputs are deterministic or can be faithfully recorded; divergence in replay reflects changes in the reasoning model/prompt, not changes in the external environment.
*   **Evidence Anchors:**
    *   [abstract]: "...counterfactual regression testing via mock replay."
    *   [section 5.2]: Example comparing codex-5.3 vs. codex-6.0 on DBINFRA-1458, showing step-level and verdict convergence metrics.
    *   [corpus]: No direct corpus evidence; surveyed agent systems (OpenClaw, ScienceClaw) lack described replay capabilities.

## Foundational Learning
*   **Concept: Computational State vs. Reasoning Provenance**
    *   *Why needed:* Grasping this distinction is prerequisite to understanding AER's necessity. It clarifies that checkpoints (snapshots of variables) and traces (logs of events) alone cannot answer questions about *why* an agent chose a specific action.
    *   *Quick check:* Can you determine from a checkpoint whether an agent checked a database listener because of a standing plan rule ("check all layers top-down") or because of a specific observed error ("TNS in error state")?
*   **Concept: Schema-Level Primitives for Cross-Run Analytics**
    *   *Why needed:* AER's value derives from its normalized, enforced schema (`intent`, `observation`, `inference` fields). This guarantees that semantically equivalent reasoning steps across thousands of investigations are stored in a comparable structure, enabling aggregate queries.
    *   *Quick check:* Why would a query for "percentage of investigations where `intent='rule out DNS'`" fail if `intent` were stored as free-text narrative in a trace?
*   **Concept: Mock Replay vs. Time-Travel Debugging**
    *   *Why needed:* This distinction is key for causal testing. Mock replay *fixes the environment* (uses recorded tool outputs) to isolate reasoning changes. Time-travel debugging (e.g., LangGraph) re-executes against live systems, conflating reasoning and environmental changes.
    *   *Quick check:* You want to test if a new, more cautious prompt changes agent behavior. Which replay mode should you use and why?

## Architecture Onboarding
*   **Component map:** `aer-sdk.py` -> `agent-executions/` (per-investigation dirs: `envelope.json`, `plans.jsonl`, `steps.jsonl`, `verdict.json`) -> `emitter/` (async stream to Kafka/Avro) -> `materializer/` (reassembles full AER from stream) -> `query-api/` (REST/GraphQL over document DB)
*   **Critical path:** `start_investigation()` → write `envelope.json` → `log_plan()` → (loop: `log_step()` for {intent, tool call, observation, inference}) → `record_verdict()` → (optional) `emit()`.
*   **Design tradeoffs:**
    *   **Storage vs. Fidelity:** Omitting raw LLM responses saves space but loses verbatim evidence for deep audits. Recommendation: omit by default, enable on-demand capture.
    *   **Self-Report vs. Ground Truth:** AER uses the agent's self-reported reasoning. Trade-off: captures perceived decision inputs vs. risks post-hoc rationalization. Mitigation: validate via action-intent consistency checks.
    *   **Schema Stability:** Core schema must evolve additively (new fields only). Domain-specific profiles version independently. Breaking changes require costly migration.
*   **Failure signatures:**
    *   `intent`/`observation`/`inference` fields are null or placeholders → prompt/agent integration failure.
    *   Verdict's `evidence_chain` references missing steps or skips logical steps → flawed inference logging.
    *   `authority_chain` (delegation) has gaps or unknown principals → IAM/service-mesh integration fault.
*   **First 3 experiments:**
    1.  **Schema capture validation:** Run a test investigation with a mock agent. Verify every `log_step()` call produces JSONL conforming to the AER JSON schema. Check `step_id` sequence integrity.
    2.  **Mock replay smoke test:** On a 5-step test case, run `aer replay --mode mock` with a trivial model override (e.g., force all `inference` to "unchanged"). Verify the divergence report correctly identifies steps where the new model's output would differ.
    3.  **Storage baseline:** Simulate 50 investigations (10 steps each). Compare cumulative checkpoint size (simulate LangGraph message accumulation) vs. AER size (without raw). Confirm the 4–22× compression ratio.

## Open Questions the Paper Calls Out
*   **Open Question 1:** How can we systematically validate the faithfulness of self-reported reasoning fields (intent, observation, inference) in AERs, given risks of post-hoc rationalization and prompt-induced artifacts?
*   **Open Question 2:** How can AER be extended to model multi-agent investigations, composing individual agent records into a unified, queryable provenance view that captures cross-agent evidence chains and joint verdicts?
*   **Open Question 3:** What is the real-world storage overhead and long-term analytical value trajectory of AERs compared to cumulative state checkpoints across diverse agent workloads and retention policies?
*   **Open Question 4:** Under what formal conditions (e.g., agent architecture, planning mechanism) is reasoning provenance provably non-reconstructible from computational state checkpoints and execution traces?

## Limitations
*   **Implementation Access:** The reference implementation/SDK location, installation instructions, and exact schema definitions are unspecified, blocking direct reproduction.
*   **Scalability Evidence:** The claimed 4–22× storage compactness is based on "preliminary analysis" from a stylized 10-step investigation. Full empirical validation across diverse, real-world workloads is absent.
*   **Schema Adoption & Ground Truth:** The core assumption that self-reported reasoning fields are stable and faithful across different LLM prompts/agents is untested at scale. No mechanism exists to validate against an external ground truth of agent reasoning.

## Confidence
*   **Reasoning Non-Reconstructibility:** High. The formal argument (intent multiplicity, observation ambiguity, inference volatility) is sound and clearly explained.
*   **AER's Value for Analytics:** Medium. The schema design logically addresses the stated gaps, but empirical evidence for "pattern mining" and cross-run utility is theoretical or based on limited examples.
*   **Mock Replay Utility:** Medium. The mechanism is convincingly described and demonstrated on one case, but generalization to non-deterministic tools, complex stateful environments, and large-scale regression testing remains unproven.

## Next Checks
1.  **Reconstructibility Test:** Implement a deterministic, fixed-rule agent. Generate executions and store ground-truth reasoning. Use an LLM-as-judge to attempt reconstructing `intent`/`inference` from state/trace alone. Quantify accuracy and failure modes.
2.  **Storage Scaling:** Using the accessible SDK, simulate 1,000 synthetic investigations (varying steps, plan versions, tool output sizes). Measure AER size (with/without raw LLM responses) against cumulative checkpoint overhead from a system like LangGraph. Verify if the 4–22× compression ratio holds.
3.  **Replay Precision:** For a suite of 20 diverse investigations, conduct mock replay with a deliberately altered model/prompt. Systematically compare step-level `inference` and final `verdict` divergence. Analyze if divergence patterns align with expected changes from the prompt modification (e.g., a "more cautious" prompt should increase `confidence` thresholds and alter risk-related `inference`).
