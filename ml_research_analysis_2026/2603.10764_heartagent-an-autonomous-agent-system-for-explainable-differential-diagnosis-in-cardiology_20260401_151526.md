# HeartAgent: An Autonomous Agent System for Explainable Differential Diagnosis in Cardiology

## Quick Facts
- arXiv ID: 2603.10764  
- Source URL: https://arxiv.org/abs/2603.10764  
- Reference count: 40  
- Primary result: Improved top-3 diagnostic accuracy by >36% on MIMIC and >20% on UMN; assisted clinicians gained 26.9% accuracy and 22.7% explanatory quality; reference precision 92% and recall 80%.

## Executive Summary
HeartAgent is a multi‑agent AI system designed to perform explainable differential diagnosis in cardiology. It orchestrates specialized sub‑agents—a specialist predictor, a generalist examiner, and a specialist reviewer—augmented with curated medical knowledge and external tools. On benchmark datasets (MIMIC, UMN) it substantially outperformed baseline methods, and when used as a decision‑support tool it increased both diagnostic accuracy and explanation quality for clinicians. The system also retrieves verifiable supporting references with high precision and recall.

## Method Summary
The system processes multimodal clinical data (notes, ECG, echocardiography, tabular labs) via modality‑specific tools (e.g., NeuroKit2 for ECG, MedGemma for imaging) to produce standardized reports. A core orchestrator then activates four cooperative agents: a specialist predictor generates initial cardiac diagnoses; a generalist examiner adds potential non‑cardiac differentials; a specialist reviewer refines the cardiac list; finally, the predictor re‑evaluates all evidence in a self‑verification loop. Explanations are enriched by a reference agent that uses hybrid BM25 + MedCPT retrieval from a curated corpus of cardiology guidelines and textbooks. No model training occurs; inference uses a fixed LLM with low temperature. Knowledge sources include a manually curated JSON disease database, a static case repository, and a web searcher for rare conditions.

## Key Results
- Top‑3 diagnostic accuracy: +36.5% on MIMIC and +20.2% on UMN vs. baselines.  
- Clinician assistance: +26.9% diagnostic accuracy and +22.7% improvement in explanatory quality over unaided experts.  
- Reference retrieval: 92% precision and 80% recall for supporting passages.

## Why This Works (Mechanism)
**Collaborative multi‑agent structure** – The reasoning task is divided among three agents with distinct roles: predictor, examiner, reviewer. This separation reduces cognitive load and enables iterative cross‑checking. The core assumption is that distributing reasoning across specialized modules improves accuracy compared to a single monolithic pass (supported by the system’s ablation showing contributions of each agent; break condition: irreconcilable agent conflict could collapse benefits).

**Dynamic invocation of curated external knowledge** – Agents call tools (knowledge retriever, web searcher, case searcher, modality analyzers) to ground LLM outputs in up‑to‑date, domain‑specific information. This bridges parametric knowledge gaps in LLMs and reduces hallucinations (supported by accuracy drops when tools are disabled; break condition: incomplete knowledge base or poor query formulation degrades performance).

**Reference verification** – After generating an explanation, the reference agent converts it into queryable claims, retrieves passages from a segmented cardiology corpus using BM25 + MedCPT, and uses an LLM to judge support. This creates a traceable link between diagnosis and authoritative sources, enhancing explainability and trust (supported by precision/recall metrics; break condition: insufficient corpus coverage or incorrect support judgment leads to missing or misleading citations).

## Foundational Learning
- **Multi‑Agent System Design** – Decomposing a complex clinical reasoning task into interacting modules can improve robustness over a single‑agent approach. Quick check: What failure modes arise when multiple autonomous agents collaborate (e.g., deadlock, inconsistent outputs)?  
- **Retrieval‑Augmented Generation (RAG) for Domain‑Specific Grounding** – Connecting an LLM to external, curated knowledge (guidelines, textbooks, case repositories) overcomes parametric limitations and reduces hallucinations in high‑stakes domains. Quick check: How do retrieval method (BM25 vs. dense MedCPT) and chunking strategy affect relevance of evidence?  
- **Clinical Differential Diagnosis Workflow** – Mapping agent roles (predictor, examiner, reviewer) onto clinician cognitive steps (hypothesis generation, broadening, narrowing) ensures clinical validity. Quick check: In what ways might an AI’s process differ from a clinician’s (e.g., handling uncertainty, patient preferences) and how does the agent design bridge that gap?

## Architecture Onboarding
Component map: Input Processor (clinical notes parser, ECG interpreter, vision analyzers, tabular risk calculator) → Core Agent Orchestrator (manages workflow among Specialist Predictor, Generalist Examiner, Specialist Reviewer) ↔ Knowledge Tools (Case Searcher, Knowledge Retriever, Web Searcher) → Self‑Verification Loop (Specialist Predictor re‑evaluates) → Reference Agent (BM25 + MedCPT retrieval + LLM verification) → Output Formatter.

Critical path:  
1. Raw clinical data → modality‑specific tools → standardized reports.  
2. Reports → Specialist Predictor → initial top‑k cardiac diagnoses + rationales.  
3. Initial outputs + reports → Generalist Examiner → non‑cardiac additions.  
4. Initial outputs + reports → Specialist Reviewer → cardiac revisions/additions.  
5. All proposals → Self‑Verification (Specialist Predictor) → final refined diagnoses.  
6. Final diagnoses + rationales → Reference Agent → evidence‑backed explanations.  
7. Final output: ranked list with supporting references.

Design tradeoffs:  
- Modularity vs. Latency – More agents/tool calls improve accuracy/explainability but increase inference time; design prioritizes accuracy for decision support over real‑time speed.  
- Curated Knowledge vs. Coverage – A small, high‑quality corpus ensures precision but may miss rare conditions; mitigated by a web searcher fallback but with less control.  
- Agent Autonomy vs. Control – Agents have some independence (e.g., Examiner suggests differentials) but final synthesis is centralized in Predictor’s self‑verification, preventing chaotic outputs but risking bottlenecking.  
- Open‑Source vs. Proprietary LLMs – System is model‑agnostic; trade‑off: open‑source models (e.g., MedGemma) are deployable but may have lower capacity; proprietary models (GPT‑5) perform better but pose privacy/access barriers.

Failure signatures:  
- Agent Conflict (persistent disagreement among agents without resolution).  
- Tool Failure (modality analyzer returns errors or irrelevant reports).  
- Knowledge Gap (disease or presentation absent from curated DB/case repo and web search fails).  
- Retrieval Miss (reference agent fails to find support for >20% of explanations).  
- Hallucination Persistence (factual errors not caught by reference verification).  
- Latency Spikes (excessive tool call or deliberation time).

First 3 experiments:  
1. Baseline Replication & Sanity Check – Run a simple Chain‑of‑Thought baseline on a small held‑out subset (e.g., 10 NEJM cases) to verify pipeline integrity and establish a performance floor.  
2. Component Ablation – Single Agent – Disable Generalist Examiner and Specialist Reviewer one at a time; measure drop in top‑3 accuracy and explanation score against full system.  
3. Tool‑Knowledge Sensitivity Test – Systematically disable curated knowledge base, web resource, and case repository (separately) on a batch of cases; evaluate impact on accuracy and factuality for common vs. rare conditions.

## Open Questions the Paper Calls Out
- **Pediatric applicability** – How well does HeartAgent perform on pediatric cardiology cases? The study used only adult datasets (MIMIC, UMN, NEJM), leaving pediatric application unexplored.  
- **HIPAA‑compliant deployment with commercial LLMs** – Can HeartAgent operate effectively in privacy‑preserving clinical environments when integrated with commercial LLMs? Due to privacy restrictions, commercial LLM performance was only evaluated on open‑source datasets.  
- **Improving reference retrieval for non‑canonical language** – How can reference retrieval be enhanced when explanations use patient‑specific or non‑standard terminology? The system missed supporting references for ~20% of explanations because clinically correct explanations differed from textbook phrasing.  
- **Long‑term knowledge maintenance** – What are the scalability and maintenance costs of the manually curated knowledge base and case repository? The paper does not address updating for evolving medical knowledge or resource scalability.

## Limitations
- **Reproducibility blockers** – Exact agent prompts, interaction protocols, and the full curated disease database structure are undisclosed, requiring significant reverse‑engineering.  
- **Evaluation opacity** – Details of the LLM‑as‑judge setup (prompt, rubric, model) for explanation quality are missing, hindering verification of secondary metrics.  
- **External validation gap** – Performance claims rely solely on proprietary/internal datasets; no independent test on a publicly available held‑out cardiology benchmark is reported.  
- **Citation coverage** – Reference recall is 80%, meaning one in five explanations lacks verifiable support, potentially limiting clinical trust.

## Confidence
- Multi‑agent collaboration benefit: Medium  
- Tool/curated knowledge grounding: Medium  
- Reference verification for explainability: Low  

## Next Checks
1. **Agent Role Isolation Test** – Run the system with only the Specialist Predictor active, then add Examiner and Reviewer sequentially on a fixed case set; quantify incremental changes in top‑3 accuracy and explanation coherence.  
2. **Tool‑Knowledge Contribution Disentanglement** – Systematically disable (a) curated JSON knowledge base, (b) web searcher, (c) case repository; measure differential impact on accuracy for common vs. rare conditions.  
3. **Clinician‑Centric Citation Utility Study** – Present 50 diagnosis explanations with and without the 92‑% precise citations to a panel of cardiologists; compare time to verify rationale, trust scores, and agreement with diagnosis.
