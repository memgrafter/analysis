# A Hybrid Deterministic Framework for Named Entity Extraction in Broadcast News Video

## Quick Facts
*   **arXiv ID:** 2602.09154
*   **Source URL:** https://arxiv.org/abs/2602.09154
*   **Reference Count:** 40
*   **Primary Result:** Proposed deterministic pipeline (ANEP) achieves 77.08% F1 for name extraction, traded for full auditability against a generative baseline (Gemini 1.5 Pro) at 84.18% F1.

## Executive Summary
This paper introduces ANEP, a deterministic, modular pipeline for extracting personal names from broadcast news video graphics. The system addresses a practical journalistic need for transparent, reliable indexing of on-screen names amidst highly variable graphic designs. It combines YOLOv12 for graphic detection, OCR, and a fine-tuned NER model. A user survey confirms 59% of people struggle to read these names, underscoring the task's relevance. While a state-of-the-art generative model (Gemini 1.5 Pro) achieves higher raw accuracy (84.18% F1), ANEP prioritizes auditability and transparent data lineage, achieving 77.08% F1. The work establishes a transparent, reproducible baseline and highlights a key accuracy-auditability trade-off for deployment in accountability-sensitive domains.

## Method Summary
The authors develop the ANEP pipeline and evaluate it on a novel News Graphics Dataset (NGD). The NGD contains 1,500 annotated frames (640x640) across six graphic categories. The pipeline stages are: 1) frame sampling & deduplication, 2) YOLOv12(m) object detection (trained from scratch on the NGD), 3) region cropping & image preprocessing, 4) OCR with confidence filtering, 5) NER via a fine-tuned transformer, 6) heuristic filtering, and 7) name clustering to merge variants. The detector's performance (mAP@0.5) is reported. Full pipeline results (Precision, Recall, F1) are compared against a zero-shot Gemini 1.5 Pro prompt on the same test set. Runtime is measured on a MacBook Air M2.

## Key Results
*   The YOLOv12-based graphic detector achieves 95.8% mAP@0.5, demonstrating robust localisation across diverse formats.
*   ANEP achieves 79.9% precision and 74.4% recall (F1: 77.08%) for final name extraction on the NGD test set.
*   The generative baseline (Gemini 1.5 Pro) achieves a higher F1-score of 84.18% but functions as a non-transparent black box.

## Why This Works (Mechanism)

### Mechanism 1: Auditability via Deterministic Modularity
*   **Claim:** ANEP's design enables full auditability and traceable data lineage for each extracted name.
*   **Mechanism:** The pipeline decomposes the task into discrete, sequential stages (detection, OCR, NER, clustering). Each stage outputs inspectable intermediates (bounding boxes, raw text, entity tags) that can be logged, validated, and diagnosed independently. This contrasts with an end-to-end generative system's opaque final output.
*   **Evidence:** [abstract] states the design enables "transparent data lineage"; [section III.C] details the five stages and their role in supporting "interpretability at each processing stage."

### Mechanism 2: Robust Foundation via YOLOv12 Detection
*   **Claim:** YOLOv12's attention-centric architecture provides operationally robust detection of diverse, variable news graphics, forming a reliable foundation for downstream OCR.
*   **Mechanism:** Attention mechanisms enhance focus on text-dense regions (e.g., lower-thirds) and improve multi-scale feature representation. This handles variability in graphic size, overlap, and styling, leading to high mAP.
*   **Evidence:** [abstract] cites 95.8% mAP@0.5; [section IV.B] uses Grad-CAM to show strong activation in text regions and cross-format success.

### Mechanism 3: Quantified Trade-off with Generative Models
*   **Claim:** The framework establishes a methodological trade-off where deterministic auditability is achieved at a measurable cost to raw extraction F1-score compared to a state-of-the-art generative model.
*   **Mechanism:** Direct comparison shows Gemini 1.5 Pro (F1: 84.18%) outperforms ANEP (F1: 77.08%). The gap is attributed to the generative model's holistic, contextual reasoning, which compensates for OCR noise and layout ambiguities that plague the stepwise pipeline.
*   **Evidence:** [abstract] and [section IV.C.1] explicitly contrast the metrics and transparency; [section IV.C.2] details ANEP's error sources (OCR noise, clustering limits) that generative models may implicitly resolve.

## Foundational Learning
*   **Concept: Modular Pipeline Design**
    *   **Why needed:** Auditability requires separable, replaceable components with clear I/O contracts to trace errors.
    *   **Quick Check:** If the OCR confidence threshold is lowered, how does precision/recall change downstream, and how would you trace this in the logs?
*   **Concept: Object Detection for UI/Graphics**
    *   **Why needed:** Graphics are non-standard "objects" differing from natural objects; detection must focus on layout and typography-dense regions.
    *   **Quick Check:** How would you augment training data to prepare the detector for semi-transparent tickers overlapping lower-thirds?
*   **Concept: OCR in Styled Environments**
    *   **Why needed:** Broadcast graphics use diverse fonts/effects that degrade OCR; preprocessing and engine choice are critical.
    *   **Quick Check:** For OCR output "Dona1d Trump" ('l'->'1'), which pipeline step failed to normalize it, and how would you fix it?

## Architecture Onboarding
*   **Component map:** Video Ingest & Frame Sampler -> Graphic Detector (YOLOv12) -> Pre-processor (crop/enhance) -> OCR Engine -> NER Model -> Heuristic Filter -> Name Clusterer -> Timeline Generator
*   **Critical path:** Frame -> Detection -> Crop -> OCR -> NER -> Clustering -> Final Name & Timestamps. A failure at any stage halts a name's progression.
*   **Design tradeoffs:**
    *   Accuracy vs. Auditability: Accepted ~7% lower F1 for full traceability vs. Gemini.
    *   Precision vs. Recall in NER: Fine-tuning likely favoured precision; clustering trades recall for canonical simplicity.
    *   Offline vs. Real-time: 542s runtime (vs. Gemini's 94s) indicates batch-processing design.
*   **Failure signatures:**
    *   Detection: Missing a graphic (FN) loses the entire name chain.
    *   OCR: Character substitution ("Dona1d") corrupts input to NER.
    *   NER: Common word "Swift" filtered as non-person (FP or FN).
    *   Clustering: "President Trump" and "Donald Trump" not merged (False Split).
*   **First 3 experiments:**
    1.  **Component Isolation Test:** Run ground-truth graphic crops *only* through the OCR module. Measure character error rate (CER) on stylized vs. plain text to isolate the primary bottleneck.
    2.  **Pipeline Sensitivity Analysis:** Systematically vary NER confidence and clustering similarity thresholds. Plot full-pipeline P-R curves to find optimal points for high-precision vs. high-recall use cases.
    3.  **Cross-Domain Generalisation Check:** Test the trained YOLOv12 on held-out frames from a novel news channel/style. Measure mAP drop to quantify robustness before deployment.

## Open Questions the Paper Calls Out
*   **Question 1:** Can deterministic pipelines like ANEP achieve generative model-level accuracy (F1 >84%) without sacrificing auditability? The paper frames this as an inherent trade-off and does not explore targeted enhancements to close the gap.
*   **Question 2:** How can ANEP's OCR and NER be reliably extended to non-Latin scripts and highly stylized/animated typography? Current limitations include reduced performance for non-Latin scripts and susceptibility to stylised text.
*   **Question 3:** What algorithmic improvements are needed for the alias resolution module to effectively merge indirect references and heavily OCR-distorted name variants? The current similarity-based approach frequently fails on cases like "Brother Rourke" vs. "Mickey Rourke".

## Limitations
*   Fine-tuning details, architecture, and training data for the NER model are unspecified.
*   Exact OCR engine parameters, preprocessing steps, and confidence thresholds are not disclosed.
*   External validation of the pipeline's auditability in real journalistic workflows is absent; the design principle is self-described with weak corpus linkage.

## Confidence
*   **Auditability via Modularity (Mechanism 1):** **Medium**. Pipeline structure is clear, but real-world validation of its auditability is lacking.
*   **YOLOv12 Robustness (Mechanism 2):** **Medium**. High mAP is self-reported; independent replication on diverse, unseen graphics is needed.
*   **Accuracy–Auditability Trade-off (Mechanism 3):** **High**. Direct quantitative comparison with Gemini is provided, though generalizability to other generative models is uncertain.
