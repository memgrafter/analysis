# Chameleons do not Forget: Prompt-Based Online Continual Learning for Next Activity Prediction

## Quick Facts
- **arXiv ID:** 2604.00653
- **Source URL:** https://arxiv.org/abs/2604.00653
- **Reference count:** 29
- **Primary result:** Proposes CNAPwP, a prompt-based online continual learning method that mitigates catastrophic forgetting in next activity prediction under recurrent concept drifts, achieving state-of-the-art average accuracy on multiple benchmarks (e.g., 0.813±0.004 on RandomTasks).

## Executive Summary
This paper introduces CNAPwP, a method for online next activity prediction that combats catastrophic forgetting in the face of recurrent concept drifts. It adapts the DualPrompt framework to the process mining domain by separating task-invariant (G-Prompt) and task-specific (E-Prompt) knowledge within a multi-head self-attention model. The approach incorporates sliding window handling, concept drift detection with task recognition via prefix trees, and bucketing by prefix length to manage variable sequence lengths. Evaluated on synthetic and real-world event logs, CNAPwP achieves state-of-the-art average accuracy and superior retention on recurring tasks, with processing times per event in the low milliseconds range, making it suitable for near-real-time business processes.

## Method Summary
CNAPwP processes a stream of events, maintaining a sliding window of the most recent events. Upon window saturation, it partitions the window data into buckets based on prefix length and updates a global G-Prompt, bucket-specific E-Prompts, a task-specific E-Prompt, and the model weights via cross-entropy loss. When an external concept drift signal occurs, a buffer of events is stored in a prefix tree and compared against stored task trees using a dissimilarity ratio; if similarity exceeds a threshold, the corresponding task’s E-Prompt is reused, otherwise a new task and E-Prompt are initialized. For prediction, the G-Prompt and the combined (task-specific + bucket-specific) E-Prompt are attached to the multi-head self-attention model via prefix tuning to forecast the next activity.

## Key Results
- Achieves state-of-the-art average accuracy on RandomTasks (0.813±0.004) and RecurrentTasks (0.789±0.002), and competitive results on ImbalancedTasks and real-world BPIC datasets.
- Demonstrates superior task-specific forgetting mitigation, showing minimal accuracy drops when previously learned tasks recur.
- Processing time per event ranges from 2.98 to 25.04 ms, appropriate for online business process scenarios.

## Why This Works (Mechanism)

### Mechanism 1
CNAPwP reduces catastrophic forgetting by disentangling task-invariant and task-specific knowledge through separate prompts (G-Prompt and E-Prompt) attached to multi-head self-attention layers. The shared G-Prompt captures general patterns common across tasks, while each task has its own E-Prompt that encodes unique sequential features. During training, both prompts and model weights are updated; during inference, the correct E-Prompt is selected via task recognition and combined with the G-Prompt.
- **Core assumption:** Task-invariant and task-specific features can be effectively separated and encoded in prompts without interference, and the MHSA architecture can leverage both simultaneously.
- **Break condition:** If tasks share few invariant features or task-specific features overlap significantly, prompts may fail to separate knowledge, leading to interference. Incorrect task recognition also causes mismatched feature application.

### Mechanism 2
CNAPwP recognizes recurring tasks by comparing prefix trees of new data with stored task representations, enabling reuse of previously learned E-Prompts and avoiding unnecessary initialization. After a detected concept drift, a buffer of ρ events is stored in a prefix tree. This tree is compared against stored trees of known tasks using a dissimilarity ratio. If the similarity exceeds threshold ε, the corresponding stored task’s E-Prompt is reused; otherwise a new task (and E-Prompt) is created.
- **Core assumption:** Prefix trees adequately capture the sequential structure of a task, and the dissimilarity ratio reliably measures task similarity.
- **Break condition:** Insufficient buffer size ρ yields an incomplete prefix tree. Poorly set threshold ε causes false matches (reusing wrong E-Prompt) or false new tasks (unnecessary initialization).

### Mechanism 3
CNAPwP handles variable prefix lengths by bucketing them into discrete ranges, assigning each bucket a dedicated E-Prompt that specializes to length-dependent patterns. The sliding window data is partitioned into buckets based on prefix length θ. Each bucket updates only its own bucket-specific E-Prompt during training, alongside the global G-Prompt and task-specific E-Prompt. At inference, the bucket is selected by the prefix length, and its E-Prompt is applied.
- **Core assumption:** Prefix length influences relevant sequential patterns; grouping similar lengths together allows prompts to specialize and reduces interference between length groups.
- **Break condition:** If bucket boundaries poorly align with natural length distributions, prompts may capture noise. Highly imbalanced bucket sizes cause overfitting to small buckets or underfitting to large ones.

## Architecture Onboarding
Preprocessing -> Window Handling -> Prompt Detection & Update -> Concept Drift Detection -> Prediction Model
- **Component map:**
  Preprocessing (filter attributes, order events, generate/encode prefixes) -> Window Handling (FIFO buffer of size γ) -> Prompt Detection (bucketing, update G-Prompt, bucket-specific E-Prompts, task-specific E-Prompt, model weights) -> Concept Drift Detection (store buffer, build prefix tree, compare, set E-Prompt) -> Prediction Model (MHSA with attached prompts)
- **Critical path:** New event arrives -> Preprocessing extracts/encodes prefix -> Window adds event; if full (γ), triggers update cycle -> Prompt Detection: bucketed training updates -> Concept Drift Detection: if drift signal, task recognition sets current E-Prompt -> Prediction: combine prompts, run MHSA, output activity.
- **Design tradeoffs:** Window size γ: larger = stable updates but higher latency/memory; smaller = faster adaptation but overfit risk. Bucket granularity: more buckets = finer specialization but more parameters/overfit; fewer = less overhead but may mix lengths. Prompting function: prefix tuning preserves sequence length efficiently. Memory vs. reuse: storing many task trees enables reuse but costs memory; threshold ε balances false reuse vs. new tasks.
- **Failure signatures:** Accuracy drop after known task recurrence → task recognition failure or prompt mismatch. High event-to-event variance → unstable bucketing/window updates. Persistent low accuracy on new task → buffer size ρ too small. Drift not triggering → missed drifts if using external detector.
- **First 3 experiments:**
  1. Preprocessing and Window Integrity: Run on small synthetic log; verify prefix generation, window updates every γ events, no data loss.
  2. Prompt Separation: Train on stream with two distinct tasks; inspect gradient norms or parameter differences between G-Prompt and E-Prompt across tasks (ablation: disable one prompt, observe performance drop).
  3. Task Recognition: Simulate a known concept drift; after ρ events, check new prefix tree build, comparison yields correct reuse or new task initialization (print dissimilarity ratios and chosen E-Prompt index).

## Open Questions the Paper Calls Out
- **Open Question 1:** How can a robust, unified concept drift detection mechanism be integrated into CNAPwP to handle both sudden and gradual drifts in online next activity prediction?
  - **Basis in paper:** The conclusion states: "In the future, it is crucial to explore areas such as integrating a robust concept drift detection mechanism, possibly for both sudden and gradual drifts."
  - **Why unresolved:** The current implementation assumes externally provided drift indices and does not include its own detection module, limiting autonomous operation in real-world streams with unknown drift patterns.
  - **What evidence would resolve it:** Empirical comparison of different drift detectors (e.g., ADWIN, DDM, EDDM) within CNAPwP's framework, measuring accuracy, detection delay, and false positive rates on synthetic and real streams with mixed drift types.

- **Open Question 2:** What alternative methods for task similarity comparison can provide sharper, faster, and more efficient task recognition than the current prefix tree dissimilarity ratio?
  - **Basis in paper:** The conclusion mentions: "exploring alternative methods for task comparison might offer sharper, faster, and more efficient ways of performing task similarity detection."
  - **Why unresolved:** The current prefix tree-based comparison depends on a manually tuned threshold ε and may not scale well with high-dimensional or noisy event sequences, potentially missing nuanced task relationships.
  - **What evidence would resolve it:** Testing alternative representations (e.g., embeddings from pre-trained models, behavioral fingerprints, or set-based similarity measures) on the same datasets, evaluating accuracy, computation time, and sensitivity to parameter tuning.

- **Open Question 3:** What is the precise impact of event log complexity (e.g., variance in trace lengths, number of activities) on the computational overhead of the prompting mechanism, and how can lightweight prompting strategies mitigate this?
  - **Basis in paper:** The conclusion hypothesizes: "the complexity of the event log directly impacts the processing time of the prompting mechanism... Future research should therefore investigate the specific relationship between log complexity and prompt overhead, with the aim of developing lightweight prompting strategies."
  - **Why unresolved:** The paper observes higher latency on complex logs (e.g., Recurrent BPIC2015) but does not quantify which complexity metrics (e.g., trace length variance, branching factor) most affect the bucketing and prompt attachment overhead.
  - **What evidence would resolve it:** Controlled experiments varying synthetic log complexity metrics, profiling runtime components (bucketing, prompt selection, MHSA operations), and developing adaptive bucketing or shared prompt schemes to reduce fragmentation.

## Limitations
- **Unknown architecture specifics:** Exact MHSA layers, attention heads, embedding/prompt vector sizes, and prompt attachment mechanism are not detailed in the paper and must be extracted from source code.
- **Underspecified components:** Bucket numeric thresholds, precise dissimilarity ratio formula for prefix trees, and integration specifics for drift detection are omitted.
- **Core assumption risk:** Separation of task-invariant and task-specific knowledge relies on minimal overlap; in domains with high feature sharing, this may degrade performance.

## Confidence
- **Catastrophic forgetting reduction via prompt separation:** Medium confidence. Mechanism plausible and partially evidenced, but assumption of cleanly separable features may not hold universally.
- **Recurring task recognition and prompt reuse:** Medium confidence. Heavily depends on correctly set buffer size ρ and threshold ε; no robustness analysis provided.
- **Handling variable prefix lengths via bucketing:** Medium confidence. Bucket granularity is a design trade-off not fully explored; poor boundaries could harm performance.
