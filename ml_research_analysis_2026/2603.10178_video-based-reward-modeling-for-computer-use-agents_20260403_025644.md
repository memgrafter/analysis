# Video-Based Reward Modeling for Computer-Use Agents

## Quick Facts
- **arXiv ID:** 2603.10178
- **Source URL:** https://arxiv.org/abs/2603.10178
- **Reference count:** 40
- **Primary result:** An 8B parameter video-execution reward model (ExeVRM) achieves 84.7% accuracy on a new benchmark, outperforming proprietary multimodal models.

## Executive Summary
This paper presents a paradigm for evaluating computer-use agents (CUAs) by analyzing execution videos rather than agent internals. The core contributions are a large-scale dataset (ExeVR-53k) of video-task-reward triplets with hard negatives, a spatiotemporal token pruning technique (STP+TTP) to handle long, high-resolution videos efficiently, and a fine-tuned model (ExeVRM) that predicts task success from user instructions and keyframe sequences. Evaluated on ExeVR-Bench, ExeVRM surpasses leading proprietary and open-source models in accuracy, recall, and temporal error localization, demonstrating the viability of a scalable, model-agnostic reward modeling approach for CUAs.

## Method Summary
The method involves three main steps. First, the ExeVR-53k dataset is constructed by converting agent trajectories into 1 FPS keyframe videos and generating adversarial negative samples via instruction translation with a VL model, ensuring semantic inconsistency while maintaining visual plausibility. Second, a spatiotemporal pruning pipeline (STP+TTP) is applied to the video tokens: STP removes spatially redundant patches by analyzing UI-connected homogeneity, and TTP removes temporally redundant tokens via cosine similarity to a reference frame, with a joint mask preserving tokens retained by both. Third, a Qwen3-VL model is fine-tuned on these pruned token sequences paired with instructions, training only the LLM parameters to perform binary reward prediction.

## Key Results
- ExeVRM (8B) achieves **84.7% accuracy** and **87.7% recall** on ExeVR-Bench, outperforming GPT-5.2, Gemini-3 Pro, and Seed-2.0 Pro.
- It provides superior **temporal attribution**, with higher tIoU for localizing the first error step compared to baselines.
- The **pruning technique (STP+TTP)** enables efficient processing of 720p, 100-frame videos, reducing memory while preserving performance.

## Why This Works (Mechanism)
The approach works because it decouples evaluation from agent-specific implementations, using only observable execution outcomes. Adversarial negative synthesis enforces learning of fine-grained visual-task alignment rather than superficial correlations. Spatiotemporal pruning aggressively removes visually redundant information (static UI elements, near-identical frames) while retaining dynamic, task-relevant cues, making long-horizon video processing tractable. The model thus learns to map compact, distilled visual evidence to success/failure judgments, generalizing across operating systems and agent architectures.

## Foundational Learning
- **Reward Modeling for Agents:** Learn to predict scalar outcomes from execution traces. *Why needed:* Enables automated, scalable evaluation of agent performance without manual testing. *Quick check:* Can a model distinguish successful vs. failed trajectories from action logs or videos?
- **Adversarial Data Synthesis:** Generate hard negatives by modifying inputs to be plausible yet incorrect. *Why needed:* Overcomes scarcity of failure examples and prevents shortcut learning. *Quick check:* Are synthetic negatives misclassified by simple heuristics (e.g., frame difference) but correctly by the target model?
- **Spatiotemporal Token Pruning:** Remove redundant visual tokens across space and time. *Why needed:* Reduces computational cost for long, high-resolution videos within fixed context windows. *Quick check:* Does pruning reduce token count by >50% while preserving key objects/actions in sample frames?
- **Video-Based Agent Evaluation:** Use raw execution videos as evaluator input. *Why needed:* Provides a universal, model-agnostic signal independent of agent internals. *Quick check:* Can a human judge success from the same keyframes without seeing the agent's thoughts or actions?
- **Keyframe Extraction:** Sample video at low frame rate (e.g., 1 FPS). *Why needed:* Compresses temporal dimension while maintaining major state changes. *Quick check:* Does 1 FPS capture critical UI transitions (e.g., menu openings, text entries) in sample tasks?
- **Model-Agnostic Assessment:** Design evaluator without relying on agent-specific traces. *Why needed:* Allows comparison across diverse agent implementations. *Quick check:* Does the reward model work on videos from agents not seen during training?

## Architecture Onboarding
**Component Map:**  
ExeVR-53k Dataset -> STP+TTP Pruning -> Qwen3-VL (frozen encoder + tuned LLM) -> Binary Reward Prediction

**Critical Path:**  
1. **Data Preparation:** Source trajectories (AgentNet, ScaleCUA, OSWorld) are converted to keyframe videos. Adversarial instruction translation generates negative samples with mismatch justifications.  
2. **Pruning Integration:** STP processes each frame's patch tokens via UI-connected graph analysis; TTP compares temporal similarity across frames; joint mask is applied before projection to LLM.  
3. **Model Training:** Vision encoder and projector are frozen; LLM is fine-tuned with cross-entropy loss on pruned token sequences + instruction.  
4. **Evaluation:** ExeVR-Bench videos (720p, 1 FPS, ≤100 frames) are processed; outputs are binary labels and first-error timestamps for tIoU.

**Design Tradeoffs:**  
- **Pruning Aggressiveness vs. Detail Loss:** Higher thresholds (τ_s, τ_t) save more memory but risk discarding subtle cues (e.g., small text edits).  
- **Synthetic Negative Realism vs. Diversity:** Adversarial translation creates hard, instruction-focused mismatches but may under-represent real failure modes (crashes, execution errors).  
- **Resolution vs. Cost:** 720p improves performance but increases tokens; pruning partially mitigates but does not eliminate quadratic scaling.

**Failure Signatures:**  
- **Over-pruning:** Recall drops significantly on tasks requiring fine-grained visual changes (e.g., text editing). Diagnose by visualizing retained masks.  
- **Temporal盲区:** Missing rapid UI transitions (e.g., pop-up dialogs) due to high τ_t=0.9999; check token similarity histories across consecutive frames.  
- **Generalization Gap:** High accuracy on synthetic negatives but low on naturally failed trajectories from unseen agents; indicates negative distribution shift.

**First Three Experiments:**  
1. **Pruning sanity check:** Run STP+TTP on a fixed set of ExeVR-Bench videos; measure token count reduction and manually inspect masks for critical regions (cursor, text fields).  
2. **Threshold sensitivity:** Train small models with varying τ_s (0.2–0.4) and τ_t (0.999–0.99995); plot accuracy vs. token reduction curve to identify knee point.  
3. **Negative type ablation:** Train on ExeVR-53k with only synthetic negatives vs. only real failures (if available subset) vs. combined; evaluate on a held-out set of real failure videos to measure synthetic coverage.

## Open Questions the Paper Calls Out
1. How can reward models distinguish productive exploration (trial-and-error) from genuine failure in long-horizon trajectories?
2. Can spatiotemporal token pruning be made more adaptive to preserve task-critical, visually subtle UI elements without sacrificing efficiency?
3. To what extent do synthetic negatives cover the true distribution of real-world CUA failures, and could their biases limit generalization?
4. Does the paradigm scale to extremely long horizons (hundreds of steps) or high-fps streams, or does it necessitate a paradigm shift beyond pruning?
5. How does video-only modeling compare against, or combine with, agent-specific internal state-based reward models for complex workflows?

## Limitations
- **Negative generation opacity:** Adversarial instruction translation prompt and GPT-5.2 settings are undocumented, hindering replication of negative sample quality.
- **Implementation gaps:** Critical details of STP/TTP integration with Qwen3-VL and modified LLaMA-Factory configuration (e.g., DeepSpeed settings) are unspecified, risking divergence.
- **Dataset split uncertainty:** ExeVR-53k train/test splits and ExeVR-Bench task composition are not publicly itemized; contamination from source trajectories cannot be ruled out.
- **Proprietary baseline comparison:** Tests against closed models lack controlled conditions (prompt format, timeouts), making superiority claims less verifiable.

## Confidence
- **Dataset scale & annotation:** Medium – counts are stated, but validation protocol is opaque.
- **Pruning efficiency & design:** Medium – algorithms described, but integration specifics and threshold sensitivity under-explored.
- **Performance on ExeVR-Bench:** Low – results depend on unreproducible baselines and unknown splits.
- **Temporal error localization (tIoU):** High – metric well-defined and consistently reported.

## Next Checks
1. **Audit negative sample quality:** Manually evaluate a random subset of ExeVR-53k adversarial pairs; measure human agreement with provided justifications.
2. **Verify pruning token reduction:** Run STP+TTP on fixed 720p videos; quantify token count reduction and visualize masks for retention of fine details.
3. **Confirm dataset split integrity:** Cross-reference ExeVR-Bench task identities against source trajectories (AgentNet, ScaleCUA, OSWorld) to ensure no training overlap.
