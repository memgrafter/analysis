# Tree-Preconditioned Differentiable Optimization and Axioms as Layers

## Quick Facts
- **ArXiv ID**: 2601.06036  
- **Source URL**: https://arxiv.org/abs/2601.06036  
- **Reference count**: 23  
- **Primary result**: Tree-preconditioned conjugate gradient solver scales projection onto RUM polytope to n=20 alternatives with 100× fewer IPM iterations and machine‑precision feasibility.

## Executive Summary
This paper tackles the NP‑hard problem of projecting empirical choice data onto the Random Utility Model (RUM) polytope, which has exponentially many constraints. The core innovation is an isomorphism between RUM consistency and flow conservation on the Boolean lattice, enabling a Tree‑Preconditioned Conjugate Gradient (CG) solver. The spanning tree of the constraint graph “whitens” the ill‑conditioned Hessian from the Interior Point Method (IPM) barrier, reducing IPM iterations by two orders of magnitude and achieving machine‑precision feasibility (ϵ≈1e‑16). The approach scales to n=20 alternatives (N>1e7 constraints) and exhibits superlinear convergence even under extreme condition numbers (κ≈1e8). Additionally, the differentiable “Axioms‑as‑Layers” paradigm integrates structural constraints as neural network layers, eliminating structural overfitting and yielding superior generalization in sparse data regimes compared to soft‑penalty baselines.

## Method Summary
The method reformulates the RUM projection as flow conservation on a Boolean lattice, revealing a sparse combinatorial structure. An interior point method solves the convex problem, but its Newton system is ill‑conditioned due to the barrier term. A spanning tree preconditioner approximates the Hessian, transforming it into a well‑conditioned (whitened) form for efficient conjugate gradient solves. The resulting tree‑preconditioned CG dramatically accelerates IPM convergence. For end‑to‑end learning, the Axioms‑as‑Layers module embeds the projection (or its gradient) as a differentiable layer, ensuring feasibility while allowing gradient‑based optimization.

## Key Results
- Scales to n=20 alternatives (N>1e7 constraints) with machine‑precision feasibility (ϵ≈1e‑16) and 100× reduction in IPM iterations.  
- Achieves superlinear convergence under extreme condition numbers (κ≈1e8).  
- Differentiable Axioms‑as‑Layers eliminates structural overfitting and outperforms soft‑penalty baselines on sparse choice data.

## Why This Works (Mechanism)
The isomorphism maps each RUM inequality to a flow conservation constraint on a Boolean lattice graph, reducing the effective number of constraints. The spanning tree of this graph provides a low‑rank approximation of the Hessian that diagonalizes its spectrum in the preconditioned space, making the conjugate gradient solver robust to ill‑conditioning. This “whitening” effect ensures that CG converges in few iterations even when the original Hessian is nearly singular. The Axioms‑as‑Layers paradigm then leverages this efficient projection as a differentiable building block, guaranteeing that all outputs lie exactly on the RUM polytope during training, which prevents the model from fitting spurious correlations in sparse datasets.

## Foundational Learning
- **Random Utility Model (RUM) polytope**: The set of choice probability vectors consistent with rational utility maximization. *Why needed*: The projection onto this polytope is the core computational task. *Quick check*: For n=3, verify that the polytope is defined by p_i>0, Σp_i=1, and no cycles in pairwise comparisons (e.g., p₁>p₂, p₂>p₃ implies p₁>p₃).  
- **Flow conservation on Boolean lattice**: An equivalence between RUM constraints and network flow constraints. *Why needed*: It transforms an exponentially constrained problem into one with a sparse, structured representation. *Quick check*: For n=4, enumerate minimal cut constraints and confirm they correspond to the RUM inequalities (e.g., p₁+p₂ ≥ p₃).  
- **Spanning tree preconditioner**: Uses a tree to approximate the Hessian matrix, making it better conditioned for CG. *Why needed*: The IPM Hessian becomes increasingly ill‑conditioned as the barrier parameter decreases; the preconditioner accelerates CG convergence. *Quick check*: For a simple chain graph, compute the tree preconditioner and show the transformed Hessian becomes diagonal (or identity).  
- **Conjugate Gradient (CG) method**: Iterative solver for symmetric positive‑definite linear systems. *Why needed*: It solves the Newton system inside IPM efficiently when combined with a good preconditioner. *Quick check*: Apply CG to a known SPD matrix (e.g., 5×5 identity) and verify exact convergence in ≤5 steps.  
- **Axioms‑as‑Layers**: A differentiable module that encodes structural constraints (e.g., RUM) as neural network layers. *Why needed*: Enables end‑to‑end learning while guaranteeing feasibility, avoiding overfitting in sparse regimes. *Quick check*: Implement a layer that projects onto the simplex (sum=1, nonnegative) and verify that forward passes produce feasible vectors and gradients are non‑zero.

## Architecture Onboarding
**Component Map**  
RUM polytope -> Flow conservation mapping -> Spanning tree construction -> Tree‑preconditioned CG solver -> Axioms‑as‑Layers module

**Critical Path**  
1. Input empirical choice frequencies.  
2. Formulate projection as convex optimization (IPM).  
3. Each IPM iteration:  
   a. Build constraint graph from current variables.  
   b. Compute a spanning tree (e.g., via BFS).  
   c. Assemble tree‑preconditioner.  
   d. Solve Newton system with preconditioned CG to get search direction.  
   e. Update variables via line search.  
4. Terminate when feasibility tolerance (ϵ) and optimality conditions met.  
5. For differentiable learning, wrap the projection (or its implicit gradient) as an Axioms‑as‑Layer within a larger model.

**Design Tradeoffs**  
- *Spanning tree choice*: Minimum spanning tree may improve conditioning but adds overhead; any spanning tree works theoretically. Tradeoff: robustness vs. per‑iteration cost.  
- *CG tolerance*: Tighter tolerance reduces IPM iterations but increases CG cost; too loose may stall outer convergence. Tradeoff: overall runtime vs. iteration count.  
- *Differentiation strategy*: Implicit differentiation yields exact gradients but requires solving linear systems; finite differences are simpler but noisy. Tradeoff: gradient accuracy vs. implementation simplicity.

**Failure Signatures**  
- CG does not converge within expected iterations: indicates poor preconditioner (e.g., degenerate tree) or ill‑conditioned barrier.  
- Final feasibility error ≫ 1e‑16: suggests insufficient IPM iterations, numerical instability, or incorrect barrier parameter update.  
- Generalization gap on sparse data: could be due to over‑regularization, incorrect gradient flow through the Axioms‑as‑Layer, or data distribution shift.

**First Experiments**  
1. **Synthetic scalability**: Generate random empirical choice data for n=10,15,20; run tree‑preconditioned IPM and standard IPM; compare iteration counts, runtime, and feasibility error.  
2. **Isomorphism verification**: For n≤8, enumerate all extreme points of the RUM polytope and the flow conservation polytope; check bijection and constraint preservation.  
3. **Sparse data generalization**: Apply Axioms‑as‑Layers to a public sparse choice dataset (e.g., Netflix movie choices); evaluate test log‑likelihood against soft‑penalty RUM baseline with statistical significance testing.
