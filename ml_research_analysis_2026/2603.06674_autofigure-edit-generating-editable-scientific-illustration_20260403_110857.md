# AutoFigure-Edit: Generating Editable Scientific Illustration

## Quick Facts
- **arXiv ID:** 2603.06674  
- **Source URL:** https://arxiv.org/abs/2603.06674  
- **Reference count:** 12  
- **Primary result:** Solves editable, style-controllable scientific illustration generation; achieves 83.0% Win-Rate on FigureBench with reference conditioning.

## Executive Summary
AutoFigure-Edit generates fully editable scientific illustrations (in SVG format) from long-form text and optional reference style images. It decomposes the problem into five sequential stages: style-conditioned raster synthesis, segmentation to expose structure, asset extraction, SVG template generation with refinement, and final asset injection. This pipeline balances semantic fidelity to the input text, stylistic adaptation to the reference, and structural editability. Evaluations on FigureBench show a Win-Rate of 83.0% (with reference) versus 53.0% for prior work. A user study with 217 participants rated semantic correctness, completeness, and style consistency around 4.0 on 5-point scales, with 48% deeming semantic correctness perfect and 126 of 262 finding figures publication-usable.

## Method Summary
The system processes a scientific text description and an optional reference image. Stage I uses a style-conditioned text-to-image model (Gemini-3-Pro-Image-Preview) to produce a raster draft that aligns with both the text semantics and reference style. Stage II applies instance segmentation (SAM 3) to this raster, generating an indexed structural mask where each component is filled uniformly and tagged with a unique identifier (e.g., `<AF>k`). Stage III extracts transparent assets for each component via background removal. Stage IV prompts a vision-language model (Gemini-3.1-Pro-Preview) to generate SVG code from the structural mask, followed by iterative refinement against the raster to ensure positional and stylistic consistency. Stage V programmatically injects the extracted assets into the SVG template, replacing placeholder tokens. The final SVG preserves vector paths and groups, enabling component-level edits.

## Key Results
- FigureBench Win-Rate of 83.0% with reference conditioning (overall score 7.99), far surpassing AutoFigure’s 53.0%.
- User study (217 participants): semantic correctness 4.04, completeness 4.11, style consistency 4.09 (5-point scales); 48% rated semantic correctness as perfect.
- 126 of 262 users found figures directly publication-usable; SVG Conversion Correctness score 3.60.

## Why This Works (Mechanism)

**1. Decomposition into sequential stages** disentangles layout planning, object identity, and visual rendering. An initial raster draft is segmented into an "indexed structural layout" with uniform fills and identifiers. A VLM then generates an SVG template aligned to this scaffold, which is refined before final asset injection. This modularity allows balancing semantic fidelity, style adaptation, and structural editability, assuming the intermediate raster can be reliably reverse-engineered. Evidence: Pipeline design; ablation supports staged approach. Break condition: Segmentation errors cascade, causing flawed scaffolds requiring manual fix.

**2. Reference-guided style conditioning** uses a user-provided image to condition the raster synthesis stage, transferring high-level stylistic attributes (colors, typography, icon aesthetics) without relying on ambiguous textual prompts. Subsequent stages preserve this style because assets are cropped from the styled raster and SVG refinement is instructed to maintain consistency. Core assumption: a single reference image provides sufficient stylistic signals for complex, long-context synthesis. Evidence: Improved Content Fidelity with references; user preference for conditioned outputs. Break condition: Style conflicts with semantic requirements (e.g., monochrome reference for color-coded figure) lead to unresolved clarity issues.

**3. Explicit structural scaffold as SVG template** enables full editability. The segmentation output yields a simplified rendering with unique tokens (e.g., `<AF>k`). A VLM generates SVG code from this scaffold, which is refined. Asset injection replaces placeholders with extracted transparent assets, preserving original vector paths and groups. This decouples layout from appearance, allowing component-level edits. Core assumption: VLMs can produce syntactically correct SVG aligned to the scaffold, and injection maintains structure. Evidence: SVG Conversion Correctness 3.60; low catastrophic failure rate. Break condition: VLM generates non-manipulable SVG (e.g., all assets merged) or injection misaligns components.

## Foundational Learning
- **Multi-modal Long-Context Understanding:** Needed to process lengthy scientific text (>10k tokens) and extract correct entities and relationships for illustration. Quick check: Can your model reliably identify and sequence all key components from a 2000-word methods description without missing critical steps?
- **Instance Segmentation for Structure Extraction:** Stage II relies on segmenting the raster draft into discrete visual components (e.g., neurons, arrows) even in stylized, non-photographic diagrams. Quick check: Does your segmentation model (e.g., SAM 3) correctly separate all visually distinct elements in a styled schematic, or does it over-merge or under-segment complex icons?
- **Vector Graphics Syntax (SVG) and DOM Manipulation:** Final output must be a native SVG where elements are individually addressable. Understanding SVG groups, paths, and coordinates is essential for template generation and asset injection to ensure true editability. Quick check: If your VLM-generated SVG uses a single group for all icons, can your injection process replace icons individually? What SVG structure guarantees component-level editability?

## Architecture Onboarding
- **Component map:**  
  Inputs (long-form text T, reference style image I_ref) -> Stage I (style-conditioned raster synthesis: Gemini-3-Pro-Image-Preview -> I_raw) -> Stage II (segmentation: SAM 3 -> Imask indexed structural mask, {M_k}, {B_k}) -> Stage III (asset extraction: background removal model -> {A_k} transparent assets) -> Stage IV (SVG template generation & refinement: Gemini-3.1-Pro-Preview, iterations -> S_ref) -> Stage V (asset injection: placeholder replacement -> S* final SVG) -> Output (S* + interactive editor)
- **Critical path:** T & I_ref -> I_raw -> Imask & {A_k} -> S_ref -> S*. Most dependency-critical node: I_raw (errors propagate). Most orchestrational node: VLM in Stage IV (must produce valid SVG).
- **Design tradeoffs:**  
  - Quality vs. Editability: Raster-first approach sacrifices some absolute semantic accuracy to gain robust assets and a scaffold for editability.  
  - Generality vs. Cost: Closed models (Gemini, SAM 3) ensure performance but bring API costs, latency, and reproducibility issues vs. open-source alternatives.  
  - Scope of Editability: Scaffold supports component-level edits (move, recolor, resize) but not deep structural changes (e.g., altering flowchart logic) without regenerating from Stage II.
- **Failure signatures:**  
  - **Segmentation failure:** Missing/merged components in Imask (detect: count of `<AF>` tokens vs. expected entities).  
  - **Asset mismatch:** Extracted asset does not match region in I_raw (detect: CLIP similarity between A_k and cropped region).  
  - **SVG invalidity:** S_ref or S* fails to render or groups poorly (detect: parse SVG code; check for syntax errors).  
  - **Style drift:** Final S* does not match I_ref's style (detect: compute style feature distance via VGG/CLIP).
- **First 3 experiments:**  
  1. **Module Isolation Test:** Feed simple method description and reference icons; manually inspect outputs at each stage (I_raw, Imask, {A_k}, S_ref, S*). Goal: verify each module produces expected, debuggable outputs.  
  2. **Segmentation Stress Test:** Generate I_raw for descriptions with dense, small components. Quantify: % of components correctly segmented and extracted; identify failure modes (over/under-segmentation).  
  3. **Editability Sanity Check:** Take generated S*, manually edit position of one `<g id="AF_3">` group; reload in embedded editor. Goal: confirm change persists and does not break other components.

## Open Questions the Paper Calls Out
1. Can open-weight foundation models achieve comparable performance to closed-source models (e.g., Gemini) in style-conditioned raster synthesis and SVG template refinement without compromising semantic fidelity or style consistency?
2. To what extent do upstream segmentation errors propagate through the pipeline, and which specific component types (e.g., small icons, text labels, connected arrows) are most vulnerable to causing irrecoverable downstream errors in final SVG editability?
3. Does reference-guided style conditioning inadvertently suppress semantic fidelity for complex, abstract scientific concepts when the reference style imposes conflicting visual norms (e.g., minimalistic style vs. inherently dense procedural diagrams)?
4. How does system performance and usability generalize to highly specialized scientific domains (e.g., molecular biology pathways, quantum circuit diagrams) with strict, domain-specific graphical conventions not well-represented in general training data?
5. What are primary failure modes in PNG-to-SVG conversion and can they be predicted from properties of the intermediate raster draft (e.g., texture complexity, contrast, component density)?

## Limitations
- Proprietary model dependence (Gemini, SAM 3) hinders replication, cost/latency analysis, and open-source substitution.
- FigureBench dataset not publicly released, preventing full quantitative benchmarking and independent verification.
- Segmentation errors can cascade through the pipeline, potentially causing irrecoverable output flaws without manual intervention.

## Confidence
- Decomposition into sequential stages: **Medium‑High** (supported by pipeline and ablation; segmentation cascade risk remains).
- Reference‑guided style conditioning: **Medium** (user studies show preference; edge cases of style‑content conflict untested).
- SVG scaffold editability: **Medium‑High** (conversion correctness 3.60; uncommon catastrophic failures; VLM code generation brittleness under‑quantified).
