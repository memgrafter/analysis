# From Documents to Spans: Code-Centric Learning for LLM-based ICD Coding

## Quick Facts
- **arXiv ID:** 2603.15270
- **Source URL:** https://arxiv.org/abs/2603.15270
- **Reference Count:** 30
- **Primary Result:** Code-Centric Learning (CCL) reduces training time by 80%, boosts unseen code F1 from 8.8% to 50.0%, and expands code coverage from <10% to ~100% while matching larger proprietary models on Micro-F1 (59.3% on MDACE) and Macro-F1 (35.2% on MDACE) with Llama3.1-8B.

## Executive Summary
Code-Centric Learning (CCL) reimagines LLM fine-tuning for ICD coding by shifting supervision from entire clinical documents to short evidence spans. It employs a mixed training strategy that combines a small set of document-level samples (with human-annotated evidence) with a large, automatically expanded set of span-level evidence–code pairs. This approach tackles three core challenges: limited code coverage via synthetic data generation for unseen codes, poor interpretability by forcing the model to extract evidence, and high computational cost by reducing context length during training. On benchmark datasets MDACE and ACI-Bench, CCL with Llama3.1-8B achieves competitive accuracy against much larger models and demonstrates a strong human-AI collaboration potential when model-predicted evidence is corrected.

## Method Summary
CCL constructs a large-scale span-level knowledge base (`D`) by integrating three tiers: (1) **Gold pairs** from official ICD resources (Alphabetic Index), (2) **Silver pairs** mined from MIMIC-IV using a two-stage LLM pipeline (extraction then summarization), and (3) **Synthetic pairs** for uncovered codes generated via an LLM conditioned on a nearest neighbor code's evidence. This database provides near-universal code coverage. For training, a small set of document-level samples (e.g., MDACE) is mixed with the abundant span-level pairs from `D` and used for standard autoregressive fine-tuning (LoRA). At inference, the model is prompted to first output evidence spans for the input document, then the corresponding ICD codes, leveraging its span-level knowledge to recognize relevant snippets within the longer context.

## Key Results
- Unseen code F1 surges from 8.8% (SFT) to 50.0% (CCL) on MDACE with Llama3.1-8B.
- Training time drops by 80% (210h to 40h on Llama3.1-8B) due to shorter span contexts.
- Code coverage expands from <10% to ~100% via the three-tier expansion.
- On MDACE, CCL attains Micro-F1 59.3% and Macro-F1 35.2%; on ACI-Bench, 65.8% and 47.1%, matching or exceeding larger proprietary models and outperforming standard SFT.
- Interpretability: Evidence recall reaches 74.0% on MDACE. Human correction of model evidence raises Micro-F1 to 78.0%, indicating collaboration potential.

## Why This Works (Mechanism)

### Mechanism 1: Span-Level Supervision as a Transferable Primitive
- **Claim:** Shifting supervision from full clinical documents to short evidence spans improves LLM performance on document-level ICD coding.
- **Mechanism:** The model first learns to recognize code-specific patterns from concise, noise-reduced evidence spans. These learned mappings are then applied compositionally during document-level inference, where the model scans the long input for fragments matching those patterns and aggregates them.
- **Core assumption:** The definitive support for an ICD code is typically contained within a short, contiguous text span; learning this span-to-code mapping is a simpler, more sample-efficient sub-task that generalizes to the full-document setting.
- **Evidence anchors:** Abstract states "shift supervision from full clinical documents to scalable, short evidence spans"; Section 3.1 claims "span-level learning improves LLMs' ability to perform document-level ICD coding"; neighboring papers exploring evidence-centric approaches support the premise.
- **Break condition:** If critical code-supporting information is inherently non-local or requires cross-sentence reasoning not captured by any single span, span-only training would fail.

### Mechanism 2: Mixed Training Marries Interpretability with Broad Coverage
- **Claim:** A mixed training strategy (combining limited document-level evidence data with abundant span-level pairs) simultaneously achieves interpretability, efficiency, and broad code coverage.
- **Mechanism:** Document-level samples teach the end-to-end skill of evidence aggregation and multi-code prediction under full context. Span-level samples efficiently inject knowledge for a vast array of codes, including those never seen in a full document. Training both jointly under a single autoregressive objective allows the span knowledge to transfer to the document task.
- **Core assumption:** Knowledge from the span-level mapping task is complementary to, not conflicting with, the document-level aggregation task.
- **Evidence anchors:** Abstract mentions mixed training "substantially reduces training cost, improves accuracy on unseen ICD codes and preserves interpretability"; Section 3.2 defines the combined loss; Table 3 (Ablation) shows adding span-level data significantly improves performance over document-level data alone.
- **Break condition:** If span-level data distribution is too divergent from true document evidence, it may teach conflicting patterns, harming document-level performance.

### Mechanism 3: Code-Centric Iterative Expansion for Near-Universal Coverage
- **Claim:** Code-centric data expansion (gold, silver, synthetic pairs) systematically achieves near-full ICD code coverage, enabling learning for unseen codes.
- **Mechanism:** Coverage is built iteratively: 1) **Gold pairs** from official resources provide high-quality seed mappings. 2) **Silver pairs** are mined from public datasets (MIMIC-IV) via LLM extraction and refinement, scaling coverage to codes appearing there. 3) **Synthetic pairs** are generated for remaining codes by prompting an LLM to infer evidence based on a nearest neighbor code's knowledge, bootstrapping the long tail.
- **Core assumption:** LLMs can generate clinically coherent evidence spans for an ICD code when conditioned on knowledge from a similar code, and learning from these synthetic pairs is beneficial despite their non-empirical origin.
- **Evidence anchors:** Abstract describes the three-tier construction; Section 3.3 details the process; Figure 3(d) shows performance gains from each tier; Appendix E human eval shows 77.5% of synthetic pairs are "fully supportive."
- **Break condition:** If synthetic evidence is clinically implausible or systematically misaligned with true coding logic, it could harm performance on real unseen codes.

## Foundational Learning
- **Concept: Multi-Label Long-Tail Classification**
  - **Why needed here:** ICD coding involves predicting from thousands of possible codes with a Zipfian distribution (many rare codes). The model must handle a huge output space and avoid bias toward frequent codes.
  - **Quick check:** Why does a simple "predict top-k most frequent codes" strategy fail catastrophically for real-world deployment?
- **Concept: Evidence-Centered Reasoning (vs. End-to-End Association)**
  - **Why needed here:** CCL decomposes coding into "find evidence" then "assign code." The model must learn a mapping from text span semantics to code semantics, not just document-level statistics.
  - **Quick check:** How might training on `(evidence_span, code)` pairs differ in what the model learns compared to training on `(full_document, code_set)` pairs?
- **Concept: Knowledge Bootstrapping & Data Synthesis**
  - **Why needed here:** The code space is huge (~70k ICD-10-CM codes), but human-annotated data is tiny. The method must generate training signals for the vast majority of codes.
  - **Quick check:** What are the key risks of using LLM-generated "synthetic" training data for a high-stakes domain like medicine?

## Architecture Onboarding
- **Component map:**
  1. Raw Data Ingestion -> 2. Silver Pair Miner (LLM pipeline) -> 3. Synthetic Pair Generator (LLM with nearest neighbor) -> 4. Dataset Mixer (combines ~200 docs + ~150k spans) -> 5. Mixed-Training SFT Loop (LoRA) -> 6. Inference Engine (document-in, evidence-then-codes out)
- **Critical path:**
  1. Build the span-level knowledge base (Steps 2 & 3). 2. Verify span data quality (e.g., human eval on synthetic samples). 3. Execute mixed SFT. 4. Evaluate on MDACE/ACI-Bench (Micro/Macro-F1, Evidence Recall).
- **Design tradeoffs:**
  - Synthetic Data Volume vs. Quality: More pairs increase coverage but risk noise.
  - Span Granularity: "Verbatim minimal" spans balance context and noise; parameter is key.
  - Backbone Model Choice: Larger models may better utilize noisy data, but CCL gives small models an efficiency edge.
- **Failure signatures:**
  - Low Evidence Recall (<50%): Span training failed to transfer to document retrieval.
  - Poor Unseen Code Performance: Code expansion (Silver/Synthetic) is ineffective.
  - Training Instability / Overfitting on Spans: Model memorizes pairs but fails at aggregation.
  - High Precision, Low Recall: Issues with decoding strategy or span data bias.
- **First 3 experiments:**
  1. **Span-Only Training Sanity Check:** Fine-tune only on span-level pairs; evaluate on a held-out span→code test set.
  2. **Ablation of Data Tiers:** Systematically remove Gold, then Silver, then Synthetic pairs in mixed training; measure drop in overall and unseen-code F1.
  3. **Human-in-the-Loop Simulation:** On test samples, manually correct predicted evidence spans and regenerate codes; compute F1 delta to quantify collaboration potential.

## Open Questions the Paper Calls Out
1. How exactly does span-level supervision transfer gains to document-level evidence extraction? What are the learned representations?
2. To what extent do synthetic evidence–code pairs capture the complex, conditional coding logic present in official guidelines (e.g., "code first," "use additional code")?
3. How does CCL's performance scale with model size and pretraining data diversity, and does the efficiency advantage hold for very large models (>70B parameters)?
4. Can the span-level knowledge base be dynamically updated or refined during training (e.g., via self-training) to improve evidence quality and coverage?
5. How does CCL handle rare, ambiguous, or contested codings where evidence spans may be subtle, conflicting, or require integration across distant sections?
6. What is the optimal mixture ratio between document-level and span-level data during mixed training, and does this ratio depend on model size, dataset, or code frequency?
7. Can CCL's evidence extraction be improved by incorporating uncertainty estimates to request human intervention selectively, and what is the theoretical upper bound on human-AI collaboration gains?

## Limitations
- Synthetic pair generation relies on GPT-5.1 (proprietary); substituting models may degrade unseen-code performance.
- Missing implementation specifics: exact mixing ratio of document- vs. span-level samples and the nearest-neighbor retrieval metric for code expansion.
- Potential distribution shift: silver/synthetic spans may not fully capture evidence in full clinical notes, risking transfer failure.

## Confidence
- **Span Supervision Efficacy:** Medium (ablation supports, but break condition for non-local reasoning untested).
- **Mixed Training Strategy:** Medium-High (loss formulation and ablation show benefit, possible objective conflict unquantified).
- **Code-Centric Expansion:** Medium (human eval positive, but clinical plausibility of synthetic data uncertain).
- **Efficiency & Interpretability:** High (direct metrics reported).
