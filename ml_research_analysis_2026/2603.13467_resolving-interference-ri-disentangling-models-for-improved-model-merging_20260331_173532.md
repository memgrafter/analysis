# Resolving Interference (RI): Disentangling Models for Improved Model Merging

## Quick Facts
- arXiv ID: 2603.13467
- Source URL: https://arxiv.org/abs/2603.13467
- Reference count: 22
- Primary result: RI reduces cross-task interference in model merging, boosting SOTA merge accuracy by up to 3.8% on 20 vision tasks and improving OOD generalization by up to 2.3%, with modest compute (~8 min/expert) and robustness to auxiliary data choices.

## Executive Summary
Model merging combines multiple fine-tuned models into a single model, but suffers from cross-task interference where parameter conflicts degrade performance. This paper formalizes interference as representation drift and introduces Resolving Interference (RI), a lightweight adaptation technique that uses only unlabeled auxiliary data to disentangle task vectors before merging. RI optimizes a twin-distillation loss for each expert: preserve its original outputs on its own task while forcing outputs on other tasks to match the pretrained backbone. This makes task vectors functionally orthogonal, reducing interference when merged by any existing method. On extensive vision benchmarks (8, 14, and 20 CLIP tasks), RI improves state-of-the-art merging accuracy by up to 3.8% absolute and boosts out-of-distribution generalization on DomainNet by up to 2.3%. The approach is robust to the choice of auxiliary data and hyperparameters, adding only about 8 minutes of compute per expert.

## Method Summary
RI operates on task vectors, which are the differences between fine-tuned expert backbones and a shared pretrained backbone. For each expert, RI creates a trainable copy of its task vector and adapts it using unlabeled auxiliary data. The adaptation minimizes a twin-distillation loss: L₁ preserves the expert's original outputs under its own task head, while L₂ encourages the adapted backbone's outputs under all other task heads to match those of the frozen pretrained backbone. This pushes each adapted task vector to only affect the feature subspace relevant to its own task, achieving functional orthogonality. After adapting all task vectors, any standard merging algorithm (e.g., TIES, TSV-M) can be applied to combine them into a final merged backbone. The method uses default hyperparameters (α=1, 2500 adaptation steps, Adam optimizer) and requires no task-specific data, making it a practical plug-in for existing merging pipelines.

## Key Results
- RI boosts SOTA merging accuracy by up to 3.8% absolute on 20 vision tasks (e.g., TSV-M: 76.5% → 80.3%).
- Out-of-distribution generalization on DomainNet improves by up to 2.3%.
- Gains are consistent across multiple merging methods, auxiliary data sources, and with modest compute overhead (~8 minutes per expert).

## Why This Works (Mechanism)
### Mechanism 1
- **Claim:** Cross-task interference is quantified as the divergence (ξ) between the merged model's outputs and each constituent expert's outputs on their respective tasks.
- **Mechanism:** The merged model's representation drift is measured by summing a distance metric (e.g., KL-divergence) between the logits of the merged backbone+task-head and the original expert backbone+task-head on the expert's task data. Minimizing this sum (ξ) is a sufficient condition for preserving individual task performance post-merge.
- **Core assumption:** The task-specific head `h_i` is fixed and only the backbone parameters are merged/adjusted. Performance preservation depends on backbone outputs aligning with the fixed head's expectations.
- **Evidence anchors:**
  - [abstract] "We formally define the notion of Cross-Task Interference as the drift in the representation of the merged model relative to its constituent models."
  - [section 4] Equation (1) defines ξ and states "ξ=0 is a sufficient condition to guaranteeing that a merged model performs equally well..."
  - [corpus] The neighboring paper "TIES-Merging" (arxiv:2306.01708) also addresses interference via representation conflict, providing corroborating context.
- **Break condition:** If task heads are also merged or significantly altered, this definition of interference based on fixed heads no longer applies.

### Mechanism 2
- **Claim:** Adapting task vectors with the RI loss on auxiliary data makes them functionally orthogonal to other tasks' heads, reducing interference.
- **Mechanism:** For each expert's task vector τ_i, a copy τ*_i is optimized via gradient descent on unlabeled auxiliary data `x ∈ D_aux` to satisfy: (1) `L1`: match the original expert's outputs under its own head `h_i` (task preservation), and (2) `L2`: match the pretrained backbone's outputs under *all other* task heads `h_j, j≠i` (interference reduction). The combined `L_RI = L1 + α/(N-1) * L2` pushes τ*_i to only affect the subspace relevant to its own task.
- **Core assumption:** Optimizing this objective on broad, diverse auxiliary data approximates the ideal condition (Eq. 2) that would require task data. General visual features in data like ImageNet are sufficiently aligned with downstream tasks to yield useful, disentangled features.
- **Evidence anchors:**
  - [section 5] Equation (3) and (4) define the RI loss. Algorithm 1 details the per-expert adaptation loop.
  - [section 8, Figure 3] Shows that minimizing L_RI on auxiliary data correlates with reduced cross-task interference ξ measured on actual task data.
  - [corpus] "LoRI: Reducing Cross-Task Interference" (arxiv:2504.07448) uses a similar twin-distillation concept for LoRA, suggesting this is an emerging pattern.
- **Break condition:** If auxiliary data is highly domain-specific to one task (e.g., medical images for a medical task), the "interference reduction" loss may over-penalize useful features for other tasks, harming performance.

### Mechanism 3
- **Claim:** After RI adaptation, standard merging methods (e.g., TIES, TSV-M) can be applied to the orthogonalized task vectors, yielding a merged backbone with reduced parameter conflict and higher performance.
- **Mechanism:** RI modifies each τ_i into τ*_i, which is constrained to live in a subspace that primarily activates only its corresponding head. When merged (τ_m = M(τ*_1, ..., τ*_N)), the combined parameter update is less likely to cause destructive interference because the components are more linearly separable in function space. The merging algorithm handles the combination, but the inputs have been "cleaned" of cross-task noise.
- **Core assumption:** Reduced functional interference at the individual task vector level translates to reduced interference in the combined vector. There is a monotonic relationship between the per-expert disentanglement and the final merge quality.
- **Evidence anchors:**
  - [abstract] "RI optimizes a twin-distillation loss... thereby making task vectors functionally orthogonal. The adapted vectors can be merged by any existing method."
  - [section 7, Table 1] Consistently higher accuracy when merging is *preceded* by RI across multiple baselines (TA, TIES, TSV-M, etc.).
  - [corpus] "Sens-Merging" (arxiv:2502.12420) and "Iso-C" (arxiv:2502.04959) also aim to create disjoint subspaces for merging, aligning with the orthogonality goal.
- **Break condition:** If a merging method itself is highly sensitive to magnitude or sign patterns that RI alters (e.g., a method that relies on specific noise patterns being present), RI's modifications could break the method's assumptions.

## Foundational Learning
### Task Vectors
**Why needed here:** The entire method operates on `τ_i = θ_i - θ_0` (the difference between a fine-tuned model and the pretrained backbone). Understanding that model merging is performed on these *difference vectors*, not the absolute parameters, is central.
**Quick check question:** If you add a task vector `τ_i` to the pretrained backbone `θ_0`, what behavior should you expect on task *i* versus other tasks? (Answer: High accuracy on task *i*, potentially degraded on others due to interference.)

### Representation Drift
**Why needed here:** RI's formal interference metric (ξ) measures drift in output representations (logits). This is a more direct measure of functional interference than parameter-based metrics.
**Quick check question:** Why is comparing merged model outputs to expert outputs a better interference metric than, say, comparing parameter L2 distances? (Answer: Parameter differences don't necessarily translate to output differences; outputs are the functional manifestation of interference.)

### Auxiliary Data for Distillation
**Why needed here:** RI uses unlabeled, non-task-specific data to optimize its objectives. The key idea is that a diverse dataset provides a broad coverage of the input space, allowing the optimization to shape features that are generally useful and not task-conflicting.
**Quick check question:** What might happen if you use a very narrow auxiliary dataset (e.g., only images of cars) to adapt a cat-classification expert? (Answer: The "interference reduction" loss might forcibly erase features useful for cat classification that happen to also activate the dog head, harming performance.)

## Architecture Onboarding
**Component map:**
1. **Shared Backbone (`f(·|θ_0)`):** The frozen pretrained model (e.g., CLIP ViT). All experts and the final merged model use this same architecture.
2. **Task Heads (`{h_i}`):** Fixed, task-specific output layers (e.g., linear classifiers on CLIP text embeddings). They are *not* trained during RI.
3. **Expert Models:** `h_i(f(x|θ_0 + τ_i))`. Each has a backbone fine-tuned on its task (θ_i = θ_0 + τ_i).
4. **RI Adaptation Module:** A copy of each expert's backbone with tunable parameters `θ_0 + τ*_i`. This is the only trained component during RI.
5. **Auxiliary Data Pipeline:** `D_aux` feeds into all three branches (frozen pretrained, frozen expert, trainable copy) to compute `L1` and `L2`.
6. **Merging Algorithm (`M`)**: Takes the set of adapted task vectors `{τ*_i}` and produces `τ_m`.

**Critical path:** 1) Load pretrained `θ_0` and expert `τ_i`. 2) For each expert: initialize `τ*_i = τ_i`. 3) For many steps: sample `x ~ D_aux`, compute `L_RI` via forward passes through `f(θ_0)`, `f(θ_0+τ_i)`, and `f(θ_0+τ*_i)` with all heads, update `τ*_i`. 4) Merge all `τ*_i` via chosen method `M` to get `τ_m`. 5) Final model: `θ_m = θ_0 + τ_m`.

**Design tradeoffs:**
- **Auxiliary Data Choice:** High visual diversity (ImageNet) is safe and effective. More task-relevant data (oracle) gives best gains but may be unavailable. Synthetic data (noise, shapes) works but yields smaller gains.
- **Compute vs. Convergence:** Adaptation for 2500 steps is the "elbow point" (Fig 3, left). More steps yield diminishing returns. This is a key efficiency win.
- **α Hyperparameter:** Default `α=1` works well. Increasing α strengthens interference reduction but could harm task preservation if overly aggressive.

**Failure signatures:**
- **Performance drop on individual tasks:** Indicates `L1` (task preservation) was compromised. Check if `α` is too high or if auxiliary data is too dissimilar.
- **No gain over baseline merging:** Could mean auxiliary data is insufficiently diverse, or the chosen merging method is already near-optimal and doesn't benefit from disentanglement.
- **Extreme sensitivity to α:** Suggests the tasks have very different feature dependencies; the balanced `L_RI` objective may not be suitable without per-task tuning (which the paper avoids).

**First 3 experiments:**
1. **Replicate Figure 3 (Left):** Run RI adaptation on one expert for many steps. Plot `L_RI` and `ξ` (cross-task interference) vs. steps. Confirm the steep initial decline and elbow at ~2500 steps.
2. **Table 1 Baseline Replication:** Merge 8/14/20 CLIP tasks with TSV-M (and one other baseline like TIES) with and without RI. Verify the reported absolute gains (~3-4%).
3. **Auxiliary Data Ablation (Figure 4):** For a fixed merge (TSV-M), apply RI using different `D_aux` (Gaussian, ImageNet, task-data oracle). Confirm the trend: more relevant/diverse data → larger gains.

## Open Questions the Paper Calls Out
1. **Tuning without task data:** How can merging hyperparameters be effectively tuned without access to task-specific validation data, given that using the cross-task interference objective on auxiliary data leads to overfitting and poor performance? The paper shows that tuning with the auxiliary-data-based interference objective generally performs worse than using defaults, and calls for more robust objectives.
2. **Multi-task distillation after merging:** How can multi-task distillation be improved to successfully adapt a merged model using only unlabeled auxiliary data? The paper finds that directly adapting a single merged model by applying the cross-task interference objective yields only marginal gains, and labels designing effective multi-task distillation strategies as an open problem.
3. **Generalization to other modalities:** Does RI generalize to non-vision modalities (e.g., NLP, audio) where model merging is applied? The evaluation is limited to vision tasks with CLIP-style architectures; applicability to other domains remains untested.

## Limitations
- The method assumes task heads remain fixed; merging or finetuning heads after RI may break the orthogonality guarantee.
- The necessity for diverse unlabeled data is only validated on standard vision datasets; performance with highly domain-specific or low-diversity auxiliary data is uncertain.
- Several implementation details (e.g., KL divergence direction, optimizer hyperparameters, prompt templates) are unspecified, making exact replication challenging.

## Next Checks
1. **Reproduce Loss Dynamics:** Run RI on a single expert for 2500 steps. Plot `L_RI`, `L₁`, and `L₂` vs. steps. Confirm monotonic decrease and that `L₁` (task preservation) does not rise significantly—validates KL direction and optimization stability.
2. **Validate Head Consistency:** Compute zero-shot accuracy of the frozen pretrained CLIP backbone on a small sample of each task’s test set using the paper’s text embedding templates. Mismatch with expected baselines indicates prompt/template error, invalidating all logit-based losses.
3. **Test α Sensitivity Boundary:** For a 5-task merge (e.g., from the 8-task set), sweep α ∈ {0.1, 0.5, 1.0, 2.0, 5.0}. Measure final accuracy and individual task performance drops. A sharp decline beyond α=2.0 would reveal hidden brittleness in the interference–preservation trade-off.
