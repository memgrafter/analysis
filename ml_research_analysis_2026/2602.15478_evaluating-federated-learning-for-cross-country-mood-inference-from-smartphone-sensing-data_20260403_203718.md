# Evaluating Federated Learning for Cross-Country Mood Inference from Smartphone Sensing Data
## Quick Facts
- **arXiv ID:** 2602.15478
- **Source URL:** https://arxiv.org/abs/2602.15478
- **Reference count:** 40
- **Primary result:** FedFAP achieves macro-AUROC 0.744, outperforming centralized and personalized FL baselines in cross-country mood inference.

## Executive Summary
The paper addresses scalable mood inference from smartphone sensing across geographically and culturally diverse populations while preserving privacy. It introduces FedFAP, a personalized federated learning framework that accommodates heterogeneous sensor availability across regions by separating global shared and client-specific local representations. Evaluated on a six-country dataset, FedFAP achieves AUROC 0.744 under optimal configuration, demonstrating that privacy-preserving, population-aware personalization can effectively handle cross-country data heterogeneity for mood-aware mobile sensing.

Experiments show that a 1D-CNN local encoder combined with FedAvg aggregation yields the best performance, and FedFAP maintains robustness across training regimes. The work highlights the importance of decoupling shared and client-specific representations in non-IID FL settings with feature heterogeneity.

## Method Summary
The study uses the DiversityOne dataset from six countries (Denmark, China, India, Mexico, Paraguay, UK). Smartphone sensors provide 59 handcrafted features aligned to 10-minute windows around mood self-reports (5-point scale collapsed to three classes). Preprocessing is performed independently per country: features with >80% missingness are discarded, and KNN imputation fills remaining gaps, yielding divergent feature subsets across clients.

FedFAP enables federated learning under this heterogeneity. Each client sends a binary feature-availability vector to the server, which computes the intersection to define a shared feature set. Clients then maintain two encoders: a shared encoder (trained via federated aggregation such as FedAvg) that processes only the shared features, and a local encoder (client-only) for the remaining unique features. The shared encoder's output is detached from the computation graph before being concatenated with the local encoder's output and passed through a fusion module and classifier. During local training, gradients update both encoders and the fusion module, but only the shared encoder's weights are uploaded to the server for aggregation. Evaluation uses 5-fold group (user) cross-validation, comparing FedFAP against centralized models (LR, RF, XGB, CNN) and personalized FL baselines (FedPer, pFedMe). Ablations examine encoder architectures and aggregation algorithms.

## Key Results
- FedFAP attains macro-AUROC 0.744 (optimal: 1D-CNN encoder, FedAvg, 10 local epochs, 50 communication rounds).
- It significantly outperforms centralized models trained on the common feature set and personalized FL methods across evaluation regimes.
- The separation of shared and local representations proves effective for cross-country mood inference with heterogeneous sensor data.

## Why This Works (Mechanism)
### Mechanism 1
**Claim:** FedFAP enables collaborative learning across clients with heterogeneous sensor availability by identifying and exploiting a minimal shared feature subset.
**Mechanism:** At initialization, each client sends a binary vector indicating consistently available features. The server computes the intersection of these vectors to define a shared feature set. Only the shared encoder, trained on this common subset, participates in federated aggregation (FedAvg/FedProx/FedAdam). This allows all clients to contribute to and benefit from globally consistent representations despite differing full feature spaces.
**Core assumption:** A non-empty intersection of reliably available features exists across all participating clients, providing a foundation for shared knowledge transfer.
**Evidence anchors:**  
  - [abstract] "accommodates heterogeneous sensing modalities across regions by separating global shared and client-specific local representations."  
  - [section 3.4] "each client transmits a binary feature availability vector... server computes the intersection of features that are reliably available across all participating clients and designates them as shared features."  
  - [corpus] Neighboring work on community-based model personalization does not propose this architectural separation, suggesting FedFAP's mechanism is distinct.
**Break condition:** If the intersection becomes empty or too small (<5-10 features), the shared encoder cannot learn meaningful global patterns, and performance degrades toward isolated local training.

### Mechanism 2
**Claim:** Personalized performance is achieved by allowing each client to maintain a local representation network that processes client-specific features unavailable to other clients, capturing region-specific behavioral patterns.
**Mechanism:** For each client, features not in the shared set are fed exclusively into a local encoder. Gradients from the local encoder are isolated and do not update the shared encoder. The outputs of both encoders are concatenated in a client-specific fusion module before classification. This preserves local feature richness and cultural/contextual nuance lost in common-feature-only approaches.
**Core assumption:** Client-specific features contain predictive signal for mood that is not redundant with the shared feature set, and this signal is consistent within a client's population.
**Evidence anchors:**  
  - [section 3.4] "local representation network... processes the remaining client-specific features... gradients... are not propagated back into the shared representation network."  
  - [section 4.2] The CNN-based local encoder (better modeling structured interactions) outperforms simpler encoders, implying the local features carry meaningful, structured information.  
  - [section 4.4] FedFAP outperforms centralized models trained on the common feature set in 5/6 countries, demonstrating the value of retained local features.
**Break condition:** If a client's local feature set is extremely sparse or non-predictive (e.g., China in Fig 6, where 17 features were dropped), the local encoder contributes little, and performance may suffer relative to a model using only strong common features.

### Mechanism 3
**Claim:** Performance stability under cross-country heterogeneity is improved by strictly separating the federated aggregation scope to only the shared representation, preventing catastrophic interference from client-specific updates.
**Mechanism:** Only the parameters of the shared encoder are transmitted to the server for aggregation. The local encoders and fusion modules are trained and stored exclusively on-client. This architectural "aggregation firewall" ensures that client-specific adaptations (driven by local feature distributions and label shifts) do not directly corrupt the global shared model, and vice versa.
**Core assumption:** The optimal shared representation is relatively stable across clients and can be improved by averaging updates from diverse clients, even when their local objectives differ.
**Evidence anchors:**  
  - [section 3.4.1] "federated aggregation is applied exclusively to the parameters of the shared representation network... local representation network and the fusion module are optimized solely on the client and are never transmitted or aggregated."  
  - [section 4.3] FedAvg (simple averaging of shared parameters) performs best under intensive training (10E-50R), suggesting the shared-space updates are largely compatible and benefit from straightforward aggregation.  
  - [section 4.1] FedFAP outperforms FedPer and pFedMe, which do not have this strict architectural separation (FedPer shares an encoder but has a private head; pFedMe personalizes the entire model via proximal terms), implying that separating feature processing is more effective than parameter-level personalization under feature heterogeneity.
**Break condition:** If the optimal shared representation is highly client-dependent (e.g., due to severe covariate shift in the shared features themselves), averaging shared updates may produce a degenerate global model suboptimal for all clients.

## Architecture Onboarding
### Component Map
Server ↔ (Shared Encoder weights) ↔ Clients.  
Within each client: Input features split into Shared Features (fed into Shared Encoder) and Local Features (fed into Local Encoder). Shared Encoder outputs a representation (detached), Local Encoder outputs a representation; these are concatenated → Fusion Module → Classifier.

### Critical Path
1. **Initialization:** Clients send binary feature-availability masks → Server computes shared feature indices → broadcasts to all clients.  
2. **Federated round start:** Server sends current global shared encoder weights to all clients.  
3. **Local training per client:**  
   a. Split local data into shared-feature matrix X_shared and local-feature matrix X_local.  
   b. Forward pass: z_shared = shared_encoder(X_shared), z_local = local_encoder(X_local).  
   c. Detach z_shared from computation graph.  
   d. Fuse: z_fused = fusion_module(concat(z_shared.detach(), z_local)).  
   e. Compute loss, backpropagate. Gradients flow into local_encoder and fusion_module, and only into shared_encoder from the loss on z_fused (no gradient from local path through z_shared).  
   f. Update all local parameters (shared, local, fusion) via optimizer.  
4. **Update transmission:** Client sends only updated shared_encoder weights to server.  
5. **Aggregation:** Server aggregates received shared weights (e.g., FedAvg: w_global_new = sum((n_k / n_total) * w_shared_k)).  
6. **Repeat** from step 2 for R rounds.

### Design Tradeoffs
- **Shared vs. Local Capacity:** Larger shared encoder improves global knowledge transfer but may overfit to common patterns; larger local encoder better captures client-specificity but reduces relative importance of shared learning.
- **Aggregation Method:** FedAvg is simplest and was best here, but FedProx/FedAdam may help with very different client update scales or partial participation; added complexity vs. marginal gain.
- **Feature Threshold (80% missingness):** Higher threshold yields a larger, more robust shared feature set but discards more potentially useful client-specific modalities; lower threshold risks a very small shared set.

### Failure Signatures
- **Country-specific performance collapse:** e.g., China shows AUROC ~0.52 vs. centralized XGB ~0.62, primarily due to severe feature loss (17 features dropped) during preprocessing.
- **No personalization gain:** If FedFAP's performance matches a global model trained only on shared features, local features may be non-predictive or fusion ineffective.
- **Training divergence:** Increasing loss on clients during federated rounds indicates shared encoder updates becoming incompatible with some clients (client drift); consider FedProx or reducing local epochs.
- **Poor cross-country generalization:** A model trained on 5 countries fails catastrophically on a held-out 6th, indicating the shared representation did not capture truly common patterns (shared feature set too small or uninformative).

## Open Questions the Paper Calls Out
1. **Formal privacy integration** – How can formal privacy guarantees (differential privacy, secure aggregation) be incorporated into FedFAP without significantly degrading mood inference performance? (Basis: Paper acknowledges lack of formal guarantees and suggests future work on secure aggregation and DP.)  
2. **Individual-level personalization** – To what extent does personalizing per participant within countries improve accuracy, and what are the scalability implications? (Basis: Paper uses country-level clients and notes individuals may differ; participant-level personalization is future work.)  
3. **CNN encoder advantage** – What specific architectural mechanisms in FedFAP’s 1D-CNN enable it to outperform feed-forward and attention-based variants under feature heterogeneity, and can this inductive bias be formalized? (Basis: CNN consistently outperforms; hypothesis about exploiting local correlations among related sensors remains speculative.)  
4. **Severe feature sparsity robustness** – How robust is FedFAP when one or more clients experience >80% missingness without discarding client-specific features? Can the shared feature selection be made adaptive? (Basis: China lost 17 features due to threshold; fixed selection may hinder sparse clients.)  
5. **Asynchronous/partial-participation scenarios** – Does FedAvg’s observed advantage over FedProx/FedAdam generalize to asynchronous, partial-participation FL with stragglers typical in mobile deployments? (Basis: Paper assumes full synchronous participation; limitation noted.)

## Limitations
- Unspecified details: threshold for feature "consistency", fusion module architecture, and size/composition of the shared feature set.
- China's significant performance drop with FedFAP (vs. centralized XGB) is not analyzed, suggesting a failure mode under feature sparsity.
- Baseline hyperparameters (e.g., XGB depth) are inadequately described, hindering exact replication.
