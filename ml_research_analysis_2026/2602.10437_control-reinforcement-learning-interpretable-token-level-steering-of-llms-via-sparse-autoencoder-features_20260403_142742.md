# Control Reinforcement Learning: Interpretable Token-Level Steering of LLMs via Sparse Autoencoder Features

## Quick Facts
- arXiv ID: 2602.10437
- Source URL: https://arxiv.org/abs/2602.10437
- Reference count: 40
- Primary result: CRL improves multiple benchmarks (MMLU +3.31, BBQ ambiguous +5.69, GSM8K +1.03, HarmBench +7.66, XSTest +1.27)

## Executive Summary
Existing approaches using sparse autoencoders can identify which features activate in a model but cannot determine which features causally affect outputs when amplified. This paper introduces Control Reinforcement Learning (CRL), which employs a Proximal Policy Optimization (PPO) agent to select individual SAE features for amplification at each token based on residual stream activations. Adaptive Feature Masking encourages the discovery of a diverse set of features while maintaining the interpretability of single-feature interventions. Evaluations on Gemma 2B show consistent gains across MMLU, BBQ, GSM8K, HarmBench, and XSTest. The framework also yields interpretable per-token intervention logs and enables analyses such as branch point tracking, critic trajectory inspection, and layer-wise feature categorization.

## Method Summary
CRL operates by training a reinforcement learning policy to choose which SAE features to amplify during generation. The policy observes the model's residual stream activations at each token and outputs a selection of features. Amplification scales the activation of chosen features, directly influencing subsequent computations. PPO optimizes the policy using rewards derived from task-specific metrics (e.g., accuracy). To prevent the policy from repeatedly selecting the same features, Adaptive Feature Masking temporarily masks features that have been recently used, promoting diversity in feature discovery. This combination allows the system to learn which features are causally beneficial for the target tasks while maintaining the ability to interpret each intervention.

## Key Results
- +3.31 MMLU, +5.69 BBQ ambiguous, +1.03 GSM8K, +7.66 HarmBench, +1.27 XSTest over baseline.
- Produces interpretable per-token intervention logs that support branch point tracking and critic trajectory analysis.
- Layer-wise analysis reveals syntactic features in early layers and semantic features in later layers.

## Why This Works (Mechanism)
The RL policy learns to select features whose amplification leads to higher rewards, effectively identifying causal relationships between features and outputs. PPO's clipped objective ensures stable training even with sparse rewards. Adaptive Feature Masking encourages exploration of the feature space, preventing collapse to a few dominant features and enabling a richer understanding of the model's internal representations. By intervening at the residual stream level, CRL directly modulates the activations that propagate through the network, making the causal effect of each feature explicit and traceable.

## Foundational Learning
**Sparse Autoencoders (SAE)**
- Why needed: Decompose high-dimensional activations into a set of interpretable, typically non-overlapping features.
- Quick check: "Can SAE features be mapped to human-understandable concepts across different datasets?"

**Residual Stream**
- Why needed: The residual stream in transformer models carries accumulated information; intervening here affects all subsequent layers.
- Quick check: "Does perturbing the residual stream preserve model coherence?"

**Proximal Policy Optimization (PPO)**
- Why needed: A stable on-policy RL algorithm suitable for sequential decision-making in high-dimensional action spaces.
- Quick check: "Is PPO robust to sparse rewards common in steering tasks?"

**Adaptive Feature Masking**
- Why needed: Prevent the policy from overusing a small subset of features, fostering diversity and discovery of new causal features.
- Quick check: "Does masking improve feature diversity without harming performance?"

## Architecture Onboarding
Component map:
Input Tokens -> Model Residual Stream -> SAE Feature Extraction -> Policy Network (PPO) -> Feature Selection -> Adaptive Feature Masking -> Feature Amplification -> Modified Residual Stream -> Model Output

Critical path: For each generated token, the system (1) extracts residual activations, (2) encodes them into SAE features, (3) passes these to the policy, (4) selects a subset of features, (5) applies masking to ensure novelty, (6) amplifies the chosen features, (7) injects them back into the residual stream, and (8) continues generation.

Design tradeoffs:
- Feature diversity vs. interpretability: masking encourages diversity but may obscure single-feature effects if not carefully tuned.
- Intervention strength: stronger amplification can yield larger effects but risks destabilizing the model.
- Computational overhead: running the policy and SAE at each step adds latency; tradeoffs between speed and steering efficacy.

Failure signatures:
- Sudden drop in generation quality (e.g., repetition, incoherence) indicating over-amplification.
- Policy selects features that are irrelevant or detrimental according to task metrics.
- Masking blocks critical features, causing the policy to underperform despite ample reward signals.

Three first experiments:
1. Single-feature amplification: manually amplify a randomly chosen feature and observe output changes to confirm individual feature effects.
2. Policy vs. random selection: replace the learned policy with uniform random feature selection and compare task performance to demonstrate the policy's contribution.
3. Masking ablation: train CRL without Adaptive Feature Masking, then compare the diversity of selected features and benchmark scores to assess masking's role.

## Limitations
- Benchmark improvements lack variance estimates, baseline comparisons, and statistical significance.
- Evaluation is restricted to Gemma 2B; generalizability to larger or different models remains untested.
- Adaptive Feature Masking may bias discovery toward spurious correlations without human validation of feature semantics.
