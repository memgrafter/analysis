# A Modular LLM Framework for Explainable Price Outlier Detection

## Quick Facts
- **arXiv ID:** 2603.20636
- **Source URL:** https://arxiv.org/abs/2603.20636
- **Reference count:** 31
- **Primary result:** An agentic LLM framework for explainable price outlier detection achieves 76.3% agreement with human auditors and reduces false discovery rate to 7.8%.

## Executive Summary
This paper introduces an agentic LLM framework to detect erroneously high product prices in e-commerce, addressing the limitations of classical threshold-based methods that lack semantic reasoning. The system decomposes outlier detection into three sequential steps: (1) relevance classification to identify semantically comparable products, (2) relative utility assessment across price-influencing attributes, and (3) a reasoning-based decision using quadrant analysis with configurable padding and voting strategies. Evaluated on a multi-set dataset with human auditor ground truth, the framework outperforms zero-shot and retrieval-augmented baselines, achieving a silver-set F1 score of 0.55. Key hyperparameters—50% price padding, seven neighbors, generic attribute selection, and a worse-pricier veto decision rule—yield the best precision-oriented balance, while ablation studies confirm tunability for different accuracy requirements.

## Method Summary
The proposed pipeline uses three specialized LLM agents in sequence. First, a Relevance Agent filters top-k embedding-similarity candidates using product descriptions, asking three disjunctive questions to retain only price-relevant substitutes. Second, a Utility Agent compares the target against each relevant neighbor along fixed price-influencing attributes (e.g., brand, quantity), scoring each as better (+1), mixed (0), or worse (-1). Third, a Decision Agent plots neighbors in a utility-vs-price quadrant, applies configurable price padding, and aggregates evidence via either a high-precision Worse-Pricier Veto rule or a higher-recall Quadrant Voting strategy. The system is configured to use Claude 3.5 Sonnet, seven neighbors, 50% price padding, generic attributes, and the veto rule for optimal balance.

## Key Results
- Achieves 76.3% agreement with human annotators and silver-set F1 of 0.55.
- Reduces false discovery rate to 7.8% with the worst-case precision of 1.0.
- Outperforms zero-shot and retrieval-augmented baselines in precision-oriented settings.
- Best hyperparameters: 7 neighbors, 50% price padding, generic attribute selection, Worse-Pricier Veto.

## Why This Works (Mechanism)
### Mechanism 1: Relevance Classification
Filters candidate neighbors to only those semantically comparable to the target product for price analysis. An LLM agent evaluates top-k embedding-similarity candidates by asking if customers would compare them, if they are similar, or serve the same use case; only "Relevant" neighbors proceed. Core assumption: Human auditors first identify true product substitutes before considering price; an LLM can emulate this semantic judgment. Break condition: Using too many neighbors (e.g., k=12) overloads context and confuses downstream agents, lowering performance.

### Mechanism 2: Relative Utility Assessment
Quantifies value differences between target and relevant neighbors across price-influencing attributes. The Utility Agent compares products along selected attributes (e.g., brand, quantity), scoring each as better (+1), mixed (0), or worse (-1). The net utility guides whether a price deviation is justified. Core assumption: Price deviations are acceptable if justified by meaningful attribute differences; an LLM can identify and weigh these. Break condition: Dynamic attribute selection (product-pair specific) overloads the LLM, leading to lower F1 and agreement versus fixed generic attributes.

### Mechanism 3: Reasoning-Based Decision
Aggregates utility and price evidence into an outlier judgment via quadrant analysis and configurable rules. Neighbors are plotted in four quadrants relative to target (utility vs. price). The "Better and cheaper" (bottom-right) quadrant supports an anomalous high price. Final decision uses either Worse-Pricier Veto (high precision) or Quadrant Voting (higher recall). Core assumption: The spatial pattern of neighbors relative to target reveals pricing anomalies; a simple rule can aggregate justified price differences. Break condition: Quadrant Voting reduces human agreement from 76.3% to 43.2% on the one-sided test set, indicating misalignment with auditor logic.

## Foundational Learning
- **Agentic LLM Frameworks (multi-step decomposition)**: The system decomposes outlier detection into sequential specialized agents rather than a single monolithic LLM call. Why needed: Each step requires distinct reasoning (semantic filtering, attribute comparison, aggregation). Quick check: What are the three sequential agents, and what specific reasoning does each perform?
- **Retrieval-Augmented Generation (RAG) for structured e-commerce data**: Initial neighbor candidates come from embedding similarity search; the framework must ground comparisons in real product catalog data. Why needed: Embedding similarity alone may retrieve visually or textually similar but price-irrelevant products. Quick check: How are candidate neighbors generated, and why might embedding similarity alone be insufficient for price-relevance?
- **Hyperparameter-driven precision/recall trade-offs in real-world systems**: Key knobs (price padding, neighbor count, decision strategy) directly control system aggressiveness. Why needed: Wrong choices cause high false positives/negatives in production. Quick check: What hyperparameter change increases recall at the cost of precision, and what business context might prefer this?

## Architecture Onboarding
- **Component map:** Candidate Neighbor Generator -> Relevance Classification Agent -> Utility Assessment Agent -> Reasoning-Based Decision Agent -> Configuration layer (padding %, k, attribute mode, decision rule)
- **Critical path:** Input product → Generate k neighbors → Relevance filter → Utility scoring per neighbor → Plot quadrants → Apply decision rule → Output outlier label + explanation. Each agent's output is required for the next.
- **Design tradeoffs:**
  - Precision vs. Recall: 50% price padding or Worse-Pricier Veto maximizes precision (1.0) but lowers recall (0.38); 30% padding or Quadrant Voting boosts recall (0.75/0.63) but hurts precision (0.67/0.42).
  - LLM autonomy vs. structure: Generic attributes work best overall; dynamic selection causes overload and worse SS F1.
  - Explainability vs. automation: Quadrant explanations are human-readable but rely on LLM's correct attribute judgment.
- **Failure signatures:**
  - High outlier rate (>10%) on unannotated set: padding too low or decision rule too aggressive.
  - Low agreement (<70%) with one-sided test: over-trusting Quadrant Voting or using Dynamic attributes.
  - Low SS F1 (<0.4): relevance filter too strict/lenient, or utility scoring inconsistent.
  - High time/cost per product: too many neighbors (k>10) or overly complex prompts.
- **First 3 experiments:**
  1. Baseline validation: Run full pipeline with default config (7 neighbors, 50% padding, Generic attributes, Worse-Pricier Veto) on Silver Set; expect SS F1 ~0.55, Agreement ~76%.
  2. Hyperparameter sweep: Vary one knob at a time (padding, k, attribute mode, decision rule) to map precision/recall frontier for your business guardrails (e.g., max 8% outlier rate).
  3. Robustness check: Test on Edge Cases and one-sided difficult set; if agreement drops below 60%, prioritize improving Relevance Agent prompt or increasing padding.

## Open Questions the Paper Calls Out
1. **How can utility quantification be made more unbiased and representative by incorporating multiple customer personas?** The current framework relies on a single LLM agent for utility assessment, which may not capture diverse customer perspectives. Evidence: "the utility quantification can be made more unbiased and representative by running an aggregated investigation over several different customer personas represented by LLMs" (Section 6, Limitations). What evidence would resolve it: Experiments with multiple LLM personas (budget-conscious, premium buyers) to measure improved agreement and reduced bias.
2. **What are effective methods for dynamically selecting price-influencing attributes that generalize across product categories?** Dynamic and weighted-dynamic attribute configurations performed worse than generic attributes, indicating suboptimal LLM self-selection. Evidence: "improving the current attribute selection process may improve system performance, particularly in dynamic configurations." (Section 6). What evidence would resolve it: Systematic comparison of alternative strategies (e.g., retrieval from domain knowledge base, supervised ranking) across diverse categories.
3. **How can the framework robustly handle incomplete or noisy product metadata to maintain detection performance?** Real-world catalogs often contain missing or erroneous attributes; the current approach compares only available attributes without adaptation. Evidence: "our framework assumes that product metadata (attributes) is available and reasonably accurate... systematic data quality issues could impact performance. We leave a detailed data quality analysis and potential mitigation strategies (e.g., confidence weighting based on attribute completeness) for future work." (Section 6). What evidence would resolve it: Controlled experiments introducing missingness/noise and testing mitigation approaches (imputation, confidence weighting).
4. **Since price outlier judgments are inherently subjective, how can we establish more objective evaluation protocols?** Ground truth depends on human annotator subjectivity, making absolute performance measurement difficult. Evidence: "comprehensive evaluation of such solutions remains challenging due to the inherent contextuality and subjectivity of price-quality ground truth... this subjectivity is reflected in our inter-annotator agreement (κ= 0.72) and represents a fundamental challenge for any evaluation methodology in this domain." (Section 6). What evidence would resolve it: Richer evaluation frameworks using large diverse auditor panels, multi-faceted annotations, or proxy metrics correlating with broader consensus.

## Limitations
- Undisclosed embedding model and neighbor retrieval pipeline prevent exact replication.
- Small evaluation sets (n=40,185) and single LLM (Claude) limit generalizability.
- Hyperparameters tuned on same dataset risk overfitting; no external validation.
- Incomplete prompt details (JSON output, dynamic attribute rules) may cause implementation drift.

## Confidence
- Framework achieves 76.3% agreement & F1 0.55: **Medium** (small datasets, one model).
- Relevance classification improves neighbor quality: **Medium** (ablation shows k sensitivity, but no direct component removal test).
- Generic attribute selection outperforms dynamic: **Medium** (supported by Table 1, but attribute set may not generalize).
- Worse-Pricier Veto yields high precision: **High** (clear trade-off in Table 2).
- Optimal hyperparameters transfer to other domains: **Low** (tuned on same data).
