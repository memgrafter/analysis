# Online Algorithms with Unreliable Guidance
## Quick Facts
- arXiv ID: 2602.20706
- Source URL: https://arxiv.org/abs/2602.20706
- Reference count: 39
- Primary result: Introduces the OAG model with β‑corrupted guidance and the simple DTB compiler, achieving optimal or state‑of‑the‑art consistency‑robustness trade‑offs for online bipartite matching, caching, and uniform metrical task systems.

## Executive Summary
This paper presents a new model for online algorithms that receive guidance which may be adversarially corrupted with probability β. The core contribution is the Drop or Trust Blindly (DTB) compiler, which transforms any prediction‑oblivious online algorithm into one that can effectively leverage such unreliable guidance. DTB randomly decides to follow the guidance or revert to the base algorithm’s distribution, yielding smooth trade‑offs between consistency (when guidance is accurate) and robustness (when guidance is adversarial). Applied to three classic online problems, DTB achieves optimal or the first non‑trivial trade‑offs, demonstrating that a simple transformation can abstract away the specifics of prediction unreliability.

## Method Summary
The reproduction plan centers on implementing the DTB wrapper around well‑known prediction‑oblivious base algorithms: Random Mark for caching, Ranking for bipartite matching, and Borodin‑Linial‑Saks for uniform metrical task systems. The DTB logic is straightforward: at each request, with probability τ it attempts to use the provided guidance γ_t if it lies in the base algorithm’s valid answer set V_t; otherwise it draws an answer from the base distribution D_t. To validate the theoretical competitive ratios, one simulates these algorithms on appropriate worst‑case or random sequences, varying τ and β, and compares empirical performance against optimal offline costs. Key challenges include faithfully simulating the adversarial guidance (or using worst‑case instances) and handling the validity check γ_t ∈ V_t.

## Key Results
- For caching (with cache size k): Marking‑DTB is min{2/(τ(1‑β)), 2H_k/(1‑τβ), k}‑competitive, asymptotically optimal in consistency and robustness.
- For uniform metrical task systems (n states): MTS‑DTB is 2·min{1/(τ(1‑β))+1, (1‑τ)/((1‑τβ)²H_n)+1, n}‑competitive, also optimal.
- For bipartite matching with adversarial arrivals: Ranking‑DTB achieves max{1/2, (1‑βτ)(1‑e^{-(1‑τ)})/(1‑τ)} competitive ratio, the first non‑trivial trade‑off between consistency and robustness.

## Why This Works (Mechanism)
#### Mechanism 1
- **Claim:** The OAG model isolates the unreliability of guidance into a single parameter β, governing independent per‑request corruption, which enables a clean trade‑off analysis between consistency and robustness.
- **Mechanism:** At each time t, nature flips a β‑biased coin. With probability 1‑β, a good guide supplies the optimal answer; with probability β, a bad guide supplies an adversarially chosen answer. The algorithm sees only the guidance, not which guide generated it.
- **Core assumption:** Corruption events are independent across requests; both guides have full knowledge of the entire request sequence and the algorithm’s past actions (adaptive guides). The algorithm is otherwise oblivious to the guide’s identity.
- **Evidence anchors:** [abstract] “with probability β, the guidance is adversarially corrupted.”; [section] Page 2: “at each time t, nature tosses a fresh β‑biased coin… generates the guidance γ_t by the good guide with probability 1−β and by the bad guide with probability β.”
- **Break condition:** If corruption exhibits temporal or conditional dependencies (e.g., bursts of bad guidance, or bad guide constrained by algorithm’s randomness), the independence assumption fails and the analysis may not hold.

#### Mechanism 2
- **Claim:** The DTB compiler uses a single trust parameter τ to randomly decide whether to follow the incoming guidance or revert to the base algorithm’s distribution, producing a smooth interpolation between consistency (τ = 1, β = 0) and robustness (τ = 0, β = 1).
- **Mechanism:** For each request, let D_t be the distribution from which a prediction‑oblivious base algorithm Alg would pick an answer, and let V_t = support(D_t). If a Bernoulli(τ) trial succeeds *and* the guidance γ_t ∈ V_t, the DTB algorithm outputs γ_t; otherwise it draws an answer from D_t. This simple rule is applied uniformly at every step.
- **Core assumption:** The base algorithm is prediction‑oblivious (does not itself use guidance) and its distribution D_t is efficiently sampleable. The guidance is always in V_t, or else it is ignored (the definition allows ignoring invalid guidance).
- **Evidence anchors:** [abstract] “the drop or trust blindly (DTB) compiler … either follows the incoming guidance blindly or ignores it altogether … based on the outcome of a (biased) coin toss.”; [section] Page 2: Formal definition of the DTB compiler.
- **Break condition:** If V_t is very small (e.g., deterministic base algorithm), the guidance may rarely be usable even when correct, harming consistency. If the base algorithm’s robustness (performance when τ = 0) is poor, DTB cannot fully recover when β = 1.

#### Mechanism 3
- **Claim:** For several classic online problems, the DTB transformation applied to well‑known prediction‑oblivious algorithms yields (asymptotically) optimal consistency‑robustness trade‑offs; for adversarial bipartite matching, it provides the first non‑trivial trade‑off.
- **Mechanism:** The analysis exploits problem‑specific structure:
  - **Caching:** Divide the request sequence into phases (max k distinct pages). Bound the expected cost per phase by analyzing *clean* pages (C) and *blame chains* for returning pages, using geometric trials and harmonic series (Lemma 8, 9).
  - **Uniform MTS:** Define phases by saturation of states. Bound the number of transitions per phase via Wald’s identity and a recurrence on unsaturated states, yielding harmonic‑type bounds.
  - **Bipartite matching:** Use the Ranking algorithm’s permutation; analyze the probability a node of rank t is matched via an induction that accounts for good/bad guidance and random ranking (Lemma 5, Theorem 6).
- **Core assumption:** The base algorithms (Random Marking for caching, Borodin‑Linial‑Saks for MTS, Ranking for matching) have known worst‑case guarantees without guidance. The OAG analysis builds on these by carefully tracking the effect of the random trust decision.
- **Evidence anchors:** [abstract] “for caching and uniform metrical task systems our algorithms are optimal, whereas for bipartite matching … outperforms the state‑of‑the‑art.”; [section] Page 11 (Theorem 7, caching), Page 14 (Theorem 10, MTS), Page 9‑10 (Theorem 6, matching).
- **Break condition:** The phase‑based techniques rely on strong structural properties (e.g., marking in caching, uniform metric in MTS). They may not extend to problems lacking such decompositions or to non‑uniform metrics without additional machinery.

## Foundational Learning
#### Competitive Ratio
- **Why needed:** It is the core performance metric; consistency (β=0) and robustness (β=1) are defined via the competitive ratio of the OAG algorithm against an optimal offline algorithm.
- **Quick check:** “If an online algorithm is 2‑competitive, what inequality relates its expected cost to the optimal offline cost?” Answer: E[ALG] ≤ 2·OPT (for minimization).

#### Request‑Answer Games
- **Why needed:** The OAG model is formulated as an extension of request‑answer games; this abstraction uniformly describes online problems by request space R, answer space A, and cost function f_P.
- **Quick check:** “What are the two main components of a request‑answer game?” Answer: (R, A) and a family of cost functions f_P: A^t → ℝ for each problem P.

#### Prediction‑Oblivious Algorithm
- **Why needed:** The DTB compiler transforms any prediction‑oblivious algorithm (which does not use guidance) into an OAG algorithm. Understanding this baseline is crucial to reason about robustness (τ=0) and to define D_t.
- **Quick check:** “How does a prediction‑oblivious algorithm differ from a learning‑augmented one in the OAG model?” Answer: A prediction‑oblivious algorithm never uses guidance γ_t in its decision; its distribution D_t is independent of γ_t. A learning‑augmented algorithm may use γ_t to influence its choices.

## Architecture Onboarding
#### Component map
Base algorithm (Alg) -> D_t, V_t; Guides -> γ_t; DTB wrapper (combines D_t, V_t, γ_t, τ) -> Final output.

#### Critical path
1. Choose a well‑studied prediction‑oblivious algorithm Alg for the target problem.
2. Characterize Alg’s distribution D_t and support V_t for each request.
3. Implement the DTB wrapper around Alg.
4. Develop an analytical bound: decompose the execution into phases or use potential functions; account for the probability of following good/bad guidance (τ(1‑β) and τβ) and for the base algorithm’s behavior when ignoring guidance.
5. Optimize τ for a given β or derive the full smoothness function c(β).

#### Design tradeoffs
- **τ selection:** Larger τ improves consistency (when guidance is accurate, i.e., small β) but degrades robustness (when guidance is adversarial, β≈1). The engineer must pick τ based on an estimated β or optimize for a desired operating point.
- **Base algorithm choice:** Prefer algorithms with strong robustness (low competitive ratio when τ=0) and a distribution D_t that often contains good guidance (large V_t). Some base algorithms yield asymptotically optimal trade‑offs; others may be suboptimal.

#### Failure signatures
- **Invalid guidance:** If the optimal answer frequently lies outside V_t, the DTB algorithm ignores correct guidance even when the coin flip favors trust, leading to worse consistency. Verify that for the intended good guide, γ_t∈V_t holds with high probability.
- **High variance in D_t:** If D_t is highly concentrated (e.g., deterministic), DTB’s randomness is limited; the algorithm may be overly sensitive to guidance corruption.
- **Analytical gap:** The derived competitive ratio may contain loose bounds (e.g., harmonic approximations) that do not match empirical performance for small problem sizes. Check the tightness of each inequality in the proof.

#### First 3 experiments
1. **Replicate caching result:** Implement Marking‑DTB (Algorithm 2) and simulate on random request sequences (Poly‑random). Vary τ and β, measure average cost ratio against optimal offline (computed via Belady’s algorithm). Confirm the min{2/(τ(1‑β)), 2H_k/(1‑τβ), k} bound from Theorem 7.
2. **Test on bipartite matching:** Implement Ranking‑DTB (Algorithm 1) for adversarial graph/arrival (worst‑case). Compare against pure Ranking (τ=0) and against perfect guidance (τ=1, β=0). Validate the max{1/2, (1‑βτ)(1‑e^{-(1‑τ)})/(1‑τ)} competitive ratio from Theorem 6.
3. **Parameter sweep:** For a fixed problem (e.g., caching with k=100) and a fixed β (e.g., β=0.2), sweep τ from 0 to 1 in small increments. Plot the empirical competitive ratio and overlay the theoretical curve. This checks the smoothness property and helps identify the optimal τ for that β.

## Open Questions the Paper Calls Out
#### Open Question 1
- **Question:** Is the competitive ratio of Ranking‑DTB for online bipartite matching with adversarial arrivals optimal in the OAG model?
- **Basis in paper:** The paper states that Ranking‑DTB "outperforms the state‑of‑the‑art" and provides the first non‑trivial trade‑off, but does not prove optimality or provide lower bounds.
- **Why unresolved:** Without a matching lower bound, it is unknown if the achieved trade‑off is the best possible for any OAG algorithm on this problem.
- **What evidence would resolve it:** Proving a lower bound on the competitive ratio for any OAG algorithm on adversarial bipartite matching, possibly via adversarial construction or reduction from known hard instances.

#### Open Question 2
- **Question:** For which other online problems beyond bipartite matching, caching, and uniform metrical task systems does the DTB compiler yield non‑trivial consistency‑robustness trade‑offs?
- **Basis in paper:** The conclusion envisions the framework as a "reference point in the future to evaluate learning‑augmented algorithms," implying extension to other problems is open.
- **Why unresolved:** The paper only applies DTB to three specific problems; its generality and effectiveness for problems with different structures (e.g., ski rental, k‑server) remain untested.
- **What evidence would resolve it:** Applying DTB to a broader set of classic online problems, analyzing the resulting competitive ratios, and comparing to known lower bounds or existing learning‑augmented algorithms.

#### Open Question 3
- **Question:** What is the optimal way to set the trust parameter τ in DTB algorithms given an estimate of the bad guidance parameter β?
- **Basis in paper:** The competitive ratios in Theorems 6, 7, and 10 depend on τ, but the paper does not provide a method for choosing τ to optimize the trade‑off for a given β.
- **Why unresolved:** Practitioners lack guidance on selecting τ, potentially leading to suboptimal performance; the theoretical relationship between τ and β is not fully characterized for minimization.
- **What evidence would resolve it:** Deriving closed‑form expressions or algorithms for the τ that minimizes the competitive ratio for each β, supported by theoretical analysis and empirical validation on synthetic or real data.

#### Open Question 4
- **Question:** How do correlated prediction corruptions (non‑independent β‑biased errors) affect the performance guarantees of DTB algorithms?
- **Basis in paper:** The OAG model assumes independent corruption at each time step, but real‑world ML predictions often exhibit temporal or structural correlations, which may invalidate the analysis.
- **Why unresolved:** The proofs for DTB algorithms rely on independence (e.g., in Lemma 5 for bipartite matching); correlated errors could degrade performance or require different analytical techniques.
- **What evidence would resolve it:** Extending the OAG model to include correlation structures (e.g., Markovian or burst errors), re‑analyzing DTB algorithms under this model, and conducting simulations to quantify the impact.

## Limitations
- Independent corruption assumption may not hold for real‑world guidance sources that exhibit temporal or conditional dependencies.
- Simulating the truly adversarial bad guide is computationally intractable; heuristics used in practice may underestimate the worst‑case performance.
- The requirement that guidance γ_t lies in the base algorithm’s valid set V_t can limit consistency gains if optimal answers often fall outside V_t.
- Analytical bounds are often asymptotic and use harmonic approximations; constants may be loose and worst‑case instances are not explicitly constructed.

## Confidence
- **OAG model abstraction:** Medium (simplifies reality, may not capture dependencies).
- **DTB correctness & smoothness:** High (simple, rigorously proven).
- **Asymptotic optimality (caching, uniform MTS):** Medium (matches lower bounds but empirical validation needed).
- **First non‑trivial trade‑off (bipartite matching):** High.
- **Robustness recovery (τ=0):** High.
